Ermöglicht Steuerungsanwendungen die Anforderung von Zustandswechseln für konfigurierte Zustandsmaschinen.

Das Service-Interface StateMachineService wird von State Management für jede konfigurierte Zustandsmaschine bereitgestellt, damit eine SMControlApplication über die Methode RequestTransition gezielt Zustandswechsel anfordern kann [SWS_SM_00600], [SWS_SM_91107]. Der Dienst wird unmittelbar nach erfolgreicher Abarbeitung des Startschritts der Zustandsmaschine angeboten und quittiert Anforderungen ohne Fire-and-Forget-Semantik. Anforderungen werden jedoch mit spezifischen Fehlern abgewiesen, falls der übergebene Wert ungültig ist, der Übergang aus dem aktuellen Zustand unzulässig ist oder zeitgleich eine Update- bzw. Recovery-Sitzung aktiv ist [SWS_SM_91107].

Rolle und Systemkontext der Service-Schnittstelle

Das Service-Interface StateMachineService wird vom funktionalen Cluster State Management (SM) über einen standardisierten Service-Port bereitgestellt [SWS_SM_91021]. Gemäß der formalen Schnittstellendefinition [SWS_SM_91022] instanziiert und bietet State Management diesen ara::com-basierten Dienst für jede einzelne konfigurierte Instanz einer StateMachine an [SWS_SM_00600].

Als primärer Consumer dieser Schnittstelle fungiert eine SMControlApplication, welche über den Dienst unmittelbar mit der Zustandsmaschine interagiert, um Zustandswechsel anzufordern SWS StateManagement §9.2.2 „StateMachine service“. Während Benachrichtigungen über eingetretene Zustände an reguläre adaptive Anwendungen primär über das separate Service-Interface StateMachineNotification erfolgen [SWS_SM_00665], bildet StateMachineService die aktive Kontrollschnittstelle zur Initiierung von Transitionen.

Methoden und Aufrufsemantik

Die Schnittstelle definiert die Methode RequestTransition, die von der SMControlApplication aufgerufen werden muss, um eine Zustandsänderung in der referenzierten StateMachine herbeizuführen [SWS_SM_91107]. Die Methode erwartet den Eingabeparameter TransitionRequest vom Typ TransitionRequestType, der den geforderten Übergangswert innerhalb der zugrundeliegenden TransitionRequestTable repräsentiert [SWS_SM_91107], SWS StateManagement §7.x „TransitionRequestTable“.

Für RequestTransition ist die Eigenschaft Fire & Forget auf false gesetzt [SWS_SM_91107]. Die aufrufende Anwendung erhält somit eine verbindliche Quittierung der Anfrage. Interpretation: Innerhalb des ara::com-Proxy-Skeleton-Musters dürfte die Rückmeldung typischerweise über ein ara::core::Future bzw. ein entsprechendes Ergebnisobjekt bereitgestellt werden, das im Erfolgsfall auflöst oder im Fehlerfall einen spezifischen Fehlerstatus übermittelt. Lebenszyklus und Zustandsabhängigkeiten

Jeder für eine zu startende StateMachine konfigurierte ara::com-Dienst – einschließlich StateMachineService – muss verfügbar sein und angeboten werden (Offer), sobald das ActionListItem „StartStateMachine“ erfolgreich abgearbeitet wurde [SWS_SM_00618]. Dies gestattet es der SMControlApplication, sofort nach erfolgreicher Erzeugung der Zustandsmaschine eine Transition anzufordern, selbst wenn die Zustandsmaschine zu diesem Zeitpunkt noch die initiale ActionList verarbeitet SWS StateManagement §7.x „StateMachine service interfaces - Offer“.

Das Anbieten des Dienstes wird beendet (StopOffer), sobald die Verarbeitung zum Stoppen der jeweiligen Zustandsmaschine erfolgt [SWS_SM_00619]. Aufrufe unterliegen zudem funktionalen Vorbedingungen: Läuft im System aktuell eine Update-Sitzung, ist die Einleitung von Zustandswechseln prinzipiell unzulässig [SWS_SM_91107].

Fehlerbehandlung und Application Errors

Bei der Ausführung von RequestTransition können spezifische Application Errors auftreten, die von State Management an den Aufrufer zurückgemeldet werden [SWS_SM_91107]:

  • kInvalidValue: Der übergebene Wert ist in der TransitionRequestTable keiner Transition zugeordnet [SWS_SM_91107].
  • kTransitionNotAllowed: Der angeforderte Zustandsübergang ist ausgehend vom aktuellen Zustand der StateMachine nicht erlaubt [SWS_SM_91107].
  • kRecoveryTransitionOngoing: Die Anforderung wird verworfen, da gegenwärtig eine Fehlerbehebung (Recovery) ausgeführt wird [SWS_SM_91107].
  • kTransitionFailed: Während der Ausführung des Übergangs in den Zielzustand ist ein Fehler aufgetreten [SWS_SM_91107].
  • kOperationCanceled: Die Anfrage wurde abgebrochen, da sie durch eine neuere Anforderung ersetzt wurde [SWS_SM_91107].
  • kUpdateInProgress: Die Operation ist verboten, da aktuell eine Update-Sitzung aktiv ist [SWS_SM_91107].

Verwendung

Die Servicemethode RequestTransition wird von einer SMControlApplication auf der Schnittstelle StateMachineService aufgerufen, um einen Zustandswechsel einer referenzierten StateMachine anzufordern ([SWS_SM_91107], SWS StateManagement §7.7 „SMControlApplication“). Als Parameter wird TransitionRequest übergeben. Die Methode besitzt Rückgabewerte und arbeitet nicht nach dem Fire-and-Forget-Prinzip. Das State Management bildet den Eingangswert über die TransitionRequestTable abhängig vom aktuellen Zustand auf einen Folgezustand ab ([SWS_SM_00607]) und fordert die resultierenden Function Group States über SetState() beim Execution Management an (AP EXP SWArchitecture §11.1 „Change System State“).

Fehlerbehandlung

Im Fehlerfall bricht die Bearbeitung ab und RequestTransition liefert spezifische Anwendungsfehler zurück ([SWS_SM_91107]):

  • kInvalidValue: Der übergebene Wert für TransitionRequest ist in der TransitionRequestTable nicht konfiguriert ([SWS_SM_00604]).
  • kTransitionNotAllowed: Der Übergang ist ausgehend vom aktuellen Zustand der StateMachine laut Konfiguration nicht zulässig ([SWS_SM_00603]).
  • kRecoveryTransitionOngoing: Eine interne Fehlerbereinigung ist aktiv, weshalb die Anforderung nicht weiter bearbeitet wird ([SWS_SM_00605]).
  • kUpdateInProgress: Während einer aktiven Update-Sitzung ist die Zustandsänderung unzulässig ([SWS_SM_91107]).
  • kTransitionFailed: Bei der Abarbeitung von ActionListItems ist ein Fehler aufgetreten ([SWS_SM_00650]).

Nebenläufigkeit und Einschränkungen

Wird ein neuer Übergangswunsch akzeptiert, während für dieselbe StateMachine noch ein früherer RequestTransition-Aufruf aussteht, wird die vorherige Anforderung abgebrochen und mit kOperationCanceled quittiert ([SWS_SM_00606]). Zeitgesteuerte Aktionen wie Sleep ActionListItem blockieren eingehende Trigger nicht; ein RequestTransition-Aufruf kann daher auch während einer solchen Wartezeit eine Zustandsänderung auslösen (SWS StateManagement §7.7.9 „ActionListItem Sleep“).
