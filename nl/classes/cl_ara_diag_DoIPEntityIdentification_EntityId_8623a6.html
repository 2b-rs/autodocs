Kapselt de zes bytes lange entiteitsidentificatie (EID) voor de DoIP-voertuigidentificatie conform ISO 13400-2 in.

De structuur ara::diag::DoIPEntityIdentification::EntityId dient als datacontainer voor de zes bytes lange entiteitsidentificatie (EID) van een DoIP-instantie conform ISO 13400-2 ([SWS_DM_01496]). Bij een overeenkomstige configuratie vraagt de Diagnostic Manager deze identificatie via de methode ara::diag::DoIPEntityIdentification::GetEntityId op bij de adaptieve applicatie om deze in te bedden in DoIP-protocolberichten zoals de voertuigaankondiging ([SWS_DM_01361]). Mocht de interface nog niet beschikbaar zijn of de opvraag mislukken, dan treedt als dwingende randvoorwaarde een fallback in werking naar de vaste vervangende waarde bestaande uit louter bytes met de waarde 0xFF ([SWS_DM_01528]).

Context

De datastructuur ara::diag::DoIPEntityIdentification::EntityId dient voor de representatie van de gestandaardiseerde entiteitsidentificatie (Entity Identification, EID) voor diagnosecommunicatie via het internetprotocol (DoIP) conform ISO 13400-2 ([SWS_DM_01496], AUTOSAR_AP_SWS_Diagnostics §8.33 “Header: ara/diag/doip_entity_identification.h”). Binnen het AUTOSAR Adaptive Platform is deze gedefinieerd als een openbaar structuurtype binnen de API-klasse ara::diag::DoIPEntityIdentification ([SWS_DM_01362], [SWS_DM_01496]).

Haar primaire verantwoordelijkheid bestaat uit het inkapselen van de exact zes bytes lange identificatiewaarde van een DoIP-entiteit ([SWS_DM_01496]). In de platformarchitectuur interageren daarbij drie hoofdactoren: ten eerste de adaptieve applicatie, die de entiteitsidentificatie beheert of uit de hardware leest. Ten tweede de interfaceklasse ara::diag::DoIPEntityIdentification, die de methode voor het beschikbaar stellen van de identificatie aanbiedt ([SWS_DM_01362]). Ten derde de Diagnostic Manager (DM), die de EID in het kader van de voertuigidentificatie opvraagt voor uitgaande DoIP-berichten ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”).

Contextdiagram: Integratie van EntityId tussen Diagnostic Manager, interfaceklasse en adaptieve applicatie. Bronnen: [SWS_DM_01361], [SWS_DM_01496].

Levenscyclus

Als datastructuur met het enige lid entityIdentification van het type ara::core::Array<std::uint8_t, 6> vertoont EntityId de eigenschappen van een lichtgewicht C++-waardeobject ([SWS_DM_01496]). Interpretatie: Bij gebrek aan dynamische resource-allocatie ondersteunt de structuur standaard vermoedelijk reguliere kopieer- en verplaatsingsoperaties en is deze niet onderhevig aan complexe interne toestandsovergangen.

De instantiëring van EntityId vindt plaats door de adaptieve applicatie zodra de Diagnostic Manager de identiteitsgegevens opvraagt via de aanroep van ara::diag::DoIPEntityIdentification::GetEntityId ([SWS_DM_01361]). De levensduur van een instantie is typisch gebonden aan de teruggave- en verwerkingscyclus van de methode-aanroep. Terwijl de omsluitende serviceklasse ara::diag::DoIPEntityIdentification over expliciete constructors ([SWS_DM_01364], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.2.1 “DoIPEntityIdentification”) en destructors ([SWS_DM_01365], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.1.1 “Destructor”) beschikt, wordt het waardeobject EntityId na het uitlezen van de velddata door de Diagnostic Manager bij het verlaten van de scope automatisch vrijgegeven.

Gebruikspad

Het reguliere gebruik van EntityId volgt een gedefinieerde sequentie in het diagnoseprotocolverloop:

  • Configuratiecontrole: De Diagnostic Manager controleert het attribuut DoIpNetworkConfiguration.eidRetrieval. Is daar DoIpEidRetrievalEnum.eidUseApi geconfigureerd, dan moet de DM de identificatie verplicht via de API opvragen ([SWS_DM_01361]).
  • Opvraag via API: De Diagnostic Manager roept de methode ara::diag::DoIPEntityIdentification::GetEntityId aan ([SWS_DM_01361]).
  • Datalevering: De applicatie maakt een instantie van EntityId aan, vult het lid entityIdentification met de 6-byte-identificatie conform ISO 13400-2 ([SWS_DM_01496]) en draagt de structuur over.
  • Protocolgebruik: De Diagnostic Manager neemt de identificatie over en plaatst deze in DoIP-berichten zoals de voertuigaankondiging (Vehicle Announcement Message) ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”).

Sequentiediagram: Verloop bij de opvraag en verdere verwerking van EntityId inclusief fout-fallback. Bronnen: [SWS_DM_01361], [SWS_DM_01496], [SWS_DM_01528].

Foutscenario's

Een centraal foutscenario ontstaat wanneer de interface ara::diag::DoIPEntityIdentification op het vereiste opvraagtijdstip nog niet wordt aangeboden door de adaptieve applicatie of wanneer de opvraag via GetEntityId mislukt ([SWS_DM_01528], AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”).

Om het verzenden van de DoIP-berichten niet permanent te blokkeren, schrijft de specificatie in dit geval een bindend vervangende-waardegedrag voor: de Diagnostic Manager moet in plaats van de reguliere applicatiedata een 6-byte-EID-veld met de vaste waarde 0xFF 0xFF 0xFF 0xFF 0xFF 0xFF verzenden ([SWS_DM_01528]). Op typeniveau sluit de vaste array ara::core::Array<std::uint8_t, 6> lengtefouten en buffer-overflows tijdens compile-tijd uit ([SWS_DM_01496]).
