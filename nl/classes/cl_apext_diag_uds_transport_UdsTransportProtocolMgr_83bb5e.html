klasse apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

Literatuurverwijzingen SWS Diagnostics: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

Context

De klasse apext::diag::uds_transport::UdsTransportProtocolMgr vormt de gestandaardiseerde interface voor de coördinatie tussen instanties van de Diagnostic Server (DM Core resp. Session Layer) en verschillende UDS-transportprotocollen zoals DoIP of CAN (AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”). Concrete transportprotocollen worden gerealiseerd als subklassen van de abstracte basisklasse apext::diag::uds_transport::UdsTransportProtocolHandler ([SWS_DM_00315], AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”).

In deze bemiddelende functie communiceert de managerklasse hoofdzakelijk met drie componenten:

  • UDS Transport Protocol Handler (Transport Layer): Melden het begin van inkomende berichten aan ([SWS_DM_00309]), dragen volledig ontvangen verzoeken over ([SWS_DM_00311]), bevestigen verzendopdrachten ([SWS_DM_00312]) en signaleren zowel kanaal- als statuswijzigingen ([SWS_DM_00313], [SWS_DM_00314]).
  • Diagnostic Server Core (Session Layer): Neemt geldige UDS-verzoeken over voor verdere diagnoseverwerking en beheert de toewijzing van berichtbuffers ([SWS_DM_00309], [SWS_DM_00311]).
  • Periodieke transporthandlers: Verzenden bevestigingen over de succesvolle overdracht van periodieke berichtenreeksen ([SWS_DM_01069]).

Contextdiagram: samenspel van de UdsTransportProtocolMgr met de transporthandlers en de Session Layer. Bronnen: AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”, [SWS_DM_00309], [SWS_DM_00311], [SWS_DM_00314].

Levenscyclus

De levenscyclus van een transportprotocol-implementatie wordt door de Diagnostic Manager (DM) bestuurd in een vast gedefinieerde volgorde van constructie, initialisatie tot stoppen ([SWS_DM_00329], AUTOSAR_AP_SWS_Diagnostics §7.1.1.1 “Initialization, Starting and Stopping of a UDS TransportLayer”). De klasse UdsTransportProtocolMgr declareert een virtuele standaarddestructor ([SWS_DM_01524]).

Tijdens bedrijf worden deactiveringsfasen gesynchroniseerd: als een handler als reactie op stoppen zijn netwerkverbindingen heeft gesloten en resources heeft vrijgegeven, stelt deze de manager via de callback HandlerStopped op de hoogte onder vermelding van zijn handlerId ([SWS_DM_00314]).

Wat betreft de geheugen- en eigendomsverhoudingen geldt voor berichtbuffers een duidelijk overdrachtsmodel: bij het begin van een overdracht maakt de DM-Core het berichtobject aan en draagt de pointer daarvan over aan de handler ([SWS_DM_00309]). Na volledige ontvangst draagt de handler het eigendom van het bericht via unique_ptr-semantiek via HandleMessage weer over aan de generieke DM-Core ([SWS_DM_00311]).

Alle interfacemethoden zijn gespecificeerd als exceptieveilig (noexcept), maar niet als thread-safe (not thread-safe) ([SWS_DM_00309], [SWS_DM_00311], [SWS_DM_00312]). Interpretatie: aanroepen naar de manager moeten daarom vermoedelijk door de aanroepende transport- en sessiecomponenten worden gesynchroniseerd.

Gebruikspad

Het reguliere verloop voor de verwerking van inkomende UDS-diagnoseverzoeken is onderverdeeld in de volgende stappen:

  1. Berichtindicatie: Voor zover de handler de indicatie ondersteunt, roept deze bij binnenkomst van de eerste gegevens IndicateMessage aan ([SWS_DM_00309]). Daarbij worden bron- en doeladres, het adresseringstype (fysiek of functioneel), de verwachte totale omvang en de GlobalChannelIdentifier ([SWS_DM_09021]) overgedragen. Via payloadInfo kunnen al de eerste bytes worden doorgegeven, zodat de DM bijvoorbeeld functionele Tester-Present-verzoeken vroegtijdig kan herkennen ([SWS_DM_00309]).
  2. Bufferbeschikbaarstelling: De manager retourneert een paar bestaande uit IndicationResult en een toegewezen UdsMessagePtr ([SWS_DM_00309]). Is het resultaat IndicationResult::kIndicationOk ([SWS_DM_00384]), dan vult de handler de buffer met de binnenkomende gegevens.
  3. Overdracht aan Session Layer: Na volledige ontvangst draagt de handler het bericht via HandleMessage over aan de manager ([SWS_DM_00311]), wat overeenkomt met de dienst T_Data.ind conform ISO 14229-2. De aanroep keert onmiddellijk terug; de verdere verwerking vindt asynchroon plaats in de Session Layer ([SWS_DM_00311]).
  4. Verzendbevestiging: Voor verzonden UDS-antwoorden bevestigt de handler het succes later via TransmitConfirmation met het resultaat kTransmitOk ([SWS_DM_00312], [SWS_DM_00307]), overeenkomstig T_Data.con conform ISO 14229-2.

Sequentiediagram: verloop van de UDS-berichtontvangst van de indicatie tot de asynchrone overdracht aan de Session Layer. Bronnen: [SWS_DM_00309], [SWS_DM_00311], [SWS_DM_00384].

Foutscenario's

Foutcondities tijdens het transport of de bufferallocatie worden afgevangen via gedefinieerde statuswaarden en foutinterfaces:

  • Mislukking bij de indicatie: Kan de DM-Core een geïndiceerd bericht niet accepteren, dan meldt deze dit via de enum IndicationResult ([SWS_DM_00309], [SWS_DM_00384]):
    • kIndicationOccupied: De server resp. de diagnosesessie is momenteel bezet ([SWS_DM_00384]).
    • kIndicationOverflow: De overgedragen berichtgrootte overschrijdt de buffercapaciteit ([SWS_DM_00384]).
    • kIndicationUnknownTargetAddress: Het geadresseerde doeladres is niet geconfigureerd ([SWS_DM_00384]).
  • Afbreken van de ontvangst: Treedt er na een succesvolle IndicateMessage een verbroken verbinding of overdrachtsfout op, dan roept de handler NotifyMessageFailure aan ([SWS_DM_00310]). Het eerder verkregen UdsMessage-object wordt aan de DM teruggegeven zonder dat er een aanroep van HandleMessage plaatsvindt ([SWS_DM_00310]).
  • Verzendoverdrachtsfout: Kan een uitgaand bericht op netwerkniveau niet worden verzonden, dan meldt de handler via TransmitConfirmation het resultaat TransmissionResult::kTransmitFailed ([SWS_DM_00312], [SWS_DM_00307]).
  • Kanaalreactivering: Na een tijdelijk verbindingsverlies signaleert de handler de hernieuwde beschikbaarheid van een kanaal via ChannelReestablished met de GlobalChannelIdentifier ([SWS_DM_00313], [SWS_DM_09021]), mits deze melding vooraf werd aangevraagd ([SWS_DM_00313]).

Berichtontvangst

HandleMessage functie

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;
IndicateMessage functie

Indicates a message start. This is an interface, which is just served/called by UdsTransportProtocolHandlers, which return TRUE from UdsTransportProtocolHandlers::isStartOfMessageIndicationSupported().

ChannelReestablished functie

Notification call from the given transport protocol channel, that it has been reestablished since the last (Re)Start from the UdsTransportProtocolHandler to which this channel belongs. To activate this notification a previous call to UdsTransportProtocolHandler::Notify Reestablishment() has to be done. Notification call from handler, that it has stopped now (e.g. closed down network connections, freed resources, etc...) This callback is expected as a reaction from handler to a call to UdsTransportProtocol Handler::Stop().

Type of tuple to pack UdsTransportProtocolHandlerID and ChannelID together, to form a global unique (among all used UdsTransportProtocolHandlers within DM) identifier of a Uds TransportProtocol channel.
