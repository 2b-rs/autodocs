klasse apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

Literatuurverwijzingen SWS Diagnostics: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

Gebruiksdoel

UdsTransportProtocolMgr beheert de interactie tussen diagnostic-server-instanties en UDS-transportprotocollen, zoals DoIP of CAN. Hij biedt de transport-handler de gestandaardiseerde interface voor berichtacceptatie, doorgifte aan de sessielaag, verzendbevestigingen en kanaalherstel. [SWS_DM_00306]

Berichtacceptatie & ownership

Een handler meldt het begin van een ontvangen bericht met IndicateMessage(), inclusief bron- en doeladres, adressoort, globale channel-ID, grootte en een alleen tijdens de aanroep geldig payload-fragment. Kan de DM de aanvraag verwerken, dan geeft deze kIndicationOk en een door UdsMessagePtr bezeten geheugengebied terug. Bij bezetting, resourcetekort of onbekend doeladres zijn respectievelijk kIndicationOccupied, kIndicationOverflow of kIndicationUnknownTargetAddress met null-pointer voorzien. [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

Na het invullen van het geretourneerde berichtobject geeft de handler dit via HandleMessage() door aan de session-laag; daarbij gaat het eigendom weer terug naar de generieke DM-kern. Heeft IndicateMessage() geen kIndicationOk geleverd, dan mag HandleMessage() niet worden aangeroepen. Bij een voortijdige transportfout wordt het object teruggegeven met NotifyMessageFailure(). [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

Levenscyclus & overdracht

TransmitConfirmation() meldt kTransmitOk of kTransmitFailed voor een door de DM via UdsTransportProtocolHandler::Transmit() aangevraagde overdracht. PeriodicTransmitConfirmation() bevestigt een geordende lijst van periodiek verzonden berichten, samen met het aantal succesvol verzonden elementen. [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

Een kanaalherstel mag de DM pas verwerken nadat de bijbehorende handler is gestart. Na diens stop is behalve HandlerStopped() geen verdere manager-aanroep toegestaan; op deze callback wacht de DM voor de procesbeëindiging. [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

Beperkingen

Alle in het fragment beschreven manager-operaties zijn exception safe, maar niet thread-safe. De identificatie van een Diagnostic Client berust op het tuple van bronadres en globale channel-ID. [SWS_DM_00309] [SWS_DM_00310] [SWS_DM_00311] [SWS_DM_00312] [SWS_DM_00313] [SWS_DM_00314] [SWS_DM_00421]

functie HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

Literatuurverwijzingen SWS Diagnostics: [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
