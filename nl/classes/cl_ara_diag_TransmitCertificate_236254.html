klasse ara::diag::TransmitCertificate

[SWS_DM_01961] Upstream: RS_Diag_04251

class TransmitCertificate {...};

Class to implement the subfunction TransmitCertificate (29 04) of UDS service Authentication as interface to application. This class implements a so called generic interface, where the application has means to handle one ore more certificateEvaluationId transferred certificates.

Context

De klasse ara::diag::TransmitCertificate stelt de programmeerinterface voor de UDS-subfunctie TransmitCertificate (0x29 04) van de service Authentication (0x29) beschikbaar AUTOSAR_AP_SWS_Diagnostics §8.26.1 “Class: TransmitCertificate”. Ze implementeert een generieke interface waarmee een Adaptive-applicatie een of meer certificaten kan ontvangen en evalueren die worden geïdentificeerd door een 16-bits ID (certificateEvaluationId).

In de systeemarchitectuur fungeert ara::diag::TransmitCertificate als schakel tussen de AUTOSAR Adaptive Diagnostic Manager (DM) respectievelijk de Diagnostic Server Instance en de concrete applicatielogica. Een externe diagnosetester verzendt het UDS-authenticatieverzoek naar de server, die het verzoek na activering doorstuurt naar de applicatie [SWS_DM_01968], [SWS_DM_01251].

Contextdiagram: inbedding van TransmitCertificate tussen diagnosetester, Diagnostic Manager en applicatielogica. Bronnen: [SWS_DM_01968], [SWS_DM_01251], [SWS_DM_01249].

Levenscyclus

De instantiëring vindt plaats via de constructor onder opgave van een [SWS_DM_01962]:

  • specifier: Een ara::core::InstanceSpecifier die verwijst naar een PortPrototype die via een DiagnosticAuthenticationPortMapping wordt getypeerd [SWS_DM_01962].
  • concurrencyType: Bepaalt of de latere uitvoering van Process als thread-veilig (kConcurrent) of niet-thread-veilig (kNotConcurrent) wordt behandeld [SWS_DM_01962], [SWS_DM_01968].

Kopieer- en verplaatsoperaties zijn volledig uitgesloten: copy-constructor [SWS_DM_01964], move-constructor [SWS_DM_01963], copy-toewijzingsoperator [SWS_DM_01966] en move-toewijzingsoperator [SWS_DM_01965] zijn als verwijderd (=delete) gedeclareerd. Een authenticatie-interface-instantie bestaat zodoende als uniek gebonden object.

De levenscyclus is na de constructie onderverdeeld in twee operationele fasen:

  1. Beschikbaarstelling (Offered): Door het aanroepen van Offer() wordt de Diagnostic Manager geautoriseerd om binnenkomende UDS-berichten voor de subfunctie door te sturen naar de methode Process() [SWS_DM_01969].
  2. Intrekking (Stopped): De aanroep van StopOffer() maakt de registratie van de doorzending weer ongedaan [SWS_DM_01970].

De destructor is virtueel en als standaard gedeclareerd (noexcept = default) [SWS_DM_01967]. Terwijl de constructor thread-veilig is, zijn Offer() en StopOffer() gespecificeerd als niet thread-veilig en mogen ze niet ongecoördineerd gelijktijdig worden aangeroepen [SWS_DM_01962], [SWS_DM_01969], [SWS_DM_01970].

Gebruikspad

Het reguliere operationele proces omvat de registratie bij de Diagnostic Manager, het asynchroon ontvangen van de certificaatgegevens en de voltooiing van de verwerking:

  1. Instantiëring en vrijgave: De applicatie instantieert de afgeleide klasse en activeert de acceptatie via Offer() [SWS_DM_01962], [SWS_DM_01969].
  2. Ontvangst en verwerking: Bij ontvangst van een UDS-verzoek stuurt de Diagnostic Server de gegevens via Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler) door [SWS_DM_01968]. De methode retourneert een ara::core::Future<void>, waardoor een asynchrone verwerking wordt ondersteund. De concrete semantiek en evaluatie van het certificaat berust volledig bij de applicatie [SWS_DM_01968].
  3. Afhandeling van afbreken: De applicatie kan via cancellationHandler.IsCanceled() controleren of de diagnoseconversatie is afgebroken, of via cancellationHandler.SetNotifier() een notificatiecallback voor afbreekgebeurtenissen registreren [SWS_DM_01968].
  4. Positieve terugkoppeling: Als de uitvoering succesvol zonder foutcode eindigt, verzendt de Diagnostic Server Instance een positief UDS-antwoord met de retourparameter authenticationReturnParameter = 0x13 (CertificateVerified) naar de tester [SWS_DM_01251].
  5. Opruimen: Bij beëindiging wordt de ontvangst via StopOffer() beëindigd [SWS_DM_01970].

Sequentiediagram: Typisch verloop van de certificaatoverdracht en -verwerking. Bronnen: [SWS_DM_01969], [SWS_DM_01968], [SWS_DM_01251], [SWS_DM_01970].

Foutscenario's

Zowel bij de initialisatie als tijdens het lopende bedrijf zijn specifieke foutcondities gedefinieerd:

  • Manifest- en modelleringsfouten bij het aanmaken: De constructor meldt schendingen wanneer de InstanceSpecifier niet kan worden opgelost (InstanceSpecifierMappingIntegrityViolation), de gerefereerde PortPrototype niet door een DiagnosticTransmitCertificateInterface is getypeerd (PortInterfaceMappingViolation), er geen procestoewijzing bestaat (ProcessMappingViolation) of de InstanceSpecifier in het proces al is vergeven (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01962].
  • Meervoudige aanmelding: Een hernieuwde aanroep van Offer() bij een reeds actieve beschikbaarstelling leidt tot de fout DiagOfferErrc::kAlreadyOffered met rollback-semantiek [SWS_DM_01969].
  • Afwijzing in Process: Mislukt de verificatie van het certificaat in de applicatie of treedt er een verwerkingsfout op, dan geeft Process() een overeenkomstige fout via het ara::core::Future terug. Hierbij dient een passende UDS-Negative-Response-Code (NRC) conform ISO 14229-1 via DiagUdsNrcErrc te worden gebruikt [SWS_DM_01968]. De Diagnostic Server Instance genereert vervolgens een negatief UDS-antwoord (NRC) aan de externe tester [SWS_DM_01249].

Deze handleiding is gebaseerd op de AUTOSAR Adaptive Platform R25-11-specificatie voor de module Diagnostics.

<h4>Context</h4>
<p>
De klasse <code>ara::diag::TransmitCertificate</code> stelt de programmeerinterface voor de UDS-subfunctie <em>TransmitCertificate</em> (<code>0x29 04</code>) van de service <em>Authentication</em> (<code>0x29</code>) beschikbaar <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=522">AUTOSAR_AP_SWS_Diagnostics §8.26.1 “Class: TransmitCertificate”</a>. </p>

<h4>Gebruikspad</h4>
<p>

</p>
<ol>
<li><strong>Instantiëring en vrijgave:</strong> De applicatie instantieert de afgeleide klasse en activeert de acceptatie via <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Ontvangst en verwerking:</strong> Bij ontvangst van een UDS-verzoek stuurt de Diagnostic Server de gegevens via <code>Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler)</code> door <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. De methode retourneert een <code>ara::core::Future&lt;void&gt;</code>, waardoor een asynchrone verwerking wordt ondersteund. De concrete semantiek en evaluatie van het certificaat berust volledig bij de applicatie <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Afhandeling van afbreken:</strong> De applicatie kan via <code>cancellationHandler.IsCanceled()</code> controleren of de diagnoseconversatie is afgebroken, of via <code>cancellationHandler.SetNotifier()</code> een notificatiecallback voor afbreekgebeurtenissen registreren <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Positieve terugkoppeling:</strong> Als de uitvoering succesvol zonder foutcode eindigt, verzendt de Diagnostic Server Instance een positief UDS-antwoord met de retourparameter <code>authenticationReturnParameter = 0x13</code> (<em>CertificateVerified</em>) naar de tester <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>.</li>
<li><strong>Opruimen:</strong> Bij beëindiging wordt de ontvangst via <code>StopOffer()</code> beëindigd <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>
