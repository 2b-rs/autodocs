Context

De klasse ara::crypto::x509::CertificateValidationCtx biedt de validatiecontext voor X.509-certificaten en certificaatpaden conform RFC 5280 ([SWS_CRYPT_50122], [SWS_CRYPT_50123]). Binnen de module crypto van het Adaptive Platform bundelt zij de configuratie, vertrouwde rootcertificaten, tussencertificaten en verificatieregels, en voert zij de cryptografische padvalidatie uit.

Bij de validatieprocessen zijn hoofdzakelijk de volgende componenten en datatypen betrokken:

  • Applicatie: Configureert de context via validatieopties ([SWS_CRYPT_50120]), stelt indien nodig de referentietijd in ([SWS_CRYPT_50121]), registreert vertrouwensankers en start de verificatie.
  • Certificaten (Certificate): Vormen de vertrouwensbasis en de te controleren objecten. Er wordt onderscheid gemaakt tussen vertrouwde certificaten ([SWS_CRYPT_50117]), niet-vertrouwde tussencertificaten voor de padconstructie ([SWS_CRYPT_50118]) en doelcertificaten ([SWS_CRYPT_50122]) of certificaatketens ([SWS_CRYPT_50123]).
  • OCSP-antwoorden (OcspResponse): Dienen als bewijs van de intrekkingsstatus van certificaten en worden aan de validatiecontext doorgegeven om in aanmerking te worden genomen ([SWS_CRYPT_50124]).
  • Validatieresultaat (CertificateValidationResult): Kapselt na voltooide controle het gedetailleerde resultaat van het RFC 5280-padvalidatieproces in ([SWS_CRYPT_50122], [SWS_CRYPT_50123]).

Contextdiagram: interactiepartners van de CertificateValidationCtx bij de certificaat- en padverificatie. Bronnen: [SWS_CRYPT_50117], [SWS_CRYPT_50118], [SWS_CRYPT_50122], [SWS_CRYPT_50123], [SWS_CRYPT_50124]

Levenscyclus

Voor het bezit en de overdracht van contextinstanties stelt de interface de type-alias Sptr als std::shared_ptr<CertificateValidationCtx> beschikbaar ([SWS_CRYPT_50116]). Aangezien de klasse zuiver virtuele methoden definieert, vindt de instantiëring van de concrete implementatie vermoedelijk plaats via een bovenliggende factory- of providerklasse van de cryptostack.

Na het aanmaken bevindt de context zich in een configureerbare toestand. De applicatie registreert stapsgewijs opties ([SWS_CRYPT_50120]), certificaten ([SWS_CRYPT_50117], [SWS_CRYPT_50118]), OCSP-antwoorden ([SWS_CRYPT_50124]) of OID's van te negeren kritieke extensies ([SWS_CRYPT_50119]). Het resetten van afzonderlijke registraties is niet voorzien; voor verschillende validatiedomeinen worden afzonderlijke contexten geïnstantieerd.

Wat betreft gelijktijdigheid en fouttolerantie zijn alle virtuele lidfuncties van de interface expliciet gespecificeerd als thread-veilig (thread-safe) en uitzonderingsveilig (exception safe) ([SWS_CRYPT_50117] tot [SWS_CRYPT_50124]). Instanties kunnen zodoende gelijktijdig door meerdere threads worden gebruikt.

Gebruikspad

Het typische gebruik van CertificateValidationCtx volgt een vaste volgorde van configuratie, vulling en uitvoering:

  1. Configuratie vastleggen: Middels SetValidationOptions wordt een bitmasker doorgegeven dat de uit te voeren controles definieert ([SWS_CRYPT_50120]). Optioneel kan via SetCurrentTime een expliciet referentietijdstip voor de geldigheidscontrole worden gekozen ([SWS_CRYPT_50121]); als deze functie niet wordt aangeroepen, gebruikt de context de standaardsysteemtijd. Indien applicatiespecifiek gevalideerde kritieke extensies moeten worden getolereerd, worden de OID's daarvan via IgnoreCriticalExtension vastgelegd ([SWS_CRYPT_50119]).
  2. Certificaten en statusgegevens registreren: Via AddTrustedCertificate worden de bepalende vertrouwensankers (root-CA's) toegevoegd ([SWS_CRYPT_50117]). Om het vinden van het pad te vergemakkelijken, kunnen via AddUntrustedCertificate tussencertificaten worden ingevoerd ([SWS_CRYPT_50118]). Als intrekkingsinformatie moet worden meegenomen, worden OCSP-antwoorden via AddOcspResponse toegevoegd ([SWS_CRYPT_50124]).
  3. Validatie uitvoeren: De controle vindt plaats via een van twee methoden:
    • ValidateCertificate controleert een afzonderlijk end-entity-certificaat en bouwt het pad op met behulp van de in de context vastgelegde vertrouwde en niet-vertrouwde certificaten ([SWS_CRYPT_50122]).
    • ValidateCertificateChain valideert een aanwezige keten als ara::core::Span ([SWS_CRYPT_50123]). Element 0 stelt daarbij het bladcertificaat voor en elk opeenvolgend element de respectieve uitgever. In deze modus worden certificaten die eerder via AddUntrustedCertificate zijn vastgelegd genegeerd; de validatie controleert de overgedragen keten uitsluitend tegen de via AddTrustedCertificate ingestelde vertrouwensankers.
  4. Resultaat evalueren: Beide validatiefuncties geven bij succes een CertificateValidationResult::Sptrc terug voor het evalueren van de gedetailleerde resultaten ([SWS_CRYPT_50122], [SWS_CRYPT_50123]).

Sequentiediagram: typische aanroepvolgorde voor configuratie, registratie van certificaten en uitvoering van de validatie. Bronnen: [SWS_CRYPT_50117], [SWS_CRYPT_50120], [SWS_CRYPT_50121], [SWS_CRYPT_50122], [SWS_CRYPT_50123], [SWS_CRYPT_50124]

Foutscenario's

Alle operaties geven fouten terug via ara::core::Result. Gestandaardiseerde foutcodes en specifieke voorwaarden omvatten:

  • Incompatibele argumenten (ara::crypto::CryptoErrc::kIncompatibleArguments): Treedt op bij ValidateCertificate ([SWS_CRYPT_50122]) en ValidateCertificateChain ([SWS_CRYPT_50123]) wanneer weliswaar via AddOcspResponse ([SWS_CRYPT_50124]) een OCSP-antwoord is vastgelegd, maar de via SetValidationOptions ([SWS_CRYPT_50120]) ingestelde opties geen overeenkomstig OCSP-gedrag definiëren. Beide functies hebben rollback-semantiek.
  • Ongeldige configuratieopties (ara::crypto::CryptoErrc::kInvalidArgument): Als SetValidationOptions ([SWS_CRYPT_50120]) wordt aangeroepen met een ongeldig bitmasker, mislukt de aanroep onder rollback-semantiek.
  • Validatiefouten bij OCSP-antwoorden: Voor AddOcspResponse ([SWS_CRYPT_50124]) moet de uitgever van het OCSP-antwoord ofwel vooraf in de context als vertrouwd of niet-vertrouwd zijn vastgelegd, zijn ondertekend door een certificaat met de Extended-Key-Usage id-kp-OCSPSigning van dezelfde CA, of via het optionele argument trustedOcspIssuerCertificate worden meegegeven. De geretourneerde Result<CertificateValidationStatus> signaleert kValid bij succesvolle overname of levert de concrete validatiestatus van het OCSP-antwoord.
  • Implementatiespecifieke fouten: Alle methoden kunnen bij interne fouten of systeemgrenzen implementatiespecifieke foutcodes in Result retourneren ([SWS_CRYPT_50117] tot [SWS_CRYPT_50124]).

Deze handleiding is gebaseerd op de specificatie AUTOSAR Adaptive R25-11 voor de module crypto.

AddOcspResponse functie

Validate and add an OCSP response to be used during certificate validation to the set of previously added OCSP responses. Multiple OCSP responses may be added to one context. In order to validate the OCSP response, the issuer of the OCSP response must have been a) set as a trusted or untrusted certificate in this context previously, or b) the CRL must have been signed by another certificate that has the id-kp-OCSPSigning extended key usage set issued by the same CA, or c) the CRL must be signed by a trusted CA passed to this function using the optional trustedOcspIssuerCertificate parameter.

Configure the context to ignore an extension during validation of certificates and OCSP responses, even if the extension is marked as critical and the validation context does not support the extension. It is the responsibility of the application to validate such extensions. Multiple invocations of this function lead to ignoring all passed extensions. This function has no effect if the kIgnoreUnknownCriticalExtensions validation option is set.

Performs certificate path validation according to RFC 5280 and according to the previous configuration of the context.
