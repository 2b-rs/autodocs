klasse ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

Kapselt een loggingcontext in voor het thread-veilige vastleggen van geformatteerde of gemodelleerde logberichten.

De klasse ara::log::Logger vertegenwoordigt een context voor het vastleggen van logberichten binnen een applicatieproces via tijdelijke streams of gemodelleerde berichtformaten [SWS_LOG_00064]. Aangezien de standaardconstructor is verwijderd, worden de creatie en het beheer van de levenscyclus volledig door het logging-framework afgehandeld [SWS_LOG_00259]. Vóór de tijdrovende voorbereiding van berichtgegevens kan het momenteel actieve meldingsniveau worden opgevraagd. Alle interfaces van de klasse zijn thread-veilig gespecificeerd en maken synchronisatievrije aanroepen vanuit meerdere threads mogelijk.

Context

De klasse ara::log::Logger vertegenwoordigt een loggercontext binnen een applicatieproces of procesbereik in de module log. Een dergelijke context omvat een specifieke context-ID, een bijbehorende beschrijving en een standaard logniveau. Applicatieontwikkelaars communiceren met loggerinstanties om logberichten hetzij via stream-objecten zoals LogStream [SWS_LOG_00064], hetzij als gestructureerde, gemodelleerde berichten aan het logging-framework door te geven [SWS_LOG_00204]. De instanties fungeren als tussenpersoon tussen de applicatie-interne threads en de logging-backend.

Contextdiagram: integratie van de logger tussen applicatie, logging-framework en LogStream. Bronnen: [SWS_LOG_00064], [SWS_LOG_00259].

Levenscyclus

Het beheer van de instanties is onderworpen aan strikt eigenaarschap door het logging-framework. Om de automatische registratie bij de logging-backend tijdens het aanmaken en de deregistratie bij het afsluiten van het applicatieproces te waarborgen, is de standaardconstructor verwijderd [SWS_LOG_00259]. Applicaties mogen en kunnen Logger-objecten niet rechtstreeks instantiëren, maar moeten in plaats daarvan de aanmaakfuncties ara::log::CreateLogger gebruiken. Het vernietigen en vrijgeven vindt plaats via de destructor [SWS_LOG_00260], die wordt bestuurd door het logging-framework, zodat gebruikers zich niet hoeven te bekommeren om de levensduur.

Wat betreft gelijktijdigheid zijn alle toegangsmethoden gespecificeerd als thread-veilig (thread-safe), waaronder [SWS_LOG_00070], [SWS_LOG_00255] en [SWS_LOG_00260]. Hierdoor kunnen meerdere gelijktijdige threads dezelfde loggercontext tegelijkertijd gebruiken, zonder dat aanvullende synchronisatiemechanismen aan de applicatiezijde vereist zijn.

Gebruikspad

Het typische gebruik van een logger omvat het controleren van de actuele configuratie, het aanpassen van drempelwaarden en het verzenden van berichten:

  • Controle van de uitvoerbevoegdheid: vóór kostbare voorbereidingen van loggegevens kan met IsEnabled worden opgevraagd of een gewenst logniveau actief wordt gerapporteerd [SWS_LOG_00070].
  • Configuratie: de minimale rapportagedrempel van een loggerinstantie kan tijdens runtime opnieuw worden geconfigureerd via SetThreshold [SWS_LOG_00255].
  • Stream-gebaseerde logging: via specifieke methoden voor afzonderlijke ernstgraden – LogFatal [SWS_LOG_00064], LogError [SWS_LOG_00065], LogWarn [SWS_LOG_00066], LogInfo [SWS_LOG_00067], LogDebug [SWS_LOG_00068] of LogVerbose [SWS_LOG_00069] – evenals via de dynamische WithLevel [SWS_LOG_00131] wordt een LogStream-object gegenereerd. Dit ontvangt gegevens via de operator <<. Gewoonlijk eindigt de levensduur van het stream-object met de puntkomma van het statement [SWS_LOG_00064].
  • Gemodelleerde berichten: als alternatief kunnen getypeerde en gemodelleerde berichten rechtstreeks met Log [SWS_LOG_00204] of onder vermelding van attributen met LogWith [SWS_LOG_00133] worden doorgegeven.

Sequentiediagram: typische volgorde bij de drempelwaardecontrole en stream-gebaseerde logging. Bronnen: [SWS_LOG_00070], [SWS_LOG_00067], [SWS_LOG_00064].

Foutscenario's

De interfaces van de klasse zijn grotendeels gespecificeerd als noexcept en uitzonderingsveilig (exception safe), wat onverwachte runtime-onderbrekingen minimaliseert [SWS_LOG_00070], [SWS_LOG_00255]. Desondanks bestaan er formele foutcondities en randgevallen:

  • Onjuiste modelparameters: als Log wordt aangeroepen met argumenten die niet overeenkomen met de specificatie van het gemodelleerde bericht, is het C++-programma onjuist opgebouwd (ill-formed) en faalt dit tijdens de compilatie [SWS_LOG_00204].
  • Ontbrekende attribuuteigenschappen: bevat het tuple voor LogWith typen die niet voldoen aan de vereiste attribuutciteria, dan neemt de functie niet deel aan overbelastingsresolutie [SWS_LOG_00133]. Het verbergen gebeurt vermoedelijk via SFINAE of concepten.
  • Uitzonderingsveiligheid bij afbraak: de destructor ~Logger is gedeclareerd als not exception safe [SWS_LOG_00260]. Dit is vermoedelijk toe te schrijven aan het feit dat bij het deregistreren bij de logging-backend fouten kunnen optreden die niet via uitzonderingen mogen worden gepropageerd.
