klasse ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Dient voor het gebufferd schrijven van binaire en tekstbestanden en de synchronisatie daarvan naar het fysieke geheugen.

De klasse ara::per::WriteAccessor maakt het schrijven van binaire of tekstuele bestandsinhoud in de persistoriemodule mogelijk en stelt methoden voor ongeformatteerde schrijftoegangen evenals een geformatteerde stream-operator ter beschikking [SWS_PER_00423]. Omdat schrijfacties eerst in het besturingssysteem kunnen worden gebufferd, dwingt de aanroep van SyncToFile() het permanent flashen naar het fysieke geheugen af [SWS_PER_00122]. Alle methoden zijn exception-safe, maar niet thread-safe, waardoor gelijktijdige toegangen door de applicatie moeten worden beschermd.

Context

ara::per::WriteAccessor is een finale klasse van de persistoriemodule (per) van het AUTOSAR Adaptive Platform en leidt virtueel af van FileAccessor. De klasse stelt schrijfbewerkingen voor bestandsinhoud ter beschikking. Zij biedt methoden voor ongeformatteerd, gecontroleerd schrijven met foutafhandeling via ara::core::Result evenals een overbeladen stream-operator voor geformatteerd schrijven. Als interactiepartners fungeren de aanroepende applicatie, de interne bestandsbuffer van het besturingssysteem en het fysieke opslagmedium.

Levenscyclus

De standaardconstructor van WriteAccessor is expliciet verwijderd en mag niet worden gebruikt [SWS_PER_00596]. (Interpretatie: instanties van WriteAccessor worden vermoedelijk aangemaakt en ter beschikking gesteld via factory-methoden van bovenliggende persistentiebeheereenheden zoals file-storage.) Vraag Q-af92be8494274611 (open)

De vernietiging vindt plaats via de virtuele destructor ~WriteAccessor() [SWS_PER_00597]. De klasse en haar methoden zijn gespecificeerd als exception-safe (“exception safe”) en gedeclareerd als noexcept. Met betrekking tot gelijktijdigheid is WriteAccessor niet thread-safe (“not thread-safe”) [SWS_PER_00597]; parallelle toegangen tot dezelfde instantie moeten extern door de applicatie worden beveiligd.

Gebruikspad

Het reguliere verloop omvat het schrijven van gegevens in ongeformatteerde of geformatteerde modus, het optioneel aanpassen van de bestandsgrootte en de uiteindelijke persistente opslag:

  • Binaire gegevens schrijven: via WriteBinary() wordt een bytebereik (ara::core::Span<const ara::core::Byte>) naar het bestand geschreven [SWS_PER_00423].
  • Tekstgegevens schrijven: met behulp van WriteText() worden tekenreeksen via een ara::core::StringView doorgegeven [SWS_PER_00166]. Aanvullend is operator<< beschikbaar als gemakkelijke functie voor niet-kritische usecases, waarbij optredende fouten stilzwijgend worden genegeerd [SWS_PER_00125].
  • Persisteren afdwingen: het tijdstip van fysieke opslag hangt af van de persistentie-implementatie; SyncToFile() flasht de buffer van het besturingssysteem bindend naar het opslagmedium [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Bestandsgrootte aanpassen: met SetFileSize() kan het bestand worden ingekort, waardoor overtollige inhoud wordt verwijderd; de bestandspositie blijft ongewijzigd of wordt op de laatste geldige positie respectievelijk 0 gezet [SWS_PER_00428].

Sequentiediagram: schrijfbewerkingen met aansluitende synchronisatie naar het fysieke geheugen. Bronnen: [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Foutscenario's

De methoden WriteBinary(), WriteText(), SyncToFile() en SetFileSize() retourneren een ara::core::Result<void> die bij mislukkingen specifieke foutcodes bevat:

  • PerErrc::kPhysicalStorageFailure: toegang tot het fysieke opslagmedium mislukt [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. De toestand van het bestand is onbekend en kan volledig beschadigd zijn (geen rollback-semantiek).
  • PerErrc::kOutOfStorageSpace: onvoldoende fysieke opslagruimte [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. Bij het schrijven wordt het overschrijdende deel verworpen en staat de positie aan het bestandseinde (geen rollback-semantiek).
  • PerErrc::kQuotaExceeded: het bestand zou de geconfigureerde maximale grootte (AllowedSize) overschrijden [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (rollback-semantiek).
  • PerErrc::kEncryptionFailed: versleuteling of ontsleuteling mislukt [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Buffer en positie worden weliswaar bijgewerkt, maar het bestand kan niet worden gepersisteerd en weerspiegelt op het geheugen een oudere versie (rollback-semantiek).
  • PerErrc::kAuthenticationFailed: berekening of controle van de MAC mislukt [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (rollback-semantiek).
  • PerErrc::kValidationFailed: geldigheid van de opgeslagen gegevens kan niet worden gewaarborgd [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (rollback-semantiek).
  • PerErrc::kInvalidSize: de nieuwe bestandsgrootte bij SetFileSize() is groter dan de huidige bestandsgrootte [SWS_PER_00428] (rollback-semantiek).

WriteBinary functie

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.
