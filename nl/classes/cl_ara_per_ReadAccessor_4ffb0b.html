klasse ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Maakt het bloksgewijs, regelsgewijs of tekengebaseerd lezen van gepersisteerde bestands- en binaire gegevens mogelijk.

De klasse ara::per::ReadAccessor stelt synchrone methoden voor het sequentiële en regelgebaseerde lezen van bestanden in binaire en tekstmodus beschikbaar [SWS_PER_00421], [SWS_PER_00119]. Naast consumerend lezen maakt zij een pointerneutrale preview van volgende bytes of tekens mogelijk. Aangezien instanties niet thread-safe zijn, moeten parallelle toegangen extern worden gecoördineerd, terwijl bij fouten een rollback-garantie de leespointerpositie beschermt [SWS_PER_00419].

Context en taakgebied

De klasse ara::per::ReadAccessor biedt een interface voor het synchroon lezen van bestandsinhoud binnen het persistencebeheer (module per) en leidt virtueel af van FileAccessor. Zij abstraheert de leestoegang tot gepersisteerde gegevensopslag en biedt zowel binaire als tekstuele toegangsmethoden. Applicaties kunnen via gespecialiseerde functies afzonderlijke bytes of tekens controleren en opvragen, evenals aaneengesloten blokken of volledige regels inlezen.

Levenscyclus en concurrency

De standaardconstructor van ReadAccessor is verwijderd [SWS_PER_00461]; de instantiatie vindt daarom typisch plaats via overkoepelende openings- en toegangsmechanismen van de persistencemodule. De vrijgave van de interface en de gebonden toegangsbronnen geschiedt via de virtuele destructor ~ReadAccessor() [SWS_PER_00417]. Instanties van ReadAccessor bezitten een interne leespointer die de huidige positie in het bestand beheert. Alle methoden van de klasse zijn expliciet gespecificeerd als niet thread-safe (not thread-safe) [SWS_PER_00419], waardoor gelijktijdige leesbewerkingen op dezelfde instantie extern door aanroepers moeten worden gesynchroniseerd.

Gebruikspaden voor binaire en tekstuele gegevens

Voor binaire bestandsbewerkingen biedt de klasse functies voor voorzienbaar of sequentieel uitlezen. Met PeekByte() kan de byte op de huidige leespositie worden geïnspecteerd zonder de leespointer te wijzigen [SWS_PER_00418]. Daarentegen leest GetByte() precies één byte uit en schuift de positie op [SWS_PER_00419]. Grotere datablokken kunnen via ReadBinary(n) in een ara::core::Vector<ara::core::Byte> worden ingelezen, waarbij de positie dienovereenkomstig wordt aangepast; wordt het bestandseinde voortijdig bereikt, dan bevat de vector minder bytes dan gevraagd [SWS_PER_00422]. Middels ReadBinary() kunnen alle resterende bytes tot aan het einde van het bestand in één stap worden opgehaald [SWS_PER_00421].

Sequentiediagram: Typisch verloop van een sequentiële leestoegang met voorafgaande controle en stapsgewijze gegevensverwerking. Bronnen: [SWS_PER_00418], [SWS_PER_00422], [SWS_PER_00421].

In tekstmodus biedt PeekChar() een tekengebaseerde preview [SWS_PER_00167], terwijl GetChar() het volgende teken consumeert [SWS_PER_00168]. Het regelsgewijs lezen vindt plaats via ReadLine(), die tot aan een scheidingsteken leest (standaard: '\n', ASCII 0x0a); het scheidingsteken wordt daarbij niet in de resultaatstring opgenomen [SWS_PER_00119]. Gedeelten van n tekens of de gehele resterende inhoud kunnen via de overloads van ReadText() worden uitgelezen [SWS_PER_00165], [SWS_PER_00420]. Bevindt de leespointer zich midden in een multibyte-teken, dan kunnen de resulterende tekenreeksen onvolledige Unicode-codepunten bevatten [SWS_PER_00119], [SWS_PER_00165].

Foutscenario's en foutafhandeling

Alle leesoperaties van ReadAccessor leveren hun waarden ingekapseld in een ara::core::Result op en zijn gespecificeerd als uitzonderingsveilig (exception safe) [SWS_PER_00419]. Als er tijdens een toegang een fout optreedt, geldt een strikte rollbacksemantiek: de actuele positie van de leeswijzer blijft in geval van een fout altijd ongewijzigd [SWS_PER_00421], [SWS_PER_00422]. Typische gedocumenteerde fouttoestanden omvatten:

  • PerErrc::kPhysicalStorageFailure bij fouten van het fysieke opslagmedium [SWS_PER_00419], [SWS_PER_00420],
  • PerErrc::kEof als de leeswijzer aan het einde van het bestand staat of het bestand leeg is [SWS_PER_00419], [SWS_PER_00168],
  • PerErrc::kValidationFailed wanneer de geldigheid van de gegevens niet kan worden geverifieerd [SWS_PER_00418], [SWS_PER_00119],
  • PerErrc::kEncryptionFailed bij mislukte ontsleuteling [SWS_PER_00419], [SWS_PER_00422] evenals
  • PerErrc::kAuthenticationFailed voor zover de MAC-controle van opgeslagen gegevens mislukt [SWS_PER_00167], [SWS_PER_00421].

Deze handleiding is gebaseerd op de specificatie AUTOSAR Adaptive R25-11 en is geautomatiseerd gegenereerd.

ReadLine functie

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ara::core::Result< ara::core::String > ReadLine (char delimiter=’\n’) noexcept;
ReadText functie 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.

              Gebruik
              

              De functie heeft de signatuur ara::core::Result<char> PeekChar() const noexcept;. Deze werkt synchroon, is gedeclareerd als const en garandeert uitzonderingsveiligheid (exception safe) [SWS_PER_00167]. Als retourwaarde dient een ara::core::Result<char>, die bij succes het uitgelezen teken bevat [SWS_PER_00167].
              

              Foutafhandeling
              

              Treedt er een fout op, dan levert de ara::core::Result fabrikantspecifieke fouten of een van de volgende foutcodes uit PerErrc [SWS_PER_00167]:
              

                

              • PerErrc::kEof: De huidige leespositie heeft het bestandseinde bereikt of het bestand is leeg [SWS_PER_00167].
                • 

              • PerErrc::kPhysicalStorageFailure: De toegang tot het fysieke opslagmedium is mislukt [SWS_PER_00167].
                • 

              • PerErrc::kValidationFailed: De geldigheid van de opgeslagen gegevens kan niet worden gewaarborgd [SWS_PER_00167].
                • 

              • PerErrc::kEncryptionFailed: De ontsleuteling van de opgeslagen gegevens is mislukt [SWS_PER_00167].
                • 

              • PerErrc::kAuthenticationFailed: De controle van de Message Authentication Code (MAC) van de gegevens is mislukt [SWS_PER_00167].
                • 

              

              Gelijktijdigheid en beperkingen
              

              De bewerking is niet thread-safe (not thread-safe) [SWS_PER_00167]. Daarom moeten parallelle toegangen tot dezelfde ReadAccessor-instantie door de aanroeper worden gesynchroniseerd.
