Gebruiksdoel

SovdAuthorization implementeert de SOVD-autorisatie op applicatieniveau. GetAuthorizationUrl() en GetTokenUrl() leveren de URL voor autorisatie resp. token-aanvraag; de DM antwoordt daarop met HTTP 307 en een location-header met deze URL. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] ValidateAuthorization() valideert het token uit de HTTP-authorization-header en markeert de geautoriseerde rollen in de doorgegeven ClientAuthentication. [SWS_DM_01483] [SWS_DM_01470]

Aanmaak & levenscyclus

De constructor koppelt een PortPrototype van de DiagnosticSovdAuthorizationInterface en neemt de ConcurrencyType aan. [SWS_DM_01489] Offer() activeert de doorschakeling, StopOffer() deactiveert deze weer. Offer kan kAlreadyOffered of kConfigurationMismatch leveren. [SWS_DM_01487] [SWS_DM_01486] De destructor is exception-safe. [SWS_DM_01488]

Beperkingen & foutafhandeling

Na het beschikbaar stellen van de Future mag de applicatie het gerefereerde ClientAuthentication-object niet meer gebruiken. [SWS_DM_01483] Een succesvolle retourwaarde staat de DM toe rollen tot validUntil voor hetzelfde token als geauthenticeerd te behandelen. [SWS_DM_01469] De validatie kan kInvalidAccessToken of kTemporarilyNotAvailable melden. [SWS_DM_01483] URL- en validatiebewerkingen zijn afhankelijk van de ConcurrencyType; Offer en StopOffer zijn niet thread-safe. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01483] [SWS_DM_01487] [SWS_DM_01486]

De DM verifieert een autorisatie opnieuw als het token niet identiek is aan een eerder gecontroleerd token dat nog geldig is. [SWS_DM_01470] Bij hetzelfde token tot validUntil en dezelfde teruggeleverde identiteit kan hij de client als identiek behandelen. [SWS_DM_01781] [SWS_DM_01782] De URL-methoden ontvangen de queryparameters en MetaInfo van het verzoek en retourneren elk asynchroon een string. [SWS_DM_01484] [SWS_DM_01485]

SOVD-toegangscontext

De SOVD-autorisatie gebruikt OAuth-tokens in de request-header. Bij een dergelijk verzoek gebruikt de Diagnostic Manager SovdAuthorization om de gecodeerde autorisatierol bij de applicatie op te vragen; op grond van deze rol beslist hij over de bevoegdheid voor de aangevraagde SOVD-operatie. functie ValidateAuthorization [SWS_DM_01483] Upstream: RS_Diag_04268

virtual ara::core::Future< ValidateAuthorizationOutput > Validate Authorization (ara::core::StringView token, const MetaInfo &metaInfo, ClientAuthentication &clientAuthentication) noexcept=0;

This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.

Gebruik Door AI gegenereerd

Automatisch gegenereerde gebruiksaanwijzing, afgeleid uit dit AUTOSAR-R25-11-specificatie-element — geen officiële AUTOSAR-tekst. Bewijs: [SWS_…].

De virtuele methode ValidateAuthorization valideert het door een SOVD-client via de HTTP-Authorization-header verzonden token (token) volgens het in het systeem gebruikte autorisatieprotocol; bij OAuth 2.0 komt dit overeen met de controle door de resource server. Op basis van het resultaat markeert de applicatie de betreffende rollen in het via parameter clientAuthentication doorgegeven object als geautoriseerd [SWS_DM_01483]. Daarnaast wordt de metaInfo van de diagnosepoort doorgegeven. De teruggegeven ara::core::Future<ValidateAuthorizationOutput> levert bij succes het validatieresultaat, anders een fout.

Foutafhandeling & concurrency

Is het toegangstoken ongeldig, wordt DiagSovdErrc::kInvalidAccessToken geleverd; kan het momenteel niet gecontroleerd worden (bijvoorbeeld omdat een online verificatie nodig is, maar de authenticatieserver niet bereikbaar is), wordt DiagSovdErrc::kTemporarilyNotAvailable geleverd. Nadat het future is vervuld, mag clientAuthentication niet meer door de applicatie worden gebruikt. Of de implementatie thread-safe of niet-thread-safe moet zijn, wordt bepaald door de in de constructor doorgegeven ConcurrencyType; de methode is exception-safe.
