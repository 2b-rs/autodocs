Can_ConfigType type

Dit is het type van de extern gegevensstructuur containing de overall initialisatie gegevens voor de CAN stuurprogramma en SFR instellingen affecting alle controllers. Furthermore het bevat pointers naar controller configuratie structures. de inhoud van de initializ ation gegevensstructuur zijn CAN hardware specifiek.

Can_ControllerStateType type

toestanden dat worden gebruikt door de meerdere controller modus functies.

Can_ErrorStateType type

fout toestanden van een CAN controller.

Can_ErrorType type

de enumeratie vertegenwoordigt een superset van CAN fout typen die typical CAN HW is able om te rapporteren. dat means niet alle CAN HW zal zijn able naar ondersteuning de volledig instellen.

Can_HwHandleType type

vertegenwoordigt de hardware object handelt af van een CAN hardware eenheid. voor CAN hardware eenheden met meer dan 255 HW objecten use extended bereik.

Can_HwType type

Dit type definieert een gegevensstructuur die clearly biedt een hardware object handle met inbegrip van zijn corresponderende CAN controller en daarom Can Drv evenals de specifiek Can Id.

Can_IdType type

vertegenwoordigt de identificatie van een L - PDU. de twee de meeste significant bits specify het frame type: 00 CAN bericht met standaard CAN ID 01 CAN FD frame met standaard CAN ID 10 CAN bericht met Extended CAN ID 11 CAN FD frame met Extended CAN ID

Can_PduType type

Dit type unites Pdu Id (sw Pdu handle), Sdu lengte (lengte), Sdu gegevens (sdu), en Can Id (id) voor elke CAN L - SDU.

Systeemarchitectuur en rol van het modulecluster

Het cluster 'CAN Communication' omvat de CAN-stack van het Classic Platform, van de controllerhardware tot de transportlaag.

  • Can (CAN Driver): kapselt de controllerhardware in. Hij schrijft L-PDU's met Can_Write naar hardware-objecten [SWS_Can_00233]. Daarbij wordt een Can_PduType-structuur overgedragen die bestaat uit swPduHandle, lengte, data en CAN-ID [SWS_Can_00415].

Foutafhandeling, DET-tracing en degradatie

Ontwikkelfouten: alle modules melden deze aan DET. De foutcodes zijn per module getabelleerd: Can [SWS_Can_91019], CanIf [SWS_CANIF_91006], CanTp [SWS_CanTp_00293], CanTrcv [SWS_CanTrcv_00050]. Typisch zijn controles op ongeldige ID's en pointers, bijvoorbeeld in CanIf_SetControllerMode [SWS_CANIF_00311] of CanIf_RxIndication [SWS_CANIF_00416]. Vóór de initialisatie weigeren CanIf-services het normale bedrijf met E_NOT_OK [SWS_CANIF_00661]; CanTp meldt in dat geval CANTP_E_UNINIT [SWS_CanTp_00031].

Runtimefouten gaan naar Det_ReportRuntimeError [SWS_CANIF_91007] [SWS_CanTrcv_91006]. Voorbeelden:

  • een mislukte lengtecontrole [SWS_CANIF_00168]
  • zenden op een offline kanaal [SWS_CANIF_00382]
  • ontbrekende communicatie naar de transceiver [SWS_CanTrcv_00114]

Productiefouten gaan naar DEM. CanTrcv_MainFunctionDiagnostics meldt CANTRCV_E_BUS_ERROR bij gezette BUSERR-vlag als FAILED. Bij geresette vlag meldt deze de gebeurtenis dienovereenkomstig terug [SWS_CanTrcv_00206] [SWS_CanTrcv_00227]. De functie bestaat alleen bij CanTrcvBusErrFlag = TRUE [SWS_CanTrcv_00205]. CanIf meldt productiefouten alleen bij de activerende gebeurtenis [SWS_CANIF_00223].

Security Events: beveiligingsrelevante busfouten geeft CanIf door aan IdsM [SWS_CANIF_00913]. Bronnen zijn CanIf_ErrorNotification [SWS_CANIF_00915] [SWS_CANIF_00916] en bus-off-gebeurtenissen [SWS_CANIF_00918].

Bus-off en herstart: Can meldt bus-off via CanIf_ControllerBusOff [SWS_CANIF_00218]. CanIf zet vervolgens het kanaal offline [SWS_CANIF_00866] en informeert CanSM [SWS_CANIF_00724] CanIf p. 154. De herstart start CanSM met CanIf_SetControllerMode naar STARTED CanIf p. 160. Met CanIf_GetTxConfirmationState controleert hij of er sinds de start zendbevestigingen zijn binnengekomen [SWS_CANIF_00734] [SWS_CANIF_00740].

Fouttoestand en foutentellers zijn beschikbaar via eigen services:

  • CanIf_GetControllerErrorState [SWS_CANIF_91001] met Can_ErrorStateType [SWS_Can_91003]
  • de teller-API's [SWS_CANIF_91003] [SWS_CANIF_91004]

Degradatie in CanTp: CanTp breekt foutieve sessies afzonderlijk af:

  • Bij timeout (N_As, N_Bs, N_Cr) beëindigt het de betreffende sessie en meldt E_NOT_OK aan PduR [SWS_CanTp_00310] [SWS_CanTp_00316] [SWS_CanTp_00313].
  • Na WFTmax FC(WAIT)-frames breekt het de ontvangst af [SWS_CanTp_00223].
  • Weigert CanIf_Transmit, dan beëindigt het de lopende verbinding [SWS_CanTp_00342] [SWS_CanTp_00343].

Andere kanalen blijven daarbij onaangetast, aangezien elk kanaal over eigen resources beschikt [SWS_CanTp_00122].
