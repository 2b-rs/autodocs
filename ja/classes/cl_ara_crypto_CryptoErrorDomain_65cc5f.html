class ara::crypto::CryptoErrorDomain

[SWS_CRYPT_19900] Upstream: RS_AP_00130

class CryptoErrorDomain final :             public ara::core::ErrorDomain {...};

Crypto Error Domain class that provides interfaces as defined by ara::core::ErrorDomain such as a name of the Crypto Error Domain or messages for each error code. This class represents an error domain responsible for all errors that may be reported by public APIs in ara::crypto namespace. .

Dient der Identifikation und textuellen Übersetzung aller Fehlercodes des Moduls crypto.

Die Klasse definiert die zentrale Fehlerdomäne für alle Fehler, die über die öffentlichen Schnittstellen im Namensraum ara::crypto gemeldet werden können [SWS_CRYPT_19950]. Zu ihren Kernaufgaben gehören die Rückgabe des eindeutigen Domänennamens sowie die Übersetzung von Fehlercodes aus der Aufzählung CryptoErrc in verständliche Fehlermeldungen [SWS_CRYPT_19953]. Sämtliche Abfragefunktionen sind threadsicher und ausnahmesicher ausgelegt, während die Methode zum Auslösen von Ausnahmen bei deaktivierten C++-Exceptions nicht an der Überladungsauflösung teilnimmt [SWS_CRYPT_19954].

Kontext

Die Klasse ara::crypto::CryptoErrorDomain fungiert als spezialisierte Fehlerdomäne innerhalb der AUTOSAR-Adaptive-Plattform. Gemäß ihrer Klassendefinition leitet sie von ara::core::ErrorDomain ab und ist als final deklariert. Ihre zentrale Verantwortung besteht darin, sämtliche Fehler abzubilden, die von den öffentlichen Schnittstellen innerhalb des Namensraums ara::crypto gemeldet werden können. Sie ordnet den Fehlern eine eindeutige Domänenidentifikation zu, die über die Methode Name abgefragt werden kann [SWS_CRYPT_19950].

Zur einheitlichen Typbindung stellt die Klasse zwei typbezogene Aliase bereit: Errc verweist als Alias direkt auf die Aufzählung CryptoErrc für kryptografische Fehlercodes [SWS_CRYPT_19903], während Exception die Basisausnahmeklasse CryptoException referenziert [SWS_CRYPT_19904]. Als Interaktionspartner treten primär die kryptografischen Funktionsbausteine auf, die Fehler dieser Domäne erzeugen, sowie die Anwendungssoftware, welche Fehler über die Basismechanismen von ara::core empfängt und auswertet.

Kontextdiagramm: Einbindung der CryptoErrorDomain in die Fehlerbehandlung zwischen ara::crypto-APIs, der Basisklasse ara::core::ErrorDomain und der Anwendung. Quellen: [SWS_CRYPT_19950], [SWS_CRYPT_19903], [SWS_CRYPT_19904].

Lebenszyklus

Die Erzeugung von Objekten der CryptoErrorDomain erfolgt über den standardmäßigen parameterlosen Konstruktor, welcher als constexpr und noexcept spezifiziert ist [SWS_CRYPT_19902]. Durch die Deklaration als constexpr kann eine Instanz bereits zur Übersetzungszeit konstruiert werden. Interpretation: In typischen Plattform-Implementierungen dürfte die Fehlerdomäne als langlebiges oder statisches Singleton existieren, damit Fehlercodes im gesamten Prozessverlauf ohne dynamische Speicherallokation auf dieselbe Domäneninstanz verweisen können. Question Q-eace74191b79fa03 (open)

Nach der Instanziierung besitzt das Objekt einen konstanten, zustandslosen Charakter; eine Vererbungshierarchie unterhalb dieser Klasse ist durch das Schlüsselwort final ausgeschlossen. Hinsichtlich der Nebenläufigkeit sind sowohl der Konstruktor [SWS_CRYPT_19902] als auch die Abfragemethoden Name [SWS_CRYPT_19950], Message [SWS_CRYPT_19953] und ThrowAsException [SWS_CRYPT_19954] explizit als threadsicher (thread-safe) klassifiziert. Instanzen können somit ohne externe Synchronisation von mehreren Threads parallel genutzt werden.

Nutzungspfad

Der reguläre Ablauf bei der Interaktion mit der CryptoErrorDomain gliedert sich in folgende Schritte:

  1. Eine Operation innerhalb des Namensraums ara::crypto schlägt fehl und erzeugt ein Fehlerobjekt vom Typ ara::core::ErrorCode, welches mit der CryptoErrorDomain verknüpft ist.
  2. Die aufrufende Anwendung oder Fehlerbehandlungsroutine prüft die Herkunft des Fehlers und kann bei Bedarf mittels Name() den eindeutigen Namen der Domäne abrufen [SWS_CRYPT_19950].
  3. Zur Erzeugung von Protokollausgaben oder Diagnosemeldungen wird die Methode Message() mit dem übergebenen errorCode aufgerufen, die den Code auflöst und die zugehörige Textmeldung als const char* zurückliefert [SWS_CRYPT_19953].
  4. Möchte der Aufrufer den Fehler in eine C++-Ausnahme umwandeln, erfolgt der Aufruf von ThrowAsException(), wodurch eine passende Ausnahme auf Basis von CryptoException ausgelöst wird [SWS_CRYPT_19954], [SWS_CRYPT_19904].

Sequenzdiagramm: Fehlerauflösung und Textausgabe über die Schnittstellen der CryptoErrorDomain. Quellen: [SWS_CRYPT_19950], [SWS_CRYPT_19953].

Fehlerszenarien

Bei der Fehlerbehandlung weist die Klasse differenzierte Garantien hinsichtlich der Ausnahmesicherheit auf. Die Methoden Name [SWS_CRYPT_19950] und Message [SWS_CRYPT_19953] sind als noexcept deklariert und vollständig ausnahmesicher (exception safe). Sollte an Message ein numerischer Wert übergeben werden, der nicht in der Aufzählung CryptoErrc definiert ist, dürfte vermutlich eine generische Fallback-Nachricht geliefert werden; ein Abbruch durch Ausnahmen ist ausgeschlossen. Question Q-6f2a8707283aa64e (open)

Im Gegensatz dazu ist die Methode ThrowAsException als nicht ausnahmesicher (not exception safe) spezifiziert und mit dem Attribut [[noreturn]] versehen, da ihr bestimmungsgemäßer Zweck im Werfen einer Ausnahme liegt [SWS_CRYPT_19954]. Eine wesentliche Randbedingung betrifft Plattformkonfigurationen ohne Exception-Unterstützung: Sind C++-Ausnahmen in der Compiler-Toolchain deaktiviert, nimmt ThrowAsException nicht an der Überladungsauflösung teil [SWS_CRYPT_19954]. In solchen Systemen ist der Aufruf kompilierunfähig, und die Fehlerbehandlung muss zwingend über fehlerwertbasierte Mechanismen wie Ergebnisobjekte abgewickelt werden.

Verwendung und Aufrufkontext

Der Standardkonstruktor CryptoErrorDomain() initialisiert eine Instanz der Fehlerdomäne für kryptografische Operationen [SWS_CRYPT_19902]. Er ist als constexpr und noexcept spezifiziert, nimmt keine Argumente entgegen und besitzt keinen Rückgabewert. Die Ausführung erfolgt synchron und kann zur Übersetzungszeit stattfinden. In Anwendungsprogrammen dürfte eine manuelle Instanziierung selten erforderlich sein, da der Zugriff auf die Domäne regulär über die globale Funktion GetCryptoErrorDomain() erfolgt [SWS_CRYPT_19952]. Question Q-1e029d80fb7bf7d1 (open)

Fehlerbehandlung und Nebenläufigkeit

Die Erzeugung des Objekts ist als exception safe sowie thread-safe definiert [SWS_CRYPT_19902]. Da der Konstruktor mit noexcept deklariert ist, treten beim Aufruf keine Fehler oder Ausnahmen auf; Fehlermeldungen an DET oder DEM existieren für diesen Konstruktor nicht.

Zusammenspiel im Modul

Die erzeugte Domäne bildet den Kontext für kryptografische Fehlerbeschreibungen:

  • Sie kapselt die Fehlercodes der Aufzählung CryptoErrc [SWS_CRYPT_10099] über den Typalias Errc [SWS_CRYPT_19903].
  • Über die freie Funktion MakeErrorCode() werden Instanzen von ara::core::ErrorCode erstellt, die fest auf diese Domäne referenzieren [SWS_CRYPT_19951].
  • Die Elementfunktionen der Domäne ermöglichen die Abfrage des Bezeichners via Name() [SWS_CRYPT_19950], die Textauflösung über Message() [SWS_CRYPT_19953] sowie das Werfen systemspezifischer Fehler über ThrowAsException() [SWS_CRYPT_19954] mit dem Basistyp Exception [SWS_CRYPT_19904].
