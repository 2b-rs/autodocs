Papel do NvM na pilha de memória

O NVRAM Manager (NvM) é o serviço central para dados não voláteis da Classic Platform. Ele oferece exclusivamente um acesso implícito: copia blocos entre a memória NV e a RAM, e a aplicação trabalha com os dados da RAM [SWS_NvM_00038] [SWS_NvM_00692]. O ambiente deve acessar a memória não volátil apenas por meio do NvM [SWS_NvM_00384]. Para baixo, o NvM apoia-se no Memory Abstraction Interface (MemIf). Juntamente com a Flash EEPROM Emulation (Fee) ou a EEPROM Abstraction (Ea), ele disponibiliza um espaço de endereçamento linear virtual de 32 bits [SWS_NvM_00051]. Camadas superiores incluem apenas NvM.h [SWS_NvM_00691].

O NvM obtém os resultados da camada inferior por duas vias, dependendo da configuração. Ou a Fee/Ea chama os callbacks NvM_JobEndNotification e NvM_JobErrorNotification, ou o NvM consulta o estado do job em modo de polling [SWS_NvM_00438] [SWS_NvM_00440] [SWS_NvM_00346]. Ambas as vias de detecção também são descritas por ErrorDescription p. 43. Outros módulos vizinhos:

  • Erros de produção vão para o DEM [SWS_NvM_00592].
  • Erros de desenvolvimento vão para o DET [SWS_NvM_00614].
  • Os CRCs são calculados pelo módulo Crc [SWS_NvM_00466].
  • O NvM informa o BswM sobre estados de múltiplos blocos e de blocos individuais [SWS_NvM_00745] [SWS_NvM_00746].
  • Opcionalmente, o NvM criptografa blocos por meio do CSM [SWS_NvM_00976].

Diagrama de contexto: o NvM faz a mediação entre usuários e o BswM, por um lado, e MemIf/Fee/Ea, por outro; DEM, DET, Crc e CSM são serviços auxiliares. Fontes: [SWS_NvM_00051], [SWS_NvM_00438], [SWS_NvM_00745], [SWS_NvM_00976], EXP_NVDataHandling p. 8

Blocos NVRAM: estrutura e tipos de gerenciamento

Cada bloco NVRAM é composto por três componentes obrigatórios: bloco NV, bloco RAM e bloco administrativo. Um bloco ROM é opcional [SWS_NvM_00138] [SWS_NvM_00139]. O descritor de bloco define a composição em tempo de configuração [SWS_NvM_00140]. Os componentes em detalhe:

  • O bloco NV contém dados úteis, bem como, opcionalmente, CRC e cabeçalho [SWS_NvM_00125].
  • O bloco ROM fornece dados padrão para blocos NV vazios ou corrompidos [SWS_NvM_00020].
  • O bloco administrativo reside na RAM e é invisível para a aplicação. Ele contém o índice do dataset, atributos e informações de erro/estado [SWS_NvM_00134] [SWS_NvM_00135].

Veja o diagrama AUTOSAR_SWS_NVRAMManager p. 10 a esse respeito.

Um bloco é endereçado por meio de seu Block ID [SWS_NvM_00069]. NvM_BlockIdType é um uint16; os bits de seleção de dataset reduzem sua faixa de valores [SWS_NvM_00471]. Dois IDs são reservados: 0 para o resultado de múltiplos blocos e 1 para o Configuration ID [SWS_NvM_00244].

Em blocos DATASET, NvM_SetDataIndex seleciona o elemento. Índices a partir de NvMNvBlockNum apontam para blocos ROM [SWS_NvM_00014] [SWS_NvM_00445]. O índice não é armazenado de forma persistente, e NvM_Init o define como zero. O usuário é responsável pela seleção correta [SWS_NvM_00160] [SWS_NvM_00192] [SWS_NvM_00695] (NVDataHandling p. 10).

Inicialização: NvM_Init e NvM_ReadAll

NvM_Init é chamado exclusivamente pelo BswM [SWS_NvM_00693]. O ponteiro de configuração é sempre NULL_PTR [SWS_NvM_00881]. A função reinicializa as variáveis internas e sinaliza "INIT DONE"; somente depois disso o NvM processa solicitações [SWS_NvM_00399] [SWS_NvM_00257]. Por motivos de tempo, ela não inicializa blocos NVRAM nem outros módulos e não altera blocos RAM permanentes [SWS_NvM_00091] [SWS_NvM_00193] [SWS_NvM_00400].

Em seguida, a solicitação de múltiplos blocos NvM_ReadAll carrega os dados [SWS_NvM_00158]. A chamada apenas sinaliza a solicitação e retorna imediatamente [SWS_NvM_00243]. Ela está disponível apenas no mestre do NvM [SWS_NvM_00970]. O job é executado nas seguintes etapas:

  1. Primeiro, ele compara o Configuration ID armazenado com o compilado [SWS_NvM_00073] [SWS_NvM_00246].
  2. Se NvMDynamicConfiguration for FALSE, ele ignora uma divergência [SWS_NvM_00248]. Caso contrário, segue-se a preparação estendida de tempo de execução [SWS_NvM_00249] (NVDataHandling p. 15).
  3. Em seguida, ele itera sobre os blocos de usuário [SWS_NvM_00244]. Ele processa apenas blocos com bloco RAM permanente ou sincronização explícita [SWS_NvM_00118].

Se um CRC de RAM configurado estiver correto, o conteúdo da RAM é considerado válido [SWS_NvM_00364]. Para cada bloco, o callback de bloco individual pode ser chamado [SWS_NvM_00281]. O resultado global é NVM_REQ_OK, ou NVM_REQ_NOT_OK, assim que um bloco falhar [SWS_NvM_00895] [SWS_NvM_00301].

O NvM relata a aceitação e a conclusão da solicitação ao BswM [SWS_NvM_00888] [SWS_NvM_00889]. O BswM continua então a inicialização, por exemplo com Rte_Start() (NVDataHandling p. 20; ModeManagementGuide p. 38).

Diagrama de sequência: NvM_Init apenas prepara o NvM; os dados de bloco só são carregados pelo NvM_ReadAll assíncrono, cuja conclusão libera a continuação da inicialização. Fontes: [SWS_NvM_00091], [SWS_NvM_00243], [SWS_NvM_00516], [SWS_NvM_00889], NVDataHandling p. 20, AUTOSAR_SWS_NVRAMManager p. 163

Solicitações de bloco individual: fila, prioridade e feedback

Serviços de bloco individual como NvM_ReadBlock ou NvM_WriteBlock operam de forma assíncrona. Eles aceitam os parâmetros, enfileiram a solicitação e retornam [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00766]. Após o enfileiramento bem-sucedido, o resultado é NVM_REQ_PENDING [SWS_NvM_00185]. Se a fila transbordar, a chamada retorna E_NOT_OK [SWS_NvM_00184]. Um bloco só é enfileirado se ainda não estiver em espera ou sendo processado [SWS_NvM_00385].

O trabalho propriamente dito ocorre em NvM_MainFunction [SWS_NvM_00256]. Nele, o NvM retira a solicitação de maior prioridade e processa as solicitações sucessivamente [SWS_NvM_00155]. Para a ordem, aplicam-se estas regras:

  • Com NvMJobPrioritization, o NvM utiliza duas filas; uma delas destina-se a solicitações de escrita imediatas (dados de colisão) [SWS_NvM_00564] [SWS_NvM_00378].
  • Solicitações imediatas interrompem jobs em execução de forma destrutiva; estes são reiniciados posteriormente [SWS_NvM_00182] [SWS_NvM_00300] [SWS_NvM_00258].
  • Sem priorização, aplica-se a ordem de chegada [SWS_NvM_00379].
  • NvM_WriteAll não é interrompido. Solicitações de leitura e escrita que chegam durante uma solicitação de múltiplos blocos são enfileiradas e executadas posteriormente [SWS_NvM_00567] [SWS_NvM_00568] [SWS_NvM_00569].

Qual buffer de RAM é utilizado depende do ponteiro passado. Em caso de NULL_PTR, o NvM utiliza o bloco RAM permanente ou a sincronização explícita [SWS_NvM_00898] [SWS_NvM_00899] [SWS_NvM_00900] [SWS_NvM_00901]. Um endereço diferente serve como bloco RAM temporário, mesmo se um permanente estiver configurado [SWS_NvM_00278] [SWS_NvM_00280]. Para blocos RAM permanentes, existem serviços PRAM dedicados [SWS_NvM_00764] [SWS_NvM_00793] (NVDataHandling p. 32).

O resultado encontra-se no campo de erro/estado do bloco administrativo [SWS_NvM_00175] e pode ser consultado por meio de NvM_GetErrorStatus [SWS_NvM_00451]. Se um callback de bloco individual estiver configurado, cada solicitação termina com a sua chamada a partir de NvM_MainFunction [SWS_NvM_00740] [SWS_NvM_00347] [SWS_NvM_00467]. Adicionalmente, o BswM pode ser informado bloco a bloco [SWS_NvM_00890] [SWS_NvM_00891]. NvM_CancelJobs remove as solicitações pendentes de um bloco; um job já em execução é continuado [SWS_NvM_00536] [SWS_NvM_00537].

Diagrama de sequência: a chamada retorna imediatamente; o processamento e o feedback via callback ou consulta de estado ocorrem em chamadas posteriores a NvM_MainFunction. Fontes: [SWS_NvM_00185], [SWS_NvM_00184], [SWS_NvM_00346], [SWS_NvM_00347], [SWS_NvM_00451], NVDataHandling p. 43

Estado do bloco RAM e sincronização com a aplicação

O NvM mantém para o bloco RAM permanente ou para o espelho um estado "válido" ou "inválido" [SWS_NvM_00132] [SWS_NvM_00128]. Adicionalmente, ele distingue blocos válidos entre alterados e inalterados [SWS_NvM_00682] [SWS_NvM_00472]. As transições em detalhe:

  • Solicitações de leitura e restore invalidam o bloco no enfileiramento ou no início do job [SWS_NvM_00198] [SWS_NvM_00227].
  • Uma leitura bem-sucedida resulta em "válido/inalterado" [SWS_NvM_00200].
  • Valores padrão carregados resultam em "válido/alterado" [SWS_NvM_00366] [SWS_NvM_00228]. Sem valores padrão, o bloco permanece inválido [SWS_NvM_00658].
  • NvM_SetRamBlockStatus com TRUE e NvM_ValidateAll marcam o bloco como alterado [SWS_NvM_00406] [SWS_NvM_00856] (EXP_NVDataHandling p. 18).
  • Após uma escrita bem-sucedida, o bloco é considerado inalterado [SWS_NvM_00472].

Diagrama de estados: solicitações de leitura e restore tornam o bloco RAM temporariamente inválido; apenas uma operação de escrita reconduz "alterado" a "inalterado". O estado inicial é uma interpretação. Fontes: [SWS_NvM_00198], [SWS_NvM_00200], [SWS_NvM_00366], [SWS_NvM_00406], [SWS_NvM_00472], [SWS_NvM_00658]

Na sincronização implícita, o NvM e a aplicação acessam o mesmo bloco RAM. Após uma solicitação de leitura ou escrita, a aplicação só pode reutilizá-lo após a confirmação [SWS_NvM_00698] [SWS_NvM_00699] (EXP_NVDataHandling p. 27). Se várias aplicações compartilharem um bloco, elas próprias são responsáveis pela sua consistência [SWS_NvM_00697].

Alternativamente, NvMBlockUseSyncMechanism configura uma sincronização explícita [SWS_NvM_00511]. O NvM cria então exatamente um espelho na RAM e o utiliza como buffer [SWS_NvM_00513] [SWS_NvM_00514]. Entre a aplicação e o espelho, os callbacks NvMWriteRamBlockToNvCallback e NvMReadRamBlockFromNvCallback copiam [SWS_NvM_00515] [SWS_NvM_00516]. Suas assinaturas são NvM_WriteRamBlockToNvm e NvM_ReadRamBlockFromNvm [SWS_NvM_00539] [SWS_NvM_00540]. Para este caso de uso, eles são entradas obrigatórias (BSWModuleDescriptionTemplate p. 242).

Até o callback, a aplicação pode continuar alterando seu bloco [SWS_NvM_00705] (NVDataHandling p. 26). Se um callback relatar E_NOT_OK, o NvM o chamará novamente na próxima execução de NvM_MainFunction, no máximo NvMRepeatMirrorOperations vezes [SWS_NvM_00840] [SWS_NvM_00579]. Um bloco com sincronização explícita não pode ter um bloco RAM permanente [SWS_NvM_00904]. Com um NvBlockSwComponent, a RTE implementa esses callbacks (NVDataHandling p. 34).

Diagrama de sequência: na sincronização explícita, o NvM só assume os dados no callback do espelho, portanto atrasado em relação à solicitação; um callback com falha é repetido. Fontes: [SWS_NvM_00515], [SWS_NvM_00579], [SWS_NvM_00705], [SWS_NvM_00840], [SWS_NvM_00901], EXP_NVDataHandling p. 13

Desligamento, mecanismos de proteção e configuração

O desligamento é acionado pelo BswM com NvM_WriteAll [SWS_NvM_00092]. A chamada retorna imediatamente e está disponível apenas no mestre do NvM [SWS_NvM_00254] [SWS_NvM_00971]. O job grava blocos RAM permanentes ou chama o callback do espelho [SWS_NvM_00018] [SWS_NvM_00252]. Antes disso, ele verifica o estado "válido/alterado" [SWS_NvM_00682]. Ele ignora blocos protegidos contra escrita e bloqueados sem mensagem de erro [SWS_NvM_00434] [SWS_NvM_00750].

Para que apenas blocos alterados sejam gravados, o usuário relata alterações por meio de NvM_SetRamBlockStatus, caso essa API esteja configurada [SWS_NvM_00408] [SWS_NvM_00453]. Em storeAtShutdown, a RTE assume isso (NVDataHandling p. 41). NvM_CancelWriteAll é reservado ao BswM [SWS_NvM_00703]. O bloco atualmente em processamento é concluído de forma consistente; os blocos restantes recebem NVM_REQ_CANCELED [SWS_NvM_00238] [SWS_NvM_00236] [SWS_NvM_00237] (ModeManagementGuide p. 37).

Diagrama de sequência: alterações relatadas em tempo de execução só são gravadas em NvM_WriteAll; o BswM pode cancelar e aguarda a mensagem de resultado. Fontes: [SWS_NvM_00092], [SWS_NvM_00238], [SWS_NvM_00682], [SWS_NvM_00889], NVDataHandling p. 41

Visão geral de outros mecanismos de proteção e configuração:

  • Proteção contra escrita: a proteção contra escrita é um atributo de bloco. Com NvMBlockWriteProt, ela fica ativa por padrão, e o ambiente pode desativá-la com NvM_SetBlockProtection [SWS_NvM_00054] [SWS_NvM_00326] [SWS_NvM_00578].
  • Escrita única: blocos com NvMWriteBlockOnce são gravados apenas uma vez. Sua proteção não pode ser revogada, e solicitações de escrita antes da primeira leitura são rejeitadas [SWS_NvM_00397] [SWS_NvM_00398] [SWS_NvM_00952].
  • Bloqueio: o bloqueio por meio de NvM_SetBlockLockStatus não pode ser alterado por outros serviços [SWS_NvM_00548] [SWS_NvM_00754].
  • Integridade: um Static Block ID no cabeçalho é armazenado na escrita e verificado na leitura [SWS_NvM_00522] [SWS_NvM_00523] [SWS_NvM_00524]. Uma comparação de CRC pode evitar a escrita de dados inalterados [SWS_NvM_00849] [SWS_NvM_00850].
  • Escopo: existem três classes de configuração de API; a Classe 1 não suporta DATASET [SWS_NvM_00149] [SWS_NvM_00365].
  • Inicialização primária: NvM_FirstInitAll grava valores padrão ou invalida blocos, ignorando a proteção contra escrita [SWS_NvM_91001] [SWS_NvM_00913] [SWS_NvM_00919] [SWS_NvM_00931].

Comportamento em caso de erro

Erros de desenvolvimento. Com a detecção de erros ativada, o NvM relata ao DET, entre outros:

  • NVM_E_UNINIT [SWS_NvM_00614]
  • NVM_E_PARAM_BLOCK_ID [SWS_NvM_00618]
  • NVM_E_PARAM_ADDRESS [SWS_NvM_00616]
  • NVM_E_BLOCK_PENDING [SWS_NvM_00615]
  • NVM_E_BLOCK_LOCKED [SWS_NvM_00748]
  • NVM_E_WRITE_PROTECTED [SWS_NvM_00962]

Para uma fila cheia, NVM_E_QUEUE_FULL também está definido [SWS_NvM_00947].

Erros de leitura. O NvM controla a recuperação por si próprio (ErrorDescription p. 62). Para isso, procede passo a passo:

  1. Em caso de erros de CRC ou de Static Block ID, ele lê novamente, se aplicável [SWS_NvM_00526] [SWS_NvM_00582].
  2. Em blocos REDUNDANT, ele lê o segundo bloco NV [SWS_NvM_00199]. Se uma cópia for válida, o resultado é NVM_REQ_OK, sem notificação ao DEM [SWS_NvM_00279] [SWS_NvM_00655]. Em seguida, o NvM tenta restaurar a redundância; se isso falhar, ele relata NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00531] [SWS_NvM_00546].
  3. Caso contrário, ele carrega valores padrão (NVM_REQ_RESTORED_DEFAULTS), sem alterar o bloco NV [SWS_NvM_00202] [SWS_NvM_00172].
  4. Se não houver valores padrão, o bloco RAM permanece inválido [SWS_NvM_00658]. O resultado depende então do tipo de erro:
    • Erro de CRC: NVM_REQ_INTEGRITY_FAILED e notificação do DEM NVM_E_INTEGRITY_FAILED [SWS_NvM_00204] [SWS_NvM_00203]
    • Erro de job: NVM_REQ_NOT_OK e notificação do DEM NVM_E_REQ_FAILED [SWS_NvM_00359] [SWS_NvM_00654]

Um bloco invalidado resulta em NVM_REQ_NV_INVALIDATED sem entrada do DEM [SWS_NvM_00341] [SWS_NvM_00652].

A ErrorDescription indica, de forma divergente, os valores de resultado NVM_REQ_REDUNDANCY_FAILED e NVM_REQ_RESTORED_FROM_ROM (ErrorDescription p. 62). Determinantes para a R20-11 são, no entanto, os requisitos [SWS_NvM_00279] [SWS_NvM_00202].

Diagrama de atividades: a recuperação de leitura passa por Read-Retry, cópia redundante e dados padrão; somente depois disso um erro é definido e relatado ao DEM. Fontes: [SWS_NvM_00526], [SWS_NvM_00199], [SWS_NvM_00279], [SWS_NvM_00202], [SWS_NvM_00204], [SWS_NvM_00359], [SWS_NvM_00341], AUTOSAR_EXP_ErrorDescription p. 76

Erros de escrita. Independentemente do tipo de gerenciamento, o NvM repete operações de escrita com falha, no máximo NVM_MAX_NUM_OF_WRITE_RETRIES vezes [SWS_NvM_00168] [SWS_NvM_00213] [SWS_NvM_00216]. Depois disso, ele define NVM_REQ_NOT_OK e relata NVM_E_REQ_FAILED [SWS_NvM_00683] [SWS_NvM_00684] (ErrorDescription p. 43). Se a verificação de escrita falhar, ele relata NVM_E_VERIFY_FAILED e repete a escrita [SWS_NvM_00528] [SWS_NvM_00529]. Em blocos REDUNDANT, uma cópia gravada com sucesso é suficiente para NVM_REQ_OK [SWS_NvM_00284]. Verificar dados incorretos e disponibilizar dados válidos antes da próxima escrita é tarefa da aplicação [SWS_NvM_00694] [SWS_NvM_00696].

NVRAM Manager (NvM)

fornece síncrono e assíncrono bloco-based dados management para non-volátil storage (EEPROM, Flash).

  • Std_ReturnType NvM_SetDataIndex (NvM_BlockIdType BlockId, uint8 Data Index); Service for setting the Data Inde x of a dataset NVRAM block.
  • Std_ReturnType NvM_GetDataIndex (NvM_BlockIdType BlockId, uint8* Data IndexPtr); Service for getting the currently set Data Index of a datase t NVRAM block
  • Std_ReturnType NvM_SetBlockProtection (NvM_BlockIdType BlockId, boolean Protection Enabled); Service for setting/ resetting the write protection for a NV block.
  • Std_ReturnType NvM_GetErrorStatus (NvM_BlockIdType BlockId, NvM_RequestResultType* Request ResultPtr); Service to read the block dependent error/ status information.
  • void NvM_GetVersionInfo (Std_VersionInfoType* versioninfo); Service to get the version information of the Nv M module.
  • Std_ReturnType NvM_SetRamBlockStatus (NvM_BlockIdType BlockId, boolean Block Changed); Service for setting the RAM block status of a permanent RAM block or the status of the explicit synchronization of a NVRAM block.
  • void NvM_SetBlockLockStatus (NvM_BlockIdType BlockId, boolean Block Locked); Service for setting the lock status of a permanent RAM block or of the explicit synchronization of a NVRAM block.

  • Std_ReturnType NvM_ReadBlock (NvM_BlockIdType BlockId, void* Nv M_DstPtr); Service to copy the data of the NV block to its corresponding RAM block.

A função síncrona e reentrante NvM_SetBlockProtection ([SWS_NvM_00450]) serve para ativar ou desativar a proteção contra gravação para um bloco NVRAM. Isso se aplica, em particular, também a blocos válidos que foram automaticamente marcados como protegidos contra gravação por operações de pré-leitura como NvM_ReadAll ([SWS_NvM_00314]), NvM_ReadBlock ([SWS_NvM_00316]) ou NvM_ReadPRAMBlock ([SWS_NvM_00784]).
