Fornece interfaces e contêineres para o Freshness Value Management com o objetivo de proteger a sincronização temporal.

O namespace apext::tsync disponibiliza interfaces e contêineres de dados para o Freshness Value Management da sincronização temporal da Adaptive. Por meio da interface FVM, valores de frescor são encapsulados em instâncias de FVContainer a fim de proteger mensagens de tempo contra ataques de repetição. Se ocorrer um erro irrecuperável durante a inicialização ou se um valor estiver temporariamente indisponível, isso é representado por meio dos códigos de erro do TsyncFvmErrorDomain [SWS_TS_14202]. A instanciação de objetos de erro padronizados ocorre de forma segura contra exceções e thread-safe por meio de MakeErrorCode [SWS_TS_14213].

Contexto

O namespace apext::tsync representa uma extensão específica de plataforma da sincronização temporal do AUTOSAR Adaptive (ara::tsync). Sua tarefa central é o Freshness Value Management (FVM), que disponibiliza mecanismos para garantir o frescor das informações de tempo, com o intuito de evitar ataques de repetição e estados obsoletos em redes sincronizadas temporalmente. Entre os componentes centrais estão a interface FVM, o contêiner de dados FVContainer, o domínio de erro TsyncFvmErrorDomain e a classe de exceção TsyncFvmException.

A classe FVContainer encapsula um valor de frescor gerenciando seu comprimento em bits, bem como o próprio valor sob a forma de um vetor de bytes. A interface FVM atua como ponte funcional para ara::tsync. É provável que FVM atue como interface de abstração por meio da qual instâncias de sincronização temporal de ara::tsync obtêm ou verificam valores de frescor atuais. O domínio de erro TsyncFvmErrorDomain e as funções auxiliares associadas asseguram o relato de erros padronizado [SWS_TS_14212].

Diagrama de contexto: componentes do namespace apext::tsync e sua interação com ara::tsync. Fontes: [SWS_TS_14202], [SWS_TS_14212].

Ciclo de vida

O ciclo de vida dos componentes no namespace apext::tsync divide-se em fases de inicialização, operação e terminação. Para a fase de inicialização, a enumeração TsyncFvmErrc define o valor de erro kFVInitializeFailed (= 2), que é especificado como erro irrecuperável (unrecoverable error) e indica que o Freshness Value Manager não pôde ser utilizado [SWS_TS_14202]. O erro kFVInitializeFailed sugere presumivelmente que, antes da recuperação de Freshness Values, deve ser executada uma fase de inicialização do FVM, cuja falha impossibilita qualquer utilização posterior.

Em operação contínua, instâncias de FVContainer possuem um tempo de vida temporário: são instanciadas conforme necessário, preenchidas com o vetor e o comprimento em bits e transferidas para as instâncias de protocolo de sincronização. Em contrapartida, o objeto de domínio de erro TsyncFvmErrorDomain possui um tempo de vida estático durante todo o período do processo. A função GetTsyncFvmErrorDomain() retorna uma referência para o objeto de instância global [SWS_TS_14212]. Tanto GetTsyncFvmErrorDomain() quanto a função fábrica MakeErrorCode() são declaradas como constexpr e noexcept, além de serem especificadas como seguras contra exceções e thread-safe [SWS_TS_14212], [SWS_TS_14213]. Isso permite a geração e a consulta concorrentes de erros sem travas de sincronização.

Caminho de utilização

O fluxo de utilização típico na interação com a sincronização temporal abrange o fornecimento e a avaliação de valores de frescor:

  1. Um componente de ara::tsync solicita um valor de frescor atual por meio da interface FVM para proteger uma mensagem temporal.
  2. Em caso de determinação bem-sucedida do valor, FVM cria ou preenche uma instância de FVContainer com o comprimento em bits e o vetor de bytes do valor, retornando-a ao chamador.
  3. Se o valor de frescor não puder ser disponibilizado temporariamente em tempo de execução, FVM sinaliza o erro recuperável kFVNotAvailable [SWS_TS_14202]. Para esse fim, um objeto ara::core::ErrorCode adequado contendo dados adicionais específicos do fabricante é criado via MakeErrorCode() [SWS_TS_14213].
  4. O componente chamador avalia o resultado e decide sobre tentativas de repetição ou medidas de contingência.

Diagrama de sequência: recuperação de um valor de frescor e tratamento de possíveis estados de erro. Fontes: [SWS_TS_14202], [SWS_TS_14213].

Cenários de erro

O tratamento de erros em apext::tsync baseia-se na arquitetura de ara::core::ErrorDomain e ara::core::ErrorCode. Os códigos de erro do TsyncFvmErrorDomain estão listados na enumeração TsyncFvmErrc, cujo tipo base é ara::core::ErrorDomain::CodeType [SWS_TS_14202]:

  • kFVNotAvailable (= 1): erro recuperável (recoverable error), que sinaliza que o Freshness Value não está disponível no momento [SWS_TS_14202]. Os chamadores podem repetir a solicitação ou ignorar o ciclo de processamento atual.
  • kFVInitializeFailed (= 2): erro irrecuperável (unrecoverable error), que indica que o Freshness Value Manager não pôde ser inicializado ou utilizado [SWS_TS_14202]. Isso leva à interrupção dos serviços de sincronização temporal dependentes.

A criação de objetos de erro concretos ocorre por meio da função auxiliar MakeErrorCode(TsyncFvmErrc code, ara::core::ErrorDomain::SupportDataType data), que recebe o enumerador e dados adicionais específicos do fabricante [SWS_TS_14213]. As declarações encontram-se no cabeçalho apext/tsync/fvm_error_domain.h, enquanto declarações antecipadas podem ser obtidas via apext/tsync/tsync_fwd.h [SWS_TS_14202]. Para fluxos de erro baseados em exceções, o namespace disponibiliza a classe TsyncFvmException. É provável que TsyncFvmException seja lançada quando erros do TsyncFvmErrorDomain forem sinalizados em contextos de exceção em vez de via ara::core::ErrorCode.

Utilização e semântica de erro

A enumeração TsyncFvmErrc define, segundo [SWS_TS_14202], os códigos de erro específicos para o domínio de erro apext::tsync::TsyncFvmErrorDomain. Dentro do domínio, a enumeração é adicionalmente disponibilizada através do alias de tipo apext::tsync::TsyncFvmErrorDomain::Errc [SWS_TS_14206]. A enumeração distingue entre dois estados centrais de erro do Freshness Value Manager (FVM):

  • kFVNotAvailable (= 1): Identifica um erro recuperável (Recoverable Error) quando um valor de frescura necessário não está disponível [SWS_TS_14202]. Este código de erro ocorre em particular na consulta de valores de frescura de envio através de apext::tsync::FVM::GetTxFreshness [SWS_TS_14199].
  • kFVInitializeFailed (= 2): Identifica um erro não recuperável (Unrecoverable Error) quando o Freshness Value Manager não está operacional e falha [SWS_TS_14202]. É sinalizado por apext::tsync::FVM::Initialize em caso de falha na inicialização [SWS_TS_14200].

Interação e tratamento de erros

Para o tratamento de erros, um enumerador é convertido juntamente com dados adicionais específicos do fabricante num objeto ara::core::ErrorCode através da função auxiliar apext::tsync::MakeErrorCode [SWS_TS_14213]. As funções do FVM, como Initialize [SWS_TS_14200], GetTxFreshness [SWS_TS_14199] e GetRxFreshness [SWS_TS_14198], encapsulam o resultado ou os estados de erro em ara::core::Result. Componentes de aplicação e de TimeSync avaliam o objeto Result para diferenciar entre falhas recuperáveis de valores de frescura individuais e erros graves de inicialização do FVM.

Além disso, ela é especificada como thread-safe («thread-safe») e pode ser executada concorrentemente sem sincronização externa [SWS_TS_14213].
