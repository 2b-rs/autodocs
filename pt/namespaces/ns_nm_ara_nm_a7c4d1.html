Permite o controle do status de rede solicitado e efetivo, bem como um tratamento de erros padronizado.

O namespace ara::nm fornece, com NetworkHandle, interfaces para o acesso controlado ao status de rede solicitado e efetivo da AUTOSAR Adaptive Platform. Possíveis situações de erro no fluxo operacional são mapeadas por meio dos códigos de erro padronizados da enumeração NmErrc, como kServiceNotAvailable ou kInvalidHandler [SWS_ANM_01111]. Para o tratamento estruturado de erros, MakeErrorCode gera códigos de erro de forma segura para threads para o domínio de erro NmErrorDomain, que é referenciado via GetNmDomain [SWS_ANM_01109]. As aplicações devem considerar a acessibilidade do serviço de Network Management antes de chamadas, para evitar falhas em consultas de status.

Contexto

O namespace ara::nm fornece na AUTOSAR Adaptive Platform as interfaces centrais para o Network Management funcional. A interface funcional primária é formada pela classe NetworkHandle, que encapsula o acesso controlado tanto ao status de rede solicitado quanto ao efetivo. Por meio desse mecanismo de abstração, aplicações funcionais e serviços de plataforma podem monitorar o estado operacional atual da rede de comunicação subjacente e iniciar alterações de status.

Para um tratamento de erros consistente e robusto, ara::nm fornece tipos padronizados e funções auxiliares integrados à arquitetura de erros da AUTOSAR Adaptive. Fazem parte disso o domínio de erro NmErrorDomain, a classe de exceção NmException e a enumeração específica de domínio NmErrc [SWS_ANM_01111]. Adicionalmente, estão disponíveis as funções seguras para threads GetNmDomain [SWS_ANM_01109] e MakeErrorCode [SWS_ANM_01110], que garantem a manipulação de estados de erro em conformidade com a instanciação e os tipos.

Diagrama de contexto: interação entre a aplicação, o NetworkHandle e a arquitetura de erros em ara::nm. Fontes: [SWS_ANM_01109], [SWS_ANM_01110], [SWS_ANM_01111].

Caminho de utilização

Num cenário de utilização típico, uma Adaptive Application interage com o namespace ara::nm para controlar o estado da rede e reagir a eventos de tempo de execução. A sequência de interação divide-se nos seguintes passos:

  • Iniciar o acesso ao estado: a aplicação utiliza um NetworkHandle para consultar o estado de rede solicitado ou o atualmente efetivo.
  • Deteção de erros: se o pedido de rede não puder ser atendido corretamente, a interface sinaliza um evento de erro correspondente. Interpretação: no caso de falhas dos serviços de rede subjacentes, o NetworkHandle deverá gerar internamente códigos de erro com base em NmErrc.
  • Gerar código de erro: a função auxiliar MakeErrorCode [SWS_ANM_01110] recebe um valor de NmErrc [SWS_ANM_01111], bem como dados adicionais específicos da aplicação (ara::core::ErrorDomain::SupportDataType), e gera a partir deles um ara::core::ErrorCode completo. A função está especificada como constexpr e noexcept e garante total segurança de threads [SWS_ANM_01110].
  • Verificar o domínio de erro: o componente chamador pode obter, através de GetNmDomain [SWS_ANM_01109], uma referência segura para threads para a NmErrorDomain global, a fim de verificar o domínio de erro do código retornado e resolver descrições de erro específicas do domínio.

Diagrama de sequência: fluxo da consulta do estado da rede e resolução de erros através de ara::nm. Fontes: [SWS_ANM_01109], [SWS_ANM_01110], [SWS_ANM_01111].

Cenários de erro

Os códigos de erro normalizados do módulo estão reunidos na enumeração NmErrc, que se baseia em ara::core::ErrorDomain::CodeType [SWS_ANM_01111]. O módulo distingue os seguintes casos de erro:

  • NmErrc::kServiceNotAvailable (código 1): este erro indica que o serviço necessário para a gestão de rede não está acessível ou operacional em tempo de execução [SWS_ANM_01111]. Neste caso, os chamadores têm de reagir com novas tentativas ou estratégias de contingência.
  • NmErrc::kInvalidHandler (código 2): ocorre quando, numa operação, foi passado ou referenciado um manipulador inválido ou não registado [SWS_ANM_01111]. Isto aponta geralmente para um erro de configuração ou de inicialização no chamador.

As pré-condições para chamadas robustas são uma infraestrutura de serviços inicializada, bem como parâmetros válidos no acesso a NetworkHandle, para evitar NmErrc::kServiceNotAvailable ou NmErrc::kInvalidHandler [SWS_ANM_01111]. Nenhuma das funções centrais de tratamento de erros, tais como MakeErrorCode [SWS_ANM_01110] e GetNmDomain [SWS_ANM_01109], lança exceções por si própria (noexcept). Interpretação: para aplicações que preferem uma estrutura de controlo baseada em exceções, a classe de exceção NmException deverá atuar como portadora para propagar estados de erro de forma estruturada através da pilha de chamadas.

Códigos de erro normalizados de Network Management.

A enumeração [SWS_ANM_01111] define os códigos de erro padronizados do Network Management (NM) no cabeçalho ara/nm/nm_error_domain.h. Ela também é disponibilizada através do alias de tipo Errc [SWS_ANM_01103] e serve, juntamente com a função fábrica thread-safe MakeErrorCode [SWS_ANM_01110], para o encapsulamento de estados de erro em valores de retorno ara::core::Result.

Os valores de erro definidos abordam casos de erro específicos na interface de NM:

  • kServiceNotAvailable (valor 1): Ocorre em consultas síncronas e solicitações do estado de rede quando o serviço NM subjacente não está disponível. Isso afeta a leitura do estado de rede efetivo através de GetNetworkState [SWS_ANM_01007], a consulta do estado solicitado através de GetNetworkRequestedState [SWS_ANM_01008], bem como a solicitação ou liberação de redes através de SetNetworkRequestedState [SWS_ANM_01009].
  • kInvalidHandler (valor 2): É reportado pelas funções de registro para handlers de notificação, nomeadamente RegisterNetworkStateChangeNotifier [SWS_ANM_01010], [SWS_ANM_01015] e RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012], [SWS_ANM_01014]. Como por interface só pode ser registrado no máximo um notificador de cada vez, este erro provavelmente ocorre quando um callback vazio é passado ou já existe um registro (interpretação).

Em relação à concorrência, deve-se notar que operações de leitura pura no estado de rede são thread-safe, enquanto SetNetworkRequestedState assim como todos os registros de notificadores são explicitamente especificados como não thread-safe. Chamadores devem, portanto, sincronizar externamente acessos concorrentes a registros e alterações de solicitação para evitar estados de chamada inválidos.

          usar
          

          A função MakeErrorCode serve no módulo anm para gerar um ara::core::ErrorCode padronizado para erros do Network Management [SWS_ANM_01110]. A função é definida no cabeçalho ara/nm/nm_error_domain.h e encapsula de forma síncrona o código de erro específico code do tipo de enumeração NmErrc juntamente com dados adicionais específicos do fabricante data do tipo ara::core::ErrorDomain::SupportDataType num respetivo objeto de erro [SWS_ANM_01110]. Os chamadores transmitem o respetivo estado de erro bem como dados de contexto, a fim de obterem um objeto de erro uniforme para o tratamento posterior de erros [SWS_ANM_01110].
          

          Tratamento de erros e simultaneidade
          

          Dado que MakeErrorCode está declarada com o especificador noexcept, a função garante não lançar nenhumas exceções durante a sua execução [SWS_ANM_01110]. Relativamente ao comportamento de concorrência, a função está classificada como thread-safe; por conseguinte, pode ser chamada com segurança a partir de threads paralelas sem medidas adicionais de sincronização externa [SWS_ANM_01110]. Devido à qualificação como constexpr, a construção do objeto de erro aquando da passagem de argumentos constantes deverá provavelmente poder ocorrer já totalmente em tempo de compilação pelo compilador [SWS_ANM_01110].
          

          Interação
          

          Como função geradora central para códigos de erro do Network Management, MakeErrorCode vincula o módulo ao conceito geral de tratamento de erros da AUTOSAR Adaptive Platform [SWS_ANM_01110]. Ao fazê-lo, endereça diretamente os requisitos upstream de nível superior RS_AP_00119, RS_AP_00120, RS_AP_00121, RS_AP_00159 bem como RS_AP_00135 [SWS_ANM_01110].
