Disponibiliza interfaces para a consulta de Extended Data Records específicos da aplicação para o diagnóstico adaptativo.

O namespace namespace <ExtendedDataRecord-Namespace> agrupa, no módulo diag da AUTOSAR Adaptive Platform, interfaces como DiagnosticExtendedDataRecordInterface para a disponibilização de Extended Data Records específicos da aplicação para entradas da memória de falhas. Interpretação: a aplicação deve instanciar e registrar a interface durante a inicialização para atender a requisições de leitura recebidas do gerenciador de diagnóstico de forma assíncrona com dados atuais de contexto e de contadores. Nesse contexto, o acesso concorrente a partir do subsistema de diagnóstico requer uma disponibilização thread-safe dos dados e uma resposta em tempo hábil para evitar timeouts de protocolo.

Contexto

No módulo diag da AUTOSAR Adaptive Platform, o namespace namespace <ExtendedDataRecord-Namespace> assume o encapsulamento lógico de interfaces para a disponibilização de dados estendidos de diagnóstico. No diagnóstico automotivo segundo a ISO 14229 (UDS), os Extended Data Records (EDR) desempenham um papel central, pois associam a uma entrada da memória de diagnóstico (DTC) informações adicionais específicas, como contadores de ocorrência de falhas, contadores de envelhecimento ou dados de estado específicos do fabricante. Interpretação: o identificador <ExtendedDataRecord-Namespace> deve servir como um placeholder formal para namespaces configurados de forma específica ao modelo, nos quais são geradas interfaces de diagnóstico específicas da aplicação para elementos de registros de dados. A classe central DiagnosticExtendedDataRecordInterface (listada no modelo como <ExtendedDataRecordElementInterface>) atua como camada de abstração entre o gerenciador de diagnóstico AUTOSAR e a aplicação em execução, que mantém os valores de estado físicos ou lógicos.

Ciclo de vida

O tempo de vida e o gerenciamento de estado de objetos do tipo DiagnosticExtendedDataRecordInterface estão estreitamente acoplados ao ciclo de vida do componente de aplicação que os disponibiliza. Interpretação: a instanciação e o gerenciamento de ciclo de vida da instância de interface devem seguir o padrão usual de provedor de serviços de ara::diag, no qual a aplicação cria a interface durante a sua fase de inicialização e a disponibiliza para o framework de diagnóstico. Durante a fase de operação ativa, a instância permanece ativa na memória para atender a requisições de leitura de dados de diagnóstico recebidas. Em um encerramento ordenado do software funcional, a instância deve ter seu registro cancelado ou ser destruída antes que os subsistemas dependentes sejam finalizados. Como as requisições de diagnóstico podem chegar de forma assíncrona por meio do daemon de diagnóstico, a implementação da classe de interface requer um projeto thread-safe para proteger acessos de leitura simultâneos aos dados de estado internos da aplicação.

Caminho de utilização

Um fluxo típico de utilização abrange a definição, a disponibilização e a execução da consulta ao registro de dados. No início, a aplicação funcional instancia a implementação concreta de DiagnosticExtendedDataRecordInterface e a vincula à porta configurada. Se, em seguida, um testador de diagnóstico externo envia, por meio de um comando UDS (por exemplo, serviço 0x19 para a consulta de informações de falha), uma requisição de leitura para um determinado Extended Data Record, o gerenciador de diagnóstico a delega para a interface registrada. Interpretação: a interface deve ser concebida como uma interface de serviço através da qual o gerenciador de diagnóstico obtém, em caso de necessidade, o conteúdo atual do registro de dados. A aplicação reúne os valores de dados solicitados, codifica-os no formato de dados especificado e retorna o resultado ao gerenciador de diagnóstico, que monta a mensagem de resposta UDS para a ferramenta de teste.

Cenários de erro

Durante a operação das interfaces de registro de dados, podem ocorrer diversas situações de erro que precisam ser tratadas de forma direcionada pelo software de aplicação. Se a instância de interface não estiver completamente registrada no momento de uma requisição de diagnóstico ou se encontrar em estado de transição, o gerenciador de diagnóstico não poderá encaminhar a solicitação para a aplicação e responderá ao testador tipicamente com um código de resposta negativa (NRC). Se a disponibilização dos dados dentro da aplicação atrasar além de uma janela temporal definida, há risco de timeouts de protocolo na interface de diagnóstico. Além disso, a interface deve ser robusta em relação a valores medidos temporariamente indisponíveis, reportando acessos inválidos a dados ou estados de erro ao gerenciador de diagnóstico por meio dos mecanismos de erro previstos, em vez de disparar exceções não tratadas no processo.
