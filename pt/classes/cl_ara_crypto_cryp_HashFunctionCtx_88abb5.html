Calcula valores de hash criptográficos sobre fluxos contínuos de dados ou blocos de memória individuais.

A classe ara::crypto::cryp::HashFunctionCtx fornece a interface para o cálculo de valores de hash criptográficos sobre blocos de memória e fluxos de dados ([SWS_CRYPT_50060]). Operações de streaming exigem a observância do ciclo de processamento composto por inicialização mediante Start(), passagem progressiva de dados via Update(), finalização por Finish() e subsequente leitura via GetDigest() ([SWS_CRYPT_21116]). Todos os métodos são especificados como thread-safe, garantem semântica de rollback e reportam erros de sequência ou de buffer de forma determinística por meio de objetos de resultado.

Contexto

A classe ara::crypto::cryp::HashFunctionCtx define, no módulo crypto da AUTOSAR Adaptive Platform, a interface para o cálculo de valores de hash criptográficos e somas de verificação. Como especialização de CryptoContext, ela disponibiliza métodos para chamadas individuais sem estado, bem como para procedimentos de streaming com estado. O gerenciamento de ciclo de vida e de posse ocorre tipicamente por meio do alias de tipo de ponteiro inteligente Sptr ([SWS_CRYPT_21101]), que é definido como std::shared_ptr<HashFunctionCtx>.

Entre os principais parceiros de interação estão:

  • Aplicação chamadora: controla o ciclo de vida do cálculo e passa dados de entrada em blocos ou como mensagem completa.
  • Áreas de memória: dados de entrada, vetores de inicialização (IV), bem como buffers de saída e de estado são transportados via ReadOnlyMemRegion e ReadWriteMemRegion.
  • Objetos de chave: por meio de CryptoObject::Sptr, chaves criptográficas podem ser diretamente incluídas no cálculo do hash como fonte de dados ([SWS_CRYPT_50057]).
  • Crypto Provider: interpretação: instâncias de HashFunctionCtx provavelmente devem ser criadas tipicamente por meio de um Crypto Provider associado; uma troca de estados de contexto exportados pressupõe obrigatoriamente o mesmo Crypto Provider e o mesmo ID de algoritmo ([SWS_CRYPT_50065]).

Ciclo de vida

Uma instância de HashFunctionCtx passa por múltiplos estados discretos durante o processamento de streaming:

Diagrama de estados: transições de estado do contexto de hash na inicialização, processamento e conclusão. Fontes: [SWS_CRYPT_50152], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50058], [SWS_CRYPT_21115], [SWS_CRYPT_50064], [SWS_CRYPT_50065]

Após a criação, o contexto encontra-se no estado não iniciado. Ao chamar Start() sem IV ([SWS_CRYPT_50152]) ou Start(iv) com vetor de inicialização ([SWS_CRYPT_50153]), o contexto transita para a fase ativa de processamento. Cálculos já em andamento são descartados implicitamente por uma nova chamada de início.

No estado de processamento, dados de entrada são acumulados por meio de chamadas repetidas de Update() com dados parciais brutos ([SWS_CRYPT_21113]) ou chaves ([SWS_CRYPT_50057]). Por meio de GetIntermediateDigest(), um resultado intermediário pode ser calculado sem concluir o contexto ou interromper o fluxo de dados ([SWS_CRYPT_50059]). Uma operação de streaming em andamento pode ser cancelada a qualquer momento mediante Cancel() ([SWS_CRYPT_50058]), fazendo com que o contexto retorne ao estado não iniciado.

A chamada de Finish() transfere o contexto para o estado "concluído" ([SWS_CRYPT_21115]). Apenas neste estado o valor de hash resultante pode ser extraído via GetDigest() ([SWS_CRYPT_21116]) ou verificado diretamente contra um valor esperado via Compare() ([SWS_CRYPT_50154]).

Para interromper e posteriormente continuar cálculos, o tamanho de buffer necessário pode ser consultado por meio de GetContextStateSize() ([SWS_CRYPT_50063]) e o estado interno pode ser salvo via ExportContextState() ([SWS_CRYPT_50064]). A retomada ocorre via ImportContextState() ([SWS_CRYPT_50065]). Todos os métodos de interface são declarados como seguros contra exceções (exception safe) e thread-safe (thread-safe).

Caminho de utilização

A classe suporta dois modos de processamento: o cálculo direto em etapa única e o processamento segmentado em streaming.

O cálculo em etapa única ocorre via CalculateHashDigest() ([SWS_CRYPT_50060]). Aqui, dados de entrada, um IV opcional e a área de memória de destino são passados, e o valor de hash é calculado em uma operação atômica.

Para volumes de dados maiores ou fluxos de dados contínuos, utiliza-se o caminho de streaming:

Diagrama de sequência: fluxo típico do cálculo de streaming via Start, Update, Finish e GetDigest. Fontes: [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116]

  1. Verificação de capacidade: consulta do tamanho de saída via GetDigestSize() ([SWS_CRYPT_50061]) e do tamanho máximo de bloco via GetMaximumChunkSize() ([SWS_CRYPT_50062]).
  2. Inicialização: preparação do contexto por meio da chamada de Start() ([SWS_CRYPT_50152]) ou Start(iv) ([SWS_CRYPT_50153]).
  3. Passagem de dados: passagem sucessiva de blocos de dados via Update(data) ([SWS_CRYPT_21113]) ou de chaves via Update(key) ([SWS_CRYPT_50057]).
  4. Finalização: encerramento do acúmulo de valores de hash por Finish() ([SWS_CRYPT_21115]).
  5. Avaliação de resultados: leitura do valor de hash calculado por meio de GetDigest() ([SWS_CRYPT_21116]) ou comparação in-place com um valor de referência via Compare() ([SWS_CRYPT_50154]).

Cenários de erro

Métodos de HashFunctionCtx sinalizam erros via ara::core::Result e garantem semântica de rollback em caso de falhas. As causas de erro típicas são:

  • Violações de sequência: Se Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) ou Cancel() ([SWS_CRYPT_50058]) for chamado sem uma chamada bem-sucedida anterior de Start(), é retornado CryptoErrc::kProcessingNotStarted. Se Finish() ([SWS_CRYPT_21115]) ou GetIntermediateDigest() ([SWS_CRYPT_50059]) for chamado sem inicialização prévia, o contexto reporta CryptoErrc::kInvalidUsageOrder. A recuperação de resultados via GetDigest() ([SWS_CRYPT_21116]) ou Compare() ([SWS_CRYPT_50154]) antes da execução de Finish() falha com CryptoErrc::kProcessingNotFinished.
  • Problemas de buffer e de tamanho: Se o buffer de saída for insuficiente, CalculateHashDigest() ([SWS_CRYPT_50060]), GetDigest() ([SWS_CRYPT_21116]), GetIntermediateDigest() ([SWS_CRYPT_50059]) e ExportContextState() ([SWS_CRYPT_50064]) retornam o erro CryptoErrc::kInsufficientCapacity. Comprimentos de entrada ou de IV não suportados levam a CryptoErrc::kInvalidInputSize em CalculateHashDigest(), Start(iv) ([SWS_CRYPT_50153]) e Update().
  • Incompatibilidade e ausência de suporte a funções: CryptoErrc::kUnsupported sinaliza que chamadas únicas não são suportadas ([SWS_CRYPT_50060]), a presença de um IV não é adequada para a função de hash ([SWS_CRYPT_50152], [SWS_CRYPT_50153]), resultados intermediários não são fornecidos ([SWS_CRYPT_50059]), a exportação/importação de contexto não é suportada ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]) ou o hashing de chaves não é permitido ([SWS_CRYPT_50057]).
  • Validação de objetos e permissões: Em passagens de chave via Update(key), uma chave incompatível leva a CryptoErrc::kIncompatibleObject e a falta de liberação para kAllowHashCalculation resulta em CryptoErrc::kUsageViolation ([SWS_CRYPT_50057]). Conteúdos de buffer inválidos em ImportContextState() geram CryptoErrc::kInvalidArgument ([SWS_CRYPT_50065]).
  • Gargalos de recursos: Se um recurso criptográfico necessário estiver ocupado, Start() responde à tentativa com CryptoErrc::kBusyResource ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).

Este guia baseia-se na especificação AUTOSAR Adaptive Platform R25-11.

O método CalculateHashDigest executa um cálculo one-shot síncrono de um valor de hash criptográfico e escreve o resultado no buffer de saída fornecido [SWS_CRYPT_50060]. Como parâmetros, são transmitidos a mensagem de entrada a ser processada data, o buffer de destino digest bem como, opcionalmente, um vetor de inicialização iv. Em caso de execução bem-sucedida, a função retorna, por meio do objeto de resultado ara::core::Result<std::size_t>, o número real de bytes de digest gravados [SWS_CRYPT_50060].

Tratamento de erros

Se o cálculo falhar, a interface garante semântica de rollback [SWS_CRYPT_50060]. Os seguintes códigos de erro podem estar contidos no resultado:

  • ara::crypto::CryptoErrc::kInvalidInputSize: O tamanho dos dados transmitidos ou do vetor de inicialização não é suportado [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kUnsupported: O cálculo single-call não é suportado pelo contexto, ou a passagem do vetor de inicialização não corresponde à configuração do contexto (IV obrigatório, mas ausente, ou IV transmitido embora não seja suportado) [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kInsufficientCapacity: A capacidade do buffer de saída digest não é suficiente para o digest calculado [SWS_CRYPT_50060].

Concorrência e interação

A função é declarada como segura contra exceções (exception safe) e segura para threads (thread-safe) [SWS_CRYPT_50060]. Para evitar previamente erros relativos a comprimentos de entrada inválidos, o tamanho máximo de buffer permitido pelo contexto para uma chamada única pode ser determinado através de GetMaximumChunkSize [SWS_CRYPT_50062].

          O método Compare da classe ara::crypto::cryp::HashFunctionCtx ([SWS_CRYPT_50154]) compara sincronicamente o tamanho e o conteúdo de um digest hash previamente calculado com um valor de referência esperado. O valor nominal é passado através do parâmetro expected do tipo ReadOnlyMemRegion. Em caso de sucesso, a função retorna um ara::core::Result<bool>, que contém true se e só se a sequência de bytes esperada for idêntica ao digest calculado.
          
  
          O pré-requisito para a chamada é que o cálculo do digest tenha sido previamente concluído com o método Finish(). Se não for esse o caso, a chamada falha e retorna o erro ara::crypto::CryptoErrc::kProcessingNotFinished com semântica de rollback ([SWS_CRYPT_50154]). Interpretação: Um comprimento divergente ou um conteúdo diferente de expected provavelmente não resulta num código de erro, mas sim num false regular no objeto de resultado.
