Contexto

A classe ara::crypto::cryp::CryptoProvider atua como interface central de abstração e fábrica para uma implementação concreta de primitivas criptográficas e seu gerenciamento de chaves. Ela encapsula operações criptográficas e desacopla as aplicações chamadoras de implementações específicas de hardware ou de bibliotecas criptográficas.

Como fábrica, CryptoProvider cria objetos de contexto especializados para diferentes procedimentos criptográficos:

  • Algoritmos simétricos: cifras de fluxo/bloco via CreateSymmetricCipherCtx [SWS_CRYPT_20742], criptografia autenticada via CreateAuthCipherCtx [SWS_CRYPT_20745], funções de hash criptográficas via CreateHashFunctionCtx [SWS_CRYPT_20747] e Message Authentication Codes via CreateMessageAuthnCodeCtx [SWS_CRYPT_20746].
  • Métodos assimétricos: criptografia de chave pública via CreateEncryptorPublicCtx [SWS_CRYPT_20750], descriptografia de chave privada via CreateDecryptorPrivateCtx [SWS_CRYPT_20751], geração de assinaturas via CreateSignerPrivateCtx [SWS_CRYPT_20756], verificação de assinaturas via CreateVerifierPublicCtx [SWS_CRYPT_20757], bem como acordos de chaves via CreateKeyAgreementPrivateCtx [SWS_CRYPT_20758].
  • Encapsulamento e transporte de chaves: mecanismos de encapsulamento de chaves via CreateKeyEncapsulatorPublicCtx [SWS_CRYPT_20752] e CreateKeyDecapsulatorPrivateCtx [SWS_CRYPT_20753], derivação de chaves via CreateKeyDerivationFunctionCtx [SWS_CRYPT_20748], key wrapping simétrico via CreateSymmetricKeyWrapperCtx [SWS_CRYPT_20743], bem como importação protegida de chaves via CreateProtectedKeyImportCtx [SWS_CRYPT_50017].

Além disso, a instância interage com recursos de gerenciamento de chaves. Ela carrega chaves armazenadas de um KeySlot ([SWS_CRYPT_20762], [SWS_CRYPT_20763], [SWS_CRYPT_20764]), gera novas chaves ([SWS_CRYPT_20721], [SWS_CRYPT_20722]), importa chaves serializadas ([SWS_CRYPT_50014], [SWS_CRYPT_20732], [SWS_CRYPT_50132]) e protege chaves para exportação ([SWS_CRYPT_20728]). Serviços de plataforma como geração de números aleatórios ([SWS_CRYPT_20741], [SWS_CRYPT_30098]), contadores de segurança ([SWS_CRYPT_20098]) e identificação do provedor ([SWS_CRYPT_50015], [SWS_CRYPT_50016]) completam o espectro de funções.

Diagrama de contexto: parceiros de interação do CryptoProvider como interface central e fábrica. Fontes: [SWS_CRYPT_20742], [SWS_CRYPT_20762], [SWS_CRYPT_20721]

Ciclo de vida

Instâncias de CryptoProvider são gerenciadas como std::shared_ptr<CryptoProvider> por meio do alias de tipo Sptr [SWS_CRYPT_20701]. A disponibilização de uma instância do provedor para a aplicação provavelmente ocorre por meio de mecanismos de fábrica específicos da plataforma. Operações de cópia e movimentação são explicitamente impedidas para o provedor: o construtor de cópia [SWS_CRYPT_41005], o construtor de movimentação [SWS_CRYPT_41006], o operador de atribuição por cópia [SWS_CRYPT_30216] e o operador de atribuição por movimentação [SWS_CRYPT_30217] foram excluídos (=delete).

A liberação dos recursos ocorre de forma polimórfica por meio do destrutor virtual ~CryptoProvider [SWS_CRYPT_20710]. Em relação à segurança de execução, todos os métodos de interface são declarados como seguros para threads (thread-safe) e seguros contra exceções (exception safe). Todos os métodos utilizam noexcept e relatam erros exclusivamente por meio do tipo de retorno ara::core::Result.

Caminho de utilização

Um fluxo de uso típico para operações criptográficas consiste na determinação de permissões de uso, no provisionamento de chaves e na subsequente criação de contexto:

  1. Consultar flags de uso padrão: antes da geração da chave, é possível determinar por meio de GetDefaultAllowedUsage(algId) [SWS_CRYPT_20955] quais flags de uso estão previstas por padrão para o algoritmo selecionado. De acordo com a especificação, as flags retornadas não contêm kAllowPlaintextExport, kAllowPersist nem kAllowSecuredExport.
  2. Provisionar chaves: uma nova chave simétrica é gerada via GenerateSymmetricKey [SWS_CRYPT_20721] ou um par de chaves assimétricas via GeneratePrivateKey [SWS_CRYPT_20722]. Alternativamente, uma chave existente pode ser carregada via LoadSymmetricKey [SWS_CRYPT_20762], LoadPrivateKey [SWS_CRYPT_20764] ou LoadPublicKey [SWS_CRYPT_20763]. Na geração de chaves privadas, o provedor deriva automaticamente as flags de uso da chave pública correspondente e ativa kAllowPlaintextExport e kAllowPersist [SWS_CRYPT_20722] para esta.
  3. Instanciar contexto: com base na transformação desejada, o chamador cria o contexto necessário, por exemplo, um AuthCipherCtx via CreateAuthCipherCtx(algId) [SWS_CRYPT_20745]. O contexto criado provavelmente será configurado com a chave em etapas posteriores.
  4. Exportação de chaves (opcional): se um objeto de chave precisar ser exportado de forma protegida, o ExportSecuredKey [SWS_CRYPT_20728] serializa e criptografa o objeto em um buffer de saída usando uma Key-Encryption-Key opcional (kek).

Diagrama de sequência: sequência típica para consulta de direitos de uso, geração de chaves e criação de contexto. Fontes: [SWS_CRYPT_20955], [SWS_CRYPT_20721], [SWS_CRYPT_20745]

Cenários de erro

Em caso de falha, os métodos de CryptoProvider asseguram uma semântica de rollback, de modo que o estado do sistema permaneça consistente. Os códigos de erro definidos (ara::crypto::CryptoErrc) incluem:

<h4>Contexto</h4>
<p>A classe <code>ara::crypto::cryp::CryptoProvider</code> atua como interface central de abstração e fábrica para uma implementação concreta de primitivas criptográficas e seu gerenciamento de chaves. Ela encapsula operações criptográficas e desacopla as aplicações chamadoras de implementações específicas de hardware ou de bibliotecas criptográficas.</p>
<p>Como fábrica, <code>CryptoProvider</code> cria objetos de contexto especializados para diferentes procedimentos criptográficos:</p>
<ul>
<li>Algoritmos simétricos: cifras de fluxo/bloco via <code>CreateSymmetricCipherCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20742" href="../spec/record.html?id=SWS_CRYPT_20742">[SWS_CRYPT_20742]</a>, criptografia autenticada via <code>CreateAuthCipherCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20745" href="../spec/record.html?id=SWS_CRYPT_20745">[SWS_CRYPT_20745]</a>, funções de hash criptográficas via <code>CreateHashFunctionCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20747" href="../spec/record.html?id=SWS_CRYPT_20747">[SWS_CRYPT_20747]</a> e Message Authentication Codes via <code>CreateMessageAuthnCodeCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20746" href="../spec/record.html?id=SWS_CRYPT_20746">[SWS_CRYPT_20746]</a>.</li>
<li>Métodos assimétricos: criptografia de chave pública via <code>CreateEncryptorPublicCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20750" href="../spec/record.html?id=SWS_CRYPT_20750">[SWS_CRYPT_20750]</a>, descriptografia de chave privada via <code>CreateDecryptorPrivateCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20751" href="../spec/record.html?id=SWS_CRYPT_20751">[SWS_CRYPT_20751]</a>, geração de assinaturas via <code>CreateSignerPrivateCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20756" href="../spec/record.html?id=SWS_CRYPT_20756">[SWS_CRYPT_20756]</a>, verificação de assinaturas via <code>CreateVerifierPublicCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20757" href="../spec/record.html?id=SWS_CRYPT_20757">[SWS_CRYPT_20757]</a>, bem como acordos de chaves via <code>CreateKeyAgreementPrivateCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20758" href="../spec/record.html?id=SWS_CRYPT_20758">[SWS_CRYPT_20758]</a>.</li>
<li>Encapsulamento e transporte de chaves: mecanismos de encapsulamento de chaves via <code>CreateKeyEncapsulatorPublicCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20752" href="../spec/record.html?id=SWS_CRYPT_20752">[SWS_CRYPT_20752]</a> e <code>CreateKeyDecapsulatorPrivateCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20753" href="../spec/record.html?id=SWS_CRYPT_20753">[SWS_CRYPT_20753]</a>, derivação de chaves via <code>CreateKeyDerivationFunctionCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20748" href="../spec/record.html?id=SWS_CRYPT_20748">[SWS_CRYPT_20748]</a>, key wrapping simétrico via <code>CreateSymmetricKeyWrapperCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20743" href="../spec/record.html?id=SWS_CRYPT_20743">[SWS_CRYPT_20743]</a>, bem como importação protegida de chaves via <code>CreateProtectedKeyImportCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50017" href="../spec/record.html?id=SWS_CRYPT_50017">[SWS_CRYPT_50017]</a>.</li>
</ul>
<p>Além disso, a instância interage com recursos de gerenciamento de chaves. Ela carrega chaves armazenadas de um <code>KeySlot</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20762" href="../spec/record.html?id=SWS_CRYPT_20762">[SWS_CRYPT_20762]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_20763" href="../spec/record.html?id=SWS_CRYPT_20763">[SWS_CRYPT_20763]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_20764" href="../spec/record.html?id=SWS_CRYPT_20764">[SWS_CRYPT_20764]</a>), gera novas chaves (<a class="spec-record-ref" data-req="SWS_CRYPT_20721" href="../spec/record.html?id=SWS_CRYPT_20721">[SWS_CRYPT_20721]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_20722" href="../spec/record.html?id=SWS_CRYPT_20722">[SWS_CRYPT_20722]</a>), importa chaves serializadas (<a class="spec-record-ref" data-req="SWS_CRYPT_50014" href="../spec/record.html?id=SWS_CRYPT_50014">[SWS_CRYPT_50014]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_20732" href="../spec/record.html?id=SWS_CRYPT_20732">[SWS_CRYPT_20732]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50132" href="../spec/record.html?id=SWS_CRYPT_50132">[SWS_CRYPT_50132]</a>) e protege chaves para exportação (<a class="spec-record-ref" data-req="SWS_CRYPT_20728" href="../spec/record.html?id=SWS_CRYPT_20728">[SWS_CRYPT_20728]</a>). Serviços de plataforma como geração de números aleatórios (<a class="spec-record-ref" data-req="SWS_CRYPT_20741" href="../spec/record.html?id=SWS_CRYPT_20741">[SWS_CRYPT_20741]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_30098" href="../spec/record.html?id=SWS_CRYPT_30098">[SWS_CRYPT_30098]</a>), contadores de segurança (<a class="spec-record-ref" data-req="SWS_CRYPT_20098" href="../spec/record.html?id=SWS_CRYPT_20098">[SWS_CRYPT_20098]</a>) e identificação do provedor (<a class="spec-record-ref" data-req="SWS_CRYPT_50015" href="../spec/record.html?id=SWS_CRYPT_50015">[SWS_CRYPT_50015]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50016" href="../spec/record.html?id=SWS_CRYPT_50016">[SWS_CRYPT_50016]</a>) completam o espectro de funções.</p>

<h4>Ciclo de vida</h4>
<p>Instâncias de <code>CryptoProvider</code> são gerenciadas como <code>std::shared_ptr&lt;CryptoProvider&gt;</code> por meio do alias de tipo <code>Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20701" href="../spec/record.html?id=SWS_CRYPT_20701">[SWS_CRYPT_20701]</a>. A disponibilização de uma instância do provedor para a aplicação provavelmente ocorre por meio de mecanismos de fábrica específicos da plataforma. Operações de cópia e movimentação são explicitamente impedidas para o provedor: o construtor de cópia <a class="spec-record-ref" data-req="SWS_CRYPT_41005" href="../spec/record.html?id=SWS_CRYPT_41005">[SWS_CRYPT_41005]</a>, o construtor de movimentação <a class="spec-record-ref" data-req="SWS_CRYPT_41006" href="../spec/record.html?id=SWS_CRYPT_41006">[SWS_CRYPT_41006]</a>, o operador de atribuição por cópia <a class="spec-record-ref" data-req="SWS_CRYPT_30216" href="../spec/record.html?id=SWS_CRYPT_30216">[SWS_CRYPT_30216]</a> e o operador de atribuição por movimentação <a class="spec-record-ref" data-req="SWS_CRYPT_30217" href="../spec/record.html?id=SWS_CRYPT_30217">[SWS_CRYPT_30217]</a> foram excluídos (<code>=delete</code>).</p>
<p>A liberação dos recursos ocorre de forma polimórfica por meio do destrutor virtual <code>~CryptoProvider</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20710" href="../spec/record.html?id=SWS_CRYPT_20710">[SWS_CRYPT_20710]</a>. Em relação à segurança de execução, todos os métodos de interface são declarados como seguros para threads (thread-safe) e seguros contra exceções (exception safe). Todos os métodos utilizam <code>noexcept</code> e relatam erros exclusivamente por meio do tipo de retorno <code>ara::core::Result</code>.</p>

<h4>Caminho de utilização</h4>
<p>Um fluxo de uso típico para operações criptográficas consiste na determinação de permissões de uso, no provisionamento de chaves e na subsequente criação de contexto:</p>
<ol>
<li>Consultar flags de uso padrão: antes da geração da chave, é possível determinar por meio de <code>GetDefaultAllowedUsage(algId)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20955" href="../spec/record.html?id=SWS_CRYPT_20955">[SWS_CRYPT_20955]</a> quais flags de uso estão previstas por padrão para o algoritmo selecionado. De acordo com a especificação, as flags retornadas não contêm <code>kAllowPlaintextExport</code>, <code>kAllowPersist</code> nem <code>kAllowSecuredExport</code>.</li>
<li>Provisionar chaves: uma nova chave simétrica é gerada via <code>GenerateSymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20721" href="../spec/record.html?id=SWS_CRYPT_20721">[SWS_CRYPT_20721]</a> ou um par de chaves assimétricas via <code>GeneratePrivateKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20722" href="../spec/record.html?id=SWS_CRYPT_20722">[SWS_CRYPT_20722]</a>. Alternativamente, uma chave existente pode ser carregada via <code>LoadSymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20762" href="../spec/record.html?id=SWS_CRYPT_20762">[SWS_CRYPT_20762]</a>, <code>LoadPrivateKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20764" href="../spec/record.html?id=SWS_CRYPT_20764">[SWS_CRYPT_20764]</a> ou <code>LoadPublicKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20763" href="../spec/record.html?id=SWS_CRYPT_20763">[SWS_CRYPT_20763]</a>. Na geração de chaves privadas, o provedor deriva automaticamente as flags de uso da chave pública correspondente e ativa <code>kAllowPlaintextExport</code> e <code>kAllowPersist</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20722" href="../spec/record.html?id=SWS_CRYPT_20722">[SWS_CRYPT_20722]</a> para esta.</li>
<li>Instanciar contexto: com base na transformação desejada, o chamador cria o contexto necessário, por exemplo, um <code>AuthCipherCtx</code> via <code>CreateAuthCipherCtx(algId)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20745" href="../spec/record.html?id=SWS_CRYPT_20745">[SWS_CRYPT_20745]</a>. O contexto criado provavelmente será configurado com a chave em etapas posteriores.</li>
<li>Exportação de chaves (opcional): se um objeto de chave precisar ser exportado de forma protegida, o <code>ExportSecuredKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20728" href="../spec/record.html?id=SWS_CRYPT_20728">[SWS_CRYPT_20728]</a> serializa e criptografa o objeto em um buffer de saída usando uma Key-Encryption-Key opcional (<code>kek</code>).</li>
</ol>
