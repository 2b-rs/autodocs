Fornece uma visualização estruturada para gerenciar e ler registros de dados de diagnóstico SOVD baseados em chave.

A classe fornece uma visualização estruturada de registros de dados SOVD do tipo RecordContentElementData para o diagnóstico da Adaptive Platform (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView»). Ela possibilita a adição, a leitura e o gerenciamento baseados em chave de elementos de diagnóstico primitivos e complexos por meio de métodos thread-safe, como Add ou operator[] ([SWS_DM_02288]). O pré-requisito para todas as operações é que o elemento de dados subjacente seja do tipo record exigido, pois, caso contrário, as chamadas são abortadas com um erro no Result de retorno.

Contexto

A classe ara::diag::DiagnosticSovdRecordContentElementDataView atua no contexto do Service-Oriented Vehicle Diagnostics (SOVD) como uma visualização estruturada (View) sobre um elemento de dados de diagnóstico do tipo RecordContentElementData ou ContentData (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView», [SWS_DM_02270]). Ela permite que aplicações de diagnóstico e o sistema de tempo de execução de diagnóstico criem, leiam e modifiquem registros baseados em campos a partir de pares chave-valor ([SWS_DM_02288]). Como parceiros de interação atuam, por um lado, as implementações de serviços de diagnóstico, que fornecem ou consomem dados de diagnóstico, e, por outro lado, os objetos de contêiner genéricos subjacentes do tipo DiagnosticSovdContentElementData. Por meio de interfaces padronizadas, a View desacopla a manipulação específica da aplicação da forma física de armazenamento dos conteúdos de diagnóstico.

Ciclo de vida

De acordo com sua finalidade como View, a instância presumivelmente mantém apenas uma referência a um objeto de dados existente do tipo DiagnosticSovdContentElementData (interpretação). Disso decorre que o tempo de vida do registro de dados referenciado deve obrigatoriamente cobrir a existência da View para evitar referências inválidas. Todos os métodos declarados da classe são projetados como thread-safe (thread-safe) e seguros contra exceções (exception safe) de acordo com a especificação ([SWS_DM_02273], [SWS_DM_02288]). O ciclo de vida dos elementos de dados contidos no registro pode ser gerenciado dinamicamente: elementos existentes podem ser removidos completamente via Clear ([SWS_DM_02276]), excluídos seletivamente mediante sua chave por meio de Remove ([SWS_DM_02287]) ou retirados do contêiner por meio de um iterador com Erase ([SWS_DM_02294]).

Caminho de utilização

Um fluxo de uso típico inclui a preparação da memória, a adição de elementos, a navegação e a leitura de campos:

  • Preparação da memória: Para evitar realocações quando o número de elementos for conhecido, a capacidade pode ser definida antecipadamente com Reserve ([SWS_DM_02283]). A capacidade atual pode ser consultada por meio de Capacity ([SWS_DM_02274]).
  • Preenchimento do registro: Valores tipados são registrados informando-se uma chave por meio de operações Add sobrecarregadas (key). Há suporte para tipos de dados primitivos como std::int64_t ([SWS_DM_02288]), std::uint64_t ([SWS_DM_02289]), double ([SWS_DM_02290]), bool ([SWS_DM_02291]) e valores de string via ara::core::StringView ([SWS_DM_02292]). Da mesma forma, elementos de diagnóstico aninhados do tipo DiagnosticSovdContentElementData podem ser adicionados ([SWS_DM_02293]).
  • Verificação e consulta: Antes do acesso, pode-se verificar se está vazio com Empty ([SWS_DM_02275]) e consultar a quantidade de elementos existentes com Size ([SWS_DM_02273]). A existência de uma chave é verificada por meio de HasContentElement ([SWS_DM_02284]).
  • Acesso e iteração: O acesso a elementos concretos ocorre diretamente por meio do operador de índice operator[], que retorna uma referência ao elemento alvo ([SWS_DM_02277], [SWS_DM_02278]), ou por meio do método de busca Find ([SWS_DM_02285], [SWS_DM_02286]). Para percursos, iteradores estão disponíveis por meio de Begin, End, CBegin e CEnd ([SWS_DM_02279], [SWS_DM_02280], [SWS_DM_02281], [SWS_DM_02282]).

Diagrama de sequência: Fluxo típico de preenchimento e leitura de um elemento de registro SOVD. Fontes: [SWS_DM_02283], [SWS_DM_02288], [SWS_DM_02277], [SWS_DM_02271].

Cenários de erro

As operações no registro de dados estão sujeitas a pré-condições rígidas quanto ao tipo de contêiner e à validade das chaves:

  • Conflitos de tipo: Todos os métodos de acesso, inserção e exclusão exigem que o elemento subjacente seja do tipo RecordContentElementData ou ContentData. Caso contrário, operações como Add ([SWS_DM_02288]), operator[] ([SWS_DM_02277]), HasContentElement ([SWS_DM_02284]) e Remove ([SWS_DM_02287]) falham e retornam um ara::core::Result com estado de erro.
  • Chaves não encontradas: Um acesso via operator[] ou uma exclusão via Remove retorna um erro se a chave solicitada não existir no registro ([SWS_DM_02277], [SWS_DM_02287]).
  • Iteradores inválidos na exclusão: A exclusão via iterador por meio de Erase retorna o código de erro DiagErrc::kInvalidArgument em caso de parâmetros inválidos ou vinculação de dados incorreta ([SWS_DM_02294]).
  • Tratamento explícito de erros: Além de erros específicos de métodos, o estado geral do registro de dados pode ser explicitamente marcado como defeituoso com um ara::core::ErrorCode por meio de SetError ([SWS_DM_02272]). Chamadores podem verificar a existência de um erro por meio de HasError, que, em caso de erro, retorna um ara::diag::DiagSovdErrc correspondente ([SWS_DM_02271]).
