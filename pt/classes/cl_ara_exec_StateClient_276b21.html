classe ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Contexto

A classe ara::exec::StateClient atua como interface funcional do Execution Management para o State Management. No sistema global, cabe ao State Management a tarefa de controlar o ciclo de vida de uma máquina e iniciar, bem como parar componentes de software conforme a necessidade. Isso ocorre por meio de transições de estado de grupos de funções configurados (Function Groups), aos quais processos de software concretos foram atribuídos pelo integrador.

O State Management utiliza ara::exec::StateClient para solicitar transições de estado para grupos de funções individuais ao Execution Management [SWS_EM_02278]. O Execution Management executa essas transições iniciando ou finalizando o software atribuído ao grupo de funções e reporta o resultado da transição de volta ao State Management. Para o estabelecimento da conexão com o Execution Management, provavelmente é utilizado em segundo plano um canal de IPC específico da plataforma (como Unix-Domain-Sockets), uma vez que a especificação não restringe mais detalhadamente a tecnologia de IPC exata.

Ciclo de vida

Para a instanciação de ara::exec::StateClient, o AUTOSAR disponibiliza dois caminhos de construção:

  • Método de fábrica nomeado: A função estática Create retorna um ara::core::Result<StateClient> e encapsula potenciais erros na criação com base em código de erro e de forma segura contra exceções ([SWS_EM_02276]).
  • Construtor regular: O construtor direto está declarado como noexcept(false) e sinaliza erros em caso de falha por meio de exceções ([SWS_EM_02561]).

Ambos os caminhos de criação exigem a passagem de um callback undefinedStateCallback com a assinatura std::function<void(const ara::exec::ExecutionErrorEvent&)>. Esse callback é chamado pela biblioteca StateClient caso um grupo de funções mude inesperadamente e sem solicitação prévia via SetState para um estado indefinido (Undefined Function Group State) ([SWS_EM_02276], [SWS_EM_02561]). Em relação ao tempo de vida, é obrigatório garantir que esse callback permaneça invocável durante todo o tempo de vida da instância de StateClient; isso se aplica especialmente à vinculação de métodos de instância via std::bind ([SWS_EM_02276], [SWS_EM_02561]).

Operações de cópia são completamente impedidas: tanto o construtor de cópia quanto o operador de atribuição estão explicitamente excluídos (delete) ([SWS_EM_02565], [SWS_EM_02568]). Por outro lado, a classe oferece suporte à semântica de movimento: o construtor de movimento e o operador de atribuição por movimento estão definidos como noexcept ([SWS_EM_02566], [SWS_EM_02567]). O destrutor está declarado como noexcept ([SWS_EM_02277]). Assim que uma mudança de estado for recebida pelo Execution Management, ela será processada independentemente do tempo de vida da instância de StateClient; contudo, o ara::core::Future retornado por SetState depende do tempo de vida da instância ([SWS_EM_02278]).

Em relação à concorrência, os métodos de instância SetState, GetExecutionError e GetInitialMachineStateTransitionResult, bem como Create e o construtor regular, são especificados como thread-safe ([SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542], [SWS_EM_02561]). As operações de movimento e o destrutor, por outro lado, não são thread-safe ([SWS_EM_02566], [SWS_EM_02567], [SWS_EM_02277]).

Caminho de utilização

Um fluxo de utilização típico pelo State Management divide-se nas seguintes etapas:

  1. Criação do cliente: O State Management instancia StateClient via Create, registrando o callback de erro ([SWS_EM_02276]).
  2. Sincronizar estado inicial: No início da operação da máquina, o resultado da transição inicial da máquina para o estado Startup é consultado via GetInitialMachineStateTransitionResult() ([SWS_EM_02279]). O método retorna um ara::core::Future<void>. Como essa transição ocorre exatamente uma vez por ciclo de vida da máquina, o resultado permanece inalterado durante o restante do tempo de execução ([SWS_EM_02279]).
  3. Solicitar mudança de estado: Em tempo de execução, o State Management solicita transições para grupos de funções individuais via SetState(state) ([SWS_EM_02278]). O método retorna imediatamente e fornece um ara::core::Future<void>, que indica o sucesso da transição ou disponibiliza um erro da ExecErrorDomain.
  4. Analisar estados de erro: Se um grupo de funções transitar inesperadamente para um estado indefinido, o callback registrado é acionado. O State Management pode obter o ExecutionErrorEvent causador por meio de GetExecutionError(functionGroupState), enquanto o grupo de funções ainda permanecer nesse estado ([SWS_EM_02542]).

Cenários de erro

Os métodos de ara::exec::StateClient utilizam códigos de erro do domínio de erros do Execution Management (ara::exec::ExecErrc). Os seguintes cenários de erro são relevantes:

  • Falha de comunicação (ExecErrc::kNoCommunication): Ocorre quando a conexão entre o cliente e o Execution Management está com falha ou interrompida. Esse erro é especificado para todas as operações ([SWS_EM_02276], [SWS_EM_02561], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]). A repetição da chamada é a medida de recuperação prevista.
  • Passagem inválida e conflitos de metamodelo:
    • ExecErrc::kInvalidArgument sinaliza durante a criação que o undefinedStateCallback passado não é invocável ([SWS_EM_02276], [SWS_EM_02561]).
    • ExecErrc::kInvalidMetaModelIdentifier indica que o estado de destino não existe no manifesto ou que o processo chamador não possui mapeamento para o respectivo grupo de funções ([SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]).
  • Falha ou cancelamento de transições de estado:
    • ExecErrc::kOperationCanceled informa que uma transição foi substituída por uma solicitação mais recente ou cancelada pelo State Management ([SWS_EM_02278], [SWS_EM_02279]).
    • ExecErrc::kInvalidTransition é retornado se a transição for inválida (por ex., mudança para o estado Off para MachineFG) ou se o estado não existir mais após uma atualização de software ([SWS_EM_02278]).
    • ExecErrc::kIntegrityOrAuthenticityCheckFailed relata a falha de verificações de autenticidade ou de integridade durante a mudança de estado ([SWS_EM_02278]).
    • ExecErrc::kUnexpectedTermination ocorre quando um processo participante é encerrado inesperadamente durante a transição ([SWS_EM_02278]).
    • ExecErrc::kOperationFailed indica a falha geral de uma transição ([SWS_EM_02278], [SWS_EM_02279]). Na chamada de GetExecutionError, esse erro indica, por outro lado, que o grupo de funções não se encontra em um estado indefinido e que o problema pode já ter sido corrigido ([SWS_EM_02542]).

Este guia baseia-se na especificação do Execution Management para a AUTOSAR Adaptive Platform no Release R25-11.

<h4>Contexto</h4>
<p>A classe <code>ara::exec::StateClient</code> atua como interface funcional do Execution Management para o State Management. No sistema global, cabe ao State Management a tarefa de controlar o ciclo de vida de uma máquina e iniciar, bem como parar componentes de software conforme a necessidade. Isso ocorre por meio de transições de estado de grupos de funções configurados (<em>Function Groups</em>), aos quais processos de software concretos foram atribuídos pelo integrador.</p>
<p>O State Management utiliza <code>ara::exec::StateClient</code> para solicitar transições de estado para grupos de funções individuais ao Execution Management <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. O Execution Management executa essas transições iniciando ou finalizando o software atribuído ao grupo de funções e reporta o resultado da transição de volta ao State Management. Para o estabelecimento da conexão com o Execution Management, provavelmente é utilizado em segundo plano um canal de IPC específico da plataforma (como Unix-Domain-Sockets), uma vez que a especificação não restringe mais detalhadamente a tecnologia de IPC exata.</p>

<p>Para a instanciação de <code>ara::exec::StateClient</code>, o AUTOSAR disponibiliza dois caminhos de construção:</p>

<li><strong>Método de fábrica nomeado:</strong> A função estática <code>Create</code> retorna um <code>ara::core::Result&lt;StateClient&gt;</code> e encapsula potenciais erros na criação com base em código de erro e de forma segura contra exceções (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Construtor regular:</strong> O construtor direto está declarado como <code>noexcept(false)</code> e sinaliza erros em caso de falha por meio de exceções (<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
</ul>
<p>Ambos os caminhos de criação exigem a passagem de um callback <code>undefinedStateCallback</code> com a assinatura <code>std::function&lt;void(const ara::exec::ExecutionErrorEvent&amp;)&gt;</code>. Esse callback é chamado pela biblioteca StateClient caso um grupo de funções mude inesperadamente e sem solicitação prévia via <code>SetState</code> para um estado indefinido (<em>Undefined Function Group State</em>) (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). Em relação ao tempo de vida, é obrigatório garantir que esse callback permaneça invocável durante todo o tempo de vida da instância de <code>StateClient</code>; isso se aplica especialmente à vinculação de métodos de instância via <code>std::bind</code> (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</p>
<p>Operações de cópia são completamente impedidas: tanto o construtor de cópia quanto o operador de atribuição estão explicitamente excluídos (<code>delete</code>) (<a class="spec-record-ref" data-req="SWS_EM_02565" href="../spec/record.html?id=SWS_EM_02565">[SWS_EM_02565]</a>, <a class="spec-record-ref" data-req="SWS_EM_02568" href="../spec/record.html?id=SWS_EM_02568">[SWS_EM_02568]</a>). Por outro lado, a classe oferece suporte à semântica de movimento: o construtor de movimento e o operador de atribuição por movimento estão definidos como <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>). O destrutor está declarado como <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>). Assim que uma mudança de estado for recebida pelo Execution Management, ela será processada independentemente do tempo de vida da instância de <code>StateClient</code>; contudo, o <code>ara::core::Future</code> retornado por <code>SetState</code> depende do tempo de vida da instância (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</p>
<p>Em relação à concorrência, os métodos de instância <code>SetState</code>, <code>GetExecutionError</code> e <code>GetInitialMachineStateTransitionResult</code>, bem como <code>Create</code> e o construtor regular, são especificados como thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). As operações de movimento e o destrutor, por outro lado, não são thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>, <a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>).</p>

<h4>Caminho de utilização</h4>
<p>Um fluxo de utilização típico pelo State Management divide-se nas seguintes etapas:</p>
<ol>
<li><strong>Criação do cliente:</strong> O State Management instancia <code>StateClient</code> via <code>Create</code>, registrando o callback de erro (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Sincronizar estado inicial:</strong> No início da operação da máquina, o resultado da transição inicial da máquina para o estado Startup é consultado via <code>GetInitialMachineStateTransitionResult()</code> (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). O método retorna um <code>ara::core::Future&lt;void&gt;</code>. Como essa transição ocorre exatamente uma vez por ciclo de vida da máquina, o resultado permanece inalterado durante o restante do tempo de execução (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><strong>Solicitar mudança de estado:</strong> Em tempo de execução, o State Management solicita transições para grupos de funções individuais via <code>SetState(state)</code> (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>). O método retorna imediatamente e fornece um <code>ara::core::Future&lt;void&gt;</code>, que indica o sucesso da transição ou disponibiliza um erro da <code>ExecErrorDomain</code>.</li>
<li><strong>Analisar estados de erro:</strong> Se um grupo de funções transitar inesperadamente para um estado indefinido, o callback registrado é acionado. O State Management pode obter o <code>ExecutionErrorEvent</code> causador por meio de <code>GetExecutionError(functionGroupState)</code>, enquanto o grupo de funções ainda permanecer nesse estado (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ol>

<h4>Cenários de erro</h4>
<p>Os métodos de <code>ara::exec::StateClient</code> utilizam códigos de erro do domínio de erros do Execution Management (<code>ara::exec::ExecErrc</code>). Os seguintes cenários de erro são relevantes:</p>
<ul>
<li><strong>Falha de comunicação (<code>ExecErrc::kNoCommunication</code>):</strong> Ocorre quando a conexão entre o cliente e o Execution Management está com falha ou interrompida. Esse erro é especificado para todas as operações (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>). A repetição da chamada é a medida de recuperação prevista.</li>
<li><strong>Passagem inválida e conflitos de metamodelo:</strong>
<ul>
<li><code>ExecErrc::kInvalidArgument</code> sinaliza durante a criação que o <code>undefinedStateCallback</code> passado não é invocável (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code> indica que o estado de destino não existe no manifesto ou que o processo chamador não possui mapeamento para o respectivo grupo de funções (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
<li><strong>Falha ou cancelamento de transições de estado:</strong>
<ul>
<li><code>ExecErrc::kOperationCanceled</code> informa que uma transição foi substituída por uma solicitação mais recente ou cancelada pelo State Management (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><code>ExecErrc::kInvalidTransition</code> é retornado se a transição for inválida (por ex., mudança para o estado Off para MachineFG) ou se o estado não existir mais após uma atualização de software (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code> relata a falha de verificações de autenticidade ou de integridade durante a mudança de estado (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kUnexpectedTermination</code> ocorre quando um processo participante é encerrado inesperadamente durante a transição (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kOperationFailed</code> indica a falha geral de uma transição (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). Na chamada de <code>GetExecutionError</code>, esse erro indica, por outro lado, que o grupo de funções não se encontra em um estado indefinido e que o problema pode já ter sido corrigido (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
</ul>
