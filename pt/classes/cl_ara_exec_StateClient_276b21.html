classe ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Solicita ao Execution Management transições de estado para grupos de funções a fim de controlar processos em uma Machine.

A interface ara::exec::StateClient permite ao State Management solicitar transições de estado para grupos de funções junto ao Execution Management a fim de controlar a execução de processos atribuídos em uma Machine [SWS_EM_02278]. Na criação via Create(), deve ser registrado um callback com validade ininterrupta para estados indefinidos inesperados [SWS_EM_02276]. Além de transições de estado assíncronas, a classe não copiável oferece métodos para consultar o resultado de inicialização da Machine, bem como para análise de falhas em erros de execução [SWS_EM_02279], [SWS_EM_02542].

Contexto

A classe ara::exec::StateClient constitui a interface do Execution Management por meio da qual o State Management solicita e controla transições de estado para grupos de funções (Function Groups). O State Management utiliza este cliente durante todo o tempo de operação de uma Machine para iniciar ou encerrar processos de maneira direcionada. O integrador atribui componentes de software a determinados estados de um grupo de funções. Caso o State Management deseje executar esse software, ele solicita ao Execution Management, por meio do StateClient, a transição para o estado do grupo de funções em questão; a parada ocorre de modo análogo, mediante a transição para um estado no qual o software não deve estar ativo [SWS_EM_02278].

Diagrama de contexto: interação entre State Management, StateClient e Execution Management. Fontes: [SWS_EM_02276], [SWS_EM_02278]

Ciclo de vida

Instâncias de StateClient podem ser criadas tanto pelo construtor nomeado Create() [SWS_EM_02276] como ara::core::Result<StateClient> quanto pelo construtor regular StateClient() [SWS_EM_02561]. Ambos os caminhos de construção exigem obrigatoriamente um parâmetro de callback undefinedStateCallback do tipo std::function<void(const ara::exec::ExecutionErrorEvent&)>. Esse callback é acionado pela biblioteca StateClient quando um grupo de funções transita para um estado indefinido de forma inesperada e sem solicitação prévia por SetState(). O chamador deve assegurar que esse callback permaneça invocável durante toda a vida útil da instância de StateClient, o que é relevante em especial nas vinculações de objetos via std::bind [SWS_EM_02276], [SWS_EM_02561].

Operações de cópia são explicitamente proibidas para StateClient: tanto o construtor de cópia [SWS_EM_02565] quanto o operador de atribuição por cópia [SWS_EM_02568] foram excluídos (=delete). A transferência da titularidade só é possível por meio da semântica de movimentação via construtor de movimentação [SWS_EM_02566] e atribuição por movimentação [SWS_EM_02567]. No tocante à concorrência, os métodos funcionais como SetState(), GetExecutionError() e GetInitialMachineStateTransitionResult(), bem como a criação, são projetados como thread-safe [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]. Em contrapartida, as operações de movimentação e o destrutor ~StateClient() não são thread-safe [SWS_EM_02277], [SWS_EM_02566], [SWS_EM_02567].

Caminho de utilização

Um ciclo típico de aplicação divide-se em inicialização, consulta do resultado da subida (inicialização), transições regulares de estado e monitoramento de erros:

  1. Criação: o State Management instancia StateClient indicando um callback válido de sinalização de erros via Create() [SWS_EM_02276].
  2. Consultar o resultado de inicialização inicial: com GetInitialMachineStateTransitionResult(), o State Management solicita o resultado da transição de estado inicial para o estado Startup [SWS_EM_02279]. Como essa transição ocorre exatamente uma vez por ciclo de vida da Machine, o ara::core::Future<void> fornecido permanece estável e não se altera mais até uma reinicialização.
  3. Solicitar mudança de estado: por meio de SetState(), o State Management solicita transições de estado assíncronas para Function Groups individuais [SWS_EM_02278]. O método retorna imediatamente e fornece um ara::core::Future<void> para consultar a conclusão. Assim que a solicitação é recebida pelo Execution Management, ela é executada independentemente do tempo de vida restante da instância chamadora.
  4. Investigar estados de erro: se um Function Group entrar inesperadamente em um estado indefinido, o erro de execução causador poderá ser determinado na forma de um ara::exec::ExecutionErrorEvent por meio de GetExecutionError() [SWS_EM_02542].

Diagrama de sequência: fluxo de criação, consulta de estado inicial, mudança assíncrona de estado e análise de erros. Fontes: [SWS_EM_02276], [SWS_EM_02279], [SWS_EM_02278], [SWS_EM_02542]

Cenários de erro

As operações da classe comunicam falhas por meio de códigos de erro de ExecErrorDomain:

  • ExecErrc::kNoCommunication: sinaliza falhas de comunicação com o Execution Management, por exemplo, no caso de uma conexão IPC interrompida. Ocorre em Create() [SWS_EM_02276], SetState() [SWS_EM_02278], GetInitialMachineStateTransitionResult() [SWS_EM_02279] bem como GetExecutionError() [SWS_EM_02542]. A recuperação prevista consiste na repetição da chamada.
  • ExecErrc::kInvalidArgument: é reportado por Create() e StateClient() se o callback fornecido não contiver uma função chamável [SWS_EM_02276], [SWS_EM_02561].
  • ExecErrc::kOperationCanceled: indica em SetState() que uma transição em andamento foi cancelada por uma solicitação mais recente [SWS_EM_02278]. Em GetInitialMachineStateTransitionResult(), esse erro ocorre se a transição inicial de inicialização tiver sido cancelada, por exemplo, devido a uma sequência interrompida de atualização de Machine [SWS_EM_02279].
  • ExecErrc::kInvalidTransition: a transição de estado solicitada é inválida, por exemplo, a transição para o estado Off para MachineFG, ou o estado não existe mais após uma atualização [SWS_EM_02278].
  • ExecErrc::kInvalidMetaModelIdentifier: o estado fornecido não existe no manifesto processado ou o processo não possui mapeamento para o respectivo Function Group [SWS_EM_02278], [SWS_EM_02542]. Se esse erro ocorrer em GetInitialMachineStateTransitionResult(), falta ao processo o mapeamento para MachineFG, o que indica um problema de configuração [SWS_EM_02279].
  • ExecErrc::kOperationFailed: a transição falhou [SWS_EM_02278]. Em GetExecutionError(), o código indica que o Function Group não se encontra em um estado indefinido e o problema presumivelmente já foi resolvido [SWS_EM_02542].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed e ExecErrc::kUnexpectedTermination: falhas específicas durante SetState() devido a verificações de integridade com falha ou encerramentos inesperados de processos durante a transição [SWS_EM_02278].

O método de fábrica estático Create serve como Named Constructor para a criação de uma instância de ara::exec::StateClient ([SWS_EM_02276]). Como parâmetro obrigatório é passado undefinedStateCallback. Este callback é disparado pela biblioteca de cliente quando um grupo de funções transiciona inesperadamente – ou seja, sem solicitação prévia via SetState() – para um estado indefinido ([SWS_EM_02276]). Nessa ocasião, o grupo de funções afetado e o erro são transmitidos ao callback através de um ExecutionErrorEvent.

Para o contexto de chamada e o tempo de vida aplicam-se condições de contorno fixas:

  • A função é thread-safe, exception-safe e declarada como noexcept ([SWS_EM_02276]).
  • O undefinedStateCallback passado deve permanecer invocável durante todo o tempo de vida da instância de StateClient criada ([SWS_EM_02276]). Isto requer cuidado especial em vinculações a instâncias de objetos (por exemplo, mediante std::bind).

A instanciação ocorre de forma síncrona e retorna um ara::core::Result<StateClient> ([SWS_EM_02276]). Em caso de falha, são definidos os seguintes códigos de erro:

  • ara::exec::ExecErrc::kInvalidArgument: É reportado quando o argumento passado não contém uma função invocável (semântica de rollback; resolução mediante fornecimento de uma função válida) ([SWS_EM_02276]).
  • ara::exec::ExecErrc::kNoCommunication: Sinaliza um erro de comunicação (semântica de no-rollback; resolução mediante nova tentativa) ([SWS_EM_02276]). Isto presumivelmente deve-se a uma falha no estabelecimento de conexão com o ambiente de execução.

O padrão de construção corresponde estruturalmente à abordagem de inicialização de clientes de execução relacionados como ara::exec::ExecutionClient ([SWS_EM_02562]), que também é criado com um callback obrigatório através de um Named Constructor.

              O método SetState serve para solicitar ao Execution Management a transição de estado para um único grupo de funções [SWS_EM_02278]. A chamada ocorre de forma assíncrona: o método dispara a transição e retorna imediatamente com um ara::core::Future<void>, por meio do qual o resultado da transição pode ser determinado [SWS_EM_02278]. Como parâmetro, é passado um FunctionGroupState, que identifica o estado de destino dentro do grupo de funções em conformidade com o metamodelo [SWS_EM_02278].
              
  
              Se a transição falhar, o Future fornece um erro do ErrorDomain Exec [SWS_EM_02278]. Uma semântica de rollback é aplicada em ara::exec::ExecErrc::kInvalidTransition (por exemplo, em transições proibidas como o estado Off para MachineFG) e em ara::exec::ExecErrc::kInvalidMetaModelIdentifier (em caso de mapeamento ausente ou definição ausente no manifesto) [SWS_EM_02278]. Sem semântica de rollback, são reportados kOperationCanceled (substituída por requisição mais recente), kOperationFailed, kNoCommunication (conexão IPC com falha), kIntegrityOrAuthenticityCheckFailed, bem como kUnexpectedTermination [SWS_EM_02278].
              
  
              O método é thread-safe e exception safe (noexcept) [SWS_EM_02278]. O ara::core::Future retornado depende do tempo de vida da instância chamadora; o Execution Management, por sua vez, processa a requisição recebida independentemente do tempo de vida da instância de StateClient [SWS_EM_02278].
              
  
              Na interação com a instanciação via Create [SWS_EM_02276] ou pelo construtor [SWS_EM_02561], um undefinedStateCallback intercepta mudanças de estado inesperadas que ocorram sem chamada prévia de SetState. O resultado da transição inicial para o estado Startup pode ser consultado separadamente via GetInitialMachineStateTransitionResult [SWS_EM_02279].

              Scopeclass ara::exec::StateClient
              Segurança de exceçãoexception safe
              Segurança entre threadsthread-safe
              

              parâmetros (em)
              

              ParâmetrosDescrição
              staterepresenting meta-model definition of a state inside a specific Function Group. Execution Management will perform state transition from the current state to the state identified by this parameter.
              

              Valor de retorno
              

              TipoDescrição
              ara::core::Future< void >void if requested transition is successful, otherwise it returns Exec ErrorDomain error.
              

              Erro
              

              Código de erroDescrição
              ara::exec::ExecErrc::kOperationCanceledno_rollback_semantics if transition to the requested Function Group state was cancelled by a newer request. Recovery: Try again (error is informative, does not indicate a problem)
              ara::exec::ExecErrc::kOperationFailedno_rollback_semantics if transition to the requested Function Group state failed. Recovery: Try transition to another state
              ara::exec::ExecErrc::kNoCommunicationno_rollback_semantics if StateClient can’t communicate with Execution Management (e.g. IPC link is down). Rovery: Try again
              ara::exec::ExecErrc::kInvalidTransitionrollback_semantics if transition to the requested state is prohibited (e.g. Off state for MachineFG) or the requested Function Group State is invalid (e.g. does not exist anymore after a software update). Recovery: Eventually try transition to another state
              ara::exec::ExecErrc::kIntegrityOrAuthenticityCheckFailedno_rollback_semantics if an integrity or authenticity check failed during state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kUnexpectedTerminationno_rollback_semantics One of the processes terminated in an unexpected way during the state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kInvalidMetaModelIdentifierrollback_semantics The given Function Group State couldn’t be found in the Processed Manifest or Process does not have a mapping to the Function Group of the requested Function Group State. Recovery: transition to another state
              

              Hinweise: Asynchronous nature of ara::exec::StateClient::SetState makes the returned ara:: core::Future dependable on lifetime of the instance from which it was received. It is expected that once state change request is received by Execution Management, it will be processed independently of lifetime of the instance from which it was requested. Please note that the qualified short names representing Function Groups and Function Group States could be quite long. They can be replaced by implementation specific data types to speed up any checks that have to be performed by the ara::exec::StateClient:: SetState method. This is enabled by the ara::exec::FunctionGroupState data-type.

                  ParâmetrosDescrição
