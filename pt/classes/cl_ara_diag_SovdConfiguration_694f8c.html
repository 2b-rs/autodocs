Serve para o provisionamento e o processamento, no lado da aplicação, de recursos de configuração SOVD modelados explicitamente.

A interface ara::diag::SovdConfiguration atua como um tratador genérico para configurações SOVD modeladas explicitamente, para o qual o Diagnostic Server encaminha os acessos de leitura e escrita recebidos [SWS_DM_01860], [SWS_DM_01787]. Após a instanciação baseada em portas, a aplicação ativa a recepção de mensagens por meio de Offer e a encerra, se necessário, com StopOffer [SWS_DM_01872], [SWS_DM_01930]. O provisionamento de dados ocorre de forma assíncrona por meio de sessões de leitura ou de escrita, sendo os erros de domínio sinalizados de acordo com a ISO 17978-3 ou ASAM SOVD 1.1 [SWS_DM_01870].

Contexto

A interface ara::diag::SovdConfiguration define a interface genérica para tratadores de configuração SOVD modelados explicitamente dentro da arquitetura de diagnóstico do Adaptive AUTOSAR [SWS_DM_01860]. Caso ao menos uma configuração SOVD esteja projetada no sistema, a instância de Diagnostic Server do Diagnostic Management (DM) disponibiliza externamente o método padronizado de SOVD Retrieve List of All Configurations Provided by the Entity de acordo com o ASAM SOVD [SWS_DM_01429]. O Diagnostic Server encaminha os acessos de leitura e escrita recebidos para tal configuração explícita à implementação concreta de ara::diag::SovdConfiguration: ao chamar o método SOVD Read Configuration, o Diagnostic Server chama o método RequestGetConfiguration [SWS_DM_01787], enquanto na chamada de Write Configuration o método RequestPutConfiguration é executado [SWS_DM_01788].

Diagrama de contexto: Integração de ara::diag::SovdConfiguration entre o cliente SOVD externo, o Diagnostic Server (DM) e o tratador específico da aplicação. Fontes: [SWS_DM_01429], [SWS_DM_01787], [SWS_DM_01788], [SWS_DM_01860].

Ciclo de vida

A instanciação de ara::diag::SovdConfiguration ocorre no lado da aplicação mediante a passagem de um ara::core::InstanceSpecifier bem como a indicação de um ConcurrencyType (kConcurrent ou kNotConcurrent) [SWS_DM_01864]. O InstanceSpecifier referencia um protótipo de porta de um DiagnosticSovdConfigurationInterface no contexto de processo [SWS_DM_01864]. A classe não pode ser copiada (o construtor de cópia e o operador de atribuição por cópia estão declarados como delete) [SWS_DM_01866], [SWS_DM_01868], mas suporta operações de movimentação protegidas [SWS_DM_01867], [SWS_DM_01869]. Para receber requisições do Diagnostic Server, a aplicação deve chamar explicitamente Offer [SWS_DM_01872]. Com a chamada de StopOffer, o encaminhamento de requisições é novamente desativado [SWS_DM_01930]. Na destruição da instância por meio do destrutor virtual [SWS_DM_01865], o objeto é liberado; a liberação pressupõe que o tratador tenha sido previamente desregistrado de forma adequada.

Diagrama de estados: Fases do ciclo de vida de uma instância de SovdConfiguration, desde a inicialização até o StopOffer, passando pelo estado Offer. Fontes: [SWS_DM_01864], [SWS_DM_01872], [SWS_DM_01930], [SWS_DM_01865].

Caminho de utilização

Um caminho de utilização típico inicia-se, após a construção da classe de tratador derivada, com o registro junto ao Diagnostic Management por meio de Offer() [SWS_DM_01872]. Assim que um cliente externo direciona uma requisição de configuração SOVD à entidade, o Diagnostic Server a encaminha: em uma solicitação de leitura, RequestGetConfiguration é chamado, sendo passados a configurationId, a metaInfo e um CancellationHandler [SWS_DM_01870]. O método retorna um ara::core::Future, que disponibiliza assincronamente uma tupla composta por uma DataTransferReadSession e SovdConfigurationMetaInfo [SWS_DM_01870]. Analogamente, o servidor encaminha requisições de escrita via RequestPutConfiguration, o qual retorna um future com uma DataTransferWriteSession e SovdConfigurationMetaInfo [SWS_DM_01871]. Antes de desligar o tratador, a aplicação chama StopOffer() para não aceitar mais nenhuma requisição [SWS_DM_01930].

Diagrama de sequência: Sequência típica de interação na inicialização, processamento de uma Read-Configuration-Request e subsequente cancelamento de registro. Fontes: [SWS_DM_01872], [SWS_DM_01787], [SWS_DM_01870], [SWS_DM_01930].

Cenários de erro

Já na instanciação no construtor podem ocorrer violações de modelo e de mapeamento, caso o InstanceSpecifier não possa ser resolvido no modelo (InstanceSpecifierMappingIntegrityViolation), o protótipo de porta referenciado não esteja tipado por um DiagnosticSovdConfigurationInterface (PortInterfaceMappingViolation), nenhum processo correspondente exista (ProcessMappingViolation) ou o identificador já esteja ocupado no processo atual (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01864]. Ao chamar Offer(), o método retorna um ara::core::Result<void>, que reporta DiagOfferErrc::kConfigurationMismatch em caso de erro, se a configuração não corresponder ao modelo DEXT, ou DiagOfferErrc::kAlreadyOffered, caso o serviço já esteja sendo oferecido [SWS_DM_01872]. Nos métodos de tratador assíncronos RequestGetConfiguration e RequestPutConfiguration, a aplicação reporta estados de erro por meio do ara::core::Future utilizando códigos de erro SOVD padronizados de acordo com a ISO 17978-3 ou ASAM SOVD 1.1 [SWS_DM_01870], [SWS_DM_01871]. Além disso, o CancellationHandler sinaliza se uma comunicação em andamento foi cancelada [SWS_DM_01870], [SWS_DM_01871].

Este guia baseia-se exclusivamente nas especificações da AUTOSAR Adaptive Platform Release R25-11.

função Offer [SWS_DM_01872] Upstream: RS_Diag_04261

ara::core::Result< void > Offer () noexcept;

This Offer will enable the DM to forward request messages to this handler.

usar

O método Offer da classe ara::diag::SovdConfiguration serve para ativar o encaminhamento de requisições de diagnóstico pelo Diagnostic Management (DM) para o handler configurado [SWS_DM_01872]. A chamada ocorre de forma síncrona, não aceita parâmetros e reporta o resultado por meio de ara::core::Result<void> [SWS_DM_01872]. Enquanto um handler não tiver sido disponibilizado via Offer, o DM não encaminha nenhuma requisição de entrada, o que corresponde ao padrão fundamental de disponibilização de interfaces de diagnóstico (cf. [SWS_DM_01525], [SWS_DM_00809]).

Tratamento de erros

Em caso de falha, é retornado um ara::core::Result com um código de erro da enumeração DiagOfferErrc, aplicando-se uma semântica de rollback [SWS_DM_01872]:

  • DiagOfferErrc::kAlreadyOffered: É reportado se o serviço já tiver sido oferecido anteriormente [SWS_DM_01872].
  • DiagOfferErrc::kConfigurationMismatch: Ocorre se a configuração não corresponder aos dados de descrição DEXT [SWS_DM_01872].

Simultaneidade e restrições

A operação é declarada como noexcept e segura contra exceções (exception safe), mas é especificada como não segura para threads (not thread-safe) [SWS_DM_01872]. Chamadas simultâneas à mesma instância a partir de múltiplas threads devem ser evitadas pela aplicação chamadora. Uma nova chamada após o serviço já ter sido oferecido presumivelmente deverá ser confirmada com um erro, sem alteração de estado.

      usar
      

      O método virtual puro RequestGetConfiguration da classe ara::diag::SovdConfiguration é chamado pela Diagnostic Server Instance quando o método SOVD “Read Configuration” é executado para uma configuração SOVD explicitamente modelada ([SWS_DM_01787], AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»). São passados como parâmetros o ID de configuração da instância a ser lida (configurationId), as metainformações da requisição (metaInfo), bem como um cancellationHandler que informa sobre um eventual cancelamento da conversação em andamento ([SWS_DM_01870]).
      

      A função trabalha de forma assíncrona e retorna um ara::core::Future, que disponibiliza uma tupla composta por uma sessão de leitura de arquivo (DataTransferReadSession) e metainformações de configuração correspondentes (SovdConfigurationMetaInfo) ([SWS_DM_01870]). A interface é declarada como noexcept e especificada como segura quanto a exceções ([SWS_DM_01870]).
      

      Tratamento de erros e simultaneidade
      

      Se ocorrer um erro durante o processamento, nenhum erro em C++ é lançado, mas sim retornado via Future um código de erro SOVD aplicável de acordo com a ISO 17978-3 ou ASAM SOVD 1.1 ([SWS_DM_01870]).
      

      Em relação à segurança de threads, aplica-se a especificação “conditional”: se a implementação concreta da função deve ser projetada como segura para threads ou não segura para threads, é decidido pelo ConcurrencyType passado ao construtor ([SWS_DM_01870]).

          O método de API ara::diag::SovdConfiguration::RequestPutConfiguration é chamado pelo Diagnostic Server quando o método “Write Configuration” deve ser executado por meio da interface SOVD para uma configuração explicitamente modelada [SWS_DM_01788], [SWS_DM_01871].
          

          Chamada e parâmetros
          

          A declaração encontra-se no cabeçalho ara/diag/sovd_configuration.h. A chamada passa os seguintes parâmetros de entrada [SWS_DM_01871]:
          

            

          • configurationId: ID da instância de configuração a ser escrita como ara::core::String.
            • 

          • metaInfo: metainformações sobre a requisição recebida (MetaInfo const &).
            • 

          • cancellationHandler: monitora o procedimento atual e sinaliza caso a comunicação tenha sido cancelada.
            • 

          

          O método possui uma semântica assíncrona e retorna um ara::core::Future, que disponibiliza em caso de sucesso uma tupla composta por uma sessão de escrita (DataTransferWriteSession) bem como metadados associados (SovdConfigurationMetaInfo) [SWS_DM_01871].
          

          Tratamento de erros e simultaneidade
          

          Em caso de falha, o Future é resolvido com um código de erro SOVD adequado de acordo com a ISO 17978-3 ou ASAM SOVD 1.1 [SWS_DM_01871]. A função é declarada como noexcept e é segura contra exceções (exception safe). A segurança de threads é condicional (conditional): se a implementação concreta deve ser projetada para ser thread-safe é determinado pelo ConcurrencyType especificado no construtor [SWS_DM_01871].
          

          Interação
          

          A função constitui a contraparte de escrita para RequestGetConfiguration, que é utilizada para o método SOVD “Read Configuration” [SWS_DM_01787] (AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»).
