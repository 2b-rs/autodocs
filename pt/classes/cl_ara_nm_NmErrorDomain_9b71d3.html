Contexto

A classe ara::nm::NmErrorDomain define o domínio de erro oficial para o cluster funcional Network Management (nm) dentro da AUTOSAR Adaptive Platform [SWS_ANM_01101]. De acordo com o modelo de tratamento de erros em toda a plataforma, ela deriva da classe base ara::core::ErrorDomain e está declarada como final, concluindo de forma vinculativa a hierarquia de herança neste ponto [SWS_ANM_01101].

A sua principal responsabilidade consiste em integrar os estados de erro específicos da gestão de rede, de forma tipada, no sistema de erros unificado do AUTOSAR Adaptive. Para este efeito, a classe fornece dois aliases de tipo centrais: Errc referencia a enumeração NmErrc com os códigos de erro concretos [SWS_ANM_01103], enquanto Exception está vinculado à classe de exceção específica de tipo NmException [SWS_ANM_01104]. O parceiro de interação mais importante no sistema de tempo de execução é o ara::core::ErrorCode [SWS_ANM_01108], que encapsula valores de erro e delega a sua representação textual, bem como o tratamento de exceções, à instância responsável de NmErrorDomain.

Ciclo de vida

A instanciação ocorre através do construtor padrão NmErrorDomain() [SWS_ANM_01105]. Este está definido como noexcept e, portanto, exclui completamente exceções durante a construção [SWS_ANM_01105]. A evidência da especificação comprova também explicitamente que o processo de construção é thread-safe [SWS_ANM_01105].

No que diz respeito às relações de propriedade e à gestão de instâncias, um domínio de erro atua tipicamente como um objeto descritor imutável e de longa duração. Em aplicações Adaptive, a instância de NmErrorDomain é presumivelmente mantida como um singleton em todo o processo ou referência estática (Interpretação), de modo a garantir um acesso consistente durante todo o tempo de execução de uma aplicação.

A classe não possui estados internos mutáveis e foi concebida sem estado. Todas as funções-membro para consulta de informações, como Name() [SWS_ANM_01106], Message() [SWS_ANM_01107], bem como a rotina ThrowAsException() [SWS_ANM_01108], estão declaradas como const e identificadas como thread-safe [SWS_ANM_01106], [SWS_ANM_01107], [SWS_ANM_01108]. Isto permite o acesso concorrente a partir de qualquer número de threads sem sobrecarga adicional de sincronização.

Caminho de utilização

Na prática, a utilização de NmErrorDomain ocorre predominantemente de forma indireta através do padrão de tratamento de erros de ara::core::Result e ara::core::ErrorCode. Se uma operação do gerenciamento de rede falhar, a camada gera um código de erro correspondente, associando-o ao domínio.

Um fluxo típico para verificação e processamento de erros divide-se nos seguintes passos:

  1. Verificação do resultado: A lógica da aplicação recebe, após uma chamada de NM, um objeto de erro do tipo ara::core::ErrorCode, que está associado a NmErrorDomain.
  2. Identificação do domínio: Para classificar a origem do erro, o identificador do domínio de erro pode ser consultado através de Name() [SWS_ANM_01106].
  3. Obtenção da mensagem de erro: Para fins de registo ou saída de diagnóstico, Message() [SWS_ANM_01107] fornece uma cadeia de caracteres descritiva para o código de erro específico.
  4. Lançamento de exceção: Se, em caso de erro, for necessário mudar para um fluxo de controlo baseado em exceções, ThrowAsException() [SWS_ANM_01108] é chamado, lançando uma exceção associada ao código de erro.

Diagrama de sequência: Sequência de interação na consulta do texto de erro e lançamento de exceções através do domínio de erro. Fontes: [SWS_ANM_01106], [SWS_ANM_01107], [SWS_ANM_01108]

Cenários de erro

A classe NmErrorDomain serve como estrutura administrativa para códigos de erro e exceções do módulo nm. As situações de erro são representadas pela enumeração NmErrc, acedida através do alias de tipo Errc [SWS_ANM_01103].

Para as chamadas de métodos individuais, são relevantes as seguintes condições e comportamentos:

  • Consulta de nome e de mensagem: Os métodos Name() [SWS_ANM_01106] e Message() [SWS_ANM_01107] estão declarados como noexcept. Garantem que, mesmo durante a consulta de informações de diagnóstico em estados de erro críticos, nenhuma exceção secundária é lançada. Caso seja passado a Message() um valor de erro numérico desconhecido, a implementação fornecerá presumivelmente uma indicação genérica ou texto padrão (Interpretação).
  • Tratamento de exceções: O método ThrowAsException() está explicitamente qualificado como noexcept(false) [SWS_ANM_01108]. A pós-condição da chamada é o lançamento da exceção específica NmException (referenciada através do alias Exception [SWS_ANM_01104]), parametrizada com o ErrorCode [SWS_ANM_01108] transmitido. Se uma aplicação chamar este método direta ou indiretamente, deve existir um bloco catch correspondente para NmException ou ara::core::Exception, a fim de evitar o encerramento do processo.
