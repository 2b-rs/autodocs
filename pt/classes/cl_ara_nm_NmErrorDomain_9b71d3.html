Define o domínio de erro para o Network Management e traduz códigos de erro em mensagens ou exceções.

O domínio de erro ara::nm::NmErrorDomain encapsula o tratamento de erros do Network Management na AUTOSAR Adaptive Platform e integra os códigos de erro NmErrc bem como a classe de exceção NmException [SWS_ANM_01101]. Entre suas tarefas principais estão o fornecimento de mensagens de erro legíveis por meio de Message() e o lançamento controlado de exceções associadas via ThrowAsException() [SWS_ANM_01108]. Como condição de contorno central, a instanciação e todas as funções-membro são implementadas como thread-safe (thread-safe), garantindo uma consulta concorrente de erros em todo o sistema.

Contexto

A classe ara::nm::NmErrorDomain atua dentro da AUTOSAR Adaptive Platform como domínio de erro específico do domínio para o subsistema do Network Management [SWS_ANM_01101]. Como especialização final da classe base ara::core::ErrorDomain, ela disponibiliza a estrutura padronizada para identificação, descrição textual e encaminhamento de erros que possam ocorrer durante a operação de funções de Network Management [SWS_ANM_01101].

Dentro do conceito de tratamento de erros do NM, a classe vincula causas concretas de erro aos mecanismos gerais de tratamento de erros do ambiente de tempo de execução. Aqui, a classe define, por meio de aliases de tipos, uma associação direta aos tipos relevantes: pelo alias Errc, ela integra a enumeração subjacente NmErrc, que declara os códigos de erro específicos para o Network Management [SWS_ANM_01103]. Ao mesmo tempo, ela referencia pelo alias Exception a classe de exceção especializada NmException, permitindo que erros sejam transferidos para o mecanismo de exceções C++, se necessário [SWS_ANM_01104]. Por meio desse agrupamento, NmErrorDomain serve como elo central entre os estados de erro do módulo e o sistema básico específico de erros de ara::core.

Ciclo de vida

A criação de uma instância de ara::nm::NmErrorDomain ocorre por meio do construtor padrão sem parâmetros [SWS_ANM_01105]. Como a classe é especificada como final, uma subdivisão adicional ou especialização por domínios de erro derivados é explicitamente impedida [SWS_ANM_01101]. O construtor é declarado com noexcept, garantindo assim que a instanciação do domínio de erro seja realizada sem o lançamento de exceções [SWS_ANM_01105].

Em relação à posse, uma instância deste domínio de erro deve normalmente existir como um objeto global de longa duração na memória, a fim de estar permanentemente disponível por meio de referências em objetos de código de erro. Uma característica essencial em seu ciclo de vida é o comportamento de simultaneidade: tanto a construção da instância [SWS_ANM_01105] quanto todas as funções de interface, como a consulta de nome [SWS_ANM_01106], a geração de mensagens [SWS_ANM_01107] e o disparo de exceções [SWS_ANM_01108], são projetadas de forma totalmente thread-safe (thread-safe). Como instâncias de NmErrorDomain não apresentam estado mutável, elas podem ser utilizadas concorrentemente a partir de múltiplas threads sem medidas adicionais de sincronização.

Caminho de utilização

O caminho de utilização regular tem início assim que um estado de erro deva ser analisado, registado ou convertido numa exceção no Network Management. Para este efeito, o domínio de erros disponibiliza as funções fundamentais de identificação e avaliação.

Para a identificação geral do domínio, pode ser chamado o método Name(), que retorna o nome do domínio como um ponteiro para cadeia de carateres constante [SWS_ANM_01106]. Quando uma aplicação ou um sistema de base pretende determinar o significado textual de um código de erro ocorrido, o método Message() é chamado passando o código de erro [SWS_ANM_01107]. Este método retorna a mensagem de erro correspondente como const char* e garante, através da sua declaração noexcept, que o próprio processo de diagnóstico permanece seguro contra exceções [SWS_ANM_01107].

Se o fluxo de controlo exigir o lançamento de uma exceção específica do sistema, recorre-se ao método ThrowAsException() [SWS_ANM_01108]. Esta função recebe um objeto de erro do tipo ara::core::ErrorCode e lança a exceção correspondente do tipo NmException [SWS_ANM_01104], [SWS_ANM_01108]. Na prática, a chamada deverá ocorrer primariamente de forma indireta através de métodos auxiliares correspondentes de objetos de erro.

Diagrama de sequência: conversão de um código de erro do Network Management numa NmException específica do tipo através do domínio de erros. Fontes: [SWS_ANM_01104], [SWS_ANM_01108].

Cenários de erro

No âmbito do tratamento de erros, o domínio cobre todos os casos de erro do módulo definidos pelo tipo de enumeração NmErrc através do alias Errc [SWS_ANM_01103]. O próprio domínio foi concebido para assegurar a avaliação de erros de forma determinística.

Na determinação de mensagens de texto através de Message(), a declaração como noexcept assegura que não são lançadas exceções imprevistas, mesmo com códigos de erro inválidos [SWS_ANM_01107]. O único cenário previsto no qual a classe dispara ativamente uma exceção é a chamada explícita de ThrowAsException() [SWS_ANM_01108]. Através da declaração noexcept(false), o método sinaliza que transfere obrigatoriamente o programa para um caminho de tratamento de exceções ao lançar uma instância de NmException [SWS_ANM_01104], [SWS_ANM_01108]. Os componentes chamadores devem, por conseguinte, assegurar que tais chamadas são capturadas, quando necessário, por blocos de exceção correspondentes.

              O construtor padrão NmErrorDomain() serve para a construção do domínio de erros para o Network Management ([SWS_ANM_01105]). A função é declarada no cabeçalho ara/nm/nm_error_domain.h e cria uma instância da classe NmErrorDomain, a qual herda de ara::core::ErrorDomain ([SWS_ANM_01101]).
              

  
              Uso e concorrência
              
  
              O construtor não aceita parâmetros e não possui valor de retorno ([SWS_ANM_01105]). A instanciação ocorre de forma síncrona. De acordo com a especificação, a chamada é classificada como thread-safe, de modo que o domínio de erros também pode ser criado com segurança a partir de threads paralelas ([SWS_ANM_01105]).
              

  
              Tratamento de erros
              
  
              A função é especificada com o identificador noexcept ([SWS_ANM_01105]). Consequentemente, não ocorrem exceções durante a execução. Não estão previstos códigos de erro específicos ou mecanismos de tratamento de erros para esta construção.
              

  
              Interação
              
  
              A classe criada NmErrorDomain define o contexto específico de domínio para erros do Network Management ([SWS_ANM_01101]). Para a disponibilização do domínio no sistema global, serve primariamente a função GetNmDomain(), que retorna uma referência global do tipo const ara::core::ErrorDomain& ([SWS_ANM_01109]). Uma instanciação direta através do construtor NmErrorDomain() provavelmente raramente será necessária em cenários típicos de aplicação, já que componentes de aplicação e de plataforma habitualmente consultam a referência singleton exposta via GetNmDomain().
