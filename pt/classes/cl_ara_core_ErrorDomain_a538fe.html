Encapsulation of an ErrorDomain. An ErrorDomain is the controlling entity for ErrorCode’s error code values, and defines the mapping of such error code values to textual representations. This type constitutes a base class for ErrorDomain implementations. This class is a literal type, and subclasses are strongly advised to be literal types as well.

Serve como classe base para o controle de códigos de erro e mapeia valores de erro específicos de domínio para mensagens de texto.

A classe ara::core::ErrorDomain serve como classe base abstrata para o controle de valores de erro e mapeia códigos específicos de área para suas representações textuais [SWS_CORE_00153]. Subclasses encapsulam um número de identificação exclusivo em todo o sistema e definem a tradução para textos de erro imutáveis, bem como o tratamento de exceções específico de tipo. Para possibilitar o uso como Literal Type em tempo de compilação, a classe base conta com um destrutor não virtual e protegido [SWS_CORE_00136]. Operações de cópia e movimentação são completamente impedidas, de modo que as instâncias atuam como identidades imutáveis.

Contexto

A classe ara::core::ErrorDomain constitui a base comum para o gerenciamento estruturado de erros na AUTOSAR Adaptive Platform. Ela atua como classe base abstrata para domínios de erro concretos e assume a responsabilidade central de controle para valores de erro encapsulados em ara::core::ErrorCode. Cada domínio estabelece seu próprio namespace e define o mapeamento de valores de erro específicos de domínio do tipo CodeType ([SWS_CORE_00122]) para representações textuais expressivas via Message() ([SWS_CORE_00153]). Além disso, a classe disponibiliza o alias de tipo IdType ([SWS_CORE_00121]) para identificadores de domínio globalmente exclusivos no sistema, bem como SupportDataType ([SWS_CORE_00123]) para dados adicionais específicos do fabricante.

No sistema global, ara::core::ErrorDomain interage com três parceiros essenciais:

  • Subclasses: domínios de erro específicos herdam de ara::core::ErrorDomain e implementam as funções-membro virtuais puras para nomes de domínio, mensagens de erro e tratamento de exceções.
  • ara::core::ErrorCode: representa um valor de erro concreto e delega a determinação do texto descritivo ao domínio de erro associado.
  • Cliente / código de aplicação: consulta informações de status por meio do código de erro ou diretamente no domínio ([SWS_CORE_00152]) ou recebe exceções C++ lançadas ([SWS_CORE_00154]).

Diagrama de contexto: relações e colaboração de ara::core::ErrorDomain com subclasses, códigos de erro e código de aplicação. Fontes: [SWS_CORE_00151], [SWS_CORE_00152], [SWS_CORE_00153], [SWS_CORE_00154].

Ciclo de vida

A instanciação de ara::core::ErrorDomain ocorre de forma protegida: o construtor possui a visibilidade protected e requer um identificador de domínio globalmente exclusivo do tipo IdType ([SWS_CORE_00135]). Como o construtor é declarado como constexpr e noexcept, a classe base suporta a criação como Literal Type em tempo de compilação. Recomenda-se expressamente que as subclasses também garantam essa propriedade de Literal Type.

Qualquer duplicação ou transferência de instâncias de domínio é impedida:

  • O construtor de cópia ([SWS_CORE_00131]) e o construtor de movimento ([SWS_CORE_00132]) estão declarados como eliminados (delete).
  • O operador de atribuição por cópia ([SWS_CORE_00133]) e o operador de atribuição por movimento ([SWS_CORE_00134]) também estão eliminados.

O destrutor é declarado como protected e definido como implementação padrão ([SWS_CORE_00136]). Ele é mantido deliberadamente trivial e não virtual para que a classe possa permanecer um Literal Type. Embora ara::core::ErrorDomain forneça interfaces puramente virtuais, nenhuma destruição polimórfica por meio de ponteiro da classe base é necessária ([SWS_CORE_00136]). Na prática, instâncias concretas de domínio devem ser gerenciadas como objetos de longa duração ou estáticos (interpretação). Pergunta Q-a874dd64f6320d21 (aberta)

Em relação à propriedade, todos os ponteiros para nomes ([SWS_CORE_00152]) e textos de erro ([SWS_CORE_00153]) permanecem na posse da classe de domínio e não devem ser liberados pelos clientes. Todas as operações de leitura e comparação são seguras para threads e seguras para exceções ([SWS_CORE_00135], [SWS_CORE_00151]).

Caminho de utilização

Duas instâncias de ara::core::ErrorDomain são comparadas como iguais se, e somente se, os seus identificadores de domínio obtidos via Id() ([SWS_CORE_00151]) coincidirem ([SWS_CORE_00137], [SWS_CORE_00138]). O fluxo típico de resolução de erros e tratamento de exceções divide-se nas seguintes etapas:

  1. Identificação do domínio: O cliente ou o objeto de erro obtém o nome do domínio como uma string terminada em nulo por meio de Name() ([SWS_CORE_00152]).
  2. Resolução da mensagem: Por meio de Message(errorCode), o valor numérico do erro é passado para o domínio ([SWS_CORE_00153]). O domínio retorna um texto de erro baseado em ponteiro, terminado em nulo, que nunca é nullptr.
  3. Tratamento de exceções: Caso um código de erro deva ser convertido em uma exceção, o cliente chama ThrowAsException(errorCode) ([SWS_CORE_00154]). Em seguida, o domínio lança uma instância adequada de ara::core::Exception que encapsula o código de erro fornecido.

Diagrama de sequência: sequência típica na resolução de texto e disparo de exceção por meio de uma ErrorDomain. Fontes: [SWS_CORE_00152], [SWS_CORE_00153], [SWS_CORE_00154].

Cenários de erro

Ao lidar com ara::core::ErrorDomain, devem ser considerados os seguintes cenários de erro e requisitos de interface:

  • Associação incorreta de domínio: Se for passado para o método Message() um errorCode que não provenha desta ErrorDomain específica, isso constituirá a violação especificada WrongDomainOfAn-ErrorCodeViolation ([SWS_CORE_00153]). Os chamadores devem garantir que o código de erro corresponda à instância do domínio.
  • Exceções C++ desativadas: O método ThrowAsException() não é seguro contra exceções (not exception safe) e lança uma exceção ([SWS_CORE_00154]). Se as exceções C++ estiverem desativadas na toolchain do compilador, essa função não poderá participar da resolução de sobrecarga ([SWS_CORE_00154]).
  • Exclusão de ponteiro nulo: Nem Name() nem Message() podem jamais retornar nullptr ([SWS_CORE_00152], [SWS_CORE_00153]). Uma implementação de subclasse que retorne nullptr quebra a especificação da interface.

              A função-membro Id() da classe ara::core::ErrorDomain do ficheiro de cabeçalho ara/core/error_domain.h retorna síncronamente o identificador unívoco do respetivo domínio de erro ([SWS_CORE_00151]). A chamada não espera parâmetros de entrada e retorna o identificador de domínio como valor do tipo IdType, garantindo assim uma distinção inequívoca de diferentes domínios de erro no sistema global.
              

              Para o tratamento de erros é relevante que a função seja declarada como noexcept e classificada como exception safe ([SWS_CORE_00151]). Portanto, nunca lança exceções e não reporta códigos de erro nem casos especiais. Devido à sua característica como método constexpr, o identificador pode, se necessário, ser avaliado em tempo de compilação e utilizado em expressões constantes.
              

              Em termos de concorrência e condições de chamada, Id() está especificada como thread-safe ([SWS_CORE_00151]). A chamada é sem estado e livre de efeitos secundários modificadores, de modo que qualquer número de threads pode aceder à mesma instância simultaneamente e sem mecanismos externos de bloqueio.
              

              Na interação dentro da arquitetura de domínios, o identificador constitui o critério primário de comparação: duas instâncias de ara::core::ErrorDomain são consideradas iguais de acordo com a especificação se, e apenas se, os seus identificadores fornecidos por Id() coincidirem, o que é implementado diretamente pelo operador de igualdade operator== ([SWS_CORE_00137]).

Ela retorna um ponteiro para uma cadeia de caracteres terminada em nulo (const char *), que é garantido nunca ser nullptr. A memória referenciada permanece em posse da respectiva subclasse de ara::core::ErrorDomain e não deve, sob hipótese alguma, ser liberada por clientes chamadores [SWS_CORE_00153].
                  

                  Em relação à concorrência e à robustez, o método está declarado como noexcept, é considerado seguro contra exceções (exception safe) e foi projetado para ser totalmente seguro para threads (thread-safe) [SWS_CORE_00153]. No que diz respeito a possíveis estados de erro, especifica-se que um errorCode que não provenha da respectiva instância de ara::core::ErrorDomain resulta em uma violação do tipo WrongDomainOfAnErrorCodeViolation [SWS_CORE_00153].

Interpretação: A interação com ara::core::ErrorCode::Message() [SWS_CORE_00518], que retorna uma representação textual como StringView, baseia-se presumivelmente no fato de que ErrorCode encaminha a tradução para o método Message do domínio de erro associado.
