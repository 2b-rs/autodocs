classe ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Serve para a escrita com memória intermédia de ficheiros binários e de texto, bem como para a sua sincronização com o armazenamento físico.

A classe ara::per::WriteAccessor permite a escrita de conteúdos de ficheiros binários ou textuais no módulo de persistência e disponibiliza métodos para acessos de escrita não formatados, bem como um operador de fluxo formatado [SWS_PER_00423]. Dado que as operações de escrita podem ser inicialmente colocadas em memória intermédia no sistema operativo, a chamada de SyncToFile() força a escrita permanente (flush) no armazenamento físico [SWS_PER_00122]. Todos os métodos são seguros contra exceções, mas não seguros para threads, razão pela qual os acessos concorrentes devem ser protegidos pela aplicação.

Contexto

ara::per::WriteAccessor é uma classe final do módulo de persistência (per) da AUTOSAR Adaptive Platform e deriva virtualmente de FileAccessor. A classe disponibiliza operações de escrita para conteúdos de ficheiros. Oferece métodos para escrita não formatada e controlada com tratamento de erros através de ara::core::Result, bem como um operador de fluxo sobrecarregado para escrita formatada. Como parceiros de interação atuam a aplicação chamadora, a memória intermédia interna de ficheiros do sistema operativo e o suporte de armazenamento físico.

Ciclo de vida

O construtor padrão de WriteAccessor está explicitamente eliminado e não pode ser utilizado [SWS_PER_00596]. (Interpretação: as instâncias de WriteAccessor deverão ser criadas e disponibilizadas através de métodos de fábrica de entidades de gestão de persistência de nível superior, como o armazenamento de ficheiros.)

A destruição ocorre através do destruidor virtual ~WriteAccessor() [SWS_PER_00597]. A classe e os seus métodos estão especificados como seguros contra exceções (“exception safe”) e declarados como noexcept. No que diz respeito à concorrência, WriteAccessor não é seguro para threads (“not thread-safe”) [SWS_PER_00597]; os acessos paralelos à mesma instância têm de ser protegidos externamente pela aplicação.

Caminho de utilização

O fluxo regular inclui a escrita de dados em modo não formatado ou formatado, o ajuste opcional do tamanho do ficheiro e o armazenamento persistente final:

  • Escrever dados binários: através de WriteBinary(), um intervalo de bytes (ara::core::Span<const ara::core::Byte>) é escrito no ficheiro [SWS_PER_00423].
  • Escrever dados de texto: através de WriteText(), as cadeias de carateres são passadas através de um ara::core::StringView [SWS_PER_00166]. Complementarmente, operator<< está disponível como função de conveniência para casos de utilização não críticos, sendo os erros ocorridos ignorados silenciosamente [SWS_PER_00125].
  • Forçar persistência: o momento do armazenamento físico depende da implementação da persistência; SyncToFile() descarrega (flashes) a memória intermédia do sistema operativo de forma vinculativa para o suporte de armazenamento [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Ajustar tamanho do ficheiro: com SetFileSize(), o ficheiro pode ser truncado, sendo os conteúdos excedentes removidos; a posição no ficheiro permanece inalterada ou é definida para a última posição válida ou 0 [SWS_PER_00428].

Diagrama de sequência: operações de escrita com subsequente sincronização com o armazenamento físico. Fontes: [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Cenários de erro

Os métodos WriteBinary(), WriteText(), SyncToFile() e SetFileSize() retornam um ara::core::Result<void> que, em caso de falha, contém códigos de erro específicos:

  • PerErrc::kPhysicalStorageFailure: o acesso ao suporte de armazenamento físico falha [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. O estado do ficheiro é desconhecido e pode estar completamente corrompido (sem semântica de reversão).
  • PerErrc::kOutOfStorageSpace: espaço de armazenamento físico insuficiente [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. Durante a escrita, a parte excedente é descartada e a posição fica no final do ficheiro (sem semântica de reversão).
  • PerErrc::kQuotaExceeded: o ficheiro excederia o tamanho máximo configurado (AllowedSize) [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (semântica de reversão).
  • PerErrc::kEncryptionFailed: a cifragem ou decifragem falha [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. A memória intermédia e a posição são atualizadas, mas o ficheiro não pode ser persistido e reflete uma versão mais antiga no armazenamento (semântica de reversão).
  • PerErrc::kAuthenticationFailed: o cálculo ou a verificação do MAC falha [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (semântica de reversão).
  • PerErrc::kValidationFailed: não é possível garantir a validade dos dados armazenados [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (semântica de reversão).
  • PerErrc::kInvalidSize: o novo tamanho do ficheiro em SetFileSize() é superior ao tamanho atual do ficheiro [SWS_PER_00428] (semântica de reversão).

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded.       A função-membro SyncToFile da classe ara::per::WriteAccessor (definida em #include "ara/per/write_accessor.h") transfere o conteúdo atual do ficheiro sincronamente para o armazenamento físico [SWS_PER_00122]. A chamada não recebe parâmetros de entrada e devolve um ara::core::Result<void> que, em caso de sucesso, está vazio ou, em caso de erro, contém códigos de erro específicos do módulo Persistency ou erros específicos do fabricante [SWS_PER_00122].
      


      Durante a execução podem ocorrer diferentes casos de erro, alguns dos quais possuem semântica de rollback [SWS_PER_00122]:
      

        

      • StorageFailure: ocorre quando o acesso físico ao meio de armazenamento falha (sem semântica de rollback) [SWS_PER_00122].
        • 

      • PerErrc::kOutOfStorageSpace: é devolvido caso o espaço de armazenamento físico seja insuficiente para o ficheiro modificado (sem semântica de rollback) [SWS_PER_00122].
        • 

      • PerErrc::kQuotaExceeded: é reportado quando o ficheiro excede o tamanho máximo configurado AllowedSize do File Storage (com semântica de rollback) [SWS_PER_00122].
        • 

      • PerErrc::kEncryptionFailed: se a encriptação dos dados armazenados falhar (com semântica de rollback) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed: se o cálculo do MAC para os dados falhar (com semântica de rollback) [SWS_PER_00122].
        • 

      


      No que diz respeito à segurança de execução, o método está declarado como noexcept e especificado como exception safe [SWS_PER_00122]. No entanto, como está expressamente classificado como not thread-safe, chamadas simultâneas na mesma instância de WriteAccessor devem provavelmente ser sincronizadas pelo chamador [SWS_PER_00122].

                  ara::core::Result< void > WriteText (ara::core::StringView s) noexcept;
                  

                  Writes the content of a StringView to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

Se a operação falhar, o conteúdo do ficheiro pode ficar corrompido e a posição de escrita pode ter sido alterada [SWS_PER_00166]:

                    •

                    •

                    • 

                  • PerErrc::kQuotaExceeded, PerErrc::kValidationFailed e PerErrc::kAuthenticationFailed: reportam excessos de quota (AllowedSize), bem como erros de validação ou de autenticação, mantendo a semântica de rollback [SWS_PER_00166].
