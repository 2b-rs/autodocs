classe ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Contexto

A classe ara::per::WriteAccessor representa a interface para o acesso de escrita a ficheiros dentro da AUTOSAR Adaptive Platform. Herda virtualmente de FileAccessor e assume a responsabilidade pela modificação direcionada, sobrescrita e truncamento de conteúdos de ficheiros persistentes. Para a transferência de dados, disponibiliza métodos de escrita não formatados: WriteBinary recebe dados brutos como ara::core::Span<const ara::core::Byte> ([SWS_PER_00423]), enquanto WriteText processa cadeias de caracteres sob a forma de ara::core::StringView ([SWS_PER_00166]). Adicionalmente, o operador de streaming sobrecarregado operator<< oferece uma forma simplificada para saídas de texto formatadas ([SWS_PER_00125]).

Uma característica essencial de WriteAccessor é o desacoplamento da escrita virtual e da persistência física: nas chamadas de WriteBinary ou WriteText, os dados são inicialmente transferidos para estruturas de buffer. O momento exato em que estes dados são armazenados de forma permanente no suporte de armazenamento depende da implementação ([SWS_PER_00423], [SWS_PER_00166]). Para forçar a escrita imediata a partir do buffer do sistema operativo para o armazenamento físico, a classe disponibiliza o método de sincronização SyncToFile ([SWS_PER_00122]). Além disso, SetFileSize permite reduzir ficheiros existentes para um tamanho em bytes especificado ([SWS_PER_00428]).

Ciclo de vida

O construtor padrão de WriteAccessor está explicitamente eliminado (WriteAccessor() = delete;, [SWS_PER_00596]). Uma instanciação direta e não inicializada pela aplicação não é, portanto, permitida; instâncias válidas deverão ser tipicamente criadas e passadas por entidades superiores de gestão de persistência ao abrir ficheiros em modo de escrita. A destruição e a libertação de recursos ocorrem de forma determinística através do destrutor virtual ~WriteAccessor() ([SWS_PER_00597]).

No que diz respeito à concorrência, todas as funções-membro de WriteAccessor são especificadas como não seguras para threads («not thread-safe») ([SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00125], [SWS_PER_00428], [SWS_PER_00122], [SWS_PER_00597]). Se múltiplas threads de execução acederem simultaneamente à mesma instância, a sincronização entre threads cabe à aplicação que efetua a chamada. Todas as operações estão declaradas como noexcept e garantem segurança contra exceções («exception safe»), uma vez que os feedbacks e os estados de erro não são sinalizados através de exceções C++, mas sim através do tipo de retorno ara::core::Result<void>.

Caminho de utilização

A utilização típica de WriteAccessor divide-se em transferência de dados, ajuste opcional do tamanho e sincronização explícita com o suporte de armazenamento:

  1. Escrever dados: A aplicação passa blocos de dados sequencialmente através de WriteBinary ([SWS_PER_00423]) ou WriteText ([SWS_PER_00166]). Ambos os métodos retornam um ara::core::Result<void>, que tem de ser verificado quanto ao sucesso. Para casos de uso não críticos, pode ser utilizado alternativamente operator<< ([SWS_PER_00125]).
  2. Ajustar tamanho do ficheiro (opcional): Se o ficheiro tiver de ser truncado, SetFileSize é chamado ([SWS_PER_00428]). Se a posição atual do ficheiro estiver além do novo tamanho de destino, esta é definida para o novo fim do ficheiro; com um tamanho de destino de 0, a posição também é definida para 0.
  3. Forçar persistência: Para garantir que os dados modificados não permaneçam no buffer volátil em caso de erro ou de perda de tensão, a aplicação chama SyncToFile ([SWS_PER_00122]), gravando de forma vinculativa o conteúdo do buffer no suporte físico.

Diagrama de sequência: Sequência típica ao escrever dados e forçar subsequentemente a persistência. Fontes: [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Cenários de erro

Em caso de erros, a especificação distingue rigorosamente de acordo com a interface utilizada, bem como entre erros com e sem semântica de rollback:

  • Ignorar silencioso no operator<<: Se ocorrer um erro durante a utilização do operador de streaming, este é ignorado sem qualquer notificação ([SWS_PER_00125]). Este operador destina-se expressamente como uma função de conveniência para caminhos não críticos e não deve ser utilizado em casos de uso relevantes para a segurança.
  • Erros em WriteBinary e WriteText: Se uma operação de escrita falhar, o conteúdo do ficheiro pode ficar corrompido ([SWS_PER_00423], [SWS_PER_00166]). Em PerErrc::kPhysicalStorageFailure («no_rollback_semantics»), o estado do ficheiro fica indefinido; pode ficar completamente destruído. Em PerErrc::kOutOfStorageSpace («no_rollback_semantics»), o conteúdo do ficheiro é atualizado, mas a parte que excede o espaço de armazenamento disponível é descartada; a posição do ficheiro fica no fim do ficheiro. Se ocorrer PerErrc::kEncryptionFailed («rollback_semantics»), o buffer e a posição foram atualizados, mas as alterações não puderam ser persistidas, fazendo com que o ficheiro guardado permaneça num estado anterior. Outros possíveis erros com semântica de rollback são PerErrc::kQuotaExceeded (excesso da AllowedSize configurada do File Storage), PerErrc::kValidationFailed (validação falhou), bem como PerErrc::kAuthenticationFailed (erro no cálculo ou na verificação do MAC).
  • Erros em SetFileSize: O método serve exclusivamente para a redução do tamanho do ficheiro. Se o parâmetro size for maior do que o tamanho atual do ficheiro, a chamada falha com PerErrc::kInvalidSize ([SWS_PER_00428]). Além disso, podem ocorrer PerErrc::kPhysicalStorageFailure, PerErrc::kValidationFailed, PerErrc::kEncryptionFailed e PerErrc::kAuthenticationFailed.
  • Erros em SyncToFile: ao descarregar o buffer para a mídia, podem ser reportados PerErrc::kPhysicalStorageFailure e PerErrc::kOutOfStorageSpace (sem rollback), bem como PerErrc::kEncryptionFailed, PerErrc::kQuotaExceeded e PerErrc::kAuthenticationFailed (com rollback) ([SWS_PER_00122]).

Este guia de classe baseia-se na especificação AUTOSAR Adaptive Platform R25-11 (módulo per).

WriteBinary função

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;

<h4>Contexto</h4>
<p>A classe <code>ara::per::WriteAccessor</code> representa a interface para o acesso de escrita a ficheiros dentro da AUTOSAR Adaptive Platform. Herda virtualmente de <code>FileAccessor</code> e assume a responsabilidade pela modificação direcionada, sobrescrita e truncamento de conteúdos de ficheiros persistentes. Para a transferência de dados, disponibiliza métodos de escrita não formatados: <code>WriteBinary</code> recebe dados brutos como <code>ara::core::Span&lt;const ara::core::Byte&gt;</code> (<a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>), enquanto <code>WriteText</code> processa cadeias de caracteres sob a forma de <code>ara::core::StringView</code> (<a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>). Adicionalmente, o operador de streaming sobrecarregado <code>operator&lt;&lt;</code> oferece uma forma simplificada para saídas de texto formatadas (<a class="spec-record-ref" data-req="SWS_PER_00125" href="../spec/record.html?id=SWS_PER_00125">[SWS_PER_00125]</a>).</p>
<p>Uma característica essencial de <code>WriteAccessor</code> é o desacoplamento da escrita virtual e da persistência física: nas chamadas de <code>WriteBinary</code> ou <code>WriteText</code>, os dados são inicialmente transferidos para estruturas de buffer. O momento exato em que estes dados são armazenados de forma permanente no suporte de armazenamento depende da implementação (<a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>). Para forçar a escrita imediata a partir do buffer do sistema operativo para o armazenamento físico, a classe disponibiliza o método de sincronização <code>SyncToFile</code> (<a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>). Além disso, <code>SetFileSize</code> permite reduzir ficheiros existentes para um tamanho em bytes especificado (<a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>).</p>

<h4>Ciclo de vida</h4>
<p>O construtor padrão de <code>WriteAccessor</code> está explicitamente eliminado (<code>WriteAccessor() = delete;</code>, <a class="spec-record-ref" data-req="SWS_PER_00596" href="../spec/record.html?id=SWS_PER_00596">[SWS_PER_00596]</a>). Uma instanciação direta e não inicializada pela aplicação não é, portanto, permitida; instâncias válidas deverão ser tipicamente criadas e passadas por entidades superiores de gestão de persistência ao abrir ficheiros em modo de escrita. A destruição e a libertação de recursos ocorrem de forma determinística através do destrutor virtual <code>~WriteAccessor()</code> (<a class="spec-record-ref" data-req="SWS_PER_00597" href="../spec/record.html?id=SWS_PER_00597">[SWS_PER_00597]</a>).</p>
<p>No que diz respeito à concorrência, todas as funções-membro de <code>WriteAccessor</code> são especificadas como não seguras para threads («not thread-safe») (<a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00125" href="../spec/record.html?id=SWS_PER_00125">[SWS_PER_00125]</a>, <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>, <a class="spec-record-ref" data-req="SWS_PER_00597" href="../spec/record.html?id=SWS_PER_00597">[SWS_PER_00597]</a>). Se múltiplas threads de execução acederem simultaneamente à mesma instância, a sincronização entre threads cabe à aplicação que efetua a chamada. Todas as operações estão declaradas como <code>noexcept</code> e garantem segurança contra exceções («exception safe»), uma vez que os feedbacks e os estados de erro não são sinalizados através de exceções C++, mas sim através do tipo de retorno <code>ara::core::Result&lt;void&gt;</code>.</p>

<h4>Caminho de utilização</h4>
<p>A utilização típica de <code>WriteAccessor</code> divide-se em transferência de dados, ajuste opcional do tamanho e sincronização explícita com o suporte de armazenamento:</p>
<ol>
<li><strong>Escrever dados</strong>: A aplicação passa blocos de dados sequencialmente através de <code>WriteBinary</code> (<a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>) ou <code>WriteText</code> (<a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>). Ambos os métodos retornam um <code>ara::core::Result&lt;void&gt;</code>, que tem de ser verificado quanto ao sucesso. Para casos de uso não críticos, pode ser utilizado alternativamente <code>operator&lt;&lt;</code> (<a class="spec-record-ref" data-req="SWS_PER_00125" href="../spec/record.html?id=SWS_PER_00125">[SWS_PER_00125]</a>).</li>
<li><strong>Ajustar tamanho do ficheiro (opcional)</strong>: Se o ficheiro tiver de ser truncado, <code>SetFileSize</code> é chamado (<a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>). Se a posição atual do ficheiro estiver além do novo tamanho de destino, esta é definida para o novo fim do ficheiro; com um tamanho de destino de 0, a posição também é definida para 0.</li>
<li><strong>Forçar persistência</strong>: Para garantir que os dados modificados não permaneçam no buffer volátil em caso de erro ou de perda de tensão, a aplicação chama <code>SyncToFile</code> (<a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>), gravando de forma vinculativa o conteúdo do buffer no suporte físico.</li>
</ol>

<h4>Cenários de erro</h4>
<p>Em caso de erros, a especificação distingue rigorosamente de acordo com a interface utilizada, bem como entre erros com e sem semântica de rollback:</p>
<ul>
<li><strong>Ignorar silencioso no <code>operator&lt;&lt;</code></strong>: Se ocorrer um erro durante a utilização do operador de streaming, este é ignorado sem qualquer notificação (<a class="spec-record-ref" data-req="SWS_PER_00125" href="../spec/record.html?id=SWS_PER_00125">[SWS_PER_00125]</a>). Este operador destina-se expressamente como uma função de conveniência para caminhos não críticos e não deve ser utilizado em casos de uso relevantes para a segurança.</li>
<li><strong>Erros em <code>WriteBinary</code> e <code>WriteText</code></strong>: Se uma operação de escrita falhar, o conteúdo do ficheiro pode ficar corrompido (<a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>). Em <code>PerErrc::kPhysicalStorageFailure</code> («no_rollback_semantics»), o estado do ficheiro fica indefinido; pode ficar completamente destruído. Em <code>PerErrc::kOutOfStorageSpace</code> («no_rollback_semantics»), o conteúdo do ficheiro é atualizado, mas a parte que excede o espaço de armazenamento disponível é descartada; a posição do ficheiro fica no fim do ficheiro. Se ocorrer <code>PerErrc::kEncryptionFailed</code> («rollback_semantics»), o buffer e a posição foram atualizados, mas as alterações não puderam ser persistidas, fazendo com que o ficheiro guardado permaneça num estado anterior. Outros possíveis erros com semântica de rollback são <code>PerErrc::kQuotaExceeded</code> (excesso da <code>AllowedSize</code> configurada do File Storage), <code>PerErrc::kValidationFailed</code> (validação falhou), bem como <code>PerErrc::kAuthenticationFailed</code> (erro no cálculo ou na verificação do MAC).</li>
<li><strong>Erros em <code>SetFileSize</code></strong>: O método serve exclusivamente para a redução do tamanho do ficheiro. Se o parâmetro <code>size</code> for maior do que o tamanho atual do ficheiro, a chamada falha com <code>PerErrc::kInvalidSize</code> (<a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>). Além disso, podem ocorrer <code>PerErrc::kPhysicalStorageFailure</code>, <code>PerErrc::kValidationFailed</code>, <code>PerErrc::kEncryptionFailed</code> e <code>PerErrc::kAuthenticationFailed</code>.</li>
<li><strong>Erros em <code>SyncToFile</code></strong>: ao descarregar o buffer para a mídia, podem ser reportados <code>PerErrc::kPhysicalStorageFailure</code> e <code>PerErrc::kOutOfStorageSpace</code> (sem rollback), bem como <code>PerErrc::kEncryptionFailed</code>, <code>PerErrc::kQuotaExceeded</code> e <code>PerErrc::kAuthenticationFailed</code> (com rollback) (<a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>).</li>
</ul>
