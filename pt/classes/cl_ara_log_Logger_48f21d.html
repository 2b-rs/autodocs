classe ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

Encapsula um contexto de registro de log para a captura thread-safe de mensagens de log formatadas ou modeladas.

A classe ara::log::Logger representa um contexto para a captura de mensagens de log dentro de um processo de aplicação por meio de streams temporários ou formatos de mensagens modelados [SWS_LOG_00064]. Como o construtor padrão foi excluído, a criação e o gerenciamento do ciclo de vida são realizados inteiramente pelo framework de logging [SWS_LOG_00259]. Antes do processamento demorado dos dados da mensagem, o nível de log atualmente ativo pode ser consultado. Todas as interfaces da classe são especificadas como thread-safe e permitem a chamada a partir de múltiplas threads sem a necessidade de sincronização.

Contexto

A classe ara::log::Logger representa um contexto de logger dentro de um processo de aplicação ou escopo de processo no módulo log. Esse contexto encapsula um ID de contexto específico, uma descrição correspondente e um nível de log padrão. Desenvolvedores de aplicações interagem com instâncias de logger para transmitir mensagens de log ao framework de logging por meio de objetos de stream como LogStream [SWS_LOG_00064] ou como mensagens estruturadas e modeladas [SWS_LOG_00204]. As instâncias atuam como intermediárias entre as threads internas da aplicação e o backend de logging.

Diagrama de contexto: integração do logger entre a aplicação, o framework de logging e o LogStream. Fontes: [SWS_LOG_00064], [SWS_LOG_00259].

Ciclo de vida

O gerenciamento das instâncias está sujeito a uma propriedade estrita por parte do framework de logging. Para garantir o registro automático no backend de logging durante a criação e o cancelamento do registro durante o encerramento do processo da aplicação, o construtor padrão está excluído [SWS_LOG_00259]. As aplicações não devem nem podem instanciar objetos Logger diretamente, devendo, em vez disso, utilizar as funções de criação ara::log::CreateLogger. A destruição e liberação ocorrem por meio do destrutor [SWS_LOG_00260], que é controlado pelo framework de logging, de modo que os usuários não precisam se preocupar com o tempo de vida.

Em relação à concorrência, todos os métodos de acesso são especificados como thread-safe (thread-safe), incluindo [SWS_LOG_00070], [SWS_LOG_00255] e [SWS_LOG_00260]. Como resultado, múltiplas threads concorrentes podem usar o mesmo contexto de logger simultaneamente, sem a necessidade de mecanismos adicionais de sincronização no lado da aplicação.

Caminho de utilização

O uso típico de um logger inclui a verificação da configuração atual, o ajuste de limites e o envio de mensagens:

  • Verificação da autorização de saída: Antes de preparações dispendiosas de dados de registo, pode-se consultar com IsEnabled se um nível de log pretendido está a ser reportado ativamente [SWS_LOG_00070].
  • Configuração: O limiar mínimo de reporte de uma instância de logger pode ser reconfigurado em tempo de execução através de SetThreshold [SWS_LOG_00255].
  • Registo baseado em fluxo: Através de métodos específicos para níveis de gravidade individuais – LogFatal [SWS_LOG_00064], LogError [SWS_LOG_00065], LogWarn [SWS_LOG_00066], LogInfo [SWS_LOG_00067], LogDebug [SWS_LOG_00068] ou LogVerbose [SWS_LOG_00069] – bem como através do dinâmico WithLevel [SWS_LOG_00131], é gerado um objeto LogStream. Este recebe dados através do operador <<. Habitualmente, o tempo de vida do objeto de fluxo termina com o ponto e vírgula da instrução [SWS_LOG_00064].
  • Mensagens modeladas: Em alternativa, mensagens tipificadas e modeladas podem ser transmitidas diretamente com Log [SWS_LOG_00204] ou mediante a especificação de atributos com LogWith [SWS_LOG_00133].

Diagrama de sequência: sequência típica na verificação do limiar e no registo baseado em fluxo. Fontes: [SWS_LOG_00070], [SWS_LOG_00067], [SWS_LOG_00064].

Cenários de erro

As interfaces da classe estão amplamente especificadas como noexcept e seguras contra exceções (exception safe), o que minimiza interrupções inesperadas em tempo de execução [SWS_LOG_00070], [SWS_LOG_00255]. Não obstante, existem condições formais de erro e casos de fronteira:

  • Parâmetros de modelo incorretos: Se Log for chamado com argumentos que não correspondem à especificação da mensagem modelada, o programa em C++ está incorretamente estruturado (ill-formed) e falha em tempo de compilação [SWS_LOG_00204].
  • Propriedades de atributo em falta: Se o tuplo para LogWith contiver tipos que não correspondam aos critérios de atributo exigidos, a função não participa na resolução de sobrecarga [SWS_LOG_00133]. A exclusão deverá presumivelmente ocorrer via SFINAE ou conceitos.
  • Segurança contra exceções na destruição: O destrutor ~Logger está declarado como not exception safe [SWS_LOG_00260]. Isto deverá dever-se ao facto de, ao cancelar o registo no backend de logging, poderem ocorrer erros que não podem ser propagados através de exceções.

Este guia baseia-se exclusivamente na especificação AUTOSAR para o módulo log na Adaptive Release R25-11.
