Disponibiliza resultados de verificações de certificados X.509 com status, cadeia de certificados encontrada e certificado com falha.

A interface ara::crypto::x509::CertificateValidationResult disponibiliza o resultado de uma validação de certificado X.509 e é tipicamente gerenciada como um Sptrc imutável [SWS_CRYPT_50093]. Através dos seus métodos, a aplicação consulta o status geral, determina a cadeia de certificados completa com o certificado folha na posição 0 ou isola o certificado com falha. Se a verificação foi bem-sucedida, a chamada para determinar o certificado com erro falha com o código de erro ara::crypto::CryptoErrc::kNoSuchValue [SWS_CRYPT_50095]. Todos os métodos da interface são concebidos como thread-safe e exception-safe.

Contexto

A interface ara::crypto::x509::CertificateValidationResult encapsula o resultado de um processo de validação de certificado X.509 dentro do módulo Adaptive crypto. A sua responsabilidade primária consiste em disponibilizar às aplicações chamadoras um resultado de verificação estruturado e consistente. Este abrange tanto o status de validação agregado do caminho de certificação quanto o acesso aos objetos de certificado envolvidos. Como intermediária entre os mecanismos internos de verificação criptográfica e aplicações críticas para a segurança, a classe permite uma avaliação diferenciada de hierarquias de certificados. Entre os seus parceiros centrais de interação contam-se instâncias de Certificate::Sptrc, que são reunidas como cadeia de certificados completa ou, em caso de erro, indicadas como causadoras da falha.

Ciclo de vida

Como interface puramente virtual, CertificateValidationResult não define construtores públicos próprios. O ciclo de vida e as relações de propriedade são controlados de forma determinante pelo smart pointer tipado Sptrc, definido como std::shared_ptr<const CertificateValidationResult> [SWS_CRYPT_50093]. Este ponteiro constante estabelece um modelo de propriedade compartilhado e imutável: após a conclusão de uma validação de certificado, o objeto de resultado é disponibilizado como um snapshot não modificável. Presume-se que a criação e a inicialização de instâncias concretas ocorram internamente por meio de funções de validação de nível superior do backend da plataforma. Como todas as funções-membro são declaradas como const e noexcept, e explicitamente especificadas como thread-safe e exception-safe ([SWS_CRYPT_50094], [SWS_CRYPT_50095], [SWS_CRYPT_50096]), múltiplas threads podem acessar a mesma instância de forma concorrente e sem medidas adicionais de sincronização até que a última referência seja liberada.

Caminho de utilização

Um caminho de uso típico inicia após o recebimento de uma instância de CertificateValidationResult::Sptrc a partir de uma verificação de certificado anterior. Os chamadores realizam a avaliação em uma sequência padronizada:

  • Primeiramente, a aplicação chama GetValidationStatus() para consultar o resultado fundamental da validação de certificado como CertificateValidationStatus [SWS_CRYPT_50094].
  • Se a validação foi bem-sucedida, o cliente chama GetCertificateChain() para obter a cadeia de certificados encontrada durante o processo de verificação como ara::core::Vector<Certificate::Sptrc> [SWS_CRYPT_50096]. De acordo com a especificação, esta cadeia inicia na posição de índice 0 sempre com o certificado folha (Leaf Certificate) [SWS_CRYPT_50096].
  • Se, por outro lado, a validação do caminho falhou, o chamador chama GetFailedCertificate() para determinar especificamente aquele certificado que disparou o erro de validação [SWS_CRYPT_50095].

Diagrama de sequência: fluxo típico para consulta de status de validação, cadeia de certificados e causa do erro. Fontes: [SWS_CRYPT_50094], [SWS_CRYPT_50095], [SWS_CRYPT_50096]

Cenários de erro

O gerenciamento de erros da interface baseia-se em ara::core::Result, onde todas as chamadas cumprem a garantia noexcept e são exception-safe:

  • Validação bem-sucedida e GetFailedCertificate(): quando a verificação foi concluída com sucesso (valor de retorno kValid), nenhum certificado causou uma falha. Neste estado, a chamada de GetFailedCertificate() falha com o código de erro ara::crypto::CryptoErrc::kNoSuchValue [SWS_CRYPT_50095]. As aplicações devem interpretar este erro como confirmação lógica de uma cadeia sem erros ou associar a chamada a um status negativo.
  • Erros de status específicos da implementação: para GetValidationStatus() não estão definidos códigos de erro padronizados; no entanto, erros específicos da implementação são encapsulados no ara::core::Result retornado [SWS_CRYPT_50094].
  • Consulta da cadeia de certificados: GetCertificateChain() também não especifica códigos de erro padronizados [SWS_CRYPT_50096]; eventuais estados de erro internos são sinalizados através do ara::core::Result resultante.

Este guia baseia-se exclusivamente na especificação AUTOSAR Adaptive para o módulo crypto no release R25-11.

Os componentes chamadores têm, por isso, de verificar obrigatoriamente se o ara::core::Result contém um código de erro antes de acederem ao pointer do certificado, a fim de evitar acessos incorretos.
