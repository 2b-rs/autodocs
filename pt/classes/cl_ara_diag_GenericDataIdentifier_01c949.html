Padrão DID genérico

GenericDataIdentifier é o gancho genérico do aplicação para um identificador de dados de diagnóstico configurado. O DM atribui UDS ReadDataByIdentifier ou WriteDataByIdentifier à interface apropriada através da atribuição DEXT/porta; a classe não processa «todos os DIDs» sem configuração SWS Diagnostics §7.3.6 «Diagnostic Data Management».

Ler e escrever

Read recebe o DID, MetaInfo e um CancellationHandler e devolve OperationOutput para dados úteis ou um NRC [SWS_DM_00636]. Write recebe adicionalmente os dados do Request e conclui com sucesso ou NRC [SWS_DM_00637]. O DM processa a verificação de serviço UDS e de autorização; a aplicação valida apenas o seu formato de dados específico de DID e executa a operação funcional.

Simultaneidade e longevidade dos dados

Callbacks DID paralelos são permitidos apenas para sessões padrão, várias conversas processadas ao mesmo tempo, a mesma porta necessária e DataIdentifierConcurrencyType::kConcurrentType [SWS_DM_00941] [SWS_DM_00942] [SWS_DM_00943]. Caso contrário, DM suprime chamadas adicionais até a conclusão [SWS_DM_00944]. Não copie ou salve requestData e MetaInfo na vida após a morte assíncrona.

Leia os nomes dos modelos corretamente

Na especificação, expressões como <data-identifier-interface-name-x> ou <data-identifier-directory-path> descrevem padrões de header e de tipos gerados. Permanecem deliberadamente visíveis nesta referência como marcadores de posição e não são identificadores C++ concretos.
