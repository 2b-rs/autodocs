Fornece metadados e informações de integridade para dados massivos de diagnóstico na comunicação SOVD.

A estrutura ara::diag::SovdBulkData::BulkDataMetaDataDescriptor serve como objeto de transferência de dados para a descrição de dados massivos para a comunicação de diagnóstico SOVD no AUTOSAR Adaptive ([SWS_DM_01830]). Ela agrupa informações de identificação, localização e tipo, como id, file_name e mimetype, bem como somas de verificação e indicações de tamanho opcionais (SWS Diagnostics §8.53.2 «Struct: BulkDataMetaDataDescriptor»). A instância é preenchida com metadados pela aplicação de diagnóstico fornecedora e repassada ao subsistema SOVD. Por ser uma estrutura C++ passiva sem sincronização própria, acessos de escrita simultâneos devem ser protegidos externamente pela aplicação chamadora.

Contexto

A estrutura de dados ara::diag::SovdBulkData::BulkDataMetaDataDescriptor é parte integrante do módulo diag da AUTOSAR Adaptive Platform e é disponibilizada por meio do cabeçalho #include "ara/diag/sovd_bulk_data.h" ([SWS_DM_01830]). Ela define o descritor de metadados para dados massivos de diagnóstico (Bulk Data) que são transmitidos no âmbito do SOVD (Service-Oriented Vehicle Diagnostics) (SWS Diagnostics §8.53.2 «Struct: BulkDataMetaDataDescriptor»). Em cenários de diagnóstico, como a leitura de arquivos de log extensos, buffers de rastreamento ou pacotes de atualização, os clientes de diagnóstico precisam de informações complementares estruturadas, além do fluxo de dados binários. A estrutura agrupa esses metadados para identificação inequívoca, interpretação e verificação de integridade.

Na interação entre a aplicação de diagnóstico, o sistema de tempo de execução ara::diag e os testadores de diagnóstico externos, a estrutura atua como um objeto de transferência de dados (DTO) passivo. O campo id define o identificador único dos dados massivos ([SWS_DM_01831]). Para nomeação, estão disponíveis file_name para o nome do arquivo ([SWS_DM_01836]), name para a designação lógica ([SWS_DM_01833]) e translation_id para fins de localização ([SWS_DM_01834]). O tipo de mídia é declarado por mimetype ([SWS_DM_01832]). A garantia de integridade é assegurada por hash ([SWS_DM_01839]) e hash_algorithm ([SWS_DM_01840]), enquanto creation_date ([SWS_DM_01837]) e last_modified ([SWS_DM_01838]) definem o enquadramento temporal (SWS Diagnostics §8.53.2.1 «Public Member Variables»).

Ciclo de vida

Como uma estrutura C++, BulkDataMetaDataDescriptor possui atributos puramente públicos, sem construtores próprios de lógica de negócios ([SWS_DM_01830]). Interpretação: presume-se que a estrutura seja instanciada e preenchida primariamente pela aplicação de diagnóstico fornecedora de dados como um objeto de valor na pilha ou na heap, para ser subsequentemente repassada ao subsistema SOVD. O tempo de vida segue as regras regulares para objetos C++; membros contidos do tipo ara::core::String, bem como o campo de tamanho opcional ara::core::Optional<std::uint64_t>, são liberados de forma determinística na destruição da instância ([SWS_DM_01835]).

A estrutura em si não possui estados internos ou transições de estado. Em ambientes multithreading, a leitura concorrente de uma instância não é crítica; no entanto, acessos de escrita às variáveis públicas devem ser sincronizados externamente pela aplicação chamadora, pois não existem mecanismos de proteção integrados.

Caminho de utilização

A ordem de chamada típica para uso do descritor de metadados no contexto de uma transferência em massa SOVD divide-se nas seguintes etapas:

  1. Instanciação: A aplicação de diagnóstico cria uma instância de BulkDataMetaDataDescriptor ([SWS_DM_01830]).
  2. Atribuir identificação e nomeação: O objeto de dados massivos é descrito por meio de id ([SWS_DM_01831]), name ([SWS_DM_01833]) e file_name ([SWS_DM_01836]). Se necessário, translation_id é informado ([SWS_DM_01834]).
  3. Preencher tipo MIME e registros de data e hora: O formato é definido por meio de mimetype ([SWS_DM_01832]). Na prática, presume-se que as indicações de data creation_date ([SWS_DM_01837]) e last_modified ([SWS_DM_01838]) sejam formatadas como strings de registro de data e hora em conformidade com a ISO-8601.
  4. Registrar valores de verificação e tamanho em bytes: Após a geração dos dados úteis, a soma de verificação em hash ([SWS_DM_01839]) e o algoritmo em hash_algorithm ([SWS_DM_01840]) são inseridos. Se a contagem de bytes for conhecida com antecedência, size será preenchido ([SWS_DM_01835]); caso o campo opcional permaneça vazio, isso provavelmente sinaliza um tamanho de arquivo ainda variável no momento da disponibilização.
  5. Repasse ao subsistema SOVD: O descritor inicializado é repassado a ara::diag para que os clientes SOVD externos possam consultar os metadados.

Diagrama de sequência: Fluxo típico de criação, preenchimento e disponibilização de BulkDataMetaDataDescriptor no contexto de diagnóstico SOVD. Fontes: SWS Diagnostics §8.53.2 «Struct: BulkDataMetaDataDescriptor», [SWS_DM_01830].

Cenários de erro

Como BulkDataMetaDataDescriptor é uma estrutura de dados passiva, nenhum código de erro é retornado diretamente por ela. Os erros manifestam-se no processamento subsequente por ara::diag ou pelo cliente:

  • Discrepância na soma de verificação: Se o hash indicado em hash ([SWS_DM_01839]) não coincidir com o conteúdo real ou se hash_algorithm ([SWS_DM_01840]) for desconhecido, a verificação no cliente falhará.
  • Divergência no tamanho em bytes: Se o campo opcional size ([SWS_DM_01835]) estiver definido e divergir da contagem de bytes efetivamente recebida, o receptor relatará um erro de transmissão.
  • Tipo de mídia inválido: Um mimetype ([SWS_DM_01832]) incorreto ou vazio leva a erros de interpretação na ferramenta cliente.
  • Identificação obrigatória ausente: Se id ([SWS_DM_01831]) ou file_name ([SWS_DM_01836]) não forem preenchidos, o registro de dados não poderá ser endereçado de forma inequívoca dentro do framework SOVD.
