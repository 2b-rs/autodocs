Contexto

A estrutura de dados [SWS_DM_01830] ara::diag::SovdBulkData::BulkDataMetaDataDescriptor define, de acordo com AUTOSAR_AP_SWS_Diagnostics §8.53.2 «Struct: BulkDataMetaDataDescriptor», os metadados descritivos para dados de diagnóstico em massa (Bulk Data) no âmbito do SOVD (Service-Oriented Vehicle Diagnostics). No módulo diag da AUTOSAR Adaptive Platform, grandes conjuntos de dados de diagnóstico, como arquivos de log, gravações de trace ou dumps de memória, são gerenciados por meio de interfaces padronizadas. Para tornar esses conjuntos de dados localizáveis, interpretáveis e verificáveis para testadores de diagnóstico externos ou serviços em nuvem, este descritor reúne todas as informações complementares administrativas e técnicas.

O descritor atua como portador de informações entre a aplicação capaz de diagnóstico (Adaptive Application) e o subsistema SOVD. De acordo com AUTOSAR_AP_SWS_Diagnostics §8.53.2.1 «Public Member Variables», a estrutura compreende as seguintes categorias de informações:

  • Identificação e nomenclatura: Os atributos id [SWS_DM_01831] e name [SWS_DM_01833] garantem o endereçamento inequívoco e a designação legível. A cadeia de caracteres opcional translation_id [SWS_DM_01834] serve para a localização específica do idioma.
  • Propriedades do arquivo: O nome do arquivo é definido por meio de file_name [SWS_DM_01836]. O atributo mimetype [SWS_DM_01832] especifica o formato de dados padronizado, enquanto size [SWS_DM_01835] indica, como ara::core::Optional<std::uint64_t>, o tamanho do arquivo em bytes.
  • Carimbos de data/hora: Os campos creation_date [SWS_DM_01837] e last_modified [SWS_DM_01838] documentam o ciclo de vida temporal dos dados.
  • Garantia de integridade: O digest criptográfico hash [SWS_DM_01839] e o método de cálculo hash_algorithm [SWS_DM_01840] permitem ao receptor a verificação da integridade dos dados.

Ciclo de vida

Como uma struct C++ pura, BulkDataMetaDataDescriptor segue a clássica semântica de valor (Value Object). A estrutura não possui processos em segundo plano ativos próprios nem máquinas de estados:

  • Criação: Instâncias são tipicamente instanciadas na pilha ou na memória livre pela Adaptive Application provedora e preenchidas com as propriedades do conjunto de dados a ser disponibilizado.
  • Propriedade e repasse: A estrutura consiste em tipos de valor padrão do C++ e do AUTOSAR (ara::core::String, bem como ara::core::Optional). Ela suporta operações regulares de cópia e de movimentação. Na entrega a interfaces de diagnóstico, a propriedade da instância ou uma cópia passa para o componente SOVD de processamento.
  • Destruição: A liberação de todos os recursos contidos ocorre automaticamente ao sair do escopo, de acordo com as regras de tempo de vida dos tipos de membros.
  • Concorrência: A estrutura não oferece proteção integrada contra acessos concorrentes. Se instâncias de descritor forem compartilhadas além dos limites de threads, os acessos de leitura e gravação devem ser protegidos por mecanismos de sincronização externos.

Caminho de utilização

Um fluxo típico para a disponibilização de dados de diagnóstico por meio do descritor de metadados se estrutura da seguinte forma:

  1. Preparação dos dados úteis: A aplicação coleta ou gera dados em massa (por exemplo, um dump de memória ou um log de erros) e os armazena no sistema de arquivos ou em um buffer.
  2. Inicialização do descritor: Uma instância de BulkDataMetaDataDescriptor é criada. A aplicação atribui os identificadores básicos, incluindo a identificação id [SWS_DM_01831], o identificador name [SWS_DM_01833] e o nome do arquivo de destino file_name [SWS_DM_01836].
  3. Especificação de formato e tamanho: A aplicação especifica o tipo MIME por meio de mimetype [SWS_DM_01832]. Se o tamanho total já for conhecido, o campo size [SWS_DM_01835] é preenchido com o valor em bytes.
  4. Determinação de checksum: Um checksum é determinado sobre o conteúdo dos dados. O nome do algoritmo (por exemplo, SHA-256) é armazenado em hash_algorithm [SWS_DM_01840] e o valor de verificação resultante é inserido em hash [SWS_DM_01839].
  5. Carimbos de data/hora e localização: Os atributos creation_date [SWS_DM_01837], bem como last_modified [SWS_DM_01838], são preenchidos. Se necessário, translation_id [SWS_DM_01834] é definido para interfaces de usuário dependentes do idioma.
  6. Entrega: O descritor totalmente preenchido é passado para os serviços SOVD do módulo diag, para que os clientes possam consultar as informações do arquivo e iniciar o download.

Cenários de erro

Por se tratar de uma estrutura de dados pura sem métodos próprios, BulkDataMetaDataDescriptor não lança códigos de erro específicos da plataforma (como ara::core::ErrorCode):

  • Inicialização incompleta: Interpretação: caso campos obrigatórios como id ou file_name não sejam preenchidos ou sejam preenchidos incorretamente, é provável que o ambiente de tempo de execução SOVD superior rejeite o registro ou a disponibilização do objeto de dados em massa.
  • Discrepância de checksum: Se o valor especificado em hash [SWS_DM_01839] não coincidir com os dados úteis reais ou se o algoritmo declarado em hash_algorithm [SWS_DM_01840] for inadmissível no lado do cliente ou do servidor, a validação durante a transferência falhará.
  • Valor ausente na especificação de tamanho: Como size [SWS_DM_01835] é do tipo ara::core::Optional, os componentes de processamento devem verificar por meio de has_value() se há uma especificação de tamanho antes do acesso, a fim de evitar acessos incorretos no caso de tamanho de dados ainda indeterminado (por exemplo, em fluxos de dados).

Este guia baseia-se na especificação AUTOSAR Adaptive R25-11 (módulo diag) e resume as características arquiteturais da estrutura de dados.
