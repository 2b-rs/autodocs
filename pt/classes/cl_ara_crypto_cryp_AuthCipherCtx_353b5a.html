Contexto

A interface ara::crypto::cryp::AuthCipherCtx define o contexto para operações criptográficas com criptografia autenticada (Authenticated Encryption with Associated Data, AEAD). Ela combina a confidencialidade de dados úteis com a verificação de integridade e a autenticidade por meio de uma tag de autenticação criptográfica (Authentication Tag), bem como dados adicionais associados opcionais (Additional Authenticated Data, AAD). As instâncias são tipicamente gerenciadas por meio do alias de smart pointer AuthCipherCtx::Sptr [SWS_CRYPT_20101].

Como parceiros de interação atuam, por um lado, a aplicação usuária, que criptografa e descriptografa fluxos de dados ou blocos individuais, e, por outro lado, o gerenciamento de chaves: o contexto opera diretamente em uma instância de chave do tipo SymmetricKey [SWS_CRYPT_23911] ou referencia um local de armazenamento persistente ou gerenciado via KeySlot [SWS_CRYPT_50072]. Funcionalmente, a interface suporta tanto streaming passo a passo quanto chamadas individuais atômicas (Single-Call).

Ciclo de vida

Da criação até a reutilização, o contexto passa por fases claramente definidas:

  • Nicht initialisiert (Uninitialized): Após a instanciação, o contexto ainda não está pronto para uso. Antes do processamento de dados, uma chave deve obrigatoriamente ser atribuída. Caso contrário, chamadas para transformação ou inicialização são rejeitadas com CryptoErrc::kUninitializedContext [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Konfiguriert (Configured / Key Set): A atribuição da chave ocorre por meio de SetKey() com um SymmetricKey [SWS_CRYPT_23911] ou um KeySlot [SWS_CRYPT_50072]. Neste estado, parâmetros estáticos como tamanhos de tag e de IV podem ser consultados. Para operações Single-Call, este estado já é suficiente.
  • Streaming aktiv (Processing): Por meio da chamada de Start() – opcionalmente com vetor de inicialização (IV) explícito [SWS_CRYPT_24715] ou sem ele, ou com o IV próprio do contexto [SWS_CRYPT_50073] –, o contexto transita para a fase ativa de streaming para uma direção de transformação (CryptoTransform). Aqui, dados adicionais e dados úteis podem ser processados sucessivamente.
  • Conclusão e retorno: O processamento é finalizado normalmente por Finish() [SWS_CRYPT_50075] ou FinishEncrypt() [SWS_CRYPT_50076]. O cancelamento prematuro de um fluxo em execução é possível a qualquer momento por meio de Cancel() [SWS_CRYPT_50077]. Após a conclusão ou cancelamento, o contexto permanece presumivelmente no estado configurado e fica disponível para uma nova inicialização por meio de Start().

Caminho de utilização

Dois caminhos estão disponíveis para o processamento: o processamento por streaming para dados maiores ou fragmentados e operações atômicas Single-Call.

A sequência típica de streaming apresenta-se da seguinte forma:

  1. Konfiguration: Vincular a chave via SetKey() [SWS_CRYPT_23911]. Previamente, podem ser determinados limites, tais como tamanhos de chunk mínimos/máximos [SWS_CRYPT_50162], [SWS_CRYPT_50082], o tamanho da tag [SWS_CRYPT_50161] e comprimentos de IV [SWS_CRYPT_50163], [SWS_CRYPT_50164], [SWS_CRYPT_50165].
  2. Start: Inicialização da operação por Start() sob indicação da direção de transformação (criptografia ou descriptografia) e, se aplicável, do IV [SWS_CRYPT_24715], [SWS_CRYPT_50073].
  3. Zugeordnete Daten (optional): Caso metadados adicionais em texto simples devam ser autenticados, eles devem ser passados via UpdateAuthenticatedData() [SWS_CRYPT_20313]. Isso deve obrigatoriamente ocorrer antes de quaisquer dados úteis confidenciais. O tamanho máximo pode ser verificado via GetMaxAssociatedDataSize() [SWS_CRYPT_20103].
  4. Vertrauliche Nutzdaten: Transferência gradual de chunks de dados por meio de UpdateConfidentialData() [SWS_CRYPT_50074]. Os tamanhos de buffer de saída necessários podem ser calculados dinamicamente via GetRequiredOutputBufferSize() [SWS_CRYPT_50081].
  5. Abschluss: Chamada de Finish() [SWS_CRYPT_50075] ou FinishEncrypt() [SWS_CRYPT_50076]. Com isso, os dados restantes são transformados, a tag de autenticação é finalizada (gerada na criptografia, verificada na descriptografia) e, se necessário, o IV gerado é retornado.

Para dados compactos disponíveis em uma única etapa, ProcessSingleCall() [SWS_CRYPT_50078], ProcessSingleCallWithInputIv() [SWS_CRYPT_50079] e EncryptSingleCallWithOutputIv() [SWS_CRYPT_50080] oferecem um processamento com pouco estado sem Start() prévio.

Diagrama de sequência: fluxo gradual de streaming de uma transformação autenticada com AuthCipherCtx. Fontes: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Cenários de erro

Os métodos garantem a sequência correta de protocolo e a segurança criptográfica por meio de códigos de erro específicos:

  • Reihenfolgeverletzung bei Zusatzdaten: Se UpdateAuthenticatedData() for chamado após dados confidenciais já terem sido processados via UpdateConfidentialData(), a operação falha com CryptoErrc::kInvalidUsageOrder [SWS_CRYPT_20313].
  • Verarbeitung ohne Start: Se UpdateAuthenticatedData(), UpdateConfidentialData(), Finish(), FinishEncrypt() ou Cancel() forem chamados sem uma chamada prévia e bem-sucedida de Start(), o erro CryptoErrc::kProcessingNotStarted é retornado [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50076], [SWS_CRYPT_50077].
  • Verificações de chaves e de permissões: Se o tipo de chave atribuído não corresponder ao contexto, SetKey() ou Start() retornará o erro CryptoErrc::kIncompatibleObject [SWS_CRYPT_23911], [SWS_CRYPT_24715]. Se faltarem à chave os sinalizadores de uso necessários (kAllowDataEncrypt ou kAllowDataDecrypt), isso resultará em CryptoErrc::kUsageViolation [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_50078]. No caso de posições ocupadas ou vazias, é reportado CryptoErrc::kBusyResource ou CryptoErrc::kEmptyKeySlot [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Puffer- und Dimensionsfehler: Se o buffer de saída fornecido for muito pequeno para os dados transformados ou para o IV, os métodos falham com CryptoErrc::kInsufficientCapacity [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50078]. Comprimentos inválidos de buffers de entrada, tags ou IVs levam a CryptoErrc::kInvalidInputSize [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_24715].
  • Fehlgeschlagene Authentifizierung: Se a verificação da tag de autenticação falhar na descriptografia, Finish() [SWS_CRYPT_50075] ou ProcessSingleCall() [SWS_CRYPT_50078] sinalizam o erro CryptoErrc::kAuthTagNotValid. Aviso de segurança importante: no streaming, UpdateConfidentialData() emite o texto simples descriptografado já antes da verificação da tag; a aplicação só deve reutilizar ou liberar esses dados após o Finish() bem-sucedido [SWS_CRYPT_50074].

Este guia baseia-se nas especificações para a AUTOSAR Adaptive Platform Release R25-11 e resume os requisitos para a classe ara::crypto::cryp::AuthCipherCtx.
