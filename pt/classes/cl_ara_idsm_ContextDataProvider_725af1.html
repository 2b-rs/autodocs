Contexto

A classe ara::idsm::ContextDataProvider serve no módulo idsm (Intrusion Detection System Manager) da AUTOSAR Adaptive Platform para o fornecimento e o enriquecimento de dados de contexto relevantes para a segurança ([SWS_AIDSM_10500]). No monitoramento de eventos críticos para a segurança, o IdsM necessita de informações adicionais de ambiente e de estado da aplicação para classificar com precisão anomalias ou incidentes de segurança detectados. Como interface, ContextDataProvider define o método abstrato ModifyContextData ([SWS_AIDSM_10509]), por meio do qual o IdsM consulta dados do componente da aplicação conforme a necessidade.

A interação ocorre entre três componentes essenciais:

  • Adaptive Application / subclasse do provedor: a aplicação implementa a lógica concreta do provedor ao sobrescrever ModifyContextData ([SWS_AIDSM_10509]) e controla o ciclo de vida do objeto de fornecimento.
  • Classe base ContextDataProvider: gerencia a vinculação à porta do provedor modelada no manifesto por meio de um identificador de instância ([SWS_AIDSM_10501]).
  • Serviço IdsM: o Intrusion Detection System acessa os dados de contexto assim que a disponibilização for ativada por meio da interface ([SWS_AIDSM_10507]).

Ciclo de vida

A instanciação de ContextDataProvider ocorre explicitamente por meio do construtor, passando um ara::core::InstanceSpecifier, o número de bytes adicionais (additionalBytes) e o deslocamento para os dados de contexto originais (originalContextDataOffset) ([SWS_AIDSM_10501]). Esse construtor é especificado como seguro para threads (thread-safe) ([SWS_AIDSM_10501]).

Em relação à semântica de posse e de valor, aplicam-se restrições rigorosas:

  • Cópia proibida: tanto o construtor de cópia ([SWS_AIDSM_10504]) quanto o operador de atribuição por cópia ([SWS_AIDSM_10506]) foram excluídos (= delete). Uma instância do provedor é vinculada de forma exclusiva a uma porta modelada e não pode ser duplicada.
  • Movimentação permitida: a classe possui um construtor de movimento seguro para threads ([SWS_AIDSM_10503]). Uma atribuição por movimento via operator= também é suportada, mas não é segura para threads (not thread-safe) ([SWS_AIDSM_10505]).

Após a construção, a instância encontra-se em um estado inativo. Somente por meio da chamada explícita de Offer() ([SWS_AIDSM_10507]) é sinalizado ao IdsM que o provedor está pronto e que ModifyContextData pode ser chamado. Com StopOffer() ([SWS_AIDSM_10508]), esse serviço é interrompido novamente. A liberação da instância ocorre por meio do destrutor virtual ~ContextDataProvider() ([SWS_AIDSM_10502]). Interpretação: para evitar race conditions durante a execução do destrutor, StopOffer() provavelmente deve ser chamado antes da destruição do objeto, já que tanto a destruição quanto o cancelamento de registro não são seguros para threads ([SWS_AIDSM_10502], [SWS_AIDSM_10508]).

Caminho de utilização

O fluxo regular para o fornecimento de dados de contexto compreende as seguintes fases:

  1. Derivação: Interpretação: como ModifyContextData é um método puramente virtual ([SWS_AIDSM_10509]), a aplicação cria sua própria classe derivada e sobrescreve essa função.
  2. Criação: a classe derivada do provedor é instanciada especificando o InstanceSpecifier para a porta modelada do provedor, o tamanho do buffer adicional e o deslocamento ([SWS_AIDSM_10501]).
  3. Ativação: a aplicação chama Offer() ([SWS_AIDSM_10507]). Após o registro bem-sucedido, o IdsM está autorizado a emitir chamadas de callback para o provedor.
  4. Fornecimento de contexto: se ocorrer um evento de segurança no IdsM, o framework chama ModifyContextData(contextData, event) ([SWS_AIDSM_10509]). A aplicação grava as informações contextuais no buffer de bytes passado (ara::core::Span<std::uint8_t>) e retorna a quantidade de bytes modificados.
  5. Desativação: antes do encerramento do componente, a aplicação chama StopOffer() ([SWS_AIDSM_10508]) para impedir novas chamadas pelo IdsM e destrói a instância ([SWS_AIDSM_10502]).

Diagrama de sequência: fluxo típico de inicialização, disponibilização (Offer), modificação de contexto orientada a eventos e cancelamento de registro (StopOffer). Fontes: [SWS_AIDSM_10501], [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509].

Cenários de erro

Os métodos de gerenciamento de estado e modificação de dados sinalizam estados de execução via ara::core::Result:

  • Falha de Offer: o método Offer() retorna ara::core::Result<void> ([SWS_AIDSM_10507]). Se a porta do provedor não puder ser registrada (por exemplo, devido à falta de recursos do sistema ou a uma modelagem incorreta), o objeto de resultado conterá o código de erro correspondente. Nesse caso, nenhuma chamada do IdsM para ModifyContextData é permitida.
  • Falha em ModifyContextData: a função de callback retorna ara::core::Result<std::size_t> ([SWS_AIDSM_10509]). Se a capacidade do ara::core::Span<std::uint8_t> passado não for suficiente ou se o contexto para o EventIdType relatado não puder ser determinado, a classe derivada retornará um resultado de erro em vez de transmitir uma contagem de bytes.
  • Pré e pós-condições: ModifyContextData só pode ocorrer entre um Offer() bem-sucedido ([SWS_AIDSM_10507]) e StopOffer() ([SWS_AIDSM_10508]). Como nem Offer(), StopOffer() nem ModifyContextData() são seguros para threads ([SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]), a aplicação chamadora deve assegurar que operações de ciclo de vida não ocorram de forma concorrente a execuções de callback em andamento.
