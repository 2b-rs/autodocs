Serve como interface para a disponibilização e modificação de dados de contexto específicos da aplicação para o IdsM.

A classe abstrata ara::idsm::ContextDataProvider serve para a disponibilização e modificação de dados de contexto específicos da aplicação para o Intrusion Detection System Manager [SWS_AIDSM_10500]. As aplicações derivam dessa classe, implementam o callback ModifyContextData e controlam a liberação para o IdsM por meio dos métodos Offer bem como StopOffer [SWS_AIDSM_10507]. A instância não é copiável e, como os métodos centrais não são thread-safe, o acesso concorrente provavelmente requer sincronização externa (interpretação).

Contexto

A classe ara::idsm::ContextDataProvider serve para a disponibilização e modificação de dados de contexto para o subsistema Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10500]. Dentro da arquitetura de segurança, a classe atua como interface entre uma aplicação relevante para a segurança e o serviço IdsM. Como a função-membro ModifyContextData está especificada como puramente virtual [SWS_AIDSM_10509], ContextDataProvider representa uma classe base abstrata. Uma aplicação deriva uma implementação própria para complementar dados de contexto específicos mediante eventos relevantes para a segurança. A vinculação à configuração da arquitetura ocorre por meio de um ara::core::InstanceSpecifier para o Provider Port modelado [SWS_AIDSM_10501].

Ciclo de vida

A criação de uma instância ocorre explicitamente por meio do construtor, especificando o identificador de porta (ara::core::InstanceSpecifier) bem como os parâmetros de buffer additionalBytes e originalContextDataOffset [SWS_AIDSM_10501]. Esse construtor é declarado como thread-safe [SWS_AIDSM_10501]. Para garantir relações de posse exclusivas para o endpoint da interface, tanto o construtor de cópia [SWS_AIDSM_10504] quanto o operador de atribuição por cópia [SWS_AIDSM_10506] foram excluídos. A transferência da instância é possível por meio da semântica de movimentação: o construtor de movimentação é thread-safe [SWS_AIDSM_10503], enquanto o operador de atribuição operator= com referência rvalue é definido como não thread-safe [SWS_AIDSM_10505].

Após a criação, a instância permanece em estado inativo. Apenas por meio da chamada explícita de Offer() o registro é ativado e o IdsM é autorizado a chamar ModifyContextData [SWS_AIDSM_10507]. Por meio de StopOffer(), essa autorização pode ser revogada a qualquer momento [SWS_AIDSM_10508]. Antes da destruição do objeto por meio do destrutor virtual [SWS_AIDSM_10502], conforme a prática comum, StopOffer() provavelmente precisa ser chamado para desativar callbacks em andamento pelo IdsM em tempo hábil (interpretação). O destrutor virtual é especificado como não thread-safe [SWS_AIDSM_10502].

Caminho de utilização

Um caso de uso típico começa com a definição de uma classe específica da aplicação que herda de ContextDataProvider e implementa o método ModifyContextData [SWS_AIDSM_10509]. Após a instanciação, a aplicação chama Offer() para disponibilizar os dados de contexto para o IdsM [SWS_AIDSM_10507]. Assim que o IdsM registra um evento de segurança para o qual dados de contexto devem ser complementados, o subsistema chama o callback ModifyContextData [SWS_AIDSM_10509]. O método recebe a área de dados como ara::core::Span<std::uint8_t> bem como o identificador EventIdType, atualiza o conteúdo do buffer e reporta o número real de bytes como ara::core::Result<std::size_t> [SWS_AIDSM_10509]. Caso a disponibilização de dados deva ser encerrada, a aplicação chama StopOffer() [SWS_AIDSM_10508].

Diagrama de sequência: sequência de interação entre aplicação, ContextDataProvider e IdsM, desde a ativação por meio de Offer passando pelo callback até a desativação via StopOffer. Fontes: [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]

Cenários de erro

Todos os métodos da interface são declarados com noexcept; erros são retornados por meio do tipo ara::core::Result. A chamada de Offer() retorna um ara::core::Result<void> [SWS_AIDSM_10507], que deve ser verificado pela aplicação para capturar eventuais erros na disponibilização do serviço. Se o provedor não puder gravar os dados de contexto solicitados em ModifyContextData, a implementação provavelmente reportará um erro específico do sistema no ara::core::Result<std::size_t> (interpretação) [SWS_AIDSM_10509].

Com relação à concorrência, deve-se observar que Offer() [SWS_AIDSM_10507], StopOffer() [SWS_AIDSM_10508], ModifyContextData() [SWS_AIDSM_10509], o operador de atribuição [SWS_AIDSM_10505] e o destrutor [SWS_AIDSM_10502] são especificados como não thread-safe. Se ocorrerem chamadas a esses métodos em paralelo a partir de múltiplas threads sem sincronização externa, isso provavelmente causará condições de corrida de dados e comportamento imprevisível (interpretação).
