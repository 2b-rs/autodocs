Monitorear como punto de reporte de um evento

Monitor conecta a lógica de erro de uma aplicação com o Diagnostic Event Management. Ele é oferecido para um monitor de diagnóstico configurado e relata as informações relevantes para o caminho de erro [SWS_DM_00543] através de ReportMonitorAction. O DM processa esta mensagem no contexto do evento associado; A interface, portanto, não substitui a configuração do evento nem o seu próprio gestão DTC.

Limites de avaliação

EnableConditions podem permitir ou bloquear o processamento do Monitor. A filtragem pode ser baseada em contadores, tempo ou no próprio Monitor; só o seu resultado é integrado no processamento do estado de evento SWS Diagnostics §7.3.4.1.4 «EnableConditions» SWS Diagnostics §7.3.4.1.5 «Debouncing». Por isso, uma ação de Monitor deve comunicar o resultado técnico da verificação, e não uma cópia inventada dos bits de estado DTC.

Leitura orientada ao estado do processamento do monitor: EnableConditions controla a avaliação, o resultado passa pelo debounce configurado e é processado como status do evento. Fontes: SWS Diagnostics §7.3.4.1.2 «Monitors», SWS Diagnostics §7.3.4.1.4 «EnableConditions», SWS Diagnostics §7.3.4.1.5 «Debouncing». Interpretação parcial: os estados agrupam o processo especificado em uma visualização do desenvolvedor.

Ciclo de vida e concorrência

O aplicação cria a interface com base no mapeamento de monitor específico da instância e a expõe com Offer. As chamadas do aplicação para o DM podem ser armazenadas em cache se o DM ainda não estiver disponível, a menos que o contrato preveja kServiceNotAvailable SWS Diagnostics §7.3.1 «Interaction between DM and applications». A API não é thread-safe por referência: várias trilhas de auditoria devem serializar a chamada para ReportMonitorAction antes de entrar nesta instância.

Quando relatar?

ReportMonitorAction reporta os resultados dos testes técnicos de um monitor configurado para o DM [SWS_DM_00543]. O método é a transição do aplicação para a depuração configurada e o processamento de eventos, não o local para definir você mesmo os bytes de status do DTC.

Prosseguir
  1. Execute a trilha de auditoria apenas se suas EnableConditions forem tecnicamente válidas.
  2. Selecione o MonitorAction apropriado para a descoberta determinada.
  3. Envie a mensagem em série para esta instância de monitor e relate apenas a próxima descoberta após sua própria sincronização.
Não antecipe o episódio

O processamento de debounce e status de evento é feito pelo DM SWS Diagnostics §7.3.4.1.5 «Debouncing» SWS Diagnostics §7.3.4.1.6 «Event Status processing». Uma chamada, portanto, não significa necessariamente que um DTC seja salvo imediatamente ou que um bit de status se torne visível.
