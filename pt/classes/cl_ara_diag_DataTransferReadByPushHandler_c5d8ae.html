Contexto

A classe ara::diag::DataTransferReadByPushHandler [SWS_DM_01515] fornece a interface padronizada para transferências de dados de diagnóstico no módulo Adaptive diag que são iniciadas por um serviço UDS como RequestReadFile ou RequestReadDirectory e nas quais os dados úteis são fornecidos ativamente ("enviados por push") pela implementação da aplicação AUTOSAR_AP_SWS_Diagnostics §8.10.3 «Class: DataTransferReadByPushHandler».

No sistema geral, interagem três atores principais:

  • Cliente UDS (testador de diagnóstico): inicia a transferência de arquivos ou diretórios por meio do protocolo de diagnóstico veicular e solicita blocos de dados sequencialmente.
  • Diagnostic Management (ara::diag): processa as solicitações UDS, gerencia a sessão de diagnóstico e encaminha chamadas de leitura e de término ao handler específico da aplicação [SWS_DM_01522].
  • Handler da aplicação: implementa a classe derivada de ara::diag::DataTransferReadByPushHandler, lê os dados da memória local e transfere a propriedade dos blocos de dados úteis para ara::diag [SWS_DM_01522].

Diagrama de contexto: interação entre o cliente UDS, o Diagnostic Management (ara::diag) e o handler específico da aplicação. Fontes: [SWS_DM_01515], [SWS_DM_01522], [SWS_DM_01523], AUTOSAR_AP_SWS_Diagnostics §8.10.3 «Class: DataTransferReadByPushHandler»

Ciclo de vida

O ciclo de vida de uma instância de handler está estritamente vinculado à duração de uma única sessão de transferência de arquivos:

  • Criação: o construtor padrão está declarado como protected [SWS_DM_01516]. Interpretação: a classe foi concebida como uma classe base pura, que deve ser derivada pela implementação específica da aplicação para fornecer os métodos puramente virtuais.
  • Posse e proibição de cópia: o construtor de cópia [SWS_DM_01518] e o operador de atribuição por cópia [SWS_DM_01521] foram excluídos (=delete). Um handler destina-se exclusivamente a exatamente uma transferência de leitura ("only one way usage i.e. per single file transfer session").
  • Capacidade de movimentação: o construtor de movimentação [SWS_DM_01517] e o operador de atribuição por movimentação [SWS_DM_01520] estão definidos como padrão (=default) e são seguros contra exceções (noexcept).
  • Destruição: o destrutor virtual [SWS_DM_01519] possui uma pré-condição rigorosa: uma instância não deve de forma alguma ser destruída antes da chamada de ExitRead() AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.1.2 «Destructor». Interpretação: a proibição de destruição assegura a consistência protocolar da sessão UDS no Diagnostic Management.
  • Concorrência: os métodos Read e ExitRead são especificados como não seguros para threads (not thread-safe) [SWS_DM_01522], [SWS_DM_01523]. Chamadas paralelas na mesma instância devem ser evitadas pelo lado da aplicação.

Caminho de utilização

O fluxo típico de uma transferência de leitura compreende os seguintes passos:

  1. Inicialização: ao receber uma solicitação de leitura (RequestReadFile ou RequestReadDirectory), a aplicação instancia seu handler concreto por meio do construtor protegido [SWS_DM_01516].
  2. Transferência de dados (Read): o Diagnostic Management chama repetidamente o método puramente virtual Read() [SWS_DM_01522] AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 «Read». São passados recommended_number_bytes_to_return para otimização de vazão, meta_info e um cancellation_handler. A aplicação monta o próximo chunk e transfere sua propriedade via ara::core::Future<ara::core::Vector<ara::core::Byte>> para ara::diag. Os dados úteis são inseridos na resposta positiva de UDS após o blockSequenceCounter como transferResponseParameterRecord.
  3. Término (ExitRead): para concluir a transferência, o Diagnostic Management chama ExitRead() [SWS_DM_01523] AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 «ExitRead». São passados o motivo do término (exit_type do tipo DataTransferExitType), parâmetros específicos do fabricante do veículo (transfer_request_parameter_record como ara::core::Span<const ara::core::Byte>), meta_info e cancellation_handler. A aplicação confirma o término assincronamente por meio do future de retorno.
  4. Liberação: somente após ExitRead() ter sido concluído é que a destruição do objeto handler pode ocorrer [SWS_DM_01519].

Diagrama de sequência: fluxo de chamadas típico em uma transferência de leitura baseada em push, desde a inicialização até a liberação. Fontes: [SWS_DM_01516], [SWS_DM_01519], [SWS_DM_01522], [SWS_DM_01523], AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 «ExitRead», AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 «Read»

Cenários de erro

No tratamento de erros e condições de exceção, devem ser cumpridas as seguintes diretrizes:

  • Negative Response Codes (NRC): ambos os métodos principais (Read e ExitRead) estão declarados como noexcept e não lançam exceções C++ [SWS_DM_01522], [SWS_DM_01523]. Se ocorrer um erro, o ara::core::Future retornado é resolvido com um ara::core::ErrorCode do domínio DiagUdsNrcErrc de acordo com a ISO 14229-1 para transmitir um NRC específico ao cliente.
  • Tratamento de cancelamento: os métodos recebem um CancellationHandler [SWS_DM_01522], [SWS_DM_01523]. A aplicação pode consultar o status de cancelamento por meio de cancellation_handler.IsCanceled() ou registrar uma função de notificação via cancellation_handler.SetNotifier(). Se o cancelamento for sinalizado, a preparação adicional dos dados deve ser interrompida.
  • Período de validade de parâmetros: o parâmetro transfer_request_parameter_record passado em ExitRead() é válido apenas até que a promise correspondente seja cumprida ou o processamento seja cancelado pelo CancellationHandler [SWS_DM_01523]. O acesso fora dessa janela de tempo é inadmissível.
  • Violação da pré-condição de destruição: se a instância for destruída antes da chamada de ExitRead(), trata-se de uma violação explícita da especificação [SWS_DM_01519], a qual pode levar a um comportamento inconsistente no Diagnostic Management.

Este guia baseia-se na especificação AUTOSAR Adaptive Platform Release R25-11.

<h4>Ciclo de vida</h4>
<p>O ciclo de vida de uma instância de handler está estritamente vinculado à duração de uma única sessão de transferência de arquivos:</p>
<ul>
<li><strong>Criação:</strong> o construtor padrão está declarado como <code>protected</code> <a class="spec-record-ref" data-req="SWS_DM_01516" href="../spec/record.html?id=SWS_DM_01516">[SWS_DM_01516]</a>. Interpretação: a classe foi concebida como uma classe base pura, que deve ser derivada pela implementação específica da aplicação para fornecer os métodos puramente virtuais.</li>
<li><strong>Posse e proibição de cópia:</strong> o construtor de cópia <a class="spec-record-ref" data-req="SWS_DM_01518" href="../spec/record.html?id=SWS_DM_01518">[SWS_DM_01518]</a> e o operador de atribuição por cópia <a class="spec-record-ref" data-req="SWS_DM_01521" href="../spec/record.html?id=SWS_DM_01521">[SWS_DM_01521]</a> foram excluídos (<code>=delete</code>). Um handler destina-se exclusivamente a exatamente uma transferência de leitura ("only one way usage i.e. per single file transfer session").</li>
<li><strong>Capacidade de movimentação:</strong> o construtor de movimentação <a class="spec-record-ref" data-req="SWS_DM_01517" href="../spec/record.html?id=SWS_DM_01517">[SWS_DM_01517]</a> e o operador de atribuição por movimentação <a class="spec-record-ref" data-req="SWS_DM_01520" href="../spec/record.html?id=SWS_DM_01520">[SWS_DM_01520]</a> estão definidos como padrão (<code>=default</code>) e são seguros contra exceções (<code>noexcept</code>).</li>
<li><strong>Destruição:</strong> o destrutor virtual <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a> possui uma pré-condição rigorosa: uma instância não deve de forma alguma ser destruída antes da chamada de <code>ExitRead()</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=374">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.1.2 «Destructor»</a>. Interpretação: a proibição de destruição assegura a consistência protocolar da sessão UDS no Diagnostic Management.</li>
<li><strong>Concorrência:</strong> os métodos <code>Read</code> e <code>ExitRead</code> são especificados como não seguros para threads (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. Chamadas paralelas na mesma instância devem ser evitadas pelo lado da aplicação.</li>
</ul>

<h4>Caminho de utilização</h4>
<p>O fluxo típico de uma transferência de leitura compreende os seguintes passos:</p>
<ol>
<li><strong>Inicialização:</strong> ao receber uma solicitação de leitura (<code>RequestReadFile</code> ou <code>RequestReadDirectory</code>), a aplicação instancia seu handler concreto por meio do construtor protegido <a class="spec-record-ref" data-req="SWS_DM_01516" href="../spec/record.html?id=SWS_DM_01516">[SWS_DM_01516]</a>.</li>
<li><strong>Transferência de dados (<code>Read</code>):</strong> o Diagnostic Management chama repetidamente o método puramente virtual <code>Read()</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=376">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 «Read»</a>. São passados <code>recommended_number_bytes_to_return</code> para otimização de vazão, <code>meta_info</code> e um <code>cancellation_handler</code>. A aplicação monta o próximo chunk e transfere sua propriedade via <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code> para <code>ara::diag</code>. Os dados úteis são inseridos na resposta positiva de UDS após o <code>blockSequenceCounter</code> como <code>transferResponseParameterRecord</code>.</li>
<li><strong>Término (<code>ExitRead</code>):</strong> para concluir a transferência, o Diagnostic Management chama <code>ExitRead()</code> <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=375">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 «ExitRead»</a>. São passados o motivo do término (<code>exit_type</code> do tipo <code>DataTransferExitType</code>), parâmetros específicos do fabricante do veículo (<code>transfer_request_parameter_record</code> como <code>ara::core::Span&lt;const ara::core::Byte&gt;</code>), <code>meta_info</code> e <code>cancellation_handler</code>. A aplicação confirma o término assincronamente por meio do future de retorno.</li>
<li><strong>Liberação:</strong> somente após <code>ExitRead()</code> ter sido concluído é que a destruição do objeto handler pode ocorrer <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a>.</li>
</ol>

<h4>Cenários de erro</h4>
<p>No tratamento de erros e condições de exceção, devem ser cumpridas as seguintes diretrizes:</p>
<ul>
<li><strong>Negative Response Codes (NRC):</strong> ambos os métodos principais (<code>Read</code> e <code>ExitRead</code>) estão declarados como <code>noexcept</code> e não lançam exceções C++ <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. Se ocorrer um erro, o <code>ara::core::Future</code> retornado é resolvido com um <code>ara::core::ErrorCode</code> do domínio <code>DiagUdsNrcErrc</code> de acordo com a ISO 14229-1 para transmitir um NRC específico ao cliente.</li>
<li><strong>Tratamento de cancelamento:</strong> os métodos recebem um <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. A aplicação pode consultar o status de cancelamento por meio de <code>cancellation_handler.IsCanceled()</code> ou registrar uma função de notificação via <code>cancellation_handler.SetNotifier()</code>. Se o cancelamento for sinalizado, a preparação adicional dos dados deve ser interrompida.</li>
<li><strong>Período de validade de parâmetros:</strong> o parâmetro <code>transfer_request_parameter_record</code> passado em <code>ExitRead()</code> é válido apenas até que a promise correspondente seja cumprida ou o processamento seja cancelado pelo <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. O acesso fora dessa janela de tempo é inadmissível.</li>
<li><strong>Violação da pré-condição de destruição:</strong> se a instância for destruída antes da chamada de <code>ExitRead()</code>, trata-se de uma violação explícita da especificação <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a>, a qual pode levar a um comportamento inconsistente no Diagnostic Management.</li>
</ul>
