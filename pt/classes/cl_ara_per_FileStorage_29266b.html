Papel não modelo de armazenamento

FileStorage representa um conjunto configurado de ficheiros nomeados, semelhante a um diretório. Os ficheiros podem ser pré-instalados, criados durante uma atualização ou criados e excluídos em tempo de execução. SWS Persistency §7.4 «File Storage specific Features»

Do armazenamento ao ficheiro

Após OpenFileStorage, FileExists e GetAllFileNames verificam o inventário. OpenFileReadOnly, OpenFileWriteOnly e OpenFileReadWrite criam o Accessor exclusivo adequado; o tratamento dos conteúdos fica então a cargo de ReadAccessor, WriteAccessor ou ReadWriteAccessor.

Escrever, bloquear e redefinir

Um descriptor de acesso aberto vincula ou ficheiro exclusivamente. Por ou tanto, não planifique DeleteFile, ResetFile e RecoverFile em paralelo com ou acesso activo. Os límites de recursos, así como os dados redundantes e de respaldo, cuentan para ou espaço de armazenamento utilizado. SWS Persistency §7.2.6 «Resource Management Concepts»

Estratégia de falha

Um armazenamento de ficheiros gerencia um conjunto de ficheiros nomeados; o acessador tem propriedade exclusiva do acesso aberto específico. Fontes: SWS Persistency §7.4 «File Storage specific Features» [SWS_PER_00113].

Resets a file of this File Storage to its initial content. ResetFile allows to reset a single file to its initial content. If the file is currently not available in the File Storage, it is re-created. Afterwards, the file will appear in both cases as if it was newly installed from the current Target Configuration. It will fail with kResourceBusy when the file is currently open, and with kInitValueNotAvailable when neither Application Design nor Target Configuration define an initial content for the file.
