Finalidade de uso

ara::core::InstanceSpecifier representa um especificador de instância AUTOSAR como um wrapper em torno de um caminho ShortName. Para interação da aplicação, um caminho válido começa com / e contém ShortNames separados por / até o PortPrototype; Um separador de caminho principal também é necessário para a interação funcional do cluster. Referência e resolução do manifesto

InstanceSpecifier é um conceito de caminho de modelo separado por / que aponta exclusivamente o código do aplicação para recursos definidos no modelo do sistema. O construtor verifica a sintaxe; Functional Clusters apenas verificam a validade semântica do caminho ao acessar o recurso designado. EXP ARAComAPI §6.2 «Usage of InstanceSpecifier»

Para ara::com, o manifesto da instância de serviço vincula tal especificador à instância do protótipo de porta e, portanto, a uma instância de serviço concreta. O InstanceIdentifier resultante depende da tecnologia. EXP ARAComAPI §6.2.1 «Modeling and configuration/mapping» TPS ManifestSpecification §B.5.1 «Relation between Instance Specifier and Instance Ref»

Diagrama de atividades: O especificador serve como uma entrada próxima do modelo para a resolução de um InstanceIdentifier específico da ligação. Interpretação: O nó «ResolveInstanceIDs» resume a resolução semântica que ocorre nos clusters funcionais. Fontes: EXP ARAComAPI §6.2 «Usage of InstanceSpecifier» EXP ARAComAPI §6.2.1 «Modeling and configuration/mapping» TPS ManifestSpecification §B.5.1 «Relation between Instance Specifier and Instance Ref».

Tipo de dados principais no contexto do modelo

A especificação Core trata os Instance Specifiers como tipos de dados próprios de AUTOSAR. A utilização como caminho próximo do modelo e a resolução posterior num Functional Cluster são, por isso, passos separados; o binding concreto de destino surge apenas fora do caminho puro de carateres.
