Contexto

A classe ara::core::InstanceSpecifier serve na AUTOSAR Adaptive Platform como encapsulamento com segurança de tipos de um caminho ShortName do AUTOSAR (caminho do metamodelo) para a identificação de elementos de modelo. Funciona como um identificador padronizado com o qual componentes de software, portas de comunicação e instâncias de serviço podem ser referenciados e resolvidos de forma inequívoca dentro de todo o sistema.

Na interação com outros componentes, ara::core::InstanceSpecifier interage essencialmente através das seguintes interfaces:

  • Vistas de strings: As especificações de caminho são passadas como ara::core::StringView e, se necessário, disponibilizadas novamente como tal através do método ToString() [SWS_CORE_08041].
  • Tratamento de resultados e de erros: O método de fábrica estático utiliza ara::core::Result para devolver instâncias válidas ou para sinalizar erros de validação [SWS_CORE_08032]. No fluxo de construção baseado em erros, pelo contrário, é lançada ara::core::CoreException [SWS_CORE_08021].
  • Contentores e metamodelo: Através da disponibilização de um operador de ordenação estrita operator<, a classe pode ser utilizada como chave em contentores ordenados (por exemplo, maps associativos) para a gestão de identificadores de elementos de modelo [SWS_CORE_08046]. Além disso, os operadores de comparação permitem a comparação direta com outras instâncias, bem como com strings de caminho em bruto [SWS_CORE_08042], [SWS_CORE_08043], [SWS_CORE_08044], [SWS_CORE_08045].

Ciclo de vida

A criação de uma instância de ara::core::InstanceSpecifier pode ocorrer de duas formas distintas:

  1. Método de fábrica Create: O método estático Create aceita um ara::core::StringView e valida as regras sintáticas da estrutura do caminho [SWS_CORE_08032]. É seguro contra exceções (noexcept), seguro para threads (thread-safe) e devolve um ara::core::Result<InstanceSpecifier>, que, em caso de sucesso, encapsula a instância concluída ou, em caso de erro, um código de erro correspondente.
  2. Construção direta: O construtor explícito também aceita um ara::core::StringView, mas está especificado como noexcept(false) e sinaliza erros de validação através do lançamento de uma exceção do tipo ara::core::CoreException [SWS_CORE_08021]. Este construtor é seguro para threads.

Para a semântica de valores, a classe disponibiliza construtores e operadores de atribuição padronizados:

  • Cópia: O construtor de cópia [SWS_CORE_08022] está declarado como noexcept e é seguro para threads. O operador de atribuição por cópia [SWS_CORE_08024] também é noexcept, mas não seguro para threads.
  • Movimento: O construtor de movimento [SWS_CORE_08023] e o operador de atribuição por movimento [SWS_CORE_08025] são noexcept, mas não seguros para threads.
  • Destruição: O destrutor ~InstanceSpecifier() [SWS_CORE_08029] é noexcept e não seguro para threads.

Em relação à posse e ao tempo de vida, existe uma restrição essencial: o tempo de vida do ara::core::StringView retornado por ToString() é garantido apenas para o tempo de vida da cadeia de caracteres subjacente, que foi originalmente passada como ara::core::StringView para o construtor ou método de criação [SWS_CORE_08041]. Interpretação: a partir dessa especificação, deve decorrer que ara::core::InstanceSpecifier não cria uma cópia profunda autônoma da string, mas apenas mantém internamente uma visão ou referência ao buffer original. Os desenvolvedores devem, portanto, assegurar que o objeto string passado permaneça válido na memória durante todo o período de uso do InstanceSpecifier e das visões dele derivadas.

Em relação à concorrência, aplica-se o seguinte: operações puras de leitura (incluindo ToString(), operator==, operator!=, operator<, bem como o construtor de cópia) são totalmente thread-safe. Operações modificadoras (construção por movimentação, operadores de atribuição e a destruição) não são thread-safe e não devem ser executadas concorrentemente de forma desprotegida no mesmo objeto.

Caminho de utilização

Um fluxo de uso típico inclui a validação de um caminho de modelo durante a configuração ou inicialização, a criação do identificador e seu uso subsequente para identificação ou ordenação.

  1. Instanciação validada: a aplicação chama ara::core::InstanceSpecifier::Create() com um caminho de metamodelo [SWS_CORE_08032].
  2. Verificação do resultado: o ara::core::Result retornado é verificado quanto a erros. Em caso de caracteres inválidos ou elementos de caminho ausentes, a lógica de execução desvia para o tratamento de erros.
  3. Identificação e comparação: a instância extraída é utilizada para comparações com identificadores esperados ou visões de cadeia de caracteres [SWS_CORE_08042], [SWS_CORE_08043].
  4. Armazenamento em contêineres: se necessário, a instância é armazenada em estruturas de dados associativas; a ordenação ocorre por meio do operador de comparação lexical operator< [SWS_CORE_08046].
  5. Saída textual: para fins de registro em log ou diagnóstico, uma representação em string é consultada por meio de ToString() [SWS_CORE_08041].

Diagrama de sequência: validação, criação e uso típicos de InstanceSpecifier. Fontes: [SWS_CORE_08032], [SWS_CORE_08041], [SWS_CORE_08046].

Cenários de erro

Na criação de um ara::core::InstanceSpecifier, podem ocorrer erros de validação relativos ao caminho de nome passado:

  • CoreErrc::kInvalidMetaModelShortname: este erro ocorre se um dos elementos de caminho do qualifiedShortName estiver ausente ou contiver caracteres inválidos [SWS_CORE_08032], [SWS_CORE_08021].
  • CoreErrc::kInvalidMetaModelPath: este erro é reportado se o qualifiedShortName passado não constituir um caminho sintaticamente válido para um elemento de modelo [SWS_CORE_08032], [SWS_CORE_08021].

A forma de sinalização de erros depende da interface selecionada:

  • Ao utilizar o método factory Create, a operação é executada com semântica de rollback; o ara::core::Result retornado contém o respectivo código de erro, sem que exceções sejam lançadas [SWS_CORE_08032].
  • Ao utilizar o construtor explícito, a ocorrência de um desses erros faz com que seja lançada uma exceção do tipo ara::core::CoreException, transportando o código de erro CoreErrc apropriado [SWS_CORE_08021].

Como pré-condição para uma instanciação sem erros, a string de entrada deve sempre atender às regras sintáticas predefinidas para elementos de caminho e caminhos de metamodelo [SWS_CORE_08032], [SWS_CORE_08021]. Por outro lado, os operadores de comparação e acesso não possuem estados de retorno de erro e garantem uma avaliação sem falhas após a criação bem-sucedida (noexcept).

Este guia baseia-se exclusivamente na especificação AUTOSAR para ara::core::InstanceSpecifier no release R25-11.

<h4>Contexto</h4>
<p>A classe <code>ara::core::InstanceSpecifier</code> serve na AUTOSAR Adaptive Platform como encapsulamento com segurança de tipos de um caminho ShortName do AUTOSAR (caminho do metamodelo) para a identificação de elementos de modelo. Funciona como um identificador padronizado com o qual componentes de software, portas de comunicação e instâncias de serviço podem ser referenciados e resolvidos de forma inequívoca dentro de todo o sistema.</p>
<p>Na interação com outros componentes, <code>ara::core::InstanceSpecifier</code> interage essencialmente através das seguintes interfaces:</p>
<ul>
<li><strong>Vistas de strings:</strong> As especificações de caminho são passadas como <code>ara::core::StringView</code> e, se necessário, disponibilizadas novamente como tal através do método <code>ToString()</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
<li><strong>Tratamento de resultados e de erros:</strong> O método de fábrica estático utiliza <code>ara::core::Result</code> para devolver instâncias válidas ou para sinalizar erros de validação <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. No fluxo de construção baseado em erros, pelo contrário, é lançada <code>ara::core::CoreException</code> <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
<li><strong>Contentores e metamodelo:</strong> Através da disponibilização de um operador de ordenação estrita <code>operator&lt;</code>, a classe pode ser utilizada como chave em contentores ordenados (por exemplo, maps associativos) para a gestão de identificadores de elementos de modelo <a class="spec-record-ref" data-req="SWS_CORE_08046" href="../spec/record.html?id=SWS_CORE_08046">[SWS_CORE_08046]</a>. Além disso, os operadores de comparação permitem a comparação direta com outras instâncias, bem como com strings de caminho em bruto <a class="spec-record-ref" data-req="SWS_CORE_08042" href="../spec/record.html?id=SWS_CORE_08042">[SWS_CORE_08042]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08043" href="../spec/record.html?id=SWS_CORE_08043">[SWS_CORE_08043]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08044" href="../spec/record.html?id=SWS_CORE_08044">[SWS_CORE_08044]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08045" href="../spec/record.html?id=SWS_CORE_08045">[SWS_CORE_08045]</a>.</li>
</ul>

<h4>Ciclo de vida</h4>

<ol>
<li><strong>Método de fábrica <code>Create</code>:</strong> O método estático <code>Create</code> aceita um <code>ara::core::StringView</code> e valida as regras sintáticas da estrutura do caminho <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. É seguro contra exceções (<code>noexcept</code>), seguro para threads (<code>thread-safe</code>) e devolve um <code>ara::core::Result&lt;InstanceSpecifier&gt;</code>, que, em caso de sucesso, encapsula a instância concluída ou, em caso de erro, um código de erro correspondente.</li>
<li><strong>Construção direta:</strong> O construtor explícito também aceita um <code>ara::core::StringView</code>, mas está especificado como <code>noexcept(false)</code> e sinaliza erros de validação através do lançamento de uma exceção do tipo <code>ara::core::CoreException</code> <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. <li><strong>Destruição:</strong> O destrutor <code>~InstanceSpecifier()</code> <a class="spec-record-ref" data-req="SWS_CORE_08029" href="../spec/record.html?id=SWS_CORE_08029">[SWS_CORE_08029]</a> é <code>noexcept</code> e não seguro para threads.</li>
</ul>
<p>Em relação à posse e ao tempo de vida, existe uma restrição essencial: o tempo de vida do <code>ara::core::StringView</code> retornado por <code>ToString()</code> é garantido apenas para o tempo de vida da cadeia de caracteres subjacente, que foi originalmente passada como <code>ara::core::StringView</code> para o construtor ou método de criação <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>. Interpretação: a partir dessa especificação, deve decorrer que <code>ara::core::InstanceSpecifier</code> não cria uma cópia profunda autônoma da string, mas apenas mantém internamente uma visão ou referência ao buffer original. Os desenvolvedores devem, portanto, assegurar que o objeto string passado permaneça válido na memória durante todo o período de uso do <code>InstanceSpecifier</code> e das visões dele derivadas.</p>
<p>Em relação à concorrência, aplica-se o seguinte: operações puras de leitura (incluindo <code>ToString()</code>, <code>operator==</code>, <code>operator!=</code>, <code>operator&lt;</code>, bem como o construtor de cópia) são totalmente thread-safe. Operações modificadoras (construção por movimentação, operadores de atribuição e a destruição) não são thread-safe e não devem ser executadas concorrentemente de forma desprotegida no mesmo objeto.</p>

<h4>Caminho de utilização</h4>
<p>Um fluxo de uso típico inclui a validação de um caminho de modelo durante a configuração ou inicialização, a criação do identificador e seu uso subsequente para identificação ou ordenação.</p>
<ol>
<li><strong>Instanciação validada:</strong> a aplicação chama <code>ara::core::InstanceSpecifier::Create()</code> com um caminho de metamodelo <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>.</li>
<li><strong>Verificação do resultado:</strong> o <code>ara::core::Result</code> retornado é verificado quanto a erros. Em caso de caracteres inválidos ou elementos de caminho ausentes, a lógica de execução desvia para o tratamento de erros.</li>
<li><strong>Identificação e comparação:</strong> a instância extraída é utilizada para comparações com identificadores esperados ou visões de cadeia de caracteres <a class="spec-record-ref" data-req="SWS_CORE_08042" href="../spec/record.html?id=SWS_CORE_08042">[SWS_CORE_08042]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08043" href="../spec/record.html?id=SWS_CORE_08043">[SWS_CORE_08043]</a>.</li>
<li><strong>Armazenamento em contêineres:</strong> se necessário, a instância é armazenada em estruturas de dados associativas; a ordenação ocorre por meio do operador de comparação lexical <code>operator&lt;</code> <a class="spec-record-ref" data-req="SWS_CORE_08046" href="../spec/record.html?id=SWS_CORE_08046">[SWS_CORE_08046]</a>.</li>
<li><strong>Saída textual:</strong> para fins de registro em log ou diagnóstico, uma representação em string é consultada por meio de <code>ToString()</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
</ol>

<h4>Cenários de erro</h4>
<p>Na criação de um <code>ara::core::InstanceSpecifier</code>, podem ocorrer erros de validação relativos ao caminho de nome passado:</p>
<ul>
<li><strong><code>CoreErrc::kInvalidMetaModelShortname</code>:</strong> este erro ocorre se um dos elementos de caminho do <code>qualifiedShortName</code> estiver ausente ou contiver caracteres inválidos <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
<li><strong><code>CoreErrc::kInvalidMetaModelPath</code>:</strong> este erro é reportado se o <code>qualifiedShortName</code> passado não constituir um caminho sintaticamente válido para um elemento de modelo <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>A forma de sinalização de erros depende da interface selecionada:</p>
<ul>
<li>Ao utilizar o método factory <code>Create</code>, a operação é executada com semântica de rollback; o <code>ara::core::Result</code> retornado contém o respectivo código de erro, sem que exceções sejam lançadas <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>.</li>
<li>Ao utilizar o construtor explícito, a ocorrência de um desses erros faz com que seja lançada uma exceção do tipo <code>ara::core::CoreException</code>, transportando o código de erro <code>CoreErrc</code> apropriado <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>Como pré-condição para uma instanciação sem erros, a string de entrada deve sempre atender às regras sintáticas predefinidas para elementos de caminho e caminhos de metamodelo <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. Por outro lado, os operadores de comparação e acesso não possuem estados de retorno de erro e garantem uma avaliação sem falhas após a criação bem-sucedida (<code>noexcept</code>).</p>
