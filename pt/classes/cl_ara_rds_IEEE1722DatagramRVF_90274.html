Encapsula metadados e campos de cabeçalho de datagramas IEEE 1722 para fluxos de dados de vídeo não compactados.

A classe ara::rds::IEEE1722DatagramRVF representa, dentro do módulo AUTOSAR Raw Data Stream, datagramas IEEE 1722 específicos para o Raw Video Format destinados à transmissão estruturada de fluxos de vídeo não compactados SWS RawDataStream §1 «Raw Data Stream». Ela reúne todos os metadados relevantes para imagem e transmissão, tais como números de linhas, espaços de cores, taxas de quadros e bits de controle de protocolo, em campos opcionais protegidos. Sendo uma estrutura de dados declarada como final, ela impede qualquer derivação adicional, assegurando, contudo, por meio de um destrutor virtual, uma desalocação determinística e livre de exceções via ponteiros de classe base [SWS_RDS_90292].

Contexto

A classe ara::rds::IEEE1722DatagramRVF representa um datagrama IEEE 1722 concreto para o Raw Video Format (RVF) dentro do módulo funcional Raw Data Stream (rds) da AUTOSAR Adaptive Platform SWS RawDataStream §1 «Raw Data Stream». O Raw Video Format serve, no escopo de Audio Video Bridging (AVB) e Time-Sensitive Networking (TSN), para o transporte de fluxos de vídeo não compactados por redes baseadas em pacotes. A estrutura de dados é definida no arquivo de cabeçalho ara/rds/raw_data_stream_IEEE1722.h [SWS_RDS_90276]. A definição da classe é provida da palavra-chave final e integra, por herança protegida (protected), tanto a classe base genérica IEEE1722Datagram quanto AVTPDUCommonStreamHeaderFields [SWS_RDS_90276]. Por meio dessa composição, a estrutura combina campos básicos de cabeçalho de fluxo AVTP com os campos de metadados específicos necessários para o processamento de linhas de vídeo e matrizes de imagem individuais.

Diagrama de contexto: incorporação de IEEE1722DatagramRVF na hierarquia de classes com IEEE1722Datagram e AVTPDUCommonStreamHeaderFields. Fontes: [SWS_RDS_90276], SWS RawDataStream §1 «Raw Data Stream»

Ciclo de vida

O ciclo de vida de uma instância de IEEE1722DatagramRVF é determinado de forma decisiva pelo pipeline de processamento do Raw Data Stream. Para a limpeza adequada de instâncias, a classe declara um destrutor virtual virtual ~IEEE1722DatagramRVF() noexcept [SWS_RDS_90292]. Embora a classe em si esteja marcada como final [SWS_RDS_90276] e, portanto, não possa atuar como classe base para outras subclasses, o projeto virtual do destrutor assegura a liberação correta caso as instâncias sejam referenciadas e destruídas polimorficamente por meio de ponteiros da classe base.

A adição noexcept no destrutor garante que, sob nenhuma circunstância, exceções possam escapar durante o processo de destruição [SWS_RDS_90292]. Em sistemas automotivos críticos para a segurança, esta é uma pré-condição essencial para assegurar processos de limpeza determinísticos sem interrupções abruptas do programa. A especificação AUTOSAR não define primitivas de sincronização explícitas para acesso concorrente a esta classe de dados; portanto, o tratamento thread-safe deve ser garantido, se necessário, no nível dos serviços de streaming adjacentes.

Caminho de utilização

No fluxo prático de processamento, a classe atua como portadora de informações para quadros de vídeo recebidos ou a serem enviados. Para isso, a estrutura agrupa inúmeros campos que descrevem em detalhes dimensões de imagem, referência temporal e codificação de cores. Para a estrutura geométrica do vídeo, são disponibilizados os pixels ativos active_pixels [SWS_RDS_90276], o número total de linhas de uma imagem total_lines [SWS_RDS_90278], o número da linha line_number [SWS_RDS_90291] e a contagem de linhas por pacote de dados num_lines [SWS_RDS_90289].

Para a correta interpretação do fluxo de dados de pixels, a classe também encapsula propriedades do formato de vídeo específicas do sistema: a profundidade de bits por pixel pixel_depth [SWS_RDS_90285], o formato de pixel pixel_format [SWS_RDS_90286], o espaço de cores colorspace [SWS_RDS_90288] e a taxa de atualização de quadros frame_rate [SWS_RDS_90287]. Somam-se a isso bits de controle e de status específicos do protocolo de transmissão AVTP: o campo ap [SWS_RDS_90279], a flag f [SWS_RDS_90280], o campo ef [SWS_RDS_90281], campos de evento como evt [SWS_RDS_90282] e pd [SWS_RDS_90283], a flag i [SWS_RDS_90284] e o número de sequência i_seq_num [SWS_RDS_90290].

Nota-se o encapsulamento contínuo de todas as variáveis em ara::core::Optional. Essa declaração sugere que os datagramas podem apresentar cabeçalhos incompletos ou que determinados metadados são transmitidos apenas sob demanda, dependendo do perfil de empacotamento AVTP. Todos os atributos possuem o nível de proteção protected [SWS_RDS_90276], [SWS_RDS_90278]. Como a derivação por código de usuário é impossível devido a final, presume-se que o acesso de leitura e escrita a esses campos seja realizado por classes auxiliares internas ou instâncias de driver amigas (friend) do módulo RDS.
