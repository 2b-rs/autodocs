Permite que skeletons de serviço enviem sinais de disparo (triggers) e monitorem o status dos assinantes.

A classe <SI-Namespace>::skeleton::triggers::<Trigger> permite que uma aplicação de servidor envie sinais de disparo a clientes assinantes por meio do Communication Management ([SWS_CM_00721]). Para controle de fluxo, é possível monitorar o status dos assinantes e registrar manipuladores de notificação ([SWS_CM_01109], [SWS_CM_01110]). O acionamento via Send() requer um skeleton de serviço oferecido e sinaliza violações de intervalos mínimos de envio ou erros de rede com os códigos de erro correspondentes ([SWS_CM_00721], [SWS_CM_10517]).

Contexto

A classe de modelo (template) <SI-Namespace>::skeleton::triggers::<Trigger> representa a interface do lado do servidor de um trigger definido dentro de um ServiceInterface na função trigger. Como parte do esqueleto de serviço (skeleton), essa classe serve para que uma instância de serviço envie notificações assíncronas ou sinais de disparo para aplicações cliente assinantes em todo o sistema. Um trigger difere de eventos normais por atuar primariamente como um evento puro de sinalização sem dados úteis complexos, conforme exposto na classificação em EXP_ARAComAPI §3 «Trigger::Send» e SWS_CommunicationManagement §7.2.2.1.4 «Handling Triggers». Os parceiros de interação incluem a aplicação servidora provedora, o middleware Communication Management (ara::com) bem como clientes assinantes conectados pela rede.

Ciclo de vida

A instanciação dos objetos de trigger ocorre tipicamente como parte integrante da instância do skeleton do respectivo ServiceInterface. Antes da utilização ativa, o skeleton deve ser oferecido por meio do Communication Management; se houver uma tentativa de acionar um trigger antes disso, a transmissão falha ([SWS_CM_00721]). A classe gerencia o estado de subscrição dos assinantes via ara::com::SubscriptionState, o qual pode ser consultado a qualquer momento com GetSubscriptionState() ([SWS_CM_01109]). Para o monitoramento assíncrono de estado, é possível registrar um callback por meio de SetSubscriptionStateChangeHandler() ([SWS_CM_01110]). Para arquiteturas concorrentes, existe uma sobrecarga que recebe um executor definido pelo usuário, de modo que as notificações sejam executadas no contexto desejado de thread ou tarefa ([SWS_CM_01111]). O registro pode ser cancelado por meio de UnsetSubscriptionStateChangeHandler() ([SWS_CM_01112]). Todos os métodos da classe oferecem a garantia de exceção noexcept (exception safe).

Caminho de utilização

O fluxo típico para a utilização de um trigger engloba a observação do status de subscrição, bem como o disparo efetivo da transmissão para todos os assinantes ativos:

  • Registro de manipulador: a aplicação de serviço registra opcionalmente um manipulador de estado por meio de SetSubscriptionStateChangeHandler() ([SWS_CM_01110], [SWS_CM_01111]) para ser informada sobre novos assinantes adicionados.
  • Verificação de estado: com GetSubscriptionState(), o servidor verifica se há pelo menos um assinante ativo ([SWS_CM_01109]), o que, de acordo com [SWS_CM_10518], constitui o pré-requisito para a requisição de envio.
  • Envio do trigger: o envio é iniciado por meio da chamada de Send() ([SWS_CM_00721], EXP_ARAComAPI §3 «Trigger::Send»), após o que o Communication Management distribui o sinal a todas as aplicações subscritas.
  • Cancelamento de registro: durante o desligamento ou quando não forem mais desejadas notificações de estado, UnsetSubscriptionStateChangeHandler() é chamado ([SWS_CM_01112]).

Diagrama de sequência: fluxo típico da transmissão de trigger com monitoramento de subscrição. Fontes: [SWS_CM_01110], [SWS_CM_01109], [SWS_CM_00721], SWS_CommunicationManagement §7.2.2.1.4.

Cenários de erro

O método Send() retorna um ara::core::Result<void>, por meio do qual são transportados eventuais erros de transmissão e de configuração ([SWS_CM_00721]):

  • ComErrc::kServiceNotOffered: ocorre quando a instância de serviço ainda não foi disponibilizada via OfferService() ([SWS_CM_00721]).
  • ComErrc::kMinimumSendIntervalViolationError: é retornado caso um intervalo mínimo de envio configurado (minimumSendInterval) entre transmissões consecutivas não tenha sido respeitado ([SWS_CM_00721]).
  • ComErrc::kCommunicationFailure: é reportado quando o envio do trigger falha localmente devido a um erro de rede subjacente ([SWS_CM_10517]).
  • Manipulador inválido (InvalidHandlerViolation): passar uma chamada de função (callable) inexistente ou vazia para SetSubscriptionStateChangeHandler() representa uma violação das condições contratuais da API ([SWS_CM_01110], [SWS_CM_01111]).

Este guia baseia-se exclusivamente nas especificações da AUTOSAR Adaptive Platform Release R25-11.

          A função SetSubscriptionStateChangeHandler serve, no lado do skeleton, para registrar uma função de callback para monitoramento de alterações de subscrição em um trigger [SWS_CM_01110]. O método pertence ao namespace <SI-Namespace>::skeleton::triggers::<Trigger> e é disponibilizado através do arquivo de cabeçalho <SiNamespaceDerivedDirectoryPath>/<SiShortname>_skeleton.h [SWS_CM_01110].
          

          Como parâmetro é passado um objeto de função chamável do tipo SubscriptionStateChangeHandler [SWS_CM_00311] [SWS_CM_01110]. A chamada é declarada como noexcept, não retorna nenhum valor e é especificada como segura contra exceções (exception safe) [SWS_CM_01110]. Se o callable de tratador passado não existir ou for nulo, o sistema relata uma InvalidHandlerViolation [SWS_CM_01110].
          

          O Communication Management chama a função de callback registrada assim que o status de subscrição do trigger muda [SWS_CM_01101]:
          

            

          • com o valor de status kSubscribed, assim que a quantidade de subscrições ativas para este trigger se torna maior que 0 [SWS_CM_01102],
            • 

          • com o valor de status kNotSubscribed no lado do skeleton, quando não houver mais assinaturas ativas [SWS_CM_01103].
            • 

          

          O tratador registrado pode ser sobrescrito em tempo de execução [SWS_CM_01101]. Se a execução do tratador tiver que ocorrer em um contexto de execução definido, está alternativamente disponível a variante de template sobrecarregada com um parâmetro ExecutorT&& [SWS_CM_01111].

              A função de template SetSubscriptionStateChangeHandler registra, no nível do skeleton para triggers ([SWS_CM_01111]), um tratador de callback para alterações do status de subscrição (ara::com::SubscriptionState). Além do parâmetro chamável handler, o método recebe um contexto de execução executor do tipo ExecutorT ([SWS_CM_01111]). A função não possui valor de retorno e é definida no escopo <SI-Namespace>::skeleton::triggers::<Trigger> ([SWS_CM_01111]).
              

              Em contraste com a função básica sem executor ([SWS_CM_01110]), esta assinatura garante que o callback seja executado em um contexto definido pelo usuário ([SWS_CM_01111]). Como na variante baseada em eventos conforme [SWS_CM_12008], a execução é presumivelmente delegada ao objeto executor fornecido, para controlar especificamente o threading dentro da aplicação skeleton.
