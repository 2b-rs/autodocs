Contexto

A classe ara::diag::DoIPTriggerVehicleAnnouncement [SWS_DM_00820] disponibiliza uma interface de programação na AUTOSAR Adaptive Platform (módulo diag), por meio da qual uma Adaptive Application pode iniciar o envio de mensagens de anúncio de veículo DoIP (Vehicle Announcement Messages).

De acordo com AUTOSAR_AP_SWS_Diagnostics p. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface», a responsabilidade primária pelo envio dessas mensagens recai diretamente sobre o Diagnostic Manager (DM). A norma prevê que o DM envie anúncios de veículo de forma autônoma com base nos cenários definidos na ISO 13400-2:

  • na inicialização da rede, como broadcast para outras unidades de controle eletrônico e gateways baseados em IP,
  • ao detectar um testador externo por meio de uma linha de ativação (Activation Line).

Embora o fluxo regular segundo a ISO 13400-2 preveja um processamento autônomo pelo DM e o disparo manual por uma Adaptive Application não esteja originalmente previsto ali (AUTOSAR_AP_SWS_Diagnostics p. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface»), a interface ara::diag::DoIPTriggerVehicleAnnouncement permite, ainda assim, o acionamento explícito por parte de uma aplicação. O DM atua, nesse caso, como executor que envia as mensagens conforme a ISO 13400-2 na interface de rede especificada [SWS_DM_00815].

Ciclo de vida

A instanciação e o gerenciamento de ciclo de vida de ara::diag::DoIPTriggerVehicleAnnouncement estão sob total responsabilidade do Diagnostic Manager:

  • Criação e destruição: o construtor padrão está declarado como excluído (DoIPTriggerVehicleAnnouncement() = delete) e protegido de forma privada [SWS_DM_02100]. Da mesma forma, o destrutor é privado e excluído (~DoIPTriggerVehicleAnnouncement() noexcept = delete) [SWS_DM_02101]. Ambos os métodos são implementados de forma específica pelo fabricante [SWS_DM_02100], [SWS_DM_02101]. Uma Adaptive Application não pode, portanto, instanciar suas próprias instâncias na stack ou na heap.
  • Obtenção de instâncias: o acesso à interface ocorre exclusivamente por meio do método de fábrica estático GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]. Este retorna um objeto do tipo ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>, que disponibiliza uma referência para o objeto gerenciado pelo DM.
  • Concorrência: tanto o método de fábrica GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] quanto o método TriggerVehicleAnnouncement() [SWS_DM_00822] são explicitamente especificados como não seguros para threads (not thread-safe). Se múltiplos threads de uma aplicação acessarem a interface, o chamador deverá assegurar a sincronização. Ambos os métodos são especificados como seguros contra exceções (exception safe) [SWS_DM_00821], [SWS_DM_00822].

Caminho de utilização

O fluxo típico para disparar um anúncio de veículo divide-se nas seguintes etapas:

  1. Solicitar referência de interface: a Adaptive Application chama a função estática ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821].
  2. Validar resultado: a aplicação verifica o ara::core::Result retornado quanto ao sucesso e desempacota o std::reference_wrapper.
  3. Disparar anúncio: por meio da referência obtida, a aplicação chama o método TriggerVehicleAnnouncement(networkInterfaceId) [SWS_DM_00822]. O parâmetro networkInterfaceId (tipo std::uint8_t) especifica a interface de rede de destino.
  4. Envio via DM: o Diagnostic Manager instrui o envio das mensagens de anúncio de acordo com a ISO 13400-2 na interface de rede especificada [SWS_DM_00815] e confirma a execução para a aplicação com ara::core::Result<void> [SWS_DM_00822].

Diagrama de sequência: padrão de interação para o disparo explícito de anúncios de veículo DoIP. Fontes: [SWS_DM_00821], [SWS_DM_00822], [SWS_DM_00815].

Cenários de erro

Ao chamar TriggerVehicleAnnouncement(), aplicam-se pré-condições específicas relativas à configuração de rede:

  • Conflito com interfaces controladas por linha de ativação: se a networkInterfaceId transmitida pertencer a uma configuração na qual a propriedade isActivationLineDependent = TRUE estiver definida, essa chamada de método representa um erro [SWS_DM_00822]. O motivo para isso é que o envio em tais interfaces, segundo [SWS_DM_00816], já ocorre de forma totalmente automática pelo DM assim que a linha de ativação sobe e um endereço IP é atribuído [SWS_DM_00822].
  • Ausência de códigos de erro padronizados: nem para GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] nem para TriggerVehicleAnnouncement() [SWS_DM_00822] existem códigos de erro específicos predefinidos na norma («This function does not specify any standardized errors»). Se, ainda assim, ocorrer um erro (como a transmissão de uma interface dependente de linha de ativação ou um erro interno), o ara::core::Result provavelmente transportará códigos de erro específicos do fabricante.

Este guia baseia-se na especificação AUTOSAR Adaptive Platform R25-11.
