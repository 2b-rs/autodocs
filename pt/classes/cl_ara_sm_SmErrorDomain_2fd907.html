Serve para a definição e resolução de códigos de erro, bem como exceções dentro do State Management.

A classe ara::sm::SmErrorDomain representa o domínio de erro específico do State Management e associa códigos de erro funcionais a mensagens de texto legíveis, bem como a exceções C++ ([SWS_SM_81241]). Em tempo de execução, ela permite, por meio de métodos thread-safe, a identificação do domínio, bem como a tradução de valores de erro individuais para registro em log e diagnóstico. Caso ocorra um erro grave, uma exceção tipada também pode ser lançada por meio da interface ([SWS_SM_81250]). Se as exceções C++ estiverem desativadas na toolchain, a lógica de exceções não estará disponível e os erros deverão, em vez disso, ser processados puramente com base em valores.

Contexto

A classe ara::sm::SmErrorDomain define o domínio de erro específico para o cluster funcional do State Management na Adaptive Platform ([SWS_SM_81241], SWS StateManagement §8.1.3 «Class: SmErrorDomain»). Como especialização da arquitetura geral de domínio de erros, ela herda de ara::core::ErrorDomain de acordo com as especificações de [SWS_CORE_90023]. Sua responsabilidade central consiste em encapsular semanticamente estados de erro do State Management, fornecer identificadores de erro padronizados e assegurar o mapeamento entre códigos de erro numéricos, textos de erro e tipos de exceção.

Entre os principais parceiros de interação estão componentes internos do State Management, que geram erros, bem como serviços de aplicação e de plataforma superiores, que recebem erros por meio de ara::core::ErrorCode. Por meio do alias de tipo público Errc, a classe faz referência à enumeração específica de domínio SmErrc ([SWS_SM_81245]). O alias de tipo Exception também aponta para a classe base de exceção associada SmException ([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 «Type Alias: Exception»).

Ciclo de vida

Instâncias de ara::sm::SmErrorDomain são criadas por meio do construtor padrão sem parâmetros ([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 «Default Constructor»). O construtor é declarado como noexcept e possui a classificação exception safe. Em ambientes de sistema típicos, uma instância de SmErrorDomain provavelmente deve existir de preferência como um objeto estático ou de longa vida útil, uma vez que domínios de erro são necessários em todo o processo no ecossistema AUTOSAR Adaptive para a interpretação de códigos de erro.

Quanto à concorrência, as funções essenciais da classe são especificadas para operação concorrente: os métodos Name() ([SWS_SM_81248]) e Message() ([SWS_SM_81249]) são classificados como thread-safe, bem como exception safe. Múltiplas threads de execução podem, portanto, consultar informações de erro em paralelo, sem que seja necessária uma sincronização externa.

Caminho de utilização

O caminho de uso regular compreende a identificação do domínio de erro, a resolução de códigos de erro em mensagens de diagnóstico legíveis e, opcionalmente, a transformação em uma exceção C++. Inicialmente, uma aplicação ou componente de plataforma pode obter o nome do domínio por meio de Name(); este retorna invariavelmente o identificador "Sm" ([SWS_SM_81248]).

Se ocorrer um erro no State Management, o respetivo código é transmitido via Message(errorCode) ([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 «Message»). A função retorna um ponteiro para a cadeia de carateres associada (const char*), fornecendo mensagens significativas aos sistemas de registo e diagnóstico. Se o subsistema chamador estiver concebido para um tratamento de erros baseado em exceções, ele passa o objeto de erro para ThrowAsException() ([SWS_SM_81250]), fazendo com que a exceção correspondente ao código de erro seja instanciada e lançada.

Diagrama de sequência: sequência típica na consulta de informações de erro e no disparo opcional de exceção. Fontes: [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

Cenários de erro

Os estados de erro geridos pelo domínio baseiam-se no tipo de enumeração SmErrc, ao qual é atribuído um alias através de Errc ([SWS_SM_81245]). As situações de erro manifestam-se quer como valores de retorno com base em ara::core::ErrorCode quer através de exceções do tipo Exception (SmException, [SWS_SM_81246]).

Ao chamar ThrowAsException(), o método é considerado, por conceção, not exception safe, visto que dispara ativamente a exceção associada ao código de erro ([SWS_SM_81250]). Uma pré-condição crítica para a disponibilidade deste método diz respeito à configuração da toolchain: de acordo com [SWS_CORE_10304], ThrowAsException() não participa na resolução de sobrecarga se as exceções de C++ estiverem desativadas na toolchain do compilador ([SWS_SM_81250]). Em configurações de sistema sem suporte a exceções, o tratamento de erros deve, por conseguinte, ser processado estritamente através de códigos de retorno.

função Message [SWS_SM_81249] Upstream: RS_AP_00119, RS_AP_00159

const char * Message (CodeType errorCode) const noexcept override;

Returns the message associated with the error code.

GERADO POR IA não revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 5c30b05c668e Procedência

A função-membro ara::sm::SmErrorDomain::Message serve para determinar de forma síncrona a mensagem textual de erro associada a um código de erro específico do domínio de erros do State Management [SWS_SM_81249]. Encontra-se declarada no ficheiro de cabeçalho ara/sm/sm_error_domain.h dentro do âmbito da classe ara::sm::SmErrorDomain e tem o estado DRAFT na especificação AUTOSAR_AP_SWS_StateManagement §8.1.3.2.2.1 «Message».

A interface possui os seguintes parâmetros e valores de retorno [SWS_SM_81249]:

  • Parâmetro: errorCode do tipo CodeType recebe o número de erro numérico para o qual a respetiva mensagem de texto é solicitada.
  • Valor de retorno: Um ponteiro do tipo const char * para a mensagem de erro atribuída ao código de erro fornecido.

Para a execução aplicam-se garantias rigorosas relativas a concorrência e tratamento de exceções: A função está especificada como thread-safe e exception safe, e declarada com o identificador noexcept [SWS_SM_81249]. Pode, assim, ser chamada em segurança a partir de quaisquer threads sem bloqueios sincronizadores ou blocos try-catch.

No âmbito da gestão de erros do AUTOSAR Adaptive, o método substitui a função virtual do domínio de erros base. Interpretação: Dado que o valor de retorno está definido como const char * sem interface de alocação, o ponteiro deverá tipicamente apontar para literais de string estáticos que permanecem válidos durante todo o tempo de execução do processo.

  Procedência
  

          

          

          usar
          

          
O construtor padrão SmErrorDomain() cria de forma síncrona uma instância do domínio de erro ara::sm::SmErrorDomain ([SWS_SM_81247]). A declaração encontra-se no arquivo de cabeçalho ara/sm/sm_error_domain.h. A chamada não necessita de parâmetros de passagem e retorna diretamente o objeto de domínio inicializado (SWS StateManagement §8.1.3.2.1.1 «Default Constructor»).

          

          Tratamento de erros
          

          
A função é provida do identificador noexcept e classificada como segura contra exceções (exception safe) ([SWS_SM_81247]). Durante a criação, não ocorrem códigos de erro e nenhuma exceção é lançada.

          

          Simultaneidade e restrições
          

          
A criação está especificada como thread-safe ([SWS_SM_81247]). Instâncias podem, portanto, ser criadas concorrentemente em ambientes multithreading sem a necessidade de mecanismos adicionais de sincronização. Não existem condições especiais de ordenação.

          

          Interação
          

          
O objeto criado pertence à classe ara::sm::SmErrorDomain ([SWS_SM_81241]), que está especificada de acordo com [SWS_CORE_90023]. Dentro do módulo State Management, o domínio de erro interage com os seguintes elementos:

          

            

          • Errc ([SWS_SM_81245]) e Exception ([SWS_SM_81246]) como sinônimos de tipo para códigos de erro (SmErrc) e tratamento de exceções (SmException).
            • 

          • Name() ([SWS_SM_81248]) fornece o nome do domínio "Sm".
            • 

          • Message() ([SWS_SM_81249]) traduz códigos de erro em descrições textuais.
            • 

          • ThrowAsException() ([SWS_SM_81250]) lança o código de erro como exceção, desde que exceções C++ estejam ativadas ([SWS_CORE_10304]).
            • 

          • GetSmDomain() ([SWS_SM_81251]) disponibiliza, alternativamente, uma instância global do domínio de erro.
