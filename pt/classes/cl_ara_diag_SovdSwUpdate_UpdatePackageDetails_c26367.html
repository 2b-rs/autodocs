Contexto

A estrutura de dados ara::diag::SovdSwUpdate::UpdatePackageDetails ([SWS_DM_01877], AUTOSAR_AP_SWS_Diagnostics §8.58.4 «Struct: UpdatePackageDetails») serve, dentro da AUTOSAR Adaptive Platform no módulo diag, como portador estruturado de informações para os metadados e parâmetros de execução de um pacote de atualização de software. Ela é declarada no cabeçalho #include "ara/diag/sovd_sw_update.h" e representa uma grandeza de interface essencial para fluxos de diagnóstico e atualização relacionados a software disponibilizados por meio do padrão ASAM SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01796]).

A integração arquitetural segue a divisão funcional de tarefas da atualização de software SOVD (AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»): como a lógica de negócios real para atualizações de software não é executada dentro do Functional Cluster Diagnostics, a implementação técnica reside primariamente na respectiva aplicação. A instância ara::diag::SovdSwUpdate::SovdSwUpdate do Diagnostic Server concentra-se no tratamento do protocolo SOVD subjacente de acordo com o ASAM SOVD ([SWS_DM_01796]). Nesse contexto, UpdatePackageDetails atua como um objeto de transferência padronizado com o qual a aplicação disponibiliza dados detalhados do pacote para o Diagnostic Server por meio da função de API ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»), permitindo que este atenda a clientes SOVD externos.

Diagrama de contexto: enquadramento de UpdatePackageDetails na interação entre cliente SOVD, Diagnostic Server e aplicação. Fontes: [SWS_DM_01796], [SWS_DM_01877], [SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API».

Ciclo de vida

Como estrutura de dados passiva (struct) [SWS_DM_01877], UpdatePackageDetails não possui máquina de estados própria e não controla fases de vida autônomas. A criação ocorre instanciada pela aplicação no momento de uma consulta concreta, momento em que as variáveis de membro públicas são preenchidas com os atributos estáticos e dinâmicos do pacote:

  • Identificação e denominação: O campo id ([SWS_DM_01878]) armazena o ID exclusivo do pacote. A designação name ([SWS_DM_01879]) especifica o nome do pacote, enquanto translation_id ([SWS_DM_01881]) disponibiliza uma chave para representações localizadas.
  • Informações de tamanho e execução: O tamanho do pacote em bytes é definido via size ([SWS_DM_01893]) como std::uint64_t. Variáveis de controle adicionais são a duração estimada de execução duration em segundos ([SWS_DM_01891], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 «duration») como ara::core::Optional<std::uint64_t>, bem como a sinalização automated ([SWS_DM_01882], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 «automated») como ara::core::Optional<bool>.
  • Pré-requisitos e atividades do usuário: Condições para a execução são transportadas em preconditions ([SWS_DM_01888]) juntamente com preconditions_translation_id ([SWS_DM_01889]), bem como execution_conditions ([SWS_DM_01890]). Ações operacionais necessárias são registradas pela aplicação em user_activity ([SWS_DM_01886]) e user_activity_translation_id ([SWS_DM_01887]). Orientações adicionais podem ser passadas por meio de notes ([SWS_DM_01884]) e notes_translation_id ([SWS_DM_01885]).
  • Relações de componentes e origem: Os componentes afetados pelo pacote são listados pelo vetor affected_components ([SWS_DM_01895], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 «affected_components»), enquanto updated_components ([SWS_DM_01894]) nomeia os componentes explicitamente atualizados. A origem do pacote de atualização é informada via origin ([SWS_DM_01883]).

Em relação à posse, a instância é criada pela aplicação e passada ao chamador por meio de valor de retorno. A destruição da instância ocorre automaticamente após sair do escopo, de acordo com a semântica padrão do C++ (RAII). A estrutura não oferece sincronização interna de threads; em acessos simultâneos de leitura ou escrita entre diferentes threads, a proteção da instância é de responsabilidade do componente de software chamador.

Caminho de utilização

O uso regular de UpdatePackageDetails ocorre no âmbito dos métodos padronizados de SOVD para consultar detalhes de atualização de software ([SWS_DM_01796]). Frequentemente, o cliente recupera previamente uma listagem de todas as atualizações disponíveis ([SWS_DM_01797]), antes de solicitar especificamente detalhes de pacotes.

O fluxo de chamada é estruturado da seguinte forma:

  1. Requisição pelo cliente SOVD: Um cliente de diagnóstico externo envia uma requisição dos detalhes de um determinado pacote de software para a Diagnostic Server Instance ([SWS_DM_01796]).
  2. Encaminhamento para a aplicação: O Diagnostic Server delega a determinação de detalhes via ara::diag::SovdSwUpdate::GetUpdatePackageDetails para a aplicação registrada ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»).
  3. Compilação dos dados: A aplicação determina os metadados do pacote, instancia UpdatePackageDetails ([SWS_DM_01877]) e preenche dados de identificação como id ([SWS_DM_01878]) e size ([SWS_DM_01893]), bem como dependências como affected_components ([SWS_DM_01895]).
  4. Retorno: Interpretação: a aplicação provavelmente retorna o objeto UpdatePackageDetails preenchido diretamente como resultado da função de GetUpdatePackageDetails para o Diagnostic Server.
  5. Resposta de protocolo: Interpretação: o Diagnostic Server provavelmente assume a serialização dos atributos C++ no formato de resposta padronizado do SOVD e o entrega ao cliente solicitante ([SWS_DM_01796]).
