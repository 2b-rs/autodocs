Gere direitos de diagnóstico dinâmicos, temporizadores de sessão e a revogação da autenticação de um cliente de diagnóstico.

A classe ara::diag::ClientAuthenticationHandle serve para a aplicação gerir uma sessão de autenticação ativa de um cliente de diagnóstico [SWS_DM_01206]. Através deste handle, a aplicação configura listas de acesso dinâmicas e renova os temporizadores de inatividade do cliente [SWS_DM_01213]. O objeto segue uma semântica de movimento estrita, sem possibilidade de cópia, e reporta erros caso a gestão de diagnóstico não esteja disponível através de DiagErrc::kServiceNotAvailable. Mediante a chamada de Revoke, os papéis atribuídos e os direitos adicionais podem ser revogados de forma controlada a qualquer momento.

Contexto

A classe de API ara::diag::ClientAuthenticationHandle está definida no ficheiro de cabeçalho ara/diag/client_authentication_handle.h [SWS_DM_01145]. Atua como objeto central de controlo, sendo disponibilizada a uma aplicação de diagnóstico pela instância do Diagnostic Server assim que um cliente é autenticado com sucesso ou os seus papéis padrão são temporariamente substituídos AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».

No arranque do sistema, um cliente encontra-se por padrão no estado kDeAuthenticated [SWS_DM_01205] com papéis padrão pré-configurados [SWS_DM_01204]. Se a aplicação chamar ara::diag::ClientAuthentication::Authenticate, o Diagnostic Server coloca o cliente no estado kAuthenticated e devolve um ara::diag::ClientAuthenticationHandle [SWS_DM_01206]. Da mesma forma, ao chamar ara::diag::ClientAuthentication::OverrideDefaultRoles para a adaptação temporária dos papéis, é gerado um tal handle [SWS_DM_01209]. Através do handle, a aplicação controla o estado de autenticação e a lista de acesso dinâmica (DynamicAccessList), a qual concede a um cliente autenticado direitos de acesso adicionais a recursos de diagnóstico para além do extrato de diagnóstico AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».

Diagrama de contexto: interação entre aplicação, ClientAuthenticationHandle e Diagnostic Server. Fontes: [SWS_DM_01206], [SWS_DM_01209], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»

Ciclo de vida

A instanciação de ara::diag::ClientAuthenticationHandle ocorre regularmente através de métodos de fábrica do Diagnostic Server no âmbito de Authenticate [SWS_DM_01206] ou OverrideDefaultRoles [SWS_DM_01209]. Complementarmente, a classe disponibiliza um construtor predefinido sem parâmetros [SWS_DM_01146]; presume-se que um objeto criado desta forma atue como um marcador de posição não vinculado até que lhe seja transferido um handle ativo por atribuição de movimento.

Relativamente à posse, a classe implementa uma semântica de movimento estrita: o construtor de movimento [SWS_DM_01148] e o operador de atribuição de movimento [SWS_DM_01149] estão definidos como noexcept = default. A cópia é completamente impedida, uma vez que o construtor de cópia [SWS_DM_01150] e o operador de atribuição de cópia [SWS_DM_01151] estão eliminados (=delete). A libertação da instância ocorre através do destrutor ~ClientAuthenticationHandle() [SWS_DM_01147].

No que diz respeito à concorrência, o construtor predefinido está especificado como seguro para threads (thread-safe) [SWS_DM_01146]. Em contrapartida, o destrutor [SWS_DM_01147], bem como todas as chamadas de métodos que alteram o estado, são indicados como não seguros para threads (not thread-safe) [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. O acesso concorrente ao mesmo handle requer, por conseguinte, sincronização do lado da aplicação.

Caminho de utilização

O fluxo típico em tempo de execução compreende a configuração de direitos dinâmicos, a manutenção da autorização e o encerramento controlado:

  1. Obter handle: A aplicação inicia a autenticação em ara::diag::ClientAuthentication e recebe a instância do handle [SWS_DM_01206].
  2. Definir ou expandir lista de acesso: Através do método Set, a aplicação substitui totalmente a lista de acesso dinâmica de uma conversação de diagnóstico [SWS_DM_01153], [SWS_DM_01213]. Como alternativa, Append anexa padrões de diagnóstico adicionais a uma lista de acesso existente [SWS_DM_01152] AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 «DynamicAccessList Creation and Update».
  3. Renovar atividade: Em caso de inatividade na sessão padrão, existe o risco de regressão automática para kDeAuthenticated [SWS_DM_01210] após expirar o timeout de inatividade. Ao chamar Refresh, a aplicação prolonga os temporizadores iniciados por Authenticate ou OverrideDefaultRoles [SWS_DM_01155] AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».
  4. Revogar permissões: Com Revoke, a aplicação desautentica explicitamente o cliente, elimina a respetiva DynamicAccessList e repõe os papéis padrão substituídos [SWS_DM_01154].

Diagrama de sequência: sequência para autenticação, gestão de direitos e revogação através do handle. Fontes: [SWS_DM_01206], [SWS_DM_01153], [SWS_DM_01155], [SWS_DM_01154]

Cenários de erro

Os métodos operacionais Set [SWS_DM_01153], Append [SWS_DM_01152], Refresh [SWS_DM_01155] e Revoke [SWS_DM_01154] devolvem respetivamente ara::core::Result<void> e estão declarados como noexcept, bem como seguros contra exceções (exception safe).

Se a comunicação ou a execução falhar devido ao facto de funcionalidades essenciais do Diagnostic Manager não estarem atualmente disponíveis, as chamadas fornecem o código de erro DiagErrc::kServiceNotAvailable [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. Neste caso, aplica-se uma semântica de rollback, de modo a que não permaneçam alterações parciais inconsistentes no estado de autenticação ou nas listas de acesso do cliente.

Baseia-se na especificação AUTOSAR Adaptive R25-11 da interface de diagnóstico.

O método Append da classe ara::diag::ClientAuthenticationHandle é utilizado por aplicações para anexar uma lista de acesso dinâmica (dynamicAccessList) à DynamicAccessList já existente de uma conversação de diagnóstico ativa [SWS_DM_01152]. A interface é disponibilizada por meio do cabeçalho ara/diag/client_authentication_handle.h AUTOSAR_AP_SWS_Diagnostics §8.6.1.1.3.1 «Append».

A chamada é executada de forma síncrona e está especificada como noexcept [SWS_DM_01152]. Como parâmetro de entrada, a função recebe uma DiagnosticServiceDynamicAccessList. O tipo de retorno ara::core::Result<void> sinaliza a conclusão bem-sucedida ou transporta, em caso de erro, o código de erro DiagErrc::kServiceNotAvailable [SWS_DM_01152]. Este último indica que funções essenciais do Diagnostic Management não estão disponíveis no momento. Para este caso de erro aplica-se uma semântica de rollback, de modo que o estado anterior da lista de acesso permaneça preservado [SWS_DM_01152].

Em termos de concorrência, a operação é considerada segura contra exceções (exception safe), mas está expressamente classificada como não segura para threads (not thread-safe) [SWS_DM_01152]. Em caso de acessos paralelos ao mesmo objeto handle, presume-se, portanto, que uma sincronização externa pela aplicação chamadora seja necessária.

                  O método Refresh da classe ara::diag::ClientAuthenticationHandle (arquivo de cabeçalho #include "ara/diag/client_authentication_handle.h") serve para que uma aplicação estenda temporizadores ativos de autenticação ou de papéis (AUTOSAR_AP_SWS_Diagnostics §8.6.1.1.3.2 «Refresh»). Ele reinicia o temporizador que foi previamente iniciado por Authenticate ou OverrideDefaultRoles. Caso ambos os métodos tenham sido chamados anteriormente, ambos os temporizadores são renovados simultaneamente pela chamada [SWS_DM_01155].
                  

                  A chamada síncrona (interpretação: retorno direto sem Future assíncrono) ocorre sem parâmetros em uma instância existente de ClientAuthenticationHandle, a qual a aplicação recebeu do Diagnostic Server após a conclusão bem-sucedida de Authenticate ou OverrideDefaultRoles (AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»). A função é declarada como noexcept e segura contra exceções (exception safe), porém especificada como não segura para threads (not thread-safe) [SWS_DM_01155]. Chamadas concorrentes na mesma instância devem, portanto, ser sincronizadas pelo chamador.
                  

                  Se a operação falhar, a função retorna o código de erro DiagErrc::kServiceNotAvailable via ara::core::Result<void> [SWS_DM_01155]. Isso indica, por meio de semântica de rollback, que a chamada não pôde ser executada porque funcionalidades essenciais do Diagnostic Management (DM) estão indisponíveis no momento [SWS_DM_01155].

                      ara::core::Result< void > Revoke () noexcept;
                      

                      This function is used by the application to de-authenticate a client, and also to clear the Dynamic AccessList and any overridden defaults.
                      

                      

                      

                      

                      

                      

                      

                      

                      
  GERADO POR IA
  não revisado
  Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 97421a5ce76e
  Procedência
  

                      

                      

                      
    O método síncrono Revoke da classe ara::diag::ClientAuthenticationHandle (SWS Diagnostics §8.6.1.1.3.3 «Revoke») serve para que aplicações desautentiquem um cliente de diagnóstico previamente autenticado, bem como descartem completamente sua lista de acesso dinâmica (DynamicAccessList) e funções padrão sobrepostas ([SWS_DM_01154], [SWS_DM_01216]).
  
                      
  
                      
    A função não possui parâmetros de passagem e retorna um ara::core::Result<void> ([SWS_DM_01154]). Em caso de sucesso, o status de autenticação do cliente é encerrado. Se uma funcionalidade essencial do Diagnostic Manager não estiver disponível no momento da chamada, a operação falha e fornece o erro DiagErrc::kServiceNotAvailable com semântica de rollback ([SWS_DM_01154]).
  
                      
  
                      
    Em relação à concorrência, a interface está especificada como segura contra exceções (exception safe), porém como não segura para threads (not thread-safe) ([SWS_DM_01154]). Interpretação: em caso de acessos concorrentes à mesma instância de handle a partir de múltiplas threads, presume-se, portanto, que a aplicação chamadora deva assegurar uma sincronização externa.
  
                      
  
                      
    No fluxo global, a instância de ClientAuthenticationHandle é disponibilizada à aplicação pela instância do servidor de diagnóstico após a autenticação bem-sucedida ou após a sobreposição de funções padrão (SWS Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»). Enquanto o handle ativo permite, além da revogação, também a substituição ([SWS_DM_01213]) ou extensão ([SWS_DM_01215]) da DynamicAccessList, Revoke encerra definitivamente essas permissões do cliente.

  Procedência
  

                          

                          

                          O método síncrono Set da classe ara::diag::ClientAuthenticationHandle ([SWS_DM_01153]) serve para uma aplicação definir ou substituir completamente a lista de acesso dinâmica (DynamicAccessList) para uma conversação de diagnóstico ou para um cliente autenticado no Diagnostic Server ([SWS_DM_01213]). O Diagnostic Manager mantém para cada cliente autenticado uma DynamicAccessList desse tipo, que pode conceder ao cliente direitos de acesso adicionais a recursos de diagnóstico além da configuração registrada no Diagnostic Extract (AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»).
                          

                          Ao utilizar, os seguintes aspectos são determinantes:
                          

                            

                          • Contexto de chamada e parâmetros: A função é chamada em uma instância de ara::diag::ClientAuthenticationHandle (declarada em #include "ara/diag/client_authentication_handle.h"). Tal instância de handle é disponibilizada à aplicação quando previamente ara::diag::ClientAuthentication::Authenticate ([SWS_DM_01206]) ou ara::diag::ClientAuthentication::OverrideDefaultRoles ([SWS_DM_01209]) foi concluído com sucesso. Como único parâmetro de passagem é transmitida a dynamicAccessList do tipo DiagnosticServiceDynamicAccessList, a qual define a nova lista de acesso ([SWS_DM_01153]).
                            • 

                          • Valor de retorno e tratamento de erros: O método está especificado como noexcept e retorna um ara::core::Result<void>. Ele trabalha com semântica de rollback: se a chamada não puder ser executada porque a funcionalidade essencial de DM não está disponível no momento, a chamada falha com o código de erro DiagErrc::kServiceNotAvailable ([SWS_DM_01153]). Quanto ao tratamento de exceções, o método é classificado como seguro contra exceções (exception safe).
                            • 

                          • Concorrência: A operação é explicitamente definida como não segura para threads (not thread-safe) ([SWS_DM_01153]). Se forem realizadas chamadas na mesma instância de handle de forma concorrente a partir de múltiplas threads, a sincronização necessária cabe à aplicação.
