Kontext

Die Template-Klasse ara::core::Array stellt in der Adaptive Platform eine standardkonforme Adaption von std::array bereit. Sie kapselt ein Array fester Größe N mit Elementen des Typs T und vermeidet dynamische Speicherallokationen zur Laufzeit. Als grundlegender sequenzieller Container dient ara::core::Array funktionalen Clustern sowie AUTOSAR-Anwendungen als typsichere Datenstruktur zur Übergabe von Nutzdaten mit statisch bekannter Elementanzahl.

Die Schnittstelle orientiert sich eng an den Vorgaben des C++-Standards, definiert jedoch spezifische Anpassungen für das AUTOSAR-Laufzeitumfeld. Dazu zählen typisierte Schnittstellen für Indizierung, Iteratoren sowie Speicherabfragen. Die Typaliase für Referenzen und Zeiger ([SWS_CORE_01210], [SWS_CORE_01211], [SWS_CORE_01217], [SWS_CORE_01218]), Indizes ([SWS_CORE_01214], [SWS_CORE_01215]) und vorwärts wie rückwärts gerichtete Iteratoren ([SWS_CORE_01212], [SWS_CORE_01213], [SWS_CORE_01219], [SWS_CORE_01220]) stellen die Interoperabilität mit Standardalgorithmen und generischen Schnittstellen sicher.

Lebenszyklus

Als Aggregattyp bindet ara::core::Array die enthaltenen Elemente direkt an die eigene Speicherrepräsentation. Die implizit deklarierten speziellen Elementfunktionen (wie Standard-, Kopier- und Verschiebekonstruktoren sowie Destruktoren) werden gemäß Spezifikation nicht erneut explizit deklariert, sondern folgen dem Standardverhalten von C++-Arrays. Die Lebensdauer aller N Elemente ist somit untrennbar an die Lebensdauer der Containerinstanz gekoppelt.

Die Dimensionierung wird zur Übersetzungszeit über den Template-Parameter N festgelegt. Methoden zur Größenabfrage wie size() ([SWS_CORE_01262]), max_size() ([SWS_CORE_01263]) und empty() ([SWS_CORE_01264]) sind als constexpr und noexcept deklariert. Ein Austausch des Inhalts zweier gleich dimensionierter Instanzen erfolgt über swap() ([SWS_CORE_01242]). Die Exception-Sicherheit von swap() hängt bedingt davon ab, ob der Elementtyp T über ara::core::is_nothrow_swappable<T>::value als nicht-werfend ausgewiesen ist ([SWS_CORE_01242]). Hinsichtlich Nebenläufigkeit bietet ara::core::Array keine interne Synchronisation; gleichzeitige schreibende Zugriffe auf dieselbe Instanz müssen anwendungsseitig abgesichert werden (Interpretation).

Nutzungspfad

Die typische Verwendung von ara::core::Array gliedert sich in Initialisierung, sequenzielle oder wahlfreie Datenverarbeitung und die Weitergabe an Low-Level-Schnittstellen:

  • Initialisierung und Befüllung: Der Container kann initial belegt oder über die Methode fill() ([SWS_CORE_01241]) homogen mit einer Kopie eines Werts beschrieben werden. Die Operation ist noexcept, sofern der Elementtyp zuweisungssicher ist (std::is_nothrow_copy_assignable<T>::value).
  • Wahlfreier und direkter Elementzugriff: Für performanten Zugriff ohne Laufzeitprüfung steht operator[] ([SWS_CORE_01265], [SWS_CORE_01266]) zur Verfügung. Die Randelemente können über front() ([SWS_CORE_01267], [SWS_CORE_01268]) und back() ([SWS_CORE_01269], [SWS_CORE_01270]) referenziert werden.
  • Iteratorkonforme Verarbeitung: Algorithmen können über Vorwärts-Iteratoren (begin() / end() gem. [SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]), konstante Iteratoren (cbegin() / cend() gem. [SWS_CORE_01258], [SWS_CORE_01259]) oder Rückwärts-Iteratoren (rbegin() / rend() / crbegin() / crend() gem. [SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261]) über die Sequenz iterieren.
  • C-API-Brücke: Über die Methode data() ([SWS_CORE_01271], [SWS_CORE_01272]) wird ein direkter Zeiger auf das zugrundeliegende zusammenhängende Speichersegment bereitgestellt, beispielsweise zur Übergabe an Treiber oder Serialisierungsroutinen.

Fehlerszenarien

Im Bereich der Fehlerbehandlung und Randwertabsicherung weicht ara::core::Array in wesentlichen Punkten vom ISO-C++-Standard ab, um AUTOSAR-spezifische Richtlinien zur Ausnahmesicherheit zu wahren:

Aufruf / Situation Bedingung Reaktion / Spezifikation
at(size_type n) n >= size() Auslösung einer IsoStdOutOfRangeViolation anstelle von std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]).
front() / back() empty() == true (d. h. N == 0) Der Aufruf an einem leeren Array führt zwingend zu einem Übersetzungszeitfehler (Compile-Time Error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
begin() Dereferenzierung empty() == true Das Dereferenzieren des zurückgegebenen Iterators bei einem leeren Array führt zu undefiniertem Verhalten ([SWS_CORE_01250], [SWS_CORE_01251]).
data() size() == 0 Rückgabe von nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
operator[] n >= size() Keine Bereichsprüfung zur Laufzeit; führt wie im C++-Standard zu undefiniertem Verhalten (Interpretation).

<h4>Kontext</h4>

<p>Als Aggregattyp bindet <code>ara::core::Array</code> die enthaltenen Elemente direkt an die eigene Speicherrepräsentation. Ein Austausch des Inhalts zweier gleich dimensionierter Instanzen erfolgt über <code>swap()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). Die Exception-Sicherheit von <code>swap()</code> hängt bedingt davon ab, ob der Elementtyp <code>T</code> über <code>ara::core::is_nothrow_swappable&lt;T&gt;::value</code> als nicht-werfend ausgewiesen ist (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). Hinsichtlich Nebenläufigkeit bietet <code>ara::core::Array</code> keine interne Synchronisation; gleichzeitige schreibende Zugriffe auf dieselbe Instanz müssen anwendungsseitig abgesichert werden (Interpretation).</p>

<h4>Nutzungspfad</h4>
<p>Die typische Verwendung von <code>ara::core::Array</code> gliedert sich in Initialisierung, sequenzielle oder wahlfreie Datenverarbeitung und die Weitergabe an Low-Level-Schnittstellen:</p>
<ul>
<li><strong>Initialisierung und Befüllung:</strong> Der Container kann initial belegt oder über die Methode <code>fill()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>) homogen mit einer Kopie eines Werts beschrieben werden. Die Operation ist <code>noexcept</code>, sofern der Elementtyp zuweisungssicher ist (<code>std::is_nothrow_copy_assignable&lt;T&gt;::value</code>).</li>
<li><strong>Wahlfreier und direkter Elementzugriff:</strong> Für performanten Zugriff ohne Laufzeitprüfung steht <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_CORE_01265" href="../spec/record.html?id=SWS_CORE_01265">[SWS_CORE_01265]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01266" href="../spec/record.html?id=SWS_CORE_01266">[SWS_CORE_01266]</a>) zur Verfügung. Die Randelemente können über <code>front()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>) und <code>back()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>) referenziert werden.</li>
<li><strong>Iteratorkonforme Verarbeitung:</strong> Algorithmen können über Vorwärts-Iteratoren (<code>begin()</code> / <code>end()</code> gem. <a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01252" href="../spec/record.html?id=SWS_CORE_01252">[SWS_CORE_01252]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01253" href="../spec/record.html?id=SWS_CORE_01253">[SWS_CORE_01253]</a>), konstante Iteratoren (<code>cbegin()</code> / <code>cend()</code> gem. <a class="spec-record-ref" data-req="SWS_CORE_01258" href="../spec/record.html?id=SWS_CORE_01258">[SWS_CORE_01258]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01259" href="../spec/record.html?id=SWS_CORE_01259">[SWS_CORE_01259]</a>) oder Rückwärts-Iteratoren (<code>rbegin()</code> / <code>rend()</code> / <code>crbegin()</code> / <code>crend()</code> gem. <a class="spec-record-ref" data-req="SWS_CORE_01254" href="../spec/record.html?id=SWS_CORE_01254">[SWS_CORE_01254]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01255" href="../spec/record.html?id=SWS_CORE_01255">[SWS_CORE_01255]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01256" href="../spec/record.html?id=SWS_CORE_01256">[SWS_CORE_01256]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01257" href="../spec/record.html?id=SWS_CORE_01257">[SWS_CORE_01257]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01260" href="../spec/record.html?id=SWS_CORE_01260">[SWS_CORE_01260]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01261" href="../spec/record.html?id=SWS_CORE_01261">[SWS_CORE_01261]</a>) über die Sequenz iterieren.</li>
<li><strong>C-API-Brücke:</strong> Über die Methode <code>data()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>) wird ein direkter Zeiger auf das zugrundeliegende zusammenhängende Speichersegment bereitgestellt, beispielsweise zur Übergabe an Treiber oder Serialisierungsroutinen.</li>
</ul>
