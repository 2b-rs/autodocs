Disponibiliza um contentor sequencial de tamanho fixo com verificação de limites segura quanto aos tipos para o AUTOSAR Adaptive.

A classe template ara::core::Array serve como contentor sequencial de tamanho fixo para elementos do tipo T e adapta o comportamento de std::array para aplicações da AUTOSAR Adaptive Platform. Os chamadores inicializam o contentor com um número fixo de elementos, manipulam conteúdos através de métodos como fill() e acedem opcionalmente sem verificação através de operator[] ou com verificação de limites através de at() a [SWS_CORE_01273]. Como restrição relevante para a segurança, uma ultrapassagem de limites em at() desencadeia a violação específica IsoStdOutOfRangeViolation em vez de std::out_of_range, enquanto chamadas a front() ou back() em instâncias vazias falham logo em tempo de compilação [SWS_CORE_01267].

Contexto

A classe template ara::core::Array encapsula um contentor sequencial com tamanho N estaticamente definido em tempo de compilação para elementos do tipo T. Implementa o tipo normalizado std::array no módulo core da AUTOSAR Adaptive Platform e representa uma abstração segura quanto aos tipos para blocos contíguos de memória. Ao disponibilizar aliases de tipo normalizados como value_type ([SWS_CORE_01216]), size_type ([SWS_CORE_01214]), difference_type ([SWS_CORE_01215]), bem como tipos de ponteiro ([SWS_CORE_01217], [SWS_CORE_01218]) e tipos de referência ([SWS_CORE_01210], [SWS_CORE_01211]), a classe atua como parceiro de interação interoperável para algoritmos C++ genéricos e fluxos de dados internos da plataforma.

Ciclo de vida

A criação e destruição de uma instância de Array segue as regras padrão para tipos agregados e de valor: as funções-membro especiais implicitamente declaradas da norma ISO C++ são utilizadas e não são redeclaradas separadamente. O array possui os seus elementos diretamente inline na mesma região de memória. A vida útil dos elementos contidos está, consequentemente, inseparavelmente associada à vida útil do objeto de array que os envolve; presumivelmente, não ocorre qualquer alocação dinâmica na memória livre (heap), o que garante um comportamento temporal e de memória determinístico.

O contentor encontra-se sempre num estado válido e gere exatamente N elementos. A capacidade do array para receber elementos, ou se se trata de um caso especial com N = 0, pode ser avaliada através de empty() ([SWS_CORE_01264]), size() ([SWS_CORE_01262]) e max_size() ([SWS_CORE_01263]). No que diz respeito à concorrência, é provável que acessos de leitura concorrentes sejam seguros sem sincronização, enquanto modificações de escrita paralelas requerem uma coordenação externa pelo chamador.

Caminho de utilização

Em casos de utilização típicos, ara::core::Array passa por uma sequência de inicialização, preenchimento de elementos, acesso aleatório ou sequencial e, se aplicável, troca de conteúdo:

  • Inicialização e preenchimento: Todo o buffer de dados pode ser uniformemente preenchido com um valor predefinido através de fill() ([SWS_CORE_01241]).
  • Acesso aleatório: Para acessos de elevado desempenho, está disponível o operador de índice não verificado operator[] ([SWS_CORE_01265], [SWS_CORE_01266]). Quando é necessária uma verificação de limites, recorre-se a at() ([SWS_CORE_01273], [SWS_CORE_01274]).
  • Elementos de extremidade: O acesso direto ao primeiro e ao último elemento é realizado através de front() ([SWS_CORE_01267], [SWS_CORE_01268]) e back() ([SWS_CORE_01269], [SWS_CORE_01270]).
  • Iteração: A travessia do contentor é efetuada para a frente através de begin() e end() ([SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]) ou através de iteradores constantes como cbegin() e cend() ([SWS_CORE_01258], [SWS_CORE_01259]). Os tipos de iterador estão definidos como ponteiros elementares T* ou const T* ([SWS_CORE_01212], [SWS_CORE_01213]). Para travessias inversas, estão disponíveis rbegin(), rend(), crbegin() e crend() ([SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261], [SWS_CORE_01219], [SWS_CORE_01220]).
  • Acesso por ponteiro e troca: A região de memória subjacente pode ser transmitida como ponteiro através de data() ([SWS_CORE_01271], [SWS_CORE_01272]). Dois arrays com as mesmas dimensões podem ser trocados através de swap() ([SWS_CORE_01242]).

Diagrama de sequência: sequência típica de chamadas para preenchimento, verificação de limites e troca de instâncias de Array. Fontes: [SWS_CORE_01241], [SWS_CORE_01273], [SWS_CORE_01242].

Cenários de erro

A especificação define pré-condições e pós-condições rigorosas para situações de limite e de erro:

  • Violação de limites no acesso indexado: Se em at() o índice n estiver fora dos limites do array (n >= size()), é acionado IsoStdOutOfRangeViolation em vez da exceção padrão do C++ std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]). Ambas as sobrecargas estão declaradas com noexcept.
  • Acesso a instâncias vazias: A chamada de front() ou back() num array vazio (empty() == true, ou seja, N = 0) resulta obrigatoriamente num erro em tempo de compilação (compile-time error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
  • Comportamento indefinido com iteradores: A desreferenciação do iterador retornado por begin() num array vazio constitui comportamento indefinido ([SWS_CORE_01250], [SWS_CORE_01251]).
  • Caso especial de obtenção de ponteiro: Se o tamanho do array for 0, a função-membro data() retorna obrigatoriamente nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
  • Segurança condicional contra exceções: A operação swap() só é noexcept se a condição relacionada com o tipo ara::core::is_nothrow_swappable<T>::value for satisfeita ([SWS_CORE_01242]). Do mesmo modo, a propriedade noexcept de fill() é determinada através de std::is_nothrow_copy_assignable<T>::value ([SWS_CORE_01241]).

A função de membro at da classe ara::core::Array permite o acesso síncrono de leitura e escrita a um elemento do array na posição especificada n com verificação implícita de limites [SWS_CORE_01273]. A função retorna uma referência modificável (reference) para o elemento endereçado e pode ser avaliada em tempo de compilação (constexpr) [SWS_CORE_01273].

Em caso de erro, quando o índice solicitado atinge ou excede o limite do contêiner (n >= size()), o comportamento diverge do contêiner C++ padrão std::array: em vez de uma exceção do tipo std::out_of_range, é desencadeada uma IsoStdOutOfRangeViolation [SWS_CORE_01273]. Como a assinatura está declarada como noexcept e classificada como segura contra exceções, não são lançadas exceções C++ regulares [SWS_CORE_01273]. Interpretação: O desencadeamento desta violação deverá conduzir diretamente, em um contexto noexcept, ao término controlado da execução.

Para instâncias protegidas contra escrita, existe a sobrecarga constante complementar [SWS_CORE_01274], a qual fornece uma referência constante. A mesma semântica de erro por meio de IsoStdOutOfRangeViolation é aplicada consistentemente também em contêineres relacionados, como ara::core::Vector ([SWS_CORE_01354], [SWS_CORE_01355]), bem como ara::core::StringView [SWS_CORE_02133].

      A função-membro at da classe ara::core::Array (cabeçalho #include "ara/core/array.h") permite o acesso indexado de leitura a um elemento de array individual [SWS_CORE_01274]. Ela recebe o índice n do tipo size_type e retorna uma referência constante (const_reference) ao elemento endereçado [SWS_CORE_01274]. Pela declaração como constexpr e noexcept, a função pode ser utilizada para expressões constantes em tempo de compilação e está especificada como segura contra exceções (exception safe) [SWS_CORE_01274]. Para acessos modificadores, está disponível a sobrecarga não constante [SWS_CORE_01273].

Como a função está qualificada com noexcept, o relato desta violação resulta presumivelmente na terminação do programa por meio do mecanismo abort de toda a plataforma, para o qual manipuladores personalizados podem ser registrados [SWS_CORE_00054].
      

      Este padrão de tratamento de erros também é aplicado uniformemente em outros contêineres de ara::core, como em ara::core::Vector [SWS_CORE_01354], ara::core::Map [SWS_CORE_01456] e ara::core::StringView [SWS_CORE_02133].                                                               usar

O comportamento orienta-se pelo uso em [array], de modo que presume-se que todos os elementos sejam definidos de forma síncrona através de atribuição por cópia para o valor u.
                                                              

                                                              Tratamento de erros e segurança de exceções
                                                              

                                                              Segundo a especificação, a função é classificada como condicionalmente segura contra exceções (conditionally exception safe) [SWS_CORE_01241]. Isto é implementado através do identificador noexcept(std::is_nothrow_copy_assignable<T>::value). Não estão previstos códigos de erro específicos, um estado de erro como valor de retorno ou mensagens DET/DEM; exceções ocorrem apenas se a atribuição por cópia do tipo T falhar e não estiver declarada como noexcept.
