classe ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

Finalidade de uso

Para chamadas síncronas, ara::core::Result<T,E> encapsula um valor do tipo T ou um erro do tipo E; E deve ser ara::core::ErrorCode. O tipo, portanto, oferece suporte ao tratamento de erros sem exceções. [SWS_CORE_00701] [SWS_CORE_10600]

Ciclo de vida da geração &

Um resultado pode ser gerado a partir de valor ou erro, bem como via FromValue() e FromError(). As operações de copiar e mover estão disponíveis e condicionais noexcept; a trivialidade do destruidor depende de T e E. Interação com outras aulas

HasValue(), Value(), Error(), Ok() e Err() permitem acesso a status e conteúdo. Bind() transforma um valor contido em um novo resultado usando um chamável, enquanto Resolve() chama uma função em caso de erro. Restrições & tratamento de erros

O acesso a erros sem erro incluído ou a um valor sem valor incluído é definido como uma violação. ValueOrThrow() pode ser acionado e é a única função de resultado isenta de uso sem inicialização ara::core. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

Papel no caminho de erro sem exceções

Para erros recuperáveis, as interfaces devem utilizar ara::core::Result ou ara::core::Future; o tipo de erro Result está definido como ara::core::ErrorCode. RS General §4.1.2 «Error handling» EXP InterfacesGuidelines §3.1.2 «Result»

No acesso sem exceção, o chamador verifica HasValue() e depois lê Value() ou Error(). Esses observadores podem ser usados ​​sem C++ exceptions; ValueOrThrow(), por outro lado, é a transição explícita para um caminho baseado em exceções. EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result» RS General §4.1.3 «The use of noexcept»

Diagrama de atividades: O fluxo livre de exceções usual ramifica para valor ou erro após HasValue(); ValueOrThrow() é o caminho de exceção exibido opcionalmente. Fontes: EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result».

Núcleo normativo: valor ou erro

A especificação Core mapeia Result para o modelo de tratamento de erros: para erros recuperáveis, as APIs devem retornar Result ou Future. Result separa assim o caminho do valor normal de um erro transportado como um valor de dados. SWS Core §7.2 «Error handling» SWS Core §7.2.5.4 «Result»
