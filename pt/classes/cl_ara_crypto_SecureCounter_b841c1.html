Disponibiliza um contador de segurança de 128 bits a partir de dois valores de 64 bits para os bits de ordem inferior e superior.

A estrutura ara::crypto::SecureCounter serve no módulo crypto como um contador de segurança de 128 bits, que consiste em dois inteiros de 64 bits para os bits menos significativos ([SWS_CRYPT_30002]) e os bits mais significativos ([SWS_CRYPT_30003]). Componentes chamadores utilizam este tipo de dados para representar estados de contagem robustos, sendo que incrementos e lógicas de transporte (carry) entre as subpalavras devem ser controlados manualmente. Como um tipo de valor puro, a estrutura não oferece sincronização interna, razão pela qual acessos paralelos em ambientes multithreading devem obrigatoriamente ser coordenados externamente.

Contexto

A estrutura ara::crypto::SecureCounter atua dentro do módulo crypto da AUTOSAR Adaptive Platform como um tipo de dados fundamental para a representação de um contador criptográfico de 128 bits de largura. Definida no arquivo de cabeçalho ara/crypto/common/base_id_types.h, a estrutura de dados é composta por dois inteiros de 64 bits do tipo std::uint64_t: o elemento de dados mLSQW para os 64 bits menos significativos de acordo com [SWS_CRYPT_30002], bem como o elemento de dados mMSQW para os 64 bits mais significativos de acordo com [SWS_CRYPT_30003]. Em arquiteturas de segurança, valores de contagem dessa ordem de grandeza servem para assegurar a atualidade temporal das mensagens e repelir eficazmente ataques de repetição (replay attacks). Interpretação: Como um tipo de dados padronizado, a estrutura provavelmente deve servir primariamente como formato de interface e de armazenamento para contadores monótonos ou números de sequência que são trocados por protocolos criptográficos, drivers e componentes de segurança próximos ao hardware. Como a especificação declara ara::crypto::SecureCounter como um contêiner puro de dados sem vinculação algorítmica direta, as camadas superiores interagem diretamente com ambos os membros parciais para verificar, persistir ou incorporar estados de contagem em mensagens de protocolo.

Ciclo de vida

Como uma estrutura clássica de C++ (struct), ara::crypto::SecureCounter está sujeita a um ciclo de vida leve, sem gerenciamento dinâmico de memória ou lógica de gerenciamento com estado. A instanciação ocorre usualmente de forma direta na pilha (stack) como um tipo de valor local ou incorporada como um elemento de campo em contextos superiores, tais como cabeçalhos de eventos de segurança ou descritores de sessão criptográfica. Presumivelmente, a estrutura, como um simples contêiner de dados, exibe uma semântica de valor regular de C++ com comportamento implícito de cópia e atribuição, mas não oferece mecanismos internos de sincronização para acesso concorrente. Para os desenvolvedores, isso significa que acessos simultâneos de leitura e escrita a partir de threads diferentes devem ser protegidos por primitivas externas de sincronização a fim de evitar inconsistências de dados em atualizações do contador. O ciclo de vida de uma instância termina automaticamente ao sair do respectivo escopo, não sendo necessárias liberações ou limpezas explícitas.

Caminho de utilização

O caminho típico de uso engloba a inicialização, o incremento passo a passo, bem como a leitura do valor combinado do contador de 128 bits por meio de ambos os componentes estruturais. Um chamador instancia inicialmente a estrutura e atribui os estados iniciais do contador à subpalavra de ordem inferior mLSQW ([SWS_CRYPT_30002]) e à subpalavra de ordem superior mMSQW ([SWS_CRYPT_30003]). Em operações contínuas de contagem, incrementa-se primariamente a palavra de ordem inferior mLSQW. Caso mLSQW atinja o valor máximo da faixa de 64 bits, ocorre um transporte aritmético (carry) para a palavra de ordem superior mMSQW, a qual é incrementada em um. Interpretação: As operações aritméticas, como incremento e tratamento de transporte, provavelmente devem ser implementadas no lado do chamador, já que a especificação não declara funções-membro próprias para ara::crypto::SecureCounter. Na transmissão ou persistência, ambos os membros de 64 bits são serializados de maneira estruturada, devendo-se atentar para uma ordem consistente de bytes e palavras a fim de excluir interpretações errôneas do valor total no lado do receptor.

Cenários de erro

Como ara::crypto::SecureCounter representa uma estrutura de dados pura sem métodos próprios, a estrutura não lança exceções em operações nem retorna especificações de erro ou códigos de erro do tipo ara::core::ErrorCode. Cenários de erro, portanto, não se originam dentro da própria estrutura, mas sim pelo tratamento incorreto de ambas as subpalavras nas camadas de software chamadoras. Um cenário crítico de erro é o overflow aritmético despercebido do contador total, quando tanto mLSQW ([SWS_CRYPT_30002]) quanto mMSQW ([SWS_CRYPT_30003]) esgotam suas faixas de valores máximas e retornam a zero, o que pode levar a brechas de segurança em mecanismos de proteção contra repetição. Outras violações de pré- e pós-condições ocorrem quando o transporte de mLSQW para mMSQW é omitido em atualizações ou quando valores indefinidos de memória entram nos cálculos em caso de inicialização incompleta. Componentes chamadores devem, portanto, assegurar antes do processamento posterior que ambos os elementos de dados estejam inicializados de forma consistente e que as lógicas de transporte estejam implementadas sem erros.
