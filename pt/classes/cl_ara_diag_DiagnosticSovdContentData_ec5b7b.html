Encapsula elementos de conteúdo e parâmetros de resultado para serviços de diagnóstico SOVD padronizados e execuções de operações.

A estrutura ara::diag::DiagnosticSovdContentData serve como contêiner de dados padronizado para o encapsulamento de conteúdos de diagnóstico para serviços SOVD no AUTOSAR Adaptive ([SWS_DM_02385]). Ela mantém os dados úteis em um vetor público de elementos de conteúdo ([SWS_DM_02386]), a partir dos quais o Diagnostic Management gera o atributo SOVD parameters em retornos de operações e de status. Como um objeto puro de transferência de valores, a estrutura não oferece sincronização interna de threads, razão pela qual modificações concorrentes devem ser protegidas internamente na aplicação.

Contexto

A estrutura de dados ara::diag::DiagnosticSovdContentData faz parte do módulo de diagnóstico (diag) da AUTOSAR Adaptive Platform e está declarada no cabeçalho ara/diag/diagnostic_sovd_content_data.h (AUTOSAR_AP_SWS_Diagnostics §8.59 «Header: ara/diag/diagnostic_sovd_content_data.h», [SWS_DM_02385]). Ela funciona como um portador de dados padronizado para o encapsulamento de conteúdos de diagnóstico no diagnóstico veicular orientado a serviços segundo a ASAM SOVD.

Dentro da plataforma, a estrutura faz a mediação entre o servidor de diagnóstico (Diagnostic Management, DM) e os provedores de serviços de uma Adaptive Application ([SWS_DM_01396], [SWS_DM_02174]). Se uma operação ou consulta de status for disparada por um cliente SOVD externo, o DM delega a chamada ao componente de software implementador. Os dados de saída gerados são armazenados pela aplicação em uma instância de DiagnosticSovdContentData ([SWS_DM_02386]). Em seguida, o DM transfere esses conteúdos para o corpo da resposta SOVD, especificamente para o atributo padronizado parameters ([SWS_DM_02176], [SWS_DM_02181]).

Diagrama de contexto: incorporação de DiagnosticSovdContentData no intercâmbio de dados entre cliente SOVD, Diagnostic Management e provedor de serviços de diagnóstico. Fontes: [SWS_DM_01396], [SWS_DM_02174], [SWS_DM_02176], [SWS_DM_02385], [SWS_DM_02386].

Ciclo de vida

A definição como struct C++ (AUTOSAR_AP_SWS_Diagnostics §8.59.1.1 «Public Member Variables», [SWS_DM_02385]) atribui a DiagnosticSovdContentData o papel de um contêiner de dados. A estrutura possui a variável-membro pública elements do tipo ara::core::Vector<DiagnosticSovdContentElementData> ([SWS_DM_02386]), na qual os elementos de conteúdo individuais são gerenciados dinamicamente.

A criação da instância ocorre tipicamente de forma local dentro dos métodos do provedor de serviço, assim que dados de diagnóstico são reunidos para um retorno. Em interfaces assíncronas como Read (AUTOSAR_AP_SWS_Diagnostics §8.x «Read»), o objeto é encapsulado em um ara::core::Future<DiagnosticSovdContentData>. Interpretação: aqui a estrutura deve passar para a posse do chamador por passagem por valor ou semântica de movimento (move semantics), de modo que seu tempo de vida esteja vinculado ao objeto Future de processamento.

No que diz respeito à concorrência, a estrutura não contém primitivas internas de sincronização. Interpretação: como se trata de um objeto puro de transferência de valor (Value Object), supõe-se que não exista proteção interna de threads; acessos concorrentes à mesma instância precisam, portanto, ser sincronizados pela lógica da aplicação chamadora. A destruição da instância ocorre automaticamente ao sair do escopo do contexto de gerenciamento.

Caminho de utilização

O caminho primário de utilização de DiagnosticSovdContentData reside na disponibilização de dados úteis em execuções síncronas de operações, bem como em consultas de status no framework SOVD:

  1. Um cliente SOVD externo envia ao veículo uma solicitação para iniciar uma operação de acordo com a ASAM SOVD ([SWS_DM_01396]).
  2. Após a validação das condições de contorno, o Diagnostic Management delega a execução à operação responsável através de ara::diag::GenericDiagnosticSovdOperation::StartExecution ([SWS_DM_02174]).
  3. A aplicação de serviço executa a operação de diagnóstico, instancia DiagnosticSovdContentData e preenche o membro elements com os dados dos elementos gerados ([SWS_DM_02386]).
  4. O objeto é transferido ao Diagnostic Management no âmbito do valor de retorno para execuções síncronas ([SWS_DM_02176]).
  5. O Diagnostic Management lê os valores de DiagnosticSovdContentData, transfere-os para o atributo parameters do corpo de resposta SOVD e envia a resposta ao cliente ([SWS_DM_02176]).

Um caminho análogo aplica-se à consulta de status através de SovdOperationExecution::GetStatus ([SWS_DM_02180]), na qual o atributo parameters também é derivado do DiagnosticSovdContentData passado ([SWS_DM_02181]). Da mesma forma, os provedores de conteúdo utilizam a mesma estrutura como tipo de retorno através de Read (AUTOSAR_AP_SWS_Diagnostics §8.x «Read»).
