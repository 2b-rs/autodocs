Encapsula códigos de erro das interfaces do IdsM como exceção C++ para tratamento estruturado de erros em aplicações.

A classe ara::idsm::IdsmException serve como classe de exceção C++ padronizada para a representação de erros das interfaces de programação do IdsM [SWS_AIDSM_10704]. Deriva de ara::core::Exception e encapsula um código de erro específico para a análise de causas. A instanciação ocorre através de um construtor explícito com um ara::core::ErrorCode, que é garantido como thread-safe e noexcept [SWS_AIDSM_10705]. Assim, a classe possibilita um tratamento de exceções determinístico e seguro em fluxos com falha do IdsM.

Contexto

A classe ara::idsm::IdsmException atua como classe de exceção dedicada para a sinalização e o tratamento de erros das interfaces de programação do Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10704]. Está definida no cabeçalho ara/idsm/idsm_error_domain.h e deriva publicamente da classe base ara::core::Exception [SWS_AIDSM_10704]. Na AUTOSAR Adaptive Platform, a classe interage primariamente com clusters funcionais utilizadores, bem como com as interfaces do módulo IdsM. Oferece aos programadores um mecanismo padronizado de exceções em C++ para capturar estados de erro de forma estruturada, em vez de propagar mensagens de erro exclusivamente através de valores de retorno.

Ciclo de vida

A instanciação de ara::idsm::IdsmException ocorre através de um construtor explícito que exige a transmissão de um ara::core::ErrorCode [SWS_AIDSM_10705]. Este construtor é declarado com o especificador noexcept, garantindo que não sejam lançadas outras exceções durante a construção do objeto de exceção [SWS_AIDSM_10705]. No que concerne à concorrência, a construção é expressamente especificada como segura para threads (thread-safe) [SWS_AIDSM_10705], de modo que os objetos de exceção também possam ser instanciados com segurança em contextos de execução multithreaded sem sincronização adicional.

Como objeto de exceção, IdsmException está sujeito à semântica de valor típica de C++. A criação tem lugar imediatamente após a deteção de uma condição de erro ou ao desempacotar um resultado de operação com falha. O tempo de vida está associado à avaliação no respetivo bloco catch; após a conclusão deste, o objeto de exceção é destruído automaticamente pelo sistema de runtime.

Caminho de utilização

A utilização típica da classe ocorre no âmbito de chamadas síncronas de serviço do IdsM. Uma aplicação chama uma função do módulo idsm. Se o ambiente de execução do IdsM detetar uma operação inválida ou um erro interno, gera um correspondente ara::core::ErrorCode e instancia com ele uma ara::idsm::IdsmException [SWS_AIDSM_10705]. Esta exceção é lançada e interrompe o fluxo de controlo regular [SWS_AIDSM_10704].

A aplicação chamadora captura o objeto especificamente como ara::idsm::IdsmException ou geralmente como ara::core::Exception. No manipulador de exceções, o código de erro encapsulado pode ser extraído e avaliado para registo de diagnóstico, estratégias de contingência (fallback) ou reinícios determinísticos.

Diagrama de sequência: fluxo típico de tratamento de erros com IdsmException numa chamada de API. Fontes: [SWS_AIDSM_10704], [SWS_AIDSM_10705]

Cenários de erro

A classe ara::idsm::IdsmException serve para a representação de erros de API do IdsM e é utilizada quando chamadas de função falham e este estado é reportado através do caminho de exceção [SWS_AIDSM_10704]. Uma pré-condição essencial para a criação é a presença de um objeto ara::core::ErrorCode válido que descreva precisamente a causa do erro [SWS_AIDSM_10705].

Um estado de erro secundário durante a criação do objeto é excluído pela garantia noexcept do construtor [SWS_AIDSM_10705]. Deste modo, evita-se que, em caminhos de tratamento de erro já críticos, seja provocada uma interrupção inesperada do programa via std::terminate. A pós-condição da chamada do construtor é um objeto de exceção inicializado que mantém o código de erro inalterado para diagnóstico adicional.

Simultaneidade e tratamento de erros

O construtor de IdsmException é provido com o identificador noexcept, de modo que na própria instanciação do objeto de exceção é garantido que nenhuma outra exceção seja disparada [SWS_AIDSM_10705]. Além disso, o construtor está especificado como thread-safe (thread-safe), o que protege a criação de objetos de exceção em contextos de execução paralelos ou assíncronos [SWS_AIDSM_10705].
