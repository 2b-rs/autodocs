Recebe eventos de segurança qualificados do IdsM por meio de uma P-Port modelada e os encaminha para callbacks.

A classe abstrata possibilita a recepção de eventos de segurança qualificados a partir do IdsM através de uma PPort modelada [SWS_AIDSM_10800]. As aplicações derivam uma classe receptora própria, instanciam-na com um Instance-Specifier e ativam a entrega de eventos via Offer() [SWS_AIDSM_10801]. Os eventos recebidos são acolhidos por meio de métodos de callback abstratos com dados contextuais e temporais opcionais. Como métodos essenciais de estado e de callback não são seguros para threads, a instância necessita de um gerenciamento coordenado do ciclo de vida.

Contexto

A classe ara::idsm::QualifiedEventsReceiver representa, no módulo idsm da AUTOSAR Adaptive Platform, a interface funcional para a recepção de eventos de segurança qualificados (Qualified Security Events, QSEv) [SWS_AIDSM_10800]. Ela serve como endpoint do lado da aplicação para uma Provided-Port (PPort) modelada no design de software [SWS_AIDSM_10801].

O conceito baseia-se no princípio de uma classe base abstrata: ara::idsm::QualifiedEventsReceiver declara métodos de callback puramente virtuais [SWS_AIDSM_10807], [SWS_AIDSM_10810]. Os parceiros de interação essenciais são a aplicação adaptativa, que implementa uma subclasse especializada, bem como o Intrusion Detection System Manager (IdsM), que detecta eventos de segurança qualificados e os encaminha à instância por meio da PPort.

Ciclo de vida

A criação de um receptor ocorre por meio da instanciação de uma classe derivada de QualifiedEventsReceiver com a especificação de um ara::core::InstanceSpecifier, que referencia a PPort modelada [SWS_AIDSM_10801]. Este construtor parametrizado é especificado como seguro para threads (thread-safe) [SWS_AIDSM_10801].

Em relação à semântica de posse e de valor, a classe foi projetada estritamente como apenas de movimentação (move-only). Tanto o construtor de cópia [SWS_AIDSM_10804] quanto o operador de atribuição por cópia [SWS_AIDSM_10806] estão excluídos (= delete). No entanto, uma transferência de propriedade é possível: o construtor de movimentação foi implementado como seguro para threads [SWS_AIDSM_10803], enquanto o operador de atribuição por movimentação não é seguro para threads (not thread-safe) [SWS_AIDSM_10805].

O ciclo de vida funcional subdivide-se em duas fases principais:

  • Disponibilização: imediatamente após a instanciação, ainda não são entregues eventos. Apenas a chamada de Offer() libera o aceite de eventos e autoriza chamadas dos métodos de callback pelo IdsM [SWS_AIDSM_10808].
  • Desativação: através do método StopOffer(), impede-se a recepção de outros eventos [SWS_AIDSM_10809].

A destruição ocorre por meio do destrutor virtual ~QualifiedEventsReceiver() [SWS_AIDSM_10802]. Como o destrutor não é seguro para threads, deve-se sempre executar StopOffer() antes da liberação do objeto receptor, a fim de excluir com segurança execuções paralelas de callbacks durante o processo de destruição.

Caminho de utilização

O fluxo típico para utilização do receptor compreende a derivação, a disponibilização e a desmontagem ordenada:

  1. Definição da classe: a aplicação define uma subclasse e sobrescreve ambos os métodos puramente virtuais OnEventQualification() para eventos com dados de contexto sem versão [SWS_AIDSM_10807], bem como para dados de contexto versionados ou vazios [SWS_AIDSM_10810].
  2. Instanciação: a subclasse é instanciada, passando-se o identificador de instância da porta para o construtor base [SWS_AIDSM_10801].
  3. Ativação via Offer: a aplicação chama Offer() para iniciar a aceitação de eventos [SWS_AIDSM_10808]. O ara::core::Result<void> retornado confirma a liberação bem-sucedida.
  4. Recepção de eventos: se o IdsM identificar um evento de segurança qualificado, ele chamará o método de callback apropriado, dependendo do formato dos dados:
    • OnEventQualification(EventIdType, ara::core::Optional<ContextDataType>, ara::core::Optional<TimestampType>) para dados sem versão [SWS_AIDSM_10807].
    • OnEventQualification(EventIdType, ara::core::Optional<VersionedContextDataType>, ara::core::Optional<TimestampType>) para dados de contexto versionados ou dados ausentes específicos do evento [SWS_AIDSM_10810].
  5. Desativação e destruição: antes do encerramento da aplicação, chama-se StopOffer() [SWS_AIDSM_10809] e o objeto é liberado regularmente através do destrutor [SWS_AIDSM_10802].

Diagrama de sequência: Fluxo típico de instanciação, liberação via Offer(), recepção de eventos qualificados via OnEventQualification() e cancelamento de registro via StopOffer(). Fontes: [SWS_AIDSM_10801], [SWS_AIDSM_10808], [SWS_AIDSM_10807], [SWS_AIDSM_10810], [SWS_AIDSM_10809], [SWS_AIDSM_10802].

Cenários de erro

Durante o uso, podem ocorrer diversas condições de erro e conflitos de concorrência:

  • Falha em Offer(): o método Offer() retorna um ara::core::Result<void> [SWS_AIDSM_10808]. Interpretação: caso a porta modelada não possa ser vinculada no sistema ou o registro junto ao IdsM falhe, o objeto de resultado retorna um erro. Pergunta (aberta) A aplicação só pode presumir que callbacks serão disparados após a verificação bem-sucedida.
  • Valores de contexto ou de carimbo de data/hora ausentes: em ambas as assinaturas de callback, os dados de contexto e os carimbos de data/hora estão encapsulados em ara::core::Optional ([SWS_AIDSM_10807], [SWS_AIDSM_10810]). Um acesso não verificado sem validação (por exemplo, a dados de contexto vazios) leva a erros na lógica de processamento da aplicação.
  • Operações não seguras para threads: à exceção dos construtores ([SWS_AIDSM_10801], [SWS_AIDSM_10803]), todas as operações — a saber, Offer() [SWS_AIDSM_10808], StopOffer() [SWS_AIDSM_10809], o operador de atribuição [SWS_AIDSM_10805], o destrutor [SWS_AIDSM_10802], bem como os callbacks ([SWS_AIDSM_10807], [SWS_AIDSM_10810]) — não são seguras para threads. Uma chamada não coordenada de Offer() ou StopOffer() a partir de threads diferentes leva a um comportamento imprevisível.

GERADO POR IA não revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: b8f71cd4e8ed Procedência

A classe QualifiedEventsReceiver serve para a recepção de Security Events qualificados do Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10800] no contexto do cabeçalho ara/idsm/qualified_events_receiver.h.

Uso e instanciação: uma instância é criada através do construtor QualifiedEventsReceiver(const ara::core::InstanceSpecifier& instance) para uma PPort modelada [SWS_AIDSM_10801]. O modelo de classes impõe semântica de movimento: o construtor de cópia [SWS_AIDSM_10804] e o operador de atribuição por cópia [SWS_AIDSM_10806] estão excluídos (= delete). Em vez disso, instâncias podem ser transferidas através do construtor de movimento [SWS_AIDSM_10803] ou da atribuição por movimento [SWS_AIDSM_10805].

Concorrência e thread safety: a criação da instância através do construtor parametrizado [SWS_AIDSM_10801], bem como a movimentação por meio do construtor de movimento [SWS_AIDSM_10803], estão especificadas como thread-safe. Por outro lado, a destruição através do destruidor virtual [SWS_AIDSM_10802] e a atribuição por movimento via operator= [SWS_AIDSM_10805] estão definidas como não seguras para threads (not thread-safe). Os chamadores devem, portanto, garantir que operações de atribuição e destruição não sejam executadas de forma concorrente no mesmo objeto.

Tratamento de erros: todas as funções especificadas de ciclo de vida e atribuição – construtores, destruidor e atribuição por movimento – estão identificadas com noexcept e, portanto, não disparam exceções.
