Criptografa dados assimetricamente em etapa única ou por meio de uma operação de streaming em várias partes.

A interface serve para a criptografia assimétrica de dados em texto simples na AUTOSAR Adaptive Platform e é gerenciada por meio do smart pointer disponibilizado [SWS_CRYPT_50174]. Após a atribuição de uma chave pública compatível, as mensagens podem ser transformadas de forma compacta em uma única execução ou continuamente por meio de uma sessão de streaming em várias partes [SWS_CRYPT_50090]. Para uma execução correta, os tamanhos de buffer devem ser calculados previamente, sendo que todas as operações do contexto são especificadas como seguras contra exceções e thread-safe.

Contexto

A classe C++ ara::crypto::cryp::EncryptorPublicCtx fornece a interface padronizada para a criptografia assimétrica de dados na AUTOSAR Adaptive Platform. Ela serve a aplicações cliente para a cifragem de dados em texto simples com a ajuda de uma chave pública assimétrica. A configuração da chave criptográfica pode ser realizada diretamente por meio de um objeto de chave ([SWS_CRYPT_50175]) ou por meio de uma referência a uma posição de armazenamento de chave (KeySlot, [SWS_CRYPT_50086]). A transferência de dados ocorre por meio de áreas de buffer eficientes em termos de memória (ReadOnlyMemRegion para dados em texto simples e ReadWriteMemRegion para a saída do criptograma).

Ciclo de vida

Instâncias do contexto são gerenciadas por meio do shared pointer std::shared_ptr<EncryptorPublicCtx> definido no alias de tipo Sptr ([SWS_CRYPT_50174]). A criação em si não faz parte desta definição de interface; presumivelmente, a instanciação ocorre por meio de um componente de factory de nível superior da arquitetura de criptografia. Pergunta Q-5b7490ba113bb861 (aberta) Ao longo de sua vida útil, o objeto passa por estados claramente definidos:

  • Não inicializado: Após a instanciação, o contexto ainda não possui chave. Operações de processamento de dados não são permitidas nesse estado.
  • Configurado (Pronto): Por meio da chamada de SetKey() com um PublicKey ([SWS_CRYPT_50175]) ou um KeySlot ([SWS_CRYPT_50086]), o contexto fica pronto para uso. A partir desse estado, é possível executar uma criptografia em etapa única ou iniciar uma sessão de streaming.
  • Streaming ativo: A chamada de Start() ([SWS_CRYPT_50087]) coloca o contexto no estado de streaming. Blocos contínuos de dados são processados via Update() ([SWS_CRYPT_50176]). A sessão é concluída com Finish() ([SWS_CRYPT_50088]) ou abortada com Cancel() ([SWS_CRYPT_50089]), retornando o contexto ao estado Configurado.

Todos os métodos da classe são especificados como seguros contra exceções (exception safe) e thread-safe (thread-safe). Se o contexto for destruído enquanto uma operação de streaming ainda não tiver sido concluída, a implementação subjacente deverá limpar os buffers alocados e descartar implicitamente a sessão. Caminho de utilização

A classe suporta dois modos de processamento: o processamento em etapa única para conjuntos completos de dados e o streaming em várias etapas para fluxos de dados segmentados. Antes de realizar criptografias, as aplicações devem considerar os limites de buffer:

  • Por meio de GetMinimumChunkSize()` (<a class="spec-record-ref" data-req="SWS_CRYPT_50178">[SWS_CRYPT_50178]</a>) und <code>GetMaximumChunkSize() ([SWS_CRYPT_50091]), é possível determinar os tamanhos de entrada mínimo e máximo suportados para chamadas individuais.
  • A capacidade necessária do buffer de saída deve ser consultada previamente com GetRequiredOutputBufferSize() ([SWS_CRYPT_50177]). O parâmetro isFinal controla se o cálculo é realizado para etapas intermediárias (false) ou para chamadas finais/etapas únicas (true).

O fluxo típico de uma criptografia por streaming divide-se nas seguintes etapas:

  1. Atribuição de chave via SetKey() com um PublicKey válido ([SWS_CRYPT_50175]).
  2. Inicialização da sessão de streaming por meio da chamada de Start() ([SWS_CRYPT_50087]).
  3. Cálculo do tamanho de buffer de saída necessário para blocos intermediários com GetRequiredOutputBufferSize(inputSize, false) ([SWS_CRYPT_50177]).
  4. Transformação repetida de blocos de dados via Update() ([SWS_CRYPT_50176]).
  5. Determinação do tamanho de buffer para o último bloco (isFinal = true) e finalização da operação via Finish() ([SWS_CRYPT_50088]).

Para dados compactos que podem ser processados em uma única passagem, Encrypt() ([SWS_CRYPT_50090]) oferece uma chamada direta em etapa única sem divisão em fases Start, Update e Finish.

Cenários de erro

Todos os métodos utilizam ara::core::Result para a sinalização de erros e garantem semântica de rollback em caso de falha:

  • Erros de estado: Uma chamada de Start(), Encrypt() ou GetRequiredOutputBufferSize() em um contexto não inicializado resulta em ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50177]). Se Update(), Finish() ou Cancel() forem chamados sem que Start() tenha sido executado previamente, a operação falhará com ara::crypto::CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089]).
  • Erros de chave e uso: Se a chave fornecida ou o KeySlot for incompatível com o contexto, ara::crypto::CryptoErrc::kIncompatibleObject será reportado ([SWS_CRYPT_50175], [SWS_CRYPT_50086], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Se o uso permitido da chave não contiver a permissão kAllowDataEncryption, isso resultará em ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Se um KeySlot referenciado estiver vazio, ara::crypto::CryptoErrc::kEmptyKeySlot será reportado ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • Erros de buffer e dados: Se o buffer de saída passado for dimensionado de forma muito pequena, Encrypt(), Update() e Finish() responderão com ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). Desvios dos tamanhos de chunk permitidos resultam em ara::crypto::CryptoErrc::kInvalidInputSize, e dados de entrada inválidos resultam em ara::crypto::CryptoErrc::kInvalidArgument.
  • Funções não suportadas e gargalos de recursos: Se a implementação não suportar streaming ou chamada em etapa única, a operação falhará com ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). Em caso de recursos criptográficos bloqueados, ara::crypto::CryptoErrc::kBusyResource é retornado ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).

Se o processamento de dados não foi iniciado previamente por Start(), a operação falha com o código de erro ara::crypto::CryptoErrc::kProcessingNotStarted mantendo a semântica de rollback [SWS_CRYPT_50089]. Interação na pilha de criptografia

O comportamento de cancelamento realizado por Cancel() segue um padrão de projeto uniforme para operações de streaming com estado no módulo de criptografia. Interfaces análogas com semântica de erro idêntica existem para:

  • códigos de autenticação de mensagem em MessageAuthnCodeCtx [SWS_CRYPT_50027] bem como cálculos de hash em HashFunctionCtx [SWS_CRYPT_50058].

          O método Finish conclui o processo de encriptação assimétrica no contexto de ara::crypto::cryp::EncryptorPublicCtx [SWS_CRYPT_50088]. A chamada é efetuada de forma síncrona e está especificada como noexcept, exception-safe bem como thread-safe. Como parâmetros, a função assume através de in (ReadOnlyMemRegion) o fragmento final de texto simples e grava os dados de texto cifrado resultantes no buffer de saída out (ReadWriteMemRegion). O tamanho de buffer necessário para out pode ser determinado previamente através de GetRequiredOutputBufferSize(). O valor de retorno ara::core::Result<std::size_t> fornece em caso de sucesso o número de bytes efetivamente gravados, o qual pode resultar inferior à capacidade total do buffer de saída [SWS_CRYPT_50088].
