Disponibiliza Negative Response Codes específicos de UDS para o tratamento padronizado de erros em funções de diagnóstico.

O domínio de erro ara::diag::DiagUdsNrcErrorDomain encapsula códigos de erro do processamento de diagnóstico e os associa a valores de erro padronizados de UDS [SWS_DM_00529]. Quando um processador de diagnóstico externo reporta um erro correspondente, o Diagnostic Server deriva dele um NRC de 1 byte e envia uma resposta negativa de UDS para o testador [SWS_DM_02060]. Como restrição essencial, os valores de NRC derivados devem situar-se estritamente na faixa de valores entre 0x01 e 0xFE.

Contexto

A classe ara::diag::DiagUdsNrcErrorDomain representa o domínio de erro padronizado para erros originados de diferentes classes de diagnóstico (AUTOSAR_AP_SWS_Diagnostics §8.12.3 «Class: DiagUdsNrcErrorDomain»). Como especialização da classe base ara::core::ErrorDomain [SWS_DM_00529], ela constitui o elo fundamental entre o processamento de diagnóstico do lado da aplicação e o protocolo UDS (Unified Diagnostic Services). Dentro da AUTOSAR Adaptive Platform, ela atua como intermediária entre processadores de diagnóstico externos ou aplicações de software e o Diagnostic Server (Diagnostic Management, DM). Se um processador de diagnóstico externo reportar um erro desse domínio durante a execução de um comando, a Diagnostic Server Instance o avalia de forma direcionada [SWS_DM_02060]. Além disso, o domínio interage com a verificação de condições ambientais configuráveis caso a leitura de elementos de dados falhe [SWS_DM_00970].

Ciclo de vida

A instanciação de ara::diag::DiagUdsNrcErrorDomain ocorre por meio do construtor padrão constexpr DiagUdsNrcErrorDomain() noexcept [SWS_DM_00532]. Esse construtor é especificado como seguro contra exceções e thread-safe [SWS_DM_00532]. Devido à concepção de constexpr e à natureza de domínios de erro sem funções, uma instância deve ser disponibilizada tipicamente como um objeto imutável de escopo de processo (interpretação). Pergunta Q-72b7b9c623c1efe0 (aberta) Os métodos de inspeção constituintes Name() [SWS_DM_00533] e Message() [SWS_DM_00534] também são thread-safe e seguros contra exceções. Como o objeto não gerencia estado mutável, o ciclo de vida está vinculado ao contexto de tempo de execução geral da aplicação de diagnóstico e permite acesso concorrente de leitura irrestrito.

Caminho de utilização

O caminho de uso típico descreve a sinalização e transformação de um erro de diagnóstico durante a execução de um serviço:

  1. Um processador de diagnóstico externo executa uma função de diagnóstico e detecta uma condição de erro.
  2. A aplicação cria um ara::core::Result com um código de erro do domínio ara::diag::DiagUdsNrcErrorDomain usando o tipo Errc (alias para DiagUdsNrcErrc) [SWS_DM_00530] e o retorna para a Diagnostic Server Instance [SWS_DM_02060].
  3. A Diagnostic Server Instance recebe o valor de retorno e identifica a presença do domínio de erro ara::diag::DiagUdsNrcErrorDomain [SWS_DM_02060].
  4. O DM deriva o UDS-NRC a partir do código de erro DiagUdsNrcErrc, por exemplo, por meio de um static_cast em um valor de NRC de 1 byte [SWS_DM_02059].
  5. O Diagnostic Server responde ao testador de diagnóstico solicitante com uma resposta negativa de UDS (negative response) contendo o valor de NRC derivado [SWS_DM_02060].

Diagrama de sequência: derivação e transmissão de um UDS-NRC em caso de execução de diagnóstico com erro. Fontes: [SWS_DM_02059], [SWS_DM_02060].

Aplica-se um tratamento especial para solicitações multi-DID: embora a ocorrência de um erro de ara::diag::DiagUdsNrcErrorDomain no resultado indique a falha do processador de diagnóstico externo para o elemento individual, ela pode, no entanto, resultar em uma resposta geral positiva no caso de múltiplos DIDs solicitados, desde que pelo menos um DID seja suportado na sessão ativa (AUTOSAR_AP_SWS_Diagnostics §7.3 «Multi-DID-Requests»).

Cenários de erro

Ao utilizar e encaminhar erros via ara::diag::DiagUdsNrcErrorDomain, aplicam-se limites de valores e regras de comportamento estritos:

  • Faixa de validade: Valores admissíveis de UDS-NRC derivados de DiagUdsNrcErrc situam-se exclusivamente na faixa de 0x01 a 0xFE [SWS_DM_02059].
  • Falha em condições ambientais: Se a obtenção de um dataElement falhar porque um processador externo reporta um erro de ara::diag::DiagUdsNrcErrorDomain, o DM avalia a expressão DiagnosticEnvConditionFormulaPart como não atendida e emite uma mensagem de Log and Trace [SWS_DM_00970].
  • Tratamento de exceções: O método ThrowAsException() converte um ErrorCode na exceção correspondente do tipo Exception (alias para DiagUdsNrcException) [SWS_DM_00531], [SWS_DM_00535]. Essa operação é declarada como não segura contra exceções; com exceções C++ desativadas, ela não participa da resolução de sobrecarga [SWS_DM_00535].
  • Resolução de mensagens: O método Message() fornece uma cadeia de caracteres descritiva para cada código de erro passado e comprovadamente nunca retorna nullptr [SWS_DM_00534].

Este guia baseia-se na especificação AUTOSAR Adaptive R25-11 e resume os requisitos para o domínio de erro DiagUdsNrcErrorDomain.

O construtor padrão sem parâmetros inicializa uma instância do domínio de erro ara::diag::DiagUdsNrcErrorDomain de forma síncrona e sem parâmetros de passagem [SWS_DM_00532]. Devido à qualificação como constexpr, a instanciação já pode ocorrer em tempo de compilação AUTOSAR_AP_SWS_Diagnostics §8.12.3.2.1.1 «Default Constructor». Na implementação prática, contudo, uma instanciação manual direta da classe de domínio [SWS_DM_00529] pelo código da aplicação raramente deverá ser necessária, uma vez que a referência global é obtida por padrão através da função GetDiagUdsNrcDomain() [SWS_DM_00536]. Pergunta Q-22c33afd620b536e (aberta)

Em relação à concorrência e à segurança contra exceções, o construtor é especificado como thread-safe e exception safe [SWS_DM_00532]. Ele é declarado como noexcept e não lança quaisquer exceções por si próprio. O domínio gerencia códigos de erro do tipo de enumeração DiagUdsNrcErrc através do alias Errc [SWS_DM_00530], os quais são gerados mediante MakeErrorCode() [SWS_DM_00537]. Além disso, a classe fornece métodos como Name() [SWS_DM_00533], Message() [SWS_DM_00534] bem como ThrowAsException() [SWS_DM_00535] no âmbito de DiagUdsNrcException [SWS_DM_00531].

Em interação com o Diagnostic Management, os erros deste domínio controlam o tratamento de respostas negativas. Se uma interface ara::diag retornar um erro de DiagUdsNrcErrorDomain, o Diagnostic Server deriva dele uma resposta negativa UDS (NRC) com o valor do código de erro na faixa válida de 0x01 a 0xFE [SWS_DM_02059], [SWS_DM_02060]. Se tal erro ocorrer ao obter um elemento ambiental, o servidor avalia a respetiva condição como não satisfeita e emite uma mensagem de Log-and-Trace [SWS_DM_00970].
