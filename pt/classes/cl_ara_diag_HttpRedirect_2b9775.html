Permite que um servidor SOVD transmita de forma estruturada um novo URL de destino para o reencaminhamento de pedidos de diagnóstico.

A estrutura ara::diag::HttpRedirect serve para que um servidor SOVD comunique a um cliente SOVD o novo endereço de um recurso SOVD movido ou disponível sob outro caminho [SWS_DM_01828]. Para este efeito, disponibiliza o atributo público url, que define o URL de destino do reencaminhamento como cadeia de caracteres [SWS_DM_01829]. Como objeto de valor puro, a estrutura é instanciada sob demanda e encapsula a informação de endereço para o protocolo de resposta HTTP de nível superior.

Contexto

A estrutura ara::diag::HttpRedirect faz parte do módulo de diagnóstico (diag) da AUTOSAR Adaptive Platform e é declarada através do ficheiro de cabeçalho ara/diag/sovd_http_redirect.h AUTOSAR_AP_SWS_Diagnostics §8.55 «Header: ara/diag/sovd_http_redirect.h». Serve para a representação padronizada de um redirecionamento HTTP no âmbito do SOVD (Service-Oriented Vehicle Diagnostics) de acordo com [SWS_DM_01828]. Caso um recurso de diagnóstico dentro do veículo tenha sido deslocado ou esteja temporária ou permanentemente acessível sob outro endereço, o servidor SOVD sinaliza a nova localização ao cliente SOVD requerente através deste tipo.

A estrutura representa um suporte de dados elementar cujo único elemento público é a variável url do tipo ara::core::String [SWS_DM_01829]. Através deste campo é especificado o endereço de destino completo ou relativo para o qual o cliente deve redirecionar o seu pedido original AUTOSAR_AP_SWS_Diagnostics §8.55.1.1 «Public Member Variables». ara::diag::HttpRedirect atua, assim, como elo padronizado entre a gestão interna de recursos do servidor de diagnóstico e o tratamento de protocolo externo perante o cliente.

Ciclo de vida

Como estrutura de dados puramente passiva (struct), ara::diag::HttpRedirect possui, de acordo com [SWS_DM_01828], um ciclo de vida transitório vinculado ao contexto de execução. Interpretação: a instanciação ocorre orientada à necessidade por parte do servidor SOVD ou de uma aplicação de diagnóstico associada no momento em que o reencaminhamento de um pedido se torna necessário. Neste processo, o URL de destino é armazenado no campo url diretamente durante a construção ou imediatamente a seguir [SWS_DM_01829]. Pergunta (aberta)

A estrutura possui semântica de valor regular de C++; a alocação e a libertação de memória regem-se integralmente pelo tempo de vida da instância encapsuladora, bem como do ara::core::String embutido. Interpretação: a criação, atribuição e destruição da estrutura é isenta de efeitos secundários e não requer registo ou cancelamento de registo em instâncias centrais do serviço de diagnóstico. Pergunta (aberta) No que diz respeito à concorrência, um único exemplar de ara::diag::HttpRedirect não é thread-safe em caso de acesso de escrita; contudo, dado que as instâncias são habitualmente criadas de forma isolada por pedido de cliente e transportadas como valor de retorno, não ocorrem conflitos de sincronização.

Caminho de utilização

A utilização típica de ara::diag::HttpRedirect realiza-se numa interação em três etapas entre o cliente SOVD, o servidor SOVD e o recurso de destino deslocado. Inicialmente, o cliente SOVD envia uma chamada HTTP para um URI de recurso conhecido. Se o servidor não puder atender o pedido diretamente porque o recurso foi movido para um novo endpoint, este cria uma instância de ara::diag::HttpRedirect de acordo com [SWS_DM_01828] e atribui o novo endereço de destino ao membro url [SWS_DM_01829].

Interpretação: a conversão do conteúdo da estrutura no fluxo de resposta HTTP (por exemplo, em conjunto com um código de estado de redirecionamento HTTP e o respetivo cabeçalho Location) é executada pela stack de comunicação SOVD subjacente. Pergunta Q-e68bb7696aa291c0 (aberta) Assim que o cliente SOVD recebe o reencaminhamento, direciona o seu pedido de diagnóstico de forma transparente para o URL de destino transmitido, a fim de executar a operação de diagnóstico propriamente dita.
