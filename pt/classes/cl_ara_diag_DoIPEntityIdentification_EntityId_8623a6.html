Contexto

A estrutura de dados ara::diag::DoIPEntityIdentification::EntityId é definida no cabeçalho ara/diag/doip_entity_identification.h como um tipo incorporado da classe de interface ara::diag::DoIPEntityIdentification (SWS Diagnostics §8.33 «Header: ara/diag/doip_entity_identification.h», [SWS_DM_01362]). A sua função consiste em fornecer, de forma encapsulada, o valor de Entity Identification (EID) padronizado na ISO 13400-2:2019 para o protocolo DoIP (Diagnostic communication over Internet Protocol). Para isso, a estrutura encapsula o membro entityIdentification como um array de bytes fixo do tipo ara::core::Array<std::uint8_t, 6> ([SWS_DM_01496]).

No sistema geral, interagem essencialmente três componentes durante o uso de EntityId:

  • Adaptive Application (AA): Implementa ou instancia a classe de API ara::diag::DoIPEntityIdentification ([SWS_DM_01364]) para disponibilizar a identificação de entidade específica do sistema. Interpretação: o identificador de 6 bytes deve tipicamente basear-se, em conformidade com a ISO 13400-2:2019, em um endereço MAC ou em uma identificação de hardware análoga da instância DoIP.
  • Diagnostic Management (DM): Atua como parceiro central de interação no daemon da Adaptive. Se o sistema estiver configurado para o valor DoIpEidRetrievalEnum.eidUseApi por meio do parâmetro DoIpNetworkConfiguration.eidRetrieval, o DM solicita a EID ativamente por meio do método ara::diag::DoIPEntityIdentification::GetEntityId ([SWS_DM_01361], SWS Diagnostics §7.2.1.2).
  • Rede DoIP / Tester externo: O ponto remoto no nível de rede para o qual o DM transmite a EID recebida dentro de mensagens de protocolo DoIP padronizadas (como a Vehicle Announcement Message) (SWS Diagnostics §7.2.1.2).

Diagrama de contexto: interação entre Adaptive Application, daemon do Diagnostic Management e rede DoIP no fornecimento da EntityId. Fontes: [SWS_DM_01361], [SWS_DM_01496], SWS Diagnostics §7.2.1.2.

Ciclo de vida

Como um mero objeto de transferência de dados (Value Object), a estrutura EntityId está sujeita a um ciclo de vida simples:

  • Criação e relações de propriedade: Interpretação: como a especificação indica exclusivamente a variável pública entityIdentification ([SWS_DM_01496]), EntityId deve ter sido concebido como um tipo de valor de criação trivial, sem lógica complexa de construção. A criação é realizada pela Adaptive Application no contexto da chamada de GetEntityId. A propriedade dos dados é repassada ao Diagnostic Management por meio do retorno por valor.
  • Tempo de vida e estados: EntityId não possui máquinas de estados internas ou fases de vida. O tempo de vida de uma instância é tipicamente limitado à execução da chamada de API e à subsequente serialização dos 6 bytes no pacote DoIP pelo DM.
  • Destruição: A liberação ocorre automaticamente ao sair do respectivo escopo. A instância de interface de nível superior é liberada por meio do destrutor ara::diag::DoIPEntityIdentification::~DoIPEntityIdentification ([SWS_DM_01365], SWS Diagnostics §8.33.1.1.1.1).
  • Concorrência: Por se tratar de uma estrutura de dados elementar composta por um array de 6 bytes, o acesso de leitura é seguro contra concorrência, desde que o objeto seja passado de forma imutável ou criado com segurança de threads no lado da aplicação.

Caminho de utilização

O fluxo regular para o uso de EntityId divide-se nos seguintes passos:

  1. Verificação de configuração: O Diagnostic Management verifica, com base no modelo de dados, se a obtenção do identificador de entidade por meio da interface está configurada para a rede DoIP (DoIpNetworkConfiguration.eidRetrieval == DoIpEidRetrievalEnum.eidUseApi) ([SWS_DM_01361]).
  2. Chamada de API: O DM inicia a obtenção da EID chamando ara::diag::DoIPEntityIdentification::GetEntityId na classe previamente instanciada pela aplicação ([SWS_DM_01361], [SWS_DM_01364]).
  3. Preenchimento da estrutura: A Adaptive Application inicializa o membro entityIdentification dentro da estrutura EntityId com os 6 bytes do identificador ([SWS_DM_01496]) e retorna o objeto como valor de retorno ao DM.
  4. Processamento do protocolo: O DM extrai os 6 bytes de EntityId e os insere nas mensagens de protocolo DoIP a serem enviadas, a fim de anunciar o veículo ou a entidade na rede (SWS Diagnostics §7.2.1.2).

Diagrama de sequência: fluxo típico da obtenção de EID via GetEntityId() e comportamento de fallback em caso de indisponibilidade. Fontes: [SWS_DM_01361], [SWS_DM_01496], [SWS_DM_01528].

Cenários de erro

No fornecimento e processamento de EntityId, devem ser observadas as seguintes condições de erro e pré-condições:

  • Pré-condição: A obtenção por meio da API C++ pressupõe obrigatoriamente que DoIpNetworkConfiguration.eidRetrieval esteja configurado para eidUseApi ([SWS_DM_01361]). Caso contrário, o método GetEntityId não é chamado pelo DM.
  • Interface não disponibilizada: Se a interface ara::diag::DoIPEntityIdentification ainda não for disponibilizada no momento da consulta de EID pelo DM ou se a leitura da EID falhar ([SWS_DM_01528], SWS Diagnostics §7.2.1.2), é acionado um fallback padronizado.
  • Comportamento de fallback (valor substituto de EID): Em caso de erro, o DM transmite nas mensagens de protocolo DoIP um valor substituto de 6 bytes firmemente definido, no qual todos os bytes estão definidos como 0xFF (0xFF 0xFF 0xFF 0xFF 0xFF 0xFF) ([SWS_DM_01528]).
  • Pós-condição: Após a execução bem-sucedida, o DM dispõe de um identificador completo de 6 bytes ([SWS_DM_01496]), de modo que mensagens DoIP conformes possam ser geradas sem recorrer ao valor substituto.

<h4>Cenários de erro</h4>
<p>No fornecimento e processamento de <code>EntityId</code>, devem ser observadas as seguintes condições de erro e pré-condições:</p>
<ul>
<li><strong>Pré-condição:</strong> A obtenção por meio da API C++ pressupõe obrigatoriamente que <code>DoIpNetworkConfiguration.eidRetrieval</code> esteja configurado para <code>eidUseApi</code> (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>). Caso contrário, o método <code>GetEntityId</code> não é chamado pelo DM.</li>
<li><strong>Interface não disponibilizada:</strong> Se a interface <code>ara::diag::DoIPEntityIdentification</code> ainda não for disponibilizada no momento da consulta de EID pelo DM ou se a leitura da EID falhar (<a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">SWS Diagnostics §7.2.1.2</a>), é acionado um fallback padronizado.</li>
<li><strong>Comportamento de fallback (valor substituto de EID):</strong> Em caso de erro, o DM transmite nas mensagens de protocolo DoIP um valor substituto de 6 bytes firmemente definido, no qual todos os bytes estão definidos como <code>0xFF</code> (<code>0xFF 0xFF 0xFF 0xFF 0xFF 0xFF</code>) (<a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>).</li>
<li><strong>Pós-condição:</strong> Após a execução bem-sucedida, o DM dispõe de um identificador completo de 6 bytes (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>), de modo que mensagens DoIP conformes possam ser geradas sem recorrer ao valor substituto.</li>
</ul>
