Permite o empacotamento e desempacotamento seguro de chaves por meio de criptografia de chave simétrica.

O contexto SymmetricKeyWrapperCtx serve para o empacotamento e desempacotamento criptográfico de chaves mediante algoritmos simétricos. Antes da execução de Wrap ou UnwrapSymmetricKey, o contexto deve ser configurado por meio de SetKey com uma chave de criptografia de chave (KEK) compatível [SWS_CRYPT_24018]. Todas as operações pressupõem as permissões de uso correspondentes dos objetos de chave envolvidos e reportam erros via ara::core::Result com semântica de rollback [SWS_CRYPT_24014]. A interface é exception-safe e especificada como thread-safe para operação concorrente.

Contexto

A classe SymmetricKeyWrapperCtx define a interface padronizada para algoritmos de envelopamento simétrico de chaves (Key Wrapping) na AUTOSAR Adaptive Platform. Sua responsabilidade central consiste na proteção criptográfica de chaves durante a exportação e na recuperação de chaves empacotadas para uso interno. Nesse processo, a classe interage primariamente com chaves de criptografia de chave (Key Encryption Keys, KEK), fornecidas como objeto de chave volátil do tipo SymmetricKey ou de forma persistente através de um KeySlot [SWS_CRYPT_24018], [SWS_CRYPT_50034]. No empacotamento, o contexto recebe um CryptoObject genérico [SWS_CRYPT_24014], enquanto a operação de desempacotamento gera e retorna um novo objeto SymmetricKey pronto para uso [SWS_CRYPT_24016].

Ciclo de vida

Instâncias de SymmetricKeyWrapperCtx são gerenciadas pelo ponteiro inteligente tipado Sptr (um alias para std::shared_ptr<SymmetricKeyWrapperCtx>) [SWS_CRYPT_24001]. A criação efetiva do objeto deve ocorrer por meio de uma factory de provedor competente, pois a classe representa uma interface abstrata com métodos puramente virtuais. Pergunta Q-7b9a1007da43ddcd (aberta) Todas as funções-membro da interface são especificadas como exception-safe e thread-safe, permitindo o uso seguro em componentes de software concorrentes [SWS_CRYPT_24014], [SWS_CRYPT_24016].

Em seu ciclo de vida, o contexto passa por duas fases essenciais: imediatamente após a instanciação, ele se encontra em estado não inicializado. Nessa fase, operações criptográficas e cálculos de buffer falham com o erro kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014]. Somente através da chamada bem-sucedida de SetKey com uma KEK ou KeySlot compatível o contexto transita para o estado operacional, no qual chaves podem ser empacotadas ou desempacotadas com segurança [SWS_CRYPT_24018], [SWS_CRYPT_50034].

Caminho de utilização

O fluxo regular para o empacotamento de uma chave requer uma sequência coordenada de configuração, verificação de buffer e execução. Inicialmente, a aplicação configura o contexto via SetKey com o objeto KEK desejado [SWS_CRYPT_24018] ou vincula um KeySlot correspondente [SWS_CRYPT_50034]. Na segunda etapa, a aplicação determina por meio de GetRequiredWrappedKeyBufferSize o tamanho máximo de buffer de saída necessário para o objeto de destino a ser empacotado [SWS_CRYPT_50035]. Após a disponibilização de uma área de memória adequadamente dimensionada (ReadWriteMemRegion), ocorre a chamada de Wrap, que grava os dados serializados e criptografados da chave no buffer e retorna o número exato de bytes [SWS_CRYPT_24014].

Diagrama de sequência: sequência típica de chamadas para o empacotamento simétrico de chaves. Fontes: [SWS_CRYPT_24018], [SWS_CRYPT_50035], [SWS_CRYPT_24014]

Para o processo complementar de desempacotamento, a aplicação, após a configuração mediante SetKey, passa o buffer de entrada com os dados empacotados para UnwrapSymmetricKey [SWS_CRYPT_24016]. Nesse procedimento, o identificador do algoritmo de destino (targetAlgId) e as flags de uso permitidas (allowedUsage) para a nova chave simétrica a ser gerada devem ser definidos explicitamente [SWS_CRYPT_24016].

Cenários de erro

Métodos da classe sinalizam erros por meio do tipo de retorno ara::core::Result com semântica de rollback. Os cenários centrais de erro incluem:

  • Inicialização ausente: se GetRequiredWrappedKeyBufferSize, Wrap ou UnwrapSymmetricKey forem chamados antes de uma atribuição de chave bem-sucedida, eles retornam ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014], [SWS_CRYPT_24016].
  • Violação de direitos de uso: ao definir a KEK, ela deve possuir pelo menos a permissão kAllowKeyWrapping ou kAllowKeyUnwrapping; caso contrário, SetKey falha com ara::crypto::CryptoErrc::kUsageViolation [SWS_CRYPT_24018]. Em Wrap, a ausência de kAllowKeyWrapping na KEK ou a ausência de kAllowSecuredExport no objeto a ser empacotado também resulta em kUsageViolation [SWS_CRYPT_24014]. No desempacotamento, verifica-se se a KEK permite kAllowKeyUnwrapping [SWS_CRYPT_24016].
  • Incompatibilidades e erros de buffer: se o buffer de destino para Wrap for muito pequeno, ara::crypto::CryptoErrc::kInsufficientCapacity é reportado [SWS_CRYPT_24014]. Formatos de chave incorretos ou tipos incompatíveis resultam em ara::crypto::CryptoErrc::kInvalidArgument [SWS_CRYPT_24014], [SWS_CRYPT_24016]. Se o contexto suportar apenas slots ou apenas objetos de chave, SetKey reporta o erro kUnsupported [SWS_CRYPT_24018], [SWS_CRYPT_50034].
  • Conflitos de recursos e slots vazios: se a operação acessar um recurso ocupado, ara::crypto::CryptoErrc::kBusyResource é retornado; se o KeySlot referenciado estiver vazio, isso resulta em ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_24014], [SWS_CRYPT_24016].

      Utilização e semântica
      

      A função-membro síncrona SetKey configura uma instância de ara::crypto::cryp::SymmetricKeyWrapperCtx de modo que o objeto SymmetricKey::Sptr passado seja utilizado como Key Encryption Key (KEK) para operações de chave subsequentes [SWS_CRYPT_24018]. A função é especificada como um método virtual puro com noexcept e retorna um ara::core::Result<void> vazio, desde que a atribuição tenha sido bem-sucedida [SWS_CRYPT_24018].
      


      Tratamento de erros e rollback
      

      Se ocorrer um erro durante a configuração, aplica-se uma semântica de rollback obrigatória, de modo que o estado do contexto permaneça inalterado [SWS_CRYPT_24018]. As possíveis causas de erro são mapeadas por meio de códigos de erro de ara::crypto::CryptoErrc:
      

        

      • kIncompatibleObject: o objeto de chave fornecido é incompatível com o contexto simétrico [SWS_CRYPT_24018].
        • 

      • kUsageViolation: o uso permitido da chave não inclui nem kAllowKeyWrapping nem kAllowKeyUnwrapping [SWS_CRYPT_24018].
        • 

      • kUnsupported: a implementação do contexto suporta exclusivamente a definição de uma chave por meio de um KeySlot [SWS_CRYPT_24018].
        • 

      


      Concorrência e interação
      

      O método é especificado como thread-safe e seguro contra exceções (exception safe) [SWS_CRYPT_24018]. Caso as chaves sejam gerenciadas por meio de slots ou o contexto suporte exclusivamente KeySlots, existe para o mesmo contexto de wrapper a sobrecarga alternativa SetKey com KeySlot::Sptr [SWS_CRYPT_50034]. Esta configura o contexto para carregar a chave armazenada no slot no momento da execução do key wrapping [SWS_CRYPT_50034].
      

      

      Esta nota de uso baseia-se na especificação AUTOSAR Adaptive Platform Release R25-11.

          usar
          

          O método virtual SetKey configura o contexto ara::crypto::cryp::SymmetricKeyWrapperCtx de modo a que a chave armazenada no KeySlot fornecido seja utilizada assim que o key wrapping for executado [SWS_CRYPT_50034]. A função é chamada de forma síncrona, está declarada com noexcept e retorna um ara::core::Result<void> [SWS_CRYPT_50034].
          


          Tratamento de erros
          

          Em caso de erro, o método assegura uma semântica de reversão e retorna um dos seguintes resultados de erro [SWS_CRYPT_50034]:
          

            

          • ara::crypto::CryptoErrc::kIncompatibleObject: o keySlot fornecido é incompatível com este contexto [SWS_CRYPT_50034].
            • 

          • ara::crypto::CryptoErrc::kUnsupported: o contexto suporta exclusivamente a definição de um SymmetricKey direto [SWS_CRYPT_50034].
            • 

          


          simultaneidade
          

          A operação é segura para threads (thread-safe) e oferece segurança garantida contra exceções (exception safe) [SWS_CRYPT_50034].
          


          Interação
          

          A interface representa, dentro de SymmetricKeyWrapperCtx, o equivalente baseado em slot à sobrecarga SetKey com SymmetricKey::Sptr, que vincula diretamente uma chave como Key Encryption Key (KEK) [SWS_CRYPT_24018]. Funções de configuração análogas baseadas em slot também são utilizadas em contextos criptográficos relacionados, como KeyDerivationFunctionCtx [SWS_CRYPT_50010], KeyEncapsulatorPublicCtx [SWS_CRYPT_50012], VerifierPublicCtx [SWS_CRYPT_50018], MessageAuthnCodeCtx [SWS_CRYPT_50026] e SignerPrivateCtx [SWS_CRYPT_50036].

              Unwrap a wrapped key using the previously set key encryption key and return an SymmetricKey.

  Procedência
  

              

              

              O método UnwrapSymmetricKey da interface ara::crypto::cryp::SymmetricKeyWrapperCtx descriptografa uma chave empacotada utilizando a Key Encryption Key (KEK) previamente definida e retorna um novo objeto SymmetricKey [SWS_CRYPT_24016]. Como parâmetros, a função síncrona recebe o buffer de entrada com os dados protegidos da chave (wrappedKey), o identificador de algoritmo para a chave de destino (targetAlgId), bem como sinalizadores de bits para os tipos de transformação permitidos desta (allowedUsage) [SWS_CRYPT_24016].
              

              O valor de retorno ara::core::Result<SymmetricKey::Sptr> contém, em caso de execução bem-sucedida, um smart pointer para a chave gerada ou sinaliza um erro com semântica de rollback [SWS_CRYPT_24016]. Possíveis causas de erro são:
              

                

              • InvalidArgument: os dados de chave passados em wrappedKey não podem ser desempacotados, por exemplo, devido a um formato inválido ou a um tamanho incorreto de buffer [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUninitializedContext: o contexto de empacotamento ainda não foi inicializado com uma KEK compatível [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUsageViolation: as restrições de uso da KEK proíbem o desempacotamento (ausência de kAllowKeyUnwrapping) [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUnknownIdentifier: o valor passado para targetAlgId não é conhecido ou não é suportado [SWS_CRYPT_24016].
                •
