Contexto

A estrutura de dados apext::com::secoc::FVContainer é parte integrante das Platform Extension Interfaces normativas da AUTOSAR Adaptive Platform no módulo Communication Management ([SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). As Platform Extension Interfaces são interfaces funcionais fornecidas ou utilizadas por um fabricante de veículos (OEM) ou integrador de sistemas para estender de forma direcionada a funcionalidade básica do sistema adaptativo (AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). Dentro desse conceito de extensão, FVContainer é definido através do cabeçalho apext/com/secoc/fvm.h e assume o papel de um contêiner de transporte padronizado para valores de frescor (Freshness Values).

No âmbito da comunicação segura a bordo (Secure Onboard Communication, SecOC), a verificação e geração de valores de frescor é elementar para prevenir eficazmente ataques de repetição contra mensagens transmitidas. A estrutura FVContainer atua como um elo de ligação dedicado entre os serviços de comunicação da plataforma e o Freshness Value Manager (FVM) específico do fabricante. Em vez de parâmetros complexos de interface, a struct encapsula a informação do valor de frescor em dois componentes elementares: o comprimento exato em bits do valor e os próprios dados úteis em formato de bytes ([SWS_CM_11344], [SWS_CM_11345]). Isso possibilita uma transferência flexível, independentemente de serem trocados valores completos ou truncados.

Diagrama de contexto: integração do FVContainer na interface entre o Communication Management e a extensão de plataforma FVM. Fontes: [SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer».

Ciclo de vida

A estrutura FVContainer é concebida como um objeto de transferência de dados puramente passivo (Value Object) ([SWS_CM_11286]). Ela não possui máquina de estados própria e não gerencia recursos ativos em segundo plano ou threads. A instanciação ocorre tipicamente de forma imediata no contexto de uma operação pendente de envio ou recepção de mensagens, seja na pilha da thread chamadora ou como um objeto temporário dentro da pipeline de processamento.

Em relação às relações de propriedade, FVContainer está sujeita às semânticas padrão de valor do C++. A instância possui suas variáveis-membro com exclusividade. Em uma atribuição ou passagem para métodos de interface, os valores são copiados ou transferidos via semântica de movimento. O elemento value encapsula um vetor do tipo ara::core::Vector<std::uint8_t> ([SWS_CM_11345]), que gerencia dinamicamente sua área de memória. A destruição de FVContainer ocorre deterministicamente ao sair do escopo delimitador de acordo com os princípios de RAII, liberando automaticamente o buffer alocado dinamicamente do vetor.

No que diz respeito à concorrência, FVContainer não oferece segurança inerente para threads. Interpretação: como a struct não disponibiliza mecanismos internos de sincronização ou mutexes, os acessos concorrentes de várias threads à mesma instância devem ser completamente serializados pelo componente chamador.

Caminho de utilização

O fluxo de utilização primário de FVContainer abrange a troca de dados entre o subsistema SecOC e as funções do FVM durante a autenticação ou verificação de mensagens. Dependendo de o contêiner atuar como valor de entrada ou de retorno, ele transporta valores de frescor completos ou truncados ([SWS_CM_11345], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 «value»).

  1. Instanciação e preparação: o Communication Management cria uma instância local de FVContainer ([SWS_CM_11286]). No caso de uma verificação de mensagem, o subsistema extrai o valor de frescor truncado (Truncated Freshness Value) da mensagem recebida e preenche o vetor value bem como o comprimento em bits em length ([SWS_CM_11344], [SWS_CM_11345]).
  2. Chamada de interface: a instância é passada para a função de interface correspondente do FVM (AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). Interpretação: o FVM reconstrói o valor de frescor completo com base no valor truncado fornecido e em contadores internos.
  3. Retorno e processamento posterior: o FVM retorna o resultado na forma de uma instância de FVContainer recém-criada ou modificada ([SWS_CM_11345]). O sistema chamador lê o comprimento real em bits de length ([SWS_CM_11344]) e a sequência de bytes de value ([SWS_CM_11345]) para realizar finalmente a autenticação criptográfica (por exemplo, cálculo de MAC).

Diagrama de sequência: fluxo típico de chamadas para o processamento de valores de frescor com FVContainer como parâmetro de entrada e de saída. Fontes: [SWS_CM_11344], [SWS_CM_11345], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 «value».

Cenários de erro

Como uma estrutura de dados pura, FVContainer não declara funções-membro próprias e, portanto, não define códigos de erro específicos nem lança exceções específicas da plataforma ([SWS_CM_11286]). Não obstante, existem pré-condições funcionais rigorosas para o uso dos atributos contidos:

  • Indicações inconsistentes de comprimento: a variável length define o comprimento do valor de frescor precisamente em bits ([SWS_CM_11344]), enquanto value mantém os dados em um vetor de bytes ([SWS_CM_11345]). Aplica-se a pré-condição de que o tamanho do vetor em bytes deve corresponder no mínimo ao número de bits arredondado para cima. Interpretação: se length apresentar um valor de 0 ou se a capacidade do vetor for inferior ao comprimento de bits especificado, a função FVM chamada deve rejeitar a entrada como inválida.
  • Erros de alocação de memória: ao atribuir ou aumentar o vetor value ([SWS_CM_11345]), pode ocorrer uma exceção do tipo std::bad_alloc em caso de esgotamento dos recursos de memória do sistema. A camada chamadora deve garantir, no nível da plataforma, que tais erros de alocação sejam interceptados de forma controlada.
  • Valores de frescor inválidos: se um valor de frescor não puder ser determinado ou verificado com sucesso pelo FVM, o sistema chamador não deve reutilizar os dados brutos remanescentes em FVContainer, para não comprometer a integridade da arquitetura de segurança.
