Atua como um contêiner de dados para a passagem de valores de atualização e seus comprimentos de bits na comunicação on-board segura.

A estrutura apext::com::secoc::FVContainer atua no módulo Communication Management como um contêiner de transporte para valores de atualização com o objetivo de proteger a comunicação on-board [SWS_CM_11286]. Ela encapsula o comprimento de bits do valor no campo length, bem como o próprio valor de atualização como um vetor de bytes no campo value [SWS_CM_11344]. Dependendo do contexto de uso, o vetor transporta valores completos ou truncados, sendo necessária uma sincronização externa em caso de concorrência devido à ausência de mecanismos internos de sincronização.

Contexto

A estrutura de dados apext::com::secoc::FVContainer é parte integrante das interfaces de extensão da plataforma (Platform Extension Interfaces) do módulo Communication Management e está declarada no cabeçalho apext/com/secoc/fvm.h [SWS_CM_11286]. De acordo com a arquitetura da AUTOSAR Adaptive Platform, as Platform Extension Interfaces destinam-se a ser utilizadas ou implementadas por fabricantes de veículos (OEM) ou integradores para adaptar a funcionalidade da plataforma a requisitos específicos do projeto (AUTOSAR_AP_SWS_CommunicationManagement p. 536 §C «Platform Extension Interfaces»).

No âmbito da comunicação on-board segura (Secure Onboard Communication, SecOC), apext::com::secoc::FVContainer atua como um contêiner de transferência de dados padronizado para valores de atualização (Freshness Values) [SWS_CM_11286]. A estrutura reúne duas informações correlacionadas: o comprimento exato do valor de atualização em bits no campo length [SWS_CM_11344], bem como os dados brutos do valor de atualização como um vetor de bytes no campo value [SWS_CM_11345]. Ela atua, dessa forma, como uma interface direta entre o AUTOSAR Communication Management e uma implementação específica do fabricante do Freshness Value Manager (FVM).

Diagrama de contexto: incorporação de FVContainer como objeto de transferência de dados entre o Communication Management e a extensão de plataforma FVM. Fontes: [SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement p. 536 §C «Platform Extension Interfaces».

Ciclo de vida

Como uma estrutura C++ (struct) [SWS_CM_11286] exclusivamente com variáveis de membro públicas, apext::com::secoc::FVContainer segue o padrão de projeto de um objeto de valor puro. A instanciação ocorre sob demanda, seja na pilha (stack) ou dinamicamente no heap pelo chamador ou chamado, dependendo se um valor de atualização é passado para um método ou fornecido como valor de retorno [SWS_CM_11345].

O tempo de vida de uma instância está diretamente vinculado ao vetor contido ara::core::Vector<std::uint8_t> [SWS_CM_11345]. Ao sair do escopo, todos os recursos de memória alocados para o valor de atualização são liberados de forma determinística. As operações de cópia e movimentação seguem a semântica padrão dos tipos std::uint64_t [SWS_CM_11344] e ara::core::Vector [SWS_CM_11345]. A estrutura não possui mecanismos internos de sincronização; o acesso concorrente entre diferentes threads deve ser, portanto, de total responsabilidade dos componentes que a utilizam (interpretação).

Caminho de utilização

O fluxo de uso típico inclui a criação, a inicialização e a posterior avaliação do contêiner durante a troca de valores de atualização para a proteção ou verificação de mensagens. Dependendo se apext::com::secoc::FVContainer atua como parâmetro de método ou como valor de retorno, o vetor value contém o valor de atualização completo ou um valor truncado (truncated value) [SWS_CM_11345].

No processo de verificação ou assinatura, o Communication Management solicita inicialmente um valor de atualização. O Freshness Value Manager instancia o contêiner, define o comprimento de bits significativo no campo length [SWS_CM_11344] e preenche o vetor value com os valores de bytes [SWS_CM_11345]. Após o retorno do contêiner, o Communication Management lê length e value, sendo que o comprimento de bits presumivelmente define o limite exato e os bits de preenchimento não utilizados no último byte do vetor são ignorados (interpretação).
