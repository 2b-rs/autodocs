Serve para a transferência, o processamento, a ativação e o monitoramento de pacotes de software e clusters de software no UCM.

A interface de serviço PackageManagement controla a transferência, o processamento e a ativação de pacotes de software na AUTOSAR Adaptive Platform [SWS_UCM_00345], [SWS_UCM_00352]. Ela permite o carregamento em blocos de pacotes, a extração de clusters de software e sua ativação controlada em coordenação com o State Management [SWS_UCM_00346], [SWS_UCM_00352]. Além disso, o serviço disponibiliza mecanismos para monitoramento de status, bem como para rollback e limpeza de dados de sessão [SWS_UCM_00353], [SWS_UCM_00361].

1. Papel e contexto de sistema da interface de serviço

O Service-Interface PackageManagement constitui a interface central do Update and Configuration Management (UCM) para gerenciamento, transferência e instalação de pacotes de software na AUTOSAR Adaptive Platform [SWS_UCM_00343]. A instância do UCM atua tipicamente como provedor de serviço (Skeleton), enquanto coordenadores de atualização ou clientes de diagnóstico de nível superior operam como consumidores de serviço (Proxy). Para identificação, o serviço fornece o identificador unívoco de instância de módulo por meio do método GetId [SWS_UCM_00343]. Durante o processo de ativação, o UCM interage estreitamente com o State Management, que deve liberar a sessão de atualização e executar verificações [SWS_UCM_00352].

2. Métodos, eventos e campos

Todos os métodos definidos na interface de serviço operam com semântica de chamada síncrona ou mensagens do tipo solicitação-resposta, uma vez que Fire & Forget false é especificado para todos os métodos [SWS_UCM_00345]. O campo de estado CurrentStatus possui um getter e um notifier, permitindo que os clientes assinem alterações de status do UCM baseadas em eventos ou as consultem ativamente [SWS_UCM_00361]. Adicionalmente, GetProgress fornece informações detalhadas de progresso para o respectivo estado ativo da máquina de estados [SWS_UCM_00360]. Para consultas ao inventário de software, estão disponíveis GetSwPackages para listar pacotes de software disponíveis [SWS_UCM_00359], GetSwClusterInfo para clusters de software instalados no estado kPresent [SWS_UCM_00357], GetSwClusterManifestInfo para dados de manifesto de cluster [SWS_UCM_00358], bem como GetSwClusterChangeInfo para alterações pendentes nos estados kAdded, kUpdating ou kRemoved [SWS_UCM_00356]. A rastreabilidade histórica das ações executadas é disponibilizada por meio de GetHistory com filtros de carimbo de data/hora [SWS_UCM_00355].

3. Ciclo de vida, fluxos de sessão e dependências de estado

Um fluxo típico de atualização divide-se em transferência, processamento, ativação e conclusão. A transferência do pacote é iniciada por TransferStart, gerando um TransferIdType e negociando o tamanho do bloco [SWS_UCM_00345], ou, alternativamente, registrada por RegisterSoftwarePackage mediante a especificação de uma URI de pacote [SWS_UCM_00344]. Na transferência por blocos, os blocos de dados são persistidos continuamente via TransferData com a indicação de um contador de blocos [SWS_UCM_00346] e finalizados com TransferExit [SWS_UCM_00347]. Em seguida, ProcessSwPackage extrai o pacote de software [SWS_UCM_00349]. Processamentos em andamento podem ser cancelados por meio de Cancel [SWS_UCM_00351] ou interrompidos e retomados com Suspend e Resume [SWS_UCM_00397], [SWS_UCM_00398]. Transferências não mais necessárias podem ser removidas com DeleteTransfer [SWS_UCM_00348]. Com Activate, os clusters de software extraídos são ativados [SWS_UCM_00352], enquanto Finish encerra a sessão de processamento e limpa os dados temporários [SWS_UCM_00354]. Caso ocorram erros, RevertProcessedSwPackages permite a reversão de pacotes processados [SWS_UCM_00350] e Rollback possibilita a restauração do estado do sistema anterior ao processamento do pacote [SWS_UCM_00353].

4. Tratamento de erros e Application Errors

Os métodos da interface resguardam condições de erro por meio de Application Errors específicos. Em chamadas fora de contexto, métodos como Activate, Cancel, Finish, ProcessSwPackage, TransferData e TransferExit retornam o erro kOperationNotPermitted [SWS_UCM_00346], [SWS_UCM_00347], [SWS_UCM_00349], [SWS_UCM_00352]. IDs de transferência inválidos são rejeitados com kTransferIdInvalid [SWS_UCM_00346], [SWS_UCM_00348], enquanto sequências de blocos incorretas ou restrições de memória resultam em kBlockIncorrect, kBlockSizeIncorrect, kBlockInconsistent ou kMemoryInsufficient [SWS_UCM_00345], [SWS_UCM_00346]. Verificações de segurança e consistência geram erros como kAuthenticationFailed, kPackageInconsistent, kPackageManifestInvalid e kPackageVersionIncompatible [SWS_UCM_00346], [SWS_UCM_00349]. A remoção do sistema central é impedida com kSwclRemovalDenied [SWS_UCM_00349]. Durante a ativação, kDependencyMissing, kUpdateSessionRejected ou kVerificationFailed sinalizam problemas de integração com dependências ou com o State Management [SWS_UCM_00352].

                                                                          TransferData (IN TransferIdType id, IN ByteVectorType Management data, IN uint64_t blockCounter)

  GERADO POR IA

  Perguntas em aberto (1)
  

                                                                          

                                                                          

                                                                          O método de serviço TransferData serve para a transferência em blocos de um pacote de software para o Update and Configuration Management Manager (UCM) dentro da interface de serviço PackageManagement ([SWS_UCM_00346]). Como o método não está definido como Fire & Forget, cada chamada retorna uma confirmação ou um erro de aplicação específico.
                                                                          

  
                                                                          Para a chamada, devem ser passados os seguintes parâmetros de entrada ([SWS_UCM_00346]):
                                                                          
  
                                                                            
    
                                                                          • id (TransferIdType): A identificação de transferência gerada anteriormente pelo UCM.
                                                                            • 
    
                                                                          • data (ByteVectorType Management): O bloco de dados úteis a ser transferido do pacote de software.
                                                                            • 
    
                                                                          • blockCounter (uint64_t): O contador sequencial do bloco de dados atual.
                                                                            • 
  
                                                                          

  
                                                                          Em relação à ordem e à interação, o método pressupõe uma chamada prévia de TransferStart ([SWS_UCM_00345]).
