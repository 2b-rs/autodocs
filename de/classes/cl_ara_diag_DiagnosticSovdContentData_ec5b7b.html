Kapselt Inhaltselemente und Ergebnisparameter für standardisierte SOVD-Diagnosedienste und -Operationsausführungen.

Die Struktur ara::diag::DiagnosticSovdContentData dient als standardisierter Datenbehälter zur Kapselung von Diagnoseinhalten für SOVD-Dienste in AUTOSAR Adaptive ([SWS_DM_02385]). Sie hält die Nutzdaten in einem öffentlichen Vektor von Inhaltselementen ([SWS_DM_02386]), aus denen das Diagnostic Management bei Operations- und Statusrückmeldungen das SOVD-Attribut parameters generiert. Als reines Wertübertragungsobjekt bietet die Struktur keine interne Thread-Synchronisation, weshalb nebenläufige Modifikationen anwendungsintern abgesichert werden müssen.

Kontext

Die Datenstruktur ara::diag::DiagnosticSovdContentData ist Teil des Diagnosemoduls (diag) der AUTOSAR Adaptive Platform und im Header ara/diag/diagnostic_sovd_content_data.h deklariert (AUTOSAR_AP_SWS_Diagnostics §8.59 „Header: ara/diag/diagnostic_sovd_content_data.h“, [SWS_DM_02385]). Sie fungiert als standardisierter Datenträger zur Kapselung von Diagnoseinhalten bei der Service-orientierten Fahrzeugdiagnose gemäß ASAM SOVD.

Innerhalb der Plattform vermittelt die Struktur zwischen dem Diagnose-Server (Diagnostic Management, DM) und den Dienstanbietern einer Adaptive Application ([SWS_DM_01396], [SWS_DM_02174]). Wird von einem externen SOVD-Client eine Operation oder eine Statusabfrage ausgelöst, delegiert das DM den Aufruf an die implementierende Softwarekomponente. Die erzeugten Ausgabedaten werden von der Anwendung in einer Instanz von DiagnosticSovdContentData abgelegt ([SWS_DM_02386]). Anschließend überführt das DM diese Inhalte in den SOVD-Antwortkörper, namentlich in das standardisierte Attribut parameters ([SWS_DM_02176], [SWS_DM_02181]).

Lebenszyklus

Die Definition als C++-struct (AUTOSAR_AP_SWS_Diagnostics §8.59.1.1 „Public Member Variables“, [SWS_DM_02385]) weist DiagnosticSovdContentData die Rolle eines Datenbehälters zu. Die Struktur besitzt die öffentliche Mitgliedsvariable elements vom Typ ara::core::Vector<DiagnosticSovdContentElementData> ([SWS_DM_02386]), in welcher die einzelnen Inhaltselemente dynamisch verwaltet werden.

Die Erzeugung der Instanz erfolgt typischerweise lokal innerhalb der Dienstanbieter-Methoden, sobald Diagnosedaten für eine Rückmeldung zusammengestellt werden. Bei asynchronen Schnittstellen wie Read (AUTOSAR_AP_SWS_Diagnostics §8.x „Read“) wird das Objekt in ein ara::core::Future<DiagnosticSovdContentData> gekapselt. Interpretation: Hierbei dürfte die Struktur per Wertübergabe oder Move-Semantik in den Besitz des Aufrufers übergehen, sodass ihre Lebensdauer an das verarbeitende Future-Objekt gebunden ist.

Hinsichtlich der Nebenläufigkeit enthält die Struktur keine internen Synchronisationsprimitive. Interpretation: Da es sich um ein reines Wertübertragungsobjekt (Value Object) handelt, dürfte kein interner Thread-Schutz existieren; nebenläufige Zugriffe auf dieselbe Instanz müssen somit durch die aufrufende Anwendungslogik synchronisiert werden. Die Zerstörung der Instanz erfolgt automatisch mit dem Verlassen des Gültigkeitsbereichs des verwaltenden Kontextes.

Nutzungspfad

Der primäre Nutzungspfad von DiagnosticSovdContentData liegt in der Bereitstellung von Nutzdaten bei synchronen Operationsausführungen sowie bei Statusabfragen im SOVD-Rahmenwerk:

  1. Ein externer SOVD-Client sendet eine Anforderung zum Start einer Operation gemäß ASAM SOVD an das Fahrzeug ([SWS_DM_01396]).
  2. Nach Validierung der Randbedingungen delegiert das Diagnostic Management die Ausführung an die zuständige Operation über ara::diag::GenericDiagnosticSovdOperation::StartExecution ([SWS_DM_02174]).
  3. Die Dienstanwendung führt die Diagnoseoperation aus, instanziiert DiagnosticSovdContentData und befüllt das Mitglied elements mit den erzeugten Elementdaten ([SWS_DM_02386]).
  4. Das Objekt wird im Rahmen des Rückgabewerts für synchrone Ausführungen an das Diagnostic Management übergeben ([SWS_DM_02176]).
  5. Das Diagnostic Management liest die Werte aus DiagnosticSovdContentData aus, überträgt sie in das Attribut parameters des SOVD-Antwortkörpers und sendet die Antwort an den Client ([SWS_DM_02176]).

Ein analoger Pfad gilt für die Statusabfrage über SovdOperationExecution::GetStatus ([SWS_DM_02180]), bei der das Attribut parameters ebenfalls aus den übergebenen DiagnosticSovdContentData abgeleitet wird ([SWS_DM_02181]). Ebenso nutzen Inhaltsanbieter dieselbe Struktur als Rückgabetyp über Read (AUTOSAR_AP_SWS_Diagnostics §8.x „Read“).
