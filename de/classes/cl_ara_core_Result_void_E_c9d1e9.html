class ara::core::Result< void, E >

Specialization of class Result for "void" values The implementation shall flag the condition E != ara::core::ErrorCode as a compile error

Kontext

Die Template-Klassenspezialisierung ara::core::Result<void, E> repräsentiert das Ergebnis von Operationen, die bei erfolgreicher Ausführung keinen Nutzdatenwert zurückgeben, sondern ausschließlich den Erfolg oder das Auftreten eines Fehlers signalisieren. Innerhalb der AUTOSAR Adaptive Platform dient sie als standardisierter Rückgabetyp für Funktionen mit void-Semantik und ermöglicht eine strukturierte Fehlerbehandlung ohne C++-Exceptions. Der Werttyp ist per Typ-Alias als value_type = void [SWS_CORE_00811] fest vorgegeben, während der Fehlertyp über den Typ-Alias error_type = E [SWS_CORE_00812] parametrisiert wird. Die Implementierung erzwingt zur Kompilierzeit, dass Bedingungen mit E != ara::core::ErrorCode zu einem Compilerfehler führen.

Als standardisierter Ergebnistyp bildet die Klasse die Schnittstelle zwischen aufrufenden Anwendungskomponenten und ausführenden Plattform- oder Anwendungsdiensten. Sie stellt sicher, dass wertlose Operationen dieselbe einheitliche Schnittstellenphilosophie und funktionale Weiterverarbeitung nutzen wie werttragende Spezialisierungen von ara::core::Result.

Lebenszyklus

Eine Instanz von ara::core::Result<void, E> befindet sich zu jedem Zeitpunkt in genau einem von zwei distinkten Zuständen: Sie repräsentiert entweder einen erfolgreichen Ablauf (Zustand mit void-Wert) oder einen Fehlerzustand mit enthaltenem Fehlerobjekt vom Typ E.

Die Erzeugung einer Erfolgsinstanz erfolgt über den parameterlosen Standardkonstruktor [SWS_CORE_00821] oder die statische Fabrikmethode FromValue() [SWS_CORE_00831]. Ein Fehlerzustand wird bei der Konstruktion durch Übergabe eines Fehlerobjekts als Lvalue [SWS_CORE_00823] oder Rvalue [SWS_CORE_00824] etabliert. Ergänzend stellen die statischen Methoden FromError() Fabriken zur Verfügung, die Fehler per Kopie [SWS_CORE_00834], per Verschiebung [SWS_CORE_00835] oder in-place aus Argumenten erzeugen [SWS_CORE_00836]. Letztere Überladung ist über SFINAE eingeschränkt und nimmt nur teil, wenn E aus den Argumenten konstruierbar ist und das erste Argument weder E noch eine Spezialisierung von Result darstellt [SWS_CORE_00836].

Die Klasse besitzt vollständige Werte- und Verschiebesemantik über den Kopierkonstruktor [SWS_CORE_00825], Kopierzuweisungsoperator [SWS_CORE_00841], Verschiebekonstruktor [SWS_CORE_00826] und Verschiebezuweisungsoperator [SWS_CORE_00842]. Bestehende Instanzen können zustandsverändernd überschrieben werden: EmplaceValue() versetzt die Instanz in den Zustand mit void-Wert [SWS_CORE_00843], während EmplaceError() einen Fehler in-place konstruiert [SWS_CORE_00844]. Mittels Swap() lassen sich zwei Instanzen vertauschen [SWS_CORE_00845].

Der Destruktor ~Result() ist trivial, wenn std::is_trivially_destructible<E>::value erfüllt ist [SWS_CORE_00827]. Bezüglich Nebenläufigkeit sind nicht-modifizierende Zugriffe wie HasValue() [SWS_CORE_00851] und der Lvalue-Fehlerzugriff Error() const & [SWS_CORE_00857] thread-safe. Modifizierende Aufrufe wie EmplaceValue() [SWS_CORE_00843], EmplaceError() [SWS_CORE_00844], Swap() [SWS_CORE_00845] sowie Move-Operationen [SWS_CORE_00826], [SWS_CORE_00835], [SWS_CORE_00842] sind explizit nicht thread-safe.

Nutzungspfad

Ein typischer Nutzungsablauf gliedert sich in die Erzeugung des Rückgabewerts durch den Dienstanbieter, die Prüfung durch den Aufrufer und die bedingte Weiterverarbeitung:

  1. Erzeugung des Ergebnisses: Eine Funktion schließt eine Operation erfolgreich ab und erzeugt das Rückgabeobjekt über Result::FromValue() [SWS_CORE_00831] oder den Standardkonstruktor [SWS_CORE_00821]. Schlägt die Operation fehl, liefert sie das Ergebnis über Result::FromError(...) [SWS_CORE_00834] zurück.
  2. Zustandsprüfung: Der Aufrufer evaluiert das Vorhandensein eines Erfolgs über HasValue() [SWS_CORE_00851] oder die boolesche Konvertierung operator bool() [SWS_CORE_00852], die bei Erfolg true und bei einem Fehler false liefern. Spezifische Fehlerwerte können direkt mit CheckError() abgeglichen werden [SWS_CORE_00865].
  3. Monadische Verkettung: Bei erfolgreichem Ausgang kann über Bind() eine Folgefunktion aufgerufen werden [SWS_CORE_00870]. Die übergebene Callable-Funktion wird nur ausgeführt, wenn die Instanz einen void-Wert enthält; liegt ein Fehler vor, wird die Funktion nicht aufgerufen und der bestehende Fehlerinhalt in das neue Ergebnisobjekt kopiert [SWS_CORE_00870].
  4. Fehlerabfrage und Auflösung: Die Methode Resolve() führt im Erfolgsfall keine Aktion aus, ruft aber im Fehlerfall eine übergebene Callable-Funktion mit const E& auf [SWS_CORE_00867]. Ein enthaltener Fehler kann zudem über Err() als ara::core::Optional<E> abgefragt [SWS_CORE_00868], [SWS_CORE_00869] oder mittels ErrorOr() mit einem Fallback-Fehler abgesichert werden [SWS_CORE_00863], [SWS_CORE_00864].

Fehlerszenarien

Beim Zugriff auf Instanzen von ara::core::Result<void, E> gelten strikte Vorbedingungen zur Vermeidung von Laufzeitverletzungen:

  • Zugriff auf fehlenden Wert (ResultWithNoValueViolation): Die Methoden Value() [SWS_CORE_00855] und operator*() [SWS_CORE_00853] existieren für die generische Programmierung und liefern void zurück. Wenn die Instanz keinen Wert enthält (also einen Fehler speichert), löst der Aufruf beider Funktionen eine ResultWithNoValueViolation aus [SWS_CORE_00853], [SWS_CORE_00855]. Die Funktion ValueOr() führt generisch keine Aktion aus und verursacht keine Verletzung [SWS_CORE_00861].
  • Zugriff auf fehlenden Fehler (ResultWithNoErrorViolation): Der direkte Zugriff auf das Fehlerobjekt über die Überladungen von Error() [SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876] setzt voraus, dass die Instanz einen Fehler enthält. Liegt stattdessen ein void-Wert vor, führt dies zu einer ResultWithNoErrorViolation.
  • Ausnahmeauslösung über ValueOrThrow: ValueOrThrow() wirft die mit dem enthaltenen Fehler verknüpfte Exception, falls kein Wert vorliegt [SWS_CORE_00866]. Sofern C++-Exceptions im Compiler-Toolchain deaktiviert sind, nimmt diese Funktion nicht an der Überladungsauflösung teil [SWS_CORE_00866].
  • Ausnahmesicherheit von Funktionsobjekten: Die Operationen Bind() [SWS_CORE_00870] und Resolve() [SWS_CORE_00867] sind als nicht ausnahmesicher spezifiziert; ihre Threadsicherheit hängt bedingt von der Threadsicherheit des jeweils übergebenen Callables ab.

Dieser Leitfaden basiert auf der AUTOSAR-Adaptive-Spezifikation R25-11 für ara::core::Result<void, E>.

<h4>Kontext</h4>
<p>Die Template-Klassenspezialisierung <code>ara::core::Result&lt;void, E&gt;</code> repräsentiert das Ergebnis von Operationen, die bei erfolgreicher Ausführung keinen Nutzdatenwert zurückgeben, sondern ausschließlich den Erfolg oder das Auftreten eines Fehlers signalisieren. Innerhalb der AUTOSAR Adaptive Platform dient sie als standardisierter Rückgabetyp für Funktionen mit void-Semantik und ermöglicht eine strukturierte Fehlerbehandlung ohne C++-Exceptions. Der Werttyp ist per Typ-Alias als <code>value_type = void</code> <a class="spec-record-ref" data-req="SWS_CORE_00811" href="../spec/record.html?id=SWS_CORE_00811">[SWS_CORE_00811]</a> fest vorgegeben, während der Fehlertyp über den Typ-Alias <code>error_type = E</code> <a class="spec-record-ref" data-req="SWS_CORE_00812" href="../spec/record.html?id=SWS_CORE_00812">[SWS_CORE_00812]</a> parametrisiert wird. Die Implementierung erzwingt zur Kompilierzeit, dass Bedingungen mit <code>E != ara::core::ErrorCode</code> zu einem Compilerfehler führen.</p>
<p>Als standardisierter Ergebnistyp bildet die Klasse die Schnittstelle zwischen aufrufenden Anwendungskomponenten und ausführenden Plattform- oder Anwendungsdiensten. Sie stellt sicher, dass wertlose Operationen dieselbe einheitliche Schnittstellenphilosophie und funktionale Weiterverarbeitung nutzen wie werttragende Spezialisierungen von <code>ara::core::Result</code>.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Result&lt;void, E&gt;</code> befindet sich zu jedem Zeitpunkt in genau einem von zwei distinkten Zuständen: Sie repräsentiert entweder einen erfolgreichen Ablauf (Zustand mit void-Wert) oder einen Fehlerzustand mit enthaltenem Fehlerobjekt vom Typ <code>E</code>.</p>
<p>Die Erzeugung einer Erfolgsinstanz erfolgt über den parameterlosen Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> oder die statische Fabrikmethode <code>FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a>. Ein Fehlerzustand wird bei der Konstruktion durch Übergabe eines Fehlerobjekts als Lvalue <a class="spec-record-ref" data-req="SWS_CORE_00823" href="../spec/record.html?id=SWS_CORE_00823">[SWS_CORE_00823]</a> oder Rvalue <a class="spec-record-ref" data-req="SWS_CORE_00824" href="../spec/record.html?id=SWS_CORE_00824">[SWS_CORE_00824]</a> etabliert. Ergänzend stellen die statischen Methoden <code>FromError()</code> Fabriken zur Verfügung, die Fehler per Kopie <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>, per Verschiebung <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a> oder in-place aus Argumenten erzeugen <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>. Letztere Überladung ist über SFINAE eingeschränkt und nimmt nur teil, wenn <code>E</code> aus den Argumenten konstruierbar ist und das erste Argument weder <code>E</code> noch eine Spezialisierung von <code>Result</code> darstellt <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>.</p>
<p>Die Klasse besitzt vollständige Werte- und Verschiebesemantik über den Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00825" href="../spec/record.html?id=SWS_CORE_00825">[SWS_CORE_00825]</a>, Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00841" href="../spec/record.html?id=SWS_CORE_00841">[SWS_CORE_00841]</a>, Verschiebekonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a> und Verschiebezuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>. Bestehende Instanzen können zustandsverändernd überschrieben werden: <code>EmplaceValue()</code> versetzt die Instanz in den Zustand mit void-Wert <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, während <code>EmplaceError()</code> einen Fehler in-place konstruiert <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>. Mittels <code>Swap()</code> lassen sich zwei Instanzen vertauschen <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>.</p>
<p>Der Destruktor <code>~Result()</code> ist trivial, wenn <code>std::is_trivially_destructible&lt;E&gt;::value</code> erfüllt ist <a class="spec-record-ref" data-req="SWS_CORE_00827" href="../spec/record.html?id=SWS_CORE_00827">[SWS_CORE_00827]</a>. Bezüglich Nebenläufigkeit sind nicht-modifizierende Zugriffe wie <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> und der Lvalue-Fehlerzugriff <code>Error() const &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a> thread-safe. Modifizierende Aufrufe wie <code>EmplaceValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, <code>EmplaceError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>, <code>Swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a> sowie Move-Operationen <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a> sind explizit nicht thread-safe.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungsablauf gliedert sich in die Erzeugung des Rückgabewerts durch den Dienstanbieter, die Prüfung durch den Aufrufer und die bedingte Weiterverarbeitung:</p>
<ol>
<li><strong>Erzeugung des Ergebnisses:</strong> Eine Funktion schließt eine Operation erfolgreich ab und erzeugt das Rückgabeobjekt über <code>Result::FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> oder den Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a>. Schlägt die Operation fehl, liefert sie das Ergebnis über <code>Result::FromError(...)</code> <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a> zurück.</li>
<li><strong>Zustandsprüfung:</strong> Der Aufrufer evaluiert das Vorhandensein eines Erfolgs über <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> oder die boolesche Konvertierung <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00852" href="../spec/record.html?id=SWS_CORE_00852">[SWS_CORE_00852]</a>, die bei Erfolg <code>true</code> und bei einem Fehler <code>false</code> liefern. Spezifische Fehlerwerte können direkt mit <code>CheckError()</code> abgeglichen werden <a class="spec-record-ref" data-req="SWS_CORE_00865" href="../spec/record.html?id=SWS_CORE_00865">[SWS_CORE_00865]</a>.</li>
<li><strong>Monadische Verkettung:</strong> Bei erfolgreichem Ausgang kann über <code>Bind()</code> eine Folgefunktion aufgerufen werden <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>. Die übergebene Callable-Funktion wird nur ausgeführt, wenn die Instanz einen void-Wert enthält; liegt ein Fehler vor, wird die Funktion nicht aufgerufen und der bestehende Fehlerinhalt in das neue Ergebnisobjekt kopiert <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>.</li>
<li><strong>Fehlerabfrage und Auflösung:</strong> Die Methode <code>Resolve()</code> führt im Erfolgsfall keine Aktion aus, ruft aber im Fehlerfall eine übergebene Callable-Funktion mit <code>const E&amp;</code> auf <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a>. Ein enthaltener Fehler kann zudem über <code>Err()</code> als <code>ara::core::Optional&lt;E&gt;</code> abgefragt <a class="spec-record-ref" data-req="SWS_CORE_00868" href="../spec/record.html?id=SWS_CORE_00868">[SWS_CORE_00868]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00869" href="../spec/record.html?id=SWS_CORE_00869">[SWS_CORE_00869]</a> oder mittels <code>ErrorOr()</code> mit einem Fallback-Fehler abgesichert werden <a class="spec-record-ref" data-req="SWS_CORE_00863" href="../spec/record.html?id=SWS_CORE_00863">[SWS_CORE_00863]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00864" href="../spec/record.html?id=SWS_CORE_00864">[SWS_CORE_00864]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Beim Zugriff auf Instanzen von <code>ara::core::Result&lt;void, E&gt;</code> gelten strikte Vorbedingungen zur Vermeidung von Laufzeitverletzungen:</p>
<ul>
<li><strong>Zugriff auf fehlenden Wert (ResultWithNoValueViolation):</strong> Die Methoden <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a> und <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a> existieren für die generische Programmierung und liefern <code>void</code> zurück. Wenn die Instanz keinen Wert enthält (also einen Fehler speichert), löst der Aufruf beider Funktionen eine <code>ResultWithNoValueViolation</code> aus <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a>. Die Funktion <code>ValueOr()</code> führt generisch keine Aktion aus und verursacht keine Verletzung <a class="spec-record-ref" data-req="SWS_CORE_00861" href="../spec/record.html?id=SWS_CORE_00861">[SWS_CORE_00861]</a>.</li>
<li><strong>Zugriff auf fehlenden Fehler (ResultWithNoErrorViolation):</strong> Der direkte Zugriff auf das Fehlerobjekt über die Überladungen von <code>Error()</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00858" href="../spec/record.html?id=SWS_CORE_00858">[SWS_CORE_00858]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00876" href="../spec/record.html?id=SWS_CORE_00876">[SWS_CORE_00876]</a> setzt voraus, dass die Instanz einen Fehler enthält. Liegt stattdessen ein void-Wert vor, führt dies zu einer <code>ResultWithNoErrorViolation</code>.</li>
<li><strong>Ausnahmeauslösung über ValueOrThrow:</strong> <code>ValueOrThrow()</code> wirft die mit dem enthaltenen Fehler verknüpfte Exception, falls kein Wert vorliegt <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>. Sofern C++-Exceptions im Compiler-Toolchain deaktiviert sind, nimmt diese Funktion nicht an der Überladungsauflösung teil <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>.</li>
<li><strong>Ausnahmesicherheit von Funktionsobjekten:</strong> Die Operationen <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a> und <code>Resolve()</code> <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a> sind als nicht ausnahmesicher spezifiziert; ihre Threadsicherheit hängt bedingt von der Threadsicherheit des jeweils übergebenen Callables ab.</li>
</ul>

<h4>Kontext</h4>
<p>Die Template-Klassenspezialisierung <code>ara::core::Result&lt;void, E&gt;</code> repräsentiert das Ergebnis von Operationen, die bei erfolgreicher Ausführung keinen Nutzdatenwert zurückgeben, sondern ausschließlich den Erfolg oder das Auftreten eines Fehlers signalisieren. Innerhalb der AUTOSAR Adaptive Platform dient sie als standardisierter Rückgabetyp für Funktionen mit void-Semantik und ermöglicht eine strukturierte Fehlerbehandlung ohne C++-Exceptions. Der Werttyp ist per Typ-Alias als <code>value_type = void</code> <a class="spec-record-ref" data-req="SWS_CORE_00811" href="../spec/record.html?id=SWS_CORE_00811">[SWS_CORE_00811]</a> fest vorgegeben, während der Fehlertyp über den Typ-Alias <code>error_type = E</code> <a class="spec-record-ref" data-req="SWS_CORE_00812" href="../spec/record.html?id=SWS_CORE_00812">[SWS_CORE_00812]</a> parametrisiert wird. Die Implementierung erzwingt zur Kompilierzeit, dass Bedingungen mit <code>E != ara::core::ErrorCode</code> zu einem Compilerfehler führen.</p>
<p>Als standardisierter Ergebnistyp bildet die Klasse die Schnittstelle zwischen aufrufenden Anwendungskomponenten und ausführenden Plattform- oder Anwendungsdiensten. Sie stellt sicher, dass wertlose Operationen dieselbe einheitliche Schnittstellenphilosophie und funktionale Weiterverarbeitung nutzen wie werttragende Spezialisierungen von <code>ara::core::Result</code>.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Result&lt;void, E&gt;</code> befindet sich zu jedem Zeitpunkt in genau einem von zwei distinkten Zuständen: Sie repräsentiert entweder einen erfolgreichen Ablauf (Zustand mit void-Wert) oder einen Fehlerzustand mit enthaltenem Fehlerobjekt vom Typ <code>E</code>.</p>
<p>Die Erzeugung einer Erfolgsinstanz erfolgt über den parameterlosen Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> oder die statische Fabrikmethode <code>FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a>. Ein Fehlerzustand wird bei der Konstruktion durch Übergabe eines Fehlerobjekts als Lvalue <a class="spec-record-ref" data-req="SWS_CORE_00823" href="../spec/record.html?id=SWS_CORE_00823">[SWS_CORE_00823]</a> oder Rvalue <a class="spec-record-ref" data-req="SWS_CORE_00824" href="../spec/record.html?id=SWS_CORE_00824">[SWS_CORE_00824]</a> etabliert. Ergänzend stellen die statischen Methoden <code>FromError()</code> Fabriken zur Verfügung, die Fehler per Kopie <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>, per Verschiebung <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a> oder in-place aus Argumenten erzeugen <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>. Letztere Überladung ist über SFINAE eingeschränkt und nimmt nur teil, wenn <code>E</code> aus den Argumenten konstruierbar ist und das erste Argument weder <code>E</code> noch eine Spezialisierung von <code>Result</code> darstellt <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>.</p>
<p>Die Klasse besitzt vollständige Werte- und Verschiebesemantik über den Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00825" href="../spec/record.html?id=SWS_CORE_00825">[SWS_CORE_00825]</a>, Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00841" href="../spec/record.html?id=SWS_CORE_00841">[SWS_CORE_00841]</a>, Verschiebekonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a> und Verschiebezuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>. Bestehende Instanzen können zustandsverändernd überschrieben werden: <code>EmplaceValue()</code> versetzt die Instanz in den Zustand mit void-Wert <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, während <code>EmplaceError()</code> einen Fehler in-place konstruiert <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>. Mittels <code>Swap()</code> lassen sich zwei Instanzen vertauschen <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>.</p>
<p>Der Destruktor <code>~Result()</code> ist trivial, wenn <code>std::is_trivially_destructible&lt;E&gt;::value</code> erfüllt ist <a class="spec-record-ref" data-req="SWS_CORE_00827" href="../spec/record.html?id=SWS_CORE_00827">[SWS_CORE_00827]</a>. Bezüglich Nebenläufigkeit sind nicht-modifizierende Zugriffe wie <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> und der Lvalue-Fehlerzugriff <code>Error() const &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a> thread-safe. <h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungsablauf gliedert sich in die Erzeugung des Rückgabewerts durch den Dienstanbieter, die Prüfung durch den Aufrufer und die bedingte Weiterverarbeitung:</p>
<ol>
<li><strong>Erzeugung des Ergebnisses:</strong> Eine Funktion schließt eine Operation erfolgreich ab und erzeugt das Rückgabeobjekt über <code>Result::FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> oder den Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a>. Schlägt die Operation fehl, liefert sie das Ergebnis über <code>Result::FromError(...)</code> <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a> zurück.</li>
<li><strong>Zustandsprüfung:</strong> Der Aufrufer evaluiert das Vorhandensein eines Erfolgs über <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> oder die boolesche Konvertierung <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00852" href="../spec/record.html?id=SWS_CORE_00852">[SWS_CORE_00852]</a>, die bei Erfolg <code>true</code> und bei einem Fehler <code>false</code> liefern. Spezifische Fehlerwerte können direkt mit <code>CheckError()</code> abgeglichen werden <a class="spec-record-ref" data-req="SWS_CORE_00865" href="../spec/record.html?id=SWS_CORE_00865">[SWS_CORE_00865]</a>.</li>
<li><strong>Monadische Verkettung:</strong> Bei erfolgreichem Ausgang kann über <code>Bind()</code> eine Folgefunktion aufgerufen werden <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>. Die übergebene Callable-Funktion wird nur ausgeführt, wenn die Instanz einen void-Wert enthält; liegt ein Fehler vor, wird die Funktion nicht aufgerufen und der bestehende Fehlerinhalt in das neue Ergebnisobjekt kopiert <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>.</li>
<li><strong>Fehlerabfrage und Auflösung:</strong> Die Methode <code>Resolve()</code> führt im Erfolgsfall keine Aktion aus, ruft aber im Fehlerfall eine übergebene Callable-Funktion mit <code>const E&amp;</code> auf <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a>. Ein enthaltener Fehler kann zudem über <code>Err()</code> als <code>ara::core::Optional&lt;E&gt;</code> abgefragt <a class="spec-record-ref" data-req="SWS_CORE_00868" href="../spec/record.html?id=SWS_CORE_00868">[SWS_CORE_00868]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00869" href="../spec/record.html?id=SWS_CORE_00869">[SWS_CORE_00869]</a> oder mittels <code>ErrorOr()</code> mit einem Fallback-Fehler abgesichert werden <a class="spec-record-ref" data-req="SWS_CORE_00863" href="../spec/record.html?id=SWS_CORE_00863">[SWS_CORE_00863]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00864" href="../spec/record.html?id=SWS_CORE_00864">[SWS_CORE_00864]</a>.</li>
</ol>

<li><strong>Zugriff auf fehlenden Wert (ResultWithNoValueViolation):</strong> Die Methoden <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a> und <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a> existieren für die generische Programmierung und liefern <code>void</code> zurück.
