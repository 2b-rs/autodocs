Ermöglicht das Warten auf den Abschluss einer asynchronen Operation ohne Rückgabewert sowie die Entnahme des Fehlerstatus.

Die Klasse ara::core::Future<void, E> ermöglicht die asynchrone Synchronisation und Fehlerprüfung von Operationen ohne Rückgabewert in AUTOSAR Adaptive [SWS_CORE_06236]. Als nicht-kopierbarer Typ erlaubt sie das Warten auf den Abschluss sowie die ausnahmesichere Ergebnisabholung als ara::core::Result<void, E> [SWS_CORE_06236] oder die asynchrone Weiterverarbeitung per Fortsetzungsfunktion [SWS_CORE_06231]. Nach Entnahme des Ergebnisses wird der geteilte Zustand invalidiert, sodass Folgeaufrufe ohne gültigen Zustand eine Verletzung darstellen [SWS_CORE_06236].

Kontext

Die Template-Klassenspezialisierung ara::core::Future<void, E> repräsentiert das Empfängerende einer asynchronen Operation in AUTOSAR Adaptive, die bei erfolgreichem Abschluss keinen Wert zurückliefert, sondern rein den Eintritt des Ereignisses oder einen aufgetretenen Fehler signalisiert. Gemäß der Klassenbeschreibung muss die Implementierung die Bedingung E != ara::core::ErrorCode mit einem Übersetzungsfehler quittieren. Die Klasse interagiert typischerweise mit einem korrespondierenden ara::core::Promise, das den geteilten Zustand (Shared State) befüllt [SWS_CORE_06236], sowie mit asynchronen Ausführungskontexten bei der Registrierung von Fortsetzungsfunktionen [SWS_CORE_06237].

Lebenszyklus

Instanzen von ara::core::Future<void, E> sind reine Move-Semantik-Objekte: Der Kopierkonstruktor [SWS_CORE_06234] sowie der Kopierzuweisungsoperator [SWS_CORE_06235] sind gelöscht (delete). Ein über den Standardkonstruktor erzeugtes Objekt besitzt keinen geteilten Zustand und verhält sich analog zu std::future [SWS_CORE_06222]. Mittels Verschiebekonstruktion [SWS_CORE_06223] oder Verschiebezuweisung [SWS_CORE_06225] übernimmt eine Instanz den Besitz eines Shared State von einer anderen Instanz.

Der Lebenszyklus wird maßgeblich durch den Zustand des Shared State geprägt. Über die Methode valid() kann geprüft werden, ob die Instanz an einen Shared State gebunden und damit nutzbar ist [SWS_CORE_06227]. Sobald das Ergebnis mittels GetResult() [SWS_CORE_06236] oder get() [SWS_CORE_06226] abgeholt oder eine Fortsetzung über then() [SWS_CORE_06231] registriert wird, verliert das Future-Objekt seinen Shared State und valid() liefert false. Der Destruktor gibt einen verbliebenen geteilten Zustand frei [SWS_CORE_06233]. Hinsichtlich der Nebenläufigkeit sind Prüf- und Zerstörungsoperationen wie valid() [SWS_CORE_06227], is_ready() [SWS_CORE_06232] und der Destruktor [SWS_CORE_06233] threadsicher, während zustandsverändernde Operationen wie GetResult() [SWS_CORE_06236], get() [SWS_CORE_06226] und die Wartefunktionen [SWS_CORE_06228] nicht threadsicher sind.

Nutzungspfad

Im synchronen Nutzungspfad wartet ein Konsument auf die Fertigstellung der asynchronen Operation. Mit is_ready() lässt sich blockadearm abfragen, ob ein Wert oder ein Fehler vorliegt [SWS_CORE_06232]. Alternativ kann mittels wait() blockierend gewartet werden [SWS_CORE_06228], oder zeitlich begrenzt über wait_for() [SWS_CORE_06229] und wait_until() [SWS_CORE_06230]. Ist das Ergebnis verfügbar, erfolgt die Wertabfrage vorzugsweise ausnahmesicher über GetResult(), wodurch ein ara::core::Result<void, E> zurückgegeben wird [SWS_CORE_06236].

Im asynchronen Pfad erlaubt die Methode then() die Registrierung einer Fortsetzungsfunktion (Continuation), die ausgeführt wird, sobald das Ergebnis vorliegt [SWS_CORE_06231]. Hierbei kann optional ein Ausführungskontext (Executor) übergeben werden [SWS_CORE_06237]. Die Continuation nimmt das Result<void, E> als Rvalue entgegen. Der Rückgabetyp von then() entpackt geschachtelte Future- oder Result-Typen automatisch (Unwrapping) [SWS_CORE_06231].

Fehlerszenarien

Wird eine zustandsabhängige Operation (wie GetResult(), is_ready(), wait(), wait_for(), wait_until() oder then()) auf einer ungültigen Instanz (valid() == false) aufgerufen, liegt eine Verletzung der Vorbedingung vor, die als FutureInvalidViolation behandelt wird [SWS_CORE_06228], [SWS_CORE_06229], [SWS_CORE_06230], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06236], [SWS_CORE_06237]. Bei Aufruf von get() auf einer ungültigen Instanz wird stattdessen eine FutureException mit dem Fehlercode kNoState ausgelöst [SWS_CORE_06226]; get() nimmt bei deaktivierten C++-Exceptions nicht an der Überladungsauflösung teil [SWS_CORE_06226].

Wurde das korrespondierende Promise zerstört oder hat es den geteilten Zustand verlassen, ohne ein Ergebnis oder einen expliziten Fehler zu setzen, wird der Fehlercode FutureErrc::kBrokenPromise gemäß [SWS_CORE_00400] im Shared State hinterlegt [SWS_CORE_06226], [SWS_CORE_06236]. Dieser wird von GetResult() als Fehler im Result<void, E> zurückgegeben [SWS_CORE_06236]. Wirft eine in then() registrierte Continuation eine Ausnahme, die keine Verletzung implementiert, führt dies zur FutureContinuationHasThrownViolation [SWS_CORE_06231], [SWS_CORE_06237].

Dieser Leitfaden basiert ausschließlich auf der AUTOSAR-Spezifikation für ara::core::Future<void, E> im Release R25-11.

                  Die Elementfunktion get der Spezialisierung ara::core::Future<void, E> dient dem Warten auf das Ergebnis einer asynchronen Operation ohne Rückgabewert ([SWS_CORE_06226]). Sie verhält sich wie die entsprechende Funktion von std::future und blockiert den Aufrufer, bis das Ergebnis oder ein Fehler bereitsteht ([SWS_CORE_06226], [SWS_CORE_00336]). Nach dem Aufruf verliert die Future-Instanz ihre Gültigkeit, sodass valid() == false gilt ([SWS_CORE_06226]).
                  
  
                  Die Funktion ist nicht ausnahmesicher (not exception safe) deklariert ([SWS_CORE_06226]). Wurde im verknüpften Promise ein Fehler hinterlegt, wird eine entsprechende Ausnahme ausgelöst ([SWS_CORE_06226]). Wurde der gemeinsame Zustand vorzeitig aufgegeben, tritt der Fehlercode kBrokenPromise gemäß [SWS_CORE_00400] auf ([SWS_CORE_06226]). Wird get auf einer bereits ungültigen Instanz ausgeführt, wirft die Funktion eine FutureException mit dem Fehlercode kNoState ([SWS_CORE_06226]).
                  
  
                  Hinsichtlich der Nebenläufigkeit ist die Methode nicht threadsicher (not thread-safe) ([SWS_CORE_06226]). Parallele Zugriffe auf dasselbe Objekt bedürfen daher einer externen Synchronisation. Des Weiteren nimmt die Funktion nicht an der Überladungsauflösung teil, wenn C++-Ausnahmen in der Compiler-Toolchain deaktiviert sind ([SWS_CORE_06226]).
                  
  
                  Im Zusammenspiel mit verwandten Funktionen stellt [SWS_CORE_00332] (is_ready) sicher, dass get garantiert nicht blockiert, falls die Operation bereits fertiggestellt ist. Für Kontexte ohne Ausnahmen bietet AUTOSAR als Alternative [SWS_CORE_00336] (GetResult), welches Fehler über einen Ergebnis-Typ zurückmeldet, anstatt Ausnahmen zu werfen.
