class ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Dient dem gepufferten Schreiben von Binär- und Textdateien sowie deren Synchronisation auf den physischen Speicher.

Die Klasse ara::per::WriteAccessor ermöglicht das Schreiben binärer oder textueller Dateiinhalte im Persistenzmodul und stellt Methoden für unformatierte Schreibzugriffe sowie einen formatierten Stream-Operator bereit [SWS_PER_00423]. Da Schreibvorgänge zunächst im Betriebssystem gepuffert werden können, erzwingt der Aufruf von SyncToFile() das dauerhafte Flashen auf den physischen Speicher [SWS_PER_00122]. Sämtliche Methoden sind ausnahmesicher, jedoch nicht threadsicher, weshalb nebenläufige Zugriffe durch die Anwendung geschützt werden müssen.

Kontext

ara::per::WriteAccessor ist eine finale Klasse des Persistenzmoduls (per) der AUTOSAR Adaptive Platform und leitet virtuell von FileAccessor ab. Die Klasse stellt Schreiboperationen für Dateiinhalte bereit. Sie bietet Methoden für unformatiertes, kontrolliertes Schreiben mit Fehlerbehandlung über ara::core::Result sowie einen überladenen Stream-Operator für formatiertes Schreiben. Als Interaktionspartner fungieren die aufrufende Anwendung, der interne Dateipuffer des Betriebssystems sowie das physische Speichermedium.

Lebenszyklus

Der Standardkonstruktor von WriteAccessor ist explizit gelöscht und darf nicht verwendet werden [SWS_PER_00596]. (Interpretation: Instanzen von WriteAccessor dürften über Fabrikmethoden übergeordneter Persistenz-Verwaltungseinheiten wie dem File-Storage erzeugt und bereitgestellt werden.) Frage Q-af92be8494274611 (offen)

Die Zerstörung erfolgt über den virtuellen Destruktor ~WriteAccessor() [SWS_PER_00597]. Die Klasse und ihre Methoden sind als ausnahmesicher („exception safe“) spezifiziert und als noexcept deklariert. Bezüglich der Nebenläufigkeit ist WriteAccessor nicht threadsicher („not thread-safe“) [SWS_PER_00597]; parallele Zugriffe auf dieselbe Instanz müssen von der Anwendung extern abgesichert werden.

Nutzungspfad

Der reguläre Ablauf umfasst das Schreiben von Daten in unformatiertem oder formatiertem Modus, das optionale Anpassen der Dateigröße und die abschließende persistente Speicherung:

  • Binärdaten schreiben: Über WriteBinary() wird ein Byte-Bereich (ara::core::Span<const ara::core::Byte>) in die Datei geschrieben [SWS_PER_00423].
  • Textdaten schreiben: Mittels WriteText() werden Zeichenketten über einen ara::core::StringView übergeben [SWS_PER_00166]. Ergänzend steht operator<< als Komfortfunktion für unkritische Anwendungsfälle zur Verfügung, wobei auftretende Fehler stillschweigend ignoriert werden [SWS_PER_00125].
  • Persistierung erzwingen: Der Zeitpunkt der physischen Speicherung hängt von der Persistenz-Implementierung ab; SyncToFile() flasht den Puffer des Betriebssystems verbindlich auf das Speichermedium [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Dateigröße anpassen: Mit SetFileSize() kann die Datei verkürzt werden, wodurch überstehende Inhalte entfernt werden; die Dateiposition bleibt unverändert oder wird auf die letzte gültige Position bzw. 0 gesetzt [SWS_PER_00428].

Fehlerszenarien

Die Methoden WriteBinary(), WriteText(), SyncToFile() und SetFileSize() geben ein ara::core::Result<void> zurück, das bei Fehlschlägen spezifische Fehlercodes enthält:

  • PerErrc::kPhysicalStorageFailure: Zugriff auf das physische Speichermedium schlägt fehl [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Der Zustand der Datei ist unbekannt und kann komplett zerstört sein (keine Rollback-Semantik).
  • PerErrc::kOutOfStorageSpace: Unzureichender physischer Speicherplatz [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. Beim Schreiben wird der überschreitende Anteil verworfen und die Position steht am Dateiende (keine Rollback-Semantik).
  • PerErrc::kQuotaExceeded: Die Datei würde die konfigurierte Maximalgröße (AllowedSize) überschreiten [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (Rollback-Semantik).
  • PerErrc::kEncryptionFailed: Ver- oder Entschlüsselung schlägt fehl [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Puffer und Position werden zwar aktualisiert, die Datei kann aber nicht persistiert werden und spiegelt auf dem Speicher eine ältere Version wider (Rollback-Semantik).
  • PerErrc::kAuthenticationFailed: Berechnung oder Prüfung des MAC schlägt fehl [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (Rollback-Semantik).
  • PerErrc::kValidationFailed: Gültigkeit der gespeicherten Daten kann nicht gewährleistet werden [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (Rollback-Semantik).
  • PerErrc::kInvalidSize: Die neue Dateigröße bei SetFileSize() ist größer als die aktuelle Dateigröße [SWS_PER_00428] (Rollback-Semantik).

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed.       Die Memberfunktion SyncToFile der Klasse ara::per::WriteAccessor (definiert in #include "ara/per/write_accessor.h") überträgt den aktuellen Dateiinhalt synchron auf den physischen Speicher [SWS_PER_00122].       Bei der Durchführung können unterschiedliche Fehlerfälle auftreten, die teilweise Rollback-Semantik besitzen [SWS_PER_00122]:
      

        

      • StorageFailure: Tritt auf, wenn der physische Zugriff auf das Speichermedium fehlschlägt (keine Rollback-Semantik) [SWS_PER_00122].
        • 

      • PerErrc::kOutOfStorageSpace: Wird zurückgegeben, falls der physische Speicherplatz für die geänderte Datei unzureichend ist (keine Rollback-Semantik) [SWS_PER_00122].

        • 

      • PerErrc::kEncryptionFailed: Scheitert die Verschlüsselung der gespeicherten Daten (mit Rollback-Semantik) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed: Schlägt die Berechnung des MAC für die Daten fehl (mit Rollback-Semantik) [SWS_PER_00122].
        •

Da sie jedoch ausdrücklich als not thread-safe eingestuft ist, müssen gleichzeitige Aufrufe auf derselben WriteAccessor-Instanz vermutlich durch den Aufrufer synchronisiert werden [SWS_PER_00122].               Die Funktion WriteBinary der Klasse ara::per::WriteAccessor schreibt den Inhalt einer Byte-Sequenz (ara::core::Span<const ara::core::Byte>) in eine Datei [SWS_PER_00423]. Der Zeitpunkt der tatsächlichen Persistierung auf dem Speichermedium hängt von der Implementierung von Persistency ab; über SyncToFile kann das synchrone Persistieren forciert werden [SWS_PER_00423]. Die Funktion ist als noexcept deklariert und gilt als ausnahmesicher [SWS_PER_00423].
              

              In Bezug auf Nebenläufigkeit ist WriteBinary als nicht threadsicher (not thread-safe) spezifiziert [SWS_PER_00423]. Parallele Zugriffe auf denselben Accessor müssen auf Anwendungsebene synchronisiert werden.
              

              Im Fehlerfall wird ein Fehlercode in ara::core::Result<void> zurückgegeben, wobei der Dateiinhalt beschädigt sein und sich die aktuelle Position verändert haben kann [SWS_PER_00423]:
              

                

              • PerErrc::kPhysicalStorageFailure: Zustand der Datei ist unbekannt und kann vollständig zerstört sein (keine Rollback-Semantik) [SWS_PER_00423].
                •

SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed.
