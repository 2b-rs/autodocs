class ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Kontext

Die Klasse ara::per::WriteAccessor stellt die Schnittstelle für den schreibenden Dateizugriff innerhalb der AUTOSAR Adaptive Platform dar. Sie erbt virtuell von FileAccessor und übernimmt die Verantwortung für das gezielte Modifizieren, Überschreiben sowie Kürzen persistenter Dateiinhalte. Für die Datenübergabe stellt sie unformatierte Schreibmethoden bereit: WriteBinary nimmt Rohdaten als ara::core::Span<const ara::core::Byte> entgegen ([SWS_PER_00423]), während WriteText Zeichenfolgen in Form von ara::core::StringView verarbeitet ([SWS_PER_00166]). Ergänzend bietet der überladene Streaming-Operator operator<< eine vereinfachte Möglichkeit für formatierte Textausgaben ([SWS_PER_00125]).

Ein wesentliches Merkmal von WriteAccessor ist die Entkopplung von virtuellem Schreiben und physischer Persistierung: Daten werden bei Aufrufen von WriteBinary oder WriteText zunächst in Pufferstrukturen überführt. Der exakte Zeitpunkt, zu dem diese Daten dauerhaft auf dem Speichermedium abgelegt werden, ist implementierungsabhängig ([SWS_PER_00423], [SWS_PER_00166]). Um das sofortige Schreiben aus dem Betriebssystempuffer in den physischen Speicher zu erzwingen, stellt die Klasse die Synchronisationsmethode SyncToFile bereit ([SWS_PER_00122]). Darüber hinaus ermöglicht SetFileSize das Verkleinern bestehender Dateien auf eine vorgegebene Bytegröße ([SWS_PER_00428]).

Lebenszyklus

Der Standardkonstruktor von WriteAccessor ist explizit gelöscht (WriteAccessor() = delete;, [SWS_PER_00596]). Eine direkte, uninitialisierte Instanziierung durch die Anwendung ist damit nicht zulässig; gültige Instanzen dürften typischerweise von übergeordneten Persistenz-Verwaltungseinheiten beim Öffnen von Dateien im Schreibmodus erzeugt und übergeben werden. Die Zerstörung und Ressourcenfreigabe erfolgt deterministisch über den virtuellen Destruktor ~WriteAccessor() ([SWS_PER_00597]).

Bezüglich der Nebenläufigkeit sind sämtliche Elementfunktionen von WriteAccessor als nicht threadsicher („not thread-safe“) spezifiziert ([SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00125], [SWS_PER_00428], [SWS_PER_00122], [SWS_PER_00597]). Greifen mehrere Ausführungsstränge zeitgleich auf dieselbe Instanz zu, obliegt die threadübergreifende Synchronisation der aufrufenden Anwendung. Alle Operationen sind als noexcept deklariert und gewährleisten Exceptionsicherheit („exception safe“), da Rückmeldungen und Fehlerzustände nicht über C++-Ausnahmen, sondern über den Rückgabetyp ara::core::Result<void> signalisiert werden.

Nutzungspfad

Die typische Verwendung von WriteAccessor gliedert sich in Datenübertragung, optionale Größenanpassung und die explizite Synchronisation mit dem Speichermedium:

  1. Daten schreiben: Die Anwendung übergibt Datenblöcke sequenziell mittels WriteBinary ([SWS_PER_00423]) oder WriteText ([SWS_PER_00166]). Beide Methoden geben ein ara::core::Result<void> zurück, das auf Erfolg geprüft werden muss. Für unkritische Anwendungsfälle kann alternativ operator<< verwendet werden ([SWS_PER_00125]).
  2. Dateigröße anpassen (optional): Soll die Datei gekürzt werden, wird SetFileSize aufgerufen ([SWS_PER_00428]). Liegt die aktuelle Dateiposition jenseits der neuen Zielgröße, wird sie auf das neue Dateiende gesetzt; bei einer Zielgröße von 0 wird die Position ebenfalls auf 0 gesetzt.
  3. Persistierung erzwingen: Um sicherzustellen, dass modifizierte Daten im Fehlerfall oder bei Spannungsverlust nicht im flüchtigen Puffer verbleiben, ruft die Anwendung SyncToFile auf ([SWS_PER_00122]), wodurch der Pufferinhalt verbindlich auf das physikalische Medium geschrieben wird.

Fehlerszenarien

Die Spezifikation unterscheidet bei Fehlern strikt nach der verwendeten Schnittstelle sowie zwischen Fehlern mit und ohne Rollback-Semantik:

  • Stillschweigendes Ignorieren bei operator<<: Tritt während der Nutzung des Streaming-Operators ein Fehler auf, wird dieser ohne Rückmeldung ignoriert ([SWS_PER_00125]). Dieser Operator ist ausdrücklich als Komfortfunktion für unkritische Pfade vorgesehen und darf in sicherheitsrelevanten Anwendungsfällen nicht zum Einsatz kommen.
  • Fehler bei WriteBinary und WriteText: Schlägt ein Schreibvorgang fehl, kann der Dateiinhalt beschädigt sein ([SWS_PER_00423], [SWS_PER_00166]). Bei PerErrc::kPhysicalStorageFailure („no_rollback_semantics“) ist der Zustand der Datei undefiniert; sie kann vollständig zerstört sein. Bei PerErrc::kOutOfStorageSpace („no_rollback_semantics“) wird der Dateiinhalt aktualisiert, jedoch der über den verfügbaren Speicherplatz hinausgehende Teil verworfen; die Dateiposition steht am Dateiende. Tritt PerErrc::kEncryptionFailed („rollback_semantics“) auf, wurden Puffer und Position zwar aktualisiert, die Änderungen konnten jedoch nicht persistiert werden, wodurch die gespeicherte Datei auf einem älteren Stand verbleibt. Weitere mögliche Fehler mit Rollback-Semantik sind PerErrc::kQuotaExceeded (Überschreitung der konfigurierten AllowedSize des File Storage), PerErrc::kValidationFailed (Validierung fehlgeschlagen) sowie PerErrc::kAuthenticationFailed (Fehler bei MAC-Berechnung oder -Prüfung).
  • Fehler bei SetFileSize: Die Methode dient ausschließlich der Reduzierung der Dateigröße. Ist der Parameter size größer als die aktuelle Dateigröße, schlägt der Aufruf mit PerErrc::kInvalidSize fehl ([SWS_PER_00428]). Zudem können PerErrc::kPhysicalStorageFailure, PerErrc::kValidationFailed, PerErrc::kEncryptionFailed und PerErrc::kAuthenticationFailed auftreten.
  • Fehler bei SyncToFile: Beim Leeren des Puffers auf das Medium können PerErrc::kPhysicalStorageFailure und PerErrc::kOutOfStorageSpace (ohne Rollback) sowie PerErrc::kEncryptionFailed, PerErrc::kQuotaExceeded und PerErrc::kAuthenticationFailed (mit Rollback) gemeldet werden ([SWS_PER_00122]).

Dieser Klassen-Leitfaden basiert auf der Spezifikation AUTOSAR Adaptive Platform R25-11 (Modul per).

WriteBinary function

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;
