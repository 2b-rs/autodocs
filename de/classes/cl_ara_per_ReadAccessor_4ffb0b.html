class ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Ermöglicht das blockweise, zeilenweise oder zeichenbasierte Lesen persistierter Datei- und Binärdaten.

Die Klasse ara::per::ReadAccessor stellt synchrone Methoden zum sequenziellen und zeilenbasierten Lesen von Dateien im Binär- und Textmodus bereit [SWS_PER_00421], [SWS_PER_00119]. Neben dem konsumierenden Lesen erlaubt sie die zeigerneutrale Vorschau auf folgende Bytes oder Zeichen. Da Instanzen nicht threadsicher sind, müssen parallele Zugriffe extern koordiniert werden, während im Fehlerfall eine Rollback-Garantie die Lesezeigerposition schützt [SWS_PER_00419].

Kontext und Aufgabenbereich

Die Klasse ara::per::ReadAccessor stellt eine Schnittstelle zum synchronen Lesen von Dateiinhalten innerhalb der Persistenzverwaltung (Modul per) bereit und leitet virtuell von FileAccessor ab. Sie abstrahiert den Lesezugriff auf persistierte Datenspeicher und stellt sowohl binäre als auch textuelle Zugriffsmethoden bereit. Anwendungen können über spezialisierte Funktionen einzelne Bytes oder Zeichen prüfen und abrufen sowie zusammenhängende Blöcke oder vollständige Zeilen einlesen.

Lebenszyklus und Nebenläufigkeit

Der Standardkonstruktor von ReadAccessor ist gelöscht [SWS_PER_00461]; die Instanziierung erfolgt daher typischerweise vermittelt über übergeordnete Öffnungs- und Zugriffsmechanismen des Persistenzmoduls. Die Freigabe der Schnittstelle und der gebundenen Zugriffsressourcen erfolgt über den virtuellen Destruktor ~ReadAccessor() [SWS_PER_00417]. Instanzen von ReadAccessor besitzen einen internen Lesezeiger, der die aktuelle Position in der Datei verwaltet. Sämtliche Methoden der Klasse sind explizit als nicht threadsicher (not thread-safe) spezifiziert [SWS_PER_00419], weshalb gleichzeitige Leseoperationen auf derselben Instanz von Aufrufern extern synchronisiert werden müssen.

Nutzungspfade für Binär- und Textdaten

Für binäre Dateioperationen bietet die Klasse Funktionen zum vorschaubaren oder sequenziellen Auslesen. Mit PeekByte() kann das Byte an der aktuellen Leseposition inspiziert werden, ohne den Lesezeiger zu verändern [SWS_PER_00418]. Dagegen liest GetByte() genau ein Byte aus und rückt die Position vor [SWS_PER_00419]. Größere Datenblöcke lassen sich über ReadBinary(n) in einen ara::core::Vector<ara::core::Byte> einlesen, wobei die Position entsprechend angepasst wird; wird das Dateiende vorzeitig erreicht, enthält der Vektor weniger Bytes als angefordert [SWS_PER_00422]. Mittels ReadBinary() können alle verbleibenden Bytes bis zum Dateiende in einem Schritt bezogen werden [SWS_PER_00421].

Sequenzdiagramm: Typischer Ablauf eines sequenziellen Lesezugriffs mit Vorabprüfung und abschnittsweiser Datenverarbeitung. Quellen: [SWS_PER_00418], [SWS_PER_00422], [SWS_PER_00421].

Im Textmodus stellt PeekChar() eine zeichenbasierte Vorschau bereit [SWS_PER_00167], während GetChar() das nächste Zeichen konsumiert [SWS_PER_00168]. Das zeilenweise Lesen erfolgt über ReadLine(), das bis zu einem Trennzeichen liest (Standard: '\n', ASCII 0x0a); das Trennzeichen wird dabei nicht in den Ergebnisstring übernommen [SWS_PER_00119]. Abschnitte von n Zeichen oder der gesamte Restinhalt lassen sich über die Überladungen von ReadText() auslesen [SWS_PER_00165], [SWS_PER_00420]. Befindet sich der Lesezeiger inmitten eines Mehrbyte-Zeichens, können die resultierenden Zeichenketten unvollständige Unicode-Codepunkte aufweisen [SWS_PER_00119], [SWS_PER_00165].

Fehlerszenarien und Fehlerbehandlung

Alle Leseoperationen von ReadAccessor liefern ihre Werte gekapselt in einem ara::core::Result zurück und sind als ausnahmesicher (exception safe) spezifiziert [SWS_PER_00419]. Tritt während eines Zugriffs ein Fehler auf, greift eine strikte Rollback-Semantik: Die aktuelle Position des Lesezeigers bleibt im Fehlerfall stets unverändert [SWS_PER_00421], [SWS_PER_00422]. Typische dokumentierte Fehlerzustände umfassen:

  • PerErrc::kPhysicalStorageFailure bei Fehlern des physischen Speichermediums [SWS_PER_00419], [SWS_PER_00420],
  • PerErrc::kEof, falls der Lesezeiger am Dateiende steht oder die Datei leer ist [SWS_PER_00419], [SWS_PER_00168],
  • PerErrc::kValidationFailed, wenn die Gültigkeit der Daten nicht verifiziert werden kann [SWS_PER_00418], [SWS_PER_00119],
  • PerErrc::kEncryptionFailed bei fehlschlagender Entschlüsselung [SWS_PER_00419], [SWS_PER_00422] sowie
  • PerErrc::kAuthenticationFailed, sofern die MAC-Überprüfung gespeicherter Daten fehlschlägt [SWS_PER_00167], [SWS_PER_00421].
