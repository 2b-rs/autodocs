Kapselt die sechs Byte lange Entitätskennung (EID) für die DoIP-Fahrzeugidentifikation gemäß ISO 13400-2.

Die Struktur ara::diag::DoIPEntityIdentification::EntityId dient als Datenbehälter für die sechs Byte lange Entitätskennung (EID) einer DoIP-Instanz gemäß ISO 13400-2 ([SWS_DM_01496]). Bei entsprechender Konfiguration ruft der Diagnostic Manager diese Kennung über die Methode ara::diag::DoIPEntityIdentification::GetEntityId von der adaptiven Anwendung ab, um sie in DoIP-Protokollnachrichten wie die Fahrzeugankündigung einzubetten ([SWS_DM_01361]). Sollte die Schnittstelle noch nicht bereitstehen oder der Abruf fehlschlagen, greift als zwingende Randbedingung ein Fallback auf den festen Ersatzwert aus lauter Bytes mit dem Wert 0xFF ([SWS_DM_01528]).

Kontext

Die Datenstruktur ara::diag::DoIPEntityIdentification::EntityId dient der Repräsentation der standardisierten Entitätskennung (Entity Identification, EID) für die Diagnosekommunikation über das Internet-Protokoll (DoIP) gemäß ISO 13400-2 ([SWS_DM_01496], AUTOSAR_AP_SWS_Diagnostics §8.33 „Header: ara/diag/doip_entity_identification.h“). Innerhalb der AUTOSAR Adaptive Platform ist sie als öffentlicher Strukturtyp innerhalb der API-Klasse ara::diag::DoIPEntityIdentification definiert ([SWS_DM_01362], [SWS_DM_01496]).

Ihre primäre Verantwortung besteht in der Kapselung des exakt sechs Byte langen Identifikationswerts einer DoIP-Entität ([SWS_DM_01496]). In der Plattformarchitektur interagieren dabei drei Hauptakteure: Erstens die adaptive Anwendung, welche die Entitätskennung verwaltet oder aus der Hardware liest. Zweitens die Schnittstellenklasse ara::diag::DoIPEntityIdentification, welche die Methode zur Bereitstellung der Kennung anbietet ([SWS_DM_01362]). Drittens der Diagnostic Manager (DM), der die EID im Rahmen der Fahrzeugidentifikation für ausgehende DoIP-Nachrichten abruft ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“).

Kontextdiagramm: Einbindung von EntityId zwischen Diagnostic Manager, Schnittstellenklasse und adaptiver Anwendung. Quellen: [SWS_DM_01361], [SWS_DM_01496].

Lebenszyklus

Als Datenstruktur mit dem einzigen Member entityIdentification vom Typ ara::core::Array<std::uint8_t, 6> weist EntityId die Eigenschaften eines leichtgewichtigen C++-Wertobjekts auf ([SWS_DM_01496]). Interpretation: Mangels dynamischer Ressourcenallokation dürfte die Struktur standardmäßig reguläre Kopier- und Verschiebeoperationen unterstützen und keinen komplexen internen Zustandsübergängen unterliegen.

Die Instanziierung von EntityId erfolgt durch die adaptive Anwendung, sobald der Diagnostic Manager die Identitätsdaten über den Aufruf von ara::diag::DoIPEntityIdentification::GetEntityId abfragt ([SWS_DM_01361]). Die Lebensdauer einer Instanz ist typischerweise an den Rückgabe- und Verarbeitungszyklus des Methodenaufrufs gebunden. Während die umgebende Service-Klasse ara::diag::DoIPEntityIdentification über explizite Konstruktoren ([SWS_DM_01364], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.2.1 „DoIPEntityIdentification“) und Destruktoren ([SWS_DM_01365], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.1.1 „Destructor“) verfügt, wird das Wertobjekt EntityId nach Auslesen der Felddaten durch den Diagnostic Manager beim Verlassen des Gültigkeitsbereichs automatisch freigegeben.

Nutzungspfad

Der reguläre Einsatz von EntityId folgt einer definierten Sequenz im Diagnoseprotokollablauf:

  • Konfigurationsprüfung: Der Diagnostic Manager prüft das Attribut DoIpNetworkConfiguration.eidRetrieval. Ist dort DoIpEidRetrievalEnum.eidUseApi hinterlegt, muss der DM die Kennung zwingend über die API abrufen ([SWS_DM_01361]).
  • Abruf per API: Der Diagnostic Manager ruft die Methode ara::diag::DoIPEntityIdentification::GetEntityId auf ([SWS_DM_01361]).
  • Datenbereitstellung: Die Anwendung erzeugt eine Instanz von EntityId, befüllt das Member entityIdentification mit der 6-Byte-Kennung gemäß ISO 13400-2 ([SWS_DM_01496]) und übergibt die Struktur.
  • Protokollverwendung: Der Diagnostic Manager entnimmt die Kennung und setzt sie in DoIP-Nachrichten wie der Fahrzeugankündigung (Vehicle Announcement Message) ein ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“).

Sequenzdiagramm: Ablauf beim Abruf und der Weiterverarbeitung von EntityId inklusive Fehler-Fallback. Quellen: [SWS_DM_01361], [SWS_DM_01496], [SWS_DM_01528].

Fehlerszenarien

Ein zentrales Fehlerszenario entsteht, wenn die Schnittstelle ara::diag::DoIPEntityIdentification zum geforderten Abfragezeitpunkt von der adaptiven Anwendung noch nicht angeboten wird oder der Abruf über GetEntityId fehlschlägt ([SWS_DM_01528], AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“).

Um das Senden der DoIP-Nachrichten nicht dauerhaft zu blockieren, schreibt die Spezifikation in diesem Fall ein verbindliches Ersatzwertverhalten vor: Der Diagnostic Manager muss anstelle der regulären Anwendungsdaten ein 6-Byte-EID-Feld mit dem festen Wert 0xFF 0xFF 0xFF 0xFF 0xFF 0xFF übertragen ([SWS_DM_01528]). Auf Typebene schließt das feste Array ara::core::Array<std::uint8_t, 6> Längenfehler und Pufferüberläufe zur Übersetzungszeit aus ([SWS_DM_01496]).
