Dient der fehlertoleranten Rückgabe einer Referenz auf ein vorhandenes Objekt oder eines aufgetretenen Fehlercodes.

Die Spezialisierung ara::core::Result<T&, E> kapselt entweder eine nicht besitzende Referenz auf ein erfolgreiches Operationsergebnis vom Typ T& ([SWS_CORE_00902]) oder einen aufgetretenen Fehlercode vom Typ E. Anwender prüfen das Vorliegen eines Werts typischerweise über HasValue() ([SWS_CORE_00918]), bevor sie über Dereferenzierungsoperatoren oder Value() auf das referenzierte Zielobjekt zugreifen. Da die Instanz das referenzierte Objekt nicht selbst besitzt, dürfte der Aufrufer sicherstellen müssen, dass dieses während der gesamten Nutzungsdauer des Ergebnisses im Speicher gültig bleibt. Kontext

Die Vorlagenspezialisierung ara::core::Result<T&, E> kapselt entweder eine Referenz auf ein erfolgreiches Operationsergebnis vom Typ value_type ([SWS_CORE_00902]) oder einen Fehlerwert vom Typ error_type ([SWS_CORE_00903]). Als standardisierte Rückgabestruktur im Modul core ermöglicht sie eine fehlerrobuste Programmierung ohne den zwingenden Einsatz von C++-Ausnahmen im regulären Ablauf. Gemäß Spezifikation erzwingt die Implementierung zur Übersetzungszeit, dass der Fehlertyp E dem Typ ara::core::ErrorCode entspricht; eine abweichende Belegung führt zu einem Übersetzungsfehler. Zu den Interaktionspartnern zählen datenliefernde Dienste, aufrufende Komponenten zur Ergebnisprüfung sowie das außerhalb verwaltete Zielobjekt, auf welches direkt über die gebundene Referenz zugegriffen wird.

Lebenszyklus

Eine Instanz wird deterministisch entweder mit einer Referenz auf einen bestehenden Lvalue oder mit einem Fehler initialisiert. Die Initialisierung mit einer Referenz erfolgt über den Konstruktor [SWS_CORE_00908] oder die statische Fabrikmethode FromValue [SWS_CORE_00904]; die Übergabe von Rvalues ist unzulässig. Fehlerzustände werden über Konstruktoren ([SWS_CORE_00909], [SWS_CORE_00910]) oder Fabriken wie FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]) erzeugt. Ein Standardkonstruktor existiert nicht. Kopier- und Verschiebekonstruktoren ([SWS_CORE_00911], [SWS_CORE_00912]) übernehmen den aktuellen Zustand einer anderen Instanz.

Hinsichtlich der Besitzverhältnisse bindet Result<T&, E> lediglich eine Referenz und übernimmt kein Eigentum oder Lebensdauermanagement für das referenzierte Zielobjekt. Der Aufrufer dürfte daher gewährleisten müssen, dass das Zielobjekt über die gesamte Existenzdauer der Result-Instanz gültig bleibt. Frage (offen) Zustandswechsel im laufenden Betrieb werden über Zuweisungsoperatoren ([SWS_CORE_00914], [SWS_CORE_00915]) durchgeführt, welche die interne Referenz auf das neue Ziel umbinden oder einen Fehler übertragen. Zudem versetzt EmplaceError [SWS_CORE_00916] die Instanz direkt in einen Fehlerzustand, während Swap [SWS_CORE_00917] die Inhalte zweier Instanzen tauscht. Der Destruktor [SWS_CORE_00913] verhält sich trivial, sofern E trivial destruierbar ist. Parallele Lesezugriffe auf Wert oder Fehler sind threadsicher, während zustandsverändernde Operationen wie Zuweisungen, Swap oder EmplaceError nicht threadsicher sind.

Nutzungspfad

Der reguläre Ablauf umfasst die Zustandskontrolle sowie die zielgerichtete Auswertung:

  • Zustandsprüfung: Vor dem Zugriff prüft der Aufrufer über HasValue() [SWS_CORE_00918] oder den Konvertierungsoperator operator bool [SWS_CORE_00919], ob ein Wert vorliegt.
  • Direkter Zugriff: Im Erfolgsfall stellen Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator* ([SWS_CORE_00920], [SWS_CORE_00921]) und operator-> ([SWS_CORE_00922], [SWS_CORE_00923]) die Referenz bzw. einen Zeiger auf das Zielobjekt bereit.
  • Optionale und rückfallbasierte Zugriffe: Über Ok() ([SWS_CORE_00926], [SWS_CORE_00927]) kann die Referenz in ein ara::core::Optional überführt werden. Die Methode ValueOr() ([SWS_CORE_00933], [SWS_CORE_00934]) liefert eine Kopie des referenzierten Werts oder einen übergebenen Ersatzwert.
  • Monadische Operationen: Mit Bind() [SWS_CORE_00941] wird eine Transformationsfunktion auf die Referenz angewendet und das Ergebnis verpackt, während Fehler automatisch weitergeleitet werden. Resolve() ([SWS_CORE_00939], [SWS_CORE_00940]) ruft bei Fehlern eine Ersatzfunktion auf, die eine kompatible Referenz bereitstellt.

Fehlerszenarien

Befindet sich die Instanz im Fehlerzustand, gewähren die Überladungen von Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) Zugriff auf das Fehlerobjekt. Ergänzend kann der Fehler über Err() ([SWS_CORE_00931], [SWS_CORE_00932]) als Optional<E> oder über ErrorOr() ([SWS_CORE_00935], [SWS_CORE_00936]) mit einem Rückfallwert bezogen werden. Für spezifische Fehlerabgleiche vergleicht CheckError() [SWS_CORE_00937] den enthaltenen Fehler mit einem Referenzfehler.

Die Spezifikation definiert strikte Vorbedingungen für die Elementzugriffe:

  • ResultWithNoValueViolation: Ein Aufruf von Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator* ([SWS_CORE_00920], [SWS_CORE_00921]) oder operator-> ([SWS_CORE_00922], [SWS_CORE_00923]) auf einer Instanz ohne Wert stellt eine Spezifikationsverletzung dar.
  • ResultWithNoErrorViolation: Der Zugriff auf Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) bei Vorliegen eines Werts verletzt die Vorbedingungen.
  • Ausnahmebehandlung: Die Aufrufe ValueOrThrow() ([SWS_CORE_00938], [SWS_CORE_00949]) werfen im Fehlerfall die dem Fehler zugeordnete Ausnahme; sie nehmen nur an der Überladungsauflösung teil, wenn C++-Ausnahmen im Compiler aktiviert sind.

Verwendung

Die Elementfunktion const T * operator-> () const noexcept ermöglicht den synchronen Lesezugriff auf den referenzierten Wert eines ara::core::Result<T &, E>-Objekts [SWS_CORE_00922]. Sie nimmt keine Argumente entgegen und liefert als Rückgabewert einen konstanten Zeiger (const T *) auf das referenzierte Zielobjekt [SWS_CORE_00922]. Für die Nutzung ist der Header #include "ara/core/result.h" einzubinden [SWS_CORE_00922].

Fehlerbehandlung

Die Operation ist als noexcept deklariert und besitzt die Eigenschaft exception safe [SWS_CORE_00922]. Enthält das Objekt keinen Wert, liegt eine Verletzung der Vorbedingung (Violation) ResultWithNoValue vor [SWS_CORE_00922]. Aufrufer müssen daher vor der Dereferenzierung sicherstellen, dass die Instanz tatsächlich einen gültigen Wert hält.

Nebenläufigkeit und Einschränkungen

Die Funktion ist als thread-safe spezifiziert [SWS_CORE_00922]. Da es sich um eine konstante Memberfunktion handelt, ist der parallele lesende Zugriff auf dieselbe Instanz sicher. Der Zugriff auf das Zielobjekt selbst unterliegt jedoch den Thread-Sicherheitsgarantien des Typs T.

Zusammenspiel

Der Operator bildet das konstante Gegenstück zur nicht-konstanten Überladung T * operator-> () noexcept [SWS_CORE_00923]. Während die nicht-konstante Variante einen modifizierbaren Zeiger T* zurückgibt [SWS_CORE_00923], erzwingt diese Version den unveränderlichen Zugriff auf die referenzierte Instanz.
