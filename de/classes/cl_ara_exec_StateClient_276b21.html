class ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Fordert beim Execution Management Zustandswechsel für Funktionsgruppen an, um Prozesse auf einer Machine zu steuern.

Die Schnittstelle ara::exec::StateClient ermöglicht dem State Management das Anfordern von Zustandswechseln für Funktionsgruppen beim Execution Management, um die Ausführung zugeordneter Prozesse auf einer Machine zu steuern [SWS_EM_02278]. Bei der Erzeugung via Create() muss ein durchgehend gültiger Callback für unerwartete undefinierte Zustände registriert werden [SWS_EM_02276]. Neben asynchronen Zustandsübergängen bietet die nicht kopierbare Klasse Methoden zur Abfrage des Machine-Hochlaufergebnisses sowie zur Fehleranalyse bei Ausführungsfehlern [SWS_EM_02279], [SWS_EM_02542].

Kontext

Die Klasse ara::exec::StateClient bildet die Schnittstelle des Execution Management, über die das State Management Zustandsübergänge für Funktionsgruppen (Function Groups) anfordert und steuert. Das State Management verwendet diesen Client während der gesamten Betriebszeit einer Machine, um Prozesse gezielt zu starten oder zu beenden. Der Integrator weist Softwarekomponenten bestimmten Zuständen einer Funktionsgruppe zu. Möchte das State Management diese Software ausführen, fordert es über den StateClient beim Execution Management den Wechsel in den betreffenden Funktionsgruppenzustand an; das Stoppen erfolgt analog durch Übergang in einen Zustand, in dem die Software nicht aktiv sein soll [SWS_EM_02278].

Kontextdiagramm: Zusammenspiel zwischen State Management, StateClient und Execution Management. Quellen: [SWS_EM_02276], [SWS_EM_02278]

Lebenszyklus

Instanzen von StateClient können entweder über den benannten Konstruktor Create() [SWS_EM_02276] als ara::core::Result<StateClient> oder über den regulären Konstruktor StateClient() [SWS_EM_02561] erzeugt werden. Beide Konstruktionspfade verlangen zwingend einen Callback-Parameter undefinedStateCallback vom Typ std::function<void(const ara::exec::ExecutionErrorEvent&)>. Dieser Callback wird durch die StateClient-Bibliothek ausgelöst, wenn eine Funktionsgruppe unerwartet und ohne vorherige Anforderung durch SetState() in einen undefinierten Zustand wechselt. Der Aufrufer muss sicherstellen, dass dieser Callback über die gesamte Lebensdauer der StateClient-Instanz aufrufbar bleibt, was insbesondere bei Objektbindungen via std::bind relevant ist [SWS_EM_02276], [SWS_EM_02561].

Kopieroperationen sind für StateClient explizit unterbunden: Sowohl der Kopierkonstruktor [SWS_EM_02565] als auch der Kopierzuweisungsoperator [SWS_EM_02568] sind gelöscht (=delete). Eine Übertragung des Besitzes ist ausschließlich über Move-Semantik via Move-Konstruktor [SWS_EM_02566] und Move-Zuweisung [SWS_EM_02567] möglich. Hinsichtlich der Nebenläufigkeit sind die fachlichen Methoden wie SetState(), GetExecutionError() und GetInitialMachineStateTransitionResult() sowie die Erzeugung threadsicher ausgelegt [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]. Dagegen sind die Move-Operationen und der Destruktor ~StateClient() nicht threadsicher [SWS_EM_02277], [SWS_EM_02566], [SWS_EM_02567].

Nutzungspfad

Ein typischer Anwendungszyklus gliedert sich in Initialisierung, Abfrage des Hochlaufergebnisses, reguläre Zustandswechsel und Fehlerüberwachung:

  1. Erzeugung: Das State Management instanziiert StateClient unter Angabe eines gültigen Fehlersignalisierungs-Callbacks via Create() [SWS_EM_02276].
  2. Initiales Hochlaufergebnis abfragen: Mit GetInitialMachineStateTransitionResult() fordert das State Management das Ergebnis des initialen Zustandsübergangs in den Startup-Zustand an [SWS_EM_02279]. Da dieser Übergang genau einmal pro Lebenszyklus der Machine stattfindet, bleibt das gelieferte ara::core::Future<void> stabil und ändert sich bis zu einem Neustart nicht mehr.
  3. Zustandswechsel anfordern: Mittels SetState() beauftragt das State Management asynchrone Zustandsübergänge für einzelne Funktionsgruppen [SWS_EM_02278]. Die Methode kehrt sofort zurück und liefert ein ara::core::Future<void> zur Abfrage des Abschlusses. Sobald der Auftrag beim Execution Management eingegangen ist, wird er unabhängig von der weiteren Lebensdauer der aufrufenden Instanz ausgeführt.
  4. Fehlerzustände untersuchen: Gelangt eine Funktionsgruppe unerwartet in einen undefinierten Zustand, kann über GetExecutionError() der auslösende Ausführungsfehler in Form eines ara::exec::ExecutionErrorEvent ermittelt werden [SWS_EM_02542].

Fehlerszenarien

Die Operationen der Klasse kommunizieren Fehlschläge über Fehlercodes der ExecErrorDomain:

  • ExecErrc::kNoCommunication: Signalisiert Kommunikationsstörungen zum Execution Management, beispielsweise bei unterbrochener IPC-Verbindung. Tritt bei Create() [SWS_EM_02276], SetState() [SWS_EM_02278], GetInitialMachineStateTransitionResult() [SWS_EM_02279] sowie GetExecutionError() [SWS_EM_02542] auf. Die vorgesehene Wiederherstellung besteht im erneuten Aufruf.
  • ExecErrc::kInvalidArgument: Wird von Create() und StateClient() gemeldet, falls der übergebene Callback keine aufrufbare Funktion enthält [SWS_EM_02276], [SWS_EM_02561].
  • ExecErrc::kOperationCanceled: Zeigt bei SetState() an, dass ein laufender Übergang durch eine neuere Anforderung abgebrochen wurde [SWS_EM_02278]. Bei GetInitialMachineStateTransitionResult() tritt dieser Fehler auf, wenn der initiale Startübergang abgebrochen wurde, etwa durch eine unterbrochene Machine-Update-Sequenz [SWS_EM_02279].
  • ExecErrc::kInvalidTransition: Der angeforderte Zustandsübergang ist unzulässig, beispielsweise der Übergang in den Off-Zustand für MachineFG, oder der Zustand existiert nach einem Update nicht mehr [SWS_EM_02278].
  • ExecErrc::kInvalidMetaModelIdentifier: Der übergebene Zustand existiert nicht im verarbeiteten Manifest oder der Prozess besitzt kein Mapping auf die betreffende Funktionsgruppe [SWS_EM_02278], [SWS_EM_02542]. Tritt dieser Fehler bei GetInitialMachineStateTransitionResult() auf, fehlt dem Prozess das Mapping zu MachineFG, was auf ein Konfigurationsproblem hinweist [SWS_EM_02279].
  • ExecErrc::kOperationFailed: Der Übergang ist fehlgeschlagen [SWS_EM_02278]. Bei GetExecutionError() zeigt der Code an, dass sich die Funktionsgruppe nicht in einem undefinierten Zustand befindet und das Problem vermutlich bereits behoben wurde [SWS_EM_02542].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed und ExecErrc::kUnexpectedTermination: Spezifische Fehlschläge während SetState() infolge gescheiterter Integritätsprüfungen oder unerwarteter Prozessbeendigungen während der Transition [SWS_EM_02278].

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 86cbb8f72d61 Herkunft Offene Fragen (1)

Die statische Factory-Methode Create dient als Named Constructor zur Erzeugung einer Instanz von ara::exec::StateClient ([SWS_EM_02276]). Als zwingender Parameter wird undefinedStateCallback übergeben. Dieser Callback wird von der Client-Bibliothek ausgelöst, wenn eine Funktionsgruppe unerwartet – das heißt ohne vorherige Anforderung über SetState() – in einen undefinierten Zustand wechselt ([SWS_EM_02276]). Dabei werden die betroffene Funktionsgruppe und der Fehler über ein ExecutionErrorEvent an den Callback übermittelt.

Für Aufrufkontext und Lebensdauer gelten feste Rahmenbedingungen:

  • Die Funktion ist thread-safe, exception-safe und als noexcept deklariert ([SWS_EM_02276]).
  • Der übergebene undefinedStateCallback muss während der gesamten Lebensdauer der erzeugten StateClient-Instanz aufrufbar bleiben ([SWS_EM_02276]). Dies erfordert besondere Sorgfalt bei Bindungen an Objektinstanzen (beispielsweise mittels std::bind).

Die Instanziierung erfolgt synchron und liefert ein ara::core::Result<StateClient> zurück ([SWS_EM_02276]). Im Fehlerfall sind folgende Fehlercodes definiert:

  • ara::exec::ExecErrc::kInvalidArgument: Wird gemeldet, wenn das übergebene Argument keine aufrufbare Funktion enthält (Rollback-Semantik; Behebung durch Bereitstellung einer gültigen Funktion) ([SWS_EM_02276]).
  • ara::exec::ExecErrc::kNoCommunication: Signalisiert einen Kommunikationsfehler (No-Rollback-Semantik; Behebung durch erneuten Versuch) ([SWS_EM_02276]). Dies dürfte vermutlich auf einen fehlgeschlagenen Verbindungsaufbau zur Ausführungsumgebung zurückzuführen sein.

Das Konstruktionsmuster entspricht strukturell dem Initialisierungsansatz verwandter Ausführungsclients wie ara::exec::ExecutionClient ([SWS_EM_02562]), der ebenfalls mit einem Pflicht-Callback über einen Named Constructor erzeugt wird.

              function SetState [SWS_EM_02278] Upstream: RS_EM_00101, RS_AP_00119, RS_AP_00120, RS_AP_00121, RS_AP_00138, RS_AP_00128, RS_AP_00159
              

              ara::core::Future< void > SetState (const FunctionGroupState &state) const noexcept;
              

              Method to request state transition for a single Function Group. This method will request Execution Management to perform state transition and return immediately. Returned ara::core::Future can be used to determine result of requested transition.
              

              

              

              

              

              

              

              

              
  KI-GENERIERT
  ungeprüft
  Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: b3951f2f28ce
  Herkunft
  

              

              

              Die Methode SetState dient dazu, den Zustandsübergang für eine einzelne Funktionsgruppe beim Execution Management anzufordern [SWS_EM_02278]. Der Aufruf erfolgt asynchron: Die Methode stößt den Wechsel an und kehrt unmittelbar mit einem ara::core::Future<void> zurück, über das das Ergebnis der Transition ermittelt werden kann [SWS_EM_02278]. Als Parameter wird ein FunctionGroupState übergeben, der den Zielzustand innerhalb der Funktionsgruppe metamodellkonform identifiziert [SWS_EM_02278].
              
  
              Schlägt die Transition fehl, liefert das Future einen Fehler aus der Exec-ErrorDomain [SWS_EM_02278]. Eine Rollback-Semantik greift bei ara::exec::ExecErrc::kInvalidTransition (z. B. bei verbotenen Übergängen wie dem Off-Zustand für MachineFG) und bei ara::exec::ExecErrc::kInvalidMetaModelIdentifier (bei fehlendem Mapping oder fehlender Definition im Manifest) [SWS_EM_02278]. Ohne Rollback-Semantik werden kOperationCanceled (durch neuere Anfrage verdrängt), kOperationFailed, kNoCommunication (IPC-Verbindung gestört), kIntegrityOrAuthenticityCheckFailed sowie kUnexpectedTermination gemeldet [SWS_EM_02278].
              
  
              Die Methode ist thread-safe und exception safe (noexcept) [SWS_EM_02278]. Das zurückgegebene ara::core::Future hängt von der Lebensdauer der aufrufenden Instanz ab; das Execution Management verarbeitet die eingegangene Anforderung hingegen unabhängig von der Lebensdauer der StateClient-Instanz [SWS_EM_02278].
              
  
              Im Zusammenspiel mit der Instanziierung über Create [SWS_EM_02276] bzw. den Konstruktor [SWS_EM_02561] fängt ein undefinedStateCallback unerwartete Zustandswechsel ab, die ohne vorherigen Aufruf von SetState eintreten. Das Ergebnis des anfänglichen Übergangs in den Startup-Zustand kann separat über GetInitialMachineStateTransitionResult abgefragt werden [SWS_EM_02279].
