class ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Kontext

Die Klasse ara::exec::StateClient fungiert als funktionale Schnittstelle des Execution Managements gegenüber dem State Management. Im Gesamtsystem obliegt dem State Management die Aufgabe, den Lebenszyklus einer Maschine zu steuern und Softwarekomponenten bedarfsgerecht zu starten sowie zu stoppen. Dies erfolgt über Zustandsübergänge konfigurierter Funktionsgruppen (Function Groups), welchen durch den Integrator konkrete Software-Prozesse zugeordnet wurden.

State Management verwendet ara::exec::StateClient, um Zustandsübergänge für einzelne Funktionsgruppen beim Execution Management anzufordern [SWS_EM_02278]. Das Execution Management führt diese Transitionen aus, indem es die der Funktionsgruppe zugeordnete Software startet oder beendet, und meldet das Resultat des Übergangs an das State Management zurück. Für den Verbindungsaufbau zum Execution Management dürfte im Hintergrund ein plattformspezifischer IPC-Kanal (wie Unix-Domain-Sockets) verwendet werden, da die Spezifikation die genaue IPC-Technologie nicht weiter eingrenzt.

Lebenszyklus

Für die Instanziierung von ara::exec::StateClient stellt AUTOSAR zwei Konstruktionspfade bereit:

  • Benannte Fabrikmethode: Die statische Funktion Create liefert ein ara::core::Result<StateClient> zurück und kapselt potenzielle Fehler bei der Erzeugung fehlercodebasiert und ausnahmesicher ([SWS_EM_02276]).
  • Regulärer Konstruktor: Der direkte Konstruktor ist als noexcept(false) deklariert und signalisiert Fehler im Fehlerfall über Ausnahmen ([SWS_EM_02561]).

Beide Erzeugungspfade fordern die Übergabe eines Callbacks undefinedStateCallback mit der Signatur std::function<void(const ara::exec::ExecutionErrorEvent&)>. Dieser Callback wird durch die StateClient-Bibliothek aufgerufen, falls eine Funktionsgruppe unerwartet und ohne vorherige Anforderung über SetState in einen undefinierten Zustand (Undefined Function Group State) wechselt ([SWS_EM_02276], [SWS_EM_02561]). Hinsichtlich der Lebensdauer ist zwingend sicherzustellen, dass dieser Callback über die gesamte Lebensdauer der StateClient-Instanz aufrufbar bleibt; dies gilt insbesondere bei der Anbindung von Instanzmethoden via std::bind ([SWS_EM_02276], [SWS_EM_02561]).

Kopieroperationen sind vollständig unterbunden: Sowohl der Kopierkonstruktor als auch der Zuweisungsoperator sind explizit gelöscht (delete) ([SWS_EM_02565], [SWS_EM_02568]). Dagegen unterstützt die Klasse Move-Semantik: Move-Konstruktor und Move-Zuweisungsoperator sind als noexcept definiert ([SWS_EM_02566], [SWS_EM_02567]). Der Destruktor ist als noexcept deklariert ([SWS_EM_02277]). Sobald eine Zustandsänderung durch das Execution Management empfangen wurde, wird sie unabhängig von der Lebensdauer der StateClient-Instanz abgearbeitet; das von SetState gelieferte ara::core::Future hängt jedoch von der Lebensdauer der Instanz ab ([SWS_EM_02278]).

Bezüglich der Nebenläufigkeit sind die Instanzmethoden SetState, GetExecutionError und GetInitialMachineStateTransitionResult sowie Create und der reguläre Konstruktor thread-safe spezifiziert ([SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542], [SWS_EM_02561]). Die Move-Operationen und der Destruktor sind hingegen nicht thread-safe ([SWS_EM_02566], [SWS_EM_02567], [SWS_EM_02277]).

Nutzungspfad

Ein typischer Nutzungsablauf durch das State Management gliedert sich in folgende Schritte:

  1. Client-Erzeugung: State Management instanziiert StateClient über Create unter Registrierung des Fehler-Callbacks ([SWS_EM_02276]).
  2. Startzustand synchronisieren: Zu Beginn des Maschinenbetriebs wird über GetInitialMachineStateTransitionResult() das Ergebnis des initialen Übergangs der Maschine in den Startup-Zustand abgefragt ([SWS_EM_02279]). Die Methode liefert ein ara::core::Future<void>. Da dieser Übergang genau einmal pro Maschinenlebenszyklus erfolgt, bleibt das Resultat über die restliche Laufzeit unverändert ([SWS_EM_02279]).
  3. Zustandswechsel anfordern: Zur Laufzeit fordert State Management über SetState(state) Übergänge für einzelne Funktionsgruppen an ([SWS_EM_02278]). Die Methode kehrt unmittelbar zurück und liefert ein ara::core::Future<void>, welches den Erfolg des Übergangs anzeigt oder einen Fehler der ExecErrorDomain bereitstellt.
  4. Fehlerzustände analysieren: Geht eine Funktionsgruppe unvorhergesehen in einen undefinierten Zustand über, wird der registrierte Callback ausgelöst. State Management kann über GetExecutionError(functionGroupState) das auslösende ExecutionErrorEvent abrufen, solange die Funktionsgruppe noch in diesem Zustand verweilt ([SWS_EM_02542]).

Fehlerszenarien

Methoden von ara::exec::StateClient verwenden Fehlercodes aus der Fehlerdomäne von Execution Management (ara::exec::ExecErrc). Folgende Fehlerszenarien sind relevant:

  • Kommunikationsausfall (ExecErrc::kNoCommunication): Tritt auf, wenn die Verbindung zwischen Client und Execution Management gestört oder unterbrochen ist. Dieser Fehler ist für alle Operationen spezifiziert ([SWS_EM_02276], [SWS_EM_02561], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]). Eine Wiederholung des Aufrufs ist die vorgesehene Recovery-Maßnahme.
  • Ungültige Übergabe und Metamodell-Konflikte:
    • ExecErrc::kInvalidArgument signalisiert bei der Erzeugung, dass der übergebene undefinedStateCallback nicht aufrufbar ist ([SWS_EM_02276], [SWS_EM_02561]).
    • ExecErrc::kInvalidMetaModelIdentifier weist darauf hin, dass der Zielzustand im Manifest nicht existiert oder der aufrufende Prozess kein Mapping auf die betreffende Funktionsgruppe besitzt ([SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]).
  • Fehlschlag oder Abbruch von Zustandsübergängen:
    • ExecErrc::kOperationCanceled informiert darüber, dass eine Transition durch eine neuere Anforderung verdrängt oder durch das State Management abgebrochen wurde ([SWS_EM_02278], [SWS_EM_02279]).
    • ExecErrc::kInvalidTransition wird zurückgegeben, wenn der Übergang unzulässig ist (z. B. Wechsel in den Off-Zustand für MachineFG) oder der Zustand nach einem Software-Update nicht mehr existiert ([SWS_EM_02278]).
    • ExecErrc::kIntegrityOrAuthenticityCheckFailed meldet das Scheitern von Authentizitäts- oder Integritätsprüfungen während des Zustandswechsels ([SWS_EM_02278]).
    • ExecErrc::kUnexpectedTermination tritt auf, wenn ein beteiligter Prozess während der Transition unerwartet beendet wurde ([SWS_EM_02278]).
    • ExecErrc::kOperationFailed zeigt das allgemeine Scheitern einer Transition an ([SWS_EM_02278], [SWS_EM_02279]). Beim Aufruf von GetExecutionError besagt dieser Fehler hingegen, dass sich die Funktionsgruppe nicht in einem undefinierten Zustand befindet und das Problem möglicherweise bereits behoben wurde ([SWS_EM_02542]).

Dieser Leitfaden basiert auf der Spezifikation von Execution Management für die AUTOSAR Adaptive Platform im Release R25-11.
