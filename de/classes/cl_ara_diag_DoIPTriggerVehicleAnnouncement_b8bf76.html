Dient dem gezielten Anstoßen von DoIP-Fahrzeugankündigungen auf einer angegebenen Netzwerkschnittstelle.

Die Klasse [SWS_DM_00820] dient Adaptive Applications dazu, das Versenden von DoIP-Fahrzeugankündigungen gemäß ISO 13400-2 auf einer bestimmten Netzwerkschnittstelle explizit beim Diagnostic Management anzustoßen. Der Zugriff erfolgt nicht über eigene Instanziierung, sondern statisch über eine vom System bereitgestellte Objektreferenz ([SWS_DM_00821]). Für Schnittstellen mit aktivierungsleitungsabhängiger Steuerung ist der explizite Aufruf unzulässig, da der Versand dort vollautomatisch erfolgt ([SWS_DM_00822]).

Kontext

Die Klasse ara::diag::DoIPTriggerVehicleAnnouncement ([SWS_DM_00820]) stellt im Header ara/diag/doip_trigger_vehicle_announcement.h (AUTOSAR_AP_SWS_Diagnostics §8.36.1 „Class: DoIPTriggerVehicleAnnouncement“) eine API bereit, mit der eine Adaptive Application das gezielte Aussenden von DoIP-Fahrzeugankündigungen („Vehicle Announcement Messages“) anstoßen kann ([SWS_DM_00815], [SWS_DM_00822]).

In der DoIP-Kommunikation nach ISO 13400-2 ist das Versenden von Fahrzeugankündigungen primär eine interne Aufgabe des Diagnostic Management (DM) (AUTOSAR_AP_SWS_Diagnostics §„About DiagnosticDoIPTriggerVehicleAnnouncementInterface“). Der DM versendet diese Nachrichten standardmäßig beim Hochfahren des Netzwerks als Broadcast an andere IP-Steuergeräte und Gateways sowie bei Erkennung der Verbindung eines externen Diagnosetesters (AUTOSAR_AP_SWS_Diagnostics §„About DiagnosticDoIPTriggerVehicleAnnouncementInterface“). Über ara::diag::DoIPTriggerVehicleAnnouncement wird Anwendungen dennoch die Möglichkeit eröffnet, dieses Senden für eine spezifische Netzwerkschnittstelle explizit zu veranlassen ([SWS_DM_00815], [SWS_DM_00820]).

Kontextdiagramm: Interaktionspartner beim Auslösen von DoIP-Fahrzeugankündigungen über den Diagnostic Manager. Quellen: [SWS_DM_00815], [SWS_DM_00820], AUTOSAR_AP_SWS_Diagnostics §„About DiagnosticDoIPTriggerVehicleAnnouncementInterface“.

Lebenszyklus

Die Erzeugung und Zerstörung von Instanzen der Klasse DoIPTriggerVehicleAnnouncement unterliegt strikten Vorgaben: Sowohl der Standardkonstruktor ([SWS_DM_02100]) als auch der Destruktor ([SWS_DM_02101]) sind als delete deklariert, privat und in ihrer konkreten Ausprägung herstellerspezifisch. Anwendungen können Objekte dieser Klasse somit weder direkt instanziieren noch zerstören.

Der Zugriff auf die Schnittstelle erfolgt statisch über die Funktion GetDoIPTriggerVehicleAnnouncement() ([SWS_DM_00821]). Diese gibt ein ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>> zurück, wodurch der Aufrufer eine Referenz auf das vom DM bereitgestellte Dienstobjekt erhält. Interpretation: Wegen der privaten, gelöschten Konstruktoren und der Rückgabe einer Objektreferenz dürfte die Klasse intern vom DM als langlebiges Singleton verwaltet werden.

Hinsichtlich der Nebenläufigkeit sind weder die Schnittstellenabfrage GetDoIPTriggerVehicleAnnouncement() noch der Methodenaufruf TriggerVehicleAnnouncement() thread-sicher spezifiziert („not thread-safe“) ([SWS_DM_00821], [SWS_DM_00822]). Ein gleichzeitiger Zugriff aus mehreren Threads erfordert daher eine externe Synchronisation. Beide Methoden sind als ausnahmesicher („exception safe“) spezifiziert ([SWS_DM_00821], [SWS_DM_00822]).

Nutzungspfad

Der typische Ablauf zur Anforderung einer DoIP-Fahrzeugankündigung gliedert sich in folgende Schritte:

  1. Instanz abrufen: Die Anwendung ruft statisch ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() auf ([SWS_DM_00821]).
  2. Ergebnis auswerten: Das resultierende ara::core::Result wird auf Fehler geprüft; bei Erfolg wird die Referenz entpackt.
  3. Ankündigung anfordern: Über die Methode TriggerVehicleAnnouncement(networkInterfaceId) wird der Versand auf der gewünschten Netzwerkschnittstelle angestoßen ([SWS_DM_00822]).
  4. Nachrichtenversand durch DM: Der DM verarbeitet die Anfrage und sendet Fahrzeugankündigungsnachrichten gemäß ISO 13400-2 auf der durch networkInterfaceId identifizierten Schnittstelle ([SWS_DM_00815]).

Sequenzdiagramm: Aufrufreihenfolge zur Auslösung von DoIP-Fahrzeugankündigungen. Quellen: [SWS_DM_00815], [SWS_DM_00821], [SWS_DM_00822].

Fehlerszenarien

Ein zentrales Fehlerszenario bei der Nutzung von TriggerVehicleAnnouncement betrifft aktivierungsleitungsabhängige Netzwerkschnittstellen: Gehört die übergebene networkInterfaceId zu einer Schnittstellenkonfiguration (DoIPNetworkConfiguration), bei der die Eigenschaft isActivationLineDependent = TRUE gesetzt ist, führt der Aufruf zu einem Fehler ([SWS_DM_00822]). Auf solchen Schnittstellen wird der Versand von Ankündigungsnachrichten bereits automatisch durch den DM ausgelöst, sobald die Aktivierungsleitung aktiv ist und eine IP-Adresse zugewiesen wurde ([SWS_DM_00816], [SWS_DM_00822]).

Für die Funktionen GetDoIPTriggerVehicleAnnouncement() und TriggerVehicleAnnouncement() sind keine standardisierten Fehlercodes spezifiziert ([SWS_DM_00821], [SWS_DM_00822]). Etwaige Laufzeitfehler oder herstellerspezifische Fehlerzustände werden im zurückgegebenen ara::core::Result transportiert und müssen von der aufrufenden Anwendung geprüft werden.

          Verwendung und Semantik
          

          Die Funktion nimmt den Parameter networkInterfaceId (std::uint8_t) entgegen, welcher die Ziel-Netzwerkschnittstelle identifiziert, und liefert ein ara::core::Result<void> zurück [SWS_DM_00822]. Sie ist als noexcept deklariert und wirft keine Ausnahmen [SWS_DM_00822].

          Standardisierte Fehlercodes sind für diese Methode nicht definiert [SWS_DM_00822]. Interpretation: Da keine standardisierten Fehlercodes existieren, dürfte der Fehler über einen herstellerspezifischen Fehlercode im Result-Objekt signalisiert werden.
          

          Nebenläufigkeit und Zusammenspiel
          

          Die Operation ist als nicht threadsicher (not thread-safe) spezifiziert [SWS_DM_00822]. Zudem merkt die Spezifikation an, dass die Ankündigung primär eine DM-interne Funktionalität darstellt und ein explizites Auslösen durch eine Adaptive Application konzeptionell eigentlich nicht vorgesehen ist AUTOSAR_AP_SWS_Diagnostics §7.x „About DiagnosticDoIPTriggerVehicleAnnouncementInterface“.
