Kontext

Die Klasse ara::diag::DoIPTriggerVehicleAnnouncement [SWS_DM_00820] stellt eine Programmierschnittstelle innerhalb der AUTOSAR Adaptive Platform (Modul diag) bereit, über die eine Adaptive Application das Aussenden von DoIP-Fahrzeugankündigungsnachrichten (Vehicle Announcement Messages) initiieren kann.

Gemäß AUTOSAR_AP_SWS_Diagnostics S. 106 „About DiagnosticDoIPTriggerVehicleAnnouncementInterface“ liegt die primäre Verantwortung für das Senden dieser Nachrichten unmittelbar beim Diagnostic Manager (DM). Der Standard sieht vor, dass der DM Fahrzeugankündigungen eigenständig auf Basis der in ISO 13400-2 definierten Szenarien aussendet:

  • beim Starten des Netzwerks als Broadcast an andere IP-basierte Steuergeräte und Gateways,
  • bei Erkennung eines externen Testers über eine Aktivierungsleitung (Activation Line).

Obwohl der reguläre Ablauf nach ISO 13400-2 eine autonome Abwicklung durch den DM vorsieht und ein manuelles Auslösen durch eine Adaptive Application dort eigentlich nicht vorgesehen ist (AUTOSAR_AP_SWS_Diagnostics S. 106 „About DiagnosticDoIPTriggerVehicleAnnouncementInterface“), ermöglicht die Schnittstelle ara::diag::DoIPTriggerVehicleAnnouncement einer Anwendung dennoch das explizite Triggern. Der DM fungiert dabei als Ausführer, der die Nachrichten nach ISO 13400-2 auf der angegebenen Netzwerkschnittstelle aussendet [SWS_DM_00815].

Lebenszyklus

Die Instanziierung und Lebensdauerverwaltung von ara::diag::DoIPTriggerVehicleAnnouncement unterliegt vollständig dem Diagnostic Manager:

  • Erzeugung und Zerstörung: Der Standardkonstruktor ist als gelöscht deklariert (DoIPTriggerVehicleAnnouncement() = delete) und privat geschützt [SWS_DM_02100]. Ebenso ist der Destruktor privat und gelöscht (~DoIPTriggerVehicleAnnouncement() noexcept = delete) [SWS_DM_02101]. Beide Methoden sind herstellerspezifisch implementiert [SWS_DM_02100], [SWS_DM_02101]. Eine Adaptive Application kann somit keine eigenen Instanzen auf dem Stack oder Heap instanziieren.
  • Instanzbeschaffung: Der Zugriff auf die Schnittstelle erfolgt ausschließlich über die statische Fabrikmethode GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]. Diese gibt ein Objekt vom Typ ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>> zurück, welches eine Referenz auf das DM-verwaltete Objekt bereitstellt.
  • Nebenläufigkeit: Sowohl die Fabrikmethode GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] als auch die Methode TriggerVehicleAnnouncement() [SWS_DM_00822] sind explizit als nicht threadsicher (not thread-safe) spezifiziert. Greifen mehrere Threads einer Anwendung auf die Schnittstelle zu, muss der Aufrufer die Synchronisation sicherstellen. Beide Methoden sind als ausnahmesicher (exception safe) spezifiziert [SWS_DM_00821], [SWS_DM_00822].

Nutzungspfad

Der typische Ablauf zur Auslösung einer Fahrzeugankündigung gliedert sich in folgende Schritte:

  1. Schnittstellenreferenz anfordern: Die Adaptive Application ruft die statische Funktion ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() auf [SWS_DM_00821].
  2. Ergebnis validieren: Die Anwendung prüft das zurückgegebene ara::core::Result auf Erfolg und entpackt den std::reference_wrapper.
  3. Ankündigung auslösen: Über die gewonnene Referenz ruft die Anwendung die Methode TriggerVehicleAnnouncement(networkInterfaceId) auf [SWS_DM_00822]. Der Parameter networkInterfaceId (Typ std::uint8_t) gibt die Ziel-Netzwerkschnittstelle an.
  4. Aussendung über den DM: Der Diagnostic Manager veranlasst das Senden der Ankündigungsnachrichten gemäß ISO 13400-2 auf dem spezifizierten Netzwerkinterface [SWS_DM_00815] und quittiert die Ausführung an die Anwendung mit ara::core::Result<void> [SWS_DM_00822].

Sequenzdiagramm: Interaktionsmuster zum expliziten Triggern von DoIP-Fahrzeugankündigungen. Quellen: [SWS_DM_00821], [SWS_DM_00822], [SWS_DM_00815].

Fehlerszenarien

Beim Aufruf von TriggerVehicleAnnouncement() gelten spezifische Vorbedingungen hinsichtlich der Netzwerkkonfiguration:

  • Konflikt mit aktivierungsleitungsgesteuerten Schnittstellen: Falls die übergebene networkInterfaceId zu einer Konfiguration gehört, bei welcher die Eigenschaft isActivationLineDependent = TRUE gesetzt ist, stellt dieser Methodenaufruf einen Fehler dar [SWS_DM_00822]. Der Grund hierfür ist, dass das Aussenden auf solchen Interfaces gemäß [SWS_DM_00816] bereits vollautomatisch durch den DM erfolgt, sobald die Aktivierungsleitung ansteigt und eine IP-Adresse zugewiesen wurde [SWS_DM_00822].
  • Fehlende standardisierte Fehlercodes: Für weder GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] noch TriggerVehicleAnnouncement() [SWS_DM_00822] sind im Standard spezifische Fehlercodes vordefiniert („This function does not specify any standardized errors“). Tritt dennoch ein Fehler auf (wie die Übergabe einer aktivierungsleitungsabhängigen Schnittstelle oder ein interner Fehler), transportiert das ara::core::Result vermutlich herstellerspezifische Fehlercodes.
