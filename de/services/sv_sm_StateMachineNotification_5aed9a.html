Informiert Adaptive Applications über den aktuellen Zustand und laufende Übergänge einer Zustandsmaschine.

Das Service-Interface StateMachineNotification stellt Adaptive Applications den Zustand einer Zustandsmaschine über das lesbare und abonnierbare Feld CurrentState bereit ([SWS_SM_91028], [SWS_SM_91109]). Bei Zustandswechseln signalisiert das Feld den Zwischenwert "inTransition", bis alle Aktionen ausgeführt wurden ([SWS_SM_00616]). Die Schnittstelle wird nach dem Start der Zustandsmaschine angeboten und bei deren Beendigung wieder entzogen ([SWS_SM_00618], [SWS_SM_00619]).

Rolle und Systemkontext der Service-Schnittstelle

Das Service-Interface StateMachineNotification wird vom Modul State Management (SM) der AUTOSAR Adaptive Platform bereitgestellt ([SWS_SM_91028]). Während Steuerungsanwendungen über gesonderte Schnittstellen neue Zustandsübergänge anfordern, interagiert StateMachineNotification vor allem mit regulären Adaptive Applications auf der Anwendungsebene (AUTOSAR_AP_SWS_StateManagement S. 44). Der Service fungiert als Provider (Skeleton), während konsumierende Anwendungen als Consumer (Proxy) über ara::com angebunden sind. Sofern für eine konkrete Zustandsmaschine konfiguriert, instanziiert State Management eine eigene Instanz dieses Interfaces ([SWS_SM_00665]). In Projekten, in denen bestimmte Zustandsmaschinen rein intern arbeiten und für Applikationen nicht relevant sind, kann auf die Konfiguration und das Bereitstellen verzichtet werden (AUTOSAR_AP_SWS_StateManagement S. 45).

Methoden, Ereignisse und Felder

Die Schnittstelle definiert keine klassischen Methoden oder reinen Events, sondern kapselt den Zustand der überwachten Zustandsmaschine in einem zentralen Feld ([SWS_SM_91109]). Das Feld CurrentState besitzt den Datentyp StateMachineStateNameType und ist rein lesend ausgelegt: Es verfügt über einen Getter (HasGetter: true) sowie einen Notifier (HasNotifier: true), besitzt jedoch keinen Setter (HasSetter: false) ([SWS_SM_91109]). Adaptive Applications können den aktuellen Wert damit sowohl synchron über den Getter abfragen als auch Benachrichtigungen abonnieren, um bei Zustandswechseln der jeweiligen Zustandsmaschine asynchron über ara::com informiert zu werden ([SWS_SM_91109]).

Sobald ein Zustandsübergang der Zustandsmaschine gestartet wird, nimmt das Feld CurrentState den festen Wert "inTransition" an ([SWS_SM_00616]). Dieser Zwischenzustand wird unabhängig von der auslösenden Quelle – beispielsweise Execution Management, Platform Health Management oder einer Steuerungsanwendung – gesetzt und bleibt auch dann bestehen, wenn als Reaktion auf Fehlerbenachrichtigungen weitere Übergänge stattfinden (AUTOSAR_AP_SWS_StateManagement S. 67). Erst wenn sämtliche zugehörigen Aktionen abgearbeitet wurden, wird der Wert auf den tatsächlichen Zielzustand der Zustandsmaschine aktualisiert ([SWS_SM_00617]).

Lebenszyklus, Bereitstellung und Zustandsabhängigkeiten

Das Starten einer Zustandsmaschine ist ein mehrstufiger Vorgang (AUTOSAR_AP_SWS_StateManagement S. 59). Eine Zustandsmaschine gilt aus Sicht übergeordneter Controller erst dann als gestartet, wenn sie existiert und ihre zugeordneten Schnittstellen angeboten werden (AUTOSAR_AP_SWS_StateManagement S. 59). Jede konfigurierte StateMachineNotification-Instanz wird über ara::com bereitgestellt (offered), sobald das ActionListItem mit dem Befehl StartStateMachine erfolgreich verarbeitet wurde ([SWS_SM_00618]). Dies ermöglicht Applikationen frühzeitig die Bindung an den Service.

Wird eine Zustandsmaschine beendet oder zurückgefahren, wird der Service wieder entzogen: Die Schnittstelle steht ab dem Zeitpunkt nicht mehr zur Verfügung (StopOffer), an dem die entsprechende Beendigungsaktion verarbeitet wird ([SWS_SM_00619]). Werden Zustandsmaschinen von einem Controller gesteuert, verlangt das Metamodell zudem, dass jede Aktionsliste die vollständige Menge der kontrollierten Agenten referenziert ([SWS_SM_CONSTR_00016]).

Fehlerbehandlung und Randbedingungen

Für StateMachineNotification sind im Schnittstellenmodell keine eigenen anwendungsspezifischen Application Errors (wie kOperationRejected) definiert, da das Interface rein beobachtend arbeitet und keine modifizierenden Methoden anbietet ([SWS_SM_91109]). Die Fehlerbehandlung stützt sich auf die Kommunikationsmechanismen von ara::com bei der Abfrage des Feldes sowie auf die Auswertung des Status "inTransition": Konsumenten dürfen diesen Zwischenwert als Kennzeichnung eines laufenden Umschalt- oder Fehlerbehebungsablaufs interpretieren (AUTOSAR_AP_SWS_StateManagement S. 67).

CurrentState service field

This field represents the current state of StateMachine. If StateMachine is currently in transition between two different states, then the value of this field is set to "InTransition". Adaptive Applications can use this field for notifications if they are interested in state changes of a particular StateMachine.
