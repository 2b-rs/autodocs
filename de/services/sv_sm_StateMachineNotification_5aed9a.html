Rolle und Systemkontext der Service-Schnittstelle

Das Service-Interface StateMachineNotification ist eine fundamentale ara::com-Serviceschnittstelle des Funktionsclusters State Management (SM) in der AUTOSAR Adaptive Platform ([SWS_SM_91028]). Sofern für eine Zustandsmaschine projektspezifisch konfiguriert, instanziiert das State Management für diese Instanz von StateMachine eine dedizierte Service-Instanz von StateMachineNotification ([SWS_SM_00665]). In dieser Kommunikationsbeziehung agiert das State Management als Service-Provider (Skeleton), während interessierte Applikationen als Consumer (Proxy) auftreten.

Der primäre Verwendungszweck liegt in der Interaktion mit regulären Adaptive Applications (AUTOSAR_AP_SWS_StateManagement §7 „StateMachineNotification service interface“). Da in realen Fahrzeugprojekten nicht jede interne Zustandsmaschine für die Anwendungsschicht von Bedeutung ist, besteht keine Verpflichtung, für jede Instanz zwingend eine Benachrichtigungsschnittstelle bereitzustellen (AUTOSAR_AP_SWS_StateManagement §7 „StateMachineNotification service interface“). Während über die komplementäre Schnittstelle StateMachineService aktive Zustandsanforderungen gestellt werden ([SWS_SM_00600]), dient StateMachineNotification der rein beobachtenden Zustandsüberwachung.

Felder und Benachrichtigungssemantik

Die Schnittstelle StateMachineNotification definiert keine RPC-Methoden oder isolierte Events, sondern stellt die Zustandsinformation über ein zentrales Feld bereit: CurrentState vom Datentyp StateMachineStateNameType ([SWS_SM_91109]). Gemäß Feldspezifikation verfügt CurrentState über einen Getter (HasGetter = true) und einen Notifier (HasNotifier = true), verbietet jedoch schreibende Zugriffe durch Anwendungen (HasSetter = false) (AUTOSAR_AP_SWS_StateManagement §8 „Definition of Field StateMachineNotification.CurrentState“, [SWS_SM_91109]). Adaptive Applications können sich somit per Notifier asynchron über Zustandsänderungen informieren lassen oder den aktuellen Status jederzeit synchron abfragen.

Sobald eine Zustandstransition initiiert wird, wechselt der Wert des Feldes CurrentState unverzüglich auf den Übergangswert "inTransition" ([SWS_SM_00616], AUTOSAR_AP_SWS_StateManagement §7 „Value of configured StateMachineNotification::CurrentState field“). Dieser Zwischenzustand signalisiert den Konsumenten, dass die Zustandsmaschine nicht stabil ist und Aktionen im Gange sind.

Erst wenn alle zugehörigen Aktionen innerhalb der abgearbeiteten ActionList vollständig ausgeführt wurden, setzt das State Management das Feld CurrentState auf den neu erreichten Zielzustand ([SWS_SM_00617]). Abonnierte Clients erhalten über den Notifier bei beiden Wechseln eine entsprechende Benachrichtigung.

Lebenszyklus und Service-Bereitstellung

Das Starten einer Zustandsmaschine ist ein mehrstufiger Ablauf (AUTOSAR_AP_SWS_StateManagement §7 „Completeness of controlled StateMachines“). Neben der Initialisierung und Bereitstellung der Schnittstellen für die Anwendungsschicht muss die Zustandsmaschine die Ausführung der ActionList anstoßen, die dem initialen Zustand entspricht (AUTOSAR_AP_SWS_StateManagement §7 „Completeness of controlled StateMachines“, [SWS_SM_CONSTR_00016]). Aus Sicht einer übergeordneten Steuerung (Controller) gilt die StateMachine erst dann als gestartet, wenn sie existiert und ihre assoziierten Services angeboten werden (AUTOSAR_AP_SWS_StateManagement §7 „Completeness of controlled StateMachines“).

Die Bereitstellung des ara::com-Services StateMachineNotification erfolgt exakt zu dem Zeitpunkt, an dem das ActionListItem "StartStateMachine" erfolgreich abgearbeitet wurde ([SWS_SM_00618]). Sobald der Service über OfferService verfügbar ist, können Anwendungen den Proxy binden und das Feld abonnieren (AUTOSAR_AP_SWS_StateManagement §7 „StateMachine service interfaces - Offer“). Wird die Zustandsmaschine heruntergefahren oder gestoppt, wird der Service nicht mehr angeboten (StopOffer) ([SWS_SM_00619]).

Zustandsüberwachung und Fehlerverhalten

Zustandstransitionen können durch unterschiedliche Quellen angestoßen werden, darunter Platform Health Management, Execution Management oder eine SMControlApplication (AUTOSAR_AP_SWS_StateManagement §7 „Value of configured StateMachineNotification::CurrentState field“). Der Übergangswert "inTransition" wird unabhängig vom Auslöser gesetzt und bleibt auch dann bestehen, wenn aufgrund einer Fehlermeldung direkt ein Folgeübergang zur Fehlerbehebung eingeleitet wird ([SWS_SM_00616]).

Da StateMachineNotification als reine Benachrichtigungsschnittstelle ohne Methoden konzipiert ist ([SWS_SM_91028], [SWS_SM_91109]), existieren keine fachlichen Application Errors. Interpretation: Mögliche Fehler beim Lesen des Feldes (Getter) beschränken sich auf Kommunikations- und Infrastrukturfehler der ara::com-Laufzeitumgebung.

CurrentState service field

This field represents the current state of StateMachine. If StateMachine is currently in transition between two different states, then the value of this field is set to "InTransition". Adaptive Applications can use this field for notifications if they are interested in state changes of a particular StateMachine.
