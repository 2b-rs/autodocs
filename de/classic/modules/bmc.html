requirement SWS_BMC_00001 [SWS_BMC_00001] 📄 PDF

The Bmc module shall provide the following files: C files Bmc_<name>.c used to implement the library. All C files shall be pre-fixed with 'Bmc_'. The header file Bmc.h provides all public function prototypes and types defined by the Bmc library specification.

requirement SWS_BMC_00002 [SWS_BMC_00002] 📄 PDF

DRAFT No error classification definition – like DET error IDs – shall be supported by library.

requirement SWS_BMC_00003 [SWS_BMC_00003] 📄 PDF

DRAFT Error detection: Functions should check at runtime (both in production and in development code) the value of input parameters, especially cases where erroneous value can bring to fatal error or unpredictable result, if they have the values allowed by the function specification. All the error cases shall be listed in SWS and the function should return a specified value (in SWS) that is not configurable. This value is dependent of the function and the error case so it is determined case by case. If values passed to the library routines are not in valid range, out of boundary condition and out of the function specification, then such errors are not detected in the library routines.

requirement SWS_BMC_00004 [SWS_BMC_00004] 📄 PDF

DRAFT The functions shall not call the DET for error notifica- tion.

requirement SWS_BMC_00005 [SWS_BMC_00005] 📄 PDF

The Bmc library shall not require an initialization phase. A Li- brary function may be called at the very first step of ECU initialization, e.g. even by the OS or EcuM, thus the library shall be ready.

requirement SWS_BMC_00006 [SWS_BMC_00006] 📄 PDF

The Bmc library shall not require a shutdown operation phase.

requirement SWS_BMC_00007 [SWS_BMC_00007] 📄 PDF

The Bmc API can be directly called from BSW modules or SWCs. No port definition is required. It is a pure function call.

requirement SWS_BMC_00008 [SWS_BMC_00008] 📄 PDF

Using a library should be documented. If a BSW module or a SWC uses a library, the developer should add an ImplementationDependencyOnArti- fact in the BSW/SWC template. minVersion and maxVersion parameters correspond to the supplier version. In case of an AUTOSAR library, these parameters may be left empty because a SWC or BSW module may rely on a library behavior, not on a sup- plier implementation. However, the SWC or BSW modules shall be compatible with the AUTOSAR platform where they are integrated.

requirement SWS_BMC_00009 [SWS_BMC_00009] 📄 PDF

The Bmc library shall be implemented in a way that the code can be shared among callers in different memory partitions.

requirement SWS_BMC_00010 [SWS_BMC_00010] 📄 PDF

Usage of macros should be avoided. The functions should be declared as functions or inline functions.

requirement SWS_BMC_00011 [SWS_BMC_00011] 📄 PDF

A library function shall not call any BSW modules functions, e.g. the DET. A library function can call other library functions because a library function shall be re-entrant. But other BSW modules functions may not be re-entrant.

requirement SWS_BMC_00012 [SWS_BMC_00012] 📄 PDF

The library, written in the C programming language, should con- form to the MISRA C Standard. Please refer to SWS_BSW_00115 for more details.

requirement SWS_BMC_00013 [SWS_BMC_00013] 📄 PDF

Each AUTOSAR library Module implementation <library> * .c and <library> * .h shall map their code to memory sections using the AUTOSAR memory mapping mechanism.

requirement SWS_BMC_00014 [SWS_BMC_00014] 📄 PDF

Each AUTOSAR library Module implementation <library> * .c that uses AUTOSAR integer data types and/or the standard return type, shall include the header file Std_Types.h .

Anforderungen

SWS_BMC_00001 requirement

The Bmc module shall provide the following files: C files Bmc_<name>.c used to implement the library. All C files shall be pre-fixed with 'Bmc_'. The header file Bmc.h provides all public function prototypes and types defined by the Bmc library specification.

SWS_BMC_00002 requirement

DRAFT No error classification definition – like DET error IDs – shall be supported by library.

SWS_BMC_00003 requirement

DRAFT Error detection: Functions should check at runtime (both in production and in development code) the value of input parameters, especially cases where erroneous value can bring to fatal error or unpredictable result, if they have the values allowed by the function specification. All the error cases shall be listed in SWS and the function should return a specified value (in SWS) that is not configurable. This value is dependent of the function and the error case so it is determined case by case. If values passed to the library routines are not in valid range, out of boundary condition and out of the function specification, then such errors are not detected in the library routines.

SWS_BMC_00004 requirement

DRAFT The functions shall not call the DET for error notifica- tion.

SWS_BMC_00005 requirement

The Bmc library shall not require an initialization phase. A Li- brary function may be called at the very first step of ECU initialization, e.g. even by the OS or EcuM, thus the library shall be ready.

SWS_BMC_00006 requirement

The Bmc library shall not require a shutdown operation phase.

SWS_BMC_00007 requirement

The Bmc API can be directly called from BSW modules or SWCs. No port definition is required. It is a pure function call.

SWS_BMC_00008 requirement

Using a library should be documented. If a BSW module or a SWC uses a library, the developer should add an ImplementationDependencyOnArti- fact in the BSW/SWC template. minVersion and maxVersion parameters correspond to the supplier version. In case of an AUTOSAR library, these parameters may be left empty because a SWC or BSW module may rely on a library behavior, not on a sup- plier implementation. However, the SWC or BSW modules shall be compatible with the AUTOSAR platform where they are integrated.

SWS_BMC_00009 requirement

The Bmc library shall be implemented in a way that the code can be shared among callers in different memory partitions.

SWS_BMC_00010 requirement

Usage of macros should be avoided. The functions should be declared as functions or inline functions.

SWS_BMC_00011 requirement

A library function shall not call any BSW modules functions, e.g. the DET. A library function can call other library functions because a library function shall be re-entrant. But other BSW modules functions may not be re-entrant.

SWS_BMC_00012 requirement

The library, written in the C programming language, should con- form to the MISRA C Standard. Please refer to SWS_BSW_00115 for more details.

SWS_BMC_00013 requirement

Each AUTOSAR library Module implementation <library> * .c and <library> * .h shall map their code to memory sections using the AUTOSAR memory mapping mechanism.

SWS_BMC_00014 requirement

Each AUTOSAR library Module implementation <library> * .c that uses AUTOSAR integer data types and/or the standard return type, shall include the header file Std_Types.h .

SWS_BMC_00015 requirement

All AUTOSAR library Modules should use the AUTOSAR data types (integers, boolean) instead of native C data types unless this library is clearly identified to be compliant only with one platform.

SWS_BMC_00016 requirement

All AUTOSAR library Modules should avoid direct use of com- piler and platform specific keywords unless this library is clearly identified to be com- pliant only with one platform.
