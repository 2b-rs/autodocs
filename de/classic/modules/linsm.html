function LinSM_ScheduleRequest [SWS_LinSM_00113] 📄 PDF

Std_ReturnType LinSM_ScheduleRequest (NetworkHandleType network, LinIf_SchHandleType schedule);

The upper layer requests a schedule table to be changed on one LIN network.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 358404935ae6 Herkunft

Verwendung und Semantik

Die Funktion LinSM_ScheduleRequest ([SWS_LinSM_00113]) dient einer oberen Schicht dazu, den Wechsel einer Schedule-Tabelle auf einem LIN-Netzwerk anzufordern. Der Dienst wird über den Header LinSM.h bereitgestellt, arbeitet asynchron und ist als reentrant spezifiziert.

Übergabeparameter:

  • network (NetworkHandleType): Identifikation des LIN-Kanals.
  • schedule (LinIf_SchHandleType): Zeiger bzw. Handle auf die neu anzufordernde Schedule-Tabelle.

Rückgabewerte und Fehlerverhalten

Die Funktion liefert einen Status vom Typ Std_ReturnType zurück ([SWS_LinSM_00113]):

  • E_OK: Die Anforderung für die Schedule-Tabelle wurde erfolgreich akzeptiert.
  • E_NOT_OK: Die Anforderung konnte nicht ausgeführt werden (beispielsweise wenn das Modul nicht initialisiert ist).

Konfigurationsabhängigkeiten und Zusammenspiel

Die Verfügbarkeit von LinSM_ScheduleRequest ist an die Rollenkonfiguration des Moduls gebunden: Gemäß [SWS_LinSM_00241] steht die Funktion nur dann zur Verfügung, wenn das Modul LinSM über den Konfigurationsparameter LinSMNodeType auf mindestens einem Kanal als LIN-Master konfiguriert ist. In einer reinen LIN-Slave-Konfiguration ist die Funktion nicht verfügbar.

In analoger Weise setzt auch die zugehörige Bestätigungsfunktion LinSM_ScheduleRequestConfirmation voraus, dass mindestens ein Kanal als LIN-Master betrieben wird ([SWS_LinSM_00242]).

Std_ReturnType LinSM_RequestComMode (NetworkHandleType network, ComM_ModeType mode);

Requesting of a communication mode. The mode switch will not be made instant. The Lin SM will notify the caller when mode transition is made.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: f91026a2c23e Herkunft

Die Funktion LinSM_RequestComMode ([SWS_LinSM_00126]) dient dem Anfordern eines Kommunikationsmodus für einen LIN-Kanal. Der Aufruf verhält sich asynchron: Der Moduswechsel wird nicht unmittelbar vollzogen, sondern das LinSM benachrichtigt den Aufrufer, sobald der Zustandsübergang abgeschlossen ist. Als Eingangsparameter werden network zur Identifikation des LIN-Kanals sowie mode für den angeforderten Kommunikationsmodus übergeben.

Hinsichtlich der Nebenläufigkeit ist die Schnittstelle als reentrant spezifiziert ([SWS_LinSM_00126]). Als Rückgabewert liefert die Funktion E_OK, wenn die Anforderung erfolgreich akzeptiert wurde. Ist die Ausführung der Anforderung nicht möglich – beispielsweise wenn das Modul nicht initialisiert ist –, wird E_NOT_OK zurückgegeben ([SWS_LinSM_00126]).

Beim Zusammenspiel mit anderen Modulen ist folgendes Fehlerverhalten geregelt: Wenn ein Aufruf von LinIf_GotoSleep den Rückgabewert E_NOT_OK liefert, muss auch LinSM_RequestComMode mit E_NOT_OK antworten ([SWS_LinSM_00177]). Gibt das LinSM-Modul bei LinSM_RequestComMode den Wert E_NOT_OK zurück, ist derselbe Zustand beizubehalten bzw. zu setzen, sodass ComM_BusSM_ModeIndication und BswM_LinSM_CurrentState aufgerufen werden ([SWS_LinSM_00177]).

function LinSM_ScheduleRequestConfirmation [SWS_LinSM_00129] 📄 PDF

void LinSM_ScheduleRequestConfirmation (NetworkHandleType network, LinIf_SchHandleType schedule);

The Lin If module will call this callback when the new requested schedule table is active.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 352b37e5c5c9 Herkunft

Die Callback-Funktion LinSM_ScheduleRequestConfirmation ([SWS_LinSM_00129]) dient als Rückmeldung an das Modul LinSM, sobald eine zuvor angeforderte neue Schedule-Tabelle tatsächlich aktiv geschaltet wurde. Sie wird vom LIN-Interface (LinIf) aufgerufen.

Verwendung und Parameter

Der Aufruf erfolgt synchron und liefert keinen Rückgabewert (void). Die Funktion ist über den Header LinSM.h deklariert und besitzt die Service-ID 0x20 gemäß [SWS_LinSM_00129]. Sie nimmt zwei Eingabeparameter entgegen:

  • network (NetworkHandleType): Identifikation des betroffenen LIN-Kanals.
  • schedule (LinIf_SchHandleType): Zeiger bzw. Handle auf die nun aktive Schedule-Tabelle.

Nebenläufigkeit und Einschränkungen

Laut Spezifikation ist die Funktion als reentrant klassifiziert ([SWS_LinSM_00129]), wodurch gleichzeitige Bestätigungen für unterschiedliche Kanäle verarbeitet werden können.

Zusammenspiel

Die Funktion fungiert als Schnittstelle im Zusammenspiel zwischen LinIf und LinSM: Nachdem ein Wechsel der Schedule-Tabelle initiiert wurde, informiert LinIf das LinSM über diese Callback-Routine über das Wirksamwerden der Umschaltung ([SWS_LinSM_00129]).

The Lin If will call this callback when the go to sleep command is received on the network or a bus idle timeout occurs. Only applicable for LIN slave nodes.

Verwendung und Aufrufkontext

Die Callback-Funktion LinSM_GotoSleepIndication ([SWS_LinSM_91000]) des Moduls LinSM besitzt die Service-ID 0x03 und wird über die Header-Datei LinSM.h deklariert. Sie wird vom LIN-Interface (LinIf) aufgerufen, sobald auf dem Netzwerk der Befehl zum Wechsel in den Schlafzustand („go to sleep command“) registriert wurde oder ein Timeout durch Bus-Inaktivität („bus idle timeout“) aufgetreten ist ([SWS_LinSM_91000]).

Die Verwendung dieses Callbacks ist ausdrücklich auf LIN-Slave-Knoten („LIN slave nodes“) beschränkt ([SWS_LinSM_91000]).

Parameter und Ausführungsverhalten

  • Channel (In): Identifiziert den betroffenen LIN-Kanal anhand des Übergabewerts vom Typ NetworkHandleType ([SWS_LinSM_91000]).
  • Rückgabewert: Keiner (void); die Schnittstelle definiert weder Ein-/Ausgangs- noch reine Ausgangsparameter ([SWS_LinSM_91000]).
  • Synchronität: Der Aufruf wird synchron abgewickelt ([SWS_LinSM_91000]).
  • Reentranz: Die Funktion ist reentrant ausgelegt ([SWS_LinSM_91000]).

Dieser Nutzungshinweis basiert auf der Spezifikation AUTOSAR Classic Release R20-11 und fasst die Festlegungen zu Service-ID, Reentranz und Parametern zusammen.

function LinSM_GotoSleepConfirmation [SWS_LinSM_00135] 📄 PDF

void LinSM_GotoSleepConfirmation (NetworkHandleType network, boolean success);

The Lin If will call this callback when the go to sleep command is sent successfully or not sent successfully on the network.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: db02cf40272e Herkunft

Verwendung

Die Funktion LinSM_GotoSleepConfirmation ist eine synchrone Callback-Schnittstelle (Service-ID 0x22), die über den Header LinSM.h zur Verfügung gestellt wird [SWS_LinSM_00135]. Sie wird von der LIN-Schnittstelle (LinIf) aufgerufen, um zu bestätigen, ob der Befehl zum Wechsel in den Schlafzustand („go to sleep command“) erfolgreich oder nicht erfolgreich auf dem Netzwerk gesendet wurde [SWS_LinSM_00135].

  • network (In, NetworkHandleType): Identifikation des betroffenen LIN-Kanals [SWS_LinSM_00135].
  • success (In, boolean): Gibt an, ob das Senden des Schlaf-Befehls erfolgreich war (TRUE) oder fehlschlug (FALSE) [SWS_LinSM_00135].

Die Funktion besitzt keinen Rückgabewert [SWS_LinSM_00135].

Nebenläufigkeit und Einschränkungen

Gemäß Spezifikation ist LinSM_GotoSleepConfirmation als reentrant eingestuft [SWS_LinSM_00135]. Dies gestattet parallele Bestätigungsaufrufe, beispielsweise bei der gleichzeitigen Verwaltung mehrerer LIN-Netzwerke durch LinIf.

Fehlerbehandlung und Zusammenspiel

Das Ergebnis der Übertragung wird über das Argument success transportiert [SWS_LinSM_00135]. Spezifische DET- oder DEM-Fehler sind für diesen Callback in den Spezifikationsdaten nicht ausgewiesen. Das Modul LinSM dürfte den Wert von success intern heranziehen, um den Kanalzustand entsprechend anzupassen oder Folgeaktionen für fehlgeschlagene Sendeversuche zu koordinieren.

Dieser Nutzungshinweis wurde automatisiert auf Basis der AUTOSAR-Spezifikation für LinSM (Release R20-11) erstellt.

function LinSM_WakeupConfirmation [SWS_LinSM_00132] 📄 PDF

void LinSM_WakeupConfirmation (NetworkHandleType network, boolean success);

The Lin If will call this callback when the wake up signal command is sent not successfully/ successfully on the network.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 0dc152a36517 Herkunft

Verwendung

Die Funktion LinSM_WakeupConfirmation ([SWS_LinSM_00132]) ist eine Callback-Schnittstelle des LIN State Managers (LinSM). Sie wird vom LIN Interface (LinIf) aufgerufen, sobald die Übertragung eines Wake-up-Signal-Befehls auf dem Netzwerk abgeschlossen ist – unabhängig davon, ob das Senden erfolgreich war oder fehlschlug.

Die Signatur lautet void LinSM_WakeupConfirmation (NetworkHandleType network, boolean success) mit der Service-ID 0x21 (verfügbar über die Header-Datei LinSM.h). Die Funktion besitzt folgende Parameter:

  • network (Eingang): Identifikation des betreffenden LIN-Netzwerks bzw. -Kanals (Typ NetworkHandleType).
  • success (Eingang): Boolescher Indikator (Typ boolean), der anzeigt, ob das Wecksignal erfolgreich auf dem Bus versendet werden konnte (true) oder nicht (false).

Die Funktion liefert keinen Rückgabewert (void) und ist mit synchroner Ausführungssemantik (Synchronous) spezifiziert.

Nebenläufigkeit und Einschränkungen

Gemäß [SWS_LinSM_00132] ist LinSM_WakeupConfirmation als reentrant (Reentrant) klassifiziert. Sie kann somit sicher für unterschiedliche LIN-Kanäle innerhalb des Steuergeräts ausgeführt werden.

Dieser Nutzungshinweis basiert auf den Festlegungen der AUTOSAR-Classic-Spezifikation für den LIN State Manager (LinSM) im Release R20-11.

type LinSM_ModeType [SWS_LinSM_00220] 📄 PDF

Type used to report the current mode to the Bsw M

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 610d38682389 Herkunft

Verwendung

Der Typ LinSM_ModeType wird im Modul LinSM verwendet, um dem BswM (Basic Software Mode Manager) den aktuellen Kommunikationsmodus zu melden ([SWS_LinSM_00220]). Er ist als elementarer Typ auf Basis von uint8 abgeleitet und steht über die Header-Datei LinSM.h zur Verfügung ([SWS_LinSM_00220]).

Wertebereich

Gemäß Anforderung [SWS_LinSM_00220] definiert der Typ zwei diskrete Zustände für die Betriebsart:

  • LINSM_FULL_COM (Wert 0x01): Vollständige Kommunikation (Full communication) ([SWS_LinSM_00220]).
  • LINSM_NO_COM (Wert 0x02): Keine Kommunikation (No communication) ([SWS_LinSM_00220]).

Fehlerbehandlung und Nebenläufigkeit

Interpretation: Da LinSM_ModeType eine reine Typdefinition auf Basis von uint8 darstellt, definiert die Spezifikation [SWS_LinSM_00220] für diesen Typ weder eigene Entwicklungs- oder Produktionsfehler (DET/DEM) noch Laufzeit- oder Reentranzvorschriften. Die Gültigkeitsprüfung auf die definierten Werte (0x01 bzw. 0x02) dürfte in den Schnittstellenfunktionen des LIN State Managers erfolgen, welche Werte dieses Typs an den BswM übergeben.

Dieser Nutzungshinweis wurde für AUTOSAR Classic R20-11 auf Basis von Spezifikation [SWS_LinSM_00220] automatisch generiert.
