function IdsM_CopyTxDataManager [SWS_IdsM_91010] 📄 PDF

BufReq_ReturnType IdsM_CopyTxData (PduIdType id, const PduInfoType* info, const RetryInfoType* retry, PduLengthType* availableDataPtr);

This function is called to acquire the transmit data of an I-PDU segment (N-PDU). Each call to this function provides the next part of the I-PDU data unless retry->TpDataState is TP_ DATARETRY. In this case the function restarts to copy the data beginning at the offset from the current position indicated by retry->TxTpDataCnt. The size of the remaining data is written to the position indicated by availableDataPtr.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 4a17f4e76471 Herkunft

Verwendung und Semantik

Die Funktion [SWS_IdsM_91010] (bereitgestellt über IdsM_Cbk.h) wird synchron von unterlagerten Modulen (wie Transportprotokollen) aufgerufen, um Sendedaten eines I-PDU-Segments (N-PDU) abzurufen.

  • id: Bezeichnet die zu übertragende I-PDU.
  • info: Übergibt den Zielpuffer (SduDataPtr) und die Anzahl der zu kopierenden Bytes (SduLength). Bei einem Wert von 0 für SduLength darf SduDataPtr ein NULL_PTR sein; dies dient der Statusaktualisierung über den retry-Parameter oder der Abfrage verbleibender Daten.
  • retry: Steuert Bestätigung und Fehlerbehebung. Ist der Parameter NULL_PTR, können übertragene Daten sofort nach dem Kopieren aus dem Puffer entfernt werden. Andernfalls steuert der Zustand: TP_CONFPENDING hält zuvor kopierte Daten für Wiederholungen vor, TP_DATACONF bestätigt vorangegangene Übertragungen, und TP_DATARETRY veranlasst das erneute Kopieren ab dem in TxTpDataCnt angegebenen Byte-Offset.
  • availableDataPtr: Gibt die verbleibende Anzahl im Tx-Puffer verfügbarer Bytes zurück, was von Transportprotokollen mit variabler Nutzdatenlänge zur Bestimmung nachfolgender Segmente genutzt werden kann.

Rückgabewerte und Fehlerbehandlung

Die Rückgabe erfolgt über den Statuscode BufReq_ReturnType:

  • BUFREQ_OK: Daten wurden vollständig wie angefordert in den Zielpuffer kopiert.
  • BUFREQ_E_BUSY: Nicht genügend Sendedaten verfügbar; es wurden keine Daten kopiert. Die unterlagerte Schicht kann die Abfrage zu einem späteren Zeitpunkt wiederholen.
  • BUFREQ_E_NOT_OK: Die Anfrage ist fehlgeschlagen; es wurden keine Daten kopiert.

Nebenläufigkeit

Die Funktion ist laut [SWS_IdsM_91010] als synchron und reentrant spezifiziert.

Wird das Ereignis bei aktivem Zeitstempel-Feature hingegen ohne Zeitstempelparameter gemeldet, setzt das IdsM das Optionsbit für den Zeitstempel im Protokoll-Header vor Übertragung oder Speicherung auf 0 ([SWS_IdsM_01112]).

Fehlerbehandlung und Nebenläufigkeit

Die Funktion ist nicht reentrant (Non Reentrant) ([SWS_IdsM_91020]). Bei aktivierter Entwicklungserkennung (IdsMDevErrorDetect) validiert das Modul die Parameter securityEventId und count: Falls eine unbekannte Ereignis-ID übergeben wird oder count gleich 0 ist, wird der Entwicklungsfehler IDSM_E_PARAM_INVALID gemeldet ([SWS_IdsM_02105]).
