function Rte_Start [SWS_Rte_03015] 📄 PDF

Std_ReturnType Rte_Start (void);

Rte_Start is intended to allocate and initialize system resources and communication resources used by the RTE.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: aab1852b5fb6 Herkunft

Verwendung

Die Funktion Rte_Start ([SWS_Rte_02569]), die stets generiert wird ([SWS_Rte_01309]), allokiert und initialisiert die von der RTE genutzten System- und Kommunikationsressourcen ([SWS_Rte_03015]). Sie besitzt keine Übergabeparameter, liefert einen Std_ReturnType zurück und muss innerhalb einer endlichen Ausführungszeit ohne Endlosschleife terminieren ([SWS_Rte_02585]).

Aufrufkontext und Nebenläufigkeit

Rte_Start darf auf jedem Core nur genau einmal durch den EcuStateManager aus einem vertrauenswürdigen OS-Kontext aufgerufen werden, nachdem alle für die RTE erforderlichen Basissoftware-Module initialisiert wurden ([SWS_Rte_CONSTR_09035]). Der Aufruf erfolgt auf jedem Core unabhängig ([SWS_Rte_07615]) und deckt die partitionsspezifischen Startup-Aktivitäten für alle diesem Core zugeordneten Partitionen ab ([SWS_Rte_07616]).

Initialisierungsreihenfolge und Zusammenspiel

Im Rahmen von Rte_Start wird eine koordinierte Startsequenz durchlaufen:

  • Die für ramBlocks allozierten Variablen werden abhängig von der konfigurierten RteInitializationStrategy initialisiert ([SWS_Rte_07632]).
  • Nach der Variableninitialisierung, aber vor der Ausführung von Runnable Entities, ruft die RTE die Initialisierungsfunktionen Rte_Rips_Rte_Start aller beteiligten RTE-Implementation-Plug-Ins auf ([SWS_Rte_80052]).
  • Durch InitEvent ausgelöste Runnables werden einmalig aktiviert ([SWS_Rte_06761]), und der Übergang in initiale Modi wird eingeleitet ([SWS_Rte_06766]).
  • Existiert kein separates Rte_StartTiming, startet Rte_Start zusätzlich die Aktivierung von Runnables, die durch TimingEvents ([SWS_Rte_07575]) oder BackgroundEvents ([SWS_Rte_07178]) gesteuert werden.

Bestimmte Funktionen wie Rte_SetMirror dürfen explizit bereits vor Rte_Start aufgerufen werden ([SWS_Rte_07319]).

Fehlerbehandlung

Wird Rte_Start vor SchM_Init aufgerufen, meldet der Basissoftware-Scheduler bzw. die RTE bei aktiviertem RteDevErrorDetectUninit den Fehler RTE_E_UNINIT (0x07) ([SWS_Rte_07683]). Ebenso führt der unzulässige Aufruf überwachter RTE-APIs vor Rte_Start zur Meldung von RTE_E_UNINIT ([SWS_Rte_07682]).

Dieser Text wurde von einer KI basierend auf den Spezifikationsanforderungen von AUTOSAR Classic R20-11 generiert.

function Rte_Stop [SWS_Rte_01262] 📄 PDF

Std_ReturnType Rte_Stop (void);

Rte_Stop is used to finalize the RTE on the core it is called. This service releases all system and communication resources allocated by the RTE on that core.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: a630a2dc0fbd Herkunft

Verwendung und Semantik

Die Funktion Rte_Stop ([SWS_Rte_02570]) dient der Finalisierung der RTE auf dem aufrufenden Core und gibt alle von der RTE auf diesem Core belegten System- und Kommunikationsressourcen frei ([SWS_Rte_01262]). Die Schnittstelle wird stets bereitgestellt ([SWS_Rte_01310]), ist parameterlos, liefert Std_ReturnType zurück und kehrt innerhalb einer endlichen Ausführungszeit zurück ([SWS_Rte_02584]).

Reihenfolgebedingungen und Nebenläufigkeit

  • Nach dem Aufruf von Rte_Stop auf einem Core darf die RTE auf diesem Core keine RunnableEntitys mehr aktivieren, starten oder freigeben ([SWS_Rte_02538]).
  • Rte_Stop muss durch den EcuStateManager aufgerufen werden, bevor die von der RTE benötigten Basissoftware-Module heruntergefahren werden ([SWS_Rte_CONSTR_09038]).
  • Das API SchM_Deinit darf erst nach der vollständigen Beendigung von Rte_Stop aufgerufen werden ([SWS_Rte_CONSTR_09056]).
  • Die Funktion Rte_GetMirror bleibt auch nach dem Stoppen der RTE durch Rte_Stop aufrufbar und stützt sich auf ein laufendes Betriebssystem ([SWS_Rte_07350]).

Zusammenspiel und Fehlerbehandlung

  • Innerhalb von Rte_Stop ruft die RTE die Stopp-Funktionen Rte_Rips_Rte_Stop aller beteiligten RTE Implementation Plug-Ins auf ([SWS_Rte_80053]), welche neben weiteren Lifecycle-APIs verpflichtend bereitzustellen sind ([SWS_Rte_70047]).
  • Sofern RteDevErrorDetectUninit aktiviert ist, wird der Fehler RTE_E_UNINIT (0x07) gemeldet, falls bestimmte RTE-APIs nach Rte_Stop aufgerufen werden ([SWS_Rte_07682]).
  • Im Spezifikationskontext wird zudem der Fehlerstatus RTE_E_LIMIT genannt, wenn ein internes Limit überschritten wurde bzw. die Allokation einer erforderlichen Ressource fehlschlug ([SWS_Rte_01262]).

function SchM_Deinit [SWS_Rte_04551] 📄 PDF

void SchM_Deinit (void);

SchM_Deinit is used to finalize Basic Software Scheduler part of the RTE of the core on which it is called. This service releases all system resources allocated by the Basic Software Scheduler part on that core.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: d60d3f8c2060 Herkunft

Verwendung und Zweck

Die Funktion SchM_Deinit dient der Finalisierung des Basic-Software-Scheduler-Anteils der RTE auf demjenigen Prozessorkern, auf dem sie ausgeführt wird ([SWS_Rte_04551]). Dabei gibt dieser Dienst alle Systemressourcen frei, die durch den BSW-Scheduler auf diesem Kern alloziiert wurden ([SWS_Rte_04551]). Das API SchM_Deinit wird stets generiert ([SWS_Rte_07275]), nimmt keine Parameter entgegen und besitzt keinen Rückgabewert (void SchM_Deinit(void); [SWS_Rte_07274]). Die Funktion muss innerhalb einer endlichen Ausführungszeit zurückkehren ([SWS_Rte_07277]).

Aufrufkontext und Reihenfolgebedingungen

Für den Aufruf gelten strikte funktionale Vor- und Nachbedingungen:

  • Vorbedingung RTE-Abschluss: SchM_Deinit darf erst aufgerufen werden, nachdem die RTE finalisiert wurde, konkret nach Beendigung von Rte_Stop ([SWS_Rte_CONSTR_09056]).
  • Aufrufer und BSW-Shutdown: Der Aufruf muss durch den EcuStateManager erfolgen, bevor diejenigen Basissoftware-Module heruntergefahren werden, die der BSW-Scheduler für seinen Betrieb benötigt ([SWS_Rte_CONSTR_09057]).
  • Auswirkung auf Ablaufentitäten: Nachdem SchM_Deinit auf einem Kern aufgerufen wurde, darf der BSW-Scheduler auf diesem Kern keine BswSchedulableEntitys mehr aktivieren oder starten ([SWS_Rte_07586]).

Zusammenspiel mit RTE Implementation Plug-Ins

Im Rahmen der Deinitialisierung ruft die RTE innerhalb von SchM_Deinit die Deinitialisierungsfunktionen Rte_Rips_SchM_Deinit aller beteiligten RTE Implementation Plug-Ins auf ([SWS_Rte_80054]).

function Rte_Rips_SchM_Deinit [SWS_Rte_89019] 📄 PDF

void Rte_Rips_SchM_Deinit (void);

Rte_Rips_SchM_Deinit deinitializes those RTE Implementation Plug-In parts which are relevant for the SchM related operations.

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 313d01437fb3 Herkunft

Verwendung und Aufrufkontext

Die Funktion Rte_Rips_SchM_Deinit deinitialisiert jene Teile eines RTE Implementation Plug-Ins (RIPS), die für Operationen des Basic Software Schedulers (SchM) relevant sind ([SWS_Rte_89019]). Die Schnittstelle wird über die Header-Datei Rte_Rips_<PlugIn>.h deklariert und besitzt die Service-ID 0xF3.

Der Aufruf erfolgt synchron; die Funktion erwartet keine Übergabeparameter (void) und besitzt keinen Rückgabewert (void).

Nebenläufigkeit und Einschränkungen

Die Funktion ist als nicht reentrant (Non Reentrant) spezifiziert ([SWS_Rte_89019]). Ein paralleler oder nebenläufiger Aufruf für dieselbe Plug-In-Instanz ist daher unzulässig.

Zusammenspiel und Lebenszyklus

Rte_Rips_SchM_Deinit ist fest in den Lifecycle der RTE und deren Plug-Ins eingebunden:

  • Jedes RTE Implementation Plug-In muss die standardisierten Lifecycle-Funktionen Rte_Rips_SchM_Init, Rte_Rips_Rte_Start, Rte_Rips_Rte_Stop und Rte_Rips_SchM_Deinit verbindlich bereitstellen ([SWS_Rte_70047]).
  • Die Deinitialisierung wird nicht direkt von Software-Komponenten aufgerufen, sondern durch die RTE gesteuert: Die RTE ruft innerhalb von SchM_Deinit die Deinitialisierungsfunktion Rte_Rips_SchM_Deinit aller beteiligten RTE Implementation Plug-Ins auf ([SWS_Rte_80054]).

type Rte_Rips_SwitchNotificationStatusType [SWS_Rte_91113] 📄 PDF

Status of the en- and dequeue operation on a mode queue Tags: atp.Status=draft

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: d1a2f47238b5 Herkunft

Der Datentyp Rte_Rips_SwitchNotificationStatusType ([SWS_Rte_91113]) ist von uint8 abgeleitet, über die Header-Datei Rte_Type.h verfügbar und kennzeichnet den Status von Einreihungs- (Enqueue) sowie Entnahmeoperationen (Dequeue) bezüglich einer Modus-Warteschlange (Mode Queue).

Verwendung und Zusammenspiel

Der Typ findet im Rahmen des RTE Implementation Plug-In (RIPS) Verwendung:

  • Enqueue-Benachrichtigung: Beim Einreihen in eine Modus-Warteschlange wird der Status über den Eingabeparameter switchNotificationStatus an den synchronen Dienst Rte_Rips_<PlugIn>_Switch_<BswSwcI>_<MMI> übergeben ([SWS_Rte_91114]). Relevante Werte sind hierbei RTE_SWITCH_NOTIFICATION_ENQUEUED_FIRST (0x01) für das Einreihen in eine zuvor leere Warteschlange sowie RTE_SWITCH_NOTIFICATION_ENQUEUED_NOT_FIRST (0x02) für eine bereits belegte Warteschlange ([SWS_Rte_91113]).
  • Dequeue-Operation: Bei der Entnahme dient der Typ als Rückgabewert des Dienstes Rte_Rips_<PlugIn>_DequeueModeSwitch_<MMI>_<OsTask> ([SWS_Rte_91115]), welcher aufgerufen wird, sobald die letzte On-Entry ExecutableEntity terminiert ist. Er meldet über RTE_SWITCH_NOTIFICATION_DEQUEUED_LAST (0x04), dass die letzte Benachrichtigung entnommen wurde, bzw. über RTE_SWITCH_NOTIFICATION_DEQUEUED_NOT_LAST (0x05), dass weitere Benachrichtigungen in der Warteschlange verbleiben ([SWS_Rte_91113]).

Fehlerbehandlung und Sonderzustände

Der Wertebereich nach [SWS_Rte_91113] definiert spezifische Fehler- und Ausnahmeindikatoren:

  • RTE_SWITCH_NOTIFICATION_ENQUEUE_FAILED (0x03): Das Einreihen in eine nicht-leere Warteschlange ist fehlgeschlagen.
  • RTE_SWITCH_NOTIFICATION_SKIP (0x00): Die Moduswechsel-Benachrichtigung kann nicht entnommen werden.

Nebenläufigkeit

Die damit interagierenden Schnittstellen [SWS_Rte_91114] und [SWS_Rte_91115] sind synchron auszuführen und jeweils als reentrant spezifiziert.

Dieser Hinweis wurde von einer KI basierend auf AUTOSAR Release R20-11 generiert.

type Rte_DsmqStatusType [SWS_Rte_91102] 📄 PDF

Status of the enqueue operation on a distributed shared mode queue

KI-GENERIERT ungeprüft Modell: gemini-3.8-flash-medium · Effort: medium · Temperatur: nicht steuerbar · Prompt: 14be0be00598 Herkunft

Verwendung

Der Typ Rte_DsmqStatusType ([SWS_Rte_91102]) ist von uint8 abgeleitet und bildet den Status von Operationen auf einer verteilten, geteilten Modus-Warteschlange (Distributed Shared Mode Queue, DSMQ) ab. Gemäß [SWS_Rte_80085] wird der Typ zusammen mit seinen zugehörigen Literalen im Header Rte_Type.h definiert.

Der Wertebereich umfasst fünf definierte Zustände ([SWS_Rte_91102]):

  • RTE_DSMQ_ENQUEUED_FIRST (0x01): Die Moduswechsel-Benachrichtigung wurde in eine zuvor leere DSMQ eingereiht.
  • RTE_DSMQ_ENQUEUED_NOT_FIRST (0x02): Die Benachrichtigung wurde in eine nicht-leere DSMQ eingereiht.
  • RTE_DSMQ_ENQUEUE_FAILED (0x03): Das Einreihen in eine nicht-leere DSMQ ist fehlgeschlagen.
  • RTE_DSMQ_DEQUEUED_LAST (0x04): Die letzte Moduswechsel-Benachrichtigung wurde aus der DSMQ entnommen.
  • RTE_DSMQ_DEQUEUED_NOT_LAST (0x05): Eine Moduswechsel-Benachrichtigung wurde aus der DSMQ entnommen, wobei weitere Benachrichtigungen in der Warteschlange verbleiben.

Fehlerbehandlung

Schlägt das Einreihen einer Moduswechsel-Benachrichtigung in eine nicht-leere DSMQ fehl, wird dies über den Statuswert RTE_DSMQ_ENQUEUE_FAILED (0x03) ausgewiesen ([SWS_Rte_91102]). Spezifische DET- oder DEM-Meldungen sind für diesen Datentyp nicht definiert.

Zusammenspiel und Nebenläufigkeit

Werte dieses Typs werden als Eingabeparameter dsmqstatus an Schnittstellen des RTE-Implementation-Plug-Ins (RIPS) übergeben:

  • Rte_Rips_<PlugIn>_DsmqSwitch_<BswSwcI>_<MMI> ([SWS_Rte_91103]) benachrichtigt das Plug-In synchron über das Einreihen in eine DSMQ.
  • Rte_Rips_<PlugIn>_DsmqTransitionEnd_<BswSwcI>_<MMI> ([SWS_Rte_91106]) signalisiert dem Plug-In synchron das Ende eines spezifischen Modusübergangs in einem DSMQ-Transition-OsTask.

Beide aufrufenden RIPS-Dienste sind als synchron und reentrant spezifiziert ([SWS_Rte_91103], [SWS_Rte_91106]).
