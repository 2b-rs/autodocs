2. Komponenten, Entitäten & Schnittstellen

  • Funktionsschnittstelle:

```c

Std_ReturnType E2E_PXXCheck(

const E2E_PXXConfigType* Config,

E2E_PXXCheckStateType* State,

const uint8* Data,

LengthType Length

);

```

  • Dargestellte Entitäten & Datenstrukturen:
  • Config (const E2E_PXXConfigType*): Unveränderliche Konfigurationsstruktur (Offsets von CRC/Counter, Datenlängen, Data-ID-Konfiguration/-Array, Schwellwerte).
  • State (E2E_PXXCheckStateType*): Zustandsstruktur des Empfängers. Hält historische Prüfwerte (letzter Counter, Window-Historie), den aktuellen Prüfstatus (State->Status) sowie das Flag State->NewDataAvailable.
  • Data (const uint8*): Zeiger auf den PDU-Nutzdatenpuffer inklusive serialisiertem E2E-Header.
  • Length (LengthType): Reale PDU- bzw. Nutzdatenlänge in Bytes.
  • NewDataAvailable (Guard/Zustandsattribut in State): Boolesches Flag zur Signalisierung, ob seit dem letzten Check-Aufruf ein neues Datenpaket empfangen wurde.
  • Rückgabewerte (API-Ebene):
  • E2E_E_OK (0x00): Funktionsdurchlauf fehlerfrei abgeschlossen (funktionales Prüfergebnis liegt in State->Status).
  • E2E_E_INPUTERR_NULL (0x13): Mindestens ein obligatorischer Zeiger (Config, State bzw. Data bei NewDataAvailable == TRUE) ist NULL_PTR.
  • E2E_E_INPUTERR_WRONG (0x17): Wertebereichsverletzung oder ungültige Konfigurations-/Längenparameter (z. B. Length außerhalb der Min-/Max-Grenzen).

3. Dynamisches Verhalten & Sequenzablauf

Synchroner, deterministischer Kontrollfluss ohne blockierende Aufrufe:

  1. Initialer Aufruf: Übergabe von (Config, State, Data, Length).
  2. Eingangsvalidierung (Verify inputs of the check function):
  • Verzweigung nach formaler Zeiger- und Wertebereichsprüfung:
  • [null input] $\rightarrow$ Direkter Abbruch, Übergang zum Activity Final Node mit Rückgabe E2E_E_INPUTERR_NULL.
  • [wrong input] $\rightarrow$ Direkter Abbruch, Übergang zum Activity Final Node mit Rückgabe E2E_E_INPUTERR_WRONG.
  • [input ok] $\rightarrow$ Fortsetzung zu Decision Node NewDataAvailable == TRUE.
  1. Prüfung auf Datenverfügbarkeit (NewDataAvailable == TRUE):
  • Pfad [FALSE] (Keine neuen Daten empfangen):
  • Überspringt die Extraktion des E2E-Headers und die CRC-Berechnung vollständig.
  • Direktsprung zu Do checks (Auswertung von Timeout/Zyklusüberwachung, Fortschreibung der Status-Historie, z. B. Setzen von E2E_P_NODATA).
  • Pfad [TRUE] (Neues Datenpaket liegt vor):
  1. Compute offset: Berechnung der absoluten Bit-/Byte-Positionen des E2E-Headers (statisch oder dynamisch bei variabler PDU-Länge).
  2. Read Length: Auslesen der übertragenen Längeninformation (sofern im Profil vorgesehen).
  3. Read Counter: Extraktion des Sequenzzählers aus dem PDU-Header.
  4. Read DataID: Auslesen/Auflösen der Data-ID (bei Profilen mit dynamischer oder im Header geführter Data-ID).
  5. Read CRC: Extraktion der vom Sender übertragenen Prüfsumme.
  6. Compute CRC: Berechnung der Referenz-CRC über den Nutzdatenbereich und die Data-ID gemäß Profilspezifikation.
  7. Do checks: Plausibilitätsprüfung (CRC-Vergleich, Validierung des Sequenzzählers gegen Vorwerte zur Erkennung von Delta-Sprung, Wiederholung oder Datenverlust). Setzen von State->Status (z. B. E2E_P_OK, E2E_P_CRCERROR, E2E_P_REPEATED, E2E_P_WRONGSEQUENCE).
  8. Terminierung: Übergang zum Activity Final Node mit Rückgabewert E2E_E_OK.

4. Normative Relevanz & Entwickler-Hinweise

  • Zweistufige Fehlersemantik (Safety-Kritisch):
  • Der Rückgabewert der C-Funktion (Std_ReturnType) meldet ausschließlich die Korrektheit des Funktionsaufrufs (API-Fehlerfreiheit).
  • Ein Rückgabewert E2E_E_OK bedeutet nicht, dass die Nutzdaten integer sind. Das funktionale ASIL-Sicherheitsergebnis muss zwingend aus State->Status (bzw. dem nachgelagerten E2E State Machine Handler E2E_PXXCheckStatus()) ausgewertet werden.
  • WCET & Verzweigungsoptimierung:
  • Der Pfad [FALSE] dient zyklischen Polling-Aufrufen (z. B. in zyklischen Tasks oder COM-Callouts) zur Dead-Deadline-/Timeout-Erkennung ohne unnötige CPU-Last durch CRC-Polynomberechnungen.
  • Reentranz & Speicherverwaltung:
  • E2E_PXXCheck() ist zustandslos bezüglich statischer Modulvariablen und reentrant für disjunkte Instanzen von State.
  • Es findet keine dynamische Speicherallokation statt.
  • Stack-Integration (COM / Transformer):
  • Bei variablen Nutzdatenlängen (dynamische PDUs) muss Length vom Aufrufer (z. B. E2E_Transformer in der RTE oder PDU-Router/COM) exakt der empfangenen Bytezahl entsprechen, da sonst Compute offset und Compute CRC fehlschlagen oder E2E_E_INPUTERR_WRONG ausgelöst wird.
