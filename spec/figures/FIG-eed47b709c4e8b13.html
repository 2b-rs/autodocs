  • Architektur-Kontext: AUTOSAR Classic Platform (Releases R24-11 und R25-11), BSW-Treiber EthSwt (Ethernet Switch Driver, Teil des Ethernet-Hardware-Abstraction-Layers / MCAL).
  • Funktionaler Zweck: Formale Definition des Konfigurations-Containers EthSwtPortIngress zur Parametrierung der Ingress-Pipeline (Empfangspfad) eines Switch-Ports. 2. Komponenten, Entitäten & Schnittstellen

#### Übergeordnete Container & Referenzierende Entitäten

  • EthSwtPort (EcucParamConfContainerDef, Multiplizität: 1..*): Übergeordneter Container für die portspezifische Switch-Konfiguration.
  • EthSwtStreamIdentificationEntry (EcucParamConfContainerDef, Multiplizität: 0..*): Externer Konfigurationscontainer für Stream Identification (IEEE 802.1CB / TSN).
  • Beinhaltet die Referenz EthSwtStreamIdentificationIngressPortRef (EcucReferenceDef, Multiplizität: 0..*), welche via Zielrolle +destination auf die Instanz von EthSwtPortIngress verweist.

#### Zentraler Ingress-Container

  • EthSwtPortIngress (EcucParamConfContainerDef, Multiplizität: 1..1 je Port via Komposition +subContainer von EthSwtPort): Zentraler Ingress-Knoten.

#### Parameter von EthSwtPortIngress

  • EthSwtPortIngressDropUntagged (EcucBooleanParamDef):
  • Multiplizität: 1..1, Default: false.
  • Verwirft alle ankommenden Frames ohne 802.1Q-VLAN-Tag, wenn auf true gesetzt.
  • EthSwtPortIngressDefaultVlan (EcucIntegerParamDef):
  • Multiplizität: 0..1, Wertebereich: [0 .. 4094], Default: 1.
  • Weist ungetaggten Ingress-Frames die Standard-Port-VLAN-ID (PVID) zu.
  • EthSwtPortIngressDefaultPriority (EcucIntegerParamDef):
  • Multiplizität: 0..1, Wertebereich: [0 .. 7], Default: 0.
  • Weist ungetaggten Ingress-Frames die Standard-PCP (Priority Code Point) zu.

#### SubContainer von EthSwtPortIngress

  • EthSwtPortIngressScheduler (EcucParamConfContainerDef):
  • Multiplizität: 0..* Instanzen.
  • Konfiguriert Ingress-Scheduling-Algorithmen (z. B. Bandbreitenbegrenzung, Ingress Rate Limiting, Metering).
  • EthSwtPortPriorityRegeneration (EcucParamConfContainerDef):
  • Multiplizität: exakt 8..8 Instanzen (Zuordnungstabelle für jede der Prioritäten 0 bis 7 gemäß IEEE 802.1Q).
  • Parameter:
  • EthSwtPortPriorityRegenerationIngressPCP (EcucIntegerParamDef): Wertebereich [0 .. 7]. Eingehende Priorität (PCP).
  • EthSwtPortPriorityRegenerationRegeneratedPriority (EcucIntegerParamDef): Wertebereich [0 .. 7]. Neu zugewiesene (regenerierte) Priorität.
  • EthSwtPortIngressVlanTranslationTable (EcucParamConfContainerDef):
  • Multiplizität: 1..1 Instanz (obligatorischer Container für VLAN-Übersetzung).
  • Enthält via Komposition +subContainer:
  • EthSwtPortIngressVlanTranslationTableEntry (EcucParamConfContainerDef, Multiplizität: 0..*): Einzelne Übersetzungsregel für VLAN-IDs.
  • Parameter:
  • EthSwtIngressVlanId (EcucIntegerParamDef): Multiplizität 0..1, Wertebereich [0 .. 4095]. Eingehende VLAN-ID.
  • EthSwtTranslatedVlanId (EcucIntegerParamDef): Multiplizität 0..1, Wertebereich [0 .. 4095]. Übersetzte Ziel-VLAN-ID.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches Daten-/Metamodell handelt, manifestiert sich das dynamische Verhalten in der Frame-Processing-Pipeline der Switch-Hardware zur Laufzeit:

```

[Ingress Frame am EthSwtPort]

│

├──> [Ist Frame ungetagged?]

│ │

│ ├── (Ja) ──> [EthSwtPortIngressDropUntagged == true?]

│ │ ├── (Ja) ──> DROP Frame

│ │ └── (Nein) ─> Setze VID = EthSwtPortIngressDefaultVlan

│ │ Setze PCP = EthSwtPortIngressDefaultPriority

│ │

│ └── (Nein) ─> [VLAN Translation Match?] (EthSwtPortIngressVlanTranslationTable)

│ ├── (Ja: EthSwtIngressVlanId) ──> VID = EthSwtTranslatedVlanId

│ └── (Nein) ─────────────────────> Frame behält empfangene VID

│

├──> [Priority Regeneration] (EthSwtPortPriorityRegeneration, 8 Einträge)

│ └── Lookup nach EthSwtPortPriorityRegenerationIngressPCP

│ └── PCP = EthSwtPortPriorityRegenerationRegeneratedPriority

│

├──> [Stream Identification Matching] (EthSwtStreamIdentificationEntry via IngressPortRef)

│ └── TSN / 802.1CB Stream-Filterung & Metering

│

└──> [Ingress Scheduling & Weiterleitung] (EthSwtPortIngressScheduler)

└── Bandwidth Enforcement / Weitergabe an Switching Core / Egress Queues

```

4. Normative Relevanz & Entwickler-Hinweise

  • Treiber-Initialisierung (EthSwt_Init): Die Parameter aus EthSwtPortIngress werden bei der BSW-Generierung in Hardware-Registerkonfigurationen übersetzt. Der Treiber programmiert Port-VLAN-ID (PVID), Tag-Filterregeln (Discard Untagged), Prioritätsregenerations-Tabellen sowie VLAN-Translation-Tabellen des Switch-ASIC deterministisch zur Boot-Zeit.
  • Vollständigkeit der Tabellen:
  • EthSwtPortPriorityRegeneration fordert strikt 8..8 Multiplizität; jede der 8 PCP-Stufen (0 bis 7) muss über EthSwtPortPriorityRegenerationIngressPCP und EthSwtPortPriorityRegenerationRegeneratedPriority eindeutig abgebildet sein.
  • EthSwtPortIngressVlanTranslationTable ist mit Multiplizität 1..1 obligatorisch vorhanden. Sie enthält 0 bis beliebig viele EthSwtPortIngressVlanTranslationTableEntry-Instanzen, um selektives VLAN-Remapping (Ingress-VLAN auf Translated-VLAN) auszuführen.
  • VLAN-Interoperabilität: Wenn EthSwtPortIngressDropUntagged = false konfiguriert ist, muss EthSwtPortIngressDefaultVlan (Default: 1) im globalen VLAN-Filter des Switches registriert sein, da ungetaggte Frames andernfalls nach Zuweisung der Default-PVID mangels Port-Mitgliedschaft im Switch-Core verworfen werden.
  • TSN / AVB Relevanz: Die Referenz EthSwtStreamIdentificationIngressPortRef bindet Ingress-Ports an Stream-Identifikationsmechanismen gemäß IEEE 802.1CB. Bleibt diese ungenutzt, erfolgt die Ingress-Verarbeitung rein über die VLAN- und Prioritäts-Regeln.
