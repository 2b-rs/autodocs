1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Sequenzdiagramm (Interaktionsdiagramm mit opt-Kombinationsfragmenten).
  • Funktionaler Kontext: AUTOSAR Classic Platform (SWS TimeSyncOverEthernet, R21-11), Subsystem Ethernet Time Synchronization (EthTSyn).
  • Technischer Zweck: Spezifikation des asynchronen Verarbeitungsablaufs beim Empfang von Time-Synchronization-Frames (Sync und nachfolgendem Follow_Up) an einem Ethernet-Switch-Port in Szenarien ohne integrierten Global Time Master am Switch (SwitchWithoutGTM). Es visualisiert das Zusammenspiel zwischen ISR/Rx-Kontext (EthIf_RxIndication), Hardware-Switch-Objektverwaltung (EthIfSwitchManagementSupport) und Entkopplung in den Task-Kontext (EthTSyn_MainFunction) bis zur Weitergabe der berechneten Zeitbasis an den Synchronized Time-Base Manager (StbM).

2. Komponenten, Entitäten & Schnittstellen

#### Akteure / BSW-Module (Lifelines)

  • «module» EthIf (Ethernet Interface): Vermittelt zwischen Switch-Treiber (EthSwt) und oberen Schichten; liefert Rx-Indikationen und verwaltet Switch-Management-Objekt-Puffer.
  • «module» EthTSyn (Time Synchronization over Ethernet): Implementiert das gPTP-Protokoll (IEEE 802.1AS / AUTOSAR-Profil), evaluiert Frame-Inhalte, korreliert Port-Timestamps und führt die Residuen-/Kompensationsberechnungen durch.
  • «module» StbM (Synchronized Time-Base Manager): Zentrale Instanz zur Verwaltung synchronisierter Zeitbasen im Steuergerät; empfängt bereinigte globale Zeitwerte und Messdaten.

#### Schnittstellen & Datentypen

  • EthTSyn_RxIndication(...):
  • Parameter: CtrlIdx: uint8, FrameType: Eth_FrameType, IsBroadcast: boolean, PhysAddrPtr: const uint8, DataPtr: const uint8, LenByte: uint16.
  • Kontext: Synchroner Aufruf aus dem Rx-Pfad des EthIf (Interrupt- oder Task-Kontext).
  • EthIf_GetRxMgmtObject(...):
  • Parameter: CtrlIdx: uint8, DataPtr: Eth_DataType, MgmtObjectPtr: EthSwt_MgmtObjectType, Rückgabewert: Std_ReturnType.
  • Liefert Zeiger auf die switch-spezifische Management-Struktur (EthSwt_MgmtObjectType), welche Hardware-Timestamps und Port-Zuordnungen kapselt.
  • EthTSyn_MainFunction():
  • Zyklische BSW-Hauptfunktion (Task-Ebene) zur Entkopplung rechenintensiver Timestamp-Verarbeitung und Validierung.
  • StbM_BusSetGlobalTime(...):
  • Parameter: timeBaseId: StbM_SynchronizedTimeBaseType, globalTimePtr: const StbM_TimeStampType, userDataPtr: const StbM_UserDataType, measureDataPtr: const StbM_MeasurementType, localTimePtr: const StbM_VirtualLocalTimeType, Rückgabewert: Std_ReturnType.
  • Übergabe der aktualisierten Master-Zeit und lokaler Zeitstempel an StbM.
  • Objekt-Attribute & States:
  • EthSwt_MgmtObjectType: Enthält MgmtInfo (SwitchIdx, SwitchPortIdx) sowie Ownership (ETHSWT_MGMT_OBJ_OWNED_BY_<UPPER_LAYER>, ETHSWT_MGMT_OBJ_UNUSED).
  • Timestamps: Port-Ingress-Timestamp $T_4$, Port-Egress-Timestamp $T_5$ (für Verweildauer- bzw. Laufzeitkorrekturen im Switch).

3. Dynamisches Verhalten & Sequenzablauf

```

[EthIf] [EthTSyn] [StbM]

| | |

|--- EthTSyn_RxIndication() ------>| |

| |-- Prüfe: [Type == Sync] |

| | |

| [opt: EthIfSwitchManagementSupport == ON] |

|<-- EthIf_GetRxMgmtObject() ------| |

|--- (return E_OK, MgmtObject) --->| |

|<---------------------------------| |

| | |

| |-- (Asynchron: Task-Trigger) |

| |-- EthTSyn_MainFunction() |

| | |

| [opt: EthIfSwitchManagementSupport == ON] |

| |-- Validiere Switch/Port/Owner |

| |-- Hole Timestamps T4 / T5 |

| |-- Setze Ownership = UNUSED |

| | |

| |-- StbM_BusSetGlobalTime() ---->|

| |<-- (return Std_ReturnType) ----|

```

  1. Empfang & Allokation (Rx-Pfad):
  • EthIf signalisiert den Empfang eines PTP-Frames via EthTSyn_RxIndication.
  • Bei Type == Sync und aktivem Pre-Compile-Schalter EthIfSwitchManagementSupport == ON:
  • EthTSyn ruft synchron EthIf_GetRxMgmtObject auf, um das zugehörige Management-Objekt des Switch-Ports zu reservieren.
  • Bei Rückgabe E_OK wird der Zeiger in usedRxMgmtObjectPtr gesichert; das Objekt befindet sich im Zustand ETHSWT_MGMT_OBJ_OWNED_BY_<UPPER_LAYER>.
  1. Entkoppelte Verarbeitung (Task-Pfad):
  • Die weitere Auswertung erfolgt asynchron im zyklischen Aufruf EthTSyn_MainFunction.
  • Unter EthIfSwitchManagementSupport == ON erfolgt eine Plausibilitätsprüfung:

$$\text{SwitchIdx}_{\text{info}} == \text{SwitchIdx}_{\text{obj}} \;\land\; \text{SwitchPortIdx}_{\text{info}} == \text{SwitchPortIdx}_{\text{obj}} \;\land\; \text{Ownership} == \text{OWNED\_BY\_}$$

  • Sind die Bedingungen erfüllt, meldet der interne Status: usedRxMgmtObject timestamps ready to use.
  1. Extraktion der Zeitstempel & Ressourcenfreigabe:
  • Für Type == Sync werden die switch-bezogenen Zeitstempel extrahiert:
  • $T_4$: Port Ingress Timestamp (Eingangszeit am Switch-Port).
  • $T_5$: Port Egress Timestamp (Ausgangszeit am Weiterleitungs-Port).
  • Ressourcenfreigabe: Das Management-Objekt wird unverzüglich durch Setzen von usedRxMgmtObject->Ownership = ETHSWT_MGMT_OBJ_UNUSED wieder für den Switch-Treiber freigegeben.
  1. Zeitbasis-Aktualisierung:
  • Nach Abschluss der Synchronisationsberechnung (unter Berücksichtigung von $T_4$, $T_5$ und der Follow_Up-Nutzdaten) übergibt EthTSyn den berechneten Globalzeitwert via StbM_BusSetGlobalTime synchron an das Modul StbM.

4. Normative Relevanz & Entwickler-Hinweise

  • Puffer- und Ressourcen-Management (EthSwt / EthIf):
  • Entwickler müssen sicherstellen, dass im Switch-Treiber (EthSwt) genügend Management-Objekte konfiguriert sind. Da Objekte zwischen EthTSyn_RxIndication und EthTSyn_MainFunction blockiert bleiben, führt eine zu niedrige MainFunction-Zykluszeit oder ein hoher Frame-Jitter zum Überlauf des Rx-Objekt-Pools (E_NOT_OK bei EthIf_GetRxMgmtObject).
  • Laufzeit- und Thread-Sicherheit:
  • EthIf_GetRxMgmtObject wird im Rx-Indication-Kontext (potenziell ISR/High-Priority-Task) ausgeführt, während die Freigabe (Ownership = UNUSED) in der EthTSyn_MainFunction (Preemptible Task) erfolgt. Der Treiber-/Interface-Stack muss atomare Operationen oder Critical Sections für den Ownership-Zustandswechsel garantieren.
  • Konfigurationsabhängigkeit:
  • Das Switch-Handling ist normativ an den Präprozessor-Parameter EthIfSwitchManagementSupport == ON gebunden. Ist dieser deaktiviert, greift der Standard-Host-Controller-Timestamping-Pfad (ohne Ingress/Egress-Kompensation des Switches).
  • Fehlerbehandlung:
  • Schlägt die Validierung von SwitchIdx, SwitchPortIdx oder Ownership fehl, dürfen $T_4$ und $T_5$ nicht ausgewertet werden. Das betroffene Objekt muss kontrolliert freigegeben und der Frame verworfen werden (i. d. R. Det-Meldung ETHTSYN_E_SYS_TIME_ERROR bzw. ETHTSYN_E_PARAM_POINTER).
