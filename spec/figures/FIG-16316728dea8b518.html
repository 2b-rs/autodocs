1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration (ECUC) Metamodell / Parameterspezifikation als UML-Klassendiagramm (Strukturmodell der BSW-Konfigurationsparameter).
  • Modul: FlexRay Interface (FrIf), Communication Drivers Abstraction Layer (BSW).
  • Technischer Zweck & Einordnung: Definiert die Konfigurationsstruktur für Controller-spezifische Datenreferenzen. Das Modell bildet die statische und dynamische Zuordnung zwischen logischen Protokolldateneinheiten (FrIfLPdu), Übertragungszeitpunkten im FlexRay-Schedule (FrIfFrameTriggering), Frame-Strukturen (FrIfFrameStructure) sowie Diagnoserückmeldungen an den Diagnostic Event Manager (Dem) ab.

2. Komponenten, Entitäten & Schnittstellen

Container-Hierarchie und Kardinalitäten
  • FrIfController (EcucParamConfContainerDef, Multiplizität 1..\*):
    • Wurzel-Container für jede konfigurierte FlexRay-Controller-Instanz.
    • Aggregiert über +subContainer:
      • FrIfLPdu (1..\*)
      • FrIfFrameTriggering (1..\*)
  • FrIfLPdu (EcucParamConfContainerDef, Multiplizität 1..\*):
    • Repräsentiert eine logische PDU (L-PDU) auf Interface-Ebene.
    • Parameter & Referenzen:
      • FrIfLPduIdx (EcucIntegerParamDef): Bereich [0, 4095], withAuto = true, symbolicNameValue = true. Dient als API-Handle/Index für obere Schichten (PduR, FrTp, FrNm).
      • FrIfReconfigurable (EcucBooleanParamDef): Steuert, ob das PDU-Routing zur Laufzeit modifizierbar ist.
      • FrIfVBTriggeringRef (EcucReferenceDef, +reference): Verweist über +destination auf die Zielinstanz FrIfFrameTriggering.
  • FrIfFrameTriggering (EcucParamConfContainerDef, Multiplizität 1..\*):
    • Kapselt den Sende-/Empfangszeitpunkt im FlexRay-Kommunikationszyklus.
    • Scheduling-Parameter:
      • FrIfSlotId (EcucIntegerParamDef): FlexRay-Slot [1, 2047] (statisches oder dynamisches Segment).
      • FrIfBaseCycle (EcucIntegerParamDef): Basiszyklus [0, 63].
      • FrIfCycleRepetition (EcucIntegerParamDef): Zykluswiederholung [1, 64] (2^n-Raster).
      • FrIfChannel (EcucEnumerationParamDef): Übertragungskanal; Literale: FRIF_CHANNEL_A, FRIF_CHANNEL_B, FRIF_CHANNEL_AB.
    • Payload- & Frame-Parameter:
      • FrIfLSduLength (EcucIntegerParamDef): Nutzdatenlänge der L-SDU in Bytes [0, 254].
      • FrIfAllowDynamicLSduLength (EcucBooleanParamDef): Aktiviert variable Längenübertragung (dynamisches Segment).
      • FrIfAlwaysTransmit (EcucBooleanParamDef): Erzwingt zyklische Frame-Übertragung (z. B. Null-Frames), auch ohne Update aus oberen Schichten.
      • FrIfPayloadPreamble (EcucBooleanParamDef): Setzt das Payload-Preamble-Bit im FlexRay-Header (NM-Vektor im statischen Segment bzw. Message-ID im dynamischen Segment).
      • FrIfMessageId (EcucIntegerParamDef, Multiplizität 0..1): Bereich [0, 65535]. Filter-/Routing-ID im dynamischen Segment bei gesetztem Payload-Preamble.
    • Referenzen & Sub-Container:
      • FrIfFrameStructureRef (EcucReferenceDef): Verweist (+destination) auf FrIfFrameStructure (1..\*), welche das PDU-Layout innerhalb des FlexRay-Frames definiert.
      • FrIfFrameTriggeringDemEventParameterRefs (EcucParamConfContainerDef, Multiplizität 0..1, +subContainer):
        • FRIF_E_LPDU_SLOTSTATUS (EcucReferenceDef, Multiplizität 0..1, requiresSymbolicNameValue = true): Referenziert (+destination) einen DemEventParameter (1..65535) zur Signalisierung von Slot-Status-Verletzungen.

3. Dynamisches Verhalten & Sequenzablauf

  • Zyklus- und Slot-Auflösung (Kommunikationsraster):
    • Ein Frame-Trigger wird aktiv, wenn im aktuellen FlexRay-Zyklus (CycleCounter) gilt: $$\text{CycleCounter} \pmod{\text{FrIfCycleRepetition}} == \text{FrIfBaseCycle}$$
    • Die Zuweisung zum Sende-/Empfangs-Puffer des Fr-Treibers erfolgt unter Auswertung von FrIfSlotId und FrIfChannel.
  • Sendeinitiierung & PDU-Bereitstellung:
    • Synchroner Pfad: Ist FrIfAlwaysTransmit == TRUE, fordert der FrIf auch ohne anstehendes FrIf_Transmit() Daten über PduR_FrIfTriggerTransmit() an oder veranlasst das Absenden des gecachten Inhalts/Null-Frames.
    • Bei variabler Frame-Länge (FrIfAllowDynamicLSduLength == TRUE) validiert der FrIf zur Laufzeit, dass die übergebene L-SDU-Länge ≤ FrIfLSduLength ist.
  • Diagnosepfad (Dem-Triggering):
    • Asynchron: Detektiert der FlexRay-Controller während des Slots Übertragungs- oder Synchronisationsfehler (z. B. Slot Status Syntax Error, Content Error), meldet der FrIf den Fehlerzustand über Dem_SetEventStatus(FRIF_E_LPDU_SLOTSTATUS, DEM_EVENT_STATUS_FAILED).

4. Normative Relevanz & Entwickler-Hinweise

  • Generierte Lookup-Tabellen (ROM vs. RAM):
    • FrIfLPduIdx dient dem Codegenerator zur Erzeugung kompakter O(1)-Indizierungs-Tabellen.
    • Ist FrIfReconfigurable == FALSE, können Routing-Deskriptoren und Trigger-Referenzen (FrIfVBTriggeringRef) vollständig in den ROM/Flash gelegt werden. Steht der Parameter auf TRUE, müssen die Verknüpfungen zur Laufzeit im RAM rekonfigurierbar vorgehalten werden.
  • Cluster-Konsistenz & Hardware-Constraints:
    • FrIfSlotId und FrIfLSduLength müssen strikt mit den FIBEX/ARXML-Cluster-Parametern übereinstimmen. Im statischen FlexRay-Segment muss die SDU-Länge für alle Frames eines Clusters identisch und stets ein gerader Byte-Wert (FlexRay 16-Bit Payload Words) sein.
    • FrIfCycleRepetition muss zwingend eine Zweierpotenz sein (1, 2, 4, …, 64), um eine bitweise Maskierung (Cycle & (Repetition - 1)) == BaseCycle im BSW-Treiber zu ermöglichen.
  • Payload-Preamble-Semantik:
    • Ist FrIfPayloadPreamble == TRUE, muss sichergestellt werden:
      • Im statischen Segment: Die ersten Bytes enthalten den Network Management (NM) Vektor.
      • Im dynamischen Segment: Die ersten 2 Bytes repräsentieren die FrIfMessageId (sofern konfiguriert).
