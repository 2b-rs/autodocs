1. Diagrammtyp & Architektur-Kontext

UML-Aktivitätsdiagramm zur Spezifikation des Kontrollflusses innerhalb der AUTOSAR E2E-Bibliothek (Profile 7). Es modelliert die interne Logik des Prüfschritts „Do Checks“ innerhalb der Funktion E2E_P07Check(), welche empfängerseitig zur Absicherung sicherheitskritischer Kommunikation gegen Datenverfälschung, Wiederholung, Verlust und Falschanordnung eingesetzt wird.

2. Komponenten, Entitäten & Schnittstellen

  • Konfigurationsstruktur Config (E2E_P07ConfigType): Parameter DataID, MaxDeltaCounter.
  • Zustandsstruktur State (E2E_P07CheckStateType): Zustandselemente Status und Counter.
  • Eingangsdaten / Lokale Variablen: NewDataAvailable, ReceivedCRC, ComputedCRC, ReceivedDataID, ReceivedLength, Length, ReceivedCounter, DeltaCounter.
  • Rückgabe- / Status-Zustände (E2E_P07CheckStatusType):
    • E2E_P07STATUS_NONEWDATA
    • E2E_P07STATUS_ERROR
    • E2E_P07STATUS_WRONGSEQUENCE
    • E2E_P07STATUS_REPEATED
    • E2E_P07STATUS_OKSOMELOST
    • E2E_P07STATUS_OK
  • Aktionen & Kontrollknoten: Initialer Startknoten, Entscheidungsknoten (Decisions), Berechnungsaktionen (Compute local variable DeltaCounter..., Zuweisung State->Counter = ReceivedCounter), Zusammenführungsknoten (Merges) und Aktivitätsendknoten.

3. Dynamisches Verhalten & Sequenzablauf

  1. Prüfung auf neue Daten: Ist NewDataAvailable == TRUE falsch ([FALSE]), wird State->Status = E2E_P07STATUS_NONEWDATA gesetzt und direkt zum Endknoten verzweigt (ohne State->Counter zu aktualisieren).
  2. Integritäts- und Metadatenprüfungen:
    • Prüfung ReceivedCRC == ComputedCRC.
    • Prüfung ReceivedDataID == Config->DataID.
    • Prüfung ReceivedLength == Length.
    • Schlägt eine dieser Prüfungen fehl ([FALSE]), wird State->Status = E2E_P07STATUS_ERROR gesetzt und zum Endknoten verzweigt (keine Zähleraktualisierung).
  3. Zähler- und Sequenzprüfung:
    • Bei erfolgreichen Vorprüfungen wird DeltaCounter berechnet als ReceivedCounter - State->Counter unter Berücksichtigung des 32-Bit-Überlaufs (0xFFFFFFFF).
    • Liegt DeltaCounter nicht im Bereich (DeltaCounter <= Config->MaxDeltaCounter) && (DeltaCounter >= 0), resultiert dies in State->Status = E2E_P07STATUS_WRONGSEQUENCE.
    • Gilt die Bedingung, wird geprüft:
      • Falls DeltaCounter > 0 falsch ist (also DeltaCounter == 0), wird State->Status = E2E_P07STATUS_REPEATED gesetzt.
      • Falls DeltaCounter > 0 wahr ist, wird geprüft, ob DeltaCounter == 1 gilt:
        • Wenn TRUE: State->Status = E2E_P07STATUS_OK.
        • Wenn FALSE: State->Status = E2E_P07STATUS_OKSOMELOST.
  4. Zähleraktualisierung: Nach Durchlaufen der Pfade WRONGSEQUENCE, REPEATED, OKSOMELOST oder OK wird State->Counter = ReceivedCounter aktualisiert, bevor der Aktivitätsendknoten erreicht wird.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm definiert das normative Ausführungsverhalten der Funktion E2E_P07Check() gemäß Anforderung [PRS_E2E_00501]. Entwickler müssen sicherstellen:

  • Die Prüfungen auf CRC, DataID und Datenlänge müssen vor der Zählerauswertung stattfinden; bei Nichterfüllung darf der Zählerstand nicht überschrieben werden.
  • Bei Ausbleiben neuer Daten (NONEWDATA) bleibt der Zustandskontext unberührt.
  • Die Berechnung des DeltaCounter muss den 32-Bit-Wrap-Around (0xFFFFFFFF) arithmetisch exakt behandeln.
  • In allen vier Fällen gültiger Sequenzanalyse (WRONGSEQUENCE, REPEATED, OKSOMELOST, OK) muss der lokale State->Counter zwingend auf ReceivedCounter synchronisiert werden.
