1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Interaktion des AUTOSAR Diagnostic Log and Trace (DLT) Basissoftware-Moduls über das DLT-Kommunikationsmodul (DltCom). Es beschreibt den Kontroll- und Datenfluss innerhalb der BSW-Architektur zwischen DLT-Anwendern, dem Kernmodul Dlt, dem Kommunikationsadapter DltCom und einem externen DLT-Client (OBD/UDS bzw. Debug-Schnittstelle).

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Entitäten (Lebenslinien):

  • Dlt User :Dlt_Cbk: Anwendungssoftware-Komponente / BSW-Nutzer mit Callback-Schnittstelle
  • «module» Dlt :Dlt: AUTOSAR DLT-Hauptmodul
  • «module» DltCom :DltCom: DLT-Kommunikationsmodul zur Entkopplung des Transports
  • External client (connectet over OBD/UDS): Externes DLT-Werkzeug / Diagnose-Client

Schnittstellen und Nachrichten:

  • Dlt_RegisterContext(Dlt_ReturnType, Dlt_SessionIDType, Dlt_ApplicationIDType, Dlt_ContextIDType, const uint8*, uint8, const uint8*, uint8): Registrierungsaufruf vom User an Dlt
  • Dlt_SetLogLevel_<SESSION>(Dlt_ApplicationIDType, Dlt_ContextIDType, Dlt_MessageLogLevelType): Callback zur Einstellung des Log-Levels
  • send a Dlt control message (over debug interface) / send a Dlt control message(): Asynchroner Steuerungsnachrichtenaustausch zwischen externem Client und DltCom
  • Dlt_ComRxIndication(PduIdType, NotifResultType): Empfangsanzeige von DltCom an Dlt
  • Dlt_SendLogMessage(Dlt_ReturnType, Dlt_SessionIDType, const Dlt_MessageLogInfoType*, const uint8*, uint16): Periodischer Log-Sendeaufruf des Users an Dlt
  • DltCom_Transmit(PduIdType, PduInfoType*, Std_ReturnType): PDU-Übertragungsanforderung von Dlt an DltCom
  • send a DLT log or trace message(serialized over debug interface): Übertragung der serialisierten Nachricht an den externen Client
  • Dlt_ComTxConfirmation(PduIdType, NotifResultType): Bestätigung der PDU-Übertragung von DltCom an Dlt

3. Dynamisches Verhalten & Sequenzablauf

Der Ablauf gliedert sich in drei Phasen:

  1. Registrierung: Dlt User registriert Applikation und Kontext mittels Dlt_RegisterContext am Modul Dlt. Daraufhin meldet Dlt initial den Log-Level über den Callback Dlt_SetLogLevel_<SESSION> zurück.
  2. Steuerung: Ein externer Client sendet über die Debug-Schnittstelle eine DLT-Control-Message (0x01: Set Log Level in SWC) an DltCom. DltCom leitet die Daten per Dlt_ComRxIndication an Dlt weiter. Dlt aktualisiert die SWC synchron/asynchron über Dlt_SetLogLevel_<SESSION> und sendet die positive Bestätigung (0x01 Response OK) über DltCom zurück an den Client.
  3. Periodische Protokollierung (in einer loop-Schleife): Dlt User ruft Dlt_SendLogMessage auf. Das Modul Dlt stößt die Übertragung mittels DltCom_Transmit an DltCom an. DltCom überträgt die serialisierte Nachricht an den externen Client und bestätigt den Versand asynchron via Dlt_ComTxConfirmation an Dlt.

4. Normative Relevanz & Entwickler-Hinweise

Entwickler von SWCs und BSW-Modulen müssen die Registrierung von Context und Application vor dem Senden von Log-Nachrichten durchführen. Bei Verwendung von DltCom erfolgt die Kommunikation gepuffert und nachgelagert; der Empfang von Steuernachrichten und die Bestätigung von Sendevorgängen erfolgen über die standardisierten Callback-Signaturen (Dlt_ComRxIndication, Dlt_ComTxConfirmation) mit Ergebniscodierung über NotifResultType. Rückgabewerte der Service-Aufrufe sind typisiert als Dlt_ReturnType.
