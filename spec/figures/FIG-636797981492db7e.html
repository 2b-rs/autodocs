  • Klassifikation: UML-Klassendiagramm zur Spezifikation des AUTOSAR ECU-Konfigurationsmodells (ECUC-Parameterdefinition / Metamodell-Ausschnitt gemäß AUTOSAR-Metamodell-Standard).
  • Architektur-Einordnung: BSW-Modul EthTSyn (Time Synchronization over Ethernet, CP-SWS-TimeSyncOverEthernet, gPTP / IEEE 802.1AS). Das Diagramm definiert den Container EthTSynGeneral als zentralen Anker für globale, modulweite Pre-Compile- und Initialisierungsparameter sowie cross-modulare Referenzen zur Hardware-Abstraktionsschicht (EthIf) und zu Security-Diensten (IdsM).

2. Komponenten, Entitäten & Schnittstellen

#### Entitäten und Container-Hierarchie

  • EthTSyn (EcucModuleDef): Wurzelmodul-Definition des Ethernet-Time-Sync-Stacks; Multiplizität: [0..1] auf ECU-Ebene.
  • EthTSynGeneral (EcucParamConfContainerDef): Modulglobaler Konfigurationscontainer; Aggregation via +container, Multiplizität: exakt [1..1].

#### Parameter (+parameter)

  • EthTSynMaxNumberOfTransmitRetries (EcucIntegerParamDef):
  • Multiplizität: [1..1], Wertebereich: [0 .. 20], Defaultwert: 0.
  • Maximale Anzahl an Wiederholungsversuchen bei gescheiterter Frame-Transmission über EthIf_Transmit().
  • EthTSynDevErrorDetect (EcucBooleanParamDef):
  • Multiplizität: [1..1], Defaultwert: false.
  • Steuert die Aktivierung der Det-Fehlererkennung und des DET-Reportings (ETHTSYN_DEV_ERROR_DETECT).
  • EthTSynMainFunctionPeriod (EcucFloatParamDef):
  • Multiplizität: [1..1], Wertebereich: [0 .. INF] (Einheit: Sekunden).
  • Zykluszeit des periodischen Schedulings für EthTSyn_MainFunction().
  • EthTSynVersionInfoApi (EcucBooleanParamDef):
  • Multiplizität: [1..1], Defaultwert: false.
  • Pre-Compile-Schalter für die Verfügbarkeit der API EthTSyn_GetVersionInfo().
  • EthTSynSwitchMgmtRxMessageBufferCount (EcucIntegerParamDef):
  • Multiplizität: [0..1] (optional), Wertebereich: [1 .. 254], Defaultwert: 10.
  • Puffergröße für den Empfang von Switch-Management-Nachrichten (relevant bei Ethernet-Switch-Integration / PTP-Offloading / Boundary/Transparent Clocks).
  • EthTSynTimeValidationSupport (EcucBooleanParamDef):
  • Multiplizität: [1..1], Defaultwert: false.
  • Aktiviert Schnittstellen und Logging zur Validierung der Zeitsynchronisations-Genauigkeit (Weiterleitung an StbM-Time-Validation).
  • EthTSynEnableSecurityEventReporting (EcucBooleanParamDef):
  • Multiplizität: [1..1], Defaultwert: false.
  • Schaltet das Reporting von Security-Events (z. B. Authentifizierungsfehler, gPTP-Anomalien) an das IdsM (Intrusion Detection Security Management) frei.

#### Sub-Container (+subContainer)

  • EthTSynSecurityEventRefs (EcucParamConfContainerDef):
  • Multiplizität: [0..1].
  • Beherbergt Referenzen auf konfigurierte IdsM-Security-Events; semantisch gekoppelt an EthTSynEnableSecurityEventReporting == true.

#### Referenzen (+reference / +destination)

  • EthTSynEthIfFrameType (EcucReferenceDef):
  • Navigiert von EthTSynGeneral via +reference zur Zielentität via +destination.
  • Ziel: EthIfFrameConfig (EcucParamConfContainerDef) mit Multiplizität [1..*].
  • Bindet das Modul EthTSyn an die Frame-Konfiguration des Ethernet-Interfaces (EtherType 0x88F7 für PTPv2/IEEE 802.1AS).

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein rein deklaratives ECUC-Konfigurationsmodell handelt, bildet das Diagramm keine Laufzeitsequenz direkt ab. Aus den Parametern leiten sich jedoch folgende Laufzeitmechanismen ab:

```

[OS / BSW-Scheduler (SchM)]

│

│ Trigger (Periode = EthTSynMainFunctionPeriod)

▼

┌─────────────────────────────────────────────────────────────┐

│ EthTSyn_MainFunction() │

│ - Verarbeitet RX/TX-Zustandsmaschinen │

│ - Evaluiert Time-Validation (falls Support == true) │

│ - Prüft Security-Verletzungen (falls Reporting == true) │

└───────┬─────────────────────────────────────────────┬───────┘

│ │

TX-Fehlschlag Security Event

▼ ▼

[Retry-Schleife] [IdsM_SetSecurityEvent()]

(Bis EthTSynMaxNumberOfTransmitRetries) (Referenz via SecurityEventRefs)

```

  1. Scheduling-Taktung: Die Ausführungsrate der internen State Machines (z. B. Sync, Follow_Up, Pdelay_Req/Resp) in EthTSyn_MainFunction() ist strikt an EthTSynMainFunctionPeriod gebunden.
  2. TX-Retry-Handling: Bei Rückgabe von E_NOT_OK durch EthIf_Transmit() greift ein Wiederholungszähler, begrenzt durch EthTSynMaxNumberOfTransmitRetries. Bei Überschreiten wird der Sendeversuch für die laufende Periode verworfen.
  3. Pufferung im Switch-Betrieb: Wenn EthTSynSwitchMgmtRxMessageBufferCount konfiguriert ist, reserviert der Treiber zur Initialisierungszeit statischen Speicher für Management-Frames zur asynchronen Auswertung von Switch-Ingress/Egress-Timestamps.
  4. Fehler- und Event-Dispatching:
  • Ist EthTSynDevErrorDetect == true, leiten API-Validierungen Fehler synchron an Det_ReportError() weiter.
  • Ist EthTSynEnableSecurityEventReporting == true, triggern Protokollverstöße asynchrone Events an den IdsM über die in EthTSynSecurityEventRefs konfigurierten Kanäle.

4. Normative Relevanz & Entwickler-Hinweise

  • Code-Generierung & Footprint (Pre-Compile Switches):
  • EthTSynDevErrorDetect, EthTSynVersionInfoApi und EthTSynTimeValidationSupport steuern Präprozessor-Direktiven (#if (ETHTSYN_DEV_ERROR_DETECT == STD_ON) etc.). Sind diese false, werden die Prüfpfade und API-Stubs nicht einkompiliert, was ROM und Ausführungszeit spart.
  • Konsistenzprüfung BSW-Scheduler (SchM):
  • Die Konfiguration EthTSynMainFunctionPeriod muss bit-exakt mit dem OS-Task-Trigger der BSW-Scheduler-Konfiguration übereinstimmen. Ein Mismatch führt zu fehlerhaften Timeout-Berechnungen in den PTP-Zustandsautomaten.
  • Strikte Abhängigkeit zu EthIf (EthTSynEthIfFrameType):
  • Mindestens eine Referenz auf EthIfFrameConfig ist obligatorisch (1..*). Fehlt im System-Extract oder der Konfiguration die Zuordnung zu einem konfigurierten PTP-EtherType im EthIf, schlägt die Modell-Validierung (Generierungszeit) fehl; Frames können weder empfangen noch übergeben werden.
  • Security-Konsistenzprüfung:
  • Wird EthTSynEnableSecurityEventReporting auf true gesetzt, muss der Container EthTSynSecurityEventRefs zwingend instanziiert und mit gültigen IdsM-Referenzen belegt sein, um unaufgelöste Symbole im generierten BSW-Code zu verhindern.
  • Switch-Management-Dimensionierung:
  • Bei ECUs mit integriertem Switch oder Switch-Management-Port ist EthTSynSwitchMgmtRxMessageBufferCount an das erwartete Ingress-Aufkommen von Sync-/Pdelay-Frames anzupassen, um Pufferüberläufe und verlorene Hardware-Timestamps im RX-Pfad zu vermeiden.
