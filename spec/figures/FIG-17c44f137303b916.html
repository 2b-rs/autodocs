1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (State Machine Diagram) zur Spezifikation des Zustands- und Betriebsmodus-Verhaltens des AUTOSAR Classic Platform Basissoftware-Moduls FlexRay Network Management (FrNm). Das Diagramm definiert die übergeordneten Betriebsmodi (Bus Sleep Mode, Synchronize, Network Mode) sowie die hierarchischen Subzustände innerhalb des Network Mode (Repeat Message, Normal Operation, Ready Sleep) und deren Interaktion mit dem Zustand Uninit.

2. Komponenten, Entitäten & Schnittstellen

  • Zustände:
    • Uninit: Initialer Ruhezustand vor der Modulinitialisierung.
    • Bus Sleep Mode: Energiesparmodus ohne Kommunikation. Entry-Aktion: FrNm_NetworkRequest = FALSE, FrNm_RepeatMessage = FALSE.
    • Synchronize: Synchronisationsphase zur Herstellung des globalen FlexRay-Zeittakts. Entry-Aktion: Benachrichtigung Notify "Sychronize Mode".
    • Network Mode: Zusammengesetzter Zustand (Composite State) mit den Subzuständen:
      • Repeat Message: Wiederholtes Senden von NM-Botschaften. Entry-Aktion: Start RepeateMessage Timer.
      • Normal Operation: Regulärer aktiver NM-Betrieb mit Abstimmung zum Wachbleiben und Datenübertragung.
      • Ready Sleep: Bereitschaft zum Übergang in den Schlafzustand; keine aktive Abstimmung zum Wachbleiben, keine Datenübertragung.
  • Pseudozustände & Endzustände:
    • Initialzustände (Start-Pseudozustand) für Top-Level und Subzustände von Network Mode.
    • Verzweigungsknoten (Choice/Junction) für zyklische Überprüfungen und Bedingungsabzweige.
    • Terminierungs- bzw. Endzustand (Terminate) nach Power Off.
  • Schnittstellen & Funktionsaufrufe (Trigger/Aktionen):
    • APIs / Callbacks: FrNm_Init(), FrNm_PassiveStartUp(), FrNm_NetworkRequest(), Nm_NetworkRequest(), FrNm_NetworkRelease().
    • Notifications: /Notify "Network Mode", /Nm_BusSleepMode.
    • Interne Signale/Ereignisse: RepeatMessagDetected, RepeatMessageTimer expired, Repetition Cycle completed, ClusterAwakeVote detected, Retrieve global time fails.
  • Statusvariablen & Zähler:
    • FrNm_NetworkRequest (BOOLEAN)
    • FrNm_RepeatMessage (BOOLEAN)
    • FrNm_ReadySleepCnt (Ganzzahl/Zähler)
    • Konfigurationsparameter: FrNmCycleCounterEmulation, StartValue.
  • Kommentar-Notizen:
    • Kennzeichnung des Sende- und Abstimmungsverhaltens je Zustand (Vote for keeping awake, Do data transmission bzw. No voting for keeping awake, No data transmission).
    • Ausführungsbedingung für den Übergang aus Network Mode nach Bus Sleep Mode: sofortige Ausführung bei wahrer Guard-Bedingung im aktuellen MainFunction-Zyklus.

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung & Hochlauf:
    • Nach Systemstart (Start) befindet sich das Modul in Uninit.
    • FrNm_Init() führt in den Bus Sleep Mode.
    • Aus Bus Sleep Mode führt FrNm_PassiveStartUp() oder FrNm_NetworkRequest() (mit Setzen von FrNm_NetworkRequest = TRUE) in den Zustand Synchronize.
  • Synchronisation:
    • In Synchronize wird auf den FlexRay-Zyklus aufsynchronisiert.
    • Bei erfolgreichem Zyklus (Repetition Cycle completed) erfolgt der Übergang in den Network Mode über einen Verzweigungspunkt: Wurde ein Netzwerk angefordert (FrNm_NetworkRequest == TRUE), führt der Pfad mit Aktion /Notify "Network Mode" und FrNm_RepeatMessage = TRUE in Repeat Message.
    • Schlägt die Synchronisation fehl (Retrieve global time fails), führt die Transition zurück nach Synchronize.
    • Reinitialisierung über FrNm_Init() oder Fehler ([FrNm_Init OR (FrNm_NetworkRequested == FALSE AND FrNm_StartUp_Error Indication)]) führt zurück in Bus Sleep Mode.
  • Network Mode Zyklen & Zustandswechsel:
    • Nach Eintritt in Network Mode startet der Subzustand Repeat Message mit dem RepeateMessage Timer.
    • Bei Ablauf des Wiederholungszyklus (Repetition Cycle completed):
      • Ist FrNm_NetworkRequest == TRUE und FrNm_RepeatMessage == FALSE, wechselt der Zustand zu Normal Operation.
      • Ist FrNm_NetworkRequest == FALSE und FrNm_RepeatMessage == FALSE, wechselt der Zustand zu Ready Sleep unter Initialisierung von FrNm_ReadySleepCnt = StartValue.
      • Ist FrNm_ReadySleepCnt > 0 und FrNm_RepeatMessage == TRUE, verbleibt bzw. verzweigt der Pfad in Repeat Message.
    • In Normal Operation:
      • FrNm_NetworkRelease() setzt FrNm_NetworkRequest = FALSE.
      • Bei Repetition Cycle completed [FrNm_NetworkRequest=FALSE AND FrNm_RepeatMessage=FALSE] erfolgt der Wechsel nach Ready Sleep mit Zählerbelegung FrNm_ReadySleepCnt = StartValue.
    • In Ready Sleep:
      • Solange FrNm_NetworkRequest == FALSE AND FrNm_RepeatMessage == FALSE AND FrNm_ReadSleepCnt > 0, dekrementiert jeder Zyklus den Zähler: /FrNm_ReadySleepCnt = FrNm_ReadySleepCnt - 1.
      • Wird eine Netzwerkanforderung empfangen (FrNm_NetworkRequest()), wird FrNm_NetworkRequest = TRUE gesetzt und bei FrNm_ReadySleepCnt > 0 nach Normal Operation gewechselt.
      • Wird ein ClusterAwakeVote detected, wird FrNm_ReadySleepCnt = StartValue neu gesetzt.
      • Wenn Repetition Cycle completed [FrNm_ReadySleepCnt < 1] eintritt, erfolgt über eine Exit-Verzweigung der Verlassen-Übergang von Network Mode in Bus Sleep Mode unter Auslösung von /Nm_BusSleepMode.
    • Übergeordnete Fehlerübergänge aus Network Mode:
      • Retrieve global time fails [FrNmCycleCounterEmulation == FALSE AND Network is requested] führt zurück nach Synchronize.
      • Reinitialisierung FrNm_Init() führt direkt nach Bus Sleep Mode.
  • Herunterfahren:
    • Aus Bus Sleep Mode führt Power Off in den Endzustand Terminate.

4. Normative Relevanz & Entwickler-Hinweise

  • Das Zustandsmodell legt die normativen Anforderungen an das AUTOSAR Classic FlexRay Network Management Modul fest.
  • Implementierer müssen sicherstellen, dass Guards unmittelbar im Zyklus der FrNm_MainFunction evaluiert und Transitionen verzögerungsfrei abgearbeitet werden, insbesondere beim Verlassen des Network Mode bei abgelaufenem FrNm_ReadySleepCnt.
  • Korrekte Pflege und synchrone Zählung von FrNm_ReadySleepCnt sowie das Rücksetzen bei externen Wachhalte-Votings (ClusterAwakeVote detected) sind essenziell für die koordinierte Cluster-Abschaltung.
  • Die Emulation des Zykluszählers (FrNmCycleCounterEmulation) bestimmt das Verhalten bei Verlust der globalen Zeitbasis.
