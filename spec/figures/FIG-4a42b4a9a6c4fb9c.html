1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm / Metamodell-Ausschnitt aus der AUTOSAR System-Template-Spezifikation (AUTOSAR_TPS_SystemTemplate, Sub-Package TransportProtocols: NmCanConfiguration).
  • Funktionale Einordnung:
  • Metamodell-Definition zur Ausprägung der Netzwerkmanagement-Topologie (NM) für CAN im Rahmen der AUTOSAR-Systembeschreibung (FIBEX-Modellierung).
  • Strukturierung der Abstraktionsebenen zwischen busunabhängigen NM-Basisstrukturen (NmCluster, NmNode, NmEcu) und deren bus-spezifischer Spezialisierung für den CAN-Stack (CanNmCluster, CanNmNode, CanNmEcu, CanNmClusterCoupling).
  • Verbindungspunkt zwischen logischer Topologie (CoreTopology::CommunicationCluster), PDU-Routing (CoreCommunication::NmPdu, ISignalToIPduMapping) und BSW-Konfigurationsgenerierung (CanNm / Nm-Stack).

2. Komponenten, Entitäten & Schnittstellen

#### Metamodell-Wurzel & Basiselemente

  • NmConfig (Spezialisierung von FibexElement):
  • Zentraler Container für die netzwerkweite NM-Konfiguration.
  • Kompositionen:
  • +nmCluster [1..\*] zu NmCluster (Stereotyp «atpVariation», Binding Time: postBuild).
  • +nmIfEcu [1..\*] zu NmEcu (Stereotyp «atpVariation», Binding Time: preCompileTime).
  • +nmClusterCoupling [0..\*] zu NmClusterCoupling (Stereotyp «atpVariation», Binding Time: postBuild).

#### Busunabhängige NM-Abstraktionen (Generalisierungen)

  • NmCluster (Spezialisierung von Identifiable):
  • Repräsentiert ein logisches NM-Netzwerksegment.
  • Attribute: nmChannelSleepMaster (Boolean), nmNodeDetectionEnabled (Boolean [0..1]), nmNodeIdEnabled (Boolean [0..1]), nmPncParticipation (Boolean [0..1]), nmRepeatMsgIndEnabled (Boolean [0..1]), nmSynchronizingNetwork (Boolean).
  • Assoziation: +communicationCluster [1] auf CoreTopology::CommunicationCluster («atpVariation», postBuild).
  • Komposition: +nmNode [0..\*] auf NmNode.
  • NmEcu (Spezialisierung von Identifiable):
  • ECU-spezifische NM-Schnittstellenkonfiguration (Generic NM-Interface / Nm).
  • Attribute: Schalter für Callbacks und Zykluszeiten (nmBusSynchronizationEnabled, nmComControlEnabled, nmCycletimeMainFunction, nmNodeDetectionEnabled, nmNodeIdEnabled, nmPduRxIndicationEnabled, nmRemoteSleepIndEnabled, nmRepeatMsgIndEnabled, nmStateChangeIndEnabled, nmUserDataEnabled).
  • Komposition: +busDependentNmEcu [0..\*] auf BusspecificNmEcu (mit Rückassoziation +nmIfEcu [1]).
  • Assoziation: +nmNode [1..\*] zu NmNode.
  • NmNode (Spezialisierung von Identifiable):
  • Logischer NM-Teilnehmer (Instanz eines Steuergeräts auf einem Cluster).
  • Attribute: nmCoordCluster (PositiveInteger [0..1]), nmCoordinatorRole (NmCoordinatorRoleEnum [0..1]), nmNodeId (Integer [0..1]), nmPassiveModeEnabled (Boolean [0..1]).
  • Assoziationen: +txNmPdu [0..\] und +rxNmPdu [1..\] zu CoreCommunication::NmPdu.
  • NmClusterCoupling & NmCoordinator:
  • Ermöglicht die hierarchische Cluster-Koordination (Multi-Bus-Gateway).
  • NmClusterCoupling aggregiert +nmCoordinator [0..1] (index, nmCoordSyncSupport, nmGlobalCoordinatorTime) und referenziert +coupledCluster [*] auf NmCluster.

#### CAN-spezifische Spezialisierungen

  • CanNmCluster (erbt von NmCluster):
  • Enthält die deterministischen Timing- und Protokoll-Parameter für das AUTOSAR CAN-NM:
  • Zustands- & Timeout-Timer: nmNetworkTimeout, nmMsgCycleTime, nmMessageTimeoutTime, nmWaitBusSleepTime, nmRepeatMessageTime, nmRemoteSleepIndicationTime.
  • Immediate Transmissions: nmImmediateNmTransmissions (PositiveInteger), nmImmediateNmCycleTime (TimeValue [0..1]).
  • PDU-Header-Layout: nmCbvPosition (Integer [0..1]), nmNidPosition (Integer [0..1]).
  • Car Wake-Up (CWU) & Busload-Reduktion: nmCarWakeUpBitPosition, nmCarWakeUpFilterNodeId, nmBusloadReductionActive.
  • CanNmNode (erbt von NmNode):
  • CAN-Knotenspezifische Sende-Offsets und CWU-Filterung:
  • nmMsgCycleOffset (TimeValue), nmMsgReducedTime (TimeValue), nmCarWakeUpFilterEnabled (Boolean [0..1]), nmCarWakeUpRxEnabled (Boolean [0..1]).
  • CanNmEcu (erbt von BusspecificNmEcu):
  • Konkrete ECU-Bindung an den BSW-Treiber CanNm.
  • CanNmClusterCoupling (erbt von NmClusterCoupling):
  • Attribute: nmBusloadReductionEnabled (Boolean), nmImmediateRestartEnabled (Boolean).

#### PDU- und Signal-Mapping

  • CoreCommunication::NmPdu (erbt von Pdu):
  • Repräsentiert die CAN-NM-Botschaft auf dem Bus.
  • Attribute: nmDataInformation (Boolean [0..1]), nmVoteInformation (Boolean [0..1]), unusedBitPattern (Integer [0..1]).
  • Komposition: +iSignalToIPduMapping [0..\*] zu CoreCommunication::ISignalToIPduMapping (Einbettung von Signalen/User Data, wie PNC-Vektoren für Partial Networking, inkl. Endianness, Startposition und Update-Bits).

3. Dynamisches Verhalten & Protokoll-Zusammenhänge

Obwohl das Diagramm statische Klassen beschreibt, parametrisieren die Attribute direkt den dynamischen SWS-Zustandsautomaten des CanNm:

```mermaid

stateDiagram-v2

[*] --> BusSleepMode

BusSleepMode --> RepeatMessageState : Network Request / Wakeup PDU

state NetworkMode {

state RepeatMessageState {

[*] --> ImmediateTransmissions : nmImmediateNmTransmissions > 0

ImmediateTransmissions --> NormalPeriodic : nach Fast-Tx-Burst

}

state NormalOperationState

state ReadySleepState

RepeatMessageState --> NormalOperationState : nmRepeatMessageTime abgelaufen

NormalOperationState --> ReadySleepState : Network Release

ReadySleepState --> NormalOperationState : Network Request

ReadySleepState --> PrepareBusSleepMode : nmNetworkTimeout abgelaufen

}

PrepareBusSleepMode --> BusSleepMode : nmWaitBusSleepTime abgelaufen

PrepareBusSleepMode --> RepeatMessageState : Network Request / Rx NM PDU

```

  • Transmissionspfade:
  • Immediate Transmission Burst: Parametrisiert über nmImmediateNmTransmissions und nmImmediateNmCycleTime.
  • Zyklisches Senden & Busload Reduction: Bei aktivem nmBusloadReductionActive Wechsel der Sendeperiode auf nmMsgReducedTime; Entzerrung gleichzeitigen Sendens über nmMsgCycleOffset.
  • Payload-Layouting:
  • Positionierung des Control Bit Vectors (CBV) via nmCbvPosition und der Quell-Knoten-ID (NID) via nmNidPosition steuert den Serialisierungs- und Filtermechanismus im PDU-Buffer.
  • Car Wake-Up (CWU):
  • Filterprüfung eingehender NM-PDUs gegen nmCarWakeUpFilterNodeId bei gesetztem Bit an nmCarWakeUpBitPosition.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW-Codegenerierung & Bindezeiten:
  • Die Variabilitäts-Stereotypen («atpVariation») trennen Compile-Zeit- und Post-Build-Konfigurationen:
  • NmEcu (preCompileTime): Schalter für Indication-Callbacks (nmPduRxIndicationEnabled, nmStateChangeIndEnabled) und nmCycletimeMainFunction bestimmen die generierten Makros und Funktionszeiger im generischen Interface Nm.
  • NmCluster / CanNmCluster (postBuild): Timer (nmNetworkTimeout, nmWaitBusSleepTime) und PDU-Layout-Offsets können in Post-Build-Strukturen (CanNm_ConfigType) ausgelagert werden.
  • Mapping System Template $\to$ BSW ECUC:
  • NmCluster $\to$ /AUTOSAR/EcucDefs/Nm/NmChannelConfig
  • CanNmCluster $\to$ /AUTOSAR/EcucDefs/CanNm/CanNmGlobalConfig/CanNmChannelConfig
  • CanNmNode $\to$ Knotenspezifische Tx/Rx-Parameter (CanNmNodeId, CanNmTxPdu)
  • Fallstricke für Integratoren:
  • Timing-Konsistenz: nmNetworkTimeout muss zwingend größer gewählt werden als nmMsgCycleTime (typisch: $Faktor \ge 2..3$), um unerwünschte Timeouts bei Jitter zu verhindern.
  • PNC / Partial Networking: Ist nmPncParticipation = true, muss die PDU-Struktur zwingend ein ISignalToIPduMapping enthalten, das den ERA/EIRA-PNC-Bitvektor innerhalb der User Data Bytes der NmPdu transportiert.
  • PDU-Offset-Kollisionen: nmCbvPosition und nmNidPosition dürfen nicht mit Nutzdaten-Signalen im ISignalToIPduMapping kollidieren (Offset 0/1 Konflikte je nach Standard-/Erweitertem PDU-Header).
