1. Diagrammtyp & Architektur-Kontext

Prozessorientiertes Datenfluss- und Build-Diagramm zur Veranschaulichung des AUTOSAR-BSW-Konfigurations- und Generierungsprozesses (ECU Configuration / BSW Configuration Steps). Das Diagramm stellt dar, wie XML-basierte Konfigurationsparameter auf Modulebene in Quellcode-Artefakte transformiert, kompiliert und zu ausführbaren Images für ein Steuergerät zusammengebunden werden.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm gliedert sich in Artefakte (Dateisymbole mit Dateiendungen) und Verarbeitungsschritte (gelbe Pfeil-Prozessblöcke):

  • Eingangsartefakte:
    • .XML ECU Configuration Description (gliedert sich über gestrichelte Pfeile in modulspezifische Parameterteile).
    • .XML BSW Pre-Compile Parameters.
    • .XML BSW Link-Time Parameters.
    • .XML BSW Post-Build Parameters.
    • Statischer Quellcode pro BSW-Modul: .c BSW Code und .h BSW Header.
    • Vorkompilierte Artefakte anderer Schichten: .obj Compiled RTE Code und .obj Compiled SWC Code.
  • Generierte Zwischenartefakte:
    • .h BSW Configuration Header.
    • .h BSW Pre-Compile Parameters.
    • .c BSW Link-Time Parameters.
    • .c BSW Post-Build Parameters.
  • Kompilierte Objektdateien:
    • .obj Compiled BSW Code.
    • .obj Compiled BSW Link-Time Configuration.
    • .obj Compiled BSW Post-Build Configuration.
  • Endartefakte (Binaries):
    • .exe ECU Code Image.
    • .exe ECU Post-Build Data Image.
  • Verarbeitungsschritte (Prozesse):
    • Generate BSW Configuration.
    • Compile BSW Code.
    • Compile BSW Link-Time Configuration.
    • Compile BSW Post-Build Configuration.
    • Link BSW Modules, RTE, and SWCs.
    • Link Post-Build Configuration.
  • Strukturierende Rahmen (Scopes):
    • Gestrichelter Rahmen Per BSW Module.
    • Unterteilung in Pre-Compile and Link-Time Part sowie Post-Build Part.

3. Dynamisches Verhalten & Sequenzablauf

  1. Konfigurationsgenerierung: Der Generatorprozess Generate BSW Configuration liest die XML-Parameter (BSW Pre-Compile Parameters, BSW Link-Time Parameters, BSW Post-Build Parameters) und erzeugt die modulspezifischen Konfigurationsdateien (.h BSW Configuration Header, .h BSW Pre-Compile Parameters, .c BSW Link-Time Parameters, .c BSW Post-Build Parameters).
  2. Kompilierung des BSW-Codes: Compile BSW Code verarbeitet den statischen Quellcode (.c BSW Code, .h BSW Header) unter Einbindung des generierten .h BSW Configuration Header und der Pre-Compile-Header und erzeugt die Objektdatei .obj Compiled BSW Code.
  3. Kompilierung der Link-Time-Konfiguration: Compile BSW Link-Time Configuration übersetzt die generierte C-Quelldatei .c BSW Link-Time Parameters unter Einbindung des Headers .h BSW Configuration Header in .obj Compiled BSW Link-Time Configuration.
  4. Kompilierung der Post-Build-Konfiguration: Compile BSW Post-Build Configuration übersetzt die generierte C-Quelldatei .c BSW Post-Build Parameters unter Einbindung des Headers .h BSW Configuration Header in .obj Compiled BSW Post-Build Configuration.
  5. Erzeugung des Code-Images: Der Linker-Schritt Link BSW Modules, RTE, and SWCs bindet .obj Compiled BSW Code, .obj Compiled BSW Link-Time Configuration sowie .obj Compiled RTE Code und .obj Compiled SWC Code zusammen zum Binary .exe ECU Code Image.
  6. Erzeugung des Post-Build-Daten-Images: Der Linker-Schritt Link Post-Build Configuration bindet .obj Compiled BSW Post-Build Configuration separat zum Binary .exe ECU Post-Build Data Image.

4. Normative Relevanz & Entwickler-Hinweise

Das Schaubild illustriert die normative Trennung der AUTOSAR-Konfigurationsklassen (Pre-Compile Time, Link Time und Post-Build Time / Selectable bzw. Loadable). Für Integratoren und Tool-Entwickler ist wesentlich:

  • Post-Build-Konfigurationsdaten werden unabhängig vom eigentlichen Code-Image kompiliert und gelinkt, sodass sie als separates Daten-Image (.exe ECU Post-Build Data Image) im Speicher platziert und nachträglich aktualisiert werden können.
  • Pre-Compile- und Link-Time-Artefakte fließen direkt zusammen mit RTE und SWCs in das monolithische Code-Image (.exe ECU Code Image) ein.
  • Der generierte Konfigurations-Header (.h BSW Configuration Header) wird von allen drei Kompilierungspfaden (Code, Link-Time-Daten, Post-Build-Daten) inkludiert, um konsistente Typ- und Strukturdefinitionen sicherzustellen.
