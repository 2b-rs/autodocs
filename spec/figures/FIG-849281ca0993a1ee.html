1. Diagrammtyp & Architektur-Kontext

Konzeptionelles Datenfluss- und Architekturdiagramm zur Veranschaulichung des Logging-Prozesses im Non-Verbose-Modus gemäß AUTOSAR PRS LogAndTraceProtocol. Es zeigt den transport- und plattformübergreifenden Weg von Log-Nachrichten aus ECU-Anwendungen über das zentrale Dlt-Modul bis hin zu einem externen Logging-/Tracing-Tool. Das Diagramm deckt sowohl die Classic Platform (DLT) als auch die Adaptive Platform (ara::log) ab.

2. Komponenten, Entitäten & Schnittstellen

  • ECU (Electronic Control Unit): Begrenzender Systemkontext für die loggenden Applikationen und die Laufzeitumgebung.
  • Application: Drei exemplarische Anwendungsblöcke (Application) auf der ECU als Quellen für Log-Ereignisse.
  • Dlt module: Zentrales Protokoll- und Verarbeitungsmodul auf der ECU, ausgewiesen als Classic-DLT (DLT) oder Adaptive-Logging-Instanz (ara::log).
  • Meta-Informationsdatei (Dokumentensymbol): Externe Beschreibungsdatei (z. B. XML/FIBEX/ARXML) mit Metadaten zur Decodierung und Zuordnung der kompakten Non-Verbose-IDs.
  • Externes Test-/Diagnosegerät (Laptop-Symbol): Empfänger, Anzeigegerät und Speicherort für DLT-Nachrichten und Auswertungsstation unter Nutzung der Metainformationen.
  • Schnittstellen:
    • Interne Schnittstelle / Datenpfad zwischen Application und Dlt module zur Übergabe von Log-Rohdaten.
    • Externe Diagnoseschnittstelle / Kommunikationskanal (z. B. Ethernet, CAN, FlexRay, USB) vom Dlt module zum externen Tool.
    • Dateischnittstelle / Importpfad für Meta-Informationen in das externe Tool.

3. Dynamisches Verhalten & Sequenzablauf

Nummerierter Ablauf in fünf Schritten:

  1. provide log data: Eine Application übergibt Log-Daten (einschließlich Message-IDs und Parameterwerte) an das Dlt module.
  2. filter/generate Dlt message: Das Dlt module filtert die Daten nach konfigurierten Log-Leveln und packt sie in das binäre DLT-Nachrichtenformat des Non-Verbose-Modus (Übertragung von IDs statt Volltext-Strings).
  3. send Dlt message: Das Dlt module sendet die generierten DLT-Nachrichten über die ECU-Kommunikationsschnittstelle an das Logging-Tool.
  4. provide meta information: Die Metainformationsdatei wird dem externen Tool bereitgestellt/eingelesen, um die Zuordnung von IDs zu Klartexten, Argumenttypen und Kontexten zu ermöglichen.
  5. store Dlt message: Das externe Tool empfängt die DLT-Nachrichten und speichert bzw. verarbeitet sie.

4. Normative Relevanz & Entwickler-Hinweise

Im Non-Verbose-Modus werden zur Reduktion von Buslast und ECU-Laufzeitaufwand keine Klartextbeschreibungen oder vollständigen Format-Strings im DLT-Payload übertragen, sondern kompakte numerische Identifikatoren (Message IDs / Static IDs). Entwickler müssen sicherstellen, dass die zugehörigen Metadaten synchron zum jeweiligen Softwarestand vorliegen, da das externe Tool die binär empfangenen und gespeicherten Non-Verbose-Nachrichten andernfalls nicht decodieren oder semantisch auflösen kann. Die Implementierung muss sowohl für AUTOSAR Classic als auch für AUTOSAR Adaptive die einheitliche Payload-Strukturierung gemäß Protokollspezifikation einhalten.
