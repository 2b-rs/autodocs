1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm / AUTOSAR ECU Configuration Metamodel (ECUC Parameter Configuration Definition Model gemäß TPS ECUConfiguration).
  • Technischer Zweck: Definition der Metamodell-Struktur für die Anbindung von Complex Device Drivern (CDD) an das AUTOSAR-Zeitsynchronisations-Framework (Global Time Synchronization, GTS).
  • Architektonische Einordnung: Erlaubt CDDs, als Timebase Provider (Master) oder Timebase Consumer (Slave) proprietäre oder spezialisierte Busprotokolle an den standardisierten Synchronized Time-Base Manager (StbM) anzubinden und diese über die Kommunikationsschnittstelle (ComIf) mit PDU-Routingstrukturen zu verknüpfen.

2. Komponenten, Entitäten & Schnittstellen

#### Metamodell-Klassen & Container-Hierarchie (Kompositionen)

  • *Cdd (:EcucModuleDef, Mult. 0..):** Moduldefinition des Complex Device Drivers.
  • +container $\rightarrow$ CddGlobalTimeContribution (:EcucParamConfContainerDef, Mult. 0..1): Optionaler Wurzelcontainer zur Aktivierung von GTS-Funktionalitäten im CDD.
  • +subContainer $\rightarrow$ *CddGlobalTimeDomain (:EcucParamConfContainerDef, Mult. 1..):** Konfigurationsknoten für eine konkrete globale Zeitdomäne innerhalb des CDD.

#### Zeitdomänen-Parameter & Referenzen

  • CddGlobalTimeDomainId (:EcucIntegerParamDef): Parameter (+parameter), Wertebereich min = 0, max = 31. Repräsentiert die AUTOSAR-Standard-Domain-ID (max. 32 Time Domains).
  • CddSynSynchronizedTimeBaseRef (:EcucReferenceDef): Referenz (+reference) mit Attribut requiresSymbolicNameValue = true, die via +destination auf den externen Container StbMSynchronizedTimeBase (:EcucParamConfContainerDef, Mult. 1..*) des StbM-Moduls verweist.

#### Master-Zweig (CddGlobalTimeMaster, Mult. 0..1)

  • Aggregiert als +subContainer unter CddGlobalTimeDomain.
  • CddGlobalTimeTxPeriod (:EcucFloatParamDef): Parameter (+parameter), Wertebereich min = 0.0 [s]. Definiert die zyklische Sendeperiode für GTS-Botschaften des CDD.
  • CddGlobalTimeMasterPdu (:EcucParamConfContainerDef, Mult. 0..1): Sub-Container für die Master-PDU.
  • +reference $\rightarrow$ CddGlobalTimeMasterPduRef (:EcucReferenceDef): Verweist via +destination auf CddComIfUpperLayerTxPdu (:EcucParamConfContainerDef, Mult. 0..*).

#### Slave-Zweig (CddGlobalTimeSlave, Mult. 0..1)

  • Aggregiert als +subContainer unter CddGlobalTimeDomain.
  • CddGlobalTimeSlavePdu (:EcucParamConfContainerDef, Mult. 0..1): Sub-Container für die Slave-PDU.
  • +reference $\rightarrow$ CddGlobalTimeSlavePduRef (:EcucReferenceDef): Verweist via +destination auf CddComIfUpperLayerRxPdu (:EcucParamConfContainerDef, Mult. 0..*).

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm bildet ein statisches Konfigurationsmodell ab. Die daraus resultierende Laufzeitdynamik gliedert sich in zwei orthogonale Pfade:

```

[Master-Pfad]

Trigger: CddGlobalTimeTxPeriod (Timer)

└─► CDD liest Zeitstempel via StbM_GetCurrentTime()

└─► Kapselung in GTS-Master-PDU

└─► PduR/ComIf-Sendeaufruf via CddComIfUpperLayerTxPdu

[Slave-Pfad]

Trigger: Rx-Indication von ComIf/PduR via CddComIfUpperLayerRxPdu

└─► CDD entpackt Sync-/FollowUp-PDU

└─► Korrekturwert-Berechnung

└─► Aktualisierung der Zeitbasis via StbM-Set-APIs (z. B. StbM_BusSetGlobalTime)

```

  • Synchronisationsabbruch / Timeout: Erreicht die Slave-PDU nicht innerhalb des parametrierten Timeouts den CDD, meldet der CDD/StbM Statusflags (z. B. TIMEOUT, Verlust des Sync-Status an BSW-Module/RTE).

4. Normative Relevanz & Entwickler-Hinweise

  • SWS-Konformität: Erfüllt ECUC_Cdd_00068 (Definition der CDD-Global-Time-Konfiguration).
  • Rollenflexibilität: Da CddGlobalTimeMaster und CddGlobalTimeSlave jeweils Multiplizität 0..1 besitzen, kann ein CDD je Domäne als reiner Master, reiner Slave oder als Gateway/Bridge (beide Container vorhanden) ausgeprägt werden.
  • PDU-Entkopplung: Der CDD bindet sich nicht direkt an Hardware-Treiberkanäle (wie Can/Fr/Eth), sondern nutzt CddComIfUpperLayerTxPdu und CddComIfUpperLayerRxPdu. Dadurch bleibt der Treiber unabhängig vom konkreten Transceiver/Bustyp und fügt sich nahtlos in die AUTOSAR-PDU-Routing-Hierarchie ein.
  • ID-Restriktion: Die Beschränkung von CddGlobalTimeDomainId auf [0..31] korrespondiert direkt mit den Limitierungen im StbM (StbM_SynchronizedTimeBaseType Bitfeld-Adressierung). Konfiguratoren müssen die Eindeutigkeit dieser ID über alle GTS-Provider hinweg validieren.
