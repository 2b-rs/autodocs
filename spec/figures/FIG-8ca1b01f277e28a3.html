1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (State Machine) für das AUTOSAR CAN Generic Network Management (CanNm) innerhalb der AUTOSAR-Basissoftware (BSW, Communication Services). Das Diagramm spezifiziert die Betriebsmodi und internen Zustände des NM-Zustandsautomaten sowie die Bedingungen für Zustandsübergänge, Timer-Steuerungen und Benachrichtigungen an übergeordnete Schichten (wie den NM Interface / NM Coordinator).

2. Komponenten, Entitäten & Schnittstellen

Hauptmodi und Zustände:

  • Bus-Sleep Mode: Ruhezustand ohne Netzwerkaktivität.
  • Prepare Bus-Sleep Mode: Übergangszustand zur Vorbereitung des Einschlafens des Busses.
  • Network Mode (Komposit-Zustand), unterteilt in drei Subzustände:
    • Repeat Message: Einstiegszustand des Network Mode zur wiederholten Übertragung/Erkennung von NM-Botschaften.
    • Normal Operation: Zustand bei aktiv angefordertem Netzwerk (aktive Teilnahme und Botschaftsübertragung).
    • Ready Sleep: Zustand bei freigegebenem Netzwerk (Warten auf Inaktivität der restlichen Busteilnehmer).
  • Pseudozustände: Initialer Zustand (PowerOff / Initialize NM) sowie Endzustand (PowerOff).

Trigger, Ereignisse und API-/Callback-Schnittstellen:

  • Ereignisse/Trigger: Initialize NM, PowerOff, Passive StartUp, Network Request, Network Release, NM-Message received, NM-Message transmitted, Repeat Message Bit Indication, Repeat Message State Request.
  • Timer: NM-Timeout Timer, Repeat Message Timer, Wait Bus-Sleep Timer.
  • Benachrichtigungen / Callbacks: Notify 'Network Mode', Notify 'Network Start', Notify 'Network Timeout', Notify 'Prepare Bus-Sleep Mode', Notify 'Bus-Sleep Mode'.

3. Dynamisches Verhalten & Sequenzablauf

  1. Initialisierung & Ruhezustand:
    • Ausgehend von PowerOff führt Initialize NM in den Zustand Bus-Sleep Mode.
    • Ein Übergang zurück nach PowerOff (Endzustand) kann aus dem Bus-Sleep Mode via PowerOff erfolgen.
    • Der Empfang einer NM-Botschaft (NM-Message received) im Bus-Sleep Mode triggert die interne Aktion Notify 'Network Start'.
  2. Übergang in den Network Mode:
    • Sowohl aus dem Bus-Sleep Mode (durch Passive StartUp or Network Request) als auch aus dem Prepare Bus-Sleep Mode (durch NM-Message received or Network Request) erfolgt der Übergang in den Subzustand Repeat Message des Network Mode. Dabei wird der NM-Timeout Timer gestartet, der Repeat Message Timer gestartet und Notify 'Network Mode' ausgelöst.
  3. Verhalten innerhalb des Network Mode:
    • Auf Ebene des Kompositzustands Network Mode bewirkt jedes NM-Message received or NM-Message transmitted eine Ausführung von Restart NM-Timeout Timer.
    • Bei Ablauf des Repeat Message Timer (Repeat Message Time expired):
      • Wenn das Netzwerk angefordert ist (Network requested), Wechsel von Repeat Message nach Normal Operation.
      • Wenn das Netzwerk freigegeben ist (Network released), Wechsel von Repeat Message nach Ready Sleep.
    • Zwischen Normal Operation und Ready Sleep:
      • Network Release führt von Normal Operation nach Ready Sleep.
      • Network Request führt von Ready Sleep nach Normal Operation.
    • Rückkehr nach Repeat Message:
      • Sowohl aus Normal Operation als auch aus Ready Sleep führt Repeat Message Bit Indication or Repeat Message State Request unter Neustart des Repeat Message Timers (Start Repeat Message Timer) zurück in den Zustand Repeat Message.
    • Lokale Timeouts:
      • In Repeat Message und Normal Operation führt NM-Timeout Time expired als interne/selbstgerichtete Transition zum Neustart des NM-Timeout-Timers (Start NM-Timeout Timer) und zur Meldung Notify 'Network Timeout'.
  4. Verlassen des Network Mode & Einschlafen:
    • Tritt in Ready Sleep das Ereignis NM-Timeout Time expired auf, wechselt der Automat in den Zustand Prepare Bus-Sleep Mode und benachrichtigt übergeordnet mit Notify 'Prepare Bus-Sleep Mode'.
    • Im Prepare Bus-Sleep Mode läuft der Wait Bus-Sleep Timer. Bei Ablauf (Wait Bus-Sleep Time expired) erfolgt der Wechsel in den Bus-Sleep Mode verbunden mit Notify 'Bus-Sleep Mode'.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm bildet das normative Kernverhalten des CAN NM-Zustandsautomaten ab. Entwickler müssen sicherstellen, dass:

  • Sämtliche Timer (NM-Timeout Timer, Repeat Message Timer, Wait Bus-Sleep Timer) mit konfigurierbaren Zeitwerten (gemäß NM-Parameter-Konfiguration) realisiert und an den angegebenen Kanten präzise gestartet, neu gestartet bzw. überwacht werden.
  • Die Benachrichtigungen (Notify ...) synchron oder asynchron an die Schnittstellen des ComM bzw. NmIf weitergeleitet werden.
  • Im Kompositzustand Network Mode der NM-Timeout-Timer durch Botschaftsempfang oder -sendung auf Kanalebene kontinuierlich nachgetriggert wird.
  • Ein Übergang in den Prepare Bus-Sleep Mode ausschließlich aus Ready Sleep bei ausbleibenden NM-Botschaften (NM-Timeout) zulässig ist, während ein neuer Network Request oder Botschaftsempfang den Zustand sofort wieder in Repeat Message überführt.
