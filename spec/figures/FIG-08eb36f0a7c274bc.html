1. Diagrammtyp & Architektur-Kontext

Konzeptionelles SPEM-basiertes Metamodell- bzw. Methodik-Diagramm (Methodology Content Definition) aus der AUTOSAR Methodology. Das Diagramm definiert die Kernbestandteile einer wiederverwendbaren Aufgabenbeschreibung (Task Definition) und stellt deren statische sowie funktionale Beziehungen zu Rollen, Werkzeugen und Arbeitsergebnissen (Work Products) dar.

2. Komponenten, Entitäten & Schnittstellen

Zentrales Element ist die Task Definition (dargestellt als pfeilförmiger Prozessbaustein). Die assoziierten Entitäten und Schnittstellen umfassen:

  • Role Definition (Piktogramm Person): Über eine gerichtete Assoziation mit dem Stereotyp «performs» mit der Task Definition verbunden (beschreibt die ausführende Rolle).
  • Tool Definition (Piktogramm Hammer): Verbunden über eine gerichtete Kante mit dem Stereotyp «used tool», ausgehend von der Task Definition hin zum Werkzeug.
  • Eingangs-Arbeitsergebnis (Dokumentensymbol links): Gerichtete Beziehung mit Stereotyp «input» und Kardinalität 0..* auf die Task Definition.
  • Ausgangs-Arbeitsergebnis (Dokumentensymbol rechts): Gerichtete Beziehung mit Stereotyp «output» und Kardinalität 0..* von der Task Definition auf das Dokumentensymbol.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm bildet ein Transformations- und Rollenzuordnungsmuster ab:

  1. Eine oder mehrere Role Definition führen die Task Definition aus («performs»).
  2. Die Task Definition konsumiert null bis beliebig viele Eingangs-Work-Products («input», 0..*).
  3. Zur Durchführung greift die Task Definition auf unterstützende Werkzeuge zu («used tool» auf Tool Definition).
  4. Als Ergebnis erzeugt oder aktualisiert die Task Definition null bis beliebig viele Ausgangs-Work-Products («output», 0..*).

4. Normative Relevanz & Entwickler-Hinweise

Metamodell-Definition für AUTOSAR-Methodik- und Prozessbeschreibungen. Für Prozessmodellierer und Tool-Entwickler verbindlich:

  • Aufgaben (Task Definition) sind deklarativ und prozessunabhängig wiederverwendbar.
  • Kardinalitäten von 0..* für Ein- und Ausgänge kennzeichnen optionale bzw. mehrfache Artefakte.
  • Rollen und Werkzeuge sind als wiederverwendbare Definitionsbausteine von konkreten Instanziierungen (Use Cases) entkoppelt.
