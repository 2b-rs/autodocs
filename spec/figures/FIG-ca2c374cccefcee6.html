1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Objektdiagramm (Instanzendiagramm) zur Spezifikation eines konkreten Beispiellayouts im AUTOSAR System Template (AUTOSAR_SystemTemplate, Kapitel Communication / PDU Description).
  • Technischer Zweck: Modellierung einer gemultiplexten I-PDU (MultiplexedIPdu) für das BSW-Modul IpduM (I-PDU Multiplexer) im AUTOSAR Classic Communication Stack. Es definiert die statische ARXML-Beschreibungsvorschrift, wie mehrere logische PDUs (ISignalIPdu) über ein gemeinsames Netzwerk-Frame (CAN/FlexRay, 64 Bit Gesamtlänge) über ein selektorgesteuertes Multiplexing aggregiert und übertragen werden.

2. Komponenten, Entitäten & Schnittstellen

  • Wurzel-Entität (MuxPdu :MultiplexedIPdu):
  • Repräsentiert die resultierende Multiplex-PDU auf Bus-Ebene.
  • Attribute: selectorFieldLength = 1, length = 64 (Bit), selectorFieldStartPosition = 0 (Bit 0).
  • Kompositionen: Exakt ein statischer Teil (:StaticPart) und ein dynamischer Teil (:DynamicPart).
  • Statischer Teil (:StaticPart & staticSegment :SegmentPosition):
  • Enthält Nutzdaten, die in jedem Sendezyklus übertragen werden.
  • Komposition auf staticSegment :SegmentPosition: segmentLength = 16, segmentPosition = 32 (belegt Bit 32 bis 47).
  • Gerichtete Assoziation auf PduA :ISignalIPdu (Quell-/Ziel-PDU für den statischen Nutzdatenbereich).
  • Dynamischer Teil (:DynamicPart & Segmente):
  • Komposition auf zwei nicht-zusammenhängende Segmente (SegmentPosition):
  • dynamicSegment1 :SegmentPosition: segmentLength = 31, segmentPosition = 1 (belegt Bit 1 bis 31).
  • dynamicSegment2 :SegmentPosition: segmentLength = 16, segmentPosition = 48 (belegt Bit 48 bis 63).
  • Summe des dynamischen Payloads: 47 Bit (31 Bit + 16 Bit), die das statische Segment umschließen.
  • Multiplex-Alternativen (DynamicPartAlternative):
  • alternative1 :DynamicPartAlternative: Attribut selectorFieldCode = 1, referenziert PduC :ISignalIPdu.
  • alternative2 :DynamicPartAlternative: Attribut selectorFieldCode = 0, referenziert PduB :ISignalIPdu.
  • Vollständiges 64-Bit-Layout:
  • [Bit 0]: Selektorfeld (1 Bit; Wert 0 oder 1).
  • [Bit 1..31]: Dynamischer Anteil 1 (31 Bit, gemappt aus PduB oder PduC).
  • [Bit 32..47]: Statischer Anteil (16 Bit, immer gemappt aus PduA).
  • [Bit 48..63]: Dynamischer Anteil 2 (16 Bit, gemappt aus PduB oder PduC).

3. Dynamisches Verhalten & Sequenzablauf

  • Sende-Pfad (TX / Interaktion COM $\rightarrow$ PduR $\rightarrow$ IpduM $\rightarrow$ CanIf):
  1. Com übergibt Signaldaten via PduR_IpduMTransmit() für PduA, PduB oder PduC.
  2. IpduM puffert den Inhalt des statischen Segments (PduA).
  3. Bei Eintreffen eines Sende-Triggers für eine dynamische PDU (PduB oder PduC):
  • IpduM setzt das Selektor-Bit an Position 0 (0 für PduB, 1 für PduC).
  • IpduM zerlegt die Nutzdaten der dynamischen PDU und serialisiert sie in dynamicSegment1 (Bit 1..31) und dynamicSegment2 (Bit 48..63).
  • IpduM fügt den aktuellen statischen Pufferinhalt von PduA in Bit 32..47 ein.
  1. Die aggregierte MuxPdu (64 Bit) wird via CanIf_Transmit() an den Bustreiber übergeben.
  • Empfangs-Pfad (RX / Interaktion CanIf $\rightarrow$ PduR $\rightarrow$ IpduM $\rightarrow$ PduR $\rightarrow$ COM):
  1. CanIf_RxIndication() meldet den Empfang der MuxPdu.
  2. IpduM wertet das Selektorfeld an Bit-Offset 0 aus:
  • Bit 0 == 0: Segmente 1 und 2 werden zusammengefügt und als PduB via PduR_IpduMRxIndication() an Com weitergeleitet.
  • Bit 0 == 1: Segmente 1 und 2 werden zusammengefügt und als PduC via PduR_IpduMRxIndication() an Com weitergeleitet.
  1. Unabhängig vom Selektorwert extrahiert IpduM Bit 32..47 und meldet diese stets als PduA an Com weiter.

4. Normative Relevanz & Entwickler-Hinweise

  • ARXML-Konformität: Zur Konfiguration einer MultiplexedIPdu müssen im AUTOSAR System Template Instanzen von SegmentPosition angelegt werden, die disjunkte Bitbereiche definieren. Die Summe aller Segmente zuzüglich des Selektorfeldes darf die definierte Gesamtlänge der PDU (length = 64) nicht überschreiten. Die Nutzdaten-PDUs werden als Typ ISignalIPdu modelliert.
  • BSW-Konfiguration (IpduM):
  • IpduMTxPathway: Konfiguration definiert einen statischen PDU-Pfad (PduA) und alternative dynamische PDU-Pfade (PduB, PduC).
  • IpduMTxConfirmation: Konfigurationsparameter bestimmen, ob Bestätigungen für dynamische oder statische Sub-PDUs zurück an COM gemeldet werden.
  • Layout-Restriktionen: Das Selektorfeld liegt an Bit 0 und ist 1 Bit breit; dadurch sind genau zwei Multiplex-Alternativen (selectorFieldCode = 0 und 1) adressierbar. Die Segmentierung über zwei getrennte Blöcke (1..31 und 48..63) erfordert vom IpduM-Modul die Unterstützung fragmentierter Segment-Mappings.

System Template AUTOSAR CP Release 4.3.1 Figure 6.24 shows an example of an IPdu Multiplexer. The static part of the multiplexed IPdu contains ComIPduA. The value of the selector field in the dynamic part decides which content is transmitted. ComIPduB is transmitted if the selector field value is "0". ComIPduC is transmitted if the selector field value is "1". The static and the dynamic part can consist of more than one element. These sub parts of the static or dynamic parts are called segments. In Figure 6.24 the dynamic Part is segmented into two parts. More details can be found in [21].
