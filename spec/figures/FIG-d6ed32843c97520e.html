1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm der AUTOSAR ECU Configuration Specification (BSW Metamodell nach EcucParamConfContainerDef / EcucReferenceDef).
  • Technischer Zweck: Spezifiziert die statische Metamodell-Struktur des zentralen Konfigurationscontainers DemGeneral im Diagnostic Event Manager (DEM) (AUTOSAR Classic Platform, Schicht: System Services).
  • Funktionale Einordnung: Definiert die globale Wiederverwendung von Deskriptor-Klassen zur Laufzeit-Erfassung von Diagnosedaten:
  • Entkopplung und Kapselung von Snapshot-Daten (Freeze Frames) und herstellerspezifischen Zusatzdaten (Extended Data Records).
  • Strukturierung von Data Identifiers (DIDs) und deren atomaren Datenelementen.
  • Verknüpfung von Überwachungsquoten (In-Use Monitor Performance Ratios / IUMPR) mit Diagnose-Events und Steuerungsfunktionen des Function Inhibition Managers (FiM via FiMFID).

2. Komponenten, Entitäten & Schnittstellen

#### Metamodell-Container (EcucParamConfContainerDef / EcucChoiceContainerDef)

  • DemGeneral [1..1]: Root-Container für globale, modulweite DEM-Konfigurationsparameter.
  • DemRatio [0..65535] (Subcontainer von DemGeneral): Definiert IUMPR-Verhältnisse (OBD-II / WWH-OBD) zur Überwachung von Diagnosemonitoren (Numerator-/Denominator-Berechnung).
  • DemFreezeFrameClass [0..65535] (Subcontainer von DemGeneral): Schablone für Schnappschuss-Datenstrukturen, die bei Fehlereintritt persistiert werden.
  • DemDidClass [0..65535] (Subcontainer von DemGeneral): Repräsentiert einen Diagnose-Identifier (DID gemäß ISO 14229-1 / UDS 0x22).
  • DemDataElementClass [0..65535] (Subcontainer von DemGeneral, Typ: EcucChoiceContainerDef): Polymorpher Container zur Definition atomarer Datenfelder (z. B. interne DEM-Werte wie Betriebsspannung oder externe Applikationssignale via RTE/CS-Interface).
  • DemExtendedDataClass [0..65535] (Subcontainer von DemGeneral): Aggregationsbehälter für herstellerspezifische Zustandsparameter (z. B. Alterungszähler, Trip-Counter).
  • DemExtendedDataRecordClass [0..253] (Subcontainer von DemGeneral): Konkreter Teildatensatz innerhalb der Extended Data (Record-Nummer 0x01–0xFD).
  • DemEventParameter [1..65535]: Repräsentiert ein konkretes Diagnoseereignis (Event-ID/DTC-Instanz).
  • DemIndicatorAttribute [0..255] (Subcontainer von DemEventParameter): Konfiguration von Warnanzeigen/MIL-Aktivierungskriterien (Blinkmuster, Schwellenwerte) für das Event.
  • FiMFID [1..*]: Fremdcontainer aus dem FiM-Modul; logischer Funktionsbezeichner zur Deaktivierung/Hemmung von Software-Funktionalitäten.

#### Konfigurations-Referenzen (EcucReferenceDef)

  • DemFunctionIdRef [0..] (an DemRatio)*: Ziel FiMFID. Eigenschaft: requiresSymbolicNameValue = true. Bindet Ratio-Monitore an FiM-Funktionsschalter.
  • DemDiagnosticEventRef [1..1] (an DemRatio): Ziel DemEventParameter. Ordnet das Ratio-Tracking exakt einem Diagnoseereignis zu.
  • DemDidClassRef [1..255] (an DemFreezeFrameClass): Ziel DemDidClass. Eigenschaft: requiresIndex = true. Aggregiert DIDs in einen Freeze Frame unter strikter Reihung.
  • DemDidDataElementClassRef [1..255] (an DemDidClass): Ziel DemDataElementClass. Eigenschaft: requiresIndex = true. Definiert das Bytelayout eines DIDs aus Datenelementen.
  • DemFreezeFrameClassRef [0..1]: Ziel DemFreezeFrameClass. Verknüpft ein Event (DemEventParameter) mit seiner Snapshot-Struktur.
  • DemExtendedDataRecordClassRef [1..253] (an DemExtendedDataClass): Ziel DemExtendedDataRecordClass. Eigenschaft: requiresIndex = true. Sortierte Zuordnung von Records zu einem Extended-Data-Set.
  • DemExtendedDataClassRef [0..1]: Ziel DemExtendedDataClass. Verknüpft ein Event (DemEventParameter) mit seinem Extended-Data-Profil.

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Konfigurationsmetamodell besitzt das Diagramm keine Laufzeitzeitleiste, erzwingt jedoch folgende deterministische Ablauflogiken im generierten BSW-Code:

```

[Dem_SetEventStatus] ──> Event Qualified (PASSED/FAILED)

│

┌───────────────────────┴───────────────────────┐

▼ ▼

[Capture FreezeFrame] [Capture ExtendedData]

│ │

├─ Iteriere DemDidClassRef [Index 1..n] └─ Iteriere DemExtendedDataRecordClassRef [Index 1..n]

│ └─ Iteriere DemDidDataElementClassRef └─ Lese Datenquellen via DemDataElementClass

│ └─ Lese Daten via RTE (S/R, C/S) └─ Kopiere in Event Memory Entry

└─ Serialisiere DIDs in NvM-Puffer

```

  • Synchroner/Asynchroner Lese-Pfad: Bei Eintritt eines Trigger-Zustands (TEST_FAILED, Bestätigung etc.) liest der DEM die konfigurierten DemDataElementClass-Instanzen aus (zyklisch gepuffert oder on-demand via RTE-Ports).
  • Serialisierung via Index: Die Attribute requiresIndex = true erzwingen zur Generierungszeit eine feste Offset-Tabelle im Flash. Die Datenerfassung erfolgt sequenziell strikt nach Index, um das geforderte UDS-Payload-Layout (ISO 14229 Service 0x19 0x04 / 0x06) jitterfrei zu garantieren.
  • Ratio-Tracking & FiM-Interaktion:
  • Monitorstatus-Änderungen an DemEventParameter triggern über DemRatio das Inkrementieren von Numerator/Denominator.
  • Gleichzeitig inhibiert der FiM über FiMFID bei Fehlerbedingungen das Ausführen der zugeordneten Monitorfunktion, wodurch das Ratio-Tracking unterdrückt wird.

4. Normative Relevanz & Entwickler-Hinweise

  • Multiplizitätsgrenzen nach Diagnose-Standards:
  • DemExtendedDataRecordClass ist hart auf 253 limitiert (0x01–0xFD). Die Record-Nummern 0xFE (OBD Freeze Frame / DTC Fault Detection Counter) und 0xFF (Request for all Records) sind gemäß UDS ISO 14229 / SAE J1979 reserviert und dürfen nicht im Metamodell konfiguriert werden.
  • Index-Integrität (requiresIndex = true):
  • Konfigurationswerkzeuge (EB tresos, DaVinci Configurator etc.) müssen lückenlose Indizes (0, 1, 2, ...) generieren. Eine fehlerhafte Indizierung führt zu ungültigen Offsets bei der Serialisierung von DIDs und Freeze Frames.
  • Speicher-Footprint (RAM/ROM-Optimierung):
  • Die Definition von DemFreezeFrameClass, DemDidClass und DemExtendedDataClass unterhalb von DemGeneral erzwingt das Architekturmuster der Flyweight-Deskriptoren: Hunderte von DemEventParameter können auf dieselbe DemFreezeFrameClass referenzieren. Entwickler dürfen Deskriptoren nicht pro Event duplizieren, sondern müssen generische Klassen teilen, um Flash-Overhead in den Konstanten-Tabellen (Dem_PBcfg.c / Dem_Cfg.c) zu minimieren.
  • Symbolic Name Values:
  • Für DemFunctionIdRef ist requiresSymbolicNameValue = true verpflichtend. Der BSW-Generator generiert hieraus C-Makros (z. B. FiMConf_FiMFID_<Name>), wodurch Compile-Time-Type-Checking zwischen DEM und FiM sichergestellt wird.
