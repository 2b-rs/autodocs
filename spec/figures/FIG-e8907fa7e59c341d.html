3. Dynamisches Verhalten & Sequenzablauf

Aus den Port-Charakteristika ergeben sich die Ausführungs- und Interaktionspfade für das interne Verhalten (SwcInternalBehavior):

  1. Initialisierungs- & Startphase:
    • Auswertung des Initialwerts an Calibration (Zugriff auf ROM/RAM-Parameter).
    • Wiederherstellung der letzten Betriebszustände über den nv-Port (RTE-Zugriff auf NvM-RAM-Mirror via Read/Restore).
  2. Zyklische / Ereignisgesteuerte Betriebsüberwachung:
    • Trigger: TimingEvent (z. B. 10 ms/50 ms zyklisch) oder DataReceivedEvent auf SeatSwitch und PowerManagement.
    • Modus-Prüfung: Prüfung des ecuMode. Ist der ECU-Zustand ungleich RUN (z. B. POST_RUN oder SLEEP), unterbindet die interne Logik die Heizungsansteuerung sofort (ModeSwitchEvent als Abbruchbedingung).
    • Logische Verknüpfung: Heizbetrieb wird nur freigegeben, wenn: $$\text{SeatSwitch} == \text{OCCUPIED} \quad \land \quad \text{PowerManagement} == \text{ENABLE} \quad \land \quad \text{ecuMode} == \text{RUN}$$
  3. Stellgrößenberechnung & Aktuator-Ansteuerung:
    • Synchroner Client-Aufruf: Über den Client-Port HeatingElement wird synchron die Stellgröße an die Treiber-/Aktuator-Schicht übergeben (Rte_Call_HeatingElement_<Operation>(powerLevel)).
    • Rückmeldekontrollpfad: Asynchrones/zyklisches Schreiben des aktuellen Schaltzustands an DialLED (Rte_Write_DialLED_<dataElement>(ledState)).
  4. Parameteränderung & Deaktivierung:
    • Externe Parameteränderung über Setting führt via OperationInvokedEvent zur Neuberechnung der Soll-Temperatur.
    • Bei Statuswechsel von SeatSwitch auf EMPTY oder PowerManagement auf INHIBIT erfolgt ein unmittelbarer Abschaltaufruf an HeatingElement.

4. Normative Relevanz & Entwickler-Hinweise

  • RTE-API-Vertrag (Generierte Schnittstellen):
    • SeatSwitch, DialLED, PowerManagement generieren Standard-S/R-Makros: Rte_Read_<p>_<d>() bzw. Rte_Write_<p>_<d>(). Pufferung (queued vs. unqueued) richtet sich nach dem XML-Attribut swImplPolicy.
    • HeatingElement: Generiert blockierende bzw. nicht-blockierende Aufrufe: Std_ReturnType Rte_Call_HeatingElement_<Op>(...). Der Return-Wert muss zwingend auf RTE_E_OK bzw. anwendungsspezifische Fehler geprüft werden.
    • Calibration: Generiert Direktzugriffe (Rte_Prm_*() bzw. Rte_CData_*()), optimiert als RAM-Mirror oder ROM-Konstante.
    • ecuMode: Generiert Mode-Abfragen via Rte_Mode_ecuMode_<modeGroup>() sowie direkte Mode-Dispatches auf Runnable Entities.
    • nv: Nutzt den standardisierten AUTOSAR NvData-Mechanismus (Rte_Read_nv_<d>() / Rte_Write_nv_<d>()) unter Synchronisation mit dem NvM-Mirror.
  • Integrations- & Allokations-Restriktionen:
    • Inter- vs. Intra-ECU: Werden SeatSwitch oder PowerManagement über Bussysteme (CAN/LIN/Ethernet) empfangen, konfiguriert der Integrator Signal-zu-DataElement-Mappings im COM-Stack; die SWC-Implementierung bleibt auf C-Code-Ebene vollständig identisch.
    • BSW-Kopplung: ecuMode und nv erfordern zwingende Service-Mappings (ServiceProxySwComponent / ServiceInstance) gegen BswM und NvM im ECU-Extract (ECUC).
    • Speicher- und Concurrency-Schutz: Der Zugriff auf nv und HeatingElement erfordert im Multicore-Betrieb OS-Ressourcen oder RTE-exklusive Bereiche (ExclusiveArea), falls Runnables unterschiedlichen OS-Tasks oder Cores zugeordnet werden.

Virtual Functional Bus AUTOSAR CP R25-11 3 Overall mechanisms and concepts 3.1 Components The central structural element used when building a system at the VFB-level is the "component". A component has well-defined "ports", through which the component can interact with other components. A port always belongs to exactly one component and represents a point of interaction between a component and other components. Figure 3.1 shows an example of the definition of a component-type called "SeatHeating Control", which controls the heating element in a seat based on several information sources. In this example, the component-type requires the following information as input: • whether a passenger is sitting on the seat (through the port "SeatSwitch") • the setting of the seat temperature dial (through the port "Setting") • and some information from a central power management system (through the port "PowerManagement"), which could decide to disable seat heating in certain conditions. It controls • the DialLED that is associated with the seat temperature dial (port "DialLED") • and the heating element (through the port "HeatingElement"). Finally, the component can be calibrated (port "Calibration"), needs the status of the ECU on which the component runs (port "ecuMode") and requires access to local nonvolatile memory (port "nv").
