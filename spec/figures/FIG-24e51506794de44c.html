1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm zur Definition des AUTOSAR ECU-Konfigurations-Metamodells (ECUC Parameter Configuration Definition).
  • Technischer Zweck: Das Diagramm spezifiziert den Konfigurations-Container J1939RmRteUser innerhalb des BSW-Moduls J1939Rm (SAE J1939 Request Manager, AUTOSAR Classic Platform, Schicht: Communication Services).
  • Funktionale Einordnung: Der Container steuert die Schnittstellengenerierung zwischen dem J1939 Request Manager und der AUTOSAR-Laufzeitumgebung (RTE). Er definiert, welche Port-Interfaces (Client-Server / Sender-Receiver) für Software-Components (SW-Cs) instanziiert werden, um J1939-Requests (PGN 59904 / 0xEA00) und Acknowledgements (PGN 59392 / 0xE800) bidirektional zu verarbeiten sowie Timeouts zu überwachen.

2. Komponenten, Entitäten & Schnittstellen

Container-Definition
  • J1939RmRteUser (EcucParamConfContainerDef):
    • Kardinalität: lowerMultiplicity = 0, upperMultiplicity = 1 (optional; modulweit existiert maximal genau eine RTE-Nutzer-Konfiguration).
Parameter-Definitionen (aggregiert via +parameter Komposition)
  1. J1939RmUserId (EcucIntegerParamDef):
    • Multiplizität: [0..1], Wertebereich: 0 bis 254 (uint8).
    • Attribut symbolicNameValue = true: Dient als Bezeichner zur Generierung von C-Präprozessor-Symbolen für den RTE-User-Handle.
  2. J1939RmUserRequestPGN (EcucIntegerParamDef):
    • Multiplizität: [0..*] (Array / Liste), Wertebereich: 0 bis 262143 (0x00000–0x3FFFF, 18-Bit-J1939-PGN-Adressraum).
    • Definiert die Menge aller PGNs, für die dieser RTE-User Request-Meldungen empfangen und verarbeiten darf.
  3. J1939RmUserAckPGN (EcucIntegerParamDef):
    • Multiplizität: [0..*], Wertebereich: 0 bis 262143 (18 Bit PGN).
    • Definiert die Menge aller PGNs, für die Acknowledgements (ACK/NACK/Access Denied/Cannot Respond) an diesen RTE-User geroutet werden.
  4. J1939RmUserRequestIndication (EcucBooleanParamDef):
    • Multiplizität: [1..1]. Aktiviert/deaktiviert die RTE-Indikationsschnittstelle für eingehende Requests.
  5. J1939RmUserAckIndication (EcucBooleanParamDef):
    • Multiplizität: [1..1]. Aktiviert/deaktiviert die RTE-Indikationsschnittstelle für eingehende ACKs.
  6. J1939RmUserSendRequest (EcucBooleanParamDef):
    • Multiplizität: [1..1]. Aktiviert/deaktiviert die RTE-Schnittstelle zum aktiven Absetzen von PGN-Requests durch SW-Cs.
  7. J1939RmUserSendAck (EcucBooleanParamDef):
    • Multiplizität: [1..1]. Aktiviert/deaktiviert die RTE-Schnittstelle zum Senden von Acknowledgement-Nachrichten.
  8. J1939RmUserTimeoutSupervision (EcucBooleanParamDef):
    • Multiplizität: [1..1]. Schaltet die Überwachung der Antwortzeit (gemäß SAE J1939-21 Timeouts T_2 / T_3) für ausgehende Anfragen dieses Nutzers frei.

3. Dynamisches Verhalten & Sequenzablauf

Die Parameter determinieren die Codegenerierung für folgende Laufzeitpfade:

[CAN-Bus] --> [CanIf / PduR / J1939Tp] --> [J1939Rm] --(RTE Service Ports)--> [SW-C]
                                              |
                     +------------------------+------------------------+
                     | Filterung: PGN in RequestPGN / AckPGN ?         |
                     | Prüfung: Indication-Flags gesetzt (TRUE) ?      |
                     | Supervision: Timeout-Timer aktiv / abgelaufen ?  |
                     +-------------------------------------------------+
  • Eingehende Requests:
    • J1939Rm empfängt eine Request-PDU (PGN 0xEA00).
    • Ist J1939RmUserRequestIndication == TRUE und die im Datenfeld angefragte PGN in J1939RmUserRequestPGN enthalten, erfolgt ein asynchroner Aufruf des konfigurierten RTE-Indication-Ports an die SW-C.
  • Eingehende Acknowledgements:
    • J1939Rm empfängt PGN 0xE800. Entspricht die referenzierte PGN einem Eintrag in J1939RmUserAckPGN und ist J1939RmUserAckIndication == TRUE, wird der Status (ACK, NACK, Access Denied, Cannot Respond) an die SW-C weitergeleitet.
  • Ausgehende Requests / ACKs:
    • SW-C ruft Server-Operationen am RTE-Service-Port auf (bedingt durch J1939RmUserSendRequest bzw. J1939RmUserSendAck). J1939Rm baut die PDU auf und übergibt sie an PduR/CanIf.
  • Timeout-Supervision:
    • Bei J1939RmUserTimeoutSupervision == TRUE startet J1939Rm beim Senden eines Requests einen internen Countdown-Timer. Läuft dieser vor Empfang einer Antwort oder eines ACK/NACK ab, meldet J1939Rm einen Timeout-Fehlerstatus über die RTE an die SW-C.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW- und RTE-Codegenerierung:
    • Die Präsenz des Containers generiert die ServiceComponentTemplate im ARXML des J1939Rm für den RTE-Generator.
    • Die Boolean-Schalter (J1939RmUserSend*, J1939RmUser*Indication) schalten ungenutzte Schnittstellen per Präprozessor (#if (J1939RM_USER_SEND_REQUEST == STD_ON)) ab, um ROM/RAM-Footprint und ungenutzte RTE-Stubs zu minimieren.
  • Speicher- und Typlayout:
    • J1939RmUserRequestPGN und J1939RmUserAckPGN erfordern im generierten C-Code aufgrund des 18-Bit-Bereichs (bis 262143) zwingend uint32 als Datentyp (typedef uint32 J1939Rm_PgnType).
    • Multiplizität 0..* resultiert in ROM-Arrays mit PGN-Listen. Ein linearer Scan oder binäre Suche entscheidet im RX-Pfad über das Routing zur RTE; bei großen PGN-Listen hat dies direkten Einfluss auf die Interrupt-/MainFunction-Laufzeit.
  • Einschränkung (upperMultiplicity = 1):
    • Es kann im Gesamtsystem maximal ein SW-C-orientierter RTE-User im J1939Rm konfiguriert werden. Benötigen mehrere Anwendungs-SW-Cs Zugriff auf J1939-Requests/ACKs, muss die Verteilung über eine vorgelagerte Gateway-/Dispatcher-SW-C oder über separate BSW-User-Module erfolgen.
