1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Sequenzdiagramm (Interaktionsdiagramm).
  • Technischer Zweck: Spezifikation des Fehler- und Laufzeitverhaltens des AUTOSAR Classic Platform MCAL ADC-Treibers (Adc) bei gleichzeitigen/überlappenden Konvertierungsanforderungen unter den Randbedingungen:
    • AdcPriorityImplementation = ADC_PRIORITY_NONE
    • AdcEnableQueuing = FALSE (kein Puffer-/Warteschlangenmechanismus aktiv)
  • Funktionale Einordnung: Veranschaulichung der strikten Nicht-Wiedereintrittsfähigkeit einer Hardware-ADC-Konvertierungseinheit (ADC Conversion Unit). Zeigt das deterministische Zurückweisen kollidierender Software- (Adc_StartGroupConversion) und Hardware-Trigger-Anfragen (Adc_EnableHardwareTrigger) via Default Error Tracer (Det).

2. Komponenten, Entitäten & Schnittstellen

  • Akteure & Lifelines:
    • Adc User: Aufrufende BSW-Komponente (z. B. IoHwAb, Complex Driver / CDD) oder SWC via RTE.
    • «module» Adc: MCAL ADC-Treiberkomponente (stateless/stateful Treiberinstanz nach AUTOSAR SWS ADC).
    • «module» Det: Default Error Tracer zur Meldung von Runtime-/Entwicklungsfehlern.
    • «Peripheral» ADC Conversion Unit: Physisches On-Chip-ADC-Wandlerwerk / SAR-/Sigma-Delta-Hardwareblock.
    • «Peripheral» HW Trigger Source: Externe oder interne Timer-/Capture-Trigger-Quelle (z. B. eMIOS, GTM, GPT).
  • Schnittstellen & Operationen:
    • Adc_EnableGroupNotification(Group_x): Konfiguriert den Callback-Mechanismus für Konvertierungsende.
    • Adc_StartGroupConversion(Adc_GroupType Group): Synchroner API-Trigger für softwaregestartete Gruppenwandlungen.
    • Adc_EnableHardwareTrigger(Adc_GroupType Group): Schärft die Hardware-Trigger-Erkennung für eine Konvertierungsgruppe.
    • Det_ReportRuntimeError(uint16 ModuleId, uint8 InstanceId, uint8 ApiId, uint8 ErrorId): Übergabe von ADC_E_BUSY (Fehlercode 0x1B).
    • Adc_Notification_Group_1(): Konfigurierter Anwender-Notification-Callback nach Wandlungsende.
  • Hardware-Schnittstellen (Treiber-intern / Register-Ebene):
    • start conversion(Group1): Start-Trigger an HW-Register der Konvertierungseinheit.
    • conversion completed(Group1): HW-Interrupt (ISR) signalisiert Abschluss.
    • enable hardware trigger(Group3): Routing/Konfiguration der HW-Trigger-Leitung zur Wandlungseinheit.

3. Dynamisches Verhalten & Sequenzablauf

Phase 1: Vorbereitung & reguläre Software-Konvertierung
  1. Adc User schaltet Notifications scharf via Adc_EnableGroupNotification().
  2. Adc User ruft Adc_StartGroupConversion(Group1) auf.
  3. Adc stößt die Wandlung im Peripheriemodul an (start conversion(Group1)). Die Wandlungseinheit wechselt in den Zustand BUSY.
Phase 2: Kollisionsbehandlung bei laufender Wandlung (ADC_E_BUSY)
  1. Kollision SW/SW: Während Group1 wandelt, setzt Adc User Adc_StartGroupConversion(GroupX) ab. Da Queuing = OFF und Priority = NONE, kann die Anfrage weder gepuffert noch priorisiert verdrängt werden. Adc meldet Det_ReportRuntimeError(ADC_E_BUSY) und verwirft den Request.
  2. Kollision SW/HW: Adc User versucht Adc_EnableHardwareTrigger(GroupY). Die Wandlungseinheit ist weiterhin durch Group1 blockiert. Adc meldet erneut Det_ReportRuntimeError(ADC_E_BUSY) an den Det.
Phase 3: Abschluss & Benachrichtigung
  1. ADC Conversion Unit feuert den Completion-Interrupt conversion completed(Group1).
  2. Adc führt den Callback Adc_Notification_Group_1() synchron/im ISR-Kontext an den Adc User aus. Die Konvertierungseinheit wechselt zurück in den Status IDLE.
Phase 4: HW-Trigger-Aktivierung & Verriegelung
  1. Adc User schärft eine HW-Gruppe: Adc_EnableHardwareTrigger(Group3). Der Trigger wird in der Peripherie parametriert. Die Einheit gilt ab diesem Zeitpunkt als exklusiv reserviert/belegt.
  2. Kollision HW/HW: Ein weiterer Aufruf Adc_EnableHardwareTrigger() wird mit Det_ReportRuntimeError(ADC_E_BUSY) abgelehnt.
  3. Kollision HW/SW: Ein Versuch, eine SW-Wandlung über Adc_StartGroupConversion() zu starten, wird analog mit Det_ReportRuntimeError(ADC_E_BUSY) abgewiesen.

4. Normative Relevanz & Entwickler-Hinweise

  • Zustandsmodell-Restriktion: Bei ADC_PRIORITY_NONE und deaktiviertem Queuing (AdcEnableQueuing == FALSE) schließen sich Software-Konvertierungen und Hardware-Trigger auf derselben ADC Conversion Unit strikt gegenseitig aus.
  • Fehlerklassifikation: Die Zurückweisung erfolgt normativ als Runtime-Error (ADC_E_BUSY). In Produktions-Builds ohne aktiven Det-Hook führt ein solcher Aufruf zu stillem Verwerfen der Wandlungsanfrage, wenn der Return-Wert der Funktion nicht geprüft wird bzw. die API laut SWS void liefert.
  • Design-Konsequenzen für Embedded-Entwickler:
    • Statusprüfung: Vor Aufruf von Adc_StartGroupConversion oder Adc_EnableHardwareTrigger muss die Applikation/SWC den Zustand über Adc_GetGroupStatus() prüfen (ADC_IDLE), um Kollisionen zu vermeiden.
    • HW-Trigger-Freigabe: Eine mit Adc_EnableHardwareTrigger() belegte Konvertierungseinheit bleibt für andere Gruppen blockiert, bis der Trigger explizit mittels Adc_DisableHardwareTrigger() deaktiviert wird oder die konfigurierte Wandlungssequenz vollständig beendet ist.
    • Multi-Group-Betrieb: Sollen mehrere Gruppen dieselbe HW-Unit nutzen, erfordert dies zwingend entweder die Konfiguration von ADC_PRIORITY_HW / ADC_PRIORITY_HW_SW oder die Aktivierung von AdcEnableQueuing = TRUE.
