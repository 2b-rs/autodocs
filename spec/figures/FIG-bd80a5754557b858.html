1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration Metamodell (ECUC) Klassendiagramm / Konfigurationsmetamodell-Ausschnitt (UML-basiert).
  • Technischer Zweck: Spezifikation der Konfigurationsstruktur zur Anbindung des Diagnostic Communication Managers (DCM) an den Intrusion Detection System Manager (IdsM) gemäß AUTOSAR Security Event Reporting.
  • Architektur-Einordnung: BSW-Diagnose- und Security-Schicht. Das Metamodell definiert die Zuordnung standardisierter UDS-Sicherheitsereignisse (Security Events) auf IdsM-Ereignis-Definitionen (IdsMEvent), um sicherheitskritische Diagnoseaktivitäten an die On-Board-Angriffserkennung zu melden.

2. Komponenten, Entitäten & Schnittstellen

Container
  • DcmSecurityEventRefs (EcucParamConfContainerDef [0..1]):
    • Konfigurationscontainer zur Kapselung der IdsM-Event-Referenzen des DCM.
  • IdsMEvent (EcucParamConfContainerDef [1..65535]):
    • Ziel-Container (+destination) aus dem Metamodell des IdsM (/AUTOSAR/EcucDefs/IdsM/IdsMEvent), der eine konkrete Sicherheitsereignis-Definition im Intrusion Detection System Manager repräsentiert.
Referenzen (EcucReferenceDef)

Alle Referenzen werden von DcmSecurityEventRefs via Komposition (+reference) mit Kardinalität [0..1] und der Eigenschaft requiresSymbolicNameValue = true aggregiert und verweisen via +destination auf IdsMEvent. Die Konfiguration ist nach Erfolgs- (SUCCESSFUL) und Fehlerfällen (FAILED) strukturiert:

  1. SEV_UDS_COMMUNICATION_CONTROL_SUCCESSFUL: Referenziert das IdsM-Event bei erfolgreicher Ausführung von UDS-Service 0x28 (CommunicationControl).
  2. SEV_UDS_COMMUNICATION_CONTROL_FAILED: Referenziert das IdsM-Event bei fehlgeschlagener Ausführung von UDS-Service 0x28 (CommunicationControl).
  3. SEV_UDS_CLEAR_DTC_SUCCESSFUL: Referenziert das IdsM-Event beim erfolgreichen Löschen von Diagnoseinformationen via UDS-Service 0x14 (ClearDiagnosticInformation).
  4. SEV_UDS_CLEAR_DTC_FAILED: Referenziert das IdsM-Event bei fehlgeschlagenem Löschen von Diagnoseinformationen via UDS-Service 0x14 (ClearDiagnosticInformation).
  5. SEV_UDS_CONTROL_DTC_SETTING_SUCCESSFUL: Referenziert das IdsM-Event bei erfolgreicher Steuerung der DTC-Eintragung via UDS-Service 0x85 (ControlDTCSetting).
  6. SEV_UDS_CONTROL_DTC_SETTING_FAILED: Referenziert das IdsM-Event bei fehlgeschlagener Steuerung der DTC-Eintragung via UDS-Service 0x85 (ControlDTCSetting).
  7. SEV_UDS_ECU_RESET_SUCCESSFUL: Referenziert das IdsM-Event bei erfolgreicher Ausführung eines Steuergeräteresets via UDS-Service 0x11 (ECUReset).
  8. SEV_UDS_ECU_RESET_FAILED: Referenziert das IdsM-Event bei fehlgeschlagenem Steuergerätereset via UDS-Service 0x11 (ECUReset).
  9. SEV_UDS_ROUTINE_CONTROL_SUCCESSFUL: Referenziert das IdsM-Event bei erfolgreicher Steuerung einer Routine via UDS-Service 0x31 (RoutineControl).
  10. SEV_UDS_ROUTINE_CONTROL_FAILED: Referenziert das IdsM-Event bei fehlgeschlagener Steuerung einer Routine via UDS-Service 0x31 (RoutineControl).
  11. SEV_UDS_IO_CONTROL_SUCCESSFUL: Referenziert das IdsM-Event bei erfolgreicher E/A-Steuerung via UDS-Service 0x2F (InputOutputControlByIdentifier).
  12. SEV_UDS_IO_CONTROL_FAILED: Referenziert das IdsM-Event bei fehlgeschlagener E/A-Steuerung via UDS-Service 0x2F (InputOutputControlByIdentifier).

3. Dynamisches Verhalten & Sequenzablauf

  • Trigger:
    • *_SUCCESSFUL: Erfolgreicher Abschluss der Diagnoseverarbeitung im DCM unmittelbar vor bzw. mit dem Senden der positiven UDS-Antwort (Positive Response).
    • *_FAILED: Abweisung bzw. fehlerhafte Beendigung einer Diagnoseanforderung (z. B. Ausgabe einer UDS Negative Response / NRCs wie ConditionsNotCorrect, RequestOutOfRange, SecurityAccessDenied).
  • Bedingungsprüfung:
    • Prüfung, ob die entsprechende EcucReferenceDef in DcmSecurityEventRefs instanziiert ist (Kardinalität 1).
    • Vorhandensein eines gültigen Ziel-Containers IdsMEvent.
  • Ablauf:
    • Tritt das Ereignis ein und ist konfiguriert, meldet der DCM dieses über die BSW-Schnittstelle des IdsM (IdsM_SetSecurityEvent(EventId, ...) bzw. IdsM_SetSecurityEventWithContextData(...)).
    • Als EventId wird der aus der Zielinstanz IdsMEvent generierte symbolische Bezeichner übergeben.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Relevanz: Spezifiziert die Metamodell-Struktur für das differenzierte Security Event Reporting von UDS-Diensten an den IdsM. Die explizite Unterscheidung von Erfolgs- und Fehlerfällen ermöglicht dem Intrusion Detection System die zielgerichtete Erkennung von Angriffsversuchen (z. B. Brute-Force- oder Scanning-Aktivitäten anhand gehäufter FAILED-Events).
  • Konfigurationshinweise:
    • Alle Referenzen sind optional (Multiplizität [0..1]), wodurch das Reporting granular pro Dienst und Resultat (Erfolg/Fehlschlag) geschaltet werden kann.
    • requiresSymbolicNameValue = true erzwingt eine konsistente Auflösung des Ziel-Symbols im IdsM für die typsichere Codegenerierung im BSW-Treiber.
