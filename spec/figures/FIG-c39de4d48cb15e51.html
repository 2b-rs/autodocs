1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm / Metamodell-Ausschnitt der AUTOSAR ECU-Konfigurationsparameter-Definition (ParamConfContainerDef, *ParamDef).
  • Architektur-Kontext: System Services Layer des AUTOSAR Classic BSW. Das Modell definiert die Konfigurationsstruktur des Moduls NvM (Non-Volatile Memory Manager) zur statischen Deklaration von NVRAM-Blöcken (NvmBlockDescriptor) und deren Bindung an die darunterliegenden Memory-Abstraction-Module Fee (Flash EEPROM Emulation) bzw. Ea (EEPROM Abstraction).

2. Komponenten, Entitäten & Schnittstellen

#### Zentraler Konfigurations-Container

  • NvmBlockDescriptor (ParamConfContainerDef):
  • Multiplizität: 1 .. 65536 (definiert die maximale Anzahl statisch konfigurierbarer NVRAM-Blöcke im NvM).

#### Enthaltene Parameter (+parameter, Aggregation via Komposition)

  • Verwaltung & Adressierung:
  • NvmNvramBlockIdentifier (IntegerParamDef): Eindeutige logische Block-ID (symbolicNameValue = true).
  • NvmBlockManagementType (EnumerationParamDef): Auswahl des Block-Verwaltungstyps über Literale (+literal):
  • NVM_BLOCK_NATIVE: Ein NV-Block, optional 1 ROM-Block, 1 RAM-Block.
  • NVM_BLOCK_REDUNDANT: Zwei identische NV-Blöcke für erhöhte Datensicherheit.
  • NVM_BLOCK_DATASET: Array von $N$ NV-Blöcken (und optional ROM-Blöcken), adressierbar über Dataset-Index.
  • NvmNvBlockNum (IntegerParamDef, min = 1, max = 255): Anzahl der NV-Blöcke (relevant bei DATASET).
  • NvmNvBlockLength (IntegerParamDef, min = 1, max = 65535): Nutzdatenlänge des Blocks in Bytes.
  • NvmRamBlockDataAddress (StringParamDef): Symbolische Adresse / C-Pointer auf den permanenten RAM-Mirror.
  • NvmRomBlockDataAddress (StringParamDef): Symbolische Adresse / C-Pointer auf Default-Daten im ROM/Flash.
  • Integrität & CRC-Prüfung:
  • NvmBlockUseCrc (BooleanParamDef): Aktiviert die CRC-Absicherung im persistenten Speicher.
  • NvmBlockCRCType (EnumerationParamDef): Auswahl des Algorithmus via Literale (+literal):
  • NVM_CRC16: 16-Bit CRC (Standard-Integritätsschutz).
  • NVM_CRC32: 32-Bit CRC (erweiterte Integrität).
  • NvmCalcRamBlockCrc (BooleanParamDef): Aktiviert Hintergrund-CRC-Berechnung im RAM-Spiegel zur Erkennung von RAM-Bitkippern/Verfälschungen.
  • Zugriffskontrolle, Verhalten & Scheduling:
  • NvmBlockWriteProt (BooleanParamDef): Initialer Schreibschutz auf Applikationsebene.
  • NvmWriteBlockOnce (BooleanParamDef): Block darf nach Erstbeschreiben nicht mehr überschrieben werden (z. B. Kalibrierdaten, FIN/VIN).
  • NvmResistantToChangedSw (BooleanParamDef): Verhindert das Überschreiben des persistenten Blocks mit ROM-Defaults bei Software-Versionswechseln.
  • NvmBlockJobPriority (IntegerParamDef, min = 0, max = 255): Priorität bei NvM-Queue-Aufträgen ($0$ = unmittelbare Priorität / Immediate-Write, $>0$ = Standard-Queue).
  • NvmSelectBlockForReadall (BooleanParamDef): Bindet den Block in den globalen Systemstart-Ablauf NvM_ReadAll() ein.
  • Callbacks:
  • NvmSingleBlockCallback (FunctionNameDef): Funktionsname für asynchrone Fertigstellungsmeldung einzelner Jobs (JobEndNotification).
  • NvmInitBlockCallback (FunctionNameDef): Callback bei fehlenden/korrupten Daten zur Laufzeitinitialisierung von Standardwerten im RAM.

#### Speicherabstraktions-Mapping (+subContainer, +choice)

  • NvmNvBlockBaseNumber (ChoiceContainerDef): Exklusive Auswahl (XOR) der Zielabstraktionsebene:
  • Zweig 1: FeeRef (ParamConfContainerDef, Multiplizität 0 .. 1):
  • Enthält NameOfFeeBlock (SymbolicNameReferenceDef), referenziert via +destination auf FeeBlockConfiguration (ParamConfContainerDef, Multiplizität 1 .. *, aus Package (from FEE)).
  • Zweig 2: EaRef (ParamConfContainerDef, Multiplizität 0 .. 1):
  • Enthält NameOfEaBlock (SymbolicNameReferenceDef), referenziert via +destination auf EaBlockConfiguration (ParamConfContainerDef, Multiplizität 1 .. *, aus Package (from EA)).

3. Dynamisches Verhalten & Sequenzablauf (Konfigurationsimplikationen)

  • Startup (NvM_ReadAll):
  • Blöcke mit NvmSelectBlockForReadall == TRUE werden während der Initialisierungsphase asynchron aus dem NV-Speicher in den RAM-Spiegel (NvmRamBlockDataAddress) geladen.
  • Bei Fehlschlag oder CRC-Fehler: Falls NvmRomBlockDataAddress konfiguriert ist, wird das ROM-Image kopiert; andernfalls wird NvmInitBlockCallback getriggert.
  • Asynchrone Auftragsabarbeitung:
  • Schreib-/Leseaufträge (NvM_ReadBlock, NvM_WriteBlock) werden über NvmBlockJobPriority in prioritätsbasierten Queues eingereiht.
  • Nach Abschluss des asynchronen Speicherzugriffs ruft der NvM den über NvmSingleBlockCallback deklarierten Funktionszeiger auf.
  • CRC-Validierungssequenz:
  • Bei gesetztem NvmBlockUseCrc: CRC wird beim Schreiben vor Übergabe an Fee/Ea berechnet und angehängt; beim Lesen verifiziert.
  • Bei gesetztem NvmCalcRamBlockCrc: Hintergrund-Prüfung im Task-Kontext (NvM_MainFunction()).

4. Normative Relevanz & Entwickler-Hinweise

  • Exklusivität Fee vs. Ea: Der ChoiceContainerDef (NvmNvBlockBaseNumber) erzwingt die Entscheidung pro Block für entweder FEE (Flash) oder EA (EEPROM). Eine Mischkonfiguration innerhalb eines einzelnen Blocks ist strukturell ausgeschlossen.
  • RAM/ROM-Pufferbindung: NvmRamBlockDataAddress und NvmRomBlockDataAddress sind als C-Symbolnamen (Strings) definiert. Werden diese auf NULL bzw. leer konfiguriert, muss die Applikation temporäre Puffer explizit über die API übergeben (NvM_ReadBlock(BlockId, NvM_DstPtr)).
  • Dataset-Dimensionierung: Bei NvmBlockManagementType == NVM_BLOCK_DATASET legt NvmNvBlockNum fest, wie viele Instanzen unterhalb der Basisnummer im FEE/EA adressiert werden. Der Adressoffset berechnet sich als BaseNumber + DatasetIndex.
  • Prioritätsinversion: Blöcke mit NvmBlockJobPriority = 0 unterbrechen laufende Standardaufträge (Immediate-Write). Nur für extrem zeitkritische NV-Daten (z. B. Crash-Daten) verwenden, da dies Schreibzyklen der zugrundeliegenden Flash-Treiber fragmentiert.
  • Metamodell-Historie (R2.1.20): Der Diagrammkommentar verweist auf Bug 11013 (12) und NVRAM Manager Spezifikation v2.0.0 (2006-04-28). Neuere AUTOSAR-Releases (ab R4.x) haben Parameterbezeichner refaktoriert (z. B. Präfix NvM... statt gemischter Groß-/Kleinschreibung wie Nvm... sowie Einführung von Pre-Compile/Post-Build-Varianten).
