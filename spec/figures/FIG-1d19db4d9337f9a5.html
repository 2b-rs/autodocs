  • Diagrammtyp: UML-Klassendiagramm zur Definition des AUTOSAR ECU Configuration Parameter Models (BSW Module Description / ECUC Metamodell).

3. Dynamisches Verhalten & Sequenzablauf

Nicht direkt zutreffend (statisches Metamodell/ECUC-Strukturdiagramm). Die abgebildeten Parameter steuern jedoch direkt das Laufzeitverhalten:

  • Scheduling/Trigger: FrTSynMainFunctionPeriod definiert die Zykluszeit des BSW-Schedulers (OS/SchM) für den Aufruf von FrTSyn_MainFunction().
  • Fehlerpfade: FrTSynDevErrorDetect == true leitet ungültige API-Parameteraufrufe oder Null-Pointer synchron an Det_ReportError().
  • Validierungs-Hooks: FrTSynTimeValidationSupport == true aktiviert synchrone Callouts/Ereignismeldungen zur Synchronisationsgenauigkeit an das Service-Modul Time Validation.
  • Sicherheitsüberwachung / Security Events: FrTSynEnableSecurityEventReporting == true aktiviert die Meldung sicherheitsrelevanter Vorfälle (wie fehlschlagende ICV-Generierung/-Verifikation oder fehlende Freshness) an das Intrusion Detection System Manager Modul (IdsM).

4. Normative Relevanz & Entwickler-Hinweise

  • Generierte Header & Pre-Compile-Schalter:
  • FrTSynDevErrorDetect, FrTSynVersionInfoApi, FrTSynTimeValidationSupport und FrTSynEnableSecurityEventReporting steuern Präprozessor-Makros (z. B. FRTSYN_DEV_ERROR_DETECT, FRTSYN_VERSION_INFO_API, FRTSYN_TIME_VALIDATION_SUPPORT, FRTSYN_ENABLE_SECURITY_EVENT_REPORTING als STD_ON/STD_OFF), wodurch Code-Footprint und ROM-Verbrauch optimiert werden.
  • API-Vertrag:
  • Ist FrTSynVersionInfoApi auf false gesetzt, darf FrTSyn_GetVersionInfo im Linker-Scope nicht exportiert werden; Aufrufer erhalten sonst undefinierte Symbole.
  • OS- und BSW-Scheduler-Konfiguration:
  • Der Wert von FrTSynMainFunctionPeriod muss strikt synchron mit dem Task-Zyklus in Os bzw. BswM/SchM konfiguriert werden; Abweichungen führen zu Berechnungsfehlern interner Timeout- und Sync-Zähler.
  • Metamodell-Restriktionen:
  • Jeder Konfigurationsdatensatz benötigt zwingend genau eine Instanz von FrTSynGeneral ([1..1]) und mindestens eine FrTSynGlobalTimeDomain ([1..*]). Fehlende Container führen zu Validierungsfehlern im AUTOSAR-Generator-Tooling.
  • Die Sicherheitsereignis-Referenzen in FrTSynSecurityEventRefs erfordern zwingend symbolische Namen (requiresSymbolicNameValue = true) und dürfen nur auf gültige Instanzen von IdsMEvent verweisen.
