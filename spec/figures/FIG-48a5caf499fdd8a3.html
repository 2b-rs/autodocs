3. Dynamisches Verhalten & Sequenzablauf

Aus der Metamodell-Konfiguration resultiert folgender normativer Laufzeit- und Datenfluss:

```

[ECU Startup]

│

▼

NvM_ReadAll() ───────► NvM RAM Mirror gefüllt (Port-Mirror-Config / ARL-Tabelle)

│

▼

EthSwt_Init() ───────► Liest RAM-Spiegel aus & programmiert Switch-Hardware-Register/ARL

│

[Laufzeit / Normalbetrieb]

│

MAC-Learning ────────► EthSwt aktualisiert ARL-Tabelle im RAM

│

NvM_SetRamBlockStatus(BlockId, TRUE) / NvM_WriteBlock(BlockId, ...) [asynchron]

│

▼

NvM Callback ────────► SingleBlockCallback informiert EthSwt über Schreibstatus

│

[ECU Shutdown]

│

▼

NvM_WriteAll() ──────► Persistierung modifizierter Blöcke im Flash/EEPROM via Mem-Stack

```

  • Startup/Restore: Beim Booten werden über die konfigurierten NvM-Blöcke persistierte Forwarding-Tabellen in den Switch-Controller geladen, um Kaltstart-Flooding (Broadcast von Unicast-Frames bei ungelernter Topologie) zu verhindern.
  • Laufzeit-Update (asynchron): Adressänderungen oder Mirror-Updates triggern NvM-Schreibanforderungen (NvM_WriteBlock). Der Switch-Treiber muss asynchron auf Job-Terminierung über Polling (NvM_GetErrorStatus) oder Callbacks reagieren.

4. Normative Relevanz & Entwickler-Hinweise

  • Puffer- und Alignment-Dimensionierung: Der für EthSwtTableNvmBlockDescriptorRef hinterlegte NvM-Block muss in seiner Bytegröße (NvMBlockLength) exakt mit der maximalen ARL-Tabellengröße der Switch-Hardware übereinstimmen. Fehlallokationen führen zu Pufferüberläufen oder unvollständiger Tabellenpersistierung.
  • Post-Build-Unterschied:
  • EthSwtConfigurationNvmBlockDescriptorRef ist nicht als Post-Build-Value variierbar (PB Variant Value = false).
  • EthSwtTableNvmBlockDescriptorRef besitzt PB Variant Value = true. Die ARL-Persistenz kann somit je nach Steuergerätevariante (z. B. Gateway vs. End-Node) dynamisch auf unterschiedliche NvM-Blöcke gemappt oder umkonfiguriert werden.
  • Flash-Endurance (Endurance-Management): Das Speichern von dynamisch gelernten ARL-Tabellen in Non-Volatile Memory birgt bei hochfrequentem Netzwerkverkehr das Risiko übermäßiger NVRAM-Schreibzyklen. Entwickler müssen im EthSwt Write-Trigger entprellen (z. B. Speichern nur bei Shutdown via NvM_WriteAll oder bei signifikanten Topologieänderungen).
  • Symbolische Adressierung: Da beide Parameter requiresSymbolicNameValue = true erzwingen, generiert der BSW-Konfigurator typsichere C-Makros (z. B. NvMConf_NvMBlockDescriptor_<Name>), die direkt als Parameter für NvM-Serviceaufrufe im Switch-Treiber zu verwenden sind. IDs < 2 sind strikt ungültig.
