1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Konzeptionelles Metamodell-Instanzdiagramm / Mapping-Semantikdiagramm (AUTOSAR Adaptive Platform M1/M2-Abstraktion).
  • Architektur-Kontext:
    • Spezifikation: AUTOSAR Adaptive Platform (AP), Release R22-11, AUTOSAR_TPS_ManifestSpecification, Kapitel 10 (System Manifest – Execution & State Management Mapping).
    • Funktionale Einordnung: Kopplung zwischen Execution Management (EM) bzw. State Management (SM) (repräsentiert durch FunctionGroup und FunctionGroupState) und dem Network Management (NM) (repräsentiert durch NmHandle).
    • Zweck: Visualisierung der normativen Semantik von [TPS_MANI_01365] (RS_MANI_00023). Es definiert die Zulässigkeit einer deklarativen N:1-Shortcut-Zuordnung mehrerer FunctionGroupState-Zustände aus identischen und unterschiedlichen FunctionGroup-Instanzen auf ein einziges logisches/physisches NM-Netzwerk-Handle (NmHandle).

2. Komponenten, Entitäten & Schnittstellen

  • Function Group „A“ & Function Group „B“:
    • Instanzen der Metaklasse ModeDeclarationGroupPrototype (formalisiert als Funktionsgruppen-Hierarchie im Machine-/Execution-Manifest).
    • Repräsentieren orthogonale Zustandsdomänen zur Prozesssteuerung auf einer Adaptive-Machine.
  • FunctionGroupState (FGS):
    • Konkrete Zustände (ModeDeclaration):
      • Gruppe A: FGS „A_1“ (grau), FGS „A_2“ (weiß), FGS „A_3“ (grau).
      • Gruppe B: FGS „B_1“ (weiß), FGS „B_2“ (grau), FGS „B_3“ (weiß).
    • Grau hinterlegte Entitäten markieren Zustände mit aktiver Netzwerkanforderung.
  • NmHandleToFunctionGroupStateMapping (ARXML-Mapping-Element):
    • Zentrales Konfigurationselement zur Interaktionssteuerung.
    • Attribut mappingDirection = functionGroupStateToNmHandle (NmHandleMappingDirectionEnum, Literal-Index 0).
    • Referenz functionGroupState: Multiplizität 1..* (erlaubt Multi-Target-Referenzierung).
    • Referenz nmHandle: Multiplizität 1 (Ziel-Netzwerkhandle).
  • „NMH_1“ (NmHandle):
    • Repräsentiert das Ziel-Netzwerk-Management-Handle (logischer Kanal, VLAN oder Partial Network Cluster im NM-Stack).
  • Beziehungen & Semantische Marker (👍):
    • Die drei grünen Daumen markieren normativ konforme Assoziationen:
      1. Intra-Gruppen-Bündelung: Zuweisung disjunkter Zustände derselben Gruppe (FGS „A_1“ und FGS „A_3“) an dasselbe Mapping.
      2. Inter-Gruppen-Bündelung: Zuweisung von Zuständen verschiedener Gruppen (FG „A“ und FG „B“) an dieselbe Mapping-Instanz.
      3. Shortcut-Funktionalität: Aggregation ohne Notwendigkeit redundanter Mapping-Instanzen.

3. Dynamisches Verhalten & Sequenzablauf

[State Management]               [Execution Management]             [Network Management (ara::nm)]
        |                                  |                                       |
        |--- FG Transition A -> A_1 ------>|                                       |
        |    (oder A -> A_3 / B -> B_2)    |                                       |
        |                                  |-- Evaluierung Mapping -------------->|
        |                                  |   (Bedingung: A_1 || A_3 || B_2)      |
        |                                  |                                       |
        |                                  |--- NetworkRequest(NMH_1) ------------>|
        |                                  |    (Full Communication Mode aktiv)    |
        |                                  |                                       |
        |--- FG Transition A_1 -> A_2 ---->|                                       |
        |    (und B != B_2)                |                                       |
        |                                  |-- Evaluierung Mapping -------------->|
        |                                  |   (Kein gemappter FGS mehr aktiv)     |
        |                                  |                                       |
        |                                  |--- NetworkRelease(NMH_1) ------------>|
        |                                  |    (Übergang in Ready Sleep)          |
  1. Trigger: Zustandsänderung einer Funktionsgruppe via ara::sm bzw. ara::exec::FunctionGroup::SetState().
  2. Evaluierung (Disjunktive ODER-Logik): Sobald mindestens ein referenzierter Zustand aktiv ist (A_1 == true OR A_3 == true OR B_2 == true), fordert der Stack die Aktivierung von NMH_1 an.
  3. NM-Aktivierung: Eintritt in den Zustand bewirkt intern den Aufruf zur Aktivierung des NM-Handles (NetworkRequest, Übergang in Full Communication).
  4. NM-Freigabe: Verlassen aller gemappten Zustände (z. B. Wechsel von A_1 nach A_2, während B in B_1 oder B_3 ist) löst die Freigabe des Handles aus (NetworkRelease, Übergang nach Ready Sleep Mode / Busruhe möglich), sofern keine externen Keep-Alive-Bedingungen vorliegen.
  5. Unterbrechungsfreier Wechsel: Ein direkter Zustandswechsel von FGS „A_1“ nach FGS „A_3“ hält das Handle NMH_1 glitch-frei aktiv, ohne Zwischen-Release.

4. Normative Relevanz & Entwickler-Hinweise

  • Deterministische 1:N-Kardinalität:
    • Für mappingDirection = functionGroupStateToNmHandle ist die 1:N-Referenzierung deterministisch, da mehrere Systemzustände gleichzeitig oder alternativ denselben Bus aktiv halten können.
    • Gegenbeispiel/Einschränkung: In der Gegenrichtung (mappingDirection = nmHandleActiveToFunctionGroupState gemäß Table 10.65) ist eine N:1-Zuordnung mehrerer Zustände derselben Gruppe unzulässig, da ein NM-Aktivierungs-Event nicht deterministisch in zwei Zielzustände einer einzelnen FunctionGroup schalten kann.
  • Manifest-Generierung & Toolchain:
    • Integratoren können die Manifest-Komplexität minimieren: Statt drei separater NmHandleToFunctionGroupStateMapping-Elemente reicht eine aggregierte Instanz mit Multi-Ref auf die entsprechenden ModeDeclaration-Elemente.
  • Applikations-Entkoppelung:
    • Prozesse innerhalb von FG „A“ und FG „B“ benötigen keinen eigenen Zugriff auf ara::nm oder Socket-Level-Keep-Alives; der Kommunikationsbedarf des Netzwerks wird vollständig deklarativ über den Lifecycle der Funktionsgruppe durch das AUTOSAR State Management gesteuert.
