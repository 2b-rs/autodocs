1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECUC-Metamodell / Konfigurations-Klassendiagramm (UML-basiertes BSW Parameter Configuration Model).
  • Architektur-Kontext: AUTOSAR Classic Platform, BSW-Modul Dem (Diagnostic Event Manager, ISO 14229 / UDS / OBD-II).
  • Funktionaler Zweck: Modellierung der statischen Konfiguration zur Ansteuerung von Warnanzeigen und optischen Indikatoren (z. B. Malfunction Indicator Lamp / MIL, Wartungs-, Emissions- oder Systemwarnleuchten). Es definiert die M:N-Beziehung zwischen diagnostischen Events (DemEventParameter) und physikalischen/logischen Anzeigen (DemIndicator), inklusive Fehlereintritts- und Heilungsschwellen sowie optischem Anzeigeverhalten.

2. Komponenten, Entitäten & Schnittstellen

ECUC-Container & Stereotypen
  • DemGeneral (EcucParamConfContainerDef, [1..1]): Zentraler Konfigurationscontainer für modulglobale Dem-Parameter.
  • DemOperationCycle (EcucParamConfContainerDef, [1..256]): Per +subContainer an DemGeneral gebunden. Repräsentiert die Betriebszyklen (z. B. OBD Driving Cycle, Ignition ON/OFF), auf denen die Zähler basieren.
  • DemIndicator (EcucParamConfContainerDef, [0..255]): Repräsentiert die logische oder physische Warnlampe (z. B. MIL, ABS-Warnung).
  • DemMILIndicatorRef (EcucReferenceDef, [0..1]): Referenz (+destination) von DemGeneral auf genau einen DemIndicator, der als gesetzliche MIL fungiert.
  • DemEventParameter (EcucParamConfContainerDef, [1..65535]): Repräsentiert ein einzelnes Diagnose-Ereignis (Event / DTC).
  • DemIndicatorAttribute (EcucParamConfContainerDef, [0..255]): Per +subContainer an DemEventParameter gebunden. Verknüpfungsentität, die festlegt, wie ein Event einen bestimmten Indikator beeinflusst.
Parameter & Referenzen innerhalb DemIndicatorAttribute
  • DemIndicatorRef (EcucReferenceDef): Unidirektionale Referenz (+destination) auf das Zielobjekt DemIndicator.
  • DemIndicatorFailureCycleCounterThreshold (EcucIntegerParamDef, [0..1]):
    • Wertebereich: Min = 1, Max = 255.
    • Anzahl aufeinanderfolgender Zyklen (DemOperationCycle) mit qualifiziertem Fehler (Event Failed), ab der die Anzeige aktiviert wird.
  • DemIndicatorHealingCycleCounterThreshold (EcucIntegerParamDef, [1..1]):
    • Wertebereich: Min = 0, Max = 255.
    • Anzahl fehlerfreier Zyklen (Event Passed), nach denen die Anzeigeanforderung erlischt. Schwellwert 0 bedeutet sofortige Deaktivierung bei Pass im selben Zyklus.
  • DemIndicatorBehaviour (EcucEnumerationParamDef): Definiert das optische Aktivierungsmuster über fünf Enums (EcucEnumerationLiteralDef via +literal):
    • DEM_INDICATOR_CONTINUOUS: Dauerlicht.
    • DEM_INDICATOR_BLINK_CONT: Kombiniertes Verhalten (z. B. erst Blinken, danach Dauerlicht).
    • DEM_INDICATOR_BLINKING: Kontinuierliches Blinken.
    • DEM_INDICATOR_SLOW_FLASH: Langsames Blinken (niedrige Frequenz).
    • DEM_INDICATOR_FAST_FLASH: Schnelles Blinken (hohe Frequenz).

3. Dynamisches Verhalten & Sequenzablauf

[SWC / BSW] ---> Dem_SetEventStatus(EventId, FAILED/PASSED)
                         │
                         ▼
        [Dem Event Debounce & Qualification]
                         │
         ┌───────────────┴───────────────┐
         ▼ (Failed im Zyklus)            ▼ (Passed im Zyklus)
[Incr. FailureCycleCounter]    [Incr. HealingCycleCounter]
         │                               │
Counter >= Threshold?           Counter >= Threshold?
         │                               │
         ├─► JA: Indikator-Anforderung   ├─► JA: Anforderung zurücknehmen
         │       (Behaviour setzen)      │
         ▼                               ▼
 [Dem Indicator Arbitrierung (Priorisierung Blinken vs. Dauerlicht)]
                         │
                         ▼
[RTE / Port Dem_GetIndicatorStatus()] ──► [HMI / IPC / Kombiinstrument]
  1. Aktivierung (Failure-Pfad):
    • Ein Event meldet DEM_EVENT_STATUS_FAILED. Der Dem inkrementiert bei Zyklusabschluss (Dem_SetOperationCycleState) den Fehlerspeicher- und Indikator-Zähler.
    • Erreicht der Zähler DemIndicatorFailureCycleCounterThreshold, geht die Event-interne Anforderung für den Indikator in den Zustand Active über, verknüpft mit dem konfigurierten DemIndicatorBehaviour.
  2. Arbitrierung:
    • Referenzieren mehrere Events denselben DemIndicator, arbitriert der Dem den Gesamtstatus nach AUTOSAR-Prioritätsregeln (Blinken/Fast Flash priorisiert i. d. R. Dauerleuchten).
  3. Deaktivierung (Healing-Pfad):
    • Wird das Event in nachfolgenden Zyklen als DEM_EVENT_STATUS_PASSED getestet, inkrementiert der Dem den Heilungszähler.
    • Erreicht dieser DemIndicatorHealingCycleCounterThreshold, wird die Aktivierungsanforderung des Events gelöscht. Wenn kein weiteres Event den Indikator anfordert, wird er deaktiviert.
  4. Statusbereitstellung:
    • Anzeigesteuernde SWCs (z. B. Instrument Cluster / BCM) fragen den Indikatorstatus zyklisch oder ereignisorientiert via RTE über Dem_GetIndicatorStatus() ab.

4. Normative Relevanz & Entwickler-Hinweise

  • Multiplizitätsgrenzen:
    • Bis zu 65.535 Events (DemEventParameter) und bis zu 255 Indikatoren (DemIndicator).
    • Ein Event kann bis zu 255 Indikatoren ansteuern (DemIndicatorAttribute), in der Praxis meist 1 (oder 0 für reine Diagnosespeicher-Einträge ohne Warnleuchte).
  • Zyklen-Abhängigkeit:
    • Jeder Indikator-Zähler hängt deterministisch am konfigurierten DemOperationCycle. Wird ein Zyklus nicht via Dem_SetOperationCycleState() getaktet (z. B. fehlender Driving-Cycle-Trigger über Bus/Klemme 15), frieren Zählerstände, MIL-Aktivierung und Entprellung ein.
  • OBD-Konformität (DemMILIndicatorRef):
    • Ist DemMILIndicatorRef gesetzt, synchronisiert der Dem den Zustand dieses Indikators direkt mit dem UDS DTC-Status-Byte (Bit 7: WarningIndicatorRequested) sowie den genormten OBD-PIDs (z. B. PID $01 via Dcm).
  • Treiber- und HMI-Umsetzung:
    • Das Dem liefert ausschließlich den logischen Ansteuerungs- und Verhaltensstatus (Dem_IndicatorStatusType), generiert jedoch keine Hardware-PWMs oder Blink-Frequenzen. Die zeitliche Zerlegung von DEM_INDICATOR_SLOW_FLASH / DEM_INDICATOR_FAST_FLASH obliegt der ansteuernden Applikations-SWC bzw. dem I/O-Treiber.
