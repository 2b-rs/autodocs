1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm zur Spezifikation des AUTOSAR BSW-Konfigurationsmetamodells (ECUC Parameter Configuration / Metamodel Definition).
  • Technischer Zweck: Modellierung der Konfigurationsstrukturen für den Function Inhibition Manager (FiM) Proxy innerhalb des Moduls Software Cluster Connection (SwCluC, AUTOSAR Classic Platform Release R21-11).
  • Funktionale Einordnung: In modularen Multi-Software-Cluster-Systemen (SWCL) bzw. partitionierten Systemen ermöglicht das Modul SwCluC die cluster- und partitionsübergreifende Vermittlung von BSW-Services. Das Metamodell definiert die Abbildung (Proxying) lokaler Function Identifiers (FiMFID) einer Quell-Partition/Cluster auf globale Cluster-Ressourcen (CpSoftwareClusterServiceResource) sowie auf DEXT-Diagnose-Funktionsbezeichner (DIAGNOSTIC-FUNCTION-IDENTIFIER).

2. Komponenten, Entitäten & Schnittstellen

Konfigurationscontainer (ECUC Container Definitions)
  • SwCluCFiMProxy (EcucParamConfContainerDef):
    • Multiplizität: [0..1].
    • Wurzel-Container für alle FiM-bezogenen Proxy-Konfigurationen innerhalb des SwCluC-Moduls.
    • Aggregiert über die Kompositionsbeziehung +subContainer den Subcontainer SwCluCFiMProxyFID.
  • SwCluCFiMProxyFID (EcucParamConfContainerDef, SWS-Item: ECUC_SwCluC_00109):
    • Multiplizität: [0..*].
    • Repräsentiert die konkrete Instanz eines weitergeleiteten/geproxyten Function Identifiers (FID).
  • FiMFID (EcucParamConfContainerDef, Package: FiM):
    • Multiplizität: [1..*].
    • Zielcontainer aus dem originären BSW-Modul FiM, der die tatsächliche FID-Instanz auf BSW-Ebene deklariert.
  • EcucPartition (EcucParamConfContainerDef, Package: EcucPartition):
    • Multiplizität: [0..*].
    • Zielcontainer zur Zuordnung der ausführenden bzw. referenzierten OS-/BSW-Partition.
Referenzen (ECUC Reference Definitions)
  • SwCluCFiMProxyFIDRef (EcucReferenceDef, SWS-Item: ECUC_SwCluC_00142):
    • Multiplizität: [1..1].
    • Typ: Interne ECUC-Referenz mit Rolle +destination auf den Zielcontainer FiMFID.
  • SwCluCProxyEcucPartitionRef (EcucReferenceDef, Package: ProxyModules):
    • Multiplizität: [1..1].
    • Typ: Interne ECUC-Referenz mit Rolle +destination auf eine EcucPartition, um den Kontext der Proxy-Instanz bindend an eine Ausführungspartition zu koppeln.
  • SwCluCResourceRef (EcucForeignReferenceDef, Package: ProxyModules):
    • Typ: Fremdreferenz (destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE).
    • Referenziert die AUTOSAR-System-/Template-Entität SoftwareCluster::CpSoftwareClusterServiceResource.
  • SwCluCDextDiagnosticFunctionIdentifierRef (EcucForeignReferenceDef):
    • Multiplizität: [0..1].
    • Typ: Fremdreferenz (destinationType = DIAGNOSTIC-FUNCTION-IDENTIFIER).
    • Verknüpft den Proxy-FID optional direkt mit einem Diagnosefunktionsbezeichner aus der Diagnostic Extract (DEXT).
Template- & Ressourcenpool-Entitäten (Metamodell / Resource Pool)
  • SoftwareCluster::CpSoftwareClusterResource (Spezialisierung von Identifiable):
    • Abstrakte Basisklasse für clusterübergreifend sichtbare Ressourcen im CP Software Cluster Resource Pool.
    • Attribute:
      • + globalResourceId: PositiveInteger [0..1] – Eindeutiger systemweiter Ressourcen-Index zur Identifikation über Clustergrenzen hinweg.
      • + isMandatory: Boolean [0..1] – Gibt an, ob die Ressource zwingend vorhanden sein muss, damit der Cluster funktionsfähig gebunden werden kann.
  • SoftwareCluster::CpSoftwareClusterServiceResource:
    • Generalisierung/Spezialisierung von CpSoftwareClusterResource.
    • Dient als Zieltyp für die Bindung des BSW-Services (FiM) über Clustergrenzen.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches ECUC-Metamodell handelt, steuert die Parametrierung das Laufzeit-Routing:

  1. Konfigurations- und Generierungszeitpunkt:
    • Der Code-Generator des SwCluC-Moduls liest SwCluCFiMProxyFID aus und generiert Proxy-/Stub-APIs für den Zugriff auf den FiM-Status über Partitions- bzw. Clustergrenzen (z. B. via IPC/Shared Memory oder Hardware-unterstützte Inter-Partition-Mechanismen).
    • Die Zuordnung SwCluCProxyEcucPartitionRef definiert, auf welcher Partition der Proxy-Aufruf registriert bzw. entgegengenommen wird.
  2. Laufzeit-Pfad (Inhibition Status Routing):
    • Abfrage / Statustransfer: Ein Software-Cluster bzw. eine ausgelagerte Applikationspartition fragt den Berechtigungs-/Inhibitionsstatus einer Funktionalität ab.
    • Vermittlung: Die Anfrage wird über die durch globalResourceId (CpSoftwareClusterServiceResource) identifizierte Kommunikationsschnittstelle der Zielpartition zugestellt, in der das Basis-FiM läuft.
    • Auflösung: Über SwCluCFiMProxyFIDRef wird die Abfrage auf die reale FiMFID gemappt und gegen FiM_GetFunctionPermission() ausgewertet; das Ergebnis wird synchron oder asynchron an den anfragenden Cluster zurückgeliefert.
  3. Diagnose-Kopplung:
    • Falls SwCluCDextDiagnosticFunctionIdentifierRef konfiguriert ist, erfolgt die automatische Querverbindung zu Dem/Dcm-Events über die systemweite DEXT-FID-Nomenklatur.

4. Normative Relevanz & Entwickler-Hinweise

  • Kardinalitäts- und Konsistenzregeln:
    • Jede Instanz von SwCluCFiMProxyFID erfordert zwingend ([1..1]) eine gültige FiMFID-Referenz sowie eine gültige EcucPartition-Referenz. Eine fehlerhafte/unaufgelöste Referenz führt zum Validierungsabbruch im ECUC-Generator.
    • SwCluCDextDiagnosticFunctionIdentifierRef ist optional ([0..1]), muss jedoch bei Nutzung auf ein valides Element des Diagnostic Extract zeigen, um Inkonsistenzen zwischen BSW-Konfiguration und DEXT zu verhindern.
  • Cluster-Entkopplung:
    • Anwendungs- und Host-Cluster müssen über die globalResourceId identisch abgeglichen sein. Ändert sich der Service-Resource-Pool im Host-Cluster, erfordert dies eine Neu-Generierung bzw. Validierung der BSW-Konfiguration des abhängigen Clusters.
  • Cross-Partition-Restriktionen:
    • Stack-Entwickler müssen sicherstellen, dass Aufrufe über SwCluCProxyEcucPartitionRef den Speicherschutzgrenzen (MPU/OS-Application Boundaries) genügen; Datenstrukturen für den FiM-Zustand müssen ggf. in nicht-privilegierten oder Shared-RAM-Sektionen gespiegelt oder per Inter-Partition-Kommunikation gesichert transportiert werden.
