1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm zur Definition des AUTOSAR ECU Configuration Metamodells (ECUC Parameter Definition) mit Verknüpfung zum AUTOSAR Software-Cluster System-Metamodell (M2/ARXML).
  • Kontext: AUTOSAR Classic Platform Release R21-11, Spezifikation AUTOSAR_SWS_SoftwareClusterConnection (SwCluC), Anforderungs-ID ECUC_SwCluC_00120.
  • Technischer Zweck: Definition der Konfigurationsstruktur für den Basis-Kommunikationsendpunkt (SwCluCDcmProxyBaseSocket) des Diagnostic Communication Manager (Dcm) Proxys. Im Rahmen des Software-Cluster-Konzepts (getrennte Update- und Ausführungsdomänen) dient dieser Endpunkt der Entkopplung und cluster-/partitionsübergreifenden Weiterleitung diagnostischer Dienste zwischen dem zentralen Host/Base-Cluster und abgesetzten Satelliten bzw. Applikations-Clustern.

2. Komponenten, Entitäten & Schnittstellen

ECUC-Konfigurationscontainer & Parameter
  • SwCluCDcmProxy (EcucParamConfContainerDef):
    • Kardinalität: 0..1.
    • Oberster Konfigurationsknoten für die Dcm-Proxy-Funktionalität im SwCluC-Modul.
    • Aggregation: Beherbergt über die Kompositionsrolle +subContainer mindestens einen Base Socket (1..*).
  • SwCluCDcmProxyBaseSocket (EcucParamConfContainerDef):
    • Kardinalität: 1..*.
    • Repräsentiert die konkrete Konfigurationsinstanz eines Dcm-Basis-Sockets.
    • Aggregiert folgende Konfigurationsparameter und Referenzen:
      • SwCluCNativeBswApi (EcucBooleanParamDef, Package: ProxyModules):
        • Rolle: +parameter, Kardinalität: 0..1, Standardwert: defaultValue = false.
        • Steuert, ob der Proxy direkt die native C-API des BSW-Dcm aufruft (true) oder den generierten IPC-/Proxy-Mechanismus des SwCluC durchläuft (false).
      • SwCluCProxyEcucPartitionRef (EcucReferenceDef, Package: ProxyModules):
        • Rolle: +reference, Kardinalität: 1..1.
        • Verweist via Assoziation +destination verbindlich auf genau eine Zielinstanz von EcucPartition (0..*, Package: EcucPartition). Definiert die OS- bzw. Speichertrennungs-Partition des Sockets.
      • SwCluCDcmProxyUsedSatelliteRef (EcucReferenceDef):
        • Rolle: +reference, Kardinalität: 0..1.
        • Assoziation +destination: Referenziert im Metamodell den zugehörigen Socket-Endpunkt (im Diagramm auf SwCluCDcmProxyBaseSocket rückgeführt zur Bindung von Proxy- und Satelliten-Kanalinstanzen).
      • SwCluCResourceRef (EcucForeignReferenceDef, Package: ProxyModules):
        • Rolle: +reference.
        • Attribut: destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE.
        • Fremdschlüssel-Referenz (Foreign Reference) in das System-Metamodell zur logischen Dienstbindung.
System-Metamodell-Entitäten (CP Software Cluster Resource Pool)
  • SoftwareCluster::CpSoftwareClusterResource (Stereotyp: «Identifiable»):
    • Basisklasse für alle clusterübergreifend exportierten oder importierten Ressourcen.
    • Attribute:
      • + globalResourceId: PositiveInteger [0..1]: Systemweit eindeutiger Identifikator zur Laufzeitadressierung der Ressource über Clustergrenzen hinweg.
      • + isMandatory: Boolean [0..1]: Kennzeichnung, ob das Vorhandensein der Ressource für die Cluster-Lauffähigkeit zwingend vorgeschrieben ist.
  • SoftwareCluster::CpSoftwareClusterServiceResource:
    • Spezialisierung: Generalisiert CpSoftwareClusterResource (Vererbungspfeil).

3. Dynamisches Verhalten & Sequenzablauf

Als rein statisches Metamodell-Strukturdiagramm bildet die Figur keine Sequenzen ab; für die Laufzeitimplementierung gilt folgende funktionale Abfolge:

  1. Initialisierungsphase (SwCluC_Init):
    • Das SwCluC-Modul liest die Konfiguration von SwCluCDcmProxyBaseSocket ein und initialisiert die Socket-Deskriptoren innerhalb der über SwCluCProxyEcucPartitionRef zugewiesenen EcucPartition.
    • Bindung an die globalResourceId der referenzierten CpSoftwareClusterServiceResource.
  2. Kanalverbindung & Routing:
    • Bei gesetzter SwCluCDcmProxyUsedSatelliteRef wird der logische Kommunikationskanal zum korrespondierenden Satelliten aufgebaut.
    • Pfad A (SwCluCNativeBswApi == false): Diagnostische Service-Requests (z. B. TesterPresent, ReadDataByIdentifier) aus einem externen Software-Cluster werden per SwCluC-IPC (z. B. Ringpuffer, IOC oder Inter-Partition Shared Memory) entpackt und an den Dcm-Kern übergeben.
    • Pfad B (SwCluCNativeBswApi == true): Funktionsaufrufe werden ohne IPC-Overhead direkt über die standardisierte C-Schnittstelle des Dcm abgewickelt, sofern Proxy und Core in derselben Partition laufen.
  3. Fehlerbehandlung:
    • Schlägt die Auflösung der globalResourceId oder die Partitionskommunikation fehl, erfolgt eine Meldung an das DET (SWCLUC_E_INIT_FAILED, SWCLUC_E_PARAM_INVALID). Bei unvollständiger Antwort bricht der Request mit einem entsprechenden Dcm-NRC (Negative Response Code) ab.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurations-Validierung (BSW-Generator / ECUC_SwCluC_00120):
    • Jeder konfigurierte SwCluCDcmProxy muss zwingend mindestens einen Base Socket instanziieren (lowerMultiplicity = 1).
    • SwCluCProxyEcucPartitionRef ist obligatorisch (1..1): Ein Socket ohne eindeutige Partitionszuordnung ist ungültig und muss vom BSW-Konfigurator mit einem Validierungsfehler abgewiesen werden.
    • Das Ziel von SwCluCResourceRef muss im System Description Extract als gültige CpSoftwareClusterServiceResource auflösbar sein; eine fehlende Bindung verhindert die Erzeugung der IPC-Routingtabellen.
  • Architektur- & Stack-Integration:
    • Memory Protection / MPU: Bei SwCluCNativeBswApi = false müssen die generierten Pufferbereiche zwischen der Partition des Proxys und der Partition des Zielclusters in gemeinsamen, zugriffsberechtigten Speicherbereichen (Shared Memory / Non-Cached RAM) platziert werden.
    • Multi-Cluster-Buildprozess: Änderungen an globalResourceId in der Systembeschreibung erfordern einen Re-Generate des SwCluC-Moduls sowohl im Host-Cluster als auch im Application-Cluster, um Konsistenz bei Diagnose-Sessions sicherzustellen.
