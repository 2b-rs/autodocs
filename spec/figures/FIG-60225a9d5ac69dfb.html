1. Diagrammtyp & Architektur-Kontext

UML-Komponentendiagramm / Schnittstellendiagramm der AUTOSAR Adaptive Platform (AP). Das Diagramm spezifiziert die serviceorientierte Interaktion («aapAPI, araComServiceInterface») zwischen dem daemon-basierten funktionalen Cluster Vehicle Update and Configuration Management (VUCM) und interagierenden Anwendungen innerhalb einer Adaptive Application (OTA Client, Vehicle Driver Interface, Vehicle State Manager).

2. Komponenten, Entitäten & Schnittstellen

Komponenten und Funktionale Cluster

  • «aapFunctionalCluster» Vehicle Update and Configuration Management: Daemon-basierter Service Provider, der drei serviceorientierte Schnittstellen über «aapProvidedPort» bereitstellt.
  • Adaptive Application: Übergeordnete Anwendungsebene, die drei logische Software-Komponenten mit jeweils einem «aapRequiredPort» («use») umfasst:
    • OTA Client: Nutzt das Interface VehiclePackageManagement.
    • Vehicle Driver Interface: Nutzt das Interface VehicleDriverApplication.
    • Vehicle State Manager: Nutzt das Interface VehicleStateManager.

3. Dynamisches Verhalten & Sequenzablauf

Statische Definition serviceorientierter Schnittstellenbeziehungen:

  • Der OTA Client initiiert Kampagnen und steuert den Pakettransfer über die Methoden und Fields von VehiclePackageManagement (z. B. TransferStart(), TransferData(), TransferExit(), TransferVehiclePackage(), AllowCampaign(), CancelCampaign()).
  • Das Vehicle Driver Interface interagiert zwecks Fahrerinteraktion, Zustandsanzeige und Freigabe mit VUCM über VehicleDriverApplication (Abfrage von Kampagnen- und Übertragungsfortschritten sowie Übermittlung von Zustimmungen via DriverApproval()).
  • Der Vehicle State Manager synchronisiert fahrzeugseitige Vorbedingungen und Sicherheitszustände über VehicleConditions und SafetyState() mit dem VUCM-Dienst.

4. Normative Relevanz & Entwickler-Hinweise

  • Die Schnittstellen sind als «aapAPI, aapAraComServiceInterface» klassifiziert und unterliegen der AUTOSAR-Adaptive-Kommunikationsinfrastruktur (ara::com).
  • Zugriffsschutz: Sowohl die Fields als auch die Methoden tragen das Stereotyp «aapAccessControlled», was eine Zugriffskontrolle (z. B. IAM-Policy-Checks) bei Interaktion mit dem VUCM-Daemon erfordert.
  • Die funktionale Aufteilung trennt strikt die Rollen für Remote-Backend-Kommunikation (OTA Client), Mensch-Maschine-Schnittstelle/Fahrerinteraktion (Vehicle Driver Interface) und Fahrzeugzustandsprüfung/Sicherheit (Vehicle State Manager).
