Dargestellt sind drei Modellierungsebenen mit ihren jeweiligen Metamodell-Entitäten (AUTOSAR_MM_ECUConfiguration):

  • Param A (EcucParameterDef): Optionaler Parameter mit Multiplizität $[0..1]$.
  • Param B (EcucParameterDef): Pflichtparameter mit Multiplizität $[1..1]$.
  • Param C (EcucParameterDef): Liste/Mehrfachwert mit unbeschränkter oberer Multiplizität $[0..*]$.

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

Das Diagramm visualisiert keinen Laufzeitablauf, sondern den statischen Verifikations- und Tooling-Workflow zur Entwurfs-/Build-Zeit:

  • Stufe A: VSMD-Konformitätsprüfung gegen StMD (Regeln 1–4):
  • (1) Feature-Omission: Parameter mit $\text{lowerMultiplicity} = 0$ im StMD dürfen im VSMD auf $[0..0]$ gesetzt und damit funktional abgewählt werden.
  • (2) Obligatorische Übernahme: Parameter mit $\text{lowerMultiplicity} > 0$ müssen im VSMD mit identischer oder kompatibler Untergrenze erhalten bleiben.
  • (3) Bereichs-Restriktion: Die Obergrenze darf in der VSMD verschärft ($\le$), jedoch niemals gelockert werden.
  • (4) Vendor-Erweiterung: Das Hinzufügen herstellerspezifischer Parameter ist zulässig.
  • Stufe B: Validierung der ECUC Description gegen VSMD (Regeln 5–9):
  • (5) Verbotene Instanziierung [FEHLER]: Instanz a = 8 verweist auf Param A [0..0]. Überschreitung von $\text{upperMultiplicity} = 0 \implies$ Tool muss Fehler werfen.
  • (6) Valide Pflichtinstanz [GÜLTIG]: b = 15 erfüllt exakt die Multiplizität $[1..1]$.
  • (7) Valide Mehrfachinstanz [GÜLTIG]: Zwei Instanzen (c = 16, c = 8) liegen innerhalb des definierten Intervalls $[0..255]$.
  • (8) Fehlender Pflichtparameter [FEHLER]: Param D besitzt $\text{lowerMultiplicity} = 1$; die Instanz d = 2 fehlt im ARXML (gestrichelt dargestellt) $\implies$ Tool muss Unterdeckung detektieren.
  • (9) Verwaiste Instanz [FEHLER]: e = 5 besitzt keine Parameterdefinition in der VSMD $\implies$ Tool muss undefinierten Parameter ablehnen.

4. Normative Relevanz & Entwickler-Hinweise

  • Monotonie-Prinzip der VSMD: Ein BSW-Treiber/-Stack darf den AUTOSAR-Standard parametrisch nur einschränken oder proprietär erweitern, niemals die Freiheitsgrade des StMD eigenmächtig vergrößern.
  • Code-Size & Pre-Compile-Optimierung: Das Setzen optionaler Parameter auf $[0..0]$ (Fall 1) dient BSW-Lieferanten zur statischen Code-Reduktion (Entfernen nicht unterstützter Treiber-Features via Pre-Processor-Switches #if (FEATURE_X == STD_OFF)).
  • Konsequenzen für BSW-Generatoren:
  • Tritt Fall (5), (8) oder (9) ein, muss der Generator-Pre-Flight mit einem Validierungsfehler abbrechen; es darf kein C-Header/Source (_Cfg.h, _Cfg.c) generiert werden.
  • Fall (8) bricht die Determinismus-Garantie: Pflichtkonfigurationen für Treiber-Register (z. B. Baudraten, Basisadressen, Mailbox-Größen) fehlen.
  • Fall (9) verhindert „Phantom-Konfigurationen“ durch veraltete ARXML-Dateien bei Plattform- oder Versions-Upgrades.

Speciﬁcation of ECU Conﬁguration V2.2.0 R3.1 Rev 0004 Figure 5.2 shows an overview about rules, which shall be checked by tools that validate that a SW module implementation conforms to its AUTOSAR speciﬁcation. In this example three parameters are deﬁned in the StMD. The multiplicity in each of this parameter deﬁnitions speciﬁes how often a parameter is allowed to occur in the ECU Conﬁguration Description. In the VSMD optional elements (with lowerMultiplicity = 0) may be omitted, as it happens with parameter A (1). Parameters deﬁned with lowerMultiplicity > 0 in StMD must be present in the VSMD (2). The upperMultiplicity of parameters in the VSMD must be equal or less than in the StMD (2, 3). New vendor speciﬁc parameters may also be added in the VSMD (4). The VSMD deﬁnes which parameters are available in which container and what kind of restrictions are to be respected. If the upperMultiplicity of a parameter deﬁnition in the VSMD is 0, the parameter shall not exist in the parameter description( 5). If the lowerMultiplicity of a parameter deﬁnition is bigger than 0, the parameter must exist (6). Missing parameters shall be detected by tools (8). Parameters without parameter deﬁnitions shall also be detected (9). The number of parameters in the ECUC Description shall not exceed the upperMultiplicity of the parameter deﬁnition in the VSMD (7).
