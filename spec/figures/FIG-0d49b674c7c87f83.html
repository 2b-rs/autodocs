1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Timing-Diagramm / Zeitablauf- und Zustands-Korrelationsdiagramm (Timing Diagram) zweier heterogener Kommunikationskanäle über einer gemeinsamen Zeitachse.
  • Architektur-Kontext:
    • AUTOSAR Classic Platform (R4.1.3), BSW-Schicht System Services / Communication Stack (ComStack).
    • Spezifikation: AUTOSAR_SWS_NetworkManagementInterface (Nm), Subfunktion NM Coordinator (NMC).
  • Technischer Zweck: Spezifikation der zeitlichen Kopplung und der Gesamtabschaltzeit (T_NmGlobalCoordinatoTime) beim koordinierten Bus-Shutdown über Netzwerk-Cluster-Grenzen hinweg. Dargestellt ist das Szenario („Timing example two“), bei dem ein zyklusgebundenes, synchronisierendes Bussystem (z. B. FlexRay via FrNm) und ein azyklisches bzw. rein timergesteuertes Bussystem (z. B. CAN via CanNm) so synchronisiert heruntergefahren werden, dass beide Netzwerke exakt zeitgleich in den Ruhezustand (Bus-sleep mode) übergehen.

2. Komponenten, Entitäten & Schnittstellen

  • Beteiligte BSW-Module & Kanäle:
    • Generic NM Interface (Nm): Zentraler Koordinator für Multichannel-Shutdown-Sequenzen (NmCoordinatorSupport = TRUE).
    • Synchronizing cyclic network: Repräsentiert durch einen synchronen Bus-NM (typischerweise FrNm auf FlexRay). Die gelben Rechtecke stellen diskrete Kommunikationszyklen (Communication Cycles / Schedule-Frames) dar (im vorliegenden Bildausschnitt links abgeschnitten).
    • Non-cyclic network: Repräsentiert durch einen ereignis-/timeout-gesteuerten Bus-NM (typischerweise CanNm auf CAN; im vorliegenden Bildausschnitt links abgeschnitten).
    • Communication Manager (ComM): Übergeordnete Instanz, welche die Kanal-Freigaben (Nm_NetworkRelease) erteilt und Statuswechsel notifiziert bekommt.
  • Zustände (States):
    • Prepare bus-sleep mode (hellblaue Blöcke): Pufferentleerung, Einstellen der aktiven NM- und Applikations-PDU-Transmission; Vorbereitung der Hardware-Transceiver auf den Schlafmodus.
    • Bus-sleep mode (dunkelblaue Blöcke): Vollständiger Ruhezustand; Bus-Aktivität ist gestoppt, Transceiver befinden sich im Standby/Sleep mit Wake-Up-Fähigkeit.
  • Zeitliche Größen & Schnittstellen-Parameter:
    • Synchronization indication: Zeitnullpunkt t_0, ausgelöst durch das Erreichen der lokalen Freigabebedingung aller koordinierten Kanäle (am unteren Rand teilweise beschnitten).
    • Shutdown Timer (rote Vektorpfeile): Parametrierbare lokale Verzögerungszeit (NmShutdownDelayTimer), um Laufzeit- und Phasenunterschiede zwischen Clustern auszugleichen.
    • T_SYNCHRONIZATION_INDICATION: Zeitintervall vom Freigabetrigger bis zum nächsten gültigen Synchronisationspunkt des zyklischen Netzwerks.
    • T_SHUTDOWN_CHANNEL: Verweildauer in der Phase Prepare bus-sleep mode des synchronisierenden zyklischen Kanals.
    • T_NmGenericBusNmShutdownTime: Verweildauer in der Phase Prepare bus-sleep mode des nicht-zyklischen Kanals.
    • T_NmGlobalCoordinatoTime (im Bild oben leicht angeschnitten): Gesamte Shutdown-Koordinatorzeit über alle koordinierten Cluster hinweg bis zum synchronen Erreichen des Bus-sleep mode.

3. Dynamisches Verhalten & Sequenzablauf

  1. Trigger (t_0, Synchronization indication):
    • Alle über ComM angebundenen Nutzer geben ihre Network-Requests für die koordinierten Kanäle via Nm_NetworkRelease() frei.
    • Nm startet auf beiden Netzwerken simultan den kanalindividuellen Shutdown Timer.
  2. Kanal 2 (Non-cyclic network – CAN):
    • Der zugeordnete Shutdown Timer läuft nach einer statisch konfigurierten Zeitspanne ab (Ende des unteren roten Pfeils, noch vor Ablauf von T_SYNCHRONIZATION_INDICATION).
    • Der Kanal wechselt sofort in den Zustand Prepare bus-sleep mode (hellblauer Block) und meldet dies via Callback ComM_Nm_PrepareBusSleepMode().
    • Der Kanal verbleibt für die Dauer T_SHUTDOWN in dieser Phase.
  3. Kanal 1 (Synchronizing cyclic network – FlexRay):
    • Der Wechsel kann nicht asynchron erfolgen, sondern muss an das statische Zyklusfenster gebunden werden.
    • Während T_SYNCHRONIZATION_INDICATION läuft der Zyklus zu Ende, bis FrNm den Synchronisationspunkt über Nm_SynchronizationPoint() an das Nm-Interface meldet (zweite gestrichelte Referenzlinie).
    • Erst nach Ablauf der Synchronisationsverzögerung und des zugehörigen Timers tritt das zyklische Netzwerk in den Zustand Prepare bus-sleep mode ein (umfasst hier exakt drei vollständige Buszyklen).
  4. Synchroner Übergang in Bus-sleep mode (t_final):
    • Beide Netzwerke beenden ihre Vorbereitungsphase im selben Moment.
    • Der koordinierte Zustandsübergang nach Bus-sleep mode wird für beide Cluster zeitgleich via ComM_Nm_BusSleepMode() gemeldet.
    • Formale Beziehung der Gesamtlaufzeit: $$T_{\text{TOTAL\_SHUTDOWN}} = T_{\text{SYNCHRONIZATION\_INDICATION}} + T_{\text{SHUTDOWN}}$$

4. Normative Relevanz & Entwickler-Hinweise

  • BSW-Konfiguration (Nm.epc / ComM.epc):
    • NmCoordinatorSupport muss zwingend auf TRUE stehen.
    • NmCoordinatorSyncSupport muss aktiviert sein, um Callbacks wie Nm_SynchronizationPoint() im FrNm freizuschalten.
    • NmShutdownDelayTimer muss im Verhältnis zur FlexRay-Zykluszeit (FrIfGMacroPerCycle) und den Bus-Timeouts (CanNmWaitBusSleepTime, FrNmPrepareBusSleepTime) so dimensioniert werden, dass die Differenz zwischen zyklischer Sync-Latenz und CAN-Timer ausgeglichen wird.
  • Gateway- und PDU-Integrität:
    • Schläft das azyklische Netzwerk vorzeitig ein, drohen Datenverluste für geroutete Signale aus dem noch aktiven zyklischen Netzwerk. T_SHUTDOWN des nicht-zyklischen Busses muss daher mindestens so groß gewählt werden, dass er die verbleibende aktive Sendezeit des zyklischen Busses vollständig abdeckt.
  • Abbruchbedingung / Race Conditions:
    • Trifft während T_SYNCHRONIZATION_INDICATION, des Shutdown Timer oder Prepare bus-sleep mode ein lokaler Request (ComM_Nm_NetworkRequest()) oder eine externe NM-PDU (Rx-Indication) auf einem der Kanäle ein, muss der gesamte Shutdown-Prozess unverzüglich für alle koordinierten Kanäle abgebrochen werden. Das System wechselt zurück in den Network Mode (Restart-Handling).
