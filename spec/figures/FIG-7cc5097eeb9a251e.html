1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Konzeptionelles Speicherlayout- und Datenstruktur-Diagramm (logisches RAM/NVM-Speicherabbild) des AUTOSAR Classic BSW-Moduls Dem (Diagnostic Event Manager).
  • Funktionale Einordnung: Dargestellt ist die Dekomposition des AUTOSAR-Fehlerspeichers (Event Memory) in logische Speicherbereiche sowie die interne Strukturierung eines einzelnen Ereigniseintrags (Event Memory Entry). Das Modell definiert, wie Diagnoseereignisse (EventId), Umgebungsdaten (Freeze Frames / Snapshot Data gem. UDS 0x19 0x04) und statistische Statusdaten (Extended Data gem. UDS 0x19 0x06) im flüchtigen Caching-Bereich organisiert und für die NVRAM-Persistierung via NvM (Non-Volatile Memory Manager) bereitgestellt werden (Ref: SWS_Dem_00162, SWS_Dem_00548).

2. Komponenten, Entitäten & Schnittstellen

  • Hierarchische Ebenen & Speicherbereiche:
    • Event Memory (Wurzelentität): Partitioniert in verschiedene funktionale Speicher:
      • primary (Pflicht): Primärer Ereignisspeicher für standardmäßige On-Board-Diagnose.
      • mirror (Optional): Spiegelspeicher für Entwicklungs-, Shadow- oder Werkstatt-Zwecke.
      • ... (Erweiterbar): Permanent-DTC-Speicher (z. B. für OBD-II/WWH-OBD) oder herstellerspezifische User-Defined-Event-Memories (DemUserDefinedEventMemory).
    • Event Memory Layout (Instanzebene):
      • event counter: Globaler Verdrängungs- bzw. Belegungszähler zur Protokollierung der Speicherhistorie und Auflösung von Verdrängungsstrategien (Displacement).
      • 1st entry bis nth entry: Bounded Array von Speicherplätzen ([1..DemMaxNumberEventEntry]).
    • Detaillierter Eintrag (Event Memory Entry):
      • EventId: Primärschlüssel (Dem_EventIdType) zur Adressierung des konfigurativ zugeordneten DTCs.
      • Freeze Frame 1, Freeze Frame 2* (Snapshot Data): Datensätze mit Erfassungszeitpunkt-Telemetrie. Beinhaltet Standard-Headerdaten wie milage (Kilometerstand) und abs. time (Systemzeitstempel) sowie Nutzdaten-DIDs (FF Data 1 bis FF Data m). Das Suffix * indiziert die Unterstützung multipler Snapshots pro Ereignis (DemMaxNumberFreezeFrameRecords).
      • Extended Data: Zustands- und Verlaufsdaten wie condition byte (interner Zustandsvektor), frequency counter 1 (Fehlerauftrittszähler / Occurrence Counter), Fault Detection Counter (FDC) und Aging Counter.
    • Heterogenität (ev. rel. data o/p): Die Einträge 2nd entry bis nth entry adaptieren das Layout des ersten Eintrags, besitzen jedoch ereignisindividuelle Datenbreiten und Record-Zusammenstellungen (DemExtendedDataRecordClass, DemFreezeFrameRecordClass).

3. Dynamisches Verhalten & Sequenzablauf

  1. Qualifikation & Allokation:
    • Ein Monitor meldet ein Fehlerereignis via Dem_SetEventStatus(EventId, DEM_EVENT_STATUS_FAILED).
    • Nach internem Debouncing setzt das Dem das UDS-Statusbyte (Bit 0 testFailed, Bit 2 pendingDTC, Bit 3 confirmedDTC).
    • Ist das Ereignis speicherrelevant und noch kein Eintrag vorhanden, alloziiert das Dem einen freien Slot im RAM. Sind alle n Slots belegt, triggert der Verdrängungsalgorithmus basierend auf DTC-Priorität (DemDTCPriority), Alter (event counter) und Status (SWS_Dem_00548).
  2. Datenerfassung (Freeze Frame & Extended Data):
    • Snapshot Capture (SWS_Dem_00329): Dem triggert synchron über R-Ports (CS-Interface DataServices_<DataElement>) oder C-Callbacks das Auslesen der konfigurierten DIDs aus den Applikations-SWCs / Sensoren und serialisiert FF Data 1..m in den Puffer.
    • Extended Data Update (SWS_Dem_00330): Inkrementierung des frequency counter und Aktualisierung herstellerspezifischer Zähler direkt im RAM-Block.
  3. Persistierung (NvM-Interaktion):
    • Der Eintrag wird als modifiziert markiert (dirty). Die Übergabe an den NvM erfolgt asynchron im zyklischen Taskkontext (Dem_MainFunction) über NvM_WriteBlock oder gebündelt beim Shutdown (Dem_Shutdown).

4. Normative Relevanz & Entwickler-Hinweise

  • Dimensionierung & Worst-Case-Sizing:
    • Im Standard-AUTOSAR-Design existiert pro Event Memory ein einheitlicher Slot-Pool. Um Fragmentierung zu vermeiden, muss jeder RAM-/NVM-Slot statisch auf die maximal mögliche Bytegröße (Worst-Case über alle zugeordneten Events hinsichtlich DID- und Extended-Data-Längen) ausgelegt werden, sofern kein proprietäres Packing/Serializing im BSW-Stack konfiguriert ist.
  • Konfigurationsparameter (ARXML / BSW-Konfigurator):
    • Speichergröße: DemMaxNumberEventEntryPrimary, DemMaxNumberEventEntryMirror.
    • Freeze Frames: DemFreezeFrameRecordClass, DemDidClass, DemCaptureEventClass.
    • Extended Data: DemExtendedDataRecordClass mit Zuordnung der DemExtendedDataNumber (0x01–0xEF gem. ISO 14229-1).
  • Laufzeit- & Echtzeitrestriktionen:
    • Da DID-Read-Callbacks für Freeze Frames im Kontext der Fehlerqualifikation aufgerufen werden, dürfen die zugrunde liegenden SWC-Runnables keine blockierenden Operationen ausführen.
    • Hohe Fehlerfrequenzen mit ständigen NVRAM-Writes bedrohen die Flash-Endurance; Entwickler müssen NVM-Schreibfilter (DemNvRamBlockId, DemImmediateNvStorage) restriktiv parametrieren.
