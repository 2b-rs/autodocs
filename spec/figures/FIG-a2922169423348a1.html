1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR-Methodik-Ablaufdiagramm (Data Flow / Activity Diagram nach AUTOSAR Methodology & Templates).
  • Technischer Zweck & Einordnung: Spezifikation des Übergangs von der Systemebene zur Steuergeräteebene innerhalb der AUTOSAR Classic Platform Methodology. Es definiert den Prozessschritt der initialen Erzeugung der Basis-Steuergerätekonfiguration (Generate Base ECU Configuration Description) aus herstellerspezifischen BSW-Artefakten und dem System-Extrakt sowie die Bereitstellung für die anschließende Feinparametrierung (Edit ECU Configuration).

2. Komponenten, Entitäten & Schnittstellen

Datenartefakte (ARXML / XML-Dateien)
  • Standardized ECU Configuration Parameter Definition (: EcucParameterDefinition): Normatives, von AUTOSAR vorgegebenes Metamodell/Schema, das alle standardisierten BSW-Parameter, Containerstrukturen und Typen definiert.
  • Standardized Module Definition (: ModuleDef / EcucModuleDef): Standardisierte Moduldefinition eines spezifischen BSW-Moduls (z. B. Can, Com, PduR).
  • Vendor Specific Module Definition (: ModuleDef / EcucModuleDef): Lieferantenspezifische Ausprägung/Erweiterung der Moduldefinition (z. B. herstellerspezifische MCAL- oder Stack-Zusatzparameter).
  • BSW-Module Description (: BswModuleDescription): Beschreibt Eigenschaften der Implementierung des Softwaremoduls (Speicheranforderungen, Schnittstellen, Timing-Requirements, Vendor-ID, API-Optionen).
  • Vendor Specific Preconfigured Configuration Description (: ModuleConfiguration / EcucModuleConfigurationValues): Nicht-veränderbare, hardware- oder implementierungsgebundene Festwerte des BSW-Lieferanten (zwingend zu übernehmen).
  • Vendor Specific Recommended Configuration Description (: ModuleConfiguration / EcucModuleConfigurationValues): Richt- und Vorgabewerte des Lieferanten zur Standardinitialisierung, die projektspezifisch überschrieben werden dürfen.
  • ECU Extract of System Configuration (: System): Projektbezogener Auszug aus der Gesamt-Systembeschreibung für das konkrete Steuergerät (enthält Signalrouting, Frames, Kommunikations-Cluster, PDU-Layouts und SWC-Topologie).
  • ECU Configuration Description (: EcucDescription / Aggregation von ModuleConfiguration): Zentrales XML-Gesamtdokument aller konfigurierten BSW- und RTE-Module der Ziel-ECU.
Prozessaktivitäten (Chevron-Knoten)
  • Generate Base ECU Configuration Description: Automatisierter Generator-/Importprozess, der den System-Extrakt mit den Moduldefinitionen und Vorbelegungen zu einer initialen Konfigurationsbasis synthetisiert.
  • Edit ECU Configuration: Nachgelagerte Aktivität zur manuellen/werkzeuggestützten Verfeinerung, Auflösung offener Referenzen und modulspezifischen Parametrierung.
Beziehungen & Abhängigkeiten
  • Datenfluss (durchgezogene Pfeile):
    • Input für Generate Base ECU Configuration Description: ECU Extract of System Configuration und BSW-Module Description.
    • Output von Generate Base ECU Configuration Description: Initial erzeugte ECU Configuration Description.
    • Input für Edit ECU Configuration: ECU Configuration Description.
  • Modellierungs- & Trace-Abhängigkeiten (gestrichelte Pfeile):
    • Vererbung/Spezialisierung: Vendor Specific Module Definition leitet sich aus Standardized Module Definition ab, welche ihrerseits auf der Standardized ECU Configuration Parameter Definition basiert.
    • Bindung der Default-Werte: Vendor Specific Recommended Configuration Description und Vendor Specific Preconfigured Configuration Description typisieren sich gegen die Vendor Specific Module Definition und werden durch die BSW-Module Description referenziert.
    • Rückkopplung/Abgleich: ECU Configuration Description hält Abhängigkeiten zum ECU Extract sowie zur BSW-Module Description.
    • Methodische Bindung: Beide Prozessschritte unterliegen den normativen Vorgaben des AUTOSAR-Standards (Werkzeugsymbol).

3. Dynamisches Verhalten & Sequenzablauf

  1. Artefakt-Bereitstellung (Prä-Kondition):
    • Der OEM/Systemintegrator liefert den ECU Extract of System Configuration.
    • Die BSW-Lieferanten stellen die modulspezifischen XML-Deskriptoren bereit (BswModuleDescription, Vendor Specific Module Definition, Preconfigured & Recommended Configuration).
  2. Generierung der Basis-Konfiguration (Synchroner Batch-Lauf):
    • Ausführung der Tool-Aktivität Generate Base ECU Configuration Description.
    • Automatisches Mapping der Bus-Kommunikationsdaten (Frames, PDUs, Signale aus dem System Extract) auf die Kommunikationsmodule (Com, PduR, CanIf, Can, Lin, Fr).
    • Starre Übernahme der Werte aus der Preconfigured Configuration Description.
    • Vorbelegung noch unberührter Modulparameter mit Werten aus der Recommended Configuration Description.
  3. Persistierung:
    • Ausgabe der konsolidierten, schema-konformen ECU Configuration Description.
  4. Feinjustierung (Iterativer Editor-Pfad):
    • Übergang in Edit ECU Configuration.
    • Der Integrator ergänzt ecu-lokale BSW-Treiber (z. B. Dio, Adc, Pwm), konfiguriert das OS (Tasks, Alarms, ISRs) und überschreibt bei Bedarf Werte aus der Recommended Configuration Description.

4. Normative Relevanz & Entwickler-Hinweise

  • Strikte Trennung von Definition und Wert: Entwickler müssen zwischen Definitionsmodell (EcucModuleDef, Schema) und Werteebelegung (EcucModuleConfigurationValues, Instanz) unterscheiden. BSW-Generatoren parsen Werte immer gegen die zugehörige Vendor Specific Module Definition.
  • Prioritätskaskade der Konfigurationswerte:
    1. Preconfigured: Höchste Priorität. Modifikationen durch den Integrator im Schritt Edit ECU Configuration führen zu Integrations- oder Validierungsfehlern, da Hardwarerestriktionen des Treibers/Stacks verletzt werden.
    2. System Extract Mapping: Werte mit direktem Bezug zur Kommunikationsmatrix (z. B. PduLength, PduId, CAN Controller Baudrate) sind bindend aus dem System Extract abzuleiten.
    3. Recommended: Dient als Initialwert; darf im Configurator explizit modifiziert werden.
  • Konsistenz-Restriktionen: Änderungen am System-Extrakt erfordern eine Wiederholung von Generate Base ECU Configuration Description. Konfiguratoren müssen dabei Mechanismen zur Beibehaltung bereits im Schritt Edit ECU Configuration manuell getätigter Nutzereinstellungen bieten (Merge-/Re-Import-Strategie).
