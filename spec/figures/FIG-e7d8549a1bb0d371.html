1. Diagrammtyp & Architektur-Kontext

  • Typ: UML-Sequenzdiagramm mit kombiniertem Fragment (alt-Kompakt-Entscheidungsbaum).
  • Funktionale Einordnung: AUTOSAR Adaptive Platform (AP), Functional Cluster State Management (SM, Document ID 908).
  • Technischer Zweck: Spezifikation des Start- und Reaktivierungsverhaltens eines StateMachine-Agenten bei Ausführung eines ActionListItem vom Typ „Start StateMachine“. Das Diagramm definiert den Lebenszyklus, die Dienstbereitstellung via Service-Oriented Communication (ara::com) sowie die Abarbeitung zustandsassoziierter Aktionslisten (ActionItemList).

2. Komponenten, Entitäten & Schnittstellen

  • «State Machine» Controller: Steuerungseinheit/Ausführungskontext innerhalb des State Management, die das ActionListItem auswertet und die Initialisierung bzw. den Zustandswechsel anfordert.
  • «State Machine» Agent: Kapselung der eigentlichen Zustandsautomaten-Instanz; verwaltet aktuellen Zustand, Transitionen und auszuführende ActionItemLists.
  • «Service[Agent]» StateMachineService: Bereitgestelltes ara::com-Service-Interface (Provided Port) zur externen Steuerung und Abfrage des StateMachine-Zustands.
  • «Service[Agent]» StateMachineNotification: Bereitgestelltes Event-/Notification-Interface (Provided Port via ara::com) zur Signalisierung von Status- und Zustandswechseln an externe Konsumenten.
  • Interaktionsbeziehungen:
  • Synchroner Aufruf: Start / Start(X) vom Controller an den Agent.
  • Dienst-Offer: OfferService() auf StateMachineService und StateMachineNotification an die Middleware (ara::com).
  • Synchrone Rückmeldung: Bestätigung started an den Controller.

3. Dynamisches Verhalten & Sequenzablauf

Der Ablauf teilt sich in vier disjunkte Pfade des alt-Fragments:

  1. Pfad 1: Agent inaktiv, kein Zielzustand spezifiziert [Agent not running; No Parameter]
  • Trigger: Start (parameterlos).
  • SWS_SM_00612: Transition in den modellierten Default-Initialzustand (Initial State).
  • SWS_SM_00618: Freigabe der Kommunikationsschnittstellen via Offer (StateMachineService, StateMachineNotification). Die Zustandsmaschine ist ab diesem Zeitpunkt extern erreichbar.
  • Synchroner Return: started an den Controller.
  • Post-Aktion: Abarbeitung der dem Initialzustand zugeordneten ActionItemList (processing ActionItemList associated with Initial state).
  1. Pfad 2: Agent inaktiv, Zielzustand X übergeben [Agent not running; State X requested]
  • Trigger: Start(X) mit Zielzustand $X$.
  • SWS_SM_00622: Direkter Übergang in den geforderten Zielzustand $X$ unter Umgehung des Initialzustands.
  • SWS_SM_00618: Freigabe via Offer an Service- und Notification-Interfaces.
  • Synchroner Return: started an den Controller.
  • Post-Aktion: Abarbeitung der zu Zustand $X$ definierten ActionItemList.
  1. Pfad 3: Agent bereits aktiv in Zustand Y, Zielzustand X übergeben [Agent running in State Y; State X requested]
  • Trigger: Start(X) auf bereits laufendem Agenten.
  • SWS_SM_00623: Reguläre Zustandstransition von $Y \to X$. Keine erneute Service-Offer (Dienste laufen bereits).
  • Synchroner Return: started an den Controller.
  • Post-Aktion: Abarbeitung der zu Zustand $X$ definierten ActionItemList.
  1. Pfad 4: Agent bereits aktiv in Zustand Y, kein Parameter [Agent running in State Y; No parameter]
  • Trigger: Start() auf bereits laufendem Agenten.
  • SWS_SM_00613: Idempotentes Verhalten / Null-Operation (no action). Zustand $Y$ bleibt unverändert erhalten.
  • Synchroner Return: started an den Controller. Keine Neuerfassung von Aktionen.

4. Normative Relevanz & Entwickler-Hinweise

  • Service Lifecycle Contract (SWS_SM_00618): ara::com::Skeleton::OfferService() darf erst ausgeführt werden, nachdem die interne Zustandsinitialisierung erfolgreich abgeschlossen ist. Das verhindert Race Conditions, bei denen externe Clients Methoden oder Field-Requests auf einem unvollständig initialisierten SM-Agenten absetzen.
  • Rückgabe vs. Aktionslisten-Abarbeitung: Das started-Signal wird synchron an den Controller zurückgegeben, während die zugeordnete ActionItemList getriggert wird. Implementierungen müssen sicherstellen, dass blockierende Aktionen innerhalb der Liste die Rückgabe des Start-Aufrufs nicht unzulässig verzögern (asynchrone Event-Queue/Worker-Thread-Konzeption).
  • Idempotenz (SWS_SM_00613): Mehrfache parameterlose Aufrufe von Start() führen zu keinem Fehler und keinem Reset des Agenten. Dies muss bei redundanten Initialisierungssequenzen im Adaptive-Startpfad berücksichtigt werden.
  • Parametrisierter Kaltstart (SWS_SM_00622): Erlaubt das direkte Übersteuern des Startzustands zur Laufzeit, ohne dass zwingend Einstiegs-Aktionen eines formalen Default-Initialzustands durchlaufen werden müssen.
