1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm / AUTOSAR ECUC-Metamodell (BSW Parameter Configuration Model).
  • Funktionaler Kontext: Konfiguration des Moduls SwCluC (Software Cluster Connection) in AUTOSAR Classic Platform (R21-11). Es definiert die Metamodell-Struktur für SwCluCComProxyBaseSocket, welcher als Kommunikations-Endpunkt auf Basisebene (Host/Base Software Cluster) dient, um Signale und I-PDUs des COM-Stacks über Partitions- und Clustergrenzen hinweg an abhängige Software Cluster (SWCLs) bereitzustellen.

2. Komponenten, Entitäten & Schnittstellen

ECUC-Konfigurationscontainer (EcucParamConfContainerDef)
  • SwCluCComProxy [0..1]: Wurzel-Container für den COM-Proxy innerhalb des SwCluC-Moduls.
    • Aggregiert via Komposition (+subContainer):
  • SwCluCComProxyBaseSocket [1..*]: Zentrale Entität des Base-Sockets; modelliert einen logischen Kommunikationskanal/Endpunkt des COM-Proxys im Basis-Cluster.
    • Aggregiert via Komposition (+subContainer):
      • ComUserModuleCnf [0..1] (from Com): Spezifische COM-Konfiguration des Moduls als PDU-Nutzer/Quelle.
  • EcucPartition [0..*] (from EcucPartition): Repräsentiert die OS- bzw. BSW-Ausführungspartition.
Referenzen (EcucReferenceDef / EcucForeignReferenceDef)
  • SwCluCResourceRef (EcucForeignReferenceDef):
    • Referenziert ein Element vom Typ CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE außerhalb des BSW-Konfigurationsbaums im System-Metamodell.
    • Ziel: SoftwareCluster::CpSoftwareClusterServiceResource.
  • SwCluCProxyEcucPartitionRef (EcucReferenceDef, [1..*]):
    • Verweist (+destination) auf mindestens eine EcucPartition, auf welcher dieser Base-Socket instanziiert und ausgeführt wird.
  • SwCluCComProxyUsedSatelliteRef (EcucReferenceDef, [0..1]):
    • Rekursive Verknüpfung (+destination) zurück auf einen SwCluCComProxyBaseSocket. Dient der Zuordnung eines Satelliten-Sockets bei verteilten Base-Satellite-Topologien.
System-Template-Entitäten (CP Software Cluster Resource Pool)
  • SoftwareCluster::CpSoftwareClusterResource (Stereotyp «Identifiable», abstrakt):
    • + globalResourceId: PositiveInteger [0..1]: Eindeutige clusterübergreifende Ressourcen-ID.
    • + isMandatory: Boolean [0..1]: Flag, ob die Ressource zwingend vorhanden sein muss.
  • SoftwareCluster::CpSoftwareClusterServiceResource:
    • Konkrete Subklasse / Generalisierung von CpSoftwareClusterResource; bildet die exportierte COM-Service-Ressource des Software-Clusters ab.

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

Da es sich um ein rein statisches BSW-Konfigurationsmetamodell handelt, existiert kein dynamischer Kontrollfluss. Das Laufzeitverhalten leitet sich aus der Struktur ab:

  • Kanal-Initialisierung: Bei der BSW-Initialisierung (SwCluC_Init) instanziiert das Modul pro konfiguriertem SwCluCComProxyBaseSocket interne Pufferstrukturen und bindet diese an die über SwCluCProxyEcucPartitionRef zugewiesene OS-Partition.
  • Inter-Partition-/Inter-Cluster-Dispatching: Eingehende oder ausgehende COM-Daten werden zur Laufzeit über die globalResourceId identifiziert.
  • Base-Satellite-Kopplung: Liegt eine Multicore-/Cross-Partition-Topologie vor, routet der Base-Socket Aufrufe über den durch SwCluCComProxyUsedSatelliteRef verknüpften Satelliten-Endpunkt via IPC/IOC an die Ziel-Partition.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationspflicht (ECUC_SwCluC_00131): Mindestens ein SwCluCComProxyBaseSocket (1..*) muss pro SwCluCComProxy deklariert werden. Jeder Base-Socket erfordert zwingend mindestens eine Partitionszuordnung (SwCluCProxyEcucPartitionRef mit Multiplizität 1..*).
  • Fremdreferenz-Validierung: Generatoren müssen sicherstellen, dass die durch SwCluCResourceRef referenzierte CpSoftwareClusterServiceResource im System-Description-ARXML existiert und eine konsistente globalResourceId besitzt.
  • BSW-Integration (Com-Stack): Wird ComUserModuleCnf konfiguriert, generiert das BSW-Tooling die Anbindung an den AUTOSAR COM-Router (Com_SendSignal / Com_ReceiveSignal bzw. Routing-Tabellen für Cluster-PDU-Fans).
  • Core-/Partitions-Schutz: Bei Verteilung über mehrere Cores (Multiplicity > 1 bei SwCluCProxyEcucPartitionRef oder Vorhandensein von SwCluCComProxyUsedSatelliteRef) sind die Schnittstellen über OS-IOC (Inter-OS-Application Communicator) oder atomare Ringpuffer gegen Cross-Core-Konkurrenz abzusichern.
