1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration (ECUC) Metamodell-Klassendiagramm (UML 2.0 Profil für BSW-Parameterdefinitionen).
  • Technischer Zweck: Spezifikation der Konfigurationsstruktur für Sende-Transportkanäle (CanTpTxNSdu) des CAN Transport Layers (CanTp, ISO 15765-2) innerhalb der AUTOSAR Classic Platform (R25-11).
  • Funktionale Einordnung: Dient als Konfigurationsanker für ausgehende N-SDUs zwischen der oberen Schicht (PduR) und der unteren Schicht (CanIf). Definiert Routing-Beziehungen, PDU-IDs, Pufferung, Adressierung, Padding sowie ISO-15765-2-konforme Protokoll-Timer (N_As, N_Bs, N_Cs).

2. Komponenten, Entitäten & Schnittstellen

Container-Hierarchie & Multiplizitäten
  • CanTpChannel (EcucParamConfContainerDef, [1..*]): Übergeordneter physischer/logischer Kanal.
    • Enthält per Komposition (+subContainer) CanTpTxNSdu ([0..*]): Konfigurationsinstanz einer dedizierten TX-N-SDU.
Sub-Container von CanTpTxNSdu
  • CanTpTxNPdu ([1..1]): Definiert die ausgehende physische N-PDU Richtung CanIf.
    • CanTpTxNPduRef (EcucReferenceDef, [1..1]): Referenz auf das globale PDU-Objekt im EcuC.
    • CanTpTxNPduConfirmationPduId (EcucIntegerParamDef, [1..1], min=0, max=65535, withAuto=true, symbolicNameValue=true): ID, über welche CanIf die Sende-Bestätigung an CanTp meldet (CanIf_TxConfirmation).
  • CanTpRxFcNPdu ([0..1]): Definiert die eingehende Flow-Control-N-PDU bei segmentierter Übertragung.
    • CanTpRxFcNPduRef (EcucReferenceDef, [1..1]): Referenz auf die FC-PDU.
    • CanTpRxFcNPduId (EcucIntegerParamDef, [1..1], min=0, max=65535, withAuto=true, symbolicNameValue=true): ID für CanTp_RxIndication bei Empfang des Flow-Control-Frames.
  • CanTpNTa ([0..1]): Target Address Container (ISO-15765-2 Zieladresse bei erweitertem/gemischtem Adressierungsmodus).
  • CanTpNSa ([0..1]): Source Address Container (ISO-15765-2 Quelladresse).
  • CanTpNAe ([0..1]): Address Extension Container (ISO-15765-2 Adresserweiterung für Mixed 11-/29-Bit).
Parameter & Referenzen von CanTpTxNSdu
  • CanTpTxNSduRef (EcucReferenceDef, [1..1]): Referenz auf die globale System-PDU (Bindeglied zur PduR).
  • CanTpTxNSduId (EcucIntegerParamDef, [1..1], min=0, max=65535, withAuto=true, symbolicNameValue=true): Handle-ID für den Aufruf von PduR an CanTp_Transmit.
  • CanTpTc (EcucBooleanParamDef, [0..1] bzw. default): Aktiviert Transmit Cancellation (CanTp_CancelTransmit).
  • Timing-Parameter (in Sekunden, EcucFloatParamDef):
    • CanTpNas ([1..1], min=0, max=INF): Übertragungszeit auf CAN-Ebene (N_As).
    • CanTpNbs ([0..1], min=0, max=INF): Wartezeit bis zum Eintreffen des nächsten Flow-Control-Frames (N_Bs).
    • CanTpNcs ([0..1], min=0, max=INF): Wartezeit bis zum Senden des nächsten Consecutive Frames nach FC (N_Cs).
  • Enumerations-Parameter:
    • CanTpTxPaddingActivation (EcucEnumerationParamDef):
      • CANTP_ON: Ungenutzte Bytes in Frames (SF oder letzter CF) werden mit Padding-Bytes aufgefüllt.
      • CANTP_OFF: DLC entspricht der tatsächlichen Nutzlastlänge (CAN FD bzw. unvollständige Classic-Frames, sofern buskonform).
    • CanTpTxTaType (EcucEnumerationParamDef):
      • CANTP_PHYSICAL: Punkt-zu-Punkt-Kommunikation (segmentiert mit Flow Control).
      • CANTP_FUNCTIONAL: 1-zu-N-Broadcast (in der Regel unsegmentiert als Single Frame beschränkt).
    • CanTpTxAddressingFormat (EcucEnumerationParamDef):
      • CANTP_STANDARD (11-Bit Identifier, Payload rein Nutzdaten/PCI).
      • CANTP_EXTENDED (erstes Payload-Byte ist Zieladresse N_TA).
      • CANTP_MIXED (11-Bit Identifier, erstes Byte ist N_AE).
      • CANTP_NORMALFIXED (29-Bit Identifier mit kodiertem N_TA und N_SA).
      • CANTP_MIXED29BIT (29-Bit Identifier mit N_AE im ersten Payload-Byte).

3. Dynamisches Verhalten & Sequenzablauf

  1. Sende-Initiierung: PduR ruft CanTp_Transmit(CanTpTxNSduId, &PduInfo) auf.
  2. Segmentierungsentscheidung:
    • Single Frame (SF): Passt die Nutzlast in einen SF (unter Berücksichtigung des gewählten CanTpTxAddressingFormat), wird PduR_CanTpCopyTxData getriggert und der Frame via CanIf_Transmit(CanTpTxNPduRef) abgesetzt. Timer N_As (CanTpNas) wird gestartet.
    • First Frame (FF): Bei Multi-Frame (nur zulässig für CANTP_PHYSICAL) wird der FF via CanIf_Transmit gesendet, N_As gestartet und nach Sendebestätigung (CanTpTxNPduConfirmationPduId) der Timer N_Bs (CanTpNbs) aktiviert.
  3. Flow Control Empfang:
    • CanIf signalisiert Empfang via CanTp_RxIndication(CanTpRxFcNPduId).
    • N_Bs stoppt. Falls FC = CTS (Continue to Send), wird N_Cs gestartet, bis der nächste Consecutive Frame (CF) bereitsteht.
  4. Consecutive Frames (CF): Iteratives Abrufen via PduR_CanTpCopyTxData im Rhythmus von STmin und Senden via CanIf_Transmit. Jeder CF überwacht N_As.
  5. Abbruchbedingungen:
    • Timeout von N_As, N_Bs oder N_Cs führt zum Abbruch der Transmission und Benachrichtigung via PduR_CanTpTxConfirmation(CanTpTxNSduId, E_NOT_OK).
    • Bei gesetztem CanTpTc = TRUE kann die Übertragung vorzeitig via CanTp_CancelTransmit(CanTpTxNSduId) abgebrochen werden.

4. Normative Relevanz & Entwickler-Hinweise

  • PDU-ID-Mapping-Vertrag:
    • CanTpTxNSduId muss exakt mit der von PduR generierten Quell-PDU-ID übereinstimmen.
    • CanTpTxNPduConfirmationPduId bildet die Rückruf-Schnittstelle von CanIf (CanIf_TxConfirmation) und muss mit dem entsprechenden CanIfTxPduId-Eintrag im CanIf synchronisiert sein.
  • FC-PDU-Entkopplung: Wenn CanTpTxTaType == CANTP_FUNCTIONAL, darf kein CanTpRxFcNPdu verarbeitet werden, da funktionale Adressierung im CAN-TP keine Multi-Frame-Transmission mit Flow Control unterstützt (RFC/ISO 15765-2 Verbot).
  • Adress-Kapselung: Bei Auswahl von Nicht-Standard-Formaten (CANTP_EXTENDED, CANTP_MIXED, CANTP_MIXED29BIT) muss der Stack-Entwickler sicherstellen, dass die Container CanTpNTa, CanTpNSa bzw. CanTpNAe konfiguriert sind, da der Treiber das entsprechende Adressierungsbyte in Byte 0 der CAN-Payload reservieren und die Nutzdatenbytes um 1 Offset nach hinten verschieben muss.
  • Padding-Vorschrift: Ist CanTpTxPaddingActivation == CANTP_ON, muss der CanTp-Treiber unvollständig gefüllte Datenrahmen (DLC < 8 für Classic CAN bzw. diskrete DLC-Schritte bei CAN FD) bis zur definierten DLC-Länge mit CanTpPaddingByte auffüllen. Bei CANTP_OFF müssen die DLCs exakt der Frame-Länge entsprechen.
