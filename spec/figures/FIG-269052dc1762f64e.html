1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Hardware-Blockdiagramm / Logisches Hardware-Sicherheitsarchitekturmodell (Security Perimeter & Trust-Boundary-Diagramm).
  • Technischer Zweck: Spezifikation der internen logischen Architektur der Secure Hardware Extension (SHE) nach HIS-/AUTOSAR-Standard sowie Definition der Isolation zwischen sicherheitskritischer Hardware-Domäne (Secure Zone) und ungesicherter Host-Domäne (ECU Controller).
  • Funktionale Einordnung: Hardwarebasierter Vertrauensanker (Root of Trust / On-Chip Crypto Peripheral) unterhalb des AUTOSAR Classic Crypto Stacks (Crypto Driver → CryIf → CSM). SHE stellt isolierte Schlüsselspeicher, symmetrische kryptografische Primitive (AES-128) und Hardware-Zustandsmaschinen bereit, um Schlüssel vor CPU-Zugriff, DMA-Angriffen und externen Debuggern (z. B. JTAG) zu schützen.

2. Komponenten, Entitäten & Schnittstellen

  • Secure Zone (SHE-Subsystem / Hardware-Sicherheitsdomäne):
    • Control Logic (Zustandsmaschine): Hardware-Controller zur Befehlsdekodierung (CMD_*), Rechtedurchsetzung (Security Flags, Schreib-/Auslesesperren) und Verwaltung des Zugriffs auf Speicher und Krypto-Core.
    • AES 128 Engine (Krypto-Primitive):
      • encode / decode: Symmetrische Ver- und Entschlüsselung (128-Bit-Blockgröße, ECB-/CBC-Modus).
      • CMAC: Cipher-based Message Authentication Code (NIST SP 800-38B) für Integritäts- und Authentizitätsprüfungen.
      • Miyaguchi-Preneel: Einweg-Kompressionsfunktion auf Basis von AES-128 für sichere Schlüsselableitungen (KDF) und das SHE-Key-Update-Protokoll.
    • RAM (Flüchtiger Schlüsselspeicher):
      • RAM_KEY (16 Byte): Temporärer Sitzungsschlüssel; flüchtig, wird bei Reset gelöscht.
      • PRNG_KEY (16 Byte) & PRNG_STATE (16 Byte): Interner Schlüssel und 128-Bit-Zustandsvektor des Pseudo-Zufallszahlengenerators.
    • ROM (Nicht-modifizierbarer Festwertspeicher):
      • SECRET_KEY (16 Byte): Halbleiterspezifischer Master-Geheimschlüssel (vom Chiphersteller injiziert; schützt SHE-Initialisierung und Debugger-Deaktivierung).
      • UID (15 Byte / 120 Bit): Weltweit eindeutige Chip-Identifikationsnummer (Unique Identifier) zur kryptografischen Bindung von Schlüsseln an ein spezifisches Silizium.
    • non-volatile (Nicht-flüchtiger Speicher, Flash/EEPROM):
      • MASTER_ECU_KEY (16 Byte): Autorisierungsschlüssel für privilegierte administrative Speicheroperationen.
      • BOOT_MAC_KEY (16 Byte) & BOOT_MAC (16 Byte): Integritätsschlüssel und Referenz-MAC für Secure Boot.
      • KEY_<n> (3 bis 10 Slots à 16 Byte, normativ KEY_1 bis KEY_10): Frei belegbare Anwendungsschlüssel für Applikationen/Stacks (z. B. SecOC).
      • PRNG_SEED (16 Byte): Persistenter Entropie-Startwert für den PRNG.
  • Ungesicherte Host-Domäne:
    • CPU (Host Controller Core): Führt AUTOSAR OS, BSW und Applikations-SWCs aus.
    • Regular Peripherals / Busses: Standard-Peripherie (CAN, LIN, FlexRay, Ethernet, Timer), angebunden an die CPU.
  • Schnittstellen & Trennlinien:
    • Hardware Boundary (Rote Trennlinie): Physische/logische Isolationsgrenze. Unterbindet direkten Bus-, DMA- oder Debug-Zugriff auf die SHE-Speicherzellen.
    • Host-SHE-Interface (Bidirektionaler Pfeil CPU ↔ Control Logic): Speicherabgebildete Register (MMIO) / Mailbox-Interface zur Übergabe von SHE-Kommandos, Parametern, Statusflags und Ergebnisblöcken (M_1–M_5).

3. Dynamisches Verhalten & Sequenzablauf

  • Befehlsabwicklung (Command/Response):
    1. Trigger: CPU schreibt Parameter/Datenblöcke in SHE-Eingaberegister und setzt den Command-Code (z. B. CMD_ENC_CBC, CMD_GENERATE_MAC, CMD_LOAD_KEY).
    2. Verarbeitung: Control Logic blockiert unberechtigten Zugriff, lädt den adressierten Schlüssel intern in die AES-Engine und führt die Operation gekapselt in Hardware aus. Schlüssel verlassen zu keinem Zeitpunkt im Klartext die Secure Zone.
    3. Abschluss & Synchronisation: Control Logic setzt ein Ready-/Status-Bit im Statusregister oder feuert einen dedizierten Hardware-Interrupt an die CPU.
  • Speicher-Update-Protokoll (CMD_LOAD_KEY):
    • Verwendet das normative M_1-M_2-M_3-Schema (Miyaguchi-Preneel & CBC-CMAC):
      • CPU übergibt ID, Auth-ID, Zählerstand und Chiffrat.
      • Control Logic verifiziert Authentizität über den autorisierenden Schlüssel (MASTER_ECU_KEY oder hierarchischer Vorgängerschlüssel), prüft den internen 28-Bit-Monotonie-Zähler (Replay-Schutz) und brennt Schlüssel/Security Flags in den NV-Slot.
      • Ausgabe von M_4/M_5 zur Rückbestätigung an die Host-CPU.
  • Secure Boot Sequenz:
    • Beim Release des System-Resets prüft die Control Logic vor Freigabe der CPU das konfigurierte Boot-Image im externen/internen Flash via BOOT_MAC_KEY (CMAC-Verifikation gegen BOOT_MAC). Bei Diskrepanz wird die CPU im Reset gehalten oder der Fehlerstatus ERC_SECURE_BOOT_FAILED signalisiert.
  • Fehlerbehandlung:
    • SHE liefert Fehlercodes im Fehlerregister (ERC_NO_ERROR, ERC_SEQUENCE_ERROR, ERC_KEY_NOT_AVAILABLE, ERC_KEY_EMPTY). Der AUTOSAR-Crypto-Treiber mappt diese auf CSM/Det-Rückgabewerte (z. B. E_NOT_OK, CRYPTO_E_KEY_NOT_VALID).

4. Normative Relevanz & Entwickler-Hinweise

  • Crypto Driver (MCAL) & CSM-Konfiguration:
    • Black-Key-Paradigma: Kein Lesezugriff auf Schlüsseldaten über die AUTOSAR-Schnittstelle. Crypto_KeyElementGet() darf für SHE-gespeicherte Schlüssel niemals Klartextdaten zurückgeben.
    • Schlüssel-Mapping: AUTOSAR-Crypto-Schlüssel-IDs müssen 1:1 auf die festen SHE-Slot-IDs (SHE_RAM_KEY, SHE_KEY_1 bis SHE_KEY_10, SHE_MASTER_ECU_KEY) gemappt werden.
    • Feste Schlüssellänge: Ausschließlich 128 Bit (16 Byte). Keine Unterstützung für asymmetrische Algorithmen (RSA/ECC) oder SHA-Hashes im SHE-Basisstandard.
  • NV-Speicher-Restriktionen & Flash-Wear-Out:
    • Normative Vorgabe: Mindestens 100 garantierte Schreibzyklen pro NV-Slot. NV-Keys dürfen nicht für hochfrequente Session-Schlüssel (z. B. im SecOC-Betrieb) genutzt werden; hierfür ist zwingend RAM_KEY zu verwenden.
  • Empty Memory Cell Detection:
    • Falls die zugrunde liegende NVM-/Flash-Technologie nicht nativ zwischen gelöschten Speicherzellen (0xFF / 0x00) und beschriebenen Zellen mit identischem Nutzdatenwert unterscheiden kann, verlangt AUTOSAR FO R25-11 ein transparentes, hardware-/treibergestütztes Statusbit je Memory-Slot.
  • UID-Bindung (15 Byte):
    • Die UID weicht mit 15 Byte (120 Bit) von typischen 128-Bit-Blöcken ab. Bei Ableitungsszenarien und Backend-Generierung von Update-Paketen (M_1–M_3) muss das standardisierte Padding/Alignment für 120-Bit-UIDs exakt nach SHE-Spezifikation eingehalten werden.

Specification of Secure Hardware Extensions AUTOSAR FO R25-11 Note: The functions of SHE rely on a detection of empty memory cells. If the underlying technology does not distinguish between erased cells and cells written with the same logical value, the implementation has to introduce another status bit for every memory slot to allow for the detection. The additional status bit has to be handled transparently to the user. Note: The initial value of the memory slots has to be used in conjunction with the memory update protocol described in Chapter 4.9 to initialize SHE. The value of the counter for every non-volatile memory slot has to be 0 after production. At least 100 successful write-cycles to the non-volatile memory must be guaranteed per memory slot by the implementation, more write cycles must be possible.
