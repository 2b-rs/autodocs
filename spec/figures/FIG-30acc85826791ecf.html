1. Diagrammtyp & Architektur-Kontext

UML-Objektdiagramm / Metamodell-Instanziierungsdiagramm gemäß AUTOSAR TPS ECU Configuration. Es veranschaulicht einen Ausschnitt der ECU Configuration Parameter Definition für das CAN Interface (CanIf) im Basic Software (BSW) Communication Stack, konkret die Definition von Konfigurationscontainern und ganzzahligen Parametern zur Konfiguration von Sende-PDUs (Tx PDUs).

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm definiert zwei Konfigurationscontainer und drei Parameter:

  • CanIfInitCfg (EcucParamConfContainerDef): Wurzelcontainer für die Initialisierungskonfiguration des CAN-Interface mit lowerMultiplicity = 1, upperMultiplicity = 1 und multipleConfigurationContainer = true.
  • CanIfTxPduCfg (EcucParamConfContainerDef): Über eine Komposition (+subContainer) eingebetteter Sub-Container mit lowerMultiplicity = 0 und upperMultiplicity = *, der jeweils eine Tx-PDU repräsentiert.
  • Drei über Kompositionsbeziehungen (+parameter) angebundene Parameter des Metatyps EcucIntegerParamDef:
    • CanIfTxPduCanId: Definiert die CAN-ID des Frames mit min = 0 und max = 536870911 (29-Bit Extended CAN Identifier).
    • CanIfTxPduDlc: Definiert die Nutzdatenlänge (DLC) mit min = 0 und max = 8 (Standard-CAN DLC).
    • CanIfTxPduId: Eindeutiger Bezeichner / Handle-ID mit min = 0, max = 4294967295 und symbolicNameValue = true.

3. Dynamisches Verhalten & Sequenzablauf

Als Metamodell-Ausschnitt für Parameterdefinitionen stellt das Diagramm eine rein statische Konfigurationsstruktur dar und beschreibt keine dynamischen Laufzeitinteraktionen oder Sequenzabläufe. Die funktionale Wirkung entfaltet sich in der Konfigurations- und Codegenerierungsphase: Basierend auf den Containerdefinitionen instanziiert das ECU-Konfigurationswerkzeug konkrete PDU-Einträge. Das Flag multipleConfigurationContainer = true erlaubt es, mehrere Konfigurationssätze für CanIfInitCfg vorzuhalten, die zur Initialisierungszeit (z. B. via CanIf_Init) ausgewählt werden.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm besitzt normative Relevanz für AUTOSAR-Konfigurationstools, Validierungsregeln und BSW-Generatoren:

  • Multiplizitäten: CanIfInitCfg ist obligatorisch und genau einmal zulässig ([1..1]), während CanIfTxPduCfg optional und mehrfach vorhanden sein darf ([0..*]). Die Parameter CanIfTxPduCanId, CanIfTxPduDlc und CanIfTxPduId besitzen mangels expliziter Angabe die Standard-Multiplizität [1..1].
  • Wertebereichsprüfung: Editoren und Generatoren müssen sicherstellen, dass CanIfTxPduCanId im Bereich [0..536870911] und CanIfTxPduDlc im Bereich [0..8] liegen.
  • Symbolische Namen: Durch symbolicNameValue = true an CanIfTxPduId müssen Generatoren eindeutige C-Makros bzw. Symbolbezeichner erzeugen, die überlagerte Module (z. B. PduR) für Sendeaufrufe (CanIf_Transmit) verwenden.
