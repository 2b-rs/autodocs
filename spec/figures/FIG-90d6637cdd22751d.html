1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm zur Spezifikation des Metamodells für Client-Server-Schnittstellen im AUTOSAR-Software-Component-Template. Es definiert die statische Struktur von ClientServerInterface mit dessen Operationen, Operationsargumenten sowie der Typisierung über Datentypen.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm umfasst folgende Metaklassen und Relationen:

  • PortInterface: Abstraktes Metamodellelement («atpType», ARElement) mit dem Attribut + isService :Boolean.
  • ClientServerInterface: Spezialisierung von PortInterface («atpType»). Enthält per Komposition über die Rolle +operation mindestens eine (1..*) OperationPrototype (+interface 1).
  • OperationPrototype: Metaklasse («atpStructureElement», Identifiable). Enthält per Komposition über die Rolle +argument eine geordnete Liste beliebiger Anzahl (* {ordered}) von ArgumentPrototype (1).
  • ArgumentPrototype: Spezialisierung der abstrakten Metaklasse DataPrototype («atpPrototype», Identifiable). Besitzt das Attribut + direction :DirectionKind.
  • DataPrototype: Assoziiert über die Beziehung «isOfType» (+type 1) genau einen Datatype («atpType», ARElement) für 0..* Instanzen.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm zeigt eine rein statische Metamodellstruktur. Ein dynamischer Ablauf ist nicht Gegenstand dieses Strukturdiagramms. Zur Laufzeit bzw. Konfigurationszeit bestimmt das Modell, dass ein Client-Server-Interface mindestens eine Operation bereitstellt und jede Operation geordnete Ein-/Ausgabeargumente definieren kann, deren Werteflüsse durch DirectionKind vorgegeben sind.

4. Normative Relevanz & Entwickler-Hinweise

Normativ für die Definition von Client-Server-Schnittstellen in Softwarekomponenten:

  • Jedes ClientServerInterface muss mindestens eine Operation (1..*) deklarieren.
  • Operationsargumente besitzen eine feste Reihenfolge ({ordered}) und eine explizite Übergaberichtung (direction: DirectionKind).
  • Jedes Argument ist ein DataPrototype und muss typisiert werden (+type 1 auf Datatype).
  • Die Service-Eigenschaft wird auf Schnittstellenebene über isService: Boolean gesteuert.
