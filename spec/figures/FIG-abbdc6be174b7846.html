1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm (Metamodell-Ausschnitt des AUTOSAR System Template, M2-Ebene).
  • Technischer Zweck: Modellierung der DLT-Konfigurations- und Extraktstrukturen, aufgeteilt in die Pakete Log And Trace Extract und System Template.
  • Funktionale Einordnung: Trennt die logische Log- und Trace-Beschreibungsstruktur (DltEcu, DltApplication, DltContext, LogAndTraceMessageCollectionSet, DltMessage, DltArgument) im Extrakt von der eigentlichen Kommunikations- und Modulkonfiguration des Steuergeräts (EcuInstance, DltConfig, DltLogChannel, PduTriggering, GeneralPurposeIPdu) im System Template.

2. Komponenten, Entitäten & Schnittstellen

#### Paket Log And Trace Extract

  • DltEcu (Spezialisierung von ARElement):
  • Repräsentiert das Steuergerät aus Sicht des Log-and-Trace-Extrakts mit dem Attribut ecuId: String [0..1].
  • Aggregiert per Komposition +application (0..*, «atpVariation,atpSplitable») Instanzen von DltApplication.
  • DltApplication (Spezialisierung von Identifiable):
  • Modelliert eine Software-Applikation mit applicationId: String [0..1] und applicationDescription: String [0..1].
  • Aggregiert per Komposition +context (0..*, «atpVariation,atpSplitable») Instanzen von DltContext.
  • Referenziert über +dltMessage (0..*, «atpVariation,atpSplitable») Instanzen von DltMessage.
  • DltContext (Spezialisierung von ARElement):
  • Modelliert einen Logging-Kontext mit contextId: String [0..1] und contextDescription: String [0..1].
  • Referenziert über +applicationContext (0..) DltApplication sowie über +dltMessage (0..) DltMessage.
  • LogAndTraceMessageCollectionSet (Spezialisierung von ARElement):
  • Aggregiert über +dltMessage (0..*, «atpVariation,atpSplitable») Nachrichten vom Typ DltMessage.
  • DltMessage (Spezialisierung von Identifiable):
  • Attribute: messageId: PositiveInteger [0..1], messageLineNumber: PositiveInteger [0..1], messageSourceFile: String [0..1], messageTypeInfo: String [0..1].
  • Aggregiert geordnet ({ordered}) über +dltArgument (0..*) Elemente vom Typ DltArgument.
  • DltArgument (Spezialisierung von Identifiable):
  • Attribute: length: PositiveInteger [0..1], optional: Boolean [0..1], predefinedText: Boolean [0..1], variableLength: Boolean [0..1].
  • Aggregiert rekursiv über +dltArgumentEntry (0..*) weitere DltArgument-Strukturen.
  • Aggregiert über +networkRepresentation (0..1, «atpSplitable») die Klasse SwDataDefProps («atpVariation»).

  • DltConfig:

  • Referenziert über +dltEcu (0..1) die Extraktklasse DltEcu.

  • DltLogChannel (Spezialisierung von Identifiable):

  • Referenziert über +txPduTriggering (0..1) und +rxPduTriggering (0..1) PduTriggering.
  • Kommunikations-Stack:
  • PduTriggering (Spezialisierung von Identifiable) referenziert über +iPdu (1) die Metaklasse Pdu.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm modelliert statische System-Deskriptoren (M2). Zur Laufzeit bestimmt diese Struktur folgende Signalflüsse:

```

[SWC / BSW]

│ Dlt_SendLogMessage(AppId, ContextId, LogLevel, ...)

▼

[DLT BSW Module] ── Formatiert DLT-Frame (Header: dltEcuId, Timestamp, SessionId, Payload)

│ Non-Verbose: messageId + kompakte Argument-Binärdaten

│ Verbose: Vollständige Typ-/Format-Deskriptoren im Stream

▼

[PduR / Com-Stack] ── Zuordnung über dltLogChannel.txPduTriggering -> GeneralPurposeIPdu

│ Transmit-Request

▼

[Bus Interface / Hardware-Treiber] (z. B. CanIf, EthIf) ── Ausstrahlung auf dem Bus

│

▼ (Gegenrichtung: Injektion / Filterung)

[Bus Interface / Hardware-Treiber] ── RxIndication über dltLogChannel.rxPduTriggering

▼

[DLT Control API] ── Dynamische Anpassung des Log-Status / Dlt_SetLogLevel()

```

  1. Log-Nachrichten-Generierung (TX):
  • Applikationen emittieren Logs unter Angabe von applicationId und contextId.
  • Das DLT-Modul serialisiert Header-Felder entsprechend der gesetzten Flags (sessionIdSupport, timestampSupport, dltEcuId).
  • Ist die Nachricht als Non-Verbose konfiguriert, wird die numerische messageId übertragen.
  • Weitergabe der serialisierten Payload an den Kommunikationsstack über die per txPduTriggering verknüpfte GeneralPurposeIPdu.
  1. Steuerung & Injektion (RX):
  • Externe DLT-Clients (z. B. DLT Viewer) senden Steuernachrichten an das Steuergerät.
  • Der Empfangspfad wird strikt über das am DltLogChannel referenzierte rxPduTriggering geroutet, welches Steuerbefehle an den DLT-Dispatcher übergibt.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Konformität: Definiert die getrennte Modellierung zwischen logischer Trace-Extraktbeschreibung (Log And Trace Extract) und der Systemkonfiguration (System Template).
  • Konfigurationsaspekte:
  • Ermöglicht den Austausch und die separate Versionierung des Log-and-Trace-Extrakts unabhängig vom Kommunikations- und Systemmodell der ECU.
  • DltLogChannel steuert Übertragungsmodi (z. B. Non-Verbose Mode, Schwellwerte für Trace/Log-Level und Segmentierung) und verbindet das Logging über optionale Triggerings (0..1) mit der PDU-Ebene.
