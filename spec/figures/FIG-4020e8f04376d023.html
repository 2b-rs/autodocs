1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (State Machine) zur Spezifikation des Zustands- und Betriebsmodus-Algorithmus des CAN Network Management (CanNm) innerhalb der AUTOSAR Classic Platform. Das Diagramm modelliert die übergeordneten Betriebsmodi des Netzwerkmanagements sowie die internen Subzustände des aktiven Netzwerkbetriebs im Zusammenspiel mit dem generischen AUTOSAR NM-Interface (Nm) und dem CAN-Treiber/Interface.

2. Komponenten, Entitäten & Schnittstellen

  • Modi und Zustände:
    • Bus-Sleep Mode (Ruhezustand)
    • Prepare Bus-Sleep Mode (Vorbereitung auf Ruhezustand)
    • Zusammengesetzter Zustand Network Mode mit den Subzuständen:
      • Repeat Message State (mit Entry-Aktion: Stop Bus Load Reduction)
      • Normal Operation State (mit Entry-Aktion: Start Bus Load Reduction)
      • Ready Sleep State
    • Pseudo-Zustände: Startzustand PowerOn, Endzustand PowerOff, Eingangsknoten/Verzweigungspunkt für Network Mode sowie Verzweigungsknoten Repeat Message.
  • Schnittstellenfunktionen (API & Callbacks):
    • Eingehend von Nm/BswM: CanNm_Init(), CanNm_PassiveStartup(), CanNm_NetworkRequest(), CanNm_NetworkRelease(), CanNm_RepeatMessageRequest().
    • Eingehend von CanIf: CanNm_RxIndication(), CanNm_TxConfirmation().
    • Ausgehend an Nm: Nm_NetworkStartIndication(), Nm_NetworkMode(), Nm_PrepareBusSleepMode(), Nm_BusSleepMode(), Nm_TxTimeoutException().
  • Timer:
    • NM-Timeout Timer
    • Repeat Message Timer
    • Wait Bus-Sleep Timer
    • Tx Timeout Timer

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung und Weckvorgang:
    • Übergang von PowerOn nach Bus-Sleep Mode via CanNm_Init() mit Initialisierung von CanNm. Aus Bus-Sleep Mode kann über PowerOff beendet werden.
    • Aus Bus-Sleep Mode führt CanNm_RxIndication() zur Benachrichtigung Nm_NetworkStartIndication() und zurück in den Bus-Sleep Mode.
    • Ein Eintritt in den Network Mode (über den Eintrittsknoten direkt in den Repeat Message State) erfolgt aus Bus-Sleep Mode über CanNm_PassiveStartup() oder CanNm_NetworkRequest(), sowie aus Prepare Bus-Sleep Mode über CanNm_RxIndication() oder CanNm_NetworkRequest(). Bei Eintritt über diesen Knoten werden der NM-Timeout Timer und der Repeat Message Timer gestartet sowie Nm_NetworkMode() aufgerufen.
  • Ablauf innerhalb von Network Mode:
    • Im Network Mode setzen interne Transitionen bei CanNm_RxIndication() und CanNm_TxConfirmation() den NM-Timeout Timer zurück (Neustart).
    • Nach Ablauf des Repeat Message Timer verzweigt der Ablauf am Knoten Repeat Message: Ist das Netzwerk angefordert ([Network Requested]), wechselt der Zustand in den Normal Operation State; ist das Netzwerk freigegeben ([Network Released]), wechselt er in den Ready Sleep State.
    • Aus Normal Operation State und Ready Sleep State führt der Empfang des Repeat-Message-Bits oder der Aufruf von CanNm_RepeatMessageRequest() unter Neustart des Repeat Message Timer zurück in den Repeat Message State.
    • Ein CanNm_NetworkRelease() im Normal Operation State führt in den Ready Sleep State.
    • Ein CanNm_NetworkRequest() im Ready Sleep State führt zurück in den Normal Operation State.
    • Läuft im Normal Operation State oder Repeat Message State der NM-Timeout Timer ab, wird er neu gestartet. Läuft der Tx Timeout Timer ab, wird Nm_TxTimeoutException() ausgelöst.
  • Übergang zum Ruhezustand:
    • Läuft im Ready Sleep State der NM-Timeout Timer ab, wechselt das System in den Prepare Bus-Sleep Mode; dabei wird der Wait Bus-Sleep Timer gestartet und Nm_PrepareBusSleepMode() aufgerufen.
    • Läuft im Prepare Bus-Sleep Mode der Wait Bus-Sleep Timer ab, erfolgt über Nm_BusSleepMode() der Wechsel in den Bus-Sleep Mode.

4. Normative Relevanz & Entwickler-Hinweise

  • Das Zustandsmodell definiert das normativ verbindliche Verhalten des AUTOSAR CAN Network Managements bezüglich Busüberwachung, Buslastreduktion und geordnetem Herunterfahren.
  • Implementierer müssen sicherstellen, dass alle Timer-Abläufe und Callbacks atomar bzw. deterministisch verarbeitet werden, insbesondere das Zusammenspiel zwischen CanNm_TxConfirmation(), CanNm_RxIndication() und dem NM-Timeout Timer.
  • Die Entry-Aktionen der Zustände steuern verbindlich die Buslastreduktionsmechanismen (entry / Stop Bus Load Reduction bzw. entry / Start Bus Load Reduction).
