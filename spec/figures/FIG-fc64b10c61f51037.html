1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Aktivitätsdiagramm (UML Activity Diagram) zur Spezifikation des sequenziellen Kontroll- und Datenflusses eines algorithmischen Einzelschritts.
  • Kontext: AUTOSAR Foundation (AUTOSAR_FO_PRS_E2EProtocol), gültig für Releases R22-11 und R23-11.
  • Technischer Zweck: Normative Festlegung des atomaren Extraktionsschritts „Read DataID“ innerhalb der E2E-Methodenprofile PXXm (z. B. E2E Profile 04m, 07m, 22m für Client-Server-/RPC-Kommunikation via SOME/IP). Die Extraktion dient als Eingangsoperation zur Erkennung von Masquerading-, Falschadressierungs- und Injektionsfehlern ([RS_E2E_08539], [PRS_E2E_01189]).

2. Komponenten, Entitäten & Schnittstellen

  • Aufrufende Prüfroutinen (Callers):
  • E2E_PXXmSourceCheck(): E2E-Prüffunktion auf Quell-/Client-Seite (Validierung empfangener Response-Nachrichten).
  • E2E_PXXmSinkCheck(): E2E-Prüffunktion auf Senken-/Server-Seite (Validierung eingehender Request-Nachrichten).
  • Platzhalter XX: Repräsentiert das jeweilige Methodenprofil (z. B. Profile 04m, 07m, 22m), welches die konkreten Längen, Offsets und CRC-Typen parametriert.
  • Datenobjekte & Parameter:
  • Data: Unstrukturierter Bytestring (const uint8*), der das empfangene Datenpaket inklusive E2E-Header kapselt.
  • Offset: Basis-Byteoffset der E2E-Daten innerhalb des Gesamtpuffers.
  • PXXMDATAID_POS: Profilspezifische relative Byteposition der DataID im E2E-Header.
  • PXXMDATAID_LEN: Profilspezifische Bytelänge der DataID (z. B. 2 Bytes bei 16-Bit-DataID, 4 Bytes bei 32-Bit-DataID).
  • ReceivedDataID: Lokale Variable des jeweiligen Basistyps (uint16 bzw. uint32), die den rekonstruierten Wert für nachfolgende Validierungen aufnimmt.
  • Notationselemente:
  • Initial Node (Startknoten) und Activity Final Node (Endknoten).
  • Action Node: „Copy DataID from bytestring Data to local variable ReceivedDataID in Big Endian order.“
  • Comment / Constraint Note: Formale Bereichsdefinition der Quellbytes im Puffer Data.

3. Dynamisches Verhalten & Sequenzablauf

  1. Initialisierung: Eintritt in den Teilschritt über den Startknoten, nachdem vorgelagerte Puffer- und Nullzeigerprüfungen der umschließenden Prüffunktion erfolgreich durchlaufen wurden.
  2. Byte-Extraktion & Deserialisierung:
  • Quellbereich im Bytestring:

$$\text{Start} = \text{Offset} + \text{PXXMDATAID\_POS}$$

$$\text{Ende} = \text{Offset} + \text{PXXMDATAID\_POS} + \text{PXXMDATAID\_LEN} - 1$$

  • Byte-Order: Unbedingte Rekonstruktion in Big-Endian-Reihenfolge (Most Significant Byte zuerst), unabhängig von der Endianness der Zielhardware.
  1. Abschluss: Direkte Transition zum Endknoten; Übergabe von ReceivedDataID an den nachgelagerten Prüfschritt (Soll-/Ist-Vergleich gegen die konfigurierte DataID gemäß [PRS_E2E_01190]).
  2. Ausführungseigenschaften: Synchron, deterministisch in $\mathcal{O}(1)$, frei von Verzweigungen, Callbacks (weder Det noch Dem) oder asynchronen Unterbrechungen.

4. Normative Relevanz & Entwickler-Hinweise

  • SWS-Konformität: Pflichtimplementierung für [PRS_E2E_01189] in AUTOSAR Classic (E2E Library / Transformer) und AUTOSAR Adaptive (ara::com E2E-Schutz).
  • Endianness & Bit-Shifting: Auf Little-Endian-Architekturen (z. B. ARM Cortex-M/R/A, x86) darf kein direkter Pointer-Cast auf den Bytestrom erfolgen. Die Rekonstruktion muss zwingend über explizite Shift-Operationen oder Byte-Swap-Intrinsics erfolgen:

```c

/ Beispiel für 16-Bit DataID (PXXMDATAID_LEN == 2) /

ReceivedDataID = (uint16)(((uint16)Data[pos] << 8) | (uint16)Data[pos + 1]);

```

  • Alignment & Safe Memory Access: Direkte Dereferenzierungen gecasteter Pointer ((uint16)&Data[...]) verstoßen gegen MISRA-C:2012 (u. a. Rule 11.3) und provozieren Alignment-Faults auf streng ausgerichteten Embedded-Kernen.
  • Puffergrenzen (Buffer Over-Read Schutz): Die umschließende BSW-/Library-Routine muss vor Eintritt garantieren, dass die Gesamtlänge von Data mindestens $\text{Offset} + \text{PXXMDATAID\_POS} + \text{PXXMDATAID\_LEN}$ Bytes beträgt. Andernfalls liegt ein E2E_E_INPUTERR_WRONG vor und dieser Teilschritt darf nicht ausgeführt werden.
