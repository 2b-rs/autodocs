1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Metamodell-Ausschnitt als UML-Klassendiagramm der AUTOSAR ECU Configuration Parameter Definition (ECUCParameterDefinitions).
  • Funktionale Einordnung: Definiert die formale Konfigurationsstruktur des BSW-Moduls DEM (Diagnostic Event Manager, System Services / Diagnostic Services Layer) für das Release AUTOSAR R2.1.20. Es spezifiziert den globalen Konfigurationscontainer DemGeneral sowie dessen skalare Parameter und Sub-Container zur Dimensionierung von Fehlerspeichern, NvM-Zugriffsstrategien, Callout-Präfixen und Basisparametern.

2. Komponenten, Entitäten & Schnittstellen

Metamodell-Hierarchie & Wurzel
  • AUTOSARParameterDefinition : EcuParameterDefinition aggregiert über +module (Multiplizität 0..1) das Modul Dem : ModuleDef.
  • Dem : ModuleDef aggregiert per Komposition +container (Kardinalität 1..1) den Pflichtcontainer DemGeneral : ParamConfContainerDef.
Skalare Konfigurationsparameter von DemGeneral (+parameter, Kardinalität 1..1 sofern nicht anders angegeben)
  • Allgemeine Schalter & Grenzwerte:
    • DemVersionInfoApi : BooleanParamDef: Aktivierung/Deaktivierung der API Dem_GetVersionInfo().
    • DemDevErrorDetect : BooleanParamDef: Aktivierung der DET-Entwicklungsfehlererkennung.
    • DemNumberOfEvents : IntegerParamDef: Maximal zu verwaltende Diagnoseereignisse (min = 0, max = 65535, defaultValue = 500).
    • DemBswErrorBufferSize : IntegerParamDef: Puffergröße für BSW-Fehler (min = 0, max = 255).
    • DemTypeOfDTCSupported : IntegerParamDef: Bitmaske/Format der unterstützten DTC-Klassifikation (min = 0, max = 31).
    • DemTypeOfOriginSupported : IntegerParamDef: Multiplizität 0..1 (min = 0, max = 7), spezifiziert die unterstützten Speicherorte (Event Memory Origins: Primary, Secondary, Mirror).
  • Speicherpuffer-Dimensionierung (Event Entries):
    • DemMaxNumberEventEntryPrm : IntegerParamDef: Maximale Einträge im Primärspeicher (min = 0, max = 65535, defaultValue = 30).
    • DemMaxNumberEventEntryMir : IntegerParamDef: Maximale Einträge im Spiegelspeicher (min = 0, max = 255, defaultValue = 0).
    • DemMaxNumberEventEntrySec : IntegerParamDef: Maximale Einträge im Sekundärspeicher (min = 0, max = 255, defaultValue = 0).
  • NVRAM-Zugriffsparameter:
    • DemNvmAccessRetry : IntegerParamDef: Anzahl Wiederholungsversuche bei fehlgeschlagenem NvM-Zugriff (min = 0, max = 255).
    • DemNvmAccessRetryTimeDelay : FloatParamDef: Zeitspanne zwischen NvM-Zugriffswiederholungen in Sekunden (min = 0.0, max = 65.535).
Sub-Container von DemGeneral (+subContainer)
  • DemEventParameter (0..65535): Container zur Einzeleventspezifikation (Entprellung, DTC-Mapping).
  • DemGroupOfDTCList (6..6): Genau sechs vordefinierte DTC-Gruppen (z. B. Powertrain, Chassis, Body, Network, All DTCs).
  • DemIndicator (0..255): Indikator-Definition (z. B. MIL). Enthält IndicatorID : IntegerParamDef (symbolicNameValue = true, min = 0, max = 255).
  • DemViewList (0..255): Diagnosesichten (Views). Enthält ViewID : IntegerParamDef (symbolicNameValue = true).
  • DemOemIdClass (0..*): OEM-Identifikatoren. Enthält DemOemID : IntegerParamDef (symbolicNameValue = true).
  • DemOperationCycleList (0..*): Definition von Betriebszyklen (z. B. Zündungszyklus, Driving Cycle).
  • DemNvramBlockIdList (0..*): NVRAM-Block-Zuordnung. Enthält DemNvramBlockId : IntegerParamDef (symbolicNameValue = true).
  • Callout- und Funktionspräfix-Container (0..*):
    • XxxDemTriggerOnEventStatusList mit Parameter PrefixDemTrigOnEventStatusList : StringParamDef: Generiert Funktionsrümpfe für Event-Statusänderungs-Callbacks.
    • XxxDemGetDataValByDataIdList mit Parameter PrefixGetDataValByDataIdList : StringParamDef: Generiert Funktionsrümpfe zur DID-Datenwertabfrage (Freeze Frames).
    • XxxDemGetExtDataRecordList mit Parameter PrefixGetExtDataRecord : StringParamDef: Generiert Callouts für Extended Data Records.

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

Als metamodellbasierte Parameterdefinition stellt das Diagramm keine Laufzeitsequenz dar. Die Parameter determinieren jedoch direkt folgende dynamische Ausführungspfade des DEM-Treibers:

  1. Statische Pufferallokation (Startup / Dem_Init):
    • RAM-Zuweisung für Event-Listen und Fehlerpuffer erfolgt fix auf Basis von DemNumberOfEvents, DemMaxNumberEventEntryPrm, DemMaxNumberEventEntryMir, DemMaxNumberEventEntrySec und DemBswErrorBufferSize.
  2. Asynchrone NVRAM-Persistierung & Fehlerbehandlung:
    • Bei Schreibfehlern in den NvM-Blöcken (DemNvramBlockId) triggert der DEM einen asynchronen Wiederholungsmechanismus: Er wartet die Dauer DemNvmAccessRetryTimeDelay ab und wiederholt den Schreibauftrag bis zu DemNvmAccessRetry-mal, bevor ein administrativer Persistierungsfehler (DET) gemeldet wird.
  3. Event-Status-Update & Callout-Trigger:
    • Meldet eine SW-C oder ein BSW-Treiber via Dem_SetEventStatus einen Fehlerzustand, iteriert der DEM über die konfigurierten Präfix-Callbacks (PrefixDemTrigOnEventStatusList) und ruft synchron/asynchron <Prefix>_DemTriggerOnEventStatus(...) auf.
    • Zur Erfassung von Freeze-Frame-Daten ruft der DEM zur Laufzeit die durch PrefixGetDataValByDataIdList und PrefixGetExtDataRecord definierten APIs auf.

4. Normative Relevanz & Entwickler-Hinweise

  • Speicherdimensionierung & Displacement: Die Summe aus DemMaxNumberEventEntryPrm, DemMaxNumberEventEntrySec und DemMaxNumberEventEntryMir bestimmt den RAM-Footprint der Fehlerdatenstrukturen. Ist DemMaxNumberEventEntryPrm erschöpft, greifen konfigurierte Verdrängungsstrategien (Displacement).
  • C-Präprozessor & Symbolische Namen: Parameter mit symbolicNameValue = true erzeugen im Generat C-Makros (z. B. DemConf_DemIndicator_<Name>). Diese müssen im Applikationscode und in Integrations-C-Dateien anstelle harter Integer-IDs genutzt werden.
  • Linker-Vertrag bei Callouts: Die Container XxxDemTriggerOnEventStatusList, XxxDemGetDataValByDataIdList und XxxDemGetExtDataRecordList erwarten korrespondierende C-Funktionen im BSW/ASW-Code. Weicht das konfigurierte Präfix vom implementierten Funktionsbezeichner ab, resultiert dies in unaufgelösten Linker-Symbolen (unresolved external symbols).
  • Timing-Restriktionen: DemNvmAccessRetryTimeDelay und DemNvmAccessRetry müssen so mit den Zykluszeiten der Dem_MainFunction() und der Shutdown-Sequenz (Dem_Shutdown()) abgestimmt sein, dass anstehende NVRAM-Schreibzyklen das Abschalten des Steuergeräts (ECU State Manager / EcuM) nicht unzulässig verzögern.
