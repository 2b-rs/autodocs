1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Technisches Bit- und Byte-Layout-Diagramm (PDU-Serialisierungs- und Signal-Packing-Schema).
  • Technischer Zweck & Einordnung:
    • Spezifiziert das Signal-Packing eines Multi-Bit-Signals über Byte-Grenzen hinweg innerhalb einer I-PDU für Big-Endian-Anordnung (mostSignificantByteFirst) im Rahmen des AUTOSAR_SystemTemplate.
    • Zeigt die Platzierung der Signal-Bits eines 9-Bit-Signals ab Bit-Offset 0 (byte0, Bit 0) über zwei aufeinanderfolgende Bytes (byte0 und byte1).
    • Dient als Referenz für Generatoren des Kommunikations-Stacks (Com) zur deterministischen Signal-Extraktion und -Kompaktierung.

2. Komponenten, Entitäten & Schnittstellen

  • Metamodell-Entitäten (System Template / M2):
    • ISignalToIPduMapping: Zuordnung des logischen Signals zur PDU.
      • Start-Position: Adressiert über Pfeilmarkierung Bit 0 von byte0.
      • Packing-Reihenfolge: Big-Endian-Schema (mostSignificantByteFirst).
    • ISignal: Nutzsignal mit 9 Bit Länge (Bits 8 bis 0).
    • IPdu: Kommunikations-PDU, dargestellt mit zwei aufeinanderfolgenden Bytes (byte0, byte1).
  • Bit- und Byte-Strukturen:
    • PDU-Byte-Reihenfolge: Sequenziell von links nach rechts (byte0 gefolgt von byte1).
    • Bit-Zellen innerhalb eines Bytes: 8 Bit je Byte, nummeriert/abgegrenzt durch gestrichelte Trennlinien.
  • Packing-Topologie:
    • Signal-Bit 8 (MSB) ist an Bit 0 von byte0 platziert (gekennzeichnet durch Pfeil Start).
    • Die restlichen Signal-Bits 7 bis 0 belegen absteigend die Bitpositionen des nachfolgenden Bytes byte1.
    • Die verbleibenden 7 höherwertigen Bits von byte0 sind unbesetzt.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches Bit-Mapping-Schema handelt, existiert kein Zustandsautomat; das dynamische Verhalten manifestiert sich in der Laufzeit-Serialisierung des BSW-Stacks (Com):

[Applikation: R-Port] 
       │ Rte_Write_<p>_<o>(data)
       ▼
   [AUTOSAR COM] ──► Puffer-Serialisierung (Packer)
       │             └─ Big Endian: MSB an Start-Position, LSBs in Folge-Byte
       ▼
   [I-PDU Puffer] ──► Übergabe via PduR_ComTransmit() an Interface (CanIf/FrIf/LinIf)
  • Tx-Pfad (Com_SendSignal / Com_MainFunctionTx):
    1. Das 9-Bit-Signal wird im PDU-Arbeitspuffer abgelegt.
    2. Gemäß Big-Endian-Mapping wird Bit 8 an Bit 0 von byte0 geschrieben.
    3. Bits 7–0 werden in byte1 serialisiert.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Verbindlichkeit:
    • Das Diagramm definiert das Verhalten für Big-Endian-Signal-Mapping über Byte-Grenzen, wenn die Startposition an das Byte-Ende grenzt.
    • Das MSB (Bit 8) liegt an der Startposition; die Folge-Bits rollieren in das numerisch nachfolgende Byte byte1.
  • Implementierungs- und Tooling-Hinweise:
    • Signal-Extraktoren und Codegeneratoren müssen sicherstellen, dass bei Überschreiten der Byte-Grenze in Big-Endian-Konfiguration das nächste Byte (byte1) adressiert wird.

  • Umkehrung der Big-Endian-Signalabbildung: Bei Big Endian byte order adressiert Startposition 5 nun das Least Significant Bit (2^0 an Bit 12, 2^9 an Bit 5) bzw. die Signalbits 2^9 … 2^4 belegen Byte 0 (Bits 5–0) und 2^3 … 2^0 belegen Byte 1 (Bits 15–12), statt zuvor MSB an Startposition 0.
  • Wiedereinführung der Little-Endian-Variante (Little Endian byte order:): Startposition 5 enthält 2^0, 2^1 an Bit 6, 2^2 an Bit 7, und die Bits 2^3 … 2^9 rollieren in Byte 1 (Bits 8–14).
  • Wegfall des Pfeils Start zur Kennzeichnung der Startposition (ersetzt durch blaue Zellenhinterlegung von Bit 5).

The packingByteOrder attribute deﬁnes the way byte frontiers are crossed when mapping data elements to I-PDUs.
