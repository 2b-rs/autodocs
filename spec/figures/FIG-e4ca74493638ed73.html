3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm beschreibt die statische Konfiguration für folgenden deterministischen PLCA-Round-Robin-Zyklus (IEEE 802.3cg):

  1. Beacon-Generierung: Node 0 (plcaLocalNodeId = 0, Coordinator) sendet periodisch das PLCA-BEACON-Signal auf dem Shared Medium und synchronisiert den Zyklus.
  2. Transmit Opportunity (TO) Scanning:
    • Ein Timer (plcaTransmitOpportunityTimer = 20) taktet die Sende-Slots durch (ID = 0 → 1 → 2 → 3).
    • Hat der zugeordnete Knoten Sendedaten im MAC-Puffer bereit, startet er die Übertragung. Das Medium gilt als belegt; alle anderen Knoten pausieren den TO-Zähler.
    • Hat der Knoten keine Daten, verstreicht der TO-Timer ungenutzt und die Berechtigung wechselt nach 20 TO-Einheiten inkrementell zur nächsten plcaLocalNodeId.
  3. Burst-Modus:
    • Sendet ein Knoten, darf er bis zu plcaMaxBurstCount aufeinanderfolgende Ethernet-Frames übertragen, solange das Zeitlimit plcaMaxBurstTimer nicht überschritten wird.
    • Nach Ablauf von Burst-Count/Timer oder Pufferleerung schaltet der PHY auf den nächsten TO-Slot weiter.
  4. Zyklus-Reset: Nach Erreichen von plcaLocalNodeCount = 4 initiiert Node 0 den nächsten Zyklus durch ein neues BEACON.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW- und MCAL-Generierung (Eth / EthIf / EthTrcv):
    • EthTrcv (Transceiver-Treiber): Die Parameter aus PlcaProps (plcaLocalNodeId, Burst-Limits) und CouplingPortConnection (plcaLocalNodeCount, plcaTransmitOpportunityTimer) fließen direkt in die MDIO/SMI-Registerkonfiguration des 10BASE-T1S-PHY (z. B. IEEE 802.3cg Clause 148 / Clause 45 Register für PLCA Control, ID und Timer).
    • Node ID 0 Restriktion: Genau ein Knoten im ARXML-Cluster darf plcaLocalNodeId = 0 besitzen. Fehlt dieser oder existieren Duplikate, schlägt die PLCA-Businitialisierung fehl (kein BEACON → Fallback auf CSMA/CD).
  • Bus-Dimensionierung & Worst-Case Latenzen (WCET):
    • plcaTransmitOpportunityTimer muss größer als die maximale Signallaufzeit über das Buskabel plus PHY-Reaktionszeiten gewählt werden (hier 20), um Kollisionen zu verhindern.
    • Die maximale Zykluszeit und damit das Latenz-Jitter für Echtzeit-PDUs wird direkt durch $\sum (\text{plcaMaxBurstCount}_i \times \text{FrameSize}_{\max})bzw.\text{plcaMaxBurstTimer}$ bestimmt. Entwickler müssen sicherstellen, dass die konfigurierten Burst-Werte die Bus-Schedules von PDU-Übertragungen höherer Schichten (Com, SomeIp) nicht verletzen.
  • Topologieprüfung:
    • Im System-Design-Tooling kennzeichnet die n-fache nodePort-Referenz an einer einzelnen CouplingPortConnection zwingend ein Multidrop-Segment. Switches entfallen auf diesem Pfad; Filtering- und Routing-Tabellen dürfen keine separaten Port-zu-Port-Forwarding-Regeln für diese ECUs instanziieren.
