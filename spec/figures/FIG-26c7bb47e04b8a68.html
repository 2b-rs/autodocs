1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Screenshot einer Autorenumgebung / GUI-Spezifikationsansicht (Eclipse/RCP-basiertes AUTOSAR AI-Tool).
  • Technischer Zweck: Modellierung und semantische Pflege standardisierter Bezeichnerfragmente (Keywords / Abbreviations) innerhalb des AUTOSAR Application Interface (AI) Frameworks (AUTOSAR_CP_EXP_AIUserGuide).
  • Funktionale Einordnung: Dient dem Entwurf von KeywordSets und Naming-Conventions für standardisierte AUTOSAR-Schnittstellen (Application Interfaces). Keywords fungieren als vordefinierte Bausteine zur deterministischen Generierung von Namen für Ports, Datentypen, Signale und Software-Komponenten-Elemente (Vermeidung proprietärer Namensdivergenzen im Multi-Partner-OEM/Tier-1-Ökosystem).

2. Komponenten, Entitäten & Schnittstellen

  • Hierarchische Verortung (ARXML-Pfad/Breadcrumb): AUTOSAR → AISpecification → KeywordSets_Blueprint → KeywordList → Accy.
  • Metamodell-Entität Keyword (abgeleitet von Identifiable):
    • Identifiable Attributes:
      • shortName: Accy (eindeutiger Identifier im AR-Package).
      • longName: Accuracy (sprachspezifisch, Attribut EN).
      • desc (Description): Semantische Definition inkl. Normenbezug (hier: Verweis auf ISO 5725 bezüglich Trueness und Precision).
      • introduction: Zusätzlicher Rich-Text / Wiki-Kontext zur Modellierungsbegründung.
    • Keyword Attributes:
      • abbrName: Accy (abgeleitete standardisierte Kurzform für C-Identifier / ARXML-ShortNames).
      • classification: Semantische Taxonomie-Zuordnung per Radio-Auswahl. Verfügbare Stereotypen/Klassen:
        • Mean / Environment / Device
        • Action / Physical Type
        • Condition / Qualifier (aktiv selektiert: Condition-Qualifier)
        • Index
        • Preposition
        • Unclassified
  • Arbeitsbereich / Properties View (unteres Panel):
    • Spiegelt die Metadaten des selektierten Modellelements wider:
      • uuid: Eindeutige persistente ID (2018-05-11_2).
      • Weitere Attribute: category, checksum, timestamp.
    • Parallele Arbeitsmodi-Tabs: Error Log, Operation History, Progress, Validation Results (Linting/Naming Checks gegen AI-Regeln), Metrics, Tabular View, Search.

3. Dynamisches Verhalten & Sequenzablauf

  • Autoren- und Validierungs-Workflow:
    1. Deklaration: Erzeugung des Blueprint-Elements Keyword unterhalb von KeywordList.
    2. Attributierung: Festlegung von Kurzform (Accy), Langform (Accuracy), technischer Definition und Klassifikation (Condition / Qualifier).
    3. Regelprüfung (AI Naming Rules): Der Tab Validation Results prüft automatisiert syntaktische Constraints (z. B. Case-Sensitivity, verbotene Sonderzeichen, Kollisionen mit bestehenden AI-Keywords).
    4. Export / Blueprint-Instanziierung: Transformation in .arxml-Repräsentationen zur Verwendung in PortInterface-, VariableDataPrototype- und DataType-Definitionen.

4. Normative Relevanz & Entwickler-Hinweise

  • Auswirkung auf SWC- und Schnittstellen-Design:
    • Entwickler dürfen für Qualifier-Begriffe keine abweichenden Abkürzungen erfinden (z. B. Acc oder Accur statt Accy), wenn Konformität mit AUTOSAR AI gefordert ist.
    • Die Klassifikation als Condition / Qualifier determiniert die Position des Keywords im zusammengesetzten Bezeichner (gemäß AUTOSAR AI Naming Composition Rules: typischerweise Präfix-/Suffix-Positionierung nach Signal-/Physischer Größe).
  • Konfigurations- & Toolchain-Vorgaben:
    • Blueprint-Keywords werden via AUTOSAR XML (.arxml) in die nachgelagerten Authoring-Tools (z. B. DaVinci Developer, SystemDesk) importiert.
    • Eine Verletzung der hinterlegten abbrName-Vorgaben führt zu Validierungsfehlern im RTE-Generator und bricht die Interoperabilität bei standardisierten Classic-Platform-Applikationsschnittstellen.
