1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Metamodell-Klassendiagramm (AUTOSAR M2 Metamodell, Software Component Template / SWCT).
  • Technischer Zweck: Modellierung von anwendungsspezifischen Port-Annotationen (SenderReceiverAnnotation) auf Port-Ebene (PortPrototype). Dient der formalen semantischen Beschreibung von Signalqualitäten (Rohwert vs. Filterung, Berechnung, Grenzwerte, Signalalter) pro Variablen-Datenelement (VariableDataPrototype) innerhalb einer Sender-Receiver-Kommunikation.

2. Komponenten, Entitäten & Schnittstellen

  • PortPrototype (Generalisierungen AtpBlueprintable, AtpPrototype):
    • Repräsentiert die Interaktionsstelle einer Software-Komponente (SWC).
    • Komposition: Hält 0..* Instanzen von SenderReceiverAnnotation über die Kompositionsrolle +senderReceiverAnnotation.
  • SenderReceiverAnnotation (Abstrakte Basisklasse, Generalisierung GeneralAnnotation):
    • Modell-Constraint: {"port's interface is a SenderReceiverInterface"}.
    • Attribute:
      • + computed: Boolean [0..1]: Kennzeichnet optional, ob der Signalwert algorithmisch berechnet ist.
      • + limitKind: DataLimitKindEnum [0..1]: Spezifiziert optional Grenzwerterwartungen.
      • + processingKind: ProcessingKindEnum [0..1]: Kennzeichnet optional den Aufbereitungsgrad des Signals.
    • Assoziation: Referenziert optional 0..1 VariableDataPrototype über die Assoziationsrolle +dataElement.
  • SenderAnnotation & ReceiverAnnotation (Spezialisierungen von SenderReceiverAnnotation):
    • SenderAnnotation: Spezifisch für PPortPrototype (Provide-Ports); erbt Basisattribute ohne Zusätze.
    • ReceiverAnnotation: Spezifisch für RPortPrototype (Require-Ports); enthält eine Komposition:
      • +signalAge: Komposition auf 0..1 Instanz von MultidimensionalTime zur Spezifikation des Signalalters.
  • VariableDataPrototype (Generalisierung AutosarDataPrototype):
    • Repräsentiert das konkrete Variablen-Datenelement des Sender-Receiver-Interfaces.
  • MultidimensionalTime:
    • Strukturierter Zeittyp zur präzisen Spezifikation von Zeitdauern.
    • Attribute:
      • + cseCode: CseCodeType [0..1]: Kodierung der physikalischen Zeiteinheit.
      • + cseCodeFactor: Integer [0..1]: Ganzzahliger Skalierungsfaktor zur Zeiteinheit.
  • Enumerationen:
    • «enumeration» ProcessingKindEnum: Literalwerte {none, raw, filtered} zur Unterscheidung von Rohdaten und vorverarbeiteten/gefilterten Messwerten.
    • «enumeration» DataLimitKindEnum: Literalwerte {none, min, max} zur Kennzeichnung von dynamischen Grenzwertsignalen.

3. Dynamisches Verhalten & Sequenzablauf

  • Entwurfs- & V-Modell-Phase: Statisches M2-Metamodell; kein direktes Laufzeit-/Sequenzdiagramm.
  • Metamodell-Auswertung (Contract Phase / System Configuration):
    1. SWC-Design: Jedem VariableDataPrototype innerhalb eines PortPrototype wird optional eine spezifische SenderReceiverAnnotation zugeordnet (z. B. Parallelexistenz eines raw- und eines filtered-Datenelements am selben Port).
    2. Kompatibilitätsprüfung: Modellierungs- und Generierungs-Tools verifizieren beim Port-Verbinden (ConnectorPrototype), ob Sender- und Receiver-Annotationen kompatibel sind (z. B. Matching von Signalaufbereitung oder Validierung von Sender-Periodizität gegen gefordertes signalAge).
    3. Tool-Auflösung: Nutzen zwei VariableDataPrototype-Elemente identische Port-Annotationsparameter, etabliert das Autorensystem jeweils explizite 1:1-Referenzen via +dataElement.

4. Normative Relevanz & Entwickler-Hinweise

  • Strikte Trennung von CompuMethod: Die Enumerationswerte von DataLimitKindEnum (none, min, max) spezifizieren die anwendungsbezogene Erwartungshaltung des Ports an Signal-Grenzwerte und dürfen nicht mit den statischen Min/Max-Attributen von CompuMethod verwechselt werden.
  • Zeitmodellierung via MultidimensionalTime: Die Anforderung an das Signalalter (signalAge) an Require-Ports wird formal strukturiert über MultidimensionalTime mit physikalischer Zeiteinheit (cseCode) und Multiplikator (cseCodeFactor) abgebildet.
  • Tool- und Codegenerierung: Die Zuordnung von Annotationen zu VariableDataPrototype erfolgt portbezogen; Codegeneratoren und Integrationswerkzeuge werten diese Angaben aus, um Pufferstrategien, Filterroutinen oder Signallaufzeit-Überwachungen im RTE- oder SWC-Rahmen zu konfigurieren.
