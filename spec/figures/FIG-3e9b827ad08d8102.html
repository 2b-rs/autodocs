1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU Configuration Parameter Definition Diagram (UML-Klassendiagramm auf Metamodell-Ebene basierend auf der AUTOSAR EcucParamConfContainerDef-Spezifikation).
  • Architektur-Kontext: AUTOSAR Classic Platform (Release R23-11), BSW-Treiber EthSwt (Ethernet Switch Driver, Teil des Ethernet-Hardware-Abstraction-Layers / MCAL).
  • Funktionaler Zweck: Formale Definition des Konfigurations-Containers EthSwtPortIngress zur Parametrierung der Ingress-Pipeline (Empfangspfad) eines Switch-Ports. Steuert VLAN-Handling (Default-VLAN, VLAN-Modifikation, Untagged-Filterung), Frame-Priorisierung (Default Priority, Priority Regeneration nach IEEE 802.1Q), Traffic-Class-Zuordnung, Ingress-Scheduling sowie die Bindung an TSN-Stream-Identifikationsmechanismen (EthSwtStreamIdentificationEntry).

2. Komponenten, Entitäten & Schnittstellen

Übergeordnete Container & Referenzierende Entitäten
  • EthSwtPort (EcucParamConfContainerDef, Multiplizität: 1..*): Übergeordneter Container für die portspezifische Switch-Konfiguration.
  • EthSwtStreamIdentificationEntry (EcucParamConfContainerDef, Multiplizität: 0..*): Externer Konfigurationscontainer für Stream Identification (IEEE 802.1CB / TSN).
    • Beinhaltet die Referenz EthSwtStreamIdentificationIngressPortRef (EcucReferenceDef, Multiplizität: 0..*), welche via Zielrolle +destination auf die Instanz von EthSwtPortIngress verweist.
Zentraler Ingress-Container
  • EthSwtPortIngress (EcucParamConfContainerDef, Multiplizität: 1..1 je Port via Komposition +subContainer von EthSwtPort): Zentraler Ingress-Knoten.
Parameter von EthSwtPortIngress
  • EthSwtPortIngressDefaultVlan (EcucIntegerParamDef):
    • Multiplizität: 0..1, Wertebereich: [0 .. 4094], Default: 1.
    • Weist ungetaggten Ingress-Frames die Standard-Port-VLAN-ID (PVID) zu.
  • EthSwtPortIngressDefaultPriority (EcucIntegerParamDef):
    • Multiplizität: 0..1, Wertebereich: [0 .. 7], Default: 0.
    • Weist ungetaggten Ingress-Frames die Standard-PCP (Priority Code Point) zu.
  • EthSwtPortIngressDropUntagged (EcucBooleanParamDef):
    • Multiplizität: 1..1, Default: false.
    • Verwirft alle ankommenden Frames ohne 802.1Q-VLAN-Tag, wenn auf true gesetzt.
  • EthSwtPortIngressVlanModification (EcucIntegerParamDef):
    • Multiplizität: 0..1, Wertebereich: [0 .. 4095].
    • Steuert hardwareseitige VLAN-ID-Modifikation/Remapping auf dem Ingress-Port.
  • EthSwtPortTrafficClassAssignment (EcucIntegerParamDef):
    • Multiplizität: 0..1, Wertebereich: [0 .. 7].
    • Portweite Standard-Traffic-Class für unklassifizierten oder prioritätsunabhängigen Datenverkehr.
SubContainer von EthSwtPortIngress
  • EthSwtPortPriorityRegeneration (EcucParamConfContainerDef):
    • Multiplizität: exakt 8..8 Instanzen (Zuordnungstabelle für jede der Prioritäten 0 bis 7 gemäß IEEE 802.1Q).
  • EthSwtPortPriorityTrafficClassAssignment (EcucParamConfContainerDef):
    • Multiplizität: 0..8 Instanzen.
    • Mappt ankommende (oder regenerierte) Prioritäten (EthSwtPortPriorityTrafficClassAssignmentRegeneratedPriority) auf interne Traffic Classes (EthSwtPortPriorityTrafficClassAssignmentTrafficClass).
  • EthSwtPortOutboundVlanPriorityAssignment (EcucParamConfContainerDef):
    • Multiplizität: 0..8 Instanzen.
    • Legt die Ausgangspriorität in Abhängigkeit von Ingress-VLAN und Port-Priorität fest.
  • EthSwtPortIngressScheduler (EcucParamConfContainerDef):
    • Multiplizität: 0..* Instanzen.
    • Konfiguriert Ingress-Scheduling-Algorithmen (z. B. Bandbreitenbegrenzung, Ingress Rate Limiting, Metering).

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches Daten-/Metamodell handelt, manifestiert sich das dynamische Verhalten in der Frame-Processing-Pipeline der Switch-Hardware zur Laufzeit:

[Ingress Frame am EthSwtPort]
         │
         ├──> [Ist Frame ungetagged?]
         │          │
         │          ├── (Ja) ──> [EthSwtPortIngressDropUntagged == true?]
         │          │                   ├── (Ja) ──> DROP Frame
         │          │                   └── (Nein) ─> Setze VID = IngressDefaultVlan
         │          │                                 Setze PCP = IngressDefaultPriority
         │          │
         │          └── (Nein) ─> Frame behält empfangenes VLAN-Tag (bzw. IngressVlanModification)
         │
         ├──> [Priority Regeneration aktiviert?] (EthSwtPortPriorityRegeneration, 8 Einträge)
         │          ├── (Ja) ──> Regenerierte Priorität = Tabellen-Lookup[PCP]
         │          └── (Nein) ─> Regenerierte Priorität = PCP
         │
         ├──> [Traffic Class Assignment] (EthSwtPortPriorityTrafficClassAssignment, 0..8)
         │          ├── Prioritätsbasiert ──> TrafficClass = Mapping(Regenerierte Priorität)
         │          └── Fallback ───────────> TrafficClass = EthSwtPortTrafficClassAssignment
         │
         ├──> [Stream Identification Matching] (EthSwtStreamIdentificationEntry via IngressPortRef)
         │          └── TSN / 802.1CB Stream-Filterung & Metering
         │
         └──> [Ingress Scheduling & Weiterleitung] (EthSwtPortIngressScheduler)
                    └── Bandwidth Enforcement / Weitergabe an Switching Core / Egress Queues

4. Normative Relevanz & Entwickler-Hinweise

  • Treiber-Initialisierung (EthSwt_Init): Die Werte aus EthSwtPortIngress werden bei der BSW-Generierung in konstante Hardware-Registertabellen übersetzt. Der Treiber muss die Switch-ASIC-Register für Port-VLAN-ID (PVID), Tag-Acceptance (Discard Untagged) und Prioritäts-Lookup-Tabellen deterministisch zur Boot-Zeit programmieren.
  • Vollständigkeit der Tabellen:
    • EthSwtPortPriorityRegeneration fordert strikt 8..8 Multiplizität; die Konfiguration muss alle 8 PCP-Stufen (0 bis 7) vollständig abbilden, andernfalls schlägt die Generator-Validierung fehl.
    • EthSwtPortPriorityTrafficClassAssignment erlaubt 0..8 Container. Werden keine separaten Mappings definiert, muss der Fallback-Parameter EthSwtPortTrafficClassAssignment gesetzt sein, um undefiniertes Routing in der Switch-Queue zu verhindern.
  • VLAN-Interoperabilität: Wenn EthSwtPortIngressDropUntagged = false konfiguriert ist, muss EthSwtPortIngressDefaultVlan (Default: 1) im globalen VLAN-Filter des Switches registriert sein, da ansonsten ungetaggte Pakete zwar den Ingress-Port passieren, aber im Switch-Core mangels gültiger VLAN-Membership verworfen werden.
  • TSN / AVB Relevanz: Die Referenz EthSwtStreamIdentificationIngressPortRef bindet Ingress-Ports exklusiv an IEEE 802.1CB Frame Replication and Elimination for Reliability (FRER) oder Per-Stream Filtering and Policing (PSFP). Fehlt dieser Verweis, greift für den Port ausschließlich die standardmäßige Prioritäts-/Traffic-Class-Verarbeitung.
