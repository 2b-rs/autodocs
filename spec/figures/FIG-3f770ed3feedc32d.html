1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECUC-Konfigurations-Metamodell (UML-Klassendiagramm zur Definition von Konfigurationsparametern und -containern) kombiniert mit normativen Tabellenauszügen der Parameterspezifikation.
  • Architektur-Kontext: Modul FrIf (FlexRay Interface, SWS Kapitel 10) in der AUTOSAR Classic Communication Stack Architecture (ComStack / MCAL-Abstraktion).
  • Funktionaler Zweck: Modellierung des Mappings zwischen den logischen Controller-/Transceiver-Instanzen des FrIf und den hardwarenahen MCAL-Treibern (Fr-Treiber für Controller, FrTrcv-Treiber für Transceiver-Kanäle) zur Abbildung physischer FlexRay-Cluster-Topologien (Kanal A und B).

2. Komponenten, Entitäten & Schnittstellen

ECUC-Container & Kardinalitäten
  • FrIfController (EcucParamConfContainerDef):
    • Multiplizität: 1..* (mindestens ein Controller im Interface definiert).
    • Repräsentiert die logische Controller-Instanz innerhalb des FlexRay-Interface.
    • Enthält Sub-Container:
      • FrIfTransceiver: Multiplizität 1..2 (realisiert die Zuordnung von bis zu zwei Transceivern für redundante Kanäle A/B pro Controller).
      • Laut Tabelle zusätzlich aggregiert: FrIfFrameTriggering (1..*) und FrIfLPdu (1..*).
  • FrController (EcucParamConfContainerDef):
    • Multiplizität: 1..*.
    • Zielcontainer im Hardware-Treiber (Fr-Modul).
  • FrTrcvChannel (EcucParamConfContainerDef):
    • Multiplizität: 1..*.
    • Zielcontainer im Transceiver-Treiber (FrTrcv-Modul).
Parameter & Literale
  • FrIfCtrlIdx (EcucIntegerParamDef):
    • Parameter von FrIfController.
    • Wertebereich: 0 .. 31, symbolicNameValue = true. Index des virtuellen Controllers im FrIf.
  • FrCtrlIdx (EcucIntegerParamDef):
    • Parameter von FrController.
    • Wertebereich: 0 .. 255, symbolicNameValue = true. Physischer Hardware-Index im MCAL-Treiber.
  • FrIfClusterChannel (EcucEnumerationParamDef):
    • Parameter von FrIfTransceiver.
    • Literale: FRIF_CHANNEL_A, FRIF_CHANNEL_B. Weist dem Transceiver den FlexRay-Buskanal zu.
Referenzen (EcucReferenceDef)
  • FrIfFrCtrlRef:
    • Typ: Symbolische Namensreferenz von FrIfController auf Ziel (+destination) FrController.
    • Eigenschaft: requiresSymbolicNameValue = true.
    • Post-Build-Variantenfähig: Post-Build Variant Value = true. Konfigurationsklasse in allen Bindungszeitpunkten (VARIANT-PRE-COMPILE, VARIANT-LINK-TIME, VARIANT-POST-BUILD) mit X belegt.
  • FrIfFrTrcvChannelRef:
    • Typ: Symbolische Namensreferenz von FrIfTransceiver auf Ziel (+destination) FrTrcvChannel.
    • Eigenschaft: requiresSymbolicNameValue = true.

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

  • Statisches Metamodell: Es liegt kein dynamischer Laufzeit-Sequenzablauf vor.
  • Initialisierungs-/Auflösungsdynamik:
    1. Die Konfiguration bindet den logischen Index FrIfCtrlIdx an den physischen MCAL-Controller FrController (FrCtrlIdx).
    2. Zur Laufzeit übersetzen die FrIf-APIs (z. B. FrIf_ControllerInit, FrIf_SetState) den Parameter FrIfCtrlIdx über Tabellen-Lookups synchron in den adressierten FrCtrlIdx des MCAL-Treibers Fr_SetAbsoluteTimer, Fr_AllowColdstart, etc.
    3. Transceiver-Steuerbefehle werden anhand von FrIfClusterChannel an den referenzierten FrTrcvChannel dispatcht (FrTrcv_SetTransceiverMode).

4. Normative Relevanz & Entwickler-Hinweise

  • Entkopplung logischer und physischer Indizes: API-Aufrufer oberhalb des FrIf (z. B. FrSM) nutzen ausschließlich FrIfCtrlIdx (0..31). Treiber-Entwickler müssen beachten, dass FrIfCtrlIdx nicht zwingend identisch mit FrCtrlIdx (0..255) ist; der BSW-Generator erzeugt dafür Zuordnungstabellen.
  • Dual-Channel-Restriktion: Die Multiplizität 1..2 von FrIfTransceiver erzwingt die FlexRay-Protokollbegrenzung auf maximal zwei physische Kanäle (A und B) pro Kommunikations-Controller.
  • Post-Build-Flexibilität: Da FrIfFrCtrlRef die Eigenschaft Post-Build Variant Value = true besitzt, kann das Mapping zwischen logischem Interface-Controller und MCAL-Controller für unterschiedliche ECU-Derivate post-build rekonfiguriert werden, ohne den Code neu zu kompilieren.
  • Symbolic Names: Sowohl FrIfCtrlIdx als auch die Zielreferenzen fordern symbolicNameValue = true. In generierten C-Headern müssen entsprechende Makrodefinitionen (#define FrIfConf_FrIfController_<Name> ...) für typsichere Aufrufe bereitgestellt werden.
