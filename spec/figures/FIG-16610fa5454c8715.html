1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML 2.0 Sequenzdiagramm mit kombiniertem Interaktionsfragment (alt / conditional polling vs. blocking wait).
  • Architektur-Kontext: AUTOSAR Classic Platform (Release 4.3.1), Schicht der System Services (BSW).
  • Funktionaler Zweck: Exemplarische Darstellung ((this is an example)) des shutdown-synchronisierenden Handshakes zwischen Master-Core und $n$ Slave-Cores im ECU State Manager (EcuM) unter Nutzung des Multicore-Betriebssystems (McOs). Sicherstellung einer geordneten BSW-Deinitialisierung aller Cores vor dem finalen, synchronisierten OS-Core-Shutdown via ShutdownAllCores().

2. Komponenten, Entitäten & Schnittstellen

  • Ausführungsebenen / Partitionen:
  • Master Core: Führender Prozessorkern für Koordination, BswM-Triggerung und OS-Shutdown.
  • Slave Core n: Generische Repräsentation der $1..N$ Sekundärkerne.
  • Instanzen / Lebenslinien:
  • <<module>> :BswM: Basic Software Mode Manager auf dem Master-Core (Initiator des Shutdown-Requests).
  • <<module>> Master :EcuM: EcuM-Zentralinstanz auf dem Master-Core.
  • <<module>> Master :McOs: AUTOSAR Multicore Operating System Instanz auf dem Master-Core.
  • <<module>> Slave n :EcuM: Lokale EcuM-Satelliteninstanz auf Slave-Core $n$.
  • <<module>> :McOs (Slave-Core-seitig): Lokaler Betriebssystem-Kontext auf Slave-Core $n$.
  • Schnittstellen & Interaktionsprimitive:
  • EcuM_GoDownHaltPoll(Std_ReturnType, uint16): API-Aufruf von BswM an Master-EcuM zur Einleitung der Deinitialisierungs- bzw. Shutdown-Sequenz im Multicore-Betrieb.
  • EcuM_MainFunction(): Zyklischer oder Core-übergreifend aktivierter Eintrittspunkt zur Abarbeitung der lokalen EcuM-Zustandsmaschine auf dem Slave-Core.
  • Inter-Core Shared Flag: Shared-Memory-Statusindikator (Set a shutdown flag / Unset the shutdown flag) zur signalisierten Core-Entkopplung.
  • OS-Services:
  • SetEvent(TaskId, Mask): Inter-Core-fähiger OS-Service; signalisiert dem Master-Core die Beendigung der BSW-Deinitialisierung des Slaves.
  • WaitEvent(Mask): Blockierender OS-Aufruf auf dem Master-Core (Extended Task).
  • GetEvent(Mask): Nicht-blockierende Zustandsabfrage der Event-Maske auf dem Master-Core.
  • ShutdownAllCores(StatusType): Finaler AUTOSAR OS-Dienst zur simultanen Überführung aller Cores in den Shutdown-Hook / Reset.

3. Dynamisches Verhalten & Sequenzablauf

  1. Shutdown-Initiierung: BswM ruft synchron auf dem Master-Core EcuM_GoDownHaltPoll(...) auf.
  2. Flag-Broadcasting: Master :EcuM setzt ein global sichtbares shutdown flag im shared RAM, welches für alle Slave-EcuM-Instanzen lesbar ist.
  3. Slave-Triggerung: Master :EcuM stößt (direkt oder über Scheduler/IOC) EcuM_MainFunction() auf Slave Core n an.
  4. Parallele BSW-Deinitialisierung:
  • Master :EcuM durchläuft die lokale BSW De-Initialization on Master Core.
  • Parallel vollzieht Slave n :EcuM die BSW De-Initialization on Slave Core.
  1. Slave-Quittierung: Nach Abschluss der Deinitialisierung ruft Slave n :EcuM SetEvent(TaskId, Mask) auf, adressiert an die wartende Task auf dem Master-Core.
  2. Master-Synchronisationsschleife (alt loop until all cores done):
  • Regelpfad (Standard): Master :EcuM ruft WaitEvent(Mask) auf und suspendiert, bis das Event des Slaves eintrifft.
  • Sonderpfad ([resource or spinlock already taken]): Falls im aktuellen Task-Kontext bereits OSEK-Ressourcen oder AUTOSAR-Spinlocks gehalten werden (wodurch blockierende Aufrufe nach OS-Standard verboten sind), wechselt EcuM auf Polling via GetEvent(Mask).
  1. Flag-Bereinigung & Abschluss: Nach erfolgreichem Empfang aller Quittierungs-Events setzt Master :EcuM das Shutdown-Flag zurück (Unset the shutdown flag).
  2. OS-Terminierung: Aufruf von ShutdownAllCores(StatusType) auf dem Master-Core; das OS stoppt die Ausführung aller Cores synchron.

4. Normative Relevanz & Entwickler-Hinweise

  • Nicht-normativer Beispielcharakter: Da explizit als (this is an example) klassifiziert, schreibt AUTOSAR nicht zwingend OS-Events für die Inter-Core-Synchronisation vor. Zulässig sind alternativ Inter-Core-Interrupts (ICU/CDD), polling-basierte Software-Flags oder IOC-Queues.
  • Task-Konfiguration & OSEK-Restriktionen:
  • Der Aufruf von WaitEvent() erzwingt, dass die EcuM-Shutdown-Sequenz auf dem Master-Core in einer Extended Task läuft.
  • Ist der EcuM-Shutdown in einer Basic Task konfiguriert oder hält während der Deinitialisierung einen AUTOSAR-Spinlock (GetSpinlock()), führt WaitEvent() zu einem fatalen OS-Fehler (E_OS_DISABLEDINT / E_OS_RESOURCE). In diesem Szenario ist die Implementierung strikt auf die dargestellte Polling-Alternative mit GetEvent() zu begrenzen.
  • Speichermodell & Cache-Kohärenz: Das gesetzte shutdown flag muss zwingend in einer Non-Cached, Shared-Memory-Region oder einer kohärenten Core-Bridge platziert sein. Vor und nach dem Zugriff sind HW-Memory-Barriers erforderlich, um Out-of-Order-Zugriffe der Pipeline vor dem OS-Event zu verhindern.
  • Timeout- & Deadlock-Vermeidung: In Serien-Stacks darf die Schleife loop until all cores done nicht unbegrenzt blockieren. Bleibt ein Slave-Core in einer Treiber-Deinitialisierung (z. B. hängender SPI-/Flash-Waitstate) hängen, muss ein parametrierbarer Timeout greifen, der via Det/Dem berichtet und den Shutdown forciert, um ein Entladen der Fahrzeugbatterie (Quiescent Current) zu verhindern.
