2. Komponenten, Entitäten & Schnittstellen

  • Aktivität / Scope:
  • E2E_P22Forward(): Bibliotheksfunktion zur Weiterleitung geschützter E2E-Botschaften (z. B. Gateway-Szenarien oder Forwarding zwischen Sicherheitsdomänen).
  • Eingangsparameter & Datenstrukturen:
  • Config (In-Parameter, Zeiger): Zeiger auf konstante Profilkonfiguration (const E2E_P22ConfigType*), u. a. enthaltend:
  • Config->DataLength: Gesamtlänge der Daten in Bits.
  • Config->Offset: Bit-/Byte-Offset des E2E-Headers (Counter und CRC).
  • State (In/Out-Parameter, Zeiger): Zeiger auf den Zustands-Deskriptor (E2E_P22ProtectStateType* bzw. Forward-State) zur Verwaltung des sequenziellen Alive-Counters.
  • Data (In/Out-Parameter, Zeiger): Zeiger auf den PDU-Byte-Array-Puffer (uint8*).
  • Length (In-Parameter, Wert/Skalar): Länge der PDU in Bytes (uint16).
  • ForwardStatus (In-Parameter): Status der vorhergehenden Prüfung der Eingangsdaten (Typ E2E_PCheckStatusType bzw. Pointer darauf).
  • Entscheidungsknoten (Decision Nodes):
  1. Null-Pointer-Guard: (Config != NULL) && (State != NULL) && (Data != NULL) && (ForwardStatus != NULL).
  2. Range-/Plausibility-Guard: Length == Config->DataLength/8 && Length >= Offset+2 && (ForwardStatus != E2E_P_NONEWDATA).
  • Aktivitätsendknoten (Activity Final Nodes):
  • no input (synonym zu null input): Tritt bei mindestens einem Null-Pointer auf.
  • wrong input: Tritt bei Längenmismatch, Offset-Verletzung oder fehlenden Neudaten auf.
  • input ok: Tritt bei vollständig validen Eingangsparametern ein.

3. Dynamisches Verhalten & Sequenzablauf

Der Kontrollfluss verläuft streng synchron und deterministisch innerhalb des Funktionsaufrufs von E2E_P22Forward():

  1. Initialer Eintritt: Start am Initial Node nach Call von E2E_P22Forward().
  2. Kaskadierte Pfad-Evaluation:
  • Stufe 1 (Null-Prüfung):
  • Evaluation des booleschen Ausdrucks: Sind alle Referenzen (Config, State, Data, ForwardStatus) ungleich NULL?
  • [FALSE] $\rightarrow$ Verzweigung zum Endzustand no input. Abbruch der Funktion mit Rückgabewert E2E_E_INPUTERR_NULL. Keine Zustandsänderung.
  • [TRUE] $\rightarrow$ Übergang zu Stufe 2.
  • Stufe 2 (Konsistenz- & Statusprüfung):
  • Evaluation der kombinierten Guard-Condition:
  1. Length == Config->DataLength / 8: Die übergebene Byte-Länge muss exakt der konfigurierten Bitlänge geteilt durch 8 entsprechen.
  2. Length >= Offset + 2: Die Gesamtlänge muss mindestens den Header-Offset plus 2 Bytes (Mindestlänge für E2E-P22-Header: CRC + Sequence Counter) abdecken.
  3. ForwardStatus != E2E_P_NONEWDATA: Es dürfen keine PDUs weitergeleitet werden, die keine neuen Daten enthalten.
  • [FALSE] $\rightarrow$ Verzweigung zum Endzustand wrong input. Abbruch der Funktion mit Rückgabewert E2E_E_INPUTERR_WRONG. Keine Modifikation des Datenpuffers.
  • [TRUE] $\rightarrow$ Verzweigung zum Endzustand input ok.
  1. Folge-Sequenz (bei input ok):
  • Übergang in die Verarbeitungsschritte gemäß Figure 6.119: Counter inkrementieren, CRC über geschützten Datenbereich berechnen, Counter & CRC in PDU schreiben, Rücksprung mit E2E_E_OK.

4. Normative Relevanz & Entwickler-Hinweise

  • API-Vertrag (Return Values):
  • Fehlende Zeiger führen zwingend zu E2E_E_INPUTERR_NULL ($0x13$).
  • Falsche Längenangaben oder Status E2E_P_NONEWDATA führen zwingend zu E2E_E_INPUTERR_WRONG ($0x17$).
  • Die Prüfreihenfolge ist normativ festgelegt: Null-Pointer-Prüfungen besitzen Vorrang vor Wertebereichs- und Konsistenzprüfungen.
  • Gateway- & Forwarding-Restriktionen:
  • Der explizite Ausschluss von E2E_P_NONEWDATA verhindert, dass bei fehlerhafter oder nicht erfolgter Vorverarbeitung (z. B. im E2E-Receiver/Check-Schritt des Quell-Busses) eine PDU ungerechtfertigt mit neuer Sequence Number / CRC weitergeleitet wird.
  • Integrations- & Stack-Implementierung:
  • Safety/MISRA: Keine Dereferenzierung von Config->DataLength vor erfolgreichem Abschluss der Null-Prüfung (Kurzschlussauswertung / Short-Circuit Evaluation oder getrennte if-Blöcke zwingend erforderlich).
  • PDU-Router / RTE: Caller (typischerweise Com, PduR oder Gateway-Software-Komponente) muss sicherstellen, dass Length in Bytes und DataLength in Bits synchron parametriert sind.
  • Header-Größe: Das feste Delta Offset + 2 basiert auf dem 16-Bit-Overhead (8 Bit CRC + 4 Bit Counter + 4 Bit Daten/Reserved) des Profils 22. Unterschreitet die PDU diesen Wert, droht Speicherzugriffsverletzung beim Schreiben des E2E-Headers.
