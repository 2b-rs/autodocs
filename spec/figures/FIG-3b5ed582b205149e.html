1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECUC-Metamodell (Parametrisierungs- und Konfigurations-Klassendiagramm) gemäß UML-Notation.
  • Architektur-Kontext: Spezifiziert im BSW-Modul SwCluC (Software Cluster Connection, SWS R20-11).
  • Technischer Zweck: Konfiguration des NvM-Proxy-Dienstes (SwCluCNvMProxy). Ermöglicht Software Clustern (SWCLs) in partitionierten Classic-Platform-Architekturen den gesicherten, standardisierten Zugriff auf Non-Volatile-Memory-Blöcke (NvMBlockDescriptor) über Partitions- und Cluster-Grenzen hinweg unter Verwendung des generischen CpSoftwareClusterResource-Modells.

2. Komponenten, Entitäten & Schnittstellen

ECUC-Container (Hierarchie & Multiplizitäten)
  • SwCluCProxies (EcucParamConfContainerDef, Multiplizität: [1..1], Paket ProxyModules):
    • Wurzel-Container für alle Proxy-Module innerhalb der SwCluC-Konfiguration.
    • Aggregiert per Komposition (+subContainer) den SwCluCNvMProxy.
  • SwCluCNvMProxy (EcucParamConfContainerDef, Multiplizität: [1..1]):
    • Spezifischer Modul-Proxy für NV-Speicheroperationen.
    • Aggregiert per Komposition (+subContainer) mindestens eine oder mehrere Instanzen von SwCluCNvMProxyNvBlock.
  • SwCluCNvMProxyNvBlock (EcucParamConfContainerDef, Multiplizität: [1..*]):
    • Repräsentiert die Konfigurationsinstanz eines einzelnen, über den Proxy nach außen exponierten NvM-Blocks.
Parameter
  • SwCluCNvMProxyNvBlockMaxLength (EcucIntegerParamDef, Multiplizität implizit [1..1], Rolle +parameter):
    • Wertebereich: min = 1, max = 65535 (16-Bit Byte-Länge).
    • Definiert die Obergrenze der Nutzdatenlänge für den betreffenden Block im Proxy.
Referenzen (EcucReferenceDef / EcucForeignReferenceDef)
  • SwCluCResourceRef (EcucForeignReferenceDef, Rolle +reference, Herkunft OsProxy):
    • Attribut: destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE.
    • Assoziiert den Proxy-Block mit dem System-Metamodell-Element SoftwareCluster::CpSoftwareClusterServiceResource im CP Software Cluster Resource Pool.
    • CpSoftwareClusterServiceResource erbt generalisierend von SoftwareCluster::CpSoftwareClusterResource (Typ Identifiable):
      • + globalResourceId: PositiveInteger [0..1] (eindeutige clusterübergreifende ID).
      • + isMandatory: Boolean [0..1] (Verbindlichkeit der Ressource).
  • SwCluCNvMProxyNvMBlockDescriptorRef (EcucReferenceDef, Multiplizität: [1..1], Rolle +reference):
    • Referenziert via +destination das BSW-Ziel NvMBlockDescriptor (EcucParamConfContainerDef, Multiplizität: [1..65536], Paket Nvm).
    • Stellt die 1:1-Bindung zum realen persistenten Block im NVRAM Manager her.
  • SwCluCNvMProxyNvBlockEcucPartitionRef (EcucReferenceDef, Multiplizität: [1..1], Rolle +reference):
    • Referenziert via +destination die zugehörige EcucPartition (EcucParamConfContainerDef, Multiplizität: [0..*], Paket EcucPartition).
    • Bindet den Proxy-Block an die spezifische OS-Partition des aufrufenden Software Clusters.

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Konfigurationsmetamodell definiert das Diagramm die Struktur für den Codegenerator; das daraus resultierende Laufzeitverhalten gliedert sich wie folgt:

  1. Service-Aufruf im Software Cluster: Eine SWC innerhalb eines Software Clusters setzt einen NvM-Dienstaufruf (z. B. NvM_ReadBlock, NvM_WriteBlock) an den lokalen Proxy-Stub ab.
  2. Partitions- und Boundary-Validierung: Der generierte SwCluCNvMProxy-Code prüft die Partitionsberechtigung (SwCluCNvMProxyNvBlockEcucPartitionRef) und validiert die Pufferlänge strikt gegen SwCluCNvMProxyNvBlockMaxLength.
  3. Cross-Partition-IPC / Inter-Cluster-Routing: Die Anforderung wird unter Verwendung der globalResourceId aus der CpSoftwareClusterServiceResource marshalliert und per IPC über die Partitions-/Cluster-Grenze an die zentrale Host-Partition übertragen, in der der NvM-Core läuft.
  4. Ausführung im NvM-Core: Der zentrale NvM-Treiber führt den Auftrag auf dem über SwCluCNvMProxyNvMBlockDescriptorRef gebundenen Zielblock aus.
  5. Callback / Asynchrone Rückmeldung: Nach Abschluss der NVRAM-Operation (oder im Fehlerfall via Det/Dem) signalisiert der NvM das Ergebnis asynchron über den IPC-Rückkanal an die Quell-Partition zurück.

4. Normative Relevanz & Entwickler-Hinweise

  • Anforderungskonformität (ECUC_SwCluC_00040): Der Generator muss validieren, dass SwCluCNvMProxyNvBlockMaxLength exakt mit der im NvM konfigurierten Blockgröße (NvMBlockDescriptor/NvMBlockLength) übereinstimmt bzw. diese nicht überschreitet, um Pufferüberläufe über Speicherschutzgrenzen (MPU) auszuschließen.
  • Partitionierungs-Restriktion: Die Kardinalität [1..1] von SwCluCNvMProxyNvBlockEcucPartitionRef erzwingt eine eindeutige Zuweisung jedes Proxy-Blocks zu genau einer OS-Partition. Sollen mehrere Partitionen auf denselben physikalischen Block zugreifen, müssen separate SwCluCNvMProxyNvBlock-Instanzen definiert werden.
  • Metamodell-Kopplung (Foreign Reference): Da SwCluCResourceRef auf destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE verweist, hängt die BSW-Konfiguration direkt von der vorgelagerten System Description / Cluster-Topologie ab. Inkonsistenzen in globalResourceId führen zu unvollständigen Linker-Symbolen bzw. fehlgeschlagenem RTE/Proxy-IPC-Binding.
