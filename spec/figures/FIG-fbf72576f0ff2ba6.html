1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU-Configuration-Metamodell (ECUC-UML-Klassendiagramm / Parameter-Konfigurationsstruktur).
  • Architektur-Kontext: Spezifiziert den Konfigurationscontainer SoAdSocketConnectionGroup des BSW-Moduls Socket Adaptor (SoAd) gemäß AUTOSAR_SWS_SocketAdaptor (Classic Platform, Communication Stack).
  • Funktionaler Zweck: Aggregation gemeinsamer Transport- und Schnittstelleneigenschaften für eine Gruppe logischer Socket-Verbindungen (SoAdSocketConnection). Der Container bündelt lokale Adressbindung (TcpIpLocalAddr), lokalen Port, Protokollauswahl (TCP oder UDP), Framing-/PDU-Header-Regeln sowie QoS-Parameter (DSCP, PCP, Flow Label) zur Entkopplung der oberen Kommunikationsschichten (PduR, DoIP, SOME/IP) von der konkreten TcpIp-Stack-Instanziierung.

2. Komponenten, Entitäten & Schnittstellen

Hauptcontainer
  • SoAdSocketConnectionGroup (EcucParamConfContainerDef, Kardinalität: 1..*): Repräsentiert die logische Socket-Gruppe. Besitzt zwingend mindestens eine untergeordnete Einzelverbindung (SoAdSocketConnection).
Subcontainer & Choices
  • SoAdSocketConnection (EcucParamConfContainerDef, Kardinalität: 1..*): Sub-Container zur Spezifikation der konkreten Endpunkt-Verbindungen (Remote-IP, Remote-Port, PDU-Routen) innerhalb dieser Gruppe.
  • SoAdSocketProtocol (EcucChoiceContainerDef, Kardinalität: 1..1): Exklusive Protokollauswahl für alle Sockets der Gruppe:
    • SoAdSocketTcp (EcucParamConfContainerDef, Kardinalität: 0..1)
    • SoAdSocketUdp (EcucParamConfContainerDef, Kardinalität: 0..1)
Externe Referenzen
  • SoAdSocketLocalAddressRef (EcucReferenceDef, Kardinalität: 1..1, requiresSymbolicNameValue = true): Ziel: TcpIpLocalAddr (EcucParamConfContainerDef, 1..*), welches den Parameter TcpIpAddrId (EcucIntegerParamDef, 0..65535, withAuto = true, symbolicNameValue = true) enthält. Bindet die Gruppe an eine im TcpIp-Modul konfigurierte lokale IP-Adresse.
  • SoAdSocketSoConModeChgNotifUpperLayerRef (EcucReferenceDef, Kardinalität: 0..1): Ziel: SoAdBswModules (EcucParamConfContainerDef, 0..*). Bestimmt das Upper-Layer-Modul für Moduswechsel-Callbacks.
  • SoAdSocketIpAddrAssignmentChgNotifUpperLayerRef (EcucReferenceDef, Kardinalität: 0..1): Ziel: SoAdBswModules (EcucParamConfContainerDef, 0..*). Bestimmt das Upper-Layer-Modul für Benachrichtigungen über Änderungen der IP-Adresszuweisung.
Konfigurationsparameter (Auswahl & Wertebereiche)
  • Framing & PDU-Handling:
    • SoAdPduHeaderEnable (EcucBooleanParamDef): Steuert das Einfügen/Auswerten des standardisierten 8-Byte AUTOSAR PDU-Headers (PDU-ID + Länge) für Multiplexing.
    • SoAdSocketTpRxBufferMin (EcucIntegerParamDef, 0..65535, Kardinalität: 0..1): Mindestpuffergröße für TP-Rx-Verarbeitung.
    • SoAdSocketMsgAcceptanceFilterEnabled (EcucBooleanParamDef, Default: true, Kardinalität: 1..1): Aktiviert die Filterung eingehender Nachrichten anhand von IP/Port/PDU-ID.
  • Verbindungsmanagement & Benachrichtigungen:
    • SoAdSocketAutomaticSoConSetup (EcucBooleanParamDef, Default: true): Automatischer Aufbau/Listen-Zustand nach Initialisierung/IP-Zuweisung.
    • SoAdSocketLocalPort (EcucIntegerParamDef, 0..65535, Default: 0): Lokaler TCP/UDP-Port (0 = dynamische Portvergabe durch TcpIp).
    • SoAdSocketIpAddrAssignmentChgNotification (EcucBooleanParamDef, Default: false): Meldet Adressänderungen an das über SoAdSocketIpAddrAssignmentChgNotifUpperLayerRef referenzierte Modul.
    • SoAdSocketSoConModeChgNotification (EcucBooleanParamDef, Default: false): Meldet Moduswechsel (SOAD_SOCON_OFFLINE / SOAD_SOCON_ONLINE) an das über SoAdSocketSoConModeChgNotifUpperLayerRef referenzierte Modul.
    • SoAdSocketSoConModeChgBswMNotification (EcucBooleanParamDef, Kardinalität: 0..1): Meldet Statuswechsel direkt an das BswM via BswM_SoAd_SoConModeChg().
  • Quality of Service (QoS) & Layer-3/4-Optionen:
    • SoAdSocketFramePriority (EcucIntegerParamDef, 0..7, Kardinalität: 0..1): IEEE 802.1Q Priority Code Point (VLAN PCP).
    • SoAdSocketDifferentiatedServicesField (EcucIntegerParamDef, 0..63, Kardinalität: 0..1): IPv4 TOS / IPv6 Traffic Class (DSCP, 6 Bit).
    • SoAdSocketFlowLabel (EcucIntegerParamDef, 0..1048575, Kardinalität: 0..1): 20-Bit Flow Label für IPv6-Header.
    • SoAdSocketPathMTUEnable (EcucBooleanParamDef, Default: false, Kardinalität: 0..1): Aktiviert Path MTU Discovery gemäß RFC 1191 / RFC 8201.

3. Dynamisches Verhalten & Sequenzablauf

  1. Initialisierung & Adressbindung:
    • Sobald TcpIp die per SoAdSocketLocalAddressRef referenzierte IP-Adresse erfolgreich zuweist (TCPIP_IPADDR_STATE_ASSIGNED), triggert SoAd_LocalIpAddrAssignmentChg().
    • Bei gesetztem SoAdSocketAutomaticSoConSetup = true führt SoAd automatisch TcpIp_Bind() auf SoAdSocketLocalPort und je nach Protokoll TcpIp_TcpListen() bzw. Verbindungsaufbau aus.
  2. Moduswechsel-Signalisierung:
    • Geht ein Socket in den Zustand SOAD_SOCON_ONLINE oder SOAD_SOCON_OFFLINE, erfolgt bei gesetztem Flag:
      • Asynchroner Call an BswM: BswM_SoAd_SoConModeChg(SoConId, Mode).
      • Konfigurierter Callback an Upper Layer: <User>_SoConModeChg(SoConId, Mode).
  3. PDU-Empfang & Filterung:
    • Eingehende Frames passieren SoAdSocketMsgAcceptanceFilterEnabled. Bei aktivem Header (SoAdPduHeaderEnable = true) extrahiert SoAd die PDU-ID aus den ersten 4 Bytes und die Länge aus den folgenden 4 Bytes, bevor die Weiterleitung an PduR via PduR_SoAdRxIndication() oder PduR_SoAdTpCopyRxData() erfolgt.

4. Normative Relevanz & Entwickler-Hinweise

  • Ressourcenallokation & BSD-Socket-Mapping: Jede SoAdSocketConnectionGroup erfordert typischerweise die Bindung eines dedizierten TcpIp-Socket-Handles für den lokalen Endpunkt; Multiplizität 1..* von SoAdSocketConnection modelliert Server-Sockets mit mehreren parallelen Client-Sitzungen (insb. TCP) oder UDP-Unicast/Multicast-Fächerung.
  • Port-Kollisionen: SoAdSocketLocalPort muss netzwerkweit und über alle Gruppen hinweg eindeutig sein, sofern dasselbe TcpIpLocalAddr referenziert wird. Ein Wert von 0 delegiert die Vergabe ephemerer Ports an den TCP/IP-Stack (Client-Rolle).
  • Protokoll-Restriktion: Die Choice SoAdSocketProtocol schließt TCP und UDP innerhalb derselben Gruppe strikt gegenseitig aus (lowerMultiplicity = 1, upperMultiplicity = 1).
  • SOME/IP & DoIP Konsistenz: Für SOME/IP ist SoAdPduHeaderEnable = false zwingend (SOME/IP definiert ein eigenes L4-Framing), während für generisches PduR-Multiplexing über denselben Port SoAdPduHeaderEnable = true gesetzt werden muss.
  • Buffer-Dimensionierung: Bei TCP oder UDP-TP-Routing muss SoAdSocketTpRxBufferMin passend zur maximal erwarteten PDU-Größe konfiguriert werden, um Truncation- oder Out-of-Buffer-Zustände im SoAd-Ringpuffer zu verhindern.
