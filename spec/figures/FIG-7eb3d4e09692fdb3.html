1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Protokoll-Schichtenmodell und Architektur-Mapping basierend auf dem ISO/OSI-7-Schichten-Referenzmodell (Physical Layer bis Application Layer) mit horizontalen Protokollabhängigkeiten und vertikalen Inspektionsgrenzen.
  • Technischer Zweck: Das Diagramm dient im Rahmen der AUTOSAR_FO_RS_Firewall (Foundation, gültig für R22-11, R23-11, R24-11) als Referenztaxonomie für die Ethernet-Filterdomänen. Es definiert die Protokollebenen für:
    • Stateless Packet Filtering (L2–L4: MAC, VLAN, IPv4/IPv6, TCP/UDP-Ports)
    • Stateful Filtering (L4: TCP-Verbindungszustände, UDP-Pseudoverbindungen)
    • Deep Packet Inspection (DPI) (L5–L7: Protokollpayloads automobiler Middleware)
    • Hardware-Offloading vs. Host-Stack-Inspektion (L2-Switching vs. μC/μP-Protokollstack)
    • Sensorik für das IdsM (Intrusion Detection System Manager).

2. Komponenten, Entitäten & Schnittstellen

Schicht 1 – Physical Layer
  • 100(0)BASE-T1/TX: Physische Schnittstellen des automobilen Single-Pair- bzw. Standard-Ethernets (100BASE-T1, 1000BASE-T1, 100BASE-TX). Bildet das Fundament für alle L2-Protokolle und ISO 15118-3.
Schicht 2 – Data Link Layer (Sicherungs- & TSN-Mechanismen)
  • VLAN (IEEE 802.1Q): Filterung nach Port, Priority Tagging, Private VLANs, Subnetz-Zuordnung und EtherType-Protokoll-ID.
  • PNAC (IEEE 802.1X): Portbasierte Netzwerk-Zugangskontrolle (Authentifizierung vor Netzzugang).
  • MACsec (IEEE 802.1AE): Layer-2-Verschlüsselung und Frame-Integrität/Authentizität.
  • IEEE 802.1Qci: Per-Stream Filtering and Policing (PSFP) zur hardwarenahen Flussüberwachung, Ratenbegrenzung und Filterung deterministischer TSN-Streams direkt im Switch.
Schicht 3 – Network Layer
  • IP Version 4, 6: Standard-Netzwerkprotokolle (Header-Inspektion: Source/Destination IP, Flow Label, Hop Limit/TTL, Fragmente).
  • IPSec: Netzwerk-Verschlüsselung/Authentifizierung (ESP/AH-Header).
  • ICMP v4/v6 & NDP: Internet Control Message Protocol und Neighbor Discovery Protocol (durchgängig von L3 bis L7 dargestellt, da Kontroll- und Fehlerkanal).
  • ARP / RARP: Adressauflösungsprotokolle (operieren direkt auf L2, logisch Schicht-3-übergreifend).
Schicht 4 – Transport Layer
  • UDP: Verbindungsloser Transportkanal.
  • TCP: Verbindungsorientierter Transportkanal (Synch, Ack, Sequence-Tracking).
  • (D)TLS: Datagram TLS und TLS zur Transportverschlüsselung.
Schichten 5 bis 7 – Session, Presentation, Application Layer
Automotive Middleware & Diagnose (IP-gebunden, auf UDP/TCP bzw. (D)TLS)
  • SOME/IP & SOME/IP-SD: Scalable service-Oriented MiddlewarE over IP inkl. Service Discovery (SD).
  • DDSI-RTPS: DDS Interoperability Wire Protocol (Data Distribution Service).
  • XCP: Universal Measurement and Calibration Protocol.
  • SecOC: Secure Onboard Communication auf PDU-/Transportebene.
  • HSFZ: High-Speed-Fahrzeugzugang.
  • DoIP: Diagnostic over IP (ISO 13400).
  • PDU Filter: Spezifischer Filter für AUTOSAR-PDUs (Signal-/PDU-Ebene).
Standard-Netzwerkdienste
  • DHCP v4/v6: Dynamische Host-Konfiguration (UDP-basiert).
  • UDP-NM: AUTOSAR UDP Network Management.
  • Bonjour: Zero-Configuration-Networking (mDNS / DNS-SD).
  • DNS, HTTP(S), SSH: Standard-Infrastrukturdienste.
Time-Sensitive Networking (TSN) & AVB-Audio/Video
  • gPTP (IEEE 802.1AS): Präzisionszeit-Synchronisation (direkt auf L2).
  • AVTP (IEEE 1722): Audio Video Transport Protocol.
  • IEEE 1722.1: AVDECC (Discovery, Enumeration, Connection Management).
  • RTP (IEEE 1733): Real-Time Transport Protocol über AVB/Ethernet.
  • DPI (Deep Packet Inspection Block): Dediziert verortet an der Schnittstelle von IEEE 1722.1 / AVTP zu L2/L3 zur Erkennung und Validierung strukturierter AVB-Stream-Payloads.
Vertikale E-Mobility Domäne (Rechte Spalte)
  • ISO 15118-1: Application Layer (Use Cases für V2G-Kommunikation).
  • ISO 15118-2: Network-, Transport-, Session-, Presentation-Layer (TLS, TCP/IP, EXI-Codierung).
  • ISO 15118-3: Physical & Data Link Layer (Powerline Communication / HomePlug Green PHY über L1/L2).

3. Dynamisches Verhalten & Sequenzablauf

Als Schichten- und Protokollklassifikationsdiagramm bildet die Grafik keinen temporalen Ablauf ab. Für die funktionale Ingress/Egress-Inspektion der Firewall gilt die folgende deterministische Pipeline:

[L1/L2 Ingress: PHY / Switch]
       │
       ▼
 1. IEEE 802.1Q / Qci (Policing, VLAN-Drop) ──[Fail]──► [Drop & IdsM-Event]
       │
       ▼
 2. MACsec Decrypt / Check ───────────────────[Fail]──► [Drop & IdsM-Event]
       │
       ├─────────────────────────────────┐ (Non-IP: ARP, gPTP, AVTP)
       ▼ (IP-Pakete)                     ▼
 3. L3 IP-Filter (v4/v6 Header, IPSec)   6. L2-DPI (z. B. IEEE 1722/1722.1)
       │                                         │
       ▼                                         ▼
 4. L4 Stateful Filter (TCP/UDP, (D)TLS)   [Stack / Forwarding]
       │
       ▼
 5. L5–L7 DPI (SOME/IP, DoIP, PDU Filter) ────[Fail]──► [Drop & IdsM-Event]
       │
       ▼
 [Host Application / BswM / PduR]
  1. L2 Frame Validation: Frühestmögliche Filterung im Switch-Treiber (EthSwt): Validierung der Port-VLAN-Zuordnung (802.1Q), Frame-Ratenprüfung via IEEE 802.1Qci, Drop unautorisierter MAC-Adressen.
  2. L3/L4 Packet Inspection: Überprüfung der IP-Tupel (Src-IP, Dst-IP, Protokoll, Port). Stateful TCP-Tracking verwirft Out-of-Order- oder Invalid-State-Segmente (z. B. ACK ohne vorherigen SYN).
  3. L5–L7 Deep Packet Inspection: Entpacken der Anwendungsdaten (z. B. Validierung von SOME/IP Message ID, Method ID, Interface ID oder DoIP Payload Types).
  4. Security-Event-Triggering: Jede Regelverletzung (Drop/Reject) löst synchron oder entkoppelt asynchron einen Security-Event-Report an das IdsM via standardisierter Schnittstelle (IdsM_SetSecurityEvent) aus.

4. Normative Relevanz & Entwickler-Hinweise

  • Partitionierung Hardware vs. Software (EthSwt vs. TcpIp):
    • L2-Filter (802.1Q, 802.1Qci, MACsec) müssen zur Laufzeit- und Latenzoptimierung auf die Hardware-Register des Ethernet-Switches (EthSwt) gemappt werden.
    • L3/L4-Filterung erfolgt typischerweise am Eintrittspunkt des AUTOSAR TcpIp-Stacks.
  • Kryptographie-Grenzen bei Deep Packet Inspection (DPI):
    • L5–L7-Filterung (SOME/IP, DoIP, SecOC) ist bei Ende-zu-Ende-Verschlüsselung via (D)TLS oder IPSec payload-blind, sofern die Firewall nicht als Endpunkt agiert oder die Inspektion nach dem Krypto-Offloading im Host-Stack erfolgt.
  • Stateful Filtering & Ressourcendimensionierung (UC 2):
    • Stateful Filtering erfordert dynamische State-Tables im RAM. Entwickler müssen Puffergrößen für parallele TCP-Verbindungen und UDP-Pinholes statisch konfigurieren (Worst-Case-Dimensionierung gegen SYN-Flood/DoS).
  • ISO 15118 Konformität:
    • Durch den separaten Vertikal-Stack (ISO 15118-1/2/3) müssen Firewall-Regelsätze spezifische Übergangsregeln definieren, die V2G-Traffic (L2-PLC-Bridging, SECC-Discovery, TLS-Handshake) isoliert behandeln.
  • PDU-Filter vs. PduR:
    • Die Entität PDU Filter greift direkt in das AUTOSAR-Kommunikationsrouting ein. Filterregeln müssen konsistent zu den PduR- und Com-Extraktionsdeskriptoren im ARXML konfiguriert werden, um Fehlverwerfungen legaler I-PDUs zu verhindern.
