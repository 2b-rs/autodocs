1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm zur Spezifikation eines AUTOSAR-BSW-Konfigurationsmetamodells (ECUC Parameter Configuration Container Definition) mit Kopplung an das MSR-Systemmetamodell via Foreign Reference.
  • Technischer Zweck: Definition der Konfigurationsstruktur für den OS Proxy Task Dispatcher innerhalb des BSW-Moduls SwCluC (Software Cluster Connection, SWS-ID: ECUC_SwCluC_00061, eingeführt mit AUTOSAR R20-11).
  • Funktionale Einordnung: In modular aktualisierbaren Classic-Platform-Systemen (Software Clusters / SwClu) entkoppelt der OS-Proxy-Mechanismus die Ausführung von Software-Clustern über Partitions- und Core-Grenzen hinweg. Der Task Dispatcher fungiert als Laufzeitanker innerhalb eines dedizierten OS-Tasks (SwCluCOsProxyOsTask), um clusterübergreifende RTE-Events (Timing, Background, Mode-Switch, Trigger) kontrolliert, ratenlimitiert und partitionsgebunden zu dispatchen.

2. Komponenten, Entitäten & Schnittstellen

  • ECUC-Container-Hierarchie (Statischer Aufbau):
    • SwCluCProxies (EcucParamConfContainerDef, [1..1]): Wurzelcontainer für alle Proxy-Definitionen des Moduls (Herkunft: ProxyModules).
      • +subContainer SwCluCOsProxy (EcucParamConfContainerDef, [0..1]): Aggregiert die OS-spezifischen Proxy-Strukturen (Multiplizität auf [0..1] geändert, Proxy ist optional).
        • +subContainer SwCluCOsProxyOsTask (EcucParamConfContainerDef, [0..*]): Repräsentiert die OS-Task-Ebene, in deren Kontext der Proxy ausgeführt wird.
          • +subContainer SwCluCOsProxyOsTaskDispatcher (EcucParamConfContainerDef, [0..*]): Konfiguriert die Dispatcher-Instanz für eingehende Cluster-Events.
  • Parameter & Subcontainer von SwCluCOsProxyOsTaskDispatcher:
    • SwCluCOsProxyMaxNumberOfCallee (EcucIntegerParamDef, [0..1]): Wertebereich Min = 1, Max = 255. Begrenzt die maximale Anzahl der nacheinander aufrufbaren Runnables/Callees innerhalb eines Dispatcher-Zyklus.
    • SwCluCOsProxyMinimumStartInterval (EcucFloatParamDef, [0..1]): Wertebereich Min = 0, Max = INF, Default = 0 (Sekunden). Definiert den Mindestabstand zwischen aufeinanderfolgenden Task-Aktivierungen zur Vermeidung von Task-Überlastung (Burst-Schutz).
    • **Event-Subcontainer (EcucParamConfContainerDef, Multiplizität jeweils [0..*]):**
      • SwCluCOsProxyDispatcherInitEvent: Neu hinzugefügter Subcontainer zur Bindung an RTE-Initialisierungsereignisse beim Hochlauf des Clusters.
      • SwCluCOsProxyDispatcherTimingEvent: Bindung an periodische RTE-Timing-Events.
      • SwCluCOsProxyDispatcherBackgroundEvent: Bindung an Hintergrund-Tasks/Runnables mit niedrigster Priorität.
      • SwCluCOsProxyDispatcherModeSwitchEvent: Bindung an RTE-Moduswechsel-Events.
      • SwCluCOsProxyDispatcherExternalTriggerOccurredEvent: Bindung an asynchrone externe Trigger.
  • Referenzen & Systemmodell-Bindung:
    • SwCluCOsProxyEcucPartitionRef (EcucReferenceDef, [0..1]): Assoziation +destination auf EcucPartition ([0..*], Herkunft: from EcucPartition). Weist den Dispatcher einer spezifischen Speicher-/Core-Partition zu (OS-Application / MPU-Sicherheitsgrenze).
    • SwCluCResourceRef (EcucForeignReferenceDef, Herkunft: ProxyModules): Wird per Komposition +reference sowohl von SwCluCOsProxyOsTask als auch von SwCluCOsProxyOsTaskDispatcher referenziert. Attribut destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE. Verweist direkt auf das Metamodell-Element SoftwareCluster::CpSoftwareClusterServiceResource im Paket CP Software Cluster Resource Pool.
  • Metamodell-Klassen (CP Software Cluster Resource Pool):
    • CpSoftwareClusterResource (abstrakt/kursiv, erbt von Identifiable): Basisklasse für Cluster-Ressourcen mit den Attributen + globalResourceId: PositiveInteger [0..1] und + isMandatory: Boolean [0..1].
    • CpSoftwareClusterServiceResource: Spezialisierung (is-a) von CpSoftwareClusterResource, dient als konkreter Zieltyp für Foreign References aus der BSW-Konfiguration.

3. Dynamisches Verhalten & Sequenzablauf

  • Ereignisüberwachung & Pufferung: Eingehende clusterübergreifende RTE-Ereignisse treffen am Software-Cluster-Proxy ein und werden dem Dispatcher zugeordnet. Neben zyklischen (TimingEvent), hintergrundbasierten (BackgroundEvent), modusabhängigen (ModeSwitchEvent) und asynchronen Trigger-Ereignissen (ExternalTriggerOccurredEvent) werden nun auch Initialisierungsereignisse (SwCluCOsProxyDispatcherInitEvent) unterstützt.
  • Initialisierungsablauf: Während des Hochlaufs des Software-Clusters werden vor dem regulären zyklischen Betrieb die über SwCluCOsProxyDispatcherInitEvent konfigurierten Runnables kontrolliert im OS-Proxy-Task-Kontext abgearbeitet.
  • Aktivierungssteuerung & Ratenbegrenzung: Vor dem Auslösen der regulären Task-Ausführung prüft die Dispatcher-Logik das konfigurierte Mindestintervall (SwCluCOsProxyMinimumStartInterval), um aufeinanderfolgende Task-Aktivierungen zu entprellen.
  • Task-Ausführung im Partitionskontext: Der zugeordnete OS-Task (SwCluCOsProxyOsTask) wird im Kontext der über SwCluCOsProxyEcucPartitionRef zugewiesenen Speicher-/Core-Partition (EcucPartition) aktiviert.
  • Sequenzieller Runnable-Aufruf & Zyklus-Deckelung: Innerhalb der Task-Aktivierung iteriert der Dispatcher über die anstehenden Event-Handler und ruft die assoziierten Runnables sequenziell auf. Die maximale Anzahl pro Aktivierungszyklus ist strikt durch SwCluCOsProxyMaxNumberOfCallee (1..255) gedeckelt.
  • Ressourcenabsicherung: Zur Laufzeit wird die Berechtigung des Task- und Dispatcher-Kontexts gegen die im Systemmodell deklarierte CpSoftwareClusterServiceResource über SwCluCResourceRef abgesichert.

4. Normative Relevanz & Entwickler-Hinweise

  • Optionale Proxy-Konfiguration: Die untere Multiplizität von SwCluCOsProxy wurde von 1 auf 0 reduziert ([0..1]). Ein Software-Cluster muss einen OS-Proxy nur noch dann definieren, wenn tatsächlich partitions- oder taskübergreifendes Dispatching benötigt wird.
  • Initialisierungsunterstützung: Mit der Einführung von SwCluCOsProxyDispatcherInitEvent ([0..*]) können clusterübergreifende Initialisierungsabläufe explizit an den OS-Task gebunden werden, wodurch deterministische Startphasen über Partitionsgrenzen hinweg gewährleistet werden.
  • Echtzeit- und WCET-Dimensionierung: Der Parameter SwCluCOsProxyMaxNumberOfCallee bleibt entscheidend für die Worst-Case Execution Time (WCET) zur Vermeidung von Task starvation.
  • Partitions- und Speicherschutz: Die Bindung über SwCluCOsProxyEcucPartitionRef stellt die Einhaltung von MPU- und OS-Application-Grenzen für alle Event-Typen sicher.
  • Foreign-Reference-Validierung: Die Konsistenz zwischen SwCluCResourceRef und CpSoftwareClusterServiceResource muss toolingseitig vor der BSW-Generierung verifiziert werden.
