1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Zeitverlaufs- bzw. Ausführungsflussdiagramm (Timing/Process Flow Diagram) entlang einer diskreten Zeitachse $t$.
  • Technischer Zweck: Visualisierung des zweistufigen Fehlererfassungs- und Pufferungsmechanismus (Prestorage of Freeze Frames) im Diagnostic Event Manager (Dem) der AUTOSAR Classic Platform.
  • Funktionale Einordnung: Temporale Entkopplung zwischen der initialen Symptomerkennung (physikalischer Fehlerzeitpunkt) und der endgültigen Fehlerqualifikation (Dem_SetEventStatus). Es verhindert, dass flüchtige Umgebungsdaten (Freeze Frames/DIDs) durch nachgelagerte Entprellzeiten (Debouncing) oder fehlende Freigabebedingungen verfälscht oder überschrieben werden.

2. Komponenten, Entitäten & Schnittstellen

  • Diagnostic Monitor / SW-C (oder BSW-Treiber):
  • Ausführende Diagnosefunktion (Monitor function), die das Fehlersymptom erkennt, Verifikationsbedingungen überwacht und den Status qualifiziert.
  • Diagnostic Event Manager (Dem):
  • Kernmodul der System Service Layer (BSW). Verwaltet Event-Status, Entprellung und Diagnosespeicher.
  • Enthält zwei Speicherbereiche:
  • Prestore Freeze Frame Buffer: Temporärer flüchtiger RAM-Puffer für vorab abgetastete Schnappschüsse.
  • Event Memory: Persistenter Fehlerspeicher (Primär-/Sekundärspeicher) für qualifizierte DTC-Einträge.
  • Schnittstellen (APIs / Ports):
  • Dem_PrestoreFreezeFrame(Dem_EventIdType EventId):
  • Service-Interface DiagnosticMonitor (C-API / RTE-Operation).
  • Löst die synchrone Erfassung der Umgebungsdaten für das spezifizierte Event aus (SWS_Dem_00050).
  • Dem_SetEventStatus(Dem_EventIdType EventId, Dem_EventStatusType EventStatus):
  • Meldet das finale Testergebnis (DEM_EVENT_STATUS_PASSED oder DEM_EVENT_STATUS_FAILED).
  • (Begleitend gemäß Spezifikation) Dem_ClearPrestoredFreezeFrame(Dem_EventIdType EventId):
  • API zur manuellen Freigabe des Prestore-Puffers bei Abbruch der Auswertung (SWS_Dem_00807).

```
| | |

| | (Puffer freigeben) |

| - ODER - |

| | (Puffer verwerfen/freigeben) |

```

  1. Schritt 1 – Symptomerkennung & Prestorage:
  • Die Überwachungsfunktion läuft (Monitor function running) und detektiert ein potenzielles Fehlersymptom ("maybe 'event failed' detected").
  • Der Monitor ruft unmittelbar Dem_PrestoreFreezeFrame(EventId) auf.
  • Der Dem fragt synchron die konfigurierten DID-Daten ab und speichert das Snapshot-Abbild im flüchtigen Prestore-Puffer ab (SWS_Dem_00461).
  1. Schritt 2 – Fehlerqualifikation & Evaluation:
  • Der Monitor verifiziert zusätzliche Bedingungen ("waiting for other additional conditions", z. B. Monitor-internes Debouncing, Bestätigungszyklen, Spannungs-/Drehzahlfenster).
  • Nach Abschluss der Evaluation ("Event Status evaluation") erfolgt der Aufruf von Dem_SetEventStatus:
  • Zweig FAILED (SWS_Dem_00464): Das Event qualifiziert als defekt. Der Dem übernimmt die zuvor gesicherten Daten aus dem Prestore-Puffer in den Event-Speicher und gibt den Prestore-Pufferplatz frei. Es findet keine erneute Datenerfassung zum späten Qualifikationszeitpunkt statt.
  • Zweig PASSED (SWS_Dem_00465): Das Event wird als fehlerfrei bewertet. Der Dem verwirft die gepufferten Freeze-Frame-Daten und gibt den Prestore-Puffer unverzüglich frei.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationspflichten (DemPrestoreFreezeframe):
  • Das Feature muss im Dem-Parameter DemPrestoreFreezeframe pro Event explizit auf TRUE konfiguriert sein (SWS_Dem_00261). Wird Dem_PrestoreFreezeFrame für ein unkonfiguriertes Event aufgerufen, erzeugt der Dem im Entwicklungsmodus einen DET-Fehler (DEM_E_PARAM_DATA / SWS_Dem_00969) und ignoriert den Aufruf.
  • Ressourcenallokation & Pufferlimitierung (DemMaxNumberPrestoredFF):
  • Die Anzahl der Prestore-Puffer ist im BSW-RAM statisch beschränkt. Mehrere zeitgleich unqualifizierte Events konkurrieren um dieselben Pufferplätze.
  • Entwickler müssen Überlaufstrategien beachten: Ist der Puffer erschöpft, wird ein neuer Prestore-Aufruf je nach Konfiguration verworfen oder ersetzt vorhandene Daten (SWS_Dem_00461).
  • Verhinderung von Pufferlecks (Deadlocks):
  • Wird ein Freeze Frame gepuffert, der Monitor bricht die Verifikation jedoch ab (z. B. Fahrzyklusende, ungültige Betriebsbedingungen ohne Dem_SetEventStatus), bleibt der Prestore-Puffer blockiert.
  • Der Monitor muss in solchen Fällen zwingend Dem_ClearPrestoredFreezeFrame(EventId) aufrufen, um den Pufferplatz für andere Events freizugeben (SWS_Dem_00808).
  • Synchronizität & Task-Laufzeit:
  • Dem_PrestoreFreezeFrame liest DIDs (z. B. via RTE-Ports) synchron im Kontext der aufrufenden Monitor-Task ein. Komplexe Freeze-Frame-Layouts belasten die WCET (Worst-Case Execution Time) der Monitor-Task unmittelbar im Schritt 1.
