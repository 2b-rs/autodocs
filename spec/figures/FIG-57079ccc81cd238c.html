1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm / ECUC-Metamodell-Ausschnitt (AUTOSAR ECU Configuration Parameter Definition).
  • Architektur-Kontext: AUTOSAR Classic Platform, BSW-Modul Bus Mirroring (Mirror).
  • Funktionaler Zweck: Formale Konfigurationsspezifikation des Quellnetzwerk-Containers MirrorSourceNetworkCan. Definiert die BSW-Generierungsparameter zur Erfassung, Filterung und CAN-ID-Transformation (ID-Remapping) von CAN-Traffic auf einem überwachten Quell-Bus zur Weiterleitung an einen Ziel-Bus (Mirror Destination, z. B. Logger/Tester via CAN oder Ethernet).

2. Komponenten, Entitäten & Schnittstellen

Hauptcontainer
  • MirrorSourceNetworkCan (EcucParamConfContainerDef [0..1]): Wurzelknoten für die CAN-spezifische Quellkanal-Konfiguration.
    • MirrorNetworkId (EcucIntegerParamDef [1..1]): Eindeutige ID des Quellbusses (min=0, max=255, symbolicNameValue=true).
    • MirrorSourceMaxDynamicFilters (EcucIntegerParamDef [1..1]): Maximale Anzahl an zur Laufzeit dynamisch konfigurierbaren CAN-Filtern (min=0, max=255, defaultValue=5).
Externe Referenz (ComM-Anbindung)
  • MirrorComMNetworkHandleRef (EcucReferenceDef [1..1]):
    • Ziel: ComMChannel (EcucParamConfContainerDef [1..256] aus dem Modul ComM).
    • Eigenschaft: requiresSymbolicNameValue=true.
    • Bindet das Mirror-Quellnetzwerk an den zugehörigen Kommunikationskanal (ComMChannelId, uint8, 0..255).
Filterstrukturen
  • MirrorSourceCanFilter (EcucChoiceContainerDef [0..255]): Ermöglicht pro Instanz exakt eine Auswahl (+choice) aus zwei statischen Filtermechanismen:
    • MirrorSourceCanFilterRange (EcucParamConfContainerDef [0..1]): Bereichsfilter (CAN-ID von/bis).
    • MirrorSourceCanFilterMask (EcucParamConfContainerDef [0..1]): Maskenbasierter Filter (Code/Mask).
ID-Mapping & Transformation (0..*)

Erlaubt das Umbiegen von CAN-IDs für das gespiegelte Zielnetzwerk zur Kollisionsvermeidung:

  • MirrorSourceCanSingleIdMapping (EcucParamConfContainerDef [0..*]):
    • MirrorSourceCanSingleIdMappingSourceCanId (EcucIntegerParamDef, 0..4294967295 / uint32): Quell-CAN-ID.
    • MirrorSourceCanSingleIdMappingDestCanId (EcucIntegerParamDef, 0..4294967295 / uint32): Ziel-CAN-ID.
  • MirrorSourceCanMaskBasedIdMapping (EcucParamConfContainerDef [0..*]):
    • MirrorSourceCanMaskBasedIdMappingSourceCanIdCode (uint32, 0..4294967295): Bitmuster für Quell-ID.
    • MirrorSourceCanMaskBasedIdMappingSourceCanIdMask (uint32, 0..4294967295): Bitmaske für Match.
    • MirrorSourceCanMaskBasedIdMappingDestBaseId (uint32, 0..4294967295): Basis-CAN-ID auf dem Zielbus (über Mask-Offset adressiert).

3. Dynamisches Verhalten & Sequenzablauf (Laufzeitabbildung)

Obgleich es sich um ein statisches Konfigurationsmodell handelt, determiniert es die Ausführungspfade des Mirror-Stacks:

  1. Frame-Ingress: Ein CAN-Frame wird über den Hardware-/Interface-Hook des referenzierten ComMChannel erfasst.
  2. Filter-Evaluierung:
    • Abgleich gegen statische Filterketten (MirrorSourceCanFilter: Range oder Mask).
    • Paralleler/nachgelagerter Abgleich gegen aktive dynamische Filter (limitiert durch MirrorSourceMaxDynamicFilters, manipulierbar via Dcm/Mirror-API zur Laufzeit).
    • Verwerfung: Erfüllt der Frame kein Filterkriterium, wird er verworfen.
  3. ID-Remapping (optional):
    • Prüfung auf Single-ID-Match (MirrorSourceCanSingleIdMapping) → Ersetzung durch DestCanId.
    • Prüfung auf Mask-Match (MirrorSourceCanMaskBasedIdMapping) → Berechnung der Ziel-ID aus DestBaseId und den variablen Bits der Quell-ID.
  4. Queueing/Forwarding: Der transformierte Frame wird in den Puffer zur Übertragung auf dem Mirror-Zielkanal eingereiht.

4. Normative Relevanz & Entwickler-Hinweise

  • 32-Bit-ID-Codierung (uint32): Der Wertebereich 0 … 4.294.967.295 (0xFFFFFFFF) ist für alle ID-Parameter gewählt, um Standard- (11-Bit) und Extended-CAN-IDs (29-Bit) inklusive der AUTOSAR-spezifischen MSB-Flag-Bits (wie CAN FD Indicator, Extended ID Flag 0x80000000U) typensicher abzubilden.
  • RAM-Dimensionierung: MirrorSourceMaxDynamicFilters steuert direkt die statische Allokation von RAM-Tabellen im BSW-Modul für Laufzeit-Diagnosefilter. Da dynamische Speicherallokation (malloc) unzulässig ist, muss dieser Wert ressourcenschonend konfiguriert werden (Default: 5 Einträge).
  • Metamodell-Restriktion: Durch EcucChoiceContainerDef bei MirrorSourceCanFilter schließt sich die gleichzeitige Konfiguration von Maske und Bereich innerhalb eines Filters zwingend aus; heterogene Filtersätze erfordern separate Instanzen (bis zu 255).
  • Generierungsabhängigkeit: requiresSymbolicNameValue = true bei MirrorComMNetworkHandleRef erzwingt, dass der referenzierte ComMChannel bereits syntaktisch valide Symbole im EcuC-Extrakt bereitstellt (Bindungsreihenfolge im BSW-Generator beachten).
