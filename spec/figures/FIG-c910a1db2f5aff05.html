1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration Metamodell (ECUC) Klassendiagramm / Konfigurationsmetamodell-Ausschnitt (UML-basiert).
  • Technischer Zweck: Spezifikation der Konfigurationsstruktur zur Anbindung des Diagnostic Communication Managers (DCM) an den Intrusion Detection System Manager (IdsM) gemäß AUTOSAR Security Event Reporting.
  • Architektur-Einordnung: BSW-Diagnose- und Security-Schicht. Das Metamodell definiert die Zuordnung standardisierter UDS-Sicherheitsereignisse (Security Events) auf IdsM-Ereignis-Definitionen (IdsMEvent), um sicherheitskritische Diagnoseaktivitäten an die On-Board-Angriffserkennung zu melden.

2. Komponenten, Entitäten & Schnittstellen

#### Container & Parameter

  • DcmGeneral (EcucParamConfContainerDef [1..1]):
  • Zentraler Konfigurationscontainer für globale DCM-Eigenschaften.
  • Parameter: DcmEnableSecurityEventReporting (EcucBooleanParamDef, Default: false), Multiplizität [1..1] über Komposition +parameter. Dient als globaler Pre-Compile-Schalter für die Security-Event-Reporting-Funktionalität.
  • DcmSecurityEventRefs (EcucParamConfContainerDef [0..1]):
  • Sub-Container von DcmGeneral (Aggregation via +subContainer). Kapselt sämtliche IdsM-Event-Referenzen des DCM.
  • IdsMEvent (EcucParamConfContainerDef [1..65535]):
  • Ziel-Container (+destination) aus dem Metamodell des IdsM (/AUTOSAR/EcucDefs/IdsM/IdsMEvent), der ein konkretes Sicherheitsereignis im Intrusion Detection System repräsentiert.

#### Referenzen (EcucReferenceDef)

Alle Referenzen aggregiert DcmSecurityEventRefs via Komposition (+reference) mit Kardinalität [0..1] und der Eigenschaft requiresSymbolicNameValue = true:

  1. SEV_UDS_ECU_UNLOCK_SUCCESSFUL: Referenziert das IdsM-Event für erfolgreiche Freischaltung via UDS-Service 0x27 (SecurityAccess).
  2. SEV_UDS_AUTHENTICATION_SUCCESSFUL: Referenziert das IdsM-Event für erfolgreiche Authentifizierung via UDS-Service 0x29 (Authentication).
  3. SEV_UDS_CLEAR_DTC_SUCCESSFUL: Referenziert das IdsM-Event für das Löschen von Fehlerspeichereinträgen via UDS-Service 0x14 (ClearDiagnosticInformation).
  4. SEV_UDS_ECU_RESET: Referenziert das IdsM-Event bei Ausführung eines Steuergeräteresets via UDS-Service 0x11 (ECUReset).
  5. SEV_UDS_WRITE_DATA: Referenziert das IdsM-Event für Schreiboperationen im NVM/RAM via UDS-Service 0x2E (WriteDataByIdentifier).
  6. SEV_UDS_REQUEST_DOWNLOAD: Referenziert das IdsM-Event bei Anforderung eines Software-/Datendownloads via UDS-Service 0x34 (RequestDownload).
  7. SEV_UDS_DTC_SETTING_SWITCHED_OFF: Referenziert das IdsM-Event bei Deaktivierung der Fehlerspeichereintragung via UDS-Service 0x85 (ControlDTCSetting).

3. Dynamisches Verhalten & Sequenzablauf

  • Trigger: Abschluss bzw. Verarbeitung des jeweiligen UDS-Dienstes im DCM (Positiv-Response-Pfad bzw. Aktivierungszeitpunkt).
  • Bedingungsprüfung:
  1. Ist DcmEnableSecurityEventReporting == TRUE?
  2. Ist für das spezifische Ereignis eine Instanz von EcucReferenceDef konfiguriert (Multiplizität 1)?
  • Ablauf:
  • Bei Erfüllung setzt der DCM synchron oder asynchron über die BSW-Schnittstelle des IdsM einen Event-Report ab:

IdsM_SetSecurityEvent(EventId, ...) bzw. IdsM_SetSecurityEventWithContextData(...).

  • Als EventId wird der aus der Zielinstanz IdsMEvent generierte symbolische Bezeichner übergeben.
  • Bypass / Abbruch:
  • Wenn DcmEnableSecurityEventReporting == FALSE oder die spezifische Referenz unkonfiguriert bleibt (Multiplicity = 0), wird der Code-Pfad via Pre-Compile-Schalter (#if DCM_SECURITY_EVENT_REPORTING_ENABLED == STD_ON) eliminiert (Zero Runtime Overhead).

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Zuordnung: SWS-Anforderung ECUC_Dcm_01245.
  • Generator-Vertrag:
  • Durch requiresSymbolicNameValue = true erzeugt der BSW-Konfigurator typsichere C-Makros (Literal-IDs) der referenzierten IdsMEvent-Instanzen im Dcm_Cfg.h bzw. IdsM_Cfg.h.
  • BSW-Integration & Abhängigkeiten:
  • Die Aktivierung setzt eine vollständige IdsM-Modulkonfiguration voraus.
  • Zirkuläre bzw. unvollständige Konfigurationen (z. B. aktivierte Referenz ohne gültiges IdsMEvent-Target) müssen vom BSW-Validator mit Validierungsfehlern quittiert werden.
  • Echtzeit- und Latenzbetrachtung:
  • UDS-Dienste unterliegen harten P2/P2*-Zeitschranken. Entwickler müssen sicherstellen, dass die IdsM-Meldefunktion (IdsM_SetSecurityEvent) nicht-blockierend arbeitet (asynchrone Event-Pufferung im IdsM), um das Diagnose-Antwort-Timing nicht zu verletzen.
