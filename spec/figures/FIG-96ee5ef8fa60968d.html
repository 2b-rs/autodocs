1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Aktivitätsdiagramm (Entscheidungs- und Kontrollflussdiagramm).
  • Architektur-Kontext: AUTOSAR Foundation Protocol Specification Time Synchronization over Ethernet (AUTOSAR_FO_PRS_TimeSyncOverEthernetProtocol, gültig für Releases R24-11 und R25-11).
  • Funktionale Einordnung: Spezifikation des Validierungs- und Entprellungsalgorithmus eines Time Slaves (z. B. im BSW-Modul EthTSyn bzw. in der Schicht oberhalb des Ethernet-Treibers) für eingehende SYNC-Nachrichten. Der Algorithmus stellt sicher, dass Nachrichtenverluste, PDU-Duplikate, eingefrorene Zählerstände (stuck counter) oder unzulässige Zählersprünge erkannt und verfälschte Zeitstempel vor der Übergabe an das Synchronized Time-Base Manager Modul (StbM) verworfen werden.

2. Komponenten, Entitäten & Schnittstellen

Akteure & Protokoll-Entitäten
  • Time Master: Sendende Instanz der Ethernet-SYNC-PDUs (inkl. Ingress-/Egress-Zeitstempel).
  • Time Slave: Empfangende Instanz, die den Zustands- und Kontrollfluss zur Validierung ausführt.
  • SYNC Message: TimeSync-over-Ethernet-PDU, enthaltend:
    • SC(n): Sequenzzähler der aktuell empfangenen Nachricht n.
    • TIMEOUT-Bit: Status-Flag im Protokoll-Header (TIMEOUT = 1 signalisiert ein zuvor aufgetretenes Timeout-Ereignis beim Sender/Master).
Zustandsvariablen & Zähler (Slave-intern)
  • SC(n-1): Zuletzt empfangener und gespeicherter Sequenzzählerwert.
  • Valid sequence counter (SC) jumps count: Integer-Zustandsvariable zur Zählung aufeinanderfolgender valider Zählersprünge zwecks Hysteresefilterung.
Konfigurationsparameter & Schwellwerte
  • GlobalTimeSequenceCounterJumpWidth: Konfigurierbare maximale Schrittweite für inkrementelle Zählersprünge. Wenn > 0, ist die Überwachung aktiv.
  • GlobalTimeSequenceCounterHysteresis: Konfigurierbare Entprellschwelle. Definiert, wie viele fehlerfreie aufeinanderfolgende Sprünge erforderlich sind, um nach einem Timeout-Zustand wieder als valide eingestuft zu werden.
Zugeordnete Spezifikationsanforderungen
  • [PRS_TS_00269]: Startup-Ausnahme (erste Nachricht nach Initialisierung).
  • [PRS_TS_00270]: Schwellwertaktivierung (JumpWidth > 0) und Timeout-Bit-Auswertung.
  • [PRS_TS_00271]: Validitätsgrenzen im regulären Betrieb ohne Timeout.
  • [PRS_TS_00272]: Erkennung stagnierender Sequenzzähler (Stuck Counter).
  • [PRS_TS_00273]: Transition/Initialisierung bei der ersten Nachricht im Timeout-Zustand.
  • [PRS_TS_00274]: Sprungweitenprüfung für Folge-Nachrichten im Timeout-Zustand.
  • [PRS_TS_00275]: Hysterese-Bedingung vor Wiederherstellung der Gültigkeit.

3. Dynamisches Verhalten & Sequenzablauf

Der Algorithmus wird synchron bei jedem Empfang einer SYNC-PDU durchlaufen:

[Initial]
   │
   ▼
(First Message after Startup?) ──[yes]──────────────────────────────────────────────┐
   │ [no]                                                                           │
   ▼                                                                                │
(GlobalTimeSequenceCounterJumpWidth > 0?) ──[no]────────────────────────────────────┤
   │ [yes]                                                                          │
   ▼                                                                                │
(TIMEOUT bit == 1?)                                                                 │
   │                                                                                │
   ├──[no]──► (0 < SC(n) - SC(n-1) <= JumpWidth?) ──[yes]───────────────────────────┤
   │             │ [no]                                                             │
   │             └─────────────────────────────────────────────────────┐            │
   │                                                                   │            │
   └──[yes]──► (SC(n) - SC(n-1) == 0?) ──[yes]──► [count = 0]          │            │
                  │ [no]                                   │           │            │
                  ▼                                        ▼           │            │
               (First message in Timeout?)                Merge        │            │
                  ├──[yes]──► [count = 1] ─────────────────┤           │            │
                  └──[no]──► (SC(n) - SC(n-1) <= JumpWidth?)           │            │
                                ├──[yes]──► [count++] ─────┤           │            │
                                └──[no]───► [count = 0] ───┘           │            │
                                                           │           │            │
                                                           ▼           │            │
                                     (count < Hysteresis + 1?)         │            │
                                        │ [yes]            │ [no]      │            │
                                        ▼                  └───────────┼────────────┤
                                      Merge                            │            │
                                        │ ◄────────────────────────────┘            ▼
                                        ▼                                   [SC is valid]
                              [SC is not valid]                                    │
                                        │                                          │
                                        └──────────────────┬───────────────────────┘
                                                           ▼
                                                        [Final]
  1. Startup-Bypass ([PRS_TS_00269]):
    • Ist es die erste Nachricht nach Startup/Reset (First Message after Startup? == yes), terminiert die Prüfung direkt mit Sequence Counter is valid. SC(n) wird als Basis SC(n-1) übernommen.
  2. Deaktivierungs-Bypass ([PRS_TS_00270]):
    • Ist GlobalTimeSequenceCounterJumpWidth == 0, ist die Sprungweitenüberwachung inaktiv; das Ergebnis ist sofort Sequence Counter is valid.
  3. Regulärer Pfad (Kein Timeout, TIMEOUT-Bit = 0):
    • Prüfung gemäß [PRS_TS_00271]: $0 < (SC(n) - SC(n-1)) \le \text{GlobalTimeSequenceCounterJumpWidth}$.
    • Bedingung erfüllt: Direkt Sequence Counter is valid.
    • Bedingung verletzt (Rücksprung, Stillstand oder Sprung > JumpWidth): Direkt Sequence Counter is not valid.
  4. Fehler- und Timeout-Pfad (TIMEOUT-Bit = 1):
    • Stuck-Counter-Check ([PRS_TS_00272]): Falls SC(n) - SC(n-1) == 0, liegt ein stehender Zähler vor → count = 0.
    • Erste Nachricht im Timeout ([PRS_TS_00273]): Falls nicht stuck, aber erste Nachricht im Timeout → count = 1.
    • Folgenachrichten im Timeout ([PRS_TS_00274]):
      • Falls $(SC(n) - SC(n-1)) \le \text{GlobalTimeSequenceCounterJumpWidth} \rightarrow \text{count++}$.
      • Falls Sprungweite überschritten → count = 0.
  5. Hysterese-Bewertung ([PRS_TS_00275]):
    • Alle Pfade aus Schritt 4 laufen im Hysterese-Knoten zusammen: $\text{count} < \text{GlobalTimeSequenceCounterHysteresis} + 1$.
    • Wahr (yes): Die geforderte Entprellanzahl wurde noch nicht erreicht → Sequence Counter is not valid.
    • Falsch (no): Die Hystereseschwelle ist überwunden → Sequence Counter is valid.

4. Normative Relevanz & Entwickler-Hinweise

  • Modulo-Arithmetik bei Zählerüberlauf: Die Differenz (SC(n) - SC(n-1)) muss als vorzeichenlose Modulo-Differenz über die Bitbreite des Sequence Counters (typischerweise 2^8 = 256 oder 2^16 = 65536) implementiert werden: $$\Delta SC = (SC(n) - SC(n-1)) \pmod{2^N}$$ Ein naiver vorzeichenbehafteter Vergleich führt beim Zählerüberlauf zu fälschlich verworfenen Nachrichten.
  • Gültigkeitsauswirkung auf den Time-Sync-Stack: Liefert die Auswertung Sequence Counter is not valid, darf die empfangene SYNC-PDU nicht zur Uhrennachführung (Drift-/Offset-Korrektur) im StbM herangezogen werden. Der zugehörige Ingress-Zeitstempel t_2 ist zu verwerfen.
  • Persistenter Modulkontext: Der Time Slave muss pro Synchronisationsdomäne folgende Zustände im RAM vorhalten:
    • SC_last (SC(n-1))
    • IsFirstMessageAfterStartup (boolesch, nach Reset auf TRUE, nach erster PDU auf FALSE)
    • ValidSequenceCounterJumpsCount (vorzeichenloser Zähler)
    • Zuletzt bekannter Timeout-Status zur Unterscheidung von „First message in Timeout“.
  • Konfigurationsabhängigkeit: Bei statisch konfiguriertem GlobalTimeSequenceCounterJumpWidth = 0 entfällt der gesamte Überprüfungs- und Hysteresezweig; der Compiler kann diesen Codepfad optimierend eliminieren (Pre-Compile-Variante).
