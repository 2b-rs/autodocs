1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm / Metamodell-Ausschnitt zur Parametrierung eines BSW-Moduls (AUTOSAR ECU Configuration Parameter Definition gemäß ECUCParameterDefinitions).
  • Architektur-Kontext: Konfigurationsmetamodell des Function Inhibition Managers (FiM) innerhalb der System Services der AUTOSAR Classic Platform (Spezifikationsstand v1.1.0 / AUTOSAR Release 2.1).
  • Technischer Zweck: Formale Definition des Konfigurationsschemas zur Generierung von FiM-Deskriptoren, Speicherstrukturen und RTE-Schnittstellen. Der FiM bildet das funktionale Bindeglied zwischen diagnostischen Ereignissen (DemEventId aus dem Diagnostic Event Manager) und funktionseinschränkenden Software-Komponenten/BSW-Funktionen via Function Identifiers (FID).

2. Komponenten, Entitäten & Schnittstellen

Metamodell-Wurzel & Moduldefinition
  • AUTOSARParameterDefinition : EcuParameterDefinition: Metamodell-Container des Gesamtsystems. Aggregiert über +module (Kardinalität [0..1]) das Modul Fim : ModuleDef.
  • Fim : ModuleDef: Wurzel der FiM-Konfiguration. Aggregiert Container für globale Parameter, FIDs, Summaries und Inhibitions-Matrizen.
Container-Hierarchie (ParamConfContainerDef)
  • FimGeneral ([1..1]): Globale Schalter und statische Dimensionierungsparameter.
  • FimFid ([0..*]): Deklaration einzelner Function Identifier (FIDs).
    • Enthält Parameter FimFuntionId : IntegerParamDef ([1..1], min=0, max=65535, symbolicNameValue=true): Numerischer ID-Wert der Funktion (Tippfehler FimFuntionId ist normativ im Metamodell verankert).
  • FimSummaryEventId ([0..*]): Deklaration von Sammel-Events zur Aggregation mehrerer Dem-Events.
    • Enthält Parameter FimEventSumId : IntegerParamDef ([1..1], min=0, max=65535, symbolicNameValue=true): Symbolischer Bezeichner des Summary-Events.
  • FimEventSummary ([0..*]): Verknüpfungs-Container für Event-Zusammenfassungen.
  • FimInhibitionConfiguration ([0..*]): Definition der Hemmungsbeziehungen (Zuordnung von Events bzw. Summary-Events zu FIDs inklusive Inhibitionsmasken).
Parameter unter FimGeneral (+parameter)
  • Boolesche Schalter (BooleanParamDef, jeweils [1..1]):
    • FimVersionInfoApi: Schaltet die API Fim_GetVersionInfo() zur Compile-Zeit frei.
    • FimDevErrorDetect: Aktiviert API-Parameterprüfungen und Fehlerreporting an den Default Error Tracer (Det_ReportError).
    • FimCyclicEventEvaluation: Steuert die Auswertestrategie (zyklisches Polling vs. ereignisgesteuertes Polling/Push).
    • FimDataFixed: Legt fest, ob Konfigurationstabellen unveränderlich im ROM (CONST) abgelegt werden (Pre-Compile/Link-Time) oder Laufzeitmodifikationen zulassen.
  • Dimensionierungsparameter (IntegerParamDef, jeweils [1..1], min=1 [bzw. 0], max=65535):
    • FimMaxTotalLinks: Maximale Gesamtzahl aller konfigurierten Verknüpfungen zwischen Events und FIDs.
    • FimMaxEventFidLinks: Obergrenze aktiver Event-zu-FID-Kopplungen.
    • FimMaxEventsPerFid: Maximale Anzahl an Dem-Events, die eine einzelne FID sperren dürfen (Fan-In).
    • FimMaxFidsPerEvent: Maximale Anzahl an FIDs, die durch ein einzelnes Dem-Event inhibiert werden können (Fan-Out).
    • FimMaxSummaryEvents (min=0): Maximale Anzahl konfigurierbarer Summary-Events.
    • FimMaxSummaryLinks: Maximale Anzahl an Verknüpfungen innerhalb von Event-Summaries.

3. Dynamisches Verhalten & Sequenzablauf

Aus den Parametern leitet sich direkt das Laufzeitverhalten des FiM ab:

[Dem_ReportErrorStatus] / Dem-Event
          │
          ├── (FimCyclicEventEvaluation == FALSE) ──> Fim_DemTriggerOnEventStatus() [Push via Dem]
          │                                                       │
          └── (FimCyclicEventEvaluation == TRUE)                  ▼
                    │                                   Status-Aktualisierung
                    ▼                                   in interner FiM-Tabelle
        Fim_MainFunction() [Zyklus]                               │
                    │                                             │
                    └─ Dem_GetEventStatus() [Pull]                │
                                                                  ▼
[SWC / Application] ─── Fim_GetFunctionPermission(FID, &perm) ─── Inhibit-Evaluation (Maskenabgleich)
  • Ereignisverarbeitung:
    • Ist FimCyclicEventEvaluation == TRUE, pollt die periodische Task Fim_MainFunction() die Event-Zustände via Dem_GetEventStatus().
    • Ist FimCyclicEventEvaluation == FALSE, informiert der Dem den FiM aktiv bei Statusänderungen über Fim_DemTriggerOnEventStatus().
  • Berechtigungsabfrage: Applikations-SWCs fragen zyklisch oder vor Funktionsausführung via RTE Fim_GetFunctionPermission(Fid, &Permission) ab.
  • Fehlerpfade: Bei aktivem FimDevErrorDetect == TRUE validiert der FiM Parameter (z. B. uninitialisierter Zustand FIM_E_UNINIT, ungültige FID FIM_E_INVALID_FID, NULL-Zeiger) und leitet Det-Fehler synchron ab.

4. Normative Relevanz & Entwickler-Hinweise

  • Speicher- und Array-Dimensionierung (BSW-Generator): Die Parameter FimMaxTotalLinks, FimMaxEventsPerFid und FimMaxFidsPerEvent dienen Pre-Compile- und Link-Time-Generatoren zur statischen Allokation von Lookup-Tabellen im RAM/ROM. Unterdimensionierung führt zu Generator-Fehlern; Überdimensionierung verschwendet statischen Speicher.
  • Flash-vs-RAM-Optimierung: FimDataFixed = TRUE verlagert Verknüpfungsmatrizen vollständig in den Flash (.rodata/CONST), wodurch wertvolles BSW-RAM eingespart wird (Post-Build-Änderungen an Inhibitionsbeziehungen sind dann ausgeschlossen).
  • Symbolic Names: Wegen symbolicNameValue = true bei FimFuntionId und FimEventSumId generiert der Konfigurator C-Makros der Form FimConf_FimFid_<ContainerName> bzw. Header-Defines, die typisiert in der RTE und den Applikations-Headers (Rte_Type.h / Fim.h) verwendet werden müssen.
  • Spezifikations-Artefakt: Der Metamodell-Bezeichner FimFuntionId enthält herstellungsbedingt ein fehlendes c; Generatoren und XML-Deskriptoren (ARXML) für R2.1 müssen diesen exakten Tag-Namen verwenden, um Schema-Validierungsfehler zu vermeiden.
