1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Binäres PDU- / Wire-Format-Layout (Bit-/Byte-Feld-Spezifikation, 32-Bit-Raster, Network Byte Order / Big-Endian).
  • Architektur-Kontext:
  • Protokollebene: AUTOSAR SOME/IP Service Discovery (AUTOSAR_FO_PRS_SOMEIPServiceDiscoveryProtocol, Foundation / Classic Platform BswM/Sd / Adaptive Platform ara::com).
  • Funktionaler Zweck: Normiertes 16-Byte-Eintragsformat (Eventgroup Entry Type) innerhalb des Entries-Arrays einer SOME/IP-SD-Nachricht. Dient der dynamischen Steuerung des Publish/Subscribe-Mechanismus für Eventgruppen auf Transportebene (UDP/TCP).

2. Komponenten, Entitäten & Schnittstellen

Strukturierte 128-Bit (16 Byte) Datenstruktur gemäß [PRS_SOMEIPSD_00845]:

| Offset (Bit) | Feldbezeichnung | Datentyp | Wertebereich / Semantik |

| :--- | :--- | :--- | :--- |

| 00 .. 07 | Type | uint8 | 0x06: Subscribe / StopSubscribeEventgroup
0x07: SubscribeAck / SubscribeEventgroupNack |

| 08 .. 15 | Index 1st options | uint8 | Nullbasierter Startindex des 1. Options-Runs im SD-Options-Array. |

| 16 .. 23 | Index 2nd options | uint8 | Nullbasierter Startindex des 2. Options-Runs im SD-Options-Array. |

| 24 .. 27 | # of opt 1 | uint4 | Anzahl konsekutiver Optionen im 1. Options-Run (0 = keine Option). |

| 28 .. 31 | # of opt 2 | uint4 | Anzahl konsekutiver Optionen im 2. Options-Run (0 = keine Option). |

| 32 .. 47 | Service ID | uint16 | Eindeutige Kennung des SOME/IP-Dienstes (0x0001 .. 0xFFFE). |

| 48 .. 63 | Instance ID | uint16 | Spezifische Instanz-ID des Dienstes. Einschränkung: 0xFFFF (Wildcard/Any) ist unzulässig! |

| 64 .. 71 | Major Version | uint8 | Hauptversion des referenzierten Dienstes ([PRS_SOMEIPSD_00268]). |

| 72 .. 95 | TTL (Time to Live) | uint24 | Gültigkeitsdauer der Subscription in Sekunden.
TTL > 0: Subscribe / SubscribeAck.
TTL == 0: StopSubscribe / SubscribeEventgroupNack. |

| 96 .. 107 | Reserved | uint12 | Normativ fixiert auf 0x000 (Sender-Zwang; Empfänger ignoriert). |

| 108 .. 111| Counter | uint4 | Differenzierung paralleler identischer Subscriptions desselben Clients; 0x0, falls nicht genutzt. |

| 112 .. 127| Eventgroup ID | uint16 | Eindeutige Kennung der abonnierten Eventgruppe (0x0001 .. 0xFFFF). |

  • Beziehungen zu SD-Optionen:
  • 1:n-Referenzierung von Endpunkt-Optionen (IPv4-Endpoint, IPv6-Endpoint, IPv4-Multicast, etc.) über die Run-Indizes und Längenzähler.
  • Typischerweise verknüpft ein Subscribe-Entry eine Unicast-Endpoint-Option für die Event-Übertragung.

3. Dynamisches Verhalten & Sequenzablauf

Das Bitfeld Type in Kombination mit dem Wert von TTL steuert den Zustandsübergang der Eventgruppen-Subscription:

  1. Abonnement (SubscribeEventgroup):
  • Client sendet Entry mit Type = 0x06 und TTL > 0.
  • Bindung an Netzwerk-Endpunkte erfolgt über referenzierte Endpoint-Optionen (z. B. UDP-Client-Port für Unicast-Events).
  1. Bestätigung (SubscribeEventgroupAck):
  • Server akzeptiert Abonnement: sendet Antwort-Entry mit Type = 0x07 und TTL > 0 (vom Server zugewiesene Lease-Time).
  • Optional: Angabe einer Multicast-Endpoint-Option im Option-Array bei Multicast-Eventgruppen.
  1. Ablehnung (SubscribeEventgroupNack):
  • Server weist Abonnement ab: sendet Entry mit Type = 0x07 und TTL = 0x000000.
  1. Kündigung (StopSubscribeEventgroup):
  • Client beendet Abonnement vor Ablauf der Lease-Time: sendet Entry mit Type = 0x06 und TTL = 0x000000.
  1. Erneuerung (Renewal):
  • Vor Ablauf des Timers (TTL) triggert der Client zyklisch einen erneuten SubscribeEventgroup-Eintrag (Type = 0x06, TTL > 0).

4. Normative Relevanz & Entwickler-Hinweise

  • Endianness & Bit-Packing:
  • Sämtliche Multi-Byte-Werte (uint16, uint24) sind strikt in Network Byte Order (Big-Endian) zu serialisieren/deserialisieren.
  • Nibble- und Sub-Byte-Felder (# of opt 1/2, Reserved (12 Bit), Counter (4 Bit)) erfordern bitweise Maskierung:
  • Byte 3: (num_opt_1 << 4) | (num_opt_2 & 0x0F)
  • Byte 12: (reserved >> 4) & 0xFF
  • Byte 13: ((reserved & 0x0F) << 4) | (counter & 0x0F)
  • Stack-Validierung (PRS_SOMEIPSD_00270, PRS_SOMEIPSD_00845):
  • Instance ID: Im Gegensatz zu Service Entries (Type 0x00/0x01), bei denen 0xFFFF für „alle Instanzen“ zulässig ist, muss der SOME/IP-SD-Stack einen Eventgroup Entry mit Instance ID == 0xFFFF verwerfen (Malformed Entry).
  • Reserved: Beim Parsen darf ein Wert ungleich 0x000 nicht zum Verwerfen der PDU führen (Forward-Compatibility), beim Zusammenbau muss der Stack zwingend 0x000 schreiben.
  • Classic Platform BswM/Sd Konfiguration:
  • Zuordnung zu SdConsumedEventGroup / SdProvidedEventGroup.
  • SdEventGroupEntry korrespondiert 1:1 mit den ARXML-Parametern SdConsumedEventGroupId bzw. SdProvidedEventGroupId.
  • Überwachung der TTL-Timer erfolgt im BSW-Modul Sd über die periodische Hauptfunktion Sd_MainFunction().
