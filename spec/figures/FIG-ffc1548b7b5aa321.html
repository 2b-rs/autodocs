1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR BSW-Konfigurationsmetamodell (ECUC Parameter Configuration Diagram / UML-Klassendiagramm) gemäß AUTOSAR-Metamodell-Standard, ergänzt durch einen tabellarischen Auszug einer Parameter- und Containerdefinition.
  • Funktionaler Kontext: Konfiguration der UDP-basierten Kommunikationsbeziehungen des BSW-Moduls DoIP (Diagnostic over IP) zur Unterlagerung an das Modul SoAd (Socket Adaptor). Dient der statischen Deklaration von UDP-Schnittstellen für verbindungslose DoIP-Funktionen (Fahrzeugidentifikation/-ankündigung, Entity-Status-Abfragen und Routing-Aktivierungsvorstufen gem. ISO 13400-2).

2. Komponenten, Entitäten & Schnittstellen

  • DoIPUdpConnection (EcucParamConfContainerDef):
    • Multiplizität: 1 .. 255.
    • Rolle: Repräsentiert eine logische UDP-Verbindungskonfiguration innerhalb des DoIP-Stacks zur Abbildung von UDP-Endpunkten.
  • DoIPSoAdUdpRxPdu (EcucParamConfContainerDef):
    • Multiplizität: 1 .. 1 (Kompositions-Subcontainer von DoIPUdpConnection).
    • Parameter & Referenzen:
      • DoIPSoAdUdpRxPduId (EcucIntegerParamDef): Wertebereich 0 .. 65535, withAuto = true, symbolicNameValue = true. Definiert den symbolischen Bezeichner (PduIdType), über den SoAd ankommende UDP-Frames dem DoIP zuordnet.
      • DoIPSoAdUdpRxPduRef (EcucReferenceDef): Referenziert via +destination eine globale Pdu aus dem systemweiten EcuC-PDU-Pool (EcucPdu).
  • DoIPSoAdUdpTxPdu (EcucParamConfContainerDef):
    • Multiplizität: 1 .. 1 (Kompositions-Subcontainer von DoIPUdpConnection).
    • Parameter & Referenzen:
      • DoIPSoAdUdpTxPduId (EcucIntegerParamDef): Wertebereich 0 .. 65535, withAuto = true, symbolicNameValue = true. Handle-ID für DoIP-interne Sendeaufrufe.
      • DoIPSoAdUdpTxPduRef (EcucReferenceDef): Referenziert via +destination dieselbe oder eine korrespondierende Sende-Pdu in EcucPdu.
  • Pdu (EcucParamConfContainerDef, aus EcucPdu):
    • Multiplizität: 0 .. *.
    • Rolle: Globales PDU-Metamodell-Element zur Kopplung zwischen DoIP, PduR und SoAd.

3. Dynamisches Verhalten & Sequenzablauf (Mapping auf BSW-Laufzeit)

  • Empfangspfad (Rx):
    1. Ankunft eines UDP-Datagramms an einem konfigurierten SoAd-Socket.
    2. SoAd löst synchron SoAd_RxIndication(RxPduId, PduInfoPtr) bzw. den DoIP-spezifischen Callback aus.
    3. Der DoIP-Stack validiert den DoIP-Header (Payload-Typ z. B. 0x0001 Vehicle Identification Request) anhand der gemappten DoIPSoAdUdpRxPduId.
  • Sendepfad (Tx):
    1. Trigger durch internen Timer (Vehicle Announcement) oder eingehenden Request (Vehicle Announcement Response).
    2. DoIP serialisiert die UDP-Payload und ruft synchron die I-PDU-Transmissions-API auf: SoAd_IfTransmit(DoIPSoAdUdpTxPduRef->TargetPduId, &PduInfo).
    3. Quittierung erfolgt asynchron über DoIP_SoAdIfTxConfirmation() via Pdu-ID-Match.
  • Fehlerbehandlung:
    • Ungültige PDU-IDs oder Pufferüberläufe führen zu Det-Fehlern (DOIP_E_INVALID_PDU_SDU_ID bzw. DOIP_E_PARAM_POINTER).

4. Normative Relevanz & Entwickler-Hinweise

  • Variantenbindung (Pre-compile time):
    • Gemäß Kopftabelle ist die Konfiguration rein als Pre-compile time (X für alle Varianten) deklariert; Post-Build Variant Value = false. Keine dynamische Rekonfiguration oder Post-Build-Umschaltung von UDP-PDU-Handles zulässig.
  • 1:1-Symmetrie je UDP-Kanal:
    • Jede DoIPUdpConnection erzwingt strikt genau eine Rx-PDU (Multiplicity = 1) und genau eine Tx-PDU (Multiplicity = 1). Ein asymmetrischer oder rein unirektionaler UDP-Kanal ist im Metamodell für DoIP nicht vorgesehen.
  • SoAd-Konfigurationsabhängigkeit:
    • Die referenzierten Pdu-Elemente müssen exakt mit korrespondierenden SoAdRxPdu bzw. SoAdTxPdu-Containern im SoAd gemappt sein. Die Socket-Connection-Groups im SoAd müssen auf UDP (SOAD_SOCK_PROT_UDP) und die DoIP-Portnummer (Standard: 13400) gebunden sein.
  • Symbolic Name Generation:
    • Durch symbolicNameValue = true generiert der BSW-Generator C-Makros (z. B. DoIPConf_DoIPSoAdUdpRxPdu_<Name>), welche als numerische Handle-IDs im BSW-C-Code und in SoAd-Routingtabellen konsistent zu halten sind.
