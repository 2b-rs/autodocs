1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: SPEM 2.0-basiertes Prozess- und Datenflussdiagramm (AUTOSAR Methodology Activity and Work Product Flow) gemäß AUTOSAR_TR_Methodology.
  • Funktionale Einordnung: Definiert den formalisierten methodischen Workflow zur Festlegung, Abstimmung und Verifikation von Datenaustauschpunkten (Data Exchange Points, DEP) im verteilten E/E-Entwicklungsprozess zwischen OEMs, Tier-1-Zulieferern und Tool-Herstellern.
  • Architektonischer Zweck: Begrenzung der syntaktischen und semantischen Freiheitsgrade des umfangreichen AUTOSAR-Metamodells. Das Diagramm spezifiziert, wie aus generischen Spezifikationen und Baseline-Profilen ein vertraglich bindendes, maschinell prüfbares ARXML-Teilmengenprofil entsteht, gegen das reale Lieferartefakte validiert werden.

2. Komponenten, Entitäten & Schnittstellen

Aktivitäten (Methodology Tasks / Activities)
  • Create Profile of Data Exchange Point: Aktivität zur initialen Erstellung bzw. iterativen Ausprägung eines DEP-Profilentwurfs.
  • Create Agreed Profile for Data Exchange Point: Bilaterale oder multilaterale Konsolidierungs- und Harmonisierungsaktivität, die aus verschiedenen Profilvorschlägen einen einheitlichen Standard aushandelt.
  • Validate Compliance of Autosar Artifact [with Profile of Data Exchange Point]: Automatisierte/statische Konformitätsprüfung eines konkreten Modellartefakts gegen das verabschiedete Profil und dessen Baseline.
Artefakte (Work Products / Deliverables)
  • **Autosar Specification [0..\*]:** Formale AUTOSAR-Standarddokumente, Metamodell-Definitionen (ARXML-XSD/Rules).
  • **General Non Autosar Artifact [0..\*]:** Externe Dokumente und Randbedingungen (z. B. OEM-Austauschrichtlinien, firmeninterne Namenskonventionen, PDF-Spezifikationen).
  • **General Autosar Artifact [0..\*]:** Reale AUTOSAR-Beschreibungsdateien (z. B. System Description, ECU Extract, Software Component Description).
  • Baseline Profile of Data Exchange Point [1]: Vorgegebenes Basisprofil (Referenz-Subset des Metamodells), das als unveränderlicher Ausgangspunkt dient.
  • **Profile of Data Exchange Point [1..\*]:** Entwurfsstand eines DEP-Profils (Constraints, OCL-Regeln, Pflicht-/Optionalitäts-Matrix).
  • Agreed Profile of Data Exchange Point [1]: Final freigegebenes, konsolidiertes und verbindliches Austauschprofil.
Beziehungen & Stereotypen
  • Stereotyp «input»: Deklariert Datenfluss und funktionale Abhängigkeit als Eingangsartefakt einer Aktivität.
  • Stereotyp «output»: Deklariert das von einer Aktivität erzeugte Ergebnisartefakt.
  • Kardinalitäten & Abhängigkeiten:
    • Create Profile of Data Exchange Point:
      • Inputs: Autosar Specification (0..*), General Non Autosar Artifact (0..*), General Autosar Artifact (0..*), Baseline Profile of Data Exchange Point (1), Profile of Data Exchange Point (0..* als Rückkopplung/Iteration).
      • Output: Profile of Data Exchange Point (1).
    • Assoziation +baseline (1): Gerichtete Referenz vom erstellten Profile of Data Exchange Point auf das zugrunde liegende Baseline Profile of Data Exchange Point.
    • Create Agreed Profile for Data Exchange Point:
      • Input: Profile of Data Exchange Point (1..*).
      • Output: Agreed Profile of Data Exchange Point (1).
    • Validate Compliance of Autosar Artifact...:
      • Inputs: Agreed Profile of Data Exchange Point (1), Baseline Profile of Data Exchange Point (über gerichteten Pfad), General Autosar Artifact (Liefergegenstand).

3. Dynamisches Verhalten & Sequenzablauf

  1. Profil-Initialisierung & Iteration:
    • Trigger: Initiierung eines Datenaustauschs zwischen Partnern (z. B. System-Design-Übergabe an Steuergeräte-Entwicklung).
    • Unter Einbindung der normativen Spezifikationen (Autosar Specification), OEM-spezifischer Regeln (General Non Autosar Artifact) und vorhandener Musterartefakte (General Autosar Artifact) wird bezugnehmend auf eine feste Baseline (Baseline Profile) ein Profilentwurf abgeleitet.
    • Der Pfad Profile of Data Exchange Point → Create Profile... («input» 0..*) bildet eine synchrone Iterationsschleife zur schrittweisen Verfeinerung des Entwurfs.
  2. Harmonisierung (Consensus Gate):
    • Mindestens ein oder mehrere Profilentwürfe (1..*) fließen in Create Agreed Profile for Data Exchange Point ein.
    • Synchroner bilateraler Abgleich zwischen OEM und Zulieferer: Konflikte in Modellabdeckungen, Datentypen oder optionalen Containern werden ausgeräumt.
    • Das Resultat ist genau eine unzweideutige Instanz: Agreed Profile of Data Exchange Point (1).
  3. Konformitätsvalidierung (Quality Gate / Fail-Fast):
    • Vor dem Einpflegen oder Weiterverarbeiten eines gelieferten ARXML-Artefakts (General Autosar Artifact) führt Validate Compliance... eine automatisierte Prüfung aus.
    • Validierungsmatrix: Einhaltung der Regeln des Agreed Profile sowie die Rückwärtskompatibilität zur referenzierten Baseline Profile.
    • Abbruchbedingung: Schlägt die Validierung fehl (Verletzung von Metamodell-Einschränkungen, fehlende Pflichtelemente, unzulässige Split-Dateien), wird das Artefakt zurückgewiesen, bevor Generatoren oder Stacks inkonsistent gespeist werden.

4. Normative Relevanz & Entwickler-Hinweise

  • Toolchain- und Ingest-Konfiguration:
    • Import-Filter in Autoren- und Konfigurationswerkzeugen (z. B. DaVinci, EB tresos, Vector CAST) müssen exakt auf das Agreed Profile of Data Exchange Point parametriert werden (Schema-Schematron-/OCL-Rulesets).
  • Auswirkung auf BSW-, RTE- und Applikations-Entwickler:
    • API- und Metamodell-Garantie: Das Profil definiert verbindlich, welche SWC-Ports, Daten-Semantiken, Init-Werte und Bus-Mappings im ARXML garantiert vorhanden sind. Das verhindert Laufzeitfehler und Generator-Abbrüche durch fehlende Metamodell-Elemente, die im globalen AUTOSAR-Metamodell als optional (0..1), im Profil aber als obligatorisch (1) deklariert wurden.
    • CI/CD Integration: Die Aktivität Validate Compliance... muss zwingend als automatisierter Pre-Commit- oder Pre-Build-Hook in der Integrations-Pipeline implementiert sein, um fehlerhafte ARXML-Lieferungen unmittelbar an der Schnittstelle abzufangen.
