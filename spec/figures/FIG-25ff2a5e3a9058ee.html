1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm zur Definition des AUTOSAR ECUC-Metamodells (ECU Configuration Parameter Definition) gemäß AUTOSAR Classic Platform (SWS OS, R21-11).
  • Technischer Zweck: Formale Spezifikation des Konfigurationscontainers OsTask (ECUC_Os_00080), der die statischen Attribute, Ressourcenkopplungen, Zugriffsrechte, Autostart-Bedingungen und Laufzeitüberwachungsmechanismen (Timing Protection) von OS-Tasks festlegt.
  • Architektur-Einordnung: Basis-Software (BSW) System Services, Schicht 1 (OS/RTE-Fundament). Bildet die Schnittstelle zwischen Generator-Toolchain (ARXML → statischer C-Code des OS) und Scheduler-Laufzeitumgebung.

2. Komponenten, Entitäten & Schnittstellen

Zentraler Container
  • OsTask (EcucParamConfContainerDef, Multiplizität: 0..*): Repräsentiert einen OSEK/AUTOSAR-Task.
Parameter (+parameter)
  • OsTaskPriority (EcucIntegerParamDef): Statische Task-Priorität (Bereich 0 bis 4294967295). Höhere numerische Werte bedeuten höhere Priorität.
  • OsTaskActivation (EcucIntegerParamDef): Maximale Anzahl zulässiger, schwebender Aktivierungsanforderungen (Bereich 1 bis 4294967295). Definiert Queuing-Tiefe bei Mehrfachaktivierung (ActivateTask()).
  • OsTaskSchedule (EcucEnumerationParamDef): Präemptionsverhalten:
    • NON: Kooperativer Task (Non-preemptive).
    • FULL: Verdrängbarer Task (Fully preemptive).
  • OsTaskPeriod (EcucFloatParamDef, Multiplizität: 0..1): Nennperiode des Tasks für Zeitanalyse / Schedule-Tabellen.
Sub-Container (+subContainer)
  • OsTaskAutostart (EcucParamConfContainerDef, Multiplizität: 0..1):
    • OsTaskAppModeRef (EcucReferenceDef, Multiplizität: 1..*): Referenziert OsAppMode (1..*), in welchen der Task beim OS-Start (StartOS()) automatisch in den Zustand READY überführt wird.
  • OsTaskTimingProtection (EcucParamConfContainerDef, Multiplizität: 0..1): Konfiguration für OS-Skalierbarkeitsklassen SC2/SC4:
    • OsTaskExecutionBudget (EcucFloatParamDef, 0..1, Einheit: Sekunden, Wertebereich: 0..INF): Maximale Netto-Ausführungszeit pro Task-Instanz.
    • OsTaskTimeFrame (EcucFloatParamDef, 0..1, Bereich 0..INF): Minimaler zeitlicher Abstand zwischen zwei aufeinanderfolgenden Task-Aktivierungen (Inter-Arrival-Time).
    • OsTaskAllInterruptLockBudget (EcucFloatParamDef, 0..1): Maximale Blockierdauer für globale Interrupt-Sperren (DisableAllInterrupts() / SuspendAllInterrupts()).
    • OsTaskOsInterruptLockBudget (EcucFloatParamDef, 0..1): Maximale Sperrdauer für Cat-2-Interrupts (SuspendOSInterrupts()).
    • OsTaskResourceLock (EcucParamConfContainerDef, Multiplizität: 0..*):
      • OsTaskResourceLockBudget (EcucFloatParamDef, Bereich 0..INF): Maximale Haltezeit für eine spezifische Ressource.
      • OsTaskResourceLockResourceRef (EcucReferenceDef): Referenziert die überwachte OsResource.
Referenzen (+reference)
  • OsTaskEventRef (EcucReferenceDef, Multiplizität: 0..*): Ziel: OsEvent (0..*). Vorhandensein klassifiziert den Task normativ als Extended Task (Unterstützung von WaitEvent()). Fehlen definiert einen Basic Task.
  • OsTaskResourceRef (EcucReferenceDef, Multiplizität: 0..*): Ziel: OsResource (0..*). Deklariert Zugriffsberechtigung für das OSEK-Priority-Ceiling-Protokoll (GetResource()).
  • OsTaskAccessingApplication (EcucReferenceDef, Multiplizität: 0..*): Ziel: OsApplication (0..*). Bestimmt OS-Applikationen mit Berechtigung zur Inter-OS-Application-Manipulation (ActivateTask(), etc.).
  • OsMemoryMapping (EcucForeignReferenceDef, Multiplizität: 0..1): Zieltyp SW-ADDR-METHOD / SwAddrMethod. Verknüpft Task-Stacks und -Code mit Speichersektionen des Compilers/Linkers.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm modelliert die statische Parametrierung, die folgende Laufzeit-Trigger und Zustandsübergänge steuert:

  1. Systemstart (StartOS):
    • Das OS liest den aktiven OsAppMode aus. Stimmt dieser mit mindestens einer Referenz in OsTaskAutostart.OsTaskAppModeRef überein, wechselt der Task synchron von SUSPENDED nach READY.
  2. Task-Aktivierung & Verdrängung:
    • Bei Aufruf von ActivateTask() prüft das OS, ob die Anzahl schwebender Instanzen kleiner als OsTaskActivation ist. Überschreitungen führen zu E_OS_LIMIT.
    • Bei Aktivierung gegen einen aktiven Task entscheidet OsTaskSchedule: Ist der aktive Task FULL und hat der aktivierte Task eine strikt höhere OsTaskPriority, erfolgt ein synchroner Kontextwechsel. Bei NON wird der Task erst bei TerminateTask(), WaitEvent() oder Schedule() verdrängt.
  3. Event-Handling (nur bei vorhandenen OsTaskEventRef):
    • Aufruf von WaitEvent(EventMask) überführt den Task in den Zustand WAITING. Das Setzen eines konfigurierten Events via SetEvent() reaktiviert ihn in READY.
  4. Timing-Protection-Monitoring (SC2/SC4):
    • Execution Budget: OS-Hardware-Timer überwacht die Ausführungszeit gegen OsTaskExecutionBudget. Bei Überlauf greift die Protection Hook mit der Aktion PRO_TERMINATETASKISR oder PRO_SHUTDOWN.
    • Time Frame: Trifft eine Aktivierung vor Ablauf von OsTaskTimeFrame ein, wird die Aktivierung verworfen und ein Protection-Fault ausgelöst.
    • Lock Budgets: Überschreitung von OsTaskResourceLockBudget, OsTaskAllInterruptLockBudget oder OsTaskOsInterruptLockBudget triggert unmittelbar die konfigurierte OS-Schutzreaktion.

4. Normative Relevanz & Entwickler-Hinweise

  • Basic vs. Extended Task:
    • Hat OsTaskEventRef Multiplizität 0, generiert der Generator einen Basic Task (minimaler TCB-Footprint, gemeinsamer Stack möglich in BCC1/BCC2).
    • Sobald mindestens ein Event referenziert wird, wird der Task zum Extended Task (ECC1/ECC2). Folge: Exklusiver Task-Stack erforderlich, was den RAM-Bedarf massiv erhöht.
  • Prioritätsumkehr & Deadlocks:
    • Jede über GetResource() genutzte Ressource muss zwingend in OsTaskResourceRef deklariert sein, damit der Ceiling-Prioritätswert zur Generierungszeit korrekt auf das Maximum aller zugreifenden Tasks kalkuliert werden kann.
  • OS-Skalierbarkeitsklassen:
    • Parameter unter OsTaskTimingProtection sind nur in den Klassen SC2 und SC4 zulässig und wirksam. In SC1/SC3 erzeugt deren Vorhandensein Konfigurationsfehler oder ungenutzte Datenstrukturen.
  • Speicherschutz (MPU) & Core-Zuweisung:
    • Tasks ohne Eintrag in OsTaskAccessingApplication dürfen nicht aus fremden Nicht-Trusted-Applikationen via API manipuliert werden.
    • Das Foreign-Mapping OsMemoryMapping steuert Linker-Attribute via Memory-Mapping-Header (MemMap.h) für Task-Stacks zur MPU-Region-Konfiguration.
