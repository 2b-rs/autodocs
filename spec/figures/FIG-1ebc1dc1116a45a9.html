1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm (AUTOSAR BSW-Metamodell / ECU Configuration Parameter Definition – ECUC).
  • Technischer Zweck: Formale Definition des Konfigurationscontainers DltGeneral innerhalb des BSW-Moduls Diagnostic Log and Trace (Dlt, AUTOSAR Classic Platform Release R23-11).
  • Architektur-Einordnung: Dlt ist im System Services Layer angesiedelt. Der Container DltGeneral kapselt modulweite Vorkompilierungs- und Post-Build-Schalter sowie Schnittstellen-Referenzen zu Zeitgebern (Gpt, StbM) und persistentem Speicher (NvM), welche die globale Codegenerierung, Ressourcenallokation und funktionale Leistungsmerkmale (Zeitstempelung, Traffic-Shaping, Injection, Pufferverwaltung) determinieren.

2. Komponenten, Entitäten & Schnittstellen

Zentraler Container
  • DltGeneral (EcucParamConfContainerDef): Root-Container für generelle Modulkonfigurationen des DLT-Treibers/Stacks.
Parameter (+parameter Kompositionen)
  • DltGeneralDevErrorDetect (EcucBooleanParamDef): Schaltet die Erkennung und Meldung von Entwicklungsfehlern (Det) ein/aus.
  • DltGeneralRegisterContextNotification (EcucBooleanParamDef): Aktiviert die Benachrichtigung bei Kontext-Registrierungen (defaultValue = false).
  • DltGeneralInjectionSupport (EcucBooleanParamDef): Schaltet Runtime-Injektion von Daten/Befehlen via DLT frei (defaultValue = false).
  • DltGeneralRxDataPathSupport (EcucBooleanParamDef): Aktiviert den Empfangspfad für DLT-Steuer- und Injektionsnachrichten (defaultValue = false).
  • DltGeneralTrafficShapingSupport (EcucBooleanParamDef): Aktiviert Bandbreitenbegrenzung und Drosselung des DLT-Ausgangsverkehrs (defaultValue = true).
  • DltGeneralTimeStampSupport (EcucBooleanParamDef): Aktiviert das Hinzufügen von Zeitstempeln zu Log-Nachrichten (defaultValue = false).
  • DltGeneralVersionInfoApi (EcucBooleanParamDef): Aktiviert die API Dlt_GetVersionInfo (lowerMultiplicity = 0, upperMultiplicity = 1).
  • DltGeneralStartUpDelayTimer (EcucFloatParamDef): Startverzögerung in Sekunden vor Beginn der Übertragung (min = 0.001, max = 10, lowerMultiplicity = 0, upperMultiplicity = 1).
  • DltGeneralNvRAMSupport (EcucBooleanParamDef): Aktiviert Persistierung von Laufzeitparametern (z. B. Log-Levels, Trace-Status je Applikation/Kontext) im NVRAM (defaultValue = false).
  • DltProtocolVersion (EcucIntegerParamDef): DLT-Protokollversion im Header (min = 1, max = 255, defaultValue = 1, lowerMultiplicity = 0, upperMultiplicity = 1).
  • DltMaxNumberOfChannels (EcucIntegerParamDef): Maximale Anzahl logischer Kommunikationskanäle (min = 1, max = 65535, lowerMultiplicity = 1, upperMultiplicity = 1).

3. Dynamisches Verhalten & Sequenzablauf

Als rein statisches Metamodell bildet das Diagramm keine Laufzeitsequenzen direkt ab; es erzwingt jedoch folgende dynamische Verhaltenspfade:

  1. Initialisierungsphase (Dlt_Init):
    • Wenn DltGeneralStartUpDelayTimer konfiguriert ist, startet Dlt_Init einen Verzögerungs-Timer. Log-Meldungen werden währenddessen blockiert oder verworfen/gepuffert, um Busüberlastungen während des Systemhochlaufs zu verhindern.
    • Wenn DltGeneralNvRAMSupport == true, triggert Dlt nach dem Hochlauf das Einlesen der Filter- und Log-Level-Konfigurationen aus dem über DltGeneralNvRamRef adressierten Block via NvM_ReadBlock.
  2. Zeitstempel-Akquise bei Log-Events:
    • Wenn DltGeneralTimeStampSupport == true:
      • Primärpfad über StbM: Abruf synchronisierter Netzwerkzeit via StbM_GetCurrentTime unter Nutzung von DltGeneralStbMTimeBaseRef.
      • Alternativpfad über Gpt: Freilaufender Hardware-Timer via Gpt_GetTimeElapsed über den in DltGeneralGptChannelRef gebundenen Kanal.
  3. Eingehende Steuer- und Injektionsnachrichten:
    • Ist DltGeneralRxDataPathSupport == true, verarbeitet die Dlt-Hauptfunktion eingehende Rx-PDUs. Bei gesetztem DltGeneralInjectionSupport == true werden Callbacks an Applikationen/SW-Cs zur Befehlsausführung weitergeleitet.
  4. Fehlerpfade:
    • Wenn DltGeneralDevErrorDetect == true, lösen ungültige Parameter an den DLT-APIs Aufrufe an Det_ReportError mit den spezifischen DLT-Fehlercodes (z. B. DLT_E_PARAM_POINTER, DLT_E_NOT_INITIALIZED) aus.

4. Normative Relevanz & Entwickler-Hinweise

  • Bedingte Abhängigkeiten (Configuration Consistency):
    • Wird DltGeneralTimeStampSupport aktiviert, muss zwingend entweder DltGeneralStbMTimeBaseRef (bevorzugt für zeitsynchronisierte Systeme wie AUTOSAR Ethernet/CAN-FD TSN) oder DltGeneralGptChannelRef aufgelöst sein.
    • Ist DltGeneralNvRAMSupport == true, muss DltGeneralNvRamRef gesetzt sein; ein unkonfigurierter Verweis führt zu Validierungsfehlern im Generator.
    • DltGeneralInjectionSupport erfordert zwingend DltGeneralRxDataPathSupport == true.
  • Speicher- und Laufzeitoptimierung:
    • Schalter wie DltGeneralDevErrorDetect, DltGeneralVersionInfoApi und DltGeneralInjectionSupport steuern Präprozessor-Makros (STD_ON / STD_OFF). Deaktivierung eliminiert nicht genutzte Codepfade vollständig aus dem Flash.
    • DltMaxNumberOfChannels dimensioniert RAM-Arrays statisch für Puffer-Deskriptoren und Kanalzustände zur Compile-Zeit.
  • Symbolic Name Values:
    • Alle Referenzen (NvMBlockDescriptor, GptChannelConfiguration, StbMSynchronizedTimeBase) fordern requiresSymbolicNameValue = true. In generierten C-Headern muss der Zugriff strikt über die symbolischen Konstanten der jeweiligen Modulkonfigurationen erfolgen, nicht über hartcodierte Integer-IDs.
