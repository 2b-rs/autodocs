1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Sequenzdiagramm (Interaktionsdiagramm).
  • Technischer Zweck: Spezifikation des asynchronen Verarbeitungsmodells von Security Events (SEv) im Intrusion Detection System Manager (IdsM, AUTOSAR CP R20-11) unter Nutzung des Synchronized Time-Base Manager (StbM) als standardisierte AUTOSAR-Zeitstempelquelle (IdsMTimestampFormat = AUTOSAR).
  • Architektonische Einordnung: Entkopplung des schnellen Sensor-Meldekontexts (ISR/Task) von der zeitintensiven Zeitstempelgenerierung und Weiterverarbeitung im zyklischen BSW-Scheduler-Kontext (BswDefaultTask).

2. Komponenten, Entitäten & Schnittstellen

  • Akteure & BSW-Module:
  • Sensor (Akteur/Caller): BSW-Modul (z. B. CanIf, LinIf, SecOC, KeyM) oder Application SW-C (über RTE/Service-Port), fungiert als IDS-Sensor zur Erkennung von Sicherheitsvorfällen.
  • IdsM (BSW-Modul, Service Layer): Zentrale Instanz zur Aggregation, Filterung, Pufferung und Qualifizierung von Security Events.
  • StbM (BSW-Modul, System Service Layer): Zeitbasis-Provider für synchronisierte globale Systemzeiten (z. B. via CAN/Ethernet/PTP).
  • BswDefaultTask (OS-Task / Scht / BswM): Ausführungskontext für periodische BSW-Hauptfunktionen.
  • Schnittstellen & Interne Entitäten:
  • IdsM_SetSecurityEvent(SecurityEventDefinitionId, ...): Synchrone Ingress-API für Sensoren.
  • Input Event Queue: Interne Pufferstruktur des IdsM zur temporären Ablage von Roh-Events (Store SEv in input event queue).
  • IdsM_MainFunction(): Zyklische Scheduling-API (gemäß BSW-Scheduler-Vertrag).
  • IdsM_ProcessInputEventQueue(): Modulinterne Subroutine zur Entleerung und Validierung der Eingangswarteschlange.
  • StbM_GetCurrentTime(StbM_SynchronizedTimeBaseType, StbM_TimeStampType, StbM_UserDataType): Synchrone Service-API zur Abfrage der aktuellen Zeitstempel-Informationen.

3. Dynamisches Verhalten & Sequenzablauf

  1. Ingress & Pufferung (asynchron zum Batch-Processing):
  • Sensor ruft synchron IdsM_SetSecurityEvent() auf.
  • IdsM legt das Event minimal-invasiv in der Input Event Queue ab (Store SEv in input event queue).
  • Unmittelbarer Return an den Aufrufer (nicht-blockierend für zeitkritische Sensoren/ISRs).
  1. Periodischer Trigger:
  • BswDefaultTask triggert turnusmäßig IdsM_MainFunction().
  1. Queue-Verarbeitung & Zeitstempel-Akquise:
  • IdsM ruft intern IdsM_ProcessInputEventQueue() auf.
  • IdsM setzt einen synchronen Abruf an den Zeitbasis-Manager ab: StbM_GetCurrentTime().
  • StbM liefert aktuelle Zeitstruktur zurück.
  1. Finalisierung des Batches:
  • IdsM generiert den AUTOSAR-konformen Zeitstempel (Generate timestamp).
  • Iterative Abarbeitung aller gepufferten SEvs: Allen in diesem Zyklus aus der Queue entnommenen Events wird der ermittelte Zeitstempel zugewiesen (Process all SEvs...).
  • Abschluss der IdsM_MainFunction() und Rückkehr zum Task-Kontext.

4. Normative Relevanz & Entwickler-Hinweise

  • Latenz vs. Zeitstempel-Präzision:
  • Der Zeitstempel repräsentiert nicht den exakten Auftrittszeitpunkt am Sensor, sondern den Entnahme- und Verarbeitungszeitpunkt in der IdsM_MainFunction(). Entwickler müssen die daraus resultierende Zeitunschärfe (Scheduling-Jitter des BswDefaultTask + Task-Zykluszeit) in Sicherheitsbetrachtungen einkalkulieren.
  • Dimensionierung der Input Queue:
  • Da die Abarbeitung gebündelt im Zyklus erfolgt, muss die Pufferkapazität (IdsMInputEventQueueSize) auf Burst-Szenarien und Worst-Case-Taskaktivierungsabstände ausgelegt sein; Queue-Überläufe führen sonst zum Verlust von Sicherheitsereignissen (Det/Dem-Meldung).
  • Konfigurations-Abhängigkeiten (IdsM / StbM):
  • IdsMTimestampSupport muss aktiviert und IdsMTimestampFormat auf AUTOSAR parametriert sein.
  • Dem IdsM muss eine gültige StbM_SynchronizedTimeBaseType (Timebase-ID) zugeordnet sein.
  • Wiedereintrittsfähigkeit & Thread-Safety:
  • IdsM_SetSecurityEvent() muss interrupt- bzw. threadsicher ausgelegt sein (z. B. geschützt über SchM-Exklusivbereiche / Spinlocks), da Schreibzugriffe aus Multi-Core- oder ISR-Kontexten zeitgleich zur Queue-Entleerung in der IdsM_MainFunction() erfolgen können.
