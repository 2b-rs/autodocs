1. Diagrammtyp & Architektur-Kontext

Timing-Ablaufdiagramm (Scheduling Timeline) mit diskreter Taktachse zur Darstellung der zeitlichen Abfolge von Task-Ausführungen in einem präemptiven Betriebssystem mit statischen Prioritäten (Fixed-Priority Preemptive Scheduling). Der Kontext ist das AUTOSAR Classic OS (SWS OS, Timing Protection), speziell die Erläuterung der konzeptionellen Unzulänglichkeit einer reinen Fristüberwachung (Deadline Monitoring) gegenüber der Laufzeit- und Aktivierungsintervall-Überwachung (Execution Time & Inter-Arrival Time Protection).

2. Komponenten, Entitäten & Schnittstellen

  • Task A: Höchstpriore Task (Spur A) mit spezifiziertem Ausführungsbudget und periodischer Aktivierung.
  • Task B: Mittelpriore Task (Spur B) mit spezifiziertem Ausführungsbudget und Mindestaktivierungsintervall.
  • Task C: Niedrigstpriore Task (Spur C) mit vorgegebener Ausführungsdauer und absoluter Frist (Deadline).
  • Zeitachse: Diskrete Ticks von 0 bis 17 mit gleichmäßiger Skalierung.
  • Farbcodierte Ausführungsblöcke:
    • Grau: Spezifikationskonforme Ausführungszeit der Tasks A, B und C.
    • Rot: Spezifikationswidrige Mehrausführung (Execution Time Overrun) von Task B (Tick 4–5) und Task A (Tick 6–7).
    • Grün: Verzögerte Ausführung von Task C nach Überschreiten ihrer Frist (Tick 15–16).
  • Indikatoren und Beschriftungsblöcke:
    • Rotes Ausrufezeichen (!): Eintritt einer Fristverletzung (Deadline Miss) bei Task C bei Tick 15.
    • Text-Callouts: Detaillierung von Budgetüberschreitungen (Task A, Task B), Frühattivierung/Inter-Arrival-Verletzung (Task B bei Tick 8 statt 10) sowie Verfehlen der Frist von Task C trotz normgerechten Verhaltens.

3. Dynamisches Verhalten & Sequenzablauf

  • Ticks 0–1: Task A startet zur Aktivierungszeit 0 und terminiert spezifikationsgemäß nach 1 Tick.
  • Ticks 1–5: Task B führt aus. Spezifiziert waren 3 Ticks (1–4); Task B überzieht unzulässig um 1 Tick (rot markiert, Ticks 4–5), hält jedoch ihre eigene Deadline ein.
  • Ticks 5–7: Task A wird reaktiviert und unterbricht Task B bzw. startet sofort. Spezifiziert war 1 Tick (5–6); Task A überzieht um 1 Tick (rot markiert, Ticks 6–7), hält aber ebenfalls ihre Deadline ein.
  • Ticks 7–8: Task C erhält erstmals Prozessorzeit und führt für 1 Tick aus.
  • Tick 8: Task B trifft vorzeitig ein (Tick 8 statt spezifiziert Tick 10) und unterbricht Task C aufgrund höherer Priorität.
  • Ticks 8–11: Task B führt 3 Ticks regulär aus.
  • Ticks 11–12: Task A wird aktiviert und verdrängt die noch laufende Task B für 1 Tick reguläre Ausführung.
  • Ticks 12–13: Task B setzt ihre Ausführung nach Terminierung von Task A fort und hält ihre Frist ein.
  • Ticks 13–15: Task C setzt ihre Ausführung fort (2 weitere Ticks, kumuliert 3 Ticks).
  • Tick 15: Die Deadline von Task C verstreicht (rotes Ausrufezeichen). Task C hat zu diesem Zeitpunkt 3 von 4 spezifizierten Ticks ausgeführt; 1 Tick verbleibt.
  • Ticks 15–16: Task C schließt ihre Ausführung verspätet ab (grüner Block).
  • Kausalität: Die Fristverletzung tritt ausschließlich bei Task C auf, obwohl die Ursachen kumulierte Laufzeitüberziehungen von Task A und B sowie die verfrühte Aktivierung von Task B sind.

4. Normative Relevanz & Entwickler-Hinweise

  • Das Diagramm dient als Begründung für die Einführung von Timing Protection Mechanismen im AUTOSAR OS (OsTaskExecutionBudget, OsTaskTimeFrame).
  • Reines Deadline Monitoring ist im präemptiven Festprioritäten-Scheduling prinzipiell unzureichend für das Fault-Containment: Höherpriore Tasks, die ihr Zeitbudget überziehen oder zu früh/häufig eintreffen, verdrängen niederpriore Tasks und verursachen bei diesen Fristverletzungen, während sie ihre eigenen Fristen einhalten.
  • Eine Fehlerreaktion basierend auf Deadline Monitoring würde fehlerhaft die unschuldige Task C sanktionieren, anstatt die Verursacher A oder B abzufangen.
  • Entwickler müssen bei ASIL-relevanten Systemen Timing Protection im OS konfigurieren, um Mehrausführungen und Verletzungen von Mindestzeitabständen direkt am Entstehungsort per Protection Hook (z. B. Terminierung der überziehenden Task) zu isolieren.
