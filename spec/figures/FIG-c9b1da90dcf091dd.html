1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm auf Metamodellebene (M2-Spezifikation gemäß AUTOSAR-Metamodell).
  • Technischer Zweck: Formale Definition des Typ- und Wertesystems für Parameter-Referenzen innerhalb der AUTOSAR ECU-Konfiguration (AUTOSAR_TPS_ECUConfiguration, R4.0.3).
  • Funktionale Einordnung: Entkopplung und Zuordnung zwischen der formalen Konfigurationsdefinition (BSW-Modulbeschreibungen / BSWMD im Paket ECU Configuration Parameter Definition) und den konkreten Projektkonfigurationswerten (EcuC-Instanzen im Paket ECU Configuration Parameter Values). Ermöglicht typisierte Verlinkungen innerhalb des BSW-Stacks, zu externen System-Beschreibungen (Foreign References) sowie zu instanziierten Software-Komponenten/Ports (Instance References).

2. Komponenten, Entitäten & Schnittstellen

Paket: ECU Configuration Parameter Definition (Definitionsmodell / BSWMD)
  • EcucAbstractReferenceDef (abstrakt): Spezialisierung von EcucCommonAttributes. Abstrakte Basisklasse aller Referenzdefinitionsparameter.
  • EcucAbstractInternalReferenceDef (abstrakt, erbt von EcucAbstractReferenceDef): Basisklasse für interne Konfigurationsreferenzen.
    • + requiresSymbolicNameValue: Boolean [0..1]: Gibt an, ob der referenzierte Wert als symbolischer Name aufgelöst werden muss.
  • EcucUriReferenceDef: Spezialisierung von EcucAbstractInternalReferenceDef für URI-basierte Referenzierungen.
  • EcucReferenceDef: Spezialisierung von EcucAbstractInternalReferenceDef für direkte interne Referenzen.
  • EcucChoiceReferenceDef: Spezialisierung von EcucAbstractInternalReferenceDef für polymorphe Auswahllisten-Referenzen.
  • EcucAbstractExternalReferenceDef (abstrakt, erbt von EcucAbstractReferenceDef): Basisklasse für externe Referenzen.
  • EcucInstanceReferenceDef: Spezialisierung von EcucAbstractExternalReferenceDef für kontextsensitive Instanzreferenzen in hierarchische Modelle.
    • + destinationContext: String: Metamodell-Kontextpfad.
    • + destinationType: String: Metamodell-Typ des referenzierten Zielknotens.
  • EcucForeignReferenceDef: Spezialisierung von EcucAbstractExternalReferenceDef für Referenzen auf Metamodell-Elemente außerhalb der ECU-Konfiguration.
    • + destinationType: String: Metamodell-Typ des Zielelements.
Paket: ECU Configuration Parameter Values (Instanzmodell / EcuC-ARXML)
  • Identifiable (abstrakt, erbt von MultilanguageReferrable): Basisklasse aller adressierbaren Werte-Entitäten.
    • + category: CategoryString [0..1]
    • + uuid: String [0..1]
  • EcucContainerValue: Repräsentiert eine instanziierte Container-Instanz (erbt von Identifiable und spezialisiert EcucIndexableValue).
    • Rekursive Komposition: +subContainer * mit Stereotyp «atpVariation,atpSplitable».
    • Komposition zu Referenzen: +referenceValue → * EcucAbstractReferenceValue mit Stereotyp «atpVariation,atpSplitable».
  • EcucAbstractReferenceValue (abstrakt, spezialisiert EcucIndexableValue): Abstrakte Instanzklasse eines Referenzwerts.
    • Assoziation +definition [1] → EcucAbstractReferenceDef: Zwingende Bindung an die Schema-Definition.
  • EcucReferenceValue: Konkreter Wert einer internen, Choice- oder Foreign-Referenz (erbt von EcucAbstractReferenceValue).
  • EcucInstanceReferenceValue: Konkreter Wert einer Instanz-Referenz (erbt von EcucAbstractReferenceValue).
    • Assoziation mit Stereotyp «instanceRef»: +value 1 → AtpFeature (zielgerichtete Instanz in der Topologie).

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches M2-Metamodell der Konfigurationsphase handelt, existiert kein CPU-Laufzeitablauf. Das Verarbeitungsverhalten in der AUTOSAR-Toolchain folgt folgendem deterministischen Generierungspfad:

[ARXML Ingestion]
       │
       ▼
[Schema Validation] ─── EcucAbstractReferenceValue.definition == EcucAbstractReferenceDef
       │
       ▼
[Target Resolution]
       ├── EcucReferenceValue: Auflösung des Identifiable-Pointers (Container-Instanz oder Foreign Model-Element)
       └── EcucInstanceReferenceValue: Auflösung des Pfad-Kontexts («instanceRef») bis zum konkreten AtpFeature
       │
       ▼
[Code Generation] ──── Transformation in C-Header/Source: Handles, Pointer-Arrays, Config-Strukturen
  • Validierungs-Trigger: Vor der Code-Generierung muss die Typprüfung gegen destinationType bzw. destinationContext fehlerfrei auflösen; ungültige Pfade führen zum Toolchain-Abbruch (Generator Error).
  • Splitting-Auflösung: Vor der Codegenerierung konsolidiert der Konfigurator alle partiellen ARXML-Fragmente gemäß «atpSplitable».

4. Normative Relevanz & Entwickler-Hinweise

  • Trennung von EcuC-internen und externen Referenzen:
    • EcucReferenceValue referenziert direkt ein Identifiable. Zeigt sie auf einen anderen BSW-Container (z. B. CanIfCtrlCfg → CanController), generiert der BSW-Generator meist direkte C-Konstanten (symbolische IDs/Handles).
    • Zeigt sie über EcucForeignReferenceDef auf externe Metamodell-Elemente (z. B. SystemSignal), erfolgt die Zuordnung stringbasiert über den Metaklassennamen (destinationType), was strikte Modellkonsistenz zwischen System Description und EcuC erfordert.
  • Kontextsensitive Bindung via EcucInstanceReferenceValue:
    • Unverzichtbar für RTE- und Service-Mappings (z. B. NvM-Block-zu-SWC-Port, Dem-Event-zu-SWC-Port).
    • Der Entwickler/Integrator muss sicherstellen, dass die vollständige Instanzkette (vom Root-Composition-Prototyp bis zum Ziel-AtpFeature) im ARXML serialisiert ist; unvollständige Kontextpfade brechen die RTE-Generierung.
  • Reihenfolgen-Determinismus (EcucIndexableValue.index):
    • Werden Referenzlisten in Array-basierte BSW-Strukturen überführt (z. B. Routing-Tabellen im PduR oder Callbacks im Com-Modul), garantiert das optionale Attribut index eine plattformunabhängige, feste Reihenfolge im generierten C-Code, unabhängig von der Einlesereihenfolge der ARXML-Tags.
  • Post-Build- und File-Splitting («atpVariation,atpSplitable»):
    • Container und Referenzen dürfen auf OEM- und Tier1-Dateien aufgeteilt (atpSplitable) oder an System-Konstanten gebunden werden (atpVariation). BSW-Treiberentwickler müssen berücksichtigen, dass nicht auflösbare Referenzwerte unter inaktiven Variant-Conditions zur Compilezeit per Präprozessor-Schalter ausmaskiert oder für Post-Build-Selectable als NULL-Pointer strukturiert werden müssen.
