1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Detailliertes Bit- und Byte-orientiertes PDU-Layout (Protokolldateneinheit-Struktur) gemäß AUTOSAR-Netzwerk- und Wire-Format-Standard (32-Bit-Word-Grid, Big-Endian / Network Byte Order).
  • Architektur-Kontext: AUTOSAR Foundation / Classic & Adaptive Platform, Spezifikation AUTOSAR_FO_PRS_SOMEIPServiceDiscoveryProtocol (PRS_SOMEIPSD).
  • Funktionaler Zweck: Exemplarische Serialisierung einer SOME/IP-SD-Nachricht (SOME/IP-SD Example PDU for Non-SOME/IP-SD). Das Layout demonstriert, wie SOME/IP Service Discovery nicht nur für native SOME/IP-Services genutzt wird, sondern über reservierte Service-IDs (hier 0xFFFE) und Konfigurations-Optionen auch zur Lokalisierung und Parameterbekanntgabe von Nicht-SOME/IP-Diensten (z. B. DoIP, interne Diagnose-Dienste, Raw-TCP/UDP-Sockets) innerhalb serviceorientierter Fahrzeugarchitekturen eingesetzt wird.

2. Komponenten, Entitäten & Schnittstellen

A. SOME/IP-Header (16 Bytes Basiskopf)
  • Message ID (0xFFFF8100):
    • Service ID (0xFFFF): Reservierte System-Service-ID für SOME/IP-SD.
    • Method ID / Event ID (0x8100): Bit 15 = 1 kennzeichnet ein Event/Notification (Event ID = 0x0100).
  • Length (0x0000005C = 92 Bytes): Gesamtlänge aller nachfolgenden Bytes ab Request ID (8 Bytes Rest-Header + 84 Bytes SD-Nutzlast).
  • Request ID (0x00000000 / ECU-spezifisch): Zusammengesetzt aus Client ID (16 Bit) und monoton inkrementierender Session ID (16 Bit zur Erkennung von Paketverlusten/Duplikaten).
  • Protocol Version: 0x01 (SOME/IP-Standard).
  • Interface Version: 0x01.
  • Message Type: 0x02 (NOTIFICATION).
  • Return Code: 0x00 (E_OK).
B. SOME/IP-SD-Header / Flags (4 Bytes)
  • Flags (8 Bit, 0x80):
    • Bit 7 (Reboot Flag): 1 signalisiert Kaltstart/Neustart des Knotens seit der letzten Session.
    • Bit 6 (Unicast Flag): 0 signalisiert Multicast-Aussendung.
  • Reserved (24 Bit, 0x000000): Padding/Reserviert gemäß Spezifikation.
C. Entries Array (Länge = 32 Bytes, 2 Einträge à 16 Bytes)
  • Length of Entries Array: 0x00000020 (32 Bytes).
  • Entry 0 (FindService):
    • Type: 0x00 (FindService).
    • Index 1st options: 0x00, Index 2nd options: 0x00.
    • # of opt 1: 0, # of opt 2: 0 (keine Optionen referenziert).
    • Service ID: 0x1001 (Suchanfrage für nativen Service).
    • Instance ID: 0xFFFF (Wildcard: alle Instanzen).
    • Major Version: 0xFF (Wildcard: jede Hauptversion).
    • TTL: 3600 s (0x000E10): Gültigkeitsdauer der Suchanfrage (1 Stunde).
    • Minor Version: 0xFFFFFFFF (Wildcard: jede Unterversion).
  • Entry 1 (OfferService für Non-SOME/IP-Dienst):
    • Type: 0x01 (OfferService).
    • Index 1st options: 0x00 (referenziert Option ab Index 0 im Options-Array).
    • Index 2nd options: 0x00.
    • # of opt 1: 2 (bindet 2 aufeinanderfolgende Optionen: Index 0 und Index 1).
    • # of opt 2: 0.
    • Service ID: 0xFFFE (Kennung für Non-SOME/IP Service / Generic Communication Endpoint).
    • Instance ID: 0x0001 (Instanz 1).
    • Major Version: 0x01.
    • TTL: 3 s (0x000003): Kurze Gültigkeit; erfordert periodische Erneuerung.
    • Minor Version: 0x00000032 (Dezimal 50).
D. Options Array (Länge = 40 Bytes, 2 Optionen)
  • Length of Options Array: 0x00000028 (40 Bytes).
  • Option 0 (IPv4 Endpoint Option, Index 0):
    • Length: 0x0009 (9 Bytes Nutzlast nach Type-Feld).
    • Type: 0x04 (IPv4 Endpoint Option).
    • Discardable Flag: 0 (zwingend zu verarbeitende Option).
    • Reserved: 0x00.
    • IPv4-Address: 192.168.0.1.
    • Reserved: 0x00.
    • L4-Proto: 0x06 (IPPROTO_TCP).
    • Port Number: 0x1A91 (Dezimal 6801).
  • Option 1 (Configuration Option, Index 1):
    • Length: 0x0015 / 0x0025 (Längenfeld für Nutzlast).
    • Type: 0x01 (Configuration Option).
    • Reserved: 0x00.
    • Data Payload: Pascal-String-Format: Längenpräfix 0x16 (22 Bytes) gefolgt vom UTF-8-Key-Value-Paar otherserv=internaldiag, terminiert mit Nullbyte (0x00). Deklariert den Diensttyp für den generischen Endpunkt 0xFFFE.

3. Dynamisches Verhalten & Sequenzablauf

  1. Multiplexing im SD-Rahmen: Eine einzelne SD-PDU bündelt simultan Client- und Server-Aktionen desselben Knotens:
    • Client-Rolle (Entry 0): Asynchrone Suchanfrage (FindService) nach Service 0x1001 über Multicast (239.255.0.1 / ff02::8).
    • Server-Rolle (Entry 1): Ankündigung (OfferService) eines internen Diagnosedienstes.
  2. Option-Referenzierung via Pointer-Indizierung:
    • Entry 1 definiert Index 1st options = 0 und # of opt 1 = 2.
    • Der Empfänger-Parser iteriert ab Position 0 im Options-Array über genau zwei aufeinanderfolgende Optionen (Endpoint + Configuration). Entry 0 ignoriert das Options-Array vollständig (# of opt = 0).
  3. Reboot-Handling:
    • Da Reboot Flag = 1, signalisiert die PDU den Erststart oder Reset des Knotens. Kommunikationspartner müssen zuvor gespeicherte Sessions/Subscriptions verwerfen und ihren Session-Counter zurücksetzen.
  4. TTL-Überwachung & Keep-Alive:
    • TTL für Service 0xFFFE beträgt 3 Sekunden. Der Server muss vor Ablauf von 3 s eine zyklische Wiederholung (OfferService) senden. Empfangene Clients starten bei Erhalt einen Abwurftimer; bleibt das Follow-up aus, wird der Endpunkt verworfen.

4. Normative Relevanz & Entwickler-Hinweise

  • Nicht-SOME/IP-Service-Abstraktion:
    • Entwickler von Diagnose-Stacks (z. B. DoIP) oder proprietären TCP-Diensten können SOME/IP-SD als universellen Service-Broker konfigurieren.
    • Das Key-Value-Paar in der Configuration Option (otherserv=internaldiag) dient der Anwendungsschicht als Dispatcher-Schlüssel, um den Socket (192.168.0.1:6801) der korrekten internen Empfängerkomponente zuzuordnen.
  • Parser-Implementierung & Validierung:
    • Option Range Checks: Strikte Validierung von Index 1st options + # of opt 1 <= Total Options Count. Fehlerhafte Indizes führen zu Out-of-Bounds-Zugriffen und müssen mit Det-Meldung verworfen werden.
    • Längen-Integrität: Das PDU-Length-Feld (92 Bytes), das Length of Entries Array (32 Bytes) und das Length of Options Array (40 Bytes) müssen exakt mit der tatsächlichen PDU-Länge korrelieren: 4 + 4 + 4 + 32 + 4 + 40 = 88 Bytes Payload + 4 Bytes Request ID = 92 Bytes. Jede Diskrepanz erfordert das Verwerfen der PDU.
  • Discardable Flag (Bit 0 im Reserved/Flag-Byte der Option):
    • Da Disc. Flag = 0, darf ein Stack, der den Option-Typ 0x04 nicht interpretiert, die gesamte PDU bzw. den zugehörigen Entry nicht akzeptieren.
