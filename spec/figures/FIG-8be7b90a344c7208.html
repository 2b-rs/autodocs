1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Zustandsdiagramm (State Machine Diagram) gemäß OMG-/AUTOSAR-Notation.
  • Architektur-Kontext: AUTOSAR Classic Platform (Release 4.0.3), System Services Layer, Modul Watchdog Manager (WdgM, SWS Document ID 080).
  • Funktionaler Zweck: Modellierung des globalen Überwachungslebenszyklus (Global Supervision Status). Der Automat aggregiert die Einzelergebnisse der lokalen Überwachungszustände (Local Supervision Status) aller aktiven Supervised Entities (SEs) im System. Er steuert zentral die Watchdog-Triggerung über das Watchdog Interface (WdgIf), verwaltet Schutzfristen für Notfall-Routinen (Grace Period) und eskaliert Fehlzustände bis zum kontrollierten oder hardwareseitigen ECU-Reset.

2. Komponenten, Entitäten & Schnittstellen

  • Zustandsmenge (WdgM_GlobalStatusType):
    • WDGM_GLOBAL_STATUS_DEACTIVATED: Initialer Ruhezustand vor Modulinitialisierung oder nach Deinitialisierung. Keine Überwachung aktiv, keine Hardware-Bedienung.
    • WDGM_GLOBAL_STATUS_OK: Nominaler Betriebszustand. Alle aktiven SEs melden fehlerfreie Ausführung.
    • WDGM_GLOBAL_STATUS_FAILED: Toleranzbehafteter Degradationszustand. Mindestens eine SE hat einen lokalen Fehler gemeldet, die globale Fehlerzyklen-Toleranz ist jedoch noch nicht ausgeschöpft. Die Hardware-Triggerung wird fortgesetzt.
    • WDGM_GLOBAL_STATUS_EXPIRED: Nicht-behebbarer Fehlerzustand mit aktiver Schutzfrist (Expired Supervision Tolerance). Der Watchdog wird bewusst nicht mehr getriggert, um den Hardware-Reset herbeizuführen; das System erhält jedoch Rechenzeit für finale Datensicherungen.
    • WDGM_GLOBAL_STATUS_STOPPED: Terminaler Endzustand. Sämtliche Triggerbedingungen sind dauerhaft blockiert. Entweder verharrt die MCU bis zum Ablauf des Hardware-Watchdogs oder leitet den Reset direkt per Treiber ein.
  • Pseudozustände (Junction / Choice):
    • Startzustand (Initial Node): Unkonditionierter Eintritt in WDGM_GLOBAL_STATUS_DEACTIVATED.
    • Entscheidungsrauten (Choice Diamonds): Verzweigung basierend auf dem Konfigurationsparameter WdgMExpiredSupervisionCycleTol (Wert > 0 führt nach EXPIRED, Wert == 0 führt direkt nach STOPPED).
  • Schnittstellen & Parameter:
    • WdgM_Init(), WdgM_DeInit(), WdgM_MainFunction(), WdgM_SetMode().
    • Treiberabstraktion: WdgIf_SetTriggerCondition(), WdgIf_SetMode().
    • Systemdienste: Dem_ReportErrorStatus() (DEM-Event bei STOPPED), Mcu_PerformReset() (optionaler Sofort-Reset).
    • Konfigurationsparameter: WdgMExpiredSupervisionCycleTol ([WDGM329_Conf]), WdgMImmediateReset ([WDGM339_Conf]), WdgMDemStoppedSupervisionReport.

3. Dynamisches Verhalten & Sequenzablauf

Die Zustandsüberführung erfolgt primär synchron im Kontext der zyklischen Hauptfunktion WdgM_MainFunction() in jedem WdgMSupervisionCycle, nachdem alle lokalen Entitäten evaluiert wurden.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationsleitfaden (WdgMExpiredSupervisionCycleTol):
    • Muss in Abhängigkeit der Periodendauer von WdgM_MainFunction dimensioniert werden: $\Delta t_{\text{grace}} = \text{Tol} \times T_{\text{SupervisionCycle}}$.
    • Dieses Zeitfenster bestimmt die maximal verfügbare Zeit für Aufräumarbeiten (z. B. Flushing kritischer Diagnosedaten via NvM_WriteAll() vor dem Reset). Ist Tol = 0, entfällt der Zustand EXPIRED vollständig (direkter Durchmarsch via Transitionen (4)/(8) nach STOPPED).
  • Reset-Strategie (WdgMImmediateReset):
    • Steht dieser Parameter auf TRUE, führt der WdgM beim Erreichen von STOPPED einen synchronen Aufruf von Mcu_PerformReset() aus. Der Hardwarereset dient dann nur als Rückfallebene, falls der Core hängt.
    • Steht der Parameter auf FALSE, wird ausschließlich die Watchdog-Bedienung eingestellt (WdgIf_SetTriggerCondition(..., 0)), wodurch der externe oder interne Hardware-Watchdog die MCU nach Ablauf seines Timeout-Fensters hart zurücksetzt.
  • Fehlermaskierung & Diagnoserückmeldung:
    • Im Zustand WDGM_GLOBAL_STATUS_FAILED wird das System nicht zurückgesetzt. Dieser Zustand fängt temporäre Jitter oder Einzelaussetzer (Alive-Zähler) ab. Applikationen können über RTE-Moduswechsel (Rte_Mode_currentMode_...) über den Zustand FAILED informiert werden, um interne Gegenmaßnahmen einzuleiten.
    • Das Erreichen von WDGM_GLOBAL_STATUS_STOPPED meldet via Dem_ReportErrorStatus() einen qualifizierten Fehler an das DEM (WdgMDemStoppedSupervisionReport), welcher beim nachfolgenden Boot über den Reset-Grund korreliert werden kann.
  • Echtzeit- und Taskbindung:
    • Da WdgM_MainFunction() die Zähler für EXPIRED dekrementiert/inkrementiert, führt ein Verpassen oder Preemptieren dieser Task zu fehlerhaften Fristberechnungen. Die WdgM-Task muss in einer hochprioren, jitterarmen OS-Taskklasse verortet sein.
