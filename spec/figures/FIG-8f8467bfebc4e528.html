1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR VFB-Kompositions- und Funktionsdekompositionsdiagramm (Software Composition Decomposition Diagram) gemäß AUTOSAR Classic R3.0 (Domain: Chassis / Driver Assistance).
  • Technischer Zweck: Funktionale Dekomposition der Software-Composition ACC (Adaptive Cruise Control) in modulare Software-Components (SW-Cs) und Definition der Schnittstellengrenzen (VFB-Ports) zum Basis-Chassis (Vehicle Longitudinal Control, VLC), zum Powertrain und zur HMI.
  • Architektonische Einordnung:
    • ACC-Domain (Komfort-Ebene): Umfeldwahrnehmung, Prädiktion, Abstands-/Geschwindigkeitsregelung und Generierung standardisierter Sollbeschleunigungen (a_target).
    • Chassis-Domain (VLC / Ausführungsebene): Nicht-ACC-Domain; Koordination von Fahrerwunsch, Komfort- und Sicherheitsanforderungen sowie Umsetzung der Sollbeschleunigung in Aktuator-Stellgrößen (Brems- und Antriebsmomente).

2. Komponenten, Entitäten & Schnittstellen

2.1 Software-Components (SW-Cs) & Module
  • Innerhalb der ACC-Domain («AtomicSwComponentType» / Sub-Compositions):
    • Sensor-HW: Abstraktion der physikalischen Erfassungseinheit (Radar/Lidar/Kamera).
    • Sensor Object Processing: Vorverarbeitung und Merkmalsextraktion von Rohzielen.
    • Sensor Fusion (OPT): Optionale Komponente zur probabilistischen Fusion redundanter Objektlisten.
    • (ACC Specific) Vehicle State Observer: Schätzt fahrzeugdynamische Zustände für die ACC (insb. Kurvenkrümmung, prädizierter Fahrschlauch).
    • Target Object Selection: Selektion des führungsrelevanten Zielobjekts (In-Lane Target).
    • Follow Control: Folgeregelung auf Zeitlücke/Abstand zum Zielobjekt.
    • Free Cruise Control: Konventionelle Geschwindigkeitsregelung (Freifahrt).
    • Comfort Acceleration Arbitration: Zentrale ACC-Koordinationseinheit (bestehend aus Sub-Komponenten: Arbitration of control loops und Internal A.D.A.S. State Machine; spezifiziert in 2 Varianten X & Y).
  • Außerhalb der ACC-Domain (Chassis / Powertrain / Platform):
    • Vehicle Longitudinal Control (VLC): Beinhaltet State Machine VLC, Long. Acceleration Arbitrator, Long. Acceleration Control und Long. Force Coordination.
    • Brake Torque Control: Rad-/Achsbezogene Bremsmomentenregelung (Chassis).
    • Engine Torque Control: Triebstrang-/Achs-Momentenregelung (Powertrain).
    • Error Management: Querschnittsfunktionalität (Chassis/Plattform-Diagnose & DEM/DET-Anbindung).
2.2 Schnittstellen-Kategorisierung & Ports
  • Standardisierte AUTOSAR Application Interfaces (Gelbe Ovale – «SenderReceiverInterface»):
    • Perzeption & Tracking: Object Data List, Sensor capability, Obj. Data (after sensor fusion), Sensor capability (after sensor fusion), Target Object Data List.
    • Fahrzeugdynamik & Prädiktion: Vehicle state information (aus Chassis), Predicted Course, ACC Spec. YawRate.
    • Fahrerwunsch / Sollwerte: Time gap request (Zeitlücke), Speed request (Wunschgeschwindigkeit).
    • Regler-Schnittstellen: Acceleration interface (standardisierter Beschleunigungsvektor von Follow Control, Free Cruise Control sowie From other longitudinal controller).
    • Inhibits / Fahrzeugstatus (Eingang ACC State Machine): - Driver override, - Pedals pressed, - Drivetrain open, - Driver Int. Direction, - Parking brake act., - Yaw stability (ESP aktiv), - Wheel slip (TCS aktiv).
    • Aktuator-Kopplung (VLC): - Comfort Acceleration Command interface (Sollbeschleunigung an VLC) und bidirektionales - VLC feedback (Status, Limitierungen, Gradienten).
  • Proprietäre / Nicht standardisierte Schnittstellen (Orange Ovale – OEM-/Sensor-spezifisch):
    • Measurements, Other inputs: Proprietäre Rohdaten zwischen Sensor-HW und Vorverarbeitung.
    • ACC User interface: Interaktion mit fahrzeugspezifischer Cockpit-HMI / Bedienelementen.
    • Decel. Pedal: Direkte Hardware-/Signal-Einkopplung des Bremspedals in die VLC-Arbitrierung.

  1. Signalvorverarbeitung & Fusion: Zyklische Bereitstellung von Zielobjekten und Sensorgüte (Sensor capability). Liegt eine Fusionskomponente vor, aggregiert diese primäre und sekundäre Sensorlisten.
  2. Objektselektion: Target Object Selection verknüpft Fusionsdaten mit dem geschätzten Kursverlauf (Predicted Course, berechnet aus Gierrate und Fahrzeugzustand) zur Bestimmung des Führungsfahrzeugs.
  3. Regler-Parallelität: Follow Control (abstandsgeführt) und Free Cruise Control (geschwindigkeitsgeführt) laufen parallel und emittieren jeweils eine normierte Sollbeschleunigung (Acceleration interface).
  4. Kaskadierte Arbitrierung (Zweistufig):
    • Stufe 1 (ACC-intern – Komfort): Comfort Acceleration Arbitration arbitriert zwischen Abstands- und Geschwindigkeitsregler (Minimum-Auswahl bzgl. Verzögerung) unter Berücksichtigung der internen ADAS-State-Machine und externer Längsregler.
    • Stufe 2 (VLC – Basis-Fahrzeug): Long. Acceleration Arbitrator koordiniert den Komfortbefehl mit Sicherheitsfunktionen (From no comfort system, z. B. AEB) und dem Fahrerwunsch (Accel. Pedal, Decel. Pedal).
  5. Abbruch- und Override-Bedingungen:
    • Betätigung von Fahr- oder Bremspedal (Driver override, Pedals pressed) schaltet die State-Machine in den Passiv-/Override-Modus.
    • Dynamische Eingriffe von Fahrdynamikregelsystemen (Yaw stability, Wheel slip, offener Triebstrang, Parkbremse) erzwingen eine sofortige Deaktivierung oder Beschränkung der ACC-Sollwertausgabe.
  6. Kraftkoordination: Die VLC setzt den resultierenden Beschleunigungsvektor über Long. Force Coordination in physische Brems- (Brake Torque Control) und Antriebsmomente (Engine Torque Control) um.

4. Normative Relevanz & Entwickler-Hinweise

  • VFB-Port-Entkopplung (Physikalische Domänentrennung):
    • Die Schnittstelle zwischen ACC und Fahrzeugplattform (Comfort Acceleration Command interface) ist strikt als Sollbeschleunigung (m/s^2) typisiert. Applikations-SW-Cs innerhalb der ACC-Domain dürfen keine direkten Momenten- oder Drosselklappenanforderungen stellen; die physikalische Umsetzung (Masse, Getriebeübersetzung, Fahrwiderstände) obliegt vollständig der VLC.
  • Standardisierungsfokus (AIS):
    • Gelb markierte Interfaces sind normative AUTOSAR Application Interfaces (Standard-Datentypen, Einheiten, Wertebereiche). Sie gewährleisten die Austauschbarkeit von Regler-SW-Cs (Follow Control, Free Cruise Control) zwischen verschiedenen Zulieferern.
    • Orange Interfaces markieren explizite Integrator-Freiheitsgrade: Rohdatenkommunikation zur Sensorik (Measurements) und HMI-Integration (ACC User interface) unterliegen herstellerspezifischen Spezifikationen und erfordern proprietäre Port-Interface-Mappings.
  • Architekturvarianten (Version X & Y):
    • Der Vermerk 2 versions (X & Y) in Comfort Acceleration Arbitration verweist auf zwei Implementierungsansätze im Standard bezüglich der Verteilung von Zustandsautomat (Internal A.D.A.S. State Machine) und Schlingenarbitrierung (Arbitration of control loops) – entweder integriert in einer SW-C oder als getrennte Runnable Entities / SW-Cs.
  • RTE- und Task-Design:
    • Zykluszeiten: Perzeptions- und Regelungspfade (Follow Control, Target Object Selection) erfordern typischerweise ein deterministisches周期isches Scheduling (z. B. 20 ms oder 40 ms Task).
    • Feedback-Loop: Die Schleife Comfort Acceleration Command ↔ VLC feedback erfordert strikte Laufzeitkontrollen, um Totzeiten und Phasenverzug im Regelkreis zu minimieren. Feedback-Signale müssen auf Sättigungsgrenzen (z. B. maximaler Bremsdruck erreicht) überwacht werden (Anti-Windup).
