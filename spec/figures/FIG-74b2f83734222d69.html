1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Metamodell-Klassendiagramm (Design-Time-Spezifikation).
  • Architektur-Kontext: AUTOSAR Classic Platform (System Template, Release R3.2.3).
  • Technischer Zweck: Definition der statischen Metamodell-Struktur für das Signal-Mapping auf Systemebene. Es bildet die normative Brücke zwischen der logischen Software-Architektur (Virtual Function Bus / VFB, Port-Schnittstellen der Application-Layer-SWCs) und der Kommunikationsmatrix (Netzwerk- und Signalebene). Konkret spezifiziert es die 1:1-Abbildung eines unzusammengesetzten (primitiven) Datenelements eines Sender-Receiver-Interfaces auf ein abstraktes System-Signal unter Berücksichtigung von Teilnetz-Parametern (PNC).

2. Komponenten, Entitäten & Schnittstellen

Metaklassen & Stereotypen
  • SystemTemplate::System
    • Spezialisierung / Kategorie: ARElement, Stereotyp «atpStructureElement».
    • Attribute: ecuExtractVersion: String [0..1], pncVectorLength: Integer [0..1], pncVectorOffset: Integer [0..1], systemVersion: String [1].
    • Rolle: Top-Level-Wurzelelement der Systembeschreibung; aggregiert System-Konfigurationen, Teilnetzwerk-Vektor-Definitionen (PNC) und Extrakt-Metadaten.
  • SystemTemplate::SystemMapping
    • Spezialisierung: Identifiable.
    • Rolle: Zentraler Mapping-Container innerhalb des Systems zur Koppelung von Software-Topologie, Topologie-Knoten und Signalnetzen.
  • DataMapping
    • Typ: Abstrakte Basisklasse (kursiv dargestellt).
    • Rolle: Generalisierter Einstiegspunkt für alle Datenzuordnungsmechanismen im System-Template.
  • SenderReceiverToSignalMapping
    • Spezialisierung: Konkrete Unterklasse von DataMapping.
    • Rolle: Spezifische Abbildungsregel für primitive Sender-Receiver-Datenelemente auf Netzwerk-Signale.
  • PortInterface::DataElementPrototype
    • Spezialisierung / Typ: DataPrototype (abstrakt), Stereotyp «atpPrototype».
    • Attribute: isQueued: Boolean.
    • Rolle: Datenelement-Prototyp innerhalb eines Sender-Receiver-PortInterface (VFB-Ebene). isQueued definiert FIFO-Pufferung vs. Last-is-Best-Semantik.
  • CoreCommunication::SystemSignal
    • Spezialisierung: AbstractSignal.
    • Attribute: length: Integer.
    • Rolle: Logisches Kommunikationssignal im Systemnetzwerk (Netzwerk-Payload-Ebene). length spezifiziert die Bitbreite.
Assoziationen, Kardinalitäten & Abhängigkeiten
  • System → SystemMapping: Komposition (+mapping, Kardinalität 0..1). Ein System kann optional höchstens eine Instanz von SystemMapping enthalten.
  • SystemMapping → DataMapping: Komposition (+dataMapping, Kardinalität *). Ein SystemMapping kapselt beliebig viele Mapping-Instanzen.
  • SenderReceiverToSignalMapping → DataElementPrototype: Gerichtete Abhängigkeit / Referenz mit Stereotyp «instanceRef» (+dataElement, Kardinalität 1). Erfordert einen vollständigen Instanzpfad (InstanceRef), der die Komponentenhierarchie von der Root-Composition über SWC-Prototypen und Ports bis zum konkreten Datenelement auflöst.
  • SenderReceiverToSignalMapping → SystemSignal: Unidirektionale Assoziation (+signal, Kardinalität 1). Bindet das referenzierte Datenelement an exakt ein Signal.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein Artefakt der Entwurfszeit handelt, liegt kein Laufzeit-Sequenzdiagramm vor. Die funktionale Verarbeitung erfolgt entlang der AUTOSAR-Authoring- und Generierungsphasen:

  1. System Definition: Definition von Software-Komponenten, Ports und Datenelementen (DataElementPrototype) sowie des Netzwerk-Clusters inklusive Kommunikationssignalen (SystemSignal).
  2. System-Mapping-Synthese: Instanziierung von SenderReceiverToSignalMapping. Die Toolchain validiert die Instanzreferenz (instanceRef) gegen die SWC-Instanzhierarchie und weist das SystemSignal zu.
  3. ECU-Extract-Generierung: Das Mapping wird in den systemspezifischen ECU-Extrakt (ecuExtractVersion) für das jeweilige Steuergerät gefiltert.
  4. BSW- / RTE-Code-Generierung:
    • RTE-Generator: Generiert APIs (Rte_Write_<p>_<o>, Rte_Read_<p>_<o>) und verknüpft sie mit den COM-Interaktionsschichten (Com_SendSignal, Com_ReceiveSignal).
    • COM-Stack-Konfiguration: Übersetzung von SystemSignal in hardwarenahe ISignal- / I-PDU-Layouts unter Berücksichtigung der Bitlänge (length).

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Relevanz: Verbindliche Metamodell-Vorgabe für System-Beschreibungsdateien (.arxml). Ein primitives Sender-Receiver-Datenelement darf im Rahmen dieses Mappings ausschließlich auf ein SystemSignal mit kompatibler Länge abgebildet werden.
  • Instanz-Referenzen: Der «instanceRef»-Mechanismus ist strikt einzuhalten; eine reine Typ-Referenz auf DataElementPrototype ist unzulässig, da im System mehrere Instanzen derselben SWC mit getrennten Signalpfaden existieren können.
  • Kardinalitätsrestriktion: Ein SystemMapping ist innerhalb von System optional (0..1). Jedes SenderReceiverToSignalMapping referenziert genau ein Signal (1) und genau ein Datenelement (1).
