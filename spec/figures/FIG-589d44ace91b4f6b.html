1. Diagrammtyp & Architektur-Kontext

Strukturiertes Datenfluss- und Prozessdiagramm für die AUTOSAR-Entwicklungsmethodik (Classic Platform). Das Diagramm veranschaulicht den durchgängigen Konfigurations- und Generierungsablauf ausgehend von Systembeschreibungen über die systemspezifische Verteilung bis hin zur steuergerätespezifischen Konfiguration und BSW-/RTE-Generierung. Eine vertikale Trennlinie teilt den Prozess in eine übergreifende Systemebene (links) und eine ECU-lokale Ebene („per ECU“, rechts).

2. Komponenten, Entitäten & Schnittstellen

  • Beschreibungs- und Datenartefakte (orangefarbene Dokumentensymbole, Information / Database, keine isolierten Dateien):
    • Systemebene: SW-Component Description, ECU Resource Description (HW only), System-Constraint Description, System Configuration Description (enthält aggregierte ECU extract of System Configuration).
    • Entkoppeltes Software-Interface: Component API e.g. app.h.
    • ECU-Ebene (ECU Configuration Description): enthält RTE Extract of ECU Config, OS extract of ECU config e.g. OIL, mehrere Basic SW Module A extract of ECU config sowie list of implementations of SW Components.
  • Generatoren und Verarbeitungsstufen (hellblaue Kreise / komplexe Generierungsschritte):
    • AUTOSAR System Configuration Generator (mit Entscheidungseinfluss decisions (e.g. mapping)).
    • Component API Generator.
    • AUTOSAR ECU Configuration Generator (mit Entscheidungseinfluss decisions (e.g. scheduling, ...)).
    • Zielgeneratoren auf Steuergeräteebene: AUTOSAR RTE Generator, Generator for OS, COM, ..., Other Basic SW Generator, MCAL-Generator.
  • Schnittstellen & Verbindungen:
    • Gerichtete Blockpfeile transportieren Beschreibungsdaten zwischen Eingangsartefakten, Generatoren, Zwischenbeschreibungen und BSW-/RTE-Codegeneratoren.
  • Legende & Kennzeichnung:
    • Orangefarbenes Rechteck: Information / Database (no files).
    • Kreis mit Sprechblase (ohne Textbeschriftung).
    • Oben rechts: Anforderungs- bzw. Spezifikationsreferenz AUTOSAR RSVI 1.

3. Dynamisches Verhalten & Sequenzablauf

  1. SW-Component Description wird dem Component API Generator zugeführt, welcher die anwendungsseitige Schnittstelle Component API e.g. app.h erzeugt.
  2. Parallel dazu gehen SW-Component Description, ECU Resource Description (HW only) und System-Constraint Description in den AUTOSAR System Configuration Generator ein.
  3. Unter Berücksichtigung von Entwurfsentscheidungen (decisions (e.g. mapping)) erstellt dieser die System Configuration Description, aus der steuergerätespezifische Extrakte (ECU extract of System Configuration) hervorgehen.
  4. Der ECU extract of System Configuration wird über die Systemgrenze hinweg in den AUTOSAR ECU Configuration Generator eingespeist.
  5. Unter Einbezug steuergerätespezifischer Auslegungen (decisions (e.g. scheduling, ...)) wird die umfassende ECU Configuration Description aufgebaut.
  6. Aus den Teilkonfigurationen der ECU Configuration Description speisen dedizierte Generatoren die Zielartefakte:
    • RTE Extract of ECU Config -> AUTOSAR RTE Generator
    • OS extract of ECU config e.g. OIL -> Generator for OS, COM, ...
    • Basic SW Module A extract of ECU config -> Other Basic SW Generator
    • Weitere Modulextrakte / Implementierungslisten -> MCAL-Generator.

4. Normative Relevanz & Entwickler-Hinweise

Die Abbildung definiert die methodische Phasenaufteilung der AUTOSAR-Konfigurationskette. Entwickler und Tool-Hersteller müssen beachten, dass Konfigurationsbeschreibungen semantisch als Datenbank-/Informationsmodelle und nicht als zwingend proprietäre Einzeldateien konzipiert sind. Die Aufteilung in System Configuration und ECU Configuration erfordert die Extraktion steuergerätespezifischer Teilmengen (ECU extract of System Configuration). Manuelle oder werkzeuggestützte Engineering-Entscheidungen (wie Komponenten-Mapping auf Topologieebene sowie Task-Scheduling auf ECU-Ebene) greifen als formale Eingangsgrößen in die jeweiligen Konfigurationsgeneratoren ein.
