1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-2.0-Klassendiagramm (AUTOSAR System Template, Metamodell-Ebene M2).
  • Technischer Zweck: Definition der Metaklassen für die Konfiguration des UDP Network Managements (UdpNm) im AUTOSAR System Template (AUTOSAR_CP_TPS_SystemTemplate, Release R24-11).
  • Funktionale Einordnung: Das Metamodell bildet die Brücke zwischen der logischen Netzwerktopologie (Cluster, Knoten, ECUs) und der BSW-Konfiguration für Nm (generisches Network Management Interface) und UdpNm (Ethernet/UDP-spezifisches NM-Modul). Es formalisiert Cluster-spezifische Timing-Parameter, Knoteneigenschaften, PDU-Strukturen sowie Netzwerkkoordination und -kopplung für Ethernet-basierte Bordnetze.

2. Komponenten, Entitäten & Schnittstellen

2.1 Top-Level-Konfiguration
  • NmConfig («FibexElement», «UploadableDesignElement»): Wurzel-Container der netzwerkweiten NM-Konfiguration.
    • Komposition +nmCluster 0..* («atpVariation, atpSplitable») → NmCluster
    • Komposition +nmClusterCoupling 0..* («atpVariation, atpSplitable») → NmClusterCoupling
    • Komposition +nmIfEcu 0..* («atpVariation, atpSplitable») → NmEcu
2.2 Cluster-Ebene (Generisch & UDP-spezifisch)
  • NmCluster («Identifiable»): Abstrakte Basis für ein NM-Kommunikationscluster.
    • Attribute: nmChannelSleepMaster: Boolean [0..1], nmLightTimeout: TimeValue [0..1], nmNodeDetectionEnabled: Boolean [0..1], nmNodeIdEnabled: Boolean [0..1], nmPncParticipation: Boolean [0..1], nmRepeatMsgIndEnabled: Boolean [0..1], nmSynchronizingNetwork: Boolean [0..1], pncClusterVectorLength: PositiveInteger [0..1].
    • Assoziation: +communicationCluster 0..1 («atpVariation, atpSplitable») → CommunicationCluster («atpVariation», «FibexElement», «UploadableDesignElement», Attribute: baudrate: PositiveUnlimitedInteger [0..1], protocolName: String [0..1], protocolVersion: String [0..1]).
    • Komposition: +nmNode 0..* → NmNode.
  • UdpNmCluster (Spezialisierung von NmCluster): UDP-/Ethernet-spezifische Cluster-Ausprägung.
    • Attribute:
      • nmCbvPosition: Integer [0..1]
      • nmImmediateNmCycleTime: TimeValue [0..1]
      • nmImmediateNmTransmissions: PositiveInteger [0..1]
      • nmMessageTimeoutTime: TimeValue [0..1]
      • nmMsgCycleTime: TimeValue [0..1]
      • nmNetworkTimeout: TimeValue [0..1]
      • nmNidPosition: Integer [0..1]
      • nmPnHandleMultipleNetworkRequests: Boolean [0..1]
      • nmRemoteSleepIndicationTime: TimeValue [0..1]
      • nmRepeatMessageTime: TimeValue [0..1]
      • nmWaitBusSleepTime: TimeValue [0..1]
    • Assoziation: +vlan 0..1 → EthernetPhysicalChannel («PhysicalChannel»).
2.3 Cluster-Kopplung & Koordination
  • NmClusterCoupling ← UdpNmClusterCoupling (Generalisierung): Ermöglicht das synchrone Wecken/Schlafenlegen gekoppelter Cluster.
    • Attribut: nmImmediateRestartEnabled: Boolean [0..1].
    • Assoziation: +coupledCluster 0..* → UdpNmCluster.
  • NmCoordinator: Gliedert Master-/Gateway-ECUs zur hierarchischen Netzwerksynchronisation.
    • Attribute: index: Integer [0..1], nmCoordSyncSupport: Boolean [0..1], nmGlobalCoordinatorTime: TimeValue [0..1].
2.4 ECU- und Knotenebene
  • NmEcu («Identifiable»): Steuergeräte-Repräsentanz im generischen NM-Kontext.
    • Attribute: nmBusSynchronizationEnabled: Boolean [0..1], nmComControlEnabled: Boolean [0..1], nmCycletimeMainFunction: TimeValue [0..1], nmPduRxIndicationEnabled: Boolean [0..1], nmRemoteSleepIndEnabled: Boolean [0..1], nmStateChangeIndEnabled: Boolean [0..1], nmUserDataEnabled: Boolean [0..1].
    • Komposition: +nmCoordinator 0..1 → NmCoordinator.
    • Komposition: +busDependentNmEcu 0..* → BusspecificNmEcu.
  • BusspecificNmEcu ← UdpNmEcu (Generalisierung): Busspezifische ECU-Ausprägung für UDP-NM.
    • Assoziation: +nmIfEcu 0..1 («atpSplitable») → NmEcu.
  • NmNode («Identifiable»): Logische NM-Knoteninstanz auf einem Cluster.
    • Attribute: nmCoordCluster: PositiveInteger [0..1], nmCoordinatorRole: NmCoordinatorRoleEnum [0..1], nmNodeId: Integer [0..1], nmPassiveModeEnabled: Boolean [0..1], nmVariant: NmVariantEnum [0..1].
    • Assoziation: +nmNode 0..* (gegenseitige Referenz / Rollenverknüpfung) → NmNode.
    • Assoziation: +controller 0..1 → CommunicationController («atpVariation», «Identifiable», Attribut: wakeUpByControllerSupported: Boolean [0..1]).
  • UdpNmNode (Spezialisierung von NmNode): Ethernet-spezifischer NM-Knoten.
    • Attribute: allNmMessagesKeepAwake: Boolean [0..1], nmMsgCycleOffset: TimeValue [0..1].
2.5 PDU- und Signal-Mapping
  • NmPdu (Spezialisierung von Pdu): Definiert Struktur und Inhalt der NM-Botschaft.
    • Attribute: nmDataInformation: Boolean [0..1], nmVoteInformation: Boolean [0..1], unusedBitPattern: Integer [0..1].
    • Assoziationen von NmNode: +txNmPdu 0..* und +rxNmPdu 0..* → NmPdu.
    • Komposition: +iSignalToIPduMapping 0..* → ISignalToIPduMapping («Identifiable»).
  • ISignalToIPduMapping («Identifiable»):
    • Attribute: packingByteOrder: ByteOrderEnum [0..1], startPosition: UnlimitedInteger [0..1], transferProperty: TransferPropertyEnum [0..1], updateIndicationBitPosition: UnlimitedInteger [0..1].

3. Dynamisches Verhalten & Sequenzablauf

Die abgebildeten Attribute steuern unmittelbar die AUTOSAR-UdpNm-Zustandsmaschine:

[Bus Sleep Mode]
       │
       ▼ (Netzwerkanforderung / Wake-up PDU)
[Repeat Message State] <── (nmImmediateRestartEnabled / Bus-Aktivität)
       │  ▲ (nmImmediateNmTransmissions × nmImmediateNmCycleTime, danach nmRepeatMessageTime)
       │  │
       ▼  │ (nmRemoteSleepIndicationTime abgelaufen)
[Normal Operation State] ──> [Ready Sleep State]
       │                            │
       └────────────────────────────┘
                     │ (nmNetworkTimeout abgelaufen, keine NM-PDUs empfangen)
                     ▼
        [Prepare Bus Sleep State]
                     │ (nmWaitBusSleepTime abgelaufen)
                     ▼
              [Bus Sleep Mode]
  • Tx-Ablauf: Im Repeat Message State optionaler Fast-Transmit-Burst (nmImmediateNmTransmissions mit Periode nmImmediateNmCycleTime). Im Normal Operation State zyklischer Versand mit nmMsgCycleTime, phasenverschoben um nmMsgCycleOffset.
  • Rx-Überwachung: Empfangene NM-PDUs setzen den nmNetworkTimeout-Timer zurück (sofern allNmMessagesKeepAwake == TRUE oder PNC-Relevanz vorliegt).
  • Payload-Serialisierung: nmNidPosition und nmCbvPosition legen die feste Positionierung von Node-ID und Control Bit Vector (enthält u. a. RepeatMessageRequestBit, ActiveCoordinatorBit) in der PDU fest; der Rest wird über ISignalToIPduMapping mit PNC-Bits oder User-Data gefüllt.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW-Codegenerierung (Mapping M2 → M1):
    • Parameter aus UdpNmCluster und UdpNmNode fließen direkt in die Konfigurationscontainer UdpNmGlobalConfig, UdpNmChannelConfig und UdpNmNodeConfig (UdpNm_Cfg.h / UdpNm_PBcfg.c).
    • NmEcu-Attribute konfigurieren Callbacks und Features im Nm-Interface (Nm_StateChangeIndication, Nm_PduRxIndication, Nm_RemoteSleepIndication).
  • Ethernet-Stack-Kopplung (SoAd / EthIf):
    • Die Assoziation +vlan 0..1 (EthernetPhysicalChannel) bedingt eine synchrone Konfiguration des Socket Adapters (SoAd). NmPdu muss einer Socket-Verbindung mit UDP-Multicast- oder Broadcast-Zieladresse und dediziertem Port (z. B. Port 23363) zugeordnet werden.
  • Ethernet-Burst-Vermeidung:
    • Auf Multi-Node-Ethernet-Bussen ist nmMsgCycleOffset zwingend für jeden UdpNmNode disjunkt zu konfigurieren, um synchrone Sendepeaks (Microbursts) an Switch-Queues zu verhindern.
  • Clusterweite PDU-Konsistenz:
    • nmNidPosition, nmCbvPosition und pncClusterVectorLength müssen über alle kommunizierenden ECUs eines UdpNmCluster hinweg strikt identisch konfiguriert sein; abweichende Offsets führen zu Fehlinterpretation des Control Bit Vectors (fälschliche Netzwerk-Wachhaltebefehle oder ignorierte Sleep-Votings).
