1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR Methodology Process Flow / Activity Diagram gemäß SPEM 2.0 (Software & Systems Process Engineering Metamodel) bzw. dem AUTOSAR-Methodik-Metamodell. Es modelliert eine zentrale Integrations-Aktivität (Activity) mit referenzierten Rollen (RoleDefinition), Werkzeugen (ToolDefinition) und Arbeitsergebnissen (WorkProduct / Artifact).
  • Technischer Zweck & Einordnung:
  • Verortet in der Phase ECU Integration der AUTOSAR Classic Platform (R4.0.3).
  • Beschreibt die Aggregation und den Übersetzungsschritt (Compile ECU Source Code) aller statischen und generierten C-Quellcodedateien sowie Schnittstellen-Header (BSW, RTE/SchM, SWCs, Bibliotheken, Systemtypen) zu relokatierbaren Objektdateien (ECU Object Code).
  • Bildet das Bindeglied zwischen der Generierungsphase (BSW-/RTE-Generatoren) und der finalen Linker-Phase (Link ECU Executable).

2. Komponenten, Entitäten & Schnittstellen

  • Rolle (RoleDefinition):
  • ECU Integrator [1]: Führt die Aktivität aus («performs»). Steuert Build-Skripte, Compiler-Flags, Translation Units, Makro-Definitionen und Include-Hierarchien.
  • Werkzeug (ToolDefinition):
  • Compiler [0..1]: Eingesetztes Übersetzungswerkzeug («used tool»). Zielarchitektur-spezifischer C-Compiler (z. B. TriCore-, ARM- oder RH850-Toolchain).
  • Arbeitsergebnis / Output (WorkProduct):
  • ECU Object Code [1..*]: Relokatierbare Maschinencode-Dateien (.o / .obj), gebildet durch «output» aus den einzelnen Übersetzungseinheiten.
  • Eingangs-Artefakte (WorkProduct mit Stereotyp «input»):
  • Plattform- & Standard-Header:
  • Standard Header Files [1]: Architekturbasis (Std_Types.h, Platform_Types.h, Compiler.h, Compiler_Cfg.h).
  • Library Header Files [0..*]: Prototypen modularer Hilfsbibliotheken (z. B. CRC, E2E, BFX).
  • Basis-Software (BSW):
  • Basic Software Module Core Source Code [0..*]: Statischer C-Code der BSW-Treiber und Stacks.
  • Basic Software Module Core Header [0..*]: Modulspezifische statische API- und Typ-Deklarationen.
  • BSW Module Configuration Data Source Code [0..*]: Generierte C-Strukturtabellen für Pre-Compile- und Link-Time-Parameter.
  • BSW Module Configuration Header File [0..]: Generierte Pre-Compile-Präprozessormakros (_Cfg.h).
  • Basic Software Module Interlink Header [1..*]: Inter-BSW-Schnittstellen und Scheduler-Anbindung (SchM_<Module>.h).
  • Basic Software Interlink Types Header [0..*]: Modulübergreifende BSW-Datentypdeklarationen.
  • Betriebssystem (OS) & Laufzeitumgebung (RTE):
  • OS Generated Code [1]: Generierter Quellcode des AUTOSAR OS (Task-Deskriptoren, Alarm- und Event-Konfigurationen, Interruptvektortabellen).
  • BSW Scheduler Code [1]: Quellcode des BSW-Schedulers (SchM-Task-Wrapper, Interrupt-Sperren/Critical Sections).
  • BSW RTE Prebuild Configuration Header [0..*] & RTE Prebuild Configuration Header [0..1]: Build- und Timing-Makros für RTE/SchM.
  • RTE Source Code [1]: Generierte C-Dateien der RTE (Rte.c, Daten-Puffer, Event-Handler, Task-Bodys).
  • Component RTE Prebuild Configuration Header [0..*]: SWC-spezifische Pre-Compile-Konfigurationsheader der RTE.
  • Applikationsebene (Software Components):
  • Software Component Data Types Header [0..*]: Typdeklarationen der Application- und Implementation-Data-Types.
  • Application Header File [1..*]: SWC-Deklarationen mit Runnable-Signaturen.
  • Atomic Software Component Implementation Source Code [0..*]: Quellcode der C-Funktionsrümpfe der Software Components.
  • Optimized Application Header File [0..*]: Zusammengefasste bzw. optimierte Header-Varianten zur Reduktion von Include-Tiefen.
  • Build-Management:
  • Build Action Manifest [0..1]: Formale Beschreibung der Build-Instruktionen, Compile-Optionen, Translation Units und Abhängigkeiten.

3. Dynamisches Verhalten & Sequenzablauf

  • Trigger & Vorbedingungen:
  • Alle statischen Quelldateien der BSW und SWCs liegen im Quellcodebaum vor.
  • OS-, RTE-, SchM- und BSW-Generatoren haben ihren Code sowie alle Konfigurations-Header vollständig generiert.
  • Ablaufschritte der Aktivität Compile ECU Source Code:
  1. Der ECU Integrator ruft den Compiler manuell oder skriptgesteuert auf.
  2. Falls vorhanden, werden Parameter, Makrodefinitionen und Translation Units aus dem Build Action Manifest ausgewertet.
  3. Der Präprozessor bindet Standard-, Interlink-, OS-, RTE- und Modul-Header rekursiv in die jeweiligen C-Dateien ein.
  4. Der Compiler übersetzt jede Übersetzungseinheit (einschließlich OS Generated Code) unabhängig in Maschinencode.
  • Nachbedingungen & Ergebnisse:
  • Erzeugung von mindestens einer oder mehreren Objektdateien (ECU Object Code [1..*]).
  • Bereitstellung der Objektdateien als zwingender Eingang für den anschließenden Linker-Schritt (Link ECU Executable).

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Verbindlichkeit:
  • Definiert den methodischen Mindestsatz an Eingangsartefakten, die für einen AUTOSAR-konformen Übersetzungslauf bereitgestellt werden müssen.
  • Schließt den generierten Betriebssystemcode (OS Generated Code) zwingend mit Kardinalität 1 in den Übersetzungsprozess ein.
  • Entwickler- & Integrationshinweise:
  • Die Schnittstellen zwischen generiertem OS-Code, RTE-Code und BSW-Treibern erfordern konsistente Include-Pfade und übereinstimmende Präprozessor-Symbole.
  • Bei Änderungen an der OS-Konfiguration ist OS Generated Code neu zu kompilieren.
