Figure 11: Mapping Description (Mapping) The System Template allows to describe mappings – both of software components to ECUs as well as data elements exchanged between components to frames, communication protocols or directly to data lines. This is done with the mapping elements, which are aggregated in the SystemMapping meta class in the System Template. The following mappings are defined (compare Figure 11): • The mapping of Software Components to ECUs: SwCompToEcuMapping maps one or several software components to ECUs. In the System Constraint Description it is possible to predefine the mapping of software components to ECUs. The predefinition limits the system architect’s freedom to map SW components to arbitrary ECUs. After the system generation in the System Configuration Description, all atomic software components that are directly or indirectly part of the top level composition must be mapped with this mapping rule. Software component mapping is described in detail in chapter 6.1.1. • The DataMapping elements are used to map data elements and operations in SW component ports (i.e. the data exchanges between SW components) to signals. The data mapping is described in detail in chapter 6.2.

1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm der Metamodell-Struktur des AUTOSAR-System-Templates (Classic Platform). Das Diagramm spezifiziert die zentrale Aggregationsstruktur für System-Mappings (SystemMapping) innerhalb des Wurzel-Elements System (ARElement). Es definiert die Verknüpfungspunkte zwischen Software-Komponenten-Architektur, Hardware-Topologie (ECUs), Kommunikationspfaden und Ressourcenabschätzungen auf Systemebene.

2. Komponenten, Entitäten & Schnittstellen

Das Metamodell umfasst folgende Klassen und Assoziationen:

  • SystemTemplate::System (spezialisiert ARElement): Aggregiert über die Komposition +mapping mit Multiplizität 1 genau eine Instanz von SystemTemplate::SystemMapping.
  • SystemTemplate::SystemMapping (Stereotyp «atpIdentifiable», spezialisiert Identifiable): Zentraler Container, der folgende Elemente per Komposition aggregiert:
  • +swMapping [*] zu SwCompToEcuMapping (spezialisiert Identifiable): Bildet Software-Komponenten auf Steuergeräte (ECUs) ab.
  • +resourceEstimation [] zu EcuResourceEstimation: Schätzung von ECU-Ressourcenbedarfen; besitzt eine gerichtete Assoziation +swCompToEcuMapping [] zu SwCompToEcuMapping.
  • +dataMapping [*] zu DataMapping::DataMapping: Abbildung von Datenelementen und Operationen auf Signale bzw. Kommunikationsprotokolle.
  • +mappingConstraint [*] zu MappingConstraint: Abstrakte Basisklasse für Mapping-Restriktionen mit den konkreten Spezialisierungen:
  • ComponentSeparation: Vorgabe zur getrennten Platzierung bestimmter Komponenten auf unterschiedlichen ECUs.
  • ComponentCluster: Vorgabe zur gemeinsamen Platzierung bestimmter Komponenten auf derselben ECU.
  • FreeTextMappingConstraint: Freitextliche Beschreibung systemspezifischer Zuordnungsbedingungen.
  • +signalPathConstraint [*] zu SignalPaths::SignalPathConstraint: Restriktionen bezüglich der Signalpfade und Latenzen über Netzwerktopologien hinweg.

3. Dynamisches Verhalten & Sequenzablauf

Statisches Metamodell ohne dynamische Laufzeitsequenz. Im AUTOSAR-Entwicklungsprozess wird SystemMapping sukzessive befüllt:

  1. Definition von Vorgaben und Randbedingungen (MappingConstraint wie ComponentSeparation, ComponentCluster, FreeTextMappingConstraint sowie SignalPathConstraint) in der System Constraint Description.
  2. Zuordnung von Software-Komponenten zu Ziel-ECUs (SwCompToEcuMapping) unter Berücksichtigung der Ressourcenabschätzungen (EcuResourceEstimation).
  3. Abbildung der ausgetauschten VFB-Signale/Datenelemente auf physische Kommunikationsbeziehungen (DataMapping).
  4. Konsolidierung aller Mappings in der System Configuration Description zur vollständigen Systemkonfiguration vor der Generierung von BSW und RTE.

4. Normative Relevanz & Entwickler-Hinweise

Normative Metamodell-Vorgaben für AUTOSAR-Autoren- und Konfigurationswerkzeuge:

  • Ein System muss exakt ein SystemMapping aggregieren (Multiplizität 1).
  • In der System Configuration Description müssen sämtliche atomaren Software-Komponenten, die direkt oder indirekt Bestandteil der Top-Level-Composition sind, über SwCompToEcuMapping mindestens einem ECU zugeordnet sein.
  • Constraints (MappingConstraint, SignalPathConstraint) schränken die zulässigen Zuordnungen für Systemarchitekten und automatisierte Synthese-Werkzeuge normativ ein und müssen vor der ECU-Extraktion validiert werden.
  • Datenaustausche über Komponentengrenzen hinweg erfordern entsprechende DataMapping-Einträge zur korrekten Signalgenerierung.
