1. Diagrammtyp & Architektur-Kontext

Struktur- und Architekturdiagramm eines fahrzeugweiten Intrusion Detection System (IDS) Kommunikationsnetzwerks über heterogene Bus- und Plattformdomänen. Das Diagramm veranschaulicht den Anwendungsfall UC_0001 („Propagation of Qualified Security Events to the IdsR“) gemäß AUTOSAR IDS Protocol Specification (AUTOSAR PRS IntrusionDetectionSystem). Dargestellt ist die Multi-Hop-Verteilung von Sicherheitsereignissen von dezentralen IdsM-Instanzen auf AUTOSAR-Classic-Plattformen über Gateway-Knoten hin zu einer zentralen IdsR-Instanz auf einer AUTOSAR-Adaptive-Plattform mit Backend-Anbindung via Mobile Data Link.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm gliedert sich in vier Steuergeräte (ECUs) und externe Verbindungen:

  • ECU A (ASR Classic): Beinhaltet eine IdsM-Instanz (Intrusion Detection Security Manager), die über eine I-PDU-Schnittstelle an den PduR (PDU Router) angebunden ist. Der PduR übergibt PDUs an den lokalen CAN Stack.
  • ECU B (ASR Classic): Dient als CAN-zu-CAN-Gateway und IdsM-Host. Beinhaltet eine eigene IdsM-Instanz mit I-PDU-Verbindung zum PduR sowie einen CAN Stack. Der PduR verfügt über eine interne Routing-Funktion (Gateway Routing), die eingehende CAN-PDUs auf einen ausgehenden CAN-Zweig weiterleitet.
  • ECU C (ASR Classic): Dient als Medien-Gateway (CAN zu Ethernet). Beinhaltet eine eigene IdsM-Instanz mit I-PDU-Anbindung an den PduR, einen CAN Stack sowie einen Eth Stack. Der PduR führt Gateway Routing von CAN zu Ethernet durch.
  • ECU D (ASR Adaptive): Zentrales Gateway / Rechenknoten auf AUTOSAR Adaptive Basis. Beinhaltet eine lokale IdsM-Instanz sowie die zentrale IdsR-Instanz (Intrusion Detection Security Reporter). Die lokale IdsM kommuniziert über eine plattforminterne Schnittstelle (gestrichelter Verbindungspfeil) mit dem IdsR. Der IdsR empfängt zudem aggregierten Ethernet-Verkehr von ECU C und verfügt über eine externe Antennenanbindung via Mobile Data Link.
  • Bussysteme: CAN Bus zwischen ECU A und ECU B, CAN Bus zwischen ECU B und ECU C sowie Ethernet zwischen ECU C und ECU D.

3. Dynamisches Verhalten & Sequenzablauf

Der Daten- und Signalfluss beschreibt die aggregierte Weiterleitung qualifizierter Sicherheitsereignisse (QSEv):

  1. Erzeugung: Die IdsM-Instanzen auf ECU A, B und C erzeugen Sicherheitsmeldungen und übergeben diese als I-PDU an den jeweiligen PduR.
  2. Kaskadiertes Routing (Classic):
  • ECU A sendet die I-PDU über den CAN Stack auf den ersten CAN Bus.
  • ECU B empfängt die PDU über den CAN Stack, leitet sie per Gateway Routing im PduR um und speist sie zusammen mit eigenen IdsM-PDUs über den CAN Stack in den nachfolgenden CAN Bus ein.
  • ECU C empfängt die CAN-PDUs, routet sie über das Gateway Routing des PduR in den Eth Stack und überträgt sie über Ethernet an ECU D.
  1. Zusammenführung im IdsR (Adaptive):
  • Der IdsR auf ECU D empfängt die über Ethernet propagierten IDS-Protokoll-Nachrichten aus dem Classic-Netzwerk.
  • Gleichzeitig empfängt der IdsR lokale Events von der auf ECU D platzierten Adaptive-IdsM-Instanz.
  1. Backend-Übertragung: Der IdsR übermittelt gesammelte bzw. aufbereitete Security-Reports über den drahtlosen Mobile Data Link an ein Backend (Vehicle Security Operations Center, VSOC).

4. Normative Relevanz & Entwickler-Hinweise

  • Protokollunabhängigkeit & Multi-Hop: Das IDS-Protokoll muss so ausgelegt sein, dass Qualified Security Events (QSEv) transparent über mehrere Zwischenstationen (Multi-Hop via PduR-Gateway-Routing) und heterogene Übertragungsmedien (CAN, Ethernet) ohne Verlust semantischer Integrität transportiert werden können.
  • Classic-Integration: In AUTOSAR Classic erfolgt die Übergabe zwischen IdsM und Kommunikationsstack streng über I-PDUs auf PduR-Ebene. Entwickler müssen das PDU-Routing im PduR für IdsM-spezifische PDU-IDs konsistent über alle Gateways hinweg konfigurieren.
  • Adaptive-Integration: Auf AUTOSAR Adaptive fungiert der IdsR typischerweise als Service oder Applikation, der Meldungen sowohl fahrzeugintern (über ara::com / SOME/IP oder IPC) von lokalen Adaptive-IdsM-Instanzen als auch via Ethernet-Stack von vernetzten Classic-ECUs empfangen und standardisiert an Cloud-Schnittstellen ausleiten kann.

ID Name Description 0001 Transmission of QSEv Transmission of qualified security events from IdsM instances to IdsR instance Table 2.1: Usecases for IDS protocols 2.1 UC_0001 "Propagation of Qualified Security Events to the IdsR" The main use case for the IDS protocol is the propagation of Qualified Security Events QSEv to the IdsR in a way that is independent from the kind of ECU or the used communication mechanism. IdsM instances can be allocated to all nodes of the vehicle architecture that are security relevant. This decision is typically based on a security analysis of the vehicle E/E architecture.
