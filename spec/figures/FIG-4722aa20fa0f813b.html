1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Konzeptionelles Architektur- und Interaktionsdiagramm (VFB- und BSW-Schichtenmodell).
  • Technischer Zweck: Darstellung des Kontroll- und Wirkungsgefüges zwischen Anwendungs-Software-Komponenten (SW-Cs) und den BSW-Diensten Diagnostic Event Manager (DEM) sowie Function Inhibition Manager (FiM).
  • Architektonische Einordnung: Veranschaulicht das AUTOSAR-Standardmuster zur funktionalen Degradierung: Ein von einer Sensor-SWC erkanntes und an das DEM gemeldetes Diagnoseereignis führt über konfigurierte FiM-Inhibition-Regeln zur automatischen Hemmung (Inhibition) abhängiger Funktionalitäten in einer Aktuator-SWC.

2. Komponenten, Entitäten & Schnittstellen

  • Front-left Anti-pinch Sensor SW-C (Application SW-C / Sensor):
    • Erkennt hardwarenah Fehlfunktionen des Einklemmschutzes (Einklemmsensorik am Fensterheber vorne links).
    • Besitzt einen R-Port zur Bereitstellung der Sensordaten an die Fensterheber-Steuerung.
    • Besitzt einen Service-Port (R-Port via RTE) zur Service-Schnittstelle DiagnosticMonitor des DEM zur Fehlermeldung unter Zuordnung von EventId: anti_pinch.
  • Front-left Window-lifter SW-C (Application SW-C / Aktuator):
    • Implementiert die Komfort- und Steuerungslogik des Fensterhebers (u. a. automatischer Schließlauf / Express Close).
    • Besitzt P-Ports und R-Ports zur Anwendungs- und Sensorkommunikation (z. B. Eingang des Sensorsignals).
    • Besitzt einen Service-Port (R-Port via RTE) zur Service-Schnittstelle FunctionInhibition des FiM zur Prüfung der Freigabeberechtigung (FunctionId: Automatic_window_closing_allowed).
  • DEM (Diagnostic Event Manager, BSW Service Layer):
    • Verwaltet den Lebenszyklus und Status der Diagnose-Events (Dem_EventIdType).
    • Aggregiert und persistiert das Event anti_pinch (DTC- und UDS-Event-Statusbyte).
  • FiM (Function Inhibition Manager, BSW Service Layer):
    • Verwaltet Funktionsbezeichner (FiM_FunctionIdType / FIDs) und berechnet deren Freigabestatus (Permission).
    • Wertet die funktionale Abhängigkeit anhand der internen Inhibition-Konfigurationstabelle aus.
  • Inhibition-Zuordnungstabelle (FiMInhibitionConfiguration):
    • Konfigurierte Entitätsbeziehung:
      • FunctionId: Automatic_window_closing_allowed
      • EventId: anti_pinch (referenziert über FiMInhEventRef auf DemEventParameter)
      • Mask: Last_Failed (spezifiziert über FiMInhInhibitionMask, entspricht UDS-Statusbit 0: testFailed)

3. Dynamisches Verhalten & Sequenzablauf

  1. Fehlererfassung & -meldung (Sensor-SWC → DEM):
    • Die Sensor-SWC detektiert einen Defekt der Einklemmerkennung und ruft synchron am RTE-Port SetEventStatus(DEM_EVENT_STATUS_FAILED) auf.
    • Das DEM empfängt das Event anti_pinch und setzt im UDS-Statusbyte das Bit testFailed (Bit 0).
  2. Statusweiterleitung (DEM → FiM):
    • Ereignisgesteuert (Event-driven, FiMEventUpdateTriggered == TRUE): Das DEM triggert das FiM über FiM_DemTriggerOnEventStatus(EventId, EventStatusOld, EventStatusNew).
    • Polling-basiert (FiMEventUpdateTriggered == FALSE): Das FiM fragt den Status zyklisch im Rahmen von FiM_MainFunction() über Dem_GetEventStatus() ab.
  3. Inhibition-Berechnung (FiM intern):
    • Das FiM gleicht das Statusbyte des Events anti_pinch gegen die Maske Last_Failed ab.
    • Da Bit 0 (testFailed) gesetzt ist, wird der Inhibition-Status aktiv gesetzt; die Berechtigung für Automatic_window_closing_allowed wechselt auf FALSE.
  4. Berechtigungsabfrage (Window-lifter SW-C → FiM):
    • Vor Ausführung eines automatischen Schließvorgangs fragt die Fensterheber-SWC über ihren Port die Operation GetFunctionPermission(FID, &Permission) ab.
    • Das FiM liefert Permission = FALSE.
    • Die SWC unterdrückt den automatischen Schließlauf (Degradierung auf rein manuellen Tastbetrieb mit Notstopp).

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationsanforderungen (SWS_Fim_00016, SWS_Fim_00020):
    • Im BSW-Konfigurator muss ein FiMConfigSet mit einem FiMFID (Automatic_window_closing_allowed) definiert werden.
    • Dem FID wird ein FiMInhibitionConfiguration-Container zugewiesen:
      • FiMInhEventRef: Referenz auf das konfigurierte DemEventParameter (anti_pinch).
      • FiMInhInhibitionMask: Enumerator FIM_LAST_FAILED (alternativ stehen u. a. FIM_TESTED_AND_FAILED oder FIM_NOT_TESTED zur Verfügung).
  • RTE- und SWC-Design (SRS_Fim_04706, SRS_Fim_04713):
    • Die Anwendungs-SWC benötigt im Software Component Description File (.arxml) einen Service-Need für den FiM: R-Port typisiert mit dem Client-Server-Interface FunctionInhibition (Operation GetFunctionPermission).
    • Die Sensor-SWC benötigt einen R-Port mit Interface DiagnosticMonitor (Operation SetEventStatus).
  • Laufzeit- und Sicherheitsimplikationen:
    • Latenz: Bei ASIL-relevanten Sicherheitsfunktionen (wie Einklemmschutz nach ISO 26262) muss die Verarbeitungszeit zwischen Fehlererkennung und Inhibition minimal sein. Hierfür ist im BSW zwingend der ereignisgesteuerte Modus (FiMEventUpdateTriggered = TRUE) zu wählen, um Jitter durch zyklische Tasks zu eliminieren.
    • Programmiervertrag: Applikations-Entwickler dürfen sicherheitskritische Aktionen niemals unkonditioniert ausführen. Der Aufruf von GetFunctionPermission() ist zwingend als Pre-Condition vor jede Funktionsinitiierung zu kapseln.
