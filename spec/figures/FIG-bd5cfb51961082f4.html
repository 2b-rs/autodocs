1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Strukturdiagramm der AUTOSAR-Methodik auf Basis des SPEM-2.0-Profils (Software & Systems Process Engineering Metamodel) in Form eines UML-Klassendiagramms für Artefakt- und Deliverable-Rollen.
  • Technischer Zweck: Spezifikation der strukturellen Beziehungen, Spezialisierungen («extends») und Aggregationen («SPEM_Aggregation») zwischen System- und Software-Deliverables. Das Diagramm definiert, wie sich Gesamtsystembeschreibungen (System Description) über Zwischenstufen (System Extract) bis hin zum steuergerätespezifischen Extrakt (ECU Extract) und den zugehörigen VFB- und Flat-Map-Sichten ableiten.

2. Komponenten, Entitäten & Schnittstellen

#### Entitäten im Namensraum System (Systemebene)

  • System Description: Zentrales Basis-Deliverable (Work Product Definition). Dient als generische Vorlage/Rolle für Systemkonfigurations- und Extraktartefakte.
  • System Constraint Description: Spezialisiert System Description via «extends». Enthält Randbedingungen, Anforderungen und Vorab-Restriktionen vor der vollständigen Systemtopologie- und Kommunikationsauslegung.
  • System Configuration Description: Spezialisiert System Description via «extends». Repräsentiert die vollständige Systemkonfiguration (inkl. Software-zu-ECU-Mapping, Netzwerktopologie und Kommunikationsmatrix).
  • System Extract: Spezialisiert System Description via «extends». Schnittmenge der System Description, bezogen auf ein Subsystem oder eine Teilmenge vernetzter Steuergeräte.
  • ECU Extract: Eigenständiges System-Deliverable (keine direkte «extends»-Vererbung von System Description), das exakt die auf ein einzelnes Steuergerät bezogene Projektion der Systemkonfiguration kapselt.

#### Entitäten im Namensraum Software (Software- & VFB-Ebene)

  • Overall VFB System: Vollständige hierarchische Komposition aller Software-Komponenten (SWCs) und deren Konnektoren auf Virtual-Functional-Bus-Ebene vor oder während des Mappings.
  • VFB System Extract: VFB-Teilmenge, die mit den im System Extract enthaltenen Subsystem-SWCs korrespondiert.
  • ECU Extract of VFB System: VFB-Sicht ausschließlich auf die dem Ziel-ECU zugewiesenen Atomic-SWC-Instanzen und deren lokale bzw. inter-ECU-Ports.
  • System Flat Map (Dokument-Artefakt): Eindeutige, abgeflachte Adressierungsstruktur (FlatInstanceDescriptor) über die gesamte Systemhierarchie zur Namensauflösung und Adressierung tiefer Instanzpfade.
  • ECU Flat Map (Dokument-Artefakt): Steuergerätespezifische Abflachung der Komponenteninstanzen zur eindeutigen Zuordnung auf RTE-, BSW- und Kalibrierebene.

#### Beziehungen und Kardinalitäten

  • Vererbung («extends»):
  • System Constraint Description $\rightarrow$ System Description
  • System Configuration Description $\rightarrow$ System Description
  • System Extract $\rightarrow$ System Description
  • Aggregationen («SPEM_Aggregation»):
  • System Constraint Description aggregiert:
  • Overall VFB System (Kardinalität 0..1)
  • System Flat Map (Kardinalität 0..1)
  • System Configuration Description aggregiert:
  • Overall VFB System (Kardinalität 1)
  • System Flat Map (Kardinalität 0..1)
  • System Extract aggregiert:
  • VFB System Extract (Kardinalität 1)
  • System Flat Map (Kardinalität 0..1)
  • ECU Extract aggregiert:
  • ECU Extract of VFB System (Kardinalität 1)
  • ECU Flat Map (Kardinalität 1 – obligatorisch für ECU-Generierung)

3. Dynamisches Verhalten & Phasenabfolge (Methodik-Workflow)

Das Diagramm ist ein statisches Strukturmodell; der implizite Generierungs- und Verfeinerungspfad im AUTOSAR-Workflow verläuft wie folgt:

  1. System Definition: Definition des Overall VFB System und Spezifikation von Randbedingungen in der System Constraint Description.
  2. System Mapping & Synthesis: Integration zur System Configuration Description (verpflichtend mit Overall VFB System: 1 und optionaler System Flat Map).
  3. Subsystem-Extraktion: Generierung des System Extract (enthält Sub-Topologie, Bus-Cluster und VFB System Extract: 1).
  4. ECU-Extraktion: Transformation in den ECU Extract mittels automatisierter Werkzeugfilterung; obligatorische Erzeugung der ECU Flat Map: 1 und des ECU Extract of VFB System: 1.

4. Normative Relevanz & Entwickler-Hinweise

  • Primärer Input für ECU-Entwicklung: Der ECU Extract (ARXML) ist die formale Übergabeschnittstelle vom OEM/Systemintegrator an den Tier-1-Zulieferer bzw. Steuergeräte-Entwickler. Er bildet die autoritative Eingabe für:
  • Den BSW-Konfigurator (Erzeugung der initialen EcucDescriptionValueCollection für Com, PduR, Can/Lin/FlexRay/Ethernet-Treiber stacks).
  • Den RTE-Generator (Erzeugung von Rte.c, Rte.h, Port-API und Task-Bodies).
  • Bedeutung der ECU Flat Map (1 obligatorisch):
  • Namensraum-Kanonisierung: Da SWCs in AUTOSAR mehrfach instanziiert werden können (SwComponentPrototype innerhalb hierarchischer CompositionSwComponentType), weist die ECU Flat Map jedem tief verschachtelten Daten- und Port-Element einen global eindeutigen, flachen Kurznamen zu.
  • A2L- & MCD-Generierung: Mess- und Kalibrierwerkzeuge (ASAM MCD-2 MC / A2L) sowie Kalibrieralgorithmen im RTE/BSW-Stack referenzieren Datenobjekte zwingend über die Einträge der ECU Flat Map. Fehlt diese oder ist sie inkonsistent, schlägt die A2L-Generierung fehl.
  • Unterschied System Extract vs. ECU Extract: Ein System Extract ist syntaktisch noch eine vollwertige System Description (daher «extends») für ein Cluster/Gateway-Subsystem. Ein ECU Extract ist semantisch auf eine konkrete ECU-Instanz beschnitten; BSW-Generatoren dürfen keine Artefakte außerhalb des definierten ECU-Kontexts erwarten.
