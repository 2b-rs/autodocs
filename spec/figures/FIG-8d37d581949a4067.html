1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU Configuration (ECUC) Parameter-Metamodell / UML-Klassendiagramm (strukturelle Konfigurationsdefinition gemäß AUTOSAR BSW Module Description Template).
  • Architektur-Kontext: BSW-Kommunikationsschicht (Communication Services), Modul CanTSyn (Time Synchronization over CAN), AUTOSAR Release R21-11.
  • Technischer Zweck: Definition der statischen Konfigurationshierarchie für die DataIDList zur Sicherung von Offset-Nachrichten (OFS / Offset Time Synchronization Messages). Die Liste stellt 16 deterministische Data-ID-Werte bereit, die im Rahmen der CRC-Berechnung und Botschaftsauthentifizierung (Replay- und Masquerading-Schutz auf CAN) zyklusabhängig verwendet werden.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein rein statisches ECUC-Metamodell handelt, existiert im Diagramm kein direkter Kontrollfluss. Das resultierende Laufzeitverhalten im BSW-Stack gestaltet sich wie folgt:

  1. Sender-Pfad (CanTSyn_MainFunction / TX-PDU):
  • CanTSyn ermittelt den aktuellen Sequenzzähler SC ($0 \dots 15$) der zu versendenden OFS-PDU.
  • SC dient als Lookup-Schlüssel in das vorliegende Array: DataID = CanTSynGlobalTimeOfsDataIDListValue[SC].
  • Die CRC-Berechnung über die OFS-Payload wird unter Berücksichtigung dieser DataID durchgeführt (gemäß SWS-Anforderung zur DataID-Inklusion).
  • Die PDU wird inkl. CRC und Sequenzzähler an das CanIf übergeben.
  1. Empfänger-Pfad (CanTSyn_RxIndication):
  • Extraktion des SC ($0 \dots 15$) aus dem empfangenen OFS-Frame.
  • Selektion der erwarteten DataID aus der identisch konfigurierten DataIDList.
  • Verifikation der CRC. Bei Nichtübereinstimmung: Verwerfen der PDU und optionales Triggern von Fehlermeldungen (z. B. DET-Meldung CANTSYN_E_CRC bzw. Security-Event).

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Referenz: [ECUC_CanTSyn_00026] (CanTSynGlobalTimeOfsDataIDList) sowie korrelierende Anforderungen für CRC-Handling in AUTOSAR_SWS_TimeSyncOverCAN.
  • Konfigurationsklasse & Variantenbildung:
  • Die Multiplizität des Containers ist zur Vorkompilierzeit (Pre-compile time) für alle Varianten festgelegt (Post-Build Variant Multiplicity = true).
  • Strikte Konfigurationsvalidierung:
  • Der BSW-Konfigurator (z. B. DaVinci Configurator, EB tresos) muss das Vorhandensein von exakt 16 Elementen (upperMultiplicity = 16, lowerMultiplicity = 16) und eine lückenlose, disjunkte Indizierung von $0$ bis $15$ erzwingen.
  • Das Fehlen einzelner Indizes oder eine Mehrfachvergabe führt zu ungültigen ARXML-Dateien bzw. Pre-Compile-Validierungsfehlern.
  • Code-Generierung (CanTSyn_Cfg.h / CanTSyn_PBcfg.c):
  • Wird üblicherweise generiert als planares Array:

```c

static const uint8 CanTSyn_OfsDataIdList[16] = { / 16 konfigurierte Werte / };

```

  • Lookup erfolgt ohne Branching direkt über Array-Index: DataId = CanTSyn_OfsDataIdList[sc & 0x0Fu];.
  • Domänen- und Netzwerk-Konsistenz:
  • Sender (Master) und alle Empfänger (Slaves) innerhalb derselben Zeitdomäne müssen zwingend dieselbe Zuordnung von Index $\rightarrow$ Value konfigurieren, andernfalls schlägt jede CRC-Prüfung bei der Offset-Synchronisation fehl.
