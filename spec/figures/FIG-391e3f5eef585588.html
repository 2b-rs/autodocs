1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Illustration des Publish/Subscribe-Mechanismus im AUTOSAR SOME/IP Service Discovery (SOME/IP-SD) Protokoll. Das Diagramm spezifiziert die Verwendung von Endpoint-Optionen (IPv4/IPv6-Endpunkte für UDP und TCP) sowie die Port-Zuordnungen über den Protokollstapel hinweg bei Service-Bekanntmachung, Verbindungsaufbau, Eventgroup-Abonnement und nachfolgender Datenkommunikation.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm gliedert sich in zwei Hauptentitäten (Knoten/Hosts) mit jeweils drei Schichten auf ihren vertikalen Lebenslinien:

  • Server:
    • SOME/IP-SD: Service-Discovery-Modul des Servers zur Signalisierung von Service-Angeboten und Verwalten von Abonnements.
    • SOME/IP: SOME/IP-Kommunikationsschicht/Laufzeitumgebung des Servers für Event-Publishing und Methodenverarbeitung.
    • TCP/IP: Transportschicht des Servers.
  • Client:
    • TCP/IP: Transportschicht des Clients.
    • SOME/IP: SOME/IP-Kommunikationsschicht des Clients für Empfang von Events und Absetzen von Requests.
    • SOME/IP-SD: Service-Discovery-Modul des Clients zur Entgegennahme von Offer-Nachrichten und Initiierung von Subscriptions.

Schnittstellen und Bezeichner der Endpunkte / Ports:

  • SU: Server UDP Endpoint (Port)
  • ST: Server TCP Endpoint (Port)
  • CU: Client UDP Endpoint (Port)
  • CT: Dynamischer Client TCP Endpoint (Port)
  • MU: Multicast UDP Endpoint (IP/Port)
  • Port 30490: Standardisierter SOME/IP-SD Port (UDP unicast/multicast)
  • Port 304901(): Tippfehler/Notation im Diagramm für den SD-Rückkanal bzw. SD-Portbereich

3. Dynamisches Verhalten & Sequenzablauf

Die Interaktionssequenz läuft chronologisch von oben nach unten ab:

  1. Service Announcement: SOME/IP-SD des Servers sendet OfferService(Endpoint UDP: SU, Endpoint TCP: ST) [30490-->30490] an das SOME/IP-SD des Clients.
  2. TCP Connection Establishment: Falls zuverlässige Events (reliable events) existieren, initiiert der Client vor der Subscription einen TCP-Dreiwege-Handshake auf Transportebene:
    • Client TCP/IP -> Server TCP/IP: TCP.SYN() [CT-->ST]
    • Server TCP/IP -> Client TCP/IP: TCP.SYN/ACK() [ST-->CT]
    • Client TCP/IP -> Server TCP/IP: TCP.ACK() [CT-->ST]
  3. Subscription Phase:
    • Client SOME/IP-SD sendet SubscribeEventgroup(Endpoint UDP: CU, Endpoint TCP: CT) [30490-->30490] an Server SOME/IP-SD.
    • Server SOME/IP-SD antwortet mit SubscribeEventgroupAck(Multicast UDP: MU) [30490-->304901()] an Client SOME/IP-SD.
  4. Data Communication Phase:
    • Initial Events: Server SOME/IP sendet UDP Initial Events [SU-->CU] und TCP Initial Events [ST-->CT] an Client SOME/IP.
    • Method Call: Client SOME/IP sendet Request [CU-->SU] an Server SOME/IP; Server antwortet mit Response [SU-->CU] (gestrichelte Linie).
    • Cyclic / Triggered Events: Server SOME/IP sendet UDP Event [SU-->CU], TCP Event [ST-->CT] sowie Multicast Event [SU-->MU] an Client SOME/IP.

4. Normative Relevanz & Entwickler-Hinweise

Normative Vorgaben und Implementierungshinweise:

  • Verbindungsaufbau vor Subscription: Wenn eine zu abonnierende Eventgroup reliable Events über TCP bereitstellt, muss die TCP-Verbindung ([CT-->ST]) vor dem Versenden der SubscribeEventgroup-Nachricht vollständig aufgebaut sein.
  • Endpoint Options in SD-Nachrichten:
    • OfferService deklariert die Server-Ports für UDP (SU) und TCP (ST) über entsprechende IPv4/IPv6-Endpoint-Optionen.
    • SubscribeEventgroup enthält die Rückkanal-Endpunkte des Clients (CU, CT), damit der Server Unicast-Events zielgerichtet an den Client zustellen kann.
    • SubscribeEventgroupAck spezifiziert bei Multicast-Eventgroups die Multicast-Adresse und den Port (MU).
  • Portnutzung: SOME/IP-SD nutzt für Signalisierungsnachrichten Port 30490. Die eigentliche Nutzdatenkommunikation (SOME/IP) erfolgt strikt entkoppelt über die in den Endpoint-Optionen ausgehandelten Ports (SU, ST, CU, CT, MU).
  • Initial Events: Unmittelbar nach Bestätigung des Abonnements (SubscribeEventgroupAck) muss der Server initial definierte Werte für die Events der Eventgroup über Unicast bereitstellen.
