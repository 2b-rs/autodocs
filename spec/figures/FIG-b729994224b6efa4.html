1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm mit Interaktionsrahmen (loop, alt), Zustandsinvariante-Symbolen (GOSLEEP, SLEEP, WAKEUP I) und Notizen.

Architekturkontext ist die AUTOSAR Classic Platform (BSW), Modul ECU State Manager Fixed (AUTOSAR_SWS_ECUStateManagerFixed).

Dargestellt ist der Ablauf zur Erkennung von Wakeup-Ereignissen über Polling für LIN-Controller bzw. LIN-Transceiver während eines Energiesparmodus mit reduzierter Prozessortaktung (Mcu_SetMode). Beteiligt sind System- und Kommunikationsstapel (EcuM, OS, MCU, LinIf, Lin, LinTrcv) sowie anwenderspezifischer Integration Code.

Teilnehmer (Lebenslinien):

  • «module» Os: AUTOSAR OS (aktives BSW-Modul); Schnittstellen: GetResource(uint8), ReleaseResource(uint8).
  • «module» EcuM: ECU State Manager Fixed; Schnittstellen / Callbacks: EcuM_SetWakeupEvent(EcuM_WakeupSourceType).
  • Integration Code: Anwenderspezifische Callouts; Schnittstellen: EcuM_EnableWakeupSources(EcuM_WakeupSourceType), EcuM_CheckWakeup(EcuM_WakeupSourceType), EcuM_DisableWakeupSources(EcuM_WakeupSourceType).

  • «module» LinIf: LIN Interface; Schnittstelle: LinIf_CheckWakeup(EcuM_WakeupSourceType).

3. Dynamisches Verhalten & Sequenzablauf

  1. Sleep-Vorbereitung (GOSLEEP):
  • EcuM ruft im Integration Code EcuM_EnableWakeupSources(EcuM_WakeupSourceType) auf. (Hinweis: LinSM hat beim Wechsel nach NO_COM bereits LinIf_GotoSleep() aufgerufen; der LIN-Controller ist im Sleep je nach Konfiguration wakeable; im Callout ist nichts auszuführen).
  • EcuM ruft GetResource(uint8) am OS auf, um die Scheduler-Ressource zu sperren und die Ausführung anderer Tasks zu verhindern.
  1. Eintritt in Sleep (SLEEP):
  • EcuM ruft Mcu_SetMode(Mcu_ModeType) auf, um den Mikrocontroller in einen Energiesparmodus mit reduzierter Taktfrequenz zu versetzen; Software läuft weiter.
  1. Polling-Schleife (loop WHILE no pendings wakeup events):
  • EcuM ruft zyklisch EcuM_CheckWakeup(EcuM_WakeupSourceType) im Integration Code auf.
  • Integration Code leitet die Abfrage via LinIf_CheckWakeup(EcuM_WakeupSourceType) an das LIN Interface weiter.
  • Verzweigung (alt WakeupSource parameter of LinIf_CheckWakeup()):
  • Fall 1 (LIN Controller): LinIf ruft am LIN-Treiber Lin_CheckWakeup(uint8) auf. Bei erkanntem Aufweckimpuls setzt der Treiber via EcuM_SetWakeupEvent(EcuM_WakeupSourceType) das Event direkt im EcuM.
  • Fall 2 (LIN Transceiver): LinIf ruft am Transceiver-Treiber LinTrcv_CheckWakeup(uint8) auf. Bei erkanntem Wakeup meldet der Treiber via EcuM_SetWakeupEvent(EcuM_WakeupSourceType) das Event direkt an den EcuM.
  • Rückkehr der Aufrufe über LinIf und Integration Code an den EcuM.
  1. Aufwachsequenz (WAKEUP I):
  • Nach Vorliegen eines anstehenden Wakeup-Events verlässt EcuM die Polling-Schleife und wechselt in den Zustand WAKEUP I.
  • EcuM ruft Mcu_SetMode(Mcu_ModeType) auf, um die normale Taktung wiederherzustellen.
  • EcuM ruft im Integration Code EcuM_DisableWakeupSources(EcuM_WakeupSourceType) auf.
  • EcuM gibt mit ReleaseResource(uint8) die Scheduler-Ressource an das OS zurück, wodurch andere Tasks wieder geplant werden können.

4. Normative Relevanz & Entwickler-Hinweise

  • Polling-Kaskade: EcuM pollt Hardwarequellen nicht direkt, sondern delegiert über den Callout EcuM_CheckWakeup() an LinIf_CheckWakeup(), welches anhand der Wakeup-Quelle an den LIN- oder Transceiver-Treiber dispatcht.
  • Asynchrone Benachrichtigung: Der Treiber signalisiert ein erkanntes Aufwachen nicht per Rückgabewert der CheckWakeup-Funktion, sondern meldet das Ereignis unmittelbar über den Callback EcuM_SetWakeupEvent() an den EcuM.
  • Task-Isolation: Die Anforderung der Scheduler-Ressource (GetResource / ReleaseResource) stellt sicher, dass während der Polling-Schleife bei verringerter Taktfrequenz keine regulären BSW- oder Anwendungs-Tasks interferieren.
  • Passive Lebenslinien: Icu und Lin Transceiver Hardware sind architektonisch modelliert, nehmen an diesem rein controller-/transceiver-internen Polling-Szenario jedoch nicht aktiv am Nachrichtenaustausch teil (sie dienen der Konsistenz zu Interrupt-basierten Wakeup-Szenarien).
