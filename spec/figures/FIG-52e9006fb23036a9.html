1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Aktivitätsdiagramm (Activity Diagram) zur Spezifikation synchroner Kontrollflüsse mit Entscheidungsknoten (Decision Nodes), Kanten mit Bedingungen (Guards) und Aktivitätsendknoten (Activity Final Nodes).
  • Architektur-Kontext: AUTOSAR Foundation / Classic & Adaptive Platform, Spezifikation des End-to-End-Kommunikationsschutzes (AUTOSAR_FO_PRS_E2EProtocol). Konkretisiert den Teilschritt „Verify inputs of the forward function“ innerhalb des Gateway-/Forwarding-Ablaufs von E2E Profile 11 (E2E_P11Forward()).
  • Funktionaler Zweck: Deterministische, ISO-26262-konforme Vorabprüfung aller Eingabeparameter (Defensive Programming / ASIL-D-Robustheit) vor Modifikation von Nutzdaten-Puffer (Data) und internem Übertragungsstatus (State).

2. Komponenten, Entitäten & Schnittstellen

  • Akteur / Funktion:
    • E2E_P11Forward(): E2E-Bibliotheksfunktion zur Weiterleitung geschützter Daten (z. B. Gatewaying / Signal-Routing mit Re-Protection).
  • Eingabeparameter & Datenstrukturen:
    • Config (const E2E_P11ConfigType*): Zeiger auf konstante Profilkonfiguration; referenziertes Element: Config->DataLength (Länge der E2E-PDU in Bits).
    • State (E2E_P11ProtectStateType*): Zeiger auf veränderlichen Zustand des Forwarders (Zählerstände etc.).
    • Data (uint8*): Zeiger auf das zu serialisierende/schützende PDU-Byte-Array.
    • ForwardStatus (E2E_PCheckStatusType* bzw. Wert): Status der vorangegangenen E2E-Prüfung der Quell-PDU.
    • Length (uint16 / uint32): Übergebene PDU-Länge in Bytes.
  • Ergebniszustände (Aktivitätsendknoten):
    • no input: NULL-Pointer-Verletzung → resultiert im API-Rückgabewert E2E_E_INPUTERR_NULL (0x13).
    • wrong input: Längeninkonsistenz oder ungültiger Status → resultiert im API-Rückgabewert E2E_E_INPUTERR_WRONG (0x17).
    • input ok: Parameter valide → Freigabe für nachfolgende Transformationsschritte (Write Counter, Write DataIDNibble, Compute CRC, etc.).

3. Dynamisches Verhalten & Sequenzablauf

Der Ablauf erfolgt synchron, blockierungsfrei und reentrant in zwei sequenziellen Prüfebenen:

[Initial Node]
       │
       ▼
   <Decision 1: NULL-Pointer-Check>
   (Config != NULL) && (State != NULL) && (Data != NULL) && (ForwardStatus != NULL)
       │
       ├─ [FALSE] ───────────────► (no input)     ──► return E2E_E_INPUTERR_NULL
       │
       └─ [TRUE]
            │
            ▼
        <Decision 2: Konsistenz- & Längen-Check>
        Length == (Config->DataLength / 8) && (ForwardStatus != E2E_P_NONEWDATA)
            │
            ├─ [FALSE] ──────────► (wrong input)  ──► return E2E_E_INPUTERR_WRONG
            │
            └─ [TRUE] ───────────► (input ok)     ──► Übergang zu E2E-Schutzberechnung
  1. Stufe 1 (Speicherzeiger-Prüfung):
    • Auswertung: (Config != NULL) && (State != NULL) && (Data != NULL) && (ForwardStatus != NULL).
    • Bei mindestens einem NULL-Zeiger ([FALSE]): Sofortiger Abbruch nach no input.
  2. Stufe 2 (Wertebereichs- und Status-Prüfung):
    • Bedingung 1: Length == Config->DataLength / 8 (Validierung, dass die übergebene Bytelänge exakt der konfigurierten Bitlänge dividiert durch 8 entspricht).
    • Bedingung 2: ForwardStatus != E2E_P_NONEWDATA (Es dürfen keine Daten weitergeleitet werden, wenn keine neuen Daten anliegen).
    • Verfehlung eines Kriteriums ([FALSE]): Abbruch nach wrong input.
    • Erfüllung beider Kriterien ([TRUE]): Verzweigung nach input ok.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Bindung: Spezifiziert unter [PRS_E2E_00631] zur Erfüllung von [RS_E2E_08539]. Die Verzweigungslogik ist für E2E-Stack-Implementierer zwingend normativ einzuhalten.
  • Fail-Fast ohne Seiteneffekte: Tritt no input oder wrong input auf, dürfen weder State modifiziert (kein Counter-Inkrement nach [PRS_E2E_00515]) noch Data beschrieben werden (kein CRC-Write nach [PRS_E2E_00514]).
  • Integrations- & Gateway-Verhalten:
    • Der Aufrufer (z. B. PduR, Com oder ein Gateway-SWC) muss sicherstellen, dass ForwardStatus explizit aus dem vorangegangenen E2E_P11Check() bzw. State-Machine-Ergebnis übergeben wird.
    • Wenn ForwardStatus == E2E_P_NONEWDATA, muss der Aufrufer den Weiterleitungszyklus unterdrücken, andernfalls bricht E2E_P11Forward() strikt mit E2E_E_INPUTERR_WRONG ab.
  • Byte-/Bit-Konvertierung: Entwickler müssen beachten, dass Config->DataLength in Bits hinterlegt ist. Bei variablen oder nicht durch 8 teilbaren Längen greift die Ganzzahlarithmetik bzw. Profil-11-Restriktion (feste PDU-Länge).
