1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: PDU- / Paket-Bit-Layout (Wire-Format-Diagramm auf 32-Bit-Wortgrenzen).
  • Architektur-Kontext: Standard-Wire-Format für das SOME/IP-Service-Discovery-Protokoll gemäß AUTOSAR_FO_PRS_SOMEIPServiceDiscoveryProtocol (PRS_SOMEIPSD_00252, RS_SOMEIPSD_00001).
  • Funktionale Einordnung:
    • Classic Platform: Interaktion im Kommunikations-Stack oberhalb des Socket Adapters (SoAd) und des TCP/IP-Stacks innerhalb des BSW-Moduls Sd (Service Discovery, SWS SD).
    • Adaptive Platform: Implementierungsbasis für das dynamische Service-Routing und Binding im Communication Management (ara::com).
    • Dient der zyklischen und ereignisgesteuerten Dienst-Bekanntgabe (OfferService), Dienst-Suche (FindService) und dem Management von Event-Gruppen-Abonnements (Subscribe/StopSubscribe) über UDP/IP (typischerweise UDP-Port 30490).

2.1 SOME/IP Header (16 Bytes, Bytes 0x00–0x0F)
  • Message ID [32 Bit]: 0xFFFF 8100
    • Service ID: 0xFFFF (fest normierte SOME/IP-SD Service-ID).
    • Method/Event ID: 0x8100 (Bit 15 = 1 kennzeichnet Event/Notification-Format).
  • Length [32 Bit]: 64 Bytes (definiert die PDU-Restlänge ab Offset Byte 8, d. h. Request-ID bis Ende Options-Array).
  • Request ID [32 Bit]: Bestehend aus Client ID (16 Bit) und Session ID (16 Bit).
  • Protocol Version [8 Bit]: 0x01.
  • Interface Version [8 Bit]: 0x01.
  • Message Type [8 Bit]: 0x02 (NOTIFICATION).
  • Return Code [8 Bit]: 0x00 (E_OK).
2.2 SOME/IP-SD Header (4 Bytes)
  • Flags [8 Bit]: 0x80
    • Bit 7 (Reboot Flag): 1 (zeigt Neustart des Senders oder Session-ID-Überlauf an).
    • Bit 6 (Unicast Flag): 0 (Multicast-Übertragung).
    • Bits 5–0: Reserviert (0x00).
  • Reserved [24 Bit]: 0x000000 (muss auf 0 gesetzt und beim Empfang ignoriert werden).
2.3 Entries Array (36 Bytes inkl. Längenfeld)
  • Length of Entries Array [32 Bit]: 0x0000 0020 (32 Bytes, exakt 2 Entries à 16 Bytes).
  • Entry 1: FindService (Type = 0x00) [16 Bytes]
    • Index 1st / 2nd options [je 8 Bit]: 0 / 0.
    • # of opt 1 / # of opt 2 [je 4 Bit]: 0 / 0 (keine Optionen referenziert).
    • Service ID [16 Bit]: 0x4711.
    • Instance ID [16 Bit]: 0xFFFF (Wildcard: sucht alle Instanzen).
    • Major Version [8 Bit]: 0xFF (Wildcard: beliebige Major Version).
    • TTL [24 Bit]: 3600 Sekunden (1 Stunde Gültigkeitsdauer der Suchanfrage).
    • Minor Version [32 Bit]: 0xFFFF FFFF (Wildcard: beliebige Minor Version).
  • Entry 2: OfferService (Type = 0x01) [16 Bytes]
    • Index 1st options [8 Bit]: 0 (verweist auf Option an Index 0 im Options-Array).
    • Index 2nd options [8 Bit]: 0.
    • # of opt 1 / # of opt 2 [je 4 Bit]: 1 / 0 (verwendet genau 1 Option aus Set 1).
    • Service ID [16 Bit]: 0x1234.
    • Instance ID [16 Bit]: 0x0001 (spezifische Instanz 1).
    • Major Version [8 Bit]: 0x01.
    • TTL [24 Bit]: 3 Sekunden (Gültigkeit des Angebots bis zum nächsten Zyklus).
    • Minor Version [32 Bit]: 0x0000 0032 (Dezimal 50).
2.4 Options Array (16 Bytes inkl. Längenfeld)
  • Length of Options Array [32 Bit]: 12 Bytes (1 Option à 12 Bytes).
  • Option 1: IPv4 Endpoint Option (Type = 0x04) [12 Bytes]
    • Length [16 Bit]: 0x0009 (Nutzdatenlänge der Option ab Byte Type bis Port-Feld).
    • Type [8 Bit]: 0x04 (Kennung für IPv4 Endpoint).
    • Flags [8 Bit]: Bit 7 (DF / Discardable Flag) = 1 (darf verworfen werden, falls Parser Optionstyp nicht unterstützt), Bits 6–0 reserviert (0x00).
    • IPv4-Address [32 Bit]: 192.168.0.1 (0xC0A80001).
    • Reserved [8 Bit]: 0x00.
    • L4-Proto [8 Bit]: 0x11 (UDP, Dezimal 17).
    • Port Number [16 Bit]: 0xD903 (Dezimal 55555).

3. Dynamisches Verhalten & Sequenzablauf

  1. Paketbündelung / Aggregation: Das Diagramm belegt die Fähigkeit des SD-Stacks, heterogene Aktionen innerhalb einer PDU zu konsolidieren (hier: gleichzeitiges Absetzen eines FindService und eines OfferService).
  2. Indirekte Referenzierung (Options Linking):
    • Entry 2 verlinkt über Index 1st options = 0 und # of opt 1 = 1 unmittelbar auf Option 1 im Options-Array (im Diagramm visualisiert durch den schwarzen Referenzpfeil).
    • Der Empfänger-Parser muss die Endpunkt-Parameter (IP:Port:Transportprotokoll) aus der Option isolieren und dem angebotenen Dienst (0x1234:0x0001) zuordnen.
  3. Session- & Lifecycle-Handling:
    • Gesetztes Reboot Flag (0x80) zwingt den Kommunikationspartner zur Re-Synchronisation interner Session-IDs und zum Verwerfen vorheriger dynamischer Subscriptions/Zustände dieses Senders.
    • Die kurze TTL des Offer-Entries (3 Sekunden) triggert im zyklischen Modus (Repetition Phase / Main Phase) periodische Keep-Alive-Offers. Verstreicht die TTL ohne Refresh, invalidiert der Client den Service (STOP_OFFER-Semantik via Timeout).

4. Normative Relevanz & Entwickler-Hinweise

  • Byte Order & Padding: Sämtliche Multi-Byte-Felder (IDs, Längen, IP-Adressen, Ports) sind strikt in Big-Endian (Network Byte Order) zu serialisieren/deserialisieren.
  • Längenberechnungen:
    • SOME/IP Length = Gesamt-PDU-Länge minus 8 Bytes (schließt Message ID und Length-Feld selbst aus).
    • Option Length = Gesamtlänge der Option minus 3 Bytes (schließt Length- und Type-Header der Option aus, zählt ab Flags).
  • Index-Validierung im Parser:
    • Der Empfänger muss prüfen, dass Index 1st/2nd options + # of opt die tatsächliche Anzahl der im Options-Array deklarierten Elemente nicht überschreitet (Pufferüberlauf- und Out-of-Bounds-Prüfung).
  • Wildcard-Restriktionen:
    • Wildcards (0xFFFF bzw. 0xFF) sind normativ ausschließlich in Such-Nachrichten (FindService) zulässig. In OfferService müssen explizite Instanz-IDs und Release-Versionen konfiguriert sein.
  • Discardable-Flag-Semantik (DF = 1):
    • Erkennt ein Stack einen Optionstyp nicht, darf die Option bei DF = 1 ignoriert werden; der zugehörige Entry bleibt gültig. Bei DF = 0 muss der gesamte referenzierende Entry verworfen werden.
