1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR Methodology Activity/Work Product Diagram (Prozessfluss- und Artefakt-Abhängigkeitsdiagramm basierend auf SPEM 2.0 / UML-Profil der AUTOSAR-Methodik).
  • Technischer Zweck: Spezifikation des methodischen Workflows zur Einbindung, Modellierung, Verschaltung und Generierung von AUTOSAR-Basissoftware-Diensten (BSW Service Modules, z. B. Dem, Dcm, NvM) auf ECU-Ebene.
  • Funktionale Einordnung: Definiert die Brücke zwischen dem System-Design (ECU Extract), der BSW-Parametrierung (ECU Configuration Values), der Abbildung von BSW-Services als Software-Komponenten (ServiceComponentType), deren VFB-Port-Verschaltung (SwConnector) und den finalen Artefakten der Codegenerierung (RTE und BSW).

2. Komponenten, Entitäten & Schnittstellen

Work Products (Artefakte)
  • ECU Extract: Aus dem Gesamtsystem abgeleiteter Steuergeräte-Extrakt (Signaldefinitionen, SWC-Instanzen, Top-Level-Composition).
  • Service Component Description: ARXML-Schnittstellenbeschreibungen der BSW-Services als ServiceComponentType-Elemente mit Service-Ports (Client/Server, Sender/Receiver).
  • ECU Service Connectors: ARXML-Konnektorbeschreibungen (AssemblySwConnector, DelegationSwConnector) zwischen Applikations-SWCs und BSW-Service-Ports.
  • ECU Configuration Values: Vollständige Steuergeräte-Konfigurationssammlung (EcucValueCollection).
Aktivitäten (Methodological Tasks)
  • Generate Base Ecu Configuration: Erzeugung/Initialisierung der Basis-Steuergerätekonfiguration aus dem System-Extrakt.
  • Create Service Component: Ableitung formaler SWC-Repräsentationen der BSW-Services unter Berücksichtigung bestehender Konfigurationswerte.
  • Connect Service Component: Verknüpfung von Applikations-Ports mit den BSW-Service-Ports.
  • Configure Diagnostics: Exemplarische BSW-Modulparametrierung (Dem, Dcm, Fim) stellvertretend für BSW-Dienste.
  • Generate RTE: Generierung der Laufzeitumgebung (RTE-Quellcode).
  • Generate BSW: Quellcodegenerierung der Basissoftware-Module.

3. Dynamisches Verhalten & Sequenzablauf

  1. Initiale Konfiguration & Extraktion: Aus dem ECU Extract wird über die Aktivität Generate Base Ecu Configuration die Basiskonfiguration ECU Configuration Values erzeugt («output», [1]).
  2. Service-Komponenten-Erstellung: Create Service Component nimmt optional den ECU Extract («input», [0..1]) sowie optional bestehende ECU Configuration Values («input», [0..1]) entgegen und erzeugt verbindlich ECU Configuration Values («output», [1]) sowie die Service Component Description («output», [1]). Zudem können iterative Anpassungen vorherige Service Component Description-Artefakte wieder als Input verwenden («input», [0..*]).
  3. Service-Verschaltung: Connect Service Component liest die Service Component Description («input», [1]) sowie den ECU Extract («input», [1]) und erzeugt mindestens einen ECU Service Connectors-Deskriptor («output», [1..*]).
  4. Modulkonfiguration: Parallel oder nachfolgend liest und aktualisiert Configure Diagnostics bestehende ECU Configuration Values («inoutput», [1]) auf Basis des ECU Extract («input», [1]).
  5. Codegenerierung:
    • Generate RTE verarbeitet ECU Extract, ECU Service Connectors, Service Component Description und ECU Configuration Values und aktualisiert ECU Configuration Values («output», [1]).
    • Generate BSW transformiert die finalen ECU Configuration Values in BSW-Quellcode.

4. Normative Relevanz & Entwickler-Hinweise

  • Dualismus von BSW-API und VFB-Interface: BSW-Module stellen native C-APIs bereit, müssen jedoch für Applikations-SWCs als ServiceComponentType gekapselt werden. Entwickler greifen in SWCs nie direkt per #include auf BSW-Header zu, sondern ausschließlich über RTE-APIs (Rte_Call_<p>_<o>, Rte_Read_<p>_<d>).
  • Tool-gestützte Synchronisation: Änderungen an Diagnose- oder BSW-Parametern (z. B. Hinzufügen eines DemEvent) erzwingen eine Re-Generierung der Service Component Description über BSW-Konfigurationstools (z. B. EB tresos, DaVinci Configurator), da die Port-Definitionen (z. B. DiagnosticMonitor, DiagnosticInfo) synchron zu den BSW-Parametern gehalten werden müssen.
  • Typkompatibilität bei Connectors: Die ECU Service Connectors erfordern strikte Interface- und Datentyp-Identität zwischen Application Port und Service Port. Varianzen bei Datentypen (Std_ReturnType, Applikations-Fehlercodes) führen zu Inkompatibilitäten zur RTE-Generierungszeit.
  • Rückkopplungspfad des RTE-Generators: Der Pfad Generate RTE → ECU Configuration Values («output», [0..1]) verdeutlicht, dass der RTE-Generator selbst ECUC-Parameter (insbesondere des OS- und SchM-Moduls) definieren oder aktualisieren kann, weshalb die finale Generierung des BSW-Codes (Generate BSW Source Code) erst nach erfolgreichem RTE-Generierungslauf abgeschlossen werden darf.
