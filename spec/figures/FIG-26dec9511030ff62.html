1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Speichermodell- und Tabellen-Layout (Physical Binary Layout / Memory-Map-Struktur) eines AUTOSAR Binary Manifests.
  • Technischer Zweck & Einordnung:
    • Definiert gemäß AUTOSAR_SWS_SoftwareClusterConnection (eingeführt ab R20-11) die binäre Repräsentation zur Entkopplung und dynamischen/semi-statischen Bindung von Software-Clustern (SwCluster) auf einem Steuergerät.
    • Ermöglicht das getrennte Kompilieren, Linken und Flashen unabhängiger Anwendungscluster (Application SwCluster) gegenüber dem Host-Cluster (HOST, SwClusId = 0) ohne Neu-Linken des Gesamtsystems.
    • Bildet das Bindeglied zwischen clusterübergreifenden Schnittstellen (RTE-Ports, NvM-Zugriffe, Dispatcher/Trigger) über standardisierte Pointers und Handle-Indizes zur Laufzeit bzw. während des Initialisierungs-/Connect-Prozesses.

2. Komponenten, Entitäten & Schnittstellen

Das Schaubild gliedert sich strikt in unveränderliche Festwert-Strukturen (ROM/Flash) und zur Laufzeit/beim Verbindungsprozess modifizierbare Datenbereiche (RAM/EEPROM/D-Flash):

2.1 Binary Manifest Header (Read-Only)

Zentraler Einstiegspunkt für den Verbindungsprozessor (SwCluC):

  • Preamble: Eindeutiges Magic-Word zur Identifikation des Manifest-Beginns.
  • ManifestMajorVersion (1) / ManifestMinorVersion (0): Formatversion des Binary Manifests.
  • SwClusId (0): Eindeutige Cluster-ID (hier 0 für den Basis-/Host-Cluster).
  • MachineId (1): Physische Maschinen-/ECU-Instanz-ID.
  • SwClType (HOST): Rolle des Clusters (Host vs. Application Cluster).
  • ConnectorControlFlags (0): Steuerungs- und Betriebsmodi für den Verbindungstreiber.
  • NoOfInterfaceDescriptors (4): Anzahl der Einträge in der Interface Descriptor Table.
  • NoOfOfferedInterfaceHandles (3): Summe aller exportierten Funktions-/Objekt-Handles.
  • NoOfSubscribedInterfaceHandles (9): Summe aller importierten Schnittstellen-Handles.
  • Sub Table Pointers: Vektor von Adress-Offset-Pointern auf die nachgelagerten Subtabellen.
2.2 Interface Descriptor Table (Read-Only)

Jede Zeile beschreibt eine logische Schnittstelle und verlinkt auf Handle-Bereiche:

  1. Row 0 (Gelb – S/R Provided):
    • Resource Properties: 0x80 (provided = Cluster stellt Ressource bereit).
    • Resource Type: 0x01 (S/R = Sender/Receiver Communication).
    • Global Resource Id: 0x00000011.
    • Resource Guard Value: 0xDEADBEEF (32-Bit-Signatur/Hash zur Typprüfung von Datentyp und Schnittstellenvertrag).
    • Offered Interface Index / NoOf Handles: Index 0, Länge 1 → Zeigt auf Handle 0x00000042.
    • Subscribed Interface Index / NoOf Handles / Sets: 0xFFFF (NO_TABLE_ENTRY), 0, 0.
  2. Row 1 (Orange – S/R Required):
    • Resource Properties: 0x00 (required = Cluster konsumiert Ressource).
    • Resource Type: 0x01 (S/R).
    • Global Resource Id: 0x00000012.
    • Resource Guard Value: 0xCAFEBABE.
    • Offered Interface Index: 0xFFFF (NO_TABLE_ENTRY), Länge 0.
    • Subscribed Interface Index / NoOf Handles / Sets: Index 0, Länge 1, Sets 0 → Verlinkt auf Subscribed Slot 0 (0xCODE2000).
  3. Row 2 (Grün – NvBlock Provided):
    • Resource Properties: 0x80 (provided).
    • Resource Type: 0x04 (NvBlock = Nichtflüchtiger Speicherblock).
    • Global Resource Id: 0x00000001.
    • Resource Guard Value: 0x23252352.
    • Offered Interface Index / NoOf Handles: Index 1, Länge 2 → Handles 0x00001000 ff.
    • Subscribed Interface Index / NoOf Handles / Sets: Index 1, Länge 4, Sets 0 → Bindet 4 Subscribed-Handles an SwClusId 0x02.
  4. Row 3 (Blau – Dispatcher Provided/Multiplexed):
    • Resource Properties: 0x80 (provided).
    • Resource Type: 0x10 (dispatcher = Task-/Event-Verteiler).
    • Global Resource Id: 0x00000500.
    • Resource Guard Value: 0x19730615.
    • Offered Interface Index: 0xFFFF (NO_TABLE_ENTRY), Länge 0.
    • Subscribed Interface Index / NoOf Handles / Sets: Index 5, Länge 4, Sets 3 → 1:n Handle-Sets über Cluster 0xFE, 0x02, 0x04, 0xFF.
2.3 Subtabellen & Speicherbereiche
  • Offered Interface Handles (ROM, Preamble 0xDADA2388): Enthält fixe Adressen / Call-Targets (0x00000042, 0x00001000), die dieser Cluster für Konsumenten bereitstellt.
  • Subscribed Interface Default Handles (ROM, Preamble 0xDADA2400): Statische Fallback-Pointer/Stubs (0xCODE0100 .. 0xCODE0200), die aktiv sind, solange ein Cluster unverbunden bleibt (SWCLUC_BMANIF_UNCONNECTED).
  • Subscribed Interface Handles (RAM/Erase-Writeable, Preamble 0xDADA2478): Dynamisch aufgelöste Funktions- oder Speicher-Handles (0xCODE2000 .. 0xCODE0400), überschrieben durch den Verbindungsprozessor.
  • Subscribed Interface Connected SwClusterIds (RAM/Erase-Writeable): Cluster-Zuordnung je Handle (z. B. 0x02, 0xFE, oder 0xFF für SWCLUC_BMANIF_UNCONNECTED).
  • Prüfsummen & Validierungsmarker:
    • Immutable Tables Checksum (0x52616d73, ROM): Schützt statische Header- und Descriptor-Tabellen.
    • Total Manifest Checksum (0x7465696e, Writeable): Integritätsprüfung über das gesamte Manifest nach dem Resolving.
    • Subscribed Interface Validity Marker (0x63726170, Writeable): Status-Flag/Magic, das der RTE signalisiert, dass alle Subscriptions gültig gebunden sind.

3. Dynamisches Verhalten & Sequenzablauf

  1. Boot-/Pre-Init-Phase:
    • Der BSW-Initialisierer oder SwCluC-Master liest den Binary Manifest Header und validiert die Immutable Tables Checksum.
    • Vor Ausführung des Verbindungsalgorithmus verweisen alle Abonnenten (Subscribed Interfaces) deterministisch auf die Einträge der Subscribed Interface Default Handles (Safe-State-Stubs).
  2. Interface Matching & Validation:
    • Iteration über die Interface Descriptor Table beider beteiligter Cluster.
    • Abgleich: Übereinstimmung von Global Resource Id (z. B. 0x00000011 mit Partner) und Kompatibilitätsprüfung via Resource Guard Value (Bitmuster-/Hash-Gleichheit).
    • Bei Guard-Fehlschlag bricht die Bindung ab (Fehlerprotokollierung an DET/DEM, z. B. SWCLUC_E_GUARD_MISMATCH).
  3. Handle Resolution & Patching:
    • Nach erfolgreicher Verifikation kopiert der Resolver die Zieladressen aus Offered Interface Handles des Providers in die Subscribed Interface Handles des Requirers.
    • Eintragung der Quell-Cluster-ID in Subscribed Interface Connected SwClusterIds. Unvollständige oder fehlende Bindungen verbleiben auf 0xFF (SWCLUC_BMANIF_UNCONNECTED).
  4. Finalisierung:
    • Neuberechnung und Schreiben der Total Manifest Checksum.
    • Setzen des Subscribed Interface Validity Marker. Erst danach schaltet die RTE die Inter-Cluster-Kommunikation frei.

4. Normative Relevanz & Entwickler-Hinweise

  • Speicherlayout & Linker-Skripte:
    • Entwickler müssen Linker-Sektionen strikt trennen: Header, Deskriptoren, Offered Handles und Default Handles gehören in nicht-flüchtigen Flash (.rodata/Flash).
    • Subscribed Interface Handles und Status-Tabellen müssen in einer separat lösch- und beschreibbaren Sektion liegen (No-Init RAM oder dediziertes D-Flash/Emulated EEPROM, falls persistiert).
  • Binärkompatibilität & Guard Values:
    • Der Resource Guard Value verhindert Calling-Convention-, Datentyp- oder Array-Size-Inkompatibilitäten zwischen unabhängig geflashten Clustern. Jede Änderung am Software-Component-Interface (swc-bsw / ARXML-PortInterface) ändert den Guard und sperrt die Interaktion zur Laufzeit.
  • 1:n Multiplexing & Handle-Sets:
    • Über Subscribed Interface NoOf HandleSets (z. B. Wert 3 bei Resource 0x00000500) können Schnittstellen an mehrere Empfänger/Dispatcher gleichzeitig gebunden werden. Entwickler müssen sicherstellen, dass die zugehörige Dispatcher-Infrastruktur reentrant und threadsicher ausgeführt ist.
  • Fehlerbehandlung:
    • Greift ein SWC auf ein Subscribed Interface zu, während der Eintrag auf 0xFF (SWCLUC_BMANIF_UNCONNECTED) steht, leitet der Default Handle den Aufruf auf einen unschädlichen Stub oder generiert eine DET-Meldung, um Hard-Faults (Null-Pointer-Dereferenzierung) zu verhindern.
