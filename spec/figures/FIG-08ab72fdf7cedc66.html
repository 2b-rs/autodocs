1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU Configuration Metamodel (ECUC) / UML-Klassendiagramm zur Konfigurationsbeschreibung gemäß AUTOSAR-Parametermetamodell.
  • Technischer Zweck: Definition der XML/ARXML-Konfigurationsstrukturen für die Senderichtung (Tx-Pfade) des BSW-Moduls J1939Fscp (SAE J1939 Functional Safety Communication Protocol, basierend auf SAE J1939-76).
  • Architektur-Kontext: Das Modul J1939Fscp ist im AUTOSAR Classic Platform Communication Stack zwischen oberen Schichten (z. B. COM / Applikation) und dem PduR/CanIf angesiedelt. Das Diagramm modelliert die statische BSW-Konfiguration zur Strukturierung von Sicherheitskanälen (Tx-Channels), Zuordnung zu Kommunikationsnetzen (ComM) sowie die Parametrierung der zusammengehörigen Safety-Header- und Data-PDUs pro Parameter Group (TxPg).

2. Komponenten, Entitäten & Schnittstellen

Container und Hierarchien
  • J1939FscpTxChannel (EcucParamConfContainerDef)
    • Multiplizität: 0..* (Optional, beliebig viele Kanäle konfigurierbar).
    • Bedeutung: Repräsentiert einen logischen Tx-Sicherheitskommunikationskanal.
    • Sub-Container & Referenzen:
      • Aggregiert 1..* Instanzen von J1939FscpTxPg (+subContainer).
      • Aggregiert genau 1..1 Instanz von J1939FscpShmTxPdu (+subContainer).
      • Besitzt die Referenz J1939FscpTxChannelComMNetworkHandleRef (+reference).
  • J1939FscpTxPg (EcucParamConfContainerDef)
    • Multiplizität: 1..* innerhalb eines J1939FscpTxChannel.
    • Bedeutung: Konfiguration einer funktional sicheren Tx Parameter Group (PG) gemäß J1939-76.
    • Parameter & Sub-Container:
      • J1939FscpSdgTxPdu (EcucParamConfContainerDef, +subContainer): Multiplizität 1..1. Definiert die Safety Data Group (SDG) Tx-PDU.
      • J1939FscpSdmTxPdu (EcucParamConfContainerDef, +subContainer): Multiplizität 1..1. Definiert die Safety Data Message (SDM) Tx-PDU.
      • J1939FscpTxSrvt (EcucFloatParamDef, +parameter): Wertebereich min = 0, max = INF. Parametriert die Safety Receiver Validation Time (SRVT) zur zeitlichen Überwachung auf Empfängerseite.
      • J1939FscpShmTxPriority (EcucIntegerParamDef, +parameter): Wertebereich 0..7, Multiplizität 0..1 (optional). Definiert die J1939-CAN-Priorität für die Übertragung der Safety Header Message (SHM).
  • J1939FscpShmTxPdu (EcucParamConfContainerDef)
    • Multiplizität: 1..1 je J1939FscpTxChannel.
    • Bedeutung: Konfiguriert die kanalweit geteilte bzw. zugeordnete Safety Header Message (SHM) Tx-PDU.
Externe Referenzen & Bindeglieder
  • J1939FscpTxChannelComMNetworkHandleRef (EcucReferenceDef)
    • Attribut: requiresSymbolicNameValue = true.
    • Ziel (+destination): ComMChannel (EcucParamConfContainerDef aus Paket ComM).
    • Multiplizität des Ziels: 1..256. Bindet den J1939Fscp-Kanal fest an ein ComM-Kanal-Handle zur Auswertung des Buszustands (Kommunikationsfreigabe/Netzwerkmodus).

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

Obwohl das Diagramm statische Konfigurationsstrukturen abbildet, determiniert es folgende Laufzeitabläufe:

  • Kanal-Initialisierung & Netzwerkstatus: Über J1939FscpTxChannelComMNetworkHandleRef korreliert J1939Fscp den Tx-Kanalstatus mit dem Kommunikationszustand des ComM. Erst bei aktivem Bus (COMM_FULL_COMMUNICATION) können Übertragungen initiiert werden.
  • PDU-Aufteilung und Sequenzierung (J1939-76 Tx):
    1. Triggerung einer sicherheitsrelevanten Übertragung pro J1939FscpTxPg.
    2. Assemblierung der Safety Header Message (J1939FscpShmTxPdu) unter Nutzung der parametrierten Priorität J1939FscpShmTxPriority (0–7) sowie des SRVT-Werts (J1939FscpTxSrvt) im Header-Nutzdatenfeld.
    3. Parallele bzw. koordinierte Bereitstellung der Safety Data Message (J1939FscpSdmTxPdu) bzw. Safety Data Group (J1939FscpSdgTxPdu) an die unteren Schichten (PduR / CAN-Interface).
  • Fehlerbehandlung: Verletzungen konfigurierter Längen, ungültige PDU-IDs oder nicht konfigurierte Referenzen führen zur Generierung von BSW-Initialisierungsfehlern bzw. Meldungen an das Default Error Tracer (DET)-Modul (J1939FSCP_E_INVALID_PDU_SDU_ID, Konfigurationsinkonsistenz).

4. Normative Relevanz & Entwickler-Hinweise

  • 1:1-Zuordnung SHM zu Channel vs. 1:N-Zuordnung PG: Pro J1939FscpTxChannel existiert exakt ein Container J1939FscpShmTxPdu, während mehrere Parameter Groups (J1939FscpTxPg) auf diesem Kanal gebündelt werden können. Entwickler müssen sicherstellen, dass die Header-PDU für alle aggregierten PGs multiplexbar oder scheduler-seitig kollisionsfrei handhabbar ist.
  • PDU-Paarung pro PG: Jede J1939FscpTxPg erzwingt strikt (lowerMultiplicity = 1, upperMultiplicity = 1) jeweils genau eine J1939FscpSdgTxPdu und eine J1939FscpSdmTxPdu. Fehlende Zuweisungen führen zu Validierungsfehlern des BSW-Konfigurationsgenerators.
  • Echtzeit- und Timing-Constraint (SRVT): J1939FscpTxSrvt ist als Fließkommazahl spezifiziert. Bei der Code-Generierung (Post-Build oder Pre-Compile) erfolgt typischerweise eine Skalierung in Ticks oder Integer-Mikrosekunden/Millisekunden; Entwickler müssen Quantisierungsfehler zwischen CAN-Übertragungszyklus und SRVT-Timeout abgleichen.
  • CAN-Identifier-Priorität: Ist J1939FscpShmTxPriority gesetzt, überschreibt bzw. definiert dieser Integerwert (0–7) die obersten 3 Bits des 29-Bit-J1939-CAN-Identifiers für die SHM-Frame-Generierung. Fehlt der optionale Parameter, greift der Default-Wert der zugrundeliegenden PDU- bzw. CAN-Treiber-Konfiguration.
