1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Aktivitätsdiagramm (UML Activity Diagram) zur Spezifikation eines synchronen Kontrollflusses.
  • Technischer Zweck: Spezifikation der clientseitigen Vorverarbeitung (E2EXf_Inv_handling_PXXm_client) innerhalb der inversen E2E-Transformationskette (E2EXf_Inv_<TransformerId>) für Multi-Source-Profile (PXXm) bei Client-Server-Kommunikation.
  • Funktionale Einordnung im AUTOSAR-Gesamtsystem:
    • Verortet im Basic Software (BSW) Stack innerhalb des E2E Transformer (E2EXf), integriert in das AUTOSAR Transformer Framework (aufgerufen bei Empfang bzw. Deserialisierung einer Client-Server-Response durch die RTE).
    • Dient der Extraktion protokollspezifischer Header-Felder aus dem Eingabepuffer und der Zuweisung der quellenspezifischen Identifikation (sourceID = config->sourceID), um nachfolgende E2E-Prüfungen auf Client-Seite für Multi-Source-Profile vorzubereiten bzw. bei fehlerhaftem Protokollheader einen harten Sicherheitslaufzeitfehler auszulösen.

2. Komponenten, Entitäten & Schnittstellen

  • Kontrollfluss-Entitäten (UML):
    • Initial Node: Einsprungpunkt der clientseitigen Vorverarbeitungsroutine.
    • Decision Nodes:
      • Profile == PXXm: Verzweigung anhand des konfigurierten E2E-Profils.
      • ok = E_OK: Validierung des Extraktionsergebnisses.
    • Action Nodes:
      • ok = extractProtocolHeaderFields(buffer/inputBuffer, bufferLength/inputBufferLength, &messageType, &messageResult) (::): Aufruf zur Extraktion von Steuerfeldern aus dem Eingabepuffer (farblich als C/S: Client gekennzeichnet).
      • WriteVariable: sourceID = config->sourceID: Zuweisung der konfigurierten Source-ID an die lokale Zustandsvariable (Stereotyp WriteVariable, farblich als C/S: Client gekennzeichnet).
    • Activity Final Nodes:
      • return E_SAFETY_HARD_RUNTIMEERROR: Abbruch bei ungültigem Protokollheader.
      • return E2E_E_OK: Erfolgreicher Abschluss der Vorverarbeitung bzw. direkter Rücksprung bei Nicht-Multi-Source-Profilen.
    • Legend: Farblegende für Kommunikationsmuster (All types, Sender/Receiver, Publisher/Subscriber, C/S: Server, C/S: Client, Signal to Service).
  • Beteiligte BSW-Module & Schnittstellen:
    • E2E Transformer (E2EXf): Kapselt die Transformationsfunktion im BSW-Stack.
    • extractProtocolHeaderFields(...): Schnittstelle/Hilfsroutine zur Dekodierung von Protokoll-Headern (z. B. SOME/IP) aus dem Eingabepuffer.
  • Datenstrukturen & Variablen:
    • buffer / inputBuffer: Zeiger auf den PDU-Eingabepuffer.
    • bufferLength / inputBufferLength: Länge des Puffers.
    • messageType, messageResult: Aus dem Header extrahierte Protokollvariablen.
    • sourceID: Lokale Zielvariable für die Quellenkennung.
    • config->sourceID: Konfigurierte Source-ID aus der Transformator-Konfiguration.
    • ok: Statusvariable (Std_ReturnType).

3. Dynamisches Verhalten & Sequenzablauf

Der Ablauf erfolgt synchron im Kontext der inversen Transformation bei PDU-Empfang auf Client-Seite:

  1. Trigger & Profile-Prüfung: Nach Einsprung über den Initial Node prüft der Verzweigungsknoten [Profile == PXXm], ob ein Multi-Source-Profil aktiv ist.
  2. Pfad [TRUE] (Multi-Source Client Handling):
    • Aufruf von extractProtocolHeaderFields(buffer/inputBuffer, bufferLength/inputBufferLength, &messageType, &messageResult).
    • Auswertung der Bedingung [ok = E_OK]:
      • Fehlerfall [FALSE]: Die Extraktion schlägt fehl. Der Kontrollfluss terminiert unmittelbar im Activity Final Node mit return E_SAFETY_HARD_RUNTIMEERROR.
      • Erfolgsfall [TRUE]: Die Aktion WriteVariable weist sourceID = config->sourceID zu.
      • Anschließend terminiert der Kontrollfluss im Activity Final Node mit return E2E_E_OK.
  3. Pfad [FALSE] (Nicht-PXXm):
    • Ist kein PXXm-Profil konfiguriert, wird die Header-Extraktion und Variablenbelegung umgangen. Der Kontrollfluss verzweigt direkt zum Activity Final Node und liefert return E2E_E_OK.

4. Normative Relevanz & Entwickler-Hinweise

  • Client-Server-Spezifik: Die Aktivität ist gemäß AUTOSAR-Farblegende explizit als C/S: Client deklariert und gilt ausschließlich für clientseitige inverse Transformatoren in Many-to-One-Kommunikationsmustern.
  • Fehlereskalation: Ein Scheitern der Header-Extraktion wird als schwerer Sicherheitsfehler (E_SAFETY_HARD_RUNTIMEERROR) gewertet, der die Weiterverarbeitung der PDU abbricht und eine strukturierte Fehlerbehandlung im BSW-Stack erzwingt.
  • Konfigurationsbindung: sourceID = config->sourceID bindet die erwartete Quellenidentifikation statisch aus der Konfiguration an den lokalen Kontext für nachfolgende Prüfschritte der E2E-Bibliothek.
  • Bypass für Standard-Profile: Für Single-Source-Profile (Profile != PXXm) ist die Vorverarbeitung transparent (return E2E_E_OK), wodurch die Kompatibilität zu bestehenden Transformationsabläufen gewahrt bleibt.
