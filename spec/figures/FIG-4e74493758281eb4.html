1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm (Metamodell-Ausschnitt der AUTOSAR Template-Spezifikation).
  • Architektur-Kontext: Trennung von Schemadefinition (ECU Configuration Parameter Definition / BSWMD) und konkreter Werteinstanziierung (ECU Configuration Parameter Values / EcucDescription ARXML) gemäß AUTOSAR CP R25-11. Das Metamodell definiert die strukturelle Kapselung hierarchischer Konfigurationswerte (EcucContainerValue), deren Aggregationen sowie deren typgebundene Bindung an die jeweiligen Definitionsknoten (EcucContainerDef, EcucParameterDef).

2. Komponenten, Entitäten & Schnittstellen

#### Paket: ECU Configuration Parameter Definition (Metamodell / BSW Module Description)

  • EcucContainerDef (abstract, spezialisiert EcucDefinitionElement):
  • Basisdefinition eines Konfigurationscontainers.
  • Attribute:
  • origin: String [0..1]: Ursprung der Definition (z. B. AUTOSAR oder OEM).
  • postBuildVariantMultiplicity: Boolean [0..1]: Gibt an, ob die Kardinalität post-build-variabel ist.
  • requiresIndex: Boolean [0..1]: Erzwingt zwingende Indexierung mehrfacher Instanzen.
  • EcucParamConfContainerDef (spezialisiert EcucContainerDef):
  • Standard-Container, der Parameter und Untercontainer aggregiert.
  • Aggregation +subContainer [0..*] «atpSplitable» zu EcucContainerDef.
  • Aggregation +parameter [0..*] «atpSplitable» zu EcucParameterDef.
  • EcucChoiceContainerDef (spezialisiert EcucContainerDef):
  • Auswahlcontainer; aggregiert alternative Containerdefinitionen über +choice [0..*] «atpSplitable» zu EcucParamConfContainerDef.
  • EcucParameterDef (abstract, spezialisiert EcucCommonAttributes):
  • Definition atomarer Konfigurationsparameter.
  • Attribute:
  • symbolicNameValue: Boolean [0..1]: Kennzeichnet Parameter als symbolischen C-Bezeichner (#define).
  • withAuto: Boolean [0..1]: Erlaubt automatische Wertberechnung durch Konfigurations-Tools.

#### Paket: ECU Configuration Parameter Values (Instanzmodell / EcucDescription)

  • EcucIndexableValue (abstract):
  • Gemeinsame Basisklasse für geordnete/indizierte Wertelemente (Spezialisierungshierarchie für Container und Parameter).
  • Attribut: index: PositiveInteger [0..1]: Eindeutiger 1-basierter Index zur festen Determinierung der Reihenfolge.
  • EcucContainerValue (spezialisiert Identifiable und EcucIndexableValue):
  • Konkrete Instanz eines Konfigurationscontainers im ECU-Extrakt.
  • Rekursive Aggregation: +subContainer [0..*] mit Stereotypen «atpVariation, atpSplitable» auf sich selbst (EcucContainerValue).
  • Aggregation: +parameterValue [0..*] mit Stereotypen «atpVariation, atpSplitable» auf EcucParameterValue.
  • EcucParameterValue (spezialisiert EcucIndexableValue):
  • Konkreter Instanzwert eines Parameters.
  • Attribut: isAutoValue: Boolean [0..1]: Markiert, dass der Wert generiert/automatisiert gesetzt wurde.

#### Cross-Package-Beziehungen & Stereotypen

  • Assoziation +definition [0..1]:
  • EcucContainerValue $\rightarrow$ EcucContainerDef: Typisierung des Containers.
  • EcucParameterValue $\rightarrow$ EcucParameterDef: Typisierung des Parameters.
  • Stereotypen:
  • «atpSplitable»: Fragmente von Containern und Parameterlisten dürfen über mehrere physische ARXML-Dateien aufgeteilt und vom Generator werkzeuggestützt zusammengeführt werden.
  • «atpVariation»: Container-Instanzen und Parameterwerte unterliegen der AUTOSAR-Variantentheorie (Pre-Compile- oder Post-Build-Selektion über VariationPoint).

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Metamodell existiert kein Laufzeit-Sequenzfluss im Ziel-ECU-Core. Der Toolchain- und Generierungszyklus verläuft stattdessen wie folgt:

```

[ARXML Parsing]

│

▼

[Splitable Resolution] ──> Zusammenführen verteilter Container-Fragmente («atpSplitable»)

│

▼

[Binding Validation] ──> Auflösen der +definition Assoziationen ([constr_3592], [constr_3593])

│

▼

[Variation Resolution] ──> Evaluierung aktiver System-Varianten («atpVariation»)

│

▼

[Index Evaluation] ──> Validierung TPS_ECUC_08043 (falls requiresIndex == true: index zwingend)

│

▼

[Code Generator BSW] ──> Generierung der Datenstrukturen (_Cfg.h, _PBcfg.c)

```

  • Validierungs-Barriere: Nicht auflösbare +definition-Referenzen führen vor der Codegenerierung zum Abbruch mit Tool-Fehler (statische Prüfung gegen ECUC-Parameter-Definition).

4. Normative Relevanz & Entwickler-Hinweise

  • Zwingende Definitionsreferenzen ([constr_3592], [constr_3593]):
  • EcucContainerValue.definition und EcucParameterValue.definition sind formal im Metamodell mit [0..1] modelliert (erforderlich für Zwischenstufen unvollständiger Tool-Exporte), müssen jedoch spätestens zum Codegenerierungszeitpunkt zwingend aufgelöst sein (1..1). Fehlt die Definition, darf der BSW-Generator keinen C-Code erzeugen.
  • Indexierung vs. Array-Layout ([TPS_ECUC_08043]):
  • Ist an EcucContainerDef das Attribut requiresIndex = true gesetzt, muss in jedem EcucContainerValue das Attribut index vergeben sein. BSW-Treiberentwickler können sich darauf verlassen, dass generierte C-Struktur-Arrays (z. B. Channel-Tabellen bei CanController oder PduRRoutingPath) deterministisch über diesen Index indiziert werden, unabhängig von der Parsing-Reihenfolge der ARXML-Fragmente.
  • Varianten- und Tool-Integration ([TPS_ECUC_03012]):
  • Durch «atpSplitable» können OEM und Tier-1 dieselbe Container-Hierarchie getrennt pflegen (z. B. Basis-Konfiguration vs. projektspezifische Parametrierung).
  • Durch «atpVariation» dürfen EcucContainerValue und EcucParameterValue in Post-Build-Loadable- (PB-L) oder Post-Build-Selectable- (PB-S) Strukturen übersetzt werden. Wenn postBuildVariantMultiplicity = true, variiert die Anzahl der Sub-Container je nach aktiver PB-Konfiguration, was dynamische Deskriptortabellen im RAM/Flash bedingt.
  • Automatisierung (isAutoValue / withAuto):
  • BSW-Generatoren nutzen isAutoValue, um vom Tool berechnete Werte (z. B. CanBaudrate Clock-Divider) von manuell vom Integrator überschriebenen Werten abzugrenzen. Überschreibt ein Entwickler einen berechneten Parameter, muss isAutoValue auf false gesetzt oder entfernt werden.
