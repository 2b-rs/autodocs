1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Strukturelles Speicherlayout- und Adressierungsdiagramm (Memory Mapping / Block Layout Specification).
  • Architektur-Kontext: AUTOSAR Classic Platform, Basic Software (BSW), System Services Layer, Modul NVRAM Manager (NvM).
  • Technischer Zweck: Spezifikation des linearen Adressierungs- und Indizierungsmodells für den schreibgeschützten ROM-Anteil eines Dataset NVRAM Blocks (NVM_BLOCK_DATASET). Es definiert den Offset und die Indexgrenzen, über die optionale Default-/Konfigurations-Datensätze im ROM über dieselbe Dataset-Schnittstelle wie NV-Datensätze adressiert werden.

2. Komponenten, Entitäten & Schnittstellen

  • Entitäten & Speicherbereiche:
    • ROM block data area (Index NVM_NV_BLOCK_NUM): Erster optionaler ROM-Datensatz. Physikalisch im On-Chip-Flash/ROM abgelegt; enthält unveränderliche Kalibrier- oder Werksdefaultdaten.
    • ROM block data area (Index NVM_NV_BLOCK_NUM + NVM_ROM_BLOCK_NUM - 1): Letzter adressierbarer ROM-Datensatz des Blocks.
    • Dazwischenliegende Instanzen (...): Äquidistante, identisch strukturierte ROM-Datenblöcke innerhalb des konfigurierten Indexbereichs.
  • Kardinalitäten & Konfigurationsparameter:
    • NvMNvBlockNum (1 … 255): Anzahl der beschreibbaren NV-Speicherblöcke im NVRAM (EEPROM/Flash via MemIf/Fee/Ea), belegt Indizes 0 bis NVM_NV_BLOCK_NUM - 1.
    • NvMRomBlockNum (0 … 255, Parameter optional): Anzahl der hinterlegten ROM-Datensätze.
    • Gesamtkardinalität eines Datasets: $\text{Gesamtanzahl Datensätze} = NvMNvBlockNum + NvMRomBlockNum \le 256$ (Begrenzung durch 8-Bit-Dataset-Index uint8).
  • Schnittstellen / Administrative Datenstrukturen:
    • NvM Administrative Block: Hält den aktuellen Laufzeit-Index (DataIndex) des jeweiligen Block-Handles.
    • API-Schnittstelle: Adressauswahl erfolgt über NvM_SetDataIndex(BlockId, DataIndex) bzw. Abfrage über NvM_GetDataIndex(BlockId, DataIndexPtr).

3. Dynamisches Verhalten & Sequenzablauf

  • Index-Selektion: Vor Ausführung eines NvM-Lese- oder Wiederherstellungsauftrags selektiert der Aufrufer (SW-C oder BSW) via NvM_SetDataIndex() einen Zielindex im Bereich $[NVM\_NV\_BLOCK\_NUM \dots NVM\_NV\_BLOCK\_NUM + NVM\_ROM\_BLOCK\_NUM - 1]$.
  • Lesezugriff (NvM_ReadBlock / NvM_RestoreBlockDefaults):
    1. NvM evaluiert den konfigurierten DataIndex.
    2. Liegt DataIndex ≥ NvMNvBlockNum, erfolgt keine Interaktion mit der Memory Abstraction Interface (MemIf/Fee/Ea).
    3. Stattdessen triggert der NvM einen synchronen/asynchronen Speichertransfer direkt aus dem referenzierten ROM-Zeiger (NvMRomBlockDataAddress) in den zugeordneten permanenten oder temporären RAM-Spiegel (RAM block data area).
    4. Nach erfolgreichem Kopiervorgang wechselt der Blockstatus auf NVM_REQ_OK; konfigurierte Single-Block-Callbacks werden ausgelöst.
  • Schreibzugriff (NvM_WriteBlock / NvM_InvalidateNvBlock / NvM_EraseNvBlock):
    • Wird ein Schreib-, Lösch- oder Invalidierungsauftrag auf einen selektierten ROM-Index (DataIndex ≥ NVM_NV_BLOCK_NUM) abgesetzt, verwirft der NvM die Anforderung synchron mit E_NOT_OK oder bricht den asynchronen Job ab, setzt den Request-Status auf NVM_REQ_NOT_OK und feuert optional den DET-Fehler NVM_E_PARAM_DATA_INDEX.

4. Normative Relevanz & Entwickler-Hinweise

  • Index-Offset-Berechnung: Applikations- und BSW-Entwickler müssen beachten, dass ROM-Datensätze nicht bei Index 0 beginnen, sondern strikt hinter den NV-Blöcken angehängt werden (Offset = NvMNvBlockNum).
  • Konfigurationsverpflichtung: Wird NvMRomBlockNum > 0 konfiguriert, muss im NvM-BSW-Konfigurator (NvMBlockDescriptor) ein valider ROM-Array-Pointer (NvMRomBlockDataAddress) hinterlegt sein, der auf ein Array mit der Elementanzahl NvMRomBlockNum und der Elementgröße NvMBlockLength verweist.
  • RAM-Mirror-Dimensionierung: Unabhängig davon, ob NV- oder ROM-Indizes angesprochen werden, muss der RAM-Block (NvMRamBlockDataAddress) exakt für die größte konfigurierte Nutzdatenlänge eines Einzelelements dimensioniert sein.
  • API-Vertrag & Schutz vor Fehlgebrauch:
    • Das Setzen eines ungültigen Index (DataIndex ≥ NvMNvBlockNum + NvMRomBlockNum) via NvM_SetDataIndex() wird bei aktivem Development Error Detection (NVM_DEV_ERROR_DETECT == STD_ON) mit NVM_E_PARAM_DATA_INDEX zurückgewiesen.
    • In Multi-Standard- oder Mehrkanal-ECUs eignen sich diese ROM-Indizes primär für unveränderliche Fahrzeugvarianten-Parameter (Fallback-Maps, OEM-Kalibrierungen), die vor Schreibzugriffen geschützt im internen Flash liegen müssen.
