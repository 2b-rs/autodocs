1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration Metamodell (ECUC ParamConfContainerDef / UML-Klassendiagramm der Parameterdefinition).
  • Architektur-Kontext: AUTOSAR Classic Platform, BSW-Modul Dem (Diagnostic Event Manager, SWS-Kapitel 10 – Configuration specification).
  • Funktionaler Zweck: Deklaration wiederverwendbarer Parametersätze für die zählerbasierte Entprellung (DemDebounceCounterBasedClass). Das Modell definiert Schwellwerte, Schrittweiten, Sprunglogiken und Persistenz-/Einfrierverhalten für interne Fehlerentprellungs-Algorithmen (DEM_DEBOUNCE_COUNTER_BASED) auf Basis eines vorzeichenbehafteten 16-Bit-Zählers (sint16).

2. Komponenten, Entitäten & Schnittstellen

Container & Hierarchie
  • DemConfigSet (EcucParamConfContainerDef): Wurzelcontainer der BSW-Konfiguration.
  • DemDebounceCounterBasedClass (EcucParamConfContainerDef):
    • Kardinalität: 0..65535 (Instanzen per Sub-Container-Aggregation +subContainer an DemConfigSet gebunden).
    • Enthält keine weiteren Sub-Container („No Included Containers“).
Parameter (+parameter)
  • DemDebounceCounterIncrementStepSize (EcucIntegerParamDef):
    • Wertebereich: [1 .. 32767]. Schrittweite bei gemeldetem Fehlerevent (DEM_EVENT_STATUS_FAILED bzw. PREFAILED).
  • DemDebounceCounterDecrementStepSize (EcucIntegerParamDef):
    • Wertebereich: [1 .. 32768]. Schrittweite bei gemeldetem Gut-Event (DEM_EVENT_STATUS_PASSED bzw. PREPASSED).
  • DemDebounceCounterFailedThreshold (EcucIntegerParamDef):
    • Wertebereich: [1 .. 32767]. Schwellwert für Fehlerqualifikation (testFailed = 1).
  • DemDebounceCounterPassedThreshold (EcucIntegerParamDef):
    • Wertebereich: [-32768 .. -1]. Schwellwert für Gut-Qualifikation (testFailed = 0, PASSED-Zustand).
  • DemDebounceCounterJumpUp (EcucBooleanParamDef): Aktiviert Sprunglogik bei Richtungswechsel nach FAILED.
  • DemDebounceCounterJumpUpValue (EcucIntegerParamDef):
    • Wertebereich: [-32768 .. 32767], Default: 0. Startwert nach FAILED-Sprung, falls aktueller Zählerstand unter diesem Wert liegt.
  • DemDebounceCounterJumpDown (EcucBooleanParamDef): Aktiviert Sprunglogik bei Richtungswechsel nach PASSED.
  • DemDebounceCounterJumpDownValue (EcucIntegerParamDef):
    • Wertebereich: [-32768 .. 32767], Default: 0. Startwert nach PASSED-Sprung, falls aktueller Zählerstand über diesem Wert liegt.
  • DemDebounceBehavior (EcucEnumerationParamDef):
    • Kardinalität: 1..1, Default: DEM_DEBOUNCE_RESET.
    • Literale (+literal):
      • DEM_DEBOUNCE_FREEZE: Zählerstand wird bei inaktiven Freigabebedingungen (EnableCondition, StorageCondition) oder DTC-Sperre eingefroren.
      • DEM_DEBOUNCE_RESET: Zählerstand wird bei Deaktivierung auf 0 zurückgesetzt.
  • DemDebounceCounterStorage (EcucBooleanParamDef):
    • Default: false. Bestimmt, ob der Entprellzählerstand über Fahrzyklen bzw. Power-Down/Warmstarts (via NvM) persistent gehalten wird.
  • DemCounterBasedFdcThresholdStorageValue (EcucIntegerParamDef):
    • Kardinalität: 0..1 (optional), Wertebereich: [1 .. 32767]. Schwellwert des Fault Detection Counter (FDC) für vorzeitiges Einfrieren/Speichern von Freeze-Frame-Daten vor endgültiger Fehlerqualifikation.

3. Dynamisches Verhalten & Sequenzablauf

  1. Trigger & Bewertung (Dem_SetEventStatus):
    • Aufruf durch SW-C oder BSW mit DEM_EVENT_STATUS_PREFAILED:
      • Wenn DemDebounceCounterJumpUp == TRUE und Zählerstand < DemDebounceCounterJumpUpValue: Zähler springt sofort auf DemDebounceCounterJumpUpValue.
      • Zähler wird um DemDebounceCounterIncrementStepSize erhöht (begrenzt auf DemDebounceCounterFailedThreshold).
      • Erreicht der Zähler DemDebounceCounterFailedThreshold, qualifiziert der Dem das Event als FAILED (Setzen von testFailed = 1, Aktualisierung des UDS-Statusbytes).
    • Aufruf mit DEM_EVENT_STATUS_PREPASSED:
      • Wenn DemDebounceCounterJumpDown == TRUE und Zählerstand > DemDebounceCounterJumpDownValue: Zähler springt sofort auf DemDebounceCounterJumpDownValue.
      • Zähler wird um DemDebounceCounterDecrementStepSize dekrementiert (begrenzt auf DemDebounceCounterPassedThreshold).
      • Erreicht der Zähler DemDebounceCounterPassedThreshold, qualifiziert der Dem das Event als PASSED.
  2. Vorzeitige Datenspeicherung (FDC-Schwelle):
    • Erreicht der interne Zähler während der Inkrementierung DemCounterBasedFdcThresholdStorageValue, löst der Dem die Erfassung von Freeze-Frame- / Extended-Data-Records aus, noch bevor der FailedThreshold erreicht ist.
  3. Inhibitions- und Kontrollzustände:
    • Bei Ausfall einer EnableCondition oder Aufruf von Dem_SetEventAvailable(..., FALSE) greift DemDebounceBehavior:
      • DEM_DEBOUNCE_FREEZE: Zähler verharrt auf dem aktuellen Wert; Inkrement/Dekrement-Operationen sind blockiert.
      • DEM_DEBOUNCE_RESET: Zähler wird synchron auf 0 initialisiert.

4. Normative Relevanz & Entwickler-Hinweise

  • RAM- und Datentyp-Allokation:
    • Der Zähler ist normativ als vorzeichenbehafteter 16-Bit-Wert (sint16) im Dem-Puffer abzubilden.
    • Schwellwertgrenzen (FailedThreshold > 0, PassedThreshold < 0) erzwingen zwingend eine Nulldurchgangs- bzw. Referenzlogik um 0.
  • Klassenbasierte Wiederverwendbarkeit:
    • Durch die Auslagerung in DemDebounceCounterBasedClass (Mult. bis 65535) können identische Entprellprofile per Referenz (DemDebounceAlgorithmClass) von hunderten DemEventParameter-Instanzen geteilt werden. Dies spart Flash-ROM bei den BSW-Konfigurationstabellen.
  • NvM-Kopplung bei Storage = TRUE:
    • Wenn DemDebounceCounterStorage = true, muss der Dem-Stack NvM-RAM-Spiegelblöcke bereitstellen und den Zähler im Shutdown-Pfad (Dem_Shutdown) sichern sowie bei Dem_Init restaurieren.
  • FDC-Mapping für UDS-Service 0x19 0x14 / 0x02:
    • Der interne sint16-Zähler muss linear auf den normierten Wertebereich des UDS Fault Detection Counter (sint8: -128 .. +127) skaliert werden:
      • FailedThreshold bildet auf +127 ab.
      • PassedThreshold bildet auf -128 ab.
      • Wert 0 bildet auf FDC 0 ab.
