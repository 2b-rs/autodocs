1. Diagrammtyp & Architektur-Kontext

Informelles Datenfluss- und Prozessdiagramm (Werkzeug- und Artefaktarchitektur) im Kontext der AUTOSAR Classic Platform (Generic Structure Template). Das Diagramm veranschaulicht die Rollen- und Datenflüsse zwischen AUTOSAR-Standardvorgaben, modulspezifischen Implementierungserweiterungen, Konfigurationswerkzeugen und Generatoren. Es teilt den Gesamtprozess vertikal entlang einer Trennlinie in zwei primäre Phasen: die Modulkonfiguration („module configuration“) und die Modulgenerierung („module generation“).

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm unterscheidet Entitäten anhand eines Farbcodes in drei Bereitstellungskategorien:

  • Provided by AUTOSAR (Hellblau):
    • Schema Configuration Parameter Template: XML-Schema zur Definition der Parameterstruktur.
    • XML Standardized Configuration Parameter Definition: Standardisierte Konfigurationsparameter-Definition gemäß AUTOSAR-Vorgabe.
    • Schema ECU Configuration Template: XML-Schema für die eigentliche Steuergerätekonfigurationsbeschreibung.
    • Schema: Allgemeines XML-Schema für das Modul-Manifest.
  • Provided by Implementer (Mittelblau):
    • XML Configuration Parameter Definition: Modulspezifische Parameterdefinitionen des BSW-Implementierers (als Dokumentstapel dargestellt).
    • Generic ECU Configuration Editor: Werkzeug/Prozess für die Konfigurationserfassung.
    • Manifest: Schnittstellen- und Abhängigkeitsbeschreibung des Moduls.
    • Dedicated Module Generator: Modulspezifischer Code- bzw. Artefaktgenerator.
    • Build-Tool: Nachgelagertes Build-System zur Kompilierung/Einbindung.
    • Autoscar Integrator: Akteur/Rolle, die die Konfiguration editiert („edit“).
  • Automatically generated (Gelb/Orange):
    • XML ECU Configuration Description: Generierte bzw. persistierte Instanz der Steuergerätekonfigurationsbeschreibung.
    • Dedicated BSW Module: Generierter Code bzw. Artefakte des spezifischen Basissoftware-Moduls.

Schnittstellen und Beziehungen:

  • Konformitätsbeziehungen (conforms to, gestrichelte Pfeile):
    • XML Configuration Parameter Definition konform zu Schema Configuration Parameter Template und zu XML Standardized Configuration Parameter Definition.
    • XML ECU Configuration Description konform zu Schema ECU Configuration Template und referenziert/konform zu XML Configuration Parameter Definition.
    • Manifest konform zu Schema.
  • Daten- und Kontrollflüsse (durchgezogene Pfeile):
    • XML Configuration Parameter Definition dient als Eingabe für den Generic ECU Configuration Editor.
    • Autosar Integrator bedient den Generic ECU Configuration Editor („edit“).
    • Generic ECU Configuration Editor erzeugt/aktualisiert die XML ECU Configuration Description (und liest diese bidirektional/zyklisch ein).
    • XML ECU Configuration Description wird an den Dedicated Module Generator übergeben.
    • Dedicated Module Generator wird beschrieben durch das Manifest („described by“).
    • Manifest dient als Eingabe für das Build-Tool.
    • Dedicated Module Generator erzeugt das Dedicated BSW Module.

3. Dynamisches Verhalten & Sequenzablauf

Der Ablauf gliedert sich sequenziell in zwei Hauptphasen:

  1. Module Configuration:
    • Der BSW-Implementierer liefert die XML Configuration Parameter Definition auf Basis des standardisierten Templates (Schema Configuration Parameter Template und XML Standardized Configuration Parameter Definition).
    • Der Autosar Integrator öffnet den Generic ECU Configuration Editor, der durch die Parameterschablone parametriert wird.
    • Der Integrator editiert die modulspezifischen Parameterwerte; der Editor persistiert die XML ECU Configuration Description, welche wiederum gegen das Schema ECU Configuration Template validiert.
  2. Module Generation:
    • Die erzeugte XML ECU Configuration Description wird an den modulspezifischen Dedicated Module Generator übergeben.
    • Der Generator erzeugt basierend auf den Konfigurationswerten das finale Zielartefakt Dedicated BSW Module (Quellcode/Header).
    • Das begleitende Manifest beschreibt den Generator (described by) und steuert das nachgelagerte Build-Tool für die Gesamtintegration.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm besitzt methodischen und architektonischen Leitfadencharakter für die Werkzeugkette und Modulentwicklung nach AUTOSAR. Es stellt sicher, dass generische Konfigurationseditoren strikt von modulspezifischen Generatoren getrennt betrieben werden können, indem standardisierte XML-Metamodelle und Schemata als Vermittlungsschicht fungieren. Entwickler und Tool-Hersteller müssen gewährleisten, dass modulspezifische Parameterdefinitionen vollständig kompatibel zu den standardisierten Definitionen bleiben und Instanzbeschreibungen stets den definierten XML-Schemata genügen. Generatoren dürfen ausschließlich auf die standardkonforme XML ECU Configuration Description und ihre eigenen Schnittstellenbeschreibungen (Manifest) zugreifen.
