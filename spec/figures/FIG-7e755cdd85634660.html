1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Sequenzdiagramm mit kombinierten Fragmenten (loop, alt, opt).
  • Architektur-Kontext: AUTOSAR Classic Platform (R22-11), Spezifikation des ECU State Manager (EcuM).
  • Technischer Zweck: Darstellung der deterministischen Shutdown-Phase OffPreOS auf dem designierten Master Core im Multicore-Betrieb. Es regelt das Ausführen von Integrationscode, die Deinitialisierung aller BswM-Instanzen, das Stilllegen des BSW-Schedulers, die konfigurierbare Wakeup-Ermittlung (validiert vs. anstehend), die bedingte Anpassung des Shutdown-Ziels, die Core-Synchronisation via OS-Events und den synchronisierten Multicore-Shutdown nach Rücksetzen des Shutdown-Flags.

2. Komponenten, Entitäten & Schnittstellen

  • Akteure / Module (Lifelines):
    • «module» EcuM: ECU State Manager (Master-Core-Instanz), steuert die Shutdown-Sequenz.
    • Integration Code: Anwenderspezifischer Integrations- und Callout-Code.
    • «module» BswM: Basic Software Mode Manager (unterstützt mehrere Instanzen pro Core).
    • «module» SchM: Basic Software Scheduler (RTE-Schicht).
    • «module» McOs: Multicore AUTOSAR Operating System.
  • Schnittstellen / APIs & Interaktionen:
    • GetCoreID(CoreIdType): OS-Systemaufruf zur Identifikation des Master Cores.
    • EcuM_OnGoOffOne(): Integrations-Callout zur Ausführung nutzerspezifischer Shutdown-Aktionen.
    • BswM_Deinit(): Synchrone Deinitialisierung der BswM-Instanzen.
    • SchM_Deinit(): Synchrone Deinitialisierung des BSW-Schedulers.
    • EcuM_GetValidatedWakeupEvents(EcuM_WakeupSourceType): EcuM-interne Abfrage bereits validierter Wakeup-Events.
    • EcuM_GetPendingWakeupEvents(EcuM_WakeupSourceType): EcuM-interne Abfrage noch anstehender Wakeup-Events.
    • EcuM_SelectShutdownTarget(Std_ReturnType, EcuM_ShutdownTargetType, EcuM_ShutdownModeType): EcuM-Aufruf zur Neufestlegung des Shutdown-Ziels.
    • WaitEvent(Mask): OS-Service zur Synchronisation und zum Warten auf Ereignisse anderer Cores.
    • Unset the shutdown flag: Rücksetzen des Shutdown-Flags vor dem OS-Stopp.
    • ShutdownAllCores(StatusType): OS-Systemservice zum koordinierten Herunterfahren aller Cores.

3. Dynamisches Verhalten & Sequenzablauf

  1. Core-Validierung: EcuM ruft synchron GetCoreID() beim McOs auf, um die Ausführung auf dem Master Core sicherzustellen.
  2. Integrations-Callout: EcuM ruft EcuM_OnGoOffOne() im Integration Code auf, um nutzerspezifische Shutdown-Aktionen auszuführen.
  3. BSW-Modusverwaltung terminieren (loop over every BswM running in this core): EcuM iteriert über alle auf diesem Core ausgeführten BswM-Instanzen und ruft jeweils BswM_Deinit() auf.
  4. BSW-Scheduling stoppen: EcuM ruft synchron SchM_Deinit() auf, um zyklische BSW-Abläufe und RTE-Scheduling einzustellen.
  5. Konfigurierbare Wakeup-Ermittlung (alt):
    • Zweig [EcuMIgnoreWakeupEvValOffPreOS is TRUE]: EcuM ruft per Self-Call EcuM_GetValidatedWakeupEvents() auf, um ausschließlich validierte Wakeup-Ereignisse abzufragen.
    • Zweig [EcuMIgnoreWakeupEvValOffPreOS is FALSE]: EcuM ruft per Self-Call EcuM_GetPendingWakeupEvents() auf, um alle anstehenden Wakeup-Ereignisse abzufragen.
  6. Bedingte Modusanpassung (opt Pending wakeup events?):
    • Bedingung: Relevante Wakeup-Ereignisse liegen vor.
    • Aktion: EcuM ruft EcuM_SelectShutdownTarget() auf, um das Shutdown-Ziel neu festzulegen.
  7. Core-Synchronisation (loop FOR all configured cores): EcuM wartet über WaitEvent(Mask) an McOs für alle konfigurierten Cores auf deren Abschluss der Shutdown-Vorbereitungen.
  8. Shutdown-Flag zurücksetzen: EcuM setzt das interne Shutdown-Flag zurück (Unset the shutdown flag).
  9. OS-Multicore-Shutdown: EcuM ruft ShutdownAllCores(StatusType) am McOs auf, um alle Cores synchron herunterzufahren.

4. Normative Relevanz & Entwickler-Hinweise

  • Wakeup-Validierungsstrategie: Über den Konfigurationsparameter EcuMIgnoreWakeupEvValOffPreOS kann gesteuert werden, ob im OffPreOS-Zustand nur bereits validierte Wakeup-Events (EcuM_GetValidatedWakeupEvents) oder auch unvalidierte anstehende Events (EcuM_GetPendingWakeupEvents) das Shutdown-Ziel modifizieren dürfen. Dies verhindert ungewollte Shutdown-Abbrüche durch transiente Störimpulse.
  • Multicore-Koordination & Synchronisation: Die Synchronisation mit den Slave-Cores erfolgt deterministisch über die OS-Event-Schleife (loop FOR all configured cores), bevor das Shutdown-Flag gelöscht und der globale Core-Stopp eingeleitet wird.
  • Modularität: Mehrere BswM-Partitionen auf dem Master Core werden sequenziell heruntergefahren, ergänzt durch benutzerdefinierte Hooks im Integration Code.
