1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm zur Definition des AUTOSAR ECU Configuration Parameter Metamodells (ECUC Parameter Definition).
  • Technischer Zweck: Spezifikation der Konfigurationsstruktur für die Ereignisklasse (DemEventClass) innerhalb des Diagnostic Event Managers (DEM, BSW-Modul der System Services Schicht) gemäß Release R2.1.20.
  • Architektur-Einordnung: Bündelt alle funktionalen, zeitlichen und speicherrelevanten Attribute, die einem oder mehreren Diagnose-Events (DemEventParameter) zur Fehlerqualifizierung, Speicherung, Entprellung, Heilung und Anzeige zugeordnet werden.

2. Komponenten, Entitäten & Schnittstellen

  • Dem : ModuleDef [0..1]
    • Aggregiert via +container: DemGeneral : ParamConfContainerDef [1..1]
      • Aggregiert via +subContainer: DemEventParameter : ParamConfContainerDef [0..65535]
        • Aggregiert via +subContainer: DemEventClass : ParamConfContainerDef [1..1]
Parameter von DemEventClass (+parameter)
  • DemEventPriority : IntegerParamDef [min=0, max=255]: Priorität des Diagnose-Events zur Verdrängungssteuerung im Fehlerspeicher bei vollem Puffer.
  • DemOperationCycle : IntegerParamDef [min=0, max=255]: Referenzierte Betriebszyklus-ID (z. B. Ignition ON/OFF, Driving Cycle) für Qualifizierung und Alterung.
  • DemHealingCycle : IntegerParamDef [min=0, max=255]: ID des Zyklus, der für das Entprellen/Rücksetzen (Healing) des Fehlers herangezogen wird.
  • DemHealingAllowed : BooleanParamDef [true/false]: Schaltet den Heilungsmechanismus für dieses Event frei bzw. sperrt ihn.
  • DemHealingCycleCounter : IntegerParamDef [0..1, min=1, max=256]: Anzahl fehlerfreier Zyklen bis zum Erlöschen der Warnanzeige bzw. Rücksetzen des Fehlerstatus.
  • DemEventDestination : IntegerParamDef [min=0, max=7]: Bitmaske/ID des Ziel-Fehlerspeichers (z. B. Primary Memory, Secondary Memory, Mirror Memory).
  • DemPredebounceAlgorithm : IntegerParamDef [min=0, max=3]: Auswahl des Entprellalgorithmus (z. B. 0: Keine/Extern, 1: Zählerbasiert, 2: Zeitbasiert, etc.).
  • DemFFPrestorageSupported : BooleanParamDef [true/false]: Aktiviert Freeze-Frame-Prestorage (Zwischenspeicherung der Umgebungsdaten vor endgültiger Fehlerqualifizierung).
  • DemEnableConditionID : IntegerParamDef [0..1, min=0, max=65535]: Bindeglied zu den Freigabebedingungen (Enable Conditions) des Dem.
  • DemEnableConditionStatus : IntegerParamDef [0..1, min=0, max=255]: Erforderlicher logischer Status der Freigabebedingung für die Ereignisauswertung.

3. Dynamisches Verhalten & Sequenzablauf (falls zutreffend)

Als statisches Metamodell für Konfigurationsparameter definiert das Diagramm keinen sequenziellen Kontrollfluss. Die Parameter determinieren jedoch direkt folgende Zustandsübergänge im DEM-Laufzeitmodul:

  1. Freigabeprüfung: Vor der Entprellung wird DemEnableConditionStatus gegen den aktiven Zustand von DemEnableConditionID evaluiert; bei Inaktivität wird das Event verworfen.
  2. Entprellung & Prestorage:
    • Meldet die SWC/BSW via Dem_SetEventStatus einen unqualifizierten Status (DEM_EVENT_STATUS_PREFAILED), wird bei DemFFPrestorageSupported == TRUE ein Zwischenspeicherpuffer angelegt.
    • DemPredebounceAlgorithm steuert die schrittweise Qualifikation zu DEM_EVENT_STATUS_FAILED.
  3. Speicherallokation: Bei bestandenem Fehlereintrag steuert DemEventDestination die Ablage; bei Speicherüberlauf entscheidet DemEventPriority über Verdrängung älterer/niedriger priorisierter DTCs.
  4. Indikatoransteuerung: Über DemIndicatorAttributeList wird das Bit DEM_UDS_STATUS_WIR (WarningIndicatorRequested) gesetzt und der durch DemLinkedIndicator referenzierte Indikator mit dem Muster aus DemIndicatorBehaviour angesteuert.
  5. Heilungsprozess: Erfolgen über die Anzahl DemHealingCycleCounter aufeinanderfolgende Zyklen (DemHealingCycle) ausschließlich PASSED-Meldungen, wird die Warnanzeige deaktiviert.

4. Normative Relevanz & Entwickler-Hinweise

  • Release-Besonderheit (R2.1.20 vs. R4.x):
    • In R2.1 ist DemEventClass direkt als 1:1-Subcontainer unterhalb von DemEventParameter eingehängt. Dies verhindert eine speichereffiziente Mehrfachverwendung (M:N-Referenzierung) identischer Event-Klassen über mehrere Events hinweg, wie sie in späteren AUTOSAR-Releases (ab R3/R4) üblich ist.
    • Algorithmen (DemPredebounceAlgorithm) und Zielspeicher (DemEventDestination) sind noch als flache Integer-ParamDefs (0..3 bzw. 0..7) typisiert anstelle von strukturierten Enum-/Choice-Containern mit parametrierbaren Schwellen (z. B. Counter Increment/Decrement Steps).
  • Code-Generierung (BSW-Stack):
    • Aus diesen Parametern generiert der Dem-Generator konstante ROM-Konfigurationstabellen (Dem_EventClassTable[], Dem_IndicatorAttributeTable[]).
    • DemEventPriority (0..255) erfordert vom Entwickler eine ECU-weite Harmonisierung, um Deadlocks bzw. unabsichtliches Verdrängen sicherheitskritischer Ereignisse zu vermeiden.
  • Applikations- & SWC-Integration:
    • Wenn DemFFPrestorageSupported == FALSE, führt ein Aufruf von Dem_PrestoreFreezeFrame() im RTE-/SWC-Code zu Fehlern (DEM_E_PRESTORE_NOT_SUPPORTED / DET).
    • Die Verknüpfung via DemLinkedIndicator bedingt, dass alle referenzierten DemIndicator-Instanzen global im Modul konsistent definiert sind.
