1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Sequenzdiagramm (Interaktionsdiagramm).
  • Architektur-Kontext: AUTOSAR Classic Platform, Microcontroller Abstraction Layer (MCAL), Modul Ocu (Output Compare Unit Driver, SWS_OCUDriver).
  • Technischer Zweck: Spezifikation des Zusammenspiels zwischen dem Aufrufer (Ocu user), dem MCAL-Treiber (Ocu) und der zugrundeliegenden Peripheriehardware («Peripheral» Ocu pin) zur Konfiguration einer autonomen HW-Pin-Aktion bei Erreichen eines definierten Zähler-/Vergleichswertes (Compare Match).

2. Komponenten, Entitäten & Schnittstellen

  • Beteiligte Instanzen (Lifelines):
    • Ocu user: Höhere Schicht (z. B. Complex Device Driver CDD, IoHwAb oder SWC via RTE), die OCU-Kanäle zur Zeitsteuerung nutzt.
    • «module» Ocu: MCAL-Treibermodul gemäß AUTOSAR-Standard.
    • «Peripheral» Ocu pin: Physikalischer Mikrocontroller-Ausgangs-Pin bzw. hardwareseitige Capture/Compare-Einheit (Timer-Peripherie).
  • Schnittstellen & Parameter:
    • Ocu_SetPinAction(Ocu_ChannelType ChannelNumber, Ocu_PinActionType PinAction):
      • ChannelNumber: Numerischer Bezeichner des logischen OCU-Kanals.
      • PinAction: Enum vom Typ Ocu_PinActionType (Werte: OCU_SET_HIGH, OCU_SET_LOW, OCU_TOGGLE, OCU_DISABLE).
    • HW-Interaktion Set Pin Action: Treiberspezifischer Registerzugriff auf die Steuerregister der Timer-/Compare-Peripherie (z. B. Konfiguration des Action-/Output-Control-Registers).

3. Dynamisches Verhalten & Sequenzablauf

  1. Synchroner API-Aufruf: Ocu user ruft synchron Ocu_SetPinAction(ChannelNumber, PinAction) auf.
  2. Hardware-Parametrierung: Das Modul Ocu schreibt die geforderte Pin-Aktion direkt in die Peripherieregister der zugeordneten Hardware-Einheit (Set Pin Action).
  3. Synchroner Rücksprung: Ocu_SetPinAction kehrt zum Aufrufer zurück (void). Der Pin-Zustand wird zu diesem Zeitpunkt softwareseitig nicht unmittelbar verändert.
  4. Asynchrone Hardware-Ausführung (Entkopplung):
    • Das Ereignis „Compare Match“ tritt rein hardwaregesteuert ein (Vergleichswert des Timer-Registers erreicht den Schwellwert).
    • Die Peripherie schaltet den Signalpegel (Pin level changed only upon compare match by HW) autonom, jitterfrei und ohne CPU-/ISR-Latenz auf den zuvor parametrierten Zustand.

4. Normative Relevanz & Entwickler-Hinweise

  • Pre-Compile-Konfiguration: Die Verfügbarkeit dieser Funktion ist an den Konfigurationsparameter OcuSetPinActionApi == TRUE gebunden. Ist der Parameter auf FALSE konfiguriert, darf das API nicht einkompiliert werden.
  • Kanal-Pin-Zuordnung: Nur Kanäle, die hardwareseitig mit einem externen Pin verknüpft sind (OcuChannelPinUsed == TRUE), dürfen für Ocu_SetPinAction verwendet werden; andernfalls ist ein DET-Fehler (OCU_E_PARAM_INVALID_CHANNEL bzw. OCU_E_PARAM_NO_PIN) zu werfen.
  • Keine Sofortwirkung: Die API dient ausschließlich der Vorbelegung der Schaltautomatik. Ein sofortiger Pegelwechsel erfolgt nicht über diese Funktion, sondern über dedizierte APIs (sofern hardware-/treiberseitig unterstützt) oder Port-Treiber (Port_SetPinMode / Dio).
  • Timing & Latenz: Da der Zustandswechsel direkt durch die Capture/Compare-Hardwareeinheit erfolgt, eignet sich dieses Verfahren für hochpräzise, echtzeitkritische Schaltvorgänge (z. B. Einspritzung, Zündung, Winkelbezogene PWM-Modulation), ohne den Interrupt-Controller oder die CPU zu belasten.
