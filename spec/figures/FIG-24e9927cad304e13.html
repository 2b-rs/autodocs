1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration Parameter Definition (ECUC-Metamodell / UML-Klassendiagramm der BSW-Konfigurationsstruktur).
  • Technischer Zweck: Statische Parametrisierung des zeitgesteuerten Frame-Empfangs (TTCAN nach ISO 11898-4) im CAN Interface (CanIf) und dessen Bindung an hardwarenahe Trigger des TTCAN-Treibers (CanDrv_TT).
  • Funktionale Einordnung: Kopplung zwischen der generischen PDU-Verwaltung der BSW-Abstraktionsschicht (CanIfRxPduCfg) und den hardwarebasierten Zeit- bzw. Mailbox-Triggern des MCAL-TTCAN-Treibers zur Gewährleistung deterministischer Empfangsfenster.

2. Komponenten, Entitäten & Schnittstellen

  • Konfigurationscontainer & Parameter (Metaklassen):
  • CanIfRxPduCfg (EcucParamConfContainerDef, Paket CanIf, Multiplizität 0..*):
  • Repräsentiert die Basiskonfiguration einer empfangenen CAN-PDU im CAN Interface.
  • CanIfTTRxFrameTriggering (EcucParamConfContainerDef, Multiplizität 0..1):
  • Subcontainer (+subContainer) unterhalb von CanIfRxPduCfg. Kapselt alle TTCAN-spezifischen Empfangsparameter für zeitgesteuerte Frames.
  • CanTTRxJoblistTimeMark (EcucIntegerParamDef, Multiplizität 0..1):
  • Parameter (+parameter) innerhalb von CanIfTTRxFrameTriggering.
  • Wertebereich: 0 bis 0xFFFF (16-Bit-Zeitmarke). Definiert die relative Zykluszeit/NTU innerhalb der TTCAN-Matrix, zu der die PDU verarbeitet bzw. in der Jobliste getriggert wird.
  • CanIfTTRxHwObjectTriggerIdRef (EcucReferenceDef):
  • Referenz-Element (+reference) innerhalb von CanIfTTRxFrameTriggering.
  • CanTTHardwareObjectTrigger (EcucParamConfContainerDef, Paket CanDrv_TT, Multiplizität 0..*):
  • Zielcontainer (+destination) im TTCAN-Treiber, der ein hardwarespezifisches Empfangs-Mailbox-/Trigger-Objekt abbildet.
  • CanTTHardwareObjectTriggerId (EcucIntegerParamDef, Paket CanDrv_TT):
  • Parameter (+parameter) in CanTTHardwareObjectTrigger.
  • Wertebereich: 0 bis 63 (symbolicNameValue = true). Eindeutiger Hardware-Trigger-Index (maximal 64 Triggerobjekte) des TTCAN-Controllers.
  • Beziehungen & Kardinalitäten:
  • CanIfRxPduCfg ──(1 : 0..1, Komposition)──> CanIfTTRxFrameTriggering: Eine Standard-Rx-PDU kann optional für TTCAN-Empfangstriggerung erweitert werden.
  • CanIfTTRxFrameTriggering ──(1 : 0..1, Komposition)──> CanTTRxJoblistTimeMark: Optionale Zuweisung einer diskreten Zeitmarke.
  • CanIfTTRxFrameTriggering ──(1 : 1, Komposition)──> CanIfTTRxHwObjectTriggerIdRef: Obligatorische Kapselung der Querverweis-Definition.
  • CanIfTTRxHwObjectTriggerIdRef ──(Assoziation / +destination)──> CanTTHardwareObjectTrigger: Unidirektionale typisierte Referenz vom CanIf in das Modul CanDrv_TT.
  • CanTTHardwareObjectTrigger ──(1 : 1, Komposition)──> CanTTHardwareObjectTriggerId: Jeder Trigger im Treiber besitzt genau eine symbolische Hardware-Trigger-ID.

3. Dynamisches Verhalten & Sequenzablauf

  • Generierungszeitpunkt (Post-Build / Pre-Compile):
  • Der BSW-Konfigurator generiert aus den referenzierten Strukturen Lookup-Tabellen (z. B. CanIf_TTRxPduConfig[]), die den Hardware-Trigger-IDs (0..63) direkte PDU-Handles (PduIdType) zuordnen.
  • Laufzeit-Empfangspfad (TTCAN-Matrixzyklus):
  1. Hardware-Trigger: Der TTCAN-Controller erreicht im Basic Cycle das konfigurierte Empfangsfenster (Time Window) für das via CanTTHardwareObjectTriggerId definierte Hardware-Objekt.
  2. Treiber-Ebene (CanDrv_TT): Nach Empfang des Frames oder bei Auslösen des Time-Marks generiert der Controller einen Interrupt oder setzt ein Status-Flag.
  3. Indication / Joblist: Über die Zeitmarke CanTTRxJoblistTimeMark synchronisiert das CAN Interface die Entnahme/Verarbeitung der Daten.
  4. PDU-Weiterleitung: Das CAN Interface mappt das ausgelöste Hardware-Trigger-Objekt auf die konfigurierte CanIfRxPduId und übergibt die PDU synchron an die oberen Schichten (z. B. PduR_CanIfRxIndication oder Com_RxIndication).

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationsabhängigkeiten (ECUC_CanIf_00128):
  • Modulübergreifende Konsistenz: Der Link CanIfTTRxHwObjectTriggerIdRef erfordert zwingend eine gültige Ziel-Instanz in CanDrv_TT. Ein Fehlen führt zu einem Validierungsfehler im Codegenerator (Dangling Reference).
  • Multiplizität 0..1 von CanIfTTRxFrameTriggering erzwingt, dass eine Rx-PDU entweder zeitgesteuert (TTCAN) oder rein eventbasiert (Standard-CAN) konfiguriert wird; Mischbetrieb pro PDU ist unzulässig.
  • Ressourcenrestriktionen auf Controller-Ebene:
  • Der Wertebereich 0..63 für CanTTHardwareObjectTriggerId spiegelt die maximale Anzahl physischer Trigger-Register/Objekte typischer TTCAN-IPs (z. B. Bosch TTCAN Core nach ISO 11898-4) wider.
  • Treiber- & Stack-Implementierung:
  • Durch symbolicNameValue = true muss der Treiber-Generator lesbare Makros/Enums für die Trigger-IDs bereitstellen, um harte Index-Kopplungen im Quellcode zu vermeiden.
  • Das Vorhandensein von CanTTRxJoblistTimeMark beeinflusst die Dimensionierung und Zeitbasis interner Joblisten/Timer-Interrupts im TTCAN-Interface.
