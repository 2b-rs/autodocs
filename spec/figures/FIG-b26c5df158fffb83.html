1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU-Konfigurations-Metamodell (UML-Klassendiagramm / ECUC Parameter Definition Model gemäß AUTOSAR BSW-Konfigurationsstandard).
  • Kontext & Zweck: Spezifiziert die Konfigurationsstruktur des Moduls TcpIp (Classic Platform BSW) für die Internet Key Exchange (IKEv2) Protokollinstanz im Rahmen von IPsec. Es definiert die globalen Zeit-, Port-, Retransmissions- und Fragmentierungs-Parameter für IKE-Verbindungen sowie das Aggregationsverhältnis zur individuellen Verbindungskonfiguration (IKEConnection).

2. Komponenten, Entitäten & Schnittstellen

  • Übergeordneter Container:
    • IKEConnections (EcucParamConfContainerDef): Zentraler BSW-Konfigurationscontainer für IKE-Sitzungsparameter.
  • Aggregierte Parameter (+parameter, Komposition):
    • IKEMaxNumFragments (EcucIntegerParamDef): Maximale Anzahl an IKE-Nachrichtenfragmenten (RFC 7383). Bereich: [1, 10], Default: 3.
    • IKEFragmentSize (EcucIntegerParamDef): Maximale Nutzdatenlänge eines IKE-Fragments in Byte zur Vermeidung von IPv4/IPv6-Path-MTU-Fragmentierung. Bereich: [576, 4096], Default: 1280 Byte.
    • IKERetransmitTries (EcucIntegerParamDef): Maximale Anzahl an Wiederholungsversuchen vor Verbindungsabbruch. Bereich: [0, 255], Default: 10.
    • IKELocalPort (EcucIntegerParamDef): Lokaler UDP-Port für IKEv2-Kommunikation. Bereich: [0, 65535], Default: 500 (Standard IKE-Port; Port 4500 wird üblicherweise bei NAT-Traversal dynamisch/separat adressiert).
    • IKERetransmitBase (EcucFloatParamDef): Multiplikativer Faktor für das exponentielle Backoff-Verhalten der Retransmissionszeit. Bereich: [1.0, 2.0], Default: 1.3.
    • IKERetransmitTimeout (EcucFloatParamDef): Initiales Timeout in Sekunden für IKE-Anfrage-Wiederholungen. Bereich: [1.0, 60.0], Default: 1.5\,s.
    • IKEReassemblingTimeout (EcucFloatParamDef): Maximales Zeitfenster in Sekunden für das Eintreffen aller Fragmente einer fragmentierten IKE-Nachricht. Bereich: [0.1, 60.0], Default: 0.5\,s.
    • IKEConnectionTimeout (EcucFloatParamDef): Gesamttimeout in Sekunden für den erfolgreichen Aufbau bzw. Erhalt einer IKE-Verbindung. Bereich: [1.0, 60.0], Default: 30.0\,s.
  • Aggregierter Sub-Container (+subContainer, Komposition):
    • IKEConnection (EcucParamConfContainerDef): Instanzspezifische Verbindungskonfiguration (Multiplizität: $1..\ast$). Mindestens ein Verbindungsprofil muss konfiguriert sein.

3. Dynamisches Verhalten & Sequenzablauf

Als statisches ECUC-Metamodell zeigt das Diagramm keine Laufzeitsequenzen; die Parameter determinieren jedoch das dynamische Verhalten der IKEv2-Zustandsmaschine im TcpIp-Stack:

  • IKE-SA-Aushandlung & Re-Transmission:
    • Das Aussenden von IKE-Paketen (z. B. IKE_SA_INIT, IKE_AUTH) startet einen Retransmissions-Timer mit T_0 = IKERetransmitTimeout.
    • Bleibt die Gegenstellen-Antwort aus, erfolgt die Neuübertragung mit exponentiellem Backoff: T_n = T_n-1 · IKERetransmitBase bis maximal IKERetransmitTries Versuche erreicht sind.
  • Fragmentierung / Reassembly:
    • Überschreitet eine IKE-Nachricht IKEFragmentSize, teilt der Stack diese in maximal IKEMaxNumFragments Fragmente.
    • Beim Empfang fragmentierter Pakete startet der Timer IKEReassemblingTimeout. Läuft dieser vor Eingang aller Fragmente ab, werden die Fragmente verworfen.
  • Verbindungsabbruch & Fehlerpfad:
    • Wird die IKE-SA nicht innerhalb von IKEConnectionTimeout vollständig etabliert oder schlägt die maximale Re-Transmission fehl, bricht der Stack den Verbindungsaufbau ab und meldet den Zustand an das Security Management bzw. erzeugt einen Det/Dem-Fehlereintrag (z. B. TCPIP_E_IKE_TIMEOUT je nach Stack-Implementierung).

4. Normative Relevanz & Entwickler-Hinweise

  • Speicherallokation (RAM/ROM-Footprint):
    • IKEMaxNumFragments und IKEFragmentSize bestimmen direkt die statisch zu reservierende Puffergröße für den Reassembly-Buffer im RAM: $\text{RAM}_{\text{Buffer}} \ge \text{IKEMaxNumFragments} \times \text{IKEFragmentSize}. Ein Default von3 \times 1280\,\text{Byte} = 3840\,\text{Byte}$ muss pro gleichzeitig aktivem Reassembly-Pfad vorgehalten werden.
  • IP-Fragmentierungs-Vermeidung:
    • Der Default IKEFragmentSize = 1280 korrespondiert mit der IPv6 Minimum MTU (RFC 8200). Im IPv4-Betrieb kann für Netzwerke mit kleinerer MTU eine Absenkung bis auf 576 erforderlich sein, um Fragmentierung auf IP-Ebene strikt zu verhindern.
  • Echtzeit- und Timer-Granularität:
    • Fließkommawerte (EcucFloatParamDef) mit Subsekunden-Auflösung (z. B. IKEReassemblingTimeout = 0.5s, IKERetransmitBase = 1.3) bedingen, dass die zyklische Task TcpIp_MainFunction() bzw. der interne IKE-Timer mit ausreichender Taktung (typischerweise 10\,ms bis 100\,ms) aufgerufen wird.
    • Fließkommazahlen werden vom Codegenerator je nach MCU-Architektur in Fixed-Point-Ticks oder ganzzahlige Millisekunden-Werte überführt.
  • Multiplizitätsrestriktion:
    • Da IKEConnection die Multiplizität $1..\ast$ besitzt, kann das IKE-Modul nicht aktiv konfiguriert werden, ohne mindestens eine Peer-Beziehung (IKEConnection) zu instanziieren.
