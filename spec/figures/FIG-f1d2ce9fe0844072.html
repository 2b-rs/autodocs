1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm zur Spezifikation der FlexRay-Frame-Struktur im Metamodell des AUTOSAR-System-Templates (AUTOSAR_SystemTemplate). Das Diagramm verortet die bus-spezifische Spezialisierung FlexrayFrame innerhalb des allgemeinen Kommunikations- und Timing-Modells für Frames (Identifiable, Frame, Timing).

2. Komponenten, Entitäten & Schnittstellen

Das Metamodell definiert folgende Entitäten und Beziehungen:

  • Identifiable: Abstrakte Vorfahr-Klasse, von der Frame erbt.
  • Frame: Basisklasse für Datenübertragungsrahmen auf Kommunikationsebene.
  • Attribute:
  • frameID: Int [0..1]
  • frameLength: Int
  • minimumDelayTime: Float [0..1]
  • Komposition: Besitzt über die gerichtete Kompositionsbeziehung +frameTiming 0 bis n (*) Instanzen von Timing (Multiplizität auf Elternseite: 0..1).
  • FlexrayFrame: Spezifische Unterklasse, erbt via Generalisierung von Frame. Besitzt im Diagramm keine eigenen lokalen Attribute.
  • Timing: Basisklasse zur Festlegung des Sende- und Zeitverhaltens.
  • AbsolutelyScheduledTiming: Spezialisierung von Timing (Generalisierung) zur deterministischen zeitgesteuerten Übertragung.
  • Attribute:
  • BaseCycle: Int
  • CycleRepetition: Enumeration{1, 2, 4, 8, 16, 32, 64}
  • slotID: Int

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm stellt eine statische Metamodellstruktur dar; es beschreibt kein dynamisches Sequenz- oder Protokollablaufdiagramm. Das resultierende dynamische Übertragungsverhalten wird über die Attribute von AbsolutelyScheduledTiming modelliert: Ein FlexrayFrame wird in einem festen Kommunikationszyklus auf Basis von slotID, BaseCycle (Startzyklus) und CycleRepetition (Wiederholrate als Zweierpotenz von 1 bis 64) deterministisch eingeplant und versendet. minimumDelayTime definiert den zeitlichen Mindestabstand zwischen aufeinanderfolgenden Übertragungen.

4. Normative Relevanz & Entwickler-Hinweise

Normativ relevant für die Systembeschreibung, Cluster-Konfiguration und Frame-Planung von FlexRay-Netzwerken in AUTOSAR:

  • FlexrayFrame übernimmt die Eigenschaften der allgemeinen Frame-Definition.
  • Ein Frame muss eine ganzzahlige Länge (frameLength) besitzen; frameID und minimumDelayTime sind optional (0..1).
  • Das Timing eines Frames wird über aggregierte Timing-Elemente beschrieben. Für FlexRay ist hierbei AbsolutelyScheduledTiming maßgeblich, wodurch Slot-Zuweisung (slotID) sowie zyklische Wiederholungen (CycleRepetition beschränkt auf Potenzen von 1 bis 64) standardisiert werden.
  • Generatoren und BSW-Konfiguratoren für den FlexRay-Kommunikationsstack (z. B. Fr, FrIf) müssen diese Metamodelleigenschaften auswerten, um die Hardware-Slot-Tabellen und Sendezeitpunkte abzugleichen.
