1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Kontrollfluss- / High-Level-Zustands- und Ablaufdiagramm (Phasen- und Lebenszyklusmodell).
  • Architektur-Kontext: AUTOSAR Adaptive Platform (AP), Start- und Zustandsübergangssequenz (AP start-up sequence). Das Diagramm stellt das Bootstrapping vom OS-Boot bis zum Eintritt in das Execution Management (ara::exec) sowie die zyklische Verwaltung von Applikationen über Maschinen-Zustände (Machine State) dar.

2. Komponenten, Entitäten & Schnittstellen

  • Akteure & Komponenten:
    • OS Boot: Initialisierungsphase des zugrunde liegenden POSIX-Betriebssystems vor Übergabe an die Plattform.
    • Execution Management: Übergeordneter Systemdienst/Daemon-Rahmen (ara::exec), der die Ausführung, Zustandsverwaltung und Manifest-Auswertung kapselt.
    • Read (processed) Manifests: Konfigurationsaufnahme mit den expliziten Artefakten:
      • Machine Manifest: Spezifiziert maschinenspezifische Konfigurationen, Hardwareressourcen und Machine States.
      • Execution Manifest Instance(s): Spezifiziert prozess- und applikationsspezifische Start-, Abhängigkeits- und Zuordnungsregeln zu Funktionsgruppen/Zuständen.
    • Application(s): Instanziierte funktionale und plattforminterne Prozesse.
  • Schnittstellen & Relationen:
    • OS Boot -> Execution Management: Initialer Kontrollübergang nach Betriebssystemstart.
    • Read (processed) Manifests -> Start Application(s): Konfigurationsgesteuerte Initiierung von Applikationen.
    • Start Application(s) -> Enter Machine State -> Stop Application(s): Zustandsbezogener Lebenszyklusfluss.
    • Stop Application(s) -> Start Application(s): Zustandswechsel-Schleife (State Change).

3. Dynamisches Verhalten & Sequenzablauf

  1. OS Boot: Hardware-Initialisierung und Start des Host-Betriebssystems.
  2. Read (processed) Manifests: Das Execution Management liest das Machine Manifest sowie die Execution Manifest Instance(s) zur Ermittlung von Zustands- und Startkonfigurationen ein.
  3. Start Application(s): Aktivierung und Start der Prozesse, die für den anvisierten Maschinen-Zustand deklariert sind.
  4. Enter Machine State: Das System erreicht und bestätigt den definierten Maschinen-Zustand (Machine State).
  5. Stop Application(s): Beim Verlassen des Zustands bzw. Herunterfahren werden die nicht mehr erforderlichen Applikationen kontrolliert beendet.
  6. State Change: Über eine Transitions-Rückkopplung (State Change) erfolgt bei Zustandswechseln erneut der Übergang zu Start Application(s) zur Anpassung der aktiven Prozesse an den neuen Zustand.

4. Normative Relevanz & Entwickler-Hinweise

  • Zustandsgetriebener Prozess-Lebenszyklus: Der Start und das Stoppen von Applikationen ist fest an Machine State-Zustände und Zustandswechsel (State Change) gebunden.
  • Manifest-Granularität: Konfigurationsdaten sind strikt zwischen maschinenweiten Parametern (Machine Manifest) und instanziierten Applikationsanforderungen (Execution Manifest Instance(s)) getrennt.
  • Dynamische Rekonfiguration: Das Diagramm modelliert nicht nur die initiale Boot-Sequenz, sondern auch die operative Laufzeitphase mit Zustandswechseln und dynamischem Starten bzw. Stoppen von Applikationen.
