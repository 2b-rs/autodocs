1. Diagrammtyp & Architektur-Kontext

Methodik-Ablaufdiagramm (AUTOSAR Methodology Activity Flow) zur Erzeugung von A2L-Dateien für Mess- und Kalibrierwerkzeuge (MCD). Der Prozess zeigt den Pfad von steuergerätespezifischen Konfigurationsbeschreibungen und extrahierten Software-Zusammensetzungen über die Glättung (Flattening) der Softwarestruktur bis zur Generierung der A2L-Datei unter Zuhilfenahme von Symbol-/Adressinformationen aus der Executable-Map.

2. Komponenten, Entitäten & Schnittstellen

  • Aktivitäten / Prozessschritte (gelbe Blockpfeile):
  • Generate flat description of SW per ECU (ausführendes Werkzeug: AUTOSAR flattener).
  • Generate A2L (ausführendes Werkzeug: A2L Generator).
  • Werkzeuge (Lineal-Symbole, gestrichelt angebunden):
  • AUTOSAR flattener
  • A2L Generator
  • Artefakte / Work Products (blaue Dokument-Icons):
  • ECU Configuration Description (.XML)
  • ECU Software Composition : EcuSwComposition (.XML)
  • BSW-Module Description (.XML; Text unten abgeschnitten als BSW-Module ...)
  • Service Component (.XML; Text unten abgeschnitten)
  • ECU Extract of System Configuration : System (.XML)
  • ECU Extract of Top-Level Composition : CompositionType (.XML)
  • Component Type (.XML)
  • ECU flat description (.XML)
  • MCD Configuration Description (.XML)
  • Map of Executable (Linker-Mapdatei / Adresszuordnung)
  • A2L (ASAM MCD-2 MC Beschreibungsdatei)
  • Beziehungen & Kontroll-/Datenflüsse:
  • ECU Configuration Description dient als Eingangsartefakt für Generate flat description of SW per ECU.
  • Gestrichelte Pfeile referenzieren Teil- bzw. Unterstrukturen der Konfiguration: von ECU Configuration Description zu BSW-Module Description, ECU Software Composition : EcuSwComposition und ECU Extract of System Configuration : System.
  • Von ECU Extract of System Configuration : System führt eine gestrichelte Verfeinerung zu ECU Extract of Top-Level Composition : CompositionType, und von dort zu Component Type.
  • Pfeil von Service Component deutet auf ECU Software Composition : EcuSwComposition.
  • Generate flat description of SW per ECU erzeugt die ECU flat description (.XML).
  • Generate A2L nimmt als Eingänge die ECU flat description (.XML), die MCD Configuration Description (.XML) sowie die Map of Executable entgegen und generiert die finale A2L-Datei.

3. Dynamisches Verhalten & Sequenzablauf

  1. Bereitstellung der steuergerätespezifischen Ausgangsbeschreibungen (ECU Configuration Description zusammen mit den Software-Zusammensetzungen wie BSW-Modulen, Service Components und extrahierten System-/Top-Level-Kompositionen).
  2. Der AUTOSAR flattener verarbeitet die Konfiguration in der Aktivität Generate flat description of SW per ECU, um eine aufgelöste, flache Repräsentation der Softwareelemente je Steuergerät (ECU flat description) zu erzeugen.
  3. Der A2L Generator führt in der Aktivität Generate A2L die geglättete Softwarebeschreibung (ECU flat description) mit der MCD Configuration Description und den Adress-/Speicherortinformationen aus der Map of Executable zusammen.
  4. Als finaler Output der Kette wird die standardisierte A2L-Datei für Mess- und Kalibriersysteme exportiert.

4. Normative Relevanz & Entwickler-Hinweise

Die A2L-Generierung bildet eine zentrale Brücke zwischen der AUTOSAR-Methodik und den standardisierten ASAM MCD-2 MC Kalibrierwerkzeugen. Für Entwickler und Tool-Ketten ist normativ relevant, dass die Software-Zusammensetzung vor der A2L-Generierung durch den Flattener aufgelöst werden muss, da A2L flache Adressräume und Mess-/Verstellgrößenbezeichner erfordert. Zudem ist die Synchronisation mit dem Linker-Map-File zwingend erforderlich, um den logischen AUTOSAR-Parametern und -Signalen reale Speicheradressen des kompilierten Steuergeräte-Binaries zuzuordnen.
