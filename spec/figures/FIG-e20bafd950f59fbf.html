1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Tabellarische Spezifikations- und Metamodellierungsansicht (AUTOSAR MOD_AI Excel-Standardtemplate / Tabellenformat zur Definition von Applikationsschnittstellen).
  • Architektur-Kontext: Dient im Rahmen der AUTOSAR Application Interfaces (CP_EXP_AIUserGuide) zur hersteller- und domänenübergreifenden Standardisierung von VFB-Schnittstellen (Virtual Function Bus) auf Anwendungsebene (Body-Domain: Zentralverriegelung und Anhängererkennung).
  • Technischer Zweck: Spezifikation von Datenelementen für das MSR/ARXML-Metamodell vor der formellen Generierung von ARXML-Dateien (SENDER-RECEIVER-INTERFACE, VARIABLE-DATA-PROTOTYPE). Es definiert den Kommunikationsvertrag zwischen Software-Components (SWCs) bezüglich Namensgebung, Typisierung und Übertragungssemantik.

2. Komponenten, Entitäten & Schnittstellen

Dargestellt ist die Metamodell-Abbildung von Schnittstellen und ihren aggregierten Datenelementen:

  • Schnittstellen-Ebene (SenderReceiverInterface):
  • LockgFbReq1 (longName: LockingFeedbackRequest): Schnittstelle zur Anforderung von optischem/akustischem Blink-Feedback über Verriegelungszustände (unlocked, locked, safed).
  • Metadaten: Initiator WP: 10.1 (Work Package Body/Security), Milestone: S3MS4, Reference: CL (Central Locking).
  • TrlrSts1 (longName: TrailerStatus1): Schnittstelle zur Bereitstellung des Anhänger-Präsenzstatus (Schaltererkennung).
  • Metadaten: Initiator WP: ID/10.1, Milestone: S3MS4.
  • *Datenelement-Ebene (VariableDataPrototype aggregiert via Rolle dataElement [1..]):**
  • Sts (in LockgFbReq1):
  • Typ-Zuordnung: LockActvn1 («isOfType» ApplicationRecordDataType oder ApplicationPrimitiveDataType / ImplementationDataType).
  • TrlrSts (in TrlrSts1):
  • Typ-Zuordnung: Boolean (Standard AUTOSAR-Primitivtyp).
  • Wertebereichssemantik: 0 = not present, 1 = present.
  • Kommunikationsattribute:
  • Spalte Queuein[g]: Steuert die Pufferungssemantik (Non-Queued / datenorientiert vs. Queued / ereignisorientiert). Bei leeren Einträgen greift der Standard: Non-Queued Data Communication (Last-is-Best).
  • Horizontale Referenzen (Registerkarten):
  • 06_Interface_DataElements (aktuelle Sender/Receiver-Sicht).
  • 06_Interface_ClientServer (Synchrone/asynchrone Funktionsaufrufe über ClientServerInterface).
  • 07_DataTypes_Continuous (Physikalische Datentypen mit CompuMethod / Unit-Definitionen).

3. Dynamisches Verhalten & Sequenzablauf

  • Kommunikationsmuster: Asynchrones 1:n- oder n:1-Publish-Subscribe über den VFB bzw. die RTE.
  • Datenfluss (Non-Queued):
  • Sender-SWC: Schreibt zyklisch oder ereignisgesteuert via RTE (Rte_Write_<p>_<o>()).
  • RTE/COM-Stack: Aktualisiert Puffer ohne Blockieren der Sender-Task.
  • Receiver-SWC: Liest den aktuellsten Wert abtastend (Rte_Read_<p>_<o>() / Explicit Read) oder empfängt implizite Variablenkopien zu Runnable-Beginn (Rte_IRead_<re>_<p>_<o>()).
  • Triggering: Optionale Bindung eines DataReceivedEvent an Empfänger-Runnables, um nach Eintreffen von LockgFbReq1 oder TrlrSts1 die Ausführung sofort zu schedulen.

4. Normative Relevanz & Entwickler-Hinweise

  • RTE-API-Vertrag:
  • Für LockgFbReq1: Generierung von typsicheren C-Signaturen:

```c

Std_ReturnType Rte_Write__Sts(LockActvn1 data);

Std_ReturnType Rte_Read__Sts(LockActvn1* data);

```

  • Für TrlrSts1:

```c

Std_ReturnType Rte_Write__TrlrSts(boolean data);

Std_ReturnType Rte_Read__TrlrSts(boolean* data);

```

  • Concurrency & Datenkonsistenz:
  • Da LockActvn1 ein zusammengesetzter Datentyp sein kann, muss der RTE-Generator bei Task-Grenzen atomare Sperrmechanismen (z. B. OS-Ressourcen, IRQ-Sperren oder Copy-Buffer) vorsehen, um Inkonsistenzen zwischen Sende- und Lese-Tasks zu verhindern.
  • Signal-Mapping (Com / CanIf / LinIf):
  • Der Systemintegrator mappt die VariableDataPrototypes im System Description ARXML auf ISignals innerhalb von I-PDUs.
  • Für TrlrSts muss im COM-Stack die Signallänge 1 Bit zugewiesen werden.
  • Für Sensor- und Statusdaten müssen InitValue sowie ggf. ComDataInvalidAction (z. B. bei Timeout-Überwachung der Anhängerelektronik) konfiguriert werden.
