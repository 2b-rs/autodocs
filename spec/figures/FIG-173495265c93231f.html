1. Diagrammtyp & Architektur-Kontext

AUTOSAR-ECU-Konfigurationsmetamodell (UML-Klassendiagramm) mit vorangestellten tabellarischen Parameterspezifikationen für das BSW-Modul KeyM (Key Manager) der AUTOSAR Classic Platform. Das Diagramm spezifiziert die Konfigurationsstruktur zur Definition logischer Verknüpfungsregeln (KeyMCertificateElementRule) für Zertifikatselement-Bedingungen.

2. Komponenten, Entitäten & Schnittstellen

Das Konfigurationsmetamodell definiert folgende Entitäten und Beziehungen:

  • Container KeyMCertificateElementRule (EcucParamConfContainerDef, Multiplizität 1..*): Repräsentiert eine Regel zur logischen Verknüpfung von Zertifikatselement-Bedingungen oder untergeordneten Regeln.
  • Parameter KeyMLogicalOperator (EcucEnumerationParamDef, Multiplizität 0..1, verknüpft über die Komposition Rolle +parameter): Bestimmt den logischen Verknüpfungsoperator mit den Aufzählungswerten (+literal / EcucEnumerationLiteralDef):
    • KEYM_AND
    • KEYM_OR
  • Referenz KeyMArgumentRef (EcucChoiceReferenceDef, Multiplizität 1..*, verknüpft über die Komposition Rolle +reference): Choice-Referenz auf die logischen Operanden / Argumente (+destination):
    • KeyMCertificateElementCondition (EcucParamConfContainerDef, Multiplizität 1..*)
    • KeyMCertificateElementRule (EcucParamConfContainerDef, rekursive Selbstreferenz zur Schachtelung von Teilausdrücken)

Die tabellarische Konfigurationsparameter-Dokumentation spezifiziert:

  • KeyMLogicalOperator (ECUC_KeyM_00057): Pre-compile time für alle Varianten konfiguriert (Value Configuration Class), Post-Build Variant Value = false, Scope: local.
  • KeyMArgumentRef (ECUC_KeyM_00058): Pre-compile time für alle Varianten bezüglich Multiplizität und Wert konfiguriert (Multiplicity Configuration Class, Value Configuration Class), Post-Build Variant Multiplicity = false, Post-Build Variant Value = false, Scope: local.
  • Keine eingebetteten Untercontainer (No Included Containers).

3. Dynamisches Verhalten & Sequenzablauf

Statisches Konfigurationsmetamodell ohne Laufzeit- oder Sequenzinteraktionen. Zur Konfigurationszeit bzw. Auswertezeit wird über KeyMCertificateElementRule ein Baum logischer Ausdrücke aufgespannt: Mehrere Argumente (KeyMArgumentRef), bestehend aus atomaren Bedingungen (KeyMCertificateElementCondition) oder rekursiv geschachtelten Regeln (KeyMCertificateElementRule), werden über den in KeyMLogicalOperator definierten Operator konjunktiv (KEYM_AND) oder disjunktiv (KEYM_OR) verknüpft (z. B. Argument_A AND Argument_B AND Argument_C). Besteht der Ausdruck nur aus einer einzelnen Bedingung, wird kein logischer Operator spezifiziert.

4. Normative Relevanz & Entwickler-Hinweise

Normative Konfigurationsvorgaben für den Key Manager (KeyM):

  • Besteht eine KeyMCertificateElementRule nur aus einem einzelnen Operanden, darf KeyMLogicalOperator nicht verwendet werden (Multiplicity 0..1).
  • Sobald zwei oder mehr Operanden über KeyMArgumentRef referenziert werden, ist die Definition des Operators erforderlich.
  • Beide Konfigurationsbestandteile sind rein zur Vorkompilierzeit festgelegt (Pre-compile time X All Variants, keine Post-Build-Variabilität).
  • Durch die Choice-Referenz auf Regeln und Bedingungen können beliebig tief verschachtelte boolesche Ausdrücke zur Zertifikatsvalidierung modelliert werden.
