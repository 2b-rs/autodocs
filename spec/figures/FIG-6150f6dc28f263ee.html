1. Diagrammtyp & Architektur-Kontext

UML-Objektdiagramm (Instanzebene) im Kontext des AUTOSAR-Software-Component-Templates (TPS SoftwareComponentTemplate, Datenmodellierung). Das Diagramm veranschaulicht die Modellierung eines dreidimensionalen Array-Datentyps auf Anwendungsebene (ApplicationArrayDataType) sowie auf Implementierungsebene (ImplementationDataType), parametrisiert über Systemkonstanten (SwSystemconst), inklusive des Mappings beider Welten über ein DataTypeMappingSet.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm gliedert sich in drei vertikale Stränge und ein verbindendes Mapping-Element:

  • Linker Strang (Application Data Types):
    • Oberste Instanz BOOLEAN_true_false_SysConDim1_SysConDim2_SysConDim3 : ApplicationArrayDataType mit category = ARRAY. Komposition (+element) zu Dim1 : ApplicationArrayElement (category = ARRAY, arraySizeSemantics = FIXED-SIZE, maxNumberOfElements = SysConDim1).
    • Verweis (+type) auf BOOLEAN_true_false_SysConDim2_SysConDim3 : ApplicationArrayDataType (category = ARRAY). Komposition (+element) zu Dim2 : ApplicationArrayElement (category = ARRAY, arraySizeSemantics = FIXED-SIZE, maxNumberOfElements = SysConDim2).
    • Verweis (+type) auf BOOLEAN_true_false_SysConDim3 : ApplicationArrayDataType (category = ARRAY). Komposition (+element) zu Dim3 : ApplicationArrayElement (category = BOOLEAN, arraySizeSemantics = FIXED-SIZE, maxNumberOfElements = SysConDim3).
    • Verweis (+type) auf den Basistyp BOOLEAN_true_false : ApplicationPrimitiveDataType mit category = BOOLEAN.
  • Mittlerer Bereich (Systemkonstanten):
    • Unabhängige Instanzen SysConDim1 : SwSystemconst, SysConDim2 : SwSystemconst und SysConDim3 : SwSystemconst, die als Werte für die Dimensionsgrößen referenziert werden.
  • Rechter Strang (Implementation Data Types):
    • Oberste Instanz boolean_NcNrDim1_NcNrDim2_NcNrDim3 : ImplementationDataType mit category = ARRAY. Komposition (+subElement) zu Dim1 : ImplementationDataTypeElement (category = ARRAY, arraySizeSemantics = FIXED-SIZE, arraySize = SysConDim1).
    • Verschachtelte Komposition (+subElement) zu Dim2 : ImplementationDataTypeElement (category = ARRAY, arraySizeSemantics = FIXED-SIZE, arraySize = SysConDim2).
    • Verschachtelte Komposition (+subElement) zu Dim3 : ImplementationDataTypeElement (category = TYPE_REFERENCE, arraySizeSemantics = FIXED-SIZE, arraySize = SysConDim3).
    • Assoziation (+swDataDefProps) von Dim3 zu einer Instanz «atpVariation» : SwDataDefProps, welche per +implementationDataType auf den elementaren Typ boolean : ImplementationDataType (category = VALUE) verweist.
  • Unterer Bereich (Datentyp-Mapping):
    • DefaultDataTypeMapping : DataTypeMappingSet aggregiert via +dataTypeMap ein unbenanntes : DataTypeMap.
    • Die : DataTypeMap verbindet über +applicationDataType die oberste Instanz BOOLEAN_true_false_SysConDim1_SysConDim2_SysConDim3 und über +implementationDataType die oberste Instanz boolean_NcNrDim1_NcNrDim2_NcNrDim3.

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Struktur- und Instanzendiagramm stellt die Abbildung keine zeitlichen Abläufe oder Laufzeitinteraktionen dar. Strukturell beschreibt sie die hierarchische Auflösung eines 3D-Arrays:

  1. Auf Anwendungsebene erfolgt die Dimensionalisierung über eine dreistufige Verkettung separater ApplicationArrayDataType-Instanzen via Typ-Referenzen (+type), bis der primitive Datentyp erreicht ist.
  2. Auf Implementierungsebene erfolgt die Dimensionalisierung über eine geschachtelte Aggregation von ImplementationDataTypeElement-Instanzen innerhalb eines einzigen übergeordneten ImplementationDataType, dessen Blattelement über SwDataDefProps auf den finalen Werte-Typ (VALUE) referenziert.
  3. Die Systemkonstanten parametrisieren dabei parallel jeweils die korrespondierende Dimension (Dim1, Dim2, Dim3) in beiden Strängen.
  4. Das DataTypeMap schließt den Verbund, indem es das 3D-Anwendungsarray ganzheitlich auf das 3D-Implementierungsarray abbildet.

4. Normative Relevanz & Entwickler-Hinweise

  • Struktureller Unterschied der Modellierung: Arrays mehrdimensionaler Natur werden im AUTOSAR-Metamodell bei ApplicationDataType typischerweise durch Typkaskadierung (ApplicationArrayDataType -> ApplicationArrayElement -> ApplicationArrayDataType) dargestellt, während ImplementationDataType eine direkte hierarchische Verschachtelung über subElement unterstützt.
  • Größenbegrenzung: Auf Anwendungsebene wird die Größe über das Attribut maxNumberOfElements angegeben, auf Implementierungsebene über arraySize. Beide nutzen hier arraySizeSemantics = FIXED-SIZE.
  • Systemkonstanten-Parametrisierung: Die Dimensionen sind nicht fest eincodiert, sondern referenzieren SwSystemconst-Instanzen, was Variabilität zur Definitionszeit unterstützt.
  • Typabbildung: Für die Codegenerierung bzw. RTL-Integration genügt ein Mapping-Eintrag (DataTypeMap) zwischen den Root-Typen der beiden Strukturen.
