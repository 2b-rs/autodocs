Figure 15: Per component part with ECU-configuration-specific optimization The Generate ECU-Configuration-Specific Component API reads the Component Implementation Description [for source code], which refers to the Component Implementation and the Component Internal Behavior Description [post Implementation]. This activity is again toolbased. The AUTOSAR RTE Generator generates the ECU-Configuration- Specific Component API. That means now we have a different set of component headers, which include the ECU-configuration-specific optimizations. The compilation activity has to consider the optimized parts. Hence the Compile ECU-Configuration-Specific Component bases on the inputs Component Implementation, on the Component Implementation Description [for source code], on the ECU-Configuration-Specific Component API and on the Additional Headers. The results of this activity will be the Component Implementation Description and the ECU-Configuration-Specific Compiled Component.

1. Diagrammtyp & Architektur-Kontext

AUTOSAR-Methodik-Aktivitätendiagramm (SPEM-basiert) für die AUTOSAR Classic Platform (Release R2.1.20). Das Diagramm spezifiziert den methodischen Teilprozess „Per component part with ECU-configuration-specific optimization“ (perComponentOptimized). Es beschreibt den optionalen Ablauf zur Erzeugung einer für ein konkretes Steuergerät optimierten Komponenten-API und der anschließenden komponentenbezogenen Objektcode-Kompilierung unter Wahrung unveränderter C-Quellen.

2. Komponenten, Entitäten & Schnittstellen

Aktivitäten (Verarbeitungsschritte):

  • Generate ECU-Configuration-Specific Component API: Tool-Aktivität zur Erzeugung optimierter Komponenten-Header.
  • Compile ECU-Configuration-Specific Component: Kompilierung des Komponenten-Quellcodes mit den optimierten Headern.

Werkzeuge:

  • AUTOSAR RTE Generator: Assoziiertes Generierungswerkzeug der Aktivität Generate ECU-Configuration-Specific Component API.

Artefakte (Work Products) & Schnittstellen:

  • Component Implementation Description [for Source-Code] : Implementation (.XML): Metadaten der Komponenten-Implementierung; referenziert das interne Verhalten (Component Internal Behavior Description [post Implementation] : InternalBehavior, .XML) sowie den Quellcode (Component Implementation, .c). Dient als Eingangsartefakt für die API-Generierung und den Compile-Schritt.
  • Component Internal Behavior Description [post Implementation] : InternalBehavior (.XML): Spezifikation des internen Verhaltens nach der Implementierungsphase.
  • Component Implementation (.c): Unveränderter C-Quellcode der Software-Komponente; Eingang in den Compile-Schritt.
  • ECU-Configuration-Specific Component API (.h): Generierte, für die spezifische ECU-Konfiguration optimierte RTE-Headerdatei; Ausgang der Generierung und Eingang in den Compile-Schritt.
  • Additional Headers (.h): Zusätzliche Header (z. B. plattform- oder komponentenübergreifende Schnittstellen); Eingang in den Compile-Schritt.
  • ECU-Configuration-Specific Compiled Component (.obj): Aus dem Compile-Schritt erzeugter kompilierter Binärcode/Objektcode.
  • Component Implementation Description [for ECU-Configuration-Specific Object-Code] : Implementation (.XML): Aus dem Compile-Schritt erzeugte Implementierungsbeschreibung, die auf den resultierenden Objektcode (.obj) referenziert.

3. Dynamisches Verhalten & Sequenzablauf

  1. Voraussetzung: Vor Beginn muss die Aktivität Implement Component abgeschlossen sein, sodass der Quellcode (.c) und die zugehörige Quellcode-Implementierungsbeschreibung (.XML) vorliegen.
  2. API-Generierung: Der AUTOSAR RTE Generator liest die Component Implementation Description [for Source-Code] ein und generiert die ECU-Configuration-Specific Component API (.h).
  3. Kompilierung: Die Aktivität Compile ECU-Configuration-Specific Component verarbeitet simultan vier Artefakte:
    • Component Implementation Description [for Source-Code] (.XML)
    • Component Implementation (.c)
    • ECU-Configuration-Specific Component API (.h)
    • Additional Headers (.h)
  4. Ergebniserzeugung: Die Kompilierung erzeugt als Ausgaben die Binärdatei ECU-Configuration-Specific Compiled Component (.obj) sowie die aktualisierte Metadatenbeschreibung Component Implementation Description [for ECU-Configuration-Specific Object-Code] (.XML), welche per Referenzkante direkt auf die .obj-Datei verweist.

4. Normative Relevanz & Entwickler-Hinweise

  • Status: Der Prozessschritt ist mit Status: proposed gekennzeichnet und stellt einen optionalen, parallelen Methodikpfad dar.
  • Optimierungsprinzip: Die Optimierung erfolgt ausschließlich über die RTE-API (z. B. Ersetzung von RTE-Funktionsaufrufen durch Inline-Makros für ECU-interne Kommunikation). Der Quellcode (Component Implementation, .c) bleibt dabei explizit unberührt, wodurch die Unabhängigkeit der Quellcode-Implementierung gewahrt bleibt.
  • Auswirkung auf Wiederverwendbarkeit: Das resultierende Objektcode-Artefakt (.obj) ist durch die Inlining-Optimierungen an die konkrete Steuergerätekonfiguration gebunden und nicht mehr universell auf andere ECUs übertragbar. Jede Änderung an der ECU-Konfiguration erfordert eine erneute API-Generierung und Neukompilierung der Komponente.
