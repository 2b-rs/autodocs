1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (sm FrNm State Machine) der FlexRay-Netzwerkverwaltung (AUTOSAR Classic Platform, BSW-Modul FrNm). Das Diagramm spezifiziert die Betriebsmodi und Subzustände des FrNm-Zustandsautomaten sowie deren Einbettung zwischen Initialisierung, synchronisierter Kommunikation, Schlaffunktion und Terminierung (Power Off).

2. Komponenten, Entitäten & Schnittstellen

  • Hauptzustände: Uninit, Bus Sleep Mode, Synchronize, Network Mode (Komposit-Zustand).
  • Subzustände in Network Mode: Repeat Message, Normal Operation, Ready Sleep.
  • Pseudozustände: Start (Initial-Pseudozustand auf Uninit), Choice- / Verzweigungsknoten (Übergang von Synchronize nach Network Mode), Junction/Merger-Knoten (Zusammenführung von Transitionen nach Ready Sleep bzw. Auswertung), Exit-Punkt / Verzweigung nach Bus Sleep Mode, Terminate (Endzustand).
  • Schnittstellen & API-Funktionen:
  • Steuerungs- & Lifecycle-Aufrufe: FrNm_Init(), FrNm_PassiveStartUp(), FrNm_NetworkRequest(), Nm_NetworkRequest(), FrNm_NetworkRelease().
  • Rückmeldungen / Benachrichtigungen: Notify "Bus-Sleep-Mode", Notify "Sychronize Mode", Notify "Network Mode".
  • Interne Variablen, Timer & Events:
  • Statusflags: FrNm_NetworkRequest (BOOLEAN), FrNm_RepeatMessage (BOOLEAN).
  • Zähler & Parameter: FrNm_ReadySleepCnt (bzw. FrNm_ReadySleepCount), StartValue.
  • Timer & Events: RepeateMessage Timer (Start, Ablauf RepeatMessageTimer expired), RepeatMessageDetected, ClusterAwakeVote detected, Repetition Cycle completed.
  • Kommentar-Annotationen:
  • Sende- und Abstimmungsverhalten je Zustand: „Vote for keeping awake, Do data transmission“ (Repeat Message, Normal Operation) vs. „No voting for keeping awake, No data transmission“ (Synchronize, Ready Sleep).
  • Definition: RepetitionCycleCompleted := (FlexRay "CycleEnd" Event) AND ((CycleNumber % RepetitionCycleLength) = 0).

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung & Start: Ausgehend vom Start-Pseudozustand erreicht das Modul Uninit. Durch FrNm_Init() erfolgt der Übergang in den Bus Sleep Mode, wobei per Entry-Aktion FrNm_NetworkRequest = FALSE und FrNm_RepeatMessage = FALSE gesetzt werden. Aus Bus Sleep Mode führt Power Off zum Terminate-Endzustand.
  • Aufwachen & Synchronisation:
  • Ein passiver Start (FrNm_PassiveStartUp()) oder ein Netzwerkanforderungsaufruf (FrNm_NetworkRequest() / FrNm_NetworkRequest = TRUE) überführt das System aus Bus Sleep Mode nach Synchronize.
  • Beim Eintritt in Synchronize wird Notify "Sychronize Mode" ausgelöst.
  • In Synchronize modifizieren FrNm_NetworkRelease() bzw. Nm_NetworkRequest() das Flag FrNm_NetworkRequest. Bei FrNm_Init() kehrt das System in Bus Sleep Mode zurück.
  • Mit dem Ereignis Repetition Cycle completed verlässt das System Synchronize über einen Verzweigungsknoten in den Komposit-Zustand Network Mode unter der Aktion /Notify "Network Mode" und FrNm_RepeatMessage = TRUE.
  • Ablauf im Komposit-Zustand Network Mode:
  • Standardmäßig wird der Subzustand Repeat Message betreten; die Entry-Aktion startet den RepeateMessage Timer.
  • Verlassen von Repeat Message:
  • Nach Ablauf des Repetition Cycles mit [FrNm_NetworkRequest = TRUE AND FrNm_RepeatMessage = FALSE] geht die State Machine nach Normal Operation.
  • Nach Ablauf des Repetition Cycles mit [FrNm_NetworkRequest = FALSE AND FrNm_RepeatMessage = FALSE] wechselt das System nach Ready Sleep und setzt /FrNm_ReadySleepCnt = StartValue.
  • In Normal Operation:
  • Bei Repetition Cycle completed [FrNm_NetworkRequest=FALSE AND FrNm_RepeatMessage=FALSE] erfolgt der Wechsel nach Ready Sleep unter /FrNm_ReadySleepCnt = StartValue.
  • Bei Repetition Cycle completed [FrNm_RepeatMessage = TRUE] kehrt das System nach Repeat Message zurück.
  • In Ready Sleep:
  • Bei Repetition Cycle completed [FrNm_ReadySleepCnt > 0 AND FrNm_NetworkRequest = TRUE AND FrNm_RepeatMessage = FALSE] wechselt das Modul nach Normal Operation.
  • Bei Repetition Cycle completed [FrNm_ReadySleepCount > 0 AND FrNm_RepeatMessage = TRUE] wechselt das Modul zurück nach Repeat Message.
  • Empfang von ClusterAwakeVote detected setzt /FrNm_ReadySleepCnt = StartValue.
  • Solange die Bedingungen für Sleep nicht erfüllt sind, zählt Repetition Cycle completed [FrNm_NetworkRequest=FALSE AND FrNm_RepeatMessage=FALSE] den Zähler herunter: /FrNm_ReadySleepCnt = FrNm_ReadySleepCnt - 1.
  • Globale Ereignisse auf Komposit-Ebene von Network Mode:
  • RepeatMessageDetected setzt /FrNm_RepeatMessage = TRUE.
  • RepeatMessageTimer expired setzt /FrNm_RepeatMessage = FALSE.
  • FrNm_NetworkRequest() setzt /FrNm_NetworkRequest = TRUE.
  • FrNm_NetworkRelease() setzt /FrNm_NetworkRequest = FALSE.
  • Rückkehr zum Bus Sleep Mode:
  • Wenn in Ready Sleep die Bedingung Repetition Cycle completed [FrNm_ReadySleepCnt < 1] erfüllt ist, wird Network Mode verlassen, Notify "Bus-Sleep-Mode" ausgeführt und Bus Sleep Mode erreicht.
  • Ein Aufruf von FrNm_Init() führt jederzeit aus Network Mode direkt in den Bus Sleep Mode.

4. Normative Relevanz & Entwickler-Hinweise

  • Das Diagramm definiert das fundamentale Status- und Transitionsmodell für FlexRay NM inklusive der Synchronisation mit dem FlexRay-Kommunikationszyklus.
  • Zustandswechsel und Guard-Bedingungen innerhalb von Network Mode und Synchronize sind an die Periodizität von RepetitionCycleCompleted gekoppelt, definiert durch das Zusammentreffen des FlexRay-CycleEnd-Events und des Repetitions-Teilers (CycleNumber % RepetitionCycleLength) == 0.
  • In Synchronize und Ready Sleep gilt für die BSW-Implementierung: kein Voting für das Wachhalten des Clusters und keine Datenübertragung, wohingegen in Repeat Message und Normal Operation aktiv für das Wachhalten gestimmt und Daten gesendet werden.
  • Zu beachten sind Schreibweisen/Tippfehler im Schaubild, die bei der Spezifikationsauslegung identifiziert werden müssen: RepeateMessage Timer, Sychronize Mode, inkonsistente Zählervariablennamen (FrNm_ReadySleepCnt, FrNm_ReadySleepCount, FrNm_ReaySleepCnt) sowie FrNM_RepeatMessage. In der Software-Implementierung repräsentieren diese jeweils denselben Zähler bzw. dasselbe Statusflag.
  • Der Aufruf FrNm_Init() fungiert als asynchroner Reset aus mehreren Modi zurück in Bus Sleep Mode.
