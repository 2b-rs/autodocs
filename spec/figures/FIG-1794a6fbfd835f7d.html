1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-2.0-Klassendiagramm (Metamodell-Ausschnitt des AUTOSAR System Templates, AUTOSAR_TPS_SystemTemplate).
  • Funktionale Einordnung: Spezifikation der Konfiguration des LIN Transport Layers (LIN TP gemäß ISO 17987 / LIN 2.1 / SAE J2602) innerhalb des AUTOSAR-Systemmodells. Es definiert die metamodellierte Brücke zwischen der Netzwerk-Topologie (EcuInstance, CommunicationController, CommunicationConnector, PhysicalChannel), den logischen Transportprotokoll-Knoten (LinTpNode), den Adressräumen (TpAddress / NAD) und den Kommunikations-PDUs (NPdu, IPdu).

2. Komponenten, Entitäten & Schnittstellen

#### Metamodell-Klassen & Hierarchie

  • TpConfig / LinTpConfig:
  • TpConfig (FibexElement, abstrakt): Basisklasse für busspezifische TP-Konfigurationen.
  • LinTpConfig (spezialisiert TpConfig): Wurzelbehälter für LIN-TP-Artefakte. Aggregiert per Komposition:
  • +tpConnection [0..*]: Instanzen von LinTpConnection («atpVariation», vh.latestBindingTime = postBuild).
  • +tpNode [0..*]: Instanzen von LinTpNode («atpVariation», vh.latestBindingTime = postBuild).
  • +tpAddress [1..*]: Instanzen von TpAddress («atpVariation», vh.latestBindingTime = postBuild).
  • LinTpConnection (spezialisiert TpConnection $\rightarrow$ Identifiable):
  • Repräsentiert einen logischen Punkt-zu-Punkt- oder Punkt-zu-Mehrpunkt-Kommunikationskanal des LIN TP.
  • Attribute:
  • dropNotRequestedNad : Boolean [0..1]: Verwirft Frames mit nicht angeforderter Node Address (NAD).
  • timeoutAs : TimeValue [0..1]: Senderseitiges Übertragungs-Timeout (N_As).
  • timeoutCr : TimeValue [0..1]: Empfängerseitiges Timeout zwischen aufeinanderfolgenden Consecutive Frames (N_Cr).
  • timeoutCs : TimeValue [0..1]: Senderseitiges Wartezeit-Timeout bis zum Senden des nächsten Consecutive Frames (N_Cs).
  • Assoziationen:
  • +transmitter [1]: Verweist auf den sendenden LinTpNode.
  • +receiver [1..*]: Verweist auf einen oder mehrere empfangende LinTpNode.
  • +dataPdu [1]: Referenz auf CoreCommunication::NPdu (Single Frame, First Frame, Consecutive Frame).
  • +flowControl [0..1]: Referenz auf CoreCommunication::NPdu für Flusskontrolle.
  • +linTpNSdu [1]: Referenz auf CoreCommunication::IPdu (repräsentiert das transportierte N-SDU, z. B. UDS-Diagnosebotschaft aus DCM/PduR).
  • +multicast [0..1]: Optionale Referenz auf TpAddress für funktionale/Broadcast-Adressierung (z. B. NAD 0x7E).
  • LinTpNode (Identifiable):
  • Repräsentiert einen logischen Endpunkt auf TP-Ebene.
  • Attribute:
  • maxNumberOfRespPendingFrames : Integer [0..1]: Maximal zulässige Anzahl an "Response Pending"-Frames (NRC 0x78) vor Abbruch.
  • p2Max : TimeValue [0..1]: Maximalzeit für Slave-Antwortbereitschaft.
  • p2Timing : TimeValue [0..1]: Nominale P2-Wartezeit für Diagnose-Sessions.
  • Assoziationen:
  • +tpAddress [0..1]: Eindeutige Zuweisung der physischen Node Address (TpAddress).
  • +connector [0..1]: Verknüpfung mit dem physischen CoreTopology::CommunicationConnector.
  • TpAddress (Identifiable):
  • Kapselt die Netzwerkkennung (tpAddress : Integer), im LIN-Kontext die NAD (1..255).

#### Topologische Einbettung & Controller-Spezialisierung

  • CoreTopology::EcuInstance (FibexElement):
  • Aggregiert physische Controller (+commController [1..]) und Connectors (+connector []).
  • Trägt globale COM-/Diagnose-Attribute (u. a. diagnosticAddress, comConfigurationTx/RxTimeBase, sleepModeSupported).
  • CoreTopology::CommunicationConnector (Identifiable):
  • Schnittstelle zwischen ECU und Kanal; referenziert CoreTopology::PhysicalChannel (+commConnector [0..*], «atpVariation») und CommunicationController (+commController [1]).
  • Attribut: pncGatewayType : PncGatewayTypeEnum [0..1].
  • LinTopology::LinCommunicationController (spezialisiert CoreTopology::CommunicationController):
  • Attribut: protocolVersion : String.
  • Vererbungslinien:
  • LinTopology::LinMaster: Besitzt Schedule-Timing-Attribute timeBase : TimeValue [0..1] und timeBaseJitter : TimeValue [0..1].
  • LinTopology::LinSlave: Spezifiziert Slave-Konformität via configuredNad : Integer, supplierId : PositiveInteger, functionId : PositiveInteger, variantId : PositiveInteger.

3. Dynamisches Verhalten & Sequenzablauf

  1. PDU-Segmentierung & Reassemblierung:
  • Empfang einer oberen Schicht-PDU (linTpNSdu via PduR/Dcm). Übersteigt die SDU-Länge die PDU-Nutzlast (LIN-Frame max. 8 Byte), initiiert LinTpConnection die Segmentierung in PCI-kodierte LIN-Frames (dataPdu: First Frame FF gefolgt von CF).
  • Bei Master-Request-Frames (MRF, ID 0x3C) und Slave-Response-Frames (SRF, ID 0x3D) wird die Nachricht über den Bus getaktet.
  1. Timer-Überwachung & Timeouts:
  • Beim Senden startet timeoutAs. Bleibt die Bestätigung über den LIN-Treiber/Interface aus $\rightarrow$ Abbruch via Timeout-Fehler.
  • Zwischen aufeinanderfolgenden CFs überwacht der Empfänger timeoutCr. Läuft der Timer ab, bevor der nächste Frame empfangen wird, wird die Verbindung verworfen.
  • timeoutCs sichert das Einhalten des Mindestabstands beim Absenden von Folge-Frames.
  1. Slave-Antwort-Handling (NRC 0x78):
  • Benötigt ein Slave mehr Verarbeitungszeit, sendet er negative Acknowledgements mit Code 0x78 ("Response Pending").
  • LinTpNode::maxNumberOfRespPendingFrames limitiert diese Zyklen. Wird der Zähler überschritten oder läuft p2Max ab, meldet der LIN TP einen Verbindungsabbruch an die Dcm.
  1. NAD-Filterung:
  • Steht dropNotRequestedNad = true, ignoriert der LIN TP im Empfangspuffer SRF-Frames, deren NAD nicht zu der aktuell aktiven Client-Anfrage passt.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW-Codegenerierung (LinTp / LinIf / PduR / Dcm):
  • LinTpConnection wird im AUTOSAR BSW direkt auf die ECUC-Parametercontainer LinTpRxNSdu und LinTpTxNSdu abgebildet.
  • LinTpNode steuert über die TpAddress die NAD-Zuweisung im LIN TP (LinTpRxNSduNad).
  • Post-Build-Variabilität («atpVariation» mit vh.latestBindingTime = postBuild):
  • tpConnection, tpNode und tpAddress können in Multibus-/Varianten-Fahrzeugen post-build schaltbar ausgelegt werden. Dies erfordert, dass Routingtabellen und Deskriptoren im LinTp als zeigerbasierte ROM/Flash-Konfigurationsstrukturen (LinTp_ConfigType) generiert werden.
  • Slave-Identifikation (Node Configuration Protocol):
  • Die Parameter supplierId, functionId und variantId in LinSlave bilden die normativen Identifier für standardisierte LIN-Diagnosekommandos (Assign NAD, Read by Identifier). Sie müssen bitgenau mit der LIN Description File (LDF) bzw. den OEM-Spezifikationen übereinstimmen.
  • Buffer- und PDU-Dimensionierung:
  • Da LIN Halbduplex auf Master-Header-Triggerung basiert, erfordert dataPdu und flowControl eine strikte Synchronisation mit den Scheduler-Tabellen des LinIf (Diagnose-Schedule-Slot-Zuweisung).
