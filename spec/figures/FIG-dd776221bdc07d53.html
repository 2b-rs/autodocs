1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Spezifikation des ECU State Manager (EcuM) im Kontext der AUTOSAR Classic Platform. Das Diagramm modelliert den Übergang von der Schlafphase (GOSLEEP / SLEEP) über den Hardware-HALT-Zustand bis zum Aufwecken über einen externen FlexRay-Transceiver-Interrupt und der anschließenden Wiederinbetriebnahme (WAKEUP I).

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Lebenslinien:

  • «module» EcuM: ECU State Manager.
  • Integration Code: Plattformspezifischer Integrations- und Callout-Code / BSW-Hooks.
  • «module» Os: AUTOSAR Betriebssystem.
  • «module» Mcu: Microcontroller Driver.
  • «module» Icu: Input Capture Unit Driver.
  • «module» FrIf: FlexRay Interface.
  • «module» Fr: FlexRay Driver (inaktiv).
  • «module» FrTrcv: FlexRay Transceiver Driver.
  • «Peripheral» FlexRay Controller: FlexRay-Kommunikationscontroller-Hardware (inaktiv).
  • «Peripheral» FlexRay Transceiver Hardware: Externe Hardwarekomponente zur Signalisierung des Aufweck-Interrupts.

Schnittstellen und Operationen:

  • EcuM_EnableWakeupSources(EcuM_WakeupSourceType), EcuM_DisableWakeupSources(EcuM_WakeupSourceType)
  • Icu_EnableWakeup(Icu_ChannelType), Icu_DisableWakeup(Icu_ChannelType)
  • GetResource(RES_AUTOSAR_ECUM_<core#>), ReleaseResource(RES_AUTOSAR_ECUM_<core#>)
  • DisableAllInterrupts(), EnableAllInterrupts()
  • Mcu_SetMode(Mcu_ModeType), synchrone Rückkehr Mcu_SetMode()
  • Wakeup interrupt(), Return from interrupt()
  • EcuM_CheckWakup(EcuM_WakeupSourceType) (ISR-Callout an EcuM)
  • EcuM_CheckWakeupHook(EcuM_WakeupSourceType) (Integration Code Hook)
  • Interne Integrationscode-Aktion: activate PLL()
  • FrIf_CheckWakeupByTransceiver(uint8, Fr_ChannelType)
  • FrTrcv_CheckWakeupByTransceiver(uint8)
  • EcuM_SetWakeupEvent(EcuM_WakeupSourceType) (Aufruf an Integration Code und Weiterleitung an EcuM)
  • Zustände: GOSLEEP, SLEEP, HALT, WAKEUP I
  • Kombiniertes Fragment: opt Wakeup detected

3. Dynamisches Verhalten & Sequenzablauf

  1. Vorbereitung auf Sleep (GOSLEEP):
    • EcuM beauftragt den Integration Code mit EcuM_EnableWakeupSources(EcuM_WakeupSourceType), welcher Icu_EnableWakeup(Icu_ChannelType) an der ICU aufruft.
    • EcuM belegt über GetResource(RES_AUTOSAR_ECUM_<core#>) die Scheduler-Ressource des OS.
  2. Eintritt in den Schlafzustand (SLEEP):
    • EcuM sperrt alle Interrupts via DisableAllInterrupts().
    • EcuM versetzt den Mikrocontroller mittels Mcu_SetMode(Mcu_ModeType) in den Zustand HALT.
  3. Aufweck-Sequenz via Interrupt:
    • Die Hardware FlexRay Transceiver Hardware erzeugt einen Wakeup interrupt() an die Icu.
    • Die ICU leitet das Ereignis via EcuM_CheckWakup(EcuM_WakeupSourceType) an den EcuM weiter.
    • EcuM delegiert die Behandlung über den Hook EcuM_CheckWakeupHook(EcuM_WakeupSourceType) an den Integration Code.
    • Der Integration Code führt die interne Aktion activate PLL() durch und ruft FrIf_CheckWakeupByTransceiver(uint8, Fr_ChannelType) auf.
    • FrIf delegiert an FrTrcv_CheckWakeupByTransceiver(uint8) am FlexRay-Transceiver-Treiber.
    • Optional (opt Wakeup detected): Bei erkanntem Wakeup ruft der FrTrcv EcuM_SetWakeupEvent(EcuM_WakeupSourceType) am Integration Code auf, der das Event synchron an EcuM meldet.
    • Die Bearbeitung kehrt über Return from interrupt() an die Transceiver-Hardware zurück.
  4. Fortsetzung nach HALT und Re-Aktivierung (WAKEUP I):
    • Der Aufruf Mcu_SetMode() kehrt nach der HALT-Instruktion synchron zu EcuM zurück.
    • EcuM führt EnableAllInterrupts() aus.
    • In der Phase WAKEUP I sperrt EcuM Interrupts (DisableAllInterrupts()), wechselt über Mcu_SetMode(Mcu_ModeType) / Mcu_SetMode() in den Normalmodus und aktiviert Interrupts (EnableAllInterrupts()).
    • EcuM ruft über den Integration Code Icu_DisableWakeup(Icu_ChannelType) auf.
    • EcuM gibt mit ReleaseResource(RES_AUTOSAR_ECUM_<core#>) die Scheduler-Ressource frei.

4. Normative Relevanz & Entwickler-Hinweise

  • Scheduler-Ressource: Um sicherzustellen, dass die Befehlsausführung nach der MCU-HALT-Instruktion fortgesetzt wird und nicht durch das Auftreten eines Cat-2-ISR vorzeitig verdrängt wird, muss RES_AUTOSAR_ECUM_<core#> gehalten werden.
  • Kanal-Wiederholung: Der Prüfaufruf FrIf_CheckWakeupByTransceiver(uint8, Fr_ChannelType) muss für beide FlexRay-Kanäle desselben Netzwerks bzw. Clusters wiederholt werden.
  • Moduswechsel: Vor dem Herunterfahren und im WAKEUP I müssen globale Interrupts konsistent gesperrt und nach PLL-Aktivierung bzw. MCU-Moduswechsel wieder freigegeben werden.
