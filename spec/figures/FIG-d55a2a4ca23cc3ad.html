1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Spezifikation des Ethernet State Managers (EthSM) innerhalb der AUTOSAR-Classic-Basissoftware. Das Diagramm modelliert das dynamische Interaktionsszenario beim Übergang vom aktiven Kommunikationsmodus (COMM_FULL_COMMUNICATION) in den Zustand ohne Kommunikation (COMM_NO_COMMUNICATION) über die Modul- und Schichtgrenzen von Kommunikationsmanagement, Zustandsmanagement, Socket-Adaption und Hardware-Abstraktion.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm definiert fünf Interaktionspartner als BSW-Module:

  • SoAd («module»): Socket Adaptor.
  • BswM («module»): Basic Software Mode Manager.
  • ComM («module»): Communication Manager (mit Endlosschleifen-Symbol).
  • EthSm («module»): Ethernet State Manager.
  • EthIf («module»): Ethernet Interface.

Ausgetauschte Schnittstellenaufrufe und Parameter:

  • ComM an EthSm: EthSM_RequestComMode(Std_ReturnType, NetworkHandleType, ComM_ModeType) mit Kommentar/Belegung ComMode := COMM_NO_COMMUNICATION.
  • EthSm an EthIf: EthIf_SetControllerMode(ControllerMode := DOWN).
  • EthSm an EthIf: EthIf_SetTransceiverMode(TransceiverMode := DOWN).
  • EthSm an SoAd: SoAd_BusSM_ModeIndication(Handle, ComMode := COMM_NO_COMMUNICATION).
  • EthSm an BswM: BswM_EthSM_CurrentState(Handle, ComMode := ETHSM_NO_COMMUNICATION).
  • EthSm an ComM: *ComM_BusSM_ModeIndication(Handle, ComMode := COMM_NO_COMMUNICATION).

3. Dynamisches Verhalten & Sequenzablauf

  1. ComM initiiert den Moduswechsel synchron über EthSM_RequestComMode(Std_ReturnType, NetworkHandleType, ComM_ModeType) mit dem Modus COMM_NO_COMMUNICATION.
  2. EthSm fährt die Ethernet-Hardware sequenziell synchron über EthIf herunter:
    • Zuerst wird EthIf_SetControllerMode(ControllerMode := DOWN) aufgerufen und synchron quittiert.
    • Anschließend wird EthIf_SetTransceiverMode(TransceiverMode := DOWN) aufgerufen und synchron quittiert.
  3. EthSm informiert die übergeordneten Schichten und Manager über den vollzogenen Moduswechsel:
    • Synchroner Aufruf von SoAd_BusSM_ModeIndication(Handle, ComMode := COMM_NO_COMMUNICATION) an SoAd.
    • Synchroner Aufruf von BswM_EthSM_CurrentState(Handle, ComMode := ETHSM_NO_COMMUNICATION) an BswM.
    • Aufruf von *ComM_BusSM_ModeIndication(Handle, ComMode := COMM_NO_COMMUNICATION) an ComM.
  4. Die ursprüngliche Anforderung EthSM_RequestComMode von ComM wird per Return-Pfeil abgeschlossen.

4. Normative Relevanz & Entwickler-Hinweise

  • Das Diagramm dokumentiert den synchronen Ablauf des vollständigen Herunterfahrens der Ethernet-Kommunikation.
  • Das Modul EthSm übernimmt die koordinierte Abschaltung der Hardware-Elemente (Controller, Transceiver) via EthIf und benachrichtigt anschließend alle betroffenen Schichten (SoAd, BswM, ComM).
  • Die Steuerung erfolgt ohne Zwischenzustände direkt von Full Communication zu No Communication.
