Figure 8.21: algorithm to map record layouts to types

1. Diagrammtyp & Architektur-Kontext

UML-Aktivitätsdiagramm zur Spezifikation des Mappings von Record Layouts auf Datentypen im Rahmen des AUTOSAR Software Component Templates. Das Diagramm modelliert einen Transformationsalgorithmus innerhalb einer iterativen Expansionsregion («iterative» bzw. for all newly required types).

2. Komponenten, Entitäten & Schnittstellen

  • Eingangs-Aktivitätsparameterknoten (ActivityParameterNode, links): CalprmElementPrototype und SwRecordLayouts.
  • Aktionen (Action / CallBehaviorAction):
  • remember Name (Aktion zur Zwischenspeicherung des Namens)
  • Get Descendant Groups/Values (Aktion zur Extraktion von Kindgruppen bzw. -werten)
  • setRlDataTypeName by ancestor -> GroupIndex (Aktion zur Namensbildung anhand von Ahnenknoten und Gruppenindex)
  • Create Type (CallBehaviorAction, gekennzeichnet durch das Verschachtelungs-/Subaktivitätssymbol in der unteren rechten Ecke)
  • Kontrollknoten: Ein Synchronisationsbalken (Join-Node / Fork-Node) zur Zusammenführung der Steuerungs- bzw. Datenflüsse vor Create Type.
  • Ausgangs-Aktivitätsparameterknoten (ActivityParameterNode, rechts): Data Type from Record layout.

3. Dynamisches Verhalten & Sequenzablauf

  1. Die Iterationsschleife durchläuft die Verarbeitung für alle neu benötigten Typen (for all newly required types).
  2. Parallel bzw. zweigeteilt treffen die Eingangsdaten ein:
  • CalprmElementPrototype wird an die Aktion remember Name übergeben; das Resultat wird zur Join-Node geführt.
  • SwRecordLayouts wird übergeben an Get Descendant Groups/Values, deren Ergebnis an setRlDataTypeName by ancestor -> GroupIndex weitergeleitet und anschließend ebenfalls in die Join-Node eingespeist wird.
  1. Nach Synchronisation beider Pfade an der Join-Node wird die Aktivität Create Type angestoßen.
  2. Das erzeugte Typ-Artefakt wird an den Ausgangsknoten Data Type from Record layout übergeben.

4. Normative Relevanz & Entwickler-Hinweise

Der Algorithmus definiert das deterministische Vorgehen zur Ableitung von Datentypen aus Record Layouts für Kalibrierparameter-Prototypen (CalprmElementPrototype). Werkzeuge zur AUTOSAR-Modellgenerierung müssen sicherstellen, dass die Namenskonvention (setRlDataTypeName by ancestor -> GroupIndex) sowie die Identifikation anhand des Prototypnamens eingehalten werden, um konsistente Datentypen aus den hierarchischen Record-Layout-Gruppen abzuleiten.
