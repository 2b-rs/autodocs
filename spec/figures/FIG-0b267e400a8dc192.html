1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm / AUTOSAR ECUC-Parametermetamodell (ECU Configuration Parameter Definition).
  • Architektur-Kontext: Konfigurationsmetamodell des BSW-Moduls J1939Tp (SAE J1939 Transport Layer) innerhalb der AUTOSAR Classic Platform (CP R23-11).
  • Technischer Zweck: Definition der Konfigurationscontainer, Parameter und Subcontainer für Empfangskanäle (J1939TpRxChannel, Teil 1) zur Segmentierung und Reassemblierung von J1939-Netzwerknachrichten (> 8 Bytes bis 1785 Bytes) via BAM (Broadcast Announce Message) oder CMDT (Connection Mode Data Transfer / RTS-CTS).

2. Komponenten, Entitäten & Schnittstellen

Das Metamodell definiert Container- und Parameterhierarchien (EcucParamConfContainerDef, EcucEnumerationParamDef, EcucIntegerParamDef, EcucBooleanParamDef, EcucEnumerationLiteralDef):

  • J1939TpConfiguration (EcucParamConfContainerDef): Wurzelkonfigurationscontainer des Moduls.
    • Aggregiert per Komposition (+subContainer, Multiplizität 0..*) Instanzen von J1939TpRxChannel.
  • J1939TpRxChannel (EcucParamConfContainerDef): Repräsentiert einen logischen Empfangskanal.
    • Parameter (+parameter):
      • J1939TpRxProtocolType (EcucEnumerationParamDef, 0..1): Definiert den Transportprotokolltyp. Literale (+literal):
        • J1939TP_PROTOCOL_BAM: 1:n Broadcast Announce Message (Zieladresse global 0xFF).
        • J1939TP_PROTOCOL_CMDT: 1:1 Connection Mode Data Transfer via RTS/CTS.
      • J1939TpRxRetrySupport (EcucBooleanParamDef, 0..1, Default: false): Aktiviert Retransmission-Support bei Paketverlust.
      • J1939TpRxCancellationSupport (EcucBooleanParamDef, 0..1, Default: false): Ermöglicht den gezielten Abbruch eines laufenden Empfangs.
      • J1939TpRxDynamicBlockCalculation (EcucBooleanParamDef, 0..1, Default: false): Steuert dynamische CTS-Blockgrößenberechnung basierend auf verfügbarem PduR-Puffer.
      • J1939TpRxDynamicBufferRatio (EcucIntegerParamDef, 0..1, Wertebereich: 0..100, Default: 80): Schwellwert in Prozent für dynamische Pufferzuweisung bei Blockberechnung.
      • J1939TpRxPacketsPerBlock (EcucIntegerParamDef, 0..1, Wertebereich: 1..255, Default: 16): Feste Paketanzahl pro Block (CTS Block Size) bei statischer Aushandlung.
      • J1939TpRxDa (EcucIntegerParamDef, 0..1, Wertebereich: 0..253): Zieladresse (Destination Address) zur Adressfilterung.
      • J1939TpRxSa (EcucIntegerParamDef, 0..1, Wertebereich: 0..253): Quelladresse (Source Address) zur Adressfilterung.
    • Subcontainer (+subContainer):
      • J1939TpRxCmNPdu (EcucParamConfContainerDef): N-PDU für Connection Management Rx (BAM / RTS).
      • J1939TpTxFcNPdu (EcucParamConfContainerDef, Multiplizität 0..1): N-PDU für Flow Control Tx (CTS, EndofMsgAck, ConnAbort im CMDT-Modus).
      • J1939TpRxDtNPdu (EcucParamConfContainerDef): N-PDU für Data Transfer Rx (TP.DT Datenpakete).
      • J1939TpRxPg (EcucParamConfContainerDef, Multiplizität 1..*): Zuordnung der Parameter Groups (PGNs), die über diesen Kanal reassembliert werden.

3. Dynamisches Verhalten & Sequenzablauf

Die Konfigurationsparameter bestimmen unmittelbar das Laufzeitverhalten der J1939Tp-Zustandsmaschine:

  1. Verbindungsaufbau (Connection Establishment):
    • Eintreffen einer TP.CM-PDU (J1939TpRxCmNPdu):
      • Bei J1939TP_PROTOCOL_BAM: Adressprüfung (J1939TpRxSa, DA = 255), Pufferallokation via PduR_J1939TpStartOfReception().
      • Bei J1939TP_PROTOCOL_CMDT (RTS): Prüfung von J1939TpRxSa und J1939TpRxDa. Antwort via J1939TpTxFcNPdu mit CTS (Clear to Send).
  2. Block- & Flusssteuerung (Flow Control bei CMDT):
    • Wenn J1939TpRxDynamicBlockCalculation == false: CTS signalisiert die statische Paketanzahl aus J1939TpRxPacketsPerBlock.
    • Wenn J1939TpRxDynamicBlockCalculation == true: J1939Tp ermittelt die Blockgröße zur Laufzeit über den von der oberen Schicht (PduR) gemeldeten freien Pufferraum gewichtet mit J1939TpRxDynamicBufferRatio (zur Vermeidung von Überläufen durch Buslatenzen).
  3. Datenempfang & Retransmission:
    • Datenpakete treffen sequenziell über J1939TpRxDtNPdu ein und werden in den PduR-Puffer kopiert (PduR_J1939TpCopyRxData()).
    • Bei fehlerhaften/fehlenden Sequenznummern: Falls J1939TpRxRetrySupport == true, fordert der Empfänger via J1939TpTxFcNPdu (CTS mit Startsequenznummer) fehlende Pakete erneut an; andernfalls Abbruch via Connection Abort Frame.
  4. Verbindungsabbruch:
    • Bei J1939TpRxCancellationSupport == true: Obere Schichten können den Empfang via PduR_J1939TpCancelReceive() aktiv terminieren; J1939Tp sendet daraufhin ggf. einen Connection Abort Frame über J1939TpTxFcNPdu.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurations-Integritätsregeln (ECUC Constraints):
    • Ist J1939TpRxProtocolType == J1939TP_PROTOCOL_BAM, darf J1939TpTxFcNPdu nicht instantiiert werden (Multiplizität 0), da BAM rein unidirektional ohne Rückkanal arbeitet.
    • Ist J1939TpRxProtocolType == J1939TP_PROTOCOL_CMDT, ist J1939TpTxFcNPdu obligatorisch (Multiplizität 1) für CTS/EOMA/Abort-Signalisierung.
    • Mindestens eine Parameter Group (J1939TpRxPg, 1..*) muss pro Kanal konfiguriert sein.
  • Pufferanforderungen & Schnittstellenvertrag:
    • Aktiviertes J1939TpRxDynamicBlockCalculation setzt voraus, dass die adressierte Ziel-BSW (z. B. PduR / Com / J1939Dcm) korrekte Restpuffergrößen im Rückgabeparameter RxBufferSizePtr von PduR_J1939TpCopyRxData() zurückliefert.
  • Speicherallokation (RAM/ROM-Footprint):
    • Die Anzahl instanziierter J1939TpRxChannel bestimmt statisch zur Generierungszeit die Dimensionierung der Rx-Kanalzustandstabellen (J1939Tp_RxChannelContextType). Jeder Kanal belegt persistente RAM-Strukturen für Timer (T1, T2, Tr), Sequenzzähler und PDU-Referenzen.
