1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration (ECUC) Metamodell-Klassendiagramm (UML-Notation für BSW-Parameter- und Container-Definitionen).
  • Technischer Zweck: Spezifikation der Konfigurationsstruktur des Moduls TcpIp zur formalen Anbindung an den Intrusion Detection System Manager (IdsM). Es definiert die BSW-internen Selektoren und Referenzen zur Erfassung und Meldung netzwerkbezogener Security-Events (SEVs) bei Protokollverletzungen oder Angriffsmustern auf den Schichten 2–4 (ARP, IPv4/IPv6, TCP, UDP).

2. Komponenten, Entitäten & Schnittstellen

Container & Parameter
  • TcpIpGeneral (EcucParamConfContainerDef):
    • Zentraler Konfigurationscontainer für allgemeine TcpIp-Parameter.
    • Beinhaltet den Parameter TcpIpEnableSecurityEventReporting (EcucBooleanParamDef):
      • Multiplizität: 1 (über Assoziation +parameter).
      • Standardwert: defaultValue = false. Globaler Schalter zur Aktivierung/Deaktivierung des Security-Event-Reportings im BSW-Modul.
    • Aggregiert über Komposition +subContainer den Subcontainer TcpIpSecurityEventRefs.
  • TcpIpSecurityEventRefs (EcucParamConfContainerDef):
    • Multiplizität: lowerMultiplicity = 0, upperMultiplicity = 1 (optionaler Container unterhalb von TcpIpGeneral).
    • Aggregiert fünf dedizierte Referenzdefinitionen (EcucReferenceDef, Rolle +reference), jeweils mit den Attributen lowerMultiplicity = 0, upperMultiplicity = 1 und requiresSymbolicNameValue = true:
      1. SEV_ARP_IP_ADDR_CONFLICT: Referenziert das IdsM-Event bei Detektion eines IP-Adresskonflikts im ARP-Modul (z. B. ARP-Spoofing / Duplicate IP).
      2. SEV_TCP_DROP_INV_PORT: Referenziert das IdsM-Event beim Verwerfen eines TCP-Segments wegen eines ungültigen bzw. unbesetzten Zielports (Port-Scan-Indikator).
      3. SEV_UDP_DROP_INV_PORT: Referenziert das IdsM-Event beim Verwerfen eines UDP-Datagramms an einen geschlossenen Port.
      4. SEV_IPV4_DROP_INV_ADDR: Referenziert das IdsM-Event beim Verwerfen eines IPv4-Pakets mit ungültiger Quell- oder Zieladresse (z. B. Martian Addresses, unerlaubte Broadcast/Multicast-Konstellationen).
      5. SEV_IPV6_DROP_INV_ADDR: Referenziert das IdsM-Event beim Verwerfen eines IPv6-Pakets mit ungültiger/reservierter Adressierung.
Externe Zielentität
  • IdsMEvent (EcucParamConfContainerDef aus dem Modul IdsM, Stereotyp/Package (from IdsM)):
    • Multiplizität: lowerMultiplicity = 1, upperMultiplicity = 65535.
    • Dient als Ziel (+destination) aller fünf EcucReferenceDef-Instanzen. Die Verbindung erfolgt über symbolische Namen (Symbolic Name Value) der IdsM-Event-Instanzen.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm selbst ist ein statisches Konfigurationsmodell. Zur Laufzeit steuert diese Konfiguration folgenden sequenziellen Ablauf:

  1. Voraussetzung / Gate:
    • Auswertung zur Compile-Time: TcpIpEnableSecurityEventReporting == true und Vorhandensein des Containers TcpIpSecurityEventRefs.
  2. Ereignis-Trigger (asynchroner Netzwerkverkehr):
    • ARP-Ebene: Empfang eines ARP-Packets mit abweichender MAC-zu-IP-Zuordnung für eine bereits konfigurierte lokale/statische Adresse → Trigger für SEV_ARP_IP_ADDR_CONFLICT.
    • IP-Validierung: Parser verwirft Frame aufgrund fehlerhafter IPv4/IPv6-Header-Adressen → Trigger für SEV_IPV4_DROP_INV_ADDR bzw. SEV_IPV6_DROP_INV_ADDR.
    • L4-Demultiplexing: Segment/Datagramm trifft auf keinen lauschenden Socket (SocketId ungültig oder State CLOSED) → Paket verworfen → Trigger für SEV_TCP_DROP_INV_PORT bzw. SEV_UDP_DROP_INV_PORT.
  3. Meldepfad:
    • Sofern die jeweilige Referenz instanziiert ist (Multiplicity = 1), ruft der TcpIp-Treiber synchron die Schnittstelle des IdsM auf: IdsM_SetSecurityEvent(IdsMEventId, ...) unter Übergabe der generierten symbolischen ID und relevanter Kontextdaten (z. B. IP-Header, Port, Interface-Index).
    • Ist die Referenz nicht konfiguriert (Multiplicity = 0), wird das Paket laut TCP/IP-Spezifikation stillschweigend verworfen, ohne IdsM-API-Aufruf.

4. Normative Relevanz & Entwickler-Hinweise

  • Codegenerierung & Speicherökonomie (Pre-Compile Switch):
    • Parameter TcpIpEnableSecurityEventReporting dient als globaler Makroschalter (z. B. TCPIP_SECURITY_EVENT_REPORTING == STD_ON). Bei false müssen sämtliche Meldezweige und die Abhängigkeit zu IdsM.h vollständig wegoptimiert werden (Zero ROM/RAM Overhead).
  • Symbolic Name Resolution (requiresSymbolicNameValue = true):
    • Der BSW-Konfigurator muss die symbolischen Bezeichner der im IdsM-Modul deklarierten Events auflösen und im generierten Header des TcpIp-Stacks als numerische IDs (z. B. IdsMConf_IdsMEvent_<ShortName>) hinterlegen.
  • Granularität im TARA-Kontext (Multiplizität [0..1]):
    • Entwickler/Integratoren können die Ereignisse selektiv aktivieren. Auf leistungskritischen ECUs können hochfrequente Events (wie UDP-Port-Drops bei potenziellen DoS-Angriffen) unkonfiguriert bleiben, um eine Überlastung der IdsM-Filterqueues und Event-Puffer zu vermeiden.
  • Implementierungsvorgabe für Stack-Entwickler:
    • Das Melden an das IdsM darf den regulären Fehlerbehandlungs- und Verwerfpfad (Packet Drop / Freeing von Eth_BufType / Socket-Bereinigung) nicht blockieren oder verzögern; IdsM-Aufrufe sind direkt vor oder nach dem Verwerfen auszuführen.
