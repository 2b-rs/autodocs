1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm / Metamodell-Ausschnitt der AUTOSAR ECU Configuration Parameter Definition (EcucParamConfContainerDef).
  • Architektur-Kontext: AUTOSAR Classic Platform, BSW-Modul TcpIp (Layer: Transport / Communication Stack).
  • Technischer Zweck: Definition des Konfigurationscontainers TcpIpTlsCiphersuiteDefinition zur statischen Spezifikation und Parametrierung der durch den integrierten TLS-Stack (Transport Layer Security) unterstützten kryptografischen Suites für gesicherte IP-Verbindungen (z. B. DoIP über TLS, SOME/IP über TLS, HTTPS/MQTT).

2. Komponenten, Entitäten & Schnittstellen

Metamodell-Container
  • TcpIpTlsCiphersuiteDefinition (EcucParamConfContainerDef):
    • Kardinalität: [1..*] (Mindestens eine Cipher Suite muss im Modul konfiguriert sein; beliebig viele sind instanziierbar).
Konfigurationsparameter (Komposition via +parameter)
  • TcpIpTlsCiphersuiteId (EcucIntegerParamDef):
    • Wertebereich: [0 .. 65535] (16-Bit unsigned Integer). Repräsentiert die normierte IANA-Cipher-Suite-Kennung (z. B. 0x002F für TLS_RSA_WITH_AES_128_CBC_SHA).
  • TcpIpTlsCiphersuitePriority (EcucIntegerParamDef):
    • Wertebereich: [1 .. 65535]. Definiert die Präferenzreihenfolge bei der Cipher-Negotiation im Handshake (1 = höchste Priorität).
  • TcpIpTlsCiphersuiteName (EcucStringParamDef):
    • Kardinalität: [0..1] (optional). Textueller RFC-Identifier zur Lesbarkeit und Generierungsunterstützung.
  • TcpIpTlsUsePresharedKeys (EcucBooleanParamDef):
    • defaultValue = false. Schaltet auf symmetrische Pre-Shared-Key-Verfahren (TLS-PSK) um.
  • TcpIpTlsUseSecurityExtensionForceEncryptThenMac (EcucBooleanParamDef):
    • defaultValue = false. Aktiviert die RFC-7366-Erweiterung ("Encrypt-then-MAC") zur Vermeidung von Padding-Oracle-Vulnerabilitäten bei CBC-Chiffren.
  • TcpIpTlsUseAEADCipher (EcucBooleanParamDef):
    • defaultValue = false. Kennzeichnet AEAD-Chiffren (Authenticated Encryption with Associated Data, z. B. AES-GCM, AES-CCM, ChaCha20-Poly1305), bei denen Verschlüsselung und Integritätsschutz in einem Schritt erfolgen.
  • TcpIpTlsVersion (EcucEnumerationParamDef):
    • Definiert die zugehörige TLS-Protokollversion.
    • Enthaltene Literale (Komposition via +literal):
      • TLS_VERSION_V12 (EcucEnumerationLiteralDef): TLS 1.2 (RFC 5246).
      • TLS_VERSION_V13 (EcucEnumerationLiteralDef): TLS 1.3 (RFC 8446).

3. Dynamisches Verhalten & Sequenzablauf

Als rein deklarative BSW-Konfigurationsstruktur bildet das Diagramm selbst keine Laufzeit-Zustände ab. Das daraus generierte Laufzeitverhalten steuert folgende Abläufe:

  1. ClientHello / ServerHello Negotiation:
    • Bei Rolle TLS Client: Der BSW-Code serialisiert alle instanziierten TcpIpTlsCiphersuiteId-Werte absteigend nach TcpIpTlsCiphersuitePriority in das cipher_suites-Feld der ClientHello-Nachricht.
    • Bei Rolle TLS Server: Der Stack evaluiert die vom Peer angebotenen Suites gegen die lokal konfigurierten Einträge und selektiert die kompatible Suite mit der höchsten lokalen Priorität.
  2. Krypto-Pfad-Verzweigung (Record Layer / CSM):
    • Abhängig von TcpIpTlsUseAEADCipher routet der TLS-Stack die Daten an AEAD-Primitive oder getrennte Cipher-/MAC-Primitive des Crypto Stack (CSM/Crypto Driver).
    • Bei TcpIpTlsUseSecurityExtensionForceEncryptThenMac == true wird während der Aushandlung die entsprechende TLS-Extension gesetzt und im Record-Processing erst verschlüsselt und anschließend der MAC über den Ciphertext gebildet.
  3. Fehlerpfade:
    • Schlägt die Einigung auf eine Cipher Suite fehl, bricht der Handshake mit einem TLS-Alert (handshake_failure, Alert Description 40) ab; optional erfolgt eine Meldung an Det_ReportError bzw. Dem_ReportErrorStatus.

4. Normative Relevanz & Entwickler-Hinweise

  • Generierungsartefakt: Der BSW-Konfigurator leitet aus diesen Parametern tabellarische Deskriptoren (ROM-Konfiguration, typischerweise TcpIp_Tls_CiphersuiteType[]) ab, die Funktionszeiger oder CSM-Job-IDs für Cipher-, Hash- und Signaturalgorithmen referenzieren.
  • Konsistenzprüfung & Validierung (BSW-Integrator):
    • TLS-1.3-Restriktionen: TLS 1.3 verbietet CBC-Chiffren und Non-AEAD-Algorithmen (RFC 8446). Wird TLS_VERSION_V13 konfiguriert, muss TcpIpTlsUseAEADCipher == true sein; TcpIpTlsUseSecurityExtensionForceEncryptThenMac ist für TLS 1.3 ungültig/irrelevant.
    • Eindeutigkeit: Jede TcpIpTlsCiphersuiteId darf innerhalb einer TLS-Instanz/Verbindungskonfiguration nur einmal vorkommen.
    • Prioritäten-Kollision: TcpIpTlsCiphersuitePriority muss strikt monoton bzw. disjunkt sein, um deterministisches Verhandlungsverhalten auf Server-Seite zu garantieren.
  • Abhängigkeiten zu Fremdmodulen:
    • Zu jeder aktivierten Cipher Suite müssen die korrespondierenden Primitiven und Keyslots im CSM (Crypto Service Manager) und CryIf/Crypto-Treiber (Hardware-HSM oder Software-Crypto) bereitgestellt und konfiguriert sein.
    • Wenn TcpIpTlsUsePresharedKeys == true, muss die Key-Verwaltung für Pre-Shared Keys angebunden sein (z. B. CSM-Key-Handling oder statische PSK-Tabellen im BSW).
