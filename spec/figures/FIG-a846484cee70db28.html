1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm / ECUC-Metamodell-Ausschnitt zur Konfiguration von Basissoftware-Exclusive-Areas (RteBswExclusiveAreaImpl) innerhalb der AUTOSAR RTE. Das Diagramm modelliert die Beziehung zwischen ECU-Konfigurationsparametern (ECUC-Container und Parameterdefinitionen) und M1- bzw. M2-Vorlagen der Pakete BswModuleTemplate sowie Os. Es zeigt, wie softwarearchitektonische Schutzzonen von BSW-Modulen auf konkrete Betriebssystem- und RTE-Synchronisationsmechanismen abgebildet werden.

  • RteBswExclusiveAreaImpl (EcucParamConfContainerDef, Multiplizität 0..*): Konfiguriert die Realisierung einer BSW ExclusiveArea. Enthält:

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm beschreibt eine statische Metamodell- und Konfigurationsstruktur. Dynamisch definiert es die Ausführungssemantik für den Eintritt und Austritt in kritische Bereiche von BSW-Entitäten:

  • Eine BswSchedulableEntity bzw. BswModuleEntity kann zur Laufzeit über APIs einen synchronisierten Abschnitt betreten (canEnterExclusiveArea) oder vollständig darin ablaufen (runsInsideExclusiveArea).
  • Abhängig vom konfigurierten Wert in RteExclusiveAreaImplMechanism generiert die RTE spezifischen Schutzkodierungsaufruf:
  • Globales Sperren aller Interrupts (ALL_INTERRUPT_BLOCKING).
  • Sperren von OS-Interrupts bis zu einer bestimmten Prioritätsstufe (OS_INTERRUPT_BLOCKING).
  • Belegen und Freigeben einer OS-Ressource (OS_RESOURCE) unter Verwendung der via RteBswExclusiveAreaOsResourceRef referenzierten OsResource.
  • Kooperatives Scheduling / deterministische Ablaufplanung (COOPERATIVE_RUNNABLE_PLACEMENT), wodurch Unterbrechungen ohne Interrupt-Sperren vermieden werden.

4. Normative Relevanz & Entwickler-Hinweise

  • Jede RteBswExclusiveAreaImpl muss über RteBswExclusiveAreaRef zwingend genau eine ExclusiveArea referenzieren (lowerMultiplicity = 1, upperMultiplicity = 1).
  • Falls als Mechanismus OS_RESOURCE gewählt wird, muss die Referenz RteBswExclusiveAreaOsResourceRef auf eine gültige OS-Ressource zeigen.
  • Die Ausführungseinheiten (BswSchedulableEntity / BswModuleEntity) müssen die modellierten Zugriffsrechte (canEnterExclusiveArea bzw. runsInsideExclusiveArea) deklarieren, damit der RTE-Generator korrekte Funktionsaufrufe (Rte_Enter_<area>, Rte_Exit_<area>) bzw. Kapselungen für das BSW-Modul erzeugt.
