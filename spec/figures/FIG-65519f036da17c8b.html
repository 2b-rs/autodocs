1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Sequenzdiagramm (Interaktionsdiagramm mit optionalem kombinierten Fragment opt).
  • Architektur-Kontext: AUTOSAR Classic Platform (Release R24-11), Kommunikationsstack (Ethernet / On-Board Communication).
  • Funktionale Einordnung: Spezifikation des standardisierten Empfangspfads (Rx-Pfad) für Ethernet-Frames über den L-SDU Router (LSduR) und den TCP/IP-Stack (TcpIp) hin zum Socket-Adaptor (SoAd) sowie die asynchrone TCP-Flusssteuerung (Receive Window Update), TCP-ACK-Aussendung und Sende-Bestätigung (Tx-Confirmation) auf L4/L2-Ebene.

2. Komponenten, Entitäten & Schnittstellen

Beteiligte BSW-Module (Lebenslinien)
  • «module» :EthIf: Ethernet Interface (Hardware Abstraction Layer) – entkoppelt obere Schichten von Ethernet-Controller- und Transceiver-Treibern (Eth/EthTrcv).
  • «module» LSduR: L-SDU Router – vermittelt Ethernet-SDUs zwischen dem Ethernet Interface und übergeordneten Protokollschichten.
  • «module» :TcpIp: TCP/IP-Stack (Services Layer / Protokollschicht L3/L4) – zuständig für IPv4/IPv6, UDP, TCP, ARP/NDP sowie ICMP.
  • «module» :SoAd: Socket Adaptor (Services Layer) – vermittelt zwischen socketbasierter IP-Kommunikation (TcpIp) und PDU-basiertem AUTOSAR-Routing (PduR, SomeIpXf, DoIP, Sd).
Schnittstellen & Funktionsaufrufe
  • Rx-Pfad (L2 → L4/L7):
    • EthIf_MainFunctionRx(): Zyklischer Task-Einsprungpunkt des Ethernet Interface zur Abfrage und Weiterleitung empfangener Ethernet-Frames.
    • LSduR_EthIfRxIndication(): Übergabe empfangener Frames von EthIf an den L-SDU Router.
    • TcpIp_RxIndication(): Weiterleitung empfangener Frames vom L-SDU Router an den TCP/IP-Stack.
    • SoAd_RxIndication(): L4-Payload-Übergabe vom TCP/IP-Stack an den Socket Adaptor.
  • TCP-Flusssteuerung, Transmission & Bestätigungspfad (opt TCP socket):
    • SoAd_MainFunction(): Zyklische Task-Funktion des Socket Adaptors zur Abarbeitung oberer PDU-Schichten und Puffer-Freigaben.
    • TcpIp_TcpReceived(): API zur Bestätigung konsumierter TCP-Nutzdaten zwecks TCP Receive-Window-Vergrößerung.
    • TcpIp_MainFunction(): Zyklische Stack-Funktion zur zeitgesteuerten L3/L4-Protokollarbeit (TCP-State-Machine, Reassembly, Timer, ACK-Generierung).
    • LSduR_TcpIpTransmit(): Übergabe des generierten TCP-Segments/ACKs von TcpIp an den L-SDU Router.
    • EthIf_Transmit(): Weiterleitung des Sendeauftrags von LSduR an das Ethernet Interface zur Transmission.
    • EthIf_MainFunctionTx(): Zyklischer Task-Einsprungpunkt des Ethernet Interface zur Bearbeitung von Sende-Bestätigungen.
    • LSduR_EthIfTxConfirmation(): Meldung der erfolgreichen Übertragung von EthIf an den L-SDU Router.
    • TcpIp_TxConfirmation(): Weiterleitung der Übertragungsbestätigung vom L-SDU Router an den TCP/IP-Stack.

3. Dynamisches Verhalten & Sequenzablauf

Phase 1: Frame-Empfang und Payload-Dispatching (Synchroner Rx-Kontext)
  1. Trigger: EthIf_MainFunctionRx() wird zyklisch im Kontext eines dedizierten OS-Tasks aufgerufen (bzw. verarbeitet Polling/deferred ISRs).
  2. L2 → LSduR Dispatch: EthIf übergibt den Frame synchron via LSduR_EthIfRxIndication() an LSduR.
  3. LSduR → L3/L4 Dispatch: LSduR leitet den Frame synchron via TcpIp_RxIndication() an TcpIp weiter.
  4. Protokollverarbeitung (TcpIp):
    • Validierung und Demultiplexing (IP-, ICMP-, UDP- oder TCP-Header).
    • TCP-Spezifikum: Mit dem Eintreffen von Daten im TCP-Empfangspuffer reduziert der Stack das verfügbare TCP-Empfangsfenster ("TCP: Decrease receive window").
  5. L4 → SoAd Indication: Bei zugeordnetem Socket ruft TcpIp synchron SoAd_RxIndication() auf.
  6. PDU-Mapping (SoAd): SoAd ermittelt anhand der Socket-Zuordnung die zugehörige PduId und die Zielschicht (z. B. PduR), extrahiert die PDU und stößt die Weiterleitung an ("find related PduId and UL for received datagram/segment and process frame").
  7. Rückkehr: Die synchrone Aufrufkette kehrt sequenziell über TcpIp und LSduR zu EthIf_MainFunctionRx() zurück.
Phase 2: TCP Window Update, Acknowledgment und Tx Confirmation (opt TCP socket)

Das Fragment opt TCP socket wird ausschließlich bei verbindungsorientierten TCP-Sockets durchlaufen:

  1. Pufferfreigabe durch Upper Layer: Sobald SoAd (oder die darüber liegende Applikations-/PDU-Schicht) die Nutzdaten vollständig prozessiert oder in eigene Puffer kopiert hat, wird im Kontext von SoAd_MainFunction() die Funktion TcpIp_TcpReceived() aufgerufen.
  2. Window Update: TcpIp markiert die konsumierte Datenmenge als freigegeben und vergrößert das TCP-Empfangsfenster entsprechend ("TCP: Increase receive window").
  3. ACK-Generierung: Im zyklischen Aufruf von TcpIp_MainFunction() prüft der Stack anstehende Bestätigungen (Delayed ACKs oder kumulative Segment-Bestätigungen) ("Acknowledge received data for one or several received segments").
  4. Sendeauftrag über LSduR: TcpIp übergibt das ACK-Segment mittels LSduR_TcpIpTransmit() an LSduR.
  5. Übertragung via EthIf: LSduR leitet die Anforderung über EthIf_Transmit() synchron an EthIf weiter.
  6. Asynchrone Übertragungsbestätigung: Zu einem späteren Zeitpunkt verarbeitet EthIf_MainFunctionTx() die Sende-Events und meldet den Übertragungsstatus synchron via LSduR_EthIfTxConfirmation() an LSduR, welcher die Bestätigung über TcpIp_TxConfirmation() an den TCP/IP-Stack durchreicht.

4. Normative Relevanz & Entwickler-Hinweise

  • Rolle von LSduR im Stack: Der L-SDU Router fungiert als obligatorisches Zwischenmodul zwischen dem Ethernet Interface und TcpIp. Sowohl der Empfangspfad (LSduR_EthIfRxIndication → TcpIp_RxIndication) als auch der Sendepfad (LSduR_TcpIpTransmit → EthIf_Transmit) sowie die Bestätigungskette laufen strikt über LSduR.
  • Pufferlebensdauer und synchrone Kette im Rx-Pfad: Der Rx-Aufruf (EthIf_MainFunctionRx → LSduR_EthIfRxIndication → TcpIp_RxIndication → SoAd_RxIndication) erfolgt als geschlossene, blockierende Aufrufkette. Obere Schichten müssen empfangene Daten synchron verarbeiten oder kopieren. Eine lange Verweildauer in oberen Schichten blockiert die Rückkehr zu EthIf_MainFunctionRx().
  • Flusssteuerung und Window Update (TcpIp_TcpReceived): Unterbleibt der Aufruf von TcpIp_TcpReceived() im Kontext von SoAd_MainFunction(), reduziert sich das TCP-Empfangsfenster bis zum Stillstand (Zero-Window). Entwickler müssen sicherstellen, dass jede konsumierte Bytemenge verlässlich über TcpIp_TcpReceived() rückgemeldet wird.
  • Entkopplung von Sendeanforderung und Sende-Bestätigung: Die Übertragung von TCP-Segmenten (ACKs) via LSduR_TcpIpTransmit() ist von der Übertragungsbestätigung entkoppelt. Letztere erfolgt asynchron über den zyklischen Task EthIf_MainFunctionTx() via LSduR_EthIfTxConfirmation() und TcpIp_TxConfirmation(). Stack-Implementierungen müssen Zustände zur Zuordnung ausstehender Bestätigungen vorhalten.
