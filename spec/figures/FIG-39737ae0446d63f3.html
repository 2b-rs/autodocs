1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm / AUTOSAR ECU Configuration Parameter Definition (Metamodell-Ausschnitt der BSW-Konfiguration).
  • Architekturebene: System Services (Basic Software / BSW), Modul Communication Manager (ComM), AUTOSAR Classic Platform Release 4.0.3.
  • Funktionaler Kontext: Spezifikation der Definitionselemente des Konfigurationscontainers ComMGeneral. Der Container kapselt alle statischen Pre-Compile- und Link-Time-Parameter, die das globale Betriebsverhalten, den BSW-Footprint, das Fehlerreporting, NvM-Persistierung und die Unterstützung von Partial Networking (PNC) determinieren.

2. Komponenten, Entitäten & Schnittstellen

#### Zentraler Definitionscontainer

  • ComMGeneral (EcucParamConfContainerDef, Multiplizität: 1..1):
  • Obligatorischer Singleton-Container auf Root-Ebene der ComM-Modulkonfiguration.

#### Enthaltene Parameter (+parameter-Kompositionen)

  • ComMDevErrorDetect (EcucBooleanParamDef, Default: false):
  • Aktiviert/deaktiviert die Überprüfung von Vorbedingungen (z. B. Modulinitialisierung) und die synchrone Benachrichtigung des Default Error Tracers (Det_ReportError).
  • ComMTMinFullComModeDuration (EcucFloatParamDef, Wertebereich: [0.001 .. 65.0] s, Default: 5.0 s):
  • Mindestverweildauer im Zustand COMM_FULL_COMMUNICATION zur Vermeidung von Schwingungen/Chattering bei schnellen Mode-Wechseln.
  • ComMWakeupInhibitionEnabled (EcucBooleanParamDef, Default: false):
  • Schaltet die Funktionalität frei, externe bzw. interne Wake-up-Ereignisse auf Kanälen zu inhibieren.
  • ComMResetAfterForcingNoComm (EcucBooleanParamDef, Default: false):
  • Steuert, ob nach dem Erzwingen des Modus COMM_NO_COMMUNICATION (z. B. durch Mode Limitation) ein Steuergeräte-Reset ausgelöst werden soll.
  • ComMModeLimitationEnabled (EcucBooleanParamDef, Default: false):
  • Schaltet die Begrenzung des Kommunikationsmodus (z. B. Zwangsführung nach COMM_NO_COMMUNICATION) frei.
  • ComMEcuGroupClassification (EcucIntegerParamDef, Wertebereich: [0 .. 255], Default: 3):
  • 8-Bit-Maske zur Einteilung des Steuergeräts in Gruppen (verwendet für koordinierte Mode-Limitations über Diagnosedienste oder interne Logik).
  • ComMSynchronousWakeUp (EcucBooleanParamDef, Default: true):
  • Steuert, ob bei einem Wake-up auf einem Kanal synchron alle logisch verknüpften Kanäle mit aufgeweckt werden.
  • ComM0PncVectorAvoidance (EcucBooleanParamDef, Multiplizität: 0..1, Default: false):
  • Steuert die Vermeidung von PNC-Vektoren auf dem Bus, wenn keine PNCs aktiv sind.
  • ComMVersionInfoApi (EcucBooleanParamDef, Default: false):

3. Dynamisches Verhalten & Sequenzablauf

Die Parameter konfigurieren deterministische Pfade in der ComM-Laufzeitumgebung:

```

[Mode Request: FULL_COM]

│

▼

┌────────────────────────────────────────┐

│ State: COMM_FULL_COMMUNICATION │

│ ──> Start: ComMTMinFullComModeDuration │

└────────────────────────────────────────┘

│

│ Mode Request: NO_COM empfangen

▼

┌────────────────────────────────────────┐

│ Ablauf Timer abwarten │

│ Timer > 0 ? ──[Ja]──> Transition blockiert

│ ──[Nein]─> Transition erlaubt

└────────────────────────────────────────┘

│ (falls ComMPncSupport == true)

▼

┌────────────────────────────────────────┐

│ State: COMM_PNC_PREPARE_SLEEP │

│ ──> Start: ComMPncPrepareSleepTimer │

└────────────────────────────────────────┘

│

│ Timer abgelaufen

▼

┌────────────────────────────────────────┐

│ State: COMM_PNC_NO_COMMUNICATION │

│ Bus Sleep freigegeben │

└────────────────────────────────────────┘

```

  • Zustandshysterese: ComMTMinFullComModeDuration erzwingt, dass ein Kanal nach dem Wechsel in COMM_FULL_COMMUNICATION für mindestens diese Zeitspanne verbleibt. Vorzeitige COMM_NO_COMMUNICATION-Anforderungen verbleiben im Status COMM_FULL_COMM_REQ_PENDING.
  • PNC-Sleep-Kaskade: Wenn ComMPncSupport == true, verzögert ComMPncPrepareSleepTimer das Abschalten der Transceiver, um In-Flight-NM-PDUs abzufangen und Race-Conditions auf dem Bus zu verhindern.
  • Synchroner vs. asynchroner Initialisierungsfluss:
  • Ist ComMGlobalNvMBlockDescriptor gesetzt, liest ComM_Init() bzw. der Startup-Task die Inhibitionszustände via NvM_ReadBlock() synchron oder per Job-Finish-Notification asynchron ein.
  • Fehlerpfad (DET): Ist ComMDevErrorDetect == true, schlägt jede API-Ausführung mit uninitialisiertem Stack (COMM_UNINIT) oder unzulässigem Mode-Parameter synchron via Det_ReportError(MODULE_ID_COMM, ...) an, anstatt still zu terminieren.

4. Normative Relevanz & Entwickler-Hinweise

  • Pre-Compile Footprint-Optimierung:
  • ComMPncSupport == false spart signifikant RAM und Flash, da PNC-Tabellen, ERA/IRA-Vektoren und NM-PDU-Mappings vom BSW-Generator gar nicht erzeugt werden (#if (COMM_PNC_SUPPORT == STD_ON)).
  • ComMDevErrorDetect == false eliminiert API-Parametervalidierungen im Release-Build.
  • Konfigurationsabhängigkeiten (Semantische Checks):
  • Wird ComMWakeupInhibitionEnabled == true oder ComMModeLimitationEnabled == true konfiguriert und soll die Inhibition nach einem Kl.30-Reset erhalten bleiben, muss ComMGlobalNvMBlockDescriptor auf einen persistenten RAM-Mirror-Block des NvM gemappt werden.
  • Ist ComMPncSupport == true, wird ComMPncPrepareSleepTimer zu einem zwingenden Timing-Parameter. Ist ComMPncSupport == false, sind ComMPncPrepareSleepTimer und ComMPncGatewayEnabled wirkungslos bzw. dürfen vom Konfigurator nicht instanziiert werden (Multiplizität 0..1).
  • Timing-Granularität:
  • Die Fließkommawerte (ComMTMinFullComModeDuration, ComMPncPrepareSleepTimer) werden im generierten Code auf ganzzahlige Ticks der periodischen Hauptfunktion heruntergebrochen:

$$\text{Ticks} = \left\lceil \frac{ComMTMinFullComModeDuration}{COMM\_MAIN\_FUNCTION\_PERIOD} \right\rceil$$

  • Liegt der Wert unterhalb der Periode von ComM_MainFunction_<x>, feuert der Timeout bereits im ersten Task-Zyklus.
