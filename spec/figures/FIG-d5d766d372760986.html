1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR BSW-Metamodell-Auszug (UML-Klassendiagramm) zur Definition der ECU-Konfigurationsparameter (ECUC ParamConf) für das BSW-Modul SwCluC (Software Cluster Connection) inklusive Kopplung an das AUTOSAR-M1-Systemmodell (SoftwareCluster-Metamodell).
  • Funktionale Einordnung: AUTOSAR Classic Platform (R20-11). Das Modul SwCluC realisiert die entkoppelte Interaktion zwischen unabhängig aktualisierbaren Software-Clustern (Host-Cluster und Application-Cluster). Dieses Konfigurationsmodell spezifiziert die Verifikationsstrukturen (SwCluCBaseConfigurationCheck), über die zur Laufzeit bzw. beim Start geprüft wird, ob die von einem Cluster erwarteten Schnittstellen/Ressourcen der Basis-Konfiguration des Service-Bereitstellers (z. B. via OsProxy) kompatibel sind.

2. Komponenten, Entitäten & Schnittstellen

ECUC-Konfigurationsebene (SwCluC)
  • SwCluC (EcucModuleDef): Wurzel-Moduldefinition des Software Cluster Connection Moduls ([0..1]).
  • SwCluCBaseConfigurationCheck (EcucParamConfContainerDef): Konfigurationscontainer ([0..*]), aggregiert via Komposition +container unter SwCluC. Bündelt die Prüfdeskriptoren für eine spezifische Cluster-Ressource.
  • SwCluCAutoBaseConfigDescriptor (EcucMultilineStringParamDef): Parameter ([0..*]), aggregiert via +parameter. Hält automatisch durch Generatoren erzeugte Hash-/Signatur-Strings der Basis-Konfiguration.
  • SwCluCUserBaseConfigDescriptor (EcucMultilineStringParamDef): Parameter ([0..1]), aggregiert via +parameter. Erlaubt dem Integrator manuell definierte Kompatibilitätsdeskriptoren zu hinterlegen.
  • SwCluCResourceRef (EcucForeignReferenceDef): Referenz (+reference), aggregiert via Komposition. Verweist modulübergreifend (from ProxyModules) via destinationType = CP-SOFTWARE-CLUSTER-SERVICE-RESOURCE auf das M1-Metamodell.
System-/Metamodell-Ebene (CPSoftware Cluster Resource Pool)
  • SoftwareCluster::CpSoftwareClusterResource (Identifiable): Abstrakte Basisklasse einer Cluster-Ressource mit:
    • + globalResourceId: PositiveInteger [0..1] – Eindeutige systemweite Ressourcen-ID.
    • + isMandatory: Boolean [0..1] – Kennzeichnung zwingend bereitzustellender Ressourcen.
  • SoftwareCluster::CpSoftwareClusterServiceResource: Spezialisierung (Generalization) von CpSoftwareClusterResource. Repräsentiert die konkrete Service-Ressource (Ziel der EcucForeignReferenceDef), die clusterübergreifend geprüft wird.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein statisches Konfigurationsmetamodell handelt, gilt für die zugehörige BSW-Laufzeit:

  1. Initialisierungs-Phase: Beim Start/Attachen eines Software-Clusters liest SwCluC die konfigurierten Instanzen von SwCluCBaseConfigurationCheck.
  2. Deskriptor-Abgleich: Für jede referenzierte CpSoftwareClusterServiceResource (über globalResourceId) vergleicht der SwCluC-Prüfmechanismus die im Ziel-Cluster hinterlegten Deskriptoren (SwCluCAutoBaseConfigDescriptor / SwCluCUserBaseConfigDescriptor) mit den tatsächlichen Deskriptoren des Host-/Basis-Clusters.
  3. Validierung & Fehlerbehandlung:
    • Match: Cluster-Verbindung und Inter-Cluster-Kommunikation für die Ressource werden freigegeben.
    • Mismatch / Fehlen bei isMandatory == TRUE: Die Initialisierung schlägt fehl. Es erfolgt Det-Meldung (DET_REPORT_ERROR) und/oder Eintrag im Dem; der Start des betroffenen Software-Clusters wird blockiert, um Inkompatibilitäten und undefinierte Speicher-/IPC-Zugriffe zu verhindern.

4. Normative Relevanz & Entwickler-Hinweise

  • Fremdreferenz-Auflösung (EcucForeignReferenceDef): BSW-Generatoren müssen zur Generierungszeit eine Cross-Modell-Validierung zwischen dem ECUC-Baum und der System-Description (ARXML, CPSoftware Cluster Resource Pool) durchführen; destinationType erzwingt Typkonformität zu CpSoftwareClusterServiceResource.
  • Generator-Vertrag (ECUC_SwCluC_00079): Die Mehrfachkardinalität von SwCluCAutoBaseConfigDescriptor ([0..*]) erlaubt versionierte oder segmentierte Signaturen. Generatoren müssen deterministische Hashes aus den relevanten BSW-/OS-Konfigurationen (z. B. Memory Layouts, Task-IDs, IPC-Endpunkte) ableiten.
  • Integrations-Restriktion: Manuelle Deskriptoren (SwCluCUserBaseConfigDescriptor, max. 1) überschreiben automatische Prüfungen nicht zwingend, sondern dienen als zusätzlicher Sicherheitsanker bei asynchronen Software-Updates über OTA (Over-The-Air) zwecks Release-Kompatibilitätsnachweis.
