1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Spezifikation des ECU State Managers (AUTOSAR Classic Platform). Das Diagramm illustriert das Wakeup-Szenario eines LIN-Transceivers über einen Hardware-Interrupt („LIN transceiver wake up by interrupt“) während des Übergangs von der Schlafphase (GOSLEEP / SLEEP) über den CPU-Zustand HALT zurück in die Wakeup-Phase (WAKEUP I).

3. Dynamisches Verhalten & Sequenzablauf

Der dynamische Ablauf gliedert sich in drei Hauptphasen:

  1. Vorbereitung und Eintritt in den Sleep-Modus (GOSLEEP bis SLEEP / HALT):
  • Im Zustand GOSLEEP ruft EcuM den Integration Code via EcuM_EnableWakeupSources(...) auf, welcher über Icu_EnableWakeup(...) die Wakeup-Quelle im ICU-Modul scharfschaltet. (Hinweis: LinSM hat zuvor bereits LinIf_GotoSleep beim Wechsel nach NO_COM aufgerufen).
  • EcuM sperrt den Scheduler durch Anfordern der Scheduler-Ressource via Os-Aufruf GetResource(uint8).
  • Nach Erreichen von SLEEP deaktiviert EcuM alle Interrupts via DisableAllInterrupts() und versetzt das System via Mcu_SetMode(Mcu_ModeType) in den Zustand HALT.
  1. Wakeup-Interrupt-Behandlung:
  • Die Lin Transceiver Hardware detektiert ein Wakeup-Signal und triggert einen Wakeup interrupt() an der Icu.
  • Die ISR der Icu ruft im Integration Code EcuM_CheckWakeup(...) auf.
  • Der Integration Code führt Activate PLL() aus und leitet die Prüfung kaskadiert weiter über LinIf_CheckWakeup(...) an LinIf und weiter über LinTrcv_CheckWakeup(...) an LinTrcv.
  • LinTrcv meldet das validierte Wakeup-Ereignis via EcuM_SetWakeupEvent(...) an den EcuM.
  • Die Aufrufskette kehrt zurück, und die Icu beendet die ISR mit Return from interrupt().
  1. Aufwachen nach HALT (WAKEUP I):
  • Der MCU-Befehlszähler setzt die Ausführung unmittelbar nach der HALT-Instruktion fort.
  • EcuM ruft Mcu_SetMode() auf und schaltet Interrupts via EnableAllInterrupts() temporär frei.
  • Im Zustand WAKEUP I deaktiviert EcuM kurzzeitig wieder alle Interrupts (DisableAllInterrupts()), setzt den MCU-Modus über Mcu_SetMode(Mcu_ModeType) und aktiviert Interrupts erneut via EnableAllInterrupts().
  • EcuM deaktiviert die Wakeup-Quellen über EcuM_DisableWakeupSources(...), woraufhin der Integration Code Icu_DisableWakeup(...) aufruft.
  • Abschließend gibt EcuM die Scheduler-Ressource über ReleaseResource(uint8) frei, sodass andere Betriebssystem-Tasks wieder ausgeführt werden können.

4. Normative Relevanz & Entwickler-Hinweise

  • Scheduler-Ressourcensicherung: Vor Eintritt in den Halt-Zustand muss die Scheduler-Ressource belegt werden (GetResource(uint8)), um sicherzustellen, dass nach Auftreten eines ISR-Kategorie-2-Interrupts kein sofortiges Re-Scheduling stattfindet, sondern der Kontrollfluss direkt hinter der HALT-Instruktion im EcuM fortfährt.
  • Nach Abarbeitung der Wakeup-Initialisierungsphase (WAKEUP I) muss die Scheduler-Ressource zwingend wieder freigegeben werden (ReleaseResource(uint8)).
  • LIN-Interface-Zustand: Der LinSM hat vor diesem Ablauf bereits LinIf_GotoSleep ausgeführt. Abhängig von der Konfiguration ist der LIN-Controller im Schlafzustand aufweckbar oder nicht.
  • Kaskadierte Wakeup-Validierung: Die synchrone Validierung der Wakeup-Quelle erfolgt über den Pfad ICU -> Integration Code -> LinIf -> LinTrcv -> EcuM_SetWakeupEvent.
  • PLL-Aktivierung: Im Integration-Code-Callout muss die PLL reaktiviert werden (Activate PLL()), bevor die Kommunikation mit den Kommunikationsmodulen (LinIf, LinTrcv) abgewickelt wird.
