1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Hybrides Architektur- und Interaktionsdiagramm (Schichten- und Datenflussdarstellung mit asynchronem Callout-/Callback-Muster).
  • Funktionaler Zweck: Erfassung hardwarebasierter Paketfilter-Statistiken aus einem Ethernet-Switch und Weiterleitung an das Intrusion Detection System Manager (IdsM) Framework via Security Events (Sev).
  • Architektur-Einordnung: Schnittstelle zwischen AUTOSAR Firewall (Fw), Ethernet Interface (EthIf), Ethernet Switch Driver (EthSwt) und dem physischen Ethernet-Switch (Hardware). Dient der Entlastung des Host-Controllers durch Aggregation („Bucketing“) von Per-Stream-Filtering-Zählern (z. B. gemäß IEEE 802.1Qci / Stream Filter and Policing) direkt in der Switch-Hardware und periodischer Auswertung in der BSW.

2. Komponenten, Entitäten & Schnittstellen

  • Beteiligte BSW-Module & Entitäten:
    • Fw (AUTOSAR Firewall BSW): Initiiert die Statistikabfrage, vergleicht Zählerstände mit dem vorherigen Poll-Zyklus und meldet Sicherheitsereignisse.
    • EthIf (Ethernet Interface): Vermittlungsschicht, routet API-Aufrufe zwischen Switch-unabhängiger BSW und treiberspezifischen Instanzen via SwitchIdx.
    • EthSwt Drv (Ethernet Switch Driver): Treibermodul zur Hardware-Steuerung und Extraktion der Zählerstände.
    • EthTrcv Drv & EthDrv: Kontextuelle Treiberkomponenten des AUTOSAR Ethernet-Stacks (in diesem Ablauf nicht aktiv eingebunden).
    • Switch (Hardware-Ebene): Beinhaltet konfigurierte Regelfilter-Buckets.
    • Sev (Security Event): IdsM-Event-Artefakt SEV_FW_PACKET_BLOCKED_BY_PERSTREAMFILTERING.
  • Hardware-Datenstruktur (Bucket-Aggregation):
    • Bucket: Gruppiert mehrere Stream-Handles zur Begrenzung von Hardware-Ressourcen/Zählern (Beispiel: Bucket 1 = Handles 1–20, Bucket 2 = Handles 21–50, Bucket 3 = Default-Regel).
    • Zähler (Count): Akkumulierter Drop-/Block-Zähler der jeweiligen Filtergruppe.
  • Schnittstellen (APIs):
    • Request (synchroner Downward-Call):
      • EthIf_GetStreamStatistics(uint8 SwitchIdx)
      • EthSwt_GetStreamStatistics(uint8 SwitchIdx)
    • Response (asynchroner Upward-Callback):
      • EthIf_StreamStatisticsIndication(uint8 SwitchIdx, uint8 NumberOfBuckets, const Eth_StreamStatisticCounterType* ListOfBucketsPtr)
      • Fw_StreamStatisticsIndication(uint8 SwitchIdx, uint8 NumberOfBuckets, const Eth_StreamStatisticCounterType* ListOfBucketsPtr)
    • Sicherheitsereignis-Parameter (Context Data):
      • Bucket ID (uint8)
      • Count Value (Zählerstand zum Blockierungszeitpunkt)

3. Dynamisches Verhalten & Sequenzablauf

  1. Trigger / Polling-Initiierung:
    • Periodischer Task oder MainFunction der Fw triggert die Abfrage über EthIf_GetStreamStatistics(SwitchIdx).
  2. Weiterleitung an den Treiber:
    • EthIf leitet den Request an den adressierten Switch-Treiber weiter: EthSwt_GetStreamStatistics(SwitchIdx).
  3. Hardware-Readout:
    • EthSwt Drv liest (z. B. via SPI/MDIO/Memory Mapped I/O) die Bucket-Zähler der Switch-Hardware aus.
  4. Asynchrone Rückmeldung (Callback-Kaskade):
    • Nach erfolgreicher Registerauslese ruft EthSwt Drv den Callback EthIf_StreamStatisticsIndication(...) auf.
    • EthIf propagiert die Statistikdaten unverändert an Fw_StreamStatisticsIndication(...).
    • Übergabeparameter umfassen den Switch-Index, die Anzahl der gültigen Buckets (NumberOfBuckets) sowie einen Zeiger auf die Zählerstrukturen (ListOfBucketsPtr vom Typ const Eth_StreamStatisticCounterType*).
  5. Delta-Evaluierung & Event-Triggering:
    • Die Fw vergleicht den gemeldeten Zählerwert jedes Buckets mit dem lokal gespeicherten Zustand des vorangegangenen Polls.
    • Bedingung: Count_aktuell > Count_vorherig.
    • Aktion: Bei positivem Delta setzt die Fw das Security Event SEV_FW_PACKET_BLOCKED_BY_PERSTREAMFILTERING inklusive Bucket ID und Count Value an den IdsM ab.

4. Normative Relevanz & Entwickler-Hinweise

  • Puffer- und Pointer-Lebenszyklus:
    • Der Zeiger ListOfBucketsPtr ist nur für die Dauer der Ausführung des Callbacks Fw_StreamStatisticsIndication gültig. Modul Fw muss die Daten synchron in interne Strukturen kopieren; kein asynchrones De-Referenzieren zulässig.
  • Hardware-Limitierung & Bucketing-Strategie:
    • Da Hardware-Switche oft nicht genügend Zähler für hunderte Streams (IEEE 802.1Qci Stream Filters) bereitstellen, müssen Integratoren Streams logisch in Buckets aggregieren. Ein Sicherheitsereignis liefert damit nur Bucket-Granularität, keine direkte Stream-ID.
  • Polling-Frequenz vs. Überlauf:
    • Das Polling-Intervall der Fw muss so gewählt werden, dass Hardware-Zähler (häufig 16- oder 32-Bit-Register) zwischen zwei Abfragen nicht überlaufen (Wrap-Around-Erkennung implementieren).
  • IdsM-Lastbegrenzung (Rate Limiting):
    • Ein kontinuierlicher Paketsturm führt pro Poll-Intervall zu neuen Events. Entwickler müssen im IdsM / FireWall-Konfigurationssatz Filter- und Throttling-Mechanismen aktivieren, um ein Überfluten des Event-Puffers und der Security-Event-Queue zu vermeiden.
