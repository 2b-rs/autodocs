1. Diagrammtyp & Architektur-Kontext

UML-Aktivitätsdiagramm zur Darstellung des Ablaufs zur Löschung diagnostischer Ereignisse und Rücknahme von Warnindikatoren innerhalb des AUTOSAR Classic Diagnostic Event Managers (Dem).

2. Komponenten, Entitäten & Schnittstellen

  • Startknoten mit Trigger [event qualified as PASSED]
  • Entscheidungsknoten:
  • Check WarningIndicator Request bit = 1
  • Check Warning-IndicatorOffCondition
  • Event memory entry exists
  • Aging completed
  • Zusammenführungsknoten (Merge Node) vor der Prüfung des Ereignisspeichereintrags
  • Aktionen:
  • Process healing
  • WarningIndicator Request bit = 0
  • Process aging
  • Delete event memory entry
  • ConfirmedDTC bit = 0
  • Endknoten (Aktivitätsendknoten)
  • Schnittstellen/Statusflags: WarningIndicator-Request-Bit, UDS-Statusbit ConfirmedDTC (Bit 3), Event-Memory-Eintrag, Aging-Zustand

3. Dynamisches Verhalten & Sequenzablauf

  1. Der Ablauf startet, sobald ein Ereignis als bestanden gewertet wird ([event qualified as PASSED]).
  2. Prüfung von Check WarningIndicator Request bit = 1:
  • Ist das Bit gesetzt ([TRUE]), wird die Aktion Process healing ausgeführt.
  • Ist das Bit nicht gesetzt ([FALSE]), wird der Heilungspfad übersprungen und vor die Prüfung des Ereignisspeichers verzweigt.
  1. Nach Process healing wird Check Warning-IndicatorOffCondition geprüft:
  • Bei Erfüllung ([TRUE]) wird die Aktion WarningIndicator Request bit = 0 ausgeführt.
  • Ist die Bedingung nicht erfüllt ([FALSE]), führt der Pfad direkt zum Aktivitätsendknoten.
  1. Nach dem Zurücksetzen des Warnindikators oder bei anfänglich nicht gesetztem Request-Bit folgt die Prüfung Event memory entry exists:
  • Existiert ein Eintrag ([TRUE]), wird Process aging durchlaufen.
  • Existiert kein Eintrag ([FALSE]), endet der Ablauf am Aktivitätsendknoten.
  1. Nach Process aging prüft Aging completed:
  • Ist die Alterung abgeschlossen ([TRUE]), wird nacheinander Delete event memory entry und ConfirmedDTC bit = 0 ausgeführt, bevor der Ablauf am Endknoten endet.
  • Ist die Alterung nicht abgeschlossen ([FALSE]), endet der Ablauf direkt am Aktivitätsendknoten.

4. Normative Relevanz & Entwickler-Hinweise

Normativer Ablauf für die Deaktivierung von Warnindikatoren (Healing) und das Löschen von Fehlerspeichereinträgen inklusive Rücksetzen des ConfirmedDTC-Bits (Aging) im Dem. Entwickler müssen beachten, dass das Aging erst nach erfolgreicher Deaktivierung des Warnindikators bzw. bei inaktivem Warnindikator durchlaufen wird und dass ohne bestehenden Ereignisspeichereintrag keine Alterung stattfindet.
