1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm (Ausschnitt des M2-Metamodells der AUTOSAR Classic Platform, Diagnostic Extract Template / DEXT, Release R22-11).
  • Technischer Zweck & Einordnung:
  • Das Metamodell definiert die statische Spezialisierungshierarchie der Klasse [DiagnosticMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticMapping) zur standardisierten Einbindung des Nutzfahrzeug-Diagnoseprotokolls SAE J1939 in das AUTOSAR-Diagnoseextrakt (DEXT).
  • Es entkoppelt und verbindet generische Diagnoseelemente (Events, SWC-Schnittstellen, Datenbezeichner) mit den J1939-spezifischen Diagnosestrukturen (DTCs bestehend aus SPN und FMI) für die Konfiguration der BSW-Module Dem (Diagnostic Event Manager) und J1939Dcm (J1939 Diagnostic Communication Manager).

2. Komponenten, Entitäten & Schnittstellen

  • Erbt von der Metaklasse DiagnosticCommonElement (und transitiv von ARElement, PackageableElement, Identifiable).
  • Abstrakte Basisklasse aller Zuordnungsentitäten im DEXT.
  • [DiagnosticSwMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticSwMapping) (kursiv: abstrakt):
  • Generalisierung: Spezialisiert [DiagnosticMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticMapping).
  • Abstrakter Anker für Mappings zwischen Diagnoseanforderungen und AUTOSAR Software-Komponenten (SW-C-Ports, Runnable Entities, Inter-Element-Verbindungen).
  • [DiagnosticEventToTroubleCodeJ1939Mapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticEventToTroubleCodeJ1939Mapping) (konkret):
  • Generalisierung: Spezialisiert direkt [DiagnosticMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticMapping).
  • Verknüpft ein generisches Diagnose-Event (DiagnosticEvent / BSW-DemEvent) mit einem J1939-Fehlercode (DiagnosticTroubleCodeJ1939).
  • [DiagnosticJ1939SpnMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticJ1939SpnMapping) (konkret):
  • Generalisierung: Spezialisiert direkt [DiagnosticMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticMapping).

  • [DiagnosticJ1939SwMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticJ1939SwMapping) (konkret):
  • Generalisierung: Spezialisiert [DiagnosticSwMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticSwMapping).
  • Bildet J1939-spezifische Diagnoseelemente direkt auf Ports bzw. Datenelemente von Application Software Components (SW-Cs) ab.

3. Dynamisches Verhalten & Sequenzablauf

  • Klassifikation: Reines statisches Strukturmodell (M2-Metamodell / XML-Schema-Definition). Keine direkte Laufzeitsequenz auf Modellebene.
  • Transformatorisches Laufzeitverhalten (Generierungskontext & BSW-Ausführung):
  1. Konfigurationsphase: Die Mappings werden während des RTE- und BSW-Generierungsprozesses aufgelöst, um die Parameter für Dem (z. B. DemEventParameter, DemJ1939DTC, DemSPNClass) und J1939Dcm konsistent zu generieren.
  2. Event-Reporting (Laufzeit): Tritt ein Fehler in einer SW-C oder einem BSW-Treiber auf, erfolgt der Call Dem_SetEventStatus(EventId, Status). Das über [DiagnosticEventToTroubleCodeJ1939Mapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticEventToTroubleCodeJ1939Mapping) verknüpfte J1939-DTC aktualisiert Status-Bits (MIL, Red Stop Lamp, Amber Warning Lamp, Occurrence Count).
  3. Diagnoseabfrage (J1939-Stack): Trifft eine J1939-Diagnoseanfrage (z. B. DM1 via PGN 65226 oder DM2 via PGN 65227) über das CAN-Interface (CanIf $\rightarrow$ J1939Tp $\rightarrow$ J1939Dcm) ein, fragt J1939Dcm die SPN- und DTC-Zustände aus dem Dem ab. Das Mapping via [DiagnosticJ1939SpnMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticJ1939SpnMapping) und [DiagnosticJ1939SwMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticJ1939SwMapping) stellt sicher, dass Datenwerte korrekt codiert im J1939-PDU-Format übertragen werden.

4. Normative Relevanz & Entwickler-Hinweise

  • DEXT-Autorenschaft & Import:
  • Werkzeuge zur Diagnosekonfiguration müssen bei J1939-fähigen Steuergeräten Instanzen dieser Mappings im DEXT erzeugen. Fehlen diese Mappings, kann der Upstream-Generator (DEXT-to-ECUC-Transformer) keine J1939-spezifischen Dem-Behälter generieren.
  • BSW-Konfiguration (Dem / J1939Dcm / J1939Rm):
  • [DiagnosticEventToTroubleCodeJ1939Mapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticEventToTroubleCodeJ1939Mapping) erzwingt die Existenz gültiger Verweise auf ein DiagnosticEvent und ein DiagnosticTroubleCodeJ1939 (SPN + FMI) im selben Diagnoseextrakt. Ein Event kann parallel auf einen UDS-DTC (DiagnosticTroubleCodeUds) und einen J1939-DTC abgebildet werden.
  • SPN-Definitionen unterliegen festen Bitlängen und Skalierungsregeln gemäß SAE J1939-71; Entwickler müssen sicherstellen, dass die verknüpften Datentypen (via [DiagnosticJ1939SwMapping](file:///private/tmp/autodocs-worktrees/task-figure-evidence/DiagnosticJ1939SwMapping)) binärkompatibel zu den standardisierten SPN-Payloads sind.
  • Constraint-Prüfungen:
  • Bei vollständigem DEXT-Stand müssen alle referenzierten Zielobjekte (DiagnosticEvent, DiagnosticTroubleCodeJ1939, DiagnosticJ1939Spn) zwingend aufgelöst werden können (analoge Gültigkeit zu constr_10084 / constr_10085). Unvollständige Referenzen führen zu Generierungsfehlern im Integrationsschritt.
