1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: PDU-Layout / Wire-Format-Spezifikation (Bit-Grid, 32-Bit-Raster, Big-Endian / Network Byte Order).
  • Technischer Zweck: Definition des binären On-the-Wire-Serialisierungsformats der IPv6 SD Endpoint Option innerhalb des SOME/IP Service Discovery Protokolls (Sd-Modul in AUTOSAR Classic, ara::com / Communication Management in AUTOSAR Adaptive).
  • Funktionale Einordnung: Dient dem Austausch von Netzwerkkonfigurationsdaten (IPv6-Unicast-Endpunkt, Transportprotokoll, Port) zur Laufzeit. Sie wird an SD-Entries (z. B. FindService, OfferService, SubscribeEventgroup, SubscribeEventgroupAck) angehängt, um dynamische Service-Verbindungen und Event-Streaming über IPv6/UDP bzw. IPv6/TCP zu initiieren.

3. Dynamisches Verhalten & Sequenzablauf

  1. Serialisierung (Sender-Pfad):
  • Das Sd-Modul (CP) bzw. Communication Management (AP) empfängt vom BSW/Service-Manager den Trigger zum Veröffentlichen einer Instanz (OfferService) oder Eventgruppe (SubscribeEventgroup).
  • Die IPv6-Adresse und der Port werden aus dem lokalen SoAd / TcpIp-Stack bzw. der Manifest-Konfiguration bezogen.
  • Length wird fest auf 0x0015 und Type auf 0x26 kodiert. Die Datenfelder werden in Network Byte Order (Big-Endian) in das Options Array der SD-PDU serialisiert.
  1. Deserialisierung & Validierung (Empfänger-Pfad):
  • Sd_RxIndication() nimmt die PDU vom Socket Adapter (SoAd) entgegen.
  • Validierungsprüfungen (SWS_Sd_00663, PRS_SOMEIPSD_00654):
  • Prüfung auf korrekte Länge: Length == 0x0015. Falls abweichend, wird die Option verworfen (Malformed Option).
  • Prüfung auf Type == 0x26.
  • Prüfung von L4-Proto: Muss dem konfigurierten Transportprotokoll der referenzierten Service-Schnittstelle entsprechen (TCP oder UDP).
  • Prüfung von Port Number: Darf nicht 0 sein, wenn ein definierter Endpunkt erwartet wird.
  1. Fehlerbehandlung:
  • Bei Längen-, Typ- oder Syntaxverletzungen wird die Option ignoriert und optional SD_E_MALFORMED_MESSAGE an das Default Error Tracer (Det) Modul gemeldet. Der verbleibende SD-PDU-Inhalt wird gemäß Spezifikation weiterverarbeitet, sofern der Entry ohne Endpoint-Option auswertbar ist.

4. Normative Relevanz & Entwickler-Hinweise

  • Längenberechnung (Falle für Parser-Implementierer):
  • Das Feld Length umfasst nicht die gesamte Option (24 Bytes) und auch nicht die Option ab dem Feld Length (22 Bytes), sondern exakt 21 Bytes (0x0015), beginnend beim ersten Reserved-Feld (Bytes 3 bis 23). Dies ist zwingend bei der Dekodierung zu beachten.
  • Robuste Auswertung von Reserved-Feldern:
  • Sender müssen beide Reserved-Felder zwingend auf 0x00 setzen (PRS_SOMEIPSD_00557, PRS_SOMEIPSD_00859).
  • Empfänger dürfen SD-Optionen nicht verwerfen, wenn Reserved != 0x00 ist (Robustness Principle).
  • SoAd- und Socket-Bindung:
  • Im BSW-Stack (Classic) steuert der Inhalt dieser Option das dynamische Erzeugen/Binden von Remote-Sockets in SoAd (SoAdSocketRemoteAddress, SoAd_SetRemoteAddr()).
  • Wenn im Manifest Port 0 spezifiziert ist, muss zur Laufzeit ein ephemerer Port allokiert und in das Feld Port Number eingesetzt werden (PRS_SOMEIPSD_00837).
  • Endpunkt-Restriktion:
  • Die Option spezifiziert strikt Unicast-Endpunkte. Für Multicast-Event-Verteilung muss stattdessen die entsprechende Multicast-Option verwendet werden.
