1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: SPEM 2.0-basiertes Aktivitäts- und Task-Dekompositionsdiagramm der AUTOSAR-Methodik (Software & Systems Process Engineering Metamodel).
  • Technischer Zweck: Spezifikation des durchgängigen Workflows zur Erfassung, Konsolidierung und Generierung von Mess- und Kalibrierdaten (MC – Measurement and Calibration) für Software-Components (SWCs) und Basissoftware (BSW) im AUTOSAR Classic Release 4.0.3. Es definiert die kausalen Abhängigkeiten zwischen Design (VFB/Internal Behavior), globaler Namenseindeutigkeit (Flat Map) und den Generierungsschritten für RTE, BSW, A2L und ECU-Executable.

2. Komponenten, Entitäten & Schnittstellen

  • Zentrale Aktivität (Root Use Case):
    • Calibration Overview
  • Zusammengesetzte Aktivitäten (Compound Tasks / Activities):
    • Define Cross-component Calibration Parameters: Erfassung komponentengreifender Parameter (Shared Calibration über Parameter-SWCs).
    • Define Local Calibration Parameters: Erfassung komponenteninterner Parameter für SWCs und BSW-Module.
    • Provide Unique Parameter Names: Eindeutige Auflösung von Instanzpfaden und Namenskollisionen für Kalibriertools.
    • Re-generate RTE and Calibration Support: Erzeugung des kalibrierfähigen Laufzeit- und BSW-Codes, der Funktionsmodelle sowie der zugehörigen MC-Support-Beschreibungen.
  • Elementare Tasks (Leaf Tasks) & Rollenbeziehungen:
    • Unter Define Cross-component Calibration Parameters:
      • Define VFB Interfaces (Definition von ParameterInterface)
      • Define VFB Parameter Component (Definition von ParameterSwComponentType)
      • Define VFB Composition Component
      • Define VFB Types mit Rolle +Define VFB Types for Parameter Interfaces
    • Unter Define Local Calibration Parameters:
      • Define VFB Types mit Rolle +Define VFB types for Local Calibration
      • Define Atomic Software Component Internal Behavior mit Rolle +Define Calibration Parameters in Internal Behavior (ParameterDataPrototype in perInstanceParameter / sharedParameter)
      • Define Partial Flat Map (Erstellung lokaler FlatInstanceDescriptor-Strukturen)
      • Define BSW Behavior mit Rolle +Define local Calibration Parameters in BSW
    • Unter Provide Unique Parameter Names:
      • Define Alias Names (Vergabe kurzer/eindeutiger A2L-kompatibler Bezeichner)
      • Generate or Adjust System Flat Map (Konsolidierung aller Partial Flat Maps zum Gesamtsystem)
      • Generate ECU Extract (Compound Task: Extrahieren der ECU-spezifischen Konfiguration)
    • Unter Re-generate RTE and Calibration Support:
      • Generate BSW Configuration Code
      • Generate Local MC Data Support (Extrahieren von MC-Metadaten aus BSW/RTE)
      • Provide RTE Calibration Dataset (Initialwerte und Initialisierungsstrukturen)
      • Generate RTE
      • Create MC Function Model (Strukturierung von Mess- und Kalibriergrößen in funktionale Einheiten für Kalibriertools)
    • Direkt unter Calibration Overview:
      • Generate ECU Executable (Compile/Link-Prozess zur Adressbindung)
      • Generate A2L (ASAM MCD-2 MC / A2L-Generierung mit Symboladressen)
  • Stereotypen & Kanten:
    • «nesting»: Komposition/Hierarchische Einbettung von Tasks in Aktivitäten.
    • «predecessor»: Gerichtete Kontroll- bzw. Datenflussabhängigkeit (zwingende Vorgänger-Bedingung).

3. Dynamisches Verhalten & Sequenzablauf

  1. Parallelphase: Parameter-Definition
    • Cross-Component Path: Modellierung der Parameter-Schnittstellen (ParameterInterface), Typen und Komponenten (ParameterSwComponentType) in Define Cross-component Calibration Parameters.
    • Local Path: Definition interner Parameter auf SWC-Ebene (Define Atomic Software Component Internal Behavior) und BSW-Ebene (Define BSW Behavior) inklusive lokaler Namenszuordnungen (Define Partial Flat Map) in Define Local Calibration Parameters. Beide Pfade teilen sich grundlegende Typdefinitionen über Define VFB Types.
  2. Synchronisation & Namensauflösung
    • Die Aktivität Provide Unique Parameter Names besitzt «predecessor»-Abhängigkeiten zu beiden vorhergehenden Definitionsaktivitäten.
    • Sie konsolidiert die lokalen Flat Maps im Systemkontext (Generate or Adjust System Flat Map), vergibt eindeutige Bezeichner (Define Alias Names) und integriert den ECU-Auszug (Generate ECU Extract).
  3. Generierung & Artefakterstellung
    • Nachgelagert («predecessor» von Provide Unique Parameter Names) erfolgt Re-generate RTE and Calibration Support. Hier werden BSW-Konfigurationscode (Generate BSW Configuration Code), RTE-Code (Generate RTE), Kalibrierdatensätze (Provide RTE Calibration Dataset), MC-Funktionsmodelle (Create MC Function Model) sowie lokale MC-Daten (Generate Local MC Data Support) erzeugt.
  4. Finalisierung auf ECU-Ebene
    • Direkt unter Calibration Overview eingebettet folgen abschließend Generate ECU Executable sowie Generate A2L.

4. Normative Relevanz & Entwickler-Hinweise

  • Methodik-Konformität: Die Kanten mit «predecessor» erzwingen eine strikte Abfolge: Kalibrierparameter müssen vor der Erzeugung der System Flat Map modelliert werden; RTE- und MC-Support-Generierung setzt eine konsolidierte Flat Map voraus.
  • Funktionsorientierte Kalibrierung: Durch die Einbindung von Create MC Function Model können Kalibrier- und Messgrößen im Rahmen der MC-Generierung modular in Funktionshierarchien (z. B. für ASAM MCD-2 MC FUNCTION-Strukturen) gruppiert werden.
  • Rollenbasierte Task-Wiederverwendung: Der generische Task Define VFB Types wird mit zwei disjunkten Rollen (+Define VFB Types for Parameter Interfaces vs. +Define VFB types for Local Calibration) in unterschiedlichen Teilaktivitäten wiederverwendet.
  • A2L-Generierung: Die Erzeugung der A2L-Datei (Generate A2L) und des Executables (Generate ECU Executable) erfolgt als integraler Bestandteil des Kalibrierungs-Gesamtprozesses zur Verknüpfung logischer Kalibrierelemente mit konkreten Speicheradressen.
