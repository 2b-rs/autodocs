1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm (sd LinSm Go-to-sleep process) im Kontext der AUTOSAR Classic Platform (Communication Stack / BSW). Es visualisiert den standardisierten Ablauf zum Herunterfahren bzw. Schlafenlegen eines LIN-Clusters (Goto-Sleep-Prozess) über den LIN State Manager (LinSM). Beteiligt sind die BSW-Module Kommunikationsmanager (ComM), LIN State Manager (LinSM), LIN Interface (LinIf) und Basic Software Mode Manager (BswM).

2. Komponenten, Entitäten & Schnittstellen

Modul-Lebenslinien (Stereotyp «module»):

  • ComM::ComM: Communication Manager als Auslöser der Kommunikationsmodus-Anforderung und Empfänger der Modusbestätigung.
  • LinSm::LinSM: LIN State Manager als zentrale Koordinationsinstanz des Zustandswechsels.
  • LinIf::LinIf: LIN Interface als Abstraktionsschicht zur Hardwareansteuerung des Busses.
  • BswM::BswM: Basic Software Mode Manager zur systemweiten Zustandsüberwachung.

Schnittstellen und Nachrichten:

  • LinSM_RequestComMode(Std_ReturnType, NetworkHandleType, ComM_ModeType): Synchroner Aufruf von ComM an LinSM (Bedingung [mode=NO_COM]).
  • LinIf_GotoSleep(Std_ReturnType, NetworkHandleType): Synchroner Aufruf von LinSM an LinIf.
  • Interne Operationen LinSM: start_timer(), stop_timer(), setmode LINSM_NO_COM().
  • LinSM_GotoSleepConfirmation(NetworkHandleType, boolean): Asynchroner Bestätigungs-Callback von LinIf an LinSM (Bedingung [success=true]).
  • ComM_BusSM_Mode Indication(NetworkHandleType, ComM_ModeType*): Bestätigung an ComM (Bedingung [mode=NO_COM]).
  • BswM_LinSM_CurrentState(LinSM_ModeType, NetworkHandleType): Zustandsindikation an BswM (Bedingung [mode=NO_COM]).

3. Dynamisches Verhalten & Sequenzablauf

  1. ComM fordert bei LinSM den Übergang in NO_COM an (LinSM_RequestComMode).
  2. LinSM ruft synchron LinIf_GotoSleep auf LinIf auf; LinIf antwortet unmittelbar.
  3. LinSM startet einen Überwachungstimer (start_timer()) und sendet den Return an ComM.
  4. Nach erfolgreichem Einschlafen des Busses meldet LinIf asynchron die Bestätigung via LinSM_GotoSleepConfirmation(..., success=true).
  5. LinSM stoppt den Timer (stop_timer()) und setzt den internen Zustand auf LINSM_NO_COM (setmode LINSM_NO_COM()).
  6. LinSM meldet den neuen Modus NO_COM synchron an ComM (ComM_BusSM_Mode Indication).
  7. LinSM meldet den neuen Zustand NO_COM synchron an BswM (BswM_LinSM_CurrentState).
  8. LinSM quittiert den Callback-Aufruf gegenüber LinIf.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm spezifiziert das Standardverhalten für das reguläre Schlafenlegen eines LIN-Netzwerks (LINSM_NO_COM) bei positivem Bestätigungsverlauf (success=true). Entwickler müssen beachten:

  • Die Kommunikation zum Bus erfolgt über das LinIf, wobei der Quittungszeitraum durch einen internen Timer überwacht wird.
  • Modusänderungen müssen sowohl dem ComM als auch dem BswM mitgeteilt werden.
  • Die im Diagramm dargestellten Typsignaturen nutzen AUTOSAR-Basis- und Stacktypen (NetworkHandleType, ComM_ModeType, LinSM_ModeType, Std_ReturnType, boolean).
