  • Klassifikation: UML-Aktivitätsdiagramm (UML Activity Diagram) zur Spezifikation des Kontrollflusses einer normativen E2E-Bibliotheksfunktion.
  • Architektur-Kontext:
    • Komponente: AUTOSAR E2E Library (E2E), Foundation / Classic Platform / Adaptive Platform.
    • Funktion: Sub-Aktivität „Verify inputs of the forward function“ der C-Funktion E2E_PXXmForward() (wobei XX als Platzhalter für ein konkretes E2E-Methodenprofil steht, z. B. Profile für Client/Server- bzw. RPC-/SOME/IP-Methodenkommunikation wie Profile 07m/22m).
    • Funktionaler Zweck: Deterministische Eingangsparameter-Validierung (Null-Pointer-, Längen-, Wertebereichs- und Statusprüfungen) vor der Transformation bzw. Weiterleitung (Forwarding) einer geschützten Methoden-PDU. Sie fungiert als sicherheitskritische Guard-Schicht gegen Fehlzugriffe (z. B. Null-Pointer-Dereferenzierung, Buffer Overflows oder out-of-range Enum-Werte).

2. Komponenten, Entitäten & Schnittstellen

  • Akteur / Funktionseinheit:
    • E2E_PXXmForward(): Normative API-Funktion des E2E-Methodenprofils XX.
  • Funktionsparameter & Datenstrukturen:
    • Config (const E2E_PXXmConfigType*): Zeiger auf die konstante Profil-Konfigurationsstruktur. Enthält u. a.:
      • MinDataLength: Minimale PDU-Länge in Bit.
      • MaxDataLength: Maximale PDU-Länge in Bit.
    • State (E2E_PXXmProtectStateType* / E2E_PXXmCheckStateType*): Zeiger auf den internen RAM-Zustand des Profils (z. B. Sequenzzähler, Historie).
    • Data (uint8*): Zeiger auf den Nutzdatenpuffer (Serialisierte PDU).
    • Length (uint32): Länge der Nutzdaten in Byte.
    • ForwardStatus (E2E_PCheckStatusType* bzw. Wert): Status der vorhergehenden Prüfung (z. B. E2E_P_OK, E2E_P_NONEWDATA).
    • SourceID (uint32): Eindeutige Methoden-/Client-Kennung (28-Bit Identifier).
    • MessageType (uint8 / Enum): Nachrichtentyp (0: Request, 1: Response).
    • MessageResult (uint8 / Enum): Ergebnisstatus des Methodenaufrufs (0: OK, 1: ERROR).
  • Ergebniszustände (Activity Final Nodes):
    • null input: Ein oder mehrere essenzielle Zeiger sind NULL (führt i. d. R. zur Rückgabe von E2E_E_INPUTERR_NULL).
    • wrong input: Parameterwerte liegen außerhalb definierter Schranken (führt i. d. R. zur Rückgabe von E2E_E_INPUTERR_WRONG).
    • input ok: Alle Validierungen erfolgreich; Übergang zur eigentlichen Forwarding-Logik.

3. Dynamisches Verhalten & Sequenzablauf

Die Ausführung erfolgt streng sequenziell, synchron und deterministisch ohne Callbacks oder asynchrone Verzweigungen:

  1. Initial Node: Start der Sub-Routine nach Aufruf von E2E_PXXmForward().
  2. Phase 1 – Null-Pointer-Check:
    • Bedingung: (Config != NULL) && (State != NULL) && (Data != NULL) && (ForwardStatus != NULL)
    • [FALSE] → Direkter Abbruch zu Endknoten null input.
    • [TRUE] → Weiter zu Phase 2.
  3. Phase 2 – Datenlängen- & Status-Validierung:
    • Bedingung: (Length >= Config->MinDataLength/8) && (Length <= Config->MaxDataLength/8) && (ForwardStatus != E2E_P_NONEWDATA)
    • Umrechnung: Bitlängen der Konfiguration werden per Ganzzahldivision / 8 in Byte mit Length abgeglichen. Zudem darf kein Leerlaufzustand (E2E_P_NONEWDATA) weitergeleitet werden.
    • [FALSE] → Abbruch zu Endknoten wrong input.
    • [TRUE] → Weiter zu Phase 3.
  4. Phase 3 – SourceID-Schrankenprüfung:
    • Bedingung: SourceID <= 0xFFFFFFF (Gültiger Bereich: max. 28 Bit, 0x00000000 .. 0x0FFFFFFF).
    • [FALSE] → Abbruch zu Endknoten wrong input.
    • [TRUE] → Weiter zu Phase 4.
  5. Phase 4 – MessageType-Bereichsprüfung:
    • Bedingung: (MessageType >= 0) && (MessageType <= 1)
    • [FALSE] → Abbruch zu Endknoten wrong input.
    • [TRUE] → Weiter zu Phase 5.
  6. Phase 5 – MessageResult-Bereichsprüfung:
    • Bedingung: (MessageResult >= 0) && (MessageResult <= 1)
    • [FALSE] → Abbruch zu Endknoten wrong input.
    • [TRUE] → Erreichen des Endknotens input ok.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Zuordnung: Erfüllt Requirement [PRS_E2E_01182] (Traceable auf RS_E2E_08539). Die Spezifikation ist als Draft gekennzeichnet, bindend für Method-Forwarding in R22-11 und R23-11.
  • Return Codes:
    • Der Pfad null input erzwingt den Rückgabewert E2E_E_INPUTERR_NULL (Wert 0x13).
    • Der Pfad wrong input erzwingt den Rückgabewert E2E_E_INPUTERR_WRONG (Wert 0x17).
    • Nur bei input ok setzt die Funktion die Datenverarbeitung fort und liefert bei fehlerfreiem Durchlauf E2E_E_OK.
  • Kein Det-Reporting in E2E: Die E2E-Library meldet Fehlerstatus ausschließlich über den Funktionsrückgabewert (Std_ReturnType) an den Aufrufer (z. B. E2E-Transformer oder RTE/ComXf). Fehler werden nicht direkt an das Det gemeldet.
  • Bit-zu-Byte-Ausrichtung: Config->MinDataLength und Config->MaxDataLength müssen ganzzahlig durch 8 teilbar konfiguriert sein, da die Division / 8 abrundet. Unvollständige Bytes führen bei ungenauer Konfiguration zu Pufferfehlauswertungen.
  • 28-Bit-Limitierung: SourceID ist auf 28 Bit begrenzt; die oberen 4 Bits eines 32-Bit-Wertes müssen 0 sein (<= 0x0FFFFFFF), andernfalls schlägt die Weiterleitung zwingend fehl.
