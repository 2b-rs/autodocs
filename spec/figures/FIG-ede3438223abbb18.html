1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (State Machine Diagram) zur Spezifikation des Zustands- und Betriebsmodus-Algorithmus des Moduls CanNm (CAN Network Management) innerhalb der AUTOSAR Classic Platform (Communication Services). Das Diagramm definiert hierarchische Betriebsmodi (Bus-Sleep Mode, Prepare Bus-Sleep Mode, Network Mode) sowie die internen Sub-Zustände des Network Mode (Repeat Message State, Normal Operation State, Ready Sleep State) samt Übergangsbedingungen, Timer-Steuerungen und API-Interaktionen mit dem übergeordneten Nm (Generic Network Management Interface).

2. Komponenten, Entitäten & Schnittstellen

  • Modi und Zustände:
    • Bus-Sleep Mode (Ruhezustand ohne Netzwerkaktivität)
    • Prepare Bus-Sleep Mode (Übergangsmodus vor dem Einschlafen)
    • Network Mode (Hierarchischer Zustand mit den Sub-Zuständen Repeat Message State, Normal Operation State, Ready Sleep State)
    • Pseudozustände: Initialzustand PowerOn, Endzustand PowerOff, Verbindungsknoten (Junctions) Network Mode und Repeat Message
  • Schnittstellen & API-Aufrufe:
    • CanNm_Init(): Initialisierung des CAN-NM-Moduls
    • CanNm_DeInit(): Deinitialisierung des CAN-NM-Moduls in Richtung Bus-Sleep Mode
    • CanNm_PassiveStartUp() / CanNm_PassiveStartup(): Passiver Start des Netzwerkmanagements
    • CanNm_NetworkRequest(): Anforderung des Netzwerks durch lokale Applikationen
    • CanNm_NetworkRelease(): Freigabe des Netzwerks durch lokale Applikationen
    • CanNm_RepeatMessageRequest(): Aufforderung zum Wiedereintritt in den Repeat Message State
    • CanNm_RxIndication(): Empfangsanzeige einer CAN-NM-Botschaft
    • CanNm_TxConfirmation(Result: E_OK): Bestätigung erfolgreicher Botschaftsübertragung
    • Nm_NetworkMode(): Callback an Nm bei Eintritt in den Network Mode
    • Nm_NetworkStartIndication(): Benachrichtigung an Nm über Netzwerkstart im Bus-Sleep Mode
    • Nm_PrepareBusSleepMode(): Benachrichtigung an Nm über Vorbereitung des Bus-Sleep
    • Nm_BusSleepMode(): Benachrichtigung an Nm über Eintritt in Bus-Sleep
    • Nm_TxTimeoutException(): Ausnahmebenachrichtigung bei Sende-Timeout
  • Timer und Flags:
    • NM-Timeout Timer: Überwachung der Netzwerkaktivität
    • Repeat Message Timer: Verweildauer im Zustand Repeat Message State
    • Wait Bus-Sleep Timer: Wartezeit im Prepare Bus-Sleep Mode
    • Tx Timeout Timer: Sendeüberwachung
    • Konfigurationsparameter: CanNmPnHandleMultipleNetworkRequests (TRUE/FALSE)
    • Nachrichten-Flags: Repeat Message Bit (RMB)

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung & Start:
    • Übergang von PowerOn via CanNm_Init() / Initialization of CanNm in den Bus-Sleep Mode.
    • Aus Bus-Sleep Mode führt CanNm_PassiveStartup() oder CanNm_NetworkRequest() über den Verbindungsknoten Network Mode in den Repeat Message State; dabei werden NM-Timeout Timer und Repeat Message Timer gestartet sowie Nm_NetworkMode() aufgerufen.
    • Empfang von CanNm_RxIndication() im Bus-Sleep Mode löst Nm_NetworkStartIndication() aus (interner Übergang).
    • Aus Prepare Bus-Sleep Mode führen CanNm_PassiveStartup(), CanNm_NetworkRequest() oder CanNm_RxIndication() ebenfalls über den Junction Network Mode in den Repeat Message State.
  • Abläufe im Network Mode:
    • Eintritt in Repeat Message State führt die Entry-Aktion + entry / Stop Bus Load Reduction aus.
    • Bei Ablauf des Repeat Message Timer verzweigt der Pseudozustand Repeat Message abhängig vom Netzwerkstatus:
      • [Network Requested]: Übergang in Normal Operation State (führt + entry / Start Bus Load Reduction aus).
      • [Network Released]: Übergang in Ready Sleep State.
    • Aus Normal Operation State führt CanNm_NetworkRelease() in Ready Sleep State.
    • Aus Ready Sleep State führt CanNm_NetworkRequest(); [CanNmPnHandleMultipleNetworkRequests == FALSE] zurück in Normal Operation State.
    • Wenn CanNmPnHandleMultipleNetworkRequests == TRUE gilt, führt CanNm_NetworkRequest() aus Normal Operation State oder Ready Sleep State direkt in den Repeat Message State unter Start des Repeat Message Timer.
    • Empfang von Repeat Message Bit received || CanNm_RepeatMessageRequest() in Normal Operation State oder Ready Sleep State führt zurück in den Repeat Message State unter Start des Repeat Message Timer.
  • Timer-Überwachung & Sleep-Übergang:
    • CanNm_RxIndication() oder CanNm_TxConfirmation(Result: E_OK) im Network Mode setzen den NM-Timeout Timer zurück / starten ihn neu.
    • Ablauf des NM-Timeout Timer im Repeat Message State oder Normal Operation State startet den NM-Timeout Timer neu.
    • Ablauf des NM-Timeout Timer im Ready Sleep State startet den Wait Bus-Sleep Timer, ruft Nm_PrepareBusSleepMode() auf und wechselt in Prepare Bus-Sleep Mode.
    • Ablauf des Wait Bus-Sleep Timer im Prepare Bus-Sleep Mode ruft Nm_BusSleepMode() auf und wechselt in Bus-Sleep Mode.
    • Ablauf des Tx Timeout Timer löst Nm_TxTimeoutException() als Selbsttransition in Repeat Message State und Normal Operation State aus.

4. Normative Relevanz & Entwickler-Hinweise

  • Zustandsmaschine & Konformität:
    • Das Diagramm legt verbindlich die Zustände und Zustandsübergänge des AUTOSAR CAN Network Managements fest. Abweichungen im Verhalten von Timern oder API-Reaktionen verletzen die SWS-Konformität.
    • Bei Verwendung von Partial Networking steuert der Parameter CanNmPnHandleMultipleNetworkRequests, ob erneute Netzwerkanforderungen einen Wechsel in den Repeat Message State erzwingen oder lediglich im Normal Operation State verbleiben.
    • Die Bus-Last-Reduktion (Bus Load Reduction) wird zustandsabhängig aktiviert (Normal Operation State) bzw. deaktiviert (Repeat Message State).
    • Im Ready Sleep State werden keine neuen NM-Nachrichten aktiv gesendet; das Verlassen des Modus in Richtung Prepare Bus-Sleep Mode erfolgt rein passiv über den Ablauf des NM-Timeout Timer.
