1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Datenfluss- und Methoden-Prozessdiagramm (Tooling- & Artefakt-Workflow nach AUTOSAR Methodology).
  • Funktionaler Zweck: Trennung der Phasen Module Configuration und Module Generation bei Einsatz eines generischen Steuergeräte-Konfigurations-Editors (Generic ECU Configuration Editor) im Zusammenspiel mit herstellerspezifischen Codegeneratoren (Dedicated Module Generator).
  • Einordnung im AUTOSAR-Gesamtsystem: Realisiert die Entkopplung zwischen der Parameter-Definition/Instanziierung auf Schema-Ebene (ECUC) und der konkreten C-Code-Generierung der Basissoftware (BSW). Ermöglicht Tool-Interoperabilität, bei der ein zentraler Integrator-Editor ARXML-Beschreibungen verschiedener BSW-Lieferanten einliest, validiert und über standardisierte Generator-Manifeste in die Build-Kette einbindet.

2. Komponenten, Entitäten & Schnittstellen

Akteure & Werkzeuge
  • Autosar Integrator: Entwickler/Rolle zur Erfassung, Anpassung und Auflösung der BSW-Konfigurationsparameter im Editor.
  • Generic ECU Configuration Editor: Plattformunabhängiges Werkzeug (vom Tool-Implementierer), das rein modellgetrieben arbeitet, Parameterstrukturen dynamisch anhand der Definitionsdateien rendert und konsistente Konfigurationsbeschreibungen exportiert.
  • Dedicated Module Generator: Herstellerspezifischer BSW-Codegenerator (Stand-Alone Executable/Skript), der BSW-spezifische C-Header/Source-Dateien erzeugt.
  • Build-Tool: Build-System (z. B. Make, CMake, Ninja), das Generatoren automatisiert orchestriert und kompiliert.
Schemata & Vorlagen (Provided by AUTOSAR)
  • Schema Configuration Parameter Template: XML-Schema für Parameter-Definitionen (EcucParameterDef).
  • Schema ECU Configuration Template: XML-Schema für die eigentliche Instanziierung/Wertebelegung (EcucValueCollection / EcucModuleConfigurationValues).
  • Schema (Manifest): Metamodell für das BSW Module Description Template (BSWMDT, spezifisch BswModuleDescription / BswImplementation / Generator).
  • XML Standardized Configuration Parameter Definition: AUTOSAR-Basisdefinition der Standard-Parameter (z. B. Can, Com, Os).
Instanzen & Zwischenartefakte (Provided by Implementer & Automatically generated)
  • XML Configuration Parameter Definition: Lieferantenspezifische BSW-Moduldefinition (EcucModuleDef), konform zum AUTOSAR-Schema und abgeleitet von/erweiternd auf die standardisierten Definitionen (Vendor-spezifische Container/Parameter).
  • XML ECU Configuration Description: Das generierte Konfigurationsmodell (*.arxml), das die konkrete ECU-Parametrisierung enthält. Es gehorcht dem ECU Configuration Template und referenziert die Typen aus der XML Configuration Parameter Definition (conforms to).
  • Manifest: XML/ARXML-Datei des BSW-Lieferanten, die Aufrufparameter, Ein-/Ausgangsdateien und Interfaces des Dedicated Module Generator maschinenlesbar spezifiziert (described by).
  • Dedicated BSW Module: Vom Modulgenerator erzeugte C/H-Dateien (<Mod>_Cfg.h, <Mod>_Cfg.c, <Mod>_PBcfg.c) zur statischen/post-build Kompilierung.

3. Dynamisches Verhalten & Sequenzablauf

  1. Phasengrenze 1: Module Configuration
    • Definitions-Import: Der Generic ECU Configuration Editor lädt die XML Configuration Parameter Definitions aller eingebundenen BSW-Stacks.
    • Interaktive Konfiguration: Der Autosar Integrator editiert Werte, Container und Referenzen gemäß den vorgegebenen Wertebereichen und Multiplizitäten.
    • Modell-Export: Der Editor serialisiert den System- und BSW-Zustand schema-konform in die XML ECU Configuration Description (EcucModuleConfigurationValues).
  2. Phasengrenze 2: Module Generation (Build-Trigger)
    • Manifest-Auswertung: Das Build-Tool liest das Manifest des BSW-Moduls aus, um Kommandozeilenargumente, Generatorpfade und Abhängigkeiten zu bestimmen (gemäß TPS_BSWMDT_04085).
    • Generator-Aufruf: Das Build-Tool stößt den Dedicated Module Generator synchron oder batch-basiert an; dieser konsumiert die XML ECU Configuration Description.
    • Codegenerierung: Der Generator erzeugt die C-Quelldateien des Dedicated BSW Module (Pre-Compile Time Konfigurationsstrukturen, Defines, Funktions-Pointer-Tabellen).

4. Normative Relevanz & Entwickler-Hinweise

  • Anforderungsbezug TPS_BSWMDT_04085: Fordert die formale Beschreibung der Generator-Schnittstelle im BSW-Modul-Manifest. BSW-Lieferanten dürfen keine proprietären Aufrufmechanismen erzwingen, sondern müssen Input-Parameter, Ausgabepfade und Ausführungsvoraussetzungen so deklarieren, dass externe Build-Tools den Generator headless ansteuern können.
  • Trennung von Konfiguration und Codegenerierung: Ein Generic ECU Configuration Editor benötigt keinen eigenen C-Code-Generator für jedes Modul. Entwickler müssen sicherstellen, dass die XML Configuration Parameter Definition (EcucModuleDef) alle semantischen Validierungsregeln (Ranges, Defaults, Multiplizitäten) vollständig enthält, da der Editor ausschließlich dieses Modell interpretiert.
  • Referenztreue und UUIDs: Bei der Erzeugung der XML ECU Configuration Description müssen die Verweise (definition-ref) exakt auf die Pfade der zugrunde liegenden Configuration Parameter Definition matchen; fehlende oder fehlerhafte Referenzen blockieren nachgelagerte Generatoren deterministisch.
  • Build-Integration: Ermöglicht inkrementelle Builds: Änderungen in der Konfigurations-ARXML triggern über das Manifest gezielt nur die Generatoren der modifizierten BSW-Module, nicht den gesamten Software-Stack.
