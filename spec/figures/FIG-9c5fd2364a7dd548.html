1. Diagrammtyp & Architektur-Kontext

UML-Anforderungs- und Rückverfolgbarkeitsdiagramm (Requirements Tracing Diagram) zur Spezifikation von Interoperabilitätsanforderungen für AUTOSAR-Authoring-Tools. Das Diagramm strukturiert funktionale und nichtfunktionale Werkzeuganforderungen hierarchisch nach Kapiteln bzw. Interoperabilitätsebenen (Physical, Data format, Content, Semantic, Presentation level sowie übergreifende Aspekte wie Concurrent Modeling, Shipment, Specialized Tools und Metamodel Migration) und bildet Traceability-Beziehungen zu zwei zentralen Hauptzielen bzw. Top-Level-Anforderungen ab.

2. Komponenten, Entitäten & Schnittstellen

Zentrale Entitäten sind Top-Level-Anforderungsknoten (hervorgehoben in Grün) sowie abgeleitete Detailanforderungen (Rechtecke mit Dokumentensymbol/Notiz-Darstellung), gruppiert in Systemgrenzen bzw. Kapitelpakete:

  • Zentrale Anforderungen / Ziele:
    • [ATIREQ_001]: Support Data Exchange
    • [ATIREQ_002]: Standardize Error Handling
  • Strukturierende Pakete und zugeordnete Anforderungen:
    • ch 6.1.1 Physical level: [ATI0010] (Authoring tool SHALL support sets of files).
    • ch 6.1.2 Data format level: [ATI0012] (Authoring tool SHALL support AUTOSAR XML descriptions), [ATI0033] (Authoring tool SHALL be able to import and export supported metamodel elements as AUTOSAR XML descriptions).
    • ch 6.1.3 Content level: [ATI0007] (Authoring tool SHALL NOT change model contents without the intention of the user), [ATI0035] (Authoring tool SHALL support exchange of partial information).
    • ch 6.1.4 Semantic level: [ATI0003] (Authoring tool SHALL support validity checks).
    • ch 6.1.5 presentation level: [ATI0014] (Authoring tool SHALL support standardized error codes), [ATI0015] (Authoring tool SHOULD use AUTOSAR graphical notation).
    • ch 6.2 support for concurrent modeling: [ATI0042] (Authoring tool SHALL support for merging of model fragments), [ATI0043] (Authoring tool SHOULD provide a mechanism for showing differences between AUTOSAR models), [ATI0044] (Authoring tool SHOULD provide a mechanism for resolving merging conflicts), [ATI0040] (Authoring tool SHOULD prohibit the user from modifying model elements that are marked read-only), [ATI0024] (Authoring tool SHALL support unique identification of model elements).
    • ch 6.3 Shipment of AUTOSAR models: [ATI0036] (Authoring tool SHOULD be able to interpret and create metadata for data exchange).
    • ch 6.4 Interoperability with specialized tools: [ATI0016] (Documentation of authoring tool SHOULD describe supported features).
    • ch 6.5 migration between different versions of the metamodel: [ATI0005] (Authoring tool SHOULD support upgrading AUTOSAR models).
  • Schnittstellen & Relationen:
    • Gestrichelte gerichtete Pfeile mit dem Stereotyp «trace» verknüpfen Anforderungen untereinander und mit den Hauptzielen.
    • Nahezu alle Anforderungen besitzen eine Rückverfolgbarkeitsbeziehung («trace») zu [ATIREQ_001].
    • Anforderung [ATI0014] besitzt eine zusätzliche «trace»-Beziehung zu [ATIREQ_002].
    • Interne Abhängigkeiten existieren innerhalb von ch 6.1.2 ([ATI0033] traciert auf [ATI0012]) sowie innerhalb von ch 6.2 ([ATI0043], [ATI0044] und [ATI0040] tracieren jeweils auf [ATI0042]).

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm stellt eine statische Rückverfolgbarkeitsarchitektur dar und beschreibt keinen zeitlichen Ablauf. Es definiert die logische Erfüllungskette zur Gewährleistung des AUTOSAR-Datenaustauschs und Fehlerhandlings: Um das übergeordnete Ziel Support Data Exchange zu erfüllen, müssen die komplementären Schichten (von der physischen Dateiablage über das AUTOSAR-XML-Format, inhaltliche Integrität, Semantik- und Validitätsprüfungen bis hin zur Darstellung) sowie Werkzeugfunktionen für Parallelbearbeitung, Modellabgleich, Metadaten und Versionsmigration konform implementiert sein. Die interne Kaskade im Bereich Concurrent Modeling legt fest, dass Differenzanzeige ([ATI0043]), Konfliktlösung ([ATI0044]) und Schreibschutzmechanismen ([ATI0040]) auf der Basisfunktion zur Fragment-Zusammenführung ([ATI0042]) aufbauen.

4. Normative Relevanz & Entwickler-Hinweise

Die Anforderungen verwenden standardisierte RFC-2119-Schlüsselwörter:

  • Verbindliche Vorgaben (SHALL / SHALL NOT):
    • Werkzeuge müssen ARXML-Beschreibungen sowie Dateisätze unterstützen ([ATI0010], [ATI0012], [ATI0033]).
    • Modellinhalte dürfen niemals ohne Nutzerabsicht modifiziert werden ([ATI0007]).
    • Unterstützung für partielle Informationsaustausche ([ATI0035]), semantische Validitätsprüfungen ([ATI0003]), eindeutige Elementidentifikation ([ATI0024]), Fragment-Merge ([ATI0042]) und standardisierte Fehlercodes ([ATI0014]) ist zwingend erforderlich.
  • Empfehlungen (SHOULD):
    • Mechanismen zur Modell-Differenzanzeige ([ATI0043]), Konfliktlösung ([ATI0044]), Schreibschutz-Sperren ([ATI0040]), Metadaten-Handling ([ATI0036]), Migration/Upgrade ([ATI0005]), AUTOSAR-Grafiknotation ([ATI0015]) sowie Dokumentation der unterstützten Features ([ATI0016]) sind als Soll-Vorgaben für Tool-Hersteller formuliert.
  • Für Tool-Entwickler und Integratoren dient die Grafik als Matrix zur Abdeckung von Interoperabilitäts- und Konformitätstests von AUTOSAR-Autorentools.
