2. Komponenten, Entitäten & Schnittstellen

#### Datenartefakte (M1-Modelle & Quellcode)

  • Component Type Description : AtomicSoftwareComponentType (.XML): Beschreibt den äußeren SWC-Typ, dessen Ports (R-Ports, P-Ports) sowie die zugehörigen PortInterface-Definitionen (Sender-Receiver, Client-Server).
  • Component Internal Behavior Description [API Generation] : InternalBehavior (.XML): Referenziert den Komponententyp (gestrichelte Assoziation). Definiert RunnableEntities, RteEvents, ExclusiveAreas, InterRunnableVariables und den Datenzugriff (DataReadAccess, DataWriteAccess).
  • Component API (.h / Application Header File): Generierter C-Header (Rte_<swc>.h). Enthält Deklarationen der RTE-APIs (Rte_Read_, Rte_Write_, Rte_Call_, Rte_IRead_ etc.), Datentypen (Rte_Type.h) und Funktionsprototypen der Runnables.
  • Component Implementation (.c): Manuell oder modellbasiert erstellter Applikationsquellcode der SWC.
  • Compiled Component (.obj): Aus der Übersetzung von .c und .h hervorgegangener Objektcode (maschinenunabhängig oder target-spezifisch vorkompiliert).
  • Component Implementation Description [for Object-Code] : Implementation (.XML): Beschreibt die Zuordnung von Quell-/Objektdateien, Compiler-Flags und Ziel-Prozessorbefehlssätzen zur Implementierungseinheit.
  • Component Implementation Description [resource needs] : Implementation (.XML): Angereicherte M1-Beschreibungsdatei nach Ressourcenanalyse; enthält konkrete ResourceConsumption-Eigenschaften (Stack-Bedarf, ROM/RAM-Footprint, Ausführungszeiten/WCET der Runnables).

#### Werkzeuge & Aktivitäten

  • AUTOSAR Component API Generator (Tool): Werkzeug zur Generierung des Application Header Files aus der Verhaltensbeschreibung.
  • Aktivitäten (Prozessschritte):
  • Generate Component API
  • Implement Component
  • Compile Component
  • Measure Resources

3. Dynamisches Verhalten & Sequenzablauf

  1. API-Vertragsgenerierung (Generate Component API):
  • Input: Component Internal Behavior Description (inkl. Component Type Description).
  • Akteur: AUTOSAR Component API Generator.
  • Output: Generierung des Headers Component API (.h).
  1. Komponentenimplementierung (Implement Component):
  • Input: Component API (.h) und InternalBehavior (.XML).
  • Aktion: Entwickler implementiert die Runnable-Körper gegen die abstrakten Funktionsdeklarationen und RTE-Makros/Inlines.
  • Output: Quellcode Component Implementation (.c).
  1. Kompilierung & Code-Extraktion (Compile Component):
  • Input: Component Implementation (.c) und Component API (.h).
  • Aktion: Host- oder Target-Compiler übersetzt den Code.
  • Output: Compiled Component (.obj) sowie Erzeugung/Aktualisierung der M1-Metadaten (Component Implementation Description [for Object-Code]).
  1. Ressourcenvermessung (Measure Resources):
  • Input: Compiled Component (.obj) und Component Implementation Description [for Object-Code].
  • Aktion: Statische oder dynamische Analyse von Stack-, Flash- (Text/Const) und RAM-Bedarf (.bss, .data).
  • Output: Component Implementation Description [resource needs] (.XML) zur Weiternutzung in der späteren ECU-Konfiguration und RTE-Generierungsphase (RTE Generation Phase).

4. Normative Relevanz & Entwickler-Hinweise

  • Header-Inklusion: Die SWC darf ausschließlich den generierten Vertragskopf Rte_<SWC_NAME>.h (bzw. abgeleitete Standardtypen via Rte_Type.h) inkludieren. Direkte Zugriffe auf interne Datenstrukturen anderer BSW-Module oder fremder SWCs verletzen die VFB-Semantik.
  • Unvollständige Funktionsdefinitionen in der Contract Phase: In der Contract Phase generierte Funktionskörper oder Makros (z. B. Dummy-Stubs oder Standard-Rückgabewerte) dienen primär der syntaktischen Gültigkeit und Typensicherheit beim Kompilieren. Die reale Implementierung der Datenweiterleitung (Puffer, Ringpuffer, OS-Events, COM-Signale) erfolgt erst in der RTE Generation Phase.
  • Iterative Schleifen: Änderungen an Port-Interfaces, RTE-Events oder Datenübertragungseigenschaften bedingen eine zwingende Neu-Generierung des Application Headers (.h). Bei ABI-/API-Signaturbrüchen scheitert der Schritt Compile Component.
  • Ressourcenanforderungen (ResourceNeeds): Die durch Measure Resources erfassten Werte sind bindende Inputs für die nachgelagerte OS-Task-Konfiguration (Task-Stack-Sizing, Task-Zuweisung von Runnables, Memory Mapping via MemMap.h).
