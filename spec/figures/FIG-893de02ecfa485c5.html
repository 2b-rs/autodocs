1. Diagrammtyp & Architektur-Kontext

AUTOSAR-ECU-Konfigurations-Metamodell (UML-Klassendiagramm) für das Basissoftware-Modul Dem (Diagnostic Event Manager) der AUTOSAR Classic Platform. Das Diagramm spezifiziert die Konfigurationscontainer, Parameter und Referenzbeziehungen zur Definition von Speicherbedingungen (DemStorageCondition), Speicherbedingungsgruppen (DemStorageConditionGroup) und deren Zuordnung zu Diagnose-Ereignissen (DemEventParameter) innerhalb des übergeordneten Konfigurationscontainers DemGeneral.

2. Komponenten, Entitäten & Schnittstellen

Das Klassendiagramm definiert folgende Konfigurationselemente und Beziehungen:

  • DemGeneral (EcucParamConfContainerDef, Multiplizität 1..1): Zentraler Dem-Container, enthält per Komposition (+subContainer) die Container DemStorageCondition und DemStorageConditionGroup.
  • DemStorageCondition (EcucParamConfContainerDef, Multiplizität 0..255): Repräsentiert eine individuelle Speicherbedingung.
    • DemStorageConditionId (EcucIntegerParamDef via +parameter): Eindeutige ID im Wertebereich 0 bis 255 (symbolicNameValue = true).
    • DemStorageConditionStatus (EcucBooleanParamDef via +parameter, Multiplizität 1..1): Initialer Erfüllungsstatus der Bedingung.
    • DemStorageConditionReplacementEventRef (EcucReferenceDef via +reference, Multiplizität 0..1): Optionale Referenz auf ein Ersatz-Ereignis mit Destination DemEventParameter.
  • DemStorageConditionGroup (EcucParamConfContainerDef, Multiplizität 0..255): Gruppierung von Speicherbedingungen.
    • DemStorageConditionRef (EcucReferenceDef via +reference, Multiplizität 1..255): Verweist mit Destination auf die zugehörigen DemStorageCondition-Container.
  • DemEventParameter (EcucParamConfContainerDef, Multiplizität 1..65535): Konfiguration eines Diagnose-Events.
    • DemStorageConditionGroupRef (EcucReferenceDef via +reference, Multiplizität 0..1): Optionale Zuordnung des Events zu einer DemStorageConditionGroup (Destination).

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Konfigurationsmetamodell bildet das Diagramm keine Laufzeitsequenzen ab. Dynamisch steuert das Modell das Freigabeverhalten für Fehlereinträge: Zur Laufzeit meldet die Applikation oder ein BSW-Modul über Dem_SetStorageCondition den Erfüllungsstatus einzelner Speicherbedingungen. Tritt ein Diagnose-Ereignis (DemEventParameter) auf, prüft der Dem die über DemStorageConditionGroupRef zugewiesene Gruppe. Ein Fehlerspeichereintrag wird nur vorgenommen, wenn alle über DemStorageConditionRef verknüpften Bedingungen erfüllt sind. Ist die Gruppe nicht erfüllt und existiert ein DemStorageConditionReplacementEventRef, kann alternativ das referenzierte Ersatzereignis verarbeitet werden.

4. Normative Relevanz & Entwickler-Hinweise

Normative Spezifikation der Dem-Parameterdefinition (EcucParameterDef). BSW-Entwickler und Integratoren müssen folgende Vorgaben beachten:

  • Eindeutigkeit und Namensgebung: DemStorageConditionId muss als symbolischer Name generiert werden, um in API-Aufrufen (Dem_SetStorageCondition) konsistent verwendbar zu sein.
  • Kardinalitätsrestriktionen: Ein DemEventParameter kann maximal einer DemStorageConditionGroup zugeordnet werden (0..1). Eine DemStorageConditionGroup muss mindestens eine und darf bis zu 255 Bedingungen referenzieren (1..255).
  • Maximal 255 Bedingungen und 255 Gruppen sind unter DemGeneral konfigurierbar.
  • Ersatzereignis-Logik: Die Zuweisung eines Ersatzereignisses (DemStorageConditionReplacementEventRef) ist optional (0..1) und erfordert sorgfältige Parametrierung, um unerwünschte Kaskadeneffekte oder Blockaden im Fehlerspeicher zu vermeiden.
