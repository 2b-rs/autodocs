2. Komponenten, Entitäten & Schnittstellen

#### Zentrale Container & Hierarchien

  • *IEEE1722TpStream (EcucParamConfContainerDef, Mult: 1..):**

Repräsentiert die Konfigurationsinstanz eines logischen IEEE-1722-Streams.

  • Komposition zu IEEE1722TpStreamDirection via +subContainer (1..1).
  • Referenz zu IEEE1722TpLowerLayerPduPool via IEEE1722TpStreamLowerLayerPduPoolRef (1..1).
  • IEEE1722TpStreamDirection (EcucChoiceContainerDef, Mult: 1..1):

Erzwingt eine strikte Richtungsauswahl (XOR) für den Stream:

  • Option Tx – IEEE1722TpStreamTx (EcucParamConfContainerDef, Mult: 0..1):
  • Aggregiert IEEE1722TpUpperLayerTxPduPoolEntry via +subContainer (0..*).
  • IEEE1722TpStreamTxPduRef (EcucReferenceDef, Mult: 1..1): Referenziert das globale Ziel Pdu (+destination, Mult: 0..*).
  • IEEE1722TpStreamTxPduId (EcucIntegerParamDef, Mult: 0..1): Wertebereich 0..65535, withAuto = true, symbolicNameValue = true. Handle-ID für die Sende-PDU der oberen Schicht.
  • Option Rx – IEEE1722TpStreamRx (EcucParamConfContainerDef, Mult: 0..1):
  • Aggregiert IEEE1722TpUpperLayerRxPduPoolEntry via +subContainer (0..*).
  • IEEE1722TpStreamRxPduRef (EcucReferenceDef, Mult: 1..1): Referenziert das globale Ziel Pdu (+destination, Mult: 0..*).
  • IEEE1722TpStreamRxPduId (EcucIntegerParamDef, Mult: 1..1): Wertebereich 0..65535, withAuto = true, symbolicNameValue = true. Handle-ID für die Empfangs-PDU der oberen Schicht.
  • *IEEE1722TpLowerLayerPduPool (EcucParamConfContainerDef, Mult: 1..):**

Modulweiter Pool für Lower-Layer-PDU-Ressourcen (Anbindung an EthIf/Treiber).

  • Ziel der Referenz IEEE1722TpStreamLowerLayerPduPoolRef.
  • Aggregiert Subcontainer:
  • IEEE1722TpLowerLayerTxPduPoolEntry (EcucParamConfContainerDef, Mult: 0..*).

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Konfigurationsmodell definiert das Diagramm die Datenstrukturen für folgende Laufzeitpfade:

  • Sende-Pfad (Tx):
  1. Trigger über Ieee1722Tp_Transmit(TxPduId, PduInfoPtr).
  2. Auflösung der Upper-Layer-PDU über IEEE1722TpStreamTxPduId zum Stream IEEE1722TpStream.
  3. Kapselung der Payload in AVTP-Protokolldaten (z. B. ACF / Encapsulated Data).
  4. Entnahme/Belegung einer Lower-Layer-Tx-PDU aus dem über IEEE1722TpStreamLowerLayerPduPoolRef angebundenen IEEE1722TpLowerLayerTxPduPoolEntry.
  5. Weiterleitung via EthIf_Transmit() / SoAd_IfTransmit().
  • Empfangs-Pfad (Rx):
  1. Asynchroner Empfangsaufruf aus dem Lower Layer (Ieee1722Tp_RxIndication()).
  2. Zuordnung zu Pool und Stream anhand der AVTP-Header-Informationen (Stream-ID).
  3. Reassemblierung/Entpacken und Übergabe an die obere Schicht via PduR_Ieee1722TpRxIndication() unter Verwendung der über IEEE1722TpStreamRxPduId fest zugeordneten Handle-ID.

4. Normative Relevanz & Entwickler-Hinweise

  • Strikte Unidirektionalität: Durch den EcucChoiceContainerDef (IEEE1722TpStreamDirection) ist ein IEEE-1722-Stream im AUTOSAR-Standard zwingend unidirektional (entweder Tx oder Rx; keine Vollduplex-Konfiguration unter derselben Stream-Instanz).
  • Asymmetrie der PduId-Kardinalitäten:
  • IEEE1722TpStreamTxPduId hat lowerMultiplicity = 0: Die ID kann weggelassen werden, wenn sie generisch vom PduR zugewiesen wird oder rein symbolisch adressiert wird.
  • IEEE1722TpStreamRxPduId hat lowerMultiplicity = 1: Zwingend erforderlich, da das Modul bei Eintreffen eines AVTP-Pakets eine eindeutige lokale Upper-Layer-Target-ID benötigt, um die PduR-Callback-API aufzurufen.
  • Header-Generierung (symbolicNameValue = true):

Der BSW-Codegenerator erzeugt für jede konfigurierte PDU zwingend numerische C-Makros (z. B. Ieee1722TpConf_IEEE1722TpUpperLayerRxPduPoolEntry_<ShortName>), die in den Routing-Tabellen des PduR als Ziel- bzw. Quell-IDs abgeglichen werden müssen.

  • Pool-Entkopplung: Streams referenzieren Lower-Layer-PDU-Pools indirekt (IEEE1722TpStreamLowerLayerPduPoolRef). Mehrere logische Streams können sich denselben Pool an Sende-/Empfangs-Puffern teilen, was Speicherallokation und Queue-Management im BSW-Stack modular entkoppelt.
