1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Konzeptionelles Metamodell-Instanziierungs- und Mapping-Diagramm (ARXML-Objektsemantik).
  • Technischer Zweck: Spezifikation der Zuordnung zwischen einem mehrdimensionalen Achsen-Array (ApplicationArrayDataType von COM_AXIS) und einer einzelnen skalaren Eingangsvariablen (VALUE / ApplicationPrimitiveDataType) zur Darstellung des Arbeitspunkts (Working Point) in Mess-, Kalibrier- und Diagnose-Systemen (MCD, z. B. ETAS INCA, Vector CANape).
  • Funktionale Einordnung: AUTOSAR Classic Platform (Release 4.3.1), Software Component Template (AUTOSAR_TPS_SoftwareComponentTemplate), Kapitel 5.4.5 „Setting an Axis Input Value“, Anforderung [TPS_SWCT_01684].

2. Komponenten, Entitäten & Schnittstellen

  • InstantiationDataDefProps:
  • Instanzspezifische Datendefinitionseigenschaften zur Konfiguration konkreter Merkmale eines Komponentenprototyps oder einer Parameterinstanz («atpSplitable», «atpVariation»).
  • parameterInstance (Rolle/Assoziation):
  • Referenziert die konkrete Instanz eines ParameterDataPrototype, der als Array aus Elementen der Kategorie COM_AXIS (Compound Primitive Data Type für gemeinsame Stützstellenachsen) typisiert ist.
  • Array von COM_AXIS ($N = 5$ im Schaubild):
  • Mehrdimensionales Array (ApplicationArrayDataType), dessen Elemente jeweils eine Stützstellenachse für Kennlinien (CURVE) oder Kennfelder (MAP) repräsentieren.
  • VALUE:
  • Ein skalarer VariableDataPrototype, typisiert über einen ApplicationPrimitiveDataType. Dient als Laufzeit-Eingangswert (Messgröße, z. B. Drehzahl, Temperatur) zur Arbeitspunktbestimmung.
  • Navigationspfad / Metamodell-Kette:
  • swDataDefProps $\rightarrow$ swCalprmAxisSet (SwCalprmAxisSet) $\rightarrow$ swCalprmAxis (SwCalprmAxis) $\rightarrow$ swCalprmAxisTypeProps (spezialisiert als SwAxisIndividual) $\rightarrow$ swVariableRef (AutosarVariableRef / autosarVariable).
  • Kardinalitäten & Relationen:
  • $N:1$-Relation: Das gesamte Array von $N$ COM_AXIS-Elementen referenziert exakt eine skalare Eingangsvariable (VALUE).
  • Im Gegensatz zu Array-auf-Array-Zuordnungen (TPS_SWCT_01683) existiert hier keine Dimensionsgleichheit zwischen Achsen-Array und Eingangswert.

3. Dynamisches Verhalten & Sequenzablauf

  • Statische vs. dynamische Ausprägung:
  • Das Diagramm beschreibt rein deklarative Metadaten (ARXML) für den Entwurfs- und Generierungsprozess; es existiert kein direkter RTE-Aufruf oder dynamischer Kontrollfluss im Steuergerät.
  • Laufzeit- und Tool-Semantik:
  1. Laufzeit (ECU): Die Software-Komponente liest den Skalarwert VALUE ein oder berechnet ihn und legt ihn im RAM ab.
  2. MCD-/A2L-Laufzeit (ASAM MCD-2 MC): Das Kalibriertool liest die Adresse von VALUE zyklisch über XCP/CCP aus.
  3. Arbeitspunkt-Projektion: Das Tool projiziert denselben Messwert von VALUE simultan als Eingangs-Arbeitspunkt auf sämtliche Achsen des COM_AXIS-Arrays, um die Stützstellen-Interpolation visuell im Kalibrier-Editor darzustellen.

4. Normative Relevanz & Entwickler-Hinweise

  • Konforme Modellierung gemäß [TPS_SWCT_01684]:
  • Ist ein DataPrototype als Array von Kennfeld-/Achsentypen (CURVE, MAP, CUBOID, CUBE_4, CUBE_5, COM_AXIS, RES_AXIS) typisiert, darf die instanzspezifische InstantiationDataDefProps (oder ParameterAccess) direkt auf eine skalare VariableDataPrototype verweisen.
  • Semantischer Vertrag: Jedes Element des Achsen-Arrays nutzt für die Achsendimension (swAxisIndex) dieselbe Eingangsvariable.
  • Abgrenzung zu [TPS_SWCT_01683] & [constr_1426]:
  • TPS_SWCT_01683 fordert bei Verweis auf ein Variablen-Array strikte Konsistenz bezüglich Dimension und maxNumberOfElements ($n$-te Achse nutzt $n$-ten Wert).
  • TPS_SWCT_01684 entbindet davon: Vermeidung von Dummy-Arrays im RAM, wenn mehrere parallele Kennfelder/Achsen von derselben physikalischen Führungsgröße abhängen.
  • A2L- und Codegenerator-Auswirkungen:
  • Der A2L-Generator muss bei der Generierung der AXIS_PTS- bzw. CHARACTERISTIC-Einträge die Referenz INPUT_QUANTITY aller Achsen-Instanzen auf dasselbe Messsymbol (VALUE) mappen.
  • Prüfpflicht auf Tooling-Ebene gemäß [constr_1425]: Die Zuweisung von SwAxisIndividual.swVariableRef innerhalb von InstantiationDataDefProps ist für ARRAY-Datentypen nur zulässig, wenn der Datentyp des ApplicationArrayElement diese Eigenschaft gemäß Metamodell-Regeln unterstützt.
