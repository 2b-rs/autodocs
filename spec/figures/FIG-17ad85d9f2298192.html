1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm zur Modellierung des generischen Variationspunkt-Konzepts (VariationPoint) im Metamodell der AUTOSAR Generic Structure Template (AUTOSAR_TPS_GenericStructureTemplate). Das Diagramm spezifiziert die Struktur zur Definition von Variabilität, Auswertungsbedingungen, Bindungszeitpunkten und Post-Build-Kriterien für Modellierungselemente auf M1- und M2-Ebene.

2. Komponenten, Entitäten & Schnittstellen

Zentrale Metaklasse ist VariationPoint mit dem optionalen Attribut + shortLabel: Identifier [0..1].

Kompositionen ausgehend von VariationPoint:

  • +swSyscond [0..1] zu ConditionByFormula (spezialisiert SwSystemconstDependentFormula), attributiert mit + bindingTime: BindingTimeEnum.
  • +blueprintCondition [0..1] zu DocumentationBlock (Stereotyp «atpMixed»).
  • +formalBlueprintGenerator [0..1] zu BlueprintGenerator mit dem optionalen Attribut + expression: VerbatimString [0..1].
  • +postBuildVariantCondition [0..*] zu PostBuildVariantCondition mit dem variablen Attribut «atpVariation» + value: Integer.
  • +desc [0..1] zu MultiLanguageOverviewParagraph.
  • +sdg [0..1] zu Sdg mit dem Attribut + gid: NameToken.

Weitere Kompositionen und Assoziationen:

  • DocumentationBlock bindet über die Komposition +introduction [0..1] die Klasse BlueprintGenerator ein.
  • PostBuildVariantCondition referenziert über die gerichtete Assoziation +matchingCriterion [1] das ARElement PostBuildVariantCriterion (Stereotyp AtpDefinition).
  • Die Klasse BlueprintFormula (Stereotyp «atpMixedString», spezialisiert SwSystemconstDependentFormula) ist unverbunden im Diagrammbereich dargestellt.

Aufzählungstypen und Nebenbedingungen:

  • Enumeration BindingTimeEnum mit den Literalen systemDesignTime, codeGenerationTime, preCompileTime und linkTime.
  • Enumeration AdditionalBindingTimeEnum mit den Literalen blueprintDerivationTime und postBuild.
  • OCL-Constraint an PostBuildVariantCondition: vh.latestBindingtime=preCompileTime.

3. Dynamisches Verhalten & Sequenzablauf

Statische Metamodellstruktur ohne Sequenzabläufe. Die Blueprint-Generierung wird über die Klasse BlueprintGenerator modelliert, die sowohl direkt an VariationPoint (formalBlueprintGenerator) als auch an den beschreibenden DocumentationBlock (introduction) angebunden werden kann und Generator-Ausdrücke via VerbatimString bereitstellt. Die herkömmliche BlueprintFormula ist strukturell nicht mehr über eine Kompositionsbeziehung an VariationPoint angebunden. Post-Build-Bedingungen und Formelbedingungen verhalten sich wie definiert.

4. Normative Relevanz & Entwickler-Hinweise

Für die Modellierung von Blueprint-Generatoren ist die Klasse BlueprintGenerator zu verwenden, welche über formalBlueprintGenerator oder als Einleitungsteil introduction eines DocumentationBlock eingebunden wird. Der Ausdruck wird als VerbatimString hinterlegt. Die Klasse BlueprintFormula verfügt über keine direkte Kompositionskante mehr am VariationPoint.

Generic Structure Template AUTOSAR CP Release 4.4.0 Furthermore, the Property Set Pattern differs from the Aggregation Pattern and the Association Pattern in that the former pattern works on a number of attributes, aggregations and associations at once, while the latter patterns determine the existence of a single aggregation or aggregation only. 7.5.7 Combining the attribute value pattern and the property set patterns In the previous section, we said that the property set pattern cannot specify an expression to define the value of an attribute. While this is true, there is a way to avoid this restriction, namely by combining the property set pattern with the attribute value pattern. In this case, the property set pattern would allow to partition the complete set of attributes into several disjoint subsets. Each of these individual attributes may have the stereotype ≪atpVariation≫, which means that the attribute value pattern is applied, and the value of the attribute may be determined by an expression.
