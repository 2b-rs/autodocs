  • Klassifikation: Informelles Metamodell-Instanz- und Transformationsdiagramm (Signal- und Datentyp-Mapping-Hierarchie).
  • Technischer Zweck: Visualisierung des strukturellen Mappings von geschachtelten Anwendungsdatentypen (ApplicationRecordDataType) auf flache logische Systemsignale (SystemSignalGroup, SystemSignal) sowie deren nachgelagerte Auffächerung (1:n RTE Fanout) in bus- bzw. empfängerspezifische Interaktionssignale (ISignalGroup, ISignal) innerhalb des AUTOSAR System Templates (VFB-to-Network Mapping).

2. Komponenten, Entitäten & Schnittstellen

#### Entitäten & Schichten

  • Applikations-Datentypebene (VFB / SWC):
  • Record A: Wurzel-Datentyp (ApplicationRecordDataType).
  • Int X: Primitives Element erster Ordnung (ApplicationRecordElement, Integer).
  • Record B: Geschachteltes Element (ApplicationRecordElement, Sub-Record).
  • Int Y, Bool Z: Primitive Blattelemente (ApplicationRecordElement) innerhalb von Record B.
  • Systemsignal-Ebene (ECU-unabhängige System Description):
  • SystemSignalGroupA: Gruppiert die aus Record A hervorgehenden Systemsignale; Zuordnung über DataElementToSystemSignalGroupMapping.
  • SystemSignal X, SystemSignal Y, SystemSignal Z: Flache Menge von SystemSignal-Instanzen.
  • Transformation: Flattening. Die hierarchische Schachtelung von Record B wird vollständig eliminiert. Jedes Blatt mit ApplicationPrimitiveDataType wird direkt als eigenständiges SystemSignal an SystemSignalGroupA aggregiert (systemSignalGroup.systemSignal).
  • Netzwerk- / Interaktionsebene (COM- & PDU-Schicht):
  • ISignalGroupA_1, ISignalGroupA_2: Spezifische ISignalGroup-Instanzen für getrennte Empfängerpfade bzw. Netzwerke.
  • ISignal X_1, ISignal Y_1, ISignal Z_1: Konkrete Gruppen-Signale (GroupSignals) innerhalb von ISignalGroupA_1.
  • ISignal X_2, ISignal Y_2, ISignal Z_3: Gruppen-Signale innerhalb von ISignalGroupA_2 (Tippfehler Z_3 im Originaldiagramm repräsentiert das korrespondierende Signal zu SystemSignal Z).

#### Beziehungen & Kardinalitäten

  • Record A $\to$ SystemSignalGroupA: 1:1 Semantische Abbildung.
  • RecordElement (primitiv) $\to$ SystemSignal: 1:1 Mapping.
  • SystemSignalGroup $\to$ ISignalGroup: 1:n Fanout (Multiplexing/Routing über unterschiedliche Busse/Ports).
  • SystemSignal $\to$ ISignal: 1:n Abbildung (jedes SystemSignal wird je Zielpfad in ein dediziertes ISignal instanziiert).
  • Aggregation: ISignalGroup aggregiert ISignal als Sub-Elemente über die Relation iSignalGroup.iSignal.

3. Dynamisches Verhalten & Sequenzablauf

  1. Datentyp-Flachlegung (Design-Time / System Generation):
  • Der hierarchische Typenbaum wird traversiert: Primitive Blätter (Int X, Int Y, Bool Z) werden extrahiert und in eine flache Signal-Liste überführt.
  1. RTE Fanout & Pfadtrennung:
  • Wird dieselbe Signalquelle an mehrere Senken übertragen (RTE Fanout, Inter-ECU), instanziiert der System-Generator für jeden Pfad eine autonome ISignalGroup (A_1, A_2).
  1. COM Shadow Buffer Mechanismus (Runtime / BSW-Interaktion):
  • Sender-Seite: Schreibzugriffe auf Signale einer Gruppe erfolgen in den Shadow Buffer (Com_UpdateShadowSignal).
  • Triggerung: Com_SendSignalGroup kopiert den Shadow Buffer atomar in die I-PDU und initiiert die Übertragung gemäß Übertragungsmodus (Direct/Periodic).
  • Empfänger-Seite: Com_ReceiveSignalGroup friert den Zustand der I-PDU in den lokalen Puffer ein; atomares Auslesen der Signale via Com_ReceiveShadowSignal.

4. Normative Relevanz & Entwickler-Hinweise

  • [TPS_SYST_01156] (ISignalTriggering für Gruppen und Gruppensignale):
  • Wird eine ISignalGroup durch ein ISignalTriggering referenziert, dürfen auch die darin enthaltenen ISignal-Elemente (GroupSignals) separat von ISignalTriggerings referenziert werden (z. B. erforderlich für Signal-Gatewaying, PDU-Multiplexing oder partielle Bus-Updates).
  • [TPS_SYST_01157] & [constr_3094] (Konsistente Kommunikationsrichtung):
  • Falls Gruppensignale über eigene ISignalTriggerings angebunden sind, muss die communicationDirection (SEND / RECEIVE) des referenzierten ISignalPorts exakt mit der communicationDirection des Ports der übergeordneten ISignalGroup übereinstimmen. Gemischte Sende-/Empfangsrichtungen innerhalb einer Gruppe sind unzulässig.
  • Heterogene Netzwerk-Repräsentationen:
  • Trotz gemeinsamer SystemSignal-Quelle können ISignal X_1 und ISignal X_2 unterschiedliche Bus-Repräsentationen besitzen:
  • Abweichende Byte-Order (Little Endian / Big Endian).
  • Unterschiedliche Bitlängen, Skalierungen (CompuMethod) oder Transformationen (E2E-Protection / Data Transformation via Transformer-Chain).
  • Entwickler-Konsequenz:
  • Im SWC-Code bleibt die hierarchische struct-Semantik vollständig erhalten.
  • Im BSW-Stack (COM) existiert keine Schachtelung: Jedes Leaf-Signal muss im Com-Stack separat konfiguriert werden (ComGroupSignal), während die ComSignalGroup ausschließlich die Datenkonsistenz und den gemeinsamen PDU-Transfer garantiert.
