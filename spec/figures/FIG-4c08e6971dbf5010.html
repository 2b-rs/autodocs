1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR Methodology / SPEM-basiertes Prozessfluss-Diagramm (Rollen-, Aktivitäts- und Artefakt-Modellierung gemäß AUTOSAR Methodik-Profil).
  • Technischer Zweck: Spezifikation des methodischen Arbeitsschritts zur Ableitung der herstellerspezifischen BSW-Moduldefinition (EcucModuleDef) aus den standardisierten AUTOSAR-Parametervorgaben.
  • Architektonische Einordnung: Lokalisierung auf Ebene des BSW-Vendors (Tier-1/Tier-2/Tool-Vendor) vor der eigentlichen ECU-Konfigurationsphase (BSW-Design-Time). Dient als formale Definitionsgrundlage für den Konfigurationseditor (BSW-Konfigurator) und den BSW-Codegenerator.

2. Komponenten, Entitäten & Schnittstellen

  • Akteure / Rollen (SPEM Roles):
    • Basic Software Designer: Verantwortlich für die Gesamtarchitektur und Parameterstruktur des BSW-Moduls.
    • Basic Software Module Developer: Verantwortlich für implementierungs- und treiberspezifische Parameterdefinitionen.
    • Beziehung: Assoziation mit Stereotyp «performs», Kardinalität jeweils 0..1 (die Aktivität wird alternativ oder kollaborativ von Designer und/oder Entwickler ausgeführt).
  • Prozessaktivität (Activity):
    • Define Vendor Specific Module Definition: Transformiert Standarddefinitionen in die herstellerspezifische Parameter-Beschreibung.
  • Artefakte (Work Products / ARXML-Deskriptoren):
    • AUTOSAR Standardized ECU Configuration Parameter Definition («input», Kardinalität 1): Normativer XML-Datensatz (EcucModuleDef) aus der AUTOSAR-SWS-Auslieferung mit standardisierten Containern (EcucParamConfContainerDef) und Parametern (EcucParameterDef).
    • BSW Module Vendor Specific Parameter Definition («output», Kardinalität 1): Vendor-spezifische EcucModuleDef (z. B. für MCAL-, Memory- oder Kommunikations-Treiber), instanziiert pro BSW-Modul (per module).

3. Dynamisches Verhalten & Sequenzablauf

  • Methodischer Ablauf (statische Toolchain-Phase, keine Target-Laufzeit):
    1. Ingestion: Import der normativen AUTOSAR Standardized ECU Configuration Parameter Definition des Ziel-Releases (R4.2.2 / R4.3.1).
    2. Refinement & Restriction:
      • Einschränkung von Kardinalitäten (z. B. Standard 0..* auf hardwarebedingt 1..4 Channels).
      • Einschränkung von Wertebereichen (lowerMultiplicity, upperMultiplicity, min, max für Integers/Floats).
    3. Vendor Extension:
      • Hinzufügen herstellerspezifischer Parameter (z. B. Hardware-Register-Offsets, Clock-Divider, Interrupt-Prioritäten, optimierte Buffer-Modi).
      • Ergänzung herstellerspezifischer Container (vendorSpecific = true).
    4. Pre-Configuration & Recommendations:
      • Festlegung fester Parameterwerte (preconfiguredValue – zur Entwurfszeit unveränderlich für den Integrator).
      • Bereitstellung von Empfehlungswerten (recommendedValue – Standardbelegungen mit Überschreibrecht).
    5. Serialization: Generierung des vendor-spezifischen ARXML-Files für das Modul.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationsvertrag:
    • Standardparameter dürfen nicht gelöscht oder semantisch verändert werden. Eine Verletzung der Standard-Validierungsregeln (Metamodell AUTOSAR_MMOD_ECUConfigurationParameterDefinition.xsd) führt zur Inkompatibilität bei OEM-Konfigurationsprüfungen.
    • Zulässige Modifikationen sind strikt hierarchisch: Der Vendor darf Vorgaben nur präzisieren oder um proprietäre Parameter erweitern, niemals die standardisierte Schnittstelle aufweichen.
  • Relevanz für Treiber- und BSW-Entwickler (MCAL/BSW-Layer):
    • Das resultierende EcucModuleDef legt 1:1 die Generierungsstruktur für Pre-Compile-Makros (#define MODULE_CFG_*), Link-Time-Strukturen und Post-Build-Arrays fest.
    • Parameter mit festgelegtem preconfiguredValue müssen im Treiber-C-Code direkt hardcodiert oder über konstante Header aufgelöst werden; variable Parameter fließen in die Initialisierungsstruktur (ConfigPtr an <Modul>_Init()).
  • Tooling & Integration:
    • Das erzeugte Artefakt ist die zwingende Voraussetzung für den BSW-Integrator: Ohne dieses Modul-ARXML kann im Konfigurationswerkzeug (z. B. DaVinci Configurator, EB tresos) keine Instanzierung der EcucModuleConfigurationValues für das Modul erfolgen.
