1. Diagrammtyp & Architektur-Kontext

Struktur- und Interaktionsdiagramm (Architekturübersicht mit nummeriertem Kontroll- und Datenfluss) für die AUTOSAR Classic Platform. Das Diagramm visualisiert den Gesamtablauf der E2E-Absicherung beim Senden sicherheitsrelevanter Daten über einen P-Port (Callout – overall flow – P-port). Es ordnet die beteiligten Schichten vom Application Layer über die AUTOSAR Runtime Environment (RTE) bis in die Communication Services des Basic Software (BSW) Stacks und die parallel liegende E2E Library ein.

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Software-Einheiten, Schichten und Schnittstellen:

  • OS-Application 1 / SW-C 1: Software-Component im Application Layer, erzeugt sicherheitsrelevante Datenelemente (safe data elements).
  • AUTOSAR Runtime Environment (RTE): Vermittlungsschicht zwischen SW-C und Basissoftware. Schnittstelle zur SW-C: RTE_*_<p>_<o>().
  • Communication Services (BSW):
    • COM: AUTOSAR-Kommunikationsmodul, empfängt COM Signals von der RTE und serialisiert diese in eine I-PDU.
    • COM E2E Callouts: Spezifischer Callout-Mechanismus innerhalb des COM-Moduls, aufgerufen über IPDU_E2EProtect_<IPDU ID>(Pduld, IPduData).
    • PDU Router (PduR): Untergeordnete Routing-Instanz für die I-PDU-Weiterleitung.
  • Libraries / E2E Lib: Funktionsbibliothek zur E2E-Absicherung, aufgerufen über E2E_PXXProtect(&Config, &State, (unit8*) IPduData). Rückgabe von aktualisierten Zuständen und I-PDU-Nutzdaten (State, IPduData).

3. Dynamisches Verhalten & Sequenzablauf

Sequentieller Kontroll- und Datenfluss (Schritte 1 bis 11):

  1. SW-C 1: Erzeugt sicherheitsrelevante Datenelemente (1. Produce safe data elements).
  2. SW-C 1 an RTE: Aufruf der Sende-API RTE_*_<p>_<o>() zur Übergabe des Datenelements (2. Invoke RTE - RTE_*_<p>_<o>() to transmit the data element).
  3. RTE: Bildet die Datenelemente auf COM-Signale ab (3. Map Data Elements to signals).
  4. RTE an COM: Übergabe der COM-Signale an das COM-Modul (4. COM Signals).
  5. COM: Serialisiert die Signale in die I-PDU (5. Serialize signals on I-PDU).
  6. COM an COM E2E Callouts: Auslösen des IPDU-spezifischen Callouts über 6. IPDU_E2EProtect_<IPDU ID>( Pduld, IPduData).
  7. COM E2E Callouts an E2E Lib: Aufruf der Protokollschutzfunktion 7. E2E_PXXProtect(&Config, &State, (unit8*) IPduData).
  8. E2E Lib: Führt den Schutzalgorithmus aus und schreibt E2E-Steuerfelder (z. B. CRC, Counter) in die PDU-Daten (8. Execute E2E Library, wrte control fields (e.g. CRC, Counter) in IPduData).
  9. E2E Lib an COM E2E Callouts: Rückgabe der aktualisierten Parameter (9. Updated parameters State and IPduData).
  10. COM E2E Callouts an COM: Rückmeldung des Status und der geschützten Daten (10. ret: TRUE if no error else FALSE; updated IPduData).
  11. COM an PDU Router: Weiterleitung der I-PDU nur bei erfolgreichem Schutz (11. If (ret = TRUE) deliver IPduData; else no action).

4. Normative Relevanz & Entwickler-Hinweise

Normative Architektur- und Integrationshinweise:

  • Die E2E-Absicherung im Senderpfad erfolgt auf I-PDU-Ebene unterhalb der Signal-Serialisierung im COM-Modul über konfigurierte I-PDU-Callouts (IPDU_E2EProtect_<IPDU ID>).
  • Die Software-Component bleibt frei von direkten E2E-Library-Aufrufen und übergibt ungeschützte Nutzdaten über standardmäßige RTE-APIs.
  • Fehlerbehandlung: Schlägt der E2E-Schutz im Callout fehl (ret == FALSE), verwirft das COM-Modul die I-PDU und unterdrückt die Weiterleitung an den PDU Router vollständig (else no action).
  • Typ- und Signaturdetails: Die E2E-Library-Schnittstelle arbeitet generisch mit Zeigern auf Konfigurations- und Zustandsstrukturen sowie einem Byte-Pointer auf den PDU-Puffer ((unit8*) IPduData, im Bild mit dem Tippfehler unit8* beschriftet).
