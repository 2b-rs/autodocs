1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm (sd EthTSyn_PdelaySequence) zur Darstellung des Peer-Delay-Mechanismus (Pdelay nach IEEE 802.1AS / AUTOSAR) über Ethernet. Das Diagramm spezifiziert die Interaktion zwischen dem Zeit-Synchronisationsmodul für Ethernet (EthTSyn) und dem Synchronized Time-Base Manager (StbM) sowohl auf Seiten des Initiators (Time Slave) als auch auf Seiten des Responders (Time Master).

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Komponenten (jeweils mit Stereotyp «module»):

  • StbM (Time Slave): StbM – Synchronized Time-Base Manager auf Initiator-Seite
  • EthTSyn (Time Slave): EthTSyn – Ethernet Time Synchronization Modul auf Initiator-Seite (Pdelay Initiator)
  • EthTSyn (Time Master): EthTSyn – Ethernet Time Synchronization Modul auf Responder-Seite (Pdelay Responder)
  • StbM (Time Master): StbM – Synchronized Time-Base Manager auf Responder-Seite

Schnittstellen und Nachrichten:

  • Interne Treiber-/Hardware-Interaktionen: Rx ISR(), Tx Confirmation ISR(), EthTSyn_TxConfirmation(), sowie referenzierte Sub-Sequenzen (INTERNAL) EthTSyn Egress Time Stamping und (INTERNAL) EthTSyn Ingress Time Stamping.
  • Modul-Scheduling: Zyklische Hauptfunktionen EthTSyn_MainFunction().
  • Modulübergreifende C-APIs:
    • StbM_BusGetCurrentTime(timeBaseId, &T_refPDInitiator, &Tvlt_refPDInitiator, &userData)
    • StbM_BusGetCurrentTime(timeBaseId, &T_refPDResponder, &Tvlt_refPDResponder, userData)
    • StbM_EthSetPdelayResponderData(timeBaseId, measurementData)
    • StbM_EthSetPdelayInitiatorData(timeBaseId, measurementData)
  • Ethernet-PDUs (Busnachrichten):
    • pDelayRequest Message ()
    • pDelayResponse Message (requestReceiptTimestamp)
    • pDelayResponseFollowup Message (responseOriginTimestamp)

3. Dynamisches Verhalten & Sequenzablauf

  1. Pdelay-Request-Phase (Initiator):
    • Im Kontext von EthTSyn_MainFunction() ruft EthTSyn (Time Slave) optional (opt [Safety Validation enabled]) StbM_BusGetCurrentTime(...) auf, um die lokalen Referenzzeiten T_refPDInitiator und Tvlt_refPDInitiator abzufragen.
    • EthTSyn (Time Slave) sendet die pDelayRequest Message () an den Time Master.
    • Das Senden löst auf Initiator-Seite Tx Confirmation ISR() und das Erfassen des Sendezeitpunkts t1 via Sub-Sequenz (INTERNAL) EthTSyn Egress Time Stamping aus.
    • Der Empfang der Request-Nachricht löst bei EthTSyn (Time Master) Rx ISR() und die Erfassung des Empfangszeitpunkts t2 via Sub-Sequenz (INTERNAL) EthTSyn Ingress Time Stamping aus.
  2. Pdelay-Response-Phase (Responder):
    • Im nächsten EthTSyn_MainFunction() des Time Masters verzweigt ein alt-Block:
      • [Time Validation enabled]: Abfrage von StbM_BusGetCurrentTime(...) gefolgt von der Berechnung requestReceiptTimestamp = T_refPDResponder - (Tvlt_refPDResponder - t2).
      • [Time Validation disabled]: Direkte Zuweisung requestReceiptTimestamp = t2.
    • EthTSyn (Time Master) sendet pDelayResponse Message (requestReceiptTimestamp) an den Time Slave.
    • Beim Time Slave löst der Empfang Rx ISR() und die Erfassung des Empfangszeitpunkts t4 via (INTERNAL) EthTSyn Ingress Time Stamping aus.
  3. Pdelay-Response-Followup- und Responder-Datenübergabe-Phase:
    • Der Versand der Response-Nachricht führt beim Master zu Tx Confirmation ISR() und EthTSyn_TxConfirmation(), worin der Sendezeitpunkt t3 via Sub-Sequenz (INTERNAL) EthTSyn Egress Time Stamping erfasst wird.
    • Im nachfolgenden EthTSyn_MainFunction() des Masters verzweigt ein zweiter alt-Block:
      • [Time Validation enabled]: Berechnung responseOriginTimestamp = T_refPDResponder + (t3 - Tvlt_refPDResponder).
      • [Time Validation disabled]: Direkte Zuweisung responseOriginTimestamp = t3.
    • EthTSyn (Time Master) überträgt pDelayResponseFollowup Message (responseOriginTimestamp) über den Bus.
    • Im nächsten Zyklus von EthTSyn_MainFunction() assembliert der Responder measurementData = {requestSequenceId, requestSourcePortId, responseSourcePortId, t2, t3, Tvlt_refPDResponder, T_refPDResponder} und übergibt diese unkonditioniert via StbM_EthSetPdelayResponderData(timeBaseId, measurementData) an den Master-StbM.
  4. Pdelay-Abschluss und Initiator-Datenübergabe-Phase:
    • Beim Time Slave löst das Eintreffen der Followup-Nachricht Rx ISR() und (INTERNAL) EthTSyn Ingress Time Stamping aus.
    • Im nachfolgenden EthTSyn_MainFunction() des Slaves werden bei aktiver Time Validation (opt [Time Validation enabled]) die Messdaten measurementData = {requestSequenceId, requestSourcePortId, responseSourcePortId, t1, t4, requestReceiptTimestamp, responseOriginTimestamp, Tvlt_refPDInitiator, T_refPDInitiator} zusammengestellt und per StbM_EthSetPdelayInitiatorData(timeBaseId, measurementData) an den Slave-StbM übermittelt.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Schnittstellenanforderungen: Spezifiziert die Kopplung zwischen EthTSyn und StbM zur Unterstützung der Laufzeitmessung (Propagation Delay) sowie der Time-/Safety-Validation.
  • Zeitstempelberechnung: Bei aktivierter Time Validation müssen die Zeitstempel im Responder (requestReceiptTimestamp und responseOriginTimestamp) um den Offset zur Virtual Local Time (Tvlt_refPDResponder) bezogen auf T_refPDResponder korrigiert werden, um synchrone Bus-Referenzzeiten in den Pdelay-Nachrichten zu garantieren; bei deaktivierter Time Validation werden die reinen Hardware-/Treiberzeitstempel t2 und t3 unmodifiziert versendet.
  • Konfigurationsabhängigkeit: Die Erfassung und Weiterleitung von Messwerten an den StbM setzt die entsprechenden Validierungs-Features (Safety Validation enabled bzw. Time Validation enabled) voraus.

  • Zeitstempelberechnung für responseOriginTimestamp beim Responder: Das alt-Konstrukt ([Time Validation enabled] mit Referenzzeitkorrektur vs. [Time Validation disabled] mit t3) wurde ersetzt durch die generelle Zuweisung responseOriginTimestamp = t3.
  • Übergabe der Responder-Messdaten an StbM: Die Aufbereitung von measurementData und der Aufruf StbM_EthSetPdelayResponderData(...) wurden in einen opt [Time Validation enabled]-Block gekapselt (zuvor unbedingte Ausführung im Responder-Hauptzyklus).
  • UML-Diagrammrahmen: Der äußere Rahmen mit Bezeichner sd EthTSyn_PdelaySequence wurde entfernt.
