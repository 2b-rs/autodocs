1. Diagrammtyp & Architektur-Kontext

Protokoll-Paketformat / Bitfeld-Layout (RFC- bzw. IETF-Stil) im Rahmen des AUTOSAR Service-Oriented Middleware Protocol (SOME/IP Service Discovery). Das Diagramm spezifiziert das binäre Wire-Format der „IPv4 Multicast Option“, welche als typisierte Option innerhalb des SOME/IP-SD-Nachrichtenformats übertragen wird, um Multicast-Endpunkte (IP-Adresse und Layer-4-Port) für Eventgroups und Notification-Events zu signalisieren.

2. Komponenten, Entitäten & Schnittstellen

Das Datenformat ist in 32-Bit-Zeilen (Bit 0 bis 31) strukturiert und umfasst 96 Bit (12 Byte) Gesamtlänge:

  • Length (=0x0009): Bit 0 bis 15 (16 Bit / 2 Byte), fixer Wert 0x0009. Gibt die konfigurierte Datenlänge der Option abzüglich des eigenen Längenfeldes an.
  • Type (=0x14): Bit 16 bis 23 (8 Bit / 1 Byte), fixer Typbezeichner 0x14 für die IPv4 Multicast Option.
  • Reserved (=0x00): Bit 24 bis 31 (8 Bit / 1 Byte), reserviertes Feld, fix auf 0x00 gesetzt.
  • IPv4-Address [32bit]: Bit 0 bis 31 der zweiten Zeile (32 Bit / 4 Byte), kodiert die IPv4-Multicast-Zieladresse.
  • Reserved (=0x00): Bit 0 bis 7 der dritten Zeile (8 Bit / 1 Byte), reserviertes Feld, fix auf 0x00 gesetzt.
  • L4-Proto (UDP/...): Bit 8 bis 15 der dritten Zeile (8 Bit / 1 Byte), Transportprotokoll gemäss IANA (typisch 0x11 für UDP).
  • Port Number: Bit 16 bis 31 der dritten Zeile (16 Bit / 2 Byte), Ziel-Portnummer des Transportprotokolls.
  • Covered by Length (incl. Reserved): Bemaßungspfeil rechts, der die Bytes ab Bit 16 der ersten Zeile (Type) bis Bit 31 der dritten Zeile (Port Number) umfasst und die 9 Byte des Length-Feldes darstellt.

3. Dynamisches Verhalten & Sequenzablauf

Statisches Datenstrukturdiagramm ohne sequenzielle Zustandsübergänge. Die Option wird von einem SOME/IP-SD-Server serialisiert und referenziert, wenn ein Dienst bzw. eine Eventgroup über Multicast bereitgestellt wird. Ein SOME/IP-SD-Client deserialisiert die Option beim Empfang von Offer-Service- bzw. Subscribe-Eventgroup-Ack-Nachrichten, extrahiert die IPv4-Multicast-Adresse sowie den L4-Port und tritt der Multicast-Gruppe über das Socket-Interface des Betriebssystems / TCP/IP-Stacks bei.

4. Normative Relevanz & Entwickler-Hinweise

Normativ bindendes Binärformat gemäß [PRS_SOMEIPSD_00327].

  • Das Feld Length muss exakt 0x0009 betragen und deckt Type, das erste Reserved, IPv4-Address, das zweite Reserved, L4-Proto sowie Port Number ab (insgesamt 9 Byte).
  • Das Feld Type muss zwingend auf 0x14 kodiert werden.
  • Beide Reserved-Felder müssen auf 0x00 gesetzt werden; Empfänger müssen reservierte Felder ignorieren oder auf 0x00 validieren.
  • Byte-Order ist Netzwerk-Byte-Reihenfolge (Big-Endian).
  • Für den Transport von Multicast-Events wird auf Layer 4 standardmäßig UDP (0x11) eingesetzt.
