1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm (Metamodell-Ausschnitt der AUTOSAR ECU Configuration Parameter Definition / ECUC).
  • Funktionale Einordnung: Spezifikation der Konfigurationsstruktur des LIN Transport Protocol (LinTp, Teilschicht des LinIf-Moduls im Communication Stack der AUTOSAR Classic Platform). Es definiert den Container LinTpRxNSdu zur statischen Parametrierung von segmentierten Empfangsbotschaften (Diagnostic / Transport Protocol Requests, ISO 17987-2 bzw. LIN TP) über LIN-Cluster in Richtung PDU Router (PduR).

2. Komponenten, Entitäten & Schnittstellen

Zentraler Konfigurationscontainer
  • LinTpRxNSdu (EcucParamConfContainerDef):
    • Multiplizität: 0..* (Beliebig viele Rx-N-SDU-Definitionen pro Modulkonfiguration, mindestens 0).
    • Repräsentiert die logische Instanz einer empfangsseitigen Transport-Protocol-PDU (N-SDU) auf LIN.
Parameter (+parameter)
  • LinTpRxNSduNad (EcucIntegerParamDef):
    • Wertebereich: [0 .. 255] (8-Bit Integer).
    • Spezifiziert die Node Address (NAD) des Slaves bzw. LIN-Teilnehmers. Dient der Adressfilterung eingehender Single Frames (SF) und First Frames (FF).
  • LinTpRxNSduId (EcucIntegerParamDef):
    • Wertebereich: [0 .. 65535] (16-Bit Integer, PduIdType).
    • Eigenschaften: withAuto = true, symbolicNameValue = true.
    • Numerischer Handle-Identifier zur eindeutigen Adressierung dieser Rx-N-SDU an der oberen Schnittstelle (LinTp_RxIndication / Interaktion mit PduR).
  • LinTpNcr (EcucFloatParamDef):
    • Wertebereich: [0.0 .. 1.0] (Sekunden).
    • Multiplizität: 0..1 (Optional).
    • Definiert das normative Timeout N_Cr (Time until reception of the next Consecutive Frame). Ablauf des Timers bricht die segmentierte Übertragung ab.
Referenzen (+reference → +destination)
  • LinTpRxNSduPduRef (EcucReferenceDef):
    • Ziel: Pdu (EcucParamConfContainerDef, aus Paket EcucPdu, Multiplizität 0..*).
    • Verknüpft die LinTp-interne N-SDU mit der systemweiten globalen PDU-Tabelle im EcuC-Metamodell (Aufrufziel für PduR_LinTpStartOfReception, PduR_LinTpCopyRxData, PduR_LinTpRxIndication).
  • LinTpRxNSduChannelRef (EcucReferenceDef):
    • Eigenschaften: requiresSymbolicNameValue = true.
    • Ziel: ComMChannel (EcucParamConfContainerDef, aus Paket ComM, Multiplizität 1..256).
    • Mappt die Empfangs-N-SDU auf den zugehörigen Kommunikationskanal des Communication Managers (ComM), um Netzwerk-Management-Zustände (Full-Com / No-Com) und den physischen LIN-Cluster zuzuordnen.

3. Dynamisches Verhalten & Sequenzablauf

Obwohl es sich um ein statisches Konfigurationsdiagramm handelt, bedingen die enthaltenen Parameter direkt das Laufzeitverhalten des LinTp-Empfangszustandsautomaten:

  1. Trigger & Empfangsstart:
    • Empfang eines Master-Request-Frames (0x3C) oder Slave-Response-Frames (0x3D) via LinIf_RxIndication.
    • LinTp prüft das Byte 0 (NAD). Stimmt dieses mit LinTpRxNSduNad überein (oder Broadcast 0x7F), wird die PDU der korrespondierenden LinTpRxNSduId zugeordnet.
  2. Buffer Allocation (PduR):
    • Bei Single Frame (SF) oder First Frame (FF) ruft LinTp synchron PduR_LinTpStartOfReception(LinTpRxNSduId, ...) auf.
    • Rückgabewert BUFREQ_OK: Puffer bereitgestellt; Timer N_Cr (LinTpNcr) wird scharfgeschaltet.
    • Rückgabewert BUFREQ_E_NOT_OK / BUFREQ_E_OVFL: Empfang wird verworfen.
  3. Consecutive Frames & Timeout-Handling:
    • Jeder nachfolgende Consecutive Frame (CF) führt zu PduR_LinTpCopyRxData(...) und setzt den Timer LinTpNcr zurück.
    • Abbruchbedingung: Trifft innerhalb des Fensters LinTpNcr kein gültiger CF ein (N_Cr-Timeout), bricht LinTp den Transfer sofort ab und meldet PduR_LinTpRxIndication(LinTpRxNSduId, E_NOT_OK).
  4. Erfolgreicher Abschluss:
    • Nach vollständigem Datenerhalt wird der Timer deaktiviert und PduR_LinTpRxIndication(LinTpRxNSduId, E_OK) signalisiert.

4. Normative Relevanz & Entwickler-Hinweise

  • PDU-Router-ID-Mapping: LinTpRxNSduId generiert das C-Makro (LinTpConf_LinTpRxNSdu_<Name>). Die ID muss im BSW-Stack 0-basiert und lückenlos sein, wenn sie als direkter Tabellenindex in LinTp verwendet wird (withAuto = true überlässt dem Generator die kollisionsfreie Zuweisung).
  • Kanalbindungen: Über LinTpRxNSduChannelRef ist zwingend sicherzustellen, dass nur ComMChannel-Referenzen verwendet werden, die einem LIN-Bussystem zugeordnet sind; fehlerhafte Zuordnungen müssen durch Model-Checks/Generatorkonsistenzprüfungen abgefangen werden.
  • N_Cr-Timer-Auflösung: Der Float-Wert LinTpNcr wird vom Codegenerator auf die Main-Function-Zykluszeit (LINIF_MAIN_FUNCTION_PERIOD bzw. LinTp_MainFunction) in ganzzahlige Ticks skaliert. Entwickler müssen sicherstellen, dass die Periodizität der Task fein genug ist, um das konfigurierte Intervall präzise abzubilden (Vermeidung von Aliasing/Jitter bei N_Cr ≤ 1.0\,s).
