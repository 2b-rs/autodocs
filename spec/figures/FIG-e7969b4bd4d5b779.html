1. Diagrammtyp & Architektur-Kontext

Aktivitäts- und Datenflussdiagramm der AUTOSAR-Methodik zur Veranschaulichung des Build- und Konfigurationsprozesses für BSW-Module mit Link-Time-Konfiguration (Link-Time-Bindung). Das Diagramm stellt dar, wie vorkompilierter BSW-Code und separat kompilierte Konfigurationsdaten während der Link-Phase zur ECU-Executable zusammengeführt werden.

2. Komponenten, Entitäten & Schnittstellen

Artefakte (Datenobjekte):

  • Basic Software Module Core Source Code (Kardinalität 1)
  • Basic Software Module Core Header (Kardinalität 1)
  • ECU Configuration Values (Kardinalität 1)
  • Basic Software Module Object Code (Kardinalität 1 als Output, Multiplizität 1..* als Input zum Linker)
  • BSW Module Configuration Header File (Kardinalität 1)
  • BSW Module Configuration Data Source Code (Kardinalität 1)
  • BSW Module Configuration Data Object Code (Kardinalität 1 als Output, Multiplizität 1..* als Input zum Linker)
  • ECU Executable (Kardinalität 1 als Output des Linkers)

Aktivitäten (Prozessschritte):

  • Compile Unconfigured BSW: Kompiliert Quellcode und Header zu unkonfiguriertem Objektcode.
  • Generate BSW Configuration Code: Generiert modulspezifische Konfigurations-Header und -Quelldateien aus den ECU-Konfigurationswerten.
  • Compile BSW Configuration Data: Kompiliert die generierten Konfigurationsdateien zusammen mit dem Modul-Header zu Konfigurations-Objektcode.
  • Link ECU Code during Link Time Configuration: Bindet die BSW-Objektdateien und Konfigurations-Objektdateien zur finalen ECU-Executable.

Alle Kanten sind gerichtet und mit Stereotypen («input», «output») sowie Kardinalitäten/Multiplizitäten (1, 1..*) annotiert.

3. Dynamisches Verhalten & Sequenzablauf

  1. Generierung der Konfigurationsdateien: Generate BSW Configuration Code konsumiert die ECU Configuration Values [1] und erzeugt die BSW Module Configuration Header File [1] sowie den BSW Module Configuration Data Source Code [1].
  2. Kompilierung des Kern-BSW-Codes: Unabhängig von den Konfigurationswerten liest Compile Unconfigured BSW den Basic Software Module Core Source Code [1] und den Basic Software Module Core Header [1] ein und erzeugt den Basic Software Module Object Code [1].
  3. Kompilierung der Konfigurationsdaten: Compile BSW Configuration Data liest den Basic Software Module Core Header [1], die generierte BSW Module Configuration Header File [1] und den generierten BSW Module Configuration Data Source Code [1] ein und erzeugt den BSW Module Configuration Data Object Code [1].
  4. Link-Vorgang: Link ECU Code during Link Time Configuration nimmt mindestens ein Basic Software Module Object Code [1..] und mindestens ein BSW Module Configuration Data Object Code [1..] entgegen und linkt diese zur ECU Executable [1].

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm verdeutlicht das Entkopplungsprinzip der Link-Time-Konfiguration in AUTOSAR: Der generische Quellcode des BSW-Moduls (Basic Software Module Core Source Code) bleibt unabhängig von konkreten ECU-Konfigurationswerten kompilierbar, wodurch BSW-Module als vorkompilierter Objektcode ausgeliefert werden können. Die systemspezifische Ausprägung erfolgt über separate Konfigurationsdatenstrukturen, die erst im Link-Schritt gebunden werden. Tool-Hersteller und Integratoren müssen sicherstellen, dass die generierten Konfigurations-Header und -Objektdateien binärkompatibel zu den Annahmen des vorkompilierten Kern-Objektcodes sind.
