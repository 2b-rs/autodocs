1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR ECU Configuration (ECUC) Parameter Definition Metamodel (UML-Klassendiagramm-Notation gemäß AUTOSAR-Metamodell).
  • Technischer Zweck: Formale Definition des Konfigurationscontainers J1939DcmNode innerhalb des BSW-Moduls J1939Dcm (SAE J1939 Diagnostic Communication Manager, Classic Platform R23-11).
  • Systemeinordnung: Modellierung eines logischen J1939-Knotens (Controller Application / CA) auf dem Steuergerät. Der Container konsolidiert die Abhängigkeiten zur Netzwerkverwaltung (J1939Nm), zum J1939-Request-Manager (J1939Rm), zum Diagnose-Ereignis-Manager (Dem) sowie die Schnittstellen zur Abwicklung generischer J1939-Diagnosemeldungen (DMx) und Datenstrom-SPNs (Suspect Parameter Numbers).

2. Komponenten, Entitäten & Schnittstellen

Zentraler Container
  • J1939DcmNode (EcucParamConfContainerDef, Multiplizität: 1..*): Repräsentiert die Konfigurationsinstanz eines logischen J1939-Knotens im DCM. Mindestens ein Knoten muss vorhanden sein; Multihoming bzw. Multi-CA-Szenarien werden unterstützt.
Konfigurationsparameter (Composition +parameter)
  • J1939DcmSPNsInDataStream (EcucIntegerParamDef, 0..*):
    • Wertebereich: 0 bis 524287 (2^19-1, entspricht dem 19-Bit-Adressraum für SPNs nach SAE J1939-71).
    • Spezifiziert die Liste aller SPNs, die von diesem Knoten in periodischen/kontinuierlichen Datenströmen unterstützt werden.
  • Generic DMx Callbacks (EcucFunctionNameDef, jeweils Multiplizität 0..1): Definieren C-Funktionsnamen für die Behandlung nicht-standardisierter oder anwendungsspezifischer J1939-Diagnosemeldungen (DMx):
    • J1939DcmGenericDMxRequestFunction: Eingehende Requests auf DMx auswerten.
    • J1939DcmGenericDMxStartOfReceptionFunction: Beginn des PDU-Empfangs (Buffer-Allocation).
    • J1939DcmGenericDMxCopyRxDataFunction: Segmentiertes Kopieren empfangener Nutzdaten.
    • J1939DcmGenericDMxRxIndicationFunction: Bestätigung des vollständigen Nachrichtenempfangs.
    • J1939DcmGenericDMxCopyTxDataFunction: Bereitstellung von Sendedaten bei segmentiertem Transfer.
    • J1939DcmGenericDMxTxConfirmationFunction: Bestätigung des erfolgreichen PDU-Versands.
Modulübergreifende Referenzen (+reference → +destination)
  • J1939DcmNmNodeRef (EcucReferenceDef, 1..1, requiresSymbolicNameValue = true):
    • Ziel: J1939NmNode (EcucParamConfContainerDef, 1..*, aus Paket J1939Nm).
    • Assoziierter Parameter im Ziel: J1939NmNodeId (EcucIntegerParamDef, Bereich 0..255, withAuto = true, symbolicNameValue = true).
    • Bindet den logischen Diagnoseknoten zwingend an einen Knoten des J1939-Network-Managements zur Auflösung von Quelladresse (Source Address / SA) und Address Claiming.
  • J1939DcmNodeRmUserRef (EcucReferenceDef, 1..1, requiresSymbolicNameValue = true):
    • Ziel: J1939RmDcmUser (EcucParamConfContainerDef, 0..1, aus Paket J1939Rm).
    • Bindet den Knoten an den J1939 Request Manager, um Anfragen nach J1939-PGNs (PGN 59904 Request PGN) gezielt an den DCM weiterzuleiten.
  • J1939DcmDemClientRef (EcucReferenceDef, 1..1, requiresSymbolicNameValue = true):
    • Ziel: DemClient (EcucParamConfContainerDef, 1..255, aus Paket Dem).
    • Weist dem J1939Dcm-Knoten einen dedizierten Dem-Client für Abfragen, Filterung und Löschung von DTCs zu.
  • J1939DcmServiceOnlyDTCsMemoryDestinationRef (EcucReferenceDef, 0..1, requiresSymbolicNameValue = true):
    • Ziel: DemUserDefinedMemory (EcucParamConfContainerDef, 0..30, aus Paket Dem).
    • Optionale Zuweisung eines anwenderspezifischen Fehlerspeichers im Dem für rein servicebezogene DTCs (z. B. herstellerspezifische Service-Only-Events ohne Auswirkung auf OBD/Standard-J1939-Status).

3. Dynamisches Verhalten & Sequenzablauf

Obwohl das Diagramm statische Konfigurationsstrukturen abbildet, determiniert es folgende Laufzeitpfade:

  • Generic DMx RX-Pfad (segmentiert/Transportprotokoll):
    1. Trigger durch PDU-Router/J1939Tp bei Eintreffen einer generischen DMx-PDU.
    2. Aufruf von J1939DcmGenericDMxStartOfReceptionFunction zur Abfrage der Pufferverfügbarkeit in der Applikation/SW-C.
    3. Iterativer Aufruf von J1939DcmGenericDMxCopyRxDataFunction für TP-Segmente (BAM oder CMDT).
    4. Abschlussmeldung via J1939DcmGenericDMxRxIndicationFunction mit Ergebnisstatus (E_OK / E_NOT_OK).
  • Generic DMx TX-Pfad:
    1. Request-Eingang via PGN 59904 über J1939Rm führt zur Auswertung in J1939DcmGenericDMxRequestFunction.
    2. Bei Akzeptanz: PDU-Versand über den Kommunikationsstack; Nutzdaten werden portionsweise über J1939DcmGenericDMxCopyTxDataFunction angefordert.
    3. Quittierung über J1939DcmGenericDMxTxConfirmationFunction.
  • DTC- und Status-Handling (Dem-Kopplung):
    • Diagnosemeldungen wie DM1 (Active DTCs), DM2 (Previously Active DTCs), DM4 oder DM5 rufen synchron/asynchron APIs des konfigurierten DemClient auf.
    • Werden Service-Only DTCs angefordert, greift der Stack exklusiv auf den via J1939DcmServiceOnlyDTCsMemoryDestinationRef verlinkten DemUserDefinedMemory zu, ohne den primären Primärspeicher (DemPrimaryMemory) zu beeinflussen.

4. Normative Relevanz & Entwickler-Hinweise

  • Kardinalitäts- und Validierungsregeln:
    • Jeder J1939DcmNode erfordert zwingend valide Konfigurationsreferenzen auf J1939NmNode, J1939RmDcmUser und DemClient. Fehlt eine dieser Referenzen, schlägt die Pre-Compile-Validierung des BSW-Generators fehl.
    • Alle Referenzen fordern requiresSymbolicNameValue = true. Das Konfigurationswerkzeug muss hierfür generierte C-Makros/Konstanten auflösen.
  • Implementierungspflicht bei Generic DMx:
    • Werden die EcucFunctionNameDef-Einträge projektiert, müssen die Callback-Signaturen exakt den AUTOSAR-Buffer-Management-Signaturen (analog zu PduR/CanTp CopyRxData/CopyTxData APIs) entsprechen. Eine Nullzeiger-Konfiguration ist zulässig (Multiplicity 0..1), deaktiviert jedoch generische Diagnosenachrichten für diesen Knoten vollständig.
  • SPN-Datenstromfilter:
    • Der 19-Bit-Wertebereich (0..524287) in J1939DcmSPNsInDataStream muss im Generator gegen den SAE-Standard validiert werden (Bereich 0x00000 bis 0x7FFFF). Nicht konfigurierte SPNs dürfen vom DCM in periodischen Diagnose-Datenströmen nicht bedient werden.
  • Speichertrennung im Dem:
    • Die Nutzung von J1939DcmServiceOnlyDTCsMemoryDestinationRef setzt voraus, dass im Modul Dem mindestens ein DemUserDefinedMemory instanziiert ist. Bleibt die Referenz unkonfiguriert (Multiplicity 0), werden alle J1939-DTCs standardmäßig über den primären Fehlerspeicher des jeweiligen DemClient abgewickelt.
