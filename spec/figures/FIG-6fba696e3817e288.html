1. Diagrammtyp & Architektur-Kontext

UML-Objektdiagramm / Architektur-Deployment-Diagramm im Kontext der AUTOSAR Adaptive Platform (Software Cluster Management und Diagnostic Management). Das Diagramm illustriert ein Adressierungsszenario, in dem jedem Root-Software-Cluster bzw. Software-Cluster eine eigene Diagnoseadresse (Diagnostic Address) zugeordnet ist, einschließlich der Mehrfachverwendung identischer Data Identifiers (DIDs) über Clustergrenzen hinweg.

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm gliedert sich in vier logische Diagnose-Adressbereiche (farbige Rahmen):

  • Grüner Rahmen (Diagnostic address 0x1): Enthält das Objekt app1: Software Cluster (category = APPLICATION_LAYER, diagnosticAddress = 0x1), das über eine gerichtete Assoziation mit einem anonymen :DiagnosticContributionSet (DID 0x1234, DID 0x2314) verknüpft ist.
  • Gelber Rahmen (Shared diagnostic address 0x2): Enthält das Root-Cluster app2Root: Software Cluster (category = APPLICATION_LAYER, diagnosticAddress = 0x2), von dem gestrichelte Pfeile auf zwei Sub-Cluster ausgehen: app2Sub1: Software Cluster (category = APPLICATION_LAYER) und app2Sub2: Software Cluster (category = APPLICATION_LAYER).
  • Blauer Rahmen (Dinagnostic address 0x3 [Tippfehler im Original]): Enthält Platform Core: Software Cluster (category = PLATFORM_CORE, diagnosticAddress = 0x3), verbunden über einen gerichteten Pfeil mit :DiagnosticContributionSet (DID 0x1234).
  • Roter Rahmen (Diagnostic address 0x4): Enthält Platform: Software Cluster (category = PLATFORM, diagnosticAddress = 0x4), verbunden über einen gerichteten Pfeil mit :DiagnosticContributionSet (DID 0x1234).

Drei Textnotizen ergänzen die Struktur:

  • „Each root Software Cluster has an own diagnostic address in this example.“ (über gestrichelte Linie an den roten Rahmen gekoppelt).
  • „The same DID may be used by Software Clusters with a different diagnostic address.“ (über gestrichelte Linien an die :DiagnosticContributionSet-Objekte von app1 und Platform Core angebunden).
  • „Please note that several simplifications and omissions to the diagnostic configuration have been made for brevity.“

3. Dynamisches Verhalten & Sequenzablauf

Statisches Konfigurations- und Deklarationsmodell. Es zeigt keine zeitliche Sequenzabfolge, sondern die logische Zuordnung von Diagnosebeiträgen (DiagnosticContributionSet) und Diagnose-Identifikatoren (DIDs) zu Software-Clustern sowie die Granularität der Diagnose-Adressierung (eigenständige Diagnoseadresse pro Cluster bzw. gemeinsame Diagnoseadresse bei hierarchischer Clusterstruktur über Root-Cluster). DIDs mit gleichem Bezeichner (0x1234) können parallel in disjunkten Diagnoseadressbereichen koexistieren.

4. Normative Relevanz & Entwickler-Hinweise

Für Implementierung und Konfiguration von Diagnose-Stacks (UDS/DoIP) auf der Adaptive Platform:

  • Diagnoseadressen können auf Ebene des Root-Software-Clusters definiert und von Sub-Clustern mitgenutzt werden (Shared diagnostic address).
  • DIDs sind primär innerhalb ihres jeweiligen Diagnose-Adressraums eindeutig; derselbe DID (0x1234) darf in unterschiedlichen Software-Clustern mit separaten Diagnoseadressen unabhängig voneinander konfiguriert werden.
  • Vereinfachte illustrative Darstellung, die reale AUTOSAR-ARXML-Metamodellstrukturen abstrahiert.
