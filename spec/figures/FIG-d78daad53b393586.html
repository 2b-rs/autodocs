1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Statisches Architektur- und Adressierungsmodell / Abbildungs- und Indexierungsschema (Hardware Abstraction Layer Mapping).
  • Architektur-Kontext: Das Diagramm verortet sich im FlexRay-Kommunikationsstack der AUTOSAR Classic Platform innerhalb der Hardware-Abstraktionsschicht (Communication Hardware Abstraction). Es illustriert das standardisierte Entkopplungs- und Mappingschema des FlexRay Interface (FrIf) zur Abstraktion physischer FlexRay-Transceiver über heterogene Transceiver-Treiber (FrTrcv) hinweg bei Multi-Cluster-, Multi-Controller- und Multi-Channel-Topologien innerhalb eines Steuergeräts (ECU).

2. Komponenten, Entitäten & Schnittstellen

  • Akteure & Hierarchieebenen:
    • ECU (Electronic Control Unit): Physischer Hardwareknoten, der mehrere FlexRay-Cluster, Controller und Transceiver beherbergt.
    • FrIf (FlexRay Interface - BSW): Zentrale Abstraktionsinstanz mit zweistufiger interner Topologie:
      • Cluster-Ebene (FrIf_ClstIdx):
        • FrIf_ClstIdx = 0: Erstes logisches FlexRay-Netzwerk.
        • FrIf_ClstIdx = 1: Zweites logisches FlexRay-Netzwerk (z. B. Gateway-Szenario).
      • Controller-Ebene (FrIf_CtrlIdx):
        • FrIf_CtrlIdx = 0: Controller zugeordnet zu Cluster 0.
        • FrIf_CtrlIdx = 1 und FrIf_CtrlIdx = 2: Zwei separate Controller zugeordnet zu Cluster 1 (Redundanz- oder Routing-Architektur).
      • Kanal-Ebene (FrIf_ChnlIdx):
        • Jeder Controller besitzt logische Anschlüsse für FR_CHANNEL_A und FR_CHANNEL_B.
    • Transceiver-Treiber & Hardware (FrTrcv):
      • Treiber-Instanz FrTrcv#0 (Hardware Type A):
        • FrTrcv_TrcvIdx = 0: Anbindung an FR_CHANNEL_A von Cluster 0.
        • FrTrcv_TrcvIdx = 1: Anbindung an FR_CHANNEL_B von Cluster 1.
      • Treiber-Instanz FrTrcv#1 (Hardware Type B):
        • FrTrcv_TrcvIdx = 0: Anbindung an FR_CHANNEL_A von Cluster 1.
        • FrTrcv_TrcvIdx = 1: Anbindung an FR_CHANNEL_B von Cluster 1.
    • Physische Busleitungen:
      • FR_CHANNEL_A (Cluster 0)
      • FR_CHANNEL_A (Cluster 1)
      • FR_CHANNEL_B (Cluster 1)
  • Beziehungen & Kardinalitäten:
    • 1 ECU : N Cluster (FrIf_ClstIdx) – Multi-Cluster-Fähigkeit.
    • 1 Cluster : 1..N Controller (FrIf_CtrlIdx) – Ein Cluster kann mehrere Controller binden (hier: Cluster 1 bindet Controller 1 und 2).
    • 1 Controller : 1..2 Kanäle (FrIf_ChnlIdx) – Maximal zwei physische Kanäle (A und B) pro FlexRay-Controller.
    • M Treiber-Instanzen (FrTrcv#0, FrTrcv#1) : K Transceiver-Kanäle (FrTrcv_TrcvIdx): Unterschiedliche Transceiver-Typen (Type A, Type B) können im selben System koexistieren. Die treiberlokale Indexierung FrTrcv_TrcvIdx beginnt pro Treibermodul jeweils bei 0. Das FrIf linearisiert und routet diese Indizes transparent für obere Schichten.

3. Dynamisches Verhalten & Sequenzablauf

Obgleich es sich um ein statisches Indexierungsdiagramm handelt, determiniert es die Laufzeitpfade bei Steuerungs- und Diagnoseoperationen:

  • Transceiver-Moduswechsel (z. B. FrIf_SetTransceiverMode):
    1. Aufruf durch den FlexRay State Manager (FrSM) oder BswM mit dem vereinheitlichten FrIf-Transceiver-Index (FrIf_TrcvIdx).
    2. Das FrIf schlägt in seiner Konfigurations-Routing-Tabelle nach:
      • Welcher Treiber ist adressiert (FrTrcv#0 [Type A] oder FrTrcv#1 [Type B])?
      • Welcher treiberinterne Index FrTrcv_TrcvIdx korrespondiert mit dem Kanal?
    3. Synchroner Durchstich zur jeweiligen Treiber-API: FrTrcv_<Vendor>_SetTransceiverMode(FrTrcv_TrcvIdx, ...) über Funktionszeiger oder Dispatcher.
    4. Rückmeldung des API-Status (E_OK / E_NOT_OK).
  • Wakeup- und Diagnoseabfragen (FrIf_GetTransceiverWUReason, FrIf_GetTransceiverMode):
    • Synchrone Abfrage über das analoge Index-Lookup.
  • Fehlerbehandlung:
    • Wird ein Index übergeben, für den kein Mapping existiert, detektiert FrIf dies synchron und meldet FRIF_E_INV_TRCVIDX an das Default Error Tracer (Det_ReportError).

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Anforderungen:
    • SWS_FrIf_05107: Das FlexRay Interface muss die Transceiver-Indizes der oberen Schichten (FrIf_TrcvIdx bzw. Zuordnung über Controller/Channel) deterministisch auf die spezifische Transceiver-Treiberinstanz und deren lokalen Kanalindex (FrTrcv_TrcvIdx) abbilden.
    • SRS_BSW_00162: Gewährleistung der Mehrkanal- und Mehrinstanzfähigkeit (Multiple instances of Basic Software basic drivers) für unterschiedliche Hardware-Derivate auf einer ECU.
  • Konfigurationsanforderungen (ARXML / BSW-Konfigurator):
    • Trennung im BSW-Datenmodell: FrIfCluster → FrIfController → FrIfTransceiver.
    • Jeder FrIfTransceiver-Container referenziert genau ein FrTrcvChannel-Element im entsprechenden FrTrcv-Treibermodul (FrTrcvChannelId).
  • Entwickler- & Integrationshinweise:
    • Heterogene Transceiver: Werden Transceiver verschiedener Hersteller oder Typen (z. B. diskret via GPIO angesteuerte vs. SPI-basierte Transceiver wie Type A und Type B) gemischt, müssen die Treiberschnittstellen im FrIf via Vendor-spezifischem API-Infixing oder Funktionszeigertabellen konfiguriert werden (FrIfUserHeaderFile / Multiple Driver Support).
    • Reentrancy & Entkopplung: Transceiver-Treiber müssen für unterschiedliche Werte von FrTrcv_TrcvIdx reentrant ausgelegt sein.
    • Abstraktion für FrSM: Der FrSM arbeitet ausschließlich mit abstrakten Netzwerk- und Cluster-IDs; er besitzt keine Kenntnis über Treiber-Aufteilungen (Type A vs. Type B) oder hardwarelokale FrTrcv_TrcvIdx-Werte.
