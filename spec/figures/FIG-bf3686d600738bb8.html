1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm (sm GenericNmAlgorithm), das den generischen Netzwerkmanagement-Zustandsautomaten für CAN (CNm / CanNm) innerhalb der AUTOSAR-Basissoftware (Classic Platform) spezifiziert. Das Diagramm ordnet sich in den Kommunikations-Stack ein und steuert über standardisierte Zustände und Betriebsmodi die Busaktivität, das Senden und Empfangen von NM-Botschaften sowie das geordnete Einschlafen und Aufwecken des Kommunikationsbusses in Koordination mit dem generischen NM-Interface (Nm).

2. Komponenten, Entitäten & Schnittstellen

Hauptkomponenten und Betriebsmodi:

  • Modi und Zustände:
  • Bus-Sleep Mode: Ruhezustand des Busses nach Initialisierung oder Ablauf des Timers.
  • Prepare Bus-Sleep Mode: Übergangszustand zur Vorbereitung des Bus-Ruhezustands.
  • Network Mode (Hierarchischer Zustand/Komposit-Zustand):
  • Repeat Message State: Initialer Zustand im Network Mode, in dem NM-Nachrichten wiederholt übertragen werden.
  • Normal Operation State: Zustand bei aktiver Netzwerkanforderung durch die Anwendung.
  • Ready Sleep State: Zustand bei freigegebenem Netzwerk, in dem auf das Einschlafen gewartet wird.
  • Pseudozustände:
  • Start-Pseudozustand PowerOff mit Initialisierungstransition.
  • Join-/Junction-Pseudozustand Network Mode für den Eintritt in den Netzwerkmodus.
  • Choice-/Junction-Pseudozustand Repeat Message zur Verzweigung nach Ablauf des Repeat Message Timers.
  • Schnittstellen und Service-Aufrufe:
  • Eingehende Aufrufe / Events: CNm_Init(), Nm_PassiveStartUp(), CNm_NetworkRequest(), CNm_NetworkRelease(), CNm_RxIndication(), CNm_TxConfirmation(), CNm_RepeatMessageRequest(), CNm_RepeatMessageBitIndication().
  • Ausgehende Aufrufe und Benachrichtigungen: Nm_NetworkMode(), Nm_NetworkStartIndication(), Nm_PrepareBusSleepMode(), Nm_BusSleepMode(), Nm_NetworkTimeoutException(), CanNm_StartTransmission(), CanNm_StopTransmission(), CanNm_TriggerTransmission(), CanNm_StartBusLoadReduction(), CanNm_StopBusLoadReduction().
  • Timer:
  • NM-Timeout Timer: Überwachung der Busaktivität bzw. des Ausbleibens von NM-Nachrichten.
  • Repeat Message Timer: Zeitdauer für den Verbleib im Repeat Message State.
  • Wait Bus-Sleep Timer: Wartezeit im Prepare Bus-Sleep Mode vor dem Übergang in den Bus-Sleep Mode.

3. Dynamisches Verhalten & Sequenzablauf

Dynamische Abläufe und Zustandsübergänge:

  • Initialisierung & Aufwecken:
  • Aus PowerOff führt CNm_Init() in den Bus-Sleep Mode.
  • Aus Bus-Sleep Mode führen Nm_PassiveStartUp() oder CNm_NetworkRequest() über den Pseudozustand Network Mode in den Repeat Message State. Aktionen: Start von NM-Timeout Timer und Repeat Message Timer, Aufruf von Nm_NetworkMode() und CanNm_StartTransmission() (bzw. zusätzlich CanNm_TriggerTransmission() bei explizitem Request).
  • Ein CNm_RxIndication() im Bus-Sleep Mode ruft Nm_NetworkStartIndication() auf.
  • Ablauf im Network Mode:
  • Bei Eintritt in den Repeat Message State läuft der Repeat Message Timer. Nach dessen Ablauf (Repeat Message Timer has expired;) verzweigt der Pseudozustand Repeat Message über die Guards [Network Requested] in den Normal Operation State (mit CanNm_StartBusLoadReduction()) oder [Network Released] in den Ready Sleep State (mit CanNm_StopTransmission()).
  • Im Normal Operation State schaltet CNm_NetworkRelease() in den Ready Sleep State (CanNm_StopTransmission(), CanNm_StopBusLoadReduction()).
  • Im Ready Sleep State schaltet CNm_NetworkRequest() zurück in den Normal Operation State (CanNm_StartBusLoadReduction(), CanNm_StartTransmission()).
  • Aus Normal Operation State und Ready Sleep State führt CNm_RepeatMessageBitIndication() oder CNm_RepeatMessageRequest() zurück in den Repeat Message State (Start Repeat Message Timer, CanNm_StartTransmission(), im Fall von Normal Operation zusätzlich CanNm_StopBusLoadReduction()).
  • Lokale Transitionen bei CNm_RxIndication() und CNm_TxConfirmation() setzen in allen drei Zuständen des Network Mode den NM-Timeout Timer zurück.
  • Läuft der NM-Timeout Timer im Repeat Message State oder Normal Operation State ab, wird er neu gestartet und Nm_NetworkTimeoutException() ausgelöst.
  • Übergang in den Bus-Sleep Mode:
  • Läuft im Ready Sleep State der NM-Timeout Timer ab, wechselt der Automat in den Prepare Bus-Sleep Mode (Start Wait Bus-Sleep Timer, Aufruf Nm_PrepareBusSleepMode()).
  • Aus Prepare Bus-Sleep Mode führt CNm_NetworkRequest() direkt zurück in den Repeat Message State (Start beider Timer, Aufruf von Nm_NetworkMode(), CanNm_TriggerTransmission(), CanNm_StartTransmission()).
  • CNm_RxIndication() im Prepare Bus-Sleep Mode führt ebenfalls über den Eintrittsknoten in den Repeat Message State.
  • Läuft der Wait Bus-Sleep Timer im Prepare Bus-Sleep Mode ab (Wait Bus-Sleep Timer has expired), wechselt der Automat in den Bus-Sleep Mode und benachrichtigt über Nm_BusSleepMode().

4. Normative Relevanz & Entwickler-Hinweise

Entwickler- und Integrationshinweise:

  • Timer-Management: Die drei zentralen Timer (NM-Timeout Timer, Repeat Message Timer, Wait Bus-Sleep Timer) müssen deterministisch konfiguriert und bedient werden. Das Zurücksetzen des NM-Timeout-Timers erfolgt sowohl auf Sende- als auch auf Empfangsbestätigungen (TxConfirmation, RxIndication).
  • Buslastreduktion (Bus Load Reduction): Beim Verlassen des Repeat Message State in den Normal Operation State wird die Buslastreduktion aktiviert (CanNm_StartBusLoadReduction()). Bei Rückkehr in den Repeat Message State oder Wechsel in den Ready Sleep State muss sie explizit gestoppt werden (CanNm_StopBusLoadReduction()).
  • Exception-Handling: Ein Timeout im aktiven Zustand (Repeat Message State oder Normal Operation State) signalisiert einen Kommunikationsausfall auf dem Bus und löst eine Ausnahmebehandlung über Nm_NetworkTimeoutException() aus, führt aber nicht zum Verlassen des Network Mode.
  • Einschlafsequenz: Ein geordnetes Herunterfahren ist nur über den Ready Sleep State und die anschließende Karenzzeit im Prepare Bus-Sleep Mode möglich, um transiente Wakeup-Ereignisse und asynchrone Botschaften vor dem physischen Bus-Sleep sauber abzufangen.
