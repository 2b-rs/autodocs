1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-Klassendiagramm / Metamodell-Ausschnitt (M2-Ebene der AUTOSAR System Template, AUTOSAR_CP_TPS_SystemTemplate).
  • Funktionale Einordnung: Systembeschreibungsmodell für das generische (Nm) und busspezifische CAN-Netzwerkmanagement (CanNm). Es definiert das Konfigurationsschema (NmConfig) zur topologischen Verknüpfung von Kommunikationsclustern, Steuergeräten (ECUs), logischen Netzwerkknoten (Nodes), PDU-Payload-Strukturen und Multi-Bus-Koordinationsmechanismen im ARXML-Format vor der ECUC-Extraktion.

2. Komponenten, Entitäten & Schnittstellen

#### Zentrale Verwaltung & Koordination

  • NmConfig («FibexElement», «UploadableDesignElement»): Wurzel-Container für die netzwerkweite NM-Konfiguration.
  • Aggregiert per Komposition («atpVariation, atpSplitable»):
  • +nmCluster [0..*] $\rightarrow$ NmCluster
  • +nmClusterCoupling [0..*] $\rightarrow$ NmClusterCoupling
  • +nmIfEcu [0..*] $\rightarrow$ NmEcu
  • NmClusterCoupling / CanNmClusterCoupling:
  • CanNmClusterCoupling spezialisiert NmClusterCoupling (Attribute: nmBusloadReductionEnabled, nmImmediateRestartEnabled).
  • Assoziiert +coupledCluster [*] $\rightarrow$ NmCluster.
  • Aggregiert +nmCoordinator [0..1] $\rightarrow$ NmCoordinator (index, nmCoordSyncSupport, nmGlobalCoordinatorTime), welcher über +nmNode [0..*] auf die beteiligten NmNode-Instanzen referenziert (Cluster-übergreifendes synchrones Herunterfahren).

#### Cluster-Ebene

  • NmCluster («Identifiable»): Abstrakte Basis für ein NM-Segment.
  • Attribute: nmChannelSleepMaster, nmLightTimeout, nmNodeDetectionEnabled, nmNodeIdEnabled, nmPncParticipation, nmRepeatMsgIndEnabled, nmSynchronizingNetwork, pncClusterVectorLength.
  • Assoziation: +communicationCluster [0..1] $\rightarrow$ CommunicationCluster («FibexElement», «UploadableDesignElement», «atpVariation»; Attribute: baudrate, protocolName, protocolVersion).
  • Aggregation («atpVariation, atpSplitable»): +nmNode [0..*] $\rightarrow$ NmNode.
  • CanNmCluster (erbt von NmCluster): CAN-spezifische Parametrisierung des NM-Stacks.
  • Timing- & Protokoll-Parameter: nmNetworkTimeout, nmMsgCycleTime, nmWaitBusSleepTime, nmRepeatMessageTime, nmMessageTimeoutTime, nmRemoteSleepIndicationTime, nmImmediateNmCycleTime, nmImmediateNmTransmissions.
  • PDU-Layout & Filterung: nmNidPosition (Node-ID-Byte), nmCbvPosition (Control Bit Vector), nmCarWakeUpBitPosition, nmCarWakeUpFilterNodeId, nmBusloadReductionActive.

#### ECU- und Knoten-Ebene

  • NmEcu («Identifiable»): ECU-spezifische NM-Schnittstellenkonfiguration.
  • Attribute: nmBusSynchronizationEnabled, nmComControlEnabled, nmCycletimeMainFunction, nmPduRxIndicationEnabled, nmRemoteSleepIndEnabled, nmStateChangeIndEnabled, nmUserDataEnabled.
  • Aggregiert +busDependentNmEcu [0..] $\rightarrow$ BusspecificNmEcu* (abstrakt; Basis für CanNmEcu).
  • NmNode («Identifiable»): Repräsentiert die logische NM-Teilnahme einer ECU auf einem Kanal.
  • Attribute: nmNodeId, nmVariant, nmPassiveModeEnabled, nmCoordinatorRole, nmCoordCluster.
  • Assoziation: +nmIfEcu [0..1] $\rightarrow$ NmEcu.
  • Aggregiert: +txNmPdu [0..] und +rxNmPdu [0..] $\rightarrow$ NmPdu.
  • CanNmNode (erbt von NmNode): CAN-spezifische Knotenausprägung.
  • Attribute: allNmMessagesKeepAwake, nmCarWakeUpFilterEnabled, nmCarWakeUpRxEnabled, nmMsgCycleOffset, nmMsgReducedTime.

#### PDU- & Signal-Mapping

  • NmPdu (erbt von Pdu):
  • Attribute: nmDataInformation, nmVoteInformation, unusedBitPattern.
  • Aggregiert +iSignalToIPduMapping [0..*] $\rightarrow$ ISignalToIPduMapping («Identifiable»; Attribute: packingByteOrder, startPosition, transferProperty, updateIndicationBitPosition) für die Übertragung von Partial-Networking-Vektoren (PNC) und anwendungsspezifischen User-Data-Bytes.

3. Dynamisches Verhalten & Parametereinfluss auf die State Machine

Obwohl rein deklarativ modelliert, steuern die Parameter direkt die deterministischen Zustandsübergänge des CanNm-Zustandsautomaten:

```

[Bus-Sleep Mode]

│ Wakeup / Network Request

▼

[Repeat Message State] <────────┐ (nmRepeatMessageTime)

│ │

├─► (Immediate Transmissions: nmImmediateNmTransmissions * nmImmediateNmCycleTime)

│ │

▼ │ Rx NM-PDU / Request

[Normal Operation State] ───────┤ (Zyklus: nmMsgCycleTime; Timeout: nmNetworkTimeout)

│ │

▼ Release Network │

[Ready Sleep State] ────────────┘

│ nmNetworkTimeout abgelaufen

▼

[Prepare Bus-Sleep Mode] (Dauer: nmWaitBusSleepTime)

│ Timer abgelaufen

▼

[Bus-Sleep Mode]

```

  • Burst-Senden: Bei Netzwerkstart erzwingen nmImmediateNmTransmissions und nmImmediateNmCycleTime ein schnelles Aufwecken des Clusters.
  • Offsets & Lastreduktion: nmMsgCycleOffset verhindert Übertragungskollisionen synchron startender Knoten; nmBusloadReductionActive i. V. m. nmMsgReducedTime drosselt die Senderate im passiven Zustand.
  • Überwachung: nmNetworkTimeout triggert bei Ausbleifen fremder NM-Botschaften den Übergang von Normal Operation nach Ready Sleep.

4. Normative Relevanz & Entwickler-Hinweise

  • BSW-Generierungskette: Das Modell bildet die Eingabeebene (System Extract / SysEx). Ein AUTOSAR-Konfigurator transformiert diese Instanzen 1:1 in die ECUC-Parameter der Module Nm (SWS Network Management Interface) und CanNm (SWS CAN Network Management).
  • PDU-Layout-Restriktionen: nmNidPosition und nmCbvPosition müssen clusterweit strikt konsistent projektiert werden (typisch: Byte 0 für Node-ID, Byte 1 für CBV oder Offset-Verschiebung). Kollisionen mit ISignalToIPduMapping.startPosition (User Data) führen zu Datenkorruption im Payload.
  • Partial Networking (PnC): nmPncParticipation = TRUE erzwingt die Auswertung des Bitvektors der Länge pncClusterVectorLength. Das zugehörige Signal-Mapping muss im Payload exakt auf den PNC-Filterbereich der ComM/CanNm-Module abgestimmt sein.
  • Multi-Core / Task-Scheduling: nmCycletimeMainFunction aus NmEcu bindet die Ausführungsperiode von CanNm_MainFunction() und Nm_MainFunction() im BswM/Os-Task-Plan; die Werte müssen Teiler aller konfigurierten NM-Timer (nmMsgCycleTime, nmNetworkTimeout) sein.
