1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Konzeptionelles Datenfluss- und Prozess-/Toolketten-Architekturdiagramm (Tool Interaction Diagram) im Kontext der AUTOSAR-Methodik (Methodology and Templates).
  • Technischer Zweck & Einordnung:
    • Veranschaulicht den Absicherungsprozess beim Datenaustausch über Modellgrenzen hinweg gemäß AUTOSAR_FO_TPS_StandardizationTemplate.
    • Adressiert die formale Validierung von ARXML-Lieferungen an definierten Schnittstellen (Data Exchange Points) zwischen Werkzeugen unterschiedlicher Domänen, Rollen oder Organisationen (z. B. OEM-zu-Tier-1, System-Authoring zu ECU-Extrakt/BSW-Konfiguration).
    • Ergänzt die reine XML-Schema-Validierung (XSD) um semantische und rollenspezifische Metamodell-Einschränkungen mittels eines formalen Austauschprofils (Profile for Data Exchange Point).

2. Komponenten, Entitäten & Schnittstellen

  • Producing Tool:
    • Quellwerkzeug der Toolkette (z. B. System-Authoring-Tool, Architecture-Tool, Software-Component-Editor).
    • Exportiert ARXML-Modellartefakte über eine dedizierte Exportschnittstelle (symbolisiert als Output-Port).
  • Consuming Tool:
    • Nachgelagertes Empfängerwerkzeug (z. B. ECU-Extract-Creator, RTE-Generator, BSW-Konfigurator).
    • Importiert ARXML-Modellartefakte über eine dedizierte Importschnittstelle (symbolisiert als Input-Port).
  • .ARXML (AUTOSAR Model):
    • Das eigentliche Datenaustausch-Artefakt (XML-basierte Instanz des AUTOSAR-Metamodells).
    • Kann vollständige Systembeschreibungen, ECU-Extrakte oder Software-Component-Descriptions (auch in Split-Dateien via «atpSplitable») kapseln.
  • Profile for Data Exchange Point (Checklisten-Symbol):
    • Normativer Regelsatz gemäß TPS_STDT_00118 / TPS_STDT_00120.
    • Definiert projektspezifische Einschränkungen (Subsets, Pflichtattribute, erlaubte Stereotypen, Kardinalitäten, Konsistenzkriterien) für genau diesen Übergabepunkt.
  • Validation Engine & Akteur:
    • Symbolisiert durch Getrieberäder und User-Icon: Ausführungseinheit (automatisiertes Tooling oder interaktiver Prüfschritt) zur Verifikation der Konformität (Validate Compliance of AUTOSAR Model against Profile for Data Exchange Point).

3. Dynamisches Verhalten & Sequenzablauf

  1. Modellerzeugung & Export:
    • Das Producing Tool serialisiert das interne Datenmodell in standardkonforme .ARXML-Dateien.
  2. Entkopplung & Injektion des Austauschprofils:
    • Die generierten .ARXML-Dateien werden nicht direkt ungeprüft an das Consuming Tool übergeben, sondern an den Prüfpfad verzweigt.
    • Das für den Austauschpunkt verbindliche Profile for Data Exchange Point wird geladen.
  3. Konformitätsvalidierung (Compliance Check):
    • Prüfschritte:
      1. Syntaktische Validierung gegen das AUTOSAR XML Schema (Release-spezifisch).
      2. Semantische Validierung gegen Metamodell-Constraints und OCL-Regeln.
      3. Profil-Validierung: Prüfung auf Vorhandensein aller für das Consuming Tool zwingend erforderlichen Elemente (z. B. vollständige Signal-zu-PDU-Mappings, Typdefinitionen, PortInterfaces).
  4. Entscheidungsgate & Freigabe:
    • Pass: Modell erfüllt alle Kriterien des Profils → Freigabe für den Import ins Consuming Tool.
    • Fail: Validierungsfehler generieren einen Fehlerbericht → Rückweisung an das Producing Tool (Vermeidung von Folgefehlern im nachgelagerten Tooling).

4. Normative Relevanz & Entwickler-Hinweise

  • Vertragssicherheit (SLA / Contract Phase):
    • Relevanz gemäß RS_STDT_00101, RS_STDT_00121, TPS_STDT_00118 und TPS_STDT_00120: Das Profil fungiert als maschinenlesbarer Vertrag zwischen Lieferant (Produzent) und Integrator (Konsument).
  • BSW- und RTE-Entwickler / Integratoren:
    • Fail-Early-Prinzip: Verhindert inkonsistente Zwischenzustände vor dem Start von RTE- oder BSW-Generatoren. Unvollständige Beschreibungen (z. B. fehlende ComPuMethods, unvollständige DataMappings, fehlerhafte SwBaseType-Zuordnungen) werden vor der Konfigurationsphase abgefangen.
    • Toolchain-Stabilität: Schützt das Consuming Tool vor Parser-Crashes oder unklaren Fehlermeldungen bei proprietären oder fehlerhaften Modellausprägungen aus Drittwerkzeugen.
  • Release- und Variantenmanagement:
    • Das Profil stellt sicher, dass an Schnittstellen nur die für das Ziel-Release (z. B. Classic R20-11 / Adaptive R20-11) zulässigen Metamodell-Elemente verwendet werden, insbesondere beim Einsatz werkzeugübergreifender Konverter.
