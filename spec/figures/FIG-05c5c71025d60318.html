1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm (AUTOSAR M2-Metamodell / System Template).
  • Technischer Zweck: Definition der Metamodell-Struktur für Partial Networking (PN). Es beschreibt die formale Abbildung virtueller Funktionscluster (VFC, repräsentiert über PortGroup) auf logische Teilnetzwerk-Cluster (PncMapping / PNC) sowie deren Verknüpfung mit Kommunikations-Ressourcen (IPduGroup, FrameTriggering) und hardwarenahen Filter-/Wake-Up-Parametern (CanCommunicationConnector).
  • Funktionale Einordnung: Bildet die Entwurfsbasis im System-Design (System Description / SystemMapping), aus der im EcuExtract die nachgelagerte Konfiguration für BSW-Module wie ComM, CanNm, Com und CanTrcv abgeleitet wird.

2. Komponenten, Entitäten & Schnittstellen

Metaklassen & Stereotypen
  • SystemMapping (Generalisierung von Identifiable):
    • Wurzelelement für systemweite Mappings.
    • Aggregiert per Komposition (+pncMapping *) Instanzen von PncMapping unter Stereotyp «atpVariation» mit Tag vh.latestBindingTime = systemDesignTime.
  • PncMapping (Generalisierung von Describable):
    • Zentrales Mapping-Element eines Teilnetzwerk-Clusters.
    • Attribute:
      • + pncIdentifier : PositiveInteger
      • + shortLabel : Identifier [0..1]
    • Referenziert 0..* PortGroup über die Rolle +vfc mit dem Stereotyp «instanceRef».
    • Assoziiert 0..* ISignalIPduGroup über die gerichtete Relation +pncGroup.
    • Assoziiert 0..* FrameTriggering über die Relation +wakeupFrame.
  • PortGroup (Generalisierung von Identifiable, Stereotyp AtpStructureElement):
    • Repräsentiert funktionale Ports eines Software-Components bzw. eines Virtual Function Clusters (VFC).
    • Rekursive Selbst-Assoziation: +innerGroup 0..* mit «instanceRef».
  • ISignalIPduGroup (Generalisierung von FibexElement):
    • Bündelt Signal-I-PDUs zur gemeinsamen Laufzeitsteuerung.
    • Attribute:
      • + communicationDirection : CommunicationDirectionType
      • + communicationMode : String
    • Rekursive Selbst-Aggregation: +containedISignalIPduGroup 0..*.
  • EcuInstance (Generalisierung von FibexElement):
    • Repräsentiert ein Steuergerät im System.
    • Assoziation: Referenziert * ISignalIPduGroup über +associatedComIPduGroup.
    • Attribute:
      • + comConfigurationGwTimeBase : TimeValue [0..1]
      • + comConfigurationRxTimeBase : TimeValue [0..1]
      • + comConfigurationTxTimeBase : TimeValue [0..1]
      • + comEnableMDTForCyclicTransmission : Boolean [0..1]
      • + diagnosticAddress : Integer [0..1]
      • + pncPrepareSleepTimer : TimeValue [0..1]
      • + pnResetTime : TimeValue [0..1]
      • + sleepModeSupported : Boolean
      • + wakeUpOverBusSupported : Boolean
  • CanCommunicationConnector (Generalisierung von AbstractCanCommunicationConnector):
    • Definiert CAN-spezifische physikalische Anbindungsparameter für Partial Networking Wake-up Frames:
      • + pncWakeupCanId : PositiveInteger [0..1]
      • + pncWakeupCanIdExtended : Boolean [0..1]
      • + pncWakeupCanIdMask : PositiveInteger [0..1]
      • + pncWakeupDataMask : PositiveUnlimitedInteger [0..1]
      • + pncWakeupDlc : PositiveInteger [0..1]

3. Dynamisches Verhalten & Sequenzablauf

Obwohl das Diagramm statische ARXML-Metaklassen darstellt, induziert es folgendes dynamisches BSW-Verhalten:

  1. PNC-Anforderung (Applikationsebene): SWC-Instanzen fordern über Ports ihrer PortGroup funktionale Kommunikation an.
  2. Cluster-Auswertung (ComM / CanNm): Der ComM mappt den PortGroup-Request auf die entsprechende PncMapping-Instanz (pncIdentifier). Im Netzwerkmanagement (CanNm) wird das entsprechende Bit im User-Data-Bereich der NM-PDU (PNI-Bit gesetzt, ERA/IRA-Filterung) gesetzt bzw. ausgewertet.
  3. PDU-Gruppen-Freigabe (Com): Bei aktivem PNC schaltet ComM via Com_IpduGroupStart() die verknüpften +pncGroup-Instanzen (IPduGroup) frei; bei Inaktivität erfolgt Com_IpduGroupStop().
  4. Selektiver Hardware-Wakeup (Bus-Ebene): Im Standby/Sleep wertet der autonome CAN-Transceiver (z. B. TJA1145) eingehende Frames anhand der via CanCommunicationConnector hinterlegten Parameter (pncWakeupCanId, pncWakeupDataMask) aus. Erst bei Bit-Match auf dem Teilnetzwerk erfolgt ein Interrupt/Wakeup an den Host-Mikrocontroller.

4. Normative Relevanz & Entwickler-Hinweise

  • ARXML-Instanzpfade («instanceRef»): Die Verknüpfung PncMapping.vfc -> PortGroup erfordert vollständige Kontextpfade über die Root-Composition und SwComponentPrototypes. Fehlerhafte Instanzreferenzen führen zu unvollständigen Signal-to-PNC-Zuordnungen im System-Extractor.
  • Signal-Packing & PDU-Zuweisung: Signale einer PortGroup müssen disjunkt auf PDUs gelegt werden, die ausschließlich zu den für diesen pncIdentifier konfigurierten IPduGroups gehören. Ein PDU-Sharing über inkompatible PNCs führt zu parasitären Weckvorgängen (False Wake-ups).
  • BSW-Konfigurationsableitung:
    • pncIdentifier steuert direkt die BSW-Parameter CanNmPnFilterMaskByte und Bitmasken im Modul CanNm.
    • CanCommunicationConnector-Felder fließen direkt in den SPI-/I²C-Initialisierungsstring für den externen CAN-Transceiver-Treiber (CanTrcv).
    • EcuInstance.associatedIPduGroup begrenzt den Scope der lokalen Signalverarbeitung im generierten Com-Stack.
