1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Protokoll-Bit-/Byte-Layout (On-Wire-Serialisierungsformat / TLV-Tag-Layout).
  • Architektur-Kontext:
    • Verortung im SOME/IP Transformer (SomeIpXf) innerhalb der AUTOSAR-Basissoftware (BSW, gemäß SWS_SomeIpXf_00267 ff.).
    • Dient der Type-Length-Value-Serialisierung (TLV) für strukturierte Datentypen (Struct).
    • Ermöglicht Vorwärts- und Rückwärtskompatibilität, Versionierung von Schnittstellen sowie das Auslassen optionaler Struktur-Elemente (optional members) im SOME/IP-Payload über Ethernet.

3. Dynamisches Verhalten & Sequenzablauf

Serialisierung (Sender-Pfad via SomeIpXf_<TransformerId>):
  1. Prüfung: Ermitteln, ob das Strukturelement belegt ist (bei optional deklarierten Members; Auswertung der Availability-Flags/Bitmasken).
  2. Tag-Generierung:
    • Maskierung der konfigurierten Data ID in High-Part ((DataID >> 8) & 0x0F) und Low-Part (DataID & 0xFF).
    • Bitweises Verodern des Wire Types in Bits 6–4 von Byte n.
  3. Längenfeld-Einschub: Bei dynamischen oder komplexen Typen (Wire Type 4–6) wird die Bytegröße der serialisierten Payload berechnet und als 8-, 16- oder 32-Bit-Integer eingefügt (Byte-Order gemäß Konfiguration, typisch Big-Endian/Network-Byte-Order).
  4. Payload-Kopie: Serialisierung der Member Data an den PDU-Buffer.
Deserialisierung (Empfänger-Pfad):
  1. Tag-Evaluation: Einlesen von 2 Bytes (Byte n, Byte n+1).
  2. Mapping: Extraktion der Data ID. Abgleich mit dem lokalen Datenmodell.
  3. Skipping unbekannter Members (Forward Compatibility):
    • Unbekannte Data ID: Der Parser liest den Wire Type.
    • Bei Basisdatentypen (0–3) überspringt der Empfänger 1, 2, 4 oder 8 Byte.
    • Bei Wire Type 4–6 liest der Empfänger das Längenfeld aus und überspringt die angegebene Byteanzahl (Skip = LengthFieldSize + LengthValue).
  4. Fehlerbehandlung:
    • Unerwarteter Wire Type oder PDU-Längenunterschreitung führt zu Serialisierungsfehlern (E_SER_MALFORMED_MESSAGE) und optionalem Report an Det / Dem.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationspflicht in ARXML: Jedes Struct-Member in einer TLV-kodierten Struktur benötigt zwingend ein eindeutiges dataId-Attribut (0–4095). Fehlende Data-IDs verhindern die Codegenerierung des SOME/IP-Transformers.
  • Wire-Format-Overhead: Gegenüber klassischer positionsbasierter Serialisierung ohne Tags entsteht pro Member ein Mindest-Overhead von 2 Byte (Tag) bzw. 3 bis 6 Byte (bei komplexen Typen inklusive Längenfeld). Kritisch für Buslast und PDU-Größenbegrenzung im Low-Memory-Bereich.
  • Bit-Ordering & Endianness:
    • Die Tag-Struktur selbst folgt fest der im Diagramm definierten Bit-Zuordnung (Bit 7 = MSB, Bit 0 = LSB im jeweiligen Byte).
    • Das Bit-Shifting für die Data-ID (Byte n: bits 3-0 + Byte n+1: bits 7-0) muss plattformunabhängig über Bitmasken implementiert werden, um Inkompatibilitäten zwischen Little-Endian (z. B. ARM Cortex-M/R/A, x86) und Big-Endian Architekturen zu verhindern.
  • Pufferallokation: Der RTE-/BSW-Puffer für die transformierte PDU muss den Maximalfall (alle optionalen Member gesetzt inkl. Tags und Längenfeldern) abbilden können (bufferSize >= sum(Tag + LengthField + MemberPayload)).

Begleitender Spezifikationstext:

Specification of SOME/IP Transformer AUTOSAR CP R23-11 Structs are modeled in the Software Component Template using an ImplementationDataType of category STRUCTURE and members are represented by ImplementationDataTypeElements. Method arguments are represented by Argument- DataPrototypes. Refer to [9] for more details. The assignment of Data IDs is modeled in the System Template in the context of SOMEIPTransformationISignalProps. Refer to [7] for more details. Moreover, the usage of Data IDs allows describing structs with optional members. To serialize data with optional members, the transformer has to know which optional members are available or not. This is stored in a bitfield which is contained inside the ImplementationDataType. This availabilityBitfield is realized as array of uint8. Whether an optional member is actually present in the struct or not, must be determined during runtime. In addition to the Data ID, a wire type encodes the datatype of the following member. Data ID and wire type are encoded in a so-called tag.
