1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur AUTOSAR Adaptive Platform (AP), Dokument AUTOSAR_AP_EXP_SWArchitecture. Das Diagramm modelliert das Beispielszenario „Store Persistent Data in File“ (Persistierung von Anwendungsdaten in dateibasierten Speichern) und zeigt die Interaktionen zwischen Anwendungsebene, AUTOSAR Adaptive Functional Clustern und dem zugrunde liegenden Betriebssystem.

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Lebenslinien:

  • :Adaptive Application (Akteur/Anwendungsprozess)
  • «aapFunctionalCluster» :Persistency (Funktionales Cluster der Adaptive Platform)
  • :Operating System (Akteur/Betriebssystemebene)
  • «aapFunctionalCluster» :Cryptography (Funktionales Cluster der Adaptive Platform)

Schnittstellen und Operationen:

  • :Adaptive Application an :Persistency:
  • OpenFileStorage(): FileStorage
  • OpenFileWriteOnly(): ReadWriteAccessor
  • WriteText()
  • :Persistency an :Operating System:
  • open() mit Stereotyp «aapInformative»
  • write() mit Stereotyp «aapInformative»
  • :Persistency an :Cryptography:
  • ProcessBlock()
  • Referenzierte Interaktionen:
  • ref Initialize Cipher
  • ref Store Redundant Data

3. Dynamisches Verhalten & Sequenzablauf

  1. Die :Adaptive Application fordert über OpenFileStorage() Zugriff auf einen dateibasierten Speicher an; :Persistency liefert ein Handle vom Typ FileStorage zurück.
  2. Anschließend öffnet die :Adaptive Application eine Datei im Schreibmodus mittels OpenFileWriteOnly(), worauf :Persistency einen ReadWriteAccessor bereitstellt.
  3. Zur Vorbereitung der Dateierstellung bzw. -öffnung setzt :Persistency den informativen Aufruf open() («aapInformative») an das :Operating System ab.
  4. Bedingter Block alt [KeySlotMapping exists in Manifest and keySlotUsage = encryption]: Ist im Manifest ein KeySlot-Mapping für Verschlüsselung konfiguriert, wird die Interaktionsreferenz ref Initialize Cipher ausgeführt, an der :Persistency, :Operating System und :Cryptography beteiligt sind.
  5. Die :Adaptive Application schreibt Textdaten mittels WriteText() in den geöffneten Datei-Accessor.
  6. Bedingter Block alt [KeySlotMapping exists in Manifest and keySlotUsage = encryption]: Liegt Verschlüsselung vor, übergibt :Persistency die Datenblöcke synchron über ProcessBlock() an :Cryptography.
  7. :Persistency schreibt die (ggf. verschlüsselten) Nutzdaten über den informativen Aufruf write() («aapInformative») an das :Operating System.
  8. Bedingter Block alt [Redundancy enabled in Manifest]: Ist Redundanz im Manifest aktiviert, führt :Persistency die Interaktionsreferenz ref Store Redundant Data unter Einbindung des :Operating System aus.

4. Normative Relevanz & Entwickler-Hinweise

Das Diagramm veranschaulicht das Zusammenspiel der Schnittstellen von ara::per mit Manifest-Konfigurationen und Plattformdiensten. Die Betriebssystemaufrufe open() und write() sind explizit als informativ («aapInformative») gekennzeichnet, da die konkrete POSIX-/OS-Realisierung implementationsspezifisch ist. Neben der optionalen Verschlüsselung (KeySlotMapping, keySlotUsage = encryption) wird die redundante Datenhaltung über die Manifest-Bedingung [Redundancy enabled in Manifest] und die Sequenz Store Redundant Data normativ als Architekturmuster für Fehlererkennung und -korrektur berücksichtigt. OpenFileWriteOnly() liefert laut Signatur einen ReadWriteAccessor.

The Adaptive Application needs to open a FileStorage by calling Open- FileStorage(). Afterwards, the Adaptive Application needs to open an individual file for writing by calling OpenFileWriteOnly() or OpenFileReadWrite () depending if the Adaptive Application needs to read data from the file as well. Then, the Adaptive Application can store data via the methods provided by ReadWriteAccessor either as binary data or text data. If enabled in the Manifest, Persistency stores redundant data to detect and correct errors when reading from a file later.
