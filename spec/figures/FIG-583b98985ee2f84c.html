1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU-Configuration-Metamodell (UML-Klassendiagramm / ECUC-Parameterdefinition gemäß AUTOSAR BSW-Konfigurationsstandard).
  • Architektur-Kontext: FlexRay Network Management (FrNm) innerhalb der Communication Services des AUTOSAR Classic Platform (CP) Stacks.
  • Funktionaler Zweck: Definition des Konfigurationscontainers FrNmChannelIdentifiers als Kind-Container von FrNmChannel. Er kapselt die kanalspezifische Adressierung, BSW-Handle-Referenzierung (ComM, FrIf), Schedule-Varianten für FlexRay-Zyklen sowie Schalter für Node Detection, Partial Networking (PNC) und Synchronisationsfeatures.

2. Komponenten, Entitäten & Schnittstellen

Metamodell-Container & Multiplizitäten
  • FrNmChannel (EcucParamConfContainerDef):
    • Kardinalität: 1..* (lowerMultiplicity = 1, upperMultiplicity = *). Mindestens ein FlexRay-NM-Kanal muss instanziiert werden.
    • Komposition (+subContainer): Enthält genau einen Kind-Container FrNmChannelIdentifiers.
  • FrNmChannelIdentifiers (EcucParamConfContainerDef):
    • Zentraler Aggregationspunkt für Parameter und Referenzen zur Identifikation und Betriebsart des Kanals.
Referenzen (EcucReferenceDef)
  • FrNmChannelHandle:
    • requiresSymbolicNameValue = true.
    • Stellt den symbolischen Index/Handle des FrNm-Kanals für die interne Identifikation und das Routing bereit.
  • FrNmComMNetworkHandleRef:
    • requiresSymbolicNameValue = true.
    • Bindet den FrNm-Kanal an den korrespondierenden Kommunikationskanal im Communication Manager (ComMChannel).
Enumerationen & Literale
  • FrNmPduScheduleVariant (EcucEnumerationParamDef):
    • Definiert das FlexRay-spezifische NM-PDU-Scheduling im Kommunikationszyklus (statisches/dynamisches Segment, Repetition Rate, Voting Cycle).
    • Enthaltene Literale (EcucEnumerationLiteralDef via +literal):
      • FRNM_PDU_SCHEDULE_VARIANT_1 bis FRNM_PDU_SCHEDULE_VARIANT_7 (vollständige Abdeckung der spezifizierten FlexRay-NM-Sendezeitpunktschemata).
Konfigurationsparameter (EcucParameterDef)
  • FrNmNodeId (EcucIntegerParamDef):
    • Wertebereich: min = 0, max = 255 (8-Bit-Knotenadresse auf dem FlexRay-Cluster).
  • FrNmRepeatMsgIndEnabled (EcucBooleanParamDef):
    • Multiplizität: 1..1 (Pflichtkonfiguration). Steuert die Auswertung/Signalisierung des Repeat Message Request Bits.
  • FrNmActiveWakeupBitEnabled (EcucBooleanParamDef):
    • defaultValue = false, Multiplizität: 0..1. Aktiviert die Handhabung des Active Wakeup Bits im CBV (Control Bit Vector).
  • FrNmDynamicPncToChannelMappingEnabled (EcucBooleanParamDef):
    • defaultValue = false, Multiplizität: 0..1. Ermöglicht dynamische PNC-zu-Kanal-Zuordnungen zur Laufzeit.
  • FrNmSynchronizedPncShutdownEnabled (EcucBooleanParamDef):
    • defaultValue = false, Multiplizität: 0..1. Aktiviert das koordinierte, synchronisierte Herunterfahren partieller Netze über FlexRay.
  • FrNmSynchronizationPointEnabled (EcucBooleanParamDef):
    • Bestimmt, ob Synchronisationspunkte im FlexRay-Zyklus für den NM-Zustandsübergang genutzt werden.
  • FrNmNodeDetectionEnabled (EcucBooleanParamDef):
    • Schaltet die Erkennung anderer Netzwerkknoten via NM-PDUs frei.
  • FrNmSourceNodeIdentifierEnabled (EcucBooleanParamDef):
    • Steuert, ob die Quell-Knoten-ID (Source Node Identifier) in übertragenen NM-PDUs mitgeführt wird.

3. Dynamisches Verhalten & Sequenzablauf

Hinweis: Als rein statisches ECUC-Metamodell-Diagramm enthält die Abbildung keine Laufzeitsequenzen; die Parameter steuern jedoch direkt das folgende Laufzeitverhalten:

  • NM-PDU-Scheduling (FrNmPduScheduleVariant): Bestimmt den deterministischen Übertragungszyklus der FrNm-PDUs im FlexRay-Schedule (z. B. Übertragung in jedem Zyklus vs. periodisches Voting in dezidierten Macrotick-Fenstern über FrIf).
  • PNC-Shutdown (FrNmSynchronizedPncShutdownEnabled): Synchronisiert das Herunterfahren von Teilnetzwerken über das globale NM-Protokoll; verhindert asynchrone Sleep-Zustände einzelner ECUs innerhalb desselben PNCs.
  • Node Tracking (FrNmNodeDetectionEnabled / FrNmSourceNodeIdentifierEnabled): Triggerung von Callbacks an das Nm-Interface (Nm_RepeatMessageInd, Nm_PduRxIndication), sobald NM-PDUs mit gesetztem Repeat-Message-Bit oder abweichender Node-ID empfangen werden.

4. Normative Relevanz & Entwickler-Hinweise

  • Code-Generierung (FrNm_Cfg.h / FrNm_PBcfg.c):
    • FrNmNodeId, FrNmRepeatMsgIndEnabled und die PNC-Parameter generieren kanalspezifische ROM-Deskriptoren (z. B. FrNm_ChannelConfigType).
    • Wenn FrNmDynamicPncToChannelMappingEnabled deaktiviert ist, werden PNC-Kanal-Vektoren zur Compile-Zeit statisch optimiert, was RAM und ROM einspart.
  • Symbolic Name Generation:
    • Da für FrNmChannelHandle und FrNmComMNetworkHandleRef requiresSymbolicNameValue = true gefordert ist, müssen EcuC-Generatoren eindeutige C-Präprozessor-Makros erzeugen (FrNmConf_FrNmChannel_<Name>), die mit den entsprechenden ComM-Kanal-Makros konsistent sind.
  • FlexRay-Stack-Konsistenz:
    • Die gewählte FrNmPduScheduleVariant (1–7) muss zwingend mit dem Fibex-/AUTOSAR-System-Template (Cluster-Kommunikationszyklus, statische/dynamische Slots) und der FrIf-Konfiguration harmonieren. Eine Fehlkonfiguration führt zu PDU-Dropping oder Zyklusüberläufen im FlexRay-Treiber.
