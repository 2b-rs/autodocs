1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Tabellarische Spezifikationsmatrix / Datendefinitions-Tabelle (Auszug aus der normativen AUTOSAR Application Interfaces Table / AI-Excel-Katalog, Tabellenblatt 07_DataTypes_ContinuousValue).

  • Technischer Zweck: Formale Spezifikation kontinuierlicher physikalischer Datentypen (ContinuousValue Data Types) für standardisierte Software-Komponenten (SWCs). Dient als Eingangsmodell zur Ableitung von AUTOSAR-M1-Metamodell-Elementen: ApplicationPrimitiveDataType, CompuMethod (Typ LINEAR/RAT_FUNC), DataConstr sowie Unit und PhysicalDimension.

2. Komponenten, Entitäten & Schnittstellen

Die Tabelle strukturiert standardisierte physikalische Beschleunigungs-Datentypen über attributierte Spaltenfelder:

  • Metadaten- & Identifikationsattribute (Grün):
  • Short name: Eindeutiger AUTOSAR-Bezeichner (Identifier für ARXML-Tags, z. B. A4, A2, A5).
  • Long name: Klartextbezeichnung (Acceleration4, Acceleration2, Acceleration5).
  • Description: Semantische Kurzbeschreibung der Zielanwendung (Generic acceleration data type [X]).
  • Initiator WP: Zuständiges AUTOSAR Work Package (hier 10.3 = Vehicle Dynamics / Chassis / Suspension).
  • Implementierungsattribute (Grau):
  • Minimal Bits Size recommended: Empfohlene Mindest-Wortbreite zur verlustfreien Diskretisierung (SInt16, SInt14, SInt17).
  • Physikalisch-mathematische Skalierung (Blau):
  • Resolution: Skalierungsfaktor / LSB-Gewichtung ($0{,}00098\,\mathrm{m/s^2}$ bei A4; $0{,}00391\,\mathrm{m/s^2}$ bei A2 und A5).
  • Physical Lower Limit / Physical Upper Limit: Gültigkeitsintervall (z. B. $[-18{,}0; +18{,}0]$ für A4, $[-30{,}0; +30{,}0]$ für A2, $[-200{,}0; +200{,}0]$ für A5).
  • Offset: Additiver Nullpunkt-Offset (jeweils $0{,}00000$).
  • Unit: SI-Einheit der physikalischen Größe ($\mathrm{m/s^2}$).
  • Anwendungsreferenz (Gelb):
  • Reference: Primäre Fahrzeugdomäne / Systemkontext (Esc für Fahrdynamikregelung/ESP, Suspension für Fahrwerk/Federung).

Spezifische Ausprägungen & visuelle Annotationen:

  • Datensatz A4: Hochaufgelöster Brems-/Fahrdynamikbereich ($LSB \approx 2^{-10}\,\mathrm{m/s^2}$, $\pm 18\,\mathrm{m/s^2}$, nativ auf 16-Bit-Vorzeichenwert abbildbar).
  • Datensatz A2: Fahrwerksbeschleunigung ($LSB \approx 2^{-8}\,\mathrm{m/s^2}$, $\pm 30\,\mathrm{m/s^2}$, 14 Bit Integerbedarf).
  • Datensatz A5 (rot hervorgehoben): Stoß-/Extremwert-Fahrwerksbeschleunigung ($\pm 200\,\mathrm{m/s^2}$, $LSB \approx 2^{-8}\,\mathrm{m/s^2}$). Die roten Rahmen markieren den ShortName A5 sowie die Einheit $\mathrm{m/s^2}$ als Referenzbeispiel für den Wertebereichs- und Einheitenabgleich im AI-Leitfaden.

4. Normative Relevanz & Entwickler-Hinweise

  • Generierung von ImplementationDataType & RTE-Types:
  • A5 erfordert laut Spezifikation SInt17 (17 Bit mit Vorzeichen). Da Standard-C (C99/MISRA) keine 17-Bit-Basisdatentypen kennt, muss der Datentyptreiber/RTE-Generator A5 in C auf sint32 abbilden. Ein fehlerhaftes Casting/Mapping auf sint16 führt zu einem kritischen Überlauf (Wertebereichsüberschreitung bei $|a| > 128\,\mathrm{m/s^2}$).
  • A2 (SInt14) und A4 (SInt16) können speichereffizient auf Standard-sint16 gemappt werden.
  • CompuMethod-Konfiguration:
  • Jede Zeile bedingt eine lineare Skalierungsformel:

$$\text{Phys} = \text{Raw} \times \text{Resolution} + \text{Offset}$$

  • Im ARXML wird hierfür eine CompuMethod vom Typ IDENTICAL oder LINEAR (CompuScale mit CompuNumerator / CompuDenominator) mit den exakt angegebenen Grenzen in DataConstr (PhysConstrs) erzeugt.
  • Port-Kompatibilität auf VFB-Ebene:
  • Sender-Receiver-Kommunikation zwischen SWCs erfordert kompatible ApplicationDataType- bzw. CompuMethod-Definitionen. Die Verbindung eines A2-Outputs mit einem A4-Input schlägt zur Design-Time fehl, sofern keine explizite RTE-Typumwandlung (Data Conversion) konfiguriert ist.
  • Bus-Signal-Mapping (COM / FIBEX):
  • Die Spalte Minimal Bits Size recommended definiert direkt die minimale BitLength des CAN/LIN/FlexRay/Ethernet-Signals im Com-Stack.
  • Das Signal muss im PDU-Frame für A5 mit mindestens 17 Bit (vorzeichenbehaftet / Two's Complement) angelegt werden, um Quantisierungsfehler und Truncation im Empfangs-Stack zu vermeiden.
