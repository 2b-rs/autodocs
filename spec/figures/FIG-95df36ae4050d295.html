1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm (class DOC_PduEndToEndProtection) zur Konfiguration des E2E-Schutzes im AUTOSAR-System-Template (System Description / FIBEX-Elemente). Es spezifiziert die metamodellhafte Einbettung von End-to-End-Schutzmechanismen (E2E Protection Wrapper bzw. PDU/Signal-basierter E2E-Schutz) auf Systemebene und definiert die Verknüpfung zwischen abstrakten E2E-Profilbeschreibungen und konkreten Kommunikationsartefakten (ISignalIPdu, ISignalGroup, ISignalToIPduMapping).

2. Komponenten, Entitäten & Schnittstellen

Das Metamodell umfasst folgende Klassen, Attribute und Assoziationen:

  • EndToEndProtection::EndToEndProtectionSet: Spezialisierung von ARElement. Dient als Aggregationscontainer für EndToEndProtection über die Komposition +endToEndProtection (Kardinalität 0..*, Stereotype «atpVariation, atpSplitable»).
  • EndToEndProtection::EndToEndProtection: Spezialisierung von Identifiable. Repräsentiert eine konkrete E2E-Schutzinstanz.
    • Besitzt eine Komposition +endToEndProfile (Kardinalität 1, Stereotyp «atpSplitable») auf EndToEndProtection::EndToEndDescription. Daran angeheftet ist ein Variationstag: «atpVariation» Tags: Vh.latestBindingTime = PreCompileTime.
    • Aggregiert über die Komposition +endToEndProtectionISignalIPdu (Kardinalität 0..*, Stereotype «atpVariation, atpSplitable») Instanzen von EndToEndProtectionISignalIPdu.
  • EndToEndProtection::EndToEndDescription: Enthält die profilspezifischen Schutzparameter:
    • + category: NameToken
    • + counterOffset: PositiveInteger [0..1]
    • + crcOffset: PositiveInteger [0..1]
    • + dataId: PositiveInteger [0..*] {ordered}
    • + dataIdMode: PositiveInteger [0..1]
    • + dataLength: PositiveInteger [0..1]
    • + maxDeltaCounterInit: PositiveInteger [0..1]
  • EndToEndProtectionISignalIPdu: Konfiguriert den E2E-Schutz im Kontext einer PDU mit Attribut + dataOffset: Integer.
    • Referenziert via unidirektionaler Assoziation +iSignalIPdu genau eine (1) Instanz von CoreCommunication::ISignalIPdu.
    • Referenziert via unidirektionaler Assoziation +iSignalGroup genau eine (1) Instanz von CoreCommunication::ISignalGroup.
  • CoreCommunication::ISignalIPdu: Spezialisierung von IPdu.
    • Attribut: + unusedBitPattern: Integer.
    • Aggregiert via Komposition +iSignalToPduMapping (Kardinalität 0..*, Stereotyp «atpVariation») Instanzen von CoreCommunication::ISignalToIPduMapping.
  • CoreCommunication::ISignalGroup: Spezialisierung von FibexElement. Repräsentiert die logische Gruppe geschützter Signale.
  • CoreCommunication::ISignalToIPduMapping: Spezialisierung von Identifiable.
    • Attribute: + packingByteOrder: ByteOrderEnum [0..1], + startPosition: Integer [0..1], + transferProperty: TransferPropertyEnum [0..1], + updateIndicationBitPosition: Integer [0..1].
    • Referenziert optional via Assoziation +iSignalGroup eine Instanz von CoreCommunication::ISignalGroup (Kardinalität 0..1).

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Metamodell / Konfigurationsmodell beschreibt das Diagramm keinen Laufzeit-Sequenzablauf. Es definiert vielmehr die deklarative Abbildungskette für den E2E-Schutz:

  1. Das EndToEndProtectionSet fasst auf oberster Ebene alle Schutzdefinitionen zusammen.
  2. Jede EndToEndProtection bindet die algorithmischen Parameter (EndToEndDescription wie Profile, Offsets für Counter und CRC, Daten-ID-Liste und Längen) spätestens zur Vorkompilierzeit (PreCompileTime).
  3. Die Zuordnung zur tatsächlichen Kommunikation erfolgt über EndToEndProtectionISignalIPdu, welche die geschützte Signalmenge (ISignalGroup) innerhalb einer konkreten PDU (ISignalIPdu) verortet (dataOffset).
  4. Das Layout innerhalb der PDU wird komplementär durch das Signal-zu-PDU-Mapping (ISignalToIPduMapping) mit Startpositionen, Byte-Reihenfolge und Transfer-Eigenschaften determiniert.

4. Normative Relevanz & Entwickler-Hinweise

  • System Template & E2E-Konfiguration: Das Modell bildet die Grundlage für Generatoren (RTE-, Wrapper- und E2E-Konfiguratoren), um E2E-Library-Aufrufe, Datenpuffer, Offsets und Prüfroutinen für die Kommunikation abzustimmen.
  • Variabilitätsbindung: Durch «atpVariation» mit Vh.latestBindingTime = PreCompileTime an der Profilzuordnung muss die Wahl des E2E-Profils und dessen Konfiguration spätestens bei der Vorkompilierung statisch aufgelöst sein (keine Post-Build-Änderung des Profilschemas).
  • Splitable-Eigenschaften: Die Stereotype «atpSplitable» an +endToEndProtection, +endToEndProfile und +endToEndProtectionISignalIPdu gestatten die verteilte Spezifikation der Modellfragmente über mehrere ARXML-Dateien.
  • Signal- vs. PDU-Bezug: Ein geschützter Datenstrom bedingt die synchrone Referenzierung von ISignalIPdu und ISignalGroup (jeweils Kardinalität 1) über EndToEndProtectionISignalIPdu, wobei die ISignalGroup auch optional im PDU-Mapping verknüpft ist.
