1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: AUTOSAR BSW Module Description / ECU Configuration Parameter Definition Metamodell (UML-Klassendiagramm-Notation für ECUC).
  • Technischer Zweck: Definition der Konfigurationsstruktur des Moduls EthIf (Ethernet Interface, AUTOSAR Classic Platform, Schicht: Microcontroller Abstraction Layer / BSW Communication Services Abstraction).
  • Architektur-Einordnung: Das Modul EthIf vermittelt zwischen den hardwarenahen Treibern (Eth, EthTrcv, EthSwt) und den transport-/netzwerkorientierten oberen Schichten (TcpIp, DoIP, EthSM, EthTSyn, SomeIp). Das Diagramm spezifiziert die Parametrierungs-Hierarchie zur Zuordnung von Ethernet-Frames zu Protokoll-Eigentümern (Upper Layers), zur Registrierung von Callback-Funktionen sowie zur Abbildung der Hardware-Topologie (Controller, Transceiver, Switches, Port-Gruppen).

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm modelliert einen Konfigurationsbaum mit EthIfConfigSet als Wurzel. Alle Kindelemente sind Container (EcucParamConfContainerDef) oder Parameter (EcucIntegerParamDef, EcucFunctionNameDef), verknüpft über Kompositionen:

Wurzel-Container
  • EthIfConfigSet (EcucParamConfContainerDef): Zentrales Konfigurations-Set des Moduls für Post-Build- bzw. Pre-Compile-Varianten.
Frame-Routing & Dispatching-Container
  • EthIfFrameConfig [1..*] (Sub-Container):
    • Multiplizität: Mindestens ein Eintrag zwingend erforderlich.
    • EthIfFrameType (EcucIntegerParamDef [0..65535]): 16-Bit IEEE 802.3 EtherType (z. B. 0x0800 IPv4, 0x0806 ARP, 0x86DD IPv6, 0x88F7 PTP).
    • EthIfFrameTxPool [0..*] (Sub-Container): Puffer- bzw. Tx-Pool-Konfiguration für Frame-Typen.
  • EthIfRxIndicationConfig [1..*] (Sub-Container):
    • EthIfRxIndicationFunction (EcucFunctionNameDef): Konfigurierter C-Funktionsbezeichner für den Empfangs-Callback an die obere Schicht (z. B. TcpIp_RxIndication).
  • EthIfTxConfirmationConfig [0..*] (Sub-Container):
    • EthIfTxConfirmationFunction (EcucFunctionNameDef): Callback für die Sendebestätigung an die obere Schicht. Multiplizität 0..* erlaubt Systemauslegungen ohne obere Tx-Bestätigungen.
  • EthIfTrcvLinkStateChgConfig [1..*] (Sub-Container):
    • EthIfTrcvLinkStateChgFunction (EcucFunctionNameDef): Callback für Transceiver-Verbindungsstatusänderungen (typischerweise Weiterleitung an EthSM_TrcvLinkStateChg).
Hardware-Topologie-Container
  • EthIfPhysController [1..*]: Physische Repräsentation eines MAC-Controllers (Eth).
  • EthIfController [1..*]: Logischer Controller (Abbildung auf VLANs oder Interface-Abstraktionen).
  • EthIfTransceiver [0..*]: Zuordnung physischer PHY-Treiber (EthTrcv).
  • EthIfSwitch [0..*]: Anbindung von Ethernet-Switch-Treibern (EthSwt).
  • EthIfSwitchPortGroup [0..*]: Logische Bündelung von Switch-Ports (z. B. für Port-basiertes VLAN-Handling oder Forwarding-Restriktionen).

3. Dynamisches Verhalten & Sequenzablauf

Obwohl das Diagramm statische Metadaten abbildet, determiniert es folgende Laufzeitpfade:

  1. Frame Demultiplexing im Rx-Pfad (synchron):
    • Treiber signalisiert Rahmen über Eth_RxIndication().
    • EthIf parst den Ethernet-Header und extrahiert den EtherType.
    • Tabellen-Lookup über die in EthIfFrameConfig konfigurierten EthIfFrameType-Einträge.
    • Aufruf der zugehörigen Callback-Funktion EthIfRxIndicationFunction() (z. B. Übergabe an IP-Stack oder Zeit-Synchronisation).
  2. Tx-Confirmation Pfad (asynchron über Treiber-Interrupt/MainFunction):
    • Hardware-Treiber meldet erfolgreiche Übertragung via Eth_TxConfirmation().
    • EthIf mappt den Frame auf den anfordernden Kontext und triggert EthIfTxConfirmationFunction().
  3. Link-State Tracking:
    • Interrupt oder zyklisches Polling im EthTrcv führt zu EthIf_TrcvModeIndication().
    • Zustandswechsel triggert synchron EthIfTrcvLinkStateChgFunction(), wodurch der EthSM State-Machine-Transitionen ausführt.

4. Normative Relevanz & Entwickler-Hinweise

  • Code-Generierung & Funktionszeigertabellen:
    • Der Codegenerator erzeugt aus EthIfRxIndicationConfig, EthIfTxConfirmationConfig und EthIfFrameConfig statische const-Funktionszeiger-Arrays oder switch-case-Verteiler.
    • Die Namen in EcucFunctionNameDef müssen C-konforme Bezeichner sein und exakt den genormten AUTOSAR-Signaturen entsprechen (z. B. <Module>_RxIndication(uint8 CtrlIdx, Eth_FrameType FrameType, boolean IsBroadcast, const uint8* PhysAddrPtr, const uint8* DataPtr, uint16 LenByte)).
  • Restriktionen & Kardinalitäten:
    • Mindestens ein logischer Controller (EthIfController), ein physischer Controller (EthIfPhysController), eine Frame-Konfiguration (EthIfFrameConfig) sowie je ein Rx- und Link-State-Callback sind mandatorisch (lowerMultiplicity = 1). Eine minimale Konfiguration erfordert somit mindestens ein funktionierendes Ethernet-Interface mit Rx-Pfad und State-Management.
    • Switches (EthIfSwitch), Switch-Port-Gruppen (EthIfSwitchPortGroup) sowie EthIfFrameTxPool sind optional (lowerMultiplicity = 0); sie werden nur generiert, wenn Switch-Management oder Frame-spezifische Tx-Pools im Steuergerät aktiviert sind.
  • Trennung von physischen und logischen Controllern:
    • Die Trennung von EthIfPhysController und EthIfController ermöglicht VLAN-Multiplexing: Mehrere logische Controller (EthIfController) können auf denselben physischen Controller (EthIfPhysController) referenzieren.
