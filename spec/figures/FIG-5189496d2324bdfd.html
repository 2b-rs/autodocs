1. Diagrammtyp & Architektur-Kontext

UML-Zustandsdiagramm des CAN-Network-Management-Zustandsautomaten (CanNm) innerhalb der AUTOSAR Classic Platform (Software Specification CAN NM). Das Diagramm modelliert die übergeordneten Betriebsmodi (Bus-Sleep Mode, Prepare Bus-Sleep Mode, Network Mode) sowie die internen Subzustände des hierarchischen Network Mode (Repeat Message State, Normal Operation State, Ready Sleep State) einschließlich der Initialisierungs- und Deinitialisierungsübergänge (PowerOn, PowerOff).

2. Komponenten, Entitäten & Schnittstellen

  • Modi und Zustände:
    • Bus-Sleep Mode: Ruhezustand ohne Kommunikation.
    • Prepare Bus-Sleep Mode: Übergangsmodus zur Vorbereitung der Busruhe.
    • Network Mode (Composite State) mit:
      • Repeat Message State: Initialer Zustand im Network Mode zur zyklischen Aussendung/Wiederholung von NM-Botschaften.
      • Normal Operation State: Regulärer Betriebsmodus bei aktiver Kommunikationsanforderung.
      • Ready Sleep State: Bereitschaftszustand bei freigegebenem Netzwerk vor Übergang in die Busruhe.
    • Pseudo-Zustände: Startzustand PowerOn, Endzustand PowerOff, Verzweigungsknoten (Junctions/Choice) für Network Mode und Repeat Message.
  • Schnittstellen & Funktionsaufrufe:
    • Eingehende Trigger / API: CNm_Init(), Nm_PassiveStartUp(), CNm_NetworkRequest(), CNm_NetworkRelease(), CNm_RxIndication(), CanNm_RxIndication(), CNm_TxConfirmation(), CNm_TransmissionConfirmation(), CNm_RepeatMessageBitIndication(), CNm_RepeatMessageRequest().
    • Ausgehende Notifications / Treiberaufrufe: Nm_NetworkStartIndication(), Nm_NetworkMode(), Nm_PrepareBusSleepMode(), Nm_BusSleepMode(), Nm_NetworkTimeoutException(), Nm_TxTimeoutException(), CanNm_StartTransmission(), CanNm_StopTransmission(), CanNm_StartBusLoadReduction(), CanNm_StopBusLoadReduction(), CanNm_TriggerTransmission().
    • Interne Timer: NM-Timeout Timer, Repeat Message Timer, Wait Bus-Sleep Timer, Tx Timeout Timer.

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung & Hochlauf:
    • Nach PowerOn führt CNm_Init() zur Initialisierung und in den Bus-Sleep Mode.
    • Im Bus-Sleep Mode führt CNm_RxIndication(); via /Nm_NetworkStartIndication(); zurück in den Bus-Sleep Mode.
    • Externer/passiver Aufruf Nm_PassiveStartUp(); oder CNm_NetworkRequest führt auf den Verzweigungspunkt Network Mode.
      • Bei Nm_PassiveStartUp();: Startet NM-Timeout Timer, Repeat Message Timer, ruft Nm_NetworkMode(); und CanNm_StartTransmission(); auf und wechselt in den Repeat Message State.
      • Bei CNm_NetworkRequest();: Startet dieselben Timer, meldet Nm_NetworkMode(); und stößt via CanNm_TriggerTransmission(); sowie CanNm_StartTransmission(); die Botschaftsübertragung an.
  • Repeat Message State & Verzweigung:
    • Bei Ablauf des Repeat Message Timer: Über den Choice-Knoten Repeat Message Verzweigung nach:
      • [Network Requested] /CanNm_StartBusLoadReduction(); in den Normal Operation State.
      • [Network Released] /CanNm_StopTransmission(); in den Ready Sleep State.
    • Innerhalb des Zustands setzen CNm_RxIndication(); und CNm_TransmissionConfirmation(); den NM-Timeout Timer zurück.
    • Ablauf des NM-Timeout Timers löst Nm_NetworkTimeoutException(); aus und startet den Timer neu; Ablauf des Tx Timeout Timers ruft Nm_TxTimeoutException(); auf.
  • Normal Operation & Ready Sleep:
    • Wechsel von Normal Operation State nach Ready Sleep State bei CNm_NetworkRelease(); /CanNm_StopTransmission(); CanNm_StopBusLoadReduction();.
    • Wechsel von Ready Sleep State nach Normal Operation State bei CNm_NetworkRequest(); /CanNm_StartBusLoadReduction(); CanNm_StartTransmission();.
    • Aus beiden Zuständen führt CNm_RepeatMessageBitIndication(); || CNm_RepeatMessageRequest(); mit Starten des Repeat Message Timers (und Start/Stopp von BusLoadReduction/Transmission) zurück in den Repeat Message State.
    • In Normal Operation State und Ready Sleep State setzen Empfangs-/Sende-Bestätigungen (CNm_RxIndication(), CNm_TxConfirmation()) den NM-Timeout Timer zurück.
  • Übergang in den Busruhe-Modus:
    • Läuft im Ready Sleep State der NM-Timeout Timer ab, wechselt der Automat in den Prepare Bus-Sleep Mode (/Start Wait Bus-Sleep Timer; Nm_PrepareBusSleepMode();).
    • Läuft dort der Wait Bus-Sleep Timer ab, wird via /Nm_BusSleepMode(); der Bus-Sleep Mode erreicht.
    • Empfang einer Botschaft (CanNm_RxIndication();) oder Netzwerkanforderung (CNm_NetworkRequest();) im Prepare Bus-Sleep Mode führt zurück in den Network Mode (Repeat Message State).
  • Abschaltung:
    • Aus dem Bus-Sleep Mode führt das Ereignis PowerOff in den Endzustand.

4. Normative Relevanz & Entwickler-Hinweise

  • Bildet das normative Kernverhalten der CAN-Netzwerkverwaltung ab; das Verhalten der Zustandswechsel und Timer-Start/-Ablauf-Aktionen ist verbindlich umzusetzen.
  • Timer-Handling (NM-Timeout Timer, Wait Bus-Sleep Timer, Repeat Message Timer, Tx Timeout Timer) ist streng an die Zustandsgrenzen gekoppelt; Überläufe lösen Ausnahmeroutinen (Nm_NetworkTimeoutException, Nm_TxTimeoutException) aus.
  • Implementierer müssen die korrekte Trennung zwischen passiver Anforderung (Nm_PassiveStartUp) und aktiver Netzwerkanforderung (CNm_NetworkRequest) beachten, insbesondere hinsichtlich des unmittelbaren Sendens (CanNm_TriggerTransmission).
