2. Komponenten, Entitäten & Schnittstellen

#### Aktivitäten (Chevron-Operatoren):

  1. Generate RTE Prebuild Dataset: Extrahiert und generiert Vorkompilierungs-/Varianten-Konfigurationsheader für die RTE.
  2. Generate OS: Erzeugt den plattformspezifischen Betriebssystem-Code aus den ECU-Konfigurationswerten.
  3. Generate RTE: Zentrale Generator-Aktivität zur Synthese von RTE-Code, BSW-Scheduler-Code, Schnittstellenbeschreibungen und M&C-Daten.
  4. Generate Local MC... (Generate Local Measurement and Calibration Support Data): Erstellt modullokale Mess- und Kalibrier-Metadaten.

#### Container / Delivery Packages (Briefumschlag-Symbol):

  • ECU Extract: Systemextrakt für das spezifische Steuergerät (enthält System-Signale, Flat-View, Topologie).
  • Delivered Atomic Software Components: Übergabepaket der Applikations-SWCs; enthält via Komposition Software Component Internal Behavior [0..*].
  • BSW Module Integration Bundle: Integrationspaket der Basis-Software; enthält via Komposition BSW Module Behavior Extension [0..] und aggregiert Local Measurement and Calibration Support Data [0..].

#### Beschreibungs- und Konfigurationsartefakte (Dokument-Symbol, ARXML):

  • ECU Configuration Values: Vollständige Parametrisierung der BSW- und RTE-Module (EcucValueCollection).
  • Service Component Description: Port- und Schnittstellen-Spezifikationen der BSW-Service-Komponenten (z. B. Dem, NvM, ComM).
  • ECU Service Connectors: Definition der Verbindungen zwischen Service-Ports und SWC-Ports auf ECU-Ebene.
  • Calibration Parameter Value Set: Explizite Wertemengen für Kalibrierparameter (z. B. Kennlinien/Kennfelder).
  • Software Component Internal Behavior: Beschreibt Runnables, Events, Inter-Runnable Variables (IRVs) und Port-API-Optionen der SWC.
  • BSW Module Behavior Extension: Beschreibt BswSchedulableEntities, BSW-Events und Modul-Trigger.
  • Basic Software ... (Basic Software Module Description, BSWMD): Formale Spezifikation der BSW-Moduleigenschaften.
  • Local Measurement and Calibration Support Data: Lokale MC-Datenfragmente auf Komponenten-/Modulebene.
  • RTE Implementation Description: Formales ARXML-Modell der generierten RTE-Schnittstellen und -Implementierungen.
  • RTE Measurement and Calibration Support Data: Konsolidierte Mess- und Kalibrierbeschreibungsdaten der RTE.

3. Dynamisches Verhalten & Sequenzablauf

  1. Phase 1: Lokale Vorbereitung & Datensatzerzeugung (Nebenläufig/Vorgelagert):
  • Lokale M&C-Erzeugung: Generate Local MC... transformiert Komponenten- und Modulverhalten zusammen mit der BSWMD in modullokale M&C-Support-Daten (Local Measurement and Calibration Support Data), welche dem BSW Module Integration Bundle beigefügt werden.
  • Prebuild-Vorbereitung: Generate RTE Prebuild Dataset berechnet aus dem ECU Extract, der Service-Komponenten-Beschreibung und den ECU Configuration Values den RTE Prebuild Configuration Header [1].
  1. Phase 2: Betriebssystem-Generierung:
  • Generate OS konsumiert die ECU Configuration Values (insb. OS-Container wie Tasks, ISRs, ScheduleTables, Counter) und emittiert den OS Generated Code [1].
  1. Phase 3: Synthese durch den RTE-Generator:
  • Sobald ECU Extract, Komponenten-Lieferpakete (Delivered Atomic Software Components), BSW-Module (BSW Module Integration Bundle), Service Connectors und Konfigurationswerte vorliegen, generiert Generate RTE:
  • Synchronisiert Task-Mappings (Zuordnung von RunnableEntities und BswSchedulableEntities auf OS-Tasks).
  • Löst Intra-ECU- und Inter-ECU-Kommunikation auf (Port-to-Port Connections, Signal-Mapping, Pufferallokation).
  • Generiert den Applikations-RTE-Code (RTE Source Code) sowie die modulspezifischen BSW-Scheduler-Header (BSW Scheduler Code).
  • Emittiert die RTE Implementation Description und leitet globale RTE-Kalibrierungs- und Messstrukturen (RTE Measurement and Calibration Support Data) ab.

4. Normative Relevanz & Entwickler-Hinweise

  • Vollständige SchM-Integration in die RTE (AUTOSAR 4.x): Der BSW Scheduler (SchM) ist kein separates BSW-Modul mehr, sondern wird integral vom RTE-Generator erzeugt (BSW Scheduler Code). Basis-Software-Entwickler müssen die BswModuleBehavior (Teil von BSW Module Behavior Extension) exakt definieren, da SchM_Enter_<Module>_<Area>(), SchM_Exit... und die Ausführungszeitpunkte der *_MainFunction() direkt vom RTE-Generator auf OS-Mechanismen gemappt werden.
  • Entkopplung Applikation vs. ECU-Integration: Delivered Atomic Software Components erfordern für die RTE-Generierung zwingend das Software Component Internal Behavior (Runnables, Events, Datenelemente), nicht jedoch C-Quellcode. Dies garantiert die Wiederverwendbarkeit der SWC-Implementierung über verschiedene Steuergeräte hinweg.
  • A2L-/M&C-Workflow (ASAP2): Ein A2L-File kann nicht isoliert aus dem SWC-Code generiert werden. Lokale M&C-Daten (Local Measurement and Calibration Support Data) müssen mit den vom RTE-Generator erzeugten Datenstrukturen (RTE Measurement and Calibration Support Data) zusammengeführt werden, da optimierte Kommunikationspuffer, Emulations-Handles und RTE-interne Signale erst nach der Generierung feste Adressen im Speicherlayout besitzen.
  • Variantenhandhabung (Prebuild vs. Post-Build): Das Vorhandensein von Generate RTE Prebuild Dataset und Calibration Parameter Value Set erzwingt eine saubere Trennung von Varianten: Prebuild-Varianten werden über den Header vorab eingefroren, während Kalibrierparameter-Sets optional als Input in die RTE einfließen, um ROM-/RAM-Layouts und Paging-Mechanismen zur Generierungszeit zu fixieren.
