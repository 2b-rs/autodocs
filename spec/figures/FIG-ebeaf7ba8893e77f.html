Figure 5.13: Mapping of a Variable Data Prototype which is aggregated within a composite data type on a System Signal

1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-2.0-Klassendiagramm (Metamodell-Ausschnitt auf M2-Ebene gemäß AUTOSAR-Templatespezifikation).
  • Spezifikatorischer Kontext: AUTOSAR_TPS_SystemTemplate, Release R4.1.3, Kapitel 5 (System Signal & Data Mapping).
  • Technischer Zweck & funktionale Einordnung:
    • Metamodellierung des Mappings eines einzelnen Datenprototyps (VariableDataPrototype), der innerhalb eines zusammengesetzten Datentyps (Record/Struktur oder Array) gekapselt ist, auf ein atomares SystemSignal.
    • Schlägt die Brücke zwischen der logischen Software-Architektur (VFB-Ebene, SWC-Ports, Datentypen) und der Netzwerk-Kommunikationsmatrix (Signal-Ebene für CAN, LIN, FlexRay, Ethernet).
    • Ermöglicht die partielle De-Komposition hierarchischer Datentypen auf isolierte Einzelsignale ohne zwingenden Einsatz einer vollständigen SignalGroup.
    • Unterstützt die Mapping-Traversierung sowohl über die Ebene der Applikationsdatentypen (Application Data Types, ADT) als auch über Implementierungsdatentypen (Implementation Data Types, IDT).

2. Komponenten, Entitäten & Schnittstellen

Basis- und Mapping-Root-Klassen
  • DataMapping (abstrakt):
    • Vererbungswurzel aller AUTOSAR-Mapping-Metaklassen im System Template.
    • Attribut: +communicationDirection : CommunicationDirectionType [0..1] (definiert die Flussrichtung: In, Out oder InOut).
  • SenderReceiverCompositeElementToSignalMapping:
    • Spezialisierung von DataMapping.
    • Assoziation +dataElement mit Stereotyp «instanceRef» (Kardinalität 0..1): Navigiert kontextsensitiv durch die Komponenten- und Port-Hierarchie auf das Quell-VariableDataPrototype (abgeleitet von AutosarDataPrototype).
    • Assoziation +systemSignal (Kardinalität 1): Zielreferenz auf das korrespondierende SystemSignal.
    • Komposition +typeMapping (Kardinalität 1): Besitzt die Wurzel des Typ-Traversierungsbaums (SenderRecCompositeTypeMapping).
Signal-Entität
  • SystemSignal (Stereotyp «ARElement»):
    • Kommunikationssignal auf System- und Busebene.
    • Attribut: +dynamicLength : Boolean (Kennzeichnung von Signalen mit zur Laufzeit variabler Länge, z. B. dynamische Arrays oder Serialisierungs-Payloads).
Typ-Traversierung (Composite-Pattern)
  • SenderRecCompositeTypeMapping (abstrakt):
    • Basisklasse zur rekursiven Auflösung hierarchisch geschachtelter Datentypen.
  • SenderRecRecordTypeMapping:
    • Spezialisierung von SenderRecCompositeTypeMapping für strukturierte Datentypen (Records / Structs).
    • Komposition +recordElementMapping (Kardinalität *): Aggregiert 1..n Instanzen von SenderRecRecordElementMapping.
  • SenderRecArrayTypeMapping:
    • Spezialisierung von SenderRecCompositeTypeMapping für Vektoren/Arrays.
    • Komposition +arrayElementMapping (Kardinalität *): Aggregiert 1..n Instanzen von SenderRecArrayElementMapping.
  • Rekursionseigenschaft (+complexTypeMapping [0..1]):
    • Sowohl SenderRecRecordElementMapping als auch SenderRecArrayElementMapping verweisen über die Assoziation +complexTypeMapping auf SenderRecCompositeTypeMapping, um tiefer verschachtelte Sub-Strukturen/Arrays abzubilden.
    • Endet die Schachtelung auf einem primitiven Blattelement, referenzieren die Element-Mappings alternativ das Ziel über +systemSignal [0..1].
Element- und Index-Ebene
  • SenderRecRecordElementMapping:
    • Repräsentiert das Mapping eines spezifischen Record-Members.
    • Assoziation +applicationRecordElement (Kardinalität 0..1): Referenziert ein ApplicationRecordElement (abgeleitet von ApplicationCompositeElementDataPrototype).
    • Assoziation +implementationRecordElement (Kardinalität 0..1): Referenziert ein ImplementationDataTypeElement (mit Stereotyp «Identifiable»).
    • Assoziation +systemSignal (Kardinalität 0..1): Verweist auf das zugeordnete SystemSignal.
  • SenderRecArrayElementMapping:
    • Repräsentiert das Mapping eines Array-Elements.
    • Komposition +indexedArrayElement (Kardinalität 1): Besitzt ein IndexedArrayElement zur Adressierung der Indexposition im Array.
    • Assoziation +systemSignal (Kardinalität 0..1): Verweist auf das zugeordnete SystemSignal.
  • IndexedArrayElement:
    • Attribut: +index : Integer (Indexposition des Array-Elements).
    • Assoziation +applicationArrayElement (Kardinalität 0..1): Referenziert ein ApplicationArrayElement (abgeleitet von ApplicationCompositeElementDataPrototype).
    • Assoziation +implementationArrayElement (Kardinalität 0..1): Referenziert ein ImplementationDataTypeElement.
Typ-Definitionselemente (Zielebene)
  • ApplicationRecordElement: Repräsentiert ein Strukturelement auf Ebene der Applikationsdatentypen.
  • ApplicationArrayElement:
    • Repräsentiert ein Array-Element auf Ebene der Applikationsdatentypen.
    • Attribute:
      • +arraySizeHandling : ArraySizeHandlingEnum [0..1]
      • +arraySizeSemantics : ArraySizeSemanticsEnum [0..1]
      • «atpVariation» +maxNumberOfElements : PositiveInteger
  • ImplementationDataTypeElement:
    • Repräsentiert ein Element auf Ebene der Implementierungsdatentypen («Identifiable»).

3. Dynamisches Verhalten & Sequenzablauf

Als M2-Metamodell-Klassendiagramm existiert kein Laufzeit-Zustandsdiagramm. Die Abbildung induziert folgende Entwurfs-, Generierungs- und Ausführungskette:

[SWC Runtime: Struct/Array] 
       │ (Rte_Write)
       ▼
[RTE: Extraktion Blatt-Element] 
       │ (Com_SendSignal)
       ▼
[COM: Serialisierung / PDU-Packing] 
       │ (PduR_ComTransmit)
       ▼
[CanIf / FrIf / EthIf: Frame TX]
  1. Konfigurations- & Generierungszeit (Toolchain):
    • Der System-Generator traversiert den Pfad von SenderReceiverCompositeElementToSignalMapping über typeMapping bis zum spezifizierten Blatt (recordElementMapping bzw. arrayElementMapping mit index).
    • Der RTE-Generator generiert typspezifische Serialisierungs- bzw. Extraktionslogik: Aus dem komplexen C-Typ der SWC wird der berechnete Speicher-Offset des adressierten Blatt-Elements ermittelt.
    • Der COM-Stack-Generator instanziiert ein ComSignal mit der Bitbreite und dem Encoding des Blattelements und ordnet dieses einer I-PDU zu.
  2. Laufzeit TX (Sende-Pfad):
    • Die SWC übergibt die vollständige Struktur/das Array an das RTE-API (z. B. Rte_Write_<port>_<dataElement>).
    • Die RTE extrahiert das konfigurierte Element via Pointer-Arithmetik/Offset und leitet ausschließlich dieses an Com_SendSignal(ComSignalId, &value) weiter.
  3. Laufzeit RX (Empfangs-Pfad):
    • Nach Empfang der I-PDU meldet der Bus-Treiber via PduR an COM.
    • Com_ReceiveSignal stellt den atomaren Wert bereit.
    • Die RTE repliziert den Wert in die entsprechende Struktur-/Arrayposition der Ziel-SWC und setzt das konfigurierte Event (z. B. DataReceivedEvent).

4. Normative Relevanz & Entwickler-Hinweise

  • Datenkonsistenz vs. SignalGroups (Architekturrisiko):
    • Dieses Mapping-Konstrukt überträgt isolierte Elemente einer Struktur als eigenständige SystemSignals. Es bietet keine inhärente atomare Konsistenz (Shadow-Buffer-Mechanismus) über mehrere Elemente derselben Datenstruktur hinweg.
    • Wenn mehrere Felder eines Records auf getrennte Signale gemappt werden, können diese in unterschiedlichen PDUs oder asynchron übertragen werden. Für vollständige Transaktionssicherheit über den gesamten Datensatz muss stattdessen SenderReceiverToSignalGroupMapping eingesetzt werden.
  • XOR-Konsistenzbedingung bei Typ-Referenzen:
    • Innerhalb von SenderRecRecordElementMapping und IndexedArrayElement darf entweder die application*Element- ODER die implementation*Element-Assoziation gesetzt sein (wechselseitiger Ausschluss). ADT-Mappings erfordern im Gesamtsystem ein entsprechendes DataTypeMappingSet.
  • Array-Index-Validierung:
    • Da IndexedArrayElement einen festen numerischen index : Integer verlangt, muss der Generator validieren, dass 0 <= index < maxNumberOfElements gilt.
    • Dynamische Arrays (arraySizeSemantics = variableSize) erfordern bei variabler Elementanzahl zwingend die Aktivierung von SystemSignal.dynamicLength = true oder ein zusätzliches Längen-Signal.
  • Variantenmanagement:
    • Das Attribut maxNumberOfElements ist mit «atpVariation» annotiert. Bei Post-Build- oder Compile-Time-Varianten muss der Konfigurations-Prüfer sicherstellen, dass Array-Index-Mappings nicht in Varianten aktiv bleiben, in denen das Array auf eine geringere Größe evaluiert wird.
