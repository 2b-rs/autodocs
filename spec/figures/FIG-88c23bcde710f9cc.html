1. Diagrammtyp & Architektur-Kontext

UML-Sequenzdiagramm zur Darstellung des Aufwachablaufs eines LIN-Controllers über Interrupt (Wakeup by Interrupt) im Kontext des AUTOSAR-Basissoftware-Zustandsmanagements (ECU State Manager, Classic Platform). Das Diagramm veranschaulicht das Zusammenspiel der Phasen GOSLEEP, SLEEP, des Hardware-Zustands HALT sowie der Wiederaufwachsequenz WAKEUP I unter Einbindung von Treibern, Interfaces, Betriebssystem und Integrationscode.

2. Komponenten, Entitäten & Schnittstellen

Beteiligte Lebenslinien (von links nach rechts):

  • «module» EcuM (ECU State Manager, BSW-Modul)
  • Integration Code (Callout- und Integrationscode)
  • «module» Os (Betriebssystem)
  • «module» Mcu (Microcontroller Unit Driver)
  • «module» Icu (Interrupt Notification / Input Capture Unit Driver; passiv dargestellt)
  • «module» LinIf (LIN Interface)
  • «module» Lin (LIN Driver)
  • «module» LinTrcv (LIN Transceiver Driver; passiv dargestellt)
  • «Peripheral» LinController/UART (Hardware-Peripherie)

Verwendete Schnittstellen und Signaturen:

  • EcuM_EnableWakeupSources(EcuM_WakeupSourceType)
  • GetResource(RES_AUTOSAR_ECUM_<core#>) / ReleaseResource(RES_AUTOSAR_ECUM_<core#>)
  • DisableAllInterrupts() / EnableAllInterrupts()
  • Mcu_SetMode(Mcu_ModeType) / Mcu_SetMode() (Return)
  • Wakeup interrupt() / Return from interrupt()

3. Dynamisches Verhalten & Sequenzablauf

  1. GOSLEEP-Phase:
    • EcuM ruft im Integration Code die Funktion EcuM_EnableWakeupSources(EcuM_WakeupSourceType) auf. (Hinweis: LinSM hat bereits beim Übergang in den NO_COM-Zustand LinIf_GotoSleep aufgerufen; im Callout ist nichts weiter zu tun).
    • EcuM fordert über GetResource(RES_AUTOSAR_ECUM_<core#>) beim Os die Scheduler-Ressource an, um ein vorzeitiges Re-Scheduling nach einem ISR-Kategorie-2-Ereignis zu verhindern.
  2. SLEEP-Phase:
    • EcuM sperrt alle Interrupts via DisableAllInterrupts() am Os.
    • EcuM versetzt den Mikrocontroller über Mcu_SetMode(Mcu_ModeType) in den stromsparenden Zustand HALT.
  3. Aufwachereignis & ISR (Wakeup by Interrupt):
    • Die Peripherie LinController/UART löst am Modul Lin einen Wakeup interrupt() aus.
    • Die ISR von Lin ruft synchron EcuM_CheckWakup(EcuM_WakeupSourceType) an EcuM auf.
    • EcuM ruft vor der PLL-Aktivierung den Hook EcuM_CheckWakeupHook(EcuM_WakeupSourceType) im Integration Code auf.
    • Der Integration Code führt Activate PLL() aus.
    • EcuM leitet die Wakeup-Prüfung über LinIf_CheckWakeup(EcuM_WakeupSourceType) an LinIf weiter.
    • LinIf ruft Lin_CheckWakeup(uint8) am Lin-Treiber auf.
    • Bei erfolgreicher Validierung meldet Lin das Aufwachereignis synchron mit EcuM_SetWakeupEvent(EcuM_WakeupSourceType) an EcuM.
    • Nach Rückkehr der Aufrufsequenz beendet die ISR die Unterbrechungsbehandlung via Return from interrupt() an LinController/UART.
  4. Wiederaufnahme nach HALT & WAKEUP I:
    • Die Programmausführung wird nach der HALT-Instruktion fortgesetzt; der ursprüngliche Aufruf Mcu_SetMode() kehrt zu EcuM zurück.
    • EcuM aktiviert vorübergehend die Interrupts mit EnableAllInterrupts().
    • Beginn der Phase WAKEUP I:
      • EcuM sperrt Interrupts via DisableAllInterrupts().
      • EcuM setzt über Mcu_SetMode(Mcu_ModeType) den Normalbetriebsmodus der MCU.
      • EcuM gibt Interrupts via EnableAllInterrupts() wieder frei.
      • EcuM ruft im Integration Code EcuM_DisableWakeupSources(EcuM_WakeupSourceType) auf.
      • EcuM gibt über ReleaseResource(RES_AUTOSAR_ECUM_<core#>) die OS-Scheduler-Ressource frei, damit andere Tasks zur Ausführung kommen können.
    • Im Nachgang informiert EcuM den ComM über den Wakeup, welcher wiederum LinSM benachrichtigt, der schließlich LinIf_Wakeup aufruft.

4. Normative Relevanz & Entwickler-Hinweise

  • Die Erfassung der OS-Ressource RES_AUTOSAR_ECUM_<core#> ist zwingend erforderlich, um sicherzustellen, dass die CPU nach dem Verlassen des HALT-Zustands im EcuM-Kontext weiterläuft und nicht direkt durch den Scheduler präemptiert wird.
  • Der Aufwachpfad bindet explizit den Callout EcuM_CheckWakeupHook ein, der vor der Re-Aktivierung der PLL im Integration Code durchlaufen wird.
  • Die Wakeup-Prüfung der ISR adressiert EcuM_CheckWakup(EcuM_WakeupSourceType), von wo aus LinIf_CheckWakeup und nachfolgend Lin_CheckWakeup getriggert werden.
  • Die Module Icu und LinTrcv sind als Lebenslinien vorhanden, werden jedoch im Szenario der internen LIN-Controller-Unterbrechung nicht aktiv angesteuert.
