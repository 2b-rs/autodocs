1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: UML-2.0-Klassendiagramm (Metamodellausschnitt aus AUTOSAR Classic Platform – Specification of Timing Extensions).
  • Architektur-Kontext: Formales Metamodell zur Spezifikation von zeitlichen Randbedingungen (TimingConstraint) auf Ebene ausführbarer Entitäten (ExecutableEntity). Es definiert die Semantik für:
    • Ausführungszeiten (ExecutionTimeConstraint),
    • Deterministische Ausführungsreihenfolgen (ExecutionOrderConstraint, EOC) inklusive hierarchischer und zyklischer Gruppen (EOCExecutableEntityRefGroup),
    • Synchronisationspunkte (SynchronizationPointConstraint) zwischen Ausführungsgruppen,
    • Einbettung in das Logical Execution Time (LET)-Paradigma, Verknüpfung mit Trigger-Ereignissen (TimingDescriptionEvent) sowie Verknüpfung mit Ursachen-Wirkungsketten (TimingDescriptionEventChain).

2. Komponenten, Entitäten & Schnittstellen

Ausführbare Entitäten & Ereignisse (Ausführungskontext)
  • ExecutableEntity («Identifiable», abstrakt): Basisklasse für ausführbaren Code.
    • Attribute: minimumStartInterval: TimeValue [0..1], reentrancyLevel: ReentrancyLevelEnum [0..1].
    • Spezialisierungen:
      • RunnableEntity («AtpStructureElement»): SWC-Runnable; assoziiert über startOnEvent [0..1] mit RTEEvent.
      • BswModuleEntity («AtpStructureElement»): BSW-Ablaufentität; assoziiert über startsOnEvent [0..1] mit BswEvent.
  • AbstractEvent («Identifiable», abstrakt): Basis für Auslöseereignisse (RTEEvent, BswEvent).
  • CompositionSwComponentType (spezialisiert SwComponentType): Struktureller Kompositionskontext, auf den sich EOCs und Event Chains beziehen (baseComposition [0..1] bzw. base [0..1] {redefines atpBase}).
  • ComponentInCompositionInstanceRef («AtpInstanceRef»): Kontextualisiert die Instanz einer SW-C innerhalb einer Kompositionshierarchie.
Timing Constraints
  • ExecutionTimeConstraint (spezialisiert TimingConstraint):
    • Attribut: executionTimeType: ExecutionTimeTypeEnum [0..1].
    • Assoziation: executable [0..1] → ExecutableEntity.
  • ExecutionOrderConstraint (spezialisiert TimingConstraint):
    • Attribute:
      • executionOrderConstraintType: ExecutionOrderConstraintTypeEnum [0..1] (ordinaryEOC, hierarchicalEOC, repetitiveEOC),
      • isEvent: Boolean [0..1],
      • permitMultipleReferencesToEE: Boolean [0..1].
    • Assoziationen:
      • baseComposition [0..1] → CompositionSwComponentType,
      • Komposition orderedElement [0..*] → EOCExecutableEntityRefAbstract.
  • SynchronizationPointConstraint (spezialisiert TimingConstraint):
    • Synchronisiert Ausführungsketten.
    • Assoziationen:
      • executable [0..1] → ExecutableEntity,
      • sourceEec [0..*] → EOCExecutableEntityRefGroup,
      • targetEec [0..*] → EOCExecutableEntityRefGroup,
      • sourceEvent [0..*] → AbstractEvent,
      • targetEvent [0..*] → AbstractEvent.
EOC-Referenzstrukturen (EOCExecutableEntityRefAbstract & Subklassen)
  • EOCExecutableEntityRefAbstract («Identifiable», abstrakt):
    • Rekursive Assoziationen:
      • directSuccessor [0..*] → EOCExecutableEntityRefAbstract,
      • successor [0..*] → EOCExecutableEntityRefAbstract.
    • Spezialisierungen:
      • EOCExecutableEntityRef: Referenziert über Komposition component [0..1] → ComponentInCompositionInstanceRef und Assoziation executable [0..1] → ExecutableEntity.
      • EOCEventRef: Referenziert über Komposition component [0..1] → ComponentInCompositionInstanceRef und Assoziation event [0..1] → AbstractEvent.
      • EOCExecutableEntityRefGroup: Definiert geordnete Gruppen von Ablaufentitäten.
        • Attribute:
          • letDataExchangeParadigm: LetDataExchangeParadigmEnum [0..1],
          • maxCycleRepetitions: PositiveInteger [0..1],
          • maxSlotsPerCycle: PositiveInteger [0..1].
        • Assoziationen:
          • Komposition nestedElement [0..*] {ordered} → EOCExecutableEntityRefAbstract,
          • letInterval [0..*] → TimingDescriptionEventChain,
          • triggeringEvent [0..1] → TimingDescriptionEvent,
          • Komposition component [0..1] → ComponentInCompositionInstanceRef.
Timing Events & Enumerationen
  • TimingDescriptionEvent (TimingDescription): Zeitbeschreibungsereignis, das als Trigger (triggeringEvent [0..1]) für eine EOCExecutableEntityRefGroup dient.
  • ExecutionOrderConstraintTypeEnum: ordinaryEOC, hierarchicalEOC, repetitiveEOC.

3. Dynamisches Verhalten & Sequenzablauf

  1. Ausführungszeit-Definition: Eine ExecutionTimeConstraint referenziert über executable eine ExecutableEntity (BSW-Entity oder SWC-Runnable) und spezifiziert deren Ausführungszeit-Typ (executionTimeType).
  2. Reihenfolgen-Restriktionen (EOC): Eine ExecutionOrderConstraint bündelt über orderedElement eine Folge von Referenzen (EOCExecutableEntityRefAbstract). Die logische Ausführungsabfolge wird über gerichtete Abhängigkeiten (directSuccessor, successor) abgebildet.
  3. Hierarchische Strukturierung & LET: Über EOCExecutableEntityRefGroup werden Teilsequenzen hierarchisch gekapselt (nestedElement {ordered}). Anhand von Slot- und Wiederholungsparametern (maxSlotsPerCycle, maxCycleRepetitions) sowie dem Datenaustausch-Paradigma (letDataExchangeParadigm) werden Ausführungsmuster und LET-Intervalle (letInterval auf TimingDescriptionEventChain) definiert; die Gruppe kann durch ein dediziertes Trigger-Ereignis (triggeringEvent auf TimingDescriptionEvent) angestoßen werden.
  4. Synchronisation: Eine SynchronizationPointConstraint verknüpft Quell- und Ziel-Gruppen (sourceEec, targetEec) bzw. auslösende Ereignisse (sourceEvent, targetEvent) mit einer synchronisierenden ExecutableEntity, um Übergänge zwischen nebenläufigen Ablaufpfaden abzugleichen.

4. Normative Relevanz & Entwickler-Hinweise

  • Constraint-Kopplung: ExecutionOrderConstraint und ExecutionTimeConstraint verfeinern das Zeitverhalten auf Entitätsebene; Implementierer und Timing-Analysewerkzeuge müssen sicherstellen, dass EOC-Reihenfolgen zyklenfrei bleiben, sofern nicht explizit als repetitiveEOC typisiert.
  • RTE- und OS-Konfiguration: Die Verknüpfungen von RunnableEntity und BswModuleEntity über RTEEvent bzw. BswEvent dienen der konsistenten Generierung von OS-Tasks, Task-Abläufen und RTE-Schnittstellen.
  • Ereignisgestützte LET-Semantik: Die Gruppierung über EOCExecutableEntityRefGroup, die direkte Bindung an ein auslösendes Ereignis (triggeringEvent zu TimingDescriptionEvent) und die Anbindung an TimingDescriptionEventChain (letInterval) ermöglichen eine präzise Steuerung deterministischer Abläufe im Logical Execution Time-Modell.
