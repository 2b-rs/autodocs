1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Prozess- und Methoden-Diagramm nach dem SPEM 2.0-Metamodell (Software & Systems Process Engineering Metamodel), adaptiert für die AUTOSAR Methodology (Aktivitäts- bzw. Task-Sicht).
  • Technischer Zweck & Einordnung: Modellierung des Entwurfsschritts zur initialen Erzeugung oder inkrementellen Aktualisierung der System Flat Map auf Systemebene (AUTOSAR Classic Platform, Phase System Design). Die Flat Map dient der Auflösung hierarchischer Software-Kompositionsstrukturen (Component Prototypes, Ports, Data Elements) in einen globalen, flachen Namensraum. Sie ist die normative Voraussetzung für die konsistente Identifikation von Instanzelementen im RTE-Kontext sowie für Mess- und Kalibriersysteme (A2L/ASAP2 nach ASAM MCD-2 MC).

2. Komponenten, Entitäten & Schnittstellen

  • Akteur / Rolle:
    • System Engineer: Ausführende Entwicklungsrolle.
      • Beziehung: Assoziation «performs» zum zentralen Arbeitsschritt Generate or Adjust System Flat Map.
  • Aktivität (Task Definition):
    • Generate or Adjust System Flat Map: Methodischer Transformationsprozess (dargestellt als SPEM-Aktivitätspfeil). Liest Artefakte ein, aggregiert hierarchische Instanzen und schreibt/modifiziert die System-Flat-Map.
  • Eingangs-Artefakte (Work Products / Inputs):
    • System Description Root Element [1]: Definiert den Einstiegspunkt der Systemkonfiguration (AR-PACKAGE / SYSTEM), setzt den globalen Systemkontext und enthält Verweise auf Top-Level-Kompositionen. Stereotyp: «input».
    • VFB System [1]: Formale Repräsentation der virtuellen Funktionsbus-Architektur (Software Component Description auf Gesamtsystemebene inkl. hierarchischer Verknüpfungen der SwComponentPrototype-Instanzen). Stereotyp: «input».
    • **Partial Flat Map [0..*]:** Optionale, dezentral erstellte Teil-Flat-Maps aus Teilsystemen, Sub-Kompositionen oder von Software-Lieferanten (3rd-Party-SWC-Zulieferungen). Stereotyp: «input».
  • Ausgangs- / Übergabe-Artefakt (Inoutput):
    • System Flat Map [1]: Vollständige, konsolidierte Zuordnungstabelle aller flachen Instanzpfade (FlatInstanceDescriptor) des Gesamtsystems.
      • Beziehung: Assoziation mit Stereotyp «inoutput» (Kardinalität 1), was den idempotenten bzw. iterativen Lese-Änderungs-Schreib-Zugriff kennzeichnet (Adjust-Modus).

3. Dynamisches Verhalten & Sequenzablauf

  1. Trigger: Bereitstellung des konsolidierten VFB System und des System Description Root Element im System-Engineering-Workflow, bzw. Eintreffen modifizierter Software-Komponenten/Teilsysteme (Partial Flat Map).
  2. Pfad-Traversierung & Instanziierung: Das Tooling des System-Engineers traversiert die hierarchische Kompositionsstruktur des VFB ausgehend vom Root-Element rekursiv bis zu den atomaren Software-Komponenten (AtomicSwComponentType).
  3. Zusammenführung (Merge): Sofern Partial Flat Maps existieren (0..*), werden deren vordefinierte Kurznamen und Bezeichner integriert.
  4. Namenskollisionsauflösung & Identifier-Generierung: Eindeutige Generierung von Kurzbezeichnern (FlatInstanceDescriptor.shortName) für mehrfach instanziierte Komponenten (Multi-Instantiation).
  5. Inkrementelle Aktualisierung («inoutput»): Ist bereits eine System Flat Map vorhanden, werden bestehende Bezeichner stabil gehalten (Preservation of Measurement/Calibration Identifiers) und lediglich geänderte/ergänzte Substrukturen angepasst.

4. Normative Relevanz & Entwickler-Hinweise

  • RTE & BSW-Konfiguration:
    • Die System Flat Map ist bindende Eingabe für die spätere ECU-Extraktion (ECU Extract of System Description). Fehlt die Flat Map oder ist sie inkonsistent, schlägt die Ableitung der instanzspezifischen RTE-Header und der Zugriff auf RTE-interne Datenstrukturen fehl.
  • Kalibrierung & Diagnose (A2L / ASAM MCD):
    • Entwickler von kalibrierbaren Applikationen (CalibrationParameter, Characteristic) sind darauf angewiesen, dass die in der Flat Map hinterlegten flachen Pfade deterministisch sind. Ein unkontrolliertes Neugenerieren ohne den „Adjust“-Zyklus führt zu Namensbrüchen in bestehenden A2L-Dateien und entwertet Tool-Konfigurationen (z. B. INCA, CANape).
  • Zulieferkette (OEM / Tier-1):
    • Die Kardinalität 0..* für Partial Flat Map ermöglicht OEM-Tier-1-Workflows: Ein Subsystem-Lieferant kann seine vorkonfigurierten Flat-Mapping-Konventionen beistellen, die auf Systemebene übernommen werden müssen.
