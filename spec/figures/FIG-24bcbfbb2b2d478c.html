1. Diagrammtyp & Architektur-Kontext

UML-Klassendiagramm zur Spezifikation des Mappings von Service-Methoden auf Client-Server-Operationen im Rahmen der AUTOSAR-Manifest-Modellierung (Plattformübergang Adaptive Platform und Classic Platform).

2. Komponenten, Entitäten & Schnittstellen

Das Diagramm definiert folgende Metaklassen und Beziehungen:

  • InterfaceMapping (Spezialisierung von ARElement): Aggregiert über eine Komposition (Rolle +methodMapping, Multiplizität 0..*) Instanzen von MethodMapping.
  • MethodMapping (Spezialisierung von Identifiable): Referenziert über zwei gerichtete Assoziationen:
  • Rolle +clientServerOperation mit Multiplizität 0..1 auf ClientServerOperation.
  • Rolle +method mit Multiplizität 0..1 auf ClientServerOperation.
  • ClientServerInterface (Spezialisierung von PortInterface): Dargestellt als isoliertes Modellelement ohne Assoziationen.
  • ServiceInterface (Spezialisierung von PortInterface): Besitzt die Attribute + majorVersion: PositiveInteger [0..1] und + minorVersion: PositiveInteger [0..1] und enthält per Komposition («atpVariation», Rolle +method, Multiplizität 0..*) Elemente vom Typ ClientServerOperation.
  • ClientServerOperation (Spezialisierung von AtpStructureElement, Identifiable): Besitzt das Attribut + fireAndForget: Boolean [0..1].

3. Dynamisches Verhalten & Sequenzablauf

Statisches Metamodell ohne Verhaltens- oder Sequenzdiagrammelemente. Es beschreibt die deklarative Zuordnung auf Modellebene: Ein MethodMapping verknüpft eine Methode eines ServiceInterface mit einer ClientServerOperation eines ClientServerInterface über entsprechende Referenzen (+method und +clientServerOperation).

4. Normative Relevanz & Entwickler-Hinweise

  • Variabilitäts-Tags für die Komposition ServiceInterface.method: «atpVariation» mit den Tags atp.Status = draft, vh.latestBindingTime = blueprintDerivationTime und mmt.RestrictToStandards = AP.
  • InterfaceMapping fungiert als eigenständiges ARElement auf Root-Ebene.
