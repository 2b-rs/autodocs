1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Konzeptionelles Datenfluss- und Architekturmodell (Informations- und Synchronisationsfluss).
  • Funktionale Einordnung: Das Diagramm spezifiziert das Verteilungs- und Synchronisationsmodell für globale Zeitbasen (Global Time Base Distribution) im Synchronized Time Base Manager (StbM, AUTOSAR Classic R4.2.2). Der StbM entkoppelt als BSW-Systemdienst die Zeitkonsumenten (SW-Cs, SecOC, Dcm, RTE) von den bus-spezifischen Synchronisationsmodulen (CanTSyn, FrTSyn, EthTSyn) sowie der zugrundeliegenden Hardware-Zeitbasis (Gpt, Os-Counter, Ethernet-MAC-Timestamp-Units).

2. Komponenten, Entitäten & Schnittstellen

  • Knotenrollen & Domänen:
    • Time Master: Taktgebende Instanz, die die autoritative Zeit einer Time Domain generiert, lokal pflegt und über das Kommunikationsnetzwerk verteilt.
    • Time Slave: Taktnehmende Instanz, die ihre lokale Zeitbasis auf Basis empfangener Synchronisationsnachrichten an die Masterzeit anpasst.
    • Global Time Synchronized / Offset (blau): Logisches Zeitnetzwerk bzw. Time Domain auf dem Bus. Unterstützt direkt synchronisierte Zeitbasen (Synch) sowie abgeleitete Offset-Zeitbasen.
  • Interne Funktionsblöcke (je Knoten):
    • Time Base Reference Clock: Physische, kontinuierlich freilaufende Hardware- oder OS-Referenzuhr (z. B. GPT-Timerkanal, OS-Counter oder Hardware-Counter im Ethernet-Controller).
    • Global / Local Time Base Raw: Diskreter Rohzeitzähler, der direkt über Inkremente/Ticks der Referenzuhr gespeist und aktualisiert wird.
    • Time Stamp: Zeitstempel-Register/Capture-Einheit für Sende- (Egress) bzw. Empfangszeitpunkte (Ingress).
    • Global / Local Time Base per Time Domain (rot gerahmt): Normierte logische Zeitbasis (Sekunden, Nanosekunden, Statusbits), die dem Gesamtsystem je Time Domain bereitgestellt wird.
  • Schnittstellen & Interaktionspfade:
    • r/w access (Master): Bidirektionaler Zugriff via BSW/RTE (Lesen via StbM_GetCurrentTime(), Initialisieren/Aktualisieren via StbM_SetGlobalTime() / StbM_UpdateGlobalTime()).
    • read access (Slave): Ausschließlicher Lesezugriff via StbM_GetCurrentTime() für Applikationen/Module.
    • TimeSyncMsg: Übertragene Zeitsynchronisations-PDU über den jeweiligen Bus-Treiber (CanTSyn, FrTSyn, EthTSyn).
    • Blitz-Symbol: Asynchrones Erfassungsereignis (Hardware-Timestamping / Interrupt bei Sende- bzw. Empfangszeitpunkt der PDU).
    • init / update: Steuerpfade zur Initialisierung der Hardware-Uhr bzw. zyklischen Abfrage von Ticks zur Extrapolation der Rohzeit.
    • $\oplus$ (Summationsstelle am Slave): Differenzbildung und Korrekturrechnung (Offset-/Ratenkorrektur) zwischen externem Master-Zeitstempel und lokalem Rohzeitstempel.

3. Dynamisches Verhalten & Sequenzablauf

Time Master (Sende- und Fortschreibepfad)
  1. Initialisierung & Freilauf: Global Time Base Raw initialisiert (init) die Time Base Reference Clock. Zyklische Ticks aktualisieren (update) fortlaufend die Rohzeit und darüber die Global Time Base per Time Domain.
  2. Master-Zeiteinspeisung: Eine autoritative Quelle (z. B. GPS, Diagnose oder interne Systemzeit) aktualisiert die Master-Zeitbasis über den r/w access-Pfad.
  3. Egress-Timestamping & Dispatch:
    • Der Versand der TimeSyncMsg wird angestoßen.
    • Beim Verlassen des Controllers wird der Sendezeitstempel (Time Stamp) exakt erfasst (Trigger via Blitz-Symbol).
    • Die Synchronisationsinformation wird über das Bussystem übertragen.
Time Slave (Empfangs- und Korrekturpfad)
  1. Ingress-Timestamping: Das Eintreffen der TimeSyncMsg löst den Trigger (Blitz-Symbol) aus und erzeugt einen präzisen Empfangs-Time Stamp.
  2. Kompensation & Korrektur ($\oplus$): Der empfangene Master-Zeitstempel wird mit dem lokalen Empfangs-Zeitstempel verrechnet (Kompensation von Signallaufzeit und Berechnen des Offsets).
  3. Aktualisierung der Rohzeitbasis: Das Korrekturergebnis fließt in die Local Time Base Raw ein.
  4. Interpolation (Zwischenintervall): Zwischen zwei Synchronisationsnachrichten treibt die lokale Time Base Reference Clock die Rohzeit via update kontinuierlich voran.
  5. Bereitstellung: Die extrapolierte, synchronisierte Zeit wird in Local Time Base per Time Domain aktualisiert und steht dem System über read access synchron zur Verfügung.

4. Normative Relevanz & Entwickler-Hinweise

  • API-Restriktionen:
    • Auf Slaves führt ein Schreibaufruf (StbM_SetGlobalTime()) zu einem Fehler (STBM_E_PARAM / Det-Eintrag); der Zugriff ist strikt auf Leseoperationen beschränkt.
    • Zeitkonsumenten müssen zwingend den Rückgabewert und das Statusbyte (StbM_TimeStampType.timeBaseStatus) prüfen (z. B. TIMEOUT, GLOBAL_TIME_BASE), um abgelaufene oder unpräzise extrapolierte Zeiten bei Busausfall zu erkennen.
  • Konfigurationsaspekte (StbM / TSyn):
    • Rollenverteilung: StbMIsSystemWideMaster definiert, ob der Knoten als Master fungiert.
    • Referenzuhr-Mapping: StbMLocalTimeHardware bindet den StbM an einen konkreten GPT-Kanal oder OS-Counter.
    • Offset-Zeitbasen: Werden über StbMOffsetTimeBaseId konfiguriert; sie teilen sich die Synchronisation der Basis-Domain, besitzen jedoch einen statischen oder dynamischen Offset.
  • Jitter & Latenzkompensation:
    • Das Blitz-Symbol verdeutlicht die Notwendigkeit von Hardware-Timestamping (insbesondere bei Ethernet/IEEE 802.1AS via EthTSyn). Software-basierte Interrupt-Zeitstempel unterliegen Scheduling-Jitter und verletzen bei engen Toleranzen die geforderte Genauigkeitsklasse.
