1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: AUTOSAR ECU Configuration Parameter Definition (ECUC-Metamodell), visualisiert als UML-Klassendiagramm.
  • Architektur-Kontext: Spezifiziert die Konfigurationsstruktur des Moduls Firewall (AUTOSAR Classic Platform, AUTOSAR_CP_SWS_Firewall, R23-11) für die sicherheitsrelevante Ereignismeldung an den Intrusion Detection System Manager (IdsM).
  • Technischer Zweck: Ermöglicht das statische Mapping protokollspezifischer Paketverwerfungen (Packet Drops aufgrund von Regelsatz-Verletzungen auf Layer 2 bis Layer 7) auf standardisierte Sicherheitsereignisse (IdsMEvent) des Intrusion Detection Frameworks.

2. Komponenten, Entitäten & Schnittstellen

  • FirewallSecurityEventRefs (EcucParamConfContainerDef):
  • Multiplizität: [0..1].
  • Optionaler Konfigurations-Container innerhalb der Firewall-Parameterdefinition zur Aggregation sämtlicher Security-Event-Referenzen.
  • Referenzdefinitionen (EcucReferenceDef via Komposition +reference):
  • Jede Referenz besitzt die Kardinalität lowerMultiplicity = 0, upperMultiplicity = 1 und die Eigenschaft requiresSymbolicNameValue = true.
  • Datalink Layer:
  • SEV_FW_PACKET_BLOCKED_DATALINKLAYER_MISMATCH: Verwerfung aufgrund von MAC-Adress- oder VLAN-Filterregeln (Layer 2).
  • Network Layer:
  • SEV_FW_PACKET_BLOCKED_IPV4_MISMATCH: Verwerfung bei IPv4-Header- oder Adressfilter-Verletzung.
  • SEV_FW_PACKET_BLOCKED_IPV6_MISMATCH: Verwerfung bei IPv6-Header- oder Adressfilter-Verletzung.
  • SEV_FW_PACKET_BLOCKED_ICMP_MISMATCH: Verwerfung unzulässiger ICMP/ICMPv6-Nachrichten.
  • Transport Layer:
  • SEV_FW_PACKET_BLOCKED_UDP_MISMATCH: Verwerfung unberechtigter UDP-Ports oder -Längenangaben.
  • SEV_FW_PACKET_BLOCKED_TCP_MISMATCH: Verwerfung bei TCP-Port-Mismatch oder unzulässigen TCP-Flags/State-Verletzungen.
  • Application / Middleware Layer:
  • SEV_FW_PACKET_BLOCKED_SOMEIP_MISMATCH: Verletzung von SOME/IP-Header-Parametern (z. B. Message-ID, Request/Response-Zuordnung).
  • SEV_FW_PACKET_BLOCKED_SOMEIPSD_MISMATCH: Unzulässige SOME/IP Service Discovery-Einträge oder -Optionen.
  • SEV_FW_PACKET_BLOCKED_DDS_MISMATCH: Regelverletzung bei Data Distribution Service-Nachrichten.
  • SEV_FW_PACKET_BLOCKED_DOIP_MISMATCH: Unerlaubte Diagnostic over IP Header, Routing-Activation- oder Payload-Typen.
  • SEV_FW_PACKET_BLOCKED_GENERIC_MISMATCH: Verwerfung durch frei definierbare / generische Nutzdaten-Filterregeln.
  • IdsMEvent (EcucParamConfContainerDef, Zielknoten via +destination):
  • Paketursprung: (from IdsM).
  • Multiplizität im Gesamtsystem: [1..65535].
  • Externer BSW-Container des Moduls IdsM, welcher die globalen Security Event IDs zur Generierungs- und Laufzeit bereitstellt.

3. Dynamisches Verhalten & Sequenzablauf

  • Trigger: Die Firewall-Engine inspiziert ein PDU/Paket im Ingress- oder Egress-Pfad und stellt eine Diskrepanz zu den konfigurierten Firewall-Regeln fest.
  • Aktion & Filterentscheidung: Das Paket wird verworfen (DROP/BLOCK).
  • Ereignismeldung:
  • Sofern die entsprechende Protokoll-Referenz konfiguriert ist (Multiplicity = 1), löst die Firewall-Laufzeitumgebung einen synchronen Aufruf an die IdsM-API aus:

IdsM_SetSecurityEvent(SecurityEventId, ContextData, ContextDataLength).

  • Als SecurityEventId wird der aus dem Zielcontainer IdsMEvent generierte symbolische Bezeichner übergeben.
  • Die Firewall übergibt protokollspezifische Kontextdaten (z. B. Header-Auszug, verletzte Rule-ID, Quell-/Zieladressen) zur forensischen Analyse.
  • Abbruch-/Bypass-Bedingung: Ist die jeweilige Referenz nicht konfiguriert (Multiplicity = 0), wird das Paket stillschweigend verworfen; es erfolgt kein IdsM-API-Aufruf (Unterdrückung von Event-Overhead).

4. Normative Relevanz & Entwickler-Hinweise

  • Code-Generierung & Typsicherheit: Durch requiresSymbolicNameValue = true muss der Konfigurations-Generator die im IdsM definierten symbolischen C-Makros (z. B. IdsMConf_IdsMEvent_<Name>) auflösen und in Firewall_Cfg.h als Typ IdsM_SecurityEventIdType bereitstellen.
  • Granulare DoS- und Quota-Prävention: Da jede Referenz isoliert aktivierbar ist ([0..1]), können Integratoren unkritische Schichten deaktivieren, um den internen Ringpuffer des IdsM bei Flooding-Angriffen (z. B. UDP- oder ICMP-Stürme) vor Überlauf zu schützen.
  • Intermodulare Abhängigkeit: Ein valider EcuExtract/ECUC-Datensatz setzt voraus, dass bei gesetzter Firewall-Security-Event-Referenz das IdsM-Modul vollständig konfiguriert und instantiiert ist. Fehlende Ziel-Container (IdsMEvent) führen zu unauflösbaren Referenzfehlern während der Generierungsphase.
