1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Klassendiagramm zur Spezifikation des AUTOSAR ECUC-Konfigurationsmetamodells (ECU Configuration Parameter Definition).
  • Technischer Zweck: Definition der globalen, transceiverspezifischen Basisparameter (CanTrcvGeneral) für den BSW-Treiber CanTrcv (CAN Transceiver Driver) gemäß AUTOSAR Classic Platform (Release R23-11).
  • Funktionale Einordnung: Der CanTrcv-Treiber abstrahiert die hardwarenahe Ansteuerung des CAN-Transceivers (Standby-, Sleep-, Normal-Modi, Wake-Up-Erkennung, Bus-Diagnose via I/O oder SPI) gegenüber dem CanIf (CAN Interface). Der Container CanTrcvGeneral steuert globale Pre-Compile-Schalter, Timer-Mechanismen, Scheduler-Perioden sowie die Multi-Core-/Partitionierungs-Zuweisung.

2. Komponenten, Entitäten & Schnittstellen

Zentraler Container

    • Kardinalität: [1..1] (obligatorischer Singleton-Container je CAN-Transceiver-Modulkonfiguration).
Parameter (+parameter-Kompositionen)
  • CanTrcvDevErrorDetect (EcucBooleanParamDef):
    • Multiplizität: [1..1], defaultValue = false. Schaltet DET-Fehlerüberwachung (CanTrcv_ReportError) zur Compile-Zeit aktiv/inaktiv.
  • CanTrcvVersionInfoApi (EcucBooleanParamDef):
    • Multiplizität: [1..1], defaultValue = false. Steuert die Verfügbarkeit der API CanTrcv_GetVersionInfo().
  • CanTrcvIndex (EcucIntegerParamDef):
    • Multiplizität: [1..1], Wertebereich: 0 … 255, withAuto = true. Eindeutige Treiber-Instanz-ID zur Identifikation bei multiplen Transceiver-Treibern.
  • CanTrcvWakeUpSupport (EcucEnumerationParamDef):
    • Multiplizität: [1..1]. Legt die globale Wake-Up-Fähigkeit fest.
    • Literale (+literal): CANTRCV_WAKEUP_BY_POLLING, CANTRCV_WAKEUP_NOT_SUPPORTED.
  • CanTrcvMainFunctionPeriod (EcucFloatParamDef):
    • Multiplizität: [0..1], Wertebereich: 0 … ∞ (Sekunden). Zykluszeit für CanTrcv_MainFunction() (relevant bei Polling).
  • CanTrcvMainFunctionDiagnosticsPeriod (EcucFloatParamDef):
    • Multiplizität: [0..1], Wertebereich: 0 … ∞ (Sekunden). Zykluszeit für CanTrcv_MainFunctionDiagnostics() zur zyklischen Zustands-/Fehlerüberwachung.
  • CanTrcvTimerType (EcucEnumerationParamDef):

    • Literale (+literal): None, Timer_1us16bit.
  • CanTrcvWaitTime (EcucFloatParamDef):
    • Multiplizität: [0..1], Wertebereich: 0.0 … 0.000255\,s ($0 \dots 255\,\mu\text{s}$). Maximale Hardware-Einschwing-/Wartezeit für Zustandswechsel des Transceivers.

3. Dynamisches Verhalten & Sequenzablauf

Als statisches Konfigurationsmodell definiert das Diagramm keine direkten Laufzeitsequenzen, determiniert jedoch die BSW-Scheduler-Integration und das Treiberverhalten:

[BswM / OS Scheduler]
       |
       +---> (alle CanTrcvMainFunctionPeriod) -----------> CanTrcv_MainFunction()
       |                                                         |
       |                                                         +-> Polling Wake-Up / Pin-Events
       |
       +---> (alle CanTrcvMainFunctionDiagnosticsPeriod) --> CanTrcv_MainFunctionDiagnostics()
                                                                 |
                                                                 +-> Status- & Fehlerregister lesen
  • Zyklische Trigger:
    • Ist CanTrcvWakeUpSupport == CANTRCV_WAKEUP_BY_POLLING konfiguriert, muss CanTrcvMainFunctionPeriod gesetzt sein; der BswM/SchM triggert periodisch CanTrcv_MainFunction() zur Wake-Up-Erkennung.
    • Ist CanTrcvMainFunctionDiagnosticsPeriod definiert, wird CanTrcv_MainFunctionDiagnostics() synchron vom BSW-Scheduler aufgerufen, um Fehlerbits (z. B. Bus-Failure, Over-Temperature) aus dem Transceiver via SPI/GPIO auszulesen und an Dem/CanIf zu melden.
  • Wartezeiten bei Moduswechseln:
    • Nach Anforderung eines Moduswechsels (CANTRCV_TRCVMODE_NORMAL, STANDBY, SLEEP) blockiert die Ausführung für maximal CanTrcvWaitTime. Die Zeitbasis wird hardwarespezifisch über CanTrcvTimerType aufgelöst (Timer_1us16bit nutzt einen 16-Bit-Timer mit 1-μs-Auflösung, None greift auf Software-Schleifen oder asynchrone Bestätigung zurück).

4. Normative Relevanz & Entwickler-Hinweise

  • Code-Generierung & Footprint (Pre-Compile):
    • CanTrcvDevErrorDetect == false eliminiert sämtliche DET-Prüfungen an den API-Eingängen (CANTRCV_E_UNINIT, CANTRCV_E_PARAM_INVALID), was Latenzen und Flash-Footprint minimiert.
    • CanTrcvVersionInfoApi == false entfernt das Makro/die Funktion CanTrcv_GetVersionInfo().
  • ECUC_CanTrcv_00173 (CanTrcvWaitTime & CanTrcvTimerType):
    • Beschränkt die Einschwingzeit strikt auf max. $255\,\mu\text{s}$. Konfiguriert der Integrator Timer_1us16bit, muss die MCAL-/Plattformschicht einen synchronen 1-μs-Tick bereitstellen. Ein fehlerhafter Wert führt zu unvollständigen Modusübergängen oder Blockaden des aufrufenden Kontexts (CanIf).
  • ECUC_CanTrcv_00175 (CanTrcvEcucPartitionRef):
    • Notwendig für Multi-Core- und Safety-Partitionierung (ASIL/QM-Split). Wird die Referenz gesetzt, darf der Treiber nur aus den referenzierten Partitionen aufgerufen werden; Inter-Partition-Aufrufe müssen über SchM/BswM-Satelliten entkoppelt werden.
  • BswM- und RTE-Mapping:
    • Fehlen CanTrcvMainFunctionPeriod oder CanTrcvMainFunctionDiagnosticsPeriod ([0..1]), generiert der BSW-Generator die entsprechenden Scheduled-Entities nicht; ein rein interrupt- oder zustandsgesteuerter Transceiver-Betrieb wird erzwungen.
