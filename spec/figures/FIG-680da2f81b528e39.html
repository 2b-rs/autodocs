  • Architektur-Kontext: Bestandteil der AUTOSAR Classic Platform E2E Communication Protection Library (AUTOSAR_CP_SWS_E2ELibrary, Release R25-11). Die Bibliothek ist auf dem BSW Service Layer angesiedelt und wird synchron von Treibern, Zwischenschichten (wie dem E2E Transformer E2EXf, dem PDU-Router / COM) oder direkt von Safety-relevanten SW-Cs genutzt.

Sie dient der standardisierten Kapselung von Protokoll-Steuerdaten für das E2E-Profil 05 (unterstützt Anforderungen RS_E2E_08528 zur Erkennung von Datenverfälschung/Reihenfolgefehlern und RS_E2E_08534 für getrennte bzw. modular serialisierte Header-Metadaten).

3. Dynamisches Verhalten & Sequenzablauf

Obgleich es sich um eine statische Typdefinition handelt, unterliegt die Struktur folgenden deterministischen Abläufen im E2E-Stack:

  • Sender-Pfad (E2E_P05Protect / Header-Generierung):
    1. Der Aufrufer (z. B. E2EXf_Transform) übergibt oder instanziiert die Struktur.
    2. Der SequenceCounter wird dem aktuellen Sende-Zustand (E2E_P05ProtectStateType->Counter) entnommen und in das Struct bzw. die PDU geschrieben.
    3. Pro Aufruf/Sendezyklus erfolgt ein zyklisches Inkrementieren modulo 256 (Counter = (Counter + 1) % 256).
  • Empfänger-Pfad (E2E_P05Check / Header-Extraktion):
    1. Der 8-Bit-Zähler wird aus dem Datenstrom / Header in E2E_P05HeaderInformationType->SequenceCounter deserialisiert.
    2. Prüfung der Differenz ($\Delta$) zwischen empfangenem Zähler und LastValidCounter des Empfänger-Zustands gegen das konfigurierte Limit (MaxDeltaCounter).
    3. Ermittlung des Prüfstatus (E2E_P05_STATUS_OK, E2E_P05_STATUS_REPEATED, E2E_P05_STATUS_WRONGSEQUENCE).
  • Synchronität & Fehler-Pfade:
    • Rein synchrone, blockierungsfreie und reentrante Bibliotheksausführung.
    • Keine internen OS-Events, Queues oder Puffer.
    • Keine direkten DET/DEM-Aufrufe innerhalb der E2E-Library; Schnittstellenfehler (z. B. Null-Pointer) werden unmittelbar per synchronem Funktionsrückgabewert (E2E_E_INPUTERR_NULL) an den Aufrufer propagiert.

4. Normative Relevanz & Entwickler-Hinweise

  • C-Implementierungsvorgabe (E2E_P05.h): 
    typedef struct {
    uint8 SequenceCounter;
} E2E_P05HeaderInformationType;
  • Memory & Alignment:
    • Netto-Größe: 1 Byte.
    • Bei Einbettung in Transformer-Deskriptoren oder Aufruf-Stacks ist compiler-spezifisches Struct-Padding bzw. Alignment zu beachten (insbesondere auf 32-/64-Bit-Architekturen), wenn Strukturen als Puffer weitergereicht werden.
  • Wrap-Around-Handhabung:
    • Entwickler müssen sicherstellen, dass der zyklische Überlauf von 0xFF auf 0x00 nicht als fehlerhafte Sequenz interpretiert wird. Die Bibliotheksfunktionen bilden dies über modulare Arithmetik ab.
  • Trennung von Data ID und Header:
    • Das E2E-Profil 05 nutzt eine 16-Bit Data ID (uint16), die jedoch nicht explizit im Header übertragen, sondern rein als Bestandteil der 16-Bit-CRC-Berechnung (Polynom 0x1021, Startwert 0xFFFF) verwendet wird. Daher enthält E2E_P05HeaderInformationType normativ ausschließlich den SequenceCounter.
  • ASIL-Konformität:
    • E2E-Bibliotheksstrukturen genügen ASIL D. Übergabe-Pointer müssen stets auf Gültigkeit geprüft werden, um Speicherschutzverletzungen (MPU-Traps) im BSW-Kontext zu vermeiden.
