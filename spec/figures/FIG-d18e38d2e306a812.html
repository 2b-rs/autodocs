1. Diagrammtyp & Architektur-Kontext

UML-Objekt- bzw. Instanzendiagramm zur Spezifikation der AUTOSAR Adaptive und Classic Platform (Software Component Template). Das Diagramm illustriert das Zusammenspiel zwischen anwendungsbezogener Typdefinition (ApplicationPrimitiveDataType), implementationsbezogener Struktur (ImplementationDataType), Speicheranordnung (SwRecordLayout) und Kalibrierungsachsen-Metadaten (SwAxisIndividual innerhalb von SwCalprmAxisSet) für eine Gruppenachse (COM_AXIS).

2. Komponenten, Entitäten & Schnittstellen

  • :ApplicationPrimitiveDataType: Anwendungs-Datentyp mit shortName = ComAxis1 und category = COM_AXIS.
  • :DataTypeMap: Verbindet ApplicationPrimitiveDataType (+applicationDataType) mit dem Implementierungsdatentyp (+implementationDataType).
  • element :ImplementationDataType: Array-Datentyp mit shortName = uint8_noOfAxisPts_Distr_u8 und category = ARRAY. Aggregiert subElement :ImplementationDataTypeElement.
  • subElement :ImplementationDataTypeElement: Array-Element mit shortName = uint8_noOfAxisPts_Distr_u8, category = TYPE_REEFRENCE und arraySize = noOfAxisPts+1. Referenziert via +implementationDataType den Basistyp :ImplementationDataType.
  • :ImplementationDataType (Ziel von +implementationDataType): Werttyp mit shortName = uint8 und category = VALUE, verknüpft mit :SwBaseType über +baseType.
  • :SwBaseType: Plattform-Basistyp mit category = FIXED_LENGTH und shortName = uint8.
  • :SwDataDefProps: Datendefinitionseigenschaften am ApplicationPrimitiveDataType, aggregiert :SwCalprmAxisSet und referenziert :SwRecordLayout über +swRecordLayout.
  • :SwCalprmAxisSet: Aggregiert Achseneigenschaften :SwAxisIndividual.
  • :SwAxisIndividual: Achsendefinition mit category = COM_AXIS, swAxisIndex = 1, swMaxAxisPoints = noOfAxisPts und swMinAxisPoints = noOfAxisPts.
  • :SwRecordLayout: Record-Layout mit shortName = Distr_u8. Aggregiert ein :SwRecordLayoutV für den Achsenpunktzähler sowie eine :SwRecordLayoutGroup.
  • :SwRecordLayoutV (Zähler): swRecordLayoutVAxis = 1, shortLabel = N, swRecordLayoutVProp = COUNT, typisiert über +baseType auf :SwBaseType. Abgebildet auf das Element 0 des Arrays (+0 element, annotiert mit Notiz: First array element holds the number of samples.).
  • :SwRecordLayoutGroup: Gruppe mit swRecordLayoutGroupAxis = 1, shortLabel = X, category = INDEX_INCR, swRecordLayoutGroupFrom = 1, swRecordLayoutGroupTo = -1. Aggregiert :SwRecordLayoutV für Achsenwerte.
  • :SwRecordLayoutV (Werte): swRecordLayoutVAxis = 1, swRecordLayoutVProp = VALUE, typisiert über +baseType auf :SwBaseType. Abgebildet auf die Array-Elemente 1 bis n (+1..n element).

3. Dynamisches Verhalten & Sequenzablauf

Statisches Datenmodell ohne dynamische Ablauf- oder Sequenzpfade. Das Diagramm beschreibt das statische Mapping eines eindimensionalen Arrays auf Speicher- und Kalibrierstrukturen: Das Index-Element 0 (+0 element) repräsentiert die Anzahl der Stützstellen (COUNT, Label N), während die nachfolgenden Indizes 1 bis n (+1..n element) die eigentlichen Achsenwerte (VALUE, Label X) in aufsteigender Indexfolge (INDEX_INCR) aufnehmen.

4. Normative Relevanz & Entwickler-Hinweise

Für eine Gruppenachse (COM_AXIS) mit noOfAxisPts Stützstellen muss das zugrundeliegende Array eine Dimension von noOfAxisPts + 1 aufweisen. Entwickler und Generatoren müssen sicherstellen, dass die Speicherabbildung (SwRecordLayout) exakt mit der Struktur des ImplementationDataType korrespondiert: Das erste Feldelement dient der Ablage der Stützstellenanzahl (COUNT), die restlichen Feldelemente der Ablage der Achsenwerte (VALUE). Beide Teilkomponenten referenzieren denselben SwBaseType (uint8).
