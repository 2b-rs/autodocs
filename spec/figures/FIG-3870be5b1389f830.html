1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Zustandsdiagramm (State Machine Diagram / Zustandsautomat).
  • Architektur-Kontext: AUTOSAR Classic Platform, Basic Software (BSW), System Services – Diagnostic Event Manager (Dem) gemäß Release 4.3.1.
  • Technischer Zweck: Formale Definition des Lebenszyklus und der Übergangslogik von Bit 2 (pendingDTC) des UDS-Statusbytes (DTCStatusByte gemäß ISO 14229-1 / AUTOSAR Dem). Es steuert, wann ein Fehler als im aktuellen oder unmittelbar vorangegangenen Operationszyklus aufgetreten gilt.

2. Komponenten, Entitäten & Schnittstellen

  • Zustände (States):
    • Initial state: Pseudo-Zustand beim Hochlauf / Kaltstart vor Evaluierung persistierter NvM-Daten.
    • PendingDTC = FALSE (Bit 2 = 0): Kein anstehender Fehler im aktuellen/letzten Operationszyklus.
    • PendingDTC = TRUE (Bit 2 = 1): Fehler im aktuellen bzw. vorherigen Operationszyklus mindestens einmal als FAILED gemeldet.
  • Schnittstellen & Service-APIs:
    • Event-Reporting (SW-C / BSW an Dem):
      • Dem_SetEventStatus(EventId, EventStatus) (Synchrone Service-API via RTE/BSW).
      • Dem_ReportErrorStatus(EventId, EventStatus) (API für BSW-Treiber).
      • Relevante Parameterwerte: DEM_EVENT_STATUS_FAILED, DEM_EVENT_STATUS_PASSED.
    • Operationszyklus-Management:
      • Dem_SetOperationCycleState(OperationCycleId, CycleState) mit DEM_CYCLE_STATE_END bzw. DEM_CYCLE_STATE_RESTART (z. B. getriggert durch EcuM/BswM oder Fahrzyklus-Signale).
    • Diagnosedienst UDS 0x14 (Clear Diagnostic Information):
      • Dem_<...>ClearDTC(DTC, DTCFormat, DTCOrigin) (z. B. Dem_ClearDTC via Dcm).
  • Interne Status-Flags & Flags des UDS-Statusbytes:
    • TestFailedThisOperationCycle (Bit 1): Zeigt an, ob im laufenden Zyklus bereits ein Fehler aufgetreten ist.
    • TestNotCompletedThisOperationCycle (Bit 6): Zeigt an, ob das Diagnosetestsystem im laufenden Zyklus vollständig durchlaufen wurde.
    • FaultRecordOverwritten: Internes Ereignis des Dem-Event-Memory (Verdrängungs-/Aging-Mechanismus bei Speicherüberlauf).

3. Dynamisches Verhalten & Sequenzablauf

  • Initialisierung:
    • Übergang von Initial state nach PendingDTC = FALSE bei Systeminitialisierung (Dem_Init), sofern kein unquittierter Pending-Zustand im NvM vorliegt.
  • Transition FALSE → TRUE (Setzen von Bit 2):
    • Trigger: Aufruf von Dem_SetEventStatus oder Dem_ReportErrorStatus mit EventStatus = DEM_EVENT_STATUS_FAILED (nach Durchlaufen des eventuellen internen Debouncings).
    • Self-Loop TRUE: Weitere FAILED-Meldungen belassen den Zustand in PendingDTC = TRUE.
  • Transition TRUE → FALSE (Rücksetzen von Bit 2):
    • Erfolgt über drei disjunkte Pfade (OR-Verknüpfung):
      1. Erfolgreicher Zyklusabschluss ohne Fehler:
        • Bedingung: NOT TestFailedThisOperationCycle AND NOT TestNotCompletedThisOperationCycle
        • Trigger: Dem_SetOperationCycleState(OperationCycleId, DEM_CYCLE_STATE_END | DEM_CYCLE_STATE_RESTART).
        • Bedeutung: Der Diagnosetest lief im Zyklus komplett durch (Bit 6 == 0) und hat zu keinem Zeitpunkt gefehlt (Bit 1 == 0).
      2. Diagnose-Löschbefehl:
        • Trigger: Dem_<...>ClearDTC(DTC, DTCFormat, DTCOrigin) (UDS-Service 0x14).
      3. Speicherverdrängung (Aging/Displacement):
        • Trigger: FaultRecordOverwritten – Wenn ein Event-Memory-Eintrag aufgrund von Prioritäts- oder Verdrängungsregeln durch ein höher priorisiertes Event überschrieben wird.
  • Self-Loop FALSE:
    • Meldungen mit EventStatus = DEM_EVENT_STATUS_PASSED belassen den Zustand in PendingDTC = FALSE.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Zuordnung:
    • Implementiert die Anforderungen SWS_Dem_00006, SWS_Dem_00389, SWS_Dem_00390, SWS_Dem_00391 und SWS_Dem_01183 zur Einhaltung von ISO 14229-1 (UDS Service 0x19 / ReadDTCInformation) und OBD-II/WWH-OBD.
  • Zyklusabhängigkeit & Entprellung (Debounce):
    • Bit 2 wird erst aktiv, wenn der Qualifizierungsalgorithmus (zeit- oder zählerbasiertes Debounce im Dem oder anwendungsintern) den Status FAILED erreicht hat.
  • Kein direktes Löschen durch PASSED im selben Zyklus:
    • Ein Aufruf von DEM_EVENT_STATUS_PASSED setzt PendingDTC nicht unmittelbar auf FALSE zurück, wenn im selben Zyklus zuvor ein FAILED auftrat (TestFailedThisOperationCycle verhindert den Reset am Zyklusende).
  • Auswirkung auf SW-C- und Systementwickler:
    • Ein fehlerfreier Zyklus reicht zum Löschen von Bit 2 nur aus, wenn die Monitor-Funktion aktiv ausgeführt wurde (TestNotCompletedThisOperationCycle == 0). Monitore, die durch Deaktivierungsbedingungen (Enable Conditions) nicht gelaufen sind, verhindern das Löschen von PendingDTC.
  • NvM-Persistenz:
    • Tritt ein CycleState = DEM_CYCLE_STATE_END auf, muss der Dem-Status gemäß Konfiguration (DemStatusBitHandlingTestFailedSinceLastClear, DemNvRamBlockId) nicht-flüchtig im NvM gesichert werden, um den Pending-Status über Klemme-15-Zyklen (Power-Off/On) hinweg normkonform zu halten.
