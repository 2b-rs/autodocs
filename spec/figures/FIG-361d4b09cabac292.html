1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Objektdiagramm (Instanziierungs- bzw. Konfigurationsbeispiel des AUTOSAR System Template Metamodells für Global Time Synchronization gem. AUTOSAR_TPS_SystemTemplate).
  • Funktionaler Kontext: Modellierung hierarchischer und clusterübergreifender Zeitdomänen im System-Description-ARXML. Dargestellt ist die Kopplung einer synchronisierten Basiszeitdomäne (Synchronized Time Domain) mit einer abgeleiteten Offset-Zeitdomäne (Offset Time Domain) über heterogene Bussysteme (FlexRay und CAN) unter Verwendung eines Time-Gateways.
  • BSW-Einordnung: Dient als Entwurfsbasis für die Konfiguration des Synchronized Time-Base Managers (StbM) sowie der bussyndizierten Zeitsynchronisationsmodule FrTSyn und CanTSyn.

2. Komponenten, Entitäten & Schnittstellen

Entitäten & Instanzen
  1. Globale Zeitdomänen (Wurzelknoten & Subdomänen):
    • TimeDomain: GlobalTimeDomain (domainId = 1, category = SYNCHRONIZED): Globale synchronisierte Basis-Zeitdomäne.
      • Enthält Subdomänen per Komposition +globalTimeSubDomain: sub11, sub12, sub21 (jeweils domainId = 1, category = SYNCHRONIZED), die physikalischen Netzwerkclustern zugeordnet sind.
    • TimeDomainOffset: GlobalTimeDomain (domainId = 16, category = OFFSET): Abgeleitete Offset-Zeitdomäne.
      • Referenziert TimeDomain über die Assoziation +offsetTimeBase.
      • Enthält Subdomänen per Komposition +globalTimeSubDomain: sub51 (FlexRay-Cluster) und sub52 (CAN-Cluster), beide mit domainId = 16, category = OFFSET.
  2. Cluster-Kopplung der Subdomänen:
    • sub51 referenziert sub11 via +offsetTimeBase.
    • sub52 referenziert sub12 via +offsetTimeBase.
  3. Knotenrollen in sub51 (FlexRay-Cluster):
    • TM51: GlobalTimeFrMaster:
      • Aggregation via Komposition (+globalTimeMaster).
      • Attribut: isSystemWideGlobalTimeMaster = true (ursprüngliche Zeitquelle der Offset-Domäne 16 im Gesamtfahrzeug).
    • :GlobalTimeFrSlave: Generischer FlexRay-Zeitslave (Komposition +slave).
    • TS5: GlobalTimeFrSlave: FlexRay-Zeitslave des Gateway-Steuergeräts (Komposition +slave).
  4. Knotenrollen in sub52 (CAN-Cluster):
    • TM52: GlobalTimeCanMaster:
      • Aggregation via Komposition (+globalTimeMaster).
      • Attribut: isSystemWideGlobalTimeMaster = false (reagiert als lokaler Master, der seine Zeit aus dem Gateway bezieht).
    • :GlobalTimeCanSlave: Generischer CAN-Zeitslave (Komposition +slave).
    • TG5: GlobalTimeGateway:
      • Aggregation via Komposition (+gateway).
      • Besitzt Assoziation +slave auf TS5: GlobalTimeFrSlave (Zeitsynchronisations-Quelle / Ingress).
      • Besitzt Assoziation +master auf TM52: GlobalTimeCanMaster (Zeitsynchronisations-Senke / Egress).

3. Dynamisches Verhalten & Sequenzablauf

Die Verteilung der Zeitbasis folgt einer hierarchischen Kaskadierung über Domänen- und Clustergrenzen:

  1. Berechnung der Offset-Zeit:
    • Der System-Master TM51 ermittelt die Zeit der Domäne 16, indem er auf die lokale Zeitbasis der synchronisierten Basisdomäne (sub11, domainId = 1) einen definierten Offset aufschlägt ($t_{Offset} = t_{Sync} + \Delta t$).
  2. FlexRay-Zeittransfer (Master → Slaves):
    • TM51 sendet Synchronisations- und Offset-Botschaften (SYNC/FUP/OFFS) zyklisch über den FlexRay-Bus.
    • Alle Slaves des Clusters (darunter TS5) empfangen die Frames und synchronisieren ihre lokale Instanz von Domäne 16.
  3. Gateway-Routing (FlexRay → CAN):
    • TS5 meldet die aktualisierte Zeitbasis intern an das BSW-Modul StbM des Gateway-ECUs.
    • TG5 transferiert die Zeitbasis von TS5 (Ingress-Slave) an TM52 (Egress-Master). Eventuelle Latenzen und Jitter während des Gateway-Übergangs werden im StbM kompensiert (Rate-Correction / Virtual Local Time VLT).
  4. CAN-Zeittransfer (Lokaler Master → Slaves):
    • TM52 generiert CAN-Zeitsynchronisations-PDUs (CanTSyn) und verteilt die Offset-Zeit an :GlobalTimeCanSlave.

4. Normative Relevanz & Entwickler-Hinweise

  • ARXML-Generierung & Metamodell-Regeln:
    • Pro GlobalTimeDomain mit category = OFFSET ist die Referenz offsetTimeBase auf eine GlobalTimeDomain mit category = SYNCHRONIZED zwingend erforderlich.
    • In einem synchronisierten Gesamtsystem darf pro Domänen-ID exakt ein Knoten das Attribut isSystemWideGlobalTimeMaster = true tragen (TM51). Sekundäre Master hinter Gateways (TM52) müssen zwingend auf isSystemWideGlobalTimeMaster = false konfiguriert werden.
  • BSW-Konfiguration (StbM):
    • Konfiguration von StbMTimeBaseRecord: Für domainId = 1 wird eine StbMSynchronizedTimeBase instanziiert; für domainId = 16 eine StbMOffsetTimeBase mit Parameter StbMOffsetTimeBaseRef auf die Basisdomäne.
    • Time-Gateway-Konfiguration: Auf dem Gateway-Knoten muss im StbM ein Gateway (StbMTimeGateway) parametriert werden, das StbMTimeGatewaySourceTimeBaseRef (TS5) mit StbMTimeGatewayDestinationTimeBaseRef (TM52) verbindet.
  • Treiber- und Bus-Stack-Implikation (FrTSyn / CanTSyn):
    • FrTSyn: Muss für Master- bzw. Slave-Betrieb (Konfiguration von FrTSynGlobalTimeMaster / FrTSynGlobalTimeSlave) mit Unterstützung für Offset-Zeitbasen parametriert sein.
    • CanTSyn: Da CAN keine intrinsische globale Taktsynchronisation besitzt (im Gegensatz zum FlexRay Macrotick), müssen CanTSynGlobalTimeMasterPdu und CanTSynGlobalTimeFollowUpPdu bzw. die CAN-Offset-PDU sequenziell korrekt übertragen werden, um Timeouts bei den Slaves (CanTSynRxTimeoutTime) zu vermeiden.
