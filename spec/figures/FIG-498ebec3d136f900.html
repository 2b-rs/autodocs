1. Diagrammtyp & Architektur-Kontext

  • Metamodell-Klassifikation: UML-Klassendiagramm zur Definition des AUTOSAR ECU Configuration Metamodels (ECUC Parameter Configuration Definition gemäß AUTOSAR R4.1.3).
  • Funktionale Einordnung: Spezifikation der Konfigurationsstruktur des Moduls J1939Rm (SAE J1939 Request Manager) innerhalb des AUTOSAR Com-Stacks. Der J1939Rm koordiniert und verwaltet Anforderungen von Parameter Groups (PGN 59904 Request / PGN 59392 Acknowledgment) zwischen Applikationsschicht (SW-Cs/User) und dem J1939-Kommunikationsnetzwerk. Der Ausschnitt definiert die Verankerung logischer Netzwerkknoten (J1939RmNode) und deren Verknüpfung mit dem Netzwerkmanagement (J1939Nm), den Kommunikationskanälen und den Software-Nutzern.

2. Komponenten, Entitäten & Schnittstellen

  • J1939RmNode (EcucParamConfContainerDef):
  • Zentraler Konfigurationscontainer für einen logischen J1939-Knoten (Controller Application, CA) innerhalb der ECU.
  • Multiplizität: 1..* (mindestens ein Knoten pro J1939Rm-Instanz erforderlich).
  • J1939RmNmNodeRef (EcucReferenceDef):
  • Kompositionselement (+reference) innerhalb von J1939RmNode.
  • Multiplizität: 1..1 (jeder RM-Knoten muss genau einem NM-Knoten zugeordnet sein).
  • Attribut: requiresSymbolicNameValue = true.
  • Zielbeziehung (+destination): Referenziert J1939NmNode.
  • J1939NmNode & J1939NmNodeId:
  • Externe Metamodell-Entitäten des J1939 Network Management.
  • J1939NmNode (EcucParamConfContainerDef, 1..*) kapselt die NM-Repräsentanz des Knotens.
  • Enthält über +parameter den Parameter J1939NmNodeId (EcucIntegerParamDef): Wertebereich 0..255 (8-Bit J1939 Source Address), deklariert als symbolicNameValue = true zur systemweiten referenziellen Auflösung.
  • J1939RmNodeChannelRef (EcucReferenceDef):
  • Kompositionselement (+reference) innerhalb von J1939RmNode.
  • Multiplizität: 1..* (ein Knoten kann auf einem oder mehreren Kanälen operieren).
  • Zielbeziehung (+destination): Referenziert J1939RmChannel (EcucParamConfContainerDef, 1..*), wodurch die Bindung an spezifische CAN-Netzwerk-Cluster/Controller erfolgt.
  • J1939RmUser (EcucChoiceContainerDef):
  • Untercontainer (+subContainer), direkt aggregiert als Auswahl-Container unter J1939RmNode.
  • Multiplizität: 1..*.
  • Definiert die alternativen Konfigurationsausprägungen der Nutzer/SW-Cs, die über diesen Knoten PG-Requests initiieren oder empfangen.

3. Dynamisches Verhalten & Sequenzablauf

Obgleich ein statisches Konfigurationsmetamodell vorliegt, steuern diese Relationen deterministisch die Laufzeitpfade des J1939-Stacks:

  • Adress- und Kanalbindung: Zur Laufzeit bindet der J1939Rm jede Request-/Ack-Operation an die via J1939NmNodeRef dynamisch oder statisch gehaltene J1939 Source Address (Address Claiming im J1939Nm).
  • Eingehender Request-Pfad (Inbound): Eingehende PGN-59904-Frames auf einem referenzierten J1939RmChannel werden gefiltert. Stimmt die Zieladresse (Destination Address, DA) mit der über den J1939NmNode aufgelösten Adresse überein (oder handelt es sich um einen globalen Broadcast-Request 0xFF), leitet der J1939Rm die Anforderung an die unter J1939RmUser registrierten Callbacks/Schnittstellen weiter.
  • Ausgehender Request-Pfad (Outbound): Löst ein J1939RmUser eine Anfrage aus, bestimmt der zugeordnete J1939RmNode die Quelladresse (SA) und routet den Frame synchron/asynchron über die in J1939RmNodeChannelRef verknüpften Kommunikationskanäle in den PduR/CanIf-Stack.

4. Normative Relevanz & Entwickler-Hinweise

  • Konfigurationsvalidierung (BSW-Generator):
  • Die Kardinalität 1..1 von J1939RmNmNodeRef erzwingt eine zwingende Abhängigkeit zum J1939Nm-Modul; eine Standalone-Konfiguration des J1939Rm ohne korrespondierende J1939Nm-Metamodell-Instanzen ist ungültig.
  • Jeder Knoten benötigt mindestens eine gültige Kanalzuordnung (1.. zu J1939RmChannel) und mindestens einen Nutzer (1.. zu J1939RmUser). Leere Knoteninstanzen sind schemawidrig.
  • Multi-Homed Nodes: Die Multiplizität 1..* bei J1939RmNodeChannelRef erlaubt Multi-Network/Multi-Channel-Knoten; der Stack-Implementierer muss sicherstellen, dass bei Requests auf mehreren Kanälen die PGN-Auflösung und die Überwachung von Antwortfristen (Timeouts) kanalspezifisch synchronisiert werden.
  • Post-Build-Fähigkeit: Sämtliche Kerncontainer besitzen das Attribut postBuildChangeable = true. Dies ermöglicht in AUTOSAR R4.1.3 Post-Build-Selectable- bzw. Loadable-Szenarien, d. h. Knoten, Kanalzuordnungen und Nutzerstrukturen können per Konfigurations-Flash-Block ohne Neukompilierung der BSW-Quellen rekonfiguriert werden.
