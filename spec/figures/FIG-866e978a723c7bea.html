1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Metamodell-Ausschnitt als UML-Klassendiagramm aus dem AUTOSAR Software Component Template (Package Software Component template).
  • Architektur-Kontext: Spezifiziert die statische Modellierung der NVRAM-Dienstbedarfe (NVRam Service Needs) einer Software-Komponente (SWC) gegenüber dem AUTOSAR-Basissoftware-Stack (NvM – NVRAM Manager) im Release-Stand R2.1.20.
  • Funktionale Einordnung: Dient dem Generierungs- und Konfigurationsübergang (BSW/RTE-Generierung): Eine SWC deklariert über Annotations und Metamodell-Elemente ihre Anforderungen an persistente Daten (NVRAM-Blöcke), RAM-Spiegel (Mirror Blocks), ROM-Defaultwerte sowie Rückmeldeports für asynchrone NVRAM-Jobs. Der ECU-Konfigurator leitet daraus die BSW-Konfiguration des NvM (u. a. Block-IDs, Speicherverwaltung, CRC, Blockmanagementtyp) ab.

2. Komponenten, Entitäten & Schnittstellen

Entitäten und Stereotypen
  • InternalBehavior::InternalBehavior (ARElement):
    • Repräsentiert das interne Verhalten der SWC.
    • Attribut: + supportsMultipleInstantiation: Boolean (definiert, ob die Komponente multi-instanzfähig über RTE-Instanzzeiger ist).
  • NVRAMMapping::NVRAMMapping (Identifiable, Stereotyp «atpObject»):
    • Zentraler Verknüpfungsknoten innerhalb des InternalBehavior, der Port-Schnittstellen, PIM und ROM-Defaults zu einem kohärenten NVRAM-Blockbedarf bündelt.
  • PerInstanceMemory::PerInstanceMemory (Identifiable, Stereotyp «atpObject»):
    • Instanzspezifischer Arbeitsspeicher (PIM) im RAM, nutzbar als permanenter RAM-Spiegel (RAM Mirror) des NVRAM-Blocks.
    • Attribute: + type: String, + typeDefinition: String.
  • Characteristic::CalprmElementPrototype (spezialisiert DataPrototype):
    • Kalibrier- und Parameter-Element zur Bereitstellung von ROM-Standarddaten (Default/Rom Block).
  • Components::PortPrototype (Identifiable, Stereotyp «atpPrototype»):
    • Abstrakte Basisklasse für SWC-Ports.
    • Spezialisierungen:
      • Components::RPortPrototype: Empfangs-/Client-Port für NVRAM-Dienste (z. B. NvM_Service oder Port zum Lesen/Schreiben).
      • Components::PPortPrototype: Sende-/Server-Port für Statusmeldungen/Job-Ende-Rückrufe an die SWC.
  • ApplicationAttributes::PortAnnotation / ServiceNeeds:
    • Abstrakte Hierarchie zur Annotation von Service-Bedarfen an Port-Ebene.
  • ApplicationAttributes::NVRAMBlockNeeds (spezialisiert ServiceNeeds → PortAnnotation):
    • Deklaration der nichtfunktionalen NVRAM-Eigenschaften:
      • + nDataSets: Int: Anzahl der Datensätze (steuert NVRAM-Blockmanagement: NATIVE vs. DATASET).
      • + readonly: Boolean: Schreibschutz-Flag.
      • + reliability: Enumeration {low, medium, high}: Anforderung an Redundanz/Fehlererkennung (z. B. CRC-Breite, redundante Speicherung).
      • + resistantToChangedSw: Boolean: Beibehaltung der Daten bei Software-Update (Layout-Invarianz).
      • + restoreAtStart: Boolean: Automatisches Laden beim Start (NvM_ReadAll).
      • + transactionSafe: Boolean: Schutz gegen Inkonsistenz bei Schreibabbruch.
      • + writeOnlyOnce: Boolean: Einmaliges Schreiben (z. B. Produktionsdaten/Fahrgestellnummer).
      • + writingFrequency: Int: Erwartete Schreibfrequenz (Einfluss auf Wear-Leveling / EEPROM-Lebensdauer).
      • + writingPriority: Enumeration {low, medium, high}: Priorisierung in der NvM-Job-Queue.

3. Dynamisches Verhalten & Sequenzablauf

Da es sich um ein strukturelles Metamodell handelt, leitet sich der Laufzeitablauf über RTE und NvM ab:

[Startphase / EcuM / NvM_ReadAll]
       |
       v
+--------------------------------------------------------------+
| restoreAtStart == true                                       |
| -> NvM liest Daten aus NVM in PIM (mirrorBlock)             |
| -> Bei CRC-/Lesefehler: Fallback auf Calprm (defaultBlock)  |
+--------------------------------------------------------------+
                               |
[Normalbetrieb / SWC Ausführung]
                               |
    +--------------------------+--------------------------+
    | (Synchrone Datenbearbeitung)                        | (Asynchroner Job)
    v                                                     v
+----------------------------+             +-------------------------------+
| SWC greift direkt auf PIM |             | SWC ruft WriteBlock über      |
| (mirrorBlock) zu           |             | NVRAMPort (RPortPrototype) auf|
+----------------------------+             +-------------------------------+
                                                          |
                                                          v
                                           +-------------------------------+
                                           | NvM reiht Job nach            |
                                           | writingPriority ein           |
                                           +-------------------------------+
                                                          |
                                                          v
                                           +-------------------------------+
                                           | NvM signalisiert Job-Ende     |
                                           | an NVRAMNotification          |
                                           | (PPortPrototype, Callback)    |
                                           +-------------------------------+
  • Trigger & Initialisierung: Bei restoreAtStart = true liest der NvM während NvM_ReadAll die Nutzdaten direkt in den durch mirrorBlock referenzierten PerInstanceMemory. Schlägt der Lesevorgang fehl (z. B. Integritätsfehler), werden die Daten aus dem per defaultBlock referenzierten CalprmElementPrototype restauriert.
  • Asynchroner Speicherzugriff: Der Schreibauftrag erfolgt über den NVRAMPort (RPortPrototype). Der NvM verarbeitet den Schreibvorgang asynchron entsprechend der angegebenen writingPriority.
  • Callback & Benachrichtigung: Nach Abschluss der Transaktion triggert der NvM den Callback über den NVRAMNotification-Port (PPortPrototype), sofern projektiert (0..1).

4. Normative Relevanz & Entwickler-Hinweise

  • Generierungsvertrag (SWC zu NvM-BCT):
    • NVRAMBlockNeeds wird im AUTOSAR-Workflow zur automatischen Generierung des NvM_BlockDescriptor im Basissoftware-Konfigurator genutzt.
    • Attribute wie nDataSets > 1 erzwingen den BSW-Blocktyp NVM_BLOCK_DATASET.
    • reliability = high erzwingt in der NvM-Konfiguration z. B. NVM_BLOCK_REDUNDANT sowie 16-/32-Bit-CRCs (NVM_CRC16 / NVM_CRC32).
  • PIM als RAM-Spiegel:
    • Ist mirrorBlock gesetzt, muss die RTE keinen separaten Puffer allozieren; die SWC greift über PIM-APIs (Rte_Pim_<name>()) direkt auf den NvM-RAM-Spiegel zu.
    • Achtung: Nebenläufigkeitsschutz (Concurrent Access) beachten, wenn der NvM asynchron schreibt/liest, während Runnables auf den PIM zugreifen.
  • Multi-Instanziierung (supportsMultipleInstantiation = true):
    • Ist eine SWC multi-instanzfähig, muss für jede Instanz ein eigener PIM existieren (perInstanceMemory), und die NvM-Block-Zuordnung muss über instanzspezifische Deskriptoren bzw. Dataset-Indizes entflochten werden.
  • ROM-Wiederherstellung:
    • Ist defaultBlock angegeben, muss der RTE/NvM-Generierungsschritt den Zeiger NvM_RomBlockDataAddress auf die generierten Kalibrierparameterdaten (CalprmElementPrototype) binden.
