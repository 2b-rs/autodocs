1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: SPEM-2.0-basiertes Prozess- und Datenflussdiagramm (AUTOSAR Methodology Work Product / Activity Flow).
  • Technischer Zweck: Spezifiziert die methodische Kette zur Auflösung und Generierung von Memory-Mapping-Artefakten in der AUTOSAR Classic Platform (R4.0.3). Es modelliert den Übergang von plattformunabhängigen logischen Speicherklassen (SwAddrMethod, MemorySection) zu plattform-, compiler- und linkerspezifischen Header-Dateien (<SWC>_MemMap.h, MemMap.h) für SWCs und BSW-Module vor der Kompilierung.

2. Komponenten, Entitäten & Schnittstellen

Aktivitäten (Methodology Tasks)
  • Define Memory Addressing Modes (Scope: Per compiler platform): Definiert compiler-spezifische Adressierungsmechanismen und Pragma-Muster.
  • Configure Memmap Allocation (Scope: Per build environment.): Weist logische Adressierungsanforderungen konkreten Compiler-Sektionen zu.
  • Generate SWC Memory Mapping Header (Scope: Per component and build environment.): Generiert komponentenspezifische Header für Applikations-SWCs.
  • Generate BSW Memory Mapping Header (Scope: Per BSW module/cluster and build environment.): Generiert den zentralen Memory-Mapping-Header für BSW-Module.
  • Kompilier-Aktivitäten (Downstream Consumers):
    • Compile Atomic Software Component
    • Compile BSW Core Code
    • Compile ECU Source Code
Work Products (Artefakte & Konfigurationsstrukturen)
  • BSW Module Preconfigured Configuration:
    • Enthält: +MemMapAddressingModeSet [1..*] (vordefinierte Satzbeschreibungen für Compiler-Adressierungsarten).
  • VFB Types:
    • Enthält: +SwAddrMethods [0..], +SwAddrMethod [1..] (abstrakte Speicheranforderungen auf VFB-/SWC-Typ-Ebene).
  • Atomic Software Component Implementation:
    • Enthält: +MemorySections [0..*] bzw. [1] (Code- und Datensektionen einer SWC-Implementierung).
  • Basic Software Module Implementation Description (BSWMD):
    • Enthält: +MemorySections [0..*] bzw. [1] sowie +DependencyOnArtifact [1].
  • ECU Configuration Values:
    • Enthält: +MemMapAllocation [1] (Zuweisungscontainer im MemMap-Modul).
    • Referenziert optional: +RteImplementationRef [0..1] (für SWC-Instanzen) und +moduleDescription [0..1] (für BSW-Module).
  • Standard Header Files:
    • Enthält generierte C-Header: +SWC_MemMap [1] und +BSW_MemMap [1].
Abhängigkeiten, Rollen & Kardinalitäten
  • Define Memory Addressing Modes «output» → +MemMapAddressingModeSet [1..*].
  • Configure Memmap Allocation:
    • «input» ← +MemMapAddressingModeSet [1..*]
    • «input» ← +SwAddrMethods [0..*] (aus VFB Types)
    • «input» ← +MemorySections [0..*] (aus Atomic Software Component Implementation)
    • «input» ← +MemorySections [0..*] (aus BSWMD)
    • «output» → +MemMapAllocation [1] in ECU Configuration Values.
  • Generate SWC Memory Mapping Header:
    • «input» ← +SwAddrMethod [1..*] (aus VFB Types)
    • «input» ← +MemorySections [1] (aus Atomic Software Component Implementation)
    • «input» ← +MemMapAddressingModeSet [1..*]
    • «input» ← +MemMapAllocation [1]
    • «input» ← +RteImplementationRef [0..1]
    • «output» → +SWC_MemMap [1].
  • Generate BSW Memory Mapping Header:
    • «input» ← +MemorySections [1] (aus BSWMD)
    • «input» ← +DependencyOnArtifact [1] (aus BSWMD)
    • «input» ← +MemMapAddressingModeSet [1..*]
    • «input» ← +MemMapAllocation [1]
    • «input» ← +moduleDescription [0..1]
    • «output» → +BSW_MemMap [1].
  • Standard Header Files «input» [1] → Alle Build-Tasks (Compile Atomic Software Component, Compile BSW Core Code, Compile ECU Source Code).

3. Dynamisches Verhalten & Sequenzablauf

  1. Vorbereitung Compiler-Adressierungsarten: Define Memory Addressing Modes erzeugt pro Compilerplattform das Artefakt +MemMapAddressingModeSet [1..*] innerhalb der BSW Module Preconfigured Configuration.
  2. MemMap-Allokationskonfiguration: Configure Memmap Allocation aggregiert compiler-spezifische Adressierungsarten (+MemMapAddressingModeSet [1..]) sowie logische Speichersektionsdefinitionen (+SwAddrMethods [0..] aus VFB Types, +MemorySections [0..] aus Atomic Software Component Implementation und +MemorySections [0..] aus Basic Software Module Implementation Description) und erzeugt die Konfiguration +MemMapAllocation [1] innerhalb der ECU Configuration Values.
  3. Header-Generierung:
    • Generate SWC Memory Mapping Header konsumiert +SwAddrMethod [1..], +MemorySections [1] aus der Atomic Software Component Implementation, +MemMapAddressingModeSet [1..], +MemMapAllocation [1] sowie +RteImplementationRef [0..1] und generiert +SWC_MemMap [1].
    • Generate BSW Memory Mapping Header konsumiert +MemorySections [1], +DependencyOnArtifact [1] aus der BSWMD, +MemMapAddressingModeSet [1..*], +MemMapAllocation [1] sowie +moduleDescription [0..1] und generiert +BSW_MemMap [1].
  4. Header-Bereitstellung & Kompilierung: Beide Header gehen als Standard Header Files ein in Compile Atomic Software Component, Compile BSW Core Code und Compile ECU Source Code.

4. Normative Relevanz & Entwickler-Hinweise

  • Include-Pattern & Mehrfachinklusion: MemMap.h und <SWC>_MemMap.h dürfen keine klassischen #ifndef-Include-Guards besitzen. Sie werden innerhalb derselben Translation Unit mehrfach re-inkludiert, gesteuert über vorangehende Präprozessor-Makros: 
    #define <PREFIX>_START_SEC_<SECTION_NAME>
#include "<PREFIX>_MemMap.h"
/* Code- oder Datendefinition */
#define <PREFIX>_STOP_SEC_<SECTION_NAME>
#include "<PREFIX>_MemMap.h"
  • Separation of Concerns (SWC vs. BSW ab R4.0):
    • Applikations-SWCs nutzen strikt <SWC>_MemMap.h (verhindert Namespace-Pollution und Build-Flaschenhälse).
    • BSW-Module referenzieren direkt MemMap.h.
  • Portabilität & Entkopplung: C-Quelldateien dürfen keine hardcodierten #pragma section-Direktiven enthalten. Die Bindeglieder sind ausschließlich die ARXML-Beschreibungen SwAddrMethod (SWC) und MemorySection (BSWMD), die erst über das Modul MemMap im ECU-Extract an die jeweilige Toolchain (Tasking, HighTec, Green Hills, Wind River etc.) gebunden werden.
