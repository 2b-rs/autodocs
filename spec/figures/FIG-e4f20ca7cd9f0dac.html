1. Diagrammtyp & Architektur-Kontext

  • Diagrammtyp: Metamodell-Ausschnitt / UML-Klassendiagramm der ECU-Konfigurationsbeschreibung (BSW Parameter Definition gemäß AUTOSAR Ecuc-Metamodell).
  • Funktionale Einordnung: Definiert die Konfigurationsstruktur des Moduls LSduR (Large SDU Router) im AUTOSAR Classic Platform Communication Stack (Release R24-11).
  • Technischer Zweck: Festlegung der Nachbarmodule (Upper Modules / Lower Modules) sowie deren statischer API-Fähigkeiten (Transmit, Buffer Handling, Indication, Confirmation) zur Codegenerierung typisierter, statischer Schnittstellenaufrufe ohne Laufzeit-Overhead.

2. Komponenten, Entitäten & Schnittstellen

  • Wurzelelement:
  • LSduR: EcucModuleDef [0..1]: Moduldefinition des LSduR auf ECU-Ebene.
  • Konfigurationscontainer:
  • LSduRBswModules: EcucParamConfContainerDef [0..\*]: Über die Kompositionsbeziehung +container eingebetteter Container. Repräsentiert jedes direkt mit dem LSduR interagierende BSW-Modul (z. B. Dcm, PduR, CanTp, DoIP).
  • Referenzen:
  • LSduRBswModuleRef: EcucForeignReferenceDef [1..1]: Fremdreferenz (+reference) auf ein EcucModuleConfigurationValues (Stereotyp: «ARElement») aus dem Ecu Configuration Description Template. Verknüpft die LSduR-Konfiguration mit der konkreten Konfigurationsinstanz des Ziel-BSW-Moduls.
  • Konfigurationsparameter (EcucBooleanParamDef via +parameter):
  • LSduRUpperModule: Identifiziert das referenzierte Modul als übergeordnete Schicht (Upper Layer).
  • LSduRLowerModule: Identifiziert das referenzierte Modul als untergeordnete Schicht (Lower Layer).
  • LSduRTransmit: Bestimmt, ob die Transmit-Schnittstelle (<User>_Transmit bzw. LSduR_Transmit) für dieses Modul aktiviert ist.
  • LSduRRxIndication: Bestimmt, ob Empfangsmeldungen (<User>_RxIndication bzw. LSduR_RxIndication) angebunden werden.
  • LSduRTxConfirmation: Aktiviert die Sende-Rückmeldeschnittstelle (<User>_TxConfirmation bzw. LSduR_TxConfirmation).
  • LSduRProvideTxBuffer: Aktiviert das bufferbereitstellende Callback-Interface für Sende-Pfade großer SDUs (dynamische Pufferallokation/Streaming).
  • LSduRReleaseRxBuffer: Aktiviert die Freigabeschnittstelle für empfangene SDU-Puffer nach Abschluss des Routings.

3. Dynamisches Verhalten & Sequenzablauf

Als strukturelles Ecuc-Klassendiagramm bildet die Grafik keinen sequenziellen Ablauf ab. Sie parametriert jedoch direkt folgende dynamische Interaktionspfade:

  • Sende-Pfad (TX):
  1. Trigger durch Upper Module via LSduR_Transmit(...) (falls LSduRTransmit == TRUE).
  2. Bei Zero-Copy-/Puffer-Routing: Abfrage von Sendepuffern via ProvideTxBuffer.
  3. Weiterleitung an Lower Module via <LowerModule>_Transmit(...).
  4. Asynchrone Rückmeldung: Lower Module signalisiert Übertragungsabschluss an LSduR, welcher via <UpperModule>_TxConfirmation quittiert (falls LSduRTxConfirmation == TRUE).
  • Empfangs-Pfad (RX):
  1. Lower Module meldet Paketempfang via LSduR_RxIndication(...) (falls LSduRRxIndication == TRUE).
  2. Routing an Upper Layer Modul; nach Konsumierung Freigabe des Puffers über ReleaseRxBuffer (falls LSduRReleaseRxBuffer == TRUE).

4. Normative Relevanz & Entwickler-Hinweise

  • Anforderungskonformität (ECUC_LSduR_00015): Jeder BSW-Kommunikationspartner muss über eine eigene Instanz von LSduRBswModules eindeutig deklariert und typisiert werden.
  • Codegenerator-Einfluss:
  • Die Booleans steuern via Pre-Compile-Schalter (#if (<MODULE>_SUPPORT == STD_ON)) oder Funktionszeiger-Tabellen die Generierung der C-Header-Inklusionen (#include "<BswModule>.h") und API-Rumpfaufrufe.
  • Module, bei denen LSduRUpperModule und LSduRLowerModule inkonsistent oder beide FALSE gesetzt sind, müssen vom Validierungs-Tooling des Generators als Validierungsfehler abgewiesen werden.
  • Buffer-Management-Vertrag: Entwickler von Treiber-/Transportprotokollen müssen sicherstellen, dass bei gesetztem LSduRProvideTxBuffer bzw. LSduRReleaseRxBuffer die AUTOSAR-Puffersemantiken (z. B. BufReq_ReturnType) strikt eingehalten werden, um Speicherlecks und Deadlocks bei asynchronen Groß-SDU-Transfers zu vermeiden.
