2. Komponenten, Entitäten & Schnittstellen

  • Kontext-Funktionen (aufrufende Aktionen/Aktivitäten):
  • E2E_PXXmProtect(): Schützt ausgehende Methoden-PDUs (Generierung von Prüfsumme und Counter).
  • E2E_PXXmForward(): Prüft und erneuert Schutzdaten bei Durchleitung/Transformation über Gateway-Grenzen.
  • E2E_PXXmSourceCheck(): Zwischenknoten-/Source-Prüfung eingehender Methoden-PDUs.
  • E2E_PXXmSinkCheck(): Finale Verifikation empfangener Methoden-PDUs an der Senke.
  • Notation XX: Platzhalter für die konkrete Methodenprofil-Nummer (z. B. 04, 07, 22).
  • Datenstrukturen & Variablen:
  • Config: Zeiger auf die statische Konfigurationsstruktur (const E2E_PXXmConfigType*). Enthält das Element Offset in Bit-Einheiten.
  • Offset: Lokale Stack-Variable vom primitiven Basistyp uint16 in Byte-Einheiten (compute local variable uint16 Offset, which is in [byte]).
  • UML-Elemente: Initial Node, Action Node (Offset = Config->Offset / 8), Activity Final Node, Comment/Constraint Notes.

3. Dynamisches Verhalten & Sequenzablauf

  • Trigger: Synchroner interner Aufruf innerhalb der jeweiligen E2E-Profilfunktion direkt nach erfolgreichem Abschluss der Parameterprüfung (Verify inputs of the protect/check function, PRS_E2E_01170).
  • Ablaufschritte:
  1. Eintritt: Start am Initial Node.
  2. Aktion: Arithmetische Auswertung Offset = Config->Offset / 8 (ganzzahlige Division / Right-Shift um 3 Bit zur Konvertierung von Bit-Offset in Byte-Offset).
  3. Speicherung: Zuweisung an die lokale Funktionsvariable Offset (uint16).
  4. Terminierung: Übergang zum Activity Final Node und sequenzieller Übergang zum nächsten Teilschritt (Adressierung des E2E-Headers im Serialisierungs-Puffer ab Data[Offset]).
  • Abbruchbedingungen / Callbacks: Keine Verzweigungen, keine Fehlerrückgaben oder Det-/Dem-Meldungen in diesem Schritt; die Operation ist deterministisch und zwingend durchlaufend.

4. Normative Relevanz & Entwickler-Hinweise

  • Normative Bindung: [PRS_E2E_01171] verpflichtet Implementierer der E2E-Bibliothek, den Schritt „Compute offset“ exakt gemäß Figure 6.24 umzusetzen; Rückverfolgbarkeit auf E2E-Anforderung [RS_E2E_08539].
  • Konfigurations-Constraint (Byte-Alignment): Da die Bit-Division durch 8 mit Integer-Arithmetik abgeschnitten wird, muss die System- und Toolchain-Konfiguration (Config->Offset) zwingend auf ein Byte-Vielfaches (Config->Offset % 8 == 0) eingeschränkt sein. Andernfalls droht Bit-Trankierung und falsche Byte-Indexierung im Puffer.
  • Embedded-C-Implementierung: In sicherheitskritischen E2E-Treibern (ASIL B bis ASIL D) wird diese Zuweisung bevorzugt als bitweiser Shift realisiert:

```c

uint16 Offset = (uint16)(Config->Offset >> 3U);

```

  • Puffer-Adressierung: Das resultierende Byte-Offset dient nachfolgend als Basisindex für die Einbettung/Prüfung von CRC, Sequence Counter und Data-ID im serialisierten Byte-Array (uint8 *DataPtr).
