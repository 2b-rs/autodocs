1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: UML-Metamodell-Klassendiagramm (AUTOSAR System Template, TPS_SystemTemplate, Release R20-11).
  • Architektur-Kontext: Spezifikation von Steuergeräte-spezifischen Ethernet- und IP-Netzwerkeigenschaften (EthIpProps) auf Systemebene. Verknüpft die topologische Netzwerkanbindung (EthernetCommunicationConnector) mit wiederverwendbaren IP-Protokollprofilen (ARElement), um Low-Level-Stack-Parameter für IPv4 und IPv6 zur Generierung der BSW-Konfiguration (TcpIp, EthIf, SoAd) festzulegen.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm definiert eine statische Metamodell-Struktur, steuert jedoch direkt das Laufzeitverhalten des AUTOSAR TCP/IP-Stacks (TcpIp):

  • Startup & Adressinitialisierung:
    • IPv4 ARP: Nach Interface-Up triggert tcpIpArpNumGratuitousArpOnStartup die Aussendung von Gratuitous ARPs zur Konflikterkennung und Switch-CAM-Aktualisierung. Eingehende Pakete während ungelöster Zieladressen werden gepuffert (tcpIpArpPacketQueueEnabled = true), bis tcpIpArpRequestTimeout abläuft.
    • IPv4 AutoIP: Fallback auf Link-Local (169.254.x.x) nach Ablauf von tcpIpAutoIpInitTimeout.
    • IPv6 SLAAC / DAD: Vor IP-Zuweisung prüft der Stack via Duplicate Address Detection (tcpIpNdpSlaacDadNumberOfTransmissions probes, Wartezeit tcpIpNdpSlaacDadRetransmissionDelay). Ist tcpIpNdpSlaacOptimisticDadEnabled = true, darf das Interface für Sendevorgänge genutzt werden, bevor DAD final abgeschlossen ist (Optimistic DAD, RFC 4429).
    • DHCPv6: Protokollstart nutzt randomisierte Verzögerungen zwischen *Min und *Max Parametern (Solicit, Confirm, Information-Request), um Lastspitzen am DHCP-Server zu verhindern.
  • Paket-Reassembly & Fragmentierung:
    • Rx-Pfad: Eintreffende IP-Fragmente werden in Reassembly-Puffern gehalten. Werden Fragmente nicht innerhalb von tcpIpIpReassTimeout vollständig empfangen, verwirft der Stack das Datagramm und gibt Ressourcen frei (optional ICMP Time Exceeded).
    • Tx-Pfad: Übersteigt eine PDU die MTU (maximumTransmissionUnit), wird unter Verwendung von tcpIpIpTxFragmentBufferCount / Size fragmentiert, sofern Fragmentierung aktiv ist.
  • Path MTU Discovery (PMTU) & NDP Maintenance:
    • Ist pathMtuEnabled = true, führen ICMPv4 "Fragmentation Needed" bzw. ICMPv6 "Packet Too Big" zur temporären Reduzierung der Ziel-MTU, die nach pathMtuTimeout revalidiert wird.
    • NDP überwacht Nachbarn zyklisch via Unreachability Detection (NUD); Zustandswechsel (INCOMPLETE → REACHABLE → STALE → PROBE) folgen den konfigurierten Timern (tcpIpNdpDefaultReachableTime, RetransTimer, DelayFirstProbeTime).

4. Normative Relevanz & Entwickler-Hinweise

  • Metamodell-Zuordnung: Das Klassendiagramm gehört zur Spezifikation AUTOSAR_TPS_SystemTemplate.
  • Referenzierung: Ein EthernetCommunicationConnector kann über die zielgerichtete Assoziation +ethIpProps optional genau eine EthIpProps-Instanz referenzieren (Kardinalität 0..1).
  • Kompositionshierarchie: EthIpProps aggregiert optional Ipv4Props und Ipv6Props via Komposition (0..1). Diese enthalten wiederum kompositionell die spezifischen Eigenschaftscontainer (Ipv4ArpProps, Ipv4AutoIpProps, Ipv4FragmentationProps bzw. Ipv6FragmentationProps, Dhcpv6Props, Ipv6NdpProps).
  • Optionale Konfigurationsparameter: Sämtliche Attribute in allen Konfigurationscontainern sind als optional ([0..1]) deklariert.
  • Implementierungsrelevanz: Die Werte dienen als Entwurfszeit-Parameter für die BSW-Codegenerierung der Module TcpIp, EthIf und verwandter Kommunikationsstacks gemäß Standard-Spezifikationen (z. B. RFC 4861 für NDP, RFC 826 für ARP, RFC 3927 für AutoIP). EthIpProps fungiert zusätzlich als UploadableDesignElement.
