1. Diagrammtyp & Architektur-Kontext

  • Klassifikation: Tabellarische Zuordnungsmatrix (Mapping-Matrix) im Vorher-/Nachher-Zustandsvergleich zur Veranschaulichung statischer vs. dynamischer Konfigurationszustände.
  • Technischer Zweck & Einordnung: Spezifikation des Partial-Network-Cluster-to-Channel-Mappings (PncToChannelMapping) in AUTOSAR Classic Platform (System Template, ComM / NM-Stack). Das Diagramm illustriert das Routing- und Gateway-Verhalten für Teilnetzwerke (Partial Networks) bei Gateway-ECUs: Es stellt dar, wie vordefinierte Cluster-Kanal-Relationen zur Laufzeit über einen PNC-Lernmechanismus erweitert und deterministisch zurückgesetzt werden können.

2. Komponenten, Entitäten & Schnittstellen

  • Partial Network Cluster (PN-Cluster 1 bis PN-Cluster N): Logische Instanzen von Teilnetzen (PnCluster), die Steuergerätefunktionen über Busschnittstellen hinweg bündeln. Die Menge 1 … N ist zur Entwurfszeit fest definiert; neue PNCs können zur Laufzeit nicht erzeugt werden.
  • Kommunikationskanäle (Bus X, Bus Y, Bus Z, Bus to other GwECU): Physische Netzwerkknoten bzw. Kanäle (PhysicalChannel / ComMChannel), die an die Gateway-ECU angebunden sind (z. B. CAN, FlexRay, Ethernet).
  • Zell-Eintragstypen:
    • S (Static PNC Mapping): In ARXML deklariertes Mapping (PnClusterToPhysicalChannelMapping). Fest im ROM/Flash bzw. initial im Non-Volatile Memory (NvM) hinterlegt. Bleibt dauerhaft als Basiskonfiguration erhalten.
    • L (Configurable / Learned PNC Mapping): Zur Laufzeit dynamisch über den PNC-Learning-Mechanismus (z. B. Erkennung externer NM-Anforderungen) hinzugefügtes Mapping zwischen existierendem PNC und einem physischen Bus.
  • Kardinalitäten & Relationen:
    • n:m-Beziehung zwischen PNCs und Bussen.
    • Ein PNC kann reine S-Mappings besitzen (z. B. Cluster 4 auf Bus Y).
    • Ein PNC kann ungemappt verbleiben, ist aber als ID vorbereitet (z. B. Cluster 3 in der oberen Matrix).
    • Ein PNC mit bestehender statischer Bindung kann zusätzliche dynamische Bindungen (L) auf anderen Bussen annehmen (z. B. Cluster 2: statisch auf Bus X und GwECU, dynamisch gelernt auf Bus Y).

3. Dynamisches Verhalten & Sequenzablauf

  • Initialzustand (Obere Matrix):
    • Kaltstart/Default: Das Gateway operiert strikt nach ARXML-Vorgabe. Es existieren ausschließlich statische Zuordnungen S. Bus Z bedient keinen PNC; PN-Cluster 3 besitzt keine aktiven Kanalzuweisungen.
  • Lernphase / Dynamische Konfiguration (Untere Matrix):
    • Trigger: Eintreffen von Routing-Bedarf, Diagnosekommandos oder dynamischem PN-Learning via Network Management (NM-Vektoren / EIRA / ERA).
    • Ablauf:
      1. Eintrag L wird in der flüchtigen Matrix gesetzt (z. B. Bus Y lernt PN-Cluster 2, Bus Z lernt PN-Cluster 3, Bus to other GwECU lernt PN-Cluster 1).
      2. NM-Routing leitet PN-Aktivierungen ab diesem Zeitpunkt auch auf die gelernten Kanäle weiter.
  • Reset-Mechanismus:
    • Trigger: Aufruf einer dedizierten Management- bzw. BSW-API (z. B. Reset-Service im ComM / Gateway-Modul).
    • Wirkung: Alle L-Einträge werden verworfen. Das System fällt deterministisch auf den Mindestbestand der S-Einträge (obere Matrix) zurück. Einträge vom Typ S können per API weder gelöscht noch überschrieben werden.

4. Normative Relevanz & Entwickler-Hinweise

  • System Template & Codegenerierung (ARXML):
    • Alle potenziell lernbaren PNCs müssen bereits zur Entwurfszeit im ARXML angelegt sein (PnCluster), selbst wenn sie initial keinem Kanal zugewiesen sind (ComMPncComMChannelRef).
  • BSW-Stack & Speicherallokation (ComM / NM / RAM-Layout):
    • Die interne Lookup-Tabelle für das PNC-Routing muss im RAM allokiert werden (Bitmaske: Kanäle × konfigurierte PNCs), um Schreibzugriffe für L-Einträge zuzulassen.
    • Die Dimensionierung der Tabellen-Dimensionen richtet sich nach ComMPncIdRange bzw. der maximalen Anzahl kanalspezifischer PNCs.
    • Das ROM- bzw. Flash-Image muss das Default-Bitmuster der statischen S-Mappings als Fallback-Referenz vorhalten.
  • Laufzeit-API & Diagnose:
    • Das Gateway-Modul muss APIs zur Laufzeit-Modifikation sowie zum Rücksetzen der gelernten Zuordnungen auf die statische Basiskonfiguration implementieren.
    • Vor dem Setzen eines L-Eintrags muss geprüft werden, ob die referenzierte PNC-ID im System existiert; ungültige PNC-IDs müssen abgewiesen werden.
