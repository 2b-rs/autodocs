1. Diagrammtyp & Architektur-Kontext

Das Diagramm stellt ein bitweises Protokolldaten-Layout (PDU-Format / Bit-Offset-Diagramm über eine 32-Bit-Zeilenbreite) für eine SOME/IP-Service-Discovery-Nachricht dar. Im Kontext der AUTOSAR-Kommunikationsarchitektur (Classic & Adaptive Platform, SOME/IP-SD) illustriert die Abbildung den strukturellen Aufbau einer SOME/IP-SD-PDU zur Handhabung von Non-SOME/IP-Services über Service Discovery. Die PDU gliedert sich vertikal in den standardisierten 16-Byte SOME/IP-Header (Bit-Offset 0 bis 31) und die anschließende SOME/IP-SD-Payload, welche aus Steuer-Flags, einem Entries-Array sowie einem Options-Array besteht.

2. Komponenten, Entitäten & Schnittstellen

Das Datenformat umfasst folgende strukturierte Felder und Sub-Elemente:

  • SOME/IP Header (16 Bytes / 128 Bit):
    • Message ID: 32 Bit, Wert 0xFFFF 8100 (reservierte Service ID / Method ID für Service Discovery).
    • Length: 32 Bit, Wert 0x0000005C (92 Bytes Nutzlast ab Request ID).
    • Request ID: 32 Bit (Client ID / Session ID).
    • Protocol Version: 8 Bit, Wert 0x01.
    • Interface Version: 8 Bit, Wert 0x01.
    • Message Type: 8 Bit, Wert 0x02 (Notification).
    • Return Code: 8 Bit, Wert 0x00 (E_OK).
  • SOME/IP-SD Header & Steuerfelder:
    • Flags: 8 Bit, Wert 0x80 (Reboot-Flag gesetzt).
    • Reserved: 24 Bit (im Bild dargestellt als Reserved [8 bit =0x00] gefolgt von ungenutztem Raum bis Bit 31).
    • Length of Entries Array in Bytes: 32 Bit, Wert 0x00000020 (32 Bytes).
  • Entries Array (2 Einträge à 16 Bytes = 32 Bytes):
    • Entry 1 (FindService):
      • Type: 0x00 (Find).
      • Index 1st options: 0, Index 2nd options: 0, # of opt 1: 0 (none), # of opt 2: 0 (none).
      • Service ID: 0x1001, Instance ID: 0xFFFF (all instances).
      • Major Version: 0xFF (any), TTL: 3600 (1 Stunde).
      • Minor Version: 0xFFFFFFFF (any).
    • Entry 2 (OfferService):
      • Type: 0x01 (Offer).
      • Index 1st options: 0, Index 2nd options: 0, # of opt 1: 2, # of opt 2: 0 (none).
      • Service ID: 0xFFFE, Instance ID: 0x0001.
      • Major Version: 0x01, TTL: 3 (3 Sekunden).
      • Minor Version: 0x00000032.
  • Options Array (40 Bytes / Length: 0x00000028):
    • Option 1 (IPv4 Endpoint Option, 12 Bytes): Length 0x0009, Type 0x04, Reserved 0x00, IPv4-Address 192.168.0.1, Reserved 0x00, L4-Proto 0x06 (TCP), Port Number 0x1A91 (Port 6801).
    • Option 2 (Configuration Option, 28 Bytes): Length 0x0025, Type 0x01, Reserved 0x00, Payload [0x16]otherserv=internaldiag[0]. Referenziert via Pointer/Index ausgehend von Entry 2.

3. Dynamisches Verhalten & Sequenzablauf

Das Diagramm illustriert einen statischen Schnappschuss einer kombinierten SD-Nachricht, die gleichzeitig zwei Vorgänge abbildet:

  1. Das Senden einer Suchanfrage (Find, Service ID 0x1001) an alle Instanzen (0xFFFF) mit einer Gültigkeitsdauer von 3600 Sekunden ohne angehängte Optionen.
  2. Das zeitgleiche Anbieten eines Dienstes (Offer, Service ID 0xFFFE, Instanz 0x0001, Version 1.50) mit kurzer Gültigkeit von 3 Sekunden. Der Offer-Eintrag verweist über Index 1st options = 0 und # of opt 1 = 2 sequenziell auf die beiden Optionen im Options-Array (Option Index 0: IPv4-TCP-Endpunkt auf Port 6801; Option Index 1: Konfigurations-String otherserv=internaldiag). Dies ermöglicht dem Empfänger die dynamische Auflösung von Netzwerkadresse, Transportprotokoll und Zusatzparametern für die Dienstinstanz.

4. Normative Relevanz & Entwickler-Hinweise

Für die Implementierung des SOME/IP-SD-Stacks in AUTOSAR gelten folgende normative Vorgaben:

  • Header-Ausrichtung: Alle Header- und Längenfelder folgen dem Big-Endian-Format (Network Byte Order).
  • Längenberechnungen:
    • SOME/IP Header Length: Zählt alle Bytes nach dem Length-Feld (Request ID [4] + Header-Rest [4] + Flags/Reserved [4] + Entries Length [4] + Entries [32] + Options Length [4] + Options [40] = 92 Bytes = 0x5C).
    • Entries Array Length: Exakte Summe aller Entry-Längen (2 * 16 Bytes = 32 Bytes = 0x20).
    • Options Array Length: Exakte Summe aller Optionen (12 Bytes Endpoint + 28 Bytes Config = 40 Bytes = 0x28).
  • Options-Indizierung: Die Referenzierung erfolgt 0-basiert. Der Offer-Eintrag bindet durch Index 1st options = 0 und # of opt 1 = 2 beide Optionen (Index 0 und Index 1) an sich.
  • Konfigurations-String: Die Configuration Option nutzt ein DNS-SD-ähnliches Format mit vorangestelltem Längenbyte (0x16 = 22 Bytes) für das Schlüssel-Wert-Paar otherserv=internaldiag gefolgt von einem Null-Terminator [0].
