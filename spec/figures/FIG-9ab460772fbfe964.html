1. Diagrammtyp & Architektur-Kontext

Protokoll- und Paketstrukturdiagramm (Bit-Level Header Layout / Wire Format) für das SOME/IP-Protokoll (Scalable service-Oriented MiddlewarE over IP) im AUTOSAR-Kontext. Das Diagramm spezifiziert die Serialisierungsstruktur auf Applikations- bzw. Middleware-Ebene oberhalb der Transportprotokolle UDP oder TCP (Socket Adaptor / PDU Router) mit einer Bitbreite von 32 Bit pro Zeile (Bit-Offsets 0 bis 31).

2. Komponenten, Entitäten & Schnittstellen

Das Header-Format besteht aus sequenziellen Feldern fester und variabler Breite:

  • Bit Offset (0–31): Horizontale Skalierungsleiste zur Kennzeichnung der Bitpositionen innerhalb der 32-Bit-Wörter (Big-Endian / Network Byte Order).
  • Message ID (Service ID / Method ID) [32 bit]: Erste 32-Bit-Zeile zur Identifikation des RPC-Aufrufs bzw. Events.
  • Length [32 bit]: Zweite 32-Bit-Zeile zur Angabe der verbleibenden Paketlänge in Bytes.
  • Request ID (Client ID / Session ID) [32 bit]: Dritte 32-Bit-Zeile zur eindeutigen Zuordnung von Anfragen und Antworten.
  • Protocol Version [8 bit]: Erstes Byte der vierten Zeile (Bit 0–7).
  • Interface Version [8 bit]: Zweites Byte der vierten Zeile (Bit 8–15).
  • Message Type [8 bit]: Drittes Byte der vierten Zeile (Bit 16–23).
  • Return Code [8 bit]: Viertes Byte der vierten Zeile (Bit 24–31).
  • Payload [variable size]: Nutzdatenblock variabler Länge.
  • Covered by Length: Vertikaler Maßpfeil an der rechten Seite, der die von dem Feld Length abgedeckte Spanne markiert; er beginnt ab einschließlich Request ID und erstreckt sich über die 8-Bit-Header-Felder bis zum Ende der Payload.

3. Dynamisches Verhalten & Sequenzablauf

Statische Paketformat-Spezifikation für die Übertragung über IP-basierte Netzwerke. Beim Senden eines SOME/IP-Pakets wird die Gesamtlänge ab einschließlich des Felds Request ID berechnet (Request ID + Protocol Version + Interface Version + Message Type + Return Code + Payload-Länge = 8 Byte Header-Anteil + Payload-Bytes) und in das Feld Length eingetragen. Die Felder Message ID und Length selbst (insgesamt 8 Byte) sind nicht in der Längenangabe enthalten. Der Empfänger wertet zunächst Message ID und Length aus, um die Paketgrenzen zu bestimmen und das Paket anschließend über Message ID und Request ID an die zuständige Service-Instanz bzw. den Client-Kontext zu dispatchen.

4. Normative Relevanz & Entwickler-Hinweise

Normatives Wire-Format für SOME/IP-Stacks. Bei der Implementierung von Serialisierern/Deserialisierern und Netzwerk-Codecs ist strikt zu beachten:

  • Das Feld Length zählt nicht die Gesamtlänge des Pakets, sondern exakt die Bytes ab Beginn der Request ID bis zum Ende der Payload.
  • Der SOME/IP-Header vor der Nutzdatenlast umfasst exakt 16 Byte (128 Bit), wovon 8 Byte vor dem Covered by Length-Bereich liegen.
  • Die Übertragung erfolgt in Network Byte Order (Big-Endian).
  • Die Substrukturierung der 32-Bit-Felder (Message ID in Service ID und Method ID; Request ID in Client ID und Session ID) sowie die 8-Bit-Felder erfordern Byte-exaktes Alignment.
