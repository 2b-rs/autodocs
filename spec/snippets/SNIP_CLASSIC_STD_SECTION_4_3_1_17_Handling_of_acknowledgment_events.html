4.3.1.17 Handling of acknowledgment events As a general rule, the acknowledgment events DataWriteCompletedEvent and DataSendCompletedEvent shall be raised immediately after the sending to all receivers has been performed and in case of Inter-ECU communication all acknowledgments from COM have been received. [SWS_Rte_01287] Upstream requirements: SRS_Rte_00051, SRS_Rte_00122, SRS_Rte_00018 ⌈A DataSendCompletedEvent that references a RunnableEntity and is referenced by a WaitPoint shall be an invalid configuration which is rejected by the RTE generator.⌋ [SWS_Rte_04640] Upstream requirements: SRS_Rte_00051, SRS_Rte_00122 ⌈The RTE generator shall reject the configuration if the VariableDataPrototype referenced by a DataSendCompletedEvent does not have transmission acknowledgment enabled.⌋ As part of the implementation detailed rules for the following communication scenarios have to be considered: Intra-Partition communication [SWS_Rte_08017] Upstream requirements: SRS_Rte_00122 ⌈For intra-partition communication with implicit dataWriteAccess the DataWriteCompletedEvent shall be fired if and only if a task/ISR2 terminates and the write-back copy actions to the global RTE-buffer are completed. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_IFeedback API.⌋ [SWS_Rte_08043] Upstream requirements: SRS_Rte_00122 ⌈For intra-partition communication with incoherent implicit dataWriteAccess no write-back copy actions to a global RTE-buffer will be performed, if the involved runnables are all running in one preemption area. In this case the DataWriteCompletedEvent shall be fired after the termination of the last sending runnable in the sending task/ISR2. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_IFeedback API.⌋ [SWS_Rte_08018] Upstream requirements: SRS_Rte_00122 ⌈For intra-partition communication with explicit dataSendPoint the DataSendCompletedEvent shall be fired if and only if the sending to all receivers has been performed. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_Feedback API.⌋ Inter-Partition communication [SWS_Rte_08020] Upstream requirements: SRS_Rte_00122 ⌈For inter-partition communication with implicit dataWriteAccess the DataWriteCompletedEvent shall be fired if and only if a task/ISR2 terminates and the write-back copy actions to the global RTE-buffer are completed. In addition the execution of the data write operations at the data receiver partitions must have taken place. Thereby the return status of the IOC for the different write operations can be neglected. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_ IFeedback API.⌋ [SWS_Rte_08044] Upstream requirements: SRS_Rte_00122 ⌈For inter-partition communication with incoherent implicit dataWriteAccess no write-back copy actions to a global RTE-buffer will be performed, if the involved runnables are all running in one preemption area. In this case the DataWriteCompletedEvent shall be fired after the termination of the last sending runnable in the sending task/ISR2 and after the execution of the data write operations at the data receiver partitions have taken place. Thereby the return status of the IOC for the different write operations can be neglected. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_IFeedback API.⌋ [SWS_Rte_08021] Upstream requirements: SRS_Rte_00122 ⌈For inter-partition communication with explicit dataSendPoint the DataSendCompletedEvent shall be fired if and only if the sending to all receivers has been performed and the execution of the data write operations at the data receiver partitions have taken place. Thereby the return status of the IOC for the different write operations can be neglected. The transmission status shall be RTE_E_TRANSMIT_ACK and can be collected with Rte_Feedback API.⌋ Inter-ECU communication A transmission of a single COM Signal(Group) or COM Large Data IPdu is considered being complete if one of the following situations occurs: • the related transmission acknowledgement callback (Rte_COMCbkTAck, Rte_ COMCbkTxConfirmation or Rte_COMCbkTpTxConfirmation) has been called • the related transmission error callback (Rte_COMCbkTErr) has been called • a transmission timeout occurred (Rte_COMCbkTxTOut or RTE internal timeout supervision) [SWS_Rte_08022] Upstream requirements: SRS_Rte_00122 ⌈For inter-ECU communication with implicit dataWriteAccess the DataWriteCompletedEvent shall be fired if and only if a task/ISR2 terminates and the write-back copy actions to the global RTE-buffer are completed. In addition the transmission of all related COM Signal(Group)s and COM Large Data IPdus has to be complete. The transmission status (success or type of error) can be collected with the Rte_IFeedback API.⌋ [SWS_Rte_08045] Upstream requirements: SRS_Rte_00122 ⌈For inter-ECU communication with incoherent implicit dataWriteAccess no write-back copy actions to a global RTE-buffer will be performed, if the involved runnables are all running in one preemption area. In this case the DataWriteCompletedEvent shall be fired after the termination of the last sending runnable in the sending task/ISR2 and after the transmission of all related COM Signal(Group)s and COM Large Data IPdus is complete. The transmission status (success or type of error) can be collected with the Rte_IFeedback API.⌋ [SWS_Rte_08023] Upstream requirements: SRS_Rte_00122 ⌈For inter-ECU communication with explicit dataSendPoint the DataSendCompletedEvent shall be fired if and only if the sending to all receivers has been performed and the transmission of all related COM Signal(Group)s and COM Large Data IPdus is complete. The transmission status (success or type of error) can be collected with the Rte_Feedback API.⌋ Note that errors occurring inside Rte_Write, Rte_Send or Rte_IWrite APIs don’t lead to the firing of DataWriteCompletedEvents or DataSendCompletedEvents.
