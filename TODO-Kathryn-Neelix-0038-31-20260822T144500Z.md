## Decisions

### D1 — deduplication key (justified, not assumed)

Two distinct keys, at two distinct scopes:

- **Within one source variant**: unchanged — `(path, line, rule, symbol, evidence_sha256)`.
  Line stays in the key here, so two occurrences on different lines remain two findings.
- **Across the variants of one file** (index vs. worktree): `(path, rule, symbol, evidence_sha256)`.

Why `evidence_sha256` is the right anchor: it is the SHA-256 of the exact evidence text — the source
line for shell rules, the full AST node source span for Python rules — so it is invariant under a
pure line move and changes the moment the code itself changes. `path` and `rule` scope it; `symbol`
keeps byte-identical statements in different functions apart.

What it does **not** do: it cannot tell two byte-identical statements in the *same* symbol apart. So
the merge does not collapse them — it is a **multiset union taking, per code site, the maximum number
of occurrences seen in any single variant**:

| case | index | worktree | reported | rationale |
|---|---|---|---|---|
| finding merely moved lines | 1 | 1 | **1** | the bug this Task fixes |
| genuinely repeated identical code | 2 | 2 | **2** | multiplicity preserved |
| finding newly introduced, uncommitted | 0 | 1 | **1** | uncommitted edits cannot hide from the gate |
| finding removed in the worktree only | 1 | 0 | **1** | committed findings cannot be hidden by an uncommitted edit |

The last two rows are the existing conservative union semantics, deliberately retained: narrowing
either would *lose* a finding.

### D2 — what the gate authoritatively measures

**The index is authoritative; the worktree is scanned additionally and unioned in.**

- Authoritative locator: when a code site is present in both variants, the **index** line number is
  reported. This makes the gate's output reproducible from a commit, and it is why the numbers no
  longer move when the tree happens to be dirty — which is the entire point of the Task.
- A code site present **only** in the worktree is reported at its worktree line, so an uncommitted
  edit can never hide a finding.
- Choosing the *worktree* line as canonical was considered and rejected: dispositions are keyed on
  `(path, rule, line, symbol, evidence_sha256)` including the line, so reporting a shifted line for
  an unchanged code site would silently un-match its disposition and flip the verdict on a dirty
  tree. Index-authoritative keeps disposition matching identical on clean and dirty trees, without
  touching the disposition mechanism.
- This is now stated in the report itself (`sources` block) and in the human output, so a reader can
  tell what was actually scanned.
