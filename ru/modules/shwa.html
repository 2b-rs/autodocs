Классификация и назначение

Безопасное аппаратное ускорение предоставляет механизмы, позволяющие адаптивным приложениям выполнять параллельные задачи на доступном оборудовании. Архитектура позволяет комбинировать очереди, устройства и буферы; другие функциональные кластеры также могут использовать API SWS SHWA §7.1 «The Architecture of Safe Hardware Acceleration».

Данные, доступ и хранение

Buffer управляет распределением памяти, а Accessor обеспечивает типизированный доступ для чтения/записи. Режимы доступа и привязка к TaskHandler предоставляют системе времени выполнения информацию для перемещения и синхронизации данных SWS SHWA §7.3 «Data Access Specifics» SWS SHWA §7.5 «Memory Allocation Specifics». Сопроводительный документ EXP группирует Buffer, Accessor, Range и Id как хранилище данных и управление данными EXP Safe Hardware Acceleration API §4.3.1.

Выбор устройства, выполнение и синхронизация

Device представляет вычислительное устройство; классы Selector выбирают устройства CPU, GPU или Accelerator по оценкам. Queue передаёт задачи, а Event поддерживает зависимости или операции ожидания при неупорядоченном выполнении SWS SHWA §7.4 «Device Specifics» SWS SHWA §7.6 «Task Queuing And Ordering Specifics».

Интерпретация: Надёжный путь приложения обычно состоит из выбора устройства, создания Queue/ErrorHandler, создания Buffer/Accessor, отправки Task и подходящей синхронизации на основе Event или Timeout. Эта последовательность обобщает описанные отдельные концепции.

Безопасность, ошибки и параллелизм

API безупречен; ошибочные операции используют ara::core::Result, а фабричные методы включают перенос ошибок во время создания объекта. Асинхронный ErrorHandler предоставляется для ошибок выполнения на устройстве; DeviceMonitor поддерживает мониторинг состояния устройства SWS SHWA §7.2 «General Features» SWS SHWA §7.2.5.3–7.2.5.4. Объекты SHWA остаются ограниченными процессом; Согласно спецификации, одновременный доступ к одному и тому же буферу записи Accessor::Set приводит к kResourceBusy SWS SHWA §7.2.2 «Parallel Access».
