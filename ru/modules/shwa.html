Роль Safe Hardware Acceleration и граница с процессом приложения

Safe Hardware Acceleration (SHWA, пространство имен ara::shwa) делает аппаратное ускорение стандартизированным и переносимым для безопасных и эффективных вычислений SWS SHWA с. 4. Согласно функциональному обзору, SHWA предоставляет API для Adaptive Applications и других Functional Clusters. Данный кластер охватывает три задачи:

  • выполнять ресурсоемкие вычисления параллельно на аппаратном ускорителе (HWA),
  • обнаруживать и исправлять ошибки выполняемых на нем задач,
  • контролировать рабочие состояния ускорителей SWS SHWA с. 7.

Требования кластера должны учитывать требования безопасности AUTOSAR SWS SHWA с. 5.

Обзор архитектуры относит SHWA к категории Safety. В отличие от Platform Health Management, SHWA не обозначен там как daemon-based EXP SW-Architektur с. 127. Интерфейсы представляют собой нативные интерфейсы C++, которые Adaptive Application использует напрямую EXP SW-Architektur с. 132. Другие Functional Clusters также могут использовать SHWA без участия Adaptive Application. Их библиотечная часть использует для этого собственную информацию о развертывании, а их демоны моделируются как Adaptive Applications SWS SHWA с. 23.

На аппаратном уровне Device различает тип вычислительного блока с помощью IsCpu, IsGpu и IsAccelerator [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00311] [AP_SWS_SHWA_00312]. Перечисление Target определяет два места выполнения: kDevice для устройства или ускорителя и kHostTask для Host-CPU [AP_SWS_SHWA_00102].

Контекстная диаграмма: Adaptive Applications и другие Functional Clusters используют SHWA в качестве нативного интерфейса; SHWA подключает CPU, GPU и ускорители. Источники: SWS SHWA с. 23, EXP SW-Architektur с. 127, [AP_SWS_SHWA_00310]

Четыре области интерфейса ara::shwa

Схема в спецификации делит API на четыре области: управление данными, выполнение задач, управление и мониторинг устройств, а также обработка ошибок SWS SHWA с. 17. Пояснение к API описывает первые три области как уровни EXP SHWA-API с. 15.

  • Управление данными: Range и Id описывают одно-трехмерные размеры и индексы [AP_SWS_SHWA_01009] [AP_SWS_SHWA_00709]. К ним добавляются Buffer [AP_SWS_SHWA_00209], Accessor [AP_SWS_SHWA_00007] и PropertyList [AP_SWS_SHWA_00802].
  • Выполнение задач: Queue [AP_SWS_SHWA_00908], TaskHandler [AP_SWS_SHWA_01202] и Event [AP_SWS_SHWA_00602].
  • Управление и мониторинг устройств: Platform [AP_SWS_SHWA_01107] и Device [AP_SWS_SHWA_00308]. К этому добавляется DeviceSelector с GpuSelector, CpuSelector и AcceleratorSelector [AP_SWS_SHWA_00403] [AP_SWS_SHWA_00407] [AP_SWS_SHWA_00410] [AP_SWS_SHWA_00413], а также DeviceMonitor [AP_SWS_SHWA_01407].
  • Обработка ошибок: ErrorHandler [AP_SWS_SHWA_00507], ShwaErrorCode [AP_SWS_SHWA_01301], ShwaErrorDomain [AP_SWS_SHWA_01307] и ShwaException [AP_SWS_SHWA_01303].

Приложению разрешено комбинировать несколько очередей, устройств и буферов. То же самое относится к другим Functional Clusters SWS SHWA с. 22. Соответствующая схема показывает две независимые группы. Каждая группа состоит из очереди с несколькими задачами, из буферов и из устройства SWS SHWA с. 23.

Диаграмма совместной работы: так центральные классы связаны между собой по всем областям: очередь привязана к устройству, Submit возвращает событие, а аксессор обращается к буферу. Источники: SWS SHWA с. 17, [AP_SWS_SHWA_00910], [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00008], [AP_SWS_SHWA_01407]

От устройства к очереди: выбор и настройка

Устройство можно определить тремя способами:

  1. Перечисление: Platform::GetPlatforms возвращает доступные платформы, GetDevices — их устройства [AP_SWS_SHWA_01107] [AP_SWS_SHWA_01108].
  2. Без аргумента: Device::Create() [AP_SWS_SHWA_00308].
  3. Через селектор: Device::Create(deviceSelector) [AP_SWS_SHWA_00309].

DeviceSelector оценивает устройство с помощью operator() и возвращает для этого Result<int>. SelectDevice возвращает выбранное устройство [AP_SWS_SHWA_00404] [AP_SWS_SHWA_00403]. Дополнительные сведения об устройстве GetInfo<InfoType> считывает из [AP_SWS_SHWA_00313].

Очередь создается либо напрямую из селектора, либо из конкретного устройства. В обоих вариантах ErrorHandler является обязательным параметром, а PropertyList — необязательным [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00909]. GetDevice возвращает привязанное устройство. IsInOrder указывает, выполняются ли задачи очереди упорядоченно [AP_SWS_SHWA_00910] [AP_SWS_SHWA_00911] EXP SW-Architektur с. 133.

Диаграмма деятельности: три пути ведут к устройству, две фабрики — к очереди; каждый результат проверяется как Result. Источники: [AP_SWS_SHWA_01107], [AP_SWS_SHWA_00308], [AP_SWS_SHWA_00309], [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909]

Предоставление данных и отправка задач

Range описывает размеры с числом измерений от одного до трех [AP_SWS_SHWA_01007] [AP_SWS_SHWA_01009]. Buffer::Create существует в нескольких вариантах [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00210] [AP_SWS_SHWA_00212] [AP_SWS_SHWA_00211] [AP_SWS_SHWA_00213] [AP_SWS_SHWA_00214]:

  • только с Range,
  • с Range и дополнительным аллокатором,
  • только с аллокатором,
  • с изменяемыми или константными данными хоста.

Accessor обращается к буферу. Он создается без TaskHandler или с ним [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00008]. Он предоставляет operator[] с Id или линейным индексом [AP_SWS_SHWA_00009] [AP_SWS_SHWA_00010]. Кроме того, он предоставляет Set и Get с возвратом Result [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012]. Доступ определяется AccessMode со значениями kRead, kWrite и kReadWrite. При kRead ReferenceT является константной ссылкой [AP_SWS_SHWA_00101] [AP_SWS_SHWA_00014].

Queue::Submit(cfg, ErrorHandler&&) отправляет задачу и возвращает Event [AP_SWS_SHWA_00912]. TaskHandler предлагает две формы выполнения: SingleTask для отдельной задачи и ParallelFor(bufferSize, cfg) для параллельного выполнения по данным [AP_SWS_SHWA_01203] [AP_SWS_SHWA_01204]. Диаграмма вариантов использования называет сценариями применения «Single Instructions on Multiple Data» и «Multiple Instructions on Multiple Data» EXP SW-Architektur с. 203.

Интерпретация: cfg, вероятно, представляет собой вызываемую конфигурацию. Она, предположительно, получает TaskHandler, создает в нем аксессоры и вызывает SingleTask или ParallelFor. На это указывает фабрика аксессоров с параметром TaskHandler [AP_SWS_SHWA_00008].

Диаграмма последовательности: подготавливаются данные, отправляется задача с параллелизмом по данным и ожидается ее завершение. Вызов cfg помечен как интерпретация. Источники: [AP_SWS_SHWA_01007], [AP_SWS_SHWA_00211], [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00008], [AP_SWS_SHWA_01204], [AP_SWS_SHWA_00604]

Синхронизация через события и функции ожидания очереди

Каждый Submit возвращает Event [AP_SWS_SHWA_00912]. На уровне событий предусмотрено три функции ожидания [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00605] [AP_SWS_SHWA_00606]:

  • Event::Wait() ожидает завершения связанных задач.
  • Статический вариант со списком событий ожидает несколько событий.
  • WaitFor(ms) ограничивает ожидание по времени.

GetWaitList возвращает список событий [AP_SWS_SHWA_00603]. На уровне очереди Wait() выполняет блокирующее ожидание всех поставленных в очередь задач, WaitFor(ms) делает то же самое с ограничением по времени [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] EXP SW-Architektur с. 133.

Требования указывают потокобезопасность для каждой функции отдельно:

  • Потокобезопасно: Queue::Create, Accessor::Create, Range::Create, а также Accessor::Set и Get [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00007] [AP_SWS_SHWA_01007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012].
  • Не потокобезопасно: Queue::Submit, Queue::Wait, Event::Wait, Device::Create и Accessor::operator[] [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00308] [AP_SWS_SHWA_00009].
  • Различия внутри одного класса: Buffer::Create потокобезопасен, тогда как вариант только с аллокатором — нет [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00212].

Второй вариант Submit вместо ErrorHandler принимает secondaryQueue [AP_SWS_SHWA_00913]. Интерпретация: эта очередь, вероятно, служит резервной очередью в случае сбоя выполнения в основной очереди. Данный вариант восходит к тому же вышестоящему требованию, что и ErrorHandler [AP_SWS_SHWA_00507].

Диаграмма последовательности: две очереди работают независимо; приложение синхронизируется через списки событий или функции ожидания очереди. Источники: [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00605], [AP_SWS_SHWA_00914], [AP_SWS_SHWA_00917], SWS SHWA с. 22

Владение объектами, свойства и состояние устройства

Для всех классов действуют три правила проектирования EXP SHWA-API с. 15:

  • Конструкторы являются приватными; объекты создаются через именованные методы Create().
  • Классы, владеющие данными, предоставляют std::unique_ptr.
  • Большинство возвращаемых значений инкапсулировано в ara::core::Result.

В версии пояснения для R23-11 в этом месте еще упоминался ara::com::SamplePtr EXP Safe-API HWA с. 15. Для R25-11 определяющими являются требования, и именно они задают std::unique_ptr [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00908].

Свойства передаются при создании в виде PropertyList [AP_SWS_SHWA_00802]. Для Buffer, Accessor и Queue HasProperty проверяет наличие свойства; GetProperty считывает его. О неподдерживаемых свойствах GetProperty сообщает с помощью kFeatureNotSupported [AP_SWS_SHWA_00215] [AP_SWS_SHWA_00216] [AP_SWS_SHWA_00015] [AP_SWS_SHWA_00016] [AP_SWS_SHWA_00915] [AP_SWS_SHWA_00916]. Какую именно информацию о развертывании Functional Clusters используют для SHWA, в имеющихся источниках подробнее не указано SWS SHWA с. 23.

Для мониторинга из устройства или селектора создается DeviceMonitor [AP_SWS_SHWA_01407] [AP_SWS_SHWA_01408]. Status() возвращает DeviceStatus с одним из следующих значений [AP_SWS_SHWA_01409] [AP_SWS_SHWA_00103]:

  • kReady: готово к выполнению задач,
  • kNotAccesible: недоступно,
  • kFailure: состояние ошибки,
  • kUnknown: статус невозможно определить.

Передается ли этот статус другим Functional Clusters, в имеющихся источниках не определено.

Диаграмма деятельности: статус запрашивается через DeviceMonitor, и происходит ветвление по DeviceStatus; реакция на значения, отличные от kReady, является интерпретацией. Источники: [AP_SWS_SHWA_01407], [AP_SWS_SHWA_01409], [AP_SWS_SHWA_00103]

Поведение при ошибке

SHWA сообщает об ошибках через ara::core::Result с кодами из ShwaErrorCode. К ним относятся kRuntime, kTaskExecutionFailure, kMemoryNotAllocated, kIntegrityCorrupted (невозможно восстановить целостность буферной памяти), kResourceBusy и kInvalidAccessMode [AP_SWS_SHWA_01301]. Отдельные функции называют дополнительные коды: kAccessorFailure, kInvalidIndex, kFeatureNotSupported и kEventInvalidOperation [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00313] [AP_SWS_SHWA_00603].

Домен ShwaErrorDomain предоставляет Name, Message и ThrowAsException. GetShwaDomain и MakeErrorCode связывают коды с доменом. ShwaException передает код в виде исключения [AP_SWS_SHWA_01308] [AP_SWS_SHWA_01309] [AP_SWS_SHWA_01310] [AP_SWS_SHWA_01311] [AP_SWS_SHWA_01312] [AP_SWS_SHWA_01303].

Особенно серьезные последствия имеют ошибки при выполнении и ожидании. Если Submit, Queue::Wait, Queue::WaitFor или Event::Wait сообщают код kRuntime, данные завершившейся сбоем задачи следует считать непреднамеренно измененными. Для Event::Wait это справедливо и для kTaskExecutionFailure [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] [AP_SWS_SHWA_00604]. Данные об ошибках от Submit имеют обозначение no_rollback_semantics [AP_SWS_SHWA_00912].

О занятых ресурсах сообщают, среди прочего, Device-запросы и Accessor::Get с kResourceBusy [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00012]. О неудачном выделении сообщает Buffer::Create с kMemoryNotAllocated [AP_SWS_SHWA_00212].

ErrorHandler инкапсулирует функцию std::function<void(ara::core::ErrorCode)> [AP_SWS_SHWA_00507]. HandleError(ShwaErrorCode) выполняет обработку и не является потокобезопасным [AP_SWS_SHWA_00508]. Каждая очередь при создании получает ErrorHandler [AP_SWS_SHWA_00908]. Интерпретация: реализация, вероятно, сообщает через HandleError об ошибках переданных задач, которые не представлены непосредственно в виде возвращаемого значения Submit; кто вызывает HandleError, в источниках не определено. На уровне устройства DeviceStatus::kFailure указывает на состояние ошибки [AP_SWS_SHWA_00103].

Диаграмма деятельности: вычисляется Result и классифицируются коды ошибок SHWA, включая последствия для данных при ошибках задач. Источники: [AP_SWS_SHWA_01301], [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00604], [AP_SWS_SHWA_01310], [AP_SWS_SHWA_00508]

AcceleratorSelector класс

AcceleratorSelector manages accelerator selection for operations on HWA if available.

Accessor класс

Accessor manages read and write access to allocated memory by Buffer. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

Buffer класс

Buffer manages memory allocation for operations on the host or/and HWA. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

CpuSelector класс

CpuSelector manages CPU selection for operations on HWA if available Allows to get a device from any supported backends for which the device type is CPU.

Device класс

Device class represents HWA device. Provides access to the device but not controlling it. Designed as copyable since not owning resources.

DeviceMonitor класс

DeviceMonitor API class. Designed as copyable since not owning resources.

DeviceSelector класс

Class allowing to choose the most appropriate device of the available ones. This is a callable object taking a device reference and returning an integer rank. One of the device with the highest non-negative value is selected.

ErrorHandler класс

ErrorHandler manages asynchronous error handling for operations on HWA.

Event класс

Event class helps to manage task execution synchronization between HWA and Host application. Can be created only inside of the Queue otherwise it’s meaningless.

GpuSelector класс

GpuSelector manages GPU selection for operations on HWA if available Select a device from any supported backends for which the device type is GPU.

Id класс

Id API class. Designed as copyable since not owning resources.

Platform класс

Platform class is responsible for extracting different HWA platforms available for current application and listing Devices bind to each platform. Designed as copyable since not owning resources.

PropertyList класс

Property List class is designed to enable vendor specific SHWA functionality extension and adjustment. Properties are not standardized and can be defined by Vendor. Class using Property list is obliged to have HasProperty() and GetProperty() methods defined.

Queue класс

Queue API provides the functionality for parallel processing on selected Device. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ ptr, which may be moved. ≙ std::unique_

Range класс

Defines size of Buffer for one, two or three dimensions. Designed as copyable since not owning resources.

ShwaErrorDomain класс

Defines the error domain for Safe Hardware Acceleration.

ShwaException класс

Exception type could be thrown by application or other FC using Safe Hardware Acceleration. Safe Hardware Acceleration API is exception free and can only return an ErrorCode, but user code can transform this error to exception and throw if it’s alligned with system error handling architecture.

TaskHandler класс

Handles tasks execution on the selected Device Can be created only inside of the Queue otherwise it’s meaningless.
