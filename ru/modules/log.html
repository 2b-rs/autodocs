Поведение при ошибке

Ошибки Logging Framework или нижележащей системы не должны затрагивать процесс приложения: соответствующие интерфейсы не имеют возвращаемых значений и не генерируют исключений; вызовы при такой ошибке молча отбрасываются. SWS Log and Trace §7.1.6 «Initialization of the Logging framework» [SWS_LOG_00002]

Перед каждым использованием ara::log требуется ara::core::Initialize(). Если Framework не может обработать сообщения, например потому что связь с Daemon ещё не установлена или инициализация ещё не завершена, они помещаются в Queue, ограниченную logSink.queueSize. При превышении этого размера необходимо отбрасывать самые старые записи; то же правило действует после сбоя Daemon. SWS Log and Trace §7.8.1 «Startup» [SWS_LOG_00001] SWS Log and Trace §7.8.3 «Daemon crash»

Диаграмма активности показывает определённую спецификацией обработку Queue при недоступном Logging и при завершении работы. Источники: SWS Log and Trace §7.8.1 «Startup» [SWS_LOG_00001] SWS Log and Trace §7.8.2 «Shutdown» [SWS_LOG_00123].

После ara::core::Deinitialize() приложение не должно продолжать использовать Logging API и не может протоколировать дальнейшие сообщения. В этот момент Framework должен передать все ещё находящиеся в Queue сообщения настроенным Log-приёмникам. SWS Log and Trace §7.8.2 «Shutdown» [SWS_LOG_00123]
