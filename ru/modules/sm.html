От целевой машины к работающему приложению

ara::sm определяет состояния Machine и Function Group; конкретное управление процессами осуществляется через Execution Management. Таким образом, эта концепция отделяет предметное решение о целевом состоянии от запуска, остановки и последовательности процессов. Настраиваемые конечные автоматы

StateMachine объединяет состояния, переходы и списки действий. Управляющее приложение запрашивает переход; Уведомления о состоянии позволяют другим приложениям отслеживать текущее состояние. Контроллер уникален для каждой конфигурации StateMachine. SWS StateManagement §7.7 «StateMachine» [SWS_SM_00619]

Диаграмма взаимодействия для триггеров и сообщений о состоянии. Источники: SWS StateManagement §7.7.5 «State changes», SWS StateManagement §7.7.11 «State notification». Частичная интерпретация: назначение смоделированных ролей триггера ролям службы сводит конфигурацию к представлению связи.

Сеанс Update как координация состояний

UCM начинает взаимодействие через RequestUpdateSession(). Затем PrepareUpdate, VerifyUpdate и при необходимости PrepareRollback переводят затронутые StateMachines в настроенные для этого состояния. Решение о допустимости Update зависит от проекта и от состояния машины или автомобиля. Поведение при ошибке

Диапазон ошибок SmErrorDomain определяет SmErrc::kRejected для проблем S2R-Satellite при входе в Suspend-Mode или выходе из него. Отдельно тип UpdateStatusType описывает значения прогресса Update-сервиса: kRejected для запроса вне Update-Session и kFailed для неуспешной обработки. ResetMachineNotifier является для этого полем с Getter и Notifier; State Management устанавливает его, чтобы информировать UCM во время и после ResetMachine(). [SWS_SM_81240] [SWS_SM_91027] [SWS_SM_91106]

Для пути StateMachine ExecutionError используется Execution Management (через GetExecutionError() или undefinedStateCallback) или Platform Health Management (через RecoveryHandler) как ErrorCode Используется StateMachine, который управляет затронутым Function Group. Если StateMachine не помечен как ImpactedByUpdate, State Management устанавливает текущую обработку ошибок, оценивает ErrorRecoveryTable, завершает предыдущую обработку ActionList и немедленно переключается в настроенное последующее состояние. Для ошибок, которые не сопоставлены явно, запись ANY является обязательной. [SWS_SM_00670] [SWS_SM_00601] [SWS_SM_CONSTR_00014]

Диаграмма активности: ошибка процесса, сообщённая Execution Management или Platform Health Management, обрабатывается как ErrorCode соответствующей StateMachine; ErrorRecoveryTable определяет её целевое состояние и ActionList. Источники: SWS State Management §7.7.13 «StateMachine ErrorCode configuration and handling» [SWS_SM_00601] [SWS_SM_00670].

Ошибки вызова StateClient::SetState() с ExecErrc::kNoCommunication, kInvalidTransition или kInvalidMetaModelIdentifier сопоставляются с настроенным functionGroupTransitionRequestFailedError; без настройки следует использовать значение ошибки 1. При обновлении RequestUpdateSession() можно отклонить с помощью kOperationRejected из-за состояния машины; пока сеанс уже активен, kNotAllowedMultipleUpdateSessions является обязательным. ResetMachine() отклоняется без ранее успешно запрошенного сеанса обновления и устанавливает для ResetMachineNotifier значение kRejected вне сеанса обновления. Если переход к ContinueUpdate не удался после сброса, необходимо установить kFailed. [SWS_SM_00671] [SWS_SM_00672] [SWS_SM_91102] [SWS_SM_91100] [SWS_SM_00661] [SWS_SM_00663]
