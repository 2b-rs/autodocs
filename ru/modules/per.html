Роль и граница системы ara::per

Persistency предоставляет Adaptive Applications и другим Functional Clusters механизмы для сохранения информации в энергонезависимой памяти Machine. Данные сохраняются между циклами загрузки и зажигания. Обычно модуль выполняется как Library в Process приложения и с его правами SWS Persistency с. 10. Персистентные данные всегда локальны для ровно одного Process. Persistency намеренно не предоставляет дополнительного пути связи между Processes SWS Persistency с. 40, SWS Persistency с. 12 и сам не предоставляет Service Interfaces через ara::com SWS Persistency с. 155. Для сервисного удаленного доступа к Key-Value Storages в R25-11 предусмотрен отдельный кластер Remote Persistency на базе демона. Он, в свою очередь, использует интерфейс KeyValueStorage модуля Persistency SWS RemotePersistency с. 9, EXP SWArchitecture с. 95.

Помимо приложений, к Persistency напрямую обращаются также платформенные демоны:

  • Time Synchronization, Diagnostic Management и State Management используют KeyValueStorage EXP SWArchitecture с. 93.
  • Update and Configuration Management и Diagnostic Management требуют FileStorage SWS UCM с. 18, EXP SWArchitecture с. 92.

Библиотечные части таких кластеров используют собственную информацию Target Configuration от Persistency SWS Persistency с. 35. На нижнем уровне Persistency опирается на три службы:

  • операционную систему или аппаратные средства хранения с прямой адресацией SWS Persistency с. 15,
  • Cryptography для всех криптографических операций SWS Persistency с. 44,
  • база времени для временных меток файлов SWS Persistency с. 19.

Контекстная диаграмма: Persistency — это библиотека локального уровня процесса. Ее используют приложения и демоны платформы, а сама она опирается на операционную систему, Cryptography и базу времени. Источники: EXP SWArchitecture с. 93, EXP SWArchitecture с. 92, SWS VUCM с. 11, SWS RemotePersistency с. 9, SWS Persistency с. 19

Типы хранилищ, дескрипторы и привязка к экземпляру

Persistency предоставляет две раздельные формы доступа SWS Persistency с. 32:

  • Key-Value Storages: ключи с сопоставленными значениями, аналогично базе данных.
  • File Storages: множество файлов, аналогично каталогу.

Приложение может комбинировать несколько хранилищ обоих видов. API обеих форм полностью разделены. Они спроектированы вокруг ara::per::SharedHandle и ara::per::UniqueHandle, возвращаемых фабричными функциями. Напрямую эти классы сконструировать нельзя SWS Persistency с. 74, [SWS_PER_00459], [SWS_PER_00460].

Оба типа дескрипторов ведут себя по-разному:

  • OpenKeyValueStorage [SWS_PER_00052] и OpenFileStorage [SWS_PER_00116] возвращают копируемый SharedHandle [SWS_PER_00369].
  • Методы OpenFile* возвращают UniqueHandle на аксессор. Он не является копируемым [SWS_PER_00373], а может только перемещаться [SWS_PER_00371].
  • После перемещения (move) исходный дескриптор становится пустым. Перед каждым использованием его состояние необходимо проверять с помощью operator bool, так как другие операторы на пустом дескрипторе приводят к неопределенному поведению [SWS_PER_00398], [SWS_PER_00399].
  • Сами объекты Storage нельзя ни копировать, ни перемещать [SWS_PER_00322], [SWS_PER_00324].

Привязка к экземпляру осуществляется через ara::core::InstanceSpecifier. Он содержит путь shortName интерфейса PortPrototype, типизированного с помощью PersistencyKeyValueStorageInterface или PersistencyFileStorageInterface. Если он не соответствует ни одному интерфейсу, сконфигурированному для Executable, сообщается об ошибке SWS Persistency с. 100, SWS Persistency с. 114.

В качестве альтернативы хранилище может быть подключено через FunctionalClusterInteractsWithPersistencyDeploymentMapping. Данные развертывания находятся в PersistencyKeyValueStorage или PersistencyFileStorage SWS Persistency с. 34. На уровне платформы R25-11 определяет конфигурационный контейнер Persistency. Он содержит PersistencyGeneral (кратность 1), а также опциональные коллекции PersistencyKeyValueStorageCollection и PersistencyFileStorageCollection (каждая 0..1) SWS Persistency с. 219. В нормативных текстах R25-11 используется термин «Target Configuration» там, где в более старых местах документации использовался «manifest» [SWS_PER_00334], [SWS_PER_00357].

Диаграмма кооперации: от InstanceSpecifier фабричная функция ведет к разделяемому дескриптору хранилища, а оттуда — к эксклюзивным файловым аксессорам. Источники: SWS Persistency с. 82, EXP SWArchitecture с. 87, [SWS_PER_00375], [SWS_PER_00376], [SWS_PER_00377]

Key-Value Storage: от открытия до синхронизации

При открытии Persistency создает временное хранилище, в котором выполняются все операции. Приложение сохраняет его с помощью SyncToStorage или возвращает его с помощью DiscardPendingChanges к последнему сохраненному состоянию SWS Persistency с. 63, [SWS_PER_00049], [SWS_PER_00365].

  • SetValue создает пары или перезаписывает их. Если новое значение имеет другой тип данных, функция возвращает kDataTypeMismatch [SWS_PER_00046]. Смена типа возможна только в том случае, если пара была предварительно удалена SWS Persistency с. 65.
  • GetValue существует в виде варианта с возвращаемым значением [SWS_PER_00332] и в виде варианта с выходным параметром для повторного доступа к очень большим значениям [SWS_PER_00044].
  • Для сохранения поддерживаются все типы данных платформы, а также сериализованные бинарные данные в виде Vector или Span для ara::core::Byte SWS Persistency с. 66.

Запросы, такие как GetAllKeys и KeyExists, видят состояние транзакции, а не физическое хранилище. Они точны только при отсутствии параллельных изменений [SWS_PER_00042], [SWS_PER_00043]. GetCurrentValueSize возвращает размер значения [SWS_PER_00554].

Даже после SyncToStorage физическая запись может быть отложена в зависимости от реализации и файловой системы. При внезапном пропадании питания данные могут быть потеряны или повреждены при отсутствии избыточности SWS Persistency с. 64, SWS Persistency с. 15.

Диаграмма последовательности: изменения сначала попадают во временное хранилище. Лишь SyncToStorage при необходимости шифрует их, добавляет избыточность и выполняет запись. Источники: EXP SWArchitecture с. 230, EXP SWArchitecture с. 228, SWS Persistency с. 42, [SWS_PER_00049]

Диаграмма состояний: открытый Key-Value Storage переключается между синхронизированным состоянием и состоянием ожидающих изменений. Операции Recover и Reset возможны только в закрытом состоянии. Источники: SWS Persistency с. 63, SWS Persistency с. 99, SWS Persistency с. 100, [SWS_PER_00365]

File Storage: открытие, чтение и запись файлов

Через дескриптор FileStorage приложение перечисляет файлы [SWS_PER_00110], проверяет их существование [SWS_PER_00112] или удаляет их [SWS_PER_00111]. Каждый тип доступа существует в трех перегрузках: без режима, с OpenMode и дополнительно с пользовательским буфером, например [SWS_PER_00376], [SWS_PER_00114], [SWS_PER_00430].

  • Для чтения работа начинается с начала файла [SWS_PER_00376].
  • OpenFileWriteOnly по умолчанию усекает файл и создает его при необходимости [SWS_PER_00377].
  • OpenFileReadWrite также создает отсутствующие файлы [SWS_PER_00375].
  • Значения OpenMode можно комбинировать с | и |=, если они не противоречат друг другу [SWS_PER_00147], [SWS_PER_00144], [SWS_PER_00434].
  • При kAppend Persistency перед каждой записью устанавливает позицию в конец файла SWS Persistency с. 71.

Функции чтения и записи аксессоров:

  • Чтение посимвольно (PeekChar, GetChar), потекстово (ReadText, ReadLine) или в бинарном виде (PeekByte, GetByte, ReadBinary) [SWS_PER_00167], [SWS_PER_00168], [SWS_PER_00420], [SWS_PER_00119], [SWS_PER_00421].
  • Функции позиционирования GetPosition, SetPosition, MovePosition и IsEof в R25-11 принадлежат классу ara::per::FileAccessor [SWS_PER_00162], [SWS_PER_00164], [SWS_PER_00107].
  • Запись с помощью WriteText или WriteBinary. Время сохранения данных определяется реализацией; SyncToFile форсирует его [SWS_PER_00166], [SWS_PER_00423], [SWS_PER_00122].
  • operator<< является лишь вспомогательной функцией для удобства и молча игнорирует ошибки [SWS_PER_00125].
  • SetFileSize может только уменьшать размер файла [SWS_PER_00428], SWS Persistency с. 72.

Файл закрывается, когда его UniqueHandle выходит из области видимости. Изменения в нем сохраняются не позднее повторного открытия или вызова ara::core::Deinitialize SWS Persistency с. 69. Если File Storage закрывается, закрываются и все еще открытые файлы. Использование UniqueHandle после этого приводит к неопределенному поведению SWS Persistency с. 41.

GetFileInfo возвращает время создания, изменения и доступа в наносекундах с 1970 года, а также FileCreationState и FileModificationState [SWS_PER_00438], [SWS_PER_00441], [SWS_PER_00435], [SWS_PER_00436]. GetCurrentFileSize учитывает только содержимое файла. GetCurrentFileStorageSize дополнительно учитывает метаданные, избыточность и резервные копии [SWS_PER_00407], [SWS_PER_00406], SWS Persistency с. 73.

Диаграмма последовательности: файл записывается через эксклюзивный аксессор и затем считывается построчно до конца файла. Шифрование/расшифрование и избыточность остаются прозрачными для приложения. Источники: EXP SWArchitecture с. 229, EXP SWArchitecture с. 227, [SWS_PER_00122], [SWS_PER_00107]

Установка, обновление и сброс персистентных данных

Update and Configuration Management управляет установкой, обновлением, финализацией, откатом (roll-back) и удалением программного обеспечения. Персистентные данные обрабатываются либо явно через UpdatePersistency на фазе верификации, либо неявно при открытии хранилища SWS Persistency с. 51, [SWS_PER_00357]. При этом Persistency сравнивает две сохраненные версии с текущей конфигурацией: contract version (структурная разметка) и deployment version (предустановленное содержимое) SWS Persistency с. 11, SWS Persistency с. 11.

  • Если персистентные данные отсутствуют, они инициализируются. При этом записи получают свое initValue SWS Persistency с. 55, SWS Persistency с. 56.
  • Если deployment version выше, Persistency сначала создает резервную копию. Затем оно выполняет обновление согласно стратегии обновления keepExisting, overwrite или delete SWS Persistency с. 57, SWS Persistency с. 53.

Через RegisterApplicationDataUpdateCallback приложение может выполнять собственные миграции данных. Функция обратного вызова (callback) получает хранилище и последнюю использованную contract version. Она вызывается из UpdatePersistency, OpenKeyValueStorage или OpenFileStorage [SWS_PER_00356], SWS Persistency с. 75. После успешной верификации CleanUpPersistency удаляет резервные копии [SWS_PER_00567], SWS Persistency с. 61.

Новое в R25-11:

  • С помощью CheckForManifestUpdate и ReloadPersistencyManifest работающее приложение распознает конфигурацию, установленную UCM, и считывает ее заново. Хранилища обновляются только после закрытия [SWS_PER_00576], [SWS_PER_00577].
  • RegisterDataUpdateIndication сообщает об обновлениях отслеживаемых элементов [SWS_PER_00578].

Для сброса служат ResetKeyValueStorage, ResetAllFiles, ResetKey и ResetFile. Они восстанавливают состояние, как после повторной установки из текущей Target Configuration [SWS_PER_00334], [SWS_PER_00336], [SWS_PER_00426], [SWS_PER_00338].

В случае ResetPersistency R25-11 отличается от формулировки документации R23-11. Там описан сброс до состояния при установке SWS Persistency с. 54. Нормативным в R25-11 является следующее: функция удаляет все содержимое всех хранилищ, и они создаются заново только при следующем вызове Open* [SWS_PER_00358].

Диаграмма деятельности: при открытии или при UpdatePersistency сравнение версий определяет выбор между установкой, обновлением с резервным копированием, откатом (roll-back) и неизмененным доступом. Источники: SWS Persistency с. 51, SWS Persistency с. 57, SWS Persistency с. 61, EXP SWArchitecture с. 92

Параллелизм, ресурсы и меры защиты

Внутри Process предусмотрен параллельный доступ из нескольких потоков. SharedHandle можно скопировать в другие потоки, либо хранилище открывается там повторно SWS Persistency с. 40. Хранилище закрывается только тогда, когда все связанные с ним SharedHandle выходят из области видимости [SWS_PER_00052].

Для файлов и операций управления действуют правила исключения:

  • Файлы являются эксклюзивными: открытие или изменение уже открытого файла возвращает kResourceBusy SWS Persistency с. 41.
  • Функции Recover и Reset хранилища завершаются сбоем, пока оно открыто SWS Persistency с. 101, SWS Persistency с. 116.
  • UpdatePersistency завершается сбоем, пока используется SharedHandle SWS Persistency с. 76.

Для каждого хранилища можно настроить минимальный размер и активно контролируемый верхний предел maximumAllowedSize SWS Persistency с. 62. Превышение приводит к kQuotaExceeded. Количество файлов, превышающее maxNumberOfFiles, приводит к kTooManyFiles SWS Persistency с. 39. Занятый объем запрашивают GetCurrentKeyValueStorageSize и GetCurrentFileStorageSize [SWS_PER_00405], [SWS_PER_00406].

Меры защиты определяются при развертывании:

  • Шифрование и аутентификация с помощью MAC прозрачны для приложения SWS Persistency с. 42.
  • Избыточность на основе CRC, хеша или копий является настраиваемой SWS Persistency с. 45. Как правило, только репликация позволяет выполнить восстановление SWS Persistency с. 12.
  • Для обращений к конфигурации определены сообщения журналов DLT, в настоящее время в статусе DRAFT SWS Persistency с. 104.

Поведение при ошибке

Об ошибках сообщается через ara::core::Result с кодами из ara::per::PerErrc. Значения 0–255 зарезервированы AUTOSAR, начиная с 256 поставщики стека могут добавлять собственные коды [SWS_PER_00311], SWS Persistency с. 37. GetPerDomain возвращает глобальный домен ошибок [SWS_PER_00352]. Те, кто предпочитает исключения, могут использовать ThrowAsException [SWS_PER_00350]. Если память не может быть выделена, Persistency завершает Process с помощью ara::core::Abort SWS Persistency с. 74.

Типичные прикладные ошибки:

  • kKeyNotFound или kFileNotFound для отсутствующих элементов SWS Persistency с. 64, SWS Persistency с. 68
  • kInvalidOpenMode для недопустимых режимов при открытии SWS Persistency с. 68
  • kIsEof при чтении в конце файла SWS Persistency с. 39
  • kInitValueNotAvailable, если ResetKey не находит начального значения SWS Persistency с. 54

При ошибках записи спецификация определяет состояние файла для каждого кода ошибки [SWS_PER_00166], [SWS_PER_00423], SWS Persistency с. 152:

  • kPhysicalStorageFailure: состояние неизвестно.
  • kEncryptionFailed: сохраненной остается более ранняя версия.
  • kOutOfStorageSpace: часть, превышающая квоту, отбрасывается.

Ошибки данных, которые можно устранить с помощью избыточности, Persistency неявно исправляет при доступе. Ошибка доходит до приложения только тогда, когда избыточность не срабатывает SWS Persistency с. 79. В обоих случаях RegisterRecoveryReportCallback информирует приложение. RecoveryReportKind отличает успешные восстановления (например, kKeyRecovered) от неудавшихся (например, kKeyRecoveryFailed). Кроме того, сообщается о затронутых элементах и затронутых избыточных экземплярах [SWS_PER_00433], [SWS_PER_00432], SWS Persistency с. 47.

Затем приложение может целенаправленно вызвать RecoverKey, RecoverFile, RecoverKeyValueStorage или RecoverAllFiles. Эти функции работают по принципу «best effort»: после этого содержимое может оказаться устаревшим, сброшенным до начальных значений или утраченным [SWS_PER_00427], [SWS_PER_00337], [SWS_PER_00333], [SWS_PER_00335]. Файлы, измененные в результате восстановления, можно распознать по FileModificationState SWS Persistency с. 120.

Диаграмма деятельности: проблема с избыточностью либо прозрачно исправляется и регистрируется, либо о ней сообщается как об ошибке. Во втором случае приложение принимает решение о вызове функций Recover или Reset. Источники: SWS Persistency с. 79, SWS Persistency с. 47, SWS Persistency с. 48, [SWS_PER_00433]

Checks for updates of the Persistency Target Configuration. This method can be used to detect configuration updates that are installed by UCM while the Adaptive Application that uses Persistency is running. To re-read the updated Target Configuration, the Adaptive Application needs to call ara::per:: ReloadPersistencyManifest.

OpenFileStorage функция

Opens a File Storage. OpenFileStorage will fail with kResourceBusy when the File Storage is currently being modified by a call from another thread to UpdatePersistency, CleanUpPersistency, ResetPersistency, RecoverAllFiles, or ResetAllFiles. Because multiple threads can access the same File Storage concurrently, the File Storage might not be closed when the SharedHandle returned by this function goes out of scope. It will only be closed when all SharedHandles that refer to the same File Storage went out of scope.

ara::core::Result< SharedHandle< FileStorage > > OpenFileStorage (const ara::core::InstanceSpecifier &fs) noexcept;

RecoverAllFiles функция

Recovers a File Storage, including all files. RecoverAllFiles recovers a File Storage when the redundancy checks fail. It will fail with kResourceBusy when the File Storage is currently open, or when it is modified by a call from another thread to UpdatePersistency, CleanUpPersistency, ResetPersistency, RecoverAllFiles, or ResetAllFiles. This method does a best-effort recovery of all files. After recovery, files might show outdated or initial content, or might be lost.

ara::core::Result< void > RecoverAllFiles (const ara::core::Instance Specifier &fs) noexcept;
RecoverKeyValueStorage функция

Recovers a Key-ValueStorage. RecoverKeyValueStorage allows to recover a Key-Value Storage when the redundancy checks fail. It will fail with kResourceBusy when the Key-Value Storage is currently open, or when it is modified by a call from another thread to UpdatePersistency, CleanUpPersistency, Reset Persistency, RecoverKeyValueStorage, or ResetKeyValueStorage. This method does a best-effort recovery of all key-value pairs. After recovery, keys might show outdated or initial value, or might be lost.

ara::core::Result< void > RecoverKeyValueStorage (const ara::core::InstanceSpecifier &kvs) noexcept;
RegisterApplicationDataUpdateCallback функция

Registers an application data update callback with Persistency. The provided callback function will be called by Persistency if an update of stored application data might be necessary. This decision is based on the contract versions. The contract version that last accessed Persistency is provided as an argument to the callback, as well as the ara::core::InstanceSpecifier referring to the updated Key- Value Storage or File Storage. Based on this information, the Adaptive Application can decide which updates are actually necessary, e.g. a migration from any older contract version could be supported, with different steps required for each of these. The provided function will be called from the context of ara::per::UpdatePersistency, ara::per::OpenKeyValueStorage, or ara::per::OpenFileStorage.

void RegisterApplicationDataUpdateCallback (std::function< void(const ara::core::InstanceSpecifier &storage, ara::core::String contract Version)> appDataUpdateCallback) noexcept;
RegisterDataUpdateIndication функция

Registers a data update indication callback with Persistency. The provided callback function will be called by Persistency when an update of stored data happened. It will be called from the context of ara::per::UpdatePersistency, ara:: per::OpenKeyValueStorage, or ara::per::OpenFileStorage.

void RegisterDataUpdateIndication (std::function< void(const ara::core::InstanceSpecifier &updatedStorage, ara::core::StringView updatedElement)> dataUpdateIndication, ara::core::InstanceSpecifier monitoredStorage, ara::core::Vector< ara::core::String > monitored Elements) noexcept;

Register a recovery reporting callback with Persistency. This callback can be used in safety-aware Adaptive Applications to detect actions of the Persistency that are related to the correctness of the persisted data and the reliability of the storage.

void RegisterRecoveryReportCallback (std::function< void(const ara::core::InstanceSpecifier &storage, ara::per::RecoveryReportKind recoveryReportKind, ara::core::Vector< ara::core::String > reported Elements, ara::core::Vector< std::uint8_t > reportedInstances)> recoveryReportCallback) noexcept;
ReloadPersistencyManifest функция

Re-reads the Target Configuration. This method can be used to prepare for updates of the Key-Value Storages and File Storages of Persistency after a new Target Configuration was installed by UCM while the Adaptive Application that uses Persistency is running. Storages are only updated after closing them, either when they are opened again or by an explicit call to ara:: per::UpdatePersistency.

ara::core::Result< void > ReloadPersistencyManifest () noexcept;
ResetAllFiles функция

Resets a File Storage, including all files. ResetAllFiles resets a File Storage to the initial state, containing only the files which were deployed from the Target Configuration, with their initial content. Afterwards, the File Storage will appear as if it was newly installed from the current Target Configuration. It will fail with kResourceBusy when the File Storage is currently open, or when it is modified by a call from another thread to UpdatePersistency, CleanUpPersistency, ResetPersistency, RecoverAllFiles, or ResetAllFiles.

ara::core::Result< void > ResetAllFiles (const ara::core::Instance Specifier &fs) noexcept;
ResetKeyValueStorage функция

Resets a Key-Value Storage to the initial state. ResetKeyValueStorage allows to reset a Key-Value Storage to the initial state, containing only key-value pairs which were deployed from the Target Configuration, with their initial values. Afterwards, the Key-Value Storage will appear as if it was newly installed from the current Target Configuration. It will fail with kResourceBusy when the Key-Value Storage is currently open, or when it is modified by a call from another thread to UpdatePersistency, CleanUpPersistency, Reset Persistency, RecoverKeyValueStorage, or ResetKeyValueStorage.

ara::core::Result< void > ResetKeyValueStorage (const ara::core::InstanceSpecifier &kvs) noexcept;

Resets all Key-Value Storages and File Storages by entirely removing their content. The Key-Value Storages and File Storages will be re-created when ara::per:: OpenFileStorage or ara::per::OpenKeyValueStorage is called next time.
