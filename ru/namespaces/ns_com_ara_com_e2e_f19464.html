Предоставляет типы, статусы проверки и домены ошибок для сквозной защиты (End-to-End) адаптивной коммуникации.

Пространство имен ara::com::e2e определяет типы, состояния и коды ошибок для сквозной защиты (End-to-End) адаптивной коммуникации. Потребляющие приложения оценивают принятые выборки данных на основе ProfileCheckStatus, а также SMState и могут использовать данные только при наличии состояния kValid ([SWS_CM_90422]). На стороне поставщика через TransportFaultConditionHandler могут отслеживаться такие ошибки, как нарушение дедлайнов или потери пакетов ([SWS_CM_00091]). Ошибочные состояния стандартизированно отображаются через домен ошибок ComE2EErrorDomain.

Контекст

Пространство имен ara::com::e2e предоставляет типы данных, перечисления статусов и структуры обработки ошибок для сквозной защиты (E2E) в коммуникационном модуле AUTOSAR Adaptive. Его основная задача заключается в прозрачной и стандартизированной фиксации ошибок передачи и целостности данных на прикладном и транспортном уровнях.

В рамках архитектуры коммуникации пространство имен взаимодействует с несколькими ключевыми компонентами:

  • Поставщик сервиса (Skeleton): на стороне поставщика условия ошибок передачи могут отслеживаться через указатели на функции. Тип TransportFaultConditionHandler ([SWS_CM_00092]) позволяет регистрировать и отменять регистрацию соответствующих обратных вызовов мониторинга для всех методов Skeleton (AUTOSAR_AP_EXP_SWArchitecture с. 68), а также для вызовов геттеров и сеттеров отдельных полей Skeleton (AUTOSAR_AP_EXP_SWArchitecture с. 69).
  • Потребители и данные событий (SamplePtr): на стороне потребителя принятые выборки данных подвергаются проверке E2E. Результат проверки отдельной выборки отображается через ProfileCheckStatus ([SWS_CM_90421]), тогда как общее состояние мониторинга фиксируется через SMState ([SWS_CM_90422]).
  • Обработка ошибок: домен ошибок ComE2EErrorDomain (AUTOSAR_AP_EXP_ARAComAPI с. 9) и соответствующие коды ошибок ComE2EErrc ([SWS_CM_10474]) бесшовно интегрируют ошибки E2E в модель архитектуры ошибок ara::core. Для обработки исключений существует класс ComE2EException.

Контекстная диаграмма: взаимодействие поставщика сервиса (Skeleton), управления выборками (SamplePtr) и домена ошибок ara::com::e2e. Источники: AUTOSAR_AP_EXP_SWArchitecture с. 68, [SWS_CM_90421], [SWS_CM_10474].

Жизненный цикл и мониторинг состояния

Мониторинг E2E имеет фазу жизненного цикла на основе состояний, которая связана с приемом выборок данных через событие. Состояние представляется перечислением SMState ([SWS_CM_90422]):

  • kInit: после инициализации еще нет достаточного количества выборок данных с успешной проверкой E2E; выборки использовать нельзя.
  • kValid: передача выборок данных согласно проверке E2E функционирует надлежащим образом; выборки разрешено потреблять.
  • kInvalid: в пределах временного окна E2E получено слишком мало безошибочных или слишком много ошибочных выборок; использовать выборки нельзя.
  • kNoData: данные от издателя еще вообще не поступали.
  • kStateMDisabled: автомат состояний E2E административно отключен.
  • kIncompatibleQoS: сконфигурированные политики качества обслуживания (QoS) обеих конечных точек коммуникации не совпадают.

Параллельно с этим ProfileCheckStatus возвращает циклический статус отдельной выборки данных ([SWS_CM_90421]): помимо статуса успеха kOk проверка дифференцирует повторы счетчика (kRepeated), недопустимые скачки счетчика (kWrongSequence), а также ошибки проверки данных (kError, такие как ошибки CRC, длины или Data-ID). При отключенной проверке возвращается kCheckDisabled.

Фундаментальным предварительным условием для обработки данных является: принятая выборка данных может использоваться приложением только тогда, когда выполняется SMState == kValid и проверка выборки данных (GetProfileCheckStatus) не привела к ошибке (kError) ([SWS_CM_90422]).

Путь использования

Типичный путь использования охватывает проверку принятых данных событий на стороне потребителя, а также конфигурацию сообщений о транспортных ошибках на стороне поставщика:

  1. Запрос статуса выборки данных: после приема выборки данных через ara::com::SamplePtr потребляющее приложение вызывает GetProfileCheckStatus(), чтобы определить специфический результат проверки выборки ([SWS_CM_90421]).
  2. Проверка состояния мониторинга: приложение вызывает GetSMState() для запроса агрегированного состояния автомата состояний E2E ([SWS_CM_90422]).
  3. Обработка или реагирование на ошибку: если имеет место SMState == kValid и ошибка не зарегистрирована, выполняется обработка полезных данных ([SWS_CM_90422]). В противном случае ошибка E2E обрабатывается через стандартизированные структуры ошибок или передается дальше с помощью MakeErrorCode ([SWS_CM_12511]).
  4. Обработка транспортных ошибок на Skeleton: поставщики сервисов для мониторинга своих методов и операций с полями регистрируют TransportFaultConditionHandler ([SWS_CM_00092], AUTOSAR_AP_EXP_SWArchitecture с. 68, AUTOSAR_AP_EXP_SWArchitecture с. 69). При возникновении ошибки, связанной с транспортом, вызывается обратный вызов с соответствующим TransportFaultCondition ([SWS_CM_00091]).

Диаграмма последовательности: порядок вызовов для валидации принятых выборок данных и обработки ошибок. Источники: [SWS_CM_90421], [SWS_CM_90422], [SWS_CM_12511].

Сценарии ошибок

В случае сбоя пространство имен предоставляет два раздельных механизма, отображающих различные источники ошибок:

Транспортные ошибки сигнализируются через перечисление TransportFaultCondition ([SWS_CM_00091]):

  • kSampleRejected: выборка данных была отброшена на уровне 4 или выше из-за исчерпания ресурсов на конечной точке.
  • kDeadlineMissed: выборка данных превысила сконфигурированный интервал крайнего срока (дедлайн).
  • kSampleLost: обнаружена потеря выборок данных (например, пропуск в порядковых номерах).

Ошибки протокола и проверки E2E-преобразования классифицируются через ComE2EErrc ([SWS_CM_10474]). Эти коды ошибок охватывают повторы счетчика (kRepeated), скачки счетчика за пределы допустимой дельты (kWrongSequence), ошибки CRC/длины (kError), отсутствие новых данных (kNoNewData), а также ошибки удаленного сервиса (kUnspecifiedE2EError). Для создания экземпляров типа ara::core::ErrorCode служит функция MakeErrorCode ([SWS_CM_12511]), тогда как GetComE2EErrorDomain возвращает ссылку на экземпляр-синглтон ComE2EErrorDomain ([SWS_CM_12510]). Интерпретация: класс ComE2EException, предположительно, находит применение прежде всего тогда, когда ошибки отображаются в путях выполнения с включенными исключениями C++.

Настоящее руководство обобщает элементы спецификации пространства имен ara::com::e2e для AUTOSAR Adaptive R25-11.

Перечисление ComE2EErrc определяет специфические коды ошибок для сквозной защиты (E2E) в пространстве имён ara::com::e2e на основе ara::core::ErrorDomain::CodeType [SWS_CM_10474]. Внутри домена ошибок ara::com::e2e::ComE2EErrorDomain тип предоставляется через псевдоним типа Errc [SWS_CM_12504].

Значения перечислителей описывают детерминированные результаты проверок и состояния ошибок [SWS_CM_10474]:

  • kRepeated: данные имеют повторяющееся значение счётчика [SWS_CM_10474].
  • kWrongSequence: проверки прошли успешно, однако скачок счётчика превысил допустимую дельту [SWS_CM_10474].
  • kError: произошла ошибка, не зависящая от счётчика (например, неверный CRC, неверная длина или недействительный Data-ID), либо результат функции проверки был неудовлетворительным [SWS_CM_10474].
  • kNoNewData: новые данные отсутствуют [SWS_CM_10474].
  • kUnspecifiedE2EError: удалённый сервис возвратил неуточнённую ошибку E2E [SWS_CM_10474].

При обработке запроса на стороне сервера ComE2EErrc передаётся в качестве аргумента errorCode методу E2EErrorHandler скелетона, если E2E-проверка сообщения завершается сбоем [SWS_CM_10470], AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.3.3 «E2E error notification». Если новое сообщение запроса отсутствует, обработчик обязательно вызывается с ComE2EErrc::kNoNewData, а также dataID = 0 и messageCounter = 0 [SWS_CM_00047]. После выполнения обработчика ошибок выполняется E2E-защита ответного сообщения [SWS_CM_90481].

В отношении параллелизма и граничных условий действует следующее: метод E2EErrorHandler не специфицирован как реентерабельный и не является exception safe [SWS_CM_10470]. Его регистрация выполняется строго статически до времени выполнения; динамическая регистрация или отмена регистрации не предусмотрены AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.3.3 «E2E error notification». Кроме того, серверное приложение при ошибках CRC не должно полагаться на переданный Data-ID, так как он может быть повреждён [SWS_CM_10470].

      Использование и контекст вызова
      

      Перечисление ProfileCheckStatus в пространстве имен ara::com::e2e представляет результат проверки End-to-End (E2E) для отдельного принятого сэмпла данных [SWS_CM_90421]. При приеме защищенного E2E сэмпла управление коммуникацией выполняет внутри GetNewSamples() подпрограмму E2E_check, возвращающую ProfileCheckStatus [SWS_CM_90411]. Этот статус сохраняется непосредственно в соответствующем ara::com::SamplePtr [SWS_CM_90413]. Получатели обращаются к статусу проверки синхронно и безопасным относительно исключений образом через метод GetProfileCheckStatus() класса ara::com::SamplePtr [SWS_CM_00042], [SWS_CM_90420].
      

      Значения статуса и обработка ошибок
      

      В качестве базового типа служит std::uint8_t [SWS_CM_90421]. Перечисление определяет следующие состояния для индивидуального анализа ошибок:
      

        

      • kOk: все проверки сэмпла в текущем цикле, включая проверку счетчика, прошли успешно [SWS_CM_90421].
        • 

      • kRepeated: принятый сэмпл данных содержит повторяющееся значение счетчика [SWS_CM_90421].
        • 

      • kWrongSequence: проверка прошла успешно, однако имеет место недопустимый скачок счетчика выше разрешенной дельты [SWS_CM_90421].
        • 

      • kError: произошла ошибка, не связанная со счетчиком, например, неверная CRC, некорректная длина или ошибочный Data ID [SWS_CM_90421].
        • 

      • kCheckDisabled: указывает, что проверка E2E не активна, если EndToEndTransformationComSpecProps.disableEndToEndCheck было сконфигурировано в TRUE [SWS_CM_90421].
