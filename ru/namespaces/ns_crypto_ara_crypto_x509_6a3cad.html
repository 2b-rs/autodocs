Предоставляет интерфейсы и структуры данных для представления, конфигурации и валидации сертификатов X.509.

Пространство имен ara::crypto::x509 предоставляет интерфейсы и типы данных для управления, определения использования и валидации сертификатов X.509, а также ответов OCSP в AUTOSAR Adaptive. Через контекст валидации CertificateValidationCtx пути сертификатов проверяются с параметризацией на основе таких опций, как CertificateValidationOptions [SWS_CRYPT_50107]. Результат возвращается структурированно через значения статуса, такие как CertificateValidationStatus [SWS_CRYPT_40203], при этом онлайн-проверки отзыва по умолчанию неактивны и должны настраиваться явно.

Контекст

Пространство имен ara::crypto::x509 предоставляет центральные интерфейсы и типы данных для обработки и валидации структур сертификатов X.509 в AUTOSAR Adaptive Platform. Модель интерфейсов включает представление цифровых сертификатов (Certificate), запросов на подписание сертификатов (CertSignRequest), Distinguished Names (X509DN), а также ответов OCSP (OcspResponse). Инстанцирование и управление этими криптографическими артефактами обычно осуществляется через интерфейс провайдера X509Provider (интерпретация: провайдер функционирует как центральный фабричный экземпляр для объектов X.509).

Для сертификатов пространство имен определяет стандартизированные назначения использования ключей через тип X509KeyUsage [SWS_CRYPT_40101]. К битовым константам относятся создание цифровых подписей kConstrDigitalSignature [SWS_CRYPT_40151], неотказуемость kConstrNonRepudiation [SWS_CRYPT_40152], шифрование ключей kConstrKeyEncipherment [SWS_CRYPT_40153], шифрование данных kConstrDataEncipherment [SWS_CRYPT_40154], согласование ключей kConstrKeyAgreement [SWS_CRYPT_40155], подписание сертификатов kConstrKeyCertSign [SWS_CRYPT_40156], подписание CRL kConstrCrlSign [SWS_CRYPT_40157], а также только шифрование kConstrEncipherOnly [SWS_CRYPT_40158] и только расшифрование kConstrDecipherOnly [SWS_CRYPT_40159]. Дополнительно X509ExtendedKeyUsage [SWS_CRYPT_50097] описывает расширенные области применения, такие как TLS-аутентификация сервера kServerAuth [SWS_CRYPT_50098], TLS-аутентификация клиента kClientAuth [SWS_CRYPT_50099], подписание кода kCodeSigning [SWS_CRYPT_50100], защита электронной почты kEmailProtection [SWS_CRYPT_50101], службы меток времени kTimeStamping [SWS_CRYPT_50102] и подписание OCSP kOCSPSigning [SWS_CRYPT_50103].

Контекстная диаграмма: взаимодействие основных интерфейсов для управления сертификатами и валидации путей. Источники: [SWS_CRYPT_40101], [SWS_CRYPT_50097]

Путь использования

Основной рабочий процесс в пространстве имен заключается в проверке путей сертификатов через CertificateValidationCtx. Поведение валидации параметризуется с помощью битовых масок типа CertificateValidationOptions [SWS_CRYPT_50107]. По умолчанию проверка пути выполняется без подключения онлайн-запросов статуса сертификата с помощью опции kOcspOff [SWS_CRYPT_50114]. Если требуется проверить действительность онлайн, можно активировать проверку либо всей цепочки через kOcspResponseCompleteChain [SWS_CRYPT_50112], либо исключительно целевого сертификата посредством kOcspResponseTargetOnly [SWS_CRYPT_50113].

Для специфических сценариев проверки дополнительные опции валидации позволяют переопределять стандартные проверки: так, временные границы действительности могут быть проигнорированы с помощью kIgnoreNotBefore [SWS_CRYPT_50108] и kIgnoreNotAfter [SWS_CRYPT_50109]. Также можно отключить анализ ранее импортированных списков отзыва сертификатов (CRL) с помощью kIgnoreCrl [SWS_CRYPT_50111] или подавить сигнализацию об ошибках при неизвестных критических расширениях через kIgnoreUnknownCriticalExtensions [SWS_CRYPT_50110]. После выполнения валидации контекст возвращает объект результата CertificateValidationResult (интерпретация: вызов валидации связывает целевой сертификат, опции проверки и опциональные ответы OCSP и инкапсулирует итог в классе результата).

Диаграмма последовательности: процесс валидации сертификата с использованием контекста проверки и анализ результата. Источники: [SWS_CRYPT_50107], [SWS_CRYPT_40203]

Сценарии ошибок

Результат проверки пути сертификата детально раскрывается через перечисление CertificateValidationStatus [SWS_CRYPT_40203]. Успешная валидация сигнализируется значением kValid (= 0). В случае сбоя проверки специфические значения статуса указывают точную причину:

  • kInvalidSignature (= 1): подпись внутри пути сертификата не удалось успешно верифицировать.
  • kNoPathToTrustedCertificate (= 3): не удалось построить путь к корневому сертификату, классифицированному как доверенный.
  • kExpired (= 4): сертификат превысил срок действия (поле notAfter).
  • kFuture (= 5): срок действия сертификата согласно полю notBefore еще не начался.
  • kRevoked (= 6): сертификат был отозван; этот статус возникает в результате импортированных CRL или активной проверки OCSP через kOcspResponseCompleteChain или kOcspResponseTargetOnly.
  • kUnknownOcspStatus (= 7): подключенный ответ OCSP возвращает для сертификата состояние «unknown».
  • kUnknownCriticalExtension (= 8): сертификат содержит неизвестное критическое расширение, которое не было проигнорировано ни посредством kIgnoreUnknownCriticalExtensions, ни предварительной обработкой исключений.

Если в процессе валидации обрабатываются онлайн-запросы статуса, перечисление OcspResponseStatus [SWS_CRYPT_40001] сигнализирует результат опроса протокола. Наряду с успешным подтверждением ответа (kSuccessful = 0) могут возникать протокольные и серверные ошибки: недействительные запросы (kMalformedRequest = 1), внутренние ошибки издателя (kInternalError = 2), временная перегрузка (kTryLater = 3), необходимость подписи (kSigRequired = 5) или отсутствие авторизации (kUnauthorized = 6).
