Управляет жизненным циклом процессов, отслеживает состояния выполнения и координирует переходы состояний групп функций.

Пространство имён предоставляет интерфейсы для управления процессами и управления группами функций на AUTOSAR Adaptive Platform. Процессы используют клиент, чтобы после успешной инициализации сообщать своё состояние выполнения kRunning в Execution Management [SWS_EM_02000]. State Management запрашивает через интерфейсы переходы групп функций, тогда как недопустимые смены состояний или ошибки коммуникации фиксируются через стандартизированные коды ошибок [SWS_EM_02281]. Строгое соблюдение порядка переходов является обязательным требованием.

Контекст

Пространство имён ara::exec предоставляет интерфейсы Execution Management на AUTOSAR Adaptive Platform. Модуль отвечает за запуск, управление и мониторинг процессов, а также координацию состояний системы и групп функций верхнего уровня. К центральным действующим лицам относятся процессы приложений, State Management и само Execution Management. Процессы используют класс ExecutionClient, чтобы сообщать своё внутреннее состояние времени выполнения в Execution Management. State Management, в свою очередь, использует интерфейс StateClient для запроса смены состояний между группами функций (FunctionGroup и FunctionGroupState). Для событий ошибок на уровне группы функций используется псевдоним типа ExecutionError [SWS_EM_02541], который может передаваться через ExecutionErrorEvent.

Жизненный цикл

Жизненный цикл выполнения процесса управляется через Execution Management [SWS_EM_02000]. После диспетчеризации вновь запущенный процесс изначально находится в неявном состоянии Initializing, в котором программный код приложения ещё не выполнялся. Execution Management предполагает, что это состояние инициализации продолжается до тех пор, пока процесс через свой ExecutionClient активно не сообщит о состоянии ExecutionState::kRunning [SWS_EM_02000]. Перечисление ExecutionState строго ограничивается теми состояниями, о которых процессы могут сообщать в Execution Management, и поэтому содержит исключительно состояние kRunning [SWS_EM_02000]. Если Execution Management запрашивает завершение, процесс переходит в фазу Terminating, которая завершается окончательным прекращением процесса [SWS_EM_02000].

Диаграмма состояний: жизненный цикл процесса с точки зрения Execution Management с неявными состояниями и сообщением kRunning. Источники: [SWS_EM_02000]

Путь использования

Типичный сценарий использования делится на следующие фазы:

  • После запуска системы процесс создается Execution Management и выполняет свою внутреннюю инициализацию [SWS_EM_02000].
  • Как только инициализация успешно завершена, процесс сообщает состояние ExecutionState::kRunning в Execution Management через экземпляр ExecutionClient [SWS_EM_02000].
  • Execution Management подтверждает этот переход; однако если о kRunning сообщается, когда процесс уже находится в работающем состоянии, это отклоняется как недопустимый переход ExecErrc::kInvalidTransition [SWS_EM_02281].
  • В ходе дальнейшей работы State Management при необходимости запрашивает через StateClient скоординированные переходы состояний для функциональных групп.

Диаграмма последовательности: последовательность вызовов при сообщении состояния через ExecutionClient и обработка ошибочных переходов. Источники: [SWS_EM_02000], [SWS_EM_02281]

Сценарии ошибок

Ошибочные ситуации отображаются в пространстве имен ara::exec через тип перечисления ExecErrc и домен ошибок ExecErrorDomain [SWS_EM_02281]. Ссылку на глобальный объект домена возвращает потокобезопасная и безисключительная функция GetExecErrorDomain() [SWS_EM_02290]. Конкретные объекты ошибок типа ara::core::ErrorCode создаются через вспомогательную функцию MakeErrorCode() с передачей кода ошибки и контекстных данных конкретного производителя [SWS_EM_02291]; для обработки исключений дополнительно доступен класс ExecException.

К специфицированным причинам ошибок относятся, в частности, [SWS_EM_02281]:

  • ExecErrc::kNoCommunication: сигнализирует об ошибке связи между клиентом и Execution Management или между State Management и Execution Management. На системном уровне такое состояние, предположительно, потребует перехода в неустранимое состояние [SWS_EM_02281].
  • ExecErrc::kInvalidTransition: недопустимый переход, например, когда процесс повторно сообщает kRunning [SWS_EM_02281].
  • ExecErrc::kOperationFailed: сбой операции, например, когда переход функциональной группы не может быть завершен из-за того, что о kRunning не было сообщено своевременно [SWS_EM_02281].
  • ExecErrc::kOperationCanceled: смена состояния функциональной группы была прервана более новым запросом [SWS_EM_02281].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed: сбой проверки целостности или подлинности запускаемого процесса [SWS_EM_02281].
  • ExecErrc::kUnexpectedTermination: аварийное прерывание во время перехода [SWS_EM_02281].
  • ExecErrc::kInvalidMetaModelIdentifier, а также ExecErrc::kInvalidArgument: недопустимые идентификаторы метамодели или недействительные значения параметров [SWS_EM_02281].

ExecutionClient класс

The ara::exec::ExecutionClient API provides the functionality for a Process to report its Execution State to the Execution Management.

ExecutionState перечисление

Defines the internal states of a Process. Scoped enumeration of uint32_t. Please note that ara::exec::ExecutionState includes only states reportable by the Process to Execution Management and therefore does not include enumerations e.g. the "Initializing" state mentioned in Figure 7.2 and Figure 7.12, which are an implied states for Execution Management. The Initializing state starts when Process is first scheduled (so no code executed yet) and ends when kRunning is reported ([SWS_EM_01004]). The Terminating state starts when termination is requested by Execution Management and ends when the Process terminates ([SWS_EM_01404]). For the reasons mentioned, Execution Management assumes that Process is in initializing state until kRunning will be reported by it.

Перечисление ExecErrc [SWS_EM_02281] определяет коды ошибок для Execution Management в пространстве имен ara::exec на основе базового типа ara::core::ErrorDomain::CodeType. Оно используется совместно с MakeErrorCode [SWS_EM_02291] для инкапсуляции в ara::core::ErrorCode и передается вызывающим сторонам синхронно через ara::core::Result или асинхронно с помощью ara::core::Future.

Перечислители охватывают различные состояния ошибок [SWS_EM_02281]:

  • kNoCommunication обозначает ошибки связи при отправке запросов или получении результатов [SWS_EM_02281]. Если это происходит между Execution Management и State Management, система может перейти в Unrecoverable State [SWS_EM_02281]. Клиенты, такие как ExecutionClient или StateClient, замечают это только при следующем вызове метода, при этом возможности восстановления на стороне клиента ограничены [SWS_EM_02281].
  • kOperationCanceled и kOperationFailed возникают при сменах состояний функциональных групп [SWS_EM_02281], например при SetState [SWS_EM_02278] или при прерывании перехода запуска машины [SWS_EM_02279].
  • kInvalidTransition сигнализирует о недопустимых переходах процессов, например если процесс повторно сообщает kRunning [SWS_EM_02281], что актуально для ReportExecutionState [SWS_EM_02003].
  • kIntegrityOrAuthenticityCheckFailed, kUnexpectedTermination, kInvalidMetaModelIdentifier, а также kInvalidArgument обрабатывают ошибки при проверках целостности, аномальные прерывания процессов при сменах состояний функциональных групп или недействительные параметры функций [SWS_EM_02281].

Вызывающие стороны анализируют эти коды ошибок, чтобы определить, завершились ли переходы состояний успешно, были ли вытеснены последующими запросами или заблокированы из-за ошибок конфигурации [SWS_EM_02281].

      Типизированное перечисление ara::exec::ExecutionState [SWS_EM_02000] определяет внутренние состояния процесса, о которых он может активно сообщать в Execution Management. Оно базируется на базовом типе std::uint32_t и предоставляется в пространстве имен ara::exec через заголовочный файл ara/exec/execution_client.h или заголовочный файл предварительного объявления ara/exec/exec_fwd.h.
      

      Спецификация определяет для процессов следующий сообщаемый перечислитель:
      

        

      • kRunning = 0: об этом состоянии процесс сообщает после того, как он был запущен компонентом Execution Management [SWS_EM_02000].
        • 

      

      Перечисление содержит исключительно состояния, о которых можно активно сообщать. Поэтому оно не включает неявные состояния Execution Management, такие как Initializing или Terminating [SWS_EM_02000]. Фаза инициализации начинается с первого планирования процесса и заканчивается сообщением kRunning [SWS_EM_01004]; до этого сообщения Execution Management предполагает, что процесс находится в состоянии инициализации. Фаза завершения начинается с запроса на завершение и заканчивается при остановке процесса [SWS_EM_01404].
      

      Сообщение о состоянии выполняется через интерфейс ara::exec::ExecutionClient::ReportExecutionState [SWS_EM_02003]. Этот метод принимает текущий ExecutionState в качестве параметра, объявлен как noexcept и является как потокобезопасным, так и исключениебезопасным. Он возвращает ara::core::Result<void>, подтверждающий успех или инкапсулирующий код ошибки в случае сбоя [SWS_EM_02003].
