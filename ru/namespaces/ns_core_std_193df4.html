Обеспечивает интеграцию типов ara::core в стандартные контейнеры и языковые средства стандартной библиотеки C++.

Пространство имен std в модуле core предоставляет специализации шаблонов std::hash, std::tuple_size и std::tuple_element для типов данных AUTOSAR Adaptive Platform. Это обеспечивает прямое использование таких типов, как ara::core::String, ara::core::Optional, ara::core::Variant, ara::core::Vector и ara::core::Array, в стандартных контейнерах и с языковыми средствами кортежей (tuple) C++. Граничным условием является то, что для вложенных типов содержащиеся типы данных во время компиляции также должны иметь корректные специализации.

Контекст

В модуле core платформы AUTOSAR Adaptive Platform пространство имен std служит для бесшовной интеграции платформозависимых базовых типов в стандартную библиотеку C++. Вместо введения новых типов пространство имен предоставляет целевые специализации шаблонов стандартизированных вспомогательных классов. Участники взаимодействия включают три основных компонента: обобщенные типы стандартной библиотеки C++ (в частности, неупорядоченные ассоциативные контейнеры и вспомогательные средства кортежей), специализации шаблонов внутри std, а также определенные в модуле core типы данных ara::core::Array, ara::core::Monostate, ara::core::Optional, ara::core::String, ara::core::StringView, ara::core::Variant и ara::core::Vector.

Контекстная диаграмма: взаимодействие стандартных контейнеров, специализаций в std и типов ara::core. Источники: объявления полезной нагрузки модуля core

Специализации std::hash позволяют использовать адаптивные базовые типы данных непосредственно в качестве ключей в таких стандартных контейнерах, как std::unordered_map или std::unordered_set. Параллельно с этим специализации std::tuple_size и std::tuple_element для ara::core::Array расширяют поддержку стандартизированных интерфейсов метапрограммирования и языковых средств.

Путь использования

Типичный сценарий использования начинается с применения типа данных ara::core в обобщенном коде C++. Например, приложение объявляет хеш-таблицу с ключами типа ara::core::String или ara::core::Optional<T>. При вставке, удалении или поиске контейнер неявно обращается к std::hash<ara::core::String> или std::hash<ara::core::Optional<T>> для вычисления хеш-значения ключа.

Специализации охватывают различные структуры данных:

  • Строки и представления (views): std::hash<ara::core::String> и std::hash<ara::core::StringView> вычисляют хеш-значения по содержащейся последовательности символов.
  • Составные типы: std::hash<ara::core::Optional<T>>, std::hash<ara::core::Variant<...>> и std::hash<ara::core::Vector<T, Allocator>> обеспечивают хеширование сложных структур типов. Интерпретация: специализации для ara::core::Optional и ara::core::Variant, вероятно, ориентируются на семантическое поведение стандартизированных прототипов и генерируют детерминированные значения для пустых или незанятых состояний.
  • Типы без состояния: std::hash<ara::core::Monostate> предоставляет хеш-функцию для пустых состояний, которые обычно применяются в вариантах (variants).
  • Протокол кортежа: Для фиксированных полей данных std::tuple_size<ara::core::Array<T, N>> предоставляет количество элементов во время компиляции, тогда как std::tuple_element<I, ara::core::Array<T, N>> определяет тип данных позиции I. Интерпретация: специализации std::tuple_size и std::tuple_element, по всей видимости, позволяют использовать ara::core::Array со структурированными привязками (structured bindings).

Сценарии ошибок

Поскольку элементы в пространстве имен std представляют собой исключительно специализации шаблонов, сценарии ошибок возникают преимущественно во время компиляции. Типичные проблемные ситуации включают:

  • Отсутствие возможности хеширования у базовых типов: если std::hash инстанциируется для вложенного типа, такого как ara::core::Optional<T> или ara::core::Vector<T, Allocator>, для типа элементов T также должна существовать корректная специализация std::hash. Ее отсутствие приводит к ошибке компиляции.
  • Недопустимая индексация в протоколе кортежа: доступ к std::tuple_element<I, ara::core::Array<T, N>> с индексом I >= N нарушает предусловие шаблона и прерывает процесс компиляции.

Интерпретация: сценарии ошибок, по всей вероятности, ограничиваются ошибками времени компиляции при неполных специализациях типов или статических нарушениях диапазона, поскольку выдержка из спецификации не определяет кодов ошибок времени выполнения или интерфейсов исключений.

Настоящее руководство основано исключительно на объявленных специализациях классов модуля core для релиза R25-11.
