Обеспечивает передачу необработанных двоичных потоков данных и датаграмм IEEE 1722 через сетевые соединения.

Пространство имен предоставляет функциональные интерфейсы для отправки и приема необработанных двоичных потоков данных через сетевые соединения, а также для критичных ко времени аудио-видеопотоков AVTP AUTOSAR_AP_SWS_RawDataStream §1. Приложения устанавливают соединения «точка-точка» через клиентские и серверные классы либо используют выделенные классы поставщиков (producer) и потребителей (consumer) для передачи типизированных датаграмм. Операции чтения структурированно предоставляют принятые необработанные данные в результирующих объектах. Ошибочные состояния во время передачи сигнализируются через специфичный для модуля домен ошибок и стандартизированные коды ошибок [SWS_RDS_12367].

Контекст

Пространство имен ara::rds в рамках AUTOSAR Adaptive Platform предоставляет функциональные интерфейсы для передачи необработанных двоичных потоков данных (Raw Data Streams) через сетевые соединения AUTOSAR_AP_SWS_RawDataStream §1. Архитектура обслуживает две взаимодополняющие модели связи: общую передачу неструктурированных байтовых потоков «точка-точка», а также критичный ко времени стриминг типизированных датаграмм по стандарту IEEE 1722 (Audio Video Transport Protocol, AVTP).

Для передачи байтовых потоков центральными компонентами являются RawDataStreamClient и RawDataStreamServer. RawDataStreamClient инициирует сетевое соединение и выполняет последующие операции чтения и записи, тогда как RawDataStreamServer принимает и обрабатывает входящие запросы на соединение. Результаты операций чтения инкапсулируются в экземплярах класса ReadDataResult для структурированной передачи принятых блоков данных в логику приложения.

Для критичных ко времени потоков аудио, видео и управления ara::rds определяет типизированную модель стриминга: IEEE1722RawDataStreamProducer служит источником для создания и отправки датаграмм IEEE 1722, а IEEE1722RawDataStreamConsumer функционирует как приемник для их приема. Полезная нагрузка и заголовки протокола отображаются через специализированные типы датаграмм, такие как IEEE1722DatagramAAF (аудио), IEEE1722DatagramRVF (видео), IEEE1722DatagramCRF (Clock Reference), а также датаграммы управления (IEEE1722Datagram61883_IIDC, IEEE1722DatagramNTSCF, IEEE1722DatagramTSCF и базовую датаграмму IEEE1722Datagram). Общие поля заголовков инкапсулируют IEEE1722DatagramAVTPDUCommonHeaderFields и IEEE1722DatagramAVTPDUCommonStreamHeaderFields.

Контекстная диаграмма: взаимодействие клиентских/серверных классов стриминга и компонентов стриминга IEEE 1722 с доменом ошибок в ara::rds. Источники: [SWS_RDS_11298], [SWS_RDS_11299], [SWS_RDS_12367], AUTOSAR_AP_SWS_RawDataStream §1.

Путь использования

В обычном рабочем процессе обмена байтовыми потоками серверный процесс сначала инстанцирует RawDataStreamServer для ожидания входящих соединений из сети. Клиентский процесс создает экземпляр RawDataStreamClient и устанавливает сетевое соединение с сервером. Как только соединение установлено, партнеры по коммуникации выполняют вызовы чтения или записи. Каждый вызов чтения возвращает ReadDataResult, который предоставляет прочитанные двоичные данные для дальнейшей обработки.

В сценарии AVTP производитель данных инстанцирует IEEE1722RawDataStreamProducer и настраивает требуемые заголовки протокола и потока через IEEE1722DatagramAVTPDUCommonStreamHeaderFields. Полезные данные упаковываются в предметно-ориентированные датаграммы, такие как IEEE1722DatagramAAF или IEEE1722DatagramRVF. Интерпретация: передача потребителю IEEE1722RawDataStreamConsumer, вероятно, обычно осуществляется через сеть AVB/TSN, после чего потребитель принимает и декодирует типизированные датаграммы.

Сценарии ошибок

Обработка ошибок в ara::rds органично вписывается в модель Adaptive Platform и опирается на домены ошибок и коды ошибок AUTOSAR_AP_SWS_RawDataStream §1. Модуль определяет домен ошибок RdsErrorDomain, экземпляр которого можно получить через функцию GetRdsErrorDomain() [SWS_RDS_11298].

Конкретные ошибочные ситуации, такие как обрывы передачи или конфликты соединений, отображаются через перечисление RdsErrc [SWS_RDS_12367]. Для создания специфичных для модуля объектов ошибок пространство имен предоставляет вспомогательную функцию MakeErrorCode(RdsErrc code, ara::core::ErrorDomain::SupportDataType data) [SWS_RDS_11299]. Интерпретация: неудачные операции ввода-вывода классов стриминга, вероятно, возвращают соответствующий ara::core::ErrorCode. Для путей выполнения на основе исключений также существует специализированный тип RdsException.
