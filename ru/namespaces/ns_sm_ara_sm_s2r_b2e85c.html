Контекст

Пространство имен ara::sm::s2r предоставляет интерфейсы и механизмы для функциональности Suspend-to-RAM (S2R) внутри модуля State Management (SM) (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»). Целью работы в режиме Suspend-to-RAM является существенная оптимизация времени запуска и завершения работы путем перевода Machine в состояние, обеспечивающее быстрый перезапуск, вместо выполнения полного выключения с последующим холодным стартом (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»).

Центральную роль в пространстве имен играет класс S2RHub (AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub»). Хаб координирует взаимодействие с распределенными экземплярами S2RSatellite. Приложения, исполняемые сущности которых сконфигурированы как suspendToRamAware, интегрируют такой экземпляр-сателлит для получения уведомлений о предстоящих циклах Suspend и Resume (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality», [SWS_SM_00710]). Процессы, объявленные как suspendToRamNotSupported, до перехода операционной системы в состояние Suspend уже должны быть остановлены процедурами State Management (например, завершением затронутых групп функций) (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»).

Для управления S2RHub существуют два взаимоисключающих подхода ([SWS_SM_00684]):

  • Подход на основе StateMachine: Controller интегрирует функциональность S2RHub внутренне через сопоставленные объекты ActionListItem. В этом режиме работы внешним управляющим приложениям запрещен доступ к C++-API хаба для предотвращения состояний гонки и несогласованности состояний (AUTOSAR_AP_SWS_StateManagement §7.7 «StateMachine approach», [SWS_SM_00684]).
  • Прямой C++-API: внешнее управляющее приложение (такое как SMControlApplication) использует методы класса S2RHub напрямую (AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub»).

Контекстная диаграмма: взаимодействие компонентов управления, S2RHub, S2RSatellite и адаптивных приложений. Источники: AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub», [SWS_SM_00710].

Жизненный цикл

Создание и освобождение экземпляров в пространстве имен ara::sm::s2r строго привязаны к проверкам полномочий (Identity and Access Management, IAM) и сконфигурированным сопоставлениям:

  • Создание экземпляра хаба: при подходе на основе StateMachine модуль State Management создает экземпляр S2RHub, как только завершается ActionListItem типов EnterSuspendToRam, EnterSuspendToRamOS или LeaveSuspendToRam ([SWS_SM_00690]). Во время выполнения конструктора ara::sm::s2r::S2RHub::S2RHub проверяется, соответствует ли контекст процесса сопоставлению в SuspendToRamHubMapping.process ([SWS_SM_00706]). Только процессы, авторизованные через SuspendToRamHubMapping, имеют право инициировать операции Suspend с помощью экземпляра хаба, идентифицированного через SuspendToRamModuleInstantiation ([SWS_SM_00714]).
  • Создание сателлита: экземпляр сателлита создается через фабричный метод ara::sm::s2r::S2RSatellite::Create ([SWS_SM_00716]).
  • Фаза регистрации: после создания сателлит регистрируется на хабе с помощью ara::sm::s2r::S2RSatellite::Offer ([SWS_SM_00710]). Хаб проверяет контекст процесса на соответствие конфигурации в SuspendToRamSatelliteMapping.process и отклоняет неавторизованные попытки регистрации ([SWS_SM_00715]). С момента успешной регистрации сателлит считается активно зарегистрированным ([SWS_SM_00710]).
  • Отмена регистрации: активная регистрация прекращается, как только сателлит вызывает ara::sm::s2r::S2RSatellite::StopOffer ([SWS_SM_00710], [SWS_SM_00713]).

Путь использования

Типичный рабочий процесс включает подготовку состояния покоя, переход в режим Suspend, а также скоординированное пробуждение после повторной активации Machine:

  1. Развертывание: каждое приложение с поддержкой S2R инициализирует свой S2RSatellite и сообщает о готовности к приему хабу через Offer() ([SWS_SM_00710]).
  2. Запрос Suspend: для инициации состояния покоя вызывается ara::sm::s2r::S2RHub::RequestToEnterSuspendMode ([SWS_SM_00701]). При подходе на основе StateMachine это выполняется через ActionListItem EnterSuspendToRam с использованием maxActionItemDuration в качестве параметра тайм-аута ([SWS_SM_00689]).
  3. Уведомление сателлитов: хаб обращается ко всем активно зарегистрированным сателлитам и вызывает их функцию обратного вызова ara::sm::s2r::S2RSatellite::EnterSuspendMode ([SWS_SM_00701], [SWS_SM_00711]). RequestToEnterSuspendMode блокирует выполнение до тех пор, пока все задействованные сателлиты не ответят, не отменят регистрацию или пока не истечет тайм-аут связи ([SWS_SM_00702]).
  4. Перевод операционной системы в Suspend: когда все сателлиты подготовлены, фактическая команда перехода операционной системы в режим Suspend может быть инициирована через EnterSuspendToRamOs ([SWS_SM_00692]).
  5. Запрос пробуждения: после пробуждения модуль управления вызывает ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode ([SWS_SM_00703]). При подходе на основе StateMachine это осуществляется через ActionListItem LeaveSuspendToRam ([SWS_SM_00691]). Согласно ограничению [SWS_SM_CONSTR_00035], LeaveSuspendToRam может быть сопоставлен исключительно с состояниями, отвечающими за выход из режима Suspend, но не с самими состояниями покоя.
  6. Повторная активация сателлитов: хаб вызывает ara::sm::s2r::S2RSatellite::LeaveSuspendMode на зарегистрированных сателлитах ([SWS_SM_00703], [SWS_SM_00711]). Вызов возвращает управление, как только все сателлиты ответят, отменят регистрацию или истечет тайм-аут ([SWS_SM_00707]).
  7. Завершение работы: при завершении процесса или сателлита отмена регистрации на хабе выполняется через StopOffer() ([SWS_SM_00710], [SWS_SM_00713]).

Диаграмма последовательности: порядок вызовов от регистрации через Suspend и Resume до отмены регистрации. Источники: [SWS_SM_00701], [SWS_SM_00702], [SWS_SM_00703], [SWS_SM_00707], [SWS_SM_00710], [SWS_SM_00711], [SWS_SM_00713].

Сценарии ошибок

Во взаимодействии между хабом и сателлитами специфицированы следующие ошибочные условия и предусловия:

  • Нарушение IAM при создании хаба: если контекст процесса вызывающей стороны S2RHub::S2RHub не соответствует конфигурации SuspendToRamHubMapping.process, сообщается о нарушении InsufficientPermissionsViolation и инициируется событие безопасности SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED ([SWS_SM_00706]).
  • Отсутствие аутентификации на сателлите: если переключатель IAM «Force IAM switch» активирован, S2RSatellite::Create возвращает код ошибки kAuthenticationRequired ([SWS_SM_00716]).
  • Отклонение неавторизованных сателлитов: если контекст процесса сателлита не совпадает с SuspendToRamSatelliteMapping.process, хаб отклоняет регистрацию ([SWS_SM_00715]).
  • Тайм-аут связи: если опрашиваемый сателлит во время выполнения RequestToLeaveSuspendMode не отвечает в течение промежутка времени, заданного timeout, хаб возвращает код ошибки kCommunicationTimeout ([SWS_SM_00707]).
  • Отказ со стороны сателлитов: если хотя бы один экземпляр сателлита при выходе из состояния покоя отвечает отрицательно с kRejected, концентратор возвращает в качестве общего результата kAtLeastOneHadIssuesToLeave ([SWS_SM_00707]). Положительный общий результат достигается только в том случае, если все сателлиты подтверждают положительно или штатно отменяют регистрацию через StopOffer ([SWS_SM_00707]).
  • Ограничения конфигурации и использования: назначение LeaveSuspendToRam состояниям Suspend в StateMachine недопустимо ([SWS_SM_CONSTR_00035]). Также запрещен одновременный доступ к C++-API S2RHub при активном подходе на основе StateMachine ([SWS_SM_00684]).
