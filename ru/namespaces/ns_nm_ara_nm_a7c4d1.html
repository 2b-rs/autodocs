Обеспечивает контроль запрошенного и фактического сетевого статуса, а также стандартизированную обработку ошибок.

Пространство имен ara::nm с помощью NetworkHandle предоставляет интерфейсы для контролируемого доступа к запрошенному и фактическому состоянию сети AUTOSAR Adaptive Platform. Возможные ошибочные ситуации в процессе работы отображаются через стандартизированные коды ошибок перечисления NmErrc, такие как kServiceNotAvailable или kInvalidHandler [SWS_ANM_01111]. Для структурированной обработки ошибок MakeErrorCode потокобезопасно генерирует коды ошибок для домена ошибок NmErrorDomain, на который ссылается GetNmDomain [SWS_ANM_01109]. Перед вызовами приложения должны учитывать доступность службы Network Management, чтобы избежать сбоев при запросах статуса.

Контекст

Пространство имен ara::nm предоставляет на AUTOSAR Adaptive Platform основные интерфейсы для функционального Network Management. Первичным функциональным интерфейсом выступает класс NetworkHandle, который инкапсулирует контролируемый доступ как к запрошенному, так и к фактическому сетевому статусу. С помощью этого механизма абстракции функциональные приложения и сервисы платформы могут контролировать текущее рабочее состояние базовой сети связи и инициировать изменения статуса.

Для согласованной и надежной обработки ошибок ara::nm предоставляет стандартизированные типы и вспомогательные функции, интегрированные в архитектуру обработки ошибок AUTOSAR Adaptive. К ним относятся домен ошибок NmErrorDomain, класс исключений NmException, а также доменно-специфичное перечисление NmErrc [SWS_ANM_01111]. Кроме того, доступны потокобезопасные функции GetNmDomain [SWS_ANM_01109] и MakeErrorCode [SWS_ANM_01110], обеспечивающие корректную с точки зрения инстанцирования и типов обработку состояний ошибок.

Контекстная диаграмма: взаимодействие приложения, NetworkHandle и архитектуры ошибок в ara::nm. Источники: [SWS_ANM_01109], [SWS_ANM_01110], [SWS_ANM_01111].

Путь использования

В типичном сценарии использования Adaptive Application взаимодействует с пространством имен ara::nm для контроля состояния сети и реагирования на события времени выполнения. Последовательность взаимодействия подразделяется на следующие шаги:

  • Инициирование доступа к статусу: приложение использует NetworkHandle для запроса требуемого или текущего фактического сетевого статуса.
  • Обнаружение ошибки: если сетевой запрос не может быть обслужен должным образом, интерфейс сигнализирует о соответствующем событии ошибки. Интерпретация: при сбоях базовых сетевых служб NetworkHandle, вероятно, внутренне генерирует коды ошибок на основе NmErrc.
  • Генерация кода ошибки: вспомогательная функция MakeErrorCode [SWS_ANM_01110] принимает значение из NmErrc [SWS_ANM_01111], а также специфичные для приложения дополнительные данные (ara::core::ErrorDomain::SupportDataType) и генерирует на их основе полноценный ara::core::ErrorCode. Функция специфицирована как constexpr и noexcept и гарантирует полную потокобезопасность [SWS_ANM_01110].
  • Верификация домена ошибок: вызывающий компонент может через GetNmDomain [SWS_ANM_01109] получить потокобезопасную ссылку на глобальный NmErrorDomain, чтобы проверить домен ошибки возвращенного кода и разрешить доменно-специфичные описания ошибок.

Диаграмма последовательности: процесс запроса сетевого статуса и разрешения ошибок через ara::nm. Источники: [SWS_ANM_01109], [SWS_ANM_01110], [SWS_ANM_01111].

Сценарии ошибок

Стандартизированные коды ошибок модуля сгруппированы в перечислении NmErrc, основанном на ara::core::ErrorDomain::CodeType [SWS_ANM_01111]. Модуль различает следующие случаи ошибок:

  • NmErrc::kServiceNotAvailable (код 1): эта ошибка указывает на то, что необходимая для управления сетью служба во время выполнения недоступна или не готова к работе [SWS_ANM_01111]. В этом случае вызывающие компоненты должны отреагировать повторными попытками или резервными стратегиями.
  • NmErrc::kInvalidHandler (код 2): возникает, если при операции был передан или сослан недействительный или незарегистрированный обработчик [SWS_ANM_01111]. Обычно это указывает на ошибку конфигурации или инициализации в вызывающем компоненте.

Предусловиями для надежных вызовов являются инициализированная инфраструктура служб, а также действительные параметры при доступе к NetworkHandle для предотвращения NmErrc::kServiceNotAvailable или NmErrc::kInvalidHandler [SWS_ANM_01111]. Все основные функции обработки ошибок, такие как MakeErrorCode [SWS_ANM_01110] и GetNmDomain [SWS_ANM_01109], сами не генерируют исключений (noexcept). Интерпретация: для приложений, предпочитающих структуру управления на основе исключений, класс исключений NmException, вероятно, служит носителем для структурированного распространения состояний ошибок по стеку вызовов.

Перечисление [SWS_ANM_01111] определяет стандартизированные коды ошибок Network Management (NM) в заголовочном файле ara/nm/nm_error_domain.h. Оно также предоставляется через псевдоним типа Errc [SWS_ANM_01103] и вместе с потокобезопасной фабричной функцией MakeErrorCode [SWS_ANM_01110] служит для инкапсуляции состояний ошибок в возвращаемых значениях ara::core::Result.

Определенные значения ошибок охватывают специфические случаи ошибок на интерфейсе NM:

  • kServiceNotAvailable (значение 1): возникает при синхронных запросах и требованиях состояния сети, если базовый сервис NM недоступен. Это касается считывания эффективного состояния сети через GetNetworkState [SWS_ANM_01007], запроса запрошенного состояния через GetNetworkRequestedState [SWS_ANM_01008], а также запроса или освобождения сетей через SetNetworkRequestedState [SWS_ANM_01009].
  • kInvalidHandler (значение 2): возвращается функциями регистрации обработчиков уведомлений, а именно RegisterNetworkStateChangeNotifier [SWS_ANM_01010], [SWS_ANM_01015] и RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012], [SWS_ANM_01014]. Поскольку на каждый интерфейс разрешено регистрировать не более одного нотификатора, эта ошибка, вероятно, возникает, если передан пустой обратный вызов или регистрация уже существует (интерпретация).

В отношении параллелизма следует учитывать, что операции только для чтения состояния сети являются потокобезопасными, тогда как SetNetworkRequestedState и все регистрации нотификаторов явно специфицированы как непотокобезопасные. Поэтому вызывающие стороны должны внешне синхронизировать конкурирующие обращения к регистрациям и изменениям запросов во избежание некорректных состояний вызова.

          Использование
          

          Функция MakeErrorCode служит в модуле anm для создания стандартизированного ara::core::ErrorCode для ошибок Network Management [SWS_ANM_01110]. Функция определена в заголовке ara/nm/nm_error_domain.h и синхронно инкапсулирует специфический код ошибки code типа перечисления NmErrc вместе с зависящими от производителя дополнительными данными data типа ara::core::ErrorDomain::SupportDataType в соответствующий объект ошибки [SWS_ANM_01110]. Вызывающие стороны передают соответствующее состояние ошибки, а также контекстные данные, чтобы получить унифицированный объект ошибки для дальнейшей обработки ошибок [SWS_ANM_01110].
          

          Обработка ошибок и параллелизм
          

          Поскольку MakeErrorCode объявлена со спецификатором noexcept, функция гарантированно не генерирует исключений при своем выполнении [SWS_ANM_01110]. С точки зрения конкурентного поведения функция классифицирована как thread-safe; следовательно, ее можно безопасно вызывать из параллельных потоков без дополнительных внешних мер синхронизации [SWS_ANM_01110]. Благодаря квалификации в качестве constexpr конструирование объекта ошибки при передаче константных аргументов, вероятно, может быть полностью выполнено компилятором еще во время компиляции [SWS_ANM_01110].
          

          Взаимодействие
          

          Являясь центральной функцией создания кодов ошибок Network Management, MakeErrorCode подключает модуль к общей концепции обработки ошибок платформы AUTOSAR Adaptive [SWS_ANM_01110]. При этом она напрямую адресует вышестоящие восходящие требования RS_AP_00119, RS_AP_00120, RS_AP_00121, RS_AP_00159, а также RS_AP_00135 [SWS_ANM_01110].
