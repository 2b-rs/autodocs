Предоставляет интерфейсы и контейнеры для Freshness Value Management в целях защиты синхронизации времени.

Пространство имен apext::tsync предоставляет интерфейсы и контейнеры данных для Freshness Value Management синхронизации времени в Adaptive. Через интерфейс FVM значения актуальности инкапсулируются в экземплярах FVContainer для защиты сообщений времени от атак повторного воспроизведения (replay attacks). Если при инициализации возникает неустранимая ошибка или значение временно недоступно, это отображается через коды ошибок TsyncFvmErrorDomain [SWS_TS_14202]. Инстанцирование стандартизированных объектов ошибок при этом осуществляется безисключительно и потокобезопасно через MakeErrorCode [SWS_TS_14213].

Контекст

Пространство имен apext::tsync представляет собой платформозависимое расширение синхронизации времени AUTOSAR Adaptive (ara::tsync). Его центральной задачей является Freshness Value Management (FVM), обеспечивающий механизмы поддержания актуальности информации о времени для предотвращения атак повторного воспроизведения и устаревших состояний в синхронизированных по времени сетях. К ключевым компонентам относятся интерфейс FVM, контейнер данных FVContainer, домен ошибок TsyncFvmErrorDomain, а также класс исключений TsyncFvmException.

Класс FVContainer инкапсулирует значение актуальности, управляя его длиной в битах, а также самим значением в виде байтового вектора. Интерфейс FVM функционирует как функциональный мост для ara::tsync. FVM, вероятно, выступает в качестве интерфейса абстракции, через который синхронизирующие время экземпляры ara::tsync получают или верифицируют актуальные значения свежести. Домен ошибок TsyncFvmErrorDomain и сопутствующие вспомогательные функции обеспечивают стандартизированное оповещение об ошибках [SWS_TS_14212].

Контекстная диаграмма: компоненты пространства имен apext::tsync и их взаимодействие с ara::tsync. Источники: [SWS_TS_14202], [SWS_TS_14212].

Жизненный цикл

Жизненный цикл компонентов в пространстве имен apext::tsync подразделяется на фазы инициализации, работы и завершения. Для фазы инициализации перечисление TsyncFvmErrc определяет значение ошибки kFVInitializeFailed (= 2), которое специфицировано как неустранимая ошибка (unrecoverable error) и указывает на то, что Freshness Value Manager не удалось использовать [SWS_TS_14202]. Ошибка kFVInitializeFailed предположительно указывает на то, что перед получением Freshness Values необходимо пройти фазу инициализации FVM, сбой которой исключает дальнейшее использование.

В процессе работы экземпляры FVContainer обладают временным временем жизни: они создаются по мере необходимости, заполняются вектором и битовой длиной и передаются синхронизирующим экземплярам протокола. Напротив, объект домена ошибок TsyncFvmErrorDomain имеет статическое время жизни на протяжении всего времени работы процесса. Функция GetTsyncFvmErrorDomain() возвращает ссылку на глобальный объект экземпляра [SWS_TS_14212]. Как GetTsyncFvmErrorDomain(), так и фабричная функция MakeErrorCode() объявлены как constexpr и noexcept, а также специфицированы как безисключительные и потокобезопасные [SWS_TS_14212], [SWS_TS_14213]. Это позволяет выполнять параллельное создание и опрос ошибок без блокировок синхронизации.

Путь использования

Типичный путь использования при взаимодействии с синхронизацией времени включает предоставление и оценку значений актуальности:

  1. Компонент из ara::tsync запрашивает актуальное значение свежести через интерфейс FVM для защиты сообщения времени.
  2. При успешном определении значения FVM создает или заполняет экземпляр FVContainer битовой длиной и байтовым вектором значения и возвращает его вызывающей стороне.
  3. Если значение свежести во время выполнения временно не может быть предоставлено, FVM сообщает об устранимой ошибке kFVNotAvailable [SWS_TS_14202]. Для этого через MakeErrorCode() создается подходящий объект ara::core::ErrorCode со специфичными для поставщика дополнительными данными [SWS_TS_14213].
  4. Вызывающий компонент анализирует результат и принимает решение о повторных попытках или альтернативных мерах.

Диаграмма последовательности: запрос значения актуальности и обработка возможных ошибочных состояний. Источники: [SWS_TS_14202], [SWS_TS_14213].

Сценарии ошибок

Обработка ошибок в apext::tsync базируется на архитектуре ara::core::ErrorDomain и ara::core::ErrorCode. Коды ошибок TsyncFvmErrorDomain приведены в перечислении TsyncFvmErrc, базовым типом которого является ara::core::ErrorDomain::CodeType [SWS_TS_14202]:

  • kFVNotAvailable (= 1): устранимая ошибка (recoverable error), сигнализирующая о том, что Freshness Value в настоящее время недоступен [SWS_TS_14202]. Вызывающие компоненты могут повторить запрос или пропустить текущий цикл обработки.
  • kFVInitializeFailed (= 2): неустранимая ошибка (unrecoverable error), указывающая на то, что Freshness Value Manager не удалось инициализировать или использовать [SWS_TS_14202]. Это приводит к прерыванию работы зависимых служб синхронизации времени.

Создание конкретных объектов ошибок осуществляется через вспомогательную функцию MakeErrorCode(TsyncFvmErrc code, ara::core::ErrorDomain::SupportDataType data), принимающую значение перечисления и специфичные для производителя дополнительные данные [SWS_TS_14213]. Объявления находятся в заголовке apext/tsync/fvm_error_domain.h, тогда как предварительные объявления могут быть получены через apext/tsync/tsync_fwd.h [SWS_TS_14202]. Для путей обработки ошибок на основе исключений пространство имен предоставляет класс TsyncFvmException. TsyncFvmException предположительно генерируется тогда, когда об ошибках TsyncFvmErrorDomain сообщается в контексте исключений, а не через ara::core::ErrorCode.

Настоящее руководство основано на спецификации AUTOSAR R25-11 для пространства имен apext::tsync и было создано автоматически.

Использование и семантика ошибок

Перечисление TsyncFvmErrc согласно [SWS_TS_14202] определяет специфические коды ошибок для домена ошибок apext::tsync::TsyncFvmErrorDomain. Внутри домена перечисление дополнительно предоставляется через псевдоним типа apext::tsync::TsyncFvmErrorDomain::Errc [SWS_TS_14206]. Перечисление различает два центральных состояния ошибки Freshness Value Manager (FVM):

  • kFVNotAvailable (= 1): обозначает исправимую ошибку (Recoverable Error), когда требуемое значение свежести недоступно [SWS_TS_14202]. Этот код ошибки возникает, в частности, при запросе значений свежести для передачи через apext::tsync::FVM::GetTxFreshness [SWS_TS_14199].
  • kFVInitializeFailed (= 2): обозначает неисправимую ошибку (Unrecoverable Error), когда Freshness Value Manager не готов к работе и дает сбой [SWS_TS_14202]. Он сигнализируется apext::tsync::FVM::Initialize при неудачной инициализации [SWS_TS_14200].

Взаимодействие и обработка ошибок

Для обработки ошибок перечислитель вместе с дополнительными данными поставщика преобразуется через вспомогательную функцию apext::tsync::MakeErrorCode в объект ara::core::ErrorCode [SWS_TS_14213]. Функции FVM, такие как Initialize [SWS_TS_14200], GetTxFreshness [SWS_TS_14199] и GetRxFreshness [SWS_TS_14198], инкапсулируют результат или состояния ошибок в ara::core::Result. Компоненты приложения и TimeSync анализируют объект Result, чтобы дифференцировать исправимые сбои отдельных значений свежести и тяжелые ошибки инициализации FVM.

      Использование
      

      Вызов выполняется синхронно и без входных параметров.       Обработка ошибок и безопасность исключений
      

      Функция объявлена как noexcept и специфицирована как исключениебезопасная (exception safe) [SWS_TS_14212]. Поскольку она лишь возвращает существующую ссылку, она не генерирует исключений и не формирует кодов ошибок.
      

      Параллелизм и ограничения
      

      Интерфейс определён как потокобезопасный (thread-safe) [SWS_TS_14212]. Он может вызываться параллельно из нескольких потоков без дополнительных механизмов синхронизации. Ограничивающих условий на очерёдность вызовов нет.
      

      Взаимодействие
      

      Интерпретация: адресуемый объект домена ошибок, по всей видимости, служит для однозначной идентификации и сопоставления специфических для модуля ошибок Freshness Value Management (FVM) в рамках модели обработки ошибок AUTOSAR Adaptive через ara::core::ErrorCode.

В качестве параметров она принимает код ошибки code типа TsyncFvmErrc, а также сопутствующие данные производителя data типа ara::core::ErrorDomain::SupportDataType и возвращает соответствующим образом инициализированный объект ara::core::ErrorCode [SWS_TS_14213].
          

          С точки зрения безопасности выполнения функция определена как noexcept и исключениебезопасная («exception safe»), благодаря чему вызовы гарантированно не вызывают C++-исключений [SWS_TS_14213]. Кроме того, она специфицирована как потокобезопасная («thread-safe») и может выполняться конкурентно без внешней синхронизации [SWS_TS_14213]. На основании сигнатуры constexpr функция, вероятно, также может вычисляться в выражениях времени компиляции, если аргументы зафиксированы во время трансляции [SWS_TS_14213].
          

          В контексте модуля функция образует аналог MakeErrorCode из стандартного пространства имен ara::tsync [SWS_TS_00910]. В то время как стандартная функция использует ara::tsync::TsyncErrc через заголовочный файл ara/tsync/tsync_error_domain.h [SWS_TS_00910], этот вариант обеспечивает специфическую инкапсуляцию ошибок TsyncFvmErrc для расширенных функций синхронизации времени [SWS_TS_14213].
