Перевод из модели в пространство привязки

ara::com::runtime::ResolveInstanceIDs преобразует уникальный в Executable InstanceSpecifier в технические InstanceIdentifier, сконфигурированные в Service-Instance-Manifest. Возвращаемое значение является контейнером, поскольку при Multi-Binding один Specifier может указывать на несколько технических экземпляров. EXP ARAComAPI §4.8.1 «Instance Identifiers and Instance Specifiers» и SWS CM §7.5.21 «Instance Specifier Translation» предоставляют семантику.

Когда требуется явное разрешение

Большинство API поиска и скелета напрямую принимают InstanceSpecifier. Таким образом, явное разрешение особенно полезно в случаях, когда конкретное техническое задание должно быть сознательно обработано, например, при диагностике или специальных стратегиях с несколькими привязками. EXP ARAComAPI §4.8.2 «When to use InstanceIdentifier versus InstanceSpecifier» описывает это ограничение.

Процедура документирована в Guide модуля как диаграмма активности: ara::com — Communication Management, диаграмма деятельности «Разрешение InstanceSpecifier по манифесту».

Осознанное использование разрешения Manifest

ResolveInstanceIDs() считывает сопоставление стороны развертывания InstanceSpecifier и возвращает InstanceIdentifierContainer. Пустой контейнер указывает на отсутствие присваивания, многозначный контейнер указывает на множественную привязку. EXP ARAComAPI §4.8.1 «Instance Identifiers and Instance Specifiers» объясняет возможные результаты.

Рекомендуемый процесс
  1. Укажите спецификатор из уникального контекста порта.
  2. Result и проверьте размер контейнера.
  3. При нескольких ID применять явную стратегию Binding/Failover.
  4. Для стандартного обнаружения предпочтительно использовать перегрузку спецификатора.

Диаграмма активности: логический InstanceSpecifier отображается относительно Manifest на один или несколько ID, специфичных для привязки. Источник: EXP ARAComAPI §4.8.1 «Instance Identifiers and Instance Specifiers».
