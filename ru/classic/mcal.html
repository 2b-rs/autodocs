AUTOSAR Classic Microcontroller Abstraction (MCAL)

Уровень абстракции микроконтроллера (MCAL) содержит драйверы для конкретного оборудования для внутренних периферийных устройств микроконтроллера (ADC преобразователей, PWM генераторов, аппаратного контроля) и отделяет верхние уровни BSW от кремниевой платформы.

Adc_GetStreamLastPointer функция

Возвращает количество допустимых выборок на канал, сохраненное в буфере результатов. Считывает указатель, указывающий на позицию в буфере результатов группы. Положение указателя позволяет получить доступ к результатам всех групповых каналов последнего завершенного раунда преобразования. С помощью указателя и возвращаемого значения можно получить доступ ко всем действительным результатам группового преобразования (пользователь должен учитывать структуру буфера результатов).

Std_ReturnType Adc_PreparePowerState (Adc_PowerStateType PowerState, Adc_PowerStateRequestResultType* Result);
Adc_ReadGroup функция

Считывает результат группового преобразования последнего завершенного цикла преобразования запрошенной группы и сохраняет значения каналов, начиная с адреса Data Buffer Ptr. Значения групповых каналов сохраняются в порядке возрастания номеров каналов (в отличие от структуры хранения буфера результатов, если настроен потоковый доступ).

Std_ReturnType Adc_ReadGroup (Adc_GroupType Group, Adc_ValueGroupType* DataBufferPtr);
Adc_SetPowerState функция

Этот API настраивает модуль Adc так, чтобы он переходил в уже подготовленное состояние питания, выбранное из заранее определенного набора настроенных.

Std_ReturnType Adc_SetPowerState (Adc_PowerStateRequestResultType* Result);
Adc_SetupResultBuffer функция

Инициализирует драйвер ADC стартовым адресом буфера результатов для конкретной группы, где будут храниться результаты преобразования. Приложение должно гарантировать, что буфер приложения, на который указывает Data Buffer Ptr, может хранить все результаты преобразования указанной группы. После сброса требуется инициализация с помощью буфера результатов настройки Adc_, прежде чем можно будет запустить групповое преобразование.

Std_ReturnType Adc_SetupResultBuffer (Adc_GroupType Group, Adc_ValueGroupType* DataBufferPtr);

Adc_Channel тип

В случае активной проверки предела: определяет, какие значения преобразования учитываются в отношении плат, определенных с помощью Adc Нижний предел канала и Adc Верхний предел канала.

Adc_ChannelType тип

Числовое ID канала ADC.

Adc_ConfigType тип

Структура данных, содержащая набор параметров конфигурации, необходимых для инициализации драйвера ADC и модулей ADC HW.

Adc_ConversionTimeType тип

Тип времени преобразования, т. е. время, в течение которого дискретное аналоговое значение преобразуется в цифровое представление. (Это не тип API).

Adc_GroupAccessModeType тип

Введите для настройки режима доступа к группировке результатов преобразования.

Adc_GroupConvModeType тип

Введите для настройки режима преобразования группы каналов ADC. AUTOSAR CP R20 - документа ID : AUTOSAR_SWS_ADCDriver

Adc_GroupDefType тип

Тип назначения каналов группе каналов (это не тип API).

Adc_GroupPriorityType тип

Уровень приоритета канала. Самый низкий приоритет — 0.

Adc_GroupReplacementType тип

Механизм замены, который используется на уровне группы ADC, если преобразование группы прерывается группой с более высоким приоритетом.

Adc_GroupType тип

Числовое ID группы каналов ADC.

Adc_HwTriggerSignalType тип

Тип для настройки, на каком фронте аппаратного триггерного сигнала драйвер должен среагировать, т.е. начать преобразование (только если поддерживается аппаратным обеспечением ADC).

Adc_HwTriggerTimerType тип

Введите значение перезагрузки встроенного таймера модуля ADC (только если поддерживается аппаратным обеспечением ADC).

Adc_PowerStateRequestResultType тип

Тип Adc_PowerStateRequestResultType.

Adc_PowerStateType тип

Состояние питания в данный момент активно или установлено как целевое состояние питания.

Adc_PrescaleType тип

Тип коэффициента прескалера часов. (Это не тип API).

Adc_PriorityImplementationType тип

Тип для настройки механизма приоритезации.

Adc_ResolutionType тип

Тип разрешения канала в битах. (Это не тип API).

Adc_ResultAlignmentType тип

Введите для выравнивания необработанных результатов ADC в буфере результатов ADC (выравнивание по левому/правому краю).

Adc_SamplingTimeType тип

Тип времени выборки, т. е. время, в течение которого производится выборка значения (в тактах – циклах). (Это не тип API).

Adc_StatusType тип

Текущий статус преобразования запрошенной группы каналов ADC.

Adc_StreamBufferModeType тип

Тип для настройки типа буфера режима потокового доступа.

Adc_StreamNumSampleType тип

Тип для настройки количества групповых преобразований в режиме потокового доступа (в режиме одиночного доступа параметр равен 1). Доступно Adc.h AUTOSAR CP R20 - документа ID : AUTOSAR_SWS_ADCDriver через

Adc_TriggerSourceType тип

Введите для настройки источника запуска для группы каналов ADC.

Adc_ValueGroupType тип

Тип для чтения преобразованных значений группы каналов (необработанные, без дальнейшего масштабирования, выравнивание по ключу прекомпиляции ADC_ RESULT_ ALIGNMENT).

Предоставляет низкоуровневые драйверы для прямой инкапсуляции и управления периферией микроконтроллера и внутренними регистрами.

Кластер модулей Microcontroller Abstraction (MCAL) включает драйверы Port, Dio, Adc, Pwm, Spi и Wdg для низкоуровневой инкапсуляции и управления встроенной периферией (SWS_ECUStateManager с. 34). К ключевым задачам относятся конфигурирование выводов перед обращением к периферии, управление аналоговыми и широтно-импульсными сигналами, а также контроль выполнения с отслеживанием времени ([SWS_Adc_00507], [SWS_Wdg_00155]). Центральные переключения режимов и состояний питания при этом должны выполняться строго последовательно и нереентерабельно ([SWS_Wdg_00107]).

Кластер модулей Microcontroller Abstraction (MCAL) инкапсулирует физические встроенные ресурсы микроконтроллера и предоставляет стандартизированные интерфейсы для абстракции аппаратного обеспечения ввода-вывода (IoHwAb), интерфейса сторожевого таймера (WdgIf), а также EcuM и BswM (SWS_ECUStateManager с. 34). Он включает шесть компонентов драйверов: Port (мультиплексирование выводов), Dio (цифровой ввод-вывод), Adc (аналого-цифровое преобразование), Pwm (широтно-импульсная модуляция), Spi (последовательная коммуникация с периферией) и Wdg (аппаратный контроль выполнения) ([SWS_Adc_00507], [SWS_Pwm_00197], [SWS_Wdg_00155]).

Модули функционируют в условиях фиксированных зависимостей: Port_Init настраивает назначение выводов до того, как драйверы, такие как Pwm или Adc, активируют соответствующие аппаратные блоки (AUTOSAR_CP_RS_PWMDriver с. 14, ModemanagementGuide с. 54). Буферы данных предоставляются со стороны приложения через Adc_SetupResultBuffer ([SWS_Adc_91000]), тогда как обслуживание сторожевого таймера асинхронно развязывается через прерывания таймера (AUTOSAR_SWS_WatchdogDriver с. 31).

Архитектурная диаграмма: многоуровневая архитектура и классификация кластера MCAL. Источники: SWS_ECUStateManager с. 34, AUTOSAR_CP_RS_PWMDriver с. 14.

В то время как вызовы драйверов для отдельных каналов и групп являются реентерабельными для непересекающихся экземпляров ([SWS_Pwm_91000], [SWS_Adc_00367]), переключения режимов и состояний требуют строго синхронных, нереентерабельных путей ([SWS_Wdg_00107]). Для снижения энергопотребления Adc и Pwm выполняют двухфазные переходы состояний питания с асинхронными сообщениями о готовности в IoHwAb ([SWS_Adc_00478], [SWS_Pwm_00183], AUTOSAR_CP_SWS_IOHardwareAbstraction с. 57).

Ошибки управления, такие как неинициализированные вызовы, передаются в DET ([SWS_Pwm_00177]), тогда как аппаратные дефекты регистрируются в DEM ([SWS_Wdg_00111]). В случае деградации Wdg_SetTriggerCondition позволяет целенаправленно вызвать сброс ECU путём передачи таймаута 0 ([SWS_Wdg_00155], SWS_WatchdogDriver с. 29).

Системная архитектура & роль кластера модулей

Кластер модулей уровня абстракции микроконтроллера (Microcontroller Abstraction Layer, MCAL) образует наиболее близкий к аппаратному обеспечению фундамент AUTOSAR Classic Platform. Он инкапсулирует обращения к регистрам встроенных периферийных модулей и предоставляет верхним уровням стандартизированный, независимый от микроконтроллера интерфейс. В рамках многоуровневой архитектуры драйверы обслуживают абстракцию аппаратного обеспечения ввода-вывода (IoHwAb), интерфейс сторожевого таймера (WdgIf), а также центральные системные службы, такие как ECU State Manager (EcuM) и Basic Software Mode Manager (BswM) (SWS_ECUStateManager с. 34).

Кластер включает шесть взаимодополняющих компонентов драйверов: Port берёт на себя глобальное конфигурирование выводов и мультиплексирование выводов микроконтроллера (AUTOSAR_CP_RS_PWMDriver с. 14). Dio реализует быстрый побитовый и попортовый цифровой доступ ввода-вывода, в то время как Spi инкапсулирует синхронную и асинхронную последовательную коммуникацию по шине с встроенными на плате периферийными компонентами. Для аналоговых и широтно-импульсных сигналов Adc ([SWS_Adc_00507]) и Pwm ([SWS_Pwm_00197]) предоставляют развитые службы преобразования и модуляции. Wdg управляет аппаратным контролем времени для защиты целостности выполнения программы ([SWS_Wdg_00155]).

Архитектурная диаграмма: многоуровневая архитектура и структурное расположение кластера MCAL между системными службами, уровнями абстракции и периферией. Источники: SWS_ECUStateManager с. 34, AUTOSAR_CP_RS_PWMDriver с. 14, AUTOSAR_SWS_WatchdogDriver с. 11.

Взаимодействие и пути взаимодействия между модулями

Модули функционируют в чётко определённых потоках сигналов и буферов. Драйвер Port предварительно инициализирует электрическую логику портов и мультиплексирование, после чего такие драйверы, как Pwm или Adc, управляют назначенными периферийными блоками без необходимости иметь информацию о разводке контактных площадок (AUTOSAR_CP_RS_PWMDriver с. 14). При считывании внутренних логических состояний через [SWS_Pwm_00100] модуль Pwm_GetOutputState считывает состояние регистра блока PWM, а не физический вывод порта ([SWS_Pwm_00108], AUTOSAR_SWS_PWMDriver с. 51).

В аналоговом тракте вышестоящий IoHwAb запрашивает измерения и предоставляет буферы со стороны приложения (AUTOSAR_CP_SWS_IOHardwareAbstraction с. 55). С помощью [SWS_Adc_91000] модуль Adc_SetupResultBuffer инициализирует внутренний указатель на область памяти вызывающей стороны (AUTOSAR_SWS_ADCDriver с. 31). После запуска преобразования программным путём ([SWS_Adc_00367]) или аппаратным триггером ([SWS_Adc_91001]) необработанные данные записываются в буфер. Доступ для чтения осуществляется синхронно через [SWS_Adc_00369] (копирование самых последних результатов) или через [SWS_Adc_00375] с помощью Adc_GetStreamLastPointer (SWS_ADCDriver с. 27).

Тракт сторожевого таймера разделяет логический контроль выполнения и аппаратное обслуживание: WdgM управляет бюджетами контроля и задаёт временное окно в Wdg_SetTriggerCondition через WdgIf с помощью [SWS_Wdg_00155] (SWS_WatchdogDriver с. 29). Непосредственное аппаратное обслуживание выполняется циклически через аппаратные прерывания таймера (AUTOSAR_SWS_WatchdogDriver с. 31). Внешние компоненты сторожевого таймера при необходимости опрашиваются через экземпляры драйверов Dio или Spi ([SWS_Wdg_00111], AUTOSAR_SWS_WatchdogDriver с. 11).

Диаграмма последовательности: взаимодействие WdgM, WdgIf и Wdg при циклическом продлении триггера и переключении режима. Источники: AUTOSAR_SWS_WatchdogDriver с. 31, AUTOSAR_SWS_WatchdogDriver с. 34, [SWS_Wdg_00155], [SWS_Wdg_00107].

Синхронизация, реентерабельность и контексты задач

Драйверы MCAL подчиняются дифференцированным правилам реентерабельности. В модуле Pwm функции управления, такие как Pwm_SetDutyCycle ([SWS_Pwm_91000]), Pwm_SetPeriodAndDuty ([SWS_Pwm_91001]) и Pwm_SetOutputToIdle ([SWS_Pwm_91002]), реентерабельны для различных каналов, однако не должны вызываться параллельно для одного и того же канала (AUTOSAR_CP_SWS_PWMDriver с. 46). В модуле Adc API управления и чтения, такие как Adc_StartGroupConversion ([SWS_Adc_00367]), Adc_StopGroupConversion ([SWS_Adc_00368]) и Adc_ReadGroup ([SWS_Adc_00369]), реентерабельны относительно различных групп каналов.

Напротив, центральные API конфигурирования и режимов строго нереентерабельны. Это относится к Wdg_SetMode ([SWS_Wdg_00107]), Wdg_SetTriggerCondition ([SWS_Wdg_00155]), а также к подпрограммам инициализации и деинициализации всех драйверов ([SWS_Adc_00366], [SWS_Pwm_00096]). Конкурирующие вызовы из различных задач OS должны быть защищены через исключительные области SchM (AUTOSAR_SWS_WatchdogDriver с. 11).

Уведомления о событиях (например, смене фронта или завершении преобразования) инициируются из контекста прерывания (ISR) через конфигурируемые обратные вызовы, такие как Pwm_Notification_<#Channel> ([SWS_Pwm_00105]) или Adc_Notification_Group_<x> ([SWS_Adc_91003]). При активации уведомлений ожидающие флаги прерываний сбрасываются ([SWS_Pwm_91004]). Если несколько групп ADC конкурируют за ресурсы преобразователя, в зависимости от конфигурации вступает в силу аппаратная приоритезация или программная организация очередей ([SWS_Adc_00522]) с настраиваемым механизмом прерывания/перезапуска (Abort/Restart) или приостановки/возобновления (Suspend/Resume) ([SWS_Adc_00523], SWS_ADCDriver с. 97).

Типичные жизненные циклы и режимы работы

Жизненный цикл драйверов MCAL начинается на фазе запуска всей системы под управлением EcuM (SWS_ECUStateManager с. 34). С помощью правил BswM обеспечивается детерминированная последовательность: сначала Port_Init инициализирует функциональность выводов (ModemanagementGuide с. 54). Только после этого следуют периферийные драйверы, такие как Dio_Init, Spi_Init, Adc_Init ([SWS_Adc_00365]), Pwm_Init ([SWS_Pwm_00095]) и Wdg_Init ([SWS_Wdg_00106], AUTOSAR_CP_SWS_PWMDriver с. 47).

В процессе работы Wdg различает три статических режима: WDGIF_OFF_MODE, WDGIF_SLOW_MODE и WDGIF_FAST_MODE ([SWS_Wdg_00107]). Модуль Adc различает однократные и непрерывные преобразования ([SWS_Adc_00515]), а также режимы одиночного и потокового доступа ([SWS_Adc_00528], [SWS_Adc_00519]). Статус группы при этом проходит через состояния ADC_IDLE, ADC_BUSY, ADC_COMPLETED и ADC_STREAM_COMPLETED ([SWS_Adc_00513], [SWS_Adc_00374], SWS_ADCDriver с. 37).

Для режимов энергосбережения (Low Power) Adc и Pwm реализуют стандартизированный двухфазный протокол состояний питания: сначала Adc_PreparePowerState ([SWS_Adc_00478]) и Pwm_PreparePowerState ([SWS_Pwm_00183]) подготавливают переход ([SWS_Pwm_00165], [SWS_Adc_00527]). После асинхронного завершения абстракция аппаратного обеспечения сообщает о готовности через обратные вызовы, такие как IoHwAb_Adc_NotifyReadyForPowerState<#Mode> ([SWS_Adc_00480]). Наконец, Adc_SetPowerState ([SWS_Adc_00475]) и Pwm_SetPowerState ([SWS_Pwm_00166]) переключают аппаратное обеспечение в целевое состояние (AUTOSAR_CP_SWS_IOHardwareAbstraction с. 57). Циклический контроль обеспечивается в задачах с помощью Pwm_Main_PowerTransitionManager ([SWS_Pwm_00189], [SWS_Pwm_00190]).

При завершении работы системы или сбросе службы деинициализации, такие как Adc_DeInit ([SWS_Adc_00366], AUTOSAR_SWS_ADC_Driver с. 76) и Pwm_DeInit ([SWS_Pwm_00096], AUTOSAR_SWS_PWMDriver с. 47), переводят модули в безопасное состояние покоя и деактивируют все прерывания.

Диаграмма последовательности: двухфазное асинхронное переключение состояния питания в кластере MCAL через BswM и IoHwAb. Источники: AUTOSAR_CP_SWS_IOHardwareAbstraction с. 57, [SWS_Adc_00478], [SWS_Pwm_00183], [SWS_Adc_00475], [SWS_Pwm_00166].

Обработка ошибок, трассировка DET и деградация

Ошибки строго разделяются на ошибки разработки и эксплуатационные ошибки. При активном контроле разработки драйверы сообщают о вызовах до выполнения инициализации в Default Error Tracer (DET), например через PWM_E_UNINIT ([SWS_Pwm_00177], [SWS_Pwm_00104]) или ADC_E_UNINIT ([SWS_Adc_00476]). Параметры-указатели проверяются на NULL, например в GetVersionInfo через ADC_E_PARAM_POINTER ([SWS_Adc_00376]) и WDG_E_PARAM_POINTER ([SWS_Wdg_00109]).

Ошибки времени выполнения защищают от недопустимых эксплуатационных переходов: если Pwm_SetPowerState вызывается в момент, когда каналы не находятся в состоянии IDLE или ещё присутствуют активные уведомления, драйвер сообщает об ошибке времени выполнения PWM_E_NOT_DISENGAGED ([SWS_Pwm_00202]). В случае Adc попытка повторного запуска занятой группы каналов в конфигурациях без очередей приводит к отправке сообщения времени выполнения ADC_E_BUSY в DET (SWS_ADCDriver с. 95).

Серьёзные эксплуатационные ошибки и отказы периферии передаются в Diagnostic Event Manager (DEM) через Dem_SetEventStatus ([SWS_Wdg_00111]). Для деградации в аварийных режимах работы Pwm_SetOutputToIdle обеспечивает немедленную деактивацию отдельных выходов PWM ([SWS_Pwm_91002]). В драйвере сторожевого таймера установка таймаута триггера в значение 0 позволяет немедленно остановить обслуживание и форсирует быстрый сброс ECU ([SWS_Wdg_00155], [SWS_Wdg_00136], SWS_WatchdogDriver с. 29).

Данное руководство основано исключительно на спецификациях и артефактах трассируемости полезной нагрузки AUTOSAR Classic R20-11.
