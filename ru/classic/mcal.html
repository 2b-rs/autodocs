AUTOSAR Classic Microcontroller Abstraction (MCAL)

Уровень абстракции микроконтроллера (MCAL) содержит драйверы для конкретного оборудования для внутренних периферийных устройств микроконтроллера (ADC преобразователей, PWM генераторов, аппаратного контроля) и отделяет верхние уровни BSW от кремниевой платформы.

Возвращает количество допустимых выборок на канал, сохраненное в буфере результатов. Считывает указатель, указывающий на позицию в буфере результатов группы. Положение указателя позволяет получить доступ к результатам всех групповых каналов последнего завершенного раунда преобразования. С помощью указателя и возвращаемого значения можно получить доступ ко всем действительным результатам группового преобразования (пользователь должен учитывать структуру буфера результатов).

Std_ReturnType Adc_PreparePowerState (Adc_PowerStateType PowerState, Adc_PowerStateRequestResultType* Result);
Adc_ReadGroup функция

Считывает результат группового преобразования последнего завершенного цикла преобразования запрошенной группы и сохраняет значения каналов, начиная с адреса Data Buffer Ptr. Значения групповых каналов сохраняются в порядке возрастания номеров каналов (в отличие от структуры хранения буфера результатов, если настроен потоковый доступ).

Std_ReturnType Adc_ReadGroup (Adc_GroupType Group, Adc_ValueGroupType* DataBufferPtr);
Adc_SetPowerState функция

Этот API настраивает модуль Adc так, чтобы он переходил в уже подготовленное состояние питания, выбранное из заранее определенного набора настроенных.

Std_ReturnType Adc_SetPowerState (Adc_PowerStateRequestResultType* Result);
Adc_SetupResultBuffer функция

Инициализирует драйвер ADC стартовым адресом буфера результатов для конкретной группы, где будут храниться результаты преобразования. Приложение должно гарантировать, что буфер приложения, на который указывает Data Buffer Ptr, может хранить все результаты преобразования указанной группы. После сброса требуется инициализация с помощью буфера результатов настройки Adc_, прежде чем можно будет запустить групповое преобразование.

Std_ReturnType Adc_SetupResultBuffer (Adc_GroupType Group, Adc_ValueGroupType* DataBufferPtr);

Adc_Channel тип

В случае активной проверки предела: определяет, какие значения преобразования учитываются в отношении плат, определенных с помощью Adc Нижний предел канала и Adc Верхний предел канала.

Adc_ChannelType тип

Числовое ID канала ADC.

Adc_ConfigType тип

Структура данных, содержащая набор параметров конфигурации, необходимых для инициализации драйвера ADC и модулей ADC HW.

Adc_ConversionTimeType тип

Тип времени преобразования, т. е. время, в течение которого дискретное аналоговое значение преобразуется в цифровое представление. (Это не тип API).

Adc_GroupAccessModeType тип

Введите для настройки режима доступа к группировке результатов преобразования.

Adc_GroupConvModeType тип

Введите для настройки режима преобразования группы каналов ADC. AUTOSAR CP R20 - документа ID : AUTOSAR_SWS_ADCDriver

Adc_GroupDefType тип

Тип назначения каналов группе каналов (это не тип API).

Adc_GroupPriorityType тип

Уровень приоритета канала. Самый низкий приоритет — 0.

Adc_GroupReplacementType тип

Механизм замены, который используется на уровне группы ADC, если преобразование группы прерывается группой с более высоким приоритетом.

Adc_GroupType тип

Числовое ID группы каналов ADC.

Adc_HwTriggerSignalType тип

Тип для настройки, на каком фронте аппаратного триггерного сигнала драйвер должен среагировать, т.е. начать преобразование (только если поддерживается аппаратным обеспечением ADC).

Adc_HwTriggerTimerType тип

Введите значение перезагрузки встроенного таймера модуля ADC (только если поддерживается аппаратным обеспечением ADC).

Adc_PowerStateRequestResultType тип

Тип Adc_PowerStateRequestResultType.

Adc_PowerStateType тип

Состояние питания в данный момент активно или установлено как целевое состояние питания.

Adc_PrescaleType тип

Тип коэффициента прескалера часов. (Это не тип API).

Adc_PriorityImplementationType тип

Тип для настройки механизма приоритезации.

Adc_ResolutionType тип

Тип разрешения канала в битах. (Это не тип API).

Adc_ResultAlignmentType тип

Введите для выравнивания необработанных результатов ADC в буфере результатов ADC (выравнивание по левому/правому краю).

Adc_SamplingTimeType тип

Тип времени выборки, т. е. время, в течение которого производится выборка значения (в тактах – циклах). (Это не тип API).

Adc_StatusType тип

Текущий статус преобразования запрошенной группы каналов ADC.

Adc_StreamBufferModeType тип

Тип для настройки типа буфера режима потокового доступа.

Adc_StreamNumSampleType тип

Тип для настройки количества групповых преобразований в режиме потокового доступа (в режиме одиночного доступа параметр равен 1). Доступно Adc.h AUTOSAR CP R20 - документа ID : AUTOSAR_SWS_ADCDriver через

Adc_TriggerSourceType тип

Введите для настройки источника запуска для группы каналов ADC.

Adc_ValueGroupType тип

Тип для чтения преобразованных значений группы каналов (необработанные, без дальнейшего масштабирования, выравнивание по ключу прекомпиляции ADC_ RESULT_ ALIGNMENT).

Системная архитектура & роль кластера модулей

Кластер «Microcontroller Abstraction» образует самый нижний уровень программного обеспечения Classic Platform. В спецификациях драйверов ADC и PWM явно зафиксировано, что эти модули находятся на самом нижнем архитектурном уровне и поэтому не предлагают функций обратного вызова для более низких уровней (SWS ADC с. 79, SWS PWM с. 40). Их пользователями являются модули абстракции ECU и системных служб, прежде всего IoHwAb, WdgIf/WdgM, а также EcuM и BswM. Нормативными для R20-11 являются требования полезной нагрузки. Фрагменты документов из более поздних релизов служат здесь только для иллюстрации, например пример ADC для IoHwAb (IoHwAb с. 55).

  • Adc выполняет преобразование аналоговых каналов по группам. Преобразование запускается программно или аппаратно ([SWS_Adc_00514]). Результаты сохраняются в буферах, предоставляемых пользователем ([SWS_Adc_91000]).
  • Pwm генерирует сигналы с широтно-импульсной модуляцией с заданными периодом и коэффициентом заполнения ([SWS_Pwm_91001]). Опционально он сообщает о фронтах сигналов ([SWS_Pwm_00109]).
  • Wdg обслуживает внутренний или внешний аппаратный сторожевой таймер через условие триггера ([SWS_Wdg_00144]).
  • Spi и Dio подтверждены в полезной нагрузке как пути доступа внешнего сторожевого таймера ([SWS_Wdg_00076]). Собственных требований SWS для этих двух модулей полезная нагрузка не содержит.
  • Port подтвержден через Port_Init как «Initializes the Port Driver module» в списке интерфейсов EcuM (SWS EcuM с. 142). На схеме «Port Logic» расположена между блоком PWM и выводом (RS PWM с. 14).

Контекстная диаграмма: драйверы MCAL инициализируются EcuM/BswM, используются IoHwAb или WdgIf и сообщают об ошибках в DET/DEM; внешний сторожевой таймер обращается к аппаратному обеспечению через Spi или Dio. Источники: [SWS_Wdg_00076], [SWS_Adc_00082], [SWS_Pwm_00198], [SWS_Wdg_00111], [SWS_Adc_00377], [SWS_Pwm_00104], Modemanagement с. 54

Взаимодействие & пути взаимодействия

Тракт данных ADC. Процесс начинается с буфера результатов.

  1. После каждого сброса и перед первым преобразованием группы пользователь должен задать буфер результатов группы с помощью Adc_SetupResultBuffer ([SWS_Adc_91000], SWS ADC с. 54).
  2. Adc_StartGroupConversion сбрасывает внутренний указатель буфера. При этом уведомление не активируется автоматически ([SWS_Adc_00367], SWS ADC с. 57).
  3. После каждого завершенного преобразования группы драйвер вызывает IoHwAb_AdcNotification<#groupID> ([SWS_Adc_00082]).
  4. Пользователь считывает результаты одним из двух способов:
    • Adc_ReadGroup копирует их ([SWS_Adc_00369]).
    • Adc_GetStreamLastPointer возвращает указатель на буфер ([SWS_Adc_00375]).

То, сколько результатов вмещает буфер, зависит от режима доступа: Single или Streaming ([SWS_Adc_00528]). В режиме Streaming буфер организован линейно или кольцевым образом ([SWS_Adc_00519]).

Диаграмма последовательности: непрерывное преобразование с программным запуском и уведомлением — настройка буфера, активация уведомления, запуск, уведомление и считывание на каждом цикле, остановка. Источники: SWS ADC с. 92, [SWS_Adc_91000], [SWS_Adc_00082], SWS ADC с. 70

Тракт управления PWM. Пользователь настраивает сигнал с помощью двух служб:

  • Pwm_SetDutyCycle изменяет только коэффициент заполнения ([SWS_Pwm_91000]).
  • Pwm_SetPeriodAndDuty изменяет период и коэффициент заполнения ([SWS_Pwm_91001]). Период можно изменять только для каналов класса PWM_VARIABLE_PERIOD ([SWS_Pwm_00110]); в противном случае драйвер сообщает PWM_E_PERIOD_UNCHANGEABLE ([SWS_Pwm_40002]).

Уведомления о фронтах поступают пользователю через Pwm_Notification_<#Channel>. Определяющим является последний вызов Pwm_EnableNotification или Pwm_DisableNotification ([SWS_Pwm_00105], [SWS_Pwm_91004]). Pwm_GetOutputState считывает внутреннее состояние выходного сигнала ([SWS_Pwm_00100]). Согласно схеме, это сигнал перед логикой портов, а не уровень на выводе (RS PWM с. 14).

Тракт сторожевого таймера. Цепочка вызовов проходит через три уровня:

  • WdgM управляет драйвером через WdgIf_SetMode и WdgIf_SetTriggerCondition (SWS WdgM с. 86).
  • WdgIf сопоставляет эти службы с соответствующим экземпляром драйвера через DeviceIndex (SWS WdgIf с. 17).
  • Wdg пересчитывает таймаут из миллисекунд в значение счетчика с учетом текущего режима ([SWS_Wdg_00138], [SWS_Wdg_00139]).

Внутренние и внешние сторожевые таймеры различаются только доступом к аппаратному обеспечению:

  • Внутренний драйвер обращается напрямую к аппаратному обеспечению ([SWS_Wdg_00161]).
  • Внешний драйвер использует Spi или Dio и содержит необходимые для этого параметры в своей конфигурации ([SWS_Wdg_00076], [SWS_Wdg_00078]).
  • API обоих вариантов семантически идентичны ([SWS_Wdg_00077]).
  • При наличии нескольких экземпляров имена API расширяются ([SWS_Wdg_00172]).

Диаграмма последовательности: установка условия триггера развязана по времени с циклическим аппаратным обслуживанием; при значении счетчика 0 триггер не срабатывает. Источники: SWS Wdg с. 31, [SWS_Wdg_00134], [SWS_Wdg_00135], [SWS_Wdg_00136]

Синхронизация, реентерабельность и контексты задач

Модули существенно различаются по своим гарантиям реентерабельности:

  • API тракта данных ADC являются реентерабельными.
  • Службы PWM, привязанные к каналам, реентерабельны только для разных каналов.
  • Инициализация, API состояний питания и все службы Wdg не являются реентерабельными.

Для согласованности данных Wdg определяет эксклюзивные области через планировщик BSW. Будучи модулем MCAL, внутренний драйвер также может напрямую блокировать прерывания ([SWS_Wdg_00040]). Во время смены режима и процедуры обслуживания состояние WDG_BUSY указывает на конкурентный доступ ([SWS_Wdg_00018], [SWS_Wdg_00052]).

Запланированные функции. Циклически через SchM выполняются Adc_Main_PowerTransitionManager и Pwm_Main_PowerTransitionManager ([SWS_Adc_00479], [SWS_Pwm_00189]). Их частота переменная, поскольку они требуются только во время текущего перехода ([SWS_Adc_00500]). До инициализации они завершаются без сообщения в DET ([SWS_Adc_00502]).

Контекст прерывания. Уведомления о группах и фронтах, вероятно, выполняются в контексте прерывания. В пользу этого говорят два обстоятельства: драйвер PWM сбрасывает флаг прерывания, относящийся к уведомлению (SWS PWM с. 42). Кроме того, пример MemMap содержит BswInterruptEntity Adc_IsrGroupScanCompleted (SWS MemMap с. 54). Поэтому функции обратного вызова должны оставаться короткими. Реентерабельность Pwm_Notification_<#Channel> явно зависит от реализации пользователя ([SWS_Pwm_00105]).

Многоядерные системы. Adc и Pwm должны отклонять назначения разделов, которые не поддерживаются реализацией ([SWS_Adc_00531], [SWS_Pwm_00203]). Разделы ядра ADC являются подмножеством пользовательских разделов ([SWS_Adc_CONSTR_00001]). Этому соответствует шаблон Master-Satellite с разделением на ядро и интерфейсную часть (BSW Distribution с. 18).

Жизненные циклы и режимы работы

Инициализация. EcuM вызывает Adc_Init ([SWS_Adc_00365], SWS ADC с. 91). В описании структуры EcuM дополнительно указаны Port_Init, Pwm_Init, Spi_Init и Wdg_Init (SWS EcuM с. 34). Вариант под управлением BswM выполняет инициализацию в следующем порядке: Port, Dio, Adc, Spi (Modemanagement с. 54). Интерпретация: Port, предположительно, стоит первым, поскольку конфигурация выводов является предварительным условием для остальных периферийных драйверов.

ADC. Драйвер переходит с помощью Adc_Init из ADC_UNINIT в ADC_INIT и с помощью Adc_DeInit обратно (SWS ADC с. 31). Каждая группа проходит через состояния ADC_IDLE, ADC_BUSY, ADC_COMPLETED и ADC_STREAM_COMPLETED ([SWS_Adc_00513]). Режим Continuous доступен только при программном запуске ([SWS_Adc_00515]). Adc_DeInit переводит аппаратное обеспечение в состояние, подобное сбросу ([SWS_Adc_00366]). Вызывать его разрешено только тогда, когда все группы находятся в ADC_IDLE (SWS ADC с. 59).

PWM. После Pwm_Init выходы, в зависимости от конфигурации, находятся в состоянии Low, High или модулированы. Уведомления отсутствуют до тех пор, пока не будет вызван Pwm_EnableNotification ([SWS_Pwm_00095], SWS PWM с. 46). Pwm_DeInit переводит выходы в состояние Idle и блокирует прерывания ([SWS_Pwm_00096], SWS PWM с. 27).

Watchdog. Wdg_Init устанавливает режим по умолчанию и начальный таймаут ([SWS_Wdg_00001], [SWS_Wdg_00100]). После этого можно выбирать режимы WDGIF_OFF_MODE, WDGIF_SLOW_MODE и WDGIF_FAST_MODE ([SWS_Wdg_00160]). Функция DeInit отсутствует. Отключение выполняется, если это допустимо, через режим OFF ([SWS_Wdg_00031]).

Состояния питания Adc и Pwm. Переход выполняется в два этапа:

  1. *_PreparePowerState инициирует его ([SWS_Adc_00478], [SWS_Pwm_00183]).
  2. В асинхронном случае функция Main завершает его и сообщает о готовности через IoHwAb_*_NotifyReadyForPowerState<#Mode> ([SWS_Adc_00480], [SWS_Pwm_00198]).
  3. *_SetPowerState выполняет переключение ([SWS_Adc_00475], [SWS_Pwm_00166]).

Предварительно ответственные SWC, такие как IoHwAb, должны перевести каналы в состояние Idle и отменить регистрацию уведомлений (SWS PWM с. 36). Во время самого перехода разрешены только специфичные для перехода изменения конфигурации ([SWS_Adc_00484]).

Диаграмма последовательности: после смены режима BswM модуль IoHwAb координирует двухэтапное переключение состояний питания Adc и Pwm, асинхронно с функциями обратного вызова Ready или синхронно путем опроса. Источники: IoHwAb с. 57, IoHwAb с. 58, [SWS_Adc_00501], [SWS_Pwm_00190]

Обработка ошибок, трассировка DET и деградация

Ошибки разработки (DET). Все три специфицированных драйвера сообщают о них через Det_ReportError ([SWS_Adc_00377], [SWS_Pwm_00104], [SWS_Wdg_00111]):

  • Adc, среди прочего, ADC_E_UNINIT и ADC_E_PARAM_GROUP ([SWS_Adc_91005]).
  • Pwm — PWM_E_UNINIT и PWM_E_PARAM_CHANNEL ([SWS_Pwm_20002], [SWS_Pwm_30002]).
  • Wdg при неверном состоянии — WDG_E_DRIVER_STATE ([SWS_Wdg_00017], [SWS_Wdg_00035]).

Ошибки времени выполнения. Здесь существует несколько случаев:

  • ADC сообщает ADC_E_BUSY, среди прочего, тогда, когда преобразование без формирования очереди уже выполняется ([SWS_Adc_91006], SWS ADC с. 95).
  • Если при смене состояния питания все еще активны каналы, оба драйвера сообщают *_E_NOT_DISENGAGED ([SWS_Adc_00487], [SWS_Pwm_00202]).
  • Недостижимое целевое состояние питания ADC в R20-11 классифицирует как ошибку времени выполнения ([SWS_Adc_00489]), тогда как PWM — как ошибку DET ([SWS_Pwm_00175]).

Производственные ошибки (DEM). В полезной нагрузке они специфицированы только для Wdg и сообщаются через Dem_SetEventStatus ([SWS_Wdg_00111]):

  • WDG_E_MODE_FAILED при неудачной смене режима; Wdg_SetMode затем возвращает E_NOT_OK ([SWS_Wdg_00016], [SWS_Wdg_00180]).
  • WDG_E_DISABLE_REJECTED, если отключение не разрешено ([SWS_Wdg_00025], [SWS_Wdg_00182]).

Деградация и безопасные состояния.

  • Pwm_SetOutputToIdle немедленно переводит выход в сконфигурированное состояние покоя ([SWS_Pwm_91002], SWS PWM с. 31).
  • Pwm_GetOutputState до инициализации или при недопустимом канале превентивно возвращает PWM_LOW ([SWS_Pwm_30051]).
  • Для сторожевого таймера сброс является последним рубежом защиты. Таймаут 0 вызывает практически мгновенный сброс ECU ([SWS_Wdg_00140]). Истекший счетчик триггера приводит к срабатыванию сторожевого таймера по тайм-ауту ([SWS_Wdg_00135]).
  • Слишком большие таймауты драйвер отклоняет с WDG_E_PARAM_TIMEOUT ([SWS_Wdg_00146]).
  • В ADC механизмы приоритетов с Abort/Restart или Suspend/Resume определяют, как возобновляются вытесненные группы ([SWS_Adc_00522], [SWS_Adc_00523]). Проверка предельных значений отфильтровывает результаты за пределами выбранного диапазона ([SWS_Adc_00524]).

Сгенерированное ИИ руководство по кластеру на основе требований и фрагментов документации R20-11, содержащихся в полезной нагрузке; Dio, Port и Spi из-за отсутствия собственных требований в полезной нагрузке описаны только через их интерфейсы с остальными модулями. Обязательную силу имеют связанные элементы спецификации.
