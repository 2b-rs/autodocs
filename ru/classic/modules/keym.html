Управляет ключами и сертификатами электронного блока управления: обновление, синтаксический анализ и проверка цепочек сертификатов.

Key Manager управляет в криптографическом стеке AUTOSAR ключевым материалом и сертификатами электронного блока управления, опираясь при этом на CSM. Подмодуль Crypto Key принимает ключи в рамках опционального сеанса, состоящего из KeyM_Start, KeyM_Prepare, KeyM_Update и KeyM_Finalize; допускается интеграция специфичных для производителя обработчиков ключей (Key Handler). Подмодуль сертификатов сохраняет сертификаты, выполняет их синтаксический анализ и асинхронно проверяет их по сконфигурированной цепочке; результат возвращает callback-функция [SWS_KeyM_00153]. Сертификат становится действительным только после безошибочной проверки, и только тогда его открытый ключ активируется в CSM [SWS_KeyM_00170].

Key Manager управляет ключевым материалом и сертификатами электронного блока управления в криптографическом стеке. Для этого он имеет два подмодуля: подмодуль Crypto Key принимает ключи от Key Master в автомобиле или бэкенде, преимущественно через диагностические команды. Подмодуль сертификатов сохраняет сертификаты, выполняет их синтаксический анализ и проверяет их по соответствующей цепочке (SWS KeyM с. 24). На нижнем уровне KeyM использует CSM, обязательными являются Csm_KeyElementGet, Csm_KeyElementSet и Csm_KeySetValid [SWS_KeyM_00076].

Операции с ключами могут выполняться сеансовым образом (SWS KeyM с. 25). KeyM_Start() открывает сеанс, KeyM_Prepare() синхронно возвращает данные для Key Server, а KeyM_Finalize() закрывает сеанс. KeyM_Update() выполняется асинхронно и передает результат через KeyM_CryptoKeyUpdateCallbackNotification() ([SWS_KeyM_00052], [SWS_KeyM_00077]). Опционально Key Handler берет на себя шаги, специфичные для производителя. При этом KeyM_KH_Update() вызывается до тех пор, пока не вернет KEYM_KH_UPDATE_FINISH ([SWS_KeyM_00092], [SWS_KeyM_00096]).

Диаграмма последовательности: сеанс проходит от Start через Prepare и асинхронный Update до Finalize, с опциональными Key Handler и callback-функциями результатов. Источники: SWS KeyM с. 25, [SWS_KeyM_00052], [SWS_KeyM_00079]

Сертификаты вводятся двумя путями. Постоянно это происходит через KeyM_ServiceCertificate(), который инициируется Key Master [SWS_KeyM_00021]. Временно вызывающий компонент передает сертификат для проверки с помощью KeyM_SetCertificate() [SWS_KeyM_00057]. Каждый сертификат имеет статус согласно KeyM_CertificateStatusType [SWS_KeyM_91003]. Лишь после безошибочной проверки он становится KEYM_CERTIFICATE_VALID, и только тогда его открытый ключ активируется в CSM [SWS_KeyM_00170].

Диаграмма состояний: сертификат переходит от NOT_AVAILABLE через синтаксический анализ к PARSED_NOT_VALIDATED и после проверки — в VALID или в состояние ошибки; сброс с длиной 0 возвращает назад. Сопоставление INVALID_CONTENT и REVOKED является интерпретацией. Источники: SWS KeyM с. 24, [SWS_KeyM_91003]

Проверка выполняется асинхронно через KeyM_VerifyCertificate(), KeyM_VerifyCertificates() или KeyM_VerifyCertificateChain(). Результат сообщает конфигурируемая callback-функция [SWS_KeyM_00153]. Отдельное содержимое считывается с помощью KeyM_CertElementGet(); элементы с множественным заполнением обходятся итератором [SWS_KeyM_00064]. Ошибки KeyM сообщает тремя путями: как ошибки разработки, такие как KEYM_E_UNINIT [SWS_KeyM_00036], как KeyM_ResultType в callback-функциях [SWS_KeyM_91008] и, в случае сбоя проверки цепочки, дополнительно как событие безопасности [SWS_KeyM_00172].

Роль в криптографическом стеке: управление ключами и сертификатами на уровне выше CSM

Key Manager (KeyM) представляет собой сервисный модуль в криптографическом стеке AUTOSAR и состоит из двух подмодулей. Подмодуль Crypto Key инициализирует, обновляет и обслуживает ключевой материал электронного блока управления. Подмодуль сертификатов сохраняет сертификаты, выполняет их синтаксический анализ и проверяет их по соответствующей цепочке (SWS KeyM с. 23, SWS KeyM с. 28). Типичным сценарием применения подмодуля Crypto Key является распределение ключей для защищенной бортовой коммуникации по ключам CSM. Данные поставляет Key Master, расположенный в автомобиле или в бэкенде; обмен данными в основном происходит через диагностические команды (SWS KeyM с. 24).

На нижнем уровне KeyM опирается на CSM. В качестве обязательных интерфейсов [SWS_KeyM_00076] называет Csm_KeyElementGet, Csm_KeyElementSet и Csm_KeySetValid. Наряду с ними [SWS_KeyM_00078] перечисляет Csm_KeyDerive, Csm_SignatureVerify, Det_ReportError и IdsM_SetSecurityEvent. Для проверки временного срока действия KeyM импортирует типы модуля StbM [SWS_KeyM_00037]. На верхнем уровне KeyM предоставляет C-API и сервисные интерфейсы RTE для сертификатов, элементов сертификатов и криптографических ключей ([SWS_KeyM_00082], [SWS_KeyM_00083], [SWS_KeyM_00084]). Специфичная для производителя логика подключается через конфигурируемые функции Key Handler, например через KeyM_KH_Start() [SWS_KeyM_00067].

Контекстная диаграмма: KeyM выступает посредником между Key Master или пользователями, опциональными Key Handler и службами CSM, StbM, NvM, IdsM и DET. Источники: SWS KeyM с. 23, [SWS_KeyM_00076], [SWS_KeyM_00078], [SWS_KeyM_00037], SWS KeyM с. 119

Инициализация, тактирование и безопасная деинициализация

KeyM_Init() инициализирует модуль [SWS_KeyM_00043]. Содержимое KeyM_ConfigType зависит от реализации [SWS_KeyM_00157], а указатель конфигурации всегда должен быть NULL_PTR [SWS_KeyM_00158]. После инициализации все сертификаты имеют статус KEYM_CERTIFICATE_NOT_AVAILABLE (SWS KeyM с. 34). KeyM_Deinit() сбрасывает модуль в неинициализированное состояние [SWS_KeyM_00047]. Соответствующий пункт документа дополнительно требует, чтобы подмодуль Crypto Key активно перезаписывал ключевой материал и промежуточные результаты в RAM (SWS KeyM с. 49).

В процессе работы KeyM_MainFunction() периодически вызывается с сконфигурированным интервалом [SWS_KeyM_00074]. KeyM_MainBackgroundFunction() выполняется, когда у вытесняющей операционной системы нет других задач. Она может вызывать длительные синхронные функции, такие как KeyM_KH_Update() [SWS_KeyM_00075]. Период представляет собой параметр контейнера KeyMGeneral (SWS KeyM с. 131). KeyM_GetVersionInfo() предоставляет информацию о версии [SWS_KeyM_00049].

Сеанс работы с ключами: от KeyM_Start до KeyM_Finalize

Операции с ключами могут конфигурироваться в виде сеанса. KeyM_Start() открывает сеанс. После этого KeyM принимает KeyM_Prepare() и KeyM_Update(), пока KeyM_Finalize() не закроет сеанс (SWS KeyM с. 25). KeyM_StartType различает режим производства OEM и режим сервисного центра; производственный режим имеет более высокие права [SWS_KeyM_00038]. По умолчанию KeyM_Start() не обрабатывает входные данные. Если установлен параметр KeyMCryptoKeyHandlerStartFinalizeEnabled, он вызывает KeyM_KH_Start() с теми же параметрами и перенимает его возвращаемое значение, например, для специфичных для OEM проверок подписей ([SWS_KeyM_00050], [SWS_KeyM_00067]).

Отдельные шаги сеанса:

  • KeyM_Prepare() работает синхронно и предоставляет прежде всего информацию для Key Server [SWS_KeyM_00051]. Если установлены KeyMCryptoKeyPrepareFunctionEnabled и KeyMCryptoKeyHandlerPrepareEnabled, KeyM немедленно вызывает KeyM_KH_Prepare() ([SWS_KeyM_00068], SWS KeyM с. 82).
  • KeyM_Update() является асинхронной. О завершении сообщает KeyM_CryptoKeyUpdateCallbackNotification() ([SWS_KeyM_00052], [SWS_KeyM_00077], [SWS_KeyM_00150]). Вызывающая сторона не должна модифицировать переданный буфер результатов до этого callback-вызова; callback возвращает тот же указатель [SWS_KeyM_00156].
  • KeyM_Finalize() также является асинхронной и переводит операцию с ключом в состояние покоя (SWS KeyM с. 56). При активированном Key Handler она делегирует выполнение KeyM_KH_Finalize() ([SWS_KeyM_00053], [SWS_KeyM_00070]). KeyM_CryptoKeyFinalizeCallbackNotification() сообщает, были ли успешно валидированы все ключи ([SWS_KeyM_00079], [SWS_KeyM_00080]).

Вне сессии KeyM_Verify() проверяет ключи синхронно или асинхронно [SWS_KeyM_00054]. При KeyMCryptoKeyVerifyAsyncMode = TRUE результат поступает через KeyM_CryptoKeyVerifyCallbackNotification() ([SWS_KeyM_00081], [SWS_KeyM_00151]). Key Handler можно подключить через KeyM_KH_Verify() [SWS_KeyM_00071].

Диаграмма последовательности: сессия проходит путь от Start через Prepare и асинхронный Update до Finalize; обработчики Key Handler опциональны, результаты поступают через callback. Источники: SWS KeyM с. 25, SWS KeyM с. 116, [SWS_KeyM_00052], [SWS_KeyM_00075], [SWS_KeyM_00079]

KeyM_Update в деталях: выбор ключа и цикл Key Handler

Сначала KeyM определяет целевой ключ:

  • По имени ключа KeyM выполняет поиск контейнера KeyMCryptoKey с подходящим KeyMCryptoKeyName [SWS_KeyM_00091].
  • При отсутствии допустимого имени и при заданных KeyMCryptoKeyCryptoProps KeyM интерпретирует RequestData как значения SHE M1M2M3 и сопоставляет биты 121..124 [SWS_KeyM_00154].
  • Если KeyID определить невозможно и ни один Key Handler обновления не активен, вызов завершается с KEYM_E_PARAMETER_MISMATCH [SWS_KeyM_00155].

При включенном KeyMCryptoKeyHandlerUpdateEnabled KeyM_Update() вызывает функцию KeyM_KH_Update(). Она передает данные запроса, имя и найденный KeymId, в противном случае 0xFFFFFFFFul [SWS_KeyM_00092]. Для этого KeyM предоставляет внутренний буфер, который не модифицирует вплоть до возврата из обработчика [SWS_KeyM_00097]. Ответ обработчика управляет дальнейшим ходом выполнения [SWS_KeyM_00055]:

  • KEYM_KH_UPDATE_KEY_UPDATE_REPEAT с данными: KeyM сохраняет ключ в CSM или выполняет его деривацию там же и вызывает обработчик повторно [SWS_KeyM_00096].
  • KEYM_KH_UPDATE_FINISH: KeyM копирует результирующие данные и инициирует callback-вызов обновления [SWS_KeyM_00093].

Сохраняет ли KeyM ключ или выполняет его деривацию, определяет KeyMCryptoKeyGenerationType со значениями KEYM_STORED_KEY или KEYM_DERIVED_KEY соответственно (SWS KeyM с. 164). При деривации Csm_KeyDerive заменяет вызов Csm_KeyElementSet (SWS KeyM с. 118). В обоих случаях Csm_KeySetValid затем активирует ключ (SWS KeyM с. 116).

Диаграмма деятельности: KeyM_Update выбирает ключ по имени или идентификатору SHE, прерывает работу при отсутствии KeyID и Key Handler и повторяет вызовы Key Handler до KEYM_KH_UPDATE_FINISH. Источники: [SWS_KeyM_00091], [SWS_KeyM_00154], [SWS_KeyM_00155], [SWS_KeyM_00092], [SWS_KeyM_00096], [SWS_KeyM_00093]

Сертификаты: постоянное и временное хранение, иерархия и статус

Для постоянно хранящихся сертификатов существует KeyM_ServiceCertificate(). Подмодуль сертификатов предоставляет эту функцию, если установлены KeyMServiceCertificateFunctionEnabled и KeyMCertificateManagerEnabled; вызывается она из Key Master [SWS_KeyM_00021]. KeyM_ServiceCertificateType различает следующие службы [SWS_KeyM_00039]:

  • запрос CSR и возврат подписанного CSR,
  • установка или обновление корневых и промежуточных сертификатов,
  • предоставление или обновление CRL.

Служба работает асинхронно и сообщает о результатах через KeyM_ServiceCertificateCallbackNotification() ([SWS_KeyM_00056], [SWS_KeyM_00149], [SWS_KeyM_00152]). Попытки установки или обновления корневых либо промежуточных сертификатов определены как события безопасности ([SWS_KeyM_00172], SWS KeyM с. 38).

Диаграмма последовательности: при внесении корневого или промежуточного сертификата сначала выполняются парсинг и проверка; сохранение в NvM или CSM следует только после успешной верификации, после чего поступает callback службы. Источники: SWS KeyM с. 120, [SWS_KeyM_00039], [SWS_KeyM_00056], [SWS_KeyM_00149], [SWS_KeyM_00172]

Предъявленный сертификат вызывающая сторона, напротив, передает временно с помощью KeyM_SetCertificate() [SWS_KeyM_00057]. Он попадает в сконфигурированное хранилище KeyMCertificateStorage, обычно в RAM, и не предназначен для постоянного хранения (SWS KeyM с. 31). Данные передаются в KeyM_CertDataType с указанием длины и указателя [SWS_KeyM_00041]. Сама цепочка сконфигурирована статически. Каждый KeyMCertificate ссылается на свой вышестоящий сертификат, а корневой сертификат — на самого себя. Кроме того, каждый сертификат ссылается на задание CSM и ключ CSM для проверки подписи (SWS KeyM с. 22).

Структурная диаграмма: в трехуровневой цепочке каждый KeyMCertificate ссылается на свой вышестоящий сертификат (корневой — на самого себя), а также на задание CSM и ключ CSM для проверки подписи. Источники: SWS KeyM с. 22, SWS KeyM с. 31, [SWS_KeyM_00170]

Каждый сертификат имеет статус типа KeyM_CertificateStatusType [SWS_KeyM_91003], который опрашивает KeyM_CertGetStatus() [SWS_KeyM_00066]. Жизненный цикл:

  • После KeyM_Init() действует KEYM_CERTIFICATE_NOT_AVAILABLE.
  • KeyM_SetCertificate() с certDataLength = 0 сбрасывает сертификат и статус (SWS KeyM с. 34).
  • Заданные данные проходят парсинг (NOT_PARSED → PARSED_NOT_VALIDATED), а затем проверку (SWS KeyM с. 24).
  • Только после безошибочной проверки KeyM активирует открытый ключ с помощью Csm_KeySetValid() и устанавливает KEYM_CERTIFICATE_VALID [SWS_KeyM_00170].

Интерпретация: KEYM_E_CERTIFICATE_INVALID_CONTENT, вероятно, относится к ошибкам парсинга, а KEYM_E_CERTIFICATE_REVOKED — к ошибкам проверки. Явно это подтверждено только для INVALID_FORMAT и INVALID_TYPE (SWS KeyM с. 33).

Диаграмма состояний: сертификат переходит из NOT_AVAILABLE через парсинг в PARSED_NOT_VALIDATED и после успешной проверки в VALID; ошибки приводят к статусам ошибок, а сброс с длиной 0 возвращает в исходное состояние. Отнесение INVALID_CONTENT и REVOKED является интерпретацией. Источники: SWS KeyM с. 24, [SWS_KeyM_91003], [SWS_KeyM_00170], SWS KeyM с. 34

Проверка сертификатов и доступ к их содержимому

Для проверки предусмотрены три асинхронных, нереэнтерабельных задания:

  • KeyM_VerifyCertificate() определяет соответствующую цепочку самостоятельно ([SWS_KeyM_00060], SWS KeyM с. 68).
  • KeyM_VerifyCertificates() проверяет нижестоящий сертификат относительно вышестоящего [SWS_KeyM_00059].
  • KeyM_VerifyCertificateChain() получает список сертификатов, отсортированный в порядке PKI [SWS_KeyM_00061].

Если KeyM принял задание с E_OK и сконфигурирована KeyMCertificateVerifyCallbackNotificationFunc, callback сообщает результат в виде KeyM_CertificateStatusType ([SWS_KeyM_00153], [SWS_KeyM_00073]). Если эта функция равна NULL, вместо нее используется требуемый порт (Required Port) KeyMCertificateNotification [SWS_KeyM_00161]. Согласно имеющимся фрагментам документов DCM из более поздних релизов, DCM использует этот способ для аутентификации (SWS DCM с. 147, SWS DCM с. 245).

Диаграмма последовательности: рабочий сертификат задается и подвергается парсингу; последующая проверка использует время StbM, проверку Subject и проверку подписи CSM и завершается активацией ключа и callback-вызовом. Источники: SWS KeyM с. 119, [SWS_KeyM_00057], [SWS_KeyM_00060], [SWS_KeyM_00170], [SWS_KeyM_00153]

Для доступа к содержимому сертификатов доступно несколько функций:

  • KeyM_GetCertificate() возвращает данные сертификата в буфер вызывающей стороны [SWS_KeyM_00058]. Процесс TLS модуля TcpIp использует эту возможность (SWS TcpIp с. 134).
  • KeyM_CertElementGet() считывает сконфигурированные элементы по идентификатору объекта из распарсенного и проверенного сертификата ([SWS_KeyM_00063], [SWS_KeyM_00127]).
  • Элементы с множественными значениями вызывающая сторона перебирает с помощью KeyM_CertElementGetFirst() и KeyM_CertElementGetNext(), а также самостоятельно управляемого итератора ([SWS_KeyM_00064], [SWS_KeyM_00065], [SWS_KeyM_00042]). Это возможно только для элементов с KeyMCertificateElementHasIteration [SWS_KeyM_00148].
  • В качестве альтернативы KeyM_CertificateElementGetCount() и KeyM_CertificateElementGetByIndex() возвращают количество и целевые отдельные записи ([SWS_KeyM_91015], [SWS_KeyM_91014]).

С помощью итерации DCM считывает белые списки (whitelists) из сертификатов (SWS DCM с. 155).

Поведение при ошибке

При включенном обнаружении ошибок разработки KeyM проверяет при каждом вызове:

  • состояние инициализации (KEYM_E_UNINIT) [SWS_KeyM_00144],
  • размер буферов результатов (KEYM_E_SMALL_BUFFER) [SWS_KeyM_00145],
  • нулевые указатели (KEYM_E_PARAM_POINTER) [SWS_KeyM_00146].

Эта функция используется для подготовки операции обновления ключа. Основная цель — предоставить информацию для ключевой операции на сервер ключей. Другие операции могут начать согласование общего секрета, который в дальнейшем используется для получения ключевого материала. Эта функция доступна только в том случае, если для параметра «Включена функция подготовки ключа MCrypto» установлено значение TRUE.

Std_ReturnType KeyM_Prepare (const uint8* Request Data, uint16 Request Data Length, uint8* Response Data, uint16* Response Data Length);
KeyM_ServiceCertificateCallbackNotification функция

Уведомляет приложение о завершении операции службы сертификации. Эта функция используется подмодулем сертификата. Этот обратный вызов предоставляется только в том случае, если для параметра Key MService Certificate Function Enabled установлено значение TRUE. Имя функции настраивается с помощью функции уведомления об обратном вызове сертификата Key MService.

KeyM_Start функция
