Отображает сигналы RTE на I-PDUs и управляет их передачей, приемом и мониторингом через PDU Router.

COM упаковывает сигналы и сигнальные группы RTE в I-PDUs и передает их на шину исключительно через PDU Router. Наоборот, он распаковывает принятые I-PDUs из Com_RxIndication и уведомляет RTE [SWS_Com_00123]. Отправка выполняется согласно сконфигурированным режимам передачи, циклическую составляющую берет на себя Com_MainFunctionTx. Коммуникация осуществляется только для I-PDUs, чья группа I-PDU запущена, обычно модулем BswM [SWS_Com_91001]. Остановленные группы приводят к COM_SERVICE_NOT_AVAILABLE; отсутствие подтверждений выявляется мониторингом дедлайнов.

COM выступает посредником между ориентированной на сигналы RTE и ориентированным на I-PDU коммуникационным стеком. RTE записывает сигналы с помощью Com_SendSignal, а группы сигналов — с помощью Com_SendSignalGroup [SWS_Com_00197] [SWS_Com_00200]. Чтение выполняется через соответствующие API приема [SWS_Com_00198]. Вниз PDU Router является единственным интерфейсом (RS COM с. 12). PduR вызывает Com_RxIndication, Com_TxConfirmation и Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001].

Контекстная диаграмма: встраивание COM между RTE, BswM, J1939Rm и PduR. Источники: SWS PduR с. 24, SWS BswM с. 93

После Com_Init межконтроллерная связь (inter-ECU) еще не разрешена [SWS_Com_00432]. Разрешение осуществляется через группы I-PDU, которыми в основном управляет BswM с помощью Com_IpduGroupStart и Com_IpduGroupStop [SWS_Com_91001] [SWS_Com_91002]. I-PDU активна до тех пор, пока запущена хотя бы одна из ее групп [SWS_Com_00771]. При остановке COM отбрасывает незавершенные запросы на передачу [SWS_Com_00777].

При отправке механизм Transmission Mode Selection выбирает между двумя сконфигурированными режимами (TPS SystemTemplate с. 274). Циклические составляющие берет на себя Com_MainFunctionTx [SWS_Com_00399]. На CAN передача выполняется напрямую, на FlexRay FrIf забирает данные через TriggerTransmit (SWS PduR с. 101). При приеме COM отбрасывает сигналы с неустановленным битом обновления (Update-Bit), а также целые группы сигналов, если один групповой сигнал отфильтровывается [SWS_Com_00802] [SWS_Com_00836]. Для цепочек трансформаторов предусмотрен доступ к массиву через Com_SendSignalGroupArray [SWS_Com_00851].

Диаграмма последовательности: отправка группы сигналов через CAN (напрямую) или FlexRay (TriggerTransmit) с последующим подтверждением для RTE. Источники: SWS COM с. 87, SWS RTE с. 329

В случае ошибки действует следующее:

  • Ошибки разработки, такие как COM_E_UNINIT или COM_E_PARAM_POINTER, передаются в DET [SWS_Com_00442] [SWS_Com_00804].
  • При остановленной группе API возвращают COM_SERVICE_NOT_AVAILABLE [SWS_Com_00865].
  • Если подтверждение отправки отсутствует, мониторинг дедлайнов отправки сообщает об этом через ComTimeoutNotification [SWS_Com_00304].

Роль COM между RTE и PDU Router

Модуль AUTOSAR COM выступает посредником между сигнало-ориентированным представлением RTE и представлением коммуникационного стека, ориентированным на I-PDU. Сигналы и группы сигналов записываются в I-PDUs через Com_SendSignal и Com_SendSignalGroup [SWS_Com_00197] [SWS_Com_00200]. С помощью Com_ReceiveSignal и Com_ReceiveSignalGroup они считываются обратно [SWS_Com_00198] [SWS_Com_00201]. На нижнем уровне PDU Router является единственным интерфейсом COM (RS COM с. 12). COM вызывает там PduR_ComTransmit [SWS_Com_00669]. В свою очередь, COM предоставляет PduR функции обратного вызова Com_RxIndication, Com_TxConfirmation и Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001]. При этом PduR преобразует идентификаторы I-PDU между модулем-источником и модулем-назначением (SWS PduR с. 33).

Помимо RTE интерфейсы COM используют и другие модули базового программного обеспечения:

  • BswM управляет через опциональные интерфейсы группами I-PDU, мониторингом дедлайнов приема и режимами передачи (SWS BswM с. 93).
  • J1939Rm целенаправленно инициирует I-PDUs через Com_TriggerIPDUSendWithMetaData [SWS_Com_00858] (SWS J1939Rm с. 62).
  • Об ошибках COM сообщает в DET [SWS_Com_00670].

Контекстная диаграмма: COM находится между RTE, BswM и J1939Rm сверху и PduR снизу. До интерфейсных модулей и модулей TP COM добирается исключительно через PduR. Источники: RS COM с. 12, SWS PduR с. 24, SWS BswM с. 93

Жизненный цикл: инициализация, группы I-PDU и статус

Com_Init инициализирует внутренние и внешние интерфейсы и переменные конфигурацией типа Com_ConfigType. Связь inter-ECU после этого еще не разрешена [SWS_Com_00432] [SWS_Com_00825]. Com_GetStatus возвращает COM_UNINIT или COM_INIT; после сброса действует COM_UNINIT [SWS_Com_00194] [SWS_Com_00819]. Com_DeInit останавливает все запущенные группы I-PDU и возвращает модуль в неинициализированное состояние [SWS_Com_00130].

Связь разрешается отдельно для каждой группы I-PDU:

  • Com_IpduGroupStart запускает группу, при необходимости с повторной инициализацией данных I-PDU. Com_IpduGroupStop снова останавливает ее [SWS_Com_91001] [SWS_Com_91002].
  • I-PDU активна до тех пор, пока запущена хотя бы одна из ее групп [SWS_Com_00771].
  • I-PDUs без привязки к группе запускает уже Com_Init, причем аналогично initialize = true [SWS_Com_00840].
  • При остановке COM отбрасывает ожидающие запросы на отправку, включая повторные попытки [SWS_Com_00777]. Более поздние подтверждения отправки для остановленной I-PDU COM игнорирует [SWS_Com_00800].

Как правило, BswM переключает группы через действие BswMPduGroupSwitch. Его параметр BswMPduGroupSwitchReinit соответствует аргументу initialize (SWS BswM с. 165). Циклическая составляющая отправки начинается после сконфигурированного timeOffset, начиная с Com_IpduGroupStart (TPS SystemTemplate с. 268).

Диаграмма состояний: состояние модуля и активация I-PDU через ее группы I-PDU. Источники: [SWS_Com_00432] [SWS_Com_00130] [SWS_Com_00771] [SWS_Com_00840] [SWS_Com_00777]

Отправка: от сигнала к I-PDU на шине

Com_SendSignal работает асинхронно [SWS_Com_00197]. Для данных, которые должны передаваться атомарно, RTE выполняет действия в два шага: сначала она записывает все групповые сигналы с помощью Com_SendSignal. Затем с помощью Com_SendSignalGroup она запускает передачу группы (SWS RTE с. 329). При этом COM выставляет бит обновления (Update-Bit) группы [SWS_Com_00801].

Когда и как часто отправляется I-PDU, определяют режимы передачи:

  • Для каждой I-PDU статически сконфигурированы два режима (True/False). Transmission Mode Selection выбирает между ними, в том числе во время выполнения (TPS SystemTemplate с. 274).
  • В качестве альтернативы Com_SwitchIpduTxMode явно устанавливает режим [SWS_Com_00784]. Циклические отправки в этом случае сдвигаются на ComTxModeTimeOffset [SWS_Com_00881].
  • Com_TriggerIPDUSend инициирует одиночную отправку независимо от режима передачи, однако только для запущенных I-PDUs [SWS_Com_00348] [SWS_Com_00861] (TPS SystemTemplate с. 371).
  • ComMinimumDelayTime принудительно задает минимальный интервал между двумя отправками [SWS_Com_00828].

Com_MainFunctionTx берет на себя все действия по отправке, которые не выполняются напрямую в функциях, вызываемых со стороны RTE [SWS_Com_00399]. Если сконфигурирована ComPreparationNotification, она вызывает Com_CbkTxPrep перед обработкой I-PDU [SWS_Com_00886] [SWS_Com_91013]. Com_TxIpduCallout может предотвратить дальнейшую обработку I-PDU с помощью false [SWS_Com_00346].

Процесс различается в зависимости от шинной системы:

  • CAN: I-PDU передается напрямую через PduR_ComTransmit.
  • FlexRay: после PduR_ComTransmit FrIf забирает данные только к слоту отправки через Com_TriggerTransmit (SWS PduR с. 101).
  • LIN: кадры, не являющиеся спорадическими (Sporadic Frames), запрашиваются исключительно через TriggerTransmit в соответствии с расписанием (SWS PduR с. 88).

Com_TriggerTransmit ничего не копирует и возвращает E_NOT_OK, если предложенный буфер слишком мал или I-PDU остановлена [SWS_Com_00869] [SWS_Com_00884]. С помощью Com_TxConfirmation COM прерывает текущие таймеры дедлайнов отправки [SWS_Com_00880]. Кроме того, он сообщает о каждой успешной отправке через сконфигурированное уведомление [SWS_Com_00883]. При обработке IMMEDIATE это происходит немедленно, при DEFERRED — с задержкой по времени через флаг (SWS COM с. 91).

Диаграмма последовательности: отправка группы сигналов, передача в CAN (напрямую) или FlexRay (TriggerTransmit) и последующее подтверждение. Источники: SWS COM с. 87, SWS PduR с. 101, SWS RTE с. 329, [SWS_Com_00880]

Прием: индикация, распаковка и уведомление

PduR вызывает Com_RxIndication с идентификатором I-PDU, длиной, указателем данных и MetaData [SWS_Com_00123]. Этот путь одинаков для CanIf, FrIf и LinIf; PduR при этом буферизацию не выполняет (SWS PduR с. 97). Затем I-PDU проходит следующие проверки:

  • Сконфигурированный Com_RxIpduCallout вызывается всегда, причем до обработки счетчика и с полной I-PDU [SWS_Com_00889] [SWS_Com_00816]. Если он возвращает false, I-PDU далее не обрабатывается [SWS_Com_00700].
  • Сигналы с неустановленным битом обновления (Update-Bit) COM отбрасывает [SWS_Com_00802].
  • Если бит обновления отсутствует из-за того, что принятая I-PDU короче, чем ожидалось, он считается установленным [SWS_Com_00794].
  • Если COM отфильтровывает групповой сигнал, он отбрасывает всю группу сигналов [SWS_Com_00836].

Диаграмма деятельности: решения при обработке принятой I-PDU вплоть до уведомления. Источники: [SWS_Com_00889] [SWS_Com_00700] [SWS_Com_00802] [SWS_Com_00794] [SWS_Com_00836] [SWS_Com_00726]; порядок «бит обновления перед фильтром» является интерпретацией.

То, как COM уведомляет RTE, зависит от типа обработки. При IMMEDIATE COM вызывает колбэки RTE непосредственно в контексте индикации. При DEFERRED COM сначала лишь устанавливает флаг и копирует данные (SWS COM с. 92). Проверка этого флага, предположительно, происходит в Com_MainFunctionRx, которая берет на себя обработку приема, не выполненную непосредственно в Com_RxIndication [SWS_Com_00398]. В случае групп сигналов COM информирует только тогда, когда все групповые сигналы распакованы. Затем RTE вызывает ровно один раз Com_ReceiveSignalGroup и далее Com_ReceiveSignal для каждого группового сигнала (SWS RTE с. 329). Принятые MetaData COM сохраняет для RTE [SWS_Com_00888].

Диаграмма последовательности: индикация со стороны PduR, уведомление IMMEDIATE по сравнению с DEFERRED и выборка группы сигналов со стороны RTE. Источники: SWS COM с. 92, SWS RTE с. 329, [SWS_Com_00123]

Большие I-PDUs, массивы сигнальных групп и метаданные

Большие I-PDUs передаются по транспортным протоколам. Для этого COM предоставляет собственный TP-интерфейс, соответствующий верхнему TP-интерфейсу PduR (SWS PduR с. 24):

  • Прием: Com_StartOfReception, Com_CopyRxData и Com_TpRxIndication [SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650].
  • Отправка: Com_CopyTxData и Com_TpTxConfirmation [SWS_Com_00693] [SWS_Com_00725].

Для работы с TP действуют некоторые специальные правила:

  • При TpSduLength = 0 COM сообщает сконфигурированную максимальную длину [SWS_Com_00874].
  • Если большая I-PDU инициируется повторно, пока она еще передается, COM отклоняет дополнительный запрос [SWS_Com_00863].
  • Если Com_TriggerIPDUSend инициирует передачу, пока буфер заблокирован, COM сохраняет запрос и отправляет данные позже [SWS_Com_00867].

Диаграмма последовательности: сегментированный прием большой I-PDU через CanTp и PduR, упрощенно без SecOC. Источники: SWS SecOC с. 111, [SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650] [SWS_Com_00838]

Для цепочек трансформеров RTE обращается к группам сигналов как к массиву байтов. Для этого предусмотрены Com_SendSignalGroupArray и Com_ReceiveSignalGroupArray [SWS_Com_00851] [SWS_Com_00854]. Соответствующие правила:

  • Размер массива: он начинается с байтового смещения сигнала группы с наименьшим ComBitPosition. Он заканчивается на последнем байте сигнала группы с наибольшим ComBitPosition [SWS_Com_00844] [SWS_Com_00845].
  • Обработка: при отправке COM обрабатывает вызов в отношении Transfer Properties и Transmission Mode Selection аналогично Com_SendSignalGroup [SWS_Com_00847]. Поддерживается только ограниченный набор фильтров [SWS_Com_00848].
  • Предварительные условия: данные должны иметь фиксированный размер, быть выровнены по байтам и не должны содержать посторонних сигналов [SWS_Com_00841]. Для таких групп использование API одиночных сигналов и групп сигналов недопустимо [SWS_Com_00843].

COM Based Transformer выполняет сериализацию данных точно так же, как это сделал бы сам COM. Последующие трансформеры затем добавляют CRC и счетчик последовательности (SWS ComXf с. 14, EXP LSA с. 103).

Диаграмма последовательности: RTE выполняет цепочку трансформеров и передает результат одним вызовом Com_SendSignalGroupArray. Источники: SWS ComXf с. 14, [SWS_Com_00846] [SWS_Com_00847]

MetaData передаваемой I-PDU берутся из последней передачи через RTE или, если таковой нет, из ComMetaDataDefault. Переданные с Com_TriggerIPDUSendWithMetaData MetaData действуют только для инициированной этим передачи [SWS_Com_00887] [SWS_Com_00862].

Конфигурация, планирование и сигнальный шлюз

COM содержит три типа Main Functions: Com_MainFunctionRx, Com_MainFunctionTx и Com_MainFunctionRouteSignals. Каждый из них может быть инстанцирован многократно и является реентерабельным для различных экземпляров [SWS_Com_00398] [SWS_Com_00399] [SWS_Com_00400]. Они вызываются без параметров планировщиком BSW (SWS BSWGeneral с. 79). Их периоды определяются в EcuInstance через comConfigurationRxTimeBase, comConfigurationTxTimeBase и comConfigurationGwTimeBase (TR Interoperability с. 98). Соответствующее уведомление Rte_COMCbkTxPrep_<mn> привязано к конкретному экземпляру Com_MainFunctionTx (SWS RTE с. 832).

Сигнальный шлюз является составной частью COM (SRS Gateway с. 11). Он перенаправляет принятые сигналы в Com_MainFunctionRouteSignals [SWS_Com_00400]. При этом он проходит определенные этапы обработки на стороне приема и передачи [SWS_Com_00872] [SWS_Com_00873]. Он также может отображать отдельные сигналы группы на самостоятельные сигналы [SWS_Com_00833].

Конфигурация подчиняется ряду граничных условий:

  • Поддерживаются типы данных из [SWS_Com_00675]. Сигналы типов UINT8_N и UINT8_DYN должны быть выровнены по байтам [SWS_Com_00105].
  • Все I-PDU одной группы имеют одинаковое направление [SWS_Com_00871].
  • Если для принимаемого сигнала настроено недопустимое значение (Invalid), должна быть также сконфигурирована ComDataInvalidAction [SWS_Com_00859].

Идентификаторы сигналов, групп и групп I-PDU представляют собой значения uint16 с отсчетом от нуля [SWS_Com_00820] [SWS_Com_00821] [SWS_Com_00822]. Их символические имена формируются из ComHandleId (TPS ECUConfiguration с. 138).

Поведение при ошибке

Об ошибках разработки COM сообщает через Det_ReportError с ModuleId 50 [SWS_Com_00442]. Определены:

  • COM_E_PARAM для некорректных параметров [SWS_Com_00803].
  • COM_E_UNINIT для вызовов до Com_Init или после Com_DeInit. Исключение составляют функции состояния, версии и Main Functions [SWS_Com_00804].
  • COM_E_PARAM_POINTER для нулевых указателей [SWS_Com_00805].
  • COM_E_INIT_FAILED для недействительного выбора конфигурации [SWS_Com_00837].
  • В качестве ошибки времени выполнения: COM_E_SKIPPED_TRANSMISSION для отклоненных запросов на передачу [SWS_Com_00864].

API сигналов возвращают COM_SERVICE_NOT_AVAILABLE, если группа I-PDU остановлена или имеет место ошибка разработки [SWS_Com_00865]. Тем не менее Com_ReceiveSignalGroupArray копирует последние известные данные [SWS_Com_00857].

Для контроля дедлайна при передаче действует следующее:

  • Таймер запускается, когда сигнал передается на нижний уровень. В первый раз он инициализируется значением ComFirstTimeout, затем — значением ComTimeout [SWS_Com_00878] [SWS_Com_00879].
  • Если таймер истекает, COM вызывает ComTimeoutNotification [SWS_Com_00304].
  • В режиме передачи NONE контроль отключен [SWS_Com_00835].

На стороне приема действуют следующие механизмы:

  • BswM отключает и снова включает мониторинг дедлайна через Com_DisableReceptionDM и Com_EnableReceptionDM [SWS_Com_91003] [SWS_Com_91004] (SWS BswM с. 148).
  • Если таймер приема истекает, SUBSTITUTE заменяет значения на ComTimeoutSubstitutionValue [SWS_Com_00875] [SWS_Com_00876].

  • Если I-PDU не назначена ни одной группе I-PDU, COM запускает эту I-PDU уже внутри Com_Init так, как если бы она была запущена через Com_IpduGroupStart с установленным параметром инициализации ([SWS_Com_00840]).
