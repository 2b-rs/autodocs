Управляет выходами микроконтроллера с широтно-импульсной модуляцией по каналам через период и коэффициент заполнения.

Драйвер PWM как модуль MCAL управляет выходами микроконтроллера с широтно-импульсной модуляцией по каналам, обращаясь для этого напрямую к его регистрам. Согласно Pwm_Init, Pwm User задает коэффициент заполнения и, для каналов с переменным периодом, также период. Пользователи могут переводить выходы в состояние Idle и включать или отключать уведомления по фронтам [SWS_Pwm_91000]. Опционально драйвер управляет двухфазным переключением состояния питания через подготовку и установку. При активном обнаружении ошибок он сообщает о таких сбоях, как отсутствие инициализации или недействительные каналы, и в этом случае ничего не выполняет [SWS_Pwm_00201].

Драйвер PWM является модулем MCAL и управляет выходами микроконтроллера с широтно-импульсной модуляцией через его регистры. Поэтому ему не требуются интерфейсы более низкоуровневых модулей (SWS PWM Driver с. 44). Он инициализируется синхронно с помощью Pwm_Init и указателя на конфигурационный набор [SWS_Pwm_00095], который ECU State Manager вызывает в качестве опционального интерфейса инициализации (SWS EcuM с. 152). Обычно он используется IoHwAb, например, через драйвер выходного каскада (SWS IoHwAb с. 37).

Контекстная диаграмма: EcuM инициализирует драйвер, Pwm User работает с ним, а драйвер отправляет уведомления и сообщает об ошибках. Источники: [SWS_Pwm_00105], [SWS_Pwm_00198], [SWS_Pwm_00104]

Управление осуществляется с помощью 16-битного коэффициента заполнения, где 0x8000 соответствует 100 % (SWS PWM Driver с. 18). Основные службы:

  • Pwm_SetDutyCycle изменяет коэффициент заполнения [SWS_Pwm_91000]. При 0 % и 100 % устанавливается статический уровень в зависимости от полярности.
  • Pwm_SetPeriodAndDuty дополнительно изменяет период, но только для каналов класса PWM_VARIABLE_PERIOD [SWS_Pwm_00110].
  • Pwm_SetOutputToIdle немедленно переключает на уровень Idle [SWS_Pwm_91002].
  • Pwm_GetOutputState считывает внутренний уровень [SWS_Pwm_00100].

Диаграмма состояний: канал переключается через API между модуляцией, статическим уровнем и состоянием Idle. Источники: [SWS_Pwm_91000], [SWS_Pwm_91001], SWS PWM Driver с. 31

Уведомления по фронтам включаются для каждого канала с помощью Pwm_EnableNotification [SWS_Pwm_91004] и поступают к Pwm User как Pwm_Notification_<#Channel> [SWS_Pwm_00105]. Опционально драйвер также управляет состояниями питания в две фазы. Pwm_PreparePowerState запускает подготовку [SWS_Pwm_00183], которую завершает циклический Pwm_Main_PowerTransitionManager [SWS_Pwm_00189]. После этого Pwm_SetPowerState устанавливает состояние [SWS_Pwm_00166].

При активном обнаружении ошибок функции сообщают о таких ошибках, как PWM_E_UNINIT, PWM_E_PARAM_CHANNEL или PWM_E_PERIOD_UNCHANGEABLE [SWS_Pwm_00201], и возвращаются без выполнения действий (SWS PWM Driver с. 44). В этих случаях Pwm_GetOutputState возвращает PWM_LOW [SWS_Pwm_30051]. Если Pwm_SetPowerState вызывается, пока драйвер еще используется, возникает ошибка времени выполнения PWM_E_NOT_DISENGAGED [SWS_Pwm_00202].

Роль в MCAL: драйвер между блоком PWM и Pwm User

Драйвер PWM инкапсулирует выходы микроконтроллера с широтно-импульсной модуляцией. Будучи модулем уровня MCAL, он напрямую обращается к регистрам микроконтроллера и поэтому не требует интерфейсов нижележащих модулей (SWS PWM Driver с. 44). По той же причине он не предоставляет функций обратного вызова (callbacks) для нижних уровней (SWS PWM Driver с. 40) и не предлагает сервисных интерфейсов (SWS PWM Driver с. 44). Его службы доступны через Pwm.h, например Pwm_Init [SWS_Pwm_00095], Pwm_SetDutyCycle [SWS_Pwm_91000] и Pwm_GetOutputState [SWS_Pwm_00100]. Стандартные типы Std_ReturnType и Std_VersionInfoType он импортирует из Std_Types.h [SWS_Pwm_00094].

ECU State Manager содержит Pwm_Init среди своих опциональных интерфейсов инициализации (SWS EcuM с. 152). В случае использования выходного каскада мощности драйвер выходного каскада в IoHwAb вызывает службы PWM, DIO и SPI, настраивая с их помощью, среди прочего, напряжения и частоты (SWS IoHwAb с. 37). В обратном направлении драйвер вызывает функции двух типов: канальные уведомления Pwm_Notification_<#Channel> [SWS_Pwm_00105] и, в рамках управления питанием, IoHwAb_Pwm_NotifyReadyForPowerState<#Mode> [SWS_Pwm_00198]. Об ошибках разработки он опционально сообщает через Det_ReportError [SWS_Pwm_00104]. Если аппаратура предоставляет различные механизмы для разных каналов, это абстрагируется не через специфичные для производителя инфиксы API, а через номер канала (TPS BSWMDT с. 122).

Контекстная диаграмма: драйвер Pwm инициализируется EcuM и обслуживается Pwm User. Он циклически вызывается планировщиком (Scheduler), отправляет уведомления Pwm User и сообщает об ошибках в DET, а также управляет блоком PWM через его регистры. Источники: [SWS_Pwm_00104], [SWS_Pwm_00105], [SWS_Pwm_00189], [SWS_Pwm_00198], SWS EcuM с. 152, SWS IoHwAb с. 37, RS PWM Driver с. 14

Модель сигнала: период, коэффициент заполнения, полярность и классы каналов

Обращение к каналу происходит через числовой идентификатор Pwm_ChannelType [SWS_Pwm_00106]. Период имеет тип Pwm_PeriodType, являющийся специфичным для реализации типом разрядностью от 8 до 32 бит [SWS_Pwm_00107]. Три понятия определяют сигнал (SWS PWM Driver с. 9):

  • Полярность определяет начальный уровень каждого периода.
  • Коэффициент заполнения задает долю этого начального уровня в периоде.
  • Состояние Idle — это исходное состояние после Pwm_SetOutputToIdle или Pwm_DeInit.

Схема описания сигнала сопоставляет обе полярности: PWM_HIGH и PWM_LOW (SWS PWM Driver с. 7).

Коэффициент заполнения представляет собой 16-битное значение. 0x0000 соответствует 0 %, а 0x8000 — 100 %. В качестве рекомендаций по реализации спецификация указывает AbsoluteDutyCycle = ((uint32)AbsolutePeriodTime * RelativeDutyCycle) >> 15; (SWS PWM Driver с. 18). Соответственно, Pwm_SetDutyCycle и Pwm_SetPeriodAndDuty ограничивают параметр DutyCycle значениями Min=0x0000 и Max=0x8000 [SWS_Pwm_91000] [SWS_Pwm_91001].

Класс канала Pwm_ChannelClassType определяет, что каналу разрешено изменять во время выполнения [SWS_Pwm_00110]:

  • PWM_VARIABLE_PERIOD: период и коэффициент заполнения можно изменять.
  • PWM_FIXED_PERIOD: можно изменять только коэффициент заполнения.
  • PWM_FIXED_PERIOD_SHIFTED: фиксированный, сдвинутый период, который нельзя изменять; доступно только в том случае, если это поддерживается аппаратурой.

Схема сдвинутого периода показывает каналы с одинаковым периодом, начала периодов которых смещены относительно друг друга на фиксированное время (SWS PWM Driver с. 23).

Жизненный цикл и управление сигналом: от Pwm_Init до состояния Idle

Pwm_Init является синхронной и нереентерабельной. Функция получает с ConfigPtr указатель на конфигурационный набор [SWS_Pwm_00095]. Его тип Pwm_ConfigType имеет аппаратно-зависимое содержимое [SWS_Pwm_00111]. Согласно схеме инициализации, выходы после этого в зависимости от конфигурации находятся в состоянии Low, High или в режиме модуляции. Уведомления появляются только после первого вызова Pwm_EnableNotification (SWS PWM Driver с. 46). Если Pwm_Init вызывается повторно для уже инициализированного драйвера, необходимо сообщить об ошибке разработки PWM_E_ALREADY_INITIALIZED [SWS_Pwm_50002].

Pwm_DeInit также является синхронной и нереентерабельной [SWS_Pwm_00096]. Функция деинициализирует модуль, переводит выходы в состояние Idle и отключает прерывания PWM, а также уведомления по фронтам. Через PwmDeInitApi ее можно включать и отключать (SWS PWM Driver с. 27). Интерпретация: после этого модуль, предположительно, снова считается неинициализированным, так что повторный вызов Pwm_Init допустим.

Диаграмма состояний: жизненный цикл модуля с инициализацией, деинициализацией и ошибками при неправильной последовательности вызовов. Возврат в состояние «не инициализирован» после Pwm_DeInit является интерпретацией. Источники: [SWS_Pwm_00095], [SWS_Pwm_00096], [SWS_Pwm_50002], [SWS_Pwm_20002], [SWS_Pwm_30051], SWS PWM Driver с. 27

В процессе работы Pwm_SetDutyCycle устанавливает коэффициент заполнения канала [SWS_Pwm_91000]. При 0 % и 100 % выход устанавливается статически (SWS PWM Driver с. 28):

  • При 0 % уровень инверсен настроенной полярности.
  • При 100 % уровень соответствует полярности.
  • При промежуточных значениях осуществляется модуляция в соответствии с периодом, коэффициентом заполнения и полярностью.

Согласно схеме, драйвер применяет новый коэффициент заполнения в конце текущего периода, если реализация это поддерживает, иначе — немедленно (SWS PWM Driver с. 37).

Pwm_SetPeriodAndDuty устанавливает период и коэффициент заполнения совместно [SWS_Pwm_91001]. При этом действуют три правила (SWS PWM Driver с. 30):

  • Период обновляется в конце периода, если реализация это поддерживает и это настроено через PwmPeriodUpdatedEndperiod.
  • Помехи (выбросы) на выходе должны подавляться.
  • Коэффициент заполнения передается вместе с периодом, чтобы частота и коэффициент заполнения соответствовали друг другу.

Диаграмма деятельности: обработка Pwm_SetDutyCycle и Pwm_SetPeriodAndDuty с проверкой класса канала и специальной обработкой 0 % и 100 %. Источники: [SWS_Pwm_40002], SWS PWM Driver с. 28, SWS PWM Driver с. 30, SWS PWM Driver с. 44

Pwm_SetOutputToIdle немедленно переводит выход в настроенное состояние Idle [SWS_Pwm_91002]. Каналы с переменным периодом впоследствии снова активируются через Pwm_SetPeriodAndDuty (SWS PWM Driver с. 31). Схема «Setting Pwm output to idle» демонстрирует именно эту последовательность (SWS PWM Driver с. 50). Pwm_GetOutputState синхронно считывает внутреннее состояние выхода как PWM_HIGH или PWM_LOW [SWS_Pwm_00100] [SWS_Pwm_00108]. Схема в спецификации требований локализует считываемое значение на выходе блока PWM, то есть до логики портов, а не на физическом выводе (RS PWM Driver с. 14).

Диаграмма состояний: выходные состояния канала (модуляция, статический уровень, Idle) и API, переключающие между ними. Источники: [SWS_Pwm_91000], [SWS_Pwm_91001], [SWS_Pwm_91002], SWS PWM Driver с. 28, SWS PWM Driver с. 31, SWS PWM Driver с. 46

Уведомления по фронтам для каждого канала

С помощью Pwm_EnableNotification Pwm User включает уведомление для канала. Параметр типа Pwm_EdgeNotificationType выбирает PWM_RISING_EDGE, PWM_FALLING_EDGE или PWM_BOTH_EDGES [SWS_Pwm_91004] [SWS_Pwm_00109]. Функция сбрасывает ожидающие прерывания (SWS PWM Driver с. 35). Она, как и Pwm_DisableNotification [SWS_Pwm_91003], существует только в том случае, если включен PwmNotificationSupported (SWS PWM Driver с. 34).

Драйвер вызывает настроенную функцию Pwm_Notification_<#Channel> в соответствии с последним вызовом Pwm_EnableNotification или Pwm_DisableNotification. При этом он сбрасывает соответствующий флаг прерывания (SWS PWM Driver с. 42). Callback не имеет параметров и объявляется через Pwm_Externals.h. Является ли он реентерабельным, зависит от реализации Pwm User [SWS_Pwm_00105].

Диаграмма последовательности: процесс от инициализации через включение и отключение уведомления по фронтам до прекращения последующих вызовов callback. Источники: [SWS_Pwm_91004], [SWS_Pwm_91003], [SWS_Pwm_00105], SWS PWM Driver с. 52, SWS PWM Driver с. 42

Состояния питания периферии PWM

Управление состояниями питания является опциональной функцией. Оно ограничивается периферией PWM и предполагает, что приложение, управление режимами и IoHwAb уже выполнили вышестоящие граничные условия (SWS PWM Driver с. 17). Если PwmLowPowerStatesSupport активен, генерируются четыре API состояний питания (SWS PWM Driver с. 16). Pwm_PowerStateType поддерживает PWM_FULL_POWER (0x00), а также диапазон 1..255 для состояний с уменьшающимся энергопотреблением. В R20-11 тип определен как перечисление [SWS_Pwm_00197]. Более поздняя редакция, напротив, определяет его как тип, производный от uint8 (SWS PWM Driver с. 25).

Смена состояния питания происходит в две фазы:

  1. Pwm_PreparePowerState запускает подготовку и возвращает в параметре результата PWM_SERVICE_ACCEPTED или причину отклонения [SWS_Pwm_00183] [SWS_Pwm_00165]. То, что невозможно завершить немедленно, выполняет циклически вызываемая Pwm_Main_PowerTransitionManager [SWS_Pwm_00189] [SWS_Pwm_00190]. Частота ее вызова вариативна, а callbacks она отправляет только в асинхронном режиме (SWS PWM Driver с. 41). О завершении подготовки драйвер сообщает с помощью IoHwAb_Pwm_NotifyReadyForPowerState<#Mode> [SWS_Pwm_00198].
  2. Pwm_SetPowerState переводит аппаратуру в подготовленное состояние [SWS_Pwm_00166]. Предварительные действия, такие как перевод всех каналов в состояние IDLE и отмена регистрации всех уведомлений, должны быть уже выполнены ответственными SWC, например IoHwAb. Неявные промежуточные состояния функция не выполняет (SWS PWM Driver с. 36).

Диаграмма состояний: двухфазное переключение состояния питания с подготовкой, завершением и установкой, а также ошибки последовательности. Источники: [SWS_Pwm_00183], [SWS_Pwm_00166], [SWS_Pwm_00165], [SWS_Pwm_00190], SWS PWM Driver с. 39, SWS IoHwAb с. 61

Pwm_GetCurrentPowerState [SWS_Pwm_00177] возвращает текущее состояние, Pwm_GetTargetPowerState [SWS_Pwm_00180] — запрошенное. Пока переход не выполняется, оба значения совпадают (SWS PWM Driver с. 38). Спецификация IoHwAb демонстрирует взаимодействие BswM, RTE/SchM, IoHwAb, ADC и PWM для асинхронного случая (SWS IoHwAb с. 60). В синхронном случае подготовка уже завершена к моменту возврата из API подготовки (SWS IoHwAb с. 61).

Диаграмма последовательности: асинхронный переход в состояние с низким энергопотреблением под управлением IoHwAb. Процесс упрощен, и ADC опущен. Источники: [SWS_Pwm_00183], [SWS_Pwm_00189], [SWS_Pwm_00198], [SWS_Pwm_00166], SWS IoHwAb с. 57, SWS IoHwAb с. 60

Конфигурация, контейнеры каналов и параллелизм

Обязательными параметрами канала являются назначенный аппаратный канал, значения по умолчанию для периода и коэффициента заполнения, полярность, уровень Idle и класс канала. Фазовый сдвиг, опорный канал и микроконтроллерные свойства являются опциональными, если они поддерживаются аппаратурой (SWS PWM Driver с. 25). В модели конфигурации PwmChannelConfigSet содержит как минимум один PwmChannel, а PwmDutycycleDefault ограничен диапазоном от 0 до 0x8000 (ECUC-Parameter с. 545). PwmChannelClass отображается на Pwm_ChannelClassType. PwmChannelId назначается символическому имени контейнера канала (SWS PWM Driver с. 57).

Опциональные службы включаются и выключаются через конфигурацию: PwmSetOutputToIdle (SWS PWM Driver с. 31), PwmGetOutputState (SWS PWM Driver с. 33), а также упомянутые выше PwmDeInitApi и PwmNotificationSupported.

Для параллельного выполнения действует следующее:

  • Канальные службы, такие как Pwm_SetDutyCycle, являются реентерабельными для различных номеров каналов [SWS_Pwm_91000].
  • API состояний питания не являются реентерабельными [SWS_Pwm_00183].
  • Конфигурации с привязками разделов, которые не поддерживаются реализацией, модуль должен отклонять [SWS_Pwm_00203].

Уровни реентерабельности вплоть до «multi-core reentrant» описаны в руководстве по распределению BSW (BSW-Distribution-Guide) (BSW Distribution Guide с. 18).

Поведение при ошибке

Если обнаружение ошибок разработки активно, функции сообщают об обнаруженных ошибках в Default Error Tracer. Затем они пропускают запрошенную функцию, чтобы не допустить искажения данных или аппаратных регистров (SWS PWM Driver с. 44). Коды ошибок: [SWS_Pwm_00201]:

  • PWM_E_INIT_FAILED (0x10)
  • PWM_E_UNINIT (0x11) для вызовов до инициализации [SWS_Pwm_20002]
  • PWM_E_PARAM_CHANNEL (0x12) для недопустимых каналов [SWS_Pwm_30002]
  • PWM_E_PERIOD_UNCHANGEABLE (0x13) для изменений периода на каналах с фиксированным периодом [SWS_Pwm_40002]
  • PWM_E_ALREADY_INITIALIZED (0x14)
  • PWM_E_PARAM_POINTER (0x15) для параметра NULL в Pwm_GetVersionInfo

Pwm_GetOutputState всегда должна возвращать значение. До инициализации или при недопустимом канале это PWM_LOW [SWS_Pwm_30051].

Диаграмма деятельности: общие проверки API каналов при активном обнаружении ошибок разработки с прерыванием без выполнения действий. Источники: [SWS_Pwm_20002], [SWS_Pwm_30002], [SWS_Pwm_30051], SWS PWM Driver с. 44

API состояний питания дополнительно сообщают об ошибках через Std_ReturnType и тип результата Pwm_PowerStateRequestResultType. Возможные значения: PWM_NOT_INIT, PWM_SEQUENCE_ERROR, PWM_HW_FAILURE, PWM_POWER_STATE_NOT_SUPP и PWM_TRANS_NOT_POSSIBLE [SWS_Pwm_00165]. Для неподдерживаемого состояния, кроме того, определено PWM_E_POWER_STATE_NOT_SUPPORTED [SWS_Pwm_00174], а для состояния, которое не может быть достигнуто напрямую, — PWM_E_TRANSITION_NOT_POSSIBLE [SWS_Pwm_00175].

Если Pwm_SetPowerState вызывается, когда каналы всё ещё находятся не в IDLE или зарегистрированы уведомления, возникает ошибка времени выполнения PWM_E_NOT_DISENGAGED (0x16) [SWS_Pwm_00202] (SWS PWM Driver с. 20). Pwm_Main_PowerTransitionManager просто возвращает управление без инициализации и намеренно не сообщает об ошибке разработки. Причина: циклические задачи могут выполняться ещё до завершения инициализации (SWS PWM Driver с. 41).
