Роль DEM в диагностическом стеке

Diagnostic Event Manager собирает все диагностические события электронного блока управления (ECU). На один ECU приходится ровно один модуль DEM [SWS_Dem_00126]. Каждое событие представляется уникальным EventId и соответствующим именем [SWS_Dem_00153]. В типе Dem_EventIdType значение 0 недопустимо [SWS_Dem_00925]. На стороне входа SW-C и модули BSW сообщают свои результаты тестирования через Dem_SetEventStatus [SWS_Dem_00183]. На стороне выхода DCM использует DEM для чтения и удаления кодов неисправностей, статуса и сопутствующих данных SWS DCM с. 103.

Другие партнеры DEM:

  • NvM берет на себя персистентное сохранение [SWS_Dem_00164] [SWS_Dem_00329].
  • FiM информируется об изменениях статуса [SWS_Dem_00029] [SWS_Dem_01132].
  • Мониторы повторно инициализируются через InitMonitorForEvent, каждый с причиной из Dem_InitMonitorReasonType [SWS_Dem_00003] [SWS_Dem_00942].
  • Поддержка J1939 доступна, если сконфигурирован DemGeneralJ1939 [SWS_Dem_00845].

Контекстная диаграмма: DEM связывает сообщающие мониторы с DCM, J1939Dcm, FiM и NvM. Источники: [SWS_Dem_00183], [SWS_Dem_00003], [SWS_Dem_01253], [SWS_Dem_00845], [SWS_Dem_01131], [SWS_Dem_00164], SWS FiM с. 29, [SWS_Dem_00029]

Запуск, работа и останов

DEM различает предварительно инициализированный режим и полностью инициализированную работу [SWS_Dem_00169].

  • Dem_PreInit инициализирует внутренние состояния, необходимые для обработки событий [SWS_Dem_00180]. К ним относится внутреннее устранение дребезга DEM [SWS_Dem_01213].
  • С этого момента возможны сообщения с дебаунсингом [SWS_Dem_01212].
  • Сообщения, поступающие до Dem_Init, DEM буферизует в очереди [SWS_Dem_00167]. Ее размер можно сконфигурировать [SWS_Dem_00207] [SWS_Dem_01079].
  • Эти ранние сообщения не вызывают callback-функции статуса монитора [SWS_Dem_01289] SWS DEM с. 169.

Dem_Init получает указатель на Dem_ConfigType и инициализирует либо повторно инициализирует модуль [SWS_Dem_00181] [SWS_Dem_00924].

  • Только при этом инициализируется статус монитора. До этого Dem_GetMonitorStatus возвращает значение E_NOT_OK [SWS_Dem_01326].
  • После Dem_Init DEM полностью готов к работе [SWS_Dem_00340].
  • Запрошенный ранее перезапуск рабочего цикла обрабатывается только после этого [SWS_Dem_01318].
  • Все задачи, не управляемые событиями, выполняет Dem_MainFunction [SWS_Dem_00125] [SWS_Dem_00266].
  • Dem_Shutdown завершает незавершенные операции [SWS_Dem_00102]. Измененные энергонезависимые данные передаются в NVRAM не позднее чем во время завершения работы (shutdown) [SWS_Dem_00341].

Диаграмма состояний: жизненный цикл проходит от «не инициализирован» через «предварительно инициализирован» к работе и завершается остановом (shutdown). Источники: [SWS_Dem_00169], [SWS_Dem_00180], [SWS_Dem_00340], [SWS_Dem_00102], [SWS_Dem_00124], [SWS_Dem_00368], [SWS_Dem_00167], [SWS_Dem_01212], [SWS_Dem_00181], [SWS_Dem_00125]

Диаграмма последовательности: сообщения между Dem_PreInit и Dem_Init буферизуются. Dem_Init инициализирует статус монитора, Dem_Shutdown сохраняет измененные данные. Источники: [SWS_Dem_00167], [SWS_Dem_01289], [SWS_Dem_01326], [SWS_Dem_00341], SWS DEM с. 85, [SWS_Dem_00180], [SWS_Dem_01213], [SWS_Dem_01212], [SWS_Dem_00164], [SWS_Dem_00340], [SWS_Dem_00102]

От результата монитора к квалифицированному событию

Dem_SetEventStatus передает значения из Dem_EventStatusType [SWS_Dem_00926]:

  • DEM_EVENT_STATUS_PASSED и DEM_EVENT_STATUS_FAILED уже являются квалифицированными результатами.
  • …_PREPASSED и …_PREFAILED — предварительные результаты, для которых DEM выполняет внутренний дебаунсинг SWS DEM с. 351.

Алгоритм дебаунсинга настраивается для каждого события [SWS_Dem_00413]. На выбор предлагаются: на основе счетчика [SWS_Dem_00414], на основе времени [SWS_Dem_00426] или внутри монитора [SWS_Dem_00437].

Дебаунсинг на основе счетчика:

  • Предварительные результаты увеличивают или уменьшают внутренний счетчик на сконфигурированный шаг [SWS_Dem_00418] [SWS_Dem_00419].
  • Квалифицированные результаты устанавливают счетчик напрямую [SWS_Dem_00420] [SWS_Dem_00421].
  • Пороговые значения определяют состояние неисправности или исправное состояние [SWS_Dem_00416] [SWS_Dem_00417].
  • Опционально можно настроить поведение скачка [SWS_Dem_00422] [SWS_Dem_00424].
  • Счетчик линейно отображается на Fault Detection Counter (−128…+127) [SWS_Dem_00415] SWS DEM с. 108.

При дебаунсинге на основе времени предварительный результат запускает таймер [SWS_Dem_00428] [SWS_Dem_00432].

Диаграмма деятельности: при дебаунсинге на основе счетчика сообщаемый статус определяет изменение счетчика; достижение порогового значения квалифицирует событие. Источники: [SWS_Dem_00415]–[SWS_Dem_00421], SWS DEM с. 108, [SWS_Dem_00414], [SWS_Dem_00424], [SWS_Dem_00422]

Обработка разделена на две части:

  • Синхронно в контексте вызывающей стороны выполняются дебаунсинг на основе счетчика [SWS_Dem_01279], а также биты 0 и 1 статуса монитора [SWS_Dem_01280].
  • Статус UDS DEM, напротив, рассчитывает асинхронно [SWS_Dem_01285].

Условия разрешения и условия сохранения:

  • Условия разрешения проверяются для каждого события [SWS_Dem_00447] и устанавливаются через Dem_SetEnableCondition [SWS_Dem_00201].
  • Пока условие разрешения не выполнено, сообщения не принимаются [SWS_Dem_00449] DEXT с. 198. В зависимости от DemDebounceBehavior дебаунсинг при этом сбрасывается или замораживается [SWS_Dem_00654] [SWS_Dem_00655].
  • Условия сохранения, напротив, управляют только тем, сохраняется ли событие в памяти [SWS_Dem_00459] [SWS_Dem_00556].

Другие вмешательства в обработку событий:

  • Dem_ResetEventDebounceStatus сбрасывает дебаунсинг или замораживает его [SWS_Dem_00684] [SWS_Dem_00685]. На квалификацию события это не влияет SWS DEM с. 267.
  • Dem_ResetEventStatus сбрасывает TestFailed асинхронно [SWS_Dem_00187].

Диаграмма последовательности: проверка разрешения, дебаунсинг и статус монитора выполняются синхронно, статус UDS и callback-функции — асинхронно. Источники: [SWS_Dem_00449], [SWS_Dem_01279], [SWS_Dem_01280], [SWS_Dem_01285], [SWS_Dem_00016], SWS DEM с. 85

Память событий, байт статуса и рабочие циклы

DEM по умолчанию ведет все биты статуса UDS [SWS_Dem_00006]. Каждый переход бита определен отдельно, например для TestFailed [SWS_Dem_00386], ConfirmedDTC [SWS_Dem_00391] и WarningIndicatorRequested [SWS_Dem_00395] SWS DEM с. 88.

Структура памяти событий:

  • Существует первичная память [SWS_Dem_00010] и опционально пользовательские памяти [SWS_Dem_00548].
  • Они организованы в наборы памяти событий [SWS_Dem_01247].
  • Триггер создания записи настраивается [SWS_Dem_00783]–[SWS_Dem_00786] SWS DEM с. 94.

Когда память заполнена:

  • DEM устанавливает индикатор переполнения [SWS_Dem_00397], который можно прочитать через Dem_GetEventMemoryOverflow [SWS_Dem_00559].
  • Он ищет кандидата в соответствии со стратегией вытеснения [SWS_Dem_00400] [SWS_Dem_00401].
  • Если кандидата нет, он отклоняет запрос на сохранение [SWS_Dem_00407].

Freeze Frames и Extended Data Records фиксируются в зависимости от сконфигурированного триггера [SWS_Dem_00799]–[SWS_Dem_00802] [SWS_Dem_00809]. Предварительно сохраненный Freeze Frame при этом имеет приоритет [SWS_Dem_00464].

Диаграмма деятельности: сохранение событий происходит через проверку условия сохранения, свободную запись, переполнение и вытеснение. Источники: [SWS_Dem_00459], [SWS_Dem_00397], [SWS_Dem_00406]–[SWS_Dem_00409], SWS DEM с. 94, [SWS_Dem_00783], [SWS_Dem_00786], [SWS_Dem_00401], [SWS_Dem_00809]

Старение (Aging):

  • Каждая запись имеет счетчик старения [SWS_Dem_00019].
  • Старение начинается после завершения восстановления [SWS_Dem_00698] SWS DEM с. 133.
  • При достижении порогового значения ConfirmedDTC сбрасывается [SWS_Dem_00498], а данные события удаляются [SWS_Dem_01075].

Рабочие циклы:

  • Dem_RestartOperationCycle работает асинхронно и повторно инициализирует затронутые мониторы [SWS_Dem_00194] [SWS_Dem_00679].
  • Очередь для перезапусков отсутствует [SWS_Dem_01316].
  • Зависимые циклы квалифицируются с помощью Dem_SetCycleQualified [SWS_Dem_01221] [SWS_Dem_91001].

Доступ к памяти неисправностей по принципу «выбрать и запросить»

Многие службы DCM работают по одному шаблону: клиент сначала выбирает DTC или группу DTC, а затем вызывает функции, работающие с этой выборкой SWS DEM с. 215.

  • Dem_SelectDTC задает целевой объект, в том числе для Dem_ClearDTC, Dem_GetStatusOfDTC и Dem_SelectFreezeFrameData [SWS_Dem_91016] [SWS_Dem_01253].
  • Выбор относится к памяти событий, сопоставленной с ClientId [SWS_Dem_01254].
  • Клиенты с различными ClientId могут работать параллельно [SWS_Dem_01251].
  • Если тот же клиент вызывает Dem_SelectDTC снова, пока предыдущая операция еще выполняется, он получает DEM_BUSY [SWS_Dem_01306].

Чтение Freeze Frames и Extended Data:

  • Dem_SelectFreezeFrameData и Dem_SelectExtendedDataRecord основываются на выборе DTC [SWS_Dem_01268] [SWS_Dem_01272].
  • Затем функции определения размера и функции Next возвращают данные [SWS_Dem_00074] [SWS_Dem_00071] [SWS_Dem_00075]. Freeze Frame имеет формат {RecordNumber, NumOfDIDs, DID, data…} SWS DEM с. 225.
  • Если запрошена допустимая, но несохраненная запись, DEM возвращает E_OK с пустым буфером [SWS_Dem_00630].
  • Чтобы данные оставались согласованными, DCM во время чтения блокирует обновление с помощью Dem_DisableDTCRecordUpdate и снимает блокировку с помощью Dem_EnableDTCRecordUpdate [SWS_Dem_00270] [SWS_Dem_00271].

Диаграмма последовательности: Freeze Frames выбираются и считываются при заблокированном обновлении; DEM_PENDING приводит к повторным вызовам. Источники: [SWS_Dem_01253], [SWS_Dem_01268], [SWS_Dem_00238], [SWS_Dem_00236], [SWS_Dem_00270], SWS DEM с. 290, [SWS_Dem_00071], [SWS_Dem_00271]

Функции фильтрации:

  • Dem_SetDTCFilter задает критерии фильтрации для последующих запросов [SWS_Dem_00057]. Каждый вызов перезапускает итерацию [SWS_Dem_00649].
  • Затем Dem_GetNumberOfFilteredDTC и Dem_GetNextFilteredDTC возвращают найденные результаты [SWS_Dem_00061] [SWS_Dem_00216].
  • В формате OBD Dem_GetNextFilteredDTC не возвращает DEM_PENDING [SWS_Dem_00653].

Удаление и DTC-Setting:

  • Dem_ClearDTC опционально запрашивает DemClearEventAllowed [SWS_Dem_00665] [SWS_Dem_00515] и повторно инициализирует затронутые мониторы [SWS_Dem_00680].
  • Dem_DisableDTCSetting предотвращает сохранение затронутых событий [SWS_Dem_00079] [SWS_Dem_00626].

Зависящие от конфигурации функциональные блоки: OBD, J1939, компоненты

OBD:

  • API-интерфейсы OBD доступны только в том случае, если DemOBDSupport не равно DEM_OBD_NO_OBD_SUPPORT SWS DEM с. 315.
  • Master ECU рассчитывает PID $31/$4D/$4E для всего автомобиля [SWS_Dem_00703] и единственная передает их диагностическому сканеру [SWS_Dem_00704].
  • Primary ECU получают значения через SW-C, которая вызывает Dem_SetDataOfPID… [SWS_Dem_00735] [SWS_Dem_00736] SWS DEM с. 170.
  • Статус условий знаменателя IUMPR передается между ECU [SWS_Dem_00714] [SWS_Dem_00716].
  • Результаты тестов (DTR) приложение передает через Dem_SetDTR [SWS_Dem_00756].

Диаграмма взаимодействия: значения PID вычисляются централизованно в Master ECU и распределяются по Primary ECU. Источники: [SWS_Dem_00703], [SWS_Dem_00704], [SWS_Dem_00735], SWS DEM с. 170, [SWS_Dem_00736]

J1939: для J1939Dcm предусмотрены собственные функции фильтрации со сводным статусом ламп [SWS_Dem_00855] [SWS_Dem_00857] и удаления [SWS_Dem_00878].

Компоненты (DemComponent):

  • Каждый компонент имеет статус FAILED и может иметь направленные зависимости от других компонентов [SWS_Dem_01118] [SWS_Dem_01119] [SWS_Dem_01120].
  • При отказе компонента зависимые компоненты также считаются отказавшими [SWS_Dem_01124].
  • FiM запрашивает этот статус через Dem_GetComponentFailed [SWS_Dem_01131].
  • Недоступные компоненты обрабатываются так, как если бы их не существовало в системе [SWS_Dem_01134]. После запуска все компоненты доступны [SWS_Dem_01239].

Доступность и подавление:

  • С помощью Dem_SetEventAvailable события можно скрывать во время выполнения [SWS_Dem_01080] [SWS_Dem_01108]. В VARIANT-POST-BUILD эта функция недоступна [SWS_Dem_01106].
  • Подавленный DTC невидим для тестера [SWS_Dem_01100], но внутри продолжает обрабатываться [SWS_Dem_01102].

Поведение при ошибке

Ошибки разработки (DET) определены в [SWS_Dem_00173], среди прочего DEM_E_PARAM_POINTER, DEM_E_UNINIT и DEM_E_WRONG_CONDITION SWS DEM с. 238.

  • Вызовы до полной инициализации сообщают DEM_E_UNINIT [SWS_Dem_00124]. Для Dem_SetEventStatus и Dem_ResetEventDebounceStatus действует отдельное правило [SWS_Dem_00364].
  • Вызовы после останова (shutdown) также распознаются [SWS_Dem_00368].
  • При отсутствии предварительных условий сообщается DEM_E_WRONG_CONDITION [SWS_Dem_00518].

Возвращаемые значения во время выполнения:

  • Недопустимые выборки приводят к DEM_WRONG_DTC или DEM_WRONG_DTCORIGIN [SWS_Dem_01261] [SWS_Dem_01262].
  • Если выборка или фильтр отсутствуют, DEM возвращает E_NOT_OK [SWS_Dem_01299] [SWS_Dem_01300].
  • При DEM_PENDING вызывающая сторона должна повторить запрос позже SWS DEM с. 289.

Отклонения на стороне событий:

  • Dem_ResetEventStatus отклоняет запрос, если событие уже было протестировано в текущем цикле [SWS_Dem_00638].
  • Dem_PrestoreFreezeFrame отклоняет запрос, если нет свободной памяти [SWS_Dem_00808].
  • При отключенном DTC-Setting бит WIR остается без изменений [SWS_Dem_00836].
  • Модули BSW могут игнорировать возвращаемое значение Dem_SetEventStatus SWS DEM с. 273.

Ошибки персистентности:

  • DEM проверяет валидность и целостность данных NvM [SWS_Dem_00339].
  • При ошибках чтения он повторно инициализирует затронутые данные [SWS_Dem_00578]. Обработку ошибок записи регулирует [SWS_Dem_00579].
  • Несогласованные предварительно сохраненные данные пропускаются [SWS_Dem_01323].

Diagnostic Event Manager (DEM)

DEM отвечает за обработку и сохранение диагностических событий, памяти неисправностей, статусов DTC и связанных данных стоп-кадра (freeze frame).

Возможности — Обзор

  • void Dem_GetVersionInfo (Std_VersionInfoType* versioninfo); Returns the version information of this module.
  • void Dem_PreInit (void); Initializes the internal states necessary to process events reported by BSW-modules.
  • void Dem_Init (const Dem_ConfigType* ConfigPtr); Initializes or reinitializes this module.
  • void Dem_Shutdown (void); Shuts down this module.
  • Std_ReturnType Dem_ClearDTC (uint8 ClientId); Clears single DTCs, as well as groups of DTCs.
  • Std_ReturnType Dem_ClearPrestoredFreezeFrame (Dem_EventIdType EventId); Clears a prestored freeze frame of a specific event.
  • Std_ReturnType Dem_GetComponentFailed (Dem_ComponentIdType ComponentId, boolean* ComponentFailed); Gets the failed status of a DemComponent.
  • Std_ReturnType Dem_GetDTCSelectionResult (uint8 ClientId); Provides information if the last call to Dem_SelectDTC has selected a valid DTC or group of DTCs.
  • Std_ReturnType Dem_GetDTCSelectionResultForClearDTC (uint8 ClientId); Provides information if the last call to Dem_SelectDTC has selected a valid DTC or group of DTCs, respecting the settings if...
  • Std_ReturnType Dem_GetEventUdsStatus (Dem_EventIdType EventId, Dem_UdsStatusByteType* UDSStatusByte); Gets the current UDS status byte assigned to the DTC for the event
  • Std_ReturnType Dem_GetMonitorStatus (Dem_EventIdType EventID, Dem_MonitorStatusType* MonitorStatus); Gets the current monitor status for an event.
  • Std_ReturnType Dem_GetDebouncingOfEvent (Dem_EventIdType EventId, Dem_DebouncingStateType* DebouncingState); Gets the debouncing status of an event.

Использование и последовательность действий

Функция Dem_ClearDTC асинхронно удаляет отдельные DTC, а также сконфигурированные группы DTC [SWS_Dem_00665]. Вызывающая сторона идентифицируется через параметр ClientId [SWS_Dem_00665]. Перед вызовом удаляемый DTC или группа, включая DTCOrigin и DTCFormat, должны быть выбраны через Dem_SelectDTC [SWS_Dem_01253]. Пока выполняется процесс удаления, API возвращает DEM_PENDING, что требует повторного вызова позже; только после успешного завершения возвращается E_OK [SWS_Dem_00665].

Обработка ошибок и возвращаемые значения

При возникновении ошибки доступны специфические возвращаемые значения [SWS_Dem_00665]:

  • E_NOT_OK: предварительно не был выбран ни один DTC [SWS_Dem_00665].
  • DEM_WRONG_DTC: DTC не существует в выбранном формате [SWS_Dem_00665], выбранный DTC подавлен [SWS_Dem_01100] или удаление ограничено параметром DemClearDTCLimitation только для DEM_ONLY_CLEAR_ALL_DTCS, в то время как была выбрана другая группа [SWS_Dem_00670].
  • DEM_WRONG_DTCORIGIN: указанное место хранения не существует [SWS_Dem_00665].
  • DEM_CLEAR_FAILED или DEM_CLEAR_MEMORY_ERROR: удаление завершилось неудачно либо возникла ошибка при удалении блоков NVRAM [SWS_Dem_00665].
  • DEM_CLEAR_BUSY: другой клиент уже выполняет операцию удаления [SWS_Dem_00665].
  • DEM_BUSY: для того же клиента уже выполняется другая операция, зависящая от Dem_SelectDTC [SWS_Dem_00665].

Параллелизм и взаимодействие

Dem_ClearDTC является реентерабельной для различных значений ClientId, однако нереентерабельна для одного и того же ClientId [SWS_Dem_00665]. Параллельные вызовы нескольких клиентов DEM обрабатывает внутренне [SWS_Dem_00661]; если процесс удаления уже выполняется, запрашивающий клиент получает DEM_PENDING [SWS_Dem_00664].

При удалении комбинированного DTC модуль DEM очищает все связанные события [SWS_Dem_00440]. При этом модуль инициирует для затронутых событий обратный вызов InitMonitorForEvent с причиной DEM_INIT_MONITOR_CLEAR [SWS_Dem_00680]. Если DemTriggerMonitorInitBeforeClearOk сконфигурирован как TRUE, E_OK возвращается только после того, как эта инициализация была запущена [SWS_Dem_00573]. Кроме того, индикатор переполнения памяти сбрасывается, как только все содержащиеся в ней DTC будут удалены [SWS_Dem_00399].

Данное указание по использованию было создано автоматически на основе спецификации AUTOSAR R20-11.

  • DEM_DEBOUNCE_STATUS_FREEZE (0x00): Замораживает внутренний счетчик устранения дребезга или таймер устранения дребезга [SWS_Dem_00927].
  • DEM_DEBOUNCE_STATUS_RESET (0x01): Сбрасывает внутренний счетчик устранения дребезга или таймер устранения дребезга [SWS_Dem_00927].
  • Значения в диапазоне от 0x02 до 0xFF зарезервированы [SWS_Dem_00927].

Контекст вызова и взаимодействие

Значения этого типа передаются в качестве входного параметра DebounceResetStatus в синхронную функцию Dem_ResetEventDebounceStatus() [SWS_Dem_00683]. Она позволяет модулям BSW и программным компонентам (SW-C) целенаправленно манипулировать поведением дебаунсинга для заданного EventId. На квалификацию события эти изменения статуса дебаунсинга не влияют [SWS_Dem_00683].

Параллелизм и обработка ошибок

Функция Dem_ResetEventDebounceStatus() является реентерабельной для различных значений EventId, однако не должна вызываться параллельно для одного и того же EventId [SWS_Dem_00683]. Для модулей BSW вызов доступен, как только завершена фаза инициализации Dem_PreInit [SWS_Dem_00683]. При успешном выполнении сервис возвращает E_OK; E_NOT_OK возвращается исключительно в случае ошибки разработки [SWS_Dem_00683].

Использование и диапазон значений

Тип передается в качестве входного параметра InitMonitorReason, чтобы монитор мог идентифицировать подлежащий выполнению вид инициализации ([SWS_Dem_00942], [SWS_Dem_00256]). Он включает следующие значения:

  • DEM_INIT_MONITOR_STORAGE_REENABLED (0x04): Условие сохранения (Storage Condition) было повторно активировано.

Причина передается либо через C-обратный вызов <Module>_DemInitMonitorFor<EventName> из Dem_Externals.h ([SWS_Dem_00256]), либо через операцию InitMonitorForEvent интерфейса сервисного порта CallbackInitMonitorForEvent ([SWS_Dem_00613]). Callback возвращает значение типа Std_ReturnType. В сигнатуре C-callback это возвращаемое значение не анализируется модулем DEM и служит исключительно для совместимости с соответствующей операцией RTE ([SWS_Dem_00256]). Через сервисный интерфейс RTE в качестве возвращаемых значений определены E_OK (операция успешна) и E_NOT_OK (сбой операции) ([SWS_Dem_00613]).

Dem_SetDTCFilter функция

Устанавливает фильтр DTC. Сервер должен выполнить побитовую логическую операцию AND между параметром DTCStatusMask и текущим статусом UDS на сервере. В дополнение к DTCStatus AvailabilityMask сервер должен возвращать все DTC, для которых результат операции AND не равен нулю [т.е. (statusOfDTC & DTCStatusMask) != 0]. Сервер должен обрабатывать только DTC биты состояния, которые он поддерживает. OBD Подавление событий должно игнорироваться при этом вычислении. Если ни один код DTC на сервере не соответствует критериям маскирования, указанным в запросе клиента, после байта DTCStatusAvailabilityMask в сообщении положительного ответа не должно быть предоставлено DTC или информации о состоянии (((statusOfDTC & DTCStatusMask) != 0) && ((серьезность & DTCSeverityMask) != 0)) == TRUE

Идентификация DemComponent по назначенному ComponentId. ComponentId автоматически назначается Dem.

Dem_ConfigType тип

Этот тип внешней структуры данных должен содержать данные инициализации после сборки для Dem.

Dem_DataType тип

Dem_DebounceResetStatusType тип

Этот тип содержит все определения для управления внутренним счетчиком/таймером устранения дребезга с помощью функции Dem_ResetEventDebounceStatus().

Dem_DTCFormatType тип

Этот тип используется для выбора формата значения DTC.

Dem_DTCKindType тип

Этот тип используется для фильтрации кодов DTC по их виду.

Dem_DTCOriginType тип

Это перечисление используется для определения местоположения событий. Определение и использование различных типов памяти зависит от OEM.

Dem_DTCRequestType тип

Этот тип используется для запроса DTC с определенными атрибутами.

Dem_DTCTranslationFormatType тип

DTC формат перевода, определенный в ISO14229-1.

Dem_DTRControlType тип

Контрольный параметр для интерпретации сообщаемых результатов испытаний.

Dem_EventIdType тип

Идентификация события по назначенному EventId. EventId назначается Dem. Пример: 1 относится к монитору x, 2 относится к монитору y и т. д.

Dem_EventStatusType тип

Этот тип содержит все значения результатов тестирования монитора, о которых можно сообщить с помощью Dem_SetEventStatus().

Dem_IndicatorStatusType тип

Режим индикатора, используемый Dem_GetIndicatorStatus().

Dem_InitMonitorReasonType тип

(Re-)Initialization reason returned by the callback _DemInitMonitorFor().

Dem_IumprDenomCondIdType тип

Этот тип содержит все возможные дополнительные условия знаменателя IUMPR, которые будут транслироваться среди ECU, соответствующих OBD.

Dem_IumprDenomCondStatusType тип

Этот тип содержит все возможные состояния дополнительного условия знаменателя IUMPR, которое будет транслироваться среди OBD соответствующих ECU.

Dem_J1939DcmDiagnosticReadiness1Type тип

Эта структура представляет все элементы данных сообщения DM05. Кодирование должно выполняться в соответствии с SAE J1939-73.

Dem_J1939DcmDiagnosticReadiness2Type тип

Эта структура представляет все элементы данных сообщения DM21. Кодирование должно выполняться в соответствии с SAE J1939-73.

Dem_J1939DcmDiagnosticReadiness3Type тип

Эта структура представляет все элементы данных сообщения DM26. Кодирование должно выполняться в соответствии с SAE J1939-73.

Dem_J1939DcmDTCStatusFilterType тип

Тип, по которому можно определить, какие коды DTC следует фильтровать.

Dem_J1939DcmLampStatusType тип
