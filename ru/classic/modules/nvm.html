Роль NvM в стеке памяти

NVRAM Manager (NvM) — это центральная служба для энергонезависимых данных в Classic Platform. Он предоставляет исключительно неявный доступ: он копирует блоки между энергонезависимой памятью (NV) и RAM, а приложение работает с данными в RAM [SWS_NvM_00038] [SWS_NvM_00692]. Окружение должно обращаться к энергонезависимой памяти только через NvM [SWS_NvM_00384]. Вниз по стеку NvM опирается на Memory Abstraction Interface (MemIf). Совместно с Flash EEPROM Emulation (Fee) или EEPROM Abstraction (Ea) он предоставляет виртуальное линейное 32-битное адресное пространство [SWS_NvM_00051]. Верхние уровни подключают только NvM.h [SWS_NvM_00691].

Результаты нижнего уровня NvM получает в зависимости от конфигурации двумя путями. Либо Fee/Ea вызывают функции обратного вызова NvM_JobEndNotification и NvM_JobErrorNotification, либо NvM опрашивает статус задания в режиме опроса (polling) [SWS_NvM_00438] [SWS_NvM_00440] [SWS_NvM_00346]. Оба способа обнаружения описаны также в ErrorDescription с. 43. Другие соседние модули:

  • Производственные ошибки передаются в DEM [SWS_NvM_00592].
  • Ошибки разработки передаются в DET [SWS_NvM_00614].
  • CRC вычисляет модуль Crc [SWS_NvM_00466].
  • NvM информирует BswM о состояниях многоблочных и одноблочных операций [SWS_NvM_00745] [SWS_NvM_00746].
  • При необходимости NvM шифрует блоки через CSM [SWS_NvM_00976].

Контекстная диаграмма: NvM является посредником между пользователями и BswM с одной стороны и MemIf/Fee/Ea с другой стороны; DEM, DET, Crc и CSM являются вспомогательными службами. Источники: [SWS_NvM_00051], [SWS_NvM_00438], [SWS_NvM_00745], [SWS_NvM_00976], EXP_NVDataHandling с. 8

Блоки NVRAM: структура и типы управления

Каждый блок NVRAM состоит из трех обязательных компонентов: блок NV, блок RAM и административный блок. Блок ROM является опциональным [SWS_NvM_00138] [SWS_NvM_00139]. Состав определяется дескриптором блока во время конфигурации [SWS_NvM_00140]. Компоненты подробно:

  • Блок NV содержит полезные данные, а также опционально CRC и заголовок [SWS_NvM_00125].
  • Блок ROM предоставляет данные по умолчанию для пустых или поврежденных блоков NV [SWS_NvM_00020].
  • Административный блок находится в RAM и невидим для приложения. Он содержит индекс набора данных, атрибуты и информацию об ошибках/статусе [SWS_NvM_00134] [SWS_NvM_00135].

Блок адресуется по своему Block-ID [SWS_NvM_00069]. NvM_BlockIdType является uint16; биты выбора Dataset уменьшают его диапазон значений [SWS_NvM_00471]. Два ID зарезервированы: 0 для многоблочного результата и 1 для Konfigurations-ID [SWS_NvM_00244].

Для блоков DATASET элемент выбирается с помощью NvM_SetDataIndex. Индексы начиная с NvMNvBlockNum указывают на блоки ROM [SWS_NvM_00014] [SWS_NvM_00445]. Индекс не сохраняется персистентно, и NvM_Init сбрасывает его в ноль. За правильный выбор отвечает пользователь [SWS_NvM_00160] [SWS_NvM_00192] [SWS_NvM_00695] (NVDataHandling с. 10).

Запуск: NvM_Init и NvM_ReadAll

NvM_Init вызывается исключительно из BswM [SWS_NvM_00693]. Указатель конфигурации всегда равен NULL_PTR [SWS_NvM_00881]. Функция сбрасывает внутренние переменные и сигнализирует «INIT DONE»; только после этого NvM обрабатывает запросы [SWS_NvM_00399] [SWS_NvM_00257]. Из соображений времени она не инициализирует ни блоки NVRAM, ни другие модули и не изменяет постоянные блоки RAM [SWS_NvM_00091] [SWS_NvM_00193] [SWS_NvM_00400].

Затем данные загружает многоблочный запрос NvM_ReadAll [SWS_NvM_00158]. Вызов лишь подает сигнал о запросе и немедленно возвращает управление [SWS_NvM_00243]. Он доступен только в NvM-Master [SWS_NvM_00970]. Задание выполняется в следующие шаги:

  1. Сначала он сравнивает сохраненный Konfigurations-ID со скомпилированным [SWS_NvM_00073] [SWS_NvM_00246].
  2. Если NvMDynamicConfiguration имеет значение FALSE, оно игнорирует расхождение [SWS_NvM_00248]. В противном случае следует расширенная подготовка во время выполнения [SWS_NvM_00249] (NVDataHandling с. 15).
  3. После этого выполняется итерация по пользовательским блокам [SWS_NvM_00244]. Обрабатываются только блоки с постоянным блоком RAM или явной синхронизацией [SWS_NvM_00118].

Если сконфигурированный CRC в RAM совпадает, содержимое RAM считается действительным [SWS_NvM_00364]. Для каждого блока может вызываться функция обратного вызова одиночного блока [SWS_NvM_00281]. Общим результатом является NVM_REQ_OK или NVM_REQ_NOT_OK, как только происходит сбой какого-либо блока [SWS_NvM_00895] [SWS_NvM_00301].

NvM сообщает BswM о принятии и завершении запроса [SWS_NvM_00888] [SWS_NvM_00889]. Затем BswM продолжает запуск, например с помощью Rte_Start() (NVDataHandling с. 20; ModeManagementGuide с. 38).

Диаграмма последовательности: NvM_Init лишь подготавливает NvM; данные блоков загружает только асинхронный NvM_ReadAll, завершение которого разрешает дальнейший запуск. Источники: [SWS_NvM_00091], [SWS_NvM_00243], [SWS_NvM_00516], [SWS_NvM_00889], NVDataHandling с. 20, AUTOSAR_SWS_NVRAMManager с. 163

Одноблочные запросы: очередь, приоритет и обратная связь

Службы одиночных блоков, такие как NvM_ReadBlock или NvM_WriteBlock, работают асинхронно. Они принимают параметры, ставят запрос в очередь и возвращают управление [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00766]. После успешной постановки в очередь результат принимает значение NVM_REQ_PENDING [SWS_NvM_00185]. При переполнении очереди вызов возвращает E_NOT_OK [SWS_NvM_00184]. Блок ставится в очередь только в том случае, если он еще не ожидает и не обрабатывается [SWS_NvM_00385].

Основная работа выполняется в NvM_MainFunction [SWS_NvM_00256]. Там NvM извлекает запрос с наивысшим приоритетом и обрабатывает запросы последовательно [SWS_NvM_00155]. Для порядка выполнения действуют следующие правила:

  • При NvMJobPrioritization NvM использует две очереди; одна из них предназначена для немедленных запросов на запись (данные при аварии) [SWS_NvM_00564] [SWS_NvM_00378].
  • Немедленные запросы деструктивно прерывают выполняемые задания; после этого они перезапускаются [SWS_NvM_00182] [SWS_NvM_00300] [SWS_NvM_00258].
  • Без приоритизации действует порядок поступления [SWS_NvM_00379].
  • NvM_WriteAll не прерывается. Запросы на чтение и запись, поступающие во время выполнения многоблочного запроса, ставятся в очередь и выполняются после него [SWS_NvM_00567] [SWS_NvM_00568] [SWS_NvM_00569].

Используемый буфер RAM зависит от переданного указателя. При NULL_PTR NvM использует постоянный блок RAM или явную синхронизацию [SWS_NvM_00898] [SWS_NvM_00899] [SWS_NvM_00900] [SWS_NvM_00901]. Другой адрес служит временным блоком RAM, даже если сконфигурирован постоянный [SWS_NvM_00278] [SWS_NvM_00280]. Для постоянных блоков RAM предусмотрены отдельные службы PRAM [SWS_NvM_00764] [SWS_NvM_00793] (NVDataHandling с. 32).

Результат находится в поле ошибки/статуса административного блока [SWS_NvM_00175] и может быть запрошен через NvM_GetErrorStatus [SWS_NvM_00451]. Если сконфигурирована функция обратного вызова одиночного блока, каждый запрос завершается ее вызовом из NvM_MainFunction [SWS_NvM_00740] [SWS_NvM_00347] [SWS_NvM_00467]. Дополнительно BswM может информироваться поблочно [SWS_NvM_00890] [SWS_NvM_00891]. NvM_CancelJobs удаляет ожидающие запросы блока; уже выполняющееся задание продолжается [SWS_NvM_00536] [SWS_NvM_00537].

Диаграмма последовательности: вызов немедленно возвращает управление; обработка и обратная связь через функцию обратного вызова или опрос статуса происходят в последующих вызовах NvM_MainFunction. Источники: [SWS_NvM_00185], [SWS_NvM_00184], [SWS_NvM_00346], [SWS_NvM_00347], [SWS_NvM_00451], NVDataHandling с. 43

Состояние блока RAM и синхронизация с приложением

NvM ведет для постоянного блока RAM или зеркала состояние «действителен» или «недействителен» [SWS_NvM_00132] [SWS_NvM_00128]. Действительные блоки он дополнительно разделяет на измененные и неизмененные [SWS_NvM_00682] [SWS_NvM_00472]. Переходы подробно:

  • Запросы на чтение и восстановление делают блок недействительным при постановке в очередь или при запуске задания [SWS_NvM_00198] [SWS_NvM_00227].
  • Успешное чтение дает результат «действителен/неизменен» [SWS_NvM_00200].
  • Загруженные значения по умолчанию дают «действителен/изменен» [SWS_NvM_00366] [SWS_NvM_00228]. Без значений по умолчанию блок остается недействительным [SWS_NvM_00658].
  • NvM_SetRamBlockStatus с TRUE и NvM_ValidateAll помечают блок как измененный [SWS_NvM_00406] [SWS_NvM_00856] (EXP_NVDataHandling с. 18).
  • После успешной записи блок считается неизмененным [SWS_NvM_00472].

Диаграмма состояний: запросы на чтение и восстановление делают блок RAM временно недействительным; только операция записи переводит состояние из «изменен» обратно в «неизменен». Начальное состояние является интерпретацией. Источники: [SWS_NvM_00198], [SWS_NvM_00200], [SWS_NvM_00366], [SWS_NvM_00406], [SWS_NvM_00472], [SWS_NvM_00658]

При неявной синхронизации NvM и приложение обращаются к одному и тому же блоку RAM. Поэтому после запроса на чтение или запись приложение может снова использовать его только после получения ответа [SWS_NvM_00698] [SWS_NvM_00699] (EXP_NVDataHandling с. 27). Если несколько приложений совместно используют один блок, они сами отвечают за его согласованность [SWS_NvM_00697].

В качестве альтернативы NvMBlockUseSyncMechanism настраивает явную синхронизацию [SWS_NvM_00511]. В этом случае NvM создает ровно одно зеркало в RAM и использует его в качестве буфера [SWS_NvM_00513] [SWS_NvM_00514]. Между приложением и зеркалом копирование выполняют функции обратного вызова NvMWriteRamBlockToNvCallback и NvMReadRamBlockFromNvCallback [SWS_NvM_00515] [SWS_NvM_00516]. Их сигнатуры — NvM_WriteRamBlockToNvm и NvM_ReadRamBlockFromNvm [SWS_NvM_00539] [SWS_NvM_00540]. Для этого сценария использования они являются обязательными элементами (BSWModuleDescriptionTemplate с. 242).

Вплоть до Callback приложение может продолжать изменять свой блок [SWS_NvM_00705] (NVDataHandling с. 26). Если Callback сообщает E_NOT_OK, NvM вызывает его снова на следующем цикле NvM_MainFunction, не более NvMRepeatMirrorOperations раз [SWS_NvM_00840] [SWS_NvM_00579]. Блок с явной синхронизацией не должен иметь постоянного RAM-блока [SWS_NvM_00904]. С помощью NvBlockSwComponent RTE реализует эти Callbacks (NVDataHandling с. 34).

Диаграмма последовательности: при явной синхронизации NvM принимает данные только в функции обратного вызова зеркала, то есть с задержкой относительно запроса; завершившаяся сбоем функция обратного вызова повторяется. Источники: [SWS_NvM_00515], [SWS_NvM_00579], [SWS_NvM_00705], [SWS_NvM_00840], [SWS_NvM_00901], EXP_NVDataHandling с. 13

Завершение работы, механизмы защиты и конфигурация

Завершение работы инициируется BswM с помощью NvM_WriteAll [SWS_NvM_00092]. Вызов немедленно возвращает управление и доступен только в NvM-Master [SWS_NvM_00254] [SWS_NvM_00971]. Задание записывает постоянные блоки RAM или вызывает функцию обратного вызова зеркала [SWS_NvM_00018] [SWS_NvM_00252]. Перед этим оно проверяет состояние «действителен/изменен» [SWS_NvM_00682]. Защищенные от записи и заблокированные блоки пропускаются без сообщения об ошибке [SWS_NvM_00434] [SWS_NvM_00750].

Чтобы записывались только измененные блоки, пользователь сообщает об изменениях через NvM_SetRamBlockStatus, если этот API сконфигурирован [SWS_NvM_00408] [SWS_NvM_00453]. В случае storeAtShutdown это берет на себя RTE (NVDataHandling с. 41). NvM_CancelWriteAll зарезервирован для BswM [SWS_NvM_00703]. Обрабатываемый в данный момент блок завершается согласованно; остальные блоки получают NVM_REQ_CANCELED [SWS_NvM_00238] [SWS_NvM_00236] [SWS_NvM_00237] (ModeManagementGuide с. 37).

Диаграмма последовательности: изменения, о которых сообщено во время выполнения, записываются только при NvM_WriteAll; BswM может прервать процесс и ожидает сообщения о результате. Источники: [SWS_NvM_00092], [SWS_NvM_00238], [SWS_NvM_00682], [SWS_NvM_00889], NVDataHandling с. 41

Обзор других механизмов защиты и конфигурации:

  • Schreibschutz: защита от записи является атрибутом блока. При NvMBlockWriteProt она активна по умолчанию, и окружение может снять ее с помощью NvM_SetBlockProtection [SWS_NvM_00054] [SWS_NvM_00326] [SWS_NvM_00578].
  • Einmal-Schreiben: блоки с NvMWriteBlockOnce записываются только один раз. Их защиту невозможно снять, а запросы на запись до первого чтения отклоняются [SWS_NvM_00397] [SWS_NvM_00398] [SWS_NvM_00952].
  • Sperre: блокировку через NvM_SetBlockLockStatus невозможно изменить другими службами [SWS_NvM_00548] [SWS_NvM_00754].
  • Integrität: Static Block ID в заголовке сохраняется при записи и проверяется при чтении [SWS_NvM_00522] [SWS_NvM_00523] [SWS_NvM_00524]. Сравнение CRC позволяет избежать записи неизмененных данных [SWS_NvM_00849] [SWS_NvM_00850].
  • Umfang: существует три класса конфигурации API; класс 1 не поддерживает DATASET [SWS_NvM_00149] [SWS_NvM_00365].
  • Erstinitialisierung: NvM_FirstInitAll записывает значения по умолчанию или инвалидирует блоки, игнорируя при этом защиту от записи [SWS_NvM_91001] [SWS_NvM_00913] [SWS_NvM_00919] [SWS_NvM_00931].

Поведение при ошибке

Entwicklungsfehler. При включенном обнаружении ошибок NvM сообщает DET, среди прочего:

  • NVM_E_UNINIT [SWS_NvM_00614]
  • NVM_E_PARAM_BLOCK_ID [SWS_NvM_00618]
  • NVM_E_PARAM_ADDRESS [SWS_NvM_00616]
  • NVM_E_BLOCK_PENDING [SWS_NvM_00615]
  • NVM_E_BLOCK_LOCKED [SWS_NvM_00748]
  • NVM_E_WRITE_PROTECTED [SWS_NvM_00962]

Для переполненной очереди дополнительно определен NVM_E_QUEUE_FULL [SWS_NvM_00947].

Lesefehler. NvM управляет восстановлением самостоятельно (ErrorDescription с. 62). При этом он действует пошагово:

  1. При ошибках CRC или Static Block ID он при необходимости выполняет повторное чтение [SWS_NvM_00526] [SWS_NvM_00582].
  2. Для блоков REDUNDANT он считывает второй блок NV [SWS_NvM_00199]. Если один экземпляр действителен, результат равен NVM_REQ_OK без сообщения в DEM [SWS_NvM_00279] [SWS_NvM_00655]. Затем NvM пытается восстановить избыточность; если это не удается, он сообщает NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00531] [SWS_NvM_00546].
  3. В противном случае он загружает значения по умолчанию (NVM_REQ_RESTORED_DEFAULTS), не изменяя блок NV [SWS_NvM_00202] [SWS_NvM_00172].
  4. Если значения по умолчанию отсутствуют, блок RAM остается недействительным [SWS_NvM_00658]. В этом случае результат зависит от типа ошибки:
    • Ошибка CRC: NVM_REQ_INTEGRITY_FAILED и сообщение DEM NVM_E_INTEGRITY_FAILED [SWS_NvM_00204] [SWS_NvM_00203]
    • Ошибка задания: NVM_REQ_NOT_OK и сообщение DEM NVM_E_REQ_FAILED [SWS_NvM_00359] [SWS_NvM_00654]

Инвалидированный блок приводит к NVM_REQ_NV_INVALIDATED без записи DEM [SWS_NvM_00341] [SWS_NvM_00652].

Использование и семантика

Синхронная и реэenterable функция NvM_SetBlockProtection ([SWS_NvM_00450]) служит для активации или деактивации защиты от записи для блока NVRAM. При этом атрибут защиты от записи устанавливается или сбрасывается в административном блоке менеджера NVRAM ([SWS_NvM_00016]). Служба относится к классу конфигурации API 3 ([SWS_NvM_00560]). Окружение NvM может явно снять защиту от записи с помощью этого вызова ([SWS_NvM_00578]). Параметр BlockId обозначает блок NVRAM, тогда как ProtectionEnabled указывает, должна ли защита быть активирована (TRUE) или деактивирована (FALSE). При успешном выполнении функция возвращает E_OK, в случае ошибки — E_NOT_OK ([SWS_NvM_00450]).

Параллелизм и ограничения

Если для указанного блока операция с отдельным блоком уже находится в очереди или на стадии выполнения, приложению запрещено вызывать NvM_SetBlockProtection, так как административные модификации допустимы только после завершения текущего задания ([SWS_NvM_00704]). Состояние блокировки (BlockLocked), установленное с помощью NvM_SetBlockLockStatus, не может быть изменено посредством NvM_SetBlockProtection ([SWS_NvM_00754]).

Взаимодействие с блоками типа Write-Once

Изменение защиты от записи через NvM_SetBlockProtection допустимо только в том случае, если блок был сконфигурирован с NvMWriteBlockOnce == FALSE, независимо от конфигурации NvMBlockWriteProt ([SWS_NvM_00325]). Если для блока сконфигурировано NvMWriteBlockOnce == TRUE, изменение или деактивация защиты от записи с помощью этой функции недопустимы ([SWS_NvM_00398], [SWS_NvM_00577]). В частности, это также распространяется на действительные блоки, которые были автоматически помечены как защищенные от записи предварительными операциями чтения, такими как NvM_ReadAll ([SWS_NvM_00314]), NvM_ReadBlock ([SWS_NvM_00316]) или NvM_ReadPRAMBlock ([SWS_NvM_00784]).

  • NVM_E_PARAM_BLOCK_ID: переданный BlockId находится вне допустимого диапазона ([SWS_NvM_00609]).
  • NVM_E_BLOCK_PENDING: для ID блока задание уже поставлено в очередь или находится в обработке ([SWS_NvM_00607]).
  • NVM_E_BLOCK_CONFIG: блок сконфигурирован с NvMWriteBlockOnce == TRUE ([SWS_NvM_00608]).
  • NVM_E_BLOCK_LOCKED: блок находится в заблокированном состоянии ([SWS_NvM_00759]).

Использование и семантика

Синхронная и реентерабельная функция NvM_SetRamBlockStatus ([SWS_NvM_00453]) служит для установки статуса RAM-блока постоянного RAM-блока или статуса явной синхронизации NVRAM-блока. Она доступна в классах конфигурации API 2 ([SWS_NvM_00561]) и 3 ([SWS_NvM_00560]), если активирована через NvMSetRamBlockStatusApi ([SWS_NvM_00408]). Если параметр BlockChanged установлен в TRUE, RAM-блок или RAM-зеркало считается валидным и измененным ([SWS_NvM_00241], [SWS_NvM_00406]). При передаче FALSE блок помечается как невалидный и неизмененный ([SWS_NvM_00453]). При успешном изменении статуса функция возвращает E_OK, а в случае ошибки — E_NOT_OK ([SWS_NvM_00453]).

Ограничения и обработка ошибок

Модуль NvM должен быть инициализирован перед вызовом ([SWS_NvM_00711]). Приложению не разрешается вызывать NvM_SetRamBlockStatus для блока до тех пор, пока для него активна или ожидает обработки операция с отдельным блоком ([SWS_NvM_00704]). Статус блокировки (BlockLocked), ранее установленный с помощью NvM_SetBlockLockStatus, не может быть изменен этой функцией ([SWS_NvM_00754]). Если обнаружение ошибок разработки (DET) активно, сообщается о следующих ошибках:

  • NVM_E_UNINIT, если модуль не инициализирован ([SWS_NvM_00643]),
  • NVM_E_BLOCK_PENDING, если Block-ID уже находится в очереди или обрабатывается ([SWS_NvM_00644]),
  • NVM_E_PARAM_BLOCK_ID, если BlockId находится вне допустимого диапазона ([SWS_NvM_00645]).

Взаимодействие и фоновая обработка

Если в BlockChanged == TRUE сконфигурирована CRC для RAM-блока (NvMCalcRamBlockCrc == TRUE), функция запрашивает для постоянных RAM-блоков пересчет CRC в фоновом режиме, который обрабатывается с помощью NvM_MainFunction ([SWS_NvM_00121]). Для блоков без постоянного RAM, но с явной синхронизацией, задание вызывает callback-функцию записи, чтобы определить данные для расчета CRC ([SWS_NvM_00906]). Если callback-функция завершается с ошибкой E_NOT_OK, NvM выполняет сконфигурированные повторные попытки на каждый вызов NvM_MainFunction ([SWS_NvM_00907], [SWS_NvM_00908]). Если все попытки остаются безуспешными, NvM считает задание завершенным, сохраняет отметку BlockChanged и продолжает работу так же, как после успешного завершения ([SWS_NvM_00909]).

Семантика и взаимодействие

  • Блокировка (BlockLocked = TRUE): NvM гарантирует, что NV-содержимое блока не будет изменено никаким запросом. Блок пропускается при NvM_WriteAll; такие запросы, как NvM_WriteBlock, NvM_WritePRAMBlock, NvM_InvalidateNvBlock и NvM_EraseNvBlock, отклоняются [SWS_NvM_00751].   • Разблокировка (BlockLocked = FALSE): модуль снова обеспечивает штатную обработку NVRAM-блока в соответствии со спецификацией AUTOSAR [SWS_NvM_00753].
  • Защита от перезаписи: выполненная блокировка не может быть перезаписана или изменена ни с помощью NvM_SetRamBlockStatus, ни с помощью NvM_SetBlockProtection [SWS_NvM_00754].

Контекст вызова и ограничения

Служба предназначена в первую очередь для использования со стороны DCM, однако может вызываться и сложными драйверами устройств (CDD). Она не содержится в интерфейсе ServicePort [SWS_NvM_00732].

Функция NvM_ReadRamBlockFromNvm представляет собой специфическую для блока callback-подпрограмму ([SWS_NvM_00540]), вызываемую менеджером NVRAM, чтобы приложение скопировало данные из внутреннего буфера зеркал модуля NvM в RAM-блок. Она предоставляется через заголовочный файл NvM_Externals.h.

  • Синхронность и реентерабельность: вызов выполняется синхронно и специфицирован как нереентерабельный (Non Reentrant) ([SWS_NvM_00540]).

  • NVM_WRITE_ALL (0x01): указывает на то, что была выполнена операция NvM_WriteAll [SWS_NvM_91003].
  • NVM_VALIDATE_ALL (0x02): указывает на то, что была выполнена операция NvM_ValidateAll [SWS_NvM_91003].
  • NVM_FIRST_INIT_ALL (0x03): указывает на то, что была выполнена операция NvM_FirstInitAll [SWS_NvM_91003].

Тип NvM_RequestResultType ([SWS_NvM_00470]) базируется на uint8 и определяет значения результата и статуса для асинхронных заданий менеджера NVRAM. Он предоставляется через заголовочный файл Rte_NvM_Type.h ([SWS_NvM_00470]). Результат асинхронного запроса опрашивается через службу API NvM_GetErrorStatus или может дополнительно сигнализироваться через функцию обратного вызова ([SWS_NvM_00470]).

Диапазон значений включает следующие состояния ([SWS_NvM_00470]):

  • NVM_REQ_OK (0x00): последний асинхронный запрос успешно завершён. Это значение по умолчанию после сброса ([SWS_NvM_00470]).
  • NVM_REQ_NOT_OK (0x01): последний асинхронный запрос на чтение, запись или управление завершился неуспешно ([SWS_NvM_00470]).
  • NVM_REQ_PENDING (0x02): асинхронный запрос в настоящее время ожидает выполнения и обрабатывается ([SWS_NvM_00470]).
  • NVM_REQ_INTEGRITY_FAILED (0x03): ошибка целостности данных при NvM_ReadBlock или NvM_ReadAll. При NvM_ReadBlock содержимое блока RAM хотя и изменилось, но является недействительным; приложение должно обновить и проверить это содержимое ([SWS_NvM_00470]).
  • NVM_REQ_BLOCK_SKIPPED (0x04): указанный блок был пропущен во время выполнения NvM_ReadAll или NvM_WriteAll, например, блоки Dataset-NVRAM при NvM_ReadAll или блоки NVRAM без постоянно сконфигурированного блока RAM ([SWS_NvM_00470]).
  • NVM_REQ_NV_INVALIDATED (0x05): указанный блок NV инвалидирован ([SWS_NvM_00470]).
  • NVM_REQ_CANCELED (0x06): мультиблочный запрос NvM_WriteAll был отменён с помощью NvM_CancelWriteAll или задание для одного блока (NvM_ReadBlock, NvM_WriteBlock, NvM_EraseNvBlock, NvM_InvalidateNvBlock или NvM_RestoreBlockDefaults) было отменено с помощью NvM_CancelJobs ([SWS_NvM_00470]).
  • NVM_REQ_RESTORED_DEFAULTS (0x08): в образ в RAM для указанного NV-блока были скопированы стандартные значения ([SWS_NvM_00470]).

Во взаимодействии с избыточными блоками (тип NVM_BLOCK_REDUNDANT) функция NvM_InvalidateNvBlock устанавливает результат запроса NvM_RequestResultType в NVM_REQ_OK только тогда, когда оба блока NV были инвалидированы ([SWS_NvM_00274]).
