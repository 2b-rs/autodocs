Управляет энергонезависимыми блоками данных и асинхронно синхронизирует их между RAM и энергонезависимой памятью.

NVRAM Manager (NvM) представляет собой единственный доступ к энергонезависимой памяти. Он неявно копирует NVRAM-блоки между RAM и энергонезависимой памятью [SWS_NvM_00038]. При запуске инициированная BswM функция NvM_ReadAll заполняет RAM-блоки, при выключении (Shutdown) NvM_WriteAll сохраняет изменённые блоки. Одиночные запросы, такие как NvM_WriteBlock, ставятся в очередь асинхронно, обрабатываются с учётом приоритетов и подтверждаются через статус или callback-вызов [SWS_NvM_00185]. Ошибки чтения NvM парирует с помощью повторных попыток, избыточных копий и данных по умолчанию; тем не менее пользователи должны самостоятельно проверять статус блока.

NVRAM Manager (NvM) является единственным доступом к энергонезависимой памяти [SWS_NvM_00384]. Он неявно копирует блоки между NVRAM и RAM; приложение работает напрямую с данными в RAM [SWS_NvM_00038]. На нижнем уровне он использует Memory Abstraction Interface с Fee или Ea [SWS_NvM_00051]. О состояниях он сообщает в BswM, об ошибках — в DEM и DET [SWS_NvM_00745] [SWS_NvM_00592].

Диаграмма контекста: встраивание NvM между пользователями, BswM, MemIf/Fee/Ea, а также DEM и DET. Источники: [SWS_NvM_00384] [SWS_NvM_00465] [SWS_NvM_00746]

Каждый NVRAM-блок состоит из NV-блока, RAM-блока и Administrative Block, опционально дополняясь ROM-блоком с данными по умолчанию [SWS_NvM_00138]. Существуют типы Native, Redundant и Dataset; они различаются количеством NV- и ROM-блоков [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559]. Синхронизацию RAM-блока NvM выполняет неявно напрямую или явно через RAM-mirror с callback-вызовами [SWS_NvM_00511].

Жизненный цикл проходит в три шага:

  • BswM монопольно вызывает NvM_Init [SWS_NvM_00693].
  • NvM_ReadAll сначала проверяет ID конфигурации и затем заполняет RAM-блоки [SWS_NvM_00073] [SWS_NvM_00718].
  • При Shutdown NvM_WriteAll сохраняет изменённые блоки [SWS_NvM_00092]. NvM_CancelWriteAll выполняет недеструктивное прерывание [SWS_NvM_00238].

Одиночные запросы, такие как NvM_WriteBlock, ставятся в очередь и после этого находятся в состоянии NVM_REQ_PENDING [SWS_NvM_00185]. Опционально NvM использует собственную очередь для запросов типа Immediate [SWS_NvM_00378]. Результат возвращает NvM_GetErrorStatus или сконфигурированный callback-вызов [SWS_NvM_00015] [SWS_NvM_00740].

Диаграмма последовательности: асинхронный запрос на запись ставится в очередь, обрабатывается в NvM_MainFunction и подтверждается через callback-вызов, сообщение в BswM и опрос статуса. Источники: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00891], SWS NvM с. 160

Ошибки чтения NvM парирует на трёх уровнях:

  • сконфигурированные повторные попытки чтения [SWS_NvM_00526],
  • вторая копия избыточных блоков [SWS_NvM_00199],
  • данные по умолчанию с результатом NVM_REQ_RESTORED_DEFAULTS [SWS_NvM_00202].

Интерпретация: порядок уровней, вероятно, соответствует перечислению в Error Description. Ошибки записи NvM повторяет до NVM_MAX_NUM_OF_WRITE_RETRIES и затем сообщает NVM_E_REQ_FAILED в DEM [SWS_NvM_00684]. Пользователи проверяют статус своих блоков самостоятельно [SWS_NvM_00694].

Роль в стеке памяти: единственный доступ к энергонезависимой памяти

NVRAM Manager (NvM) объединяет доступ к энергонезависимым данным. Окружение обращается к энергонезависимой памяти исключительно через NvM, который предоставляет для этого callback-интерфейс [SWS_NvM_00384]. Доступ является неявным: NvM копирует блоки между NVRAM и совместно используемой RAM. Приложение работает напрямую с данными в RAM с соблюдением правил синхронизации [SWS_NvM_00038] [SWS_NvM_00692]. Блок выбирается по его сконфигурированному Block ID [SWS_NvM_00069] [SWS_NvM_00471]. Верхние уровни подключают для этого только NvM.h [SWS_NvM_00691]. Схема неявного обновления демонстрирует разделение обязанностей: другие компоненты базового программного обеспечения инициируют сохранение и восстановление всех блоков в зависимости от состояния ECU. SW-C обращается только к содержимому своих RAM-блоков (SWS NvM с. 121).

На нижнем уровне NvM взаимодействует с Memory Abstraction Interface. Совместно с Fee или Ea он предоставляет виртуальное линейное 32-битное адресное пространство [SWS_NvM_00051] [SWS_NvM_00465]. Контрольные суммы NvM вычисляет через модуль Crc [SWS_NvM_00466]. О завершении задания нижнего уровня он узнаёт двумя путями:

  • путем опроса (polling) через MemIf_GetJobResult,
  • при отключённом опросе — через NvM_JobEndNotification и NvM_JobErrorNotification [SWS_NvM_00440] [SWS_NvM_00441] (Error Description с. 43).

Производственные ошибки отправляются в DEM [SWS_NvM_00592], ошибки разработки — в DET [SWS_NvM_00614]. О состояниях запросов NvM сообщает в BswM [SWS_NvM_00745] [SWS_NvM_00746].

Диаграмма контекста: NvM выступает посредником между пользователями и BswM с одной стороны и MemIf/Fee/Ea — с другой. Об ошибках он сообщает в DEM и DET. Источники: [SWS_NvM_00384] [SWS_NvM_00745] [SWS_NvM_00746] [SWS_NvM_00465] [SWS_NvM_00466], Error Description с. 43

Структура NVRAM-блока и три типа управления

NVRAM-блок состоит из обязательных компонентов: NV-блока, RAM-блока и Administrative Block. ROM-блок с данными по умолчанию является опциональным [SWS_NvM_00138] [SWS_NvM_00139] [SWS_NvM_00020]. Состав определяется дескриптором блока во время конфигурации [SWS_NvM_00140]. Отдельные компоненты:

  • NV-блок содержит полезные данные, а также, опционально, CRC и заголовок [SWS_NvM_00125] (SWS NvM с. 39).
  • RAM-блок может располагаться в глобальной RAM без ограничений по адресам [SWS_NvM_00088].
  • Administrative Block невидим для приложения. Он хранит индекс набора данных, атрибуты и поле ошибок/статуса [SWS_NvM_00134] [SWS_NvM_00135] [SWS_NvM_00136].

NvM поддерживает типы NVM_BLOCK_NATIVE, NVM_BLOCK_REDUNDANT и NVM_BLOCK_DATASET [SWS_NvM_00137]. Они различаются количеством NV- и ROM-блоков [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] (SWS NvM с. 10). Для Dataset-блоков действует следующее:

  • NvM_SetDataIndex выбирает элемент. Индексы начиная с NvMNvBlockNum адресуют ROM-блоки [SWS_NvM_00014] [SWS_NvM_00445] (NV Data Handling с. 10).
  • Индекс не сохраняется персистентно; NvM_Init сбрасывает его в ноль [SWS_NvM_00160] [SWS_NvM_00192].
  • За корректную установку отвечает SW-C [SWS_NvM_00695].

Диаграмма кооперации (структура блоков): обязательные и опциональные компоненты NVRAM-блока с кардинальностями для каждого типа управления. Источники: [SWS_NvM_00138] [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] [SWS_NvM_00134], SWS NvM с. 10

Жизненный цикл: NvM_Init, NvM_ReadAll и NvM_WriteAll

BswM монопольно вызывает NvM_Init [SWS_NvM_00693]. NvM_Init сбрасывает очереди и конечные автоматы и внутренне сигнализирует «INIT DONE» [SWS_NvM_00399]. Он не инициализирует ни RAM-блоки, ни нижележащие модули [SWS_NvM_00091] [SWS_NvM_00193]. Указатель конфигурации всегда равен NULL_PTR [SWS_NvM_00881]. Только после этого NvM_MainFunction обрабатывает запросы [SWS_NvM_00257].

Затем RAM-блоки заполняет NvM_ReadAll [SWS_NvM_00718]. Вызов лишь сигнализирует о запросе. Обработка откладывается до тех пор, пока не завершатся одиночные запросы к блокам [SWS_NvM_00243]. После этого задание выполняется в три шага:

  1. Сначала выполняется сравнение сохранённого ID конфигурации со скомпилированным [SWS_NvM_00073]. При несовпадении поведение зависит от NvMDynamicConfiguration: при NvMDynamicConfiguration == FALSE расхождение игнорируется [SWS_NvM_00248]. В противном случае блоки, не устойчивые к изменениям, получают данные по умолчанию [SWS_NvM_00249] [SWS_NvM_00674] (NV Data Handling с. 15).
  2. Затем выполняется итерация по пользовательским блокам, за исключением Block ID 0 и 1 [SWS_NvM_00244]. При этом обрабатываются только блоки с постоянным RAM-блоком или явной синхронизацией [SWS_NvM_00118].
  3. В завершение общий результат устанавливается в NVM_REQ_OK или NVM_REQ_NOT_OK [SWS_NvM_00895] [SWS_NvM_00301].

В примере с управлением режимами правило BswM NvMReadAllFinished запускает оставшуюся инициализацию только после завершения NvM_ReadAll (Mode Management Guide с. 31).

Диаграмма последовательности: асинхронный запуск с NvM_Init, NvM_ReadAll и обратная передача состояния мультиблочной операции в BswM. Источники: [SWS_NvM_00693] [SWS_NvM_00243] [SWS_NvM_00073] [SWS_NvM_00888] [SWS_NvM_00889], NV Data Handling с. 20

Для Shutdown BswM вызывает NvM_WriteAll [SWS_NvM_00092]. Задание ведёт себя следующим образом:

  • Оно записывает постоянные RAM-блоки или получает явно синхронизированные данные через NvM_WriteRamBlockToNvm [SWS_NvM_00252].
  • Предварительно оно проверяет состояние «valid/modified» [SWS_NvM_00682].
  • Защищённые и заблокированные блоки пропускаются без сообщения об ошибке [SWS_NvM_00434] [SWS_NvM_00750].
  • Другие запросы его не прерывают [SWS_NvM_00567].

Пользователи помечают изменённые блоки с помощью NvM_SetRamBlockStatus(…, TRUE), если этот API активирован [SWS_NvM_00406] [SWS_NvM_00408]. Для блоков с флагом изменений (Dirty-Flag) этот вызов берёт на себя RTE (NV Data Handling с. 41).

NvM_CancelWriteAll зарезервирован за BswM [SWS_NvM_00703] и остаётся безрезультатным при отсутствии выполняющегося NvM_WriteAll [SWS_NvM_00233]. Текущий блок завершается недеструктивно [SWS_NvM_00238]. Оставшиеся блоки и результат мультиблочной операции получают NVM_REQ_CANCELED [SWS_NvM_00236] [SWS_NvM_00237] (SWS NvM с. 161).

Жизненный цикл дополняют два других мультиблочных запроса:

  • NvM_ValidateAll переводит блоки с автоматической валидацией в состояние «VALID / CHANGED» [SWS_NvM_00856].
  • NvM_FirstInitAll перезаписывает блоки данными по умолчанию или инвалидирует их, если они отсутствуют [SWS_NvM_00913] [SWS_NvM_00919].

Для всех мультиблочных запросов длина очереди равна единице [SWS_NvM_00380].

Диаграмма последовательности: Shutdown с NvM_WriteAll и опциональным прерыванием через NvM_CancelWriteAll. Источники: [SWS_NvM_00092] [SWS_NvM_00682] [SWS_NvM_00238] [SWS_NvM_00237] [SWS_NvM_00889], Mode Management Guide с. 37

Одиночные запросы: очереди, приоритеты и обратная связь

Одиночные запросы к блокам, такие как NvM_ReadBlock, NvM_WriteBlock или NvM_RestoreBlockDefaults, являются асинхронными. Функция принимает параметры, ставит запрос в очередь и возвращает управление [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00224]. После этого результат блока находится в NVM_REQ_PENDING [SWS_NvM_00185]. При переполнении очереди функция возвращает E_NOT_OK [SWS_NvM_00184]. Блок ставится в очередь только в том случае, если он ещё не ожидает и не обрабатывается [SWS_NvM_00385].

Другие службы действуют синхронно в контексте вызывающей стороны, например NvM_SetDataIndex [SWS_NvM_00448] и NvM_GetErrorStatus (SWS NvM с. 158). NvM_CancelJobs удаляет ожидающие запросы блока; однако выполняющееся задание продолжается [SWS_NvM_00536] [SWS_NvM_00537].

Обработка выполняется последовательно в соответствии с приоритетом [SWS_NvM_00162]. Если активен NvMJobPrioritization, NvM использует две очереди, одна из которых предназначена для запросов на немедленную запись Immediate (Crash-данные) [SWS_NvM_00564] [SWS_NvM_00378]. Такой NvM_WriteBlock деструктивно прерывает ожидающее задание [SWS_NvM_00300]. NvM_MainFunction затем перезапускает прерванное задание [SWS_NvM_00258]. Без приоритезации NvM работает в порядке поступления, без Immediate-заданий [SWS_NvM_00379]. Запросы, поступающие во время выполнения мультиблочного запроса, ставятся в очередь и выполняются после него [SWS_NvM_00568] [SWS_NvM_00569].

Каждый асинхронный запрос сохраняет свой результат в поле ошибок/статуса [SWS_NvM_00175]. NvM_GetErrorStatus считывает это поле [SWS_NvM_00015]. Кроме того, существуют два опциональных способа обратной связи:

  • Если сконфигурирован callback-вызов, NvM_MainFunction вызывает NvM_SingleBlockCallbackFunction [SWS_NvM_00740] [SWS_NvM_00347]. Без callback-вызова асинхронное уведомление отсутствует [SWS_NvM_00742] (SWS NvM с. 160).
  • С помощью NvMBswMBlockStatusInformation NvM сообщает о приёме и результате в BswM [SWS_NvM_00890] [SWS_NvM_00891] (SWS NvM с. 162).

Диаграмма последовательности: асинхронный запрос на запись со статусными сообщениями в BswM, callback-вызовом и опросом статуса. Источники: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00740] [SWS_NvM_00890] [SWS_NvM_00891], SWS NvM с. 160

Синхронизация RAM-блоков и состояние блоков

NvM предусматривает два способа синхронизации данных с RAM-блоком приложения. При неявной синхронизации он работает непосредственно на этом RAM-блоке. Приложение предоставляет блок и не обращается к нему до завершения запроса [SWS_NvM_00698] [SWS_NvM_00699]. Если оно передаёт NULL_PTR, NvM использует постоянный RAM-блок [SWS_NvM_00898] [SWS_NvM_00900]. Тем не менее временный блок по указателю возможен [SWS_NvM_00278]. Службы PRAM всегда работают на постоянном RAM-блоке [SWS_NvM_00765] [SWS_NvM_00794]. В сценарии RTE этот блок представляет собой Per-Instance-Memory (NV Data Handling с. 32).

При явной синхронизации (NvMBlockUseSyncMechanism) обмен происходит через внутренний RAM-mirror [SWS_NvM_00511]. Он существует ровно в одном экземпляре, размер которого рассчитан по наибольшему задействованному блоку [SWS_NvM_00513]. NvM вызывает NvMWriteRamBlockToNvCallback или NvMReadRamBlockFromNvCallback [SWS_NvM_00515] [SWS_NvM_00516]. Если callback возвращает E_NOT_OK, он повторяет вызов в следующем цикле, до NvMRepeatMirrorOperations раз [SWS_NvM_00579] [SWS_NvM_00840]. Вплоть до callback-вызова приложению разрешено изменять RAM-блок [SWS_NvM_00705]. Блок использует либо явную синхронизацию, либо постоянный RAM-блок, но не то и другое одновременно [SWS_NvM_00904]. Этот механизм допускает разделяемые блоки через NvBlockSwComponentType (NV Data Handling с. 12).

Диаграмма последовательности: запрос на запись с явной синхронизацией через RAM-mirror, включая повторную попытку при E_NOT_OK. Источники: [SWS_NvM_00515] [SWS_NvM_00705] [SWS_NvM_00579] [SWS_NvM_00840], NV Data Handling с. 27

Для постоянных RAM-блоков и mirror NvM ведёт состояние «valid»/«invalid» [SWS_NvM_00128] [SWS_NvM_00132]. Переходы подробно:

  • NvM_ReadBlock инвалидирует постоянный RAM-блок уже при постановке в очередь [SWS_NvM_00198].
  • После успешного чтения он переходит в «valid/unchanged» [SWS_NvM_00200].
  • После загрузки данных по умолчанию он переходит в «valid/changed» [SWS_NvM_00366].
  • NvM_SetRamBlockStatus(…, TRUE) помечает его как изменённый и инициирует фоновый пересчёт CRC [SWS_NvM_00406] [SWS_NvM_00121].
  • После успешной записи он считается «valid/unmodified» [SWS_NvM_00472].

Диаграмма состояний: состояния RAM-блока и инициирующие события. Источники: [SWS_NvM_00198] [SWS_NvM_00200] [SWS_NvM_00366] [SWS_NvM_00406] [SWS_NvM_00472] [SWS_NvM_00856]

Конфигурация, механизмы защиты и привязка к разделам (Partition)

Для ограниченных ресурсов предусмотрены три класса конфигурации API [SWS_NvM_00149]. Класс 1 не поддерживает Dataset-блоки [SWS_NvM_00365]. Таблицы дескрипторов генерируются [SWS_NvM_00143]. Потребность в памяти пользователи декларируют во время конфигурации [SWS_NvM_00030]. Модули BSW делают это через NvBlockNeeds (BSWMD Template с. 241). Интегратор ECU формирует на этой основе конфигурацию NvM (Methodology с. 444).

Для отдельных блоков доступно несколько механизмов защиты:

  • Поле атрибутов управляет защитой от записи [SWS_NvM_00054]; NvMBlockWriteProt активирует её по умолчанию [SWS_NvM_00326].
  • Блоки с NvMWriteBlockOnce записываются только один раз [SWS_NvM_00397]. Запросы на запись до первого чтения NvM отклоняет [SWS_NvM_00952].
  • Для заблокированных блоков (NvM_SetBlockLockStatus) NvM_WriteBlock возвращает E_NOT_OK [SWS_NvM_00749]. Блокировку не изменяют ни NvM_SetRamBlockStatus, ни NvM_SetBlockProtection [SWS_NvM_00754].
  • Опционально доступны также заголовок Static-Block-ID [SWS_NvM_00522], сравнение CRC для предотвращения лишней записи [SWS_NvM_00849] и шифрование через CSM [SWS_NvM_00976].

При разделении на разделы (Partitioning) NvM вызывает интерфейсы в контексте соответствующего назначенного раздела. Общие функции выполняются в master-разделе [SWS_NvM_00969]. NvM_ReadAll и NvM_WriteAll предоставляются только master-разделом [SWS_NvM_00970] [SWS_NvM_00971] [SWS_NvM_CONSTR00974]. SW-C обращаются к NvM через порты, ориентированные на блоки:

  • PS_{Block} (Service) [SWS_NvM_00847]
  • PAdmin_{Block} (Administration) [SWS_NvM_00843]
  • PM_{Block} (Mirror) [SWS_NvM_00844]
  • PNJF_{Block} (уведомление о завершении задания) [SWS_NvM_00846]

Поведение при ошибке

При чтении NvM по-разному интерпретирует сообщения от MemIf:

  • Расхождение CRC он сообщает как NVM_E_INTEGRITY_FAILED [SWS_NvM_00203].
  • О MEMIF_JOB_FAILED он сообщает как о NVM_E_REQ_FAILED [SWS_NvM_00654].
  • MEMIF_BLOCK_INVALID приводит только к NVM_REQ_NV_INVALIDATED, без сообщения в DEM [SWS_NvM_00341] [SWS_NvM_00652].

Затем вступают в действие несколько этапов восстановления:

  1. При ошибках CRC следуют сконфигурированные повторные попытки чтения [SWS_NvM_00526].
  2. Для избыточных блоков NvM считывает вторую копию и пытается восстановить избыточность [SWS_NvM_00199] [SWS_NvM_00531]. Если это не удаётся, он сообщает NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00546].
  3. Наконец, NvM загружает данные по умолчанию с результатом NVM_REQ_RESTORED_DEFAULTS [SWS_NvM_00202]. Содержимое NV при этом остаётся без изменений [SWS_NvM_00172].

Если данные по умолчанию отсутствуют, RAM-блок остаётся недействительным [SWS_NvM_00658] [SWS_NvM_00204]. Интерпретация: порядок этапов, вероятно, соответствует перечислению в Error Description (Error Description с. 62). Этот источник расходится с требованиями в двух пунктах. Он указывает NVM_REQ_RESTORED_FROM_ROM вместо NVM_REQ_RESTORED_DEFAULTS. Кроме того, он обобщённо сводит окончательный сбой к NVM_E_REQ_FAILED. Нормативными являются приведённые выше требования.

Диаграмма деятельности: обработка ошибок чтения от повторной попытки и избыточной копии до данных по умолчанию. Интерпретация: порядок соответствует перечислению в Error Description. Источники: [SWS_NvM_00526] [SWS_NvM_00199] [SWS_NvM_00202] [SWS_NvM_00341] [SWS_NvM_00658], Error Description с. 62

При записи NvM считает отрицательные подтверждения до NVM_MAX_NUM_OF_WRITE_RETRIES [SWS_NvM_00213] [SWS_NvM_00216]. При превышении предела он устанавливает NVM_REQ_NOT_OK и сообщает NVM_E_REQ_FAILED [SWS_NvM_00683] [SWS_NvM_00684] (Error Description с. 43). Два других сценария ошибок:

  • Если верификация записи завершается неудачей, NvM сообщает NVM_E_VERIFY_FAILED и повторяет запись [SWS_NvM_00528] [SWS_NvM_00529].
  • Избыточный блок считается записанным, как только одна копия успешно записана [SWS_NvM_00284].

Об ошибках некорректного использования NvM сообщает в DET при активированном обнаружении ошибок разработки. Примерами являются NVM_E_UNINIT и NVM_E_BLOCK_PENDING [SWS_NvM_00614] [SWS_NvM_00615], а также NVM_E_WRITE_PROTECTED [SWS_NvM_00962]. Мультиблочный запрос завершается с NVM_REQ_NOT_OK, как только происходит сбой в отдельном блоке [SWS_NvM_00318]. Пользователи проверяют статус своих блоков самостоятельно [SWS_NvM_00694]. После неудачного чтения они предоставляют валидные данные перед следующей записью [SWS_NvM_00696].

Использование и контекст вызова

Функция NvM_Init служит для синхронного сброса всех внутренних переменных NVRAM Manager [SWS_NvM_00447]. В качестве входного параметра ConfigPtr она ожидает указатель на выбранный набор конфигурационных данных и не имеет возвращаемого значения [SWS_NvM_00447]. Будучи API типа 4, она входит в состав классов конфигурации 2 и 3 [SWS_NvM_00560], [SWS_NvM_00561]. Функция не является реентерабельной и может вызываться исключительно через BSW Mode Manager [SWS_NvM_00447], [SWS_NvM_00693].

Задачи инициализации

Во время вызова функция выполняет следующие действия:

  • сброс всех внутренних переменных, включая конечные автоматы, очереди заданий и флаги запросов, в их начальные значения [SWS_NvM_00399];
  • установка индекса набора данных всех блоков NVRAM типа NVM_BLOCK_DATASET в ноль [SWS_NvM_00192];
  • внутренняя установка сигнала «INIT DONE», который является предпосылкой для обработки заданий, управления очередями и пересчёта CRC в модуле [SWS_NvM_00257], [SWS_NvM_00399].

Ограничения и взаимодействие

Из-за строгих требований ко времени запуска электронного блока управления (ECU) NvM_Init не инициализирует сконфигурированные блоки NVRAM [SWS_NvM_00091]. Постоянное содержимое блоков RAM не изменяется, а функции обратного вызова синхронизации не вызываются; это закреплено за функцией NvM_ReadAll [SWS_NvM_00400]. Кроме того, NvM_Init не инициализирует ни нижележащие драйверы, ни аппаратную абстракцию памяти, ни сторонние модули, так как их инициализация предполагается выполненной через BSW Mode Manager [SWS_NvM_00157], [SWS_NvM_00193].

Это указание по использованию было сгенерировано автоматически на основе спецификации AUTOSAR R20-11.

Пока запрос для отдельного блока активен или находится в очереди для того же блока, вызов не допускается [SWS_NvM_00704].

  • NVM_E_BLOCK_LOCKED, если блок заблокирован [SWS_NvM_00759].

Синхронная и реентерабельная функция NvM_SetRamBlockStatus служит для установки статуса блока RAM для постоянных блоков RAM или для блоков с явной синхронизацией [SWS_NvM_00453]. Она доступна в классах конфигурации API 2 и 3 [SWS_NvM_00561], [SWS_NvM_00560], если она была активирована через конфигурационный параметр NvMSetRamBlockStatusApi [SWS_NvM_00408].

Через параметр BlockChanged управляется, помечается ли блок как действительный и изменённый (TRUE) или как недействительный и неизменённый (FALSE) [SWS_NvM_00453], [SWS_NvM_00406]. При передаче TRUE модуль исходит из действительности данных [SWS_NvM_00241]. Функция возвращает E_OK при успешном изменении статуса и E_NOT_OK в случае ошибки [SWS_NvM_00453].

Если BlockChanged устанавливается в TRUE, функция запрашивает в фоновом режиме перерасчет контрольной суммы в NvM_MainFunction, если сконфигурирован NvMCalcRamBlockCrc [SWS_NvM_00121]. Для блоков без постоянного RAM с явной синхронизацией это задание использует функцию обратного вызова записи для получения данных [SWS_NvM_00906]. Если она завершается сбоем, выполняются сконфигурированные повторные попытки на каждый вызов NvM_MainFunction [SWS_NvM_00907], [SWS_NvM_00908]. Если все попытки остаются безуспешными, задание тем не менее считается завершенным, а блок остается помеченным как измененный [SWS_NvM_00909].

Перед вызовом модуль NvM должен быть инициализирован [SWS_NvM_00711]. При активном обнаружении ошибок разработки функция сообщает NVM_E_UNINIT при неинициализированном модуле [SWS_NvM_00643], NVM_E_PARAM_BLOCK_ID при недействительном BlockId [SWS_NvM_00645] и NVM_E_BLOCK_PENDING при уже выполняющихся или находящихся в очереди заданиях [SWS_NvM_00644].
