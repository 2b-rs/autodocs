Роль в MCAL и системная граница драйвера ADC

Драйвер ADC инкапсулирует аналого-цифровые преобразователи микроконтроллера. Adc_Init инициализирует аппаратные блоки ADC и сам драйвер ([SWS_Adc_00365]). ECU State Manager содержит эту службу в качестве опционального интерфейса (SWS EcuM с. 142). Типичным пользователем является I/O Hardware Abstraction. Она запускает преобразования групп и по завершении группы получает обратный вызов IoHwAb_AdcNotification<#groupID> ([SWS_Adc_00082], SWS IoHwAb с. 58).

В направлении вниз драйвер является последним уровнем программного обеспечения. Поэтому он не предоставляет обратных вызовов для нижележащих модулей (SWS ADC с. 79). API не допускает прямого доступа к аппаратным регистрам результатов. Результаты попадают исключительно в буферы приложения (SWS ADC с. 27). Об ошибках драйвер сообщает в Default Error Tracer ([SWS_Adc_00377]).

Для разделов действуют два правила. Модуль должен отклонять назначения разделов, которые не поддерживаются его реализацией ([SWS_Adc_00531]). Кроме того, разделы ядра должны являться подмножеством разделов модуля ([SWS_Adc_CONSTR_00001]).

Контекстная диаграмма: драйвер ADC является связующим звеном между инициализацией (EcuM), пользователем (IoHwAb), отчетами об ошибках (DET) и периферией, состоящей из блока преобразователя и источника триггера. Источники: [SWS_Adc_00365], [SWS_Adc_00082], [SWS_Adc_00377], [SWS_Adc_00479], SWS IoHwAb с. 58

От сброса до первого преобразования: инициализация, буфер результатов, деинициализация

Adc_Init синхронен и не является реентерабельным. В варианте PB служба ожидает указатель на конфигурационный набор, а в варианте PC — NULL_PTR ([SWS_Adc_00365]). Содержимое Adc_ConfigType зависит от реализации ([SWS_Adc_00505]). В примере фазы запуска под управлением BswM вызывается Adc_Init(null) (Modemanagement-Guide с. 54). Повторный вызов Init считается ошибкой разработки ADC_E_ALREADY_INITIALIZED ([SWS_Adc_91005]).

Перед первым преобразованием каждая группа должна получить свой буфер результатов. Это выполняется с помощью Adc_SetupResultBuffer ([SWS_Adc_91000]). Приложение гарантирует, что буфер способен вместить все результаты группы. Окружение не должно запускать преобразование без допустимого указателя на буфер (SWS ADC с. 54). Adc_StartGroupConversion и Adc_EnableHardwareTrigger сбрасывают внутренний указатель записи на базовый адрес этого буфера (SWS ADC с. 57, SWS ADC с. 62).

Adc_DeInit переводит все блоки ADC в состояние, сравнимое со сбросом при включении питания (Power-on-Reset) ([SWS_Adc_00366]). При этом все используемые прерывания и уведомления отключаются. Окружение может вызывать эту службу только тогда, когда все группы находятся в состоянии ADC_IDLE. Доступна ли эта служба вообще, определяет переключатель AdcDeInitApi (SWS ADC с. 59).

Диаграмма состояний: жизненный цикл модуля переключается между ADC_UNINIT и ADC_INIT. Внутри ADC_INIT каждая группа в зависимости от конфигурации следует автомату One-Shot или Continuous. Источники: [SWS_Adc_00365], [SWS_Adc_00366], SWS ADC с. 31, SWS ADC с. 37

Группы каналов как единица управления: триггер, режим преобразования и тип доступа

Управление всегда осуществляется группой каналов, которая идентифицируется через Adc_GroupType ([SWS_Adc_00507]). Назначение каналов ([SWS_Adc_00506]) группам описывает Adc_GroupDefType ([SWS_Adc_00517]). Символические имена для каналов и групп генерирует конфигуратор (SWS ADC с. 123). Группа может содержать один или несколько каналов (SWS ADC с. 35).

Поведение группы определяют три оси конфигурации:

  • Источник триггера: программный (ADC_TRIGG_SRC_SW) или аппаратный (ADC_TRIGG_SRC_HW) ([SWS_Adc_00514]). Для аппаратных триггеров дополнительно настраиваются выбор фронта ([SWS_Adc_00520]) и встроенный таймер ([SWS_Adc_00521]).
  • Режим преобразования: One-Shot преобразует каждый канал ровно один раз на триггер. Continuous выполняет преобразование многократно и доступен только с программным триггером ([SWS_Adc_00515]).
  • Тип доступа: Single или Streaming ([SWS_Adc_00528]). Количество раундов выборки определяет Adc_StreamNumSampleType; в режиме Single оно равно 1 ([SWS_Adc_00518]). Буфер потоковой передачи работает линейно или циклически ([SWS_Adc_00519]).

Диаграммы спецификации выводят из этих осей соответствующий конечный автомат группы. One-Shot с программным триггером поддерживает там только доступ Single (SWS ADC с. 38, SWS ADC с. 39). Результаты представляют собой необработанные значения без масштабирования ([SWS_Adc_00508]). Их выравнивание в буфере настраивается по левому или правому краю ([SWS_Adc_00525]).

Диаграмма деятельности: из режима преобразования, источника триггера и типа доступа следует, какой конечный автомат группы применяется. Источники: [SWS_Adc_00514], [SWS_Adc_00515], [SWS_Adc_00528], SWS ADC с. 38, SWS ADC с. 39

Запуск преобразований, отслеживание статуса, получение результатов

Adc_StartGroupConversion запускает преобразование всех каналов группы и работает асинхронно ([SWS_Adc_00367]). В зависимости от конфигурации после этого выполняется преобразование One-Shot или Continuous. При этом уведомление явным образом не включается автоматически (SWS ADC с. 57). Adc_StopGroupConversion работает синхронно ([SWS_Adc_00368]). Служба останавливает текущее преобразование и удаляет поставленную в очередь задачу на запуск (SWS ADC с. 58).

Без уведомления пользователь опрашивает статус группы с помощью Adc_GetGroupStatus ([SWS_Adc_00374]). Возможными значениями являются ADC_IDLE, ADC_BUSY, ADC_COMPLETED и ADC_STREAM_COMPLETED ([SWS_Adc_00513]). Затем он считывает результаты с помощью Adc_ReadGroup. Служба возвращает E_OK, если результаты доступны ([SWS_Adc_00369]). Она копирует последний полный раунд в порядке возрастания каналов в буфер чтения пользователя. Этот порядок отличается от размещения в буфере результатов потоковой передачи (SWS ADC с. 61). Согласно диаграмме состояний, группа One-Shot с программным триггером после чтения возвращается в ADC_IDLE (SWS ADC с. 35).

Диаграмма последовательности: при преобразовании One-Shot с программным триггером без уведомления пользователь опрашивает статус до готовности группы и затем выполняет чтение. Источники: [SWS_Adc_00367], [SWS_Adc_00374], [SWS_Adc_00369], SWS ADC с. 91, SWS ADC с. 92

Уведомление пользователь включает и выключает с помощью Adc_EnableGroupNotification и Adc_DisableGroupNotification ([SWS_Adc_91003], [SWS_Adc_91004]). Обе службы могут быть отключены во время компиляции с помощью AdcGrpNotifCapability (SWS ADC с. 67).

Группы с аппаратным триггером активируются с помощью Adc_EnableHardwareTrigger ([SWS_Adc_91001]). После этого они выполняют преобразование при каждом событии триггера. Adc_DisableHardwareTrigger завершает этот режим работы ([SWS_Adc_91002]). Служба удаляет задачи из очереди, прерывает текущее преобразование, если это поддерживается аппаратным обеспечением, и отключает уведомление. После этого группа переходит в состояние ADC_IDLE (SWS ADC с. 65).

Диаграмма последовательности: при аппаратном триггере с уведомлением каждый раунд преобразования инициирует обратный вызов, после которого пользователь выполняет чтение. Без уведомления преобразования продолжаются без оповещений. Источники: [SWS_Adc_91001], [SWS_Adc_91002], [SWS_Adc_91003], [SWS_Adc_91004], SWS ADC с. 94, SWS ADC с. 93

В режиме Streaming драйвер записывает несколько раундов в буфер результатов приложения, причем блоками по каждому каналу. Отдельный буфер чтения необходим только для Adc_ReadGroup (SWS ADC с. 32, SWS ADC с. 33). В качестве альтернативы Adc_GetStreamLastPointer возвращает количество действительных выборок на канал ([SWS_Adc_00375]). Кроме того, служба устанавливает указатель на самый свежий результат первого канала группы. При этом структуру буфера пользователь должен учитывать самостоятельно (SWS ADC с. 27). Линейный буфер останавливает преобразование, как только заполняется. Кольцевой буфер продолжает работу и перезаписывает самые старые значения ([SWS_Adc_00519]).

Диаграмма состояний: при непрерывном преобразовании (Continuous) с программным триггером и потоковым доступом (Streaming) состояние ADC_COMPLETED различает промежуточные раунды и заполненный буфер (ADC_STREAM_COMPLETED). Линейный и кольцевой буферы при чтении разветвляются по-разному. Источники: [SWS_Adc_00513], [SWS_Adc_00519], SWS ADC с. 39, SWS ADC с. 44

Конкурирующие группы: приоритет, очередь и вытеснение

То, как обрабатываются одновременные запросы групп, определяет Adc_PriorityImplementationType. Возможные варианты: отсутствие механизма, только аппаратный либо аппаратный и программный ([SWS_Adc_00522]). Приоритеты варьируются от 0 до 255; 0 — наименьший ([SWS_Adc_00516]).

Без механизма приоритетов и без очереди конфликтующие запуски и разрешения триггеров отклоняются с ошибкой времени выполнения ADC_E_BUSY ([SWS_Adc_91006], SWS ADC с. 95). При наличии программной очереди драйвер вместо этого сохраняет задачу. Он обрабатывает ее, как только текущая группа завершит работу (SWS ADC с. 96).

При активном механизме приоритетов группа с более высоким приоритетом может вытеснить текущую группу ([SWS_Adc_00523]). Что происходит с вытесненной группой, определяет Adc_GroupReplacementType:

  • Abort/Restart: прерванный раунд перезапускается полностью. В режиме Streaming теряются только значения этого раунда.
  • Suspend/Resume: прерванный раунд продолжается.

В обоих случаях результаты предыдущих раундов в буфере остаются неизменными (SWS ADC с. 50).

Диаграмма последовательности: аппаратный триггер группы 1 с более высоким приоритетом вытесняет текущее программное преобразование группы 2. После этого группа 2 перезапускается или продолжается. Источники: [SWS_Adc_00523], [SWS_Adc_00522], [SWS_Adc_91001], SWS ADC с. 98, SWS ADC с. 99

Состояния питания: двухэтапный переход под управлением IoHwAb

Управление питанием является опциональной функцией и касается только периферии ADC. Вышележащие уровни должны уже выполнить граничные условия с точки зрения системы. Драйвер лишь проверяет, поступают ли вызовы в правильном порядке (SWS ADC с. 39). ADC_FULL_POWER соответствует значению 0. Значения от 1 до 255 обозначают состояния с убывающим энергопотреблением ([SWS_Adc_00526]).

Переход происходит в два этапа.

  1. Подготовка: Adc_PreparePowerState инициирует подготовку ([SWS_Adc_00478]). Асинхронные части Adc_Main_PowerTransitionManager выполняет в фоновом режиме ([SWS_Adc_00498], [SWS_Adc_00499]). Функция вызывается циклически с тактом AdcMainSchedulePeriod, это необходимо только во время перехода ([SWS_Adc_00500]). Интерпретация: вызов, вероятно, берет на себя BSW-Scheduler, поскольку служба предоставляется через SchM_Adc.h ([SWS_Adc_00479]). В асинхронном случае драйвер сообщает о завершении через IoHwAb_Adc_NotifyReadyForPowerState<#Mode> ([SWS_Adc_00480], [SWS_Adc_00501]).
  2. Переключение: Adc_SetPowerState активирует подготовленное состояние ([SWS_Adc_00475]). Подготовительные шаги, такие как перевод каналов в IDLE или отмена регистрации уведомлений, IoHwAb должна выполнить заранее. Неявных промежуточных состояний не существует (SWS ADC с. 81).

Для нормального состояния драйвер использует параметры из Adc_Init ([SWS_Adc_00483]). Для других состояний разрешены только специфичные для перехода реконфигурации ([SWS_Adc_00484], [SWS_Adc_00485]). Текущее и целевое состояния возвращают Adc_GetCurrentPowerState и Adc_GetTargetPowerState ([SWS_Adc_00476], [SWS_Adc_00477]). Без текущего перехода оба одинаковы (SWS ADC с. 77).

Диаграмма последовательности: смена режима BswM приводит через IoHwAb к подготовке, завершению в фоновом режиме, сообщению о готовности и, наконец, к переключению ADC. Источники: [SWS_Adc_00478], [SWS_Adc_00479], [SWS_Adc_00480], [SWS_Adc_00475], SWS IoHwAb с. 60, SWS IoHwAb с. 57

Поведение при ошибке

Ошибки разработки определены в [SWS_Adc_91005] и передаются через Det_ReportError ([SWS_Adc_00377]):

  • ADC_E_UNINIT: вызов до инициализации.
  • ADC_E_PARAM_POINTER: недопустимый указатель, например указатель NULL при Adc_GetVersionInfo (SWS ADC с. 80).
  • ADC_E_PARAM_GROUP: группа не существует. В этом случае служба возвращается без выполнения действий (SWS ADC с. 67).
  • ADC_E_WRONG_CONV_MODE и ADC_E_WRONG_TRIGG_SRC: вызов не соответствует конфигурации группы.
  • ADC_E_NOTIF_CAPABILITY: указатель уведомления равен NULL.

Ошибки времени выполнения определяет [SWS_Adc_91006]:

  • ADC_E_BUSY: конфликт с текущим преобразованием, активным триггером или уже поставленным в очередь заданием.
  • ADC_E_IDLE: вызов для группы в ADC_IDLE.
  • ADC_E_NOT_DISENGAGED: группы не находятся в состоянии покоя.
  • ADC_E_TRANSITION_NOT_POSSIBLE: состояние питания недостижимо.

Схема без приоритета показывает, как ADC_E_BUSY передается через Det_ReportRuntimeError (SWS ADC с. 95).

Обращения к данным сигнализируют о проблемах через возвращаемые значения. Adc_ReadGroup возвращает E_NOT_OK, если результаты отсутствуют ([SWS_Adc_00369]). То же самое относится к Adc_SetupResultBuffer при сбое ([SWS_Adc_91000]). Вызов Adc_DeInit при не находящихся в состоянии покоя группах является некорректным использованием, о котором сообщает драйвер (SWS ADC с. 59).

Службы управления питанием дополнительно сообщают о результате через Adc_PowerStateRequestResultType ([SWS_Adc_00527]). Возможные значения: ADC_NOT_INIT, ADC_SEQUENCE_ERROR, ADC_HW_FAILURE, ADC_POWER_STATE_NOT_SUPP и ADC_TRANS_NOT_POSSIBLE. Дополнительно действуют следующие сообщения:

  • ADC_E_UNINIT при отсутствии инициализации ([SWS_Adc_00486], [SWS_Adc_00496]).
  • ADC_E_POWER_STATE_NOT_SUPPORTED при неподдерживаемом состоянии ([SWS_Adc_00488], [SWS_Adc_00497]).
  • ADC_E_NOT_DISENGAGED при активных каналах или все еще зарегистрированных уведомлениях ([SWS_Adc_00487]).
  • ADC_E_TRANSITION_NOT_POSSIBLE при недостижимой напрямую цели ([SWS_Adc_00489]).

Если модуль еще не инициализирован, Adc_Main_PowerTransitionManager возвращается без сообщения DET. Предыстория: на этапе запуска планировщик уже может вызывать эту функцию ([SWS_Adc_00502]).

ADC Driver (Adc)

Предоставляет услуги инициализации и преобразования аналого-цифровых преобразователей.

Возможности — Обзор

  • void Adc_Init (const Adc_ConfigType* ConfigPtr); Initializes the ADC hardware units and driver.
  • Std_ReturnType Adc_SetupResultBuffer (Adc_GroupType Group, Adc_ValueGroupType* DataBufferPtr); Initializes ADC driver with the group specific result buffer start address where the conversion results will be stored.

Интерпретация: различие между выравниванием по левому и правому краю, вероятно, служит главным образом для того, чтобы предоставлять результаты аппаратного преобразования с разрешением ниже разрядности целевой памяти (например, 10-битные или 12-битные значения в 16-битном поле) последующим программным модулям либо с арифметическим масштабированием, либо в виде прямого целочисленного исходного значения.

Интерпретация: определение этого типа выравнивания обычно, по всей видимости, выполняется статически при конфигурации соответствующих групп каналов ADC, поскольку фрагмент спецификации не предусматривает интерфейса времени выполнения для динамического переключения.

Перечислимый тип Adc_PowerStateType описывает состояния электропитания драйвера ADC и доступен через заголовочный файл Adc.h ([SWS_Adc_00526]). Он служит для представления текущего активного состояния питания (Power State) или целевого заданного состояния питания ([SWS_Adc_00526]).

Перечисление различает следующие диапазоны значений ([SWS_Adc_00526]):

  • ADC_FULL_POWER (значение 0): обозначает режим полной функциональности модуля (Full Power) ([SWS_Adc_00526]).
  • Диапазон значений 1..255: обозначает режимы энергосбережения с убывающим энергопотреблением (power modes with decreasing power consumptions) ([SWS_Adc_00526]).

Интерпретация: этот тип, вероятно, используется прежде всего в управляющих состояниями API драйвера ADC в качестве передаваемого параметра для целевых состояний, а также для опроса статуса активного режима. Назначение отдельных ступеней в диапазоне 1..255, вероятно, зависит от аппаратно-специфических возможностей Low-Power соответствующего микроконтроллера.

Диапазон значений и обработка ошибок

Согласно [SWS_Adc_00527] определены следующие значения перечисления:

  • ADC_SERVICE_ACCEPTED (0): изменение состояния мощности выполнено.

  • ADC_SEQUENCE_ERROR (2): имеет место некорректная последовательность вызовов API.

  • ADC_POWER_STATE_NOT_SUPP (4): модуль ADC не поддерживает запрошенное состояние мощности.
  • ADC_TRANS_NOT_POSSIBLE (5): модуль ADC не может напрямую перейти из текущего состояния мощности в требуемое, либо аппаратная периферия все еще занята.

На основании этих значений вызывающая сторона может определить, был ли переход успешным или какая конкретная причина ошибки (например, недопустимая последовательность вызовов или занятость аппаратного обеспечения) воспрепятствовала выполнению.
