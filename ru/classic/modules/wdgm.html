Роль и границы системы: проверка потока выполнения программы, разрешение аппаратного сторожевого таймера

Watchdog Manager (WdgM) контролирует выполнение Supervised Entities (SE). На основе результата он решает, продолжать ли обслуживание аппаратных сторожевых таймеров. Точный по времени триггеринг инкапсулирован в Watchdog Driver. WdgM лишь устанавливает условие срабатывания триггера через Watchdog Interface, которое предписывает драйверу продолжать триггеринг SWS WdgM с. 56. Для этого ему обязательно требуются WdgIf_SetMode, WdgIf_SetTriggerCondition, функция OS GetElapsedValue и Det_ReportRuntimeError [SWS_WdgM_00161].

В R20-11 модуль также опционально использует BswM_WdgM_RequestPartitionReset, Dem_SetEventStatus, Det_ReportError и Mcu_PerformReset [SWS_WdgM_00162]. Для запроса сброса раздела BswM создает для каждого раздела отдельный ModeRequestSource Mode Management Guide с. 30. В концепции безопасности логический контроль выполнения программы с контрольными точками и разрешенными переходами является механизмом, с помощью которого WdgM выполняет соответствующие требования безопасности Safety Concept с. 47.

Контекстная диаграмма: WdgM находится между контролируемыми приложениями, управляющими модулями BSW и стеком сторожевого таймера и использует OS, DET, DEM и Mcu в качестве служб. Источники: [SWS_WdgM_00161], [SWS_WdgM_00162], SWS WdgM с. 85, SWS EcuM с. 34

Жизненный цикл: инициализация, работа, сон и сброс

WdgM_Init получает указатель на WdgM_ConfigType. Эта структура содержит все параметры, конфигурируемые на этапе post-build [SWS_WdgM_00151] [SWS_WdgM_00355]. После вызова активируется контроль для Supervised Entities начального режима. Повторная инициализация выполняется через WdgM_DeInit с последующим WdgM_Init SWS WdgM с. 74. До инициализации глобальный статус статически установлен в WDGM_GLOBAL_STATUS_DEACTIVATED [SWS_WdgM_00387]. Кроме того, WdgM_Init очищает сохраненный в неинициализированной RAM SEID сущности, время ожидания которой истекло первым [SWS_WdgM_00370].

Функции контроля, эталонные циклы и обработка сторожевого таймера запускаются только при первом вызове WdgM_MainFunction после инициализации [SWS_WdgM_00406]. Если установлен WdgMDemStoppedSupervisionReport, WdgM в этом первом цикле сообщает WDGM_E_SUPERVISION как PASSED в DEM [SWS_WdgM_00408]. Спецификация показывает запуск как последовательность между EcuM, WdgM und WdgIf SWS WdgM с. 102.

Диаграмма последовательности: инициализация устанавливает начальный режим и применяет режимы сторожевого таймера; контроль становится активным только с первой главной функцией. Источники: [SWS_WdgM_00151], [SWS_WdgM_00030], [SWS_WdgM_00186], [SWS_WdgM_00406], [SWS_WdgM_00408], SWS WdgM с. 102

WdgM_DeInit останавливает контроль и обработку сторожевого таймера [SWS_WdgM_00407]. Перед этим WdgM посредством смены режима устанавливает условия срабатывания триггера всех работающих сторожевых таймеров на таймаут, допускающий завершение остального останова без сброса. Это следствие концепции «Windowed Watchdogs» SWS WdgM с. 75. Перед SLEEP EcuM вызывает WdgM_DeInit. Пока WdgM деактивирован, все еще активные модули, такие как BswM или EcuM, должны обслуживать аппаратные сторожевые таймеры SWS WdgM с. 59.

WdgM_PerformReset устанавливает условие срабатывания триггера всех драйверов сторожевого таймера в 0 и больше его не обновляет. Вследствие этого аппаратный сторожевой таймер инициирует внешний сброс [SWS_WdgM_00264] SWS WdgM с. 82. EcuM рассматривает этот путь как отдельную цель сброса наряду с Mcu_PerformReset SWS EcuM с. 72.

Диаграмма последовательности: при переходе в спящий режим WdgM передает сторожевые таймеры с увеличенным таймаутом; при целенаправленном сбросе он намеренно дает им истечь. Источники: [SWS_WdgM_00261], [SWS_WdgM_00407], [SWS_WdgM_00264], SWS WdgM с. 59, SWS WdgM с. 82

Контрольные точки и три функции контроля

Supervised Entities сообщают о своем прогрессе синхронно и реэнтерабельно через WdgM_CheckpointReached(SEID, CheckpointID) [SWS_WdgM_00263]. Оба идентификатора представляют собой uint16. Контрольная точка однозначно определяется только парой из SEID и идентификатора контрольной точки [SWS_WdgM_00356] [SWS_WdgM_00357]. Работа распределяется по двум контекстам. В контексте SE выполняются инкрементирование счетчика Alive, а также проверка Deadline и Logical. Циклическая WdgM_MainFunction затем производит оценку для каждой SE SWS WdgM с. 32 [SWS_WdgM_00159].

  • Alive Supervision проверяет циклическое выполнение. Параметры действуют для каждой контрольной точки: WdgMExpectedAliveIndications, WdgMMinMargin, WdgMMaxMargin и WdgMSupervisionReferenceCycle. Главная функция проверяет счетчик в соответствующем эталонном цикле SWS WdgM с. 42 SWS WdgM с. 42.
  • Deadline Supervision измеряет время между начальной и конечной контрольными точками. Для этого служит GetElapsedValue со счетчиком OS для SE, масштабируемый через OsSecondsPerTick [SWS_WdgM_00373] [SWS_WdgM_00374]. Если у конечной контрольной точки отсутствует временная метка начала (значение 0), вызов завершается успешно без измерения [SWS_WdgM_00354]. Таймауты распознаются главной функцией, если установлен WdgMEnableTimeoutDetection [SWS_WdgM_00403] [SWS_WdgM_00404].
  • Logical Supervision проверяет последовательность вдоль сконфигурированных графов. Внутренние переходы находятся внутри SE, внешние переходы связывают контрольные точки различных SE SWS WdgM с. 65 SWS WdgM с. 61. Необходимые ресурсы данных WdgM выводит из числа SE, режимов и сконфигурированных переходов [SWS_WdgM_00366].

Диаграмма последовательности: сообщения контрольных точек проверяются немедленно; главная функция объединяет результаты в статус, сообщения о режиме и условие срабатывания триггера. Источники: [SWS_WdgM_00263], [SWS_WdgM_00373], [SWS_WdgM_00404], [SWS_WdgM_00197], [SWS_WdgM_00198], SWS WdgM с. 32, SWS WdgM с. 78

От локального статуса контроля к глобальному

Каждая SE имеет локальный статус типа WdgM_LocalStatusType со значениями OK, FAILED, EXPIRED и DEACTIVATED. FAILED остается «исправимым», пока не превышен конфигурируемый предел ошибок [SWS_WdgM_00359]. Допуск через WdgMFailedAliveSupervisionRefCycleTol существует только для Alive Supervision. Ошибки Deadline и Logical приводят непосредственно к EXPIRED SWS WdgM с. 30 SWS WdgM с. 126.

Диаграмма состояний: локальный статус SE может вернуться из FAILED, EXPIRED является окончательным. Источники: [SWS_WdgM_00359], [SWS_WdgM_00315], [SWS_WdgM_00182], SWS WdgM с. 34

На основе всех локальных статусов WdgM вычисляет глобальный статус WdgM_GlobalStatusType. В дополнение к локальным значениям здесь присутствует STOPPED. В состоянии EXPIRED драйвер все еще продолжает триггеринг; в STOPPED ему предписано прекратить триггеринг, и следует сброс сторожевого таймера [SWS_WdgM_00360]. На какой срок EXPIRED откладывает сброс, определяет WdgMExpiredSupervisionCycleTol в единицах, кратных Supervision Cycle. Главная функция вычисляет статус в каждом цикле SWS WdgM с. 34. Оба статуса можно запросить через WdgM_GetGlobalStatus и WdgM_GetLocalStatus [SWS_WdgM_00175] [SWS_WdgM_00169].

Диаграмма состояний: глобальный статус эскалирует от OK через FAILED и EXPIRED к STOPPED и завершается сбросом сторожевого таймера. Источники: [SWS_WdgM_00360], [SWS_WdgM_00387], [SWS_WdgM_00139], SWS WdgM с. 38, SWS WdgM с. 32, SWS WdgM с. 57

Режимы и конфигурация: WdgMMode как связующее звено

WdgMConfigSet содержит WdgMInitialMode и от 1 до 255 контейнеров WdgMMode SWS WdgM с. 114. Режим объединяет:

  • допуск WdgMExpiredSupervisionCycleTol,
  • контроли Alive, Deadline и внешние Logical Supervision,
  • параметры локального статуса,
  • конфигурацию триггера WdgMTrigger SWS WdgM с. 117.

WdgMTrigger определяет для каждого сторожевого таймера WdgMWatchdogMode (FAST, SLOW, OFF) и WdgMTriggerConditionValue SWS WdgM с. 125. Поддерживаются VARIANT-PRE-COMPILE и VARIANT-POST-BUILD SWS WdgM с. 97. Интегратор ECU выполняет конфигурацию сверху вниз на основе ServiceNeeds приложений TR Methodology с. 389. Для каждой SE SupervisedEntityNeeds описывают, например, активацию при запуске и длительность циклов Alive SWC Template с. 716.

WdgM_SetMode(Mode) является синхронным и нереэнтерабельным [SWS_WdgM_00154]. Служба выполняется только при глобальном статусе OK или FAILED [SWS_WdgM_00145]. SE, активные в новом режиме, сохраняют свое состояние [SWS_WdgM_00182]. Деактивированные SE переходят в DEACTIVATED; их результаты и счетчики ошибок сбрасываются [SWS_WdgM_00315]. Затем все сторожевые таймеры получают параметры своего режима через WdgIf_SetMode [SWS_WdgM_00186]. Пока новый режим еще не активен полностью, WdgM_GetMode возвращает прежний режим [SWS_WdgM_00168] SWS WdgM с. 77.

Диаграмма деятельности: смена режима имеет три предварительных условия и обрабатывает SE и сторожевые таймеры раздельно; если WdgIf_SetMode завершается сбоем, происходит эскалация смены режима. Источники: [SWS_WdgM_00145], [SWS_WdgM_00392], [SWS_WdgM_00031], [SWS_WdgM_00182], [SWS_WdgM_00315], [SWS_WdgM_00186], [SWS_WdgM_00139], SWS WdgM с. 57

Порты, типы данных и сообщения о статусе для приложений

  • Сообщение контрольной точки: для каждой SE существует сервисный порт [SWS_WdgM_00146]. Он называется localSupervision_{SupervisedEntityCheckpointName}, предоставляет WdgM_LocalSupervision с операцией CheckpointReached и содержит SEID и идентификатор контрольной точки в качестве Port-Defined Arguments [SWS_WdgM_00147] [SWS_WdgM_00333].
  • Сообщения о режиме: для каждой SE имеется порт mode_{SupervisedEntityName} с WdgM_LocalMode [SWS_WdgM_00148] [SWS_WdgM_00149] [SWS_WdgM_00335]. Кроме того, имеется отдельный порт globalmode с WdgM_GlobalMode [SWS_WdgM_00150] [SWS_WdgM_00336]. Оба используют Mode Declaration Group WdgM_Mode со значениями от SUPERVISION_OK (0) до SUPERVISION_DEACTIVATED (4) [SWS_WdgM_00334].
  • Запросы: порт globalSupervision предоставляет WdgM_GlobalSupervision [SWS_WdgM_91002] [SWS_WdgM_91001]. Для каждой SE localSupervisonStatus_{SupervisedEntityName} предоставляет интерфейс WdgM_LocalSupervisionStatus [SWS_WdgM_91003] [SWS_WdgM_91004].

При изменении локального статуса WdgM немедленно сообщает об этом через Mode-порт соответствующей SE [SWS_WdgM_00197]. Изменения глобального статуса передаются через глобальный Mode-порт [SWS_WdgM_00198] и сообщаются только один раз [SWS_WdgM_00199]. Локальный и глобальный статусы имеют раздельные интерфейсы. Благодаря этому глобальный порт не появляется в списке Indirect Port API, через который WdgM обращается ко всем локальным Mode-портам SWS WdgM с. 101 SWS WdgM с. 100. Модули BSW запрашивают глобальные службы через GlobalSupervisionNeeds BSWMD Template с. 257.

Контекстная диаграмма: контролируемые SW-C сообщают контрольные точки и получают свой локальный статус; компонент управления состоянием использует глобальный статус и глобальные службы. Источники: [SWS_WdgM_00147], [SWS_WdgM_00149], [SWS_WdgM_00150], [SWS_WdgM_91002], [SWS_WdgM_91003], SWS WdgM с. 99

Поведение при ошибке

Обработка ошибок варьируется от локального восстановления в SE до сброса электронного блока управления SWS WdgM с. 53. Если глобальный статус достигает STOPPED, WdgM сообщает о событии DEM WDGM_E_SUPERVISION [SWS_WdgM_00375]. Какой DemEventParameter для этого используется, определяет WdgMDemEventParameterRefs SWS WdgM с. 116.

После перезапуска можно определить вызвавшую сбой SE. WdgM_GetFirstExpiredSEID доступен еще до WdgM_Init [SWS_WdgM_00346] [SWS_WdgM_00348]. Служба считывает дважды инвертированное сохраненное значение из неинициализированной RAM. Если значение и инвертированное значение не согласуются друг с другом, она возвращает E_NOT_OK и записывает 0 в *SEID [SWS_WdgM_00349]. Согласно истории изменений, она была внедрена именно для анализа после перезапуска SWS WdgM с. 3.

Ошибки времени выполнения WdgM сообщает независимо от WdgMDevErrorDetect [SWS_WdgM_00402]:

  • WDGM_E_DISABLE_NOT_ALLOWED: переход в WDGIF_OFF_MODE не разрешен. Ошибка может возникнуть в WdgM_SetMode и WdgM_Init [SWS_WdgM_00031] [SWS_WdgM_00030].
  • WDGM_E_SET_MODE: WdgIf_SetMode завершился сбоем [SWS_WdgM_00139]. В этом случае WdgM исходит из наличия глобальной ошибки и устанавливает STOPPED. Сброс следует по истечении времени первого сторожевого таймера, а при сконфигурированном немедленном сбросе — также немедленно SWS WdgM с. 57.
  • WDGM_E_SEDEACTIVATED: контрольная точка принадлежит SE, которая деактивирована в текущем режиме. Вызов возвращает E_NOT_OK [SWS_WdgM_00319].

WdgM_Init не имеет возвращаемого значения [SWS_WdgM_00151], хотя [SWS_WdgM_00030] говорит о возврате с E_NOT_OK. Интерпретация: для вызывающей стороны отказ в запуске, вероятно, различим только по сообщенной ошибке времени выполнения.

Ошибки разработки, такие как WDGM_E_UNINIT, WDGM_E_PARAM_MODE, WDGM_E_PARAM_SEID, WDGM_E_INV_POINTER и WDGM_E_CPID, определены в [SWS_WdgM_00004]. Если активен WdgMDevErrorDetect, службы в состоянии DEACTIVATED сообщают WDGM_E_UNINIT [SWS_WdgM_00253] [SWS_WdgM_00173] [SWS_WdgM_00279]. Без этой опции они возвращаются там без каких-либо действий [SWS_WdgM_00394] [SWS_WdgM_00397] [SWS_WdgM_00401]. Для WdgM_Init в [SWS_WdgM_00389] в качестве ошибочного случая указано состояние DEACTIVATED, а в ее аналоге [SWS_WdgM_00390], напротив, — «не DEACTIVATED». Интерпретация: в обоих случаях, вероятно, имеется в виду защита от повторной инициализации.

Дальнейшие подробные доказательства

  • Конечные автоматы с нумерованными переходами показаны в SWS WdgM с. 34 (локальный) и SWS WdgM с. 38 (глобальный). Нормативными являются определения типов [SWS_WdgM_00359] и [SWS_WdgM_00360].
  • Распределение между контекстом контрольной точки и главной функцией регулируют [SWS_WdgM_00263], [SWS_WdgM_00404] и [SWS_WdgM_00406].
  • Смену режима и ее влияние на сторожевые таймеры описывают [SWS_WdgM_00154], [SWS_WdgM_00186] и SWS WdgM с. 75.
  • Необязательные интерфейсы в более поздних релизах содержат службы SwCluC вместо сброса разделов BswM SWS WdgM с. 79. Для R20-11 действует [SWS_WdgM_00162].
  • В обзоре релиза указаны открытые вопросы: поведение циклического контроля непосредственно после смены режима или после WdgM_Init еще требует уточнения. Кроме того, номера переходов в глобальном конечном автомате содержат ошибки начиная с R21-11 Release Overview с. 32.

Использование и семантика

Синхронная и реентерабельная функция WdgM_CheckpointReached ([SWS_WdgM_00263]) сигнализирует Watchdog Manager о том, что была достигнута определенная контрольная точка (Checkpoint) внутри контролируемой сущности (Supervised Entity). Она предоставляется через заголовочный файл WdgM.h и принимает в качестве входных параметров идентификатор сообщающей сущности (SEID), а также идентификатор достигнутого контрольного пункта (Checkpoint ID). Если счетчик жизнеспособности (Alive-счетчик) удалось успешно обновить, функция возвращает E_OK; если обновление завершилось неудачно, она возвращает E_NOT_OK ([SWS_WdgM_00263]).

Обработка ошибок и состояние инициализации

Если Watchdog Manager находится в состоянии глобальной деактивации WDGM_GLOBAL_STATUS_DEACTIVATED, поведение зависит от конфигурации контроля разработки:

  • Если WdgMDevErrorDetect активирован, WdgM_CheckpointReached сообщает код ошибки WDGM_E_UNINIT в Default Error Tracer (DET) и завершает выполнение без дальнейших действий ([SWS_WdgM_00279]).
  • Если WdgMDevErrorDetect деактивирован, функция сразу же прерывает выполнение без какого-либо действия ([SWS_WdgM_00394], [SWS_WdgM_00396]).

Мониторинг дедлайнов и взаимодействие с OS

При мониторинге времени выполнения и дедлайнов функция взаимодействует с операционной системой:

  • Если достигается контрольная точка завершения дедлайна (Deadline-End-Checkpoint), на которую ссылаются в активном режиме, в то время как временная метка соответствующей начальной контрольной точки имеет значение 0, функция успешно завершается без вычисления разницы во времени ([SWS_WdgM_00354]).
  • Для определения временных меток и вычисления разниц (как для обнаружения преждевременного прибытия, так и задержек) функция использует функцию операционной системы GetElapsedValue, передавая сконфигурированную для Supervised Entity CounterID ([SWS_WdgM_00373]).
  • Пересчет разницы во времени в сконфигурированные предельные значения WdgMDeadlineMin и WdgMDeadlineMax осуществляется на основе конфигурационного параметра OsSecondsPerTick ([SWS_WdgM_00374]).

Применение группы объявления режимов WdgM_Mode

Элемент WdgM_Mode специфицирован согласно [SWS_WdgM_00334] как Mode Declaration Group модуля WdgM и принадлежит к категории EXPLICIT_ORDER. Он служит в Watchdog Manager для формального объявления режимов контроля контролируемых сущностей.

Группа объявления режимов включает следующие режимы с жестко закрепленными числовыми значениями атрибутов:

  • SUPERVISION_OK (значение 0): определяет начальный режим контроля (Initial mode).
  • SUPERVISION_FAILED (значение 1): представляет статус неудавшегося контроля.
  • SUPERVISION_EXPIRED (значение 2): обозначает истекший контроль.
  • SUPERVISION_STOPPED (значение 3): сигнализирует о том, что контроль был остановлен.
  • SUPERVISION_DEACTIVATED (значение 4): обозначает деактивированное состояние контроля.

Кроме того, значение перехода (On transition value) установлено на 255. Что касается динамики, в качестве интерпретации принимается: благодаря категории EXPLICIT_ORDER переключение между отдельными режимами, вероятно, подчиняется упорядоченной последовательности. Значение перехода 255, предположительно, служит для обозначения активного переходного состояния во время смены между двумя режимами.

Поскольку спецификация в [SWS_WdgM_00334] исключительно объявляет тип, значения режимов и параметры переходов, для этого типа данных самих по себе не существует независимых параметров API, сообщений об ошибках DET или DEM, а также требований к реентрабельности.

Настоящее указание по использованию базируется исключительно на данных спецификации для [SWS_WdgM_00334].

При анализе переменных этого типа необходимо особо учитывать необратимость состояния WDGM_LOCAL_STATUS_EXPIRED [SWS_WdgM_00359].

Состояния и диапазон значений

Диапазон значений включает пять определенных состояний мониторинга ([SWS_WdgM_00360]):

  • WDGM_GLOBAL_STATUS_OK (0): мониторинг не выявил ошибок ([SWS_WdgM_00360]).
  • WDGM_GLOBAL_STATUS_FAILED (1): мониторинг завершился неудачно, однако находится в пределах допустимого количества ошибок ([SWS_WdgM_00360]).
  • WDGM_GLOBAL_STATUS_EXPIRED (2): мониторинг завершился неудачно, и допустимый предел погрешности превышен; однако драйверу сторожевого таймера еще не была отдана команда прекратить триггирование ([SWS_WdgM_00360]).

  • WDGM_GLOBAL_STATUS_DEACTIVATED (4): модуль WdgM не инициализирован и, следовательно, не управляет сторожевыми таймерами ([SWS_WdgM_00360]).

WdgM_CheckpointIdType тип

Этот тип идентифицирует контрольную точку в контексте контролируемого объекта для диспетчера сторожевого таймера. Обратите внимание, что отдельная контрольная точка может быть идентифицирована только парой контролируемого объекта ID и контрольной точки ID.

WdgM_ConfigType тип

Эта структура содержит все настраиваемые параметры Watchdog Manager после сборки. Указатель на эту структуру передается функции инициализации Watchdog Manager для настройки. AUTOSAR CP R20 - документа ID : AUTOSAR_SWS_WatchdogManager

WdgM_GlobalStatusType тип

Этот тип должен использоваться для переменных, которые представляют глобальный статус контроля модуля Watchdog Manager.

WdgM_LocalStatusType тип

Этот тип должен использоваться для переменных, которые представляют текущий статус надзора для отдельных Контролируемых объектов.

WdgM_Mode тип

Категория группы объявлений режима Wdg M_ Mode — EXPLICIT_ ORDER. Значение атрибута для объявления режима установлено следующим образом: «SUPERVISION_ OK» = 0 «SUPERVISION_ FAILED» = 1 «SUPERVISION_ EXPIRED" = 2 "SUPERVISION_ STOPPED" = 3 "SUP ERVISION_ DEACTIVATED" = 4 Значение перехода определяется как 255

WdgM_ModeType тип

Этот тип различает различные режимы, настроенные для Watchdog Manager.

WdgM_SupervisedEntityIdType тип

Этот тип идентифицирует отдельный контролируемый объект для диспетчера сторожевого таймера.
