Классификация: транспортный уровень между PduR и FlexRay Interface

FrTp представляет собой транспортный уровень стандарта ISO 10681-2 для связи по FlexRay. Модуль расположен между PDU Router и FlexRay Interface. Он разбивает на сегменты I-PDU, которые не помещаются в назначенную FlexRay-L-PDU, и собирает их заново при приеме (SWS FrTp с. 11). Там, где AUTOSAR не определяет собственных правил, действует ISO 10681-2 ([SWS_FrTp_01005]). Модуль поддерживает соответствующие форматы N-PDU ([SWS_FrTp_01006]).

PduR вызывает службы FrTp_Transmit, FrTp_CancelTransmit, FrTp_ChangeParameter и FrTp_CancelReceive ([SWS_FrTp_00149], [SWS_FrTp_00150], [SWS_FrTp_00151], [SWS_FrTp_01172]). В обратном направлении FrTp использует PduR_FrTpStartOfReception, PduR_FrTpCopyRxData, PduR_FrTpRxIndication, PduR_FrTpCopyTxData и PduR_FrTpTxConfirmation (SWS FrTp с. 19).

Вниз FrTp передает N-PDU с помощью FrIf_Transmit. Снизу он получает вызовы FrTp_RxIndication, FrTp_TxConfirmation и FrTp_TriggerTransmit ([SWS_FrTp_00152], [SWS_FrTp_00153], [SWS_FrTp_00154], SWS FrTp с. 20). Начиная с R24-11 между ними дополнительно расположен L-SDU Router (SWS FrTp с. 19). Для R20-11, напротив, применяется прямой вызов FrIf_Transmit ([SWS_FrTp_01050], [SWS_FrTp_00577]).

Другими партнерами являются:

  • ECU State Manager вызывает FrTp_Init и FrTp_Shutdown (SWS FrTp с. 19).
  • BSW Scheduler вызывает FrTp_MainFunction ([SWS_FrTp_00162], SWS FrTp с. 81).
  • Об ошибках времени выполнения FrTp сообщает через Det_ReportRuntimeError ([SWS_FrTp_00577]).

Контекстная диаграмма: FrTp выступает посредником между PduR и FrIf и управляется EcuM и BSW Scheduler. Источники: SWS FrTp с. 19, SWS FrTp с. 20, [SWS_FrTp_00577]

Жизненный цикл модуля и циклическая обработка

FrTp имеет ровно два внутренних состояния: FRTP_OFF и FRTP_ON ([SWS_FrTp_01028]). Текущее состояние хранится в статической переменной FrTpState ([SWS_FrTp_01029], [SWS_FrTp_01106]).

  • После включения питания модуль находится в FRTP_OFF ([SWS_FrTp_01030]).
  • Успешный вызов FrTp_Init с указателем на FrTp_ConfigType переключает в FRTP_ON ([SWS_FrTp_00147], [SWS_FrTp_01194], [SWS_FrTp_01032]). При этом инициализируются все глобальные переменные и экземпляр переводится в режим ожидания.
  • Сегментация, сборка и все остальные задачи выполняются только в FRTP_ON ([SWS_FrTp_01033]).
  • Если служба вызывается без инициализации, она сообщает FRTP_E_UNINIT. Исключение составляют FrTp_Init и FrTp_GetVersionInfo ([SWS_FrTp_01201]).

FrTp_Shutdown просто останавливает все открытые соединения и освобождает ресурсы ([SWS_FrTp_00148]). После этого модуль снова переходит в FRTP_OFF ([SWS_FrTp_01036], SWS FrTp с. 36).

Продвижение протокола обеспечивает FrTp_MainFunction. Она является точкой входа для всех задач обработки ([SWS_FrTp_00203], [SWS_FrTp_00580]) и должна выполняться как минимум один раз за цикл FlexRay ([SWS_FrTp_01152]). Для этого службы устанавливают внутренние флаги, такие как TX_SDU_AVAILABLE и RX_PDU_AVAILABLE ([SWS_FrTp_00416], [SWS_FrTp_00418], SWS FrTp с. 37).

Диаграмма состояний: только FrTp_Init переводит из FRTP_OFF в FRTP_ON, и только там происходит обработка. Источники: [SWS_FrTp_01030], [SWS_FrTp_01032], [SWS_FrTp_01036], SWS FrTp с. 36

Типы передачи по ISO 10681-2

FrTp поддерживает шесть типов передачи:

  • несегментированная, без подтверждения и с подтверждением приема, при известной длине ([SWS_FrTp_01007], [SWS_FrTp_01008]);
  • сегментированная, без подтверждения и с подтверждением приема, при известной длине ([SWS_FrTp_01009], [SWS_FrTp_01010]);
  • сегментированная, без подтверждения и с подтверждением приема, при неизвестной длине ([SWS_FrTp_01011], [SWS_FrTp_01012]).

Сегментированная передача состоит из StartFrame, FlowControl, ConsecutiveFrames и LastFrame. Кадр ConsecutiveFrame_EOB завершает блок; затем получатель разрешает следующий блок с помощью FlowControl (SWS FrTp с. 28).

Передачи с неизвестной длиной функционируют следующим образом:

  • Функция активируется с помощью переключателя компилятора ([SWS_FrTp_01062]).
  • Верхний уровень запрашивает ее с помощью SduLength = 0 ([SWS_FrTp_01043], [SWS_FrTp_01064]).
  • Передача завершается, как только верхний уровень сообщает о длине 0 ([SWS_FrTp_01066]).
  • FrTp суммирует частичные длины и передает общую длину в LastFrame ([SWS_FrTp_01067]).

В соединениях 1:n нет ни квитирования, ни повторных попыток ([SWS_FrTp_00598]). Сегментация в них приводит к ошибке FRTP_E_SEG_ERROR ([SWS_FrTp_01187], [SWS_FrTp_01208]).

Диаграмма последовательности: сегментированная передача известной длины без подтверждения приема с двумя блоками, каждый из которых разрешается через FlowControl_CTS. Источники: [SWS_FrTp_01009], SWS FrTp с. 28

Процесс передачи: от FrTp_Transmit до PduR_FrTpTxConfirmation

Каждый процесс передачи начинается с FrTp_Transmit ([SWS_FrTp_00136]). Служба устанавливает TX_SDU_AVAILABLE только в том случае, если TxPduId действителен и канал свободен ([SWS_FrTp_01039]). В противном случае она возвращает E_NOT_OK ([SWS_FrTp_01040], [SWS_FrTp_01041]). То же самое справедливо, если для той же адресной информации передача уже выполняется ([SWS_FrTp_01200]). Адреса поступают из FrTpLa/FrTpRa или из метаданных SOURCE_ADDRESS_16/TARGET_ADDRESS_16 ([SWS_FrTp_01204], [SWS_FrTp_01205]).

В функции MainFunction процесс передачи выполняется в следующие этапы:

  1. FrTp определяет доступную длину с помощью PduR_FrTpCopyTxData ([SWS_FrTp_01042]).
  2. FrTp занимает первый свободный FrTpTxPdu из пула ([SWS_FrTp_01045]). Если свободных нет, обработка соединения откладывается до следующего вызова ([SWS_FrTp_01047]).
  3. На основе длины этой PDU FrTp решает, требуется ли сегментация ([SWS_FrTp_01048]).
  4. FrTp копирует полезные данные длиной в PDU ([SWS_FrTp_01123]) и отправляет их с помощью FrIf_Transmit и точной длины ([SWS_FrTp_01050], [SWS_FrTp_01051]).
  5. FrTp_TxConfirmation подтверждает каждую N-PDU и сбрасывает FrTpTxPdu обратно в состояние «idle» ([SWS_FrTp_01052], [SWS_FrTp_01054]).

Если PduR_FrTpCopyTxData возвращает BUFREQ_E_BUSY, FrTp повторяет попытку до FrTpTimeCs раз ([SWS_FrTp_01196]).

Канал и флаг освобождаются, как только выполняются три условия: все данные отправлены, подтверждение положительное, а при передаче с подтверждением приема получена финальная квитанция ([SWS_FrTp_01056], [SWS_FrTp_01057]). Для каждого принятого запроса FrTp вызывает PduR_FrTpTxConfirmation ровно один раз, со значением E_OK или E_NOT_OK ([SWS_FrTp_01058]).

Для направления передачи существуют два режима буфера: «Immediate» и «Decoupled Buffer Access» ([SWS_FrTp_01084]). В разделенном режиме нижний уровень забирает N-PDU через FrTp_TriggerTransmit. При этом FrTp копирует адресную информацию, PCI и данные с точной длиной ([SWS_FrTp_01060], [SWS_FrTp_01061]). Поскольку этот вызов выполняется в контексте прерывания, AI и PCI следует предварительно буферизовать локально (SWS FrTp с. 50).

Диаграмма последовательности: запрос на передачу принимается синхронно и обрабатывается асинхронно в MainFunction (Immediate Buffer Access; в режиме Decoupled добавляется FrTp_TriggerTransmit). Источники: SWS FrTp с. 44, [SWS_FrTp_01039], [SWS_FrTp_01042], [SWS_FrTp_01058]

Диаграмма деятельности: длина первой свободной PDU из пула определяет, требуется ли сегментация; для соединений 1:n необходимость сегментации прерывает передачу. Источники: [SWS_FrTp_01047], [SWS_FrTp_01048], SWS FrTp с. 46, SWS FrTp с. 52

Процесс приема и сборка

Прием всегда начинается с FrTp_RxIndication ([SWS_FrTp_00137]). FrTp обрабатывает N-PDU только при выполнении двух условий ([SWS_FrTp_01069], [SWS_FrTp_01071]):

  • RxPduId действителен.
  • Адрес назначения и адрес источника соответствуют FrTpLa/FrTpRa определенного FrTpConnection.

В противном случае N-PDU игнорируется ([SWS_FrTp_01070], [SWS_FrTp_01072]). Кроме того, RX_PDU_AVAILABLE устанавливается только при наличии свободного канала ([SWS_FrTp_01074]). Если свободный канал отсутствует, FrTp сообщает FRTP_E_NO_CHANNEL ([SWS_FrTp_01186]). StartFrame остается локально буферизованным. Это позволяет, например, шлюзу отправить FlowControl позже, как только освободится канал (SWS FrTp с. 56).

Новое соединение обрабатывается следующим образом:

  • FrTp вызывает PduR_FrTpStartOfReception с ожидаемой длиной ([SWS_FrTp_01078]). При неизвестной длине это значение равно 0 ([SWS_FrTp_01184]). Данные и размер StartFrame также передаются ([SWS_FrTp_01193]).
  • Фрагменты передаются наверх с помощью PduR_FrTpCopyRxData ([SWS_FrTp_01138]).
  • Кадры FlowControl-N-PDU, требуемые протоколом, FrTp отправляет самостоятельно ([SWS_FrTp_01080]).
  • После полного приема канал освобождается ([SWS_FrTp_01081]). О завершении сообщает PduR_FrTpRxIndication ([SWS_FrTp_01083]).
  • Принятые адреса FrTp передает дальше в виде метаданных ([SWS_FrTp_01206]).

Источники по-разному описывают контекст, в котором вызывается PduR_FrTpStartOfReception:

  • На рисунке из R20-11 показана MainFunction (SWS FrTp с. 86).
  • В более новых редакциях указан FrTp_RxIndication (SWS FrTp с. 49).
  • В одном из примечаний допускаются оба варианта (SWS FrTp с. 53).

Диаграмма последовательности: индикация проверяет и буферизует, MainFunction выполняет сборку, отправляет FlowControl и сообщает в PduR. Источники: SWS FrTp с. 86, [SWS_FrTp_01074], [SWS_FrTp_01078], [SWS_FrTp_01083]

Каналы, соединения, пулы PDU и управление полосой пропускания

Каждое коммуникационное отношение представляет собой отдельный контейнер FrTpConnection ([SWS_FrTp_01014]). Он имеет уникальный в масштабах модуля N-SDU-ID и уникальную пару адресов ([SWS_FrTp_01018], [SWS_FrTp_01017]). Количество соединений настраивается на этапе post-build ([SWS_FrTp_01015]). Количество каналов задается параметром FrTpChanNum, и каналы работают параллельно ([SWS_FrTp_00088], [SWS_FrTp_00228]).

Полосу пропускания FrTp представляет в виде N-PDU, напрямую отображаемых на L-PDU (SWS FrTp с. 60). Для пулов PDU передачи действует следующее:

  • Несколько соединений могут ссылаться на один и тот же FrTpTxPduPool ([SWS_FrTp_01020]).
  • Пулы могут перекрываться ([SWS_FrTp_01176]).
  • PDU пула упорядочены по возрастанию согласно их позиции в сетевом расписании ([SWS_FrTp_01088]) и могут иметь разную длину ([SWS_FrTp_01089]).

Кадры ConsecutiveFrame не должны обгонять друг друга. Для этого счетчик TxPduPendingCounter для каждого канала подсчитывает еще не подтвержденные N-PDU ([SWS_FrTp_01090], [SWS_FrTp_01091], [SWS_FrTp_01092]). Соединение обрабатывается только в том случае, если его счетчик равен 0 ([SWS_FrTp_01094], [SWS_FrTp_01095]). Все активные соединения обслуживаются поочередно, пока в пуле есть свободные PDU ([SWS_FrTp_01096], SWS FrTp с. 61).

Во время выполнения FrTp_ChangeParameter с помощью TP_BC изменяет параметр BandwidthControl. Он состоит из FrTpSCexp и FrTpMaxNbrOfNPduPerCycle ([SWS_FrTp_00242], [SWS_FrTp_01178], ComStack Types с. 18). Биты 3..7 содержат количество PDU, биты 0..2 — экспоненту ([SWS_FrTp_01195]). Во время текущего приема FrTp отклоняет изменение со значением E_NOT_OK ([SWS_FrTp_01115]); в противном случае с этого момента действует новое значение ([SWS_FrTp_01156]).

В качестве отправителя FrTp соблюдает границу, сообщенную получателем:

  • При BC.MPPC ≠ 0 он использует только соответствующее количество PDU из пула ([SWS_FrTp_01175]).
  • Если установлен FrTpBandwidthLimitation, StartFrame и FlowControl всегда направляются в первую PDU пула ([SWS_FrTp_01174], [SWS_FrTp_01177], SWS FrTp с. 134).

Диаграмма кооперации (схематический пример): соединения совместно используют перекрывающиеся пулы Tx-PDU, чьи N-PDU однозначно отображаются на L-PDU модуля FrIf. Источники: [SWS_FrTp_01020], [SWS_FrTp_01176], SWS FrTp с. 60

Поведение при ошибке

Ошибки разработки и времени выполнения. При включенном обнаружении ошибок разработки службы проверяют свои параметры. В таком случае они сообщают FRTP_E_INVALID_PDU_SDU_ID, FRTP_E_PARAM_POINTER или FRTP_E_INVALID_PARAMETER ([SWS_FrTp_01201]).

  • Службы с возвращаемым значением при этом возвращают E_NOT_OK, например FrTp_Transmit ([SWS_FrTp_01139], [SWS_FrTp_01140]), FrTp_CancelTransmit ([SWS_FrTp_01141]), FrTp_ChangeParameter ([SWS_FrTp_01143], [SWS_FrTp_01144]), FrTp_TriggerTransmit ([SWS_FrTp_01145], [SWS_FrTp_01146]) и FrTp_CancelReceive ([SWS_FrTp_01180]).
  • Функции обратного вызова FrTp_RxIndication и FrTp_TxConfirmation только сообщают об ошибке ([SWS_FrTp_01147], [SWS_FrTp_01148], [SWS_FrTp_01149], [SWS_FrTp_01203]).
  • Передача неизвестной длины, которая не сконфигурирована, приводит к FRTP_E_UMSG_LENGTH_ERROR ([SWS_FrTp_01134]).
  • Ошибками времени выполнения являются FRTP_E_SEG_ERROR и FRTP_E_NO_CHANNEL ([SWS_FrTp_01208]).

Ошибки протокола. При таких ошибках FrTp активно прерывает передачу и сообщает PduR_FrTpTxConfirmation(E_NOT_OK) ([SWS_FrTp_01198], [SWS_FrTp_01199]):

  • кадр FlowControl с недопустимым FS или с OVFLW либо ABT;
  • кадр ACK_RET, позиция буфера которого находится за пределами буфера передатчика.

Отрицательный FrTp_TxConfirmation освобождает занятый канал ([SWS_FrTp_01056], [SWS_FrTp_01081]).

Таймеры и счетчики. Контроль времени осуществляется в соответствии с определенными таймерами и реакциями на таймаут ([SWS_FrTp_01055], [SWS_FrTp_01099], [SWS_FrTp_01100]). Их конфигурация должна удовлетворять фиксированным неравенствам ([SWS_FrTp_00599], [SWS_FrTp_01153], [SWS_FrTp_01154], [SWS_FrTp_01155]). Счетчики COUNTER_FCWT и Counter_RX_RN ограничены; при достижении предела применяется определенная реакция ([SWS_FrTp_01105], [SWS_FrTp_01114], [SWS_FrTp_01113], SWS FrTp с. 69). Если при сегментированном приеме возникает ошибка, флаг RX_ERROR фиксирует ее до наступления реакции ([SWS_FrTp_00429], [SWS_FrTp_00430]).

Отмена передачи. Transmit Cancellation активируется через FrTpTransmitCancellation ([SWS_FrTp_01097]) и запрашивается с помощью FrTp_CancelTransmit ([SWS_FrTp_00384]). Результат зависит от степени выполнения:

  • Еще не начатый запрос немедленно освобождает соединение ([SWS_FrTp_00385]).
  • Текущая передача останавливается; служба возвращает E_OK ([SWS_FrTp_01116]).
  • При неактивном соединении или если последняя N-PDU неподтвержденной передачи уже передана, служба возвращает E_NOT_OK ([SWS_FrTp_01116]).

Получатель распознает отмену только по таймауту и сообщает о ней через PduR_FrTpRxIndication (SWS FrTp с. 65).

Отмена приема. FrTp_CancelReceive прерывает сегментированный прием и затем возвращает E_OK ([SWS_FrTp_01181], [SWS_FrTp_01183]). При несегментированном приеме или во время LastFrame служба отклоняет запрос ([SWS_FrTp_01182]).

Диаграмма последовательности: отмена передачи в процессе сегментированной передачи приводит на стороне получателя к таймауту с отрицательным итоговым сообщением. Источники: SWS FrTp с. 65, [SWS_FrTp_01116], SWS FrTp с. 58

Использование и семантика

Функция FrTp_Transmit служит для запроса на передачу PDU ([SWS_FrTp_00149]). Вызов ведёт себя синхронно и возвращает E_OK, если запрос на передачу был принят, или E_NOT_OK, если запрос был отклонён ([SWS_FrTp_00149]). Через параметр TxPduId указывается передаваемая PDU; PduInfoPtr передаёт длину, указатель на полезные данные, а также указатель на метаданные ([SWS_FrTp_00149]). Если требуется запустить передачу данных верхнего уровня с неизвестной длиной сообщения, необходимо вызвать FrTp_Transmit со значением параметра PduLength = 0 ([SWS_FrTp_01064]).

Обработка ошибок и проверки

Если обнаружение ошибок разработки (Development Error Detection) активировано, функция выполняет проверки входных параметров:

  • Если указатель PduInfoPtr недействителен, FrTp_Transmit сообщает об ошибке FRTP_E_PARAM_POINTER и возвращает E_NOT_OK ([SWS_FrTp_01140]).
  • Если параметр TxPduId недействителен или не поддерживается, сообщается об ошибке FRTP_E_INVALID_PDU_SDU_ID, служба прерывается и возвращается E_NOT_OK ([SWS_FrTp_01040], [SWS_FrTp_01139]).

Кроме того, выполнение прерывается и возвращается E_NOT_OK, если в данный момент нет свободного канала передачи (состояние FrTpTxChannelState ≠ Idle) ([SWS_FrTp_01041]).

Параллелизм и реентерабельность

FrTp_Transmit реентерабельна для вызовов с различными идентификаторами PDU (TxPduId). Для одного и того же идентификатора PDU функция, напротив, не является реентерабельной ([SWS_FrTp_00149]).

Это указание по использованию было сгенерировано автоматически на основе спецификации AUTOSAR CP R20-11.

Семантика и возвращаемые значения

  • Если запрос на передачу всё ещё ожидает обработки, но сам процесс передачи ещё не начался, функция немедленно освобождает соединение ([SWS_FrTp_00385]).

Обработка ошибок и параллелизм

Если Development Error Tracer (DET) активирован для FrTp_CancelTransmit, функция проверяет параметр TxPduId на валидность. Если эта проверка завершается неудачно, сообщается об ошибке разработки FRTP_E_INVALID_PDU_SDU_ID и возвращается E_NOT_OK ([SWS_FrTp_01141]).

Что касается реентерабельности, вызов является реентерабельным для различных PDU-ID, но нереентерабельным для идентичных PDU-ID ([SWS_FrTp_00150]).

Использование

Синхронная функция FrTp_ChangeParameter ([SWS_FrTp_00151], объявленная в FrTp.h) служит для изменения параметров транспортного протокола во время выполнения. С помощью этой службы параметры FlowControl-PDU управления полосой пропускания (BandwidthControl) согласно ISO 10681-2 — а именно FrTpSCexp и FrTpMaxNbrOfNPduPerCycle — могут быть скорректированы во время выполнения ([SWS_FrTp_00242]).

Функция ожидает следующие входные параметры ([SWS_FrTp_00151]):

  • id (PduIdType): идентификатор PDU, на который должно повлиять изменение параметра.
  • parameter (TPParameterType): идентификатор модифицируемого параметра.
  • value (uint16): новое значение для выбранного параметра.

Возвращаемое значение сигнализирует с помощью E_OK об успешном выполнении изменения или с помощью E_NOT_OK об отклонении запроса на изменение ([SWS_FrTp_00151]).

Обработка ошибок

Если обнаружение ошибок разработки (Development Error Detection) активировано для FrTp_ChangeParameter, выполняются проверки входных данных со специфическими сообщениями об ошибках:

  • При недопустимом идентификаторе PDU (id) модуль сообщает об ошибке разработки FRTP_E_INVALID_PDU_SDU_ID и прерывает выполнение с E_NOT_OK ([SWS_FrTp_01143]).
  • При недопустимом идентификаторе параметра (parameter) генерируется ошибка разработки FRTP_E_INVALID_PARAMETER и возвращается E_NOT_OK ([SWS_FrTp_01144]).

Параллелизм и ограничения

Служба определена как нереентерабельная (Non Reentrant) ([SWS_FrTp_00151]). Следует также учитывать, что на стороне отправителя дополнительный FlowControl вследствие изменения параметра принимается как неожиданный N-PDU и игнорируется ([SWS_FrTp_00242]).

Данное указание по использованию основано на спецификации AUTOSAR Classic R20-11.

Если отмена завершается сбоем или отклоняется целевым модулем, вызывающей стороне сообщается об этом через результат E_NOT_OK ([SWS_FrTp_01172]). Если служба FrTp_CancelReceive была выполнена успешно, возвращаемое значение в соответствии с [SWS_FrTp_01183] обязательно должно быть E_OK.

Функция FrTp_TriggerTransmit ([SWS_FrTp_00154]) служит для синхронного предоставления данных передачи SDU. При вызове вызывающий уровень передаёт идентификатор TxPduId, а также через параметр PduInfoPtr указатель на структуру PduInfoType. Она содержит адрес буфера SduDataPtr и доступный размер буфера в SduLength.

Использование и передача данных

  • Модуль синхронно проверяет, помещаются ли передаваемые данные в буфер, о котором сообщает PduInfoPtr->SduLength ([SWS_FrTp_00154]).
  • Если размер буфера достаточен, информация об адресе, PCI и данные N-SDU копируются в буфер ([SWS_FrTp_01060]). Поле SduLength обновляется точным количеством скопированных байтов данных, и функция возвращает E_OK ([SWS_FrTp_00154], [SWS_FrTp_01061]).
  • Если буфера недостаточно, функция прерывает выполнение с E_NOT_OK без модификации PduInfoPtr. В этом случае использовать буфер запрещено ([SWS_FrTp_00154]).

Обработка ошибок

Если обнаружение ошибок разработки (DET) активировано, функция валидирует свои входные параметры:

  • Если передаётся недопустимый TxPduId, функция сообщает об ошибке FRTP_E_INVALID_PDU_SDU_ID и возвращает E_NOT_OK ([SWS_FrTp_01145]).
  • Если указатель PduInfoPtr недопустим, функция сообщает об FRTP_E_PARAM_POINTER и также возвращает E_NOT_OK ([SWS_FrTp_01146]).

Параллелизм

Функция является реентерабельной для различных значений TxPduId, однако нереентерабельной для одного и того же TxPduId ([SWS_FrTp_00154]).

Данное указание по использованию основано на данных спецификации AUTOSAR Classic R20-11 для FrTp_TriggerTransmit.

Функция FrTp_TxConfirmation вызывается нижележащим уровнем связи, чтобы подтвердить модулю FrTp успешную передачу или сбой PDU [SWS_FrTp_00153], [SWS_FrTp_01053]. Параметр result указывает, был ли PDU успешно передан (E_OK) или передача завершилась сбоем (E_NOT_OK) [SWS_FrTp_00153].

Параллелизм и ограничения

Функция является реентерабельной для вызовов с различными PDU-ID, однако нереентерабельной для одного и того же PDU-ID [SWS_FrTp_00153].

Обработка ошибок

При активированном обнаружении ошибок разработки (Development Error Detection) переданные аргументы проверяются:

  • Если TxPduId недопустим, функция сообщает об ошибке FRTP_E_INVALID_PDU_SDU_ID [SWS_FrTp_01149].
  • Если параметр result недопустим, генерируется ошибка разработки FRTP_E_INVALID_PARAMETER [SWS_FrTp_01203].

Взаимодействие и управление состояниями

При каждом вызове с соответствующим ID подтверждения счетчик TxPduPendingCounter декрементируется [SWS_FrTp_01092]. Кроме того, вызов влияет на внутренние состояния каналов и флаги управления:

  • Канал передачи (Tx): модуль освобождает выделенный канал (FrTpTxChannelState = Idle) и сбрасывает флаг TX_SDU_AVAILABLE, если result имеет значение E_NOT_OK или если все данные Tx-N-SDU были переданы, подтверждение получено с E_OK и было принято возможно сконфигурированное финальное подтверждение (Acknowledge) [SWS_FrTp_01056], [SWS_FrTp_01057]. При тех же условиях (а также при прерывании передачи) сбрасывается также флаг TX_SDU_UNKNOWN_MSG_LENGTH [SWS_FrTp_01124].
  • Канал приёма (Rx): занятый канал приёма освобождается (FrTpRxChannelState = Idle), если о FrTp_TxConfirmation сообщается с E_NOT_OK или если все данные N-SDU приняты и все требуемые PDU ответа (FlowControl) успешно подтверждены с E_OK [SWS_FrTp_01081].

FrTp_GetVersionInfo функция

Возвращает информацию о версии.

void FrTp_GetVersionInfo (Std_VersionInfoType* versioninfo);
FrTp_Init функция

Эта служба инициализирует все глобальные переменные экземпляра транспортного уровня Flex Ray и переводит его в состояние ожидания. Он не имеет возвращаемого значения, поскольку ошибки программного обеспечения в данных инициализации должны быть обнаружены во время конфигурации (например, с помощью инструмента конфигурации).

void FrTp_Init (const FrTp_ConfigType* configPtr);

Std_ReturnType FrTp_CancelReceive (PduIdType RxPduId);
FrTp_CancelTransmit функция

FrTp_Shutdown функция

Эта служба закрывает все ожидающие соединения транспортного протокола, просто останавливая работу, освобождает все ресурсы и останавливает модуль Fr Tp.

void FrTp_Shutdown (void);

FrTp_RxIndication функция

Индикация получения PDU от модуля интерфейса связи нижнего уровня.

void FrTp_RxIndication (PduIdType RxPduId, const PduInfoType* PduInfoPtr);
FrTp_TriggerTransmit функция

В пределах этого API модуль верхнего уровня (называемый модулем) должен проверить, помещаются ли доступные данные в размер буфера, сообщаемый Pdu Info Ptr - >Sdu Длина. Если он подходит, он должен скопировать свои данные в буфер, предоставленный Pdu Info Ptr - >Sdu Data Ptr, и обновить длину фактически скопированных данных в Pdu Info Ptr - >Sdu Длина. Если нет, он возвращает E_ NOT_ OK без изменения Pdu Info Ptr.

Std_ReturnType FrTp_TriggerTransmit (PduIdType TxPduId, PduInfoType* PduInfoPtr);
FrTp_TxConfirmation функция

Модуль интерфейса связи нижнего уровня подтверждает передачу PDU или невозможность передачи PDU.

void FrTp_TxConfirmation (PduIdType TxPduId, Std_ReturnType result);
