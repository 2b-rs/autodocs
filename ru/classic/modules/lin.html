Роль драйвера LIN между LIN Interface и аппаратной частью контроллера

Драйвер LIN (Lin) инкапсулирует аппаратный блок LIN блока управления, то есть выделенный LIN-контроллер или простой UART. Он предоставляет его для LIN Interface (LinIf) в виде сервисов, привязанных к каналам. Задания на фреймы драйвер получает как Lin_PduType со следующими данными: PID, модель контрольной суммы, тип ответа, длина данных и указатель на SDU [SWS_Lin_00232]. В модели характеристик LIN является опциональной сетевой технологией с подфункциями LIN_Master и LIN_Slave FO Features с. 58. Драйвер обслуживает обе роли для каждого канала. Однако ряд сервисов доступен только мастер-каналам [SWS_Lin_00287] [SWS_Lin_00288] [SWS_Lin_00289].

Драйвер использует три обязательных интерфейса других модулей:

  • Dem_SetEventStatus для производственных ошибок.
  • EcuM_SetWakeupEvent и LinIf_WakeupConfirmation для обнаруженных событий пробуждения [SWS_Lin_00234].

Опционально добавляются Det_ReportError, EcuM_CheckWakeup и управление уведомлениями Icu [SWS_Lin_00235]. На слейв-каналах драйвер сообщает о заголовках, приеме, подтверждении передачи и ошибках через функции обратного вызова LinIf [SWS_Lin_00280] [SWS_Lin_00274] [SWS_Lin_00275] [SWS_Lin_00277]. Собственных функций обратного вызова он не предоставляет SWS LINDriver с. 49. Полные диаграммы последовательности приведены не в спецификации драйвера, а в спецификации LinIf SWS LINDriver с. 52.

Контекстная диаграмма: драйвер находится между LinIf и аппаратным обеспечением и сообщает о событиях пробуждения в EcuM, а также об ошибках в DEM и DET. Источники: [SWS_Lin_00234] [SWS_Lin_00235] SWS LINDriver с. 50 SWS LINInterface с. 112

Состояния модуля и каналов от сброса до рабочего режима

Драйвер работает с двухступенчатым конечным автоматом. После сброса модуль находится в LIN_UNINIT и не может использоваться. Вызов Lin_Init переводит его в LIN_INIT; там каждый доступный канал готов к работе SWS LINDriver с. 24 SWS LINDriver Рис. 7.1 с. 24. Lin_Init является синхронным и нереентерабельным. Сервис получает указатель на Lin_ConfigType. Его содержимое аппаратно зависимо и конфигурирует драйвер, аппаратный блок и каналы [SWS_Lin_00006] [SWS_Lin_00227]. Окружение должно вызывать Lin_Init во время выполнения только один раз SWS LINDriver с. 24.

Внутри LIN_INIT каждый канал имеет собственное состояние SWS LINDriver с. 23:

  • LIN_CH_OPERATIONAL: канал инициализирован и участвует в кластере LIN SWS LINDriver с. 24.
  • LIN_CH_SLEEP: распознавание импульса пробуждения активно, аппаратное обеспечение при необходимости находится в режиме низкого энергопотребления SWS LINDriver с. 24.
  • LIN_CH_SLEEP_PENDING: только для мастер-каналов. Промежуточное состояние после Lin_GoToSleep, которое завершает только Lin_GetStatus SWS LINDriver Рис. 7.1 с. 24.

То, какое состояние канала устанавливает Lin_Init, в полезной нагрузке затронуто лишь поверхностно. Вероятно, каждый канал запускается в LIN_CH_SLEEP; на это указывает описание диаграммы состояний SWS LINDriver Рис. 7.1 с. 23. Обратно в LIN_CH_OPERATIONAL канал переходит через Lin_Wakeup или Lin_WakeupInternal [SWS_Lin_00169] [SWS_Lin_00256].

Диаграмма состояний: состояния модуля и состояния каналов с инициирующими сервисами. LIN_CH_SLEEP_PENDING существует только для мастер-каналов. Источники: SWS LINDriver Рис. 7.1 с. 24 [SWS_Lin_00006] [SWS_Lin_00166] [SWS_Lin_00167] [SWS_Lin_00169] [SWS_Lin_00256]

Мастер-каналы: задание на фрейм и опрос статуса

На мастер-канале LinIf инициирует каждую запись расписания с помощью Lin_SendFrame. Сервис является асинхронным и отправляет LIN-заголовок, а также, в зависимости от типа ответа, Response [SWS_Lin_00191]. Поля Lin_PduType определяют фрейм [SWS_Lin_00232]:

  • Pid (Lin_FramePidType, 0…0xFE): идентификатор 0…0x3F, включая два бита четности [SWS_Lin_00228].
  • Cs (Lin_FrameCsModelType): LIN_CLASSIC_CS или LIN_ENHANCED_CS. Драйвер вычисляет соответствующую контрольную сумму [SWS_Lin_00229] [SWS_Lin_00019].
  • Drc (Lin_FrameResponseType): Response поступает от этого узла (LIN_FRAMERESPONSE_TX), от другого, релевантного узла (LIN_FRAMERESPONSE_RX) или не имеет значения (LIN_FRAMERESPONSE_IGNORE) [SWS_Lin_00230].
  • Dl (Lin_FrameDlType, 1…8): количество копируемых байтов данных [SWS_Lin_00231].

В памяти элемент 0 массива SDU содержит байт, передаваемый первым SWS LINDriver с. 30. Если аппаратное обеспечение не может буферизовать байты, драйвер предоставляет временный буфер. Передача и прием выполняются в неблокирующем режиме SWS LINDriver с. 28. Фреймы Slave-to-Slave мастер отправляет с помощью LIN_FRAMERESPONSE_IGNORE SWS LINDriver с. 37. LinIf поддерживает этот тип связи, но не рекомендует его SWS LINInterface с. 45.

Диаграмма последовательности: отправленный фрейм инициируется, передается и подтверждается посредством опроса состояния в течение трех циклов главной функции LinIf. В более поздних релизах верхний уровень называется LSduR. Источники: SWS LINInterface Рис. 9.1 с. 120 [SWS_Lin_00191] [SWS_Lin_00168] SWS LINInterface с. 37

Результат обработки фрейма возвращает синхронный сервис Lin_GetStatus. Он возвращает Lin_StatusType. При приеме он устанавливает Lin_SduPtr на теневой буфер или на отображенный аппаратный буфер приема [SWS_Lin_00168] [SWS_Lin_00233]. LinIf вызывает его не ранее чем через максимальную длину фрейма и не позднее следующей записи расписания SWS LINInterface с. 35. Вся обработка приема может находиться в Lin_GetStatus. Принятые данные остаются целостными до тех пор, пока следующий фрейм не будет успешно принят или не изменится состояние канала SWS LINDriver с. 30. Конец фрейма распознается либо аппаратным контроллером, либо самим драйвером побайтово через прерывание UART SWS LINDriver Рис. 9.1 с. 56.

Диаграмма последовательности: прием фрейма на мастере, в зависимости от аппаратного обеспечения — с помощью контроллера или UART, завершаемый Lin_GetStatus. Источники: SWS LINDriver Рис. 9.1 с. 56 SWS LINInterface Рис. 9.4 с. 122 [SWS_Lin_00168]

Slave-каналы: обработка ответа, управляемая заголовком

Slave не знает расписания мастера. Он реагирует только на полученные заголовки SWS LINInterface с. 38. В состоянии LIN_CH_OPERATIONAL драйвер должен в любой момент быть готов принять заголовок, состоящий из Break, Sync и PID [SWS_Lin_00272]. Затем он вызывает LinIf_HeaderIndication. При этом он передает полученный PID и указатель на свой аппаратный или теневой буфер [SWS_Lin_00280]. Если аппаратное обеспечение не может распознавать недопустимые PID, драйвер передает PID дальше без проверки [SWS_Lin_00271].

LinIf определяет тип ответа в обратном вызове. Если она возвращает E_OK, драйвер обрабатывает PduPtr->Drc [SWS_Lin_00282]:

  • LIN_FRAMERESPONSE_TX: драйвер формирует ответ из Cs, Dl и SduPtr и отправляет его. Об успехе он сообщает через LinIf_TxConfirmation [SWS_Lin_00283] [SWS_Lin_00275].
  • LIN_FRAMERESPONSE_RX: драйвер настраивает прием с помощью Cs и Dl. Об успехе он сообщает через LinIf_RxIndication вместе с принятыми данными [SWS_Lin_00284] [SWS_Lin_00274].
  • E_NOT_OK или LIN_FRAMERESPONSE_IGNORE: драйвер игнорирует ответ и ничего не сообщает до следующего заголовка [SWS_Lin_00286] [SWS_Lin_00276].

Каждый соответствующий ответ должен быть завершен до следующей индикации заголовка, а именно индикацией Rx, подтверждением Tx или индикацией ошибки [SWS_Lin_00285]. При отправке LinIf инициирует запись данных непосредственно в буфер драйвера; копирование выполняет драйвер SWS LINInterface с. 121.

Диаграмма последовательности: после каждого заголовка Slave-драйвер ветвится на основе Drc на отправку, прием или игнорирование. Источники: SWS LINInterface Рис. 9.3 с. 121 SWS LINInterface с. 123 SWS LINInterface с. 134 [SWS_Lin_00282] [SWS_Lin_00286]

Команда перехода в спящий режим, пробуждение и обнаружение пробуждения

Только мастер может отправлять команду Go-to-sleep. Lin_GoToSleep является асинхронным и поручает это драйверу [SWS_Lin_00166]. В чисто Slave-конфигурациях этого сервиса нет [SWS_Lin_00288] SWS LINDriver с. 31. При этом канал переходит в LIN_CH_SLEEP_PENDING, даже если передача завершилась неудачно SWS LINDriver с. 43.

Lin_GoToSleepInternal, напротив, работает синхронно и без команды шины: сервис переводит канал в LIN_CH_SLEEP, активирует обнаружение пробуждения и опционально переключает аппаратное обеспечение в энергосберегающий режим [SWS_Lin_00167] SWS LINDriver с. 44. Каждый канал принимает запросы перехода в спящий режим независимо от других SWS LINDriver с. 31.

Диаграмма последовательности: переход Master-канала в спящий режим через LIN_CH_SLEEP_PENDING или, если он уже спит, напрямую через Lin_GoToSleepInternal. Источники: SWS LINInterface Рис. 9.15 с. 136 [SWS_Lin_00166] [SWS_Lin_00167] SWS LINInterface с. 56

Для пробуждения предусмотрено два сервиса:

  • Lin_Wakeup генерирует импульс пробуждения и переводит канал в LIN_CH_OPERATIONAL [SWS_Lin_00169].
  • Lin_WakeupInternal также переводит канал в LIN_CH_OPERATIONAL, но не отправляет импульс на шину [SWS_Lin_00256] [SWS_Lin_00262].

Особый случай касается пробуждения во время перехода в спящий режим: если пользователь запрашивает пробуждение, пока команда перехода в спящий режим еще ожидает выполнения, и Lin_GetStatus после этого уже сообщает о состоянии сна, LinIf снова вызывает Lin_Wakeup SWS LINInterface с. 56.

Если сконфигурирован LinChannelWakeupSupport, аппаратное обеспечение в состоянии сна отслеживает шину на наличие запросов пробуждения SWS LINDriver с. 31. Lin_CheckWakeup синхронно проверяет, присутствует ли на канале событие пробуждения [SWS_Lin_00160]. Об обнаруженном событии сервис немедленно сообщает в EcuM_SetWakeupEvent и LinIf_WakeupConfirmation SWS LINDriver с. 42 [SWS_Lin_00234]. Lin_CheckWakeup вызывается из LinIf_CheckWakeup. Последний опрашивает драйвер или драйвер трансивера в зависимости от источника пробуждения SWS LINInterface с. 112. Валидация пробуждения для LIN не требуется SWS EcuM с. 173.

Диаграмма последовательности: событие пробуждения на спящем канале проверяется через EcuM и LinIf вплоть до Lin_CheckWakeup и передается обратно в оба модуля. Источники: [SWS_Lin_00160] [SWS_Lin_00234] [SWS_Lin_00235] SWS EcuM Рис. 9.9 с. 175 SWS LINInterface с. 112

Конфигурация: тип узла, каналы и разделы

Параметр LinNodeType определяет, какие сервисы существуют. Lin_SendFrame, Lin_GoToSleep и Lin_GetStatus присутствуют только в том случае, если хотя бы один канал сконфигурирован как Master [SWS_Lin_00287] [SWS_Lin_00288] [SWS_Lin_00289]. Контейнер LinChannel для каждого канала содержит, помимо прочего, скорость передачи в бодах, ID канала, поддержку пробуждения, тип узла, опциональный источник пробуждения EcuM и тактовую опорную частоту SWS LINDriver с. 60. LinGeneral объединяет параметры уровня драйвера SWS LINDriver с. 57. Согласно схеме конфигурации, к ним относятся обнаружение ошибок разработки, API версий и длительность таймаута SWS LINDriver Рис. 10.1 с. 48.

В многораздельных системах действуют следующие правила:

  • Драйвер работает в каждом разделе как независимый экземпляр; вызов API действует только в собственном разделе [SWS_Lin_CONSTR_00270].
  • Если LinEcucPartitionRef ссылается на разделы, каждый канал должен ссылаться ровно на один из них [SWS_Lin_CONSTR_00291].
  • LinChannel и LinTrcvChannel канала должны использовать один и тот же раздел [SWS_Lin_CONSTR_00279].
  • Неподдерживаемые сопоставления разделов драйвер отклоняет [SWS_Lin_00269].

Информацию о версии модуля возвращает Lin_GetVersionInfo [SWS_Lin_00161].

Поведение при ошибке

Если обнаружение ошибок разработки активно, сервисы каналов проверяют инициализацию, номер канала и состояние. Для Lin_WakeupInternal это нормативно подтверждено [SWS_Lin_00258] [SWS_Lin_00259] [SWS_Lin_00260]:

  • LIN_E_UNINIT: вызов до Lin_Init.
  • LIN_E_INVALID_CHANNEL: недействительный или неактивный канал.
  • LIN_E_STATE_TRANSITION: канал не находится в LIN_CH_SLEEP.

Lin_Wakeup проверяет SWS LINDriver с. 45 таким же образом. Lin_GetVersionInfo сообщает об LIN_E_PARAM_POINTER, если передан указатель NULL SWS LINDriver с. 41. Классы ошибок соответствуют схеме общей спецификации BSW SWS LINDriver с. 32.

В качестве производственной ошибки драйвер сообщает об LIN_E_TIMEOUT. Если после обращения к регистрам управления ему приходится ожидать изменения состояния, это время ожидания защищается конфигурируемым таймаутом. Если он истекает, это указывает на аппаратную ошибку [SWS_Lin_00290]. Сообщение передается через Dem_SetEventStatus событию, на которое ссылается LinDemEventParameterRefs [SWS_Lin_00234] SWS LINDriver с. 65.

На Master-каналах ошибки шины отображаются в значении состояния [SWS_Lin_00233]:

  • LIN_TX_HEADER_ERROR: ошибка обратного считывания, ошибка четности или физическая ошибка шины в заголовке.
  • LIN_TX_ERROR: ошибочная передача ответа.
  • LIN_RX_ERROR: ошибка кадрирования, переполнения или контрольной суммы либо слишком короткий ответ.
  • LIN_RX_NO_RESPONSE: до сих пор не принято ни одного байта ответа.

Оценку берет на себя LinIf. Для фреймов Event-triggered LIN_RX_ERROR считается коллизией; затем LinIf переключается на расписание разрешения коллизий SWS LINInterface с. 129. LIN_RX_NO_RESPONSE в этом случае не является ошибкой связи SWS LINInterface с. 127.

Диаграмма деятельности: так LinIf оценивает возвращаемое значение Lin_GetStatus на Master-канале. Источники: [SWS_Lin_00233] SWS LINInterface с. 40 SWS LINInterface Рис. 9.4 с. 122 SWS LINInterface с. 129 SWS LINInterface с. 127

На Slave-каналах при ошибке отправки или приема ответа драйвер прерывает обработку фрейма и вызывает LinIf_LinErrorIndication [SWS_Lin_00277]. О недопустимых заголовках он сообщает с помощью LIN_ERR_HEADER [SWS_Lin_00281]. Lin_SlaveErrorType охватывает следующие типы ошибок: ошибки заголовка, стоп-бита и контрольной суммы, ошибки мониторинга переданных битов данных, а также отсутствующий и неполный ответ [SWS_Lin_91140] SWS LINInterface с. 109.

LIN Driver (Lin)

Управляет аппаратными контроллерами LIN на ECU.

Использование

Перечислимый тип Lin_StatusType определяет согласно [SWS_Lin_00233] рабочие состояния LIN-канала, а также состояния выполняющихся или завершенных операций с фреймами LIN. Тип предоставляется через заголовочный файл Lin_GeneralTypes.h и служит возвращаемым значением службы API Lin_GetStatus().

Значения состояний различают общеканальные состояния и состояния операций, связанных с фреймами:

  • Состояния канала: LIN_OPERATIONAL представляет собой нормальный режим работы, при котором канал готов к передаче следующего заголовка и данных предыдущего фрейма больше не имеется (например, после инициализации). LIN_CH_SLEEP указывает на состояние покоя (режим Sleep), в котором активировано обнаружение пробуждения узлами-ведомыми.
  • Состояния передачи: LIN_TX_OK подтверждает успешную передачу, в то время как LIN_TX_BUSY обозначает текущую выполняющуюся передачу (заголовка или ответа).
  • Состояния приема: LIN_RX_OK сообщает о безошибочном приеме ответа. LIN_RX_BUSY сигнализирует о текущем приеме, при котором был принят как минимум один байт данных, но еще не байт контрольной суммы. LIN_RX_NO_RESPONSE означает, что до настоящего момента байтов ответа принято не было.

Обработка ошибок

Если во время выполнения операции с фреймом возникает ошибка, это отображается через специфические значения ошибок согласно [SWS_Lin_00233]:

  • LIN_NOT_OK: указывает на то, что во время операции с фреймом возникла ошибка разработки или производственная ошибка.
  • LIN_TX_HEADER_ERROR: ошибочная передача заголовка, например, из-за расхождений между отправленными и прочитанными обратно данными, ошибки четности идентификатора или физических ошибок шины.
  • LIN_TX_ERROR: ошибочная передача ответа, вызванная несогласованностью данных (Mismatch) или физическими ошибками шины.
  • LIN_RX_ERROR: ошибочный прием ответа, вызванный ошибками кадрирования, ошибками переполнения, ошибками контрольной суммы или неполным ответом (Short Response).

Согласно [SWS_Lin_91140] тип определяет следующие константы ошибок:

  • LIN_ERR_HEADER: обозначает ошибку во время приема заголовка (Error in header) ([SWS_Lin_91140]).
  • LIN_ERR_RESP_STOPBIT: сигнализирует об ошибке кадрирования в ответе (Framing error in response) ([SWS_Lin_91140]).
  • LIN_ERR_RESP_CHKSUM: указывает на ошибку контрольной суммы ответа (Checksum error) ([SWS_Lin_91140]).
  • LIN_ERR_RESP_DATABIT: сообщает об ошибке мониторинга переданного бита данных в ответе (Monitoring error of transmitted data bit in response) ([SWS_Lin_91140]).
  • LIN_ERR_NO_RESP: указывает на отсутствие ожидаемого ответа (No response) ([SWS_Lin_91140]).
  • LIN_ERR_INC_RESP: возникает, если ответ был не полностью передан или принят (Incomplete response) ([SWS_Lin_91140]).

Благодаря этим значениям Lin_SlaveErrorType различает ошибки на этапе управления (заголовок) и проблемы в непосредственно области данных (ответ) ([SWS_Lin_91140]). Lin_GoToSleep функция

Служба инструктирует драйвер передать команду перехода в спящий режим по адресованному каналу LIN. Используется только для главных узлов LIN.

Lin_GoToSleepInternal функция

Устанавливает состояние канала на LIN_ CH_ SLEEP, включает обнаружение пробуждения и дополнительно переводит аппаратный блок LIN в режим пониженного энергопотребления (если поддерживается HW).

Std_ReturnType Lin_GoToSleepInternal (uint8 Channel);
Lin_SendFrame функция

При необходимости отправляет заголовок LIN и ответ LIN. Направление ответа кадра (ответ ведущего, ответ ведомого, связь между ведомыми) определяется Pdu Info Ptr. Используется только для главных узлов LIN.

Std_ReturnType Lin_SendFrame (uint8 Channel, const Lin_PduType* PduInfoPtr);

Std_ReturnType Lin_Wakeup (uint8 Channel);

Std_ReturnType Lin_WakeupInternal (uint8 Channel);

Типы

Lin_ConfigType тип

Это тип внешней структуры данных, содержащей общие данные инициализации для драйвера LIN и настроек SFR, влияющих на каналы LIN. Указатель на такую ​​структуру предоставляется процедуре инициализации драйвера LIN для настройки драйвера, LIN аппаратного блока и LIN аппаратных каналов.

Lin_FrameCsModelType тип

Этот тип используется для указания модели контрольной суммы, которая будет использоваться для кадра LIN.

Lin_FrameDlType тип

Этот тип используется для указания количества SDU байтов данных для копирования.

Lin_FramePidType тип

Представляет все действительные защищенные идентификаторы, используемые функцией Lin_ Send Frame().

Lin_FrameResponseType тип

Этот тип используется для указания, требуется ли процессору кадров передавать ответную часть кадра LIN.

Lin_PduType тип

Этот тип используется для предоставления PID, модели контрольной суммы, длины данных и указателя SDU от интерфейса LIN к драйверу LIN.

Lin_SlaveErrorType тип

Этот тип представляет типы ошибок ведомого устройства, которые обнаруживаются во время приема заголовка и передачи/приема ответа.

Lin_StatusType тип

LIN состояния операций для LIN канала или кадра, возвращаемые службой API Lin_ Get Status().
