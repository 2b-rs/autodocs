AUTOSAR Classic Memory Services

Memory Services управляют энергонезависимыми блоками данных (NvM), абстрактной флэш-памятью и технологиями EEPROM (MemIf, Fee, Ea) и обеспечивают согласованность данных и безопасность данных ECU циклами выключения.

Системная архитектура и роль кластера модулей

В Classic Platform службы Memory Services представляют собой путь, по которому программные компоненты и модули BSW энергонезависимо сохраняют данные. На верхнем уровне службы предоставляет только NVRAM Manager (NvM). Он управляет логическими блоками NVRAM. Такой блок обязательно состоит из NV-блока, RAM-блока и Administrative Block [SWS_NvM_00138]. Опционально добавляется ROM-блок с данными по умолчанию [SWS_NvM_00139]. Поддерживаются типы блоков NVM_BLOCK_NATIVE, NVM_BLOCK_REDUNDANT и NVM_BLOCK_DATASET [SWS_NvM_00137]. Схема логической структуры блоков демонстрирует это разбиение (SWS NVRAMManager с. 10).

Ниже NvM располагается Memory Hardware Abstraction с тремя модулями:

  • MemIf (Memory Abstraction Interface) передает каждый вызов в модуль абстракции, выбранный через DeviceIndex [SWS_MemIf_00039] [SWS_MemIf_00040]. В R20-11 DeviceIndex имеет тип uint8. В более новых фрагментах документации приводится uint16 (SWS MemIf с. 18); определяющим для R20-11 является Requirement.
  • Fee (Flash EEPROM Emulation) эмулирует блочно перезаписываемую память поверх драйвера флеш-памяти Fls [SWS_Fee_00084] [SWS_Fee_00104].
  • Ea (EEPROM Abstraction) отображает логические блоки на драйвер EEPROM Eep [SWS_Ea_00083].

Вместе MemIf, Fee и Ea предоставляют модулю NvM виртуальное линейное 32-битное адресное пространство [SWS_NvM_00051]. Базовый номер NV-блока находится в старших битах номера блока Fee/Ea [SWS_NvM_00123]. Избыточные блоки адресуются точно так же, как и блоки Dataset [SWS_NvM_00343].

Контекстная диаграмма: NvM является единственной точкой входа для пользователей. MemIf распределяет вызовы между Fee и Ea, они обращаются к Fls и Eep соответственно, а обратная связь передается вверх через callbacks. Источники: [SWS_MemIf_00047] [SWS_Fee_00098] [SWS_Ea_00099] [SWS_NvM_00745] SWS FEE с. 48. Интерпретация: Eep вызывает Ea_JobEndNotification аналогично Fls и Fee.

Взаимодействие и пути взаимодействия

Прием и обработка заданий. NvM_WriteBlock принимает параметры, помещает задание в Job-Queue и немедленно возвращает управление [SWS_NvM_00208] [SWS_NvM_00162]. После успешной постановки в очередь действует NVM_REQ_PENDING [SWS_NvM_00185]. При переполнении очереди функция возвращает E_NOT_OK [SWS_NvM_00184]. Непосредственная обработка происходит в NvM_MainFunction [SWS_NvM_00256]. Оттуда цепочка вызовов ведет через MemIf_Write к Fee_Write или Ea_Write. Ea вычисляет адрес записи по номеру блока и задает сконфигурированную длину блока (SWS EA с. 25).

Путь возврата статуса. Статус возвращается в NvM одним из двух путей:

  • Polling: NvM_MainFunction опрашивает статус задания через MemIf_GetJobResult [SWS_NvM_00346] [SWS_MemIf_00043].
  • Callback: Fee или Ea вызывают NvM_JobEndNotification либо NvM_JobErrorNotification. NvM предоставляет эти функции только в том случае, если режим опроса отключен [SWS_NvM_00440] [SWS_NvM_00441]. Сам Fee получает сигнал о завершении задания от драйвера флеш-памяти через Fee_JobEndNotification [SWS_Fee_00095].

NvM преобразует значения MemIf_JobResultType [SWS_MemIf_00065] при чтении следующим образом:

  • MEMIF_BLOCK_INVALID → результат NVM_REQ_NV_INVALIDATED [SWS_NvM_00341]
  • MEMIF_BLOCK_INCONSISTENT → сообщение DEM NVM_E_INTEGRITY_FAILED [SWS_NvM_00653]
  • MEMIF_JOB_FAILED → сообщение DEM NVM_E_REQ_FAILED [SWS_NvM_00654]

Передача буфера пользователям. Блоки с явной синхронизацией совместно используют единственный RAM-Mirror в NvM [SWS_NvM_00513]. Данные копируются через NvMWriteRamBlockToNvCallback и NvMReadRamBlockFromNvCallback [SWS_NvM_00515] [SWS_NvM_00516] (EXP NVDataHandling с. 14). После завершения задания NvM_MainFunction вызывает сконфигурированные callbacks [SWS_NvM_00347] [SWS_NvM_00113]. Опционально NvM дополнительно информирует BswM о состояниях блоков и мультиблоков [SWS_NvM_00746].

Диаграмма последовательности: запрос на запись принимается асинхронно, циклически обрабатывается, а статус возвращается через callback или опрос. Источники: [SWS_NvM_00208] [SWS_NvM_00256] [SWS_NvM_00346] [SWS_Fee_00095] SWS FEE с. 48

Синхронизация, реентерабельность и контексты задач

Контексты выполнения. NvM не использует объекты OS напрямую, а работает исключительно через планировщик BSW [SWS_NvM_00332]. Каждый модуль имеет собственную циклическую обработку: NvM_MainFunction [SWS_NvM_00464], Fee_MainFunction [SWS_Fee_00097] и Ea_MainFunction [SWS_Ea_00096]. Функции получения статуса и перенаправления нижнего уровня не являются реентерабельными, например MemIf_Read [SWS_MemIf_00039], Fee_GetStatus [SWS_Fee_00090] и Ea_GetStatus [SWS_Ea_00089]. Поэтому сериализацию берет на себя Job-Queue модуля NvM.

Уровень прерываний и задач. В фрагменте документации из R24-11 отмечается, что Fee_JobEndNotification должна быть вызываемой на уровне прерываний (SWS FEE с. 37). R20-11 определяет эту функцию как синхронную [SWS_Fee_00095], так же как и NvM_JobEndNotification [SWS_NvM_00462]. Вызовы callbacks пользователям, напротив, выполняются на уровне задач в контексте NvM_MainFunction [SWS_NvM_00347].

Приоритеты и согласованность.

  • При приоритетной обработке существует отдельная очередь для заданий Immediate (данные при аварии) [SWS_NvM_00378]. Эти задания прерывают выполняющиеся операции [SWS_NvM_00182].
  • Задания из NvM_WriteAll не прерываются [SWS_NvM_00567]. Запросы на чтение во время NvM_ReadAll ставятся в очередь и выполняются после этого [SWS_NvM_00568].
  • При неявной синхронизации приложению разрешается изменять RAM-блок только после завершения задания [SWS_NvM_00698]. При явной синхронизации оно может продолжать изменять его вплоть до callback копирования [SWS_NvM_00705].
  • В многораздельных системах только мастер NvM предоставляет NvM_ReadAll и NvM_WriteAll [SWS_NvM_00970] [SWS_NvM_00971].
  • Fee_Cancel и Ea_Cancel в R20-11 являются синхронными [SWS_Fee_00089] [SWS_Ea_00088]. В более поздних релизах они представлены как асинхронные (SWS EA с. 27).

Жизненные циклы и режимы работы

Инициализация. NvM_Init вызывается исключительно модулем BswM [SWS_NvM_00693] и еще не инициализирует блоки [SWS_NvM_00091]. Нижние уровни к этому моменту уже должны быть инициализированы [SWS_NvM_00157] [SWS_NvM_00193]. Fee_Init в R20-11 является асинхронной [SWS_Fee_00085]. Руководство по управлению режимами показывает типичную последовательность: Eep_Init, Fls_Init, NvM_Init, затем NvM_ReadAll (ModeManagementGuide с. 38).

Запуск с помощью NvM_ReadAll. NvM_ReadAll загружает блоки RAM. Функция только принимает запрос; обрабатывается он в NvM_MainFunction [SWS_NvM_00158] [SWS_NvM_00243]. В качестве первого шага сравнивается ID конфигурации [SWS_NvM_00073]. В случае NvMDynamicConfiguration == FALSE расхождение игнорируется [SWS_NvM_00248]. При необходимости NvM перед запуском переключает устройства памяти через MemIf_SetMode в режим Fast-Mode, а затем обратно в режим Slow-Mode [SWS_NvM_00426] [SWS_NvM_00427] [SWS_MemIf_00066]. О принятии и завершении мультиблочного задания NvM сообщает в BswM [SWS_NvM_00888] [SWS_NvM_00889]. Правило которого затем запускает остальную инициализацию.

Завершение работы с помощью NvM_WriteAll. Завершение работы инициируется модулем BswM с помощью NvM_WriteAll [SWS_NvM_00092]. Записываются только блоки с постоянным RAM-блоком или явной синхронизацией [SWS_NvM_00252]. С помощью NvM_SetRamBlockStatus это можно ограничить фактически измененными блоками (EXP NVDataHandling с. 18). NvM_CancelWriteAll предназначена исключительно для BswM [SWS_NvM_00703]. После завершения NvM_WriteAll BswM вызывает EcuM_GoDown (ModeManagementGuide с. 37).

Диаграмма последовательности: BswM управляет запуском и завершением работы. Обратные сообщения NvM по мультиблочным заданиям инициируют соответствующую следующую фазу. Источники: [SWS_NvM_00693] [SWS_NvM_00460] [SWS_NvM_00461] [SWS_NvM_00888] SWS NVRAMManager с. 163

Рабочие состояния Fee и Ea. Оба модуля сообщают свое состояние в виде MemIf_StatusType со значениями MEMIF_UNINIT, MEMIF_IDLE, MEMIF_BUSY и MEMIF_BUSY_INTERNAL [SWS_MemIf_00064]. MEMIF_BUSY_INTERNAL обозначает внутренние служебные операции, такие как сборка мусора (SWS EA с. 28). Ea_Write принимает задания даже в этом состоянии.

Диаграмма состояний: Fee и Ea переключаются между состоянием простоя, обработкой заданий и внутренними служебными операциями. Источники: [SWS_Fee_00090] [SWS_Ea_00089] SWS FEE с. 29 SWS EA с. 25. Интерпретация: после принятия задания из MEMIF_BUSY_INTERNAL модуль, вероятно, сообщает MEMIF_BUSY.

Обработка ошибок, трассировка DET и деградация

Обнаружение по уровням. Ошибки обнаруживаются поэтапно на каждом уровне:

  1. Драйвер (Fls или Eep) обнаруживает ошибку.
  2. Fee или Ea обрабатывают ее специфичным для реализации способом.
  3. Fee или Ea передают информацию дальше: через результат задания MEMIF_JOB_FAILED или через NvM_JobErrorNotification (ErrorDescription с. 40, ErrorDescription с. 48).

Восстановлением управляет NvM (ErrorDescription с. 43).

Восстановление модулем NvM.

  • Запись: NvM повторяет операцию записи до сконфигурированного максимального числа раз [SWS_NvM_00168] [SWS_NvM_00213] [SWS_NvM_00296].
  • Чтение избыточных блоков: NvM дополнительно считывает второй NV-блок [SWS_NvM_00199] [SWS_NvM_00288].
  • Последний резервный уровень: NvM загружает данные по умолчанию из ROM-блока [SWS_NvM_00389] [SWS_NvM_00171]. При этом NV-блок остается без изменений [SWS_NvM_00172]. Если использовались данные ROM, результат равен NVM_REQ_RESTORED_FROM_ROM [SWS_NvM_00470].
  • Потеря избыточности: NvM сообщает NVM_E_LOSS_OF_REDUNDANCY в DEM [SWS_NvM_00546] (ErrorDescription с. 62, EXP ErrorDescription с. 76).

Сообщения для DEM и пользователей. В качестве производственных ошибок NvM сообщает в DEM следующее:

  • NVM_E_INTEGRITY_FAILED [SWS_NvM_00864]
  • NVM_E_REQ_FAILED [SWS_NvM_00865]
  • NVM_E_WRONG_BLOCK_ID [SWS_NvM_00866]
  • NVM_E_VERIFY_FAILED [SWS_NvM_00867]
  • NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00868]

Пользователи получают результат в зависимости от конфигурации посредством опроса с помощью NvM_GetErrorStatus [SWS_NvM_00451] либо через одиночные и мультиблочные callbacks [SWS_NvM_00113] [SWS_NvM_00260].

Трассировка DET и деградация. Ошибки разработки модули передают в DET, например:

  • NVM_E_UNINIT [SWS_NvM_00614]
  • FEE_E_UNINIT [SWS_Fee_00010]
  • EA_E_UNINIT [SWS_Ea_91001]
  • MEMIF_E_PARAM_DEVICE [SWS_MemIf_00006]

Если данные по умолчанию отсутствуют, RAM-блок после неудачного чтения остается недействительным [SWS_NvM_00658] [SWS_NvM_00680]. В этом случае приложение должно самостоятельно предоставить действительные данные перед следующей попыткой записи [SWS_NvM_00696].

Сгенерированное ИИ руководство на основе содержащихся в полезной нагрузке Requirements (R20-11) и фрагментов документации. Фрагменты документации из других релизов отмечены соответствующим образом; в случае расхождений действует R20-11-Requirement.
