AUTOSAR Classic Memory Services

Memory Services управляют энергонезависимыми блоками данных (NvM), абстрактной флэш-памятью и технологиями EEPROM (MemIf, Fee, Ea) и обеспечивают согласованность данных и безопасность данных ECU циклами выключения.

Асинхронные операции чтения и записи обрабатываются через циклические MainFunctions и выполняются пакетно во время запуска блока управления (NvM_ReadAll), а также при завершении работы (NvM_WriteAll) ModemanagementGuide с. 54. При аппаратных сбоях задействуются многоуровневые механизмы повторов, избыточности и восстановления из ROM с автоматическим формированием отчетов в DEM ([SWS_NvM_00470]).

Кластер 'Memory Services' обеспечивает персистентное хранение и управление энергонезависимыми данными в стеке AUTOSAR Classic BSW. Он включает в себя NVRAM Manager ([SWS_NvM_00447]) на сервисном уровне, а также Memory Abstraction Interface ([SWS_MemIf_00039]) с модулями Flash EEPROM Emulation ([SWS_Fee_00085]) и EEPROM Abstraction ([SWS_Ea_00083]) на уровне аппаратной абстракции AUTOSAR SWS NVRAMManager с. 10.

Обмен данными происходит через синхронные управляющие API и асинхронные задания на запись и чтение. Данные передаются либо неявно через постоянные блоки RAM, либо явно через модульные зеркала RAM ([SWS_NvM_00455], [SWS_NvM_00514]) NVDataHandling с. 12. Циклическая обработка поставленных в очередь заданий выполняется через периодически вызываемые основные функции BSW (NvM_MainFunction, Fee_MainFunction), в то время как MemIf делегирует вызовы нижележащим драйверам без сохранения состояния ([SWS_MemIf_00040]) AUTOSAR CP SWS FlashEEPROMEmulation с. 42.

В рабочем цикле BswM координирует многоблочные действия: при запуске системы NvM_ReadAll считывает персистентные данные из энергонезависимой памяти в RAM ([SWS_NvM_00460]), в то время как при завершении работы NvM_WriteAll сохраняет измененные данные ([SWS_NvM_00461]) ModemanagementGuide с. 54. Ошибочные обращения на чтение или запись перехватываются с помощью повторных попыток, а также избыточных копий или резервных значений из ROM; о постоянных сбоях система сообщает в DEM ([SWS_NvM_00470], [SWS_NvM_00279]) ErrorDescription с. 62.

Системная архитектура & роль кластера модулей

Модульный кластер служб памяти (Memory Services) платформы AUTOSAR Classic Platform обеспечивает стандартизированное, аппаратно-независимое управление и персистентность данных приложений и базового программного обеспечения в энергонезависимой памяти. Кластер делится по вертикали на два уровня архитектуры базового ПО AUTOSAR: NVRAM Manager ([SWS_NvM_00447]) на сервисном уровне (Services Layer), а также Memory Abstraction Interface ([SWS_MemIf_00039]) с расположенными ниже модулями абстракции Flash EEPROM Emulation ([SWS_Fee_00085]) и EEPROM Abstraction ([SWS_Ea_00083]) на уровне аппаратной абстракции памяти (Memory Hardware Abstraction Layer) AUTOSAR SWS NVRAMManager с. 10.

NVRAM Manager (NvM) образует центральную точку входа для программных компонентов (SW-C) и BSW-модулей, таких как модуль Diagnostic Event Manager (Dem) SWS DiagnosticEventManager с. 238. Он управляет логическими блоками памяти, которые состоят из NV-блоков в энергонезависимой памяти, RAM-блоков в энергозависимой памяти и опциональных ROM-блоков для данных инициализации ([SWS_NvM_00137], [SWS_NvM_00128]). В зависимости от требований поддерживаются типы управления блоками native (NVM_BLOCK_NATIVE), redundant (NVM_BLOCK_REDUNDANT) или dataset (NVM_BLOCK_DATASET) AUTOSAR CP RS MemoryServices с. 10.

Модули Fee и Ea инкапсулируют особенности соответствующих физических носителей данных (Flash или EEPROM) и сопоставляют логические номера блоков и смещения адресов с линейными адресными пространствами соответствующих MCAL-драйверов (Fls и Eep соответственно) ([SWS_Fee_00087], [SWS_Ea_00086]) AUTOSAR SWS EEPROMAbstraction с. 23. При этом модуль MemIf служит исключительно уровнем маршрутизации, который на основе параметра DeviceIndex перенаправляет обращения к целевому модулю без содержания собственных буферных структур ([SWS_MemIf_00040]).

Архитектурная диаграмма: послойная структура и взаимосвязи модулей в кластере Memory Services. Источники: [SWS_MemIf_00039], AUTOSAR SWS NVRAMManager с. 10

Взаимодействие и пути взаимодействия между модулями

Взаимодействие между модулями происходит по строго стандартизированным синхронным и асинхронным путям. Если пользователь инициирует операцию записи через NvM_WriteBlock, запрос сначала регистрируется в административном блоке NvM ([SWS_NvM_00455]). При синхронном вызове перенаправление в MemIf происходит через MemIf_Write ([SWS_MemIf_00040]), который передает вызов в Fee_Write или Ea_Write ([SWS_Fee_00088], [SWS_Ea_00087]) AUTOSAR SWS NVRAMManager с. 160.

В отношении хранения данных и синхронизации между приложением и NVRAM Manager существуют две основные концепции: неявная синхронизация через постоянные блоки RAM (NvMRamBlockDataAddress) и явная синхронизация через буферы на основе зеркал (NvMBlockUseSyncMechanism) NVDataHandling с. 12. При явной синхронизации NvM копирует полезные данные через сконфигурированные callback-процедуры NvMWriteRamBlockToNvCallback или NvMReadRamBlockFromNvCallback между RAM приложения и внутренним зеркалом RAM ([SWS_NvM_00514], [SWS_NvM_00515]) EXP NVDataHandling с. 30.

При использовании блоков типа Dataset (NVM_BLOCK_DATASET) вызывающая сторона предварительно выбирает желаемый индекс набора данных через NvM_SetDataIndex ([SWS_NvM_00448]). После этого модули абстракции вычисляют точное смещение адреса для MCAL-драйвера на основе логического номера блока и индекса ([SWS_NvM_00123]) AUTOSAR SWS Flash EEPROM Emulation с. 21. Запросы на отмену передаются через MemIf_Cancel напрямую в подмодули Fee_Cancel или Ea_Cancel ([SWS_MemIf_00041], [SWS_Fee_00089]).

Диаграмма последовательности: асинхронное задание на запись с callback-оповещением и поллингом. Источники: [SWS_NvM_00455], AUTOSAR SWS NVRAMManager с. 160

Синхронизация, реентерабельность и контексты задач

Большинство API управления и статуса кластера, включая NvM_GetErrorStatus ([SWS_NvM_00451]), NvM_SetBlockProtection ([SWS_NvM_00450]) и MemIf_GetVersionInfo ([SWS_MemIf_00045]), реализованы синхронными и могут обрабатываться непосредственно в контексте задачи вызывающей стороны AUTOSAR SWS NVRAMManager с. 157. Напротив, функции передачи данных (NvM_ReadBlock, NvM_WriteBlock, Ea_Write) спроектированы асинхронными и нереентерабельными ([SWS_MemIf_00040], [SWS_Ea_00087]).

Циклическое продвижение текущих заданий возложено на основные функции NvM_MainFunction и Fee_MainFunction, периодически вызываемые Schedule Manager (SchM) или задачей BSW AUTOSAR CP SWS FlashEEPROMEmulation с. 42. При асинхронных сообщениях от MCAL-драйвера уведомление Fee_JobEndNotification или Fee_JobErrorNotification может происходить непосредственно на уровне прерываний ([SWS_Fee_00095]). Оно устанавливает статус в MEMIF_JOB_OK или вызывает сконфигурированные процедуры оповещения ([SWS_Fee_00142], [SWS_Fee_00194]) SWS FlashEEPROMEmulation с. 37.

Интерпретация: чтобы исключить состояния гонки (race conditions) между вызывающими сторонами API на уровне задач и пошаговой дальнейшей обработкой в MainFunctions, внутренние очереди и административные атрибуты, вероятно, защищены эксклюзивными областями, в то время как MemIf действует как уровень перенаправления без сохранения состояния AUTOSAR SWS NVRAMManager с. 160.

Типичные жизненные циклы и режимы работы

Жизненный цикл кластера тесно оркеструется Basic Software Mode Manager (BswM) и ECU State Manager (EcuM). Во время запуска блока управления (Startup Phase) вслед за драйверами сначала синхронно инициализируются модули абстракции через Fee_Init и Ea_Init соответственно ([SWS_Fee_00085], [SWS_Ea_00083]), а затем NVRAM Manager через NvM_Init ([SWS_NvM_00447]) AUTOSAR SWS NVRAMManager с. 156.

Вслед за инициализацией BswM запускает многоблочную операцию чтения NvM_ReadAll, чтобы восстановить из энергонезависимой памяти все блоки RAM, помеченные как персистентные ([SWS_NvM_00460]) ModemanagementGuide с. 54. О ходе выполнения и конечном результате NvM сообщает обратно в BswM через callback-функцию BswM_NvM_CurrentJobMode ([SWS_NvM_00745], [SWS_NvM_00888]). Состояния отдельных блоков сигнализируются через BswM_NvM_CurrentBlockMode ([SWS_NvM_00746], [SWS_NvM_00890]) ModemanagementGuide с. 28.

В фазе завершения работы (Shutdown) система инициирует через NvM_WriteAll персистентную обратную запись всех измененных блоков RAM в NV-память ([SWS_NvM_00461]). Чтобы оптимизировать количество циклов записи во Flash, с помощью NvM_SetRamBlockStatus можно целенаправленно отметить, был ли блок модифицирован ([SWS_NvM_00453]) EXP NVDataHandling с. 18. Текущий процесс записи при преждевременных событиях пробуждения можно отменить через NvM_CancelWriteAll ([SWS_NvM_00238]) AUTOSAR SWS NVRAMManager с. 161.

Обработка ошибок, трассировка DET и деградация

Кластер обладает многоуровневой концепцией обнаружения ошибок и деградации. Ошибки, возникающие на уровне драйверов и абстракции, опрашиваются через возвращаемый статус MEMIF_JOB_FAILED с помощью MemIf_GetJobResult или передаются через NvM_JobErrorNotification ([SWS_Fee_00091], [SWS_Ea_00095]) ErrorDescription с. 49.

При возникновении ошибок чтения NvM обращается к сконфигурированным механизмам восстановления: сначала предпринимаются повторные попытки (Read Retries) ([SWS_NvM_00390]). Если они завершаются неудачно, для избыточных блоков (NVM_BLOCK_REDUNDANT) считывается избыточная копия ([SWS_NvM_00171], [SWS_NvM_00531]). Если при этом обнаруживается потеря избыточности, NvM устанавливает результат задания в NVM_REQ_REDUNDANCY_FAILED и сообщает о производственной ошибке NVM_E_LOSS_OF_REDUNDANCY в DEM ([SWS_NvM_00470], [SWS_NvM_00546]) ErrorDescription с. 62.

Если восстановление с помощью стандартных значений ROM проходит успешно, NvM сообщает результат NVM_REQ_RESTORED_FROM_ROM ([SWS_NvM_00470]). Если все меры восстановления терпят неудачу, в DEM передается NVM_E_REQ_FAILED ([SWS_NvM_00279], [SWS_NvM_00288]), а результат опроса устанавливается в NVM_REQ_NOT_OK ([SWS_NvM_00451]). При ошибках записи NvM управляет повторными попытками записи (NvMMaxNumOfWriteRetries), прежде чем запрос будет отменен ([SWS_NvM_00168], [SWS_NvM_00213]) ErrorDescription с. 56.

В этом руководстве обобщены ключевая архитектура, взаимодействие модулей и механизмы обработки ошибок кластера Memory Services. Все сведения основаны на нормативных спецификациях AUTOSAR Classic Platform.
