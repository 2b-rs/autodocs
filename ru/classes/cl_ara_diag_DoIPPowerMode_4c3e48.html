Предоставляет модулю Diagnostic Management текущий режим энергопотребления DoIP транспортного средства через интерфейс обратного вызова.

Интерфейсный класс ara::diag::DoIPPowerMode позволяет приложениям предоставлять текущий режим энергопотребления DoIP модулю Diagnostic Management через функцию обратного вызова GetDoIPPowerMode() [SWS_DM_00734]. После инстанцирования обработчик должен быть активирован с помощью Offer() и перед уничтожением повторно дерегистрирован через StopOffer() [SWS_DM_00735], [SWS_DM_00736]. Будучи одиночным экземпляром, класс не поддерживает ни копирование, ни перемещение [SWS_DM_01645].

Контекст

Абстрактный класс ara::diag::DoIPPowerMode определяет интерфейс для предоставления текущего режима энергопотребления DoIP модулю Diagnostic Management (DM). В архитектурах транспортных средств, использующих диагностику по протоколу Internet Protocol (DoIP), коммуникационный протокол должен быть проинформирован о рабочем состоянии сети транспортного средства или электропитании. Прикладное программное обеспечение порождает конкретный класс обработчика от ara::diag::DoIPPowerMode и реализует опрос режима энергопотребления [SWS_DM_00734]. Партнерами по взаимодействию являются предоставляющее диагностическое приложение, предлагающее интерфейс, а также среда выполнения DM, которая делегирует этому обработчику входящие запросы [SWS_DM_00735].

Жизненный цикл

Экземпляры ara::diag::DoIPPowerMode создаются внутри приложения и идентифицируются через прототип порта, на который ссылается ara::core::InstanceSpecifier [SWS_DM_00732]. При вызове конструктора с помощью аргумента ConcurrencyType определяется, должен ли метод обратного вызова GetDoIPPowerMode() выполняться потокобезопасно (kConcurrent) или непотокобезопасно (kNotConcurrent) [SWS_DM_00732]. Сам конструктор реализован потокобезопасным [SWS_DM_00732].

Согласно спецификации экземпляр не может быть скопирован или перемещен: как конструктор копирования [SWS_DM_01645], так и конструктор перемещения [SWS_DM_01646], а также соответствующие операторы присваивания [SWS_DM_01643], [SWS_DM_01644] явно удалены (=delete).

После инстанцирования обработчик должен быть активирован с помощью Offer(), чтобы DM мог перенаправлять запросы [SWS_DM_00735]. Чтобы прекратить пересылку запросов, вызывается StopOffer() [SWS_DM_00736]. Виртуальный деструктор ~DoIPPowerMode() [SWS_DM_00733], а также Offer() и StopOffer() специфицированы как непотокобезопасные. Предположительно, перед вызовом деструктора всегда следует выполнять StopOffer(), чтобы корректно завершить ожидающие взаимодействия с DM.

Путь использования

Типичное использование ara::diag::DoIPPowerMode следует фиксированной последовательности из инициализации, регистрации сервиса, циклического или основанного на событиях опроса режима и дерегистрации:

  1. Приложение инстанцирует свой производный класс с подходящим InstanceSpecifier и желаемым ConcurrencyType [SWS_DM_00732].
  2. Приложение активно регистрирует обработчик в модуле Diagnostic Management с помощью Offer() [SWS_DM_00735].
  3. Как только протоколу DoIP требуется состояние, DM вызывает чисто виртуальную функцию GetDoIPPowerMode() [SWS_DM_00734]. Реализация возвращает ara::core::Future<PowerModeType>, разрешаемый асинхронно [SWS_DM_00734].
  4. При завершении работы приложение вызывает StopOffer(), чтобы больше не принимать запросы [SWS_DM_00736].
  5. Экземпляр освобождается через деструктор [SWS_DM_00733].

Диаграмма последовательности: типичный процесс регистрации, асинхронного опроса состояния и отмены регистрации для DoIPPowerMode. Источники: [SWS_DM_00732], [SWS_DM_00734], [SWS_DM_00735], [SWS_DM_00736], AUTOSAR_AP_SWS_Diagnostics §8.2 «DoIP Power Mode».

Сценарии ошибок

При вызове конструктора могут возникать документированные нарушения модели и сопоставления [SWS_DM_00732]:

  • InstanceSpecifierMappingIntegrityViolation: идентификатор не может быть разрешен в контексте исполняемого файла или не ссылается на элемент PortPrototype [SWS_DM_00732].
  • PortInterfaceMappingViolation: целевой PortPrototype не типизирован с помощью DiagnosticDoIPPowerModeInterface [SWS_DM_00732].
  • ProcessMappingViolation: ссылка на экземпляр существует, однако подходящий смоделированный процесс для среды выполнения отсутствует [SWS_DM_00732].
  • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже использовался для другого экземпляра в рамках того же процесса [SWS_DM_00732].

Если Offer() вызывается, когда сервис уже активно предлагается, метод возвращает код ошибки DiagOfferErrc::kAlreadyOffered через ara::core::Result [SWS_DM_00735]. Напротив, метод GetDoIPPowerMode() не определяет стандартизированных кодов ошибок [SWS_DM_00734].

Настоящее руководство основано на спецификации AUTOSAR для Adaptive Platform (Release R25-11). Все сведения и коды ошибок опираются на указанные требования SWS.

                  Синхронный метод Offer класса ara::diag::DoIPPowerMode служит для того, чтобы приложение Adaptive Application могло зарегистрировать и разрешить сервис для DoIP Power Mode в Diagnostic Management (DM) [SWS_DM_00735]. Вызов переводит DM в состояние, позволяющее пересылать входящие сообщения запросов этому обработчику [SWS_DM_00735]. Функция не ожидает входных параметров, не генерирует исключений (noexcept) и возвращает ara::core::Result<void> в качестве возвращаемого значения [SWS_DM_00735].
                  

                  Пока Offer ещё не вызван предоставляющим приложением, DM отвечает на клиентские запросы информации о DoIP Power Mode значением состояния 0 («Not ready») согласно ISO 13400-2 [SWS_DM_01525]. Если обработчик зарегистрирован и DM требует актуальный Power Mode для ответа на сообщения DoIP, он запрашивает его через ara::diag::DoIPPowerMode::GetDoIPPowerMode [SWS_DM_00814].
                  

                  В случае ошибки объект Result содержит соответствующий код ошибки. Если метод на соответствующем экземпляре уже ранее успешно вызывался, повторный вызов завершается неудачей и возвращает DiagOfferErrc::kAlreadyOffered с семантикой отката [SWS_DM_00735].
                  

                  С точки зрения параллелизма функция специфицирована как непотокобезопасная (not thread-safe) [SWS_DM_00735]. Поэтому параллельные вызовы на одном и том же экземпляре должны синхронизироваться вызывающей стороной. Функция обеспечивает полную безопасность исключений (exception safe) [SWS_DM_00735].
