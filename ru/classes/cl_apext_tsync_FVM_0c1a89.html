Предоставляет значения актуальности для аутентификации отправленных и принятых сообщений синхронизации времени.

Класс apext::tsync::FVM служит интерфейсом модуля для предоставления значений актуальности для защищенных сообщений синхронизации времени [SWS_TS_14199]. Перед эксплуатационным использованием экземпляр необходимо инициализировать, после чего можно получать значения актуальности для отправки, а также для верификации принятых сообщений [SWS_TS_14200]. При приеме усеченные значения актуальности передаются вместе со счетчиком неудачных попыток для восстановления полного значения с целью проверки аутентификатора. Все методы интерфейса специфицированы как безопасные относительно исключений и потокобезопасные.

Контекст

Класс apext::tsync::FVM представляет собой интерфейс для управления значениями актуальности (Freshness Value Management) внутри модуля tsync AUTOSAR Adaptive Platform. Его основная ответственность заключается в предоставлении актуальных значений актуальности (Freshness Values) для службы синхронизации времени ara::tsync, чтобы сообщения могли быть криптографически защищены от атак повторного воспроизведения и спуфинга [SWS_TS_14198], [SWS_TS_14199].

В качестве центрального партнера по взаимодействию выступает функциональность TimeSync, которая вызывает FVM для запроса контейнеров значений актуальности (apext::tsync::FVContainer) как для исходящих, так и для принятых защищенных сообщений [SWS_TS_14198], [SWS_TS_14199]. Объявление класса подключается через файл заголовка #include "apext/tsync/fvm.h". Все специфицированные методы объявлены как потокобезопасные и безопасные относительно исключений (noexcept), благодаря чему вызовы могут происходить параллельно из различных контекстов выполнения синхронизации времени [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200].

Жизненный цикл

Функциональный жизненный цикл экземпляра FVM подразделяется на явную фазу инициализации и последующую фазу эксплуатационной работы:

  • Инициализация: перед использованием функций запроса необходимо вызвать метод Initialize() [SWS_TS_14200]. При успешном завершении он возвращает пустой ara::core::Result<void>. Если инициализация не удалась, он возвращает код ошибки TsyncFvmErrc::kFVInitializeFailed с семантикой отката [SWS_TS_14200].
  • Рабочее состояние: успешная инициализация, вероятно, является необходимым условием для того, чтобы последующие запросы значений актуальности возвращали корректные результаты. После успешной инициализации экземпляр остается в рабочем состоянии и отвечает на запросы для сконфигурированных ID значений актуальности.
  • Параллельный доступ: поскольку все методы помечены как thread-safe, доступ к значениям актуальности для отправки и приема может осуществляться параллельно без внешних механизмов блокировки [SWS_TS_14198], [SWS_TS_14199].

Путь использования

Типичный порядок вызовов со стороны компонента TimeSync включает инициализацию, а также непрерывное определение значений актуальности для трактов отправки и приема:

  1. Инициализация службы: TimeSync выполняет при запуске метод Initialize() и проверяет возвращенный ara::core::Result на отсутствие ошибок [SWS_TS_14200].
  2. Отправка защищенных сообщений: перед отправкой сообщения TimeSync вызывает GetTxFreshness() с соответствующим FreshnessValueID [SWS_TS_14199]. Полученный объект FVContainer предоставляет значение актуальности, которое используется для вычисления аутентификатора [SWS_TS_14199].
  3. Прием защищенных сообщений: при поступлении сообщения TimeSync вызывает GetRxFreshness() и передает FreshnessValueID, содержащееся в сообщении усеченное значение TruncatedFreshnessValue, а также количество предыдущих попыток аутентификации AuthVerifyAttempts [SWS_TS_14198]. FVM определяет на их основе полное значение актуальности для верификации аутентификатора [SWS_TS_14198].

Диаграмма последовательности: типичная последовательность инициализации и запроса значений актуальности для отправки и приема со стороны TimeSync. Источники: [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200]

Сценарии ошибок

Все интерфейсные методы сигнализируют об ошибках через ara::core::Result и специфицированы с noexcept [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200]. Актуальны следующие состояния ошибок и предусловия:

  • Неудачная инициализация (TsyncFvmErrc::kFVInitializeFailed): возникает, если FVM не может быть инициализирован [SWS_TS_14200]. Благодаря семантике отката система остается в неинициализированном, определенном исходном состоянии.
  • Недоступное значение актуальности (TsyncFvmErrc::kFVNotAvailable): возвращается методом GetTxFreshness() или GetRxFreshness(), если для запрошенного ID значение актуальности отсутствует [SWS_TS_14198], [SWS_TS_14199]. В случае ошибки операции не изменяют свое состояние (семантика отката).
  • Повторные попытки верификации при приеме: параметр AuthVerifyAttempts начинается с 0 и инкрементируется при каждой неудачной попытке аутентификации [SWS_TS_14198]. Инкрементирование, вероятно, служит для того, чтобы FVM постепенно корректировал внутреннее окно приемлемости для компенсации небольших временных сдвигов значений актуальности.

Настоящее руководство основано исключительно на требованиях спецификации AUTOSAR R25-11 для модуля tsync и создано автоматически.

Used by TimeSync to obtain the current freshness value for received messages.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 37f7da507510 Provenance

Синхронный интерфейс GetRxFreshness класса apext::tsync::FVM (определенный в apext/tsync/fvm.h) служит TimeSync для определения актуального значения свежести входящих сообщений [SWS_TS_14198].

Вызов требует трех параметров [SWS_TS_14198]:

  • FreshnessValueID: числовой идентификатор значения свежести (std::uint16_t) [SWS_TS_14198].
  • TruncatedFreshnessValue: контейнер (apext::tsync::FVContainer) с усеченными значениями свежести из принятого защищенного сообщения [SWS_TS_14198].
  • AuthVerifyAttempts: счетчик попыток аутентификации для этого сообщения с момента его последнего приема; значение начинается с 0 для первой попытки и инкрементируется при каждой неудавшейся попытке верификации [SWS_TS_14198].

Функция возвращает ara::core::Result<FVContainer> [SWS_TS_14198]. В случае успеха он содержит apext::tsync::FVContainer с полным значением свежести, которое требуется для последующего вычисления аутентификатора компонентом TimeSync [SWS_TS_14198]. Если значение свежести недоступно, возвращается исправимая ошибка с кодом ошибки TsyncFvmErrc::kFVNotAvailable и семантикой отката [SWS_TS_14198].

Сигнатура объявлена с noexcept; реализация специфицирована как исключениебезопасная (exception safe) и потокобезопасная (thread-safe) [SWS_TS_14198].

          Использование
          

          Функция Initialize в пространстве имен apext::tsync::FVM служит для инициализации Freshness Value Manager (FVM) согласно [SWS_TS_14200]. Интерфейс предоставляется через заголовочный файл apext/tsync/fvm.h и имеет сигнатуру ara::core::Result<void> Initialize() noexcept;. Вызов выполняется синхронно и без входных параметров. В случае успеха предоставляется ara::core::Result с пустым возвращаемым типом void.
          

          Обработка ошибок
          

          Если при выполнении возникает проблема, функция возвращает специфический код ошибки TsyncFvmErrc::kFVInitializeFailed внутри объекта результата [SWS_TS_14200]. Спецификация при этом предусматривает семантику отката, так что в случае ошибки несогласованных промежуточных состояний оставаться не должно.
          

          Параллелизм и ограничения
          

          Для контекста вызова функция явно классифицирована как thread-safe, а также как exception safe [SWS_TS_14200]. Благодаря идентификатору noexcept гарантированно никакие C++-исключения не передаются наружу. Интерпретация: вероятно, этот шаг инициализации должен быть успешно пройден до того, как могут быть вызваны другие функциональные методы компонента FVM.
