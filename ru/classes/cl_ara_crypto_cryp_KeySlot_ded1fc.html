Управляет слотом хранения для криптографических ключей и обеспечивает запросы метаданных, а также обратные вызовы при изменении.

Интерфейс инкапсулирует постоянный или энергозависимый слот хранения для криптографических ключей и позволяет запрашивать метаданные ключа, а также ответственный CryptoProvider [SWS_CRYPT_30403]. Приложения могут отслеживать изменения содержимого с помощью регистрируемого обратного вызова наблюдателя [SWS_CRYPT_30404]. При пустом слоте обращения к типу ключа или его алгоритму завершаются с кодом ошибки ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_50055]. Поскольку копирование и перемещение запрещены, доступ осуществляется потокобезопасно через Shared-Pointer.

Контекст

Интерфейс ara::crypto::cryp::KeySlot представляет собой выделенный слот хранения для криптографических ключей в рамках AUTOSAR Adaptive Platform. Являясь инкапсуляцией логического слота ключа, он управляет метаданными, информацией о типе и сопоставлением поддерживаемых алгоритмов для размещенного в нем ключа. Экземпляр обычно взаимодействует с тремя сторонами: использующим программным обеспечением, соответствующим cryp::CryptoProvider, на который через [SWS_CRYPT_30403] может быть получена разделяемая ссылка, а также прикладным обратным вызовом для отслеживания содержимого согласно [SWS_CRYPT_30404].

Контекстная диаграмма: партнеры по взаимодействию интерфейса KeySlot. Источники: [SWS_CRYPT_30403], [SWS_CRYPT_30404]

Жизненный цикл

KeySlot жестко привязан к представляемому им хранилищу ключей. Соответственно интерфейс предотвращает дублирование и перемещение экземпляра: как конструктор копирования [SWS_CRYPT_50149], так и конструктор перемещения [SWS_CRYPT_50150] явно удалены. То же самое относится к оператору присваивания копированием [SWS_CRYPT_50147] и оператору присваивания перемещением [SWS_CRYPT_50148].

Для управления отношениями владения и ссылок класс определяет псевдоним типа интеллектуального указателя Sptr как std::shared_ptr<KeySlot> [SWS_CRYPT_50151]. Освобождение осуществляется через виртуальный стандартный деструктор [SWS_CRYPT_50146]. Интерпретация: поскольку интерфейс не определяет открытых конструкторов, конкретные экземпляры, вероятно, создаются ответственным CryptoProvider и предоставляются как Sptr. Все предоставляемые методы объявлены потокобезопасными, благодаря чему одновременный доступ для чтения и мониторинга из нескольких контекстов выполнения допустим.

Путь использования

Типичное взаимодействие с KeySlot подразделяется на конфигурацию мониторинга содержимого и опрос сохраненных метаданных ключа:

  1. Регистрация наблюдателя: приложение регистрирует с помощью RegisterUpdateObserver функцию обратного вызова, а также прикладной идентификатор keySlotIdentifier [SWS_CRYPT_30404]. При повторном вызове при обновлениях или удалениях содержимого слота всегда вызывается только последний переданный callback.
  2. Запрос поддерживаемых алгоритмов: через GetPossibleAlgIds приложение получает список всех идентификаторов алгоритмов, поддерживаемых слотом [SWS_CRYPT_50056].
  3. Проверка текущего ключа: если в слоте находится ключ, GetCryptoObjectType возвращает тип объекта ключа [SWS_CRYPT_50054], а GetAlgId — его конкретный идентификатор алгоритма [SWS_CRYPT_50055].
  4. Определение ответственного провайдера: при необходимости через GetCryptoProvider можно запросить управляющий CryptoProvider в виде Shared-Pointer [SWS_CRYPT_30403].
  5. Отмена регистрации наблюдателя: после завершения мониторинга регистрация отменяется через UnregisterUpdateObserver [SWS_CRYPT_30406].

Диаграмма последовательности: типичный процесс регистрации, запроса метаданных и отмены регистрации в KeySlot. Источники: [SWS_CRYPT_30404], [SWS_CRYPT_50056], [SWS_CRYPT_50054], [SWS_CRYPT_50055], [SWS_CRYPT_30406]

Сценарии ошибок

Опрашивающие методы защищают состояния ошибок через тип результата ara::core::Result. Если KeySlot не содержит ключа, вызовы GetCryptoObjectType [SWS_CRYPT_50054] и GetAlgId [SWS_CRYPT_50055] возвращают стандартизированный код ошибки ara::crypto::CryptoErrc::kEmptyKeySlot с семантикой отката. Методы GetPossibleAlgIds [SWS_CRYPT_50056] и GetCryptoProvider [SWS_CRYPT_30403] не специфицируют стандартизированных кодов ошибок. Для управления наблюдателем с помощью RegisterUpdateObserver [SWS_CRYPT_30404], а также UnregisterUpdateObserver [SWS_CRYPT_30406] в случае сбоя в объекте результата предусмотрены ошибки, зависящие от реализации.

Данное руководство было создано ИИ на основе спецификации R25-11.
