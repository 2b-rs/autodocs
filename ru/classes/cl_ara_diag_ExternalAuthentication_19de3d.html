Служит для получения экземпляров аутентификации для управления статусом внешних диагностических клиентов.

Класс ara::diag::ExternalAuthentication предоставляет интерфейс порта, через который адаптивное приложение запрашивает экземпляры ara::diag::ClientAuthentication для управления состоянием аутентификации внешних диагностических клиентов [SWS_DM_01191]. После связывания со смоделированным сервисным портом объекты аутентификации целенаправленно запрашиваются у Diagnostic Manager на основе адреса источника или метаинформации [SWS_DM_01200]. Экземпляр обладает семантикой перемещения, запрещает операции копирования и требует синхронизированного удаления из-за непотокобезопасного деструктора.

Контекст

Класс ara::diag::ExternalAuthentication служит в AUTOSAR Adaptive Platform интерфейсом порта для аутентификации внешних диагностических клиентов [SWS_DM_01191], AUTOSAR_AP_SWS_Diagnostics §8.17 «Header: ara/diag/external_authentication.h». Через этот порт адаптивное приложение получает доступ к конкретным экземплярам ara::diag::ClientAuthentication, которые отображают состояние аутентификации соответствующего диагностического клиента и управляют им [SWS_DM_01202].

Назначение и количество доступных клиентских экземпляров определяются в программной модели через элемент DiagnosticExternalAuthenticationIdentification. Он позволяет приложению задавать фиксированные адреса источников или сконфигурированные диапазоны адресов типа Address (псевдоним для std::uint16_t [SWS_DM_01192]) для диагностических тестеров, если окончательный адрес источника становится известен только во время выполнения AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 «Get ClientAuthentication Instance».

В число участвующих партнеров по взаимодействию входят:

  • адаптивное приложение, которое создает экземпляр порта и запрашивает состояния аутентификации;
  • Diagnostic Manager (DM), который управляет диагностическими соединениями и контролирует состояния аутентификации клиентов [SWS_DM_01202];
  • объекты ara::diag::ClientAuthentication, сопоставленные с запрашивающим клиентом;
  • внешний диагностический клиент, соединение которого идентифицируется по адресу источника или метаинформации.

Контекстная диаграмма: интеграция класса порта между приложением, Diagnostic Manager и аутентификацией клиентов. Источники: [SWS_DM_01191], [SWS_DM_01202], AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 «Get ClientAuthentication Instance».

Жизненный цикл

Создание экземпляра ara::diag::ExternalAuthentication выполняется явно путем передачи ara::core::InstanceSpecifier в конструктор [SWS_DM_01193]. Этот идентификатор связывает объект со смоделированным PortPrototype для DiagnosticExternalAuthenticationInterface.

С точки зрения владения класс обладает чистой семантикой перемещения: конструктор перемещения [SWS_DM_01194] и оператор присваивания с перемещением [SWS_DM_01195] присутствуют (default), тогда как конструктор копирования [SWS_DM_01196] и оператор присваивания с копированием [SWS_DM_01197] удалены (delete). Таким образом, порт представляет собой неделимый, некопируемый объект интерфейса.

Для уничтожения предназначен деструктор ~ExternalAuthentication() [SWS_DM_01198]. В отношении многопоточности конструктор и методы запроса специфицированы как потокобезопасные (thread-safe) и безопасные к исключениям (exception safe) [SWS_DM_01193], [SWS_DM_01199], [SWS_DM_01200], [SWS_DM_01201]. Деструктор, напротив, явно не является потокобезопасным (not thread-safe) [SWS_DM_01198]. Поэтому приложение должно гарантировать, что до разрушения объекта параллельные вызовы больше не производятся.

Путь использования

Типичный рабочий процесс включает инициализацию порта и последующее получение объектов аутентификации:

  1. Приложение инстанцирует ExternalAuthentication с указанием идентификатора экземпляра [SWS_DM_01193].
  2. Приложение запрашивает экземпляр аутентификации для конкретного клиента. Для этого доступны перегруженные методы Get(Address) с использованием адреса тестера [SWS_DM_01200] или Get(const MetaInfo&) на основе принятых метаданных запроса [SWS_DM_01199]. В качестве альтернативы оно запрашивает список всех экземпляров, ведущихся в данный момент Diagnostic Manager, с помощью GetAll() [SWS_DM_01201].
  3. Diagnostic Manager определяет соответствующий объект и возвращает ara::core::Result<ClientAuthentication> или вектор [SWS_DM_01202].
  4. Приложение проверяет результат и затем взаимодействует с полученным экземпляром ClientAuthentication, который, вероятно, выступает в качестве дескриптора на стороне приложения для состояния сеанса аутентификации. Вопрос Q-e7ddbab981bf21de (открытый)

Диаграмма последовательности: типичная последовательность вызовов для инстанцирования и запроса экземпляра ClientAuthentication. Источники: [SWS_DM_01193], [SWS_DM_01200], [SWS_DM_01202].

Сценарии ошибок

При инстанцировании через конструктор ошибки конфигурации и моделирования могут приводить к определенным нарушениям [SWS_DM_01193]:

  • InstanceSpecifierMappingIntegrityViolation: идентификатор не может быть разрешён в контексте исполняемого файла или не ссылается на PortPrototype.
  • PortInterfaceMappingViolation: указанный PortPrototype не типизирован как DiagnosticExternalAuthenticationInterface.
  • ProcessMappingViolation: подходящее смоделированное определение процесса для процесса времени выполнения отсутствует.
  • InstanceSpecifierAlreadyInUseViolation: данный идентификатор уже используется другим экземпляром порта в том же процессе.

При вызовах Get(const MetaInfo&) или Get(Address) возвращаемое значение через ara::core::Result может содержать код ошибки DiagErrc::kServiceNotAvailable [SWS_DM_01199], [SWS_DM_01200]. Это сигнализирует о том, что важная функциональность Diagnostic Manager временно недоступна. Вызов GetAll() при отсутствии экземпляров возвращает не код ошибки, а пустой вектор [SWS_DM_01201].

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 26d2f2a81fd4 Provenance

Явный конструктор [SWS_DM_01193] инициализирует экземпляр класса порта ara::diag::ExternalAuthentication [SWS_DM_01191] для аутентификации внешних диагностических клиентов (SWS Diagnostics §8.17 «Header: ara/diag/external_authentication.h»). В качестве параметра функция ожидает ara::core::InstanceSpecifier, который должен указывать на смоделированный в манифесте PortPrototype сервисного экземпляра DiagnosticExternalAuthenticationInterface [SWS_DM_01193].

Синхронный вызов объявлен как noexcept и специфицирован как thread-safe, так и exception-safe [SWS_DM_01193]. Поскольку исключения не генерируются, ошибки моделирования и конфигурации приводят к определенным нарушениям (violations) фреймворка [SWS_DM_01193]:

  • InstanceSpecifierMappingIntegrityViolation: идентификатор не удается разрешить в контексте исполняемого файла или он ссылается на элемент модели, отличный от PortPrototype.
  • PortInterfaceMappingViolation: указанный по ссылке PortPrototype не типизирован через DiagnosticExternalAuthenticationInterface.
  • ProcessMappingViolation: для ссылки не существует подходящего смоделированного процесса времени выполнения.
  • InstanceSpecifierAlreadyInUseViolation: идентификатор уже используется другим экземпляром в работающем процессе.

Операции копирования для ExternalAuthentication явно запрещены [SWS_DM_01196] [SWS_DM_01197], в то время как операции перемещения поддерживаются [SWS_DM_01194] [SWS_DM_01195]. В отличие от конструктора, соответствующий деструктор не является потокобезопасным [SWS_DM_01198]. После успешного инстанцирования объект служит для запроса соответствующих экземпляров аутентификации клиентов через такие методы, как Get или GetAll [SWS_DM_01201] [SWS_DM_01202].

Данное указание по использованию было сгенерировано автоматически на основе спецификации AUTOSAR.

                                  Деструктор ~ExternalAuthentication() завершает жизненный цикл экземпляра класса ara::diag::ExternalAuthentication из заголовочного файла ara/diag/external_authentication.h [SWS_DM_01198]. Он выполняется синхронно при выходе из области видимости или при освобождении объекта, не требует входных параметров и не имеет возвращаемого значения AUTOSAR_AP_SWS_Diagnostics §8.17.1.2.1.2 «Destructor».
                                  

                                  В отношении обработки ошибок функция снабжена спецификатором noexcept и формально определена как безопасная по исключениям (exception safe) [SWS_DM_01198]. Таким образом, вызов гарантирует, что в случае ошибки исключения C++ не прервут процесс уничтожения и не будут переданы вызывающей стороне.
                                  

                                  Относительно параллелизма и ограничений следует учитывать, что деструктор специфицирован как непотокобезопасный (not thread-safe) [SWS_DM_01198]. Поэтому вызывающие компоненты должны гарантировать, что во время уничтожения отсутствуют одновременные обращения к одному и тому же экземпляру ara::diag::ExternalAuthentication из отдельных потоков. По-видимому, перед вызовом все активные операции диагностики и аутентификации этого экземпляра должны быть полностью завершены во избежание некоординированных обращений к памяти. Вопрос Q-67c112ea87f722d2 (открытый)
