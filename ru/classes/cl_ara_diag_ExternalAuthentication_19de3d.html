Контекст и архитектура

Класс ara::diag::ExternalAuthentication формирует в Adaptive Platform интерфейс для адаптивных приложений для управления и запроса экземпляров аутентификации диагностических тестеров [SWS_DM_01191]. В архитектуре AUTOSAR он выполняет функцию входного портала (порта) к Diagnostic Manager (DM) для получения экземпляров ara::diag::ClientAuthentication, адаптированных для запрашивающих диагностических клиентов AUTOSAR_AP_SWS_Diagnostics с. 129.

В метамодели AUTOSAR элемент DiagnosticExternalAuthenticationIdentification определяет фиксированные адреса источников или диапазоны адресов для диагностических клиентов, из которых выводится количество доступных объектов ara::diag::ClientAuthentication AUTOSAR_AP_SWS_Diagnostics с. 129. При этом отдельные адреса тестеров отображаются через стандартизированный псевдоним типа Address как 16-битное целое число [SWS_DM_01192]. Таким образом, ExternalAuthentication выступает непосредственным посредником между адаптивным приложением, диагностическим сервером или Diagnostic Manager и представленными состояниями аутентификации клиентов.

Контекстная диаграмма: взаимодействие между адаптивным приложением, ExternalAuthentication, Diagnostic Manager и ClientAuthentication. Источники: [SWS_DM_01191], [SWS_DM_01202], AUTOSAR_AP_SWS_Diagnostics с. 129

Жизненный цикл и параллелизм

Экземпляры ara::diag::ExternalAuthentication создаются явно через ara::core::InstanceSpecifier [SWS_DM_01193]. Этот идентификатор должен указывать на определенный в манифесте выполнения PortPrototype, типизированный с помощью DiagnosticExternalAuthenticationInterface [SWS_DM_01193]. Конструирование специфицировано как безопасное относительно исключений (exception safe) и потокобезопасное (thread-safe) [SWS_DM_01193].

В отношении владения класс обладает исключительной семантикой: конструктор копирования [SWS_DM_01196] и оператор присваивания с копированием [SWS_DM_01197] удалены (=delete). Однако объект можно переместить с помощью конструктора перемещения [SWS_DM_01194] или оператора перемещающего присваивания [SWS_DM_01195], причем оба оператора объявлены как noexcept.

Уничтожение осуществляется через виртуальный или обычный деструктор [SWS_DM_01198]. В отличие от обычных вызовов методов, деструктор прямо классифицирован как непотокобезопасный (not thread-safe) [SWS_DM_01198]; следовательно, приложение должно гарантировать, что во время процесса уничтожения параллельные обращения к тому же экземпляру отсутствуют.

Сценарий использования для аутентификации клиента

Штатный процесс управления внешней аутентификацией делится на следующие фазы:

  1. Инстанцирование порта аутентификации: Приложение инстанцирует ExternalAuthentication с указанием заданного в манифесте InstanceSpecifier [SWS_DM_01193].
  2. Получение экземпляра аутентификации клиента: В зависимости от контекста приложению доступны две перегрузки Get, а также групповой запрос:
    • По адресу источника: Get(Address) получает экземпляр на основе адреса тестера (std::uint16_t) [SWS_DM_01192], [SWS_DM_01200].
    • По метаданным запроса: Get(const MetaInfo&) определяет экземпляр на основе переданных метаданных UDS входящего диагностического запроса [SWS_DM_01199].
    • Групповой запрос: GetAll() возвращает все экземпляры ClientAuthentication, управляемые в данный момент Diagnostic Manager, в виде вектора [SWS_DM_01201].
  3. Управление состоянием в Diagnostic Manager: Diagnostic Manager передает приложению соответствующий экземпляр ClientAuthentication, который отвечает за управление состоянием аутентификации соответствующего клиента [SWS_DM_01202]. По всей видимости, приложение затем использует этот объект для выполнения проверок аутентификации и предоставления прав для соответствующего тестера.

Диаграмма последовательности: последовательность вызовов для инстанцирования и запроса объектов ClientAuthentication. Источники: [SWS_DM_01193], [SWS_DM_01200], [SWS_DM_01202]

Сценарии ошибок и предусловия

Ошибки могут возникать как при разрешении модели во время инстанцирования, так и в ходе штатной работы:

  • Нарушения модели и манифеста (конструктор): Если разрешение InstanceSpecifier завершается сбоем или конфигурация модели не совпадает с процессом выполнения, возникают стандартизированные нарушения времени выполнения AUTOSAR [SWS_DM_01193]:
    • InstanceSpecifierMappingIntegrityViolation: идентификатор не указывает на PortPrototype или не может быть разрешен в контексте приложения [SWS_DM_01193].
    • PortInterfaceMappingViolation: порт, на который указывает ссылка, не типизирован DiagnosticExternalAuthenticationInterface [SWS_DM_01193].
    • ProcessMappingViolation: для смоделированного процесса во время выполнения отсутствует соответствующее сопоставление процессов [SWS_DM_01193].
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже использовался в рамках того же процесса для существующего экземпляра порта [SWS_DM_01193].
  • Ошибки времени выполнения при запросах: Методы Get(Address) и Get(const MetaInfo&) возвращают ara::core::Result<ClientAuthentication> [SWS_DM_01199], [SWS_DM_01200]. Если основная функциональность Diagnostic Manager в настоящее время недоступна, вызов завершается сбоем и возвращает код ошибки DiagErrc::kServiceNotAvailable с семантикой отката [SWS_DM_01199], [SWS_DM_01200].
  • Пустые списки результатов: GetAll() возвращает не объект Result, а напрямую вектор ara::core::Vector<ClientAuthentication>. Если клиенты отсутствуют или экземпляры не зарегистрированы, возвращается пустой список [SWS_DM_01201].

Данное руководство основано на требованиях спецификации AUTOSAR Adaptive Platform R25-11.
