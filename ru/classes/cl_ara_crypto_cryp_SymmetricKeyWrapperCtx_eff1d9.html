Позволяет безопасно упаковывать и распаковывать ключи с помощью симметричного шифрования ключей.

Контекст SymmetricKeyWrapperCtx служит для криптографической упаковки и распаковки ключей с помощью симметричных алгоритмов. Перед выполнением Wrap или UnwrapSymmetricKey контекст должен быть сконфигурирован через SetKey с использованием совместимого ключа шифрования ключей (KEK) [SWS_CRYPT_24018]. Все операции требуют соответствующих прав использования задействованных объектов ключей и сообщают об ошибках через ara::core::Result с семантикой отката [SWS_CRYPT_24014]. Интерфейс является безопасным относительно исключений и специфицирован как потокобезопасный для параллельной работы.

Контекст

Класс SymmetricKeyWrapperCtx определяет стандартизированный интерфейс для алгоритмов симметричного обертывания ключей (Key Wrapping) в рамках AUTOSAR Adaptive Platform. Его главная обязанность заключается в криптографической защите ключей при экспорте, а также в восстановлении упакованных ключей для внутреннего использования. При этом класс в первую очередь взаимодействует с ключами шифрования ключей (Key Encryption Keys, KEK), которые предоставляются либо как временный объект ключа типа SymmetricKey, либо персистентно через KeySlot [SWS_CRYPT_24018], [SWS_CRYPT_50034]. При упаковке контекст принимает обобщенный CryptoObject [SWS_CRYPT_24014], тогда как операция распаковки создает и возвращает новый, готовый к использованию объект SymmetricKey [SWS_CRYPT_24016].

Жизненный цикл

Экземпляры SymmetricKeyWrapperCtx управляются через типизированный умный указатель Sptr (псевдоним для std::shared_ptr<SymmetricKeyWrapperCtx>) [SWS_CRYPT_24001]. Фактическое создание объектов, вероятно, выполняется через соответствующую фабрику провайдера, поскольку класс представляет собой абстрактный интерфейс с чисто виртуальными методами. Вопрос Q-7b9a1007da43ddcd (открытый) Все функции-члены интерфейса специфицированы как безопасные относительно исключений (exception safe) и потокобезопасные (thread-safe), что обеспечивает безопасное использование в параллельных программных компонентах [SWS_CRYPT_24014], [SWS_CRYPT_24016].

В жизненном цикле контекст проходит две основные фазы: непосредственно после инстанцирования он находится в неинициализированном состоянии. В этой фазе криптографические операции и вычисления размера буфера завершаются с ошибкой kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014]. Только после успешного вызова SetKey с совместимым KEK или KeySlot контекст переходит в рабочее состояние, в котором ключи можно безопасно упаковывать или распаковывать [SWS_CRYPT_24018], [SWS_CRYPT_50034].

Путь использования

Стандартный процесс упаковки ключа требует скоординированной последовательности конфигурации, проверки буфера и выполнения. Сначала приложение настраивает контекст через SetKey с желаемым объектом KEK [SWS_CRYPT_24018] или привязывает соответствующий KeySlot [SWS_CRYPT_50034]. На втором шаге приложение определяет через GetRequiredWrappedKeyBufferSize максимально необходимый размер выходного буфера для упаковываемого целевого объекта [SWS_CRYPT_50035]. После того как предоставлена область памяти соответствующего размера (ReadWriteMemRegion), выполняется вызов Wrap, который записывает сериализованные и зашифрованные данные ключа в буфер и возвращает точное количество байт [SWS_CRYPT_24014].

Диаграмма последовательности: типичная последовательность вызовов для симметричной упаковки ключей. Источники: [SWS_CRYPT_24018], [SWS_CRYPT_50035], [SWS_CRYPT_24014]

Для комплементарной операции распаковки приложение после конфигурации с помощью SetKey передает входной буфер с упакованными данными в UnwrapSymmetricKey [SWS_CRYPT_24016]. При этом для вновь создаваемого симметричного ключа должны быть явно заданы идентификатор целевого алгоритма (targetAlgId), а также разрешенные флаги использования (allowedUsage) [SWS_CRYPT_24016].

Сценарии ошибок

Методы класса сигнализируют об ошибках через тип возвращаемого значения ara::core::Result с семантикой отката. К ключевым сценариям ошибок относятся:

  • Отсутствие инициализации: если GetRequiredWrappedKeyBufferSize, Wrap или UnwrapSymmetricKey вызываются до успешного назначения ключа, они возвращают ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014], [SWS_CRYPT_24016].
  • Нарушение прав использования: при установке KEK он должен иметь как минимум разрешение kAllowKeyWrapping или kAllowKeyUnwrapping, иначе SetKey завершается с ошибкой ara::crypto::CryptoErrc::kUsageViolation [SWS_CRYPT_24018]. В Wrap отсутствие kAllowKeyWrapping у KEK или отсутствие kAllowSecuredExport у упаковываемого объекта также приводит к kUsageViolation [SWS_CRYPT_24014]. При распаковке проверяется, разрешает ли KEK kAllowKeyUnwrapping [SWS_CRYPT_24016].
  • Несовместимости и ошибки буфера: если целевой буфер для Wrap слишком мал, возвращается ara::crypto::CryptoErrc::kInsufficientCapacity [SWS_CRYPT_24014]. Некорректные форматы ключей или несовместимые типы приводят к ara::crypto::CryptoErrc::kInvalidArgument [SWS_CRYPT_24014], [SWS_CRYPT_24016]. Если контекст поддерживает только слоты или только объекты ключей, SetKey сообщает об ошибке kUnsupported [SWS_CRYPT_24018], [SWS_CRYPT_50034].
  • Конфликты ресурсов и пустые слоты: если операция обращается к занятому ресурсу, возвращается ara::crypto::CryptoErrc::kBusyResource; если ссылаемый KeySlot пуст, это приводит к ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_24014], [SWS_CRYPT_24016].

Данное руководство создано ИИ и опирается исключительно на спецификацию AUTOSAR.

      Использование и семантика
      

      Синхронная функция-член SetKey конфигурирует экземпляр ara::crypto::cryp::SymmetricKeyWrapperCtx таким образом, чтобы переданный объект SymmetricKey::Sptr использовался в качестве Key Encryption Key (KEK) для последующих операций с ключами [SWS_CRYPT_24018]. Функция специфицирована как чисто виртуальный метод с noexcept и возвращает пустое ara::core::Result<void> в случае успешного назначения [SWS_CRYPT_24018].
      


      Обработка ошибок и откат
      

      Если при конфигурации возникает ошибка, применяется обязательная семантика отката, так что состояние контекста остается неизменным [SWS_CRYPT_24018]. Возможные причины ошибок отражаются через коды ошибок из ara::crypto::CryptoErrc:

        • 

      • kUsageViolation: разрешенное использование ключа не включает ни kAllowKeyWrapping, ни kAllowKeyUnwrapping [SWS_CRYPT_24018].
        • 

      • kUnsupported: реализация контекста поддерживает установку ключа исключительно через KeySlot [SWS_CRYPT_24018].
        • 

      


      Параллелизм и взаимодействие

Если ключи управляются через слоты или контекст поддерживает исключительно KeySlot, для того же контекста оболочки (wrapper) существует альтернативная перегрузка SetKey с KeySlot::Sptr [SWS_CRYPT_50034]. Она настраивает контекст на загрузку ключа, размещенного в слоте, в момент выполнения key wrapping [SWS_CRYPT_50034].

          Использование
          

          Виртуальный метод SetKey конфигурирует контекст ara::crypto::cryp::SymmetricKeyWrapperCtx таким образом, чтобы использовать ключ, сохранённый в предоставленном KeySlot, как только будет выполняться оборачивание ключа [SWS_CRYPT_50034]. Вызов ожидает в качестве параметра keySlot объект KeySlot::Sptr, содержащий симметричный ключ [SWS_CRYPT_50034]. Функция вызывается синхронно, объявлена с noexcept и возвращает ara::core::Result<void> [SWS_CRYPT_50034].
          


          Обработка ошибок
          

          В случае ошибки метод обеспечивает семантику отката (rollback) и возвращает один из следующих результатов ошибки [SWS_CRYPT_50034]:
          

            

          • ara::crypto::CryptoErrc::kIncompatibleObject: переданный keySlot несовместим с этим контекстом [SWS_CRYPT_50034].
            • 

          • ara::crypto::CryptoErrc::kUnsupported: контекст поддерживает установку исключительно прямого SymmetricKey [SWS_CRYPT_50034].
            • 

          


          Параллелизм
          

          Операция является потокобезопасной (thread-safe) и обеспечивает гарантированную безопасность исключений (exception safe) [SWS_CRYPT_50034].
          


          Взаимодействие
          

          Интерфейс представляет собой внутри SymmetricKeyWrapperCtx слот-ориентированный аналог перегрузки SetKey с SymmetricKey::Sptr, которая привязывает ключ напрямую в качестве ключа шифрования ключей (Key Encryption Key, KEK) [SWS_CRYPT_24018].
