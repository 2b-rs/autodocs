Позволяет приложениям предоставлять диагностические данные и отвечать на запросы чтения для Diagnostic Manager.

Интерфейс служит адаптивным приложениям для предоставления диагностических данных для операций чтения со стороны Diagnostic Management. После инстанцирования с помощью спецификатора экземпляра приложение должно активно предложить службу, чтобы можно было принимать входящие запросы на чтение [SWS_DM_00597]. Входящие запросы обрабатываются через асинхронный метод чтения, который предоставляет запрошенные выходные данные или отрицательные коды ответа в объекте future [SWS_DM_00596]. Поскольку операции копирования и перемещения удалены, каждый экземпляр жестко привязан к своему контексту.

Контекст

Сгенерированный C++-класс <DataElementInterface> функционирует внутри функционального кластера diag (AUTOSAR Adaptive Platform) в качестве стандартизированного серверного интерфейса для предоставления доступных для чтения диагностических данных AUTOSAR_AP_SWS_Diagnostics с. 68. В частности, он отображает DiagnosticDataElementInterface в роли read, через который адаптивное приложение передает значения данных для диагностических запросов (таких как UDS ReadDataByIdentifier) в Diagnostic Manager (DM) [SWS_DM_00596].

Ключевыми партнерами по взаимодействию являются Diagnostic Management системного демона платформы, координирующий входящие диагностические запросы, а также реализующее адаптивное приложение, которое наследует этот интерфейс и формулирует логику предоставления данных. Инстанцирование и сопоставление с архитектурой программного обеспечения выполняются через смоделированный прототип порта, подключенный через ara::core::InstanceSpecifier [SWS_DM_00587]. При этом выходные данные инкапсулируются в типизированной структуре, аргументы которой представлены соответствующими выходными элементами [SWS_DM_80023], [SWS_DM_00581].

Жизненный цикл

Создание экземпляра выполняется через конструктор с указанием ara::core::InstanceSpecifier, а также режима параллелизма ara::diag::ConcurrencyType [SWS_DM_00587]. Для сохранения однозначного сопоставления внутри процесса как конструктор копирования, так и конструктор перемещения удалены [SWS_DM_01661], [SWS_DM_01662]. Аналогично явно удалены операторы присваивания с копированием и присваивания с перемещением [SWS_DM_01659], [SWS_DM_01660]. Таким образом, экземпляр остается жестко зафиксированным по своему созданному адресу.

С точки зрения функционирования объект проходит определенные фазы:

  • Не предлагается (Not Offered): после конструирования объект изначально находится в неактивном состоянии, в котором DM не доставляет запросы на чтение.
  • Предлагается (Offered): вызовом Offer() служба активируется в DM, благодаря чему входящие запросы на чтение перенаправляются [SWS_DM_00597].
  • Снято с регистрации: вызов StopOffer() деактивирует перенаправление будущих диагностических запросов со стороны DM [SWS_DM_00617].
  • Уничтожение: виртуальный деструктор ~<DataElementInterface>() завершает жизненный цикл экземпляра интерфейса [SWS_DM_00588].

В то время как конструктор специфицирован как потокобезопасный [SWS_DM_00587], Offer(), StopOffer(), Read() и деструктор не являются потокобезопасными [SWS_DM_00597], [SWS_DM_00617], [SWS_DM_00596], [SWS_DM_00588]. Параметр concurrencyType в конструкторе определяет, выполнена ли реализация обработчика потокобезопасной (kConcurrent) или непотокобезопасной (kNotConcurrent) [SWS_DM_00587].

Диаграмма состояний: фазы состояний экземпляра интерфейса между инициализацией, статусом публикации и уничтожением. Источники: [SWS_DM_00587], [SWS_DM_00597], [SWS_DM_00617], [SWS_DM_00588].

Путь использования

Штатный процесс запроса данных следует фиксированной последовательности шагов:

  1. Инстанцирование: приложение инстанцирует производный класс обработчика с требуемыми instanceSpec и concurrencyType [SWS_DM_00587].
  2. Предоставление службы: приложение вызывает Offer(), что дает DM возможность перенаправлять запросы на чтение [SWS_DM_00597].
  3. Обработка запросов на чтение: если запрос на чтение поступает в DM, он вызывает чисто виртуальный метод Read(metaInfo, cancellationHandler) у обработчика [SWS_DM_00596]. Приложение оценивает metaInfo и может через cancellationHandler.IsCanceled() проверить, был ли диалог прерван, или зарегистрировать функцию обратного вызова через cancellationHandler.SetNotifier [SWS_DM_00596].
  4. Обратная связь: интерпретация: фактическое определение выходных данных, как правило, должно происходить асинхронно; результат предоставляется в ara::core::Future с соответствующим объектом ReadOutput [SWS_DM_00596], [SWS_DM_00581].
  5. Завершение сервиса: перед завершением работы приложение вызывает StopOffer(), чтобы предотвратить пересылку [SWS_DM_00617], после чего следует уничтожение объекта [SWS_DM_00588].

Диаграмма последовательности: последовательность вызовов от регистрации сервиса через асинхронное чтение до отмены регистрации. Источники: [SWS_DM_00597], [SWS_DM_00596], [SWS_DM_00617].

Сценарии ошибок

В случае сбоя различные фазы жизненного цикла следует рассматривать дифференцированно:

Уже при конструировании могут возникать нарушения целостности, сигнализируемые через специальные violations [SWS_DM_00587]:

  • InstanceSpecifierMappingIntegrityViolation: спецификатор экземпляра не может быть разрешен в модели исполняемого файла или не указывает на PortPrototype.
  • PortInterfaceMappingViolation: PortPrototype, типизированный через DiagnosticDataElementInterface, не упоминается ни в одном DiagnosticDataPortMapping.
  • ProcessMappingViolation: подходящий InstanceRef существует, но не найден подходящий смоделированный процесс, соответствующий процессу времени выполнения.
  • InstanceSpecifierAlreadyInUseViolation: конструктор был вызван с InstanceSpecifier, который уже используется в текущем процессе.

Если Offer() вызывается для уже предлагаемого сервиса, метод возвращает ara::core::Result с кодом ошибки DiagOfferErrc::kAlreadyOffered (семантика отката) [SWS_DM_00597].

Если запрос на чтение в Read() не может быть успешно обработан, возвращенный ara::core::Future должен содержать соответствующий ISO 14229-1 Negative Response Code (NRC) через DiagUdsNrcErrc или ApApplicationError [SWS_DM_00596].

Данное руководство основано на спецификации AUTOSAR AP Release R25-11 и обобщает требования модуля diag.

Construct a DataElement from an ara::core::InstanceSpecifier

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 838df6a198bf Provenance

Функция-конструктор [SWS_DM_00587] служит для создания экземпляра <DataElementInterface> через ara::core::InstanceSpecifier в соответствии с AUTOSAR_AP_SWS_Diagnostics §8.28.2.2.1.6.

Использование и параметры:

  • instanceSpec: специфицирует конкретный экземпляр службы в контексте модели.
  • concurrencyType: определяет поведение при параллелизме и задает, выполняется ли интерфейс потокобезопасно (kConcurrent) или непотокобезопасно (kNotConcurrent).

Параллелизм и безопасность исключений: функция объявлена как noexcept и классифицирована в спецификации как thread-safe, а также exception-safe [SWS_DM_00587].

Обработка ошибок и нарушения моделирования: ошибки не приводят к исключениям C++, а вызывают специфицированные нарушения (violations):

  • InstanceSpecifierMappingIntegrityViolation: возникает, если instanceSpec не разрешается в контексте процесса или не указывает на PortPrototype.
  • PortInterfaceMappingViolation: сообщается, если PortPrototype, типизированный через DiagnosticDataElementInterface, не ссылается на DiagnosticDataPortMapping.
  • ProcessMappingViolation: возникает, если ссылка на экземпляр присутствует, однако подходящий смоделированный процесс для процесса времени выполнения отсутствует.
  • InstanceSpecifierAlreadyInUseViolation: отправляется, если instanceSpec в том же процессе уже занят вызовом конструктора.

Данное указание по использованию сгенерировано автоматически на основе AUTOSAR R25-11.
