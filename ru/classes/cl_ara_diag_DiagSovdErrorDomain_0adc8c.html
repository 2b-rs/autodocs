Контекст

Класс ara::diag::DiagSovdErrorDomain определяет стандартизированный домен ошибок для состояний ошибок, возникающих в контексте SOVD (Service-Oriented Vehicle Diagnostics) (SWS Diagnostics §8.51.3 «Class: DiagSovdErrorDomain», [SWS_DM_01809]). Будучи финальным классом, он наследуется напрямую от базового класса ara::core::ErrorDomain и интегрирует специфичные для SOVD коды ошибок в единую модель ошибок AUTOSAR Adaptive Platform.

Внутри домена предоставляются основные псевдонимы типов, которые устанавливают связь между обобщёнными структурами ошибок и типами, специфичными для домена:

  • Errc: псевдоним для перечисления DiagSovdErrc, предназначенный для представления специфических кодов ошибок (SWS Diagnostics §8.51.3.1.1 «Type Alias: Errc», [SWS_DM_01810]).
  • Exception: псевдоним для базового класса исключений DiagSovdException, специфичного для домена (SWS Diagnostics §8.51.3.1.2 «Type Alias: Exception», [SWS_DM_01811]).

Через свободную вспомогательную функцию ara::diag::GetDiagSovdErrorDomain вызывающие диагностические компоненты и приложения получают прямой доступ к глобальному экземпляру домена ошибок (SWS Diagnostics §8.51.2.1.1 «GetDiagSovdErrorDomain», [SWS_DM_01816]).

Жизненный цикл

Создание экземпляра DiagSovdErrorDomain осуществляется через конструктор по умолчанию без параметров (SWS Diagnostics §8.51.3.2.1.1 «Default Constructor», [SWS_DM_01812]). Поскольку конструктор объявлен как constexpr и noexcept, создание может происходить уже во время компиляции в рамках статической инициализации.

Интерпретация: приложения, как правило, по всей видимости, создают экземпляр домена ошибок не в виде локальной переменной, а используют его в качестве долгоживущей ссылки на синглтон через GetDiagSovdErrorDomain() ([SWS_DM_01816]). Класс не управляет динамическими ресурсами и не имеет внутренних изменений состояния.

Что касается параллелизма, конструктор, а также методы запроса Name() и Message() явно специфицированы как потокобезопасные и безопасные к исключениям (exception safe) ([SWS_DM_01812], [SWS_DM_01813], [SWS_DM_01814]). ThrowAsException() также гарантирует потокобезопасность, однако из-за процесса возбуждения исключения по определению не является безопасным к исключениям ([SWS_DM_01815]).

Путь использования

Типичный сценарий использования включает обработку возникшей ошибки, а также её преобразование в текстовые сообщения или исключения:

  1. Идентификация домена: при получении кода ошибки (инкапсулированного в ara::core::ErrorCode) через Name() можно запросить краткое имя домена ([SWS_DM_01813], [SWS_CORE_90023]).
  2. Разрешение сообщения об ошибке: с помощью Message(errorCode) числовое значение ошибки преобразуется в описательную строку (SWS Diagnostics §8.51.3.2.2.1 «Message», [SWS_DM_01814]).
  3. Выброс исключения: если система настроена на работу с исключениями C++, ThrowAsException(errorCode) преобразует ошибку в соответствующий объект исключения и выбрасывает его ([SWS_DM_01815]).

Диаграмма последовательности: порядок вызовов при запросе текстов ошибок и возбуждении исключений. Источники: [SWS_DM_01814], [SWS_DM_01815], [SWS_DM_01816].

Сценарии ошибок

При взаимодействии с DiagSovdErrorDomain необходимо учитывать определённые граничные условия и гарантии спецификации:

  • Гарантия указателя для Message: метод Message() согласно спецификации никогда не возвращает нулевой указатель («the text message, never nullptr» в соответствии с [SWS_DM_01814]). Интерпретация: для не определённых явно значений ошибок реализация, вероятно, предоставляет общую резервную строку.
  • Обработка исключений без поддержки компилятора: согласно [SWS_CORE_10304] функция-член ThrowAsException() не участвует в разрешении перегрузки, если C++-исключения отключены в тулчейне ([SWS_DM_01815]). Приложения в средах без исключений должны обрабатывать ошибки исключительно по значению через коды ошибок и типы результатов.

Данное руководство основано на спецификации AUTOSAR Adaptive R25-11 (модуль diag) и было создано автоматически.
