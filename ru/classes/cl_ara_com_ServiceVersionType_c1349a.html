Служит для представления, журналирования и сравнительного управления версиями сервисов в приложениях.

Класс ara::com::ServiceVersionType служит для стандартизированного представления и управления версиями сервисов в AUTOSAR Adaptive Platform ([SWS_CM_11515]). Приложения используют экземпляры для проверки совместимости с помощью сравнений на равенство и упорядочение, для сохранения в контейнерах, а также для журналирования с помощью ToString() ([SWS_CM_11519]). Точный тип может быть переопределен поставщиком Communication Management, однако он должен удовлетворять базовым требованиям C++ к сравнению и присваиванию. При использовании следует учитывать, что все функции-члены класса по спецификации классифицированы как небезопасные относительно исключений.

Контекст

Класс ara::com::ServiceVersionType определяет в заголовочном файле ara/com/service/service_version.h (AUTOSAR_AP_SWS_CommunicationManagement §8.11 «Header: ara/com/service/service_version.h») версию службы связи ([SWS_CM_11515]). Его основная обязанность заключается в том, чтобы сделать версии сервисов доступными для обработки прикладным программным обеспечением, позволяя ему сохранять, администрировать, сравнивать и журналировать сведения о версиях ([SWS_CM_11515]).

Архитектурная особенность заключается в гибкости платформы: согласно [SWS_CM_11515], конкретный тип данных может быть переопределен или расширен поставщиком программного обеспечения Communication Management. Чтобы тем не менее обеспечить согласованную обработку в переносимых приложениях, спецификация требует, чтобы данный тип соответствовал как минимум стандартным концепциям C++ [equalitycomparable] ([SWS_CM_11516]), [lessthancomparable] ([SWS_CM_11517]) и [copyassignable] ([SWS_CM_11518]) согласно ISO/IEC 14882:2014.

К партнерам по взаимодействию относятся не только поставщик программного обеспечения Communication Management, но и сервисные интерфейсы, предоставляющие версии в виде статической константы serviceVersion (AUTOSAR_AP_SWS_CommunicationManagement с. 320), а также использующее программное обеспечение, выполняющее сверку версий.

Контекстная диаграмма: встраивание ara::com::ServiceVersionType между поставщиком программного обеспечения, сервисным интерфейсом и приложением. Источники: [SWS_CM_11515], AUTOSAR_AP_SWS_CommunicationManagement с. 320, AUTOSAR_AP_SWS_CommunicationManagement §8.11.1 «Class: ServiceVersionType».

Жизненный цикл

Экземпляры ara::com::ServiceVersionType спроектированы как обычные типы значений (Value Types). Создание и принятие значения происходят путем копирования и присваивания: с помощью оператора присваивания operator= выполняется требование [copyassignable] ([SWS_CM_11518]), благодаря чему экземпляры могут принимать новые значения.

С точки зрения владения ara::com::ServiceVersionType подчиняется области видимости соответствующего вызывающего компонента или хранится в качестве константы определения сервиса (AUTOSAR_AP_SWS_CommunicationManagement с. 320). Тип не имеет сложного внутреннего конечного автомата, а инкапсулирует дискретное значение версии. Его уничтожение происходит автоматически при выходе из области видимости.

Что касается конкурентности, операции чтения operator== ([SWS_CM_11516]), operator< ([SWS_CM_11517]) и ToString ([SWS_CM_11519]) объявлены как const. Интерпретация: одновременный доступ на чтение к одному и тому же экземпляру из нескольких потоков, вероятно, безопасен без синхронизации, тогда как параллельные операции записи и присваивания должны быть защищены извне.

Путь использования

Типичная последовательность использования ara::com::ServiceVersionType в приложении подразделяется на следующие шаги:

  1. Запрос версии: приложение обращается к информации о версии сервиса, например через статическую константу serviceVersion интерфейса (AUTOSAR_AP_SWS_CommunicationManagement с. 320).
  2. Проверка совместимости: приложение сравнивает версию с ожидаемой версией через operator== ([SWS_CM_11516]). Для проверок порядка или для размещения в отсортированных стандартных контейнерах используется operator< ([SWS_CM_11517]).
  3. Управление и сохранение: для передачи или локального сохранения состояний версий приложение использует оператор присваивания operator= ([SWS_CM_11518]).
  4. Журналирование: для диагностических сообщений или вывода логов приложение формирует через метод ToString() текстовое представление в виде ara::core::StringView ([SWS_CM_11519], AUTOSAR_AP_SWS_CommunicationManagement §8.11.1.1.2.1 «ToString»).

Сценарии ошибок

При использовании интерфейса необходимо учитывать специфические граничные условия:

  • Безопасность относительно исключений: все специфицированные функции — operator= ([SWS_CM_11518]), operator== ([SWS_CM_11516]), operator< ([SWS_CM_11517]) и ToString ([SWS_CM_11519]) — в спецификации явно объявлены как not exception safe. Приложениям не следует полагаться на автоматические гарантии восстановления в случае ошибки (например, при выделении памяти в реализациях поставщика).
  • Действительность String-View: метод ToString() возвращает ara::core::StringView ([SWS_CM_11519]). Интерпретация: поскольку StringView не управляет собственной памятью, время жизни ссылающейся строки, вероятно, привязано к базовому экземпляру или к статической памяти; использование за пределами срока действия источника данных приводит к неопределенному поведению.

Настоящее руководство основано на стандарте AUTOSAR версии R25-11 и учитывает исключительно требования из AUTOSAR_AP_SWS_CommunicationManagement.

Синхронная функция-член ToString класса ara::com::ServiceVersionType служит для сериализации и предоставления сведений о версии в виде читаемого строкового представления ([SWS_CM_11519], SWS CommunicationManagement §8.11.1.1.2.1 «ToString»). Она объявлена в заголовочном файле #include "ara/com/service/service_version.h", в качестве метода const не принимает параметров и возвращает ara::core::StringView на строковое представление версии сервиса ([SWS_CM_11519]).

Отображаемые сведения о версии в соответствии с [SWS_CM_99029] выводятся из атрибутов majorVersion и minorVersion соответствующего ServiceInterface (SWS CommunicationManagement §7.5.22.1 «Service Identifier Data Types»). Конкретный формат строки согласно [SWS_CM_00088] является специфичным для производителя Communication Management и не стандартизирован в рамках всей AUTOSAR (SWS CommunicationManagement §7.5.22.1 «Service Identifier Data Types»).

Для применения и конкурентности действуют следующие граничные условия:

  • Безопасность исключений: в спецификации функция явно классифицирована как небезопасная относительно исключений (not exception safe) ([SWS_CM_11519]). Специфические коды ошибок или сообщения в DET или DEM не определены.
  • Время жизни возвращаемого значения: поскольку возвращается ara::core::StringView, ссылочный буфер, вероятно, привязан к времени жизни объекта ServiceVersionType или к статической памяти (интерпретация). Поэтому представление не следует использовать за пределами времени жизни исходного экземпляра.
  • Контекст вызова: являясь операцией const без побочных эффектов, вызов не изменяет объект; отдельные требования к реэнтрантности не специфицированы.
