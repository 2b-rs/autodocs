Контекст

Структура ara::diag::DTCInformation::SnapshotRecordUpdatedType представляет собой специализированный тип данных внутри функционального кластера Diagnostics (AUTOSAR_AP_SWS_Diagnostics §8.48.5 «Struct: SnapshotRecordUpdatedType», [SWS_DM_00662]). Ее основная задача заключается в инкапсуляции данных о состоянии и предыстории, как только в диагностической системе обновляются записи моментальных снимков (снимки данных или Freeze-Frames) определенного диагностического кода неисправности (Diagnostic Trouble Code, DTC).

В архитектуре AUTOSAR Adaptive этот тип взаимодействует главным образом с тремя участниками:

  • Управление диагностикой (демон / базовая система): контролирует жизненный цикл диагностических событий и DTC. Когда регистрируются новые параметры окружения для события ошибки или перезаписываются существующие Freeze-Frames, платформа создает экземпляр структуры и заполняет его данными.
  • Интерфейс ara::diag::DTCInformation: образует пространство имен и предоставляет канал связи для изменений статуса через тип обратного вызова SnapshotRecordUpdatedTypeNotifier (AUTOSAR_AP_SWS_Diagnostics §8.48.2.1.5 «Type Alias: SnapshotRecordUpdatedTypeNotifier», [SWS_DM_02123]).
  • Адаптивное приложение: регистрирует наблюдателей за изменениями DTC, чтобы своевременно реагировать на обновленные диагностические данные (например, для мониторинга автопарка, логирования данных или оповещения водителя).

При этом структура объединяет два основных свойства: 32-битное поле DTC для идентификации соответствующего кода неисправности (AUTOSAR_AP_SWS_Diagnostics §8.48.5.1.1 «DTC», [SWS_DM_02116]), а также вектор snapshotDataRecords (AUTOSAR_AP_SWS_Diagnostics §8.48.5.1.2 «snapshotDataRecords», [SWS_DM_02117]) типа ara::core::Vector<SnapshotDataRecordType>, который передает конкретные обновленные наборы данных.

Контекстная диаграмма: позиционирование SnapshotRecordUpdatedType между Diagnostic Management, интерфейсом и приложением. Источники: [SWS_DM_00662], [SWS_DM_02123], AUTOSAR_AP_SWS_Diagnostics §8.48.5 «Struct: SnapshotRecordUpdatedType».

Жизненный цикл

Поскольку SnapshotRecordUpdatedType объявлена как C++-struct, ее жизненный цикл соответствует жизненному циклу чистой структуры значений или передачи данных (Plain Old Data с контейнерами):

  • Создание: экземпляр обычно создается внутри платформы диагностической средой выполнения, как только для DTC регистрируется обновление данных стоп-кадра. Поля DTC и snapshotDataRecords заполняются перед передачей.
  • Отношения владения: структура передается в зарегистрированный callback приложения через callback нотификатора SnapshotRecordUpdatedTypeNotifier ([SWS_DM_02123]). Следует исходить из того (интерпретация), что передача осуществляется по const-ссылке или в виде временного объекта-значения, так что принимающее приложение синхронно обрабатывает данные или при необходимости создает собственную копию.
  • Состояния: структура не имеет собственного внутреннего конечного автомата. После инициализации она существует как неизменяемый снимок события обновления.
  • Уничтожение: когда экземпляр покидает область видимости вызова нотификатора, его память и динамически выделенная память вектора snapshotDataRecords детерминированно освобождаются.
  • Параллелизм: SnapshotRecordUpdatedType не реализует внутренних механизмов синхронизации. Поскольку вызовы нотификатора обычно могут выполняться в отдельных рабочих потоках диагностического конвейера, приложение должно позаботиться о синхронизации для потокобезопасной дальнейшей обработки собственных структур данных.

Путь использования

Типичный порядок использования SnapshotRecordUpdatedType делится на следующие шаги:

  1. Регистрация нотификатора: приложение регистрирует функцию обратного вызова в соответствии с сигнатурой SnapshotRecordUpdatedTypeNotifier ([SWS_DM_02123]) в диагностическом экземпляре ara::diag::DTCInformation.
  2. Фиксация события: базовая система обнаруживает изменение статуса или перерасчет данных стоп-кадра для активного DTC.
  3. Создание экземпляра и уведомление: диагностическая система упаковывает соответствующий DTC ([SWS_DM_02116]) и обновленные наборы данных ([SWS_DM_02117]) в экземпляр SnapshotRecordUpdatedType ([SWS_DM_00662]) и инициирует обратный вызов.
  4. Обработка: приложение получает объект, проверяет значение DTC и выполняет итерацию по snapshotDataRecords, чтобы, например, проанализировать измененные параметры окружения.

Диаграмма последовательности: типичный процесс от регистрации нотификатора до обработки данных SnapshotRecordUpdatedType. Источники: [SWS_DM_00662], [SWS_DM_02116], [SWS_DM_02117], [SWS_DM_02123], AUTOSAR_AP_SWS_Diagnostics §8.48.2.1.5 «Type Alias: SnapshotRecordUpdatedTypeNotifier», AUTOSAR_AP_SWS_Diagnostics §8.48.5 «Struct: SnapshotRecordUpdatedType».

Сценарии ошибок

Будучи пассивной структурой данных, SnapshotRecordUpdatedType не предоставляет собственных методов, которые могли бы возвращать ara::core::Result или коды ошибок. Однако при взаимодействии необходимо учитывать следующие граничные условия:

  • Пустой список наборов данных: возможно, что snapshotDataRecords будет передан пустым (например, если наборы данных были аннулированы или сброшены). Приложения всегда должны проверять наличие элементов в векторе перед доступом по индексу.
  • Сопоставление с DTC: значение в DTC соответствует сконфигурированному 32-битному идентификатору ([SWS_DM_02116]). Если приложение получает обновления для DTC, который оно функционально не обрабатывает, ему следует отбросить это событие.
  • Нагрузка на память при больших объемах данных: поскольку snapshotDataRecords основан на ara::core::Vector, при частых обновлениях или больших полезных нагрузках стоп-кадров локальные затраты на копирование могут влиять на скорость обработки; следует избегать ненужного дублирования данных в функции обратного вызова.

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform R25-11 (модуль diag) и обобщает архитектуру и использование SnapshotRecordUpdatedType.
