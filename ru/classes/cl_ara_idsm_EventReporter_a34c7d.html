Позволяет приложениям потокобезопасно сообщать о Security Events с опциональными контекстными данными в IdsM.

Класс ara::idsm::EventReporter служит в AUTOSAR Adaptive центральным программным интерфейсом для сообщения о событиях безопасности в Intrusion Detection System Manager [SWS_AIDSM_10101]. После инстанцирования с использованием ara::core::InstanceSpecifier для смоделированного порта приложения гибко передают инциденты со счетчиком, временной меткой или (версионированными) контекстными данными [SWS_AIDSM_10301]. Все методы явно специфицированы как потокобезопасные и допускают параллельное использование из нескольких потоков приложения. Поскольку все интерфейсы снабжены noexcept, ошибки передачи не передаются вызывающей стороне через исключения C++.

Контекст

Класс ara::idsm::EventReporter служит в AUTOSAR Adaptive Platform основным программным интерфейсом для функциональных приложений при сообщении об инцидентах безопасности (Security Events) в Intrusion Detection System Management (IdsM) [SWS_AIDSM_10101]. В рамках архитектуры платформы класс берет на себя роль посредника между логикой обнаружения конкретного приложения и общеплатформенными службами безопасности. К непосредственным партнерам по взаимодействию относятся функциональные программные компоненты, идентифицирующие аномалии или критические для безопасности инциденты, экземпляр-посредник EventReporter, а также служба IdsM платформы Adaptive Platform, отвечающая за сбор, фильтрацию и дальнейшую обработку событий безопасности.

Контекстная диаграмма: интеграция EventReporter между отправляющим сообщение приложением и IdsM. Источники: [SWS_AIDSM_10101], [SWS_AIDSM_10301]

Жизненный цикл

Создание объекта EventReporter осуществляется через его конструктор с передачей идентификатора типа ara::core::InstanceSpecifier [SWS_AIDSM_10301]. Это привязывает экземпляр к смоделированному в манифесте порту типа SecurityEventReportInterface [SWS_AIDSM_10301]. Права владения принадлежат использующему приложению; обычно целесообразно долгосрочное хранение на протяжении всего времени работы компонента во избежание повторных привязок к порту. Для параллелизма спецификация гарантирует полную потокобезопасность: как конструирование, так и все методы отправки событий спроектированы потокобезопасными (thread-safe) [SWS_AIDSM_10301], [SWS_AIDSM_10302]. Благодаря этому несколько потоков приложения могут параллельно использовать один и тот же экземпляр репортера без необходимости внешних мер синхронизации.

Путь использования

Стандартный рабочий процесс включает инстанцирование репортера и последующее сообщение об инцидентах через метод ReportEvent. После инициализации с подходящим ara::core::InstanceSpecifier [SWS_AIDSM_10301] приложение выбирает одну из предоставленных перегрузок в зависимости от типа события и степени детализации доступной контекстной информации:

  • Сообщение без контекста: для простых событий без сопутствующих данных используется базовая перегрузка, опционально передающая количество событий (count, значение по умолчанию 1) [SWS_AIDSM_10302].
  • Сообщение с временной меткой: если событие требуется снабдить явным моментом фиксации, доступен вариант с TimestampType [SWS_AIDSM_10303].
  • Сообщение с контекстными данными: для передачи диагностических данных или подробностей инцидента метод ReportEvent может вызываться с параметрами типа ContextDataType, на выбор без явной временной метки или с ней [SWS_AIDSM_10304], [SWS_AIDSM_10305].
  • Сообщение с версионированными контекстными данными: если формат обмена определен структурированным или зависимым от версии, перегрузки с VersionedContextDataType — также с временной меткой или без нее — предоставляют соответствующий интерфейс [SWS_AIDSM_10306], [SWS_AIDSM_10307].

Как только вызывается ReportEvent, репортер пересылает данные в подсистему IdsM и немедленно возвращает управление приложению.

Диаграмма последовательности: типичная последовательность взаимодействия от создания репортера до отправки Event. Источники: [SWS_AIDSM_10301], [SWS_AIDSM_10304]

Сценарии ошибок

Важным предусловием для отправки сообщений считается успешное конструирование EventReporter с действительным идентификатором порта, зафиксированным в модели платформы [SWS_AIDSM_10301]. В отношении обработки ошибок и безопасности исключений все интерфейсы класса имеют одну особенность: конструктор, а также без исключения все перегрузки ReportEvent объявлены как noexcept [SWS_AIDSM_10301], [SWS_AIDSM_10302], [SWS_AIDSM_10303], [SWS_AIDSM_10304], [SWS_AIDSM_10305], [SWS_AIDSM_10306], [SWS_AIDSM_10307]. Исключения C++ не возбуждаются, и объекты ошибок, такие как ara::core::Result, не возвращаются. Если во время передачи в IdsM возникают инфраструктурные проблемы, такие как дефицит буфера или сбои служб, они, вероятно, обрабатываются внутри службы платформы, отбрасываются или протоколируются, чтобы не блокировать отправляющее приложение.

Настоящее руководство основано на спецификации AUTOSAR Adaptive R25-11 и создано автоматически.

Класс EventReporter определен в заголовочном файле ara/idsm/event_reporter.h и служит в Adaptive Platform для сообщения о событиях безопасности (Security Events) в Intrusion Detection System Management (IdsM) [SWS_AIDSM_10101].

Использование и инстанцирование

Для использования класса необходимо создать экземпляр через параметризованный конструктор, который принимает идентификатор типа const ara::core::InstanceSpecifier& [SWS_AIDSM_10301]. Этот конструктор инициализирует репортер для порта типа SecurityEventReportInterface, сконфигурированного в модели системы [SWS_AIDSM_10301]. Интерпретация: привязка к смоделированному порту, вероятно, предполагает, что переданный InstanceSpecifier согласованно определен в манифесте ARXML и может быть разрешен во время выполнения.

Обработка ошибок и параллелизм

В отношении поведения при исключениях конструирование специфицировано с noexcept [SWS_AIDSM_10301]; таким образом, конструктор не генерирует исключений C++. В отношении параллелизма функция конструирования явно объявлена потокобезопасной (thread-safe) [SWS_AIDSM_10301]. Интерпретация: таким образом, несколько потоков, вероятно, могут параллельно инстанцировать экземпляры репортера для своих соответствующих портов без необходимости во внешних механизмах синхронизации.

Взаимодействие

Взаимодействие с IdsM основано на сопоставлении экземпляра с соответствующим портом моделирования: благодаря спецификации как EventReporter для SecurityEventReportInterface [SWS_AIDSM_10301] класс представляет собой интерфейс, через который адаптивные приложения передают события безопасности в архитектуру IdsM [SWS_AIDSM_10101].

          Использование
          

          Функция ReportEvent из заголовочного файла ara/idsm/event_reporter.h служит для сообщения о Security Event с контекстными данными [SWS_AIDSM_10304]. При вызове передается аргумент contextData типа ContextDataType. Дополнительно можно опционально указать количество событий через count (тип CountType), значение по умолчанию которого задано как 1 [SWS_AIDSM_10304]. Функция не возвращает значения (void) и, будучи объявленной как noexcept, не генерирует исключений.
          


          Параллелизм и ограничения
          

          Интерфейс явно определен как thread-safe [SWS_AIDSM_10304] и может вызываться параллельно из нескольких потоков без дополнительных мер синхронизации. Поскольку сигнатура не предоставляет параметра для метки времени, фиксация момента сообщения, по-видимому, выполняется внутри при приеме события.
          


          Взаимодействие со связанными интерфейсами
          

          Спецификация определяет несколько связанных перегрузок ReportEvent для различных объемов информации:
          

            

          • Сообщение о событии без контекстных данных и метки времени [SWS_AIDSM_10302].
            • 

          • Сообщение с меткой времени, но без контекстных данных [SWS_AIDSM_10303].
            • 

          • Сообщение с контекстными данными и явной меткой времени [SWS_AIDSM_10305].
            • 

          • Сообщения с версионированными контекстными данными типа VersionedContextDataType, либо без метки времени [SWS_AIDSM_10306], либо с меткой времени [SWS_AIDSM_10307].
