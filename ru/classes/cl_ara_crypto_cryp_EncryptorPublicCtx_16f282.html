Шифрует данные асимметрично за один шаг или с помощью составной потоковой операции.

Интерфейс служит для асимметричного шифрования открытых данных на AUTOSAR Adaptive Platform и управляется через предоставляемый умный указатель [SWS_CRYPT_50174]. После назначения подходящего открытого ключа сообщения могут преобразовываться либо компактно за один проход, либо непрерывно в рамках составного сеанса потоковой передачи [SWS_CRYPT_50090]. Для корректного выполнения размеры буферов должны рассчитываться предварительно, при этом все операции контекста специфицированы как исключениебезопасные и потокобезопасные.

Контекст

Класс C++ ara::crypto::cryp::EncryptorPublicCtx предоставляет стандартизированный интерфейс для асимметричного шифрования данных в AUTOSAR Adaptive Platform. Он служит клиентским приложениям для шифрования открытых данных с использованием асимметричного открытого ключа. При этом конфигурация криптографического ключа может выполняться либо напрямую через ключевой объект ([SWS_CRYPT_50175]), либо через ссылку на место хранения ключа (KeySlot, [SWS_CRYPT_50086]). Передача данных осуществляется через эффективные по использованию памяти буферные области (ReadOnlyMemRegion для открытых данных и ReadWriteMemRegion для вывода шифротекста).

Жизненный цикл

Экземпляры контекста управляются через shared-указатель std::shared_ptr<EncryptorPublicCtx>, определенный в псевдониме типа Sptr ([SWS_CRYPT_50174]). Само создание не является частью данного определения интерфейса; вероятно, инстанцирование выполняется вышестоящим фабричным компонентом криптоархитектуры. Вопрос Q-5b7490ba113bb861 (открытый) В течение своего жизненного цикла объект проходит четко определенные состояния:

  • Не инициализирован: после инстанцирования контекст еще не имеет ключа. Операции обработки данных в этом состоянии недопустимы.
  • Сконфигурирован (готов): при вызове SetKey() с PublicKey ([SWS_CRYPT_50175]) или KeySlot ([SWS_CRYPT_50086]) контекст становится готов к использованию. Из этого состояния можно либо выполнить одношаговое шифрование, либо запустить сеанс потоковой передачи.
  • Потоковая передача активна: вызов Start() ([SWS_CRYPT_50087]) переводит контекст в состояние потоковой передачи. Последовательные блоки данных обрабатываются через Update() ([SWS_CRYPT_50176]). Сеанс либо завершается с помощью Finish() ([SWS_CRYPT_50088]), либо прерывается с помощью Cancel() ([SWS_CRYPT_50089]), в результате чего контекст возвращается в состояние Сконфигурирован.

Все методы класса специфицированы как исключениебезопасные (exception safe) и потокобезопасные (thread-safe). Если контекст уничтожается в то время, когда потоковая операция еще не была завершена, базовая реализация, вероятно, очищает выделенные буферы и неявно сбрасывает сеанс. Вопрос Q-3eadc946a0bdbdfd (открытый)

Диаграмма состояний: жизненный цикл и переходы состояний контекста от конфигурации до преобразования. Источники: [SWS_CRYPT_50086], [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089], [SWS_CRYPT_50090]

Путь использования

Класс поддерживает два режима обработки: одношаговую обработку для полных наборов данных и многошаговую потоковую передачу для сегментированных потоков данных. Перед выполнением операций шифрования приложения должны учитывать границы буферов:

  • С помощью GetMinimumChunkSize()` (<a class="spec-record-ref" data-req="SWS_CRYPT_50178">[SWS_CRYPT_50178]</a>) und <code>GetMaximumChunkSize() ([SWS_CRYPT_50091]) можно определить минимально и максимально поддерживаемые размеры входных данных для отдельных вызовов.
  • Необходимая емкость выходного буфера должна быть предварительно запрошена с помощью GetRequiredOutputBufferSize() ([SWS_CRYPT_50177]). Параметр isFinal управляет тем, выполняется ли расчет для промежуточных шагов (false) или для финальных вызовов либо однократных шагов (true).

Типичный процесс потокового шифрования делится на следующие шаги:

  1. Назначение ключа через SetKey() с действительным PublicKey ([SWS_CRYPT_50175]).
  2. Инициализация сеанса потоковой передачи путем вызова Start() ([SWS_CRYPT_50087]).
  3. Расчет требуемого размера выходного буфера для промежуточных блоков с помощью GetRequiredOutputBufferSize(inputSize, false) ([SWS_CRYPT_50177]).
  4. Повторное преобразование блоков данных через Update() ([SWS_CRYPT_50176]).
  5. Определение размера буфера для последнего блока (isFinal = true) и финализация операции через Finish() ([SWS_CRYPT_50088]).

Для компактных данных, которые могут быть обработаны за один проход, Encrypt() ([SWS_CRYPT_50090]) предоставляет прямой одношаговый вызов без разделения на фазы Start, Update и Finish.

Диаграмма последовательности: типичный процесс многоэтапного потокового шифрования с определением размера буфера. Источники: [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50177], [SWS_CRYPT_50176], [SWS_CRYPT_50088]

Сценарии ошибок

Все методы используют ara::core::Result для сигнализации об ошибках и гарантируют семантику отката в случае сбоя:

  • Ошибки состояния: вызов Start(), Encrypt() или GetRequiredOutputBufferSize() для неинициализированного контекста приводит к ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50177]). Если Update(), Finish() или Cancel() вызываются без предварительного выполнения Start(), операция завершается с ошибкой ara::crypto::CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089]).
  • Ошибки ключа и использования: если предоставленный ключ или KeySlot несовместим с контекстом, возвращается ara::crypto::CryptoErrc::kIncompatibleObject ([SWS_CRYPT_50175], [SWS_CRYPT_50086], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Если разрешенное использование ключа не содержит разрешения kAllowDataEncryption, это приводит к ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Если указанный KeySlot пуст, сообщается о ara::crypto::CryptoErrc::kEmptyKeySlot ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • Ошибки буфера и данных: если переданный выходной буфер имеет недостаточный размер, Encrypt(), Update() и Finish() отвечают ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). Отклонения от допустимых размеров фрагментов приводят к ara::crypto::CryptoErrc::kInvalidInputSize, недопустимые входные данные — к ara::crypto::CryptoErrc::kInvalidArgument.
  • Неподдерживаемые функции и нехватка ресурсов: если реализация не поддерживает потоковую передачу или одношаговый вызов, операция завершается ошибкой с ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). При блокировке криптографических ресурсов возвращается ara::crypto::CryptoErrc::kBusyResource ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).

Данное руководство основано на требованиях AUTOSAR Adaptive Platform Release R25-11 и обобщает спецификацию класса ara::crypto::cryp::EncryptorPublicCtx.

Метод Cancel() прерывает активную операцию потоковой передачи в контексте ara::crypto::cryp::EncryptorPublicCtx, которая ранее была инициирована с помощью Start() и еще не завершена [SWS_CRYPT_50089]. Он не принимает входных параметров и возвращает ara::core::Result<void>, который в случае успеха пуст [SWS_CRYPT_50089]. Поскольку сигнатура сразу возвращает Result, а не Future, прерывание, вероятно, выполняется синхронно. Вопрос Q-cd18e56d693fe1a4 (открытый)

Обработка ошибок и параллелизм

Если обработка данных не была предварительно запущена через Start(), операция завершается сбоем с кодом ошибки ara::crypto::CryptoErrc::kProcessingNotStarted с соблюдением семантики отката [SWS_CRYPT_50089]. Согласно спецификации интерфейс объявлен с noexcept, является безопасным относительно исключений (exception safe) и для параллельного доступа классифицирован как потокобезопасный (thread-safe) [SWS_CRYPT_50089].

Взаимодействие в криптографическом стеке

Поведение прерывания, реализованное с помощью Cancel(), следует единому шаблону проектирования для потоковых операций с сохранением состояния в криптографическом модуле. Аналогичные интерфейсы с идентичной семантикой ошибок существуют для:

  • операций подписи и проверки подписи в SignerPrivateCtx [SWS_CRYPT_50041] и VerifierPublicCtx [SWS_CRYPT_50023],
  • симметричного и аутентифицированного шифрования в SymmetricCipherCtx [SWS_CRYPT_50046], а также AuthCipherCtx [SWS_CRYPT_50077],
  • асимметричного расшифрования в DecryptorPrivateCtx [SWS_CRYPT_50069],
  • кодов аутентификации сообщений в MessageAuthnCodeCtx [SWS_CRYPT_50027], а также вычислений хеша в HashFunctionCtx [SWS_CRYPT_50058].

                              Использование
                              

                              
Виртуальный метод SetKey класса ara::crypto::cryp::EncryptorPublicCtx конфигурирует контекст для использования предоставленного открытого ключа [SWS_CRYPT_50175].
Через параметр key (типа PublicKey::Sptr) передается объект ключа, используемый для шифрования [SWS_CRYPT_50175].
Выполнение происходит синхронно и возвращает ara::core::Result<void>, которое в случае успеха не содержит значения [SWS_CRYPT_50175].

                              


                              Обработка ошибок
                              

                              
Если при конфигурации возникает ошибка, возвращается соответствующий код ошибки с определенной семантикой отката [SWS_CRYPT_50175]:

                              

                                

                              • ara::crypto::CryptoErrc::kUsageViolation: допустимое использование ключа не разрешает шифрование данных (kAllowDataEncryption) [SWS_CRYPT_50175].
                                • 

                              • ara::crypto::CryptoErrc::kIncompatibleObject: переданный объект ключа несовместим с данным контекстом шифрования [SWS_CRYPT_50175].
                                • 

                              • ara::crypto::CryptoErrc::kUnsupported: конкретная реализация контекста поддерживает исключительно привязку через KeySlot [SWS_CRYPT_50175].
                                • 

                              


                              Параллелизм и ограничения
                              

                              
Интерфейс определен как noexcept и специфицирует поведение, являющееся как thread-safe, так и exception safe [SWS_CRYPT_50175].
Благодаря семантике отката контекст в случае ошибки остается в своем предыдущем состоянии.
Интерпретация: успешный вызов, вероятно, является обязательным условием для последующих операций шифрования, поскольку без назначенного ключа контекст не может выполнять операции. Вопрос Q-ab4779cac18793fa (открытый)

                              


                              Взаимодействие
                              

                              
Этот подход следует общемодульному шаблону асимметричных контекстов, который также используется в VerifierPublicCtx::SetKey [SWS_CRYPT_24115] и KeyEncapsulatorPublicCtx::SetKey [SWS_CRYPT_21815] для привязки ключа.
В качестве альтернативы родственные интерфейсы для конфигурации предусматривают также варианты KeySlot, как, например, в VerifierPublicCtx [SWS_CRYPT_50018] или KeyEncapsulatorPublicCtx [SWS_CRYPT_50012].

                                  Использование и семантика
                                  

                                  Чисто виртуальный метод Start класса ara::crypto::cryp::EncryptorPublicCtx служит для инициализации контекста для нового шифрования [SWS_CRYPT_50087]. Он не принимает входных параметров и выполняется синхронно. В качестве возвращаемого значения функция передает ara::core::Result<void>, которое либо подтверждает успешную инициализацию, либо передает возникший код ошибки [SWS_CRYPT_50087].
                                  


                                  Обработка ошибок и поведение при откате
                                  

                                  Если требуемые предварительные условия для операции шифрования не выполнены, вызов завершается неудачно. Спецификация гарантирует семантику отката для случаев ошибок и определяет следующие причины ошибок [SWS_CRYPT_50087]:
                                  

                                    

                                  • UninitializedContext: контексту предварительно не был назначен ключ.
                                    • 

                                  • ara::crypto::CryptoErrc::kEmptyKeySlot: сконфигурированный KeySlot в данный момент не занят.
                                    • 

                                  • ara::crypto::CryptoErrc::kUsageViolation: права доступа ключа не содержат флаг использования kAllowDataEncryption.
                                    • 

                                  • ara::crypto::CryptoErrc::kIncompatibleObject: назначенный тип ключа несовместим с требуемым преобразованием.
                                    • 

                                  • ara::crypto::CryptoErrc::kBusyResource: ресурс, необходимый для инициализации, занят.
                                    • 

                                  • ara::crypto::CryptoErrc::kUnsupported: потоковая обработка не поддерживается конкретным контекстом.
                                    • 

                                  


                                  Параллелизм и взаимодействие
                                  

                                  Метод специфицирован как thread-safe и exception safe [SWS_CRYPT_50087]. Предоставление подходящего ключа в контексте является обязательным предварительным условием успеха. Концептуально функция встраивается в стандартизированные жизненные циклы криптографических контекстов, в которых операции подготавливаются вызовами без параметров — сравнимо с проверками подписи [SWS_CRYPT_50019], формированиями подписи [SWS_CRYPT_50037] или вычислениями MAC [SWS_CRYPT_22111]. Вызов, по-видимому, представляет собой обязательную отправную точку перед фактическим выполнением потокового шифрования.                                       Использование
                                      

                                      Синхронный метод Update класса ara::crypto::cryp::EncryptorPublicCtx служит для пошагового шифрования блоков открытого текста [SWS_CRYPT_50176]. Через параметр in (ReadOnlyMemRegion) передается часть открытого текста, тогда как зашифрованные данные записываются в выходной буфер out (ReadWriteMemRegion) [SWS_CRYPT_50176]. В качестве возвращаемого значения функция передает через ara::core::Result<std::size_t> фактическое количество записанных байтов, которое может быть меньше предоставленной емкости out [SWS_CRYPT_50176].
                                      


                                      Порядок выполнения и взаимодействие
                                      

                                      Перед первым вызовом Update обработка данных обязательно должна быть инициирована с помощью Start() [SWS_CRYPT_50176]. Максимально допустимый размер входных данных для отдельных вызовов можно запросить через метод GetMaximumChunkSize() [SWS_CRYPT_50091]. Минимальный размер, требуемый для out, также может быть вычислен через GetRequiredOutputBufferSize() [SWS_CRYPT_50176].
                                      


                                      Обработка ошибок и параллелизм
                                      

                                      Если во время выполнения возникает ошибка, о ней сообщается с семантикой отката [SWS_CRYPT_50176]:
                                      

                                        

                                      • ara::crypto::CryptoErrc::kProcessingNotStarted: обработка данных не была предварительно начата с помощью Start() [SWS_CRYPT_50176].
                                        • 

                                      • ara::crypto::CryptoErrc::kInsufficientCapacity: емкости буфера out недостаточно для результата [SWS_CRYPT_50176].
                                        • 

                                      • ara::crypto::CryptoErrc::kInvalidInputSize: размер буфера in некорректен [SWS_CRYPT_50176].
                                        • 

                                      • ara::crypto::CryptoErrc::kUnsupported: потоковая обработка не поддерживается текущим контекстом [SWS_CRYPT_50176].
                                        • 

                                      

                                      Метод объявлен как исключениебезопасный и потокобезопасный [SWS_CRYPT_50176]. Тем не менее параллельный вызов нескольких операций для одного и того же объекта контекста, предположительно, требует внешней синхронизации, чтобы гарантировать детерминированный порядок зашифрованных фрагментов данных.
