Kontext

In der AUTOSAR Adaptive Platform stellt das funktionale Modul crypto standardisierte kryptografische Schnittstellen für sicherheitsrelevante Fahrzeuganwendungen bereit. Innerhalb dieses Moduls und des dedizierten Namensraums ara::crypto::x509 definiert die Klasse ara::crypto::x509::CertSignRequest eine Schnittstelle zur Repräsentation von Zertifikatssignierungsanforderungen (Certificate Signing Requests, CSR).

In modernen Public-Key-Infrastrukturen (PKI) bilden Zertifikatssignierungsanforderungen das Bindeglied zwischen einem Schlüsselbesitzer und einer Zertifizierungsstelle (Certificate Authority, CA). Ein CSR kapselt den öffentlichen Schlüssel des Antragstellers zusammen mit Identitätsattributen und belegt den Besitz des korrespondierenden privaten Schlüssels. Die Schnittstelle ara::crypto::x509::CertSignRequest stellt das objektorientierte Gegenstück für diesen kryptografischen Standard in der Adaptive Platform dar.

Aus der Klassendeklaration geht hervor, dass die Klasse öffentlich von ara::crypto::Serializable erbt: class CertSignRequest : public ara::crypto::Serializable. Durch diese Basisklasse wird CertSignRequest direkt an das Serialisierungsframework des Kryptomoduls angebunden. Interpretation: Als Schnittstellenobjekt für Zertifikatsanträge dürfte ara::crypto::x509::CertSignRequest primär dazu dienen, die Validierung und Übermittlung von CSR-Datenstrukturen softwareseitig zu kapseln.

Lebenszyklus

Der Lebenszyklus einer Instanz von ara::crypto::x509::CertSignRequest wird im AUTOSAR-Kryptokonzept über Smart Pointer verwaltet. Für die Interaktion mit konstanten Objekten definiert die Spezifikation eine standardisierte Zeigerdefinition:

  • Gemäß [SWS_CRYPT_40301] deklariert die Klasse den Typalias using Sptrc = std::shared_ptr<const CertSignRequest>; im Header ara/crypto/x509/cert_sign_request.h als Smart Pointer auf das konstante Schnittstellenobjekt.

Aus dieser Deklaration lassen sich wesentliche Aspekte für die Verwaltung und Nebenläufigkeit der Instanzen ableiten:

  • Gemeinsame Eigentümerschaft: Der Einsatz von std::shared_ptr ermöglicht eine flexible Weitergabe des Objekts an unterschiedliche Funktionseinheiten, etwa Verarbeitungsdienste oder Kommunikationsadapter, wobei die Lebensdauer automatisch über Referenzzählung gesteuert wird.
  • Unveränderlichkeit: Da Sptrc ([SWS_CRYPT_40301]) auf ein konstantes Interface zeigt, wird sichergestellt, dass Konsumenten die Eigenschaften des Signierungsantrags nach dessen Erstellung nicht mehr verändern können.
  • Zerstörung: Sobald die letzte Sptrc-Kopie freigegeben wird, erfolgt die automatische Zerstörung des Objekts und die Deallokation aller zugeordneten Ressourcen.
  • Nebenläufigkeit: Der ausschließliche Lesezugriff über die konstante Schnittstelle ermöglicht eine threadsichere Nutzung über mehrere Ausführungskontexte hinweg, ohne dass zusätzliche Synchronisationsmechanismen erforderlich sind.

Nutzungspfad

Ein charakteristischer Verwendungsablauf von ara::crypto::x509::CertSignRequest gliedert sich in folgende logische Phasen:

  1. Erzeugung: Eine Anwendung initiiert die Generierung eines neuen Schlüsselpaares und veranlasst die Erstellung eines korrespondierenden CSR-Objekts.
  2. Kapselung und Bereitstellung: Das fertige Objekt wird als CertSignRequest::Sptrc ([SWS_CRYPT_40301]) an konsumierende Komponenten übergeben, wodurch ein unveränderlicher Zustand garantiert ist.
  3. Serialisierung: Über die Vererbung von ara::crypto::Serializable wird das CSR-Objekt in einen standardisierten Bytestrom überführt (Interpretation: vermutlich in das DER-kodierte Format gemäß PKCS#10).
  4. Versand und Zertifikatserhalt: Der Bytestrom wird über standardisierte Protokolle an eine externe Zertifizierungsstelle übermittelt, um im Gegenzug das signierte X.509-Zertifikat zu empfangen.

Dieser Leitfaden basiert auf der Spezifikation von AUTOSAR Adaptive Platform Release R25-11.
