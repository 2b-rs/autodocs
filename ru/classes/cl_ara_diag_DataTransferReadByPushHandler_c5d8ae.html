Контекст

Класс ara::diag::DataTransferReadByPushHandler [SWS_DM_01515] предоставляет стандартизированный интерфейс для диагностической передачи данных в модуле Adaptive diag, которая инициируется такой службой UDS, как RequestReadFile или RequestReadDirectory, и при которой полезные данные активно предоставляются («передаются методом push») реализацией приложения AUTOSAR_AP_SWS_Diagnostics §8.10.3 «Class: DataTransferReadByPushHandler».

При этом во всей системе взаимодействуют три основных участника:

  • UDS-клиент (диагностический тестер): инициирует передачу файла или каталога по протоколу автомобильной диагностики и последовательно запрашивает блоки данных.
  • Diagnostic Management (ara::diag): обрабатывает запросы UDS, управляет диагностическим сеансом и перенаправляет вызовы чтения и завершения обработчику конкретного приложения [SWS_DM_01522].
  • Обработчик приложения: реализует класс, производный от ara::diag::DataTransferReadByPushHandler, считывает данные из локального хранилища и передает владение блоками полезных данных в ara::diag [SWS_DM_01522].

Контекстная диаграмма: взаимодействие между UDS-клиентом, Diagnostic Management (ara::diag) и обработчиком приложения. Источники: [SWS_DM_01515], [SWS_DM_01522], [SWS_DM_01523], AUTOSAR_AP_SWS_Diagnostics §8.10.3 «Class: DataTransferReadByPushHandler»

Жизненный цикл

Жизненный цикл экземпляра обработчика тесно связан с продолжительностью одного сеанса передачи файлов:

  • Создание: конструктор по умолчанию объявлен как protected [SWS_DM_01516]. Интерпретация: класс спроектирован как чисто базовый класс, от которого необходимо наследовать в реализации приложения для предоставления чисто виртуальных методов.
  • Владение и запрет копирования: конструктор копирования [SWS_DM_01518] и оператор присваивания копированием [SWS_DM_01521] удалены (=delete). Обработчик предназначен исключительно для одной передачи чтения («only one way usage i.e. per single file transfer session»).
  • Перемещение: конструктор перемещения [SWS_DM_01517] и оператор присваивания перемещением [SWS_DM_01520] определены как стандартные (=default) и являются безопасными относительно исключений (noexcept).
  • Уничтожение: виртуальный деструктор [SWS_DM_01519] имеет строгое предусловие: экземпляр ни в коем случае не должен уничтожаться до вызова ExitRead() AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.1.2 «Destructor». Интерпретация: запрет на уничтожение обеспечивает протокольную согласованность сеанса UDS в Diagnostic Management.
  • Параллелизм: методы Read и ExitRead специфицированы как непотокобезопасные (not thread-safe) [SWS_DM_01522], [SWS_DM_01523]. Параллельные вызовы для одного и того же экземпляра должны предотвращаться на стороне приложения.

Путь использования

Типичный процесс передачи для чтения включает следующие шаги:

  1. Инициализация: при поступлении запроса на чтение (RequestReadFile или RequestReadDirectory) приложение создает экземпляр своего конкретного обработчика через защищенный конструктор [SWS_DM_01516].
  2. Передача данных (Read): Diagnostic Management повторно вызывает чисто виртуальный метод Read() [SWS_DM_01522] AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 «Read». При этом передаются recommended_number_bytes_to_return для оптимизации пропускной способности, meta_info и cancellation_handler. Приложение формирует следующий фрагмент и передает право владения им через ara::core::Future<ara::core::Vector<ara::core::Byte>> в ara::diag. Полезные данные помещаются в положительный ответ UDS после blockSequenceCounter в виде transferResponseParameterRecord.
  3. Завершение (ExitRead): для завершения передачи Diagnostic Management вызывает ExitRead() [SWS_DM_01523] AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 «ExitRead». Передаются причина завершения (exit_type типа DataTransferExitType), специфичные для автопроизводителя параметры (transfer_request_parameter_record в виде ara::core::Span<const ara::core::Byte>), meta_info и cancellation_handler. Приложение подтверждает завершение асинхронно через возвращаемое future.
  4. Освобождение: уничтожение объекта обработчика разрешается только после завершения ExitRead() [SWS_DM_01519].

Диаграмма последовательности: типичный порядок вызовов при передаче чтения на основе push от инициализации до освобождения. Источники: [SWS_DM_01516], [SWS_DM_01519], [SWS_DM_01522], [SWS_DM_01523], AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 «ExitRead», AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 «Read»

Сценарии ошибок

При обработке ошибок и исключительных условий необходимо соблюдать следующие требования:

  • Коды отрицательного ответа (NRC): оба основных метода (Read и ExitRead) объявлены как noexcept и не генерируют исключений C++ [SWS_DM_01522], [SWS_DM_01523]. При возникновении ошибки возвращаемое ara::core::Future разрешается с ara::core::ErrorCode из домена DiagUdsNrcErrc согласно ISO 14229-1, чтобы передать клиенту определенный NRC.
  • Обработка отмены: методы получают CancellationHandler [SWS_DM_01522], [SWS_DM_01523]. Приложение может с помощью cancellation_handler.IsCanceled() запросить состояние отмены или через cancellation_handler.SetNotifier() зарегистрировать функцию уведомления. Если сигнализируется отмена, дальнейшую подготовку данных следует прекратить.
  • Срок действия параметров: параметр transfer_request_parameter_record, переданный в ExitRead(), действителен только до тех пор, пока не будет выполнено соответствующее promise или пока обработка не будет отменена с помощью CancellationHandler [SWS_DM_01523]. Доступ за пределами этого временного окна недопустим.
  • Нарушение предусловия уничтожения: если экземпляр уничтожается до вызова ExitRead(), это является явным нарушением спецификации [SWS_DM_01519], которое может привести к несогласованному поведению в Diagnostic Management.

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform версии R25-11.
