Сигнализирует об успешном завершении операции, не возвращающей значения, или передает возникший код ошибки.

Класс ara::core::Result<void, E> специализирует паттерн Result для операций без возвращаемого значения и отображает либо успешное завершение, либо ошибку ([SWS_CORE_00811]). После выполнения вызывающая сторона проверяет статус успеха с помощью HasValue() ([SWS_CORE_00851]) или operator bool() и в случае ошибки обращается к содержащейся причине ошибки. В качестве обязательного граничного условия тип ошибки E должен соответствовать типу ara::core::ErrorCode, так как отличающиеся типы отклоняются еще во время компиляции.

Контекст

Шаблонный класс ara::core::Result<void, E> представляет собой частичную специализацию паттерна Result для операций, которые в случае успеха не передают возвращаемого значения (void), а исключительно сигнализируют об успехе или неудаче действия. Согласно определению типа, тип значения value_type всегда зафиксирован как void ([SWS_CORE_00811]), тогда как error_type представляет параметризованный тип ошибки E ([SWS_CORE_00812]). Для типа E действует функциональное требование: любое отклонение от ara::core::ErrorCode должно отклоняться реализацией как ошибка компиляции.

В AUTOSAR Adaptive Platform ara::core::Result<void, E> функционирует как стандартизированный возвращаемый тип для процедур с потенциальными ошибками и команд управления между вызывающими компонентами и исполняющими интерфейсами. Вместо классической обработки исключений C++ класс предлагает экономную с точки зрения ресурсов явную передачу ошибок, которая обеспечивает как прямой опрос состояния, так и функциональную маршрутизацию в тракте вызова.

Жизненный цикл

Экземпляр ara::core::Result<void, E> на протяжении всего своего жизненного цикла находится ровно в одном из двух дискретных состояний: состоянии значения (успех) или состоянии ошибки. Инициализация со значением void осуществляется через конструктор по умолчанию Result() ([SWS_CORE_00821]) или статический фабричный метод FromValue() ([SWS_CORE_00831]). Для создания в состоянии ошибки доступны явные конструкторы для lvalue и rvalue типа ошибки E ([SWS_CORE_00823], [SWS_CORE_00824]). Дополнительно фабричные функции FromError() обеспечивают конструирование из lvalue ошибки ([SWS_CORE_00834]), rvalue ([SWS_CORE_00835]) или путем прямого конструирования на месте (in-place) из пакетов параметров ([SWS_CORE_00836]).

Уже существующие экземпляры могут быть впоследствии переведены в состояние значения с помощью EmplaceValue() ([SWS_CORE_00843]) или напрямую наделены новой ошибкой с помощью EmplaceError() ([SWS_CORE_00844]). Конструкторы копирования и перемещения ([SWS_CORE_00825], [SWS_CORE_00826]), а также соответствующие операторы присваивания ([SWS_CORE_00841], [SWS_CORE_00842]) переносят состояние между экземплярами; Swap() выполняет обмен содержимым двух объектов ([SWS_CORE_00845]).

Деструктор ~Result() завершает жизненный цикл ([SWS_CORE_00827]) и является тривиальным, если справедливо std::is_trivially_destructible<E>::value. Что касается параллелизма, операции исключительно чтения являются потокобезопасными, тогда как операции, изменяющие состояние, такие как EmplaceValue(), EmplaceError(), присваивания или Swap(), не являются потокобезопасными.

Диаграмма состояний: жизненный цикл и переходы состояний между состоянием значения и состоянием ошибки. Источники: [SWS_CORE_00821], [SWS_CORE_00831], [SWS_CORE_00823], [SWS_CORE_00834], [SWS_CORE_00843], [SWS_CORE_00844]

Путь использования

Стандартный процесс начинается с получения экземпляра ara::core::Result<void, E> из вызова функции. Вызывающая сторона оценивает результат с помощью HasValue() ([SWS_CORE_00851]) или преобразования operator bool() ([SWS_CORE_00852]). При успешном выполнении через Bind() ([SWS_CORE_00870]) может быть функционально подключена последующая операция: Bind() выполняет переданный вызываемый объект (callable) только в том случае, если экземпляр содержит значение, и возвращает его преобразованный результат. Если же вместо этого присутствует ошибка, вызываемая функция пропускается, а содержимое ошибки переносится в новый результат.

Для унификации в обобщенном коде специализация предоставляет интерфейсы, формально соответствующие общему классу Result: Value() ([SWS_CORE_00855]), operator*() ([SWS_CORE_00853]) и ValueOr() ([SWS_CORE_00861]) не возвращают значения и действуют как методы no-op. Аналогично Resolve() ([SWS_CORE_00867]) выполняет переданный callable только при наличии ошибки и остается неактивным в случае успеха.

Диаграмма последовательности: типичная последовательность вызова, проверки статуса и обработки ошибки либо дальнейшей передачи. Источники: [SWS_CORE_00851], [SWS_CORE_00857], [SWS_CORE_00868], [SWS_CORE_00870]

Сценарии ошибок

Если экземпляр находится в состоянии ошибки, содержащаяся ошибка может быть запрошена в виде ссылки через перегрузки Error() ([SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876]). При этом действует строгое предусловие: вызов Error() для экземпляра, не содержащего ошибки, представляет собой ResultWithNoErrorViolation. И наоборот, вызов Value() ([SWS_CORE_00855]) или operator*() ([SWS_CORE_00853]) для экземпляра в состоянии ошибки вызывает ResultWithNoValueViolation.

Чтобы избежать нарушений предусловий, предлагаются альтернативные методы запроса: Err() возвращает ошибку, упакованную в ara::core::Optional<E>, который в случае успеха остается пустым ([SWS_CORE_00868], [SWS_CORE_00869]). С помощью ErrorOr() можно указать ошибку по умолчанию, которая возвращается, если ошибка не содержится ([SWS_CORE_00863], [SWS_CORE_00864]). Для проверок на определенные значения ошибок CheckError() сопоставляет внутреннюю ошибку со значением для сравнения ([SWS_CORE_00865]).

Если предпочтительна обработка ошибок на основе исключений, ValueOrThrow() ([SWS_CORE_00866]) в случае ошибки генерирует исключение, сопоставленное этой ошибке; при наличии значения вызов завершается штатно. Если исключения C++ отключены в цепочке инструментов (toolchain), ValueOrThrow() не участвует в разрешении перегрузок ([SWS_CORE_00866]).

Использование и контекст вызова

Функция-член Bind специализации ara::core::Result<void, E> из ara/core/result.h выполняет последующее вычисление на успешном экземпляре без значения результата [SWS_CORE_00870]. Если значение присутствует, переданный callable f вызывается синхронно и без параметров. Callable должен удовлетворять либо интерфейсу Result<XXX, E> f(), либо XXX f(), где XXX должен быть допустимым типом для Result [SWS_CORE_00870]. Если callable возвращает Result, тип возвращаемого значения соответствует decltype(f()); если он возвращает напрямую XXX, результат упаковывается как Result<decltype(f()), E> [SWS_CORE_00870].

Обработка ошибок и параллелизм

Если экземпляр не содержит значения, возвращается новый Result<XXX, E>, в который копируется исходная ошибка [SWS_CORE_00870]. Интерпретация: в этом случае выполнение callable f, вероятно, не происходит. Вопрос Q-6288a7106d2730c3 (открытый) В плане безопасности выполнения функция считается not exception safe [SWS_CORE_00870]. Потокобезопасность является условной (conditional) и полностью зависит от потокобезопасности переданного callable f [SWS_CORE_00870].

Взаимодействие со связанными требованиями

В отличие от первичных функций Result<T, E> из [SWS_CORE_00768] и [SWS_CORE_00941], в которых callable принимает значение экземпляра через f(const T&), данная перегрузка [SWS_CORE_00870] привязывает операции к результатам void и поэтому ожидает callable без параметров.

      Функция-член EmplaceError специализации ara::core::Result<void, E> синхронно конструирует новое значение ошибки непосредственно in-place внутри существующего экземпляра из переданных аргументов args [SWS_CORE_00844].       Что касается обработки ошибок и безопасности относительно исключений, операция классифицирована как условно безопасная относительно исключений (conditionally exception safe) [SWS_CORE_00844]. С помощью спецификатора noexcept(std::is_nothrow_constructible<E, Args...>::value) отсутствие исключений гарантируется при условии, что тип E может быть сконструирован с типами Args... без исключений [SWS_CORE_00844].
      
  
      В отношении многопоточности и граничных условий функция-член определена как непотокобезопасная (not thread-safe) [SWS_CORE_00844]. Если несколько потоков параллельно обращаются к одному и тому же экземпляру Result, для предотвращения нескоординированных изменений состояния, вероятно, требуется внешний механизм синхронизации.           Использование и контекст вызова
          
  
          Шаблонная функция-член EmplaceValue принадлежит модулю core и определяется через заголовочный файл #include "ara/core/result.h" для специализации ara::core::Result<void, E> [SWS_CORE_00843]. Поскольку типом значения специализации является void, вызов переводит экземпляр в состояние успеха; в качестве интерпретации прием args, вероятно, служит главным образом для совместимости сигнатуры на обобщенном уровне с первичным классом шаблона. Вопрос Q-b53ca5908f2517fb (открытый)
          

  
          Обработка ошибок и безопасность исключений
          
  
          Функция объявлена как noexcept и имеет спецификацию exception safe [SWS_CORE_00843]. Она не возвращает кодов ошибок и не генерирует исключений. Если объект Result ранее находился в состоянии ошибки, оно перезаписывается установкой значения.
          

  
          Параллелизм и ограничения
          
  
          Операция обозначена как непотокобезопасная (not thread-safe) [SWS_CORE_00843]. При потенциально параллельных обращениях на чтение или запись к одному и тому же экземпляру ara::core::Result внешняя синхронизация со стороны вызывающего кода является строго обязательной.
          

  
          Взаимодействие со смежными спецификациями

                                      Функция-член ErrorOr специализации ara::core::Result<void, E> служит для синхронного считывания ошибки из rvalue-экземпляра ([SWS_CORE_00864]).                                                                                                                           Шаблонная функция-член CheckError специализации ara::core::Result<void, E> синхронно проверяет, содержит ли текущий экземпляр определенную ошибку [SWS_CORE_00865]. Для этого переданный аргумент error преобразуется с помощью static_cast в тип ошибки E и сравнивается с возвращаемым значением внутреннего состояния ошибки Error() [SWS_CORE_00865]. Вызов осуществляется через заголовок #include "ara/core/result.h" [SWS_CORE_00865].
                                                                                                                          
  
                                                                                                                          Для использования и контекста вызова действуют следующие свойства:
                                                                                                                          
  
                                                                                                                            
    
                                                                                                                          • Параметры и возвращаемое значение: универсальный ссылочный параметр error типа G&& принимает проверяемую ошибку [SWS_CORE_00865]. Функция возвращает true, если экземпляр содержит ошибку, эквивалентную error, и false в противном случае [SWS_CORE_00865].
                                                                                                                            • 
    
                                                                                                                          • Многопоточность и безопасность относительно исключений: операция объявлена как const noexcept, считается безопасной относительно исключений (exception safe) и может безоговорочно вызываться потокобезопасно (thread-safe) [SWS_CORE_00865].
                                                                                                                            • 
  
                                                                                                                          
  
                                                                                                                          Во взаимодействии с модулем core существуют аналогичные перегрузки CheckError: первичный класс шаблона ara::core::Result предоставляет ту же сигнатуру также потокобезопасно и с безопасностью относительно исключений с noexcept [SWS_CORE_00765]. В отличие от этого специализация для ссылок ara::core::Result<T&, E> хоть и обладает тем же механизмом сравнения и является потокобезопасной, однако явно специфицирована без noexcept как небезопасная относительно исключений (not exception safe) [SWS_CORE_00937].
                                                                                                                          

                                                                                                                          

                                                                                                                          Это указание по использованию было сгенерировано автоматически на основе требований спецификации.
