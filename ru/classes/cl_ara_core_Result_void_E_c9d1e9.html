Контекст

Специализация шаблонного класса ara::core::Result<void, E> представляет результат операций, которые при успешном выполнении не возвращают полезных данных, а лишь сигнализируют об успехе или возникновении ошибки. В рамках AUTOSAR Adaptive Platform она служит стандартизированным типом возвращаемого значения для функций с семантикой void и обеспечивает структурированную обработку ошибок без исключений C++. Тип значения жестко задан через псевдоним типа как value_type = void [SWS_CORE_00811], в то время как тип ошибки параметризуется через псевдоним типа error_type = E [SWS_CORE_00812]. Реализация во время компиляции принудительно обеспечивает, чтобы условия с E != ara::core::ErrorCode приводили к ошибке компилятора.

В качестве стандартизированного типа результата данный класс образует интерфейс между вызывающими компонентами приложения и исполняющими службами платформы или приложения. Он гарантирует, что операции, не возвращающие значения, используют ту же единую концепцию интерфейса и функциональную дальнейшую обработку, что и возвращающие значение специализации ara::core::Result.

Жизненный цикл

Экземпляр ara::core::Result<void, E> в любой момент времени находится ровно в одном из двух различных состояний: он представляет либо успешное выполнение (состояние со значением void), либо состояние ошибки с содержащимся объектом ошибки типа E.

Создание экземпляра с успешным результатом осуществляется через конструктор по умолчанию без параметров [SWS_CORE_00821] или статический фабричный метод FromValue() [SWS_CORE_00831]. Состояние ошибки устанавливается при конструировании путем передачи объекта ошибки в виде lvalue [SWS_CORE_00823] или rvalue [SWS_CORE_00824]. Дополнительно статические методы FromError() предоставляют фабрики, создающие ошибки путем копирования [SWS_CORE_00834], перемещения [SWS_CORE_00835] или на месте из аргументов [SWS_CORE_00836]. Последняя перегрузка ограничена через SFINAE и участвует в разрешении только в том случае, если E может быть сконструирован из аргументов, а первый аргумент не является ни E, ни специализацией Result [SWS_CORE_00836].

Класс обладает полноценной семантикой значений и перемещения благодаря конструктору копирования [SWS_CORE_00825], оператору присваивания с копированием [SWS_CORE_00841], конструктору перемещения [SWS_CORE_00826] и оператору присваивания с перемещением [SWS_CORE_00842]. Существующие экземпляры могут быть перезаписаны с изменением состояния: EmplaceValue() переводит экземпляр в состояние со значением void [SWS_CORE_00843], тогда как EmplaceError() конструирует ошибку на месте [SWS_CORE_00844]. С помощью Swap() можно обменять значениями два экземпляра [SWS_CORE_00845].

Деструктор ~Result() является тривиальным, если выполняется std::is_trivially_destructible<E>::value [SWS_CORE_00827]. Что касается параллелизма, немодифицирующие обращения, такие как HasValue() [SWS_CORE_00851], и доступ к ошибке через lvalue Error() const & [SWS_CORE_00857] являются потокобезопасными. Модифицирующие вызовы, такие как EmplaceValue() [SWS_CORE_00843], EmplaceError() [SWS_CORE_00844], Swap() [SWS_CORE_00845], а также операции перемещения [SWS_CORE_00826], [SWS_CORE_00835], [SWS_CORE_00842], явно не являются потокобезопасными.

Диаграмма состояний: жизненный цикл и переходы между состояниями экземпляра ara::core::Result<void, E>. Источники: [SWS_CORE_00821], [SWS_CORE_00823], [SWS_CORE_00831], [SWS_CORE_00834], [SWS_CORE_00843], [SWS_CORE_00844], [SWS_CORE_00827].

Путь использования

Типичный процесс использования подразделяется на создание возвращаемого значения поставщиком службы, проверку вызывающим компонентом и условную дальнейшую обработку:

  1. Создание результата: функция успешно завершает операцию и создает возвращаемый объект через Result::FromValue() [SWS_CORE_00831] или конструктор по умолчанию [SWS_CORE_00821]. Если операция завершается неудачно, она возвращает результат через Result::FromError(...) [SWS_CORE_00834].
  2. Проверка состояния: вызывающий компонент проверяет наличие успеха через HasValue() [SWS_CORE_00851] или логическое преобразование operator bool() [SWS_CORE_00852], которые возвращают true при успехе и false при ошибке. Конкретные значения ошибок можно напрямую сопоставить с CheckError() [SWS_CORE_00865].
  3. Монадическая цепочка: при успешном исходе через Bind() может быть вызвана последующая функция [SWS_CORE_00870]. Переданная вызываемая функция выполняется только в том случае, если экземпляр содержит значение void; если присутствует ошибка, функция не вызывается, а существующее содержимое ошибки копируется в новый объект результата [SWS_CORE_00870].
  4. Запрос ошибки и разрешение: метод Resolve() в случае успеха не выполняет никаких действий, однако в случае ошибки вызывает переданную вызываемую функцию с const E& [SWS_CORE_00867]. Кроме того, содержащуюся ошибку можно запросить через Err() как ara::core::Optional<E> [SWS_CORE_00868], [SWS_CORE_00869] или подстраховать с помощью ErrorOr() резервной ошибкой [SWS_CORE_00863], [SWS_CORE_00864].

Диаграмма последовательности: типичный процесс вызова, проверки состояния и ветвления с помощью Bind() или Error(). Источники: [SWS_CORE_00831], [SWS_CORE_00834], [SWS_CORE_00851], [SWS_CORE_00857], [SWS_CORE_00870].

Сценарии ошибок

При доступе к экземплярам ara::core::Result<void, E> действуют строгие предусловия для предотвращения нарушений во время выполнения:

  • Доступ к отсутствующему значению (ResultWithNoValueViolation): методы Value() [SWS_CORE_00855] и operator*() [SWS_CORE_00853] существуют для обобщенного программирования и возвращают void. Если экземпляр не содержит значения (то есть сохраняет ошибку), вызов обеих функций приводит к возникновению ResultWithNoValueViolation [SWS_CORE_00853], [SWS_CORE_00855]. Функция ValueOr() обобщенно не выполняет никаких действий и не вызывает нарушения [SWS_CORE_00861].
  • Доступ к отсутствующей ошибке (ResultWithNoErrorViolation): прямой доступ к объекту ошибки через перегрузки Error() [SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876] требует, чтобы экземпляр содержал ошибку. Если вместо этого присутствует значение void, это приводит к ResultWithNoErrorViolation.
  • Генерация исключения через ValueOrThrow: ValueOrThrow() генерирует исключение, связанное с содержащейся ошибкой, если значение отсутствует [SWS_CORE_00866]. Если исключения C++ отключены в цепочке инструментов компилятора, эта функция не участвует в разрешении перегрузки [SWS_CORE_00866].
  • Безопасность относительно исключений функциональных объектов: операции Bind() [SWS_CORE_00870] и Resolve() [SWS_CORE_00867] специфицированы как небезопасные относительно исключений; их потокобезопасность условно зависит от потокобезопасности каждого переданного вызываемого объекта.

Настоящее руководство основано на спецификации AUTOSAR Adaptive R25-11 для ara::core::Result<void, E>.

<h4>Контекст</h4>
<p>Специализация шаблонного класса <code>ara::core::Result&lt;void, E&gt;</code> представляет результат операций, которые при успешном выполнении не возвращают полезных данных, а лишь сигнализируют об успехе или возникновении ошибки. В рамках AUTOSAR Adaptive Platform она служит стандартизированным типом возвращаемого значения для функций с семантикой void и обеспечивает структурированную обработку ошибок без исключений C++. Тип значения жестко задан через псевдоним типа как <code>value_type = void</code> <a class="spec-record-ref" data-req="SWS_CORE_00811" href="../spec/record.html?id=SWS_CORE_00811">[SWS_CORE_00811]</a>, в то время как тип ошибки параметризуется через псевдоним типа <code>error_type = E</code> <a class="spec-record-ref" data-req="SWS_CORE_00812" href="../spec/record.html?id=SWS_CORE_00812">[SWS_CORE_00812]</a>. Реализация во время компиляции принудительно обеспечивает, чтобы условия с <code>E != ara::core::ErrorCode</code> приводили к ошибке компилятора.</p>
<p>В качестве стандартизированного типа результата данный класс образует интерфейс между вызывающими компонентами приложения и исполняющими службами платформы или приложения. Он гарантирует, что операции, не возвращающие значения, используют ту же единую концепцию интерфейса и функциональную дальнейшую обработку, что и возвращающие значение специализации <code>ara::core::Result</code>.</p>

<h4>Жизненный цикл</h4>
<p>Экземпляр <code>ara::core::Result&lt;void, E&gt;</code> в любой момент времени находится ровно в одном из двух различных состояний: он представляет либо успешное выполнение (состояние со значением void), либо состояние ошибки с содержащимся объектом ошибки типа <code>E</code>.</p>
<p>Создание экземпляра с успешным результатом осуществляется через конструктор по умолчанию без параметров <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> или статический фабричный метод <code>FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a>. Состояние ошибки устанавливается при конструировании путем передачи объекта ошибки в виде lvalue <a class="spec-record-ref" data-req="SWS_CORE_00823" href="../spec/record.html?id=SWS_CORE_00823">[SWS_CORE_00823]</a> или rvalue <a class="spec-record-ref" data-req="SWS_CORE_00824" href="../spec/record.html?id=SWS_CORE_00824">[SWS_CORE_00824]</a>. Дополнительно статические методы <code>FromError()</code> предоставляют фабрики, создающие ошибки путем копирования <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>, перемещения <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a> или на месте из аргументов <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>. Последняя перегрузка ограничена через SFINAE и участвует в разрешении только в том случае, если <code>E</code> может быть сконструирован из аргументов, а первый аргумент не является ни <code>E</code>, ни специализацией <code>Result</code> <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>.</p>
<p>Класс обладает полноценной семантикой значений и перемещения благодаря конструктору копирования <a class="spec-record-ref" data-req="SWS_CORE_00825" href="../spec/record.html?id=SWS_CORE_00825">[SWS_CORE_00825]</a>, оператору присваивания с копированием <a class="spec-record-ref" data-req="SWS_CORE_00841" href="../spec/record.html?id=SWS_CORE_00841">[SWS_CORE_00841]</a>, конструктору перемещения <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a> и оператору присваивания с перемещением <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>. Существующие экземпляры могут быть перезаписаны с изменением состояния: <code>EmplaceValue()</code> переводит экземпляр в состояние со значением void <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, тогда как <code>EmplaceError()</code> конструирует ошибку на месте <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>. С помощью <code>Swap()</code> можно обменять значениями два экземпляра <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>.</p>
<p>Деструктор <code>~Result()</code> является тривиальным, если выполняется <code>std::is_trivially_destructible&lt;E&gt;::value</code> <a class="spec-record-ref" data-req="SWS_CORE_00827" href="../spec/record.html?id=SWS_CORE_00827">[SWS_CORE_00827]</a>. Что касается параллелизма, немодифицирующие обращения, такие как <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a>, и доступ к ошибке через lvalue <code>Error() const &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a> являются потокобезопасными. Модифицирующие вызовы, такие как <code>EmplaceValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, <code>EmplaceError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>, <code>Swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>, а также операции перемещения <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>, явно не являются потокобезопасными.</p>

<h4>Путь использования</h4>
<p>Типичный процесс использования подразделяется на создание возвращаемого значения поставщиком службы, проверку вызывающим компонентом и условную дальнейшую обработку:</p>
<ol>
<li><strong>Создание результата:</strong> функция успешно завершает операцию и создает возвращаемый объект через <code>Result::FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> или конструктор по умолчанию <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a>. Если операция завершается неудачно, она возвращает результат через <code>Result::FromError(...)</code> <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>.</li>
<li><strong>Проверка состояния:</strong> вызывающий компонент проверяет наличие успеха через <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> или логическое преобразование <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00852" href="../spec/record.html?id=SWS_CORE_00852">[SWS_CORE_00852]</a>, которые возвращают <code>true</code> при успехе и <code>false</code> при ошибке. Конкретные значения ошибок можно напрямую сопоставить с <code>CheckError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00865" href="../spec/record.html?id=SWS_CORE_00865">[SWS_CORE_00865]</a>.</li>
<li><strong>Монадическая цепочка:</strong> при успешном исходе через <code>Bind()</code> может быть вызвана последующая функция <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>. Переданная вызываемая функция выполняется только в том случае, если экземпляр содержит значение void; если присутствует ошибка, функция не вызывается, а существующее содержимое ошибки копируется в новый объект результата <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>.</li>
<li><strong>Запрос ошибки и разрешение:</strong> метод <code>Resolve()</code> в случае успеха не выполняет никаких действий, однако в случае ошибки вызывает переданную вызываемую функцию с <code>const E&amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a>. Кроме того, содержащуюся ошибку можно запросить через <code>Err()</code> как <code>ara::core::Optional&lt;E&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_00868" href="../spec/record.html?id=SWS_CORE_00868">[SWS_CORE_00868]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00869" href="../spec/record.html?id=SWS_CORE_00869">[SWS_CORE_00869]</a> или подстраховать с помощью <code>ErrorOr()</code> резервной ошибкой <a class="spec-record-ref" data-req="SWS_CORE_00863" href="../spec/record.html?id=SWS_CORE_00863">[SWS_CORE_00863]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00864" href="../spec/record.html?id=SWS_CORE_00864">[SWS_CORE_00864]</a>.</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>При доступе к экземплярам <code>ara::core::Result&lt;void, E&gt;</code> действуют строгие предусловия для предотвращения нарушений во время выполнения:</p>
<ul>
<li><strong>Доступ к отсутствующему значению (ResultWithNoValueViolation):</strong> методы <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a> и <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a> существуют для обобщенного программирования и возвращают <code>void</code>. Если экземпляр не содержит значения (то есть сохраняет ошибку), вызов обеих функций приводит к возникновению <code>ResultWithNoValueViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a>. Функция <code>ValueOr()</code> обобщенно не выполняет никаких действий и не вызывает нарушения <a class="spec-record-ref" data-req="SWS_CORE_00861" href="../spec/record.html?id=SWS_CORE_00861">[SWS_CORE_00861]</a>.</li>
<li><strong>Доступ к отсутствующей ошибке (ResultWithNoErrorViolation):</strong> прямой доступ к объекту ошибки через перегрузки <code>Error()</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00858" href="../spec/record.html?id=SWS_CORE_00858">[SWS_CORE_00858]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00876" href="../spec/record.html?id=SWS_CORE_00876">[SWS_CORE_00876]</a> требует, чтобы экземпляр содержал ошибку. Если вместо этого присутствует значение void, это приводит к <code>ResultWithNoErrorViolation</code>.</li>
<li><strong>Генерация исключения через ValueOrThrow:</strong> <code>ValueOrThrow()</code> генерирует исключение, связанное с содержащейся ошибкой, если значение отсутствует <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>. Если исключения C++ отключены в цепочке инструментов компилятора, эта функция не участвует в разрешении перегрузки <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>.</li>
<li><strong>Безопасность относительно исключений функциональных объектов:</strong> операции <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a> и <code>Resolve()</code> <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a> специфицированы как небезопасные относительно исключений; их потокобезопасность условно зависит от потокобезопасности каждого переданного вызываемого объекта.</li>
</ul>
