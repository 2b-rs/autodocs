Служит для асимметричной верификации цифровых подписей в одношаговом или многоэтапном потоковом режиме.

Интерфейс ara::crypto::cryp::VerifierPublicCtx служит для верификации цифровых подписей с помощью асимметричных открытых ключей через одиночный вызов (one-shot) или многошаговый поток ([SWS_CRYPT_24112], [SWS_CRYPT_50022]). Перед верификацией контекст должен быть обязательно сконфигурирован с действительным ключом, назначенные права использования которого разрешают проверку подписи ([SWS_CRYPT_24115]). Все методы интерфейса разработаны как исключебнобезопасные и потокобезопасные.

Контекст

Интерфейс ara::crypto::cryp::VerifierPublicCtx служит для верификации цифровых подписей на основе асимметричной криптографии с использованием открытого ключа. Он напрямую взаимодействует с объектами ключей ([SWS_CRYPT_24115]) или внешними хранилищами ключей ([SWS_CRYPT_50018]) и предоставляет методы для проверки подписей либо за один шаг (one-shot), либо в потоковом режиме через несколько промежуточных шагов.

Жизненный цикл

Внутри приложения экземпляры контекста верификации обычно управляются через псевдоним типа умного указателя ara::crypto::cryp::VerifierPublicCtx::Sptr, который определен как std::shared_ptr<VerifierPublicCtx> ([SWS_CRYPT_24101]). Все методы интерфейса объявлены как исключебнобезопасные (exception safe) и потокобезопасные.

Контекст проходит четко разграниченные фазы работы. После создания экземпляр контекста находится в неинициализированном состоянии, в котором вызовы верификации отклоняются с ошибкой ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50019], [SWS_CRYPT_24112]). Только после назначения подходящего ключа с помощью SetKey() контекст переходит в состояние готовности к работе ([SWS_CRYPT_24115], [SWS_CRYPT_50018]). Из этого состояния можно либо выполнить атомарную проверку, либо инициировать потоковый сеанс. После завершения ([SWS_CRYPT_50022]) или прерывания ([SWS_CRYPT_50023]) потокового процесса контекст, предположительно, снова готов к новым проверкам.

Диаграмма состояний: жизненный цикл и переходы состояний контекста верификации. Источники: [SWS_CRYPT_24115], [SWS_CRYPT_50018], [SWS_CRYPT_50019], [SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_50023], [SWS_CRYPT_24112]

Путь использования

Для проверки подписи доступны два взаимодополняющих пути обработки:

  • One-Shot-верификация: если полное сообщение находится в памяти, после назначения ключа через SetKey() ([SWS_CRYPT_24115]) можно напрямую вызвать Verify() ([SWS_CRYPT_24112]). Если алгоритм поддерживает или требует контекстные данные, специфичные для приложения, используется перегруженный вариант с дополнительным буфером контекста ([SWS_CRYPT_50024]). Оба варианта возвращают ara::core::Result<bool>, булево значение которого указывает на действительность подписи.
  • Потоковая верификация: при больших объемах данных или пошагово поступающих блоках данных после SetKey() сначала вызывается Start() ([SWS_CRYPT_50019], опционально с буфером контекста согласно [SWS_CRYPT_50020]). Затем фрагменты данных повторно подаются с помощью Update() ([SWS_CRYPT_50021]). Максимальный размер буфера для отдельных фрагментов может быть предварительно определен через GetMaximumChunkSize() ([SWS_CRYPT_50025]). Завершающим этапом является вызов Finish() с передачей подписи и идентификатора ее формата ([SWS_CRYPT_50022]). Текущий потоковый процесс можно в любой момент сбросить через Cancel() ([SWS_CRYPT_50023]).

Диаграмма последовательности: пошаговый процесс проверки подписи в потоковом режиме. Источники: [SWS_CRYPT_24115], [SWS_CRYPT_50019], [SWS_CRYPT_50021], [SWS_CRYPT_50022]

Сценарии ошибок

Все методы, изменяющие состояние и выполняющие верификацию, работают с ara::core::Result и обладают семантикой отката при ошибках:

  • Конфигурация ключа: при передаче несовместимого с алгоритмом ключа или KeySlot метод SetKey() возвращает ошибку CryptoErrc::kIncompatibleObject ([SWS_CRYPT_24115], [SWS_CRYPT_50018]). Если у ключа отсутствует право на использование kAllowSigVerification, вызов завершается с ошибкой CryptoErrc::kUsageViolation ([SWS_CRYPT_24115]). Кроме того, SetKey() сообщает CryptoErrc::kUnsupported, если контекст принимает исключительно другую форму ключа (KeySlot или PublicKey соответственно).
  • Ошибки последовательности и предусловий: если Update(), Finish() или Cancel() вызываются без предшествующего успешного вызова Start(), они завершаются с ошибкой CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_50023]). Вызов Start() или Verify() без предшествующего связывания ключа приводит к CryptoErrc::kUninitializedContext ([SWS_CRYPT_50019], [SWS_CRYPT_24112]). Для используемых ссылками, но пустых KeySlot возвращается CryptoErrc::kEmptyKeySlot.
  • Ошибки данных и формата: на некорректные размеры буфера методы реагируют возвратом CryptoErrc::kInvalidInputSize ([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_24112]). Неподдерживаемые форматы подписи вызывают CryptoErrc::kUnsupportedFormat, тогда как структурно поврежденные подписи приводят к CryptoErrc::kInvalidArgument ([SWS_CRYPT_50022], [SWS_CRYPT_24112]). При занятых аппаратных ресурсах возвращается CryptoErrc::kBusyResource.

Настоящее руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform R25-11.

Использование и семантика

Метод Cancel() прерывает текущую потоковую операцию, которая была ранее инициирована с помощью Start() и ещё не завершена [SWS_CRYPT_50023]. Он определён в заголовочном файле ara/crypto/cryp/verifier_public_ctx.h как чисто виртуальный метод контекста ara::crypto::cryp::VerifierPublicCtx [SWS_CRYPT_50023]. Вызов выполняется синхронно и без аргументов. В качестве возвращаемого значения служит ara::core::Result<void>, которое в случае успеха является пустым и подтверждает успешное прерывание операции [SWS_CRYPT_50023].

Обработка ошибок

Если обработка данных ещё не была начата вызовом метода Start(), операция прерывания завершается сбоем. В этом сценарии функция возвращает ошибочный результат с кодом ошибки ara::crypto::CryptoErrc::kProcessingNotStarted с обеспечением семантики отката [SWS_CRYPT_50023].

Параллелизм и ограничения

Спецификация определяет метод как потокобезопасный (thread-safe) и исключениебезопасный (exception safe) с обозначением noexcept [SWS_CRYPT_50023]. Интерпретация: после успешного прерывания контекст, по всей видимости, должен вернуться в исходное состояние до начала обработки, что позволяет запустить новый процесс потоковой передачи.

Взаимодействие в модуле crypt

Этот единообразный шаблон прерывания с идентичной сигнатурой и обработкой ошибок согласованно применяется ко всем потоковым контекстам модуля crypt:

  • MessageAuthnCodeCtx для кодов аутентификации сообщений (Message Authentication Codes) [SWS_CRYPT_50027],
  • SignerPrivateCtx для формирования цифровых подписей [SWS_CRYPT_50041],
  • SymmetricCipherCtx для симметричного шифрования и дешифрования [SWS_CRYPT_50046],
  • HashFunctionCtx для криптографических хеш-операций [SWS_CRYPT_50058],
  • DecryptorPrivateCtx для асимметричного дешифрования [SWS_CRYPT_50069],
  • AuthCipherCtx для аутентифицированного шифрования [SWS_CRYPT_50077], а также
  • EncryptorPublicCtx для асимметричного шифрования [SWS_CRYPT_50089].
