Использование по назначению

SovdAuthorization реализует авторизацию SOVD на уровне приложения. GetAuthorizationUrl() и GetTokenUrl() возвращают URL соответственно для авторизации и запроса Token; DM отвечает на это HTTP 307 и заголовком Location с данным URL. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] ValidateAuthorization() валидирует Token из HTTP-Authorization-Header и помечает авторизованные роли в переданном ClientAuthentication. [SWS_DM_01483] [SWS_DM_01470]

Создание & жизненный цикл

Конструктор связывает PortPrototype DiagnosticSovdAuthorizationInterface и принимает ConcurrencyType. [SWS_DM_01489] Offer() активирует переадресацию, StopOffer() снова ее деактивирует. Предложение может поставить kAlreadyOffered или kConfigurationMismatch. [SWS_DM_01487] [SWS_DM_01486] Деструктор защищен от исключений. [SWS_DM_01488]

SOVD контекст доступа

Авторизация SOVD использует OAuth-Token в заголовке Request. Для такого Request Diagnostic Manager использует SovdAuthorization, чтобы запросить у приложения закодированную роль авторизации; на основании этой роли он принимает решение о разрешении запрошенной операции SOVD. EXP SOVD §3.2.1 «Access Permissions»

Схема последовательности: авторизация SOVD с использованием токена OAuth и получение роли, описанные в документе. Источник: EXP SOVD §3.2.1 «Access Permissions». Интерпретация: В последнем сообщении суммируется решение об авторизации, описанное в тексте как «Разрешить/Отклонить».

функция ValidateAuthorization [SWS_DM_01483] Upstream: RS_Diag_04268

virtual ara::core::Future< ValidateAuthorizationOutput > Validate Authorization (ara::core::StringView token, const MetaInfo &metaInfo, ClientAuthentication &clientAuthentication) noexcept=0;

This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.

Используйте Сгенерировано ИИ / AI generated

Автоматически сформированное примечание по использованию, выведенное из этого элемента спецификации AUTOSAR R25-11, — не официальный текст AUTOSAR. Подтверждение: [SWS_…].

Виртуальный метод ValidateAuthorization проверяет Token (token), отправленный SOVD-клиентом через HTTP-Authorization-Header, в соответствии с используемым в системе протоколом авторизации; в случае OAuth 2.0 это соответствует проверке Resource Server. На основании результата приложение устанавливает соответствующие роли как авторизованные в объекте, переданном параметром clientAuthentication [SWS_DM_01483]. Дополнительно передаётся metaInfo диагностического порта. Возвращаемый ara::core::Future<ValidateAuthorizationOutput> в случае успеха предоставляет результат проверки, иначе ошибку.

Обработка ошибок & параллелизм

Если токен доступа недействителен, возвращается DiagSovdErrc::kInvalidAccessToken; Если в настоящий момент его невозможно проверить (например, поскольку необходима онлайн-проверка, но сервер аутентификации недоступен), доставляется DiagSovdErrc::kTemporarilyNotAvailable. После того, как будущее наступит, clientAuthentication больше не может использоваться приложением. ConcurrencyType, переданный в конструктор, определяет, должна ли реализация быть потокобезопасной или нет; метод защищен от исключений.
