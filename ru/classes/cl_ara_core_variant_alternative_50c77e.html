Спецификация отражает std::variant_alternative 1:1: Помимо основного шаблона [SWS_CORE_01607], существуют частичные специализации variant_alternative< I, Variant< Types... > > [SWS_CORE_01611], variant_alternative< I, const T > [SWS_CORE_01608], variant_alternative< I, volatile T > [SWS_CORE_01609] и variant_alternative< I, const volatile T > [SWS_CORE_01610] как а также псевдоним variant_alternative_t [SWS_CORE_01612]. Все записи описывают контент исключительно с помощью «As per corresponding usage in [variant]» и имеют статус ЧЕРНОВИК. Отдельный признак по-прежнему необходим, поскольку ara::core::Variant является отдельным типом: std::variant_alternative специализируется только на std::variant, а сигнатуры get [SWS_CORE_01613], get_if [SWS_CORE_01621] и Variant::emplace [SWS_CORE_01663] формулируются через variant_alternative_t.

Интерпретация: Для кода приложения практически значим только variant_alternative_t; сам Trait редко инстанцируется непосредственно. cv-специализации отражают состояние C++17 для [variant] — в стандарте ISO формы volatile и const volatile с C++20 отмечены как устаревшие (P1831R1 «Deprecating volatile: library»), предложено их удаление (P2866 «Remove Deprecated Volatile Features»); форма const остаётся без изменений. То, что AUTOSAR без изменений включает все четыре cv-формы в R25-11, следует понимать как полноту относительно C++17, а не как рекомендацию по применению: новый код должен применять Trait только к неквалифицированным типам Variant и избегать типов Variant с квалификатором volatile. Единый статус DRAFT также означает, что интерфейс формально ещё не является обязательным и может измениться в будущих релизах.
