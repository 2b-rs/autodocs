Контекст

Класс ara::core::FutureException в модуле core AUTOSAR Adaptive Platform выступает в качестве специализированного типа исключений для состояний ошибок в рамках асинхронных операций. Согласно спецификации, это исключение генерируется ara::core::Future и ara::core::Promise для структурированного информирования вызывающих компонентов о возникших ошибочных условиях. В общей архитектуре Adaptive Platform класс, по всей видимости, образует функциональный мост между обработкой ошибок на основе кодов и смоделированным механизмом исключений: он наследуется от базового класса Exception и инкапсулирует конкретное состояние ошибки в форме ara::core::ErrorCode [SWS_CORE_00412].

В асинхронном взаимодействии обычно участвуют создающий контекст через ara::core::Promise, потребляющий контекст через ara::core::Future, а также вышестоящее приложение. Если асинхронная обработка завершается сбоем или запрашивается недопустимое состояние, ara::core::FutureException служит носителем сигнала. Благодаря предоставлению через заголовочный файл ara/core/future_error_domain.h исключение находится в тесной связке со специфичными для домена определениями ошибок для асинхронных процессов [SWS_CORE_00412].

Контекстная диаграмма: классификация ara::core::FutureException и её связи с Future, Promise, Exception и ErrorCode. Источники: [SWS_CORE_00412]

Жизненный цикл

Жизненный цикл экземпляра ara::core::FutureException начинается с его создания через специфицированный для этого конструктор, принимающий инициализирующий ara::core::ErrorCode [SWS_CORE_00412]. Объявление как explicit предотвращает непреднамеренные неявные преобразования типов из кодов ошибок в объекты исключений и гарантирует, что создание всегда происходит осознанно [SWS_CORE_00412]. Конструктор также объявлен как noexcept, тем самым гарантируя полную исключительную безопасность при создании объекта [SWS_CORE_00412].

Что касается работы в параллельных системах, класс согласно спецификации классифицирован как thread-safe [SWS_CORE_00412]. Это свойство существенно для его назначения, поскольку ara::core::Promise и ara::core::Future штатно выполняются в раздельных потоках. При возникновении исключения объект инстанцируется в среде выполнения C++. Владение во время раскрутки стека передаётся по иерархии вызовов обрабатывающему блоку catch, где объект исключения автоматически уничтожается после выхода из блока исключения.

Путь использования

Регулярный путь использования ara::core::FutureException разворачивается вдоль цепочки вызовов асинхронных задач. Обычно компонент приложения инициирует асинхронную операцию, результат которой управляется через связанную пару из ara::core::Promise и ara::core::Future. Если при выполнении задачи или запросе результата возникает ошибочная ситуация, генерируется исключение.

В типичном сценарии потребитель пытается получить результат через ara::core::Future. Если в базовом ara::core::Promise отсутствует валидный результат или зафиксировано состояние ошибки, это обращение приводит к генерации ara::core::FutureException. При этом конструктор обязательно требует передачи соответствующего кода ошибки err [SWS_CORE_00412]. Потребляющее приложение перехватывает исключение в подходящем обработчике исключений. Предположительно, вызывающие компоненты могут анализировать инкапсулированный ara::core::ErrorCode, чтобы точно определить конкретную причину ошибки в домене ошибок и принять адекватные меры противодействия.

Сценарии ошибок

При использовании и обработке ara::core::FutureException определяющими являются следующие сценарии ошибок и гарантии системной безопасности:

  • Безопасное относительно исключений инстанцирование: поскольку конструктор отмечен как noexcept, создание самого объекта исключения никогда не даёт сбоя и не генерирует вторичных исключений [SWS_CORE_00412]. Это обеспечивает детерминированный переход к обработке исключений даже под нагрузкой.
  • Обязательное указание кода ошибки: класс не предоставляет конструктор по умолчанию без параметров; для инстанцирования обязательно требуется валидный ara::core::ErrorCode в качестве параметра [SWS_CORE_00412]. Таким образом, объект исключения без сохранённого кода ошибки не может быть создан.
  • Необработанные исключения: если сгенерированное ara::core::Future или ara::core::Promise исключение ara::core::FutureException не перехвачено подходящим блоком catch приложения, вступает в силу стандартное поведение среды выполнения C++, что приводит к завершению процесса. Поскольку класс открыто наследуется от Exception, он может перехватываться как специфично, так и полиморфно через ссылки на базовый класс.

Это руководство основано на данных спецификации AUTOSAR Adaptive Platform релиза R25-11.
