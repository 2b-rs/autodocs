Контекст

Структура <SI-Namespace>::proxy::methods::<Method>::Output служит в Adaptive Platform (модуль com) инкапсуляцией для выходных параметров (аргументов out) вызова метода на уровне клиента или прокси ([SWS_CM_99333], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output»). Если метод сервисного интерфейса определяет несколько возвращаемых значений или специфических выходных аргументов, платформа объединяет эти параметры в сгенерированной структуре Output вместо раздельной передачи отдельных значений.

Во взаимодействии в основном участвуют следующие компоненты:

  • Вызывающее клиентское приложение: инициирует вызов метода через экземпляр прокси и оценивает данные результата после завершения.
  • Прокси метода: функциональный объект <SI-Namespace>::proxy::methods::<Method>, который при вызове сериализует параметры и инициирует обмен данными.
  • Контейнер возвращаемого значения: объект ara::core::Future, который в случае успешного выполнения содержит инстанцированную структуру Output (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output»).
  • Ответная сторона скелетона: на стороне поставщика сервиса существует типизированный аналог {<hierarchical-namespace-list-lower-skeleton>}::skeleton::{<service-interface-name>}Skeleton::{<method-name>}Output ([SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.4.6 «Struct: {<method-name>}Output»), который также предоставляется поставщиком сервиса через Future (AUTOSAR_AP_SWS_CommunicationManagement §8.4.6).

Контекстная диаграмма: интеграция структуры Output в путь вызова и возврата прокси-метода. Источники: [SWS_CM_99333], [SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output».

Жизненный цикл

Жизненный цикл и управление состоянием экземпляра Output тесно связаны с вышестоящим объектом ara::core::Future и асинхронным обменом данными:

  • Создание: объект Output не инстанцируется кодом приложения вручную. Он создается коммуникационным уровнем после успешного приема и десериализации ответного сообщения поставщика услуг и помещается в соответствующий ara::core::Future (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output»).
  • Владение и передача: объект остается во Future до тех пор, пока вызывающее приложение не заберет результат через get() или GetResult(). В результате этого получения экземпляр Output переходит во владение вызывающего контекста клиента.
  • Прерывание и уничтожение: если вызывающая сторона преждевременно уничтожает возвращенный объект ara::core::Future, его деструктор приводит к прерыванию вызова метода ([SWS_CM_00194], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). В этом случае экземпляр Output не доставляется приложению, а обработка отменяется.

Путь использования

Стандартный процесс использования структуры Output делится на следующие этапы:

  1. Вызов метода: приложение вызывает объект прокси-метода operator()(...) с определенными входными аргументами.
  2. Получение объекта Future: в качестве непосредственного возвращаемого значения вызывающая сторона получает объект типа ara::core::Future<Output> (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output»).
  3. Синхронизация и опрос: вызывающая сторона синхронно блокируется или асинхронно ожидает завершения и запрашивает результат через get() или GetResult() ([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6).
  4. Обработка: при успешном выполнении приложение извлекает объект Output ([SWS_CM_99333]) и считывает содержащиеся в нем поля-члены выходных параметров.

Диаграмма последовательности: вызов прокси-метода и обработка структуры Output через объект Future. Источники: [SWS_CM_99333], [SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output».

Сценарии ошибок

В случае ошибок структура Output не передается вызывающей стороне:

  • Ошибки инфраструктуры и Future: если вызов метода завершается неудачно, результирующий ara::core::Future содержит не объект Output, а код ошибки, например ara::core::FutureErrc (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 «Struct: Output») либо ara::com::ComErrc или ApApplicationError (AUTOSAR_AP_SWS_CommunicationManagement §8.4.6).
  • Контролируемые ошибки приложения (Checked Errors): если во время обработки вызова метода возникает определенная проверяемая ошибка, соответствующий ara::core::ErrorCode возвращается в контексте вызова GetResult() либо get() ([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). В этой ветви экземпляр Output не конструируется.
  • Методы Fire-and-Forget: для вызовов Fire-and-Forget, согласно спецификации, проверяемых ошибок не существует ([SWS_CM_90436], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6); у таких методов в силу архитектуры системы также отсутствует структура Output, поскольку возвращаемые значения не передаются.

В этом руководстве по классу обобщены требования спецификации к структуре Proxy-Output на основе релиза R25-11.
