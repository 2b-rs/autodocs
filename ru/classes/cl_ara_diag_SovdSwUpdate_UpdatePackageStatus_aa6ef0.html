Предоставляет подробные данные о фазах, прогрессе и ошибках для мониторинга текущего пакета обновления программного обеспечения.

Структура ara::diag::SovdSwUpdate::UpdatePackageStatus предоставляет информацию о статусе, фазе и прогрессе процесса обновления программного обеспечения для диагностических приложений SOVD [SWS_DM_01902]. Она получается путем вызова GetUpdatePackageStatus и позволяет непрерывно отслеживать фазы выполнения, процентный прогресс, а также отдельные шаги. В случае ошибки структура сигнализирует о сбое и передает через опциональное поле ошибки точный код ошибки из домена DiagSovdErrc [SWS_DM_01909]. Будучи чистым объектом передачи данных, структура, предположительно, требует синхронизации на стороне приложения при конкурентном доступе.

Контекст

Структура данных ara::diag::SovdSwUpdate::UpdatePackageStatus является частью модуля diag AUTOSAR Adaptive Platform SWS Diagnostics §8.58.5 «Struct: UpdatePackageStatus» [SWS_DM_01902]. В рамках Service-Oriented Vehicle Diagnostics (SOVD) она служит стандартизированным носителем информации для сбора и предоставления текущего состояния пакета обновления программного обеспечения. Через функцию API ara::diag::SovdSwUpdate::GetUpdatePackageStatus объект статуса генерируется диагностическим интерфейсом и передается запрашивающим экземплярам SWS Diagnostics §8.58.2.1.3.5 «GetUpdatePackageStatus» [SWS_DM_01921].

В системной архитектуре структура служит элементом развязки между исполняющим сервисным компонентом SovdSwUpdate и внешними или внутренними диагностическими клиентами. В то время как сервис управляет непосредственной обработкой и установкой пакета, UpdatePackageStatus инкапсулирует снимок состояния по фазам обработки, прогрессу и возможным состояниям ошибок [SWS_DM_01902].

Жизненный цикл

Являясь чистым контейнером данных (struct), UpdatePackageStatus не имеет собственной внутренней логики состояний и не осуществляет самостоятельного управления ресурсами SWS Diagnostics §8.58.5 «Struct: UpdatePackageStatus» [SWS_DM_01902]. Экземпляры создаются в ходе вызова GetUpdatePackageStatus, заполняются актуальными значениями статуса и возвращаются вызывающей стороне по значению [SWS_DM_01921]. Время жизни привязано к области видимости получателя и заканчивается с его уничтожением.

Хотя объект C++ пассивен, его переменные-члены представляют жизненный цикл лежащего в основе процесса обновления. Поле phase типа SovdUpdatePhase описывает текущую фазу общего процесса SWS Diagnostics §8.58.5.1.2 «phase» [SWS_DM_01903], в то время как переменная status типа SovdUpdateStatus указывает конкретное состояние этой фазы SWS Diagnostics §8.58.5.1.4 «status» [SWS_DM_01904]. Поскольку внутренние мьютексы или механизмы синхронизации не специфицированы, конкурентный доступ к одному и тому же экземпляру требует внешней защиты со стороны пользователя.

Путь использования

Типичный сценарий использования включает циклический или событийный мониторинг обновления пакета диагностическим клиентом:

  • Запрос статуса: клиент вызывает метод GetUpdatePackageStatus интерфейса SovdSwUpdate SWS Diagnostics §8.58.2.1.3.5 «GetUpdatePackageStatus» [SWS_DM_01921].
  • Оценка фазы и статуса: после получения объекта [SWS_DM_01902] клиент проверяет переменные phase [SWS_DM_01903] и status [SWS_DM_01904], чтобы определить, продолжается ли процесс в штатном режиме или завершен.
  • Анализ прогресса: если доступен общий процентный прогресс, он вычисляется через опциональный член progress SWS Diagnostics §8.58.5.1.3 «progress» [SWS_DM_01905]. Дополнительные подфазы можно просмотреть через вектор subprogress [SWS_DM_01906].
  • Отображение шага: для протоколирования или ведения пользователя используются текстовое обозначение шага step [SWS_DM_01907], а также ключ локализации step_translation_id [SWS_DM_01908].

Диаграмма последовательности: последовательность вызовов для запроса статуса и анализа переменных-членов UpdatePackageStatus. Источники: [SWS_DM_01921], [SWS_DM_01902], [SWS_DM_01904], [SWS_DM_01909].

Сценарии ошибок

Ошибки в процессе обновления делаются прозрачными через специфические атрибуты структуры данных:

  • Статус сбоя: если в процессе возникает проблема, поле status принимает состояние «failed» [SWS_DM_01904].
  • Детали ошибки: в этом случае ошибки поле error типа ara::core::Optional<ara::diag::DiagSovdErrc> специфицирует возникший код ошибки SWS Diagnostics §8.58.5.1.1 «error» [SWS_DM_01909].
  • Штатный ход выполнения: если ошибка отсутствует, опциональное поле error, по-видимому, остается незаполненным, поскольку согласно спецификации оно явно привязано к состоянию «failed» [SWS_DM_01909].
  • Интерфейсная ошибка: если вызов API GetUpdatePackageStatus завершается сбоем на уровне платформы, вместо объекта статуса, по-видимому, возвращается специфичное для платформы состояние ошибки [SWS_DM_01921].

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform версии R25-11.
