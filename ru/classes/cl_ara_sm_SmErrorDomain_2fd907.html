Служит для определения и разрешения кодов ошибок, а также исключений в рамках State Management.

Класс ara::sm::SmErrorDomain представляет предметно-ориентированный домен ошибок State Management и сопоставляет функциональные коды ошибок с читаемыми текстовыми сообщениями, а также C++-исключениями ([SWS_SM_81241]). Во время выполнения он позволяет через потокобезопасные методы идентифицировать домен и транслировать отдельные значения ошибок для протоколирования и диагностики. При возникновении серьезной ошибки через интерфейс также может быть сгенерировано типизированное исключение ([SWS_SM_81250]). Если C++-исключения отключены в тулчейне, логика исключений недоступна, и ошибки вместо этого должны обрабатываться исключительно на основе значений.

Контекст

Класс ara::sm::SmErrorDomain определяет специфический домен ошибок для функционального кластера State Management на Adaptive Platform ([SWS_SM_81241], SWS StateManagement §8.1.3 «Class: SmErrorDomain»). Являясь специализацией общей архитектуры доменов ошибок, он наследуется от ara::core::ErrorDomain согласно требованиям из [SWS_CORE_90023]. Его основная ответственность заключается в том, чтобы семантически инкапсулировать состояния ошибок State Management, предоставлять стандартизированные идентификаторы ошибок и обеспечивать отображение между числовыми кодами ошибок, текстами ошибок и типами исключений.

К основным партнерам по взаимодействию относятся внутренние компоненты State Management, генерирующие ошибки, а также вышестоящие службы приложений и платформы, получающие ошибки через ara::core::ErrorCode. Через публичный псевдоним типа Errc класс ссылается на предметно-ориентированное перечисление SmErrc ([SWS_SM_81245]). Кроме того, псевдоним типа Exception ссылается на соответствующий базовый класс исключений SmException ([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 «Type Alias: Exception»).

Жизненный цикл

Экземпляры ara::sm::SmErrorDomain создаются через конструктор по умолчанию без параметров ([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 «Default Constructor»). Конструктор объявлен как noexcept и имеет классификацию exception safe. Экземпляр SmErrorDomain в типичных системных окружениях, вероятно, должен существовать преимущественно как долгоживущий или статический объект, поскольку домены ошибок в экосистеме AUTOSAR Adaptive требуются во всем процессе для интерпретации кодов ошибок.

Что касается конкурентности, основные функции класса специфицированы для параллельной работы: методы Name() ([SWS_SM_81248]) и Message() ([SWS_SM_81249]) обозначены как thread-safe, а также exception safe. Таким образом, несколько выполняемых потоков могут параллельно запрашивать информацию об ошибках без необходимости внешней синхронизации.

Путь использования

Штатный сценарий использования охватывает идентификацию домена ошибок, разрешение кодов ошибок в читаемые диагностические сообщения, а также опциональное преобразование в C++-исключение. Сначала приложение или компонент платформы может запросить имя домена через Name(); данный метод неизменно возвращает идентификатор "Sm" ([SWS_SM_81248]).

При возникновении ошибки в State Management ее код передается через Message(errorCode) ([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 «Message»). Функция возвращает указатель на соответствующую символьную строку (const char*), благодаря чему системы протоколирования и диагностики получают информативные сообщения. Если вызывающая подсистема рассчитана на обработку ошибок на основе исключений, она передает объект ошибки в ThrowAsException() ([SWS_SM_81250]), в результате чего инстанцируется и выбрасывается исключение, соответствующее коду ошибки.

Диаграмма последовательности: типичная последовательность действий при запросе информации об ошибках и опциональной генерации исключения. Источники: [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

Сценарии ошибок

Управляемые доменом состояния ошибок основаны на типе перечисления SmErrc, для которого задан псевдоним через Errc ([SWS_SM_81245]). Ошибочные ситуации проявляются либо как возвращаемые значения на основе ara::core::ErrorCode, либо через исключения типа Exception (SmException, [SWS_SM_81246]).

При вызове ThrowAsException() метод по своей концепции считается not exception safe, поскольку он активно генерирует исключение, связанное с кодом ошибки ([SWS_SM_81250]). Критическое предварительное условие доступности этого метода касается конфигурации тулчейна: согласно [SWS_CORE_10304], ThrowAsException() не участвует в разрешении перегрузки, если C++-исключения отключены в тулчейне компилятора ([SWS_SM_81250]). Следовательно, в системных конфигурациях без поддержки исключений обработка ошибок должна производиться строго через коды возврата.

функция Message [SWS_SM_81249] Upstream: RS_AP_00119, RS_AP_00159

const char * Message (CodeType errorCode) const noexcept override;

Returns the message associated with the error code.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 5c30b05c668e Provenance

Функция-член ara::sm::SmErrorDomain::Message служит для синхронного определения текстового сообщения об ошибке, сопоставленного определенному коду ошибки домена ошибок State Management [SWS_SM_81249]. Она объявлена в файле заголовка ara/sm/sm_error_domain.h в области видимости класса ara::sm::SmErrorDomain и имеет в спецификации статус DRAFT AUTOSAR_AP_SWS_StateManagement §8.1.3.2.2.1 «Message».

Интерфейс имеет следующие параметры и возвращаемые значения [SWS_SM_81249]:

  • Параметр: errorCode типа CodeType принимает числовой номер ошибки, для которого запрашивается соответствующее текстовое сообщение.
  • Возвращаемое значение: Указатель типа const char * на сообщение об ошибке, сопоставленное переданному коду ошибки.

Для выполнения действуют строгие гарантии относительно параллелизма и обработки исключений: функция специфицирована как thread-safe и exception safe, а также объявлена с идентификатором noexcept [SWS_SM_81249]. Таким образом, ее можно безопасно вызывать из произвольных потоков без синхронизирующих блокировок или блоков try-catch.

В рамках управления ошибками AUTOSAR Adaptive метод переопределяет виртуальную функцию базового домена ошибок. Интерпретация: поскольку возвращаемое значение определено как const char * без интерфейса выделения памяти, указатель, вероятно, обычно ссылается на статические строковые литералы, остающиеся действительными на протяжении всего времени выполнения процесса.

          Использование
          

          
Конструктор по умолчанию SmErrorDomain() синхронно создает экземпляр домена ошибок ara::sm::SmErrorDomain ([SWS_SM_81247]). Объявление находится в заголовочном файле ara/sm/sm_error_domain.h. Вызов не требует входных параметров и напрямую возвращает инициализированный объект домена (SWS StateManagement §8.1.3.2.1.1 «Default Constructor»).

          

          Обработка ошибок
          

          
Функция снабжена идентификатором noexcept и классифицирована как безопасная относительно исключений (exception safe) ([SWS_SM_81247]). При создании коды ошибок не возникают и исключения не генерируются.

          

          Параллелизм и ограничения
          

          
Создание специфицировано как thread-safe ([SWS_SM_81247]). Таким образом, экземпляры могут создаваться параллельно в многопоточных средах без необходимости использования дополнительных механизмов синхронизации. Особых требований к порядку не предъявляется.

          

          Взаимодействие
          

          
Созданный объект принадлежит классу ara::sm::SmErrorDomain ([SWS_SM_81241]), который специфицирован в соответствии с [SWS_CORE_90023]. Внутри модуля State Management домен ошибок взаимодействует со следующими элементами:

          

            

          • Errc ([SWS_SM_81245]) и Exception ([SWS_SM_81246]) в качестве синонимов типов для кодов ошибок (SmErrc) и обработки исключений (SmException).
            • 

          • Name() ([SWS_SM_81248]) возвращает имя домена "Sm".
            • 

          • Message() ([SWS_SM_81249]) преобразует коды ошибок в текстовые описания.
            • 

          • ThrowAsException() ([SWS_SM_81250]) выбрасывает код ошибки в виде исключения, если включены исключения C++ ([SWS_CORE_10304]).
            • 

          • GetSmDomain() ([SWS_SM_81251]) в качестве альтернативы предоставляет глобальный экземпляр домена ошибок.
