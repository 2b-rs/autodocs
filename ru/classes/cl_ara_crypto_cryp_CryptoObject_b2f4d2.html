Контекст

Интерфейс ara::crypto::cryp::CryptoObject служит общим базовым интерфейсом для всех криптографических объектов, которые могут распознаваться и управляться CryptoProvider. Благодаря наследованию от ara::crypto::Serializable он определяет единую основу для сериализуемых объектов в рамках архитектуры криптографии AUTOSAR Adaptive Platform, таких как ключевой материал и сопутствующие метаданные.

Интерфейс объединяет базовые свойства идентификации и управления для криптографических ресурсов. К основным участникам взаимодействия относятся:

  • Приложение: использует интерфейс для запроса идентификаторов алгоритмов и ограничений использования, а также для инициации сохранения в слоте ключа.
  • CryptoProvider: предоставляет контекст выполнения для криптографических объектов. Согласно [SWS_CRYPT_20517], существует логическая привязка к соответствующему провайдеру; несовместимости возникают, если целевые структуры сопоставлены другому провайдеру.
  • WriteableKeySlot: представляет базовое место хранения, в которое объект персистентно переносится через Save() ([SWS_CRYPT_20517]).

Контекстная диаграмма: участники взаимодействия CryptoObject при управлении и персистировании. Источники: [SWS_CRYPT_20517]

Жизненный цикл

Жизненный цикл и управление памятью CryptoObject соответствуют требованиям к ресурсам адаптивной платформы:

  • Отношения владения: для управления экземплярами класс предоставляет псевдоним типа Sptr ([SWS_CRYPT_20501]), который определен как std::shared_ptr<CryptoObject>. Это обеспечивает совместное использование объектов с подсчетом ссылок через границы компонентов.
  • Создание: поскольку это чисто виртуальный интерфейс, создать экземпляр CryptoObject напрямую невозможно; создание конкретных экземпляров, предположительно, обычно осуществляется через фабричные методы CryptoProvider.
  • Персистирование: CryptoObject может во время выполнения удерживаться в энергозависимом состоянии или же сохраняться на постоянной основе в WriteableKeySlot с помощью метода Save() ([SWS_CRYPT_20517]). При успешном выполнении записываются как ключевой материал, так и метаданные; данные, ранее находившиеся в слоте, при этом полностью перезаписываются.
  • Параллелизм и безопасность: все методы (GetAlgId(), GetAllowedUsage(), Save()) объявлены как noexcept и специфицируют безопасность относительно исключений (exception safe), а также потокобезопасность (thread-safe) ([SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]). Параллельные вызовы из нескольких потоков допустимы без внешней синхронизации.

Путь использования

Типичный сценарий использования заключается в проверке свойств объекта и последующем сохранении в постоянном слоте ключа:

  1. Запрос алгоритма: приложение вызывает GetAlgId() ([SWS_CRYPT_20505]), чтобы получить идентификатор алгоритма в виде ara::crypto::AlgIdString внутри ara::core::Result.
  2. Проверка правил использования: с помощью GetAllowedUsage() ([SWS_CRYPT_50092]) определяются AllowedUsageFlags. Перед сохранением необходимо проверить, содержится ли разрешение kAllowPersist ([SWS_CRYPT_20517]).
  3. Выполнение сохранения: если объект удовлетворяет всем критериям, вызывается метод Save() с передачей WriteableKeySlot::Sptr ([SWS_CRYPT_20517]).
  4. Проверка результата: метод возвращает ara::core::Result<void>, на основе которого можно оценить успешность или специфические коды ошибок.

Диаграмма последовательности: типичная последовательность валидации и сохранения CryptoObject. Источники: [SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]

Сценарии ошибок

Простой контроль состояния с помощью методов запроса существенно отличается от операций записи, связанных с ресурсами:

  • Методы запроса: для GetAlgId() ([SWS_CRYPT_20505]) и GetAllowedUsage() ([SWS_CRYPT_50092]) не определены стандартизированные коды ошибок.
  • Несовместимость (kIncompatibleObject): если Save() завершается сбоем из-за того, что ключ не подходит к целевому слоту (например, несовместимые AlgId или происхождение из другого CryptoProvider), возвращается ara::crypto::CryptoErrc::kIncompatibleObject ([SWS_CRYPT_20517]).
  • Нарушение прав (kUsageViolation): если разрешенное использование ключа не содержит право kAllowPersist, в персистировании отказывается с ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_20517]).
  • Занятый ресурс (kBusyResource): если операция записи временно не может быть выполнена, Save() возвращает ошибку ara::crypto::CryptoErrc::kBusyResource ([SWS_CRYPT_20517]).
  • Гарантия отката: для всех ошибок при Save() действует семантика отката (rollback_semantics) ([SWS_CRYPT_20517]), так что исходное состояние слота ключа в случае сбоев остается неизменным.

Данное руководство было создано ИИ на основе спецификации AUTOSAR Adaptive R25-11.
