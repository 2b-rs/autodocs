Служит для безопасной распаковки и импорта защищенных криптографических ключей и данных в приложении.

Интерфейс обеспечивает безопасную распаковку и импорт защищенных криптографических данных и ключей с помощью сконфигурированного транспортного ключа [SWS_CRYPT_50205]. Распакованный ключевой материал может быть либо напрямую записан в постоянный слот для ключей, либо типизированно загружен в память в виде ключевого объекта [SWS_CRYPT_50207]. Все методы работают потокобезопасно и следуют строгой семантике отката при ошибках, в то время как Reset гарантирует удаление внутренних буферов без остатка [SWS_CRYPT_50212].

Контекст

Интерфейс ara::crypto::cryp::ProtectedKeyImportCtx предоставляет криптографический контекст для безопасного импорта и распаковки в системе защищенных структур данных, таких как секретный ключевой материал. Контекст выступает в качестве посредника между запрашивающим приложением, механизмом защиты на основе транспортного ключа и целевыми структурами криптографии AUTOSAR. Входящие сериализованные пакеты данных аутентифицируются, расшифровываются и парсятся контекстом [SWS_CRYPT_50207]. Источниками необходимого транспортного ключа служат либо самостоятельные симметричные ключевые объекты [SWS_CRYPT_50205], либо слоты для ключей в хранилище ключей [SWS_CRYPT_50206]. В качестве приемника распакованные ключевые объекты могут передаваться напрямую вызывающему приложению или непосредственно сериализоваться в доступный для записи слот для ключей [SWS_CRYPT_50207].

Жизненный цикл

Для совместного доступа контекст обычно управляется через предоставленный тип умного указателя Sptr [SWS_CRYPT_50085]; при этом экземпляры, вероятно, предоставляются соответствующим компонентом криптодрайвера. Вопрос Q-3517b24b5eec4529 (открытый) До непосредственной обработки контекст находится в несконфигурированном исходном состоянии, в котором транспортный ключ еще не назначен. Назначение транспортного ключа осуществляется через метод SetKey, в результате чего контекст переходит в готовое к работе состояние [SWS_CRYPT_50205] [SWS_CRYPT_50206].

После успешного выполнения операции Import контекст сохраняет распакованные данные и метаданные во внутренних буферах, что позволяет идентифицировать тип объекта и считывать ключевые объекты [SWS_CRYPT_50207] [SWS_CRYPT_50208]. С помощью метода Reset контекст возвращается обратно в исходное состояние: все внутренние буферы с ранее импортированными данными полностью очищаются, а сохраненный транспортный ключ удаляется [SWS_CRYPT_50212]. Все методы интерфейса специфицированы как исключебнобезопасные и потокобезопасные, благодаря чему конкурентный доступ из нескольких контекстов выполнения остается контролируемым [SWS_CRYPT_50207].

Диаграмма состояний: жизненные фазы контекста от конфигурации через импорт до очистки. Источники: [SWS_CRYPT_50205], [SWS_CRYPT_50206], [SWS_CRYPT_50207], [SWS_CRYPT_50212]

Путь использования

Стандартный рабочий процесс начинается с конфигурации транспортного ключа. Для этого приложение вызывает SetKey либо с SymmetricKey::Sptr [SWS_CRYPT_50205], либо с KeySlot::Sptr [SWS_CRYPT_50206]. На следующем шаге выполняется метод Import, которому сериализованный пакет данных передается в виде ReadOnlyMemRegion [SWS_CRYPT_50207]. Если ключ должен быть сохранен персистентно, можно опционально напрямую передать WriteableKeySlot::Sptr, куда будет записан распакованный материал [SWS_CRYPT_50207].

Если целевой слот не был указан или ключ должен использоваться как временный, приложение определяет категорию последнего импортированного объекта с помощью GetCryptoObjectType [SWS_CRYPT_50208]. На основе этого типа приложение вызывает соответствующий типу метод получения: GetPrivateKey для закрытых ключей [SWS_CRYPT_50209], GetPublicKey для открытых ключей [SWS_CRYPT_50211] или GetSymmetricKey для симметричного ключевого материала [SWS_CRYPT_50210]. Если используемый протокол импорта требует обратной связи с отправителем — как, например, в случае контрольных блоков M4 и M5 последовательности SHE-LoadKey —, ее можно записать в предоставленный буфер через GetResponse [SWS_CRYPT_41020]. После завершения последовательности обработки вызов Reset возвращает контекст в исходное состояние [SWS_CRYPT_50212].

Диаграмма последовательности: типичная последовательность вызовов при импорте и считывании ключевого материала. Источники: [SWS_CRYPT_50205], [SWS_CRYPT_50207], [SWS_CRYPT_50208], [SWS_CRYPT_50210], [SWS_CRYPT_50212]

Сценарии ошибок

Если во время вызова метода возникает ошибка, применяется строгая семантика отката, сохраняющая состояние до вызова. При конфигурации через SetKey вызов завершается ошибкой с CryptoErrc::kUsageViolation, если флаг использования ключа не содержит разрешения kAllowKeyUnwrapping [SWS_CRYPT_50205] [SWS_CRYPT_50206]. Если объект ключа или указанный слот принципиально непригодны для использования в качестве транспортного ключа, сообщается CryptoErrc::kIncompatibleObject [SWS_CRYPT_50205] [SWS_CRYPT_50206].

При вызове Import несоответствия размера входных данных приводят к CryptoErrc::kInvalidInputSize, а нарушения формата — к CryptoErrc::kInvalidArgument [SWS_CRYPT_50207]. Если проверка целостности или подлинности защитного слоя завершается неудачно (например, из-за недействительного кода аутентификации сообщения или некорректной подписи), вызов возвращает CryptoErrc::kAuthTagNotValid [SWS_CRYPT_50207]. Если криптографический компонент временно занят, об этом сигнализируется через CryptoErrc::kBusyResource [SWS_CRYPT_50207].

Предварительным условием для считывания импортированных ключей является успешное выполнение Import; в противном случае GetPrivateKey, GetPublicKey и GetSymmetricKey отвечают CryptoErrc::kProcessingNotFinished [SWS_CRYPT_50209] [SWS_CRYPT_50210] [SWS_CRYPT_50211]. Если запрошенный тип ключа не совпадает с фактически распакованным объектом или объект еще не был импортирован, методы получения подтверждают это с помощью CryptoErrc::kNoSuchValue [SWS_CRYPT_50208] [SWS_CRYPT_50209] [SWS_CRYPT_50210] [SWS_CRYPT_50211]. Если емкости выходного буфера при GetResponse недостаточно, это приводит к CryptoErrc::kInsufficientCapacity [SWS_CRYPT_41020]. Если конкретная реализация не поддерживает частичную функцию (например, определенные типы ключей или сброс), единообразно возвращается CryptoErrc::kUnsupported [SWS_CRYPT_50205] [SWS_CRYPT_50208] [SWS_CRYPT_50212].

          Метод GetPublicKey класса ara::crypto::cryp::ProtectedKeyImportCtx служит для синхронного получения указателя на ранее импортированный, распакованный открытый ключ ([SWS_CRYPT_50211]). Функция не принимает входных параметров и возвращает результат типобезопасным образом в виде ara::core::Result<PublicKey::Sptr> ([SWS_CRYPT_50211]).
          

          Перед вызовом операция импорта должна быть успешно завершена; в противном случае вызов завершается сбоем и возвращает код ошибки ara::crypto::CryptoErrc::kProcessingNotFinished ([SWS_CRYPT_50211]). Если последний импортированный криптографический объект не являлся открытым ключом, это приводит к ошибке ara::crypto::CryptoErrc::kNoSuchValue ([SWS_CRYPT_50211]).
