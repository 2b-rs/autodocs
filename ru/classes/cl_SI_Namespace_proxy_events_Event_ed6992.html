Использование по назначению

Для каждого элемента Service Interface, смоделированного как Event, Proxy создаёт Event-Wrapper. После соединения с экземпляром сервиса Consumer подписывается на Event; Provider отправляет данные в Communication Management, которое уведомляет подписчиков. Затем Samples явно извлекаются через GetNewSamples(). EXP ARAComAPI §4.3 «Event and Trigger based communication» §5.3.5 «Events»

Subscription, кэш и модель приёма

Subscribe(maxSampleCount) одновременно устанавливает максимальный бюджет локального кеша Sample. Вызов асинхронно принимает запрос; Subscription-State можно запросить или отслеживать через обработчик изменения состояния. Для циклических приложений достаточно опроса посредством GetNewSamples(); реактивные приложения регистрируют SetReceiveHandler(), который при появлении новых данных предлагает их получить. EXP ARAComAPI §5.3.5.1 «Event Subscription and Local Cache» §5.3.5.2 «Monitoring Event Subscription» §5.3.5.5 «Event-Driven vs Polling-Based access»

Образец владения

Передаваемые Callback объекты SamplePtr переносят на приложение ответственность за слот Cache. Пока удерживается SamplePtr, этот слот нельзя повторно использовать; это ограничивает число одновременно доступных Samples. EXP ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»

Диаграмма последовательностей: Subscribe и приём. Источники: EXP ARAComAPI §4.3 «Event and Trigger based communication», §5.3.5.1 «Event Subscription and Local Cache» и §5.3.5.5 «Event-Driven vs Polling-Based access».
