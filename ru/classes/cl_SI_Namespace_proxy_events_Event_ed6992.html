Контекст

Сгенерированный C++-класс <SI-Namespace>::proxy::events::<Event> представляет собой интерфейс принимающей стороны для конкретного события сервиса внутри сервисного прокси в AUTOSAR Adaptive (AUTOSAR_AP_EXP_ARAComAPI с. 10). Его основная обязанность заключается в управлении подпиской на события, регистрации обратных вызовов для уведомлений, а также в типобезопасном доступе к входящим данным событий через псевдоним типа SampleType [SWS_CM_11401].

Класс взаимодействует преимущественно с тремя участниками:

  • Прикладное программное обеспечение: инициирует подписку с помощью таких методов, как Subscribe [SWS_CM_00141] и Unsubscribe [SWS_CM_00151], устанавливает обратные вызовы и обрабатывает полученные сэмплы данных с помощью функторов в GetNewSamples [SWS_CM_00701].
  • Communication Management (среда выполнения): отслеживает состояние соединения и подписки, принимает сериализованные данные событий и инициирует вызов зарегистрированного EventReceiveHandler при поступлении данных [SWS_CM_00181].
  • Контекст выполнения (ExecutorT): опционально позволяет передавать пользовательский контекст выполнения, благодаря чему уведомления, смены состояний и обработчики ошибок целенаправленно обрабатываются в определенных потоках или очередях рабочих потоков [SWS_CM_11354], [SWS_CM_11356], [SWS_CM_00100].
  • End-to-End-защита (E2E): обеспечивает мониторинг ошибок передачи данных через SetTransportFaultConditionHandler [SWS_CM_00099], а также опрос состояния E2E после обработки принятых сэмплов [SWS_CM_11554].

Жизненный цикл

Экземпляр <SI-Namespace>::proxy::events::<Event> создается как составная часть вышестоящего прокси сервиса и разделяет время его жизни; таким образом, владение закреплено за объектом-прокси. Функциональный жизненный цикл в значительной степени определяется внутренним состоянием подписки (SubscriptionState), которое можно в любой момент запросить через GetSubscriptionState [SWS_CM_00316].

В начальный момент событие находится в состоянии отсутствия подписки. Вызов Subscribe(maxSampleCount) [SWS_CM_00141] инициирует переход: в зависимости от состояния связи экземпляр переходит в состояние kSubscriptionPending или напрямую в kSubscribed [SWS_CM_00141]. Об изменениях состояния сообщается коллбэку, зарегистрированному через SetSubscriptionStateChangeHandler [SWS_CM_00333] или [SWS_CM_11354]. Повторный вызов Subscribe с тем же значением размера буфера не оказывает никакого действия [SWS_CM_00141].

Завершение выполняется через Unsubscribe [SWS_CM_00151], в результате чего событие возвращается в состояние без подписки. Если подписка на событие отсутствовала, вызов не имеет эффекта [SWS_CM_00151]. Для освобождения ресурсов зарегистрированные обработчики могут быть явно удалены с помощью UnsetSubscriptionStateChangeHandler [SWS_CM_00334], UnsetReceiveHandler [SWS_CM_00183] и UnsetTransportFaultConditionHandler [SWS_CM_00105]. Все методы API объявлены как noexcept.

Диаграмма состояний: жизненный цикл подписки на событие с состояниями и переходами. Источники: [SWS_CM_00141], [SWS_CM_00151], [SWS_CM_00316], [SWS_CM_00333].

Путь использования

Типичный сценарий использования для обработки сэмплов данных по событиям делится на следующие шаги:

  1. Настройка обработчиков: приложение сначала регистрирует обработчик приема через SetReceiveHandler [SWS_CM_00181] или в сочетании с контекстом выполнения через SetReceiveHandler(handler, executor) [SWS_CM_11356]. Опционально можно настроить обработчики для смены статуса [SWS_CM_00333] или ошибок передачи E2E [SWS_CM_00099].
  2. Активация подписки: с помощью Subscribe(maxSampleCount) [SWS_CM_00141] приложение сообщает промежуточному ПО, какое максимальное количество сэмплов может одновременно храниться в локальном кэше.
  3. Уведомление и выборка данных: как только появляются новые данные, Communication Management вызывает зарегистрированный обработчик [SWS_CM_00181]. В нем приложение вызывает GetNewSamples [SWS_CM_00701]. Переданный вызываемый функтор получает каждый новый элемент данных в виде типизированного указателя ara::com::SamplePtr<SampleType const>. Возвращаемое значение сообщает об общем количестве обработанных сэмплов.
  4. Проверка буфера и состояния: приложение может запросить наличие свободных мест в кэше с помощью GetFreeSampleCount [SWS_CM_00705], а также после GetNewSamples проанализировать результат E2E-проверки с помощью GetE2EStateMachineState [SWS_CM_11554].
  5. Деактивация: после завершения обработки приложение отменяет регистрацию обработчиков ([SWS_CM_00183], [SWS_CM_00334], [SWS_CM_00105]) и отменяет подписку с помощью Unsubscribe [SWS_CM_00151].

Диаграмма последовательности: последовательность вызовов при регистрации обработчиков, оформлении подписки на события и обработке сэмплов. Источники: [SWS_CM_00141], [SWS_CM_00181], [SWS_CM_00701], [SWS_CM_00151].

Сценарии ошибок

Методы интерфейса сигнализируют об ошибочных состояниях преимущественно через ara::core::Result, а также через специфицированные нарушения правил API:

  • ComErrc::kMaxSamplesExceeded: возвращается методом GetNewSamples, если приложение удерживает одновременно больше экземпляров ara::com::SamplePtr, чем было гарантировано ранее при вызове Subscribe. При этом семантика отката не применяется, и последующие сэмплы могли быть отброшены [SWS_CM_00701].
  • ComErrc::kMaxSampleCountNotRealizable: возникает при вызове Subscribe, если при повторной подписке передается другое значение maxSampleCount, отличное от согласованного для текущей активной подписки [SWS_CM_00141].
  • InsufficientPermissionsViolation: возникает в том случае, если механизм контроля прав (Grant Enforcement) отклоняет доступ к подписке на событие при вызове Subscribe [SWS_CM_00141].
  • InvalidHandlerViolation: возникает, если в методы регистрации SetReceiveHandler [SWS_CM_00181], [SWS_CM_11356], SetSubscriptionStateChangeHandler [SWS_CM_00333], [SWS_CM_11354] или SetTransportFaultConditionHandler [SWS_CM_00099], [SWS_CM_00100] передается недействительный или пустой обработчик.
  • DanglingSamplesViolation: сигнализирует при вызове Unsubscribe о том, что в контексте приложения все еще существуют незакрытые выборки (dangling samples) и предварительные условия для отмены подписки были нарушены [SWS_CM_00151].

Настоящее руководство составлено ИИ-ассистентом курации на основе спецификации AUTOSAR Adaptive (релиз R25-11).
