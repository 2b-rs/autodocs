Служит для предоставления и обработки явно смоделированных конфигурационных ресурсов SOVD на стороне приложения.

Интерфейс ara::diag::SovdConfiguration служит универсальным обработчиком явно смоделированных конфигураций SOVD, на который Diagnostic Server перенаправляет входящие обращения на чтение и запись [SWS_DM_01860], [SWS_DM_01787]. После инстанцирования на основе портов приложение активирует прием сообщений через Offer и при необходимости завершает его с помощью StopOffer [SWS_DM_01872], [SWS_DM_01930]. Предоставление данных выполняется асинхронно через сеансы чтения или записи, при этом функциональные ошибки сигнализируются согласно ISO 17978-3 или ASAM SOVD 1.1 [SWS_DM_01870].

Контекст

Интерфейс ara::diag::SovdConfiguration определяет универсальный интерфейс для явно смоделированных обработчиков конфигурации SOVD в рамках архитектуры диагностики Adaptive AUTOSAR [SWS_DM_01860]. Если в системе спроектирована хотя бы одна конфигурация SOVD, экземпляр Diagnostic Server компонента Diagnostic Management (DM) предоставляет вовне стандартизированный метод SOVD Retrieve List of All Configurations Provided by the Entity согласно ASAM SOVD [SWS_DM_01429]. Входящие обращения на чтение и запись к такой явной конфигурации Diagnostic Server перенаправляет конкретной реализации ara::diag::SovdConfiguration: при вызове метода SOVD Read Configuration Diagnostic Server вызывает метод RequestGetConfiguration [SWS_DM_01787], тогда как при вызове Write Configuration выполняется метод RequestPutConfiguration [SWS_DM_01788].

Диаграмма контекста: встраивание ara::diag::SovdConfiguration между внешним клиентом SOVD, Diagnostic Server (DM) и специализированным обработчиком приложения. Источники: [SWS_DM_01429], [SWS_DM_01787], [SWS_DM_01788], [SWS_DM_01860].

Жизненный цикл

Инстанцирование ara::diag::SovdConfiguration выполняется на стороне приложения путем передачи ara::core::InstanceSpecifier, а также указания ConcurrencyType (kConcurrent или kNotConcurrent) [SWS_DM_01864]. InstanceSpecifier ссылается на прототип порта сущности DiagnosticSovdConfigurationInterface в контексте процесса [SWS_DM_01864]. Класс не разрешается копировать (конструктор копирования и оператор присваивания с копированием объявлены как delete) [SWS_DM_01866], [SWS_DM_01868], однако он поддерживает защищенные операции перемещения [SWS_DM_01867], [SWS_DM_01869]. Чтобы принимать запросы от Diagnostic Server, приложение должно явно вызвать Offer [SWS_DM_01872]. Вызовом StopOffer перенаправление запросов снова деактивируется [SWS_DM_01930]. При уничтожении экземпляра через виртуальный деструктор [SWS_DM_01865] объект освобождается; освобождение предполагает, что обработчик был предварительно надлежащим образом дерегистрирован.

Диаграмма состояний: фазы жизненного цикла экземпляра SovdConfiguration от инициализации через состояние Offer до StopOffer. Источники: [SWS_DM_01864], [SWS_DM_01872], [SWS_DM_01930], [SWS_DM_01865].

Путь использования

Типичный путь использования начинается после конструирования производного класса обработчика с регистрации в Diagnostic Management с помощью Offer() [SWS_DM_01872]. Как только внешний клиент направляет сущности запрос конфигурации SOVD, Diagnostic Server перенаправляет его: при запросе на чтение вызывается RequestGetConfiguration, при этом передаются configurationId, metaInfo и CancellationHandler [SWS_DM_01870]. Метод возвращает ara::core::Future, который асинхронно предоставляет кортеж из DataTransferReadSession и SovdConfigurationMetaInfo [SWS_DM_01870]. Аналогично сервер перенаправляет запросы на запись через RequestPutConfiguration, который возвращает future с DataTransferWriteSession и SovdConfigurationMetaInfo [SWS_DM_01871]. Перед завершением работы обработчика приложение вызывает StopOffer(), чтобы больше не принимать запросы [SWS_DM_01930].

Диаграмма последовательности: типичная последовательность взаимодействий при инициализации, диспетчеризации запроса Read-Configuration и последующей отмене регистрации. Источники: [SWS_DM_01872], [SWS_DM_01787], [SWS_DM_01870], [SWS_DM_01930].

Сценарии ошибок

Уже при инстанцировании в конструкторе могут возникать нарушения модели и сопоставления (mapping), если InstanceSpecifier не может быть разрешен в модели (InstanceSpecifierMappingIntegrityViolation), на который ссылается прототип порта, не типизирован через DiagnosticSovdConfigurationInterface (PortInterfaceMappingViolation), подходящий процесс не существует (ProcessMappingViolation) или идентификатор в текущем процессе уже занят (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01864]. При вызове Offer() метод возвращает ara::core::Result<void>, который в случае ошибки сообщает DiagOfferErrc::kConfigurationMismatch, если конфигурация не соответствует модели DEXT, или DiagOfferErrc::kAlreadyOffered, если сервис уже предлагается [SWS_DM_01872]. В асинхронных методах обработчика RequestGetConfiguration и RequestPutConfiguration приложение сообщает о состояниях ошибок через ara::core::Future с использованием стандартизированных кодов ошибок SOVD согласно ISO 17978-3 или ASAM SOVD 1.1 [SWS_DM_01870], [SWS_DM_01871]. Кроме того, CancellationHandler сигнализирует, была ли прервана текущая коммуникация [SWS_DM_01870], [SWS_DM_01871].

Данное руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform Release R25-11.

Использование

Метод Offer класса ara::diag::SovdConfiguration служит для того, чтобы активировать пересылку диагностических запросов модулем Diagnostic Management (DM) сконфигурированному обработчику [SWS_DM_01872]. Вызов выполняется синхронно, не принимает параметров и сообщает о результате через ara::core::Result<void> [SWS_DM_01872]. До тех пор пока обработчик не предоставлен через Offer, DM не пересылает входящие запросы, что соответствует базовому паттерну предоставления диагностических интерфейсов (ср. [SWS_DM_01525], [SWS_DM_00809]).

Обработка ошибок

В случае ошибки возвращается ara::core::Result с кодом ошибки перечисления DiagOfferErrc, причем действует семантика отката [SWS_DM_01872]:

  • DiagOfferErrc::kAlreadyOffered: сообщается, если служба уже предлагалась ранее [SWS_DM_01872].
  • DiagOfferErrc::kConfigurationMismatch: возникает, если конфигурация не совпадает с данными описания DEXT [SWS_DM_01872].

Параллелизм и ограничения

Операция объявлена как noexcept, а также безопасна относительно исключений (exception safe), однако специфицирована как непотокобезопасная (not thread-safe) [SWS_DM_01872]. Одновременные вызовы одного и того же экземпляра из нескольких потоков должны предотвращаться вызывающим приложением. Повторный вызов после уже состоявшегося предложения, предположительно, будет завершен ошибкой без изменения состояния.

      Использование
      

      Чисто виртуальный метод RequestGetConfiguration класса ara::diag::SovdConfiguration вызывается Diagnostic Server Instance при выполнении SOVD-метода «Read Configuration» для явно смоделированной SOVD-конфигурации ([SWS_DM_01787], AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»). В качестве параметров передаются идентификатор конфигурации считываемого экземпляра (configurationId), метаинформация запроса (metaInfo), а также cancellationHandler, информирующий о возможном прерывании текущего диалога ([SWS_DM_01870]).
      

      Функция работает асинхронно и возвращает ara::core::Future, предоставляющий кортеж из сеанса чтения файла (DataTransferReadSession) и сопутствующей метаинформации конфигурации (SovdConfigurationMetaInfo) ([SWS_DM_01870]). Интерфейс объявлен как noexcept и специфицирован как безопасный относительно исключений ([SWS_DM_01870]).
      

      Обработка ошибок и параллелизм
      

      Если при обработке возникает ошибка, C++-ошибка не генерируется, а через Future возвращается подходящий код ошибки SOVD согласно ISO 17978-3 или ASAM SOVD 1.1 ([SWS_DM_01870]).
      

      В отношении потокобезопасности действует требование «conditional»: должна ли конкретная реализация функции проектироваться потокобезопасной или непотокобезопасной, определяет переданный в конструктор ConcurrencyType ([SWS_DM_01870]).

          API-метод ara::diag::SovdConfiguration::RequestPutConfiguration вызывается сервером Diagnostic Server, когда через SOVD-интерфейс должен быть выполнен метод «Write Configuration» для явно смоделированной конфигурации [SWS_DM_01788], [SWS_DM_01871].
          

          Вызов и параметры
          

          Объявление находится в заголовочном файле ara/diag/sovd_configuration.h. Вызов передает следующие входные параметры [SWS_DM_01871]:
          

            

          • configurationId: ID записываемого экземпляра конфигурации как ara::core::String.
            • 

          • metaInfo: метаинформация о входящем запросе (MetaInfo const &).
            • 

          • cancellationHandler: отслеживает текущую операцию и сигнализирует, если коммуникация была прервана.
            • 

          

          Метод обладает асинхронной семантикой и возвращает ara::core::Future, который в случае успеха предоставляет кортеж из сеанса записи (DataTransferWriteSession) и сопутствующих метаданных (SovdConfigurationMetaInfo) [SWS_DM_01871].
          

          Обработка ошибок и параллелизм
          

          В случае ошибки Future разрешается с подходящим SOVD-кодом ошибки согласно ISO 17978-3 или ASAM SOVD 1.1 [SWS_DM_01871]. Функция объявлена как noexcept и является безопасной относительно исключений (exception safe). Потокобезопасность является условной (conditional): должна ли конкретная реализация проектироваться потокобезопасной, определяет указанный в конструкторе ConcurrencyType [SWS_DM_01871].
          

          Взаимодействие
          

          Функция образует записывающий эквивалент для RequestGetConfiguration, которая используется для SOVD-метода «Read Configuration» [SWS_DM_01787] (AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»).
