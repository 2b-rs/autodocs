Позволяет ожидать завершения асинхронной операции без возвращаемого значения, а также извлекать статус ошибки.

Класс ara::core::Future<void, E> обеспечивает асинхронную синхронизацию и проверку ошибок для операций без возвращаемого значения в AUTOSAR Adaptive [SWS_CORE_06236]. Будучи некопируемым типом, он позволяет ожидать завершения, а также безопасно с точки зрения исключений получать результат в виде ara::core::Result<void, E> [SWS_CORE_06236] или выполнять асинхронную дальнейшую обработку с помощью функции продолжения [SWS_CORE_06231]. После извлечения результата разделяемое состояние инвалидируется, поэтому последующие вызовы без действительного состояния представляют собой нарушение [SWS_CORE_06236].

Контекст

Специализация шаблонного класса ara::core::Future<void, E> представляет собой принимающую сторону асинхронной операции в AUTOSAR Adaptive, которая при успешном завершении не возвращает значение, а лишь сигнализирует о наступлении события или возникшей ошибке. Согласно описанию класса, реализация должна завершать условие E != ara::core::ErrorCode ошибкой компиляции. Класс обычно взаимодействует с соответствующим ara::core::Promise, заполняющим разделяемое состояние (shared state) [SWS_CORE_06236], а также с асинхронными контекстами выполнения при регистрации функций продолжения [SWS_CORE_06237].

Жизненный цикл

Экземпляры ara::core::Future<void, E> являются объектами исключительно с семантикой перемещения: конструктор копирования [SWS_CORE_06234] и оператор присваивания с копированием [SWS_CORE_06235] удалены (delete). Объект, созданный через конструктор по умолчанию, не имеет разделяемого состояния и ведет себя аналогично std::future [SWS_CORE_06222]. С помощью конструктора перемещения [SWS_CORE_06223] или оператора присваивания с перемещением [SWS_CORE_06225] экземпляр принимает владение shared state от другого экземпляра.

Жизненный цикл в значительной степени определяется состоянием shared state. С помощью метода valid() можно проверить, привязан ли экземпляр к shared state и пригоден ли он тем самым к использованию [SWS_CORE_06227]. Как только результат извлекается с помощью GetResult() [SWS_CORE_06236] или get() [SWS_CORE_06226] либо регистрируется продолжение через then() [SWS_CORE_06231], объект Future теряет свое shared state и valid() возвращает false. Деструктор освобождает оставшееся разделяемое состояние [SWS_CORE_06233]. С точки зрения конкурентности операции проверки и уничтожения, такие как valid() [SWS_CORE_06227], is_ready() [SWS_CORE_06232] и деструктор [SWS_CORE_06233], потокобезопасны, тогда как изменяющие состояние операции, такие как GetResult() [SWS_CORE_06236], get() [SWS_CORE_06226] и функции ожидания [SWS_CORE_06228], не являются потокобезопасными.

Диаграмма состояний: переходы состояний и валидность ara::core::Future<void, E>. Источники: [SWS_CORE_06222], [SWS_CORE_06226], [SWS_CORE_06227], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06233], [SWS_CORE_06236]

Путь использования

В синхронном пути использования потребитель ожидает завершения асинхронной операции. С помощью is_ready() можно с минимальными блокировками запросить наличие значения или ошибки [SWS_CORE_06232]. В качестве альтернативы можно ожидать блокирующим образом с помощью wait() [SWS_CORE_06228] или с ограничением по времени через wait_for() [SWS_CORE_06229] и wait_until() [SWS_CORE_06230]. Если результат доступен, опрос значения предпочтительно выполняется безопасным по отношению к исключениям способом через GetResult(), благодаря чему возвращается ara::core::Result<void, E> [SWS_CORE_06236].

В асинхронном пути метод then() позволяет зарегистрировать функцию продолжения (continuation), которая выполняется, как только результат становится доступен [SWS_CORE_06231]. При этом опционально может быть передан контекст выполнения (executor) [SWS_CORE_06237]. Функция продолжения принимает Result<void, E> как rvalue. Возвращаемый тип then() автоматически распаковывает вложенные типы Future или Result (unwrapping) [SWS_CORE_06231].

Диаграмма последовательности: синхронный процесс запроса результата через GetResult. Источники: [SWS_CORE_06227], [SWS_CORE_06228], [SWS_CORE_06232], [SWS_CORE_06236]

Сценарии ошибок

Если зависящая от состояния операция (такая как GetResult(), is_ready(), wait(), wait_for(), wait_until() или then()) вызывается на недействительном экземпляре (valid() == false), возникает нарушение предусловия, которое обрабатывается как FutureInvalidViolation [SWS_CORE_06228], [SWS_CORE_06229], [SWS_CORE_06230], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06236], [SWS_CORE_06237]. При вызове get() на недействительном экземпляре вместо этого инициируется FutureException с кодом ошибки kNoState [SWS_CORE_06226]; при отключенных исключениях C++ get() не участвует в разрешении перегрузок [SWS_CORE_06226].

Если соответствующий promise был уничтожен или покинул разделяемое состояние без установки результата или явной ошибки, код ошибки FutureErrc::kBrokenPromise согласно [SWS_CORE_00400] сохраняется в shared state [SWS_CORE_06226], [SWS_CORE_06236]. Он возвращается методом GetResult() как ошибка в Result<void, E> [SWS_CORE_06236]. Если continuation, зарегистрированная в then(), генерирует исключение, не реализующее нарушение, это приводит к FutureContinuationHasThrownViolation [SWS_CORE_06231], [SWS_CORE_06237].

Данное руководство основано исключительно на спецификации AUTOSAR для ara::core::Future<void, E> в релизе R25-11.
