Контекст

Структура данных C++ ara::diag::DoIPGroupIdentification::GidStatus является частью модуля диагностики (diag) платформы AUTOSAR Adaptive Platform в релизе R25-11 ([SWS_DM_00721], SWS Diagnostics §8.34.2 «Struct: GidStatus»). Она функционирует как стандартизированный носитель данных для данных положительного ответа («Response data of positive response message») при запросах идентификации группы (Group Identification, GID) в рамках протокола Diagnostic over IP (DoIP).

В подсистеме DoIP идентификация группы служит для идентификации логических групп или кластеров электронных блоков управления и диагностических узлов в сети транспортного средства. Согласно [SWS_DM_00813] (SWS Diagnostics §7 «Providing the GID in DoIP protocol messages using application interface»), демон Diagnostic Management (DM) отвечает за предоставление GID в исходящих протокольных сообщениях DoIP. Если параметр DoIpInstantiation.gid не сконфигурирован статически заранее, Diagnostic Management должен запросить идентификацию группы во время выполнения через интерфейс приложения. Для этого DM вызывает функцию интерфейса ara::diag::DoIPGroupIdentification::GetGidStatus ([SWS_DM_00724], SWS Diagnostics §8.34.1.1.3.1 «GetGidStatus»).

Структура GidStatus представляет в этом взаимодействии связующее звено между предоставляющим адаптивным приложением и Diagnostic Management. Она инкапсулирует релевантную для сообщения положительного ответа информацию о статусе и идентификации, благодаря чему демон может сформировать сообщение DoIP в соответствии со спецификацией и передать его запрашивающему внешнему клиенту.

Жизненный цикл

Как структура данных (struct GidStatus) GidStatus не имеет собственного внутреннего конечного автомата, а ведет себя как классический объект передачи данных. Экземпляры этой структуры создаются адаптивным приложением, реализующим и предоставляющим сервис ara::diag::DoIPGroupIdentification, чтобы ответить на вызов GetGidStatus ([SWS_DM_00724]).

Интерпретация: поскольку GidStatus в спецификации указана исключительно как структура результата для сообщений положительного ответа, время жизни объекта, по-видимому, тесно связано с выполнением и возвратом метода запроса. Адаптивное приложение создает экземпляр обычно в локальном контексте или передает его по семантике перемещения либо через оболочки результатов в среду выполнения Diagnostic Management. Как только Diagnostic Management считывает значения GID для протокольного сообщения, экземпляр снова отбрасывается.

Что касается параллелизма, GidStatus не имеет внутренних механизмов синхронизации. Поскольку запросы через GetGidStatus могут обрабатываться Diagnostic Management асинхронно, обязанностью реализующего приложения является обеспечение согласованного и потокобезопасного предоставления диагностических данных, передаваемых внутри GidStatus.

Путь использования

Типичный сценарий использования GidStatus происходит при динамическом ответе на запросы идентификации DoIP. Взаимодействие между внешним DoIP-клиентом, Diagnostic Management и адаптивным приложением подразделяется на следующие фазы:

  • 1. Запрос со стороны DoIP-клиента: внешний диагностический тестер или DoIP-клиент отправляет в блок управления сообщение для идентификации автомобиля или группы.
  • 2. Проверка конфигурации GID: Diagnostic Management проверяет, сконфигурирована ли идентификация группы статически в модели через DoIpInstantiation.gid ([SWS_DM_00813]).
  • 3. Запрос прикладного интерфейса: если статическая конфигурация отсутствует, DM вызывает метод ara::diag::DoIPGroupIdentification::GetGidStatus ([SWS_DM_00724]).
  • 4. Создание и возврат GidStatus: адаптивное приложение определяет текущие данные GID, инстанциирует объект типа GidStatus ([SWS_DM_00721]) и возвращает его в DM в качестве положительного ответа.
  • 5. Формирование ответа DoIP: Diagnostic Management извлекает идентификационные данные из GidStatus, формирует соответствующее стандарту ответное сообщение DoIP и отправляет его клиенту DoIP.

Диаграмма последовательности: динамическое определение идентификатора группы и возврат через GidStatus. Источники: [SWS_DM_00813], [SWS_DM_00724], [SWS_DM_00721].
