Контекст

Класс ara::diag::CommunicationControl предоставляет стандартизированный интерфейс для обработки UDS-службы 0x28 (CommunicationControl) на платформе Adaptive AUTOSAR. Приложения реализуют этот обработчик для приема и выполнения с учетом специфики приложения запросов на управление отправкой или приемом сообщений (например, деактивация или активация сообщений в определенных коммуникационных средах). Во взаимодействии в первую очередь участвуют три роли: внешний диагностический тестер, универсальный демон Diagnostic Management (DM) платформы и конкретный экземпляр сервиса внутри диагностического приложения.

Контекстная диаграмма: компоненты и роли при обработке CommunicationControl (0x28). Источники: [SWS_DM_00806], [SWS_DM_00808], [SWS_DM_00809]

Жизненный цикл

Экземпляры ara::diag::CommunicationControl семантически привязаны к фиксированному порту: операции копирования и перемещения явно удалены ([SWS_DM_01675], [SWS_DM_01676], [SWS_DM_01677], [SWS_DM_01678]). Создание осуществляется через конструктор с указанием ara::core::InstanceSpecifier, который должен ссылаться на PortPrototype элемента DiagnosticComControlInterface, а также ConcurrencyType ([SWS_DM_00806]). Через ConcurrencyType (kConcurrent или kNotConcurrent) определяется, должен ли метод обратного вызова CommCtrlRequest поддерживать потокобезопасное выполнение ([SWS_DM_00806], [SWS_DM_00808]).

После инстанцирования объект находится в состоянии NotOffered. Только вызов Offer() авторизует DM для пересылки входящих 0x28-запросов объекту ([SWS_DM_00809]). Предоставление сервиса может быть отозвано с помощью StopOffer() ([SWS_DM_00810]). Перед уничтожением через виртуальный деструктор ~CommunicationControl() ([SWS_DM_00807]) сервис должен быть штатно остановлен.

Диаграмма состояний: жизненный цикл экземпляра CommunicationControl. Источники: [SWS_DM_00806], [SWS_DM_00807], [SWS_DM_00809], [SWS_DM_00810]

Путь использования

Штатный процесс включает создание обработчика, регистрацию в демоне Diagnostic Management и асинхронную обработку UDS-запросов:

  1. Инстанцирование: приложение инстанцирует производный от ara::diag::CommunicationControl класс с подходящим InstanceSpecifier ([SWS_DM_00806]).
  2. Предоставление сервиса: вызов Offer() активирует пересылку запросов демоном DM ([SWS_DM_00809]).
  3. Обработка запроса: при поступлении диагностического сообщения 0x28 демон DM вызывает переопределенный метод CommCtrlRequest(controlType, metaInfo, cancellationHandler) ([SWS_DM_00808]). Параметр controlType содержит все параметры UDS-запроса, включая значение подфункции. Приложение возвращает ara::core::Future<void>.
  4. Мониторинг прерывания: во время выполнения приложение может проверить через cancellationHandler.IsCanceled(), был ли прерван диалог, или зарегистрировать уведомление через cancellationHandler.SetNotifier ([SWS_DM_00808]).
  5. Завершение: как только действие выполнено, Promise удовлетворяет возвращенный Future, после чего DM отправляет тестеру положительный UDS-ответ.
  6. Завершение сервиса: перед завершением работы StopOffer() останавливает прием дальнейших запросов ([SWS_DM_00810]).

Диаграмма последовательности: типичная обработка запроса UDS 0x28. Источники: [SWS_DM_00808], [SWS_DM_00809], [SWS_DM_00810]

Сценарии ошибок

Ошибки могут возникать как при привязке конфигурации и регистрации сервиса, так и при обработке UDS-запросов:

  • Нарушения в конструкторе: если разрешение модели завершается неудачно, возникают специфические нарушения ([SWS_DM_00806]):
    • InstanceSpecifierMappingIntegrityViolation: идентификатор не может быть разрешен или не ссылается на PortPrototype.
    • PortInterfaceMappingViolation: на элемент порта, типизированный через DiagnosticComControlInterface, не ссылается DiagnosticServiceGenericMapping.
    • ProcessMappingViolation: подходящий смоделированный процесс для среды выполнения не найден.
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже используется внутри процесса.
  • Ошибка предоставления сервиса: если Offer() вызывается в то время, когда сервис уже предлагается, вызов завершается сбоем и возвращает код ошибки DiagOfferErrc::kAlreadyOffered ([SWS_DM_00809]).
  • Отрицательные диагностические ответы (NRC): если запрос не может быть обработан по функциональным причинам (например, недопустимая субфункция или невыполненные условия), реализация через Future сообщает соответствующий Negative Response Code (NRC) по стандарту ISO 14229-1 через DiagUdsNrcErrc обратно в DM ([SWS_DM_00808]).

Настоящее руководство основано на спецификации AUTOSAR Adaptive R25-11 (модуль diag).
