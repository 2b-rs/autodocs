класс ara::log::LogStream

[SWS_LOG_00173] Upstream: RS_LT_00003, RS_LT_00046

class LogStream final {...};

Represents a Log message, allowing stream operators to be used for appending data. Note: Normally Application processes would not use this class directly. Instead one of the log methods provided in the main Logging API shall be used. Those methods automatically setup a temporary object of this class with the given log severity level. The only reason to use this class directly is, if the user wants to hold a ara::log::LogStream object longer than the default one-statement scope. This is useful in order to create log messages that are distributed over multiple code lines. See the ara::log::LogStream::Flush method for further information. Once this temporary object gets out of scope, its destructor takes care that the message buffer is ready to be processed by the Logging framework. Besides the existing supported operator<< overloads for ara::log::LogStream it can be easily extended for other derived types by providing a stream operator that makes use of already supported types.

Example: struct MyCustomType { int8_t foo; ara::core::String bar; };

LogStream& operator<<(LogStream& out, const MyCustomType& value) { return (out << value.foo << value.bar); }

// Producing the output "42 the answer is." Logger& ctx0 = CreateLogger("CTX0", "Context Description CTX0"); ctx0.LogDebug () << MyCustomType{42, " the answer is."};

Контекст и роль

Класс ara::log::LogStream представляет форматированное сообщение журналирования в рамках AUTOSAR Adaptive Platform и предоставляет потоковые операторы для сборки сообщений журнала. Как правило, процессы приложений не взаимодействуют с этим классом напрямую через конструкторы. Вместо этого основные интерфейсы API журналирования (например, контекст Logger) предоставляют специфические методы журналирования, которые настраивают и возвращают временные экземпляры ara::log::LogStream с соответствующим уровнем важности (Severity Level).

Взаимодействие обычно происходит между тремя сторонами: приложением, которое передает данные в поток, объектом LogStream, который буферизует полезные данные и метаданные, а также нижележащим фреймворком журналирования, которому буфер передается для окончательной обработки. Прямое инстанциирование или более длительное хранение объекта LogStream предназначено исключительно для компоновки сообщений журнала через несколько строк или инструкций.

Контекстная диаграмма: взаимодействие между приложением, API журналирования, LogStream и фреймворком журналирования. Источники: [SWS_LOG_00039], [SWS_LOG_00176], [SWS_LOG_00262]

Жизненный цикл и отношения владения

Жизненный цикл ara::log::LogStream рассчитан на строгую привязку к области видимости создания и ограничительные отношения владения:

  • Создание и семантика перемещения: конструктор перемещения [SWS_LOG_00176] объявлен как noexcept, однако обычно не определяется. Это требование спецификации позволяет компилятору, совместимому с C++14, возвращать экземпляры вызывающей стороне напрямую из фабричных методов API журналирования с помощью Return Value Optimization (RVO).
  • Ограничения копирования и присваивания: как конструктор копирования [SWS_LOG_00174], так и оператор копирующего присваивания [SWS_LOG_00175] и оператор перемещающего присваивания [SWS_LOG_00177] удалены (= delete). Поэтому экземпляры нельзя ни дублировать, ни перемещать впоследствии.
  • Уничтожение и передача буфера: стандартным случаем является область видимости одной инструкции, при которой временный объект уничтожается в конце инструкции. Деструктор [SWS_LOG_00262] определен как noexcept и гарантирует, что внутренний буфер сообщений передается во фреймворк логирования для дальнейшей обработки.
  • Многострочное повторное использование через Flush: если объект LogStream сохраняется локально на протяжении нескольких инструкций, необходимо вызвать метод Flush() [SWS_LOG_00039], чтобы отправить текущее содержимое буфера во фреймворк логирования и инициировать новый поток сообщений. Следует отметить, что Flush() не очищает буфер, а передает дальше его текущее состояние.
  • Параллелизм: согласно определениям интерфейса ara::log::LogStream не является потокобезопасным (not thread-safe). Экземпляр не должен наполняться или изменяться конкурентно из нескольких потоков без защиты.

Сценарий использования и связывание операторов в цепочку

Стандартный сценарий использования реализуется через fluent-интерфейс перегруженных операторов сдвига (operator<<) и методов метаданных, каждый из которых возвращает ссылку на *this:

  1. Добавление метаданных: до или во время потоковой передачи можно добавить контекстную информацию. WithLocation() [SWS_LOG_00129] вставляет имя исходного файла и номер строки, WithTag() [SWS_LOG_00132] присоединяет тег к сообщению, а WithPrivacy() [SWS_LOG_00258] настраивает уровень конфиденциальности данных.
  2. Ввод полезных данных: перегрузки operator<< принимают стандартные типы данных:
    • Логические значения через [SWS_LOG_00040].
    • Знаковые целочисленные типы (от 8 до 64 бит) через [SWS_LOG_00045], [SWS_LOG_00046], [SWS_LOG_00047] и [SWS_LOG_00048].
    • Беззнаковые целые числа (от 8 до 64 бит) через [SWS_LOG_00041], [SWS_LOG_00042], [SWS_LOG_00043] и [SWS_LOG_00044].
    • Типы с плавающей точкой (float, double) через [SWS_LOG_00049] и [SWS_LOG_00050].
    • Строки в виде нуль-терминированных UTF-8-строк через [SWS_LOG_00051] или в виде ara::core::StringView через [SWS_LOG_00062].
    • Двоичные последовательности через ara::core::Span<const ara::core::Byte> через [SWS_LOG_00128].
    • Атрибутированные аргументы через ara::log::Argument<T> через [SWS_LOG_00203].
  3. Расширяемость: определяемые приложением типы могут быть беспрепятственно интегрированы путем предоставления свободных потоковых операторов, сопоставляющих пользовательские структуры с существующими базовыми операторами.
  4. Завершение: при выходе из области видимости инструкции или функции деструктор [SWS_LOG_00262] автоматически инициирует процесс сброса во фреймворк логирования.

Диаграмма последовательности: создание, дополнение метаданных, потоковая передача и передача буфера в стандартном случае и в случае нескольких инструкций. Источники: [SWS_LOG_00039], [SWS_LOG_00129], [SWS_LOG_00132], [SWS_LOG_00040], [SWS_LOG_00051], [SWS_LOG_00262]

Сценарии ошибок и граничные условия

Интерфейсы ara::log::LogStream не генерируют исключений и гарантируют безопасность исключений:

  • Гарантия noexcept: все методы и операторы ([SWS_LOG_00039], [SWS_LOG_00129], [SWS_LOG_00132], [SWS_LOG_00258], [SWS_LOG_00262], а также перегрузки operator<<) помечены как noexcept.
  • Ограничение типов для WithPrivacy: шаблон WithPrivacy<T>() [SWS_LOG_00258] строго требует целочисленный тип или тип перечисления для T. Вызов с отличающимися типами приводит к некорректной программе (ill-formed) и прерывается еще на этапе компиляции. Кроме того, во время выполнения оцениваются исключительно младшие 8 бит переданного значения; старшие биты игнорируются.
  • Отсутствие синхронизации: поскольку класс внутри не содержит механизмов синхронизации, при межпоточном использовании синхронизация обязательно должна выполняться на уровне вызывающей стороны для предотвращения повреждения данных во внутреннем буфере.

<h4>Контекст и роль</h4>
<p>Класс <code>ara::log::LogStream</code> представляет форматированное сообщение журналирования в рамках AUTOSAR Adaptive Platform и предоставляет потоковые операторы для сборки сообщений журнала. Как правило, процессы приложений не взаимодействуют с этим классом напрямую через конструкторы. Вместо этого основные интерфейсы API журналирования (например, контекст <code>Logger</code>) предоставляют специфические методы журналирования, которые настраивают и возвращают временные экземпляры <code>ara::log::LogStream</code> с соответствующим уровнем важности (Severity Level).</p>
<p>Взаимодействие обычно происходит между тремя сторонами: приложением, которое передает данные в поток, объектом <code>LogStream</code>, который буферизует полезные данные и метаданные, а также нижележащим фреймворком журналирования, которому буфер передается для окончательной обработки. Прямое инстанциирование или более длительное хранение объекта <code>LogStream</code> предназначено исключительно для компоновки сообщений журнала через несколько строк или инструкций.</p>

<h4>Жизненный цикл и отношения владения</h4>
<p>Жизненный цикл <code>ara::log::LogStream</code> рассчитан на строгую привязку к области видимости создания и ограничительные отношения владения:</p>
<ul>
  <li><strong>Создание и семантика перемещения:</strong> конструктор перемещения <a class="spec-record-ref" data-req="SWS_LOG_00176" href="../spec/record.html?id=SWS_LOG_00176">[SWS_LOG_00176]</a> объявлен как <code>noexcept</code>, однако обычно не определяется. Это требование спецификации позволяет компилятору, совместимому с C++14, возвращать экземпляры вызывающей стороне напрямую из фабричных методов API журналирования с помощью Return Value Optimization (RVO).</li>
  <li><strong>Ограничения копирования и присваивания:</strong> как конструктор копирования <a class="spec-record-ref" data-req="SWS_LOG_00174" href="../spec/record.html?id=SWS_LOG_00174">[SWS_LOG_00174]</a>, так и оператор копирующего присваивания <a class="spec-record-ref" data-req="SWS_LOG_00175" href="../spec/record.html?id=SWS_LOG_00175">[SWS_LOG_00175]</a> и оператор перемещающего присваивания <a class="spec-record-ref" data-req="SWS_LOG_00177" href="../spec/record.html?id=SWS_LOG_00177">[SWS_LOG_00177]</a> удалены (<code>= delete</code>). Поэтому экземпляры нельзя ни дублировать, ни перемещать впоследствии.</li>
  <li><strong>Уничтожение и передача буфера:</strong> стандартным случаем является область видимости одной инструкции, при которой временный объект уничтожается в конце инструкции. Деструктор <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a> определен как <code>noexcept</code> и гарантирует, что внутренний буфер сообщений передается во фреймворк логирования для дальнейшей обработки.</li>
  <li><strong>Многострочное повторное использование через Flush:</strong> если объект <code>LogStream</code> сохраняется локально на протяжении нескольких инструкций, необходимо вызвать метод <code>Flush()</code> <a class="spec-record-ref" data-req="SWS_LOG_00039" href="../spec/record.html?id=SWS_LOG_00039">[SWS_LOG_00039]</a>, чтобы отправить текущее содержимое буфера во фреймворк логирования и инициировать новый поток сообщений. Следует отметить, что <code>Flush()</code> не очищает буфер, а передает дальше его текущее состояние.</li>
  <li><strong>Параллелизм:</strong> согласно определениям интерфейса <code>ara::log::LogStream</code> не является потокобезопасным (<code>not thread-safe</code>). Экземпляр не должен наполняться или изменяться конкурентно из нескольких потоков без защиты.</li>
</ul>

<h4>Сценарий использования и связывание операторов в цепочку</h4>
<p>Стандартный сценарий использования реализуется через fluent-интерфейс перегруженных операторов сдвига (<code>operator&lt;&lt;</code>) и методов метаданных, каждый из которых возвращает ссылку на <code>*this</code>:</p>
<ol>
  <li><strong>Добавление метаданных:</strong> до или во время потоковой передачи можно добавить контекстную информацию. <code>WithLocation()</code> <a class="spec-record-ref" data-req="SWS_LOG_00129" href="../spec/record.html?id=SWS_LOG_00129">[SWS_LOG_00129]</a> вставляет имя исходного файла и номер строки, <code>WithTag()</code> <a class="spec-record-ref" data-req="SWS_LOG_00132" href="../spec/record.html?id=SWS_LOG_00132">[SWS_LOG_00132]</a> присоединяет тег к сообщению, а <code>WithPrivacy()</code> <a class="spec-record-ref" data-req="SWS_LOG_00258" href="../spec/record.html?id=SWS_LOG_00258">[SWS_LOG_00258]</a> настраивает уровень конфиденциальности данных.</li>
  <li><strong>Ввод полезных данных:</strong> перегрузки <code>operator&lt;&lt;</code> принимают стандартные типы данных:
    <ul>
      <li>Логические значения через <a class="spec-record-ref" data-req="SWS_LOG_00040" href="../spec/record.html?id=SWS_LOG_00040">[SWS_LOG_00040]</a>.</li>
      <li>Знаковые целочисленные типы (от 8 до 64 бит) через <a class="spec-record-ref" data-req="SWS_LOG_00045" href="../spec/record.html?id=SWS_LOG_00045">[SWS_LOG_00045]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00046" href="../spec/record.html?id=SWS_LOG_00046">[SWS_LOG_00046]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00047" href="../spec/record.html?id=SWS_LOG_00047">[SWS_LOG_00047]</a> и <a class="spec-record-ref" data-req="SWS_LOG_00048" href="../spec/record.html?id=SWS_LOG_00048">[SWS_LOG_00048]</a>.</li>
      <li>Беззнаковые целые числа (от 8 до 64 бит) через <a class="spec-record-ref" data-req="SWS_LOG_00041" href="../spec/record.html?id=SWS_LOG_00041">[SWS_LOG_00041]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00042" href="../spec/record.html?id=SWS_LOG_00042">[SWS_LOG_00042]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00043" href="../spec/record.html?id=SWS_LOG_00043">[SWS_LOG_00043]</a> и <a class="spec-record-ref" data-req="SWS_LOG_00044" href="../spec/record.html?id=SWS_LOG_00044">[SWS_LOG_00044]</a>.</li>
      <li>Типы с плавающей точкой (<code>float</code>, <code>double</code>) через <a class="spec-record-ref" data-req="SWS_LOG_00049" href="../spec/record.html?id=SWS_LOG_00049">[SWS_LOG_00049]</a> и <a class="spec-record-ref" data-req="SWS_LOG_00050" href="../spec/record.html?id=SWS_LOG_00050">[SWS_LOG_00050]</a>.</li>
      <li>Строки в виде нуль-терминированных UTF-8-строк через <a class="spec-record-ref" data-req="SWS_LOG_00051" href="../spec/record.html?id=SWS_LOG_00051">[SWS_LOG_00051]</a> или в виде <code>ara::core::StringView</code> через <a class="spec-record-ref" data-req="SWS_LOG_00062" href="../spec/record.html?id=SWS_LOG_00062">[SWS_LOG_00062]</a>.</li>
      <li>Двоичные последовательности через <code>ara::core::Span&lt;const ara::core::Byte&gt;</code> через <a class="spec-record-ref" data-req="SWS_LOG_00128" href="../spec/record.html?id=SWS_LOG_00128">[SWS_LOG_00128]</a>.</li>
      <li>Атрибутированные аргументы через <code>ara::log::Argument&lt;T&gt;</code> через <a class="spec-record-ref" data-req="SWS_LOG_00203" href="../spec/record.html?id=SWS_LOG_00203">[SWS_LOG_00203]</a>.</li>
    </ul>
  </li>
  <li><strong>Расширяемость:</strong> определяемые приложением типы могут быть беспрепятственно интегрированы путем предоставления свободных потоковых операторов, сопоставляющих пользовательские структуры с существующими базовыми операторами.</li>
  <li><strong>Завершение:</strong> при выходе из области видимости инструкции или функции деструктор <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a> автоматически инициирует процесс сброса во фреймворк логирования.</li>
</ol>

<h4>Сценарии ошибок и граничные условия</h4>
<p>Интерфейсы <code>ara::log::LogStream</code> не генерируют исключений и гарантируют безопасность исключений:</p>
<ul>
  <li><strong>Гарантия noexcept:</strong> все методы и операторы (<a class="spec-record-ref" data-req="SWS_LOG_00039" href="../spec/record.html?id=SWS_LOG_00039">[SWS_LOG_00039]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00129" href="../spec/record.html?id=SWS_LOG_00129">[SWS_LOG_00129]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00132" href="../spec/record.html?id=SWS_LOG_00132">[SWS_LOG_00132]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00258" href="../spec/record.html?id=SWS_LOG_00258">[SWS_LOG_00258]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a>, а также перегрузки <code>operator&lt;&lt;</code>) помечены как <code>noexcept</code>.</li>
  <li><strong>Ограничение типов для WithPrivacy:</strong> шаблон <code>WithPrivacy&lt;T&gt;()</code> <a class="spec-record-ref" data-req="SWS_LOG_00258" href="../spec/record.html?id=SWS_LOG_00258">[SWS_LOG_00258]</a> строго требует целочисленный тип или тип перечисления для <code>T</code>. Вызов с отличающимися типами приводит к некорректной программе (ill-formed) и прерывается еще на этапе компиляции. Кроме того, во время выполнения оцениваются исключительно младшие 8 бит переданного значения; старшие биты игнорируются.</li>
  <li><strong>Отсутствие синхронизации:</strong> поскольку класс внутри не содержит механизмов синхронизации, при межпоточном использовании синхронизация обязательно должна выполняться на уровне вызывающей стороны для предотвращения повреждения данных во внутреннем буфере.</li>
</ul>
