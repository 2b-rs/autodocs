класс ara::log::LogStream

[SWS_LOG_00173] Upstream: RS_LT_00003, RS_LT_00046

class LogStream final {...};

Represents a Log message, allowing stream operators to be used for appending data. Note: Normally Application processes would not use this class directly. Instead one of the log methods provided in the main Logging API shall be used. Those methods automatically setup a temporary object of this class with the given log severity level. The only reason to use this class directly is, if the user wants to hold a ara::log::LogStream object longer than the default one-statement scope. This is useful in order to create log messages that are distributed over multiple code lines. See the ara::log::LogStream::Flush method for further information. Once this temporary object gets out of scope, its destructor takes care that the message buffer is ready to be processed by the Logging framework. Besides the existing supported operator<< overloads for ara::log::LogStream it can be easily extended for other derived types by providing a stream operator that makes use of already supported types.

Example: struct MyCustomType { int8_t foo; ara::core::String bar; };

LogStream& operator<<(LogStream& out, const MyCustomType& value) { return (out << value.foo << value.bar); }

// Producing the output "42 the answer is." Logger& ctx0 = CreateLogger("CTX0", "Context Description CTX0"); ctx0.LogDebug () << MyCustomType{42, " the answer is."};

Буферизует данные журнала через операторы потока и передает отформатированные сообщения в инфраструктуру логирования.

Класс ara::log::LogStream представляет собой форматируемое сообщение журнала, внутренний буфер которого пошагово заполняется данными и метаданными через операторы потока. Экземпляры обычно получаются временно через методы логирования и при выходе из области видимости автоматически передают собранное содержимое в инфраструктуру логирования через деструктор [SWS_LOG_00262]. Для многострочных или повторно используемых сообщений пересылка может быть инициирована явно через Flush() [SWS_LOG_00039]. В качестве центрального граничного условия класс не является потокобезопасным и полностью запрещает операции копирования.

Контекст

Класс ara::log::LogStream представляет собой форматируемое сообщение журнала в адаптивной подсистеме логирования. Он предоставляет ориентированный на сообщения интерфейс буфера, позволяющий пошагово добавлять разнородные полезные данные во внутренний буфер через перегруженные операторы потока.

В обычном сценарии использования процессы приложений не взаимодействуют с LogStream напрямую путем явного создания экземпляров. Вместо этого основной API логирования (например, через такие методы логирования, как LogDebug()) предоставляет временные экземпляры этого класса, уже инициализированные с требуемым уровнем важности. Единственная предусмотренная причина удержания объекта LogStream за пределами стандартной области видимости одного оператора (One-Statement-Scope) заключается в сборке сообщений журнала по нескольким строкам кода. Как только объект выходит из своей области видимости или явно сбрасывается, содержимое буфера передается в инфраструктуру логирования для дальнейшей обработки.

Контекстная диаграмма: взаимодействие между процессом приложения, API логирования, LogStream и инфраструктурой логирования. Источники: [SWS_LOG_00039], [SWS_LOG_00262]

Жизненный цикл

Создание экземпляров LogStream выполняется преимущественно в виде временного объекта через фабричные методы основного API логирования. Для эффективного предоставления класс объявляет конструктор перемещения как noexcept [SWS_LOG_00176]. Этот конструктор перемещения обычно лишь объявляется, но не определяется, что позволяет компиляторам, совместимым с C++14, использовать оптимизацию возвращаемого значения (RVO) при возврате из фабричных функций [SWS_LOG_00176]. Дублирование или присваивание с перемещением экземпляров строго исключены: конструктор копирования [SWS_LOG_00174], оператор присваивания копированием [SWS_LOG_00175] и оператор присваивания перемещением [SWS_LOG_00177] удалены (=delete).

Завершение жизненного цикла управляется деструктором ~LogStream() [SWS_LOG_00262]. Если объект выходит из своей области видимости (например, в конце блока функции или оператора), деструктор внутренне обеспечивает пересылку содержимого буфера для обработки в инфраструктуру логирования [SWS_LOG_00039], [SWS_LOG_00262].

Если экземпляр LogStream повторно используется в той же области видимости для нескольких последовательных сообщений, необходимо вызвать функцию-член Flush() [SWS_LOG_00039]. При этом важно отметить, что Flush() не очищает буфер, а отправляет текущие данные в инфраструктуру логирования и немедленно инициирует новый поток сообщений [SWS_LOG_00039].

Что касается параллелизма, все функции-члены специфицированы как непотокобезопасные ([SWS_LOG_00039], [SWS_LOG_00040], [SWS_LOG_00129]). Поэтому экземпляр LogStream не должен использоваться параллельно несколькими потоками без внешней синхронизации.

Путь использования

Типичный процесс логирования включает следующие фазы:

  1. Предоставление потока: процесс приложения вызывает метод логирования, который создает временный экземпляр LogStream и возвращает его через RVO [SWS_LOG_00176].
  2. Обогащение метаданными: до или во время ввода данных могут быть добавлены опциональные атрибуты посредством цепочки вызовов методов, включая указание места в исходном коде через WithLocation(file, line) [SWS_LOG_00129], тегов через WithTag(tag) [SWS_LOG_00132] или уровней конфиденциальности через WithPrivacy(value) [SWS_LOG_00258]. Каждый из этих методов возвращает ссылку на *this.
  3. Заполнение данными: полезные данные записываются во внутренний буфер через перегруженные операторы operator<<. Интерфейс поддерживает стандартные типы, такие как логические значения [SWS_LOG_00040], целые числа различной разрядности [SWS_LOG_00041], [SWS_LOG_00044], числа с плавающей запятой [SWS_LOG_00049], символьные строки и строковые представления [SWS_LOG_00051], [SWS_LOG_00062], байтовые последовательности через core::Span<const core::Byte> [SWS_LOG_00128], а также структурированные аргументы через Argument<T> [SWS_LOG_00203]. Кроме того, оператор может быть расширен для пользовательских типов.
  4. Передача в инфраструктуру: при выходе из области видимости деструктор пересылает сообщение [SWS_LOG_00262]. Если экземпляр должен сохраняться для дальнейших сообщений, явно вызывается Flush() [SWS_LOG_00039].

Диаграмма последовательности: процесс логирования от создания потока через заполнение метаданными и данными до отправки при завершении области видимости или через Flush(). Источники: [SWS_LOG_00039], [SWS_LOG_00040], [SWS_LOG_00129], [SWS_LOG_00176], [SWS_LOG_00262]

Сценарии ошибок

Класс следует строгому подходу No-Exception-Design. Все функции-члены, включая операторы потока (от [SWS_LOG_00040] до [SWS_LOG_00051], [SWS_LOG_00062], [SWS_LOG_00128], [SWS_LOG_00203]), WithLocation() [SWS_LOG_00129], WithTag() [SWS_LOG_00132], WithPrivacy() [SWS_LOG_00258], Flush() [SWS_LOG_00039] и деструктор [SWS_LOG_00262], объявлены как noexcept и являются исключение-безопасными («exception safe»).

Условия ошибок и риски использования ограничиваются следующими сценариями:

  • Ошибка типа при WithPrivacy: шаблон WithPrivacy<T> строго требует, чтобы T являлся целочисленным типом или типом перечисления. Если функция инстанцируется с несоответствующим типом, программа некорректна (ill-formed) и приводит к ошибке компиляции [SWS_LOG_00258]. Кроме того, используются только младшие 8 бит переданного значения, а старшие биты игнорируются [SWS_LOG_00258].
  • Отсутствие потокобезопасности: поскольку LogStream определен как непотокобезопасный ([SWS_LOG_00039], [SWS_LOG_00040]), конкурентные операции чтения или записи над одним и тем же экземпляром без внешней синхронизации, предположительно, приводят к несогласованности данных или повреждению буфера (интерпретация). Вопрос Q-30a5037999c96fa2 (открытый)
  • Передача буфера при Flush: поскольку Flush() физически не очищает буфер, а лишь передает текущее содержимое в инфраструктуру логирования [SWS_LOG_00039], при повторном использовании необходимо учитывать, что семантически начинается новое сообщение.

Функция-член Flush класса ara::log::LogStream (предоставляемая через заголовочный файл ara/log/log_stream.h) передает текущее состояние буфера журнала в платформу журналирования и одновременно инициирует новый поток сообщений [SWS_LOG_00039]. Здесь важно различать, что вызов ara::log::LogStream::Flush не очищает буфер, а передает его текущие данные во фреймворк без изменений [SWS_LOG_00039].

Явный вызов функции требуется только в том случае, если объект ara::log::LogStream должен повторно использоваться в той же области видимости для последующего вывода журнала [SWS_LOG_00039]. Если же объект выходит за пределы своей области видимости — например, при достижении конца блока функции, — отправка буфера выполняется автоматически внутри через деструктор класса [SWS_LOG_00039].

Метод имеет сигнатуру void Flush () noexcept;, не принимает аргументов и не имеет возвращаемого значения [SWS_LOG_00039]. Он помечен как исключениебезопасный («exception safe»), однако не обеспечивает потокобезопасность («not thread-safe») [SWS_LOG_00039].
