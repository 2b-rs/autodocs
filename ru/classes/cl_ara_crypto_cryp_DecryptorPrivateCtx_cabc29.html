Обеспечивает асимметричное расшифрование данных с использованием закрытых ключей в виде однократного вызова или потока данных.

Интерфейс ara::crypto::cryp::DecryptorPrivateCtx предназначен для асимметричного расшифрования шифротекстов в AUTOSAR Adaptive Platform ([SWS_CRYPT_50070]). Перед выполнением контексту обязательно должен быть передан закрытый ключ, обладающий правами на расшифрование ([SWS_CRYPT_50157]). Обработка может выполняться либо в рамках одиночного вызова, либо в виде составного потока данных через фазы Start, Update и Finish. Все методы интерфейса реализованы потокобезопасными и исключениебезопасными.

Контекст

Интерфейс ara::crypto::cryp::DecryptorPrivateCtx служит для асимметричного расшифрования шифротекстов в модуле криптографии AUTOSAR Adaptive Platform. Являясь специализацией CryptoContext, он предоставляет криптографические функции преобразования, с помощью которых шифротексты переводятся обратно в открытый текст с использованием закрытых ключей. К основным партнерам по взаимодействию относятся вызывающее приложение и ключевые объекты, предоставляемые как PrivateKey или через KeySlot. Экземпляры этого интерфейса обычно управляются через типизированный умный указатель Sptr ([SWS_CRYPT_50156]).

Жизненный цикл

Управление DecryptorPrivateCtx осуществляется через псевдоним ara::crypto::cryp::DecryptorPrivateCtx::Sptr, отображаемый на std::shared_ptr<DecryptorPrivateCtx> ([SWS_CRYPT_50156]). Интерпретация: поскольку данный класс представляет собой интерфейс с чисто виртуальными методами, конкретное создание, вероятно, обычно выполняется фабрикой криптодрайвера.

Сразу после инстанцирования контекст находится в неинициализированном состоянии. В этом состоянии рабочие вызовы преобразования приводят к ошибкам. Для активации необходимо назначить закрытый ключ. Это осуществляется либо передачей PrivateKey::Sptr с помощью SetKey() ([SWS_CRYPT_50157]), либо через KeySlot::Sptr ([SWS_CRYPT_50066]), инкапсулирующий ключ.

Как только контекст сконфигурирован с действительным ключом, он переходит в состояние Initialized. В этом состоянии контекст может использоваться либо непосредственно для однократного расшифрования, либо переводиться через Start() ([SWS_CRYPT_50067]) в состояние обработки Streaming. Во время потоковой передачи Update() ([SWS_CRYPT_50158]) принимает фрагменты шифротекста. Последовательность завершается методом Finish() ([SWS_CRYPT_50068]) или прерывается через Cancel() ([SWS_CRYPT_50069]), после чего контекст снова готов к новым операциям. Все методы интерфейса специфицированы как потокобезопасные и исключениебезопасные ([SWS_CRYPT_50066], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).

Диаграмма состояний: состояния жизненного цикла контекста от привязки ключа через потоковую передачу до завершения. Источники: [SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50158], [SWS_CRYPT_50068], [SWS_CRYPT_50069], [SWS_CRYPT_50070].

Путь использования

Для расшифрования доступны два различных процесса: однократное расшифрование без сохранения состояния и многошаговая потоковая обработка. Перед передачей данных вызывающее приложение может запросить допустимые ограничения на входные данные для шифротекстов с помощью GetMinimumChunkSize() ([SWS_CRYPT_50160]) и GetMaximumChunkSize() ([SWS_CRYPT_50071]). С помощью GetRequiredOutputBufferSize() ([SWS_CRYPT_50159]) можно предварительно определить требуемый размер выходного буфера для Update(), Finish() или Decrypt().

Для компактных объемов данных расшифрование после конфигурации ключа выполняется непосредственно через Decrypt() ([SWS_CRYPT_50070]). Шифротекст преобразуется за один шаг, и возвращается фактическое количество расшифрованных байтов.

Более крупные или фрагментированные входящие шифротексты обрабатываются по пути потоковой передачи:

  1. Назначение ключа: конфигурация контекста через SetKey() с PrivateKey ([SWS_CRYPT_50157]) или KeySlot ([SWS_CRYPT_50066]).
  2. Инициализация: вызов Start() ([SWS_CRYPT_50067]) для подготовки внутреннего состояния обработки.
  3. Поблочная обработка: повторный вызов Update() ([SWS_CRYPT_50158]) для последовательных блоков шифротекста.
  4. Финализация: вызов Finish() ([SWS_CRYPT_50068]) для обработки финального блока и завершения потока. В качестве альтернативы операция может быть прервана досрочно с помощью Cancel() ([SWS_CRYPT_50069]).

Диаграмма последовательности: типичная последовательность вызовов многоэтапного потокового расшифрования. Источники: [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50158], [SWS_CRYPT_50068].

Сценарии ошибок

Методы DecryptorPrivateCtx возвращают ошибки через ara::core::Result с кодами из ara::crypto::CryptoErrc и следуют семантике отката:

  • ara::crypto::CryptoErrc::kUninitializedContext: возникает, когда операции преобразования, такие как Decrypt() ([SWS_CRYPT_50070]) или Start() ([SWS_CRYPT_50067]), а также вычисления буфера через GetRequiredOutputBufferSize() ([SWS_CRYPT_50159]) вызываются до того, как был сконфигурирован ключ.
  • ara::crypto::CryptoErrc::kProcessingNotStarted: возвращается из Update() ([SWS_CRYPT_50158]), Finish() ([SWS_CRYPT_50068]) или Cancel() ([SWS_CRYPT_50069]), если предшествующий вызов Start() не выполнялся.
  • ara::crypto::CryptoErrc::kUsageViolation: сигнализирует о том, что правила использования ключа не содержат разрешения kAllowDataDecryption ([SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kIncompatibleObject: возникает, если назначенный ключевой объект или слот не подходит для алгоритма контекста ([SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kInsufficientCapacity и ara::crypto::CryptoErrc::kInvalidInputSize: выходной буфер не обладает достаточной емкостью или размер входных данных нарушает граничные значения контекста ([SWS_CRYPT_50070], [SWS_CRYPT_50158], [SWS_CRYPT_50068]).
  • ara::crypto::CryptoErrc::kUnsupported: указывает на то, что потоковая передача, однократные вызовы или выбранный способ привязки ключа не поддерживаются конкретной реализацией ([SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kEmptyKeySlot и ara::crypto::CryptoErrc::kBusyResource: указывают на то, что сконфигурированный KeySlot в данный момент пуст или требуемый ресурс занят ([SWS_CRYPT_50067], [SWS_CRYPT_50070]).

Определённый в ara/crypto/cryp/decryptor_private_ctx.h метод Cancel класса ara::crypto::cryp::DecryptorPrivateCtx прерывает выполняющуюся потоковую операцию, которая ранее была инициирована с помощью Start() и ещё не завершена [SWS_CRYPT_50069]. Вызов не принимает входных параметров и в качестве возвращаемого значения возвращает ara::core::Result<void> [SWS_CRYPT_50069]. Если прерывание потоковой обработки прошло успешно, объект содержит пустой результат; в противном случае он передаёт возникшую ошибку [SWS_CRYPT_50069]. Чисто виртуальный интерфейс объявлен как noexcept, обладает полной безопасностью относительно исключений и обозначен как thread-safe для конкурентного доступа [SWS_CRYPT_50069].

При обработке ошибок и условий выполнения следует соблюдать точный порядок: если обработка данных ранее не была инициирована вызовом метода Start(), операция завершается неудачей и возвращает специфический код ошибки ara::crypto::CryptoErrc::kProcessingNotStarted с семантикой отката [SWS_CRYPT_50069]. Поэтому вызывающая сторона должна убедиться, что до прерывания уже существует активная операция, чтобы избежать этого состояния ошибки [SWS_CRYPT_50069].

Во взаимодействии со всей архитектурой модуля crypt метод Cancel следует стандартизированному шаблону проектирования для потоковых процессов с состоянием. Одинаковую сигнатуру, семантику возвращаемого значения и обработку ошибок разделяют родственные криптографические контексты ara::crypto::cryp::VerifierPublicCtx [SWS_CRYPT_50023], ara::crypto::cryp::MessageAuthnCodeCtx [SWS_CRYPT_50027], ara::crypto::cryp::SignerPrivateCtx [SWS_CRYPT_50041], ara::crypto::cryp::SymmetricCipherCtx [SWS_CRYPT_50046], ara::crypto::cryp::HashFunctionCtx [SWS_CRYPT_50058], ara::crypto::cryp::AuthCipherCtx [SWS_CRYPT_50077], а также ara::crypto::cryp::EncryptorPublicCtx [SWS_CRYPT_50089].

      Синхронный метод Decrypt дешифрует данные зашифрованного текста за один шаг ([SWS_CRYPT_50070]). Входной буфер in передает зашифрованный текст как ReadOnlyMemRegion, в то время как выходной буфер out типа ReadWriteMemRegion принимает открытый текст ([SWS_CRYPT_50070]). При успешном дешифровании функция через ara::core::Result<std::size_t> возвращает фактическое количество записанных байтов, которое может быть меньше общей емкости out ([SWS_CRYPT_50070]).
      

      Интерфейс специфицирован как thread-safe, а также exception safe ([SWS_CRYPT_50070]). Перед вызовом контекст должен быть инициализирован назначением ключа; в противном случае функция завершается неудачно с UninitializedContext или, при пустом KeySlot, с ara::crypto::CryptoErrc::kEmptyKeySlot ([SWS_CRYPT_50070]). Ключ должен быть совместим с алгоритмом преобразования (иначе kIncompatibleObject) и включать право доступа kAllowDataDecryption (иначе kUsageViolation) ([SWS_CRYPT_50070]).
      

      Чтобы предотвратить переполнение буфера, максимально необходимую емкость выходного буфера можно предварительно запросить с помощью GetRequiredOutputBufferSize с указанием isFinal = true ([SWS_CRYPT_50159]). Если емкости out недостаточно, метод аварийно завершается с ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50070]). Кроме того, размер входного буфера in должен находиться в диапазоне между GetMinimumChunkSize ([SWS_CRYPT_50160]) и GetMaximumChunkSize ([SWS_CRYPT_50071]), в противном случае возвращается ara::crypto::CryptoErrc::kInvalidInputSize ([SWS_CRYPT_50070]). Другими специфицированными ошибками с семантикой отката являются kUnsupported, kInvalidArgument, а также kBusyResource ([SWS_CRYPT_50070]).
