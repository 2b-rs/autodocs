Контекст

Структура данных ara::diag::SovdSwUpdate::UpdatePackageDetails ([SWS_DM_01877], AUTOSAR_AP_SWS_Diagnostics §8.58.4 «Struct: UpdatePackageDetails») служит в рамках AUTOSAR Adaptive Platform в модуле diag структурированным носителем информации для метаданных и параметров выполнения пакета обновления программного обеспечения. Она объявлена в заголовочном файле #include "ara/diag/sovd_sw_update.h" и представляет собой важный элемент интерфейса для связанных с программным обеспечением диагностических процессов и процессов обновления, предоставляемых через стандарт ASAM SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01796]).

Архитектурная интеграция следует функциональному разделению задач обновления ПО в SOVD (AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»): поскольку фактическая бизнес-логика обновлений ПО выполняется не внутри функционального кластера Diagnostics, прикладная реализация возлагается главным образом на соответствующее приложение. Экземпляр ara::diag::SovdSwUpdate::SovdSwUpdate сервера Diagnostic Server концентрируется на обработке нижележащего протокола SOVD в соответствии с ASAM SOVD ([SWS_DM_01796]). В этом контексте UpdatePackageDetails функционирует как стандартизированный объект передачи, с помощью которого приложение через функцию API ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails») предоставляет серверу Diagnostic Server подробные данные пакета, чтобы тот мог обслуживать внешних клиентов SOVD.

Контекстная диаграмма: размещение UpdatePackageDetails во взаимодействии между SOVD-клиентом, Diagnostic Server и приложением. Источники: [SWS_DM_01796], [SWS_DM_01877], [SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API».

Жизненный цикл

Как пассивная структура данных (struct) [SWS_DM_01877], UpdatePackageDetails не имеет собственного конечного автомата и не управляет автономными фазами жизненного цикла. Создание происходит путем инстанцирования приложением в момент конкретного запроса, после чего открытые переменные-члены заполняются статическими и динамическими атрибутами пакета:

  • Идентификация и наименование: поле id ([SWS_DM_01878]) сохраняет уникальный ID пакета. Обозначение name ([SWS_DM_01879]) указывает имя пакета, тогда как translation_id ([SWS_DM_01881]) предоставляет ключ для локализованных представлений.
  • Сведения о размере и выполнении: размер пакета в байтах определяется через size ([SWS_DM_01893]) как std::uint64_t. Дополнительными управляющими параметрами являются расчетная продолжительность выполнения duration в секундах ([SWS_DM_01891], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 «duration») как ara::core::Optional<std::uint64_t>, а также признак automated ([SWS_DM_01882], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 «automated») как ara::core::Optional<bool>.
  • Предусловия и действия пользователя: условия для выполнения передаются в preconditions ([SWS_DM_01888]) наряду с preconditions_translation_id ([SWS_DM_01889]), а также execution_conditions ([SWS_DM_01890]). Необходимые действия оператора приложение сохраняет в user_activity ([SWS_DM_01886]) и user_activity_translation_id ([SWS_DM_01887]). Дополнительные указания могут передаваться через notes ([SWS_DM_01884]) и notes_translation_id ([SWS_DM_01885]).
  • Связи компонентов и происхождение: компоненты, затрагиваемые пакетом, перечислены в векторе affected_components ([SWS_DM_01895], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 «affected_components»), в то время как updated_components ([SWS_DM_01894]) указывает явно обновляемые компоненты. Происхождение пакета обновления передается через origin ([SWS_DM_01883]).

Что касается отношений владения, экземпляр создается приложением и передается вызывающей стороне через возвращаемое значение. Уничтожение экземпляра происходит автоматически после выхода из области видимости в соответствии со стандартной семантикой C++ (RAII). Структура не обеспечивает внутренней синхронизации потоков; при параллельных операциях чтения или записи через границы потоков защита экземпляра возлагается на вызывающий программный компонент.

Путь использования

Штатное использование UpdatePackageDetails происходит в рамках стандартизированных методов SOVD для запроса сведений об обновлении программного обеспечения ([SWS_DM_01796]). Зачастую клиент предварительно запрашивает список всех доступных обновлений ([SWS_DM_01797]), прежде чем целенаправленно запросить сведения о пакете.

Последовательность вызовов выглядит следующим образом:

  1. Запрос от SOVD-клиента: внешний диагностический клиент отправляет запрос сведений об определенном пакете программного обеспечения в Diagnostic Server Instance ([SWS_DM_01796]).
  2. Перенаправление в приложение: Diagnostic Server делегирует определение сведений через ara::diag::SovdSwUpdate::GetUpdatePackageDetails зарегистрированному приложению ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»).
  3. Формирование данных: приложение определяет метаданные пакета, создает экземпляр UpdatePackageDetails ([SWS_DM_01877]) и заполняет идентификационные данные, такие как id ([SWS_DM_01878]) и size ([SWS_DM_01893]), а также зависимости, такие как affected_components ([SWS_DM_01895]).
  4. Возврат: Интерпретация: приложение, по всей видимости, возвращает заполненный объект UpdatePackageDetails напрямую в качестве результата функции GetUpdatePackageDetails серверу Diagnostic Server.
  5. Ответ протокола: Интерпретация: Diagnostic Server, вероятно, берет на себя сериализацию атрибутов C++ в стандартизированный формат ответа SOVD и отправляет его запросившему клиенту ([SWS_DM_01796]).

Диаграмма последовательности: поток вызовов и данных при запросе UpdatePackageDetails через GetUpdatePackageDetails. Источники: [SWS_DM_01796], [SWS_DM_01877], [SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API», AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails».
