Контекст

Шаблонный класс ara::rds::IEEE1722RawDataStreamProducer в модуле rds (Raw Data Stream) платформы AUTOSAR Adaptive Platform предоставляет интерфейс для отправки типизированных пакетов данных согласно стандарту IEEE 1722. Его основная ответственность заключается в том, чтобы выступать в качестве производителя данных (Producer) и предоставлять датаграммы прикладного типа через сконфигурированный поток данных. Адресация и сопоставление конечных точек связи осуществляются через ara::core::InstanceSpecifier, передаваемый при инстанцировании [SWS_RDS_90323].

В качестве партнеров по взаимодействию обычно выступают программный компонент на стороне приложения, генерирующий полезные данные в виде датаграмм, а также нижележащая инфраструктура связи среды выполнения Adaptive. Через эту инфраструктуру функционирует физический или логический поток данных IEEE 1722. При этом Producer служит связующим звеном, которое инкапсулирует данные приложения и передает их в поток.

Жизненный цикл

Создание экземпляров класса ara::rds::IEEE1722RawDataStreamProducer происходит контролируемым образом через паттерн «фабрика» с помощью статического метода Create [SWS_RDS_90323]. Поскольку прямые конструкторы являются закрытыми или ограниченными, гарантируется, что создание пройдет успешно только при наличии корректной конфигурации экземпляра службы. В отношении прав владения вызывающая сторона владеет экземпляром монопольно: конструктор копирования [SWS_RDS_90327] и оператор присваивания копированием [SWS_RDS_90328] удалены (delete), что исключает дублирование потока и его состояний.

Напротив, класс поддерживает семантику перемещения: как конструктор перемещения [SWS_RDS_90324], так и оператор присваивания перемещением [SWS_RDS_90326] определены как noexcept. Они позволяют передавать владение, например, в контейнеры или при асинхронных сменах контекста. Однако обе операции перемещения явно специфицированы как непотокобезопасные ([SWS_RDS_90324], [SWS_RDS_90326]), поэтому одновременный доступ из нескольких потоков должен предотвращаться с помощью внешней синхронизации.

Жизненный цикл завершается уничтожением объекта деструктором ~IEEE1722RawDataStreamProducer [SWS_RDS_90329]. Он также помечен как непотокобезопасный. В соответствии с концепцией RAII деструктор гарантирует, что соединение с потоком, остающееся открытым на момент уничтожения, будет автоматически и корректно закрыто [SWS_RDS_90329].

Путь использования

Штатный рабочий процесс с IEEE1722RawDataStreamProducer следует фиксированной последовательности фаз: инициализация, установление соединения, циклическая отправка и разрыв соединения.

  1. Создание: приложение инициирует инстанцирование через Create(instance) с подходящим идентификатором экземпляра [SWS_RDS_90323]. После успешного возврата приложение удерживает готовый к работе экземпляр Producer.
  2. Установление соединения: перед непосредственным обменом данными соединение с каналом IEEE 1722 устанавливается с помощью явного вызова Connect() [SWS_RDS_90330].
  3. Передача данных: как только соединение становится активным, приложение передает структурированные полезные данные через метод WriteData(std::vector<T>) [SWS_RDS_90332]. Этот вызов обычно выполняется периодически в рамках циклической логики приложения или по событиям при поступлении новых данных измерений или потоковых данных.
  4. Разрыв соединения: по завершении передачи данных соединение контролируемо завершается через Shutdown() [SWS_RDS_90331]. Явный вызов Shutdown перед уничтожением, вероятно, является необязательным, поскольку деструктор автоматически закрывает открытые каналы [SWS_RDS_90329], однако рекомендуется для целенаправленного контроля ошибок и состояния.

Диаграмма последовательности: типичный процесс создания, установления соединения, повторной отправки и закрытия Producer. Источники: [SWS_RDS_90323], [SWS_RDS_90330], [SWS_RDS_90332], [SWS_RDS_90331], [SWS_RDS_90329].

Сценарии ошибок

В соответствии с моделью обработки ошибок AUTOSAR Adaptive Platform интерфейс полностью отказывается от исключений C++. Все методы объявлены с noexcept и сигнализируют о сбоях через обобщенный тип возвращаемого значения ara::core::Result ([SWS_RDS_90323], [SWS_RDS_90330], [SWS_RDS_90331], [SWS_RDS_90332]).

Ошибочные ситуации могут возникать на различных этапах:

  • Сбой при создании: если вызов Create завершается сбоем, например при некорректном или неизвестном в системе InstanceSpecifier, объект Result возвращает системно-специфичный код ошибки вместо экземпляра Producer [SWS_RDS_90323].
  • Ошибка подключения: если Connect() [SWS_RDS_90330] завершается неудачно (например, из-за нехватки сетевых ресурсов или недоступности интерфейсов), Producer не должен использоваться для отправки. Перед вызовом WriteData, по всей видимости, обязательно требуется успешное подключение через Connect.
  • Ошибка передачи: если во время WriteData происходит переполнение буфера или сбой на сетевом уровне, ara::core::Result<void> возвращает соответствующий объект ошибки [SWS_RDS_90332], который должен быть обработан приложением.
  • Ошибка при завершении работы: вызов Shutdown() [SWS_RDS_90331] также возвращает ara::core::Result<void>, чтобы сообщить о возможных ошибках при корректном разрыве соединения.

Следовательно, вызывающий компонент обязан на каждом шаге проверять результат ara::core::Result с помощью таких методов, как HasValue(), прежде чем продолжить.

Настоящее руководство основано исключительно на требованиях спецификации AUTOSAR Adaptive R25-11 для модуля rds.

<h4>Контекст</h4>
<p>Шаблонный класс <code>ara::rds::IEEE1722RawDataStreamProducer</code> в модуле <code>rds</code> (Raw Data Stream) платформы AUTOSAR Adaptive Platform предоставляет интерфейс для отправки типизированных пакетов данных согласно стандарту IEEE 1722. Его основная ответственность заключается в том, чтобы выступать в качестве производителя данных (Producer) и предоставлять датаграммы прикладного типа через сконфигурированный поток данных. Адресация и сопоставление конечных точек связи осуществляются через <code>ara::core::InstanceSpecifier</code>, передаваемый при инстанцировании <a class="spec-record-ref" data-req="SWS_RDS_90323" href="../spec/record.html?id=SWS_RDS_90323">[SWS_RDS_90323]</a>.</p>
<p>В качестве партнеров по взаимодействию обычно выступают программный компонент на стороне приложения, генерирующий полезные данные в виде датаграмм, а также нижележащая инфраструктура связи среды выполнения Adaptive. Через эту инфраструктуру функционирует физический или логический поток данных IEEE 1722. При этом Producer служит связующим звеном, которое инкапсулирует данные приложения и передает их в поток.</p>

<h4>Жизненный цикл</h4>
<p>Создание экземпляров класса <code>ara::rds::IEEE1722RawDataStreamProducer</code> происходит контролируемым образом через паттерн «фабрика» с помощью статического метода <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_90323" href="../spec/record.html?id=SWS_RDS_90323">[SWS_RDS_90323]</a>. Поскольку прямые конструкторы являются закрытыми или ограниченными, гарантируется, что создание пройдет успешно только при наличии корректной конфигурации экземпляра службы. В отношении прав владения вызывающая сторона владеет экземпляром монопольно: конструктор копирования <a class="spec-record-ref" data-req="SWS_RDS_90327" href="../spec/record.html?id=SWS_RDS_90327">[SWS_RDS_90327]</a> и оператор присваивания копированием <a class="spec-record-ref" data-req="SWS_RDS_90328" href="../spec/record.html?id=SWS_RDS_90328">[SWS_RDS_90328]</a> удалены (<code>delete</code>), что исключает дублирование потока и его состояний.</p>
<p>Напротив, класс поддерживает семантику перемещения: как конструктор перемещения <a class="spec-record-ref" data-req="SWS_RDS_90324" href="../spec/record.html?id=SWS_RDS_90324">[SWS_RDS_90324]</a>, так и оператор присваивания перемещением <a class="spec-record-ref" data-req="SWS_RDS_90326" href="../spec/record.html?id=SWS_RDS_90326">[SWS_RDS_90326]</a> определены как <code>noexcept</code>. Они позволяют передавать владение, например, в контейнеры или при асинхронных сменах контекста. Однако обе операции перемещения явно специфицированы как непотокобезопасные (<a class="spec-record-ref" data-req="SWS_RDS_90324" href="../spec/record.html?id=SWS_RDS_90324">[SWS_RDS_90324]</a>, <a class="spec-record-ref" data-req="SWS_RDS_90326" href="../spec/record.html?id=SWS_RDS_90326">[SWS_RDS_90326]</a>), поэтому одновременный доступ из нескольких потоков должен предотвращаться с помощью внешней синхронизации.</p>
<p>Жизненный цикл завершается уничтожением объекта деструктором <code>~IEEE1722RawDataStreamProducer</code> <a class="spec-record-ref" data-req="SWS_RDS_90329" href="../spec/record.html?id=SWS_RDS_90329">[SWS_RDS_90329]</a>. Он также помечен как непотокобезопасный. В соответствии с концепцией RAII деструктор гарантирует, что соединение с потоком, остающееся открытым на момент уничтожения, будет автоматически и корректно закрыто <a class="spec-record-ref" data-req="SWS_RDS_90329" href="../spec/record.html?id=SWS_RDS_90329">[SWS_RDS_90329]</a>.</p>

<h4>Путь использования</h4>
<p>Штатный рабочий процесс с <code>IEEE1722RawDataStreamProducer</code> следует фиксированной последовательности фаз: инициализация, установление соединения, циклическая отправка и разрыв соединения.</p>
<ol>
<li><strong>Создание:</strong> приложение инициирует инстанцирование через <code>Create(instance)</code> с подходящим идентификатором экземпляра <a class="spec-record-ref" data-req="SWS_RDS_90323" href="../spec/record.html?id=SWS_RDS_90323">[SWS_RDS_90323]</a>. После успешного возврата приложение удерживает готовый к работе экземпляр Producer.</li>
<li><strong>Установление соединения:</strong> перед непосредственным обменом данными соединение с каналом IEEE 1722 устанавливается с помощью явного вызова <code>Connect()</code> <a class="spec-record-ref" data-req="SWS_RDS_90330" href="../spec/record.html?id=SWS_RDS_90330">[SWS_RDS_90330]</a>.</li>
<li><strong>Передача данных:</strong> как только соединение становится активным, приложение передает структурированные полезные данные через метод <code>WriteData(std::vector&lt;T&gt;)</code> <a class="spec-record-ref" data-req="SWS_RDS_90332" href="../spec/record.html?id=SWS_RDS_90332">[SWS_RDS_90332]</a>. Этот вызов обычно выполняется периодически в рамках циклической логики приложения или по событиям при поступлении новых данных измерений или потоковых данных.</li>
<li><strong>Разрыв соединения:</strong> по завершении передачи данных соединение контролируемо завершается через <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_90331" href="../spec/record.html?id=SWS_RDS_90331">[SWS_RDS_90331]</a>. Явный вызов <code>Shutdown</code> перед уничтожением, вероятно, является необязательным, поскольку деструктор автоматически закрывает открытые каналы <a class="spec-record-ref" data-req="SWS_RDS_90329" href="../spec/record.html?id=SWS_RDS_90329">[SWS_RDS_90329]</a>, однако рекомендуется для целенаправленного контроля ошибок и состояния.</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>В соответствии с моделью обработки ошибок AUTOSAR Adaptive Platform интерфейс полностью отказывается от исключений C++. Все методы объявлены с <code>noexcept</code> и сигнализируют о сбоях через обобщенный тип возвращаемого значения <code>ara::core::Result</code> (<a class="spec-record-ref" data-req="SWS_RDS_90323" href="../spec/record.html?id=SWS_RDS_90323">[SWS_RDS_90323]</a>, <a class="spec-record-ref" data-req="SWS_RDS_90330" href="../spec/record.html?id=SWS_RDS_90330">[SWS_RDS_90330]</a>, <a class="spec-record-ref" data-req="SWS_RDS_90331" href="../spec/record.html?id=SWS_RDS_90331">[SWS_RDS_90331]</a>, <a class="spec-record-ref" data-req="SWS_RDS_90332" href="../spec/record.html?id=SWS_RDS_90332">[SWS_RDS_90332]</a>).</p>
<p>Ошибочные ситуации могут возникать на различных этапах:</p>
<ul>
<li><strong>Сбой при создании:</strong> если вызов <code>Create</code> завершается сбоем, например при некорректном или неизвестном в системе <code>InstanceSpecifier</code>, объект Result возвращает системно-специфичный код ошибки вместо экземпляра Producer <a class="spec-record-ref" data-req="SWS_RDS_90323" href="../spec/record.html?id=SWS_RDS_90323">[SWS_RDS_90323]</a>.</li>
<li><strong>Ошибка подключения:</strong> если <code>Connect()</code> <a class="spec-record-ref" data-req="SWS_RDS_90330" href="../spec/record.html?id=SWS_RDS_90330">[SWS_RDS_90330]</a> завершается неудачно (например, из-за нехватки сетевых ресурсов или недоступности интерфейсов), Producer не должен использоваться для отправки. Перед вызовом <code>WriteData</code>, по всей видимости, обязательно требуется успешное подключение через <code>Connect</code>.</li>
<li><strong>Ошибка передачи:</strong> если во время <code>WriteData</code> происходит переполнение буфера или сбой на сетевом уровне, <code>ara::core::Result&lt;void&gt;</code> возвращает соответствующий объект ошибки <a class="spec-record-ref" data-req="SWS_RDS_90332" href="../spec/record.html?id=SWS_RDS_90332">[SWS_RDS_90332]</a>, который должен быть обработан приложением.</li>
<li><strong>Ошибка при завершении работы:</strong> вызов <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_90331" href="../spec/record.html?id=SWS_RDS_90331">[SWS_RDS_90331]</a> также возвращает <code>ara::core::Result&lt;void&gt;</code>, чтобы сообщить о возможных ошибках при корректном разрыве соединения.</li>
</ul>
<p>Следовательно, вызывающий компонент обязан на каждом шаге проверять результат <code>ara::core::Result</code> с помощью таких методов, как <code>HasValue()</code>, прежде чем продолжить.</p>
