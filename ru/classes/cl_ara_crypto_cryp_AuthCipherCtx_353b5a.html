Предоставляет интерфейс для аутентифицированного симметричного шифрования и расшифрования с защитой целостности.

Интерфейс ara::crypto::cryp::AuthCipherCtx служит для аутентифицированного шифрования и расшифрования данных с сохранением конфиденциальности и целостности [SWS_CRYPT_23911]. После настройки ключа обработка осуществляется либо как атомарный одиночный вызов, либо как потоковая последовательность из инициализации, опциональных данных аутентификации, обновлений полезных данных и финализации. В качестве критического условия безопасности расшифрование завершается сбоем при недействительном теге аутентификации, поэтому расшифрованные полезные данные разрешается обрабатывать только после успешной валидации [SWS_CRYPT_50075].

Контекст

Интерфейс ara::crypto::cryp::AuthCipherCtx определяет стандартизированный программный интерфейс для операций аутентифицированного шифрования (Authenticated Encryption with Associated Data, AEAD) в рамках AUTOSAR Adaptive Platform. Он сочетает конфиденциальность с защитой целостности, генерируя или валидируя криптографический тег аутентификации наряду с фактическим шифрованием или расшифрованием полезных данных. В качестве центральных партнеров по взаимодействию выступают вызывающие приложения, а также ключевые объекты: перед использованием контекст либо привязывается к конкретному экземпляру SymmetricKey [SWS_CRYPT_23911], либо конфигурируется с персистентным или предоставленным KeySlot [SWS_CRYPT_50072]. Помимо пошаговой потоковой обработки, класс также поддерживает автономные одиночные вызовы для обработки полных сообщений за один шаг [SWS_CRYPT_50078].

Жизненный цикл

Контексты управляются в области приложения через общий тип указателя ara::crypto::cryp::AuthCipherCtx::Sptr [SWS_CRYPT_20101]. (Интерпретация: создание объекта обычно осуществляется через вышестоящую фабрику провайдера, поскольку AuthCipherCtx специфицирован как чистый интерфейс). Вопрос Q-23125789874cf2f3 (открытый) Все функции-члены объявлены как безопасные к исключениям (exception safe) и потокобезопасные (thread-safe) [SWS_CRYPT_23911], [SWS_CRYPT_24715]. Функциональный жизненный цикл проходит через чётко определённые состояния:

  • Неинициализирован: непосредственно после создания экземпляра. Вызовы для обработки данных отклоняются, так как ключ ещё не был назначен [SWS_CRYPT_50081].
  • Ключ сконфигурирован: при успешном вызове SetKey с SymmetricKey [SWS_CRYPT_23911] или KeySlot [SWS_CRYPT_50072] контекст переходит в состояние готовности к работе. Из этого состояния можно напрямую выполнять одиночные (single-shot) операции.
  • Потоковая передача активна: осуществляется переход вызовом Start с указанием направления преобразования с вектором инициализации (IV) [SWS_CRYPT_24715] или без явного IV [SWS_CRYPT_50073].
  • Завершение / сброс: текущая потоковая операция завершается штатно с помощью Finish [SWS_CRYPT_50075] или FinishEncrypt [SWS_CRYPT_50076] либо прерывается досрочно через Cancel [SWS_CRYPT_50077]. После этого контекст снова готов к новым последовательностям обработки.

Диаграмма состояний: фазы состояний контекста от привязки ключа через потоковую обработку до завершения. Источники: [SWS_CRYPT_23911], [SWS_CRYPT_50072], [SWS_CRYPT_24715], [SWS_CRYPT_50075], [SWS_CRYPT_50077].

Путь использования

Для непрерывной потоковой обработки данных интерфейс требует упорядоченной последовательности вызовов:

  1. Конфигурация: назначение ключа через SetKey [SWS_CRYPT_23911] или SetKey с KeySlot [SWS_CRYPT_50072].
  2. Запрос параметров: опциональное определение предельных значений и размеров буферов с помощью GetMinimumChunkSize [SWS_CRYPT_50162], GetMaximumChunkSize [SWS_CRYPT_50082], GetMinimumInputIvSize [SWS_CRYPT_50163], GetMaximumInputIvSize [SWS_CRYPT_50164], GetTagSize [SWS_CRYPT_50161], а также GetRequiredOutputBufferSize [SWS_CRYPT_50081].
  3. Запуск операции: вызов Start с определением направления (шифрование или расшифрование), а также предоставлением IV [SWS_CRYPT_24715] или запросом собственного IV контекста [SWS_CRYPT_50073].
  4. Ассоциированные данные (AAD): если в расчет целостности необходимо включить дополнительные открытые данные, они передаются через UpdateAuthenticatedData [SWS_CRYPT_20313]. Максимально допустимый размер AAD можно запросить с помощью GetMaxAssociatedDataSize [SWS_CRYPT_20103]. Важно: блоки AAD обязательно должны передаваться до фактических полезных данных.
  5. Обработка полезных данных: пошаговая передача блоков данных через UpdateConfidentialData [SWS_CRYPT_50074]. При расшифровании открытый текст возвращается до подтверждения его подлинности; приложение может использовать эти данные только после успешной финализации.
  6. Финализация: завершение операции с помощью Finish [SWS_CRYPT_50075] или FinishEncrypt [SWS_CRYPT_50076], в результате чего обрабатывается финальный блок и вычисляется либо проверяется тег аутентификации.

Для компактных полезных нагрузок существуют альтернативы в виде одиночного вызова: ProcessSingleCall обрабатывает данные без передачи IV [SWS_CRYPT_50078], ProcessSingleCallWithInputIv принимает внешний IV [SWS_CRYPT_50079], а EncryptSingleCallWithOutputIv возвращает сгенерированный контекстом IV вызывающей стороне [SWS_CRYPT_50080].

Диаграмма последовательности: последовательность вызовов потокового аутентифицированного шифрования. Источники: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Сценарии ошибок

Методы AuthCipherCtx возвращают результаты через ara::core::Result и в случае ошибки обладают семантикой отката. Соответствующими кодами ошибок из ara::crypto::CryptoErrc являются:

  • kUninitializedContext: возникает при вызове Start [SWS_CRYPT_24715], ProcessSingleCall [SWS_CRYPT_50078] или вычислений буфера [SWS_CRYPT_50081], если ключ еще не был сконфигурирован через SetKey.
  • kProcessingNotStarted: возвращается, если UpdateAuthenticatedData [SWS_CRYPT_20313], UpdateConfidentialData [SWS_CRYPT_50074], Finish [SWS_CRYPT_50075] или Cancel [SWS_CRYPT_50077] вызываются без предшествующего Start.
  • kInvalidUsageOrder: сигнализирует о неверной последовательности вызовов, если UpdateAuthenticatedData вызывается после того, как полезные данные уже были обработаны через UpdateConfidentialData [SWS_CRYPT_20313].
  • kAuthTagNotValid: указывает при расшифровании в Finish [SWS_CRYPT_50075] или в методах одиночного вызова [SWS_CRYPT_50078] на то, что вычисленный тег не совпадает с переданным тегом и проверка подлинности не удалась.
  • kUsageViolation: возникает, если атрибуты использования ключа не соответствуют запрошенной операции (например, отсутствует kAllowDataEncrypt или kAllowDataDecrypt) [SWS_CRYPT_23911], [SWS_CRYPT_50078].
  • kInsufficientCapacity / kInvalidInputSize: указывают на недостаточный размер выходных буферов или недопустимую длину входных данных, IV либо тега [SWS_CRYPT_24715], [SWS_CRYPT_50074], [SWS_CRYPT_50075].
  • kEmptyKeySlot / kBusyResource: относятся к ошибочным состояниям при использовании сконфигурированных слотов ключей [SWS_CRYPT_24715], [SWS_CRYPT_50078].

Использование

Метод Cancel() интерфейса ara::crypto::cryp::AuthCipherCtx прерывает активную потоковую операцию, которая ранее была начата через Start() и ещё не завершена [SWS_CRYPT_50077]. Функция предоставляется через заголовочный файл ara/crypto/cryp/auth_cipher_ctx.h и работает синхронно без входных параметров [SWS_CRYPT_50077]. Она возвращает ara::core::Result<void>, который в случае успеха пуст.

Обработка ошибок и граничные условия

Прерывание предполагает, что обработка данных действительно ранее была начата с помощью Start(). Если потоковая операция не была запущена, вызов завершается сбоем и возвращает код ошибки ara::crypto::CryptoErrc::kProcessingNotStarted с семантикой отката [SWS_CRYPT_50077].

Параллелизм

Операция объявлена как noexcept и согласно спецификации классифицирована как thread-safe, так и exception safe [SWS_CRYPT_50077].

Взаимодействие

                                                                      Использование
                                                                      

                                                                      
Чисто виртуальный метод Start класса ara::crypto::cryp::AuthCipherCtx синхронно инициализирует контекст для предстоящего шифрования или дешифрования [SWS_CRYPT_50073]. Через параметр transformDirection указывается, подготавливается ли контекст для шифрования или дешифрования. Эту перегрузку без вектора инициализации (IV) разрешается использовать только в том случае, если криптографический контекст в выбранном направлении преобразования не требует IV или определяет его самостоятельно [SWS_CRYPT_50073]. Возвращаемым значением является пустой ara::core::Result<void> в случае успеха или соответствующий код ошибки.

                                                                      


                                                                      Обработка ошибок и предварительные условия
                                                                      

                                                                      
Перед вызовом контекст должен быть успешно сконфигурирован с ключом через SetKey; в противном случае функция завершается неудачно с ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_50073]. Кроме того, в случае ошибки возникают следующие возвращаемые значения:

                                                                      

                                                                        

                                                                      • ara::crypto::CryptoErrc::kUnsupported, если потоковая обработка не поддерживается контекстом или если контекст в выбранном направлении преобразования строго требует явного указания IV [SWS_CRYPT_50073].
                                                                        • 

                                                                      • ara::crypto::CryptoErrc::kUsageViolation, если разрешенное использование ключа в сконфигурированном KeySlot на момент вызова не включает необходимое право доступа kAllowDataEncrypt для шифрования или kAllowDataDecrypt для дешифрования [SWS_CRYPT_50073].
                                                                        • 

                                                                      • EmptyKeySlot или ara::crypto::CryptoErrc::kBusyResource, если сконфигурированный KeySlot в настоящее время пуст или заблокирован [SWS_CRYPT_50073].
                                                                        • 

                                                                      • ara::crypto::CryptoErrc::kIncompatibleObject, если сконфигурированный KeySlot не содержит SymmetricKey или этот тип ключа не поддерживается контекстом [SWS_CRYPT_50073].
                                                                        • 

                                                                      

                                                                      
При возникновении ошибки действует специфицированная семантика отката (rollback_semantics) [SWS_CRYPT_50073].
