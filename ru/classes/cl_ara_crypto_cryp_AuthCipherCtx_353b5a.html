Контекст

Интерфейс ara::crypto::cryp::AuthCipherCtx определяет контекст для криптографических операций с аутентифицированным шифрованием (Authenticated Encryption with Associated Data, AEAD). Он сочетает конфиденциальность полезных данных с проверкой целостности и подлинности посредством криптографического тега аутентификации (Authentication Tag), а также опциональных ассоциированных дополнительных данных (Additional Authenticated Data, AAD). Экземпляры обычно управляются через псевдоним смарт-указателя AuthCipherCtx::Sptr [SWS_CRYPT_20101].

В качестве участников взаимодействия выступают, с одной стороны, использующее приложение, которое шифрует и расшифровывает потоки данных или отдельные блоки, а с другой стороны — служба управления ключами: контекст оперирует либо непосредственно с экземпляром ключа типа SymmetricKey [SWS_CRYPT_23911], либо ссылается на персистентное или управляемое хранилище через KeySlot [SWS_CRYPT_50072]. Функционально интерфейс поддерживает как пошаговый потоковый режим, так и атомарные одиночные вызовы (Single-Call).

Жизненный цикл

Контекст проходит четко определенные фазы от создания до повторного использования:

  • Не инициализирован (Uninitialized): после инстанцирования контекст еще не готов к использованию. Перед обработкой данных обязательно должен быть назначен ключ. В противном случае вызовы трансформации или инициализации отклоняются с ошибкой CryptoErrc::kUninitializedContext [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Сконфигурирован (Configured / Key Set): назначение ключа выполняется через SetKey() с помощью SymmetricKey [SWS_CRYPT_23911] или KeySlot [SWS_CRYPT_50072]. В этом состоянии можно запрашивать статические параметры, такие как размеры тега и вектора инициализации (IV). Для операций одиночного вызова этого состояния уже достаточно.
  • Потоковая обработка активна (Processing): при вызове Start() — по выбору с явным вектором инициализации (IV) [SWS_CRYPT_24715] либо без него / с собственным IV контекста [SWS_CRYPT_50073] — контекст переходит в активную фазу потоковой обработки для определенного направления трансформации (CryptoTransform). Здесь можно последовательно обрабатывать дополнительные данные и полезные данные.
  • Завершение и возврат: обработка штатно финализируется с помощью Finish() [SWS_CRYPT_50075] или FinishEncrypt() [SWS_CRYPT_50076]. Досрочное прерывание текущего потока возможно в любой момент через Cancel() [SWS_CRYPT_50077]. После завершения или прерывания контекст, предположительно, остается в сконфигурированном состоянии и готов к повторной инициализации через Start().

Диаграмма состояний: жизненный цикл и переходы между фазами AuthCipherCtx. Источники: [SWS_CRYPT_23911], [SWS_CRYPT_50072], [SWS_CRYPT_24715], [SWS_CRYPT_50073], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50077].

Путь использования

Для обработки доступны два пути: потоковая обработка для больших или фрагментированных данных и атомарные операции Single-Call.

Типичная последовательность потоковой обработки выглядит следующим образом:

  1. Конфигурация: привязать ключ через SetKey() [SWS_CRYPT_23911]. Предварительно можно определить предельные значения, например минимальный/максимальный размер фрагмента [SWS_CRYPT_50162], [SWS_CRYPT_50082], размер тега [SWS_CRYPT_50161], а также длины IV [SWS_CRYPT_50163], [SWS_CRYPT_50164], [SWS_CRYPT_50165].
  2. Запуск: инициализация операции через Start() с указанием направления трансформации (шифрование или расшифрование) и при необходимости IV [SWS_CRYPT_24715], [SWS_CRYPT_50073].
  3. Ассоциированные данные (опционально): если требуется аутентифицировать дополнительные открытые метаданные, их необходимо передать через UpdateAuthenticatedData() [SWS_CRYPT_20313]. Это обязательно должно быть выполнено до любых конфиденциальных полезных данных. Максимальный размер можно проверить через GetMaxAssociatedDataSize() [SWS_CRYPT_20103].
  4. Конфиденциальные полезные данные: пошаговая передача фрагментов данных с помощью UpdateConfidentialData() [SWS_CRYPT_50074]. Необходимый размер выходного буфера можно динамически рассчитать через GetRequiredOutputBufferSize() [SWS_CRYPT_50081].
  5. Завершение: вызов Finish() [SWS_CRYPT_50075] или FinishEncrypt() [SWS_CRYPT_50076]. При этом трансформируются остаточные данные, финализируется тег аутентификации (генерируется при шифровании, проверяется при расшифровании) и при необходимости возвращается сгенерированный IV.

Для компактных данных, доступных за один шаг, функции ProcessSingleCall() [SWS_CRYPT_50078], ProcessSingleCallWithInputIv() [SWS_CRYPT_50079] и EncryptSingleCallWithOutputIv() [SWS_CRYPT_50080] обеспечивают обработку без сохранения состояния без предварительного вызова Start().

Диаграмма последовательности: пошаговый процесс потоковой обработки для аутентифицированной трансформации с AuthCipherCtx. Источники: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Сценарии ошибок

Методы обеспечивают корректную последовательность протокола и криптографическую безопасность с помощью специальных кодов ошибок:

  • Нарушение порядка для дополнительных данных: если UpdateAuthenticatedData() вызывается после того, как конфиденциальные данные уже были обработаны через UpdateConfidentialData(), операция завершается с ошибкой CryptoErrc::kInvalidUsageOrder [SWS_CRYPT_20313].
  • Обработка без запуска: если UpdateAuthenticatedData(), UpdateConfidentialData(), Finish(), FinishEncrypt() или Cancel() вызываются без предварительного успешного вызова Start(), возвращается ошибка CryptoErrc::kProcessingNotStarted [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50076], [SWS_CRYPT_50077].
  • Проверки ключей и прав: если назначенный тип ключа не соответствует контексту, SetKey() или Start() возвращает ошибку CryptoErrc::kIncompatibleObject [SWS_CRYPT_23911], [SWS_CRYPT_24715]. Если у ключа отсутствуют требуемые флаги использования (kAllowDataEncrypt или kAllowDataDecrypt), это приводит к CryptoErrc::kUsageViolation [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_50078]. Для занятых или пустых слотов сообщается CryptoErrc::kBusyResource или CryptoErrc::kEmptyKeySlot соответственно [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Ошибки буфера и размерности: если предоставленный выходной буфер слишком мал для преобразованных данных или IV, методы завершаются с ошибкой CryptoErrc::kInsufficientCapacity [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50078]. Недопустимая длина входных буферов, тегов или IV приводит к CryptoErrc::kInvalidInputSize [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_24715].
  • Сбой аутентификации: если при расшифровании проверка тега аутентификации завершается неудачно, Finish() [SWS_CRYPT_50075] или ProcessSingleCall() [SWS_CRYPT_50078] сигнализируют об ошибке CryptoErrc::kAuthTagNotValid. Важное указание по безопасности: при потоковой обработке UpdateConfidentialData() выдает расшифрованный открытый текст еще до проверки тега; приложение может продолжить использование или передачу этих данных только после успешного выполнения Finish() [SWS_CRYPT_50074].
