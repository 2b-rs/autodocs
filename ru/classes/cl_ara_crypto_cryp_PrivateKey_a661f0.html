Инкапсулирует асимметричные закрытые ключи и предоставляет соответствующий открытый ключ.

Интерфейс ara::crypto::cryp::PrivateKey определяет общий интерфейс для асимметричных закрытых ключей в AUTOSAR Adaptive и управляется преимущественно через псевдоним разделяемого указателя PrivateKey::Sptr [SWS_CRYPT_22501]. Его центральная функция GetPublicKey() позволяет получать соответствующий открытый ключ как PublicKey::Sptr для предоставления его партнерским криптографическим операциям [SWS_CRYPT_22511]. Данное получение специфицировано как потокобезопасное и безопасное относительно исключений без стандартизированных кодов ошибок, при этом возможные ошибки, вероятно, сигнализируются специфичным для реализации образом через тип возвращаемого значения ara::core::Result (интерпретация).

Контекст

Интерфейс ara::crypto::cryp::PrivateKey функционирует в AUTOSAR Adaptive Platform как обобщенный интерфейс для асимметричных закрытых ключей внутри модуля crypto. Он объявлен в заголовочном файле ara/crypto/cryp/cryobj/private_key.h и наследуется напрямую от базового интерфейса CryptoObject. Будучи ключевым компонентом системы асимметричной криптографии, PrivateKey инкапсулирует конфиденциальный ключевой материал, необходимый для криптографических операций, таких как формирование электронных цифровых подписей или процедуры асимметричного расшифрования.

К основным партнерам по взаимодействию, помимо базового класса CryptoObject, относятся, в частности, соответствующий интерфейс открытого ключа PublicKey, а также потребляющие криптографические сервисы и прикладные подпрограммы. В то время как закрытый ключ должен всегда храниться в секрете, интерфейс через функцию-член GetPublicKey() обеспечивает прямое предоставление соответствующего открытого ключа [SWS_CRYPT_22511]. Таким образом реализуется фиксированная типовая связь между закрытым ключом и его математическим аналогом.

Контекстная диаграмма: встраивание PrivateKey в криптографическую объектную модель и отношение к соответствующему PublicKey. Источники: [SWS_CRYPT_22501], [SWS_CRYPT_22511]

Жизненный цикл

Управление и передача экземпляров интерфейса PrivateKey осуществляются через типизированный умный указатель PrivateKey::Sptr, который определен как псевдоним типа для std::shared_ptr<PrivateKey> [SWS_CRYPT_22501]. Этот разделяемый указатель гарантирует совместное владение и автоматическое управление ресурсами посредством подсчета ссылок, так что защищенный ключевой материал освобождается, как только аннулируется последняя ссылка.

Поскольку PrivateKey представляет собой абстрактный интерфейс с чисто виртуальными методами, такими как GetPublicKey() [SWS_CRYPT_22511], приложения не могут напрямую создавать экземпляры этого класса. Создание и предоставление конкретных экземпляров PrivateKey::Sptr, вероятно, осуществляется через специализированные фабрики, компоненты управления ключами или криптопровайдеры системы Adaptive (интерпретация). Сам интерфейс не определяет дискретных внутренних состояний или переходов между состояниями.

Что касается параллелизма, интерфейс для центральной функции-члена GetPublicKey() явно специфицирует потокобезопасность (thread-safe) [SWS_CRYPT_22511]. Это позволяет нескольким потокам выполнения осуществлять параллельный, не требующий синхронизации доступ на чтение к одному и тому же экземпляру ключа для получения соответствующего открытого ключа.

Путь использования

Типичный сценарий использования PrivateKey включает получение закрытого ключа и последующее извлечение соответствующего открытого ключа для целей валидации, регистрации или коммуникации:

  1. Получение ключа: потребляющий программный компонент получает действительный экземпляр асимметричного закрытого ключа в форме PrivateKey::Sptr [SWS_CRYPT_22501].
  2. Запрос партнерского ключа: если для последующего рабочего процесса требуется соответствующий открытый ключ, компонент вызывает функцию-член GetPublicKey() на экземпляре [SWS_CRYPT_22511].
  3. Обработка результата: вызов возвращает ara::core::Result<PublicKey::Sptr> [SWS_CRYPT_22511]. Приложение проверяет объект результата на успешность и при успешном выполнении распаковывает указатель PublicKey::Sptr.
  4. Дальнейшее использование: полученный открытый ключ затем может быть передан внешним коммуникационным партнерам или передан локальным подпрограммам верификации. Формирование открытого ключа внутри, вероятно, осуществляется непосредственно из математических ключевых параметров закрытого ключа (интерпретация).

Сценарии ошибок

Для безошибочной интеграции решающее значение имеют характеристики ошибок и граничные условия GetPublicKey():

  • Стандартизированные ошибки: согласно спецификации, функция GetPublicKey() не определяет стандартизированных кодов ошибок [SWS_CRYPT_22511].
  • Канал ошибок: хотя стандартизированные ошибки не определены, тип возвращаемого значения ara::core::Result передает потенциальные сбои. Если при внутреннем формировании ключа или создании объекта возникает ошибка, объект результата, вероятно, будет содержать специфичные для реализации коды ошибок базовых криптографических драйверов (интерпретация).
  • Безопасность относительно исключений: функция явно классифицирована как безопасная относительно исключений (exception safe) и снабжена идентификатором noexcept [SWS_CRYPT_22511]. Поэтому вызывающим компонентам не требуется перехватывать исключения C++.
  • Предусловия и постусловия: предусловием для успешного вызова является действительный, не освобожденный экземпляр PrivateKey. В качестве постусловия интерфейс в случае успеха гарантирует возврат PublicKey::Sptr, математически точно соответствующего закрытому ключу [SWS_CRYPT_22511].

Использование

Метод GetPublicKey класса ara::crypto::cryp::PrivateKey служит для синхронного получения открытого ключа, соответствующего закрытому ключу [SWS_CRYPT_22511]. Вызов выполняется без параметров на существующем экземпляре PrivateKey. В качестве возвращаемого значения интерфейс возвращает ara::core::Result<PublicKey::Sptr>, предоставляющий при успешном выполнении shared pointer на соответствующий объект PublicKey [SWS_CRYPT_22511].

Обработка ошибок и параллелизм

Для данного метода в спецификации не определены стандартизированные коды ошибок [SWS_CRYPT_22511]. Обработка ошибок выполняется через возвращаемый объект типа ara::core::Result. Поскольку операция объявлена как noexcept, она считается исключениебезопасной (exception safe) [SWS_CRYPT_22511]. Кроме того, метод квалифицирован как const и специфицирован как потокобезопасный (thread-safe), благодаря чему допустимы параллельные операции чтения из нескольких потоков [SWS_CRYPT_22511].

Взаимодействие

В типичных криптографических сценариях GetPublicKey используется после создания асимметричной пары ключей с помощью GeneratePrivateKey [SWS_CRYPT_20722]. При этом допустимые флаги использования созданного закрытого ключа переносятся на соответствующий открытый ключ (например, разрешение на проверку подписи из операции создания подписи) [SWS_CRYPT_20722]. Следует отличать эту функцию от одноименного интерфейса в ProtectedKeyImportCtx, который служит для распаковки импортированных открытых ключей [SWS_CRYPT_50211].
