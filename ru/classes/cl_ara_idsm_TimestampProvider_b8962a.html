Позволяет приложениям предоставлять специфичные для системы временные метки для событий безопасности IdsM.

Класс ara::idsm::TimestampProvider предоставляет интерфейс, через который приложения могут передавать временные метки для модуля IdsM через смоделированный PPort [SWS_AIDSM_10400]. Активация и деактивация обратных вызовов опроса выполняется через методы Offer() и StopOffer() [SWS_AIDSM_10408] [SWS_AIDSM_10409]. Экземпляры некопируемы, поддерживают семантику перемещения и требуют внешней синхронизации для методов без гарантированной потокобезопасности.

Контекст

Класс ara::idsm::TimestampProvider служит интерфейсом для предоставления временных меток для модуля Intrusion Detection System Manager (IdsM) в рамках AUTOSAR Adaptive Platform [SWS_AIDSM_10400]. События безопасности и протоколы в IdsM требуют надежной информации о времени, которая запрашивается этим классом-провайдером от платформы или специфичного для приложения источника времени. Экземпляр TimestampProvider привязывается к PPort, смоделированному через ara::core::InstanceSpecifier [SWS_AIDSM_10401]. Поскольку метод GetTimestamp() определен как чисто виртуальная функция обратного вызова [SWS_AIDSM_10407], TimestampProvider функционирует как абстрактный базовый класс, от которого должны наследоваться конкретные реализации.

Жизненный цикл

Создание поставщика временных меток осуществляется явно через конструктор с указанием соответствующего ara::core::InstanceSpecifier [SWS_AIDSM_10401]. Этот конструктор объявлен как потокобезопасный. Операции копирования полностью запрещены: как конструктор копирования [SWS_AIDSM_10404], так и оператор присваивания с копированием [SWS_AIDSM_10406] удалены (= delete). Таким образом, экземпляры обладают уникальной идентичностью и не могут быть дублированы.

Напротив, класс поддерживает семантику перемещения: конструктор перемещения потокобезопасно передает существующие ресурсы новому объекту [SWS_AIDSM_10403]. Присваивание с перемещением через operator= также предусмотрено, однако, в отличие от конструктора, оно не является потокобезопасным [SWS_AIDSM_10405]. Жизненный цикл активного предоставления сервиса явно контролируется после создания экземпляра: с помощью метода Offer() активируется регистрация для IdsM [SWS_AIDSM_10408]. С помощью StopOffer() предоставление снова прекращается [SWS_AIDSM_10409]. Освобождение экземпляра происходит через виртуальный деструктор [SWS_AIDSM_10402], который специфицирован как непотокобезопасный. Интерпретация: перед уничтожением экземпляра, как правило, должен вызываться StopOffer(), чтобы убедиться, что незавершенные вызовы со стороны IdsM больше не выполняются. Вопрос Q-fcf21d9d93d053a6 (открытый)

Путь использования

Типичное использование требует наследования специфичного для приложения класса, который переопределяет метод GetTimestamp() и возвращает текущую временную метку как TimestampType [SWS_AIDSM_10407]. Как только экземпляр для соответствующего порта создан [SWS_AIDSM_10401], приложение сигнализирует о готовности к работе вызовом Offer() [SWS_AIDSM_10408]. С этого момента IdsM может автономно вызывать метод обратного вызова GetTimestamp() для соотнесения событий со временем. Если сервис должен быть завершен или компонент останавливается, StopOffer() отзывает доступность интерфейса [SWS_AIDSM_10409].

Диаграмма последовательности: последовательность взаимодействия при инициализации, запросе временной метки со стороны IdsM и завершении работы поставщика. Источники: [SWS_AIDSM_10401], [SWS_AIDSM_10407], [SWS_AIDSM_10408], [SWS_AIDSM_10409]

Сценарии ошибок

Все методы интерфейса объявлены как noexcept и не генерируют исключений C++. Ошибки при активации предоставления сервиса вместо этого передаются через возвращаемый тип ara::core::Result<void> метода Offer() [SWS_AIDSM_10408]. Интерпретация: если регистрация в коммуникационном или платформенном фреймворке завершается неудачно (например, из-за неподходящей конфигурации порта), возвращенный Result содержит соответствующий код ошибки, который должен быть проверен перед дальнейшим использованием. Вопрос Q-5a971906b458dd6f (открытый)

Особого внимания требует поведение при параллелизме: ни деструктор [SWS_AIDSM_10402], ни методы Offer() [SWS_AIDSM_10408], StopOffer() [SWS_AIDSM_10409], operator=(&&) [SWS_AIDSM_10405] или GetTimestamp() [SWS_AIDSM_10407] не классифицированы как потокобезопасные. Поэтому вызывающие стороны должны гарантировать, что операции жизненного цикла и обработка обратных вызовов происходят синхронизированно по потокам и не возникает гонок данных.

Это руководство основано на требованиях спецификации AUTOSAR для модуля idsm (R25-11).
