класс ara::per::SharedHandle

[SWS_PER_00362] Upstream: RS_PER_00002, RS_AP_00122, RS_AP_00140

template <typename T> class SharedHandle final {...};

Handle to a File Storage or Key-Value Storage. A SharedHandle is returned by the functions OpenFileStorage() and OpenKeyValueStorage() and can be passed between threads as needed. It provides the abstraction that is necessary to allow thread-safe implementation of OpenFile Storage() and OpenKeyValueStorage().

Обеспечивает потокобезопасный доступ к хранилищу файлов и хранилищу «ключ-значение» через границы потоков.

Шаблонный класс ara::per::SharedHandle служит абстракцией умного указателя (smart pointer) для хранилищ файлов и хранилищ «ключ-значение» для обеспечения потокобезопасного доступа через границы потоков. После получения через фабричные функции состояние валидности дескриптора (handle) должно быть проверено через operator bool() [SWS_PER_00398], поскольку вызов других операторов для пустого или сделанного недействительным операциями перемещения дескриптора приводит к неопределенному поведению. В то время как разыменование инкапсулированного объекта является потокобезопасным, операции присваивания и уничтожение дескриптора [SWS_PER_00568] для одного и того же экземпляра требуют внешней синхронизации.

Контекст

Шаблонный класс ara::per::SharedHandle представляет собой абстракцию «умного указателя» для персистентных ресурсов хранения в модуле per (Persistency) платформы AUTOSAR Adaptive Platform. Он служит стандартизированным типом возвращаемого значения фабричных функций OpenFileStorage() и OpenKeyValueStorage(). Основная обязанность класса состоит в координации доступа к файловым хранилищам и хранилищам типа «ключ — значение» через границы потоков, а также в обеспечении необходимой инкапсуляции для потокобезопасной реализации процедур открытия хранилищ и доступа к ним. Участниками взаимодействия являются потоки выполнения на стороне приложения, управление персистентностью, а также соответствующий инкапсулированный ресурс хранения T.

Жизненный цикл

Дескриптор SharedHandle обычно создается при открытии экземпляра хранилища через фабричные интерфейсы модуля per. С помощью конструктора копирования [SWS_PER_00369] и оператора присваивания копированием [SWS_PER_00370] дескриптор можно дублировать, благодаря чему несколько экземпляров дескриптора получают разделяемый доступ к одному и тому же целевому объекту. Если дескриптор передается с использованием конструктора перемещения [SWS_PER_00367] или оператора присваивания перемещением [SWS_PER_00368], исходный дескриптор переходит в инвалидированное состояние и больше не должен использоваться для доступа к хранилищу.

Текущее состояние дескриптора определяется явным оператором преобразования operator bool() [SWS_PER_00398]: он возвращает true, если имеется ссылка на действительный экземпляр хранилища, и false, если дескриптор пуст. Освобождение ресурсов дескриптора осуществляется через деструктор ~SharedHandle() [SWS_PER_00568]. Интерпретация: базовый ресурс хранения, по-видимому, освобождается, как только уничтожается последний ссылающийся SharedHandle.

Что касается параллелизма, операции доступа к инкапсулированному ресурсу через operator* ([SWS_PER_00402], [SWS_PER_00403]) и operator-> ([SWS_PER_00363], [SWS_PER_00364]), а также опрос состояния через operator bool() [SWS_PER_00398] являются потокобезопасными. Операции присваивания для одного и того же дескриптора ([SWS_PER_00368], [SWS_PER_00370]) и его уничтожение [SWS_PER_00568], напротив, не являются потокобезопасными и требуют внешней синхронизации при разделяемом использовании дескриптора.

Диаграмма состояний: жизненный цикл и переходы состояний ara::per::SharedHandle между действительным и пустым состоянием. Источники: [SWS_PER_00367], [SWS_PER_00368], [SWS_PER_00369], [SWS_PER_00370], [SWS_PER_00398], [SWS_PER_00568]

Путь использования

Типичное использование ara::per::SharedHandle включает контролируемое получение, валидацию и доступ к структурам хранения:

  1. Получение дескриптора: приложение вызывает OpenFileStorage() или OpenKeyValueStorage() и принимает SharedHandle<T>.
  2. Проверка валидности: перед каждым доступом приложение проверяет состояние дескриптора с помощью operator bool() [SWS_PER_00398].
  3. Доступ к ресурсу: вызов функций хранения выполняется путем разыменования с помощью operator-> ([SWS_PER_00363], [SWS_PER_00364]) или operator* ([SWS_PER_00402], [SWS_PER_00403]).
  4. Передача: при необходимости дескриптор может быть передан в другие потоки посредством копирования ([SWS_PER_00369], [SWS_PER_00370]) или перемещения ([SWS_PER_00367], [SWS_PER_00368]).
  5. Завершение жизненного цикла: при выходе из области видимости деструктор [SWS_PER_00568] разрушает дескриптор.

Диаграмма последовательности: процесс получения, проверки валидности, вызова методов и разрушения SharedHandle. Источники: [SWS_PER_00363], [SWS_PER_00398], [SWS_PER_00568]

Сценарии ошибок

Критические ошибочные состояния возникают преимущественно при недопустимых операциях над пустыми или инвалидированными дескрипторами. Согласно [SWS_PER_00398], вызов любых операторов, кроме operator bool(), на пустом дескрипторе непосредственно приводит к неопределенному поведению (Undefined Behavior). Это касается, в частности, исходных дескрипторов после перемещающего конструирования [SWS_PER_00367] или перемещающего присваивания [SWS_PER_00368], поскольку они инвалидируются и больше не должны использоваться.

Чтобы предотвратить неопределенное поведение, спецификация обязательно требует проверки состояния дескриптора с помощью operator bool() перед вызовом других операторов ([SWS_PER_00367], [SWS_PER_00368]). Все конструкторы, операторы присваивания, операторы доступа и деструктор объявлены как noexcept и специфицированы как безопасные относительно исключений («exception safe») ([SWS_PER_00367], [SWS_PER_00368], [SWS_PER_00369], [SWS_PER_00370], [SWS_PER_00363], [SWS_PER_00364], [SWS_PER_00402], [SWS_PER_00403], [SWS_PER_00398], [SWS_PER_00568]). Таким образом, недействительное состояние не вызывает исключения, а должно в обязательном порядке обрабатываться вызывающей стороной по возвращаемому значению operator bool().

Данное руководство основано на спецификации AUTOSAR для модуля per (Adaptive Platform, релиз R25-11) и создано ИИ-ассистентом курации.
