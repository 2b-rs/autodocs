Служит для идентификации и текстового преобразования всех кодов ошибок модуля crypto.

Класс определяет центральный домен ошибок для всех ошибок, которые могут быть зарегистрированы через открытые интерфейсы в пространстве имен ara::crypto [SWS_CRYPT_19950]. К его ключевым задачам относятся возврат уникального имени домена, а также преобразование кодов ошибок из перечисления CryptoErrc в понятные сообщения об ошибках [SWS_CRYPT_19953]. Все функции запросов реализованы как потокобезопасные и безопасные относительно исключений, тогда как метод генерации исключений при отключенных C++-исключениях не участвует в разрешении перегрузки [SWS_CRYPT_19954].

Контекст

Класс ara::crypto::CryptoErrorDomain функционирует как специализированный домен ошибок в составе платформы AUTOSAR Adaptive. Согласно определению класса, он наследует от ara::core::ErrorDomain и объявлен как final. Его главная ответственность заключается в представлении всех ошибок, о которых могут сообщать открытые интерфейсы в пространстве имен ara::crypto. Он присваивает ошибкам уникальный идентификатор домена, который можно запросить с помощью метода Name [SWS_CRYPT_19950].

Для унифицированного связывания типов класс предоставляет два специализированных псевдонима типов: Errc в качестве псевдонима напрямую указывает на перечисление CryptoErrc для криптографических кодов ошибок [SWS_CRYPT_19903], тогда как Exception ссылается на базовый класс исключений CryptoException [SWS_CRYPT_19904]. В качестве партнеров по взаимодействию выступают преимущественно функциональные криптографические блоки, порождающие ошибки данного домена, а также прикладное ПО, принимающее и анализирующее ошибки через базовые механизмы ara::core.

Контекстная диаграмма: интеграция CryptoErrorDomain в обработку ошибок между API-интерфейсами ara::crypto, базовым классом ara::core::ErrorDomain и приложением. Источники: [SWS_CRYPT_19950], [SWS_CRYPT_19903], [SWS_CRYPT_19904].

Жизненный цикл

Создание объектов CryptoErrorDomain осуществляется через стандартный конструктор без параметров, который специфицирован как constexpr и noexcept [SWS_CRYPT_19902]. Благодаря объявлению в качестве constexpr экземпляр может быть сконструирован уже на этапе компиляции. Интерпретация: в типичных реализациях платформы домен ошибок, вероятно, существует как долгоживущий или статический singleton, чтобы коды ошибок на протяжении всего выполнения процесса могли ссылаться на один и тот же экземпляр домена без динамического выделения памяти.

После инстанцирования объект имеет неизменяемый характер без сохранения состояния; иерархия наследования ниже этого класса исключена ключевым словом final. Что касается конкурентности, как конструктор [SWS_CRYPT_19902], так и методы запросов Name [SWS_CRYPT_19950], Message [SWS_CRYPT_19953] и ThrowAsException [SWS_CRYPT_19954] явно классифицированы как потокобезопасные (thread-safe). Таким образом, экземпляры могут использоваться параллельно несколькими потоками без внешней синхронизации.

Путь использования

Стандартная последовательность действий при взаимодействии с CryptoErrorDomain состоит из следующих шагов:

  1. Операция в пространстве имен ara::crypto завершается сбоем и создает объект ошибки типа ara::core::ErrorCode, связанный с CryptoErrorDomain.
  2. Вызывающее приложение или подпрограмма обработки ошибок проверяет источник ошибки и при необходимости может запросить уникальное имя домена с помощью Name() [SWS_CRYPT_19950].
  3. Для формирования диагностических сообщений или записей журнала вызывается метод Message() с переданным errorCode, который расшифровывает код и возвращает соответствующее текстовое сообщение в виде const char* [SWS_CRYPT_19953].
  4. Если вызывающий компонент хочет преобразовать ошибку в C++-исключение, выполняется вызов ThrowAsException(), в результате чего генерируется подходящее исключение на основе CryptoException [SWS_CRYPT_19954], [SWS_CRYPT_19904].

Диаграмма последовательности: разрешение ошибок и вывод текста через интерфейсы CryptoErrorDomain. Источники: [SWS_CRYPT_19950], [SWS_CRYPT_19953].

Сценарии ошибок

При обработке ошибок класс предоставляет дифференцированные гарантии безопасности относительно исключений. Методы Name [SWS_CRYPT_19950] и Message [SWS_CRYPT_19953] объявлены как noexcept и полностью безопасны относительно исключений (exception safe). Если в Message передано числовое значение, не определенное в перечислении CryptoErrc, предположительно будет возвращено общее резервное сообщение; аварийное завершение из-за исключений исключено.

В противоположность этому метод ThrowAsException специфицирован как небезопасный относительно исключений (not exception safe) и снабжен атрибутом [[noreturn]], поскольку его прямое назначение состоит в генерации исключения [SWS_CRYPT_19954]. Существенное граничное условие относится к конфигурациям платформы без поддержки исключений: если C++-исключения отключены в тулчейне компилятора, ThrowAsException не участвует в разрешении перегрузки [SWS_CRYPT_19954]. В таких системах вызов не сможет скомпилироваться, и обработка ошибок должна в обязательном порядке осуществляться через механизмы, основанные на значениях ошибок, такие как объекты результатов.

Использование и контекст вызова

Конструктор по умолчанию CryptoErrorDomain() инициализирует экземпляр домена ошибок для криптографических операций [SWS_CRYPT_19902]. Он специфицирован как constexpr и noexcept, не принимает аргументов и не имеет возвращаемого значения. Выполнение происходит синхронно и может осуществляться во время компиляции. В прикладных программах ручное инстанцирование вряд ли потребуется, поскольку доступ к домену штатно осуществляется через глобальную функцию GetCryptoErrorDomain() [SWS_CRYPT_19952].

Обработка ошибок и параллелизм

Создание объекта определено как exception safe, а также thread-safe [SWS_CRYPT_19902]. Поскольку конструктор объявлен с noexcept, при вызове не возникает ошибок или исключений; сообщений об ошибках в DET или DEM для этого конструктора не предусмотрено.

Взаимодействие в модуле

Созданный домен образует контекст для описаний криптографических ошибок:

  • Он инкапсулирует коды ошибок перечисления CryptoErrc [SWS_CRYPT_10099] через псевдоним типа Errc [SWS_CRYPT_19903].
  • Через свободную функцию MakeErrorCode() создаются экземпляры ara::core::ErrorCode, жестко ссылающиеся на этот домен [SWS_CRYPT_19951].
  • Функции-члены домена позволяют запрашивать идентификатор через Name() [SWS_CRYPT_19950], получать текстовое описание через Message() [SWS_CRYPT_19953], а также генерировать системно-специфичные ошибки через ThrowAsException() [SWS_CRYPT_19954] с базовым типом Exception [SWS_CRYPT_19904].
