Контекст

Класс ara::idsm::ContextDataProvider служит в модуле idsm (Intrusion Detection System Manager) AUTOSAR Adaptive Platform для предоставления и дополнения контекстных данных, относящихся к безопасности ([SWS_AIDSM_10500]). При мониторинге критических с точки зрения безопасности событий IdsM требуются дополнительные сведения об окружении и состоянии приложения, чтобы точно классифицировать обнаруженные аномалии или инциденты безопасности. В качестве интерфейса ContextDataProvider определяет абстрактный метод ModifyContextData ([SWS_AIDSM_10509]), с помощью которого IdsM при необходимости запрашивает данные из использующего его компонента.

Взаимодействие осуществляется между тремя основными компонентами:

  • Adaptive Application / подкласс провайдера: приложение реализует конкретную логику провайдера путем переопределения ModifyContextData ([SWS_AIDSM_10509]) и управляет жизненным циклом объекта предоставления.
  • Базовый класс ContextDataProvider: управляет привязкой к смоделированному в манифесте порту провайдера через идентификатор экземпляра ([SWS_AIDSM_10501]).
  • Служба IdsM: Intrusion Detection System обращается к контекстным данным, как только предоставление через интерфейс было активировано ([SWS_AIDSM_10507]).

Жизненный цикл

Инстанцирование ContextDataProvider выполняется явно через конструктор с передачей ara::core::InstanceSpecifier, количества дополнительных байтов (additionalBytes), а также смещения для исходных контекстных данных (originalContextDataOffset) ([SWS_AIDSM_10501]). Этот конструктор специфицирован как потокобезопасный (thread-safe) ([SWS_AIDSM_10501]).

В отношении семантики владения и значений действуют строгие ограничения:

  • Копирование запрещено: как конструктор копирования ([SWS_AIDSM_10504]), так и оператор присваивания с копированием ([SWS_AIDSM_10506]) удалены (= delete). Экземпляр провайдера однозначно привязан к смоделированному порту и не может быть продублирован.
  • Перемещение разрешено: класс имеет потокобезопасный конструктор перемещения ([SWS_AIDSM_10503]). Присваивание с перемещением через operator= также поддерживается, однако не является потокобезопасным (not thread-safe) ([SWS_AIDSM_10505]).

После конструирования экземпляр находится в неактивном состоянии. Только явный вызов Offer() ([SWS_AIDSM_10507]) сигнализирует IdsM о том, что провайдер готов и разрешено вызывать ModifyContextData. С помощью StopOffer() ([SWS_AIDSM_10508]) эта служба снова прерывается. Освобождение экземпляра выполняется через виртуальный деструктор ~ContextDataProvider() ([SWS_AIDSM_10502]). Интерпретация: во избежание race conditions во время работы деструктора, вероятно, следует вызывать StopOffer() перед уничтожением объекта, поскольку как уничтожение, так и отмена регистрации не являются потокобезопасными ([SWS_AIDSM_10502], [SWS_AIDSM_10508]).

Путь использования

Стандартный процесс предоставления контекстных данных включает следующие фазы:

  1. Наследование: Интерпретация: поскольку ModifyContextData является чисто виртуальным методом ([SWS_AIDSM_10509]), приложение создает собственный производный класс и переопределяет эту функцию.
  2. Создание: производный класс провайдера инстанцируется с указанием InstanceSpecifier для смоделированного порта провайдера, дополнительного размера буфера, а также смещения ([SWS_AIDSM_10501]).
  3. Активация: приложение вызывает Offer() ([SWS_AIDSM_10507]). После успешной регистрации IdsM авторизован выполнять callback-вызовы к провайдеру.
  4. Предоставление контекста: при возникновении события безопасности в IdsM фреймворк вызывает ModifyContextData(contextData, event) ([SWS_AIDSM_10509]). Приложение записывает контекстную информацию в переданный байтовый буфер (ara::core::Span<std::uint8_t>) и возвращает количество измененных байтов.
  5. Деактивация: перед завершением работы компонента приложение вызывает StopOffer() ([SWS_AIDSM_10508]), чтобы предотвратить дальнейшие вызовы со стороны IdsM, и уничтожает экземпляр ([SWS_AIDSM_10502]).

Диаграмма последовательности: типичный процесс инициализации, предоставления (Offer), событийно-управляемой модификации контекста и отмены регистрации (StopOffer). Источники: [SWS_AIDSM_10501], [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509].

Сценарии ошибок

Методы управления состоянием и модификации данных сигнализируют о состояниях выполнения через ara::core::Result:

  • Сбой Offer: метод Offer() возвращает ara::core::Result<void> ([SWS_AIDSM_10507]). Если порт провайдера не может быть зарегистрирован (например, из-за нехватки системных ресурсов или некорректного моделирования), объект результата содержит соответствующий код ошибки. В этом случае вызовы IdsM к ModifyContextData не допускаются.
  • Сбой в ModifyContextData: функция обратного вызова возвращает ara::core::Result<std::size_t> ([SWS_AIDSM_10509]). Если емкости переданного ara::core::Span<std::uint8_t> недостаточно или контекст для переданного EventIdType не может быть определен, производный класс возвращает результат с ошибкой вместо передачи количества байтов.
  • Предусловия и постусловия: ModifyContextData может выполняться исключительно между успешным Offer() ([SWS_AIDSM_10507]) и StopOffer() ([SWS_AIDSM_10508]). Поскольку ни Offer(), ни StopOffer(), ни ModifyContextData() не являются потокобезопасными ([SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]), вызывающее приложение должно гарантировать, что операции жизненного цикла не выполняются параллельно с текущими выполнениями callback-функций.

Настоящее руководство было сгенерировано моделью ИИ на основе спецификации AUTOSAR Adaptive Platform R25-11 (модуль idsm).

<h4>Контекст</h4>
<p>Класс <code>ara::idsm::ContextDataProvider</code> служит в модуле <code>idsm</code> (Intrusion Detection System Manager) AUTOSAR Adaptive Platform для предоставления и дополнения контекстных данных, относящихся к безопасности (<a class="spec-record-ref" data-req="SWS_AIDSM_10500" href="../spec/record.html?id=SWS_AIDSM_10500">[SWS_AIDSM_10500]</a>). При мониторинге критических с точки зрения безопасности событий IdsM требуются дополнительные сведения об окружении и состоянии приложения, чтобы точно классифицировать обнаруженные аномалии или инциденты безопасности. В качестве интерфейса <code>ContextDataProvider</code> определяет абстрактный метод <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), с помощью которого IdsM при необходимости запрашивает данные из использующего его компонента.</p>
<p>Взаимодействие осуществляется между тремя основными компонентами:</p>
<ul>
<li><strong>Adaptive Application / подкласс провайдера:</strong> приложение реализует конкретную логику провайдера путем переопределения <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>) и управляет жизненным циклом объекта предоставления.</li>
<li><strong>Базовый класс ContextDataProvider:</strong> управляет привязкой к смоделированному в манифесте порту провайдера через идентификатор экземпляра (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</li>
<li><strong>Служба IdsM:</strong> Intrusion Detection System обращается к контекстным данным, как только предоставление через интерфейс было активировано (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>).</li>
</ul>

<h4>Жизненный цикл</h4>
<p>Инстанцирование <code>ContextDataProvider</code> выполняется явно через конструктор с передачей <code>ara::core::InstanceSpecifier</code>, количества дополнительных байтов (<code>additionalBytes</code>), а также смещения для исходных контекстных данных (<code>originalContextDataOffset</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>). Этот конструктор специфицирован как потокобезопасный (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</p>
<p>В отношении семантики владения и значений действуют строгие ограничения:</p>
<ul>
<li><strong>Копирование запрещено:</strong> как конструктор копирования (<a class="spec-record-ref" data-req="SWS_AIDSM_10504" href="../spec/record.html?id=SWS_AIDSM_10504">[SWS_AIDSM_10504]</a>), так и оператор присваивания с копированием (<a class="spec-record-ref" data-req="SWS_AIDSM_10506" href="../spec/record.html?id=SWS_AIDSM_10506">[SWS_AIDSM_10506]</a>) удалены (<code>= delete</code>). Экземпляр провайдера однозначно привязан к смоделированному порту и не может быть продублирован.</li>
<li><strong>Перемещение разрешено:</strong> класс имеет потокобезопасный конструктор перемещения (<a class="spec-record-ref" data-req="SWS_AIDSM_10503" href="../spec/record.html?id=SWS_AIDSM_10503">[SWS_AIDSM_10503]</a>). Присваивание с перемещением через <code>operator=</code> также поддерживается, однако не является потокобезопасным (<code>not thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10505" href="../spec/record.html?id=SWS_AIDSM_10505">[SWS_AIDSM_10505]</a>).</li>
</ul>
<p>После конструирования экземпляр находится в неактивном состоянии. Только явный вызов <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) сигнализирует IdsM о том, что провайдер готов и разрешено вызывать <code>ModifyContextData</code>. С помощью <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>) эта служба снова прерывается. Освобождение экземпляра выполняется через виртуальный деструктор <code>~ContextDataProvider()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>). Интерпретация: во избежание race conditions во время работы деструктора, вероятно, следует вызывать <code>StopOffer()</code> перед уничтожением объекта, поскольку как уничтожение, так и отмена регистрации не являются потокобезопасными (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>).</p>

<h4>Путь использования</h4>
<p>Стандартный процесс предоставления контекстных данных включает следующие фазы:</p>
<ol>
<li><strong>Наследование:</strong> Интерпретация: поскольку <code>ModifyContextData</code> является чисто виртуальным методом (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), приложение создает собственный производный класс и переопределяет эту функцию.</li>
<li><strong>Создание:</strong> производный класс провайдера инстанцируется с указанием <code>InstanceSpecifier</code> для смоделированного порта провайдера, дополнительного размера буфера, а также смещения (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</li>
<li><strong>Активация:</strong> приложение вызывает <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>). После успешной регистрации IdsM авторизован выполнять callback-вызовы к провайдеру.</li>
<li><strong>Предоставление контекста:</strong> при возникновении события безопасности в IdsM фреймворк вызывает <code>ModifyContextData(contextData, event)</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>). Приложение записывает контекстную информацию в переданный байтовый буфер (<code>ara::core::Span&lt;std::uint8_t&gt;</code>) и возвращает количество измененных байтов.</li>
<li><strong>Деактивация:</strong> перед завершением работы компонента приложение вызывает <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>), чтобы предотвратить дальнейшие вызовы со стороны IdsM, и уничтожает экземпляр (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>).</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>Методы управления состоянием и модификации данных сигнализируют о состояниях выполнения через <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Сбой Offer:</strong> метод <code>Offer()</code> возвращает <code>ara::core::Result&lt;void&gt;</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>). Если порт провайдера не может быть зарегистрирован (например, из-за нехватки системных ресурсов или некорректного моделирования), объект результата содержит соответствующий код ошибки. В этом случае вызовы IdsM к <code>ModifyContextData</code> не допускаются.</li>
<li><strong>Сбой в ModifyContextData:</strong> функция обратного вызова возвращает <code>ara::core::Result&lt;std::size_t&gt;</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>). Если емкости переданного <code>ara::core::Span&lt;std::uint8_t&gt;</code> недостаточно или контекст для переданного <code>EventIdType</code> не может быть определен, производный класс возвращает результат с ошибкой вместо передачи количества байтов.</li>
<li><strong>Предусловия и постусловия:</strong> <code>ModifyContextData</code> может выполняться исключительно между успешным <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) и <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>). Поскольку ни <code>Offer()</code>, ни <code>StopOffer()</code>, ни <code>ModifyContextData()</code> не являются потокобезопасными (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), вызывающее приложение должно гарантировать, что операции жизненного цикла не выполняются параллельно с текущими выполнениями callback-функций.</li>
</ul>
