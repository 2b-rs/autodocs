Служит интерфейсом для предоставления и модификации контекстных данных конкретного приложения для IdsM.

Абстрактный класс ara::idsm::ContextDataProvider служит для предоставления и модификации специфичных для приложения контекстных данных для Intrusion Detection System Manager [SWS_AIDSM_10500]. Приложения наследуются от этого класса, реализуют callback ModifyContextData и управляют предоставлением сервиса для IdsM с помощью методов Offer, а также StopOffer [SWS_AIDSM_10507]. Экземпляр не является копируемым, и поскольку центральные методы не являются потокобезопасными, параллельный доступ, вероятно, потребует внешней синхронизации (интерпретация). Вопрос (открытый)

Контекст

Класс ara::idsm::ContextDataProvider служит для предоставления и модификации контекстных данных для подсистемы Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10500]. В рамках архитектуры безопасности класс функционирует как интерфейс между критически важным для безопасности приложением и сервисом IdsM. Поскольку функция-член ModifyContextData специфицирована как чисто виртуальная [SWS_AIDSM_10509], ContextDataProvider представляет собой абстрактный базовый класс. Приложение выводит собственную реализацию, чтобы дополнять специфические контекстные данные при возникновении событий безопасности. Привязка к конфигурации архитектуры осуществляется через ara::core::InstanceSpecifier для смоделированного порта поставщика (provider port) [SWS_AIDSM_10501].

Жизненный цикл

Создание экземпляра выполняется явно через конструктор с указанием идентификатора порта (ara::core::InstanceSpecifier), а также параметров буфера additionalBytes и originalContextDataOffset [SWS_AIDSM_10501]. Этот конструктор объявлен как потокобезопасный [SWS_AIDSM_10501]. Чтобы гарантировать однозначные отношения владения для конечной точки интерфейса, как конструктор копирования [SWS_AIDSM_10504], так и оператор присваивания с копированием [SWS_AIDSM_10506] удалены. Передача экземпляра возможна через семантику перемещения: конструктор перемещения потокобезопасен [SWS_AIDSM_10503], тогда как оператор присваивания operator= со ссылкой на rvalue определен как непотокобезопасный [SWS_AIDSM_10505].

После создания экземпляр находится в неактивном состоянии. Только явный вызов Offer() активирует регистрацию и авторизует IdsM вызывать ModifyContextData [SWS_AIDSM_10507]. Через StopOffer() эту авторизацию можно отозвать в любой момент [SWS_AIDSM_10508]. Перед уничтожением объекта через виртуальный деструктор [SWS_AIDSM_10502] согласно общепринятой практике, вероятно, потребуется вызвать StopOffer(), чтобы своевременно отключить выполняющиеся вызовы callback со стороны IdsM (интерпретация). Вопрос Q-ee65caee57919f00 (открытый) Виртуальный деструктор специфицирован как непотокобезопасный [SWS_AIDSM_10502].

Путь использования

Типичный сценарий использования начинается с определения специфичного для приложения класса, который наследуется от ContextDataProvider и реализует метод ModifyContextData [SWS_AIDSM_10509]. После создания экземпляра приложение вызывает Offer(), чтобы предоставить контекстные данные для IdsM [SWS_AIDSM_10507]. Как только IdsM регистрирует событие безопасности, для которого должны быть дополнены контекстные данные, подсистема вызывает callback ModifyContextData [SWS_AIDSM_10509]. Метод получает область данных в виде ara::core::Span<std::uint8_t>, а также идентификатор EventIdType, обновляет содержимое буфера и возвращает фактическое количество байт как ara::core::Result<std::size_t> [SWS_AIDSM_10509]. Если предоставление данных требуется завершить, приложение вызывает StopOffer() [SWS_AIDSM_10508].

Диаграмма последовательности: последовательность взаимодействия между приложением, ContextDataProvider и IdsM от активации с помощью Offer через callback до деактивации через StopOffer. Источники: [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]

Сценарии ошибок

Все методы интерфейса объявлены с noexcept; ошибки возвращаются через тип ara::core::Result. Вызов Offer() возвращает ara::core::Result<void> [SWS_AIDSM_10507], который должен быть проверен приложением для перехвата возможных ошибок при предоставлении сервиса. Если поставщик не может записать запрошенные контекстные данные в ModifyContextData, реализация, вероятно, сообщит о системно-специфической ошибке в ara::core::Result<std::size_t> (интерпретация) [SWS_AIDSM_10509]. Вопрос Q-585e19770d59309e (открытый)

Что касается параллелизма, следует учитывать, что Offer() [SWS_AIDSM_10507], StopOffer() [SWS_AIDSM_10508], ModifyContextData() [SWS_AIDSM_10509], оператор присваивания [SWS_AIDSM_10505] и деструктор [SWS_AIDSM_10502] специфицированы как непотокобезопасные. Если вызовы этих методов происходят параллельно из нескольких потоков без внешней синхронизации, это, вероятно, приведет к гонкам данных и непредсказуемому поведению (интерпретация). Вопрос Q-80b83a52aba53d67 (открытый)
