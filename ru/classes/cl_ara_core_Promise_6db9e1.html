Использование по назначению

ara::core::Promise<T, E> — это AUTOSAR вариант std::promise. Тип ошибки должен быть ara::core::ErrorCode. Вместе с Future класс может предоставлять значения и ошибки асинхронно и потокобезопасно без обработки исключений. [SWS_CORE_00340] [SWS_CORE_10800]

Жизненный цикл и право собственности

Копирование запрещено (=delete), перемещение возможно. Присваивание перемещением и деструктор отказываются от возможно существующего Shared State. [SWS_CORE_00350] [SWS_CORE_00351] [SWS_CORE_00342] [SWS_CORE_00343] [SWS_CORE_00349]

Взаимодействие с другими классами

get_future() возвращает соответствующий Future<T,E> с тем же Shared State; этот вызов разрешён только один раз для каждого Promise. set_value(), SetError() и SetResult() подготавливают Shared State. Ограничения & Обработка ошибок

Повторная установка значения, ошибки или результата, а также вызов setter без Shared State определены как Violation. [SWS_CORE_13015] [SWS_CORE_13016]

Предоставление асинхронного результата

На стороне скелета Promise может предоставить уже вычисленное значение или может быть отправлен в асинхронный рабочий процесс; связанный Future возвращается вызывающей стороне. EXP ARAComAPI §5.4.6 «Methods»

Если обнаруживается ошибка приложения, соответствующий ErrorCode помещается в Promise; затем клиент может обработать его как Result, используя путь Future. EXP ARAComAPI §4.7 «Error Handling» EXP ARAComAPI §5.4.6 «Methods»

Диаграмма последовательности: многоразовый поток Promise/Future для асинхронных методов. Источники: EXP ARAComAPI §4.4 «Method based communication» EXP ARAComAPI §5.4.6 «Methods».

Договор об общем государстве

Promise завершает общее состояние, наблюдаемое в Future. Релевантная основа — определённая в Core концепция Future/Promise для асинхронных результатов со значением или ошибкой. SWS Core §7.2 «Error handling» SWS Core §7.2.5.5 «Future and Promise»

Поведение при ошибке

Promise может подготовить свой Shared State со значением, ошибкой или Result только один раз. Последующий вызов set_value(), SetError() или SetResult(), когда значение или ошибка уже сохранены, специфицируется как Violation promise_already_satisfied. Setter без Shared State является отдельной Violation. [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356] [SWS_CORE_13015] [SWS_CORE_13016]

get_future() можно вызывать только один раз для каждого общего состояния. Второй вызов установлен как нарушение future_already_retrieved; Если общее состояние отсутствует, применяется нарушение no_state. Эти случаи не являются ошибками приложения, о которых сообщается через _Result в контракте API. [SWS_CORE_00344] [SWS_CORE_13013] [SWS_CORE_13014]

Деструктор и назначение перемещения удаляют существующий Shared State. Если уже выведенная страница Future ожидает результата, она вернет GetResult() ошибку FutureErrc::kBrokenPromise; get() обрабатывает то же условие в виде исключения. Полный процесс, включая установку ошибки и тайм-аута, показан в Fehlerpfad-Diagramm von Future. [SWS_CORE_00343] [SWS_CORE_00349] [SWS_CORE_00336] [SWS_CORE_00326]

функция get_future [SWS_CORE_00344] Upstream: RS_AP_00130

Future< T, E > get_future () noexcept;

Return an associated Future with the same shared state as *this The returned Future is set as soon as this Promise receives the result, value, or an error. This fuction must only be called once as it is not allowed to have multiple Futures per Promise.

Используйте Сгенерировано ИИ / AI generated

Автоматически созданная рекомендация по использованию, выведенная из элементов спецификации AUTOSAR R25-11 и сопроводительных стандартных документов; не является официальным текстом AUTOSAR.

get_future (ara::core::Promise) возвращает объект ara::core::Future, относящийся к ara::core::Promise и имеющий то же Shared State. Возвращаемый Future устанавливается, как только этот Promise получает результат, значение или ошибку. Функцию разрешается вызывать лишь один раз для каждого Promise, поскольку несколько Futures для одного Promise не допускаются. Согласно спецификации вызов не потокобезопасен и exception-safe. Функция не определяет стандартизированных ошибок. [SWS_CORE_00344]

Обработка ошибок

  • IsoStdFutureErrcFutureAlreadyRetrievedViolation: если функция вызывается более одного раза в одном и том же общем состоянии.
  • IsoStdFutureErrcNoStateViolation: если *this не имеет Shared State.

Возвращенный Future формирует клиентскую часть общего состояния; скелет может вернуть его до того, как асинхронный рабочий процесс заполнит значение в Promise. EXP ARAComAPI §5.4.6 «Methods»
