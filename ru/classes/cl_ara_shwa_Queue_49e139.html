Контекст

Класс ara::shwa::Queue представляет собой центральный интерфейс в модуле shwa (Shared Hardware Accelerator) для планирования выполнения задач на аппаратных ускорителях. Очередь инкапсулирует соединение с конкретным устройством выполнения (Device) или аппаратным блоком, адресуемым через DeviceSelector, и координирует передачу, а также синхронизацию рабочих заданий.

В общей системе ara::shwa::Queue взаимодействует со следующими участниками:

  • Приложение: создает очередь с помощью фабричных методов и управляет отправкой задач, а также синхронизацией.
  • Device / DeviceSelector: представляет целевое устройство, к которому привязана очередь и свойства которого она отражает [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909], [AP_SWS_SHWA_00910].
  • ErrorHandler: принимает сообщения об ошибках, возникших асинхронно во время обработки задач [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909], [AP_SWS_SHWA_00912].
  • Event: создается при планировании задачи (Submit) и служит объектом управления и синхронизации для последующих операций [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00913].
  • PropertyList: передает необязательные параметры конфигурации при создании очереди [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909].

Контекстная диаграмма: участники взаимодействия класса ara::shwa::Queue. Источники: [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909], [AP_SWS_SHWA_00910], [AP_SWS_SHWA_00912]

Жизненный цикл

Класс ara::shwa::Queue обладает строго контролируемой семантикой создания экземпляров и владения:

  • Создание: конструктор по умолчанию явно удален [AP_SWS_SHWA_00902]. Новые экземпляры могут создаваться исключительно через статические фабричные методы Create, которые возвращают ara::core::Result<std::unique_ptr<Queue>> [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909]. Создание привязывает очередь к Device или DeviceSelector, связывает ErrorHandler и обрабатывает необязательные свойства PropertyList.
  • Владение и идентичность: класс ara::shwa::Queue не может быть ни скопирован, ни перемещен. Как конструктор копирования [AP_SWS_SHWA_00903] и оператор присваивания копированием [AP_SWS_SHWA_00904], так и конструктор перемещения [AP_SWS_SHWA_00905] и оператор присваивания перемещением [AP_SWS_SHWA_00906] удалены. Поэтому жизненный цикл экземпляра управляется исключительно через возвращенный std::unique_ptr.
  • Уничтожение: если очередь освобождена или уничтожена, объект считается недействительным. Вызовы методов для уничтоженных или недействительных очередей отклоняются с ошибкой ShwaErrorCode::kInvalidObject [AP_SWS_SHWA_00913], [AP_SWS_SHWA_00914], [AP_SWS_SHWA_00917].
  • Параллелизм: методы создания Create потокобезопасны (thread-safe) [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909]. Напротив, все обычные функции-члены созданного экземпляра (GetDevice, GetProperty, HasProperty, IsInOrder, Submit, Wait, WaitFor) не являются потокобезопасными (not thread-safe). Поэтому одновременный доступ к одному и тому же экземпляру очереди из нескольких потоков требует внешней синхронизации со стороны приложения.

Путь использования

Типичный процесс использования ara::shwa::Queue включает создание экземпляра, проверку свойств, передачу заданий и синхронизацию:

  1. Создание очереди: приложение вызывает Queue::Create с требуемым Device (или DeviceSelector), ErrorHandler и необязательным PropertyList [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909].
  2. Запрос свойств: перед отправкой задач можно проверить, обрабатываются ли задачи строго последовательно (IsInOrder [AP_SWS_SHWA_00911]), какое Device сопоставлено (GetDevice [AP_SWS_SHWA_00910]) или имеются ли определенные свойства возможностей (HasProperty [AP_SWS_SHWA_00915], GetProperty [AP_SWS_SHWA_00916]).
  3. Постановка задач в очередь (Submit): рабочая задача передается в очередь через Submit. При этом конфигурация cfg (интерпретация: специфичная для задачи конфигурация ядра или команды) либо передается со специфичным для задачи ErrorHandler [AP_SWS_SHWA_00912], либо связывается со вторичной очередью (secondaryQueue) [AP_SWS_SHWA_00913]. Оба варианта возвращают ara::core::Result<Event>.
  4. Синхронизация завершения задач: приложение ожидает завершения поставленных в очередь задач либо неограниченно с помощью Wait() [AP_SWS_SHWA_00914], либо с ограничением по времени и таймаутом в миллисекундах через WaitFor(ms) [AP_SWS_SHWA_00917].

Диаграмма последовательности: типичный порядок вызовов от создания очереди через Submit до синхронизации. Источники: [AP_SWS_SHWA_00909], [AP_SWS_SHWA_00911], [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00917]

Сценарии ошибок

Методы ara::shwa::Queue используют для индикации ошибок ara::core::Result с кодами ошибок из диапазона ShwaErrorCode:

  • Ошибки создания: метод Create завершается ошибкой, если переданные параметры недопустимы (ShwaErrorCode::kInvalidParameter), запрошенное свойство не поддерживается (ShwaErrorCode::kFeatureNotSupported), аппаратный ресурс занят (ShwaErrorCode::kResourceBusy) или возникает общая ошибка времени выполнения (ShwaErrorCode::kRuntime) [AP_SWS_SHWA_00908], [AP_SWS_SHWA_00909].
  • Ошибки отправки: при вызове Submit операция может завершиться ошибкой, если были переданы недопустимые аргументы (ShwaErrorCode::kInvalidParameter), очередь уже уничтожена или недействительна (ShwaErrorCode::kInvalidObject), ресурс занят (ShwaErrorCode::kResourceBusy) или выполнение задачи завершается сбоем (ShwaErrorCode::kTaskExecutionFailure) [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00913].
  • Ошибки синхронизации и таймауты: для Wait и WaitFor, помимо kResourceBusy, kInvalidObject, kFeatureNotSupported и kTaskExecutionFailure, в частности при вызове WaitFor может возникнуть ошибка ShwaErrorCode::kTimedOut, если указанный срок истекает до завершения задач [AP_SWS_SHWA_00914], [AP_SWS_SHWA_00917].
  • Отсутствие семантики отката: для Submit, Wait и WaitFor в случае ошибки kTaskExecutionFailure или kRuntime явно не действует гарантия отката (no_rollback_semantics). Данные и области памяти, на которые ссылались внутри завершившейся сбоем задачи, должны рассматриваться как непреднамеренно измененные [AP_SWS_SHWA_00912], [AP_SWS_SHWA_00913], [AP_SWS_SHWA_00914], [AP_SWS_SHWA_00917].

Данное руководство по классу было сгенерировано автоматически и основано исключительно на требованиях спецификации AUTOSAR Adaptive R25-11.
