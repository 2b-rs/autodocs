Контекст

Интерфейс <ExtendedDataRecord-Namespace>::<ExtendedDataRecordElementInterface> служит в AUTOSAR Adaptive Platform в рамках функционального кластера diag для предоставления данных для так называемых Extended Data Records (AUTOSAR_AP_SWS_Diagnostics с. 68). Эти наборы данных собираются при диагностических событиях и сохраняются компонентом Diagnostic Management (DM) на постоянной основе в энергонезависимой памяти ([SWS_DM_02156]).

Интерфейс определяет роль поставщика (Provider) на стороне приложения: адаптивное приложение реализует чисто виртуальный метод Read, чтобы при соответствующих диагностических запросах передавать требуемые значения компоненту Diagnostic Manager ([SWS_DM_02156]). Во взаимодействии участвуют как минимум три системных компонента: зависящая от приложения реализация интерфейса, Diagnostic Manager как посредник для входящих диагностических запросов ([SWS_DM_02152]), а также энергонезависимая память, в которой DM сохраняет запрошенные данные для диагностического контекста ([SWS_DM_02156]).

Контекстная диаграмма: партнеры по взаимодействию интерфейса для предоставления наборов данных. Источники: [SWS_DM_02152], [SWS_DM_02156], AUTOSAR_AP_SWS_Diagnostics с. 68

Жизненный цикл

Инстанцирование выполняется через конструктор с указанием ara::core::InstanceSpecifier и режима параллелизма ara::diag::ConcurrencyType ([SWS_DM_02158]). Параметр concurrencyType определяет, функционирует ли реализация как потокобезопасная (kConcurrent) или непотокобезопасная (kNotConcurrent) ([SWS_DM_02158]). Класс имеет строгую привязку к своей идентичности: конструктор копирования и оператор присваивания копированием удалены ([SWS_DM_02147], [SWS_DM_02148]). Также удалены конструктор перемещения и оператор присваивания перемещением ([SWS_DM_02149], [SWS_DM_02150]). Таким образом, экземпляр привязан к месту и не может быть передан.

После успешного конструирования экземпляр изначально остается в неактивном состоянии (NotOffered). При вызове Offer() пересылка запросов компонентом Diagnostic Management активируется, вследствие чего экземпляр переходит в состояние Offered ([SWS_DM_02152]). Повторный вызов Offer() в состоянии Offered приводит к ошибке ([SWS_DM_02152]). С помощью метода StopOffer() пересылка снова отключается, и объект возвращается в состояние NotOffered ([SWS_DM_02153]).

Уничтожение выполняется через виртуальный деструктор ([SWS_DM_02151]). В то время как конструктор объявлен потокобезопасным ([SWS_DM_02158]), деструктор явным образом не является потокобезопасным ([SWS_DM_02151]). Интерпретация: прекращение предложения службы через StopOffer(), по всей видимости, должно быть обязательно завершено до вызова деструктора, чтобы предотвратить параллельные обращения для чтения во время разрушения объекта.

Диаграмма состояний: жизненный цикл и состояния предоставления экземпляра интерфейса. Источники: [SWS_DM_02151], [SWS_DM_02152], [SWS_DM_02153], [SWS_DM_02158]

Путь использования

Типичный процесс предоставления и ответа на диагностические запросы выглядит следующим образом:

  1. Инстанцирование: производный класс поставщика создается с передачей ara::core::InstanceSpecifier, а также желаемого concurrencyType ([SWS_DM_02158]).
  2. Объявление о предоставлении: приложение вызывает Offer(). Только после успешного возврата управления входящие диагностические запросы пересылаются от DM экземпляру ([SWS_DM_02152]).
  3. Запрос записи данных (Read): если Diagnostic Management запрашивает элемент данных, оно вызывает метод Read(metaInfo, cancellationHandler) ([SWS_DM_02156]):
    • Запрос предоставляет контекстную информацию через metaInfo ([SWS_DM_02156]).
    • Через cancellationHandler.IsCanceled() или регистрацию функции уведомления с помощью cancellationHandler.SetNotifier() приложение может обработать преждевременное прерывание диалога ([SWS_DM_02156]).
    • Метод возвращает ara::core::Future со структурой ReadOutput ([SWS_DM_02154], [SWS_DM_02156]). Если на момент запроса данные недоступны, реализация должна всегда возвращать значение и заполнять данные шаблоном заполнения (например, 0xFF) ([SWS_DM_02156]).
  4. Отзыв предложения сервиса: перед завершением работы или в состояниях технического обслуживания приложение вызывает StopOffer(), чтобы остановить пересылку запросов ([SWS_DM_02153]).

Диаграмма последовательности: предоставление, опрос и завершение диагностического сервиса. Источники: [SWS_DM_02152], [SWS_DM_02153], [SWS_DM_02156]

Сценарии ошибок

Условия ошибок и нарушения сопоставлены соответствующим фазам:

  • Нарушения при конструировании: недействительные связи модели приводят к определенным сообщениям об ошибках ([SWS_DM_02158]):
    • InstanceSpecifierMappingIntegrityViolation: идентификатор не может быть разрешен в контексте Executable или не ссылается на PortPrototype ([SWS_DM_02158]).
    • PortInterfaceMappingViolation: на порт, типизированный с помощью DiagnosticExtendedDataRecordInterface, не ссылается DiagnosticDataPortMapping ([SWS_DM_02158]).
    • ProcessMappingViolation: для процесса времени выполнения не существует подходящего смоделированного процесса ([SWS_DM_02158]).
    • InstanceSpecifierAlreadyInUseViolation: идентификатор уже используется в процессе другим экземпляром ([SWS_DM_02158]).
  • Ошибка при регистрации сервиса: повторный вызов Offer() для уже предложенного экземпляра завершается сбоем с кодом ошибки DiagOfferErrc::kAlreadyOffered ([SWS_DM_02152]).
  • Ошибка во время запроса данных: если операция чтения не может быть выполнена надлежащим образом, ara::core::Future возвращает диагностический отрицательный код (DiagUdsNrcErrc) или зависящий от приложения код ошибки (ApApplicationError) ([SWS_DM_02156]). Если отсутствуют только необработанные данные, об ошибке сообщать нельзя; вместо этого запись данных необходимо заполнить значением-заменителем (например, 0xFF) ([SWS_DM_02156]).

Данное руководство по классу было создано автоматически для AUTOSAR Adaptive Platform R25-11 на основе требований спецификации.

Параметр <code>concurrencyType</code> определяет, функционирует ли реализация как потокобезопасная (<code>kConcurrent</code>) или непотокобезопасная (<code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>). Класс имеет строгую привязку к своей идентичности: конструктор копирования и оператор присваивания копированием удалены (<a class="spec-record-ref" data-req="SWS_DM_02147" href="../spec/record.html?id=SWS_DM_02147">[SWS_DM_02147]</a>, <a class="spec-record-ref" data-req="SWS_DM_02148" href="../spec/record.html?id=SWS_DM_02148">[SWS_DM_02148]</a>). Также удалены конструктор перемещения и оператор присваивания перемещением (<a class="spec-record-ref" data-req="SWS_DM_02149" href="../spec/record.html?id=SWS_DM_02149">[SWS_DM_02149]</a>, <a class="spec-record-ref" data-req="SWS_DM_02150" href="../spec/record.html?id=SWS_DM_02150">[SWS_DM_02150]</a>). Таким образом, экземпляр привязан к месту и не может быть передан.</p>
  <p>После успешного конструирования экземпляр изначально остается в неактивном состоянии (<em>NotOffered</em>). При вызове <code>Offer()</code> пересылка запросов компонентом Diagnostic Management активируется, вследствие чего экземпляр переходит в состояние <em>Offered</em> (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>). Повторный вызов <code>Offer()</code> в состоянии <em>Offered</em> приводит к ошибке (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>). С помощью метода <code>StopOffer()</code> пересылка снова отключается, и объект возвращается в состояние <em>NotOffered</em> (<a class="spec-record-ref" data-req="SWS_DM_02153" href="../spec/record.html?id=SWS_DM_02153">[SWS_DM_02153]</a>).</p>
  <p>Уничтожение выполняется через виртуальный деструктор (<a class="spec-record-ref" data-req="SWS_DM_02151" href="../spec/record.html?id=SWS_DM_02151">[SWS_DM_02151]</a>). В то время как конструктор объявлен потокобезопасным (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>), деструктор явным образом не является потокобезопасным (<a class="spec-record-ref" data-req="SWS_DM_02151" href="../spec/record.html?id=SWS_DM_02151">[SWS_DM_02151]</a>). Интерпретация: прекращение предложения службы через <code>StopOffer()</code>, по всей видимости, должно быть обязательно завершено до вызова деструктора, чтобы предотвратить параллельные обращения для чтения во время разрушения объекта.</p>

  <h4>Путь использования</h4>
  <p>Типичный процесс предоставления и ответа на диагностические запросы выглядит следующим образом:</p>
  <ol>
    <li><strong>Инстанцирование:</strong> производный класс поставщика создается с передачей <code>ara::core::InstanceSpecifier</code>, а также желаемого <code>concurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
    <li><strong>Объявление о предоставлении:</strong> приложение вызывает <code>Offer()</code>. Только после успешного возврата управления входящие диагностические запросы пересылаются от DM экземпляру (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>).</li>
    <li><strong>Запрос записи данных (Read):</strong> если Diagnostic Management запрашивает элемент данных, оно вызывает метод <code>Read(metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>):
      <ul>
        <li>Запрос предоставляет контекстную информацию через <code>metaInfo</code> (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
        <li>Через <code>cancellationHandler.IsCanceled()</code> или регистрацию функции уведомления с помощью <code>cancellationHandler.SetNotifier()</code> приложение может обработать преждевременное прерывание диалога (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
        <li>Метод возвращает <code>ara::core::Future</code> со структурой <code>ReadOutput</code> (<a class="spec-record-ref" data-req="SWS_DM_02154" href="../spec/record.html?id=SWS_DM_02154">[SWS_DM_02154]</a>, <a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>). Если на момент запроса данные недоступны, реализация должна всегда возвращать значение и заполнять данные шаблоном заполнения (например, <code>0xFF</code>) (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
      </ul>
    </li>
    <li><strong>Отзыв предложения сервиса:</strong> перед завершением работы или в состояниях технического обслуживания приложение вызывает <code>StopOffer()</code>, чтобы остановить пересылку запросов (<a class="spec-record-ref" data-req="SWS_DM_02153" href="../spec/record.html?id=SWS_DM_02153">[SWS_DM_02153]</a>).</li>
  </ol>

  <h4>Сценарии ошибок</h4>
  <p>Условия ошибок и нарушения сопоставлены соответствующим фазам:</p>
  <ul>
    <li><strong>Нарушения при конструировании:</strong> недействительные связи модели приводят к определенным сообщениям об ошибках (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>):
      <ul>
        <li><code>InstanceSpecifierMappingIntegrityViolation</code>: идентификатор не может быть разрешен в контексте Executable или не ссылается на <code>PortPrototype</code> (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
        <li><code>PortInterfaceMappingViolation</code>: на порт, типизированный с помощью <code>DiagnosticExtendedDataRecordInterface</code>, не ссылается <code>DiagnosticDataPortMapping</code> (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
        <li><code>ProcessMappingViolation</code>: для процесса времени выполнения не существует подходящего смоделированного процесса (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
        <li><code>InstanceSpecifierAlreadyInUseViolation</code>: идентификатор уже используется в процессе другим экземпляром (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
      </ul>
    </li>
    <li><strong>Ошибка при регистрации сервиса:</strong> повторный вызов <code>Offer()</code> для уже предложенного экземпляра завершается сбоем с кодом ошибки <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>).</li>
