Контекст

Класс ara::fw::FwErrorDomain представляет специфический домен ошибок для модуля Firewall (fw) в рамках AUTOSAR Adaptive Platform. Являясь специализацией абстрактного базового класса ara::core::ErrorDomain, он интегрирует состояния ошибок Firewall в единую общеплатформенную модель ошибок. Через псевдоним типа Errc класс ссылается на перечисление FwErrc [AP_SWS_Fw_83007], которое отображает множество определенных в модуле кодов ошибок. Кроме того, псевдоним Exception подключает соответствующий тип исключения FwException [AP_SWS_Fw_83008].

В архитектуре программного обеспечения ara::fw::FwErrorDomain берет на себя однозначное сопоставление числовых кодов ошибок со специфичной для Firewall контекстной информацией. Благодаря этому вышестоящие прикладные уровни или сервисы платформы могут идентифицировать и обрабатывать ошибки модуля на основе имени домена.

Жизненный цикл

Управление жизненным циклом ara::fw::FwErrorDomain устроено так, что экземпляры не создаются произвольно во время выполнения. Конструктор по умолчанию явно удален (FwErrorDomain() = delete;) [AP_SWS_Fw_83009]. Интерпретация: класс, вероятно, предоставляется внутри процесса как долгоживущий статический синглтон, к которому компоненты приложения обращаются через глобальную функцию получения экземпляра.

Что касается многопоточности, соответствующие операции запроса и выполнения специфицированы как потокобезопасные. Как определение имени домена с помощью Name() [AP_SWS_Fw_83010], так и текстовое разрешение кодов ошибок через Message() [AP_SWS_Fw_83011] и преобразование в исключения посредством ThrowAsException() [AP_SWS_Fw_83012] гарантируют потокобезопасность. Несколько параллельных потоков могут вызывать эти методы без внешней синхронизации.

Путь использования

Типичный сценарий использования возникает, когда операция подсистемы Firewall завершается сбоем и необходимо создать или проверить объект ошибки:

  • Разрешение имени: с помощью метода Name() запрашивается идентификатор домена ошибок [AP_SWS_Fw_83010], что используется, в частности, при журналировании и анализе ошибок.
  • Разрешение текста ошибки: на основе переданного значения ошибки (CodeType) Message() возвращает описательное текстовое сообщение в виде const char* [AP_SWS_Fw_83011]. Предположительно, реализация при этом опирается на значения перечисления FwErrc.
  • Возбуждение исключения: если код ошибки требуется преобразовать в исключение, это выполняется через ThrowAsException() [AP_SWS_Fw_83012].

Диаграмма последовательности: типичный процесс проверки ошибок и опциональной генерации исключений. Источники: [AP_SWS_Fw_83010], [AP_SWS_Fw_83011], [AP_SWS_Fw_83012].

Сценарии ошибок

В рамках обработки ошибок ara::fw::FwErrorDomain служит посредником между кодами ошибок на основе возвращаемых значений и исключениями C++. Методы Name() [AP_SWS_Fw_83010] и Message() [AP_SWS_Fw_83011] объявлены с noexcept и сами ни при каких обстоятельствах не генерируют исключений.

В отличие от этого, ThrowAsException() явно определен как noexcept(false) и классифицирован как небезопасный относительно исключений (not exception safe) [AP_SWS_Fw_83012]. Метод создает из переданного экземпляра ara::core::ErrorCode объект исключения типа FwException (псевдоним типа Exception [AP_SWS_Fw_83008]) и генерирует его. Интерпретация: этот вызов, вероятно, служит стандартизированным мостом эскалации для уровней программного обеспечения, которые предпочитают поток управления на основе исключений структурам ошибок на основе возвращаемых значений.

<h4>Жизненный цикл</h4>
<p>Управление жизненным циклом <code>ara::fw::FwErrorDomain</code> устроено так, что экземпляры не создаются произвольно во время выполнения. Конструктор по умолчанию явно удален (<code>FwErrorDomain() = delete;</code>) <a class="spec-record-ref" data-req="AP_SWS_Fw_83009" href="../spec/record.html?id=AP_SWS_Fw_83009">[AP_SWS_Fw_83009]</a>. Интерпретация: класс, вероятно, предоставляется внутри процесса как долгоживущий статический синглтон, к которому компоненты приложения обращаются через глобальную функцию получения экземпляра.</p>
<p>Что касается многопоточности, соответствующие операции запроса и выполнения специфицированы как потокобезопасные. Как определение имени домена с помощью <code>Name()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83010" href="../spec/record.html?id=AP_SWS_Fw_83010">[AP_SWS_Fw_83010]</a>, так и текстовое разрешение кодов ошибок через <code>Message()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83011" href="../spec/record.html?id=AP_SWS_Fw_83011">[AP_SWS_Fw_83011]</a> и преобразование в исключения посредством <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83012" href="../spec/record.html?id=AP_SWS_Fw_83012">[AP_SWS_Fw_83012]</a> гарантируют потокобезопасность. Несколько параллельных потоков могут вызывать эти методы без внешней синхронизации.</p>

<h4>Путь использования</h4>
<p>Типичный сценарий использования возникает, когда операция подсистемы Firewall завершается сбоем и необходимо создать или проверить объект ошибки:</p>
<ul>
<li><strong>Разрешение имени:</strong> с помощью метода <code>Name()</code> запрашивается идентификатор домена ошибок <a class="spec-record-ref" data-req="AP_SWS_Fw_83010" href="../spec/record.html?id=AP_SWS_Fw_83010">[AP_SWS_Fw_83010]</a>, что используется, в частности, при журналировании и анализе ошибок.</li>
<li><strong>Разрешение текста ошибки:</strong> на основе переданного значения ошибки (<code>CodeType</code>) <code>Message()</code> возвращает описательное текстовое сообщение в виде <code>const char*</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83011" href="../spec/record.html?id=AP_SWS_Fw_83011">[AP_SWS_Fw_83011]</a>. Предположительно, реализация при этом опирается на значения перечисления <code>FwErrc</code>.</li>
<li><strong>Возбуждение исключения:</strong> если код ошибки требуется преобразовать в исключение, это выполняется через <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83012" href="../spec/record.html?id=AP_SWS_Fw_83012">[AP_SWS_Fw_83012]</a>.</li>
</ul>

<h4>Сценарии ошибок</h4>
<p>В рамках обработки ошибок <code>ara::fw::FwErrorDomain</code> служит посредником между кодами ошибок на основе возвращаемых значений и исключениями C++. Методы <code>Name()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83010" href="../spec/record.html?id=AP_SWS_Fw_83010">[AP_SWS_Fw_83010]</a> и <code>Message()</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83011" href="../spec/record.html?id=AP_SWS_Fw_83011">[AP_SWS_Fw_83011]</a> объявлены с <code>noexcept</code> и сами ни при каких обстоятельствах не генерируют исключений.</p>
<p>В отличие от этого, <code>ThrowAsException()</code> явно определен как <code>noexcept(false)</code> и классифицирован как небезопасный относительно исключений (not exception safe) <a class="spec-record-ref" data-req="AP_SWS_Fw_83012" href="../spec/record.html?id=AP_SWS_Fw_83012">[AP_SWS_Fw_83012]</a>. Метод создает из переданного экземпляра <code>ara::core::ErrorCode</code> объект исключения типа <code>FwException</code> (псевдоним типа <code>Exception</code> <a class="spec-record-ref" data-req="AP_SWS_Fw_83008" href="../spec/record.html?id=AP_SWS_Fw_83008">[AP_SWS_Fw_83008]</a>) и генерирует его. Интерпретация: этот вызов, вероятно, служит стандартизированным мостом эскалации для уровней программного обеспечения, которые предпочитают поток управления на основе исключений структурам ошибок на основе возвращаемых значений.</p>
