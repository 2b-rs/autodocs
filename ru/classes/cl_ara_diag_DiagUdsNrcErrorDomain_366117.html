Контекст

Класс [SWS_DM_00529] ara::diag::DiagUdsNrcErrorDomain представляет стандартизированный домен ошибок для диагностических ошибок, поступающих из различных классов диагностики и интерфейсов AUTOSAR Adaptive Platform. Согласно [SWS_DM_00529] он наследуется от базового класса ara::core::ErrorDomain и выступает основным связующим звеном между прикладными диагностическими процедурами и Diagnostic Management (DM).

В общей системе домен ошибок взаимодействует на интерфейсах трёх ключевых компонентов:

  • Diagnostic Server (DM): экземпляр, который обрабатывает диагностические запросы автомобильного диагностического тестера, проверяет условия окружения и формирует стандартные ответы UDS.
  • Внешнее диагностическое приложение: прикладная логика или внешний диагностический процессор, реализующий специфичные для автомобиля диагностические службы и возвращающий результаты или ошибки через интерфейсы ara::diag.
  • Диагностический клиент (тестер): внешнее диагностическое устройство, которое отправляет диагностические команды в блок управления и при возникновении ошибок ожидает стандартизированные отрицательные ответы (Negative Response Codes, NRC).

Если диагностическое приложение возвращает через интерфейс ara::diag результат с ошибкой домена ara::diag::DiagUdsNrcErrorDomain, Diagnostic Server целенаправленно обрабатывает эту ошибку: он выводит из переданного кода ошибки UDS Negative Response Code [SWS_DM_02059] и передает отрицательный ответ с этим кодом диагностическому клиенту [SWS_DM_02060]. Кроме того, домен взаимодействует с проверкой конфигурируемых условий окружения: если извлечение элемента данных завершается сбоем из-за ошибки этого домена, сервер классифицирует условие как невыполненное и отправляет сообщение журнала и трассировки [SWS_DM_00970].

Контекстная диаграмма: встраивание домена ошибок во взаимодействие между тестером, Diagnostic Server и приложением. Источники: [SWS_DM_02059], [SWS_DM_02060], AUTOSAR_AP_SWS_Diagnostics с. 144

Жизненный цикл

Жизненный цикл ara::diag::DiagUdsNrcErrorDomain следует требованиям к доменам ошибок платформы без сохранения состояния:

  • Создание и инициализация: класс предоставляет конструктор по умолчанию без параметров, определенный как constexpr и noexcept [SWS_DM_00532]. Интерпретация: экземпляры DiagUdsNrcErrorDomain создаются как долгоживущие константы или объекты-одиночки во время компиляции или загрузки, чтобы оставаться доступными на протяжении всего времени выполнения процесса.
  • Отношения владения: приложения, как правило, не создают динамические экземпляры в куче, а ссылаются на домен через константные ссылки при типизации значений ara::core::ErrorCode.
  • Состояния и переходы: домен не имеет изменяемых внутренних состояний и не требует переходов между состояниями. Наблюдающие запросы, такие как Name() [SWS_DM_00533] или Message() [SWS_DM_00534], функционируют детерминированно и без сохранения состояния.
  • Конкурентность: все функции-члены — конструктор [SWS_DM_00532], Name() [SWS_DM_00533], Message() [SWS_DM_00534], а также ThrowAsException() [SWS_DM_00535] — явно специфицированы как потокобезопасные. Их можно параллельно вызывать из различных контекстов выполнения без дополнительных блокировок.

Путь использования

Стандартная последовательность действий при сигнализации диагностических ошибок делится на следующие шаги:

  1. Запрос службы: диагностический клиент отправляет сервисный запрос UDS в Diagnostic Server.
  2. Вызов диагностического приложения: Diagnostic Server делегирует обработку через типизированный интерфейс ara::diag соответствующему внешнему диагностическому процессору.
  3. Возврат ошибки: если диагностическое приложение обнаруживает недопустимое условие, оно создает код ошибки типа ara::diag::DiagUdsNrcErrorDomain::Errc [SWS_DM_00530] и возвращает его внутри ara::core::Result.
  4. Вывод NRC: если Diagnostic Server обнаруживает ошибку домена ara::diag::DiagUdsNrcErrorDomain, он выводит из значения DiagUdsNrcErrc UDS Negative Response Code [SWS_DM_02059]. Обычно это происходит путем приведения типа (static_cast) к 1-байтовому значению в допустимом диапазоне от 0x01 до 0xFE [SWS_DM_02059].
  5. Протокольный ответ: Diagnostic Server формирует отрицательный ответ UDS с определенным кодом ошибки и отправляет его клиенту [SWS_DM_02060].
  6. Разрешение текста ошибки: для диагностических протоколов или системных сообщений описание ошибки можно запросить через Message(), которая всегда возвращает действительный указатель на текст [SWS_DM_00534].

Диаграмма последовательности: распространение ошибки и вывод UDS-NRC при неудачной диагностической операции. Источники: [SWS_DM_02059], [SWS_DM_02060]

Сценарии ошибок

Для контролируемой обработки ошибочных состояний класс предоставляет специализированные типы и механизмы преобразования:

  • Перечисление кодов ошибок: псевдоним типа Errc указывает на перечисление DiagUdsNrcErrc [SWS_DM_00530]. Интерпретация: значения перечисления отражают стандартизированные UDS Negative Response Codes. Допустимые значения для вывода находятся в диапазоне от 0x01 до 0xFE [SWS_DM_02059].
  • Отображение исключений: псевдоним Exception указывает на DiagUdsNrcException [SWS_DM_00531]. С помощью ThrowAsException() [SWS_DM_00535] код ошибки может быть преобразован в соответствующее исключение и выброшен. Если исключения C++ отключены в наборе инструментов сборки, эта функция не участвует в разрешении перегрузок [SWS_DM_00535].
  • Ошибка при извлечении элемента данных: если извлечение элемента данных внешним процессором приводит к ошибке домена ara::diag::DiagUdsNrcErrorDomain, диагностический менеджмент рассматривает соответствующую часть формулы условия окружения как невыполненную и инициирует сообщение журнала и трассировки [SWS_DM_00970].
  • Поведение при мульти-DID-запросах: наличие ara::diag::DiagUdsNrcErrorDomain в результате сигнализирует об отрицательном промежуточном результате внешнего процессора. Однако при запросах к нескольким DID единичная ошибка не обязательно приводит к общему отрицательному ответу, если в активном сеансе поддерживается хотя бы один DID (AUTOSAR_AP_SWS_Diagnostics §7.3.x с. 160).

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform версии R25-11.
