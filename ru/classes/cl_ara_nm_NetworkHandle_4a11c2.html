Позволяет State Management запрашивать и отслеживать состояния связи логических и физических сетей.

ara::nm::NetworkHandle представляет собой перемещаемый некопируемый объект доступа, с помощью которого State Management через идентификатор экземпляра запрашивает и отслеживает состояние связи сетей [SWS_ANM_01000], [SWS_ANM_01001]. Наряду с синхронными запросами статуса класс позволяет устанавливать запросы, а также регистрировать уведомители для фактических или запрошенных состояний [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]. Отсутствие доступности службы или ошибочные уведомители при этом сообщаются через стандартизированные коды ошибок в объекте результата.

Контекст

Класс ara::nm::NetworkHandle функционирует в модуле nm как стандартизированный объект доступа для конкретного логического или физического сетевого дескриптора, адресуемого через ara::core::InstanceSpecifier прототипа порта [SWS_ANM_01000], [SWS_ANM_01001]. Основным пользователем этого интерфейса является функциональный State Management (SM), заявляющий и отслеживающий через дескриптор потребность в связи для Partial Network Cluster (PNC), VLAN или физических сетей [SWS_ANM_01000], [SWS_ANM_01009]. В качестве промежуточного слоя объект инкапсулирует взаимодействие между запрашивающей функциональной группой и базовой подсистемой NM.

Контекстная диаграмма: встраивание NetworkHandle между State Management и управлением сетью. Источники: [SWS_ANM_01000], [SWS_ANM_01001], [SWS_ANM_01009], [SWS_ANM_01010], [SWS_ANM_01020], [SWS_ANM_01007]

Жизненный цикл

ara::nm::NetworkHandle инстанцируется явно с указанием действительного ara::core::InstanceSpecifier для NetworkManagementPortInterface; этот конструктор специфицирован как потокобезопасный [SWS_ANM_01001]. Экземпляр обладает семантикой эксклюзивности: конструктор копирования и оператор присваивания с копированием явно удалены (= delete) [SWS_ANM_01005], [SWS_ANM_01006]. Класс поддерживает семантику перемещения через конструктор перемещения и оператор присваивания с перемещением, при этом присваивание не является потокобезопасным [SWS_ANM_01003], [SWS_ANM_01004].

Уничтожение выполняется через непотокобезопасный деструктор ~NetworkHandle() [SWS_ANM_01002]. Зарегистрированные до уничтожения уведомители, предположительно, должны быть дерегистрированы приложением во избежание асинхронных обращений к недействительным контекстам (интерпретация). Что касается сетевых состояний, дескриптор отображает две элементарные ступени через перечисление NetworkStateType: kNoCom (как минимум одна сопоставленная сеть не находится в состоянии полной связи) и kFullCom (все сопоставленные сети активны) [SWS_ANM_01358].

Путь использования

Штатный процесс включает инстанцирование, опциональную регистрацию уведомителей, запрос сетевого состояния, а также последующее освобождение:

  • Инстанцирование: создание дескриптора с помощью идентификатора экземпляра [SWS_ANM_01001].
  • Регистрация наблюдателей: регистрация функций обратного вызова типа NetworkStateChangeNotifier [SWS_ANM_01020] либо для фактического эффективного состояния через RegisterNetworkStateChangeNotifier [SWS_ANM_01010], либо для запрошенного состояния через RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]. Оба метода существуют также в виде шаблонного варианта для указания пользовательского контекста выполнения (ExecutorT) [SWS_ANM_01014], [SWS_ANM_01015]. На один дескриптор может быть активен максимум один уведомитель каждой категории.
  • Запрос состояния: запрос полной связи (NetworkStateType::kFullCom) или освобождения (NetworkStateType::kNoCom) через SetNetworkRequestedState [SWS_ANM_01009].
  • Опрос состояния: синхронное считывание текущего запрошенного состояния с помощью GetNetworkRequestedState [SWS_ANM_01008] или фактически действующего состояния сети с помощью GetNetworkState [SWS_ANM_01007]. Оба запроса потокобезопасны.
  • Очистка: явная отмена регистрации обработчиков обратного вызова через UnregisterNetworkStateChangeNotifier [SWS_ANM_01011] и UnregisterNetworkRequestedStateChangeNotifier [SWS_ANM_01013].

Диаграмма последовательности: типичный сценарий использования для регистрации уведомителей, запроса состояния и опроса. Источники: [SWS_ANM_01001], [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]

Сценарии ошибок

Вызовы методов для NetworkHandle сигнализируют об ошибках через ara::core::Result. Специфицированы следующие случаи ошибок:

  • NmErrc::kServiceNotAvailable: возникает при SetNetworkRequestedState [SWS_ANM_01009], GetNetworkRequestedState [SWS_ANM_01008] и GetNetworkState [SWS_ANM_01007], если базовая служба управления сетью недоступна или не отвечает.
  • NmErrc::kInvalidHandler: возвращается методами регистрации уведомителей [SWS_ANM_01010], [SWS_ANM_01012], [SWS_ANM_01014], [SWS_ANM_01015], если передана недействительная функция-обработчик или уведомитель уже зарегистрирован.

Что касается параллелизма, операции чтения состояния GetNetworkState и GetNetworkRequestedState потокобезопасны, тогда как модифицирующие операции, а также регистрации не являются потокобезопасными и требуют внешней синхронизации [SWS_ANM_01007], [SWS_ANM_01008], [SWS_ANM_01009], [SWS_ANM_01010].

Использование и жизненный цикл

Класс NetworkHandle функционирует как объект доступа к дескриптору сети, адресуемому через ara::core::InstanceSpecifier, и предназначен для State Management [SWS_ANM_01000]. Инстанцирование осуществляется путем передачи InstanceSpecifier прототипа порта NetworkManagementPortInterface [SWS_ANM_01001]. Поскольку класс объявлен как final, его нельзя использовать в качестве базового класса для наследования [SWS_ANM_01000].

Семантика перемещения и параллелизм

Объекты этого класса обладают чистой семантикой перемещения: конструктор копирования [SWS_ANM_01005], а также оператор присваивания с копированием [SWS_ANM_01006] удалены (= delete). Экземпляры вместо этого могут передаваться через конструктор перемещения [SWS_ANM_01003] и оператор присваивания с перемещением [SWS_ANM_01004].

В отношении потокобезопасности действуют следующие требования:

  • Конструктор с InstanceSpecifier является потокобезопасным (thread-safe) [SWS_ANM_01001].
  • Для конструктора перемещения потокобезопасность определена как зависящая от реализации (implementation-defined) [SWS_ANM_01003].
  • Деструктор [SWS_ANM_01002] и присваивание с перемещением [SWS_ANM_01004] явно указаны как не потокобезопасные (not thread-safe). Интерпретация: поскольку потокобезопасность не гарантируется, вызывающий контекст, вероятно, отвечает за внешнюю синхронизацию, если несколько потоков используют один и тот же дескриптор.

Обработка ошибок

Все конструкторы, операторы присваивания, а также деструктор объявлены как noexcept [SWS_ANM_01001], [SWS_ANM_01002], [SWS_ANM_01003], [SWS_ANM_01004]. Исключения или возвращаемые значения ошибок в этом интерфейсе класса не предусмотрены.

      Уведомитель находит применение при мониторинге сетевого управления через две точки регистрации:

В качестве альтернативы шаблонная перегрузка позволяет передавать пользовательский executor, в контексте которого выполняется уведомитель [SWS_ANM_01015]. На один экземпляр может быть активен максимум один уведомитель [SWS_ANM_01010].
        • 
    
      • Для уведомлений о запрашиваемом состоянии сети регистрация выполняется через RegisterNetworkRequestedStateChangeNotifier, на выбор напрямую [SWS_ANM_01012] или с указанием целевого исполнителя [SWS_ANM_01014]. Здесь также допускается максимум один обработчик [SWS_ANM_01012].

Это, по всей видимости, происходит главным образом тогда, когда передается не полностью инициализированный или пустой функциональный объект.

Поэтому вызывающие стороны должны гарантировать, что присваивание, а также регистрация осуществляются синхронизированно или последовательно.

Ее задача состоит в отмене нотификатора для изменений запрошенного состояния сети [SWS_ANM_01013], благодаря чему она способствует реализации вышестоящего требования RS_Nm_00051.
  
                                                                  
  
                                                                  
    Интерфейс не ожидает входных параметров и не возвращает значения (void) [SWS_ANM_01013]. Интерпретация: поскольку сигнатура не предусматривает асинхронного типа результата, вызов, вероятно, выполняется синхронно, а разрегистрация вступает в силу сразу после возврата функции.
  
                                                                  

  
                                                                  Обработка ошибок
                                                                  
  
                                                                  
    Функция специфицирована с noexcept [SWS_ANM_01013] и тем самым не генерирует исключений. В спецификации для вызывающей стороны не предусмотрено ни кодов ошибок, ни отдельных реакций на ошибки.
  
                                                                  

  
                                                                  Параллелизм и ограничения
