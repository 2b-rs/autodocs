класс apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

Библиография SWS Diagnostics: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

Использование по назначению

UdsTransportProtocolMgr управляет взаимодействием между экземплярами Diagnostic Server и транспортными протоколами UDS, например DoIP или CAN. Он предоставляет Transport Handler стандартизированный интерфейс для приёма сообщений, передачи уровню Session, подтверждений отправки и восстановления канала. [SWS_DM_00306]

Принятие и владение сообщениями

Обработчик сообщает о начале полученного сообщения с помощью IndicateMessage(), включая адреса источника и назначения, тип адреса, глобальный идентификатор канала, размер и фрагмент полезной нагрузки, действительный только во время вызова. Если DM может обработать запрос, он возвращает kIndicationOk и память, принадлежащую UdsMessagePtr. В случае занятости, нехватки ресурсов или неизвестного адреса назначения kIndicationOccupied, kIndicationOverflow или kIndicationUnknownTargetAddress предоставляются с нулевыми указателями. [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

После заполнения возвращенного объекта сообщения обработчик передает его на уровень сеанса через HandleMessage(); При этом право собственности возвращается к общему ядру DM. Если IndicateMessage() не предоставил kIndicationOk, HandleMessage() не может быть вызван. Если произошла преждевременная ошибка транспортировки, объект возвращается с NotifyMessageFailure(). [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

Жизненный цикл и передача

TransmitConfirmation() сообщает kTransmitOk или kTransmitFailed для передачи, запрошенной DM посредством UdsTransportProtocolHandler::Transmit(). PeriodicTransmitConfirmation() подтверждает упорядоченный список периодически отправляемых сообщений вместе с числом успешно отправленных элементов. [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

DM может обрабатывать восстановление канала только после запуска соответствующего обработчика. После его остановки не допускается никакой другой вызов менеджера, кроме HandlerStopped(); DM ожидает этого обратного вызова, прежде чем завершить процесс. [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

функция HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

Библиография SWS Diagnostics: [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org

HandleMessage передает правильно полученное сообщение UDS (в настоящее время только запросы) с транспортного уровня на сеансовый уровень и соответствует T_Data.ind из ISO 14229-2, рисунок 2; поведение асинхронное, т.е. h. вызов должен вернуть «instantan», в то время как фактическая обработка выполняется асинхронно транспортным уровнем [SWS_DM_00311]. Вызывающая сторона возвращает право собственности на переданный UdsMessagePtr ядру управления общей диагностикой.
