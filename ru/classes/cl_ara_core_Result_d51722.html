класс ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

Использование по назначению

ara::core::Result<T,E> инкапсулирует для синхронных вызовов либо значение типа T, либо ошибку типа E; E должен быть ara::core::ErrorCode. Тем самым тип поддерживает обработку ошибок без исключений. [SWS_CORE_00701] [SWS_CORE_10600]

Создание & жизненный цикл

Результат может быть сгенерирован на основе значения или ошибки, а также с помощью FromValue() и FromError(). Операции копирования и перемещения доступны и требуют noexcept; тривиальность деструктора зависит от T и E. Взаимодействие с другими классами

HasValue(), Value(), Error(), Ok() и Err() предоставляют доступ к статусу и содержимому. Bind() преобразует содержащееся значение посредством Callable в новый Result, тогда как Resolve() вызывает функцию для случая ошибки. Ограничения & Обработка ошибок

Доступ к ошибкам без включенной ошибки или к значению без включенного значения определяется как нарушение. ValueOrThrow() может сработать и является единственной функцией Result, которую нельзя использовать без ara::core инициализации. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

Роль в пути безисключительных ошибок

Для исправимых ошибок интерфейсы должны использовать ara::core::Result или ara::core::Future; тип ошибки Result установлен на ara::core::ErrorCode. RS General §4.1.2 «Error handling» EXP InterfacesGuidelines §3.1.2 «Result»

При доступе без исключений вызывающая сторона проверяет HasValue(), затем считывает Value() или Error(). Эти Observers могут использоваться без C++-Exceptions; напротив, ValueOrThrow() — это явный переход к пути на основе Exceptions. EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result» RS General §4.1.3 «The use of noexcept»

Диаграмма активности: обычная процедура без исключений после HasValue() ветвится на значение или ошибку; ValueOrThrow() — факультативно показанный путь Exception. Источники: EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result».

Нормативное ядро: значение или ошибка

Спецификация Core сопоставляет Result с моделью обработки ошибок: для устранимых ошибок API должны возвращать либо Result, либо Future. Result таким образом отделяет нормальный путь значения от ошибки, передаваемой как значение данных. SWS Core §7.2 «Error handling» SWS Core §7.2.5.4 «Result»
