Предоставляет соответствующую стандарту, типобезопасную абстракцию битового поля фиксированного размера с гарантиями noexcept для Adaptive Core.

Шаблон класса ara::core::Bitset предоставляет адаптированную для AUTOSAR Adaptive реализацию std::bitset для битовых последовательностей фиксированного размера [SWS_CORE_01741]. Он предлагает комплексные операции для манипуляции битами, логических связок и оптимизированных преобразований в скалярные целочисленные типы со строгими гарантиями noexcept [SWS_CORE_01738]. Позиционные модификации сообщают о недопустимых индексах через ara::core::Result вместо исключений C++, тогда как преобразования обрабатывают ошибки переполнения детерминированно. Благодаря этому класс особенно подходит для ресурсоэффективных и отказоустойчивых функций электронных блоков управления (ECU).

Контекст

Шаблонный класс ara::core::Bitset предоставляет в рамках Adaptive Platform реализацию стандартного типа C++ std::bitset для последовательностей битов с фиксированной во время компиляции длиной N [SWS_CORE_01741]. В экосистеме AUTOSAR класс служит для высокопроизводительной и типобезопасной обработки битовых полей, масок состояния и регистров флагов на блоках управления. Он бесшовно интегрируется в систему типов модуля core, поддерживая платформозависимый тип ara::core::BasicString вместо std::basic_string [SWS_CORE_01749], [SWS_CORE_01751]. Кроме того, AUTOSAR расширяет стандартизированный интерфейс специализированными функциями преобразования в беззнаковые целочисленные типы фиксированной ширины, такие как std::uint8_t, std::uint16_t, std::uint32_t и std::uint64_t [SWS_CORE_01736], [SWS_CORE_01737], [SWS_CORE_01738], [SWS_CORE_01739].

Жизненный цикл

Создание экземпляра гибко осуществляется через несколько конструкторов. Конструктор по умолчанию инициализирует все N битов нулевыми значениями и объявлен как constexpr, а также noexcept [SWS_CORE_01713]. В качестве альтернативы bitset может быть инстанцирован из скалярного значения типа unsigned long long [SWS_CORE_01719] или на основе текста из ara::core::BasicString [SWS_CORE_01749] либо указателя на нуль-терминированную строку const CharT* [SWS_CORE_01750]. Конструктор копирования и конструктор перемещения присутствуют и определены как noexcept=default [SWS_CORE_01714], [SWS_CORE_01716]. Также предоставляются соответствующие операторы присваивания [SWS_CORE_01715], [SWS_CORE_01717]. Деструктор специфицирован как noexcept и потокобезопасный [SWS_CORE_01718]. С точки зрения параллелизма функции преобразования в целые числа также являются потокобезопасными [SWS_CORE_01736], [SWS_CORE_01737], тогда как модифицирующие доступы к одному и тому же экземпляру bitset должны синхронизироваться.

Путь использования

Типичный сценарий использования включает инстанцирование, последующую манипуляцию отдельными битами или битовыми масками, а также завершающее вычисление или преобразование битового поля:

  • Создание: bitset обычно создается с начальным значением [SWS_CORE_01719] или инициализируется конструктором по умолчанию [SWS_CORE_01713].
  • Манипуляция: отдельные биты можно изменять посредством позиционных вызовов set [SWS_CORE_01726], reset [SWS_CORE_01728] и flip [SWS_CORE_01731]. Для всего битового поля доступны варианты без параметров set [SWS_CORE_01725], reset [SWS_CORE_01727] и flip [SWS_CORE_01730], а также побитовые логические операторы и операторы сдвига, такие как operator&= [SWS_CORE_01720], operator|= [SWS_CORE_01721], operatorˆ= [SWS_CORE_01722], operator~ [SWS_CORE_01729], operator<<= [SWS_CORE_01723] и operator>>= [SWS_CORE_01724].
  • Вычисление: состояние можно запросить с помощью test [SWS_CORE_01743], operator[] [SWS_CORE_01732], [SWS_CORE_01733] или предикатов, таких как all [SWS_CORE_01744], any [SWS_CORE_01745], none [SWS_CORE_01746], а также count [SWS_CORE_01740].
  • Преобразование: для дальнейшей обработки содержимое битового поля может быть переведено в числовые типы фиксированной ширины, например с помощью to_uint32t [SWS_CORE_01738], или экспортировано в виде строки посредством to_string [SWS_CORE_01751].

Диаграмма последовательности: типичная последовательность взаимодействия при инициализации, манипуляции, вычислении и преобразовании bitset. Источники: [SWS_CORE_01719], [SWS_CORE_01726], [SWS_CORE_01730], [SWS_CORE_01743], [SWS_CORE_01738]

Сценарии ошибок

В отличие от std::bitset, ara::core::Bitset использует отказоустойчивую, детерминированную концепцию обработки ошибок без исключений (noexcept):

  • Выход за пределы диапазона при позиционном доступе: в манипулирующих функциях set(pos) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728] и flip(pos) [SWS_CORE_01731] используется возвращаемый тип Result<Bitset<N>&>. Если pos находится вне допустимого диапазона, возвращается IsoStdOutOfRangeViolation вместо std::out_of_range. Интерпретация: последовательное применение ara::core::Result и noexcept, вероятно, служит для соблюдения строгих требований отказа от исключений (no-exception) в критически важных для безопасности областях Adaptive Platform. Вопрос Q-322c53fff705bce6 (открытый) Функция проверки test(pos) при недопустимом pos также указывает на IsoStdOutOfRangeViolation [SWS_CORE_01743].
  • Недопустимые строки: при конструировании из ara::core::BasicString [SWS_CORE_01749] при pos > size() генерируется IsoStdOutOfRangeViolation, а при наличии символов, отличных от 0 или 1, — IsoStdInvalidArgumentViolation (вместо std::invalid_argument).
  • Числовое переполнение: если представленное состояние битов не может быть отображено в запрошенном целевом типе, функции преобразования to_uint8t [SWS_CORE_01736], to_uint16t [SWS_CORE_01737], to_uint32t [SWS_CORE_01738], to_uint64t [SWS_CORE_01739], to_ulong [SWS_CORE_01734] и to_ullong [SWS_CORE_01735] возвращают соответственно IsoStdOverflowErrorViolation вместо std::overflow_error.
  • Ограниченная безопасность исключений: в то время как большинство операций noexcept и безопасны относительно исключений, конструирование из указателей const CharT* [SWS_CORE_01750], а также экспорт посредством to_string [SWS_CORE_01751] явно классифицированы как небезопасные относительно исключений (not exception safe).

Настоящее руководство по классу основано на спецификации AUTOSAR Adaptive Release R25-11 и создано автоматически.

                                              Использование
                                              

                                              Функция-член none класса ara::core::Bitset служит для запроса состояния занятости битовой последовательности [SWS_CORE_01746]. Метод требует включения заголовка ara/core/bitset.h и имеет сигнатуру bool none () const noexcept; [SWS_CORE_01746]. Вызов выполняется синхронно и без параметров на существующем экземпляре. В отношении поведения спецификация ссылается на соответствующее использование в [bitset] [SWS_CORE_01746]; интерпретация: метод, вероятно, возвращает true тогда и только тогда, когда ни один бит в битовой последовательности не установлен (то есть все биты равны false), и false в противном случае. Вопрос Q-de8593251c7748d5 (открытый)
                                              


                                              Обработка ошибок и безопасность исключений
                                              

                                              Для none не определены ни коды ошибок, ни отдельные состояния ошибок. Согласно спецификации, функция объявлена как noexcept и имеет классификацию «безопасна относительно исключений» (exception safe) [SWS_CORE_01746]. Таким образом, в случае ошибки или во время выполнения исключения C++ не возникают.
                                              


                                              Параллелизм и ограничения
                                              

                                              Поскольку none объявлена как const [SWS_CORE_01746], вызов метода не модифицирует внутреннее состояние объекта.
