Контекст

Шаблонный класс ara::shwa::Accessor служит в модуле shwa типизированным и размерным посредником доступа к областям памяти, предоставляемым ara::shwa::Buffer. Через свои параметры шаблона он настраивает тип данных (DataT), размерность (Dimensions), режим доступа (AccessModeType, по умолчанию режим чтения), а также область памяти и аллокатор. Он инкапсулирует физические или виртуальные ресурсы буфера и предоставляет контролируемые интерфейсы чтения и записи.

При этом Accessor обычно взаимодействует со следующими участниками:

  • Приложение: создает Accessor, управляет монопольным владением им и инициирует доступ к данным или запросы свойств.
  • ara::shwa::Buffer: выступает в качестве фундамента памяти, на целостность которого опирается Accessor ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • TaskHandler: может опционально подключаться при инстанцировании для синхронизации задач выполнения или обработки, связанных с доступом к памяти ([AP_SWS_SHWA_00008]).

Контекстная диаграмма: отношения компонентов ara::shwa::Accessor с приложением, буфером и TaskHandler. Источники: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]

Жизненный цикл

Срок жизни и инстанцирование ara::shwa::Accessor подчиняются строгому контролю ресурсов и владения:

  • Создание: конструктор по умолчанию удален ([AP_SWS_SHWA_00002]). Экземпляры могут инстанцироваться исключительно через статические фабричные методы Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Они проверяют переданную ссылку на буфер, а также опциональные свойства (PropertyList) и в случае успеха возвращают ara::core::Result<std::unique_ptr<Accessor>>.
  • Владение и уничтожение: благодаря типу возвращаемого значения std::unique_ptr владение однозначно и монопольно привязывается к вызывающей стороне. Класс полностью исключает копирование и перемещение: как конструктор копирования ([AP_SWS_SHWA_00003]) и оператор присваивания с копированием ([AP_SWS_SHWA_00004]), так и конструктор перемещения ([AP_SWS_SHWA_00005]) и оператор присваивания с перемещением ([AP_SWS_SHWA_00006]) объявлены удаленными (delete). Удаление операций перемещения, по-видимому, преследует цель обеспечить жесткую привязку Accessor к его исходному месту и начальному буферу на протяжении всего его существования. Уничтожение происходит автоматически при освобождении std::unique_ptr.
  • Параллелизм: методы создания Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]), а также методы синхронного доступа Get ([AP_SWS_SHWA_00012]) и Set ([AP_SWS_SHWA_00011]) явно специфицированы как потокобезопасные. Напротив, операторы индексации operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) и методы свойств HasProperty ([AP_SWS_SHWA_00015]) и GetProperty ([AP_SWS_SHWA_00016]) не являются потокобезопасными и требуют внешней синхронизации при параллельном использовании.

Путь использования

Обычный процесс при использовании Accessor обычно включает следующие этапы:

  1. Вызов фабрики: приложение вызывает Create со ссылкой на существующий Buffer и опциональными конфигурациями или TaskHandler ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Результат проверяется на успешность, и содержащийся std::unique_ptr принимается.
  2. Запрос свойств: опционально приложение проверяет наличие определенных возможностей через HasProperty<PropertyT>() ([AP_SWS_SHWA_00015]) и считывает их с помощью GetProperty<PropertyT>() ([AP_SWS_SHWA_00016]).
  3. Доступ для записи: если AccessModeType предусматривает это, данные записываются в буфер через Set с указанием размерного индекса Id<Dimensions> ([AP_SWS_SHWA_00011]).
  4. Доступ для чтения: данные получаются потокобезопасно через Get ([AP_SWS_SHWA_00012]). Для прямого доступа по ссылке без потокобезопасности в качестве альтернативы можно использовать operator[] с Index-ID или последовательным индексом ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]), который возвращает типизированную ссылку ReferenceT ([AP_SWS_SHWA_00014]).
  5. Освобождение: при выходе из области действия вызывающая сторона уничтожает std::unique_ptr, тем самым завершая доступ.

Диаграмма последовательности: типичная последовательность вызовов для создания, настройки и использования ara::shwa::Accessor. Источники: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012], [AP_SWS_SHWA_00015], [AP_SWS_SHWA_00016]

Сценарии ошибок

Методы Accessor передают состояния ошибок через тип ShwaErrorCode в возвращаемом значении ara::core::Result:

  • ShwaErrorCode::kAccessorFailure: возникает при Create, если конструирование или использование Accessor является недопустимым ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • ShwaErrorCode::kIntegrityCorrupted: сообщается Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) и Set ([AP_SWS_SHWA_00011]), если структурная целостность выделенной буфером памяти нарушена или не может быть проверена.
  • ShwaErrorCode::kInvalidIndex: возникает при Get ([AP_SWS_SHWA_00012]) и Set ([AP_SWS_SHWA_00011]), если операция не может быть выполнена из-за недействительного индекса или отсутствующего начального значения.
  • ShwaErrorCode::kInvalidAccessMode: сигнализирует при Set ([AP_SWS_SHWA_00011]) о том, что установленный режим доступа не разрешает операции записи.
  • ShwaErrorCode::kResourceBusy: возвращается при Get ([AP_SWS_SHWA_00012]) и Set ([AP_SWS_SHWA_00011]), если ресурс временно занят.
  • ShwaErrorCode::kFeatureNotSupported: возникает при GetProperty, если запрошенное свойство не реализовано или не поддерживается ([AP_SWS_SHWA_00016]).

С точки зрения безопасности исключений Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]), а также HasProperty ([AP_SWS_SHWA_00015]) и GetProperty ([AP_SWS_SHWA_00016]) объявлены как безопасные относительно исключений (noexcept), тогда как операции доступа к данным Get ([AP_SWS_SHWA_00012]), Set ([AP_SWS_SHWA_00011]) и operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) считаются небезопасными относительно исключений.

<li><strong><code>ara::shwa::Buffer</code>:</strong> выступает в качестве фундамента памяти, на целостность которого опирается Accessor (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>).</li>
<li><strong><code>TaskHandler</code>:</strong> может опционально подключаться при инстанцировании для синхронизации задач выполнения или обработки, связанных с доступом к памяти (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>).</li>
</ul>

<h4>Жизненный цикл</h4>
<p>Срок жизни и инстанцирование <code>ara::shwa::Accessor</code> подчиняются строгому контролю ресурсов и владения:</p>
<ul>
<li><strong>Создание:</strong> конструктор по умолчанию удален (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00002" href="../spec/record.html?id=AP_SWS_SHWA_00002">[AP_SWS_SHWA_00002]</a>). Экземпляры могут инстанцироваться исключительно через статические фабричные методы <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>). Они проверяют переданную ссылку на буфер, а также опциональные свойства (<code>PropertyList</code>) и в случае успеха возвращают <code>ara::core::Result&lt;std::unique_ptr&lt;Accessor&gt;&gt;</code>.</li>
<li><strong>Владение и уничтожение:</strong> благодаря типу возвращаемого значения <code>std::unique_ptr</code> владение однозначно и монопольно привязывается к вызывающей стороне. Класс полностью исключает копирование и перемещение: как конструктор копирования (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00003" href="../spec/record.html?id=AP_SWS_SHWA_00003">[AP_SWS_SHWA_00003]</a>) и оператор присваивания с копированием (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00004" href="../spec/record.html?id=AP_SWS_SHWA_00004">[AP_SWS_SHWA_00004]</a>), так и конструктор перемещения (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00005" href="../spec/record.html?id=AP_SWS_SHWA_00005">[AP_SWS_SHWA_00005]</a>) и оператор присваивания с перемещением (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00006" href="../spec/record.html?id=AP_SWS_SHWA_00006">[AP_SWS_SHWA_00006]</a>) объявлены удаленными (<code>delete</code>). Удаление операций перемещения, по-видимому, преследует цель обеспечить жесткую привязку Accessor к его исходному месту и начальному буферу на протяжении всего его существования. Уничтожение происходит автоматически при освобождении <code>std::unique_ptr</code>.</li>
<li><strong>Параллелизм:</strong> методы создания <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>), а также методы синхронного доступа <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>) и <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>) явно специфицированы как потокобезопасные. Напротив, операторы индексации <code>operator[]</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00009" href="../spec/record.html?id=AP_SWS_SHWA_00009">[AP_SWS_SHWA_00009]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00010" href="../spec/record.html?id=AP_SWS_SHWA_00010">[AP_SWS_SHWA_00010]</a>) и методы свойств <code>HasProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00015" href="../spec/record.html?id=AP_SWS_SHWA_00015">[AP_SWS_SHWA_00015]</a>) и <code>GetProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>) не являются потокобезопасными и требуют внешней синхронизации при параллельном использовании.</li>
</ul>

<h4>Путь использования</h4>
<p>Обычный процесс при использовании <code>Accessor</code> обычно включает следующие этапы:</p>
<ol>
<li><strong>Вызов фабрики:</strong> приложение вызывает <code>Create</code> со ссылкой на существующий <code>Buffer</code> и опциональными конфигурациями или <code>TaskHandler</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>). Результат проверяется на успешность, и содержащийся <code>std::unique_ptr</code> принимается.</li>
<li><strong>Запрос свойств:</strong> опционально приложение проверяет наличие определенных возможностей через <code>HasProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00015" href="../spec/record.html?id=AP_SWS_SHWA_00015">[AP_SWS_SHWA_00015]</a>) и считывает их с помощью <code>GetProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>).</li>
<li><strong>Доступ для записи:</strong> если <code>AccessModeType</code> предусматривает это, данные записываются в буфер через <code>Set</code> с указанием размерного индекса <code>Id&lt;Dimensions&gt;</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>).</li>
<li><strong>Доступ для чтения:</strong> данные получаются потокобезопасно через <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>). Для прямого доступа по ссылке без потокобезопасности в качестве альтернативы можно использовать <code>operator[]</code> с Index-ID или последовательным индексом (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00009" href="../spec/record.html?id=AP_SWS_SHWA_00009">[AP_SWS_SHWA_00009]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00010" href="../spec/record.html?id=AP_SWS_SHWA_00010">[AP_SWS_SHWA_00010]</a>), который возвращает типизированную ссылку <code>ReferenceT</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00014" href="../spec/record.html?id=AP_SWS_SHWA_00014">[AP_SWS_SHWA_00014]</a>).</li>
<li><strong>Освобождение:</strong> при выходе из области действия вызывающая сторона уничтожает <code>std::unique_ptr</code>, тем самым завершая доступ.</li>
</ol>

<p>Методы <code>Accessor</code> передают состояния ошибок через тип <code>ShwaErrorCode</code> в возвращаемом значении <code>ara::core::Result</code>:</p>
<ul>
<li><code>ShwaErrorCode::kAccessorFailure</code>: возникает при <code>Create</code>, если конструирование или использование Accessor является недопустимым (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>).</li>
<li><code>ShwaErrorCode::kIntegrityCorrupted</code>: сообщается <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>) и <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>), если структурная целостность выделенной буфером памяти нарушена или не может быть проверена.</li>
<li><code>ShwaErrorCode::kInvalidIndex</code>: возникает при <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>) и <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>), если операция не может быть выполнена из-за недействительного индекса или отсутствующего начального значения.</li>
<li><code>ShwaErrorCode::kInvalidAccessMode</code>: сигнализирует при <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>) о том, что установленный режим доступа не разрешает операции записи.</li>
<li><code>ShwaErrorCode::kResourceBusy</code>: возвращается при <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>) и <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>), если ресурс временно занят.</li>
<li><code>ShwaErrorCode::kFeatureNotSupported</code>: возникает при <code>GetProperty</code>, если запрошенное свойство не реализовано или не поддерживается (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>).</li>
</ul>
<p>С точки зрения безопасности исключений <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>), а также <code>HasProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00015" href="../spec/record.html?id=AP_SWS_SHWA_00015">[AP_SWS_SHWA_00015]</a>) и <code>GetProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>) объявлены как безопасные относительно исключений (<code>noexcept</code>), тогда как операции доступа к данным <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>), <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>) и <code>operator[]</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00009" href="../spec/record.html?id=AP_SWS_SHWA_00009">[AP_SWS_SHWA_00009]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00010" href="../spec/record.html?id=AP_SWS_SHWA_00010">[AP_SWS_SHWA_00010]</a>) считаются небезопасными относительно исключений.</p>
