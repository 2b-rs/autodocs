Позволяет адаптивным приложениям формировать динамические списки доступа и шаблоны служб для диагностических служб.

Класс служит адаптивным приложениям для создания и конфигурации динамических списков доступа для диагностических служб [SWS_DM_01156]. После опционального предварительного выделения памяти он создает через такие методы, как MakeServiceBuilder, экземпляры для определения шаблонов отдельных идентификаторов служб или последовательностей байтов [SWS_DM_01164]. Все функции-члены объявлены как noexcept исключебно-безопасными, тогда как модифицирующие операции должны быть защищены со стороны приложения от параллельного доступа [SWS_DM_01163].

Контекст

Класс ara::diag::DiagnosticServiceDynamicAccessList служит адаптивному приложению (AA) для формирования динамического списка доступа (DynamicAccessList) для диагностических служб [SWS_DM_01156]. Он выступает в роли фабрики и модуля управления для шаблонов служб, создавая экземпляры DynamicAccessListDiagServiceBuilder [SWS_DM_01164], [SWS_DM_01165]. В архитектуре приложение напрямую взаимодействует со списком для определения правил доступа на основе идентификаторов служб (SID) или последовательностей байтов, которые образуют основу для динамического контроля доступа в диагностической подсистеме SWS Diagnostics §8.13.1 «Class: DiagnosticServiceDynamicAccessList».

Жизненный цикл

Экземпляры DiagnosticServiceDynamicAccessList создаются через конструктор по умолчанию без параметров [SWS_DM_01157]. Класс объявлен как final SWS Diagnostics §8.13.1 «Class: DiagnosticServiceDynamicAccessList». Он поддерживает полноценную семантику значений: объекты можно как копировать, так и перемещать, для чего предусмотрены соответствующие конструкторы копирования и перемещения [SWS_DM_01159], [SWS_DM_01160], а также операторы присваивания [SWS_DM_01161], [SWS_DM_01162]. После инициализации объект находится в состоянии приема шаблонов, пока в конце своего срока службы не будет очищен через деструктор [SWS_DM_01158].

С точки зрения параллелизма конструкторы (конструктор по умолчанию, конструкторы копирования и перемещения) явно специфицированы как потокобезопасные [SWS_DM_01157], [SWS_DM_01159], [SWS_DM_01160]. Напротив, все модифицирующие методы, такие как присваивания, резервирование памяти и создание билдеров, а также деструктор, определены как непотокобезопасные [SWS_DM_01161], [SWS_DM_01162], [SWS_DM_01163], [SWS_DM_01164], [SWS_DM_01165], [SWS_DM_01158]. Поэтому параллельный доступ к одному и тому же объекту требует синхронизации на стороне приложения.

Путь использования

Типичный процесс формирования динамического списка доступа к службам включает следующие фазы:

  • Предварительное выделение памяти: перед добавлением шаблонов служб приложение может предварительно зарезервировать память для всех ожидаемых шаблонов служб с помощью Reserve [SWS_DM_01163]. Передаваемые параметры numberOfServiceHeads и maxServiceHeadSize позволяют выполнить оценку необходимой памяти по наихудшему сценарию, чтобы минимизировать последующие динамические перераспределения.
  • Создание шаблонов: приложение вызывает MakeServiceBuilder для инициации шаблона диагностической службы. Это происходит либо на основе одного байта SID [SWS_DM_01164], либо на основе последовательности байтов serviceHead для более глубоких проверок шаблона [SWS_DM_01165].
  • Конфигурация шаблона: метод возвращает объект типа DynamicAccessListDiagServiceBuilder [SWS_DM_01164], который приложение затем конфигурирует.

Диаграмма последовательности: типичный процесс создания шаблона через DiagnosticServiceDynamicAccessList. Источники: [SWS_DM_01163], [SWS_DM_01164], [SWS_DM_01165]

Сценарии ошибок

Все открытые функции-члены и конструкторы класса объявлены как noexcept и гарантируют строгую исключебно-безопасность (exception safe) [SWS_DM_01157], [SWS_DM_01163], [SWS_DM_01164]. Ошибочные состояния в виде C++-исключений или возврата ara::core::Result с кодами ошибок на этом интерфейсе не возникают. При резервировании памяти через Reserve указанное значение может быть приблизительной оценкой; занижение оценки не приводит к аварийному завершению функции, однако, вероятно, потребует повторных выделений памяти впоследствии [SWS_DM_01163]. Разработчики приложений должны гарантировать, что непотокобезопасные функции Reserve, MakeServiceBuilder и операторы присваивания никогда не выполняются одновременно над одним и тем же объектом без внешней блокировки.

Настоящее руководство основано на стандарте AUTOSAR версии R25-11 и обобщает спецификацию класса ara::diag::DiagnosticServiceDynamicAccessList.

              Использование
              

              Синхронная функция MakeServiceBuilder класса ara::diag::DiagnosticServiceDynamicAccessList служит адаптивному приложению для инициализации шаблона для динамического списка доступа (DynamicAccessList) через один идентификатор сервиса (sid) ([SWS_DM_01164]). Она принимает параметр sid типа DynamicAccessListDiagServiceBuilder::Byte и возвращает новый экземпляр DynamicAccessListDiagServiceBuilder ([SWS_DM_01164]). Посредством этого вызова приложение указывает экземпляру Diagnostic Server построить новый DynamicAccessList, начиная с переданного однобайтового шаблона ([SWS_DM_01218]; AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 «DynamicAccessList Creation and Update»).
              


              Взаимодействие и альтернативы
              

              После запуска динамический список доступа всех клиентов по умолчанию пуст ([SWS_DM_01214]). Помимо этой функции приложению доступна перегрузка со строкой байтов (serviceHead) ([SWS_DM_01165]). Обе перегрузки представляют собой точку входа, с помощью которой инициируется создание нового списка доступа на сервере ([SWS_DM_01218]).
              


              Обработка ошибок и параллелизм
              

              Интерфейс объявлен как noexcept и специфицирован как безопасный относительно исключений (exception safe) ([SWS_DM_01164]). Он не генерирует исключений и не возвращает кодов ошибок; ошибочные идентификаторы сервисов, следовательно, скорее всего, будут обнаружены только при последующей оценке шаблона сервером Diagnostic Server. В отношении конкурентности функция явно классифицирована как непотокобезопасная (not thread-safe) ([SWS_DM_01164]). При параллельном доступе из нескольких контекстов выполнения вызывающее приложение должно обеспечить внешнюю синхронизацию.
