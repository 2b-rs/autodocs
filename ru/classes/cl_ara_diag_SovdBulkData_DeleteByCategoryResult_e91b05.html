Контекст

Структура C++ ara::diag::SovdBulkData::DeleteByCategoryResult является частью AUTOSAR Adaptive Platform в модуле diag [SWS_DM_01926]. Она служит специальным типом возвращаемого значения для метода «Delete All Bulk Data Defined by Category» в рамках сервисного интерфейса ara::diag::SovdBulkData AUTOSAR_AP_SWS_Diagnostics §8.53.3 «Struct: DeleteByCategoryResult». Функциональная мотивация вытекает из вышестоящего требования RS_Diag_04266.

Основная обязанность DeleteByCategoryResult заключается в инкапсуляции общего результата категориального группового удаления массивов данных SOVD (Service-Oriented Vehicle Diagnostics Bulk Data). Поскольку такая массовая операция может распространяться на множество отдельных наборов данных, структура агрегирует соответствующие частичные результаты. К ее партнерам по взаимодействию относятся вызывающее диагностическое приложение (клиент), предоставляющий диагностический интерфейс SovdBulkData, а также агрегированные типы информации BulkDataMetaDataDescriptor и DeletionError, представляющие отдельные результаты.

Контекстная диаграмма: встраивание DeleteByCategoryResult во взаимодействие между приложением, SovdBulkData и структурами частичных результатов. Источники: [SWS_DM_01926], [SWS_DM_01842], [SWS_DM_01843].

Путь использования

Типичное использование DeleteByCategoryResult происходит в виде многоэтапного процесса очистки массивов данных:

  1. Инициация удаления: приложение вызывает на экземпляре SovdBulkData метод «Delete All Bulk Data Defined by Category» и передает желаемый идентификатор категории.
  2. Получение результирующей структуры: после выполнения приложение получает объект результата типа DeleteByCategoryResult [SWS_DM_01926].
  3. Оценка успешно удаленных элементов: вызывающая сторона обращается к переменной deleted_items [SWS_DM_01842]. Этот вектор типа ara::core::Vector<BulkDataMetaDataDescriptor> содержит дескрипторы всех экземпляров массивов данных, которые были успешно удалены из системы. Эта информация служит для обновления внутренних массивов данных или подтверждающих сообщений.
  4. Анализ неудавшихся удалений: затем приложение инспектирует переменную failed_items [SWS_DM_01843]. Вектор типа ara::core::Vector<DeletionError> перечисляет все экземпляры, для которых удаление завершилось неудачей, вместе с конкретными причинами ошибок.
  5. Управление последующими действиями: на основе сопоставления deleted_items и failed_items приложение принимает решение о протоколировании ошибок, повторных попытках или обратной связи с внешним диагностическим инструментом.

Сценарии ошибок

DeleteByCategoryResult реализует паттерн частичного успеха (Partial Success Pattern). Поскольку категория может охватывать несколько объектов массивов данных, частичная неудача не расценивается как общий сбой, а фиксируется дифференцированно:

  • Частичная ошибка: если определенные массивы данных не могут быть удалены из-за прав доступа, состояний блокировки или проблем с памятью, общий вызов не терпит сбоя. Затронутые элементы вносятся с указанием причины ошибки в failed_items [SWS_DM_01843], в то время как параллельно успешно удаленные записи остаются в deleted_items [SWS_DM_01842].
  • Полный успех: если все относящиеся к категории наборы данных удалось удалить без исключения, вектор failed_items пуст, а deleted_items перечисляет все удаленные дескрипторы.
  • Полная неудача: если не удалось удалить ни одного элемента категории, deleted_items остается пустым, а все обнаруженные экземпляры документируются в failed_items.
  • Пустая категория: если в указанной категории вообще не было сохранено массивов данных, вероятно, оба вектора (deleted_items и failed_items) возвращаются пустыми.
  • Предусловия и постусловия: предусловием для анализа является штатно завершенный вызов SovdBulkData. Постусловие состоит в том, что каждый элемент массивов данных, адресованный при выполнении, непересекающимся образом учтен либо в deleted_items, либо в failed_items.
