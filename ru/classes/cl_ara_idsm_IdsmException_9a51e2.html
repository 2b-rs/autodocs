Инкапсулирует коды ошибок интерфейсов IdsM в виде исключения C++ для структурированной обработки ошибок в приложениях.

Класс ara::idsm::IdsmException служит стандартизированным классом исключений C++ для представления ошибок программных интерфейсов IdsM [SWS_AIDSM_10704]. Он наследует от ara::core::Exception и инкапсулирует конкретный код ошибки для анализа первопричин. Инстанцирование выполняется через явный конструктор с ara::core::ErrorCode, который является потокобезопасным и гарантированно noexcept [SWS_AIDSM_10705]. Тем самым класс обеспечивает детерминированную и безопасную обработку исключений при сбойных операциях IdsM.

Контекст

Класс ara::idsm::IdsmException выполняет роль специализированного класса исключений для сигнализации и обработки ошибок программных интерфейсов Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10704]. Он определён в заголовке ara/idsm/idsm_error_domain.h и открыто наследует от базового класса ara::core::Exception [SWS_AIDSM_10704]. В рамках AUTOSAR Adaptive Platform класс взаимодействует преимущественно с использующими его функциональными кластерами, а также с интерфейсами модуля IdsM. Он предоставляет разработчикам стандартизированный механизм исключений C++ для структурированного перехвата ошибочных состояний вместо передачи сообщений об ошибках исключительно через возвращаемые значения.

Жизненный цикл

Инстанцирование ara::idsm::IdsmException осуществляется через явный конструктор, требующий передачи ara::core::ErrorCode [SWS_AIDSM_10705]. Этот конструктор объявлен со спецификатором noexcept, благодаря чему гарантируется, что во время конструирования объекта исключения не будут выброшены другие исключения [SWS_AIDSM_10705]. В отношении параллелизма конструирование явно специфицировано как потокобезопасное (thread-safe) [SWS_AIDSM_10705], поэтому объекты исключений могут безопасно создаваться без дополнительной синхронизации даже в многопоточных контекстах выполнения.

Являясь объектом исключения, IdsmException подчиняется типичной семантике значений C++. Создание происходит непосредственно при обнаружении ошибочного условия или при распаковке ошибочного результата операции. Время жизни связано с обработкой в соответствующем блоке catch; после его завершения объект исключения автоматически уничтожается исполняющей средой.

Путь использования

Типичное использование класса происходит в рамках синхронных вызовов служб IdsM. Приложение вызывает функцию модуля idsm. Если среда выполнения IdsM обнаруживает недопустимую операцию или внутреннюю ошибку, она формирует соответствующий ara::core::ErrorCode и инстанцирует с его помощью ara::idsm::IdsmException [SWS_AIDSM_10705]. Это исключение генерируется и прерывает штатный поток управления [SWS_AIDSM_10704].

Вызывающее приложение перехватывает объект конкретно как ara::idsm::IdsmException или обобщённо как ara::core::Exception. В обработчике исключений инкапсулированный код ошибки может быть извлечён и проанализирован для диагностического логирования, стратегий отката или детерминированных перезапусков.

Диаграмма последовательности: типичный ход обработки ошибок с помощью IdsmException при вызове API. Источники: [SWS_AIDSM_10704], [SWS_AIDSM_10705]

Сценарии ошибок

Класс ara::idsm::IdsmException служит для представления ошибок API IdsM и используется тогда, когда вызовы функций завершаются сбоем и это состояние передаётся через механизм исключений [SWS_AIDSM_10704]. Важным предусловием для создания является наличие допустимого объекта ara::core::ErrorCode, точно описывающего причину ошибки [SWS_AIDSM_10705].

Вторичное состояние ошибки во время создания объекта исключено благодаря гарантии noexcept конструктора [SWS_AIDSM_10705]. За счёт этого предотвращается аварийное завершение программы через std::terminate в и без того критических путях обработки ошибок. Постусловием вызова конструктора является инициализированный объект исключения, сохраняющий код ошибки в неизменном виде для дальнейшей диагностики.

Использование

Класс IdsmException служит центральным классом исключений для инкапсуляции и передачи ошибок API IdsM [SWS_AIDSM_10704]. Являясь специализацией ara::core::Exception, он переносит специфические для IdsM состояния ошибок и объявлен в заголовочном файле ara/idsm/idsm_error_domain.h [SWS_AIDSM_10704]. Инстанцирование выполняется явно через конструктор IdsmException(ara::core::ErrorCode errorCode), при этом должен передаваться подходящий объект ara::core::ErrorCode [SWS_AIDSM_10705].

Параллелизм и обработка ошибок

Конструктор IdsmException снабжен спецификатором noexcept, благодаря чему при инстанцировании самого объекта исключения гарантированно не возбуждаются другие исключения [SWS_AIDSM_10705]. Кроме того, конструктор специфицирован как потокобезопасный (thread-safe), что обеспечивает безопасность создания объектов исключений в параллельных или асинхронных контекстах выполнения [SWS_AIDSM_10705].

Взаимодействие и псевдонимы типов

Через тот же заголовочный файл ara/idsm/idsm_error_domain.h дополнительно доступен псевдоним типа using Exception = IdsmException; [SWS_AIDSM_10708]. Этот псевдоним функционирует как синонимичный идентификатор класса исключений в рамках домена ошибок IdsM и упрощает унифицированную обработку ошибок во взаимодействии с модулем IdsM [SWS_AIDSM_10708].
