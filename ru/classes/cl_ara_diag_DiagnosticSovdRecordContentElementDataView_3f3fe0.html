Предоставляет структурированное представление для управления и чтения диагностических записей SOVD на основе ключей.

Класс предоставляет структурированное представление записей SOVD типа RecordContentElementData для диагностики в Adaptive Platform (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView»). Он позволяет добавлять, считывать и администрировать примитивные и комплексные диагностические элементы на основе ключей с помощью потокобезопасных методов, таких как Add или operator[] ([SWS_DM_02288]). Предусловием для всех операций является то, что базовый элемент данных относится к требуемому типу Record, так как в противном случае вызовы завершаются с ошибкой в возвращаемом объекте Result.

Контекст

Класс ara::diag::DiagnosticSovdRecordContentElementDataView функционирует в контексте Service-Oriented Vehicle Diagnostics (SOVD) как структурированное представление (View) диагностического элемента данных типа RecordContentElementData или ContentData (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView», [SWS_DM_02270]). Он позволяет диагностическим приложениям и среде выполнения диагностики создавать, считывать и модифицировать наборы данных (Records) на основе полей, состоящие из пар «ключ-значение» ([SWS_DM_02288]). Партнерами по взаимодействию выступают, с одной стороны, диагностические сервисные реализации, которые предоставляют или потребляют диагностические данные, а с другой стороны — лежащие в основе обобщенные объекты-контейнеры типа DiagnosticSovdContentElementData. Через стандартизированные интерфейсы представление отделяет специфичную для приложения манипуляцию от физической формы хранения диагностического содержимого.

Жизненный цикл

Согласно своему назначению в качестве View, экземпляр, предположительно, хранит лишь ссылку на существующий объект данных типа DiagnosticSovdContentElementData (интерпретация). Отсюда следует, что время жизни адресуемой записи данных обязано полностью охватывать существование View во избежание недействительных ссылок. Все объявленные методы класса согласно спецификации спроектированы как потокобезопасные (thread-safe) и безопасные относительно исключений (exception safe) ([SWS_DM_02273], [SWS_DM_02288]). Жизненным циклом содержащихся в записи элементов данных можно управлять динамически: существующие элементы могут быть полностью удалены через Clear ([SWS_DM_02276]), целенаправленно стерты с помощью Remove по их ключу ([SWS_DM_02287]) или удалены из контейнера по итератору посредством Erase ([SWS_DM_02294]).

Путь использования

Типичный процесс использования включает подготовку памяти, добавление элементов, навигацию и считывание полей:

  • Подготовка памяти: чтобы предотвратить перераспределение памяти при известном количестве элементов, емкость можно заранее задать с помощью Reserve ([SWS_DM_02283]). Текущую емкость можно запросить через Capacity ([SWS_DM_02274]).
  • Заполнение записи данных: типизированные значения регистрируются с указанием ключа (key) через перегруженные операции Add. Поддерживаются примитивные типы данных, такие как std::int64_t ([SWS_DM_02288]), std::uint64_t ([SWS_DM_02289]), double ([SWS_DM_02290]), bool ([SWS_DM_02291]), и строковые значения через ara::core::StringView ([SWS_DM_02292]). Также могут добавляться вложенные диагностические элементы типа DiagnosticSovdContentElementData ([SWS_DM_02293]).
  • Проверка и опрос: перед доступом можно проверить контейнер на пустоту с помощью Empty ([SWS_DM_02275]) и узнать количество имеющихся элементов через Size ([SWS_DM_02273]). Существование ключа верифицируется посредством HasContentElement ([SWS_DM_02284]).
  • Доступ и итерация: доступ к конкретным элементам осуществляется либо напрямую через оператор индексации operator[], возвращающий ссылку на целевой элемент ([SWS_DM_02277], [SWS_DM_02278]), либо через метод поиска Find ([SWS_DM_02285], [SWS_DM_02286]). Для обхода доступны итераторы через Begin, End, CBegin и CEnd ([SWS_DM_02279], [SWS_DM_02280], [SWS_DM_02281], [SWS_DM_02282]).

Диаграмма последовательности: типичный процесс заполнения и считывания элемента SOVD Record. Источники: [SWS_DM_02283], [SWS_DM_02288], [SWS_DM_02277], [SWS_DM_02271].

Сценарии ошибок

Операции над записью данных подчиняются строгим предусловиям в отношении типа контейнера и валидности ключей:

  • Конфликты типов: все методы доступа, вставки и удаления предполагают, что базовый элемент имеет тип RecordContentElementData или ContentData. В противном случае такие операции, как Add ([SWS_DM_02288]), operator[] ([SWS_DM_02277]), HasContentElement ([SWS_DM_02284]) и Remove ([SWS_DM_02287]), завершаются ошибкой и возвращают ara::core::Result с состоянием ошибки.
  • Ненайденные ключи: доступ через operator[] или удаление через Remove возвращает ошибку, если запрошенный ключ не существует в записи данных ([SWS_DM_02277], [SWS_DM_02287]).
  • Недействительные итераторы при удалении: удаление по итератору через Erase при недействительных параметрах или некорректной привязке данных возвращает код ошибки DiagErrc::kInvalidArgument ([SWS_DM_02294]).
  • Явная обработка ошибок: помимо ошибок конкретных методов общее состояние записи данных может быть явно помечено как ошибочное через SetError с помощью ara::core::ErrorCode ([SWS_DM_02272]). Вызывающие стороны могут проверить наличие ошибки через HasError, который в случае сбоя возвращает соответствующий ara::diag::DiagSovdErrc ([SWS_DM_02271]).

Использование

Синхронная функция [SWS_DM_02288] вставляет целочисленное значение со знаком (std::int64_t) под указанным ключом key (ara::core::StringView) в структуру данных SOVD. Она объявлена как метод класса ara::diag::DiagnosticSovdRecordContentElementDataView и подключается через заголовочный файл ara/diag/diagnostic_sovd_content_element_data.h.

Предварительные условия и обработка ошибок

Согласно [SWS_DM_02288], базовый объект DiagnosticSovdContentElementData должен иметь тип RecordContentElementData или ContentData, в то время как добавляемый элемент сам по себе не должен быть ContentData. Функция определена как noexcept и возвращает ara::core::Result<void>. В случае сбоя операции — например, если целевой контейнер имеет несовместимый тип или элемент не может быть добавлен — результат содержит код ошибки; Интерпретация: предположительно, это типично и при коллизиях ключей.

Параллелизм и взаимодействие

Выполнение специфицировано как потокобезопасное и исключение-безопасное [SWS_DM_02288]. В интерфейсе существуют перегрузки с идентичной семантикой типов для беззнаковых целых чисел ([SWS_DM_02289]), чисел с плавающей точкой ([SWS_DM_02290]), логических значений ([SWS_DM_02291]), строк ([SWS_DM_02292]), а также вложенных элементов данных ([SWS_DM_02293]). Тот же метод дополнительно предоставляется в классе-носителе DiagnosticSovdContentElementData ([SWS_DM_02368]).

                                                                              Метод Reserve класса ara::diag::DiagnosticSovdRecordContentElementDataView ([SWS_DM_02283], AUTOSAR_AP_SWS_Diagnostics §8.60.11.1.1.20 «Reserve») синхронно резервирует требуемую емкость памяти для RecordContentElementData. Вызов предоставляется через заголовочный файл #include "ara/diag/diagnostic_sovd_content_element_data.h" и принимает параметр capacity типа std::size_t. В качестве возвращаемого значения функция возвращает void.
                                                                              

                                                                              Интерфейс объявлен как noexcept и специфицирован как исключебно-безопасный («exception safe») ([SWS_DM_02283]). Специфические коды ошибок или структуры ошибок не возвращаются. Интерпретация: если выделение требуемой емкости завершается неудачно, ошибка из-за отсутствия канала возврата, такого как ara::core::Result, вероятно, перехватывается внутри или приводит к аварийному завершению программы.
                                                                              

                                                                              Что касается параллелизма, функция определена как потокобезопасная («thread-safe») ([SWS_DM_02283]). Таким образом, её можно вызывать параллельно и без дополнительных мер синхронизации из нескольких потоков.
                                                                              

                                                                              Во взаимодействии со связанными интерфейсами вариант для массивов DiagnosticSovdArrayContentElementDataView::Reserve ([SWS_DM_02240]) ведёт себя аналогично. В отличие от него, DiagnosticSovdContentElementData::Reserve ([SWS_DM_02345]) возвращает ara::core::Result<void> для сообщения о конфликтах типов. Функция DiagnosticServiceDynamicAccessList::Reserve ([SWS_DM_01163]), напротив, служит для наихудшего предварительного выделения (worst-case) для шаблонов служб, ожидает два параметра и не является потокобезопасной.
