Контекст

Класс ara::diag::DiagnosticSovdRecordContentElementDataView ([SWS_DM_02270], SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView») представляет собой типизированное представление диагностического элемента содержимого (DiagnosticSovdContentElementData), организованного в виде структурированной записи. В рамках сервисно-ориентированной диагностики транспортных средств (SOVD) он служит интерфейсом для управления и манипулирования сопоставлениями «ключ — значение» внутри диагностического набора данных. В число его партнеров по взаимодействию входят вышестоящие диагностические приложения, базовые экземпляры DiagnosticSovdContentElementData, а также специализированные типы итераторов DiagnosticSovdRecordContentElementDataIterator и DiagnosticSovdRecordContentElementDataConstIterator ([SWS_DM_02279], [SWS_DM_02281]). Для типизированного заполнения класс предоставляет перегруженные операции Add, которые принимают как примитивные типы данных, такие как std::int64_t, std::uint64_t, double, bool и ara::core::StringView, так и вложенные объекты DiagnosticSovdContentElementData (с [SWS_DM_02288] по [SWS_DM_02293]).

Жизненный цикл

Являясь классом представления, DiagnosticSovdRecordContentElementDataView не владеет управляемыми данными сам (интерпретация: экземпляр служит легковесной оболочкой доступа к существующей структуре данных). Необходимым условием безошибочного использования представления является то, что базовый элемент, на который указывает ссылка, относится к типу RecordContentElementData или ContentData ([SWS_DM_02273], [SWS_DM_02288]). Внутреннее состояние отражает заполнение базовой записи: степень заполнения можно отслеживать с помощью Empty ([SWS_DM_02275]) и Size ([SWS_DM_02273]), в то время как Capacity ([SWS_DM_02274]) и Reserve ([SWS_DM_02283]) управляют выделением памяти. С помощью Clear ([SWS_DM_02276]) можно сбросить все элементы. Кроме того, состояние содержимого можно явно перевести в состояние ошибки с помощью SetError ([SWS_DM_02272]) или запросить через HasError ([SWS_DM_02271]). Что касается конкурентного выполнения, все функции-члены класса специфицированы как потокобезопасные (thread-safe) и безопасные относительно исключений (exception safe) (с [SWS_DM_02271] по [SWS_DM_02294]).

Путь использования

Типичный сценарий использования включает предварительное резервирование емкости, пошаговое заполнение записи и произвольный доступ к отдельным элементам полей:

  1. Резервирование емкости: перед вставкой нескольких значений с помощью Reserve предварительно резервируется предполагаемая требуемая емкость ([SWS_DM_02283]).
  2. Вставка элементов: с помощью типоспецифичных перегрузок Add элементы данных регистрируются с указанием ключа (с [SWS_DM_02288] по [SWS_DM_02293]).
  3. Проверка существования и поиск: с помощью HasContentElement можно проверить наличие ключа ([SWS_DM_02284]), либо через Find получить итератор на элемент ([SWS_DM_02285], [SWS_DM_02286]).
  4. Чтение или изменение значений: с помощью operator[] определяется ссылка на требуемый DiagnosticSovdContentElementData ([SWS_DM_02277], [SWS_DM_02278]).
  5. Удаление элементов: больше не требующиеся записи удаляются по ключу через Remove ([SWS_DM_02287]) или через итератор с помощью Erase ([SWS_DM_02294]).

Диаграмма последовательности: типичная последовательность действий для резервирования, заполнения и запроса элемента записи по ключу. Источники: [SWS_DM_02283], [SWS_DM_02292], [SWS_DM_02277].

Сценарии ошибок

Методы, потенциально способные завершиться с ошибкой, сигнализируют о сбоях через тип возвращаемого значения ara::core::Result:

  • Несовместимый тип данных базового экземпляра: если базовый экземпляр DiagnosticSovdContentElementData не относится к типу RecordContentElementData или ContentData, модифицирующие и опрашивающие операции, такие как Add, operator[], HasContentElement, Remove и Erase, завершаются с ошибкой в Result ([SWS_DM_02277], [SWS_DM_02284], [SWS_DM_02287], [SWS_DM_02288], [SWS_DM_02294]).
  • Недопустимый тип элемента при вставке: при попытке добавить дочерний элемент, который сам относится к типу ContentData, вызов Add завершается сбоем (с [SWS_DM_02288] по [SWS_DM_02293]).
  • Ключ не найден: в случае operator[], HasContentElement или Remove объект Result возвращает ошибку, если указанный ключ отсутствует в записи ([SWS_DM_02277], [SWS_DM_02284], [SWS_DM_02287]).
  • Недействительный итератор при Erase: если в Erase передается недействительный итератор, функция возвращает код ошибки DiagErrc::kInvalidArgument ([SWS_DM_02294]).
  • Установленная ошибка SOVD: если содержимое содержит код ошибки ([SWS_DM_02272]), установленный через SetError, HasError возвращает эту ошибку как ara::diag::DiagSovdErrc в Result ([SWS_DM_02271]).
