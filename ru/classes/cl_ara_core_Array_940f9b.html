Предоставляет последовательный контейнер фиксированного размера с типобезопасным контролем границ диапазона для AUTOSAR Adaptive.

Шаблонный класс ara::core::Array служит последовательным контейнером фиксированного размера для элементов типа T и адаптирует поведение std::array для приложений AUTOSAR Adaptive Platform. Вызывающие стороны инициализируют контейнер с фиксированным числом элементов, манипулируют содержимым с помощью таких методов, как fill(), и обращаются к элементам либо без проверки через operator[], либо с проверкой диапазона через at() к [SWS_CORE_01273]. В качестве существенного для безопасности граничного условия выход за пределы диапазона при at() вызывает специфическое нарушение IsoStdOutOfRangeViolation вместо std::out_of_range, в то время как вызовы front() или back() для пустых экземпляров завершаются ошибкой ещё на этапе компиляции [SWS_CORE_01267].

Контекст

Шаблонный класс ara::core::Array инкапсулирует последовательный контейнер со статически заданным во время компиляции размером N для элементов типа T. Он реализует стандартизированный тип std::array в модуле core AUTOSAR Adaptive Platform и представляет собой типобезопасную абстракцию для непрерывных блоков памяти. Благодаря предоставлению стандартизированных псевдонимов типов, таких как value_type ([SWS_CORE_01216]), size_type ([SWS_CORE_01214]), difference_type ([SWS_CORE_01215]), а также типов указателей ([SWS_CORE_01217], [SWS_CORE_01218]) и ссылочных типов ([SWS_CORE_01210], [SWS_CORE_01211]), класс функционирует как интероперабельный партнер взаимодействия для обобщенных алгоритмов C++ и внутриплатформенных потоков данных.

Жизненный цикл

Создание и уничтожение экземпляра массива следуют стандартным правилам для агрегатных типов и типов-значений: используются неявно объявленные специальные функции-члены стандарта ISO C++, которые не объявляются заново отдельно. Массив хранит свои элементы непосредственно inline в той же области памяти. Следовательно, время жизни содержащихся элементов неразрывно связано со временем жизни охватывающего объекта массива; динамическое выделение памяти в куче (heap), предположительно, не выполняется, что обеспечивает детерминированное поведение по времени и памяти.

Контейнер всегда находится в корректном состоянии и управляет ровно N элементами. Может ли массив принимать элементы или представляет собой особый случай с N = 0, можно оценить с помощью empty() ([SWS_CORE_01264]), size() ([SWS_CORE_01262]), а также max_size() ([SWS_CORE_01263]). Что касается параллелизма, вероятно, справедливо следующее: параллельные операции чтения безопасны без синхронизации, тогда как параллельные модификации с записью требуют внешней координации со стороны вызывающей стороны.

Путь использования

В типичных сценариях использования ara::core::Array проходит последовательность этапов инициализации, заполнения элементами, произвольного или последовательного доступа, а также, при необходимости, обмена содержимым:

  • Инициализация и заполнение: весь буфер данных можно единообразно заполнить заданным значением с помощью fill() ([SWS_CORE_01241]).
  • Произвольный доступ: для высокопроизводительного доступа доступен оператор индексации без проверки operator[] ([SWS_CORE_01265], [SWS_CORE_01266]). Если требуется проверка диапазона, задействуется at() ([SWS_CORE_01273], [SWS_CORE_01274]).
  • Граничные элементы: прямой доступ к первому и последнему элементам осуществляется через front() ([SWS_CORE_01267], [SWS_CORE_01268]) и back() ([SWS_CORE_01269], [SWS_CORE_01270]).
  • Итерация: обход контейнера в прямом направлении осуществляется через begin() и end() ([SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]) или через константные итераторы, такие как cbegin() и cend() ([SWS_CORE_01258], [SWS_CORE_01259]). Типы итераторов определены как элементарные указатели T* и const T* соответственно ([SWS_CORE_01212], [SWS_CORE_01213]). Для обратного обхода доступны rbegin(), rend(), crbegin() и crend() ([SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261], [SWS_CORE_01219], [SWS_CORE_01220]).
  • Доступ по указателю и обмен: базовая область памяти может быть передана в виде указателя с помощью data() ([SWS_CORE_01271], [SWS_CORE_01272]). Два массива одинакового размера можно обменять содержимым посредством swap() ([SWS_CORE_01242]).

Диаграмма последовательности: типичный порядок вызовов для заполнения, проверки диапазона и обмена экземпляров массивов. Источники: [SWS_CORE_01241], [SWS_CORE_01273], [SWS_CORE_01242].

Сценарии ошибок

Спецификация определяет строгие предусловия и постусловия для граничных и ошибочных ситуаций:

  • Нарушение диапазона при индексированном доступе: если при at() индекс n выходит за границы массива (n >= size()), инициируется IsoStdOutOfRangeViolation вместо стандартного исключения C++ std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]). Обе перегрузки объявлены с noexcept.
  • Доступ к пустым экземплярам: вызов front() или back() для пустого массива (empty() == true, то есть N = 0) в обязательном порядке приводит к ошибке времени компиляции (Compile-Time Error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
  • Неопределенное поведение при использовании итераторов: разыменование итератора, возвращенного begin(), для пустого массива представляет собой неопределенное поведение ([SWS_CORE_01250], [SWS_CORE_01251]).
  • Особый случай получения указателя: если размер массива равен 0, функция-член data() в обязательном порядке возвращает nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
  • Условная безопасность относительно исключений: операция swap() является noexcept только тогда, когда выполняется условие ara::core::is_nothrow_swappable<T>::value, связанное с типом ([SWS_CORE_01242]). Соответственно, свойство noexcept для fill() определяется через std::is_nothrow_copy_assignable<T>::value ([SWS_CORE_01241]).

Настоящее руководство основано на спецификации AUTOSAR Adaptive для функционального класса Core ara::core::Array и создано автоматически.

Функция-член at класса ara::core::Array обеспечивает синхронный доступ на чтение и запись к элементу массива в указанной позиции n с неявной проверкой граничных значений [SWS_CORE_01273]. Функция возвращает модифицируемую ссылку (reference) на адресуемый элемент и может вычисляться во время компиляции (constexpr) [SWS_CORE_01273].

В случае ошибки, когда запрошенный индекс достигает границы контейнера или превышает ее (n >= size()), поведение отличается от стандартного контейнера C++ std::array: вместо исключения типа std::out_of_range генерируется IsoStdOutOfRangeViolation [SWS_CORE_01273]. Поскольку сигнатура объявлена как noexcept и классифицирована как безопасная относительно исключений, обычные исключения C++ не выбрасываются [SWS_CORE_01273]. Интерпретация: возникновение этого нарушения в контексте noexcept, по-видимому, непосредственно приводит к контролируемому завершению выполнения.

Для неизменяемых экземпляров существует комплементарная константная перегрузка [SWS_CORE_01274], возвращающая константную ссылку. Та же семантика ошибок с использованием IsoStdOutOfRangeViolation согласованно применяется и в родственных контейнерах, таких как ara::core::Vector ([SWS_CORE_01354], [SWS_CORE_01355]), а также ara::core::StringView [SWS_CORE_02133].

      Функция-член at класса ara::core::Array (заголовок #include "ara/core/array.h") обеспечивает индексированный доступ для чтения к отдельному элементу массива [SWS_CORE_01274]. Она принимает индекс n типа size_type и возвращает константную ссылку (const_reference) на адресованный элемент [SWS_CORE_01274]. Благодаря объявлению как constexpr и noexcept функция пригодна для константных выражений во время компиляции и специфицирована как безопасная относительно исключений (exception safe) [SWS_CORE_01274]. Для модифицирующего доступа доступна неконстантная перегрузка [SWS_CORE_01273].
      

      В случае ошибки семантика отличается от std::array: если индекс превышает размер контейнера (n >= size()), std::out_of_range не выбрасывается, а регистрируется нарушение IsoStdOutOfRangeViolation [SWS_CORE_01274]. Поскольку функция квалифицирована с noexcept, сообщение об этом нарушении, вероятно, приводит к аварийному завершению программы через общеплатформенный механизм аварийного останова (Abort), для которого могут быть зарегистрированы пользовательские обработчики [SWS_CORE_00054].
      

      Этот паттерн обработки ошибок единообразно применяется и в других контейнерах ara::core, например в ara::core::Vector [SWS_CORE_01354], ara::core::Map [SWS_CORE_01456] и ara::core::StringView [SWS_CORE_02133]. Однако если ara::core::Vector и ara::core::BasicString при at не считаются безопасными относительно исключений [SWS_CORE_01354] [SWS_CORE_03063], то ara::core::Array гарантирует безопасность относительно исключений [SWS_CORE_01274].
