Точка расширения для UDS 0x27

SecurityAccess инкапсулирует специфичную для приложения логику начального числа/ключа для службы UDS 0x27. Diagnostic Server берет на себя проверку запроса, диалог и контекст авторизации и вызывает интерфейс, предлагаемый для запроса начального значения или сравнения ключей SWS Diagnostics §7.3.2.8.9 «SecurityAccess». Таким образом, приложение реализует техническую проверку, а не транспортный ответ UDS.

DM вызывает два реализованных приложением шага для службы 0x27; оба доставляют результат асинхронно. Источники: SWS Diagnostics §7.3.2.8.9 «SecurityAccess», [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_01345].

Асинхронная реализация

GetSeed получает Security-Access-Data-Record и возвращает вектор байтов, CompareKey получает Key и возвращает KeyCompareResultType [SWS_DM_00764] [SWS_DM_00765]. Оба метода получают MetaInfo и CancellationHandler. Callback должен завершить Future ровно один раз либо учитывать CancellationHandler; предоставленные Spans и MetaInfo действительны только в Callback [SWS_DM_01345].

Предел ответственности

Проверки Session и Security относятся к обработке UDS-Service в DM. Поэтому разработчику следует проверять только настроенный Security-Level и возвращать однозначный результат сравнения. Сопоставление положительного или отрицательного UDS-Response и протоколирование Security Events остаются задачей Diagnostic Server SWS Diagnostics §7.5.1 «Security Events».
