Контекст

Класс ara::diag::SecurityAccess определяет интерфейс для обработки UDS-сервиса 0x27 (SecurityAccess) в AUTOSAR Adaptive. Он служит абстрактным обработчиком, с помощью которого приложения предоставляют процедуру «seed и ключ» для разблокировки защищенных диагностических функций. Основным партнером по взаимодействию выступает центральный диспетчер диагностики (Diagnostic Management, DM), который принимает входящие диагностические сообщения от внешних диагностических тестеров и после регистрации перенаправляет их экземпляру ara::diag::SecurityAccess [SWS_DM_00766]. Прикладное программное обеспечение наследуется от этого класса и реализует чисто виртуальные методы для предоставления seed ([SWS_DM_00764]), а также для валидации ключа ([SWS_DM_00765]).

Контекстная диаграмма: взаимодействие между диагностическим тестером, Diagnostic Management (DM) и прикладной реализацией SecurityAccess. Источники: [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_00766]

Жизненный цикл

Экземпляры ara::diag::SecurityAccess представляют отдельный, уникальный элемент порта. Соответственно, операции копирования и перемещения явно запрещены: недоступны ни конструктор копирования, ни конструктор перемещения, ни соответствующие операторы присваивания ([SWS_DM_01615], [SWS_DM_01616], [SWS_DM_01617], [SWS_DM_01618]). Создание обязательно выполняется через параметризованный конструктор с указанием смоделированного ara::core::InstanceSpecifier, а также режима параллелизма ConcurrencyType [SWS_DM_00762].

После инстанцирования объект находится в состоянии «не предлагается». Активный прием запросов должен быть явно активирован вызовом Offer() [SWS_DM_00766]. С помощью StopOffer() перенаправление диагностических запросов через DM может быть прервано в любой момент [SWS_DM_00767]. Интерпретация: перед уничтожением экземпляра через виртуальный деструктор ~SecurityAccess() [SWS_DM_00763], вероятно, целесообразно явно вызвать StopOffer(), поскольку деструктор объявлен как непотокобезопасный. Передаваемый в конструктор ConcurrencyType (kConcurrent или kNotConcurrent) определяет, должны ли производные функции обратного вызова быть реализованы как потокобезопасные [SWS_DM_00762].

Путь использования

Типичный процесс аутентификации безопасности включает предоставление службы, запрос seed и проверку переданного ключа:

  1. Предложение службы: приложение инстанцирует производный класс и вызывает Offer(), тем самым авторизуя DM для перенаправления диагностических запросов для назначенного уровня безопасности [SWS_DM_00766].
  2. Запрос seed: если диагностический тестер отправляет UDS-сообщение для запроса seed (подфункция Request Seed), DM перенаправляет этот вызов в GetSeed() [SWS_DM_00764]. Метод получает запись полезных данных (securityAccessDataRecord), метаданные запроса (metaInfo), а также cancellationHandler. Реализация возвращает ara::core::Future, предоставляющий seed в виде байтового вектора. Переданные полезные данные остаются действительными до тех пор, пока соответствующий promise не будет выполнен или операция не будет отменена [SWS_DM_00764].
  3. Проверка ключа: после получения ключа от тестера (подфункция Send Key) DM вызывает метод CompareKey() [SWS_DM_00765]. Проверяемый ключ передается как ara::core::Span. Приложение асинхронно валидирует ключ и сообщает результат через ara::core::Future<KeyCompareResultType>.
  4. Завершение службы: если интерфейс требуется деактивировать, приложение вызывает StopOffer(), в результате чего DM больше не доставляет запросы [SWS_DM_00767].

Диаграмма последовательности: типичный процесс аутентификации безопасности от Offer через GetSeed и CompareKey до StopOffer. Источники: [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_00766], [SWS_DM_00767]

Сценарии ошибок

Ошибки могут возникать при моделировании, предоставлении службы, а также во время выполнения методов аутентификации:

  • Ошибки моделирования и инстанцирования: при вызове конструктора [SWS_DM_00762] могут быть вызваны нарушения:
    • InstanceSpecifierMappingIntegrityViolation: InstanceSpecifier не может быть разрешен в контексте процесса или не указывает на PortPrototype.
    • PortInterfaceMappingViolation: PortPrototype не указывает на DiagnosticSecurityLevelInterface.
    • ProcessMappingViolation: для ссылки на экземпляр не существует подходящего смоделированного процесса.
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже используется другим экземпляром в работающем процессе.
  • Конфликты состояний при предложении: если Offer() вызывается, когда служба уже предлагается, вызов завершается сбоем и возвращает код ошибки DiagOfferErrc::kAlreadyOffered в результате [SWS_DM_00766].
  • Диагностические ошибки (NRC): если генерация seed или сравнение ключей не могут быть завершены штатно, приложение сигнализирует об ошибках через возвращаемый ara::core::Future с помощью соответствующих кодов отрицательного ответа (Negative Response Codes, NRC согласно ISO 14229-1) с использованием DiagUdsNrcErrc ([SWS_DM_00764], [SWS_DM_00765]).
  • Персистентные счетчики неудачных попыток: После каждой неудачной попытки изменения уровня безопасности счетчик неудачных попыток должен быть инкрементирован и в обязательном порядке сохранен персистентно, чтобы сохраняться при сбросах (AUTOSAR_AP_SWS_Diagnostics §4.1 с. 63).
  • Прерывание диалогов: если диагностический диалог завершается досрочно, это можно опросить через cancellationHandler.IsCanceled() или отслеживать с помощью SetNotifier ([SWS_DM_00764], [SWS_DM_00765]).

Настоящее руководство было сформировано автоматически на основе спецификации AUTOSAR Adaptive R25-11.

Использование

Чисто виртуальный метод CompareKey класса ara::diag::SecurityAccess ([SWS_DM_00765], заголовочный файл #include "ara/diag/security_access.h") реализуется диагностическим приложением для валидации переданного клиентом ключа для разблокировки уровня безопасности в рамках службы UDS 0x27 (SecurityAccess) ([SWS_DM_00236], [SWS_DM_00765]).

  • key: ara::core::Span<const std::uint8_t> с валидируемым ключом. Допустимость данных гарантируется до тех пор, пока Promise не будет выполнено или операция не будет отменена ([SWS_DM_00765]).
  • metaInfo: предоставляет метаинформацию (MetaInfo) о входящем запросе ([SWS_DM_00765]).
  • cancellationHandler: позволяет опрашивать отмену сессии с помощью IsCanceled, а также регистрировать функцию уведомления через SetNotifier ([SWS_DM_00765]).

Обработка выполняется асинхронно через возврат ara::core::Future<KeyCompareResultType> ([SWS_DM_00765]).

Обработка ошибок

В случае ошибки соответствующий отрицательный код ответа (NRC) согласно ISO 14229-1 должен быть предоставлен через DiagUdsNrcErrc ([SWS_DM_00765]). Экземпляр диагностического сервера подсчитывает неудачные попытки изменения уровня безопасности ([SWS_DM_00270]) и сопоставляет их со сконфигурированными пороговыми значениями ([SWS_DM_00271]).

Параллелизм и ограничения

Функция определена как noexcept и является безопасной относительно исключений (exception safe) ([SWS_DM_00765]). Потокобезопасность является условной (conditional): должна ли реализация метода быть потокобезопасной, зависит от переданного в конструкторе ConcurrencyType ([SWS_DM_00765]).

Взаимодействие

Совместно с GetSeed CompareKey образует реализацию алгоритма Seed/Key на стороне приложения для службы 0x27 (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.9 «Service 0x27 – SecurityAccess»). При успешной разблокировке экземпляр сервера обновляет статус безопасности сессии ([SWS_DM_00846]) и сообщает о событии безопасности SEV_UDS_SECURITY_ACCESS_SUCCESSFUL в IdsM ([SWS_DM_02019]).

Это указание по использованию было автоматически сгенерировано на основе спецификации AUTOSAR AP R25-11.
