Контекст

Шаблонный класс ara::shwa::Buffer в модуле shwa (Shared Hardware Acceleration) AUTOSAR Adaptive Platform представляет собой центральную абстракцию для инкапсуляции буферов данных и управления ими. Определение класса параметризовано типом элементов T, пространственной размерностью Dimensions, а также аллокатором памяти AllocatorT.

Интерпретация: параметры шаблона T и Dimensions, вероятно, определяют базовый тип данных, а также геометрическую структуру буферной памяти для предоставления многомерных областей данных аппаратным ускорителям.

Класс выступает посредником между прикладным программным обеспечением и областями памяти, которые либо динамически предоставляются через пользовательские аллокаторы, либо подключаются напрямую через существующие указатели памяти хоста (hostData) ([AP_SWS_SHWA_00211], [AP_SWS_SHWA_00214]). При этом ara::shwa::Buffer тесно взаимодействует со сведениями о размерности (Range<Dimensions>) и списками свойств (PropertyList), конфигурирующими управляющие параметры и метаданные.

Жизненный цикл

Жизненный цикл ara::shwa::Buffer характеризуется строгими отношениями владения и фабричной семантикой:

  • Отключенные операции по умолчанию и копирования: конструктор по умолчанию удален ([AP_SWS_SHWA_00202]). Конструктор копирования ([AP_SWS_SHWA_00203]) и оператор присваивания с копированием ([AP_SWS_SHWA_00204]) также определены как =delete, что исключает дублирование экземпляров буфера.
  • Запрет операций перемещения: конструктор перемещения ([AP_SWS_SHWA_00205]), а также оператор присваивания с перемещением ([AP_SWS_SHWA_00206]) также удалены. Вследствие этого экземпляр буфера жестко привязан к своему адресу в памяти.
  • Создание и владение: новые буферы создаются исключительно через статические методы Create, которые возвращают объект, инкапсулированный в std::unique_ptr<Buffer>, в виде ara::core::Result ([AP_SWS_SHWA_00209], [AP_SWS_SHWA_00210], [AP_SWS_SHWA_00211], [AP_SWS_SHWA_00212], [AP_SWS_SHWA_00213], [AP_SWS_SHWA_00214]). Таким образом, исключительное владение принадлежит вызывающей стороне.
  • Уничтожение: интерпретация: освобождение базовой памяти и внутренних дескрипторов, вероятно, связано со сроком жизни управляющего std::unique_ptr<Buffer> и происходит при его деструкции.
  • Параллелизм: перегрузки Create с явными диапазонами размерностей ([AP_SWS_SHWA_00209], [AP_SWS_SHWA_00210], [AP_SWS_SHWA_00211], [AP_SWS_SHWA_00213], [AP_SWS_SHWA_00214]) указаны как потокобезопасные. Перегрузка без диапазона размерностей ([AP_SWS_SHWA_00212]), а также запросы свойств HasProperty ([AP_SWS_SHWA_00215]) и GetProperty ([AP_SWS_SHWA_00216]) непотокобезопасны и при совместном доступе требуют внешней синхронизации.

Путь использования

Типичный сценарий использования включает инстанцирование буфера с помощью подходящего фабричного метода, а также последующую проверку и запрос свойств буфера:

  1. Создание буфера: приложение вызывает статический метод Create, например, с указанием диапазона размерностей и опциональных списков свойств ([AP_SWS_SHWA_00209]) или с подключением внешних данных хоста ([AP_SWS_SHWA_00211]).
  2. Валидация результата: возвращенный ara::core::Result проверяется на наличие ошибок. В случае успеха приложение принимает std::unique_ptr<Buffer>.
  3. Проверка доступности свойства: перед обращением к типоспецифичным свойствам приложение с помощью HasProperty<PropertyT>() проверяет, поддерживается ли свойство буфером ([AP_SWS_SHWA_00215]).
  4. Запрос свойства: если признак присутствует, он считывается с помощью GetProperty<PropertyT>() ([AP_SWS_SHWA_00216]), возвращающего значение типобезопасным образом в ara::core::Result<PropertyT>.

Диаграмма последовательности: типичный сценарий использования для создания и запроса свойств объекта буфера. Источники: [AP_SWS_SHWA_00209], [AP_SWS_SHWA_00215], [AP_SWS_SHWA_00216]

Сценарии ошибок

Интерфейс детерминированно сигнализирует об ошибках через ara::core::Result; все методы являются noexcept и безопасными относительно исключений:

  • ShwaErrorCode::kMemoryNotAllocated: возвращается всеми методами Create (от [AP_SWS_SHWA_00209] до [AP_SWS_SHWA_00214]), если выделение памяти на хосте или аппаратном ускорителе завершается сбоем.
  • ShwaErrorCode::kRuntime: в рамках семантики отката (rollback) методов Create (от [AP_SWS_SHWA_00209] до [AP_SWS_SHWA_00214]) служит общей ошибкой времени выполнения при возникновении сбоев во время процесса создания.
  • ShwaErrorCode::kFeatureNotSupported: возникает при вызове GetProperty<PropertyT>() ([AP_SWS_SHWA_00216]), если запрашиваемое свойство не поддерживается конкретным буфером. Предварительный вызов HasProperty<PropertyT>() ([AP_SWS_SHWA_00215]) предотвращает этот ошибочный случай.

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform Release R25-11 (модуль shwa) и создано автоматически.

<li><strong>Запрет операций перемещения:</strong> конструктор перемещения (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00205" href="../spec/record.html?id=AP_SWS_SHWA_00205">[AP_SWS_SHWA_00205]</a>), а также оператор присваивания с перемещением (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00206" href="../spec/record.html?id=AP_SWS_SHWA_00206">[AP_SWS_SHWA_00206]</a>) также удалены. Вследствие этого экземпляр буфера жестко привязан к своему адресу в памяти.</li>
<li><strong>Создание и владение:</strong> новые буферы создаются исключительно через статические методы <code>Create</code>, которые возвращают объект, инкапсулированный в <code>std::unique_ptr&lt;Buffer&gt;</code>, в виде <code>ara::core::Result</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00209" href="../spec/record.html?id=AP_SWS_SHWA_00209">[AP_SWS_SHWA_00209]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00210" href="../spec/record.html?id=AP_SWS_SHWA_00210">[AP_SWS_SHWA_00210]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00211" href="../spec/record.html?id=AP_SWS_SHWA_00211">[AP_SWS_SHWA_00211]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00212" href="../spec/record.html?id=AP_SWS_SHWA_00212">[AP_SWS_SHWA_00212]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00213" href="../spec/record.html?id=AP_SWS_SHWA_00213">[AP_SWS_SHWA_00213]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00214" href="../spec/record.html?id=AP_SWS_SHWA_00214">[AP_SWS_SHWA_00214]</a>). Таким образом, исключительное владение принадлежит вызывающей стороне.</li>
<li><strong>Уничтожение:</strong> интерпретация: освобождение базовой памяти и внутренних дескрипторов, вероятно, связано со сроком жизни управляющего <code>std::unique_ptr&lt;Buffer&gt;</code> и происходит при его деструкции.</li>
<li><strong>Параллелизм:</strong> перегрузки <code>Create</code> с явными диапазонами размерностей (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00209" href="../spec/record.html?id=AP_SWS_SHWA_00209">[AP_SWS_SHWA_00209]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00210" href="../spec/record.html?id=AP_SWS_SHWA_00210">[AP_SWS_SHWA_00210]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00211" href="../spec/record.html?id=AP_SWS_SHWA_00211">[AP_SWS_SHWA_00211]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00213" href="../spec/record.html?id=AP_SWS_SHWA_00213">[AP_SWS_SHWA_00213]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00214" href="../spec/record.html?id=AP_SWS_SHWA_00214">[AP_SWS_SHWA_00214]</a>) указаны как потокобезопасные. Перегрузка без диапазона размерностей (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00212" href="../spec/record.html?id=AP_SWS_SHWA_00212">[AP_SWS_SHWA_00212]</a>), а также запросы свойств <code>HasProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00215" href="../spec/record.html?id=AP_SWS_SHWA_00215">[AP_SWS_SHWA_00215]</a>) и <code>GetProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00216" href="../spec/record.html?id=AP_SWS_SHWA_00216">[AP_SWS_SHWA_00216]</a>) непотокобезопасны и при совместном доступе требуют внешней синхронизации.</li>
</ul>

<h4>Путь использования</h4>
<p>Типичный сценарий использования включает инстанцирование буфера с помощью подходящего фабричного метода, а также последующую проверку и запрос свойств буфера:</p>
<ol>
<li><strong>Создание буфера:</strong> приложение вызывает статический метод <code>Create</code>, например, с указанием диапазона размерностей и опциональных списков свойств (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00209" href="../spec/record.html?id=AP_SWS_SHWA_00209">[AP_SWS_SHWA_00209]</a>) или с подключением внешних данных хоста (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00211" href="../spec/record.html?id=AP_SWS_SHWA_00211">[AP_SWS_SHWA_00211]</a>).</li>
<li><strong>Валидация результата:</strong> возвращенный <code>ara::core::Result</code> проверяется на наличие ошибок. В случае успеха приложение принимает <code>std::unique_ptr&lt;Buffer&gt;</code>.</li>
<li><strong>Проверка доступности свойства:</strong> перед обращением к типоспецифичным свойствам приложение с помощью <code>HasProperty&lt;PropertyT&gt;()</code> проверяет, поддерживается ли свойство буфером (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00215" href="../spec/record.html?id=AP_SWS_SHWA_00215">[AP_SWS_SHWA_00215]</a>).</li>
<li><strong>Запрос свойства:</strong> если признак присутствует, он считывается с помощью <code>GetProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00216" href="../spec/record.html?id=AP_SWS_SHWA_00216">[AP_SWS_SHWA_00216]</a>), возвращающего значение типобезопасным образом в <code>ara::core::Result&lt;PropertyT&gt;</code>.</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>Интерфейс детерминированно сигнализирует об ошибках через <code>ara::core::Result</code>; все методы являются <code>noexcept</code> и безопасными относительно исключений:</p>
<ul>
<li><code>ShwaErrorCode::kMemoryNotAllocated</code>: возвращается всеми методами <code>Create</code> (от <a class="spec-record-ref" data-req="AP_SWS_SHWA_00209" href="../spec/record.html?id=AP_SWS_SHWA_00209">[AP_SWS_SHWA_00209]</a> до <a class="spec-record-ref" data-req="AP_SWS_SHWA_00214" href="../spec/record.html?id=AP_SWS_SHWA_00214">[AP_SWS_SHWA_00214]</a>), если выделение памяти на хосте или аппаратном ускорителе завершается сбоем.</li>
<li><code>ShwaErrorCode::kRuntime</code>: в рамках семантики отката (rollback) методов <code>Create</code> (от <a class="spec-record-ref" data-req="AP_SWS_SHWA_00209" href="../spec/record.html?id=AP_SWS_SHWA_00209">[AP_SWS_SHWA_00209]</a> до <a class="spec-record-ref" data-req="AP_SWS_SHWA_00214" href="../spec/record.html?id=AP_SWS_SHWA_00214">[AP_SWS_SHWA_00214]</a>) служит общей ошибкой времени выполнения при возникновении сбоев во время процесса создания.</li>
<li><code>ShwaErrorCode::kFeatureNotSupported</code>: возникает при вызове <code>GetProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00216" href="../spec/record.html?id=AP_SWS_SHWA_00216">[AP_SWS_SHWA_00216]</a>), если запрашиваемое свойство не поддерживается конкретным буфером. Предварительный вызов <code>HasProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00215" href="../spec/record.html?id=AP_SWS_SHWA_00215">[AP_SWS_SHWA_00215]</a>) предотвращает этот ошибочный случай.</li>
</ul>
