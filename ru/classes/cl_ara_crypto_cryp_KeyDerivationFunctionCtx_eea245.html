Безопасно формирует симметричные ключи из базовых ключей и настраиваемых параметров контекста.

Интерфейс ara::crypto::cryp::KeyDerivationFunctionCtx служит для формирования новых симметричных ключей из имеющегося ключевого материала и настраиваемых параметров контекста, таких как соли (salts) или счетчики [SWS_CRYPT_21515]. Перед генерацией ключа с помощью DeriveKey контекст должен быть инициализирован через SetKey ключом или KeySlot и опционально сконфигурирован через SetParameter [SWS_CRYPT_21525]. Важным условием безопасности является то, что формирование ключа может выполняться только в том случае, если исходный ключевой материал явно авторизован для операций KDF, а требуемые флаги использования целевого ключа совместимы.

Контекст

Класс ara::crypto::cryp::KeyDerivationFunctionCtx предоставляет интерфейс для функций формирования ключа (Key Derivation Functions, KDF) в криптографическом модуле AUTOSAR Adaptive. Его основная задача заключается в формировании новых симметричных ключей из заданного ключевого материала и настраиваемых параметров контекста [SWS_CRYPT_21515].

Типичными участниками взаимодействия являются вызывающие службы приложений, базовый исходный материал в виде SymmetricKey [SWS_CRYPT_21525] или KeySlot [SWS_CRYPT_50010], а также результат формирования ключа в форме нового SymmetricKey::Sptr [SWS_CRYPT_21515]. Дополнительные криптографические параметры могут передаваться как области памяти, целые числа или вспомогательные ключи [SWS_CRYPT_50007] [SWS_CRYPT_50008] [SWS_CRYPT_50009].

Жизненный цикл

Время жизни и владение экземплярами управляются через типизированный умный указатель ara::crypto::cryp::KeyDerivationFunctionCtx::Sptr [SWS_CRYPT_21501]. Создание экземпляра конкретной реализации, вероятно, происходит через специализированную фабрику или ответственный CryptoProvider, поскольку класс определяет чисто виртуальный интерфейс.

Вновь созданный контекст изначально находится в неполном состоянии. Контекст готов к вычислению только после успешного назначения ключа через SetKey [SWS_CRYPT_21525] [SWS_CRYPT_50010] и установки требуемых параметров KDF через SetParameter [SWS_CRYPT_50007] [SWS_CRYPT_50008] [SWS_CRYPT_50009]. С точки зрения параллелизма методы интерфейса объявлены потокобезопасными и безопасными относительно исключений ([SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50007]).

Путь использования

Типичная последовательность вызовов для формирования ключа включает три последовательные фазы:

  1. Назначение базового ключа: через SetKey конфигурируется исходный ключевой материал. При этом может передаваться либо существующий объект ключа (SymmetricKey::Sptr) [SWS_CRYPT_21525], либо постоянный слот хранения ключа (KeySlot::Sptr) [SWS_CRYPT_50010].
  2. Настройка параметров контекста: специфичные для KDF значения, такие как соль, векторы инициализации или счетчики итераций, определяются через SetParameter. Поддерживаются буферы памяти (ReadOnlyMemRegion) [SWS_CRYPT_50007], 64-битные целые числа (std::uint64_t) [SWS_CRYPT_50008] и дополнительные симметричные ключи (SymmetricKey::Sptr) [SWS_CRYPT_50009].
  3. Формирование целевого ключа: вызов DeriveKey выполняет криптографическое вычисление [SWS_CRYPT_21515]. Метод ожидает идентификатор целевого алгоритма (AlgId), а также разрешенные флаги использования (AllowedUsageFlags) и в случае успеха возвращает SymmetricKey::Sptr.

Диаграмма последовательности: типичная последовательность вызовов для формирования симметричного ключа через KeyDerivationFunctionCtx. Источники: [SWS_CRYPT_21525], [SWS_CRYPT_50007], [SWS_CRYPT_21515].

Сценарии ошибок

Методы интерфейса сигнализируют об ошибках через ara::core::Result с использованием определенных кодов ошибок:

  • Неполная инициализация: если DeriveKey вызывается без достаточной конфигурации, вызов завершается ошибкой с ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_21515]. Если назначенный KeySlot пуст на момент выполнения, сообщается ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_21515].
  • Нарушение прав использования: исходный ключ должен разрешать операцию kAllowKeyDerivation, в противном случае генерируется ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_21525], [SWS_CRYPT_21515], [SWS_CRYPT_50009]). Если назначение включает kAllowPlaintextExport, исходный ключ также должен содержать kAllowDerivedPlaintextExport, иначе также возникает kUsageViolation [SWS_CRYPT_21515].
  • Несовместимость и недопустимые аргументы: неподдерживаемый целевой алгоритм возвращает UnknownIdentifier, а несовместимые друг с другом флаги использования вызывают ara::crypto::CryptoErrc::kIncompatibleArguments [SWS_CRYPT_21515]. При передаче неподходящих для контекста объектов ключей или KeySlot метод SetKey возвращает ara::crypto::CryptoErrc::kIncompatibleObject ([SWS_CRYPT_21525], [SWS_CRYPT_50010]). Недопустимые значения параметров приводят к ara::crypto::CryptoErrc::kInvalidArgument ([SWS_CRYPT_50007], [SWS_CRYPT_50008]).
  • Неподдерживаемые функции интерфейса: если конкретная реализация поддерживает исключительно KeySlot или исключительно SymmetricKey, соответствующий другой вызов SetKey приводит к ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_21525], [SWS_CRYPT_50010]). Неизвестные имена параметров в SetParameter также вызывают kUnsupported ([SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009]).
  • Конфликты ресурсов: если криптографический ресурс, необходимый для вычисления, заблокирован, DeriveKey сигнализирует код ошибки ara::crypto::CryptoErrc::kBusyResource [SWS_CRYPT_21515].

virtual ara::core::Result< SymmetricKey::Sptr > DeriveKey (AlgId targetAlgId, AllowedUsageFlags allowedUsage) const noexcept=0;

Derive a symmetric key from the provided key material and provided context configuration, e.g., salt, context, IV, iteration count.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: ad7de7f8f0b6 Provenance

Метод DeriveKey класса ara::crypto::cryp::KeyDerivationFunctionCtx синхронно выводит новый симметричный ключ из имеющегося ключевого материала и сохраненных в контексте параметров, таких как соль (salt), вектор инициализации (IV) или счетчик итераций [SWS_CRYPT_21515].

Использование

При вызове передаются идентификатор требуемого криптоалгоритма через targetAlgId, а также разрешенные флаги использования через allowedUsage [SWS_CRYPT_21515]. В качестве возвращаемого значения функция синхронно возвращает ara::core::Result<SymmetricKey::Sptr>, который при успешном выполнении предоставляет смарт-указатель на созданный объект симметричного ключа [SWS_CRYPT_21515].

Обработка ошибок

Если генерация ключа завершается неудачей, функция гарантирует семантику отката и возвращает соответствующий код ошибки в ara::core::Result [SWS_CRYPT_21515]:

  • UnknownIdentifier: возвращается, если переданное значение для targetAlgId не поддерживается [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kIncompatibleArguments: возникает, если заданные в allowedUsage флаги использования несовместимы с целевым алгоритмом [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kUninitializedContext: контекст перед выводом ключа не был инициализирован в достаточной степени [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kBusyResource: ресурс, требуемый для вывода ключа, занят [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kEmptyKeySlot: сконфигурированный для операции KeySlot в данный момент пуст [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kUsageViolation: возникает, если полномочия использования исходного ключа не содержат kAllowKeyDerivation или если цель требует kAllowPlaintextExport, однако источник не разрешает kAllowDerivedPlaintextExport [SWS_CRYPT_21515].

Параллелизм и контекст выполнения

Метод специфицирован как noexcept, обеспечивает безопасность исключений (exception safe) и рассчитан как потокобезопасный (thread-safe) для одновременного вызова [SWS_CRYPT_21515].

      Использование
      

      Метод SetKey служит для конфигурации KeyDerivationFunctionCtx с симметричным ключевым материалом, предоставленным в виде key [SWS_CRYPT_21525]. Функция выполняется синхронно и сообщает о результате операции через возвращаемый тип ara::core::Result<void> [SWS_CRYPT_21525].
      


      Параллелизм и надёжность выполнения
      

      Интерфейс снабжен спецификатором noexcept и классифицирован как exception-safe [SWS_CRYPT_21525]. Кроме того, выполнение специфицировано как thread-safe, благодаря чему вызов может безопасно выполняться и в конкурентных средах [SWS_CRYPT_21525].
      


      Обработка ошибок
      

      В случае ошибки возвращается не пустой статус успеха, а соответствующий код ошибки, при этом для всех случаев ошибок определена семантика отката (rollback) [SWS_CRYPT_21525]:
      

        

      • ara::crypto::CryptoErrc::kIncompatibleObject: переданный объект ключа несовместим с симметричным контекстом [SWS_CRYPT_21525].
        • 

      • ara::crypto::CryptoErrc::kUsageViolation: Допустимое использование ключа не включает право kAllowKey Derivation [SWS_CRYPT_21525].
        • 

      • ara::crypto::CryptoErrc::kUnsupported: Конкретный контекст поддерживает назначение исключительно через KeySlot [SWS_CRYPT_21525].
        • 

      


      Взаимодействие
      

      Если базовая реализация контекста не поддерживает прямое назначение SymmetricKey::Sptr или если ключ вместо этого должен быть получен из слота памяти только в момент деривации ключа, доступна альтернативная перегрузка SetKey с KeySlot::Sptr [SWS_CRYPT_50010].
