класс ara::com::SamplePtr

[SWS_CM_00306] Upstream: RS_CM_00202, RS_CM_00203, RS_AP_00114, RS_AP_00122, RS_AP_00135, RS_AP_00145

template <typename T> class SamplePtr {...};

Emulates a std::unique_ptr to an event sample.

The ara::com::SamplePtr behaves as a std::unique_ptr as long as the event/ field is subscribed to, or the Proxy it belongs to is not destroyed. The precondition defined in [SWS_CM_00085] and [SWS_CM_00087] must be fulfilled. Otherwise it is considered a violation.

Note: The SamplePtr is always passed with a const SampleType to the callable in GetNewSamples() (see [SWS_CM_00701]). Therefore the sample datatype (typename T) and the SamplePtr operators using the sample datatype (typename T) are implicitly declared as const. This means that the sample data will always be read-only.

Контекст

Шаблон класса ara::com::SamplePtr представляет собой центральную точку доступа и входа для доступа на чтение к принятым данным событий (Event Samples) в рамках управления коммуникацией Adaptive Platform (EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»). Согласно [SWS_CM_00306], класс семантически эмулирует эксклюзивный указатель по образцу std::unique_ptr на конкретный сэмпл события.

В общей системе ara::com::SamplePtr взаимодействует с тремя основными участниками:

  • Логика приложения (Callable): Приложение предоставляет вызываемую сущность (Callable) с сигнатурой void(ara::com::SamplePtr<SampleType const>) (EXP_ARAComAPI §5.3.5 «Event Reception», EXP_ARAComAPI §5.3.5.3 «GetNewSamples»). Полезные данные всегда передаются Callable как const SampleType, благодаря чему тип данных и все операторы доступа неявно доступны только для чтения (read-only) ([SWS_CM_00701]).
  • Управление коммуникацией (обертка события прокси): При синхронном вызове GetNewSamples() среда выполнения десериализует новые данные в слоты буфера и передает приложению ответственность за время жизни каждого слота через экземпляр SamplePtr (EXP_ARAComAPI §5.3.5.3 «GetNewSamples», EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»).
  • Локальный кэш и буфер промежуточного ПО: Архитектура отдает предпочтение подходу на основе ссылок для коммуникации событий 1:N. Вместо копирования и дублирования данных событий в локальной памяти SamplePtr указывает непосредственно на управляемую область буфера промежуточного ПО, что обеспечивает эффективную обработку с нулевым копированием (EXP_ARAComAPI §5.3.5 «Buffer Management»).

Помимо инкапсуляции данных, SamplePtr предоставляет с помощью GetProfileCheckStatus() ([SWS_CM_90420]) интерфейс для запроса статуса сквозной защиты (E2E) принятого сэмпла.

Контекстная диаграмма: роль ara::com::SamplePtr во взаимодействии между приложением, прокси и управлением буферами. Источники: [SWS_CM_00306], [SWS_CM_00701], [SWS_CM_90420], EXP_ARAComAPI §5.3.5.3 «GetNewSamples», EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs», EXP_ARAComAPI §5.3.5 «Buffer Management».

Жизненный цикл

Жизненный цикл ara::com::SamplePtr подчиняется строгим правилам исключительного владения (семантика только перемещения — move-only):

  • Создание: Пустой указатель может быть явно создан с помощью конструктора по умолчанию ([SWS_CM_11534]) или конструктора нулевого указателя ([SWS_CM_11535]). Оба конструктора определены как constexpr и noexcept. Валидный, заполненный данными SamplePtr создается исключительно реализацией ara::com и при выполнении GetNewSamples() передается вызываемой сущности приложения (Callable) с передачей владения (EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»).
  • Исключение операций копирования: Чтобы сохранить однозначность доступа к буферу, конструктор копирования ([SWS_CM_11536]), а также оператор присваивания копированием ([SWS_CM_11538]) явно удалены (= delete).
  • Передача владения и обмен: Владение слотом буфера может быть передано другим экземплярам SamplePtr с помощью перемещающего конструктора ([SWS_CM_11537]) или перемещающего присваивания ([SWS_CM_11540]). Метод Swap() ([SWS_CM_11544]) обеспечивает безопасный относительно исключений обмен управляемыми объектами двух экземпляров.
  • Освобождение и уничтожение: Пока приложение удерживает SamplePtr, промежуточное ПО не может затребовать занятый слот памяти обратно (EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»). Возврат слота промежуточному ПО осуществляется вызовом Reset(nullptr) ([SWS_CM_11545]), присваиванием nullptr ([SWS_CM_11539]) или при выходе из области видимости через деструктор ~SamplePtr() ([SWS_CM_11547]).
  • Границы валидности: SamplePtr ведет себя как валидный представитель по образцу std::unique_ptr только до тех пор, пока оформлена активная подписка на соответствующее событие или поле и существует связанный прокси. При нарушении этих предварительных условий дальнейшее использование считается нарушением спецификации согласно [SWS_CM_00085] и [SWS_CM_00087].

Диаграмма состояний: фазы жизненного цикла и переходы ara::com::SamplePtr. Источники: [SWS_CM_11534], [SWS_CM_11537], [SWS_CM_11540], [SWS_CM_11545], [SWS_CM_11547], EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs».

Путь использования

Типичная последовательность вызовов для приема и обработки данных событий подразделяется на следующие шаги:

  1. Предоставление обратного вызова: Приложение передает в GetNewSamples() вызываемую функцию f с сигнатурой void(ara::com::SamplePtr<SampleType const>), а также опционально параметр maxNumberOfSamples (EXP_ARAComAPI §5.3.5.3 «GetNewSamples»).
  2. Прием и вступление во владение: Для каждого доступного события промежуточное ПО десериализует элемент данных и вызывает f. С передачей исключительное право владения переходит пользователю (EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»).
  3. Проверка валидности и защиты:
    • Экземпляр проверяется на валидность. Интерпретация: хотя спецификация в [SWS_CM_11543] описывает возвращаемое значение operator bool() как «TRUE if the stored pointer is null, FALSE otherwise», оператор преобразования, вероятно, используется по аналогии со стандартными умными указателями для проверки наличия управляемого объекта.
    • С помощью GetProfileCheckStatus() ([SWS_CM_90420]) приложение опрашивает статус проверки E2E, чтобы выявить поврежденные или неполные сэмплы до дальнейшей обработки.
  4. Доступ к данным для чтения: После успешной проверки статуса приложение обращается к полезным данным через оператор разыменования operator*() ([SWS_CM_11541]), оператор «стрелка» operator->() ([SWS_CM_11542]) или через «сырой» указатель Get() ([SWS_CM_11546]). Модифицирующий доступ исключен константной типизацией ([SWS_CM_00701]).
  5. Освобождение или продление времени жизни:
    • Если сэмпл требуется только внутри функции обратного вызова, время его жизни автоматически завершается при выходе из области видимости вызовом деструктора ([SWS_CM_11547]), вследствие чего слот промежуточного ПО немедленно освобождается (EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»). Досрочное ручное освобождение возможно через Reset(nullptr) ([SWS_CM_11545]).
    • Если сэмпл должен сохраняться после завершения функции обратного вызова, приложение должно переместить SamplePtr в собственные структуры данных с помощью семантики перемещения ([SWS_CM_11537], [SWS_CM_11540]).

Диаграмма последовательности: последовательность обработки сэмпла события при вызове GetNewSamples(). Источники: [SWS_CM_00701], [SWS_CM_11541], [SWS_CM_11545], [SWS_CM_11547], [SWS_CM_90420], EXP_ARAComAPI §5.3.5.3 «GetNewSamples», EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs».

Сценарии ошибок

При использовании ara::com::SamplePtr необходимо учитывать следующие ошибочные ситуации и граничные условия:

  • Превышение квоты буфера (Quota Violation): Реализация ara::com перед десериализацией проверяет, превышает ли количество экземпляров SamplePtr, удерживаемых в данный момент приложением, максимальное число, согласованное при предыдущем Subscribe(). Если это так, GetNewSamples() прерывает выполнение и возвращает код ошибки в ara::core::Result (EXP_ARAComAPI §5.3.5.3 «GetNewSamples», EXP_ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»). Разгрузка наступает только тогда, когда приложение освобождает удерживаемые экземпляры путем уничтожения или через Reset(nullptr).
  • Нарушение привязки к прокси и подписке: Если SamplePtr продолжает использоваться после уничтожения связанного объекта прокси или после отмены подписки, предварительные условия согласно [SWS_CM_00085] и [SWS_CM_00087] нарушаются, что приводит к неопределенному поведению системы.
  • Сбой проверки E2E: Если результат GetProfileCheckStatus() ([SWS_CM_90420]) отличается от успешного статуса, данные, на которые указывает ссылка, нельзя интерпретировать как валидные управляющие данные. В этом случае приложение должно инициировать освобождение указателя.
  • Безопасность исключений: Все операции и конструкторы класса ara::com::SamplePtr имеют спецификацию noexcept ([SWS_CM_11534], [SWS_CM_11535], [SWS_CM_11537], от [SWS_CM_11539] до [SWS_CM_11547], [SWS_CM_90420]). Они не вызывают исключений и предоставляют полную гарантию no-throw.

Данное руководство по классу было создано ИИ-ассистентом курации на основе спецификации AUTOSAR для релиза R25-11.
