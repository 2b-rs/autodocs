Контекст

C++-класс <DataIdentifierInterface> служит в модуле diag платформы AUTOSAR Adaptive Platform серверным базовым интерфейсом для идентификаторов диагностических данных (Data Identifier, DID) согласно ISO 14229-1 (UDS). Интерфейс определяет стандартизированный мост между управлением диагностикой платформы и специфичными для приложения подпрограммами предоставления или обновления диагностических данных.

Во взаимодействии обычно участвуют три ключевых компонента:

  • Diagnostic Manager (DM): принимает запросы диагностических служб UDS (таких как служба 0x22 ReadDataByIdentifier или служба 0x2E WriteDataByIdentifier) от внешних диагностических тестеров и перенаправляет их соответствующему зарегистрированному экземпляру интерфейса ([SWS_DM_00599], [SWS_DM_00600]).
  • Обработчик приложения: конкретный класс Adaptive-приложения наследуется от <DataIdentifierInterface> и реализует чистые виртуальные методы Read ([SWS_DM_00640]) и Write ([SWS_DM_00598]).
  • Диагностический тестер (клиент): отправляет UDS-запросы в электронный блок управления автомобиля и принимает ответы, агрегированные Diagnostic Manager.

Контекстная диаграмма: взаимодействие между диагностическим тестером, Diagnostic Manager и <DataIdentifierInterface>. Источники: [SWS_DM_00599], [SWS_DM_00600], [SWS_DM_00640], [SWS_DM_00598]

Жизненный цикл

Создание экземпляра выполняется через параметризованный конструктор с передачей ara::core::InstanceSpecifier, а также режима ara::diag::ConcurrencyType ([SWS_DM_00585]). Через тип конкурентности вызывающая сторона указывает, рассчитана ли реализация как потокобезопасная (kConcurrent) или непотокобезопасная (kNotConcurrent) ([SWS_DM_00585]).

Экземпляры <DataIdentifierInterface> обладают уникальной идентичностью и не могут быть ни скопированы, ни перемещены. Соответственно, конструктор копирования ([SWS_DM_01665]), конструктор перемещения ([SWS_DM_01666]), а также соответствующие операторы присваивания ([SWS_DM_01663], [SWS_DM_01664]) удалены (=delete).

В отношении состояний службы класс различает две фазы:

  • Неактивно (не предлагается): после конструирования объект присутствует локально, но не принимает диагностические запросы.
  • Активно (предлагается): только явный вызов метода Offer() ([SWS_DM_00599]) активирует пересылку запросов через Diagnostic Manager этому экземпляру.
  • Деактивировано: вызовом StopOffer() ([SWS_DM_00600]) пересылка прерывается, и экземпляр снова переходит в неактивное состояние.

Уничтожение выполняется через виртуальный деструктор ~<DataIdentifierInterface>() ([SWS_DM_00586]). Он не является потокобезопасным и не является безопасным относительно исключений; перед уничтожением, предположительно, следует вызвать StopOffer(), чтобы корректно завершить незавершенные пересылки в Diagnostic Manager.

Путь использования

Штатная процедура предоставления и обработки диагностических запросов на чтение следует определенной последовательности шагов:

  1. Конструирование: приложение создает экземпляр производного DID-класса и связывает его через instanceSpec со смоделированным прототипом порта ([SWS_DM_00585]).
  2. Предоставление: приложение вызывает Offer() ([SWS_DM_00599]). Метод возвращает ara::core::Result<void>, указывающий на успешность регистрации в Diagnostic Manager.
  3. Обработка: если в Diagnostic Manager поступает UDS-запрос на чтение для этого DID, он делегирует вызов виртуальному методу Read(metaInfo, cancellationHandler) ([SWS_DM_00640]). При запросах на запись DM аналогично вызывает Write(..., metaInfo, cancellationHandler) ([SWS_DM_00598]).
  4. Обработка отмены и возврат: во время асинхронного выполнения реализация может через cancellationHandler.IsCanceled() проверить, был ли отменен диалог, или через cancellationHandler.SetNotifier(...) зарегистрировать уведомитель ([SWS_DM_00640], [SWS_DM_00598]). Результат предоставляется в виде ara::core::Future, который в случае успеха содержит сгенерированный выходной объект <DataIdentifier>ReadOutput с выходными аргументами ([SWS_DM_00579], [SWS_DM_80013]).
  5. Отмена регистрации: если служба больше не требуется, приложение вызывает StopOffer() ([SWS_DM_00600]).

Диаграмма последовательности: последовательность выполнения UDS-запроса на чтение через Offer, Read и StopOffer. Источники: [SWS_DM_00599], [SWS_DM_00640], [SWS_DM_00600]

Сценарии ошибок

Ошибки могут возникать при инициализации, при предоставлении службы, а также во время обработки методов:

  • Нарушения при конструировании: если разрешение или связывание InstanceSpecifier в модели завершается сбоем, фреймворк генерирует определенные violations ([SWS_DM_00585]):
    • InstanceSpecifierMappingIntegrityViolation: идентификатор не может быть разрешен в контексте исполняемого файла или не ссылается на PortPrototype.
    • PortInterfaceMappingViolation: PortPrototype, типизированный с помощью DiagnosticDataIdentifierInterface, не упоминается в DiagnosticDataPortMapping.
    • ProcessMappingViolation: во время выполнения отсутствует подходящий смоделированный процесс для существующего InstanceRef.
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже используется другим вызовом конструктора внутри этого процесса.
  • Ошибки при Offer: если служба уже предложена, Offer() завершается сбоем и возвращает ara::core::Result с кодом ошибки ara::diag::DiagOfferErrc::kAlreadyOffered ([SWS_DM_00599]).
  • Ошибки обработки и ошибки UDS: если запрос на чтение или запись не может быть успешно выполнен, обработчик устанавливает возвращаемый ara::core::Future в соответствующий Negative Response Code (NRC) через ara::diag::DiagUdsNrcErrc согласно ISO 14229-1 или в ApApplicationError ([SWS_DM_00640], [SWS_DM_00598]).

Данное руководство по классам основано на спецификации AUTOSAR Adaptive Platform R25-11 (модуль diag) и обобщает контекст, жизненный цикл, шаблоны взаимодействия и сценарии ошибок.

<h4>Контекст</h4>
<p>C++-класс <code>&lt;DataIdentifierInterface&gt;</code> служит в модуле <code>diag</code> платформы AUTOSAR Adaptive Platform серверным базовым интерфейсом для идентификаторов диагностических данных (Data Identifier, DID) согласно ISO 14229-1 (UDS). Интерфейс определяет стандартизированный мост между управлением диагностикой платформы и специфичными для приложения подпрограммами предоставления или обновления диагностических данных.</p>
<p>Во взаимодействии обычно участвуют три ключевых компонента:</p>
<ul>
<li><strong>Diagnostic Manager (DM):</strong> принимает запросы диагностических служб UDS (таких как служба 0x22 <em>ReadDataByIdentifier</em> или служба 0x2E <em>WriteDataByIdentifier</em>) от внешних диагностических тестеров и перенаправляет их соответствующему зарегистрированному экземпляру интерфейса (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>, <a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>).</li>

<li><strong>Диагностический тестер (клиент):</strong> отправляет UDS-запросы в электронный блок управления автомобиля и принимает ответы, агрегированные Diagnostic Manager.</li>
</ul>

<h4>Жизненный цикл</h4>
<p>Создание экземпляра выполняется через параметризованный конструктор с передачей <code>ara::core::InstanceSpecifier</code>, а также режима <code>ara::diag::ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>). Через тип конкурентности вызывающая сторона указывает, рассчитана ли реализация как потокобезопасная (<code>kConcurrent</code>) или непотокобезопасная (<code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</p>
<p>Экземпляры <code>&lt;DataIdentifierInterface&gt;</code> обладают уникальной идентичностью и не могут быть ни скопированы, ни перемещены. Соответственно, конструктор копирования (<a class="spec-record-ref" data-req="SWS_DM_01665" href="../spec/record.html?id=SWS_DM_01665">[SWS_DM_01665]</a>), конструктор перемещения (<a class="spec-record-ref" data-req="SWS_DM_01666" href="../spec/record.html?id=SWS_DM_01666">[SWS_DM_01666]</a>), а также соответствующие операторы присваивания (<a class="spec-record-ref" data-req="SWS_DM_01663" href="../spec/record.html?id=SWS_DM_01663">[SWS_DM_01663]</a>, <a class="spec-record-ref" data-req="SWS_DM_01664" href="../spec/record.html?id=SWS_DM_01664">[SWS_DM_01664]</a>) удалены (<code>=delete</code>).</p>
<p>В отношении состояний службы класс различает две фазы:</p>
<ul>
<li><strong>Неактивно (не предлагается):</strong> после конструирования объект присутствует локально, но не принимает диагностические запросы.</li>
<li><strong>Активно (предлагается):</strong> только явный вызов метода <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>) активирует пересылку запросов через Diagnostic Manager этому экземпляру.</li>
<li><strong>Деактивировано:</strong> вызовом <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>) пересылка прерывается, и экземпляр снова переходит в неактивное состояние.</li>
</ul>
<p>Уничтожение выполняется через виртуальный деструктор <code>~&lt;DataIdentifierInterface&gt;()</code> (<a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>). Он не является потокобезопасным и не является безопасным относительно исключений; перед уничтожением, предположительно, следует вызвать <code>StopOffer()</code>, чтобы корректно завершить незавершенные пересылки в Diagnostic Manager.</p>

<h4>Путь использования</h4>
<p>Штатная процедура предоставления и обработки диагностических запросов на чтение следует определенной последовательности шагов:</p>
<ol>
<li><strong>Конструирование:</strong> приложение создает экземпляр производного DID-класса и связывает его через <code>instanceSpec</code> со смоделированным прототипом порта (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</li>
<li><strong>Предоставление:</strong> приложение вызывает <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>). Метод возвращает <code>ara::core::Result&lt;void&gt;</code>, указывающий на успешность регистрации в Diagnostic Manager.</li>
<li><strong>Обработка:</strong> если в Diagnostic Manager поступает UDS-запрос на чтение для этого DID, он делегирует вызов виртуальному методу <code>Read(metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>). При запросах на запись DM аналогично вызывает <code>Write(..., metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
<li><strong>Обработка отмены и возврат:</strong> во время асинхронного выполнения реализация может через <code>cancellationHandler.IsCanceled()</code> проверить, был ли отменен диалог, или через <code>cancellationHandler.SetNotifier(...)</code> зарегистрировать уведомитель (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>). Результат предоставляется в виде <code>ara::core::Future</code>, который в случае успеха содержит сгенерированный выходной объект <code>&lt;DataIdentifier&gt;ReadOutput</code> с выходными аргументами (<a class="spec-record-ref" data-req="SWS_DM_00579" href="../spec/record.html?id=SWS_DM_00579">[SWS_DM_00579]</a>, <a class="spec-record-ref" data-req="SWS_DM_80013" href="../spec/record.html?id=SWS_DM_80013">[SWS_DM_80013]</a>).</li>
<li><strong>Отмена регистрации:</strong> если служба больше не требуется, приложение вызывает <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>).</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>Ошибки могут возникать при инициализации, при предоставлении службы, а также во время обработки методов:</p>
<ul>
<li><strong>Нарушения при конструировании:</strong> если разрешение или связывание <code>InstanceSpecifier</code> в модели завершается сбоем, фреймворк генерирует определенные violations (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>):
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: идентификатор не может быть разрешен в контексте исполняемого файла или не ссылается на PortPrototype.</li>
  <li><code>PortInterfaceMappingViolation</code>: PortPrototype, типизированный с помощью <code>DiagnosticDataIdentifierInterface</code>, не упоминается в <code>DiagnosticDataPortMapping</code>.</li>
  <li><code>ProcessMappingViolation</code>: во время выполнения отсутствует подходящий смоделированный процесс для существующего <code>InstanceRef</code>.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: <code>InstanceSpecifier</code> уже используется другим вызовом конструктора внутри этого процесса.</li>
  </ul>
</li>
<li><strong>Ошибки при Offer:</strong> если служба уже предложена, <code>Offer()</code> завершается сбоем и возвращает <code>ara::core::Result</code> с кодом ошибки <code>ara::diag::DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>).</li>
<li><strong>Ошибки обработки и ошибки UDS:</strong> если запрос на чтение или запись не может быть успешно выполнен, обработчик устанавливает возвращаемый <code>ara::core::Future</code> в соответствующий Negative Response Code (NRC) через <code>ara::diag::DiagUdsNrcErrc</code> согласно ISO 14229-1 или в <code>ApApplicationError</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
</ul>
