Позволяет приложению отвечать на диагностические запросы чтения и записи для конкретных идентификаторов данных.

Интерфейс <DataIdentifier-Namespace>::<DataIdentifierInterface> позволяет адаптивным приложениям предоставлять специфичные для модели диагностические идентификаторы данных для Diagnostic Management [SWS_DM_00585]. После создания Offer() активирует пересылку запросов, которые асинхронно обрабатываются через Read() или Write() и при необходимости получают ответ с кодами ошибок UDS [SWS_DM_00599] [SWS_DM_00640]. Поскольку экземпляр не подлежит ни копированию, ни перемещению, служба перед уничтожением явно завершается через StopOffer() [SWS_DM_01665] [SWS_DM_00600].

Контекст

C++-класс <DataIdentifier-Namespace>::<DataIdentifierInterface> функционирует как функциональный интерфейс для диагностических идентификаторов данных (Data Identifiers, DID) в модуле diag Adaptive Platform SWS Diagnostics с. 68. Он связывает уровень адаптивных приложений с центральным Diagnostic Management (DM). Diagnostic Management принимает внешние диагностические запросы и перенаправляет их зарегистрированному экземпляру [SWS_DM_00599]. Прикладное программное обеспечение через производные классы предоставляет конкретную реализацию для запроса или обновления содержимого данных посредством операций чтения или записи [SWS_DM_00640] [SWS_DM_00598].

Жизненный цикл

Создание осуществляется через параметризованный конструктор с передачей ara::core::InstanceSpecifier и режима параллелизма ara::diag::ConcurrencyType [SWS_DM_00585]. Последний определяет, разрешено ли обрабатывать вызовы экземпляра параллельно (kConcurrent) или не параллельно (kNotConcurrent) [SWS_DM_00585]. Поскольку экземпляр жёстко привязан к конфигурации своей модели, как конструктор копирования, так и конструктор перемещения явно удалены [SWS_DM_01665] [SWS_DM_01666]; то же самое относится к операторам присваивания копированием и перемещением [SWS_DM_01663] [SWS_DM_01664].

После инстанцирования интерфейс находится в неактивном состоянии. Только после вызова Offer() активируется пересылка диагностических запросов со стороны Diagnostic Management [SWS_DM_00599]. Метод StopOffer() снова прекращает эту пересылку [SWS_DM_00600]. Освобождение ресурсов выполняется через виртуальный деструктор [SWS_DM_00586]. Интерпретация: перед уничтожением объекта обычно должен вызываться StopOffer(), чтобы упорядоченно предотвратить незавершённые или вновь поступающие пересылки от DM. Вопрос Q-3710c559625978c9 (открытый)

Путь использования

Штатная процедура включает в себя инстанцирование, регистрацию службы, асинхронную обработку запросов и последующую деактивацию:

  1. Инстанцирование: приложение создаёт экземпляр интерфейса с указанием InstanceSpecifier и требуемой настройки ConcurrencyType [SWS_DM_00585].
  2. Активация службы: приложение вызывает Offer(), благодаря чему Diagnostic Management может доставлять запросы этому обработчику [SWS_DM_00599].
  3. Обработка запроса: при операциях чтения DM вызывает чисто виртуальный метод Read() [SWS_DM_00640], при операциях записи — Write() [SWS_DM_00598]. Через переданный cancellationHandler приложение может отслеживать события отмены. Результаты предоставляются асинхронно в виде ara::core::Future, который в случае Read() содержит объект ReadOutput с выходными данными [SWS_DM_00579] [SWS_DM_00640] [SWS_DM_80013].
  4. Завершение службы: вызовом StopOffer() пересылка останавливается [SWS_DM_00600] перед тем, как объект будет уничтожен [SWS_DM_00586].

Диаграмма последовательности: типичный процесс предоставления DID от инициализации через асинхронный ответ на запросы до деактивации. Источники: [SWS_DM_00585], [SWS_DM_00599], [SWS_DM_00640], [SWS_DM_00600], [SWS_DM_00586].

Сценарии ошибок

Ошибки моделирования могут приводить к нарушениям уже при создании объекта: при отсутствии связей портов или процессов возникают InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation или ProcessMappingViolation [SWS_DM_00585]. Если один и тот же InstanceSpecifier повторно используется в том же процессе, фреймворк сообщает о InstanceSpecifierAlreadyInUseViolation [SWS_DM_00585].

Если Offer() вызывается, когда служба уже предлагается, вызов завершается неудачей и через ara::core::Result возвращает код ошибки DiagOfferErrc::kAlreadyOffered [SWS_DM_00599]. Если выполнение Read() или Write() завершается сбоем, реализация передаёт ошибки асинхронно в Future с помощью кодов ошибок UDS по ISO 14229-1 (DiagUdsNrcErrc) или специфичных для приложения ApApplicationError [SWS_DM_00640] [SWS_DM_00598]. Что касается безопасности исключений, конструктор и методы обработки специфицированы как exception safe [SWS_DM_00585] [SWS_DM_00599] [SWS_DM_00640] [SWS_DM_00598], тогда как деструктор не обозначен как exception safe [SWS_DM_00586].

Настоящее руководство опирается на спецификацию AUTOSAR для Adaptive Platform (релиз R25-11).

Использование

Функция-конструктор <DataIdentifierInterface> служит для создания экземпляра идентификатора данных из ara::core::InstanceSpecifier [SWS_DM_00585]. Объявление выполняется внутри пространства имен <DataIdentifier-Namespace> через заголовочный файл #include "<DataIdentifierDirectoryPath>/<DataIdentifierShortname>.h" [SWS_DM_00585]. Синхронный вызов специфицирован как noexcept и обладает свойствами «exception safe» и «thread-safe» [SWS_DM_00585].

Функция принимает следующие входные параметры [SWS_DM_00585]:

  • instanceSpec (ara::core::InstanceSpecifier): идентификатор конкретного экземпляра службы [SWS_DM_00585].
  • concurrencyType (ara::diag::ConcurrencyType): определяет, работает ли интерфейс потокобезопасно с kConcurrent или непотокобезопасно с kNotConcurrent [SWS_DM_00585].

Обработка ошибок и правила моделирования

Функция не возвращает значения и не генерирует исключений. Ошибки в конфигурации или моделировании приводят вместо этого к определенным нарушениям (violations) [SWS_DM_00585]:

  • InstanceSpecifierMappingIntegrityViolation: instanceSpec не может быть разрешен в контексте исполняемого файла или не указывает на PortPrototype [SWS_DM_00585].
  • PortInterfaceMappingViolation: PortPrototype, типизированный через DiagnosticDataIdentifierInterface, не ссылается на DiagnosticDataPortMapping [SWS_DM_00585].
  • ProcessMappingViolation: для ссылки на экземпляр отсутствует подходящий смоделированный процесс для текущего процесса времени выполнения [SWS_DM_00585].
  • InstanceSpecifierAlreadyInUseViolation: конструктор был вызван с instanceSpec, который уже используется в текущем процессе [SWS_DM_00585].

Интерпретация: поскольку функция объявлена как noexcept, обнаруженные нарушения, вероятно, обрабатываются внутри фреймворка как критические ошибки инициализации. Вопрос Q-8616025446bf33f2 (открытый)

Параллелизм

Сама функция-конструктор выполнена потокобезопасной [SWS_DM_00585]. Через аргумент concurrencyType регулируется, разрешены ли последующие параллельные вызовы интерфейса данного экземпляра [SWS_DM_00585].

Это указание по использованию было сгенерировано автоматически на основе спецификации.

              Использование и контекст вызова

Интерпретация: вызов, вероятно, обычно должен выполняться во время фазы инициализации приложения, поскольку DM не может доставлять запросы до предоставления.
