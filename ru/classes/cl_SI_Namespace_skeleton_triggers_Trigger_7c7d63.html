Позволяет Service-Skeleton отправлять триггерные сигналы и отслеживать статус подписчиков.

Класс <SI-Namespace>::skeleton::triggers::<Trigger> позволяет серверному приложению отправлять триггерные сигналы подписанным клиентам через Communication Management ([SWS_CM_00721]). Для управления последовательностью выполнения можно отслеживать статус подписчиков и регистрировать обработчики уведомлений ([SWS_CM_01109], [SWS_CM_01110]). Инициирование через Send() требует предоставленного Service-Skeleton и подтверждает нарушения минимальных интервалов отправки или сетевые ошибки соответствующими кодами ошибок ([SWS_CM_00721], [SWS_CM_10517]).

Контекст

Шаблонный класс <SI-Namespace>::skeleton::triggers::<Trigger> представляет собой интерфейс триггера на стороне сервера, который определен внутри ServiceInterface в роли trigger. Являясь составной частью скелета сервиса (Skeleton), этот класс служит экземпляру сервиса для отправки асинхронных уведомлений или сигналов запуска подписанным клиентским приложениям во всей системе. Триггер отличается от обычных событий тем, что функционирует преимущественно как чисто сигнальное событие без сложных полезных данных, как показывает классификация в EXP_ARAComAPI §3 «Trigger::Send» и SWS_CommunicationManagement §7.2.2.1.4 «Handling Triggers». Стороны взаимодействия включают предоставляющее серверное приложение, связующее программное обеспечение Communication Management (ara::com), а также подключенных по сети клиентов-подписчиков (Subscriber).

Жизненный цикл

Инстанцирование объектов триггера обычно выполняется как неотъемлемая часть экземпляра Skeleton соответствующего ServiceInterface. Перед активным использованием Skeleton должен быть предложен через Communication Management; при попытке инициировать триггер до этого передача завершается неудачей ([SWS_CM_00721]). Класс управляет состоянием подписки подписчиков через ara::com::SubscriptionState, которое в любой момент можно запросить с помощью GetSubscriptionState() ([SWS_CM_01109]). Для асинхронного мониторинга состояния с помощью SetSubscriptionStateChangeHandler() можно зарегистрировать функцию обратного вызова ([SWS_CM_01110]). Для параллельных архитектур существует перегрузка, принимающая пользовательский Executor, благодаря чему уведомления выполняются в желаемом контексте потока или задачи ([SWS_CM_01111]). Регистрацию можно отменить через UnsetSubscriptionStateChangeHandler() ([SWS_CM_01112]). Все методы класса обеспечивают гарантию безопасности исключений noexcept (exception safe).

Путь использования

Типичный порядок использования триггера включает наблюдение за статусом подписки, а также непосредственную инициацию передачи всем активным подписчикам:

  • Регистрация обработчика: сервисное приложение опционально регистрирует обработчик состояния через SetSubscriptionStateChangeHandler() ([SWS_CM_01110], [SWS_CM_01111]), чтобы получать информацию о вновь появляющихся подписчиках.
  • Проверка состояния: с помощью GetSubscriptionState() сервер проверяет наличие хотя бы одного активного подписчика ([SWS_CM_01109]), что согласно [SWS_CM_10518] является предварительным условием для запроса на отправку.
  • Отправка триггера: отправка инициируется вызовом Send() ([SWS_CM_00721], EXP_ARAComAPI §3 «Trigger::Send»), после чего Communication Management распределяет сигнал по всем подписанным приложениям.
  • Отмена регистрации: при завершении работы или если уведомления о состоянии больше не требуются, вызывается UnsetSubscriptionStateChangeHandler() ([SWS_CM_01112]).

Диаграмма последовательности: типичный процесс передачи триггера с мониторингом подписки. Источники: [SWS_CM_01110], [SWS_CM_01109], [SWS_CM_00721], SWS_CommunicationManagement §7.2.2.1.4.

Сценарии ошибок

Метод Send() возвращает ara::core::Result<void>, посредством которого передаются возможные ошибки отправки и конфигурации ([SWS_CM_00721]):

  • ComErrc::kServiceNotOffered: возникает, если экземпляр сервиса еще не был предоставлен через OfferService() ([SWS_CM_00721]).
  • ComErrc::kMinimumSendIntervalViolationError: возвращается, если нарушен сконфигурированный минимальный интервал отправки (minimumSendInterval) между последовательными передачами ([SWS_CM_00721]).
  • ComErrc::kCommunicationFailure: выдается, если локальная отправка триггера завершается сбоем из-за базовой сетевой ошибки ([SWS_CM_10517]).
  • Недопустимый обработчик (InvalidHandlerViolation): передача отсутствующего или пустого вызываемого объекта (Callable) в SetSubscriptionStateChangeHandler() представляет собой нарушение условий контракта API ([SWS_CM_01110], [SWS_CM_01111]).

Настоящее руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform выпуска R25-11.

          Функция SetSubscriptionStateChangeHandler служит на стороне скелетона для регистрации функции обратного вызова для мониторинга изменений подписки на триггере [SWS_CM_01110]. Метод относится к пространству имен <SI-Namespace>::skeleton::triggers::<Trigger> и предоставляется через заголовочный файл <SiNamespaceDerivedDirectoryPath>/<SiShortname>_skeleton.h [SWS_CM_01110].
          

          В качестве параметра передается вызываемый функциональный объект типа SubscriptionStateChangeHandler [SWS_CM_00311] [SWS_CM_01110]. Вызов объявлен как noexcept, не возвращает значения и специфицирован как безопасный относительно исключений (exception safe) [SWS_CM_01110]. Если переданный вызываемый объект обработчика не существует или равен null, система сообщает о InvalidHandlerViolation [SWS_CM_01110].
          

          Communication Management вызывает зарегистрированную функцию обратного вызова, как только изменяется статус подписки триггера [SWS_CM_01101]:
          

            

          • со значением статуса kSubscribed, как только количество активных подписок для этого триггера становится больше 0 [SWS_CM_01102],
            • 

          • со значением статуса kNotSubscribed на стороне скелетона, когда активные подписки больше отсутствуют [SWS_CM_01103].
            • 

          

          Зарегистрированный обработчик разрешается перезаписывать во время выполнения [SWS_CM_01101]. Если выполнение обработчика должно происходить в определенном контексте выполнения, в качестве альтернативы доступен перегруженный шаблонный вариант с параметром ExecutorT&& [SWS_CM_01111].

              Шаблонная функция SetSubscriptionStateChangeHandler регистрирует на уровне скелетона для триггеров ([SWS_CM_01111]) обработчик обратного вызова для изменений статуса подписки (ara::com::SubscriptionState). Помимо вызываемого параметра handler, метод принимает контекст выполнения executor типа ExecutorT ([SWS_CM_01111]). Функция не имеет возвращаемого значения и определена в области видимости <SI-Namespace>::skeleton::triggers::<Trigger> ([SWS_CM_01111]).
              

              В отличие от базовой функции без исполнителя ([SWS_CM_01110]), данная сигнатура гарантирует, что обратный вызов будет выполнен в пользовательском контексте ([SWS_CM_01111]). Как и в случае событийно-ориентированного варианта согласно [SWS_CM_12008], выполнение, вероятно, делегируется переданному объекту-исполнителю для адресного управления потоками внутри скелетон-приложения.
              

              Интерфейс специфицирован как noexcept и безопасный относительно исключений ([SWS_CM_01111]). Если переданный вызываемый объект недействителен или равен null, согласно спецификации имеет место InvalidHandlerViolation ([SWS_CM_01111]).
              

              Функционально метод соответствует аналогичным перегрузкам с исполнителем для скелетон-событий ([SWS_CM_12009]), а также клиентским эквивалентам прокси-интерфейса ([SWS_CM_01106], [SWS_CM_11354]).
