Обеспечивает пошаговое построение и финализацию динамических списков прав доступа для диагностических служб.

Класс служит для пошагового создания динамических списков прав доступа для диагностических служб через связываемый в цепочку Fluent API ([SWS_DM_01166]). Приложения добавляют точные байты, диапазоны значений, а также подстановочные знаки (wildcards) для гибкого определения шаблонов доступа для Diagnostic Server ([SWS_DM_01175], [SWS_DM_01220]). Перед уничтожением непотокобезопасного объекта, допускающего только перемещение (move-only), необходимо обязательно вызвать метод Build() для завершения конфигурации ([SWS_DM_01181]).

Контекст

Класс ara::diag::DynamicAccessListDiagServiceBuilder служит приложениям AUTOSAR Adaptive Platform для пошагового конструирования динамических списков прав доступа (DynamicAccessList) для диагностических служб ([SWS_DM_01166], AUTOSAR_AP_SWS_Diagnostics §8.15.1 «Class: DynamicAccessListDiagServiceBuilder»). С помощью этих списков приложение управляет тем, какие диагностические запросы (например, конкретные службы UDS с определенными DID или подфункциями) динамически авторизуются во время выполнения (AUTOSAR_AP_SWS_Diagnostics §8.2 «Adding wildcards to a DynamicAccessList»).

Центральными участниками взаимодействия являются само приложение, фабричные методы класса ara::diag::DiagnosticServiceDynamicAccessList ([SWS_DM_01164], [SWS_DM_01165]), а также экземпляр Diagnostic Server, который оценивает сформированные битовые и байтовые шаблоны при проверке прав служб относительно входящих запросов ([SWS_DM_01220], [SWS_DM_01221]). Для представления структур шаблонов класс предоставляет псевдонимы типов Byte для отдельных октетов (std::uint8_t) и ByteString для последовательностей байтов (ara::core::Span<Byte>) ([SWS_DM_01167], [SWS_DM_01168], AUTOSAR_AP_SWS_Diagnostics §8.15.1.1 «Public Member Types»).

Жизненный цикл

Объект builder обычно инстанциируется через DiagnosticServiceDynamicAccessList::MakeServiceBuilder ([SWS_DM_01164], [SWS_DM_01165]) или напрямую через конструктор, принимающий начальное значение, а также ссылку на буфер сериализации content (ara::core::Vector<std::uint8_t>&) ([SWS_DM_01169]). Интерпретация: параметр content, предположительно, служит последовательно заполняемой памятью для сериализованного представления, которое после завершения передается в Diagnostic Server.

В отношении владения и копируемости класс обеспечивает строгую семантику перемещения (move-only) с ограниченным присваиванием: конструктор копирования ([SWS_DM_01171]) и оператор присваивания копированием ([SWS_DM_01172]) удалены (=delete). Также удален оператор присваивания перемещением ([SWS_DM_01173]). Реализован только конструктор перемещения ([SWS_DM_01170]), благодаря чему экземпляры могут при необходимости перемещаться, но не могут неконтролируемо дублироваться или повторно присваиваться.

Жизненный цикл подчиняется обязательному постусловию: перед вызовом деструктора ([SWS_DM_01174]) необходимо вызвать метод Build(), чтобы завершить создание списка ([SWS_DM_01181]). В то время как конструкторы специфицированы как потокобезопасные ([SWS_DM_01169], [SWS_DM_01170]), все методы расширения шаблона, а также деструктор являются непотокобезопасными (not thread-safe, [SWS_DM_01174]).

Диаграмма состояний: фазы жизненного цикла builder от создания через пошаговое построение шаблона до обязательной финализации перед уничтожением. Источники: [SWS_DM_01169], [SWS_DM_01175], [SWS_DM_01181], [SWS_DM_01174].

Путь использования

Конфигурирование шаблона осуществляется через Fluent API, в котором вызовы методов возвращают ссылку на тот же экземпляр builder ([SWS_DM_01175]):

  1. Инициализация: приложение создает builder, например, через DiagnosticServiceDynamicAccessList::MakeServiceBuilder с вводным байтом или байтовой строкой ([SWS_DM_01164], [SWS_DM_01165]).
  2. Расширение шаблона: с помощью перегруженных методов Add() добавляются отдельные байты ([SWS_DM_01175]), последовательности байтов ([SWS_DM_01176]) или замкнутые диапазоны значений ByteRange ([SWS_DM_01177]). Эти значения проверяются на точное совпадение при последующей оценке.
  3. Вставка подстановочных знаков: с помощью Any(numberOfBytesToIgnore) приложение определяет заполнители ([SWS_DM_01178]). Diagnostic Server игнорирует указанное количество байтов при сопоставлении шаблона, что позволяет реализовать гибкие фильтры, такие как 22F1XX для диапазонов DID ([SWS_DM_01220], AUTOSAR_AP_SWS_Diagnostics §8.2 «Adding wildcards to a DynamicAccessList»).
  4. Завершение и финализация шаблона: с помощью EndsWith() можно задать завершающий байт или диапазон ([SWS_DM_01179], [SWS_DM_01180], [SWS_DM_01221]). В завершение вызов Build() окончательно закрывает процесс создания ([SWS_DM_01181]).

Диаграмма последовательности: типичная последовательность взаимодействия между приложением, фабричным методом и builder при определении шаблона. Источники: [SWS_DM_01165], [SWS_DM_01175], [SWS_DM_01178], [SWS_DM_01181].

Сценарии ошибок

Все методы класса объявлены с noexcept и специфицированы как безопасные относительно исключений (exception safe) ([SWS_DM_01169], [SWS_DM_01174], [SWS_DM_01181]). Обработка ошибок через исключения C++ или возвращаемые значения ошибок на уровне API не осуществляется.

Существенное контрактное предусловие заключается в вызове Build() перед уничтожением builder ([SWS_DM_01181]). Интерпретация: если объект builder уничтожается без выполнения Build(), начатая конфигурация шаблона, вероятно, отбрасывается или оставляет недопустимое состояние в базовом списке доступа.

Кроме того, модифицирующие функции не являются потокобезопасными ([SWS_DM_01175], [SWS_DM_01178], [SWS_DM_01181]). Незащищенный параллельный доступ к одному и тому же экземпляру builder из нескольких потоков приводит к неопределенным состояниям памяти (гонкам данных).

Настоящее руководство основано исключительно на спецификации AUTOSAR Adaptive R25-11.

Использование

Синхронный метод Add класса ara::diag::DynamicAccessListDiagServiceBuilder служит для добавления одного байта (Byte value) к DynamicAccessListPattern [SWS_DM_01175]. Переданное значение байта проверяется на точное совпадение при оценке прав доступа для диагностических сервисов [SWS_DM_01175]. Возвращая ссылку на экземпляр того же объекта (DynamicAccessListDiagServiceBuilder&), функция поддерживает вызов в стиле Fluent API [SWS_DM_01175].

Обработка ошибок и безопасность исключений

Операция объявлена как noexcept и специфицирована как безопасная относительно исключений (exception safe) [SWS_DM_01175]. Не возвращаются ни коды ошибок, ни возвращаемые значения типа ara::core::Result; специфические сообщения DET или DEM в полезной нагрузке для этой функции не указаны.

Параллелизм и ограничения

Метод специфицирован как непотокобезопасный (not thread-safe) [SWS_DM_01175]. Интерпретация: вызовы для одного и того же экземпляра строителя (Builder), следовательно, обычно должны выполняться последовательно внутри одного потока до того, как созданный шаблон доступа будет оцениваться в сервере диагностики.

Взаимодействие

Внутри интерфейса DynamicAccessListDiagServiceBuilder этот метод дополняет родственные перегрузки Add, с помощью которых к DynamicAccessListPattern могут добавляться последовательности байтов через ByteString [SWS_DM_01176] или диапазоны значений через ByteRange [SWS_DM_01177].

              Использование
              
  
              Метод ara::diag::DynamicAccessListDiagServiceBuilder::Any служит прикладному программному обеспечению для определения подстановочных знаков (wildcards) в шаблоне доступа ([SWS_DM_01178]). Синхронный вызов выполняется на экземпляре строителя (builder). С помощью параметра numberOfBytesToIgnore определяется, сколько последовательных байтов хотя и включается в шаблон доступа, однако игнорируется при последующем сопоставлении с шаблоном (pattern matching) со входящими диагностическими запросами ([SWS_DM_01220]). Благодаря возврату ссылки на тот же объект строителя обеспечивается текучий (fluent) стиль вызова API (AUTOSAR_AP_SWS_Diagnostics §8.15.1.2.3.4 «Any»).
              

  
              Обработка ошибок и поведение при исключениях
              
  
              Функция специфицирована как noexcept и безопасная относительно исключений (exception safe) ([SWS_DM_01178]). Не предусмотрено ни кодов ошибок, ни обратных сообщений в DET или DEM. Интерпретация: при передаче значения 0 для numberOfBytesToIgnore вызов, вероятно, завершается без ошибки и не регистрирует байты подстановочных знаков в шаблоне.
              

  
              Параллелизм и ограничения
              
  
              Интерфейс явно указан как непотокобезопасный (not thread-safe) ([SWS_DM_01178]). Поэтому несколько вызовов строителя на одном и том же экземпляре DynamicAccessListDiagServiceBuilder обязательно должны выполняться последовательно или синхронизироваться вызывающей стороной.
              

  
              Взаимодействие
              
  
              Определения плейсхолдеров через Any обычно комбинируются с такими шаблонами, как EndsWith ([SWS_DM_01221]). После компоновки всех составных частей шаблона конфигурация должна быть финализирована методом Build ([SWS_DM_01222]), прежде чем результирующий список доступа станет доступен для верификаций (AUTOSAR_AP_SWS_Diagnostics §7.3.2 «Adding wildcards to a DynamicAccessList»).
