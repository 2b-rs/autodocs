Контекст

Класс ara::tsync::SynchronizedTimeBaseConsumer представляет собой центральный интерфейс для приложений на Adaptive Platform для доступа к синхронизированной базе времени, которая адресуется через идентификатор экземпляра (ara::core::InstanceSpecifier). Потребитель позволяет считывать текущий момент времени, отклонение скорости хода часов, текущее состояние, а также принятые пользовательские данные.

В системной архитектуре этот класс является посредником между использующим прикладным программным обеспечением и подсистемой Tsync:

  • Прикладное программное обеспечение: использует экземпляр либо для циклического опроса состояния и времени, либо асинхронно реагирует на сконфигурированные события базы времени.
  • SynchronizedTimeBaseConsumer: управляет системно-специфичной привязкой к порту и инкапсулирует логику опроса и уведомителей.
  • Подсистема Tsync / база времени: предоставляет синхронизированные временные метки, информацию о состоянии и блоки данных валидации.

Жизненный цикл

Экземпляр SynchronizedTimeBaseConsumer создается с помощью явного конструктора [SWS_TS_01001] с указанием ara::core::InstanceSpecifier. Этот конструктор специфицирован как безопасный к исключениям (exception safe) и потокобезопасный (thread-safe).

В отношении владения объектом класс обеспечивает строгую семантику перемещения:

  • Конструктор копирования [SWS_TS_01005] и оператор присваивания с копированием [SWS_TS_01006] удалены (=delete), что предотвращает дублирование экземпляров потребителя.
  • Операции перемещения с помощью конструктора перемещения [SWS_TS_01003] и оператора присваивания с перемещением [SWS_TS_01004] поддерживаются. Обе операции являются noexcept, однако классифицированы как непотокобезопасные (non_threadsafe).

Уничтожение выполняется через деструктор [SWS_TS_01002], который также является noexcept, но non_threadsafe. Интерпретация: во избежание конфликтов параллелизма при уничтожении или повторном заполнении, зарегистрированные функции обратного вызова, вероятно, должны быть явно отменены перед окончанием жизненного цикла экземпляра с помощью соответствующих функций отмены регистрации.

Что касается параллелизма во время работы, следует отметить, что доступ только для чтения к базе времени ([SWS_TS_01008], [SWS_TS_01009]) является потокобезопасным, тогда как все вызовы регистрации и отмены регистрации для уведомителей (например, [SWS_TS_01010], [SWS_TS_01011]) классифицированы как non_threadsafe и требуют внешней синхронизации.

Путь использования

Типичный процесс использования синхронизированной базы времени подразделяется на инициализацию, конфигурацию событий, рабочие опросы и очистку:

  1. Создание экземпляра: создание объекта с подходящим InstanceSpecifier [SWS_TS_01001].
  2. Регистрация событий: приложение регистрирует по мере необходимости функции обратного вызова для релевантных изменений состояния:
    • RegisterStatusChangeNotifier [SWS_TS_01010] для общих изменений флагов состояния (статус синхронизации, скачки времени или пользовательские данные).
    • RegisterSynchronizationStateChangeNotifier [SWS_TS_01012] исключительно для смены состояния синхронизации.
    • RegisterTimeLeapNotifier [SWS_TS_01014] для отдельной обработки возникших скачков времени.
    • RegisterTimePrecisionMeasurementNotifier [SWS_TS_01018] при доступности новых снимков точности времени.
    • RegisterTimeValidationNotification [SWS_TS_01016] для приема блоков данных валидации базы времени.
  3. Рабочий опрос времени и состояния: приложение получает через GetTimeWithStatus [SWS_TS_01009] снимок состояния часов, содержащий флаги состояния, конфигурацию часов, а также локальные и синхронизированные значения времени. Текущее отклонение скорости хода часов можно запросить с помощью GetRateDeviation [SWS_TS_01008].
  4. Отмена регистрации: больше не требующиеся уведомления удаляются с помощью соответствующих аналогов: UnregisterStatusChangeNotifier [SWS_TS_01011], UnregisterSynchronizationStateChangeNotifier [SWS_TS_01013], UnregisterTimeLeapNotifier [SWS_TS_01015], UnregisterTimeValidationNotification [SWS_TS_01017] и UnregisterTimePrecisionMeasurementNotifier [SWS_TS_01019].

Диаграмма последовательности: типичный процесс регистрации уведомителя, опроса времени и отмены регистрации потребителя времени. Источники: [SWS_TS_01001], [SWS_TS_01009], [SWS_TS_01010], [SWS_TS_01011]

Сценарии ошибок

Все функции-члены SynchronizedTimeBaseConsumer определены как noexcept и exception safe. Ошибочные условия возникают преимущественно из-за некорректного моделирования или недопустимых контекстов вызова:

  • Неверная конфигурация интерфейса порта: если PortPrototype, на который ссылается TimeSyncPortPrototypeToTimeBaseMapping, не типизирован типом интерфейса SynchronizedTimeBaseConsumerInterface, при создании экземпляра возникает PortInterfaceMappingViolation [SWS_TS_01001].
  • Перезапись существующих уведомителей: для каждой категории событий одновременно может быть зарегистрирован максимум один уведомитель. Каждый повторный вызов функции регистрации ([SWS_TS_01010], [SWS_TS_01012], [SWS_TS_01014], [SWS_TS_01016], [SWS_TS_01018]) перезаписывает существующую регистрацию без предупреждения.
  • Потеря результатов измерений из-за отсутствия очереди: согласно [SWS_TS_01018], Tsync не выполняет никакого управления очередями (Queuing) для измерений точности времени. Если приложение не может немедленно обработать последовательные снимки, они должны буферизоваться внутри самого уведомителя, так как в противном случае вновь поступающие данные, вероятно, будут отброшены.
  • Нарушение потокобезопасности: поскольку регистрация и отмена регистрации уведомителя объявлены как non_threadsafe, параллельный вызов этих методов приводит к несогласованности данных при управлении функциями обратного вызова.
