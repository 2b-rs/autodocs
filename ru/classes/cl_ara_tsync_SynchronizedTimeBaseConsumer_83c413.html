Позволяет приложениям потокобезопасно опрашивать синхронизированные значения времени, а также регистрировать уведомители статуса.

Класс ara::tsync::SynchronizedTimeBaseConsumer позволяет приложениям времени получать доступ к синхронизированной базе времени ([SWS_TS_01001]), на которую ссылается ara::core::InstanceSpecifier. С помощью потокобезопасных методов приложения могут запрашивать актуальные моментальные снимки (снапшоты) значений времени и флагов статуса, а также отклонение хода часов ([SWS_TS_01009]). Кроме того, могут регистрироваться уведомители для изменений статуса, скачков времени, данных валидации и измерений точности, при этом на каждый тип события активна максимум одна регистрация. Операции копирования запрещены, поэтому экземпляры могут только перемещаться или освобождаться через свой деструктор.

Контекст

Класс ara::tsync::SynchronizedTimeBaseConsumer образует для приложений времени на Adaptive Platform интерфейс к синхронизированной базе времени, идентифицируемой через ara::core::InstanceSpecifier ([SWS_TS_01001]). Его основная задача состоит в предоставлении приложениям текущего момента времени опроса, отклонения хода часов ([SWS_TS_01008]), а также согласованных флагов статуса и полученных пользовательских данных ([SWS_TS_01009]). Основными партнерами по взаимодействию являются вызывающее прикладное ПО (Time Consumer Application), сам экземпляр потребителя и подсистема Tsync, собирающая данные синхронизации и инициирующая события уведомления ([SWS_TS_01016], [SWS_TS_01018]).

Жизненный цикл

Инстанцирование выполняется через явный конструктор с указанием ara::core::InstanceSpecifier ([SWS_TS_01001]). Этот конструктор классифицирован как потокобезопасный и бессбойный (exception-safe). Для управления ресурсами класс реализует строгую семантику перемещения: конструктор перемещения ([SWS_TS_01003]) и оператор присваивания с перемещением ([SWS_TS_01004]) допускают передачу владения, тогда как конструктор копирования ([SWS_TS_01005]) и оператор присваивания с копированием ([SWS_TS_01006]) явно удалены (=delete). Это предотвращает случайное дублирование доступа к одному и тому же ресурсу базы времени.

Деструктор освобождает экземпляр ([SWS_TS_01002]). В отношении параллелизма действует четкое разделение: в то время как конструктор ([SWS_TS_01001]) и методы опроса GetRateDeviation ([SWS_TS_01008]) и GetTimeWithStatus ([SWS_TS_01009]) выполнены потокобезопасными, все функции регистрации и дерегистрации, а также операции перемещения и деструктор специфицированы как непотокобезопасные (non_threadsafe).

Путь использования

Штатная последовательность использования включает фазы инициализации, регистрации соответствующих уведомителей, циклических или событийных опросов и финальной очистки:

  • Инициализация: приложение создает объект с подходящей спецификацией экземпляра порта ([SWS_TS_01001]).
  • Регистрация уведомителей: приложение регистрирует функции обратного вызова или объекты-уведомители для специфических событий:
    • общие изменения флагов статуса через RegisterStatusChangeNotifier ([SWS_TS_01010]),
    • изменения состояния синхронизации через RegisterSynchronizationStateChangeNotifier ([SWS_TS_01012]),
    • возникновение скачка времени через RegisterTimeLeapNotifier ([SWS_TS_01014]),
    • получение блоков данных валидации через RegisterTimeValidationNotification ([SWS_TS_01016]),
    • наличие измерений точности времени через RegisterTimePrecisionMeasurementNotifier ([SWS_TS_01018]).
    Для каждого типа уведомителя может быть активна максимум одна регистрация; каждая последующая регистрация перезаписывает предыдущую ([SWS_TS_01010], [SWS_TS_01018]).
  • Опрос во время работы: через GetTimeWithStatus() приложение запрашивает согласованный моментальный снимок (SynchronizedTimeBaseStatus) с флагами статуса, конфигурацией часов, а также локальными и синхронизированными значениями времени ([SWS_TS_01009]). С помощью GetRateDeviation() определяется текущее отклонение хода часов ([SWS_TS_01008]).
  • Очистка: перед удалением потребителя уведомители при необходимости дерегистрируются через соответствующие вызовы, такие как UnregisterStatusChangeNotifier ([SWS_TS_01011]), UnregisterSynchronizationStateChangeNotifier ([SWS_TS_01013]), UnregisterTimeLeapNotifier ([SWS_TS_01015]), UnregisterTimeValidationNotification ([SWS_TS_01017]) или UnregisterTimePrecisionMeasurementNotifier ([SWS_TS_01019]), до того как объект будет уничтожен ([SWS_TS_01002]).

Диаграмма последовательности: типичная последовательность инициализации, регистрации уведомителей, циклического опроса и очистки. Источники: [SWS_TS_01001], [SWS_TS_01008], [SWS_TS_01009], [SWS_TS_01010], [SWS_TS_01011], [SWS_TS_01002].

Сценарии ошибок

Все интерфейсные методы класса объявлены с noexcept и специфицированы как бессбойные (exception safe). Поэтому об ошибках не сообщается через исключения C++. Необходимо учитывать следующие граничные условия и нарушения конфигурации:

  • Ошибки конфигурации сопоставления портов: PortPrototype, на который ссылается TimeSyncPortPrototypeToTimeBaseMapping, обязательно должен быть типизирован через SynchronizedTimeBaseConsumerInterface; в противном случае возникает PortInterfaceMappingViolation ([SWS_TS_01001]).
  • Перезапись существующих обратных вызовов: при повторном вызове метода регистрации новый уведомитель перезаписывает ранее сохраненный обратный вызов без отдельного сообщения об ошибке ([SWS_TS_01010], [SWS_TS_01012], [SWS_TS_01014], [SWS_TS_01016], [SWS_TS_01018]).
  • Отсутствие очереди при измерениях точности: подсистема Tsync не выполняет промежуточного сохранения (буферизации в очередь) для данных измерений точности времени ([SWS_TS_01018]). Если уведомитель не может обработать данные вовремя, последующие измерения, предположительно, теряются, если приложение не предусматривает собственной буферизации в уведомителе.
  • Опасность гонок данных в методах уведомителей: поскольку операции регистрации и дерегистрации уведомителей указаны как непотокобезопасные, параллельный вызов из различных контекстов выполнения без внешних механизмов защиты может привести к несогласованным состояниям (интерпретация).

Его сигнатура имеет вид void UnregisterTimeValidationNotification () noexcept; [SWS_TS_01017]. Он не принимает параметров и не имеет возвращаемого значения. Согласно спецификации он служит приложениям-потребителям в контексте параметров синхронизации времени [SWS_TS_01017]. Интерпретация: судя по идентификатору, вызов, предположительно, служит для отмены регистрации ранее зарегистрированных уведомлений по валидации времени.
                                                          

  
                                                          Обработка ошибок и безопасность исключений
                                                          
  
                                                          Операция специфицирована как exception safe и объявлена с noexcept [SWS_TS_01017]. Она не генерирует исключений и не возвращает специфических кодов ошибок [SWS_TS_01017].
                                                          

  
                                                          Параллелизм
                                                          
  
                                                          Спецификация помечает метод как non_threadsafe [SWS_TS_01017]. Поэтому параллельный вызов нескольких операций на одном и том же экземпляре SynchronizedTimeBaseConsumer должен синхронизироваться со стороны приложения.
                                                          

  
                                                          Взаимодействие
