Служит для предоставления службы на стороне сервера и обработки входящих вызовов методов.

Класс <SI-Namespace>::skeleton::<SI>Skeleton служит серверной основой для предоставления службы в AUTOSAR Adaptive Platform и привязывает события, поля, а также методы к middleware. После инстанциации с идентификатором экземпляра служба становится доступной для потребителей в сети с помощью OfferService() и может быть отозвана с помощью StopOfferService() [SWS_CM_00101], [SWS_CM_00111]. В зависимости от сконфигурированного режима обработки входящие вызовы методов либо обрабатываются на основе событий, либо должны активно инициироваться приложением через опрос (polling). Поскольку операции копирования удалены, владение экземпляром строго сохраняется за создающим приложением службы.

Контекст

Шаблонный класс <SI-Namespace>::skeleton::<SI>Skeleton образует серверную конечную точку для предоставления Service Interface на AUTOSAR Adaptive Platform. Выступая связующим звеном между логикой приложения и уровнем связи, skeleton инкапсулирует специфическую для middleware привязку и предоставляет типизированные элементы интерфейса. Для этого класс объявляет переменные-члены для событий через events::<Event> [SWS_CM_99557], для полей через fields::<Field> [SWS_CM_99558], для триггеров через triggers::<Trigger> [SWS_CM_99559], а также для выходных параметров методов через <MethodOutArgType> [SWS_CM_11550]. Интерпретация: для предоставления фактической функциональности службы приложение службы, как правило, наследует конкретный класс от <SI>Skeleton для полной реализации методов интерфейса.

Жизненный цикл

Инстанциация skeleton осуществляется с заданием сопоставления экземпляра и режима обработки для вызовов методов (ara::com::MethodCallProcessingMode, по умолчанию kEvent). Допустимые конструкторы принимают ara::core::InstanceSpecifier [SWS_CM_00152], отдельный ara::com::InstanceIdentifier [SWS_CM_00130] или множество идентификаторов через ara::com::InstanceIdentifierContainer [SWS_CM_00153]. Поскольку идентичность конечной точки службы уникальна, конструктор копирования [SWS_CM_00134] и оператор присваивания копированием [SWS_CM_11548] явно удалены (delete). Однако ресурсы могут быть переданы через конструктор перемещения [SWS_CM_00135], а также оператор присваивания перемещением [SWS_CM_11549].

Непосредственно после конструирования экземпляр службы создан локально, но еще не виден в сети связи. Публикация для потребителей службы происходит только при вызове OfferService() [SWS_CM_00101], EXP_ARAComAPI с. 10. Если служба больше не должна предлагаться, StopOfferService() отзывает предоставление [SWS_CM_00111], EXP_ARAComAPI с. 10. После этого skeleton можно предложить повторно или уничтожить через виртуальный деструктор ~<SI>Skeleton() [SWS_CM_11370].

Диаграмма состояний: жизненный цикл и переходы состояний skeleton службы от инстанциации до освобождения. Источники: [SWS_CM_00101], [SWS_CM_00111], [SWS_CM_11370], EXP_ARAComAPI с. 10

Путь использования

Регулярный процесс предоставления службы подразделяется на следующие шаги:

  1. Конфигурация и регистрация обработчиков: до предложения службы могут быть заданы специфичные для приложения обработчики. С помощью SetTransportFaultConditionHandler() обработчик ошибок транспорта регистрируется либо напрямую [SWS_CM_00093], либо с выделенным исполнителем для асинхронных задач [SWS_CM_00094]; при необходимости его можно удалить с помощью UnsetTransportFaultConditionHandler() [SWS_CM_00095]. Сквозную обработку ошибок (End-to-End) можно переопределить через виртуальный метод E2EErrorHandler() [SWS_CM_10470].
  2. Предложение службы: приложение службы вызывает OfferService() [SWS_CM_00101]. Успешный вызов возвращает пустой ara::core::Result<void> и активирует экземпляр службы в сети.
  3. Обработка входящих запросов: если skeleton был инстанциирован в режиме MethodCallProcessingMode::kPoll, приложение должно активно выполнять ожидающие вызовы клиентов путем вызова ProcessNextMethodCall() [SWS_CM_00199]. Вызов метода выполняется в контексте этого потока; возвращаемое значение сигнализирует, есть ли еще ожидающие вызовы.
  4. Завершение службы: перед уничтожением экземпляра предложение прекращается с помощью StopOfferService() [SWS_CM_00111].

Диаграмма последовательности: последовательность взаимодействия между серверным приложением, skeleton службы и уровнем связи во время работы службы. Источники: [SWS_CM_00101], [SWS_CM_00111], [SWS_CM_00199], [SWS_CM_00093]

Сценарии ошибок

При использовании класса skeleton необходимо учитывать различные сценарии ошибок и предусловия:

  • Нарушения при конструировании: если авторизация через Grant Enforcement завершается неудачно, конструирование прерывается с InsufficientPermissionsViolation [SWS_CM_00130], [SWS_CM_00152], [SWS_CM_00153]. Передача недопустимого режима обработки приводит к WrongMethodCallProcessingModeViolation. Если используется InstanceSpecifier, несогласованности модели или множественные назначения могут вызывать ошибки InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation, ProcessMappingViolation или InstanceSpecifierAlreadyInUseViolation [SWS_CM_00152].
  • Сбой предложения службы: если OfferService() завершается сбоем, возвращается код ошибки из ara::com::ComErrc [SWS_CM_00101]: ComErrc::kFieldValueNotInitialized (поле не было предварительно инициализировано через Update()), ComErrc::kFieldSetHandlerNotSet (отсутствует обязательный set-обработчик поля) или ComErrc::kCommunicationFailure (ошибка соединения или безопасности сетевой привязки).
  • Нарушение режима обработки: вызов ProcessNextMethodCall() инициирует WrongMethodCallProcessingModeViolation, если skeleton был сконфигурирован не для kPoll, а для kEvent или kEventSingleThread [SWS_CM_00199].
  • Недопустимые обработчики ошибок: если в SetTransportFaultConditionHandler() передается несуществующий или пустой вызываемый объект (callable), это приводит к InvalidHandlerViolation [SWS_CM_00093], [SWS_CM_00094].
  • Ошибки E2E и повреждение данных: при приеме ошибочных сообщений вызывается E2EErrorHandler() с соответствующим ComE2EErrc [SWS_CM_10470]. Если речь идет об ошибке CRC, DataID также может быть поврежден, так что приложение не должно классифицировать переданный идентификатор как надежный.
  • Ошибки уничтожения: если при уничтожении skeleton еще имеются открытые выборки данных (data samples), деструктор аварийно завершает работу с DanglingSamplesViolation [SWS_CM_11370].

Настоящее руководство основано исключительно на требованиях спецификации AUTOSAR Adaptive Platform R25-11.

      Метод OfferService() вызывается на экземпляре скелетон-класса, чтобы предложить предоставленный сервис в системе и сделать его доступным для обнаружения потребителями через Service Discovery [SWS_CM_00101], ARAComAPI §6.5 «Service Discovery». Вызов выполняется без параметров и синхронно, как только реализация сервиса полностью инстанцирована и приведена в рабочее состояние AUTOSAR_AP_EXP_ARAComAPI §5.4.4 «Offering Service instance». Функция объявлена как noexcept и возвращает ara::core::Result<void> [SWS_CM_00101].
      
  
      Предложение является обязательным условием для функциональной коммуникации через методы, события, поля или триггеры AUTOSAR_AP_EXP_ARAComAPI §4.2 «Means of Communication». Если, например, попытаться отправить триггер без предварительного предложения, это завершится ошибкой с ComErrc::kServiceNotOffered [SWS_CM_00721]. В отношении параллелизма действует следующее: как только вызывается OfferService(), входящие вызовы методов уже могут доставляться экземпляру сервиса — даже если вызов OfferService() еще не завершился AUTOSAR_AP_EXP_ARAComAPI §5.4.4 «Offering Service instance».
      
  
      Если предложение завершается неудачно, возвращаемый ara::core::Result содержит соответствующий код ошибки из ComErrc [SWS_CM_00101], [SWS_CM_10432]:
      
  
        
    
      • ComErrc::kFieldValueNotInitialized: по меньшей мере одно сконфигурированное значение поля еще не было инициализировано до предложения [SWS_CM_00101].
        • 
    
      • ComErrc::kFieldSetHandlerNotSet: для поля с поддержкой сеттера еще не был зарегистрирован обработчик через RegisterSetHandler() [SWS_CM_00101].
        • 
    
      • ComErrc::kCommunicationFailure: сетевая привязка сообщает об устранимой ошибке коммуникации или о сбое защищенной коммуникации [SWS_CM_00101].
        • 
  
      
  
      Если предоставление сервиса требуется прекратить, необходимо вызвать StopOfferService() AUTOSAR_AP_EXP_ARAComAPI §5.4.4 «Offering Service instance».
