Использование по назначению

<SI-Namespace>::skeleton::<SI>Skeleton — базовый класс Skeleton, генерируемый toolchain генерации из модели Service Interface в ARXML-Manifest. Иерархический SI-Namespace и имя класса выводятся из Manifest; сгенерированный Header следует пути <SiShortname>_skeleton.h, выведенному из модели [SWS_CM_00002]. Собственная реализация сервиса наследуется от этого класса и переопределяет чистые виртуальные методы сервиса или методы Fire-and-Forget [SWS_CM_00191] [SWS_CM_90434].

Поколение & Разрушение

Производная реализация может создать скелет с помощью ara::core::InstanceSpecifier, одного InstanceIdentifier или контейнера идентификаторов; По умолчанию режим обработки — kEvent [SWS_CM_00152] [SWS_CM_00130] [SWS_CM_00153]. Виртуальный деструктор позволяет уничтожить объект с помощью базового класса [SWS_CM_11370].

Жизненный цикл и право собственности

Копирование запрещено [SWS_CM_00134] [SWS_CM_11548]. Поддерживаются Move-конструирование и Move-присваивание; конструирование не является exception-safe, а присваивание является exception-safe [SWS_CM_00135] [SWS_CM_11549].

Взаимодействие с другими классами

  • После создания экземпляра OfferService() предлагает услугу; StopOfferService() прекращает действие предложения [SWS_CM_00101] [SWS_CM_00111].
  • Для каждого Event модели существует член events::<Event>; реализация отправляет значения через skeleton::events::<Event>::Send [SWS_CM_99557] [SWS_CM_00162].
  • Для каждого поля существует элемент fields::<Field>; Значения полей обновляются через skeleton::fields::<Field>::Update [SWS_CM_99558] [SWS_CM_00119].
  • Режимы kEvent, kEventSingleThread и kPoll управляют обработкой входящих вызовов методов [SWS_CM_00301]. При kPoll ProcessNextMethodCall() выполняет следующий ожидающий вызов в контексте этой функции [SWS_CM_00199].

Ограничения & Обработка ошибок

OfferService() может завершиться ошибкой из-за неинициализированных значений Field, отсутствующего Field-Set-Handler или ошибки связи [SWS_CM_00101]. E2E-обработчик ошибок может быть переопределён, однако не является reentrant; при ошибках CRC переданный DataID недостоверен [SWS_CM_10470]. Обработчики ошибок транспорта можно зарегистрировать для всех методов и затем удалить [SWS_CM_00093] [SWS_CM_00094] [SWS_CM_00095].

Архитектурное встраивание

Skeleton — это сгенерированный адаптер на стороне Provider: реализация сервиса обычно наследуется от него и тем самым предоставляет свои методы, Events и Fields через Communication Management. Интерфейс генерируется из описания Service Interface; базовая модель допускает Events, Fields, Methods и Triggers в одном Service Interface. EXP ARAComAPI §4.1 «Proxy/Skeleton Architecture» TPS Manifest §4.2 «Service Interface»

Предложение и обработка метода

До OfferService() экземпляр не виден потребителям. После вызова методы уже могут быть доставлены, даже если вызов еще не вернулся; после StopOfferService() дальнейшие вызовы доставляться не будут. Режим обработки, выбранный при его создании, применяется на протяжении всего времени существования экземпляра скелета. EXP ARAComAPI §5.4.4 «Offering Service instance» §5.4.5 «Polling and event-driven processing modes»

Диаграмма активности: экземпляр сервиса становится видимым только после OfferService(); режим, выбранный в конструкторе, определяет обработку. Источник: EXP ARAComAPI §5.4.4 «Offering Service instance» и §5.4.5 «Polling and event-driven processing modes».

Параллелизм и ограничения

Он обрабатывает не более одного ожидающего вызова и использует возвращаемое значение, чтобы сообщить, есть ли еще ожидающие вызовы; Это позволяет циклически активируемому приложению контролировать свой собственный бюджет времени.
