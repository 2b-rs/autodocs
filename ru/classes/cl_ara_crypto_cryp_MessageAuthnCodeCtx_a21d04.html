Контекст

Интерфейс ara::crypto::cryp::MessageAuthnCodeCtx определяет криптографический контекст для генерации и проверки кодов аутентификации сообщений (Message Authentication Codes, MAC) в AUTOSAR Adaptive Platform. Он служит для обеспечения целостности и подлинности данных с помощью симметричных криптографических методов. Жизненный цикл и отношения владения экземплярами контекста в первую очередь отображаются через тип интеллектуального указателя Sptr ([SWS_CRYPT_22101]).

Для выполнения криптографических преобразований контекст напрямую взаимодействует с ключевым материалом. Он может либо передаваться как конкретный объект ключа типа SymmetricKey ([SWS_CRYPT_22118]), либо связываться через управляемый KeySlot ([SWS_CRYPT_50026]). Для этого интерфейс предоставляет два взаимодополняющих режима обработки:

  • Потоковая обработка: сообщения могут обрабатываться по частям с помощью итеративных вызовов (инициализация, непрерывное обновление данных, финализация и оценка результата).
  • Обработка за один вызов: полные блоки данных могут преобразовываться или верифицироваться за одну операцию.

В зависимости от сконфигурированного алгоритма (такого как GMAC или CMAC) контекст поддерживает векторы инициализации (IV) или нонсы, рекомендуемый размер которых можно запросить через GetRecommendedIvSize() ([SWS_CRYPT_50135]).

Жизненный цикл

MessageAuthnCodeCtx проходит несколько рабочих фаз, управляющих переходом от связывания ключа до оценки результата:

  • Не инициализирован (Uninitialized): после создания контекст ещё не имеет назначенного ключевого материала. Вызовы вычислений и потоковой обработки на этом этапе завершаются с ошибкой CryptoErrc::kUninitializedContext ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
  • Инициализирован (готов): при назначении ключа через SetKey() с SymmetricKey ([SWS_CRYPT_22118]) или KeySlot ([SWS_CRYPT_50026]) контекст переходит в готовое к работе состояние. В этом состоянии могут напрямую выполняться вызовы обработки за один вызов или инициироваться потоковые операции.
  • Потоковая обработка активна (Processing): вычисление запускается через Start() ([SWS_CRYPT_22111]) или Start(iv) ([SWS_CRYPT_22110]). Последующие блоки данных аккумулируются через Update() ([SWS_CRYPT_22113]). Выполняемую операцию можно прервать с помощью Cancel() ([SWS_CRYPT_50027]); интерпретация: после отмены контекст, вероятно, остаётся в инициализированном состоянии и готов к новым вычислениям.
  • Завершено (Finished): вызов Finish() ([SWS_CRYPT_22115]) завершает вычисление MAC. После этого результат можно запросить или сравнить с ожидаемым значением.

Все методы интерфейса согласно спецификации спроектированы как потокобезопасные (thread-safe) и безопасные относительно исключений (exception safe) (в том числе [SWS_CRYPT_50027], [SWS_CRYPT_22118]).

Диаграмма состояний: фазы и переходы состояний MAC-контекста от связывания ключа через потоковую обработку до оценки результата. Источники: [SWS_CRYPT_22118], [SWS_CRYPT_50026], [SWS_CRYPT_22110], [SWS_CRYPT_22111], [SWS_CRYPT_22113], [SWS_CRYPT_22115], [SWS_CRYPT_50027], [SWS_CRYPT_22116], [SWS_CRYPT_50133].

Путь использования

Для практического применения контекста существуют два типичных шаблона использования:

1. Потоковый путь (инкрементная обработка):

  1. Конфигурация: назначение ключа через SetKey() ([SWS_CRYPT_22118]).
  2. Определение размера буфера: предварительно можно определить максимально обрабатываемый размер чанка через GetMaximumChunkSize() ([SWS_CRYPT_50033]), а также длину дайджеста через GetDigestSize() ([SWS_CRYPT_50134]).
  3. Запуск: инициализация процесса вычисления с помощью Start() ([SWS_CRYPT_22111]) или Start(iv) ([SWS_CRYPT_22110]).
  4. Обновление данных: повторная передача фрагментов сообщений в Update(data) ([SWS_CRYPT_22113]).
  5. Завершение: финализация вычисления с помощью Finish() ([SWS_CRYPT_22115]).
  6. Получение результата: приём дайджеста через GetDigest() ([SWS_CRYPT_22116]) или проверка на соответствие эталонному значению с помощью Compare() ([SWS_CRYPT_50133]) либо CompareSubspan() ([SWS_CRYPT_50028]).

2. Путь обработки за один вызов (компактная обработка):

Если все данные готовы в непрерывном буфере, операцию можно выполнить без шагов потоковой обработки:

  • Генерация MAC через Generate() ([SWS_CRYPT_50029]) или в виде усеченного префиксного дайджеста через GenerateSubspan() ([SWS_CRYPT_50030]).
  • Верификация данных по отношению к ожидаемому значению MAC через Verify() ([SWS_CRYPT_50031]) или VerifySubspan() ([SWS_CRYPT_50032]).

Диаграмма последовательности: процесс полного потокового вычисления MAC со связыванием ключа, пофрагментной обработкой чанков и получением результата. Источники: [SWS_CRYPT_22118], [SWS_CRYPT_22111], [SWS_CRYPT_22113], [SWS_CRYPT_22115], [SWS_CRYPT_22116], [SWS_CRYPT_50133].

Сценарии ошибок

Ошибки сигнализируются через возвращаемые значения типа ara::core::Result с кодами ошибок домена CryptoErrc. Спецификация гарантирует семантику отката, благодаря чему при возникновении ошибок контекст остаётся в согласованном состоянии:

  • Конфликты состояний и последовательности выполнения:
    • CryptoErrc::kUninitializedContext: вызов вычислительных операций без предварительно сконфигурированного ключа ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kProcessingNotStarted: вызов Update() ([SWS_CRYPT_22113]), Finish() ([SWS_CRYPT_22115]) или Cancel() ([SWS_CRYPT_50027]) до того, как обработка была инициирована с помощью Start().
    • CryptoErrc::kProcessingNotFinished: вызов GetDigest() ([SWS_CRYPT_22116]), Compare() ([SWS_CRYPT_50133]) или CompareSubspan() ([SWS_CRYPT_50028]) до успешной финализации через Finish().
  • Ошибки ключей и использования:
    • CryptoErrc::kUsageViolation: предоставленный ключ не имеет права kAllowMac, необходимого для операций MAC ([SWS_CRYPT_22118], [SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kEmptyKeySlot: KeySlot, назначенный через SetKey(), не содержит ключа на момент выполнения ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kIncompatibleObject: переданный объект ключа или слота не подходит к контексту ([SWS_CRYPT_22118], [SWS_CRYPT_50026]).
  • Ошибки буфера и параметров:
    • CryptoErrc::kInsufficientCapacity: целевой буфер для GetDigest() ([SWS_CRYPT_22116]) или Generate() ([SWS_CRYPT_50029]) меньше сгенерированного дайджеста.
    • CryptoErrc::kInvalidInputSize: неподдерживаемый размер буфера для входных данных, IV или ожидаемого значения MAC ([SWS_CRYPT_22110], [SWS_CRYPT_22113], [SWS_CRYPT_50133]).
    • CryptoErrc::kUnsupported: отсутствие поддержки потоковой обработки или обработки за один вызов либо несовместимость с требованиями алгоритма к IV ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kBusyResource: необходимый криптографический ресурс в данный момент занят ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).

Это руководство по классу основано на спецификации AUTOSAR Adaptive R25-11 и было сформировано автоматически.
