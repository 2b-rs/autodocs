Контекст

Класс ara::diag::SovdSwUpdate образует интерфейс для выполнения обновлений программного обеспечения по протоколу Service-Oriented Vehicle Diagnostics (SOVD) в соответствии с ASAM SOVD и ISO 17978-3 ([SWS_DM_01874], [SWS_DM_01796]). В рамках AUTOSAR Adaptive Platform существует четкое функциональное разделение задач: непосредственная бизнес-логика выполнения и управления обновлениями программного обеспечения остается в адаптивном приложении, тогда как функциональный кластер Diagnostics (экземпляр Diagnostic Server или Diagnostic Management) берет на себя обработку базового протокола SOVD (AUTOSAR_AP_SWS_Diagnostics §7.3 «Figure 7.4: SOVD Software Update API»).

Будучи абстрактным базовым классом, SovdSwUpdate определяет интерфейсы обратного вызова, которые должны быть реализованы прикладным программным обеспечением. Входящие запросы внешних клиентов SOVD анализируются экземпляром Diagnostic Server и делегируются приложению через соответствующие методы SovdSwUpdate (AUTOSAR_AP_SWS_Diagnostics §7.3 «SOVD Software Update API»).

Контекстная диаграмма: партнеры по взаимодействию и распределение ролей при обновлении ПО через SOVD. Источники: [SWS_DM_01796], [SWS_DM_01874], AUTOSAR_AP_SWS_Diagnostics §7.3 «Figure 7.4: SOVD Software Update API»

Жизненный цикл

Создание экземпляра для конкретного приложения выполняется через параметризованный конструктор с указанием идентификатора экземпляра (ara::core::InstanceSpecifier) и требуемой модели параллелизма (ConcurrencyType) ([SWS_DM_01910]). При этом InstanceSpecifier ссылается на объявленный в манифесте программного обеспечения PortPrototype, который должен быть типизирован как DiagnosticSovdUpdateInterface ([SWS_DM_01910]). С помощью concurrencyType определяется, должны ли методы обратного вызова экземпляра вызываться потокобезопасно (kConcurrent) или последовательно / непотокобезопасно (kNotConcurrent) при одновременных запросах ([SWS_DM_01910]).

Экземпляры SovdSwUpdate взаимно однозначно привязаны к сервисному порту. Поэтому конструктор копирования и оператор присваивания явно удалены (=delete) ([SWS_DM_01912], [SWS_DM_01914]). Операции перемещения определены как защищенные (protected) ([SWS_DM_01913], [SWS_DM_01915]).

После успешной инициализации приложение должно явно активировать сервис с помощью Offer() ([SWS_DM_01924]). Только этот вызов указывает Diagnostic Manager (DM) перенаправлять входящие SOVD-запросы в зарегистрированные методы-обработчики. Перед уничтожением объекта-обработчика сервис необходимо отменить через StopOffer(), чтобы предотвратить дальнейшую пересылку запросов ([SWS_DM_01925]). Деинициализация завершается через виртуальный деструктор ~SovdSwUpdate() ([SWS_DM_01911]).

Путь использования

Типичный рабочий процесс включает несколько последовательных фаз обновления программного обеспечения:

  1. Предоставление сервиса: приложение создает экземпляр своего производного класса от SovdSwUpdate и вызывает Offer() ([SWS_DM_01924]).
  2. Регистрация и передача пакета: входящие запросы регистрации от SOVD-клиента Diagnostic Server перенаправляет в RequestUpdatePackageRegistration() ([SWS_DM_01923]). Метод возвращает ara::core::Future с кортежем из сессии записи (DataTransferWriteSession) и уникального идентификатора пакета (updatePackageId) ([SWS_DM_01923]). Интерпретация: фактическая передача полезных данных обновления, вероятно, осуществляется через эту предоставленную сессию записи (AUTOSAR_AP_SWS_Diagnostics §7.3 «Figure 7.4: SOVD Software Update API»).
  3. Подготовка пакета: для подготовки установки Diagnostic Server вызывает PrepareUpdatePackage() ([SWS_DM_01800], [SWS_DM_01919]). В качестве альтернативы автоматизированная установка может быть запущена через PutUpdatePackageAutomated() ([SWS_DM_01799], [SWS_DM_01918]).
  4. Выполнение пакета: установка подготовленного пакета обновления инициируется вызовом ExecuteUpdatePackage() ([SWS_DM_01801], [SWS_DM_01920]).
  5. Запрос статуса и инспекция: во время или после процесса подробная информация и статус могут быть запрошены через GetUpdatePackageStatus() ([SWS_DM_01802], [SWS_DM_01921]), GetUpdatePackageDetails() ([SWS_DM_01917]), а общий список — через GetAllUpdates() ([SWS_DM_01797], [SWS_DM_01916]). Ненужные пакеты удаляются с помощью DeleteUpdatePackage() ([SWS_DM_01922]).

Диаграмма последовательности: шаблоны взаимодействия при регистрации, установке и запросе статуса пакета обновления. Источники: [SWS_DM_01800], [SWS_DM_01801], [SWS_DM_01802], [SWS_DM_01919], [SWS_DM_01920], [SWS_DM_01921], [SWS_DM_01923], [SWS_DM_01924]

Сценарии ошибок

Условия ошибок подразделяются на ошибки конфигурации и моделирования, ошибки состояния сервиса, а также протокольно-специфичные ошибки выполнения:

  • Ошибки модели и инстанциирования: если разрешение InstanceSpecifier завершается сбоем или он указывает на неподходящий элемент, сообщается о специфических нарушениях времени выполнения (Violations): InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation, ProcessMappingViolation, а также InstanceSpecifierAlreadyInUseViolation, если идентификатор уже используется в рамках процесса ([SWS_DM_01910]).
  • Ошибки предоставления сервиса: вызов Offer() возвращает ara::core::Result<void>. В случае ошибки он содержит DiagOfferErrc::kAlreadyOffered, если сервис уже предоставляется, или DiagOfferErrc::kConfigurationMismatch, если конфигурация не совпадает с диагностическим экстрактом (DEXT) ([SWS_DM_01924]).
  • Ошибки выполнения и протокола: асинхронные методы обратного вызова возвращают результаты в виде ara::core::Future. В случае ошибки применимый код ошибки согласно ASAM SOVD 1.1 или ISO 17978-3 должен быть сохранен в Future ([SWS_DM_01917], [SWS_DM_01918], [SWS_DM_01919], [SWS_DM_01920], [SWS_DM_01921], [SWS_DM_01922], [SWS_DM_01923]).
  • Обработка отмены: всем асинхронным методам передается CancellationHandler. Приложение отвечает за его опрос, чтобы корректно завершить преждевременно прерванный сеанс связи с клиентом ([SWS_DM_01919], [SWS_DM_01920]).

<h4>Контекст</h4>
<p>Класс <code>ara::diag::SovdSwUpdate</code> образует интерфейс для выполнения обновлений программного обеспечения по протоколу Service-Oriented Vehicle Diagnostics (SOVD) в соответствии с ASAM SOVD и ISO 17978-3 (<a class="spec-record-ref" data-req="SWS_DM_01874" href="../spec/record.html?id=SWS_DM_01874">[SWS_DM_01874]</a>, <a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>). В рамках AUTOSAR Adaptive Platform существует четкое функциональное разделение задач: непосредственная бизнес-логика выполнения и управления обновлениями программного обеспечения остается в адаптивном приложении, тогда как функциональный кластер Diagnostics (экземпляр Diagnostic Server или Diagnostic Management) берет на себя обработку базового протокола SOVD (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.3 «Figure 7.4: SOVD Software Update API»</a>).</p>
<p>Будучи абстрактным базовым классом, <code>SovdSwUpdate</code> определяет интерфейсы обратного вызова, которые должны быть реализованы прикладным программным обеспечением. Входящие запросы внешних клиентов SOVD анализируются экземпляром Diagnostic Server и делегируются приложению через соответствующие методы <code>SovdSwUpdate</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=224">AUTOSAR_AP_SWS_Diagnostics §7.3 «SOVD Software Update API»</a>).</p>

<h4>Жизненный цикл</h4>
<p>Создание экземпляра для конкретного приложения выполняется через параметризованный конструктор с указанием идентификатора экземпляра (<code>ara::core::InstanceSpecifier</code>) и требуемой модели параллелизма (<code>ConcurrencyType</code>) (<a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>). При этом <code>InstanceSpecifier</code> ссылается на объявленный в манифесте программного обеспечения <code>PortPrototype</code>, который должен быть типизирован как <code>DiagnosticSovdUpdateInterface</code> (<a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>). С помощью <code>concurrencyType</code> определяется, должны ли методы обратного вызова экземпляра вызываться потокобезопасно (<code>kConcurrent</code>) или последовательно / непотокобезопасно (<code>kNotConcurrent</code>) при одновременных запросах (<a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>).</p>
<p>Экземпляры <code>SovdSwUpdate</code> взаимно однозначно привязаны к сервисному порту. Поэтому конструктор копирования и оператор присваивания явно удалены (<code>=delete</code>) (<a class="spec-record-ref" data-req="SWS_DM_01912" href="../spec/record.html?id=SWS_DM_01912">[SWS_DM_01912]</a>, <a class="spec-record-ref" data-req="SWS_DM_01914" href="../spec/record.html?id=SWS_DM_01914">[SWS_DM_01914]</a>). Операции перемещения определены как защищенные (<code>protected</code>) (<a class="spec-record-ref" data-req="SWS_DM_01913" href="../spec/record.html?id=SWS_DM_01913">[SWS_DM_01913]</a>, <a class="spec-record-ref" data-req="SWS_DM_01915" href="../spec/record.html?id=SWS_DM_01915">[SWS_DM_01915]</a>).</p>
<p>После успешной инициализации приложение должно явно активировать сервис с помощью <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>). Только этот вызов указывает Diagnostic Manager (DM) перенаправлять входящие SOVD-запросы в зарегистрированные методы-обработчики. Перед уничтожением объекта-обработчика сервис необходимо отменить через <code>StopOffer()</code>, чтобы предотвратить дальнейшую пересылку запросов (<a class="spec-record-ref" data-req="SWS_DM_01925" href="../spec/record.html?id=SWS_DM_01925">[SWS_DM_01925]</a>). Деинициализация завершается через виртуальный деструктор <code>~SovdSwUpdate()</code> (<a class="spec-record-ref" data-req="SWS_DM_01911" href="../spec/record.html?id=SWS_DM_01911">[SWS_DM_01911]</a>).</p>

<h4>Путь использования</h4>
<p>Типичный рабочий процесс включает несколько последовательных фаз обновления программного обеспечения:</p>
<ol>
<li><strong>Предоставление сервиса:</strong> приложение создает экземпляр своего производного класса от <code>SovdSwUpdate</code> и вызывает <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>).</li>
<li><strong>Регистрация и передача пакета:</strong> входящие запросы регистрации от SOVD-клиента Diagnostic Server перенаправляет в <code>RequestUpdatePackageRegistration()</code> (<a class="spec-record-ref" data-req="SWS_DM_01923" href="../spec/record.html?id=SWS_DM_01923">[SWS_DM_01923]</a>). Метод возвращает <code>ara::core::Future</code> с кортежем из сессии записи (<code>DataTransferWriteSession</code>) и уникального идентификатора пакета (<code>updatePackageId</code>) (<a class="spec-record-ref" data-req="SWS_DM_01923" href="../spec/record.html?id=SWS_DM_01923">[SWS_DM_01923]</a>). Интерпретация: фактическая передача полезных данных обновления, вероятно, осуществляется через эту предоставленную сессию записи (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.3 «Figure 7.4: SOVD Software Update API»</a>).</li>
<li><strong>Подготовка пакета:</strong> для подготовки установки Diagnostic Server вызывает <code>PrepareUpdatePackage()</code> (<a class="spec-record-ref" data-req="SWS_DM_01800" href="../spec/record.html?id=SWS_DM_01800">[SWS_DM_01800]</a>, <a class="spec-record-ref" data-req="SWS_DM_01919" href="../spec/record.html?id=SWS_DM_01919">[SWS_DM_01919]</a>). В качестве альтернативы автоматизированная установка может быть запущена через <code>PutUpdatePackageAutomated()</code> (<a class="spec-record-ref" data-req="SWS_DM_01799" href="../spec/record.html?id=SWS_DM_01799">[SWS_DM_01799]</a>, <a class="spec-record-ref" data-req="SWS_DM_01918" href="../spec/record.html?id=SWS_DM_01918">[SWS_DM_01918]</a>).</li>
<li><strong>Выполнение пакета:</strong> установка подготовленного пакета обновления инициируется вызовом <code>ExecuteUpdatePackage()</code> (<a class="spec-record-ref" data-req="SWS_DM_01801" href="../spec/record.html?id=SWS_DM_01801">[SWS_DM_01801]</a>, <a class="spec-record-ref" data-req="SWS_DM_01920" href="../spec/record.html?id=SWS_DM_01920">[SWS_DM_01920]</a>).</li>
<li><strong>Запрос статуса и инспекция:</strong> во время или после процесса подробная информация и статус могут быть запрошены через <code>GetUpdatePackageStatus()</code> (<a class="spec-record-ref" data-req="SWS_DM_01802" href="../spec/record.html?id=SWS_DM_01802">[SWS_DM_01802]</a>, <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>), <code>GetUpdatePackageDetails()</code> (<a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>), а общий список — через <code>GetAllUpdates()</code> (<a class="spec-record-ref" data-req="SWS_DM_01797" href="../spec/record.html?id=SWS_DM_01797">[SWS_DM_01797]</a>, <a class="spec-record-ref" data-req="SWS_DM_01916" href="../spec/record.html?id=SWS_DM_01916">[SWS_DM_01916]</a>). Ненужные пакеты удаляются с помощью <code>DeleteUpdatePackage()</code> (<a class="spec-record-ref" data-req="SWS_DM_01922" href="../spec/record.html?id=SWS_DM_01922">[SWS_DM_01922]</a>).</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>Условия ошибок подразделяются на ошибки конфигурации и моделирования, ошибки состояния сервиса, а также протокольно-специфичные ошибки выполнения:</p>
<ul>
<li><strong>Ошибки модели и инстанциирования:</strong> если разрешение <code>InstanceSpecifier</code> завершается сбоем или он указывает на неподходящий элемент, сообщается о специфических нарушениях времени выполнения (Violations): <code>InstanceSpecifierMappingIntegrityViolation</code>, <code>PortInterfaceMappingViolation</code>, <code>ProcessMappingViolation</code>, а также <code>InstanceSpecifierAlreadyInUseViolation</code>, если идентификатор уже используется в рамках процесса (<a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>).</li>
<li><strong>Ошибки предоставления сервиса:</strong> вызов <code>Offer()</code> возвращает <code>ara::core::Result&lt;void&gt;</code>. В случае ошибки он содержит <code>DiagOfferErrc::kAlreadyOffered</code>, если сервис уже предоставляется, или <code>DiagOfferErrc::kConfigurationMismatch</code>, если конфигурация не совпадает с диагностическим экстрактом (DEXT) (<a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>).</li>
<li><strong>Ошибки выполнения и протокола:</strong> асинхронные методы обратного вызова возвращают результаты в виде <code>ara::core::Future</code>. В случае ошибки применимый код ошибки согласно ASAM SOVD 1.1 или ISO 17978-3 должен быть сохранен в Future (<a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>, <a class="spec-record-ref" data-req="SWS_DM_01918" href="../spec/record.html?id=SWS_DM_01918">[SWS_DM_01918]</a>, <a class="spec-record-ref" data-req="SWS_DM_01919" href="../spec/record.html?id=SWS_DM_01919">[SWS_DM_01919]</a>, <a class="spec-record-ref" data-req="SWS_DM_01920" href="../spec/record.html?id=SWS_DM_01920">[SWS_DM_01920]</a>, <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>, <a class="spec-record-ref" data-req="SWS_DM_01922" href="../spec/record.html?id=SWS_DM_01922">[SWS_DM_01922]</a>, <a class="spec-record-ref" data-req="SWS_DM_01923" href="../spec/record.html?id=SWS_DM_01923">[SWS_DM_01923]</a>).</li>
<li><strong>Обработка отмены:</strong> всем асинхронным методам передается <code>CancellationHandler</code>. Приложение отвечает за его опрос, чтобы корректно завершить преждевременно прерванный сеанс связи с клиентом (<a class="spec-record-ref" data-req="SWS_DM_01919" href="../spec/record.html?id=SWS_DM_01919">[SWS_DM_01919]</a>, <a class="spec-record-ref" data-req="SWS_DM_01920" href="../spec/record.html?id=SWS_DM_01920">[SWS_DM_01920]</a>).</li>
</ul>
