Контекст

Класс ara::per::PerException определяет центральный тип исключений для модуля Persistency (per) в рамках AUTOSAR Adaptive Platform в релизе R25-11. Согласно определению класса, он открыто наследует от базового класса исключений ara::core::Exception и тем самым представляет собой специфичное C++-исключение подсистемы персистентности. Его главная ответственность состоит в инкапсуляции состояний ошибок из операций персистентности с файлами и парами «ключ-значение» в виде объекта исключения и передаче их вызывающим слоям приложения. При этом он выступает связующим звеном между функциональным API персистентности из ara::per, базовой типизацией ошибок из ara::core и вызывающим прикладным программным обеспечением. Объявление и подключение заданы через заголовочный файл ara/per/per_error_domain.h, как указано в [SWS_PER_00355].

Жизненный цикл

Жизненный цикл экземпляра ara::per::PerException инициируется конструктором explicit PerException(ara::core::ErrorCode errorCode) noexcept [SWS_PER_00355]. Спецификация гарантирует для этого конструктора полную безопасность исключений (exception safe) и потокобезопасность (thread-safe) [SWS_PER_00355]. Поскольку конструктор объявлен как noexcept, гарантируется, что при создании самого объекта исключения вторичное исключение возникнуть не может.

Что касается отношений владения и параллелизма, объект обычно возникает на стороне модуля персистентности в случае ошибки и передается через механизм исключений C++. После инициализации переданным ara::core::ErrorCode объект исключения больше не изменяет свое состояние. Благодаря документированной потокобезопасности [SWS_PER_00355] несколько потоков внутри одного процесса могут одновременно независимо друг от друга создавать экземпляры ara::per::PerException. Уничтожение объекта исключения происходит автоматически в конце соответствующего блока catch в соответствии со стандартными правилами времени жизни C++ для объектов на стеке и объектов исключений.

Путь использования

Приложения в Adaptive Platform используют сервисы персистентности для хранения конфигурационных данных или данных состояния. Если при этом возникает ошибочная ситуация, типичный путь использования ara::per::PerException выглядит следующим образом:

  1. Обнаружение ошибки в Persistency: приложение выполняет операцию над модулем персистентности. Подсистема определяет, что доступ (например, к ресурсам памяти) завершается неудачно, и генерирует специфический ara::core::ErrorCode.
  2. Создание и возбуждение: подсистема инстанцирует ara::per::PerException с передачей кода ошибки через специфицированный конструктор [SWS_PER_00355] и выбрасывает исключение. Это, предположительно, происходит в первую очередь тогда, когда прикладное программное обеспечение обрабатывает ошибочные возвращаемые значения через вспомогательные функции, такие как ara::core::Result::Value(), или использует функциональный интерфейс в режиме на основе исключений.
  3. Перехват вызывающей стороной: вызывающий код приложения перехватывает исключение в блоке try-catch либо специфично как const ara::per::PerException&, либо более обобщенно через const ara::core::Exception&.
  4. Диагностика ошибки и реакция: приложение анализирует исключение. Инкапсулированный ara::core::ErrorCode, предположительно, считывается через методы инспекции, унаследованные от ara::core::Exception, после чего приложение выполняет обработку ошибки или протоколирование.

Сценарии ошибок

Поскольку ara::per::PerException сам по себе является средством сигнализации об ошибках, он не имеет собственных кодов ошибок или возвращаемых значений ошибок. Единственным предварительным условием для его использования является предоставление инициализированного ara::core::ErrorCode при вызове конструктора [SWS_PER_00355]. В качестве постусловия выступает валидный, безошибочный объект исключения.

Охватываемые сценарии ошибок включают все условия ошибок домена ошибок персистентности, определенные через заголовочный файл ara/per/per_error_domain.h [SWS_PER_00355]. Поскольку конструктор объявлен как noexcept [SWS_PER_00355], сбой обработки ошибок из-за исключений внутри создания исключения исключен. Тем самым класс реализует вышестоящие системные требования к детерминированной и надежной обработке исключений в соответствии со ссылками RS_AP_00120, RS_AP_00121, RS_AP_00135 и RS_AP_00159 [SWS_PER_00355].
