Контекст

C++-класс <SI-Namespace>::proxy::fields::<Field> представляет собой клиентскую репрезентацию поля, объявленного в сервисном интерфейсе. В AUTOSAR Adaptive Platform поле объединяет свойства опрашиваемого значения состояния, изменяемого значения состояния, а также потока событий для уведомления об изменениях значения.

Класс взаимодействует главным образом с вызывающей логикой приложения, а также с нижележащим Communication Management. В зависимости от моделирования в сервисном интерфейсе класс предоставляет различные элементы интерфейса:

  • Геттер: если в интерфейсе сконфигурирован Field.hasGetter == TRUE, существует метод Get() для асинхронного запроса значения ([SWS_CM_00112]; AUTOSAR_AP_EXP_ARAComAPI с. 10).
  • Сеттер: если определен Field.hasSetter == TRUE, класс предоставляет метод Set() для изменения значения ([SWS_CM_00113]; AUTOSAR_AP_EXP_ARAComAPI с. 10).
  • Нотификатор: поступающие уведомления об измененных значениях поля предоставляются в локальном кэше данных через механизмы приема на основе подписки ([SWS_CM_11601], [SWS_CM_11610]).

Кроме того, класс предоставляет функции мониторинга для защиты End-to-End (E2E): состояние конечного автомата E2E можно запрашивать раздельно для геттера ([SWS_CM_00145]), сеттера ([SWS_CM_00146]) и нотификатора ([SWS_CM_11612]).

Жизненный цикл

Время жизни экземпляра <SI-Namespace>::proxy::fields::<Field>, предположительно, связано со временем жизни вышестоящего экземпляра сервисного прокси, который агрегирует это поле.

Для функциональности нотификатора существует явный жизненный цикл подписки. Состояния включают kNotSubscribed, kSubscriptionPending и kSubscribed. Вызовом Subscribe() запрашивается подписка с указанием размера буфера maxSampleCount ([SWS_CM_11601]). Если при этом вызове поле уже находится в состояниях kSubscribed или kSubscriptionPending с неизменной квотой, вызов не имеет эффекта ([SWS_CM_11601]).

Текущее состояние подписки можно запросить с помощью GetSubscriptionState() ([SWS_CM_11604]). Переходы между состояниями можно отслеживать путем регистрации обработчика через SetSubscriptionStateChangeHandler() ([SWS_CM_00106], [SWS_CM_11607]), при желании также с пользовательским Executor ([SWS_CM_11608]). Обработчик можно снова удалить через UnsetSubscriptionStateChangeHandler() ([SWS_CM_11609]).

Прекращение уведомлений выполняется посредством Unsubscribe() ([SWS_CM_11602]). Если на момент вызова подписка на поле отсутствует, метод возвращается без каких-либо действий ([SWS_CM_11602]). Для транспортных ошибок в канале нотификатора можно также зарегистрировать ([SWS_CM_00109], [SWS_CM_00110]) и снова разрегистрировать обработчик транспортных сбоев ([SWS_CM_00126]).

Диаграмма состояний: переходы состояний подписки нотификатора для поля прокси. Источники: [SWS_CM_11601], [SWS_CM_11602], [SWS_CM_11604].

Путь использования

Типичное взаимодействие с полем включает два раздельных пути связи:

  1. Подписка и обработка сэмплов:
    • Приложение с помощью Subscribe(maxSampleCount) резервирует места в буфере для обновлений ([SWS_CM_11601]).
    • Через SetReceiveHandler() регистрируется callback, который срабатывает при поступлении новых данных поля ([SWS_CM_11605], опционально с Executor согласно [SWS_CM_11611]).
    • В обработчике приложение вызывает GetNewSamples(f, maxNumberOfSamples) для обработки новых значений в локальном кэше ([SWS_CM_11610]). С помощью GetFreeSampleCount() можно запросить количество оставшихся свободных мест в кэше ([SWS_CM_11603]).
    • В завершение обработчик разрегистрируется через UnsetReceiveHandler() ([SWS_CM_11606]), а подписка прекращается через Unsubscribe() ([SWS_CM_11602]).
  2. Прямой запрос значения и модификация:
    • С помощью Get() приложение запрашивает текущее значение и получает ara::core::Future<FieldType> ([SWS_CM_00112]; псевдоним типа FieldType согласно [SWS_CM_11403]).
    • С помощью Set(value) новое значение передается скелетону сервиса, что также синхронизируется через ara::core::Future<FieldType> ([SWS_CM_00113]).

Диаграмма последовательности: типичная последовательность из подписки, приема нотификаций, а также вызовов Get и Set. Источники: [SWS_CM_00112], [SWS_CM_00113], [SWS_CM_11601], [SWS_CM_11605], [SWS_CM_11610], [SWS_CM_11602].

Сценарии ошибок

Методы класса обеспечивают свою работоспособность с помощью кодов ошибок, исключений и ограничений доступа:

  • Сбои связи (ComErrc::kCommunicationFailure): сообщается сетевым байндингом при ошибках передачи или нарушениях защищенной связи. Для Get() действует семантика отката ([SWS_CM_00112]). Для Set() семантика отката отсутствует, так как в случае таймаута связи удаленное состояние на стороне сервера может оставаться неопределенным ([SWS_CM_00113]).
  • Нарушение минимального интервала отправки (ComErrc::kMinimumSendIntervalViolationError): Происходит в Get() ([SWS_CM_00112]) и Set() ([SWS_CM_00113]), если запросы на передачу инициируются быстрее, чем позволяет сконфигурированный минимальный интервал отправки (minimumSendInterval).
  • Границы буфера (ComErrc::kMaxSampleCountNotRealizable и ComErrc::kMaxSamplesExceeded): Subscribe() завершается сбоем, если запрошенное количество сэмплов не может быть предоставлено системой ([SWS_CM_11601]). GetNewSamples() сообщает об ошибке, если превышено максимальное количество сэмплов ([SWS_CM_11610]).
  • Нарушения безопасности (InsufficientPermissionsViolation): Инициируется Grant Enforcement, если клиент не обладает достаточными правами для выполнения Get() ([SWS_CM_00112]), Set() ([SWS_CM_00113]) или Subscribe() ([SWS_CM_11601]).
  • Недопустимые обработчики обратного вызова (InvalidHandlerViolation): Генерируется, если при регистрации через SetReceiveHandler() ([SWS_CM_11605], [SWS_CM_11611]), SetSubscriptionStateChangeHandler() ([SWS_CM_11607], [SWS_CM_11608]) или SetTransportFaultConditionHandler() ([SWS_CM_00109], [SWS_CM_00110]) передается пустой или недопустимый Callable.
