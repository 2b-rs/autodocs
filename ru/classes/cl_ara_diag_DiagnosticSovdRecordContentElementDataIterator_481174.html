Служит для последовательного обхода и считывания элементов диагностических данных в записи SOVD.

Класс ara::diag::DiagnosticSovdRecordContentElementDataIterator служит итератором для последовательного обхода элементов диагностических данных записи SOVD ([SWS_DM_02258]). Через операторы разыменования приложения получают доступ к элементам типа DiagnosticSovdContentElementDataWithKey, тогда как продвижение вперед осуществляется с помощью оператора инкремента. В качестве ключевого граничного условия все функции специфицированы как noexcept и потокобезопасные ([SWS_DM_02263]). Интерпретация: вызывающее приложение должно перед каждым доступом самостоятельно проверять, достигнут ли конец последовательности, чтобы предотвратить неопределенное поведение.

Контекст

Класс ara::diag::DiagnosticSovdRecordContentElementDataIterator специфицирован в AUTOSAR Adaptive Platform как итератор для элементов данных записей SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_02258], AUTOSAR_AP_SWS_Diagnostics §8.60.10 «Class: DiagnosticSovdRecordContentElementDataIterator»). В подсистеме диагностики он служит стандартизированным интерфейсом доступа для поэлементного обхода структурированных диагностических данных записи SOVD.

К основным партнерам по взаимодействию относятся запрашивающее диагностическое приложение, обрабатывающее данные записи, а также базовая структура данных диагностического модуля. Итератор обеспечивает доступ к отдельным элементам данных типа DiagnosticSovdContentElementDataWithKey, предоставляя через свои операторы разыменования на выбор ссылки или указатели на эти элементы данных ([SWS_DM_02259], [SWS_DM_02260]).

Жизненный цикл

Экземпляры итератора обычно создаются при операциях запроса к содержимому SOVD. Спецификация не определяет для итератора отдельного открытого конструктора в рамках API; поэтому экземпляры, скорее всего, предоставляются вышестоящими контейнерами или функциями запроса и копируются по значению. Итератор ссылается на существующие полезные данные, не принимая на себя владение ими.

Жизненный цикл в рамках процесса обхода управляется шагами вперед и сравнениями позиций. С помощью префиксного оператора инкремента operator++ итератор переключается на следующий элемент данных ([SWS_DM_02263]). Корректность и достижение конца последовательности определяются с помощью операторов равенства и неравенства operator== ([SWS_DM_02261]) и operator!= ([SWS_DM_02262]) относительно сигнального или конечного итератора (sentinel / end).

С точки зрения параллелизма все функции-члены класса явно специфицированы как потокобезопасные ([SWS_DM_02259], [SWS_DM_02260], [SWS_DM_02261], [SWS_DM_02262], [SWS_DM_02263]). Это допускает параллельный доступ по чтению к отдельным экземплярам итератора в многопоточных средах.

Путь использования

Типичный процесс обработки содержимого SOVD-записи следует классическому паттерну однонаправленного итератора C++:

  • Проверка условия завершения: перед каждым доступом приложение сравнивает текущую позицию с конечным итератором с помощью operator!= ([SWS_DM_02262]).
  • Доступ к элементу: если итератор указывает на допустимый элемент, приложение либо обращается по ссылке через operator* к DiagnosticSovdContentElementDataWithKey ([SWS_DM_02259]), либо использует оператор доступа к элементу operator-> ([SWS_DM_02260]), чтобы напрямую адресовать методы или поля элемента данных.
  • Переход к следующему: с помощью operator++ итератор инкрементируется на следующую позицию ([SWS_DM_02263]).

Диаграмма последовательности: типичный процесс обхода элементов данных SOVD-записи. Источники: [SWS_DM_02259], [SWS_DM_02260], [SWS_DM_02262], [SWS_DM_02263].

Сценарии ошибок

Все специфицированные операции итератора объявлены как исключениебезопасные (exception safe) и как noexcept ([SWS_DM_02259], [SWS_DM_02260], [SWS_DM_02261], [SWS_DM_02262], [SWS_DM_02263]). Это означает, что при штатной работе исключения не выбрасываются и коды ошибок для обработки не формируются.

Интерпретация: существенным предусловием для вызовов operator*, operator-> и operator++ является то, что итератор должен ссылаться на допустимую позицию и не должен соответствовать конечному итератору. Переход к следующему элементу или разыменование недействительного итератора в контексте стандарта C++, вероятно, приведет к неопределенному поведению. Поэтому приложения должны строго проверять достижение конца с помощью operator!= или operator== ([SWS_DM_02261], [SWS_DM_02262]).

Настоящее руководство по классу основано на спецификации AUTOSAR Adaptive Platform R25-11 (модуль diag) и обобщает требования к ara::diag::DiagnosticSovdRecordContentElementDataIterator.

Использование и семантика

Оператор разыменования operator-> класса ara::diag::DiagnosticSovdRecordContentElementDataIterator служит для синхронного доступа к членам адресуемого элемента данных ([SWS_DM_02260]). Вызов возвращает указатель типа DiagnosticSovdContentElementDataWithKey* на текущий элемент ([SWS_DM_02260]). Интерфейс определен в заголовке ara/diag/diagnostic_sovd_content_element_data.h ([SWS_DM_02260]).

Параллелизм и граничные условия

Функция указана как noexcept, гарантирует безопасность по исключениям (exception safe) и специфицирована как thread-safe ([SWS_DM_02260]). Специфического кода ошибки для этой функции-члена не существует. Интерпретация: перед вызовом итератор должен указывать на действительный элемент данных и не должен соответствовать концу диапазона, так как разыменование недействительного итератора, вероятно, приведет к неопределенному поведению.

Взаимодействие

Итератор используется в рамках обработки содержимого записей совместно с другими функциями:

  • Он может быть получен через операции поиска, такие как Find на DiagnosticSovdRecordContentElementDataView ([SWS_DM_02285]).
  • Управление циклом обычно осуществляется через префиксный оператор инкремента operator++ ([SWS_DM_02263]), а также оператор неравенства operator!= ([SWS_DM_02262]) при сопоставлении с конечным итератором из RecordEnd ([SWS_DM_02360]).
  • Для контекстов, доступных только для чтения, доступен DiagnosticSovdRecordContentElementDataConstIterator, чей operator-> возвращает указатель на const DiagnosticSovdContentElementDataWithKey ([SWS_DM_02266]).

Это указание по использованию создано автоматически и основано на спецификациях AUTOSAR.
