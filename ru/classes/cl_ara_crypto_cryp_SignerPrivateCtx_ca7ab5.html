Контекст

Интерфейс ara::crypto::cryp::SignerPrivateCtx определяет контекст для криптографических операций подписи с использованием закрытого ключа на платформе AUTOSAR Adaptive Platform. Являясь специализацией CryptoContext, он инкапсулирует алгоритмическую логику создания цифровых подписей для блоков сообщений произвольного размера.

К основным партнерам по взаимодействию интерфейса относятся:

  • Вызывающий компонент приложения: управляет процессом подписи, передает входные данные и принимает результат подписи.
  • Объекты ключей: контексту требуется доступ к материалу закрытого ключа. Он либо передается напрямую в виде PrivateKey::Sptr [SWS_CRYPT_23515], либо подключается через ссылочный слот ключа KeySlot::Sptr [SWS_CRYPT_50036].
  • Буферы памяти: входные данные и необязательные контекстные данные предоставляются в виде ReadOnlyMemRegion, тогда как результирующее значение подписи записывается в доступный для записи буфер типа ReadWriteMemRegion [SWS_CRYPT_23512], [SWS_CRYPT_50040].

Жизненный цикл

Экземпляры контекста обычно управляются с помощью смарт-указателей через предоставленный псевдоним типа ara::crypto::cryp::SignerPrivateCtx::Sptr (определенный как std::shared_ptr<SignerPrivateCtx>) [SWS_CRYPT_23501]. Поскольку класс предоставляет чисто виртуальные методы интерфейса, создание объектов, вероятно, выполняется с помощью фабричного метода вышестоящей криптографической службы.

Жизненный цикл контекста делится на отдельные фазы:

  1. Не инициализирован: непосредственно после инстанцирования контексту не сопоставлен ни один ключ. Прямые вызовы подписи или запуска в этом состоянии отклоняются с ошибкой [SWS_CRYPT_23512], [SWS_CRYPT_50037].
  2. Сконфигурирован (готов): благодаря вызову SetKey() с PrivateKey::Sptr [SWS_CRYPT_23515] или KeySlot::Sptr [SWS_CRYPT_50036] контекст становится готовым к работе. Из этого состояния можно либо выполнить One-Shot-подписание через Sign(), либо инициировать потоковую обработку.
  3. Потоковая обработка активна: вызов Start() [SWS_CRYPT_50037] или Start(context) [SWS_CRYPT_50038] переводит контекст в режим текущей обработки. В этой фазе могут выполняться итеративные обновления через Update() [SWS_CRYPT_50039].
  4. Завершение или отмена: текущая последовательность потоковой обработки штатно завершается с помощью Finish() [SWS_CRYPT_50040] или досрочно сбрасывается через Cancel() [SWS_CRYPT_50041]. После обоих методов контекст, предположительно, остается в сконфигурированном состоянии с назначенным ключом, благодаря чему можно сразу запустить новое вычисление подписи.

Все методы интерфейса объявлены как noexcept, обладают уровнем безопасности исключений exception safe и, согласно спецификации, спроектированы как thread-safe [SWS_CRYPT_50041].

Диаграмма состояний: жизненный цикл и состояния обработки SignerPrivateCtx. Источники: [SWS_CRYPT_23515], [SWS_CRYPT_50036], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040], [SWS_CRYPT_50041], [SWS_CRYPT_23512]

Путь использования

Интерфейс поддерживает два функциональных пути использования для вычисления подписи:

1. Потоковое создание подписи: этот путь подходит для больших сообщений или сообщений, поступающих фрагментами. Перед началом можно определить максимально допустимый размер блока через GetMaximumChunkSize() [SWS_CRYPT_50042] и ожидаемую длину подписи для определенного целевого формата через GetSignatureSize() [SWS_CRYPT_29004]. После назначения ключа через SetKey() [SWS_CRYPT_23515] вычисление инициализируется с помощью Start() [SWS_CRYPT_50037]. Затем части сообщений последовательно передаются через Update() [SWS_CRYPT_50039]. Вызов Finish() [SWS_CRYPT_50040] завершает создание подписи и записывает результат в предоставленный буфер.

Диаграмма последовательности: типичный процесс потокового создания подписи. Источники: [SWS_CRYPT_23515], [SWS_CRYPT_29004], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040]

2. Создание подписи за один вызов (Single-Call): если полное сообщение уже находится в непрерывной области памяти, в качестве альтернативы можно вызвать метод Sign() [SWS_CRYPT_23512]. Он обрабатывает сообщение, желаемый формат и необязательные контекстные данные за один атомарный шаг и записывает подпись непосредственно в выходной буфер.

<li><strong>Объекты ключей:</strong> контексту требуется доступ к материалу закрытого ключа. Он либо передается напрямую в виде <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a>, либо подключается через ссылочный слот ключа <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>.</li>
<li><strong>Буферы памяти:</strong> входные данные и необязательные контекстные данные предоставляются в виде <code>ReadOnlyMemRegion</code>, тогда как результирующее значение подписи записывается в доступный для записи буфер типа <code>ReadWriteMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>.</li>
</ul>

<h4>Жизненный цикл</h4>
<p>Экземпляры контекста обычно управляются с помощью смарт-указателей через предоставленный псевдоним типа <code>ara::crypto::cryp::SignerPrivateCtx::Sptr</code> (определенный как <code>std::shared_ptr&lt;SignerPrivateCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>. Поскольку класс предоставляет чисто виртуальные методы интерфейса, создание объектов, вероятно, выполняется с помощью фабричного метода вышестоящей криптографической службы.</p>
<p>Жизненный цикл контекста делится на отдельные фазы:</p>
<ol>
<li><strong>Не инициализирован:</strong> непосредственно после инстанцирования контексту не сопоставлен ни один ключ. Прямые вызовы подписи или запуска в этом состоянии отклоняются с ошибкой <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>.</li>
<li><strong>Сконфигурирован (готов):</strong> благодаря вызову <code>SetKey()</code> с <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> или <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a> контекст становится готовым к работе. Из этого состояния можно либо выполнить One-Shot-подписание через <code>Sign()</code>, либо инициировать потоковую обработку.</li>
<li><strong>Потоковая обработка активна:</strong> вызов <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a> или <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50038" href="../spec/record.html?id=SWS_CRYPT_50038">[SWS_CRYPT_50038]</a> переводит контекст в режим текущей обработки. В этой фазе могут выполняться итеративные обновления через <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>.</li>
<li><strong>Завершение или отмена:</strong> текущая последовательность потоковой обработки штатно завершается с помощью <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> или досрочно сбрасывается через <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>. После обоих методов контекст, предположительно, остается в сконфигурированном состоянии с назначенным ключом, благодаря чему можно сразу запустить новое вычисление подписи.</li>
</ol>
<p>Все методы интерфейса объявлены как <code>noexcept</code>, обладают уровнем безопасности исключений <em>exception safe</em> и, согласно спецификации, спроектированы как thread-safe <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>.</p>

<h4>Путь использования</h4>
<p>Интерфейс поддерживает два функциональных пути использования для вычисления подписи:</p>
<p><strong>1. Потоковое создание подписи:</strong> этот путь подходит для больших сообщений или сообщений, поступающих фрагментами. Перед началом можно определить максимально допустимый размер блока через <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50042" href="../spec/record.html?id=SWS_CRYPT_50042">[SWS_CRYPT_50042]</a> и ожидаемую длину подписи для определенного целевого формата через <code>GetSignatureSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_29004" href="../spec/record.html?id=SWS_CRYPT_29004">[SWS_CRYPT_29004]</a>. После назначения ключа через <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> вычисление инициализируется с помощью <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>. Затем части сообщений последовательно передаются через <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>. Вызов <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> завершает создание подписи и записывает результат в предоставленный буфер.</p>
