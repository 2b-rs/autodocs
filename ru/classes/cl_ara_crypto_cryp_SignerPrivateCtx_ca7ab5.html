Служит для создания цифровой подписи с использованием закрытых криптографических ключей в одношаговом или потоковом режиме.

Интерфейс ara::crypto::cryp::SignerPrivateCtx инкапсулирует закрытые ключи для операций цифровой подписи на Adaptive Platform [SWS_CRYPT_23501]. После конфигурации ключа через SetKey() сообщения могут подписываться либо в один шаг с помощью Sign(), либо в несколько этапов через Start(), Update() и Finish() [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50040]. Все вызовы являются потокобезопасными и сигнализируют об ошибках, таких как недостаточная емкость буфера или недопустимые состояния контекста, через ara::core::Result [SWS_CRYPT_50040].

Контекст

Интерфейс ara::crypto::cryp::SignerPrivateCtx представляет контекст криптографического выполнения для операций цифровой подписи с использованием закрытого ключа на AUTOSAR Adaptive Platform. Класс наследуется от CryptoContext и инкапсулирует алгоритмы асимметричной подписи. Для подключения необходимого ключевого материала контекст взаимодействует либо напрямую с объектом закрытого ключа через PrivateKey::Sptr [SWS_CRYPT_23515], либо с управляемым слотом для ключа через KeySlot::Sptr [SWS_CRYPT_50036]. Вызывающие стороны обычно управляют экземплярами этого интерфейса через определенный псевдоним типа умного указателя ara::crypto::cryp::SignerPrivateCtx::Sptr [SWS_CRYPT_23501].

Жизненный цикл

Экземпляры SignerPrivateCtx работают как объекты с состоянием и управляются через структуры shared-указателей (std::shared_ptr) [SWS_CRYPT_23501]. Перед выполнением криптографических вычислений экземпляр находится в неинициализированном состоянии и требует назначения подходящего ключа. С помощью метода SetKey() контексту либо назначается конкретный закрытый ключ [SWS_CRYPT_23515], либо сохраняется KeySlot, значение ключа которого используется в момент запуска вычисления подписи [SWS_CRYPT_50036]. Как только ключ успешно привязан, контекст переходит в готовое к работе состояние. Все методы интерфейса специфицированы как исключениебезопасные (exception safe) и потокобезопасные (thread-safe) [SWS_CRYPT_23512] [SWS_CRYPT_50037].

В рамках обработки данных интерфейс различает однократное подписание и многоэтапные потоковые процедуры. Операция потоковой подписи инициируется с помощью Start() [SWS_CRYPT_50037] [SWS_CRYPT_50038], пошагово снабжается блоками данных через Update() [SWS_CRYPT_50039] и финализируется с помощью Finish() [SWS_CRYPT_50040]. В качестве альтернативы текущая потоковая передача может быть в любой момент прервана через Cancel(), в результате чего экземпляр возвращается в готовое к работе состояние [SWS_CRYPT_50041].

Диаграмма состояний: переходы состояний контекста подписи от конфигурации до завершения операции. Источники: [SWS_CRYPT_23515], [SWS_CRYPT_50036], [SWS_CRYPT_23512], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040], [SWS_CRYPT_50041]

Путь использования

Приложения могут создавать подписи либо за один шаг (Single-Call), либо в виде непрерывного потока данных (Streaming). Перед выполнением приложение определяет через GetSignatureSize() ожидаемый размер буфера для требуемого формата подписи FormatId [SWS_CRYPT_29004], а также через GetMaximumChunkSize() максимально допустимый размер блока для отдельных операций считывания [SWS_CRYPT_50042].

В одношаговом сценарии полное сообщение подписывается напрямую с помощью Sign(). Метод принимает входное сообщение, целевой буфер ReadWriteMemRegion, формат подписи, а также опциональное значение контекста, специфичное для алгоритма, и возвращает фактическое количество записанных байтов [SWS_CRYPT_23512].

Для больших объемов данных или фрагментированных сообщений потоковый сценарий следует трехфазному шаблону:

  1. Инициализация: вызов Start() без параметров [SWS_CRYPT_50037] или с контекстным буфером, специфичным для приложения ReadOnlyMemRegion [SWS_CRYPT_50038].
  2. Обработка: повторяющаяся передача фрагментов сообщений через Update(), при этом каждый блок должен укладываться в верхнюю границу, заданную GetMaximumChunkSize() [SWS_CRYPT_50039] [SWS_CRYPT_50042].
  3. Завершение или прерывание: финализация формирования подписи и запись в целевую память через Finish() [SWS_CRYPT_50040] или досрочное прерывание текущей операции с помощью Cancel() [SWS_CRYPT_50041].

Диаграмма последовательности: типичный процесс потокового создания подписи с проверкой буфера и финализацией. Источники: [SWS_CRYPT_23515], [SWS_CRYPT_29004], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040]

Сценарии ошибок

Вызовы методов по умолчанию возвращают ara::core::Result и при сбоях используют стандартизированные коды ошибок из ara::crypto::CryptoErrc с семантикой отката. Распространенные причины ошибок включают:

  • CryptoErrc::kUninitializedContext: вызов Sign() или Start() до привязки ключа через SetKey() [SWS_CRYPT_23512] [SWS_CRYPT_50037] [SWS_CRYPT_50038].
  • CryptoErrc::kUsageViolation: предоставленный ключ не обладает необходимыми правами на использование kAllowSigGeneration [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50037].
  • CryptoErrc::kIncompatibleObject: переданный PrivateKey или KeySlot несовместим с алгоритмом контекста [SWS_CRYPT_23515] [SWS_CRYPT_50036].
  • CryptoErrc::kProcessingNotStarted: вызов Update(), Finish() или Cancel() без предварительного успешного вызова Start() [SWS_CRYPT_50039] [SWS_CRYPT_50040] [SWS_CRYPT_50041].
  • CryptoErrc::kInsufficientCapacity: выходной буфер, переданный для Sign() или Finish(), меньше записываемой подписи [SWS_CRYPT_23512] [SWS_CRYPT_50040].
  • CryptoErrc::kUnsupportedFormat: запрошенный FormatId не поддерживается контекстом [SWS_CRYPT_29004] [SWS_CRYPT_23512] [SWS_CRYPT_50040].
  • CryptoErrc::kEmptyKeySlot: сконфигурированный KeySlot на момент выполнения не содержит ключа [SWS_CRYPT_23512] [SWS_CRYPT_50037].
  • CryptoErrc::kInvalidInputSize: некорректные размеры буфера при вызовах Sign(), Start() или Update() [SWS_CRYPT_23512] [SWS_CRYPT_50038] [SWS_CRYPT_50039].

Это руководство основано исключительно на требованиях спецификации AUTOSAR Adaptive для модуля crypto в релизе R25-11.

Метод Cancel() служит для синхронного прерывания выполняющейся, ещё не завершённой потоковой операции внутри класса ara::crypto::cryp::SignerPrivateCtx, которая ранее была инициирована вызовом Start() [SWS_CRYPT_50041]. Чисто виртуальный интерфейс virtual ara::core::Result<void> Cancel() noexcept = 0; объявлен в заголовочном файле ara/crypto/cryp/signer_private_ctx.h, не принимает входных параметров и сигнализирует об успешном прерывании через пустой ara::core::Result<void> [SWS_CRYPT_50041]. Для вызывающей стороны метод специфицирован как безопасный относительно исключений (exception safe) и потокобезопасный при конкурентном доступе (thread-safe) [SWS_CRYPT_50041].

В отношении порядка вызовов и обработки ошибок Cancel() обязательно требует активной обработки: если обработка данных предварительно не была инициирована вызовом метода Start(), прерывание завершается ошибкой и возвращает код ошибки ara::crypto::CryptoErrc::kProcessingNotStarted с определённой семантикой отката [SWS_CRYPT_50041]. Интерпретация: после успешного вызова Cancel() контекст, по-видимому, возвращается в исходное незапущенное состояние, так что может быть начата новая операция подписи или потоковой обработки.

Проектное решение следует единому принципу для всех потоковых операций в криптографическом модуле. Полностью идентичные сигнатуры и семантика ошибок существуют для таких родственных контекстов, как VerifierPublicCtx [SWS_CRYPT_50023], MessageAuthnCodeCtx [SWS_CRYPT_50027], SymmetricCipherCtx [SWS_CRYPT_50046], HashFunctionCtx [SWS_CRYPT_50058], DecryptorPrivateCtx [SWS_CRYPT_50069], AuthCipherCtx [SWS_CRYPT_50077], а также EncryptorPublicCtx [SWS_CRYPT_50089].

      Использование
      

      Метод ara::crypto::cryp::SignerPrivateCtx::Finish синхронно завершает создание подписи и записывает вычисленную подпись непосредственно в предоставленный выходной буфер signature [SWS_CRYPT_50040]. В качестве входных параметров функция ожидает доступную для записи область памяти signature (тип ReadWriteMemRegion) и требуемый формат signatureFormat (тип FormatId) [SWS_CRYPT_50040]. В качестве возвращаемого значения ara::core::Result<size_t> передает фактический размер записанных данных подписи в байтах; этот объем данных может быть меньше емкости целевого буфера [SWS_CRYPT_50040].
      


      Обработка ошибок
      

      Для всех возникающих случаев ошибок специфицирована семантика отката [SWS_CRYPT_50040]. Через результат могут возвращаться следующие коды ошибок:
      

        

      • ara::crypto::CryptoErrc::kProcessingNotStarted: создание подписи не было предварительно успешно запущено [SWS_CRYPT_50040].
        • 

      • ara::crypto::CryptoErrc::kInsufficientCapacity: емкость переданного выходного буфера signature слишком мала [SWS_CRYPT_50040].
        • 

      • ara::crypto::CryptoErrc::kUnsupportedFormat: значение signatureFormat неизвестно или не поддерживается [SWS_CRYPT_50040].
        • 

      


      Параллелизм и ограничения
      

      Метод специфицирован как thread-safe и exception safe и не должен генерировать исключений (noexcept) [SWS_CRYPT_50040]. Корректный вызов обязательно предполагает, что процесс создания в контексте был предварительно успешно инициирован [SWS_CRYPT_50040].
      


      Взаимодействие
      

      Прямым функциональным аналогом для верификации созданной подписи является метод ara::crypto::cryp::VerifierPublicCtx::Finish [SWS_CRYPT_50022]. По сравнению с контекстами для вычисления хэша или MAC, в которых Finish() только финализирует вычисление, а промежуточный или конечный результат извлекается отдельно [SWS_CRYPT_21115] [SWS_CRYPT_21116], SignerPrivateCtx::Finish записывает подпись непосредственно в буфер [SWS_CRYPT_50040].
