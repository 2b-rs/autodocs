Контекст

Класс ara::diag::DoIPTriggerVehicleAnnouncement [SWS_DM_00820] предоставляет программный интерфейс в рамках AUTOSAR Adaptive Platform (модуль diag), с помощью которого Adaptive Application может инициировать отправку сообщений с объявлением автомобиля DoIP (Vehicle Announcement Messages).

Согласно AUTOSAR_AP_SWS_Diagnostics с. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface», основная ответственность за отправку этих сообщений возложена непосредственно на Diagnostic Manager (DM). Стандарт предусматривает, что DM отправляет объявления автомобиля самостоятельно на основе сценариев, определенных в ISO 13400-2:

  • при запуске сети в виде широковещательной рассылки другим блокам управления на базе IP и шлюзам,
  • при обнаружении внешнего тестера через линию активации (Activation Line).

Хотя штатный процесс согласно ISO 13400-2 предусматривает автономную обработку со стороны DM, и ручной запуск со стороны Adaptive Application там изначально не предусмотрен (AUTOSAR_AP_SWS_Diagnostics с. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface»), интерфейс ara::diag::DoIPTriggerVehicleAnnouncement тем не менее позволяет приложению выполнять явный запуск. При этом DM выступает в качестве исполнителя, который отправляет сообщения согласно ISO 13400-2 через указанный сетевой интерфейс [SWS_DM_00815].

Жизненный цикл

Создание экземпляров и управление жизненным циклом ara::diag::DoIPTriggerVehicleAnnouncement полностью находятся в ведении Diagnostic Manager:

  • Создание и уничтожение: конструктор по умолчанию объявлен удаленным (DoIPTriggerVehicleAnnouncement() = delete) и закрытым [SWS_DM_02100]. Деструктор также является закрытым и удаленным (~DoIPTriggerVehicleAnnouncement() noexcept = delete) [SWS_DM_02101]. Оба метода реализованы специфично для поставщика [SWS_DM_02100], [SWS_DM_02101]. Таким образом, Adaptive Application не может создавать собственные экземпляры в стеке или куче.
  • Получение экземпляра: доступ к интерфейсу осуществляется исключительно через статический фабричный метод GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]. Он возвращает объект типа ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>, предоставляющий ссылку на объект, управляемый DM.
  • Параллелизм: как фабричный метод GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821], так и метод TriggerVehicleAnnouncement() [SWS_DM_00822] явно специфицированы как потоконебезопасные (not thread-safe). Если несколько потоков приложения обращаются к интерфейсу, вызывающая сторона должна обеспечить синхронизацию. Оба метода специфицированы как безопасные относительно исключений (exception safe) [SWS_DM_00821], [SWS_DM_00822].

Путь использования

Типичный процесс запуска объявления автомобиля подразделяется на следующие шаги:

  1. Запрос ссылки на интерфейс: Adaptive Application вызывает статическую функцию ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821].
  2. Проверка результата: приложение проверяет возвращенный ara::core::Result на успешность и извлекает std::reference_wrapper.
  3. Запуск объявления: с помощью полученной ссылки приложение вызывает метод TriggerVehicleAnnouncement(networkInterfaceId) [SWS_DM_00822]. Параметр networkInterfaceId (тип std::uint8_t) задает целевой сетевой интерфейс.
  4. Отправка через DM: Diagnostic Manager инициирует отправку сообщений с объявлением согласно ISO 13400-2 через указанный сетевой интерфейс [SWS_DM_00815] и подтверждает выполнение приложению с помощью ara::core::Result<void> [SWS_DM_00822].

Диаграмма последовательности: шаблон взаимодействия для явного запуска объявлений автомобиля DoIP. Источники: [SWS_DM_00821], [SWS_DM_00822], [SWS_DM_00815].

Сценарии ошибок

При вызове TriggerVehicleAnnouncement() действуют особые предварительные условия относительно конфигурации сети:

  • Конфликт с интерфейсами, управляемыми линией активации: если переданная networkInterfaceId относится к конфигурации, в которой установлено свойство isActivationLineDependent = TRUE, данный вызов метода является ошибкой [SWS_DM_00822]. Причина заключается в том, что отправка через такие интерфейсы согласно [SWS_DM_00816] уже происходит полностью автоматически с помощью DM, как только на линии активации появляется высокий уровень и назначается IP-адрес [SWS_DM_00822].
  • Отсутствие стандартизированных кодов ошибок: ни для GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821], ни для TriggerVehicleAnnouncement() [SWS_DM_00822] в стандарте не специфицированы конкретные коды ошибок («This function does not specify any standardized errors»). Если ошибка все же возникает (например, передача интерфейса, зависящего от линии активации, или внутренняя ошибка), ara::core::Result, вероятно, передает коды ошибок, специфичные для поставщика.

Настоящее руководство основано на спецификации AUTOSAR Adaptive Platform версии R25-11.
