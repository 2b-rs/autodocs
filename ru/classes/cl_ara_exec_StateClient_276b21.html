класс ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Контекст

Класс ara::exec::StateClient функционирует как функциональный интерфейс Execution Management для State Management. В общей системе задача State Management заключается в управлении жизненным циклом машины, а также в запуске и остановке программных компонентов по мере необходимости. Это осуществляется посредством переходов между состояниями сконфигурированных групп функций (Function Groups), которым интегратор сопоставил конкретные программные процессы.

State Management использует ara::exec::StateClient для запроса у Execution Management переходов между состояниями для отдельных групп функций [SWS_EM_02278]. Execution Management выполняет эти переходы, запуская или завершая работу программного обеспечения, назначенного группе функций, и возвращает результат перехода в State Management. Для установления соединения с Execution Management в фоновом режиме, вероятно, используется платформозависимый IPC-канал (например, сокеты домена Unix), поскольку спецификация не ограничивает точную технологию IPC.

Контекстная диаграмма: встраивание StateClient между State Management, Execution Management и управляемыми программными процессами. Источники: [SWS_EM_02278]

Жизненный цикл

Для инстанцирования ara::exec::StateClient AUTOSAR предоставляет два пути конструирования:

  • Именованный фабричный метод: статическая функция Create возвращает ara::core::Result<StateClient> и инкапсулирует потенциальные ошибки при создании на основе кодов ошибок и с гарантией безопасности исключений ([SWS_EM_02276]).
  • Обычный конструктор: прямой конструктор объявлен как noexcept(false) и в случае сбоя сигнализирует об ошибках через исключения ([SWS_EM_02561]).

Оба пути создания требуют передачи обратного вызова undefinedStateCallback с сигнатурой std::function<void(const ara::exec::ExecutionErrorEvent&)>. Этот обратный вызов выполняется библиотекой StateClient, если группа функций неожиданно и без предварительного запроса через SetState переходит в неопределённое состояние (Undefined Function Group State) ([SWS_EM_02276], [SWS_EM_02561]). С точки зрения времени жизни необходимо строго обеспечить, чтобы этот обратный вызов оставался доступным для вызова на протяжении всего времени жизни экземпляра StateClient; в частности, это относится к привязке методов экземпляра через std::bind ([SWS_EM_02276], [SWS_EM_02561]).

Операции копирования полностью запрещены: как конструктор копирования, так и оператор присваивания явно удалены (delete) ([SWS_EM_02565], [SWS_EM_02568]). Напротив, класс поддерживает семантику перемещения: конструктор перемещения и оператор присваивания перемещением определены как noexcept ([SWS_EM_02566], [SWS_EM_02567]). Деструктор объявлен как noexcept ([SWS_EM_02277]). Как только изменение состояния получено Execution Management, оно обрабатывается независимо от времени жизни экземпляра StateClient; однако возвращаемый SetState объект ara::core::Future зависит от времени жизни экземпляра ([SWS_EM_02278]).

Что касается параллелизма, методы экземпляра SetState, GetExecutionError и GetInitialMachineStateTransitionResult, а также Create и обычный конструктор специфицированы как потокобезопасные ([SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542], [SWS_EM_02561]). Операции перемещения и деструктор, напротив, не являются потокобезопасными ([SWS_EM_02566], [SWS_EM_02567], [SWS_EM_02277]).

Путь использования

Типовой сценарий использования со стороны State Management подразделяется на следующие шаги:

  1. Создание клиента: State Management инстанцирует StateClient через Create с регистрацией обратного вызова для обработки ошибок ([SWS_EM_02276]).
  2. Синхронизация начального состояния: в начале работы машины через GetInitialMachineStateTransitionResult() запрашивается результат исходного перехода машины в состояние Startup ([SWS_EM_02279]). Метод возвращает ara::core::Future<void>. Поскольку этот переход происходит ровно один раз за жизненный цикл машины, результат остаётся неизменным на протяжении всего оставшегося времени работы ([SWS_EM_02279]).
  3. Запрос смены состояния: во время выполнения State Management запрашивает через SetState(state) переходы для отдельных групп функций ([SWS_EM_02278]). Метод немедленно возвращает управление и предоставляет ara::core::Future<void>, которое указывает на успешность перехода или предоставляет ошибку из ExecErrorDomain.
  4. Анализ ошибочных состояний: если группа функций непредвиденно переходит в неопределённое состояние, срабатывает зарегистрированный обратный вызов. State Management может получить через GetExecutionError(functionGroupState) инициирующее ExecutionErrorEvent, пока группа функций всё ещё находится в этом состоянии ([SWS_EM_02542]).

Диаграмма последовательности: процесс от создания через асинхронный запрос состояния до завершения перехода. Источники: [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279]

Сценарии ошибок

Методы ara::exec::StateClient используют коды ошибок из домена ошибок Execution Management (ara::exec::ExecErrc). Актуальны следующие сценарии ошибок:

  • Сбой связи (ExecErrc::kNoCommunication): возникает, если соединение между клиентом и Execution Management нарушено или прервано. Эта ошибка специфицирована для всех операций ([SWS_EM_02276], [SWS_EM_02561], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]). Повторный вызов является предусмотренной мерой восстановления.
  • Недопустимая передача параметров и конфликты метамодели:
    • ExecErrc::kInvalidArgument при создании сигнализирует о том, что переданный undefinedStateCallback недоступен для вызова ([SWS_EM_02276], [SWS_EM_02561]).
    • ExecErrc::kInvalidMetaModelIdentifier указывает на то, что целевое состояние не существует в манифесте или вызывающий процесс не имеет сопоставления с соответствующей группой функций ([SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]).
  • Сбой или прерывание переходов между состояниями:
    • ExecErrc::kOperationCanceled информирует о том, что переход был вытеснен более новым запросом или отменён со стороны State Management ([SWS_EM_02278], [SWS_EM_02279]).
    • ExecErrc::kInvalidTransition возвращается, если переход недопустим (например, переключение в состояние Off для MachineFG) или состояние больше не существует после обновления программного обеспечения ([SWS_EM_02278]).
    • ExecErrc::kIntegrityOrAuthenticityCheckFailed сообщает о сбое проверок подлинности или целостности во время смены состояния ([SWS_EM_02278]).
    • ExecErrc::kUnexpectedTermination возникает, если участвующий процесс был неожиданно завершен во время перехода ([SWS_EM_02278]).
    • ExecErrc::kOperationFailed указывает на общий сбой перехода ([SWS_EM_02278], [SWS_EM_02279]). При вызове GetExecutionError эта ошибка, напротив, говорит о том, что группа функций не находится в неопределенном состоянии и проблема, возможно, уже устранена ([SWS_EM_02542]).

              параметры (в)
              

              ПараметрыОписание
              staterepresenting meta-model definition of a state inside a specific Function Group. Execution Management will perform state transition from the current state to the state identified by this parameter.
              

              Возвращаемое значение
              

              ТипОписание
              ara::core::Future< void >void if requested transition is successful, otherwise it returns Exec ErrorDomain error.
              

              Ошибка
              

              Код ошибкиОписание
              ara::exec::ExecErrc::kOperationCanceledno_rollback_semantics if transition to the requested Function Group state was cancelled by a newer request. Recovery: Try again (error is informative, does not indicate a problem)
              ara::exec::ExecErrc::kOperationFailedno_rollback_semantics if transition to the requested Function Group state failed. Recovery: Try transition to another state
              ara::exec::ExecErrc::kNoCommunicationno_rollback_semantics if StateClient can’t communicate with Execution Management (e.g. IPC link is down). Rovery: Try again
              ara::exec::ExecErrc::kInvalidTransitionrollback_semantics if transition to the requested state is prohibited (e.g. Off state for MachineFG) or the requested Function Group State is invalid (e.g. does not exist anymore after a software update). Recovery: Eventually try transition to another state
              ara::exec::ExecErrc::kIntegrityOrAuthenticityCheckFailedno_rollback_semantics if an integrity or authenticity check failed during state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kUnexpectedTerminationno_rollback_semantics One of the processes terminated in an unexpected way during the state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kInvalidMetaModelIdentifierrollback_semantics The given Function Group State couldn’t be found in the Processed Manifest or Process does not have a mapping to the Function Group of the requested Function Group State. Recovery: transition to another state
              

              Hinweise: Asynchronous nature of ara::exec::StateClient::SetState makes the returned ara:: core::Future dependable on lifetime of the instance from which it was received. It is expected that once state change request is received by Execution Management, it will be processed independently of lifetime of the instance from which it was requested. Please note that the qualified short names representing Function Groups and Function Group States could be quite long. They can be replaced by implementation specific data types to speed up any checks that have to be performed by the ara::exec::StateClient:: SetState method. This is enabled by the ara::exec::FunctionGroupState data-type.

                  параметры (в)
                  

                  ПараметрыОписание
                  undefinedStateCallbackcallback to be invoked by StateClient library if a FunctionGroup changes its state unexpectedly to an Undefined Function Group State, i.e. without previous request by SetState(). The affected FunctionGroup and ExecutionError is provided as an argument to the callback in form of ExecutionErrorEvent Lifetime: it is expected that undefinedStateCallback remains callable, during entire lifetime of the StateClient instance. This is especially important if, undefinedStateCallback is bound to an instance of a class (e.g. using std::bind).
