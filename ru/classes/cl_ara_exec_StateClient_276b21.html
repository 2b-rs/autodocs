класс ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Запрашивает у Execution Management смену состояний для групп функций для управления процессами на Machine.

Интерфейс ara::exec::StateClient позволяет State Management запрашивать у Execution Management смену состояний для групп функций, чтобы управлять выполнением назначенных процессов на Machine [SWS_EM_02278]. При создании через Create() должен быть зарегистрирован непрерывно действительный callback для неожиданных неопределенных состояний [SWS_EM_02276]. Наряду с асинхронными переходами состояний этот некопируемый класс предоставляет методы для запроса результата запуска Machine, а также для анализа ошибок при сбоях выполнения [SWS_EM_02279], [SWS_EM_02542].

Контекст

Класс ara::exec::StateClient образует интерфейс Execution Management, через который State Management запрашивает переходы состояний для групп функций (Function Groups) и управляет ими. State Management использует этот клиент в течение всего времени работы Machine для целенаправленного запуска или завершения процессов. Интегратор назначает программные компоненты определенным состояниям группы функций. Если State Management требуется запустить это программное обеспечение, оно запрашивает через StateClient у Execution Management переход в соответствующее состояние группы функций; остановка выполняется аналогично путем перехода в состояние, в котором это программное обеспечение не должно быть активно [SWS_EM_02278].

Контекстная диаграмма: взаимодействие между State Management, StateClient и Execution Management. Источники: [SWS_EM_02276], [SWS_EM_02278]

Жизненный цикл

Экземпляры StateClient могут создаваться либо через именованный конструктор Create() [SWS_EM_02276] как ara::core::Result<StateClient>, либо через обычный конструктор StateClient() [SWS_EM_02561]. Оба пути конструирования обязательно требуют параметр обратного вызова undefinedStateCallback типа std::function<void(const ara::exec::ExecutionErrorEvent&)>. Этот callback вызывается библиотекой StateClient, если группа функций неожиданно и без предварительного запроса со стороны SetState() переходит в неопределенное состояние. Вызывающая сторона должна гарантировать, что этот callback остается доступным для вызова на протяжении всего времени жизни экземпляра StateClient, что особенно важно при привязках объектов через std::bind [SWS_EM_02276], [SWS_EM_02561].

Операции копирования для StateClient явно запрещены: как конструктор копирования [SWS_EM_02565], так и оператор присваивания с копированием [SWS_EM_02568] удалены (=delete). Передача владения возможна исключительно через семантику перемещения с помощью конструктора перемещения [SWS_EM_02566] и присваивания с перемещением [SWS_EM_02567]. Что касается параллелизма, прикладные методы, такие как SetState(), GetExecutionError() и GetInitialMachineStateTransitionResult(), а также создание спроектированы потокобезопасными [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]. Напротив, операции перемещения и деструктор ~StateClient() не являются потокобезопасными [SWS_EM_02277], [SWS_EM_02566], [SWS_EM_02567].

Путь использования

Типичный жизненный цикл применения подразделяется на инициализацию, запрос результата запуска, штатную смену состояний и мониторинг ошибок:

  1. Создание: State Management создает экземпляр StateClient с указанием действительного callback сигнализации об ошибках через Create() [SWS_EM_02276].
  2. Запрос начального результата запуска: с помощью GetInitialMachineStateTransitionResult() State Management запрашивает результат начального перехода состояния в состояние Startup [SWS_EM_02279]. Поскольку этот переход происходит ровно один раз за жизненный цикл Machine, возвращаемый ara::core::Future<void> остается стабильным и больше не изменяется до перезапуска.
  3. Запрос смены состояния: с помощью SetState() State Management заказывает асинхронные переходы состояний для отдельных групп функций [SWS_EM_02278]. Метод немедленно возвращает управление и возвращает ara::core::Future<void> для опроса завершения. Как только поручение поступило в Execution Management, оно выполняется независимо от дальнейшего времени жизни вызывающего экземпляра.
  4. Исследование ошибочных состояний: если группа функций неожиданно переходит в неопределенное состояние, через GetExecutionError() можно определить вызвавшую сбой ошибку выполнения в виде ara::exec::ExecutionErrorEvent [SWS_EM_02542].

Диаграмма последовательности: процесс создания, запроса начального состояния, асинхронной смены состояния и анализа ошибок. Источники: [SWS_EM_02276], [SWS_EM_02279], [SWS_EM_02278], [SWS_EM_02542]

Сценарии ошибок

Операции класса сообщают о сбоях через коды ошибок ExecErrorDomain:

  • ExecErrc::kNoCommunication: сигнализирует о сбоях связи с Execution Management, например, при прерывании IPC-соединения. Возникает при Create() [SWS_EM_02276], SetState() [SWS_EM_02278], GetInitialMachineStateTransitionResult() [SWS_EM_02279], а также GetExecutionError() [SWS_EM_02542]. Предусмотренное восстановление заключается в повторном вызове.
  • ExecErrc::kInvalidArgument: сообщается со стороны Create() и StateClient(), если переданный callback не содержит вызываемой функции [SWS_EM_02276], [SWS_EM_02561].
  • ExecErrc::kOperationCanceled: указывает в случае SetState() на то, что выполняющийся переход был отменен более новым запросом [SWS_EM_02278]. В случае GetInitialMachineStateTransitionResult() эта ошибка возникает, если начальный переход запуска был прерван, например, из-за прерванной последовательности обновления Machine [SWS_EM_02279].
  • ExecErrc::kInvalidTransition: запрошенный переход состояния недопустим, например, переход в состояние Off для MachineFG, или состояние больше не существует после обновления [SWS_EM_02278].
  • ExecErrc::kInvalidMetaModelIdentifier: переданное состояние не существует в обработанном манифесте или у процесса отсутствует сопоставление (mapping) с соответствующей группой функций [SWS_EM_02278], [SWS_EM_02542]. Если эта ошибка возникает при GetInitialMachineStateTransitionResult(), у процесса отсутствует сопоставление с MachineFG, что указывает на проблему конфигурации [SWS_EM_02279].
  • ExecErrc::kOperationFailed: переход завершился неудачно [SWS_EM_02278]. В случае GetExecutionError() код указывает на то, что группа функций не находится в неопределенном состоянии и проблема, предположительно, уже устранена [SWS_EM_02542].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed и ExecErrc::kUnexpectedTermination: специфические сбои во время SetState() вследствие неудавшихся проверок целостности или неожиданных завершений процессов во время перехода [SWS_EM_02278].

Настоящее руководство основано исключительно на требованиях спецификации AUTOSAR Adaptive R25-11.

Статический фабричный метод Create служит именованным конструктором для создания экземпляра ara::exec::StateClient ([SWS_EM_02276]). В качестве обязательного параметра передается undefinedStateCallback. Этот callback инициируется клиентской библиотекой, если группа функций неожиданно — то есть без предварительного запроса через SetState() — переходит в неопределенное состояние ([SWS_EM_02276]). При этом затронутая группа функций и ошибка передаются в callback через ExecutionErrorEvent.

Для контекста вызова и времени жизни действуют строгие рамочные условия:

  • Функция является thread-safe, exception-safe и объявлена как noexcept ([SWS_EM_02276]).
  • Переданный undefinedStateCallback должен оставаться доступным для вызова в течение всего времени жизни созданного экземпляра StateClient ([SWS_EM_02276]). Это требует особой внимательности при связывании с экземплярами объектов (например, с помощью std::bind).

Инстанцирование выполняется синхронно и возвращает ara::core::Result<StateClient> ([SWS_EM_02276]). В случае сбоя определены следующие коды ошибок:

  • ara::exec::ExecErrc::kInvalidArgument: выдается, если переданный аргумент не содержит вызываемой функции (семантика отката; устранение путем предоставления корректной функции) ([SWS_EM_02276]).
  • ara::exec::ExecErrc::kNoCommunication: сигнализирует об ошибке связи (семантика без отката; устранение путем повторной попытки) ([SWS_EM_02276]). Это, вероятно, связано с неудачной установкой соединения со средой выполнения.

Шаблон конструирования структурно соответствует подходу к инициализации родственных клиентов выполнения, таких как ara::exec::ExecutionClient ([SWS_EM_02562]), который также создается с обязательным callback через именованный конструктор.
