Предоставляет типизированный доступ для чтения и записи к элементам массива диагностических данных SOVD через индексы и итераторы.

Класс предоставляет структурированный интерфейс для произвольного и основанного на итераторах доступа к базирующимся на массивах диагностическим элементам данных Adaptive Platform ([SWS_DM_02227]). Он позволяет приложениям динамически добавлять примитивные значения данных и сложные элементы содержимого, а также превентивно резервировать емкость памяти. При несовместимых типах данных, недопустимом доступе по индексу или явно установленных состояниях ошибки вызывающей стороне передаются коды ошибок через типы Result ([SWS_DM_02228]). Все специфицированные операции согласно стандарту реализованы полностью безопасно относительно исключений и потокобезопасно.

Контекст

Класс ara::diag::DiagnosticSovdArrayContentElementDataView определён в AUTOSAR_AP_SWS_Diagnostics §8.60.5 «Class: DiagnosticSovdArrayContentElementDataView» под [SWS_DM_02227]. В диагностическом модуле AUTOSAR Adaptive он служит типизированным представлением (view) диагностического элемента содержимого (DiagnosticSovdContentElementData) с базовым типом ArrayContentElementData. Объявление осуществляется через заголовочный файл ara/diag/diagnostic_sovd_content_element_data.h.

Его основная задача заключается в структурированной инкапсуляции операций с массивами для Service-Oriented Vehicle Diagnostics (SOVD). В качестве партнеров по взаимодействию выступают вызывающие диагностические приложения, которые обрабатывают или предоставляют структуры данных SOVD, а также базовые обобщённые контейнеры данных. Доступ к отдельным элементам массива осуществляется либо через выделенные итераторы, либо через типизированные операторы индексации.

Жизненный цикл

Являясь объектом-представлением (view), экземпляр, вероятно, не обладает единоличным владением фактическими полезными данными, а привязывается к памяти существующего DiagnosticSovdContentElementData. Жизненный цикл данных включает следующие фазы:

  • Резервирование памяти и ёмкость: перед вставкой больших объёмов данных внутреннюю ёмкость памяти можно заблаговременно определить с помощью Reserve ([SWS_DM_02240]). Текущую ёмкость можно определить с помощью Capacity ([SWS_DM_02231]).
  • Заполнение: новые элементы добавляются последовательно через перегрузки PushBack. Поддерживаются примитивные типы данных, такие как std::int64_t ([SWS_DM_02241]), std::uint64_t ([SWS_DM_02242]), double ([SWS_DM_02243]), bool ([SWS_DM_02244]) и ara::core::StringView ([SWS_DM_02245]), а также вложенные экземпляры DiagnosticSovdContentElementData ([SWS_DM_02246]).
  • Инспекция и очистка: состояние заполнения можно запросить в любое время с помощью Size ([SWS_DM_02230]) и Empty ([SWS_DM_02232]). Отдельные элементы можно удалить с помощью итератора через Erase ([SWS_DM_02247]), тогда как Clear ([SWS_DM_02233]) сбрасывает весь массив.

Что касается параллелизма и поведения при исключениях, то согласно спецификации все функции-члены класса спроектированы как безопасные к исключениям (объявлены с noexcept) и потокобезопасные («thread-safe»).

Путь использования

Типичный сценарий использования включает предварительное резервирование ёмкости, пошаговое заполнение данными, считывание элементов, а также финальную валидацию на наличие состояний ошибок:

  1. Резервирование ёмкости: приложение вызывает Reserve, чтобы минимизировать динамические перераспределения при последующих операциях записи ([SWS_DM_02240]).
  2. Вставка элементов: наборы данных добавляются с помощью PushBack ([SWS_DM_02241]).
  3. Чтение или обход элементов: доступ осуществляется либо произвольно через operator[] ([SWS_DM_02234], [SWS_DM_02235]), либо последовательно через итераторы с помощью Begin/End ([SWS_DM_02236], [SWS_DM_02237]) или CBegin/CEnd ([SWS_DM_02238], [SWS_DM_02239]).
  4. Проверка статуса: после завершения операций приложение проверяет с помощью HasError, не содержит ли ошибок содержимое массива ([SWS_DM_02228]).

Диаграмма последовательности: типичный процесс заполнения, индексации и проверки ошибок элемента массива SOVD. Источники: [SWS_DM_02240], [SWS_DM_02241], [SWS_DM_02234], [SWS_DM_02228].

Сценарии ошибок

Методы с потенциалом ошибок используют ara::core::Result для возврата информации о нарушенных предусловиях или прерывании выполнения вместо исключений C++:

  • Несоответствие типов: такие операции, как PushBack ([SWS_DM_02241]) или operator[] ([SWS_DM_02234]), требуют, чтобы инкапсулированный элемент действительно имел тип ArrayContentElementData. В противном случае они возвращают соответствующую ошибку в объекте Result. При PushBack вставляемый тип должен, кроме того, соответствовать типу данных, заданному в конструкторе элемента массива.
  • Неудачное удаление: вызов Erase ([SWS_DM_02247]) возвращает ошибку в Result, если цель не относится к типу ArrayContentElementData или элемент не удалось удалить по указанному итератору.
  • Явные состояния ошибок: через SetError ([SWS_DM_02229]) содержимому массива может быть присвоен ara::core::ErrorCode. Если содержимое помечено таким образом как ошибочное, запрос HasError ([SWS_DM_02228]) возвращает код ошибки как ara::diag::DiagSovdErrc.

Он работает синхронно, не принимает параметров и не возвращает значения ([SWS_DM_02233]).

    Синхронный метод Reserve класса ara::diag::DiagnosticSovdArrayContentElementDataView служит для предварительного выделения емкости памяти для элементов данных массива ([SWS_DM_02240], SWS Diagnostics §8.60.5.1.1.16 «Reserve»). Он предоставляется через заголовочный файл #include "ara/diag/diagnostic_sovd_content_element_data.h" и принимает параметр capacity типа std::size_t, определяющий предоставляемую емкость базового DiagnosticSovdArrayContentElementData ([SWS_DM_02240]). Возвращаемое значение не возвращается ([SWS_DM_02240]).
  
                                                              
  
                                                              
    Что касается обработки ошибок, функция объявлена как исключебно-безопасная (exception safe), а также noexcept ([SWS_DM_02240]). Она не использует ни кодов ошибок через ara::core::Result, ни исключений C++. Интерпретация: при нехватке памяти выделение, вероятно, завершается сбоем внутри или приводит к аварийному завершению программы, поскольку вызывающей стороне недоступен канал передачи ошибок.
  
                                                              
  
                                                              
    С точки зрения параллелизма операция явно специфицирована как потокобезопасная (thread-safe) ([SWS_DM_02240]). Таким образом, вызовы могут выполняться из параллельных потоков без внешней блокировки.
  
                                                              
  
                                                              
    В общей системе интерфейс дополняет связанные функции резервирования: в то время как DiagnosticSovdRecordContentElementDataView::Reserve аналогично отвечает за структуры данных Record ([SWS_DM_02283], SWS Diagnostics §8.60.11.1.1.20 «Reserve»), общая функция базового класса DiagnosticSovdContentElementData::Reserve возвращает ara::core::Result<void>, чтобы сообщить об ошибке в случае неверного типа элемента ([SWS_DM_02345], SWS Diagnostics §8.60.6.1.2.55 «Reserve»). В отличие от непотокобезопасного резервирования памяти DiagnosticServiceDynamicAccessList::Reserve ([SWS_DM_01163], SWS Diagnostics §8.13.1.1.3.3 «Reserve»), этот view-метод работает напрямую и конкурентно над элементами массива SOVD.
