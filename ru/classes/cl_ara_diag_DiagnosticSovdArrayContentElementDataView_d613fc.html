Контекст

Класс ara::diag::DiagnosticSovdArrayContentElementDataView определяет структурированное представление для структур данных типа ArrayContentElementData внутри вышестоящего DiagnosticSovdContentElementData [SWS_DM_02227] AUTOSAR_AP_SWS_Diagnostics §8.60.5 с. 776. В рамках Service-Oriented Vehicle Diagnostics (SOVD) в AUTOSAR Adaptive Platform эта абстракция представления позволяет диагностическим приложениям и серверным компонентам обеспечивать типобезопасную обработку, заполнение и анализ структур массивов без необходимости вручную разбирать базовое обобщенное представление данных.

В качестве интерфейса взаимодействия представление инкапсулирует операции для гетерогенных и гомогенных списков. Оно позволяет добавлять элементарные типы данных, такие как целочисленные значения (std::int64_t, std::uint64_t), числа с плавающей запятой (double), логические значения (bool) и текстовые структуры (ara::core::StringView), а также встроенные экземпляры DiagnosticSovdContentElementData [SWS_DM_02241] [SWS_DM_02242] [SWS_DM_02243] [SWS_DM_02244] [SWS_DM_02245] [SWS_DM_02246]. Тем самым класс выступает центральным связующим звеном между внутренним представлением диагностически значимых моделей данных и прикладными функциями модуля diag.

Жизненный цикл

Класс следует семантике невладеющей оболочки (Интерпретация: как представление (View), он обычно сам не владеет управляемыми данными, а ссылается на существующий объект DiagnosticSovdContentElementData). Действительность представления привязана к времени жизни базового элемента данных. Все функции-члены согласно спецификации объявлены как noexcept и гарантируют как безопасность исключений, так и потокобезопасность [SWS_DM_02230] [SWS_DM_02231] AUTOSAR_AP_SWS_Diagnostics §8.60.5.1 с. 777.

Что касается внутреннего управления памятью и жизненным циклом, класс поддерживает предварительное резервирование памяти: с помощью Reserve можно задать целевую емкость структуры массива [SWS_DM_02240]. Новые записи добавляются через перегруженные методы PushBack. С помощью Erase можно целенаправленно удалять отдельные элементы [SWS_DM_02247], тогда как Clear освобождает все содержащиеся элементы и сбрасывает массив [SWS_DM_02233].

Путь использования

Типичный вариант использования включает выделение емкости, добавление элементов, считывание по индексу или итератору, а также проверку состояния согласованности:

  1. Проверка емкости и подготовка: перед вставкой приложение может с помощью Empty проверить, имеются ли данные [SWS_DM_02232], запросить текущий размер через Size [SWS_DM_02230], а также просмотреть буфер через Capacity [SWS_DM_02231]. Выделение памяти осуществляется через Reserve [SWS_DM_02240].
  2. Вставка данных: приложение использует PushBack для добавления примитивных типов данных или полных узлов DiagnosticSovdContentElementData [SWS_DM_02241] [SWS_DM_02246].
  3. Индексированный доступ и итерация: к элементам можно обращаться напрямую в произвольном порядке через operator[]. Как модифицирующий вариант [SWS_DM_02234], так и константный вариант [SWS_DM_02235] возвращают ссылку std::reference_wrapper внутри ara::core::Result. Для последовательного обхода доступны STL-совместимые итераторы через Begin [SWS_DM_02236], End [SWS_DM_02237], а также их константные аналоги CBegin [SWS_DM_02238] и CEnd [SWS_DM_02239] AUTOSAR_AP_SWS_Diagnostics §8.60.5.1 с. 778.
  4. Валидация: приложение проверяет статус ошибки элемента через HasError [SWS_DM_02228].

Диаграмма последовательности: последовательность вызовов для конфигурации, заполнения, индексации и валидации элемента массива SOVD. Источники: [SWS_DM_02240], [SWS_DM_02241], [SWS_DM_02234], [SWS_DM_02228].

Сценарии ошибок

Условия ошибок единообразно отображаются в интерфейсе через тип возвращаемого значения ara::core::Result:

  • Несоответствие типов: практически все модифицирующие и опрашивающие функции требуют в качестве предварительного условия, чтобы базовый DiagnosticSovdContentElementData действительно имел тип ArrayContentElementData (Интерпретация: ошибочная типизация проверяется во время выполнения). Если эта проверка завершается неудачно, такие методы, как PushBack [SWS_DM_02241] или operator[] [SWS_DM_02234], возвращают ошибочный результат в ara::core::Result.
  • Сбой при удалении: вызов Erase требует допустимого итератора, указывающего на содержащийся элемент. Если элемент не удается удалить или тип узла некорректен, об ошибке сигнализируется в возвращаемом значении [SWS_DM_02247].
  • Явные состояния ошибки: элемент массива может быть явно объявлен ошибочным путем присвоения соответствующего ara::core::ErrorCode с помощью SetError [SWS_DM_02229]. Вызывающие стороны определяют наличие такой ошибки через HasError, который при установленном коде ошибки возвращает тип ara::diag::DiagSovdErrc в качестве значения ошибки [SWS_DM_02228].

Это руководство основано на спецификации AUTOSAR Adaptive Platform R25-11 (модуль diag) и обобщает аспекты архитектуры, жизненного цикла и использования класса DiagnosticSovdArrayContentElementDataView.
