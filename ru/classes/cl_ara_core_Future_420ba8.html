Использование по назначению

ara::core::Future<T, E> представляет результат или ошибку асинхронного вызова, доступные позднее. Тип ошибки должен быть ara::core::ErrorCode, иначе требуется ошибка времени компиляции. Вместе с Promise этот тип обеспечивает потокобезопасную обработку асинхронных значений и ошибок без исключений. [SWS_CORE_00321] [SWS_CORE_10800]

Взаимодействие с другими классами

GetResult() блокируется до тех пор, пока не появится значение или ошибка, и возвращает не вызывающий срабатывание Result<T,E>. _then() генерирует последующий Future из функции через этот Result; перегрузка с Executor выполняет функцию в контексте выполнения. Ограничения & Обработка ошибок

Для заброшенного соответствующего Promise GetResult() возвращает ошибку FutureErrc::kBrokenPromise. is_ready() можно проверить перед блокировкой; для true get(), GetResult() и вызовы ожидания не блокируются. Запрещенные вызовы недействительных фьючерсов указаны как нарушения. [SWS_CORE_00336] [SWS_CORE_00332] [SWS_CORE_13011]

Future — это согласованный тип возврата для асинхронных вызовов, которые могут возвращать значение или завершаться ошибкой. В отличие от get(), GetResult() после ожидания возвращает Result со значением или ошибкой и не вызывает исключение. Общее состояние и транспорт ошибок

Функциональная спецификация рассматривает Future и Promise как асинхронный аналог пути ошибки: последующий результат может представлять значение или ошибку, не выводя обработку ошибок за пределы возврата. SWS Core §7.2 «Error handling» SWS Core §7.2.5.5 «Future and Promise»

Поведение при ошибке

GetResult() блокирует выполнение, пока не будут доступны значение или ошибка, и возвращает содержимое Shared State как Result<T,E>; ошибка, установленная через SetError(), тем самым остаётся в пути результата. Если Shared State был оставлен соответствующим Promise, GetResult() возвращает вместо этого FutureErrc::kBrokenPromise. Напротив, get() передаёт лежащую в Shared State ошибку как Exception; при недействительном Future там содержится kNoState. [SWS_CORE_00336] [SWS_CORE_00326] [SWS_CORE_00400]

wait_for() ожидает максимум переданного времени, wait_until() максимум до крайнего срока. Оба возвращают FutureStatus; kTimeout означает лишь то, что Shared State не был готов в соответствующий срок. Поэтому тайм-аут следует отличать от ошибки, передаваемой в результате. [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00361]

Ошибка читается как Result из Shared State; Альтернативное поле показывает ошибку, вызванную отказом от Promise и отдельного тайм-аута ожидания. Источники: [SWS_CORE_00336] [SWS_CORE_00329] [SWS_CORE_00330].

then() дает своему продолжению именно тот Result, который GetResult() мог бы обеспечить для этого Future; таким образом, продолжение может оценить ошибку и передать ее как Result или как продолжение Future. После then() исходный Future недействителен. Исключение, выходящее из продолжения, считается нарушением; Чтобы передать ошибки, их следует перевести в ошибку. [SWS_CORE_00337] [SWS_CORE_00331]

Состояния future_already_retrieved и promise_already_satisfied, названные в API-контрактах, присутствуют в R25-11 как описания Violation. Для доступа к недопустимому Future также определена Violation; только get() задаёт для этого FutureException с kNoState. [SWS_CORE_13013] [SWS_CORE_13014] [SWS_CORE_13015] [SWS_CORE_00326]
