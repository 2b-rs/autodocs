Контекст

Класс ara::core::Future представляет собой читающий конец асинхронной операции в рамках AUTOSAR Adaptive Platform. Он реализует известную из стандарта C++ концепцию std::future в соответствии с ISO/IEC 14882:2017. Шаблон класса определен как template <typename T, typename E = ErrorCode> class Future final. При этом спецификация явно требует, чтобы параметризация с E != ara::core::ErrorCode приводила к ошибке компиляции.

В модели асинхронной обработки ara::core::Future связан со следующими участниками:

  • Асинхронный поставщик (Promise): Соответствующий экземпляр ara::core::Promise управляет тем же Shared State и заполняет его через SetResult или SetError результирующим значением или ошибкой ([SWS_CORE_00336], [SWS_CORE_00326]).
  • Потребитель (приложение): Потребляющий поток опрашивает статус доступности, синхронно блокируется в ожидании результата или регистрирует асинхронные функции продолжения.
  • Контекст выполнения (Executor): При связывании в цепочку через then() опционально может быть указан контекст выполнения ExecutorT, в котором вызывается переданное продолжение ([SWS_CORE_00337]).

Жизненный цикл

Экземпляры ara::core::Future подчиняются строгой модели владения с перемещением (Move). Как конструктор копирования ([SWS_CORE_00334]), так и оператор присваивания копированием ([SWS_CORE_00335]) удалены (=delete). Передача Shared State возможна исключительно с помощью перемещающего конструирования ([SWS_CORE_00323]) или перемещающего присваивания ([SWS_CORE_00325]). Конструктор по умолчанию создает пустой экземпляр аналогично std::future ([SWS_CORE_00322]); интерпретация: такой сконструированный по умолчанию объект изначально не имеет Shared State и, вероятно, обычно отображает активную операцию только после перемещающего присваивания.

Экземпляр проходит следующие фазы состояния:

  • Недействителен (valid() == false): Объект не имеет Shared State ([SWS_CORE_00327]). Это относится к экземплярам, сконструированным по умолчанию, оставленным экземплярам после перемещения, а также объектам непосредственно после потребления через GetResult() ([SWS_CORE_00336]), get() ([SWS_CORE_00326]) или then() ([SWS_CORE_00331]).
  • Действителен, ожидает (valid() == true && is_ready() == false): Shared State связан, однако асинхронное выполнение еще не завершено ([SWS_CORE_00332]).
  • Действителен, готов (valid() == true && is_ready() == true): Значение или ошибка сохранены в Shared State. В этом состоянии GetResult(), get(), а также функции ожидания гарантированно больше не блокируют ([SWS_CORE_00332]).

Деструктор ~Future() освобождает Shared State ([SWS_CORE_00333]). При наличии зарегистрированных продолжений через then() деструктор возвращенного объекта Future блокируется до тех пор, пока выполняемое в данный момент продолжение (continuation) не завершится полностью ([SWS_CORE_00331], [SWS_CORE_00337]).

Что касается потокобезопасности, методы valid() ([SWS_CORE_00327]) и is_ready() ([SWS_CORE_00332]) специфицированы как потокобезопасные. Все остальные вызовы, в частности запросы значений и функции ожидания, не являются потокобезопасными.

Диаграмма состояний: жизненный цикл и переходы состояний экземпляра Future. Источники: [SWS_CORE_00327], [SWS_CORE_00332], [SWS_CORE_00336], [SWS_CORE_00333]

Путь использования

Типичный процесс подразделяется на синхронизацию и извлечение значения:

  1. Проверка статуса и синхронизация: С помощью is_ready() можно без блокировки проверить, готов ли результат ([SWS_CORE_00332]). Для синхронного ожидания доступен wait() ([SWS_CORE_00328]). Ограниченное по времени ожидание осуществляется через wait_for() ([SWS_CORE_00329]) с длительностью времени или через wait_until() ([SWS_CORE_00330]) с абсолютным моментом времени, каждый из которых возвращает FutureStatus.
  2. Запрос результата: Специфический для AUTOSAR метод GetResult() ([SWS_CORE_00336]) блокируется до завершения, не выбрасывает исключений и возвращает ara::core::Result<T, E>. В качестве альтернативы стандартная функция get() ([SWS_CORE_00326]) напрямую возвращает значение T или выбрасывает исключение в случае ошибки; при отключенных исключениях C++ она не участвует в разрешении перегрузки. Оба метода инвалидируют объект Future ([SWS_CORE_00336], [SWS_CORE_00326]).
  3. Реактивное связывание в цепочку: Через then() ([SWS_CORE_00331]) или then() с Executor ([SWS_CORE_00337]) может быть зарегистрировано продолжение, принимающее Result<T, E> как rvalue. Возвращаемый тип выполняет автоматическое развертывание (unwrapping) Future или Result в случае вложенных возвратов. Исходный объект Future при этом сразу становится недействительным.

Диаграмма последовательности: процесс асинхронного предоставления, проверки статуса и получения значения. Источники: [SWS_CORE_00332], [SWS_CORE_00336]

Сценарии ошибок

Спецификация определяет конкретные состояния ошибок и нарушения времени выполнения (Violations):

  • Вызов на недействительном Future (valid() == false): Вызов GetResult() ([SWS_CORE_00336]), is_ready() ([SWS_CORE_00332]), wait() ([SWS_CORE_00328]), wait_for() ([SWS_CORE_00329]), wait_until() ([SWS_CORE_00330]) или then() ([SWS_CORE_00331], [SWS_CORE_00337]) на недействительном Future приводит к нарушению времени выполнения FutureInvalidViolation. В случае get() ([SWS_CORE_00326]) вместо этого выбрасывается FutureException с кодом ошибки kNoState.
  • Покинутый Shared State (Broken Promise): Если разделяемое состояние уничтожается или покидается соответствующим Promise до того, как был установлен результат, GetResult() возвращает результат с кодом ошибки FutureErrc::kBrokenPromise ([SWS_CORE_00336]). При вызове get() ([SWS_CORE_00326]) инициируется связанное исключение.
  • Исключение в продолжении: Если продолжение, зарегистрированное в then(), выбрасывает исключение, не реализующее Violation, инициируется нарушение FutureContinuationHasThrownViolation ([SWS_CORE_00331], [SWS_CORE_00337]). Пользователи должны перехватывать информацию об исключениях и возвращать ее как ошибку через Result или Future.
