Контекст

Класс ara::tsync::SynchronizedTimeBaseProvider предоставляет доступ к синхронизированной базе времени, которая адресуется через идентификатор экземпляра (ara::core::InstanceSpecifier) ([SWS_TS_01101]). В рамках архитектуры AUTOSAR Adaptive он служит специализированным интерфейсом для приложений-поставщиков времени (Time Provider Applications). Его основная ответственность включает установку и обновление моментов времени для коммуникационной шины ([SWS_TS_01107], [SWS_TS_01108]), подстройку скорости хода часов ([SWS_TS_01110]), управление пользовательскими данными приложения ([SWS_TS_01112]), а также прием данных валидации ([SWS_TS_01114]).

Во взаимодействии участвуют как минимум три стороны: приложение-поставщик, экземпляр класса поставщика и Time Sync Daemon, который управляет соединением и координирует физическую передачу по шине ([SWS_TS_01107]).

Контекстная диаграмма: участники взаимодействия SynchronizedTimeBaseProvider при предоставлении времени. Источники: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01108].

Жизненный цикл и параллелизм

Создание выполняется явно через конструктор с использованием ara::core::InstanceSpecifier ([SWS_TS_01101]). При этом связанный PortPrototype обязательно должен быть типизирован с помощью SynchronizedTimeBaseProviderInterface; в противном случае имеет место PortInterfaceMappingViolation ([SWS_TS_01101]).

Что касается отношений владения, класс реализует эксклюзивную семантику перемещения (Move-Only):

  • Конструктор копирования ([SWS_TS_01104]) и оператор присваивания копированием ([SWS_TS_01105]) удалены (=delete), что исключает дублирование интерфейса доступа.
  • Конструктор перемещения ([SWS_TS_01102]) и оператор присваивания перемещением ([SWS_TS_01103]) доступны и защищены с помощью noexcept.
  • Уничтожение выполняется через деструктор ([SWS_TS_01106]).

С точки зрения потокобезопасности интерфейс строго разделяет операции запроса и операции модификации:

  • Конструктор ([SWS_TS_01101]) и методы чтения GetCurrentTime ([SWS_TS_01109]), GetRateDeviation ([SWS_TS_01111]), а также GetUserData ([SWS_TS_01113]) потокобезопасны (thread-safe).
  • Операции, изменяющие состояние, такие как SetTime ([SWS_TS_01107]), UpdateTime ([SWS_TS_01108]), SetRateCorrection ([SWS_TS_01110]), SetUserData ([SWS_TS_01112]), RegisterTimeValidationNotification ([SWS_TS_01114]), UnregisterTimeValidationNotification ([SWS_TS_01115]), а также операции перемещения и деструктор ([SWS_TS_01106]), классифицируются как непотокобезопасные (non_threadsafe) и требуют внешней синхронизации.

Путь использования

Типичный сценарий использования для предоставления синхронизированной информации о времени выглядит следующим образом:

  1. Создание экземпляра: приложение создает экземпляр поставщика с передачей сконфигурированного InstanceSpecifier ([SWS_TS_01101]).
  2. Регистрация уведомлений: если требуется валидация параметров синхронизации, приложение регистрирует объект уведомления через RegisterTimeValidationNotification ([SWS_TS_01114]). Одновременно может быть зарегистрирован не более чем один нотификатор; повторные вызовы перезаписывают существующую регистрацию ([SWS_TS_01114]).
  3. Обновление времени: для передачи на выбор доступны два механизма:
    • SetTime: обновляет время и незамедлительно инициирует передачу по шине ([SWS_TS_01107]).
    • UpdateTime: обновляет значение времени только локально; фактическая передача по шине выполняется циклически в следующем интервале отправки ([SWS_TS_01108]).
  4. Коррекция и статус: при необходимости скорость хода часов можно скорректировать с помощью SetRateCorrection ([SWS_TS_01110]). Дополнительно можно считать статусные значения, такие как текущее время ([SWS_TS_01109]) или отклонение скорости хода ([SWS_TS_01111]).
  5. Отмена регистрации: перед удалением экземпляра, вероятно, целесообразно выполнить явную отмену регистрации нотификатора через UnregisterTimeValidationNotification ([SWS_TS_01115]).

Диаграмма последовательности: типичная последовательность вызовов для предоставления времени и регистрации уведомлений. Источники: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01114], [SWS_TS_01115].

Сценарии ошибок

Модифицирующие методы сообщают об ошибках через возвращаемые объекты типа ara::core::Result<void>. Неудачные вызовы не имеют семантики отката (no_rollback_semantics):

<h4>Контекст</h4>
<p>Класс <code>ara::tsync::SynchronizedTimeBaseProvider</code> предоставляет доступ к синхронизированной базе времени, которая адресуется через идентификатор экземпляра (<code>ara::core::InstanceSpecifier</code>) (<a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>). В рамках архитектуры AUTOSAR Adaptive он служит специализированным интерфейсом для приложений-поставщиков времени (Time Provider Applications). Его основная ответственность включает установку и обновление моментов времени для коммуникационной шины (<a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>, <a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a>), подстройку скорости хода часов (<a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>), управление пользовательскими данными приложения (<a class="spec-record-ref" data-req="SWS_TS_01112" href="../spec/record.html?id=SWS_TS_01112">[SWS_TS_01112]</a>), а также прием данных валидации (<a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>).</p>
<p>Во взаимодействии участвуют как минимум три стороны: приложение-поставщик, экземпляр класса поставщика и Time Sync Daemon, который управляет соединением и координирует физическую передачу по шине (<a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>).</p>

<h4>Жизненный цикл и параллелизм</h4>
<p>Создание выполняется явно через конструктор с использованием <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>). При этом связанный <code>PortPrototype</code> обязательно должен быть типизирован с помощью <code>SynchronizedTimeBaseProviderInterface</code>; в противном случае имеет место <code>PortInterfaceMappingViolation</code> (<a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>).</p>
<p>Что касается отношений владения, класс реализует эксклюзивную семантику перемещения (Move-Only):</p>
<ul>
<li>Конструктор копирования (<a class="spec-record-ref" data-req="SWS_TS_01104" href="../spec/record.html?id=SWS_TS_01104">[SWS_TS_01104]</a>) и оператор присваивания копированием (<a class="spec-record-ref" data-req="SWS_TS_01105" href="../spec/record.html?id=SWS_TS_01105">[SWS_TS_01105]</a>) удалены (<code>=delete</code>), что исключает дублирование интерфейса доступа.</li>
<li>Конструктор перемещения (<a class="spec-record-ref" data-req="SWS_TS_01102" href="../spec/record.html?id=SWS_TS_01102">[SWS_TS_01102]</a>) и оператор присваивания перемещением (<a class="spec-record-ref" data-req="SWS_TS_01103" href="../spec/record.html?id=SWS_TS_01103">[SWS_TS_01103]</a>) доступны и защищены с помощью <code>noexcept</code>.</li>
<li>Уничтожение выполняется через деструктор (<a class="spec-record-ref" data-req="SWS_TS_01106" href="../spec/record.html?id=SWS_TS_01106">[SWS_TS_01106]</a>).</li>
</ul>
<p>С точки зрения потокобезопасности интерфейс строго разделяет операции запроса и операции модификации:</p>
<ul>
<li>Конструктор (<a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>) и методы чтения <code>GetCurrentTime</code> (<a class="spec-record-ref" data-req="SWS_TS_01109" href="../spec/record.html?id=SWS_TS_01109">[SWS_TS_01109]</a>), <code>GetRateDeviation</code> (<a class="spec-record-ref" data-req="SWS_TS_01111" href="../spec/record.html?id=SWS_TS_01111">[SWS_TS_01111]</a>), а также <code>GetUserData</code> (<a class="spec-record-ref" data-req="SWS_TS_01113" href="../spec/record.html?id=SWS_TS_01113">[SWS_TS_01113]</a>) потокобезопасны (<code>thread-safe</code>).</li>
<li>Операции, изменяющие состояние, такие как <code>SetTime</code> (<a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>), <code>UpdateTime</code> (<a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a>), <code>SetRateCorrection</code> (<a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>), <code>SetUserData</code> (<a class="spec-record-ref" data-req="SWS_TS_01112" href="../spec/record.html?id=SWS_TS_01112">[SWS_TS_01112]</a>), <code>RegisterTimeValidationNotification</code> (<a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>), <code>UnregisterTimeValidationNotification</code> (<a class="spec-record-ref" data-req="SWS_TS_01115" href="../spec/record.html?id=SWS_TS_01115">[SWS_TS_01115]</a>), а также операции перемещения и деструктор (<a class="spec-record-ref" data-req="SWS_TS_01106" href="../spec/record.html?id=SWS_TS_01106">[SWS_TS_01106]</a>), классифицируются как непотокобезопасные (<code>non_threadsafe</code>) и требуют внешней синхронизации.</li>
</ul>

<h4>Путь использования</h4>
<p>Типичный сценарий использования для предоставления синхронизированной информации о времени выглядит следующим образом:</p>
<ol>
<li><strong>Создание экземпляра:</strong> приложение создает экземпляр поставщика с передачей сконфигурированного <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>).</li>
<li><strong>Регистрация уведомлений:</strong> если требуется валидация параметров синхронизации, приложение регистрирует объект уведомления через <code>RegisterTimeValidationNotification</code> (<a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>). Одновременно может быть зарегистрирован не более чем один нотификатор; повторные вызовы перезаписывают существующую регистрацию (<a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>).</li>
<li><strong>Обновление времени:</strong> для передачи на выбор доступны два механизма:
<ul>
<li><code>SetTime</code>: обновляет время и незамедлительно инициирует передачу по шине (<a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>).</li>
<li><code>UpdateTime</code>: обновляет значение времени только локально; фактическая передача по шине выполняется циклически в следующем интервале отправки (<a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a>).</li>
</ul>
</li>
<li><strong>Коррекция и статус:</strong> при необходимости скорость хода часов можно скорректировать с помощью <code>SetRateCorrection</code> (<a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>). Дополнительно можно считать статусные значения, такие как текущее время (<a class="spec-record-ref" data-req="SWS_TS_01109" href="../spec/record.html?id=SWS_TS_01109">[SWS_TS_01109]</a>) или отклонение скорости хода (<a class="spec-record-ref" data-req="SWS_TS_01111" href="../spec/record.html?id=SWS_TS_01111">[SWS_TS_01111]</a>).</li>
<li><strong>Отмена регистрации:</strong> перед удалением экземпляра, вероятно, целесообразно выполнить явную отмену регистрации нотификатора через <code>UnregisterTimeValidationNotification</code> (<a class="spec-record-ref" data-req="SWS_TS_01115" href="../spec/record.html?id=SWS_TS_01115">[SWS_TS_01115]</a>).</li>
</ol>
