Служит приложениям-поставщикам времени для установки, коррекции и валидации синхронизированной шкалы времени на шине.

Перемещаемый класс (move-only) ara::tsync::SynchronizedTimeBaseProvider служит приложениям-поставщикам времени для ввода, коррекции скорости и валидации синхронизированной шкалы времени [SWS_TS_01101] [SWS_TS_01110]. Обновления могут либо вызывать немедленную передачу по шине, либо планироваться как локальное обновление для следующего цикла передачи [SWS_TS_01107] [SWS_TS_01108]. В то время как операции чтения потокобезопасны, все модифицирующие методы, а также регистрация уведомителя требуют потоко-локального или синхронизированного вызова [SWS_TS_01109] [SWS_TS_01114].

Контекст

Класс ara::tsync::SynchronizedTimeBaseProvider предоставляет приложениям-поставщикам времени активный управляющий доступ к синхронизированной шкале времени, смоделированной через ara::core::InstanceSpecifier [SWS_TS_01101]. В AUTOSAR Adaptive данный экземпляр выступает в качестве интерфейса между предоставляющей логикой приложения, локальным демоном Time-Sync и подключенными коммуникационными шинами. Через этот компонент приложение подает новые значения времени и пользовательские полезные данные в систему, компенсирует дрейфы с помощью коррекции скорости и регистрирует параметры валидации [SWS_TS_01107] [SWS_TS_01110] [SWS_TS_01114].

Контекстная диаграмма: интеграция SynchronizedTimeBaseProvider между приложением-поставщиком, валидацией и передачей по шине. Источники: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01114]

Жизненный цикл

Инстанцирование выполняется явно через ara::core::InstanceSpecifier, который должен указывать на PortPrototype, типизированный через SynchronizedTimeBaseProviderInterface [SWS_TS_01101]. Конструктор объявлен безопасным к исключениям и потокобезопасным [SWS_TS_01101]. Объект класса является исключительно перемещаемым (move-only): конструктор копирования и оператор присваивания копированием явно удалены [SWS_TS_01104] [SWS_TS_01105], тогда как перемещающее конструирование и присваивание перемещением поддерживаются [SWS_TS_01102] [SWS_TS_01103].

В отношении параллелизма действует строгое разделение: операции только для чтения состояния, такие как GetCurrentTime(), GetRateDeviation() и GetUserData(), являются потокобезопасными и могут выполняться конкурентно [SWS_TS_01109] [SWS_TS_01111] [SWS_TS_01113]. Все модифицирующие операции, регистрация уведомлений, а также уничтожение объекта через деструктор, напротив, не являются потокобезопасными и требуют синхронизации на стороне приложения [SWS_TS_01106] [SWS_TS_01107] [SWS_TS_01114].

Путь использования

Типичное применение делится на регистрацию для получения обратной связи по валидации, а также циклическую или управляемую событиями передачу времени:

  • Регистрация валидации: при необходимости приложение-поставщик регистрирует через RegisterTimeValidationNotification() объект уведомления для приема вновь записанных блоков данных синхронизации времени [SWS_TS_01114]. Активным может быть максимум один получатель уведомлений; повторная регистрация перезаписывает существующую [SWS_TS_01114], тогда как UnregisterTimeValidationNotification() разрывает привязку [SWS_TS_01115].
  • Установка значения времени: при необходимости немедленного распределения приложение вызывает SetTime(). Это устанавливает локальное значение времени и напрямую инициирует передачу по шине [SWS_TS_01107]. Если же передача по шине должна состояться только в следующем регулярном цикле, используется UpdateTime(), благодаря чему часы сначала обновляются только локально [SWS_TS_01108].
  • Коррекция и полезные данные: с помощью SetRateCorrection() дрейф локальных часов можно скорректировать коэффициентом коррекции (значения меньше 1.0 замедляют часы, значения больше 1.0 ускоряют их) [SWS_TS_01110]. Дополнительные пользовательские данные шкалы времени можно обновить через SetUserData() [SWS_TS_01112].

Диаграмма последовательности: процесс регистрации уведомителя и обновления времени с альтернативными путями передачи по шине. Источники: [SWS_TS_01107], [SWS_TS_01108], [SWS_TS_01114]

Сценарии ошибок

Методы с возвращаемым значением ara::core::Result<void> сигнализируют о сбоях через коды ошибок типа TsyncErrc без семантики отката:

  • TsyncErrc::kInvalidUserDataSize: возникает при SetTime(), UpdateTime() и SetUserData(), если переданные UserData превышают максимальную длину UserData::kMaxUserDataSize (в настоящее время 3 байта) [SWS_TS_01107] [SWS_TS_01108] [SWS_TS_01112].
  • TsyncErrc::kDaemonConnectionLost: возникает при SetTime(), если IPC-соединение с демоном Time-Sync прервано в момент вызова [SWS_TS_01107].
  • TsyncErrc::kLimitsExceeded: возвращается из SetRateCorrection(), если запрошенный коэффициент коррекции скорости находится вне допустимого диапазона значений [SWS_TS_01110].
  • TsyncErrc::kFunctionNotSupported: сообщается из SetRateCorrection(), если базовая платформа или шкала времени не поддерживает коррекцию скорости [SWS_TS_01110].

              Использование
              
  
              Метод RegisterTimeValidationNotification является частью класса ara::tsync::SynchronizedTimeBaseProvider и подключается через заголовочный файл #include "ara/tsync/synchronized_time_base_provider.h" [SWS_TS_01114]. Он служит приложениям Time Provider для приема параметров синхронизации времени [SWS_TS_01114]. Через параметр timeBaseValidationNotification передается ссылка на объект уведомлений типа ProviderTimeBaseValidationNotification, который информируется, как только становится доступным новый блок данных для базиса времени [SWS_TS_01114]. Метод не возвращает значения (void) [SWS_TS_01114].
              

  
              Обработка ошибок
              
  
              Метод объявлен как noexcept и обладает свойством exception safe [SWS_TS_01114]. Он не генерирует исключений и не возвращает кодов ошибок [SWS_TS_01114].
              

  
              Параллелизм и ограничения
              
  
              При использовании необходимо соблюдать следующие ограничения:
              
  
                
    
              • Ограничение регистрации: может быть зарегистрирован только один нотификатор; каждая последующая регистрация перезаписывает текущую регистрацию [SWS_TS_01114].
                • 
    
              • Потокобезопасность: функция специфицирована как non_threadsafe [SWS_TS_01114]. Вызовы на одном и том же экземпляре при параллельном доступе должны синхронизироваться со стороны приложения.
                • 
  
              

  
              Взаимодействие
              
  
              В то время как эта функция реализует регистрацию на стороне источника времени (Provider) [SWS_TS_01114], класс ara::tsync::SynchronizedTimeBaseConsumer с RegisterTimeValidationNotification и типом ConsumerTimeBaseValidationNotification представляет собой функциональный аналог для потребителей времени (Consumer) [SWS_TS_01016].
              

              

              Это указание по использованию сгенерировано автоматически на основе спецификации AUTOSAR.
