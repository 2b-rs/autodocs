Контекст

Класс ara::crypto::x509::CertificateValidationCtx предоставляет контекст валидации для сертификатов X.509 и путей сертификации в соответствии с RFC 5280 ([SWS_CRYPT_50122], [SWS_CRYPT_50123]). В рамках модуля crypto Adaptive Platform он объединяет конфигурацию, доверенные корневые сертификаты, промежуточные сертификаты и правила проверки, а также выполняет криптографическую валидацию пути.

В процессах валидации в основном участвуют следующие компоненты и типы данных:

  • Приложение: настраивает контекст с помощью параметров валидации ([SWS_CRYPT_50120]), при необходимости задает опорное время ([SWS_CRYPT_50121]), регистрирует якоря доверия и запускает проверку.
  • Сертификаты (Certificate): формируют основу доверия и объекты проверки. Различают доверенные сертификаты ([SWS_CRYPT_50117]), недоверенные промежуточные сертификаты для построения пути ([SWS_CRYPT_50118]), а также целевые сертификаты ([SWS_CRYPT_50122]) или цепочки сертификатов ([SWS_CRYPT_50123]).
  • Ответы OCSP (OcspResponse): служат для подтверждения статуса отзыва сертификатов и передаются в контекст валидации для учета ([SWS_CRYPT_50124]).
  • Результат валидации (CertificateValidationResult): инкапсулирует подробный результат процесса валидации пути по RFC 5280 после выполнения проверки ([SWS_CRYPT_50122], [SWS_CRYPT_50123]).

Контекстная диаграмма: партнеры CertificateValidationCtx по взаимодействию при проверке сертификатов и путей. Источники: [SWS_CRYPT_50117], [SWS_CRYPT_50118], [SWS_CRYPT_50122], [SWS_CRYPT_50123], [SWS_CRYPT_50124]

Жизненный цикл

Для владения экземплярами контекста и их передачи интерфейс предоставляет псевдоним типа Sptr как std::shared_ptr<CertificateValidationCtx> ([SWS_CRYPT_50116]). Поскольку класс определяет чисто виртуальные методы, инстанцирование конкретной реализации, вероятно, происходит через вышестоящий класс фабрики или провайдера криптографического стека.

После создания контекст находится в конфигурируемом состоянии. Приложение поэтапно регистрирует параметры ([SWS_CRYPT_50120]), сертификаты ([SWS_CRYPT_50117], [SWS_CRYPT_50118]), ответы OCSP ([SWS_CRYPT_50124]) или OID игнорируемых критических расширений ([SWS_CRYPT_50119]). Сброс отдельных регистраций не предусмотрен; для различных доменов валидации создаются отдельные контексты.

Что касается параллелизма и отказоустойчивости, все виртуальные функции-члены интерфейса явно специфицированы как потокобезопасные (thread-safe) и безопасные относительно исключений (exception safe) (от [SWS_CRYPT_50117] до [SWS_CRYPT_50124]). Таким образом, экземпляры могут параллельно использоваться несколькими потоками.

Путь использования

Типичное использование CertificateValidationCtx следует фиксированной последовательности: настройка, наполнение и выполнение:

  1. Определение конфигурации: с помощью SetValidationOptions передается битовая маска, определяющая выполняемые проверки ([SWS_CRYPT_50120]). Опционально через SetCurrentTime можно выбрать явный опорный момент времени для проверки срока действия ([SWS_CRYPT_50121]); если эта функция не вызывается, контекст использует системное время. Если требуется допускать критические расширения, валидированные на уровне приложения, их OID сохраняются через IgnoreCriticalExtension ([SWS_CRYPT_50119]).
  2. Регистрация сертификатов и данных о статусе: через AddTrustedCertificate добавляются определяющие якоря доверия (Root-CA) ([SWS_CRYPT_50117]). Для облегчения построения пути через AddUntrustedCertificate могут вводиться промежуточные сертификаты ([SWS_CRYPT_50118]). Если должна учитываться информация об отзыве, ответы OCSP добавляются через AddOcspResponse ([SWS_CRYPT_50124]).
  3. Выполнение валидации: проверка осуществляется одним из двух методов:
    • ValidateCertificate проверяет отдельный конечный сертификат (End-Entity) и строит путь с помощью сохраненных в контексте доверенных и недоверенных сертификатов ([SWS_CRYPT_50122]).
    • ValidateCertificateChain валидирует имеющуюся цепочку как ara::core::Span ([SWS_CRYPT_50123]). При этом элемент 0 представляет собой листовой сертификат, а каждый последующий элемент — соответствующего издателя. В этом режиме сертификаты, ранее сохраненные через AddUntrustedCertificate, игнорируются; валидация проверяет переданную цепочку исключительно относительно якорей доверия, установленных через AddTrustedCertificate.
  4. Анализ результата: в случае успеха обе функции валидации возвращают CertificateValidationResult::Sptrc для анализа подробных результатов ([SWS_CRYPT_50122], [SWS_CRYPT_50123]).

Диаграмма последовательности: типичная последовательность вызовов для настройки, регистрации сертификатов и выполнения валидации. Источники: [SWS_CRYPT_50117], [SWS_CRYPT_50120], [SWS_CRYPT_50121], [SWS_CRYPT_50122], [SWS_CRYPT_50123], [SWS_CRYPT_50124]

Сценарии ошибок

Все операции возвращают ошибки через ara::core::Result. Стандартизированные коды ошибок и специфические предусловия включают:

  • Несовместимые аргументы (ara::crypto::CryptoErrc::kIncompatibleArguments): возникает в ValidateCertificate ([SWS_CRYPT_50122]) и ValidateCertificateChain ([SWS_CRYPT_50123]), если через AddOcspResponse ([SWS_CRYPT_50124]) был сохранен ответ OCSP, однако параметры, заданные через SetValidationOptions ([SWS_CRYPT_50120]), не определяют соответствующего поведения OCSP. Обе функции обладают семантикой отката.
  • Недопустимые параметры конфигурации (ara::crypto::CryptoErrc::kInvalidArgument): если SetValidationOptions ([SWS_CRYPT_50120]) вызывается с недопустимой битовой маской, вызов завершается сбоем с семантикой отката.
  • Ошибки валидации ответов OCSP: для AddOcspResponse ([SWS_CRYPT_50124]) издатель ответа OCSP должен быть либо предварительно сохранен в контексте как доверенный или недоверенный, либо подписан сертификатом с Extended-Key-Usage id-kp-OCSPSigning того же CA, либо передан через необязательный аргумент trustedOcspIssuerCertificate. Возвращаемый Result<CertificateValidationStatus> сигнализирует о kValid при успешном принятии или предоставляет конкретный статус валидации ответа OCSP.
  • Специфичные для реализации ошибки: при внутренних ошибках или системных ограничениях все методы могут возвращать специфичные для реализации коды ошибок в Result (от [SWS_CRYPT_50117] до [SWS_CRYPT_50124]).

Методы

AddOcspResponse функция

Validate and add an OCSP response to be used during certificate validation to the set of previously added OCSP responses. Multiple OCSP responses may be added to one context. In order to validate the OCSP response, the issuer of the OCSP response must have been a) set as a trusted or untrusted certificate in this context previously, or b) the CRL must have been signed by another certificate that has the id-kp-OCSPSigning extended key usage set issued by the same CA, or c) the CRL must be signed by a trusted CA passed to this function using the optional trustedOcspIssuerCertificate parameter.

virtual ara::core::Result< CertificateValidationStatus > AddOcsp Response (OcspResponse::Sptrc ocspResponse, ara::core::Optional< Certificate::Sptrc > trustedOcspIssuerCertificate) noexcept=0;

Add a trusted certificates to be used during certificate path validation to the set of previously added trusted certificates.

virtual ara::core::Result< void > AddTrustedCertificate ( Certificate::Sptrc trustedCertificate) noexcept=0;
AddUntrustedCertificate функция

Add an untrusted certificate to be used during certificate path validation to the set of previously added untrusted certificates.

virtual ara::core::Result< void > AddUntrustedCertificate ( Certificate::Sptrc untrustedCertificate) noexcept=0;
IgnoreCriticalExtension функция

Configure the context to ignore an extension during validation of certificates and OCSP responses, even if the extension is marked as critical and the validation context does not support the extension. It is the responsibility of the application to validate such extensions. Multiple invocations of this function lead to ignoring all passed extensions. This function has no effect if the kIgnoreUnknownCriticalExtensions validation option is set.

virtual ara::core::Result< void > IgnoreCriticalExtension (ara::core::StringView ignoredExtensionOid) noexcept=0;
SetCurrentTime функция

Set the reference time point to be used as the current time during certificate validation. If this function is not called, the system time will be used during certificate validation.

virtual ara::core::Result< void > SetCurrentTime (Timestamp current Time) noexcept=0;

Set validation options to be used during certificate validation.

ValidateCertificate функция

Performs certificate path validation according to RFC 5280 and according to the previous configuration of the context.

virtual ara::core::Result< CertificateValidationResult::Sptrc > ValidateCertificate (Certificate::Sptrc certificate) noexcept=0;
ValidateCertificateChain функция

Performs certificate path validation according to RFC 5280 and according to the previous configuration of the context. The function ignores any certificates added to the context via Add UntrustedCertificate. Instead, the function validates the provided chain against any trusted certificate that has been set using the function AddTrustedCertificate.

virtual ara::core::Result< CertificateValidationResult::Sptrc > ValidateCertificateChain (const ara::core::Span< Certificate::Sptrc > certificateChain) noexcept=0;
