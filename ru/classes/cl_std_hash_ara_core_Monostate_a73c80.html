Позволяет вычислять хэш-значение для пустых состояний для использования в ассоциативных хэш-контейнерах.

Специализация std::hash<ara::core::Monostate> предоставляет соответствующий стандарту функциональный объект для вычисления хэш-значений для ara::core::Monostate [SWS_CORE_01671]. Через оператор вызова operator() структура принимает константную ссылку на объект Monostate и возвращает соответствующее хэш-значение в виде size_t [SWS_CORE_01671]. Интерпретация: поскольку объект Monostate не имеет внутреннего состояния, для каждого экземпляра, вероятно, вычисляется единое, детерминированное значение. В качестве центрального граничного условия операция специфицирована как noexcept, а также как безопасная относительно исключений и полностью исключает ошибки времени выполнения.

Контекст

Специализация шаблона std::hash<ara::core::Monostate> представляет собой функциональное связующее звено между базовым типом AUTOSAR Adaptive ara::core::Monostate и стандартной инфраструктурой хэширования [SWS_CORE_01671]. Внутри модуля core тип ara::core::Monostate служит для представления пустого состояния, например, в качестве альтернативного типа в вариантах. Чтобы обеспечить возможность беспрепятственного использования подобных типов в ассоциативных хэш-контейнерах или обобщенных алгоритмах хэширования, спецификация определяет явную специализацию стандартного класса функтора std::hash [SWS_CORE_01671].

Структура предоставляется через заголовочный файл ara/core/variant.h [SWS_CORE_01671]. В качестве функционального объекта хэширования специализация взаимодействует преимущественно с обобщенными реализациями контейнеров, такими как хэш-таблицы, а также с экземплярами ara::core::Monostate. Благодаря соблюдению интерфейсных соглашений стандартной библиотеки C++ она функционирует как адаптер, обеспечивающий единообразный доступ к хэш-значениям даже для компонентов без состояния [SWS_CORE_01671].

Жизненный цикл

Структура std::hash<ara::core::Monostate> спроектирована как регулярный функциональный объект [SWS_CORE_01671]. Поскольку ей не требуются специфичные для экземпляра данные для вычисления хэш-значения, она не имеет собственного изменяемого состояния. Создание и уничтожение экземпляров специализации не требует специальных мер и не влечет за собой затрат на динамическую память.

С точки зрения параллелизма и отношений владения функциональный объект полностью не имеет состояния. Оператор вызова функции operator() объявлен как const [SWS_CORE_01671]. Это означает, что один и тот же экземпляр может безопасно и конкурентно использоваться параллельно несколькими контекстами выполнения или потоками. Исключительные права владения переданными объектами Monostate отсутствуют, так как они считываются исключительно по константной ссылке [SWS_CORE_01671].

Путь использования

Типичный путь использования начинается с подключения заголовочного файла ara/core/variant.h [SWS_CORE_01671] в соответствующей единице трансляции. Как только заголовочный файл включен, специализация автоматически становится доступной в пространстве имен std и при необходимости разрешается структурами данных на основе хэширования.

Фактическое выполнение происходит через перегруженный оператор вызова функции operator(), принимающий константную ссылку на объект ara::core::Monostate [SWS_CORE_01671]: size_t operator() (ara::core::Monostate const &v) const noexcept; [SWS_CORE_01671]. В качестве результата вызов возвращает числовое хэш-значение типа size_t [SWS_CORE_01671]. Интерпретация: поскольку ara::core::Monostate по определению не несет изменяемого состояния, функция, вероятно, вычисляет для всех переданных экземпляров идентичное, детерминированное хэш-значение. На практике этот вызов чаще всего происходит прозрачно в рамках операций поиска или вставки вышестоящих структур данных.

Сценарии ошибок

Спецификация устанавливает для метода operator() строгое поведение в отношении исключений и надежности: оператор объявлен со спецификатором noexcept и явно классифицирован как безопасный относительно исключений (exception safe) [SWS_CORE_01671]. Это гарантирует, что во время процесса хэширования ни при каких обстоятельствах не возникнут исключения C++.

Специфические коды ошибок, возвращаемые значения для сигнализации об ошибках или предусловия, выходящие за рамки синтаксически корректной ссылки на объект, отсутствуют [SWS_CORE_01671]. Таким образом, вызов никогда не может завершиться ошибкой. Постусловием вызова всегда является успешное предоставление целочисленного хэш-значения типа size_t, поэтому вызывающим сторонам не требуется реализовывать резервные ветви или ветви обработки ошибок [SWS_CORE_01671].

Использование

Функция operator() специализации std::hash<ara::core::Monostate> синхронно вычисляет хэш-значение для переданного объекта ara::core::Monostate [SWS_CORE_01671]. Для доступа необходимо подключить заголовочный файл #include "ara/core/variant.h" [SWS_CORE_01671]. Вызов осуществляется через сигнатуру size_t operator() (ara::core::Monostate const &v) const noexcept, принимает константную ссылку на значение monostate и возвращает результат как size_t [SWS_CORE_01671].

Обработка ошибок и безопасность исключений

Операция явно объявлена как noexcept и классифицирована как безопасная относительно исключений (exception safe) [SWS_CORE_01671]. Специфические коды ошибок или сообщения DET/DEM не определены; вызов не завершается ошибкой и гарантирует отсутствие исключений.

Параллелизм и взаимодействие

Будучи функцией-членом const без побочных эффектов, вызов является реентерабельным и полностью безопасным для параллельного доступа из нескольких потоков. Поскольку ara::core::Monostate представляет собой пустой тип состояния, вычисленное хэш-значение, вероятно, будет одинаковым для всех экземпляров. Специализация, предположительно, служит для того, чтобы беспрепятственно поддерживать ara::core::Monostate или variant, содержащие этот тип, в качестве ключей в стандартных контейнерах на основе хэшей, таких как std::unordered_set.
