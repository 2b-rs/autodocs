Предоставляет управлению коммуникацией интерфейс для управления значениями свежести для SecOC, специфичного для изготовителя.

Класс служит интерфейсом, реализуемым OEM или производителем стека, для предоставления и управления значениями свежести для SecOC в управлении коммуникацией [SWS_CM_11287]. Он снабжает ara::com при отправке и приёме защищённых сообщений значениями свежести через GetTxFreshness() и GetRxFreshness() и принимает результат верификации через SetVerificationStatus() [SWS_CM_11274] [SWS_CM_11276]. При этом его жизненный цикл полностью управляется ara::com как синглтон [SWS_CM_11272].

Контекст

Класс apext::com::secoc::FVM определяет стандартизированный интерфейс для Freshness Value Management (FVM) в рамках управления коммуникацией в AUTOSAR Adaptive [SWS_CM_11287]. Он действует как точка расширения (интерфейс плагина), реализуемая OEM или производителем стека для предоставления специфичных для приложения значений свежести для защиты с точностью до сообщения AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM». К партнёрам по взаимодействию относятся управление коммуникацией (ara::com), модуль криптографической защиты SecOC, а также специфическая библиотека FVM производителя.

Контекстная диаграмма: встраивание интерфейса FVM между управлением коммуникацией и специфичной для производителя библиотекой значений свежести. Источники: [SWS_CM_11272], [SWS_CM_11287], AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM»

Жизненный цикл

Внутри управления коммуникацией существует ровно один единственный экземпляр этого класса AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM». Весь жизненный цикл реализации SecOC-FreshnessValueManager полностью управляется через ara::com [SWS_CM_11272]. Инициализация реализации FVM обязательно выполняется через вызов метода Initialize() [SWS_CM_11273] [SWS_CM_11290]. Все методы интерфейса объявлены как безопасные по отношению к исключениям (noexcept) [SWS_CM_11288]. Интерпретация: поскольку инстанцирование и управление жизненным циклом выполняются внутренне через ara::com, внутренняя синхронизация от параллельных вызовов со стороны нескольких каналов связи возлагается на конкретную реализацию плагина FVM.

Путь использования

В процессе работы управление коммуникацией различает отправку и приём защищённых сообщений:

  • Операция отправки: если сообщение сконфигурировано для передачи с SecOC и имеет freshnessValueId, управление коммуникацией вызывает GetTxFreshness() с ID значения свежести [SWS_CM_11274] [SWS_CM_11289]. При успешном возврате значение свежести в FVContainer привлекается для вычисления аутентификатора (MAC), которое происходит после вычислений по защите E2E [SWS_CM_11274].
  • Операция приема: если верификация входящих сообщений не обходится конфигурацией [SWS_CM_11372], SecOC перед E2E-проверкой GetRxFreshness() вызывает [SWS_CM_11276] [SWS_CM_11288]. При этом передаются SecOCFreshnessValueID, принятое усеченное значение свежести (SecOCTruncatedFreshnessValue), а также количество предыдущих попыток верификации (SecOCAuthVerifyAttempts) [SWS_CM_11288]. После сверки вычисленного аутентификатора управление связью сообщает результат через SetVerificationStatus() с указанием VerificationStatus обратно в FVM [SWS_CM_19999] [SWS_CM_11378].

Диаграмма последовательности: процесс верификации при приеме защищенного сообщения с запросом значения свежести и обратной связью по статусу. Источники: [SWS_CM_11276], [SWS_CM_11288], [SWS_CM_19999], AUTOSAR_AP_SWS_CommunicationManagement §8.1 «SecOC secure channel reception»

Сценарии ошибок

Ошибки сигнализируются через типы возвращаемого значения типа ara::core::Result:

  • Ошибка инициализации: в случае сбоя подготовки реализации FVM Initialize() возвращает код ошибки ComSecOcFvmErrc::kFVInitializeFailed [SWS_CM_11290].
  • Недоступное значение свежести: если значения свежести для отправки или приема временно не могут быть определены, GetTxFreshness() и GetRxFreshness() возвращают ошибку ComSecOcFvmErrc::kFVNotAvailable [SWS_CM_11288] [SWS_CM_11289].
  • Повторные попытки при отправке: если GetTxFreshness() возвращает восстановимую ошибку kFVNotAvailable или вычисление аутентификатора завершается неудачей, система инкрементирует Authentication Build Counter [SWS_CM_11275]. Защита сообщения повторяется способом, зависящим от производителя; если счетчик достигает сконфигурированного предела SecOCAuthenticationBuildAttempts, сообщение отбрасывается [SWS_CM_11275] AUTOSAR_AP_SWS_CommunicationManagement §8.1 «SecOC secure message build attempts».
  • Сообщения о статусе при сбоях верификации: через SetVerificationStatus() в FVM передаются специфические режимы ошибок, такие как kSecOcVerificationFailure, kSecOcFreshnessFailure или kSecOcAuthenticationBuildFailure [SWS_CM_19999] [SWS_CM_11378].

Данное руководство по классу основано на спецификации AUTOSAR Adaptive R25-11 и сформировано автоматически.

Функция-член apext::com::secoc::FVM::GetRxFreshness служит уровню SecOC для определения полного значения актуальности для принятых сообщений [SWS_CM_11288]. В качестве входных параметров функция ожидает идентификатор SecOCFreshnessValueID, усечённое значение актуальности, извлечённое из защищённого сообщения в FVContainer согласно [SWS_CM_11286], а также счётчик SecOCAuthVerifyAttempts [SWS_CM_11288]. Этот счётчик начинается со значения 0 при первой попытке верификации и инкрементируется при каждой последующей неудачной попытке для того же сообщения [SWS_CM_11288].

Метод специфицирован как noexcept и безопасный относительно исключений (AUTOSAR_AP_SWS_CommunicationManagement §C.1.2.2.1.1 «GetRxFreshness»). Благодаря прямому возврату ara::core::Result<FVContainer> без типа Future вызов, вероятно, обрабатывается синхронно с блокировкой. В случае успеха результат содержит полное значение актуальности для последующей верификации MAC аутентификатора [SWS_CM_11288]. Если значение не может быть предоставлено, функция возвращает исправимый код ошибки ComSecOcFvmErrc::kFVNotAvailable [SWS_CM_11288].

Определение значения актуальности является неотъемлемой частью пути приёма SecOC: аутентификация сообщений принципиально выполняется до последующих проверок E2E [SWS_CM_11276] и связана со счётчиком попыток аутентификации [SWS_CM_11277]. Специфические требования к реентерабельности или потокобезопасности в стандарте не определены; поведение при параллельных вызовах, следовательно, вероятно, зависит от конкретной реализации Freshness Value Manager.

      Синхронная библиотечная функция apext::com::secoc::FVM::GetTxFreshness ([SWS_CM_11289]) служит для обработки SecOC при получении текущего значения актуальности при отправке защищённых сообщений через Communication Management ([SWS_CM_11274], AUTOSAR_AP_SWS_CommunicationManagement с. 224 «SecOC secure channel sending»).
      


      Использование и контекст вызова
      

      Вызов выполняется ara::com, если для соответствующего элемента сервисного интерфейса в конфигурации задана freshnessValueId ([SWS_CM_11274]):
      

        
  
      • Параметры: SecOCFreshnessValueID (тип std::uint16_t) идентифицирует запрашиваемое значение актуальности ([SWS_CM_11289]).
        • 
  
      • Возвращаемое значение: ara::core::Result<FVContainer> ([SWS_CM_11289]). В случае успеха оно содержит apext::com::secoc::FVContainer ([SWS_CM_11286]), значение актуальности которого используется для последующего вычисления аутентификатора или MAC ([SWS_CM_11274]).
        • 
  
      • Безопасность исключений: функция объявлена как noexcept ([SWS_CM_11289]).
        • 

      


      Обработка ошибок и граничные условия
      

      Если действительное значение актуальности не может быть предоставлено, функция возвращает ara::core::Result с кодом ошибки ComSecOcFvmErrc::kFVNotAvailable («Freshness Value not available») с семантикой отката ([SWS_CM_11289]). Специфические сообщения в DET или DEM для этого интерфейса в стандарте Adaptive не определены.
      


      Последовательность и параллелизм
      

      В рамках процесса отправки вызов подчиняется строгому порядку ([SWS_CM_11274]):
      

        
  
      1. Предварительно жизненный цикл Freshness Value Manager должен управляться ara::com ([SWS_CM_11272]), а экземпляр должен быть инициализирован через apext::com::secoc::FVM::Initialize ([SWS_CM_11273]).
        2. 
  
      2. При отправке GetTxFreshness выполняется после вычислений защиты E2E ([SWS_CM_11274]).
        3. 
  
      3. Затем выполняются вычисление MAC, опциональные усечения и сборка защищённого сообщения ([SWS_CM_11274]).
        4. 

      

      Относительно реентерабельности спецификация умалчивает; тем не менее, реализация FVM, вероятно, должна быть спроектирована потокобезопасной или реентерабельной, если параллельные коммуникационные потоки запрашивают значения актуальности одновременно.

          Использование и контекст вызова
          

          Синхронная библиотечная функция Initialize в области видимости apext::com::secoc::FVM служит для инициализации специфической для поставщика плагин-реализации Freshness Value Manager (FVM) для коммуникации, критичной для безопасности, через SecOC [SWS_CM_11290]. Объявление доступно через заголовочный файл apext/com/secoc/fvm.h SWS CommunicationManagement §C.1.2.2.1.3 «Initialize».
          

          Функция не принимает параметров и декларирует безопасность исключений noexcept (exception safe) [SWS_CM_11290]. Управление жизненным циклом FVM в обязательном порядке берет на себя промежуточное программное обеспечение связи ara::com [SWS_CM_11272], которое выполняет инициализацию плагина FVM посредством явного вызова этого интерфейса [SWS_CM_11273]. Интерпретация: для разработчиков приложений прямого контекста вызова не существует, поскольку предоставление выполняется в качестве плагина для платформы, а управление полностью возложено на ara::com.
          


          Обработка ошибок
          

          Результат операции передаётся через тип возвращаемого значения ara::core::Result<void> [SWS_CM_11290]:
          

            

          • Успех: при успешной инициализации ara::core::Result содержит пустое значение (value_type равно void) [SWS_CM_11290].
            • 

          • Неудачная инициализация: если Freshness Value Manager не удалось инициализировать, возвращается объект ошибки со специфическим кодом ошибки ComSecOcFvmErrc::kFVInitializeFailed; при этом применяется семантика отката для сохранения определённого состояния [SWS_CM_11290].
            • 

          


          Взаимодействие и последовательность
          

          Инициализация с помощью Initialize образует функциональное предварительное условие для всех остальных сервисов FVM в системе [SWS_CM_11273]. Только после успешного выполнения ara::com в рамках операций отправки SecOC после вычисления E2E может обращаться к интерфейсу apext::com::secoc::FVM::GetTxFreshness для получения значений актуальности для сконфигурированных атрибутов freshnessValueId [SWS_CM_11274].
