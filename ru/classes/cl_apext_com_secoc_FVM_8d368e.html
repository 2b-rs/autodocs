Управление ценностью свежести как расширение платформы

apext::com::secoc::FVM обеспечивает обработку SecOC значениями актуальности приема и отправки. Это собственный интерфейс для интеграции платформы; спецификация Communication Management связывает его вызовы с обработкой защищенных сообщений. SWS CM §7.3.2 «Secure Communication» и EXP SW Architecture §9.3.1.1.3 «Interfaces for freshness value management» описывают роль и встраивание.

Порядок вызовов

Перед эксплуатацией платформа инициализирует FVM. При отправке запрашивается значение свежести; При получении переданное, возможно, сокращенное значение актуальности используется для проверки или восстановления. Результатом проверки является установленный статус. Конкретное управление счетчиками и идентификаторами остается вопросом реализации/конфигурации.

Обработка ошибок

Четыре операции возвращают успех через семантику Extension. Ошибки относятся к специальной домене ошибок FVM; приложению не следует приравнивать их к ошибкам E2E-Profile или общим ошибкам ComErrc. EXP ARAComAPI §4.7 «Error Handling» объясняет вышестоящее разделение доменов ошибок.

Совместная работа: расширение платформы FVM предоставляет или проверяет значения актуальности для SecOC; статус проверки передается настроенному интерфейсу состояния. Источники: SWS CM §7.3.2 «Secure Communication», EXP SW Architecture §9.3.1.1.3 «Interfaces for freshness value management».

Предварительное условие для работы FVM

Initialize() настраивает интеграцию управления значением актуальности перед запросом получения или отправки актуальности. EXP SW Architecture §9.3.1.1.3 «Interfaces for freshness value management» описывает этот символ интеграции.

Надёжное использование
  1. Инициализировать FVM при запуске платформы.
  2. Только после этого выполнять Rx-/Tx-операции.
  3. Оцените статус возврата вашего собственного домена ошибок.

SetVerificationStatus() подключает обработку Freshness/SecOC к настроенному интерфейсу состояния. Статус должен принадлежать тому же контексту безопасности, что и ранее обработанное сообщение. (Интерпретация: привязка контекста соответствует архитектуре состояния актуальности и проверки.)

демаркация

Набор статусов проверки не эквивалентен ProfileCheckStatus из образца E2E. Оба механизма лежат в разных защитных слоях. SWS CM §7.3.2 «Secure Communication» и SWS CM §7.4 «Safety» обозначают разделение.
