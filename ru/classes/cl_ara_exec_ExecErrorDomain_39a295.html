Служит для идентификации ошибок Execution Management, а также для их сопоставления с текстами сообщений и объектами исключений.

Класс ara::exec::ExecErrorDomain определяет домен ошибок для Execution Management и сопоставляет числовые коды ошибок с описательными сообщениями ([SWS_EM_02288]). Он создается по умолчанию ([SWS_EM_02286]) и позволяет генерировать типобезопасные исключения ExecException ([SWS_EM_02289]). При отключенных исключениях C++ функция ThrowAsException() согласно [SWS_CORE_10304] отключена во время компиляции ([SWS_EM_02289]).

Контекст

Класс ara::exec::ExecErrorDomain определяет специфический домен ошибок для функционального кластера Execution Management в рамках AUTOSAR Adaptive Platform. Являясь финальной специализацией базового класса ara::core::ErrorDomain, он инкапсулирует сопоставление доменно-специфических причин ошибок и образует мост между числовыми кодами ошибок и семантическими описаниями ошибок. Помимо базового типа ara::core::ErrorDomain, класс тесно взаимодействует с ara::core::ErrorCode и в случае ошибки инстанцирует специфические объекты исключений типа ExecException ([SWS_EM_02289]). Через метод Name() класс предоставляет текстовый идентификатор домена, который соответствует спецификации ara::exec::ExecErrorDomain в [SWS_CORE_90023] ([SWS_EM_02287]).

Контекстная диаграмма: классификация ExecErrorDomain и взаимодействующих с ней компонентов в системе обработки ошибок. Источники: [SWS_EM_02287], [SWS_EM_02289], [SWS_CORE_90023]

Жизненный цикл

Объекты ara::exec::ExecErrorDomain создаются через конструктор по умолчанию ([SWS_EM_02286]). Конструирование объявлено как noexcept и гарантирует полную безопасность относительно исключений, а также потокобезопасность ([SWS_EM_02286]). Поскольку класс не предоставляет изменяемых состояний и объявлен как final, все операции чтения выполняются без побочных эффектов. Вероятно, в реальных приложениях обычно используется глобальный или статический экземпляр домена ошибок (интерпретация: в соответствии с общей моделью ошибок Adaptive AUTOSAR), хотя прямое инстанцирование через конструктор возможно в любой момент.

С точки зрения параллелизма все функции-члены — а именно запрос имени через Name() ([SWS_EM_02287]), разрешение сообщения об ошибке через Message() ([SWS_EM_02288]), а также выбрасывание исключений с помощью ThrowAsException() ([SWS_EM_02289]) — явно специфицированы как потокобезопасные. Таким образом, несколько потоков выполнения могут опрашивать один и тот же экземпляр параллельно и без внешней синхронизации.

Путь использования

В обычном пути выполнения домен служит для преобразования номеров ошибок в понятные диагностические сообщения, а также для перевода кодов ошибок в объекты исключений. Если внутри операции Execution Management возникает ошибка, она обычно представляется как ara::core::ErrorCode, который внутренне ссылается на экземпляр ara::exec::ExecErrorDomain. Для вывода текста вызывающая сторона передает числовой идентификатор ошибки в Message() ([SWS_EM_02288]) и получает указатель на неизменяемую строку (const char*), описывающую причину.

Если вызывающий компонент выбирает обработку ошибок на основе исключений, используется метод ThrowAsException() ([SWS_EM_02289]). Функция принимает ссылку на ara::core::ErrorCode, создает на ее основе новый экземпляр ExecException и непосредственно выбрасывает его в контекст вызова как C++-исключение ([SWS_EM_02289]).

Диаграмма последовательности: процесс генерации C++-исключения через ThrowAsException. Источники: [SWS_EM_02289], [SWS_CORE_10304]

Сценарии ошибок

Методы запроса информации отличаются строгими гарантиями: ни конструирование ([SWS_EM_02286]), ни запрос имени через Name() ([SWS_EM_02287]), ни запрос сообщения через Message() ([SWS_EM_02288]) не вызывают исключений (noexcept), и все три классифицированы как исключениебезопасные («exception safe»). Для неизвестных кодов ошибок Message(), вероятно, возвращает обобщенный текст-заполнитель или пустую строку (интерпретация: полезная нагрузка не определяет отдельного поведения при ошибке для недопустимых значений CodeType).

Особое поведение действует для ThrowAsException(): эта функция специфицирована как noexcept(false), а также явно как не являющаяся исключениебезопасной («not exception safe»), поскольку ее истинная цель состоит в выбрасывании ExecException ([SWS_EM_02289]). Кроме того, действует существенное условие тулчейна: согласно [SWS_CORE_10304], ThrowAsException() не участвует в разрешении перегрузки, если исключения C++ отключены в компиляторе ([SWS_EM_02289]). Таким образом, в системных средах без поддержки исключений этот путь недоступен во время компиляции, вследствие чего ошибки обязательно должны обрабатываться через возвращаемые значения.

Конструктор по умолчанию ExecErrorDomain() инициализирует новый экземпляр домена ошибок ara::exec::ExecErrorDomain согласно [SWS_EM_02286]. Вызов выполняется синхронно, не принимает параметров и не имеет возвращаемого значения. Объявление подключено через заголовочный файл ara/exec/exec_error_domain.h.

В отношении надежности и параллелизма конструктор объявлен как noexcept, считается исключениебезопасным (exception safe) и специфицирован как полностью потокобезопасный (thread-safe) [SWS_EM_02286]. Обработка ошибок при создании объекта не требуется, так как операция выполняется безошибочно и не вызывает кодов ошибок или исключений.

В системе в целом созданный объект служит для представления и описания специфических для модуля ошибок Execution Management. Через экземпляр можно запросить имя домена [SWS_EM_02287], получить текстовые сообщения для кодов ошибок [SWS_EM_02288] или выбросить ошибки в виде C++-исключения [SWS_EM_02289]. Явная инициализация через этот конструктор вряд ли потребуется в модулях приложений, поскольку через свободную функцию GetExecErrorDomain() уже предоставляется глобальная ссылка на экземпляр [SWS_EM_02290].

          Использование
          

          Функция-член Name класса ara::exec::ExecErrorDomain синхронно возвращает указатель на символьную константу (const char *), которая обозначает домен ошибок [SWS_EM_02287]. Возвращаемое значение соответствует определению для ara::exec::ExecErrorDomain из [SWS_CORE_90023]. Метод подключается через заголовочный файл ara/exec/exec_error_domain.h, не ожидает входных параметров и действует как константная функция-член на экземплярах домена ошибок [SWS_EM_02287].
          


          Обработка ошибок и параллелизм
          

          Интерфейс объявлен как noexcept и, таким образом, классифицирован как полностью исключебно-безопасный (exception safe) [SWS_EM_02287]. Коды ошибок не возвращаются, исключения не генерируются. В отношении параллельного доступа функция специфицирована как потокобезопасная (thread-safe) [SWS_EM_02287]. Следовательно, вызовы могут выполняться параллельно из различных потоков без дополнительных мер синхронизации.
          


          Взаимодействие
          

          Благодаря объявлению как override функция реализует общий интерфейс для запроса имени домена в рамках [SWS_CORE_90023]. Возвращаемая строка предположительно служит для того, чтобы однозначно идентифицировать домен ошибок в удобочитаемом виде в выводе протокола или диагностики [SWS_EM_02287].

              Метод ThrowAsException домена ошибок ara::exec::ExecErrorDomain служит для синхронной генерации исключения C++ на основе возникшего кода ошибки [SWS_EM_02289]. Он принимает в качестве входного параметра ссылку на errorCode (тип const ara::core::ErrorCode &), создает из нее объект исключения типа ExecException и непосредственно выбрасывает его как исключение C++ [SWS_EM_02289]. Функция не возвращает значения.
              
  
              В отношении поведения при ошибках и во время выполнения необходимо учитывать следующие аспекты:
              
  
                
    
              • Безопасность исключений: поскольку предполагаемое поведение функции заключается в выбросе исключения, она аннотирована как noexcept(false) и формально классифицирована как небезопасная относительно исключений (not exception safe) [SWS_EM_02289]. Поэтому вызывающие стороны должны быть готовы к перехвату или обработке ExecException.
                • 
    
              • Параллелизм: спецификация определяет функцию-член как потокобезопасную (thread-safe) [SWS_EM_02289]. Таким образом, ее можно безопасно вызывать из параллельных потоков.
                • 
    
              • Ограничения инструментария сборки: согласно [SWS_CORE_10304], ThrowAsException не участвует в разрешении перегрузки, если исключения C++ отключены в инструментарии компилятора [SWS_EM_02289]. Следовательно, в средах без поддержки исключений этот вызов недоступен.
