Управляет динамическими правами диагностики, таймерами сессий и отзывом аутентификации диагностического клиента.

Класс ara::diag::ClientAuthenticationHandle служит приложению для управления активной сессией аутентификации диагностического клиента [SWS_DM_01206]. С помощью этого дескриптора приложение настраивает динамические списки доступа и обновляет таймеры неактивности клиента [SWS_DM_01213]. Объект следует строгой семантике перемещения без возможности копирования и сообщает об ошибках при недоступности управления диагностикой через DiagErrc::kServiceNotAvailable. Путем вызова Revoke предоставленные роли и дополнительные права могут быть в любое время контролируемо отозваны.

Контекст

API-класс ara::diag::ClientAuthenticationHandle определен в заголовочном файле ara/diag/client_authentication_handle.h [SWS_DM_01145]. Он функционирует как центральный управляющий объект, предоставляемый диагностическому приложению экземпляром Diagnostic Server, как только клиент успешно аутентифицирован или его стандартные роли временно переопределены AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».

При запуске системы клиент по умолчанию находится в состоянии kDeAuthenticated [SWS_DM_01205] с предварительно сконфигурированными стандартными ролями [SWS_DM_01204]. Если приложение вызывает ara::diag::ClientAuthentication::Authenticate, Diagnostic Server переводит клиента в состояние kAuthenticated и возвращает ara::diag::ClientAuthenticationHandle [SWS_DM_01206]. Аналогично такой дескриптор создается при вызове ara::diag::ClientAuthentication::OverrideDefaultRoles для временной адаптации ролей [SWS_DM_01209]. Через дескриптор приложение управляет статусом аутентификации и динамическим списком доступа (DynamicAccessList), который предоставляет аутентифицированному клиенту дополнительные права доступа к диагностическим ресурсам помимо диагностического экстракта AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».

Контекстная диаграмма: взаимодействие приложения, ClientAuthenticationHandle и Diagnostic Server. Источники: [SWS_DM_01206], [SWS_DM_01209], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»

Жизненный цикл

Инстанцирование ara::diag::ClientAuthenticationHandle обычно выполняется фабричными методами Diagnostic Server в ходе Authenticate [SWS_DM_01206] или OverrideDefaultRoles [SWS_DM_01209]. Дополнительно класс предоставляет конструктор по умолчанию без параметров [SWS_DM_01146]; созданный таким образом объект, предположительно, функционирует как несвязанный заполнитель до тех пор, пока ему посредством перемещающего присваивания не будет передан активный дескриптор.

Что касается отношений владения, класс реализует строгую семантику перемещения: конструктор перемещения [SWS_DM_01148] и оператор перемещающего присваивания [SWS_DM_01149] определены как noexcept = default. Копирование полностью запрещено, так как конструктор копирования [SWS_DM_01150] и оператор копирующего присваивания [SWS_DM_01151] удалены (=delete). Освобождение экземпляра осуществляется через деструктор ~ClientAuthenticationHandle() [SWS_DM_01147].

Относительно параллелизма конструктор по умолчанию специфицирован как потокобезопасный (thread-safe) [SWS_DM_01146]. Напротив, деструктор [SWS_DM_01147], а также все изменяющие состояние вызовы методов указаны как непотокобезопасные (not thread-safe) [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. Поэтому параллельный доступ к одному и тому же дескриптору требует синхронизации на стороне приложения.

Путь использования

Типичный процесс во время выполнения включает настройку динамических прав, поддержание авторизации и контролируемое завершение:

  1. Получение дескриптора: приложение инициирует аутентификацию в ara::diag::ClientAuthentication и получает экземпляр дескриптора [SWS_DM_01206].
  2. Установка или расширение списка доступа: с помощью метода Set приложение полностью заменяет динамический список доступа диагностического сеанса связи [SWS_DM_01153], [SWS_DM_01213]. В качестве альтернативы Append добавляет дополнительные диагностические шаблоны к существующему списку доступа [SWS_DM_01152] AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 «DynamicAccessList Creation and Update».
  3. Обновление активности: при неактивности в стандартной сессии по истечении таймаута неактивности грозит автоматический возврат в kDeAuthenticated [SWS_DM_01210]. Вызовом Refresh приложение продлевает таймеры, запущенные с помощью Authenticate или OverrideDefaultRoles [SWS_DM_01155] AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle».
  4. Отвержение полномочий: с помощью Revoke приложение явно деаутентифицирует клиента, удаляет соответствующий DynamicAccessList и сбрасывает переопределенные стандартные роли [SWS_DM_01154].

Диаграмма последовательности: процесс аутентификации, управления правами и отзыва через дескриптор. Источники: [SWS_DM_01206], [SWS_DM_01153], [SWS_DM_01155], [SWS_DM_01154]

Сценарии ошибок

Оперативные методы Set [SWS_DM_01153], Append [SWS_DM_01152], Refresh [SWS_DM_01155] и Revoke [SWS_DM_01154] возвращают соответственно ara::core::Result<void> и объявлены как noexcept, а также безопасны относительно исключений (exception safe).

Если связь или выполнение завершаются сбоем из-за того, что существенная функциональность Diagnostic Manager в данный момент недоступна, вызовы возвращают код ошибки DiagErrc::kServiceNotAvailable [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. В этом случае действует семантика отката, так что не остается никаких несогласованных частичных изменений состояния аутентификации или списков доступа клиента.

Опирается на спецификацию диагностического интерфейса AUTOSAR Adaptive R25-11.

функция Append [SWS_DM_01152] Upstream: RS_Diag_04251

ara::core::Result< void > Append (DiagnosticServiceDynamicAccessList dynamicAccessList) noexcept;

This function is used by the application to append a DynamicAccessList to the already existing DynamicAccessList of a Diagnostic Conversation.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: ecc404bb2530 Provenance

Метод Append класса ara::diag::ClientAuthenticationHandle используется приложениями для добавления динамического списка доступа (dynamicAccessList) к уже существующему DynamicAccessList активной диагностической сессии [SWS_DM_01152]. Интерфейс предоставляется через заголовочный файл ara/diag/client_authentication_handle.h AUTOSAR_AP_SWS_Diagnostics §8.6.1.1.3.1 «Append».

Вызов выполняется синхронно и специфицирован как noexcept [SWS_DM_01152]. В качестве входного параметра функция принимает DiagnosticServiceDynamicAccessList. Возвращаемый тип ara::core::Result<void> сигнализирует об успешном завершении или передает код ошибки DiagErrc::kServiceNotAvailable в случае сбоя [SWS_DM_01152]. Последний указывает на то, что важные функции Diagnostic Management в настоящее время недоступны. Для этого случая ошибки действует семантика отката, благодаря чему сохраняется прежнее состояние списка доступа [SWS_DM_01152].

В отношении параллелизма операция считается безопасной по исключениям (exception safe), но явно классифицируется как непотокобезопасная (not thread-safe) [SWS_DM_01152]. Таким образом, при параллельных обращениях к одному и тому же объекту дескриптора, вероятно, потребуется внешняя синхронизация со стороны вызывающего приложения.

Это указание по использованию сгенерировано автоматически и основано исключительно на данных спецификации AUTOSAR R25-11.
