Контекст

Класс ara::diag::ClientAuthenticationHandle ([SWS_DM_01145]) служит интерфейсом управления для активного сеанса диагностической аутентификации. Экземпляр этого дескриптора предоставляется адаптивному приложению со стороны Diagnostic Server Instance, как только успешно завершается либо аутентификация через ara::diag::ClientAuthentication::Authenticate ([SWS_DM_01206]), либо временное переопределение стандартных ролей через ara::diag::ClientAuthentication::OverrideDefaultRoles ([SWS_DM_01209]) (AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle»).

Diagnostic Manager управляет динамическим списком контроля доступа (DynamicAccessList) для каждого аутентифицированного клиента. Этот список содержит шаблоны диагностических запросов, которые предоставляют аутентифицированному клиенту дополнительные права доступа к диагностическим ресурсам сверх конфигурации, сохраненной в Diagnostic Extract (AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle», AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 «DynamicAccessList Creation and Update»). Через ClientAuthenticationHandle приложение управляет как этими динамическими правами доступа, так и статусом аутентификации и соответствующими таймерами неактивности и истечения срока действия по отношению к экземпляру сервера ([SWS_DM_01213], [SWS_DM_01155]).

Контекстная диаграмма: взаимодействие между приложением, дескриптором и Diagnostic Server Instance. Источники: AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle», [SWS_DM_01206], [SWS_DM_01209].

Жизненный цикл

Создание действительного дескриптора обычно выполняется не через конструктор по умолчанию, а в качестве возвращаемого значения методов аутентификации класса ara::diag::ClientAuthentication ([SWS_DM_01206], [SWS_DM_01209]). Хотя класс предоставляет потокобезопасный и безисключительный конструктор по умолчанию ([SWS_DM_01146]), он создает неинициализированный или пустой дескриптор. Что касается владения, ClientAuthenticationHandle реализует строгую семантику перемещения (move-only): конструктор копирования ([SWS_DM_01150]) и оператор присваивания с копированием ([SWS_DM_01151]) удалены (=delete). Дескриптор можно только перемещать (конструктор перемещения [SWS_DM_01148] и оператор присваивания с перемещением [SWS_DM_01149]), что гарантирует наличие единственного владельца для каждого контекста аутентификации.

Уничтожение объекта осуществляется через деструктор ~ClientAuthenticationHandle() ([SWS_DM_01147]). В отношении параллелизма следует учитывать, что ни деструктор, ни управляющие функции-члены (Set, Append, Refresh, Revoke) не являются потокобезопасными ([SWS_DM_01147], [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]). Если несколько потоков приложения обращаются к одному и тому же дескриптору, доступ должен быть синхронизирован.

Путь использования

Типичный сценарий использования включает успешную аутентификацию, определение и расширение прав доступа, регулярное продление срока действия, а также окончательный отзыв прав:

  1. Получение дескриптора: Приложение вызывает Authenticate или OverrideDefaultRoles и в случае успеха получает ClientAuthenticationHandle ([SWS_DM_01206], [SWS_DM_01209]).
  2. Установка прав: С помощью Set(dynamicAccessList) приложение полностью заменяет динамический список доступа диагностического клиента ([SWS_DM_01153], [SWS_DM_01213]).
  3. Расширение прав: При необходимости через Append(dynamicAccessList) к существующему DynamicAccessList можно инкрементно добавлять дополнительные шаблоны диагностических служб ([SWS_DM_01152]).
  4. Обновление таймеров: При продолжающемся диагностическом обмене приложение вызывает Refresh() для сброса таймеров неактивности или тайм-аута ролей ([SWS_DM_01155], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 «ClientAuthenticationHandle», [SWS_DM_01210]). Если ранее использовались и аутентификация, и переопределение ролей, этот вызов обновляет оба таймера одновременно ([SWS_DM_01155]).
  5. Отзыв прав: С помощью Revoke() приложение явно переводит клиента обратно в состояние kDeAuthenticated, сбрасывает назначенную DynamicAccessList и отменяет временно переопределенные роли ([SWS_DM_01154]).

Диаграмма последовательности: типичная последовательность взаимодействия для управления правами и продления таймеров через дескриптор. Источники: [SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155], [SWS_DM_01206].

Сценарии ошибок

Все изменяющие состояние методы дескриптора (Set, Append, Refresh и Revoke) объявлены как noexcept и сообщают об ошибках через возвращаемый тип ara::core::Result<void>:

  • DiagErrc::kServiceNotAvailable: возникает, когда операция не может быть выполнена из-за того, что ключевые функциональные возможности Diagnostic Manager в данный момент недоступны ([SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]). В этом случае применяется семантика отката (rollback), благодаря чему предыдущее состояние в системе остается неизменным.
  • Тайм-аут и автоматическая деаутентификация: Если таймер неактивности не обновляется своевременно через UDS-запросы или Refresh(), Diagnostic Server Instance автоматически переводит клиента в состояние kDeAuthenticated ([SWS_DM_01210]). Интерпретация: последующие попытки управления в контексте с истекшим сроком действия, вероятно, завершатся ошибкой или останутся безрезультатными.

Настоящее руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform R25-11.
