Контекст

Класс ara::diag::DownloadService в модуле diag платформы AUTOSAR Adaptive Platform предоставляет центральный интерфейс C++ для выполнения диагностических загрузок AUTOSAR_AP_SWS_Diagnostics, с. 74. Он служит сервисным обработчиком со стороны приложения, инкапсулирующим операции загрузки для конкретного диагностического интерфейса. Основное взаимодействие происходит между AUTOSAR Diagnostic Management (DM) и конкретной реализацией приложения. Интерпретация: Diagnostic Management принимает UDS-запросы внешнего диагностического тестера согласно ISO 14229-1 и перенаправляет их экземпляру, как только служба начинает предоставляться.

После активации через Offer() класс выступает в качестве интерфейса для стандартизированных фаз диагностической загрузки: запрос (RequestDownload), сегментированная передача данных (TransferData через DownloadData) и завершение (RequestTransferExit через RequestDownloadExit). Приложение реализует чисто виртуальные методы [SWS_DM_00789], [SWS_DM_00790] и [SWS_DM_00791] для приема, верификации и сохранения блоков данных в целевой памяти.

Жизненный цикл

Экземпляр DownloadService создается через конструктор DownloadService(const ara::core::InstanceSpecifier&, ConcurrencyType) [SWS_DM_00787]. InstanceSpecifier связывает экземпляр с определенным в проектной модели PortPrototype для DiagnosticDownloadInterface. С помощью аргумента concurrencyType определяется, вызываются ли реализованные методы сервиса параллельно (kConcurrent) или непараллельно (kNotConcurrent), что задает требование к потокобезопасности логики приложения [SWS_DM_00787]. Сам конструктор выполнен потокобезопасным.

С точки зрения семантики владения и копирования DownloadService спроектирован как уникальный объект: удалены как конструктор копирования [SWS_DM_01649] и оператор присваивания [SWS_DM_01647], так и конструктор перемещения [SWS_DM_01650] и оператор присваивания с перемещением [SWS_DM_01648] (delete).

Операционный жизненный цикл подразделяется на следующие состояния и переходы:

  • Инстанцирован (неактивен): После конструирования экземпляр готов, но еще не перенаправляет диагностические запросы.
  • Предоставлен (активен): Вызов Offer() [SWS_DM_00792] авторизует DM для перенаправления входящих диагностических запросов на загрузку виртуальным методам-обработчикам экземпляра.
  • Остановлен: С помощью StopOffer() [SWS_DM_00793] перенаправление запросов отключается; экземпляр возвращается в неактивное состояние.
  • Уничтожение: виртуальный деструктор ~DownloadService() [SWS_DM_00788] освобождает ресурсы. Поскольку деструктор не является потокобезопасным, службу следует предварительно остановить.

Диаграмма состояний: фазы состояний экземпляра DownloadService от конструирования через предоставление до завершения. Источники: [SWS_DM_00787], [SWS_DM_00792], [SWS_DM_00793], [SWS_DM_00788].

Путь использования

После успешного инстанцирования и предоставления с помощью Offer() процесс загрузки обычно проходит три последовательных шага посредством асинхронных вызовов интерфейса:

  1. Инициализация загрузки (RequestDownload): DM вызывает RequestDownload(...) [SWS_DM_00789]. Передаются идентификатор формата данных (dataFormatIdentifier), формат адреса и длины (addressAndLengthFormatIdentifier), целевой адрес и размер в виде диапазона байтов (memoryAddressAndSize), а также metaInfo и cancellationHandler. Данные в memoryAddressAndSize остаются действительными до тех пор, пока соответствующий Promise не будет выполнен или обработка не будет отменена. Метод возвращает ara::core::Future<void>, который успешно предоставляется при положительной валидации.
  2. Блочная передача данных (DownloadData): для каждого последующего запроса на передачу DM вызывает DownloadData(...) [SWS_DM_00790]. Полезные данные передаются в transferRequestParameterRecord. Приложение обрабатывает данные и сообщает о результате через ara::core::Future<OperationOutput>. Данные в OperationOutput.responseData помещаются в положительном ответе UDS после счетчика последовательности блоков.
  3. Завершение передачи (RequestDownloadExit): для завершения загрузки DM вызывает RequestDownloadExit(...) [SWS_DM_00791]. После заключительной проверки целостности (например, валидации контрольной суммы) приложение возвращает ara::core::Future<OperationOutput>, чьи необязательные данные ответа помещаются после Service-ID.

Все три метода получают cancellationHandler [SWS_DM_00789]. С помощью cancellationHandler.IsCanceled() приложение может проверять статус отмены; с помощью cancellationHandler.SetNotifier(...) можно зарегистрировать колбэк, чтобы непосредственно реагировать на прерывание диагностического диалога. Интерпретация: при преждевременной отмене приложение завершает внутреннюю буферизацию и прерывает текущие операции записи.

Диаграмма последовательности: типичная последовательность взаимодействия между Diagnostic Management и DownloadService во время диагностической загрузки. Источники: [SWS_DM_00789], [SWS_DM_00790], [SWS_DM_00791].

Сценарии ошибок

Ошибки могут возникать как при создании и конфигурации, так и во время предоставления службы и обработки данных:

  • Ошибки моделирования и инициализации: при вызове конструктора могут быть вызваны нарушения моделирования [SWS_DM_00787]:
    • InstanceSpecifierMappingIntegrityViolation: InstanceSpecifier не удается разрешить в модели в контексте выполнения или он не указывает на PortPrototype.
    • PortInterfaceMappingViolation: PortPrototype, типизированный с помощью DiagnosticDownloadInterface, отображен на DiagnosticServiceGenericMapping без соблюдения соответствия типов.
    • ProcessMappingViolation: для InstanceRef не существует подходящего смоделированного Process.
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier уже используется другим экземпляром внутри этого процесса.
  • Ошибка при предложении службы: повторный вызов Offer() при уже предложенной службе завершается сбоем и возвращает код ошибки DiagOfferErrc::kAlreadyOffered [SWS_DM_00792].
  • Ошибки диагностики (Negative Response Codes): если обработка в RequestDownload, DownloadData или RequestDownloadExit завершается сбоем (например, при некорректном форматировании, недопустимой области памяти или ошибках записи), возвращенный Future предоставляется с соответствующим кодом ошибки из DiagUdsNrcErrc согласно ISO 14229-1 [SWS_DM_00789], [SWS_DM_00790], [SWS_DM_00791]. DM формирует на этой основе отрицательный ответ (NRC) для тестера.

Данное руководство по классу основано на спецификации AUTOSAR AP R25-11 (Diagnostics). Все сведения были проверены по требованиям спецификации.
