Контекст

Класс ara::diag::DiagReportingErrorDomain определяет стандартизированный домен ошибок для состояний ошибок в области диагностической отчетности Adaptive Platform [SWS_DM_00996] (AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»). Являясь финальной специализацией базового класса ara::core::ErrorDomain, он обеспечивает единую классификацию и передачу ошибок отчетности внутри модуля диагностики.

Домен ошибок обычно взаимодействует со следующими компонентами и элементами инфраструктуры:

  • Функции диагностической отчетности: сообщают об определенных состояниях ошибок, возникающих при диагностических процессах, и соотносят их с доменом диагностической отчетности.
  • Инкапсуляция ошибок (ara::core::ErrorCode): включает ссылку на экземпляр DiagReportingErrorDomain вместе с конкретным значением кода ошибки.
  • Прикладные и базовые системы: используют домен для преобразования информации об ошибках в читаемый текст или создания соответствующих объектов исключений.

Для единообразной типизации класс предоставляет два публичных псевдонима типов: Errc ссылается на перечисление DiagReportingErrc для конкретных значений ошибок [SWS_DM_00997], в то время как Exception определяет базовый тип DiagReportingException для специфичных для домена исключений [SWS_DM_00998] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.1 «Public Member Types»).

Контекстная диаграмма: встраивание DiagReportingErrorDomain в систему обработки ошибок Adaptive Platform. Источники: [SWS_DM_00996], [SWS_DM_00997], [SWS_DM_00998].

Жизненный цикл

Инстанцирование ara::diag::DiagReportingErrorDomain осуществляется через конструктор по умолчанию, объявленный как constexpr и noexcept [SWS_DM_00999] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Это допускает конструирование уже во время компиляции и гарантирует безопасность относительно исключений.

Что касается отношений владения, действует интерпретация, согласно которой экземпляры этого домена ошибок обычно хранятся как долгоживущие глобальные или статические объекты (синглтоны), поскольку они предоставляют исключительно метаданные и функции трансляции для кодов ошибок. Класс не инкапсулирует изменяемое состояние; после создания переходы состояний отсутствуют.

Что касается параллелизма, все функции-члены спроектированы как потокобезопасные. Как инстанцирование через конструктор [SWS_DM_00999], так и последующие вызовы Name() [SWS_DM_01000], Message() [SWS_DM_01001] и ThrowAsException() [SWS_DM_01002] могут безопасно и параллельно выполняться несколькими потоками. Уничтожение экземпляра тривиально и происходит при освобождении окружающей статической области памяти.

Путь использования

Типичный сценарий использования при диагностике включает создание, опрос и дальнейшую обработку ошибок:

  1. Идентификация ошибки: если во время процесса диагностики возникает ошибка отчётности, соответствующее значение перечисления из DiagReportingErrc получается через псевдоним Errc [SWS_DM_00997] и инкапсулируется в ara::core::ErrorCode вместе с доменом.
  2. Получение имени домена: для идентификации домена ошибок через Name() можно запросить короткое имя домена [SWS_DM_01000]. При этом именование соответствует требованиям [SWS_CORE_90023] (AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»).
  3. Разрешение сообщения об ошибке: с помощью метода Message(errorCode) числовое значение ошибки преобразуется в понятное текстовое сообщение [SWS_DM_01001] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 «Message»). Возвращаемое значение гарантированно никогда не бывает nullptr.
  4. Генерация исключения: если вышестоящей логике приложения требуется обработка исключений, вызывается ThrowAsException(errorCode) [SWS_DM_01002], в результате чего генерируется соответствующее DiagReportingException [SWS_DM_00998].

Диаграмма последовательности: типичный процесс инкапсуляции ошибки, запроса сообщения и опциональной генерации исключения. Источники: [SWS_DM_00997], [SWS_DM_01001], [SWS_DM_01002].

Сценарии ошибок

При работе с ara::diag::DiagReportingErrorDomain актуальны следующие аспекты безопасности исключений и предусловий:

  • Безопасные относительно исключений базовые функции: конструктор по умолчанию DiagReportingErrorDomain() [SWS_DM_00999], запрос имени Name() [SWS_DM_01000], а также Message() [SWS_DM_01001] объявлены с noexcept и полностью безопасны относительно исключений (exception safe).
  • Гарантированный возврат текстовых сообщений: поскольку Message() по контракту никогда не возвращает nullptr [SWS_DM_01001], реализация, вероятно, предоставляет стандартизированный резервный текст даже для неизвестных или недопустимых кодов ошибок.
  • Поведение при генерации исключений: функция ThrowAsException() аннотирована noexcept(false) и классифицирована как небезопасная относительно исключений (not exception safe) [SWS_DM_01002], поскольку её основная цель заключается в преднамеренной генерации исключения.
  • Отключённые исключения C++: если исключения C++ отключены в тулчейне компилятора, ThrowAsException() согласно [SWS_CORE_10304] не участвует в разрешении перегрузки [SWS_DM_01002]. В таких средах вызывающие стороны должны реализовывать обработку ошибок исключительно через ara::core::ErrorCode.

Настоящее руководство основано исключительно на спецификации AUTOSAR для Adaptive Platform (релиз R25-11).
