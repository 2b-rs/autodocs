Определяет домен ошибок для Diagnostic Reporting и преобразует коды ошибок в текстовые сообщения или исключения.

Класс ara::diag::DiagReportingErrorDomain образует стандартизированный домен ошибок для отчетов об ошибках в области диагностики платформы AUTOSAR Adaptive Platform ([SWS_DM_00996]). Он берет на себя преобразование числовых кодов ошибок в детерминированные текстовые сообщения и при необходимости поддерживает генерацию соответствующих объектов исключений ([SWS_DM_01001]). Поскольку все функции запроса спроектированы без сохранения состояния и потокобезопасными, данный домен подходит для параллельного использования. В качестве важного граничного условия обработка исключений при отключенных исключениях C++ не участвует в разрешении перегрузки.

Контекст

Класс ara::diag::DiagReportingErrorDomain представляет домен ошибок для ошибок в системе диагностических сообщений (Diagnostic Reporting) в AUTOSAR Adaptive ([SWS_DM_00996], AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»). В качестве финальной реализации он специализирует базовый класс ara::core::ErrorDomain и представляет собой функциональное связующее звено между обобщенной архитектурой ошибок и состояниями ошибок, связанными с диагностикой. К ключевым партнерам по взаимодействию относятся компоненты Diagnostic Reporting, а также экземпляры ara::core::ErrorCode, которые переносят ошибки этой области ([SWS_DM_01002]). Класс определяет псевдоним типа Errc для перечисления кодов ошибок ara::diag::DiagReportingErrc ([SWS_DM_00997], AUTOSAR_AP_SWS_Diagnostics §8.11.7.1.1 «Type Alias: Errc»), а также псевдоним типа Exception для базового класса исключений ara::diag::DiagReportingException ([SWS_DM_00998], AUTOSAR_AP_SWS_Diagnostics §8.11.7.1.2 «Type Alias: Exception»). Через метод Name() он возвращает стандартизированное короткое имя домена ошибок согласно [SWS_CORE_90023] ([SWS_DM_01000], AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»).

Контекстная диаграмма: встраивание DiagReportingErrorDomain в архитектуру ошибок с базовыми типами и идентификаторами. Источники: [SWS_DM_00996], [SWS_DM_00997], [SWS_DM_00998], [SWS_DM_01002].

Жизненный цикл

Экземпляры ara::diag::DiagReportingErrorDomain создаются через конструктор по умолчанию без параметров ([SWS_DM_00999], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Он объявлен как constexpr и noexcept, что гарантирует безопасное конструирование во время компиляции или во время запуска программы без динамических выделений памяти или риска возникновения исключений. Поскольку класс не инкапсулирует изменяемые данные состояния, динамические переходы жизненного цикла или явные передачи владения отсутствуют. Интерпретация: в случае экземпляров речь, как правило, должна идти о долгоживущих объектах-одиночках (singleton), глобально доступных в процессе на протяжении всего времени выполнения. Вопрос Q-4aa1b2858839e55d (открытый) В отношении многопоточности как конструирование, так и все методы запроса явно специфицированы как thread-safe и exception safe ([SWS_DM_00999], [SWS_DM_01000], [SWS_DM_01001]), благодаря чему параллельный доступ из нескольких потоков допустим без внешней синхронизации.

Путь использования

Обычный сценарий использования заключается в оценке и разрешении диагностических ошибок, подключаемых через заголовочный файл #include "ara/diag/diag_error_domain.h" ([SWS_DM_00997], [SWS_DM_00999]). Если при отправке диагностической информации возникает ошибка, она обычно инкапсулируется в ara::core::ErrorCode, который ссылается на домен. Для протоколирования или отображения система опрашивает метод Message(errorCode) ([SWS_DM_01001], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 «Message»). Эта функция принимает числовое значение ошибки и возвращает соответствующее текстовое сообщение в виде указателя на константную строку. Спецификация строго гарантирует, что нулевой указатель (never nullptr) никогда не будет возвращен ([SWS_DM_01001]), что обеспечивает надежную дальнейшую обработку в службах протоколирования без проверок на нулевой указатель. Через Name() можно дополнительно получить текстовый идентификатор домена ([SWS_DM_01000]).

Сценарии ошибок

Для целенаправленной эскалации ошибок домен предоставляет метод ThrowAsException(errorCode) ([SWS_DM_01002]). Он объявлен с noexcept(false) и формально классифицирован как небезопасный относительно исключений ([SWS_DM_01002]), поскольку его назначение состоит в намеренном выходе из потока управления через исключение. Интерпретация: функция внутри, вероятно, конструирует и выбрасывает экземпляр исключения типа DiagReportingException с переданным errorCode. Вопрос Q-747db3b9fec32fcd (открытый) Существенное предусловие касается конфигурации компилятора: если исключения C++ отключены в наборе инструментов, метод ThrowAsException согласно [SWS_CORE_10304] не участвует в разрешении перегрузки ([SWS_DM_01002]). В таких окружениях вызов терпит неудачу уже при компиляции, так что проверки ошибок должны обязательно выполняться на основе значений через коды ошибок. Потенциальные ошибочные ситуации из-за недействительных кодов ошибок метод Message() перехватывает тем, что всегда предоставляет определенный текстовый указатель ([SWS_DM_01001]).

Данное руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform Release R25-11.

Конструктор по умолчанию без параметров [SWS_DM_00999] инициализирует экземпляр домена ошибок ara::diag::DiagReportingErrorDomain ([SWS_DM_00996], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Он объявлен как constexpr, а также noexcept и создает домен синхронно без возвращаемого значения. Класс подключается через заголовочный файл #include "ara/diag/diag_error_domain.h".

Операция специфицирована как потокобезопасная и безопасная по отношению к исключениям ([SWS_DM_00999]). Поскольку конструктор определен как noexcept, при инстанцировании исключений времени выполнения не возникает. Созданный домен ошибок служит для классификации и сопоставления ошибок из перечисления DiagReportingErrc ([SWS_DM_00560], псевдоним типа Errc в [SWS_DM_00997]), которое отображает специфические причины ошибок в диагностическом репортинге, такие как kAlreadyOffered, kConfigurationMismatch, kDebouncingConfigurationInconsistent или kReportIgnored.

Во взаимодействии с доменом ошибок функции-члены Name ([SWS_DM_01000]) и Message ([SWS_DM_01001]) возвращают имя домена, а также тексты ошибок для переданных кодов ошибок. С помощью ThrowAsException ([SWS_DM_01002]) коды ошибок могут преобразовываться в объекты исключений базового типа DiagReportingException ([SWS_DM_00998]), тогда как MakeErrorCode ([SWS_DM_01006]) служит для создания новых экземпляров ara::core::ErrorCode. Интерпретация: ручное инстанцирование через этот конструктор в прикладных программах вряд ли потребуется, поскольку доступ обычно осуществляется через глобальную функцию-синглтон GetDiagReportingDomain ([SWS_DM_01004]). Вопрос Q-772337db203849c6 (открытый)

      Использование
      

      Метод Message класса ara::diag::DiagReportingErrorDomain ([SWS_DM_01001]) служит для синхронного преобразования числового кода ошибки (ara::core::ErrorDomain::CodeType errorCode) в описательное текстовое сообщение. В качестве возвращаемого значения функция возвращает указатель типа const char *, который согласно спецификации никогда не равен nullptr ([SWS_DM_01001]). Из-за типа возвращаемого значения без механизма освобождения указатель, предположительно, ссылается на статическую память (интерпретация). Вопрос Q-6c1dffd8e5f8f2c2 (открытый) Интерфейс предоставляется через заголовочный файл #include "ara/diag/diag_error_domain.h" ([SWS_DM_01001]).
      


      Обработка ошибок и параллелизм
      

      Функция определена как noexcept, а также exception safe ([SWS_DM_01001]). Поскольку по контракту гарантируется, что нулевой указатель никогда не возвращается, функция всегда формирует допустимую строку даже для неизвестных кодов ошибок ([SWS_DM_01001]). Что касается параллелизма, Message специфицирована как thread-safe ([SWS_DM_01001]). Таким образом, вызовы могут выполняться параллельно из нескольких потоков без дополнительной синхронизации.
      


      Взаимодействие
      

      Метод как override переопределяет одноименный базовый метод преобразования кодов ошибок в контексте Adaptive AUTOSAR ([SWS_DM_01001]). Этот единый паттерн поведения разделяют и другие домены ошибок диагностического модуля, например ara::diag::DiagErrorDomain ([SWS_DM_00522]), ara::diag::DiagUdsNrcErrorDomain ([SWS_DM_00534]), ara::diag::DiagOfferErrorDomain ([SWS_DM_00994]) и ara::diag::DiagSovdErrorDomain ([SWS_DM_01814]).

          Функция-член Name() класса ara::diag::DiagReportingErrorDomain из заголовочного файла #include "ara/diag/diag_error_domain.h" возвращает сконфигурированное короткое имя (shortname) области ошибок ApApplicationErrorDomain.SN в виде нуль-терминированной C-строки [SWS_DM_01000]. Вызов выполняется синхронно и без входных параметров, чтобы предоставить идентификатор для целей диагностики и протоколирования в системе AUTOSAR_AP_SWS_Diagnostics с. 68.
          


          Для обработки ошибок не определены ни специфические коды ошибок, ни сообщения DET или DEM. Благодаря спецификации как noexcept и исключебно-безопасности (exception safe) гарантируется, что вызов функции всегда успешен и не генерирует исключений [SWS_DM_01000].
          


          Что касается параллелизма и ограничений, метод специфицирован как потокобезопасный (thread-safe) и допускает параллельный реентерабельный доступ из различных потоков [SWS_DM_01000]. Интерпретация: возвращаемый указатель, вероятно, ссылается на строку, неизменяемую на протяжении всего времени жизни экземпляра домена ошибок. Вопрос Q-d67122aa15cc13f8 (открытый)
          


          В общей системе интерфейс следует единому стандарту для доменов ошибок Adaptive. Функционально он соответствует эквивалентным методам Name() родственных доменов, таких как DiagErrorDomain [SWS_DM_00521], DiagUdsNrcErrorDomain [SWS_DM_00533], DiagOfferErrorDomain [SWS_DM_00993], а также DiagSovdErrorDomain [SWS_DM_01813].

    Функция ThrowAsException области ara::diag::DiagReportingErrorDomain служит для генерации C++-исключения, соответствующего переданному коду ошибки ([SWS_DM_01002], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.3 «ThrowAsException»). Интерфейс предоставляется через заголовочный файл ara/diag/diag_error_domain.h ([SWS_DM_01002]).
  
              
  
              Использование и контекст вызова
              
  
              
    В качестве входного параметра метод принимает экземпляр типа const ara::core::ErrorCode& (errorCode) ([SWS_DM_01002]). Он не имеет возвращаемого значения (void) и специфицирован с noexcept(false) ([SWS_DM_01002]). Если C++-исключения отключены в тулчейне компилятора, эта функция не участвует в разрешении перегрузки ([SWS_DM_01002]).
  
              
  
              Параллелизм и безопасность ошибок
              
  
              
    Функция определена как потокобезопасная (thread-safe) ([SWS_DM_01002]). В отношении безопасности исключений она классифицирована как не исключебно-безопасная (not exception safe), поскольку генерация исключения представляет собой основную семантику операции ([SWS_DM_01002]).
