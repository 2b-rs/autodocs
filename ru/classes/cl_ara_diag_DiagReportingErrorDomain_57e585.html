Контекст

Класс ara::diag::DiagReportingErrorDomain определяет стандартизированный домен ошибок для состояний ошибок в области диагностической отчетности Adaptive Platform [SWS_DM_00996] (AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»). Являясь финальной специализацией базового класса ara::core::ErrorDomain, он обеспечивает единую классификацию и передачу ошибок отчетности внутри модуля диагностики.

Домен ошибок обычно взаимодействует со следующими компонентами и элементами инфраструктуры:

  • Функции диагностической отчетности: сообщают об определенных состояниях ошибок, возникающих при диагностических процессах, и соотносят их с доменом диагностической отчетности.
  • Инкапсуляция ошибок (ara::core::ErrorCode): включает ссылку на экземпляр DiagReportingErrorDomain вместе с конкретным значением кода ошибки.
  • Прикладные и базовые системы: используют домен для преобразования информации об ошибках в читаемый текст или создания соответствующих объектов исключений.

Для единообразной типизации класс предоставляет два публичных псевдонима типов: Errc ссылается на перечисление DiagReportingErrc для конкретных значений ошибок [SWS_DM_00997], в то время как Exception определяет базовый тип DiagReportingException для специфичных для домена исключений [SWS_DM_00998] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.1 «Public Member Types»).

Контекстная диаграмма: встраивание DiagReportingErrorDomain в систему обработки ошибок Adaptive Platform. Источники: [SWS_DM_00996], [SWS_DM_00997], [SWS_DM_00998].

Жизненный цикл

Инстанцирование ara::diag::DiagReportingErrorDomain осуществляется через конструктор по умолчанию, объявленный как constexpr и noexcept [SWS_DM_00999] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Это допускает конструирование уже во время компиляции и гарантирует безопасность относительно исключений.

Что касается отношений владения, действует интерпретация, согласно которой экземпляры этого домена ошибок обычно хранятся как долгоживущие глобальные или статические объекты (синглтоны), поскольку они предоставляют исключительно метаданные и функции трансляции для кодов ошибок. Класс не инкапсулирует изменяемое состояние; после создания переходы состояний отсутствуют.

Что касается параллелизма, все функции-члены спроектированы как потокобезопасные. Как инстанцирование через конструктор [SWS_DM_00999], так и последующие вызовы Name() [SWS_DM_01000], Message() [SWS_DM_01001] и ThrowAsException() [SWS_DM_01002] могут безопасно и параллельно выполняться несколькими потоками. Уничтожение экземпляра тривиально и происходит при освобождении окружающей статической области памяти.

Путь использования

Типичный сценарий использования при диагностике включает создание, опрос и дальнейшую обработку ошибок:

  1. Идентификация ошибки: если во время процесса диагностики возникает ошибка отчётности, соответствующее значение перечисления из DiagReportingErrc получается через псевдоним Errc [SWS_DM_00997] и инкапсулируется в ara::core::ErrorCode вместе с доменом.
  2. Получение имени домена: для идентификации домена ошибок через Name() можно запросить короткое имя домена [SWS_DM_01000]. При этом именование соответствует требованиям [SWS_CORE_90023] (AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»).
  3. Разрешение сообщения об ошибке: с помощью метода Message(errorCode) числовое значение ошибки преобразуется в понятное текстовое сообщение [SWS_DM_01001] (AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 «Message»). Возвращаемое значение гарантированно никогда не бывает nullptr.
  4. Генерация исключения: если вышестоящей логике приложения требуется обработка исключений, вызывается ThrowAsException(errorCode) [SWS_DM_01002], в результате чего генерируется соответствующее DiagReportingException [SWS_DM_00998].

Диаграмма последовательности: типичный процесс инкапсуляции ошибки, запроса сообщения и опциональной генерации исключения. Источники: [SWS_DM_00997], [SWS_DM_01001], [SWS_DM_01002].

Сценарии ошибок

При работе с ara::diag::DiagReportingErrorDomain актуальны следующие аспекты безопасности исключений и предусловий:

  • Безопасные относительно исключений базовые функции: конструктор по умолчанию DiagReportingErrorDomain() [SWS_DM_00999], запрос имени Name() [SWS_DM_01000], а также Message() [SWS_DM_01001] объявлены с noexcept и полностью безопасны относительно исключений (exception safe).
  • Гарантированный возврат текстовых сообщений: поскольку Message() по контракту никогда не возвращает nullptr [SWS_DM_01001], реализация, вероятно, предоставляет стандартизированный резервный текст даже для неизвестных или недопустимых кодов ошибок.
  • Поведение при генерации исключений: функция ThrowAsException() аннотирована noexcept(false) и классифицирована как небезопасная относительно исключений (not exception safe) [SWS_DM_01002], поскольку её основная цель заключается в преднамеренной генерации исключения.
  • Отключённые исключения C++: если исключения C++ отключены в тулчейне компилятора, ThrowAsException() согласно [SWS_CORE_10304] не участвует в разрешении перегрузки [SWS_DM_01002]. В таких средах вызывающие стороны должны реализовывать обработку ошибок исключительно через ara::core::ErrorCode.

Настоящее руководство основано исключительно на спецификации AUTOSAR для Adaptive Platform (релиз R25-11).

<h4>Контекст</h4>
<p>Класс <code>ara::diag::DiagReportingErrorDomain</code> определяет стандартизированный домен ошибок для состояний ошибок в области диагностической отчетности Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_00996" href="../spec/record.html?id=SWS_DM_00996">[SWS_DM_00996]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=410">AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»</a>). Являясь финальной специализацией базового класса <code>ara::core::ErrorDomain</code>, он обеспечивает единую классификацию и передачу ошибок отчетности внутри модуля диагностики.</p>

<p>Домен ошибок обычно взаимодействует со следующими компонентами и элементами инфраструктуры:</p>
<ul>
<li><strong>Функции диагностической отчетности:</strong> сообщают об определенных состояниях ошибок, возникающих при диагностических процессах, и соотносят их с доменом диагностической отчетности.</li>
<li><strong>Инкапсуляция ошибок (<code>ara::core::ErrorCode</code>):</strong> включает ссылку на экземпляр <code>DiagReportingErrorDomain</code> вместе с конкретным значением кода ошибки.</li>
<li><strong>Прикладные и базовые системы:</strong> используют домен для преобразования информации об ошибках в читаемый текст или создания соответствующих объектов исключений.</li>
</ul>

<p>Для единообразной типизации класс предоставляет два публичных псевдонима типов: <code>Errc</code> ссылается на перечисление <code>DiagReportingErrc</code> для конкретных значений ошибок <a class="spec-record-ref" data-req="SWS_DM_00997" href="../spec/record.html?id=SWS_DM_00997">[SWS_DM_00997]</a>, в то время как <code>Exception</code> определяет базовый тип <code>DiagReportingException</code> для специфичных для домена исключений <a class="spec-record-ref" data-req="SWS_DM_00998" href="../spec/record.html?id=SWS_DM_00998">[SWS_DM_00998]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=411">AUTOSAR_AP_SWS_Diagnostics §8.11.7.1 «Public Member Types»</a>).</p>

<h4>Жизненный цикл</h4>
<p>Инстанцирование <code>ara::diag::DiagReportingErrorDomain</code> осуществляется через конструктор по умолчанию, объявленный как <code>constexpr</code> и <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=412">AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»</a>). Это допускает конструирование уже во время компиляции и гарантирует безопасность относительно исключений.</p>

<p>Что касается отношений владения, действует интерпретация, согласно которой экземпляры этого домена ошибок обычно хранятся как долгоживущие глобальные или статические объекты (синглтоны), поскольку они предоставляют исключительно метаданные и функции трансляции для кодов ошибок. Класс не инкапсулирует изменяемое состояние; после создания переходы состояний отсутствуют.</p>

<p>Что касается параллелизма, все функции-члены спроектированы как потокобезопасные. Как инстанцирование через конструктор <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a>, так и последующие вызовы <code>Name()</code> <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a>, <code>Message()</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a> и <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a> могут безопасно и параллельно выполняться несколькими потоками. Уничтожение экземпляра тривиально и происходит при освобождении окружающей статической области памяти.</p>

<h4>Путь использования</h4>
<p>Типичный сценарий использования при диагностике включает создание, опрос и дальнейшую обработку ошибок:</p>
<ol>
<li><strong>Идентификация ошибки:</strong> если во время процесса диагностики возникает ошибка отчётности, соответствующее значение перечисления из <code>DiagReportingErrc</code> получается через псевдоним <code>Errc</code> <a class="spec-record-ref" data-req="SWS_DM_00997" href="../spec/record.html?id=SWS_DM_00997">[SWS_DM_00997]</a> и инкапсулируется в <code>ara::core::ErrorCode</code> вместе с доменом.</li>
<li><strong>Получение имени домена:</strong> для идентификации домена ошибок через <code>Name()</code> можно запросить короткое имя домена <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a>. При этом именование соответствует требованиям <a class="spec-record-ref" data-req="SWS_CORE_90023" href="../spec/record.html?id=SWS_CORE_90023">[SWS_CORE_90023]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=410">AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»</a>).</li>
<li><strong>Разрешение сообщения об ошибке:</strong> с помощью метода <code>Message(errorCode)</code> числовое значение ошибки преобразуется в понятное текстовое сообщение <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=412">AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 «Message»</a>). Возвращаемое значение гарантированно никогда не бывает <code>nullptr</code>.</li>
<li><strong>Генерация исключения:</strong> если вышестоящей логике приложения требуется обработка исключений, вызывается <code>ThrowAsException(errorCode)</code> <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a>, в результате чего генерируется соответствующее <code>DiagReportingException</code> <a class="spec-record-ref" data-req="SWS_DM_00998" href="../spec/record.html?id=SWS_DM_00998">[SWS_DM_00998]</a>.</li>
</ol>

<h4>Сценарии ошибок</h4>
<p>При работе с <code>ara::diag::DiagReportingErrorDomain</code> актуальны следующие аспекты безопасности исключений и предусловий:</p>
<ul>
<li><strong>Безопасные относительно исключений базовые функции:</strong> конструктор по умолчанию <code>DiagReportingErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a>, запрос имени <code>Name()</code> <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a>, а также <code>Message()</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a> объявлены с <code>noexcept</code> и полностью безопасны относительно исключений (exception safe).</li>
<li><strong>Гарантированный возврат текстовых сообщений:</strong> поскольку <code>Message()</code> по контракту никогда не возвращает <code>nullptr</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a>, реализация, вероятно, предоставляет стандартизированный резервный текст даже для неизвестных или недопустимых кодов ошибок.</li>
<li><strong>Поведение при генерации исключений:</strong> функция <code>ThrowAsException()</code> аннотирована <code>noexcept(false)</code> и классифицирована как небезопасная относительно исключений (not exception safe) <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a>, поскольку её основная цель заключается в преднамеренной генерации исключения.</li>
<li><strong>Отключённые исключения C++:</strong> если исключения C++ отключены в тулчейне компилятора, <code>ThrowAsException()</code> согласно <a class="spec-record-ref" data-req="SWS_CORE_10304" href="../spec/record.html?id=SWS_CORE_10304">[SWS_CORE_10304]</a> не участвует в разрешении перегрузки <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a>. В таких средах вызывающие стороны должны реализовывать обработку ошибок исключительно через <code>ara::core::ErrorCode</code>.</li>
</ul>
