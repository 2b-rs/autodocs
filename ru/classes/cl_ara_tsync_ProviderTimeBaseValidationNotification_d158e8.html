Контекст

Класс ara::tsync::ProviderTimeBaseValidationNotification представляет собой абстрактный интерфейс (callback-интерфейс) в составе модуля AUTOSAR Adaptive tsync. Он служит для уведомления вышестоящего приложения валидации (Validator Application) о доступности новых блоков данных измерений, записанных для некоторого базиса времени.

В синхронизированной по времени комплексной системе обычно взаимодействуют три основных компонента:

  • tsync-провайдер (Time Base): подсистема синхронизации собирает данные протокола и тайминга во время выполнения. Как только появляется новый блок измерений, провайдер вызывает соответствующие методы уведомления.
  • ProviderTimeBaseValidationNotification: абстрактный callback-интерфейс определяет контракты вызова для передачи данных измерений мастера и ответчика ([SWS_TS_00421], [SWS_TS_00423]).
  • Приложение валидатора: логика на стороне приложения реализует этот интерфейс для анализа полученных блоков измерений, выполнения проверок правдоподобности и мониторинга валидности базиса времени.

Контекстная диаграмма: взаимодействие между tsync-провайдером, интерфейсом обратного вызова и приложением валидатора. Источники: [SWS_TS_00421], [SWS_TS_00423].

Жизненный цикл

Поскольку ProviderTimeBaseValidationNotification представляет собой чисто абстрактный базовый класс с чисто виртуальными функциями-членами, он не может быть инстанцирован напрямую. Его жизненный цикл делится на следующие фазы:

  • Создание и владение: приложение валидатора порождает конкретный класс наблюдателя от ProviderTimeBaseValidationNotification и инстанцирует его. Владение (ownership) сохраняется за приложением валидатора.
  • Предоставление: интерпретация: созданный экземпляр обратного вызова регистрируется в контролируемом базисе времени tsync-провайдера, чтобы провайдер мог удерживать ссылки на него и выполнять вызовы методов.
  • Состояния: сам интерфейс не содержит внутренних хранилищ состояния. После регистрации объект остается в состоянии готовности к приему поступающих данных измерений.
  • Уничтожение: класс содержит виртуальный стандартный деструктор ~ProviderTimeBaseValidationNotification() noexcept = default; ([SWS_TS_01301]). Это гарантирует корректное освобождение ресурсов полиморфных экземпляров при их удалении через указатель на интерфейс. Перед уничтожением объекта необходимо убедиться, что tsync-провайдер больше не отправляет уведомлений этому экземпляру.
  • Конкурентность: согласно спецификации методы интерфейса классифицированы как non_threadsafe ([SWS_TS_00421], [SWS_TS_00423]). Поэтому приложение валидатора не должно исходить из того, что параллельные вызовы могут безопасно обрабатываться в многопоточной среде без внешних механизмов синхронизации.

Путь использования

Типичный сценарий использования описывает прием и пересылку данных измерений тайминга во время активной работы базиса времени:

  1. Реализация обратного вызова: приложение переопределяет оба метода интерфейса SetMasterTimingData ([SWS_TS_00421]) и SetPdelayResponderData ([SWS_TS_00423]).
  2. Предоставление базису времени: предположительно приложение передает ссылку на производный экземпляр подсистеме tsync для активации мониторинга.
  3. Прием данных Time Master: как только для Time Master базиса времени становится доступен новый блок данных измерений, подсистема tsync вызывает метод SetMasterTimingData ([SWS_TS_00421]). При этом вызывающая сторона передает параметр measurementData типа const TimeMasterMeasurementType&, содержащий подробные данные валидации Time Master.
  4. Прием данных Pdelay Responder: если имеются записанные данные измерений для pDelay Responder базиса времени, вызывается SetPdelayResponderData ([SWS_TS_00423]). При этом для анализа передается блок данных типа const PdelayResponderMeasurementType&.
  5. Анализ и завершение: приложение валидатора проверяет полученные данные измерений на соответствие и отклонения от пороговых значений. При остановке системы или завершении валидации экземпляр освобождается через виртуальный деструктор ([SWS_TS_01301]).

Диаграмма последовательности: предоставление блоков данных измерений через интерфейс уведомлений. Источники: [SWS_TS_00421], [SWS_TS_00423], [SWS_TS_01301].

Сценарии ошибок

В отношении обработки ошибок и граничных условий для ProviderTimeBaseValidationNotification действуют следующие требования:

  • Безопасность исключений: все функции-члены — SetMasterTimingData ([SWS_TS_00421]), SetPdelayResponderData ([SWS_TS_00423]), а также деструктор ([SWS_TS_01301]) — объявлены как noexcept и специфицированы как exception safe. Реализации приложения валидатора не должны допускать выхода исключений C++ из обратных вызовов, поскольку состояние исключения в функции noexcept приводит к немедленному аварийному завершению программы через std::terminate.
  • Возвращаемые значения и сигнализация об ошибках: методы имеют тип возвращаемого значения void. Прямое уведомление tsync-провайдера об успехе или сбое через этот интерфейс не предусмотрено.
  • Действительность ссылок: передаваемые структуры данных измерений передаются по константным ссылкам. Вызываемое приложение должно исходить из того, что действительность данных может быть ограничена длительностью вызова метода, поэтому значения, требующие сохранения, следует копировать в собственные структуры приложения.
  • Конкурентный доступ: поскольку обе функции уведомления помечены как non_threadsafe ([SWS_TS_00421], [SWS_TS_00423]), одновременный вызов из нескольких потоков представляет собой нарушение предусловия. Вызовы, вероятно, производятся синхронно фреймворком; если реализация модифицирует внутренние структуры данных, она должна принять собственные меры по синхронизации.
