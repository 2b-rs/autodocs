Служит интерфейсом для приложений для проверки и выполнения сбросов ЭБУ по UDS в Diagnostic Management.

Класс ara::diag::EcuResetRequest представляет интерфейс приложения для обработки служб сброса UDS (Service 0x11) в Diagnostic Management AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.1. После активации с помощью Offer() он принимает запросы на проверку и выполнение перезапусков, а также на управление Rapid Shutdown ([SWS_DM_01016], [SWS_DM_01013], [SWS_DM_01014]). Экземпляры не поддерживают ни копирование, ни перемещение, и все методы специфицированы как непотокобезопасные ([SWS_DM_01010], [SWS_DM_01621]).

Контекст

Интерфейсный класс ara::diag::EcuResetRequest служит для обработки службы UDS ECUReset (Service 0x11) в AUTOSAR Adaptive Platform AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.1 «Service 0x11 – ECUReset – RapidPowerShutdown sub function». Он позволяет приложению выступать в качестве обработчика запросов на сброс от Diagnostic Management (DM). К задачам относятся активация или деактивация быстрого завершения работы ([SWS_DM_01012]), проверка входящих запросов на сброс ([SWS_DM_01013]), а также фактическое выполнение перезапуска ([SWS_DM_01014]). Участвующими сторонами взаимодействия являются внешний диагностический тестер, экземпляр Diagnostic Management (DM или Diagnostic Server) и реализация EcuResetRequest на стороне приложения.

Контекстная диаграмма: взаимодействие между диагностическим тестером, Diagnostic Management (DM) и приложением-обработчиком. Источники: AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.1, AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2, [SWS_DM_01010], [SWS_DM_01016].

Жизненный цикл

Экземпляр EcuResetRequest создается с помощью явного конструктора с указанием ara::core::InstanceSpecifier, ссылающегося на PortPrototype элемента DiagnosticEcuResetInterface ([SWS_DM_01010]). Согласно проектным требованиям, класс не поддерживает ни копирование, ни перемещение; конструкторы копирования и перемещения ([SWS_DM_01621], [SWS_DM_01622]), а также соответствующие операторы присваивания ([SWS_DM_01619], [SWS_DM_01620]) явно удалены (=delete). Все методы интерфейса, а также деструктор ([SWS_DM_01011]) специфицированы как not thread-safe ([SWS_DM_01010], [SWS_DM_01016], [SWS_DM_01017]). После инициализации обработчик сначала находится в состоянии, в котором пересылка запросов не происходит, пока регистрация не будет явно активирована с помощью Offer() ([SWS_DM_01016]). Вызовом StopOffer() пересылка запросов снова деактивируется ([SWS_DM_01017]), прежде чем объект может быть уничтожен ([SWS_DM_01011]).

Диаграмма состояний: фазы жизненного цикла и состояния регистрации экземпляра EcuResetRequest. Источники: [SWS_DM_01010], [SWS_DM_01016], [SWS_DM_01017], [SWS_DM_01011].

Путь использования

Типичный сценарий использования делится на инициализацию, включение и последующую обработку диагностических запросов:

  1. Инстанцирование и включение: приложение инстанцирует производный класс с подходящим InstanceSpecifier ([SWS_DM_01010]) и вызывает Offer(), чтобы позволить DM пересылать запросы ([SWS_DM_01016]).
  2. Управление Rapid Shutdown: если DM получает запрос UDS для EnableRapidPowerShutdown или DisableRapidPowerShutdown, он вызывает EnableRapidShutdown(enable, metaInfo, cancellationHandler) ([SWS_DM_01020], [SWS_DM_01021], [SWS_DM_01012]). При положительном подтверждении DM подставляет сконфигурированное значение времени отключения в ответ (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.1 [SWS_DM_01092]).
  3. Запрос на сброс: для всех остальных подфункций сброса UDS DM вызывает метод RequestReset(resetType, id, metaInfo, cancellationHandler) ([SWS_DM_01013]). Инстанцирующий процесс должен тщательно проверить, допустим ли перезапуск частей машины или всей машины в целом ([SWS_DM_01013]). Через cancellationHandler можно запросить статус отмены или зарегистрировать нотификатор ([SWS_DM_01013]).
  4. Выполнение сброса: если запрос принят и сконфигурирована отправка положительного ответа до сброса (respondBeforeReset или отсутствует), Diagnostic Server отправляет положительный ответ UDS и затем вызывает ExecuteReset(metaInfo) (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2 [SWS_DM_01023], [SWS_DM_01014]). Если вместо этого было сконфигурировано respondAfterReset, положительный ответ отправляется обратно только после перезапуска, при условии, что RequestReset() не сообщил об ошибке (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2 [SWS_DM_00360]).
  5. Отмена регистрации службы: для прекращения пересылки службы приложение вызывает StopOffer() ([SWS_DM_01017]).

Диаграмма последовательности: выполнение запроса EcuReset с подтверждением перед выполнением сброса (respondBeforeReset). Источники: [SWS_DM_01016], [SWS_DM_01013], [SWS_DM_01014], AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2 [SWS_DM_01023].

Сценарии ошибок

В случае ошибки при различных вызовах необходимо учитывать следующие аспекты:

  • Нарушения в конструкторе: при создании могут возникать нарушения модели, в частности, если InstanceSpecifier не может быть разрешен в модели (InstanceSpecifierMappingIntegrityViolation), ссылается на неверный элемент модели, отсутствует привязка к порту (PortInterfaceMappingViolation), отсутствует связь с процессом (ProcessMappingViolation) или идентификатор уже используется в процессе (InstanceSpecifierAlreadyInUseViolation) ([SWS_DM_01010]).
  • Ошибки регистрации: если Offer() вызывается, когда служба уже предлагается, метод возвращает ara::core::Result с кодом ошибки DiagOfferErrc::kAlreadyOffered ([SWS_DM_01016]).
  • Диагностические коды ошибок (NRC): если EnableRapidShutdown, RequestReset или ExecuteReset не могут быть успешно завершены, возвращаемые ими Future возвращают ошибку с соответствующим кодом отрицательного ответа ISO 14229-1 (NRC) через DiagUdsNrcErrc ([SWS_DM_01012], [SWS_DM_01013], [SWS_DM_01014]). Следует учитывать: если respondToReset установлено в respondBeforeReset или не сконфигурировано, ошибка в ExecuteReset() больше не влияет на диагностический ответ, поскольку положительное подтверждение уже было отправлено тестеру ранее ([SWS_DM_01014], AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2 [SWS_DM_01023]).

Настоящее руководство основано исключительно на спецификациях AUTOSAR Adaptive Platform R25-11.

              Использование и контекст вызова
              

              Чисто виртуальный метод EnableRapidShutdown класса ara::diag::EcuResetRequest служит интерфейсом для обработки субфункций UDS для быстрого завершения работы ([SWS_DM_01012]). При входящих диагностических запросах службы 0x11 (ECUReset) Diagnostic Manager (DM) вызывает эту функцию: для EnableRapidPowerShutdown с аргументом enable = true ([SWS_DM_01020]), а для DisableRapidPowerShutdown — с enable = false ([SWS_DM_01021]). Это отличает обе эти субфункции от всех остальных служб ECUReset, которые вместо этого инициируют RequestReset ([SWS_DM_00235]).
              

              Метод принимает три параметра ([SWS_DM_01012]):
              

                

              • enable: активирует быстрое завершение работы при true и деактивирует его при false.
                • 

              • metaInfo: передает метаинформацию о диагностическом запросе.
                • 

              • cancellationHandler: служит для контроля статуса отмены через cancellationHandler.IsCanceled() или регистрации нотификатора через cancellationHandler.SetNotifier() на случай прерывания текущей диагностической сессии.
                • 

              

              Семантика, обработка ошибок и параллелизм
              

              Интерфейс возвращает ara::core::Future<void>; таким образом, фактическая обработка, предположительно, выполняется асинхронно в фоновом режиме ([SWS_DM_01012]). В случае успеха future не возвращает значения. В случае ошибки необходимо установить подходящий Negative Response Code (NRC) согласно ISO 14229-1 с помощью DiagUdsNrcErrc (AUTOSAR_AP_SWS_Diagnostics §8.16.3.1.3.1 «EnableRapidShutdown»). Функция специфицирована как noexcept и безопасная относительно исключений (exception safe), однако считается непотокобезопасной (not thread-safe), из-за чего параллельных вызовов на одном и том же экземпляре необходимо избегать на стороне приложения ([SWS_DM_01012]).
