Контекст

Класс ara::diag::GenericUDSService представляет собой общий сервисный интерфейс для обработки диагностики в стандарте AUTOSAR Adaptive. Он служит прикладной основой для обработки диагностических запросов UDS (Unified Diagnostic Services), для которых не смоделированы и не используются специализированные сервисные классы.

В общей системе ara::diag::GenericUDSService функционирует на стыке следующих компонентов:

  • Diagnostic Management (DM): центральная диагностическая подсистема AUTOSAR Adaptive Platform принимает диагностические сообщения внешних диагностических тестеров и после успешной разблокировки пересылает их зарегистрированному обработчику сервиса [SWS_DM_00619] [SWS_DM_00620].
  • Специфичный для приложения обработчик сервиса: конкретное приложение наследуется от GenericUDSService и реализует чисто виртуальный метод HandleMessage, чтобы проанализировать фактическую полезную нагрузку запроса UDS и сформировать ответ [SWS_DM_00618].
  • Моделирование платформы: сопоставление с конечными точками связи выполняется декларативно через ara::core::InstanceSpecifier, который указывает на смоделированный PortPrototype для DiagnosticGenericUdsInterface [SWS_DM_00616].

Жизненный цикл

Создание экземпляра GenericUDSService осуществляется через явный конструктор с указанием ara::core::InstanceSpecifier, а также поведения конкурентности ConcurrencyType [SWS_DM_00616]:

  • Режим конкурентности: через ConcurrencyType::kConcurrent или ConcurrencyType::kNotConcurrent вызывающая сторона определяет, должна ли последующая обработка в HandleMessage осуществляться потокобезопасно или непотокобезопасно [SWS_DM_00616] [SWS_DM_00618].
  • Проверки модели: конструктор проверяет корректность сопоставления портов, привязку к процессу, а также то, используется ли спецификатор уже внутри процесса [SWS_DM_00616].

С точки зрения семантики и отношений владения GenericUDSService определен как уникальный экземпляр. Конструкторы копирования и перемещения, а также соответствующие операторы присваивания явно удалены (=delete) [SWS_DM_01657] [SWS_DM_01658] [SWS_DM_01655] [SWS_DM_01656].

Операционный жизненный цикл делится на два основных состояния:

  1. NichtAngeboten (начальное состояние): после конструирования пересылка через Diagnostic Management деактивирована.
  2. Предложено: вызовом Offer() экземпляр разрешает DM доставлять входящие UDS-сообщения [SWS_DM_00619].
  3. Возврат в NichtAngeboten: с помощью StopOffer() пересылка во время работы снова блокируется [SWS_DM_00620].

Деструктор является виртуальным и объявлен как noexcept [SWS_DM_00584]. В то время как сам конструктор потокобезопасен, Offer(), StopOffer() и деструктор не являются потокобезопасными (not thread-safe) [SWS_DM_00616] [SWS_DM_00619] [SWS_DM_00620] [SWS_DM_00584]. Перед уничтожением объекта сервиса пересылка, вероятно, должна быть явно завершена через StopOffer() (интерпретация).

Диаграмма состояний: жизненный цикл и состояния регистрации GenericUDSService. Источники: [SWS_DM_00616], [SWS_DM_00619], [SWS_DM_00620], [SWS_DM_00584].

Путь использования

Типичное использование GenericUDSService включает конфигурацию, предоставление и асинхронный ответ на запросы UDS:

  1. Инициализация и запуск: приложение инстанциирует производный класс с подходящим InstanceSpecifier и запускает готовность сервиса с помощью Offer() [SWS_DM_00616] [SWS_DM_00619].
  2. Входящий запрос: как только поступает UDS-запрос, Diagnostic Management делегирует его в HandleMessage(sid, requestData, metaInfo, cancellationHandler) [SWS_DM_00618]:
    • sid возвращает идентификатор сервиса UDS (Service Identifier).
    • requestData предоставляет данные запроса после SID в виде ara::core::Span. Данные остаются действительными до тех пор, пока не будет выполнено соответствующее обещание (Promise) или обработка не будет отменена [SWS_DM_00618].
    • metaInfo содержит контекстную информацию о запросе.
    • cancellationHandler позволяет проверить отмену через IsCanceled() или зарегистрировать функцию-оповещатель через SetNotifier [SWS_DM_00618].
  3. Возврат результата: метод возвращает ara::core::Future<OperationOutput>. При успешной обработке результат содержит полезную нагрузку ответа в OperationOutput, в противном случае — код диагностической ошибки [SWS_DM_00618].
  4. Отмена регистрации: при завершении работы компонента приложение вызывает StopOffer(), чтобы остановить пересылку сообщений [SWS_DM_00620].

Диаграмма последовательности: порядок вызовов и взаимодействия при обработке сообщений UDS. Источники: [SWS_DM_00616], [SWS_DM_00618], [SWS_DM_00619], [SWS_DM_00620].

Сценарии ошибок

При использовании GenericUDSService на различных уровнях могут возникать состояния ошибок:

  • Неправильная конфигурация при инстанцировании: конструктор объявлен как noexcept, однако при недопустимых конфигурациях приводит к архитектурным нарушениям (Violations) [SWS_DM_00616]:
    • InstanceSpecifierMappingIntegrityViolation: Идентификатор не может быть разрешен в модели или не ссылается на PortPrototype.
    • PortInterfaceMappingViolation: Порт с типом DiagnosticGenericUdsInterface не связан через DiagnosticServiceGenericMapping.
    • ProcessMappingViolation: в модели выполнения подходящий процесс не найден.
    • InstanceSpecifierAlreadyInUseViolation: идентификатор уже использовался в том же процессе для вызова конструктора.
  • Служба уже предложена: если Offer() вызывается многократно без промежуточного StopOffer(), вызов завершается с ошибкой и возвращает ara::core::Result с кодом ошибки DiagOfferErrc::kAlreadyOffered (с сохранением семантики отката) [SWS_DM_00619].
  • Отрицательные ответы UDS (Negative Response Codes): если обработка UDS-сообщения в HandleMessage завершается сбоем, обработчик должен передать в возвращаемом ara::core::Future подходящий UDS-NRC согласно ISO 14229-1 через тип ошибки DiagUdsNrcErrc [SWS_DM_00618].

Данное руководство основано исключительно на спецификации AUTOSAR для Adaptive Platform (Release R25-11, модуль diag).
