Контекст

Класс ara::diag::DiagOfferErrorDomain функционирует в AUTOSAR Adaptive как специализированный домен ошибок для ошибок, возникающих в связи с предложением и предоставлением диагностических сервисов (Diagnostic Offers) (AUTOSAR_AP_SWS_Diagnostics §8.11.5 «Class: DiagOfferErrorDomain», [SWS_DM_00989]). Данный класс специфицирован как final и напрямую наследуется от фундаментального базового класса платформы ara::core::ErrorDomain. Его основная ответственность заключается в семантической инкапсуляции кодов ошибок, связанных с offer, их сопоставлении с информативными текстовыми сообщениями, а также в генерации типобезопасных исключений по мере необходимости.

В рамках диагностической архитектуры DiagOfferErrorDomain взаимодействует с прикладными модулями и общей инфраструктурой обработки ошибок AUTOSAR Adaptive. Состояния ошибок при предложении сервисов обычно передаются через экземпляры ara::core::ErrorCode, которые ссылаются на домен ошибок ([SWS_DM_00995]). Для типизированного определения состояний ошибок класс включает базовый перечислимый тип DiagOfferErrc через псевдоним типа Errc ([SWS_DM_00990]). Для потоков управления на основе исключений он предоставляет доменно-специфичное базовое исключение DiagException через псевдоним типа Exception ([SWS_DM_00991]).

Контекстная диаграмма: взаимодействие логики приложения, домена ошибок DiagOfferErrorDomain, кода ошибки и типов исключений. Источники: [SWS_DM_00989], [SWS_DM_00990], [SWS_DM_00991], [SWS_DM_00995], AUTOSAR_AP_SWS_Diagnostics §8.11.5 «Class: DiagOfferErrorDomain»

Жизненный цикл

Создание экземпляра DiagOfferErrorDomain выполняется через стандартный конструктор без параметров constexpr DiagOfferErrorDomain() noexcept; (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.1 «Special Member Functions», [SWS_DM_00992]). Поскольку конструктор объявлен как constexpr и noexcept, создание может происходить уже во время компиляции без выделения динамической памяти и без возможности возникновения исключений времени выполнения ([SWS_DM_00992]).

Что касается отношений владения, класс не содержит изменяемого состояния. Интерпретация: экземпляры DiagOfferErrorDomain, вероятно, хранятся на типичных Adaptive Platform как долгоживущие глобальные или статические синглтоны, поэтому ручное управление жизненным циклом со стороны вызывающего кода не требуется. Уничтожение является бессостоятельным и не требует освобождения ресурсов операционной системы. Все функции-члены класса явно специфицированы как потокобезопасные (thread-safe) ([SWS_DM_00992], [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995]), благодаря чему к экземплярам можно без проблем обращаться из нескольких параллельных потоков без внешней синхронизации.

Путь использования

Практическое применение DiagOfferErrorDomain сосредоточено на оценке и преобразовании значений ошибок при сбойных диагностических операциях:

  • Запрос имени домена: через функцию-член Name() можно получить символический краткий идентификатор (Shortname) домена ошибок (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2 «Member Functions», [SWS_DM_00993]). Возвращаемое значение представляет собой const char *, вызов безопасен относительно исключений (exception safe) и не генерирует исключений ([SWS_DM_00993]).
  • Преобразование кодов ошибок: если вызывающий компонент получает код ошибки в рамках предложения диагностики, числовое значение ошибки типа ara::core::ErrorDomain::CodeType преобразуется с помощью Message(errorCode) в текстовое описание ([SWS_DM_00994]).
  • Гарантированная валидность сообщения об ошибке: возвращаемый указатель Message() указывает на нуль-терминированную строку и, согласно спецификации, гарантированно никогда не равен nullptr ([SWS_DM_00994]). Поэтому диагностические логгеры и модули приложений могут обрабатывать сообщение без дополнительной проверки на нулевой указатель.

Сценарии ошибок

Для передачи ошибок в архитектурах с обработкой исключений домен реализует виртуальную функцию ThrowAsException(errorCode) ([SWS_DM_00995]). Этот метод принимает ссылку на ara::core::ErrorCode и генерирует соответствующее значению ошибки исключение типа Exception или DiagException ([SWS_DM_00995], [SWS_DM_00991]).

Поскольку ThrowAsException() по своей конструкции генерирует исключение, метод объявлен с noexcept(false) и классифицирован как небезопасный относительно исключений (not exception safe) ([SWS_DM_00995]). Существенным аспектом конфигурации является поддержка цепочек инструментов без исключений C++: если исключения C++ отключены в цепочке инструментов компилятора, ThrowAsException() не участвует в разрешении перегрузки ([SWS_DM_00995]). В таких окружениях обработка ошибок детерминированно сводится к проверке кодов ошибок через псевдоним Errc (DiagOfferErrc) и соответствующие капсулы ошибок ([SWS_DM_00990]).

Настоящее руководство основано на спецификации AUTOSAR AP R25-11 (модуль diag) и обобщает архитектуру, жизненный цикл и обработку ошибок класса DiagOfferErrorDomain.
