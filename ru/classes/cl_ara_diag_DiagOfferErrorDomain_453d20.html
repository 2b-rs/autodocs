Управляет и преобразует коды ошибок и исключения для предложений диагностики в модуле diag.

Класс ara::diag::DiagOfferErrorDomain представляет стандартизированный домен ошибок для сбоев при предоставлении диагностических служб в AUTOSAR Adaptive Platform [SWS_DM_00989]. Будучи специализацией базового класса ara::core::ErrorDomain, он сопоставляет числовым кодам ошибок типа DiagOfferErrc читаемые текстовые сообщения и поддерживает преобразование в объекты исключений типа DiagException [SWS_DM_00994]. Все функции-члены выполнены потокобезопасными, тогда как генерация исключений не участвует в разрешении перегрузки при отключенных в компиляторе исключениях C++.

Контекст

Класс ara::diag::DiagOfferErrorDomain определяет специфический домен ошибок для состояний ошибок, возникающих в связи с предложениями диагностики (Diagnostic Offers) в модуле diag AUTOSAR Adaptive [SWS_DM_00989]. Будучи финальным классом, он специализирует общий платформенный класс ara::core::ErrorDomain (AUTOSAR_AP_SWS_Diagnostics §8.11.5 «Class: DiagOfferErrorDomain»). Его основная обязанность заключается в типизированном представлении ошибочных состояний при предложении диагностических служб и предоставлении стандартизированного интерфейса для текстового описания и обработки исключений.

В рамках архитектуры ошибок ara::diag::DiagOfferErrorDomain тесно взаимодействует с ara::core::ErrorCode: сбойные операции создают экземпляры кодов ошибок, связывающие соответствующее значение перечисления с доменом ошибок. Для этого класс предоставляет псевдоним типа Errc, ссылающийся на тип перечисления DiagOfferErrc [SWS_DM_00990]. Для обеспечения отказоустойчивого потока управления класс устанавливает связь с базовым классом исключений DiagException через псевдоним типа Exception [SWS_DM_00991].

Контекстная диаграмма: встраивание DiagOfferErrorDomain в архитектуру ошибок ara::diag и ara::core. Источники: [SWS_DM_00989], [SWS_DM_00990], [SWS_DM_00991].

Жизненный цикл

Создание экземпляра ara::diag::DiagOfferErrorDomain выполняется через конструктор по умолчанию без параметров, который определен как constexpr и noexcept [SWS_DM_00992]. Этот конструктор находится в заголовочном файле ara/diag/diag_error_domain.h (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.1.1 «Default Constructor»). Благодаря спецификации constexpr объект домена может быть сконструирован уже во время компиляции. В AUTOSAR-системах домен ошибок, как правило, содержится в виде доступного на уровне процесса статического объекта или синглтона, поэтому динамические выделения памяти не требуются.

Все функции-члены класса без исключения объявлены как потокобезопасные (thread-safe) [SWS_DM_00992], [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995]. Это обеспечивает безопасный параллельный доступ из нескольких потоков. Поскольку класс объявлен как final, создание производных классов запрещено. Уничтожение не подчиняется каким-либо особым требованиям и происходит при освобождении статической памяти при завершении работы приложения.

Путь использования

Класс обычно используется косвенно через ara::core::ErrorCode или напрямую при обработке результатов диагностических операций:

  1. Операция при предоставлении диагностической службы завершается сбоем, после чего создается ara::core::ErrorCode со значением типа DiagOfferErrc (псевдоним Errc) [SWS_DM_00990].
  2. Для идентификации домена может быть вызван метод Name(), возвращающий идентификатор домена ошибок приложения [SWS_DM_00993] (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.2 «Name»).
  3. Чтобы получить читаемое сообщение об ошибке для целей протоколирования или диагностики, вызывается Message() с кодом ошибки; возвращаемая C-строка согласно спецификации никогда не бывает nullptr [SWS_DM_00994].
  4. Если архитектура программного обеспечения обрабатывает ошибки с помощью исключений, вызывается ThrowAsException() с ErrorCode, что инициирует выброс соответствующего исключения [SWS_DM_00995].

Диаграмма последовательности: типичный запрос сообщений об ошибках и выброс исключений через DiagOfferErrorDomain. Источники: [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995].

Сценарии ошибок

Сам домен не сообщает о внутренних ошибках, а служит для классификации внешних ошибок при предоставлении диагностической функциональности. Конкретные условия ошибок выражаются через тип перечисления DiagOfferErrc, жестко закрепленный за доменом через Errc [SWS_DM_00990]. Предположительно, эти значения ошибок охватывают ситуации конфигурации или конфликтов при регистрации диагностических служб.

Функция-член Message() гарантированно безопасна относительно исключений (exception safe) и возвращает корректное текстовое сообщение для каждого переданного значения ошибки [SWS_DM_00994]. Напротив, ThrowAsException() классифицируется как небезопасная относительно исключений (not exception safe) и помечена как noexcept(false), поскольку ее явной задачей является выброс исключения базового типа DiagException (псевдоним Exception) [SWS_DM_00991], [SWS_DM_00995].

Центральное граничное условие существует на платформах или в конфигурациях компилятора без поддержки исключений: если исключения C++ отключены в тулчейне, функция ThrowAsException() не участвует в разрешении перегрузок [SWS_DM_00995]. В этом случае приложение должно выполнять обработку ошибок исключительно на основе значений через коды ошибок.

Настоящее руководство основано на спецификации AUTOSAR Adaptive R25-11 и создано автоматически.

Конструктор по умолчанию без параметров [SWS_DM_00992] служит для создания экземпляра класса ara::diag::DiagOfferErrorDomain (SWS Diagnostics §8.11.5 «Class: DiagOfferErrorDomain»). Он объявлен через заголовочный файл ara/diag/diag_error_domain.h и имеет сигнатуру constexpr DiagOfferErrorDomain() noexcept; (SWS Diagnostics §8.11.5.2.1.1 «Default Constructor»). Вызов выполняется синхронно, не обрабатывает входных параметров и, типично для конструктора, не имеет возвращаемого значения [SWS_DM_00992].

В отношении параллелизма и отказоустойчивости функция специфицирована как thread-safe, а также exception safe [SWS_DM_00992]. Спецификацией noexcept гарантируется, что во время выполнения исключения не генерируются [SWS_DM_00992]. Специфические коды ошибок или уведомления через DET либо DEM для этого конструктора не предусмотрены.

В контексте модуля домен представляет ошибочные состояния, связанные с диагностическими службами, коды ошибок которых определены в перечислении DiagOfferErrc [SWS_DM_00559] и могут быть сосланы через псевдоним типа Errc [SWS_DM_00990]. Класс предоставляет стандартные методы, такие как Name() [SWS_DM_00993], Message() [SWS_DM_00994] и ThrowAsException() [SWS_DM_00995]. В практических сценариях прямой вызов конструктора вряд ли потребуется (интерпретация), поскольку с помощью функции ara::diag::GetDiagOfferDomain() уже доступна глобальная ссылка на экземпляр [SWS_DM_01003], используемая, среди прочего, в ara::diag::MakeErrorCode() [SWS_DM_01005].

          • Контекст вызова и параметры: вызов выполняется синхронно, без параметров и без предварительных условий непосредственно на экземпляре ara::diag::DiagOfferErrorDomain ([SWS_DM_00993]).
            • 
    
          • Возвращаемое значение: функция возвращает const char*, который представляет идентификатор ApApplicationErrorDomain.SN домена ошибок ([SWS_DM_00993]).             • 
    
          • Обработка ошибок: метод объявлен как noexcept и специфицирован как exception safe ([SWS_DM_00993]). Он не сообщает о кодах ошибок и не генерирует исключений.
            • 
    
          • Параллелизм: выполнение классифицировано как thread-safe ([SWS_DM_00993]), поэтому параллельные вызовы из нескольких потоков допустимы без внешней синхронизации.
