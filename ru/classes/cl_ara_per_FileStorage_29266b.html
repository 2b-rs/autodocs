Управляет персистентными файлами и открывает их через дескрипторы на основе RAII для блочного чтения и записи.

Класс ara::per::FileStorage позволяет управлять и открывать набор сконфигурированных персистентных файлов по уникальным именам файлов [SWS_PER_00110]. Фактический доступ для чтения и записи осуществляется через аксессоры, управляемые по принципу UniqueHandle, которые автоматически закрывают файл при выходе из области видимости [SWS_PER_00114]. Поскольку уже открытые файлы защищены от конфликтующих операций удаления или восстановления, такие параллельные обращения завершаются с ошибкой PerErrc::kResourceBusy [SWS_PER_00111].

Контекст

Класс ara::per::FileStorage инкапсулирует доступ к сконфигурированной коллекции персистентных файлов, идентифицируемых по уникальным именам файлов. Он выступает в качестве центрального интерфейса для приложений при выполнении файловых операций, таких как получение списка существующих файлов через GetAllFileNames [SWS_PER_00110], проверка на существование с помощью FileExists [SWS_PER_00112], а также опрос метаданных и размеров файлов через GetFileInfo [SWS_PER_00438] и GetCurrentFileSize [SWS_PER_00407]. Прямой доступ на чтение или запись на уровне байтов при этом выполняется не на самом экземпляре хранилища, а через специальные объекты-аксессоры, предоставляемые методами открытия как UniqueHandle [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00115].

Жизненный цикл

Инстанцирование FileStorage подчиняется строгим ограничениям: конструктор по умолчанию [SWS_PER_00460], конструкторы копирования и перемещения [SWS_PER_00328] [SWS_PER_00326], а также операторы присваивания с копированием и перемещением [SWS_PER_00329] [SWS_PER_00327] явно удалены. Экземпляр FileStorage, следовательно, обычно открывается и предоставляется платформенными фабричными функциями модуля персистентности. Деструктор ~FileStorage является безопасным относительно исключений (noexcept), однако явно специфицирован как непотокобезопасный [SWS_PER_00330], поэтому должно быть обеспечено отсутствие параллельных вызовов объекта во время уничтожения.

В процессе работы обычные файловые операции, такие как FileExists, DeleteFile или открытие файлов, спроектированы как потокобезопасные [SWS_PER_00111] [SWS_PER_00112] [SWS_PER_00114]. Однако следует учитывать, что результаты запросов статуса, таких как GetAllFileNames [SWS_PER_00110] или FileExists [SWS_PER_00112], обладают точной достоверностью только тогда, когда в другом потоке одновременно не добавляются и не удаляются файлы. Аналогичное относится к GetFileInfo: время модификации и доступа, а также статус обработки являются надежно точными только до тех пор, пока целевой файл не открыт [SWS_PER_00438].

Путь использования

Типичный сценарий использования включает проверку, выборочное открытие, обработку данных через дескриптор аксессора и последующую очистку:

  1. Проверка статуса файла: перед доступом можно опционально выяснить через FileExists, существует ли требуемый файл [SWS_PER_00112], или запросить список файлов через GetAllFileNames [SWS_PER_00110].
  2. Открытие файла: в зависимости от предполагаемого режима доступа класс предоставляет специализированные методы. Для доступа только для чтения доступны перегрузки OpenFileReadOnly [SWS_PER_00114] [SWS_PER_00376] [SWS_PER_00430]. Для доступа на чтение и запись служит OpenFileReadWrite [SWS_PER_00113] [SWS_PER_00375] [SWS_PER_00429], при этом несуществующий файл создается автоматически. Для записи только служит OpenFileWriteOnly [SWS_PER_00115] [SWS_PER_00377] [SWS_PER_00431], который по умолчанию усекает файл (kTruncate) или создает его заново. Для повышения производительности при множестве мелких обращений перегрузки позволяют передавать пользовательский буфер для блочного чтения или записи [SWS_PER_00430] [SWS_PER_00429] [SWS_PER_00431].
  3. Закрытие файла и освобождение ресурсов: возвращаемый методами открытия ara::core::Result инкапсулирует UniqueHandle на соответствующий аксессор. Файл автоматически закрывается, как только этот UniqueHandle покидает свою область видимости [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00115]. Предположительно, при этом также снимается файловая отметка занятости в FileStorage.
  4. Обслуживание и очистка: больше не требующиеся файлы удаляются с помощью DeleteFile [SWS_PER_00111]. При нарушениях целостности RecoverFile обеспечивает восстановление избыточных данных по мере возможностей (Best-Effort) [SWS_PER_00337], тогда как ResetFile сбрасывает файл до его исходного содержимого развертывания или создает заново при его отсутствии [SWS_PER_00338].

Диаграмма последовательности: типичный процесс от проверки и открытия файла через буферизованную обработку до автоматического закрытия по выходу дескриптора из области видимости. Источники: [SWS_PER_00112], [SWS_PER_00430], [SWS_PER_00114], [SWS_PER_00111].

Сценарии ошибок

Методы FileStorage сигнализируют об ошибках через ara::core::Result с использованием перечисления ошибок PerErrc. К наиболее важным ошибочным ситуациям относятся:

  • Конфликты ресурсов (PerErrc::kResourceBusy): файл не может быть открыт, удален, восстановлен или сброшен, если он уже открыт или параллельно выполняется DeleteFile, RecoverFile либо ResetFile для того же имени файла [SWS_PER_00111] [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00337] [SWS_PER_00338].
  • Файлы не найдены (PerErrc::kFileNotFound): возникает, если несуществующий файл пытаются открыть только для чтения [SWS_PER_00114], удалить [SWS_PER_00111], запросить [SWS_PER_00407] [SWS_PER_00438] или восстановить [SWS_PER_00337].
  • Нарушения доступа и полномочий: попытки открытия на запись или операции удаления завершаются с ошибкой PerErrc::kIllegalWriteAccess, если хранилище сконфигурировано только для чтения (read-only) [SWS_PER_00111] [SWS_PER_00113] [SWS_PER_00115]. Недопустимые комбинации режимов отклоняются с ошибкой PerErrc::kInvalidOpenMode [SWS_PER_00114] [SWS_PER_00113].
  • Ограничения памяти и квоты: при создании нового файла или увеличении размера могут возникать PerErrc::kOutOfStorageSpace (физическая память заполнена), PerErrc::kTooManyFiles (превышение maxNumberOfFiles) или PerErrc::kQuotaExceeded (превышение maximumAllowedSize) [SWS_PER_00113] [SWS_PER_00337] [SWS_PER_00338].
  • Ошибки целостности и безопасности: при сбоях физического уровня хранения сообщается PerErrc::kPhysicalStorageFailure. Поврежденные структуры данных, неудачные проверки валидности или криптографические проблемы приводят к PerErrc::kIntegrityCorrupted, PerErrc::kValidationFailed, PerErrc::kEncryptionFailed или PerErrc::kAuthenticationFailed [SWS_PER_00110] [SWS_PER_00112] [SWS_PER_00114] [SWS_PER_00337].
  • Отсутствие исходных данных (PerErrc::kInitValueNotAvailable): завершается ошибкой при сбросе через ResetFile, если начальные значения не были заданы ни в Application Design, ни в целевой конфигурации [SWS_PER_00338].

Синхронный метод DeleteFile класса ara::per::FileStorage удаляет файл по его имени (fileName) из файлового хранилища [SWS_PER_00111]. Идентификатор может соответствовать сконфигурированному PersistencyFile.fileName [SWS_PER_00111]. Вызов специфицирован как noexcept, считается безопасным к исключениям, а также потокобезопасным и сообщает о результате через ara::core::Result<void> [SWS_PER_00111].

Перед вызовом должны быть завершены все активные обращения к целевому файлу. Если файл в данный момент открыт, операция удаления завершается ошибкой PerErrc::kResourceBusy [SWS_PER_00111]. Поэтому приложения должны гарантировать, что экземпляры UniqueHandle, созданные ранее через OpenFileReadWrite [SWS_PER_00113], OpenFileReadOnly [SWS_PER_00114] или OpenFileWriteOnly [SWS_PER_00115], вышли из своей области видимости, в результате чего файл закрывается. Аналогично параллельное выполнение RecoverFile [SWS_PER_00337] или ResetFile [SWS_PER_00338] для того же имени файла приводит к PerErrc::kResourceBusy [SWS_PER_00111].

В случае сбоя возвращаемый тип Result предоставляет конкретные причины ошибок [SWS_PER_00111]:

  • PerErrc::kFileNotFound: указанный файл не существует в файловом хранилище [SWS_PER_00111].
  • PerErrc::kIllegalWriteAccess: хранилище File Storage настроено только для чтения [SWS_PER_00111].
  • PerErrc::kPhysicalStorageFailure: доступ к физическому носителю данных завершается сбоем (без семантики отката) [SWS_PER_00111].
  • PerErrc::kIntegrityCorrupted, PerErrc::kEncryptionFailed или PerErrc::kAuthenticationFailed: ошибки структурной целостности, шифрования/дешифрования или проверки MAC (каждая с семантикой отката), а также ошибки, специфичные для производителя [SWS_PER_00111].
