Контекст

Класс ara::diag::DiagnosticSovdRecordContentElementDataConstView предоставляет интерфейс только для чтения (Const View) к диагностическим элементам содержимого SOVD типа Record ([SWS_DM_02295], AUTOSAR_AP_SWS_Diagnostics §8.60.9 «Class: DiagnosticSovdRecordContentElementDataConstView»). Он инкапсулирует доступ только для чтения к вложенным или табличным структурам данных в рамках фреймворка SOVD (Service-Oriented Vehicle Diagnostics) в модуле Adaptive Platform diag. В число партнеров по взаимодействию входят прикладные программные компоненты, анализирующие диагностический вывод, базовый элемент DiagnosticSovdContentElementData, а также итераторы типа DiagnosticSovdRecordContentElementDataConstIterator ([SWS_DM_02301], [SWS_DM_02306]). Заголовочным файлом для использования класса является ara/diag/diagnostic_sovd_content_element_data.h ([SWS_DM_02296]).

Жизненный цикл

Будучи классом-представлением (View), DiagnosticSovdRecordContentElementDataConstView не владеет данными самостоятельно, а ссылается на существующий DiagnosticSovdContentElementData, который должен иметь тип RecordContentElementData или ContentData ([SWS_DM_02298], [SWS_DM_02300]). Следовательно, время жизни данных, на которые указывает ссылка, должно по меньшей мере охватывать время использования представления (интерпретация: объект функционирует как легковесный указатель или ссылочный адаптер и не имеет собственного управления данными). Все задокументированные функции-члены специфицированы как безопасные относительно исключений (exception safe) и потокобезопасные (thread-safe) (с [SWS_DM_02296] по [SWS_DM_02306]). Благодаря этому несколько потоков могут параллельно выполнять операции чтения над наборами данных через один и тот же или отдельные экземпляры без необходимости использования дополнительных примитивов синхронизации в коде вызывающей стороны.

Путь использования

Типичный сценарий использования для инспекции набора данных включает следующие шаги:

  1. Проверка состояния ошибки: Перед доступом к содержимому с помощью HasError() проверяется, присутствуют ли базовые данные без ошибок ([SWS_DM_02296]).
  2. Запрос метаданных и степени заполнения: С помощью Empty() ([SWS_DM_02299]), Size() ([SWS_DM_02297]) и Capacity() ([SWS_DM_02298]) можно определить количество и емкость содержащихся элементов набора данных.
  3. Прямой доступ по ключу: Перед считыванием записи с помощью HasContentElement(key) можно проверить, существует ли элемент с указанным ключом ([SWS_DM_02305]). Затем доступ к данным осуществляется через оператор индексации operator[](key) ([SWS_DM_02300]), возвращающий ссылку на константный целевой элемент, или через функцию поиска Find(key) ([SWS_DM_02306]).
  4. Последовательная итерация: В качестве альтернативы индивидуальному поиску класс позволяет обойти все содержащиеся элементы данных с помощью пар итераторов Begin() / End() ([SWS_DM_02301], [SWS_DM_02302]) или CBegin() / CEnd() ([SWS_DM_02303], [SWS_DM_02304]).

Диаграмма последовательности: типичный процесс запроса содержимого SOVD-Record только для чтения через представление. Источники: [SWS_DM_02296], [SWS_DM_02305], [SWS_DM_02300], [SWS_DM_02301].

Сценарии ошибок

Методы класса используют стандартизированные механизмы обработки ошибок AUTOSAR Adaptive (ara::core::Result) для оповещения о недопустимых состояниях или неудачных операциях без использования исключений:

  • Ошибочное содержимое: Если запрос HasError() дает отрицательный результат, результат содержит системно-специфичный код ошибки ara::diag::DiagSovdErrc вместо успешного значения void ([SWS_DM_02296]).
  • Ключ не найден или неверный тип данных: Вызов HasContentElement(key) возвращает ошибочный ara::core::Result<bool>, если базовый DiagnosticSovdContentElementData не относится ни к типу RecordContentElementData, ни к типу ContentData, либо если искомый ключ не существует ([SWS_DM_02305]).
  • Ошибка доступа через оператор индексации: При доступе через operator[](key) возврат ara::core::Result<std::reference_wrapper<DiagnosticSovdContentElementData const>> завершается неудачей, если тип несовместим или указанный идентификатор отсутствует в наборе данных ([SWS_DM_02300]).

Настоящее руководство основано на требованиях и спецификациях AUTOSAR Adaptive Platform R25-11.

<h4>Контекст</h4>
<p>Класс <code>ara::diag::DiagnosticSovdRecordContentElementDataConstView</code> предоставляет интерфейс только для чтения (Const View) к диагностическим элементам содержимого SOVD типа Record (<a class="spec-record-ref" data-req="SWS_DM_02295" href="../spec/record.html?id=SWS_DM_02295">[SWS_DM_02295]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=828">AUTOSAR_AP_SWS_Diagnostics §8.60.9 «Class: DiagnosticSovdRecordContentElementDataConstView»</a>). Он инкапсулирует доступ только для чтения к вложенным или табличным структурам данных в рамках фреймворка SOVD (Service-Oriented Vehicle Diagnostics) в модуле Adaptive Platform <code>diag</code>. В число партнеров по взаимодействию входят прикладные программные компоненты, анализирующие диагностический вывод, базовый элемент <code>DiagnosticSovdContentElementData</code>, а также итераторы типа <code>DiagnosticSovdRecordContentElementDataConstIterator</code> (<a class="spec-record-ref" data-req="SWS_DM_02301" href="../spec/record.html?id=SWS_DM_02301">[SWS_DM_02301]</a>, <a class="spec-record-ref" data-req="SWS_DM_02306" href="../spec/record.html?id=SWS_DM_02306">[SWS_DM_02306]</a>). Заголовочным файлом для использования класса является <code>ara/diag/diagnostic_sovd_content_element_data.h</code> (<a class="spec-record-ref" data-req="SWS_DM_02296" href="../spec/record.html?id=SWS_DM_02296">[SWS_DM_02296]</a>).</p>

<h4>Жизненный цикл</h4>
<p>Будучи классом-представлением (View), <code>DiagnosticSovdRecordContentElementDataConstView</code> не владеет данными самостоятельно, а ссылается на существующий <code>DiagnosticSovdContentElementData</code>, который должен иметь тип <code>RecordContentElementData</code> или <code>ContentData</code> (<a class="spec-record-ref" data-req="SWS_DM_02298" href="../spec/record.html?id=SWS_DM_02298">[SWS_DM_02298]</a>, <a class="spec-record-ref" data-req="SWS_DM_02300" href="../spec/record.html?id=SWS_DM_02300">[SWS_DM_02300]</a>). Следовательно, время жизни данных, на которые указывает ссылка, должно по меньшей мере охватывать время использования представления (интерпретация: объект функционирует как легковесный указатель или ссылочный адаптер и не имеет собственного управления данными). Все задокументированные функции-члены специфицированы как безопасные относительно исключений (<em>exception safe</em>) и потокобезопасные (<em>thread-safe</em>) (с <a class="spec-record-ref" data-req="SWS_DM_02296" href="../spec/record.html?id=SWS_DM_02296">[SWS_DM_02296]</a> по <a class="spec-record-ref" data-req="SWS_DM_02306" href="../spec/record.html?id=SWS_DM_02306">[SWS_DM_02306]</a>). Благодаря этому несколько потоков могут параллельно выполнять операции чтения над наборами данных через один и тот же или отдельные экземпляры без необходимости использования дополнительных примитивов синхронизации в коде вызывающей стороны.</p>

<h4>Сценарии ошибок</h4>
<p>Методы класса используют стандартизированные механизмы обработки ошибок AUTOSAR Adaptive (<code>ara::core::Result</code>) для оповещения о недопустимых состояниях или неудачных операциях без использования исключений:</p>
<ul>
<li><strong>Ошибочное содержимое:</strong> Если запрос <code>HasError()</code> дает отрицательный результат, результат содержит системно-специфичный код ошибки <code>ara::diag::DiagSovdErrc</code> вместо успешного значения <code>void</code> (<a class="spec-record-ref" data-req="SWS_DM_02296" href="../spec/record.html?id=SWS_DM_02296">[SWS_DM_02296]</a>).</li>
<li><strong>Ключ не найден или неверный тип данных:</strong> Вызов <code>HasContentElement(key)</code> возвращает ошибочный <code>ara::core::Result&lt;bool&gt;</code>, если базовый <code>DiagnosticSovdContentElementData</code> не относится ни к типу <code>RecordContentElementData</code>, ни к типу <code>ContentData</code>, либо если искомый ключ не существует (<a class="spec-record-ref" data-req="SWS_DM_02305" href="../spec/record.html?id=SWS_DM_02305">[SWS_DM_02305]</a>).</li>
<li><strong>Ошибка доступа через оператор индексации:</strong> При доступе через <code>operator[](key)</code> возврат <code>ara::core::Result&lt;std::reference_wrapper&lt;DiagnosticSovdContentElementData const&gt;&gt;</code> завершается неудачей, если тип несовместим или указанный идентификатор отсутствует в наборе данных (<a class="spec-record-ref" data-req="SWS_DM_02300" href="../spec/record.html?id=SWS_DM_02300">[SWS_DM_02300]</a>).</li>
</ul>
