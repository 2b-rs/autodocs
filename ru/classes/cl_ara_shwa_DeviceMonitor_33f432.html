Контекст

Класс ara::shwa::DeviceMonitor является ключевым компонентом модуля shwa (Smart Hardware Access) в составе AUTOSAR Adaptive Platform. Его основная задача заключается в инкапсуляции, наблюдении и запросе состояния физического или логического аппаратного устройства (такого как датчики или исполнительные механизмы). Он гарантирует, что использующие его компоненты могут применять унифицированный и контролируемый интерфейс для мониторинга состояния.

Основными участниками взаимодействия являются запрашивающая логика приложения, а также соответствующая целевая система. Последняя подключается при создании экземпляра либо через ссылку на конкретный Device, либо обобщенно через объект DeviceSelector. После успешной конфигурации приложение взаимодействует с классом преимущественно для получения информации DeviceStatus.

Жизненный цикл

Создание экземпляров подчиняется строгим требованиям платформы. Конструктор по умолчанию недоступен; он явно удален ([AP_SWS_SHWA_01402]). Создание экземпляров осуществляется исключительно через статические фабричные методы:

  • Через прямую ссылку на устройство: Create(const Device& device) ([AP_SWS_SHWA_01407]).
  • Через шаблон с селектором: Create(const DeviceSelector& deviceSelector) ([AP_SWS_SHWA_01408]).

Оба пути создания потокобезопасны, не вызывают исключений и возвращают объект, инкапсулированный в ara::core::Result<DeviceMonitor>.

С точки зрения отношений владения DeviceMonitor реализован как полноценный тип-значение:

  • Как конструктор копирования ([AP_SWS_SHWA_01403]), так и оператор присваивания копированием ([AP_SWS_SHWA_01404]) объявлены как noexcept = default и безопасны относительно исключений.
  • Аналогично конструктор перемещения ([AP_SWS_SHWA_01405]) и оператор присваивания перемещением ([AP_SWS_SHWA_01406]) реализованы как noexcept = default.

Явный деструктор в интерфейсе не указан; поэтому уничтожение предположительно происходит по стандартному поведению компилятора (интерпретация). В отношении параллелизма действует следующее: хотя методы создания потокобезопасны, метод Status() явно специфицирован как not thread-safe ([AP_SWS_SHWA_01409]). При параллельном доступе к одному и тому же монитору приложение должно предусмотреть внешние механизмы синхронизации.

Путь использования

Типичный процесс использования DeviceMonitor включает подготовку целевого устройства, создание через фабричный интерфейс, валидацию результата, а также регулярный или инициируемый событиями запрос статуса:

  1. Создание: приложение вызывает ara::shwa::DeviceMonitor::Create(...) либо со ссылкой на Device ([AP_SWS_SHWA_01407]), либо с DeviceSelector ([AP_SWS_SHWA_01408]).
  2. Проверка результата: возвращенный ara::core::Result проверяется. В случае ошибки операция прерывается или инициируется обработка ошибок.
  3. Запрос состояния: при наличии значения приложение вызывает на экземпляре монитора метод Status() ([AP_SWS_SHWA_01409]), чтобы получить текущий DeviceStatus.

Диаграмма последовательности: типичная последовательность вызовов для создания экземпляра и запроса статуса устройства. Источники: [AP_SWS_SHWA_01407], [AP_SWS_SHWA_01409]

Сценарии ошибок

Класс использует отказоустойчивый паттерн проектирования AUTOSAR Adaptive Platform и сообщает об ошибках через ara::core::Result вместо исключений C++. Все методы специфицированы с noexcept и категорией гарантии exception safe.

Ошибки могут возникать в методах создания ([AP_SWS_SHWA_01407], [AP_SWS_SHWA_01408]). В этих случаях Create возвращает код ошибки из ShwaErrorCode:

  • ShwaErrorCode::kRuntime: общая ошибка времени выполнения во время инициализации монитора.
  • ShwaErrorCode::kResourceBusy: базовый аппаратный ресурс в данный момент занят и не может отслеживаться.
  • ShwaErrorCode::kInvalidParameter: переданный аргумент (например, недействительный идентификатор устройства или недействительный селектор) содержит ошибку.
  • ShwaErrorCode::kFeatureNotSupported: запрошенная функция мониторинга не поддерживается аппаратным обеспечением или драйвером.

Для этих случаев сбоя спецификация гарантирует семантику отката, благодаря чему при сбое Create не остается не полностью выделенных ресурсов. Запрос состояния Status(), напротив, возвращает непосредственно DeviceStatus без кода ошибки ([AP_SWS_SHWA_01409]); аппаратные сбои и нарушения связи, по всей видимости, отображаются через само значение состояния (интерпретация).

Данное руководство по классу составлено на основе спецификации AUTOSAR для модуля shwa (релиз R25-11).
