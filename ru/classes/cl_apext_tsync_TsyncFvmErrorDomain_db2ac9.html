Управляет кодами ошибок и исключениями Freshness Value Manager для потокобезопасного разрешения ошибок.

Класс apext::tsync::TsyncFvmErrorDomain представляет домен ошибок Freshness Value Manager в модуле tsync и сопоставляет кодам ошибок семантические описания, а также типы исключений [SWS_TS_14206]. Он обеспечивает потокобезопасный запрос специфичных для домена имен и сообщений об ошибках, а также адресную генерацию типизированных исключений при ошибках времени выполнения [SWS_TS_14211]. Если система компилируется без поддержки исключений C++, функция генерации исключений исключается из разрешения перегрузок.

Контекст

Класс apext::tsync::TsyncFvmErrorDomain представляет домен ошибок Freshness Value Manager (FVM) внутри модуля tsync платформы AUTOSAR Adaptive Platform. Являясь специализацией ara::core::ErrorDomain, он предоставляет семантический контекст для ошибочных состояний и диагностических сообщений, которые могут возникать при управлении значениями свежести и их валидации. С помощью псевдонимов типов Errc [SWS_TS_14206] и Exception [SWS_TS_14207] домен связывает специфическое перечисление TsyncFvmErrc, а также базовый тип исключения TsyncFvmException напрямую с доменом ошибок. Тем самым класс выступает в качестве связующего звена между подсистемами FVM, типовыми структурами обработки ошибок, такими как ara::core::ErrorCode, и использующими их компонентами синхронизации времени.

Жизненный цикл

Экземпляры apext::tsync::TsyncFvmErrorDomain создаются через конструктор по умолчанию [SWS_TS_14208]. Конструктор специфицирован как constexpr и noexcept, что обеспечивает безопасную относительно исключений инициализацию уже на этапе компиляции [SWS_TS_14208]. Освобождение осуществляется через виртуальный деструктор по умолчанию [SWS_TS_14201], который также объявлен как noexcept и является безопасным относительно исключений. Интерпретация: в качестве реализации домена ошибок AUTOSAR данный класс, вероятно, эксплуатируется как долгоживущий экземпляр, чтобы предоставлять прикладным модулям долговременную ссылку для разрешения ошибок. Все операции наблюдения, как и конструктор, специфицированы как потокобезопасные [SWS_TS_14208] [SWS_TS_14209] [SWS_TS_14210] [SWS_TS_14211], благодаря чему параллельное использование через границы потоков может осуществляться без внешней синхронизации.

Путь использования

Основной сценарий использования домена ошибок включает идентификацию, текстовое разрешение причин ошибок, а также опциональную передачу в виде исключения C++:

  1. Идентификация домена: с помощью метода Name() [SWS_TS_14209] система времени выполнения запрашивает идентификатор домена ошибок. Возвращаемое значение представляет собой строковую константу, однозначно присвоенную домену [SWS_TS_14209].
  2. Текстовое описание ошибки: если во время обработки FVM возникает ошибка, ее числовой код ошибки преобразуется в читаемую строку с помощью Message() [SWS_TS_14210]. Интерпретация: текст сообщения, возвращаемый Message(), вероятно, основан на статических строковых литералах, поскольку метод объявлен как потокобезопасный и безопасный относительно исключений без динамического управления памятью.
  3. Эскалация в виде исключения: если возникшая ошибка не может быть обработана локально, ThrowAsException() [SWS_TS_14211] позволяет преобразовать ara::core::ErrorCode в исключение типа apext::tsync::TsyncFvmException, которое затем немедленно генерируется.

Диаграмма последовательности: процесс создания и генерации исключения через домен ошибок. Источники: [SWS_TS_14211]

Сценарии ошибок

Обработка ошибок класса apext::tsync::TsyncFvmErrorDomain подразделяется на опрос диагностической информации и передачу ошибок времени выполнения:

  • Разрешение ошибок без исключений: методы опроса Name() [SWS_TS_14209] и Message() [SWS_TS_14210] полностью безопасны относительно исключений и помечены noexcept. Они гарантируют, что при инспекции состояния ошибки не будут вызваны дополнительные исключения.
  • Распространение ошибок через исключения: метод ThrowAsException() [SWS_TS_14211] явно определен как noexcept(false) и не является безопасным относительно исключений, поскольку его непосредственное назначение состоит в создании и выбрасывании apext::tsync::TsyncFvmException [SWS_TS_14211].
  • Условие цепочки инструментов: если исключения C++ отключены в цепочке инструментов компилятора, ThrowAsException() в соответствии со спецификацией не участвует в разрешении перегрузок [SWS_TS_14211]. Это обеспечивает безошибочную компиляцию в средах без поддержки исключений.

Функция-член [SWS_TS_14210] принадлежит классу apext::tsync::TsyncFvmErrorDomain и подключается через заголовочный файл apext/tsync/fvm_error_domain.h. Она служит для синхронного определения текстового описания для возникшего кода ошибки. В качестве входного параметра функция принимает числовой код ошибки errorCode типа CodeType и возвращает связанное с ним сообщение об ошибке в виде указателя на константную строку (const char *).

В отношении конкурентности и отказоустойчивости спецификация обеспечивает исчерпывающие гарантии: метод классифицирован как thread-safe и, таким образом, может вызываться из параллельных потоков без дополнительных мер по синхронизации [SWS_TS_14210]. Кроме того, функция отнесена к exception safe и снабжена идентификатором noexcept, благодаря чему возникновение исключений во время выполнения исключено.

В модуле ts существует тесная связь с элементом спецификации [SWS_TS_00907]. Он определяет аналогичную функцию Message для домена ошибок ara::tsync::TsyncErrorDomain в заголовочном файле ara/tsync/tsync_error_domain.h. Оба интерфейса имеют одинаковую сигнатуру, а также идентичные гарантии относительно потокобезопасности и безопасности исключений и обеспечивают единообразный запрос текстов ошибок между различными доменами.

Константная функция-член Name() класса apext::tsync::TsyncFvmErrorDomain возвращает указатель на неизменяемую строку (const char*), представляющую имя домена ошибок для FVM синхронизации времени [SWS_TS_14209]. Функция служит для запроса идентификатора домена ошибок во время выполнения. Вызов выполняется синхронно и без параметров и требует подключения заголовочного файла apext/tsync/fvm_error_domain.h [SWS_TS_14209].

      

      
Что касается поведения при ошибках, интерфейс объявлен как noexcept и считается исключениебезопасным (exception safe) [SWS_TS_14209]. Поскольку он лишь ссылается на фиксированную строковую константу, специфические коды ошибок не возвращаются и ошибочные ситуации не возникают. В отношении конкурентности метод явно классифицирован как потокобезопасный (thread-safe) [SWS_TS_14209]. Параллельные вызовы из нескольких потоков, следовательно, вероятно, допустимы в любое время без дополнительной внешней синхронизации или механизмов защиты.

      

      
В архитектурном взаимодействии функция переопределяет (override) интерфейс идентификации домена ошибок и дополняет аналогичную функцию из [SWS_TS_00906]. В то время как [SWS_TS_00906] через ara/tsync/tsync_error_domain.h предоставляет имя домена ошибок ara::tsync::TsyncErrorDomain для базовой синхронизации времени, [SWS_TS_14209] служит для обозначения специализированного домена ошибок apext::tsync::TsyncFvmErrorDomain. Оба метода, таким образом, следуют единой модели ошибок AUTOSAR Adaptive.

          Функция-член ThrowAsException домена ошибок apext::tsync::TsyncFvmErrorDomain служит для синхронной генерации C++-исключения на основе кода ошибки ([SWS_TS_14211]). Объявление доступно через заголовочный файл apext/tsync/fvm_error_domain.h. Метод принимает входной параметр errorCode (const ara::core::ErrorCode &), инстанцирует на его основе специфическое apext::tsync::TsyncFvmException и напрямую генерирует его ([SWS_TS_14211]). Соответственно, функция, специфицированная с noexcept(false), не имеет возвращаемого значения.
          
  
          Для контекста вызова функция специфицирована как потокобезопасная (thread-safe), однако указана как не исключениебезопасная (not exception safe) ([SWS_TS_14211]). Интерпретация: такая классификация как не исключениебезопасной, вероятно, связана с тем, что преднамеренный выброс исключения прерывает штатный поток управления. Ключевое ограничение компилятора определяет [SWS_CORE_10304]: если исключения C++ отключены в наборе инструментов сборки, функция не участвует в разрешении перегрузки.
          
  
          В общей системе функция дополняет обработку ошибок аналогично [SWS_TS_00908] из ara::tsync::TsyncErrorDomain.               Использование
              

              Конструктор по умолчанию без параметров TsyncFvmErrorDomain() синхронно создает новый экземпляр домена ошибок apext::tsync::TsyncFvmErrorDomain [SWS_TS_14208]. Он не принимает входных параметров и объявлен как constexpr, а также noexcept. Для интеграции необходимо подключить заголовочный файл apext/tsync/fvm_error_domain.h [SWS_TS_14208].
              


              Обработка ошибок и параллелизм
              

              Поскольку конструктор специфицирован как noexcept, при инстанцировании исключения не возникают; выполнение считается потокобезопасным и исключителюзеустойчивым [SWS_TS_14208]. Созданный объект управляет кодами ошибок перечисления TsyncFvmErrc [SWS_TS_14202] (псевдоним типа Errc [SWS_TS_14206]) и транслирует их, охватывая специфические ошибки kFVNotAvailable и kFVInitializeFailed [SWS_TS_14202].
              


              Взаимодействие и жизненный цикл
              

              Экземпляр домена предоставляет интерфейсы для разрешения имен и сообщений через Name() [SWS_TS_14209] и Message() [SWS_TS_14210], а также для генерации типоспецифичных исключений через ThrowAsException() [SWS_TS_14211] с использованием Exception [SWS_TS_14207]. Уничтожение выполняется через виртуальный деструктор ~TsyncFvmErrorDomain() [SWS_TS_14201]. В коде приложения прямое ручное конструирование вряд ли потребуется часто; вероятно, вместо этого глобальный экземпляр-одиночка (синглтон) запрашивается через GetTsyncFvmErrorDomain() [SWS_TS_14212].
