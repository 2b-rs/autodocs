Типобезопасно хранит ровно одно значение из определенного набора типов с условной безопасностью относительно исключений.

Шаблонный класс ara::core::Variant служит типобезопасным объединением (union) для хранения ровно одного значения из заданного набора типов и управления им [SWS_CORE_01649]. Он поддерживает гибкие механизмы конструирования, присваивания и emplace, а также позволяет определять активную альтернативу через index() [SWS_CORE_01665]. Важнейшей особенностью по сравнению со стандартом являются модифицированные условные noexcept-спецификации всех модифицирующих операций, а также защита от состояния valueless_by_exception() [SWS_CORE_01666].

Контекст

Шаблонный класс ara::core::Variant представляет собой типобезопасное объединение для AUTOSAR Adaptive Platform, подключаемое через заголовочный файл ara/core/variant.h. Он инкапсулирует управление ровно одним значением из списка типов, определенного во время компиляции (template <typename... Types> class Variant). Определение принципиально ориентируется на поведение std::variant из стандарта C++ [variant], однако имеет специфические отличия AUTOSAR в части спецификации исключений. Описание класса в составе метаданных ссылается на [basic.string]; интерпретация: в данном случае речь, вероятно, идет о редакционной неточности, поскольку все требования согласованно ссылаются на раздел стандарта [variant]. Жизненный цикл

Экземпляр ara::core::Variant проходит детерминированные фазы жизненного цикла от инициализации через смену значения до уничтожения. Создание происходит либо через конструктор по умолчанию без параметров [SWS_CORE_01649], инициализирующий первую альтернативу, либо через конструкторы копирования и перемещения [SWS_CORE_01650], [SWS_CORE_01651], либо путем прямой передачи значения [SWS_CORE_01652]. Кроме того, доступны перегрузки для конструирования на месте (in-place) с помощью in_place_type_t [SWS_CORE_01653], [SWS_CORE_01654], а также in_place_index_t [SWS_CORE_01655], [SWS_CORE_01656], в том числе в сочетании со списками инициализации.

В обычном состоянии объект всегда содержит допустимую альтернативу, отсчитываемый от нуля индекс которой можно определить с помощью метода index() [SWS_CORE_01665]. Если смена значения во время конструирования или присваивания завершается сбоем из-за выброса исключения, экземпляр переходит в состояние valueless_by_exception() [SWS_CORE_01666]. Объект остается в этом состоянии до тех пор, пока в результате успешной повторной инициализации снова не будет занята допустимая альтернатива. Деструктор надлежащим образом уничтожает удерживаемый в данный момент объект и объявлен условно безопасным относительно исключений [SWS_CORE_01657].

Диаграмма состояний: переходы состояний экземпляра Variant между корректной заполненностью типом и состоянием исключения. Источники: [SWS_CORE_01649], [SWS_CORE_01657], [SWS_CORE_01661], [SWS_CORE_01665], [SWS_CORE_01666]

Путь использования

Типичный процесс использования включает инстанциацию, присваивание или замену содержимого, запрос состояния и обмен значениями:

  • Инициализация: создание экземпляра с помощью одного из конструкторов, например путем прямой передачи значения [SWS_CORE_01652] или явно по типу с помощью in_place_type_t [SWS_CORE_01653].
  • Обновление значения и повторное заполнение: присваивание нового значения через оператор присваивания копированием [SWS_CORE_01658], оператор присваивания перемещением [SWS_CORE_01659] или универсальное присваивание значения [SWS_CORE_01660]. В качестве альтернативы значение можно переконструировать непосредственно на месте через emplace по типу [SWS_CORE_01661], [SWS_CORE_01662] или по индексу [SWS_CORE_01663], [SWS_CORE_01664].
  • Проверка состояния: запрос индекса активного типа через index() [SWS_CORE_01665], а также защита от предшествующих ошибок через valueless_by_exception() [SWS_CORE_01666].
  • Обмен объектов: эффективный обмен двух экземпляров Variant через функцию-член swap() [SWS_CORE_01667].

Поскольку рассматриваемый набор записей спецификации охватывает исключительно функции-члены, прямые операции чтения, такие как доступ к значению, отсутствуют; вероятно, функции доступа и обхода (аналогично std::get или std::visit) предоставляются как свободные вспомогательные функции в пространстве имен ara::core. Сценарии ошибок

В центре обработки ошибок находится свойство условной безопасности относительно исключений (conditionally exception safe). В то время как стандартная библиотека предусматривает для std::variant фиксированные правила noexcept, AUTOSAR целенаправленно отклоняется: все конструкторы [SWS_CORE_01650], [SWS_CORE_01653], операторы присваивания [SWS_CORE_01658], операции emplace [SWS_CORE_01661], [SWS_CORE_01663], функция обмена swap() [SWS_CORE_01667], а также деструктор [SWS_CORE_01657] условно noexcept. Их гарантия безопасности исключений напрямую зависит от свойств noexcept конструкторов базовых типов.

Если конструирование нового значения во время присваивания или вызова emplace выбрасывает исключение, вариант может перейти в недопустимое промежуточное состояние. Об этом сигнализирует valueless_by_exception() [SWS_CORE_01666]. Исключительно две функции запроса index() [SWS_CORE_01665] и valueless_by_exception() [SWS_CORE_01666] предоставляют безоговорочную гарантию noexcept и полностью безопасны относительно исключений.

Настоящее руководство основано на спецификации AUTOSAR для Adaptive Platform (Release R25-11, модуль core) и подготовлено с помощью ИИ-ассистента курации.
