Служит для предоставления статуса идентификации группы DoIP для Diagnostic Manager.

Класс ara::diag::DoIPGroupIdentification служит абстрактным интерфейсом для адаптивных приложений, позволяя предоставлять актуальный статус идентификации группы DoIP для Diagnostic Management [SWS_DM_00724]. После инстанцирования с привязкой к порту приложение активирует пересылку запросов через Offer() и прекращает ее перед уничтожением объекта с помощью StopOffer() [SWS_DM_00725]. Экземпляр обработчика уникален, не подлежит ни копированию, ни перемещению и отвечает на запросы асинхронно через ara::core::Future.

Контекст

Класс ara::diag::DoIPGroupIdentification предоставляет функциональный интерфейс Diagnostic Management (AUTOSAR AP SWS Diagnostics с. 73), через который адаптивное приложение передает актуальный статус идентификации группы (GID-статус) для протокола DoIP [SWS_DM_00724]. В архитектуре платформы класс выступает в качестве посредника между двумя основными партнерами по взаимодействию: внутренним демоном Diagnostic Management Daemon (DM), обрабатывающим стандартизированные сообщения идентификации автомобиля и сообщения DoIP по сети, и специфичной для приложения реализацией, конкретизирующей чисто виртуальный метод GetGidStatus(). Предоставление сервиса и прием запросов управляются посредством явных предложений сервиса [SWS_DM_00725].

Жизненный цикл

Экземпляр DoIPGroupIdentification представляет уникальный диагностический порт. По этой причине класс спроектирован как объект с уникальным управлением: как конструктор копирования [SWS_DM_01641] и конструктор перемещения [SWS_DM_01642], так и соответствующие операторы присваивания [SWS_DM_01639], [SWS_DM_01640] явно удалены (=delete).

Создание обязательно выполняется через параметризованный конструктор с указанием ara::core::InstanceSpecifier, а также режима параллелизма ConcurrencyType [SWS_DM_00722]. Жизненный цикл делится на следующие фазы:

  • Не предлагается (Not Offered): после конструирования объект существует в адресном пространстве процесса, но еще не принимает запросы от DM.
  • Предлагается (Offered): посредством синхронного вызова Offer() [SWS_DM_00725] обработчик активируется в DM, так что входящие запросы статуса DoIP пересылаются.
  • Остановлен (Stopped): вызов StopOffer() [SWS_DM_00726] отзывает у DM право пересылки и переводит объект обратно в неактивное состояние.

Уничтожение осуществляется через виртуальный деструктор ~DoIPGroupIdentification() [SWS_DM_00723]. В отношении многопоточности конструктор является потокобезопасным, в то время как Offer(), StopOffer() и деструктор непотокобезопасны [SWS_DM_00722], [SWS_DM_00723], [SWS_DM_00725], [SWS_DM_00726]. Потокобезопасность функции запроса GetGidStatus() условно определяется выбранным в конструкторе ConcurrencyType [SWS_DM_00724]. Интерпретация: деструктор, по всей видимости, неявно прекращает текущие пересылки, если ранее не был вызван StopOffer().

Путь использования

Типичное использование включает инициализацию, активацию, асинхронную обработку и деактивацию:

  1. Конкретный диагностический класс наследуется от ara::diag::DoIPGroupIdentification и реализует метод GetGidStatus() [SWS_DM_00724].
  2. Приложение создает объект с InstanceSpecifier сконфигурированного прототипа порта и задает, разрешено ли вызывать GetGidStatus() параллельно (kConcurrent) или нет (kNotConcurrent) [SWS_DM_00722].
  3. С помощью Offer() приложение активирует обработчик для Diagnostic Management [SWS_DM_00725].
  4. Как только поступают запросы DoIP, DM вызывает GetGidStatus(); приложение возвращает состояние GID асинхронно через ara::core::Future<GidStatus> [SWS_DM_00724].
  5. Перед завершением сервиса или остановом компонента приложение вызывает StopOffer() [SWS_DM_00726] с последующим уничтожением объекта [SWS_DM_00723].

Диаграмма последовательности: типичный процесс инстанцирования, активации, запроса статуса и деактивации. Источники: [SWS_DM_00722], [SWS_DM_00724], [SWS_DM_00725], [SWS_DM_00726].

Сценарии ошибок

При использовании DoIPGroupIdentification определены условия ошибок на этапах конструирования и предоставления:

  • Ошибки модели и привязки (конструктор): если инстанцирование завершается сбоем, сообщается о стандартизированных нарушениях [SWS_DM_00722]:
    • InstanceSpecifierMappingIntegrityViolation: идентификатор не удается разрешить или он не указывает на прототип порта.
    • PortInterfaceMappingViolation: целевой порт не типизирован как DiagnosticDoIPGroupIdentificationInterface.
    • ProcessMappingViolation: контексту выполнения в модели не сопоставлен подходящий процесс.
    • InstanceSpecifierAlreadyInUseViolation: указанный идентификатор порта уже используется другим экземпляром в работающем процессе.
  • Ошибка предоставления сервиса (Offer()): метод возвращает ara::core::Result<void>. Если сервис для этого обработчика уже был успешно предложен, повторный вызов завершается с кодом ошибки DiagOfferErrc::kAlreadyOffered [SWS_DM_00725].
  • Ошибка при запросе состояния: интерфейс GetGidStatus() не определяет стандартизированных кодов ошибок [SWS_DM_00724]; внутренние ошибки приложения должны отображаться через объект результата возвращаемого объекта Future.

Настоящее руководство основано исключительно на спецификации AUTOSAR Adaptive R25-11.

                  Синхронная функция-член Offer класса ara::diag::DoIPGroupIdentification сигнализирует Diagnostic Management (DM), что предоставляющее приложение Adaptive Application готово и запросы на идентификацию групп DoIP могут обрабатываться [SWS_DM_00725]. Только после этого вызова DM при необходимости может запросить ID группы через метод GetGidStatus, если отсутствует фиксированная конфигурация [SWS_DM_00813].
                  


                  В отношении контекста вызова и параллелизма действуют следующие условия:
                  

                    

                  • Сигнатура и семантика: вызов выполняется без параметров и синхронно возвращает ara::core::Result<void> [SWS_DM_00725]. Метод объявлен как noexcept и является исключения-безопасным (exception safe) [SWS_DM_00725].
                    • 

                  • Потокобезопасность: операция специфицирована как не потокобезопасная (not thread-safe) [SWS_DM_00725]. Вызовы для одного и того же экземпляра не должны производиться без защиты из конкурирующих потоков.
                    • 

                  


                  В случае ошибки результирующий объект возвращает код ошибки DiagOfferErrc::kAlreadyOffered с семантикой отката, если сервис для этого интерфейса уже был предложен [SWS_DM_00725].
