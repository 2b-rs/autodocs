Служит интерфейсом для операций симметричного шифрования и расшифрования в потоках данных или одиночных вызовах.

Класс ara::crypto::cryp::SymmetricCipherCtx служит потокобезопасным интерфейсом для операций симметричного шифрования и расшифрования в AUTOSAR Adaptive [SWS_CRYPT_50044]. После конфигурирования ключа через SetKey() данные могут обрабатываться либо в рамках одиночного вызова, либо пошагово в потоковом цикле из Start(), Update() и Finish() [SWS_CRYPT_50138], [SWS_CRYPT_50139]. Все методы специфицированы как noexcept и сигнализируют об ошибках, таких как отсутствие инициализации или слишком малый размер буфера, через ara::core::Result [SWS_CRYPT_50140].

Контекст

Интерфейс ara::crypto::cryp::SymmetricCipherCtx инкапсулирует симметричные криптографические преобразования, охватывающие как операции шифрования, так и расшифрования. Внутри криптографической архитектуры класс действует как контекст выполнения для симметричных алгоритмов и взаимодействует с объектами ключей, а также буферами памяти. Для конфигурирования криптографического ключа класс взаимодействует либо напрямую с временными ключами через SymmetricKey [SWS_CRYPT_50138], либо с постоянными или изолированно управляемыми ключами через KeySlot [SWS_CRYPT_50043]. Подлежащие обработке открытые и зашифрованные тексты, а также векторы инициализации (IV) передаются и принимаются через области памяти типа ReadOnlyMemRegion и ReadWriteMemRegion [SWS_CRYPT_50048], [SWS_CRYPT_50049].

Жизненный цикл

Жизненный цикл и отношения владения интерфейса управляются преимущественно через типизированный псевдоним интеллектуального указателя Sptr (std::shared_ptr<SymmetricCipherCtx>) [SWS_CRYPT_50137]. Предоставление конкретного экземпляра на практике, вероятно, осуществляется через вышестоящий криптографический фабричный метод (интерпретация), поскольку само определение интерфейса не содержит функций создания.

После инстанциации контекст проходит несколько рабочих фаз:

  • Не инициализирован: непосредственно после инстанциации контексту не сопоставлен ключ. Любой вызов обработки в этой фазе приводит к ошибке CryptoErrc::kUninitializedContext [SWS_CRYPT_50044], [SWS_CRYPT_50047].
  • Инициализирован / ключ привязан: путем вызова SetKey() с SymmetricKey [SWS_CRYPT_50138] или KeySlot [SWS_CRYPT_50043] контекст становится готовым к использованию. Из этого состояния можно либо выполнять операции без сохранения состояния в режиме одиночного вызова, либо запускать процесс потоковой обработки с сохранением состояния.
  • Потоковая обработка: вызов Start() запускает пошаговое преобразование [SWS_CRYPT_50044], [SWS_CRYPT_23625]. В этой фазе данные могут преобразовываться через Update() [SWS_CRYPT_50139], а позиция может изменяться через Seek() [SWS_CRYPT_23613]. Состояние потоковой обработки штатно завершается с помощью Finish() [SWS_CRYPT_50045] либо FinishEncrypt() [SWS_CRYPT_23618] или преждевременно отбрасывается через Cancel() [SWS_CRYPT_50046]. После этого контекст возвращается в инициализированное базовое состояние.

Все методы SymmetricCipherCtx объявлены как noexcept, обеспечивают безопасность относительно исключений («exception safe») и специфицированы как потокобезопасные («thread-safe») для параллельного доступа [SWS_CRYPT_50044], [SWS_CRYPT_50139].

Диаграмма состояний: жизненный цикл и переходы состояний контекста симметричного шифрования. Источники: [SWS_CRYPT_50138], [SWS_CRYPT_50044], [SWS_CRYPT_50139], [SWS_CRYPT_50045], [SWS_CRYPT_50046]

Путь использования

Перед фактическим преобразованием данных рекомендуется определить требуемые размеры буферов и фрагментов (chunks). С помощью GetMinimumChunkSize() [SWS_CRYPT_50144] и GetMaximumChunkSize() [SWS_CRYPT_50050] можно определить допустимые границы для входных блоков. Если требуются векторы инициализации, границы их длины можно запросить с помощью GetMinimumInputIvSize() [SWS_CRYPT_50141], GetMaximumInputIvSize() [SWS_CRYPT_50142] или GetOutputIvSize() [SWS_CRYPT_50143]. Максимально необходимый размер целевого буфера для операции рассчитывается с помощью GetRequiredOutputBufferSize() [SWS_CRYPT_50140].

Для пошагового потокового шифрования или расшифрования действует следующий стандартный порядок:

  1. Конфигурирование ключа: привязка криптографического ключа к контексту через SetKey() [SWS_CRYPT_50138].
  2. Запуск преобразования: вызов Start() с указанием направления преобразования (шифрование или расшифрование) и опционального IV [SWS_CRYPT_23625] либо без IV [SWS_CRYPT_50044].
  3. Преобразование блоков данных: повторный вызов Update() для пошаговой передачи входных данных и извлечения выходных данных [SWS_CRYPT_50139]. При необходимости можно осуществлять навигацию внутри потока данных с помощью Seek() [SWS_CRYPT_23613].
  4. Завершение: финализация через Finish() [SWS_CRYPT_50045] или через FinishEncrypt(), если требуется вернуть сгенерированный контекстом IV [SWS_CRYPT_23618].

В качестве альтернативы этой потоковой модели интерфейс поддерживает синхронные одиночные вызовы. Если доступна вся полезная нагрузка целиком, операция может быть выполнена напрямую через ProcessSingleCall() [SWS_CRYPT_50047], ProcessSingleCallWithInputIv() [SWS_CRYPT_50048] или для собственной генерации IV контекстом через EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049].

Диаграмма последовательности: типичная последовательность вызовов потокового шифрования. Источники: [SWS_CRYPT_50138], [SWS_CRYPT_23625], [SWS_CRYPT_50139], [SWS_CRYPT_23618]

Сценарии ошибок

Методы класса сигнализируют об ошибках через ara::core::Result с кодами домена ошибок ara::crypto::CryptoErrc. Основные условия ошибок включают:

  • CryptoErrc::kUninitializedContext: возникает, когда вызовы обработки, такие как Start() [SWS_CRYPT_50044], процедуры одиночного вызова [SWS_CRYPT_50047] или GetRequiredOutputBufferSize() [SWS_CRYPT_50140], вызываются до того, как ключ был задан через SetKey().
  • CryptoErrc::kProcessingNotStarted: возникает, когда потоковые функции, такие как Update() [SWS_CRYPT_50139], Finish() [SWS_CRYPT_50045], FinishEncrypt() [SWS_CRYPT_23618], Seek() [SWS_CRYPT_23613] или Cancel() [SWS_CRYPT_50046], выполняются без предварительного успешного вызова Start().
  • CryptoErrc::kInsufficientCapacity: предоставленный целевой буфер для данных или IV меньше минимально необходимой емкости [SWS_CRYPT_50139], [SWS_CRYPT_50049].
  • CryptoErrc::kUsageViolation и CryptoErrc::kIncompatibleObject: переданный тип ключа не подходит для преобразования или заданные в ключе правила использования запрещают операцию (например, отсутствие kAllowDataEncryption или kAllowDataDecryption) [SWS_CRYPT_50044], [SWS_CRYPT_50047].
  • CryptoErrc::kEmptyKeySlot и CryptoErrc::kBusyResource: указывает на то, что сконфигурированный KeySlot во время выполнения не содержит ключа или заблокирован ресурс, необходимый для криптографической операции [SWS_CRYPT_50048], [SWS_CRYPT_50049].
  • CryptoErrc::kUnsupported: возвращается, если режим работы (такой как потоковая обработка, одиночный вызов или Seek()) не поддерживается выбранным контекстом или алгоритмом [SWS_CRYPT_23613], [SWS_CRYPT_50047].

Синхронный метод Cancel() класса ara::crypto::cryp::SymmetricCipherCtx служит для преждевременного прерывания текущей потоковой операции, которая ранее была инициирована с помощью Start() и еще не завершена [SWS_CRYPT_50046]. Интерфейс объявлен без параметров в ara/crypto/cryp/symmetric_cipher_ctx.h и при успешном выполнении возвращает пустой ara::core::Result<void> [SWS_CRYPT_50046].

Если обработка данных не была предварительно начата вызовом Start(), операция завершается сбоем с конкретным кодом ошибки ara::crypto::CryptoErrc::kProcessingNotStarted и семантикой отката [SWS_CRYPT_50046]. Для контекста вызова спецификация гарантирует потокобезопасность (thread-safe), а также безопасность исключений (exception safe) с объявлением noexcept [SWS_CRYPT_50046]. Интерпретация: благодаря семантике отката объект после прерывания, вероятно, возвращается в исходное состояние готовности.

Этот функциональный шаблон согласованно определен для всех криптографических контекстов потоковой передачи в AUTOSAR Adaptive. Идентичные сигнатуры и семантика ошибок действуют для контекстных классов VerifierPublicCtx ([SWS_CRYPT_50023]), MessageAuthnCodeCtx ([SWS_CRYPT_50027]), SignerPrivateCtx ([SWS_CRYPT_50041]), HashFunctionCtx ([SWS_CRYPT_50058]), DecryptorPrivateCtx ([SWS_CRYPT_50069]), AuthCipherCtx ([SWS_CRYPT_50077]) и EncryptorPublicCtx ([SWS_CRYPT_50089]).

      Использование и обработка буферов
      

      Синхронный метод EncryptSingleCallWithOutputIv выполняет симметричное шифрование за один вызов и возвращает сгенерированный контекстом вектор инициализации через буфер ivOut [SWS_CRYPT_50049]. Входные данные передаются через in, тогда как out принимает зашифрованные данные [SWS_CRYPT_50049]. При успешном выполнении результат ara::core::Result<std::size_t> предоставляет фактический размер созданных выходных данных, который может быть меньше общей емкости out [SWS_CRYPT_50049]. Если выбранный алгоритм не требует вектора инициализации, данные в ivOut не записываются [SWS_CRYPT_50049].
      

      Взаимодействие и предварительные условия
      

      Перед вызовом контекст должен быть инициализирован с помощью подходящего ключа [SWS_CRYPT_50049].
