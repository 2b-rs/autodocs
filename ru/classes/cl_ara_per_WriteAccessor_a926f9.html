класс ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Служит для буферизованной записи бинарных и текстовых файлов, а также их синхронизации с физическим накопителем.

Класс ara::per::WriteAccessor обеспечивает запись бинарного или текстового содержимого файлов в модуле персистентности и предоставляет методы для неформатированного доступа на запись, а также форматированный оператор потока [SWS_PER_00423]. Поскольку операции записи сначала могут буферизоваться в операционной системе, вызов SyncToFile() принудительно выполняет окончательный сброс данных на физический накопитель [SWS_PER_00122]. Все методы являются безопасными к исключениям, однако не являются потокобезопасными, в связи с чем параллельный доступ должен защищаться приложением.

Контекст

ara::per::WriteAccessor является финальным классом модуля персистентности (per) платформы AUTOSAR Adaptive Platform и виртуально наследуется от FileAccessor. Класс предоставляет операции записи для содержимого файлов. Он предлагает методы для неформатированной контролируемой записи с обработкой ошибок через ara::core::Result, а также перегруженный оператор потока для форматированной записи. В качестве партнеров по взаимодействию выступают вызывающее приложение, внутренний файловый буфер операционной системы и физический носитель данных.

Жизненный цикл

Конструктор по умолчанию WriteAccessor явно удален и не должен использоваться [SWS_PER_00596]. (Интерпретация: экземпляры WriteAccessor, вероятно, создаются и предоставляются фабричными методами вышестоящих сущностей управления персистентностью, таких как File-Storage.)

Уничтожение выполняется через виртуальный деструктор ~WriteAccessor() [SWS_PER_00597]. Класс и его методы специфицированы как безопасные к исключениям («exception safe») и объявлены как noexcept. В отношении многопоточности WriteAccessor не является потокобезопасным («not thread-safe») [SWS_PER_00597]; параллельный доступ к одному и тому же экземпляру должен защищаться приложением извне.

Путь использования

Стандартная процедура включает запись данных в неформатированном или форматированном режиме, опциональную корректировку размера файла и заключительное персистентное сохранение:

  • Запись бинарных данных: с помощью WriteBinary() диапазон байтов (ara::core::Span<const ara::core::Byte>) записывается в файл [SWS_PER_00423].
  • Запись текстовых данных: с помощью WriteText() строки передаются через ara::core::StringView [SWS_PER_00166]. Дополнительно доступен operator<< как удобная функция для некритичных сценариев использования, при этом возникающие ошибки негласно игнорируются [SWS_PER_00125].
  • Принудительное сохранение: момент фактической физической записи зависит от реализации персистентности; SyncToFile() гарантированно сбрасывает буфер операционной системы на носитель данных [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Изменение размера файла: с помощью SetFileSize() файл может быть усечен, в результате чего выступающее содержимое удаляется; позиция в файле остается без изменений либо устанавливается на последнюю допустимую позицию или 0 [SWS_PER_00428].

Диаграмма последовательности: операции записи с последующей синхронизацией с физическим носителем. Источники: [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Сценарии ошибок

Методы WriteBinary(), WriteText(), SyncToFile() и SetFileSize() возвращают ara::core::Result<void>, содержащий при сбоях специфические коды ошибок:

  • PerErrc::kPhysicalStorageFailure: сбой доступа к физическому носителю данных [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Состояние файла неизвестно и он может быть полностью поврежден (семантика отката отсутствует).
  • PerErrc::kOutOfStorageSpace: недостаточно физического дискового пространства [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. При записи превышающая часть отбрасывается, а позиция устанавливается в конец файла (семантика отката отсутствует).
  • PerErrc::kQuotaExceeded: файл превысил бы сконфигурированный максимальный размер (AllowedSize) [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (семантика отката).
  • PerErrc::kEncryptionFailed: сбой шифрования или расшифрования [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Хотя буфер и позиция обновляются, файл не может быть сохранен и отражает на накопителе более старую версию (семантика отката).
  • PerErrc::kAuthenticationFailed: сбой вычисления или проверки MAC [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (семантика отката).
  • PerErrc::kValidationFailed: невозможно гарантировать валидность сохраненных данных [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (семантика отката).
  • PerErrc::kInvalidSize: новый размер файла при SetFileSize() больше текущего размера файла [SWS_PER_00428] (семантика отката).

Данное руководство было сгенерировано ИИ на основе спецификации AUTOSAR R25-11.

WriteBinary функция

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;

The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown.       Функция-член SyncToFile класса ara::per::WriteAccessor (определенная в #include "ara/per/write_accessor.h") синхронно переносит текущее содержимое файла в физическое хранилище [SWS_PER_00122]. Вызов не принимает входных параметров и возвращает ara::core::Result<void>, которое в случае успеха пусто или в случае ошибки содержит специфические коды ошибок модуля Persistency либо ошибки, специфичные для поставщика [SWS_PER_00122].
      


      При выполнении могут возникать различные случаи ошибок, часть из которых обладает семантикой отката [SWS_PER_00122]:
      

        

      • StorageFailure: возникает, если сбой физического доступа к носителю данных (без семантики отката) [SWS_PER_00122].
        • 

      • PerErrc::kOutOfStorageSpace: возвращается, если физического объема хранилища для измененного файла недостаточно (без семантики отката) [SWS_PER_00122].
        • 

      • PerErrc::kQuotaExceeded: сообщается, если файл превышает сконфигурированный максимальный размер AllowedSize хранилища File Storage (с семантикой отката) [SWS_PER_00122].
        • 

      • PerErrc::kEncryptionFailed: сбой шифрования сохраненных данных (с семантикой отката) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed: сбой вычисления MAC для данных (с семантикой отката) [SWS_PER_00122].
        • 

      


      С точки зрения безопасности выполнения метод объявлен как noexcept и специфицирован как exception safe [SWS_PER_00122]. Однако, поскольку он явно классифицирован как not thread-safe, одновременные вызовы для одного и того же экземпляра WriteAccessor, вероятно, должны синхронизироваться вызывающей стороной [SWS_PER_00122].
      


      

      Это указание по использованию было автоматически сгенерировано на основе спецификации AUTOSAR R25-11.
