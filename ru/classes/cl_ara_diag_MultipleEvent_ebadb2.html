Позволяет опрашивать и отслеживать несколько диагностических событий с помощью дескрипторов событий и уведомлений через обратный вызов.

Класс позволяет приложениям выполнять опрос состояний и мониторинг нескольких диагностических событий через общий интерфейс на основе дескрипторов событий [SWS_DM_01705]. Помимо регистрации обратных вызовов для уведомлений, доступны асинхронные методы для определения статуса события, устранения дребезга, счетчика ошибок и номера DTC [SWS_DM_01707], [SWS_DM_01709]. Экземпляры не могут ни копироваться, ни перемещаться, и из-за непотокобезопасного деструктора требуют корректного завершения активных операций перед освобождением [SWS_DM_01706], [SWS_DM_02067].

Контекст

Класс ara::diag::MultipleEvent предоставляет приложению интерфейсы для опроса и мониторинга диагностических событий через интерфейсы для множественных событий [SWS_DM_01705]. В отличие от классов одиночных событий, операции над экземплярами MultipleEvent обращаются к конкретным событиям через идентификатор типа EventHandleType [SWS_DM_01707], [SWS_DM_01708]. Класс действует как интерфейс между использующим программным компонентом и управлением диагностикой (Diagnostic Management, DM) в Adaptive AUTOSAR AUTOSAR AP SWS Diagnostics, с. 69. Через прототип порта DiagnosticMultipleEventInterface объект привязывается к сконфигурированной диагностической инфраструктуре [SWS_DM_01705].

Жизненный цикл

Экземпляр MultipleEvent создается через явный конструктор с указанием ara::core::InstanceSpecifier [SWS_DM_01705]. Конструктор является потокобезопасным и проверяет смоделированную привязку к прототипу порта с типом интерфейса DiagnosticMultipleEventInterface [SWS_DM_01705]. Если сопоставление завершается сбоем или один и тот же идентификатор экземпляра используется повторно в рамках процесса, платформа сообщает о соответствующих нарушениях, таких как InstanceSpecifierAlreadyInUseViolation или PortInterfaceMappingViolation [SWS_DM_01705].

Операции копирования и перемещения для MultipleEvent полностью заблокированы: как конструкторы копирования и перемещения, так и соответствующие операторы присваивания объявлены удаленными [SWS_DM_02067], [SWS_DM_02068], [SWS_DM_02069], [SWS_DM_02070]. Таким образом, объект обладает строгой идентичностью и остается в месте своего создания. Деструктор ~MultipleEvent() специфицирован как непотокобезопасный [SWS_DM_01706]. Поэтому вызывающие компоненты перед уничтожением должны убедиться, что через данный экземпляр больше не выполняются асинхронные опросы или уведомления AUTOSAR AP SWS Diagnostics, с. 78.

Путь использования

После создания экземпляра приложение обычно регистрирует функцию обратного вызова с помощью SetEventStatusChangedNotifier, чтобы получать информацию об изменениях статуса определенного события (идентифицируемого через EventHandleType) [SWS_DM_01708]. Повторный вызов этого метода для того же события перезаписывает ранее установленный нотификатор [SWS_DM_01708]. Эта функция регистрации не является потокобезопасной [SWS_DM_01708].

Во время работы актуальная диагностическая информация может быть целенаправленно запрошена для каждого дескриптора события. Все операции чтения, связанные с состоянием, возвращают свои данные асинхронно в ara::core::Future:

  • GetEventStatus возвращает текущий байт статуса события как EventStatusByte [SWS_DM_01707].
  • GetDebouncingStatus возвращает состояние устранения дребезга (DebouncingState) события [SWS_DM_01710].
  • GetFaultDetectionCounter возвращает текущий счетчик обнаружения ошибок (FaultDetectionCounter) в виде 8-битного целочисленного значения со знаком [SWS_DM_01711].
  • GetDTCNumber опрашивает назначенный номер DTC в запрошенном DTCFormatType [SWS_DM_01709].

Потокобезопасность этих функций опроса зависит от конфигурации [SWS_DM_01707], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].

Диаграмма последовательности: типичный путь использования для наблюдения и опроса диагностических событий через MultipleEvent. Источники: [SWS_DM_01705], [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711]

Сценарии ошибок

Методы MultipleEvent сигнализируют о состояниях ошибок через тип DiagErrc, который передается инкапсулированным либо в ara::core::Result, либо в возвращаемом ara::core::Future [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709]. Специфицированы следующие случаи ошибок:

  • DiagErrc::kInvalidArgument: возникает при передаче недопустимых параметров, например, недействительного EventHandleType, или при внутренних ошибках устранения дребезга, таких как kPreFailed [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].
  • DiagErrc::kNoSuchDTC: сообщается GetDTCNumber, если для запрошенного диагностического события не сконфигурирован или не сопоставлен соответствующий DTC [SWS_DM_01709].
  • DiagErrc::kServiceNotAvailable: возникает при операциях чтения, если базовые функциональные возможности Diagnostic Management, необходимые для работы, недоступны во время выполнения [SWS_DM_01707], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].

В случае ошибки операции гарантируют семантику отката [SWS_DM_01707], [SWS_DM_01709].

Данное руководство основано исключительно на требованиях спецификации AUTOSAR Adaptive R25-11.

                              ara::core::Result< void > SetEventStatusChangedNotifier (EventHandle Type eventHandle, EventStatusByteNotifier notifier) noexcept;
                              

                              Register a notifier function which is called if a diagnostic event is changed. A consecutive call of this method will overwrite the previous registered notifier.

                              Использование
                              

                              Метод ara::diag::MultipleEvent::SetEventStatusChangedNotifier [SWS_DM_01708] регистрирует функцию обратного вызова типа EventStatusByteNotifier, которая вызывается при изменении состояния диагностического события. Через параметр eventHandle идентифицируется требуемое событие внутри экземпляра. Метод специфицирован как noexcept и возвращает ara::core::Result<void>. Повторный вызов перезаписывает ранее зарегистрированный нотификатор [SWS_DM_01708].
                              


                              Обработка ошибок
                              

                              Если при регистрации возникает ошибка, ara::core::Result возвращает соответствующий код ошибки. Специфицирована ошибка DiagErrc::kInvalidArgument, например, в контексте внутреннего дебаунсинга, такого как kPreFailed [SWS_DM_01708].
                              


                              Параллелизм и ограничения
                              

                              Операция объявлена как exception safe, однако явно классифицирована как not thread-safe [SWS_DM_01708]. Одновременные вызовы на одном и том же экземпляре поэтому должны синхронизироваться извне.
                              


                              Взаимодействие
                              

                              В то время как класс ara::diag::Event с SetEventStatusChangedNotifier [SWS_DM_00650] управляет отдельными событиями без дескриптора, MultipleEvent объединяет несколько событий. Вероятно, Diagnostic Management (DM) аналогично [SWS_DM_01029] при каждом изменении состояния сопоставленного через eventHandle события инициирует вызов зарегистрированного нотификатора AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.7 «Event status change notifications».
