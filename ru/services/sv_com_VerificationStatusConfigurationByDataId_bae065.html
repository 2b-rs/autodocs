Обеспечивает целенаправленное переопределение поведения верификации SecOC для конкретных Data ID.

Находящийся в статусе DRAFT сервисный интерфейс VerificationStatusConfigurationByDataId предоставляется Functional Cluster Communication Management для динамической конфигурации поведения верификации SecOC для конкретных Data ID ([SWS_CM_11369]). Через метод VerifyStatusOverride авторизованные приложения могут принудительно задавать прием, отбрасывание или пропуск сообщений и определять заданный результат верификации ([SWS_CM_10050]). Вызов метода выполняется с синхронным подтверждением посредством Fire & Forget false, причем через параметр счетчика также может быть задано ограничение на фиксированное число последовательных сообщений.

1. Роль и системный контекст сервисного интерфейса

Сервисный интерфейс VerificationStatusConfigurationByDataId предоставляется Functional Cluster Communication Management (CM) в качестве сервисного порта ([SWS_CM_11369]). В сервисной архитектуре AUTOSAR Adaptive управление коммуникацией принимает на себя роль сервис-провайдера (Skeleton), тогда как авторизованные функциональные приложения взаимодействуют через сгенерированный прокси в роли Consumer (AUTOSAR_AP_SWS_CommunicationManagement §8.x «Definition of Port VerificationStatusConfigurationByDataId»). Основная задача этого интерфейса состоит в том, чтобы целенаправленно конфигурировать и переопределять криптографическое поведение верификации Secure Onboard Communication (SecOC) для переданного идентификатора сообщения (dataID) ([SWS_CM_10050]).

Интерфейс дополняет регулярную службу сообщений о статусе верификации, через которую система передает каждый результат верификации приложениям ([SWS_CM_11278]). Потребителями конфигурационного интерфейса обычно, вероятно, являются специализированные системы управления безопасностью, Intrusion Detection Systems (IDS) или приложения для тестирования и диагностики, которые динамически управляют отбрасыванием или пересылкой сообщений и отслеживают их (AUTOSAR_AP_SWS_CommunicationManagement §9.1 «SecOC VerificationStatus»). Таким образом Communication Management получает возможность целенаправленно переопределять результаты верификации в процессе работы ([SWS_CM_11279]).

2. Методы, события и поля

Спецификация сервиса не содержит ни Events, ни Fields, а определяет исключительно синхронный либо поддерживающий подтверждение клиент-серверный метод ([SWS_CM_10050]):

  • VerifyStatusOverride: принудительно задает определенное поведение SecOC при приеме сообщений (прием или отбрасывание с выполнением или без выполнения верификации аутентификатора) и позволяет устанавливать определенный результат для VerificationStatusResult ([SWS_CM_10050]).

Метод имеет версию 1.0 и специфицирован с Fire & Forget false ([SWS_CM_10050]). В модели программирования C++ для ara::com вызов поэтому обычно возвращает ara::core::Future, подтверждающий завершение конфигурации (интерпретация). Метод определяет три входных параметра ([SWS_CM_10050]):

  • dataID (направление IN, тип uint16_t): уникальный идентификатор сообщения, для которого должно применяться переопределение ([SWS_CM_10050]).
  • overrideStatus (направление IN, тип OverrideStatus): значение перечисления, определяющее, выполняется ли верификация, отбрасывается или пересылается сообщение, и в течение какой длительности переопределение остается активным ([SWS_CM_10050]).
  • numberOfMessagesToOverride (направление IN, тип uint8_t): количество последовательных операций верификации, которые должны быть переопределены. Этот счетчик учитывается исключительно в том случае, если overrideStatus установлено в kSecOcOverrideDropUntilLimit, kSecOcOverrideSkipUntilLimit или kSecOcOverridePassUntilLimit ([SWS_CM_10050]).

3. Жизненный цикл, процессы сессий и зависимости от состояний

Определение сервисного порта VerificationStatusConfigurationByDataId в релизе R25-11 имеет статус DRAFT ([SWS_CM_11369]). После запуска Functional Cluster Communication Management предоставляет службу Skeleton, после чего заинтересованные Consumer разрешают и связывают экземпляр через поиск служб (AUTOSAR_AP_SWS_CommunicationManagement §8.x «Definition of Port VerificationStatusConfigurationByDataId»).

Диаграмма последовательности: процесс переопределения статуса верификации через метод VerifyStatusOverride. Источники: [SWS_CM_10050], [SWS_CM_11279], AUTOSAR_AP_SWS_CommunicationManagement §9.1 «SecOC VerificationStatus».

В штатном режиме неудачная верификация аутентификатора в SecOC приводит к тому, что затронутое сообщение отбрасывается (AUTOSAR_AP_SWS_CommunicationManagement §9.1 «SecOC VerificationStatus»). Однако как только VerifyStatusOverride был успешно вызван, сохраненная конфигурация немедленно применяется для всех последующих сообщений указанного dataID ([SWS_CM_10050]). В зависимости от параметра overrideStatus манипуляция либо остается активной постоянно, либо завершается автоматически, как только будет обработано количество сообщений, заданное в счетчике numberOfMessagesToOverride ([SWS_CM_10050]).

4. Обработка ошибок и Application Errors

Поскольку VerifyStatusOverride не демонстрирует поведения Fire-and-Forget, вызывающее приложение получает явное подтверждение о результате конфигурационного запроса ([SWS_CM_10050]). Специфические ошибки приложения (Application Errors) или коды ошибок для этого сервисного интерфейса в стандарте не объявлены; поэтому возможные ошибки вызова, вероятно, сообщаются через общие домены ошибок инфраструктуры ara::com ([SWS_CM_10050]).

С функциональной точки зрения сам сервис служит центральным инструментом для обработки ошибок на стороне приложения: благодаря возможности принудительно задать конкретный VerificationStatusResult можно стимулировать и валидировать процедуры обработки ошибок в приложении ([SWS_CM_10050]). Это позволяет IDS или системе управления безопасностью целенаправленно воспроизводить смоделированные атаки или сбойные передачи и отрабатывать адекватные динамические контрмеры во всей системе (AUTOSAR_AP_SWS_CommunicationManagement §9.1 «SecOC VerificationStatus»).

Настоящее руководство основано на спецификации AUTOSAR Adaptive R25-11 и обобщает требования к сервисному интерфейсу VerificationStatusConfigurationByDataId.
