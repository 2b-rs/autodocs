Роль и системный контекст сервисного интерфейса

Сервисный интерфейс StateMachineService представляет собой основной интерфейс управления Functional Cluster State Management (SM) на AUTOSAR Adaptive Platform ([SWS_SM_91021], [SWS_SM_91022]). При этом кластер State Management выступает в роли поставщика и предоставляет для каждого сконфигурированного экземпляра автомата состояний (StateMachine) собственный сервис на базе ara::com ([SWS_SM_00600]). В роли потребителя выступает управляющее приложение SMControlApplication, которое взаимодействует с соответствующим автоматом состояний через соответствующий Proxy для активного запроса смены состояния (AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 «Interfaces for a SMControlApplication», AUTOSAR_AP_SWS_StateManagement §9.2.2 «StateMachine service»).

С точки зрения архитектуры State Management строго разграничивает активное управляющее взаимодействие и пассивные уведомления: в то время как StateMachineService служит исключительно для SMControlApplication с целью воздействия на состояние (AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 «Defined interfaces»), отдельно конфигурируемый сервисный интерфейс StateMachineNotification информирует обычные Adaptive Applications о произошедших изменениях состояния ([SWS_SM_00665]).

Методы, события и поля

Сервисный интерфейс StateMachineService не определяет ни полей (Fields), ни событий (Events), а полностью сосредоточен на синхронном взаимодействии через методы с обратной связью ([SWS_SM_91022], [SWS_SM_91107]). В качестве центральной операции специфицирован метод RequestTransition, который должен вызываться со стороны SMControlApplication для запуска смены состояния в указанном StateMachine ([SWS_SM_91107]).

Метод не смоделирован по принципу Fire-and-Forget (Fire & Forget false) и обрабатывает один входной параметр ([SWS_SM_91107]):

  • TransitionRequest (направление: IN, тип: TransitionRequestType): содержит конкретное значение запроса, заданное в качестве триггера в TransitionRequestTable, сконфигурированном для автомата состояний ([SWS_SM_91107], AUTOSAR_AP_SWS_StateManagement §7.8 «TransitionRequestTable»).

Интерпретация: поскольку выходной параметр (OUT) не объявлен, успешный вызов метода в ara::com, вероятно, предоставляет пустой результат (void) через объект Future, подтверждая для SMControlApplication безошибочное завершение перехода ([SWS_SM_91107]).

Диаграмма последовательности: процесс вызова метода RequestTransition между SMControlApplication и State Management. Источники: [SWS_SM_91107], [SWS_SM_00600].

Жизненный цикл, предоставление и условия выполнения

Предоставление (Offer) StateMachineService напрямую привязано к внутреннему жизненному циклу соответствующего StateMachine: каждый сконфигурированный экземпляр сервиса должен предлагаться через ara::com, как только элемент действия ActionListItem с командой StartStateMachine будет успешно выполнен ([SWS_SM_00618]). Это позволяет SMControlApplication запрашивать переход непосредственно после успешного создания автомата состояний, даже если автомат состояний параллельно еще отрабатывает свой начальный ActionList (AUTOSAR_AP_SWS_StateManagement §7.8 «StateMachine service interfaces - Offer»).

Предоставление сервиса соответственно прекращается (StopOffer), как только StateMachine завершается и сервис больше не должен быть доступен ([SWS_SM_00619]). Во время штатной работы выполнение переходов также зависит от вышестоящих состояний платформы: например, если через Update and Configuration Management выполняется сеанс обновления, запросы переходов блокируются (AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 «Defined interfaces», [SWS_SM_91107]).

Обработка ошибок и Application Errors

Если запрос перехода не может быть выполнен, метод RequestTransition возвращает специальную ошибку Application Error ([SWS_SM_91107]). Для этого интерфейс специфицирует шесть различных кодов ошибок ([SWS_SM_91107]):

Application Error Значение и причина
kInvalidValue Переданное значение TransitionRequest не сопоставлено ни с одним переходом в TransitionRequestTable ([SWS_SM_91107]).
kTransitionNotAllowed Запрошенный переход состояния недопустим, исходя из текущего состояния StateMachine ([SWS_SM_91107]).
kRecoveryTransitionOngoing Запрос не выполняется, так как в настоящее время активен переход восстановления (Recovery) ([SWS_SM_91107]).
kTransitionFailed Во время перехода в запрошенное целевое состояние произошла ошибка ([SWS_SM_91107]).
kOperationCanceled Запрос был вытеснен более новым последующим запросом и вследствие этого отменен ([SWS_SM_91107]).
kUpdateInProgress Запрошенная операция запрещена, так как в данный момент выполняется сеанс обновления ([SWS_SM_91107]).

Вызывающий SMControlApplication должен обрабатывать эти коды ошибок отдельно, чтобы, например, в случае kOperationCanceled ожидать результата последующего запроса или в случае kRecoveryTransitionOngoing и kUpdateInProgress повторить вызов позже ([SWS_SM_91107]).

Данное руководство основано на спецификациях AUTOSAR Adaptive Platform R25-11 для модуля State Management (sm).

Использование и контекст вызова

Сервисный метод RequestTransition вызывается со стороны SMControlApplication через сервисный интерфейс StateMachineService для запроса смены состояния некоторой StateMachine, на которую имеется ссылка ([SWS_SM_91107], SWS StateManagement §7.7 «StateMachine»). Вызов осуществляется не как Fire & Forget ([SWS_SM_91107]). Через параметр TransitionRequest типа TransitionRequestType передается требуемое значение перехода. State Management определяет на основе TransitionRequestTable следующее состояние и запрашивает соответствующие Function Group States у Execution Management через SetState() (EXP SWArchitecture §11.4 «Scenario: Change System State», [SWS_SM_00607]).

Обработка ошибок

Если запрос завершается неудачно или не может быть выполнен, метод возвращает специфические ошибки:

  • kInvalidValue: переданное значение не сконфигурировано в TransitionRequestTable ([SWS_SM_00604]).
  • kTransitionNotAllowed: запрошенный переход недопустим согласно таблице, исходя из текущего состояния StateMachine ([SWS_SM_00603]).
  • kRecoveryTransitionOngoing: устранение ошибки уже выполняется; запрос не обрабатывается ([SWS_SM_00605]).
  • kTransitionFailed: во время отработки ActionListItems произошла ошибка ([SWS_SM_00650]).
  • kOperationCanceled: запрос был отменен, так как был принят более новый запрос для StateMachine ([SWS_SM_00606]).
  • kUpdateInProgress: операция недопустима, поскольку в настоящий момент активна сессия обновления ([SWS_SM_91107]).

Параллелизм и ограничения

Если принимается новое изменение состояния, пока для той же StateMachine еще ожидает завершения предыдущий вызов RequestTransition, последний завершается с kOperationCanceled ([SWS_SM_00606]). Кроме того, отложенное по времени выполнение через Sleep ActionListItem не блокирует входящие триггеры; вызов RequestTransition может вызвать смену состояния даже во время такой фазы ожидания (SWS StateManagement §7.7.9 «ActionListItem Sleep»).

Это указание по использованию основано на предписаниях из AUTOSAR_AP_SWS_StateManagement и AUTOSAR_AP_EXP_SWArchitecture.

<h4>Роль и системный контекст сервисного интерфейса</h4>
<p>Сервисный интерфейс <code>StateMachineService</code> представляет собой основной интерфейс управления Functional Cluster State Management (SM) на AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_SM_91021" href="../spec/record.html?id=SWS_SM_91021">[SWS_SM_91021]</a>, <a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>). При этом кластер State Management выступает в роли поставщика и предоставляет для каждого сконфигурированного экземпляра автомата состояний (<code>StateMachine</code>) собственный сервис на базе ara::com (<a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>). В роли потребителя выступает управляющее приложение <code>SMControlApplication</code>, которое взаимодействует с соответствующим автоматом состояний через соответствующий Proxy для активного запроса смены состояния (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 «Interfaces for a SMControlApplication»</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=141">AUTOSAR_AP_SWS_StateManagement §9.2.2 «StateMachine service»</a>).</p>
<p>С точки зрения архитектуры State Management строго разграничивает активное управляющее взаимодействие и пассивные уведомления: в то время как <code>StateMachineService</code> служит исключительно для <code>SMControlApplication</code> с целью воздействия на состояние (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 «Defined interfaces»</a>), отдельно конфигурируемый сервисный интерфейс <code>StateMachineNotification</code> информирует обычные Adaptive Applications о произошедших изменениях состояния (<a class="spec-record-ref" data-req="SWS_SM_00665" href="../spec/record.html?id=SWS_SM_00665">[SWS_SM_00665]</a>).</p>

<h4>Методы, события и поля</h4>
<p>Сервисный интерфейс <code>StateMachineService</code> не определяет ни полей (Fields), ни событий (Events), а полностью сосредоточен на синхронном взаимодействии через методы с обратной связью (<a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>). В качестве центральной операции специфицирован метод <code>RequestTransition</code>, который должен вызываться со стороны <code>SMControlApplication</code> для запуска смены состояния в указанном <code>StateMachine</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>
<p>Метод не смоделирован по принципу Fire-and-Forget (<code>Fire &amp; Forget false</code>) и обрабатывает один входной параметр (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>):</p>
<ul>
<li><code>TransitionRequest</code> (направление: <code>IN</code>, тип: <code>TransitionRequestType</code>): содержит конкретное значение запроса, заданное в качестве триггера в <code>TransitionRequestTable</code>, сконфигурированном для автомата состояний (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">AUTOSAR_AP_SWS_StateManagement §7.8 «TransitionRequestTable»</a>).</li>
</ul>
<p>Интерпретация: поскольку выходной параметр (OUT) не объявлен, успешный вызов метода в ara::com, вероятно, предоставляет пустой результат (<code>void</code>) через объект Future, подтверждая для <code>SMControlApplication</code> безошибочное завершение перехода (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<h4>Жизненный цикл, предоставление и условия выполнения</h4>
<p>Предоставление (Offer) <code>StateMachineService</code> напрямую привязано к внутреннему жизненному циклу соответствующего <code>StateMachine</code>: каждый сконфигурированный экземпляр сервиса должен предлагаться через ara::com, как только элемент действия <code>ActionListItem</code> с командой <code>StartStateMachine</code> будет успешно выполнен (<a class="spec-record-ref" data-req="SWS_SM_00618" href="../spec/record.html?id=SWS_SM_00618">[SWS_SM_00618]</a>). Это позволяет <code>SMControlApplication</code> запрашивать переход непосредственно после успешного создания автомата состояний, даже если автомат состояний параллельно еще отрабатывает свой начальный <code>ActionList</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=45">AUTOSAR_AP_SWS_StateManagement §7.8 «StateMachine service interfaces - Offer»</a>).</p>
<p>Предоставление сервиса соответственно прекращается (StopOffer), как только <code>StateMachine</code> завершается и сервис больше не должен быть доступен (<a class="spec-record-ref" data-req="SWS_SM_00619" href="../spec/record.html?id=SWS_SM_00619">[SWS_SM_00619]</a>). Во время штатной работы выполнение переходов также зависит от вышестоящих состояний платформы: например, если через Update and Configuration Management выполняется сеанс обновления, запросы переходов блокируются (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 «Defined interfaces»</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<h4>Обработка ошибок и Application Errors</h4>
<p>Если запрос перехода не может быть выполнен, метод <code>RequestTransition</code> возвращает специальную ошибку Application Error (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>). Для этого интерфейс специфицирует шесть различных кодов ошибок (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>):</p>

<tr>

<th>Значение и причина</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>kInvalidValue</code></td>

</tr>
<tr>
<td><code>kTransitionNotAllowed</code></td>
<td>Запрошенный переход состояния недопустим, исходя из текущего состояния <code>StateMachine</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kRecoveryTransitionOngoing</code></td>
<td>Запрос не выполняется, так как в настоящее время активен переход восстановления (Recovery) (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
