Позволяет управляющим приложениям запрашивать смену состояния для сконфигурированных конечных автоматов.

Сервисный интерфейс StateMachineService предоставляется State Management для каждого сконфигурированного конечного автомата, чтобы SMControlApplication могло целенаправленно запрашивать смену состояния через метод RequestTransition [SWS_SM_00600], [SWS_SM_91107]. Сервис предлагается непосредственно после успешного выполнения шага запуска конечного автомата и квитирует запросы без семантики Fire-and-Forget. Однако запросы отклоняются со специфическими ошибками, если переданное значение недействительно, переход из текущего состояния недопустим или одновременно активен сеанс обновления либо восстановления (Recovery) [SWS_SM_91107].

Роль и системный контекст сервисного интерфейса

Сервисный интерфейс StateMachineService предоставляется функциональным кластером State Management (SM) через стандартизированный сервисный порт [SWS_SM_91021]. Согласно формальному определению интерфейса [SWS_SM_91022], State Management инстанцирует и предлагает данный сервис на базе ara::com для каждого отдельного сконфигурированного экземпляра StateMachine [SWS_SM_00600].

В качестве основного потребителя (Consumer) этого интерфейса выступает SMControlApplication, которое напрямую взаимодействует с конечным автоматом через данный сервис для запроса смены состояний SWS StateManagement §9.2.2 «StateMachine service». В то время как уведомления о наступивших состояниях передаются обычным адаптивным приложениям преимущественно через отдельный сервисный интерфейс StateMachineNotification [SWS_SM_00665], StateMachineService представляет собой активный интерфейс управления для инициирования переходов.

Методы и семантика вызова

Интерфейс определяет метод RequestTransition, который должен вызываться SMControlApplication для выполнения изменения состояния в указанном StateMachine [SWS_SM_91107]. Метод ожидает входной параметр TransitionRequest типа TransitionRequestType, представляющий требуемое значение перехода в базовом TransitionRequestTable [SWS_SM_91107], SWS StateManagement §7.x «TransitionRequestTable».

Для RequestTransition свойство Fire & Forget установлено в false [SWS_SM_91107]. Таким образом, вызывающее приложение получает обязательное квитирование запроса. Интерпретация: в рамках паттерна прокси-скелетона ara::com обратная связь, как правило, должна предоставляться через ara::core::Future или соответствующий объект результата, который завершается успешно в случае успеха или передает специфический статус ошибки в случае сбоя.

Жизненный цикл и зависимости от состояний

Каждый сконфигурированный для запускаемого StateMachine сервис ara::com — включая StateMachineService — должен быть доступен и предлагаться (Offer), как только ActionListItem «StartStateMachine» будет успешно выполнен [SWS_SM_00618]. Это позволяет SMControlApplication запрашивать переход сразу после успешного создания конечного автомата, даже если конечный автомат в этот момент все еще обрабатывает начальное ActionList SWS StateManagement §7.x «StateMachine service interfaces - Offer».

Предложение сервиса прекращается (StopOffer), как только начинается обработка останова соответствующего конечного автомата [SWS_SM_00619]. Вызовы также подчиняются функциональным предварительным условиям: если в системе в данный момент выполняется сеанс обновления, инициация смены состояний принципиально недопустима [SWS_SM_91107].

Обработка ошибок и Application Errors

При выполнении RequestTransition могут возникать специфические Application Errors, о которых State Management сообщает вызывающей стороне [SWS_SM_91107]:

  • kInvalidValue: переданное значение не сопоставлено ни с одним переходом в TransitionRequestTable [SWS_SM_91107].
  • kTransitionNotAllowed: запрошенный переход состояния недопустим, исходя из текущего состояния StateMachine [SWS_SM_91107].
  • kRecoveryTransitionOngoing: запрос отклонен, так как в данный момент выполняется устранение ошибок (Recovery) [SWS_SM_91107].
  • kTransitionFailed: во время выполнения перехода в целевое состояние произошла ошибка [SWS_SM_91107].
  • kOperationCanceled: запрос был отменен, так как он был заменен более новым запросом [SWS_SM_91107].
  • kUpdateInProgress: операция запрещена, так как в данный момент активен сеанс обновления [SWS_SM_91107].

Диаграмма последовательности: процесс запроса перехода через StateMachineService с предоставлением, квитированием успешного выполнения и обработкой ошибок. Источники: [SWS_SM_91107], [SWS_SM_00618], SWS StateManagement §7.x «StateMachine service interfaces - Offer».

RequestTransition (IN TransitionRequestType TransitionRequest)

Has to be called by a SMControlApplication to request a change in the referenced StateMachine.

Использование

Сервисный метод RequestTransition вызывается из SMControlApplication на интерфейсе StateMachineService для запроса смены состояния ассоциированного StateMachine ([SWS_SM_91107], SWS StateManagement §7.7 «SMControlApplication»). В качестве параметра передается TransitionRequest. Метод возвращает значения и не работает по принципу Fire-and-Forget. State Management сопоставляет входное значение через TransitionRequestTable в зависимости от текущего состояния со следующим состоянием ([SWS_SM_00607]) и запрашивает результирующие Function Group States через SetState() у Execution Management (AP EXP SWArchitecture §11.1 «Change System State»).

Обработка ошибок

В случае сбоя обработка прерывается и RequestTransition возвращает специфичные прикладные ошибки ([SWS_SM_91107]):

  • kInvalidValue: переданное значение для TransitionRequest не сконфигурировано в TransitionRequestTable ([SWS_SM_00604]).
  • kTransitionNotAllowed: переход, исходя из текущего состояния StateMachine, согласно конфигурации недопустим ([SWS_SM_00603]).
  • kRecoveryTransitionOngoing: активно внутреннее устранение ошибок, поэтому запрос дальше не обрабатывается ([SWS_SM_00605]).
  • kUpdateInProgress: во время активного сеанса обновления смена состояния недопустима ([SWS_SM_91107]).
  • kTransitionFailed: при обработке ActionListItems произошла ошибка ([SWS_SM_00650]).

Параллелизм и ограничения

Если принимается новый запрос на переход в то время, как для того же StateMachine еще ожидает выполнения более ранний вызов RequestTransition, предыдущий запрос отменяется и подтверждается с kOperationCanceled ([SWS_SM_00606]). Действия, управляемые по времени, такие как Sleep ActionListItem, не блокируют входящие триггеры; поэтому вызов RequestTransition может инициировать смену состояния также и во время такого ожидания (SWS StateManagement §7.7.9 «ActionListItem Sleep»).
