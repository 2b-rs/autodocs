## Implementation

### Design

`DEC-0043-003` requires the page model to be bound to **exactly one**
schema-valid tracked ledger entry, using at least `combined_report_digest`,
`recorded_at` and `run_archive_ref`. Implemented as:

1. **Producer** — `_src/tools/build_report.py`:
   - `publication_provenance(ledger_path, rendered_run_archive_ref, previous)`
     derives the binding from the tracked ledger alone (`entries[-1]`, the
     newest schema-valid entry). It never needs the raw combined report, which
     lives under git-ignored `output/` per `DEC-0043-001` and is absent in any
     clean checkout.
   - `generate_report_page()` writes the object into the page model under the
     new top-level key `publication_provenance`.
   - New command `build_report.py provenance` recomputes **only** the binding
     of an existing page model, leaving the rendered body untouched. This is
     the supported path when the raw combined report of the recorded run no
     longer exists — the exact situation of the historic backfilled entry.
   - `bound_at` records when *this binding* was established and is preserved
     while the binding is unchanged, so republishing the same run produces a
     **byte-identical** tracked page model (no diff churn).
   - `combine`/`publish` with `--no-ledger` now mark the combined report
     `"diagnostic_no_ledger": true`. This is the machine-readable distinction
     `DEC-0043-003` requires between an expressly diagnostic cohort (not a
     publication candidate) and a publication run whose ledger append merely
     **failed** (still a finding).
2. **Gate** — `_src/validate.py`, one focused named check
   `check_report_freshness()`, using the existing `record_finding()` mechanism
   and severity model, registered in `main()` alongside the other checks.

### Firing conditions — exactly the closed list B-02

- **(a) `stale-build-report`** — the page model's `publication_provenance` is
  missing, unreadable, of unknown `schema_version`, or does not match the
  newest schema-valid ledger entry on `recorded_at` / `run_archive_ref` /
  `combined_report_digest`; a binding with a null `run_archive_ref` that is not
  marked `backfilled`; or a page body rendered from a cohort other than the one
  bound.
- **(b) `unrecorded-publication-run`** — a **complete**, non-diagnostic
  publication cohort under `output/build-reports/` has no matching entry in
  `docs/evidence/build-ledger.jsonl`.

Malformed ledger data is passed through with the ledger's own categories
(`malformed-build-ledger`, `duplicate-build-ledger-entry`,
`rewritten-build-ledger`, `build-ledger-baseline-unavailable`) per the `0043-02`
consumer contract. **No firing condition beyond B-02 was added.**

### False-positive guards (B-03)

- A cohort is a publication candidate only when **complete**: all four required
  stages, each schema-valid, under one non-empty `run_archive_ref`. An
  incomplete/in-flight cohort never fires.
- The validator's own subreport alone is an incomplete cohort — no
  self-inflicted finding. The canonical sequence's **final** validation runs
  under the same `RUN_ARCHIVE_REF` and therefore creates no newer cohort.
- Identity-less reports (`run_archive_ref` null/empty) are excluded.
- Diagnostic `--no-ledger` cohorts are excluded via `diagnostic_no_ledger`.
- Decidable from tracked state alone: a fresh clone with an empty — or entirely
  absent — `output/build-reports/` and a page model matching the newest ledger
  entry passes. **Absence of git-ignored artifacts is never itself a finding.**
- Unreadable raw subreport JSON is skipped, not reported: `combine` owns that
  finding, and it is not one of the two firing conditions.

### Read-only

The check never combines, publishes, appends to the ledger, or repairs the
page. It names the missing command in the finding message instead.
