## Backlog-repair note (design resolution, recorded per AGENTS.md Autonomous
backlog repair)

The Task text says to emit the notice "through the canonical `SENTINEL`
retrigger channel," but `SENTINEL.md`'s only concrete mechanism is "create a
new sentinel atomically at `run.sh`," which `SANDBOX.md` explicitly forbids
using as an escalation/notification channel — a contradiction the doctor
itself already detects and reports as `LTD-POLICY-CONTRADICTION`. The doctor
is also contractually read-only (never edits/creates/deletes files, never
touches `run.sh`). Given this, the determinable, intent-preserving resolution
is: the "channel" this Task can actually implement inside the doctor is its
existing non-mutating findings/plans/summary pipeline — the same advisory
mechanism the doctor already uses for every other reconciliation notice. A new
info-severity finding rule `LTD-FEATURE-INTEGRATION-READY` (message names the
ready Feature and states it needs an explicitly assigned privileged
integrator) realizes the notice through that pipeline; no file is created or
written by the tool. This is documented in
`docs/pipeline/legacy-task-doctor.md`.

The Task also says "on transition to ready or during an otherwise-idle global
scan." The doctor is a stateless single-pass scanner with no persisted
prior-run state, so it cannot itself detect a *transition*. Resolution:
treat every invocation as satisfying the "otherwise-idle global scan" arm of
the OR — the notice fires deterministically whenever the Feature is currently
ready. Detecting the transition edge is left to a caller diffing two report
runs, not to hidden mutable state in a read-only tool. Documented in the same
file.
