يتيح التخزين الدائم لبيانات التطبيق وإدارتها عبر مخازن المفتاح والقيمة ومخازن الملفات.

يوفر فضاء التسمية ara::per واجهات للتخزين الدائم للبيانات من خلال تمكين التطبيقات التكيفية من الوصول إلى نطاقات التخزين القائمة على الملفات وتلك القائمة على المفتاح والقيمة عبر معرّفات المثيلات ([SWS_PER_00052]، [SWS_PER_00116]). وتدير التطبيقات المخازن المفتوحة عبر مقابض مشتركة، وتجري تحديثات منسقة عند تغييرات البيان (Manifest)، ويمكنها إصلاح البيانات غير المتسقة عبر آليات الاستعادة ([SWS_PER_00333]، [SWS_PER_00357]). وبينما تتم عمليات الوصول إلى التخزين بشكل متزامن عبر المقابض، تتطلب العمليات الإدارية مثل التحديثات أو إعادة ضبط التخزين غياب عمليات الوصول المتزامنة ([SWS_PER_00311]).

السياق

يوفر فضاء التسمية ara::per واجهات المجموعة الوظيفية للاستمرارية لـ AUTOSAR Adaptive Platform. وتتمثل مسؤوليته الأساسية في التخزين الدائم لبيانات التطبيق بما يتجاوز الذاكرة عبر عمليات إعادة تشغيل النظام ودورات حياة العمليات. وتميز الوحدة بين نموذجي تخزين أساسيين: KeyValueStorage لأزواج المفتاح والقيمة المنظمة، وFileStorage للوصول إلى التخزين القائم على الملفات. وتصل التطبيقات التكيفية إلى هذه الموارد عبر نماذج المنافذ المكونة باستخدام ara::core::InstanceSpecifier ([SWS_PER_00052]، [SWS_PER_00116]).

الشركاء المهمون للتفاعل مع فضاء التسمية هم Update and Configuration Management (UCM)، الذي يمكنه توفير تكوينات مستهدفة (Target Configuration) محدثة أثناء وقت التشغيل ([SWS_PER_00576]، [SWS_PER_00577])، وكذلك وسيط التخزين المادي، الذي يضمن ara::per عليه الاتساق والتكرار وأمان البيانات ([SWS_PER_00311]).

مخطط السياق: التفاعل بين التطبيق، وara::per، وإدارة التحديث، والتخزين المادي. المصادر: [SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00576]

دورة الحياة

يتم تنظيم الوصول إلى كائنات التخزين عبر تجريدات المقابض. ويؤدي فتح وحدة تخزين عبر OpenKeyValueStorage أو OpenFileStorage إلى إنشاء SharedHandle ([SWS_PER_00052]، [SWS_PER_00116]). ونظرًا لأن عدة خيوط يمكنها الوصول بالتزامن إلى نفس وحدة التخزين، فلا يتم بالضرورة إغلاق المورد المادي عند خروج SharedHandle فردي من نطاق صلاحيته؛ بل يتم الإغلاق فقط عند إزالة جميع مثيلات SharedHandle المُسندة ([SWS_PER_00052]، [SWS_PER_00116]).

بالنسبة للملفات الموجودة داخل FileStorage، يتم تتبع حالات الإنشاء والتعديل بالتفصيل. ويمثل التعداد FileCreationState ما إذا كان الملف قد أُنشئ أثناء التثبيت (kCreatedDuringInstallation)، أو أثناء التحديث (kCreatedDuringUpdate)، أو عبر إعادة الضبط (kCreatedDuringReset)، أو نتيجة للاستعادة (kCreatedDuringRecovery)، أو بواسطة التطبيق نفسه (kCreatedByApplication) ([SWS_PER_00435]). وبشكل مماثل، يعكس FileModificationState متى وعبر أي عملية تم تعديل الملف لآخر مرة ([SWS_PER_00436]).

لإدارة الحالات الأولية، يوفر فضاء التسمية دوال إعادة الضبط: حيث يعيد ResetKeyValueStorage ([SWS_PER_00334]) وResetAllFiles ([SWS_PER_00336]) مخازن فردية إلى القيم التي تم تعريفها مبدئيًا في البيان. وفي المقابل، تُفرغ العملية العامة ResetPersistency ([SWS_PER_00358]) جميع مخازن المفتاح والقيمة ومخازن الملفات بالكامل؛ ويحدث إعادة إنشائها عند الاستدعاء التالي لـ OpenFileStorage أو OpenKeyValueStorage.

فيما يتعلق بالتزامن، فإن دوال الفتح (OpenFileStorage، OpenKeyValueStorage)، واستعلامات حجم التخزين (GetCurrentFileStorageSize، GetCurrentKeyValueStorageSize)، وكذلك دوال الاستعادة وإعادة الضبط الخاصة بالتخزين آمنة خيطيًا ([SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00405]، [SWS_PER_00406]، [SWS_PER_00333]، [SWS_PER_00334]، [SWS_PER_00335]، [SWS_PER_00336]). وبالمقابل، فإن عمليات التحديث والتنظيف العامة مثل UpdatePersistency ([SWS_PER_00357])، وCleanUpPersistency ([SWS_PER_00567])، وResetPersistency ([SWS_PER_00358])، وCheckForManifestUpdate ([SWS_PER_00576])، وReloadPersistencyManifest ([SWS_PER_00577]) مصرح عنها بأنها غير آمنة خيطيًا.

مسار الاستخدام

يتضمن مسار التطبيق النموذجي التحقق من تحديثات التكوين، وتطبيق ترحيل البيانات، والوصول اللاحق إلى التخزين:

قبل التشغيل المنتظم أو أثناءه، يتحقق التطبيق باستخدام CheckForManifestUpdate مما إذا كانت UCM قد قامت بتثبيت تكوين مستهدف جديد ([SWS_PER_00576]). وإذا كان الأمر كذلك، تتم قراءة البيان الجديد عبر ReloadPersistencyManifest ([SWS_PER_00577]). وأثناء مرحلة التحقق اللاحقة، يبدأ التطبيق UpdatePersistency ([SWS_PER_00357]). وللتحكم في عمليات ترحيل البيانات الخاصة بالإصدار، يسجل التطبيق مسبقًا عبر RegisterApplicationDataUpdateCallback دالة معاودة اتصال يتم إعلامها بإصدارات العقود الأقدم وتنفذ خطوات الترحيل الخاصة بالتطبيق ([SWS_PER_00356]). بالإضافة إلى ذلك، يمكن مراقبة تغييرات العناصر باستخدام RegisterDataUpdateIndication ([SWS_PER_00578]). وبعد اكتمال التحديث، يزيل CleanUpPersistency النسخ الاحتياطية القديمة والأصول الزائدة عن الحاجة ([SWS_PER_00567]).

للوصول المنتظم، يفتح التطبيق المورد المستهدف عبر OpenKeyValueStorage ([SWS_PER_00052]) أو OpenFileStorage ([SWS_PER_00116]). وتتم إدارة عمليات الوصول إلى الملفات في FileStorage عبر أقنعة بتات التعداد OpenMode (مثل kAtTheBeginning، وkAtTheEnd، وkTruncate، وkAppend)، والتي يتم دمجها عبر المعاملين operator| ([SWS_PER_00144]) وoperator|= ([SWS_PER_00434]) ([SWS_PER_00147]). وتتم عمليات تحديد الموضع بالنسبة إلى Origin (kBeginning، kCurrent، kEnd) ([SWS_PER_00146]). ويمكن تحديد حجم التخزين المشغول حاليًا في وقت التشغيل عبر GetCurrentKeyValueStorageSize ([SWS_PER_00405]) وGetCurrentFileStorageSize ([SWS_PER_00406]).

مخطط تسلسلي: تسلسل للتحقق من تحديثات البيان، وتنفيذ التحديث، ثم الوصول لاحقًا إلى مخزن المفتاح والقيمة. المصادر: [SWS_PER_00052]، [SWS_PER_00356]، [SWS_PER_00357]، [SWS_PER_00567]، [SWS_PER_00576]، [SWS_PER_00577]

سيناريوهات الأخطاء

تتم الإشارة إلى الأخطاء في فضاء التسمية بشكل قياسي عبر التعداد PerErrc ([SWS_PER_00311]) مقترنًا بـ PerErrorDomain ([SWS_PER_00352]) وMakeErrorCode ([SWS_PER_00351]). ومن المتوقع أن تعمل الفئة المصرح عنها PerException كنوع استثناء C++ للبيئات التي لا تتم فيها معالجة الأخطاء عبر ara::core::Result، بل عبر الاستثناءات (تفسير).

تشمل سيناريوهات الخطأ المركزية ما يلي:

  • أخطاء التكوين والعنونة: إذا كان InstanceSpecifier المُمرَّر لا يطابق أي PortInterface مُهيأ في النموذج، يفشل الفتح مع PerErrc::kStorageNotFound ([SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00311]). وتؤدي عمليات الوصول إلى ملفات غير موجودة إلى توليد PerErrc::kFileNotFound ([SWS_PER_00311]).
  • تعارضات الموارد: عندما تكون وحدات التخزين مفتوحة أو يجري تشغيل أوامر إدارية في الوقت نفسه، تفشل عمليات مثل OpenKeyValueStorage، OpenFileStorage، RecoverKeyValueStorage، RecoverAllFiles، ResetKeyValueStorage، ResetAllFiles، UpdatePersistency، CleanUpPersistency أو ResetPersistency مع PerErrc::kResourceBusy ([SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00333]، [SWS_PER_00334]، [SWS_PER_00335]، [SWS_PER_00336]، [SWS_PER_00357]، [SWS_PER_00358]، [SWS_PER_00567]).
  • فقدان السلامة والاستعادة: في حالات التلف الهيكلي (PerErrc::kIntegrityCorrupted) أو فشل فحوصات التكرار (PerErrc::kValidationFailed)، يتيح ara::per استعادة بأفضل جهد ممكن عبر RecoverKeyValueStorage ([SWS_PER_00333]) أو RecoverAllFiles ([SWS_PER_00335]). وعبر RegisterRecoveryReportCallback ([SWS_PER_00433])، يمكن للتطبيقات ذات الصلة بالسلامة تسجيل تدابير التصحيح تلقائيًا بالاستناد إلى RecoveryReportKind (مثل kKeyValueStorageRecovered، kFileRecovered) ([SWS_PER_00432]).
  • حدود التخزين والأخطاء المادية: في حال تجاوز الحصص النسبية أو السعات المادية، يتم الإبلاغ عن PerErrc::kOutOfStorageSpace، PerErrc::kQuotaExceeded أو PerErrc::kTooManyFiles ([SWS_PER_00311]). وتؤدي أخطاء العتاد أو نظام الملفات إلى PerErrc::kPhysicalStorageFailure ([SWS_PER_00311]).
  • الأمان وأنماط الوصول: إذا فشلت عمليات التحقق أو الحسابات التشفيرية، يُرجع النموذج PerErrc::kEncryptionFailed أو PerErrc::kAuthenticationFailed ([SWS_PER_00311]). وتُرفض محاولات الكتابة على مساحات تخزين محمية ضد الكتابة باستخدام PerErrc::kIllegalWriteAccess ([SWS_PER_00311]).

يستند هذا الدليل حصريًا إلى مواصفة AUTOSAR Adaptive R25-11.

Registers an application data update callback with Persistency. The provided callback function will be called by Persistency if an update of stored application data might be necessary.
