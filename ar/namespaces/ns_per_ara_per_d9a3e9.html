السياق

توفر مساحة الاسم ara::per لتطبيق Adaptive Application آليات استدامة قياسية لحفظ البيانات المتعلقة بالتطبيق بشكل دائم عبر دورات التنفيذ وإعادة تشغيل المنصة. وتُميز البنية الوظيفية بين نموذجين أساسيين للتخزين: الوصول القائم على المفاتيح إلى مجموعات البيانات المهيكلة عبر KeyValueStorage، والتخزين القائم على الملفات لكميات البيانات غير المهيكلة عبر FileStorage. ويتم التصريح عن كلا نوعي التخزين منطقيًا عبر نماذج المنافذ الأولية في نموذج AUTOSAR وتتم عنونتهما في التعليمات البرمجية للتطبيق عبر ara::core::InstanceSpecifier ([SWS_PER_00052]، [SWS_PER_00116]).

يتم التفاعل بين التطبيق ووحدة الاستدامة عبر مقابض محددة النوع: يُدير SharedHandle الوصول المحسوب المراجع إلى حالات التخزين KeyValueStorage وFileStorage، بينما يُغلّف UniqueHandle وصول القراءة أو الكتابة الحصري عبر معاملات الوصول مثل ReadAccessor أو WriteAccessor أو ReadWriteAccessor. وبالنسبة للعمليات القائمة على الملفات، يُحدد OpenMode ([SWS_PER_00147]، [SWS_PER_00144]، [SWS_PER_00434]) وOrigin ([SWS_PER_00146]) دلالات قياسية لمؤشرات الملفات وفتحها. وإلى جانب التفاعل الأساسي مع التطبيق، يتفاعل ara::per بشكل وثيق مع Update and Configuration Management (UCM)، من خلال اكتشاف تحديثات البرمجيات والبيانات الوصفية (Manifest) ومزامنة أصول البيانات ذات الإصدارات المحددة ([SWS_PER_00576]، [SWS_PER_00577]).

مخطط سياقي: تفاعل Adaptive Application وUCM وأنظمة التخزين الخاصة بـ ara::per. المصادر: [SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00576]

دورة الحياة وإدارة الذاكرة

يتم فتح مثيلات التخزين من خلال استدعاء OpenKeyValueStorage ([SWS_PER_00052]) أو OpenFileStorage ([SWS_PER_00116]) وإنشاؤها كمثيل SharedHandle. ويتم تحرير الموارد المادية بشكل حتمي عبر دورة حياة المقابض: ونظرًا لأن سلاسل عمليات متعددة يمكنها فتح مثيل تخزين بشكل متزامن، فلا يتم إغلاق المورد المادي إلا بعد أن تغادر جميع مثيلات SharedHandle النشطة نطاق الصلاحية ([SWS_PER_00052]، [SWS_PER_00116]). وفي وقت التشغيل، يمكن الاستعلام عن مساحة التخزين المشغولة بما في ذلك بيانات التكرار والبيانات الوصفية عبر GetCurrentKeyValueStorageSize ([SWS_PER_00405]) وGetCurrentFileStorageSize ([SWS_PER_00406]).

في سياق تحديثات البرمجيات بواسطة UCM، يتيح CheckForManifestUpdate ([SWS_PER_00576]) اكتشاف التكوينات الهدف المعدلة أثناء وقت التشغيل. وعبر ReloadPersistencyManifest ([SWS_PER_00577]) تتم قراءة التكوين الجديد قبل أن يُطلق UpdatePersistency ([SWS_PER_00357]) أو إعادة فتح وحدات التخزين عملية الترحيل. ولإجراء عمليات تكييف البيانات عبر المخططات، يسجل التطبيق مسبقًا إجراءات ترحيل روتينية عبر RegisterApplicationDataUpdateCallback ([SWS_PER_00356]) أو إشعارات تغيير عبر RegisterDataUpdateIndication ([SWS_PER_00578]). وبعد اكتمال التحديث بنجاح، يمكن إزالة البيانات القديمة والنسخ الاحتياطية باستخدام CleanUpPersistency ([SWS_PER_00567]). وإذا كان يلزم إجراء إعادة ضبط إلى حالة المصنع أو حالة التثبيت، فإن ResetKeyValueStorage ([SWS_PER_00334]) أو ResetAllFiles ([SWS_PER_00336]) أو عالميًا ResetPersistency ([SWS_PER_00358]) تنقل المحتويات إلى حالة النشر الخاصة بها. وتوثق عمليتا التعداد FileCreationState ([SWS_PER_00435]) وFileModificationState ([SWS_PER_00436]) أصل وحالة الملفات الفردية.

مسار الاستخدام: الوصول إلى الملفات ودورة حياة الاستدامة

يتضمن مسار الاستخدام النموذجي للاستدامة المعتمدة على الملفات تسجيل آليات المراقبة، وفتح وحدة التخزين، والوصول إلى الملفات، وتحرير الموارد بشكل نظامي:

  1. التكوين وتسجيل عمليات الاستدعاء: تسجل التطبيقات ذات الصلة بالسلامة عند الحاجة مسبقًا عمليات استدعاء لتسجيل الأخطاء بواسطة RegisterRecoveryReportCallback ([SWS_PER_00433]) وكذلك لإشعارات التحديث ([SWS_PER_00356]).
  2. فتح وحدة التخزين: يستدعي التطبيق OpenFileStorage باستخدام ara::core::InstanceSpecifier المخطط ([SWS_PER_00116]) ويحصل عند النجاح على SharedHandle<FileStorage>.
  3. إعداد الوصول إلى الملف: باستخدام رايات ثنائية من OpenMode ([SWS_PER_00147]، [SWS_PER_00144]، [SWS_PER_00434])، يطلب التطبيق الوصول إلى الملف، والذي يُعاد كـ UniqueHandle لعوامل القراءة أو الكتابة.
  4. الإكمال والتنظيف: بعد مغادرة نطاق صلاحية مقابض الوصول والتخزين، يتم إغلاق وحدة التخزين. وفي حال وجود عمليات تنظيف معلقة للنظام، يقوم CleanUpPersistency بإزالة بيانات النسخ الاحتياطي المؤقتة ([SWS_PER_00567]).

مخطط تسلسلي: مسار فتح وحدة تخزين الملفات مع عمليات الاستدعاء والإكمال اللاحق. المصادر: [SWS_PER_00433]، [SWS_PER_00116]، [SWS_PER_00567]

سيناريوهات الأخطاء والاستعادة

تشير جميع العمليات الفاشلة إلى أخطاء عبر ara::core::Result برموز من التعداد PerErrc ([SWS_PER_00311])، مدمجة في مجال الخطأ PerErrorDomain ([SWS_PER_00351]، [SWS_PER_00352]) أو كـ PerException. وتميز المواصفة بين أسباب الأخطاء الأساسية:

  • تعارضات الموارد (PerErrc::kResourceBusy): يحدث عند الوصول إلى وحدة تخزين في حين تكون العمليات الإدارية المتوازية مثل UpdatePersistency ([SWS_PER_00357]) أو CleanUpPersistency ([SWS_PER_00567]) أو ResetPersistency ([SWS_PER_00358]) أو إجراءات الاستعادة الروتينية نشطة ([SWS_PER_00052]، [SWS_PER_00116]).
  • أخطاء السلامة والتكرار: تؤدي تلفيات الوسائط المادية (kPhysicalStorageFailure)، أو فقدان سلامة البيانات الوصفية (kIntegrityCorrupted)، أو أخطاء التحقق من الصحة (kValidationFailed)، أو أخطاء فحص التشفير أو فحص MAC (kEncryptionFailed، kAuthenticationFailed) إلى منع الوصول العادي ([SWS_PER_00052]، [SWS_PER_00116]، [SWS_PER_00311]).
  • الاستعادة (Recovery): في حالة تلف بيانات التكرار، يتيح RecoverKeyValueStorage ([SWS_PER_00333]) أو RecoverAllFiles ([SWS_PER_00335]) إجراء استعادة بأفضل جهد ممكن. ويتم توضيح الأحداث المبلغ عنها عبر RegisterRecoveryReportCallback ([SWS_PER_00433]) بشكل متمايز بواسطة RecoveryReportKind ([SWS_PER_00432])، على سبيل المثال ما إذا كان قد أمكن إصلاح العناصر التالفة بالكامل استنادًا إلى نسخ التكرار المتبقية أو أنها فُقدت.
  • أخطاء التكوين والحصص: يؤدي المعرّف غير المناسب إلى kStorageNotFound، بينما يتم الإبلاغ عن تجاوزات الكتابة ومساحة التخزين عبر kQuotaExceeded أو kOutOfStorageSpace أو kTooManyFiles ([SWS_PER_00311]). وتؤدي المعلمات غير الصالحة عند تغيير الموضع أو الحجم إلى kInvalidPosition أو kInvalidSize أو kInvalidOpenMode ([SWS_PER_00311]).

يستند هذا الدليل حصريًا إلى متطلبات مواصفات AUTOSAR Adaptive R25-11 لـ ara::per.

                                                                                      ara::core::Result< void > ResetKeyValueStorage (const ara::core::InstanceSpecifier &kvs) noexcept;
                                                                                      

                                                                                      Resets a Key-Value Storage to the initial state. ResetKeyValueStorage allows to reset a Key-Value Storage to the initial state, containing only key-value pairs which were deployed from the Target Configuration, with their initial values. Afterwards, the Key-Value Storage will appear as if it was newly installed from the current Target Configuration. It will fail with kResourceBusy when the Key-Value Storage is currently open, or when it is modified by a call from another thread to UpdatePersistency, CleanUpPersistency, Reset Persistency, RecoverKeyValueStorage, or ResetKeyValueStorage.
