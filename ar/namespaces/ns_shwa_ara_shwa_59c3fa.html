السياق

توفر مساحة الاسم ara::shwa (Safe Hardware Acceleration) واجهات لاكتشاف مسرعات الأجهزة (مثل وحدات معالجة الرسومات أو وحدات المعالجة المركزية) وتخصيصها واستخدامها للمهام كثيفة الحوسبة على AUTOSAR Adaptive Platform. تفصل الوحدة بنيوياً بين استكشاف النظام، وإدارة الموارد، ومعالجة المهام غير المتزامنة الفعلية.

تشكل Platform وحدة الاكتشاف المركزية، والتي يتم من خلالها تحديد منصات مسرعات الأجهزة المتاحة في النظام والاستعلام عن نسخ Device المتصلة. لاختيار أهداف تنفيذ محددة، توفر مساحة الاسم محددات مثل DeviceSelector وCpuSelector وGpuSelector وAcceleratorSelector، والتي يتم بمساعدتها تحديد Device مناسب استناداً إلى رتب خاصة بالتطبيق أو بنيات معمارية مستهدفة.

لا يتم بدء المهام مباشرة على Device، بل يتم تنسيقها عبر Queue، والتي تتحكم في المعالجة المتوازية على الهدف المحدد. وتوفر البيانات عبر Buffer، ويحدد حجمها عبر Range، ويؤمن وصولها إلى الذاكرة عبر Accessor. وبذلك يغطي تفاعل المكونات الأساسية الاختيار وإدارة الذاكرة والتنفيذ المتوازي.

مخطط السياق: تفاعل الفئات الأساسية أثناء الاكتشاف والتخصيص والتنفيذ في ara::shwa. المصادر: أوصاف فئات الحمولة Platform، Device، Queue، Buffer، Accessor.

دورة الحياة

في دورة حياة الكائنات المعنية، يميز ara::shwa بدقة بين الكيانات المالكة للموارد وغير المالكة لها:

  • الكائنات المالكة للموارد: تمتلك Queue وBuffer وAccessor موارد أجهزة أو ذاكرة محددة. وهي صراحة غير قابلة للنسخ (non-copyable) ومصممة لتتم إدارتها حصرياً عبر std::unique_ptr ونقلها (move) عند الحاجة.
  • الكائنات المرجعية الخالية من الموارد: لا تمتلك Platform وDevice وDeviceMonitor وId وRange الموارد الأساسية بنفسها. وهي مصممة كواصفات ومقابض قابلة للنسخ (copyable).
  • الكائنات المرتبطة بـ Queue: لا يمكن إنشاء نسخ من Event (للمزامنة بين المضيف وHWA) وكذلك TaskHandler (للتحكم في تنفيذ المهام) إلا داخل Queue حصراً؛ وخارج الـ Queue لا تملك أي أهمية وظيفية.

يعكس Device فيما يتعلق بتوفره حالات تشغيل منفصلة يتم تمثيلها عبر التعداد DeviceStatus [AP_SWS_SHWA_00103]. وقبل تخصيص المهمة، تشير الحالة kReady إلى الجاهزية للتنفيذ، بينما تقيد kNotAccesible أو kFailure أو kUnknown الاستخدام أو تمنعه.

مخطط الحالة: حالات تشغيل جهاز مسرع الأجهزة وفقاً لـ DeviceStatus. المصادر: [AP_SWS_SHWA_00103].

مسار الاستخدام

يمتد مسار المعالجة النموذجي عبر عدة فئات في مساحة الاسم ويتبع تسلسلاً ثابتاً من اختيار الجهاز، وإنشاء خط أنابيب التنفيذ، والتخزين المؤقت في الذاكرة، والمعالجة المتزامنة:

  1. اختيار المنصة والجهاز: يقرأ التطبيق الأجهزة المتاحة عبر Platform أو يستخدم DeviceSelector (أو GpuSelector أو CpuSelector أو AcceleratorSelector) لاختيار نسخة Device الأنسب ذات الرتبة الأعلى.
  2. إنشاء نسخة Queue: للمعالجة المتوازية، يتم إنشاء Queue كـ std::unique_ptr<Queue> لـ Device المحدد.
  3. تخصيص الذاكرة وإدارة الوصول: تُحدد الأبعاد عبر Range. بعد ذلك، يتم إنشاء Buffer لتخصيص الذاكرة على المضيف أو المسرع. ولإجراء عمليات قراءة وكتابة خاضعة للتحكم، يتم إنشاء نسخة من Accessor، ويُحدد نمطها عبر AccessMode كـ kRead أو kWrite أو kReadWrite [AP_SWS_SHWA_00101].
  4. إرسال المهام والمزامنة: عبر Queue، يتم إدراج TaskHandler في قائمة الانتظار للتنفيذ على الهدف (المحدد عبر Target::kDevice أو Target::kHostTask [AP_SWS_SHWA_00102]). وتتم المزامنة بين تطبيق المضيف ومعالجة HWA باستخدام Event تم إنشاؤه داخل الـ Queue.

مخطط التسلسل: المسار النموذجي لاختيار الجهاز، وإدارة المخزن المؤقت، وتخصيص Queue، ومزامنة المهام. المصادر: أوصاف فئات الحمولة Platform، DeviceSelector، Queue، Buffer، Accessor، TaskHandler، Event بالإضافة إلى [AP_SWS_SHWA_00101] و[AP_SWS_SHWA_00102].

سيناريوهات الأخطاء

صُممت API الخاصة بـ Safe Hardware Acceleration لتكون خالية من الاستثناءات بشكل أساسي (exception-free). تُشير العمليات إلى الأخطاء عبر رموز أخطاء من النوع ara::core::ErrorCode، والتي ترتبط بنطاق الخطأ المحدد ShwaErrorDomain.

يتم الوصول إلى النطاق عبر GetShwaDomain() [AP_SWS_SHWA_01311]، بينما يتم إنشاء رموز الأخطاء القياسية عبر الدالة المساعدة MakeErrorCode() [AP_SWS_SHWA_01312]. ويحدد التعداد ShwaErrorCode، من بين أمور أخرى، الأسباب التالية [AP_SWS_SHWA_01301]:

  • kRuntime: خطأ تشغيل عام أثناء التشغيل.
  • kTaskExecutionFailure: خطأ في تنفيذ مهمة تم تمريرها على المسرع أو المضيف.
  • kMemoryNotAllocated: فشل تخصيص ذاكرة العمل بواسطة Buffer.
  • kIntegrityCorrupted: تعذر الحفاظ على سلامة ذاكرة Buffer.
  • kResourceBusy: جهاز مطلوب أو مورد Queue مشغول.
  • kInvalidAccessMode وkAccessorFailure: نمط وصول غير مسموح به في AccessMode أو فشل في إنشاء Accessor أو استخدامه.
  • kEventInvalidOperation: عملية غير مسموح بها على كائن مزامنة Event.
  • kFeatureNotSupported: ميزة العتاد المطلوبة غير مدعومة من الواجهة الخلفية أو برنامج التشغيل.
  • kInvalidIndex وkInvalidParameter وkInvalidObject: قيم تمرير غير صحيحة، أو فهارس غير صالحة، أو استخدام كائنات مدمرة بالفعل أو غير صالحة.
  • kTimedOut: انتهاء المهلة أثناء التنفيذ أو المزامنة.

بالنسبة للبنى التي تعتمد على استثناءات C++، تتوفر الفئة ShwaException. لا تطرح API نفسها هذا الاستثناء، إلا أنه يمكن للتطبيقات تحويل رموز الأخطاء إلى استثناءات وتمريرها عند الحاجة. ولإجراء معالجة غير متزامنة للأخطاء على مستوى HWA، يُضمّن التطبيق بالإضافة إلى ذلك ErrorHandler.

اختيار الجهاز

AcceleratorSelector فئة

AcceleratorSelector manages accelerator selection for operations on HWA if available.

CpuSelector فئة

CpuSelector manages CPU selection for operations on HWA if available Allows to get a device from any supported backends for which the device type is CPU.

DeviceSelector فئة

Class allowing to choose the most appropriate device of the available ones. This is a callable object taking a device reference and returning an integer rank. One of the device with the highest non-negative value is selected.

GpuSelector فئة

GpuSelector manages GPU selection for operations on HWA if available Select a device from any supported backends for which the device type is GPU.

تجريد الجهاز

Device فئة

Device class represents HWA device. Provides access to the device but not controlling it. Designed as copyable since not owning resources.

DeviceMonitor فئة

DeviceMonitor API class. Designed as copyable since not owning resources.

Id فئة

Id API class. Designed as copyable since not owning resources.

Platform فئة

Platform class is responsible for extracting different HWA platforms available for current application and listing Devices bind to each platform. Designed as copyable since not owning resources.

Buffer فئة

Range فئة

معالجة الأخطاء

ErrorHandler فئة

ErrorHandler manages asynchronous error handling for operations on HWA.

ShwaErrorDomain فئة

Defines the error domain for Safe Hardware Acceleration.

ShwaException فئة

Exception type could be thrown by application or other FC using Safe Hardware Acceleration. Safe Hardware Acceleration API is exception free and can only return an ErrorCode, but user code can transform this error to exception and throw if it’s alligned with system error handling architecture.
