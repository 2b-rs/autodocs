السياق

توفر مساحة الاسم ara::exec واجهات الوحدة Execution Management على AUTOSAR Adaptive Platform. وتتولى الوحدة مسؤولية دورة حياة العمليات، وتتحكم في بدء تشغيل النظام، وتراقب انتقالات الحالة لمجموعات الوظائف (Function Groups) المكوّنة. وتغلّف فئات مساحة الاسم التفاعل بين ثلاثة أطراف فاعلة رئيسية: العمليات الخاصة بالتطبيق، وExecution Management المركزي، وState Management.

بالنسبة للعمليات، تُستخدم الفئة ExecutionClient كقناة اتصال رئيسية تُبَلّغ العملية التي تم بدء تشغيلها من خلالها عن حالة تنفيذها الحالية إلى Execution Management. ويصل State Management عبر الفئة StateClient إلى Execution Management لطلب انتقالات حالة محددة بين مجموعات الوظائف (FunctionGroup) وحالاتها المستهدفة (FunctionGroupState). وإذا حدث خطأ في التنفيذ أثناء تشغيل مجموعة وظائف، فيتم تمثيله عبر ExecutionErrorEvent مع نوع الخطأ المقابل ExecutionError [SWS_EM_02541].

مخطط السياق: التفاعل بين العمليات وExecution Management وState Management. المصادر: [SWS_EM_02000]، [SWS_EM_02281]

دورة الحياة

تُوصف دورة حياة العملية من خلال حالات تتم إدارتها جزئياً بشكل ضمني بواسطة Execution Management ويتم الإبلاغ عنها جزئياً بشكل نشط بواسطة العملية [SWS_EM_02000]. وتصف عناصر التعداد ExecutionState حصرياً تلك الحالات التي يمكن للعملية إرسالها بشكل نشط إلى Execution Management. وقيمة الحالة الوحيدة المحددة لذلك هي ExecutionState::kRunning [SWS_EM_02000].

من منظور Execution Management، تمر العملية بالمراحل التالية:

  • Initializing: حالة ضمنية تبدأ بمجرد جدولة العملية بواسطة نظام التشغيل (قبل تنفيذ التعليمات البرمجية الخاصة بالتطبيق)، وتنتهي بمجرد إبلاغ العملية عن kRunning [SWS_EM_02000].
  • Running: حالة التنفيذ النشطة بعد الإبلاغ الناجح عن ExecutionState::kRunning [SWS_EM_02000].
  • Terminating: حالة ضمنية أخرى تبدأ عندما يطلب Execution Management إنهاء العملية، وتكتمل بالإغلاق الكامل للعملية [SWS_EM_02000].

مخطط الحالة: مراحل حالة العملية في Execution Management. المصادر: [SWS_EM_02000]

مسار الاستخدام

يتضمن مسار الاستخدام النموذجي لعملية تطبيق التهيئة والإشارة اللاحقة إلى الجاهزية التشغيلية. بعد أن يبدأها Execution Management، تنفذ العملية إجراءات البدء الداخلية الخاصة بها. وبمجرد اكتمال التهيئة وبدء التشغيل الفعلي المنتظم، تنشئ العملية مثيلًا من ExecutionClient وترسل الحالة ExecutionState::kRunning [SWS_EM_02000].

يستقبل Execution Management هذا الإشعار ويتحقق من صحة الانتقال. إذا حاولت عملية الإبلاغ عن kRunning بينما هي بالفعل في الحالة Running، يُعتبر ذلك انتقالًا غير مسموح به [SWS_EM_02281]. وبالمثل، يراقب Execution Management ما إذا كان الإشعار قد تم في الوقت المحدد، حيث يمكن أن يؤدي عدم وروده إلى فشل عمليات الانتقال لمجموعات الوظائف [SWS_EM_02281].

مخطط التسلسل: الإشارة إلى kRunning عبر ExecutionClient. المصادر: [SWS_EM_02000]، [SWS_EM_02281]

سيناريوهات الأخطاء

تُمثَّل حالات الخطأ داخل الوحدة عبر نطاق الخطأ ExecErrorDomain. وتوفر الدالة GetExecErrorDomain() [SWS_EM_02290] مرجعًا آمنًا على مستوى الخيوط وآمنًا ضد الاستثناءات لمثيل النطاق العام. لإنشاء كائنات خطأ قياسية من النوع ara::core::ErrorCode، تُستخدم الدالة MakeErrorCode() [SWS_EM_02291] مع تحديد رمز الخطأ وبيانات إضافية خاصة بالشركة المصنعة.

تُعرَّف أسباب الخطأ المحددة في التعداد ExecErrc [SWS_EM_02281]:

  • kNoCommunication (=3): خطأ في الاتصال، على سبيل المثال عند إرسال طلب أو استرداد نتيجة. إذا حدث هذا الخطأ بين Execution Management وState Management، فقد يضطر النظام بأكمله إلى الانتقال إلى حالة غير قابلة للاسترداد (Unrecoverable State) [SWS_EM_02281].
  • kInvalidMetaModelIdentifier (=4): معرّف نموذج وصفي غير صالح عند استدعاءات الدوال [SWS_EM_02281].
  • kOperationCanceled (=5): تم إلغاء انتقال الحالة إلى مجموعة وظائف بواسطة طلب أحدث [SWS_EM_02281].
  • kOperationFailed (=6): فشلت العملية المطلوبة، على سبيل المثال لأن kRunning لعملية ما لم يتم الإبلاغ عنه في الوقت المحدد [SWS_EM_02281].
  • kInvalidTransition (=9): تم طلب انتقال حالة غير صالح، مثل الإبلاغ عن kRunning مجددًا أثناء تشغيل العملية بالفعل [SWS_EM_02281].
  • kIntegrityOrAuthenticityCheckFailed (=14): فشل التحقق من سلامة أو موثوقية عملية يُراد تشغيلها [SWS_EM_02281].
  • kUnexpectedTermination (=15): تم إنهاء عملية بشكل غير متوقع أثناء انتقال الحالة [SWS_EM_02281].
  • kInvalidArgument (=16): وسيط ممرر غير صالح [SWS_EM_02281].

لمعالجة الأخطاء القائمة على الاستثناءات، توفر الوحدة أيضًا فئة الاستثناء ExecException.

حالة العملية

ExecutionClient فئة

The ara::exec::ExecutionClient API provides the functionality for a Process to report its Execution State to the Execution Management.

ExecutionState تعداد

Defines the internal states of a Process. Scoped enumeration of uint32_t. Please note that ara::exec::ExecutionState includes only states reportable by the Process to Execution Management and therefore does not include enumerations e.g. the "Initializing" state mentioned in Figure 7.2 and Figure 7.12, which are an implied states for Execution Management. The Initializing state starts when Process is first scheduled (so no code executed yet) and ends when kRunning is reported ([SWS_EM_01004]). The Terminating state starts when termination is requested by Execution Management and ends when the Process terminates ([SWS_EM_01404]). For the reasons mentioned, Execution Management assumes that Process is in initializing state until kRunning will be reported by it.

kInvalidMetaModelIdentifier=4 Wrong meta model identifier passed to a function
kOperationCanceled=5 Transition to the requested Function Group state was canceled by a newer request
kOperationFailed=6 Requested operation could not be performed, e.g. Function Group state transition cannot be finished because kRunning was not reported on time
kInvalidTransition=9 Invalid transition (e.g. Process attempted to report kRunning, when it was already in a Running Process State)

Hinweise: If a kNoCommunication occurs at Execution Management or State Management level (or communication between both), the system may need to enter an Unrecoverable State. The internal mechanisms can detect this issue in the moment that a communication attempt occurs. This is not the case for applications that are using the interface of the ara::exec:: ExecutionClient or ara::exec::StateClient - they eventually get a communication error in the moment of the API use, i.e. possibly after the actual error occurrence. However, this is not problematic as the recovery options are limited from a client side viewpoint.
