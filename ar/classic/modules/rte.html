يربط مكونات البرمجيات ببعضها البعض وكذلك مع البرمجيات الأساسية وينسق تنفيذها.

تربط Runtime Environment (RTE) مكونات برمجيات AUTOSAR ببعضها البعض وكذلك مع وحدات البرمجيات الأساسية، وتنظم الجدولة الحتمية على Classic Platform عبر Basic Software Scheduler (SchM) (SWS_RTE ص. 100). ويتم تنسيق دورة الحياة عبر واجهات معيارية تمتد من SchM_Init وRte_Start إلى Rte_Stop وSchM_Deinit [SWS_Rte_08060]، [SWS_Rte_03015]. وإلى جانب أنماط المرسل-المستقبل والعميل-الخادم، تضمن أساليب مؤشرات البرمجيات لمعاملات المعايرة وكذلك عمليات فحص حماية الذاكرة عند حدود الأقسام تشغيلًا قويًا في الوقت الحقيقي [SWS_Rte_03914]، [SWS_Rte_02752].

تفصل Runtime Environment (RTE) مكونات برمجيات AUTOSAR عن عتاد وحدة التحكم الإلكترونية (ECU)، وتنسق بالاشتراك مع Basic Software Scheduler (SchM) تنفيذ كافة تدفقات التطبيقات والبرمجيات الأساسية (SWS_RTE ص. 100). ويتم بدء التشغيل المنضبط تدريجيًا عبر EcuStateManager: في البداية يقوم SchM_Init بتهيئة هياكل المجدول، يليه SchM_Start قبل استدعاء BswM_Init وكذلك SchM_StartTiming لتمكين أحداث BSW الدورية [SWS_Rte_08060]، [SWS_Rte_07273]، [SWS_Rte_04548]. ويتم بعد ذلك بدء مكونات البرمجيات التطبيقية (Application SW-Cs) عبر Rte_Start، وإيقافها عند إيقاف التشغيل بواسطة Rte_Stop قبل إلغاء التهيئة عبر SchM_Deinit [SWS_Rte_03015]، [SWS_Rte_01262]، [SWS_Rte_04551].

مخطط التسلسل: التنسيق الزمني لبدء التشغيل وإيقاف التشغيل بين EcuM وSchM وRTE. المصادر: [SWS_Rte_08060]، [SWS_Rte_07273]، [SWS_Rte_04548]، [SWS_Rte_03015]، [SWS_Rte_01262]، [SWS_Rte_04551]، [SWS_Rte_89019].

تغطي الاتصالات أنماط المرسل-المستقبل والعميل-الخادم داخل وحدة التحكم الإلكترونية نفسها (intra-ECU) وعبر وحدات متعددة (inter-ECU) (SWS_RTE ص. 286). وتضمن عناصر البيانات غير المخزنة مؤقتًا قيم إخراج متسقة عبر initValue، بينما تتم معالجة الأحداث المخزنة مؤقتًا عبر طوابير FIFO [SWS_Rte_06009]، [SWS_Rte_02521]. وفي تفاعلات العميل-الخادم، تربط مقابض المعاملات (Transaction Handles) الثنائية الطلبات غير المتزامنة باستجاباتها المقابلة [SWS_Rte_02649]. وتُنفذ تغييرات الأوضاع عبر Rte_Switch تسلسلًا حتميًا من عشر مراحل، حيث تضمن Distributed Shared Mode Queues الترتيب الصارم لمعالجة آلات الأوضاع المتعددة [SWS_Rte_02631]، [SWS_Rte_02665]، [SWS_Rte_91102].

مخطط السياق: هياكل العنونة والتوجيه غير المباشر لطرق المعايرة Single Pointered وDouble Pointered. المصادر: [SWS_Rte_03913]، [SWS_Rte_03914]، [SWS_Rte_03947]، AUTOSAR_SWS_RTE ص. 180، AUTOSAR_SWS_RTE ص. 181.

للمعايرة عبر الإنترنت (Online Calibration)، تُنشئ RTE هياكل مؤشرات وفقًا لمبدأ Single Pointered أو Double Pointered، مما يتيح تعديل مجموعات المعلمات في RAM دون الحاجة إلى محاكاة عتادية [SWS_Rte_03913]، [SWS_Rte_03914]. ويتم الإبلاغ عن التجاوزات غير الصحيحة للنطاق أو انتهاء المهلة عبر Std_ReturnType إلى المكون المستدعي، بينما تمنع عمليات التحقق من حماية الذاكرة عند حدود الأقسام التلاعب غير المصرح به [SWS_Rte_01034]، [SWS_Rte_03845]، [SWS_Rte_02752].

دور RTE وحدود النظام الخاصة بها في Classic Platform

تُشكّل Runtime Environment (RTE) العمود الفقري الوظيفي لبنية AUTOSAR Classic، حيث تفصل مكونات البرمجيات (SW-Cs) تمامًا عن عتاد الحاسوب الأساسي وكذلك عن وحدات Basic Software (BSW) القريبة من العتاد (SWS_RTE ص. 100). يُنشئ مولد RTE واجهة مخصصة لكل ECU، حيث يحل كافة علاقات الاتصال — محليًا على وحدة تحكم دقيقة (Intra-ECU) وكذلك عبر الشبكة من خلال نواقل الاتصال (Inter-ECU) — عبر استدعاءات API موحدة مثل Rte_Read أو Rte_Write أو Rte_Call [SWS_Rte_01091]، [SWS_Rte_01102]. ومن خلال توفير عنصر BswModuleDescription مُولَّد بالإضافة إلى أوصاف BswInternalBehavior المرتبطة به، تتكامل RTE كعنصر أساسي في مخطط التكوين والتحزيم لـ AUTOSAR [SWS_Rte_05165]، [SWS_Rte_05166].

تتم معالجة مثيلات التعدد لنفس مكون البرمجيات بواسطة RTE حصريًا عبر Runnable Entities قابلة لإعادة الدخول وتعتمد مشاركة الشيفرة (Code-Sharing)؛ ولا يتم دعم تكرار الشيفرة صراحةً [SWS_Rte_03015]، [SWS_Rte_02002]. ولكل مثيل، يتم تمرير معرف مثيل فريد في شيفرة C أو عنونته عبر Component Data Structure (CDS)، مما يضمن تنفيذ المثيلات بالتوازي ضمن سياقات مهام مشتركة دون حدوث تلف متبادل للبيانات (SWS_RTE ص. 126، SWS_RTE ص. 804). بالإضافة إلى SW-Cs التطبيقية، تغطي RTE عبر Basic Software Scheduler (SchM) الجدولة الدورية وإدارة الأنماط لكافة وحدات BSW [SWS_Rte_08060]، [SWS_Rte_07273].

دورة الحياة وتنسيق بدء التشغيل لـ SchM وRTE

يتطلب بدء تشغيل النظام تسلسلًا مضبوطًا بصرامة بين مجدول BSW (SchM) وRTE الموجهة للتطبيقات (SWS_RTE ص. 459). وقبل تهيئة SchM، تتوفر حصريًا دالتا القفل SchM_Enter وSchM_Exit لأسباب تتعلق بسلامة النظام. يستدعي EcuStateManager أولاً الدالة SchM_Init، والتي يتم من خلالها تهيئة هياكل البيانات الداخلية وآلات الأنماط وكذلك بدء BswSchedulableEntities ذات Background-Events [SWS_Rte_08060]، [SWS_Rte_07584]. وقبل استدعاء BswM_Init، يجب استدعاء SchM_Start [SWS_Rte_07273]، [SWS_Rte_04548]. بعد ذلك، يتم تمكين تنشيط عمليات BSW الدورية (BswTimingEvents) عبر SchM_StartTiming [SWS_Rte_04548]، [SWS_Rte_04551]، [SWS_Rte_07574].

مخطط التسلسل: التنسيق الزمني لبدء التشغيل وإيقاف التشغيل بين EcuM وSchM وRTE. المصادر: [SWS_Rte_08060]، [SWS_Rte_07273]، [SWS_Rte_04548]، [SWS_Rte_03015]، [SWS_Rte_01262]، [SWS_Rte_04551]، [SWS_Rte_89019].

فقط عندما تكون الخدمات الأساسية المطلوبة قيد التشغيل، يقوم EcuStateManager بتنشيط تنفيذ SW-Cs التطبيقية باستخدام Rte_Start ويبدأ عمليات انتقال الأنماط لـ On-Entry-Runnables غير المجمعة [SWS_Rte_03015]، [SWS_Rte_06766]. وإذا فشل تخصيص الموارد عند Rte_Start، تُرجع الدالة رمز الخطأ RTE_E_LIMIT [SWS_Rte_01262]. عند إيقاف تشغيل ECU، يُنهي Rte_Stop أولاً تنفيذ التطبيق ويتجاهل من هذه اللحظة الطلبات والبيانات الواردة [SWS_Rte_02538]، [SWS_Rte_02535]، [SWS_Rte_02536]. وفقط بعد الإنهاء الكامل لـ Rte_Stop، يُسمح باستدعاء SchM_Deinit، الذي يحرر جميع موارد النظام الخاصة بالمجدول ويبدأ عمليات التنظيف الخاصة بالمكونات الإضافية عبر Rte_Rips_SchM_Deinit [SWS_Rte_04551]، [SWS_Rte_07277]، [SWS_Rte_89019].

أنماط الاتصال: Sender-Receiver وClient-Server

تميز RTE في نموذج Sender-Receiver بشكل أساسي بين دلالات البيانات ودلالات الأحداث (SWS_RTE ص. 286). في حالة دلالات البيانات (swImplPolicy != queued)، يتم الاحتفاظ بآخر قيمة مكتوبة في المخزن المؤقت ويتم استهلاكها صراحةً باستخدام Rte_Read أو ضمنيًا عبر Rte_IRead [SWS_Rte_01091]، [SWS_Rte_06000]. وفي القراءة الضمنية، تضمن RTE نسخة متسقة من قيمة البيانات طوال مدة تنفيذ Runnable Entity بأكملها [SWS_Rte_06001]. وقبل الاستقبال الأول، توفر RTE قيمة initValue المكونة، بحيث لا تتم معالجة حالات ذاكرة غير مهيأة [SWS_Rte_06009]، [SWS_Rte_06010].

مخطط تسلسلي: اتصال Sender-Receiver بين وحدات ECU (Inter-ECU) للإشارات غير المخزنة مؤقتًا مع تأمين القيمة الأولية. المصادر: [SWS_Rte_01091]، [SWS_Rte_06009]، [SWS_Rte_01289]، AUTOSAR_SWS_RTE ص. 148.

على النقيض من ذلك، تعالج دلالات الأحداث (swImplPolicy = queued) تسلسلات البيانات دون فقدان عبر هياكل مخازن مؤقتة FIFO، والتي يتم ملؤها بواسطة Rte_Send وخفضها بواسطة Rte_Receive [SWS_Rte_01072]، [SWS_Rte_01092]، [SWS_Rte_02521]. وإذا تم الوصول إلى حد المخزن المؤقت المحدد عبر RteQueuedReceiverQueueLength، تتجاهل RTE البيانات الواردة حديثًا وتضبط راية خطأ مقابلة [SWS_Rte_08940]، [SWS_Rte_02523]. ولكميات البيانات الكبيرة، تستخدم RTE مسارات نقل متخصصة مثل LdCom أو Large-Data-COM مع تأمين مخزن الإشارة المؤقت (Signalbuffer-Locking) [SWS_Rte_01376]، [SWS_Rte_01379].

يدعم اتصال Client-Server الاستدعاءات المتزامنة (Rte_Call) وكذلك التفاعلات غير المتزامنة مع استعلام منفصل عن النتائج عبر Rte_Result [SWS_Rte_01102]، [SWS_Rte_01111]. في جانب الخادم، تخزن RTE الطلبات الواردة مؤقتًا في قائمة انتظار FIFO، ما لم يتم تكوين استدعاء مباشر، بينما يتم تخزين الاستجابة مؤقتًا في جانب العميل في مخزن مؤقت بطول 1 [SWS_Rte_02527]، [SWS_Rte_02528]. في الاستدعاءات عبر الأقسام أو عبر وحدات ECU، يضمن مقبض المعاملة (Transaction Handle) المكون من جزأين، والمؤلف من معرف العميل (Client Identifier) وعداد التسلسل (Sequence Counter)، المطابقة الدقيقة لحزم الاستجابة مع الطلب الأصلي [SWS_Rte_02649]، [SWS_Rte_08711].

إدارة الأنماط، انتقالات الحالة وDistributed Shared Mode Queues

تتيح إدارة الأنماط التبديل المنسق لحالات التشغيل عبر آلات أنماط مخصصة (ModeMachineInstances)، والتي يتم التحكم فيها عبر Rte_Switch [SWS_Rte_02631]. يمر كل انتقال للحالة بتسلسل حتمي مكون من عشر خطوات فردية، يشمل من بين أمور أخرى تنشيط أقفال الأنماط، والانتظار المنضبط لإنهاء Runnables المعنية، وكذلك التنفيذ التسلسلي لكيانات OnExit وOnTransition وOnEntry [SWS_Rte_02665]. وفقط بعد الاكتمال التام لجميع المراحل، يتم إطلاق حدث الإقرار ModeSwitchedAckEvent، والذي يمكن الاستعلام عن حالته عبر Rte_SwitchAck [SWS_Rte_02679]، [SWS_Rte_02725]، [SWS_Rte_02758].

مخطط نشاط: تسلسل حتمي من عشر مراحل لانتقال نمط داخل ModeMachineInstance. المصادر: [SWS_Rte_02665]، [SWS_Rte_02679]، EXP_ModeManagementGuide ص. 16.

لفرض ترتيب صارم لتغييرات الأنماط في حالة وجود عدة آلات أنماط — على سبيل المثال بين حالة الإشعال وحالة المحرك — توفر RTE قوائم انتظار Distributed Shared Mode Queues (DSMQ) (SWS_RTE ص. 442). ويتم الإشارة إلى حالة عمليات الإدراج والإخراج في قوائم الانتظار هذه عبر النوع Rte_DsmqStatusType [SWS_Rte_91102]. وبالنسبة لانتقالات مجموعات البرمجيات (Software Cluster)، يمثل Rte_Rips_SwitchNotificationStatusType حالتي الإدراج في قائمة الانتظار والإخراج منها (Enqueue وDequeue) المقابلتين [SWS_Rte_91113]. تفسير: في مجدول BSW، يُرجح اختيار تكوين نقاط المزامنة قبل Rte_Start، لتأسيس حالات نظام حتمية قبل تمكين المهام الدورية [SWS_Rte_06767].

المعايرة ومحاكاة البيانات وطوبولوجيا الذاكرة

تحدد RTE مواضع معلمات المعايرة مركزيًا في الذاكرة، نظرًا لأن مولد RTE فقط هو من يعرف التوزيع الإجمالي لجميع المكونات والأقسام على ECU [SWS_Rte_03961]. ولتمكين المعايرة عبر الإنترنت دون عتاد محاكاة متخصص، تدعم RTE طرق المحاكاة البرمجية مثل Single Pointered Method وDouble Pointered Method (SWS_RTE ص. 236، SWS_RTE ص. 237). في طريقة Single Pointered Method، يوجد في RAM جدول مؤشرات (<RteParameterRefTab>) يتكون من مدخلات void*، والتي تشير إلى ParameterElementGroups [SWS_Rte_03913]، [SWS_Rte_03947].

مخطط السياق: هياكل العنونة والتوجيه غير المباشر لطرق المعايرة Single Pointered وDouble Pointered. المصادر: [SWS_Rte_03913]، [SWS_Rte_03914]، [SWS_Rte_03947]، AUTOSAR_SWS_RTE ص. 180، AUTOSAR_SWS_RTE ص. 181.

في المقابل، تستخدم Double Pointered Method إسنادًا غير مباشر ثنائي المراحل: يشير جدول مرجعي مخزن في ROM/Flash إلى مجموعات المعلمات، بينما يشير مؤشر أساسي قابل للتعديل (Base reference) في RAM مبدئيًا إلى جدول Flash هذا، ويمكن تحويله عند إجراء المعايرة ليشير إلى نسخة RAM معدلة [SWS_Rte_03914]. ويتم هنا فصل ParameterDataPrototypes إلى مجموعات متمايزة استنادًا إلى swAddrMethod الخاصة بها [SWS_Rte_03908]. يُصدّر مولد RTE كافة معلومات الهيكل والمؤشرات في الحاوية McSupportData عبر McSwEmulationMethodSupport، لمنح أدوات المعايرة (مثل INCA أو CANape) وصولاً دقيقًا إلى عنونة A2L [SWS_Rte_05118]، [SWS_Rte_05137]، [SWS_Rte_05138]. تفسير: بالنسبة لوحدات ECU الخاصة بالسلامة عالية التكامل، يُرجح تفضيل Double Pointered Method، نظرًا لأن جدول المؤشرات نفسه يظل أساسًا في ذاكرة Flash المحمية ولا يحجز مخازن RAM مؤقتة إلا أثناء المعايرة النشطة.

التقسيم وحماية الذاكرة والاتصال بين تطبيقات نظام التشغيل (Inter-OS-Application)

في البنى متعددة الأنوية والمحمية الذاكرة، تربط RTE مكونات البرمجيات عبر حدود الأقسام (OS-Applications) باستخدام Inter-OS-Application Communication (IOC) (SWS_RTE ص. 372). وتستبدل RTE هنا مخازن الإشارات المؤقتة الداخلية بمخازن IOC مؤقتة قريبة من العتاد ودوال حماية مُولَّدة. وللوصول إلى المناطق الحصرية (ExclusiveAreas)، يختار مسؤول التكامل معلمات تكوين خاصة بالآلية (RteExclusiveAreaImplMechanism)، تتراوح من عمليات حظر المقاطعات إلى أقفال OS-Spinlocks للوصول عبر الأنوية (SWS_RTE ص. 203).

إذا مرر قسم غير مختبر أو غير موثوق به (Non-Trusted) معلمات مؤشرات إلى قسم BSW أو SWC موثوق به، تُجري RTE إلزاميًا عمليات تحقق من العناوين ونطاقات الذاكرة [SWS_Rte_02752]، [SWS_Rte_02753]. ولا يتم توجيه المؤشر إلا إذا كان كائن الذاكرة المشار إليه بأكمله ملكًا للقسم المستدعي، مما يمنع بفعالية انتهاكات نطاق الحماية والكتابة غير المصرح بها فوق نطاقات الذاكرة الأخرى (SWS_RTE ص. 378).

التصرف في حالة الخطأ

تفصل معالجة الأخطاء في RTE بصرامة بين أخطاء البنية التحتية وأخطاء التطبيق (SWS_RTE ص. 579). ويتم إبلاغ المستدعي بجميع حالات الخطأ مباشرة عبر نوع الإرجاع Std_ReturnType [SWS_Rte_01034]. وتشمل أخطاء البنية التحتية المباشرة، من بين أمور أخرى، RTE_E_TIMEOUT (129)، RTE_E_LIMIT (130)، RTE_E_NO_DATA (131)، RTE_E_UNCONNECTED (134)، RTE_E_IN_EXCLUSIVE_AREA (135) وكذلك RTE_E_SEG_FAULT (136) (SWS_RTE ص. 586).

مخطط تسلسلي: اكتشاف أخطاء نطاق القيم ونشرها عبر Rte_Read. المصادر: [SWS_Rte_01091]، [SWS_Rte_01371]، [SWS_Rte_03845]، AUTOSAR_CP_SWS_RTE ص. 409.

عند تفعيل التحقق من صحة البيانات (DataSemantics range check)، تتحقق RTE من قيم الإشارات الواردة مقابل نطاقات القيم المحددة [SWS_Rte_01371]. وإذا كانت القيمة المستلمة خارج الحدود، تُرجع واجهة برمجة التطبيقات للقراءة (Lese-API) RTE_E_OUT_OF_RANGE [SWS_Rte_03845]، [SWS_Rte_03846]. وبالنسبة للإشارات ذات سياسة الإبطال (Invalidation-Policy)، تستبدل RTE القيمة عند replace بـ initValue، أو تحتفظ بالقيمة السابقة عند keep وتضبط حدث خطأ [SWS_Rte_05030]، [SWS_Rte_05049]. وعند مراقبة انتهاء المهلة عبر aliveTimeout، تسجل RTE عدم الحضور عبر Rte_COMCbkRxTOut وتنشر RTE_E_TIMEOUT إلى SW-Cs المنتظرة [SWS_Rte_08061]، [SWS_Rte_03763].
