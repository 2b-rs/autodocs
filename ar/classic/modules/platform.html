يُوفر أنواعًا أساسية موحدة التسمية ورموزًا مميزة لعرض السجل وترتيب البايتات (Endianness) للمعالج الهدف.

يُوفر Platform_Types.h الأنواع الأساسية المعتمدة على المنصة لـ Classic Platform: أنواع أعداد صحيحة ثابتة العرض من uint8 إلى sint64، وأنواع *_least المحسّنة، وfloat32/float64، وboolean مع TRUE/FALSE بالإضافة إلى مؤشرات المخزن المؤقت VoidPtr وConstVoidPtr. بالإضافة إلى ذلك، تُحدد CPU_TYPE وCPU_BIT_ORDER وCPU_BYTE_ORDER عرض السجل وترتيب البايتات للهدف [SWS_Platform_00046]. لا يجوز استخدام boolean إلا مع TRUE وFALSE ودون عوامل حسابية أو منطقية للبت [SWS_Platform_00034]. ولا يجوز توسيع ملف الرأس، وإلا فسيتم فقدان التوافق مع AUTOSAR.

Platform_Types.h هو أساس الأنواع المعتمد على المنصة لـ Classic Platform. يُغلف ملف الرأس عروض الكلمات وترتيب البايتات للهدف خلف أسماء موحدة، ولا يجوز توسيعه لأن أي توسيع يُلغي التوافق مع AUTOSAR [SWS_Platform_00002]. وفي عرض النموذج، تقع الأنواع تحت مسار ثابت مثل /AUTOSAR_Platform/ImplementationDatatypes/uint8 TPS StandardizationTemplate ص. 77.

يُوفر ملف الرأس مجموعات الأنواع التالية:

  • أنواع أعداد صحيحة ثابتة العرض من uint8 إلى sint64 [SWS_Platform_00013] [SWS_Platform_00067]؛ وبالنسبة للأنواع ذات الإشارة، ينطبق متمم الاثنين فقط [SWS_Platform_00061].
  • أنواع محسّنة *_least بعرض أدنى، على سبيل المثال لعدادات الحلقات التكرارية [SWS_Platform_00020].
  • float32 وfloat64 وفقًا للمعيار IEEE 754-2008 [SWS_Platform_00041].
  • مؤشرات المخزن المؤقت VoidPtr للبيانات الموجهة إلى المتصل وConstVoidPtr للبيانات الموجهة إلى الطرف المُستدعى [SWS_Platform_91001] [SWS_Platform_91002].

مخطط النشاط: يتبع اختيار نوع المنصة المناسب أسئلة مؤشر المخزن المؤقت، والقيمة المنطقية، والعدد ذي الفاصلة العائمة، والحد الأدنى للعرض أو العرض الدقيق. المصادر: [SWS_Platform_91001]، [SWS_Platform_00026]، SWS PlatformTypes ص. 17

يتم تنفيذ boolean في R20-11 كأقصر نوع عدد صحيح بدون إشارة مدعوم أصلاً، عادةً 8 بت [SWS_Platform_00027]. وتختلف الإصدارات اللاحقة عن ذلك وتستخدم _Bool SWS PlatformTypes ص. 18. ويجب أن يقبل النوع استخدام المؤشرات [SWS_Platform_00060] ولا يجوز استخدامه إلا مع TRUE وFALSE. تُحظر العوامل الحسابية والمنطقية للبت [SWS_Platform_00034]، ويجب تجنب إعادة تعريف الرموز عبر فحص شرطي [SWS_Platform_00054].

لكل منصة، يجب أيضًا تحديد ثلاثة رموز: CPU_TYPE لعرض السجل [SWS_Platform_00045]، وCPU_BIT_ORDER مع MSB_FIRST أو LSB_FIRST [SWS_Platform_00048] [SWS_Platform_00049]، وCPU_BYTE_ORDER مع HIGH_BYTE_FIRST أو LOW_BYTE_FIRST [SWS_Platform_00050] [SWS_Platform_00051]. ولا يجوز خلط أسماء البتات وأوزانها في هذا السياق، لأن MSB يقع دائمًا على اليسار في المُركم SWS PlatformTypes ص. 15. تفسير: لا يعرف النموذج أخطاء وقت التشغيل؛ ولا تظهر التعيينات الخاطئة إلا أثناء التكامل أو اختبار التوافق.

مخطط النشاط: يتم تعيين كل من عرض السجل وترتيب البتات وترتيب البايتات للهدف إلى قيمة رمزية واحدة بالضبط. المصادر: [SWS_Platform_00045]، [SWS_Platform_00048]، [SWS_Platform_00050]

دور Platform_Types.h: أساس الأنواع المعتمد على المنصة

الوحدة ليست عنصر بناء قابلاً للتنفيذ، بل هي ملف رأس. جميع الأنواع والرموز المحددة هي «Available via Platform_Types.h»، مثل uint8 [SWS_Platform_00013] أو CPU_TYPE [SWS_Platform_00064]. يُخفي ملف الرأس خصائص وحدة التحكم الدقيقة الهدف والمترجم خلف أسماء موحدة: عروض الكلمات، وترتيب البتات، وترتيب البايتات. وبذلك، فإنه ينتمي إلى تجريد وحدة التحكم الدقيقة المطلوب في SRS_BSW_00161 مع واجهة معيارية للطبقات العليا SRS BSWGeneral ص. 88. وإلى متطلب Upstream هذا تحديدًا، تُشير أيضًا القواعد الخاصة بترتيب البايتات SWS PlatformTypes ص. 16.

حدود النظام محددة بدقة. لا يجوز توسيع ملف الرأس، لأن أي توسيع يُلغي التوافق مع AUTOSAR [SWS_Platform_00002]. في المقابل، توجد أنواع الإرجاع للنجاح أو الفشل في استدعاء API في Std_Types.h SRS BSWGeneral ص. 68. في عرض النموذج، تُحفظ أنواع المنصة كمخططات أولية (Blueprints)، على سبيل المثال تحت /AUTOSAR/Platform/ImplementationDatatypes_Blueprint/uint8. وتُنفّذ تحت /AUTOSAR_Platform/ImplementationDatatypes/uint8، بحيث يمكن لموردي المكونات الوصول إليها عبر مسار يمكن التنبؤ به TPS StandardizationTemplate ص. 77.

مخطط السياق: تُحدد المنصة الهدف محتوى Platform_Types.h، وتقع أنواعه في عرض النموذج تحت مسار ثابت وتستخدمه العديد من وحدات BSW. أمثلة المستخدمين مأخوذة من إصدارات لاحقة. المصادر: [SWS_Platform_00038]، TPS StandardizationTemplate ص. 77، SWS BFXLibrary ص. 19، SWS CRCLibrary ص. 41، SWS BSWMulticoreLibrary ص. 16، SWS KeyManager ص. 111، SWS CANStateManager ص. 83

أنواع الأعداد الصحيحة والأعداد ذات الفاصلة العائمة بعرض مضمون

جوهر الوحدة هو أنواع بدون إشارة وبإشارة ذات عرض ثابت يتراوح من 8 إلى 64 بت بالإضافة إلى نوعين من الأعداد ذات الفاصلة العائمة. تحدد المتطلبات المعيارية العرض ونطاق القيم، مثل «32 bit unsigned» لـ uint32 [SWS_Platform_00015]. ويُرجح قراءة تعريفات النوع في لغة C (C-Typedefs) في دليل API، على سبيل المثال typedef unsigned long uint32;، على أنها تخطيط نموذجي يمكن أن يختلف باختلاف المترجم (تفسير).

بالنسبة للأنواع ذات الإشارة، يدعم AUTOSAR في المترجم والهدف حساب متمم الاثنين حصريًا. وينتج عن ذلك نطاقات القيم غير المتماثلة في الجدول [SWS_Platform_00061]. تفترض المواصفات الأخرى هذه الأنواع باستمرار. على سبيل المثال، تُعرّف مكتبة CRC uint8 Crc_CalculateCRC8(const uint8*, uint32, uint8, boolean) SWS CRCLibrary ص. 41. ويجب أن يدعم COM تحويل Endianness لـ uint16 حتى float64 RS COM ص. 14. كلا الموضعين مأخوذان من إصدارات لاحقة ويوضحان الاستخدام فقط.

الأنواع المحسّنة *_least للعدادات والحالات

بالإضافة إلى الأنواع ذات العرض الدقيق، تُعرّف الوحدة ستة أنواع محسّنة. وهي تضمن حدًا أدنى للعرض فقط وهي مشتقة من uint أو sint:

  • uint8_least [SWS_Platform_00020]
  • uint16_least [SWS_Platform_00021]
  • uint32_least [SWS_Platform_00022]
  • sint8_least [SWS_Platform_00023]
  • sint16_least [SWS_Platform_00024]
  • sint32_least [SWS_Platform_00025]

لذا يُسمح للتنفيذ باختيار تمثيل أوسع. تُعيّن تواقيع الفهرس الأنواع الستة بأكملها إلى unsigned int أو signed int على التوالي [SWS_Platform_00020].

تذكر المواصفة كأمثلة للاستخدام عدّادات الحلقات (124 تكرارًا كحد أقصى ⇒ uint8_least) ووسائط switch (17 حالة ⇒ uint8_least). وللحصول على التفاصيل، تُحيل إلى فصل «AUTOSAR Integer Data Types» ضمن متطلبات BSW العامة SWS PlatformTypes ص. 17.

استخدام boolean وTRUE وFALSE بما يتوافق مع القواعد

يمتلك boolean نطاق القيم FALSE = 0 وTRUE = 1 ولا يجوز استخدامه إلا جنبًا إلى جنب مع هذه التعريفات [SWS_Platform_00026]. بالنسبة للإصدار R20-11: يتم تنفيذ boolean كنوع أعداد صحيحة غير مؤشرة بأقصر طول بت تدعمه المنصة أصلاً، وهو عادةً 8 بت [SWS_Platform_00027]. ويصيغ موضع توثيق من R24-11/R25-11 المعرّف نفسه بصورة مختلفة: حيث يتم تنفيذ boolean هناك عبر النوع C99 _Bool، ولم تعد AUTOSAR تحدد الحجم الدقيق SWS PlatformTypes ص. 18. وبالنسبة للإصدار R20-11، فإن هذه الصيغة اللاحقة ليست معيارية.

يجب علاوةً على ذلك تعيين boolean إلى نوع يمكن للمؤشرات الإشارة إليه، وذلك حتى يمكن تمرير المعلمات عبر API. إن أنواع البتات الفعالة لبعض الأجهزة لا تقبل التأشير، وبالتالي فهي مستبعدة [SWS_Platform_00060]. تنطبق ثلاث قواعد على الرمزين TRUE وFALSE:

  • يتم تعريفهما بحماية #ifndef كـ 1 و0 [SWS_Platform_00056].
  • إذا كان المترجم يتضمن الرمزين بالفعل، فيجب تجنب إعادة التعريف من خلال فحص شرطي [SWS_Platform_00054].
  • لا يجوز استخدامهما إلا مع boolean [SWS_Platform_00055].

عند الإسناد إلى متغيرات boolean، تُحظر المعاملات الحسابية ومعاملات البت: + و++ و- و-- و* و/ و% و<< و>> و~ و&. المسموح به فقط هو إسناد TRUE أو FALSE وكذلك النتائج الناتجة عن العلاقات، والروابط المنطقية، وفحوصات التساوي وعدم التساوي. لا تتم المقارنة إلا باستخدام == أو != مقابل TRUE/FALSE أو عبر if (var) أو if (!var) [SWS_Platform_00034]. وتتبع الوحدات المستهلكة هذا النمط؛ حيث يُرجع Bfx_GetBit نتيجة اختبار بت صراحةً كـ TRUE أو FALSE SWS BFXLibrary ص. 19.

مخطط نشاط: بالنسبة لمتغيرات boolean، يُسمح فقط بصيغ الإسناد والمقارنة المدرجة، دون معاملات الحساب والبت. المصادر: [SWS_Platform_00034]، [SWS_Platform_00026]

مؤشرات مخزن مؤقت غير محددة النوع: VoidPtr وConstVoidPtr

يختلف نوعا المؤشرات في اتجاه تدفق البيانات:

  • VoidPtr هو void* للمخازن المؤقتة التي تحتوي على بيانات معادة إلى المتصل [SWS_Platform_91001].
  • ConstVoidPtr هو const void* للمخازن المؤقتة التي يتم تمريرها إلى الطرف المستدعى [SWS_Platform_91002].

وبذلك يكون اتجاه تدفق البيانات متضمنًا بالفعل في اسم النوع SWS PlatformTypes ص. 27 SWS PlatformTypes ص. 28.

يوضح Key Manager كيف يبدو ذلك في الواجهات؛ حيث يمرر KeyMServiceCertificateByCertId RequestData كـ ConstVoidPtr مصحوبًا بطول من النوع uint32. وتستقبل الاستجابة ResponseData من النوع VoidPtr؛ مع تحديد ResponseDataLength (INOUT) لطول المخزن المؤقت المتاح SWS KeyManager ص. 111. أمثلة أخرى:

  • يُرجع KeyM_CertDataType بيانات الشهادة في منطقة البيانات المحلية للمتصل عبر VoidPtr SWS KeyManager ص. 97.
  • يمرر Crypto Service Manager القيمة الأولية (Seed) كـ ConstVoidPtr SWS CryptoServiceManager ص. 124.

في جميع الأمثلة الثلاثة، يتم تضمين الطول كمعلمة uint32 مستقلة أو كعنصر بنية مستقل، لأن المؤشر غير محدد النوع لا يحمل أي معلومات عن الطول.

مخطط تسلسل: عند استدعاء خدمة، ينقل ConstVoidPtr الطلب إلى الطرف المستدعى، بينما يستقبل VoidPtr الاستجابة لصالح المتصل. المصادر: SWS KeyManager ص. 111، [SWS_Platform_91001]، [SWS_Platform_91002]

مخطط نشاط: يتبع اختيار النوع الأسئلة المتعلقة بمؤشر المخزن المؤقت، والقيمة المنطقية، والعدد ذي الفاصلة العائمة، والحد الأدنى للعرض أو العرض الدقيق. المصادر: [SWS_Platform_91001]، [SWS_Platform_91002]، [SWS_Platform_00026]، [SWS_Platform_00041]، [SWS_Platform_00020]، SWS PlatformTypes ص. 17

معرّف المنصة: CPU_TYPE، CPU_BIT_ORDER، CPU_BYTE_ORDER

يجب تحديد ثلاث خصائص في الترويسة لكل منصة:

  • عرض السجل عبر CPU_TYPE [SWS_Platform_00044]، بإحدى القيم CPU_TYPE_8 أو CPU_TYPE_16 أو CPU_TYPE_32 أو CPU_TYPE_64 [SWS_Platform_00045] [SWS_Platform_00064].
  • ترتيب البتات على مستوى السجل عبر CPU_BIT_ORDER [SWS_Platform_00043].
  • ترتيب البايتات في الذاكرة عبر CPU_BYTE_ORDER [SWS_Platform_00046].

كلا رمزي الترتيب هما #define يحملان قيمة واحدة فقط من القيم المسموح بها [SWS_Platform_00038] [SWS_Platform_00039].

مخطط نشاط: عند النقل إلى هدف ما، يتم تحديد عرض السجل وترتيب البتات وترتيب البايتات وتعيين كل منها إلى قيمة رمز واحدة تحديدًا. المصادر: [SWS_Platform_00045]، [SWS_Platform_00048]، [SWS_Platform_00049]، [SWS_Platform_00050]، [SWS_Platform_00051]

في ترتيب البتات ذي النهاية الكبرى (Big-Endian)، يسري CPU_BIT_ORDER = MSB_FIRST، وفي النهاية الصغرى (Little Endian)، يسري LSB_FIRST [SWS_Platform_00048] [SWS_Platform_00049]. ويجب الفصل الصارم بين أسماء البتات وأهميتها الوزنية؛ حيث يقع MSB دائمًا في أقصى اليسار في المجمّع بغض النظر عن نوع CPU. وفي بنيات Motorola (Big Endian Bit Order)، يشير Bit0 إلى البت الأكثر أهمية، بينما يشير في جميع البنيات الأخرى إلى الأقل أهمية SWS PlatformTypes ص. 15 SWS PlatformTypes الشكل 7.1 ص. 14.

مخطط بنيوي وفقًا للشكل 7.1: تكون الأهمية الوزنية لبتات السجل ثابتة، وفقط ترقيم Bit0 يعتمد على CPU_BIT_ORDER. المصادر: SWS PlatformTypes الشكل 7.1 ص. 14، SWS PlatformTypes ص. 15

في ترتيب البايتات ذي النهاية الكبرى (Big-Endian)، يسري CPU_BYTE_ORDER = HIGH_BYTE_FIRST: يقع البايت الأكثر أهمية لقيمة 16 بت عند العنوان n، والأقل أهمية عند العنوان n+1. وفي النهاية الصغرى (Little Endian)، يسري LOW_BYTE_FIRST بتوزيع معكوس [SWS_Platform_00050] [SWS_Platform_00051]. وتُستخدم التسميتان Byte0 وByte1 للتوضيح فقط وقد تختلفان في التوثيق المرجعي لإحدى الشركات المصنعة SWS PlatformTypes ص. 16.

مخطط بنيوي وفقًا للشكل 7.2/7.3: يتم تعيين نفس uint16 مع تبديل البايتات إلى العنوانين n وn+1 اعتمادًا على CPU_BYTE_ORDER. المصادر: SWS PlatformTypes الشكل 7.2 ص. 16، SWS PlatformTypes الشكل 7.3 ص. 15، [SWS_Platform_00039]

تبرر مواصفات أخرى سبب ضرورة هذه البيانات. إذ يعتمد تمثيل البيانات في الذاكرة اعتمادًا كبيرًا على بنية المعالج وإعدادات المترجم. ولهذا السبب، يتطلب SOME/IP خوارزمية تسلسل تحوّل إلى تمثيل شبكي مشترك RS SOMEIPProtocol ص. 21. ويُفترض أن مثل هذه التحويلات في التنفيذات تستند إلى CPU_BYTE_ORDER؛ غير أن حمولة البيانات (Payload) لا تثبت ذلك صراحةً.

التصرف في حالة الخطأ

تفسير: نظرًا لأن Platform_Types.h لا يوفر سوى الأنواع والرموز، فإن الوحدة لا تعرف أي أخطاء أثناء وقت التشغيل ولا أي رموز أخطاء. وتظهر أنماط الأخطاء أثناء الترجمة أو الدمج أو فحص المطابقة. وتحدد المتطلبات الأسباب النمطية [SWS_Platform_00002]:

  • توسيعات الترويسة غير مسموح بها؛ وكل توسيع يلغي المطابقة [SWS_Platform_00002].
  • يجب منع التعريفات المزدوجة لـ TRUE/FALSE عند توفر دعم المترجم عبر فحص شرطي [SWS_Platform_00054] [SWS_Platform_00056].
  • تنتهك رموز الترتيب ذات التعيين غير الصحيح المتطلبات من [SWS_Platform_00048] إلى [SWS_Platform_00051]. ويُعد خلط أسماء البتات الواردة في توثيق الشركة المصنعة مع الأهمية الوزنية عرضةً للخطأ بشكل خاص SWS PlatformTypes ص. 15.
  • إن boolean غير القابل للتأشير ينتهك [SWS_Platform_00060]، لأن المعلمات لا يمكن تمريرها حينئذٍ عبر API.
  • تُعد العمليات الحسابية أو عمليات البت على boolean غير مسموح بها، وكذلك صيغ المقارنة الأخرى غير المدرجة [SWS_Platform_00034].
  • الكود الذي يفترض متمم الآحاد أو نطاقات قيم متناظرة غير مشمول، حيث يتم دعم متمم الاثنين فقط [SWS_Platform_00061].
  • عند تغيير الإصدار، يجب مراعاة التوجيه الخاص بـ boolean: حيث يختلف R20-11 [SWS_Platform_00027] عن الصيغ اللاحقة SWS PlatformTypes ص. 18. ولذلك يجب فحص الكود الذي يفترض حجمًا ثابتًا لـ boolean قبل التغيير.

  • أنواع الأعداد الصحيحة ذات العرض الثابت: يحدد [SWS_Platform_00013] إلى [SWS_Platform_00018] بالإضافة إلى [SWS_Platform_00066] و[SWS_Platform_00067] العرض ونطاق القيم.
  • الأنواع المحسّنة: [SWS_Platform_00020] إلى [SWS_Platform_00025]، مع أمثلة للاستخدام في SWS PlatformTypes ص. 17.
  • أنواع الفاصلة العائمة وفقًا لـ IEEE 754-2008: [SWS_Platform_00041]، [SWS_Platform_00042].
  • القيم المنطقية: [SWS_Platform_00026]، [SWS_Platform_00027]، [SWS_Platform_00034]، [SWS_Platform_00055]، [SWS_Platform_00056]، [SWS_Platform_00060].
  • مؤشرات المخزن المؤقت: [SWS_Platform_91001]، [SWS_Platform_91002]، مع التطبيق في SWS KeyManager ص. 111.
  • رموز المنصة: [SWS_Platform_00043] إلى [SWS_Platform_00046]، [SWS_Platform_00064]، [SWS_Platform_00038]، [SWS_Platform_00039]. يتم تنظيم تعيين ترتيب البايتات (Endianness) عبر [SWS_Platform_00048] إلى [SWS_Platform_00051]، وهو موضح في SWS PlatformTypes ص. 16.
  • القواعد الإطارية: [SWS_Platform_00002] (لا توسيعات)، [SWS_Platform_00054] (لا إعاد تعريف)، [SWS_Platform_00061] (متمم الاثنين). يعلن [SWS_Platform_00063] عدم قابلية تطبيق مجموعة من المتطلبات؛ والمجموعة المقصودة لا تظهر من النص المختصر.

Platform Types (Platform_Types)

أنواع البيانات الأساسية الخاصة بالمنصة (الأعداد الصحيحة، والقيم المنطقية، وأرقام الفاصلة العائمة) المعينة إلى CPU أوليات البنية.

الأنواع – نظرة عامة

  • typedef boolean This standard AUTOSAR type shall only be used together with the definitions TRUE and FALSE.
  • typedef uint8 This standard AUTOSAR type shall be of 8 bit unsigned.
  • typedef uint16 This standard AUTOSAR type shall be of 16 bit unsigned.
  • typedef uint32 This standard AUTOSAR type shall be 32 bit unsigned.
  • typedef uint64 This standard AUTOSAR type shall be 64 bit unsigned.
  • typedef sint8 This standard AUTOSAR type shall be of 8 bit signed.
  • typedef sint16 This standard AUTOSAR type shall be of 16 bit signed.
  • typedef sint32 This standard AUTOSAR type shall be 32 bit signed.
  • typedef sint64 This standard AUTOSAR type shall be 64 bit signed.
  • typedef uint8_least This optimized AUTOSAR type shall be at least 8 bit unsigned.
  • typedef uint16_least This optimized AUTOSAR type shall be at least 16 bit unsigned.
  • typedef uint32_least This optimized AUTOSAR type shall be at least 32 bit unsigned.
  • typedef sint8_least This optimized AUTOSAR type shall be at least 8 bit signed.
  • typedef sint16_least This optimized AUTOSAR type shall be at least 16 bit signed.
  • typedef sint32_least This optimized AUTOSAR type shall be at least 32 bit signed.
  • typedef float32 This standard AUTOSAR type shall follow the 32-bit binary interchange format according to IEEE 754-2008 with encoding...
  • typedef float64 This standard AUTOSAR type shall follow the 64-bit binary interchange format according to IEEE 754-2008 with encoding...
  • typedef VoidPtr This standard AUTOSAR type shall be a void pointer Note: This type shall be used for buffers that contain data returned to the...
  • typedef ConstVoidPtr This standard AUTOSAR type shall be a void pointer to const.
  • CPU_TYPE This symbol shall be defined as #define having one of the values CPU_TYPE_8, CPU_TYPE_16, CPU_TYPE_32 or CPU_TYPE_64 according...
  • CPU_BIT_ORDER This symbol shall be defined as #define having one of the values MSB_FIRST or LSB_FIRST according to the platform.
  • CPU_BYTE_ORDER This symbol shall be defined as #define having one of the values HIGH_BYTE_FIRST or LOW_ BYTE_FIRST according to the platform.
  • TRUE_FALSE The symbols TRUE and FALSE shall be defined as follows: #ifndef TRUE #define TRUE 1 #endif #ifndef FALSE #define FALSE 0 #endif
