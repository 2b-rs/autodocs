يدير كتل البيانات غير المتطايرة ويقوم بمزامنتها بشكل غير متزامن بين RAM وذاكرة NV.

يُعد NVRAM Manager (NvM) منفذ الوصول الوحيد إلى الذاكرة غير المتطايرة. فهو ينسخ كتل NVRAM ضمنيًا بين RAM وذاكرة NV [SWS_NvM_00038]. عند بدء التشغيل، يملأ NvM_ReadAll الذي يطلقه BswM كتل RAM، وعند إيقاف التشغيل، يحفظ NvM_WriteAll الكتل المعدلة. تُدرج الطلبات الفردية مثل NvM_WriteBlock في قائمة انتظار بشكل غير متزامن، وتُعالج وفقًا للأولوية، ويجري تأكيد إتمامها عبر الحالة أو عبر دالة رد نداء [SWS_NvM_00185]. يعالج NvM أخطاء القراءة عبر إعادات المحاولة، والنسخ الاحتياطية المتكررة، والبيانات الافتراضية؛ ومع ذلك، يجب على المستخدمين التحقق من حالة الكتلة بأنفسهم.

يُعد NVRAM Manager (NvM) منفذ الوصول الوحيد إلى الذاكرة غير المتطايرة [SWS_NvM_00384]. فهو ينسخ الكتل ضمنيًا بين NVRAM وRAM؛ ويعمل التطبيق مباشرةً مع بيانات RAM [SWS_NvM_00038]. ومن جهة الطبقات الأدنى، يستخدم Memory Abstraction Interface مع Fee أو Ea [SWS_NvM_00051]. ويُبلّغ BswM بالحالات، ويُبلّغ DEM وDET بالأخطاء [SWS_NvM_00745] [SWS_NvM_00592].

مخطط السياق: تضمين NvM بين المستخدمين، وBswM، وMemIf/Fee/Ea، بالإضافة إلى DEM وDET. المصادر: [SWS_NvM_00384] [SWS_NvM_00465] [SWS_NvM_00746]

تتكون كل كتلة NVRAM من كتلة NV، وكتلة RAM، وAdministrative Block، ويُضاف إليها اختياريًا كتلة ROM تحتوي على بيانات افتراضية [SWS_NvM_00138]. تتوفر الأنواع Native وRedundant وDataset؛ وهي تختلف في عدد كتل NV وROM [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559]. يقوم NvM بمزامنة كتلة RAM ضمنيًا ومباشرةً، أو صراحةً عبر RAM-Mirror باستخدام دوال رد النداء [SWS_NvM_00511].

تسير دورة الحياة في ثلاث خطوات:

  • يستدعي BswM الدالة NvM_Init حصريًا [SWS_NvM_00693].
  • يتحقق NvM_ReadAll أولاً من ID التكوين ثم يملأ كتل RAM [SWS_NvM_00073] [SWS_NvM_00718].
  • عند إيقاف التشغيل، يحفظ NvM_WriteAll الكتل المعدلة [SWS_NvM_00092]. ويقوم NvM_CancelWriteAll بالإلغاء بصورة غير مدمرة [SWS_NvM_00238].

تُدرج الطلبات الفردية مثل NvM_WriteBlock في قائمة الانتظار وتصبح بعد ذلك في الحالة NVM_REQ_PENDING [SWS_NvM_00185]. اختياريًا، يستخدم NvM قائمة انتظار خاصة للطلبات الفورية (Immediate) [SWS_NvM_00378]. وتُوفَّر النتيجة عبر NvM_GetErrorStatus أو عبر دالة رد نداء مُكوَّنة [SWS_NvM_00015] [SWS_NvM_00740].

مخطط تسلسلي: يُدرج طلب كتابة غير متزامن في قائمة الانتظار، ويُنفّذ في NvM_MainFunction، ويجري تأكيد إتمامه عبر دالة رد نداء، ورسالة إلى BswM، واستعلام عن الحالة. المصادر: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00891]، SWS NvM ص. 160

يعالج NvM أخطاء القراءة عبر ثلاث مراحل:

  • إعادات القراءة المُكوَّنة [SWS_NvM_00526]،
  • النسخة الثانية للكتل المتكررة (redundant) [SWS_NvM_00199]،
  • البيانات الافتراضية مع النتيجة NVM_REQ_RESTORED_DEFAULTS [SWS_NvM_00202].

Interpretation: يُرجّح أن يتبع ترتيب المراحل التسلسل الوارد في Error Description. يعيد NvM محاولة أخطاء الكتابة حتى NVM_MAX_NUM_OF_WRITE_RETRIES ثم يُبلّغ DEM بالقيمة NVM_E_REQ_FAILED [SWS_NvM_00684]. ويتحقق المستخدمون من حالة كتلهم بأنفسهم [SWS_NvM_00694].

الدور في مكدس الذاكرة: منفذ الوصول الوحيد إلى الذاكرة غير المتطايرة

يُجمّع NVRAM Manager (NvM) الوصول إلى البيانات غير المتطايرة. وتتعامل البيئة المحيطة مع الذاكرة غير المتطايرة حصريًا عبر NvM، الذي يوفر واجهة رد نداء لهذا الغرض [SWS_NvM_00384]. يكون الوصول ضمنيًا: ينسخ NvM الكتل بين NVRAM وRAM المشتركة. ويعمل التطبيق مباشرةً مع بيانات RAM مع مراعاة قواعد المزامنة [SWS_NvM_00038] [SWS_NvM_00692]. يجري اختيار الكتلة عبر ID الكتلة المُكوَّن الخاص بها [SWS_NvM_00069] [SWS_NvM_00471]. وتُضمّن Upper Layer لهذا الغرض NvM.h فقط [SWS_NvM_00691]. يوضح الرسم التخطيطي للتحديث الضمني تقسيم العمل: تُطلق أجزاء أخرى من البرمجيات الأساسية عمليات حفظ واستعادة جميع الكتل بناءً على حالة ECU. وتصل SW-C فقط إلى محتوى كتل RAM الخاصة بها (SWS NvM ص. 121).

ومن جهة الطبقات الأدنى، يعمل NvM مع Memory Abstraction Interface. وتوفر هذه الواجهة بالاشتراك مع Fee أو Ea مساحة عناوين خطية ظاهرية بحجم 32 بت [SWS_NvM_00051] [SWS_NvM_00465]. ويقوم NvM بحساب مجاميع الفحص عبر وحدة Crc [SWS_NvM_00466]. ويعرف انتهاء مهمة Lower-Layer بطريقتين:

  • عبر الاستقصاء (Polling) من خلال MemIf_GetJobResult،
  • عند تعطيل الاستقصاء، عبر NvM_JobEndNotification وNvM_JobErrorNotification [SWS_NvM_00440] [SWS_NvM_00441] (Error Description ص. 43).

تُرسل أخطاء الإنتاج إلى DEM [SWS_NvM_00592]، وأخطاء التطوير إلى DET [SWS_NvM_00614]. ويُبلّغ NvM بحالات الطلبات إلى BswM [SWS_NvM_00745] [SWS_NvM_00746].

مخطط السياق: يتوسط NvM بين المستخدمين وBswM من جهة، وMemIf/Fee/Ea من جهة أخرى. ويُبلّغ DEM وDET بالأخطاء. المصادر: [SWS_NvM_00384] [SWS_NvM_00745] [SWS_NvM_00746] [SWS_NvM_00465] [SWS_NvM_00466]، Error Description ص. 43

بنية كتلة NVRAM وأنواع الإدارة الثلاثة

تتكون كتلة NVRAM من المكونات الإلزامية: كتلة NV، وكتلة RAM، وAdministrative Block. وتُعد كتلة ROM التي تحتوي على بيانات افتراضية اختيارية [SWS_NvM_00138] [SWS_NvM_00139] [SWS_NvM_00020]. يحدد واصف الكتلة (Block Descriptor) هذا التركيب في وقت التكوين [SWS_NvM_00140]. المكونات الفردية:

  • تحمل كتلة NV بيانات المستخدم بالإضافة إلى CRC وترويسة (Header) اختياريًا [SWS_NvM_00125] (SWS NvM ص. 39).
  • يجوز أن تقع كتلة RAM في RAM العمومية دون قيود على العناوين [SWS_NvM_00088].
  • تكون Administrative Block غير مرئية للتطبيق. وتحتفظ بفهرس مجموعة البيانات، والسمات، وحقل الخطأ/الحالة [SWS_NvM_00134] [SWS_NvM_00135] [SWS_NvM_00136].

يدعم NvM الأنواع NVM_BLOCK_NATIVE وNVM_BLOCK_REDUNDANT وNVM_BLOCK_DATASET [SWS_NvM_00137]. وهي تختلف في عدد كتل NV وROM [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] (SWS NvM ص. 10). وبالنسبة لكتل Dataset، يسري ما يلي:

  • يحدد NvM_SetDataIndex العنصر. وتُعنون الفهارس بدءًا من NvMNvBlockNum كتل ROM [SWS_NvM_00014] [SWS_NvM_00445] (NV Data Handling ص. 10).
  • لا يُحفظ الفهرس بشكل دائم؛ ويقوم NvM_Init بضبطه على الصفر [SWS_NvM_00160] [SWS_NvM_00192].
  • تتحمل SW-C مسؤولية الضبط الصحيح [SWS_NvM_00695].

مخطط التعاون (بنية الكتلة): المكونات الإلزامية والاختيارية لكتلة NVRAM مع الأعداد المقابلة (Cardinalities) لكل نوع إدارة. المصادر: [SWS_NvM_00138] [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] [SWS_NvM_00134]، SWS NvM ص. 10

دورة الحياة: NvM_Init وNvM_ReadAll وNvM_WriteAll

يستدعي BswM الدالة NvM_Init حصريًا [SWS_NvM_00693]. يعيد NvM_Init ضبط قوائم الانتظار وآلات الحالة ويشير داخليًا إلى «INIT DONE» [SWS_NvM_00399]. وهو لا يُهيئ كتل RAM ولا الوحدات النمطية التابعة [SWS_NvM_00091] [SWS_NvM_00193]. ويكون مؤشر التكوين دائمًا NULL_PTR [SWS_NvM_00881]. بعد ذلك فقط يعالج NvM_MainFunction الطلبات [SWS_NvM_00257].

يملأ NvM_ReadAll كتل RAM بعد ذلك [SWS_NvM_00718]. يُشير الاستدعاء فقط إلى وجود الطلب. وتُؤجل المعالجة حتى تكتمل طلبات الكتل الفردية [SWS_NvM_00243]. وبعد ذلك تُنفّذ المهمة في ثلاث خطوات:

  1. يقارن أولاً ID التكوين المخزن مع ID التكوين المُصرّف [SWS_NvM_00073]. وفي حال وجود اختلاف، يعتمد السلوك على NvMDynamicConfiguration: فمع NvMDynamicConfiguration == FALSE يجري تجاهل الاختلاف [SWS_NvM_00248]. وبخلاف ذلك، تتلقى الكتل غير المقاومة للتغيير بيانات افتراضية [SWS_NvM_00249] [SWS_NvM_00674] (NV Data Handling ص. 15).
  2. ثم يمر تكراريًا على كتل المستخدم باستثناء ID الكتلة 0 و1 [SWS_NvM_00244]. وفي أثناء ذلك، لا يعالج سوى الكتل ذات كتلة RAM الدائمة أو ذات المزامنة الصريحة [SWS_NvM_00118].
  3. وفي النهاية، يضبط النتيجة الإجمالية على NVM_REQ_OK أو NVM_REQ_NOT_OK [SWS_NvM_00895] [SWS_NvM_00301].

في مثال إدارة الأنماط (Mode Management)، لا تبدأ قاعدة BswM NvMReadAllFinished التهيئة المتبقية إلا بعد اكتمال NvM_ReadAll (Mode Management Guide ص. 31).

مخطط تسلسلي: بدء تشغيل غير متزامن باستخدام NvM_Init وNvM_ReadAll مع إبلاغ BswM بحالة الكتل المتعددة (Multiblock). المصادر: [SWS_NvM_00693] [SWS_NvM_00243] [SWS_NvM_00073] [SWS_NvM_00888] [SWS_NvM_00889]، NV Data Handling ص. 20

عند إيقاف التشغيل، يستدعي BswM الدالة NvM_WriteAll [SWS_NvM_00092]. ويتصرف هذا الإجراء على النحو التالي:

  • يكتب كتل RAM الدائمة أو يجلب البيانات المتزامنة صراحةً عبر NvM_WriteRamBlockToNvm [SWS_NvM_00252].
  • يتحقق مسبقًا من الحالة «valid/modified» [SWS_NvM_00682].
  • يتجاوز الكتل المحمية والمقفلة دون إرسال رسالة خطأ [SWS_NvM_00434] [SWS_NvM_00750].
  • لا تقاطعه الطلبات الأخرى [SWS_NvM_00567].

يُميّز المستخدمون الكتل المعدلة باستخدام NvM_SetRamBlockStatus(…, TRUE)، شريطة تفعيل API [SWS_NvM_00406] [SWS_NvM_00408]. وفي كتل علامة التعديل (Dirty Flag)، تتولى RTE إجراء هذا الاستدعاء (NV Data Handling ص. 41).

إن NvM_CancelWriteAll مخصص لـ BswM [SWS_NvM_00703] ويبقى عديم التأثير دون وجود NvM_WriteAll قيد التشغيل [SWS_NvM_00233]. وتُختتم الكتلة الحالية بصورة غير مدمرة [SWS_NvM_00238]. وتحصل الكتل المتبقية ونتيجة الكتل المتعددة على NVM_REQ_CANCELED [SWS_NvM_00236] [SWS_NvM_00237] (SWS NvM ص. 161).

يُكمّل طلبان إضافيان للكتل المتعددة دورة الحياة:

  • يضبط NvM_ValidateAll الكتل ذات التحقق التلقائي على «VALID / CHANGED» [SWS_NvM_00856].
  • يكتب NvM_FirstInitAll البيانات الافتراضية في الكتل أو يُبطل صلاحيتها إذا لم تكن متوفرة [SWS_NvM_00913] [SWS_NvM_00919].

ينطبق طول قائمة انتظار يبلغ واحدًا على جميع طلبات الكتل المتعددة [SWS_NvM_00380].

مخطط تسلسلي: إيقاف التشغيل باستخدام NvM_WriteAll والإلغاء الاختياري بواسطة NvM_CancelWriteAll. المصادر: [SWS_NvM_00092] [SWS_NvM_00682] [SWS_NvM_00238] [SWS_NvM_00237] [SWS_NvM_00889]، Mode Management Guide ص. 37

الطلبات الفردية: قوائم الانتظار، والأولويات، والإفادة بالنتائج

تكون طلبات الكتل الفردية مثل NvM_ReadBlock أو NvM_WriteBlock أو NvM_RestoreBlockDefaults غير متزامنة. تستلم الدالة المعلمات، وتدرج الطلب في قائمة الانتظار، ثم تعود [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00224]. بعد ذلك تصبح نتيجة الكتلة NVM_REQ_PENDING [SWS_NvM_00185]. وعند فيضان قائمة الانتظار، تُرجع الدالة E_NOT_OK [SWS_NvM_00184]. ولا تُدرج الكتلة في قائمة الانتظار إلا إذا لم تكن معلقة بالفعل أو قيد المعالجة [SWS_NvM_00385].

تعمل الخدمات الأخرى بشكل متزامن في سياق المتصل، مثل NvM_SetDataIndex [SWS_NvM_00448] وNvM_GetErrorStatus (SWS NvM ص. 158). ويزيل NvM_CancelJobs الطلبات المعلقة لكتلة معينة؛ غير أن المهمة الجارية تستمر في التنفيذ [SWS_NvM_00536] [SWS_NvM_00537].

تجري المعالجة بصورة تسلسلية وفقًا للأولوية [SWS_NvM_00162]. وإذا كان NvMJobPrioritization نشطًا، يستخدم NvM قائمتي انتظار، إحداهما لطلبات الكتابة الفورية (بيانات حوادث الاصطدام) [SWS_NvM_00564] [SWS_NvM_00378]. ويقوم طلب NvM_WriteBlock من هذا النوع بإلغاء مهمة معلقة بصورة مدمرة [SWS_NvM_00300]. ثم يُعيد NvM_MainFunction بعد ذلك تشغيل المهمة المُلغاة [SWS_NvM_00258]. ودون تحديد الأولويات، يعمل NvM وفق ترتيب الوصول، دون مهام فورية [SWS_NvM_00379]. أما الطلبات التي ترد أثناء تنفيذ طلب متعدد الكتل، فتُدرج في قائمة الانتظار وتُنفّذ لاحقًا [SWS_NvM_00568] [SWS_NvM_00569].

يُودع كل طلب غير متزامن نتيجته في حقل الخطأ/الحالة [SWS_NvM_00175]. ويقرأ NvM_GetErrorStatus هذا الحقل [SWS_NvM_00015]. علاوة على ذلك، هناك مساران اختياريان لتقديم الإفادة:

  • إذا جرى تكوين دالة رد نداء، يستدعي NvM_MainFunction الدالة NvM_SingleBlockCallbackFunction [SWS_NvM_00740] [SWS_NvM_00347]. ودون دالة رد نداء، لا يوجد إشعار غير متزامن [SWS_NvM_00742] (SWS NvM ص. 160).
  • باستخدام NvMBswMBlockStatusInformation، يُبلّغ NvM وحدة BswM بالقبول والنتيجة [SWS_NvM_00890] [SWS_NvM_00891] (SWS NvM ص. 162).

مخطط تسلسلي: طلب كتابة غير متزامن مع رسائل حالة BswM، ودالة رد نداء، واستعلام عن الحالة. المصادر: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00740] [SWS_NvM_00890] [SWS_NvM_00891]، SWS NvM ص. 160

مزامنة كتلة RAM وحالة الكتلة

يعرف NvM طريقتين لمزامنة البيانات مع كتلة RAM الخاصة بالتطبيق. في المزامنة الضمنية، يعمل مباشرةً على كتلة RAM هذه. يوفر التطبيق الكتلة ولا يصل إليها حتى نهاية الطلب [SWS_NvM_00698] [SWS_NvM_00699]. وإذا مرر NULL_PTR، يستخدم NvM كتلة RAM الدائمة [SWS_NvM_00898] [SWS_NvM_00900]. وتظل الكتلة المؤقتة عبر مؤشر ممكنة مع ذلك [SWS_NvM_00278]. وتعمل خدمات PRAM دائمًا على كتلة RAM الدائمة [SWS_NvM_00765] [SWS_NvM_00794]. وفي سيناريو RTE، تكون هذه الكتلة عبارة عن ذاكرة مخصصة لكل نسخة (Per-Instance-Memory) (NV Data Handling ص. 32).

في المزامنة الصريحة (NvMBlockUseSyncMechanism)، يجري التبادل عبر RAM-Mirror داخلي [SWS_NvM_00511]. ويوجد منه واحد فقط، يُحدد حجمه وفقًا لأكبر كتلة معنية [SWS_NvM_00513]. يستدعي NvM الدالة NvMWriteRamBlockToNvCallback أو NvMReadRamBlockFromNvCallback [SWS_NvM_00515] [SWS_NvM_00516]. وإذا أرجعت دالة رد نداء E_NOT_OK، فإنه يعيد الاستدعاء في الدورة التالية، حتى NvMRepeatMirrorOperations مرات [SWS_NvM_00579] [SWS_NvM_00840]. ويُسمح للتطبيق بتعديل كتلة RAM حتى استدعاء رد النداء [SWS_NvM_00705]. تستخدم الكتلة إما المزامنة الصريحة أو كتلة RAM دائمة، وليس كلاهما [SWS_NvM_00904]. تتيح هذه الآلية كتلًا مشتركة عبر NvBlockSwComponentType (NV Data Handling ص. 12).

مخطط تسلسلي: طلب كتابة مع مزامنة صريحة عبر RAM-Mirror، بما في ذلك إعادة المحاولة عند E_NOT_OK. المصادر: [SWS_NvM_00515] [SWS_NvM_00705] [SWS_NvM_00579] [SWS_NvM_00840]، NV Data Handling ص. 27

يحتفظ NvM بحالة «valid»/«invalid» لكتل RAM الدائمة أو للمرآة (Mirror) [SWS_NvM_00128] [SWS_NvM_00132]. الانتقالات بالتفصيل:

  • يُبطل NvM_ReadBlock صلاحية كتلة RAM الدائمة بمجرد إدراجها في قائمة الانتظار [SWS_NvM_00198].
  • بعد القراءة الناجحة تصبح «valid/unchanged» [SWS_NvM_00200].
  • بعد تحميل البيانات الافتراضية تصبح «valid/changed» [SWS_NvM_00366].
  • يُميّزها NvM_SetRamBlockStatus(…, TRUE) بأنها معدلة ويُطلق إعادة حساب CRC في الخلفية [SWS_NvM_00406] [SWS_NvM_00121].
  • بعد الكتابة الناجحة تُعد «valid/unmodified» [SWS_NvM_00472].

مخطط الحالة: حالات كتلة RAM والأحداث المحفزة لها. المصادر: [SWS_NvM_00198] [SWS_NvM_00200] [SWS_NvM_00366] [SWS_NvM_00406] [SWS_NvM_00472] [SWS_NvM_00856]

التكوين، وآليات الحماية، والارتباط بالأقسام (Partitions)

تتوفر ثلاث فئات لتكوين API للموارد المحدودة [SWS_NvM_00149]. لا تدعم الفئة 1 كتل Dataset [SWS_NvM_00365]. ويجري توليد جداول الواصفات [SWS_NvM_00143]. يُصرح المستخدمون عن متطلبات الذاكرة في وقت التكوين [SWS_NvM_00030]. وتقوم وحدات BSW بذلك عبر NvBlockNeeds (BSWMD Template ص. 241). ويشتق مكامل ECU تكوين NvM من ذلك (Methodology ص. 444).

تتوفر عدة آليات حماية للكتل الفردية:

  • يدير حقل سمات الحماية من الكتابة [SWS_NvM_00054]؛ ويُفعّلها NvMBlockWriteProt كإعداد افتراضي [SWS_NvM_00326].
  • تُكتب الكتل ذات NvMWriteBlockOnce مرة واحدة فقط [SWS_NvM_00397]. ويرفض NvM طلبات الكتابة قبل القراءة الأولى [SWS_NvM_00952].
  • بالنسبة للكتل المقفلة (NvM_SetBlockLockStatus)، يُرجع NvM_WriteBlock القيمة E_NOT_OK [SWS_NvM_00749]. ولا يغير هذا القفل أي من NvM_SetRamBlockStatus أو NvM_SetBlockProtection [SWS_NvM_00754].
  • اختياريًا، تتوفر أيضًا ترويسة ID الكتلة الثابت (Static-Block-ID-Header) [SWS_NvM_00522]، ومقارنة CRC لتجنب الكتابة غير الضرورية [SWS_NvM_00849]، والتشفير عبر CSM [SWS_NvM_00976].

  • PAdmin_{Block} (إدارة) [SWS_NvM_00843]
  • PM_{Block} (مرآة) [SWS_NvM_00844]
