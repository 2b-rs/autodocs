يؤمّن ويدير البيانات الدائمة بشكل مستقل عن العتاد عبر كتل NVRAM مهيكلة وبرامج تشغيل التجريد.

تحقق حزمة وحدات 'Memory Services' التخزين المستقل عن العتاد وضمان اتساق بيانات التطبيق غير المتطايرة عبر NVRAM Manager بالإضافة إلى وحدات تجريد العتاد MemIf وFee وEa ([SWS_NvM_00447]، [SWS_MemIf_00039]). وتتم معالجة عمليات القراءة والكتابة غير المتزامنة عبر MainFunctions دورية وتُنفذ مجمعةً أثناء بدء تشغيل وحدة التحكم الإلكترونية (NvM_ReadAll) وكذلك عند إيقاف التشغيل (NvM_WriteAll) ModemanagementGuide ص. 54. وفي حالة حدوث أخطاء في العتاد، تتدخل آليات متعددة المستويات لإعادة المحاولة والتكرار والاسترداد من ROM مع إرسال تقارير تلقائية إلى DEM ([SWS_NvM_00470]).

توفر حزمة 'Memory Services' التخزين الدائم وإدارة البيانات غير المتطايرة في حزمة برمجيات BSW لـ AUTOSAR Classic. وتتضمن NVRAM Manager ([SWS_NvM_00447]) على مستوى الخدمات، بالإضافة إلى Memory Abstraction Interface ([SWS_MemIf_00039]) مع وحدتي Flash EEPROM Emulation ([SWS_Fee_00085]) وEEPROM Abstraction ([SWS_Ea_00083]) على مستوى تجريد العتاد AUTOSAR SWS NVRAMManager ص. 10.

مخطط معماري: هيكل الطبقات وعلاقات الوحدات في حزمة Memory Services. المصادر: [SWS_MemIf_00039]، AUTOSAR SWS NVRAMManager ص. 10

يتم تبادل البيانات عبر واجهات برمجة تطبيقات (APIs) متزامنة للتحكم وأوامر قراءة وكتابة غير متزامنة. ويتم تبادل البيانات إما ضمنيًا عبر كتل RAM الدائمة أو صراحةً عبر مرايا RAM الموجهة للوحدة ([SWS_NvM_00455]، [SWS_NvM_00514]) NVDataHandling ص. 12. وتتم المعالجة الدورية للأوامر المصطفة عبر دوال BSW الرئيسية المنفذة دوريًا (NvM_MainFunction، Fee_MainFunction)، بينما تفوّض MemIf الاستدعاءات بدون حالة إلى برامج التشغيل التابعة ([SWS_MemIf_00040]) AUTOSAR CP SWS FlashEEPROMEmulation ص. 42.

في دورة التشغيل، ينسق BswM إجراءات الكتل المتعددة: عند بدء تشغيل النظام، يقرأ NvM_ReadAll البيانات الدائمة من ذاكرة NV إلى RAM ([SWS_NvM_00460])، بينما يقوم NvM_WriteAll بحفظ البيانات المعدلة عند إيقاف التشغيل ([SWS_NvM_00461]) ModemanagementGuide ص. 54. ويتم اعتراض عمليات القراءة أو الكتابة الخاطئة من خلال محاولات إعادة المحاولة وكذلك النسخ المتكررة أو القيم الاحتياطية من ROM؛ ويُبلغ النظام DEM بالأخطاء الدائمة ([SWS_NvM_00470]، [SWS_NvM_00279]) ErrorDescription ص. 62.

معمارية النظام & دور مجموعة الوحدات

تضمن حزمة وحدات خدمات الذاكرة (Memory Services) لـ AUTOSAR Classic Platform الإدارة القياسية والمستقلة عن العتاد واستدامة بيانات التطبيقات والبرمجيات الأساسية في الذاكرة غير المتطايرة. وتنقسم الحزمة عموديًا إلى طبقتين في بنية برمجيات AUTOSAR الأساسية: NVRAM Manager ([SWS_NvM_00447]) على طبقة الخدمات (Services Layer)، بالإضافة إلى Memory Abstraction Interface ([SWS_MemIf_00039]) مع وحدات التجريد التابعة لها Flash EEPROM Emulation ([SWS_Fee_00085]) وEEPROM Abstraction ([SWS_Ea_00083]) على طبقة تجريد عتاد الذاكرة (Memory Hardware Abstraction Layer) AUTOSAR SWS NVRAMManager ص. 10.

يمثل NVRAM Manager (NvM) نقطة الدخول المركزية لمكونات البرمجيات (SW-C) ووحدات BSW مثل وحدة Diagnostic Event Manager (Dem) SWS DiagnosticEventManager ص. 238. ويدير كتل الذاكرة المنطقية، التي تتألف من كتل NV في الذاكرة غير المتطايرة، وكتل RAM في الذاكرة المتطايرة، بالإضافة إلى كتل ROM اختيارية لبيانات التهيئة الأولية ([SWS_NvM_00137]، [SWS_NvM_00128]). وبحسب المتطلبات، يتم دعم أنواع إدارة الكتل native (NVM_BLOCK_NATIVE)، أو redundant (NVM_BLOCK_REDUNDANT)، أو dataset (NVM_BLOCK_DATASET) AUTOSAR CP RS MemoryServices ص. 10.

تغلّف الوحدتان Fee وEa الخصائص المميزة لوسائط التخزين المادية المعنية (Flash أو EEPROM)، وتعينان أرقام الكتل المنطقية وإزاحات العناوين على مساحات العناوين الخطية لبرامج تشغيل MCAL المعنية (Fls أو Eep) ([SWS_Fee_00087]، [SWS_Ea_00086]) AUTOSAR SWS EEPROMAbstraction ص. 23. وتعمل الوحدة MemIf في هذا السياق كطبقة توجيه بحتة، تقوم بإعادة توجيه عمليات الوصول إلى الوحدة الهدف استنادًا إلى المعامل DeviceIndex، دون الاحتفاظ بهياكل تخزين مؤقت خاصة بها ([SWS_MemIf_00040]).

مخطط معماري: هيكل الطبقات وعلاقات الوحدات في حزمة Memory Services. المصادر: [SWS_MemIf_00039]، AUTOSAR SWS NVRAMManager ص. 10

التكامل ومسارات التفاعل بين الوحدات

يتم التفاعل بين الوحدات عبر مسارات متزامنة وغير متزامنة قياسية بشكل صارم. إذا بدأ مستخدم عملية كتابة عبر NvM_WriteBlock، يتم تسجيل الطلب أولاً في الكتلة الإدارية لـ NvM ([SWS_NvM_00455]). وفي حالة الاستدعاء المتزامن، تتم إعادة التوجيه إلى MemIf عبر MemIf_Write ([SWS_MemIf_00040])، والتي تسلم الاستدعاء بدروها إلى Fee_Write أو Ea_Write ([SWS_Fee_00088]، [SWS_Ea_00087]) AUTOSAR SWS NVRAMManager ص. 160.

فيما يتعلق بالاحتفاظ بالبيانات والمزامنة بين التطبيق وNVRAM Manager، يوجد مفهومان أساسيان: المزامنة الضمنية عبر كتل RAM الدائمة (NvMRamBlockDataAddress) والمزامنة الصريحة عبر مخازن مؤقتة قائمة على المرايا (NvMBlockUseSyncMechanism) NVDataHandling ص. 12. وفي حالة المزامنة الصريحة، ينسخ NvM البيانات الصافية عبر روتينات رد النداء المهيأة NvMWriteRamBlockToNvCallback أو NvMReadRamBlockFromNvCallback بين ذاكرة RAM للتطبيق ومرآة RAM الداخلية ([SWS_NvM_00514]، [SWS_NvM_00515]) EXP NVDataHandling ص. 30.

عند استخدام كتل Dataset (NVM_BLOCK_DATASET)، يحدد المستدعي مسبقًا فهرس مجموعة البيانات المطلوب عبر NvM_SetDataIndex ([SWS_NvM_00448]). وبناءً على ذلك، تحسب وحدات التجريد إزاحة العنوان الدقيقة لبرنامج تشغيل MCAL من رقم الكتلة المنطقي والفهرس ([SWS_NvM_00123]) AUTOSAR SWS Flash EEPROM Emulation ص. 21. وتُمرر طلبات الإلغاء عبر MemIf_Cancel مباشرة إلى الوحدات الفرعية Fee_Cancel أو Ea_Cancel ([SWS_MemIf_00041]، [SWS_Fee_00089]).

مخطط تسلسلي: أمر كتابة غير متزامن مع إشعار رد النداء والاستقصاء الدوري (Polling). المصادر: [SWS_NvM_00455]، AUTOSAR SWS NVRAMManager ص. 160

المزامنة، وقابلية إعادة الدخول، وسياقات المهام

معظم واجهات برمجة التطبيقات للتحكم والحالة في الحزمة، بما في ذلك NvM_GetErrorStatus ([SWS_NvM_00451]) وNvM_SetBlockProtection ([SWS_NvM_00450]) وMemIf_GetVersionInfo ([SWS_MemIf_00045])، متزامنة التنفيذ ويمكن معالجتها مباشرة في سياق مهمة المستدعي AUTOSAR SWS NVRAMManager ص. 157. في المقابل، صُممت الدوال الناقلة للبيانات (NvM_ReadBlock، NvM_WriteBlock، Ea_Write) لتكون غير متزامنة وغير قابلة لإعادة الدخول (non-reentrant) ([SWS_MemIf_00040]، [SWS_Ea_00087]).

تُسند المتابعة الدورية للأوامر الجارية إلى الدوال الرئيسية NvM_MainFunction وFee_MainFunction التي يستدعيها Schedule Manager (SchM) أو إحدى مهام BSW بصورة دورية AUTOSAR CP SWS FlashEEPROMEmulation ص. 42. وفي حالة الرسائل غير المتزامنة من برنامج تشغيل MCAL، يمكن أن يتم الإشعار Fee_JobEndNotification أو Fee_JobErrorNotification مباشرة على مستوى المقاطعة ([SWS_Fee_00095]). ويقوم هذا الإشعار بضبط الحالة إلى MEMIF_JOB_OK أو يستدعي روتينات إشعار مهيأة ([SWS_Fee_00142]، [SWS_Fee_00194]) SWS FlashEEPROMEmulation ص. 37.

تفسير: لمنع حالات التسابق (Race Conditions) بين مستدعي API على مستوى المهام والمعالجة الإضافية التدريجية في MainFunctions، يُرجح أن تكون قوائم الانتظار الداخلية والسمات الإدارية محمية بواسطة أقسام حصرية، بينما تعمل MemIf كطبقة إعادة توجيه عديمة الحالة AUTOSAR SWS NVRAMManager ص. 160.

دورات الحياة النموذجية وأنماط التشغيل

يتم تنسيق دورة حياة الحزمة بشكل وثيق بواسطة Basic Software Mode Manager (BswM) وECU State Manager (EcuM). وأثناء مرحلة بدء تشغيل وحدة التحكم الإلكترونية (Startup Phase)، تتم التهيئة الأولية المتزامنة لوحدات التجريد أولاً بعد برامج التشغيل عبر Fee_Init أو Ea_Init ([SWS_Fee_00085]، [SWS_Ea_00083])، ثم يليها NVRAM Manager عبر NvM_Init ([SWS_NvM_00447]) AUTOSAR SWS NVRAMManager ص. 156.

عقب التهيئة الأولية، يطلق BswM عملية قراءة الكتل المتعددة NvM_ReadAll لاستعادة جميع كتل RAM المحددة كدائمة من الذاكرة غير المتطايرة ([SWS_NvM_00460]) ModemanagementGuide ص. 54. ويبلغ NvM بالتقدم والنتيجة النهائية إلى BswM عبر دالة رد النداء BswM_NvM_CurrentJobMode ([SWS_NvM_00745]، [SWS_NvM_00888]). وتتم الإشارة إلى حالات الكتل الفردية عبر BswM_NvM_CurrentBlockMode ([SWS_NvM_00746]، [SWS_NvM_00890]) ModemanagementGuide ص. 28.

في مرحلة إيقاف التشغيل، يوجه النظام عبر NvM_WriteAll بإعادة الكتابة الدائمة لجميع كتل RAM المعدلة إلى ذاكرة NV ([SWS_NvM_00461]). ولتحسين عدد دورات كتابة Flash، يمكن عبر NvM_SetRamBlockStatus تحديد ما إذا كانت الكتلة قد عُدلت على نحو موجه ([SWS_NvM_00453]) EXP NVDataHandling ص. 18. ويمكن إلغاء عملية الكتابة الجارية عند حدوث أحداث تنبيه مبكرة عبر NvM_CancelWriteAll ([SWS_NvM_00238]) AUTOSAR SWS NVRAMManager ص. 161.

معالجة الأخطاء، وتتبع DET، والتدهور التدريجي للخدمة (Degradation)

تمتلك الحزمة مفهومًا متعدد المستويات لاكتشاف الأخطاء وتدهور الأداء الوظيفي. ويتم الاستعلام عن الأخطاء التي تحدث على مستوى برنامج التشغيل والتجريد عبر حالة الإرجاع MEMIF_JOB_FAILED باستخدام MemIf_GetJobResult أو الإبلاغ عنها عبر NvM_JobErrorNotification ([SWS_Fee_00091]، [SWS_Ea_00095]) ErrorDescription ص. 49.

عند حدوث أخطاء في القراءة، يعتمد NvM على آليات استرداد مهيأة: في البداية، تُجرى محاولات إعادة القراءة (Read Retries) ([SWS_NvM_00390]). وإذا فشلت هذه المحاولات، يتم في الكتل المتكررة (NVM_BLOCK_REDUNDANT) قراءة النسخة المتكررة ([SWS_NvM_00171]، [SWS_NvM_00531]). وإذا تم اكتشاف فقدان التكرار هنا، يضبط NvM نتيجة المهمة إلى NVM_REQ_REDUNDANCY_FAILED ويبلغ عن خطأ الإنتاج NVM_E_LOSS_OF_REDUNDANCY إلى DEM ([SWS_NvM_00470]، [SWS_NvM_00546]) ErrorDescription ص. 62.

إذا نجح الاسترداد عبر قيم ROM الافتراضية، يبلغ NvM بالنتيجة NVM_REQ_RESTORED_FROM_ROM ([SWS_NvM_00470]). وإذا فشلت جميع إجراءات الاسترداد، يتم الإبلاغ عن NVM_E_REQ_FAILED إلى DEM ([SWS_NvM_00279]، [SWS_NvM_00288]) وتُضبط نتيجة الاستعلام إلى NVM_REQ_NOT_OK ([SWS_NvM_00451]). وفي حالة أخطاء الكتابة، يتحكم NvM في عمليات إعادة محاولة الكتابة (NvMMaxNumOfWriteRetries) قبل إلغاء الطلب ([SWS_NvM_00168]، [SWS_NvM_00213]) ErrorDescription ص. 56.

يلخص هذا الدليل البنية الأساسية وتفاعلات الوحدات وآليات الأخطاء لحزمة Memory Services. تستند جميع المعلومات إلى المواصفات المعيارية لـ AUTOSAR Classic Platform.
