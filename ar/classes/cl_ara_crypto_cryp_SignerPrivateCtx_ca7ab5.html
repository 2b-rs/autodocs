يُستخدم لإنشاء التوقيع الرقمي باستخدام مفاتيح تشفيرية خاصة عبر إجراء الخطوة الواحدة أو إجراء البث.

تغلّف الواجهة ara::crypto::cryp::SignerPrivateCtx المفاتيح الخاصة لعمليات التوقيع الرقمي على Adaptive Platform [SWS_CRYPT_23501]. بعد تكوين المفتاح عبر SetKey()، يمكن توقيع الرسائل إما في خطوة واحدة عبر Sign() أو على مراحل متعددة عبر Start() وUpdate() وFinish() [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50040]. جميع الاستدعاءات آمنة لخيوط التنفيذ (thread-safe) وتشير إلى أخطاء مثل السعات غير الكافية للمخزن المؤقت أو حالات السياق غير الصالحة عبر ara::core::Result [SWS_CRYPT_50040].

السياق

تمثل الواجهة ara::crypto::cryp::SignerPrivateCtx سياق التنفيذ التشفيري لعمليات التوقيع الرقمي باستخدام مفتاح خاص على AUTOSAR Adaptive Platform. ترث الفئة من CryptoContext وتغلّف خوارزميات التوقيع غير المتماثلة. لربط مادة المفتاح المطلوبة، يتفاعل السياق إما مباشرةً مع كائن مفتاح خاص عبر PrivateKey::Sptr [SWS_CRYPT_23515] أو مع فتحة مفتاح مُدارة عبر KeySlot::Sptr [SWS_CRYPT_50036]. يدير المتصلون عادةً مثيلات هذه الواجهة عبر الاسم المستعار المحدَّد لنوع المؤشر الذكي ara::crypto::cryp::SignerPrivateCtx::Sptr [SWS_CRYPT_23501].

دورة الحياة

تُشغَّل مثيلات SignerPrivateCtx ككائنات ذات حالة وتُدار عبر هياكل مؤشرات مشتركة (std::shared_ptr) [SWS_CRYPT_23501]. قبل إجراء الحسابات التشفيرية، يكون المثيل في حالة غير مهيأة ويتطلب تعيين مفتاح مناسب. عبر الطريقة SetKey()، يُعيَّن للسياق إما مفتاح خاص محدد [SWS_CRYPT_23515] أو يُودع KeySlot تُستخدم قيمة مفتاحه عند وقت بدء حساب التوقيع [SWS_CRYPT_50036]. بمجرد ربط المفتاح بنجاح، ينتقل السياق إلى الحالة الجاهزة للتشغيل. جميع طرق الواجهة محددة بأنها آمنة من الاستثناءات (exception safe) وآمنة لخيوط التنفيذ (thread-safe) [SWS_CRYPT_23512] [SWS_CRYPT_50037].

في إطار معالجة البيانات، تميز الواجهة بين التوقيع لمرة واحدة وإجراءات البث متعددة المراحل. تُبدأ عملية توقيع البث بواسطة Start() [SWS_CRYPT_50037] [SWS_CRYPT_50038]، وتُغذى تدريجياً بكتل البيانات عبر Update() [SWS_CRYPT_50039]، ويتم إنهاؤها بواسطة Finish() [SWS_CRYPT_50040]. كبديل، يمكن إلغاء البث الجاري في أي وقت عبر Cancel()، مما يعيد المثيل إلى الحالة الجاهزة للتشغيل [SWS_CRYPT_50041].

مخطط الحالة: انتقالات حالة سياق التوقيع من التكوين حتى اكتمال العملية. المصادر: [SWS_CRYPT_23515]، [SWS_CRYPT_50036]، [SWS_CRYPT_23512]، [SWS_CRYPT_50037]، [SWS_CRYPT_50039]، [SWS_CRYPT_50040]، [SWS_CRYPT_50041]

مسار الاستخدام

يمكن للتطبيقات إنشاء التواقيع إما في خطوة واحدة (Single-Call) أو كتدفق بيانات مستمر (Streaming). قبل التنفيذ، يحدد التطبيق عبر GetSignatureSize() الحجم المتوقع للمخزن المؤقت لتنسيق التوقيع المطلوب FormatId [SWS_CRYPT_29004] بالإضافة إلى الحد الأقصى المسموح به لحجم الكتلة لعمليات القراءة الفردية عبر GetMaximumChunkSize() [SWS_CRYPT_50042].

بالنسبة لكميات البيانات الأكبر أو الرسائل المجزأة، يتبع مسار البث نمطاً من ثلاث مراحل:

  1. التهيئة: استدعاء Start() دون معلمات [SWS_CRYPT_50037] أو باستخدام مخزن مؤقت للسياق خاص بالتطبيق ReadOnlyMemRegion [SWS_CRYPT_50038].
  2. المعالجة: التغذية المتكررة للرسائل الجزئية عبر Update()، مع ضرورة التزام كل كتلة بالحد الأقصى المحدد بواسطة GetMaximumChunkSize() [SWS_CRYPT_50039] [SWS_CRYPT_50042].
  3. الاكتمال أو الإلغاء: إنهاء إنشاء التوقيع والكتابة في الذاكرة الهدف عبر Finish() [SWS_CRYPT_50040]، أو الإلغاء المبكر للعملية الجارية باستخدام Cancel() [SWS_CRYPT_50041].

مخطط التسلسل: التدفق النموذجي لإنشاء توقيع عبر البث مع فحص المخزن المؤقت والإنهاء. المصادر: [SWS_CRYPT_23515]، [SWS_CRYPT_29004]، [SWS_CRYPT_50037]، [SWS_CRYPT_50039]، [SWS_CRYPT_50040]
