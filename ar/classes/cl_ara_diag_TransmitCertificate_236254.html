فئة ara::diag::TransmitCertificate

[SWS_DM_01961] Upstream: RS_Diag_04251

class TransmitCertificate {...};

Class to implement the subfunction TransmitCertificate (29 04) of UDS service Authentication as interface to application. This class implements a so called generic interface, where the application has means to handle one ore more certificateEvaluationId transferred certificates.

السياق

توفر الفئة ara::diag::TransmitCertificate واجهة برمجة التطبيقات للوظيفة الفرعية لـ UDS المسماة TransmitCertificate (0x29 04) التابعة للخدمة Authentication (0x29) AUTOSAR_AP_SWS_Diagnostics §8.26.1 «Class: TransmitCertificate». وهي تنفذ واجهة عامة يمكن لتطبيق Adaptive من خلالها استلام وتقييم شهادة واحدة أو أكثر محددة بواسطة معرّف 16 بت (certificateEvaluationId).

في بنية النظام، يعمل ara::diag::TransmitCertificate كحلقة وصل بين AUTOSAR Adaptive Diagnostic Manager (DM) أو Diagnostic Server Instance ومنطق التطبيق الفعلي. يرسل جهاز اختبار تشخيص خارجي طلب مصادقة UDS إلى الخادم، والذي يقوم بدوره بإعادة توجيه الطلب بعد التنشيط إلى التطبيق [SWS_DM_01968]، [SWS_DM_01251].

مخطط السياق: تضمين TransmitCertificate بين جهاز اختبار التشخيص وDiagnostic Manager ومنطق التطبيق. المصادر: [SWS_DM_01968]، [SWS_DM_01251]، [SWS_DM_01249].

دورة الحياة

يتم إنشاء المثيل عبر المُنشئ مع تحديد [SWS_DM_01962]:

  • specifier: ara::core::InstanceSpecifier يشير إلى PortPrototype يتم تحديد نوعه عبر DiagnosticAuthenticationPortMapping [SWS_DM_01962].
  • concurrencyType: يحدد ما إذا كان التنفيذ اللاحق لـ Process سيُعامل على أنه آمن بالنسبة للخيوط (kConcurrent) أو غير آمن بالنسبة للخيوط (kNotConcurrent) [SWS_DM_01962]، [SWS_DM_01968].

عمليات النسخ والنقل محظورة تمامًا: مُنشئ النسخ [SWS_DM_01964]، ومُنشئ النقل [SWS_DM_01963]، وعامل إسناد النسخ [SWS_DM_01966]، وعامل إسناد النقل [SWS_DM_01965] مصرح عنها بأنها محذوفة (=delete). وبالتالي، يوجد مثيل واجهة المصادقة ككائن مرتبط بشكل فريد.

تنقسم دورة الحياة بعد الإنشاء إلى مرحلتي تشغيل:

  1. التوفير (Offered): من خلال استدعاء Offer()، يتم تفويض Diagnostic Manager بإعادة توجيه رسائل UDS الواردة الخاصة بالوظيفة الفرعية إلى الطريقة Process() [SWS_DM_01969].
  2. الإلغاء (Stopped): يؤدي استدعاء StopOffer() إلى إلغاء تسجيل إعادة التوجيه مرة أخرى [SWS_DM_01970].

المُخرِّب افتراضي ومُصرَّح عنه كافتراضي (noexcept = default) [SWS_DM_01967]. وبينما يُعدّ المُنشئ آمنًا بالنسبة للخيوط، فإن Offer() وStopOffer() مُحدَّدان على أنهما غير آمنين بالنسبة للخيوط ولا يجوز استدعاؤهما بالتزامن دون تنسيق [SWS_DM_01962]، [SWS_DM_01969]، [SWS_DM_01970].

مسار الاستخدام

يشمل سير التشغيل العادي التسجيل في Diagnostic Manager، والاستلام غير المتزامن لبيانات الشهادة، وإتمام المعالجة:

  1. إنشاء المثيل والتمكين: ينشئ التطبيق مثيلاً من الفئة المشتقة ويُفعل القبول عبر Offer() [SWS_DM_01962]، [SWS_DM_01969].
  2. الاستلام والمعالجة: عند ورود طلب UDS، يمرر Diagnostic Server البيانات عبر Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler) [SWS_DM_01968]. تُرجع الطريقة ara::core::Future<void>، مما يدعم المعالجة غير المتزامنة. وتقع الدلالات الفعلية وتقييم الشهادة بالكامل على عاتق التطبيق [SWS_DM_01968].
  3. معالجة الإلغاء: يمكن للتطبيق التحقق عبر cancellationHandler.IsCanceled() مما إذا كانت محادثة التشخيص قد أُلغيت، أو تسجيل رد نداء للإشعار بأحداث الإلغاء عبر cancellationHandler.SetNotifier() [SWS_DM_01968].
  4. استجابة إيجابية: إذا انتهى التنفيذ بنجاح دون رمز خطأ، تُرسل Diagnostic Server Instance استجابة UDS إيجابية مع معامل الإرجاع authenticationReturnParameter = 0x13 (CertificateVerified) إلى جهاز الاختبار [SWS_DM_01251].
  5. التنظيف: عند الإنهاء، يتم إنهاء الاستلام عبر StopOffer() [SWS_DM_01970].

مخطط تسلسلي: المسار النموذجي لنقل الشهادة ومعالجتها. المصادر: [SWS_DM_01969]، [SWS_DM_01968]، [SWS_DM_01251]، [SWS_DM_01970].

سيناريوهات الأخطاء

تم تحديد شروط خطأ محددة سواء أثناء التهيئة أو أثناء التشغيل المستمر:

  • أخطاء البيان والنمذجة أثناء الإنشاء: يُبلغ المُنشئ عن انتهاكات إذا تعذر حل InstanceSpecifier (InstanceSpecifierMappingIntegrityViolation)، أو إذا لم يكن PortPrototype المشار إليه مصنف النوع بواسطة DiagnosticTransmitCertificateInterface (PortInterfaceMappingViolation)، أو في حال عدم وجود تعيين للعملية (ProcessMappingViolation)، أو إذا كان InstanceSpecifier محجوزًا بالفعل في العملية (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01962].
  • التسجيل المتعدد: يؤدي استدعاء Offer() مجددًا عندما يكون التوفير نشطًا بالفعل إلى الخطأ DiagOfferErrc::kAlreadyOffered مع دلالات التراجع [SWS_DM_01969].
  • الرفض أثناء المعالجة: إذا فشل التحقق من صحة الشهادة في التطبيق أو حدث خطأ في المعالجة، يُرجع Process() خطأً مطابقًا عبر ara::core::Future. ويجب هنا استخدام رمز استجابة سلبية (NRC) مناسب لـ UDS وفقًا للمعيار ISO 14229-1 عبر DiagUdsNrcErrc [SWS_DM_01968]. وتُنشئ Diagnostic Server Instance بعد ذلك استجابة UDS سلبية (NRC) إلى جهاز الاختبار الخارجي [SWS_DM_01249].

يستند هذا الدليل إلى مواصفة AUTOSAR Adaptive Platform R25-11 للوحدة Diagnostics.
