السياق

يُستخدم هيكل البيانات ara::diag::SovdSwUpdate::UpdatePackageDetails ([SWS_DM_01877]، AUTOSAR_AP_SWS_Diagnostics §8.58.4 «Struct: UpdatePackageDetails») داخل AUTOSAR Adaptive Platform في الوحدة diag كحامل معلومات مهيكل للبيانات الوصفية ومعلمات التنفيذ لحزمة تحديث البرمجيات. وهو مصرح عنه في الترويسة #include "ara/diag/sovd_sw_update.h" ويمثل كمية واجهة أساسية لعمليات التشخيص والتحديث المتعلقة بالبرمجيات، والتي يتم توفيرها عبر معيار ASAM SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01796]).

يتبع التكامل المعماري تقسيم المهام الوظيفي لتحديث برمجيات SOVD (AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»): ونظرًا لأن منطق العمل الفعلي لتحديثات البرمجيات لا يُنفذ داخل Functional Cluster Diagnostics، فإن التنفيذ الوظيفي يقع في المقام الأول على عاتق التطبيق المعني. ويركز المثيل ara::diag::SovdSwUpdate::SovdSwUpdate لـ Diagnostic Server على معالجة بروتوكول SOVD الأساسي وفقًا لمواصفة ASAM SOVD ([SWS_DM_01796]). وفي هذا السياق، يعمل UpdatePackageDetails ككائن نقل قياسي يوفر التطبيق من خلاله بيانات الحزمة التفصيلية لـ Diagnostic Server عبر دالة API ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917]، AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»)، حتى يتمكن من خدمة عملاء SOVD الخارجيين.

مخطط السياق: موضع UpdatePackageDetails في التفاعل بين عميل SOVD وDiagnostic Server والتطبيق. المصادر: [SWS_DM_01796]، [SWS_DM_01877]، [SWS_DM_01917]، AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API».

دورة الحياة

كهيكل بيانات غير نشط (struct) [SWS_DM_01877]، لا يمتلك UpdatePackageDetails آلة حالة خاصة به ولا يتحكم في دورات حياة مستقلة. ويتم الإنشاء كنسخة بواسطة التطبيق في لحظة استعلام محدد، حيث يتم ملء متغيرات الأعضاء العامة بخصائص الحزمة الثابتة والديناميكية:

  • التعريف والتسمية: يخزن الحقل id ([SWS_DM_01878]) معرف ID الفريد للحزمة. وتحدد التسمية name ([SWS_DM_01879]) اسم الحزمة، بينما يوفر translation_id ([SWS_DM_01881]) مفتاحًا للتمثيلات المحلية.
  • بيانات الحجم والتنفيذ: يتم تحديد حجم الحزمة بالبايت عبر size ([SWS_DM_01893]) كـ std::uint64_t. وتتمثل متغيرات التحكم الإضافية في مدة التنفيذ التقديرية duration بالثواني ([SWS_DM_01891]، AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 «duration») كـ ara::core::Optional<std::uint64_t>، بالإضافة إلى العلامة automated ([SWS_DM_01882]، AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 «automated») كـ ara::core::Optional<bool>.
  • الشروط المسبقة وأنشطة المستخدم: تُنقل شروط التنفيذ في preconditions ([SWS_DM_01888]) إلى جانب preconditions_translation_id ([SWS_DM_01889]) بالإضافة إلى execution_conditions ([SWS_DM_01890]). ويضع التطبيق إجراءات المشغل المطلوبة في user_activity ([SWS_DM_01886]) وuser_activity_translation_id ([SWS_DM_01887]). ويمكن تمرير إرشادات إضافية عبر notes ([SWS_DM_01884]) وnotes_translation_id ([SWS_DM_01885]).
  • علاقات المكونات والمصدر: يسرد المتجه affected_components ([SWS_DM_01895]، AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 «affected_components») المكونات التي تتأثر بالحزمة، بينما يحدد updated_components ([SWS_DM_01894]) المكونات المحدثة صراحةً. ويتم الإبلاغ عن مصدر حزمة التحديث عبر origin ([SWS_DM_01883]).

فيما يتعلق بعلاقات الملكية، يتم إنشاء المثيل بواسطة التطبيق وتمريره إلى المتصل عبر قيمة الإرجاع. ويتم تدمير المثيل تلقائيًا بعد مغادرة نطاق الصلاحية وفقًا لدلالات C++ القياسية (RAII). لا توفر البنية مزامنة داخلية لسلاسل العمليات؛ وفي حالة عمليات القراءة أو الكتابة المتزامنة عبر حدود سلاسل العمليات، تقع مسؤولية حماية المثيل على عاتق مكون البرمجيات المتصل.

مسار الاستخدام

يتم الاستخدام المنتظم لـ UpdatePackageDetails في سياق طرق SOVD القياسية للاستعلام عن تفاصيل تحديث البرمجيات ([SWS_DM_01796]). وغالبًا ما يسترجع العميل مسبقًا قائمة بجميع التحديثات المتاحة ([SWS_DM_01797]) قبل طلب تفاصيل حزمة معينة بشكل هادف.

يسير تسلسل الاستدعاء على النحو التالي:

  1. Anfrage durch SOVD-Client: يرسل عميل تشخيص خارجي طلبًا للحصول على تفاصيل حزمة برمجيات معينة إلى Diagnostic Server Instance ([SWS_DM_01796]).
  2. Weiterleitung an die Applikation: يفوض Diagnostic Server تحديد التفاصيل عبر ara::diag::SovdSwUpdate::GetUpdatePackageDetails إلى التطبيق المسجل ([SWS_DM_01917]، AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»).
  3. Zusammenstellung der Daten: يحدد التطبيق البيانات الوصفية للحزمة، وينشئ مثيلًا من UpdatePackageDetails ([SWS_DM_01877]) ويملأ بيانات التعريف مثل id ([SWS_DM_01878]) وsize ([SWS_DM_01893]) بالإضافة إلى التبعيات مثل affected_components ([SWS_DM_01895]).
  4. Rückgabe: تفسير: من المرجح أن يقوم التطبيق بإرجاع كائن UpdatePackageDetails بعد ملئه مباشرة كنتيجة لدالة GetUpdatePackageDetails إلى Diagnostic Server.
  5. Protokollantwort: تفسير: من المفترض أن يتولى Diagnostic Server تسلسل سمات C++ إلى تنسيق استجابة SOVD القياسي وتقديمه إلى العميل الطالب ([SWS_DM_01796]).

مخطط تسلسلي: تدفق الاستدعاء والبيانات أثناء الاستعلام عن UpdatePackageDetails عبر GetUpdatePackageDetails. المصادر: [SWS_DM_01796]، [SWS_DM_01877]، [SWS_DM_01917]، AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»، AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails».

تم إنشاء هذا الدليل بواسطة نظام ذكاء اصطناعي بناءً على مواصفات AUTOSAR Adaptive R25-11.
