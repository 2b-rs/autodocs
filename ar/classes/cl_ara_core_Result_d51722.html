فئة ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

الغرض من الاستخدام

يغلّف ara::core::Result<T,E>، للاستدعاءات المتزامنة، إما قيمة من النوع T أو خطأً من النوع E؛ ويجب أن يكون E هو ara::core::ErrorCode. وبذلك يدعم النوع معالجة أخطاء خالية من الاستثناءات. [SWS_CORE_00701] [SWS_CORE_10600]

جيل وأمبير. دورة الحياة

يمكن إنشاء Result من القيمة أو الخطأ وكذلك عبر FromValue() وFromError(). عمليات النسخ والنقل متاحة ومشروطة noexcept؛ تفاهة المدمر تعتمد على T و E. [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

التفاعل مع الفئات الأخرى

HasValue()، Value()، Error()، Ok() و Err() تسمح بالوصول إلى الحالة والمحتوى. Bind() يحول القيمة المضمنة إلى Result جديدة باستخدام قابل للاستدعاء، بينما Resolve() يستدعي دالة في حالة حدوث خطأ. القيود & معالجة الأخطاء

يتم تعريف الوصول إلى الأخطاء بدون خطأ مضمن أو إلى قيمة بدون قيمة مضمنة على أنه انتهاك. يمكن تشغيل ValueOrThrow() وهو Result-Funktion الوحيد المعفى من الاستخدام بدون تهيئة ara::core. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

الدور في مسار الخطأ الخالي من الاستثناءات

بالنسبة إلى الأخطاء القابلة للاسترداد، ينبغي أن تستخدم الواجهات ara::core::Result أو ara::core::Future؛ ويكون نوع الخطأ Result محدداً بـ ara::core::ErrorCode. RS General §4.1.2 «Error handling» EXP InterfacesGuidelines §3.1.2 «Result»

في الوصول الخالي من الاستثناءات، يفحص المستدعي HasValue() ثم يقرأ Value() أو Error(). يمكن استخدام هذه المراقبات من دون C++ Exceptions؛ أما ValueOrThrow() فهو الانتقال الصريح إلى مسار قائم على الاستثناءات. EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result» RS General §4.1.3 «The use of noexcept»

مخطط نشاط: يتفرع التسلسل المعتاد الخالي من الاستثناءات، بعد HasValue()، إلى قيمة أو خطأ؛ وValueOrThrow() هو مسار Exception المعروض اختياريًا. المصدران: EXP InterfacesGuidelines §3.1.2.3 «Advanced topics» EXP PlatformDesign §18.1.3 «Result».

الجوهر المعياري: القيمة أو الخطأ

يقوم Core-Spezifikation بتعيين Result إلى نموذج معالجة الأخطاء: بالنسبة للأخطاء القابلة للاسترداد، يجب أن يقوم APIs بإرجاع إما Result أو Future. وبالتالي، يفصل Result مسار القيمة العادية عن الخطأ المنقول كقيمة بيانات. SWS Core §7.2 «Error handling» SWS Core §7.2.5.4 «Result»

template <typename F> auto Bind (F &&f) const -> <see below>;

Apply the given Callable to the value of this instance, and return a new ara::core:: Result with the result of the call.

The Callable is expected to be compatible to one of these two interfaces: • Result<XXX, E> f(const T&); • <ARTechTerm{XXX f(const T&);}> • <ARNewline{}> • <ARNewline{}> • <ARTechTerm{Callable}> • Result<XXX> or a XXX directly, where XXX can be any type that is suitable for use by ara::core::Result.

The return type of this function is decltype(f(Value())) for a template argument F that returns a ara::core::Result type, and it is Result<decltype(f(Value())), E> for a template argument F that does not return a ara::core::Result type.

If this instance does not contain a value, a new Result<XXX, E> is still created and returned, with the original error contents of this instance being copied into the new instance.}>}
