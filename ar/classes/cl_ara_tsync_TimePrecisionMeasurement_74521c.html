يوفر بيانات قياس تفصيلية وبتات حالة لتقييم دقة مزامنة الوقت لـ Time Slave.

يقدم الهيكل ara::tsync::TimePrecisionMeasurement قيم قياس تفصيلية لرصد دقة Time Slave متزامن مقارنة بقاعدة وقت عامة. وهو يلتقط طوابع زمنية محلية مباشرة قبل المزامنة وبعدها ([SWS_TS_01401]، [SWS_TS_01406]) بالإضافة إلى انحرافات زمن الانتقال والمعدل. وعبر حقل بتات الحالة [SWS_TS_01403]، يشير كذلك إلى حالات الخطأ مثل فترات خروج المهلة (Timeouts)، أو القفزات الزمنية المفرطة، أو تجاوزات المعدل.

السياق

تُستخدم بنية البيانات ara::tsync::TimePrecisionMeasurement لتوفير بيانات قياس تفصيلية لرصد دقة Time Slave متزامن مقارنة بقاعدة وقت عليا. وداخل الوحدة tsync، تلتقط عند حدوث واقعة مزامنة لقطات للوقت المحلي مباشرة قبل المواءمة مع قاعدة الوقت العامة وبعدها. وبذلك تشكل البنية الواجهة البينية للمراقبة القياسية وتقييم الجودة وتشخيص مزامنة الساعات في الأنظمة الموزعة.

مخطط سياقي: رصد بيانات الدقة وتمريرها بين قاعدة الوقت وTime Slave وتطبيق المراقبة. المصادر: [SWS_TS_01401]، [SWS_TS_01403]، [SWS_TS_01408]

دورة الحياة

بصفته هيكلًا نهائيًا دون إدارة خاصة للمؤشرات أو الموارد، يتم إنشاء مثيل TimePrecisionMeasurement كنوع قيمة (Value Object). وتتم عملية إنشاء المثيل والتعبئة عادة بشكل دوري بواسطة Time Slave الخاص بـ Adaptive Platform مباشرة في أعقاب خطوة المزامنة. لا يمتلك الهيكل مراحل دورة حياة ديناميكية أو انتقالات حالة داخلية؛ وتكون حالته غير قابلة للتغيير بدءًا من وقت التعبئة كسجل بيانات قياس متسق. وبما أنه يُفترض عادة أن يتم تمرير الهيكل بنسخه أو عبر مراجع ثابتة إلى المكونات المقيِّمة، فلا توجد علاقات ملكية عليا أو متطلبات إتلاف معقدة. ويُعد الوصول المتزامن للقراءة إلى مثيل معبأ من عدة خيوط تنفيذ غير حرج، ما لم تحدث عملية كتابة متزامنة.

مسار الاستخدام

يتبع التقييم النموذجي لقيم القياس نمطًا ثابتًا لتحليل دقة المسير وقفزات المزامنة وتأخيرات الشبكة:

  • فحص حالة المزامنة: أولًا، يتم تحليل حقل البتات [SWS_TS_01403] (timeBaseStatus) لتحديد ما إذا كانت هناك مزامنة عامة صالحة أم أن شروط خطأ قد حدثت.
  • تحديد القفزة الزمنية: من خلال مقارنة الطوابع الزمنية لقاعدة الوقت المحلية مباشرة قبل المزامنة ([SWS_TS_01406] locSeconds، [SWS_TS_01407] locNanoSeconds) بالقيم الموجودة مباشرة بعد المزامنة ([SWS_TS_01401] glbSeconds، [SWS_TS_01402] glbNanoSeconds)، يمكن حساب قفزة التصحيح المطبقة بدقة.
  • تحديد جودة الإرسال: عبر [SWS_TS_01408] (pathDelay) يتم تقييم زمن الإرسال وانتقال الإشارة الحالي بالنانوثانية. وبالإضافة إلى ذلك، يوفر [SWS_TS_01405] (rateDeviation) انحراف المعدل المحسوب لمعدل النبض المحلي مباشرة بعد قياس المعدل.
  • الربط بالوقت المحلي الافتراضي: تتيح الـ 32 بتة الدنيا لقاعدة الوقت المحلية الافتراضية ([SWS_TS_01404] virtualLocalTimeLow) ربط وقت المزامنة بالساعة المرجعية المستمرة للعقدة.

سيناريوهات الأخطاء

لا يتم الإبلاغ عن حالات الخطأ والاستثناء عبر استثناءات C++‎، بل يتم ترميزها مباشرة عبر بتات الحالة في [SWS_TS_01403] (timeBaseStatus). ويجب على المكونات المقيِّمة قبل مواصلة معالجة قيم الوقت التحقق من شروط الخطأ الموجودة:

  • مهلة الاستقبال: إذا كانت البتة 0 (TIMEOUT، 0x01) معينة، فهذا يعني حدوث انتهاء مهلة عند استقبال رسائل المزامنة.
  • القفزات الزمنية: تشير البتات TIMELEAP_FUTURE (0x10، البتة 4) أو TIMELEAP_PAST (0x20، البتة 5) إلى أنه تم تجاوز حد معيّن لتصحيحات الوقت المفاجئة إلى المستقبل أو الماضي.
  • أخطاء المعدل: إذا كانت البتة 7 (RATE_EXCEEDED، 0x80) معينة، فإن معدل النبض المحسوب يتجاوز القيم الحدية المحددة؛ بينما تشير البتة 6 (RATE_CORRECTED، 0x40) إلى ما إذا كان قد أمكن حساب تصحيح معدل صالح على الإطلاق.
  • شرط الاعتمادية: وفقًا لـ [SWS_TS_01403]، لا يمكن أن تكون البتات TIMEOUT وTIMELEAP_FUTURE وTIMELEAP_PAST وSYNC_TO_GATEWAY (0x04، البتة 2) معينة إلا إذا كانت البتة 3 (GLOBAL_TIME_BASE، 0x08) معينة. وفي حال غياب GLOBAL_TIME_BASE، فإن قاعدة الوقت المحلية كانت تعمل حتى الآن حصرًا على الساعة المرجعية المحلية ولم تكن متزامنة قط مع قاعدة الوقت العامة.

تم إنشاء هذا الدليل بواسطة ذكاء اصطناعي بناءً على مواصفات AUTOSAR بالإصدار R25-11.

                          std::uint8_t timeBaseStatus;
                          

                          TimeBaseStatus. Time Base Status of the Local Time Base directly after synchronization with the Global Time Base TIMEOUT 0x01 Bit 0 (LSB): 0x00: No Timeout on receiving Synchronisation Messages 0x01: Timeout on receiving Synchronisation Messages SYNC_TO_GATEWAY 0x04 Bit 2 0x00: Local Time Base is synchronous to Global Time Master 0x04: Local Time Base updates are based on a Time Gateway below the Global Time Master GLOBAL_TIME_BASE 0x08 Bit 3 0x00: Local Time Base is based on Local Time Base reference clock only (never synchronized with Global Time Base) 0x08: Local Time Base was at least synchronized with Global Time Base one time TIMELEAP_FUTURE 0x10 Bit 4 0x00: No leap into the future within the received time for Time Base, 0x10: Leap into the future within the received time for Time Base exceeds a configured threshold TIMELEAP_ PAST 0x20 Bit 5 0x00: No leap into the past within the received time for Time Base 0x20: Leap into the past within the received time for Time Base exceeds a configured threshold.
                          Bit 6 RATE_CORRECTED 0x00: Valid rate correction not calculated for the Synchronized Time Base, 0x40: Valid rate correction calculated for the Synchronized Time Base. Bit 7 RATE_EXCEEDED 0x00: Calculated rate for Time Base does not exceed limits, 0x80: Calculated rate for Time Base exceeds limits. Description Bit 1 is always 0 (reserved for future usage) Variables of this type are used to express if and how a Local Time Base is synchronized to the Global Time Master. The type is a bitfield of individual status bits, although not every combination is possible, i.e. any of the bits TIMEOUT, TIMELEAP_ FUTURE, TIMELEAP_PAST and SYNC_TO_GATEWAY can only be set if the GLOBAL_ TIME_BASE bit is set.
