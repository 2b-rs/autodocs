فئة ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

يُستخدم للكتابة المخزنة مؤقتاً للملفات الثنائية والنصية وكذلك لمزامنتها مع وحدة التخزين الفعلية.

تتيح الفئة ara::per::WriteAccessor كتابة محتويات الملفات الثنائية أو النصية في وحدة الاستمرارية وتوفر طرقاً لعمليات الكتابة غير المنسقة بالإضافة إلى عامل تدفق منسق [SWS_PER_00423]. ونظراً لإمكانية تخزين عمليات الكتابة مؤقتاً في البداية في نظام التشغيل، فإن استدعاء SyncToFile() يفرض التفريغ الدائم على وحدة التخزين الفعلية [SWS_PER_00122]. وجميع الطرق آمنة من الاستثناءات، ولكنها ليست آمنة بالنسبة للخيوط، ولهذا السبب يجب حماية عمليات الوصول المتزامنة من قِبل التطبيق.

السياق

إن ara::per::WriteAccessor هي فئة نهائية لوحدة الاستمرارية (per) الخاصة بـ AUTOSAR Adaptive Platform وتشتق افتراضياً من FileAccessor. توفر الفئة عمليات كتابة لمحتويات الملفات. وتقدم طرقاً للكتابة غير المنسقة والمنضبطة مع معالجة الأخطاء عبر ara::core::Result بالإضافة إلى عامل تدفق محمل بصورة زائدة للكتابة المنسقة. وتعمل الأطراف المتفاعلة كالتطبيق المستدعي، ومخزن الملفات المؤقت الداخلي لنظام التشغيل، ووسيط التخزين الفعلي.

دورة الحياة

تم حذف المنشئ الافتراضي لـ WriteAccessor صراحةً ولا يجوز استخدامه [SWS_PER_00596]. (تفسير: يُرجح إنشاء مثيلات WriteAccessor وتوفيرها عبر طرق المصنع لوحدات إدارة الاستمرارية الأعلى مستوى مثل تخزين الملفات). سؤال Q-af92be8494274611 (مفتوح)

يتم الإتلاف عبر المدمر الافتراضي ~WriteAccessor() [SWS_PER_00597]. تم تحديد الفئة وطرقها على أنها آمنة من الاستثناءات (”exception safe“) وتم الإعلان عنها كـ noexcept. وفيما يتعلق بالتزامن، فإن WriteAccessor ليست آمنة بالنسبة للخيوط (”not thread-safe“) [SWS_PER_00597]؛ ويجب تأمين عمليات الوصول المتوازية إلى نفس المثيل خارجياً من قِبل التطبيق.

مسار الاستخدام

يشمل التسلسل العادي كتابة البيانات في الوضع غير المنسق أو المنسق، والتعديل الاختياري لحجم الملف، والتخزين الدائم النهائي:

  • كتابة البيانات الثنائية: عبر WriteBinary()، تتم كتابة نطاق بايتات (ara::core::Span<const ara::core::Byte>) في الملف [SWS_PER_00423].
  • كتابة البيانات النصية: باستخدام WriteText()، يتم تمرير سلاسل نصية عبر ara::core::StringView [SWS_PER_00166]. بالإضافة إلى ذلك، يتوفر operator<< كوظيفة ملائمة لحالات الاستخدام غير الحرجة، مع تجاهل الأخطاء التي تحدث بشكل ضمني [SWS_PER_00125].
  • فرض الاستمرارية: يعتمد وقت التخزين الفعلي على تنفيذ الاستمرارية؛ يقوم SyncToFile() بتفريغ المخزن المؤقت لنظام التشغيل بشكل ملزم إلى وسيط التخزين [SWS_PER_00122]، [SWS_PER_00423]، [SWS_PER_00166].
  • تعديل حجم الملف: باستخدام SetFileSize()، يمكن تقليص الملف، مما يزيل المحتويات الزائدة؛ ويظل موضع الملف دون تغيير أو يتم ضبطه على آخر موضع صالح أو 0 [SWS_PER_00428].

مخطط تسلسلي: عمليات الكتابة متبوعة بالمزامنة مع وحدة التخزين الفعلية. المصادر: [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122]

سيناريوهات الأخطاء

تُرجع الطرق WriteBinary() وWriteText() وSyncToFile() وSetFileSize() الكائن ara::core::Result<void>، والذي يحتوي في حالة الفشل على رموز أخطاء محددة:

  • PerErrc::kPhysicalStorageFailure: يفشل الوصول إلى وسيط التخزين الفعلي [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122]، [SWS_PER_00428]. وتكون حالة الملف غير معروفة وقد تتلف بالكامل (دون دلالات التراجع rollback).
  • PerErrc::kOutOfStorageSpace: مساحة تخزين فعلية غير كافية [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122]. عند الكتابة، يتم تجاهل الجزء الزائد ويستقر الموضع عند نهاية الملف (دون دلالات التراجع rollback).
  • PerErrc::kQuotaExceeded: سيتجاوز الملف الحد الأقصى للحجم الذي تم تكوينه (AllowedSize) [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122] (دلالات التراجع rollback).
  • PerErrc::kEncryptionFailed: يفشل التشفير أو فك التشفير [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122]، [SWS_PER_00428]. يتم بالفعل تحديث المخزن المؤقت والموضع، ولكن يتعذر الحفاظ على استمرارية الملف ويعكس إصداراً أقدم على وحدة التخزين (دلالات التراجع rollback).
  • PerErrc::kAuthenticationFailed: يفشل حساب MAC أو التحقق منه [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00122]، [SWS_PER_00428] (دلالات التراجع rollback).
  • PerErrc::kValidationFailed: لا يمكن ضمان صلاحية البيانات المخزنة [SWS_PER_00423]، [SWS_PER_00166]، [SWS_PER_00428] (دلالات التراجع rollback).
  • PerErrc::kInvalidSize: حجم الملف الجديد عند SetFileSize() أكبر من حجم الملف الحالي [SWS_PER_00428] (دلالات التراجع rollback).

تم إنشاء هذا الدليل بواسطة ذكاء اصطناعي بناءً على مواصفة AUTOSAR R25-11.

SetFileSize دالة

Reduces the size of the file to ’size’, effectively removing the current content of the file beyond this size. The current file position is unchanged if it is lower than ’size’, or set to the last valid position in the file otherwise. If ’size’ is 0, the current file position will also be set to 0.

ara::core::Result< void > SetFileSize (std::uint64_t size) noexcept;
SyncToFile دالة

Flushes the current file content to the physical storage.

ara::core::Result< void > SyncToFile () noexcept;
WriteBinary دالة

Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;
WriteText دالة

Writes the content of a StringView to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

      عند التنفيذ، يمكن أن تحدث حالات خطأ مختلفة، والتي يتمتع بعضها بدلالات التراجع (rollback) [SWS_PER_00122]:
      

        

      • StorageFailure: يحدث عندما يفشل الوصول الفعلي إلى وسيط التخزين (بدون دلالات تراجع) [SWS_PER_00122].

      • PerErrc::kOutOfStorageSpace: يتم إرجاعه إذا كانت مساحة التخزين الفعلية غير كافية للملف المُعدّل (بدون دلالات تراجع) [SWS_PER_00122].
        • 

      • PerErrc::kQuotaExceeded: يتم الإبلاغ عنه عندما يتجاوز الملف الحجم الأقصى المكوّن AllowedSize لـ File Storage (مع دلالات تراجع) [SWS_PER_00122].
        • 

      • PerErrc::kEncryptionFailed: فشل تشفير البيانات المخزنة (مع دلالات التراجع) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed: فشل حساب MAC للبيانات (مع دلالات التراجع) [SWS_PER_00122].
        •

              ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;
              

              Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed.
