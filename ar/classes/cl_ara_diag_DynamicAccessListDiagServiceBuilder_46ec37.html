يتيح البناء التدريجي والإنهاء النهائي لقوائم أذونات الوصول الديناميكية لخدمات التشخيص.

تُستخدم الفئة للإنشاء التدريجي لقوائم أذونات الوصول الديناميكية لخدمات التشخيص عبر API انسيابية قابلة للربط المتسلسل ([SWS_DM_01166]). وتضيف التطبيقات بايتات دقيقة ونطاقات قيم بالإضافة إلى أحرف البدل لتعريف أنماط الوصول لـ Diagnostic Server بمرونة ([SWS_DM_01175]، [SWS_DM_01220]). وقبل تدمير الكائن القابل للنقل فقط وغير الآمن خيطياً، يجب بالضرورة استدعاء الدالة Build() لإنهاء التهيئة ([SWS_DM_01181]).

السياق

تخدم الفئة ara::diag::DynamicAccessListDiagServiceBuilder تطبيقات AUTOSAR Adaptive Platform للبناء التدريجي لقوائم أذونات الوصول الديناميكية (DynamicAccessList) لخدمات التشخيص ([SWS_DM_01166]، AUTOSAR_AP_SWS_Diagnostics §8.15.1 «Class: DynamicAccessListDiagServiceBuilder»). وعبر هذه القوائم، يتحكم التطبيق في أي طلبات تشخيص (على سبيل المثال، خدمات UDS محددة مع DIDs معينة أو دوال فرعية) يتم تفويضها ديناميكياً أثناء وقت التشغيل (AUTOSAR_AP_SWS_Diagnostics §8.2 «Adding wildcards to a DynamicAccessList»).

شركاء التفاعل المركزيون هم التطبيق نفسه، ودوال المصنع للفئة ara::diag::DiagnosticServiceDynamicAccessList ([SWS_DM_01164]، [SWS_DM_01165])، بالإضافة إلى مثيل Diagnostic Server الذي يقيّم أنماط البت والبايت المُجمَّعة عند التحقق من حقوق الخدمة مقابل الطلبات الواردة ([SWS_DM_01220]، [SWS_DM_01221]). ولتمثيل هياكل الأنماط، توفر الفئة الأسماء المستعارة للأنواع Byte للثمانيات الفردية (std::uint8_t) وByteString لتسلسلات البايت (ara::core::Span<Byte>) ([SWS_DM_01167]، [SWS_DM_01168]، AUTOSAR_AP_SWS_Diagnostics §8.15.1.1 «Public Member Types»).

دورة الحياة

يتم إنشاء مثيل كائن الباني عادةً عبر DiagnosticServiceDynamicAccessList::MakeServiceBuilder ([SWS_DM_01164]، [SWS_DM_01165]) أو مباشرةً عبر المنشئ، الذي يقبل قيمة ابتدائية ومرجعاً إلى المخزن المؤقت للتسلسل content (ara::core::Vector<std::uint8_t>&) ([SWS_DM_01169]). تفسير: يُرجّح أن المعلمة content تعمل كذاكرة تخزين يتم ملؤها باستمرار للتمثيل المتسلسل، والذي يتم تمريره بعد الإكمال إلى Diagnostic Server.

فيما يتعلق بالملكية وقابلية النسخ، تفرض الفئة دلالات نقل فقط صارمة مع تعيين مقيد: فمنشئ النسخ ([SWS_DM_01171]) ومعامل تعيين النسخ ([SWS_DM_01172]) محذوفان (=delete). وبالمثل، فإن معامل تعيين النقل محذوف ([SWS_DM_01173]). ويتم تنفيذ منشئ النقل فقط ([SWS_DM_01170])، بحيث يمكن نقل المثيلات عند الحاجة، ولكن لا يمكن تكرارها أو إعادة تعيينها دون رقابة.

تخضع دورة الحياة لشرط لاحق إلزامي: قبل استدعاء المدمر ([SWS_DM_01174])، يجب استدعاء الدالة Build() لإكمال إنشاء القائمة ([SWS_DM_01181]). وبينما حُددت المنشئات بأنها آمنة خيطياً ([SWS_DM_01169]، [SWS_DM_01170])، فإن جميع دوال توسيع الأنماط والمدمر ليست آمنة خيطياً (not thread-safe، [SWS_DM_01174]).

مخطط الحالة: مراحل حياة الباني بدءاً من الإنشاء مروراً بالبناء التدريجي للنمط وحتى الإنهاء النهائي الإلزامي قبل التدمير. المصادر: [SWS_DM_01169]، [SWS_DM_01175]، [SWS_DM_01181]، [SWS_DM_01174].

مسار الاستخدام

تتم تهيئة نمط ما عبر API انسيابية، حيث تُعيد استدعاءات الدوال مرجعاً إلى نفس مثيل الباني ([SWS_DM_01175]):

  1. التهيئة: يُنشئ التطبيق الباني، على سبيل المثال عبر DiagnosticServiceDynamicAccessList::MakeServiceBuilder ببايت تمهيدي أو سلسلة بايتات تمهيدية ([SWS_DM_01164]، [SWS_DM_01165]).
  2. توسيع النمط: عبر دوال Add() المحملة بشكل زائد، يتم إلحاق بايتات مفردة ([SWS_DM_01175])، أو تسلسلات بايتات ([SWS_DM_01176])، أو نطاقات قيم مغلقة ByteRange ([SWS_DM_01177]). ويتم فحص هذه القيم لاحقاً أثناء التقييم للتحقق من التطابق الدقيق.
  3. إدراج أحرف البدل: باستخدام Any(numberOfBytesToIgnore)، يحدد التطبيق عناصر نائبة ([SWS_DM_01178]). ويتجاهل Diagnostic Server العدد المحدد من البايتات أثناء مطابقة النمط، مما يتيح تحقيق مرشحات مرنة مثل 22F1XX لنطاقات DID ([SWS_DM_01220]، AUTOSAR_AP_SWS_Diagnostics §8.2 «Adding wildcards to a DynamicAccessList»).
  4. إكمال النمط والإنهاء النهائي: عبر EndsWith()، يمكن تحديد بايت إنهاء أو نطاق إنهاء ([SWS_DM_01179]، [SWS_DM_01180]، [SWS_DM_01221]). وفي النهاية، يُنهي استدعاء Build() عملية الإنشاء بشكل نهائي ([SWS_DM_01181]).

مخطط التسلسل: تسلسل تفاعل نموذجي بين التطبيق، ودالة المصنع، والباني أثناء تعريف النمط. المصادر: [SWS_DM_01165]، [SWS_DM_01175]، [SWS_DM_01178]، [SWS_DM_01181].

سيناريوهات الأخطاء

أُعلن أن جميع دوال الفئة مزودة بـ noexcept ومحددة بأنها آمنة استثنائياً (exception safe) ([SWS_DM_01169]، [SWS_DM_01174]، [SWS_DM_01181]). ولا تحدث معالجة للأخطاء عبر استثناءات C++ أو قيم إرجاع الأخطاء على مستوى API.

يتمثل الشرط المسبق التعاقدي الأساسي في استدعاء Build() قبل تدمير الباني ([SWS_DM_01181]). تفسير: إذا تم تدمير كائن الباني دون تنفيذ Build()، فمن المرجح أن يتم تجاهل تهيئة النمط التي بدأت أو ترك حالة غير صالحة في قائمة الوصول الأساسية.

علاوة على ذلك، فإن الدوال المُعدِّلة ليست آمنة خيطياً ([SWS_DM_01175]، [SWS_DM_01178]، [SWS_DM_01181]). ويؤدي الوصول المتوازي غير المحمي إلى نفس مثيل الباني من خيوط متعددة إلى حالات ذاكرة غير محددة (سباقات البيانات / Data Races).
