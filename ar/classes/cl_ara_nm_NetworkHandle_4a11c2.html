يتيح لـ State Management طلب ومراقبة حالات الاتصال للشبكات المنطقية والفيزيائية.

يمثل ara::nm::NetworkHandle كائن وصول قابل للنقل وغير قابل للنسخ، يستخدمه State Management عبر معرّف الكائن لطلب ومراقبة حالة الاتصال للشبكات [SWS_ANM_01000]، [SWS_ANM_01001]. وإلى جانب الاستعلامات المتزامنة عن الحالة، تتيح الفئة تعيين الطلبات وتسجيل أدوات الإشعار (Notifiers) للحالات الفعلية أو المطلوبة [SWS_ANM_01007]، [SWS_ANM_01009]، [SWS_ANM_01010]. ويتم الإبلاغ عن عدم توفر الخدمة أو أدوات الإشعار الخاطئة عبر رموز خطأ موحدة في كائن النتيجة.

السياق

تعمل الفئة ara::nm::NetworkHandle في الوحدة nm ككائن وصول موحد لمقبض شبكة منطقية أو فيزيائية محددة، يُعنون عبر ara::core::InstanceSpecifier لنموذج أولي للمنفذ (PortPrototype) [SWS_ANM_01000]، [SWS_ANM_01001]. والمستخدم الأساسي لهذه الواجهة هو State Management الوظيفي (SM)، والذي يطلب ويراقب متطلبات الاتصال لـ Partial Network Cluster (PNC)، أو شبكات VLAN، أو الشبكات الفيزيائية عبر المقبض [SWS_ANM_01000]، [SWS_ANM_01009]. وكطبقة وسيطة، يغلف الكائن التفاعل بين مجموعة الوظائف الطالبة ونظام NM الفرعي الأساسي.

مخطط سياقي: تضمين NetworkHandle بين State Management وإدارة الشبكة (NM). المصادر: [SWS_ANM_01000]، [SWS_ANM_01001]، [SWS_ANM_01009]، [SWS_ANM_01010]، [SWS_ANM_01020]، [SWS_ANM_01007]

دورة الحياة

تتم تهيئة كائن ara::nm::NetworkHandle بشكل صريح مع تحديد ara::core::InstanceSpecifier صالح لـ NetworkManagementPortInterface؛ وتم تحديد هذا المنشئ ليكون thread-safe [SWS_ANM_01001]. ويمتلك الكائن دلالات حصرية: تم حذف منشئ النسخ وعامل تعيين النسخ بشكل صريح (= delete) [SWS_ANM_01005]، [SWS_ANM_01006]. تدعم الفئة دلالات النقل عبر منشئ النقل وتعيين النقل، مع العلم أن التعيين ليس thread-safe [SWS_ANM_01003]، [SWS_ANM_01004].

يتم التدمير عبر المدمر غير الآمن لخيارات المعالجة المتعددة ~NetworkHandle() [SWS_ANM_01002]. يُفترض أنه ينبغي للتطبيق إلغاء تسجيل أدوات الإشعار المسجلة قبل التدمير، لتجنب الوصول غير المتزامن إلى سياقات غير صالحة (تفسير). وفيما يتعلق بحالات الشبكة، يمثل المقبض مستويين أساسيين عبر التعداد NetworkStateType: kNoCom (شبكة مخصصة واحدة على الأقل ليست في حالة الاتصال الكامل) وkFullCom (جميع الشبكات المخصصة نشطة) [SWS_ANM_01358].

مسار الاستخدام

يشمل التدفق المعتاد إنشاء النسخة، والتسجيل الاختياري لأدوات الإخطار (Notifiers)، وطلب حالة الشبكة، بالإضافة إلى التحرير اللاحق:

  • إنشاء النسخة: إنشاء المقبض باستخدام معرّف النسخة [SWS_ANM_01001].
  • تسجيل المراقبين: تسجيل دوال رد الاتصال من النوع NetworkStateChangeNotifier [SWS_ANM_01020] إما للحالة الفعلية السارية عبر RegisterNetworkStateChangeNotifier [SWS_ANM_01010] أو للحالة المطلوبة عبر RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]. تتوفر كلتا الطريقتين أيضًا كمتغير قالب لتحديد سياق تنفيذ مخصص من قبل المستخدم (ExecutorT) [SWS_ANM_01014]، [SWS_ANM_01015]. يمكن تنشيط أداة إخطار واحدة كحد أقصى لكل فئة لكل مقبض.
  • طلب الحالة: طلب الاتصال الكامل (NetworkStateType::kFullCom) أو التحرير (NetworkStateType::kNoCom) عبر SetNetworkRequestedState [SWS_ANM_01009].
  • الاستعلام عن الحالة: القراءة المتزامنة للحالة المطلوبة حاليًا باستخدام GetNetworkRequestedState [SWS_ANM_01008] أو لحالة الشبكة السارية فعليًا باستخدام GetNetworkState [SWS_ANM_01007]. كلا الاستعلامين آمنان بالنسبة للخيوط (thread-safe).
  • التنظيف: إلغاء تسجيل معالجات رد الاتصال صراحةً عبر UnregisterNetworkStateChangeNotifier [SWS_ANM_01011] وUnregisterNetworkRequestedStateChangeNotifier [SWS_ANM_01013].

مخطط التسلسل: مسار الاستخدام النموذجي لتسجيل أدوات الإخطار، وطلب الحالة، والاستعلام. المصادر: [SWS_ANM_01001]، [SWS_ANM_01007]، [SWS_ANM_01009]، [SWS_ANM_01010]

سيناريوهات الأخطاء

تشير استدعاءات الطرق في NetworkHandle إلى الأخطاء عبر ara::core::Result. تم تحديد حالات الخطأ التالية:

  • NmErrc::kServiceNotAvailable: تحدث عند SetNetworkRequestedState [SWS_ANM_01009]، وGetNetworkRequestedState [SWS_ANM_01008]، وGetNetworkState [SWS_ANM_01007]، إذا كانت خدمة إدارة الشبكة الأساسية غير متاحة أو لا تستجيب.
  • NmErrc::kInvalidHandler: يتم إرجاعها بواسطة طرق تسجيل أدوات الإخطار [SWS_ANM_01010]، [SWS_ANM_01012]، [SWS_ANM_01014]، [SWS_ANM_01015]، في حال تم تمرير دالة معالج غير صالحة أو إذا كان هناك أداة إخطار مسجلة بالفعل.

فيما يتعلق بالتزامن، فإن استعلامات الحالة للقراءة GetNetworkState وGetNetworkRequestedState آمنة بالنسبة للخيوط (thread-safe)، في حين أن العمليات المعدِّلة والتسجيلات ليست آمنة بالنسبة للخيوط وتتطلب مزامنة خارجية [SWS_ANM_01007]، [SWS_ANM_01008]، [SWS_ANM_01009]، [SWS_ANM_01010].

تم إنشاء دليل الفئة هذا آليًا استنادًا إلى بيانات مواصفات AUTOSAR R25-11.

تعمل الفئة NetworkHandle ككائن وصول إلى مقبض شبكة تتم مخاطبته عبر ara::core::InstanceSpecifier، وهي مخصصة لـ State Management [SWS_ANM_01000]. يتم إنشاء النسخ عبر تمرير الـ Instance-Specifier لنموذج أولي لمنفذ NetworkManagementPortInterface [SWS_ANM_01001]. وبما أن الفئة معلنة كـ final، فلا يمكن استخدامها كفئة أساسية للاشتقاقات [SWS_ANM_01000].

دلالات النقل والتزامن

تمتلك كائنات هذه الفئة دلالات نقل خالصة: منشئ النسخ [SWS_ANM_01005] وعامل إسناد النسخ [SWS_ANM_01006] محذوفان (= delete). ويمكن نقل النسخ بدلاً من ذلك عبر منشئ النقل [SWS_ANM_01003] وعامل إسناد النقل [SWS_ANM_01004].

فيما يتعلق بأمان مؤشرات الترابط (Thread Safety)، تسري المتطلبات التالية:

  • منشئ الفئة المزود بـ InstanceSpecifier آمن بالنسبة لمؤشرات الترابط (thread-safe) [SWS_ANM_01001].
  • بالنسبة لمنشئ النقل، تم تعريف أمان مؤشرات الترابط بصورة خاصة بالتنفيذ (implementation-defined) [SWS_ANM_01003].
  • تم تحديد هادم الفئة [SWS_ANM_01002] وعامل تعيين النقل [SWS_ANM_01004] صراحةً على أنهما غير آمنين بالنسبة لمؤشرات الترابط (not thread-safe). تفسير: نظرًا لعدم ضمان أمان مؤشرات الترابط، يُرجّح أن يكون سياق الاستدعاء مسؤولًا عن إجراء مزامنة خارجية، إذا كانت عدة مؤشرات ترابط تستخدم المقبض نفسه.
