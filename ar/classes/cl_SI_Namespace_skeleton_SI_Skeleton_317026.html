الغرض من الاستخدام

<SI-Namespace>::skeleton::<SI>Skeleton هي فئة Skeleton الأساسية التي تولدها Generierungs-Toolchain من نموذج Service Interface في ARXML Manifest. يُشتق SI Namespace الهرمي واسم الفئة من Manifest؛ ويتبع Header المُولَّد مسار <SiShortname>_skeleton.h المستمد من النموذج [SWS_CM_00002]. يشتق تنفيذ خدمة خاص من هذه الفئة ويعيد تعريف Service Methods الافتراضية الخالصة أو Fire-and-Forget Methods ‏[SWS_CM_00191] [SWS_CM_90434].

جيل وأمبير. دمار

يمكن للتطبيق المشتق إنشاء الهيكل العظمي باستخدام ara::core::InstanceSpecifier أو InstanceIdentifier واحد أو حاوية معرف؛ بشكل افتراضي، وضع المعالجة هو kEvent [SWS_CM_00152] [SWS_CM_00130] [SWS_CM_00153]. يسمح المدمر الافتراضي بالتدمير عبر الفئة الأساسية [SWS_CM_11370].

دورة حياة ملكية &

النسخ معطل [SWS_CM_00134] [SWS_CM_11548]. يتوفر إنشاء Move وإسناد Move؛ والإنشاء غير آمن من الاستثناءات، أما الإسناد فآمن منها [SWS_CM_00135] [SWS_CM_11549].

التفاعل مع الفئات الأخرى

  • بعد الإنشاء، تعرض OfferService() الخدمة؛ وتنهي StopOfferService() العرض [SWS_CM_00101] [SWS_CM_00111].
  • لكل نموذج Event يوجد عضو events::<Event>; يرسل التنفيذ قيمًا أعلى من skeleton::events::<Event>::Send [SWS_CM_99557] [SWS_CM_00162].
  • يوجد لكل حقل عضو fields::<Field>؛ يتم تحديث قيم الحقول عبر skeleton::fields::<Field>::Update [SWS_CM_99558] [SWS_CM_00119].
  • تتحكم الأوضاع kEvent وkEventSingleThread وkPoll في معالجة استدعاءات الطريقة الواردة [SWS_CM_00301]. عند kPoll، ينفذ ProcessNextMethodCall() الاستدعاء التالي المنتظر في سياق هذه الدالة [SWS_CM_00199].

القيود & معالجة الأخطاء

قد تفشل OfferService() بسبب قيم Field غير مهيأة أو غياب Field Set Handler أو خطأ اتصال [SWS_CM_00101]. يمكن إعادة تعريف E2E Error Handler، لكنه غير قابل لإعادة الدخول؛ وعند أخطاء CRC لا تكون DataID المُمرَّرة موثوقة [SWS_CM_10470]. يمكن تسجيل معالجات أخطاء النقل لجميع الطرق وإزالتها مجددًا [SWS_CM_00093] [SWS_CM_00094] [SWS_CM_00095].

التضمين المعماري

إن Skeleton هو Adapter المُولّد على جانب Provider: يشتق تنفيذ الخدمة منه عادةً، وبذلك يوفر Methods وEvents وFields الخاصة به عبر Communication Management. تُولَّد الواجهة من وصف Service Interface؛ وتسمح النمذجة الأساسية بـ Events وFields وMethods وTriggers في Service Interface واحد. EXP ARAComAPI §4.1 «Proxy/Skeleton Architecture» TPS Manifest §4.2 «Service Interface»

العرض وطريقة المعالجة

قبل OfferService()، لا يكون المثيل مرئيًا لـ Consumer. بعد الاستدعاء، يجوز تسليم Methods بالفعل حتى إذا لم يعد الاستدعاء بعد؛ وبعد StopOfferService() لا تُسلَّم Calls أخرى. ينطبق Processing Mode المختار عند الإنشاء طوال عمر مثيل Skeleton. EXP ARAComAPI §5.4.4 «Offering Service instance» §5.4.5 «Polling and event-driven processing modes»

مخطط النشاط: يصبح مثيل الخدمة مرئيًا فقط بعد OfferService(); يحدد الوضع المحدد في المنشئ المعالجة. المصدر: EXP ARAComAPI §5.4.4 «Offering Service instance» و §5.4.5 «Polling and event-driven processing modes».

دالة E2EErrorHandler [SWS_CM_10470] Upstream: RS_CM_00401, RS_CM_00402

virtual void E2EErrorHandler (ara::com::e2e::ComE2EErrc errorCode, ara::com::e2e::DataID dataID, ara::com::e2e::MessageCounter message Counter);

Implementation may be overridden by the actual ServiceSkeleton implementation and it is not required to be reentrant. If the E2E error is a CRC error then some parts of the received message are faulty. If this part is the DataID then the E2E error handler is called with a faulty DataID. Consequently, in case of CRC error the server application can not rely on the DataID received by its error handler.
