وصف مولد تلقائياً، مشتق من حيث المحتوى من وثائق AUTOSAR R25-11 المشار إليها (مواصفة SWS والوثائق المعيارية المصاحبة) — وليس نصاً رسمياً لـ AUTOSAR. العبارات المعلّمة بأنها تفسير هي استنتاجات من المصادر.

الغرض من الاستخدام

ينفذ SovdAuthorization تفويض SOVD على مستوى التطبيق. يعيد GetAuthorizationUrl() وGetTokenUrl() عنوان URL لطلب التفويض أو Token، على التوالي؛ ويستجيب DM لذلك برمز HTTP 307 وLocation Header يتضمن عنوان URL هذا. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] يتحقق ValidateAuthorization() من Token في HTTP Authorization Header، ويضع علامة على الأدوار المفوضة في ClientAuthentication المُمرر. [SWS_DM_01483] [SWS_DM_01470]

جيل وأمبير. دورة الحياة

يربط المنشئ PortPrototype بـ DiagnosticSovdAuthorizationInterface ويقبل ConcurrencyType. [SWS_DM_01489] Offer() يقوم بتفعيل إعادة التوجيه، StopOffer() يعطلها مرة أخرى. يمكن توصيل العرض kAlreadyOffered أو kConfigurationMismatch. [SWS_DM_01487] [SWS_DM_01486] المدمر آمن بشكل استثنائي. [SWS_DM_01488]

القيود & معالجة الأخطاء

بعد توفير Future، لا يجوز للتطبيق استخدام كائن ClientAuthentication المشار إليه بعد الآن. [SWS_DM_01483] تسمح قيمة إرجاع ناجحة لـ DM بمعاملة الأدوار حتى validUntil لـ Token نفسه بوصفها مُصادَقًا عليها. [SWS_DM_01469] قد تبلغ عملية التحقق عن kInvalidAccessToken أو kTemporarilyNotAvailable. [SWS_DM_01483] تعتمد عمليات URL والتحقق على ConcurrencyType؛ ولا يكون Offer وStopOffer آمنين للخيوط. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01483] [SWS_DM_01487] [SWS_DM_01486]

يعيد DM التحقق من التفويض إذا لم يكن Token مطابقًا لـ Token تم التحقق منه سابقًا وما زال صالحًا. [SWS_DM_01470] ومع Token نفسه حتى validUntil وبالهوية المعادة نفسها، يمكنه معاملة العميل بوصفه متطابقًا. [SWS_DM_01781] [SWS_DM_01782] تتلقى طرق URL معلمات Query وMetaInfo الخاصة بالطلب، وتعيد كل منها String بشكل غير متزامن. [SWS_DM_01484] [SWS_DM_01485]

سياق وصول SOVD

يستخدم تفويض SOVD رموز OAuth في Request Header. عند مثل هذا Request، يستخدم Diagnostic Manager ‏SovdAuthorization لطلب دور التفويض المشفر من التطبيق؛ وبناءً على هذا الدور يقرر الإذن لعملية SOVD المطلوبة. EXP SOVD §3.2.1 «Access Permissions»

مخطط تسلسلي: تفويض SOVD باستخدام OAuth Token واستعلام الأدوار الموصوفين في الوثيقة. المصدر: EXP SOVD §3.2.1 «Access Permissions». تفسير: تلخص الرسالة الأخيرة قرار الإذن الموصوف في النص بوصفه سماحًا/رفضًا.

دالة ValidateAuthorization [SWS_DM_01483] Upstream: RS_Diag_04268

virtual ara::core::Future< ValidateAuthorizationOutput > Validate Authorization (ara::core::StringView token, const MetaInfo &metaInfo, ClientAuthentication &clientAuthentication) noexcept=0;

This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.
