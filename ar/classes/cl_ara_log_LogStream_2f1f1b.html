فئة ara::log::LogStream

[SWS_LOG_00173] Upstream: RS_LT_00003, RS_LT_00046

class LogStream final {...};

Represents a Log message, allowing stream operators to be used for appending data. Note: Normally Application processes would not use this class directly. Instead one of the log methods provided in the main Logging API shall be used. Those methods automatically setup a temporary object of this class with the given log severity level. The only reason to use this class directly is, if the user wants to hold a ara::log::LogStream object longer than the default one-statement scope. This is useful in order to create log messages that are distributed over multiple code lines. See the ara::log::LogStream::Flush method for further information. Once this temporary object gets out of scope, its destructor takes care that the message buffer is ready to be processed by the Logging framework. Besides the existing supported operator<< overloads for ara::log::LogStream it can be easily extended for other derived types by providing a stream operator that makes use of already supported types.

Example: struct MyCustomType { int8_t foo; ara::core::String bar; };

LogStream& operator<<(LogStream& out, const MyCustomType& value) { return (out << value.foo << value.bar); }

// Producing the output "42 the answer is." Logger& ctx0 = CreateLogger("CTX0", "Context Description CTX0"); ctx0.LogDebug () << MyCustomType{42, " the answer is."};

يمثل الصنف ara::log::LogStream رسالة تسجيل قابلة للتنسيق، وتُملأ ذاكرتها المؤقتة الداخلية تدريجيًا بالبيانات والبيانات الوصفية عبر معاملات التدفق. يتم عادةً الحصول على الحالات مؤقتًا عبر دوال التسجيل، وتُعيد توجيه المحتوى المجمّع تلقائيًا عند مغادرة نطاق الصلاحية عبر مدمر الكائن إلى إطار عمل التسجيل [SWS_LOG_00262]. بالنسبة للرسائل متعددة الأسطر أو المعاد استخدامها، يمكن تشغيل إعادة التوجيه صراحةً عبر Flush() [SWS_LOG_00039]. وكشرط أساسي حاسم، فإن الصنف ليس آمنًا بالنسبة للخيوط ويمنع عمليات النسخ تمامًا.

السياق

يمثل الصنف ara::log::LogStream رسالة تسجيل قابلة للتنسيق في نظام التسجيل الفرعي لـ Adaptive. ويوفر واجهة تخزين مؤقت قائمة على الرسائل، والتي تتيح الإلحاق التدريجي للحمولات غير المتجانسة بذاكرة مؤقتة داخلية عبر معاملات التدفق المحملة بشكل زائد.

في حالة الاستخدام العادية، لا تتفاعل عمليات التطبيق مباشرةً مع LogStream عبر إنشاء نسخ صريحة. بدلاً من ذلك، توفر API التسجيل الرئيسية (على سبيل المثال عبر دوال التسجيل مثل LogDebug()) حالات مؤقتة من هذا الصنف، والتي تكون مهيأة بالفعل بمستوى الخطورة المطلوب. السبب الوحيد المخصص للاحتفاظ بكائن LogStream إلى ما بعد نطاق العبارة الواحدة القياسي (One-Statement-Scope) يتمثل في تجميع رسائل السجل عبر عدة أسطر برمجية. وبمجرد أن يغادر الكائن نطاق صلاحيته أو يُفرغ صراحةً، يتم تسليم محتوى الذاكرة المؤقتة إلى إطار عمل التسجيل لمزيد من المعالجة.

دورة الحياة

يتم إنشاء حالات LogStream أساسًا ككائن مؤقت عبر دوال المصنع الخاصة بـ API التسجيل الرئيسية. ولتوفير فعال، يعلن الصنف عن منشئ نقل كـ noexcept [SWS_LOG_00176]. عادةً ما يُعلن عن منشئ النقل هذا فقط دون تعريفه، مما يسمح للمترجمات المتوافقة مع C++14 باستخدام تحسين القيمة المرجعة (RVO) عند الإرجاع من دوال المصنع [SWS_LOG_00176]. يُستبعد تمامًا تكرار الحالات أو تعيين النقل: منشئ النسخ [SWS_LOG_00174]، ومعامل تعيين النسخ [SWS_LOG_00175]، ومعامل تعيين النقل [SWS_LOG_00177] محذوفة (=delete).

تتم إدارة نهاية دورة الحياة بواسطة مدمر الكائن ~LogStream() [SWS_LOG_00262]. إذا غادر الكائن نطاق صلاحيته (على سبيل المثال في نهاية كتلة دالة أو عبارة برمجية)، يضمن مدمر الكائن داخليًا إعادة توجيه محتوى الذاكرة المؤقتة إلى إطار عمل التسجيل للمعالجة [SWS_LOG_00039]، [SWS_LOG_00262].

إذا تمت إعادة استخدام حالة LogStream في نفس نطاق الصلاحية لعدة رسائل متتالية، يجب استدعاء الدالة العضو Flush() [SWS_LOG_00039]. المهم هنا هو أن Flush() لا يفرغ الذاكرة المؤقتة، بل يرسل البيانات الحالية إلى إطار عمل التسجيل ويبدأ على الفور تدفق رسائل جديد [SWS_LOG_00039].

فيما يتعلق بالتزامن، تم تحديد جميع الدوال الأعضاء على أنها غير آمنة بالنسبة للخيوط ([SWS_LOG_00039]، [SWS_LOG_00040]، [SWS_LOG_00129]). لذلك، لا يجوز استخدام نموذج LogStream بالتوازي بواسطة عدة خيوط دون مزامنة خارجية.

مسار الاستخدام

يتضمن سير عمل التسجيل النموذجي المراحل التالية:

  1. توفير التدفق: تستدعي عملية التطبيق دالة تسجيل تنشئ حالة LogStream مؤقتة وتُرجعها عبر RVO [SWS_LOG_00176].
  2. إثراء البيانات الوصفية: قبل إدخال البيانات أو أثناءه، يمكن إلحاق سمات اختيارية عبر تسلسل الدوال، بما في ذلك مواقع التعليمات البرمجية المصدرية عبر WithLocation(file, line) [SWS_LOG_00129]، أو الوسوم عبر WithTag(tag) [SWS_LOG_00132]، أو مستويات السرية عبر WithPrivacy(value) [SWS_LOG_00258]. وتُرجع كل من هذه الدوال مرجعًا إلى *this.
  3. ملء البيانات: تُكتب بيانات الحمولة في الذاكرة المؤقتة الداخلية عبر المعاملات المحملة بشكل زائد operator<<. تدعم الواجهة الأنواع القياسية مثل القيم المنطقية [SWS_LOG_00040]، والأعداد الصحيحة بمختلف السعات [SWS_LOG_00041]، [SWS_LOG_00044]، والأعداد ذات الفاصلة العائمة [SWS_LOG_00049]، والسلاسل النصية ومعاينات السلاسل النصية [SWS_LOG_00051]، [SWS_LOG_00062]، وتسلسلات البايتات عبر core::Span<const core::Byte> [SWS_LOG_00128]، بالإضافة إلى المعاملات المهيكلة عبر Argument<T> [SWS_LOG_00203]. علاوة على ذلك، يمكن توسيع المعامل للأنواع المعرفة من قبل المستخدم.
  4. التسليم إلى إطار العمل: عند مغادرة نطاق الصلاحية، يعيد مدمر الكائن توجيه الرسالة [SWS_LOG_00262]. إذا كان يجب استمرار وجود الحالة لرسائل إضافية، يتم استدعاء Flush() صراحةً [SWS_LOG_00039].

مخطط تسلسل: سير عملية التسجيل من إنشاء التدفق، ومرورًا بملء البيانات الوصفية والبيانات، وحتى الإرسال عبر نهاية النطاق أو ()Flush. المصادر: [SWS_LOG_00039]، [SWS_LOG_00040]، [SWS_LOG_00129]، [SWS_LOG_00176]، [SWS_LOG_00262]

سيناريوهات الأخطاء

يتبع الصنف تصميمًا صارمًا خاليًا من الاستثناءات. جميع الدوال الأعضاء، بما في ذلك معاملات التدفق ([SWS_LOG_00040] إلى [SWS_LOG_00051]، [SWS_LOG_00062]، [SWS_LOG_00128]، [SWS_LOG_00203])، وWithLocation() [SWS_LOG_00129]، وWithTag() [SWS_LOG_00132]، وWithPrivacy() [SWS_LOG_00258]، وFlush() [SWS_LOG_00039]، ومدمر الكائن [SWS_LOG_00262]، مُعلنة كـ noexcept وآمنة من حيث الاستثناءات ("exception safe").

تقتصر حالات الخطأ ومخاطر الاستخدام على السيناريوهات التالية:

  • خطأ في النوع مع WithPrivacy: يتطلب القالب WithPrivacy<T> إلزاميًا أن يكون T نوعًا صحيحًا أو نوع تعداد. إذا تم إنشاء الدالة بنوع مغاير، يكون البرنامج غير صحيح الصياغة (ill-formed) ويؤدي إلى خطأ ترجمة [SWS_LOG_00258]. بالإضافة إلى ذلك، يتم استخدام البايتات الثمانية الأقل أهمية فقط من القيمة الممررة، وتُتجاهل البايتات الأعلى أهمية [SWS_LOG_00258].
  • غياب الأمان بالنسبة للخيوط: نظرًا لأن LogStream معرّف بأنه غير آمن بالنسبة للخيوط ([SWS_LOG_00039]، [SWS_LOG_00040])، فإن عمليات القراءة أو الكتابة المتزامنة على نفس الحالة دون مزامنة خارجية تؤدي على الأرجح إلى عدم اتساق البيانات أو تلف الذاكرة المؤقتة (تفسير).
  • الاستحواذ على الذاكرة المؤقتة عند Flush: نظرًا لأن Flush() لا يفرغ الذاكرة المؤقتة ماديًا، بل يسلم فقط المحتوى الحالي إلى إطار عمل التسجيل [SWS_LOG_00039]، يجب مراعاة أنه عند إعادة الاستخدام، يتم دلاليًا بدء رسالة جديدة.
