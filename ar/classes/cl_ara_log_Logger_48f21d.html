فئة ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

يُغلف سياق تسجيل (Logging) للالتقاط الآمن خيطياً لرسائل السجل المنسقة أو المنمذجة.

تمثّل الفئة ara::log::Logger سياقاً لالتقاط رسائل السجل (Log) داخل عملية تطبيق عبر تدفقات مؤقتة أو تنسيقات رسائل منمذجة [SWS_LOG_00064]. ونظراً لأن المُنشئ الافتراضي محذوف، فإن إنشاء النسخة وإدارة دورة الحياة تتم بالكامل من قِبل إطار عمل التسجيل (Logging Framework) [SWS_LOG_00259]. وقبل الإعداد المستغرق للوقت لبيانات الرسائل، يمكن الاستعلام عن مستوى الإبلاغ النشط حالياً. وقد تم تحديد كافة واجهات الفئة على أنها آمنة خيطياً، وتسمح بالاستدعاء دون الحاجة إلى مزامنة من عدة خيوط معالجة.

السياق

تمثّل الفئة ara::log::Logger سياق مسجل (Logger) داخل عملية تطبيق أو نطاق عملية في الوحدة log. ويُغلف هذا السياق مُعرّف سياق ID محدداً، ووصفاً مرتبطاً به، بالإضافة إلى مستوى افتراضي للتسجيل. ويتفاعل مطورو التطبيقات مع نسخ المسجل لتسليم رسائل السجل إلى إطار عمل التسجيل إما عبر كائنات تدفق مثل LogStream [SWS_LOG_00064] أو كرسائل مهيكلة ومنمذجة [SWS_LOG_00204]. وتعمل النسخ كوسيط بين خيوط المعالجة الداخلية للتطبيق والواجهة الخلفية للتسجيل.

مخطط السياق: دمج المسجل بين التطبيق وإطار عمل التسجيل وLogStream. المصادر: [SWS_LOG_00064]، [SWS_LOG_00259].

دورة الحياة

تخضع إدارة النسخ لملكية صارمة من قِبل إطار عمل التسجيل. ولضمان التسجيل التلقائي في الواجهة الخلفية للتسجيل عند الإنشاء، وإلغاء التسجيل عند إيقاف تشغيل عملية التطبيق، تم حذف المُنشئ الافتراضي [SWS_LOG_00259]. ولا يُسمح للتطبيقات ولا يمكنها إنشاء كائنات Logger مباشرة، بل يجب عليها بدلاً من ذلك استخدام دوال الإنشاء ara::log::CreateLogger. ويتم التدمير والتحرير عبر المُدمّر [SWS_LOG_00260]، الذي يتحكم فيه إطار عمل التسجيل، بحيث لا يتعين على المستخدمين الاهتمام بدورة الحياة.

فيما يتعلق بالتزامن، تم تحديد كافة طرق الوصول لتكون آمنة خيطياً (thread-safe)، من بينها [SWS_LOG_00070] و[SWS_LOG_00255] و[SWS_LOG_00260]. وبفضل ذلك، يمكن لعدة خيوط معالجة متزامنة استخدام سياق المسجل نفسه في الوقت ذاته، دون الحاجة إلى آليات مزامنة إضافية من جانب التطبيق.

مسار الاستخدام

يشمل الاستخدام النموذجي للمسجل فحص التكوين الحالي، وتعديل قيم العتبة، وإرسال الرسائل:

  • فحص صلاحية الإخراج: قبل التحضيرات المستهلكة للموارد لبيانات السجل، يمكن الاستعلام باستخدام IsEnabled عما إذا كان مستوى السجل المطلوب يتم الإبلاغ عنه بنشاط [SWS_LOG_00070].
  • التكوين: يمكن إعادة تكوين الحد الأدنى لعتبة الإبلاغ لنسخة المسجل أثناء وقت التشغيل عبر SetThreshold [SWS_LOG_00255].
  • التسجيل المستند إلى الدفق: عبر دوال محددة لدرجات خطورة منفردة – LogFatal [SWS_LOG_00064]، LogError [SWS_LOG_00065]، LogWarn [SWS_LOG_00066]، LogInfo [SWS_LOG_00067]، LogDebug [SWS_LOG_00068] أو LogVerbose [SWS_LOG_00069] – وكذلك عبر الدالة الديناميكية WithLevel [SWS_LOG_00131]، يُنشأ كائن LogStream. يستقبل هذا الكائن البيانات عبر المعامل <<. وعادةً ما ينتهي العمر الافتراضي لكائن الدفق مع الفاصلة المنقوطة للتعليمة [SWS_LOG_00064].
  • الرسائل المنمذجة: كبديل، يمكن تمرير الرسائل المحددة النوع والمنمذجة مباشرةً باستخدام Log [SWS_LOG_00204] أو مع تحديد السمات باستخدام LogWith [SWS_LOG_00133].

مخطط تسلسلي: التسلسل النموذجي لفحص العتبة والتسجيل المستند إلى الدفق. المصادر: [SWS_LOG_00070]، [SWS_LOG_00067]، [SWS_LOG_00064].

سيناريوهات الأخطاء

تم تحديد واجهات الفئة إلى حد كبير على أنها noexcept وآمنة من الاستثناءات (exception safe)، مما يقلل من انقطاعات وقت التشغيل غير المتوقعة [SWS_LOG_00070]، [SWS_LOG_00255]. ومع ذلك، توجد شروط خطأ رسمية وحالات حافية:

  • معاملات نموذج غير صحيحة: إذا تم استدعاء Log بوسائط لا تتطابق مع مواصفات الرسالة المنمذجة، فإن برنامج ++C يكون مبنيًا بشكل غير صحيح (ill-formed) ويفشل في وقت الترجمة [SWS_LOG_00204].
  • خصائص سمة مفقودة: إذا احتوت المجموعة لـ LogWith على أنواع لا تتوافق مع معايير السمة المطلوبة، فلن تشارك الدالة في حل فرط التحميل [SWS_LOG_00133]. يُفترض على الأرجح أن الاستبعاد يتم عبر SFINAE أو المفاهيم.
  • أمان الاستثناءات أثناء التفكيك: تم الإعلان عن مُدمِّر الفئة ~Logger بأنه not exception safe [SWS_LOG_00260]. ويُرجَّح أن يرجع ذلك إلى احتمال حدوث أخطاء أثناء إلغاء التسجيل في الواجهة الخلفية للتسجيل، والتي لا يجوز نشرها عبر استثناءات.

يستند هذا الدليل حصريًا إلى مواصفات AUTOSAR للوحدة log في Adaptive Release R25-11.
