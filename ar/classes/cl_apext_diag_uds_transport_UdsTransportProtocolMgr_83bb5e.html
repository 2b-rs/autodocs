فئة apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

قائمة مراجع SWS Diagnostics: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

الغرض من الاستخدام

UdsTransportProtocolMgr يدير التفاعل بين مثيلات خادم التشخيص وبروتوكولات النقل UDS، مثل DoIP أو CAN. وهو يوفر النقل Handler مع واجهة موحدة لقبول الرسائل وتسليمها إلى طبقة الجلسة وإرسال التأكيدات واستعادة القناة. [SWS_DM_00306]

قبول الرسالة ملكية &

يقوم المعالج بالإبلاغ عن بداية الرسالة المستلمة باستخدام IndicateMessage() بما في ذلك عناوين المصدر والوجهة ونوع العنوان وChannel-ID العام والحجم وPayload-Ausschnitt الصالح فقط أثناء المكالمة. إذا كان بإمكان DM معالجة الطلب، فإنه يقوم بإرجاع kIndicationOk وذاكرة مملوكة لـ UdsMessagePtr. في حالة الإشغال أو نقص الموارد أو عنوان الهدف غير معروف، يتم تزويد kIndicationOccupied أو kIndicationOverflow أو kIndicationUnknownTargetAddress بمؤشرات فارغة. [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

بعد ملء كائن الرسالة الذي تم إرجاعه، يقوم المعالج بتمريره إلى Session-Schicht عبر HandleMessage()؛ وبذلك، تعود الملكية إلى جوهر DM العام. إذا لم يقم IndicateMessage() بتسليم kIndicationOk، فقد لا يتم استدعاء HandleMessage(). إذا حدث فشل سابق لأوانه في النقل، فسيتم إرجاع الكائن بـ NotifyMessageFailure(). [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

دورة الحياة & الانتقال

تبلغ TransmitConfirmation() عن kTransmitOk أو kTransmitFailed لنقل طلبه DM عبر UdsTransportProtocolHandler::Transmit(). وتؤكد PeriodicTransmitConfirmation() قائمة مرتبة من الرسائل المرسلة دوريًا، إلى جانب عدد العناصر التي أُرسلت بنجاح. [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

لا يجوز لـ DM معالجة استعادة القناة إلا بعد بدء المعالج المرتبط. بعد توقفه، لا يُسمح باستدعاء مدير آخر باستثناء HandlerStopped()؛ ينتظر DM رد الاتصال هذا قبل إنهاء العملية. [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

دالة HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

قائمة مراجع SWS Diagnostics: [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
