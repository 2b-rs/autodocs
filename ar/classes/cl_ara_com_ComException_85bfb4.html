السياق

تشكّل الفئة ara::com::ComException التمثيل المركزي للاستثناء داخل وحدة Communication Management (com) التابعة لـ AUTOSAR Adaptive Platform ([SWS_CM_11327]، AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»). وتتمثل مسؤوليتها الأساسية في تغليف حالات الخطأ التي تطرأ في API الاتصال والإشارة إليها كاستثناء C++ قياسي (AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»).

في التسلسل الهرمي للفئات، تم تعريف ara::com::ComException كفئة نهائية ترث بشكل عام من ara::core::Exception (class ComException final : public ara::core::Exception). وبذلك تتكامل مع البنية الموحدة للأخطاء الخاصة بـ ara::core. وتشمل أطراف التفاعل الرئيسية ما يلي:

  • طبقة الاتصال (ara::com): ينشئ تنفيذ الـ API عند حالات الإخفاق المتزامنة مثيلاً من ComException من رمز خطأ ويطرحه (AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»).
  • التطبيق: يستدعي التطبيق الوظيفي دوال إدارة الاتصال ويلتقط ComException عند تفعيل استثناءات C++ لتوجيه إجراءات معالجة الأخطاء.
  • نطاق الخطأ (ara::core::ErrorCode): يُضمّن كل كائن استثناء رمز خطأ بشكل إلزامي ([SWS_CM_11328]، AUTOSAR_AP_SWS_CommunicationManagement §8.12.5.1.1.1 «ComException»)، والذي يحدد السبب الدلالي للخطأ ضمن نطاق الاتصال.
  • سلسلة أدوات المترجم (Compiler-Toolchain): يعتمد وجود وتوقيع دوال API التي تطرح استثناءات مباشرةً على إعدادات C++-Toolchain فيما يتعلق باستثناءات اللغة ([SWS_CORE_10304]، AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»).

دورة الحياة

يتم إنشاء ara::com::ComException لكل حالة عند حدوث خطأ. وتوفر الفئة منشئاً صريحاً ([SWS_CM_11328]، AUTOSAR_AP_SWS_CommunicationManagement §8.12.5.1.1.1 «ComException»):

explicit ComException (ara::core::ErrorCode errorCode) noexcept;

يقبل هذا المنشئ ara::core::ErrorCode المتسبب ويهيئ معلومات الخطأ الداخلية ([SWS_CM_11328]). وفيما يتعلق بأمان الاستثناءات، تم التصريح عن المنشئ كـ noexcept ويُعد آمناً تماماً من الاستثناءات (”exception safe“) ([SWS_CM_11328]). ويضمن ذلك عدم إمكانية إطلاق أي استثناءات أخرى أثناء إنشاء الاستثناء نفسه.

فيما يتعلق بالملكية وفترة البقاء، يتم تخصيص الكائن بواسطة دالة الـ API التي تطرح الاستثناء على الـ Stack أو في ذاكرة الـ Exception ويُنقل بالقيمة عبر آلية اللغة (throw) (AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»). وتمتد فترة البقاء عبر عملية الـ Stack-Unwinding حتى مغادرة كتلة catch المقابلة في الطبقة المعالِجة، وعندئذٍ يتم تدمير المثيل تلقائيًا. والوراثة الإضافية مستبعدة بواسطة سمة الفئة final. يتم توفير التصريح عبر ملف الرأس #include "ara/com/com_error_domain.h" ([SWS_CM_11328]).

مسار الاستخدام

ينقسم المسار المعتاد عند حدوث خطأ في إدارة الاتصال إلى تسلسل ثابت من الخطوات:

  1. استدعاء الدالة: يستدعي التطبيق دالة متزامنة لواجهة ara::com.
  2. اكتشاف الخطأ: يكتشف تنفيذ ara::com حالة خطأ ويحدد ara::core::ErrorCode المقابل.
  3. إنشاء المثيل: تنشئ الـ API مثيلاً من ara::com::ComException مع تمرير رمز الخطأ إلى المُنشئ ([SWS_CM_11328]).
  4. طرح الاستثناء: تطرح الـ API كائن الاستثناء الذي تم إنشاؤه (AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»).
  5. الالتقاط: يلتقط التطبيق الاستثناء في كتلة try-catch. ويحدث هذا على الأرجح وفقاً لممارسات AUTOSAR الشائعة كمرجع لـ const ara::com::ComException& أو بشكل متعدد الأشكال عبر const ara::core::Exception&.
  6. التقييم: يصل التطبيق إلى معلومات الخطأ الخاصة برمز الخطأ المغلف ويبدأ إجراءات معالجة الخطأ.

مخطط تسلسلي: التسلسل عند حدوث خطأ وإطلاق ComException بواسطة الـ API. المصادر: [SWS_CM_11327]، [SWS_CM_11328]، AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException».

سيناريوهات الأخطاء

يرتبط سلوك ara::com::ComException ارتباطاً وثيقاً بتهيئة البيئة المستهدفة ودلالات الأخطاء:

  • استثناءات C++ المعطلة: إذا تم تعطيل استثناءات C++ في سلسلة أدوات المترجم، فإن الدالة المسؤولة عن إنشاء ComException وإطلاقه من errorCode لا تشارك في حل التحميل الزائد وفقاً لـ [SWS_CORE_10304] (AUTOSAR_AP_SWS_CommunicationManagement §8.12.5 «Class: ComException»). وبالتالي، لا يمكن إطلاق نسخ من ComException في مثل هذه البيئات؛ وتتم معالجة الأخطاء هناك بدلاً من ذلك عبر قنوات أخطاء قائمة على القيم (مثل ara::core::Result).
  • اشتراط وجود رمز خطأ: لا يمكن إنشاء كائن من النوع ComException دون رمز خطأ صريح ([SWS_CM_11328]). ولا يوجد منشئ افتراضي بدون معلمات، مما يضمن أن كل حالة استثنائية ترتبط دائماً بسبب محدد.
  • الموثوقية ضد فشل الإنشاء: نظراً لأن المنشئ مُعلن كـ noexcept ([SWS_CM_11328])، يتم منع فشل إنشاء الاستثناء نفسه. وبالتالي، يُستبعد حدوث توالي الاستثناءات أثناء إنشاء الخطأ.
