السياق

تمثل الواجهة ara::crypto::cryp::SymmetricCipherCtx التجريد المركزي لعمليات التشفير وفك التشفير المتناظرة ضمن الوحدة crypto في AUTOSAR Adaptive Platform. وهي تتيح التحويل الآمن للنصوص الصريحة والمشفرة باستخدام مواد المفاتيح المتناظرة. وتتم إدارة دورة حياة مثيلات هذا السياق والتعامل معها عادةً عبر الاسم المستعار لنوع المؤشر الذكي SymmetricCipherCtx::Sptr [SWS_CRYPT_50137].

في بنية التطبيق، يتفاعل SymmetricCipherCtx مباشرة مع المتصل وكذلك مع كائنات المفاتيح التشفيرية. ويتم توفير مادة المفتاح إما مباشرة ككائن مفتاح في الذاكرة SymmetricKey::Sptr أو إدراجها بشكل غير مباشر عبر فتحة مفتاح مدارة KeySlot::Sptr. وبحسب الخوارزمية ووضع التشغيل، يعالج السياق متجهات التهيئة (IV) أو الـ Nonces، التي يتم إما تمريرها من قِبل التطبيق أو إنشاؤها بواسطة السياق نفسه.

دورة الحياة

يمر مثيل SymmetricCipherCtx بحالات محددة بوضوح، والتي تتحدد من خلال توفير المفاتيح ووضع المعالجة:

  • غير مهيأ (Uninitialized): بعد الإنشاء المحض، لا يمتلك السياق أي مادة مفتاح مقترنة. ويتم رفض استدعاءات معالجة البيانات في هذه الحالة مع الخطأ CryptoErrc::kUninitializedContext. ويتم الانتقال إلى الحالة الجاهزة للتشغيل عبر SetKey()، حيث يتم تهيئة KeySlot [SWS_CRYPT_50043] أو SymmetricKey [SWS_CRYPT_50138] اختيارياً.
  • مهيأ / المفتاح مُعدّ (Ready): يكون السياق مهيأً بمفتاح. ومن هذه الحالة، يمكن إما تنفيذ استدعاءات فردية عديمة الحالة (معالجة Single-Call) أو بدء جلسة تدفق متعددة المراحل.
  • التدفق نشط (Processing): من خلال استدعاء Start() — إما مع متجه تهيئة صريح [SWS_CRYPT_23625] أو بدونه أو مع IV خاص بالسياق [SWS_CRYPT_50044] — تبدأ معالجة التدفق. وفي هذه الحالة، يمكن تحويل البيانات باستمرار عبر Update() [SWS_CRYPT_50139]. بالإضافة إلى ذلك، يتيح Seek() [SWS_CRYPT_23613] إعادة التموضع في تدفق البيانات في أوضاع التشغيل المدعومة.
  • الإتمام أو الإلغاء: يتم إما إتمام معاملة التدفق الجارية بصورة اعتيادية عبر Finish() [SWS_CRYPT_50045] أو FinishEncrypt() [SWS_CRYPT_23618]، أو يتم التخلص منها عبر Cancel() [SWS_CRYPT_50046]. وبعد الانتهاء بنجاح أو بعد الإلغاء، يعود السياق إلى الحالة الأساسية المهيأة.

تم تحديد جميع دوال الواجهة كمواصفة بأنها آمنة من الاستثناءات (exception safe) وآمنة بالنسبة للخيوط (thread-safe).

مخطط الحالة: دورة الحياة وحالات المعالجة لـ SymmetricCipherCtx. المصادر: [SWS_CRYPT_50043]، [SWS_CRYPT_50138]، [SWS_CRYPT_23625]، [SWS_CRYPT_50044]، [SWS_CRYPT_50139]، [SWS_CRYPT_50045]، [SWS_CRYPT_23618]، [SWS_CRYPT_50046]، [SWS_CRYPT_50047]

مسار الاستخدام

تدعم المواصفة مسارَي تنفيذ أساسيَّين لمهام التشفير وفك التشفير: الاستدعاء الفردي عديم الحالة ومعالجة الكتل المتدفقة.

في معالجة الاستدعاء الفردي (Single-Call) يتم تحويل جميع البيانات في عملية واحدة. وتتوفر لهذا الغرض ثلاث دوال اعتماداً على التعامل مع متجه التهيئة (IV):

  • ProcessSingleCall() [SWS_CRYPT_50047] للخوارزميات التي لا تتوقع متجه تهيئة (IV) ولا تُرجعه.
  • ProcessSingleCallWithInputIv() [SWS_CRYPT_50048]، عندما يحدد المتصل متجه التهيئة بشكل صريح.
  • EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049]، عندما يتم التشفير ويُرجع السياق متجه التهيئة (IV) المُنشأ إلى المتصل.

في معالجة التدفق يتم التحويل تدريجياً عبر كتل تخزين مؤقت متعددة. وقبل البدء، يمكن تحديد حدود المخزن المؤقت: يحدد GetMinimumChunkSize() [SWS_CRYPT_50144] وGetMaximumChunkSize() [SWS_CRYPT_50050] أحجام الكتل الدنيا والقصوى. ويمكن الاستعلام عن أطوال IV المسموح بها باستخدام GetMinimumInputIvSize() [SWS_CRYPT_50141]، وGetMaximumInputIvSize() [SWS_CRYPT_50142]، بالإضافة إلى GetOutputIvSize() [SWS_CRYPT_50143]. ويتم حساب حجم المخزن المؤقت الهدف المطلوب حسب الحالة عبر GetRequiredOutputBufferSize() [SWS_CRYPT_50140].

ينقسم التسلسل النموذجي إلى:

  1. تهيئة المفتاح بواسطة SetKey() [SWS_CRYPT_50138].
  2. بدء جلسة التدفق بواسطة Start() مع تحديد الاتجاه (CryptoTransform) وبشكل اختياري متجه التهيئة IV [SWS_CRYPT_23625].
  3. التحويل المتكرر لكتل البيانات عبر Update() [SWS_CRYPT_50139].
  4. الإنهاء النهائي عبر Finish() [SWS_CRYPT_50045] أو FinishEncrypt() [SWS_CRYPT_23618] للحصول على متجه التهيئة IV المُنشأ.

مخطط التتابع: التسلسل النموذجي لتشفير تدفقي تزايدي مع حساب المخزن المؤقت وتوفير متجه التهيئة IV. المصادر: [SWS_CRYPT_50138]، [SWS_CRYPT_50140]، [SWS_CRYPT_23625]، [SWS_CRYPT_50139]، [SWS_CRYPT_50045]

سيناريوهات الأخطاء

تُرجع دوال SymmetricCipherCtx عند فشل العمليات رموز خطأ من التعداد ara::crypto::CryptoErrc مع دلالات التراجع (Rollback):

  • CryptoErrc::kUninitializedContext: يحدث عند Start() [SWS_CRYPT_23625] [SWS_CRYPT_50044]، أو ProcessSingleCall() [SWS_CRYPT_50047]، أو ProcessSingleCallWithInputIv() [SWS_CRYPT_50048]، أو EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049]، أو GetRequiredOutputBufferSize() [SWS_CRYPT_50140]، إذا لم يتم تكوين مفتاح متوافق مسبقاً.
  • CryptoErrc::kProcessingNotStarted: يتم إطلاقه عند استدعاء دوال متعلقة بالتدفق مثل Update() [SWS_CRYPT_50139]، أو Finish() [SWS_CRYPT_50045]، أو FinishEncrypt() [SWS_CRYPT_23618]، أو Seek() [SWS_CRYPT_23613]، أو Cancel() [SWS_CRYPT_50046]، دون بدء عملية تدفق مسبقاً عبر Start().
  • CryptoErrc::kInsufficientCapacity: يشير عند Update()، وFinish()، وFinishEncrypt()، بالإضافة إلى إجراءات Single-Call، إلى أن حجم مخزن المخرجات أو مخزن IV المؤقت الممرر صغير للغاية.
  • CryptoErrc::kInvalidInputSize / CryptoErrc::kInvalidArgument: يشير إلى أحجام غير صالحة للمخزن المؤقت، أو عدم محاذاة الكتل عند Seek()، أو بيانات إدخال غير صالحة.
  • CryptoErrc::kUsageViolation / CryptoErrc::kIncompatibleObject / CryptoErrc::kEmptyKeySlot: يحدث عندما تحظر رايات استخدام المفتاح اتجاه التحويل المطلوب (على سبيل المثال غياب kAllowDataEncryption أو kAllowDataDecryption)، أو عندما يكون نوع المفتاح غير متوافق، أو عندما يكون KeySlot المشار إليه فارغاً.
  • CryptoErrc::kUnsupported: يشير إلى أن التدفق أو عمليات البحث (Seek) أو الاستدعاءات الفردية أو تكوين IV المحدد غير مدعوم بواسطة السياق أو الخوارزمية الفعلية.

يعتمد هذا الدليل حصرياً على متطلبات مواصفات AUTOSAR Adaptive Release R25-11.

<h4>السياق</h4>
<p>تمثل الواجهة <code>ara::crypto::cryp::SymmetricCipherCtx</code> التجريد المركزي لعمليات التشفير وفك التشفير المتناظرة ضمن الوحدة <code>crypto</code> في AUTOSAR Adaptive Platform. وهي تتيح التحويل الآمن للنصوص الصريحة والمشفرة باستخدام مواد المفاتيح المتناظرة. وتتم إدارة دورة حياة مثيلات هذا السياق والتعامل معها عادةً عبر الاسم المستعار لنوع المؤشر الذكي <code>SymmetricCipherCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50137" href="../spec/record.html?id=SWS_CRYPT_50137">[SWS_CRYPT_50137]</a>.</p>
<p>في بنية التطبيق، يتفاعل <code>SymmetricCipherCtx</code> مباشرة مع المتصل وكذلك مع كائنات المفاتيح التشفيرية. ويتم توفير مادة المفتاح إما مباشرة ككائن مفتاح في الذاكرة <code>SymmetricKey::Sptr</code> أو إدراجها بشكل غير مباشر عبر فتحة مفتاح مدارة <code>KeySlot::Sptr</code>. وبحسب الخوارزمية ووضع التشغيل، يعالج السياق متجهات التهيئة (IV) أو الـ Nonces، التي يتم إما تمريرها من قِبل التطبيق أو إنشاؤها بواسطة السياق نفسه.</p>

<h4>دورة الحياة</h4>
<p>يمر مثيل <code>SymmetricCipherCtx</code> بحالات محددة بوضوح، والتي تتحدد من خلال توفير المفاتيح ووضع المعالجة:</p>
<ul>
  <li><strong>غير مهيأ (Uninitialized):</strong> بعد الإنشاء المحض، لا يمتلك السياق أي مادة مفتاح مقترنة. ويتم رفض استدعاءات معالجة البيانات في هذه الحالة مع الخطأ <code>CryptoErrc::kUninitializedContext</code>. ويتم الانتقال إلى الحالة الجاهزة للتشغيل عبر <code>SetKey()</code>، حيث يتم تهيئة <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50043" href="../spec/record.html?id=SWS_CRYPT_50043">[SWS_CRYPT_50043]</a> أو <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a> اختيارياً.</li>
  <li><strong>مهيأ / المفتاح مُعدّ (Ready):</strong> يكون السياق مهيأً بمفتاح. ومن هذه الحالة، يمكن إما تنفيذ استدعاءات فردية عديمة الحالة (معالجة Single-Call) أو بدء جلسة تدفق متعددة المراحل.</li>
  <li><strong>التدفق نشط (Processing):</strong> من خلال استدعاء <code>Start()</code> — إما مع متجه تهيئة صريح <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a> أو بدونه أو مع IV خاص بالسياق <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a> — تبدأ معالجة التدفق. وفي هذه الحالة، يمكن تحويل البيانات باستمرار عبر <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>. بالإضافة إلى ذلك، يتيح <code>Seek()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a> إعادة التموضع في تدفق البيانات في أوضاع التشغيل المدعومة.</li>
  <li><strong>الإتمام أو الإلغاء:</strong> يتم إما إتمام معاملة التدفق الجارية بصورة اعتيادية عبر <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a> أو <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>، أو يتم التخلص منها عبر <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50046" href="../spec/record.html?id=SWS_CRYPT_50046">[SWS_CRYPT_50046]</a>. وبعد الانتهاء بنجاح أو بعد الإلغاء، يعود السياق إلى الحالة الأساسية المهيأة.</li>
</ul>
<p>تم تحديد جميع دوال الواجهة كمواصفة بأنها آمنة من الاستثناءات (<em>exception safe</em>) وآمنة بالنسبة للخيوط (<em>thread-safe</em>).</p>

<h4>مسار الاستخدام</h4>
<p>تدعم المواصفة مسارَي تنفيذ أساسيَّين لمهام التشفير وفك التشفير: الاستدعاء الفردي عديم الحالة ومعالجة الكتل المتدفقة.</p>
<p>في <strong>معالجة الاستدعاء الفردي (Single-Call)</strong> يتم تحويل جميع البيانات في عملية واحدة. وتتوفر لهذا الغرض ثلاث دوال اعتماداً على التعامل مع متجه التهيئة (IV):</p>
<ul>
  <li><code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a> للخوارزميات التي لا تتوقع متجه تهيئة (IV) ولا تُرجعه.</li>
  <li><code>ProcessSingleCallWithInputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50048" href="../spec/record.html?id=SWS_CRYPT_50048">[SWS_CRYPT_50048]</a>، عندما يحدد المتصل متجه التهيئة بشكل صريح.</li>
  <li><code>EncryptSingleCallWithOutputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a>، عندما يتم التشفير ويُرجع السياق متجه التهيئة (IV) المُنشأ إلى المتصل.</li>
</ul>
<p>في <strong>معالجة التدفق</strong> يتم التحويل تدريجياً عبر كتل تخزين مؤقت متعددة. وقبل البدء، يمكن تحديد حدود المخزن المؤقت: يحدد <code>GetMinimumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50144" href="../spec/record.html?id=SWS_CRYPT_50144">[SWS_CRYPT_50144]</a> و<code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50050" href="../spec/record.html?id=SWS_CRYPT_50050">[SWS_CRYPT_50050]</a> أحجام الكتل الدنيا والقصوى. ويمكن الاستعلام عن أطوال IV المسموح بها باستخدام <code>GetMinimumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50141" href="../spec/record.html?id=SWS_CRYPT_50141">[SWS_CRYPT_50141]</a>، و<code>GetMaximumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50142" href="../spec/record.html?id=SWS_CRYPT_50142">[SWS_CRYPT_50142]</a>، بالإضافة إلى <code>GetOutputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50143" href="../spec/record.html?id=SWS_CRYPT_50143">[SWS_CRYPT_50143]</a>. ويتم حساب حجم المخزن المؤقت الهدف المطلوب حسب الحالة عبر <code>GetRequiredOutputBufferSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a>.</p>
<p>ينقسم التسلسل النموذجي إلى:</p>
<ol>
  <li>تهيئة المفتاح بواسطة <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a>.</li>
  <li>بدء جلسة التدفق بواسطة <code>Start()</code> مع تحديد الاتجاه (<code>CryptoTransform</code>) وبشكل اختياري متجه التهيئة IV <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a>.</li>
  <li>التحويل المتكرر لكتل البيانات عبر <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>.</li>
  <li>الإنهاء النهائي عبر <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a> أو <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a> للحصول على متجه التهيئة IV المُنشأ.</li>
</ol>

<h4>سيناريوهات الأخطاء</h4>
<p>تُرجع دوال <code>SymmetricCipherCtx</code> عند فشل العمليات رموز خطأ من التعداد <code>ara::crypto::CryptoErrc</code> مع دلالات التراجع (Rollback):</p>
<ul>
  <li><code>CryptoErrc::kUninitializedContext</code>: يحدث عند <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>، أو <code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a>، أو <code>ProcessSingleCallWithInputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50048" href="../spec/record.html?id=SWS_CRYPT_50048">[SWS_CRYPT_50048]</a>، أو <code>EncryptSingleCallWithOutputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a>، أو <code>GetRequiredOutputBufferSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a>، إذا لم يتم تكوين مفتاح متوافق مسبقاً.</li>
  <li><code>CryptoErrc::kProcessingNotStarted</code>: يتم إطلاقه عند استدعاء دوال متعلقة بالتدفق مثل <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>، أو <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a>، أو <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>، أو <code>Seek()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a>، أو <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50046" href="../spec/record.html?id=SWS_CRYPT_50046">[SWS_CRYPT_50046]</a>، دون بدء عملية تدفق مسبقاً عبر <code>Start()</code>.</li>
  <li><code>CryptoErrc::kInsufficientCapacity</code>: يشير عند <code>Update()</code>، و<code>Finish()</code>، و<code>FinishEncrypt()</code>، بالإضافة إلى إجراءات Single-Call، إلى أن حجم مخزن المخرجات أو مخزن IV المؤقت الممرر صغير للغاية.</li>
  <li><code>CryptoErrc::kInvalidInputSize</code> / <code>CryptoErrc::kInvalidArgument</code>: يشير إلى أحجام غير صالحة للمخزن المؤقت، أو عدم محاذاة الكتل عند <code>Seek()</code>، أو بيانات إدخال غير صالحة.</li>
  <li><code>CryptoErrc::kUsageViolation</code> / <code>CryptoErrc::kIncompatibleObject</code> / <code>CryptoErrc::kEmptyKeySlot</code>: يحدث عندما تحظر رايات استخدام المفتاح اتجاه التحويل المطلوب (على سبيل المثال غياب <code>kAllowDataEncryption</code> أو <code>kAllowDataDecryption</code>)، أو عندما يكون نوع المفتاح غير متوافق، أو عندما يكون <code>KeySlot</code> المشار إليه فارغاً.</li>
  <li><code>CryptoErrc::kUnsupported</code>: يشير إلى أن التدفق أو عمليات البحث (Seek) أو الاستدعاءات الفردية أو تكوين IV المحدد غير مدعوم بواسطة السياق أو الخوارزمية الفعلية.</li>
</ul>
