تُستخدم الواجهة ara::crypto::cryp::AuthCipherCtx للتشفير وفك التشفير الموثق للبيانات مع الحفاظ على السرية والسلامة [SWS_CRYPT_23911]. وبعد تهيئة المفتاح، تتم المعالجة إما كاستدعاء فردي ذري أو كتسلسل متدفق يتكون من التهيئة، وبيانات التوثيق الاختيارية، وتحديثات بيانات الحمولة، والإنهاء. كشرط أمني حرج، يفشل فك التشفير في حالة وجود وسم توثيق غير صالح، بحيث لا يجوز معالجة بيانات الحمولة المفكوكة تشفيرها إلا بعد التحقق الناجح [SWS_CRYPT_50075].

السياق

تُعرّف الواجهة ara::crypto::cryp::AuthCipherCtx واجهة برمجة التطبيقات المعيارية لعمليات التشفير الموثّق (Authenticated Encryption with Associated Data, AEAD) ضمن AUTOSAR Adaptive Platform. وهي تجمع بين السرية وحماية السلامة، حيث يتم دائماً توليد وسَم توثيق تشفيري أو التحقق منه إلى جانب التشفير أو فك التشفير الفعلي للبيانات المفيدة. وتعمل التطبيقات المستدعية بالإضافة إلى كائنات المفاتيح كشركاء تفاعل مركزيين: يتم إما ربط السياق بمثيل ملموس من SymmetricKey [SWS_CRYPT_23911] قبل الاستخدام، أو تهيئته بواسطة KeySlot مُستدام أو مُقدَّم [SWS_CRYPT_50072]. وإلى جانب المعالجة الدفقية خطوة بخطوة، تدعم الفئة أيضاً استدعاءات فردية قائمة بذاتها لمعالجة رسائل كاملة في خطوة واحدة [SWS_CRYPT_50078].

دورة الحياة

تُدار السياقات في نطاق التطبيق عبر نوع المؤشر المشترك ara::crypto::cryp::AuthCipherCtx::Sptr [SWS_CRYPT_20101]. (تفسير: يتم إنشاء الكائن نموذجياً عبر مصنع مزوّد ذي مستوى أعلى، نظراً لأن AuthCipherCtx مُحددة كواجهة مجردة). وقد أُعلن أن جميع الدوال الأعضاء آمنة استثنائياً (exception safe) وآمنة خيطياً (thread-safe) [SWS_CRYPT_23911]، [SWS_CRYPT_24715]. وتمر دورة الحياة الوظيفية بحالات محددة بوضوح:

  • غير مهيأ: مباشرة بعد إنشاء المثيل. يتم رفض استدعاءات معالجة البيانات، نظراً لعدم تعيين أي مفتاح بعد [SWS_CRYPT_50081].
  • المفتاح مهيأ: من خلال الاستدعاء الناجح لـ SetKey باستخدام SymmetricKey [SWS_CRYPT_23911] أو KeySlot [SWS_CRYPT_50072]، ينتقل السياق إلى الحالة الجاهزة للتشغيل. ومن هذه الحالة، يمكن تنفيذ عمليات الطلقة الواحدة مباشرةً.
  • الدفق نشط: يتم الدخول فيها من خلال استدعاء Start مع تحديد اتجاه التحويل باستخدام متجه تهيئة (IV) [SWS_CRYPT_24715] أو بدون IV صريح [SWS_CRYPT_50073].
  • الإنهاء / إعادة التعيين: تكتمل عملية الدفق الجارية بشكل نظامي عبر Finish [SWS_CRYPT_50075] أو FinishEncrypt [SWS_CRYPT_50076]، أو يتم إحباطها مبكراً عبر Cancel [SWS_CRYPT_50077]. وبعد ذلك، يصبح السياق جاهزاً من جديد لتسلسلات معالجة جديدة.

مخطط الحالة: مراحل حالة السياق بدءاً من ربط المفتاح مروراً بالمعالجة الدفقية وحتى الإنهاء. المصادر: [SWS_CRYPT_23911]، [SWS_CRYPT_50072]، [SWS_CRYPT_24715]، [SWS_CRYPT_50075]، [SWS_CRYPT_50077].

مسار الاستخدام

من أجل المعالجة المستمرة لتدفق البيانات، تتطلب الواجهة تسلسلاً مرتباً من الاستدعاءات:

  1. التهيئة: تعيين المفتاح عبر SetKey [SWS_CRYPT_23911] أو SetKey باستخدام KeySlot [SWS_CRYPT_50072].
  2. الاستعلام عن المعلمات: التحديد الاختياري للقيم الحدية وأحجام المخازن المؤقتة عبر GetMinimumChunkSize [SWS_CRYPT_50162]، GetMaximumChunkSize [SWS_CRYPT_50082]، GetMinimumInputIvSize [SWS_CRYPT_50163]، GetMaximumInputIvSize [SWS_CRYPT_50164]، GetTagSize [SWS_CRYPT_50161] وكذلك GetRequiredOutputBufferSize [SWS_CRYPT_50081].
  3. بدء العملية: استدعاء Start مع تحديد الاتجاه (تشفير أو فك تشفير) بالإضافة إلى توفير IV [SWS_CRYPT_24715] أو طلب IV خاص بالسياق [SWS_CRYPT_50073].
  4. البيانات المقترنة (AAD): إذا كان يتعين تضمين بيانات نص صريح إضافية في حساب السلامة، فسيتم تمريرها عبر UpdateAuthenticatedData [SWS_CRYPT_20313]. ويمكن الاستعلام عن الحد الأقصى المسموح به لحجم AAD عبر GetMaxAssociatedDataSize [SWS_CRYPT_20103]. مهم: يجب بالضرورة إرسال كتل AAD قبل البيانات المفيدة الفعلية.
  5. معالجة البيانات المفيدة: التمرير التدريجي لكتل البيانات عبر UpdateConfidentialData [SWS_CRYPT_50074]. وعند فك التشفير، يتم إرجاع النص الصريح قبل ثبوت موثوقيته؛ ولا يجوز للتطبيق استخدام هذه البيانات إلا بعد اكتمال الإنهاء النهائي بنجاح.
  6. الإنهاء النهائي: إنهاء العملية بواسطة Finish [SWS_CRYPT_50075] أو FinishEncrypt [SWS_CRYPT_50076]، وبذلك تتم معالجة الكتلة الأخيرة وحساب وسَم التوثيق أو التحقق منه.

بالنسبة لحمولات البيانات المدمجة، توجد بدائل أحادية الاستدعاء: يعالج ProcessSingleCall البيانات دون تمرير IV [SWS_CRYPT_50078]، ويقبل ProcessSingleCallWithInputIv قيمة IV خارجية [SWS_CRYPT_50079]، ويُرجع EncryptSingleCallWithOutputIv قيمة IV تم إنشاؤها بواسطة السياق إلى المستدعي [SWS_CRYPT_50080].

مخطط التسلسل: تسلسل استدعاء تشفير موثّق متدفق. المصادر: [SWS_CRYPT_23911]، [SWS_CRYPT_24715]، [SWS_CRYPT_20313]، [SWS_CRYPT_50074]، [SWS_CRYPT_50075].

سيناريوهات الأخطاء

تُعيد دوال AuthCipherCtx النتائج عبر ara::core::Result وتمتلك دلالات التراجع في حالة الخطأ. رموز الخطأ ذات الصلة من ara::crypto::CryptoErrc هي:

  • kUninitializedContext: يحدث عند استدعاء Start [SWS_CRYPT_24715]، أو ProcessSingleCall [SWS_CRYPT_50078]، أو حسابات المخازن المؤقتة [SWS_CRYPT_50081]، في حال لم تتم بعد تهيئة أي مفتاح عبر SetKey.
  • kProcessingNotStarted: يُبلّغ عنه عندما يتم استدعاء UpdateAuthenticatedData [SWS_CRYPT_20313]، أو UpdateConfidentialData [SWS_CRYPT_50074]، أو Finish [SWS_CRYPT_50075]، أو Cancel [SWS_CRYPT_50077] دون Start مسبق.
  • kInvalidUsageOrder: يشير إلى ترتيب استدعاء غير صحيح عند استدعاء UpdateAuthenticatedData بعد معالجة بيانات مفيدة بالفعل عبر UpdateConfidentialData [SWS_CRYPT_20313].
  • kAuthTagNotValid: يشير عند فك التشفير في Finish [SWS_CRYPT_50075] أو دوال الطلقة الواحدة [SWS_CRYPT_50078] إلى أن الوسَم المحسوب لا يتطابق مع الوسَم المُمرَّر وأن فحص الموثوقية قد فشل.
  • kUsageViolation: يحدث عندما لا تتطابق سمات استخدام المفتاح مع العملية المطلوبة (مثل غياب kAllowDataEncrypt أو kAllowDataDecrypt) [SWS_CRYPT_23911]، [SWS_CRYPT_50078].
  • kInsufficientCapacity / kInvalidInputSize: يشيران إلى مخازن مؤقتة للإخراج ذات أحجام غير كافية أو أطوال غير مسموح بها للمدخلات أو IV أو الوسَم [SWS_CRYPT_24715]، [SWS_CRYPT_50074]، [SWS_CRYPT_50075].
  • kEmptyKeySlot / kBusyResource: يتعلقان بحالات الخطأ عند استخدام مواضع تخزين مفاتيح مُهيأة [SWS_CRYPT_24715]، [SWS_CRYPT_50078].
