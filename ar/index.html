Adaptive Platform في جملة واحدة

تُعد AUTOSAR Adaptive Platform بيئة تشغيل موجهة للخدمات لحواسيب المركبات عالية الأداء: تعمل Adaptive Applications كعمليات POSIX مستقلة، وتُشغّل وتُراقب ديناميكيًا، وتتواصل عبر Services محددة بعقود بدلًا من إشارات موصّلة بشكل ثابت (EXP PlatformDesign §3.3 «Adaptive Platform – Characteristics»، §8.2 «Service Oriented Communication»).

ARA — واجهة البرمجة لهذا المرجع

تشكل جميع Namespaces ara::* الموثقة هنا معًا واجهة ARA (AUTOSAR Runtime for Adaptive Applications). يصدّر كل Functional Cluster في المنصة واجهة C++ API الخاصة به في Namespace مستقل — من الأنواع الأساسية في ara::core، عبر اتصال الخدمات في ara::com، إلى خدمات المنصة مثل ara::exec وara::per أو ara::crypto (EXP PlatformDesign §4.1 «Logical view»، EXP SWArchitecture §9.1 «Building Block View – Overview»).

ZXQK0000QXZ وZXQK0001QXZ والتفاعلات النموذجية للتطبيق التكيفي (عقدة قابلة للنقر). المصادر: EXP PlatformDesign §4.1، EXP SWArchitecture §9.1. التفسير الجزئي: اختيار التفاعلات ووضع العلامات عليها يلخص فصول المصادر المذكورة.

المفاهيم الشاملة

  • Machine & Software Cluster: إن Machine هي بيئة التنفيذ (وربما الافتراضية)؛ وتُحزم البرمجيات بوصفها Software Clusters قابلة للتثبيت وتُحدَّث عبر ara::ucm ‏(EXP SWArchitecture §13.4 «Software Cluster»، §13.5 «Machine»).
  • ينص Function Groups & على ما يلي: يتم تعيين العمليات إلى Function Groups؛ ara::sm يوجه Execution Management لبدء/إيقاف العمليات عبر حالات المجموعة الوظيفية (EXP SWArchitecture §13.2 «Function Group»، EXP PlatformDesign الفصل 7 «State Management»).
  • Manifests: تهيئ Execution- وService-Instance- وMachine-Manifest بصورة تصريحية Deployment وسلوك البدء وربط Service (EXP PlatformDesign §4.4 «Manifest»، EXP SWArchitecture §13.6 «Manifest»).
  • معالجة الأخطاء دون Exceptions: على مستوى المنصة، تُرجع الأخطاء على أنها ara::core::Result/ErrorCode (EXP PlatformDesign §18.1 «Error Handling»، EXP SWArchitecture §13.12 «Error Handling»).
  • السلامة والأمن بوصفهما عنصرين عابرين للمجالات: تؤمّن حماية E2E، وHealth Monitoring (ara::phm)، ومكدس التشفير، وIdentity & Access Management، وIntrusion Detection (ara::idsm)، وFirewall (ara::fw) المنصة والاتصال (EXP PlatformDesign الفصل 17 «Safety»، EXP SWArchitecture §13.13 «Trusted Platform»).

الروابط المتقاطعة بين الوحدات

الإطارات المستديرة = Modules؛ والعقد = مجالات فرعية لوحدة (Namespaces أو مجموعات وظائف). السهم A → B: تشير مواضع API للمجال A (Signatures والحقول والمعلمات) إلى أنواع المجال B — مستنبطة من التصريحات المرتبطة في هذا المرجع؛ ويتناسب سمك الخط مع عدد مواضع الإشارة (العدد الدقيق كتلميح أداة على السهم). تسمية الحافة = نوع التفاعل مع الهدف: قيم الإرجاع، نتائج غير متزامنة، معالجة الأخطاء، أنواع البيانات، عنونة المثيلات، دوال مساعدة؛ «يستخدم» يشير إلى إشارات الأنواع الأخرى. الأسهم الرمادية الفاتحة: نمذجة الخدمة عبر ara::com. ترتبط جميع العقد بصفحات Namespace/الفئة ذات الصلة.

ملاحظات

  • نصوص الوصف مأخوذة دون تغيير من مواصفات (Englisch).
  • قد تظهر أحيانًا آثار فواصل الأسطر عند الاستخراج الآلي من PDF.
  • تُنمذج ara::ucm وأجزاء من ara::sm/ara::com بوصفها خدمات ara::com ‏(Service Interfaces ذات معلمات IN/OUT) بدل APIs ‏C++ مباشرة.
  • الأقسام ذات الشارة البنفسجية مولَّد بالذكاء الاصطناعي / AI generated هي أوصاف مصاغة تلقائيًا. وهي مشتقة من عناصر المواصفات المشار إليها (وموثقة بإحالة [SWS_…])، لكنها ليست نصًا رسميًا من AUTOSAR.
  • يتم إنشاء الرسوم البيانية لفئة UML (الميراث، الأعضاء) من سجلات API المستخرجة؛ يؤدي النقر فوق المربع إلى فتح الصفحة المقابلة.
  • تحت «Anforderungen (Volltext)» يتم عرض متطلبات SWS لكل فئة، الذي يذكر الفصل نصه بالاسم (المهمة التلقائية، النص الأصلي باللغة الإنجليزية).

API رؤية التطبيقات

ليست كل عناصر المواصفة الموثقة هنا جزءًا من ARA API العامة: تحدد وثائق SWS في الفصل 5 («Dependencies to other Functional Clusters»، في كل منها الجدول 5.1) الواجهات التي تُتاح حصريًا لـ Functional Clusters أخرى. يجعل هذا المرجع ذلك ظاهرًا بصورة متسقة من خلال لون الخلفية لاسم Module وNamespace والفئة المعنية — في صفحة كل عنصر (رأس الصفحة والعلامة إلى اليمين في شريط التنقل)، وفي جميع الإشارات إلى العنصر في الصفحات الأعلى، وفي عقد المخططات المرتبطة. تكون الخلفيات باهتة جدًا افتراضيًا لضمان سهولة القراءة وتصبح أكثر كثافة قليلًا عند Mouseover:

  • APPLICATION الأزرق: من Adaptive Applications يمكن استخدامه مباشرةً - على سبيل المثال. على سبيل المثال ara::core، ara::com، ara::log، ara::per، ara::crypto، ara::diag، ara::rds، ara::shwa (يعمل كمكتبة في عملية التطبيق، SWS SHWA الفصل 1)، ara::tsync (استخدام قاعدة الوقت النشطة والسلبية، SWS TSync §2.2) و ara::idsm (تطبيقات كأجهزة استشعار أمنية، SWS IdsM §7.2). ara::exec::ExecutionClient ينتمي أيضًا إلى هنا، ولكن يمكنه فقط الإبلاغ عن حالة العملية الخاصة به [SWS_EM_01401].
  • PRIVILEGED Red: فقط للتطبيقات المخصصة المعتمدة عبر تعيين IAM أو ZXQK0000QXZ؛ المستخدم المصرح له موجود بين قوسين في سطر التنقل. أمثلة: PackageManagement-Service لـ ara::ucm (ZXQK0001QXZ = على سبيل المثال، عميل OTA أو Diagnose-Applikation، SWS UCM §7.1)، وStateMachine-Services لـ ara::sm لواحد SM-Control-Application [SWS_SM_00600] وSuspend-to-RAM-API ara::sm::s2r (فقط الأقمار الصناعية المعتمدة IAM مع SuspendToRamSatelliteMapping و[SWS_SM_00715]) وara::fw (تغيير الحالة فقط مع AdaptiveFirewallToPortPrototypeMapping، [AP_SWS_Fw_40013]).
  • INTERNAL رمادي داكن: واجهات داخلية بحتة للمجموعة، وليست مخصصة للتطبيقات قطعاً؛ وترد Functional Cluster المستخدمة بين قوسين في شريط التنقل. أمثلة: ara::exec::StateClient مع FunctionGroup/FunctionGroupState (لـ State Management فقط، SWS EM Tab. 5.1)، والوحدة الكاملة ara::nm (أُزيل Service-Interface للتطبيقات، وتتم طلبات الشبكة عبر State Management وSWS NM §4.1 وTab. 5.1)، وara::phm::RecoveryAction (SWS PHM Tab. 5.1)، وكذلك جميع واجهات apext::* للملحقات المعيارية «Platform Extension Interfaces» (تكامل المنصة باتجاه البرامج الأساسية: Watchdog، وPower، وUDS-Transport، وFreshness-Value-Manager، وTrace/ARTI).

تحمل الصفحات التجميعية (Modules وNamespaces) ذات المحتوى المختلط كلمةً مفتاحية لأغلبية عناصرها الفرعية، وتدرج الاستثناءات بين قوسين، مثل APPLICATION (Except INTERNAL StateClient, …). يمكن تعديل مخطط الألوان مركزيًا في كتلة الرؤية في style.css: قيم الألوان عبر --vis-app-rgb (أزرق) و--vis-priv-rgb (أحمر) و--vis-internal-rgb (رمادي داكن)، وبهتان الخلفيات عبر --vis-bg-alpha (افتراضي) و--vis-bg-alpha-hover (Mouseover).

تفسير: التصنيف اللوني هو تصنيف من KI استنادًا إلى جداول 5.1 وفصول الاستخدام (الفصل 7) وملاحق SWS المعنية؛ ولا تسجل المعايير ذاتها مثل هذا التصنيف عنصرًا بعنصر. أُسندت الأنواع المرافقة (Error Domains وExceptions وHandles) إلى مرئية واجهتها الرئيسية.

تفسير: يتبع تجميع Modules في هذه النظرة العامة (الأساس، ووقت التشغيل، والاتصال، والتخزين، والأمان، والتشخيص) هيكل Building Blocks في وثيقة البنية، وليس تقسيمًا معياريًا للمعايير.
