دور Safe Hardware Acceleration والحدود الفاصلة مع عملية التطبيق

تتيح Safe Hardware Acceleration (SHWA، مساحة الأسماء ara::shwa) استخدام تسريع العتاد بصورة معيارية وقابلة للنقل لإجراء عمليات حسابية آمنة وفعالة SWS SHWA ص. 4. ووفقًا للنظرة العامة الوظيفية، توفر SHWA واجهات برمجة تطبيقات (APIs) لـ Adaptive Applications ومجموعات Functional Clusters الأخرى. وتغطي هذه المجموعة (Cluster) ثلاث مهام:

  • تنفيذ المهام كثيفة الحوسبة بالتوازي على مسرّع العتاد (HWA)،
  • اكتشاف أخطاء Tasks قيد التشغيل هناك وتصحيحها،
  • مراقبة حالات عمل المسرّعات SWS SHWA ص. 7.

من المفترض أن تراعي متطلبات هذه المجموعة متطلبات السلامة الخاصة بـ AUTOSAR SWS SHWA ص. 5.

تُصنِّف النظرة العامة على البنية المعمارية SHWA ضمن فئة Safety. وخلافًا لـ Platform Health Management، لم يتم تصنيف SHWA هناك على أنها daemon-based EXP SW-Architektur ص. 127. والواجهات هي واجهات C++ أصلية تستخدمها Adaptive Application مباشرة EXP SW-Architektur ص. 132. ويمكن لمجموعات Functional Clusters الأخرى أيضًا استخدام SHWA دون مشاركة من Adaptive Application. ويستخدم جزء المكتبة الخاص بها معلومات النشر (Deployment) الخاصة به لذلك، بينما يتم تصميم الخوادم الخفية (Daemons) الخاصة بها مثل Adaptive Applications SWS SHWA ص. 23.

على جانب العتاد، يميّز Device نوع وحدة الحوسبة عبر IsCpu وIsGpu وIsAccelerator [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00311] [AP_SWS_SHWA_00312]. ويحدد التعداد Target موقعَي تنفيذ: kDevice للجهاز أو المسرّع، وkHostTask لوحدة المعالجة المركزية المضيفة (Host-CPU) [AP_SWS_SHWA_00102].

مخطط السياق: تستخدم Adaptive Applications ومجموعات Functional Clusters الأخرى SHWA كواجهة أصلية؛ وتقوم SHWA بربط CPU وGPU والمسرّعات. المصادر: SWS SHWA ص. 23، EXP SW-Architektur ص. 127، [AP_SWS_SHWA_00310]

أربعة مجالات لواجهة ara::shwa

يقسم الرسم التوضيحي للمواصفة واجهة برمجة التطبيقات (API) إلى أربعة مجالات: إدارة البيانات، وتنفيذ المهام، وإدارة الأجهزة ومراقبتها، بالإضافة إلى معالجة الأخطاء SWS SHWA ص. 17. ويصف الشرح التوضيحي لواجهة برمجة التطبيقات المجالات الثلاثة الأولى كطبقات EXP SHWA-API ص. 15.

  • إدارة البيانات: يصف Range وId الأحجام والفهارس ذات البعد الواحد إلى الأبعاد الثلاثة [AP_SWS_SHWA_01009] [AP_SWS_SHWA_00709]. ويضاف إلى ذلك Buffer [AP_SWS_SHWA_00209] وAccessor [AP_SWS_SHWA_00007] وPropertyList [AP_SWS_SHWA_00802].
  • تنفيذ المهام: Queue [AP_SWS_SHWA_00908] وTaskHandler [AP_SWS_SHWA_01202] وEvent [AP_SWS_SHWA_00602].
  • إدارة الأجهزة ومراقبتها: Platform [AP_SWS_SHWA_01107] وDevice [AP_SWS_SHWA_00308]. ويضاف إلى ذلك DeviceSelector مع GpuSelector وCpuSelector وAcceleratorSelector [AP_SWS_SHWA_00403] [AP_SWS_SHWA_00407] [AP_SWS_SHWA_00410] [AP_SWS_SHWA_00413] وكذلك DeviceMonitor [AP_SWS_SHWA_01407].
  • معالجة الأخطاء: ErrorHandler [AP_SWS_SHWA_00507] وShwaErrorCode [AP_SWS_SHWA_01301] وShwaErrorDomain [AP_SWS_SHWA_01307] وShwaException [AP_SWS_SHWA_01303].

يجوز للتطبيق الجمع بين عدة Queues وDevices وBuffers. وينطبق الأمر نفسه على Functional Clusters الأخرى SWS SHWA ص. 22. ويُظهر الرسم التوضيحي المقترن مجموعتين مستقلتين. تتكون كل مجموعة من Queue مع عدة Tasks، ومن Buffers ومن Device واحد SWS SHWA ص. 23.

مخطط التعاون: هكذا تترابط الفئات المركزية عبر المجالات المختلفة: ترتبط Queue بجهاز Device، وتوفر Submit حدثًا (Event)، ويصل Accessor إلى Buffer. المصادر: SWS SHWA ص. 17، [AP_SWS_SHWA_00910]، [AP_SWS_SHWA_00912]، [AP_SWS_SHWA_00008]، [AP_SWS_SHWA_01407]

من الجهاز إلى Queue: الاختيار والإعداد

يمكن تحديد Device بثلاث طرق:

  1. التعداد: يُرجع Platform::GetPlatforms المنصات المتاحة، وGetDevices أجهزتها (Devices) [AP_SWS_SHWA_01107] [AP_SWS_SHWA_01108].
  2. دون وسيطة: Device::Create() [AP_SWS_SHWA_00308].
  3. عبر محدد: Device::Create(deviceSelector) [AP_SWS_SHWA_00309].

يقوم DeviceSelector بتقييم Device باستخدام operator() ويُرجع مقابل ذلك Result<int>. ويُرجع SelectDevice الجهاز (Device) المختار [AP_SWS_SHWA_00404] [AP_SWS_SHWA_00403]. ويقرأ GetInfo<InfoType> تفاصيل إضافية حول الجهاز من [AP_SWS_SHWA_00313].

يتم إنشاء Queue إما مباشرةً من محدد أو من Device ملموس. وفي كلا المتغيرين، يُعد ErrorHandler وسيطة إلزامية، بينما تكون PropertyList اختيارية [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00909]. ويُرجع GetDevice الجهاز المرتبط (Device). ويشير IsInOrder إلى ما إذا كانت مهام (Tasks) الخاصة بـ Queue تُنفَّذ بترتيب معين [AP_SWS_SHWA_00910] [AP_SWS_SHWA_00911] EXP SW-Architektur ص. 133.

مخطط النشاط: تؤدي ثلاث طرق إلى Device، ومصنعان إلى Queue؛ ويتم فحص كل نتيجة كـ Result. المصادر: [AP_SWS_SHWA_01107]، [AP_SWS_SHWA_00308]، [AP_SWS_SHWA_00309]، [AP_SWS_SHWA_00908]، [AP_SWS_SHWA_00909]

توفير البيانات وإرسال المهام

يصف Range الأحجام من بُعد واحد إلى ثلاثة أبعاد [AP_SWS_SHWA_01007] [AP_SWS_SHWA_01009]. ويتوفر Buffer::Create بعدة صيغ [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00210] [AP_SWS_SHWA_00212] [AP_SWS_SHWA_00211] [AP_SWS_SHWA_00213] [AP_SWS_SHWA_00214]:

  • مع Range فقط،
  • مع Range ومخصِّص إضافي،
  • مع مخصِّص فقط،
  • مع بيانات مضيف متغيرة أو ثابتة.

يصل Accessor إلى Buffer. ويتم إنشاؤه بدون أو مع TaskHandler [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00008]. وهو يوفر operator[] مع Id أو فهرس خطي [AP_SWS_SHWA_00009] [AP_SWS_SHWA_00010]. وبالإضافة إلى ذلك، يوفر Set وGet مع قيمة مرجعة من نوع Result [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012]. ويعتمد الوصول على AccessMode بالقيم kRead وkWrite وkReadWrite. وفي حالة kRead، يكون ReferenceT مرجعًا ثابتًا [AP_SWS_SHWA_00101] [AP_SWS_SHWA_00014].

يقوم Queue::Submit(cfg, ErrorHandler&&) بتقديم مهمة (Task) ويُرجع Event [AP_SWS_SHWA_00912]. ويوفر TaskHandler شكلين للتنفيذ: SingleTask لمهمة مفردة وParallelFor(bufferSize, cfg) للتنفيذ المتوازي للبيانات [AP_SWS_SHWA_01203] [AP_SWS_SHWA_01204]. ويذكر مخطط حالات الاستخدام كسيناريوهات استخدام «Single Instructions on Multiple Data» و«Multiple Instructions on Multiple Data» EXP SW-Architektur ص. 203.

تفسير: من المحتمل أن يكون cfg تكوينًا قابلاً للاستدعاء. إذ يتلقى على الأرجح TaskHandler، وينشئ بداخله Accessors ويستدعي SingleTask أو ParallelFor. ويشير مصنع Accessor المزود بوسيطة TaskHandler إلى ذلك [AP_SWS_SHWA_00008].

مخطط التسلسل: يتم توفير البيانات، وتقديم مهمة (Task) متوازية البيانات وانتظار اكتمالها. تم تمييز استدعاء cfg كتفسير. المصادر: [AP_SWS_SHWA_01007]، [AP_SWS_SHWA_00211]، [AP_SWS_SHWA_00912]، [AP_SWS_SHWA_00008]، [AP_SWS_SHWA_01204]، [AP_SWS_SHWA_00604]

المزامنة عبر الأحداث (Events) ودوال الانتظار الخاصة بـ Queue

يُرجع كل Submit Event [AP_SWS_SHWA_00912]. وعلى مستوى الحدث (Event)، تتوفر ثلاث دوال انتظار [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00605] [AP_SWS_SHWA_00606]:

  • ينتظر Event::Wait() اكتمال المهام المرتبطة.
  • تنتظر الصيغة الثابتة المزودة بقائمة أحداث أحداثًا متعددة (Events).
  • يحدد WaitFor(ms) الانتظار بمهلة زمنية.

يُرجع GetWaitList قائمة بالأحداث (Events) [AP_SWS_SHWA_00603]. وعلى مستوى Queue، ينتظر Wait() بشكل حاجِب (blocking) جميع المهام (Tasks) المدرجة في قائمة الانتظار، بينما يقوم WaitFor(ms) بالشيء نفسه مع حد زمني [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] EXP SW-Architektur ص. 133.

توضح المتطلبات (Requirements) أمان الخيوط (Thread Safety) لكل دالة على حدة:

  • آمن بالنسبة للخيوط: Queue::Create وAccessor::Create وRange::Create، وكذلك Accessor::Set وGet [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00007] [AP_SWS_SHWA_01007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012].
  • غير آمن بالنسبة للخيوط: Queue::Submit وQueue::Wait وEvent::Wait وDevice::Create وAccessor::operator[] [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00308] [AP_SWS_SHWA_00009].
  • الاختلافات داخل الفئة الواحدة: Buffer::Create آمن بالنسبة للخيوط، بينما الصيغة التي تحتوي على مخصِّص فقط ليست كذلك [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00212].

تقبل صيغة ثانية لـ Submit secondaryQueue بدلاً من ErrorHandler [AP_SWS_SHWA_00913]. تفسير: من المحتمل أن تعمل هذه الـ Queue كـ Queue احتياطية إذا فشل التنفيذ على الـ Queue الأساسية. وترجع هذه الصيغة إلى متطلب المنبع نفسه مثل ErrorHandler [AP_SWS_SHWA_00507].

مخطط التسلسل: تعمل قائمتا انتظار (Queues) بشكل مستقل؛ ويقوم التطبيق بالمزامنة عبر قوائم الأحداث (Events) أو دوال الانتظار الخاصة بـ Queue. المصادر: [AP_SWS_SHWA_00912]، [AP_SWS_SHWA_00605]، [AP_SWS_SHWA_00914]، [AP_SWS_SHWA_00917]، SWS SHWA ص. 22

تنطبق ثلاث قواعد تصميم على جميع الفئات EXP SHWA-API ص. 15:

  • تكون الدوال الإنشائية خاصة؛ ويتم إنشاء الكائنات عبر دوال Create() المسماة.
  • الفئات التي تمتلك بيانات توفر std::unique_ptr.
  • معظم القيم المرجعة مغلفة في ara::core::Result.

يتم تمرير الخصائص عند الإنشاء كـ PropertyList [AP_SWS_SHWA_00802]. وفي Buffer وAccessor وQueue، يتحقق HasProperty مما إذا كانت الخاصية موجودة؛ ويقرؤها GetProperty. ويبلغ GetProperty عن الخصائص غير المدعومة بـ kFeatureNotSupported [AP_SWS_SHWA_00215] [AP_SWS_SHWA_00216] [AP_SWS_SHWA_00015] [AP_SWS_SHWA_00016] [AP_SWS_SHWA_00915] [AP_SWS_SHWA_00916]. ولا تحدد المصادر المتاحة بالتفصيل معلومات النشر (Deployment) التي تستخدمها Functional Clusters لـ SHWA SWS SHWA ص. 23.

للمراقبة، يتم إنشاء DeviceMonitor من Device أو محدد [AP_SWS_SHWA_01407] [AP_SWS_SHWA_01408]. ويُرجع Status() DeviceStatus بإحدى هذه القيم [AP_SWS_SHWA_01409] [AP_SWS_SHWA_00103]:

  • kReady: جاهز لتنفيذ المهام،
  • kNotAccesible: غير قابل للوصول،
  • kFailure: حالة خطأ،
  • kUnknown: لا يمكن تحديد الحالة.

لا تحدد المصادر المتاحة ما إذا كانت هذه الحالة يتم تمريرها إلى Functional Clusters الأخرى.

مخطط النشاط: يتم الاستعلام عن الحالة عبر DeviceMonitor وتتفرع وفقًا لـ DeviceStatus؛ والاستجابة للقيم الأخرى بخلاف kReady تُعد تفسيرًا. المصادر: [AP_SWS_SHWA_01407]، [AP_SWS_SHWA_01409]، [AP_SWS_SHWA_00103]

التصرف في حالة الخطأ

يُبلّغ SHWA عن الأخطاء عبر ara::core::Result برموز من ShwaErrorCode. وتشمل هذه kRuntime وkTaskExecutionFailure وkMemoryNotAllocated وkIntegrityCorrupted (تعذر استعادة سلامة ذاكرة التخزين المؤقت Buffer) وkResourceBusy وkInvalidAccessMode [AP_SWS_SHWA_01301]. وتحدد دوال مفردة رموزًا أخرى: kAccessorFailure وkInvalidIndex وkFeatureNotSupported وkEventInvalidOperation [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00313] [AP_SWS_SHWA_00603].

يوفر النطاق ShwaErrorDomain كلاً من Name وMessage وThrowAsException. ويربط GetShwaDomain وMakeErrorCode الرموز بالنطاق. وينقل ShwaException رمزًا كاستثناء [AP_SWS_SHWA_01308] [AP_SWS_SHWA_01309] [AP_SWS_SHWA_01310] [AP_SWS_SHWA_01311] [AP_SWS_SHWA_01312] [AP_SWS_SHWA_01303].

تترتب عواقب وخيمة بوجه خاص على الأخطاء أثناء التنفيذ والانتظار. إذا أبلغ Submit أو Queue::Wait أو Queue::WaitFor أو Event::Wait عن الرمز kRuntime، فيجب اعتبار بيانات المهمة الفاشلة قد عُدّلت عن غير قصد. وفي حالة Event::Wait، ينطبق ذلك أيضًا على kTaskExecutionFailure [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] [AP_SWS_SHWA_00604]. وتحمل بيانات الخطأ الخاصة بـ Submit العلامة no_rollback_semantics [AP_SWS_SHWA_00912].

تُبلّغ استعلامات الأجهزة وAccessor::Get، من بين جهات أخرى، عن الموارد المشغولة باستخدام kResourceBusy [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00012]. ويُبلّغ Buffer::Create عن فشل التخصيص باستخدام kMemoryNotAllocated [AP_SWS_SHWA_00212].

يُغلّف ErrorHandler دالة std::function<void(ara::core::ErrorCode)> [AP_SWS_SHWA_00507]. ويُنفّذ HandleError(ShwaErrorCode) المعالجة وهو غير آمن خيطيًا [AP_SWS_SHWA_00508]. وتحصل كل Queue عند إنشائها على ErrorHandler [AP_SWS_SHWA_00908]. تفسير: يُرجَّح أن يُبلّغ التنفيذ عبر HandleError عن أخطاء المهام المُقدَّمة التي لا تتوفر مباشرة كقيمة إرجاع من Submit؛ ولا تحدد المصادر الجهة التي تستدعي HandleError. وعلى مستوى الجهاز، يشير DeviceStatus::kFailure إلى حالة خطأ [AP_SWS_SHWA_00103].

مخطط نشاط: يُقيَّم Result وتُصنَّف رموز خطأ SHWA، بما في ذلك عواقب أخطاء المهام على البيانات. المصادر: [AP_SWS_SHWA_01301]، [AP_SWS_SHWA_00912]، [AP_SWS_SHWA_00604]، [AP_SWS_SHWA_01310]، [AP_SWS_SHWA_00508]

ara::shwa

AcceleratorSelector فئة

AcceleratorSelector manages accelerator selection for operations on HWA if available.

Accessor فئة

Accessor manages read and write access to allocated memory by Buffer. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

Buffer فئة

Buffer manages memory allocation for operations on the host or/and HWA. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

CpuSelector فئة

CpuSelector manages CPU selection for operations on HWA if available Allows to get a device from any supported backends for which the device type is CPU.

Device فئة

Device class represents HWA device. Provides access to the device but not controlling it. Designed as copyable since not owning resources.

DeviceMonitor فئة

DeviceMonitor API class. Designed as copyable since not owning resources.

DeviceSelector فئة

Class allowing to choose the most appropriate device of the available ones. This is a callable object taking a device reference and returning an integer rank. One of the device with the highest non-negative value is selected.

ErrorHandler فئة

ErrorHandler manages asynchronous error handling for operations on HWA.

Event فئة

Event class helps to manage task execution synchronization between HWA and Host application. Can be created only inside of the Queue otherwise it’s meaningless.

GpuSelector فئة

GpuSelector manages GPU selection for operations on HWA if available Select a device from any supported backends for which the device type is GPU.

Id فئة

Id API class. Designed as copyable since not owning resources.

Platform فئة

Platform class is responsible for extracting different HWA platforms available for current application and listing Devices bind to each platform. Designed as copyable since not owning resources.

PropertyList فئة

Property List class is designed to enable vendor specific SHWA functionality extension and adjustment. Properties are not standardized and can be defined by Vendor. Class using Property list is obliged to have HasProperty() and GetProperty() methods defined.

Queue فئة

Queue API provides the functionality for parallel processing on selected Device. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ ptr, which may be moved. ≙ std::unique_

Range فئة

Defines size of Buffer for one, two or three dimensions. Designed as copyable since not owning resources.

ShwaErrorDomain فئة

Defines the error domain for Safe Hardware Acceleration.

ShwaException فئة

Exception type could be thrown by application or other FC using Safe Hardware Acceleration. Safe Hardware Acceleration API is exception free and can only return an ErrorCode, but user code can transform this error to exception and throw if it’s alligned with system error handling architecture.

TaskHandler فئة

Handles tasks execution on the selected Device Can be created only inside of the Queue otherwise it’s meaningless.
