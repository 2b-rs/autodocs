التصنيف والغرض

توفر Safe Hardware Acceleration آليات تتيح لـ Adaptive Applications تنفيذ مهام متوازية على Hardware متاحة. تسمح البنية بدمج Queues وDevices وBuffers؛ ويمكن أن تستخدم Functional Clusters أخرى API أيضًا SWS SHWA §7.1 «The Architecture of Safe Hardware Acceleration».

البيانات والوصول والذاكرة

يدير Buffer تخصيص الذاكرة، بينما يعبّر Accessor عن وصول القراءة/الكتابة المطبّع. توفر Access Modes والارتباط بـ TaskHandler لنظام وقت التشغيل معلومات عن حركة البيانات والمزامنة SWS SHWA §7.3 «Data Access Specifics» SWS SHWA §7.5 «Memory Allocation Specifics». ويجمع مستند EXP المرافق Buffer وAccessor وRange وId بوصفها حفظًا للبيانات وإدارتها EXP Safe Hardware Acceleration API §4.3.1.

اختيار الجهاز والتنفيذ والمزامنة

يمثل Device جهاز حوسبة؛ وتختار فئات Selector أجهزة CPU أو GPU أو Accelerator استنادًا إلى التقييمات. تمرر Queue المهام، ويدعم Event التبعيات أو عمليات الانتظار عند تنفيذ غير مرتب SWS SHWA §7.4 «Device Specifics» SWS SHWA §7.6 «Task Queuing And Ordering Specifics».

تفسير: يتكون مسار تطبيق متين عادةً من اختيار جهاز، وإنشاء Queue/ErrorHandler، وإنشاء Buffer/Accessor، وTask Submission، ومزامنة ملائمة قائمة على Event أو Timeout. يلخص هذا الترتيب المفاهيم الفردية الموصوفة.

الأمن والأخطاء والتزامن

API استثنائي. استخدم عمليات قابلة للخطأ ara::core::Result، بينما تسمح أساليب المصنع بنقل الأخطاء أثناء إنشاء الكائن. يتم توفير ErrorHandler غير المتزامن لأخطاء التنفيذ على Device؛ يدعم DeviceMonitor مراقبة صحة الجهاز SWS SHWA §7.2 «General Features» SWS SHWA §7.2.5.3–7.2.5.4. تظل كائنات SHWA مقتصرة على عملية واحدة؛ وفقًا للمواصفات، فإن الكتابة المتزامنة Accessor::Set تصل إلى نفس Buffer تؤدي إلى kResourceBusy SWS SHWA §7.2.2 «Parallel Access».

سياق الطلب

وتدعو وثيقة المتطلبات الأساسية إلى إجراء حسابات متوازية آمنة وفعالة، واكتشاف/معالجة الأخطاء ومراقبة حالات التسريع RS Safe Hardware Acceleration §4.1. كما يتطلب أيضًا مراقبة Device وحظرًا يمكن التحكم فيه بالوقت ومعالجة كائنات SHWA محلية RS_SHWA_00004 RS_SHWA_00005 RS_SHWA_00011.
