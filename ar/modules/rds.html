يتيح النقل عالي الأداء والخالي من التسلسل لتدفقات البيانات الخام غير المهيكلة لـ IP وIEEE-1722.

تُستخدم المجموعة التكيفية Raw Data Stream (RDS) لنقل تدفقات البيانات غير المهيكلة بالإضافة إلى بيانات الحساسات والوسائط المتعددة الحساسة للوقت، مع تحسين زمن الوصول ومعدل النقل، وذلك عبر تجاوز الأعباء العامة الإضافية للتسلسل الموجه نحو الخدمة AUTOSAR_AP_EXP_SWArchitecture ص. 74. وتوفر واجهات برمجة تطبيقات C++ لتدفقات البايتات نقطة لنقطة القائمة على IP (TCP/UDP) وكذلك للبث على Layer-2 وفقاً لمعيار AVTP الخاص بـ IEEE 1722 [SWS_RDS_10482]، [SWS_RDS_90312]. يعمل كلا شكلي الاتصال حصرياً عبر دوال مصنعية ثابتة، ويبلغان عن الأخطاء باستهلاك اقتصادي للموارد عبر بنية Result الممتدة عبر المنصة [SWS_RDS_12367].

توفر المجموعة الوظيفية Raw Data Stream (RDS) واجهات عالية الأداء لنقل تدفقات البايتات غير المنسقة وبيانات الحساسات الحساسة للوقت لصالح AUTOSAR Adaptive Platform AUTOSAR_AP_EXP_SWArchitecture ص. 73. من خلال التجريد المباشر لمقابس شبكة POSIX وواجهات شبكة Layer-2 Ethernet، يتجاوز RDS عمليات التسلسل المعقدة للاتصال الموجه نحو الخدمة القياسي (ara::com) AUTOSAR_AP_EXP_SWArchitecture ص. 74.

بالنسبة لتدفقات البايتات القائمة على IP عبر TCP أو UDP، تستخدم التطبيقات الفئتين RawDataStreamClient وRawDataStreamServer، واللتين تُربطان بالمنافذ المصممة عبر دوال Create ثابتة [SWS_RDS_10482]، [SWS_RDS_11312]. بعد إنشاء الاتصال عبر Connect أو WaitForConnection، يُجرى تبادل كميات البيانات دون نسخ غير ضرورية للذاكرة بواسطة std::unique_ptr<ara::core::Byte[]> عبر ReadData وWriteData [SWS_RDS_10486]، [SWS_RDS_10487]، [SWS_RDS_11301].

مخطط تسلسلي: إنشاء الاتصال، وتبادل البيانات، والإنهاء في تدفقات Raw Data Stream القائمة على IP. المصادر: [SWS_RDS_10482]، [SWS_RDS_10484]، [SWS_RDS_10486]، [SWS_RDS_11312]، [SWS_RDS_11318]، [SWS_RDS_11322]

بالنسبة لتدفقات البيانات الحتمية في الوقت الفعلي من الكاميرات أو مصادر الصوت، يُنفذ RDS فئات متوافقة مع IEEE 1722 (AVTP) مثل IEEE1722RawDataStreamProducer وIEEE1722RawDataStreamConsumer [SWS_RDS_90312]، [SWS_RDS_90323]. وتغلف فئات الأنواع الفرعية المحددة مثل RVF (فيديو)، وAAF (صوت)، وCRF (مرجع الساعة) ترويسات الإطارات المتوافقة مع المعايير والبيانات المفيدة [SWS_RDS_90262]، [SWS_RDS_90276]، [SWS_RDS_90295].

يُشار إلى الأخطاء بشكل متوافق مع المنصة دون استثناءات C++ عبر ara::core::Result ومجال الخطأ RdsErrorDomain برموز أخطاء محددة (RdsErrc) [SWS_RDS_11298]، [SWS_RDS_12367]. وفي بيان AUTOSAR، يُربط تعريف الواجهة بسلاسة بنقاط نهاية Ethernet عبر RawDataStreamClientMapping وRawDataStreamServerMapping AUTOSAR_AP_TPS_ManifestSpecification ص. 851.

التصنيف المعماري وحدود النظام

توفر المجموعة الوظيفية Raw Data Stream (RDS) في AUTOSAR Adaptive Platform واجهات برمجة تطبيقات قياسية (APIs) للنقل عالي الأداء لتدفقات البيانات غير المهيكلة أو الحساسة للوقت الفعلي AUTOSAR_AP_EXP_SWArchitecture ص. 73. وعلى عكس الاتصال الموجه نحو الخدمة والمحدد الأنواع بدقة عبر ServiceInterfaces (مثل SOME/IP أو DDS)، يتجاوز RDS بالكامل العبء الإضافي للبروتوكول والتسلسل الخاص بـ ara::com AUTOSAR_AP_EXP_SWArchitecture ص. 74. ويتيح ذلك ربط أجهزة الاستشعار عريضة النطاق مثل كاميرات الفيديو، أو حساسات الرادار، أو LiDAR، أو أنظمة الصوت مباشرةً بـ Adaptive Applications في الوقت الفعلي مع تحسين معدل النقل AUTOSAR_AP_EXP_SWArchitecture ص. 61.

معمارياً، ينقسم المودول إلى ركيزتي اتصال أساسيتين: من جهة، نقل تدفق البايتات القائم على IP عبر بروتوكولات النقل مثل TCP أو UDP مع تغليف مقابس POSIX وحماية اختيارية بـ TLS/IPsec AUTOSAR_SWS_CommunicationManagement ص. 58. ومن جهة أخرى، يوفر المودول نظاماً فرعياً مخصصاً للبث على Layer-2 وفقاً لمعيار IEEE 1722 (بروتوكول نقل الصوت والفيديو، AVTP) عبر شبكات Ethernet وشبكات Time-Sensitive Networking (TSN) AUTOSAR_AP_EXP_SWArchitecture ص. 74. ويجرّد كلا شكلي الاتصال هياكل الشبكة والمخازن المؤقتة الخاصة بالنظام خلف فئات C++ موحدة في نطاق الأسماء ara::rds AUTOSAR_AP_SWS_RawDataStream ص. 39.

إنشاء النسخ وإدارة الاتصال

يتم إنشاء نقاط نهاية الاتصال في RDS حصرياً عبر دوال مصنعية ثابتة مرتبطة بنسخ المنافذ المصممة [SWS_RDS_10482]. بالنسبة لتدفقات البايتات القائمة على IP، تُغلف الفئتان ara::rds::RawDataStreamClient وara::rds::RawDataStreamServer أدوار المبتدئ والمستمع AUTOSAR_AP_EXP_SWArchitecture ص. 73. يُنشئ المصنع RawDataStreamClient::Create نقطة نهاية عميل لمنفذ محدد في البيان بطريقة آمنة بالنسبة للخيوط (thread-safe) عبر ara::core::InstanceSpecifier [SWS_RDS_10482]. وبالمثل، يُنشئ RawDataStreamServer::Create نسخة نقطة نهاية الخادم المقابلة [SWS_RDS_11312]. تمنع كلتا الفئتين منشئات النسخ وتعيينات النسخ، ولكنهما تدعمان صراحةً دلالات النقل (move semantics) لتحقيق ملكية واضحة للموارد [SWS_RDS_11303]، [SWS_RDS_11305]، [SWS_RDS_11316]، [SWS_RDS_11314].

بعد التهيئة الناجحة، ينتظر الخادم عبر WaitForConnection بشكل مانع (blocking) أو بمهلة زمنية محددة وصول الاتصالات الواردة [SWS_RDS_11318]، [SWS_RDS_11319]. ومن جانبه، يؤسس العميل الاتصال بنشاط عبر Connect، إما بشكل غير محدود أو خلال فترة زمنية بالمللي ثانية [SWS_RDS_10484]، [SWS_RDS_11307]. ويتم إنهاء الجلسة النشطة إما بشكل حتمي عبر استدعاء Shutdown [SWS_RDS_10485]، [SWS_RDS_11320] أو ضمنياً في سياق استدعاء الهدام، والذي يغلق الاتصال الذي لا يزال مفتوحاً ويحرره تلقائياً [SWS_RDS_10483]، [SWS_RDS_11313].

تبادل بيانات IP غير المهيكلة عبر المقابس

صُمم نقل البيانات لاتصالات IP ليكون ثنائي الاتجاه ويتم عبر عمليات قابلة للتنفيذ المتزامن مع مراقبة اختيارية للمهلة الزمنية [SWS_RDS_10486]، [SWS_RDS_11309]. على جانب الاستقبال، تُرجع العملية ReadData بنية بيانات من النوع ara::rds::ReadDataResult [SWS_RDS_10486]، [SWS_RDS_11322]. وتُغلّف هذه البنية البيانات الثنائية المقروءة في شكل مؤشر ذكي data (std::unique_ptr<ara::core::Byte[]>) وتشير عبر الحقل numberOfBytes إلى العدد الفعلي للبايتات المستلمة [SWS_RDS_11301]، [SWS_RDS_11302]. ومن خلال نقل ملكية المخزن المؤقت هذا، يتم تجنب عمليات نسخ الذاكرة غير الضرورية.

لإرسال البيانات الثنائية، تمرر التطبيقات المخزن المؤقت للبايتات أيضًا بواسطة دلالات النقل عبر std::unique_ptr<ara::core::Byte[]> وتحدد الطول الأقصى maxLength في WriteData [SWS_RDS_10487]، [SWS_RDS_11324]. وفي مسارات الشبكة الحساسة للزمن الانتقالي أو المعرضة لخطر الحظر، تتوفر متغيرات محملة بشكل زائد من ReadData وWriteData مع تحديد صريح للمهلة الزمنية بالمللي ثانية [SWS_RDS_11310]، [SWS_RDS_11323]، [SWS_RDS_11325]. يتيح ذلك التعامل بشكل حتمي مع الأطراف المقابلة المتخلفة عن الاستجابة أو المخازن المؤقتة للشبكة المتعطلة AUTOSAR_AP_EXP_InterfacesGuidelines ص. 41.

البث المباشر القريب من الوقت الفعلي باستخدام IEEE 1722 (AVTP)

بالنسبة لتدفقات الوسائط المتعددة والمستشعرات المتزامنة والحتمية، يوفر RDS فئات قوالب متخصصة للمستهلكين والمنتجين وفقًا للمعيار IEEE 1722 [SWS_RDS_90312]، [SWS_RDS_90323]. تعمل الفئة ara::rds::IEEE1722RawDataStreamConsumer<T> كمصب للبيانات ويتم إنشاء مثيل لها عبر Create [SWS_RDS_90312]. ومن خلال Connect ترتبط بالتدفق المخصص (مع تصفية Multicast-MAC وVLAN ومعرّف التدفق) AUTOSAR_AP_EXP_SWArchitecture ص. 203، لقراءة ما يصل إلى maxNumberOfDatagrams من مخططات البيانات المنظمة كـ std::vector<T> لاحقًا عبر ReadData [SWS_RDS_90319]، [SWS_RDS_90321]. وبالمثل، تتولى ara::rds::IEEE1722RawDataStreamProducer<T> توليد وإرسال أطر AVTP عبر WriteData(std::vector<T>) [SWS_RDS_90323]، [SWS_RDS_90330]، [SWS_RDS_90332].

تشكل أنواع مخططات البيانات تسلسلًا هرميًا قياسيًا للوراثة الموجهة للكائنات AUTOSAR_AP_SWS_RawDataStream ص. 39. أساس جميع الأطر هو IEEE1722Datagram مع حقل بيانات الحمولة data ومواصفة الطول stream_data_length [SWS_RDS_90226]، [SWS_RDS_90227]، [SWS_RDS_90228]. ومنه تغلف الفئة المشتقة IEEE1722DatagramAVTPDUCommonHeaderFields معلومات الترويسة العامة مثل avtpStreamDataSubtype، headerSpecific والبروتوكول version [SWS_RDS_90230]، [SWS_RDS_90231]، [SWS_RDS_90232]، متبوعة بـ IEEE1722DatagramAVTPDUCommonStreamHeaderFields مع الطوابع الزمنية (avtp_timestamp)، وتحديد التدفق (unique_id، mac_address)، وأرقام تسلسل الحزم (sequenceNum) [SWS_RDS_90235]، [SWS_RDS_90237]، [SWS_RDS_90240].

بناءً على هذا الأساس المشترك، تستند تخصيصات الأنواع الفرعية المحددة:\nIEEE1722DatagramRVF لبيانات الفيديو الخام مع معلمات البكسل ومعدل تحديث الإطارات ومعلومات الأسطر (pixel_format، pixel_depth، frame_rate، colorspace، total_lines) [SWS_RDS_90276]، [SWS_RDS_90278]، [SWS_RDS_90285]، [SWS_RDS_90286]، [SWS_RDS_90287]؛\nIEEE1722DatagramAAF لتنسيقات الصوت مثل PCM أو AES3 (channels_per_frame، bit_depth، aes3_data_type_h) [SWS_RDS_90262]، [SWS_RDS_90266]، [SWS_RDS_90267]، [SWS_RDS_90270]؛\nIEEE1722DatagramCRF لمزامنة الساعة ونقل إشارة الساعة عبر TSN (base_frequency، timestamp_interval، pull) [SWS_RDS_90295]، [SWS_RDS_90297]، [SWS_RDS_90302]، [SWS_RDS_90303]؛\nبالإضافة إلى IEEE1722Datagram61883_IIDC لعمليات نقل الكاميرات الصناعية [SWS_RDS_90245]، [SWS_RDS_90260] وIEEE1722DatagramNTSCF لتنسيقات التحكم غير الحساسة للوقت [SWS_RDS_90306]، [SWS_RDS_90310].

التصرف في حالة الخطأ

تتبع معالجة الأخطاء في RDS نهج تقييم الأخطاء لـ AUTOSAR Adaptive Platform عبر ara::core::Result وara::core::ErrorCode [SWS_RDS_10484]، [SWS_RDS_11299]. تم الإعلان عن جميع طرق API التي يحتمل أن تفشل - بما في ذلك Create، Connect، WaitForConnection، ReadData وWriteData - على أنها noexcept وتبلغ عن رموز الخطأ عبر نوع الإرجاع ara::core::Result [SWS_RDS_10482]، [SWS_RDS_10484]، [SWS_RDS_11318]. وتتم إدارة حالات الخطأ الخاصة بالوحدة في التعداد ara::rds::RdsErrc [SWS_RDS_12367]، والذي يمكن الرجوع إليه عبر الاسم المستعار للنوع ara::rds::RdsErrorDomain::Errc [SWS_RDS_11326].

تحدد الوحدة لهذا الغرض نطاق الخطأ RdsErrorDomain، الذي يتم استرداد مثيله عبر GetRdsErrorDomain() [SWS_RDS_11298]. يتم حذف الإنشاء الافتراضي لـ RdsErrorDomain بشكل صريح [SWS_RDS_11294]. يمكن قراءة أوصاف الأخطاء واسم النطاق عبر الطرق الافتراضية Message(CodeType) وName() [SWS_RDS_11295]، [SWS_RDS_11296]. تتيح دالة المصنع MakeErrorCode إنشاء كائنات خطأ ذات نوع محدد من رمز RdsErrc وبيانات إضافية [SWS_RDS_11299]. وبالنسبة للبيئات التي يتم فيها تمكين استثناءات C++، توفر الوحدة الاستثناء ara::rds::RdsException [SWS_RDS_11292]، [SWS_RDS_11327]، والذي يمكن إطلاقه عبر RdsErrorDomain::ThrowAsException [SWS_RDS_11297].
