Stellt einen sequenziellen Container mit fester Größe und typsicherer Bereichsprüfung für AUTOSAR Adaptive bereit.

Die Template-Klasse ara::core::Array dient als sequenzieller Festgrößen-Container für Elemente des Typs T und adaptiert das Verhalten von std::array für AUTOSAR Adaptive Platform Anwendungen. Aufrufer initialisieren den Container mit fester Elementanzahl, manipulieren Inhalte über Methoden wie fill() und greifen wahlweise ungeprüft über operator[] oder bereichsgeprüft über at() zu [SWS_CORE_01273]. Als sicherheitsrelevante Randbedingung löst eine Bereichsüberschreitung bei at() die spezifische Verletzung IsoStdOutOfRangeViolation anstelle von std::out_of_range aus, während Aufrufe von front() oder back() auf leeren Instanzen bereits zur Übersetzungszeit fehlschlagen [SWS_CORE_01267].

Kontext

Die Template-Klasse ara::core::Array kapselt einen sequenziellen Container mit statisch zur Übersetzungszeit festgelegter Größe N für Elemente des Typs T. Sie implementiert den standardisierten Typ std::array im Modul core der AUTOSAR Adaptive Platform und stellt eine typsichere Abstraktion für zusammenhängende Speicherblöcke dar. Durch die Bereitstellung standardisierter Typ-Aliase wie value_type ([SWS_CORE_01216]), size_type ([SWS_CORE_01214]), difference_type ([SWS_CORE_01215]) sowie Zeigertypen ([SWS_CORE_01217], [SWS_CORE_01218]) und Referenztypen ([SWS_CORE_01210], [SWS_CORE_01211]) fungiert die Klasse als interoperabler Interaktionspartner für generische C++-Algorithmen und plattforminterne Datenflüsse.

Lebenszyklus

Die Erzeugung und Vernichtung einer Array-Instanz folgt den standardmäßigen Regeln für Aggregat- und Werttypen: Die implizit deklarierten speziellen Memberfunktionen des ISO-C++-Standards werden verwendet und nicht gesondert re-deklariert. Das Array besitzt seine Elemente direkt inline im selben Speicherbereich. Die Lebensdauer der enthaltenen Elemente ist folglich untrennbar an die Lebensdauer des umschließenden Array-Objekts gekoppelt; es findet vermutlich keine dynamische Allokation auf dem Freispeicher (Heap) statt, was für deterministisches Zeit- und Speicherverhalten sorgt. Question Q-945fdce67844d6a6 (open)

Der Container befindet sich stets in einem gültigen Zustand und verwaltet exakt N Elemente. Ob das Array Elemente aufnehmen kann oder als Sonderfall mit N = 0 vorliegt, lässt sich über empty() ([SWS_CORE_01264]), size() ([SWS_CORE_01262]) sowie max_size() ([SWS_CORE_01263]) evaluieren. Bezüglich der Nebenläufigkeit dürfte gelten, dass nebenläufige lesende Zugriffe ohne Synchronisation sicher sind, während parallele schreibende Modifikationen einer externen Koordinierung durch den Aufrufer bedürfen. Question Q-7abd5842b7560a04 (open)

Nutzungspfad

In typischen Anwendungsfällen durchläuft ara::core::Array eine Abfolge von Initialisierung, Elementbefüllung, wahlfreiem oder sequentiellem Zugriff sowie gegebenenfalls Inhaltsaustausch:

  • Initialisierung und Befüllung: Der gesamte Datenpuffer kann über fill() ([SWS_CORE_01241]) einheitlich mit einem vorgegebenen Wert belegt werden.
  • Wahlfreier Zugriff: Für performante Zugriffe steht der unüberprüfte Indexoperator operator[] ([SWS_CORE_01265], [SWS_CORE_01266]) zur Verfügung. Wenn eine Bereichsüberprüfung erforderlich ist, wird at() ([SWS_CORE_01273], [SWS_CORE_01274]) herangezogen.
  • Randelemente: Der direkte Zugriff auf das erste und letzte Element erfolgt über front() ([SWS_CORE_01267], [SWS_CORE_01268]) und back() ([SWS_CORE_01269], [SWS_CORE_01270]).
  • Iteration: Das Durchlaufen des Containers erfolgt vorwärts über begin() und end() ([SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]) oder über konstante Iteratoren wie cbegin() und cend() ([SWS_CORE_01258], [SWS_CORE_01259]). Die Iteratortypen sind als elementare Zeiger T* bzw. const T* definiert ([SWS_CORE_01212], [SWS_CORE_01213]). Für umgekehrte Traversierungen stehen rbegin(), rend(), crbegin() und crend() bereit ([SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261], [SWS_CORE_01219], [SWS_CORE_01220]).
  • Zeigerzugriff und Austausch: Der zugrundeliegende Speicherbereich kann über data() ([SWS_CORE_01271], [SWS_CORE_01272]) als Zeiger übergeben werden. Zwei gleich dimensionierte Arrays lassen sich mittels swap() ([SWS_CORE_01242]) austauschen.

Fehlerszenarien

Die Spezifikation definiert strenge Vor- und Nachbedingungen für Grenz- und Fehlersituationen:

  • Bereichsverletzung bei indiziertem Zugriff: Wenn bei at() der Index n außerhalb der Array-Grenzen liegt (n >= size()), wird IsoStdOutOfRangeViolation ausgelöst anstelle der C++-Standard-Ausnahme std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]). Beide Überladungen sind mit noexcept deklariert.
  • Zugriff auf leere Instanzen: Das Aufrufen von front() oder back() auf einem leeren Array (empty() == true, also N = 0) führt verpflichtend zu einem Übersetzungszeitfehler (Compile-Time Error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
  • Undefiniertes Verhalten bei Iteratoren: Das Dereferenzieren des von begin() zurückgegebenen Iterators auf einem leeren Array stellt undefiniertes Verhalten dar ([SWS_CORE_01250], [SWS_CORE_01251]).
  • Sonderfall Zeigerabruf: Ist die Größe des Arrays 0, liefert die Elementfunktion data() zwingend nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
  • Bedingte Ausnahme-Sicherheit: Die Operation swap() ist nur dann noexcept, wenn die typbezogene Bedingung ara::core::is_nothrow_swappable<T>::value erfüllt ist ([SWS_CORE_01242]). Entsprechend bestimmt sich die noexcept-Eigenschaft von fill() über std::is_nothrow_copy_assignable<T>::value ([SWS_CORE_01241]).
