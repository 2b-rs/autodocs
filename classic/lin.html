AUTOSAR Classic LIN

Das LIN-Cluster umfasst Low-Cost-Subbus-Kommunikation für Karosserie- und Komfortfunktionen inklusive Treiber, LinIf-Schedule-Tabellen-Handling, Transceiver-Steuerung und State-Management.

Architektur und Rollenverteilung im LIN-Cluster

Das AUTOSAR Classic LIN-Cluster implementiert den standardisierten Kommunikations-Stack für Local Interconnect Networks (LIN 2.1 / 2.2 / ISO 17987) als kostenoptimiertes Subbus-System im Fahrzeug. Gemäß dem AUTOSAR-Schichtenarchitekturkonzept gliedert sich das Cluster in vier komplementäre Basissoftware-Module (BSW):

  • LIN State Manager (LinSM, BSW ID 141): Verwaltet die Netzwerkzustände der zugewiesenen LIN-Kanäle und fungiert als Bindeglied zum Communication Manager (ComM) [SWS_ComM_00135] sowie zum BSW Mode Manager (BswM).
  • LIN Interface (LinIf, BSW ID 62): Zentrales Kernmodul des Clusters. Es steuert und schaltet Schedule-Tabellen für Master-Knoten [SWS_LinIf_00197], wickelt sporadische und ereignisgesteuerte Frames mit dem PDU Router (PduR) ab [SWS_LinIf_00201] und bindet den Transport Layer (LinTp) ein [SWS_LinIf_00351].
  • LIN Driver (Lin, BSW ID 82): Bildet die hardwarenahe Microcontroller Abstraction Layer (MCAL). Er steuert die on-chip LIN-Controller/UARTs, führt die Frame-Ausgabe aus [SWS_Lin_00190] und validiert externe Wakeup-Impulse auf Busebene [SWS_Lin_00098].
  • LIN Transceiver Driver (LinTrcv, BSW ID 64): Steuert physikalische Busteilnehmer-Schaltkreise (Transceiver) und schaltet Betriebsmodi (NORMAL, SLEEP, STANDBY) synchron auf Anforderung des LinIf [SWS_LinTrcv_00015].

Schedule-Abarbeitung, JIT-Routing und Frame-Transmission

Im LIN-Master-Betrieb basiert die Buskommunikation auf zeitgesteuerten TDMA-Schedule-Tabellen:

  • Schedule-Umschaltung: Auf Anforderung des LinSM schaltet das LinIf zur Laufzeit zwischen verschiedenen Schedule-Tabellen (z. B. Normalbetrieb, Diagnose oder Initialisierung) um [SWS_LinIf_00202]. Der LinSM delegiert Schedule-Anforderungen unmittelbar bei Aufruf von LinSM_ScheduleRequest an LinIf_ScheduleRequest weiter, ohne auf den nächsten Main-Function-Zyklus zu warten [SWS_LinSM_00079].
  • Just-in-Time (JIT) Datenabruf: Um Latenzen und Datenalter zu minimieren, fordert das LinIf Sendedaten (I-PDUs) erst unmittelbar vor dem jeweiligen Sende-Slot über die TriggerTransmit-Schnittstelle (<User_TriggerTransmit>) aus dem PDU Router an [SWS_LinIf_00528].
  • Rückmeldekette: Nach erfolgreichem Frame-Versand durch den LIN-Treiber bestätigt das LinIf die Übertragung über PduR_LinIfTxConfirmation gegenüber dem PDU Router [SWS_LinIf_00529].

Netzwerk-Zustandsmanagement, Sleep-Übergang und Wakeup-Validierung

Das Zusammenspiel bei Energiemanagement und Busruhe ist im Cluster strikt hierarchisch geordnet:

  • Go-to-Sleep-Kaskade: Fordert der ComM den Modus COMM_NO_COMMUNICATION an, ruft der LinSM synchron LinIf_GotoSleep auf [SWS_LinSM_00036]. Das LinIf setzt das Go-to-Sleep-Kommando auf dem Bus ab [SWS_LinIf_00204], instruiert den Treiber via Lin_GoToSleep und versetzt Transceiver in den Low-Power-Modus via LinIf_SetTrcvMode [SWS_LinIf_00544].
  • Wakeup-Erkennung & Signal-Validierung: Wird ein Bus-Aufweckimpuls detektiert, informiert der Transceiver den ECU State Manager (EcuM). Der EcuM stößt die Prüfung über LinIf_CheckWakeup an [SWS_LinIf_00378]; das LinIf bindet den LIN-Treiber via Lin_CheckWakeup ein, welcher das Wakeup-Signal hardwareseitig verbindlich validiert [SWS_Lin_00098].

Diagnosekommunikation und Transport Layer (LinTp nach ISO 17987)

Für Diagnose (UDS) und segmentierte Datenübertragungen enthält das LIN Interface das Untermodul LinTp. Es implementiert das LIN-Transportprotokoll gemäß ISO 17987 und wickelt Mehrebenen-PDU-Transfers zwischen dem Diagnostic Communication Manager (Dcm) und den LIN-Slaves über spezialisierte Diagnose-Schedule-Tabellen ab [SWS_LinIf_00351].

</ul>
