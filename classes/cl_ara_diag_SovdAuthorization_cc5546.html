Verwendungszweck

SovdAuthorization implementiert die SOVD-Autorisierung auf Anwendungsebene. GetAuthorizationUrl() und GetTokenUrl() liefern die URL für Autorisierung beziehungsweise Token-Anforderung; der DM antwortet darauf mit HTTP 307 und einem Location-Header mit dieser URL. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] ValidateAuthorization() validiert das Token aus dem HTTP-Authorization-Header und markiert die autorisierten Rollen im übergebenen ClientAuthentication. [SWS_DM_01483] [SWS_DM_01470]

Erzeugung & Lebenszyklus

Der Konstruktor bindet einen PortPrototype der DiagnosticSovdAuthorizationInterface und nimmt den ConcurrencyType entgegen. [SWS_DM_01489] Offer() aktiviert die Weiterleitung, StopOffer() deaktiviert sie wieder. Offer kann kAlreadyOffered oder kConfigurationMismatch liefern. [SWS_DM_01487] [SWS_DM_01486] Der Destruktor ist ausnahmesicher. [SWS_DM_01488]

Einschränkungen & Fehlerbehandlung

Nach Bereitstellung des Futures darf die Anwendung das referenzierte ClientAuthentication-Objekt nicht mehr verwenden. [SWS_DM_01483] Ein erfolgreicher Rückgabewert erlaubt dem DM, Rollen bis validUntil für dasselbe Token als authentifiziert zu behandeln. [SWS_DM_01469] Die Validierung kann kInvalidAccessToken oder kTemporarilyNotAvailable melden. [SWS_DM_01483] URL- und Validierungsoperationen sind abhängig vom ConcurrencyType; Offer und StopOffer sind nicht thread-safe. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01483] [SWS_DM_01487] [SWS_DM_01486]

Der DM prüft eine Autorisierung erneut, wenn der Token nicht mit einem noch gültigen zuvor geprüften Token identisch ist. [SWS_DM_01470] Bei gleichem Token bis validUntil und bei gleicher zurückgelieferter Identität kann er den Client als identisch behandeln. [SWS_DM_01781] [SWS_DM_01782] Die URL-Methoden erhalten die Anfrage-Query-Parameter und MetaInfo und liefern jeweils einen String asynchron zurück. [SWS_DM_01484] [SWS_DM_01485]

SOVD-Zugriffskontext

Die SOVD-Autorisierung verwendet OAuth-Token im Request-Header. Bei einem solchen Request nutzt der Diagnostic Manager SovdAuthorization, um die kodierte Autorisierungsrolle von der Anwendung anzufordern; anhand dieser Rolle entscheidet er über die Berechtigung für die angeforderte SOVD-Operation. This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.

Die virtuelle Methode ValidateAuthorization validiert das von einem SOVD-Client per HTTP-Authorization-Header gesendete Token (token) gemäß dem im System verwendeten Autorisierungsprotokoll; im Fall von OAuth 2.0 entspricht dies der Prüfung durch den Resource Server. Nach Erfüllung des Future darf clientAuthentication von der Anwendung nicht mehr verwendet werden.
