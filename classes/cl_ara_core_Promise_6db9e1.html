Verwendungszweck

ara::core::Promise<T, E> ist die AUTOSAR-Variante von std::promise. Der Fehlertyp muss ara::core::ErrorCode sein. Zusammen mit Future kann die Klasse Werte und Fehler asynchron sowie thread-sicher ohne Ausnahmebehandlung bereitstellen. [SWS_CORE_00340] [SWS_CORE_10800]

Lebenszyklus & Ownership

Kopieren ist unterbunden (=delete), Verschieben ist möglich. Move-Zuweisung und Destruktor geben einen gegebenenfalls bestehenden Shared State auf. [SWS_CORE_00350] [SWS_CORE_00351] [SWS_CORE_00342] [SWS_CORE_00343] [SWS_CORE_00349]

Zusammenspiel mit anderen Klassen

get_future() liefert das zugehörige Future<T,E> mit demselben Shared State; dieser Aufruf ist nur einmal pro Promise erlaubt. set_value(), SetError() und SetResult() machen den Shared State bereit. Einschränkungen & Fehlerbehandlung

Das wiederholte Setzen von Wert, Fehler oder Ergebnis und ein Setter-Aufruf ohne Shared State sind als Violation spezifiziert. [SWS_CORE_13015] [SWS_CORE_13016]

Bereitstellung des asynchronen Ergebnisses

Auf der Skeleton-Seite kann eine Promise einen bereits berechneten Wert bereitstellen oder in einen asynchronen Worker verschoben werden; das zugehörige Future wird an den Aufrufer zurückgegeben. EXP ARAComAPI §5.4.6 „Methods“

Wird ein Application Error erkannt, wird der zugehörige ErrorCode in die Promise gesetzt; der Client kann ihn anschließend über den Future-Pfad als Result verarbeiten. EXP ARAComAPI §4.7 „Error Handling“ EXP ARAComAPI §5.4.6 „Methods“

Vertrag des gemeinsamen Zustands

Die Promise vervollständigt den in Future beobachteten gemeinsamen Zustand. Der relevante Rahmen ist das in Core definierte Future/Promise-Konzept für asynchrone Wert- oder Fehlerergebnisse. SWS Core §7.2 „Error handling“ SWS Core §7.2.5.5 „Future and Promise“

Verhalten im Fehlerfall

Eine Promise kann ihren Shared State nur einmal mit Wert, Fehler oder Result bereitmachen. Ein nachfolgender Aufruf von set_value(), SetError() oder SetResult(), wenn bereits Wert oder Fehler gespeichert sind, ist als promise_already_satisfied-Violation spezifiziert. Ein Setter ohne Shared State ist eine eigene Violation. [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356] [SWS_CORE_13015] [SWS_CORE_13016]

get_future() darf pro Shared State nur einmal aufgerufen werden. Der zweite Aufruf ist als future_already_retrieved-Violation festgelegt; fehlt der Shared State, gilt die no_state-Violation. Diese Fälle sind im API-Vertrag keine über Result rückgemeldeten Anwendungsfehler. [SWS_CORE_00344] [SWS_CORE_13013] [SWS_CORE_13014]

Der Destruktor und die Move-Zuweisung geben einen bestehenden Shared State auf. Wartet die bereits ausgegebene Future-Seite anschließend auf das Ergebnis, liefert ihr GetResult() den Fehler FutureErrc::kBrokenPromise; get() behandelt denselben Zustand exception-basiert. Der vollständige Ablauf einschließlich Setzen eines Fehlers und Timeout ist im Fehlerpfad-Diagramm von Future dargestellt. [SWS_CORE_00343] [SWS_CORE_00349] [SWS_CORE_00336] [SWS_CORE_00326]
