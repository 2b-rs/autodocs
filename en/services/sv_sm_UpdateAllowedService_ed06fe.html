Role and system context of the service interface

The service interface UpdateAllowedService represents a standardized communication interface within the Functional Cluster State Management (SM) of the AUTOSAR Adaptive Platform ([SWS_SM_91025]). The service is provided by the Functional Cluster State Management via a port defined for this purpose ([SWS_SM_91024]). A SMControlApplication acts as a service consumer, which uses this interface to interact directly with the Controller or the StateMachine of State Management (AUTOSAR_AP_SWS_StateManagement §9.2.3 “StateMachine UpdateAllowed service”, AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 “Interfaces for a SMControlApplication”).

In the overall architectural context, UpdateAllowedService belongs to the dedicated interfaces for a SMControlApplication (AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”). The interface forms the link between the high-level control logic of the overall vehicle and the interaction with the Update and Configuration Management (UCM) by defining via the content of the service field whether update sessions are allowed or blocked (AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”, AUTOSAR_AP_SWS_StateManagement §9.2.3 “StateMachine UpdateAllowed service”).

Fields, Methods, and Communication Semantics

The functional definition of UpdateAllowedService focuses entirely on the field UpdateAllowed ([SWS_SM_91108]). Dedicated methods or isolated events are not specified in the service interface ([SWS_SM_91025], [SWS_SM_91108]). The field is of type UpdateAllowedType and implements the complete communication semantics of ara::com, consisting of getter, setter, and notifier ([SWS_SM_91108]).

The three characteristics of the field cover the following tasks:

  • Setter (HasSetter true): Is called by the SMControlApplication to actively determine whether software updates are permitted during runtime system operation or not ([SWS_SM_91108], AUTOSAR_AP_SWS_StateManagement §9.2.3 “StateMachine UpdateAllowed service”).
  • Getter (HasGetter true): Enables the controlling application to read the release status currently stored in State Management ([SWS_SM_91108]).
  • Notifier (HasNotifier true): Informs subscribed consumers asynchronously and in an event-based manner about every status change of the field ([SWS_SM_91108]).

Lifecycle and Session Flows in the Update Process

In practical use, it is intended that the feasibility of an update campaign is fundamentally evaluated in advance at the overall vehicle level, so that the Update and Configuration Management (UCM) does not call the session request RequestUpdateSession without prior synchronization (AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”). However, since an update campaign can encompass multiple adaptive machines and require considerable time, the local circumstances of a machine can change in the meantime (AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”).

For this reason, a call to RequestUpdateSession is required before starting the local update phase (AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”). The Modelled Process, which controls the StateMachine of type Controller in State Management, checks the current value of the field UpdateAllowed during this method call (AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”, AUTOSAR_AP_SWS_StateManagement §9.2.3 “StateMachine UpdateAllowed service”). The decision on granting an update session thus depends directly on the specification previously set via UpdateAllowedService ([SWS_SM_91108]).

Sequence diagram: Interaction between SMControlApplication, State Management, and UCM to allow or reject an update session. Sources: [SWS_SM_91108], [SWS_SM_00630], AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”, AUTOSAR_AP_SWS_StateManagement §9.2.3 “StateMachine UpdateAllowed service”.

Error Handling and Rejection of an Update Session

If the SMControlApplication determines that local conditions do not permit an update, it signals this via the service field ([SWS_SM_91108], AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”). If UpdateAllowed is set to the enumeration value kUpdateNotAllowed, the Modelled Process is strictly required to reject the update request of Update and Configuration Management ([SWS_SM_00630]).

The rejection occurs at the interface level by returning the Application Error kOperationRejected from the method RequestUpdateSession ([SWS_SM_00630]). This ensures that no update can be initiated as long as the higher-level application logic prohibits this via the field UpdateAllowed ([SWS_SM_00630], AUTOSAR_AP_SWS_StateManagement §“Rejection of update session”).
