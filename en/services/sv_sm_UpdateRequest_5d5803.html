Checkpoint before an update change

UpdateRequest connects UCM with the update-relevant states of State Management. UCM first opens a session and then only allows the affected function groups to be prepared, verified or converted for rollback. SWS StateManagement §7.3 “Interaction with UCM” SWS StateManagement §7.7.14 “StateMachine support for UCM”

Session contract

RequestUpdateSession determines entry; parallel sessions are rejected. Within an admitted session, PrepareUpdate, VerifyUpdate, and PrepareRollback map StateMachines to the corresponding states declared in the Manifest. On completion, UCM closes the session with StopUpdateSession. [SWS_SM_00209] [SWS_SM_00206] [SWS_SM_00207] [SWS_SM_00208]

Activity diagram of the update session framed by UpdateRequest. Sources: SWS StateManagement §7.3 “Interaction with UCM”, SWS StateManagement §7.7.14 “StateMachine support for UCM”.

Reset and progress feedback

ResetMachine requests a machine reset, while ResetMachineNotifier informs UCM of changes during and after processing. Both are part of the controlled update process and are not a replacement for the session and preparation sequence. [SWS_SM_91100] [SWS_SM_91106]

Implementation rule

Access control is intended to limit the use of the service to UCM. UCM must calculate the order of affected function groups itself and not execute the prepare/verify/rollback calls at the same time. [SWS_UCM_00260]
