Used for transfer, processing, activation, and monitoring of software packages and software clusters in UCM.

The service interface PackageManagement controls the transfer, processing, and activation of software packages on the AUTOSAR Adaptive Platform [SWS_UCM_00345], [SWS_UCM_00352]. It enables the block-by-block loading of packages, the extraction of software clusters, and their controlled activation in coordination with State Management [SWS_UCM_00346], [SWS_UCM_00352]. In addition, the service provides mechanisms for status monitoring as well as for rolling back and cleaning up session data [SWS_UCM_00353], [SWS_UCM_00361].

1. Role and system context of the service interface

The service interface PackageManagement forms the central interface of Update and Configuration Management (UCM) for managing, transferring, and installing software packages on the AUTOSAR Adaptive Platform [SWS_UCM_00343]. Here, the UCM instance typically acts as a service provider (skeleton), while higher-level update coordinators or diagnostic clients act as service consumers (proxies). For identification, the service provides the unique module instance identifier via the method GetId [SWS_UCM_00343]. During the activation process, UCM interacts closely with State Management, which must release the update session and perform verifications [SWS_UCM_00352].

2. Methods, events, and fields

All methods defined in the service interface operate with synchronous invocation semantics or request-response messages, since Fire & Forget false is specified for all methods [SWS_UCM_00345]. The state field CurrentStatus has a getter and a notifier, allowing clients to subscribe to UCM status changes in an event-driven manner or query them actively [SWS_UCM_00361]. In addition, GetProgress provides detailed progress information on the currently active state of the state machine [SWS_UCM_00360]. For querying the software inventory, GetSwPackages is available for listing available software packages [SWS_UCM_00359], GetSwClusterInfo for installed software clusters in state kPresent [SWS_UCM_00357], GetSwClusterManifestInfo for cluster manifest data [SWS_UCM_00358], and GetSwClusterChangeInfo for pending changes in the states kAdded, kUpdating, or kRemoved [SWS_UCM_00356]. Historical traceability of executed actions is provided via GetHistory with timestamp filters [SWS_UCM_00355].

3. Lifecycle, session flows, and state dependencies

A typical update sequence is divided into transfer, processing, activation, and completion. The package transfer is either initiated by TransferStart, which creates a TransferIdType and negotiates the block size [SWS_UCM_00345], or alternatively registered by RegisterSoftwarePackage by specifying a package URI [SWS_UCM_00344]. In the case of block-by-block transfer, the data blocks are continuously persisted via TransferData with a block counter specified [SWS_UCM_00346] and finalized with TransferExit [SWS_UCM_00347]. Subsequently, ProcessSwPackage extracts the software package [SWS_UCM_00349]. Ongoing processings can be cancelled using Cancel [SWS_UCM_00351] or interrupted and resumed with Suspend and Resume [SWS_UCM_00397], [SWS_UCM_00398]. Transfers that are no longer needed can be removed with DeleteTransfer [SWS_UCM_00348]. With Activate, the extracted software clusters are activated [SWS_UCM_00352], while Finish terminates the processing session and cleans up temporary data [SWS_UCM_00354]. If errors occur, RevertProcessedSwPackages allows rolling back processed packages [SWS_UCM_00350], and Rollback enables restoring the system state prior to package processing [SWS_UCM_00353].

4. Error handling and application errors

The interface methods guard error conditions via specific application errors. In case of calls contrary to the context, methods like Activate, Cancel, Finish, ProcessSwPackage, TransferData, and TransferExit return the error kOperationNotPermitted [SWS_UCM_00346], [SWS_UCM_00347], [SWS_UCM_00349], [SWS_UCM_00352]. Invalid transfer IDs are rejected with kTransferIdInvalid [SWS_UCM_00346], [SWS_UCM_00348], while corrupted block sequences or memory bottlenecks lead to kBlockIncorrect, kBlockSizeIncorrect, kBlockInconsistent, or kMemoryInsufficient [SWS_UCM_00345], [SWS_UCM_00346]. Security and consistency checks raise errors such as kAuthenticationFailed, kPackageInconsistent, kPackageManifestInvalid, and kPackageVersionIncompatible [SWS_UCM_00346], [SWS_UCM_00349]. Removal of the core system is prevented with kSwclRemovalDenied [SWS_UCM_00349]. During activation, kDependencyMissing, kUpdateSessionRejected, or kVerificationFailed signal integration problems with dependencies or State Management [SWS_UCM_00352].
