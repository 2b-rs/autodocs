Context

The class ara::nm::NmErrorDomain defines the official error domain for the functional cluster Network Management (nm) within the AUTOSAR Adaptive Platform [SWS_ANM_01101]. According to the platform-wide error handling model, it derives from the base class ara::core::ErrorDomain and is declared as final, which definitively terminates the inheritance hierarchy at this point [SWS_ANM_01101].

Its primary responsibility is to integrate the error states specific to network management in a typed manner into the uniform error system of AUTOSAR Adaptive. For this purpose, the class provides two central type aliases: Errc references the enumeration NmErrc with the concrete error codes [SWS_ANM_01103], while Exception is bound to the type-specific exception class NmException [SWS_ANM_01104]. The most important interaction partner in the runtime system is ara::core::ErrorCode [SWS_ANM_01108], which encapsulates error values and delegates their textual representation and exception handling to the responsible instance of NmErrorDomain.

Lifecycle

Instantiation takes place via the default constructor NmErrorDomain() [SWS_ANM_01105]. This is defined as noexcept, thus completely precluding exceptions during construction [SWS_ANM_01105]. The specification evidence also explicitly proves that the construction process is thread-safe [SWS_ANM_01105].

Regarding ownership and instance management, an error domain typically acts as an immutable, long-lived descriptor object. In Adaptive applications, the instance of NmErrorDomain is presumably maintained as a process-wide singleton or static reference (interpretation), ensuring consistent access throughout an application's entire runtime.

The class has no mutable internal state and is designed to be stateless. All member functions for querying information such as Name() [SWS_ANM_01106], Message() [SWS_ANM_01107], and the routine ThrowAsException() [SWS_ANM_01108] are declared as const and designated as thread-safe [SWS_ANM_01106], [SWS_ANM_01107], [SWS_ANM_01108]. This enables concurrent access from any number of threads without additional synchronization effort.

Usage Path

In practice, NmErrorDomain is predominantly used indirectly via the error handling pattern of ara::core::Result and ara::core::ErrorCode. If a network management operation fails, the layer generates a corresponding error code and assigns it to the domain.

A typical sequence for error checking and processing is divided into the following steps:

  1. Result check: After an NM call, the application logic receives an error object of type ara::core::ErrorCode that is associated with NmErrorDomain.
  2. Domain identification: To classify the origin of the error, the identifier of the error domain can be queried via Name() [SWS_ANM_01106].
  3. Retrieval of the error message: For logging or diagnostic output, Message() [SWS_ANM_01107] provides a descriptive string for the specific error code.
  4. Exception throwing: If a switch to an exception-based control flow is required in case of an error, ThrowAsException() [SWS_ANM_01108] is called, throwing an exception assigned to the error code.

The following conditions and behaviors are relevant for the individual method calls:

<li><strong>Domain identification:</strong> To classify the origin of the error, the identifier of the error domain can be queried via <code>Name()</code> <a class="spec-record-ref" data-req="SWS_ANM_01106" href="../spec/record.html?id=SWS_ANM_01106">[SWS_ANM_01106]</a>.</li>
<li><strong>Retrieval of the error message:</strong> For logging or diagnostic output, <code>Message()</code> <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a> provides a descriptive string for the specific error code.</li>
<li><strong>Exception throwing:</strong> If a switch to an exception-based control flow is required in case of an error, <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a> is called, throwing an exception assigned to the error code.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The class <code>NmErrorDomain</code> serves as an administrative framework for error codes and exceptions of the module <code>nm</code>. Error situations are represented by the enumeration <code>NmErrc</code>, which is accessed via the type alias <code>Errc</code> <a class="spec-record-ref" data-req="SWS_ANM_01103" href="../spec/record.html?id=SWS_ANM_01103">[SWS_ANM_01103]</a>.</p>
<p>The following conditions and behaviors are relevant for the individual method calls:</p>
<ul>
<li><strong>Name and message query:</strong> The methods <code>Name()</code> <a class="spec-record-ref" data-req="SWS_ANM_01106" href="../spec/record.html?id=SWS_ANM_01106">[SWS_ANM_01106]</a> and <code>Message()</code> <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a> are declared as <code>noexcept</code>. They guarantee that no subsequent exceptions are thrown, even when querying diagnostic information in critical error states. If an unknown numerical error value is passed to <code>Message()</code>, the implementation presumably returns a generic notice or default text (interpretation).</li>
<li><strong>Exception handling:</strong> The method <code>ThrowAsException()</code> is explicitly qualified as <code>noexcept(false)</code> <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. The postcondition of the call is the throwing of the specific exception <code>NmException</code> (referenced via the alias <code>Exception</code> <a class="spec-record-ref" data-req="SWS_ANM_01104" href="../spec/record.html?id=SWS_ANM_01104">[SWS_ANM_01104]</a>), parameterized with the passed <code>ErrorCode</code> <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. If an application calls this method directly or indirectly, a corresponding <code>catch</code> block for <code>NmException</code> or <code>ara::core::Exception</code> must be present to prevent process termination.</li>
</ul>
