Encapsulates the Time Synchronization error domain and maps error codes to descriptive texts and C++ exceptions.

Error domain ara::tsync::TsyncErrorDomain maps textual descriptions to the error codes of Time Synchronization and binds them to the platform's error handling system ([SWS_TS_00906]). It provides methods for identification and message querying and enables the conversion of errors into specific C++ exceptions ([SWS_TS_00908]). All read operations and construction are implemented in a thread-safe manner. When exception support is disabled in the toolchain, throwing exceptions via the domain is not available.

Context

Class ara::tsync::TsyncErrorDomain defines the error domain for the Time Synchronization functional cluster (Time Synchronization, tsync) in the AUTOSAR Adaptive Platform. As a concrete manifestation of the general error domain ara::core::ErrorDomain, it forms the bridge between platform-wide error handling mechanisms and the time-specific error states of the module. It uniquely categorizes error codes of enumeration Errc ([SWS_TS_01266]) and provides textual as well as semantic descriptions for synchronization problems that have occurred. Via the member function Name(), the class provides a fixed string identifier for the domain ([SWS_TS_00906]). Typical interaction partners are the components and interfaces of module tsync that generate errors, the error objects of ara::core, and utilizing applications that query time information and need to analyze or forward erroneous states.

Lifecycle

Instances of the class are initialized via the parameterless constructor TsyncErrorDomain() ([SWS_TS_00905]). The constructor is specified as exception-safe (exception safe) and thread-safe (thread-safe) ([SWS_TS_00905]). Interpretation: In practice, the object is likely to be provided as a long-lived, global instance, since error domains in the AUTOSAR Adaptive Platform are retained for the runtime of the process and have no mutable state data. After instantiation, the object has no mutable lifecycle phases or internal state transitions. All read accesses via Name() ([SWS_TS_00906]) and Message() ([SWS_TS_00907]) are defined as exception-safe and thread-safe, so that the instance can be queried concurrently and without synchronization by multiple threads.

Usage Path

In regular operation, the error domain comes into play as soon as an operation of module tsync fails or an error status is to be evaluated. An error is primarily identified via type alias Errc, which refers to enumeration TsyncErrc ([SWS_TS_01266]). For diagnosis or logging, a software component calls function Message() with the corresponding error code to obtain the associated text message as a constant pointer to a character string ([SWS_TS_00907]). In addition, the identification string of the domain can be determined via Name() ([SWS_TS_00906]).

If an error is to be propagated not as a value but within the scope of classic exception handling, member function ThrowAsException() is used ([SWS_TS_00908]). This call accepts an object of type ara::core::ErrorCode, creates a new instance of type TsyncException from it – also accessible via the class-internal alias Exception ([SWS_TS_01267]) – and throws it as a C++ exception ([SWS_TS_00908]). Error Scenarios

The error spectrum of the domain is represented via enumeration Errc ([SWS_TS_01266]). Error codes are passed to Message(), where the function always returns the associated message in an exception-safe and thread-safe manner ([SWS_TS_00907]). When using ThrowAsException(), the function is by definition considered not exception-safe (not exception safe), as it aborts execution of the normal control flow and throws a C++ exception ([SWS_TS_00908]).

A crucial constraint concerns the compiler and toolchain configuration: If C++ exceptions are disabled during the compilation process, ThrowAsException() does not participate in overload resolution according to platform specifications ([SWS_TS_00908]). In deployment-specific environments without exception support, applications must therefore rely on the value-based return mechanism using result objects and must not call exception generation.
