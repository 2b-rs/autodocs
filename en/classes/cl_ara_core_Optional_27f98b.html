intended use

ara::core::Optional<T> implements std::optional<T> and models a possible existing value. It supports empty construction or nullopt, in-place construction, emplace(), reset(), status queries and value access. [SWS_CORE_01033] [SWS_CORE_01103] [SWS_CORE_01104] [SWS_CORE_01107] [SWS_CORE_01119] [SWS_CORE_01136] [SWS_CORE_01129]

Lifecycle & Ownership

Copy and move construction, assignment and destruction are dependent on the properties of T and noexcept. [SWS_CORE_01105] [SWS_CORE_01106] [SWS_CORE_01114] [SWS_CORE_01115] [SWS_CORE_01112]

Interaction with other classes

The specification requires support for lvalue references through the Optional<T&> specialization. [SWS_CORE_01032]

Limitations & Error handling

The accesses operator*, operator-> and value() are noexcept, but can trigger a IsoStdBadOptionalAccessViolation if a value is missing. has_value() or bool conversion can be used before access. [SWS_CORE_01124] [SWS_CORE_01122] [SWS_CORE_01130] [SWS_CORE_01129] [SWS_CORE_01128]

Optionality in modeled data sets

Optional is not just a general convenience type: Core specifically mentions it for optional record elements of a StdCppImplementationDataType of the STRUCTURE category. Mandatory fields, on the other hand, appear directly with their implementation data type. Alternatively, Optional can express the possible missing return value of a function. SWS Core §7.4 “Core data types” SWS Core §7.4.2 “Data types derived from the C++ standard” SWS LanguageBinding §7.1 “C++ binding for CppImplementationDataTypes”

For Optional<T&>, an assignment follows the rebind behavior: it binds the Optional reference to the new object instead of writing to the originally bound object via the reference. [SWS_CORE_01032] [SWS_CORE_01034]
