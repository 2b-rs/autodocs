Enables the typed transmission of IEEE 1722 data stream datagrams via a configured connection.

The template class ara::rds::IEEE1722RawDataStreamProducer serves in the AUTOSAR Adaptive Platform to send typed data stream datagrams according to the IEEE 1722 standard (AUTOSAR_AP_SWS_RawDataStream, p. 1). Following static creation using Create, the connection is established via Connect, whereupon payload data is transmitted as a vector via WriteData [SWS_RDS_90332]. The class features strict move-only semantics and is not thread-safe for move operations or in the destructor. An explicit invocation of Shutdown or the destruction of the object terminates the connection properly.

Context

The template class ara::rds::IEEE1722RawDataStreamProducer provides the interface for sending typed data stream datagrams according to the IEEE 1722 standard (AUTOSAR_AP_SWS_RawDataStream, p. 1) within the module rds (Raw Data Stream) of the AUTOSAR Adaptive Platform. As a producer component, it encapsulates channel- and protocol-specific connection establishment as well as the transport of payload data across the underlying network.

Addressing and software-side binding to a configured stream instance are performed by passing an ara::core::InstanceSpecifier to the creation method [SWS_RDS_90323]. Primary interaction partners are the using software, which generates data elements of the template type T, and the IEEE 1722 network stack, which physically transports the datagrams. The class definition is included via header #include "ara/rds/raw_data_stream_IEEE1722.h" [SWS_RDS_90323].

Lifecycle

Instantiation of ara::rds::IEEE1722RawDataStreamProducer occurs exclusively via the static factory method Create [SWS_RDS_90323]. The class is subject to strict move-only semantics: The copy constructor [SWS_RDS_90327] and the copy assignment operator [SWS_RDS_90328] are deleted (=delete), thereby preventing resource duplication.

Transferring the instance to other owners is possible via the move constructor [SWS_RDS_90324] and the move assignment operator [SWS_RDS_90326]. Regarding concurrency, move operations and the destructor are declared as not thread-safe [SWS_RDS_90324], [SWS_RDS_90326], [SWS_RDS_90329]; concurrent access from different threads requires external synchronization.

After creation, the producer is initially in the disconnected state. The connection is established via Connect [SWS_RDS_90330]. Termination of the connection occurs either explicitly via Shutdown [SWS_RDS_90331] or automatically upon destruction of the instance: The destructor ~IEEE1722RawDataStreamProducer() ensures that an open connection is shut down [SWS_RDS_90329].

Usage Path

The regular sequence for transmitting IEEE 1722 data streams is divided into the following phases:

  1. Creation: The application instantiates the producer via Create, specifying the instance identifier [SWS_RDS_90323], and takes ownership of the returned instance.
  2. Connection establishment: Before transmitting data, the application calls Connect [SWS_RDS_90330] to open the communication channel.
  3. Data transmission: Datagrams are then passed to the network as a vector of type T using WriteData(std::vector<T> data) [SWS_RDS_90332]. This step can be repeated cyclically or in an event-driven manner.
  4. Connection teardown: After transmissions are complete, Shutdown terminates the connection explicitly [SWS_RDS_90331]. Alternatively, the destructor closes the connection when leaving scope [SWS_RDS_90329].
