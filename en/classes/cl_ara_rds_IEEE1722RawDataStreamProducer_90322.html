Context

The template class ara::rds::IEEE1722RawDataStreamProducer provides the interface for sending typed data packets according to the IEEE 1722 standard in the rds (Raw Data Stream) module of the AUTOSAR Adaptive Platform. Its main responsibility is to act as a data generator (producer) and provide datagrams of an application-specific type via a configured data stream. The addressing and assignment of communication endpoints is carried out via a ara::core::InstanceSpecifier, which is passed during instantiation [SWS_RDS_90323].

Typical interaction partners are the application-side software component, which generates payload data as datagrams, and the underlying communication infrastructure of the Adaptive runtime system. The physical or logical IEEE 1722 data stream is operated via this infrastructure. In this case, the producer acts as a link that encapsulates the application data and feeds it into the stream.

Lifecycle

The creation of instances of class ara::rds::IEEE1722RawDataStreamProducer takes place in a controlled manner via the factory pattern using the static method Create [SWS_RDS_90323]. Since direct constructors are private or restricted, it is ensured that creation succeeds only depending on a valid service instance configuration. Regarding ownership, the caller owns the instance exclusively: Copy constructor [SWS_RDS_90327] and copy assignment operator [SWS_RDS_90328] are deleted (delete), preventing duplication of the stream and its states.

In contrast, the class supports move semantics: Both the move constructor [SWS_RDS_90324] and the move assignment operator [SWS_RDS_90326] are defined as noexcept. They enable the transfer of ownership, for example into containers or asynchronous context transitions. Both move operations are, however, explicitly specified as not thread-safe ([SWS_RDS_90324], [SWS_RDS_90326]), so that concurrent accesses from multiple threads must be prevented by external synchronization.

The lifecycle ends with the destruction of the object by the destructor ~IEEE1722RawDataStreamProducer [SWS_RDS_90329]. This is also marked as not thread-safe. Within the scope of RAII guidelines, the destructor guarantees that a stream connection still open at the time of destruction is shut down automatically and properly [SWS_RDS_90329].

Usage Path

The regular workflow with a IEEE1722RawDataStreamProducer follows a fixed sequence of phases: initialization, connection establishment, cyclic transmission, and connection teardown.

  1. Creation: The application initiates instantiation via Create(instance) with the matching instance identifier [SWS_RDS_90323]. After successful return, the application holds the operational producer instance.
  2. Connection establishment: Before the actual data exchange, the connection to the IEEE 1722 channel is established via the explicit call of Connect() [SWS_RDS_90330].
  3. Data transmission: As soon as the connection is active, the application transmits structured payload data via the method WriteData(std::vector<T>) [SWS_RDS_90332]. This call typically occurs repeatedly within the framework of cyclic application logic or event-driven upon new measurement or streaming data.
  4. Connection teardown: After completion of the data transmission, the connection is terminated in a controlled manner via Shutdown() [SWS_RDS_90331]. An explicit call of Shutdown before destruction is presumably optional, since the destructor automatically disconnects open channels [SWS_RDS_90329], but is recommended for targeted error and state monitoring.

Error Scenarios

In accordance with the error model of the AUTOSAR Adaptive Platform, the interface completely dispenses with C++ exceptions. All methods are declared with noexcept and signal failures via the generic return type ara::core::Result ([SWS_RDS_90323], [SWS_RDS_90330], [SWS_RDS_90331], [SWS_RDS_90332]).

Error situations can occur in various phases:

  • Failure during creation: If Create fails, for example in the case of a faulty InstanceSpecifier or one unknown to the system, the Result object returns a system-specific error code instead of the producer instance [SWS_RDS_90323].
  • Connection error: If Connect() [SWS_RDS_90330] fails (for instance, due to missing network resources or inaccessible interfaces), the producer must not be used for transmission. Prior to calling WriteData, a successful connection via Connect is presumably mandatory.
  • Transmission error: If a buffer overflow or an issue on the network layer occurs during WriteData, the ara::core::Result<void> returns a corresponding error object [SWS_RDS_90332], which must be handled by the application.
  • Shutdown error: Shutdown() [SWS_RDS_90331] also returns a ara::core::Result<void> to report any errors during proper disconnection.

Consequently, the calling component is required to check the result of the ara::core::Result at each step via methods such as HasValue() before proceeding.
