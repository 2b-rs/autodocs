Role in the storage model

FileStorage represents a configured, directory-like set of named files. Files can be preinstalled, created during an update, or created and deleted at runtime. SWS Persistency §7.4 “File Storage specific Features”

From storage to file

After OpenFileStorage, FileExists and GetAllFileNames check the inventory. OpenFileReadOnly, OpenFileWriteOnly and OpenFileReadWrite create the appropriate exclusive accessor; The handling of content is then ReadAccessor, WriteAccessor or ReadWriteAccessor.

Write, lock and reset

An open Accessor binds the file exclusively. Therefore, do not schedule DeleteFile, ResetFile, and RecoverFile in parallel with active access. Resource limits as well as redundant and backup data count toward occupied storage memory. SWS Persistency §7.2.6 “Resource Management Concepts”

Error strategy

Check every Result, particularly for access rights, physical memory, integrity, encryption, authentication, storage space, and resource conflicts. Recovery is not a substitute for a technical consistency check. SWS Persistency §7.2.4 “Redundancy Concepts”

A file storage manages a set of named files; the accessor has exclusive ownership of the specific opened access. Sources: SWS Persistency §7.4 “File Storage specific Features” [SWS_PER_00113].

Recovery is best effort; In the event of an error, a report can name the affected storage or elements. Source: SWS Persistency §7.2.4 “Redundancy Concepts”. Partial interpretation: The activity sequence combines several permitted redundancy procedures.

Precondition and result

OpenFileReadWrite(fileName, mode) opens a file of this storage for reading and writing and can create a missing file. The result contains a UniqueHandle<ReadWriteAccessor>; its lifespan limits the opened access. [SWS_PER_00113]

Recommended order
