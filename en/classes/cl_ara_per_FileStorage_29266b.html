Context

The class ara::per::FileStorage represents a persistent file storage that manages a set of files identified by unique file names. Within the AUTOSAR Adaptive Platform (module per), it forms the central abstraction layer for file-based persistence. The interaction partners include the adaptive application, which requests read and write operations, as well as the access objects created by the storage instance (such as ReadAccessor, WriteAccessor, and ReadWriteAccessor), which are passed encapsulated via ara::core::UniqueHandle. While data transfer takes place decoupled via the respective accessors, FileStorage controls the higher-level management operations such as file creation, integrity checks, recovery, and deletion.

Lifecycle

The lifecycle of an instance of FileStorage is subject to restrictive conditions regarding copy and move operations. The default constructor is explicitly deleted ([SWS_PER_00460]). Likewise, the copy constructor ([SWS_PER_00328]), the copy assignment operator ([SWS_PER_00329]), the move constructor ([SWS_PER_00326]), and the move assignment operator ([SWS_PER_00327]) are declared as =delete. An instance can therefore neither be copied nor moved. The creation of a FileStorage instance is therefore likely performed via external factory functions of the persistence runtime environment (Interpretation: Since no public constructors are present, provisioning is the responsibility of the platform infrastructure).

The destructor ~FileStorage is defined as noexcept, but is explicitly not thread-safe (not thread-safe) ([SWS_PER_00330]). Prior to the destruction of the object, it must therefore be ensured that all concurrent accesses to this instance have terminated. During the regular operating phase, the instance's function calls are thread-safe and exception-safe. In the case of read status queries, however, concurrency effects must be taken into account: Queries such as FileExists ([SWS_PER_00112]) or GetAllFileNames ([SWS_PER_00110]) are only exact if files are not concurrently being created or deleted in another thread. Likewise, GetCurrentFileSize ([SWS_PER_00407]) and GetFileInfo ([SWS_PER_00438]) reflect the current file status accurately only if the file in question is not open or being modified at the time of the query.

Usage Path

A typical usage path includes checking for existence, opening the desired file, accessing it via an RAII handle, and subsequent maintenance:

  1. Determine files and check metadata: Before access, existence can be checked with FileExists ([SWS_PER_00112]) or a list of all files can be obtained using GetAllFileNames ([SWS_PER_00110]). GetCurrentFileSize ([SWS_PER_00407]) and GetFileInfo ([SWS_PER_00438]) provide details on file size and timestamps.
  2. Open file: Three modes are available for opening, each returning a ara::core::Result with a UniqueHandle:
    • Read-only: OpenFileReadOnly opens the file at the beginning ([SWS_PER_00376]), with a specified mode ([SWS_PER_00114]), or with a custom block buffer for performance optimization with many small accesses ([SWS_PER_00430]).
    • Write-only: OpenFileWriteOnly ([SWS_PER_00377], [SWS_PER_00115], [SWS_PER_00431]) truncates the file by default (kTruncate) and creates it automatically if it does not already exist.
    • Read and write: OpenFileReadWrite ([SWS_PER_00375], [SWS_PER_00113], [SWS_PER_00429]) sets the file position to the beginning, creates a missing file, and optionally also supports custom buffers.
  3. Processing and closing: File access is performed via the returned accessor handle. As soon as the UniqueHandle leaves the scope, the file is automatically closed ([SWS_PER_00114]).
  4. Administration: Files that are no longer needed are deleted using DeleteFile ([SWS_PER_00111]). A file can be reset to its delivery state via ResetFile ([SWS_PER_00338]) or restored via RecoverFile ([SWS_PER_00337]) in case of redundancy errors.

Error Scenarios

Method calls report errors via error codes of type PerErrc. Key scenarios and preconditions are:

  • PerErrc::kResourceBusy: Occurs when a file is to be opened ([SWS_PER_00114], [SWS_PER_00113], [SWS_PER_00115]), deleted ([SWS_PER_00111]), recovered ([SWS_PER_00337]), or reset ([SWS_PER_00338]) while it is still open or a recovery, reset, or delete operation is running concurrently on the same file name.
  • PerErrc::kFileNotFound: Occurs when a file name does not exist for read operations ([SWS_PER_00114]), delete operations ([SWS_PER_00111]), size queries ([SWS_PER_00407]), metadata queries ([SWS_PER_00438]), or recoveries ([SWS_PER_00337]). This error does not occur when opening for writing, as missing files are created directly ([SWS_PER_00113], [SWS_PER_00115]).
  • PerErrc::kIllegalWriteAccess: Is returned when write or delete access to read-only storage is attempted or when the file already exists in mode write-only-once ([SWS_PER_00111], [SWS_PER_00113], [SWS_PER_00115]).
  • Resource and quota limitations: If physical storage space is insufficient for new or initialized files, operations fail with PerErrc::kOutOfStorageSpace ([SWS_PER_00113], [SWS_PER_00337], [SWS_PER_00338]). If the configured maximum size is exceeded, PerErrc::kQuotaExceeded is reported ([SWS_PER_00337], [SWS_PER_00338]). If creation exceeds the configured file count maxNumberOfFiles, the call fails with PerErrc::kTooManyFiles ([SWS_PER_00113], [SWS_PER_00338]).
  • PerErrc::kInitValueNotAvailable: Occurs with ResetFile if initial file contents are defined neither in the Application Design nor in the Target Configuration ([SWS_PER_00338]).
  • Hardware and integrity errors: Storage medium failures (PerErrc::kPhysicalStorageFailure), structural integrity violations (PerErrc::kIntegrityCorrupted), validation errors (PerErrc::kValidationFailed), and cryptographic and authentication errors (PerErrc::kEncryptionFailed, PerErrc::kAuthenticationFailed) signal defects or security inconsistencies of the persistent data.

<h4>Context</h4>
<p>The class <code>ara::per::FileStorage</code> represents a persistent file storage that manages a set of files identified by unique file names. Within the AUTOSAR Adaptive Platform (module <code>per</code>), it forms the central abstraction layer for file-based persistence. The interaction partners include the adaptive application, which requests read and write operations, as well as the access objects created by the storage instance (such as <code>ReadAccessor</code>, <code>WriteAccessor</code>, and <code>ReadWriteAccessor</code>), which are passed encapsulated via <code>ara::core::UniqueHandle</code>. While data transfer takes place decoupled via the respective accessors, <code>FileStorage</code> controls the higher-level management operations such as file creation, integrity checks, recovery, and deletion.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>FileStorage</code> is subject to restrictive conditions regarding copy and move operations. The default constructor is explicitly deleted (<a class="spec-record-ref" data-req="SWS_PER_00460" href="../spec/record.html?id=SWS_PER_00460">[SWS_PER_00460]</a>). Likewise, the copy constructor (<a class="spec-record-ref" data-req="SWS_PER_00328" href="../spec/record.html?id=SWS_PER_00328">[SWS_PER_00328]</a>), the copy assignment operator (<a class="spec-record-ref" data-req="SWS_PER_00329" href="../spec/record.html?id=SWS_PER_00329">[SWS_PER_00329]</a>), the move constructor (<a class="spec-record-ref" data-req="SWS_PER_00326" href="../spec/record.html?id=SWS_PER_00326">[SWS_PER_00326]</a>), and the move assignment operator (<a class="spec-record-ref" data-req="SWS_PER_00327" href="../spec/record.html?id=SWS_PER_00327">[SWS_PER_00327]</a>) are declared as <code>=delete</code>. An instance can therefore neither be copied nor moved. The creation of a <code>FileStorage</code> instance is therefore likely performed via external factory functions of the persistence runtime environment (Interpretation: Since no public constructors are present, provisioning is the responsibility of the platform infrastructure).</p>
<p>The destructor <code>~FileStorage</code> is defined as <code>noexcept</code>, but is explicitly not thread-safe (<code>not thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_PER_00330" href="../spec/record.html?id=SWS_PER_00330">[SWS_PER_00330]</a>). Prior to the destruction of the object, it must therefore be ensured that all concurrent accesses to this instance have terminated. During the regular operating phase, the instance's function calls are thread-safe and exception-safe. In the case of read status queries, however, concurrency effects must be taken into account: Queries such as <code>FileExists</code> (<a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a>) or <code>GetAllFileNames</code> (<a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a>) are only exact if files are not concurrently being created or deleted in another thread. Likewise, <code>GetCurrentFileSize</code> (<a class="spec-record-ref" data-req="SWS_PER_00407" href="../spec/record.html?id=SWS_PER_00407">[SWS_PER_00407]</a>) and <code>GetFileInfo</code> (<a class="spec-record-ref" data-req="SWS_PER_00438" href="../spec/record.html?id=SWS_PER_00438">[SWS_PER_00438]</a>) reflect the current file status accurately only if the file in question is not open or being modified at the time of the query.</p>

<h4>Usage Path</h4>
<p>A typical usage path includes checking for existence, opening the desired file, accessing it via an RAII handle, and subsequent maintenance:</p>
<ol>
<li><strong>Determine files and check metadata:</strong> Before access, existence can be checked with <code>FileExists</code> (<a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a>) or a list of all files can be obtained using <code>GetAllFileNames</code> (<a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a>). <code>GetCurrentFileSize</code> (<a class="spec-record-ref" data-req="SWS_PER_00407" href="../spec/record.html?id=SWS_PER_00407">[SWS_PER_00407]</a>) and <code>GetFileInfo</code> (<a class="spec-record-ref" data-req="SWS_PER_00438" href="../spec/record.html?id=SWS_PER_00438">[SWS_PER_00438]</a>) provide details on file size and timestamps.</li>
<li><strong>Open file:</strong> Three modes are available for opening, each returning a <code>ara::core::Result</code> with a <code>UniqueHandle</code>:
<ul>
<li><em>Read-only:</em> <code>OpenFileReadOnly</code> opens the file at the beginning (<a class="spec-record-ref" data-req="SWS_PER_00376" href="../spec/record.html?id=SWS_PER_00376">[SWS_PER_00376]</a>), with a specified mode (<a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>), or with a custom block buffer for performance optimization with many small accesses (<a class="spec-record-ref" data-req="SWS_PER_00430" href="../spec/record.html?id=SWS_PER_00430">[SWS_PER_00430]</a>).</li>
<li><em>Write-only:</em> <code>OpenFileWriteOnly</code> (<a class="spec-record-ref" data-req="SWS_PER_00377" href="../spec/record.html?id=SWS_PER_00377">[SWS_PER_00377]</a>, <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>, <a class="spec-record-ref" data-req="SWS_PER_00431" href="../spec/record.html?id=SWS_PER_00431">[SWS_PER_00431]</a>) truncates the file by default (<code>kTruncate</code>) and creates it automatically if it does not already exist.</li>
<li><em>Read and write:</em> <code>OpenFileReadWrite</code> (<a class="spec-record-ref" data-req="SWS_PER_00375" href="../spec/record.html?id=SWS_PER_00375">[SWS_PER_00375]</a>, <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00429" href="../spec/record.html?id=SWS_PER_00429">[SWS_PER_00429]</a>) sets the file position to the beginning, creates a missing file, and optionally also supports custom buffers.</li>
</ul>
</li>
<li><strong>Processing and closing:</strong> File access is performed via the returned accessor handle. As soon as the <code>UniqueHandle</code> leaves the scope, the file is automatically closed (<a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>).</li>
<li><strong>Administration:</strong> Files that are no longer needed are deleted using <code>DeleteFile</code> (<a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>). A file can be reset to its delivery state via <code>ResetFile</code> (<a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>) or restored via <code>RecoverFile</code> (<a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>) in case of redundancy errors.</li>

<h4>Error Scenarios</h4>
<p>Method calls report errors via error codes of type <code>PerErrc</code>. Key scenarios and preconditions are:</p>
<ul>
<li><code>PerErrc::kResourceBusy</code>: Occurs when a file is to be opened (<a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>, <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>), deleted (<a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>), recovered (<a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>), or reset (<a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>) while it is still open or a recovery, reset, or delete operation is running concurrently on the same file name.</li>
<li><code>PerErrc::kFileNotFound</code>: Occurs when a file name does not exist for read operations (<a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>), delete operations (<a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>), size queries (<a class="spec-record-ref" data-req="SWS_PER_00407" href="../spec/record.html?id=SWS_PER_00407">[SWS_PER_00407]</a>), metadata queries (<a class="spec-record-ref" data-req="SWS_PER_00438" href="../spec/record.html?id=SWS_PER_00438">[SWS_PER_00438]</a>), or recoveries (<a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>). This error does not occur when opening for writing, as missing files are created directly (<a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>).</li>
<li><code>PerErrc::kIllegalWriteAccess</code>: Is returned when write or delete access to read-only storage is attempted or when the file already exists in mode <code>write-only-once</code> (<a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>, <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>).</li>
<li><strong>Resource and quota limitations:</strong> If physical storage space is insufficient for new or initialized files, operations fail with <code>PerErrc::kOutOfStorageSpace</code> (<a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>, <a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>). If the configured maximum size is exceeded, <code>PerErrc::kQuotaExceeded</code> is reported (<a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>, <a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>). If creation exceeds the configured file count <code>maxNumberOfFiles</code>, the call fails with <code>PerErrc::kTooManyFiles</code> (<a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a>, <a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>).</li>
<li><code>PerErrc::kInitValueNotAvailable</code>: Occurs with <code>ResetFile</code> if initial file contents are defined neither in the Application Design nor in the Target Configuration (<a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>).</li>
<li><strong>Hardware and integrity errors:</strong> Storage medium failures (<code>PerErrc::kPhysicalStorageFailure</code>), structural integrity violations (<code>PerErrc::kIntegrityCorrupted</code>), validation errors (<code>PerErrc::kValidationFailed</code>), and cryptographic and authentication errors (<code>PerErrc::kEncryptionFailed</code>, <code>PerErrc::kAuthenticationFailed</code>) signal defects or security inconsistencies of the persistent data.</li>
</ul>
