class ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Writing an open file

WriteAccessor is exclusive write access to a file of a FileStorage. It follows OpenFileWriteOnly and offers text, binary and size operations. SWS Persistency §7.4 “File Storage specific Features”

Persistence limit

WriteText and WriteBinary change the access context. SyncToFile is the targeted step to transfer the current file contents to physical memory; treat its result value as a commit result.

Capacity and ownership

A write operation may fail due to quota, space, or protection processing. Accessor methods are not thread-safe, so the UniqueHandle belongs in a single controlled execution path. SWS Persistency §7.2.6 “Resource Management Concepts”

A file storage manages a set of named files; the accessor has exclusive ownership of the specific opened access. Sources: SWS Persistency §7.4 “File Storage specific Features” [SWS_PER_00113].

ara::core::Result< void > SetFileSize (std::uint64_t size) noexcept;

Reduces the size of the file to ’size’, effectively removing the current content of the file beyond this size. The current file position is unchanged if it is lower than ’size’, or set to the last valid position in the file otherwise. If ’size’ is 0, the current file position will also be set to 0.

Usage AI generated

The ara::per::WriteAccessor::SetFileSize [SWS_PER_00428] method reduces the size of the file to the value specified by size and removes any content beyond it. The current position remains unchanged if it is smaller than size, otherwise it is set to the last valid position, or if size is equal to zero, it is set to zero. The method is not thread-safe, but is exception-safe and returns a ara::core::Result<void>.

Error handling

kInvalidSize is returned if the new size is larger than the current size. Other errors include kPhysicalStorageFailure, kValidationFailed, kEncryptionFailed and kAuthenticationFailed.

              function WriteBinary [SWS_PER_00423] Upstream: RS_PER_00001, RS_PER_00004, RS_AP_00119, RS_AP_00120, RS_ AP_00121, RS_AP_00127, RS_AP_00135, RS_AP_00139, RS_AP_00159
              

              ara::core::Result< void > WriteBinary (ara::core::Span< const ara::core::Byte > b) noexcept;
              

              Writes the content of a Span of Byte to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed. The expected state of the file for each supported error can be expected to be as follows: • kPhysicalStorageFailure: The state of the file is unknown. It could have been entirely destroyed. • kEncryptionFailed: The content of the file and the current position will have been updated, but could not be persisted. The persisted file will reflect an older version of the file. • kOutOfStorageSpace: The content of the file will have been updated, but the part of the operation that exceeded the quota will have been discarded. The current position will be at the end of the file.

In case of error, the file content may be corrupted and the current position may or may not have changed: For kPhysicalStorageFailure, the file state is unknown and the file may be destroyed; for kEncryptionFailed, content and position were updated but not persisted; for kOutOfStorageSpace the content was updated, but the part that exceeded the quota was discarded and the position was set to the end of the file.
