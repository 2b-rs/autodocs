Context

The data structure ara::diag::DoIPEntityIdentification::EntityId is defined in the header ara/diag/doip_entity_identification.h as an embedded type of the interface class ara::diag::DoIPEntityIdentification (SWS Diagnostics §8.33 “Header: ara/diag/doip_entity_identification.h”, [SWS_DM_01362]). Its purpose is to encapsulate and provide the Entity Identification value (EID) standardized in ISO 13400-2:2019 for the DoIP protocol (Diagnostic communication over Internet Protocol). For this purpose, the structure encapsulates the member entityIdentification as a fixed byte array of type ara::core::Array<std::uint8_t, 6> ([SWS_DM_01496]).

In the overall system, essentially three components interact when using EntityId:

  • Adaptive Application (AA): Implements or instantiates the API class ara::diag::DoIPEntityIdentification ([SWS_DM_01364]) to provide the system-specific entity identification. Interpretation: The 6-byte identifier is likely to be typically based on a MAC address or an analogous hardware identification of the DoIP instance in accordance with ISO 13400-2:2019.
  • Diagnostic Management (DM): Acts as the central interaction partner in the Adaptive daemon. If the system is configured to the value DoIpEidRetrievalEnum.eidUseApi via the parameter DoIpNetworkConfiguration.eidRetrieval, the DM actively requests the EID via the method ara::diag::DoIPEntityIdentification::GetEntityId ([SWS_DM_01361], SWS Diagnostics §7.2.1.2).
  • DoIP network / external tester: The peer at the network level to which the DM transmits the received EID within standardized DoIP messages (such as the Vehicle Announcement Message) (SWS Diagnostics §7.2.1.2).

Usage Path

The regular sequence for using EntityId is divided into the following steps:

  1. Configuration check: Based on the data model, Diagnostic Management checks whether retrieving the entity identifier via the interface is configured for the DoIP network (DoIpNetworkConfiguration.eidRetrieval == DoIpEidRetrievalEnum.eidUseApi) ([SWS_DM_01361]).
  2. API call: The DM initiates the retrieval of the EID by calling ara::diag::DoIPEntityIdentification::GetEntityId on the class previously instantiated by the application ([SWS_DM_01361], [SWS_DM_01364]).
  3. Populating the structure: The Adaptive Application initializes the member entityIdentification within the structure EntityId with the 6 bytes of the identifier ([SWS_DM_01496]) and returns the object to the DM as a return value.
  4. Protocol processing: The DM extracts the 6 bytes from EntityId and inserts them into the DoIP protocol messages to be transmitted in order to announce the vehicle or entity on the network (SWS Diagnostics §7.2.1.2).

Error Scenarios

When providing and processing EntityId, the following error conditions and preconditions must be observed:

  • Precondition: Retrieval via the C++ API strictly requires that DoIpNetworkConfiguration.eidRetrieval is configured to eidUseApi ([SWS_DM_01361]). Otherwise, the method GetEntityId is not called by the DM.
  • Interface not provided: If the interface ara::diag::DoIPEntityIdentification is not yet offered at the time of the EID query by the DM or if reading the EID fails ([SWS_DM_01528], SWS Diagnostics §7.2.1.2), a standardized fallback takes effect.
  • Fallback behavior (EID replacement value): In the event of an error, the DM transmits a firmly defined 6-byte replacement value in the DoIP protocol messages, where all bytes are set to 0xFF (0xFF 0xFF 0xFF 0xFF 0xFF 0xFF) ([SWS_DM_01528]).
  • Postcondition: After successful execution, the DM has a complete 6-byte identifier ([SWS_DM_01496]) so that conformant DoIP messages can be generated without resorting to the replacement value.
