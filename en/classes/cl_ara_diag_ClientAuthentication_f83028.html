class ara::diag::ClientAuthentication

[SWS_DM_01132] Upstream: RS_Diag_04251

class ClientAuthentication final {...};

Interface for the application to inform the Diagnostic Server instance about the authentication states and the user roles that are currently authenticated.

Header file#include "ara/diag/client_authentication.h"

intended use

ClientAuthentication allows an application to report the authentication state and user roles of a Diagnostic Client to the Diagnostic Server. An instance is obtained via ExternalAuthentication::Get() for the passed MetaInfo or client address; GetAll() delivers all existing instances. [SWS_DM_01132] [SWS_DM_01202] [SWS_DM_01203]

Interaction with other classes

Authenticate() sets the client to kAuthenticated, takes over the passed roles and returns a ClientAuthenticationHandle. This handle can then set or extend dynamic access lists. Successful authentication resets previously overwritten default roles to the configured default roles. [SWS_DM_01142] [SWS_DM_01206] [SWS_DM_01570]

GetState() reads the current status. In state kDeAuthenticated, OverrideDefaultRoles() can override the default roles for a specified duration and also returns a handle. SetNotifier() registers a function for status changes, for example on an S3 timeout; a subsequent registration replaces the existing one. [SWS_DM_01143] [SWS_DM_01141] [SWS_DM_01209] [SWS_DM_01144] [SWS_DM_01360]

Life Cycle & restrictions

The class is not copyable, but is movable and move-assignable. The destructor is exception-safe. The operations are not thread-safe and may return DiagErrc::kServiceNotAvailable if essential DM functionality is not available. [SWS_DM_01139] [SWS_DM_01140] [SWS_DM_01137] [SWS_DM_01138] [SWS_DM_01136] [SWS_DM_01142] [SWS_DM_01143] [SWS_DM_01141]

function Authenticate [SWS_DM_01142] Upstream: RS_Diag_04251

ara::core::Result< ClientAuthenticationHandle > Authenticate (ara::core::Vector< DiagnosticAuthRole > userRoles) noexcept;

This function is used by the application to report the authenticated state to the Diagnostic Server instance. The authentication could be either done using the Authentication interfaces of the Diagnostic Server instance, or through other means in the application.
