intended use

GenericDiagnosticSovdOperation is the application interface for a generic SOVD diagnostic operation. The Diagnostic Manager (DM) calls StartExecution when an SOVD request is received to start the specified operation; If necessary, the proximity challenge validation must first be successful. [SWS_DM_02203] [SWS_DM_02210] [SWS_DM_02174] The implementation asynchronously provides either a synchronous or an asynchronous start response. For a synchronous response, the DM derives the parameters of the positive SOVD response from the returned DiagnosticSovdContentData. [SWS_DM_02210] [SWS_DM_02176]

Generation & destruction

The instance is created with a InstanceSpecifier for a PortPrototype of DiagnosticDataIdentifierGenericInterface and a ConcurrencyType. Offer() activates the forwarding of requests by the DM, StopOffer() deactivates it again. [SWS_DM_02204] [SWS_DM_02211] [SWS_DM_02212] A new offer will be rejected with DiagOfferErrc::kAlreadyOffered. [SWS_DM_02211]

Lifecycle & Ownership

The interface is movable: Move construction and Move assignment are provided. [SWS_DM_02206] [SWS_DM_02207] The destructor is noexcept, exception-safe and thread-safe. [SWS_DM_02205]

Limitations & Error handling

The data of the sovd_content_data parameter only remains valid until the promise is fulfilled or until an abort message is processed. The CancellationHandler may not be stored or used beyond the lifetime of this operation. Execution errors shall be provided as an applicable SOVD error code. [SWS_DM_02210] Offer() and StopOffer() are not thread-safe; StartExecution is thread-safe. [SWS_DM_02211] [SWS_DM_02212] [SWS_DM_02210]

StartExecution can return a synchronous or asynchronous start response as a variant and is a pure virtual function that must therefore be implemented by the application. [SWS_DM_02210] The constructor itself is exception-safe and thread-safe. [SWS_DM_02204]

SOVD context

For SOVD use cases corresponding to UDS, reusing the same port instance as the corresponding UDS service is a guiding principle; The same rules regarding reentrancy and parallel execution apply. EXP SOVD §3.1 “Common use cases in SOVD and UDS” SOVD operations are derived from DiagnosticRoutine in DEXT. EXP SOVD §3.1 “Common use cases in SOVD and UDS”

Role in the interface model

The architecture leads GenericDiagnosticSovdOperation with Offer, StartExecution and StopOffer; StartExecution is for “Start execution of an operation” of the specified SOVD operation. EXP SWArchitecture §9.8.1.1.10
