Context

Within the AUTOSAR Adaptive Platform, the class ara::exec::FunctionGroupState represents a state of a Function Group (Function Group State) defined in the metamodel (ARXML). At runtime, it serves as an implementation-specific representation of the state information modeled in the ARXML metamodel. Each instance of this class is coupled to a specific Function Group (FunctionGroup) and identifies the state via the short name (Short Name) of the corresponding metamodel declaration (ModeDeclaration) [SWS_EM_02324]. As a final class (final), it is not intended for an inheritance hierarchy. Through the direct binding to the ARXML path, it forms the typed bridge between the model-based configuration and the runtime mechanisms of Execution Management.

Context diagram: Integration of FunctionGroupState between Function Group and metamodel. Sources: [SWS_EM_02324]

Lifecycle

The lifecycle of an instance of FunctionGroupState begins with its creation via the parameterized constructor, passing a reference to the associated Function Group and a ara::core::StringView for the state identifier [SWS_EM_02324]. According to the specification, the internal value of the object remains immutably bound to the underlying ARXML path after initialization over its entire lifetime. The class exhibits complete value semantics and supports both copying and moving instances:

  • Instances can be duplicated by means of the copy constructor [SWS_EM_02325] and copy assignment operator [SWS_EM_02330], with the assignment returning a reference to the target object.
  • Resources can be efficiently transferred to new or existing instances by means of the move constructor [SWS_EM_02331] and move assignment operator [SWS_EM_02332].

Destruction of the object occurs deterministically via the destructor [SWS_EM_02272] as soon as the scope is exited.

With regard to concurrency and thread safety, the class is specified with distinctions: The parameterized constructor is explicitly designated as thread-safe [SWS_EM_02324]. Likewise, the comparison operators for read access are defined as thread-safe ([SWS_EM_02273], [SWS_EM_02274]). In contrast, the copy constructor [SWS_EM_02325], the move constructor [SWS_EM_02331], the assignment operators ([SWS_EM_02330], [SWS_EM_02332]), and the destructor [SWS_EM_02272] are not thread-safe. Modifying lifecycle operations on the same instance therefore require external synchronization.

Usage Path

The typical usage path comprises instantiation, forwarding as a state value, and subsequent logical comparison:

  1. Creation: The application instantiates an object of FunctionGroupState, specifying an existing FunctionGroup and the short name of the target ModeDeclaration [SWS_EM_02324].
  2. Forwarding and storage: Since the instance immutably represents the target state, it can be passed to other functional blocks or stored in data structures by copying or moving ([SWS_EM_02325], [SWS_EM_02331], [SWS_EM_02330], [SWS_EM_02332]).
  3. State value check: Applications compare instances via the equality and inequality operators. The operator operator== returns true if and only if both FunctionGroupState instances represent exactly the same metamodel element, and false otherwise [SWS_EM_02273]. Complementarily, operator!= returns false if and only if the same metamodel entity is mapped, and true in case of inequality [SWS_EM_02274].
  4. Release: When leaving the scope, all bound resources are automatically cleaned up by the destructor [SWS_EM_02272].

Error Scenarios

The interface design of ara::exec::FunctionGroupState is engineered for maximum robustness and exception-free execution:

  • Exception safety and noexcept: All member functions – including the parameterized constructor [SWS_EM_02324], the copy and move operations ([SWS_EM_02325], [SWS_EM_02331], [SWS_EM_02330], [SWS_EM_02332]), the comparison operators ([SWS_EM_02273], [SWS_EM_02274]), and the destructor [SWS_EM_02272] – are declared with noexcept and specified as exception safe. The class thus never throws C++ exceptions under any circumstances.
  • Preconditions and error codes: The member functions do not return error codes (such as via ara::core::Result). An essential precondition for error-free use is that the short name passed to the constructor actually corresponds to a ModeDeclaration of the specified Function Group defined in the ARXML metamodel [SWS_EM_02324]. Interpretation: Since the constructor neither throws exceptions nor returns error codes, the validity of the metamodel identifier is likely presumed as a strict precondition on the caller; invalid identifiers presumably lead to the instance not being able to be mapped to a valid model element and comparisons via operator== failing.

<h4>Context</h4>
<p>Within the AUTOSAR Adaptive Platform, the class <code>ara::exec::FunctionGroupState</code> represents a state of a Function Group (Function Group State) defined in the metamodel (ARXML). At runtime, it serves as an implementation-specific representation of the state information modeled in the ARXML metamodel. Each instance of this class is coupled to a specific Function Group (<code>FunctionGroup</code>) and identifies the state via the short name (Short Name) of the corresponding metamodel declaration (<code>ModeDeclaration</code>) <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>. As a final class (<code>final</code>), it is not intended for an inheritance hierarchy. Through the direct binding to the ARXML path, it forms the typed bridge between the model-based configuration and the runtime mechanisms of Execution Management.</p>
