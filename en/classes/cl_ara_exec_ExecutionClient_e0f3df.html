Role in the reported process lifecycle

ExecutionClient is the process-side interface for a reporting process. A reported kRunning causes Execution Management to reach the process state Running; The execution state and the internally managed process state remain separate models SWS EM §7.3.1 “Execution State” SWS EM §7.3.2 “Process States”.

Deterministic start-up and scheduling

A Reporting Process reports kRunning after completing its initialization and before a potentially non-deterministic service discovery phase. This allows configured dependencies to resolve to a resilient process state. On a scheduling request, Execution Management triggers SIGTERM; The handler stored at Create is called by ExecutionClient [SWS_EM_02562] [SWS_EM_02003] [SWS_EM_02577].

State diagram: The EM view of the process run differs from the reported execution state SWS EM §7.3.1 “Execution State” SWS EM §7.3.2 “Process States”. Interpretation: The labels summarize several standardized transition triggers.

Sequence diagram: The kRunning report connects the process view with lifecycle tracking by EM and the start of Alive Supervision by PHM SWS EM §7.3.1 “Execution State” SWS PHM §7.2 “Supervision of Supervised Entities”.

Limits of responsibility

The client only reports its own status; Execution Management is responsible for start, stop and OS configuration, but not for the ongoing scheduling of the process, which lies with the operating system [SWS_EM_01401] SWS Operating System Interface §7.1.2 “Process Handling” SWS Operating System Interface §7.1.3 “Scheduling Policies”.

Report running at the right point

Call the method only for the reporting process itself and report kRunning after initialization is complete. Execution Management may then set the Process State to Running [SWS_EM_01401] [SWS_EM_01004].

Avoid misuse
