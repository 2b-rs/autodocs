intended use

<SI>Proxy is the client-side proxy of a service interface. The generation toolchain creates it from the ServiceInterface model of the ARXML manifest; the hierarchical SI namespace and the class name are derived from this. The declared header follows the scheme <SiNamespaceDerivedDirectoryPath>/<SiShortname>_proxy.h. The proxy contains a corresponding member for each interface element modeled as an event, field or method. [SWS_CM_00004] [SWS_CM_99445] [SWS_CM_99446] [SWS_CM_99447]

Generation & destruction

A proxy can be constructed directly from a HandleType obtained by FindService() or StartFindService(). Alternatively, the exception-safe factory Create() returns a ara::core::Result with proxy or a matching ara::com::ComErrc. The destructor is declared, but its exception safety is not guaranteed. [SWS_CM_00131] [SWS_CM_10438] [SWS_CM_99444]

Lifecycle & Ownership

Copy construction and copy assignment are prohibited (=delete); the proxy is movable. The Move assignment is noexcept and is exception-safe, but the Move constructor is not specified as exception-safe. GetHandle() returns the handle used to create it. [SWS_CM_00136] [SWS_CM_11551] [SWS_CM_00137] [SWS_CM_11552] [SWS_CM_10383]

Interaction with other classes

The instant search using FindService() accepts InstanceIdentifier or InstanceSpecifier and returns matching handles. The registering search via StartFindService() calls a handler when matching service instances are found; the returned FindServiceHandle ends the monitoring with StopFindService(). A state handler can observe service availability changes and be replaced or removed at runtime; Overloads allow an execution context for this. [SWS_CM_00122] [SWS_CM_00622] [SWS_CM_00123] [SWS_CM_00623] [SWS_CM_11352] [SWS_CM_11365] [SWS_CM_00125] [SWS_CM_01074] [SWS_CM_01076] [SWS_CM_01075]

Item Access & Error handling

For the generated interface elements, events and field notifications are activated with Subscribe() and fetched from the local cache via GetNewSamples(). Fields also allow asynchronous Get() and Set(). Methods that are not modeled as fire-and-forget return a ara::core::Future when called immediately to evaluate the result or error. [SWS_CM_11601] [SWS_CM_11610] [SWS_CM_00112] [SWS_CM_00113] [SWS_CM_00196]

Search and state queries, the factory, and handler and stop operations are specified as exception-safe. A failed search, factory creation, or state query is represented in each case through ara::core::Result with a corresponding ComErrc. [SWS_CM_00122] [SWS_CM_00622] [SWS_CM_10438] [SWS_CM_01073]

Architectural embedding

Proxy and skeleton are the code artifacts generated from a formal service definition: the proxy is the local facade of the consumer, while the skeleton connects the service implementation to the communication management transport layer. EXP ARAComAPI §4.1 “Proxy/Skeleton Architecture”

Service Discovery and Handle

FindService() supplies the currently available instances as handles, StartFindService() monitors availability changes and also initially informs the registered handler with the current, possibly empty list. The handle encapsulates the binding-specific address information and intentionally leaves open whether multiple proxy instances represent the same service.
