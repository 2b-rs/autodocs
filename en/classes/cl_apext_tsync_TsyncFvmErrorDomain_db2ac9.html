Manages error codes and exceptions of the Freshness Value Manager for thread-safe error resolution.

Class apext::tsync::TsyncFvmErrorDomain represents the error domain of the Freshness Value Manager in module tsync and maps error codes to semantic descriptions and exception types [SWS_TS_14206]. It enables thread-safe querying of domain-specific names and error messages as well as the targeted throwing of typed exceptions in the event of runtime errors [SWS_TS_14211]. If the system is compiled without C++ exception support, the function for throwing exceptions is excluded from overload resolution.

Context

Class apext::tsync::TsyncFvmErrorDomain represents the error domain of the Freshness Value Manager (FVM) within module tsync of the AUTOSAR Adaptive Platform. As a specialization of ara::core::ErrorDomain, it provides the semantic context for error states and diagnostic messages that can occur during the management and validation of freshness values. Via the type aliases Errc [SWS_TS_14206] and Exception [SWS_TS_14207], the domain directly binds the specific enumeration TsyncFvmErrc and the base exception type TsyncFvmException to the error domain. The class thus acts as a link between the FVM subsystems, generic error handling structures such as ara::core::ErrorCode, and the applying components of time synchronization.

Lifecycle

Instances of apext::tsync::TsyncFvmErrorDomain are created via the default constructor [SWS_TS_14208]. The constructor is specified as constexpr and noexcept, which enables exception-safe initialization as early as compile time [SWS_TS_14208]. Deallocation is performed via the virtual default destructor [SWS_TS_14201], which is likewise implemented as noexcept and exception-safe. Interpretation: As an implementation of an AUTOSAR error domain, the class is likely to be operated typically as a long-lived instance in order to provide application modules with a permanent reference for error resolutions. All observing operations as well as the constructor are specified as thread-safe [SWS_TS_14208] [SWS_TS_14209] [SWS_TS_14210] [SWS_TS_14211], allowing concurrent use across thread boundaries without external synchronization.

Usage Path

The primary usage path of the error domain encompasses identification, textual resolution of error causes, and optional propagation as a C++ exception:

  1. Domain identification: Via method Name() [SWS_TS_14209], the runtime system queries the identifier of the error domain. The return value is a character-based constant that is uniquely assigned to the domain [SWS_TS_14209].
  2. Textual error description: If an error occurs during FVM processing, its numeric error code is converted into a readable string using Message() [SWS_TS_14210]. Interpretation: The message text returned by Message() is likely based on static string literals, as the method is declared thread-safe and exception-safe without dynamic memory management.
  3. Escalation as exception: If an encountered error cannot be handled locally, ThrowAsException() [SWS_TS_14211] enables converting a ara::core::ErrorCode into an exception of type apext::tsync::TsyncFvmException, which is then thrown immediately.

Sequence diagram: Sequence of exception creation and throwing via the error domain. Sources: [SWS_TS_14211]

Error Scenarios

Error handling of class apext::tsync::TsyncFvmErrorDomain is divided into querying diagnostic information and propagating runtime errors:

  • Error resolution without exceptions: The query methods Name() [SWS_TS_14209] and Message() [SWS_TS_14210] are fully exception-safe and marked with noexcept. They guarantee that inspecting an error state causes no additional exceptions.
  • Error propagation via exceptions: Method ThrowAsException() [SWS_TS_14211] is explicitly defined as noexcept(false) and not exception-safe, as its dedicated purpose is to create and throw a apext::tsync::TsyncFvmException [SWS_TS_14211].
  • Toolchain condition: If C++ exceptions are disabled in the compiler toolchain, ThrowAsException() does not participate in overload resolution according to the specification [SWS_TS_14211]. This ensures that environments without exception support compile without errors.
