Context

In the AUTOSAR Adaptive Platform, the abstract base class ara::diag::SovdBulkData forms the central interface for handling bulk data within the scope of Service-Oriented Vehicle Diagnostics (SOVD) [SWS_DM_01841], AUTOSAR_AP_SWS_Diagnostics p. 701. It is implemented by adaptive applications to provide or receive diagnostic and operational data such as fault logs, traces, or software packages for external diagnostic clients.

At least three parties are involved in the interaction:

  • SOVD client: An external entity that requests bulk data operations via standardized REST/HTTP calls in accordance with ISO 17978-3 or ASAM SOVD.
  • Diagnostic Management (DM): The AUTOSAR diagnostic server receives requests and forwards them to the registered instance of ara::diag::SovdBulkData, provided the service was previously offered via Offer() [SWS_DM_01857].
  • Application handler: The application-specific specialization of ara::diag::SovdBulkData, which serves the concrete virtual callback methods for metadata queries [SWS_DM_01791], [SWS_DM_01853], data download [SWS_DM_01792], [SWS_DM_01873], data upload [SWS_DM_01793], [SWS_DM_01854], as well as data deletion [SWS_DM_01855], [SWS_DM_01856].

Context diagram: Interaction between SOVD client, Diagnostic Management, and the SovdBulkData handler. Sources: [SWS_DM_01841], [SWS_DM_01857], AUTOSAR_AP_SWS_Diagnostics p. 222, [SWS_DM_01791], [SWS_DM_01792].

Lifecycle

The class ara::diag::SovdBulkData undergoes a clearly defined lifecycle consisting of instantiation, service offering, operational operation, and destruction:

  • Creation: Instantiation takes place via the constructor, passing an ara::core::InstanceSpecifier referencing a PortPrototype of a DiagnosticSovdBulkDataInterface, as well as a parameter of type ConcurrencyType [SWS_DM_01847]. The constructor itself is thread-safe (thread-safe).
  • Copy and move semantics: The instance represents an exclusive interface per port. Copy constructor [SWS_DM_01848] and copy assignment operator [SWS_DM_01850] are deleted (=delete). Move constructor [SWS_DM_01849] and move assignment operator [SWS_DM_01851] are specified with protected (protected) visibility.
  • State management: After creation, the object is in an idle state. Calling Offer() activates the forwarding of incoming SOVD messages by the DM to the handler [SWS_DM_01857]. Via StopOffer(), this forwarding is deactivated again [SWS_DM_01858].
  • Destruction: The destructor ~SovdBulkData() is declared virtual [SWS_DM_01852], AUTOSAR_AP_SWS_Diagnostics p. 702. In application practice, StopOffer() is likely to be called regularly before destroying an instance in order to complete pending requests in an orderly manner.
  • Concurrency: The ConcurrencyType passed in the constructor determines whether the application-specific implementations of the virtual methods must be designed thread-safe (kConcurrent) or not thread-safe (kNotConcurrent) [SWS_DM_01847]. The control methods Offer() and StopOffer() as well as the destructor are specified as not thread-safe (not thread-safe) and require calls from a protected context [SWS_DM_01857], [SWS_DM_01858], [SWS_DM_01852].

Usage Path

A typical usage path comprises the registration of the handler and the asynchronous processing of bulk data transfer requests, exemplified by the download of bulk data:

  1. Initialization and offering: The application instantiates the derived handler class with the configured InstanceSpecifier [SWS_DM_01847] and calls Offer() to activate routing in the DM [SWS_DM_01857].
  2. Request reception: An external client sends a request to the SOVD method "Download Bulk Data". The DM delegates the request to RequestBulkDataDownload(), passing category, ID, HTTP Accept header, meta-information, and a CancellationHandler [SWS_DM_01792], [SWS_DM_01873].
  3. Processing and response: The implementation checks the resource and asynchronously returns a ara::core::Future. This contains either a read session (DataTransferReadSession) including the associated BulkDataMetaDataDescriptor or an HTTP redirect (HttpRedirect) [SWS_DM_01873].
  4. Cancellation handling: If the client disconnects prematurely, the DM signals this via the passed CancellationHandler, allowing the application to release resources [SWS_DM_01873].
  5. Service unregistration: When shutting down the component, the application calls StopOffer(), whereby the DM no longer delivers any further requests [SWS_DM_01858].

Sequence diagram: Typical call sequence during the provision and execution of a bulk data download. Sources: [SWS_DM_01792], [SWS_DM_01857], [SWS_DM_01858], [SWS_DM_01873].

Error Scenarios

Error situations can occur in different phases and are reported via specific mechanisms:

  • Model and port violations during construction: The constructor is declared as noexcept, but performs integrity checks against the AUTOSAR model [SWS_DM_01847]. Possible violations include:
    • InstanceSpecifierMappingIntegrityViolation: The identifier cannot be resolved in the context of the executable or does not reference a PortPrototype.
    • PortInterfaceMappingViolation: The referenced port is not typed by a DiagnosticSovdBulkDataInterface.
    • ProcessMappingViolation: The modeled process does not match the runtime process.
    • InstanceSpecifierAlreadyInUseViolation: The InstanceSpecifier is already used by another instance in the current process.
  • Configuration and state errors during Offer(): The method Offer() returns a ara::core::Result<void> [SWS_DM_01857]. Possible error codes are:
    • DiagOfferErrc::kConfigurationMismatch: The configuration of the monitor does not match the DEXT diagnostic description.
    • DiagOfferErrc::kAlreadyOffered: The service instance was already registered previously.
  • SOVD protocol and processing errors: The pure virtual methods RequestBulkDataDownload, RequestBulkDataUpload, DeleteAllBulkData, and DeleteSpecificBulkData signal errors asynchronously via the returned ara::core::Future using standardized SOVD error codes according to ISO 17978-3 or ASAM SOVD 1.1 (using DiagSovdErrc) [SWS_DM_01854], [SWS_DM_01855], [SWS_DM_01856], [SWS_DM_01873]. For GetBulkDataMetaData, on the other hand, no standardized error codes are specified [SWS_DM_01853].

<h4>Lifecycle</h4>
<p>The class <code>ara::diag::SovdBulkData</code> undergoes a clearly defined lifecycle consisting of instantiation, service offering, operational operation, and destruction:</p>
<ul>
<li><strong>Creation:</strong> Instantiation takes place via the constructor, passing an <code>ara::core::InstanceSpecifier</code> referencing a <code>PortPrototype</code> of a <code>DiagnosticSovdBulkDataInterface</code>, as well as a parameter of type <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. The constructor itself is thread-safe (<em>thread-safe</em>).</li>
<li><strong>Copy and move semantics:</strong> The instance represents an exclusive interface per port. Copy constructor <a class="spec-record-ref" data-req="SWS_DM_01848" href="../spec/record.html?id=SWS_DM_01848">[SWS_DM_01848]</a> and copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01850" href="../spec/record.html?id=SWS_DM_01850">[SWS_DM_01850]</a> are deleted (<code>=delete</code>). Move constructor <a class="spec-record-ref" data-req="SWS_DM_01849" href="../spec/record.html?id=SWS_DM_01849">[SWS_DM_01849]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01851" href="../spec/record.html?id=SWS_DM_01851">[SWS_DM_01851]</a> are specified with protected (<code>protected</code>) visibility.</li>
<li><strong>State management:</strong> After creation, the object is in an idle state. Calling <code>Offer()</code> activates the forwarding of incoming SOVD messages by the DM to the handler <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Via <code>StopOffer()</code>, this forwarding is deactivated again <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
<li><strong>Destruction:</strong> The destructor <code>~SovdBulkData()</code> is declared virtual <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=702">AUTOSAR_AP_SWS_Diagnostics p. 702</a>. In application practice, <code>StopOffer()</code> is likely to be called regularly before destroying an instance in order to complete pending requests in an orderly manner.</li>
<li><strong>Concurrency:</strong> The <code>ConcurrencyType</code> passed in the constructor determines whether the application-specific implementations of the virtual methods must be designed thread-safe (<code>kConcurrent</code>) or not thread-safe (<code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. The control methods <code>Offer()</code> and <code>StopOffer()</code> as well as the destructor are specified as not thread-safe (<em>not thread-safe</em>) and require calls from a protected context <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>, <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>, <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical usage path comprises the registration of the handler and the asynchronous processing of bulk data transfer requests, exemplified by the download of bulk data:</p>
<ol>
<li><strong>Initialization and offering:</strong> The application instantiates the derived handler class with the configured <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a> and calls <code>Offer()</code> to activate routing in the DM <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>.</li>
<li><strong>Request reception:</strong> An external client sends a request to the SOVD method "Download Bulk Data". The DM delegates the request to <code>RequestBulkDataDownload()</code>, passing category, ID, HTTP Accept header, meta-information, and a <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01792" href="../spec/record.html?id=SWS_DM_01792">[SWS_DM_01792]</a>, <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Processing and response:</strong> The implementation checks the resource and asynchronously returns a <code>ara::core::Future</code>. This contains either a read session (<code>DataTransferReadSession</code>) including the associated <code>BulkDataMetaDataDescriptor</code> or an HTTP redirect (<code>HttpRedirect</code>) <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Cancellation handling:</strong> If the client disconnects prematurely, the DM signals this via the passed <code>CancellationHandler</code>, allowing the application to release resources <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Service unregistration:</strong> When shutting down the component, the application calls <code>StopOffer()</code>, whereby the DM no longer delivers any further requests <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error situations can occur in different phases and are reported via specific mechanisms:</p>
<ul>
<li><strong>Model and port violations during construction:</strong> The constructor is declared as <code>noexcept</code>, but performs integrity checks against the AUTOSAR model <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. Possible violations include:
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not reference a <code>PortPrototype</code>.</li>
  <li><code>PortInterfaceMappingViolation</code>: The referenced port is not typed by a <code>DiagnosticSovdBulkDataInterface</code>.</li>
  <li><code>ProcessMappingViolation</code>: The modeled process does not match the runtime process.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another instance in the current process.</li>
  </ul>
</li>
<li><strong>Configuration and state errors during Offer():</strong> The method <code>Offer()</code> returns a <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Possible error codes are:
  <ul>
  <li><code>DiagOfferErrc::kConfigurationMismatch</code>: The configuration of the monitor does not match the DEXT diagnostic description.</li>
  <li><code>DiagOfferErrc::kAlreadyOffered</code>: The service instance was already registered previously.</li>
  </ul>
</li>
<li><strong>SOVD protocol and processing errors:</strong> The pure virtual methods <code>RequestBulkDataDownload</code>, <code>RequestBulkDataUpload</code>, <code>DeleteAllBulkData</code>, and <code>DeleteSpecificBulkData</code> signal errors asynchronously via the returned <code>ara::core::Future</code> using standardized SOVD error codes according to ISO 17978-3 or ASAM SOVD 1.1 (using <code>DiagSovdErrc</code>) <a class="spec-record-ref" data-req="SWS_DM_01854" href="../spec/record.html?id=SWS_DM_01854">[SWS_DM_01854]</a>, <a class="spec-record-ref" data-req="SWS_DM_01855" href="../spec/record.html?id=SWS_DM_01855">[SWS_DM_01855]</a>, <a class="spec-record-ref" data-req="SWS_DM_01856" href="../spec/record.html?id=SWS_DM_01856">[SWS_DM_01856]</a>, <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.
