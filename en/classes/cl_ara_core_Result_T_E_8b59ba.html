Context

The template class ara::core::Result<T &, E> represents a partial specialization of the generic result type Result for references. In the AUTOSAR Adaptive Platform, it serves as a unified return type for operations that, upon successful execution, do not create or copy a new value on the caller's stack, but provide an lvalue reference to an existing object (value_type according to [SWS_CORE_00902]). If an error occurs during execution, the instance transports an error object instead (error_type according to [SWS_CORE_00903]).

For the error type E, the specification requires a mandatory condition: If the compile-time check yields E != ara::core::ErrorCode, the implementation must trigger a compiler error. Interpretation: This restriction is likely intended to ensure that errors are tied uniformly across the platform to the error domains and error codes of AUTOSAR Adaptive. The class primarily interacts as a synchronous transfer medium between a called component (producer) and the caller (consumer), allowing references to be transmitted without dynamic allocation or object duplication.

Lifecycle

An instance of ara::core::Result<T &, E> is at any time in exactly one of two states: It either holds a bound reference to an lvalue object of type T or an error object of type E.

Creation takes place via specialized interfaces depending on the state:

  • Value state: Instantiation is performed via the constructor [SWS_CORE_00908] or the static helper function FromValue [SWS_CORE_00904]. Both interfaces enforce that the passed argument is an lvalue; passing rvalues leads to an ill-formed program (ill-formed).
  • Error state: Population with an error occurs via lvalue and rvalue constructors ([SWS_CORE_00909], [SWS_CORE_00910]), copy and move construction ([SWS_CORE_00911], [SWS_CORE_00912]), or via FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]), where [SWS_CORE_00907] enables the direct in-place construction of an error via parameter packs.

Interpretation: Since Result<T &, E> merely binds a reference, it does not assume ownership of the target object T; its lifetime must therefore outlive the lifetime of the Result instance as well as the evaluation. The error object E, on the other hand, is directly owned by the instance.

State changes and assignments are controlled via the copy and move assignment operators ([SWS_CORE_00914], [SWS_CORE_00915]): If the assigned source object holds a value, the internal reference is rebound to the target of the source object; if it holds an error, the error is copied or moved. In addition, a new error can be constructed in-place via EmplaceError [SWS_CORE_00916]. Two instances can exchange their contents using Swap [SWS_CORE_00917].

Destruction takes place via the destructor [SWS_CORE_00913], which is trivial if std::is_trivially_destructible<E>::value holds. Regarding concurrency, non-mutating accesses such as HasValue [SWS_CORE_00918] are thread-safe, whereas modifying operations such as EmplaceError [SWS_CORE_00916], assignments, and Swap [SWS_CORE_00917] are specified as not thread-safe.

Usage Path

The typical usage of ara::core::Result<T &, E> is divided into creation, state evaluation, and conditional access:

  1. Creation: The producer creates the instance after executing an operation—in case of success via FromValue [SWS_CORE_00904] or in case of an error via FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]).
  2. State check: The consumer checks the status via HasValue() [SWS_CORE_00918] or the boolean conversion operator operator bool() [SWS_CORE_00919]. Alternatively, equality with a specific error code can be checked directly using CheckError() [SWS_CORE_00937].
  3. Value or error access:
    • If a value is present, access occurs via Value() ([SWS_CORE_00924], [SWS_CORE_00925]), the dereference operator operator*() ([SWS_CORE_00920], [SWS_CORE_00921]), or the member access operator operator->() ([SWS_CORE_00922], [SWS_CORE_00923]).
    • If an error is present, the error reference is queried via Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]).
  4. Transformation and functional processing:
    • Bind() [SWS_CORE_00941] applies a callable to the referenced value and transforms it if a value is present; in case of an error, a new Result with the copied error is returned.
    • Resolve() ([SWS_CORE_00939], [SWS_CORE_00940]) returns the referenced value or, in case of an error, calls a fallback callable that returns a type-compatible reference.
    • Via Ok() ([SWS_CORE_00926], [SWS_CORE_00927]) or Err() ([SWS_CORE_00931], [SWS_CORE_00932]), the state can be transferred into a ara::core::Optional.

Error Scenarios

When handling ara::core::Result<T &, E>, preconditions must be met to avoid runtime errors:

  • Violations:
    • If Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator*() ([SWS_CORE_00920], [SWS_CORE_00921]), or operator->() ([SWS_CORE_00922], [SWS_CORE_00923]) is called even though the instance contains no value, a ResultWithNoValueViolation occurs.
    • If Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) is called even though the instance contains a value, a ResultWithNoErrorViolation occurs.
  • Exception handling: On success, the methods ValueOrThrow() ([SWS_CORE_00938], [SWS_CORE_00949]) return the reference to the object, but in case of an error they throw the exception associated with the error. If C++ exceptions are disabled in the toolchain, these methods do not participate in overload resolution.
  • Safe fallback values: To avoid violations and exceptions, ValueOr() ([SWS_CORE_00933], [SWS_CORE_00934]) and ErrorOr() ([SWS_CORE_00935], [SWS_CORE_00936]) are suitable: ValueOr() returns a copy of the referenced object or a predefined default value; ErrorOr() returns the contained error or a default error.
