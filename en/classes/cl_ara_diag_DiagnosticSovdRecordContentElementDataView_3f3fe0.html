Context

The class ara::diag::DiagnosticSovdRecordContentElementDataView ([SWS_DM_02270], SWS Diagnostics §8.60.11 “Class: DiagnosticSovdRecordContentElementDataView”) represents a typed view of a diagnostic content element (DiagnosticSovdContentElementData) organized as a structured record. In the context of Service-Oriented Vehicle Diagnostics (SOVD), it acts as an interface for managing and manipulating key-value mappings within a diagnostic record. Its interaction partners include higher-level diagnostic applications, the underlying DiagnosticSovdContentElementData instances, and the specialized iterator types DiagnosticSovdRecordContentElementDataIterator and DiagnosticSovdRecordContentElementDataConstIterator ([SWS_DM_02279], [SWS_DM_02281]). For typed population, the class provides overloaded Add operations that accept both primitive data types such as std::int64_t, std::uint64_t, double, bool, and ara::core::StringView as well as nested DiagnosticSovdContentElementData objects ([SWS_DM_02288] to [SWS_DM_02293]).

Lifecycle

As a view class, DiagnosticSovdRecordContentElementDataView does not own the managed data itself (Interpretation: The instance acts as a lightweight access wrapper around an existing data structure). A prerequisite for the error-free use of the view is that the referenced base element is of type RecordContentElementData or ContentData ([SWS_DM_02273], [SWS_DM_02288]). The internal state reflects the population of the underlying record: The fill level can be monitored via Empty ([SWS_DM_02275]) and Size ([SWS_DM_02273]), while Capacity ([SWS_DM_02274]) and Reserve ([SWS_DM_02283]) control memory allocation. All elements can be reset with Clear ([SWS_DM_02276]). In addition, the status of the content can be explicitly set to an error state via SetError ([SWS_DM_02272]) or queried via HasError ([SWS_DM_02271]). With regard to concurrency, all member functions of the class are specified as thread-safe and exception-safe ([SWS_DM_02271] to [SWS_DM_02294]).

Usage Path

A typical usage path comprises preparatory capacity reservation, step-by-step population of the record, and random access to individual field elements:

  1. Reserve capacity: Prior to inserting multiple values, the expected required capacity is reserved via Reserve ([SWS_DM_02283]).
  2. Insert elements: Using the type-specific overloads of Add, data elements are registered by specifying a key ([SWS_DM_02288] to [SWS_DM_02293]).
  3. Check existence and search: The presence of a key can be checked via HasContentElement ([SWS_DM_02284]), or an iterator to the element is retrieved via Find ([SWS_DM_02285], [SWS_DM_02286]).
  4. Read or modify values: A reference to the desired DiagnosticSovdContentElementData is determined via operator[] ([SWS_DM_02277], [SWS_DM_02278]).
  5. Remove elements: Entries that are no longer needed are deleted by key via Remove ([SWS_DM_02287]) or via an iterator using Erase ([SWS_DM_02294]).

Sequence diagram: Typical sequence for reserving, populating, and key-based querying of a record element. Sources: [SWS_DM_02283], [SWS_DM_02292], [SWS_DM_02277].

Error Scenarios

Methods with error potential signal failures via the return type ara::core::Result:

  • Incompatible data type of the base instance: If the underlying DiagnosticSovdContentElementData instance is not of type RecordContentElementData or ContentData, modifying and querying operations such as Add, operator[], HasContentElement, Remove, and Erase fail with an error in the Result ([SWS_DM_02277], [SWS_DM_02284], [SWS_DM_02287], [SWS_DM_02288], [SWS_DM_02294]).
  • Disallowed element type during insertion: If an attempt is made to add a child element that is itself of type ContentData, the call to Add fails ([SWS_DM_02288] to [SWS_DM_02293]).
  • Key not found: With operator[], HasContentElement, or Remove, the Result returns an error if the specified key does not exist in the record ([SWS_DM_02277], [SWS_DM_02284], [SWS_DM_02287]).
  • Invalid iterator on erase: If an invalid iterator is passed to Erase, the function returns the error code DiagErrc::kInvalidArgument ([SWS_DM_02294]).
  • Set SOVD error: If the content contains an error code set via SetError ([SWS_DM_02272]), HasError returns this error as ara::diag::DiagSovdErrc in the Result ([SWS_DM_02271]).
