Provides a structured view for key-based management and retrieval of SOVD diagnostic records.

The class provides a structured view of SOVD records of type RecordContentElementData for Adaptive Platform Diagnostics (SWS Diagnostics §8.60.11 “Class: DiagnosticSovdRecordContentElementDataView”). It enables key-based adding, reading, and managing of primitive as well as complex diagnostic elements via thread-safe methods such as Add or operator[] ([SWS_DM_02288]). A prerequisite for all operations is that the underlying data element is of the required record type, as calls otherwise abort with an error in the return Result.

Context

The class ara::diag::DiagnosticSovdRecordContentElementDataView acts in the context of Service-Oriented Vehicle Diagnostics (SOVD) as a structured view (View) on a diagnostic data element of type RecordContentElementData or ContentData (SWS Diagnostics §8.60.11 “Class: DiagnosticSovdRecordContentElementDataView”, [SWS_DM_02270]). It enables diagnostic applications and the diagnostic runtime system to create, read, and modify field-based records consisting of key-value pairs ([SWS_DM_02288]). The interaction partners are, on the one hand, the diagnostic service implementations that provide or consume diagnostic data and, on the other hand, the underlying generic container objects of type DiagnosticSovdContentElementData. Via standardized interfaces, the view decouples the application-specific manipulation from the physical storage form of the diagnostic content.

Lifecycle

According to its purpose as a view, the instance presumably holds only a reference to an existing data object of type DiagnosticSovdContentElementData (Interpretation). It follows that the lifetime of the referenced record must strictly encompass the existence of the view in order to avoid dangling references. All declared methods of the class are designed to be thread-safe (thread-safe) and exception-safe (exception safe) according to the specification ([SWS_DM_02273], [SWS_DM_02288]). The lifecycle of the contained data elements within the record can be dynamically managed: Existing elements can be completely removed via Clear ([SWS_DM_02276]), deleted specifically via Remove by their key ([SWS_DM_02287]), or removed from the container via an iterator using Erase ([SWS_DM_02294]).

Usage Path

A typical usage flow comprises preparing storage, adding elements, navigating, and reading fields:

  • Storage preparation: To prevent reallocations when element counts are known, the capacity can be proactively set with Reserve ([SWS_DM_02283]). The current capacity can be queried via Capacity ([SWS_DM_02274]).
  • Populating the record: Typed values are registered specifying a key (key) via overloaded Add operations. Primitive data types such as std::int64_t ([SWS_DM_02288]), std::uint64_t ([SWS_DM_02289]), double ([SWS_DM_02290]), bool ([SWS_DM_02291]), and string values via ara::core::StringView ([SWS_DM_02292]) are supported. Likewise, nested diagnostic elements of type DiagnosticSovdContentElementData can be added ([SWS_DM_02293]).
  • Check and query: Prior to access, emptiness can be checked with Empty ([SWS_DM_02275]) and the number of existing elements with Size ([SWS_DM_02273]). The existence of a key is verified using HasContentElement ([SWS_DM_02284]).
  • Access and iteration: Access to specific elements takes place either directly via the index operator operator[], which provides a reference to the target element ([SWS_DM_02277], [SWS_DM_02278]), or via the search method Find ([SWS_DM_02285], [SWS_DM_02286]). For traversals, iterators via Begin, End, CBegin, and CEnd are available ([SWS_DM_02279], [SWS_DM_02280], [SWS_DM_02281], [SWS_DM_02282]).

Sequence diagram: Typical flow when populating and reading an SOVD record element. Sources: [SWS_DM_02283], [SWS_DM_02288], [SWS_DM_02277], [SWS_DM_02271].

Error Scenarios

Operations on the record are subject to strict preconditions regarding container type and key validity:

  • Type conflicts: All access, insertion, and deletion methods require the underlying element to be of type RecordContentElementData or ContentData. Otherwise, operations such as Add ([SWS_DM_02288]), operator[] ([SWS_DM_02277]), HasContentElement ([SWS_DM_02284]), and Remove ([SWS_DM_02287]) fail and return a ara::core::Result with an error state.
  • Keys not found: An access via operator[] or a deletion via Remove returns an error if the requested key does not exist in the record ([SWS_DM_02277], [SWS_DM_02287]).
  • Invalid iterators upon deletion: Deletion by iterator via Erase returns the error code DiagErrc::kInvalidArgument in the event of invalid parameters or faulty data binding ([SWS_DM_02294]).
  • Explicit error handling: In addition to method-specific errors, the overall state of the record can be explicitly marked as faulty with a ara::core::ErrorCode via SetError ([SWS_DM_02272]). Callers can query the presence of an error via HasError, which returns a corresponding ara::diag::DiagSovdErrc in the event of an error ([SWS_DM_02271]).
