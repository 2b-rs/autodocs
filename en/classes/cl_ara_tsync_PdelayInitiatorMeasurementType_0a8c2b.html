Context

The structure ara::tsync::PdelayInitiatorMeasurementType functions in module tsync of the AUTOSAR Adaptive Platform as a specialized data container for detailed time measurements of a peer delay initiator (pDelay Initiator). It bundles the raw measurement data and reference timestamps recorded on the initiating node side during a complete peer delay measurement cycle. The primary purpose of this structure is to provide measurement data for time validation (Time Validation) in order to comprehensibly monitor the accuracy, propagation delays, and consistency of the time synchronization in the network.

The interaction partners here are the internal protocol instance for time measurement on the initiator side as well as downstream validation and diagnostic components. The structure records both local transmission and reception times in virtual local time and global timestamps reported back via network messages from the partner instance (responder). Via the sequence number [SWS_TS_14167], the measurement record can be unambiguously assigned to the respective transmitted request message.

Lifecycle

The structure ara::tsync::PdelayInitiatorMeasurementType is designed as a C++ POD or value object declared as final, without its own dynamic memory management or polymorphic interfaces. It is typically instantiated on the stack or within internal buffers of the initiator driver as soon as a measurement round is completed or a measurement event is assembled for time validation.

Regarding ownership, after being populated by the initiator, the structure is usually passed to interested recipients by copy (value semantics) or const reference. Interpretation: As a passive data type, the structure has no internal lifecycle states and implements no synchronization of its own against concurrent access; concurrent read and write accesses to the same instance across thread boundaries must therefore be coordinated by the calling environment. Destruction occurs deterministically upon leaving the scope of the managing object.

Usage Path

The typical sequence for the creation and evaluation of a ara::tsync::PdelayInitiatorMeasurementType instance follows the protocol cycle of the peer delay mechanism:

  1. Sending the request: When frame Pdelay_Req is sent, its departure time requestOriginTimestamp is recorded in virtual local time [SWS_TS_14160]. At the same time, the sequence identifier sequenceId is assigned and stored in the data record [SWS_TS_14167].
  2. Receiving the response: Upon arrival of the response message Pdelay_Resp, its arrival time responseReceiptTimestamp is recorded on the receiver side in virtual local time [SWS_TS_14161]. In addition, the arrival time requestReceiptTimestamp registered at the partner in global time is adopted from the content of Pdelay_Resp [SWS_TS_14162].
  3. Evaluation of the follow-up message: Via the follow-up message Pdelay_Resp_Follow_Up, the initiator receives the partner-side transmission time responseOriginTimestamp in global time [SWS_TS_14163].
  4. Completion and referencing: The initiator calculates the currently valid propagation delay value pDelay [SWS_TS_14166] and links the measurement to a reference tuple of virtual local time referenceLocalTimestamp [SWS_TS_14164] and the associated global reference time referenceGlobalTimestamp [SWS_TS_14165].

Subsequently, the fully populated structure is passed on to analysis or monitoring functions. Interpretation: Processing components use the combination of transmission, reception, and reference timestamps to evaluate asymmetries on the transmission path and detect erroneous time deviations at an early stage.
