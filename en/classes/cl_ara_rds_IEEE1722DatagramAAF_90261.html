Used for representing IEEE 1722 audio datagrams with protected header fields and virtual destructor.

In the Raw Data Stream module, the class is used for the structured representation of audio datagrams according to the IEEE 1722 AVTP Audio Format AUTOSAR_AP_SWS_RawDataStream p. 1. It encapsulates protocol-specific header data such as format, channel count, and bit depth in protected attributes, which are typically initialized and evaluated by derived data stream classes. A virtual destructor ensures that specialized datagram objects can be released polymorphically and exception-safely via base class pointers [SWS_RDS_90273]. Since no internal synchronization exists, concurrent accesses must be coordinated by the consuming streaming architecture.

Context

The class ara::rds::IEEE1722DatagramAAF provides the data representation of an IEEE 1722 datagram for the AVTP Audio Format (AAF) in the Raw Data Stream (rds) module of the AUTOSAR Adaptive Platform AUTOSAR_AP_SWS_RawDataStream p. 1. The IEEE 1722 (Audio Video Transport Protocol, AVTP) standard serves for the time-synchronized transmission of time-critical audio and video data streams over Ethernet networks in automotive environments. The header file ara/rds/raw_data_stream_IEEE1722.h declares the structure within the namespace ara::rds.

The class is responsible for encapsulating the protocol-specific control and metadata fields of an AAF data frame. This includes the mandatory format field format [SWS_RDS_90262] as well as specifications of the number of data streams per frame via streams_per_frame [SWS_RDS_90263] and sp [SWS_RDS_90269], respectively. For flexible mapping of different audio formats and AES3 specifications, the class comprises optional attributes for sampling rates and frame rates such as nsr [SWS_RDS_90268] and nfr [SWS_RDS_90265], event identifiers evt [SWS_RDS_90264], channel information channels_per_frame [SWS_RDS_90267], bit depths bit_depth [SWS_RDS_90266], and AES3 data type and reference fields aes3_data_type_h [SWS_RDS_90270], aes3_data_type_l [SWS_RDS_90271], and aes3_dt_ref [SWS_RDS_90272].

Interaction partners are the processing components of the RDS subsystem, which receive raw data streams from the network, parse them, or prepare them for transmission.

For controlled destruction, the class declares a virtual destructor ~IEEE1722DatagramAAF() noexcept [SWS_RDS_90273]. The virtual declaration ensures that derived classes are cleaned up completely and without errors when released via base class pointers, without leading to resource leaks. The noexcept specification guarantees that no exceptions are thrown during object destruction, which is essential particularly during stack unwinding in error scenarios.

With regard to concurrency, ara::rds::IEEE1722DatagramAAF does not provide internal synchronization of its own.
