intended use

ara::diag::DownloadService is the application interface for diagnostic download. The Diagnostic Server calls RequestDownload() for UDS 0x34, DownloadData() for TransferData and RequestDownloadExit() for UDS 0x37 on [SWS_DM_00784] [SWS_DM_00867] [SWS_DM_00869] [SWS_DM_00871].

Generation & destruction

The derived implementation is constructed with a InstanceSpecifier to a DiagnosticDownloadInterface and a ConcurrencyType to a [SWS_DM_00787]. It cannot be copied or moved; the virtual destructor is noexcept [SWS_DM_01649] [SWS_DM_01650] [SWS_DM_01647] [SWS_DM_01648] [SWS_DM_00788].

Interaction with other classes

Offer() enables request forwarding by the DM, and StopOffer() disables it [SWS_DM_00792] [SWS_DM_00793]. The pure virtual operations receive request data, MetaInfo, and an CancellationHandler; DownloadData() and RequestDownloadExit() return an OperationOutput on success [SWS_DM_00789] [SWS_DM_00790] [SWS_DM_00791].

Limitations & Error handling

The thread safety of the handlers is determined by the ConcurrencyType. The passed spans only remain valid until promise fulfillment or until abort processing [SWS_DM_00787] [SWS_DM_00789] [SWS_DM_00790] [SWS_DM_00791]. For negative answers, an appropriate DiagUdsNrcErrc error should be returned. A new offer reports DiagOfferErrc::kAlreadyOffered [SWS_DM_00790] [SWS_DM_00792].

Result & Error handling

The parameters include transferRequestParameterRecord (valid until the promise is fulfilled or the process is canceled via cancellationHandler), metaInfo and cancellationHandler for status queries or registration of a cancellation notifier. The result is returned as ara::core::Future<OperationOutput>, either with the data of the positive answer (placed after the blockSequenceCounter) or with a ErrorCode from DiagUdsNrcErrc according to ISO 14229-1 for a negative answer. Whether the implementation needs to be thread-safe depends on the ConcurrencyType passed in the constructor; the call is exception-safe.
