Context

In module core of the AUTOSAR Adaptive Platform, the class ara::core::FutureException acts as a specialized exception type for error states in the context of asynchronous operations. According to the specification, this exception is thrown by ara::core::Future and ara::core::Promise to report occurred error conditions to callers in a structured manner. In the overall architecture of the Adaptive Platform, the class is likely to form a functional bridge between error-code-based error handling and the modeled exception mechanism: It derives from the base class Exception and encapsulates a concrete error state in the form of an ara::core::ErrorCode [SWS_CORE_00412].

Typically, a producing context via ara::core::Promise, a consuming context via ara::core::Future, and the higher-level application are involved in the asynchronous interaction. If asynchronous processing fails or an invalid state is queried, ara::core::FutureException serves as the signal carrier. Being provided via the header file ara/core/future_error_domain.h, the exception is closely linked with the domain-specific error definitions for asynchronous workflows [SWS_CORE_00412].

Context diagram: Placement of ara::core::FutureException and its relationships to Future, Promise, Exception, and ErrorCode. Sources: [SWS_CORE_00412]

Lifecycle

The lifecycle of an instance of ara::core::FutureException begins with its creation via the constructor specified for this purpose, which accepts an initializing ara::core::ErrorCode [SWS_CORE_00412]. The declaration as explicit prevents unintended implicit type conversions of error codes into exception objects and ensures that creation always occurs deliberately [SWS_CORE_00412]. The constructor is also declared as noexcept and thus guarantees complete exception safety during object creation [SWS_CORE_00412].

Regarding operation in concurrent systems, the class is classified as thread-safe according to the specification [SWS_CORE_00412]. This property is essential for its intended purpose, as ara::core::Promise and ara::core::Future are regularly executed in separate threads. When an exception is thrown, the object is instantiated in the C++ runtime system. Ownership is transferred along the call hierarchy to the handling catch block during stack unwinding, where the exception object is automatically destroyed after exiting the exception block.

Usage Path

The regular usage path of ara::core::FutureException unfolds along the call chain of asynchronous tasks. Typically, an application component initiates an asynchronous operation whose result is managed via an associated pair of ara::core::Promise and ara::core::Future. If an error situation occurs during task execution or result retrieval, the exception is thrown.

In a typical flow, a consumer attempts to retrieve the result via a ara::core::Future. If no valid result is present in the underlying ara::core::Promise or an error state has been stored, this access leads to the throwing of a ara::core::FutureException. Here, the constructor strictly requires passing the associated error code err [SWS_CORE_00412]. The consuming application catches the exception in a suitable exception handler. Presumably, callers can evaluate the encapsulated ara::core::ErrorCode to accurately determine the concrete cause of the error within the error domain and initiate adequate countermeasures.

Error Scenarios

When using and handling ara::core::FutureException, the following error scenarios and system safety guarantees are decisive:

  • Exception-safe instantiation: Since the constructor is designated with noexcept, object creation of the exception itself never fails and throws no further secondary exceptions [SWS_CORE_00412]. This ensures a deterministic transition into exception handling even under load.
  • Mandatory specification of an error code: The class does not provide a parameterless default constructor; instantiation strictly requires a valid ara::core::ErrorCode as a parameter [SWS_CORE_00412]. An exception object without a stored error code can therefore not be created.
  • Unhandled exceptions: If a ara::core::FutureException thrown by ara::core::Future or ara::core::Promise is not caught by a matching catch block of the application, the standard runtime behavior of C++ applies, leading to termination of the process. Since the class inherits publicly from Exception, it can be caught both specifically and polymorphically via base class references.
