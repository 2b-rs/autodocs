From technical status to diagnostic approval

Condition is a configured reporting point that an application uses to pass its current condition state to the DM. The DM uses Conditions in particular as EnableConditions of monitor processing and as context for ClearConditions SWS Diagnostics §7.3.4.1.4 “EnableConditions” SWS Diagnostics §7.3.4.4.5 “Clearing DTCs”. It is therefore not a general Boolean memory, but part of a diagnostics-relevant configuration path.

Conditions provide a release status consumed by the DM for monitoring and clearing processing. Sources: SWS Diagnostics §7.3.4.1.4 “EnableConditions”, SWS Diagnostics §7.3.4.2 “Condition Management”, SWS Diagnostics §7.3.4.4.5 “Clearing DTCs”. Partial interpretation: The graphic compares two specified consumption points of a condition signal.

Set without local side effects

SetCondition reports the new ConditionType value [SWS_DM_00715]. The method should be called when the technical state actually changes, not as a replacement for polling. The sequence for a monitor or DTC clearing determines the DM configuration; the application must not infer an immediate DTC status change.

Availability at launch

Status messages are among the API calls that the DM may buffer and process when available. This allows an application to report its initial state early; It must still keep the state consistent SWS Diagnostics §7.3.1 “Interaction between DM and applications”.

The constructor of the class ara::diag::Condition creates an instance from a ara::core::InstanceSpecifier that points to a PortPrototype of a DiagnosticConditionInterface [SWS_DM_00712]. The call is thread-safe and exception safe.

Error handling

  • InstanceSpecifierMappingIntegrityViolation – the InstanceSpecifier cannot be resolved in the model or does not refer to a PortPrototype.
  • PortInterfaceMappingViolation – a PortPrototype typed by DiagnosticConditionInterface must be referenced by either a DiagnosticEnableConditionPortMapping or a DiagnosticClearConditionPortMapping.
  • ProcessMappingViolation - there is a suitable InstanceRef, but no suitable modeled process for the runtime process.
  • InstanceSpecifierAlreadyInUseViolation – the InstanceSpecifier is already used in the process.

ara::core::Result< void > SetCondition (ConditionType condition) noexcept;

Set condition.

Usage AI generated

Automatically generated usage notice derived from the referenced AUTOSAR R25-11 documents — not official AUTOSAR text.

Report functional state

SetCondition passes the current ConditionType to the DM [SWS_DM_00715]. It makes sense to only report an actual change and to clearly set the initial state during commissioning.

Do not simulate the effect locally

The diagnostic configuration SWS Diagnostics §7.3.4.1.4 “EnableConditions” SWS Diagnostics §7.3.4.4.5 “Clearing DTCs” determines whether a condition enables the monitor evaluation or influences a DTC deletion. The method itself therefore does not confirm a DTC status change.
