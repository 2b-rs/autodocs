Encapsulates an optional reference to an object and enables safe access without dynamic memory allocation.

The specialization ara::core::Optional<T &> serves as a type-safe container for optional lvalue references with the element type T & [SWS_CORE_01151]. It enables reassigning or resetting the reference at runtime without dynamic memory allocation [SWS_CORE_01164], [SWS_CORE_01165]. Prior to any access via dereference operators or the potentially throwing access method value(), the presence of a valid target object must strictly be verified [SWS_CORE_01172], [SWS_CORE_01173].

Context

The template specialization ara::core::Optional<T &> provides a type-safe container for an optional lvalue reference. The underlying element type is defined by the type alias value_type as T & [SWS_CORE_01151]. In contrast to the primary template for value types, this specialization serves as a reusable, rebindable reference that either points to an existing object of type T or represents an unengaged state. It interacts directly with calling software components and the referenced target object without allocating dynamic memory.

Lifecycle

An instance of ara::core::Optional<T &> is always in one of two well-controlled states: empty (disengaged) or engaged (referencing an object). The empty state is entered via the default constructor [SWS_CORE_01152] or initialization with nullopt_t [SWS_CORE_01153]. Binding to a reference occurs upon construction by passing a compatible value or reference [SWS_CORE_01156] as well as via converting constructors [SWS_CORE_01157]. Copy and move constructors transfer the state of the source container [SWS_CORE_01154], [SWS_CORE_01155].

At runtime, the state can be dynamically modified: Assigning a value or a reference rebinds the Optional to the passed target object [SWS_CORE_01162], which also happens via assignment operators of other Optional containers [SWS_CORE_01159], [SWS_CORE_01160], [SWS_CORE_01163] or the method emplace [SWS_CORE_01164]. A transition to the empty state occurs by calling reset [SWS_CORE_01165] or by assigning nullopt_t [SWS_CORE_01161]. Furthermore, swap allows the atomic swapping of two instances [SWS_CORE_01166]. The default destructor terminates the lifetime of the wrapper instance [SWS_CORE_01158], but presumably does not affect the referenced original object, as a reference semantically establishes no ownership.

Usage Path

A typical application cycle comprises creation, validation, and reading or modifying access to the referenced target:

  1. Initialization: An instance is created empty [SWS_CORE_01152] or engaged with the reference to an existing object [SWS_CORE_01156].
  2. State check: Prior to dereferencing, the caller checks the presence of a reference via the explicit conversion operator operator bool [SWS_CORE_01171] or the method has_value [SWS_CORE_01172].
  3. Access: Upon confirmed reference, access to the referenced object takes place via the dereference operators operator* [SWS_CORE_01169], [SWS_CORE_01170] or the arrow operator operator-> [SWS_CORE_01167], [SWS_CORE_01168]. Alternatively, value_or returns the referenced value or a specified default value [SWS_CORE_01175].
  4. Reset: After processing is complete, the reference is explicitly removed via reset if required [SWS_CORE_01165].

Sequence diagram: Typical sequence of initialization, verification, and dereferencing of an optional reference. Sources: [SWS_CORE_01156], [SWS_CORE_01165], [SWS_CORE_01170], [SWS_CORE_01172].

Error Scenarios

Errors occur primarily during premature or unauthorized access attempts to empty instances. If value() is called while the object does not contain a value, a violation of type IsoStdBadOption-alAccessViolation is thrown [SWS_CORE_01173], [SWS_CORE_01174]. Accordingly, in contrast to most other operations of the class, value() is explicitly classified as not exception safe (not exception safe).

Direct dereferencing operations using operator* [SWS_CORE_01169], [SWS_CORE_01170] and operator-> [SWS_CORE_01167], [SWS_CORE_01168] also document a violation of category IsoStdBadOption-alAccessViolation if the instance does not hold a reference. Although these operators are declared with noexcept, their usage strictly requires adhering to the precondition that a valid reference exists.
