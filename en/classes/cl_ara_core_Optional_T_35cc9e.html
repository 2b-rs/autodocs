Context

The template class ara::core::Optional<T&> provides a partial specialization of ara::core::Optional for lvalue references of type T&. Via the defined type alias value_type ([SWS_CORE_01151]), the specialization binds an optional reference to an existing object. In contrast to the primary template class for value types, this specialization allows an optional reference to an external object to be held without having to use dynamic memory allocation or raw C pointers with null pointer semantics. In software architectures of the AUTOSAR Adaptive Platform, it acts as a type-safe wrapper for interfaces where return values or parameters can optionally refer to an already existing instance.

Lifecycle

The lifecycle of an instance of ara::core::Optional<T&> is characterized by two disjoint states: the disengaged state (empty) and the engaged state (referencing). By default, the object can be initialized in the disengaged state without an assigned value via the default constructor ([SWS_CORE_01152]) or via the literal nullopt_t ([SWS_CORE_01153]). A direct transition to the engaged state occurs during construction by passing a reference value via the constructor template ([SWS_CORE_01156]) or by conversion from another compatible Optional instance ([SWS_CORE_01157]). Copy and move constructors are implemented by default and declared as noexcept ([SWS_CORE_01154], [SWS_CORE_01155]).

At runtime, an existing instance can dynamically change its state. The methods emplace ([SWS_CORE_01164]) and the assignment operators for compatible types ([SWS_CORE_01162], [SWS_CORE_01163]) transition the object into the engaged state or rebind it to a new reference. Copy and move assignments are also present as default implementations ([SWS_CORE_01159], [SWS_CORE_01160]). Resetting to the disengaged state occurs explicitly via reset() ([SWS_CORE_01165]) or by assigning nullopt ([SWS_CORE_01161]). In addition, swap ([SWS_CORE_01166]) allows swapping the contents of two instances. The destructor is specified as noexcept=default ([SWS_CORE_01158]). Interpretation: Because it is a reference specialization, the class presumably does not manage the lifetime of the target object; the target object is therefore expected to exist and be destroyed independently of the container.

Usage Path

A typical usage path comprises the creation, validation, and conditional data access to the referenced object:

  • Creation and engagement: A component creates the object either initially empty ([SWS_CORE_01152]) or binds it directly to an instance ([SWS_CORE_01156]). Afterwards, the reference can be set anew via emplace ([SWS_CORE_01164]) or value assignment ([SWS_CORE_01162]).
  • State check: Before accessing the target object, the caller checks for the presence of a value. The boolean conversion operator operator bool() ([SWS_CORE_01171]) as well as the method has_value() ([SWS_CORE_01172]) are available for this purpose, both of which are specified as constexpr noexcept.
  • Dereferencing and access: When the state is assured, the reference can be accessed via operator* ([SWS_CORE_01169], [SWS_CORE_01170]) or members of the target object can be accessed directly via the arrow operator operator-> ([SWS_CORE_01167], [SWS_CORE_01168]). In addition, value() ([SWS_CORE_01173], [SWS_CORE_01174]) enables direct access to T& and const T&, respectively.
  • Fallback value: If a fallback value is required when no object is referenced, value_or ([SWS_CORE_01175]) can be called to return either the value of the reference or a passed replacement value.
  • Release: If the reference is no longer valid or is to be reset, the instance is transitioned back to the disengaged state by means of reset() ([SWS_CORE_01165]).

Error Scenarios

Erroneous usages primarily arise from erroneous accesses to an uninitialized or empty object (precondition violation: If *this does not contain a value):

  • Triggering access violations: The unprotected call of the access method value() ([SWS_CORE_01173], [SWS_CORE_01174]) on a disengaged instance violates the precondition and leads to a IsoStdBadOptionalAccessViolation. The specification explicitly classifies the method as not exception safe.
  • Dereferencing without a value: For the operators operator* ([SWS_CORE_01169], [SWS_CORE_01170]) and operator-> ([SWS_CORE_01167], [SWS_CORE_01168]) as well, the precondition is defined that a value must be contained. In the event of a violation, a IsoStdBadOptionalAccessViolation is also documented, although the operators are declared with noexcept.

To avoid these error conditions, the caller must always check with has_value() ([SWS_CORE_01172]) prior to dereferencing or resort to the safe alternative value_or ([SWS_CORE_01175]).
