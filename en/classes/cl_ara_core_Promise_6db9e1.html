intended use

ara::core::Promise<T, E> is the AUTOSAR variant of std::promise. The error type must be ara::core::ErrorCode. Together with Future, the class can provide values and errors asynchronously and thread-safely without exception handling. [SWS_CORE_00340] [SWS_CORE_10800]

Lifecycle & Ownership

Copying is prohibited (=delete), moving is possible. Move assignment and destructor give up any existing shared state. [SWS_CORE_00350] [SWS_CORE_00351] [SWS_CORE_00342] [SWS_CORE_00343] [SWS_CORE_00349]

Interaction with other classes

get_future() returns the associated Future<T,E> with the same shared state; this call is permitted only once per Promise. set_value(), SetError(), and SetResult() make the shared state ready. [SWS_CORE_00344] [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356]

Limitations & Error handling

Repeatedly setting the value, error, or result, and invoking a setter without Shared State, are specified as violations. [SWS_CORE_13015] [SWS_CORE_13016]

Providing the asynchronous result

On the skeleton side, a Promise can provide an already calculated value or be pushed into an asynchronous worker; the associated Future is returned to the caller. EXP ARAComAPI §5.4.6 “Methods”

If an application error is detected, the associated ErrorCode is placed in the Promise; the client can then process it as Result using the Future path. EXP ARAComAPI §4.7 “Error Handling” EXP ARAComAPI §5.4.6 “Methods”

Sequence Diagram: Reusable Promise/Future flow for asynchronous methods. Sources: EXP ARAComAPI §4.4 “Method based communication” EXP ARAComAPI §5.4.6 “Methods”.

Treaty of Common State

The Promise completes the common state observed in Future. The relevant framework is the Future/Promise concept defined in Core for asynchronous value or error results. SWS Core §7.2 “Error handling” SWS Core §7.2.5.5 “Future and Promise”

Behavior in the event of an error

A Promise can only prepare its shared state once with value, error or Result. A subsequent call to set_value(), SetError(), or SetResult() when value or error is already stored is specified as a promise_already_satisfied violation. A setter without a shared state is its own violation. [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356] [SWS_CORE_13015] [SWS_CORE_13016]

get_future() may only be called once per shared state. The second call is set as future_already_retrieved violation; If the shared state is missing, the no_state violation applies. These cases are not application errors reported via Result in the API contract. [SWS_CORE_00344] [SWS_CORE_13013] [SWS_CORE_13014]

The destructor and move assignment give up an existing shared state. If the already output Future page then waits for the result, you GetResult() returns the error FutureErrc::kBrokenPromise; get() handles the same condition on an exception basis. The complete process including setting an error and timeout is shown in Fehlerpfad-Diagramm von Future. [SWS_CORE_00343] [SWS_CORE_00349] [SWS_CORE_00336] [SWS_CORE_00326]

Future< T, E > get_future () noexcept;

Return an associated Future with the same shared state as *this The returned Future is set as soon as this Promise receives the result, value, or an error. This fuction must only be called once as it is not allowed to have multiple Futures per Promise.

Usage AI generated

get_future (ara::core::Promise) returns, for ara::core::Promise, an associated ara::core::Future object with the same Shared State. The returned Future is set as soon as this Promise receives a result, value, or error. The function may be called only once per Promise because multiple Futures per Promise are not permitted.
