Context

The template class ara::core::Promise<T, E> provides the AUTOSAR-Adaptive-specific variant of the C++ standard class std::promise. Its core task is to form the writing end of an asynchronous synchronization channel and manage a shared state. Via this shared state, a producing execution path passes the result of an asynchronous computation—either a value of type T, an error of type E, or a composite ara::core::Result<T, E>—to the reading counterpart ara::core::Future<T, E>, which is obtained via get_future() [SWS_CORE_00344].

A central AUTOSAR requirement of the template signature is the default assignment E = ara::core::ErrorCode. If the instantiation deviates from this (E != ara::core::ErrorCode), the specification mandatorily requires a compilation error. This stipulation presumably serves the strict enforcement of the standardized error model of the Adaptive Platform so that asynchronous interfaces can work uniformly with ara::core::Result. Three entities are typically involved in the collaboration: the producing program part as owner of the Promise, the managed shared state for cross-thread state coupling, and one or more consumers that receive the asynchronous result via ara::core::Future.

Lifecycle

The lifecycle of ara::core::Promise follows strict move-only semantics and controls the existence of the underlying shared state:

  • Creation: The default constructor Promise() constructs an instance with a new, not yet satisfied shared state [SWS_CORE_00341]. It is specified as noexcept guaranteed exception-safe and thread-safe [SWS_CORE_00341].
  • Copy protection and transfer of ownership: Copy constructor [SWS_CORE_00350] and copy assignment operator [SWS_CORE_00351] are explicitly deleted (= delete). A transfer of ownership is only possible via move operations. The move constructor takes over the shared state of the source instance and is noexcept, but not thread-safe [SWS_CORE_00342]. The move assignment operator abandons a previously held shared state (abandons any shared state) and transfers the state of the other instance analogously to a subsequent swap [SWS_CORE_00343]. Two instances can also swap their state via swap() [SWS_CORE_00352].
  • Future coupling: Exactly one instance of ara::core::Future<T, E> is associated with the same shared state via get_future() [SWS_CORE_00344]. Since only one future may exist per promise, this call is permissible only once [SWS_CORE_00344].
  • State transition to ready: Supplying a value via set_value() [SWS_CORE_00345], [SWS_CORE_00346], an error via SetError() [SWS_CORE_00353], [SWS_CORE_00354], or an overall result via SetResult() [SWS_CORE_00355], [SWS_CORE_00356] irreversibly switches the shared state to the status ready. All of these satisfaction methods are declared thread-safe.
  • Destruction: The destructor ~Promise() abandons and discards the shared state (abandons any shared state) [SWS_CORE_00349]. Interpretation: If destruction occurs before setting a value or error, the orphaned shared state is likely aborted for waiting futures, analogous to the behavior of std::promise.

Usage Path

The typical call sequence for asynchronous value or error transmission comprises the following steps:

  1. Creation: The producer instantiates ara::core::Promise<T, E> via the default constructor [SWS_CORE_00341].
  2. Connect channel: Prior to passing the asynchronous task to a background thread, the producer calls get_future() [SWS_CORE_00344] and passes the resulting ara::core::Future instance to the consumer.
  3. Asynchronous processing: The producer executes the computation or the I/O operation. The consumer can continue working in parallel or wait for the Future.
  4. Set result: After completion of the operation, the producer stores the result in the shared state. Depending on the outcome, it selects:
    • Successful value: set_value() as copy [SWS_CORE_00345] or move [SWS_CORE_00346].
    • Error state: SetError() by move [SWS_CORE_00353] or copy [SWS_CORE_00354].
    • Existing Result object: SetResult() via copy [SWS_CORE_00355] or move [SWS_CORE_00356].
  5. Release: By setting the result, the shared state is marked as ready; the consumer reads the value. The Promise is destroyed upon leaving the scope [SWS_CORE_00349].

Sequence diagram: Typical call and interaction sequence for asynchronous value or error transmission. Sources: [SWS_CORE_00341], [SWS_CORE_00344], [SWS_CORE_00345], [SWS_CORE_00353], [SWS_CORE_00355].

Error Scenarios

The specification defines fixed violation conditions (violations) for impermissible calls as well as exception safety requirements:

  • Multiple future retrieval: If get_future() is called more than once for the same shared state, the violation IsoStdFutureErrcFutureAlreadyRetrievedViolation occurs [SWS_CORE_00344].
  • Operations without shared state: If *this has no shared state (e.g., after a move operation), method calls lead to documented violations:
    • get_future() reports IsoStdFutureErrcNoStateViolation [SWS_CORE_00344].
    • set_value(), SetError(), and SetResult() trigger PromiseNoSharedStateToSetViolation ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Double satisfaction: If a value, an error, or a result has already been stored in the shared state, each further call to set_value(), SetError(), or SetResult() leads to the violation IsoStdFutureErrcPromiseAlreadySatisfiedViolation ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Compile error with deviating error type: If the class template is instantiated with a type for which E != ara::core::ErrorCode holds, the build aborts mandatorily with a compile error.
  • Conditional exception safety: Constructors, destructor, assignment, move, swap, and get_future() are unconditionally noexcept and exception-safe ([SWS_CORE_00341], [SWS_CORE_00342], [SWS_CORE_00343], [SWS_CORE_00344], [SWS_CORE_00349], [SWS_CORE_00352]). The methods set_value(), SetError(), and SetResult(), on the other hand, are conditionally exception-safe (conditionally exception safe); their noexcept property depends on whether the copy or move constructors of T and E are declared as non-throwing (std::is_nothrow_*_constructible) ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
