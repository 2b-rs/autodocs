Context

The data structure ara::tsync::TimePrecisionMeasurement serves to provide detailed measurement data for evaluating the synchronization accuracy of a Time Slave within the module tsync. As part of time-synchronized communication, the structure records the time differences and synchronization parameters that occur when aligning a local time base (Local Time Base) with a higher-level global time base (Global Time Base). In addition to the local Time Slave, relevant interaction partners include the higher-level Global Time Master and intermediary instances such as a Time Gateway [SWS_TS_01403]. The structure bundles snapshots of the system state directly before and directly after the synchronization process to enable applications or diagnostic functions to accurately assess the quality and stability of clock synchronization.

Lifecycle

As a final data structure (struct final), ara::tsync::TimePrecisionMeasurement has no independent lifecycle with active state transitions or internal threads. Instances of the structure are typically created by the runtime system of the Time Slave when a synchronization cycle is run. Presumably, the structure is instantiated on the stack or within a managing synchronization component and, after data collection is complete, passed by copy or reference to evaluating functional units. Regarding concurrency, the structure is to be regarded as a passive data container: Concurrent read and write access from different threads requires external synchronization mechanisms, as no inherent synchronization locks are specified.

Usage Path

The intended use of the structure takes place in the context of a completed synchronization event. In doing so, the structure represents a self-contained snapshot of the alignment:

  • Recording the prior state: Before alignment with the Global Time Base, the Time Slave records the status of the local time. This includes the seconds in locSeconds [SWS_TS_01406] and the nanoseconds in locNanoSeconds [SWS_TS_01407].
  • Recording the post-state: Immediately after synchronization with the global time base, the updated timestamps are documented in glbSeconds [SWS_TS_01401] and glbNanoSeconds [SWS_TS_01402]. In addition, virtualLocalTimeLow represents the lower-order 32 bits of the virtual local time directly after alignment [SWS_TS_01404].
  • Transmission parameters and rate measurement: The propagation delay of the transmission path is stored in nanoseconds in the field pathDelay [SWS_TS_01408]. In addition, rateDeviation records the calculated rate deviation immediately after the rate measurement [SWS_TS_01405].
  • State validation: Finally, the synchronization status is recorded via the bit field timeBaseStatus to represent the mode and scope of validity of the measurement data [SWS_TS_01403].

Error Scenarios

Since ara::tsync::TimePrecisionMeasurement is a purely POD-like data type without method calls, the structure throws no exceptions and returns no error codes via ara::core::Result. Instead, error and exceptional situations of time synchronization manifest themselves in the values of the bit field timeBaseStatus [SWS_TS_01403]:

  • TIMEOUT (bit 0): Indicates that a timeout occurred during the reception of synchronization messages.
  • GLOBAL_TIME_BASE (bit 3): If this bit is not set, the local time base is based exclusively on the local reference clock and has never been synchronized with the global time base. According to the specification, error bits such as TIMEOUT, TIMELEAP_FUTURE, TIMELEAP_PAST, and SYNC_TO_GATEWAY can only be active if GLOBAL_TIME_BASE is set [SWS_TS_01403].
  • TIMELEAP_FUTURE (bit 4) and TIMELEAP_PAST (bit 5): Signal impermissibly large time jumps into the future or past that exceed a configured threshold value.
  • RATE_EXCEEDED (bit 7): Indicates that the rate deviation determined for the time base lies outside the defined limit values.

This guide is based on the AUTOSAR Adaptive R25-11 specification for the module tsync.

                          std::uint8_t timeBaseStatus;
                          

                          TimeBaseStatus. Time Base Status of the Local Time Base directly after synchronization with the Global Time Base TIMEOUT 0x01 Bit 0 (LSB): 0x00: No Timeout on receiving Synchronisation Messages 0x01: Timeout on receiving Synchronisation Messages SYNC_TO_GATEWAY 0x04 Bit 2 0x00: Local Time Base is synchronous to Global Time Master 0x04: Local Time Base updates are based on a Time Gateway below the Global Time Master GLOBAL_TIME_BASE 0x08 Bit 3 0x00: Local Time Base is based on Local Time Base reference clock only (never synchronized with Global Time Base) 0x08: Local Time Base was at least synchronized with Global Time Base one time TIMELEAP_FUTURE 0x10 Bit 4 0x00: No leap into the future within the received time for Time Base, 0x10: Leap into the future within the received time for Time Base exceeds a configured threshold TIMELEAP_ PAST 0x20 Bit 5 0x00: No leap into the past within the received time for Time Base 0x20: Leap into the past within the received time for Time Base exceeds a configured threshold.
                          Bit 6 RATE_CORRECTED 0x00: Valid rate correction not calculated for the Synchronized Time Base, 0x40: Valid rate correction calculated for the Synchronized Time Base. Bit 7 RATE_EXCEEDED 0x00: Calculated rate for Time Base does not exceed limits, 0x80: Calculated rate for Time Base exceeds limits. Description Bit 1 is always 0 (reserved for future usage) Variables of this type are used to express if and how a Local Time Base is synchronized to the Global Time Master. The type is a bitfield of individual status bits, although not every combination is possible, i.e. any of the bits TIMEOUT, TIMELEAP_ FUTURE, TIMELEAP_PAST and SYNC_TO_GATEWAY can only be set if the GLOBAL_ TIME_BASE bit is set.

<h4>Context</h4>
<p>The data structure <code>ara::tsync::TimePrecisionMeasurement</code> serves to provide detailed measurement data for evaluating the synchronization accuracy of a Time Slave within the module <code>tsync</code>. As part of time-synchronized communication, the structure records the time differences and synchronization parameters that occur when aligning a local time base (Local Time Base) with a higher-level global time base (Global Time Base). In addition to the local Time Slave, relevant interaction partners include the higher-level Global Time Master and intermediary instances such as a Time Gateway <a class="spec-record-ref" data-req="SWS_TS_01403" href="../spec/record.html?id=SWS_TS_01403">[SWS_TS_01403]</a>. The structure bundles snapshots of the system state directly before and directly after the synchronization process to enable applications or diagnostic functions to accurately assess the quality and stability of clock synchronization.</p>

<h4>Lifecycle</h4>
<p>As a final data structure (<code>struct final</code>), <code>ara::tsync::TimePrecisionMeasurement</code> has no independent lifecycle with active state transitions or internal threads. Instances of the structure are typically created by the runtime system of the Time Slave when a synchronization cycle is run. Presumably, the structure is instantiated on the stack or within a managing synchronization component and, after data collection is complete, passed by copy or reference to evaluating functional units. Regarding concurrency, the structure is to be regarded as a passive data container: Concurrent read and write access from different threads requires external synchronization mechanisms, as no inherent synchronization locks are specified.</p>

<h4>Usage Path</h4>
<p>The intended use of the structure takes place in the context of a completed synchronization event. In doing so, the structure represents a self-contained snapshot of the alignment:</p>
<ul>
  <li><strong>Recording the prior state:</strong> Before alignment with the Global Time Base, the Time Slave records the status of the local time. This includes the seconds in <code>locSeconds</code> <a class="spec-record-ref" data-req="SWS_TS_01406" href="../spec/record.html?id=SWS_TS_01406">[SWS_TS_01406]</a> and the nanoseconds in <code>locNanoSeconds</code> <a class="spec-record-ref" data-req="SWS_TS_01407" href="../spec/record.html?id=SWS_TS_01407">[SWS_TS_01407]</a>.</li>
  <li><strong>Recording the post-state:</strong> Immediately after synchronization with the global time base, the updated timestamps are documented in <code>glbSeconds</code> <a class="spec-record-ref" data-req="SWS_TS_01401" href="../spec/record.html?id=SWS_TS_01401">[SWS_TS_01401]</a> and <code>glbNanoSeconds</code> <a class="spec-record-ref" data-req="SWS_TS_01402" href="../spec/record.html?id=SWS_TS_01402">[SWS_TS_01402]</a>. In addition, <code>virtualLocalTimeLow</code> represents the lower-order 32 bits of the virtual local time directly after alignment <a class="spec-record-ref" data-req="SWS_TS_01404" href="../spec/record.html?id=SWS_TS_01404">[SWS_TS_01404]</a>.</li>
  <li><strong>Transmission parameters and rate measurement:</strong> The propagation delay of the transmission path is stored in nanoseconds in the field <code>pathDelay</code> <a class="spec-record-ref" data-req="SWS_TS_01408" href="../spec/record.html?id=SWS_TS_01408">[SWS_TS_01408]</a>. In addition, <code>rateDeviation</code> records the calculated rate deviation immediately after the rate measurement <a class="spec-record-ref" data-req="SWS_TS_01405" href="../spec/record.html?id=SWS_TS_01405">[SWS_TS_01405]</a>.</li>
  <li><strong>State validation:</strong> Finally, the synchronization status is recorded via the bit field <code>timeBaseStatus</code> to represent the mode and scope of validity of the measurement data <a class="spec-record-ref" data-req="SWS_TS_01403" href="../spec/record.html?id=SWS_TS_01403">[SWS_TS_01403]</a>.</li>
</ul>

<h4>Error Scenarios</h4>
<p>Since <code>ara::tsync::TimePrecisionMeasurement</code> is a purely POD-like data type without method calls, the structure throws no exceptions and returns no error codes via <code>ara::core::Result</code>. Instead, error and exceptional situations of time synchronization manifest themselves in the values of the bit field <code>timeBaseStatus</code> <a class="spec-record-ref" data-req="SWS_TS_01403" href="../spec/record.html?id=SWS_TS_01403">[SWS_TS_01403]</a>:</p>
<ul>
  <li><code>TIMEOUT</code> (bit 0): Indicates that a timeout occurred during the reception of synchronization messages.</li>
  <li><code>GLOBAL_TIME_BASE</code> (bit 3): If this bit is not set, the local time base is based exclusively on the local reference clock and has never been synchronized with the global time base. According to the specification, error bits such as <code>TIMEOUT</code>, <code>TIMELEAP_FUTURE</code>, <code>TIMELEAP_PAST</code>, and <code>SYNC_TO_GATEWAY</code> can only be active if <code>GLOBAL_TIME_BASE</code> is set <a class="spec-record-ref" data-req="SWS_TS_01403" href="../spec/record.html?id=SWS_TS_01403">[SWS_TS_01403]</a>.</li>
  <li><code>TIMELEAP_FUTURE</code> (bit 4) and <code>TIMELEAP_PAST</code> (bit 5): Signal impermissibly large time jumps into the future or past that exceed a configured threshold value.</li>
  <li><code>RATE_EXCEEDED</code> (bit 7): Indicates that the rate deviation determined for the time base lies outside the defined limit values.</li>
</ul>
