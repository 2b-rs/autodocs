Context

The ara::tsync::SynchronizedTimeBaseProvider class provides access to a synchronized time base addressed via an instance identifier (ara::core::InstanceSpecifier) ([SWS_TS_01101]). Within the AUTOSAR Adaptive architecture, it serves as a dedicated interface for time-providing applications (Time Provider Applications). Its central responsibility includes setting and updating timestamps for the communication bus ([SWS_TS_01107], [SWS_TS_01108]), readjusting clock rates ([SWS_TS_01110]), managing application-specific user data ([SWS_TS_01112]), and receiving validation data ([SWS_TS_01114]).

At least three participants are involved in the interaction: the provider application, the provider class instance, and the Time Sync Daemon, which manages the connection and coordinates physical transmission on the bus ([SWS_TS_01107]).

Context diagram: Interaction partners of the SynchronizedTimeBaseProvider during time provision. Sources: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01108].

Life cycle and concurrency

Creation takes place explicitly via the constructor using a ara::core::InstanceSpecifier ([SWS_TS_01101]). The linked PortPrototype must strictly be typed by a SynchronizedTimeBaseProviderInterface; otherwise, a PortInterfaceMappingViolation is present ([SWS_TS_01101]).

Regarding ownership, the class implements exclusive move-only semantics:

  • The copy constructor ([SWS_TS_01104]) and copy assignment operator ([SWS_TS_01105]) are deleted (=delete), thereby precluding duplicates of the access interface.
  • The move constructor ([SWS_TS_01102]) and move assignment operator ([SWS_TS_01103]) are available and secured with noexcept.
  • Destruction takes place via the destructor ([SWS_TS_01106]).

Regarding thread safety, the interface strictly separates between querying and modifying operations:

  • The constructor ([SWS_TS_01101]) and the reading methods GetCurrentTime ([SWS_TS_01109]), GetRateDeviation ([SWS_TS_01111]), and GetUserData ([SWS_TS_01113]) are thread-safe (thread-safe).
  • State-modifying operations such as SetTime ([SWS_TS_01107]), UpdateTime ([SWS_TS_01108]), SetRateCorrection ([SWS_TS_01110]), SetUserData ([SWS_TS_01112]), RegisterTimeValidationNotification ([SWS_TS_01114]), UnregisterTimeValidationNotification ([SWS_TS_01115]) as well as move operations and the destructor ([SWS_TS_01106]) are classified as not thread-safe (non_threadsafe) and require external synchronization.

Usage Path

A typical usage path for providing synchronized time information is structured as follows:

  1. Instantiation: The application creates the provider instance by passing the configured InstanceSpecifier ([SWS_TS_01101]).
  2. Notification registration: If synchronization parameters are to be validated, the application registers a notification object via RegisterTimeValidationNotification ([SWS_TS_01114]). At most one notifier can be registered at a time; renewed calls overwrite the existing registration ([SWS_TS_01114]).
  3. Time update: Two mechanisms are available for transmission:
    • SetTime: Updates the time and immediately triggers the transmission on the bus ([SWS_TS_01107]).
    • UpdateTime: Only updates the time value locally; the actual bus transmission takes place cyclically in the next transmission interval ([SWS_TS_01108]).
  4. Correction and status: If needed, the clock rate can be adjusted via SetRateCorrection ([SWS_TS_01110]). In addition, status values such as the current time ([SWS_TS_01109]) or the rate deviation ([SWS_TS_01111]) can be read out.
  5. Deregistration: Before tearing down the instance, an explicit deregistration of the notifier via UnregisterTimeValidationNotification is presumably advisable ([SWS_TS_01115]).

Sequence diagram: Typical call sequence for time provision and notification registration. Sources: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01114], [SWS_TS_01115].

Error Scenarios

Modifying methods report errors via return objects of type ara::core::Result<void>. Failed calls have no rollback semantics (no_rollback_semantics):

Method Error code Condition and impact
SetTime, UpdateTime, SetUserData TsyncErrc::kInvalidUserDataSize The passed user data exceeds the upper limit defined by UserData::kMaxUserDataSize (currently 3 bytes) ([SWS_TS_01107], [SWS_TS_01108], [SWS_TS_01112]).
SetTime TsyncErrc::kDaemonConnectionLost The connection to the Time Sync Daemon is interrupted; the action cannot be executed ([SWS_TS_01107]).
SetRateCorrection TsyncErrc::kLimitsExceeded The correction factor violates the permissible value range ([SWS_TS_01110]). A factor less than 1.0 slows down the clock, a value greater than 1.0 speeds it up ([SWS_TS_01110]).
SetRateCorrection TsyncErrc::kFunctionNotSupported Rate correction is not supported for the addressed time base ([SWS_TS_01110]).

All methods are specified as exception-safe (exception safe) and marked with noexcept. Read methods such as GetCurrentTime ([SWS_TS_01109]) return the time without error regardless of the current synchronization status.
