Context

The struct ara::diag::EventStatusByte represents the current, bit-coded status of a diagnostic event within the diag module of the AUTOSAR Adaptive Platform [SWS_DM_00644]. As a lightweight data object, it encapsulates the individual status bits of an event and provides typed query methods. The header file #include "ara/diag/event_types.h" defines the type and associated helper structures.

In the overall system, EventStatusByte primarily interacts with Diagnostic Management (DM) and the Adaptive Application. An essential architectural aspect is the decoupling of event combinations: The calculation of EventStatusByte is not influenced by event combinations, so that the object always reflects the exact state of the individual associated event AUTOSAR_AP_SWS_Diagnostics p. 234. If an event combination occurs, the DM separately calculates the superordinate combined DTC status [SWS_DM_01109] and triggers configured callbacks [SWS_DM_01110]. Likewise, the DM forwards clear operations to all associated individual events [SWS_DM_01108]. Via the function alias ara::diag::EventStatusByteNotifier [SWS_DM_02118], applications can directly receive status changes and evaluate them based on the struct.

Context diagram: Interaction of Diagnostic Management, EventStatusByte, application, and combined DTC status. Sources: [SWS_DM_00644], [SWS_DM_01108], [SWS_DM_01109], [SWS_DM_01110], [SWS_DM_02118], AUTOSAR_AP_SWS_Diagnostics p. 234.

Lifecycle

EventStatusByte is designed as a pure value type and does not have a dynamic state machine. Its lifetime is governed by regular C++ scopes (stack allocation or embedding in notifier signatures):

  • Creation: Via a variadic template constructor EventStatusByte(Args... bits) [SWS_DM_01753], an object can be initialized with an arbitrary number of set EventStatusBits. A copy constructor [SWS_DM_01752] and a move constructor [SWS_DM_01751] are available for value transfers. All constructors are declared as constexpr and noexcept.
  • Assignment and copy: Instances can be assigned via the copy assignment operator [SWS_DM_01750] or the move assignment operator [SWS_DM_01749]. Both operators return a self-reference and throw no exceptions.
  • Destruction: As a stateless struct without dynamic resource management, deallocation occurs trivially upon leaving scope; a user-defined destructor is likely omitted.
  • Concurrency: The constructors ([SWS_DM_01751], [SWS_DM_01753]) and all reading bit checks are thread-safe. The assignment operators operator= ([SWS_DM_01749], [SWS_DM_01750]), however, are explicitly specified as not thread-safe. Modifying a shared instance by concurrent threads therefore requires external synchronization.

Usage Path

A typical usage path in diagnostic monitors or evaluation routines comprises three phases:

  1. Reception or creation: The application receives the EventStatusByte either via callback through the type alias EventStatusByteNotifier [SWS_DM_02118] or specifically creates an instance for status checking via the variadic constructor [SWS_DM_01753].
  2. Checking individual or multiple bits:
    • IsSet(bits...): Returns true if all passed bits are set [SWS_DM_01755].
    • IsNotSet(bits...): Returns true if all passed bits are unset [SWS_DM_01754].
  3. Aggregated state queries:
    • IsFailedAndTested(): Returns true if both bit kTestFailed and bit kTestFailedThisOperationCycle are set [SWS_DM_01757].
    • IsPassedAndTested(): Returns true if neither kTestFailed nor kTestNotCompletedThisOperationCycle is set (both unset) [SWS_DM_01756].

Since all query operations are declared as constexpr, evaluations and maskings can be evaluated at compile time if required.

Error Scenarios

The struct EventStatusByte is characterized by a robust, error-free design:

  • Exception safety: All member functions, including all constructors, assignment operators, and predicates, are declared with noexcept and classified as exception-safe (exception safe) ([SWS_DM_01749] to [SWS_DM_01757]). Neither C++ exceptions are thrown nor are ara::core::Result error codes returned.
  • Pre- and postconditions: No restrictive preconditions exist for the method calls. The predicates perform full logical AND operations over the passed bit patterns and deliver deterministic boolean results. Only in the case of concurrent write operations via operator= must the caller ensure that no data races occur.

<h4>Context</h4>
<p>The struct <code>ara::diag::EventStatusByte</code> represents the current, bit-coded status of a diagnostic event within the <code>diag</code> module of the AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_00644" href="../spec/record.html?id=SWS_DM_00644">[SWS_DM_00644]</a>. As a lightweight data object, it encapsulates the individual status bits of an event and provides typed query methods. The header file <code>#include "ara/diag/event_types.h"</code> defines the type and associated helper structures.</p>
<p>In the overall system, <code>EventStatusByte</code> primarily interacts with Diagnostic Management (DM) and the Adaptive Application. An essential architectural aspect is the decoupling of event combinations: The calculation of <code>EventStatusByte</code> is not influenced by event combinations, so that the object always reflects the exact state of the individual associated event <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=234">AUTOSAR_AP_SWS_Diagnostics p. 234</a>. If an event combination occurs, the DM separately calculates the superordinate combined DTC status <a class="spec-record-ref" data-req="SWS_DM_01109" href="../spec/record.html?id=SWS_DM_01109">[SWS_DM_01109]</a> and triggers configured callbacks <a class="spec-record-ref" data-req="SWS_DM_01110" href="../spec/record.html?id=SWS_DM_01110">[SWS_DM_01110]</a>. Likewise, the DM forwards clear operations to all associated individual events <a class="spec-record-ref" data-req="SWS_DM_01108" href="../spec/record.html?id=SWS_DM_01108">[SWS_DM_01108]</a>. Via the function alias <code>ara::diag::EventStatusByteNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_02118" href="../spec/record.html?id=SWS_DM_02118">[SWS_DM_02118]</a>, applications can directly receive status changes and evaluate them based on the struct.</p>
