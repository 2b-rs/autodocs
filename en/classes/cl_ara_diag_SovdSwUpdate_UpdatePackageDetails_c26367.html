Context

The data structure ara::diag::SovdSwUpdate::UpdatePackageDetails ([SWS_DM_01877], AUTOSAR_AP_SWS_Diagnostics §8.58.4 “Struct: UpdatePackageDetails”) serves within the AUTOSAR Adaptive Platform in the diag module as a structured information carrier for the metadata and execution parameters of a software update package. It is declared in the header #include "ara/diag/sovd_sw_update.h" and represents an essential interface entity for software-related diagnostic and update processes provided via the ASAM SOVD (Service-Oriented Vehicle Diagnostics) standard ([SWS_DM_01796]).

The architectural embedding follows the functional division of responsibilities of the SOVD software update (AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API”): Since the actual business logic for software updates is not executed within the Diagnostics Functional Cluster, the domain implementation lies primarily with the respective application. The ara::diag::SovdSwUpdate::SovdSwUpdate instance of the diagnostic server focuses on handling the underlying SOVD protocol in accordance with ASAM SOVD ([SWS_DM_01796]). In this context, UpdatePackageDetails acts as a standardized transfer object with which the application provides detailed package data to the diagnostic server via the API function ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”) so that it can serve external SOVD clients.

The regular use of UpdatePackageDetails takes place in the course of the standardized SOVD methods for querying software update details ([SWS_DM_01796]). Often, the client first retrieves a list of all available updates ([SWS_DM_01797]) before specifically requesting package details.

The call sequence is as follows:

  1. Request by SOVD client: An external diagnostic client sends a request for the details of a specific software package to the Diagnostic Server Instance ([SWS_DM_01796]).
  2. Forwarding to the application: The Diagnostic Server delegates the determination of details via ara::diag::SovdSwUpdate::GetUpdatePackageDetails to the registered application ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”).

  4. Return: Interpretation: The application is likely to return the populated UpdatePackageDetails object directly to the Diagnostic Server as the function result of GetUpdatePackageDetails.
  5. Protocol response: Interpretation: The Diagnostic Server presumably handles the serialization of the C++ attributes into the standardized SOVD response format and delivers it to the requesting client ([SWS_DM_01796]).
