Enables waiting for the completion of an asynchronous operation without a return value and retrieving the error status.

The class ara::core::Future<void, E> enables asynchronous synchronization and error checking for operations without a return value in AUTOSAR Adaptive [SWS_CORE_06236]. As a non-copyable type, it allows waiting for completion as well as exception-safe result retrieval as ara::core::Result<void, E> [SWS_CORE_06236] or asynchronous continuation via a continuation function [SWS_CORE_06231]. After retrieving the result, the shared state is invalidated such that subsequent calls without a valid state constitute a violation [SWS_CORE_06236].

Context

The template class specialization ara::core::Future<void, E> represents the receiving end of an asynchronous operation in AUTOSAR Adaptive that does not return a value upon successful completion, but purely signals the occurrence of the event or an error that occurred. According to the class description, the implementation must terminate the condition E != ara::core::ErrorCode with a compilation error. The class typically interacts with a corresponding ara::core::Promise, which populates the shared state [SWS_CORE_06236], as well as with asynchronous execution contexts when registering continuation functions [SWS_CORE_06237].

Lifecycle

Instances of ara::core::Future<void, E> are move-only objects: the copy constructor [SWS_CORE_06234] and copy assignment operator [SWS_CORE_06235] are deleted (delete). An object created via the default constructor has no shared state and behaves analogously to std::future [SWS_CORE_06222]. By means of move construction [SWS_CORE_06223] or move assignment [SWS_CORE_06225], an instance takes ownership of a shared state from another instance.

The lifecycle is largely defined by the state of the shared state. Via the method valid(), it can be checked whether the instance is bound to a shared state and thus usable [SWS_CORE_06227]. As soon as the result is retrieved by means of GetResult() [SWS_CORE_06236] or get() [SWS_CORE_06226], or a continuation is registered via then() [SWS_CORE_06231], the future object loses its shared state and valid() returns false. The destructor releases any remaining shared state [SWS_CORE_06233]. With regard to concurrency, inspection and destruction operations such as valid() [SWS_CORE_06227], is_ready() [SWS_CORE_06232], and the destructor [SWS_CORE_06233] are thread-safe, whereas state-mutating operations such as GetResult() [SWS_CORE_06236], get() [SWS_CORE_06226], and the waiting functions [SWS_CORE_06228] are not thread-safe.

Usage Path

In the synchronous usage path, a consumer waits for the completion of the asynchronous operation. With is_ready(), it can be queried in a low-blocking manner whether a value or an error is present [SWS_CORE_06232]. Alternatively, blocking wait can be performed by means of wait() [SWS_CORE_06228], or with a time limit via wait_for() [SWS_CORE_06229] and wait_until() [SWS_CORE_06230]. Once the result is available, value retrieval is preferably performed in an exception-safe manner via GetResult(), whereby a ara::core::Result<void, E> is returned [SWS_CORE_06236].

In the asynchronous path, the method then() allows registering a continuation function that is executed as soon as the result is available [SWS_CORE_06231]. An execution context (Executor) can optionally be passed here [SWS_CORE_06237]. The continuation takes the Result<void, E> as an rvalue. The return type of then() automatically unwraps nested Future or Result types [SWS_CORE_06231].

Error Scenarios

If a state-dependent operation (such as GetResult(), is_ready(), wait(), wait_for(), wait_until(), or then()) is called on an invalid instance (valid() == false), a precondition violation occurs, which is handled as FutureInvalidViolation [SWS_CORE_06228], [SWS_CORE_06229], [SWS_CORE_06230], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06236], [SWS_CORE_06237]. Calling get() on an invalid instance instead throws a FutureException with the error code kNoState [SWS_CORE_06226]; get() does not participate in overload resolution when C++ exceptions are disabled [SWS_CORE_06226].

If the corresponding promise was destroyed or has abandoned the shared state without setting a result or an explicit error, the error code FutureErrc::kBrokenPromise is stored in the shared state according to [SWS_CORE_00400] [SWS_CORE_06226], [SWS_CORE_06236]. This is returned by GetResult() as an error in the Result<void, E> [SWS_CORE_06236]. If a continuation registered in then() throws an exception that does not implement a violation, this leads to FutureContinuationHasThrownViolation [SWS_CORE_06231], [SWS_CORE_06237].
