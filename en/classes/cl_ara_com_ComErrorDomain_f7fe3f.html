General communication errors

ComErrorDomain consolidates the recoverable errors of standardized ara::com operations. An Result or an asynchronous Future can thus supply an ComErrc code instead of a value. EXP ARAComAPI §4.7 “Error Handling” defines the Result/ErrorCode model.

Use domain

Name() describes the domain, Message() the individual error and ThrowAsException() supports the exception mapping. Technical logic should respond to the domain and the enumerated code first in the event of an error; E2E and FVM errors are deliberately separated by their own domains. SWS CM §7.5.22 “API Data Types” classifies error data as API types.
