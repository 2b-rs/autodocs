intended use

SovdProximityChallenge implements the SOVD interface for proximity challenges. GetChallenge() returns a challenge generated by the application including the validity date; If proximity proof is required for an SOVD operation, the Diagnostic Server puts this value in the corresponding response. [SWS_DM_01481] [SWS_DM_01494] [SWS_DM_01398] ValidateResponse() checks the response provided by the client. [SWS_DM_01493] [SWS_DM_01395]

Creation & lifecycle

The constructor binds a PortPrototype of DiagnosticSovdProximityChallengeInterface and accepts the concurrency specification. [SWS_DM_01480] Offer() enables, and StopOffer() disables, forwarding by the DM. An Offer can return kAlreadyOffered or kConfigurationMismatch. [SWS_DM_01478] [SWS_DM_01495] The destructor is exception-safe. [SWS_DM_01479]

Limitations & Error handling

The proximity response is only valid until promise fulfillment or cancellation processing. [SWS_DM_01493] To schedule a SOVD operation, the Diagnostic Server must check an existing proximity_response with ValidateResponse(). [SWS_DM_01391] GetChallenge and ValidateResponse depend on ConcurrencyType for thread safety; Offer and StopOffer are not thread-safe. [SWS_DM_01494] [SWS_DM_01493] [SWS_DM_01478] [SWS_DM_01495]

GetChallenge() and ValidateResponse() deliver their results asynchronously and do not specify standardized errors. [SWS_DM_01494] [SWS_DM_01493] The DM considers a proximity challenge valid if validation returns kProximityChallengeValidationSuccessful. [SWS_DM_01395] The constructor itself is thread-safe, while the destructor is not thread-safe. [SWS_DM_01480] [SWS_DM_01479]

The challenge itself and its validity are transmitted by GetChallenge() as a return value. [SWS_DM_01494]

SOVD access context

An SOVD proximity challenge requests proof of proximity before executing an SOVD operation. The interface SovdProximityChallenge passes the challenge procedure to the application and informs the Diagnostic Manager of the result; on this basis he carries out the operation.
