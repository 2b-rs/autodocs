Context

The class ara::rds::RdsErrorDomain represents the central error domain for the Raw Data Stream (RDS) module within the AUTOSAR Adaptive Platform in release R25-11. It is declared as final and inherits from the base class ara::core::ErrorDomain. Its primary task is the unique identification, classification, and textual description of errors that occur within the functional scope of RDS.

As a specialized form of ara::core::ErrorDomain, RdsErrorDomain links several types and components of the error system:

  • The error enumeration RdsErrc, which is directly available in the class scope via the typed alias Errc ([SWS_RDS_11326]).
  • The exception type RdsException, which is anchored within the domain via the alias Exception ([SWS_RDS_11327]).
  • The standard error object ara::core::ErrorCode, which connects a concrete error code from Errc with the instance of RdsErrorDomain.
  • Application code and framework services that query error messages via Name() ([SWS_RDS_11295]) and Message() ([SWS_RDS_11296]) or forward errors for exception handling.

Lifecycle

The creation of objects of class RdsErrorDomain is subject to restrictive specifications: The default constructor is explicitly defined as deleted (RdsErrorDomain() = delete, [SWS_RDS_11294]). Direct or multiple instantiation by user applications on the stack or heap is therefore excluded.

The provision of the domain instance is likely to take place internally via a long-lived or static singleton object, as typically a single global instance exists per error domain in the AUTOSAR Adaptive error model. Due to the declaration as final, specialization via inheritance is prevented.

With respect to concurrency, the class behaves statelessly. The inspection methods Name() ([SWS_RDS_11295]) und Message() ([SWS_RDS_11296]) are declared as const noexcept. They do not modify any internal states and allow simultaneous, concurrent read access from multiple threads without synchronization overhead.

Usage Path

In regular operation, the class is rarely instantiated directly by application code; instead, it serves as a backend for ara::core::ErrorCode and ara::core::Result. A typical sequence during error handling is as follows:

  1. An operation within module rds fails and produces an error value of enumeration type Errc ([SWS_RDS_11326]).
  2. The error value is encapsulated in an ara::core::ErrorCode in conjunction with the RdsErrorDomain and passed to the caller.
  3. The application checks the error object. Via Name() ([SWS_RDS_11295]), it can be verified that the error originates from the RDS error domain.
  4. For diagnosis or logging, the system calls Message() ([SWS_RDS_11296]) to retrieve the textual message associated with the error code.
  5. If an exception mechanism is chosen, calling ErrorCode::ThrowAsException() delegates to the method RdsErrorDomain::ThrowAsException() ([SWS_RDS_11297]), thereby triggering an exception of type Exception ([SWS_RDS_11327]).

Error Scenarios

RdsErrorDomain itself serves to handle error situations and defines robust guarantees for its interfaces:

  • Error codes: Specific causes are represented by the enumeration RdsErrc, which is typed as Errc ([SWS_RDS_11326]).
  • Exception safety of queries: The methods Name() ([SWS_RDS_11295]) and Message(CodeType errorCode) ([SWS_RDS_11296]) are specified as noexcept. They guarantee that no further exceptions are thrown even in the event of resource bottlenecks or errors. If an unknown error code is passed, a generic fallback text is presumably returned to maintain the noexcept guarantee.
  • Exception throwing: The method ThrowAsException(const ara::core::ErrorCode &errorCode) is declared with noexcept(false) ([SWS_RDS_11297]). It deterministically throws an instance of RdsException ([SWS_RDS_11327]). The precondition is a valid ErrorCode object; a regular return does not take place.

<h4>Lifecycle</h4>
<p>The creation of objects of class <code>RdsErrorDomain</code> is subject to restrictive specifications: The default constructor is explicitly defined as deleted (<code>RdsErrorDomain() = delete</code>, <a class="spec-record-ref" data-req="SWS_RDS_11294" href="../spec/record.html?id=SWS_RDS_11294">[SWS_RDS_11294]</a>). Direct or multiple instantiation by user applications on the stack or heap is therefore excluded.</p>
<p>The provision of the domain instance is likely to take place internally via a long-lived or static singleton object, as typically a single global instance exists per error domain in the AUTOSAR Adaptive error model. Due to the declaration as <code>final</code>, specialization via inheritance is prevented.</p>
<p>With respect to concurrency, the class behaves statelessly. The inspection methods <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>) und <code>Message()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) are declared as <code>const noexcept</code>. They do not modify any internal states and allow simultaneous, concurrent read access from multiple threads without synchronization overhead.</p>

<h4>Usage Path</h4>
<p>In regular operation, the class is rarely instantiated directly by application code; instead, it serves as a backend for <code>ara::core::ErrorCode</code> and <code>ara::core::Result</code>. A typical sequence during error handling is as follows:</p>
<ol>
<li>An operation within module <code>rds</code> fails and produces an error value of enumeration type <code>Errc</code> (<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>).</li>
<li>The error value is encapsulated in an <code>ara::core::ErrorCode</code> in conjunction with the <code>RdsErrorDomain</code> and passed to the caller.</li>
<li>The application checks the error object. Via <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>), it can be verified that the error originates from the RDS error domain.</li>
<li>For diagnosis or logging, the system calls <code>Message()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) to retrieve the textual message associated with the error code.</li>
<li>If an exception mechanism is chosen, calling <code>ErrorCode::ThrowAsException()</code> delegates to the method <code>RdsErrorDomain::ThrowAsException()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>), thereby triggering an exception of type <code>Exception</code> (<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p><code>RdsErrorDomain</code> itself serves to handle error situations and defines robust guarantees for its interfaces:</p>
<ul>
<li><strong>Error codes:</strong> Specific causes are represented by the enumeration <code>RdsErrc</code>, which is typed as <code>Errc</code> (<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>).</li>
<li><strong>Exception safety of queries:</strong> The methods <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>) and <code>Message(CodeType errorCode)</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) are specified as <code>noexcept</code>. They guarantee that no further exceptions are thrown even in the event of resource bottlenecks or errors. If an unknown error code is passed, a generic fallback text is presumably returned to maintain the <code>noexcept</code> guarantee.</li>
<li><strong>Exception throwing:</strong> The method <code>ThrowAsException(const ara::core::ErrorCode &amp;errorCode)</code> is declared with <code>noexcept(false)</code> (<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>). It deterministically throws an instance of <code>RdsException</code> (<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>). The precondition is a valid <code>ErrorCode</code> object; a regular return does not take place.</li>
</ul>
