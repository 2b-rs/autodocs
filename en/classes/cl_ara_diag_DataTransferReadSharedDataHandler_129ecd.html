intended use

DataTransferReadSharedDataHandler implements read data transfers after RequestReadFile or RequestReadDirectory through a shared data view. Read() returns the complete file or directory content as a byte span from application memory and receives an ReleaseHandler. [SWS_DM_01497] [SWS_DM_01504]

Ownership & Lifecycle

The application remains responsible for the provisioned memory until the ReleaseHandler signals a release. The ReleaseHandler must be saved for the relevant MetaInfo and used until a new handler for the same UDS client. The handler cannot be copied per file transfer session, but is movable and may only be destroyed after ExitRead(). [SWS_DM_01504] [SWS_DM_01501] [SWS_DM_01500] [SWS_DM_01502] [SWS_DM_01499] [SWS_DM_01505]

Limitations & Error handling

Read and ExitRead receive MetaInfo and CancellationHandler. ExitRead terminates the transfer and returns data for a positive response or an error from DiagUdsNrcErrc. The methods are exception-safe and not thread-safe. [SWS_DM_01504] [SWS_DM_01505]

function Read [SWS_DM_01504] Upstream: RS_Diag_04135

virtual auto Read (ReleaseHandler release_handler, MetaInfo const &meta_info, CancellationHandler cancellation_handler) noexcept -> ara::core::Future< ara::core::Span< ara::core::Byte > >=0;

Provides the whole data to be read out from the application in form of a shared data view. The whole file/directory info content to be sent back to the UDS client will be allocated by the application and its shared ownership (view over the memory location) is passed as a result to AraDiag. The allocated memory must be kept until the ReleaseHandler’s notifier is invoked or the status polled, signalling that the memory, addressed by the Span now can safely be released.
