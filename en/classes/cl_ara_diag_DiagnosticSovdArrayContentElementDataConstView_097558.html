Enables thread-safe, read-only access to array elements of an SOVD diagnostic data object.

The class ara::diag::DiagnosticSovdArrayContentElementDataConstView provides a read-only view of an array-type DiagnosticSovdContentElementData for efficient diagnostic queries [SWS_DM_02248]. Applications first check the integrity status using HasError() and then access the array elements either randomly via operator[] or iteratively via CBegin() and CEnd() [SWS_DM_02253]. All operations are designed to be thread-safe and exception-safe (noexcept), but require the ongoing validity of the referenced base element.

Context

The class ara::diag::DiagnosticSovdArrayContentElementDataConstView provides a read-only view (const view) of an array-type diagnostic data element within the Adaptive AUTOSAR diagnostic architecture for SOVD (Service-Oriented Vehicle Diagnostics) [SWS_DM_02248] (AUTOSAR_AP_SWS_Diagnostics §8.60.3 “Class: DiagnosticSovdArrayContentElementDataConstView”). It enables controlled read access to sequential elements of diagnostic content without having to copy the underlying data buffer.

The primary interaction partners of the class include:

  • the calling diagnostic application evaluating array data,
  • the referenced DiagnosticSovdContentElementData, which stores the concrete array elements and is referenced upon random access via [SWS_DM_02253],
  • the helper type DiagnosticSovdArrayContentElementDataConstIterator, which is created for standard-compliant iterations over the array elements [SWS_DM_02254].

Context diagram: Embedding of the view between diagnostic application, base element, and iterators. Sources: [SWS_DM_02248], [SWS_DM_02253], [SWS_DM_02254].

Lifecycle

The class is available via the header #include "ara/diag/diagnostic_sovd_content_element_data.h" [SWS_DM_02248]. As a pure view class, it does not own the actual array data. Interpretation: The lifetime of a view instance is tied to the validity of the underlying DiagnosticSovdContentElementData; the data object must remain in memory for the duration of the view's use.

Regarding concurrency, all member functions of the class are explicitly declared as thread-safe [SWS_DM_02250], [SWS_DM_02253]. Multiple threads can thus simultaneously access the same view instance for reading (interpretation: as long as the underlying data object is not concurrently modified by write operations). In addition, all methods guarantee full exception safety (exception safe) and are without exception specified with noexcept [SWS_DM_02249], [SWS_DM_02251]. Since it is an immutable view, the class exhibits no internal state transitions or complex lifecycle phases.

Usage Path

The regular procedure for using the array data is divided into integrity checking, dimension querying, and data extraction:

  1. Integrity check: Before accessing, the application should verify via HasError() whether the content element is present without errors [SWS_DM_02249].
  2. Dimension query: Using Empty(), it can be checked whether the array contains elements ([SWS_DM_02252], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.5 “Empty”). The current number of elements is returned by Size() [SWS_DM_02250], while Capacity() returns the reserved capacity of the array ([SWS_DM_02251], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.4 “Capacity”).
  3. Data access: Two paths are available for accessing array elements:
    • Random access by index: A reference to the target element is requested via operator[](std::size_t index), encapsulated in ara::core::Result<std::reference_wrapper<DiagnosticSovdContentElementData const>> [SWS_DM_02253].
    • Sequential iteration: For linear passes, Begin() ([SWS_DM_02254], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.1 “Begin”) and End() [SWS_DM_02255] as well as their explicitly constant variants CBegin() ([SWS_DM_02256], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.2 “CBegin”) and CEnd() ([SWS_DM_02257], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.3 “CEnd”) each provide a DiagnosticSovdArrayContentElementDataConstIterator.

Sequence diagram: Typical sequence for error checking, size determination, and element retrieval. Sources: [SWS_DM_02249], [SWS_DM_02250], [SWS_DM_02253], [SWS_DM_02256], [SWS_DM_02257].

Error Scenarios

The class does not use C++ exceptions and reports functional errors via ara::core::Result:

  • Erroneous data content: If the content element contains faulty data, HasError() does not return an empty success result, but an error code of type ara::diag::DiagSovdErrc [SWS_DM_02249].
  • Type mismatch during index access: The operator[] strictly requires that the referenced element actually is of type ArrayContentElementData [SWS_DM_02253]. If this is not the case, the call fails and returns a corresponding error object in Result instead of a reference.
  • Index bounds: Since operator[] may only be called within the valid range, callers should ensure in advance via Size() [SWS_DM_02250] or Empty() [SWS_DM_02252] that the requested index exists.
