Context

The interface ara::crypto::cryp::MessageAuthnCodeCtx defines the cryptographic context for the generation and verification of message authentication codes (MAC) in the AUTOSAR Adaptive Platform. It serves to ensure the integrity and authenticity of data via symmetric cryptographic methods. The lifecycle and ownership of context instances are primarily represented via the smart pointer type Sptr ([SWS_CRYPT_22101]).

To execute cryptographic transformations, the context interacts directly with key material. This can either be passed as a concrete key object of type SymmetricKey ([SWS_CRYPT_22118]) or bound via a managed KeySlot ([SWS_CRYPT_50026]). The interface provides two complementary processing modes for this:

  • Streaming processing: Messages can be processed piece by piece via iterative calls (initialization, continuous data update, finalization, and evaluation).
  • Single-call processing: Complete data blocks can be transformed or verified in a single operation.

Depending on the configured algorithm (such as GMAC or CMAC), the context supports initialization vectors (IV) or nonces, whose recommended size can be queried via GetRecommendedIvSize() ([SWS_CRYPT_50135]).

Lifecycle

A MessageAuthnCodeCtx passes through several operating phases that control the transition from key binding to result evaluation:

  • Not initialized (Uninitialized): After creation, the context does not yet possess any assigned key material. Computation and streaming calls fail in this phase with CryptoErrc::kUninitializedContext ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
  • Initialized (Ready): By assigning a key via SetKey() with SymmetricKey ([SWS_CRYPT_22118]) or KeySlot ([SWS_CRYPT_50026]), the context transitions to the ready-for-operation state. Here, single-call calls can be executed directly or streaming operations can be initiated.
  • Streaming active (Processing): The computation is started via Start() ([SWS_CRYPT_22111]) or Start(iv) ([SWS_CRYPT_22110]). Subsequent data blocks are accumulated via Update() ([SWS_CRYPT_22113]). An ongoing operation can be aborted with Cancel() ([SWS_CRYPT_50027]); interpretation: after the abort, the context is likely to remain in the initialized state and be ready for new computations.
  • Completed (Finished): Calling Finish() ([SWS_CRYPT_22115]) terminates the MAC computation. The result can then be queried or compared with an expected value.

According to the specification, all methods of the interface are designed to be thread-safe and exception-safe (including [SWS_CRYPT_50027], [SWS_CRYPT_22118]).

Usage Path

Two typical usage patterns exist for the practical application of the context:

1. Streaming path (incremental processing):

  1. Configuration: Assigning the key via SetKey() ([SWS_CRYPT_22118]).
  2. Buffer dimensioning: In advance, the maximum processable chunk size can be determined via GetMaximumChunkSize() ([SWS_CRYPT_50033]) and the digest length via GetDigestSize() ([SWS_CRYPT_50134]).
  3. Start: Initializing the computation run using Start() ([SWS_CRYPT_22111]) or Start(iv) ([SWS_CRYPT_22110]).
  4. Data update: Repeated passing of partial messages to Update(data) ([SWS_CRYPT_22113]).
  5. Completion: Finalizing the computation with Finish() ([SWS_CRYPT_22115]).
  6. Evaluation: Receiving the digest via GetDigest() ([SWS_CRYPT_22116]) or checking against an expected value using Compare() ([SWS_CRYPT_50133]) or CompareSubspan() ([SWS_CRYPT_50028]).

2. Single-call path (compact processing):

If all data is available in a contiguous buffer, the operation can be executed without streaming steps:

  • Generation of the MAC via Generate() ([SWS_CRYPT_50029]) or as a truncated prefix digest via GenerateSubspan() ([SWS_CRYPT_50030]).
  • Verification of the data against an expected MAC via Verify() ([SWS_CRYPT_50031]) or VerifySubspan() ([SWS_CRYPT_50032]).

Error Scenarios

Errors are signaled via return values of type ara::core::Result with error codes of domain CryptoErrc. The specification guarantees rollback semantics so that the context remains in a consistent state in the event of errors:

  • State and sequence conflicts:
    • CryptoErrc::kUninitializedContext: Invocation of computation operations without a previously configured key ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kProcessingNotStarted: Call of Update() ([SWS_CRYPT_22113]), Finish() ([SWS_CRYPT_22115]), or Cancel() ([SWS_CRYPT_50027]) before processing was initiated with Start().
    • CryptoErrc::kProcessingNotFinished: Call of GetDigest() ([SWS_CRYPT_22116]), Compare() ([SWS_CRYPT_50133]), or CompareSubspan() ([SWS_CRYPT_50028]) before successful finalization via Finish().
  • Key and usage errors:
    • CryptoErrc::kUsageViolation: The provided key does not possess the permission kAllowMac required for MAC operations ([SWS_CRYPT_22118], [SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kEmptyKeySlot: A KeySlot assigned via SetKey() contains no key at the time of execution ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kIncompatibleObject: The passed key or slot object does not match the context ([SWS_CRYPT_22118], [SWS_CRYPT_50026]).
  • Buffer and parameter errors:
    • CryptoErrc::kInsufficientCapacity: The destination buffer for GetDigest() ([SWS_CRYPT_22116]) or Generate() ([SWS_CRYPT_50029]) is smaller than the generated digest.
    • CryptoErrc::kInvalidInputSize: Unsupported buffer size for input data, IV, or expected MAC value ([SWS_CRYPT_22110], [SWS_CRYPT_22113], [SWS_CRYPT_50133]).
    • CryptoErrc::kUnsupported: Lack of support for streaming or single-call, or incompatibility with the IV requirements of the algorithm ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).
    • CryptoErrc::kBusyResource: A required cryptographic resource is currently busy ([SWS_CRYPT_22110], [SWS_CRYPT_50029]).

<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::MessageAuthnCodeCtx</code> defines the cryptographic context for the generation and verification of message authentication codes (MAC) in the AUTOSAR Adaptive Platform. It serves to ensure the integrity and authenticity of data via symmetric cryptographic methods. The lifecycle and ownership of context instances are primarily represented via the smart pointer type <code>Sptr</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22101" href="../spec/record.html?id=SWS_CRYPT_22101">[SWS_CRYPT_22101]</a>).</p>
<p>To execute cryptographic transformations, the context interacts directly with key material. This can either be passed as a concrete key object of type <code>SymmetricKey</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>) or bound via a managed <code>KeySlot</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50026" href="../spec/record.html?id=SWS_CRYPT_50026">[SWS_CRYPT_50026]</a>). The interface provides two complementary processing modes for this:</p>
<ul>
<li><strong>Streaming processing:</strong> Messages can be processed piece by piece via iterative calls (initialization, continuous data update, finalization, and evaluation).</li>
<li><strong>Single-call processing:</strong> Complete data blocks can be transformed or verified in a single operation.</li>
</ul>
<p>Depending on the configured algorithm (such as GMAC or CMAC), the context supports initialization vectors (IV) or nonces, whose recommended size can be queried via <code>GetRecommendedIvSize()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50135" href="../spec/record.html?id=SWS_CRYPT_50135">[SWS_CRYPT_50135]</a>).</p>

<h4>Lifecycle</h4>
<p>A <code>MessageAuthnCodeCtx</code> passes through several operating phases that control the transition from key binding to result evaluation:</p>
<ul>
<li><strong>Not initialized (Uninitialized):</strong> After creation, the context does not yet possess any assigned key material. Computation and streaming calls fail in this phase with <code>CryptoErrc::kUninitializedContext</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>).</li>
<li><strong>Initialized (Ready):</strong> By assigning a key via <code>SetKey()</code> with <code>SymmetricKey</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>) or <code>KeySlot</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50026" href="../spec/record.html?id=SWS_CRYPT_50026">[SWS_CRYPT_50026]</a>), the context transitions to the ready-for-operation state. Here, single-call calls can be executed directly or streaming operations can be initiated.</li>
<li><strong>Streaming active (Processing):</strong> The computation is started via <code>Start()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22111" href="../spec/record.html?id=SWS_CRYPT_22111">[SWS_CRYPT_22111]</a>) or <code>Start(iv)</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>). Subsequent data blocks are accumulated via <code>Update()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a>). An ongoing operation can be aborted with <code>Cancel()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50027" href="../spec/record.html?id=SWS_CRYPT_50027">[SWS_CRYPT_50027]</a>); interpretation: after the abort, the context is likely to remain in the initialized state and be ready for new computations.</li>
<li><strong>Completed (Finished):</strong> Calling <code>Finish()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a>) terminates the MAC computation. The result can then be queried or compared with an expected value.</li>
</ul>
<p>According to the specification, all methods of the interface are designed to be thread-safe and exception-safe (including <a class="spec-record-ref" data-req="SWS_CRYPT_50027" href="../spec/record.html?id=SWS_CRYPT_50027">[SWS_CRYPT_50027]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>).</p>

<h4>Usage Path</h4>
<p>Two typical usage patterns exist for the practical application of the context:</p>
<p><strong>1. Streaming path (incremental processing):</strong></p>
<ol>
<li><strong>Configuration:</strong> Assigning the key via <code>SetKey()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>).</li>
<li><strong>Buffer dimensioning:</strong> In advance, the maximum processable chunk size can be determined via <code>GetMaximumChunkSize()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50033" href="../spec/record.html?id=SWS_CRYPT_50033">[SWS_CRYPT_50033]</a>) and the digest length via <code>GetDigestSize()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50134" href="../spec/record.html?id=SWS_CRYPT_50134">[SWS_CRYPT_50134]</a>).</li>
<li><strong>Start:</strong> Initializing the computation run using <code>Start()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22111" href="../spec/record.html?id=SWS_CRYPT_22111">[SWS_CRYPT_22111]</a>) or <code>Start(iv)</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>).</li>
<li><strong>Data update:</strong> Repeated passing of partial messages to <code>Update(data)</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a>).</li>
<li><strong>Completion:</strong> Finalizing the computation with <code>Finish()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a>).</li>
<li><strong>Evaluation:</strong> Receiving the digest via <code>GetDigest()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a>) or checking against an expected value using <code>Compare()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50133" href="../spec/record.html?id=SWS_CRYPT_50133">[SWS_CRYPT_50133]</a>) or <code>CompareSubspan()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50028" href="../spec/record.html?id=SWS_CRYPT_50028">[SWS_CRYPT_50028]</a>).</li>
</ol>
<p><strong>2. Single-call path (compact processing):</strong></p>
<p>If all data is available in a contiguous buffer, the operation can be executed without streaming steps:</p>
<ul>
<li>Generation of the MAC via <code>Generate()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>) or as a truncated prefix digest via <code>GenerateSubspan()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50030" href="../spec/record.html?id=SWS_CRYPT_50030">[SWS_CRYPT_50030]</a>).</li>
<li>Verification of the data against an expected MAC via <code>Verify()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50031" href="../spec/record.html?id=SWS_CRYPT_50031">[SWS_CRYPT_50031]</a>) or <code>VerifySubspan()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50032" href="../spec/record.html?id=SWS_CRYPT_50032">[SWS_CRYPT_50032]</a>).</li>
</ul>

<h4>Error Scenarios</h4>
<p>Errors are signaled via return values of type <code>ara::core::Result</code> with error codes of domain <code>CryptoErrc</code>. The specification guarantees rollback semantics so that the context remains in a consistent state in the event of errors:</p>
<ul>
<li><strong>State and sequence conflicts:</strong>
<ul>
<li><code>CryptoErrc::kUninitializedContext</code>: Invocation of computation operations without a previously configured key (<a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>).</li>
<li><code>CryptoErrc::kProcessingNotStarted</code>: Call of <code>Update()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a>), <code>Finish()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a>), or <code>Cancel()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50027" href="../spec/record.html?id=SWS_CRYPT_50027">[SWS_CRYPT_50027]</a>) before processing was initiated with <code>Start()</code>.</li>
<li><code>CryptoErrc::kProcessingNotFinished</code>: Call of <code>GetDigest()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a>), <code>Compare()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50133" href="../spec/record.html?id=SWS_CRYPT_50133">[SWS_CRYPT_50133]</a>), or <code>CompareSubspan()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50028" href="../spec/record.html?id=SWS_CRYPT_50028">[SWS_CRYPT_50028]</a>) before successful finalization via <code>Finish()</code>.</li>
</ul></li>
<li><strong>Key and usage errors:</strong>
<ul>
<li><code>CryptoErrc::kUsageViolation</code>: The provided key does not possess the permission <code>kAllowMac</code> required for MAC operations (<a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>).</li>
<li><code>CryptoErrc::kEmptyKeySlot</code>: A <code>KeySlot</code> assigned via <code>SetKey()</code> contains no key at the time of execution (<a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>).</li>
