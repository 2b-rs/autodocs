intended use

ara::core::InstanceSpecifier represents an AUTOSAR InstanceSpecifier as a wrapper around a ShortName path. For application interaction, a valid path begins with / and contains ShortNames separated by / up to the PortPrototype; a leading path separator is likewise required for Functional Cluster interaction. [SWS_CORE_08001] [SWS_CORE_10200] [SWS_CORE_10203]

Generation & destruction

The constructor from StringView can trigger; Create() alternatively returns a Result<InstanceSpecifier>. Syntactically invalid meta model paths must be rejected. [SWS_CORE_08021] [SWS_CORE_08032] [SWS_CORE_10201] [SWS_CORE_10202]

Lifecycle & Ownership

Copy and Move construction and both assignments are available and noexcept. The lifetime of the string content returned by ToString() is only guaranteed for the lifetime of the StringView content passed to the constructor. Limitations & Error handling

Create() returns CoreErrc::kInvalidMetaModelShortname if path elements are missing or invalid, and CoreErrc::kInvalidMetaModelPath if the model path is invalid. [SWS_CORE_08032]

Manifesto reference and resolution

InstanceSpecifier is a model-path concept separated by / that unambiguously refers application code to resources defined in the system model. The constructor checks the syntax; Functional Clusters check semantic validity of the path only when accessing the named resource. EXP ARAComAPI §6.2 “Usage of InstanceSpecifier”

For ara::com, the service instance manifest links such a specifier with the port prototype instance and thus with a concrete service instance. The resulting InstanceIdentifier is technology dependent. EXP ARAComAPI §6.2.1 “Modeling and configuration/mapping” TPS ManifestSpecification §B.5.1 “Relation between Instance Specifier and Instance Ref”

Activity diagram: The specifier serves as a near-model input for the resolution to a binding-specific InstanceIdentifier. Interpretation: The “ResolveInstanceIDs” node summarizes the semantic resolution that occurs in the functional clusters. Sources: EXP ARAComAPI §6.2 “Usage of InstanceSpecifier” EXP ARAComAPI §6.2.1 “Modeling and configuration/mapping” TPS ManifestSpecification §B.5.1 “Relation between Instance Specifier and Instance Ref”.

Core data type in the model context

The core specification lists instance specifiers as AUTOSAR's own data types. The use as a model-based path and the later resolution in a functional cluster are therefore separate steps; The concrete goal commitment only arises outside the pure sign path. SWS Core §7.4 “Core data types” SWS Core §7.4.1 – Data types devised by AUTOSAR
