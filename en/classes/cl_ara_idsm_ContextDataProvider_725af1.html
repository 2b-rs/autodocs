Context

The class ara::idsm::ContextDataProvider is used in the idsm (Intrusion Detection System Manager) module of the AUTOSAR Adaptive Platform to provide and enrich security-relevant context data ([SWS_AIDSM_10500]). When monitoring security-critical events, the IdsM requires additional environment and state information from the application in order to accurately classify detected anomalies or security incidents. As an interface, ContextDataProvider defines the abstract method ModifyContextData ([SWS_AIDSM_10509]), via which the IdsM queries data from the application component as needed.

The interaction takes place between three essential components:

  • Adaptive Application / Provider Subclass: The application implements the concrete provider logic by overriding ModifyContextData ([SWS_AIDSM_10509]) and controls the lifecycle of the provider object.
  • ContextDataProvider Base Class: Manages the connection to the provider port modeled in the manifest via an instance identifier ([SWS_AIDSM_10501]).
  • IdsM Service: The Intrusion Detection System accesses the context data as soon as the provision has been activated via the interface ([SWS_AIDSM_10507]).

Lifecycle

ContextDataProvider is instantiated explicitly via the constructor by passing an ara::core::InstanceSpecifier, the number of additional bytes (additionalBytes), and the offset for the original context data (originalContextDataOffset) ([SWS_AIDSM_10501]). This constructor is specified as thread-safe (thread-safe) ([SWS_AIDSM_10501]).

Strict restrictions apply regarding ownership and value semantics:

  • Copying Prohibited: Both the copy constructor ([SWS_AIDSM_10504]) and the copy assignment operator ([SWS_AIDSM_10506]) are deleted (= delete). A provider instance is uniquely bound to a modeled port and cannot be duplicated.
  • Moving Permitted: The class has a thread-safe move constructor ([SWS_AIDSM_10503]). Move assignment via operator= is also supported, but is not thread-safe (not thread-safe) ([SWS_AIDSM_10505]).

After construction, the instance is in an inactive state. Only through the explicit call to Offer() ([SWS_AIDSM_10507]) is it signaled to the IdsM that the provider is ready and ModifyContextData may be called. This service is interrupted again with StopOffer() ([SWS_AIDSM_10508]). The instance is released via the virtual destructor ~ContextDataProvider() ([SWS_AIDSM_10502]). Interpretation: To avoid race conditions during the destructor run, StopOffer() should probably be called before destroying the object, since both destruction and deregistration are not thread-safe ([SWS_AIDSM_10502], [SWS_AIDSM_10508]).

Usage Path

The regular sequence for providing context data comprises the following phases:

  1. Derivation: Interpretation: Since ModifyContextData is a pure virtual method ([SWS_AIDSM_10509]), the application creates its own derived class and overrides this function.
  2. Creation: The derived provider class is instantiated specifying the InstanceSpecifier for the modeled provider port, the additional buffer size, and the offset ([SWS_AIDSM_10501]).
  3. Activation: The application calls Offer() ([SWS_AIDSM_10507]). After successful registration, the IdsM is authorized to issue callback calls to the provider.
  4. Context Provision: If a security event occurs in the IdsM, the framework calls ModifyContextData(contextData, event) ([SWS_AIDSM_10509]). The application writes the contextual information into the passed byte buffer (ara::core::Span<std::uint8_t>) and reports back the number of modified bytes.
  5. Deactivation: Before shutting down the component, the application calls StopOffer() ([SWS_AIDSM_10508]) to prevent further calls by the IdsM, and destroys the instance ([SWS_AIDSM_10502]).

Sequence diagram: Typical sequence of initialization, provision (Offer), event-driven context modification, and deregistration (StopOffer). Sources: [SWS_AIDSM_10501], [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509].

Error Scenarios

The methods for state management and data modification signal execution states via ara::core::Result:

  • Failure of Offer: The method Offer() returns ara::core::Result<void> ([SWS_AIDSM_10507]). If the provider port cannot be registered (for example due to missing system resources or faulty modeling), the result object contains the corresponding error code. In this case, no IdsM calls to ModifyContextData are permitted.
  • Failure in ModifyContextData: The callback function returns ara::core::Result<std::size_t> ([SWS_AIDSM_10509]). If the capacity of the passed ara::core::Span<std::uint8_t> is insufficient or the context for the reported EventIdType cannot be determined, the derived class returns an error result instead of transmitting a byte count.
  • Pre- and Postconditions: ModifyContextData may only occur between successful Offer() ([SWS_AIDSM_10507]) and StopOffer() ([SWS_AIDSM_10508]). Since neither Offer(), StopOffer() nor ModifyContextData() are thread-safe ([SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]), the calling application must ensure that lifecycle operations do not occur concurrently with ongoing callback executions.

<h4>Context</h4>
<p>The class <code>ara::idsm::ContextDataProvider</code> is used in the <code>idsm</code> (Intrusion Detection System Manager) module of the AUTOSAR Adaptive Platform to provide and enrich security-relevant context data (<a class="spec-record-ref" data-req="SWS_AIDSM_10500" href="../spec/record.html?id=SWS_AIDSM_10500">[SWS_AIDSM_10500]</a>). When monitoring security-critical events, the IdsM requires additional environment and state information from the application in order to accurately classify detected anomalies or security incidents. As an interface, <code>ContextDataProvider</code> defines the abstract method <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), via which the IdsM queries data from the application component as needed.</p>
<p>The interaction takes place between three essential components:</p>
<ul>
<li><strong>Adaptive Application / Provider Subclass:</strong> The application implements the concrete provider logic by overriding <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>) and controls the lifecycle of the provider object.</li>
<li><strong>ContextDataProvider Base Class:</strong> Manages the connection to the provider port modeled in the manifest via an instance identifier (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</li>
<li><strong>IdsM Service:</strong> The Intrusion Detection System accesses the context data as soon as the provision has been activated via the interface (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p><code>ContextDataProvider</code> is instantiated explicitly via the constructor by passing an <code>ara::core::InstanceSpecifier</code>, the number of additional bytes (<code>additionalBytes</code>), and the offset for the original context data (<code>originalContextDataOffset</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>). This constructor is specified as thread-safe (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</p>
<p>Strict restrictions apply regarding ownership and value semantics:</p>
<ul>
<li><strong>Copying Prohibited:</strong> Both the copy constructor (<a class="spec-record-ref" data-req="SWS_AIDSM_10504" href="../spec/record.html?id=SWS_AIDSM_10504">[SWS_AIDSM_10504]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_AIDSM_10506" href="../spec/record.html?id=SWS_AIDSM_10506">[SWS_AIDSM_10506]</a>) are deleted (<code>= delete</code>). A provider instance is uniquely bound to a modeled port and cannot be duplicated.</li>
<li><strong>Moving Permitted:</strong> The class has a thread-safe move constructor (<a class="spec-record-ref" data-req="SWS_AIDSM_10503" href="../spec/record.html?id=SWS_AIDSM_10503">[SWS_AIDSM_10503]</a>). Move assignment via <code>operator=</code> is also supported, but is not thread-safe (<code>not thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10505" href="../spec/record.html?id=SWS_AIDSM_10505">[SWS_AIDSM_10505]</a>).</li>
</ul>
<p>After construction, the instance is in an inactive state. Only through the explicit call to <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) is it signaled to the IdsM that the provider is ready and <code>ModifyContextData</code> may be called. This service is interrupted again with <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>). The instance is released via the virtual destructor <code>~ContextDataProvider()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>). Interpretation: To avoid race conditions during the destructor run, <code>StopOffer()</code> should probably be called before destroying the object, since both destruction and deregistration are not thread-safe (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>).</p>

<li><strong>Context Provision:</strong> If a security event occurs in the IdsM, the framework calls <code>ModifyContextData(contextData, event)</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>). </ol>

<li><strong>Pre- and Postconditions:</strong> <code>ModifyContextData</code> may only occur between successful <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) and <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>).
