intended use

SovdConfiguration implements a generic SOVD configuration interface. RequestGetConfiguration() returns a read session with SovdConfigurationMetaInfo for a configuration ID; RequestPutConfiguration() returns the corresponding write session. [SWS_DM_01860] [SWS_DM_01870] [SWS_DM_01871] When a write request is made for an explicitly modeled SOVD configuration, the Diagnostic Server calls RequestPutConfiguration(). [SWS_DM_01788]

Creation & lifecycle

The class is created for a PortPrototype of DiagnosticSovdConfigurationInterface with ConcurrencyType. [SWS_DM_01864] Offer() and StopOffer() control DM forwarding; Offer can supply kConfigurationMismatch or kAlreadyOffered. [SWS_DM_01872] [SWS_DM_01930] The instance is not copyable and not copy-assignable, but movable and move-assignable. [SWS_DM_01866] [SWS_DM_01868] [SWS_DM_01867] [SWS_DM_01869]

Limitations & Error handling

Both transfer requests provide applicable SOVD error codes if failed; their thread safety is conditioned by the ConcurrencyType. [SWS_DM_01870] [SWS_DM_01871] The CancellationHandler informs about the termination of the conversation. [SWS_DM_01870] [SWS_DM_01871] Offer and StopOffer are not thread-safe. [SWS_DM_01872] [SWS_DM_01930]

RequestGetConfiguration and RequestPutConfiguration each receive the configuration ID, MetaInfo and a CancellationHandler. [SWS_DM_01870] [SWS_DM_01871] The read session is combined with meta information, the write session with the corresponding return metadata. [SWS_DM_01870] [SWS_DM_01871] The constructor is exception-safe and thread-safe, the destructor is exception-safe and not thread-safe. [SWS_DM_01864] [SWS_DM_01865]

Both request methods are pure virtual functions and are therefore implemented by the application. [SWS_DM_01870] [SWS_DM_01871] The created instance has a virtual, exception-safe destructor. [SWS_DM_01865]
