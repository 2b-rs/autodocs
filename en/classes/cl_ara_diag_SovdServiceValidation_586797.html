intended use

SovdServiceValidation implements manufacturer or supplier specific SOVD checks. Validate() is called for every SOVD request and, for resource collections, once per contained element. [SWS_DM_01822] [SWS_DM_01827] The DM calls the configured validators in the specified order and immediately terminates processing with error as soon as one of them fails. [SWS_DM_01784] [SWS_DM_01785]

Creation & lifecycle

The instance is created for a PortPrototype of DiagnosticSovdServiceValidationInterface with ConcurrencyType. [SWS_DM_01823] Offer enables DM forwarding and StopOffer disables it. Offer can supply kAlreadyOffered or kConfigurationMismatch. [SWS_DM_01825] [SWS_DM_01826] The destructor is exception-safe. [SWS_DM_01824]

Limitations & Error handling

Validate receives the HTTP method and MetaInfo, including the resource path, and returns either success or an SOVD error. [SWS_DM_01827] Specified cases include server misconfiguration, unmet preconditions, temporary unavailability, and missing access rights. [SWS_DM_01827] The thread safety of Validate depends on ConcurrencyType; Offer and StopOffer are not thread-safe. [SWS_DM_01827] [SWS_DM_01825] [SWS_DM_01826]

For a resource collection, the DM first validates the collection and then each item to be returned using its own path in MetaInfo. [SWS_DM_01785] The validation function is exception-safe and returns an Future<void>. [SWS_DM_01827] The constructor is exception-safe and thread-safe, while the destructor is exception-safe and not thread-safe. [SWS_DM_01823] [SWS_DM_01824]

If an error occurs, the DM will not continue processing the request. [SWS_DM_01784]

function Validate [SWS_DM_01827] Upstream: RS_Diag_04256, RS_Diag_04273

virtual ara::core::Future< void > Validate (SovdRequestMethod request Method, const MetaInfo &metaInfo) noexcept;

Called for every SOVD request message. Will be called multiple times if the request is for a resource collection: • once for the resource collection, • once for each resource in the resource collection.

Usage AI generated

Automatically generated usage note derived from this AUTOSAR R25-11 specification element—not official AUTOSAR text. Evidence: [SWS_…].

The virtual method Validate is called for each incoming SOVD request message; In the case of a resource collection, the call is made multiple times - once for the collection itself and once for each resource it contains. The requestMethod used in the request (HTTP method) and the metaInfo including the path of the requested resource or resource collection [SWS_DM_01827] are passed. The returned ara::core::Future<void> returns an empty value if the request is allowed, otherwise an error.

Error handling & concurrency

Possible errors are DiagSovdErrc::kSovdServerMisconfigured (SOVD server misconfigured), DiagSovdErrc::kPreconditionNotFulfilled (prerequisites not met), DiagSovdErrc::kTemporarilyNotAvailable (request currently not operable) and DiagSovdErrc::kInsufficientAccessRights (insufficient access rights); additional DiagSovdErrc values ​​for SOVD-specific error messages are permitted. Whether the implementation must be thread-safe or non-thread-safe is determined by the ConcurrencyType passed in the constructor; the method is exception-safe.
