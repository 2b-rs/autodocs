Enables the synchronous or asynchronous reception of values and errors from a concurrent operation.

The class ara::core::Future serves as a receiver handle for the result of an asynchronous operation and manages access to a shared state [SWS_CORE_00327]. Consumers can inspect the state in a non-blocking manner, wait synchronously for completion, or retrieve the result via GetResult() without exceptions as ara::core::Result [SWS_CORE_00336]. Because copy operations are deleted, ownership is managed exclusively, and following result retrieval or forwarding by means of a continuation, the object immediately becomes invalid.

Context

The template class ara::core::Future represents the receiver endpoint for results of asynchronous operations within the AUTOSAR Adaptive Platform. It enables controlled access to a shared state that is asynchronously populated by a producing instance [SWS_CORE_00327]. Conceptually, the class implements std::future from the C++17 standard ISO/IEC 14882:2017 [11], but integrates seamlessly into the platform's error-exception-based concept: For the template parameter E, the error type ara::core::ErrorCode is strictly prescribed; any deviating specification leads to a compilation error. The primary interaction partners include the asynchronous producer (such as an associated Promise) that provides the value or error, the Future instance as the exclusive receiver, and a consumer or execution context (ExecutorT) to which subsequent tasks are passed [SWS_CORE_00331] [SWS_CORE_00337].

Lifecycle

The creation, state management, and destruction of ara::core::Future are subject to strict rules to guarantee deterministic ownership:

  • Creation: The default constructor creates an empty instance without shared state, for which valid() == false holds [SWS_CORE_00322] [SWS_CORE_00327]. Interpretation: Valid instances regularly originate through asynchronous platform interfaces or coupled Promise objects. Question Q-6149efe498e0f5f6 (open)
  • Ownership and transfer: The copy constructor and copy assignment operator are explicitly deleted (delete), preventing any duplication of the access handle [SWS_CORE_00334] [SWS_CORE_00335]. Moving instances is possible via the move constructor and move assignment operator and transfers ownership of the shared state completely [SWS_CORE_00323] [SWS_CORE_00325].
  • States and transitions: The state is divided into invalid (valid() == false), valid-pending (valid() == true, is_ready() == false), and ready (valid() == true, is_ready() == true) [SWS_CORE_00327] [SWS_CORE_00332]. Following successful result retrieval via GetResult() or get() as well as following forwarding by means of then(), the object loses its state and immediately becomes invalid (valid() == false) [SWS_CORE_00326] [SWS_CORE_00331] [SWS_CORE_00336] [SWS_CORE_00337].
  • Destruction: The destructor ~Future() releases any shared state still held [SWS_CORE_00333]. If continuations were registered, the destructor of the returned instance blocks until an already running continuation function has completed execution [SWS_CORE_00331] [SWS_CORE_00337].
  • Concurrency: The status methods valid() and is_ready() are thread-safe [SWS_CORE_00327] [SWS_CORE_00332]. All other interfaces—including wait(), wait_for(), wait_until(), GetResult(), get(), then(), and the destructor—are not thread-safe for the same instance [SWS_CORE_00323] [SWS_CORE_00325] [SWS_CORE_00326] [SWS_CORE_00328] [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00331] [SWS_CORE_00333] [SWS_CORE_00336] [SWS_CORE_00337].

Usage Path

A typical usage path for result processing is divided into the following phases:

  1. Status check and synchronization: is_ready() can be used to determine in advance whether the asynchronous result is already available [SWS_CORE_00332]. If this is the case, subsequent retrievals are guaranteed not to block anymore [SWS_CORE_00332]. Otherwise, synchronization can be performed indefinitely using wait() [SWS_CORE_00328] or with a time limit via wait_for() or wait_until() [SWS_CORE_00329] [SWS_CORE_00330].
  2. Result extraction: In AUTOSAR Adaptive applications, calling GetResult() is decisive: The method blocks if necessary, but never throws exceptions and hands over the value or error as ara::core::Result<T, E> via move [SWS_CORE_00336]. The method get() provides STL conformance, throws C++ exceptions in case of error, and does not participate in overload resolution if toolchain exception handling is disabled [SWS_CORE_00326].
  3. Asynchronous chaining (continuations): Instead of synchronous blocking, a callback can be registered via then(), optionally assigning it to an execution context (executor) [SWS_CORE_00331] [SWS_CORE_00337]. The callback accepts the result as a Result<T, E> rvalue. If the continuation function itself returns a Future or Result, then() performs automatic unwrapping and directly returns a corresponding Future<T2, E2> [SWS_CORE_00331] [SWS_CORE_00337].

Sequence diagram: Typical sequence of asynchronous synchronization and result retrieval via GetResult(). Sources: [SWS_CORE_00327], [SWS_CORE_00332], [SWS_CORE_00336]

Error Scenarios

When working with ara::core::Future, the following error situations are specified:

  • Call on invalid instance: Calling is_ready(), wait(), wait_for(), wait_until(), GetResult(), or then() on an invalid instance (valid() == false) constitutes a FutureInvalidViolation [SWS_CORE_00328] [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00331] [SWS_CORE_00332] [SWS_CORE_00336] [SWS_CORE_00337]. In this case, calling get() throws a FutureException with the error code kNoState [SWS_CORE_00326].
  • Abandoned shared state (broken promise): If the shared state is prematurely abandoned by the associated Promise, GetResult() returns a Result with the standardized error code FutureErrc::kBrokenPromise [SWS_CORE_00336]. Calling get() throws the corresponding exception [SWS_CORE_00326].
  • Exceptions in continuation functions: A registered continuation must not throw exceptions, except to implement a violation. If it nevertheless throws an exception, this results in a FutureContinuationHasThrownViolation [SWS_CORE_00331] [SWS_CORE_00337]. Exceptions in closures must be caught and returned as an error state in the form of a Result or Future [SWS_CORE_00331] [SWS_CORE_00337].

                  use
                  

                  The method get() synchronously retrieves the result of type T from a ara::core::Future [SWS_CORE_00326]. The function behaves identically to its counterpart in std::future; if the asynchronous computation is still ongoing, the call blocks until completion or until an error occurs [SWS_CORE_00336]. By calling it, the object loses its state so that the future becomes invalid immediately (valid() == false) [SWS_CORE_00326]. A non-blocking call can be ensured in advance via is_ready() [SWS_CORE_00332].
                  

                  Error handling
                  

                  Failures are reported via C++ exceptions [SWS_CORE_00326]:
                  

                    

                  • If an error was stored in the associated Promise via SetError() or SetResult(), an exception of the corresponding error type is thrown [SWS_CORE_00326].
                    • 

                  • If the shared state is abandoned prematurely by the asynchronous operation, this results in error kBrokenPromise according to FutureErrc [SWS_CORE_00326], [SWS_CORE_00400].
                    • 

                  • If the call is made on an invalid instance, a FutureException with error code kNoState is thrown [SWS_CORE_00326].
                    • 

                  

                  Concurrency and Limitations
                  

                  The operation is neither thread-safe nor exception-safe (not exception safe) [SWS_CORE_00326]. Concurrent accesses to the same future from multiple threads require external synchronization. If exceptions are disabled in the compiler toolchain, get() does not participate in overload resolution [SWS_CORE_00326]; for this case, the exception-free alternative GetResult() exists [SWS_CORE_00336]. For instances without a return value, the specialization Future<void, E>::get() is available [SWS_CORE_06226].
