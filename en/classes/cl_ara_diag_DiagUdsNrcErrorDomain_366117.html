Provides UDS-specific Negative Response Codes for standardized error handling in diagnostic functions.

The error domain ara::diag::DiagUdsNrcErrorDomain encapsulates error codes from diagnostic processing and maps them to standardized UDS error values [SWS_DM_00529]. When an external diagnostic processor reports a corresponding error, the Diagnostic Server derives a 1-byte NRC from it and sends a negative UDS response to the tester [SWS_DM_02060]. As an essential boundary condition, the derived NRC values must strictly lie within the value range between 0x01 and 0xFE.

Context

The class ara::diag::DiagUdsNrcErrorDomain represents the standardized error domain for errors originating from different diagnostic classes (AUTOSAR_AP_SWS_Diagnostics §8.12.3 “Class: DiagUdsNrcErrorDomain”). As a specialization of the base class ara::core::ErrorDomain [SWS_DM_00529], it forms the fundamental link between application-side diagnostic processing and the UDS protocol (Unified Diagnostic Services). Within the AUTOSAR Adaptive Platform, it mediates between external diagnostic processors or software applications and the Diagnostic Server (Diagnostic Management, DM). If an external diagnostic processor reports an error of this domain during command execution, the Diagnostic Server Instance evaluates it specifically [SWS_DM_02060]. In addition, the domain interacts with the checking of configurable environmental conditions if reading data elements fails [SWS_DM_00970].

Lifecycle

Instantiation of ara::diag::DiagUdsNrcErrorDomain is performed via the default constructor constexpr DiagUdsNrcErrorDomain() noexcept [SWS_DM_00532]. This constructor is specified as exception-safe and thread-safe [SWS_DM_00532]. Due to the constexpr design and the nature of functionless error domains, an instance is likely typically provided as an immutable, process-wide object (interpretation). The constituent inspection methods Name() [SWS_DM_00533] and Message() [SWS_DM_00534] are also thread-safe and exception-safe. Since the object does not manage any mutable state, the lifecycle is tied to the overall runtime context of the diagnostic application and allows unrestricted, concurrent read access.

Usage Path

The typical usage path describes the signaling and transformation of a diagnostic error during service execution:

  1. An external diagnostic processor executes a diagnostic function and detects an error condition.
  2. The application creates a ara::core::Result with an error code of the domain ara::diag::DiagUdsNrcErrorDomain using the type Errc (alias for DiagUdsNrcErrc) [SWS_DM_00530] and returns it to the Diagnostic Server Instance [SWS_DM_02060].
  3. The Diagnostic Server Instance receives the return value and identifies the presence of the error domain ara::diag::DiagUdsNrcErrorDomain [SWS_DM_02060].
  4. The DM derives the UDS NRC from the error code DiagUdsNrcErrc, for example via a static_cast into a 1-byte NRC value [SWS_DM_02059].
  5. The Diagnostic Server replies to the requesting diagnostic tester with a negative UDS response (negative response) carrying the derived NRC value [SWS_DM_02060].

Sequence diagram: Derivation and transmission of a UDS NRC in case of faulty diagnostic execution. Sources: [SWS_DM_02059], [SWS_DM_02060].

Special handling applies to multi-DID requests: Although the occurrence of an error of ara::diag::DiagUdsNrcErrorDomain in the result indicates the failure of the external diagnostic processor for the individual element, it can still lead to an overall positive response in case of multiple requested DIDs, provided that at least one DID is supported in the active session (AUTOSAR_AP_SWS_Diagnostics §7.3 “Multi-DID-Requests”).

Error Scenarios

Strict value limits and behavioral rules apply when using and forwarding errors via ara::diag::DiagUdsNrcErrorDomain:

  • Scope of validity: Permissible UDS NRC values derived from DiagUdsNrcErrc lie exclusively in the range from 0x01 to 0xFE [SWS_DM_02059].
  • Failure under environmental conditions: If retrieving a dataElement fails because an external processor reports an error of ara::diag::DiagUdsNrcErrorDomain, the DM evaluates the expression DiagnosticEnvConditionFormulaPart as not fulfilled and emits a Log and Trace message [SWS_DM_00970].
  • Exception handling: The method ThrowAsException() converts a ErrorCode into the corresponding exception of type Exception (alias for DiagUdsNrcException) [SWS_DM_00531], [SWS_DM_00535]. This operation is declared as not exception-safe; if C++ exceptions are disabled, it does not participate in overload resolution [SWS_DM_00535].
  • Message resolution: The method Message() returns a descriptive text string for each passed error code and is guaranteed never to return nullptr [SWS_DM_00534].

In interaction with Diagnostic Management, errors of this domain control negative response handling. If a ara::diag interface returns an error of DiagUdsNrcErrorDomain, the Diagnostic Server derives a negative UDS response (NRC) from it with the value of the error code in the valid range from 0x01 to 0xFE [SWS_DM_02059], [SWS_DM_02060]. If such an error occurs when retrieving an environmental element, the server evaluates the relevant condition as not fulfilled and issues a Log and Trace message [SWS_DM_00970].
