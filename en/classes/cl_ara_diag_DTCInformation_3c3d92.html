DTC view of the error memory

DTCInformation is the application interface to DTC-related results of an associated diagnostic event: current UDS DTC status, snapshot updates, number of saved entries, overflow and control DTC status. This information is created in event memory processing and cannot be understood independently of the event, storage target and DTC configuration SWS Diagnostics §7.3.4.4 “Event memory”.

Monitor changes

The UDS DTC status is updated after event processing; SetDTCStatusChangedNotifier registers the callback for this change [SWS_DM_00667]. Additional notifiers separate status, snapshot, memory count and overflow changes. A new registration call replaces the previous callback of the respective category, so the application should centralize its receiving logic.

DTC information follows event and memory processing; Notifiers make relevant changes available while Clear starts a separate asynchronous deletion path. Sources: SWS Diagnostics §7.3.4.4 “Event memory”, SWS Diagnostics §7.3.4.4.2 “UDS DTC Status”, SWS Diagnostics §7.3.4.4.5 “Clearing DTCs”. Partial interpretation: The graphic summarizes status and notification relationships.

Clear DTCs

Clear triggers the asynchronous deletion of a DTC or DTC group from [SWS_DM_00671]. Wait for the result future before a subsequent technical action originates from the cleaned memory: ClearConditions and possible locks are part of the DTC clearing processing SWS Diagnostics §7.3.4.4.5 “Clearing DTCs”. The group of all DTCs has the identifier 0xFFFFFF SWS Diagnostics §7.3.4.4.1 “DTC Introduction” in the specification.

Usage limit

The class is a state and notification interface. It should only be used for the configured event; DTC number, aging, displacement and snapshot/extended data recording remain DM and configuration responsibility.

Method for Clearing a DTC or a group of DTCs.

Usage AI generated

Automatically generated usage notice derived from the referenced AUTOSAR R25-11 documents — not official AUTOSAR text.

Start the deletion job consciously

Clear requests deletion of a DTC or DTC group and returns an Future<void> [SWS_DM_00671]. The routine is asynchronous because the DM processes memory cleanup and its conditions.

Recommended order
  1. Only transfer a configured DTC or group number.
  2. Wait for the future and evaluate success or errors.
  3. Only then carry out local follow-up steps that require the memory to be emptied.
No circumventing conditions

ClearConditions and locks are part of the specified clearing process SWS Diagnostics §7.3.4.4.5 “Clearing DTCs”. The application should therefore not set a local "cleared" flag before the Future completes successfully.

function SetDTCStatusChangedNotifier [SWS_DM_00667] Upstream: RS_AP_00139, RS_Diag_04148

ara::core::Result< void > SetDTCStatusChangedNotifier (DtcStatus ChangedNotifier notifier) noexcept;

Register a notifier function which is called if a UDS DTC status is changed. A consecutive call of this method will overwrite the previous registered notifier.

Usage AI generated

Automatically generated usage notice derived from the referenced AUTOSAR R25-11 documents — not official AUTOSAR text.

Subscribe to status change

SetDTCStatusChangedNotifier registers a callback for UDS DTC status changes [SWS_DM_00667]. The callback complements queries about the current status, but does not replace the configuration of the underlying event.

One owner per instance

A subsequent registration replaces the previous notifier. The application should therefore provide a unique owner and a short, non-blocking callback routine for each DTCInformation instance.

Technical classification

The status is derived from event processing and the UDS DTC rules SWS Diagnostics §7.3.4.4.2 “UDS DTC Status”; a notifier can therefore have multiple causes, such as a qualified monitor finding or memory processing.

Supplementary, already linked specification evidence for this API: [SWS_DM_00667].
