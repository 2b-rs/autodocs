Enables asymmetric decryption of data using private keys as a single call or data stream.

The interface ara::crypto::cryp::DecryptorPrivateCtx is used for asymmetric decryption of ciphertexts in the AUTOSAR Adaptive Platform ([SWS_CRYPT_50070]). Before execution, a private key possessing the usage permission for decryption must be provided to the context ([SWS_CRYPT_50157]). Processing can take place either in a single call or as a multi-part data stream across the Start, Update, and Finish phases. All methods of the interface are implemented to be thread-safe and exception-safe.

Context

The interface ara::crypto::cryp::DecryptorPrivateCtx is used for the asymmetric decryption of ciphertexts in the cryptography module of the AUTOSAR Adaptive Platform. As a specialization of CryptoContext, it provides the cryptographic transformation functions used to convert ciphertexts back into plaintext using private keys. Essential interaction partners include the calling application as well as key objects provided as PrivateKey or via a KeySlot. Instances of this interface are typically managed via the typed smart pointer Sptr ([SWS_CRYPT_50156]).

Lifecycle

Management of DecryptorPrivateCtx is performed via the alias ara::crypto::cryp::DecryptorPrivateCtx::Sptr, which maps to std::shared_ptr<DecryptorPrivateCtx> ([SWS_CRYPT_50156]). Interpretation: Since the class is an interface with pure virtual methods, concrete creation is typically expected to be performed by a factory of the crypto driver.

Immediately after instantiation, the context is in an uninitialized state. In this state, operational transformation calls lead to errors. For activation, a private key must be assigned. This is done either by passing an PrivateKey::Sptr using SetKey() ([SWS_CRYPT_50157]) or via a KeySlot::Sptr ([SWS_CRYPT_50066]) that encapsulates the key.

As soon as the context is configured with a valid key, it transitions to the Initialized state. In this state, the context can either be used directly for single-call decryption or transitioned via Start() ([SWS_CRYPT_50067]) to the Streaming processing state. During streaming, Update() ([SWS_CRYPT_50158]) accepts ciphertext fragments. The sequence is completed by Finish() ([SWS_CRYPT_50068]) or aborted via Cancel() ([SWS_CRYPT_50069]), whereupon the context is again ready for new operations. All interface methods are specified as thread-safe and exception-safe ([SWS_CRYPT_50066], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).

State diagram: Lifecycle states of the context from key binding through streaming to termination. Sources: [SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50158], [SWS_CRYPT_50068], [SWS_CRYPT_50069], [SWS_CRYPT_50070].

Usage Path

Two different sequences are available for decryption: stateless single-call decryption and multi-step streaming processing. Before passing data, the calling application can query the permissible input restrictions for ciphertexts using GetMinimumChunkSize() ([SWS_CRYPT_50160]) and GetMaximumChunkSize() ([SWS_CRYPT_50071]). Via GetRequiredOutputBufferSize() ([SWS_CRYPT_50159]), the required size of the output buffer for Update(), Finish(), or Decrypt() can be determined in advance.

For compact amounts of data, decryption takes place directly via Decrypt() ([SWS_CRYPT_50070]) after key configuration. The ciphertext is transformed in a single step, and the actual number of decrypted bytes is returned.

Larger or fragmented incoming ciphertexts are processed via the streaming path:

  1. Key assignment: Configuration of the context via SetKey() with an PrivateKey ([SWS_CRYPT_50157]) or KeySlot ([SWS_CRYPT_50066]).
  2. Initialization: Call to Start() ([SWS_CRYPT_50067]) to prepare the internal processing state.
  3. Blockwise processing: Repeated call to Update() ([SWS_CRYPT_50158]) for successive ciphertext blocks.
  4. Finalization: Call to Finish() ([SWS_CRYPT_50068]) to process the final block and terminate the stream. Alternatively, the operation can be aborted prematurely using Cancel() ([SWS_CRYPT_50069]).

Sequence diagram: Typical call sequence of a multi-part streaming decryption. Sources: [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50158], [SWS_CRYPT_50068].

Error Scenarios

Methods of DecryptorPrivateCtx return errors via ara::core::Result with codes from ara::crypto::CryptoErrc and follow rollback semantics:

  • ara::crypto::CryptoErrc::kUninitializedContext: Occurs when transformation operations such as Decrypt() ([SWS_CRYPT_50070]) or Start() ([SWS_CRYPT_50067]) as well as buffer calculations via GetRequiredOutputBufferSize() ([SWS_CRYPT_50159]) are called before a key has been configured.
  • ara::crypto::CryptoErrc::kProcessingNotStarted: Reported by Update() ([SWS_CRYPT_50158]), Finish() ([SWS_CRYPT_50068]), or Cancel() ([SWS_CRYPT_50069]) if no preceding call to Start() took place.
  • ara::crypto::CryptoErrc::kUsageViolation: Signals that the key's usage rules do not contain the permission kAllowDataDecryption ([SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kIncompatibleObject: Occurs when the assigned key object or slot does not match the algorithm of the context ([SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kInsufficientCapacity and ara::crypto::CryptoErrc::kInvalidInputSize: The output buffer does not provide sufficient capacity or the input size violates the limits of the context ([SWS_CRYPT_50070], [SWS_CRYPT_50158], [SWS_CRYPT_50068]).
  • ara::crypto::CryptoErrc::kUnsupported: Indicates that streaming, single calls, or the chosen type of key binding are not supported by the concrete implementation ([SWS_CRYPT_50066], [SWS_CRYPT_50157], [SWS_CRYPT_50067], [SWS_CRYPT_50070]).
  • ara::crypto::CryptoErrc::kEmptyKeySlot and ara::crypto::CryptoErrc::kBusyResource: Indicate that a configured KeySlot is currently empty or a required resource is occupied ([SWS_CRYPT_50067], [SWS_CRYPT_50070]).

Method Cancel of class ara::crypto::cryp::DecryptorPrivateCtx, defined in ara/crypto/cryp/decryptor_private_ctx.h, aborts an ongoing streaming operation that was previously initiated by means of Start() and has not yet been completed [SWS_CRYPT_50069]. The call takes no input parameters and returns a ara::core::Result<void> as return value [SWS_CRYPT_50069]. If the abort of the streaming processing was successful, the object contains an empty result; otherwise, it conveys an occurred error [SWS_CRYPT_50069]. The purely virtual interface is declared as noexcept, exhibits complete exception safety, and is designated as thread-safe for concurrent access [SWS_CRYPT_50069].

In error handling and pre-conditions, the exact sequence must be observed: If data processing was not previously initiated by calling the Start() method, the operation fails and returns the specific error code ara::crypto::CryptoErrc::kProcessingNotStarted with rollback semantics [SWS_CRYPT_50069]. The caller must therefore ensure that an active operation already exists prior to the abort in order to avoid this error state [SWS_CRYPT_50069].

In interaction with the overall module architecture of crypt, Cancel follows a standardized design pattern for stateful streaming operations. The related cryptographic contexts ara::crypto::cryp::VerifierPublicCtx [SWS_CRYPT_50023], ara::crypto::cryp::MessageAuthnCodeCtx [SWS_CRYPT_50027], ara::crypto::cryp::SignerPrivateCtx [SWS_CRYPT_50041], ara::crypto::cryp::SymmetricCipherCtx [SWS_CRYPT_50046], ara::crypto::cryp::HashFunctionCtx [SWS_CRYPT_50058], ara::crypto::cryp::AuthCipherCtx [SWS_CRYPT_50077], and ara::crypto::cryp::EncryptorPublicCtx [SWS_CRYPT_50089] share the same signature, return semantics, and error handling.

      The synchronous method Decrypt decrypts ciphertext data in a single step ([SWS_CRYPT_50070]). The input buffer in passes the ciphertext as ReadOnlyMemRegion, while the output buffer out of type ReadWriteMemRegion receives the plaintext ([SWS_CRYPT_50070]). Upon successful decryption, the function returns the actual number of bytes written via ara::core::Result<std::size_t>, which may be smaller than the total capacity of out ([SWS_CRYPT_50070]).
      

      The interface is specified as thread-safe as well as exception-safe ([SWS_CRYPT_50070]). Before the call, the context must have been initialized by assigning a key; otherwise the function fails with UninitializedContext or, if the KeySlot is empty, with ara::crypto::CryptoErrc::kEmptyKeySlot ([SWS_CRYPT_50070]). The key must be compatible with the transformation algorithm (otherwise kIncompatibleObject) and include permission kAllowDataDecryption (otherwise kUsageViolation) ([SWS_CRYPT_50070]).
      

      To prevent buffer overflows, the maximum required capacity of the output buffer can be queried in advance using GetRequiredOutputBufferSize by specifying isFinal = true ([SWS_CRYPT_50159]). If the capacity of out is insufficient, the method aborts with ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50070]). Furthermore, the size of the input buffer in must be in the range between GetMinimumChunkSize ([SWS_CRYPT_50160]) and GetMaximumChunkSize ([SWS_CRYPT_50071]); otherwise ara::crypto::CryptoErrc::kInvalidInputSize is returned ([SWS_CRYPT_50070]). Other specified errors with rollback semantics are kUnsupported, kInvalidArgument, and kBusyResource ([SWS_CRYPT_50070]).

          The Finish method synchronously completes a decryption process in the context of ara::crypto::cryp::DecryptorPrivateCtx [SWS_CRYPT_50068]. Via the input buffer in (ReadOnlyMemRegion), it processes the last ciphertext segment and writes the resulting plaintext data into the output buffer out (ReadWriteMemRegion) [SWS_CRYPT_50068]. The actual number of written bytes is returned as ara::core::Result<std::size_t> and may be smaller than the total capacity of the destination buffer out [SWS_CRYPT_50068].
          
  
          Prior to the call, data processing must strictly have been initiated with Start(); otherwise, the error CryptoErrc::kProcessingNotStarted is reported [SWS_CRYPT_50068]. The maximum permitted block size for in can be determined via GetMaximumChunkSize() [SWS_CRYPT_50071]; if the input length is inappropriate, the call fails with CryptoErrc::kInvalidInputSize [SWS_CRYPT_50068]. If out is too small, CryptoErrc::kInsufficientCapacity results, where the required buffer size can be queried using GetRequiredOutputBufferSize() [SWS_CRYPT_50068]. Further possible errors are CryptoErrc::kInvalidArgument in case of invalid ciphertext data as well as CryptoErrc::kUnsupported if stream processing is not supported in the context [SWS_CRYPT_50068].
          
  
          The operation is specified as thread-safe as well as exception safe [SWS_CRYPT_50068]. Thanks to the designated rollback semantics, the processing state is expected to remain unchanged in the event of buffer errors, so that a retry should be possible after increasing the buffer size.
