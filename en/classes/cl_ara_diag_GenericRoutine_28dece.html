Context

The class ara::diag::GenericRoutine provides a generic interface for handling diagnostic routines in the diagnostic module (ara::diag) of the AUTOSAR Adaptive Platform. It encapsulates the interaction around the UDS service RoutineControl (ISO 14229-1 Service 0x31) at the application level. In contrast to type-specifically generated routine interfaces, GenericRoutine processes request data generically as byte spans, allowing the same implementation to be used flexibly for different routine identifiers (routineId).

The central interaction partners are the Diagnostic Management (DM) of the AUTOSAR runtime environment and the application-specific diagnostic logic. The Diagnostic Management receives diagnostic requests from external testers and forwards incoming RoutineControl requests to the instance as soon as it has been bound to a modeled PortPrototype of type DiagnosticRoutineGenericInterface via a ara::core::InstanceSpecifier and activated [SWS_DM_00552], [SWS_DM_00557]. The using software derives its own handler class from GenericRoutine and implements the application-specific execution logic in the vehicle electronic control unit.

Lifecycle

The lifecycle of a GenericRoutine instance comprises the phases creation, service provision, request processing, deregistration, and destruction.

During creation via constructor GenericRoutine(const ara::core::InstanceSpecifier &specifier, ConcurrencyType concurrencyType), the object is bound to the port defined in the model [SWS_DM_00552]. The parameter concurrencyType bindingly specifies whether the interface is implemented thread-safe (kConcurrent) or not thread-safe (kNotConcurrent), which determines whether callback methods may be invoked concurrently by the DM [SWS_DM_00552].

Regarding ownership semantics, GenericRoutine is designed as a strict single instance: Both copy and move constructors and assignment operators are deleted (=delete) [SWS_DM_01635], [SWS_DM_01636], [SWS_DM_01637], [SWS_DM_01638]. An instance therefore remains fixed at its place of creation.

After instantiation, the object is in the Instantiated state. The DM does not forward any messages at this point. Only by the synchronous invocation of Offer() is forwarding activated and the instance transitioned into the Provided state [SWS_DM_00557]. Via StopOffer(), the forwarding of requests by the DM can be deactivated again at any time [SWS_DM_00558].

Destruction occurs via the virtual destructor ~GenericRoutine() [SWS_DM_00553]. The methods Offer(), StopOffer() and the destructor are not thread-safe; lifecycle transitions must therefore occur synchronized in application code [SWS_DM_00553], [SWS_DM_00557], [SWS_DM_00558].

Usage Path

The typical usage of GenericRoutine comprises the following steps:

  1. Instantiation and registration: The application creates an instance of the derived subclass specifying the InstanceSpecifier and the ConcurrencyType [SWS_DM_00552]. Subsequently, it enables reception via Offer() [SWS_DM_00557].
  2. Routine start (SubFunction 0x01): If the DM receives a RoutineControl request with the sub-function Start, it calls the pure virtual method Start() [SWS_DM_00554]. In doing so, the routineId, the raw data requestData as ara::core::Span<const std::uint8_t>, the context metaInfo, and a CancellationHandler are passed [SWS_DM_00554]. The data in requestData remains valid until the resulting promise is fulfilled or processing is canceled [SWS_DM_00554].
  3. Asynchronous processing: The method immediately returns a ara::core::Future<OperationOutput> to the DM [SWS_DM_00554]. The actual processing takes place asynchronously in the application logic. After completion, the associated promise is fulfilled with the OperationOutput.
  4. Optional operations: Depending on the specification of the routine, the tester can initiate further actions during or after execution:
    • Stop() (SubFunction 0x02): Called to specifically stop a running routine [SWS_DM_00555].
    • RequestResults() (SubFunction 0x03): Used to query intermediate or final results of a routine [SWS_DM_00556].
    Both methods similarly return a ara::core::Future<OperationOutput> [SWS_DM_00555], [SWS_DM_00556].
  5. Service termination: Prior to shutdown, the application calls StopOffer() to terminate forwarding by the DM [SWS_DM_00558].

Sequence diagram: Call and execution sequence of Start and StopOffer. Sources: [SWS_DM_00554], [SWS_DM_00557], [SWS_DM_00558].

Error Scenarios

Errors can occur during configuration, service registration, and execution:

  • Configuration and instantiation errors: If binding of the InstanceSpecifier fails in the constructor, specific runtime violations are triggered [SWS_DM_00552]:
    • InstanceSpecifierMappingIntegrityViolation: The identifier cannot be resolved in the context of the executable or does not refer to a PortPrototype.
    • PortInterfaceMappingViolation: A port typed by DiagnosticRoutineGenericInterface is not mapped to any DiagnosticServiceGenericMapping.
    • ProcessMappingViolation: No matching modeled process exists at runtime for the existing instance reference.
    • InstanceSpecifierAlreadyInUseViolation: The InstanceSpecifier is already used by another instance in the current process.
  • Error during offering: If Offer() is called when the service is already actively offered, the call fails and returns error code DiagOfferErrc::kAlreadyOffered with rollback semantics in ara::core::Result<void> [SWS_DM_00557].
  • Negative diagnostic responses (UDS NRC): If an error occurs during routine execution, the future is not fulfilled with OperationOutput. Instead, an appropriate Negative Response Code according to ISO 14229-1 must be returned via DiagUdsNrcErrc in the error path [SWS_DM_00554], [SWS_DM_00555], [SWS_DM_00556].
  • Cancellation of the diagnostic conversation: If an ongoing request is canceled, the application can handle this via the cancellationHandler [SWS_DM_00554]: The status can be queried actively via cancellationHandler.IsCanceled() (returns TRUE upon cancellation), or a notification callback is registered in advance via cancellationHandler.SetNotifier() that is triggered upon cancellation [SWS_DM_00554].

<h4>Context</h4>
<p>The class <code>ara::diag::GenericRoutine</code> provides a generic interface for handling diagnostic routines in the diagnostic module (<code>ara::diag</code>) of the AUTOSAR Adaptive Platform. It encapsulates the interaction around the UDS service <em>RoutineControl</em> (ISO 14229-1 Service 0x31) at the application level. In contrast to type-specifically generated routine interfaces, <code>GenericRoutine</code> processes request data generically as byte spans, allowing the same implementation to be used flexibly for different routine identifiers (<code>routineId</code>).</p>
<p>The central interaction partners are the Diagnostic Management (DM) of the AUTOSAR runtime environment and the application-specific diagnostic logic. The Diagnostic Management receives diagnostic requests from external testers and forwards incoming RoutineControl requests to the instance as soon as it has been bound to a modeled PortPrototype of type <code>DiagnosticRoutineGenericInterface</code> via a <code>ara::core::InstanceSpecifier</code> and activated <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>, <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>. The using software derives its own handler class from <code>GenericRoutine</code> and implements the application-specific execution logic in the vehicle electronic control unit.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a <code>GenericRoutine</code> instance comprises the phases creation, service provision, request processing, deregistration, and destruction.</p>
<p>During creation via constructor <code>GenericRoutine(const ara::core::InstanceSpecifier &amp;specifier, ConcurrencyType concurrencyType)</code>, the object is bound to the port defined in the model <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>. The parameter <code>concurrencyType</code> bindingly specifies whether the interface is implemented thread-safe (<code>kConcurrent</code>) or not thread-safe (<code>kNotConcurrent</code>), which determines whether callback methods may be invoked concurrently by the DM <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>.</p>
<p>Regarding ownership semantics, <code>GenericRoutine</code> is designed as a strict single instance: Both copy and move constructors and assignment operators are deleted (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01635" href="../spec/record.html?id=SWS_DM_01635">[SWS_DM_01635]</a>, <a class="spec-record-ref" data-req="SWS_DM_01636" href="../spec/record.html?id=SWS_DM_01636">[SWS_DM_01636]</a>, <a class="spec-record-ref" data-req="SWS_DM_01637" href="../spec/record.html?id=SWS_DM_01637">[SWS_DM_01637]</a>, <a class="spec-record-ref" data-req="SWS_DM_01638" href="../spec/record.html?id=SWS_DM_01638">[SWS_DM_01638]</a>. An instance therefore remains fixed at its place of creation.</p>
<p>After instantiation, the object is in the <em>Instantiated</em> state. The DM does not forward any messages at this point. Only by the synchronous invocation of <code>Offer()</code> is forwarding activated and the instance transitioned into the <em>Provided</em> state <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>. Via <code>StopOffer()</code>, the forwarding of requests by the DM can be deactivated again at any time <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</p>
<p>Destruction occurs via the virtual destructor <code>~GenericRoutine()</code> <a class="spec-record-ref" data-req="SWS_DM_00553" href="../spec/record.html?id=SWS_DM_00553">[SWS_DM_00553]</a>. The methods <code>Offer()</code>, <code>StopOffer()</code> and the destructor are not thread-safe; lifecycle transitions must therefore occur synchronized in application code <a class="spec-record-ref" data-req="SWS_DM_00553" href="../spec/record.html?id=SWS_DM_00553">[SWS_DM_00553]</a>, <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>, <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</p>

<h4>Usage Path</h4>
<p>The typical usage of <code>GenericRoutine</code> comprises the following steps:</p>
<ol>
  <li><strong>Instantiation and registration:</strong> The application creates an instance of the derived subclass specifying the <code>InstanceSpecifier</code> and the <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>. Subsequently, it enables reception via <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>.</li>
  <li><strong>Routine start (SubFunction 0x01):</strong> If the DM receives a RoutineControl request with the sub-function <em>Start</em>, it calls the pure virtual method <code>Start()</code> <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. In doing so, the <code>routineId</code>, the raw data <code>requestData</code> as <code>ara::core::Span&lt;const std::uint8_t&gt;</code>, the context <code>metaInfo</code>, and a <code>CancellationHandler</code> are passed <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. The data in <code>requestData</code> remains valid until the resulting promise is fulfilled or processing is canceled <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>.</li>
  <li><strong>Asynchronous processing:</strong> The method immediately returns a <code>ara::core::Future&lt;OperationOutput&gt;</code> to the DM <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. The actual processing takes place asynchronously in the application logic. After completion, the associated promise is fulfilled with the <code>OperationOutput</code>.</li>
  <li><strong>Optional operations:</strong> Depending on the specification of the routine, the tester can initiate further actions during or after execution:
    <ul>
      <li><code>Stop()</code> (SubFunction 0x02): Called to specifically stop a running routine <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>.</li>
      <li><code>RequestResults()</code> (SubFunction 0x03): Used to query intermediate or final results of a routine <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
    </ul>
    Both methods similarly return a <code>ara::core::Future&lt;OperationOutput&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>, <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
  <li><strong>Service termination:</strong> Prior to shutdown, the application calls <code>StopOffer()</code> to terminate forwarding by the DM <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors can occur during configuration, service registration, and execution:</p>
<ul>
  <li><strong>Configuration and instantiation errors:</strong> If binding of the <code>InstanceSpecifier</code> fails in the constructor, specific runtime violations are triggered <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>:
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not refer to a <code>PortPrototype</code>.</li>
      <li><code>PortInterfaceMappingViolation</code>: A port typed by <code>DiagnosticRoutineGenericInterface</code> is not mapped to any <code>DiagnosticServiceGenericMapping</code>.</li>
      <li><code>ProcessMappingViolation</code>: No matching modeled process exists at runtime for the existing instance reference.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another instance in the current process.</li>
    </ul>
  </li>
  <li><strong>Error during offering:</strong> If <code>Offer()</code> is called when the service is already actively offered, the call fails and returns error code <code>DiagOfferErrc::kAlreadyOffered</code> with rollback semantics in <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>.</li>
  <li><strong>Negative diagnostic responses (UDS NRC):</strong> If an error occurs during routine execution, the future is not fulfilled with <code>OperationOutput</code>. Instead, an appropriate Negative Response Code according to ISO 14229-1 must be returned via <code>DiagUdsNrcErrc</code> in the error path <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>, <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>, <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
  <li><strong>Cancellation of the diagnostic conversation:</strong> If an ongoing request is canceled, the application can handle this via the <code>cancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>: The status can be queried actively via <code>cancellationHandler.IsCanceled()</code> (returns <code>TRUE</code> upon cancellation), or a notification callback is registered in advance via <code>cancellationHandler.SetNotifier()</code> that is triggered upon cancellation <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>.</li>
</ul>
