Context

The template class ara::core::Promise<void, E> is the specialization of Promise for asynchronous operations without a regular return value (void). Its primary responsibility is to provide a common communication point—the shared state—on the producer side, via which the successful completion of an operation or an occurred error is signaled to the consumer. Interpretation: The specification in the class description that condition E != *ara::core::ErrorCode triggers a compilation error likely means in practice that ara::core::ErrorCode must mandatorily be used as error type E.

The central interaction partners include the calling producer thread, the corresponding receiver instance ara::core::Future<void, E> [SWS_CORE_06344], and the jointly managed shared state, which forms the synchronization barrier between both parties.

Lifecycle and ownership

The lifecycle of a Promise<void, E> instance is subject to strict ownership rules:

  • Creation: The default constructor initializes a promise object and creates a new shared state [SWS_CORE_06341]. It behaves equivalently to the corresponding function from std::promise and is specified as thread-safe [SWS_CORE_06341].
  • Ownership semantics: Since a shared state is always assigned to exactly one producer instance, the copy constructor [SWS_CORE_06350] and the copy assignment operator [SWS_CORE_06351] are deleted (= delete).
  • Move: The class supports move semantics: The move constructor takes over the state of the source instance [SWS_CORE_06342]. The move assignment operator abandons any existing shared state of its own (abandons shared state) and subsequently takes over the state of the passed instance analogously to Promise(std::move(other)).swap(*this) [SWS_CORE_06343]. Both move operations are not thread-safe [SWS_CORE_06342], [SWS_CORE_06343].
  • State swap: Via the method swap, two instances can swap their shared states [SWS_CORE_06352].
  • Destruction: The destructor ~Promise() releases any still held shared state (abandons any shared state) and is not thread-safe with respect to the same instance [SWS_CORE_06349].

Usage Path

The typical use of ara::core::Promise<void, E> follows a defined sequence:

  1. Retrieve future: First, the producer creates the associated Future<void, E> object via get_future() [SWS_CORE_06344]. Since only a single future is permitted per promise, this function may be called exactly once per instance [SWS_CORE_06344]. The obtained future is passed to the consumer.
  2. Execute operation: The producer executes the asynchronous computation or processing task.
  3. Set state to ready:
    • Success case: By calling set_value() without arguments, the shared state is set to the value void and transitioned to the "ready" state [SWS_CORE_06345].
    • Error case: If an error occurs, it is stored in the state via SetError() using move semantics [SWS_CORE_06353] or copy [SWS_CORE_06354], and the state is set to "ready".
    • Combined result: Alternatively, a finished Result<void, E> can be transmitted via SetResult() as a copy [SWS_CORE_06355] or rvalue [SWS_CORE_06356].

All methods for setting the result (set_value, SetError, SetResult) are specified as thread-safe [SWS_CORE_06345], [SWS_CORE_06353], [SWS_CORE_06354], [SWS_CORE_06355], [SWS_CORE_06356].

Error scenarios and preconditions

The specification defines concrete violations for incorrect call sequences:

  • Multiple retrieval of the future: If get_future() is called more than once for the same shared state, this leads to violation IsoStdFutureErrcFutureAlreadyRetrievedViolation [SWS_CORE_06344].
  • Missing shared state: If the Promise instance has no active shared state (for example, after being moved away via move), get_future() reports the violation IsoStdFutureErrcNoStateViolation [SWS_CORE_06344]. Calls to set_value() [SWS_CORE_06345], SetError() [SWS_CORE_06353], [SWS_CORE_06354], or SetResult() [SWS_CORE_06355], [SWS_CORE_06356] without state violate the precondition with PromiseNoSharedStateToSetViolation.
  • Multiple result setting: If the shared state has already been set with a value or an error, each renewed attempt of state fulfillment (via set_value, SetError, or SetResult) leads to violation IsoStdFutureErrcPromiseAlreadySatisfiedViolation [SWS_CORE_06345], [SWS_CORE_06353], [SWS_CORE_06354], [SWS_CORE_06355], [SWS_CORE_06356].
  • Exception safety: The constructors, operator=, swap, get_future, and set_value offer unconditional exception safety (noexcept) [SWS_CORE_06341], [SWS_CORE_06342], [SWS_CORE_06343], [SWS_CORE_06344], [SWS_CORE_06345], [SWS_CORE_06352]. SetError and SetResult are conditionally exception-safe (conditionally exception safe); they are noexcept if and only if the move or copy construction of the error type E is specified as nothrow [SWS_CORE_06353], [SWS_CORE_06354], [SWS_CORE_06355], [SWS_CORE_06356].

<h4>Context</h4>
<p>The template class <code>ara::core::Promise&lt;void, E&gt;</code> is the specialization of <code>Promise</code> for asynchronous operations without a regular return value (<code>void</code>). Its primary responsibility is to provide a common communication point—the shared state—on the producer side, via which the successful completion of an operation or an occurred error is signaled to the consumer. Interpretation: The specification in the class description that condition <code>E != *ara::core::ErrorCode</code> triggers a compilation error likely means in practice that <code>ara::core::ErrorCode</code> must mandatorily be used as error type <code>E</code>.</p>
<p>The central interaction partners include the calling producer thread, the corresponding receiver instance <code>ara::core::Future&lt;void, E&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>, and the jointly managed shared state, which forms the synchronization barrier between both parties.</p>

<h4>Lifecycle and ownership</h4>
<p>The lifecycle of a <code>Promise&lt;void, E&gt;</code> instance is subject to strict ownership rules:</p>
<ul>
<li><strong>Creation:</strong> The default constructor initializes a promise object and creates a new shared state <a class="spec-record-ref" data-req="SWS_CORE_06341" href="../spec/record.html?id=SWS_CORE_06341">[SWS_CORE_06341]</a>. It behaves equivalently to the corresponding function from <code>std::promise</code> and is specified as thread-safe <a class="spec-record-ref" data-req="SWS_CORE_06341" href="../spec/record.html?id=SWS_CORE_06341">[SWS_CORE_06341]</a>.</li>
<li><strong>Ownership semantics:</strong> Since a shared state is always assigned to exactly one producer instance, the copy constructor <a class="spec-record-ref" data-req="SWS_CORE_06350" href="../spec/record.html?id=SWS_CORE_06350">[SWS_CORE_06350]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_CORE_06351" href="../spec/record.html?id=SWS_CORE_06351">[SWS_CORE_06351]</a> are deleted (<code>= delete</code>).</li>
<li><strong>Move:</strong> The class supports move semantics: The move constructor takes over the state of the source instance <a class="spec-record-ref" data-req="SWS_CORE_06342" href="../spec/record.html?id=SWS_CORE_06342">[SWS_CORE_06342]</a>. The move assignment operator abandons any existing shared state of its own (abandons shared state) and subsequently takes over the state of the passed instance analogously to <code>Promise(std::move(other)).swap(*this)</code> <a class="spec-record-ref" data-req="SWS_CORE_06343" href="../spec/record.html?id=SWS_CORE_06343">[SWS_CORE_06343]</a>. Both move operations are not thread-safe <a class="spec-record-ref" data-req="SWS_CORE_06342" href="../spec/record.html?id=SWS_CORE_06342">[SWS_CORE_06342]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06343" href="../spec/record.html?id=SWS_CORE_06343">[SWS_CORE_06343]</a>.</li>
<li><strong>State swap:</strong> Via the method <code>swap</code>, two instances can swap their shared states <a class="spec-record-ref" data-req="SWS_CORE_06352" href="../spec/record.html?id=SWS_CORE_06352">[SWS_CORE_06352]</a>.</li>
<li><strong>Destruction:</strong> The destructor <code>~Promise()</code> releases any still held shared state (abandons any shared state) and is not thread-safe with respect to the same instance <a class="spec-record-ref" data-req="SWS_CORE_06349" href="../spec/record.html?id=SWS_CORE_06349">[SWS_CORE_06349]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical use of <code>ara::core::Promise&lt;void, E&gt;</code> follows a defined sequence:</p>
<ol>
<li><strong>Retrieve future:</strong> First, the producer creates the associated <code>Future&lt;void, E&gt;</code> object via <code>get_future()</code> <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>. Since only a single future is permitted per promise, this function may be called exactly once per instance <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>. The obtained future is passed to the consumer.</li>
<li><strong>Execute operation:</strong> The producer executes the asynchronous computation or processing task.</li>
<li><strong>Set state to ready:</strong>
<ul>
<li><em>Success case:</em> By calling <code>set_value()</code> without arguments, the shared state is set to the value <code>void</code> and transitioned to the "ready" state <a class="spec-record-ref" data-req="SWS_CORE_06345" href="../spec/record.html?id=SWS_CORE_06345">[SWS_CORE_06345]</a>.</li>
<li><em>Error case:</em> If an error occurs, it is stored in the state via <code>SetError()</code> using move semantics <a class="spec-record-ref" data-req="SWS_CORE_06353" href="../spec/record.html?id=SWS_CORE_06353">[SWS_CORE_06353]</a> or copy <a class="spec-record-ref" data-req="SWS_CORE_06354" href="../spec/record.html?id=SWS_CORE_06354">[SWS_CORE_06354]</a>, and the state is set to "ready".</li>
<li><em>Combined result:</em> Alternatively, a finished <code>Result&lt;void, E&gt;</code> can be transmitted via <code>SetResult()</code> as a copy <a class="spec-record-ref" data-req="SWS_CORE_06355" href="../spec/record.html?id=SWS_CORE_06355">[SWS_CORE_06355]</a> or rvalue <a class="spec-record-ref" data-req="SWS_CORE_06356" href="../spec/record.html?id=SWS_CORE_06356">[SWS_CORE_06356]</a>.</li>
</ul>
</li>
</ol>
<p>All methods for setting the result (<code>set_value</code>, <code>SetError</code>, <code>SetResult</code>) are specified as thread-safe <a class="spec-record-ref" data-req="SWS_CORE_06345" href="../spec/record.html?id=SWS_CORE_06345">[SWS_CORE_06345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06353" href="../spec/record.html?id=SWS_CORE_06353">[SWS_CORE_06353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06354" href="../spec/record.html?id=SWS_CORE_06354">[SWS_CORE_06354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06355" href="../spec/record.html?id=SWS_CORE_06355">[SWS_CORE_06355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06356" href="../spec/record.html?id=SWS_CORE_06356">[SWS_CORE_06356]</a>.</p>

<h4>Error scenarios and preconditions</h4>
<p>The specification defines concrete violations for incorrect call sequences:</p>
<ul>
<li><strong>Multiple retrieval of the future:</strong> If <code>get_future()</code> is called more than once for the same shared state, this leads to violation <code>IsoStdFutureErrcFutureAlreadyRetrievedViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>.</li>
<li><strong>Missing shared state:</strong> If the <code>Promise</code> instance has no active shared state (for example, after being moved away via move), <code>get_future()</code> reports the violation <code>IsoStdFutureErrcNoStateViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>. Calls to <code>set_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_06345" href="../spec/record.html?id=SWS_CORE_06345">[SWS_CORE_06345]</a>, <code>SetError()</code> <a class="spec-record-ref" data-req="SWS_CORE_06353" href="../spec/record.html?id=SWS_CORE_06353">[SWS_CORE_06353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06354" href="../spec/record.html?id=SWS_CORE_06354">[SWS_CORE_06354]</a>, or <code>SetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_06355" href="../spec/record.html?id=SWS_CORE_06355">[SWS_CORE_06355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06356" href="../spec/record.html?id=SWS_CORE_06356">[SWS_CORE_06356]</a> without state violate the precondition with <code>PromiseNoSharedStateToSetViolation</code>.</li>
<li><strong>Multiple result setting:</strong> If the shared state has already been set with a value or an error, each renewed attempt of state fulfillment (via <code>set_value</code>, <code>SetError</code>, or <code>SetResult</code>) leads to violation <code>IsoStdFutureErrcPromiseAlreadySatisfiedViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_06345" href="../spec/record.html?id=SWS_CORE_06345">[SWS_CORE_06345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06353" href="../spec/record.html?id=SWS_CORE_06353">[SWS_CORE_06353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06354" href="../spec/record.html?id=SWS_CORE_06354">[SWS_CORE_06354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06355" href="../spec/record.html?id=SWS_CORE_06355">[SWS_CORE_06355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06356" href="../spec/record.html?id=SWS_CORE_06356">[SWS_CORE_06356]</a>.</li>
<li><strong>Exception safety:</strong> The constructors, <code>operator=</code>, <code>swap</code>, <code>get_future</code>, and <code>set_value</code> offer unconditional exception safety (<code>noexcept</code>) <a class="spec-record-ref" data-req="SWS_CORE_06341" href="../spec/record.html?id=SWS_CORE_06341">[SWS_CORE_06341]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06342" href="../spec/record.html?id=SWS_CORE_06342">[SWS_CORE_06342]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06343" href="../spec/record.html?id=SWS_CORE_06343">[SWS_CORE_06343]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06344" href="../spec/record.html?id=SWS_CORE_06344">[SWS_CORE_06344]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06345" href="../spec/record.html?id=SWS_CORE_06345">[SWS_CORE_06345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06352" href="../spec/record.html?id=SWS_CORE_06352">[SWS_CORE_06352]</a>. <code>SetError</code> and <code>SetResult</code> are conditionally exception-safe (<code>conditionally exception safe</code>); they are <code>noexcept</code> if and only if the move or copy construction of the error type <code>E</code> is specified as nothrow <a class="spec-record-ref" data-req="SWS_CORE_06353" href="../spec/record.html?id=SWS_CORE_06353">[SWS_CORE_06353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06354" href="../spec/record.html?id=SWS_CORE_06354">[SWS_CORE_06354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06355" href="../spec/record.html?id=SWS_CORE_06355">[SWS_CORE_06355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06356" href="../spec/record.html?id=SWS_CORE_06356">[SWS_CORE_06356]</a>.</li>
