Encrypts data asymmetrically in a single step or via a multi-part streaming operation.

The interface serves for asymmetric encryption of plaintext data on the AUTOSAR Adaptive Platform and is managed via the provided smart pointer [SWS_CRYPT_50174]. After assigning a suitable public key, messages can be transformed either compactly in a single pass or continuously via a multi-part streaming session [SWS_CRYPT_50090]. For proper execution, buffer sizes must be calculated in advance, with all context operations specified as exception-safe and thread-safe.

Context

The C++ class ara::crypto::cryp::EncryptorPublicCtx provides the standardized interface for asymmetric data encryption in the AUTOSAR Adaptive Platform. It serves client applications for encrypting plaintext data using an asymmetric public key. Configuration of the cryptographic key can take place either directly via a key object ([SWS_CRYPT_50175]) or via a reference to a key slot (KeySlot, [SWS_CRYPT_50086]). Data transfer occurs via memory-efficient buffer regions (ReadOnlyMemRegion for plaintext data and ReadWriteMemRegion for the ciphertext output).

Lifecycle

Instances of the context are managed via the shared pointer std::shared_ptr<EncryptorPublicCtx> defined in the type alias Sptr ([SWS_CRYPT_50174]). The creation itself is not part of this interface definition; instantiation is presumably performed via a higher-level factory component of the crypto architecture. The object passes through clearly defined states during its lifetime:

  • Uninitialized: After instantiation, the context does not yet possess a key. Data processing operations are not permitted in this state.
  • Configured (Ready): Calling SetKey() with an PublicKey ([SWS_CRYPT_50175]) or a KeySlot ([SWS_CRYPT_50086]) makes the context ready for use. From this state, either single-step encryption can be executed or a streaming session can be started.
  • Streaming active: The call to Start() ([SWS_CRYPT_50087]) places the context into the streaming state. Consecutive data blocks are processed via Update() ([SWS_CRYPT_50176]). The session is either completed with Finish() ([SWS_CRYPT_50088]) or aborted with Cancel() ([SWS_CRYPT_50089]), returning the context to the Configured state.

All methods of the class are specified as exception-safe (exception safe) and thread-safe (thread-safe). If the context is destroyed while a streaming operation has not yet finished, the underlying implementation is expected to clean up allocated buffers and implicitly discard the session.

State diagram: Lifecycle and state transitions of the context from configuration to transformation. Sources: [SWS_CRYPT_50086], [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089], [SWS_CRYPT_50090]

Usage Path

The class supports two processing modes: single-step processing for complete datasets and multi-step streaming for segmented data streams. Before performing encryptions, applications must account for buffer limits:

  • Via GetMinimumChunkSize()` (<a class="spec-record-ref" data-req="SWS_CRYPT_50178">[SWS_CRYPT_50178]</a>) und <code>GetMaximumChunkSize() ([SWS_CRYPT_50091]), the minimum and maximum supported input sizes for individual calls can be determined.
  • The necessary capacity of the output buffer must be queried in advance with GetRequiredOutputBufferSize() ([SWS_CRYPT_50177]). The parameter isFinal controls whether the calculation is performed for intermediate steps (false) or final calls and single steps (true).

The typical sequence of a streaming encryption is divided into the following steps:

  1. Key assignment via SetKey() with a valid PublicKey ([SWS_CRYPT_50175]).
  2. Initialization of the streaming session by calling Start() ([SWS_CRYPT_50087]).
  3. Calculation of the required output buffer size for intermediate blocks with GetRequiredOutputBufferSize(inputSize, false) ([SWS_CRYPT_50177]).
  4. Repeated transformation of data blocks via Update() ([SWS_CRYPT_50176]).
  5. Determination of the buffer size for the last block (isFinal = true) and finalization of the operation via Finish() ([SWS_CRYPT_50088]).

For compact data that can be processed in a single pass, Encrypt() ([SWS_CRYPT_50090]) provides a direct single-step call without division into start, update, and finish phases.

Sequence diagram: Typical sequence of a multi-part streaming encryption with buffer size determination. Sources: [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50177], [SWS_CRYPT_50176], [SWS_CRYPT_50088]

Error Scenarios

All methods use ara::core::Result for error signaling and guarantee rollback semantics in the event of an error:

  • State errors: A call to Start(), Encrypt(), or GetRequiredOutputBufferSize() on an uninitialized context results in ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50177]). If Update(), Finish(), or Cancel() are called without Start() having been executed beforehand, the operation fails with ara::crypto::CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089]).
  • Key and usage errors: If the provided key or KeySlot is incompatible with the context, ara::crypto::CryptoErrc::kIncompatibleObject is reported ([SWS_CRYPT_50175], [SWS_CRYPT_50086], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). If the permitted usage of the key does not include permission kAllowDataEncryption, this results in ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). If a referenced KeySlot is empty, ara::crypto::CryptoErrc::kEmptyKeySlot is reported ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • Buffer and data errors: If the provided output buffer is too small, Encrypt(), Update(), and Finish() respond with ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). Deviations from the permitted chunk sizes result in ara::crypto::CryptoErrc::kInvalidInputSize, and invalid input data in ara::crypto::CryptoErrc::kInvalidArgument.
  • Unsupported features and resource bottlenecks: If the implementation does not support streaming or a single-step call, the operation fails with ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). In the event of blocked cryptographic resources, ara::crypto::CryptoErrc::kBusyResource is returned ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).

function Cancel [SWS_CRYPT_50089] Upstream: RS_CRYPTO_02302

virtual ara::core::Result< void > Cancel () noexcept=0;

Cancel the ongoing streaming operation that has been initiated by Start() and has not yet been finished.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: c2111af75063 Provenance

The method Cancel() aborts an active streaming operation in context ara::crypto::cryp::EncryptorPublicCtx that was previously initiated via Start() and has not yet finished [SWS_CRYPT_50089]. It takes no input parameters and returns a ara::core::Result<void>, which is empty on success [SWS_CRYPT_50089]. Since the signature returns a Result directly and not a Future, the abort is likely executed synchronously.

Error Handling and Concurrency

If data processing was not started in advance by Start(), the operation fails with the error code ara::crypto::CryptoErrc::kProcessingNotStarted complying with rollback semantics [SWS_CRYPT_50089]. According to the specification, the interface is declared with noexcept, exception safe, and classified as thread-safe for concurrent access [SWS_CRYPT_50089].

Interaction in the Crypto Stack

The abort behavior implemented by Cancel() follows a unified design pattern for stateful streaming operations in the crypto module. Analogous interfaces with identical error semantics exist for:

  • signature and verification operations in SignerPrivateCtx [SWS_CRYPT_50041] and VerifierPublicCtx [SWS_CRYPT_50023],
  • symmetric and authenticated ciphers in SymmetricCipherCtx [SWS_CRYPT_50046] as well as AuthCipherCtx [SWS_CRYPT_50077],
  • asymmetric decryption in DecryptorPrivateCtx [SWS_CRYPT_50069],
  • message authentication codes in MessageAuthnCodeCtx [SWS_CRYPT_50027] as well as hash computations in HashFunctionCtx [SWS_CRYPT_50058].

          The method Finish completes the asymmetric encryption operation in the context of ara::crypto::cryp::EncryptorPublicCtx [SWS_CRYPT_50088]. The call is synchronous and is specified as noexcept, exception-safe, and thread-safe. As parameters, the function accepts the final plaintext fragment via in (ReadOnlyMemRegion) and writes the resulting ciphertext data to the output buffer out (ReadWriteMemRegion). The required buffer size for out can be determined in advance via GetRequiredOutputBufferSize(). The return value ara::core::Result<std::size_t> returns the number of bytes actually written in the success case, which may be smaller than the total capacity of the output buffer [SWS_CRYPT_50088].

          • kProcessingNotStarted: Data processing was not previously initiated by calling Start().
            • 

          • kInsufficientCapacity: The provided output buffer out is dimensioned too small.
            • 

          • kInvalidInputSize: The buffer size of in cannot be processed by the context.
            • 

          • kInvalidArgument: The passed input data contains invalid values.
            • 

          • kUnsupported: Stream processing is not supported by the concrete context.
            • 

          


          Interaction
          

          Finalization concludes the cryptographic processing sequence [SWS_CRYPT_50088]. DecryptorPrivateCtx::Finish [SWS_CRYPT_50068] acts as the complementary counterpart for decryption, while in the area of symmetric ciphers SymmetricCipherCtx::Finish [SWS_CRYPT_50045] provides a comparable sequence pattern.
