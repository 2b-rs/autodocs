Context

The interface ara::crypto::cryp::EncryptorPublicCtx provides the abstraction for asymmetric encryption operations in the crypto module of the AUTOSAR Adaptive Platform. The class derives from CryptoContext and serves as the primary service provider for transforming plaintext data into ciphertext using an asymmetric public key. It typically interacts with two other entities: the calling application software, which requests the cryptographic operation and passes data buffers, and an asymmetric key object. Either a directly passed public key (PublicKey) according to [SWS_CRYPT_50175] or a persistent or managed key slot (KeySlot) according to [SWS_CRYPT_50086] serves as the key source.

Lifecycle

Instances of EncryptorPublicCtx are typically managed in client applications via the provided smart pointer type alias Sptr (std::shared_ptr<EncryptorPublicCtx>) [SWS_CRYPT_50174]. Interpretation: Instantiation of the context presumably takes place via factory methods of a higher-level crypto provider, since the interface declares pure virtual methods. All interface methods are specified as exception-safe (exception safe) and thread-safe (thread-safe).

During its lifetime, the context passes through clearly defined processing states:

  • Not initialized (Uninitialized): After creation, the context is in the Uninitialized state. If an attempt is made to process data or query buffer sizes in this state, the methods fail with CryptoErrc::kUninitializedContext ([SWS_CRYPT_50090], [SWS_CRYPT_50087], [SWS_CRYPT_50177]).
  • Initialized (Initialized): By assigning a key using SetKey() with a PublicKey::Sptr [SWS_CRYPT_50175] or a KeySlot::Sptr [SWS_CRYPT_50086], the context transitions to the ready state. From here, either single-block processing (Single-Call) via Encrypt() [SWS_CRYPT_50090] or multi-step streaming processing can be started.
  • Streaming active (Processing): The call to Start() puts the context into the active streaming phase [SWS_CRYPT_50087]. In this state, input data can be processed continuously via Update() [SWS_CRYPT_50176].
  • Completion or cancellation: The streaming phase is completed regularly by calling Finish() [SWS_CRYPT_50088], whereby the last data block is encrypted and the context returns to the Initialized state. Alternatively, the ongoing operation can be discarded prematurely with Cancel() [SWS_CRYPT_50089]. A direct call to Update(), Finish(), or Cancel() without prior Start() is rejected with CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089]).

State diagram: States and transitions of EncryptorPublicCtx. Sources: [SWS_CRYPT_50086], [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089], [SWS_CRYPT_50090]

Usage Path

The specification provides for two primary processing paths: single-step processing (Single-Call) and step-by-step streaming processing.

In single-step processing, the application first assigns the public key (SetKey()) and optionally checks the permitted input sizes via GetMinimumChunkSize() [SWS_CRYPT_50178] as well as GetMaximumChunkSize() [SWS_CRYPT_50091]. To determine the required output buffer size, the application calls GetRequiredOutputBufferSize() with the parameter isFinal = true [SWS_CRYPT_50177]. Subsequently, calling Encrypt(in, out) executes the transformation directly in a single step [SWS_CRYPT_50090].

In streaming processing, execution takes place in the following steps:

  1. Key assignment: Configuration of the context via SetKey() with a PublicKey [SWS_CRYPT_50175] or KeySlot [SWS_CRYPT_50086].
  2. Initialization: Call of Start() to open the streaming session [SWS_CRYPT_50087].
  3. Ongoing processing: Repeated passing of plaintext segments to Update(in, out) [SWS_CRYPT_50176]. The required buffer size for the intermediate steps can be determined beforehand using GetRequiredOutputBufferSize(inputSize, false) [SWS_CRYPT_50177].
  4. Finalization: Passing of the final data block and completion of the encryption via Finish(in, out) [SWS_CRYPT_50088]. The output capacity is calculated for this purpose using GetRequiredOutputBufferSize(inputSize, true). If the session must be terminated prematurely, Cancel() aborts the operation [SWS_CRYPT_50089].

Sequence diagram: Typical call sequence for streaming encryption. Sources: [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50177], [SWS_CRYPT_50176], [SWS_CRYPT_50088]

Error Scenarios

Methods of EncryptorPublicCtx signal errors via the return type ara::core::Result. All specified errors follow rollback semantics, so that the context remains in a consistent state upon failure:

  • ara::crypto::CryptoErrc::kUninitializedContext: The operation requires a configured context, but no key was assigned prior to calling Encrypt() [SWS_CRYPT_50090], Start() [SWS_CRYPT_50087], or GetRequiredOutputBufferSize() [SWS_CRYPT_50177].
  • ara::crypto::CryptoErrc::kProcessingNotStarted: Call of Update() [SWS_CRYPT_50176], Finish() [SWS_CRYPT_50088], or Cancel() [SWS_CRYPT_50089] without Start() having been called successfully beforehand.
  • ara::crypto::CryptoErrc::kUsageViolation: The provided key does not possess the permission kAllowDataEncryption strictly required for encryption operations ([SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • ara::crypto::CryptoErrc::kIncompatibleObject: The passed key object or the referenced KeySlot is incompatible with the underlying transformation ([SWS_CRYPT_50086], [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • ara::crypto::CryptoErrc::kEmptyKeySlot: An assigned KeySlot does not contain a key at the time of execution ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • ara::crypto::CryptoErrc::kInsufficientCapacity: The buffer out provided for the ciphertext is insufficient to hold the generated data ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]).
  • ara::crypto::CryptoErrc::kInvalidInputSize and ara::crypto::CryptoErrc::kInvalidArgument: The size of the input data is outside the processable block limits or the input data contains invalid structures ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]).
  • ara::crypto::CryptoErrc::kUnsupported: The concrete implementation does not support the respective mode (e.g., streaming processing versus single-call) or the key assignment type ([SWS_CRYPT_50086], [SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]).
  • ara::crypto::CryptoErrc::kBusyResource: Required hardware or software resources of the crypto module are busy ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
