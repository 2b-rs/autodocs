Enables State Management to request and monitor communication states of logical and physical networks.

ara::nm::NetworkHandle represents a movable, non-copyable access object with which State Management requests and monitors the communication state of networks via an instance specifier [SWS_ANM_01000], [SWS_ANM_01001]. In addition to synchronous status queries, the class enables setting requests and registering notifiers for effective or requested states [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]. Missing service availability or erroneous notifiers are reported via standardized error codes in the result object.

Context

In module nm, class ara::nm::NetworkHandle functions as a standardized access object for a concrete logical or physical network handle addressed via an ara::core::InstanceSpecifier of a port prototype [SWS_ANM_01000], [SWS_ANM_01001]. The primary user of this interface is functional State Management (SM), which announces and monitors communication needs for partial network clusters (PNC), VLANs, or physical networks via the handle [SWS_ANM_01000], [SWS_ANM_01009]. As an intermediary layer, the object encapsulates the interaction between the requesting function group and the underlying NM subsystem.

Context diagram: Embedding of NetworkHandle between State Management and network management. Sources: [SWS_ANM_01000], [SWS_ANM_01001], [SWS_ANM_01009], [SWS_ANM_01010], [SWS_ANM_01020], [SWS_ANM_01007]

Lifecycle

A ara::nm::NetworkHandle is instantiated explicitly by specifying a valid ara::core::InstanceSpecifier for a NetworkManagementPortInterface; this constructor is specified as thread-safe [SWS_ANM_01001]. The instance has exclusive semantics: copy constructor and copy assignment operator are explicitly deleted (= delete) [SWS_ANM_01005], [SWS_ANM_01006]. The class supports move semantics via move constructor and move assignment, with the assignment not being thread-safe [SWS_ANM_01003], [SWS_ANM_01004].

Destruction takes place via the non-thread-safe destructor ~NetworkHandle() [SWS_ANM_01002]. Notifiers registered prior to destruction should presumably be deregistered by the application to avoid asynchronous accesses to invalid contexts (interpretation). Regarding network states, the handle maps two elementary levels via enum NetworkStateType: kNoCom (at least one associated network is not in the full communication state) and kFullCom (all associated networks are active) [SWS_ANM_01358].

Usage Path

The regular sequence includes instantiation, optional notifier registration, network state requesting, and subsequent release:

  • Instantiation: Creating the handle using instance specifier [SWS_ANM_01001].
  • Registering observers: Registering callback functions of type NetworkStateChangeNotifier [SWS_ANM_01020] either for the actual effective state via RegisterNetworkStateChangeNotifier [SWS_ANM_01010] or for the requested state via RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]. Both methods also exist as a template variant for specifying a user-defined execution context (ExecutorT) [SWS_ANM_01014], [SWS_ANM_01015]. At most one notifier per category can be active per handle.
  • Requesting state: Requesting full communication (NetworkStateType::kFullCom) or release (NetworkStateType::kNoCom) via SetNetworkRequestedState [SWS_ANM_01009].
  • Querying state: Synchronous reading of the currently requested state with GetNetworkRequestedState [SWS_ANM_01008] or of the actually effective network state with GetNetworkState [SWS_ANM_01007]. Both queries are thread-safe.
  • Cleanup: Explicitly unregistering callback handlers via UnregisterNetworkStateChangeNotifier [SWS_ANM_01011] and UnregisterNetworkRequestedStateChangeNotifier [SWS_ANM_01013].

Sequence diagram: Typical usage path for registering notifiers, requesting state, and querying. Sources: [SWS_ANM_01001], [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]

Error Scenarios

Method calls on NetworkHandle signal errors via ara::core::Result. The following error cases are specified:

  • NmErrc::kServiceNotAvailable: Occurs for SetNetworkRequestedState [SWS_ANM_01009], GetNetworkRequestedState [SWS_ANM_01008], and GetNetworkState [SWS_ANM_01007] if the underlying network management service is unavailable or unreachable.
  • NmErrc::kInvalidHandler: Returned by the notifier registration methods [SWS_ANM_01010], [SWS_ANM_01012], [SWS_ANM_01014], [SWS_ANM_01015] if an invalid handler function is passed or a notifier is already registered.

Regarding concurrency, reading status queries GetNetworkState and GetNetworkRequestedState are thread-safe, whereas modifying operations and registrations are not thread-safe and require external synchronization [SWS_ANM_01007], [SWS_ANM_01008], [SWS_ANM_01009], [SWS_ANM_01010].

Usage and lifecycle

The class NetworkHandle acts as an access object to a network handle addressed via an ara::core::InstanceSpecifier, and is intended for State Management [SWS_ANM_01000]. Instantiation is performed by passing the InstanceSpecifier of an NetworkManagementPortInterface port prototype [SWS_ANM_01001]. Since the class is declared as final, it cannot be used as a base class for derivation [SWS_ANM_01000].

Move Semantics and Concurrency

Objects of this class have move-only semantics: The copy constructor [SWS_ANM_01005] and the copy assignment operator [SWS_ANM_01006] are deleted (= delete). Instead, instances can be transferred via the move constructor [SWS_ANM_01003] and the move assignment operator [SWS_ANM_01004].

Regarding thread safety, the following requirements apply:

  • The constructor with InstanceSpecifier is thread-safe (thread-safe) [SWS_ANM_01001].
  • For the move constructor, thread safety is implementation-defined (implementation-defined) [SWS_ANM_01003].
  • The destructor [SWS_ANM_01002] and the move assignment [SWS_ANM_01004] are explicitly designated as not thread-safe (not thread-safe). Interpretation: Since thread safety is not guaranteed, the calling context is likely responsible for external synchronization if multiple threads use the same handle.

Error handling

All constructors, assignment operators, and the destructor are declared as noexcept [SWS_ANM_01001], [SWS_ANM_01002], [SWS_ANM_01003], [SWS_ANM_01004]. Exceptions or error return values are not provided in this class interface.
