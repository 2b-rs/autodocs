Role in the Crypto Stack

ara::crypto::cryp::KeyAgreementPrivateCtx is an algorithm-specific crypto context. It separates the selection/binding of key and algorithm from the execution of a concrete operation and, where supported, follows the uniform single-call or streaming pattern. SWS Cryptography §7.4 “Crypto Contexts”

Call pattern

A context is created with an appropriate AlgId and configured before key-bound operations. Single steps are suitable for complete messages; the streaming API follows the scheme Start(), one or more Update() and Finish(). Output sizes and IV requirements can be queried in advance if the respective class offers this. SWS Cryptography §7.4.1 “Overview”

Streaming contexts are configured before processing and exited through completion or cancellation. Source: SWS Cryptography §7.4.1 “Overview”. Partial interpretation: The state names condense the API sequences.

Error and resource model

The caller checks ara::core::Result, key compatibility, allowed usage, buffer size and context state. A second hardware resource that is used in parallel may be temporarily unavailable; Instead of blocking indefinitely, the provider can report a busy error. SWS Cryptography §7.1.6 “Concurrent Access”

Classification of the operation

ara::crypto::cryp::KeyAgreementPrivateCtx::AgreeKey Performs the actual cryptographic transformation with the previously determined algorithm and key configuration. If there are errors or incorrect usage rights, no successful result will be assumed. [SWS_CRYPT_21312]

Checkpoint before and after the call

Before the call, the object state, algorithm and key compatibility as well as available buffers are checked. After that, only the return status determines further processing; kBusyResource, usage violations or insufficient capacity will not be treated as a partial success.
