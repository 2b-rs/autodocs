Context

The class ara::shwa::Id represents a typed identifier within the module shwa of the AUTOSAR Adaptive Platform, designed for multidimensional indexing. The class definition is implemented as class template template <int Dimensions = 1> class Id final. Interpretation: The module shwa addresses shared hardware or workload structures, with ara::shwa::Id presumably serving as a structured coordinate or index key for uniquely addressing work packages, buffers, or data points along up to three dimensions.

Interaction partners of ara::shwa::Id are primarily client adaptive applications as well as functional components of the shwa subsystem. The class encapsulates dimensions and indices so that higher-level processing functions can receive position-related parameters in a type-safe manner. Since the class is specified as final, derivation is precluded; it functions as a self-contained value type.

Lifecycle

The lifecycle of an instance of ara::shwa::Id necessarily begins via static factory methods. The default constructor is explicitly deleted ([AP_SWS_SHWA_00702]), which prevents incompletely initialized instances at compile time. Object creation instead takes place via overloaded Create methods, each returning an instance packaged in an ara::core::Result:

  • One-dimensional initialization using Create(const std::size_t dim0) ([AP_SWS_SHWA_00707]). This variant is designated as thread-safe.
  • Two-dimensional initialization using Create(std::size_t dim0, std::size_t dim1) ([AP_SWS_SHWA_00708]). This variant is declared as not thread-safe.
  • Three-dimensional initialization using Create(std::size_t dim0, std::size_t dim1, std::size_t dim2) ([AP_SWS_SHWA_00709]). This variant is also declared as not thread-safe.

With regard to ownership semantics and the copy model, ara::shwa::Id behaves like a regular value type. Copy constructor ([AP_SWS_SHWA_00703]) and copy assignment operator ([AP_SWS_SHWA_00704]) are defined as noexcept=default and ensure full exception safety (Exception Safe). Move constructor ([AP_SWS_SHWA_00705]) and move assignment operator ([AP_SWS_SHWA_00706]) with noexcept=default are likewise provided. Instances can therefore be efficiently moved, copied, and held in standard containers. Upon leaving scope, the instance is automatically destroyed; additional cleanup or destruction steps are not specified.

With regard to concurrency, it should be noted for existing instances that read and write accesses via Get ([AP_SWS_SHWA_00710]) and Set ([AP_SWS_SHWA_00711]) are not thread-safe according to the specification. If multiple threads of execution modify the same instance or read and write concurrently, the caller must ensure external synchronization.

Usage Path

The regular usage path comprises instantiation via one of the factory functions, evaluation of the ara::core::Result, optional adaptation of individual dimension values, and reading of the indices.

  1. Creation: For example, the application calls ara::shwa::Id::Create(dim0) ([AP_SWS_SHWA_00707]) or one of the multidimensional overloads ([AP_SWS_SHWA_00708], [AP_SWS_SHWA_00709]).
  2. Result check: The returned ara::core::Result<Id> is checked for errors (e.g. via HasValue()). In case of success, the instance is unpacked.
  3. Modification: An index for a specific dimension can be selectively updated via Set(dimension, index) ([AP_SWS_SHWA_00711]).
  4. Query: Using Get(dimension) ([AP_SWS_SHWA_00710]), the application queries the stored index of the specified dimension.

Sequence diagram: Typical sequence of creation, modification, and query of an Id instance. Sources: [AP_SWS_SHWA_00707], [AP_SWS_SHWA_00710], [AP_SWS_SHWA_00711]

Error Scenarios

Error situations are signaled during object creation via the AUTOSAR standard pattern ara::core::Result without C++ exceptions. The methods Create have the exception classification "exception safe" and are declared as noexcept ([AP_SWS_SHWA_00707], [AP_SWS_SHWA_00708], [AP_SWS_SHWA_00709]). In case of an error, the return values contain an error code:

  • ShwaErrorCode::kRuntime: General runtime error during factory execution (General runtime error). In this case, rollback semantics take effect, so that no invalid instance remains.

For the element access methods Get ([AP_SWS_SHWA_00710]) and Set ([AP_SWS_SHWA_00711]), the specification indicates the classification "not exception safe". The caller must ensure that a valid dimension index lying within the dimensionality of the object is passed as dimension, since invalid parameter values can lead to runtime errors.

  <h4>Context</h4>
  <p>
    The class <code>ara::shwa::Id</code> represents a typed identifier within the module <code>shwa</code> of the AUTOSAR Adaptive Platform, designed for multidimensional indexing. The class definition is implemented as class template <code>template &lt;int Dimensions = 1&gt; class Id final</code>. Interpretation: The module <code>shwa</code> addresses shared hardware or workload structures, with <code>ara::shwa::Id</code> presumably serving as a structured coordinate or index key for uniquely addressing work packages, buffers, or data points along up to three dimensions.
  </p>
  <p>
    Interaction partners of <code>ara::shwa::Id</code> are primarily client adaptive applications as well as functional components of the <code>shwa</code> subsystem. The class encapsulates dimensions and indices so that higher-level processing functions can receive position-related parameters in a type-safe manner. Since the class is specified as <code>final</code>, derivation is precluded; it functions as a self-contained value type.
  </p>

  <h4>Lifecycle</h4>
  <p>
    The lifecycle of an instance of <code>ara::shwa::Id</code> necessarily begins via static factory methods. The default constructor is explicitly deleted (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00702" href="../spec/record.html?id=AP_SWS_SHWA_00702">[AP_SWS_SHWA_00702]</a>), which prevents incompletely initialized instances at compile time. Object creation instead takes place via overloaded <code>Create</code> methods, each returning an instance packaged in an <code>ara::core::Result</code>:
  </p>
  <ul>
    <li>One-dimensional initialization using <code>Create(const std::size_t dim0)</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00707" href="../spec/record.html?id=AP_SWS_SHWA_00707">[AP_SWS_SHWA_00707]</a>). This variant is designated as thread-safe.</li>
    <li>Two-dimensional initialization using <code>Create(std::size_t dim0, std::size_t dim1)</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00708" href="../spec/record.html?id=AP_SWS_SHWA_00708">[AP_SWS_SHWA_00708]</a>). This variant is declared as not thread-safe.</li>
    <li>Three-dimensional initialization using <code>Create(std::size_t dim0, std::size_t dim1, std::size_t dim2)</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00709" href="../spec/record.html?id=AP_SWS_SHWA_00709">[AP_SWS_SHWA_00709]</a>). This variant is also declared as not thread-safe.</li>
  </ul>
  <p>
    With regard to ownership semantics and the copy model, <code>ara::shwa::Id</code> behaves like a regular value type. Copy constructor (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00703" href="../spec/record.html?id=AP_SWS_SHWA_00703">[AP_SWS_SHWA_00703]</a>) and copy assignment operator (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00704" href="../spec/record.html?id=AP_SWS_SHWA_00704">[AP_SWS_SHWA_00704]</a>) are defined as <code>noexcept=default</code> and ensure full exception safety (Exception Safe). Move constructor (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00705" href="../spec/record.html?id=AP_SWS_SHWA_00705">[AP_SWS_SHWA_00705]</a>) and move assignment operator (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00706" href="../spec/record.html?id=AP_SWS_SHWA_00706">[AP_SWS_SHWA_00706]</a>) with <code>noexcept=default</code> are likewise provided. Instances can therefore be efficiently moved, copied, and held in standard containers. Upon leaving scope, the instance is automatically destroyed; additional cleanup or destruction steps are not specified.

  </p>

  <h4>Error Scenarios</h4>
  <p>
    Error situations are signaled during object creation via the AUTOSAR standard pattern <code>ara::core::Result</code> without C++ exceptions. The methods <code>Create</code> have the exception classification "exception safe" and are declared as <code>noexcept</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00707" href="../spec/record.html?id=AP_SWS_SHWA_00707">[AP_SWS_SHWA_00707]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00708" href="../spec/record.html?id=AP_SWS_SHWA_00708">[AP_SWS_SHWA_00708]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00709" href="../spec/record.html?id=AP_SWS_SHWA_00709">[AP_SWS_SHWA_00709]</a>). In case of an error, the return values contain an error code:

  <p>
    For the element access methods <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00710" href="../spec/record.html?id=AP_SWS_SHWA_00710">[AP_SWS_SHWA_00710]</a>) and <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00711" href="../spec/record.html?id=AP_SWS_SHWA_00711">[AP_SWS_SHWA_00711]</a>), the specification indicates the classification "not exception safe". The caller must ensure that a valid dimension index lying within the dimensionality of the object is passed as <code>dimension</code>, since invalid parameter values can lead to runtime errors.
