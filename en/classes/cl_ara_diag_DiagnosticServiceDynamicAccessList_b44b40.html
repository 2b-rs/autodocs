Context

The class ara::diag::DiagnosticServiceDynamicAccessList provides the central interface for adaptive applications (Adaptive Applications, AA) to create a dynamic access list (DynamicAccessList) for diagnostic services ([SWS_DM_01156]). It is declared in the header file ara/diag/diagnostic_service_dynamic_access_list.h (AUTOSAR_AP_SWS_Diagnostics §8.13 “Header: ara/diag/diagnostic_service_dynamic_access_list.h”).

The class acts as a factory and buffer for configuring service patterns: via special factory methods, it creates builder objects of type DynamicAccessListDiagServiceBuilder ([SWS_DM_01164], [SWS_DM_01165]). Interpretation: The resulting access list presumably serves the diagnostic management system at runtime as a rule set to dynamically authorize or restrict incoming diagnostic requests based on their service identifiers or byte sequences.

Lifecycle

Instances of DiagnosticServiceDynamicAccessList are instantiated via the parameterless default constructor ([SWS_DM_01157]). The class implements full value semantics and supports copy and move operations:

  • Copy operations: Existing access lists can be duplicated via the copy constructor ([SWS_DM_01159]) and the copy assignment operator ([SWS_DM_01161]).
  • Move operations: Buffered patterns and internal memory structures can be transferred without allocation overhead via the move constructor ([SWS_DM_01160]) and the move assignment operator ([SWS_DM_01162]).
  • Destruction: The destructor ([SWS_DM_01158]) cleans up all allocated resources of the object.

Regarding concurrency, the specification strictly distinguishes between creation and use: While all constructors (default, copy, and move constructor) are designated as thread-safe (thread-safe) ([SWS_DM_01157], [SWS_DM_01159], [SWS_DM_01160]), the destructor ([SWS_DM_01158]), the assignment operators ([SWS_DM_01161], [SWS_DM_01162]), and the modifying member functions ([SWS_DM_01163], [SWS_DM_01164], [SWS_DM_01165]) are not thread-safe (not thread-safe). Concurrent access by multiple threads to the same instance therefore requires external synchronization.

Usage Path

The typical usage of DiagnosticServiceDynamicAccessList is divided into the following steps:

  1. Instantiation: Creating an instance via the default constructor ([SWS_DM_01157]).
  2. Memory pre-allocation (Reserve): Before adding service patterns, internal memory can be reserved in advance via Reserve(numberOfServiceHeads, maxServiceHeadSize) ([SWS_DM_01163]). This enables a worst-case calculation of the required memory for the planned number of service headers and their maximum byte length in order to minimize subsequent reallocations.
  3. Creation of patterns (MakeServiceBuilder): For each pattern to be registered, the application calls MakeServiceBuilder:
    • Via the single-byte SID overload MakeServiceBuilder(DynamicAccessListDiagServiceBuilder::Byte sid) ([SWS_DM_01164]) if the pattern consists exclusively of the service identifier.
    • Via the byte string overload MakeServiceBuilder(DynamicAccessListDiagServiceBuilder::ByteString serviceHead) ([SWS_DM_01165], AUTOSAR_AP_SWS_Diagnostics §8.13.1.1.3 “Member Functions”) if the pattern is formed from a byte sequence (e.g., SID combined with subfunction).
  4. Pattern definition: Using the instance of DynamicAccessListDiagServiceBuilder returned by MakeServiceBuilder, the application performs the fine-grained configuration of the service pattern.

Sequence diagram: Sequence for instantiation, memory reservation, and step-by-step creation of service patterns via DiagnosticServiceDynamicAccessList. Sources: [SWS_DM_01157], [SWS_DM_01163], [SWS_DM_01164], [SWS_DM_01165]

Error Scenarios

The API of DiagnosticServiceDynamicAccessList completely dispenses with error return values and C++ exceptions:

  • Exception safety (Exception Safety): All functions of the class – constructors ([SWS_DM_01157], [SWS_DM_01159], [SWS_DM_01160]), assignment operators ([SWS_DM_01161], [SWS_DM_01162]), destructor ([SWS_DM_01158]), Reserve ([SWS_DM_01163]), and MakeServiceBuilder ([SWS_DM_01164], [SWS_DM_01165]) – are declared as noexcept and are exception-safe (exception safe). No ara::core::Result error objects are returned.
  • Preconditions for memory reservation: The function Reserve ([SWS_DM_01163]) works with estimates for the worst-case demand. If the application underestimates the number or size of the patterns, this does not lead to an abort, but may necessitate subsequent dynamic reallocations.
  • Synchronization requirement: Since modifications are not thread-safe ([SWS_DM_01163], [SWS_DM_01164], [SWS_DM_01165]), unprotected concurrent pattern creation leads to data races (data races) and undefined behavior.

<h4>Context</h4>
<p>The class <code>ara::diag::DiagnosticServiceDynamicAccessList</code> provides the central interface for adaptive applications (Adaptive Applications, AA) to create a dynamic access list (<code>DynamicAccessList</code>) for diagnostic services (<a class="spec-record-ref" data-req="SWS_DM_01156" href="../spec/record.html?id=SWS_DM_01156">[SWS_DM_01156]</a>). It is declared in the header file <code>ara/diag/diagnostic_service_dynamic_access_list.h</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=428">AUTOSAR_AP_SWS_Diagnostics §8.13 “Header: ara/diag/diagnostic_service_dynamic_access_list.h”</a>).</p>
<p>The class acts as a factory and buffer for configuring service patterns: via special factory methods, it creates builder objects of type <code>DynamicAccessListDiagServiceBuilder</code> (<a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>, <a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>). Interpretation: The resulting access list presumably serves the diagnostic management system at runtime as a rule set to dynamically authorize or restrict incoming diagnostic requests based on their service identifiers or byte sequences.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>DiagnosticServiceDynamicAccessList</code> are instantiated via the parameterless default constructor (<a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>). The class implements full value semantics and supports copy and move operations:</p>
<ul>
  <li><strong>Copy operations:</strong> Existing access lists can be duplicated via the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01159" href="../spec/record.html?id=SWS_DM_01159">[SWS_DM_01159]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01161" href="../spec/record.html?id=SWS_DM_01161">[SWS_DM_01161]</a>).</li>
  <li><strong>Move operations:</strong> Buffered patterns and internal memory structures can be transferred without allocation overhead via the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01160" href="../spec/record.html?id=SWS_DM_01160">[SWS_DM_01160]</a>) and the move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01162" href="../spec/record.html?id=SWS_DM_01162">[SWS_DM_01162]</a>).</li>
  <li><strong>Destruction:</strong> The destructor (<a class="spec-record-ref" data-req="SWS_DM_01158" href="../spec/record.html?id=SWS_DM_01158">[SWS_DM_01158]</a>) cleans up all allocated resources of the object.</li>
</ul>
<p>Regarding concurrency, the specification strictly distinguishes between creation and use: While all constructors (default, copy, and move constructor) are designated as thread-safe (<em>thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>, <a class="spec-record-ref" data-req="SWS_DM_01159" href="../spec/record.html?id=SWS_DM_01159">[SWS_DM_01159]</a>, <a class="spec-record-ref" data-req="SWS_DM_01160" href="../spec/record.html?id=SWS_DM_01160">[SWS_DM_01160]</a>), the destructor (<a class="spec-record-ref" data-req="SWS_DM_01158" href="../spec/record.html?id=SWS_DM_01158">[SWS_DM_01158]</a>), the assignment operators (<a class="spec-record-ref" data-req="SWS_DM_01161" href="../spec/record.html?id=SWS_DM_01161">[SWS_DM_01161]</a>, <a class="spec-record-ref" data-req="SWS_DM_01162" href="../spec/record.html?id=SWS_DM_01162">[SWS_DM_01162]</a>), and the modifying member functions (<a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>, <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>, <a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>) are not thread-safe (<em>not thread-safe</em>). Concurrent access by multiple threads to the same instance therefore requires external synchronization.</p>

<h4>Usage Path</h4>
<p>The typical usage of <code>DiagnosticServiceDynamicAccessList</code> is divided into the following steps:</p>
<ol>
  <li><strong>Instantiation:</strong> Creating an instance via the default constructor (<a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>).</li>
  <li><strong>Memory pre-allocation (Reserve):</strong> Before adding service patterns, internal memory can be reserved in advance via <code>Reserve(numberOfServiceHeads, maxServiceHeadSize)</code> (<a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>). This enables a worst-case calculation of the required memory for the planned number of service headers and their maximum byte length in order to minimize subsequent reallocations.</li>
  <li><strong>Creation of patterns (MakeServiceBuilder):</strong> For each pattern to be registered, the application calls <code>MakeServiceBuilder</code>:
    <ul>
      <li>Via the single-byte SID overload <code>MakeServiceBuilder(DynamicAccessListDiagServiceBuilder::Byte sid)</code> (<a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>) if the pattern consists exclusively of the service identifier.</li>
      <li>Via the byte string overload <code>MakeServiceBuilder(DynamicAccessListDiagServiceBuilder::ByteString serviceHead)</code> (<a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=430">AUTOSAR_AP_SWS_Diagnostics §8.13.1.1.3 “Member Functions”</a>) if the pattern is formed from a byte sequence (e.g., SID combined with subfunction).</li>
    </ul>
  </li>
  <li><strong>Pattern definition:</strong> Using the instance of <code>DynamicAccessListDiagServiceBuilder</code> returned by <code>MakeServiceBuilder</code>, the application performs the fine-grained configuration of the service pattern.</li>
</ol>
