Context

The template class ara::shwa::Buffer forms the central abstraction for the encapsulation and management of data buffers in module shwa (Shared Hardware Acceleration) of the AUTOSAR Adaptive Platform. The class definition is parameterized via the element type T, the spatial dimensioning Dimensions, and a memory allocator AllocatorT.

Interpretation: The template parameters T and Dimensions are likely to define the elementary data type and the geometric structure of the buffer memory in order to provide multidimensional data regions for hardware accelerators.

The class mediates between the application software and memory areas that are either dynamically provided via user-defined allocators or bound directly via existing host memory pointers (hostData) ([AP_SWS_SHWA_00211], [AP_SWS_SHWA_00214]). In doing so, ara::shwa::Buffer interacts closely with dimension specifications (Range<Dimensions>) and property lists (PropertyList), which configure control parameters and metadata.

Lifecycle

The lifecycle of ara::shwa::Buffer is characterized by strict ownership semantics and factory semantics:

  • Disabled default and copy operations: The default constructor is deleted ([AP_SWS_SHWA_00202]). Likewise, the copy constructor ([AP_SWS_SHWA_00203]) and the copy assignment operator ([AP_SWS_SHWA_00204]) are defined as =delete, which precludes duplication of buffer instances.
  • Prevention of move operations: The move constructor ([AP_SWS_SHWA_00205]) and the move assignment operator ([AP_SWS_SHWA_00206]) are also deleted. A buffer instance is thus immovably bound to its memory address.
  • Creation and ownership: New buffers are created exclusively via static Create methods, which return the object encapsulated in a std::unique_ptr<Buffer> as ara::core::Result ([AP_SWS_SHWA_00209], [AP_SWS_SHWA_00210], [AP_SWS_SHWA_00211], [AP_SWS_SHWA_00212], [AP_SWS_SHWA_00213], [AP_SWS_SHWA_00214]). Exclusive ownership thus lies with the caller.
  • Destruction: Interpretation: The release of the underlying memory and internal descriptors is likely to be tied to the lifetime of the managing std::unique_ptr<Buffer> and occur upon its destruction.
  • Concurrency: The Create overloads with explicit dimension ranges ([AP_SWS_SHWA_00209], [AP_SWS_SHWA_00210], [AP_SWS_SHWA_00211], [AP_SWS_SHWA_00213], [AP_SWS_SHWA_00214]) are designated as thread-safe. The overload without dimension range ([AP_SWS_SHWA_00212]) as well as the property queries HasProperty ([AP_SWS_SHWA_00215]) and GetProperty ([AP_SWS_SHWA_00216]) are not thread-safe and require external synchronization in case of shared access.

Usage Path

A typical usage path comprises the instantiation of the buffer via the appropriate factory method as well as the subsequent checking and querying of buffer properties:

  1. Buffer creation: The application calls a static Create method, for example specifying the dimension range and optional property lists ([AP_SWS_SHWA_00209]) or integrating external host data ([AP_SWS_SHWA_00211]).
  2. Result validation: The returned ara::core::Result is checked for errors. On success, the application takes over the std::unique_ptr<Buffer>.
  3. Checking property availability: Before accessing type-specific properties, the application checks via HasProperty<PropertyT>() whether the property is supported on the buffer ([AP_SWS_SHWA_00215]).
  4. Querying the property: If the property is present, it is read out using GetProperty<PropertyT>() ([AP_SWS_SHWA_00216]), which returns the value type-safely in a ara::core::Result<PropertyT>.

Sequence diagram: Typical usage path for creating and querying properties of a buffer object. Sources: [AP_SWS_SHWA_00209], [AP_SWS_SHWA_00215], [AP_SWS_SHWA_00216]

Error Scenarios

The interface signals errors deterministically via ara::core::Result; all methods are noexcept and exception-safe:

  • ShwaErrorCode::kMemoryNotAllocated: Returned by all Create methods ([AP_SWS_SHWA_00209] to [AP_SWS_SHWA_00214]) if memory allocation fails on the host or the hardware accelerator.
  • ShwaErrorCode::kRuntime: Serves within the rollback semantics of the Create methods ([AP_SWS_SHWA_00209] to [AP_SWS_SHWA_00214]) as a general runtime error in case of errors during the creation process.
  • ShwaErrorCode::kFeatureNotSupported: Occurs when calling GetProperty<PropertyT>() ([AP_SWS_SHWA_00216]) if a requested property is not supported by the concrete buffer. An upstream call to HasProperty<PropertyT>() ([AP_SWS_SHWA_00215]) prevents this error case.
