Serves as an interface for symmetric encryption and decryption operations in data streams or single calls.

The class ara::crypto::cryp::SymmetricCipherCtx serves as a thread-safe interface for symmetric encryption and decryption operations in AUTOSAR Adaptive [SWS_CRYPT_50044]. After configuring a key via SetKey(), data can be processed either in a single call or stepwise in a streaming cycle of Start(), Update(), and Finish() [SWS_CRYPT_50138], [SWS_CRYPT_50139]. All methods are specified as noexcept and signal errors such as missing initialization or undersized buffers via ara::core::Result [SWS_CRYPT_50140].

Context

The interface ara::crypto::cryp::SymmetricCipherCtx encapsulates symmetric cryptographic transformations, which include both encryption and decryption operations. Within the crypto architecture, the class acts as an execution context for symmetric algorithms and cooperates with key objects and memory buffers. To configure the cryptographic key, the class interacts either directly with volatile keys via SymmetricKey [SWS_CRYPT_50138] or with keys managed persistently or in isolation via KeySlot [SWS_CRYPT_50043]. Plaintexts and ciphertexts to be processed as well as initialization vectors (IV) are passed and received via memory areas of type ReadOnlyMemRegion and ReadWriteMemRegion [SWS_CRYPT_50048], [SWS_CRYPT_50049].

Lifecycle

Lifecycle and ownership of the interface are primarily controlled via the typed smart pointer alias Sptr (std::shared_ptr<SymmetricCipherCtx>) [SWS_CRYPT_50137]. In practice, the provision of a concrete instance is likely to take place via a higher-level crypto factory method (interpretation), as the interface definition itself does not feature creation functions.

After instantiation, the context passes through several operational phases:

  • Uninitialized: Immediately after instantiation, no key is assigned to the context. Any processing call in this phase leads to error CryptoErrc::kUninitializedContext [SWS_CRYPT_50044], [SWS_CRYPT_50047].
  • Initialized / key bound: By calling SetKey() with a SymmetricKey [SWS_CRYPT_50138] or KeySlot [SWS_CRYPT_50043], the context becomes ready for use. From this state, either stateless single-call operations can be executed or a stateful streaming process can be started.
  • Streaming processing: A call to Start() initiates a stepwise transformation [SWS_CRYPT_50044], [SWS_CRYPT_23625]. In this phase, data can be transformed via Update() [SWS_CRYPT_50139] and the position modified via Seek() [SWS_CRYPT_23613]. The streaming state is terminated regularly by Finish() [SWS_CRYPT_50045] or FinishEncrypt() [SWS_CRYPT_23618], or aborted prematurely via Cancel() [SWS_CRYPT_50046]. Afterwards, the context returns to the initialized base state.

All methods of SymmetricCipherCtx are declared as noexcept, ensure exception safety (\"exception safe\"), and are specified as thread-safe for concurrent access [SWS_CRYPT_50044], [SWS_CRYPT_50139].

Usage Path

Determining the required buffer and chunk sizes is recommended before the actual data transformation. Via GetMinimumChunkSize() [SWS_CRYPT_50144] and GetMaximumChunkSize() [SWS_CRYPT_50050], the permitted limits for input blocks can be determined. If initialization vectors are required, their length limits can be queried using GetMinimumInputIvSize() [SWS_CRYPT_50141], GetMaximumInputIvSize() [SWS_CRYPT_50142], or GetOutputIvSize() [SWS_CRYPT_50143]. The maximum required destination buffer size for an operation is calculated using GetRequiredOutputBufferSize() [SWS_CRYPT_50140].

For stepwise stream encryption or decryption, the following standard procedure applies:

  1. Configure key: Binding the cryptographic key to the context via SetKey() [SWS_CRYPT_50138].
  2. Start transformation: Calling Start() specifying the transformation direction (encryption or decryption) and optional IV [SWS_CRYPT_23625] or without IV [SWS_CRYPT_50044].
  3. Transform data blocks: Repeated calling of Update() for the stepwise passing of input data and retrieval of output data [SWS_CRYPT_50139]. If needed, navigation within the data stream is possible via Seek() [SWS_CRYPT_23613].
  4. Completion: Finalization via Finish() [SWS_CRYPT_50045] or via FinishEncrypt() if the IV generated by the context is to be returned [SWS_CRYPT_23618].

As an alternative to this streaming pattern, the interface supports synchronous single calls. If the entire payload is available, the operation can be executed directly via ProcessSingleCall() [SWS_CRYPT_50047], ProcessSingleCallWithInputIv() [SWS_CRYPT_50048], or for context-owned IV generation via EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049].

Sequence diagram: Typical call sequence of a streaming encryption. Sources: [SWS_CRYPT_50138], [SWS_CRYPT_23625], [SWS_CRYPT_50139], [SWS_CRYPT_23618]

Error Scenarios

Methods of the class signal errors via ara::core::Result with codes of error domain ara::crypto::CryptoErrc. Essential error conditions include:

  • CryptoErrc::kUninitializedContext: Occurs when processing calls such as Start() [SWS_CRYPT_50044], single-call routines [SWS_CRYPT_50047], or GetRequiredOutputBufferSize() [SWS_CRYPT_50140] are called before a key has been configured via SetKey().
  • CryptoErrc::kProcessingNotStarted: Is triggered when streaming functions such as Update() [SWS_CRYPT_50139], Finish() [SWS_CRYPT_50045], FinishEncrypt() [SWS_CRYPT_23618], Seek() [SWS_CRYPT_23613], or Cancel() [SWS_CRYPT_50046] are executed without a prior successful call to Start().
  • CryptoErrc::kInsufficientCapacity: The provided destination buffer for data or IVs is smaller than the minimum required capacity [SWS_CRYPT_50139], [SWS_CRYPT_50049].
  • CryptoErrc::kUsageViolation and CryptoErrc::kIncompatibleObject: The passed key type is inappropriate for the transformation, or the usage rules defined in the key prohibit the operation (e.g., absence of kAllowDataEncryption or kAllowDataDecryption) [SWS_CRYPT_50044], [SWS_CRYPT_50047].
  • CryptoErrc::kEmptyKeySlot and CryptoErrc::kBusyResource: Indicates that a configured KeySlot does not contain a key at runtime or a resource required for the crypto operation is blocked [SWS_CRYPT_50048], [SWS_CRYPT_50049].
  • CryptoErrc::kUnsupported: Is returned when an operating mode (such as stream processing, single-call, or Seek()) is not supported by the selected context or algorithm [SWS_CRYPT_23613], [SWS_CRYPT_50047].

The synchronous method Cancel() of class ara::crypto::cryp::SymmetricCipherCtx serves to prematurely abort an ongoing streaming operation that was previously initiated with Start() and has not yet finished [SWS_CRYPT_50046]. The interface is declared without parameters in ara/crypto/cryp/symmetric_cipher_ctx.h and returns an empty ara::core::Result<void> upon successful execution [SWS_CRYPT_50046].

If data processing was not started beforehand by calling Start(), the operation fails with the specific error code ara::crypto::CryptoErrc::kProcessingNotStarted and rollback semantics [SWS_CRYPT_50046]. For the call context, the specification guarantees thread safety (thread-safe) as well as exception safety (exception safe) with a noexcept declaration [SWS_CRYPT_50046]. Interpretation: Due to the rollback semantics, the object will likely return to a ready initial state after an abort.

This functional pattern is consistently defined across all cryptographic streaming contexts in AUTOSAR Adaptive. Identical signatures and error semantics apply to the context classes VerifierPublicCtx ([SWS_CRYPT_50023]), MessageAuthnCodeCtx ([SWS_CRYPT_50027]), SignerPrivateCtx ([SWS_CRYPT_50041]), HashFunctionCtx ([SWS_CRYPT_50058]), DecryptorPrivateCtx ([SWS_CRYPT_50069]), AuthCipherCtx ([SWS_CRYPT_50077]), and EncryptorPublicCtx ([SWS_CRYPT_50089]).

      Usage and Buffer Handling
      

      The synchronous method EncryptSingleCallWithOutputIv performs symmetric encryption in a single call and returns the initialization vector generated by the context via the buffer ivOut [SWS_CRYPT_50049]. The input data are passed via in, while out accommodates the encrypted data [SWS_CRYPT_50049]. Upon successful execution, the result ara::core::Result<std::size_t> provides the actual size of the generated output data, which may be smaller than the total capacity of out [SWS_CRYPT_50049]. If the selected algorithm does not require an initialization vector, no data are written to ivOut [SWS_CRYPT_50049].
      

      Interaction and Preconditions
      

      Prior to the call, the context must be initialized via a suitable key [SWS_CRYPT_50049]. To ensure sufficient capacity of the buffer ivOut, the required IV length can be determined in advance via GetOutputIvSize() [SWS_CRYPT_50143]. If authentication with tag calculation is additionally required, ara::crypto::cryp::AuthCipherCtx provides the corresponding counterpart [SWS_CRYPT_50080].
      

      Error Handling and Concurrency
      

      The interface is specified as thread-safe and exception safe (“exception safe”) and applies rollback semantics in case of errors [SWS_CRYPT_50049]. Interpretation: These rollback semantics are presumably intended to ensure that, in the event of errors, the context state remains intact and no incomplete data remain valid in the buffer. Relevant errors include:
      

        

      • UninitializedContext: No key has yet been assigned to the context [SWS_CRYPT_50049].
        • 

      • ara::crypto::CryptoErrc::kInsufficientCapacity: The capacity of out or ivOut is insufficient [SWS_CRYPT_50049].
        • 

      • ara::crypto::CryptoErrc::kUnsupported: Single-call encryption is not supported or the algorithm enforces the specification of an input IV [SWS_CRYPT_50049].
        • 

      • ara::crypto::CryptoErrc::kUsageViolation or ara::crypto::CryptoErrc::kIncompatibleObject: The key type does not match the transformation or the key usage does not permit data encryption [SWS_CRYPT_50049].
