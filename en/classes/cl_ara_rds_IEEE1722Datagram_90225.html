Serves as a base class for encapsulating IEEE 1722 payload buffers and length specifications in raw data streaming.

The class ara::rds::IEEE1722Datagram serves in module rds as a base class for encapsulating IEEE 1722 streaming datagrams (AUTOSAR_AP_SWS_RawDataStream p. 1). Via the protected attribute data, it manages the dynamic byte buffer in exclusive ownership and holds the respective payload length with stream_data_length. Releasing allocated buffer resources takes place deterministically and without exceptions via the virtual destructor ~IEEE1722Datagram() [SWS_RDS_90228]. Internal synchronization for concurrent accesses does not exist, so cross-thread usages must be guarded externally.

Lifecycle

The lifecycle of a datagram instance is significantly determined by the management of the associated data buffer and the RAII paradigm. The attribute data is declared protected as std::unique_ptr<ara::core::Byte[]> [SWS_RDS_90226]. This establishes an exclusive ownership relationship: A datagram owns its byte buffer exclusively, preventing accidental copying of large amounts of data at the type level.

Together with the buffer, the length of the valid payload is maintained via the protected field stream_data_length of type std::uint16_t [SWS_RDS_90227]. Resource release takes place deterministically: The class provides a virtual destructor ~IEEE1722Datagram() noexcept [SWS_RDS_90228]. This ensures that when derived instances are destroyed via a pointer to the base class, all resources are released completely and without memory leaks.

Regarding concurrency, the base class contains no internal synchronization mechanisms. Simultaneous access to the same datagram instance from multiple threads presumably requires external coordination by the using component.

  • Length specification: The actual payload length of the stream is stored in stream_data_length [SWS_RDS_90227].
  • Passing and processing: Interpretation: The datagram is likely to be transported preferably by means of move semantics through the processing pipeline of module rds in order to avoid unnecessary copy operations of streaming data.
  • Destruction: After processing is complete, the datagram leaves its scope; the virtual destructor ~IEEE1722Datagram() is called and the buffer is deallocated automatically [SWS_RDS_90228].

Error Scenarios

Errors when handling ara::rds::IEEE1722Datagram can occur particularly during memory management and boundary checking:

  • Memory allocation error: If the allocation of the dynamic byte array for data fails, this can lead to a standard memory exception (std::bad_alloc) before the datagram is validly provided [SWS_RDS_90226].
  • Length inconsistency: If a value exceeding the real size of the memory allocated via data is entered for stream_data_length, buffer overflows threaten during read accesses [SWS_RDS_90227]. Derived classes must ensure consistency between buffer allocation and length specification.
  • Exception safety during destruction: The destructor is explicitly declared as noexcept [SWS_RDS_90228]. This guarantees that no exceptions are propagated during the destruction of the object, which is essential for the stability of RAII chains.
