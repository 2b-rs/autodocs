Manages persistent key-value pairs via transactional read and write operations with explicit synchronization.

The class provides a transactional key-value storage whose modifications are written to the physical storage medium only by SyncToStorage() or discarded by DiscardPendingChanges() [SWS_PER_00049], [SWS_PER_00365]. Instances are neither copyable nor movable and offer thread-safe access methods, but require the exclusion of concurrent calls during destruction [SWS_PER_00322], [SWS_PER_00050]. In the event of hardware defects during synchronization, automatic rollback semantics no longer take effect [SWS_PER_00049].

Context

Class ara::per::KeyValueStorage provides a typed key-value storage within the AUTOSAR Adaptive Platform that manages persistent data as a set of keys with associated values. It serves applications as the primary interface for persistently storing and retrieving configured application data. Accesses occur with transactional semantics via an internal transaction state rather than directly on the physical storage medium, as specified for read operations in [SWS_PER_00042], [SWS_PER_00043], [SWS_PER_00044], [SWS_PER_00332], and [SWS_PER_00554], for example. Modifying operations initially take effect purely transactionally and only alter the physical storage upon explicit synchronization [SWS_PER_00046], [SWS_PER_00047], [SWS_PER_00048], [SWS_PER_00049].

Lifecycle

Instantiation and ownership of ara::per::KeyValueStorage are subject to strict constraints: the default constructor [SWS_PER_00459] as well as copy and move constructors [SWS_PER_00324], [SWS_PER_00322] are deleted (=delete). Likewise, copy and move assignment operators are explicitly removed [SWS_PER_00325], [SWS_PER_00323]. Instances can thus neither be copied nor moved. Creation of a storage object occurs via initialization via OpenKeyValueStorage(), which simultaneously defines the baseline for pending changes [SWS_PER_00365]. Destructor [SWS_PER_00050] is specified as exception-safe, but explicitly as not thread-safe; destruction may therefore only take place when no parallel accesses are running anymore. In regular operation, all access methods are designed to be thread-safe, but may be delayed by concurrent write or synchronization calls from other threads [SWS_PER_00046], [SWS_PER_00049], [SWS_PER_00365].

Usage Path

A typical usage path involves setting or updating data values, optionally checking or reading the current transaction state, and finally persistently writing or discarding the changes. With SetValue<T>(), a key-value pair is assigned or overwritten in the current transaction context [SWS_PER_00046]. Existing keys can be checked via KeyExists() [SWS_PER_00043], their byte size determined via GetCurrentValueSize() [SWS_PER_00554], and their values read via the type-safe overloads of GetValue<T>() [SWS_PER_00044], [SWS_PER_00332]. Only the call to SyncToStorage() atomically transfers all accumulated changes to the physical storage medium [SWS_PER_00049]. If non-synchronized changes are to be discarded instead, DiscardPendingChanges() resets the state to the state of the last SyncToStorage() or opening [SWS_PER_00365].

Error Scenarios

All methods return errors via ara::core::Result. In doing so, a precise distinction is made between operations with a rollback guarantee and errors without rollback:

  • Configuration and write-protection errors: When write methods are called on write-protected storage or when a key is already present in write-only-once configurations, the operation fails with PerErrc::kIllegalWriteAccess [SWS_PER_00046], [SWS_PER_00047], [SWS_PER_00048], [SWS_PER_00049].
  • Type conflicts and key availability: If the data type does not match the stored type during overwriting or reading, PerErrc::kDataTypeMismatch occurs [SWS_PER_00044], [SWS_PER_00332], [SWS_PER_00046]. Keys that are not found report PerErrc::kKeyNotFound [SWS_PER_00044], [SWS_PER_00554]. For ResetKey(), PerErrc::kInitValueNotAvailable is triggered if no initial value is defined [SWS_PER_00426].
  • Storage space and quota violations: If the new data volume exceeds the configured limit maximumAllowedSize, PerErrc::kQuotaExceeded is reported [SWS_PER_00046], [SWS_PER_00049]. If physical storage is insufficient, SyncToStorage() or RecoverKey() returns error PerErrc::kOutOfStorageSpace without rollback semantics [SWS_PER_00049], [SWS_PER_00427].
  • Integrity, crypto, and hardware errors: Physical access errors (PerErrc::kPhysicalStorageFailure) have rollback semantics for read operations and SetValue() [SWS_PER_00046], but no rollback semantics for SyncToStorage() [SWS_PER_00049]. Structural corruption (PerErrc::kIntegrityCorrupted), decryption errors (PerErrc::kEncryptionFailed), or failed MAC checks (PerErrc::kAuthenticationFailed) are signaled by read, write, and recovery operations such as RecoverKey() [SWS_PER_00427].

Usage and Semantics

The synchronous member function DiscardPendingChanges of class ara::per::KeyValueStorage ([SWS_PER_00365]) is provided via header ara/per/key_value_storage.h. It takes no parameters and returns a ara::core::Result<void>. Its purpose is to discard all pending changes to the key-value storage instance that have accumulated since the last call to SyncToStorage or since opening via OpenKeyValueStorage() [SWS_PER_00365].

Interaction and Transaction Behavior

Writing operations such as SetValue [SWS_PER_00046], RemoveKey [SWS_PER_00047], and RemoveAllKeys [SWS_PER_00048] are subject to transaction semantics. Their changes are written permanently to the physical storage medium only upon calling SyncToStorage [SWS_PER_00049]. Through DiscardPendingChanges, these unsaved modifications are rolled back, so that queries via GetCurrentValueSize also reflect the previous transactional initial state again [SWS_PER_00554].

Error Handling and Concurrency

In case of an error, the result contains a vendor-specific error or an error code from PerErrc with defined rollback semantics [SWS_PER_00365]:

  • PerErrc::kIllegalWriteAccess: if the storage is read-only or, in a write-only-once configuration, the key already exists.
  • PerErrc::kPhysicalStorageFailure: if access to the physical storage medium fails.
  • PerErrc::kIntegrityCorrupted, PerErrc::kValidationFailed, PerErrc::kEncryptionFailed, or PerErrc::kAuthenticationFailed: in case of loss of integrity, validation errors, decryption errors, or failed MAC verification.

The method is declared as noexcept, exception-safe, and thread-safe [SWS_PER_00365]. However, execution may be delayed if calls to SyncToStorage, SetValue, RemoveKey, RemoveAllKeys, ResetKey, or RecoverKey are active in parallel in other threads [SWS_PER_00365] [SWS_PER_00426] [SWS_PER_00427].
