Context

The class ara::per::KeyValueStorage provides a persistent key-value storage within the AUTOSAR Adaptive Platform. Its primary responsibility is the encapsulation and management of a set of unique keys with their respective assigned data values. The class acts as a transactional interface between user processes and the physical storage medium. Read and write operations are executed decoupled via transactional semantics so that modifications are permanently committed to physical storage only through an explicit synchronization step [SWS_PER_00049].

Context diagram: Integration of the KeyValueStorage interface between application and physical storage. Sources: [SWS_PER_00042], [SWS_PER_00046], [SWS_PER_00049]

Lifecycle

Instances of ara::per::KeyValueStorage are subject to strict ownership and lifecycle rules. Both the default constructor [SWS_PER_00459] and copy and move constructors [SWS_PER_00324], [SWS_PER_00322] as well as the assignment operators [SWS_PER_00325], [SWS_PER_00323] are specified as deleted (=delete). Object creation is performed via the function OpenKeyValueStorage() [SWS_PER_00365]. Presumably, instance management is handled by the caller via pointer-based ownership structures such as smart pointers.

During operation, the class is designed to be thread-safe: all functional interfaces can be called in parallel from multiple threads, whereby concurrent calls may lead to mutual delays [SWS_PER_00046], [SWS_PER_00049]. Upon destruction via the destructor [SWS_PER_00050], this protection ends: the destructor itself is explicitly specified as not thread-safe and requires coordinated release without concurrent accesses.

Usage Path

A typical usage path comprises the validation of existing keys, setting or updating values, and final persistent storage:

  1. Check and query: Before an update, the presence of a key can be checked using KeyExists [SWS_PER_00043]. Already existing keys can be listed with GetAllKeys [SWS_PER_00042], their byte size determined via GetCurrentValueSize [SWS_PER_00554], or their content read in via GetValue [SWS_PER_00332], [SWS_PER_00044].
  2. Transactional writing: Values are stored in a typed manner or overwritten via SetValue [SWS_PER_00046]. Similarly, RemoveKey [SWS_PER_00047] or RemoveAllKeys [SWS_PER_00048] remove entries. All changes initially take effect only within the running transaction.
  3. Completion or discarding: Calling SyncToStorage [SWS_PER_00049] writes all pending changes permanently to physical storage. If unsaved modifications since the last sync or open are to be reverted, DiscardPendingChanges [SWS_PER_00365] serves this purpose. In case of defects or misconfigurations, keys can be reset to the configured initial value via ResetKey [SWS_PER_00426] or recovered via RecoverKey [SWS_PER_00427] after integrity errors.

Sequence diagram: Write access with transaction semantics and physical flush. Sources: [SWS_PER_00046], [SWS_PER_00049]

Error Scenarios

Methods of KeyValueStorage signal errors via ara::core::Result with specific error codes from PerErrc:

  • Key and type errors: If a caller attempts to access non-existent entries, GetValue, GetCurrentValueSize, RemoveKey, and RecoverKey return the error PerErrc::kKeyNotFound [SWS_PER_00332], [SWS_PER_00554], [SWS_PER_00047], [SWS_PER_00427]. If the template data type in SetValue or GetValue does not match the stored type, the API acknowledges this with PerErrc::kDataTypeMismatch [SWS_PER_00046], [SWS_PER_00044]. If no initial value exists for a key, ResetKey returns the code PerErrc::kInitValueNotAvailable [SWS_PER_00426].
  • Access and capacity limits: If a storage is write-protected or configured as write-only-once and the key already exists, every write operation (such as SetValue, RemoveKey, SyncToStorage) results in PerErrc::kIllegalWriteAccess [SWS_PER_00046], [SWS_PER_00049]. Exceeding the storage volume leads to PerErrc::kOutOfStorageSpace or, when reaching the configured limit, to PerErrc::kQuotaExceeded [SWS_PER_00046], [SWS_PER_00049].
  • Hardware, integrity, and security errors: A failure of the storage medium manifests as PerErrc::kPhysicalStorageFailure. If checksums, validations, encryption or decryption, or MAC checks fail, the operations report PerErrc::kIntegrityCorrupted, PerErrc::kValidationFailed, PerErrc::kEncryptionFailed, or PerErrc::kAuthenticationFailed, respectively, [SWS_PER_00042], [SWS_PER_00046], [SWS_PER_00049].

ResetKey function

Resets a key of this Key-Value Storage to its initial value. ResetKey allows to reset a single key to its initial value. If the key is currently not available in the Key-Value Storage, it is re-created. Afterwards, the key-value pair will appear in both cases as if it was newly installed from the current Target Configuration. ResetKey will fail with kInitValueNotAvailable when neither Application Design nor Target Configuration define an initial value for the key. ResetKey may be delayed by an ongoing call from another thread to RemoveAllKeys, SyncTo Storage, or DiscardPendingChanges, or to SetValue, GetValue, GetCurrentValueSize, Remove Key, RecoverKey, or ResetKey for the same key-value pair.
