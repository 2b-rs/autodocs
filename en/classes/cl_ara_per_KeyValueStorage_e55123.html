Role in the storage model

KeyValueStorage provides a lot of named, typed values. It can ship with predefined pairs while application code creates, modifies, and removes pairs at runtime. SWS Persistency §7.1.2 “Configuration of Key-Value Storages”

Temporary workspace

After opening, GetValue, SetValue, RemoveKey, KeyExists, and GetAllKeys take place in temporary Storage. Changes are visible between copies of the same SharedHandle, but are not made persistent solely by the end of the lifetime. SWS Persistency §7.3 “Key-Value Storage specific Features”

Explicitly persist or discard

SyncToStorage persists all changes that have occurred since opening or last synchronization and updates redundancy. DiscardPendingChanges, on the other hand, restores the last persisted state. Type changes to an existing pair require removal and re-creation. SWS Persistency §7.3 “Key-Value Storage specific Features”

Recovery and capacity

RecoverKey and Storage-wide recovery are intended for redundancy problems, but may provide older or initial data. Quota and storage-space errors are result errors and must be handled during commit. SWS Persistency §7.2.4 “Redundancy Concepts” SWS Persistency §7.2.6 “Resource Management Concepts”

The persistence boundary affects all keys changed since opening or the last synchronization; updating configured redundancy is included. Source: SWS Persistency §7.3 “Key-Value Storage specific Features”.

Recovery is best effort; In the event of an error, a report can name the affected storage or elements. Source: SWS Persistency §7.2.4 “Redundancy Concepts”. Partial interpretation: The activity sequence combines several permitted redundancy procedures.

Behavior in the event of an error and recovery

GetValue() returns its result via Result. For a missing key, PerErrc::kKeyNotFound is specified, for an inappropriate template type, PerErrc::kDataTypeMismatch is specified; When reading, kPhysicalStorageFailure, kIntegrityCorrupted, kValidationFailed, kEncryptionFailed and kAuthenticationFailed also come into consideration. In particular, SetValue() can fail with kIllegalWriteAccess, kDataTypeMismatch, kOutOfStorageSpace or kQuotaExceeded. [SWS_PER_00044] [SWS_PER_00332] [SWS_PER_00046]

SyncToStorage() persists the pairs changed since opening or last synchronization and the configured redundancy. Its error contract contains kIllegalWriteAccess, kPhysicalStorageFailure, kIntegrityCorrupted, kEncryptionFailed, kOutOfStorageSpace, kQuotaExceeded and kAuthenticationFailed. kQuotaExceeded means exceeding MaximumAllowedSize; kOutOfStorageSpace concerns insufficient physical memory. [SWS_PER_00494] [SWS_PER_00049] [SWS_PER_00543] [SWS_PER_00544]

The graphic only summarizes the central, operation-typical error outputs; the complete lists additionally contain integrity, cryptographic and hardware errors. Sources: [SWS_PER_00044] [SWS_PER_00046] [SWS_PER_00049].

If storage is structurally inaccessible, kIntegrityCorrupted is provided; Insufficiently recoverable redundancy is reported as kValidationFailed. For a single key, RecoverKey() first checks for its existence and otherwise returns kKeyNotFound; recovery is best effort and may result in a stale or initial value or lose the key. A storage-wide restore is called RecoverKeyValueStorage() in R25-11, not RecoverAllKeys, and can also leave stale values ​​or a reset to initial values. Removes all pending changes to this Key-Value Storage since the last call to SyncToStorage() or since this Key-Value Storage was opened using OpenKeyValueStorage().
