Stores type-safely exactly one value from a defined set of types with conditional exception safety.

The template class ara::core::Variant serves as a type-safe union for storing and managing exactly one value from a specified set of types [SWS_CORE_01649]. It supports flexible construction, assignment, and emplace mechanisms and allows determining the active alternative via index() [SWS_CORE_01665]. The most important distinction compared to the standard is the modified, conditional noexcept specifications of all modifying operations as well as protection against the state valueless_by_exception() [SWS_CORE_01666].

Context

The template class ara::core::Variant represents a type-safe union for the AUTOSAR Adaptive Platform, included via header ara/core/variant.h. It encapsulates the management of exactly one value from a type list defined at compile time (template <typename... Types> class Variant). The definition is fundamentally based on the behavior of std::variant from the C++ standard [variant], but exhibits specific AUTOSAR deviations regarding the exception specification. The description of the class refers in the metadata to [basic.string]; interpretation: this is likely an editorial inconsistency, as all requirements consistently reference the standard section [variant].

Lifecycle

An instance of ara::core::Variant undergoes deterministic lifecycle phases from initialization through value changes to destruction. Creation takes place either via the parameterless default constructor [SWS_CORE_01649], which initializes the first alternative, via copy and move constructors [SWS_CORE_01650], [SWS_CORE_01651], or via direct value passing [SWS_CORE_01652]. In addition, overloads for in-place construction using in_place_type_t [SWS_CORE_01653], [SWS_CORE_01654] as well as in_place_index_t [SWS_CORE_01655], [SWS_CORE_01656] are available, also in combination with initializer lists.

In the regular state, the object always holds a valid alternative whose zero-based index can be determined with method index() [SWS_CORE_01665]. If a value change fails during construction or assignment due to an exception being thrown, the instance transitions into the state valueless_by_exception() [SWS_CORE_01666]. The object remains in this state until a valid alternative is occupied again by successful re-initialization. The destructor properly destroys the currently held object and is declared conditionally exception-safe [SWS_CORE_01657].

Usage Path

A typical usage flow comprises instantiation, assigning or replacing content, querying state, and value exchange:

  • Initialization: Creating an instance via one of the constructors, for example by direct value passing [SWS_CORE_01652] or explicitly type-based using in_place_type_t [SWS_CORE_01653].
  • Value update and re-allocation: Assigning a new value via the copy assignment operator [SWS_CORE_01658], the move assignment operator [SWS_CORE_01659], or generic value assignment [SWS_CORE_01660]. Alternatively, the value can be constructed anew directly in place via emplace by type [SWS_CORE_01661], [SWS_CORE_01662] or by index [SWS_CORE_01663], [SWS_CORE_01664].
  • State check: Querying the active type index via index() [SWS_CORE_01665] as well as checking against previous errors via valueless_by_exception() [SWS_CORE_01666].
  • Object swap: Efficient swapping of two variant instances via member function swap() [SWS_CORE_01667].

Since the present specification record set comprises exclusively member functions, direct read operations such as value access are missing; access and visitation functions (analogous to std::get or std::visit) are presumably provided as free utility functions in namespace ara::core.

Error Scenarios

At the center of error handling is the property of conditional exception safety (conditionally exception safe). While the standard library provides fixed noexcept rules for std::variant, AUTOSAR deliberately deviates: all constructors [SWS_CORE_01650], [SWS_CORE_01653], assignment operators [SWS_CORE_01658], emplace operations [SWS_CORE_01661], [SWS_CORE_01663], the swap function swap() [SWS_CORE_01667], and the destructor [SWS_CORE_01657] are conditionally noexcept. Their exception guarantee depends directly on the noexcept properties of the underlying type constructors.

If constructing a new value throws an exception during an assignment or a call to emplace, the variant can enter an invalid intermediate state. This is signaled via valueless_by_exception() [SWS_CORE_01666]. Exclusively the two query functions index() [SWS_CORE_01665] and valueless_by_exception() [SWS_CORE_01666] offer an unconditional noexcept guarantee and are completely exception-safe.
