Process-near reporting point for supervision

SupervisedEntity represents an instantiated set of checkpoints in a process or subprocess. Checkpoints mark code points whose frequency, time interval or sequence is evaluated by alive, deadline or logical supervision SWS PHM §7.2 “Supervision of Supervised Entities” RS Health Monitoring (Foundation), Supervision-Arten (S. 6).

When a message can be evaluated

PHM ignores a checkpoint for evaluation if it does not belong to the reporting process or if the current configuration provides for NoCheckpointSupervision or NoSupervision. Alive supervision only begins after the kRunning message from the process; Deadline and logical supervision can start beforehand with an intra-process configuration [SWS_PHM_01229] [SWS_PHM_01341] [SWS_PHM_01331].

State diagram: The elementary evaluation has the statuses kDEACTIVATED, kOK, kFAILED and kEXPIRED; kFAILED is only relevant for alive supervision SWS PHM §7.4 “Determination of Supervision Status” [SWS_PHM_01343].

Runtime control and mode switching

Supervision modes are derived from Function Group states. Disable stops monitoring and ignores checkpoints; Enable reactivates them, with alive cycles starting over and Deadline/Logical waiting for a new source checkpoint SWS PHM §7.3 “Supervision Modes” [SWS_PHM_01364] [SWS_PHM_01366].

Sequence diagram: Checkpoint reports produce elementary and global statuses; with an expired Global Supervision, the recovery or Watchdog path can follow SWS PHM §7.4 “Determination of Supervision Status” SWS PHM §7.5 “Recovery actions”.

Behavior in the event of an error and recovery

ReportCheckpoint() has return type void and does not specify a PhmErrc return. If the checkpoint is reported by a process that is not modeled in the associated SupervisionCheckpoint.process reference, this is a InsufficientPermissionsViolation. A kServiceNotAvailable is not defined in R25-11: PhmErrc contains kOfferFailed, kSMCanNotHandleRecovery and kServiceNotReady; The latter is specified for parallel Enable()/Disable() requests. [SWS_PHM_01127] [SWS_PHM_01240] [SWS_PHM_01130] [SWS_PHM_01380]

If the checkpoint sequence is not in accordance with the configuration, the elementary supervision goes from kOK to kEXPIRED for deadline or logical supervision and ends this supervision. With alive supervision, a temporary deviation initially leads to kFAILED; Only when the counter exceeds the configured error tolerance does kEXPIRED follow. The R25-11 term is Elementary Supervision Status, not “Local Supervision Status”. [SWS_PHM_01343] [SWS_PHM_01346] [SWS_PHM_01347] [SWS_PHM_01350]

The recovery path requires assigned global supervision. The two linked participants are marked as internal interfaces. Sources: [SWS_PHM_00101] [SWS_PHM_01359] [SWS_PHM_00104].

If a Global Supervision assigned via RecoveryNotificationToPPortPrototypeMapping changes to kEXPIRED, PHM notifies State Management via RecoveryAction::RecoveryHandler. The handler is only active after a successful Offer(). If kEXPIRED occurs before this offer or after StopOffer(), PHM terminates the AliveNotification and triggers the watchdog reaction. [SWS_PHM_00101] [SWS_PHM_01147] [SWS_PHM_01359] [SWS_PHM_01360]

Even if State Management does not confirm in time after a notification, or if the handler returns kSMCanNotHandleRecovery, PHM stops the AliveNotification and calls WatchdogInterface::FireWatchdogReaction(). For Global Supervisions of State Management, Execution Management, or the operating system, an expired elementary status leads, depending on expiredSupervisionTolerance, to kEXPIRED or directly to kSTOPPED; for kSTOPPED, the watchdog response is required. [SWS_PHM_00104] [SWS_PHM_00107] [SWS_PHM_00224] [SWS_PHM_00225] [SWS_PHM_00105]

Report checkpoint at the technical checkpoint

Call ReportCheckpoint where frequency, time, or sequence is to be evaluated. PHM accepts only the Checkpoints assigned to the process for evaluation [SWS_PHM_01229] RS Health Monitoring (Foundation), Supervision-Arten (S. 6).

Consider mode and deactivation

The message cannot be evaluated in NoSupervision or during Disable. After reactivation, Deadline/Logical must reach their entry again SWS PHM §7.3 “Supervision Modes” [SWS_PHM_01365].
