intended use

The interface handles RequestFileTransfer requests for files and directories. Pure virtual methods cover reading a file, reading a directory, writing, resuming a write, and deleting; the results are delivered asynchronously as futures. [SWS_DM_01320] [SWS_DM_01331] [SWS_DM_01332] [SWS_DM_01333] [SWS_DM_01334] [SWS_DM_01335]

Interaction with other classes

For AddFile, the Diagnostic Server calls RequestWriteFile with WriteFileMode::kAdd; For ReadFile or ReadDir it calls the appropriate reading methods. Read operations return a DataTransferReadSession, write operations return a DataTransferWriteSession; File sizes are passed or returned as FileSizes. [SWS_DM_01311] [SWS_DM_01314] [SWS_DM_01315] [SWS_DM_01331] [SWS_DM_01332] [SWS_DM_01333] [SWS_DM_01334]

Lifecycle & Ownership

The constructor takes port InstanceSpecifier and ConcurrencyType. Copying and copy assignment are prohibited; Move construction and move assignment are present. [SWS_DM_01325] [SWS_DM_01327] [SWS_DM_01328] [SWS_DM_01329] [SWS_DM_01330]

Limitations & Error handling

All virtual file operations receive a MetaInfo and a CancellationHandler; this can query the abort status and register a notifier. Errors should be provided as applicable UDS-NRCs from DiagUdsNrcErrc; the implementation's thread safety follows the constructor parameter. Offer/StopOffer control the forwarding, and double offer is provided by DiagOfferErrc::kAlreadyOffered. [SWS_DM_01331] [SWS_DM_01332] [SWS_DM_01333] [SWS_DM_01334] [SWS_DM_01335] [SWS_DM_01336] [SWS_DM_01337]

Parameter and result rules RequestReadFile uses the data format identifier and provides read session and file sizes. For a read file, zero uncompressed or compressed sizes are not reported; with no compression, the compressed size is zero. RequestResumeWriteFile also provides the byte position for continuing. DeleteFile is the full delete operation. [SWS_DM_01331] [SWS_DM_01334] [SWS_DM_01335]

DeleteFile is called for RequestFileTransfer with ModeOfOperation DeleteFile and represents the complete file deletion operation [SWS_DM_01335]; As a purely virtual method, it must be implemented by the application. The fileName parameter specifies the path and name of the file to be deleted.

Result & Error handling

Additional parameters are metaInfo and the cancellationHandler for cancellation handling. The result is supplied as ara::core::Future<void>, which serves as a positive response to the UDS client or as an NRC value from DiagUdsNrcErrc in accordance with ISO 14229-1 for a negative response. Whether thread-safe implementation is required depends on the ConcurrencyType passed in the constructor; the call is exception-safe.
