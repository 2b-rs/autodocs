intended use

SovdAuthorization implements SOVD authorization at application level. GetAuthorizationUrl() and GetTokenUrl() provide the URL for authorization and token request, respectively; the DM responds with HTTP 307 and a Location header containing that URL. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] ValidateAuthorization() validates the token from the HTTP Authorization header and marks the authorized roles in the passed ClientAuthentication. [SWS_DM_01483] [SWS_DM_01470]

Creation & lifecycle

The constructor binds a PortPrototype of DiagnosticSovdAuthorizationInterface and accepts the ConcurrencyType. [SWS_DM_01489] Offer() activates forwarding, StopOffer() deactivates it again. Offer can supply kAlreadyOffered or kConfigurationMismatch. [SWS_DM_01487] [SWS_DM_01486] The destructor is exception-safe. [SWS_DM_01488]

Limitations & Error handling

After the future is deployed, the application is no longer allowed to use the referenced ClientAuthentication object. [SWS_DM_01483] A successful return value allows the DM to treat rolls up to validUntil as authenticated for the same token. [SWS_DM_01469] Validation can report kInvalidAccessToken or kTemporarilyNotAvailable. [SWS_DM_01483] URL and validation operations depend on the ConcurrencyType; Offer and StopOffer are not thread-safe. [SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01483] [SWS_DM_01487] [SWS_DM_01486]

The DM re-verifies an authorization if the token is not identical to a previously verified token that is still valid. [SWS_DM_01470] If the token is the same up to validUntil and the identity returned is the same, it can treat the client as identical. [SWS_DM_01781] [SWS_DM_01782] The URL methods receive the request query parameters and MetaInfo and each return a string asynchronously. [SWS_DM_01484] [SWS_DM_01485]

SOVD access context

SOVD authorization uses OAuth tokens in the request header. For such a request, the Diagnostic Manager uses SovdAuthorization to request the encoded authorization role from the application; based on this role, it decides whether the requested SOVD operation is authorized. function ValidateAuthorization [SWS_DM_01483] Upstream: RS_Diag_04268

virtual ara::core::Future< ValidateAuthorizationOutput > Validate Authorization (ara::core::StringView token, const MetaInfo &metaInfo, ClientAuthentication &clientAuthentication) noexcept=0;

This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.

Usage AI generated

Automatically generated usage note derived from this AUTOSAR R25-11 specification element—not official AUTOSAR text. Evidence: [SWS_…].

The virtual method ValidateAuthorization validates the token (token) sent by a SOVD client via HTTP Authorization header according to the authorization protocol used in the system; in the case of OAuth 2.0, this corresponds to the check by the resource server. Based on the result, the application sets the corresponding roles in the object passed via parameter clientAuthentication as authorized [SWS_DM_01483]. In addition, the metaInfo of the diagnostic port is transferred. The returned ara::core::Future<ValidateAuthorizationOutput> provides the validation result if successful, otherwise an error.

Error handling & concurrency

If the access token is invalid, DiagSovdErrc::kInvalidAccessToken is delivered; If it cannot currently be checked (e.g. because online verification is necessary but the authentication server cannot be reached), DiagSovdErrc::kTemporarilyNotAvailable is delivered. After the future has been fulfilled, clientAuthentication may no longer be used by the application. The ConcurrencyType passed in the constructor determines whether the implementation must be thread-safe or non-thread-safe; the method is exception-safe.
