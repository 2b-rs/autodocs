intended use

The interface processes generic SOVD content data. The Diagnostic Manager uses the instance mapped above DiagnosticSovdContentPortMapping to read SOVD data. Read returns DiagnosticSovdContentData asynchronously for a content name; Write accepts such data for “Write a Data Value”. [SWS_DM_02186] [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_02164]

Interaction with other classes

For a read request, the manager calls Read and forms the SOVD response from the aggregated content elements. For a write request, it calls Write with DiagnosticSovdContentData, whose elements are constructed using SetName and SetContent. [SWS_DM_01432] [SWS_DM_02166]

Lifecycle & Ownership

The constructor gets InstanceSpecifier and SovdContentConcurrencyType. The class is movable; Move construction and move assignment are specified. [SWS_DM_02187] [SWS_DM_02189] [SWS_DM_02190]

Limitations & Error handling

Read and Write return an SOVD error in the event of a negative result. The CancellationHandler must not be stored or used beyond the lifetime of the running operation. Offer enables request forwarding, and StopOffer terminates it; an interface already offered reports DiagOfferErrc::kAlreadyOffered. The functions shown are thread-safe. [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_02193] [SWS_DM_02194]

Parameter and Result Rules Read receives ContentName, MetaInfo and CancellationHandler and provides either abstract SOVD content data for a positive response or an SOVD error. Write receives the same context information as well as the content data to be written; This data is valid until the future is fulfilled or canceled. The constructor and destructor are exception-safe and thread-safe. [SWS_DM_02187] [SWS_DM_02188] [SWS_DM_02191] [SWS_DM_02192]

The asynchronous operations are purely virtual interface points; The concrete processing therefore implements the providing application. The external response is formed by the Diagnostic Manager based on the fulfilled futures. [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_01432]

SOVD context

The architecture describes GenericDiagnosticSovdContent as an interface for SOVD data: Read is called for “Read Single Data Value”, Write for “Write a Data Value” of the specified SOVD content instance. EXP SWArchitecture §9.8.1.1.10 SOVD data is methodically derived from DiagnosticDataIdentifier. EXP SOVD §3.1 “Common use cases in SOVD and UDS”
