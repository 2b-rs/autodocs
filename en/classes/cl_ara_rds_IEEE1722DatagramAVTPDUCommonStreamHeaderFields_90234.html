Context

Within the module rds (Raw Data Stream) of the AUTOSAR Adaptive Platform, the class ara::rds::IEEE1722DatagramAVTPDUCommonStreamHeaderFields maps the standardized header fields of an IEEE 1722 AVTPDU stream (Audio Video Transport Protocol Data Unit). The header ara/rds/raw_data_stream_IEEE1722.h declares this data type as a structural component for encapsulating AVTP data streams.

The class assumes the responsibility of providing fundamental metadata of the IEEE 1722 transport protocol. This includes, among others, timestamps via the synchronization interface ara::tsync::Timestamp [SWS_RDS_90237], sequence numbers for detecting packet loss [SWS_RDS_90240], as well as protocol-specific flags and identifiers such as time uncertainties (tu) [SWS_RDS_90241], timestamp validity indicators (tv) [SWS_RDS_90236], media restart flags (mr) [SWS_RDS_90239], addressing attributes (mac_address) [SWS_RDS_90238], and unique stream identifiers (unique_id) [SWS_RDS_90235]. Since all data members are provided with the access modifier protected, the class primarily functions as a reusable base class for specialized IEEE 1722 datagram structures within the streaming pipeline.

Lifecycle

In regular operation, instantiation does not take place in isolation via the base class, but via concrete derived datagram classes that assume the representation of complete AVTPDU messages for transmission or reception channels. The lifetime of an object is typically tied to the processing of the respective network frame or data packet within the Raw Data Stream buffer.

For destruction, the class provides a virtual destructor specified as noexcept [SWS_RDS_90242]. This ensures that derived datagram instances can be deallocated safely and without throwing exceptions when managed polymorphically via base class pointers or references. Regarding concurrency, the class possesses no internal synchronization mechanisms; instances are designed for exclusive access within the executing processing thread of the RDS pipeline.

Usage Path

The regular processing workflow comprises derivation, population, and stepwise evaluation of the stream header information during packet processing:

  1. Specialization and initialization: A derived class instantiates the header fields in the course of parsing an incoming Ethernet frame or constructing an outgoing AVTP stream.
  2. Management of optional header values: All protected attributes are typed as ara::core::Optional. Fields such as the sequence number [SWS_RDS_90240], the AVTP timestamp [SWS_RDS_90237], or stream identifiers [SWS_RDS_90235] are only populated if the concrete AVTPDU format provides for them.
  3. Evaluation in processing logic: Downstream layers of the RDS driver access the header values via interfaces of the derived class, for example to synchronize media playback via the timestamp [SWS_RDS_90237] or to detect gaps in the data stream based on the sequence number [SWS_RDS_90240].
  4. Resource release: After payload processing is completed, the datagram is released via the virtual destructor [SWS_RDS_90242].

Error Scenarios

Since the class purely performs structured data storage for protocol headers and executes no complex internal operations, runtime errors primarily occur through invalid access to unset optional fields or erroneous lifecycle management:

  • Access to incomplete stream headers: Inadvertent access to empty ara::core::Optional members (such as avtp_timestamp [SWS_RDS_90237] or sequenceNum [SWS_RDS_90240]) without prior check using has_value() leads to failed dereferences. Derived accessor methods must validate the presence of the optional values before evaluation.
  • Exception safety during destruction: The virtual destructor is declared as noexcept [SWS_RDS_90242]. This guarantees that even in the event of premature errors in the processing pipeline or when leaving scopes during stack unwinding, no secondary exceptions are thrown.
