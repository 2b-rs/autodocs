<h4>Error Scenarios</h4>
<p>Since all datagram fields are typed as <code>ara::core::Optional&lt;T&gt;</code> (for example, <code>active_pixels</code> <a class="spec-record-ref" data-req="SWS_RDS_90276" href="../spec/record.html?id=SWS_RDS_90276">[SWS_RDS_90276]</a> or <code>line_number</code> <a class="spec-record-ref" data-req="SWS_RDS_90289" href="../spec/record.html?id=SWS_RDS_90289">[SWS_RDS_90289]</a>), the class does not throw any exceptions for incomplete or fragmented AVTP headers. Instead, untransmitted or invalid fields remain in the empty state (<code>!has_value()</code>). Processing components must check before access whether the parameters required for the processing step are present in order to avoid misinterpretations of incomplete video frames.</p>
<p>In addition, the <code>noexcept</code> guarantee of the virtual destructor <a class="spec-record-ref" data-req="SWS_RDS_90292" href="../spec/record.html?id=SWS_RDS_90292">[SWS_RDS_90292]</a> ensures that safe release of the datagram objects remains guaranteed even in the event of premature aborts or errors during stream processing.</p>
