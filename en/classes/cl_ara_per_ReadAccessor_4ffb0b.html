class ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Context

Within module per (Persistency) of the Adaptive Platform, class ara::per::ReadAccessor serves for sequential reading of persistent file contents. It virtually inherits from FileAccessor and provides read access in both binary mode and text mode. Via this abstraction, applications access stored data without having to manage the physical storage directly. The interface offers granular operations for inspecting individual characters or bytes as well as methods for block-wise or complete reading of contents and lines.

Lifecycle

The lifecycle of an instance of ara::per::ReadAccessor is subject to strict requirements regarding creation and resource management:

  • Creation: According to [SWS_PER_00461], the default constructor is explicitly deleted (delete). Direct parameterless initialization by the application is thus precluded. Interpretation: An instance is therefore likely to be created via higher-level mechanisms of persistency file access and passed to the caller.
  • Destruction: The destructor ~ReadAccessor() is declared virtual, marked with override, and defined as noexcept [SWS_PER_00417]. Upon destruction of the object, the underlying read descriptors are released.
  • Concurrency and exception safety: All methods of the class are specified as not thread-safe (e.g., [SWS_PER_00417], [SWS_PER_00419]). Concurrent access by multiple threads to the same instance therefore requires external synchronization. At the same time, all read operations are exception-safe (exception safe) and declared as noexcept; errors are conveyed via the return type ara::core::Result.

Usage Path

The usage of ara::per::ReadAccessor distinguishes between inspective operations (without position change) and consuming read operations (advancing the file pointer):

  • Inspection (peeking): By means of PeekByte() [SWS_PER_00418] or PeekChar() [SWS_PER_00167], the byte or character present at the current position can be queried without changing the read position. Both methods are declared as const.
  • Step-by-step reading: Via GetByte() [SWS_PER_00419] or GetChar() [SWS_PER_00168], respectively, the current element is read and the internal pointer is advanced by one position.
  • Chunked reading (binary mode): With ReadBinary(std::uint64_t n) [SWS_PER_00422], a defined number of bytes is read into a ara::core::Vector<ara::core::Byte>. If the end of the file is reached before reaching n, the vector contains fewer bytes than requested. The parameterless overload ReadBinary() [SWS_PER_00421] reads all remaining bytes up to the end of the file.
  • Text mode and line processing: By means of ReadText(std::uint64_t n) [SWS_PER_00165] or ReadText() [SWS_PER_00420], character strings are read into a ara::core::String. For structured text files, ReadLine(char delimiter = '\n') [SWS_PER_00119] allows line-by-line reading up to the delimiter. The delimiter is not included in the resulting string. If the read position lies within a Unicode code point, the returned text may contain incomplete code points.

Sequence diagram: Typical sequence of line-by-line text processing including inspection and end-of-file detection. Sources: [SWS_PER_00167], [SWS_PER_00119]

Error Scenarios

All read and inspection methods return a ara::core::Result. If an error occurs, rollback semantics take effect: The current read position of the file is not changed in the event of an error (specified, among others, in [SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00421], [SWS_PER_00119]). The following error states from the error domain PerErrc are specified:

  • PerErrc::kEof: Returned if the current read position is already at the end of the file or the file is empty ([SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00418], [SWS_PER_00167], [SWS_PER_00421], [SWS_PER_00422], [SWS_PER_00119], [SWS_PER_00165], [SWS_PER_00420]).
  • PerErrc::kPhysicalStorageFailure: Occurs if physical read access to the storage medium fails ([SWS_PER_00420]).
  • PerErrc::kValidationFailed: Indicates that the integrity or validity of the stored data cannot be guaranteed ([SWS_PER_00419]).
  • PerErrc::kEncryptionFailed: Returned if the decryption of the stored payload fails ([SWS_PER_00419]).
  • PerErrc::kAuthenticationFailed: Occurs if the verification of the Message Authentication Code (MAC) of the stored data fails ([SWS_PER_00419]).

ReadLine function

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ara::core::Result< ara::core::String > ReadLine (char delimiter=’\n’) noexcept;
ReadText function 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.

<h4>Context</h4>
<p>
Within module <code>per</code> (Persistency) of the Adaptive Platform, class <code>ara::per::ReadAccessor</code> serves for sequential reading of persistent file contents. It virtually inherits from <code>FileAccessor</code> and provides read access in both binary mode and text mode. Via this abstraction, applications access stored data without having to manage the physical storage directly. The interface offers granular operations for inspecting individual characters or bytes as well as methods for block-wise or complete reading of contents and lines.
</p>

<h4>Lifecycle</h4>
<p>
The lifecycle of an instance of <code>ara::per::ReadAccessor</code> is subject to strict requirements regarding creation and resource management:
</p>
<ul>
<li><strong>Creation:</strong> According to <a class="spec-record-ref" data-req="SWS_PER_00461" href="../spec/record.html?id=SWS_PER_00461">[SWS_PER_00461]</a>, the default constructor is explicitly deleted (<code>delete</code>). Direct parameterless initialization by the application is thus precluded. Interpretation: An instance is therefore likely to be created via higher-level mechanisms of persistency file access and passed to the caller.</li>
<li><strong>Destruction:</strong> The destructor <code>~ReadAccessor()</code> is declared virtual, marked with <code>override</code>, and defined as <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_PER_00417" href="../spec/record.html?id=SWS_PER_00417">[SWS_PER_00417]</a>. Upon destruction of the object, the underlying read descriptors are released.</li>
<li><strong>Concurrency and exception safety:</strong> All methods of the class are specified as <code>not thread-safe</code> (e.g., <a class="spec-record-ref" data-req="SWS_PER_00417" href="../spec/record.html?id=SWS_PER_00417">[SWS_PER_00417]</a>, <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>). Concurrent access by multiple threads to the same instance therefore requires external synchronization. At the same time, all read operations are exception-safe (<code>exception safe</code>) and declared as <code>noexcept</code>; errors are conveyed via the return type <code>ara::core::Result</code>.</li>
</ul>

<h4>Usage Path</h4>
<p>
The usage of <code>ara::per::ReadAccessor</code> distinguishes between inspective operations (without position change) and consuming read operations (advancing the file pointer):
</p>
<ul>
<li><strong>Inspection (peeking):</strong> By means of <code>PeekByte()</code> <a class="spec-record-ref" data-req="SWS_PER_00418" href="../spec/record.html?id=SWS_PER_00418">[SWS_PER_00418]</a> or <code>PeekChar()</code> <a class="spec-record-ref" data-req="SWS_PER_00167" href="../spec/record.html?id=SWS_PER_00167">[SWS_PER_00167]</a>, the byte or character present at the current position can be queried without changing the read position. Both methods are declared as <code>const</code>.</li>
<li><strong>Step-by-step reading:</strong> Via <code>GetByte()</code> <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a> or <code>GetChar()</code> <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a>, respectively, the current element is read and the internal pointer is advanced by one position.</li>
<li><strong>Chunked reading (binary mode):</strong> With <code>ReadBinary(std::uint64_t n)</code> <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a>, a defined number of bytes is read into a <code>ara::core::Vector&lt;ara::core::Byte&gt;</code>. If the end of the file is reached before reaching <code>n</code>, the vector contains fewer bytes than requested. The parameterless overload <code>ReadBinary()</code> <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a> reads all remaining bytes up to the end of the file.</li>
<li><strong>Text mode and line processing:</strong> By means of <code>ReadText(std::uint64_t n)</code> <a class="spec-record-ref" data-req="SWS_PER_00165" href="../spec/record.html?id=SWS_PER_00165">[SWS_PER_00165]</a> or <code>ReadText()</code> <a class="spec-record-ref" data-req="SWS_PER_00420" href="../spec/record.html?id=SWS_PER_00420">[SWS_PER_00420]</a>, character strings are read into a <code>ara::core::String</code>. For structured text files, <code>ReadLine(char delimiter = '\n')</code> <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a> allows line-by-line reading up to the delimiter. The delimiter is not included in the resulting string. If the read position lies within a Unicode code point, the returned text may contain incomplete code points.</li>
</ul>

<h4>Error Scenarios</h4>
<p>
All read and inspection methods return a <code>ara::core::Result</code>. If an error occurs, rollback semantics take effect: The current read position of the file is not changed in the event of an error (specified, among others, in <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a>, <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>, <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>). The following error states from the error domain <code>PerErrc</code> are specified:
</p>
<ul>
<li><code>PerErrc::kEof</code>: Returned if the current read position is already at the end of the file or the file is empty (<a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a>, <a class="spec-record-ref" data-req="SWS_PER_00418" href="../spec/record.html?id=SWS_PER_00418">[SWS_PER_00418]</a>, <a class="spec-record-ref" data-req="SWS_PER_00167" href="../spec/record.html?id=SWS_PER_00167">[SWS_PER_00167]</a>, <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>, <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a>, <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>, <a class="spec-record-ref" data-req="SWS_PER_00165" href="../spec/record.html?id=SWS_PER_00165">[SWS_PER_00165]</a>, <a class="spec-record-ref" data-req="SWS_PER_00420" href="../spec/record.html?id=SWS_PER_00420">[SWS_PER_00420]</a>).</li>
<li><code>PerErrc::kPhysicalStorageFailure</code>: Occurs if physical read access to the storage medium fails (<a class="spec-record-ref" data-req="SWS_PER_00420" href="../spec/record.html?id=SWS_PER_00420">[SWS_PER_00420]</a>).</li>
<li><code>PerErrc::kValidationFailed</code>: Indicates that the integrity or validity of the stored data cannot be guaranteed (<a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>).</li>
<li><code>PerErrc::kEncryptionFailed</code>: Returned if the decryption of the stored payload fails (<a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>).</li>
<li><code>PerErrc::kAuthenticationFailed</code>: Occurs if the verification of the Message Authentication Code (MAC) of the stored data fails (<a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>).</li>
</ul>
