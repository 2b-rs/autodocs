class ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Enables block-by-block, line-by-line, or character-based reading of persisted file and binary data.

The class ara::per::ReadAccessor provides synchronous methods for sequential and line-based reading of files in binary and text modes [SWS_PER_00421], [SWS_PER_00119]. In addition to consuming reads, it allows pointer-neutral previewing of subsequent bytes or characters. Because instances are not thread-safe, concurrent accesses must be coordinated externally, while a rollback guarantee protects the read pointer position in the event of an error [SWS_PER_00419].

Context and Scope

The class ara::per::ReadAccessor provides an interface for synchronous reading of file contents within persistence management (module per) and derives virtually from FileAccessor. It abstracts read access to persisted data storage and provides both binary and textual access methods. Applications can inspect and retrieve individual bytes or characters as well as read contiguous blocks or complete lines via specialized functions.

Life cycle and concurrency

The default constructor of ReadAccessor is deleted [SWS_PER_00461]; instantiation therefore typically occurs mediated via higher-level opening and access mechanisms of the persistence module. The interface and bound access resources are released via the virtual destructor ~ReadAccessor() [SWS_PER_00417]. Instances of ReadAccessor possess an internal read pointer that manages the current position in the file. All methods of the class are explicitly specified as not thread-safe (not thread-safe) [SWS_PER_00419], which is why concurrent read operations on the same instance must be synchronized externally by callers.

Usage Paths for Binary and Text Data

For binary file operations, the class offers functions for previewable or sequential reading. With PeekByte(), the byte at the current read position can be inspected without modifying the read pointer [SWS_PER_00418]. In contrast, GetByte() reads exactly one byte and advances the position [SWS_PER_00419]. Larger data blocks can be read into a ara::core::Vector<ara::core::Byte> via ReadBinary(n), adjusting the position accordingly; if the end of the file is reached prematurely, the vector contains fewer bytes than requested [SWS_PER_00422]. Using ReadBinary(), all remaining bytes up to the end of the file can be obtained in a single step [SWS_PER_00421].

Sequence diagram: Typical flow of a sequential read access with advance inspection and section-by-section data processing. Sources: [SWS_PER_00418], [SWS_PER_00422], [SWS_PER_00421].

In text mode, PeekChar() provides a character-based preview [SWS_PER_00167], while GetChar() consumes the next character [SWS_PER_00168]. Line-by-line reading is performed via ReadLine(), which reads up to a delimiter (default: '\n', ASCII 0x0a); the delimiter is not included in the resulting string [SWS_PER_00119]. Sections of n characters or the entire remaining content can be read via the overloads of ReadText() [SWS_PER_00165], [SWS_PER_00420]. If the read pointer is located in the middle of a multi-byte character, the resulting character strings may exhibit incomplete Unicode code points [SWS_PER_00119], [SWS_PER_00165].

Error Scenarios and Error Handling

All read operations of ReadAccessor return their values encapsulated in a ara::core::Result and are specified as exception-safe (exception safe) [SWS_PER_00419]. If an error occurs during an access, strict rollback semantics apply: the current position of the read pointer always remains unchanged in case of an error [SWS_PER_00421], [SWS_PER_00422]. Typical documented error conditions include:

  • PerErrc::kPhysicalStorageFailure in the event of errors of the physical storage medium [SWS_PER_00419], [SWS_PER_00420],
  • PerErrc::kEof if the read pointer is at the end of the file or the file is empty [SWS_PER_00419], [SWS_PER_00168],
  • PerErrc::kValidationFailed if the validity of the data cannot be verified [SWS_PER_00418], [SWS_PER_00119],
  • PerErrc::kEncryptionFailed in the event of failed decryption [SWS_PER_00419], [SWS_PER_00422], as well as
  • PerErrc::kAuthenticationFailed if the MAC verification of stored data fails [SWS_PER_00167], [SWS_PER_00421].

ReadLine function

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ara::core::Result< ara::core::String > ReadLine (char delimiter=’\n’) noexcept;
ReadText function 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.
