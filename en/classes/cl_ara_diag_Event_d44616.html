intended use

The final class offers operations for a diagnostic event. It reads status byte, debouncing status, fault detection counter, test complete status and the DTC number asynchronously in a desired format. [SWS_DM_00646] [SWS_DM_00649] [SWS_DM_00653] [SWS_DM_00654] [SWS_DM_00655] [SWS_DM_00656]

Lifecycle & Ownership

The instance is constructed over a port InstanceSpecifier. Copying, moving, and both forms of assignment are prohibited (=delete), so it represents a single unassignable instance. [SWS_DM_00647] [SWS_DM_01681] [SWS_DM_01682] [SWS_DM_01679] [SWS_DM_01680]

Interaction with other classes

SetEventStatusChangedNotifier registers a callback function for every status change; a further call overwrites the previous notifier. The Diagnostic Manager processes event status bits according to UDS DTC status bits and returns the current status of the associated event for GetEventStatus. [SWS_DM_00650] [SWS_DM_01029] [SWS_DM_01349] [SWS_DM_01024] [SWS_DM_00886]

Limitations & Error handling

For GetDTCNumber, the manager returns DiagErrc::kNoSuchDTC if no event-to-UDS-DTC mapping exists; the queries can also report kServiceNotAvailable. Most status queries and the notifier are not thread-safe; GetDTCNumber is thread-safe. [SWS_DM_01269] [SWS_DM_00653] [SWS_DM_00649] [SWS_DM_00654] [SWS_DM_00655] [SWS_DM_00656] [SWS_DM_00650]

Technical context The manager updates event status bits based on test results reported above Monitor::ReportMonitorAction. With kResetTestFailed only bit kTestFailed is reset. When restarting an associated OperationCycle, the manager sets kTestFailedThisOperationCycle to zero and kTestNotCompletedThisOperationCycle to one; Deleting a DTC also resets specified event status bits. [SWS_DM_01025] [SWS_DM_01026] [SWS_DM_01027] [SWS_DM_01028]

The return value of GetTestComplete is true if and only if the FDC is -128 or 127. The API supplies the status information via ara::core::Future. [SWS_DM_00655] [SWS_DM_00649] [SWS_DM_00654] [SWS_DM_00656]

Architectural embedding

The architecture runs Event as a public API interface with access to event status, debouncing status, fault detection counter and associated DTC number. EXP SWArchitecture §9.8.1.1.2 The diagnostics should process event status; The expressly mentioned use case is the evaluation of monitor results and actions derived from them. FO RS Diagnostics [RS_Diag_04151]

Fault-memory relation

Management of event memory entries can be triggered by reported event status or internal information such as debounce and occurrence counters. FO RS Diagnostics [RS_Diag_04105]
