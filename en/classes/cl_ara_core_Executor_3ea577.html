class ara::core::Executor

[SWS_CORE_00008] Upstream: RS_AP_00130

class Executor {...};

Provides an interface for a executing context, which asynchronously invokes Callable ([4] [func.wrap.func]) objects in a guaranteed thread-safe context. The execute(...) method in [SWS_CORE_00024] returns a ara::core::Future object to the caller for further result/error extraction or management of the asynchronous-context; the execute_oneway(...) method in [SWS_CORE_00025] imply fire-and-forget semantics and thus no asynchronous-context (ara::core::Future) is returned.

Context

The class ara::core::Executor provides an interface for an execution context that executes callable objects (callables) asynchronously in a guaranteed thread-safe environment. Within the core module of the AUTOSAR Adaptive Platform, the class abstracts the decoupling of invocation and actual execution, allowing applications to initiate background work without having to directly manage their own thread structures or synchronization primitives.

Essentially three parties are involved in the interaction with ara::core::Executor:

  • Caller: Submits a callable entity (such as a function object, lambda, or function pointer) along with the associated arguments.
  • Execution context (executor instance and background worker): Accepts the task and executes the callable asynchronously as well as thread-safe.
  • Return channel (ara::core::Future): For tasks requiring synchronization, calling execute ([SWS_CORE_00024]) returns a Future object via which the caller can later access the calculation result or occurred errors. For pure fire-and-forget tasks via oneway_execute ([SWS_CORE_00025]), this return channel is completely omitted.

Lifecycle

The lifecycle of an instance of ara::core::Executor is determined by construction, value transfer, and destruction. The specification defines specific properties regarding thread safety and exception safety:

  • Copying: The copy constructor ([SWS_CORE_00009]) and the copy assignment operator ([SWS_CORE_00017]) are declared as thread-safe (thread-safe), but explicitly as not exception safe (not exception safe). An instance may thus be copied concurrently, but callers must take precautions against failing copy operations.
  • Move: The move constructor ([SWS_CORE_00015]) as well as the move assignment operator ([SWS_CORE_00018]) are declared with noexcept and are exception-safe (exception safe). However, they are not thread-safe (not thread-safe), so that moving an executor must take place exclusively without concurrent access.
  • Destruction: The destructor ~Executor() ([SWS_CORE_00019]) is noexcept, exception safe, and thread-safe. It ensures the orderly destruction of the instance even in multithreading scenarios.

Usage Path

For asynchronous task processing, ara::core::Executor offers two different paths:

  1. Asynchronous execution with result monitoring (execute): The caller passes the callable f and its arguments p... to the template method execute ([SWS_CORE_00024]). The function immediately returns an object of type ara::core::Future<std::invoke_result_t<std::decay_t<F>, std::decay_t<P>...>>. The execution of f takes place concurrently in the background. The caller queries the result via the future at the appropriate time. It should be noted that execute itself is declared as not thread-safe (not thread-safe) ([SWS_CORE_00024]); concurrent calls to execute on the same executor instance must therefore be synchronized on the caller side.
  2. One-way execution without return channel (oneway_execute): If the caller requires neither a result nor error monitoring, oneway_execute ([SWS_CORE_00025]) is used. This method has fire-and-forget semantics, returns void, and does not create a future. In contrast to execute, oneway_execute is directly declared as thread-safe (thread-safe) ([SWS_CORE_00025]).

Sequence diagram: Typical flow of asynchronous function dispatch with result query via future. Sources: [SWS_CORE_00024]

Error Scenarios

Error handling differs depending on the chosen execution method and lifecycle operation:

  • No synchronous error codes: Neither execute ([SWS_CORE_00024]) nor oneway_execute ([SWS_CORE_00025]) defines standardized error codes during the call itself; both methods are declared with noexcept.
  • Error forwarding via future for execute: If an error occurs during the asynchronous execution of the callable, it is stored in the ara::core::Future returned by execute ([SWS_CORE_00024]). Upon successful processing, the future contains the computed value, and in the event of an error, an error code (ErrorCode).
  • Error handling for oneway_execute: Since no return channel exists, errors that occur during the asynchronous execution of a callable passed via oneway_execute ([SWS_CORE_00025]) cannot be propagated to the caller. They must be caught within the function object itself.
  • Failing copy operations: Since the copy constructor ([SWS_CORE_00009]) and copy assignment ([SWS_CORE_00017]) are designated as not exception safe, copy operations can fail, whereas move operations ([SWS_CORE_00015], [SWS_CORE_00018]) are guaranteed to be exception safe by noexcept.
