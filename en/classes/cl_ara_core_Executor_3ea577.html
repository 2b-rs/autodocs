class ara::core::Executor

[SWS_CORE_00008] Upstream: RS_AP_00130

class Executor {...};

Provides an interface for a executing context, which asynchronously invokes Callable ([4] [func.wrap.func]) objects in a guaranteed thread-safe context. The execute(...) method in [SWS_CORE_00024] returns a ara::core::Future object to the caller for further result/error extraction or management of the asynchronous-context; the execute_oneway(...) method in [SWS_CORE_00025] imply fire-and-forget semantics and thus no asynchronous-context (ara::core::Future) is returned.

Bibliography SWS Core: [4] ISO/IEC 14882:2014, Information technology – Programming languages – C++ – www.iso.org

intended use

ara::core::Executor provides an execution context that invokes Callable objects asynchronously in a guaranteed thread-safe context. [SWS_CORE_00008]

Interaction with other classes

execute() calls a function with its arguments asynchronously and returns a Future containing either the result or an error. oneway_execute() also starts the function asynchronously, but follows fire-and-forget semantics and does not return Future. [SWS_CORE_00024] [SWS_CORE_00025]

Lifecycle & Ownership

Copy and move construction and copy and move assignment are available; Move operations and destructor are noexcept. [SWS_CORE_00009] [SWS_CORE_00015] [SWS_CORE_00017] [SWS_CORE_00018] [SWS_CORE_00019]

Destruction on outstanding callables

The specification does not specify what happens to callables that are still running or waiting when a Executor is destroyed: [SWS_CORE_00019] describes the destructor without any behavioral commitment (no join, detach or abort), and the functional chapter SWS Core §7.4.1.2 “ara::core::Executor” also makes no statement about the lifespan of the execution context. The specification itself names the only informal description of behavior as a known limitation SWS Core §4.1 “Known limitations”. The behavior is therefore implementation-dependent; It also remains unclear whether a Future obtained from execute() will ever become ready after the executor has been destroyed.

Interpretation: Since the Executor can be copied [SWS_CORE_00009], handle semantics suggests a shared execution context - this is not guaranteed. Portable code keeps the executor alive at least as long as all callables started with it: at execute() complete the delivered Future before destroying it with wait()/GetResult() or check is_ready(); for oneway_execute() and for Future::then(func, executor) continuations, link the executor to the application lifetime.

Usage AI generated

Automatically generated usage note derived from this AUTOSAR R25-11 specification element—not official AUTOSAR text. Evidence: [SWS_…].

The ara::core::Executor::~Executor destructor terminates the lifetime of a Executor object and is called [SWS_CORE_00019] when a Executor instance goes out of scope or is explicitly deleted. It has no parameters and does not provide a return value.

Concurrency & restrictions

The call is specified as thread-safe and exception safe. The behavior towards callables that have not yet been completed at this point is not specified and is therefore implementation dependent - see “Destruction for outstanding callables” above.

Interpretation: Complete outstanding Future results before destruction and do not let the executor die before its callables.
