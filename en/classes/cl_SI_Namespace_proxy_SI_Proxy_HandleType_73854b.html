class <SI-Namespace>::proxy::<SI>Proxy::HandleType

[SWS_CM_00312] Upstream: RS_CM_00102, RS_AP_00114, RS_AP_00122

class HandleType {...};

Handle for a specific AdaptivePlatformServiceInstance. It contains the information that is needed to create a service proxy. HandleType satisfies the [equalitycomparable] and [lessthancomparable] requirements as per [30]. This, together with [SWS_CM_00317] and [SWS_CM_00318], allows storing and managing HandleTypes by the application.

Role in the service

HandleType is the binding-specific but application code encapsulated proof of a service instance found. Service search produces handles; the generated proxy class uses it as input for its creation. EXP ARAComAPI §5.3.3 “Constructor and Handle Concept” and SWS CM §7.5.11 “Service proxy creation” clarify the separation of search and stateful proxy.

Practical treatment

The application does not create the handle itself, but rather preserves it from FindService or the Find handler. GetInstanceId() supplies the instance reference linked to it, for example to compare an instance that is available again. The detailed shape of the handle is deliberately hidden by the network binding. [SWS_CM_11531] and EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers” are the relevant documents.

Sequence: Discovery delivers handles; This creates a usable proxy. The automatic reconnection of an existing proxy is a specified runtime behavior. Sources: SWS CM §7.5.10 “Find service”, SWS CM §7.5.11 “Service proxy creation”.

Read instance reference

GetInstanceId() provides the identifier with which this handle represents the service instance found. Use it for identity comparisons between the handles reported by Discovery and already established proxies, not for interpreting binding internals. EXP ARAComAPI §5.3.3 “Constructor and Handle Concept” explains the encapsulation.

Typical process
  1. Handle from FindService or get handler.
  2. Use GetInstanceId() only as a comparison or diagnostic value.
  3. Give handle to proxy creation and manage proxy lifetime separately.
