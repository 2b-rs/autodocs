Context

The class ara::crypto::cryp::KeyDerivationFunctionCtx defines the interface for cryptographic key derivation functions (Key Derivation Function, KDF) on the AUTOSAR Adaptive Platform. It is part of the module crypto and extends the basic interface CryptoContext with mechanisms by which new symmetric keys can be deterministically generated from existing key material and additional context parameters [SWS_CRYPT_21515].

Within the crypto architecture, the interface interacts with the following entities:

  • Application component: Controls the lifecycle of the context, sets parameters, and initiates the derivation process.
  • Source key or key storage: Provides the cryptographic base material either directly as a volatile key object SymmetricKey [SWS_CRYPT_21525] or via a referenced key slot KeySlot [SWS_CRYPT_50010].
  • Target key: The result of the derivation is an independent symmetric key object (SymmetricKey::Sptr) that is created with dedicated algorithm and usage restrictions [SWS_CRYPT_21515].

Context diagram: Interaction of application, KDF context, source material, and derived target key. Sources: [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50010].

Lifecycle

Instances of KeyDerivationFunctionCtx are referenced and managed via the smart pointer type Sptr (defined as std::shared_ptr<KeyDerivationFunctionCtx>) [SWS_CRYPT_21501]. (Interpretation: Since the class is a pure virtual interface, concrete instantiation is likely typically performed via a factory method of a responsible crypto provider).

After creation, the context is in an incompletely initialized state. Before key derivation is performed, the base key material as well as all parameters required for the algorithm must strictly be provided. If the derivation is called prematurely, the operation aborts with ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_21515].

Regarding concurrency, all methods of the interface are defined as thread-safe and exception-safe (noexcept) [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50010], [SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009]. In case of errors, rollback semantics take effect so that the context always remains in a defined state.

Usage Path

Typical usage is divided into a sequential configuration and execution phase:

  1. Assign source key: The base key is either passed to the context via a direct key object using SetKey(SymmetricKey::Sptr) [SWS_CRYPT_21525] or bound via a managed key slot using SetKey(KeySlot::Sptr) [SWS_CRYPT_50010].
  2. Configure KDF parameters: Depending on the KDF method (e.g., HKDF or PBKDF2), required additional data is provided via the overloaded SetParameter methods:
    • Memory areas (ReadOnlyMemRegion) for binary data such as salts, labels, or context data [SWS_CRYPT_50007],
    • Integer values (std::uint64_t) for counters or iteration counts [SWS_CRYPT_50008],
    • Additional key objects (SymmetricKey::Sptr) if the method requires multi-stage key material [SWS_CRYPT_50009].
  3. Trigger key derivation: The method DeriveKey executes the derivation [SWS_CRYPT_21515]. The target algorithm ID (targetAlgId) and the desired usage flags (allowedUsage) of the new key are passed as parameters.
  4. Check result: Upon successful derivation, the call returns a ara::core::Result with a pointer to the newly instantiated symmetric target key (SymmetricKey::Sptr) [SWS_CRYPT_21515].

Sequence diagram: Typical sequence of key derivation from configuration to key return. Sources: [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50007], [SWS_CRYPT_50008].

Error Scenarios

During configuration and derivation, the context strictly monitors preconditions and usage rights and signals errors via ara::core::Result:

  • Incomplete initialization: ara::crypto::CryptoErrc::kUninitializedContext occurs in DeriveKey if required parameters or the base key are missing [SWS_CRYPT_21515].
  • Rights violations (kUsageViolation):
    • Returned if the provided source key does not have the flag kAllowKeyDerivation [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50009].
    • Occurs during DeriveKey if kAllowPlaintextExport is required for the target key, but the source key does not authorize this via kAllowDerivedPlaintextExport [SWS_CRYPT_21515].
  • Incompatibility (kIncompatibleObject, kIncompatibleArguments):
    • kIncompatibleObject signals that the passed SymmetricKey or KeySlot is not compatible with the KDF context [SWS_CRYPT_21525], [SWS_CRYPT_50010], [SWS_CRYPT_50009].
    • kIncompatibleArguments indicates that the specified allowedUsage flags are incompatible with the selected targetAlgId [SWS_CRYPT_21515].
  • Unsupported values or parameters (kUnsupported, UnknownIdentifier):
    • UnknownIdentifier is triggered if an unknown target algorithm targetAlgId is passed [SWS_CRYPT_21515].
    • kUnsupported reports that a configured parameter name is not supported by the context [SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009], or that the implementation supports exclusively key objects or exclusively key slots [SWS_CRYPT_21525], [SWS_CRYPT_50010].
  • Invalid arguments (kInvalidArgument): Returned if a passed parameter value is syntactically or semantically invalid [SWS_CRYPT_50007], [SWS_CRYPT_50008].
  • Resource and memory errors (kEmptyKeySlot, kBusyResource):
    • kEmptyKeySlot occurs if a configured KeySlot is empty at execution time [SWS_CRYPT_21515].
    • kBusyResource indicates that a required internal crypto resource is busy [SWS_CRYPT_21515].

<h4>Context</h4>
<p>The class <code>ara::crypto::cryp::KeyDerivationFunctionCtx</code> defines the interface for cryptographic key derivation functions (Key Derivation Function, KDF) on the AUTOSAR Adaptive Platform. It is part of the module <code>crypto</code> and extends the basic interface <code>CryptoContext</code> with mechanisms by which new symmetric keys can be deterministically generated from existing key material and additional context parameters <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</p>
<p>Within the crypto architecture, the interface interacts with the following entities:</p>
<ul>
<li><strong>Application component</strong>: Controls the lifecycle of the context, sets parameters, and initiates the derivation process.</li>
<li><strong>Source key or key storage</strong>: Provides the cryptographic base material either directly as a volatile key object <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a> or via a referenced key slot <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>.</li>
<li><strong>Target key</strong>: The result of the derivation is an independent symmetric key object (<code>SymmetricKey::Sptr</code>) that is created with dedicated algorithm and usage restrictions <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>Instances of <code>KeyDerivationFunctionCtx</code> are referenced and managed via the smart pointer type <code>Sptr</code> (defined as <code>std::shared_ptr&lt;KeyDerivationFunctionCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21501" href="../spec/record.html?id=SWS_CRYPT_21501">[SWS_CRYPT_21501]</a>. (Interpretation: Since the class is a pure virtual interface, concrete instantiation is likely typically performed via a factory method of a responsible crypto provider).</p>
<p>After creation, the context is in an incompletely initialized state. Before key derivation is performed, the base key material as well as all parameters required for the algorithm must strictly be provided. If the derivation is called prematurely, the operation aborts with <code>ara::crypto::CryptoErrc::kUninitializedContext</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</p>
<p>Regarding concurrency, all methods of the interface are defined as thread-safe and exception-safe (<code>noexcept</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>. In case of errors, rollback semantics take effect so that the context always remains in a defined state.</p>

<h4>Usage Path</h4>
<p>Typical usage is divided into a sequential configuration and execution phase:</p>
<ol>
<li><strong>Assign source key</strong>: The base key is either passed to the context via a direct key object using <code>SetKey(SymmetricKey::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a> or bound via a managed key slot using <code>SetKey(KeySlot::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>.</li>
<li><strong>Configure KDF parameters</strong>: Depending on the KDF method (e.g., HKDF or PBKDF2), required additional data is provided via the overloaded <code>SetParameter</code> methods:
<ul>
<li>Memory areas (<code>ReadOnlyMemRegion</code>) for binary data such as salts, labels, or context data <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>,</li>
<li>Integer values (<code>std::uint64_t</code>) for counters or iteration counts <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>,</li>
<li>Additional key objects (<code>SymmetricKey::Sptr</code>) if the method requires multi-stage key material <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
</ul>
</li>
<li><strong>Trigger key derivation</strong>: The method <code>DeriveKey</code> executes the derivation <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>. The target algorithm ID (<code>targetAlgId</code>) and the desired usage flags (<code>allowedUsage</code>) of the new key are passed as parameters.</li>
<li><strong>Check result</strong>: Upon successful derivation, the call returns a <code>ara::core::Result</code> with a pointer to the newly instantiated symmetric target key (<code>SymmetricKey::Sptr</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>During configuration and derivation, the context strictly monitors preconditions and usage rights and signals errors via <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Incomplete initialization</strong>: <code>ara::crypto::CryptoErrc::kUninitializedContext</code> occurs in <code>DeriveKey</code> if required parameters or the base key are missing <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
<li><strong>Rights violations (<code>kUsageViolation</code>)</strong>:
<ul>
<li>Returned if the provided source key does not have the flag <code>kAllowKeyDerivation</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
<li>Occurs during <code>DeriveKey</code> if <code>kAllowPlaintextExport</code> is required for the target key, but the source key does not authorize this via <code>kAllowDerivedPlaintextExport</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>
</li>
<li><strong>Incompatibility (<code>kIncompatibleObject</code>, <code>kIncompatibleArguments</code>)</strong>:
<ul>
<li><code>kIncompatibleObject</code> signals that the passed <code>SymmetricKey</code> or <code>KeySlot</code> is not compatible with the KDF context <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
<li><code>kIncompatibleArguments</code> indicates that the specified <code>allowedUsage</code> flags are incompatible with the selected <code>targetAlgId</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>
</li>
