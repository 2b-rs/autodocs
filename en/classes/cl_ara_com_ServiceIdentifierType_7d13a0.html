Serves for the unique identification of services for management, sorting, and logging in Adaptive applications.

The class ara::com::ServiceIdentifierType serves for the unique identification of services in AUTOSAR Adaptive Communication Management [SWS_CM_11510]. It allows applications to manage, copy, and sort service identifiers as well as to output text for logging purposes via standardized C++ concepts and operators SWS CommunicationManagement §8.10.1 “Class: ServiceIdentifierType”. The concrete type form is specified by the software provider, with all provided member functions classified as not exception-safe according to the specification.

Context

The class ara::com::ServiceIdentifierType specifies the unique identifier of a service in Communication Management of the AUTOSAR Adaptive Platform [SWS_CM_11510]. The concrete type form is the responsibility of the respective software vendor of the Communication Management and may be overridden vendor-specifically SWS CommunicationManagement §8.10.1 “Class: ServiceIdentifierType”. At interfaces of concrete services, the class appears, among other things, as a static constant serviceIdentifier SWS CommunicationManagement p. 319. Application software uses this identifier to log, store, and manage instances SWS CommunicationManagement §8.10.1 “Class: ServiceIdentifierType”.

Context diagram: Integration of ServiceIdentifierType between provider implementation, service interface, and application. Sources: [SWS_CM_11510], SWS CommunicationManagement §8.10.1, p. 319

Lifecycle

As an identifier, ara::com::ServiceIdentifierType acts as a value type without its own complex state machine. Creation and value assignment adhere to the C++ concept copyassignable, which is implemented via the assignment operator operator= [SWS_CM_11513]. This allows identifier instances to be copied and passed on internally within the application without issues.

Ownership remains either statically at the interface definition SWS CommunicationManagement p. 319 or as an independent copy within the area of responsibility of the calling application. Fixed lifecycle phases or transitions are not defined. Since all member functions are not exception-safe according to the specification, concurrent writing assignments to the same instance are likely not thread-safe without external synchronization by the application. Question Q-f6569be429992e62 (open)

Usage Path

The typical usage of ara::com::ServiceIdentifierType comprises the following steps:

  • Acquisition and assignment: The application acquires the identifier from the static service interface SWS CommunicationManagement p. 319 and assigns it via copy assignment operator= to a local variable or storage structure [SWS_CM_11513].
  • Comparison and sorting: For storage in sorted or associative containers, class operator== provides equalitycomparable according to [SWS_CM_11511] as well as operator< according to lessthancomparable [SWS_CM_11512]. This allows identifiers to be checked for equality and placed into a strict order.
  • Serialization for diagnostics: For logging and trace purposes, method toString() provides a textual representation in the form of a ara::core::StringView [SWS_CM_11514].

Error Scenarios

The interface defines no special error codes or returns of type ara::core::ErrorCode. All member functions (operator=, operator<, operator==, toString) are explicitly classified as not exception safe in the requirements [SWS_CM_11511] [SWS_CM_11512] [SWS_CM_11513] [SWS_CM_11514].

As a precondition for comparison operations, participating instances must be validly initialized. The ara::core::StringView returned by toString() does not own storage; its validity is therefore likely tied to the lifetime of the underlying memory buffer or instance (interpretation).               The synchronous member function toString of class ara::com::ServiceIdentifierType generates a textual representation of the service identifier as ara::core::StringView ([SWS_CM_11514], SWS CommunicationManagement §8.10.1.1.2.3 “toString”). It is declared via header #include "ara/com/service/service_identifier.h", takes no parameters, and does not modify the state of the object ([SWS_CM_11514]).
              

              Regarding failure safety, the function is expressly classified in the specification as not exception safe ([SWS_CM_11514]). Specific error codes, error return values, or DET/DEM notifications are not specified in the sources; callers must consequently take into account that exceptions may occur during the call.
              

              Because ara::core::StringView is defined as the return type, it presumably references the internal character data of the identifier object. Question Q-54e93f60d3b6a2b4 (open) The validity of the provided view is therefore expected to be tied to the lifetime of the underlying ServiceIdentifierType instance and must not be dereferenced further after its expiration.
              

              In interaction with related interfaces, an analogous method toString exists for instance identification ara::com::InstanceIdentifier ([SWS_CM_11522], SWS CommunicationManagement §8.8.1.1.3.4 “toString”). In contrast to that function, which is specified as noexcept and exception safe, ServiceIdentifierType::toString offers no guarantee of exception freeness ([SWS_CM_11514], [SWS_CM_11522]).
