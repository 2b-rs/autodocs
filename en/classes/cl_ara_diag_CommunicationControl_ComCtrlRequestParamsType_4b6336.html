Serves as a parameter container for the evaluation and processing of UDS 0x28 communication control requests.

The data structure bundles all input parameters of a UDS service request 0x28 for adaptive communication control according to [SWS_DM_00805]. Upon arrival of such a diagnostic message, the platform deserializes the control and communication types as well as the node identification and passes the populated structure to the corresponding service handler. The application software evaluates the contained values to specifically influence the transmission and reception behavior of defined network segments (AUTOSAR_AP_SWS_Diagnostics §8.7.2 “Struct: ComCtrlRequestParamsType”). As a stateless data container, the structure possesses no concurrency synchronization of its own, which is why accesses should remain within the execution context of the handler.

Context

The structure ara::diag::CommunicationControl::ComCtrlRequestParamsType is a central data transfer type within the functional diagnostic interface of AUTOSAR Adaptive [SWS_DM_00805]. It is declared in the header file ara/diag/communication_control.h and serves as a standardized parameter container encapsulating all input parameters of a diagnostic request of the UDS service 0x28 (CommunicationControl) (AUTOSAR_AP_SWS_Diagnostics §8.7.2 “Struct: ComCtrlRequestParamsType”).

In the overall system, the structure acts as an intermediary between AUTOSAR Diagnostic Management and the adaptive application software responsible for vehicle-specific communication control. Incoming diagnostic commands from external testers are deserialized at the platform level and passed to the application via this structure. The structure comprises three public member variables (AUTOSAR_AP_SWS_Diagnostics §8.7.2.1 “Public Member Variables”):

  • controlType ([SWS_DM_01562], AUTOSAR_AP_SWS_Diagnostics §8.7.2.1.2 “controlType”): Defined as std::uint8_t, this field conveys the sub-function extracted from the UDS request to specify the control operation to be executed.
  • communicationType ([SWS_DM_01563], AUTOSAR_AP_SWS_Diagnostics §8.7.2.1.1 “communicationType”): Likewise of type std::uint8_t, this field represents the communication type specified in the UDS request (such as normal or network management communication).
  • nodeIdentificationNumber ([SWS_DM_01564], AUTOSAR_AP_SWS_Diagnostics §8.7.2.1.3 “nodeIdentificationNumber”): Defined as std::uint16_t, this variable identifies the specific target node or subnet to which the control instruction is directed.

  1. Reception of the diagnostic message: An external diagnostic tester sends a UDS 0x28 request to the ECU. The Adaptive Diagnostic Management receives the data packet at transport layer.
  2. Deserialization and instantiation: The diagnostic stack parses the payload, creates an instance of ComCtrlRequestParamsType [SWS_DM_00805], and assigns the transmitted values to the fields controlType [SWS_DM_01562], communicationType [SWS_DM_01563], and nodeIdentificationNumber [SWS_DM_01564].
