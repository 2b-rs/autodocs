intended use

For every service interface element modeled as an event, the proxy creates an event wrapper. After connecting to the service instance, the consumer subscribes to the event; the provider sends data to Communication Management, which notifies subscribers. Samples are then retrieved explicitly through GetNewSamples(). EXP ARAComAPI §4.3 “Event and Trigger based communication” §5.3.5 “Events”

Subscription, cache and reception model

Subscribe(maxSampleCount) also sets the maximum budget of the local sample cache. The call accepts the order asynchronously; The subscription state can be queried or monitored via a state change handler. For cyclic applications, polling with GetNewSamples() is sufficient; reactive applications register a SetReceiveHandler() that prompts for collection when new data arrives. EXP ARAComAPI §5.3.5.1 “Event Subscription and Local Cache” §5.3.5.2 “Monitoring Event Subscription” §5.3.5.5 “Event-Driven vs Polling-Based access”

Sample ownership

The SamplePtr passed to the callback transfer responsibility for a cache slot to the application. As long as a SamplePtr is held, this slot cannot be reused; this limits the number of samples accessible at the same time. EXP ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”
