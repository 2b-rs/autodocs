Calculates cryptographic hash values over continuous data streams or individual memory blocks.

The class ara::crypto::cryp::HashFunctionCtx provides the interface for calculating cryptographic hash values over memory blocks and data streams ([SWS_CRYPT_50060]). Streaming operations require compliance with the processing cycle consisting of initialization using Start(), incremental data feeding via Update(), finalization by Finish(), and subsequent retrieval via GetDigest() ([SWS_CRYPT_21116]). All methods are specified as thread-safe, guarantee rollback semantics, and report sequence or buffer errors deterministically via result objects.

Context

The class ara::crypto::cryp::HashFunctionCtx defines the interface for calculating cryptographic hash values and checksums in the module crypto of the AUTOSAR Adaptive Platform. As a specialization of CryptoContext, it provides methods for stateless one-shot calls as well as for stateful streaming operations. Lifecycle and ownership management are typically handled via the smart pointer type alias Sptr ([SWS_CRYPT_21101]), which is defined as std::shared_ptr<HashFunctionCtx>.

The essential interaction partners include:

  • Calling application: Controls the lifecycle of the calculation and passes input data block by block or as an entire message.
  • Memory areas: Input data, initialization vectors (IV), as well as output and state buffers are transported via ReadOnlyMemRegion and ReadWriteMemRegion.
  • Key objects: Cryptographic keys can be directly included as a data source in the hash calculation via CryptoObject::Sptr ([SWS_CRYPT_50057]).
  • Crypto Provider: Interpretation: instances of HashFunctionCtx are typically created via an associated Crypto Provider; exchanging exported context states strictly requires the same Crypto Provider and the same algorithm ID ([SWS_CRYPT_50065]). Question Q-8365d4bee96bbf67 (open)

Lifecycle

An instance of HashFunctionCtx transitions through several discrete states during streaming processing:

State diagram: State transitions of the hash context during initialization, processing, and completion. Sources: [SWS_CRYPT_50152], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50058], [SWS_CRYPT_21115], [SWS_CRYPT_50064], [SWS_CRYPT_50065]

After creation, the context is in the unstarted state. By calling Start() without an IV ([SWS_CRYPT_50152]) or Start(iv) with an initialization vector ([SWS_CRYPT_50153]), the context transitions into the active processing phase. Calculations already in progress are implicitly discarded by another start call.

In the processing state, input data is accumulated via repeated calls to Update() with raw chunk data ([SWS_CRYPT_21113]) or keys ([SWS_CRYPT_50057]). Via GetIntermediateDigest(), an intermediate result can be calculated without finalizing the context or interrupting the data stream ([SWS_CRYPT_50059]). An ongoing streaming operation can be aborted at any time using Cancel() ([SWS_CRYPT_50058]), causing the context to return to the unstarted state.

Calling Finish() transitions the context into the "completed" state ([SWS_CRYPT_21115]). Only in this state can the resulting hash value be extracted via GetDigest() ([SWS_CRYPT_21116]) or checked directly against an expected value via Compare() ([SWS_CRYPT_50154]).

To suspend and later resume calculations, the required buffer size can be queried using GetContextStateSize() ([SWS_CRYPT_50063]) and the internal state can be saved via ExportContextState() ([SWS_CRYPT_50064]). Resumption takes place via ImportContextState() ([SWS_CRYPT_50065]). All interface methods are declared exception-safe (exception safe) and thread-safe (thread-safe).

Usage Path

The class supports two processing modes: direct one-shot calculation and segmented streaming processing.

One-shot calculation is performed via CalculateHashDigest() ([SWS_CRYPT_50060]). Here, input data, an optional IV, and the destination memory area are passed, and the hash value is calculated in an atomic operation.

For larger amounts of data or continuous data streams, the streaming path is used:

Sequence diagram: Typical flow of streaming calculation via Start, Update, Finish, and GetDigest. Sources: [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116]

  1. Capacity check: Querying the output size via GetDigestSize() ([SWS_CRYPT_50061]) and the maximum block size via GetMaximumChunkSize() ([SWS_CRYPT_50062]).
  2. Initialization: Preparing the context by calling Start() ([SWS_CRYPT_50152]) or Start(iv) ([SWS_CRYPT_50153]).
  3. Data transfer: Successive passing of data blocks via Update(data) ([SWS_CRYPT_21113]) or keys via Update(key) ([SWS_CRYPT_50057]).
  4. Finalization: Terminating the hash value accumulation by Finish() ([SWS_CRYPT_21115]).
  5. Result evaluation: Reading the calculated hash value using GetDigest() ([SWS_CRYPT_21116]) or in-place comparison with a reference value via Compare() ([SWS_CRYPT_50154]).

Error Scenarios

Methods of HashFunctionCtx signal errors via ara::core::Result and guarantee rollback semantics in the event of errors. Typical error causes are:

  • Sequencing violations: If Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) or Cancel() ([SWS_CRYPT_50058]) is called without a prior successful Start() call, CryptoErrc::kProcessingNotStarted is returned. If Finish() ([SWS_CRYPT_21115]) or GetIntermediateDigest() ([SWS_CRYPT_50059]) is called without prior initialization, the context reports CryptoErrc::kInvalidUsageOrder. Retrieving results via GetDigest() ([SWS_CRYPT_21116]) or Compare() ([SWS_CRYPT_50154]) before executing Finish() fails with CryptoErrc::kProcessingNotFinished.
  • Buffer and size issues: If the output buffer is insufficient, CalculateHashDigest() ([SWS_CRYPT_50060]), GetDigest() ([SWS_CRYPT_21116]), GetIntermediateDigest() ([SWS_CRYPT_50059]), and ExportContextState() ([SWS_CRYPT_50064]) return the error CryptoErrc::kInsufficientCapacity. Unsupported input or IV lengths result in CryptoErrc::kInvalidInputSize for CalculateHashDigest(), Start(iv) ([SWS_CRYPT_50153]), and Update().
  • Incompatibility and missing feature support: CryptoErrc::kUnsupported signals that one-shot calls are not supported ([SWS_CRYPT_50060]), the presence of an IV does not match the hash function ([SWS_CRYPT_50152], [SWS_CRYPT_50153]), intermediate results are not provided ([SWS_CRYPT_50059]), context export/import is not supported ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]), or hashing keys is not permitted ([SWS_CRYPT_50057]).
  • Object validation and permissions: During key passing via Update(key), an incompatible key leads to CryptoErrc::kIncompatibleObject and a missing permission for kAllowHashCalculation leads to CryptoErrc::kUsageViolation ([SWS_CRYPT_50057]). Invalid buffer contents in ImportContextState() produce CryptoErrc::kInvalidArgument ([SWS_CRYPT_50065]).
  • Resource constraints: If a required crypto resource is busy, Start() acknowledges the attempt with CryptoErrc::kBusyResource ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).

The CalculateHashDigest method performs a synchronous one-shot calculation of a cryptographic hash value and writes the result into the provided output buffer [SWS_CRYPT_50060]. The input message data to be processed, the destination buffer digest, and optionally an initialization vector iv are passed as parameters. Upon successful execution, the function returns the actual number of written digest bytes via the result object ara::core::Result<std::size_t> [SWS_CRYPT_50060].

Error handling

If the calculation fails, the interface guarantees rollback semantics [SWS_CRYPT_50060]. The following error codes can be contained in the result:

  • ara::crypto::CryptoErrc::kInvalidInputSize: The size of the passed data or of the initialization vector is not supported [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kUnsupported: Single-call calculation is not supported by the context, or the passing of the initialization vector does not match the configuration of the context (IV required but missing, or IV passed although not supported) [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kInsufficientCapacity: The capacity of the output buffer digest is not sufficient for the calculated digest [SWS_CRYPT_50060].

Concurrency and Interaction

The function is declared as exception-safe (exception safe) and thread-safe (thread-safe) [SWS_CRYPT_50060]. To avoid errors regarding impermissible input lengths in advance, the maximum buffer size permitted for a single call of the context can be determined via GetMaximumChunkSize [SWS_CRYPT_50062].
