Context

The interface ara::crypto::cryp::HashFunctionCtx defines the standardized abstraction for cryptographic hash functions within the module crypto of the AUTOSAR Adaptive Platform [SWS_CRYPT_21101]. Its primary responsibility consists in calculating cryptographic checksums and message digests over arbitrary byte streams or structured key objects.

The calling application software primarily acts as an interaction partner, providing input data via ReadOnlyMemRegion and receiving calculated hash values via ReadWriteMemRegion [SWS_CRYPT_50060]. In addition to regular memory areas, the context can interact directly with cryptographic objects to securely include key material of type CryptoObject::Sptr in the digest calculation [SWS_CRYPT_50057]. Furthermore, the context potentially interacts with other context instances of the same algorithm and crypto provider via the import and export of the internal processing state [SWS_CRYPT_50065].

Lifecycle

The lifetime and ownership of an instance are typically managed via the smart pointer type alias ara::crypto::cryp::HashFunctionCtx::Sptr (std::shared_ptr<HashFunctionCtx>) [SWS_CRYPT_21101]. Since HashFunctionCtx is a purely abstract interface, the concrete instance is likely created via a factory method of a crypto provider (interpretation). All member functions are declared as noexcept and specified as exception-safe and thread-safe (among others, [SWS_CRYPT_50060], [SWS_CRYPT_50058]).

The operational flow follows a stateful model with three main phases:

  • Ready / Not started: After creation, the context is in the idle state. In this state, either a single-step hash operation can be executed via CalculateHashDigest() [SWS_CRYPT_50060] or an iterative calculation can be initiated via Start() without an initialization vector (IV) [SWS_CRYPT_50152] or with an IV [SWS_CRYPT_50153], respectively. An import via ImportContextState() transitions the context directly into the state of the imported image [SWS_CRYPT_50065].
  • In processing (streaming): After successful Start(), the context accepts data fragments [SWS_CRYPT_21113] or key objects [SWS_CRYPT_50057] via repeated calls to Update(). In this phase, an intermediate state can be queried at any time via GetIntermediateDigest() without interrupting the data flow [SWS_CRYPT_50059]. With ExportContextState(), the computation state can be serialized [SWS_CRYPT_50064]. A call to Cancel() aborts the operation and resets processing [SWS_CRYPT_50058]; likewise, a renewed call to Start() aborts an ongoing operation [SWS_CRYPT_50152].
  • Finished: The call to Finish() completes the calculation [SWS_CRYPT_21115]. In this state, no further data can be fed via Update(). The final hash value can now be read out via GetDigest() [SWS_CRYPT_21116] or checked directly against a reference using Compare() [SWS_CRYPT_50154]. A renewed Start() transitions the context back into a new calculation phase.

State diagram: Lifecycle and state transitions of an instance of HashFunctionCtx. Sources: [SWS_CRYPT_50152], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116], [SWS_CRYPT_50058], [SWS_CRYPT_50060], [SWS_CRYPT_50065]

Usage Path

The interface supports two usage patterns:

1. Single-step calculation (single-call): If the entire message is already present in memory, CalculateHashDigest() performs the initialization, transformation, and digest generation in a single atomic step [SWS_CRYPT_50060].

2. Step-by-step streaming calculation (multi-call): For streamed data or messages that are larger than the maximum block size GetMaximumChunkSize() [SWS_CRYPT_50062], the call typically occurs in the following individual steps:

  1. Buffer dimensioning: The application determines the output size via GetDigestSize() [SWS_CRYPT_50061] and allocates a suitable buffer.
  2. Starting: Call to Start() [SWS_CRYPT_50152] or Start(iv) [SWS_CRYPT_50153], respectively, to activate the calculation.
  3. Feeding data: Sequential passing of data sections via Update(data) [SWS_CRYPT_21113] or keys via Update(key) [SWS_CRYPT_50057].
  4. Finishing: Call to Finish() to complete the digest calculation [SWS_CRYPT_21115].
  5. Result processing: Either the digest is written into the provided destination buffer using GetDigest() [SWS_CRYPT_21116], or it is compared directly with an expected reference value using Compare() [SWS_CRYPT_50154].

Sequence diagram: Typical sequence of an iterative hash value calculation via Start, Update, Finish, and evaluation. Sources: [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116], [SWS_CRYPT_50154]

Error Scenarios

All methods return a ara::core::Result and implement rollback semantics so that the context remains in a consistent state in case of errors. The defined error codes cover the following problem areas:

  • Sequence errors:
    • ara::crypto::CryptoErrc::kProcessingNotStarted: A call to Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) or Cancel() [SWS_CRYPT_50058] occurs without the calculation having been initiated by Start().
    • ara::crypto::CryptoErrc::kInvalidUsageOrder: Finish() [SWS_CRYPT_21115] or GetIntermediateDigest() [SWS_CRYPT_50059] is called without the hashing process having been started successfully beforehand.
    • ara::crypto::CryptoErrc::kProcessingNotFinished: GetDigest() [SWS_CRYPT_21116] or Compare() [SWS_CRYPT_50154] is called before the calculation has been completed by Finish().
  • Buffer and size issues:
    • ara::crypto::CryptoErrc::kInsufficientCapacity: The provided output buffer is too small for the result in CalculateHashDigest() [SWS_CRYPT_50060], GetDigest() [SWS_CRYPT_21116], GetIntermediateDigest() [SWS_CRYPT_50059], or ExportContextState() [SWS_CRYPT_50064].
    • ara::crypto::CryptoErrc::kInvalidInputSize: The size of the input data or the IV is invalid ([SWS_CRYPT_50060], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50057]).
  • Incompatibility and missing support:
    • ara::crypto::CryptoErrc::kUnsupported: The function or configuration is not supported by the context, e.g., single calls [SWS_CRYPT_50060], IV usage for algorithms without IV or missing IV for functions requiring an IV ([SWS_CRYPT_50060], [SWS_CRYPT_50152], [SWS_CRYPT_50153]), intermediate results [SWS_CRYPT_50059], key hashing [SWS_CRYPT_50057], or state export/import ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]).
    • ara::crypto::CryptoErrc::kIncompatibleObject and ara::crypto::CryptoErrc::kUsageViolation: The key object passed to Update() is incompatible or prohibits usage for hash calculation (missing kAllowHashCalculation) [SWS_CRYPT_50057].
    • ara::crypto::CryptoErrc::kInvalidArgument: The state data passed to ImportContextState() is invalid [SWS_CRYPT_50065].
    • ara::crypto::CryptoErrc::kBusyResource: A required cryptographic hardware or software resource is busy ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).
