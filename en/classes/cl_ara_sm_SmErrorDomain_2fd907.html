Used for defining and resolving error codes and exceptions within State Management.

The class ara::sm::SmErrorDomain represents the domain-specific error domain of State Management and maps functional error codes to readable text messages and C++ exceptions ([SWS_SM_81241]). At runtime, it enables domain identification and the translation of individual error values for logging and diagnostics via thread-safe methods. If a severe error occurs, a typed exception can also be thrown via the interface ([SWS_SM_81250]). If C++ exceptions are disabled in the toolchain, the exception logic is unavailable and errors must instead be processed purely on a value basis.

Context

The class ara::sm::SmErrorDomain defines the specific error domain for the State Management functional cluster on the Adaptive Platform ([SWS_SM_81241], SWS StateManagement §8.1.3 “Class: SmErrorDomain”). As a specialization of the general error domain architecture, it inherits from ara::core::ErrorDomain according to the requirements from [SWS_CORE_90023]. Its central responsibility is to semantically encapsulate State Management error states, provide standardized error identifiers, and guarantee the mapping between numerical error codes, error texts, and exception types.

Primary interaction partners include internal components of State Management that generate errors, as well as higher-level application and platform services that receive errors via ara::core::ErrorCode. Via the public type alias Errc, the class references the domain-specific enumeration SmErrc ([SWS_SM_81245]). The type alias Exception also references the associated exception base class SmException ([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 “Type Alias: Exception”).

Lifecycle

Instances of ara::sm::SmErrorDomain are created via the parameterless default constructor ([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 “Default Constructor”). The constructor is declared as noexcept and has the classification exception safe. In typical system environments, an instance of SmErrorDomain is likely to exist preferably as a long-lived or static object, since error domains are required process-wide in the AUTOSAR Adaptive ecosystem to interpret error codes.

Regarding concurrency, the core functions of the class are specified for concurrent operation: The methods Name() ([SWS_SM_81248]) and Message() ([SWS_SM_81249]) are designated as thread-safe and exception safe. Multiple executing threads can thus query error information in parallel without requiring external synchronization.

Usage Path

The regular usage path comprises identifying the error domain, resolving error codes into readable diagnostic messages, and optionally transforming them into a C++ exception. First, an application or platform component can retrieve the domain name via Name(); this immutably returns the identifier "Sm" ([SWS_SM_81248]).

If an error occurs in State Management, its code is passed via Message(errorCode) ([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 “Message”). The function returns a pointer to the associated string (const char*), providing logging and diagnostic systems with meaningful messages. If the calling subsystem is designed for exception-based error handling, it passes the error object to ThrowAsException() ([SWS_SM_81250]), thereby instantiating and throwing the exception corresponding to the error code.

Sequence diagram: Typical sequence when querying error information and optionally throwing an exception. Sources: [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

Error Scenarios

The error states managed by the domain are based on the enumeration type SmErrc, which is aliased via Errc ([SWS_SM_81245]). Error situations manifest either as return values based on ara::core::ErrorCode or via exceptions of type Exception (SmException, [SWS_SM_81246]).

When calling ThrowAsException(), the method is considered not exception safe by design, as it actively throws the exception associated with the error code ([SWS_SM_81250]). A critical precondition for the availability of this method relates to the toolchain configuration: According to [SWS_CORE_10304], ThrowAsException() does not participate in overload resolution if C++ exceptions are disabled in the compiler toolchain ([SWS_SM_81250]). In system configurations without exception support, error handling must consequently be handled strictly via return codes.

The member function ara::sm::SmErrorDomain::Message serves to synchronously determine the textual error message that is assigned to a specific error code of the State Management error domain [SWS_SM_81249]. It is declared in the header file ara/sm/sm_error_domain.h within the scope of class ara::sm::SmErrorDomain and has the status DRAFT in the specification AUTOSAR_AP_SWS_StateManagement §8.1.3.2.2.1 “Message”.

The interface has the following parameters and return values [SWS_SM_81249]:

  • Parameter: errorCode of type CodeType accepts the numerical error number for which the associated text message is requested.
  • Return value: A pointer of type const char * to the error message assigned to the passed error code.

Strict assurances regarding concurrency and exception handling apply to the execution: The function is specified as thread-safe and exception safe and is declared with the identifier noexcept [SWS_SM_81249]. It can thus be safely called from arbitrary threads without synchronizing locks or try-catch blocks.

Within the error management of AUTOSAR Adaptive, the method overrides the virtual function of the base error domain. Interpretation: Because the return value is defined as const char * without an allocation interface, the pointer is typically likely to refer to static string literals that remain valid across the entire process runtime.

It is declared in the header file ara/sm/sm_error_domain.h and overrides the corresponding base function for error domains (SWS StateManagement §8.1.3.2.2.3 “ThrowAsException”).
