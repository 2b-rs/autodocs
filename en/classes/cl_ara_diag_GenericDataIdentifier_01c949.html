Generic DID pattern

GenericDataIdentifier is the generic application hook for a configured Diagnostic Data Identifier. The DM assigns UDS ReadDataByIdentifier or WriteDataByIdentifier to the appropriate interface via the DEXT/port assignment; the class does not process “all DIDs” without configuration SWS Diagnostics §7.3.6 “Diagnostic Data Management”.

Reading and writing

Read receives the DID, MetaInfo and a CancellationHandler and returns OperationOutput for payload or a NRC [SWS_DM_00636]. Write also receives the request data and completes [SWS_DM_00637] with success or NRC. The DM processes the UDS service and authorization check; the application only validates its DID-specific data format and carries out the business operation.

Concurrency and data longevity

Parallel DID callbacks are only permitted for default sessions, several conversations processed at the same time, the same required port and DataIdentifierConcurrencyType::kConcurrentType [SWS_DM_00941] [SWS_DM_00942] [SWS_DM_00943]. Otherwise, the DM suppresses further calls until [SWS_DM_00944] is completed. Do not copy or save requestData and MetaInfo to the asynchronous afterlife.

Read template names correctly

In the specification, expressions such as <data-identifier-interface-name-x> or <data-identifier-directory-path> describe generated header and type patterns. They intentionally remain visible in this reference as placeholders and are not concrete C++ identifiers.

Read DID

Read is called for ReadDataByIdentifier of an assigned DID and returns a OperationOutput [SWS_DM_00636]. The method returns payload or an NRC; it does not write a UDS frame.

Use context correctly

Check dataIdentifier against the expected configuration, evaluate MetaInfo only during the callback and note the CancellationHandler [SWS_DM_01345] when aborted.
