Enables applications to generically handle UDS read and write requests for diagnostic identifiers.

The class ara::diag::GenericDataIdentifier serves as a generic interface for the asynchronous processing of UDS read and write requests for diagnostic identifiers in AUTOSAR Adaptive [SWS_DM_00636]. After binding to a port and enabling via Offer(), Diagnostic Management forwards requests to the implemented methods [SWS_DM_00638]. As a singular instance, the object can neither be copied nor moved, while the thread safety of request processing is controlled via the concurrency configuration selected during construction.

Context

The class ara::diag::GenericDataIdentifier represents a generic service interface within the functional cluster Diagnostic Management (DM) of the AUTOSAR Adaptive Platform SWS Diagnostics §8.2 “GenericDataIdentifier”. While type-specific interfaces are bound to firmly modeled data types, GenericDataIdentifier serves the flexible processing of diagnostic identifiers (Data Identifiers, DIDs), where the 16-bit identifier is passed dynamically as a parameter.

Diagnostic processing primarily involves three roles:

  • The external diagnostic tester, which directs standardized UDS services such as ReadDataByIdentifier (0x22) or WriteDataByIdentifier (0x2E) to the vehicle.
  • Diagnostic Management (DM), which accepts diagnostic requests, validates them, and forwards them to the corresponding application instance via defined port interfaces, provided it was previously activated via Offer [SWS_DM_00638].
  • The application-specific implementation of GenericDataIdentifier, which encapsulates the actual processing logic by providing the methods Read [SWS_DM_00636] and Write [SWS_DM_00637] and returning the data asynchronously.

Lifecycle

An instance of ara::diag::GenericDataIdentifier is explicitly instantiated via its constructor [SWS_DM_00634]. In doing so, the caller binds the object to an ara::core::InstanceSpecifier referencing an PortPrototype of a modeled DiagnosticDataIdentifierGenericInterface. Via the argument concurrencyType (of type DataIdentifierConcurrencyType), it is specified whether requests are passed concurrently (kConcurrent) or sequentially (kNotConcurrent) to the handler [SWS_DM_00634].

Regarding ownership and lifetime, GenericDataIdentifier is modeled as a singular, non-copyable, and non-movable instance:

  • The copy constructor [SWS_DM_01653] and the assignment operator [SWS_DM_01651] are deleted (=delete).
  • Likewise, the move constructor [SWS_DM_01654] and the move assignment operator [SWS_DM_01652] are deleted.

After instantiation, the object is in the inactive state; Diagnostic Management does not yet forward requests. Forwarding is only activated by calling Offer() [SWS_DM_00638]. To deactivate the forwarding of diagnostic requests again, the application calls StopOffer() [SWS_DM_00639]. The object is destroyed via the virtual destructor [SWS_DM_00635].

In terms of concurrency, the constructor is thread-safe (thread-safe) [SWS_DM_00634]. In contrast, the administrative methods Offer() [SWS_DM_00638] and StopOffer() [SWS_DM_00639] as well as the destructor [SWS_DM_00635] are specified as not thread-safe. The thread safety of the methods Read and Write conditionally depends on the selected concurrencyType [SWS_DM_00636], [SWS_DM_00637].

Usage Path

A typical end-to-end flow for handling diagnostic requests is divided into the following steps:

  1. Initialization: The application instantiates its derived handler class, specifying the InstanceSpecifier and the concurrency configuration [SWS_DM_00634]. Interpretation: In practice, this likely typically occurs during the initialization phase of the application process.
  2. Service provision: The application calls Offer() [SWS_DM_00638]. Diagnostic Management activates the forwarding of incoming DID requests.
  3. Request processing:
    • If a read request is received, the DM calls the method Read(dataIdentifier, metaInfo, cancellationHandler) [SWS_DM_00636]. The application checks the passed 16-bit identifier and asynchronously returns a ara::core::Future<OperationOutput>.
    • If a write request arrives, the DM calls Write(dataIdentifier, requestData, metaInfo, cancellationHandler) [SWS_DM_00637]. The payload data in requestData remains valid until the associated promise is fulfilled or processing is canceled.
  4. Cancellation check: During lengthy operations, the handler can check via cancellationHandler.IsCanceled() whether the conversation was cancelled, or register a notification function via cancellationHandler.SetNotifier [SWS_DM_00636], [SWS_DM_00637].
  5. Service de-registration: Before terminating the handler, the application calls StopOffer() [SWS_DM_00639], whereupon DM stops forwarding.

Sequence diagram: Interaction between external tester, Diagnostic Management, and GenericDataIdentifier during a UDS read request. Sources: [SWS_DM_00638], [SWS_DM_00636]

Error Scenarios

Errors can occur in different phases of the interaction:

  • Configuration and mapping violations: If InstanceSpecifier cannot be resolved in the model or does not reference a PortPrototype, a InstanceSpecifierMappingIntegrityViolation is present [SWS_DM_00634]. If the mapping to a DiagnosticDataPortMapping is missing, a PortInterfaceMappingViolation occurs [SWS_DM_00634]. A missing process mapping generates a ProcessMappingViolation, and an already used InstanceSpecifier leads to a InstanceSpecifierAlreadyInUseViolation [SWS_DM_00634].
  • Multiple offering: If Offer() is called even though the service is already actively offered, the method returns a ara::core::Result with the error code DiagOfferErrc::kAlreadyOffered [SWS_DM_00638].
  • Domain-specific diagnostic errors: If a read or write request cannot be served functionally, the application returns no success status in Future, but rather a standardized UDS NRC (Negative Response Code) via DiagUdsNrcErrc in accordance with ISO 14229-1 [SWS_DM_00636], [SWS_DM_00637].

By this call, the DM is authorized to forward incoming diagnostic requests (request messages) for the respective data identifier to this handler ([SWS_DM_00638]). The function takes no input parameters and synchronously returns a ara::core::Result<void> ([SWS_DM_00638]) that provides information about success or error.

                  use
                  

                  The method Read of class ara::diag::GenericDataIdentifier is called as soon as a diagnostic request for ReadDataByIdentifier (UDS 0x22) is received for the respective data identifier [SWS_DM_00636]. As parameters, the function accepts the numeric identifier dataIdentifier, the context metaInfo, and a cancellationHandler. Via the cancellationHandler, the application can query the cancellation status by means of IsCanceled or register a notification function for canceled conversations via SetNotifier [SWS_DM_00636]. The result is provided asynchronously via a ara::core::Future<OperationOutput>, which returns the payload (OperationOutput) in the case of success [SWS_DM_00636].
                  


                  Error handling
                  

                  In the event of an error, the Future returns a negative UDS return value (NRC) according to ISO 14229-1 via DiagUdsNrcErrc [SWS_DM_00636]. If the interface is not yet or no longer offered via offer(), Diagnostic Management (DM) responds autonomously with NRC 0x94 (ResourceTemporarilyNotAvailable) [SWS_DM_01257]. If the configured limit of Response Pending messages is reached, the server aborts processing and responds with NRC 0x10 (generalReject) [SWS_DM_00369].
                  


                  Concurrency and Interaction
                  

                  The method is declared as noexcept and exception safe [SWS_DM_00636]. Its thread safety is conditional: Whether the implementation must be thread-safe is controlled via the ConcurrencyType passed in the constructor [SWS_DM_00636]. If readWrite is set to kConcurrent, the DM may initiate read and write accesses concurrently; otherwise (kNotConcurrent), the call occurs sequentially [SWS_DM_00939]. In contrast to specific interfaces such as [SWS_DM_00640], GenericDataIdentifier covers generic DID ranges flexibly via the passed ID [SWS_DM_00636].
