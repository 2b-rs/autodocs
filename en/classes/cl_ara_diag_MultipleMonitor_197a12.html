class ara::diag::MultipleMonitor

Class to implement monitor operations on the multiple monitor interfaces.

intended use

ara::diag::MultipleMonitor implements monitor operations for multiple monitor interfaces and allows status reporting for more than one monitor [SWS_DM_01694] [SWS_DM_01695].

Generation & destruction

The construction uses a InstanceSpecifier for a DiagnosticMultipleMonitorInterface [SWS_DM_01695]. The class cannot be copied or moved [SWS_DM_02065] [SWS_DM_02066] [SWS_DM_02063] [SWS_DM_02064].

Interaction with other classes

Before use, each monitor must be initialized exactly once using one of the ConfigureMonitor() variants: with counter-based, time-based, internal or without debouncing [SWS_DM_01702] [SWS_DM_01697] [SWS_DM_01696] [SWS_DM_01973]. According to Offer(), DM forwards requests to the handler; StopOffer() stops forwarding. ReportMonitorAction() reports qualified or unqualified test results as well as debouncing or prestorage actions [SWS_DM_01699] [SWS_DM_01700] [SWS_DM_01698].

Limitations & Error handling

The configuration is not thread-safe and returns DiagErrc::kInvalidArgument if the handle is invalid; a monitor can only be used after initialization [SWS_DM_01702] [SWS_DM_01732]. The thread safety of ReportMonitorAction() depends on the ConcurrencyType; Invalid monitor handles are ignored there [SWS_DM_01698]. A second Offer() reports DiagOfferErrc::kAlreadyOffered [SWS_DM_01699].
