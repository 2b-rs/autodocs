Defines the error domain of Platform Health Management for mapping messages and throwing exceptions.

The class serves as the domain-specific error domain of Platform Health Management and translates numeric error codes into associated text messages [SWS_PHM_01249]. When exception handling is enabled, it allows matching error exceptions to be thrown selectively via ThrowAsException [SWS_PHM_01250]. If C++ exceptions are disabled in the toolchain, this conversion function is not available, and errors must be processed purely value-based [SWS_PHM_01250].

Context

Class ara::phm::PhmErrorDomain represents the specific error domain of Platform Health Management (PHM) within the AUTOSAR Adaptive Platform. It inherits publicly from base infrastructure ara::core::ErrorDomain and is declared as final, which prevents further derivation. Its central task is to encapsulate numeric error codes of the PHM subsystem, embed them in a standardized context, and provide the semantic mapping to error messages as well as error handling types. Via method Name(), the class provides the standardized identifier of the domain [SWS_PHM_01248]. In addition, it defines standardized interface aliases for error handling: Errc serves as a type alias for the underlying enumeration format PhmErrc [SWS_PHM_01245], while Exception references the base type for domain-specific exceptions PhmException [SWS_PHM_01246].

Lifecycle

Instantiation of ara::phm::PhmErrorDomain occurs via the parameterless default constructor PhmErrorDomain() [SWS_PHM_01247]. This constructor is qualified as noexcept and classified according to the specification as exception-safe (exception safe) and thread-safe [SWS_PHM_01247]. In a typical runtime scenario, an instance of the error domain is likely to be available process-wide as a long-lived object (singleton), so that applications and internal PHM components share the same instance. All stateless query functions of the class—in particular Name() and Message()—are declared as const noexcept and fully thread-safe [SWS_PHM_01248], [SWS_PHM_01249]. As a result, error descriptions can be queried from multiple parallel control flows without external synchronization.

Usage Path

If an error occurs during monitoring or management of the system health state, the PHM subsystem generates a corresponding error code, which is typically passed to callers encapsulated as ara::core::ErrorCode referencing PhmErrorDomain. Based on the domain, the receiving application software can verify whether the occurred error originates from health management. For diagnosis and logging, it calls method Message(errorCode), which returns the associated text message for the passed code as const char* [SWS_PHM_01249]. If the application handles failed operations via exception handling, it passes the ara::core::ErrorCode to ThrowAsException(errorCode) in order to throw the associated exception [SWS_PHM_01250].

Sequence diagram: Typical flow of error checking and exception throwing via PhmErrorDomain. Sources: [SWS_PHM_01245], [SWS_PHM_01246], [SWS_PHM_01249], [SWS_PHM_01250]

Error Scenarios

The explicit conversion of an error code into a C++ exception is implemented via the method ThrowAsException(errorCode) [SWS_PHM_01250]. The thrown exception corresponds to type Exception, which maps to PhmException [SWS_PHM_01246]. Because this function throws an exception by design, it is identified in the specification as not exception-safe (not exception safe), but remains thread-safe with respect to invocation [SWS_PHM_01250]. For environments without exception handling, an essential constraint exists: If C++ exceptions are disabled in the compiler, ThrowAsException does not participate in overload resolution [SWS_PHM_01250]. In this mode, callers must handle errors purely value-based via the methods Message() and the return value of the error code [SWS_PHM_01249].

              use
              

              The member function ThrowAsException is a method of the error domain class ara::phm::PhmErrorDomain and is provided via the header file ara/phm/phm_error_domain.h ([SWS_PHM_01250]). Its purpose is to synchronously throw the C++ exception associated with the passed error code ([SWS_PHM_01250]). For this purpose, the function takes a reference to the error object errorCode of type const ara::core::ErrorCode & as an input parameter ([SWS_PHM_01250]). Because control flow is continued via the exception in case of faulty execution, the method has no return value (void) ([SWS_PHM_01250]).
              


              Concurrency and Execution Safety
              

              With regard to behavior during parallel calls, ThrowAsException is declared as thread-safe ([SWS_PHM_01250]). It can thus be safely and concurrently called from multiple threads. Regarding exception safety, however, the interface is explicitly classified as "not exception safe" in the specification ([SWS_PHM_01250]).
              


              Compiler Restrictions and Overload Resolution
              

              An essential boundary condition for use is defined by [SWS_CORE_10304]: If C++ exceptions are disabled in the used compiler toolchain, ThrowAsException does not participate in overload resolution ([SWS_PHM_01250]). For software builds for platforms or configurations without exception support, the function is thus not available to the compiler for overload resolution ([SWS_PHM_01250]).
