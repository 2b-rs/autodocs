Serves to provide application-side extended diagnostic data to adaptive Diagnostic Management.

The class <ExtendedDataRecordElementInterface> serves adaptive applications as an interface for providing extended diagnostic data to Diagnostic Management ([SWS_DM_02152]). Following instantiation and activation via Offer(), the handler implements asynchronous provisioning of the data via the pure virtual method Read() ([SWS_DM_02156]). Because the Diagnostic Manager permanently saves the records in non-volatile memory, unavailable values must mandatorily be padded with a fill pattern. The interface is neither copyable nor movable, and its destructor is not thread-safe.

Context

The interface <ExtendedDataRecordElementInterface> serves in the diagnostic subsystem of the AUTOSAR Adaptive Platform to provide application-specific extended diagnostic data (Extended Data Records) to Diagnostic Management (DM) (AUTOSAR AP SWS Diagnostics §7.2 “DiagnosticExtendedDataRecordInterface”). An Extended Data Record contains diagnostic-related additional data, such as counter readings or environmental information, associated with a failure event. The class acts as an abstract base interface for application-side handler components. Interaction partners include the Diagnostic Manager (DM), which requests and coordinates read operations, the concrete handler implementation within the application, and the non-volatile memory (NVM) in which the DM permanently stores the retrieved data ([SWS_DM_02156]). Interpretation: The invocation of Read() is presumably initiated by internal diagnostic processing in the DM, for example upon the occurrence of a failure event or upon status changes of a diagnostic trouble code.

Context diagram: Interaction of application handler, Diagnostic Management, and non-volatile memory. Sources: [SWS_DM_02152], [SWS_DM_02156], AUTOSAR AP SWS Diagnostics §7.2 “DiagnosticExtendedDataRecordInterface”

Lifecycle

Creation occurs via the parameterized constructor with specification of an ara::core::InstanceSpecifier and the concurrency mode ara::diag::ConcurrencyType ([SWS_DM_02158], AUTOSAR AP SWS Diagnostics §7.2 “DiagnosticExtendedDataRecordInterface”). Construction is thread-safe and exception safe. The parameter concurrencyType determines whether calls to the interface may be processed concurrently (kConcurrent) or sequentially (kNotConcurrent) ([SWS_DM_02158]). Copy and move operations are completely prevented: copy constructor ([SWS_DM_02147]), copy assignment ([SWS_DM_02148]), move constructor ([SWS_DM_02149]), and move assignment ([SWS_DM_02150]) are deleted (=delete). An instance thus possesses a fixed identity and can neither be duplicated nor transferred.

After instantiation, the object is initially in an inactive state. Only by calling Offer() ([SWS_DM_02152]) is the service activated and the DM forwards requests to the handler. Using StopOffer() ([SWS_DM_02153]), this forwarding can be stopped at any time. Destruction occurs via the virtual destructor ~<ExtendedDataRecordElementInterface>() ([SWS_DM_02151]). Although this destructor is exception-safe, it is explicitly not thread-safe ([SWS_DM_02151]). Interpretation: StopOffer() likely has to be called before destroying the handler object to ensure that no further requests arrive while the object is being deallocated.

Usage Path

The regular flow comprises the offering, the asynchronous answering of read requests, and the deactivation of the service:

  • Initialization: The application instantiates the derived class with the appropriate port identifier and concurrency configuration ([SWS_DM_02158]).
  • Service offering: By calling Offer(), the forwarding of requests in the DM is enabled ([SWS_DM_02152]). The method returns a ara::core::Result<void>.
  • Data retrieval: When a read request arrives, the DM calls the pure virtual method Read() ([SWS_DM_02156]). In doing so, the request metadata (metaInfo) and a cancellationHandler are passed.
  • Cancellation handling and return: The handler can check via cancellationHandler.IsCanceled() whether the conversation was cancelled, or register a notification via cancellationHandler.SetNotifier() ([SWS_DM_02156]). The result is delivered asynchronously via a ara::core::Future with a ReadOutput object ([SWS_DM_02156], [SWS_DM_02154]).
  • Persistence: The DM takes over the retrieved data and permanently stores it in non-volatile memory ([SWS_DM_02156]).
  • Service deregistration: Prior to shutdown, the application calls StopOffer() ([SWS_DM_02153]) to terminate forwarding by the DM before the instance is destroyed ([SWS_DM_02151]).

Sequence diagram: Typical flow of data provision and retrieval. Sources: [SWS_DM_02152], [SWS_DM_02153], [SWS_DM_02156], [SWS_DM_02158]

Error Scenarios

When using the interface, several error conditions and preconditions must be observed:

  • Construction errors and model violations: When calling the constructor, modeling errors can occur ([SWS_DM_02158]). These include InstanceSpecifierMappingIntegrityViolation (the identifier cannot be resolved or does not reference a PortPrototype), PortInterfaceMappingViolation (missing referencing by a DiagnosticDataPortMapping), ProcessMappingViolation (no suitable process found in the model), as well as InstanceSpecifierAlreadyInUseViolation (the identifier is already used in the process) ([SWS_DM_02158]).
  • Multiple offering: If Offer() is called when the service is already actively offered, the call fails and returns the error code DiagOfferErrc::kAlreadyOffered ([SWS_DM_02152]).
  • Unavailable data during read requests: Because the DM stores the data in non-volatile memory, a value must mandatory be returned when Read() is called ([SWS_DM_02156]). If data is not available at the time of the query, the handler implementation must fill it with a defined fill pattern such as 0xFF ([SWS_DM_02156]).
  • Application and diagnostic errors: If the data provision fails entirely, the returned ara::core::Future can contain a corresponding diagnostic NRC error code (DiagUdsNrcErrc) or an application-specific error (ApApplicationError) ([SWS_DM_02156]).
  • Destruction hazard: Because the destructor is not thread-safe ([SWS_DM_02151]), destroying the object during concurrent calls or without prior StopOffer() ([SWS_DM_02153]) leads to undefined behavior.

              The function Offer enables the forwarding of diagnostic requests by the Diagnostic Management Daemon (DM) to the corresponding instance of the handler [SWS_DM_02152]. It is called without parameters and synchronously returns an ara::core::Result<void>, declared as noexcept and specified as exception-safe [SWS_DM_02152].
              


              For proper usage and error handling, the following specifications apply:
              

                

              • Return value and errors: In case of success, the result contains an empty value. If the service was already registered for this handler instance previously, the call fails and returns the error code DiagOfferErrc::kAlreadyOffered with rollback semantics [SWS_DM_02152]. Related error domains also define the error code kAlreadyOffered for this state [SWS_DM_00514] [SWS_DM_00560].
                • 

              • Concurrency: In contrast to other diagnostic handlers, which are often designated as not thread-safe (such as in [SWS_DM_00557]), this method is explicitly defined as thread-safe [SWS_DM_02152].
                • 

              • Interplay in the system: As long as an interface has not yet been offered by the application using Offer, the DM reacts depending on the context with defined default or fallback values, such as with the status "Not ready" for DoIP PowerMode queries [SWS_DM_01525] or fallback values for group identifiers [SWS_DM_01527]. In addition, the specification emphasizes that diagnostic offer functions are specific to ara::diag and must not be confused with ara::com::Offer AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 “Monitors”.
                • 

              


              Interpretation: The synchronous feedback behavior of Offer is likely intended to ensure that handler registration is completely finished before subsequent UDS requests are received.

                  Usage and Semantics
                  

                  The pure virtual method Read is called by the Diagnostic Management (DM) to retrieve the data of an ExtendedDataRecordElement from the application ([SWS_DM_02156]). Since the DM permanently saves the retrieved data in non-volatile memory, the method must always supply a value. If data is not available at the time of the call, it must be padded by the implementation with a fill pattern such as 0xFF ([SWS_DM_02156]).
                  

                  Execution is asynchronous and returns a ara::core::Future, which encapsulates the structure ReadOutput in the case of success ([SWS_DM_02154]). The call passes the following parameters ([SWS_DM_02156]):
                  

                    

                  • metaInfo: Transmits meta-information of the underlying diagnostic request.
                    • 

                  • cancellationHandler: Enables querying a cancellation via cancellationHandler.IsCanceled() as well as registering a notification function via cancellationHandler.SetNotifier().
                    • 

                  

                  Error handling
                  

                  In case of an error, the Future provides a negative UDS response code (DiagUdsNrcErrc) or an application-specific error (ApApplicationError) ([SWS_DM_02156], AUTOSAR_AP_SWS_Diagnostics §7.3.2.6.1 “NRCs created by application”). If the required service interface is not yet or no longer provided via offer(), the DM responds with NRC 0x94 (ResourceTemporarilyNotAvailable) ([SWS_DM_01257]). In addition, DiagOfferErrc::kAlreadyOffered reports if the service is already being offered ([SWS_DM_02156]).
                  

                  Concurrency and Interaction
                  

                  The method is specified as exception-safe (exception safe) ([SWS_DM_02156]). Thread safety is conditional and implementation-defined (implementation defined) ([SWS_DM_02156]). This distinguishes Read for extended data records from read operations on regular data elements ([SWS_DM_00596]) or data identifiers ([SWS_DM_00640]), which are explicitly not thread-safe.
