intended use

The <ExtendedDataRecordElementInterface> class is an application interface for an extended data record element. The application implements the purely virtual method Read(); the result is provided as read output in a ara::core::Future. [SWS_DM_02146] [SWS_DM_02156]

Generation & destruction

The constructor takes instance specifiers and ConcurrencyType. The DM can forward requests via Offer(); this forwarding is stopped via StopOffer(). A second offer of the same interface leads to DiagOfferErrc::kAlreadyOffered. [SWS_DM_02158] [SWS_DM_02152] [SWS_DM_02153]

Interaction with other classes

Read() gets MetaInfo and CancellationHandler. The DM saves the read data in a non-volatile manner; Therefore, the implementation must always provide a value and fill unavailable data with a padding pattern, for example 0xFF. [SWS_DM_02156]

Life Cycle & restrictions

Copy and move construction as well as both assignments are deleted; the destructor is virtual and noexcept. Offer and StopOffer are thread-safe, whereas the thread safety of Read() is implementation-defined. function Read [SWS_DM_02156] Upstream: RS_AP_00114, RS_AP_00127, RS_AP_00128, RS_AP_00138

virtual ara::core::Future< <ExtendedDataRecordElement>ReadOutput > Read (const ara::diag::MetaInfo &metaInfo, ara::diag::CancellationHandler cancellationHandler) noexcept=0;

Provision of a Read ExtendedDataRecordElement. The data fetched by this method is stored in non-volatile memory by the DM and therefore always a value needs to be returned. Not available data at the time of the method call shall be filled with a filling pattern, e.g 0xFF by the implementation of this method (DiagnosticExtendedDataRecordInterface in the role provide).

Usage AI generated

Automatically generated usage note derived from this AUTOSAR R25-11 specification element—not official AUTOSAR text. Evidence: [SWS_…].

The virtual method Read provides reading of an ExtendedDataRecordElement (role provide of DiagnosticExtendedDataRecordInterface). Because the data is stored in nonvolatile memory of Diagnostic Management, a value must always be returned; unavailable data must be filled with a padding pattern (for example, 0xFF) [SWS_DM_02156]. metaInfo and an cancellationHandler are passed for cancellation checking or notifier registration.

Concurrency & restrictions

Thread safety is implementation dependent (conditional); the call is exception safe. If it fails, the ara::core::Future returns a DiagUdsNrcErrc or ApApplicationError.
