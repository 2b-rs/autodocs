Enables monitoring active diagnostic channels as well as controlling diagnostic session and security level.

The class ara::diag::Conversation represents a diagnostic communication channel for monitoring activity status, diagnostic session, and security level as well as for resetting to the default session [SWS_DM_00692] [SWS_DM_00701]. Applications obtain instances exclusively as references via static search functions, since custom instantiations as well as copy and move operations are deleted [SWS_DM_02090]. While read status queries can be executed thread-safely, callback registrations and resetting the session require external synchronization.

Context

The class ara::diag::Conversation represents the interface to a communication channel between an external diagnostic tester and the Adaptive Platform SWS Diagnostics §8.2 “Conversation”. It serves as a link between the application and the internal Diagnostic Management (DM) to track and control ongoing diagnostic activities. Through its instances, Adaptive Applications gain insight into the current connection state [SWS_DM_00694], the active diagnostic session [SWS_DM_00696], the security level [SWS_DM_00698], and the identification characteristics of the channel [SWS_DM_00700].

Context diagram: Integration of ara::diag::Conversation between application and Diagnostic Management. Sources: [SWS_DM_00692], [SWS_DM_00782], SWS Diagnostics §8.2 “Conversation”.

Lifecycle

Instances of ara::diag::Conversation are entirely instantiated and managed by the Diagnostic Management daemon. Manual creation, copying, or moving by the application is excluded: both the copy constructor [SWS_DM_02090] and move constructor [SWS_DM_02092] as well as the assignment operators [SWS_DM_02091] [SWS_DM_02093] are deleted (=delete). The lifetime of the referenced objects is therefore likely directly tied to the runtime state of the diagnostic subsystem.

Access to existing instances occurs exclusively via static query functions. With GetAllConversations(), references to all configured connections can be retrieved [SWS_DM_00782], while GetCurrentActiveConversations() provides a list of all currently active channels whose activity status corresponds to kActive [SWS_DM_00783]. In addition, a specific connection can be resolved via GetConversation(metaInfo) based on the metadata of an ongoing diagnostic request [SWS_DM_00692].

Regarding concurrency, all read accesses to status and identifiers are specified as thread-safe [SWS_DM_00694] [SWS_DM_00696] [SWS_DM_00698]. Registering notification callbacks and resetting the session, on the other hand, are considered not thread-safe [SWS_DM_00695] [SWS_DM_00701] and require application-side synchronization.

Usage Path

A typical use case comprises obtaining the connection, registering notification functions, and selectively monitoring or manipulating the session state:

  • Obtain reference: For an incoming diagnostic request, the corresponding instance is obtained using GetConversation(metaInfo) [SWS_DM_00692].
  • Set up state monitoring: The application is notified of changes via the registration methods SetActivityNotifier() [SWS_DM_00695] [SWS_DM_02126], SetDiagnosticSessionNotifier() [SWS_DM_00697] [SWS_DM_02127], and SetSecurityLevelNotifier() [SWS_DM_00699] [SWS_DM_02128]. A repeated call overwrites the previously registered callback.
  • Query status: The instantaneous state can be determined synchronously with GetDiagnosticSession() [SWS_DM_00696] or GetDiagnosticSecurityLevel() [SWS_DM_00698]. Using GetDiagnosticSessionShortName() [SWS_DM_00707] and GetDiagnosticSecurityLevelShortName() [SWS_DM_00708], the enums can be resolved into human-readable short identifiers.
  • Reset session: If logic requires an abort or falling back to the base state, ResetToDefaultSession() resets the channel to the default session [SWS_DM_00701].

Sequence diagram: Typical interaction sequence for registering notifiers, querying state, and resetting the session. Sources: [SWS_DM_00692], [SWS_DM_00697], [SWS_DM_00696], [SWS_DM_00701].

Error Scenarios

Methods of ara::diag::Conversation signal errors via ara::core::Result. If the basic functionality of Diagnostic Management is temporarily unavailable, GetConversation(), GetActivityStatus(), GetDiagnosticSession(), GetDiagnosticSecurityLevel(), and GetConversationIdentifier() fail with error code DiagErrc::kServiceNotAvailable [SWS_DM_00692] [SWS_DM_00694] [SWS_DM_00696] [SWS_DM_00698] [SWS_DM_00700]. Calls follow rollback semantics and remain without side effects.

For the string conversion functions GetDiagnosticSessionShortName() [SWS_DM_00707] and GetDiagnosticSecurityLevelShortName() [SWS_DM_00708], passing an unknown or invalid enumeration value results in error DiagErrc::kInvalidArgument. For the notifier registration methods as well as for ResetToDefaultSession(), no standardized error codes are defined in the specification [SWS_DM_00701].
