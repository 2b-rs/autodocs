Encapsulates symmetric keys asymmetrically via public keys or generates them during the encapsulation process.

The interface ara::crypto::cryp::KeyEncapsulatorPublicCtx enables asymmetric key encapsulation mechanisms (KEM) to wrap symmetric keys for secure exchange or to generate and instantiate them directly during encapsulation ([SWS_CRYPT_50011]). Prior to execution, the context must be initialized via SetKey with a public key or slot and the required output buffer size must be determined ([SWS_CRYPT_21815]). Essential constraints are the required key usage flags such as kAllowKeyWrapping and complete thread safety for all operations.

Context

The interface ara::crypto::cryp::KeyEncapsulatorPublicCtx defines the asymmetric context for Key Encapsulation Mechanisms (KEM) using a public key. Within the cryptography architecture of AUTOSAR Adaptive, the class serves for secure key exchange and key transport. It accepts an asymmetric public key in order to either encapsulate an existing symmetric key ([SWS_CRYPT_21813]) or generate and provide a new symmetric key during encapsulation ([SWS_CRYPT_50011]). The key basis can be bound as a direct key object PublicKey ([SWS_CRYPT_21815]) or via a persisted slot KeySlot ([SWS_CRYPT_50012]).

Context diagram: Integration of KeyEncapsulatorPublicCtx between application, key sources, and target keys. Sources: [SWS_CRYPT_21813], [SWS_CRYPT_21815], [SWS_CRYPT_50011], [SWS_CRYPT_50012]

Lifecycle

Instances of KeyEncapsulatorPublicCtx are managed via the typed smart pointer KeyEncapsulatorPublicCtx::Sptr, which is defined as std::shared_ptr<KeyEncapsulatorPublicCtx> ([SWS_CRYPT_21801]). Actual object creation is likely handled via an underlying provider factory of the platform, as the class represents a pure virtual interface. Question Q-3551020e7b9c0f0c (open)

After creation, the context is in an incompletely initialized state. As long as no public key has been assigned to the context, calls for buffer size calculation ([SWS_CRYPT_50013]) and encapsulation operations ([SWS_CRYPT_21813], [SWS_CRYPT_50011]) fail with the error CryptoErrc::kUninitializedContext. Operational readiness is established by configuration via SetKey with PublicKey::Sptr ([SWS_CRYPT_21815]) or KeySlot::Sptr ([SWS_CRYPT_50012]). When assigning a KeySlot, the contained public key is likely read dynamically only at the actual execution time of the encapsulation. Question Q-ea760070f05941d2 (open) All methods of the context are thread-safe according to the specification and guarantee exception safety ([SWS_CRYPT_21813], [SWS_CRYPT_50011], [SWS_CRYPT_50013], [SWS_CRYPT_21815], [SWS_CRYPT_50012]).

Usage Path

Practical application of the context follows a defined sequence of key binding, buffer dimensioning, and encapsulation execution:

  • Key binding: The application initializes the context via SetKey with either a loaded PublicKey ([SWS_CRYPT_21815]) or a KeySlot ([SWS_CRYPT_50012]).
  • Buffer dimensioning: Before providing the output buffer, the application determines the maximum required output size in bytes via GetRequiredOutputBufferSize(algId) ([SWS_CRYPT_50013]) for the intended symmetric target algorithm and reserves a corresponding ReadWriteMemRegion.
  • Execution of encapsulation: Depending on the intended use, the application selects one of the two encapsulation variants:
    • Provisioning of an existing key: Encapsulate(key, encapsulatedKey) encapsulates the passed SymmetricKey and returns the number of written bytes ([SWS_CRYPT_21813]).
    • Autonomous generation: Encapsulate(algId, allowedUsage, encapsulatedKey) generates a new symmetric key according to the required usage flags and returns a pair consisting of the byte size and the new SymmetricKey::Sptr ([SWS_CRYPT_50011]).

Sequence diagram: Typical call sequence from key assignment and buffer calculation through to key encapsulation. Sources: [SWS_CRYPT_21813], [SWS_CRYPT_21815], [SWS_CRYPT_50011], [SWS_CRYPT_50013]

Error Scenarios

Methods of KeyEncapsulatorPublicCtx report errors via ara::core::Result with values from ara::crypto::CryptoErrc and ensure rollback semantics in case of error. Essential error situations include:

  • CryptoErrc::kUninitializedContext: Occurs when GetRequiredOutputBufferSize ([SWS_CRYPT_50013]) or Encapsulate ([SWS_CRYPT_21813], [SWS_CRYPT_50011]) is called without prior successful configuration using SetKey.
  • CryptoErrc::kUsageViolation: Signals impermissible key usages. This occurs if the encapsulation key lacks the flag kAllowKeyWrapping ([SWS_CRYPT_21815], [SWS_CRYPT_21813], [SWS_CRYPT_50011]) or if the symmetric key to be encapsulated is not enabled for secure export via kAllowSecuredExport ([SWS_CRYPT_21813]).
  • CryptoErrc::kIncompatibleObject: Indicates that a passed key or slot is not compatible with the algorithm of the context ([SWS_CRYPT_21815], [SWS_CRYPT_50012], [SWS_CRYPT_21813]).
  • CryptoErrc::kInsufficientCapacity and CryptoErrc::kInvalidInputSize: Triggered if the passed ReadWriteMemRegion does not have the required buffer capacity or if the input size of the key is not supported ([SWS_CRYPT_21813], [SWS_CRYPT_50011]).
  • CryptoErrc::kEmptyKeySlot and CryptoErrc::kBusyResource: Arise when a KeySlot bound via SetKey is empty at the execution time of the encapsulation or an involved hardware resource is busy ([SWS_CRYPT_21813], [SWS_CRYPT_50011]).
  • CryptoErrc::kUnsupported: Returned if the context implementation exclusively supports key objects instead of slots ([SWS_CRYPT_50012]) or vice versa ([SWS_CRYPT_21815]), or if setting external keys or autonomous key generation is not supported in the context ([SWS_CRYPT_21813], [SWS_CRYPT_50011]).

function Encapsulate [SWS_CRYPT_21813] Upstream: RS_CRYPTO_02102, RS_CRYPTO_02108, RS_CRYPTO_02115

virtual ara::core::Result< std::size_t > Encapsulate (Symmetric Key::Sptr key, ReadWriteMemRegion encapsulatedKey) const noexcept=0;

Encapsulate the provided symmetric key.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 998c7d355307 Provenance

The synchronous method Encapsulate encapsulates a passed symmetric key (key) and writes the result into the output buffer encapsulatedKey [SWS_CRYPT_21813]. Upon successful execution, it returns the byte size of the encapsulated key via ara::core::Result<std::size_t> [SWS_CRYPT_21813].

In case of an error, a corresponding error code with rollback semantics is returned [SWS_CRYPT_21813]. Relevant error causes are:

  • UninitializedContext: The context was not initialized with a public key value [SWS_CRYPT_21813].
  • ara::crypto::CryptoErrc::kUsageViolation: The encapsulation key lacks the usage flag kAllowKeyWrapping or the key to be encapsulated lacks kAllowSecuredExport [SWS_CRYPT_21813].
  • ara::crypto::CryptoErrc::kIncompatibleObject or CryptoErrc::kInvalidInputSize: The key object is incompatible or the key size is not supported by the context [SWS_CRYPT_21813].
  • CryptoErrc::kUnsupported: The context does not support encapsulating provided keys because it generates them itself during encapsulation [SWS_CRYPT_21813].
  • ara::crypto::CryptoErrc::kInsufficientCapacity: The buffer encapsulatedKey is dimensioned too small [SWS_CRYPT_21813].
  • ara::crypto::CryptoErrc::kBusyResource or ara::crypto::CryptoErrc::kEmptyKeySlot: A resource is busy or a configured KeySlot is empty [SWS_CRYPT_21813].

The operation is declared as const, noexcept and specified as thread-safe and exception safe [SWS_CRYPT_21813].

In interaction with the module, this function differs from the alternative overload [SWS_CRYPT_50011], which does not accept an existing key, but dynamically regenerates the symmetric key and returns it together with the encapsulation result [SWS_CRYPT_50011].

      Usage and Semantics
      

      The synchronous method Encapsulate internally generates a new symmetric key and encapsulates it using context [SWS_CRYPT_50011]. The target algorithm algId and the permitted usage flags allowedUsage for the generated key are specified as input parameters [SWS_CRYPT_50011]. The ciphertext of the key is written to the output buffer encapsulatedKey [SWS_CRYPT_50011]. Upon success, the return value encapsulates a pair consisting of the actual byte size of the encapsulated key and a smart pointer to the generated key object (std::pair<std::size_t, SymmetricKey::Sptr>) within a ara::core::Result [SWS_CRYPT_50011].
      

      Error Handling and Safeguarding
      

      In case of an error, the return values predominantly feature rollback semantics [SWS_CRYPT_50011]. Possible error causes include:
      

        

      • UninitializedContext: The context was not previously initialized with a public key [SWS_CRYPT_50011].
        • 

      • CryptoErrc::kUsageViolation: The encapsulation key lacks flag kAllowKeyWrapping or the target key lacks kAllowSecuredExport [SWS_CRYPT_50011].
        • 

      • CryptoErrc::kInsufficientCapacity: Output buffer encapsulatedKey does not provide sufficient capacity [SWS_CRYPT_50011].
        • 

      • CryptoErrc::kUnknownIdentifier or CryptoErrc::kUnsupported: The algId is unknown or generation during encapsulation is not supported [SWS_CRYPT_50011].
        • 

      • CryptoErrc::kEmptyKeySlot or CryptoErrc::kBusyResource: A configured KeySlot is empty or a required resource is busy [SWS_CRYPT_50011].
        • 

      

      Concurrency and Interaction
      

      The operation is specified as const, noexcept, thread-safe, and exception-safe [SWS_CRYPT_50011]. In comparison to overload [SWS_CRYPT_21813], to which an existing key is passed and which only returns its size, this method performs key generation and encapsulation in a joint step [SWS_CRYPT_50011].
