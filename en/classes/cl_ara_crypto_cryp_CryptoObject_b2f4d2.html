Context

The interface ara::crypto::cryp::CryptoObject serves as a common base interface for all cryptographic objects that can be recognized and managed by a CryptoProvider. Through inheritance from ara::crypto::Serializable, it defines the uniform foundation for serializable objects within the cryptography architecture of the AUTOSAR Adaptive Platform, such as key material and associated metadata.

The interface bundles basic identification and control properties for cryptographic resources. The primary interaction partners include:

  • Application: Uses the interface to query algorithm identifiers and usage restrictions as well as to initiate storage in a key slot.
  • CryptoProvider: Provides the execution context for cryptographic objects. According to [SWS_CRYPT_20517], there is a logical binding to the respective provider; incompatibilities occur if target structures are assigned to a different provider.
  • WriteableKeySlot: Represents the underlying storage location to which the object is persistently transferred via Save() ([SWS_CRYPT_20517]).

Context diagram: Interaction partners of CryptoObject during management and persistence. Sources: [SWS_CRYPT_20517]

Lifecycle

The lifecycle and memory management of a CryptoObject follow the specifications for adaptive platform resources:

  • Ownership: For instance management, the class provides the type alias Sptr ([SWS_CRYPT_20501]), which is defined as std::shared_ptr<CryptoObject>. This enables the shared, reference-counted use of objects across component boundaries.
  • Creation: Since it is a purely virtual interface, CryptoObject cannot be instantiated directly; the creation of concrete instances is likely typically done via factory methods of a CryptoProvider.
  • Persistence: A CryptoObject can be kept in a volatile state at runtime or stored permanently in a WriteableKeySlot via the Save() method ([SWS_CRYPT_20517]). Upon successful execution, both the key material and the metadata are written; data previously present in the slot is completely overwritten in the process.
  • Concurrency and safety: All methods (GetAlgId(), GetAllowedUsage(), Save()) are declared as noexcept and specify exception safety (exception safe) as well as thread safety (thread-safe) ([SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]). Parallel calls from multiple threads are therefore permitted without external synchronization.

Usage Path

A typical use case consists of validating the object properties and subsequently storing them in a permanent key slot:

  1. Query algorithm: The application calls GetAlgId() ([SWS_CRYPT_20505]) to obtain the algorithm identifier as ara::crypto::AlgIdString within a ara::core::Result.
  2. Check usage rules: The AllowedUsageFlags are determined using GetAllowedUsage() ([SWS_CRYPT_50092]). Prior to storage, it must be checked whether the permission kAllowPersist is included ([SWS_CRYPT_20517]).
  3. Perform storage: If the object meets all criteria, the Save() method is called, passing a WriteableKeySlot::Sptr ([SWS_CRYPT_20517]).
  4. Check result: The method returns a ara::core::Result<void>, which can be used to evaluate success or specific error codes.

Sequence diagram: Typical validation and storage sequence of a CryptoObject. Sources: [SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]

Error Scenarios

Pure state checking via query methods differs significantly from resource-related write operations:

  • Query methods: No standardized error codes are defined for GetAlgId() ([SWS_CRYPT_20505]) and GetAllowedUsage() ([SWS_CRYPT_50092]).
  • Incompatibility (kIncompatibleObject): If Save() fails because the key does not match the target slot (e.g. incompatible AlgId or origin from a different CryptoProvider), ara::crypto::CryptoErrc::kIncompatibleObject is returned ([SWS_CRYPT_20517]).
  • Usage violation (kUsageViolation): If the permitted usage of the key does not include the right kAllowPersist, persistence is refused with ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_20517]).
  • Busy resource (kBusyResource): If the write operation cannot be performed temporarily, Save() returns the error ara::crypto::CryptoErrc::kBusyResource ([SWS_CRYPT_20517]).
  • Rollback guarantee: For all errors with Save(), rollback semantics apply (rollback_semantics) ([SWS_CRYPT_20517]), so that the original state of the key slot remains unchanged in case of failures.
