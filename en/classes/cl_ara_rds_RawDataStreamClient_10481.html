Context

The C++ class ara::rds::RawDataStreamClient is part of the functional cluster Raw Data Stream (rds) of the AUTOSAR Adaptive Platform in release R25-11. It serves as a client-side endpoint for reading and writing binary raw data streams via an underlying network connection. Via a modeling artifact, identified by ara::core::InstanceSpecifier, the client binds to a specific communication port and encapsulates connection establishment and data transport for application-specific byte streams.

Lifecycle

An instance of ara::rds::RawDataStreamClient cannot be instantiated via regular constructors. The default constructor is not publicly accessible, and both the copy constructor [SWS_RDS_11303] and the copy assignment operator [SWS_RDS_11304] are explicitly deleted (move-only). Creation takes place instead via the static factory method Create [SWS_RDS_10482] by passing the responsible ara::core::InstanceSpecifier. Create is specified as thread-safe and returns an initialized client instance in a ara::core::Result upon success.

Ownership is exclusive: Moving instances is possible via the move constructor [SWS_RDS_11305] and the move assignment operator [SWS_RDS_11306]. Both operations are declared with noexcept, but are not thread-safe.

After creation, the client is in the disconnected state. The active network connection is subsequently established via Connect [SWS_RDS_10484], [SWS_RDS_11307]. The connection is terminated in an orderly manner via Shutdown [SWS_RDS_10485]. The destructor ~RawDataStreamClient [SWS_RDS_10483] ensures that a connection that is still open is automatically shut down upon leaving scope. It is specified as not thread-safe.

Usage Path

The regular procedure for transmitting binary data is divided into creation, connection establishment, payload transmission, and connection teardown:

  1. Instantiation: The application creates the client synchronously using Create(instance) [SWS_RDS_10482].
  2. Connection establishment: Before data is exchanged for the first time, the connection is established. Either the blocking variant Connect() [SWS_RDS_10484] or the time-limited overload Connect(timeout) [SWS_RDS_11307] with a timeout of type std::chrono::milliseconds is available for this purpose.
  3. Sending data: Writing is performed via WriteData(data, maxLength) [SWS_RDS_10487] or WriteData(data, maxLength, timeout) [SWS_RDS_11310], respectively. The payload data is passed as std::unique_ptr<ara::core::Byte[]>, whereby the memory buffer is transferred exclusively to the management of the send operation.
  4. Receiving data: ReadData(maxLength) [SWS_RDS_10486] or the variant with timeout monitoring ReadData(maxLength, timeout) [SWS_RDS_11309] is used to read data. Upon successful reception, a ReadDataResult is returned.
  5. Connection teardown: After data transmission is completed, the application explicitly closes the network connection via Shutdown() [SWS_RDS_10485].

Sequence diagram: Typical call sequence from creation through data transfer to connection teardown. Sources: [SWS_RDS_10482], [SWS_RDS_10484], [SWS_RDS_10487], [SWS_RDS_10486], [SWS_RDS_10485]

Error Scenarios

All functional interfaces of ara::rds::RawDataStreamClient dispense with C++ exceptions and signal success or failure via the return type ara::core::Result with noexcept guarantee:

  • Failed connection establishment: If the client cannot establish a connection to the peer or the specified timeout expires, Connect fails and returns an error code from the error domain RdsErrc in ara::core::Result<void> [SWS_RDS_10484].
  • Errors during write and read operations: If the connection is terminated during transmission or if the timeout of WriteData or ReadData is exceeded, the respective result object contains the corresponding error code [SWS_RDS_10486], [SWS_RDS_10487], [SWS_RDS_11309], [SWS_RDS_11310].
  • Configuration error: If the passed ara::core::InstanceSpecifier does not exist in the system model or is not assigned to a valid communication port, Create already fails and returns a corresponding error cause in the Result object [SWS_RDS_10482].

<h4>Context</h4>
<p>The C++ class <code>ara::rds::RawDataStreamClient</code> is part of the functional cluster <em>Raw Data Stream</em> (<code>rds</code>) of the AUTOSAR Adaptive Platform in release R25-11. It serves as a client-side endpoint for reading and writing binary raw data streams via an underlying network connection. Via a modeling artifact, identified by <code>ara::core::InstanceSpecifier</code>, the client binds to a specific communication port and encapsulates connection establishment and data transport for application-specific byte streams.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::rds::RawDataStreamClient</code> cannot be instantiated via regular constructors. The default constructor is not publicly accessible, and both the copy constructor <a class="spec-record-ref" data-req="SWS_RDS_11303" href="../spec/record.html?id=SWS_RDS_11303">[SWS_RDS_11303]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_RDS_11304" href="../spec/record.html?id=SWS_RDS_11304">[SWS_RDS_11304]</a> are explicitly deleted (<em>move-only</em>). Creation takes place instead via the static factory method <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a> by passing the responsible <code>ara::core::InstanceSpecifier</code>. <code>Create</code> is specified as thread-safe and returns an initialized client instance in a <code>ara::core::Result</code> upon success.</p>
<p>Ownership is exclusive: Moving instances is possible via the move constructor <a class="spec-record-ref" data-req="SWS_RDS_11305" href="../spec/record.html?id=SWS_RDS_11305">[SWS_RDS_11305]</a> and the move assignment operator <a class="spec-record-ref" data-req="SWS_RDS_11306" href="../spec/record.html?id=SWS_RDS_11306">[SWS_RDS_11306]</a>. Both operations are declared with <code>noexcept</code>, but are not thread-safe.</p>
<p>After creation, the client is in the disconnected state. The active network connection is subsequently established via <code>Connect</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11307" href="../spec/record.html?id=SWS_RDS_11307">[SWS_RDS_11307]</a>. The connection is terminated in an orderly manner via <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_10485" href="../spec/record.html?id=SWS_RDS_10485">[SWS_RDS_10485]</a>. The destructor <code>~RawDataStreamClient</code> <a class="spec-record-ref" data-req="SWS_RDS_10483" href="../spec/record.html?id=SWS_RDS_10483">[SWS_RDS_10483]</a> ensures that a connection that is still open is automatically shut down upon leaving scope. It is specified as not thread-safe.</p>

<h4>Usage Path</h4>
<p>The regular procedure for transmitting binary data is divided into creation, connection establishment, payload transmission, and connection teardown:</p>
<ol>
  <li><strong>Instantiation:</strong> The application creates the client synchronously using <code>Create(instance)</code> <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a>.</li>
  <li><strong>Connection establishment:</strong> Before data is exchanged for the first time, the connection is established. Either the blocking variant <code>Connect()</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a> or the time-limited overload <code>Connect(timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11307" href="../spec/record.html?id=SWS_RDS_11307">[SWS_RDS_11307]</a> with a timeout of type <code>std::chrono::milliseconds</code> is available for this purpose.</li>
  <li><strong>Sending data:</strong> Writing is performed via <code>WriteData(data, maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_10487" href="../spec/record.html?id=SWS_RDS_10487">[SWS_RDS_10487]</a> or <code>WriteData(data, maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11310" href="../spec/record.html?id=SWS_RDS_11310">[SWS_RDS_11310]</a>, respectively. The payload data is passed as <code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code>, whereby the memory buffer is transferred exclusively to the management of the send operation.</li>
  <li><strong>Receiving data:</strong> <code>ReadData(maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_10486" href="../spec/record.html?id=SWS_RDS_10486">[SWS_RDS_10486]</a> or the variant with timeout monitoring <code>ReadData(maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11309" href="../spec/record.html?id=SWS_RDS_11309">[SWS_RDS_11309]</a> is used to read data. Upon successful reception, a <code>ReadDataResult</code> is returned.</li>
  <li><strong>Connection teardown:</strong> After data transmission is completed, the application explicitly closes the network connection via <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_10485" href="../spec/record.html?id=SWS_RDS_10485">[SWS_RDS_10485]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>All functional interfaces of <code>ara::rds::RawDataStreamClient</code> dispense with C++ exceptions and signal success or failure via the return type <code>ara::core::Result</code> with <code>noexcept</code> guarantee:</p>
<ul>
  <li><strong>Failed connection establishment:</strong> If the client cannot establish a connection to the peer or the specified timeout expires, <code>Connect</code> fails and returns an error code from the error domain <code>RdsErrc</code> in <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a>.</li>
  <li><strong>Errors during write and read operations:</strong> If the connection is terminated during transmission or if the timeout of <code>WriteData</code> or <code>ReadData</code> is exceeded, the respective result object contains the corresponding error code <a class="spec-record-ref" data-req="SWS_RDS_10486" href="../spec/record.html?id=SWS_RDS_10486">[SWS_RDS_10486]</a>, <a class="spec-record-ref" data-req="SWS_RDS_10487" href="../spec/record.html?id=SWS_RDS_10487">[SWS_RDS_10487]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11309" href="../spec/record.html?id=SWS_RDS_11309">[SWS_RDS_11309]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11310" href="../spec/record.html?id=SWS_RDS_11310">[SWS_RDS_11310]</a>.</li>
  <li><strong>Configuration error:</strong> If the passed <code>ara::core::InstanceSpecifier</code> does not exist in the system model or is not assigned to a valid communication port, <code>Create</code> already fails and returns a corresponding error cause in the <code>Result</code> object <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a>.</li>
</ul>
