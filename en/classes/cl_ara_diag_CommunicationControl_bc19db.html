Context

The ara::diag::CommunicationControl class provides the standardized interface for handling the UDS service 0x28 (CommunicationControl) on the Adaptive AUTOSAR platform. Applications implement this handler to receive requests to control the sending or receiving of messages (for example, disabling or enabling messages on specific communication media) and to execute them in an application-specific manner. Primarily three roles are involved in the interaction: the external diagnostic tester, the platform's generic Diagnostic Management daemon (DM), and the concrete service instance within the diagnostic application.

Context diagram: Components and roles during the processing of CommunicationControl (0x28). Sources: [SWS_DM_00806], [SWS_DM_00808], [SWS_DM_00809]

Lifecycle

Instances of ara::diag::CommunicationControl are semantically bound to a fixed port: copy and move operations are explicitly deleted ([SWS_DM_01675], [SWS_DM_01676], [SWS_DM_01677], [SWS_DM_01678]). Creation is performed via the constructor specifying an ara::core::InstanceSpecifier, which must reference a PortPrototype of a DiagnosticComControlInterface, as well as a ConcurrencyType ([SWS_DM_00806]). The ConcurrencyType (kConcurrent or kNotConcurrent) determines whether the callback method CommCtrlRequest must be able to be executed thread-safely ([SWS_DM_00806], [SWS_DM_00808]).

After instantiation, the object is in the NotOffered state. Only by calling Offer() is the DM authorized to forward incoming 0x28 requests to the object ([SWS_DM_00809]). Offering can be revoked again by means of StopOffer() ([SWS_DM_00810]). Before destruction via the virtual destructor ~CommunicationControl() ([SWS_DM_00807]), the service should be stopped properly.

State diagram: Lifecycle of a CommunicationControl instance. Sources: [SWS_DM_00806], [SWS_DM_00807], [SWS_DM_00809], [SWS_DM_00810]

Usage Path

The regular sequence includes creating the handler, registering with the Diagnostic Management daemon, and asynchronously processing UDS requests:

  1. Instantiation: The application instantiates the class derived from ara::diag::CommunicationControl with the appropriate InstanceSpecifier ([SWS_DM_00806]).
  2. Offer service: Calling Offer() enables the forwarding of requests by the DM ([SWS_DM_00809]).
  3. Request processing: If a 0x28 diagnostic message arrives, the DM calls the overridden method CommCtrlRequest(controlType, metaInfo, cancellationHandler) ([SWS_DM_00808]). The parameter controlType contains all UDS request parameters including the sub-function value. The application returns a ara::core::Future<void>.
  4. Cancellation monitoring: During execution, the application can check via cancellationHandler.IsCanceled() whether the conversation was cancelled, or register a notification via cancellationHandler.SetNotifier ([SWS_DM_00808]).
  5. Completion: As soon as the action is executed, the Promise fulfills the returned Future, whereupon the DM sends a positive UDS response to the tester.
  6. Stop service: Before shutdown, StopOffer() stops the reception of further requests ([SWS_DM_00810]).

Sequence diagram: Typical UDS 0x28 request processing. Sources: [SWS_DM_00808], [SWS_DM_00809], [SWS_DM_00810]

Error Scenarios

Errors can occur both during configuration binding and service registration and during UDS request processing:

  • Constructor violations: If the model resolution fails, specific violations occur ([SWS_DM_00806]):
    • InstanceSpecifierMappingIntegrityViolation: The identifier cannot be resolved or does not reference a PortPrototype.
    • PortInterfaceMappingViolation: The port element typed by DiagnosticComControlInterface is not referenced by a DiagnosticServiceGenericMapping.
    • ProcessMappingViolation: No matching modeled process found for the runtime environment.
    • InstanceSpecifierAlreadyInUseViolation: The InstanceSpecifier is already being used within the process.
  • Offering error: If Offer() is called while the service is already being offered, the call fails and returns the error code DiagOfferErrc::kAlreadyOffered ([SWS_DM_00809]).
  • Diagnostic negative responses (NRC): If the request cannot be handled functionally (for example, invalid sub-function or unfulfilled conditions), the implementation reports a corresponding ISO-14229-1 Negative Response Code (NRC) back to the DM via DiagUdsNrcErrc using the Future ([SWS_DM_00808]).

<h4>Context</h4>
<p>The <code>ara::diag::CommunicationControl</code> class provides the standardized interface for handling the UDS service 0x28 (<em>CommunicationControl</em>) on the Adaptive AUTOSAR platform. Applications implement this handler to receive requests to control the sending or receiving of messages (for example, disabling or enabling messages on specific communication media) and to execute them in an application-specific manner. Primarily three roles are involved in the interaction: the external diagnostic tester, the platform's generic Diagnostic Management daemon (DM), and the concrete service instance within the diagnostic application.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>ara::diag::CommunicationControl</code> are semantically bound to a fixed port: copy and move operations are explicitly deleted (<a class="spec-record-ref" data-req="SWS_DM_01675" href="../spec/record.html?id=SWS_DM_01675">[SWS_DM_01675]</a>, <a class="spec-record-ref" data-req="SWS_DM_01676" href="../spec/record.html?id=SWS_DM_01676">[SWS_DM_01676]</a>, <a class="spec-record-ref" data-req="SWS_DM_01677" href="../spec/record.html?id=SWS_DM_01677">[SWS_DM_01677]</a>, <a class="spec-record-ref" data-req="SWS_DM_01678" href="../spec/record.html?id=SWS_DM_01678">[SWS_DM_01678]</a>). Creation is performed via the constructor specifying an <code>ara::core::InstanceSpecifier</code>, which must reference a <code>PortPrototype</code> of a <code>DiagnosticComControlInterface</code>, as well as a <code>ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00806" href="../spec/record.html?id=SWS_DM_00806">[SWS_DM_00806]</a>). The <code>ConcurrencyType</code> (<code>kConcurrent</code> or <code>kNotConcurrent</code>) determines whether the callback method <code>CommCtrlRequest</code> must be able to be executed thread-safely (<a class="spec-record-ref" data-req="SWS_DM_00806" href="../spec/record.html?id=SWS_DM_00806">[SWS_DM_00806]</a>, <a class="spec-record-ref" data-req="SWS_DM_00808" href="../spec/record.html?id=SWS_DM_00808">[SWS_DM_00808]</a>).</p>
<p>After instantiation, the object is in the <em>NotOffered</em> state. Only by calling <code>Offer()</code> is the DM authorized to forward incoming 0x28 requests to the object (<a class="spec-record-ref" data-req="SWS_DM_00809" href="../spec/record.html?id=SWS_DM_00809">[SWS_DM_00809]</a>). Offering can be revoked again by means of <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00810" href="../spec/record.html?id=SWS_DM_00810">[SWS_DM_00810]</a>). Before destruction via the virtual destructor <code>~CommunicationControl()</code> (<a class="spec-record-ref" data-req="SWS_DM_00807" href="../spec/record.html?id=SWS_DM_00807">[SWS_DM_00807]</a>), the service should be stopped properly.</p>

<h4>Usage Path</h4>
<p>The regular sequence includes creating the handler, registering with the Diagnostic Management daemon, and asynchronously processing UDS requests:</p>
<ol>
<li><strong>Instantiation:</strong> The application instantiates the class derived from <code>ara::diag::CommunicationControl</code> with the appropriate <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_00806" href="../spec/record.html?id=SWS_DM_00806">[SWS_DM_00806]</a>).</li>
<li><strong>Offer service:</strong> Calling <code>Offer()</code> enables the forwarding of requests by the DM (<a class="spec-record-ref" data-req="SWS_DM_00809" href="../spec/record.html?id=SWS_DM_00809">[SWS_DM_00809]</a>).</li>
<li><strong>Request processing:</strong> If a 0x28 diagnostic message arrives, the DM calls the overridden method <code>CommCtrlRequest(controlType, metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00808" href="../spec/record.html?id=SWS_DM_00808">[SWS_DM_00808]</a>). The parameter <code>controlType</code> contains all UDS request parameters including the sub-function value. The application returns a <code>ara::core::Future&lt;void&gt;</code>.</li>
<li><strong>Cancellation monitoring:</strong> During execution, the application can check via <code>cancellationHandler.IsCanceled()</code> whether the conversation was cancelled, or register a notification via <code>cancellationHandler.SetNotifier</code> (<a class="spec-record-ref" data-req="SWS_DM_00808" href="../spec/record.html?id=SWS_DM_00808">[SWS_DM_00808]</a>).</li>
<li><strong>Completion:</strong> As soon as the action is executed, the <code>Promise</code> fulfills the returned <code>Future</code>, whereupon the DM sends a positive UDS response to the tester.</li>
<li><strong>Stop service:</strong> Before shutdown, <code>StopOffer()</code> stops the reception of further requests (<a class="spec-record-ref" data-req="SWS_DM_00810" href="../spec/record.html?id=SWS_DM_00810">[SWS_DM_00810]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors can occur both during configuration binding and service registration and during UDS request processing:</p>
<ul>
<li><strong>Constructor violations:</strong> If the model resolution fails, specific violations occur (<a class="spec-record-ref" data-req="SWS_DM_00806" href="../spec/record.html?id=SWS_DM_00806">[SWS_DM_00806]</a>):
  <ul>
    <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved or does not reference a <code>PortPrototype</code>.</li>
    <li><code>PortInterfaceMappingViolation</code>: The port element typed by <code>DiagnosticComControlInterface</code> is not referenced by a <code>DiagnosticServiceGenericMapping</code>.</li>
    <li><code>ProcessMappingViolation</code>: No matching modeled process found for the runtime environment.</li>
    <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already being used within the process.</li>
  </ul>
</li>
<li><strong>Offering error:</strong> If <code>Offer()</code> is called while the service is already being offered, the call fails and returns the error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00809" href="../spec/record.html?id=SWS_DM_00809">[SWS_DM_00809]</a>).</li>
<li><strong>Diagnostic negative responses (NRC):</strong> If the request cannot be handled functionally (for example, invalid sub-function or unfulfilled conditions), the implementation reports a corresponding ISO-14229-1 Negative Response Code (NRC) back to the DM via <code>DiagUdsNrcErrc</code> using the <code>Future</code> (<a class="spec-record-ref" data-req="SWS_DM_00808" href="../spec/record.html?id=SWS_DM_00808">[SWS_DM_00808]</a>).</li>
</ul>
