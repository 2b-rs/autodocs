Signals the successful completion of a valueless operation or carries an encountered error code.

The class ara::core::Result<void, E> specializes the Result pattern for operations without a return value and represents either successful completion or an error ([SWS_CORE_00811]). After execution, the caller checks the success status via HasValue() ([SWS_CORE_00851]) or operator bool() and, in the event of an error, accesses the contained cause of the error. As a mandatory constraint, the error type E must correspond to type ara::core::ErrorCode, as differing types are rejected as early as compile time.

Context

The template class ara::core::Result<void, E> represents a partial specialization of the Result pattern for operations that do not return a value (void) in the success case, but exclusively signal the success or failure of an action. According to the type definition, the value type value_type is always fixed as void ([SWS_CORE_00811]), while error_type represents the parameterized error type E ([SWS_CORE_00812]). For the type E, the functional requirement applies that any deviation from ara::core::ErrorCode must be rejected by the implementation as a compile error.

In the AUTOSAR Adaptive Platform, ara::core::Result<void, E> functions as the standardized return type for fallible procedures and control commands between calling components and executing interfaces. Instead of classic C++ exception handling, the class provides resource-efficient, explicit error propagation that enables both direct state inspection and functional forwarding along the call path.

Lifecycle

An instance of ara::core::Result<void, E> is in exactly one of two discrete states throughout its entire lifetime: the value state (success) or the error state. Initialization with a void value takes place via the default constructor Result() ([SWS_CORE_00821]) or the static factory method FromValue() ([SWS_CORE_00831]). For creation in the error state, explicit constructors for lvalues and rvalues of the error type E are available ([SWS_CORE_00823], [SWS_CORE_00824]). In addition, the factory functions FromError() enable construction from error lvalues ([SWS_CORE_00834]), rvalues ([SWS_CORE_00835]), or via direct in-place construction from parameter packs ([SWS_CORE_00836]).

Already existing instances can subsequently be transitioned into the value state via EmplaceValue() ([SWS_CORE_00843]) or directly populated with a new error via EmplaceError() ([SWS_CORE_00844]). Copy and move constructors ([SWS_CORE_00825], [SWS_CORE_00826]) as well as corresponding assignment operators ([SWS_CORE_00841], [SWS_CORE_00842]) transfer the state between instances; Swap() swaps the contents of two objects ([SWS_CORE_00845]).

The destructor ~Result() terminates the lifecycle ([SWS_CORE_00827]) and is trivial if std::is_trivially_destructible<E>::value holds. With regard to concurrency, pure read operations are thread-safe, whereas state-modifying operations such as EmplaceValue(), EmplaceError(), assignments, or Swap() are not thread-safe.

Usage Path

The regular flow begins with receiving a ara::core::Result<void, E> instance from a function call. The caller evaluates the result via HasValue() ([SWS_CORE_00851]) or the conversion operator bool() ([SWS_CORE_00852]). Upon successful execution, a subsequent operation can be chained functionally via Bind() ([SWS_CORE_00870]): Bind() executes the passed callable only if the instance contains a value, and returns its transformed result. If an error is present instead, the called function is bypassed and the error content is adopted into the new result.

For uniformity in generic code, the specialization provides interfaces that formally match the general Result class: Value() ([SWS_CORE_00855]), operator*() ([SWS_CORE_00853]), and ValueOr() ([SWS_CORE_00861]) do not return a value and act as no-op methods. Analogously, Resolve() ([SWS_CORE_00867]) executes a passed callable only if an error is present, and remains inactive in the success case.

Error Scenarios

If the instance is in the error state, the contained error can be queried as a reference via the overloads of Error() ([SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876]). In this case, a strict precondition applies: calling Error() on an instance that contains no error constitutes a ResultWithNoErrorViolation. Conversely, calling Value() ([SWS_CORE_00855]) or operator*() ([SWS_CORE_00853]) on an instance in the error state triggers a ResultWithNoValueViolation.

To avoid precondition violations, alternative query methods are available: Err() returns the error wrapped in an ara::core::Optional<E>, which remains empty in the success case ([SWS_CORE_00868], [SWS_CORE_00869]). With ErrorOr(), a default error can be specified that is returned if no error is contained ([SWS_CORE_00863], [SWS_CORE_00864]). For checks against specific error values, CheckError() compares the internal error with a comparison value ([SWS_CORE_00865]).

If exception-based error handling is preferred, ValueOrThrow() ([SWS_CORE_00866]) throws the exception associated with the error in the error case; when a value is present, the call returns normally. If C++ exceptions are disabled in the toolchain, ValueOrThrow() does not participate in overload resolution ([SWS_CORE_00866]).
