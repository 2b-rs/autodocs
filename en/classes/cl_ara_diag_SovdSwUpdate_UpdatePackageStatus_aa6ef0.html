In the context of Service-Oriented Vehicle Diagnostics (SOVD), it serves as an information carrier for mapping the state and progress of a software update package.

<h4>Usage Path</h4>
<p>The regular procedure for monitoring an update process is divided into the following steps:</p>
<ol>
<li><strong>Call status query:</strong> The client calls <code>ara::diag::SovdSwUpdate::GetUpdatePackageStatus</code> <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>.</li>
<li><strong>Aggregate state data:</strong> The instance of <code>SovdSwUpdate</code> queries the internal package progress and populates an instance of <code>UpdatePackageStatus</code> <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a>.</li>
<li><strong>Evaluate macro state:</strong> The caller checks the phase via <code>phase</code> <a class="spec-record-ref" data-req="SWS_DM_01903" href="../spec/record.html?id=SWS_DM_01903">[SWS_DM_01903]</a> and the status via <code>status</code> <a class="spec-record-ref" data-req="SWS_DM_01904" href="../spec/record.html?id=SWS_DM_01904">[SWS_DM_01904]</a> to classify the overall progress.</li>
<li><strong>Process detailed information:</strong> If available, the percentage values from <code>progress</code> <a class="spec-record-ref" data-req="SWS_DM_01905" href="../spec/record.html?id=SWS_DM_01905">[SWS_DM_01905]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=761">AUTOSAR_AP_SWS_Diagnostics §8.58.5.1.3 “progress”</a>) and <code>subprogress</code> <a class="spec-record-ref" data-req="SWS_DM_01906" href="../spec/record.html?id=SWS_DM_01906">[SWS_DM_01906]</a> as well as descriptions via <code>step</code> <a class="spec-record-ref" data-req="SWS_DM_01907" href="../spec/record.html?id=SWS_DM_01907">[SWS_DM_01907]</a> and <code>step_translation_id</code> <a class="spec-record-ref" data-req="SWS_DM_01908" href="../spec/record.html?id=SWS_DM_01908">[SWS_DM_01908]</a> are read.</li>
<li><strong>Cyclic repetition:</strong> If the update is still in progress, the client repeats the query at defined intervals until completion.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When errors occur during package processing, the struct provides specific diagnostic fields:</p>
<ul>
<li><strong>Error signaling via <code>error</code>:</strong> The member <code>error</code> is declared as <code>ara::core::Optional&lt;ara::diag::DiagSovdErrc&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_01909" href="../spec/record.html?id=SWS_DM_01909">[SWS_DM_01909]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=760">AUTOSAR_AP_SWS_Diagnostics §8.58.5.1.1 “error”</a>). It specifies the exact error code if the update status is failed (“Specifies the error if status is failed” <a class="spec-record-ref" data-req="SWS_DM_01909" href="../spec/record.html?id=SWS_DM_01909">[SWS_DM_01909]</a>). In case of successful or running processing, the optional field remains unset (<code>ara::core::nullopt</code>).</li>
<li><strong>Missing progress values:</strong> The field <code>progress</code> <a class="spec-record-ref" data-req="SWS_DM_01905" href="../spec/record.html?id=SWS_DM_01905">[SWS_DM_01905]</a> is also optional (<code>ara::core::Optional&lt;std::uint8_t&gt;</code>). During steps whose duration or extent is not quantifiable, this field presumably remains unset. A caller must therefore always check whether <code>progress.has_value()</code> is true before reading.</li>
<li><strong>Reaction to error states:</strong> If <code>status</code> <a class="spec-record-ref" data-req="SWS_DM_01904" href="../spec/record.html?id=SWS_DM_01904">[SWS_DM_01904]</a> signals an abort, the caller is likely to evaluate primarily <code>error</code>, since progress information is no longer relevant in error states.</li>
</ul>
