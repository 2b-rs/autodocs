Provides an interface for authenticated symmetric encryption and decryption with integrity protection.

The interface ara::crypto::cryp::AuthCipherCtx serves for authenticated encryption and decryption of data while preserving confidentiality and integrity [SWS_CRYPT_23911]. After configuring the key, processing takes place either as an atomic single call or as a streamed sequence of initialization, optional authentication data, payload updates, and finalization. As a critical security precondition, decryption fails if the authentication tag is invalid, meaning decrypted payload data may only be processed after successful validation [SWS_CRYPT_50075].

Context

The interface ara::crypto::cryp::AuthCipherCtx defines the standardized application programming interface for authenticated cipher operations (Authenticated Encryption with Associated Data, AEAD) within the AUTOSAR Adaptive Platform. It combines confidentiality with integrity protection by always generating or validating a cryptographic authentication tag in addition to the actual encryption or decryption of payload data. Calling applications and key objects act as central interaction partners: Prior to use, a context is either bound to a concrete instance of SymmetricKey [SWS_CRYPT_23911] or configured with a persisted or provided KeySlot [SWS_CRYPT_50072]. In addition to step-by-step streaming processing, the class also supports self-contained single calls for processing complete messages in one step [SWS_CRYPT_50078].

Lifecycle

In the application domain, contexts are managed via the shared pointer type ara::crypto::cryp::AuthCipherCtx::Sptr [SWS_CRYPT_20101]. (Interpretation: Object creation typically occurs via a higher-level provider factory, as AuthCipherCtx is specified as a pure interface). All member functions are declared as exception-safe (exception safe) and thread-safe (thread-safe) [SWS_CRYPT_23911], [SWS_CRYPT_24715]. The functional lifecycle passes through clearly defined states:

  • Uninitialized: Immediately after instantiation. Calls for data processing are rejected, as no key has been assigned yet [SWS_CRYPT_50081].
  • Key configured: Through a successful call to SetKey with a SymmetricKey [SWS_CRYPT_23911] or a KeySlot [SWS_CRYPT_50072], the context transitions to the ready state. From this state, single-shot operations can be executed directly.
  • Streaming active: Entered by calling Start with specification of the transformation direction with initialization vector (IV) [SWS_CRYPT_24715] or without explicit IV [SWS_CRYPT_50073].
  • Completion / reset: An ongoing streaming operation is completed regularly by Finish [SWS_CRYPT_50075] or FinishEncrypt [SWS_CRYPT_50076], or aborted prematurely via Cancel [SWS_CRYPT_50077]. Afterward, the context is ready for new processing sequences again.

State diagram: State phases of the context from key binding through streaming processing to completion. Sources: [SWS_CRYPT_23911], [SWS_CRYPT_50072], [SWS_CRYPT_24715], [SWS_CRYPT_50075], [SWS_CRYPT_50077].

Usage Path

For continuous data stream processing, the interface requires an ordered sequence of calls:

  1. Configuration: Assignment of the key via SetKey [SWS_CRYPT_23911] or SetKey with KeySlot [SWS_CRYPT_50072].
  2. Parameter query: Optional retrieval of limits and buffer sizes via GetMinimumChunkSize [SWS_CRYPT_50162], GetMaximumChunkSize [SWS_CRYPT_50082], GetMinimumInputIvSize [SWS_CRYPT_50163], GetMaximumInputIvSize [SWS_CRYPT_50164], GetTagSize [SWS_CRYPT_50161], and GetRequiredOutputBufferSize [SWS_CRYPT_50081].
  3. Operation start: Calling Start specifying the direction (encryption or decryption) and providing the IV [SWS_CRYPT_24715] or requesting a context-owned IV [SWS_CRYPT_50073].
  4. Associated data (AAD): If additional plaintext data is to be included in the integrity calculation, it is passed via UpdateAuthenticatedData [SWS_CRYPT_20313]. The maximum allowed AAD size can be queried via GetMaxAssociatedDataSize [SWS_CRYPT_20103]. Important: AAD blocks must strictly be transmitted before the actual payload.
  5. Payload processing: Stepwise passing of data blocks via UpdateConfidentialData [SWS_CRYPT_50074]. During decryption, the plaintext is returned before its authenticity is established; the application must only use this data after successful finalization.
  6. Finalization: Terminating the operation using Finish [SWS_CRYPT_50075] or FinishEncrypt [SWS_CRYPT_50076], whereby the final block is processed and the authentication tag is calculated or verified.

Single-call alternatives exist for compact payloads: ProcessSingleCall processes data without passing an IV [SWS_CRYPT_50078], ProcessSingleCallWithInputIv accepts an external IV [SWS_CRYPT_50079], and EncryptSingleCallWithOutputIv returns an IV generated by the context to the caller [SWS_CRYPT_50080].

Sequence diagram: Call sequence of a streamed authenticated encryption. Sources: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Error Scenarios

Methods of AuthCipherCtx return results via ara::core::Result and have rollback semantics in case of error. Relevant error codes from ara::crypto::CryptoErrc are:

  • kUninitializedContext: Occurs when calling Start [SWS_CRYPT_24715], ProcessSingleCall [SWS_CRYPT_50078], or buffer calculations [SWS_CRYPT_50081] if no key has been configured via SetKey yet.
  • kProcessingNotStarted: Is reported when UpdateAuthenticatedData [SWS_CRYPT_20313], UpdateConfidentialData [SWS_CRYPT_50074], Finish [SWS_CRYPT_50075], or Cancel [SWS_CRYPT_50077] are called without preceding Start.
  • kInvalidUsageOrder: Signals an incorrect call sequence when UpdateAuthenticatedData is called after payload data has already been processed via UpdateConfidentialData [SWS_CRYPT_20313].
  • kAuthTagNotValid: Indicates during decryption in Finish [SWS_CRYPT_50075] or single-shot methods [SWS_CRYPT_50078] that the calculated tag does not match the passed tag and the authenticity verification has failed.
  • kUsageViolation: Occurs when the usage flags of the key do not match the requested operation (e.g., missing kAllowDataEncrypt or kAllowDataDecrypt) [SWS_CRYPT_23911], [SWS_CRYPT_50078].
  • kInsufficientCapacity / kInvalidInputSize: Indicate insufficiently sized output buffers or invalid input, IV, or tag lengths [SWS_CRYPT_24715], [SWS_CRYPT_50074], [SWS_CRYPT_50075].
  • kEmptyKeySlot / kBusyResource: Concern error conditions when using configured key slots [SWS_CRYPT_24715], [SWS_CRYPT_50078].

use

The method Cancel() of interface ara::crypto::cryp::AuthCipherCtx aborts an active streaming operation that was previously initiated via Start() and has not yet been completed [SWS_CRYPT_50077]. The function is provided via the header ara/crypto/cryp/auth_cipher_ctx.h and operates synchronously without parameters [SWS_CRYPT_50077]. It returns a ara::core::Result<void> that is empty in case of success.

Error Handling and Boundary Conditions

An abort requires that data processing was actually started beforehand by Start(). If the streaming operation was not started, the call fails and returns the error code ara::crypto::CryptoErrc::kProcessingNotStarted with rollback semantics [SWS_CRYPT_50077].

Concurrency

The operation is declared as noexcept and, according to the specification, classified as both thread-safe and exception safe [SWS_CRYPT_50077].

Interaction

The abort pattern realized by Cancel() is standardized in module crypt. An identical interface semantics and the same error code ara::crypto::CryptoErrc::kProcessingNotStarted are defined for corresponding streaming contexts:

          Usage and Semantics
          
  
          The method Finish synchronously completes encryption or decryption within a ara::crypto::cryp::AuthCipherCtx and calculates or verifies the authentication tag without returning an initialization vector (IV) [SWS_CRYPT_50075]. The caller passes the remaining data via the buffer in as well as the destination buffer out. In the case of encryption, the calculated tag is output via the buffer tag, whereas in the case of decryption, the tag to be verified is passed [SWS_CRYPT_50075]. The return value ara::core::Result<std::size_t> specifies the number of bytes actually written to out, which may be smaller than the capacity of the output buffer [SWS_CRYPT_50075].
          

  
          Sequence and Interaction
          
  
          Prior to the call, data processing must mandatorily have been initiated by Start() [SWS_CRYPT_50075]. If data blocks were previously processed using UpdateConfidentialData, an application may use the resulting plaintext during decryption only after successful authentication by Finish [SWS_CRYPT_50074]. The maximum required buffer size for out can be determined in advance via GetRequiredOutputBufferSize by specifying isFinal = true [SWS_CRYPT_50081].
          

  
          Error Handling and Concurrency
          
  
          The method is specified as thread-safe and exception-safe [SWS_CRYPT_50075]. Errors are reported via ara::core::Result with rollback semantics [SWS_CRYPT_50075]:
