class ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

intended use

ara::core::Result<T,E> encapsulates either a value of type T or an error of type E for synchronous calls; E must be ara::core::ErrorCode. The type therefore supports exception-free error handling. [SWS_CORE_00701] [SWS_CORE_10600]

Creation & lifecycle

A result can be generated from value or error as well as via FromValue() and FromError(). Copy and move operations are available and require noexcept; the triviality of the destructor depends on T and E. [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

Interaction with other classes

HasValue(), Value(), Error(), Ok(), and Err() allow status and content access. Bind() transforms a contained value through a Callable into a new Result, whereas Resolve() invokes a function for the error case. [SWS_CORE_00751] [SWS_CORE_00755] [SWS_CORE_00757] [SWS_CORE_00770] [SWS_CORE_00772] [SWS_CORE_00768] [SWS_CORE_00767]

Limitations & Error handling

Access to errors without an included error or to a value without an included value is defined as a violation. ValueOrThrow() can trigger and is the only result function exempt from use without ara::core initialization. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

Role in the exceptionless error path

For recoverable errors, interfaces should use ara::core::Result or ara::core::Future; the Result error type is set to ara::core::ErrorCode. RS General §4.1.2 “Error handling” EXP InterfacesGuidelines §3.1.2 “Result”

For exception-free access, the caller checks HasValue() and then reads Value() or Error(). These observers can be used without C++ exceptions; ValueOrThrow(), by contrast, is the explicit transition to an exception-based path. EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result” RS General §4.1.3 “The use of noexcept”

Activity diagram: the usual exception-free flow branches to value or error after HasValue(); ValueOrThrow() is the optionally depicted exception path. Sources: EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result”.

Normative core: value or error

The Core specification maps Result to the error handling model: for recoverable errors, APIs should return either Result or Future. Result thus separates the normal value path from an error transported as a data value. SWS Core §7.2 “Error handling” SWS Core §7.2.5.4 “Result”
