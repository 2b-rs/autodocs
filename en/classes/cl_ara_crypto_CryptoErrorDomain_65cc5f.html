Used for the identification and textual translation of all error codes of module crypto.

The class defines the central error domain for all errors that can be reported via the public interfaces in namespace ara::crypto [SWS_CRYPT_19950]. Its core tasks include returning the unique domain name and translating error codes from enumeration CryptoErrc into comprehensible error messages [SWS_CRYPT_19953]. All query functions are designed to be thread-safe and exception-safe, while the method for throwing exceptions does not participate in overload resolution when C++ exceptions are disabled [SWS_CRYPT_19954].

Context

The class ara::crypto::CryptoErrorDomain acts as a specialized error domain within the AUTOSAR Adaptive Platform. According to its class definition, it derives from ara::core::ErrorDomain and is declared as final. Its central responsibility is to map all errors that can be reported by the public interfaces within namespace ara::crypto. It assigns a unique domain identification to the errors, which can be queried via method Name [SWS_CRYPT_19950].

For uniform type binding, the class provides two type-related aliases: as an alias, Errc refers directly to enumeration CryptoErrc for cryptographic error codes [SWS_CRYPT_19903], whereas Exception references the base exception class CryptoException [SWS_CRYPT_19904]. Key interaction partners primarily include the cryptographic function blocks that generate errors of this domain, as well as application software that receives and evaluates errors via the base mechanisms of ara::core.

Context diagram: Integration of CryptoErrorDomain into error handling between ara::crypto APIs, base class ara::core::ErrorDomain, and the application. Sources: [SWS_CRYPT_19950], [SWS_CRYPT_19903], [SWS_CRYPT_19904].

Lifecycle

Creation of objects of CryptoErrorDomain is performed via the standard parameterless constructor, which is specified as constexpr and noexcept [SWS_CRYPT_19902]. Due to the declaration as constexpr, an instance can already be constructed at compile time. Interpretation: In typical platform implementations, the error domain is likely to exist as a long-lived or static singleton so that error codes throughout the entire process execution can refer to the same domain instance without dynamic memory allocation.

After instantiation, the object possesses a constant, stateless character; an inheritance hierarchy below this class is precluded by keyword final. With respect to concurrency, both constructor [SWS_CRYPT_19902] and query methods Name [SWS_CRYPT_19950], Message [SWS_CRYPT_19953], and ThrowAsException [SWS_CRYPT_19954] are explicitly classified as thread-safe. Instances can thus be used concurrently by multiple threads without external synchronization.

Usage Path

The regular sequence when interacting with CryptoErrorDomain is structured into the following steps:

  1. An operation within namespace ara::crypto fails and generates an error object of type ara::core::ErrorCode, which is associated with CryptoErrorDomain.
  2. The calling application or error handling routine checks the origin of the error and can retrieve the unique name of the domain using Name() if needed [SWS_CRYPT_19950].
  3. To generate log outputs or diagnostic messages, method Message() is called with the passed errorCode, which resolves the code and returns the associated text message as const char* [SWS_CRYPT_19953].
  4. If the caller wishes to convert the error into a C++ exception, ThrowAsException() is called, triggering a suitable exception based on CryptoException [SWS_CRYPT_19954], [SWS_CRYPT_19904].

Sequence diagram: Error resolution and text output via the interfaces of CryptoErrorDomain. Sources: [SWS_CRYPT_19950], [SWS_CRYPT_19953].

Error Scenarios

In error handling, the class features differentiated guarantees regarding exception safety. Methods Name [SWS_CRYPT_19950] and Message [SWS_CRYPT_19953] are declared as noexcept and are completely exception-safe. Should a numeric value be passed to Message that is not defined in enumeration CryptoErrc, a generic fallback message is presumably returned; termination due to exceptions is ruled out.

In contrast, method ThrowAsException is specified as not exception safe and provided with attribute [[noreturn]], since its intended purpose is throwing an exception [SWS_CRYPT_19954]. An essential boundary condition concerns platform configurations without exception support: If C++ exceptions are disabled in the compiler toolchain, ThrowAsException does not participate in overload resolution [SWS_CRYPT_19954]. In such systems, calling it cannot compile, and error handling must strictly be handled via error-value-based mechanisms such as result objects.

Usage and Call Context

The default constructor CryptoErrorDomain() initializes an instance of the error domain for cryptographic operations [SWS_CRYPT_19902]. It is specified as constexpr and noexcept, takes no arguments, and has no return value. Execution is synchronous and can take place at compile time. In application programs, manual instantiation is unlikely to be required, as the domain is regularly accessed via the global function GetCryptoErrorDomain() [SWS_CRYPT_19952].

Error Handling and Concurrency

The creation of the object is defined as exception safe as well as thread-safe [SWS_CRYPT_19902]. Since the constructor is declared with noexcept, no errors or exceptions occur during invocation; error messages to DET or DEM do not exist for this constructor.

Interplay in the module

The created domain forms the context for cryptographic error descriptions:

  • It encapsulates the error codes of the enumeration CryptoErrc [SWS_CRYPT_10099] via the type alias Errc [SWS_CRYPT_19903].
  • Via the free function MakeErrorCode(), instances of ara::core::ErrorCode are created that firmly reference this domain [SWS_CRYPT_19951].
  • The member functions of the domain allow querying the identifier via Name() [SWS_CRYPT_19950], text resolution via Message() [SWS_CRYPT_19953], and throwing system-specific errors via ThrowAsException() [SWS_CRYPT_19954] with the base type Exception [SWS_CRYPT_19904].
