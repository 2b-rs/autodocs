Encapsulates asymmetric private keys and provides the corresponding public key.

The interface ara::crypto::cryp::PrivateKey defines the general interface for asymmetric private keys in AUTOSAR Adaptive and is primarily managed via the shared-pointer alias PrivateKey::Sptr [SWS_CRYPT_22501]. Its central function GetPublicKey() allows retrieving the associated public key as PublicKey::Sptr in order to provide it for cryptographic partner operations [SWS_CRYPT_22511]. This retrieval is specified as thread-safe and exception-safe without standardized error codes, where any errors would likely be signaled in an implementation-specific manner via the return type ara::core::Result (interpretation).

Context

In the AUTOSAR Adaptive Platform, the interface ara::crypto::cryp::PrivateKey acts as a generalized interface for asymmetric private keys within the module crypto. It is declared in the header file ara/crypto/cryp/cryobj/private_key.h and derives directly from the base interface CryptoObject. As a core component of the asymmetric cryptography system, PrivateKey encapsulates the confidential key material required for cryptographic operations such as generating digital signatures or asymmetric decryption procedures.

In addition to the base class CryptoObject, the primary interaction partners include in particular the corresponding public key interface PublicKey as well as consuming crypto services and application routines. While the private key must always be kept secret, the interface enables the direct provisioning of the associated public key [SWS_CRYPT_22511] via the member function GetPublicKey(). In this way, a fixed type-related relationship between the private key and its mathematical counterpart is realized.

Lifecycle

Instances of the interface PrivateKey are managed and passed via the typed smart pointer PrivateKey::Sptr, which is defined as a type alias for std::shared_ptr<PrivateKey> [SWS_CRYPT_22501]. This shared pointer ensures shared ownership and automatic resource management via reference counting, so that the protected key material is released as soon as the last reference expires.

Since PrivateKey represents an abstract interface with pure virtual methods such as GetPublicKey() [SWS_CRYPT_22511], applications cannot instantiate the class directly. The creation and provisioning of concrete instances of PrivateKey::Sptr is likely to take place via specialized factories, key management components, or crypto providers of the Adaptive system (interpretation). The interface itself defines no discrete internal states or state transitions.

Regarding concurrency, the interface explicitly specifies thread safety (thread-safe) for the central member function GetPublicKey() [SWS_CRYPT_22511]. This allows multiple threads of execution concurrent, synchronization-free read access to the same key instance to obtain the corresponding public key.

Usage Path

The typical usage path of PrivateKey includes receiving the private key and subsequently extracting the corresponding public key for validation, registration, or communication purposes:

  1. Key acquisition: The consuming software component receives a valid instance of an asymmetric private key in the form of a PrivateKey::Sptr [SWS_CRYPT_22501].
  2. Retrieving the partner key: If the corresponding public key is required for a downstream workflow, the component invokes the member function GetPublicKey() on the instance [SWS_CRYPT_22511].
  3. Result processing: The call returns a ara::core::Result<PublicKey::Sptr> [SWS_CRYPT_22511]. The application checks the result object for success and, upon successful execution, unwraps the pointer PublicKey::Sptr.
  4. Further usage: The obtained public key can subsequently be transmitted to external communication partners or passed to local verification routines. Internally, the derivation of the public key is presumably performed directly from the mathematical key parameters of the private key (interpretation).

use

The method GetPublicKey of class ara::crypto::cryp::PrivateKey serves to synchronously retrieve the public key corresponding to the private key [SWS_CRYPT_22511]. The call is parameterless on an existing instance of PrivateKey. As return value, the interface returns a ara::core::Result<PublicKey::Sptr>, which upon successful execution provides a shared pointer to the associated PublicKey object [SWS_CRYPT_22511].

Error Handling and Concurrency

No standardized error codes are defined in the specification for this method [SWS_CRYPT_22511]. Error handling is performed via the return object of type ara::core::Result. Because the operation is declared as noexcept, it is considered exception-safe (exception safe) [SWS_CRYPT_22511]. In addition, the method is qualified as const and specified as thread-safe (thread-safe), whereby concurrent read access across multiple threads is permitted [SWS_CRYPT_22511].

Interaction

In typical cryptographic workflows, GetPublicKey is used after generating an asymmetric key pair using GeneratePrivateKey [SWS_CRYPT_20722]. In doing so, the permitted usage flags of the generated private key are transferred to the corresponding public key (for example, the permission for signature verification from signature generation) [SWS_CRYPT_20722]. The function must be distinguished from the interface of the same name in ProtectedKeyImportCtx, which serves to unpack imported public keys [SWS_CRYPT_50211].
