Role in the Crypto Stack

ara::crypto::cryp::KeySlot represents application-side access to persisted key material. The slot is obtained via a modeled InstanceSpecifier, is statically assigned to a provider and describes the type and permitted algorithm identifiers of the stored key. SWS Cryptography §7.3.1 “KeySlot Access”

Manifesto, rights and commitment

Read access is provided via a KeySlot or client port; Changes require the write-authorized port. The runtime enforces this assignment. Material may not be altered when deleted or saved while it is being used in a streaming operation. [SWS_CRYPT_10000] [SWS_CRYPT_10001] [SWS_CRYPT_60006]

A slot is accessible via the manifest and statically assigned to a provider. Source: SWS Cryptography §7.3.1 “KeySlot Access”.

Practical sequence

  1. Load slot via the modeled identifier.
  2. Query type, possible algorithms and providers.
  3. Bind slot directly to a compatible context or load a runtime key object.
  4. Only make changes outside of active streaming operations.
