Enables typed, controlled read and write access to memory areas of a buffer.

The template class enables typed and controlled access to the allocated memory of an underlying data buffer. Instantiation takes place exclusively via static factory methods, which return the instance as a unique pointer ([AP_SWS_SHWA_00007]). At runtime, data can be processed via type-safe read and write operations or via index operators ([AP_SWS_SHWA_00011]). All copy and move operations are prohibited, while individual data operations are subject to specific requirements for thread safety and error handling.

Context

The template class ara::shwa::Accessor forms the central access interface for typed memory access to shared memory buffers in AUTOSAR Adaptive Platform. It encapsulates the addressing and access logic to an underlying ara::shwa::Buffer and parameterizes it statically via the data type (DataT), dimensionality (Dimensions), access mode (AccessModeType), target device (AccessTargetType), and the memory allocator used (AllocatorT). In advanced scenarios, the class incorporates a TaskHandler, which presumably controls processing tasks in the buffer environment.

Within the module, the class acts in interaction with three central interaction partners:

  • Application / caller: Requests instances via the factory interface and executes read or write operations via methods or operators.
  • ara::shwa::Buffer: Provides the allocated memory area and is passed to the accessor as a reference during its creation ([AP_SWS_SHWA_00007]).
  • TaskHandler: Is registered during creation if needed in order to coordinate tasks during buffer handling ([AP_SWS_SHWA_00008]).

Context diagram: Interaction partners of ara::shwa::Accessor. Sources: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]

Lifecycle

The lifecycle of ara::shwa::Accessor is subject to strict semantic restrictions that prevent uncontrolled duplication or moving of access instances. The default constructor is explicitly deleted ([AP_SWS_SHWA_00002]). Likewise, both the copy constructor ([AP_SWS_SHWA_00003]) and the move constructor ([AP_SWS_SHWA_00005]) as well as all copy and move assignment operators are declared as deleted ([AP_SWS_SHWA_00004], [AP_SWS_SHWA_00006]). Direct instantiation on the stack or value semantics is thus excluded.

The creation of new instances occurs exclusively via the static factory method Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). It returns a ara::core::Result<std::unique_ptr<Accessor>>, whereby ownership is transferred exclusively to the caller. The object is automatically destroyed as soon as the owning std::unique_ptr goes out of scope. The creation methods are specified as thread-safe and exception safe ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).

Regarding concurrency during normal operation, the explicit access methods Get ([AP_SWS_SHWA_00012]) and Set ([AP_SWS_SHWA_00011]) are classified as thread-safe. In contrast, index accesses via operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) and property queries via HasProperty ([AP_SWS_SHWA_00015]) and GetProperty ([AP_SWS_SHWA_00016]) are not thread-safe and require application-side synchronization.

Usage Path

A regular usage sequence is divided into object creation, optional property checking, and subsequent read and write operations on the buffer:

  1. Instantiation via factory: The application calls Accessor::Create and passes the reference to a ara::shwa::Buffer as well as optionally configuration properties and a TaskHandler ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). After checking the ara::core::Result, the application takes over the std::unique_ptr<Accessor>.
  2. Evaluating properties: The template method HasProperty<PropertyT>() can be used to query whether a specific characteristic is present ([AP_SWS_SHWA_00015]). Present characteristics are subsequently read out with GetProperty<PropertyT>() ([AP_SWS_SHWA_00016]).
  3. Executing data access: Two interface paths are available for the actual data exchange:
    • Method-based access: Write operations take place via Set(index, value) ([AP_SWS_SHWA_00011]), read operations via Get(index) ([AP_SWS_SHWA_00012]), in each case addressed via a dimensional identifier (Id<Dimensions>).
    • Operator-based access: The index operator operator[] allows direct addressing via Id<Dimensions> ([AP_SWS_SHWA_00009]) or a linear offset of type std::size_t ([AP_SWS_SHWA_00010]). The return type ReferenceT resolves to const DataT& for read access and to DataT& for write access ([AP_SWS_SHWA_00014]).

Sequence diagram: Typical call sequence for buffer interaction via Accessor. Sources: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012], [AP_SWS_SHWA_00015]

Error Scenarios

Erroneous operations are represented via the ara::core::Result using error codes from ShwaErrorCode:

  • ShwaErrorCode::kAccessorFailure: Occurs during Create if the construction conditions or parameters are invalid ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • ShwaErrorCode::kIntegrityCorrupted: Signals corrupted memory integrity of the buffer. This can occur during instantiation ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) as well as during writing via Set ([AP_SWS_SHWA_00011]).
  • ShwaErrorCode::kInvalidIndex: Is reported for Get ([AP_SWS_SHWA_00012]) and Set ([AP_SWS_SHWA_00011]) if no valid initial value is present or the index is out of bounds.
  • ShwaErrorCode::kInvalidAccessMode: Occurs for Set if the combination of access modes is invalid ([AP_SWS_SHWA_00011]); this is likely the case when a write call is made on a class instantiated for AccessMode::kRead.
  • ShwaErrorCode::kResourceBusy: Indicates for Get ([AP_SWS_SHWA_00012]) and Set ([AP_SWS_SHWA_00011]) that the resource is currently busy. For this error, rollback semantics are guaranteed, whereby the previous state is preserved.
  • ShwaErrorCode::kFeatureNotSupported: Is returned when a property requested via GetProperty is not supported ([AP_SWS_SHWA_00016]).

Regarding exception safety, Create, HasProperty, and GetProperty are declared with noexcept and specified as exception safe ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008], [AP_SWS_SHWA_00015], [AP_SWS_SHWA_00016]). In contrast, the data access operations Get, Set, and operator[] are considered not exception safe ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012]).
