Context

Struct ara::diag::DTCInformation::SnapshotDataRecordType is a central data type of the diagnostic module (diag) in the AUTOSAR Adaptive Platform in release R25-11 [SWS_DM_00661]. It is defined as an embedded data structure in the scope of interface class ara::diag::DTCInformation and is available via header file ara/diag/dtc_information.h AUTOSAR_AP_SWS_Diagnostics §8.48.4 “Struct: SnapshotDataRecordType”. The primary role of this type is to encapsulate snapshot data (freeze frame records) captured by the diagnostic system when a Diagnostic Trouble Code (DTC) occurs and is stored.

Technically, SnapshotDataRecordType represents the data structure for snapshot records in accordance with diagnostic requirements AUTOSAR_AP_SWS_Diagnostics §p. 1109. Each snapshot record represents a specific set of environmental conditions and measured values at the time of fault occurrence. For this purpose, the structure contains two essential attributes:

  • snapshotRecordNumber: An integer identifier of type std::uint8_t defining a unique record number for a snapshot entry [SWS_DM_02114] AUTOSAR_AP_SWS_Diagnostics §8.48.4.1.2 “snapshotRecordNumber”.
  • snapshotDataIdentifiers: A vector of type ara::core::Vector<SnapshotDataIdentifierType> containing the list of captured Diagnostic Data Identifiers (Data Identifiers, DIDs) and their associated payload [SWS_DM_02115] AUTOSAR_AP_SWS_Diagnostics §8.48.4.1.1 “snapshotDataIdentifiers”.

Interaction partners of this data structure are typically the diagnostic management of the Adaptive Platform as well as diagnostic applications evaluating detailed state and fault contexts via DTCInformation AUTOSAR_AP_SWS_Diagnostics §p. 75 AUTOSAR_AP_SWS_Diagnostics §p. 83.

Lifecycle

As a pure value type (struct) without its own virtual methods or complex state machines, ara::diag::DTCInformation::SnapshotDataRecordType is subject to the regular value and RAII semantics of modern C++ [SWS_DM_00661]. Instantiation is generally carried out by the runtime environment of the diagnostic subsystem when stored snapshot entries are read from the fault memory and converted into adaptive data types.

Regarding ownership, the instance fully owns all data stored within it. Through the use of ara::core::Vector for the identifiers [SWS_DM_02115], the object manages its dynamic memory area independently. Copy and move operations follow the standard behavior of the container and the primitive data type std::uint8_t [SWS_DM_02114]. Upon destruction of an instance when leaving scope, all allocated resources of the contained elements in the vector are automatically released.

The structure defines no internal synchronization mechanisms for concurrent access. Concurrent reading by multiple threads is thread-safe as long as no competing write accesses take place. Modifications to an instance must be synchronized externally by calling application layers if needed.

Usage Path

Typical deployment of SnapshotDataRecordType occurs in the context of diagnostic queries of fault memory data. A diagnostic application interacts with the query functions of DTCInformation to determine detailed fault causes and accompanying circumstances.

  1. Querying snapshots: The application initiates a query of snapshot records for a specific fault code via the diagnostic interface. Interpretation: The diagnostic system then generates a collection of SnapshotDataRecordType instances as a result.
  2. Identifying the record: The caller evaluates the record number snapshotRecordNumber from [SWS_DM_02114] to determine the context of the snapshot (for example, whether it is the first occurring fault or the most recent occurrence).
  3. Reading diagnostic identifiers: By iterating over vector snapshotDataIdentifiers, the application accesses the individual SnapshotDataIdentifierType elements [SWS_DM_02115]. In doing so, stored measured variables such as speeds, temperatures, supply voltages, or timestamps are read.
  4. Processing and forwarding: The extracted values are either evaluated internally in the ECU or transmitted via downstream UDS diagnostic services to an external diagnostic tester tool.

Error Scenarios

Since SnapshotDataRecordType is designed as a passive data container [SWS_DM_00661], the structure itself does not raise any specific exception handling or error codes. Nevertheless, various error situations can occur in practical application that must be taken into account during processing:

  • Empty record list: If no environmental data was configured for a DTC or no measured values were available at the time of triggering, vector snapshotDataIdentifiers is likely empty ([SWS_DM_02115]). Calling code must check whether the vector contains values before accessing elements.
  • Invalid or unexpected record number: If the received snapshotRecordNumber does not match the expected values, this presumably indicates a differing configuration of the diagnostic memory [SWS_DM_02114].
  • Memory bottlenecks during allocation: Because container ara::core::Vector claims dynamic memory for the DIDs, memory allocations can fail in resource-constrained systems, which must be intercepted by the surrounding runtime environment.
