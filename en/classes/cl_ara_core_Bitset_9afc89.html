Context

The class template ara::core::Bitset<std::size_t N> provides an adaptation of the standard type std::bitset for safety-related automotive software in the core module of the AUTOSAR Adaptive Platform. It is declared via the header file ara/core/bitset.h. It serves for the efficient management and bitwise manipulation of fixed-length bit sequences N.

Compared to the ISO C++ model, ara::core::Bitset features targeted adaptations to the fault-tolerant and exception-free programming model of AUTOSAR. This particularly concerns the interaction with platform-specific data types such as ara::core::BasicString, the return of ara::core::Result for synchronous error reporting in positional operations, as well as dedicated conversion functions to fixed widths of integer types.

Lifecycle

Instances of ara::core::Bitset are characterized by strictly regulated lifecycle behavior without dynamic memory management for the bit vector. Initialization can occur via various paths:

  • Default initialization: The parameterless default constructor [SWS_CORE_01713] is declared as constexpr and noexcept and pre-initializes all N bits with the value zero.
  • Integer initialization: Via the constructor [SWS_CORE_01719], a bitset can be created from a value of type unsigned long long, likewise as constexpr and noexcept.
  • Initialization from strings: Using ara::core::BasicString, the constructor [SWS_CORE_01749] enables the parsing of a character sequence. This constructor is defined as noexcept. In addition, there is a constructor for classic C strings via pointers of type const CharT* [SWS_CORE_01750], which is classified as not exception-safe (not exception safe).

The class implements full value semantics. The copy constructor [SWS_CORE_01714], the move constructor [SWS_CORE_01716], the copy assignment operator [SWS_CORE_01715], and the move assignment operator [SWS_CORE_01717] are explicitly specified as noexcept=default. The destructor [SWS_CORE_01718] is declared exception-safe and thread-safe.

Usage Path

A typical processing workflow with ara::core::Bitset is divided into three consecutive phases:

  1. Creation and initialization: The application creates the bitset with the required bit width at compile time, for example via the default constructor [SWS_CORE_01713] or by converting a bit mask [SWS_CORE_01719].
  2. Bit manipulation and combination:
    • Full modifications are performed via set() [SWS_CORE_01725], reset() [SWS_CORE_01727], and flip() [SWS_CORE_01730].
    • Targeted manipulations of individual bits at position pos are performed via set(pos, val) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728], or flip(pos) [SWS_CORE_01731].
    • Logical bit operations are available via compound assignment operators such as operator&= [SWS_CORE_01720], operator|= [SWS_CORE_01721], and operatorˆ= [SWS_CORE_01722]. Bitwise inversion is provided via operator~ [SWS_CORE_01729].
    • Shifts of bits are implemented via operator<<= [SWS_CORE_01723], operator>>= [SWS_CORE_01724], and the corresponding shift operators [SWS_CORE_01747] and [SWS_CORE_01748].
    • Read and write accesses to individual bits can be performed directly via the subscripted operator[] [SWS_CORE_01732] (constant) or [SWS_CORE_01733] (reference).
  3. Evaluation and conversion:
    • State checks are performed via all() [SWS_CORE_01744], any() [SWS_CORE_01745], none() [SWS_CORE_01746], count() [SWS_CORE_01740], and size() [SWS_CORE_01741]. Equality of two instances is checked by operator== [SWS_CORE_01742]. Individual positions are checked by test(pos) [SWS_CORE_01743].
    • For conversion back, ara::core::Bitset offers, in addition to to_ulong() [SWS_CORE_01734], to_ullong() [SWS_CORE_01735], and to_string() [SWS_CORE_01751], dedicated, thread-safe fixed-width conversions: to_uint8t() [SWS_CORE_01736], to_uint16t() [SWS_CORE_01737], to_uint32t() [SWS_CORE_01738], and to_uint64t() [SWS_CORE_01739].

Error Scenarios

Instead of C++ standard exceptions, the Adaptive Platform uses a consistent violation and error model for ara::core::Bitset with strict noexcept declaration of most methods:

  • Position violations (out of range): The positioned modifiers set(pos, val) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728], and flip(pos) [SWS_CORE_01731] return a ara::core::Result. If pos does not represent a valid bit position, the violation IsoStdOutOfRangeViolation is triggered (instead of std::out_of_range). The query function test(pos) [SWS_CORE_01743] also triggers IsoStdOutOfRangeViolation in case of an invalid position.
  • String parsing errors: In the constructor from ara::core::BasicString [SWS_CORE_01749], a start position pos > size() leads to violation IsoStdOutOfRangeViolation. If the analyzed string contains a character that corresponds to neither zero nor one, IsoStdInvalidArgumentViolation is signaled (instead of std::invalid_argument).
  • Conversion overflows: If the integer value represented in the bitset cannot be represented in the respective return type, the conversion functions to_ulong() [SWS_CORE_01734], to_ullong() [SWS_CORE_01735] as well as to_uint8t() [SWS_CORE_01736], to_uint16t() [SWS_CORE_01737], to_uint32t() [SWS_CORE_01738], and to_uint64t() [SWS_CORE_01739] trigger violation IsoStdOverflowErrorViolation (instead of std::overflow_error).
  • Exception safety: While almost all functions of the class are specified as exception safe, the constructor from const CharT* [SWS_CORE_01750] and to_string() [SWS_CORE_01751] are explicitly classified as not exception safe, presumably due to dynamic memory allocations during string processing.
