Provides a standard-compliant, type-safe, fixed-size bitfield abstraction with noexcept guarantees for Adaptive Core.

The class template ara::core::Bitset provides an implementation of std::bitset for fixed-size bit sequences adapted for AUTOSAR Adaptive [SWS_CORE_01741]. It offers comprehensive operations for bit manipulation, logical operations, and optimized conversions to scalar integer types with strict noexcept guarantees [SWS_CORE_01738]. Position-based modifications report invalid indices via ara::core::Result instead of C++ exceptions, while conversions handle overflow errors deterministically. This makes the class particularly suitable for resource-efficient and fail-safe ECU functions.

Context

The template class ara::core::Bitset provides an implementation of the C++ standard type std::bitset for bit sequences with a length N fixed at compile time within the Adaptive Platform [SWS_CORE_01741]. In the AUTOSAR ecosystem, the class serves for the performant and type-safe handling of bitfields, status masks, and flag registers on ECUs. It integrates seamlessly into the type system of the core module by supporting the platform-specific type ara::core::BasicString instead of std::basic_string [SWS_CORE_01749], [SWS_CORE_01751]. In addition, AUTOSAR extends the standardized interface with dedicated conversion functions to unsigned fixed-width integer types such as std::uint8_t, std::uint16_t, std::uint32_t, and std::uint64_t [SWS_CORE_01736], [SWS_CORE_01737], [SWS_CORE_01738], [SWS_CORE_01739].

Lifecycle

An instance is created flexibly via multiple constructors. The default constructor initializes all N bits as zero values and is declared as constexpr and noexcept [SWS_CORE_01713]. Alternatively, a bitset can be instantiated from a scalar value of type unsigned long long [SWS_CORE_01719] or text-based from ara::core::BasicString [SWS_CORE_01749] or a null-terminated string pointer const CharT* [SWS_CORE_01750]. Copy and move constructors are provided and defined as noexcept=default [SWS_CORE_01714], [SWS_CORE_01716]. Likewise, the corresponding assignment operators are provided [SWS_CORE_01715], [SWS_CORE_01717]. The destructor is specified as noexcept and thread-safe [SWS_CORE_01718]. With regard to concurrency, the integer conversion functions are also thread-safe [SWS_CORE_01736], [SWS_CORE_01737], whereas modifying accesses to the same bitset instance must be synchronized.

Usage Path

A typical usage path comprises instantiation, subsequent manipulation of individual bits or bitmasks, and final evaluation or conversion of the bitfield:

  • Creation: The bitset is typically created with an initial value [SWS_CORE_01719] or initialized via the default constructor [SWS_CORE_01713].
  • Manipulation: Individual bits can be modified via position-based calls to set [SWS_CORE_01726], reset [SWS_CORE_01728], and flip [SWS_CORE_01731]. For the entire bitfield, parameterless variants of set [SWS_CORE_01725], reset [SWS_CORE_01727], and flip [SWS_CORE_01730] as well as bitwise logical and shift operators such as operator&= [SWS_CORE_01720], operator|= [SWS_CORE_01721], operatorˆ= [SWS_CORE_01722], operator~ [SWS_CORE_01729], operator<<= [SWS_CORE_01723], and operator>>= [SWS_CORE_01724] are available.
  • Evaluation: The status can be queried via test [SWS_CORE_01743], operator[] [SWS_CORE_01732], [SWS_CORE_01733], or predicates such as all [SWS_CORE_01744], any [SWS_CORE_01745], none [SWS_CORE_01746], as well as count [SWS_CORE_01740].
  • Conversion: For further processing, the bitfield content can be converted into numerical fixed-width types, for example via to_uint32t [SWS_CORE_01738], or exported as a string using to_string [SWS_CORE_01751].

Error Scenarios

In contrast to std::bitset, ara::core::Bitset uses a fault-tolerant, deterministic error handling concept without exceptions (noexcept):

  • Out of bounds on positional accesses: The mutating functions set(pos) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728], and flip(pos) [SWS_CORE_01731] use the return type Result<Bitset<N>&>. If pos is outside the valid range, IsoStdOutOfRangeViolation is reported instead of std::out_of_range. Interpretation: The consistent use of ara::core::Result and noexcept is likely intended to comply with the strict no-exception requirements in safety-critical areas of the Adaptive Platform. The inspection function test(pos) also indicates IsoStdOutOfRangeViolation if pos is invalid [SWS_CORE_01743].
  • Invalid strings: During construction from ara::core::BasicString [SWS_CORE_01749], a IsoStdOutOfRangeViolation is triggered on pos > size(), and a IsoStdInvalidArgumentViolation (instead of std::invalid_argument) is triggered on characters other than 0 or 1.
  • Numeric overflow: If the represented bit state cannot be represented in the requested target type, the conversion functions to_uint8t [SWS_CORE_01736], to_uint16t [SWS_CORE_01737], to_uint32t [SWS_CORE_01738], to_uint64t [SWS_CORE_01739], to_ulong [SWS_CORE_01734], and to_ullong [SWS_CORE_01735] report IsoStdOverflowErrorViolation instead of std::overflow_error in each case.
  • Restricted exception safety: While most operations are noexcept and exception-safe, construction from pointers const CharT* [SWS_CORE_01750] as well as export via to_string [SWS_CORE_01751] are explicitly classified as not exception safe (not exception safe).
