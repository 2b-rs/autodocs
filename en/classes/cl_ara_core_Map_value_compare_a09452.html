Context

Within module core of the AUTOSAR Adaptive Platform, class ara::core::Map::value_compare provides a helper function object designed for the ordered comparison of complete elements in an associative container. The enclosing container ara::core::Map<Key, T, Compare, Allocator> manages elements of type value_type, which are composed of key-value pairs. While users typically define a comparison predicate for the pure key type Key, internal search and insertion operations as well as external algorithms often require a comparator capable of operating directly on complete element pairs. value_compare encapsulates this functionality by incorporating the key predicate and making it applicable at the element level.

The specification defines the functional behavior of value_compare via the reference “As per corresponding usage in [map]”. The container ara::core::Map, the underlying predicate Compare, and generic algorithms of the standard library act as interaction partners in the context of this class. Declared in the header file #include "ara/core/map.h", the class is an integral part of the standardized AUTOSAR core library. Its technical responsibility is limited to using the key comparator ([SWS_CORE_01421]) held in the protected member variable comp for higher-level value comparisons, without performing its own data or memory management.

Lifecycle

The lifecycle of a value_compare object is bound to the enclosing container or the calling algorithm. Constructor value_compare(Compare c) is explicitly specified with visibility protected ([SWS_CORE_01422]). This precludes direct instantiation by arbitrary user code. Interpretation: An instance is therefore likely created exclusively in a controlled manner by ara::core::Map, which instantiates the object internally when needed or passes it outward via an interface. Upon creation, predicate instance c is passed to the protected member variable comp ([SWS_CORE_01421]) and stored in the object.

Regarding ownership, value_compare holds predicate Compare by value copy. The lifetime of the contained comparator thus strictly ends with the destruction of the value_compare instance. Because it is a low-state function object, cleanup follows regular RAII and stack mechanisms in C++, without an independent multi-phase state machine. For concurrency, it is essential that the function call operator is declared as const ([SWS_CORE_01423]). Provided that the encapsulated predicate Compare does not modify thread-unsafe state, multiple threads of execution can use the same comparator in parallel for read and sort operations.

Usage Path

The typical usage path of ara::core::Map::value_compare comprises obtaining the predicate, applying it repeatedly to element pairs, and evaluating the resulting ordering criterion:

  • Provision: A caller obtains the value_compare instance from the associated ara::core::Map container, which calls the protected constructor [SWS_CORE_01422] while passing the current key predicate.
  • Comparison call: The caller or a generic algorithm applies the function object to two elements of the container via call operator operator()(const value_type &x, const value_type &y) const ([SWS_CORE_01423]).
  • Delegation: Interpretation: During the execution of operator(), the object presumably accesses the respective key components x.first and y.first of the value pairs and delegates the actual comparison to the protected member comp ([SWS_CORE_01421]).
  • Evaluation: The call returns a bool value ([SWS_CORE_01423]) indicating whether element x strictly precedes element y with respect to the defined sort order.

This sequence is typically traversed within algorithms such as std::includes or during custom range analyses. The encapsulation ensures that the algorithm does not need to manually access the key structure of the entries.

Error Scenarios

In the specification, both constructor [SWS_CORE_01422] and call operator [SWS_CORE_01423] are explicitly classified as not exception safe. The class thus offers no proprietary guarantees for error neutralization or exception handling. If initializing or copying predicate Compare in the constructor throws an exception, instantiation is aborted and the exception is passed on to the calling site.

The same applies when calling operator() ([SWS_CORE_01423]): If the encapsulated predicate comp ([SWS_CORE_01421]) throws an exception during the key comparison, it propagates out of the operator unattenuated. A mandatory precondition for logical correctness is that the configured predicate must implement a strict weak ordering (Strict Weak Ordering). If the comparator violates these mathematical properties, this results in incorrect ordering states within the map, without value_compare being able to intercept this error. Furthermore, both parameters x and y must refer to valid instances of value_type.
