intended use

ara::core::Vector<T, Allocator> implements the sequential std::pmr::vector container with parameterized memory resource [SWS_CORE_01301] [SWS_CORE_01303]. It provides size and capacity management, random element access, iterators, and container modifiers [SWS_CORE_01348] [SWS_CORE_01355] [SWS_CORE_01332] [SWS_CORE_01362] [SWS_CORE_01372].

Generation & destruction

The container can be created empty, from an allocator, with a number of elements, a range or an initializer list [SWS_CORE_01318] [SWS_CORE_01319] [SWS_CORE_01320] [SWS_CORE_01322] [SWS_CORE_01325]. Copy and move operations are available and conditionally exception-safe depending on T or allocator; the destructor is noexcept [SWS_CORE_01314] [SWS_CORE_01315] [SWS_CORE_01316] [SWS_CORE_01317] [SWS_CORE_01326].

Interaction with other classes

data() returns a pointer to the elements. reserve(), shrink_to_fit(), resize(), and capacity() control or observe capacity [SWS_CORE_01360] [SWS_CORE_01361] [SWS_CORE_01347] [SWS_CORE_01349] [SWS_CORE_01350] [SWS_CORE_01348]. emplace_back, push_back, insert, erase, and clear modify the content [SWS_CORE_01362] [SWS_CORE_01363] [SWS_CORE_01367] [SWS_CORE_01372] [SWS_CORE_01375].

Limitations & Error handling

at() triggers a IsoStdOutOfRangeViolation out of bounds [SWS_CORE_01354] [SWS_CORE_01355]. For values in reserve() or resize() that are too large, a IsoStdLengthErrorViolation is specified, [SWS_CORE_01347] [SWS_CORE_01350] [SWS_CORE_01351]. Many change operations are not exception-safe; push_back and swap are conditionally exception-safe depending on type and allocator properties [SWS_CORE_01362] [SWS_CORE_01372] [SWS_CORE_01363] [SWS_CORE_01364] [SWS_CORE_01374].

Container base for modeled vector data types

Core runs Vector as a container derived from the C++ standard library. The language binding uses a C++ alias for modeled vector data types with a configurable allocator and optional maximum size. The type thus connects the general container API with generated interface types. SWS Core §7.4 “Core data types” SWS Core §7.4.2 “Data types derived from the C++ standard” SWS LanguageBinding §7.1 “C++ binding for CppImplementationDataTypes” SWS LanguageBinding §8.2.4 “Vector Data Type”

The choice and behavior of the allocator remains part of the specific binding or implementation contract. Interpretation: Capacity changes such as reserve() or resize() should be planned against this model limit at modeled maximum sizes instead of just considering them as local container optimization.
