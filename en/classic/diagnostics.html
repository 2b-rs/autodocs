System architecture and role of the module cluster

The "Diagnostic Services" cluster comprises the four BSW modules with which a Classic Platform ECU detects, stores, reports to a tester, and logs errors. The DCM receives diagnostic requests according to the session layer services of ISO 14229-2 (SWS DCM p. 57). The roles of the modules are:

  • DCM (Diagnostic Communication Manager): Server for tester requests. It implements UDS services according to ISO 14229-1, including 0x19 ReadDTCInformation, 0x14 ClearDiagnosticInformation, and 0x85 ControlDTCSetting ([SWS_Dcm_00248], [SWS_Dcm_00247], [SWS_Dcm_00249]). Internally, it is structured into the submodules DSL, DSD, and DSP ([SWS_Dcm_00111], [SWS_Dcm_00221]).
  • DEM (Diagnostic Event Manager): manages diagnostic events via EventIds ([SWS_Dem_00153]), maintains the UDS status bits ([SWS_Dem_00006]) and the primary fault memory ([SWS_Dem_00010]). There is exactly one DEM per ECU ([SWS_Dem_00126]).
  • DET (Default Error Tracer): receives development and runtime errors via Det_ReportError and Det_ReportRuntimeError ([SWS_Det_00009], [SWS_Det_01001]).
  • Dlt (Diagnostic Log and Trace): buffers log and trace messages from BSW and SW-Cs ([SWS_Dlt_00003]) and transmits them via PduR_DltTransmit ([SWS_Dlt_00762]).

Persistence and communication control lie outside the cluster. Dem and Dlt store non-volatile data via the NvM ([SWS_Dem_00164], [SWS_Dlt_00453]). The DCM receives communication modes from the ComM ([SWS_Dcm_00356]).

Context diagram: DCM and DEM form the diagnostic path to the tester, DET and Dlt form the error and logging path; NvM, PduR, and ComM are the external partners. Sources: [SWS_Dcm_00094], [SWS_Dem_00183], [SWS_Dem_00124], [SWS_Dlt_00763], [SWS_Dlt_00430], [SWS_Dlt_00377], [SWS_Dlt_00736]

Interaction and interaction paths

The main path is the request-response chain between PduR and DCM (SWS DCM p. 55). It proceeds in three steps:

  • The PduR reports the start of reception with Dcm_StartOfReception ([SWS_Dcm_00094]).
  • It copies the segments with Dcm_CopyRxData ([SWS_Dcm_00556]).
  • It completes the reception with Dcm_TpRxIndication ([SWS_Dcm_00093]).

The DSL forwards the data to the DSD with E_OK only after Dcm_TpRxIndication ([SWS_Dcm_00111]). If the requested length is greater than the DCM buffer, Dcm_StartOfReception returns BUFREQ_E_OVFL. A length of 0 is rejected with BUFREQ_E_NOT_OK ([SWS_Dcm_00444], [SWS_Dcm_00642]).

The DSD checks service identifier, session, and security level ([SWS_Dcm_00196], [SWS_Dcm_00211], [SWS_Dcm_00217]). It then calls the responsible functionality of the DSP ([SWS_Dcm_00221]). The response is sent via DSD and DSL to the PduR ([SWS_Dcm_00232], [SWS_Dcm_00237]). The DSL forwards the confirmation Dcm_TpTxConfirmation to the DSD, which reports it via DspInternal_DcmConfirmation to the DSP ([SWS_Dcm_00235], [SWS_Dcm_00236]; SWS DCM p. 479).

Sequence diagram: A request is processed only after successful reception indication; response and confirmation run back through all three DCM submodules. Sources: [SWS_Dcm_00094], [SWS_Dcm_00556], [SWS_Dcm_00111], [SWS_Dcm_00236], SWS DCM p. 479

Between DCM and DEM flow the data of the fault memory services:

  • Filter and iteration: Before each readout, the DCM sets a filter via Dem_SetDTCFilter and then iterates with Dem_GetNextFilteredDTC ([SWS_Dcm_00835], [SWS_Dem_00215]). Each new filter resets the client's sequence ([SWS_Dem_00649]).
  • Status mask: The availability mask is returned by Dem_GetDTCStatusAvailabilityMask ([SWS_Dcm_00007]). The DEM uses it to mask all status bytes that it passes to the DCM ([SWS_Dem_00657]).
  • Freeze frames: The DEM already provides them in the response layout of 0x19 0x04 ([SWS_Dem_00071]; SWS DEM p. 225).
  • Consistency: During reading, the DCM locks updating of the entry ([SWS_Dcm_00371]). Dem_EnableDTCRecordUpdate releases it again ([SWS_Dem_00271]).
  • OBD: The DEM provides dedicated interfaces such as Dem_DcmReadDataOfPID01 to the DCM ([SWS_Dem_00304], [SWS_Dem_00318]).

Synchronization, reentrancy and task contexts

Dcm_CopyRxData, Dcm_TpRxIndication, and Dcm_TpTxConfirmation can be called in the interrupt context ([SWS_Dcm_00556], [SWS_Dcm_00093], [SWS_Dcm_00351]; SWS DCM p. 274). Interpretation: The actual service processing is therefore likely to take place at task level in Dcm_MainFunction. This is supported by the fact that calls following DCM_E_PENDING are repeated in the next MainFunction cycle ([SWS_Dcm_00760]).

Asynchronous operations follow the Dcm_OpStatusType protocol in the DCM ([SWS_Dcm_00527], [SWS_Dcm_00530], [SWS_Dcm_00528]):

  • The first call is made with DCM_INITIAL ([SWS_Dcm_00527]).
  • On DCM_E_PENDING, the operation is called again ([SWS_Dcm_00530]).
  • On DCM_E_FORCE_RCRRP, the DCM transmits NRC 0x78 ([SWS_Dcm_00528]).

The same pattern applies towards the DEM: if Dem_ClearDTC returns DEM_PENDING, the DCM calls the function again in the next Dcm_MainFunction ([SWS_Dcm_00703]).

In the DEM, Dem_MainFunction processes all non-event-driven internal functions ([SWS_Dem_00125], [SWS_Dem_00266]). For reentrancy, the following applies:

  • Dem_SetEventStatus is reentrant only for different EventIds ([SWS_Dem_00183]).
  • Dem_ResetEventStatus takes effect asynchronously at a later time ([SWS_Dem_00187]).
  • The readout APIs are reentrant for different ClientIds, but not for the same client ([SWS_Dem_00215], [SWS_Dem_00227]).

In multicore systems, a module calls the DEM on the core on which the error occurs (BSWDistributionGuide p. 43). Dlt_SendLogMessage and Dlt_SendTraceMessage are reentrant ([SWS_Dlt_00241], [SWS_Dlt_00243]). This also applies to the DET callouts <User_Error_Hooks> ([SWS_Det_00181]).

Typical lifecycles and operating modes

The DEM distinguishes between a pre-initialized and a fully initialized mode ([SWS_Dem_00169]). The lifecycle comprises:

  • Pre-initialization: After Dem_PreInit, the DEM buffers event reports in a configurable queue ([SWS_Dem_00179], [SWS_Dem_00180], [SWS_Dem_00167], [SWS_Dem_00207]). These reports do not yet trigger a monitor status callback (SWS DEM p. 169).
  • Operation: After Dem_Init, the DEM is fully operational ([SWS_Dem_00181], [SWS_Dem_00340]).
  • Shutdown: Dem_Shutdown completes pending operations and triggers the saving of modified non-volatile data ([SWS_Dem_00182], [SWS_Dem_00102], [SWS_Dem_00341]).

Dem_RestartOperationCycle restarts an operation cycle and reinitializes the monitors via InitMonitorForEvent ([SWS_Dem_00194], [SWS_Dem_00679]). The attribute cycleStatusStorage defines whether the cycle status survives a power cycle. automaticEnd no longer has any meaning on the Classic Platform in R20-11 (DEXT p. 225).

State diagram: The DEM undergoes pre-initialization with an event buffer, full operation, and shutdown with NvM backup. Sources: [SWS_Dem_00169], [SWS_Dem_00167], [SWS_Dem_00340], [SWS_Dem_00341], [SWS_Dem_00181]

The DCM undergoes the following states and mode changes:

  • Start: The DCM starts with a locked security level in the default session ([SWS_Dcm_00033], [SWS_Dcm_00034]). During initialization, it checks via Dcm_GetProgConditions whether a return from the bootloader has occurred ([SWS_Dcm_00536], [SWS_Dcm_00544]).
  • Bootloader jump: Beforehand, Dcm_SetProgConditions saves the context data ([SWS_Dcm_00535], [SWS_Dcm_00543]).
  • Session timeout: If S3Server expires, the DCM returns to the default session ([SWS_Dcm_00140]). Applications can force this with Dcm_ResetToDefaultSession ([SWS_Dcm_00520]).
  • Communication modes: No Communication and Silent Communication disable transmissions, Full Communication enables them ([SWS_Dcm_00148], [SWS_Dcm_00153], [SWS_Dcm_00157]).

The Dlt is initialized late during startup after the NvM and adopts the configuration stored there ([SWS_Dlt_00239], [SWS_Dlt_00350]). Dlt_StoreConfiguration writes it back ([SWS_Dlt_00736], [SWS_Dlt_00078]). The DET is started with Det_Start ([SWS_Det_00010]). Interpretation: Dcm_Init is likely to follow after Dem_Init because the fault memory services require a fully initialized DEM ([SWS_Dem_00340]).

Error Handling, DET Tracing, and Degradation

If development error detection is active, the modules report development errors to the DET. For the DEM, this occurs via DemDevErrorDetect with the error codes from [SWS_Dem_00173] ([SWS_Dem_00124]). The Dlt defines its own development and runtime errors, such as DLT_E_SKIPPED_TRANSMISSION ([SWS_Dlt_00727], [SWS_Dlt_00728]). Det_ReportError calls all configured callouts with the signature of <User_Error_Hooks> ([SWS_Det_00501], [SWS_Det_00181]).

In R20-11, a fan-out connects DET and Dlt. The Dlt provides Dlt_DetForwardErrorTrace ([SWS_Dlt_00430], [SWS_Dlt_00432], [SWS_Det_00211]). From this, it generates log messages with fixed IDs; the same applies to DEM events ([SWS_Dlt_00376], [SWS_Dlt_00377], [SWS_Dlt_00031]). Newer releases remove this path: R25-11 removes SWS_Dlt_00432 as well as the Dlt calls in the DET (SWS Dlt p. 1, SWS DET p. 1). For R20-11, the mentioned requirements apply.

Sequence diagram: A reported development error reaches the bus via callouts and the Dlt fan-out. Sources: [SWS_Det_00009], [SWS_Det_00501], [SWS_Dlt_00430], [SWS_Dlt_00003], [SWS_Dlt_00762], [SWS_Dlt_00273]

In the DEM, several degradation mechanisms take effect:

  • Full fault memory: The displacement strategy decides on the replacement. If there is no displaceable entry, the storage request is discarded ([SWS_Dem_00401], [SWS_Dem_00407]). Dem_GetEventMemoryOverflow indicates the overflow ([SWS_Dem_00398], [SWS_Dem_00559]).
  • NvM error: The DEM reinitializes unreadable data and ignores write errors ([SWS_Dem_00578], [SWS_Dem_00579]).
  • DTC storage disabled: If it is disabled via 0x85, the DEM ignores status reports ([SWS_Dem_00626], [SWS_Dcm_00406]). When changing to the default session, the DCM enables it again ([SWS_Dcm_00751]).

On the communication side, Dcm_TpTxConfirmation unlocks the transmit buffer and aborts ongoing error handlings such as timeouts ([SWS_Dcm_00352], [SWS_Dcm_00353]; ErrorDescription p. 26). If the Dlt cannot buffer a log message in any assigned LogChannel, Dlt_SendLogMessage returns DLT_E_NO_BUFFER instead of blocking ([SWS_Dlt_00241]).
