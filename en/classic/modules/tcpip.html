Role in the Ethernet stack: Protocol collection between socket owner and EthIf

TcpIp is the TCP/IP stack of the Classic Platform. It consists of submodules each with its own protocol function [SWS_TCPIP_00052]. For IPv4, it comprises:

  • IP [SWS_TCPIP_00053], ARP [SWS_TCPIP_00056] and Auto-IP [SWS_TCPIP_00057],
  • DHCPv4 client and server [SWS_TCPIP_00058] as well as ICMPv4 [SWS_TCPIP_00059].

For IPv6, it brings along the header processing [SWS_TCPIP_00160], NDP [SWS_TCPIP_00164], ICMPv6 [SWS_TCPIP_00163] and a DHCPv6 client [SWS_TCPIP_00166]. Above these lie UDP [SWS_TCPIP_00060] and TCP [SWS_TCPIP_00061]. Optionally, TLS from version 1.2 is added [SWS_TCPIP_00300][SWS_TCPIP_00302]. Which protocols a project contains is determined by scaling classes; class 3 is the dual stack [SWS_TCPIP_00150], SWS TcpIp Fig. 3 p. 18.

Interface upwards. TcpIp serves configured socket owners. If the owner type is SOAD, <Up> is replaced by SoAd; if it is CDD, the configured function names apply [SWS_TCPIP_00220][SWS_TCPIP_00221]. Each owner receives its own TcpIp_<Up>GetSocket function with exclusively assigned sockets [SWS_TCPIP_00222], SWS TcpIp p. 123.

Interface downwards and control. TcpIp receives frames via TcpIp_RxIndication [SWS_TCPIP_00029]. Transmission takes place via EthIf_Transmit, always with TxConfirmation = FALSE [SWS_TCPIP_00131]. The state is controlled by EthSM via TcpIp_RequestComMode [SWS_TCPIP_00070], SWS EthSM p. 27. Further dependencies:

  • CSM optionally for cryptographic services [SWS_TCPIP_00028],
  • DET and DEM for error reports [SWS_TCPIP_00027],
  • TcpIp_MainFunction as a clock [SWS_TCPIP_00026].

Controller state machine: From TcpIp_Init to ONLINE

TcpIp_Init takes over an implementation-specific configuration of type TcpIp_ConfigType [SWS_TCPIP_00002][SWS_TCPIP_00067]. Afterwards, TcpIp maintains its own state per EthIf controller and stores the last request. It distinguishes OFFLINE, STARTUP, ONLINE, ONHOLD and SHUTDOWN [SWS_TCPIP_00083][SWS_TCPIP_00073]. If the stored request deviates from the active state, TcpIp initiates the necessary steps [SWS_TCPIP_00136]. Interpretation: After initialization, each controller is likely to be in TCPIP_STATE_OFFLINE, as the diagram suggests SWS TcpIp Fig. 7.2 p. 60.

TcpIp_RequestComMode operates asynchronously. It rejects requests of STARTUP or SHUTDOWN with E_NOT_OK [SWS_TCPIP_00089], SWS TcpIp p. 88. The transitions in detail:

  • OFFLINE → ONLINE requested: TcpIp enables the configured address assignments [SWS_TCPIP_00075][SWS_TCPIP_00071]. With the first assigned address, the controller transitions from STARTUP to ONLINE [SWS_TCPIP_00085].
  • ONHOLD: New transmission jobs are rejected, sockets and addresses are retained [SWS_TCPIP_00074]. TCPIP_IPADDR_STATE_ONHOLD is reported to the owners [SWS_TCPIP_00076]. The return to ONLINE reactivates the communication and reports ASSIGNED [SWS_TCPIP_00086].
  • OFFLINE from ONLINE/ONHOLD (or release of all addresses): TcpIp reports UNASSIGNED, deactivates the communication and closes the sockets of the controller [SWS_TCPIP_00077][SWS_TCPIP_00072]. Once the resources are released, OFFLINE follows from SHUTDOWN [SWS_TCPIP_00087].
  • OFFLINE from STARTUP: Ongoing assignments are aborted [SWS_TCPIP_00088], SWS TcpIp p. 60.

State diagram: Each EthIf controller goes through OFFLINE, STARTUP, ONLINE, ONHOLD and SHUTDOWN; each state entry is reported to EthSM. The initial transition from TcpIp_Init is an interpretation. Sources: [SWS_TCPIP_00083], [SWS_TCPIP_00075], [SWS_TCPIP_00085], [SWS_TCPIP_00076], [SWS_TCPIP_00077], [SWS_TCPIP_00087], SWS TcpIp Fig. 7.2 p. 60

Local address table and address assignment

TcpIp manages a table of local IP addresses according to the container TcpIpLocalAddr [SWS_TCPIP_00099]. A TcpIp_LocalAddrIdType identifier uniquely designates the address and EthIf controller in each case [SWS_TCPIP_00030], SWS TcpIp Fig. 10.24 p. 220. Changes of the assignment state are reported by <Up_LocalIpAddrAssignmentChg> [SWS_TCPIP_00082][SWS_TCPIP_00229]. The methods (static, DHCP, Link-Local, Link-Local with DoIP parameters, etc.) are defined by TcpIp_IpAddrAssignmentType [SWS_TCPIP_00065]. If a higher prioritized method yields an address, it replaces the previous one [SWS_TCPIP_00127], SWS TcpIp Fig. 10.25 p. 224.

Whether an assignment may be requested or released at runtime is determined by TcpIpAssignmentTrigger:

  • TCPIP_MANUAL: TcpIp_RequestIpAddrAssignment and TcpIp_ReleaseIpAddrAssignment switch the assignment to available and not available, respectively [SWS_TCPIP_00195][SWS_TCPIP_00196].
  • TCPIP_AUTOMATIC: Both services are rejected with E_NOT_OK [SWS_TCPIP_00198][SWS_TCPIP_00199], SWS TcpIp p. 91.

With type STATIC without static configuration, TcpIp takes over the passed values [SWS_TCPIP_00079]. TCPIP_IPADDR_ASSIGNMENT_ALL triggers all manual methods [SWS_TCPIP_00299]. Methods with TCPIP_STORE first use a valid address from the NvM block [SWS_TCPIP_00219]. TcpIp_ResetIpAssignment invalidates these stored addresses and can be disabled via configuration [SWS_TCPIP_00215][SWS_TCPIP_00216][SWS_TCPIP_00217]. R20-11 lists the service as "Synchronous/Asynchronous", the more recent document reference only as synchronous SWS TcpIp p. 92.

Activity diagram: The trigger decides on acceptance or rejection of an assignment request; type and TCPIP_STORE determine the source of the address. Sources: [SWS_TCPIP_00198], [SWS_TCPIP_00195], [SWS_TCPIP_00079], [SWS_TCPIP_00299], [SWS_TCPIP_00219], SWS TcpIp Fig. 10.25 p. 224

The DHCP server can be enabled at compile time [SWS_TCPIP_00200] and assigns addresses per TcpIpCtrl [SWS_TCPIP_00201]. With port-related configuration, it determines the switch port of the client via EthIf_GetPortMacAddr() [SWS_TCPIP_00218], SWS EthSwt Fig. 7.7 p. 38. DHCP options are read and written by the (DHCPv6) option services [SWS_TCPIP_00040][SWS_TCPIP_00020][SWS_TCPIP_00189][SWS_TCPIP_00190]. Address data is provided by TcpIp_GetIpAddr, TcpIp_GetPhysAddr and TcpIp_GetCtrlIdx [SWS_TCPIP_00032][SWS_TCPIP_00033][SWS_TCPIP_00141].

Sockets: Creating, binding, connecting, listening

Creation. A socket is created via TcpIp_<Up>GetSocket with address family and protocol [SWS_TCPIP_00018][SWS_TCPIP_00009][SWS_TCPIP_00010]. An invalid family is reported by the error detection as TCPIP_E_AFNOSUPPORT [SWS_TCPIP_00128]. All APIs pass addresses as a generic TcpIp_SockAddrType, which is cast to the IPv4 or IPv6 structure [SWS_TCPIP_00012][SWS_TCPIP_00013][SWS_TCPIP_00014].

Binding. TcpIp_Bind binds the socket to a local address and port [SWS_TCPIP_00015][SWS_TCPIP_00111]. TCPIP_LOCALADDRID_ANY and TCPIP_PORT_ANY serve as placeholders [SWS_TCPIP_00135][SWS_TCPIP_00134]. TcpIp takes an automatically chosen port from 49152 to 65535 SWS TcpIp p. 85. Bind fails if the same combination is already occupied or the address is not assigned [SWS_TCPIP_00146][SWS_TCPIP_00254].

Connecting and listening. As a client, TcpIp_TcpConnect asynchronously establishes a connection [SWS_TCPIP_00022][SWS_TCPIP_00112]; the success is reported by <Up_TcpConnected> [SWS_TCPIP_00227]. As a server, TcpIp_TcpListen puts the socket into the listen state [SWS_TCPIP_00023][SWS_TCPIP_00113]. For each incoming connection, TcpIp derives its own socket, up to MaxChannels SWS TcpIp p. 87. It offers this socket via <Up_TcpAccepted>; the owner can reject it with E_NOT_OK [SWS_TCPIP_00226], SWS SoAd p. 81. TcpIp accepts new connections only in ONLINE [SWS_TCPIP_00094].

Sequence diagram: The owner prepares a listen socket; after the handshake, TcpIp offers the derived socket for acceptance. The labeling of the frames as SYN/SYN-ACK/ACK is an interpretation. Sources: [SWS_TCPIP_00018], [SWS_TCPIP_00015], [SWS_TCPIP_00023], [SWS_TCPIP_00226], SWS TcpIp p. 107

Closing, events, parameters. TcpIp_Close regularly terminates TCP connections via termination handshake. With Abort = TRUE, it terminates them immediately via RST [SWS_TCPIP_00017][SWS_TCPIP_00109]. UDP sockets are released immediately [SWS_TCPIP_00110]. Reset, close, FIN and UDP close are reported by <Up_TcpIpEvent> [SWS_TCPIP_00144][SWS_TCPIP_00031][SWS_TCPIP_00224]. TcpIp_ChangeParameter adjusts socket parameters, such as receive window, Nagle, path MTU discovery or UDP checksum [SWS_TCPIP_00016][SWS_TCPIP_00126][SWS_TCPIP_00267][SWS_TCPIP_00279].

Data paths for TCP and UDP

Sending TCP. TcpIp_TcpTransmit is asynchronous [SWS_TCPIP_00050][SWS_TCPIP_00123]. The data source depends on DataPtr:

  • DataPtr points to a linear buffer: TcpIp uses this buffer.
  • DataPtr = NULL_PTR: TcpIp retrieves up to AvailableLength bytes via <Up_CopyTxData> [SWS_TCPIP_00124][SWS_TCPIP_00228]; with ForceRetrieve = TRUE exactly AvailableLength [SWS_TCPIP_00125].

Only after confirmation by the remote node does <Up_TxConfirmation> report the number of sent bytes [SWS_TCPIP_00225], SWS SoAd p. 86. Note on the diagrams: As of R24-11, LSduR is additionally located between TcpIp and EthIf. The R20-11 requirements do not know this module; therefore, the diagrams here show the direct EthIf access SWS TcpIp p. 109.

Sequence diagram: Data takeover in the call, transmission in the cycle of the MainFunction, confirmation only after the TCP-ACK of the remote node. Sources: [SWS_TCPIP_00050], [SWS_TCPIP_00124], [SWS_TCPIP_00125], [SWS_TCPIP_00131], [SWS_TCPIP_00225], SWS TcpIp p. 109

Sending UDP. TcpIp_UdpTransmit operates synchronously and immediately sends TotalLength bytes [SWS_TCPIP_00025][SWS_TCPIP_00120]. As with TCP, the data comes from a linear buffer or from <Up_CopyTxData> [SWS_TCPIP_00121].

Receiving. The assignment of an incoming packet runs in stages:

  1. Each IP datagram is assigned to an entry of the local address table [SWS_TCPIP_00169].
  2. UDP datagrams go to the matching sockets based on destination port and address [SWS_TCPIP_00170]; in case of broadcast and multicast to all matching ones [SWS_TCPIP_00171].
  3. TCP segments of existing connections must additionally fully match source and destination [SWS_TCPIP_00172][SWS_TCPIP_00173].

The data reach the owner via <Up_RxIndication> [SWS_TCPIP_00223]. For TCP, TcpIp_TcpReceived subsequently increases the receive window by the consumed bytes [SWS_TCPIP_00024][SWS_TCPIP_00115]. TcpIp reassembles fragmented datagrams [SWS_TCPIP_00054] and decouples reception and forwarding for this purpose SWS TcpIp p. 131.

Sequence diagram: Reception from EthIf to the owner; for TCP, the window release completes the process. Sources: [SWS_TCPIP_00029], [SWS_TCPIP_00169], [SWS_TCPIP_00054], [SWS_TCPIP_00223], [SWS_TCPIP_00115], SWS TcpIp p. 108

Address resolution and source address selection

ARP table. Its size is limited [SWS_TCPIP_00090]; unused entries expire after TcpIpArpTableEntryTimeout [SWS_TCPIP_00091]. TcpIp announces new addresses via gratuitous ARP [SWS_TCPIP_00093]. It suppresses repeated requests to the same destination for TcpIpArpRequestTimeout [SWS_TCPIP_00350]. ARP packets are processed in TcpIp_RxIndication or the next TcpIp_MainFunction [SWS_TCPIP_00351]. Every table change is reported by <Up_PhysAddrTableChg> [SWS_TCPIP_00142][SWS_TCPIP_00143]. In R20-11, TcpIp learns from every received IP packet [SWS_TCPIP_00092]; the more recent document location links this to TcpIpArpDefensiveProcessing SWS TcpIp p. 29. The neighbor cache is also limited; on overflow, the oldest entry yields [SWS_TCPIP_00263][SWS_TCPIP_00264].

Cache miss during transmission. If the link-layer address is missing, TcpIp starts the resolution. With an activated packet queue, it queues the packet and answers E_OK [SWS_TCPIP_00191][SWS_TCPIP_00193]. Without a queue, it rejects IPv4 requests with E_NOT_OK [SWS_TCPIP_00192]. An assignment can be queried specifically with TcpIp_GetRemotePhysAddr; as long as it is unknown, the service returns TCPIP_E_PHYS_ADDR_MISS [SWS_TCPIP_00137][SWS_TCPIP_00138][SWS_TCPIP_00066]. Entire caches are copied by TcpIp_GetArpCacheEntries and TcpIp_GetNdpCacheEntries [SWS_TCPIP_91002][SWS_TCPIP_91001][SWS_TCPIP_00272].

Activity diagram: A UDP request is sent immediately if the link-layer address is known, and queued or rejected if it is unknown. For IPv6 without a queue, the payload contains no requirement; this branch remains open. Sources: [SWS_TCPIP_00120], [SWS_TCPIP_00121], [SWS_TCPIP_00191], [SWS_TCPIP_00192], [SWS_TCPIP_00193], SWS TcpIp p. 110

Source address. Which sender address a packet receives depends on the binding of the socket SWS TcpIp Fig. 4 p. 20. For IPv6, TcpIp applies section 5 of IETF RFC 6724, restricted to the configured addresses [SWS_TCPIP_00182][SWS_TCPIP_00183]. For IPv4, the following applies:

Behavior in the event of an error

Development errors. Codes such as TCPIP_E_UNINIT, TCPIP_E_PARAM_POINTER, TCPIP_E_INV_ARG and TCPIP_E_ADDRINUSE are centrally defined [SWS_TCPIP_00042]. For example, LocalIpAddrId and option of the DHCP services [SWS_TCPIP_00233][SWS_TCPIP_00243][SWS_TCPIP_00238][SWS_TCPIP_00248] and the bind address [SWS_TCPIP_00147] are checked. In case of a domain mismatch in TcpIp_GetIpAddr and double binding, TcpIp rejects with E_NOT_OK even without error detection [SWS_TCPIP_00205][SWS_TCPIP_00206][SWS_TCPIP_00146].

Runtime errors. TcpIp reports them via Det_ReportRuntimeError [SWS_TCPIP_00255]:

  • TCPIP_E_TIMEDOUT on unanswered SYN, expired keep-alive or exhausted repetitions [SWS_TCPIP_00256],
  • TCPIP_E_CONNREFUSED and TCPIP_E_HOSTUNREACH on corresponding ICMP messages [SWS_TCPIP_00257][SWS_TCPIP_00258],
  • TCPIP_E_PACKETTOBIG on too large frames with set DF bit [SWS_TCPIP_00259],
  • TCPIP_E_DADCONFLICT on duplicate addresses, optionally supplemented by a callout [SWS_TCPIP_00282][SWS_TCPIP_00283][SWS_TCPIP_91005].

After the last TCP repetition, TcpIp starts the retransmission timer one last time and then closes the connection [SWS_TCPIP_00202]. The values TCPIP_E_TX_QUEUE_OVERRUN and TCPIP_E_TX_INTERNAL_PROCESSING_FAILED stem from the more recent version SWS TcpIp p. 65; R20-11 only knows 0x01 to 0x05.

Dropped packets and measurement data. TcpIp silently drops invalid packets. This concerns TCP segments to broadcast or multicast addresses [SWS_TCPIP_00174], IPv6 datagrams with invalid extension headers [SWS_TCPIP_00260] and segments with unapproved TCP options [SWS_TCPIP_00266]. If measurement is activated, TcpIp counts such drops [SWS_TCPIP_00296]; the counters do not overflow [SWS_TCPIP_00294]. TcpIp_GetAndResetMeasurementData reads and resets them [SWS_TCPIP_91006][SWS_TCPIP_00287][SWS_TCPIP_00292], SWS TcpIp p. 107. With IPsec, the security policy decides on forwarding or dropping [SWS_TCPIP_00359][SWS_TCPIP_00360]; security events go to IdsM upon request [SWS_TCPIP_00361]. Interpretation: Time-controlled tasks such as repetitions and table timeouts presumably run in the context of the cyclic TcpIp_MainFunction [SWS_TCPIP_00026].
