Role of Platform_Types.h: common type base of Classic basic software

The “platform” module consists of the header file Platform_Types.h. Through it, all standardized basic types and platform symbols are available, such as uint8 [SWS_Platform_00013], boolean [SWS_Platform_00026], and CPU_TYPE [SWS_Platform_00064]. The module contains no functions. It specifies which value ranges, bit widths, and encodings code on a platform may assume. The reason for this is the requirement that all basic software modules use only AUTOSAR data types. Native C types such as char, int, or long are prohibited because their size, signedness, and precision depend on the platform (RS_BSWGeneral p. 65).

Modules usually do not include the types directly. In the example of the requirement specification, Eep.h includes the file Std_Types.h, and this automatically includes Platform_Types.h as well (RS_BSWGeneral p. 65). Libraries such as Bfx explicitly trace their abbreviations u8, u16, s32, and boolean back to the platform types (SWS_BFXLibrary p. 8). The file itself must not be modified: any extension invalidates AUTOSAR conformance [SWS_Platform_00002].

Context diagram: Platform_Types.h is the common type base. BSW modules access it via Std_Types.h; libraries, service interfaces, and model blueprints reference it directly. Sources: RS_BSWGeneral p. 65, SWS_BFXLibrary p. 8, StandardizationTemplate p. 77, [SWS_Platform_00002]

Integer types: exact width or platform-optimized minimum range

The standard integer types have fixed bit widths and value ranges. uint8, uint16, uint32, and uint64 are unsigned with 8, 16, 32, and 64 bits ([SWS_Platform_00013], [SWS_Platform_00014], [SWS_Platform_00015], [SWS_Platform_00066]). sint8 through sint64 are the signed counterparts ([SWS_Platform_00016], [SWS_Platform_00017], [SWS_Platform_00018], [SWS_Platform_00067]). Their ranges, such as -128..+127 for sint8, result from the fact that AUTOSAR supports only two's complement arithmetic for compilers and target systems [SWS_Platform_00061].

The optimized types, by contrast, guarantee only a minimum range. uint8_least, uint16_least, and uint32_least have at least 8, 16, and 32 bits, respectively, and are derived from uint ([SWS_Platform_00020], [SWS_Platform_00021], [SWS_Platform_00022]). sint8_least through sint32_least are the signed variants and are derived from sint ([SWS_Platform_00023], [SWS_Platform_00024], [SWS_Platform_00025]). The specification mentions two typical use cases: loop counters with at most 124 iterations and switch arguments with 17 states. In both cases, uint8_least is to be selected (SWS_PlatformTypes p. 17).

The payload contains declarations such as typedef unsigned int uint8_least; or typedef unsigned long uint32;. Interpretation: These are mappings for a specific compiler. Only the required width or minimum width is normative ([SWS_Platform_00015], [SWS_Platform_00020]).

Floating-point and pointer types for values and data buffers

For floating-point values, the formats according to IEEE 754-2008 apply:

  • float32 follows the binary32 format, range ±3.4028235e+38 [SWS_Platform_00041].
  • float64 follows the binary64 format, range ±1.7976931348623157e+308 [SWS_Platform_00042].

For data buffers without a fixed type, there are two pointer types with a defined direction:

  • VoidPtr (void*) is intended for buffers that return data to the caller [SWS_Platform_91001] (SWS_PlatformTypes p. 27).
  • ConstVoidPtr (const void*) is intended for buffers that are passed to the callee [SWS_Platform_91002] (SWS_PlatformTypes p. 28).

Activity diagram: How the appropriate platform type is selected, from boolean via buffer pointers and floating-point to optimized or exact-width integers. Sources: [SWS_Platform_00026], [SWS_Platform_91001], [SWS_Platform_91002], [SWS_Platform_00041], [SWS_Platform_00042], SWS_PlatformTypes p. 17

boolean, TRUE, and FALSE: Representation and permitted expressions

In R20-11, boolean is implemented as an unsigned integer type, specifically with the shortest bit length that the platform supports natively, usually 8 bits [SWS_Platform_00027]. The stored declaration is typedef unsigned char boolean; [SWS_Platform_00026].

Deviation in later releases: The version for R24-11/R25-11 requires the C99 type _Bool and no longer specifies the object size (SWS_PlatformTypes p. 18). For R20-11, the requirement above applies.

Furthermore, boolean must be mapped to a type that pointers can point to. The efficient bit types of some hardware are therefore excluded [SWS_Platform_00060]. This is a prerequisite for interfaces such as CanNm_CheckRemoteSleepIndication that return a result via boolean* (SWS_CANNetworkManagement p. 68).

TRUE (1) and FALSE (0) are defined only if they do not already exist (#ifndef TRUE) [SWS_Platform_00056]. They may only be used together with boolean [SWS_Platform_00055]. The following rules apply to handling boolean variables [SWS_Platform_00034]:

  • Assignments are only allowed with TRUE, FALSE, comparisons, or logical expressions (&&, ||, !).
  • Arithmetic and bitwise operators such as +, ++, <<, ~, or & are prohibited.
  • Comparisons are restricted to == TRUE, == FALSE, != TRUE, != FALSE, if (var), and if (!var) (SWS_PlatformTypes p. 18).

Activity diagram: Check whether an assignment or a comparison with a boolean variable is permissible. Sources: [SWS_Platform_00034], [SWS_Platform_00055], SWS_PlatformTypes p. 18

Platform symbols CPU_TYPE, CPU_BIT_ORDER, and CPU_BYTE_ORDER

Platform_Types.h specifies three properties of the CPU for each platform, in each case as #define:

  • The register width via CPU_TYPE [SWS_Platform_00044]. Permissible are CPU_TYPE_8, CPU_TYPE_16, CPU_TYPE_32, and CPU_TYPE_64 ([SWS_Platform_00045], [SWS_Platform_00064]).
  • The bit order at register level via CPU_BIT_ORDER ([SWS_Platform_00043], [SWS_Platform_00038]).
  • The byte order in memory via CPU_BYTE_ORDER ([SWS_Platform_00046], [SWS_Platform_00039]).

The mapping to endianness is unambiguous. Big-endian bit order results in MSB_FIRST, little-endian bit order results in LSB_FIRST ([SWS_Platform_00048], [SWS_Platform_00049]). Big-endian byte order results in HIGH_BYTE_FIRST, little-endian byte order results in LOW_BYTE_FIRST ([SWS_Platform_00050], [SWS_Platform_00051]).

The specification warns against confusing bit numbering and significance. In Motorola architectures with big-endian bit order, Bit0 designates the most significant bit, whereas in all others it designates the least significant. In the accumulator, by contrast, the MSB is always on the far left (SWS_PlatformTypes p. 15).

Activity diagram: Procedure for determining the three platform symbols for a target platform without extending the file. Sources: [SWS_Platform_00045], [SWS_Platform_00048], [SWS_Platform_00049], [SWS_Platform_00050], [SWS_Platform_00051], [SWS_Platform_00002]

Regarding byte order, the specification shows a 16-bit value. Its most significant byte is called Byte1, the least significant Byte0. With HIGH_BYTE_FIRST, Byte1 is located at address n and Byte0 at n+1; with LOW_BYTE_FIRST, it is the reverse (SWS_PlatformTypes p. 16). This naming is not unambiguous and may differ in manufacturer documentation (SWS_PlatformTypes p. 16). Byte order is practically important where data is converted between bus and processor representations. For example, AUTOSAR COM must support endianness conversion for uint16 through float64 (evidence from R25-11: RS_COM p. 14).

Activity diagram: Memory storage of a uint16 value depending on CPU_BYTE_ORDER, based on Figure 7.2/7.3 of the specification. Sources: SWS_PlatformTypes p. 16, [SWS_Platform_00039]

Platform types in service interfaces and models

Other specifications base their signatures on these types. Two examples from R24-11/R25-11 show the direction rule for buffer pointers ([SWS_Platform_91001], [SWS_Platform_91002]):

  • In KeyM_ServiceCertificateByCertId, the Key Manager passes the request data as ConstVoidPtr with a length of type uint32. It receives results via a VoidPtr buffer whose available size is indicated by ResponseDataLength (INOUT) (SWS_KeyManager p. 111).
  • The CSM operation RandomSeed passes the seed in as ConstVoidPtr (SWS_CryptoServiceManager p. 124).

Sequence diagram: The caller provides request data as read-only via ConstVoidPtr and receives data back via a VoidPtr buffer. The return value reports whether the service accepted the request. Sources: SWS_KeyManager p. 111, SWS_KeyManager p. 97, [SWS_Platform_91001], [SWS_Platform_91002]

The types are also firmly anchored in the model. The element /AUTOSAR_Platform/ImplementationDatatypes/uint8 is derived from the blueprint /AUTOSAR/Platform/ImplementationDatatypes_Blueprint/uint8. This allows software suppliers to find it via a predictable path (StandardizationTemplate p. 77). Record layouts reference base types such as /AUTOSAR/Platform/BaseTypes_Blueprint/sint16 (GeneralBlueprintsSupplement p. 47). Libraries such as Crc use uint8, uint32, and boolean directly in their APIs (SWS_CRCLibrary p. 41).

Behavior in the event of an error

Platform_Types.h only provides types and symbols that are available via this file ([SWS_Platform_00013], [SWS_Platform_00038]). Therefore, runtime error behavior with return values or error messages should not exist. Instead, errors arise during integration and usage:

  • Extended or supplemented file: Any extension voids AUTOSAR conformity [SWS_Platform_00002].
  • Duplicate definitions: If the compiler already provides the symbols, redefinitions are to be avoided by means of a conditional check ([SWS_Platform_00054], [SWS_Platform_00056]).
  • Incorrect platform symbols: A CPU_BYTE_ORDER or CPU_BIT_ORDER that does not match the hardware violates [SWS_Platform_00048] through [SWS_Platform_00051]. Interpretation: Code branching on these symbols would then assemble multibyte values incorrectly (cf. SWS_PlatformTypes p. 16).
  • Bit type for boolean: Without pointer capability, no parameters can be passed via pointers [SWS_Platform_00060].
  • Impermissible expressions such as var++ or var = a & b violate [SWS_Platform_00034].
  • AUTOSAR does not support representations of negative numbers other than two's complement [SWS_Platform_00061].
