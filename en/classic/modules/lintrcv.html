Role of the LIN Transceiver Driver between LinIf and Transceiver Hardware

The LIN Transceiver Driver (LinTrcv) encapsulates the physical LIN transceivers of an ECU. It sets and reads their operating mode on a channel-by-channel basis and provides wakeup information. Its interface consists of seven synchronous functions: LinTrcv_Init [SWS_LinTrcv_00001], LinTrcv_SetOpMode [SWS_LinTrcv_00002], LinTrcv_GetOpMode [SWS_LinTrcv_00005], LinTrcv_GetBusWuReason [SWS_LinTrcv_00007], LinTrcv_GetVersionInfo [SWS_LinTrcv_00008], LinTrcv_SetWakeupMode [SWS_LinTrcv_00009], and LinTrcv_CheckWakeup [SWS_LinTrcv_00012]. The channel-related functions address the network via a uint8 parameter (LinNetwork or LINNetwork, respectively).

The document passages (releases from R23-11 onward) show the LIN Interface as user. LinIf_SetTrcvMode, LinIf_GetTrcvMode, LinIf_GetTrcvWakeupReason, and LinIf_SetTrcvWakeupMode each call the corresponding LinTrcv function (SWS LinIf p. 90, SWS LinIf p. 91, SWS LinIf p. 92, SWS LinIf p. 93). Depending on WakeupSource, LinIf_CheckWakeup branches to Lin_CheckWakeup or LinTrcv_CheckWakeup (SWS LinIf p. 112). The driver does not offer its own callback notifications (SWS LinTrcv p. 32). Instead, it reports detected wakeups via LinIf_WakeupConfirmation [SWS_LinTrcv_91002].

Downward, the driver accesses the hardware via Dio and Spi. It imports types from Dio, Spi, Icu, EcuM, and Std_Types [SWS_LinTrcv_91001]. The required services include, among others, Det_ReportError, the Dio read and write services, as well as EcuM_SetWakeupEvent [SWS_LinTrcv_91003]. It implements wait times during state changes with Tm_BusyWait1us16bit [SWS_LinTrcv_00171]. It switches the wakeup notification via Icu_EnableNotification and Icu_DisableNotification (SWS LinTrcv p. 17).

Context diagram: LinTrcv lies between LinIf and the drivers Dio, Spi, and Icu, and uses DET, Tm, and EcuM as services. Sources: [SWS_LinTrcv_91001], [SWS_LinTrcv_91002], [SWS_LinTrcv_91003], [SWS_LinTrcv_00171], SWS LinTrcv p. 17

Initialization and Operating Modes NORMAL, STANDBY, and SLEEP

LinTrcv_TrcvModeType [SWS_LinTrcv_00168] describes the operating modes with the values LINTRCV_TRCV_MODE_NORMAL, LINTRCV_TRCV_MODE_STANDBY, and LINTRCV_TRCV_MODE_SLEEP. The type is available via Lin_GeneralTypes.h (SWS LinTrcv p. 22). These are software states. The hardware may have more transitions, and which hardware states a software state covers is determined by the implementation. In doing so, it must guarantee all described functionality (SWS LinTrcv p. 16).

The operating modes diagram divides the powered-on state POWER_ON into NOT_ACTIVE and ACTIVE; the transition is performed with LinTrcv_Init (SWS LinTrcv p. 15). Init receives a pointer to the selected configuration set [SWS_LinTrcv_00001]. Its structure LinTrcv_ConfigType is implementation-specific [SWS_LinTrcv_00172]. Since version 4.3.1, the initial state is restricted to LINTRCV_TRCV_MODE_SLEEP (SWS LinTrcv p. 1). Transitions to STANDBY are optional in the diagram. STANDBY can also be a purely internal state for hardware transitions (SWS LinTrcv p. 15).

State diagram: After LinTrcv_Init, the channel is in SLEEP; LinTrcv_SetOpMode switches between the modes, STANDBY is optional (transition assignment reconstructed as interpretation). Sources: SWS LinTrcv p. 15, SWS LinTrcv p. 25, SWS LinTrcv p. 1

According to [SWS_LinTrcv_91002], a LIN transceiver driver also reports the wakeup source to LinIf_WakeupConfirmation after being powered on by the bus. Interpretation: This report likely occurs in connection with LinTrcv_Init, because according to the diagram, Init is the first call after power-on (SWS LinTrcv p. 15).

Sequence diagram: LinTrcv_Init transitions the channel from NOT_ACTIVE to SLEEP; a power-on by the bus is reported to LinIf (timing as interpretation). Sources: [SWS_LinTrcv_00001], [SWS_LinTrcv_91002], SWS LinTrcv p. 1

Mode Switch and Mode Query via the LIN Interface

LinTrcv_SetOpMode (Service ID 0x01, non-reentrant) returns E_OK if the transceiver has switched to the requested mode. E_NOT_OK follows if the switch was not accepted, failed, or the parameter is outside the valid range [SWS_LinTrcv_00002]. The function switches the internal state of the channel to the value of OpMode (SWS LinTrcv p. 25). LinIf_SetTrcvMode is applicable to all transceivers with all values, regardless of hardware support. It returns the result of LinTrcv_SetOpMode unchanged (SWS LinIf p. 90).

LinIf addresses with NetworkHandleType Channel, whereas LinTrcv addresses with uint8 LinNetwork (SWS LinIf p. 90, [SWS_LinTrcv_00002]). The payload does not describe how both identifiers are mapped to each other. LinTrcv_GetOpMode (0x02, reentrant) returns the current software state of the driver in OpMode [SWS_LinTrcv_00005], SWS LinTrcv p. 26. For each channel, the configuration defines hardware access as DIO or SPI access (SWS LinTrcv p. 44).

Sequence diagram: A mode change runs synchronously from LinIf via LinTrcv to the hardware; Tm_BusyWait1us16bit bridges wait times, and LinIf returns the result unchanged. Sources: [SWS_LinTrcv_00002], [SWS_LinTrcv_91003], [SWS_LinTrcv_00171], SWS LinIf p. 90

Wakeup Detection: Internal and External Wakeup Paths

The driver distinguishes two wake-up types (SWS LinTrcv p. 17). An internal wake-up is triggered by an upper layer, such as via LinTrcv_Init or LinTrcv_SetOpMode. The driver itself detects an external wake-up and passes it upwards via LinTrcv_CheckWakeup; LinIf calls this function. The driver does not support wake-ups via a dedicated ISR, but only via the ICU. It releases the ICU channels when the transceiver switches to standby mode.

LinIf_CheckWakeup is called after EcuM has been notified of a wake-up on a LIN channel (SWS LinIf p. 112). LinTrcv_CheckWakeup (0x07, reentrant) evaluates the wake-up on the addressed network, such as a dominant bus state or a negative edge on the wake-up pin (SWS LinTrcv p. 30). After successful detection, the driver reports the wake-up source to LinIf_WakeupConfirmation [SWS_LinTrcv_91002]. EcuM_SetWakeupEvent is additionally listed as a required interface [SWS_LinTrcv_91003].

For R20-11: LinTrcv_CheckWakeup returns E_OK if a wake-up was detected, and E_NOT_OK if none was detected [SWS_LinTrcv_00012]. The document passage from R24-11/R25-11, by contrast, interprets the return values as “call accepted/not accepted” (SWS LinTrcv p. 30). According to the change history, they were not revised until R22-11 (SWS LinTrcv p. 1). The older diagram for bus wake-up mentions interfaces such as LinIf_WakeUpTrcvNotification, which do not appear in the R20-11 requirements (SWS LinIf p. 81). LinIf_WakeupConfirmation [SWS_LinTrcv_91002] is authoritative.

Sequence diagram: An external wake-up reaches LinIf_CheckWakeup via ICU and EcuM; LinTrcv checks the network and confirms a detected wake-up via LinIf_WakeupConfirmation. Sources: [SWS_LinTrcv_00012], [SWS_LinTrcv_91002], SWS LinIf p. 112, SWS LinTrcv p. 17

Control wake-up notification and evaluate wake-up reason

LinTrcv_SetWakeupMode (0x05, non-reentrant) enables, disables, or clears the notification for wake-up events on the addressed network [SWS_LinTrcv_00009]. For this purpose, LinTrcv_TrcvWakeupModeType [SWS_LinTrcv_00169] provides LINTRCV_WUMODE_ENABLE, LINTRCV_WUMODE_DISABLE, and LINTRCV_WUMODE_CLEAR; CLEAR clears a stored wake-up event. If a stored event is already present upon activation, the notification occurs during the call or immediately afterwards (SWS LinTrcv p. 31). LinIf reaches the function via LinIf_SetTrcvWakeupMode (SWS LinIf p. 93).

Activity diagram: LinTrcv_SetWakeupMode branches according to the requested mode; upon activation, an already stored event is reported immediately. Sources: [SWS_LinTrcv_00009], [SWS_LinTrcv_00169], SWS LinTrcv p. 31

LinTrcv_GetBusWuReason (0x03, reentrant) returns the wake-up reason detected by the transceiver in Reason [SWS_LinTrcv_00007]. How finely the reasons can be distinguished depends heavily on the hardware (SWS LinTrcv p. 28). LinTrcv_TrcvWakeupReasonType [SWS_LinTrcv_00170] includes LINTRCV_WU_ERROR, LINTRCV_WU_NOT_SUPPORTED, LINTRCV_WU_BY_BUS, and LINTRCV_WU_BY_PIN, among others; further values are truncated in the payload (SWS LinTrcv p. 30). LinIf provides the reason via LinIf_GetTrcvWakeupReason (SWS LinIf p. 92).

Configuration: channels, wake-up support, and partitions

The configuration diagrams (from R23-11 onwards) show the container LinTrcvGeneral with LinTrcvDevErrorDetect and LinTrcvVersionInfoApi (each default false) as well as LinTrcvWakeUpSupport (SWS LinTrcv p. 36). There is at least one LinTrcvChannel container. Each carries LinTrcvChannelUsed (default true), LinTrcvWakeupByBusUsed (default false), LinTrcvChannelId (0..255), and a reference to an EcuM wake-up source (SWS LinTrcv p. 44). LinTrcvWakeUpSupport selects the wake-up type. LinTrcvWakeupByBusUsed toggles wake-up support per channel (SWS LinTrcv p. 17).

Two rules apply to multi-core systems. The partitions referenced via LinTrcvChannelEcucPartitionRef must be a subset of those referenced via LinTrcvEcucPartitionRef [SWS_LinTrcv_00176]. In addition, LinTrcvChannel and LinChannel of a communication channel must reference the same partition [SWS_LinTrcv_00177]. Partition assignments that the implementation does not support must be rejected [SWS_LinTrcv_00174]. According to the change history, multi-core distribution was added with R19-11 (SWS LinTrcv p. 1).

Context diagram (configuration structure): General switches are located in LinTrcvGeneral, channel-specific parameters and partition references in LinTrcvChannel. Sources: SWS LinTrcv p. 36, SWS LinTrcv p. 44, [SWS_LinTrcv_00176], [SWS_LinTrcv_00177]

Behavior in the event of an error

The driver reports runtime errors via return values. In R20-11, LinTrcv_GetOpMode and LinTrcv_GetBusWuReason return E_NOT_OK in case of development errors or if the mode or wake-up reason could not be determined [SWS_LinTrcv_00005], [SWS_LinTrcv_00007]. E_NOT_OK is also provided in the event of missing or faulty communication with the transceiver (SWS LinTrcv p. 26, SWS LinTrcv p. 28). If the wake-up reason cannot be determined due to an error, LINTRCV_WU_ERROR is available [SWS_LinTrcv_00170]. In R20-11, an E_NOT_OK from LinTrcv_CheckWakeup, by contrast, only means “no wake-up detected” [SWS_LinTrcv_00012].

The driver reports development errors to DET via Det_ReportError [SWS_LinTrcv_91003]. Detection is enabled by LinTrcvDevErrorDetect (SWS LinTrcv p. 36). The document passages mention three error codes: LINTRCV_E_UNINIT for calls prior to initialization, LINTRCV_E_INVALID_LIN_NETWORK for invalid network numbers, and LINTRCV_E_PARAM_POINTER for versioninfo == NULL (SWS LinTrcv p. 26, SWS LinTrcv p. 30, SWS LinTrcv p. 29). These passages originate from R23-11 and later. In R20-11, the error classification was cleaned up, and in R21-11, the error codes (SWS LinTrcv p. 1). Identifiers and scope may therefore differ in R20-11.

Activity diagram: LinTrcv_GetOpMode reports a missing init to DET and returns E_NOT_OK, likewise in case of disrupted transceiver communication; the order of the checks is exemplary, further checks truncated in the payload are omitted. Sources: [SWS_LinTrcv_00005], SWS LinTrcv p. 26, [SWS_LinTrcv_91003]

Incorrect partition assignments lead to the rejection of the configuration [SWS_LinTrcv_00174]. If a mode change initiated via LinIf fails, the previous state remains unchanged according to the LinIf specification (SWS LinIf p. 90).

The function LinTrcv_SetWakeupMode ([SWS_LinTrcv_00009]) enables, disables, or clears the notification for wake-up events on the specified network channel. The interface is provided via the header file Lin_Trcv.h.

<h4>Role of the LIN Transceiver Driver between LinIf and Transceiver Hardware</h4>
<p>The LIN Transceiver Driver (<code>LinTrcv</code>) encapsulates the physical LIN transceivers of an ECU. It sets and reads their operating mode on a channel-by-channel basis and provides wakeup information. Its interface consists of seven synchronous functions: <code>LinTrcv_Init</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00001" href="../../spec/record.html?id=SWS_LinTrcv_00001">[SWS_LinTrcv_00001]</a>, <code>LinTrcv_SetOpMode</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00002" href="../../spec/record.html?id=SWS_LinTrcv_00002">[SWS_LinTrcv_00002]</a>, <code>LinTrcv_GetOpMode</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00005" href="../../spec/record.html?id=SWS_LinTrcv_00005">[SWS_LinTrcv_00005]</a>, <code>LinTrcv_GetBusWuReason</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00007" href="../../spec/record.html?id=SWS_LinTrcv_00007">[SWS_LinTrcv_00007]</a>, <code>LinTrcv_GetVersionInfo</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00008" href="../../spec/record.html?id=SWS_LinTrcv_00008">[SWS_LinTrcv_00008]</a>, <code>LinTrcv_SetWakeupMode</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00009" href="../../spec/record.html?id=SWS_LinTrcv_00009">[SWS_LinTrcv_00009]</a>, and <code>LinTrcv_CheckWakeup</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00012" href="../../spec/record.html?id=SWS_LinTrcv_00012">[SWS_LinTrcv_00012]</a>. The channel-related functions address the network via a <code>uint8</code> parameter (<code>LinNetwork</code> or <code>LINNetwork</code>, respectively).</p>
<p>The document passages (releases from R23-11 onward) show the LIN Interface as user. <code>LinIf_SetTrcvMode</code>, <code>LinIf_GetTrcvMode</code>, <code>LinIf_GetTrcvWakeupReason</code>, and <code>LinIf_SetTrcvWakeupMode</code> each call the corresponding LinTrcv function (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode">SWS LinIf p. 90</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_8_LinIf_GetTrcvMode.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_8_LinIf_GetTrcvMode">SWS LinIf p. 91</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_9_LinIf_GetTrcvWakeupReason.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_9_LinIf_GetTrcvWakeupReason">SWS LinIf p. 92</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_10_LinIf_SetTrcvWakeupMode.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_10_LinIf_SetTrcvWakeupMode">SWS LinIf p. 93</a>). Depending on <code>WakeupSource</code>, <code>LinIf_CheckWakeup</code> branches to <code>Lin_CheckWakeup</code> or <code>LinTrcv_CheckWakeup</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_20_LinIf_CheckWakeup.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_20_LinIf_CheckWakeup">SWS LinIf p. 112</a>). The driver does not offer its own callback notifications (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_4_Callback_notifications.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_4_Callback_notifications">SWS LinTrcv p. 32</a>). <h4>Initialization and Operating Modes NORMAL, STANDBY, and SLEEP</h4>
<p><code>LinTrcv_TrcvModeType</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00168" href="../../spec/record.html?id=SWS_LinTrcv_00168">[SWS_LinTrcv_00168]</a> describes the operating modes with the values <code>LINTRCV_TRCV_MODE_NORMAL</code>, <code>LINTRCV_TRCV_MODE_STANDBY</code>, and <code>LINTRCV_TRCV_MODE_SLEEP</code>. The type is available via <code>Lin_GeneralTypes.h</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_2_2_LinTrcv_TrcvModeType.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_2_2_LinTrcv_TrcvModeType">SWS LinTrcv p. 22</a>). These are software states. The hardware may have more transitions, and which hardware states a software state covers is determined by the implementation. In doing so, it must guarantee all described functionality (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_7_2_LIN_transceiver_hardware_operation_modes.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_7_2_LIN_transceiver_hardware_operation_modes">SWS LinTrcv p. 16</a>).</p>
<p>The operating modes diagram divides the powered-on state <code>POWER_ON</code> into <code>NOT_ACTIVE</code> and <code>ACTIVE</code>; the transition is performed with <code>LinTrcv_Init</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-56c57f141c18b36f.html" data-snip="FIG-56c57f141c18b36f">SWS LinTrcv p. 15</a>). Init receives a pointer to the selected configuration set <a class="spec-record-ref" data-req="SWS_LinTrcv_00001" href="../../spec/record.html?id=SWS_LinTrcv_00001">[SWS_LinTrcv_00001]</a>. Its structure <code>LinTrcv_ConfigType</code> is implementation-specific <a class="spec-record-ref" data-req="SWS_LinTrcv_00172" href="../../spec/record.html?id=SWS_LinTrcv_00172">[SWS_LinTrcv_00172]</a>. Since version 4.3.1, the initial state is restricted to <code>LINTRCV_TRCV_MODE_SLEEP</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER">SWS LinTrcv p. 1</a>). Transitions to STANDBY are optional in the diagram. STANDBY can also be a purely internal state for hardware transitions (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_FIGURE_Figure_7_1_LINTRANSCEIVERDRIVER.html" data-snip="SNIP_CLASSIC_LIN_FIGURE_Figure_7_1_LINTRANSCEIVERDRIVER">SWS LinTrcv p. 15</a>).</p>

<p><code>LinTrcv_SetOpMode</code> (Service ID 0x01, non-reentrant) returns <code>E_OK</code> if the transceiver has switched to the requested mode. <code>E_NOT_OK</code> follows if the switch was not accepted, failed, or the parameter is outside the valid range <a class="spec-record-ref" data-req="SWS_LinTrcv_00002" href="../../spec/record.html?id=SWS_LinTrcv_00002">[SWS_LinTrcv_00002]</a>. The function switches the internal state of the channel to the value of <code>OpMode</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_2_LinTrcv_SetOpMode.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_2_LinTrcv_SetOpMode">SWS LinTrcv p. 25</a>). <code>LinIf_SetTrcvMode</code> is applicable to all transceivers with all values, regardless of hardware support. It returns the result of <code>LinTrcv_SetOpMode</code> unchanged (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode">SWS LinIf p. 90</a>).</p>
<p>LinIf addresses with <code>NetworkHandleType Channel</code>, whereas LinTrcv addresses with <code>uint8 LinNetwork</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_7_LinIf_SetTrcvMode">SWS LinIf p. 90</a>, <a class="spec-record-ref" data-req="SWS_LinTrcv_00002" href="../../spec/record.html?id=SWS_LinTrcv_00002">[SWS_LinTrcv_00002]</a>). The payload does not describe how both identifiers are mapped to each other. <code>LinTrcv_GetOpMode</code> (0x02, reentrant) returns the current software state of the driver in <code>OpMode</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00005" href="../../spec/record.html?id=SWS_LinTrcv_00005">[SWS_LinTrcv_00005]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode">SWS LinTrcv p. 26</a>. <h4>Wakeup Detection: Internal and External Wakeup Paths</h4>
<p>The driver distinguishes two wake-up types (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_7_4_LIN_transceiver_wakeup_modes.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_7_4_LIN_transceiver_wakeup_modes">SWS LinTrcv p. 17</a>). An internal wake-up is triggered by an upper layer, such as via <code>LinTrcv_Init</code> or <code>LinTrcv_SetOpMode</code>. The driver itself detects an external wake-up and passes it upwards via <code>LinTrcv_CheckWakeup</code>; LinIf calls this function. The driver does not support wake-ups via a dedicated ISR, but only via the ICU. It releases the ICU channels when the transceiver switches to standby mode.</p>
<p><code>LinIf_CheckWakeup</code> is called after EcuM has been notified of a wake-up on a LIN channel (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_20_LinIf_CheckWakeup.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_20_LinIf_CheckWakeup">SWS LinIf p. 112</a>). <code>LinTrcv_CheckWakeup</code> (0x07, reentrant) evaluates the wake-up on the addressed network, such as a dominant bus state or a negative edge on the wake-up pin (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup">SWS LinTrcv p. 30</a>). After successful detection, the driver reports the wake-up source to <code>LinIf_WakeupConfirmation</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_91002" href="../../spec/record.html?id=SWS_LinTrcv_91002">[SWS_LinTrcv_91002]</a>. <code>EcuM_SetWakeupEvent</code> is additionally listed as a required interface <a class="spec-record-ref" data-req="SWS_LinTrcv_91003" href="../../spec/record.html?id=SWS_LinTrcv_91003">[SWS_LinTrcv_91003]</a>.</p>
<p>For R20-11: <code>LinTrcv_CheckWakeup</code> returns <code>E_OK</code> if a wake-up was detected, and <code>E_NOT_OK</code> if none was detected <a class="spec-record-ref" data-req="SWS_LinTrcv_00012" href="../../spec/record.html?id=SWS_LinTrcv_00012">[SWS_LinTrcv_00012]</a>. The document passage from R24-11/R25-11, by contrast, interprets the return values as “call accepted/not accepted” (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup">SWS LinTrcv p. 30</a>). According to the change history, they were not revised until R22-11 (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER">SWS LinTrcv p. 1</a>). The older diagram for bus wake-up mentions interfaces such as <code>LinIf_WakeUpTrcvNotification</code>, which do not appear in the R20-11 requirements (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-d7a39543ed3424c7.html" data-snip="FIG-d7a39543ed3424c7">SWS LinIf p. 81</a>). <code>LinIf_WakeupConfirmation</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_91002" href="../../spec/record.html?id=SWS_LinTrcv_91002">[SWS_LinTrcv_91002]</a> is authoritative.</p>

<h4>Control wake-up notification and evaluate wake-up reason</h4>
<p><code>LinTrcv_SetWakeupMode</code> (0x05, non-reentrant) enables, disables, or clears the notification for wake-up events on the addressed network <a class="spec-record-ref" data-req="SWS_LinTrcv_00009" href="../../spec/record.html?id=SWS_LinTrcv_00009">[SWS_LinTrcv_00009]</a>. <h4>Configuration: channels, wake-up support, and partitions</h4>
<p>The configuration diagrams (from R23-11 onwards) show the container <code>LinTrcvGeneral</code> with <code>LinTrcvDevErrorDetect</code> and <code>LinTrcvVersionInfoApi</code> (each default false) as well as <code>LinTrcvWakeUpSupport</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-3e493c6090c47d6f.html" data-snip="FIG-3e493c6090c47d6f">SWS LinTrcv p. 36</a>). There is at least one <code>LinTrcvChannel</code> container. Each carries <code>LinTrcvChannelUsed</code> (default true), <code>LinTrcvWakeupByBusUsed</code> (default false), <code>LinTrcvChannelId</code> (0..255), and a reference to an EcuM wake-up source (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c77cf69a4bd6400e.html" data-snip="FIG-c77cf69a4bd6400e">SWS LinTrcv p. 44</a>). <code>LinTrcvWakeUpSupport</code> selects the wake-up type. <code>LinTrcvWakeupByBusUsed</code> toggles wake-up support per channel (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_7_4_LIN_transceiver_wakeup_modes.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_7_4_LIN_transceiver_wakeup_modes">SWS LinTrcv p. 17</a>).</p>
<p>Two rules apply to multi-core systems. The partitions referenced via <code>LinTrcvChannelEcucPartitionRef</code> must be a subset of those referenced via <code>LinTrcvEcucPartitionRef</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_00176" href="../../spec/record.html?id=SWS_LinTrcv_00176">[SWS_LinTrcv_00176]</a>. According to the change history, multi-core distribution was added with R19-11 (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER">SWS LinTrcv p. 1</a>).</p>

<h4>Behavior in the event of an error</h4>
<p>The driver reports runtime errors via return values. In R20-11, <code>LinTrcv_GetOpMode</code> and <code>LinTrcv_GetBusWuReason</code> return <code>E_NOT_OK</code> in case of development errors or if the mode or wake-up reason could not be determined <a class="spec-record-ref" data-req="SWS_LinTrcv_00005" href="../../spec/record.html?id=SWS_LinTrcv_00005">[SWS_LinTrcv_00005]</a>, <a class="spec-record-ref" data-req="SWS_LinTrcv_00007" href="../../spec/record.html?id=SWS_LinTrcv_00007">[SWS_LinTrcv_00007]</a>. <code>E_NOT_OK</code> is also provided in the event of missing or faulty communication with the transceiver (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode">SWS LinTrcv p. 26</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_4_LinTrcv_GetBusWuReason.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_4_LinTrcv_GetBusWuReason">SWS LinTrcv p. 28</a>). If the wake-up reason cannot be determined due to an error, <code>LINTRCV_WU_ERROR</code> is available <a class="spec-record-ref" data-req="SWS_LinTrcv_00170" href="../../spec/record.html?id=SWS_LinTrcv_00170">[SWS_LinTrcv_00170]</a>. In R20-11, an <code>E_NOT_OK</code> from <code>LinTrcv_CheckWakeup</code>, by contrast, only means “no wake-up detected” <a class="spec-record-ref" data-req="SWS_LinTrcv_00012" href="../../spec/record.html?id=SWS_LinTrcv_00012">[SWS_LinTrcv_00012]</a>.</p>
<p>The driver reports development errors to DET via <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_LinTrcv_91003" href="../../spec/record.html?id=SWS_LinTrcv_91003">[SWS_LinTrcv_91003]</a>. Detection is enabled by <code>LinTrcvDevErrorDetect</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-3e493c6090c47d6f.html" data-snip="FIG-3e493c6090c47d6f">SWS LinTrcv p. 36</a>). The document passages mention three error codes: <code>LINTRCV_E_UNINIT</code> for calls prior to initialization, <code>LINTRCV_E_INVALID_LIN_NETWORK</code> for invalid network numbers, and <code>LINTRCV_E_PARAM_POINTER</code> for <code>versioninfo == NULL</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_3_LinTrcv_GetOpMode">SWS LinTrcv p. 26</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_6_LinTrcv_CheckWakeup">SWS LinTrcv p. 30</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_8_3_5_LinTrcv_GetVersionInfo.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_8_3_5_LinTrcv_GetVersionInfo">SWS LinTrcv p. 29</a>). These passages originate from R23-11 and later. In R20-11, the error classification was cleaned up, and in R21-11, the error codes (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER.html" data-snip="SNIP_CLASSIC_LINTRCV_SECTION_General_Overview_LINTRANSCEIVERDRIVER">SWS LinTrcv p. 1</a>). Identifiers and scope may therefore differ in R20-11.</p>
