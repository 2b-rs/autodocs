Role of the LIN Transceiver Driver between LinIf and Transceiver Hardware

The LIN Transceiver Driver (LinTrcv) encapsulates the physical LIN transceivers of an ECU. It sets and reads their operating mode on a channel-by-channel basis and provides wakeup information. Its interface consists of seven synchronous functions: LinTrcv_Init [SWS_LinTrcv_00001], LinTrcv_SetOpMode [SWS_LinTrcv_00002], LinTrcv_GetOpMode [SWS_LinTrcv_00005], LinTrcv_GetBusWuReason [SWS_LinTrcv_00007], LinTrcv_GetVersionInfo [SWS_LinTrcv_00008], LinTrcv_SetWakeupMode [SWS_LinTrcv_00009], and LinTrcv_CheckWakeup [SWS_LinTrcv_00012]. The channel-related functions address the network via a uint8 parameter (LinNetwork or LINNetwork, respectively).

The document passages (releases from R23-11 onward) show the LIN Interface as user. LinIf_SetTrcvMode, LinIf_GetTrcvMode, LinIf_GetTrcvWakeupReason, and LinIf_SetTrcvWakeupMode each call the corresponding LinTrcv function (SWS LinIf p. 90, SWS LinIf p. 91, SWS LinIf p. 92, SWS LinIf p. 93). Depending on WakeupSource, LinIf_CheckWakeup branches to Lin_CheckWakeup or LinTrcv_CheckWakeup (SWS LinIf p. 112). The driver does not offer its own callback notifications (SWS LinTrcv p. 32). Instead, it reports detected wakeups via LinIf_WakeupConfirmation [SWS_LinTrcv_91002].

Downward, the driver accesses the hardware via Dio and Spi. It imports types from Dio, Spi, Icu, EcuM, and Std_Types [SWS_LinTrcv_91001]. The required services include, among others, Det_ReportError, the Dio read and write services, as well as EcuM_SetWakeupEvent [SWS_LinTrcv_91003]. It implements wait times during state changes with Tm_BusyWait1us16bit [SWS_LinTrcv_00171]. It switches the wakeup notification via Icu_EnableNotification and Icu_DisableNotification (SWS LinTrcv p. 17).

Context diagram: LinTrcv lies between LinIf and the drivers Dio, Spi, and Icu, and uses DET, Tm, and EcuM as services. Sources: [SWS_LinTrcv_91001], [SWS_LinTrcv_91002], [SWS_LinTrcv_91003], [SWS_LinTrcv_00171], SWS LinTrcv p. 17

Initialization and Operating Modes NORMAL, STANDBY, and SLEEP

LinTrcv_TrcvModeType [SWS_LinTrcv_00168] describes the operating modes with the values LINTRCV_TRCV_MODE_NORMAL, LINTRCV_TRCV_MODE_STANDBY, and LINTRCV_TRCV_MODE_SLEEP. The type is available via Lin_GeneralTypes.h (SWS LinTrcv p. 22). These are software states. The hardware may have more transitions, and which hardware states a software state covers is determined by the implementation. In doing so, it must guarantee all described functionality (SWS LinTrcv p. 16).

The operating modes diagram divides the powered-on state POWER_ON into NOT_ACTIVE and ACTIVE; the transition is performed with LinTrcv_Init (SWS LinTrcv p. 15). Init receives a pointer to the selected configuration set [SWS_LinTrcv_00001]. Its structure LinTrcv_ConfigType is implementation-specific [SWS_LinTrcv_00172]. Since version 4.3.1, the initial state is restricted to LINTRCV_TRCV_MODE_SLEEP (SWS LinTrcv p. 1). Transitions to STANDBY are optional in the diagram. STANDBY can also be a purely internal state for hardware transitions (SWS LinTrcv p. 15).

State diagram: After LinTrcv_Init, the channel is in SLEEP; LinTrcv_SetOpMode switches between the modes, STANDBY is optional (transition assignment reconstructed as interpretation). Sources: SWS LinTrcv p. 15, SWS LinTrcv p. 25, SWS LinTrcv p. 1

According to [SWS_LinTrcv_91002], a LIN transceiver driver also reports the wakeup source to LinIf_WakeupConfirmation after being powered on by the bus. Interpretation: This report likely occurs in connection with LinTrcv_Init, because according to the diagram, Init is the first call after power-on (SWS LinTrcv p. 15).

Sequence diagram: LinTrcv_Init transitions the channel from NOT_ACTIVE to SLEEP; a power-on by the bus is reported to LinIf (timing as interpretation). Sources: [SWS_LinTrcv_00001], [SWS_LinTrcv_91002], SWS LinTrcv p. 1

Mode Switch and Mode Query via the LIN Interface

LinTrcv_SetOpMode (Service ID 0x01, non-reentrant) returns E_OK if the transceiver has switched to the requested mode. E_NOT_OK follows if the switch was not accepted, failed, or the parameter is outside the valid range [SWS_LinTrcv_00002]. The function switches the internal state of the channel to the value of OpMode (SWS LinTrcv p. 25). LinIf_SetTrcvMode is applicable to all transceivers with all values, regardless of hardware support. It returns the result of LinTrcv_SetOpMode unchanged (SWS LinIf p. 90).

LinIf addresses with NetworkHandleType Channel, whereas LinTrcv addresses with uint8 LinNetwork (SWS LinIf p. 90, [SWS_LinTrcv_00002]). The payload does not describe how both identifiers are mapped to each other. LinTrcv_GetOpMode (0x02, reentrant) returns the current software state of the driver in OpMode [SWS_LinTrcv_00005], SWS LinTrcv p. 26. For each channel, the configuration defines hardware access as DIO or SPI access (SWS LinTrcv p. 44).

Sequence diagram: A mode change runs synchronously from LinIf via LinTrcv to the hardware; Tm_BusyWait1us16bit bridges wait times, and LinIf returns the result unchanged. Sources: [SWS_LinTrcv_00002], [SWS_LinTrcv_91003], [SWS_LinTrcv_00171], SWS LinIf p. 90

Wakeup Detection: Internal and External Wakeup Paths

The driver distinguishes two wake-up types (SWS LinTrcv p. 17). An internal wake-up is triggered by an upper layer, such as via LinTrcv_Init or LinTrcv_SetOpMode. The driver itself detects an external wake-up and passes it upwards via LinTrcv_CheckWakeup; LinIf calls this function. The driver does not support wake-ups via a dedicated ISR, but only via the ICU. It releases the ICU channels when the transceiver switches to standby mode.

LinIf_CheckWakeup is called after EcuM has been notified of a wake-up on a LIN channel (SWS LinIf p. 112). LinTrcv_CheckWakeup (0x07, reentrant) evaluates the wake-up on the addressed network, such as a dominant bus state or a negative edge on the wake-up pin (SWS LinTrcv p. 30). After successful detection, the driver reports the wake-up source to LinIf_WakeupConfirmation [SWS_LinTrcv_91002]. EcuM_SetWakeupEvent is additionally listed as a required interface [SWS_LinTrcv_91003].

For R20-11: LinTrcv_CheckWakeup returns E_OK if a wake-up was detected, and E_NOT_OK if none was detected [SWS_LinTrcv_00012]. The document passage from R24-11/R25-11, by contrast, interprets the return values as “call accepted/not accepted” (SWS LinTrcv p. 30). According to the change history, they were not revised until R22-11 (SWS LinTrcv p. 1). The older diagram for bus wake-up mentions interfaces such as LinIf_WakeUpTrcvNotification, which do not appear in the R20-11 requirements (SWS LinIf p. 81). LinIf_WakeupConfirmation [SWS_LinTrcv_91002] is authoritative.

Sequence diagram: An external wake-up reaches LinIf_CheckWakeup via ICU and EcuM; LinTrcv checks the network and confirms a detected wake-up via LinIf_WakeupConfirmation. Sources: [SWS_LinTrcv_00012], [SWS_LinTrcv_91002], SWS LinIf p. 112, SWS LinTrcv p. 17

Control wake-up notification and evaluate wake-up reason

LinTrcv_SetWakeupMode (0x05, non-reentrant) enables, disables, or clears the notification for wake-up events on the addressed network [SWS_LinTrcv_00009]. For this purpose, LinTrcv_TrcvWakeupModeType [SWS_LinTrcv_00169] provides LINTRCV_WUMODE_ENABLE, LINTRCV_WUMODE_DISABLE, and LINTRCV_WUMODE_CLEAR; CLEAR clears a stored wake-up event. If a stored event is already present upon activation, the notification occurs during the call or immediately afterwards (SWS LinTrcv p. 31). LinIf reaches the function via LinIf_SetTrcvWakeupMode (SWS LinIf p. 93).

Activity diagram: LinTrcv_SetWakeupMode branches according to the requested mode; upon activation, an already stored event is reported immediately. Sources: [SWS_LinTrcv_00009], [SWS_LinTrcv_00169], SWS LinTrcv p. 31

LinTrcv_GetBusWuReason (0x03, reentrant) returns the wake-up reason detected by the transceiver in Reason [SWS_LinTrcv_00007]. How finely the reasons can be distinguished depends heavily on the hardware (SWS LinTrcv p. 28). LinTrcv_TrcvWakeupReasonType [SWS_LinTrcv_00170] includes LINTRCV_WU_ERROR, LINTRCV_WU_NOT_SUPPORTED, LINTRCV_WU_BY_BUS, and LINTRCV_WU_BY_PIN, among others; further values are truncated in the payload (SWS LinTrcv p. 30). LinIf provides the reason via LinIf_GetTrcvWakeupReason (SWS LinIf p. 92).

Configuration: channels, wake-up support, and partitions

The configuration diagrams (from R23-11 onwards) show the container LinTrcvGeneral with LinTrcvDevErrorDetect and LinTrcvVersionInfoApi (each default false) as well as LinTrcvWakeUpSupport (SWS LinTrcv p. 36). There is at least one LinTrcvChannel container. Each carries LinTrcvChannelUsed (default true), LinTrcvWakeupByBusUsed (default false), LinTrcvChannelId (0..255), and a reference to an EcuM wake-up source (SWS LinTrcv p. 44). LinTrcvWakeUpSupport selects the wake-up type. LinTrcvWakeupByBusUsed toggles wake-up support per channel (SWS LinTrcv p. 17).

Two rules apply to multi-core systems. The partitions referenced via LinTrcvChannelEcucPartitionRef must be a subset of those referenced via LinTrcvEcucPartitionRef [SWS_LinTrcv_00176]. In addition, LinTrcvChannel and LinChannel of a communication channel must reference the same partition [SWS_LinTrcv_00177]. Partition assignments that the implementation does not support must be rejected [SWS_LinTrcv_00174]. According to the change history, multi-core distribution was added with R19-11 (SWS LinTrcv p. 1).

Context diagram (configuration structure): General switches are located in LinTrcvGeneral, channel-specific parameters and partition references in LinTrcvChannel. Sources: SWS LinTrcv p. 36, SWS LinTrcv p. 44, [SWS_LinTrcv_00176], [SWS_LinTrcv_00177]

Behavior in the event of an error

The driver reports runtime errors via return values. In R20-11, LinTrcv_GetOpMode and LinTrcv_GetBusWuReason return E_NOT_OK in case of development errors or if the mode or wake-up reason could not be determined [SWS_LinTrcv_00005], [SWS_LinTrcv_00007]. E_NOT_OK is also provided in the event of missing or faulty communication with the transceiver (SWS LinTrcv p. 26, SWS LinTrcv p. 28). If the wake-up reason cannot be determined due to an error, LINTRCV_WU_ERROR is available [SWS_LinTrcv_00170]. In R20-11, an E_NOT_OK from LinTrcv_CheckWakeup, by contrast, only means “no wake-up detected” [SWS_LinTrcv_00012].

The driver reports development errors to DET via Det_ReportError [SWS_LinTrcv_91003]. Detection is enabled by LinTrcvDevErrorDetect (SWS LinTrcv p. 36). The document passages mention three error codes: LINTRCV_E_UNINIT for calls prior to initialization, LINTRCV_E_INVALID_LIN_NETWORK for invalid network numbers, and LINTRCV_E_PARAM_POINTER for versioninfo == NULL (SWS LinTrcv p. 26, SWS LinTrcv p. 30, SWS LinTrcv p. 29). These passages originate from R23-11 and later. In R20-11, the error classification was cleaned up, and in R21-11, the error codes (SWS LinTrcv p. 1). Identifiers and scope may therefore differ in R20-11.

Activity diagram: LinTrcv_GetOpMode reports a missing init to DET and returns E_NOT_OK, likewise in case of disrupted transceiver communication; the order of the checks is exemplary, further checks truncated in the payload are omitted. Sources: [SWS_LinTrcv_00005], SWS LinTrcv p. 26, [SWS_LinTrcv_91003]

Incorrect partition assignments lead to the rejection of the configuration [SWS_LinTrcv_00174]. If a mode change initiated via LinIf fails, the previous state remains unchanged according to the LinIf specification (SWS LinIf p. 90).

Usage and Operation

The function LinTrcv_SetWakeupMode ([SWS_LinTrcv_00009]) enables, disables, or clears the notification for wake-up events on the specified network channel. The interface is provided via the header file Lin_Trcv.h.

Execution is synchronous. Since the function is specified as non-reentrant (non Reentrant), the caller must ensure that no concurrent or interrupting calls to the interface occur ([SWS_LinTrcv_00009]).

Parameters and Return Values

  • LINNetwork: Addresses the respective LIN network to which the configuration is to be applied ([SWS_LinTrcv_00009]).
  • Trcv Wakup Mode (type LinTrcv_TrcvWakeupModeType): Passes the requested wake-up mode to the transceiver ([SWS_LinTrcv_00009]).
  • Return value (Std_ReturnType):
    • E_OK: The transceiver state was successfully changed to the requested mode ([SWS_LinTrcv_00009]).
    • E_NOT_OK: The service request has failed, either due to development errors (development errors) or because the requested wake-up mode could not be set ([SWS_LinTrcv_00009]).

Error Handling and Restrictions

In case of an error – for example upon detection of development errors or if the hardware cannot perform the mode change – the function returns E_NOT_OK. Callers must evaluate this return value to reliably verify the status of the wake-up notification ([SWS_LinTrcv_00009]).
