Brokers frames, mode switches, and link states between Ethernet drivers, switches, and the communication stack.

The Ethernet Interface mediates between EthSM and upper layers on the one hand and the drivers for controllers, transceivers, and switches on the other. Via the asynchronous EthIf_SetControllerMode, it switches controllers including referenced hardware [SWS_EthIf_00034]. It transmits frames in two steps, distributes receive indications, and reports link states to EthSM or BswM. It disables port groups with a delay and forwards wake-up checks to transceivers and switches. Most important constraint: With error detection enabled, almost every service requires a preceding EthIf_Init, otherwise ETHIF_E_UNINIT is reported [SWS_EthIf_00155].

The Ethernet Interface connects the users of the Ethernet stack with the drivers for controllers, transceivers, and switches. It accesses switches via one or more Ethernet Switch Drivers [SWS_EthIf_00228]. Upwards, the EthSM controls the controller modes and receives mode and link notifications [SWS_EthIf_00252]. The BswM receives the link states of independent port groups [SWS_EthIf_00261].

Communication start is triggered by the asynchronous EthIf_SetControllerMode [SWS_EthIf_00034]. In doing so, EthIf also switches referenced transceivers and port groups [SWS_EthIf_00266], [SWS_EthIf_00264]. It reports the attained controller mode via EthSM_CtrlModeIndication [SWS_EthIf_00252].

Transmission is performed in two steps with EthIf_ProvideTxBuffer and EthIf_Transmit [SWS_EthIf_00067], [SWS_EthIf_00075]. Confirmations reach the upper layer via <UL>_TxConfirmation; in polling mode, EthIf_MainFunctionTx triggers them [SWS_EthIf_00255], [SWS_EthIf_00113]. EthIf distributes received frames via <User>_RxIndication [SWS_EthIf_00104]. It discards and counts frames with invalid VLAN [SWS_EthIf_00317], [SWS_EthIf_00309].

Sequence diagram: Buffer request, transmission, and confirmation in polling or interrupt mode. Sources: [SWS_EthIf_00067], [SWS_EthIf_00075], [SWS_EthIf_00091], [SWS_EthIf_00113], EthIf-SWS p. 87

EthIf cyclically determines link states in EthIf_MainFunctionState [SWS_EthIf_00407]. It accumulates them for port groups [SWS_EthIf_00259], and polls signal quality for active links [SWS_EthIf_00409]. EthIf shuts down switch ports of port groups with a delay via the timer EthIfSwitchOffPortTimedelay [SWS_EthIf_00270]. EthIf_CheckWakeup forwards wake-up checks to transceivers and switches [SWS_EthIf_00245], [SWS_EthIf_00500].

With DET enabled, the services report, among other things, invalid indices and missing initialization (ETHIF_E_UNINIT) [SWS_EthIf_00017], [SWS_EthIf_00155]. If the DET is disabled, many services return E_NOT_OK instead [SWS_EthIf_00325]. Optional services such as timestamping or wireless Ethernet can be disabled via configuration parameters [SWS_EthIf_00164], [SWS_EthIf_00342].

Role of EthIf between Ethernet drivers and communication stack

The Ethernet Interface is the hardware-independent mediation layer between the users of the Ethernet stack and the drivers for controllers (Eth), transceivers (EthTrcv), and switches (EthSwt). For switches, EthIf uses one or more Ethernet Switch Drivers, which encapsulate the characteristics of the respective hardware [SWS_EthIf_00228]. EthIf distributes accesses via EthIfSwitchIdx to the responsible EthSwt module with its EthSwtIdx [SWS_EthIf_00224]. With EthIfEnableWEthApi, wireless controller and transceiver drivers are added [SWS_EthIf_00340]. The layering is shown in diagrams EthSwt-SWS p. 5 and Eth-SWS p. 18.

In the upper direction, EthIf collaborates with several partners:

  • The EthSM controls the controller modes and receives mode and link indications [SWS_EthIf_00252], [SWS_EthIf_00262].
  • The BswM receives the link states of port groups without controller reference [SWS_EthIf_00261].
  • Upper layers transmit frames and receive reception indications as well as transmission confirmations [SWS_EthIf_00104], [SWS_EthIf_00106].
  • The integration code triggers wake-up checks via EthIf_CheckWakeup [SWS_EthIf_00244].

The imported types, including Eth_BufIdxType and EcuM_WakeupSourceType, are defined by [SWS_EthIf_00023]. The file structure is shown in EthIf-SWS p. 15.

From EthIf_Init to active EthIfController

EthIf_Init [SWS_EthIf_00024] takes an implementation-specific post-build structure of type EthIf_ConfigType [SWS_EthIf_00149]. Almost all services check whether initialization has been performed if error detection is enabled. Otherwise, they report ETHIF_E_UNINIT, such as according to [SWS_EthIf_00155] or [SWS_EthIf_00273].

EthIf_SetControllerMode triggers the communication start; the service operates asynchronously [SWS_EthIf_00034]. In doing so, EthIf also switches the referenced hardware:

  • If a referenced EthIfTransceiver is set to ETH_MODE_DOWN, EthTrcv_SetTransceiverMode and further calls follow in a fixed order [SWS_EthIf_00266].
  • For a port group of type "control", its ports are switched [SWS_EthIf_00264].
  • In case of a direct switch reference, all ports of the switch are switched (DRAFT) [SWS_EthIf_00478].

Controller and remaining hardware are controlled independently of each other EthIf-SWS p. 30. The feedback arrives asynchronously: The driver calls EthIf_CtrlModeIndication [SWS_EthIf_00231], and EthIf reports onward to EthSM_CtrlModeIndication [SWS_EthIf_00252]. Transceivers report via EthIf_TrcvModeIndication [SWS_EthIf_00232].

During shutdown with ETH_MODE_DOWN, EthIf shuts down only active transceivers or switch ports [SWS_EthIf_00484], [SWS_EthIf_00485], [SWS_EthIf_00265]. In contrast, EthIf forwards ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST on every call, regardless of the current mode [SWS_EthIf_00479], [SWS_EthIf_00480], [SWS_EthIf_00481]. Older rules regarding switch shutdown are OBSOLETE in R20-11 [SWS_EthIf_00256], [SWS_EthIf_00257].

Transmitting and receiving frames: buffers, VLAN, and confirmations

Transmission takes place in two steps:

  1. EthIf_ProvideTxBuffer [SWS_EthIf_00067] provides buffer index and buffer pointer. Without configured EthIfVlanID, FrameType and Priority remain unused [SWS_EthIf_00146].
  2. EthIf_Transmit [SWS_EthIf_00075] triggers the transmission of the filled buffer. For VLAN controllers, EthIf passes the value 0x8100 to Eth_Transmit instead of the FrameType [SWS_EthIf_00250].

The document citation from R23-11 adds a condition: Forwarding only occurs if the last accepted mode is ETH_MODE_ACTIVE or ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST EthIf-SWS p. 101. Silent communication via ETH_MODE_TX_OFFLINE is only described there EthIf-SWS p. 34. It does not belong to the R20-11 requirements in the payload.

EthIf_TxConfirmation [SWS_EthIf_00091] passes the result through to the upper layer via <UL>_TxConfirmation [SWS_EthIf_00255], [SWS_EthIf_00106]. In polling mode, EthIf_MainFunctionTx generates the confirmations and additionally checks state changes of the transceivers [SWS_EthIf_00113]. In interrupt mode, the driver's ISR calls back directly EthIf-SWS p. 88. The PDU-based signature of EthIf_Transmit from R24-11 onward EthIf-SWS p. 97 does not apply to R20-11.

Sequence diagram: Two-step transmission and confirmation in polling or interrupt mode. Sources: [SWS_EthIf_00067], [SWS_EthIf_00075], [SWS_EthIf_00250], [SWS_EthIf_00113], [SWS_EthIf_00091], [SWS_EthIf_00255], EthIf-SWS p. 87, EthIf-SWS p. 88

The driver reports received frames via EthIf_RxIndication [SWS_EthIf_00085]. In polling mode, EthIf_MainFunctionRx checks cyclically for new frames [SWS_EthIf_00097]. In priority processing, this is done per receive queue via Eth_Receive with the appropriate FifoIdx [SWS_EthIf_91051]. It is passed onward via <User>_RxIndication [SWS_EthIf_00104], presumably to the user assigned via FrameType.

If the VLAN is not active, EthIf discards the frame and increments the associated measurement value [SWS_EthIf_00317], namely ETHIF_MEAS_DROP_CRTLIDX [SWS_EthIf_00309]. With EthIfEnableSecurityEventReporting, EthIf additionally reports security events to the IdsM [SWS_EthIf_00502], [SWS_EthIf_00503], EthIf-SWS p. 225.

Link state, port groups, and signal quality

Controllers without transceiver reference behave as if the link were ETHTRCV_LINK_STATE_ACTIVE [SWS_EthIf_00229]. If the link changes, EthIf calls <User>_TrcvLinkStateChg for each affected EthIfController [SWS_EthIf_00230], [SWS_EthIf_00108]. Without a port group, EthIf reports the state of the host port to the EthSM [SWS_EthIf_00260].

For port groups, EthIf accumulates the state across the ports. For example, ETHTRCV_LINK_STATE_DOWN applies if a host or uplink port is down [SWS_EthIf_00259]. The result is sent to the EthSM if the group is assigned to a controller [SWS_EthIf_00262], otherwise to the BswM [SWS_EthIf_00261].

The polling occurs cyclically in EthIf_MainFunctionState [SWS_EthIf_91104] with the period EthIfMainFunctionStatePeriod [SWS_EthIf_00407]. If this parameter is missing, according to the diagram EthIf_MainFunctionRx handles the polling EthIf-SWS p. 89.

For active links, EthIf additionally polls the signal quality via EthSwt_GetPortSignalQuality [SWS_EthIf_00408] or EthTrcv_GetPhySignalQuality [SWS_EthIf_00409]. Current, highest, and lowest values reside in EthIf_SignalQualityResultType [SWS_EthIf_91057]. They are read via [SWS_EthIf_91056] and reset via [SWS_EthIf_00400] and [SWS_EthIf_00404]. The rule for updating is described in EthIf-SWS p. 176.

Sequence diagram: Cyclic link polling, accumulation, notification to EthSM or BswM, and signal quality polling. Sources: [SWS_EthIf_00407], [SWS_EthIf_00259], [SWS_EthIf_00262], [SWS_EthIf_00261], [SWS_EthIf_00408], [SWS_EthIf_00409], EthIf-SWS p. 91, EthIf-SWS p. 92

Port groups are controlled via EthIf_SwitchPortGroupIdxType [SWS_EthIf_91101] and the asynchronous service EthIf_SwitchPortGroupRequestMode [SWS_EthIf_91102]. When activating, EthIf first sets the port mode and then issues the link request [SWS_EthIf_00272].

Shutdown is delayed. Only when all referencing groups request ETH_MODE_DOWN does timer EthIfSwitchOffPortTimedelay start [SWS_EthIf_00270]. After its expiration, EthSwt_PortLinkStateRequest and EthSwt_SetSwitchPortMode follow, each with DOWN [SWS_EthIf_00271]. A new active request affects a running timer [SWS_EthIf_00483]; interpretation: the timer is likely canceled.

EthIf_StartAllPorts [SWS_EthIf_91103] switches on all affected ports [SWS_EthIf_00275]. After expiration of EthIfPortStartupActiveTime, EthIf deactivates those ports that were not actively requested up to that point [SWS_EthIf_00276].

Wake-up, sleep, and forwarded special services

EthIf_CheckWakeup [SWS_EthIf_00244] operates asynchronously. The integration code calls the service, including in interrupt context EthIf-SWS p. 56. EthIf forwards to EthTrcv_CheckWakeup of all affected transceivers [SWS_EthIf_00245] and to EthSwt_SwitchCheckWakeup of the switches [SWS_EthIf_00500]. The service can be disabled via EthIfWakeUpSupport [SWS_EthIf_00248].

For host ECUs, the EcuM specification recommends polling on demand. Whether EthIf is called in EcuM_CheckWakeupHook is implementation-specific EcuM-SWS p. 192, EcuM-SWS p. 189.

Sequence diagram: Wake-up check of a host ECU via EthIf to switch and transceiver drivers. Sources: [SWS_EthIf_00244], [SWS_EthIf_00245], [SWS_EthIf_00500], EcuM-SWS p. 192, EcuM-SWS p. 189

There are DRAFT requirements for the opposite direction: EthIf_SleepIndication [SWS_EthIf_91006] leads to EthSM_SleepIndication [SWS_EthIf_00497]. As soon as no timers are running, EthIf checks whether the hardware has reached the requested mode [SWS_EthIf_00498]. For transceivers operating as a passive slave, EthIf additionally checks for unexpected link loss [SWS_EthIf_00499]. Wake-up reasons are provided by EthIf_GetPhyWakeupReason via EthTrcv_GetBusWuReason [SWS_EthIf_91004], [SWS_EthIf_00486]. EthIf_SetTransceiverWakeupMode is OBSOLETE [SWS_EthIf_00233].

Many services merely forward:

  • Statistics, mirroring, and test modes of switch ports go to EthSwt [SWS_EthIf_00415], [SWS_EthIf_00432], [SWS_EthIf_00448], [SWS_EthIf_00456].
  • PHY test modes and signal quality go to EthTrcv [SWS_EthIf_00324], [SWS_EthIf_00391]. Cable diagnostics on the switch port require an active controller [SWS_EthIf_00464].
  • The timestamp services [SWS_EthIf_00160], [SWS_EthIf_00166], and [SWS_EthIf_00172] depend on EthIfGlobalTimeSupport [SWS_EthIf_00164].
  • Switch management information [SWS_EthIf_91003] and port timestamping [SWS_EthIf_91007], [SWS_EthIf_00387] depend on EthIfSwitchManagementSupport [SWS_EthIf_00279]. The interaction with EthTSyn is shown in EthTSyn-SWS p. 74.
  • Wireless services go to WEth or WEthTrcv [SWS_EthIf_00341], [SWS_EthIf_00360].

Behavior in the event of an error

EthIf reports development errors to the DET. [SWS_EthIf_00017] defines, among others, ETHIF_E_INV_CTRL_IDX (0x01) and ETHIF_E_INV_TRCV_IDX (0x02). The requirements of the individual services additionally use:

  • ETHIF_E_UNINIT [SWS_EthIf_00155]
  • ETHIF_E_PARAM_POINTER [SWS_EthIf_00157]
  • ETHIF_E_INV_PARAM [SWS_EthIf_00247]
  • ETHIF_E_INV_SWT_IDX [SWS_EthIf_00397]
  • ETHIF_E_INV_PORT_IDX [SWS_EthIf_00493]
  • ETHIF_E_INV_PORT_GROUP_IDX for port groups with controller reference [SWS_EthIf_00274]

If the DET is disabled, many services return E_NOT_OK [SWS_EthIf_00325], [SWS_EthIf_00326] instead. Differing from this, [SWS_EthIf_00319] specifies the code ETHIF_E_NOTINIT.

Runtime errors are made visible via return values:

  • EthIf_Transmit returns E_NOT_OK if the transmission fails [SWS_EthIf_00075].
  • EthIf_ProvideTxBuffer returns a BufReq_ReturnType [SWS_EthIf_00067].
  • A negative transmission result is passed through unchanged to the upper layer by EthIf_TxConfirmation [SWS_EthIf_00255].
  • EthIf_GetPortMacAddr reports E_NOT_OK if no port or multiple ports match [SWS_EthIf_00191].
  • EthIf_GetAndResetMeasurementData reports E_NOT_OK for an unsupported index [SWS_EthIf_00310]. Counters do not overflow [SWS_EthIf_00313], and ETHIF_MEAS_ALL serves only for resetting [SWS_EthIf_00312], EthIf-SWS p. 65.

At network level, EthIf counts discarded frames and optionally reports them as a security event [SWS_EthIf_00309], [SWS_EthIf_00503]. EthIf propagates link loss to the users or to EthSM or BswM [SWS_EthIf_00230], [SWS_EthIf_00262], [SWS_EthIf_00261]. For transceivers operating as a passive slave, EthIf additionally detects an unexpected link-down [SWS_EthIf_00499].
