EthIf as Intermediary Between Ethernet Users and Hardware Drivers

The Ethernet Interface (EthIf) provides upper layers with uniform access to Ethernet controller, transceiver, and switch drivers. For switches, EthIf uses one or more Ethernet Switch Drivers [SWS_EthIf_00228]. Each access is forwarded via EthIfSwitchIdx to the responsible EthSwt driver with its EthSwtIdx [SWS_EthIf_00224]. For controllers, the same principle applies: The indexing diagram maps the contiguous EthIf controller index to the pair of driver and driver-local controller index SWS EthIf p. 18.

EthIf manages the following hardware representations:

  • physical controllers,
  • virtual EthIfController, such as for VLANs,
  • transceivers,
  • switches,
  • switch port groups.

A EthIfController connects a physical controller with the hardware through which it communicates SWS EthIf p. 31. This representation originates from R24-11. R20-11 also uses the same terms, for example in [SWS_EthIf_00264] and [SWS_EthIf_00266].

Context diagram: EthIf mediates between upper layers, EthSM, BswM, and the wakeup trigger on the one hand and the drivers Eth, EthTrcv, EthSwt, and WEth/WEthTrcv on the other. Sources: [SWS_EthIf_00228], [SWS_EthIf_00252], [SWS_EthIf_00261], [SWS_EthIf_00245], [SWS_EthIf_00340], SWS EthSwt p. 25

Startup: From EthIf_Init to Active Controller

EthIf_Init receives a pointer to the implementation-specific configuration [SWS_EthIf_00024]. EthIf_ConfigType is defined as a post-build structure [SWS_EthIf_00149]. If development error detection is enabled, the services check whether EthIf_Init has already been called (e.g. [SWS_EthIf_00155], [SWS_EthIf_00273]).

Communication is requested via EthIf_SetControllerMode, an asynchronous, non-reentrant service [SWS_EthIf_00034]. EthIf_GetControllerMode provides the current mode [SWS_EthIf_00039]. What EthIf does upon ETH_MODE_ACTIVE depends on the reference of EthIfController:

  • Transceiver in mode ETH_MODE_DOWN: EthIf calls, among others, EthTrcv_SetTransceiverMode with ETH_MODE_ACTIVE [SWS_EthIf_00266].
  • Port group of type “control”: EthIf controls all ports of the group in a fixed order [SWS_EthIf_00264].
  • Switch: EthIf controls all ports of the switch (DRAFT) [SWS_EthIf_00478].

ETH_MODE_DOWN acts in a mirror-image manner and affects only currently active hardware ([SWS_EthIf_00484], [SWS_EthIf_00485], [SWS_EthIf_00265]). For ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST, by contrast, EthIf forwards upon every call, regardless of the current mode ([SWS_EthIf_00479], [SWS_EthIf_00481]).

The feedback arrives asynchronously:

  • EthIf_CtrlModeIndication follows a preceding Eth_SetControllerMode and may arrive directly within the triggering call [SWS_EthIf_00231], SWS EthIf p. 154. EthIf forwards it to EthSM via EthSM_CtrlModeIndication [SWS_EthIf_00252].
  • Transceivers report via EthIf_TrcvModeIndication [SWS_EthIf_00232].
  • For a switch port, EthIf derives from the EthSwtPort configuration whether the notification arrives from the transceiver or from the switch via EthIf_SwitchPortModeIndication [SWS_EthIf_91055], SWS EthIf p. 170.

Sequence diagram: An EthIfController with transceiver is activated; the confirmations arrive asynchronously. Sources: [SWS_EthIf_00034], [SWS_EthIf_00266], [SWS_EthIf_00231], [SWS_EthIf_00252], [SWS_EthIf_00232], SWS EthIf p. 85

Transmitting and Receiving Frames

Transmission proceeds in two steps:

  1. EthIf_ProvideTxBuffer reserves a buffer with the responsible driver [SWS_EthIf_00067].
  2. EthIf_Transmit initiates the transmission of the filled buffer [SWS_EthIf_00075].

The VLAN configuration alters parameter handling:

  • Without configured EthIfVlanID, FrameType and Priority remain unused during buffer retrieval [SWS_EthIf_00146].
  • With a configured VLAN ID, EthIf passes the value 0x8100 instead of FrameType during transmission [SWS_EthIf_00250].

Confirmations run via EthIf_TxConfirmation. Their Result is forwarded to <UL>_TxConfirmation ([SWS_EthIf_00091], [SWS_EthIf_00255], [SWS_EthIf_00106]). In polling mode, EthIf_MainFunctionTx generates the confirmations and additionally checks transceiver state changes [SWS_EthIf_00113].

Sequence diagram: Request buffer, issue transmit request, and receive confirmation, in polling or interrupt mode. Sources: [SWS_EthIf_00067], [SWS_EthIf_00075], [SWS_EthIf_00250], [SWS_EthIf_00113], [SWS_EthIf_00255], SWS EthIf p. 87, SWS EthIf p. 88

Differences from later releases:

  • In R24-11, EthIf_Transmit has a PDU-based signature SWS EthIf p. 97. Normative for R20-11 is the signature with CtrlIdx and BufIdx [SWS_EthIf_00075].
  • The mode ETH_MODE_ACTIVE_TX_OFFLINE and the coupling of transmit forwarding to the controller mode are only described in document sections from R23-11 onward SWS EthIf p. 34. The payload contains no requirement from R20-11 for this.

The driver reports received frames via EthIf_RxIndication [SWS_EthIf_00085]. EthIf forwards them to <User>_RxIndication [SWS_EthIf_00104]. In polling mode, EthIf_MainFunctionRx cyclically checks for new frames [SWS_EthIf_00097]. Prioritized variants call Eth_Receive with the respective FifoIdx for this purpose [SWS_EthIf_91051]. EthIfEnableRxInterrupt controls whether receive checking is active SWS EthIf p. 174.

Sequence diagram: Reception via polling or interrupt up to the indication to the user. Newer diagrams show LSduR instead of a generic user. Sources: [SWS_EthIf_00097], [SWS_EthIf_91051], [SWS_EthIf_00085], [SWS_EthIf_00104], SWS EthIf p. 48, SWS EthIf p. 89

Switch Ports, Port Groups, and Link State

Port groups are addressed via the zero-based index EthIf_SwitchPortGroupIdxType [SWS_EthIf_91101]. EthIf_SwitchPortGroupRequestMode requests their mode asynchronously [SWS_EthIf_91102]:

  • ETH_MODE_ACTIVE: EthIf connects the ports via EthSwt_SetSwitchPortMode and EthSwt_PortLinkStateRequest [SWS_EthIf_00272].
  • ETH_MODE_DOWN: The timer EthIfSwitchOffPortTimedelay starts for a port only when all groups referencing the port have requested DOWN [SWS_EthIf_00270]. After expiry, EthSwt_PortLinkStateRequest with ETHTRCV_LINK_STATE_DOWN and EthSwt_SetSwitchPortMode with ETH_MODE_DOWN follow [SWS_EthIf_00271].
  • Repeated ACTIVE request while shutdown timer is running: [SWS_EthIf_00483] governs this case; presumably the timer is stopped.

EthIf_StartAllPorts activates all affected ports [SWS_EthIf_00275]. EthIf deactivates ports again that were not requested with ACTIVE by the expiry of EthIfPortStartupActiveTime [SWS_EthIf_00276].

State diagram: Lifecycle of a switch port under port group control, with shutdown and startup timers. Sources: [SWS_EthIf_00270], [SWS_EthIf_00271], [SWS_EthIf_00272], [SWS_EthIf_00483], [SWS_EthIf_00275], [SWS_EthIf_00276]

EthIf merges the link states of the hardware:

  • Controllers without a transceiver are considered ETHTRCV_LINK_STATE_ACTIVE [SWS_EthIf_00229].
  • Upon every change, EthIf calls <User>_TrcvLinkStateChg for each affected controller [SWS_EthIf_00230].
  • For switches without a port group, the state of the host port counts [SWS_EthIf_00260].
  • For port groups, EthIf forms an accumulated state [SWS_EthIf_00259]. It is reported to EthSM [SWS_EthIf_00262] or, without an assigned controller, to BswM [SWS_EthIf_00261].

EthIf_MainFunctionState polls [SWS_EthIf_00407] at the rate of EthIfMainFunctionStatePeriod. For active links, the function reads the signal quality ([SWS_EthIf_00408], [SWS_EthIf_00409]). The current, highest, and lowest values since the last clear are stored [SWS_EthIf_91057].

Activity diagram: How the link state is determined and reported depends on the hardware reference. Sources: [SWS_EthIf_00229], [SWS_EthIf_00230], [SWS_EthIf_00259], [SWS_EthIf_00260], [SWS_EthIf_00261], [SWS_EthIf_00262], SWS EthIf p. 90, SWS EthIf p. 91

Wake-up check and sleep indication

EthIf_CheckWakeup is asynchronous and reentrant. The service requests the affected hardware to check a signaled wake-up [SWS_EthIf_00244]. According to the specification, the integration code calls it SWS EthIf p. 56. EthIf forwards to:

  • EthTrcv_CheckWakeup of all affected transceivers [SWS_EthIf_00245],
  • EthSwt_SwitchCheckWakeup of all affected switches [SWS_EthIf_00500].

The service can be disabled via EthIfWakeUpSupport [SWS_EthIf_00248].

Two services provide the wake-up reason (both DRAFT):

  • EthIf_GetPhyWakeupReason via EthTrcv_GetBusWuReason [SWS_EthIf_00486],
  • for switch ports, the call of EthSwt_GetSwitchPortWakeupReason [SWS_EthIf_00490].

EthIf forwards sleep notifications via EthIf_SleepIndication [SWS_EthIf_91006] to EthSM_SleepIndication [SWS_EthIf_00497]. EthIf_SetTransceiverWakeupMode and EthIf_GetTransceiverWakeupMode are obsolete in R20-11 ([SWS_EthIf_00233], [SWS_EthIf_00238]).

Sequence diagram: The wake-up check runs across all affected transceivers and switches. The EcuM diagram originates from releases from R21-11 onwards. Sources: [SWS_EthIf_00244], [SWS_EthIf_00245], [SWS_EthIf_00500], [SWS_EthIf_00486], SWS EcuM p. 189

Diagnostic, timestamp, and wireless services as pass-throughs

A large part of the API passes calls through to a driver:

  • To EthTrcv: test mode, loopback, cable diagnostics, and PHY identifier ([SWS_EthIf_00324], [SWS_EthIf_91018], [SWS_EthIf_91014], [SWS_EthIf_00334]).
  • To EthSwt: port mode, counters, statistics, port mirroring, and configuration data ([SWS_EthIf_00415], [SWS_EthIf_00432], [SWS_EthIf_00436], [SWS_EthIf_00448], [SWS_EthIf_00454], [SWS_EthIf_00468]).

Two services do more than pass through. EthIf_RunPortCableDiagnostic ensures that the associated EthIfController is in ETH_MODE_ACTIVE [SWS_EthIf_00464]. EthIf_GetPortMacAddr queries all switch drivers and returns E_NOT_OK if no port or multiple ports match [SWS_EthIf_00191].

Three services are available for time synchronization ([SWS_EthIf_00160], [SWS_EthIf_00166], [SWS_EthIf_00172]):

  • EthIf_EnableEgressTimeStamp activates egress timestamping of a transmit buffer.
  • EthIf_GetEgressTimeStamp and EthIf_GetIngressTimeStamp read the timestamps.

All three can be configured via EthIfGlobalTimeSupport ([SWS_EthIf_00164], [SWS_EthIf_00170], [SWS_EthIf_00176]). According to a passage from R23-11, the ingress query must occur within the Rx indication SWS EthIf p. 76. SWS TimeSync p. 55 shows the interaction with EthTSyn.

For switches, EthIf_SetSwitchMgmtInfo sets management information [SWS_EthIf_91003]. EthIf_SwitchEnableTimeStamping calls EthSwt_PortEnableTimeStamp for each port of the group [SWS_EthIf_00387]. This is enabled via EthIfSwitchManagementSupport [SWS_EthIf_00279].

Differences from later releases:

  • EthIf_GetCurrentTime [SWS_EthIf_00154] is obsolete as of R23-11 SWS EthIf p. 68.
  • R25-11 addresses EthIf_EnableEgressTimeStamp via a PduId instead of via CtrlIdx/BufIdx SWS EthIf p. 155.

Wireless functions are enabled via EthIfEnableWEthApi [SWS_EthIf_00340] and forwarded to WEth or WEthTrcv ([SWS_EthIf_00341], [SWS_EthIf_00353], [SWS_EthIf_00360], [SWS_EthIf_00366]). Many optional services can be disabled at compile time, for instance via EthIfStoreConfigurationApi [SWS_EthIf_00216] or EthIfVerifyConfigApi [SWS_EthIf_00305].

Behavior in the event of an error

[SWS_EthIf_00017] defines the development error codes, e.g., ETHIF_E_INV_CTRL_IDX (0x01) and ETHIF_E_INV_TRCV_IDX (0x02). A three-stage check is typical:

  1. Initialization: ETHIF_E_UNINIT.
  2. Index: ETHIF_E_INV_CTRL_IDX, ETHIF_E_INV_TRCV_IDX, ETHIF_E_INV_SWT_IDX, ETHIF_E_INV_PORT_IDX.
  3. Pointer: ETHIF_E_PARAM_POINTER.

Examples are the timestamp services ([SWS_EthIf_00167], [SWS_EthIf_00168], [SWS_EthIf_00169]) and the switch port wake-up reason query ([SWS_EthIf_00491], [SWS_EthIf_00492], [SWS_EthIf_00493], [SWS_EthIf_00494]). For many services, it explicitly applies: if DET is disabled, the function returns E_NOT_OK instead ([SWS_EthIf_00325], [SWS_EthIf_00326]).

Two special cases in error detection:

  • EthIf_SwitchPortGroupRequestMode rejects port groups that are assigned to a EthIfController. The service then reports ETHIF_E_INV_PORT_GROUP_IDX and returns E_NOT_OK [SWS_EthIf_00274].
  • [SWS_EthIf_00319] deviantly specifies the error code ETHIF_E_NOTINIT.

In the receive path, EthIf discards invalid frames:

  • Frames with an invalid CtrlIdx/VLAN are counted by measurement index ETHIF_MEAS_DROP_CRTLIDX. If the VLAN is not active, all VLAN-tagged frames are also counted ([SWS_EthIf_00309], [SWS_EthIf_00317]).
  • If EthIfEnableSecurityEventReporting is set, EthIf reports security events to the IdsM, such as ETHIF_SEV_DROP_INV_VLAN ([SWS_EthIf_00502], [SWS_EthIf_00503]).

EthIf_GetAndResetMeasurementData reads the counters [SWS_EthIf_91011]. They do not overflow [SWS_EthIf_00313]. An unsupported measurement index results in E_NOT_OK [SWS_EthIf_00310]. ETHIF_MEAS_ALL resets all values [SWS_EthIf_00312].

Activity diagram: Discard reasons in the receive path with counting and security events; the check order is interpretation. Sources: [SWS_EthIf_00309], [SWS_EthIf_00317], [SWS_EthIf_00502], [SWS_EthIf_00503]

Operational errors are reflected in return values:

  • EthIf_SwitchPortGroupRequestMode returns E_NOT_OK if the mode could not be changed [SWS_EthIf_91102], SWS EthIf p. 77.
  • According to the documentation, EthIf_GetSwitchPortMode also fails in the states ETHSWT_STATE_UNINIT and ETHSWT_STATE_INIT SWS EthIf p. 104.

Two further checks are specified as DRAFT. For passive transceivers, EthIf monitors unexpected link losses [SWS_EthIf_00499]. EthIf also checks whether the managed hardware has reached the requested mode and link state [SWS_EthIf_00498].
