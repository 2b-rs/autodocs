Role of CryIf: Dispatcher between Crypto Service Manager and crypto drivers

The Crypto Interface (CryIf) is located in the crypto stack of the Classic Platform between the Crypto Service Manager (CSM) and one or more crypto drivers. It accepts jobs and forwards them to the configured Crypto Driver Object. This applies both to job processing via CryIf_ProcessJob [SWS_CryIf_91003] and to job cancellation, which CryIf dispatches “to the configured Crypto Driver Object” [SWS_CryIf_91014]. In the layer model of the CSM specification, CryIf is located in the ECU abstraction layer. Above it lies CSM in the service layer, below it the crypto driver in the microcontroller abstraction layer SWS CSM p. 28.

For an active job, CSM calls CryIf_ProcessJob and forwards its return value to its caller SWS CSM p. 22. CryIf itself requires the following interfaces:

  • Csm_CallbackNotification, with which “the underlying layer (CRYIF)” reports the end of a job to CSM, as well as Det_ReportRuntimeError [SWS_CryIf_91100].
  • Optionally Det_ReportError for development errors [SWS_CryIf_91101].

The API call tree of the specification distinguishes two paths: job-based services and the direct API for key management SWS CSM p. 20.

Context diagram: CryIf connects CSM queues to Crypto Driver Objects via channels, forwards feedback to CSM, and reports errors to DET. Sources: [SWS_CryIf_91003], [SWS_CryIf_91100], SWS CSM p. 28, SWS CSM p. 26

Channels, Crypto Driver Objects, and configuration

A channel is the path from a CSM queue via CryIf to a Crypto Driver Object. Each CSM queue is assigned to exactly one channel. A Crypto Driver Object represents an independent crypto “device” in hardware or software, such as an AES accelerator in an HSM or an RSA implementation in software SWS CSM p. 26.

Channels are configured in the container CryIfChannel (multiplicity 0..*, pre-compile only). It contains the parameters CryIfChannelId and CryIfDriverObjectRef. CryIfChannelId specifies which channel a CSM queue is connected to SWS CryptoInterface p. 51. Interpretation: Parameter channelId of CryIf_ProcessJob and CryIf_CancelJob is likely resolved via this container to the Crypto Driver Object referenced via CryIfDriverObjectRef [SWS_CryIf_91003] [SWS_CryIf_91014].

The content of the configuration structure CryIf_ConfigType is implementation-specific; the specification does not define it [SWS_CryIf_91118]. The include dependencies between CSM, CryIf, and the drivers Crypto_<vi>_<ai> are shown in the file structure of the specification SWS CryptoInterface p. 11.

Job processing: Operating modes and asynchronous notification

All cryptographic primitives run via the single function CryIf_ProcessJob. The field job->jobPrimitiveInputOutput.mode contains the operating modes START, UPDATE, and FINISH, which can be combined. A single call corresponds to the combination of all three modes SWS CryptoInterface p. 22. In R20-11, it depends on the configuration whether the reentrant function operates synchronously or asynchronously [SWS_CryIf_91003]. On the CSM side, an additional rule applies: If START and FINISH are set without UPDATE, CSM rejects the call with E_NOT_OK SWS CSM p. 22.

In the asynchronous case, the interfaces pass only the necessary information downward SWS CSM p. 26. The feedback then proceeds in three stages:

  1. The driver can trigger the computation via its main function. After completion, it reports the job and result to CryIf via CryIf_CallbackNotification SWS Crypto p. 27 [SWS_CryIf_91013].
  2. CryIf notifies the CSM via Csm_CallbackNotification [SWS_CryIf_91100].
  3. The CSM calls the callback configured in the job primitive SWS CSM p. 26.

This cascade is also shown in the sequence diagram of the CSM specification for R20-11 SWS CSM p. 164.

Sequence diagram: The job returns immediately; the result is passed later via callback from the driver via CryIf and CSM to the application. Sources: [SWS_CryIf_91013], [SWS_CryIf_91100], SWS CSM p. 164, SWS Crypto p. 27

The CSM cancels a running job in two ways: It removes it from its own queue or calls CryIf_CancelJob. CryIf distributes this cancellation synchronously to the Crypto Driver Object SWS CSM p. 80 [SWS_CryIf_91014]. For E_OK, the CSM calls the job's completion callback. The document passages from later releases additionally mention CRYPTO_E_JOB_CANCELED: The cancellation then only occurs at the next suitable processing step and is reported back negatively SWS CryptoInterface p. 24. Whether R20-11 already includes this value is left open by the shortened requirement text.

Sequence diagram: The cancellation of a job is passed through to the driver via CryIf, and the result determines the feedback to the user. Sources: [SWS_CryIf_91014], SWS CSM p. 80, SWS CryptoInterface p. 46

Key references: from cryIfKeyId to the driver's key ID

CryIf uses its own key identifiers (cryIfKeyId) and translates them into the key IDs of the responsible driver. This affects the key management services CRYPTO_KEYSETVALID, CRYPTO_KEYSETINVALID, CRYPTO_RANDOMSEED, CRYPTO_KEYGENERATE, CRYPTO_KEYDERIVE, CRYPTO_KEYEXCHANGECALCPUBVAL, and CRYPTO_KEYEXCHANGECALCSECRET. For them, CryIf_ProcessJob checks whether cryIfKeyId and, if applicable, targetCryIfKeyId are within the valid range. If this is the case, CryIf sets job->cryptoKeyId and, if applicable, job->targetCryptoKeyId [SWS_CryIf_00133]. If an identifier is out of range, CryIf reports CRYPTO_E_PARAM_HANDLE to the DET and returns E_NOT_OK. For CRYPTO_KEYDERIVE, this also applies to the target identifier [SWS_CryIf_00134] [SWS_CryIf_00135] [SWS_CryIf_00141].

For key-based primitives, CryIf checks job->jobPrimitiveInfo->cryIfKeyId in the same way. These include MAC, encryption and decryption, AEAD, random number generation, as well as signature generation and verification [SWS_CryIf_00143]. In the case of job processing redirection, CryIf also translates the incoming key and key element references into the driver's values [SWS_CryIf_00136]. The document passage from later releases additionally includes CRYPTO_CUSTOM in the service list. According to the change history, this service was not added until R22-11 and therefore does not apply to R20-11 SWS CryptoInterface p. 23 SWS CryptoInterface p. 1.

Activity diagram: Depending on the service, CryIf_ProcessJob checks the key identifiers, sets the driver key IDs for key management, and aborts with E_NOT_OK in case of out-of-range errors. Sources: [SWS_CryIf_00133], [SWS_CryIf_00134], [SWS_CryIf_00135], [SWS_CryIf_00143]

Initialization and concurrency

Prior to any other use, CryIf_Init must be called with a pointer to the selected configuration. The function is synchronous and non-reentrant [SWS_CryIf_91000]. If an API is called prior to initialization, CryIf reports CRYIF_E_UNINIT when development error detection is enabled [SWS_CryIf_00009]. The specification illustrates this, for example, for CryIf_KeyGetStatus SWS CryptoInterface p. 29. Version information is provided synchronously and reentrantly by CryIf_GetVersionInfo [SWS_CryIf_91001].

The following applies to concurrency:

  • CryIf_ProcessJob and CryIf_CancelJob are reentrant [SWS_CryIf_91003] [SWS_CryIf_91014].
  • CryIf_CallbackNotification is non-reentrant. Calls from multiple drivers must therefore not overlap [SWS_CryIf_91013].
  • The copy functions may run in parallel, but not for the same cryIfKeyId [SWS_CryIf_91015].

Behavior in the event of an error

For development errors, R20-11 defines the following codes [SWS_CryIf_00009]:

  • CRYIF_E_UNINIT (0x00): Call before initialization
  • CRYIF_E_INIT_FAILED (0x01): Initialization failed
  • CRYIF_E_PARAM_POINTER (0x02): Null pointer
  • CRYIF_E_PARAM_HANDLE (0x03): Parameter out of range
  • CRYIF_E_PARAM_VALUE (0x04): Invalid value
  • CRYIF_E_KEY_SIZE_MISMATCH (0x05): Size of source element does not match target element

Code CRYIF_E_KEY_SIZE_MISMATCH is likely relevant primarily when copying between drivers, because CryIf performs this copy itself [SWS_CryIf_00140].

For the range checks on keys, R20-11 uses a different designation than the error table. The requirements state CRYPTO_E_PARAM_HANDLE [SWS_CryIf_00134] [SWS_CryIf_00143], whereas the table defines CRYIF_E_PARAM_HANDLE. With R22-11, this was harmonized, and the return values after DET reports were omitted SWS CryptoInterface p. 1. For R20-11: An out-of-range error for a key identifier leads to E_NOT_OK even without development mode [SWS_CryIf_00141].

Functional errors come from the driver as crypto return values [SWS_CryIf_91020]:

  • CRYPTO_E_BUSY (0x02)
  • CRYPTO_E_ENTROPY_EXHAUSTED (0x04)
  • CRYPTO_E_KEY_READ_FAIL (0x06)
  • CRYPTO_E_KEY_WRITE_FAIL (0x07)
  • CRYPTO_E_KEY_NOT_AVAILABLE (0x08)
  • CRYPTO_E_KEY_NOT_VALID (0x09)

CryIf forwards these values. For example, CryIf_ProcessJob can end with CRYPTO_E_BUSY, CRYPTO_E_KEY_NOT_VALID, or CRYPTO_E_KEY_SIZE_MISMATCH [SWS_CryIf_91003]. If setting a key element fails, its state is to be considered unknown. The application can check it with Csm_KeyGetStatus, which in turn calls CryIf_KeyGetStatus SWS CSM p. 62 SWS CSM p. 63.

CryIf_CallbackNotification also checks its inputs: Prior to initialization, it reports CRYIF_E_UNINIT, and in case of an invalid pointer CRYIF_E_PARAM_POINTER SWS CryptoInterface p. 44. For runtime errors, Det_ReportRuntimeError is provided as a required interface [SWS_CryIf_91100].

function CryIf_ProcessJob [SWS_CryIf_91003] 📄 PDF

Std_ReturnType CryIf_ProcessJob (uint32 channelId, Crypto_JobType* job);

Service CryIf_ProcessJob.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: ddb7806dc298 Provenance

The function CryIf_ProcessJob ([SWS_CryIf_91003]) forwards passed cryptographic jobs to the configured Crypto Driver Object. It accepts the channel identifier channelId as well as a pointer to the job configuration job (of type Crypto_JobType*). Depending on the configuration, the job is executed synchronously or asynchronously. The function is designed to be reentrant.

Parameter Checking and DET Reports

Prior to processing, the function performs specific checks of the key parameters:

  • If one of the services CRYPTO_KEYSETVALID, CRYPTO_KEYSETINVALID, CRYPTO_RANDOMSEED, CRYPTO_KEYGENERATE, CRYPTO_KEYDERIVE, CRYPTO_KEYEXCHANGECALCPUBVAL, or CRYPTO_KEYEXCHANGECALCSECRET is configured in job->jobPrimitiveInfo->primitiveInfo->service, job->cryIfKeyId must be within the valid range. Otherwise, CryIf_ProcessJob reports the error CRYPTO_E_PARAM_HANDLE to the DET and returns E_NOT_OK ([SWS_CryIf_00134]).
  • If the service CRYPTO_KEYDERIVE is set, the target key job->cryIfTargetKeyId must additionally be within the valid value range. In case of a range violation, the function likewise reports CRYPTO_E_PARAM_HANDLE to the DET and returns E_NOT_OK ([SWS_CryIf_00135]).

Return Values

The return value of type Std_ReturnType signals success (E_OK), general failure (E_NOT_OK), or specific error states ([SWS_CryIf_91003]):

  • CRYPTO_E_BUSY: The Crypto Driver Object is busy.
  • CRYPTO_E_QUEUE_FULL: The job queue is full.
  • CRYPTO_E_JOB_CANCELED: The synchronous job was canceled.
  • Error in key state or access rights: CRYPTO_E_KEY_NOT_VALID, CRYPTO_E_KEY_SIZE_MISMATCH, CRYPTO_E_KEY_READ_FAIL, CRYPTO_E_KEY_WRITE_FAIL, CRYPTO_E_KEY_NOT_AVAILABLE, or CRYPTO_E_KEY_EMPTY.
  • CRYPTO_E_ENTROPY_EXHAUSTED: Exhaustion of entropy pool.
