Interfaces Ethernet controllers to the AUTOSAR stack: initialization, modes, transmission, reception, and diagnostics.

The Ethernet driver interfaces Ethernet controllers to the Ethernet Interface. It initializes the controllers, switches their Rx/Tx communication asynchronously between ETH_MODE_DOWN and ETH_MODE_ACTIVE, and reports the change via indication ([SWS_Eth_00276]). Transmission is two-staged: request buffer, then hand over. The driver acknowledges each transmission with E_OK or E_NOT_OK ([SWS_Eth_00243]). In addition, it provides reception with address filtering, MII accesses, timestamps, and diagnostic counters. During shutdown, locked transmit buffers must be released.

The Ethernet driver Eth abstracts one or more Ethernet controllers for the Ethernet Interface (EthIf). EthIf can bundle multiple drivers from different vendors (SWS Eth p. 17). Eth reports results via EthIf_RxIndication, EthIf_TxConfirmation, and EthIf_CtrlModeIndication ([SWS_Eth_00244], [SWS_Eth_00243], [SWS_Eth_00119]). Further neighbors are EthTrcv, EthSwt, DET, and DEM ([SWS_Eth_00241], [SWS_Eth_00120]).

Context diagram: Callers and callback receivers of the Ethernet driver. Sources: [SWS_Eth_00119], [SWS_Eth_00120], SWS Eth p. 17

Eth_Init disables the Rx/Tx communication of all configured controllers, configures them, and discards pending requests ([SWS_Eth_00027], [SWS_Eth_00275]). The asynchronous Eth_SetControllerMode switches between ETH_MODE_DOWN and ETH_MODE_ACTIVE ([SWS_Eth_91009], [SWS_Eth_00276]). During shutdown, the driver releases locked transmit buffers ([SWS_Eth_00280]). The result follows via EthIf_CtrlModeIndication, in polling mode from Eth_MainFunction ([SWS_Eth_00240]).

For transmission, the upper layer requests a buffer with Eth_ProvideTxBuffer and hands it over with Eth_Transmit ([SWS_Eth_00077], [SWS_Eth_00087]). The confirmation is E_OK or E_NOT_OK ([SWS_Eth_00243], [SWS_Eth_00256]). Eth_Receive reads frames from a FIFO and reports whether further frames are available ([SWS_Eth_00095], [SWS_Eth_00162]). Eth discards frames with a non-matching destination address ([SWS_Eth_00245], [SWS_Eth_00246]).

Sequence diagram: Buffer request, transmission, and confirmation in polling mode. Sources: [SWS_Eth_00077], [SWS_Eth_00087], [SWS_Eth_00243], SWS EthIf p. 87

Additional functions include MII accesses, which are asynchronous in R20-11 ([SWS_Eth_00058]), hardware timestamps ([SWS_Eth_00190]), statistics services ([SWS_Eth_00233]), and an optional Credit Based Shaper (DRAFT, [SWS_Eth_00263]). Eth reports errors as development errors to DET ([SWS_Eth_00016]). Production errors such as ETH_E_ACCESS or ETH_E_RX_FRAMES_LOST go to DEM ([SWS_Eth_00173], [SWS_Eth_00174]).

Role in the Ethernet stack and system boundary

The Ethernet driver Eth resides as a hardware-oriented module below the Ethernet Interface (EthIf). According to the diagram of the basic structure of the stack, EthIf bundles one or more Eth drivers from different vendors, each with its own controller types (SWS Eth p. 17). To the upper layers, Eth offers services such as Eth_Init, Eth_SetControllerMode, Eth_ProvideTxBuffer, Eth_Transmit, and Eth_Receive ([SWS_Eth_00027], [SWS_Eth_91009], [SWS_Eth_00077], [SWS_Eth_00087], [SWS_Eth_00095]). It reports results back via the callbacks EthIf_RxIndication, EthIf_TxConfirmation, and EthIf_CtrlModeIndication ([SWS_Eth_00244], [SWS_Eth_00243], [SWS_Eth_00119]).

Further neighbors are the following modules:

  • the transceiver driver, which is connected via MII indications ([SWS_Eth_00241], [SWS_Eth_00242]);
  • the switch driver with its management services such as EthSwt_EthRxProcessFrame ([SWS_Eth_00247], [SWS_Eth_00120]);
  • DET and DEM for error reporting ([SWS_Eth_00119], [SWS_Eth_00120]).

If multiple controllers share peripheral resources, Eth emulates independent controllers towards the upper layers. The upper layers then handle coordination ([SWS_Eth_00258]).

Context diagram: Eth is called by EthIf and EcuM and reports to EthIf, EthTrcv, EthSwt, DET, and DEM. Sources: [SWS_Eth_00119], [SWS_Eth_00120], [SWS_Eth_00241], SWS Eth p. 17

From Eth_Init to ETH_MODE_ACTIVE: startup and controller modes

Eth_Init receives a pointer to the post-build structure Eth_ConfigType ([SWS_Eth_00027], [SWS_Eth_00156]). For each controller of the current EthConfigSet, the function executes the following steps ([SWS_Eth_00275], DRAFT; older version [SWS_Eth_00034] obsolete):

  • disable Rx/Tx communication,
  • clear pending interrupts,
  • configure controller parameters and transmit/receive resources,
  • discard pending requests.

Eth_StateType distinguishes between ETH_STATE_UNINIT and ETH_STATE_INIT and serves development error detection ([SWS_Eth_00159]). Newer versions summarize the calling rule: Except for Eth_GetVersionInfo and planned functions such as Eth_MainFunction, services are permitted only after initialization (SWS Eth p. 27). R20-11 regulates this per service via checking for ETH_E_UNINIT, e.g. in [SWS_Eth_00066].

Sequence diagram: Startup with Eth_Init and an initial, asynchronously acknowledged MII access of the transceiver driver. Sources: [SWS_Eth_00275], [SWS_Eth_00058], [SWS_Eth_00241], SWS EthIf p. 84

In R20-11, Eth_SetControllerMode applies in the asynchronous, non-reentrant version [SWS_Eth_91009]; it replaces [SWS_Eth_00041]. The two modes take effect as follows ([SWS_Eth_00276]):

  • ETH_MODE_DOWN: The driver disables Rx/Tx and resets all buffers. Locked and pending transmit buffers are released ([SWS_Eth_00280], [SWS_Eth_00281]).
  • ETH_MODE_ACTIVE: The driver activates all buffers and Rx/Tx communication.

Eth reports the result of a mode switch asynchronously via EthIf_CtrlModeIndication ([SWS_Eth_00119]). In polling mode, Eth_MainFunction detects the switch and calls this callback ([SWS_Eth_00171], [SWS_Eth_00240]). Eth_GetControllerMode returns the current state ([SWS_Eth_91010], [SWS_Eth_00277]).

Eth_ModeType additionally knows ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST. With ETH_MODE_DOWN, the hardware can trigger a sleep sequence, for example with OA-TC10 hardware ([SWS_Eth_91008]). However, the parameter description of Eth_SetControllerMode only lists ETH_MODE_DOWN and ETH_MODE_ACTIVE ([SWS_Eth_91009]).

State diagram: Driver state UNINIT/INIT and, per controller, the modes DOWN and ACTIVE with the obligations during transition. Sources: [SWS_Eth_00159], [SWS_Eth_00275], [SWS_Eth_00276], [SWS_Eth_00280]

Sequence diagram: Activation by EthSM with synchronous acceptance and asynchronous mode indication. Sources: [SWS_Eth_91009], [SWS_Eth_00119], [SWS_Eth_00240], SWS EthIf p. 85

Transmit path: request buffer, transmit, confirm

Transmission proceeds in two stages. First, Eth_ProvideTxBuffer selects a transmit FIFO based on Priority. The service returns an index of type Eth_BufIdxType, a buffer pointer, and via LenBytePtr the granted length ([SWS_Eth_00077], [SWS_Eth_00175]). Possible return values are BUFREQ_OK, BUFREQ_E_NOT_OK, BUFREQ_E_BUSY, and BUFREQ_E_OVFL. The buffer remains locked until Eth_Transmit follows with this index (SWS Eth p. 91).

Then, Eth_Transmit initiates transmission with FrameType, destination MAC address, and the flag TxConfirmation ([SWS_Eth_00087], [SWS_Eth_00160]). In doing so, the driver constructs the Ethernet header (SWS Eth p. 93). Eth_Transmit is reentrant for different buffer and controller indices ([SWS_Eth_00087]).

If confirmation is requested, Eth calls EthIf_TxConfirmation with E_OK. In interrupt mode, this occurs from the interrupt routine; in polling mode, from Eth_TxConfirmation ([SWS_Eth_00243], [SWS_Eth_00100]). If transmission fails, the result is E_NOT_OK ([SWS_Eth_00256]). Upper layers can rely on each Eth_Transmit being followed by a confirmation (SWS Eth p. 32).

In the polling diagram, EthIf_MainFunctionTx calls the function Eth_TxConfirmation (SWS EthIf p. 87). In interrupt mode, Eth_TxIrqHdlr_<CtrlIdx> handles this (SWS EthIf p. 88). When the driver releases the buffer is left to the implementation (SWS Eth p. 93).

Sequence diagram: Request buffer, fill, transmit, and confirm in polling mode, with success and failure branches. Sources: [SWS_Eth_00077], [SWS_Eth_00087], [SWS_Eth_00243], [SWS_Eth_00256], SWS EthIf p. 87

Reception path and address filter

Eth_Receive reads a frame from the FIFO addressed via FifoIdx. The service is reentrant for different FIFOs, but not for the same one ([SWS_Eth_00095]). RxStatusPtr returns ETH_RECEIVED, ETH_NOT_RECEIVED, or ETH_RECEIVED_MORE_DATA_AVAILABLE ([SWS_Eth_00162]). Interpretation: A polling caller is likely to repeat Eth_Receive as long as additional frames are reported. Who calls in polling mode is not specified; presumably it is EthIf.

Eth reports reception via EthIf_RxIndication, either from the interrupt or from Eth_Receive ([SWS_Eth_00244]). Broadcast frames are indicated as such ([SWS_Eth_00153]). Newer versions name the parameter QueueIdx (SWS Eth p. 110).

The own source address is set by Eth_SetPhysAddr; Eth_GetPhysAddr reads it ([SWS_Eth_00151], [SWS_Eth_00052]). Eth_UpdatePhysAddrFilter adds multicast destination addresses to the receive filter with ETH_ADD_TO_FILTER and removes them with ETH_REMOVE_FROM_FILTER ([SWS_Eth_00152], [SWS_Eth_00163], [SWS_Eth_00150]).

If the destination address matches, Eth notifies the upper layer; otherwise, it discards the frame ([SWS_Eth_00245], [SWS_Eth_00246]). If the hardware cannot filter, initialization enables promiscuous mode ([SWS_Eth_00146]). The address 00:00:00:00:00:00 reduces the filter to the own unicast address and ends promiscuous mode ([SWS_Eth_00147]; cf. SWS Eth p. 74).

Activity diagram: Filter update with zero-address special case, hardware or software filtering, and acceptance or discarding upon reception. Sources: [SWS_Eth_00146], [SWS_Eth_00147], [SWS_Eth_00163], [SWS_Eth_00245], [SWS_Eth_00246]

Transceiver access, hardware timestamps, and diagnostic counters

Eth_WriteMii and Eth_ReadMii are asynchronous and non-reentrant in R20-11 ([SWS_Eth_00058], [SWS_Eth_00064]). Eth reports completion via EthTrcv_WriteMiiIndication or EthTrcv_ReadMiiIndication, respectively ([SWS_Eth_00241], [SWS_Eth_00242]). Clause 45 registers are accessed via registers 13 and 14 according to Annex 22D ([SWS_Eth_00273], [SWS_Eth_00274]). Access is enabled via EthCtrlEnableMii ([SWS_Eth_00069]). In contrast, R24-11 describes Eth_WriteMii as synchronous (SWS Eth p. 95); for R20-11, the asynchronous definition applies.

The timestamp functions are enabled via EthGlobalTimeSupport ([SWS_Eth_00210], [SWS_Eth_00211]). In detail, the following applies:

  • Eth_GetCurrentTime reads the hardware time as Eth_TimeStampType with 48-bit seconds plus nanoseconds ([SWS_Eth_00181], [SWS_Eth_00178]).
  • Eth_EnableEgressTimeStamp activates timestamping per buffer; disabling is not provided ([SWS_Eth_00186]; SWS Eth p. 111).
  • Eth_GetEgressTimeStamp and Eth_GetIngressTimeStamp read the timestamps in the context of TxConfirmation and RxIndication, respectively ([SWS_Eth_00190], [SWS_Eth_00195]; SWS Eth p. 89).

The upper layer discards timestamps of quality ETH_UNCERTAIN or ETH_INVALID ([SWS_Eth_00177]). Starting with R23-11, Eth_GetCurrentTime is obsolete (SWS Eth p. 82); in R20-11, the service is normative.

Four diagnostic services can each be enabled individually:

  • Eth_GetCounterValues ([SWS_Eth_00226], [SWS_Eth_00231]),
  • Eth_GetRxStats ([SWS_Eth_00233], [SWS_Eth_00238]),
  • Eth_GetTxStats ([SWS_Eth_91005], [SWS_Eth_00251]),
  • Eth_GetTxErrorCounterValues ([SWS_Eth_91006], [SWS_Eth_00255]).

For the statistical services, the maximum value indicates an unavailable counter (SWS Eth p. 98).

Configuration, Partitioning, and SW Buffer Management (CBS)

With EthCtrlEnableOffloadChecksumIPv4, EthCtrlEnableOffloadChecksumICMP, EthCtrlEnableOffloadChecksumTCP, and EthCtrlEnableOffloadChecksumUDP, the controller calculates checksums in hardware. Upon reception, it drops frames with an incorrect checksum ([SWS_Eth_00216], [SWS_Eth_00217]). The base addresses of the buffers must satisfy the alignment of all AUTOSAR data types ([SWS_Eth_00218]). Unsupported partition assignments must be rejected. The partitions in EthCtrlEcucPartitionRef must be a subset of EthEcucPartitionRef ([SWS_Eth_00257], [SWS_Eth_00260], [SWS_Eth_CONSTR_00001]).

If fair scheduling in hardware is missing, a Credit Based Shaper in software is available (SWS Eth p. 38). In R20-11, all associated requirements are DRAFT. The method operates as follows:

  • It is enabled with EthCtrlConfigSwBufferHandling ([SWS_Eth_00263]).
  • Each SW FIFO belongs to exactly one priority ([SWS_Eth_00265]).
  • Eth_ProvideTxBuffer remembers the priority, Eth_Transmit assigns the buffer to the matching FIFO ([SWS_Eth_00267], [SWS_Eth_00268]).
  • Eth_MainFunction updates the credits and moves messages into the HW FIFO ([SWS_Eth_00270], [SWS_Eth_00266], [SWS_Eth_00271]).
  • EthTrcvPhysLayerPLCAMaxBurstCount limits bursts ([SWS_Eth_00272]; SWS Eth p. 56).

Behavior in the event of an error

Eth reports development errors to DET ([SWS_Eth_00120]). The codes are ETH_E_INV_CTRL_IDX, ETH_E_UNINIT, ETH_E_PARAM_POINTER, ETH_E_INV_PARAM, and ETH_E_INV_MODE ([SWS_Eth_00016]). Typical checks concern initialization, CtrlIdx, and pointers ([SWS_Eth_00066], [SWS_Eth_00067], [SWS_Eth_00068]). If DET is disabled, the statistical services return E_NOT_OK in these cases ([SWS_Eth_00228], [SWS_Eth_00236], [SWS_Eth_00248], [SWS_Eth_00254]).

Production errors are sent to DEM via Dem_SetEventStatus ([SWS_Eth_00119]). A failed controller access results in ETH_E_ACCESS with DEM_EVENT_STATUS_PREFAILED; Eth_SetControllerMode then returns E_NOT_OK ([SWS_Eth_00039], [SWS_Eth_00173], [SWS_Eth_00168]). Eth_MainFunction reports the following extended production errors ([SWS_Eth_00169], [SWS_Eth_00172]):

  • ETH_E_RX_FRAMES_LOST ([SWS_Eth_00174]),
  • ETH_E_CRC ([SWS_Eth_00219]),
  • erroneous frame sizes and alignment ([SWS_Eth_00220], [SWS_Eth_00221], [SWS_Eth_00222]),
  • collisions ([SWS_Eth_00223], [SWS_Eth_00224], [SWS_Eth_00225]).

During operation, errors also manifest via return values. These include BUFREQ_E_BUSY and BUFREQ_E_OVFL (SWS Eth p. 91) as well as a negative transmit confirmation ([SWS_Eth_00256]). The behavior of Eth_Receive when the controller is inactive depends on the release. R23-11 and R24-11 require ETH_E_INV_MODE (SWS Eth p. 94, SWS Eth p. 116), R25-11 an immediate return (SWS Eth p. 110). For R20-11, the DET variant likely applies because of [SWS_Eth_00016].

The function Eth_SetControllerMode (Service ID 0x03, provided via Eth.h) serves to enable and disable receive and transmit communication (Rx/Tx) of a specific Ethernet controller [SWS_Eth_91009].

Usage and Call Conditions

Execution of the function is asynchronous and specified as non-reentrant (Non Reentrant) [SWS_Eth_91009]. Upon invocation, two parameters are passed:

  • CtrlIdx: Index of the respective controller in the context of the Ethernet driver [SWS_Eth_91009].
  • CtrlMode: Target mode for the controller, either ETH_MODE_ACTIVE to enable Rx/Tx communication or ETH_MODE_DOWN to disable it [SWS_Eth_91009].
