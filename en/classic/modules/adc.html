Controls the analog-to-digital converters of the microcontroller via channel groups and provides their raw values.

In the MCAL, the ADC driver encapsulates the analog-to-digital converters of the microcontroller and always converts channels as configured groups: software- or hardware-triggered, one-shot or continuous [SWS_Adc_00515]. After Adc_Init, users such as the IoHwAb start conversions. They detect completion via status query or notification, then read the raw values with Adc_ReadGroup or Adc_GetStreamLastPointer. Optionally, the driver supports two-stage power state transitions. Key boundary condition: Without a result buffer set up beforehand with Adc_SetupResultBuffer, no group conversion must start [SWS_Adc_91000].

The driver always converts channels as configured groups. Each group has three settings:

  • Trigger source: software or hardware [SWS_Adc_00514].
  • Conversion mode: one-shot or continuous; continuous only with software trigger [SWS_Adc_00515].
  • Access mode: single or streaming with linear or circular buffer [SWS_Adc_00528], [SWS_Adc_00519].

The group status shows the progress with ADC_IDLE, ADC_BUSY, ADC_COMPLETED, and ADC_STREAM_COMPLETED [SWS_Adc_00513].

State diagram: Group status for continuous streaming conversion; a linear buffer ends in ADC_IDLE after reading. Sources: SWS ADC p. 39

Software-triggered groups are started by Adc_StartGroupConversion and stopped by Adc_StopGroupConversion. Hardware-triggered groups are switched via Adc_EnableHardwareTrigger and Adc_DisableHardwareTrigger [SWS_Adc_00367], [SWS_Adc_91001]. The user detects completion by polling Adc_GetGroupStatus or via notification; the user must activate this separately SWS ADC p. 57. Unscaled raw values are read with Adc_ReadGroup or Adc_GetStreamLastPointer [SWS_Adc_00369], [SWS_Adc_00375].

Competing requests are governed by priority mechanism, queuing, and preemption strategy [SWS_Adc_00522], [SWS_Adc_00523]. Without both, the driver rejects a second request with ADC_E_BUSY [SWS_Adc_91006]. Optionally, the driver transitions power states in two stages: prepare with Adc_PreparePowerState, switch with Adc_SetPowerState. Asynchronous parts run in Adc_Main_PowerTransitionManager [SWS_Adc_00478], [SWS_Adc_00479].

Role of the ADC Driver Between IoHwAb and Converter Hardware

The ADC driver is the MCAL module for the analog-to-digital converters of the microcontroller. Adc_Init initializes ADC hardware units and the driver [SWS_Adc_00365]. All further services operate on channel groups that are addressed via a numerical ID (Adc_GroupType) [SWS_Adc_00507]. A typical user is the I/O Hardware Abstraction: It starts conversions on behalf of a sensor SWC and is notified via IoHwAb_AdcNotification<#groupID> after completion [SWS_Adc_00082], SWS IoHwAb p. 55. EcuM initializes the driver, for which Adc_Init is an optional interface SWS EcuM p. 142.

The driver resides at the lowest architectural level. It therefore offers no callbacks for lower modules SWS ADC p. 79. The ADC API does not access hardware result registers directly. Results always reach the user via application buffers SWS ADC p. 27. The driver reports errors via Det_ReportError [SWS_Adc_00377]. The cited document passages originate predominantly from R23-11 to R25-11. The requirements are normative for R20-11.

Context diagram: The ADC driver mediates between EcuM, IoHwAb, DET, and the converter peripheral; notifications flow upward only. Sources: SWS IoHwAb p. 55, [SWS_Adc_00082], [SWS_Adc_00480], [SWS_Adc_00377]

The implementation must reject configurations with unsupported partition assignments [SWS_Adc_00531]. The partitions referenced via AdcKernelEcucPartitionRef must be a subset of the partitions of AdcEcucPartitionRef [SWS_Adc_CONSTR_00001]. Interpretation: This is likely based on the division into an interrupt-related kernel part and an interface part, as shown by the memory mapping example for Adc SWS MemMap p. 57.

Lifecycle: Initialization, Result Buffer, and Deinitialization

After reset, the driver is in ADC_UNINIT. Adc_Init leads to ADC_INIT, Adc_DeInit leads back SWS ADC p. 31. Adc_Init is synchronous and non-reentrant. In variant PB, ConfigPtr points to the configuration set; variant PC requires NULL_PTR [SWS_Adc_00365]. Adc_ConfigType is an implementation-specific structure [SWS_Adc_00505]. The configurator creates symbolic names for channels and groups in the configuration header SWS ADC p. 123.

State diagram: Adc_Init and Adc_DeInit switch between ADC_UNINIT and ADC_INIT; one-shot and continuous are configuration options per group. Sources: SWS ADC p. 31, SWS ADC p. 91

After each reset, the user must pass the start address of the result buffer using Adc_SetupResultBuffer prior to the first conversion of a group. The application ensures that the buffer can hold all results of the group [SWS_Adc_91000]. No conversion may start without a validly initialized buffer pointer SWS ADC p. 54.

Adc_DeInit brings all HW units into a state comparable to power-on reset [SWS_Adc_00366]. The service disables all used interrupts and notifications. It is only permitted if all groups are in ADC_IDLE, and can be disabled via AdcDeInitApi SWS ADC p. 59.

Channel Groups: Trigger, Conversion Mode, and Access Mode

A group bundles channels [SWS_Adc_00517], [SWS_Adc_00506]. It is configured along three axes:

  • Trigger source: ADC_TRIGG_SRC_SW or ADC_TRIGG_SRC_HW [SWS_Adc_00514].
  • Conversion mode: ADC_CONV_MODE_ONESHOT converts each channel exactly once per trigger. ADC_CONV_MODE_CONTINUOUS converts continuously and is only possible with a software trigger [SWS_Adc_00515].
  • Access mode: ADC_ACCESS_MODE_SINGLE or ADC_ACCESS_MODE_STREAMING [SWS_Adc_00528]. For streaming, Adc_StreamNumSampleType defines the number of rounds [SWS_Adc_00518]. A linear buffer stops the conversion as soon as it is full; a circular buffer wraps around [SWS_Adc_00519].

Prescaler, conversion time, sampling time, and resolution are not API types [SWS_Adc_00509], [SWS_Adc_00510], [SWS_Adc_00511], [SWS_Adc_00512]. For hardware triggers, the edge and timer reload can be set if supported by the hardware [SWS_Adc_00520], [SWS_Adc_00521]. Results are unscaled raw values, aligned left or right [SWS_Adc_00508], [SWS_Adc_00525].

The progress of a group is described by Adc_StatusType [SWS_Adc_00513]:

  • ADC_IDLE: not started.
  • ADC_BUSY: conversion in progress.
  • ADC_COMPLETED: one round is completed, but not the last one.
  • ADC_STREAM_COMPLETED: result buffer complete.

The transitions depend on the configuration SWS ADC p. 39.

State diagram: Group status during continuous, software-triggered conversion with streaming; linear buffer ends in ADC_IDLE after reading, circular buffer continues running. Sources: SWS ADC p. 39, SWS ADC p. 70, [SWS_Adc_00513]

From Start to Result: Typical Conversion Sequences

In the simplest case, a one-shot conversion takes place in three steps SWS ADC p. 91:

  1. Adc_StartGroupConversion starts the group asynchronously [SWS_Adc_00367].
  2. Adc_GetGroupStatus queries the status [SWS_Adc_00374].
  3. Adc_ReadGroup reads the results [SWS_Adc_00369].

The start resets the buffer pointer to the base address. It does not automatically enable the notification SWS ADC p. 57.

Sequence diagram: Set up buffer, start, poll status, read. Sources: SWS ADC p. 91, [SWS_Adc_91000]

Instead of polling, the user can call Adc_EnableGroupNotification in advance [SWS_Adc_91003]. This service is enabled by AdcGrpNotifCapability SWS ADC p. 67. In continuous conversion, the driver reports each completed round. This only ends with Adc_StopGroupConversion [SWS_Adc_00368], SWS ADC p. 92.

Sequence diagram: For each completed round, notification and reading follow until the user stops. Sources: SWS ADC p. 92, [SWS_Adc_00082]

Hardware-triggered groups are enabled by Adc_EnableHardwareTrigger [SWS_Adc_91001]. Thereafter, the group converts upon each trigger event SWS ADC p. 62. Adc_DisableHardwareTrigger [SWS_Adc_91002] has several effects SWS ADC p. 65:

  • It removes pending requests.
  • It aborts an ongoing conversion if supported by the hardware.
  • It disables the notification.
  • It sets the group to ADC_IDLE.

With linear streaming, the trigger is disabled as soon as the buffer is full SWS ADC p. 95.

Sequence diagram: Each trigger event initiates a conversion; notifications are only issued if notification is active. Sources: SWS ADC p. 93

There are two ways to read:

  • Adc_ReadGroup copies the values of the last complete round in ascending channel order. If no results are available, it returns E_NOT_OK [SWS_Adc_00369], SWS ADC p. 61.
  • Adc_GetStreamLastPointer returns the number of valid samples per channel and a pointer to the most recent result of the first group channel [SWS_Adc_00375]. The user must account for the channel-wise buffer layout themselves SWS ADC p. 27.

Competing Groups: Priority, Queuing, and Preemption

Simultaneous requests are governed by Adc_PriorityImplementationType: no mechanism, hardware only, or hardware and software [SWS_Adc_00522]. Priorities range from 0 (lowest) to 255 [SWS_Adc_00516]. If a group is interrupted by a higher-priority group, its round restarts (ADC_GROUP_REPL_ABORT_RESTART) or is resumed (ADC_GROUP_REPL_SUSPEND_RESUME). In both cases, results of earlier rounds are preserved [SWS_Adc_00523].

Without priority and without queuing, the driver rejects a second request with ADC_E_BUSY SWS ADC p. 95. With software queuing, it stores the request and starts it later SWS ADC p. 96. With prioritization, the higher-priority group preempts the running one SWS ADC p. 97, SWS ADC p. 98. Adc_StopGroupConversion also removes a pending start request SWS ADC p. 58.

Activity diagram: Whether a request is rejected, stored, or prioritized when the converter is busy depends on the priority mechanism and queuing. Sources: [SWS_Adc_00522], [SWS_Adc_00523], SWS ADC p. 99

Power States of the ADC Hardware

Power control is optional and restricted to the ADC peripheral. Architectural constraints are fulfilled by the upper layers; the driver only checks the invocation sequence SWS ADC p. 39. Adc_PowerStateType defines ADC_FULL_POWER (0) and states 1..255 with decreasing power consumption [SWS_Adc_00526]. The result of each request is reported by Adc_PowerStateRequestResultType [SWS_Adc_00527].

The transition takes place in two stages:

  1. Prepare: Adc_PreparePowerState starts the preparation [SWS_Adc_00478]. Asynchronous parts run in the cyclic Adc_Main_PowerTransitionManager [SWS_Adc_00498], [SWS_Adc_00479]. Its period is defined by AdcMainSchedulePeriod [SWS_Adc_00500]. In asynchronous mode, it reports readiness via IoHwAb_Adc_NotifyReadyForPowerState<#Mode> [SWS_Adc_00501], [SWS_Adc_00480].
  2. Switch: Adc_SetPowerState activates the prepared state [SWS_Adc_00475]. Preparatory actions such as idling channels are the responsibility of the users. There are no implicit intermediate states SWS ADC p. 81.

Sequence diagram: Asynchronous power state transition, coordinated by the IoHwAb. Sources: SWS IoHwAb p. 57, SWS IoHwAb p. 57, [SWS_Adc_00479]

The following presumably also applies to Adc_SetPowerState: The normal state uses the same configuration containers as Adc_Init, while other states only use transition-specific reconfigurations [SWS_Adc_00483], [SWS_Adc_00484], [SWS_Adc_00485]. Adc_GetCurrentPowerState and Adc_GetTargetPowerState return current and target states [SWS_Adc_00476], [SWS_Adc_00477]. Without an ongoing transition, both match SWS ADC p. 77.

Behavior in the event of an error

The driver reports development errors via Det_ReportError [SWS_Adc_00377]. [SWS_Adc_91005] mentions, among others:

  • ADC_E_UNINIT
  • ADC_E_ALREADY_INITIALIZED
  • ADC_E_PARAM_POINTER
  • ADC_E_PARAM_GROUP
  • ADC_E_WRONG_CONV_MODE
  • ADC_E_WRONG_TRIGG_SRC
  • ADC_E_NOTIF_CAPABILITY

Two examples: In case of an unknown group, the notification services report ADC_E_PARAM_GROUP and return without effect SWS ADC p. 68. Adc_GetVersionInfo checks its pointer for NULL SWS ADC p. 80.

Runtime errors are ADC_E_BUSY (conversion running, trigger active, or request already queued), ADC_E_IDLE, ADC_E_NOT_DISENGAGED, and ADC_E_TRANSITION_NOT_POSSIBLE [SWS_Adc_91006]. Services with a return value additionally report failure with E_NOT_OK, such as Adc_ReadGroup and Adc_SetupResultBuffer [SWS_Adc_00369], [SWS_Adc_91000].

Specific errors apply to power control:

  • ADC_E_UNINIT: Call prior to initialization [SWS_Adc_00486], [SWS_Adc_00496].
  • ADC_E_POWER_STATE_NOT_SUPPORTED: State not supported [SWS_Adc_00488], [SWS_Adc_00497].
  • ADC_E_TRANSITION_NOT_POSSIBLE: Target state not directly reachable [SWS_Adc_00489], [SWS_Adc_00498].
  • ADC_E_NOT_DISENGAGED: Channels still active or notifications still registered [SWS_Adc_00487].

Result also distinguishes between ADC_SEQUENCE_ERROR and ADC_HW_FAILURE [SWS_Adc_00527]. Prior to initialization, Adc_Main_PowerTransitionManager returns without a DET report [SWS_Adc_00502].
