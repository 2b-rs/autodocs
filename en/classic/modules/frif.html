FrIf as an intermediary between FlexRay stack and hardware drivers

The FlexRay Interface encapsulates the FlexRay driver (Fr) and the transceiver driver (FrTrcv) from the modules of the communication stack. Most control services are thin wrappers. For example, FrIf_StartCommunication translates the FrIf-wide controller index into the tuple (FlexRay driver | driver-specific Fr_CtrlIdx) based on the static configuration. Afterward, it calls Fr_StartCommunication() of the determined driver ([SWS_FrIf_05005], SWS FrIf p. 56). The required driver services are specified as mandatory and optional interfaces ([SWS_FrIf_05043], [SWS_FrIf_05044]). Among them are the CC-CHI commands 'FREEZE', 'DEFERRED_HALT', 'WAKEUP', and 'ALL_SLOTS'.

The users access different parts of the interface:

  • FrSM controls controllers and clusters via functional elements such as FE_CONFIG, FE_START, and FE_HALT (SWS FrSM p. 22).
  • The PduR accepts received I-PDUs and forwards them to Com (SWS PduR p. 98).
  • FrNm transmits NM-Vote and NM-Data via FrIf_Transmit and reads the cycle via FrIf_GetGlobalTime (SWS FrNm p. 38).
  • FrTp also transmits its N-PDUs via FrIf_Transmit (SWS FrTp p. 20).
  • FrTSyn uses state and time services (SWS FrTSyn p. 13).

From FrIf_Init to the synchronized cluster

FrIf_Init receives a pointer to FrIf_ConfigType ([SWS_FrIf_05003], [SWS_FrIf_05301]). The function sets the FrIf_State of each cluster to FRIF_STATE_OFFLINE (SWS FrIf p. 25). In the initialization sequence, EcuM calls FrIf_Init before FrSm_Init (SWS FrSM p. 46).

FrSM handles the startup. It calls FrIf_ControllerInit, FrIf_StartCommunication, and FrIf_AllowColdstart for each controller of the cluster ([SWS_FrIf_05004], [SWS_FrIf_05017]). FrIf_AllowColdstart follows only upon FrSMIsColdstartEcu and can be delayed via timer t1 (SWS FrSM p. 21).

Start, coldstart enable, wakeup, and halt are asynchronous ([SWS_FrIf_05011], [SWS_FrIf_05006]). In this context, E_OK merely states that the driver call returned E_OK. FrSM queries the actual protocol state cyclically via FrIf_GetPOCStatus until FR_POCSTATE_NORMAL_ACTIVE is reached. Only after that does it request FRIF_GOTO_ONLINE ([SWS_FrIf_05014], SWS FrSM p. 50).

Sequence diagram: Only a POC state NORMAL_ACTIVE confirmed by polling switches the FrIf cluster online. Sources: SWS FrSM p. 46, SWS FrSM p. 50, [SWS_FrIf_05005]

Several services are available for wakeup:

  • FrIf_SendWUP sends the wakeup pattern.
  • For dual-channel nodes, FrIf_SetWakeupChannel selects the wakeup channel. FR_CHANNEL_AB must not be used for this ([SWS_FrIf_05010], SWS FrIf p. 61).
  • FrIf_SetTransceiverMode, FrIf_GetTransceiverWUReason, and FrIf_GetWakeupRxStatus provide transceiver control and wakeup reason ([SWS_FrIf_05034], [SWS_FrIf_05036], [SWS_FrIf_05102]).
  • In sleep, the EcuM integration checks a bus wakeup via FrIf_CheckWakeupByTransceiver ([SWS_FrIf_05041], SWS EcuM p. 178).

Sequence diagram: A dual-channel node with a local wakeup reason activates both transceivers, sets channel A as the wakeup channel, and transmits the WUP. Interpretation: The call order is reconstructed from the figure text. Sources: SWS FrSM p. 52, SWS FrSM p. 22

Cluster state ONLINE/OFFLINE as a switch for communication services

There are exactly two states per cluster, FRIF_STATE_OFFLINE and FRIF_STATE_ONLINE ([SWS_FrIf_05755]). Transitions are requested using FrIf_SetState and a value from FrIf_StateTransitionType ([SWS_FrIf_05174], [SWS_FrIf_05303]). FRIF_GOTO_ONLINE takes effect only from OFFLINE, FRIF_GOTO_OFFLINE only from ONLINE; any other request does not trigger a transition (SWS FrIf p. 25).

FrIf_GetState is reentrant, whereas FrIf_SetState is not ([SWS_FrIf_05170], SWS FrIf p. 63). Both services expect a cluster index FrIf_ClstIdx. Some FrSM diagrams label the parameter with "CtrlIdx"; the signature is authoritative.

In the OFFLINE state, FrIf_Transmit rejects transmit requests with E_NOT_OK (SWS FrIf p. 68). When transitioning to OFFLINE, FrIf reports back every PDU with TxConfCounter > 0 via <UL>_TxConfirmation(id, E_NOT_OK) ([SWS_FrIf_05501]). An older diagram additionally shows the states HALT and RXONLY. These do not apply to R20-11, because [SWS_FrIf_05755] only knows two literals (SWS FrIf (alt) p. 28).

State diagram: The cluster life cycle starts in OFFLINE and transitions only upon explicit request. Sources: [SWS_FrIf_05755], [SWS_FrIf_05303], [SWS_FrIf_05501], SWS FrIf p. 25

Job List Execution: time-controlled transmission and reception

For each cluster, there is a job list execution function FrIf_JobListExec_<FrIfCluster.ShortName> and a main function ([SWS_FrIf_05040], [SWS_FrIf_05042]). The main function is called cyclically by the BSW Scheduler. In the ONLINE state, it monitors the continuous execution of the job list including (re-)synchronization (SWS FrIf p. 26). The diagrams show an ISR as the trigger, and the FrIfJobList references a FrIfAbsTimer. Presumably, an absolute timer interrupt therefore triggers the job list (SWS FrIf p. 125).

There are two buffer modes for transmission via FrIf_Transmit ([SWS_FrIf_05033]):

  • For immediate PDUs, the data goes directly to Fr_TransmitTxLPdu. For a fixed length, it is checked against the configuration ([SWS_FrIf_05757], SWS FrIf p. 106).
  • With decoupled access, FrIf_Transmit only flags the PDU. The data is only fetched by the job list via <UL_TriggerTransmit> ([SWS_FrIf_05047], SWS FrIf p. 107).

Sequence diagram: With decoupled transmission, the transmit request and data retrieval lie in separate contexts; counters safeguard retry and cancellation. Sources: SWS FrIf p. 107, SWS FrIf p. 102

The job list determines transmit confirmations via Fr_CheckTxLPduStatus. It then decrements TxConfCounter and calls <UL_TxConfirmation> ([SWS_FrIf_05046], SWS FrIf p. 112). Upon reception, Fr_ReceiveRxLPdu reads the frame into a temporary buffer. FrIf then checks the update bit for each PDU. <UL_RxIndication> follows either immediately (ReceiveAndIndicate) or later from the FrIf buffer ([SWS_FrIf_05045], SWS FrIf p. 115, SWS FrIf p. 117).

Further operations of the job list:

  • Prepare LPdu reconfigures hardware buffers if necessary (SWS FrIf p. 113).
  • <Free_Op_A> and <Free_Op_B> integrate user-defined operations ([SWS_FrIf_05316], [SWS_FrIf_05317]).
  • FrIf reports transmit conflicts via <UL_TxConflictNotification> ([SWS_FrIf_91001]).

The ONLINE check per operation is explicitly substantiated only in later versions (SWS FrIf p. 41). However, it matches the R20-11 state description in [SWS_FrIf_05755].

Activity diagram: With Receive-and-Indicate, cluster state, reception status, and update bit determine forwarding. Sources: SWS FrIf p. 115, SWS FrIf p. 41, [SWS_FrIf_05045]

Time base, timers, and status services for neighboring modules

FrIf_GetGlobalTime provides the cycle and macrotick. The service may be called within an exclusive area ([SWS_FrIf_05015], SWS FrIf p. 64). FrTSyn only calls it if FrIf_GetState reports the state FRIF_STATE_ONLINE; only then is the time information valid (SWS FrTSyn p. 19). Macroticks per cycle, macrotick duration, and cycle length originate from the static configuration ([SWS_FrIf_05018], [SWS_FrIf_05019], [SWS_FrIf_05239]).

Sequence diagram: A FrTSyn time slave reads the FlexRay time only after a positive ONLINE check. Sources: SWS FrTSyn p. 38, SWS FrTSyn p. 19, [SWS_FrIf_05434]

Absolute timers are set, stopped, enabled, disabled, acknowledged, and queried via dedicated services ([SWS_FrIf_05021], [SWS_FrIf_05023], [SWS_FrIf_05025], [SWS_FrIf_05031], [SWS_FrIf_05029], [SWS_FrIf_05027]). For the same CC, these services are non-reentrant. For diagnostics and FrSM, channel status, clock correction, sync frame list, startup frames, and NM vector are available ([SWS_FrIf_05030], [SWS_FrIf_05071], [SWS_FrIf_05072], [SWS_FrIf_05073], [SWS_FrIf_05016]). In key slot only mode, FrIf_AllSlots enables full slot operation ([SWS_FrIf_05020], SWS FrSM p. 57).

Indices, Configuration, and Optional Services

FrIf operates with three index spaces:

  • FrIf_CtrlIdx addresses the CC and is translated into the driver index.
  • FrIf_ClstIdx addresses the cluster, for example in FrIf_EnableBusMirroring ([SWS_FrIf_05726]).
  • FrIf_ChnlIdx addresses the channel. For transceiver services, FR_CHANNEL_AB is not permitted (SWS FrIf p. 69).

FrIf_ConfigType is an implementation-specific post-build structure from which only pointers may be used (SWS FrIf p. 50).

Many additional services can be enabled or disabled at compile time. These include FrIf_DisableLPdu via FrIfDisableLPduSupport ([SWS_FrIf_05710], SWS FrIf p. 84) and FrIf_CancelTransmit via FrIfCancelTransmitSupport ([SWS_FrIf_05070], SWS FrIf p. 88). Bus mirroring returns E_NOT_OK if it is globally disabled (SWS FrIf p. 92). At runtime, L-PDUs can be reconfigured via FrIf_ReconfigLPdu and CC parameters can be read via FrIf_ReadCCConfig ([SWS_FrIf_05048], [SWS_FrIf_05313]).

Behavior in the event of an error

FrIf reports development errors only when FrIfDevErrorDetect = ON, specifically to Det_ReportError (SWS FrIf p. 59). The codes include FRIF_E_INV_CTRL_IDX, FRIF_E_INV_CLST_IDX, FRIF_E_INV_CHNL_IDX, FRIF_E_PARAM_POINTER, FRIF_E_UNINIT, and FRIF_E_INV_FRIF_STATE, among others ([SWS_FrIf_05145], [SWS_FrIf_05037]). The wrappers return E_NOT_OK if the driver returns E_NOT_OK or a development error was detected ([SWS_FrIf_05004]).

If Job List Execution loses synchronization with the global time, FrIf reports the runtime error FRIF_E_JLE_SYNC ([SWS_FrIf_05432], SWS FrIf p. 45). Errors in the NIT, symbol window, and ACS per channel are reported as production errors via Dem_SetEventStatus with DEM_EVENT_STATUS_PREFAILED to the DEM ([SWS_FrIf_05146], [SWS_FrIf_05426], [SWS_FrIf_05428]). However, the text of [SWS_FrIf_05430] mentions FRIF_E_SW_CH_B instead of FRIF_E_ACS_CH_B in the criterion; this is an inconsistency in the requirement.

There are two ways to shut down. FrIf_AbortCommunication is synchronous and triggers 'FREEZE', whereas FrIf_HaltCommunication triggers the delayed 'DEFERRED_HALT' ([SWS_FrIf_05007], SWS FrIf p. 94). During regular shutdown, the FrSM takes the cluster offline and stops the controller. Subsequently, it switches the transceivers to standby and reinitializes the controllers (SWS FrSM p. 58).

Usage and Semantics

The function FrIf_EnableAbsoluteTimerIRQ ([SWS_FrIf_05025], Service ID 0x1d) is a synchronous service of the FlexRay Interface and is provided via the header file FrIf.h. The service encapsulates the API function Fr_EnableAbsoluteTimerIRQ() of the underlying FlexRay driver for activating the interrupt for an absolute timer.

When calling, the following input parameters must be passed:

  • FrIf_CtrlIdx: Index of the FlexRay Communication Controller (CC) to be addressed.
  • FrIf_AbsTimerIdx: Index of the absolute timer to be activated.

Return Values and Error Handling

The return value is of type Std_ReturnType ([SWS_FrIf_05025]):

  • E_OK: The call to the driver API Fr_EnableAbsoluteTimerIRQ() was executed successfully and returned E_OK.
  • E_NOT_OK: The API call of the FlexRay driver reported E_NOT_OK or an error was detected in development mode (Development Mode).

Concurrency and Limitations

Regarding concurrency behavior, the following applies according to [SWS_FrIf_05025]:

  • Non-reentrant for the same FlexRay CC (same FrIf_CtrlIdx).
  • Reentrant for different FlexRay CCs (different FrIf_CtrlIdx).

The synchronous interface function FrIf_AckAbsoluteTimerIRQ ([SWS_FrIf_05029], Service ID 0x21) acts as a wrapper for the FlexRay driver API Fr_AckAbsoluteTimerIRQ() and is used to acknowledge the interrupt of an absolute timer.

The function is provided via the header file FrIf.h and executed synchronously ([SWS_FrIf_05029]). It accepts two input parameters:

  • FrIf_CtrlIdx: Index of the FlexRay Communication Controller (CC) to be addressed.
