Provides hardware-independent IP network services, frame abstraction, and driver control for Ethernet communication.

The Ethernet Services module cluster, with Eth, EthIf, and TcpIp, provides the standardized communication infrastructure for Ethernet networks in AUTOSAR Classic ([SWS_Eth_00077], [SWS_TCPIP_00056]). It handles data transmissions via a two-stage buffering and confirmation procedure and transparently routes incoming frames to upper socket layers via VLAN and IP filters ([SWS_EthIf_00075], [SWS_TCPIP_00169]). Robust operating modes, TC10 wakeup routines, and comprehensive RFC diagnostic counters ensure deterministic vehicle operation ([SWS_EthIf_00034], [SWS_Eth_00226]).

In the AUTOSAR Classic Platform (R20-11), the “Ethernet Services” module cluster provides the complete protocol and abstraction chain for packet-based in-vehicle networks. It comprises the modules Eth (MCAL controller driver), EthIf (hardware-independent interface abstraction and VLAN management), and TcpIp (network and transport layer with IPv4/IPv6, TCP, UDP, and ARP) ([SWS_Eth_00077], [SWS_EthIf_00075], [SWS_TCPIP_00056]). Via standardized interfaces, the cluster integrates upper layers such as the Socket Adaptor (SoAd) for service-oriented communication and DoIP (SWS_TcpIp p. 123).

Context diagram: Layered architecture and system context of the Ethernet Services cluster with module interactions. Sources: SWS_TcpIp p. 123, AUTOSAR_SWS_EthernetInterface p. 87, [SWS_EthIf_00075]

During transmission, the data path relies on a coordinated buffering concept: upper layers request hardware resources synchronously via EthIf_ProvideTxBuffer(), whereupon Eth locks the buffer ([SWS_Eth_00077]). After filling, EthIf_Transmit() triggers the transmission, adds VLAN tags, and passes the data via Eth_Transmit() to the MAC controller ([SWS_Eth_00087], [SWS_EthIf_00075]). Confirmation occurs asynchronously, either via interrupt or cyclically via EthIf_MainFunctionTx() ([SWS_EthIf_00091], [SWS_EthIf_00115]). Incoming frames are received via EthIf_RxIndication() and, after controller and address validation, passed via <Up_RxIndication>() to the responsible socket ([SWS_EthIf_00085], [SWS_TCPIP_00169], [SWS_TCPIP_00223]).

Lifecycle and network operation are managed via controller states (EthIf_SetControllerMode()) and communication modes (TcpIp_RequestComMode()) ([SWS_EthIf_00034], [SWS_TCPIP_00070]). The cluster supports wakeup validations according to OPEN Alliance TC10 via EthIf_CheckWakeup() ([SWS_EthIf_00244], SWS_ECUStateManager p. 192). For diagnostics and error detection, Eth and EthIf provide standardized RFC error counters, signal quality measurements, and DET runtime checks ([SWS_Eth_00226], [SWS_EthIf_91056], [SWS_Eth_00228]).

System architecture and role of the module cluster

In the AUTOSAR Classic Platform (Release R20-11), the “Ethernet Services” module cluster forms the functional backbone for wired, packet-based communication via Ethernet networks. It spans an end-to-end abstraction arc from the hardware-near driver layers of the Microcontroller Abstraction Layer (MCAL) via the ECU Abstraction Layer up to the standardized Internet transport and routing protocols in the Communication Services layer. The cluster addresses the increased bandwidth requirements of modern E/E architectures and seamlessly integrates standard vehicle protocols such as Diagnostic communication over IP (DoIP according to ISO 13400) and service-oriented communication (SOME/IP) into the AUTOSAR basic software by serving upper layers such as the Socket Adaptor (SoAd) SWS_TcpIp p. 123.

The three core modules of the cluster each assume clearly defined architectural responsibilities:

  • Ethernet Driver (Eth): As an MCAL module, Eth directly controls the Ethernet MAC controller. It manages the hardware-near transmit and receive buffer descriptors, controls MII/MDIO register interfaces for transceiver configuration ([SWS_Eth_00058]), activates physical filter rules ([SWS_Eth_00152]), and provides high-precision hardware timestamps for global time synchronization mechanisms ([SWS_Eth_00186], [SWS_Eth_00190]).
  • Ethernet Interface (EthIf): Forms the central abstraction layer and decouples upper layers from the physical hardware topology. EthIf abstracts multiple Ethernet controllers, switches, and transceivers (PHYs). It handles virtual LAN processing (VLAN tagging according to IEEE 802.1Q), frame type multiplexing, buffer assignments, and the aggregation of switch port groups and link states ([SWS_EthIf_00075], [SWS_EthIf_91102], AUTOSAR_CP_SWS_EthernetInterface p. 213).
  • TCP/IP Stack (TcpIp): Implements the Internet protocol family as a communication service. The module encompasses IPv4 and IPv6, dynamic address assignment via Auto-IP (RFC 3927) and DHCPv6 (RFC 3315) ([SWS_TCPIP_00057], [SWS_TCPIP_00166]), address resolution via ARP (RFC 826) ([SWS_TCPIP_00056]), connectionless transport via UDP, and connection-oriented, reliable byte-stream transport via TCP ([SWS_TCPIP_00050]). Furthermore, it enables transport encryption via TLS ([SWS_TCPIP_00300]).

Interplay and Interaction Paths Between the Modules

The data transmission path (Transmission Path) is based on a two-stage buffer request and transmission procedure that supports a zero-copy design of the network card buffers. An upper protocol entity or the module TcpIp requests a contiguous memory buffer via EthIf_ProvideTxBuffer(), specifying priority and desired frame length ([SWS_Eth_00077], AUTOSAR_SWS_EthernetInterface p. 87). EthIf delegates this request to the corresponding driver by means of Eth_ProvideTxBuffer(), causing the driver to lock the hardware buffer and return a descriptor index (Eth_BufIdxType) as well as the buffer pointer ([SWS_Eth_00077]). After payload population, the calling layer initiates transmission via EthIf_Transmit() ([SWS_EthIf_00075]). When appropriately configured, EthIf inserts the VLAN tag (EtherType 0x8100) and calls Eth_Transmit(), whereupon the driver constructs the Ethernet header, sets the destination MAC address, and transfers the transmission request to the MAC controller ([SWS_Eth_00087], [SWS_EthIf_00250]).

Sequence diagram: Buffer allocation, data transmission, and asynchronous transmit confirmation in the Ethernet cluster. Sources: [SWS_Eth_00077], [SWS_Eth_00087], [SWS_EthIf_00075], [SWS_EthIf_00091]

The reception path (Reception Path) processes incoming Ethernet frames either event-driven from an interrupt or polling-based. After reading the buffer from the hardware queue using Eth_Receive() ([SWS_Eth_00095], [SWS_Eth_00162]), the driver signals the packet to the interface via EthIf_RxIndication() ([SWS_EthIf_00085]). EthIf verifies the validity of the controller and any VLAN tags, filters invalid datagrams ([SWS_EthIf_00309]), and forwards the frame to the assigned upper layer based on the EtherType. Received IP packets are handled by TcpIp, which evaluates the frame based on the referenced receive PDU (TcpIpCtrlRxPdu) and the metadata ([SWS_TcpIp_00411], [SWS_TcpIp_00412]). If the interface and destination IP fulfill the assignment conditions to the local address table ([SWS_TCPIP_00169]), the packet is unpacked and passed synchronously to the responsible socket owner (e.g., SoAd) via the interface <Up_RxIndication>() ([SWS_TCPIP_00220], [SWS_TCPIP_00223]).

Sequence diagram: Frame reception path and packet dispatching up to the socket layer. Sources: [SWS_Eth_00095], [SWS_EthIf_00085], [SWS_TCPIP_00169], [SWS_TCPIP_00223]

In the area of address resolution and packet filtering, TcpIp and Eth interact closely via EthIf. If TcpIp discovers new address relationships via incoming packets or ARP replies, it updates the ARP cache ([SWS_TCPIP_00056], [SWS_TcpIp_00092]) and reports changes via Up_PhysAddrTableChg() ([SWS_TCPIP_00142]). In the absence of a MAC address, TcpIp_GetRemotePhysAddr() initiates an address resolution ([SWS_TCPIP_00137]). To limit network broadcasts and multicast traffic, EthIf configures hardware-supported hash filters or tables in the MAC controller via Eth_UpdatePhysAddrFilter() in order to selectively forward or drop multicast frames on Layer 2 ([SWS_Eth_00152], [SWS_Eth_00245]).

Synchronization, reentrancy and task contexts

The module cluster supports two operating modes for temporal decoupling: polling mode and interrupt mode. In polling mode, the cyclic function EthIf_MainFunctionTx() at task level handles querying completed transmission processes by calling Eth_TxConfirmation() for all configured drivers ([SWS_EthIf_00115], AUTOSAR_SWS_EthernetInterface p. 87). Similarly, receive queues are drained via periodic calls of Eth_Receive() in the task context ([SWS_Eth_00095]). In interrupt mode, transmit and receive ISRs (Eth_TxIrqHdlr_<CtrlIdx>(), Eth_RxIrqHdlr_<CtrlIdx>()) report events directly from the interrupt context to EthIf_TxConfirmation() and EthIf_RxIndication() ([SWS_EthIf_00091], AUTOSAR_SWS_EthernetInterface p. 88, SWS_EthernetInterface p. 173). The cyclic state monitoring of transceiver and switch connections takes place decoupled in EthIf_MainFunctionState() (AUTOSAR_CP_SWS_EthernetInterface p. 213).

The reentrancy requirements are precisely tailored to multi-core and multitasking systems. Eth_ProvideTxBuffer() is designed to be fully reentrant ([SWS_Eth_00077]). The transmit APIs Eth_Transmit() and EthIf_Transmit() are reentrant for different controller and buffer indices ([SWS_Eth_00087], [SWS_EthIf_00075]). In contrast, control functions such as Eth_SetPhysAddr() or Eth_UpdatePhysAddrFilter() are non-reentrant for the same controller, but may be executed concurrently for different controllers ([SWS_Eth_00151], [SWS_Eth_00152]). Status acquisitions and hardware timestamp queries (e.g., Eth_GetCurrentTime() and EthIf_GetCurrentTime(), respectively) are explicitly specified for invocation within exclusive areas in order to ensure jitter-free timestamp consistency for protocols such as gPTP (IEEE 802.1AS) (SWS_EthernetDriver p. 82, SWS_EthernetInterface p. 140).

Typical lifecycles and operating modes

The lifecycle of the cluster requires a strict initialization sequence, which is typically controlled by the ECU State Manager (EcuM): first, the hardware-near driver is initialized by means of Eth_Init(), followed by EthIf_Init(), and finally the protocol stack TcpIp_Init(). In regular operation, all interfaces verify whether initialization completed successfully and otherwise refuse execution while signaling development errors ([SWS_Eth_00027], [SWS_Eth_00051], [SWS_EthIf_00024]).

Layer 2 mode management is controlled via EthIf_SetControllerMode(), whereby the mode of the addressed controller is transitioned between ETH_MODE_DOWN, ETH_MODE_ACTIVE, and ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST ([SWS_EthIf_00034], [SWS_Eth_91008]). The driver performs the mode transition and confirms it asynchronously via the callback EthIf_CtrlModeIndication(), which forwards the state change to the Ethernet State Manager (EthSM) ([SWS_EthIf_00231], [SWS_EthIf_00252]). For networked switches, EthIf additionally controls switch port groups by means of EthIf_SwitchPortGroupRequestMode() or starts all ports via EthIf_StartAllPorts() ([SWS_EthIf_91102], [SWS_EthIf_91103]). In the TcpIp stack, the network's communication state is controlled separately via TcpIp_RequestComMode(): TCPIP_STATE_ONLINE activates IP address assignment, TCPIP_STATE_ONHOLD pauses transmission activities, and TCPIP_STATE_OFFLINE closes all active sockets ([SWS_TCPIP_00070], [SWS_TCPIP_00071], [SWS_TCPIP_00072], [SWS_TCPIP_00074]).

In the areas of shutdown, sleep, and wakeup, the cluster supports standardized wakeup sequences according to OPEN Alliance TC10 (SWS_ECUStateManager p. 192). If the Ethernet hardware (PHY or switch port) detects a wakeup signal in sleep state, an interrupt signals the event. The integration code or EcuM then triggers EthIf_CheckWakeup(), which instructs the affected transceiver drivers to perform asynchronous verification ([SWS_EthIf_00244], [SWS_EthIf_00245]). Detailed wakeup reasons can be read out via EthIf_GetSwitchPortWakeupReason() ([SWS_EthIf_91005]). During shutdown, TcpIp_ResetIpAssignment() allows persisted IP assignments in the NvM to be reset specifically ([SWS_TCPIP_00215], [SWS_TCPIP_00216]).

Error Handling, DET Tracing, and Degradation

The modules of the cluster implement a multi-stage error monitoring and diagnostic concept. During development and system integration, the Default Error Tracer (DET) intercepts programming and configuration errors. These include calls prior to successful module initialization (ETH_E_UNINIT, ETHIF_E_UNINIT) ([SWS_Eth_00228], [SWS_EthIf_00036]), invalid controller or transceiver indices (ETH_E_INV_CTRL_IDX, ETHIF_E_INV_TRCV_IDX) ([SWS_Eth_00229], [SWS_EthIf_00326]), and invalid pointer parameters ([SWS_Eth_00230], [SWS_Eth_00250]). In case of hardware-related communication disturbances on the MII bus, Eth_WriteMii() reports the runtime error ETH_E_COMMUNICATION ([SWS_Eth_00058], [SWS_Eth_00286]).

For operational diagnostics and diagnostic event management (DEM), Eth and EthIf provide standardized counter structures in accordance with IETF RFC standards. Via Eth_GetCounterValues() and Eth_GetRxStats(), drop events caused by buffer overruns, CRC errors, oversized and undersized packets (jabbers, undersize), and alignment errors according to RFC 1757, RFC 1643, and RFC 2819 are captured ([SWS_Eth_00226], [SWS_Eth_00233], [SWS_Eth_91007], [SWS_Eth_91002]). Transmit counters and error statistics are provided by means of Eth_GetTxStats() and Eth_GetTxErrorCounterValues() ([SWS_Eth_91005], [SWS_Eth_91006], [SWS_Eth_91003]). EthIf transparently forwards these counter queries for external switch hardware via EthIf_SwitchPortGetCounterValues() and EthIf_SwitchPortGetTxErrorCounterValues() ([SWS_EthIf_91115], [SWS_EthIf_91118]).

Degradation mechanisms and link quality monitoring ensure functional robustness: EthIf_GetTrcvSignalQuality() provides current, minimum, and maximum link qualities of the physical transceivers ([SWS_EthIf_91056], [SWS_EthIf_91057]), allowing degraded transmission links to be diagnosed before link drop occurs. EthIf_GetAndResetMeasurementData() enables reading out and resetting detailed measurement data on dropped datagrams, for instance in case of configuration deficiencies regarding VLAN IDs or controller assignments ([SWS_EthIf_91011], [SWS_EthIf_00309]). In the event of link losses, EthIf_Transmit() stops forwarding to the driver ([SWS_EthIf_00076]), while TcpIp terminates sockets and clears transmit queues in offline states ([SWS_TCPIP_00072]).
