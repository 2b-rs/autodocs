System architecture and role of the module cluster

The "Ethernet Services" cluster in the Classic Platform maps the communication path from the Ethernet controller to the IP transport layer. The architecture overview assigns TcpIp to the Communication Services, the Ethernet Interface to the Communication Hardware Abstraction, and the Ethernet driver to the Communication Drivers (SWS TcpIp p. 17). TcpIp itself consists of functional submodules ([SWS_TCPIP_00052]).

  • Eth (Ethernet Driver): manages transmit and receive buffers, controller modes, and controller statistics. It is initialized with Eth_Init ([SWS_Eth_00027]) and uses hardware offloading for checksums ([SWS_Eth_00216], [SWS_Eth_00217]).
  • EthIf (Ethernet Interface): combines multiple drivers and controllers into a unified index space (SWS EthIf p. 18). It distributes switch accesses to EthSwt ([SWS_EthIf_00224]) and forwards transceiver calls to EthTrcv ([SWS_EthIf_00391]). It reports mode switches to EthSM ([SWS_EthIf_00252]).
  • TcpIp: implements the IETF protocols IPv4 ([SWS_TCPIP_00053]), ARP ([SWS_TCPIP_00056]), UDP ([SWS_TCPIP_00060]), TCP ([SWS_TCPIP_00061]), IPv6 ([SWS_TCPIP_00160]), NDP ([SWS_TCPIP_00164]), and DHCPv4 ([SWS_TCPIP_00058]). It encapsulates IP packets into Ethernet frames according to RFC 894 ([SWS_TCPIP_00095]) and serves socket users such as SoAd ([SWS_TCPIP_00220]).

Context diagram: TcpIp, EthIf, and Eth form a call chain with feedback via callback; EthIf additionally connects transceiver, switch, and EthSM. Sources: SWS TcpIp p. 17, [SWS_EthIf_00075], [SWS_TCPIP_00029], [SWS_EthIf_00252], [SWS_TCPIP_00027]

Release note: Some document passages originate from R23-11 to R25-11. They show an LSduR between TcpIp and EthIf as well as a PDU-based EthIf_Transmit (SWS EthIf p. 97). For R20-11, by contrast, the signature with CtrlIdx/BufIdx ([SWS_EthIf_00075]) and the direct receive call TcpIp_RxIndication ([SWS_TCPIP_00029]) apply.

Interaction and interaction paths

Transmission: The upper layer first requests a buffer with EthIf_ProvideTxBuffer ([SWS_EthIf_00067]). EthIf obtains it via Eth_ProvideTxBuffer ([SWS_Eth_00077]), and the driver locks the buffer until the associated Eth_Transmit (SWS Eth p. 108). After filling, EthIf_Transmit triggers the call Eth_Transmit ([SWS_Eth_00087]). In doing so, the driver constructs the Ethernet header with the destination MAC address (SWS Eth p. 115). With a configured VLAN ID, EthIf passes 0x8100 as FrameType ([SWS_EthIf_00250]).

Transmit confirmation: Eth reports a successful transmission with E_OK ([SWS_Eth_00243]) and a failure with E_NOT_OK ([SWS_Eth_00256]). In polling mode, EthIf_MainFunctionTx triggers the confirmations ([SWS_EthIf_00113], SWS EthIf p. 171). EthIf forwards the result to <UL>_TxConfirmation ([SWS_EthIf_00255]). TcpIp, however, always calls EthIf_Transmit with TxConfirmation = FALSE ([SWS_TCPIP_00131]). It ensures reliability itself, for example via TCP retransmissions ([SWS_TCPIP_00202]).

Sequence diagram: Transmission in two stages (request buffer, then transmit), confirmation via polling or interrupt and only upon request. Sources: [SWS_EthIf_00067], [SWS_Eth_00077], [SWS_Eth_00087], [SWS_Eth_00100], [SWS_EthIf_00091], [SWS_TCPIP_00131], SWS EthIf p. 88

Reception: Eth calls EthIf_RxIndication either from the interrupt routine or from Eth_Receive ([SWS_Eth_00244]). Eth_Receive reports via Eth_RxStatusType whether further frames are pending ([SWS_Eth_00095], [SWS_Eth_00162]). In polling mode, EthIf_MainFunctionRx drives the reception ([SWS_EthIf_00097]). EthIf distributes the frames to <User>_RxIndication ([SWS_EthIf_00104]). TcpIp maps UDP and TCP datagrams to the sockets via port and address ([SWS_TCPIP_00170], [SWS_TCPIP_00172]).

Filtering: Upstream, Eth filters by MAC addresses ([SWS_Eth_00152]) and discards non-matching frames ([SWS_Eth_00246]). EthIf counts datagrams that are discarded due to an invalid CtrlIdx or VLAN ([SWS_EthIf_00309]).

Sequence diagram: Receive path in polling and in interrupt mode up to socket delivery. Sources: [SWS_Eth_00244], [SWS_Eth_00095], [SWS_EthIf_00085], [SWS_TCPIP_00029], [SWS_TCPIP_00223], SWS EthIf p. 89

Synchronization, reentrancy and task contexts

Cyclic functions: Eth_MainFunction checks for controller errors ([SWS_Eth_00171]). In addition, it polls mode changes and calls EthIf_CtrlModeIndication upon change ([SWS_Eth_00240]). EthIf_MainFunctionState polls hardware states at the rate of EthIfMainFunctionStatePeriod ([SWS_EthIf_00407]). TcpIp_MainFunction schedules the stack ([SWS_TCPIP_00026]). ARP packets may be processed directly in TcpIp_RxIndication or in the next MainFunction ([SWS_TCPIP_00351]).

Lifecycles and operating modes

Initialization: The modules are initialized via Eth_Init ([SWS_Eth_00027]), EthIf_Init ([SWS_EthIf_00024]), and TcpIp_Init ([SWS_TCPIP_00002]). Because EthIf accesses Eth, the order is likely Eth → EthIf → TcpIp. Calls prior to initialization are detected by the DET check ([SWS_Eth_00228], [SWS_EthIf_00155]).

Controller mode: EthIf_SetControllerMode operates asynchronously ([SWS_EthIf_00034]). In R20-11, the new driver function Eth_SetControllerMode is specified as DRAFT ([SWS_Eth_91009]), the predecessor version as OBSOLETE ([SWS_Eth_00041]). Upon ETH_MODE_DOWN, the driver disables Rx and Tx and resets all buffers ([SWS_Eth_00276]). It releases locked and pending transmit buffers ([SWS_Eth_00280], [SWS_Eth_00281]). The result passes via EthIf_CtrlModeIndication to EthSM_CtrlModeIndication ([SWS_EthIf_00231], [SWS_EthIf_00252]).

Transceiver and switch ports: EthIf also switches referenced transceivers and switch port groups ([SWS_EthIf_00264], [SWS_EthIf_00266]). It switches ports off with a delay via EthIfSwitchOffPortTimedelay ([SWS_EthIf_00270]). Only an R23-11 passage substantiates the mode ETH_MODE_TX_OFFLINE for "silent communication" (SWS EthIf p. 34); in R20-11, it is not normative.

TcpIp states: TcpIp maintains its own state for each EthIf controller ([SWS_TCPIP_00083], [SWS_TCPIP_00073]), which is controlled via TcpIp_RequestComMode ([SWS_TCPIP_00070]). TCPIP_STATE_STARTUP and TCPIP_STATE_SHUTDOWN cannot be requested ([SWS_TCPIP_00089]). TcpIp accepts new TCP connections only in the ONLINE state ([SWS_TCPIP_00094]). Each state entry is reported via EthSM_TcpIpModeIndication (SWS TcpIp p. 60). Interpretation: EthSM thereby orchestrates the modes of EthIf and TcpIp.

State diagram: The TcpIp state per controller passes through STARTUP and SHUTDOWN as transition states between OFFLINE and ONLINE. Sources: [SWS_TCPIP_00075], [SWS_TCPIP_00085], [SWS_TCPIP_00088], [SWS_TCPIP_00076], [SWS_TCPIP_00086], [SWS_TCPIP_00077], [SWS_TCPIP_00087], SWS TcpIp p. 60

Wakeup and sleep: EthIf_CheckWakeup ([SWS_EthIf_00244]) queries transceivers and switches ([SWS_EthIf_00245], [SWS_EthIf_00500]). The sleep path is specified as DRAFT in R20-11: EthIf_SleepIndication reports to EthSM_SleepIndication ([SWS_EthIf_91006], [SWS_EthIf_00497]). In addition, the system template describes the PHY sleep sequence according to OA TC10 (SystemTemplate p. 141).

Error Handling, DET Tracing, and Degradation

DET errors: All three modules define development errors, for example for invalid controller indices or missing initialization ([SWS_Eth_00016], [SWS_EthIf_00017], [SWS_TCPIP_00042]). TcpIp reports network problems at runtime via Det_ReportRuntimeError ([SWS_TCPIP_00255]):

  • timeouts ([SWS_TCPIP_00256])
  • rejected connections ([SWS_TCPIP_00257])
  • unreachable hosts ([SWS_TCPIP_00258])
  • address conflicts from Duplicate Address Detection ([SWS_TCPIP_00282])

Dem error memory: Eth reports production errors such as ETH_E_ACCESS ([SWS_Eth_00173]) and ETH_E_RX_FRAMES_LOST ([SWS_Eth_00174]). In addition, there are extended events for CRC, length, and collision errors ([SWS_Eth_00219], [SWS_Eth_00221], [SWS_Eth_00225]), which Eth_MainFunction checks cyclically ([SWS_Eth_00172]).

Diagnostic counters: RFC-based counters are available for diagnostics ([SWS_Eth_00226], [SWS_Eth_00233], [SWS_Eth_91005]). Measurement data is provided by EthIf_GetAndResetMeasurementData ([SWS_EthIf_91011]) and the TcpIp drop counters ([SWS_TCPIP_00287]). These counters do not overflow ([SWS_TCPIP_00294], [SWS_EthIf_00313]). EthIf and TcpIp optionally report security events ([SWS_EthIf_00502], [SWS_TCPIP_00361]).

Degradation: If the MAC address of a destination is missing, TcpIp buffers the packet until resolution or discards it, depending on the configuration ([SWS_TCPIP_00191], [SWS_TCPIP_00192]). In this case, TcpIp_GetRemotePhysAddr returns TCPIP_E_PHYS_ADDR_MISS and can initiate address resolution ([SWS_TCPIP_00137]). In the ONHOLD state, TcpIp does not accept any new transmit requests ([SWS_TCPIP_00074]). If a higher-priority address becomes available, it switches to it ([SWS_TCPIP_00127]).
