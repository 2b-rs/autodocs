AUTOSAR Classic Microcontroller Abstraction (MCAL)

Die Microcontroller Abstraction Layer (MCAL) enthält hardware-spezifische Treiber für interne Mikrocontroller-Peripherie (ADC-Wandler, PWM-Generatoren, Hardware-Watchdog) und entkoppelt obere BSW-Schichten von der Silizium-Plattform.

System Architecture & Role of the Module Cluster

The cluster “Microcontroller Abstraction” forms the lowest software layer of the Classic Platform. The specifications of ADC and PWM drivers explicitly state that these modules are located at the lowest architectural level and therefore do not provide callbacks for lower layers (SWS ADC p. 79, SWS PWM p. 40). Their users are modules of the ECU abstraction and the system services, above all IoHwAb, WdgIf/WdgM as well as EcuM and BswM, respectively. The requirements of the payload are normative for R20-11. Document passages from later releases serve here only for illustration, such as the ADC example of the IoHwAb (IoHwAb p. 55).

  • Adc converts analog channels group by group. A conversion is triggered via software or hardware ([SWS_Adc_00514]). The results are stored in buffers provided by the user ([SWS_Adc_91000]).
  • Pwm generates pulse-width modulated signals with period and duty cycle ([SWS_Pwm_91001]). Optionally, it reports signal edges ([SWS_Pwm_00109]).
  • Wdg services the internal or external hardware watchdog via a trigger condition ([SWS_Wdg_00144]).
  • Spi and Dio are evidenced in the payload as access paths of an external watchdog ([SWS_Wdg_00076]). The payload does not contain dedicated SWS requirements for these two modules.
  • Port is documented via Port_Init as “Initializes the Port Driver module” in the EcuM interface list (SWS EcuM p. 142). A diagram locates the “Port Logic” between the PWM unit and the pin (RS PWM p. 14).

Context diagram: The MCAL drivers are initialized by EcuM/BswM, used by IoHwAb or WdgIf, and report errors to DET/DEM; an external watchdog reaches the hardware via Spi or Dio. Sources: [SWS_Wdg_00076], [SWS_Adc_00082], [SWS_Pwm_00198], [SWS_Wdg_00111], [SWS_Adc_00377], [SWS_Pwm_00104], Modemanagement p. 54

Interaction & Interaction Paths

ADC data path. The sequence begins with the result buffer.

  1. After each reset and before the first group conversion, the user must set the result buffer of the group using Adc_SetupResultBuffer ([SWS_Adc_91000], SWS ADC p. 54).
  2. Adc_StartGroupConversion resets the internal buffer pointer. The notification is not automatically activated in the process ([SWS_Adc_00367], SWS ADC p. 57).
  3. After each completed group conversion, the driver calls IoHwAb_AdcNotification<#groupID> ([SWS_Adc_00082]).
  4. The user reads the results in one of two ways:
    • Adc_ReadGroup copies them ([SWS_Adc_00369]).
    • Adc_GetStreamLastPointer provides a pointer into the buffer ([SWS_Adc_00375]).

How many results the buffer accommodates depends on the access mode: Single or Streaming ([SWS_Adc_00528]). In streaming mode, the buffer is organized linearly or circularly ([SWS_Adc_00519]).

Sequence diagram: Software-triggered continuous conversion with notification – set up buffer, activate notification, start, notify and read per round, stop. Sources: SWS ADC p. 92, [SWS_Adc_91000], [SWS_Adc_00082], SWS ADC p. 70

PWM control path. The user adjusts the signal via two services:

  • Pwm_SetDutyCycle changes only the duty cycle ([SWS_Pwm_91000]).
  • Pwm_SetPeriodAndDuty changes period and duty cycle ([SWS_Pwm_91001]). The period can only be changed for channels of class PWM_VARIABLE_PERIOD ([SWS_Pwm_00110]); otherwise, the driver reports PWM_E_PERIOD_UNCHANGEABLE ([SWS_Pwm_40002]).

Edge notifications reach the user via Pwm_Notification_<#Channel>. The decisive factor is the last call of Pwm_EnableNotification or Pwm_DisableNotification, respectively ([SWS_Pwm_00105], [SWS_Pwm_91004]). Pwm_GetOutputState reads the internal state of the output signal ([SWS_Pwm_00100]). According to the diagram, this is the tap before the port logic, not the level at the pin (RS PWM p. 14).

Watchdog path. The call chain runs across three levels:

  • WdgM controls the driver via WdgIf_SetMode and WdgIf_SetTriggerCondition (SWS WdgM p. 86).
  • WdgIf maps these services to the respective driver instance via DeviceIndex (SWS WdgIf p. 17).
  • Wdg converts the timeout from milliseconds into a counter value, taking into account the current mode ([SWS_Wdg_00138], [SWS_Wdg_00139]).

Internal and external watchdogs differ only in their hardware access:

  • An internal driver accesses the hardware directly ([SWS_Wdg_00161]).
  • An external driver uses Spi or Dio and maintains the parameters required for this in its configuration ([SWS_Wdg_00076], [SWS_Wdg_00078]).
  • The APIs of both variants are semantically identical ([SWS_Wdg_00077]).
  • If there are multiple instances, the API names are expanded ([SWS_Wdg_00172]).

Sequence diagram: Setting the trigger condition is decoupled in time from cyclic hardware servicing; at counter value 0, the trigger is omitted. Sources: SWS Wdg p. 31, [SWS_Wdg_00134], [SWS_Wdg_00135], [SWS_Wdg_00136]

Synchronization, reentrancy and task contexts

The modules differ significantly in their reentrancy commitments:

  • Data path APIs of the ADC are reentrant.
  • Channel-related PWM services are reentrant only for different channels.
  • Initialization, power-state APIs, and all Wdg services are non-reentrant.

For data consistency, Wdg defines exclusive areas via the BSW Scheduler. As an MCAL module, the internal driver may also disable interrupts directly ([SWS_Wdg_00040]). During mode switches and the servicing routine, the state WDG_BUSY indicates concurrent accesses ([SWS_Wdg_00018], [SWS_Wdg_00052]).

Scheduled functions. Adc_Main_PowerTransitionManager and Pwm_Main_PowerTransitionManager run cyclically via SchM ([SWS_Adc_00479], [SWS_Pwm_00189]). Their rate is variable because they are only needed during an ongoing transition ([SWS_Adc_00500]). Prior to initialization, they return without a DET report ([SWS_Adc_00502]).

Interrupt context. The group and edge notifications are likely to run in the interrupt context. Two aspects support this: The PWM driver resets the interrupt flag belonging to the notification (SWS PWM p. 42). Furthermore, the MemMap example lists a BswInterruptEntity Adc_IsrGroupScanCompleted (SWS MemMap p. 54). Callbacks should therefore remain short. The reentrancy of Pwm_Notification_<#Channel> explicitly depends on the user's implementation ([SWS_Pwm_00105]).

Multi-core systems. Adc and Pwm must reject partition assignments that the implementation does not support ([SWS_Adc_00531], [SWS_Pwm_00203]). The kernel partitions of the ADC are a subset of the user partitions ([SWS_Adc_CONSTR_00001]). The master-satellite pattern with division into kernel and interface part fits with this (BSW Distribution p. 18).

Lifecycles and operating modes

Initialization. EcuM calls Adc_Init ([SWS_Adc_00365], SWS ADC p. 91). The structural description of EcuM additionally lists Port_Init, Pwm_Init, Spi_Init, and Wdg_Init (SWS EcuM p. 34). A BswM-controlled variant initializes in the sequence Port, Dio, Adc, Spi (Modemanagement p. 54). Interpretation: Port is presumably first because pin configuration is a prerequisite for the remaining peripheral drivers.

ADC. The driver switches from ADC_UNINIT to ADC_INIT with Adc_Init and back with Adc_DeInit (SWS ADC p. 31). Each group passes through the states ADC_IDLE, ADC_BUSY, ADC_COMPLETED, and ADC_STREAM_COMPLETED ([SWS_Adc_00513]). Continuous mode is available only with software triggering ([SWS_Adc_00515]). Adc_DeInit puts the hardware into a reset-like state ([SWS_Adc_00366]). It may only be called when all groups are in ADC_IDLE (SWS ADC p. 59).

PWM. After Pwm_Init, the outputs are low, high, or modulated depending on the configuration. Notifications remain inactive until Pwm_EnableNotification is called ([SWS_Pwm_00095], SWS PWM p. 46). Pwm_DeInit sets the outputs to the idle state and disables the interrupts ([SWS_Pwm_00096], SWS PWM p. 27).

Watchdog. Wdg_Init sets the default mode and the initial timeout ([SWS_Wdg_00001], [SWS_Wdg_00100]). Thereafter, the modes WDGIF_OFF_MODE, WDGIF_SLOW_MODE, and WDGIF_FAST_MODE are selectable ([SWS_Wdg_00160]). There is no DeInit function. Disabling is performed, if permitted, via the OFF mode ([SWS_Wdg_00031]).

Power states of Adc and Pwm. The transition takes place in two stages:

  1. *_PreparePowerState initiates it ([SWS_Adc_00478], [SWS_Pwm_00183]).
  2. In the asynchronous case, the main function completes it and reports readiness via IoHwAb_*_NotifyReadyForPowerState<#Mode> ([SWS_Adc_00480], [SWS_Pwm_00198]).
  3. *_SetPowerState executes the transition ([SWS_Adc_00475], [SWS_Pwm_00166]).

In advance, the responsible SWCs, such as IoHwAb, must set channels to idle and unregister notifications (SWS PWM p. 36). In the transition itself, only transition-specific reconfigurations are permitted ([SWS_Adc_00484]).

Sequence diagram: Following a BswM mode switch, IoHwAb coordinates the two-stage power state transition of Adc and Pwm, asynchronously with ready callbacks or synchronously via polling. Sources: IoHwAb p. 57, IoHwAb p. 58, [SWS_Adc_00501], [SWS_Pwm_00190]

Error Handling, DET Tracing, and Degradation

Development errors (DET). All three specified drivers report them via Det_ReportError ([SWS_Adc_00377], [SWS_Pwm_00104], [SWS_Wdg_00111]):

  • Adc, among others, ADC_E_UNINIT and ADC_E_PARAM_GROUP ([SWS_Adc_91005]).
  • Pwm PWM_E_UNINIT and PWM_E_PARAM_CHANNEL ([SWS_Pwm_20002], [SWS_Pwm_30002]).
  • Wdg in case of an incorrect state WDG_E_DRIVER_STATE ([SWS_Wdg_00017], [SWS_Wdg_00035]).

Runtime errors. Several cases exist here:

  • The ADC reports ADC_E_BUSY, among other cases, when a conversion without queuing is already in progress ([SWS_Adc_91006], SWS ADC p. 95).
  • If channels are still active during a power state transition, both drivers report *_E_NOT_DISENGAGED ([SWS_Adc_00487], [SWS_Pwm_00202]).
  • In R20-11, the ADC classifies an unreachable target power state as a runtime error ([SWS_Adc_00489]), whereas the PWM classifies it as a DET error ([SWS_Pwm_00175]).

Production errors (DEM). In the payload, these are specified only for Wdg and are reported via Dem_SetEventStatus ([SWS_Wdg_00111]):

  • WDG_E_MODE_FAILED upon a failed mode switch; Wdg_SetMode then returns E_NOT_OK ([SWS_Wdg_00016], [SWS_Wdg_00180]).
  • WDG_E_DISABLE_REJECTED if switching off is not allowed ([SWS_Wdg_00025], [SWS_Wdg_00182]).

Degradation and safe states.

  • Pwm_SetOutputToIdle immediately sets the output to the configured idle state ([SWS_Pwm_91002], SWS PWM p. 31).
  • Pwm_GetOutputState defensively returns PWM_LOW prior to initialization or for an invalid channel ([SWS_Pwm_30051]).
  • For the watchdog, reset is the last fallback level. A timeout of 0 triggers an almost immediate ECU reset ([SWS_Wdg_00140]). An expired trigger counter causes the watchdog to time out ([SWS_Wdg_00135]).
  • The driver rejects timeouts that are too large with WDG_E_PARAM_TIMEOUT ([SWS_Wdg_00146]).
  • For the ADC, priority mechanisms with Abort/Restart or Suspend/Resume govern how preempted groups are resumed ([SWS_Adc_00522], [SWS_Adc_00523]). Limit checking filters results outside the selected range ([SWS_Adc_00524]).
