Enables persistent storage and management of application data via key-value and file storage.

The namespace ara::per provides interfaces for persistent data storage by enabling Adaptive Applications to access file-based and key-value-based storage areas via instance specifiers ([SWS_PER_00052], [SWS_PER_00116]). Applications manage opened storages via shared handles, perform coordinated updates upon manifest changes, and can repair inconsistent data via recovery mechanisms ([SWS_PER_00333], [SWS_PER_00357]). While storage accesses occur concurrently via handles, administrative operations such as updates or storage resets require the absence of competing accesses ([SWS_PER_00311]).

Context

The namespace ara::per provides the interfaces of the persistence functional cluster for the AUTOSAR Adaptive Platform. Its primary responsibility is the durable, memory-surviving storage of application data across system startups and process lifecycles. The module distinguishes two fundamental storage paradigms: KeyValueStorage for structured key-value pairs and FileStorage for file-based storage access. Adaptive Applications access these resources via configured port prototypes using ara::core::InstanceSpecifier ([SWS_PER_00052], [SWS_PER_00116]).

Important interaction partners of the namespace are the Update and Configuration Management (UCM), which can provide updated target configurations (Target Configuration) during runtime ([SWS_PER_00576], [SWS_PER_00577]), and the physical storage medium on which ara::per ensures consistency, redundancy, and data safety ([SWS_PER_00311]).

Context diagram: Interaction between application, ara::per, Update Management, and physical storage. Sources: [SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00576]

Lifecycle

Access to storage objects is controlled via handle abstractions. Opening a storage via OpenKeyValueStorage or OpenFileStorage creates a SharedHandle ([SWS_PER_00052], [SWS_PER_00116]). Since multiple threads can access the same storage concurrently, the physical resource is not necessarily closed when a single SharedHandle leaves its scope; closing occurs only when all referencing SharedHandle instances have been dismantled ([SWS_PER_00052], [SWS_PER_00116]).

For files within a FileStorage, creation and modification states are tracked in detail. The enumeration FileCreationState indicates whether a file was created during installation (kCreatedDuringInstallation), during an update (kCreatedDuringUpdate), by a reset (kCreatedDuringReset), as a result of recovery (kCreatedDuringRecovery), or by the application itself (kCreatedByApplication) ([SWS_PER_00435]). Analogously, FileModificationState reflects when and by which operation a file was last modified ([SWS_PER_00436]).

To manage initial states, the namespace provides reset functions: ResetKeyValueStorage ([SWS_PER_00334]) and ResetAllFiles ([SWS_PER_00336]) reset individual storages to the values initially defined in the manifest. In contrast, the global operation ResetPersistency ([SWS_PER_00358]) completely empties all key-value and file storages; their recreation occurs upon the next call to OpenFileStorage or OpenKeyValueStorage.

With regard to concurrency, the opening functions (OpenFileStorage, OpenKeyValueStorage), storage size queries (GetCurrentFileStorageSize, GetCurrentKeyValueStorageSize), and storage-related recovery and reset functions are thread-safe ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00405], [SWS_PER_00406], [SWS_PER_00333], [SWS_PER_00334], [SWS_PER_00335], [SWS_PER_00336]). Global update and cleanup operations such as UpdatePersistency ([SWS_PER_00357]), CleanUpPersistency ([SWS_PER_00567]), ResetPersistency ([SWS_PER_00358]), CheckForManifestUpdate ([SWS_PER_00576]), and ReloadPersistencyManifest ([SWS_PER_00577]), by contrast, are declared as not thread-safe.

Usage Path

A typical application flow comprises checking for configuration updates, applying data migrations, and subsequent storage access:

Prior to or during regular operation, the application checks via CheckForManifestUpdate whether UCM has installed a new target configuration ([SWS_PER_00576]). If this is the case, the new manifest is read in via ReloadPersistencyManifest ([SWS_PER_00577]). During the subsequent verification phase, the application triggers UpdatePersistency ([SWS_PER_00357]). To control version-specific data migrations, the application registers a callback function in advance via RegisterApplicationDataUpdateCallback, which is informed about older contract versions and performs application-own migration steps ([SWS_PER_00356]). Additionally, element changes can be monitored by means of RegisterDataUpdateIndication ([SWS_PER_00578]). After completion of the update, CleanUpPersistency removes obsolete backups and redundant legacy data ([SWS_PER_00567]).

For regular access, the application opens the target resource via OpenKeyValueStorage ([SWS_PER_00052]) or OpenFileStorage ([SWS_PER_00116]). File accesses in FileStorage are controlled via bitmasks of the enumeration OpenMode (e.g., kAtTheBeginning, kAtTheEnd, kTruncate, kAppend), which are combined using the operators operator| ([SWS_PER_00144]) and operator|= ([SWS_PER_00434]) ([SWS_PER_00147]). Positionings are performed relative to Origin (kBeginning, kCurrent, kEnd) ([SWS_PER_00146]). The currently occupied storage size can be determined at runtime via GetCurrentKeyValueStorageSize ([SWS_PER_00405]) and GetCurrentFileStorageSize ([SWS_PER_00406]).

Error Scenarios

Errors are signaled in the namespace in a standardized manner via the enumeration PerErrc ([SWS_PER_00311]) in conjunction with PerErrorDomain ([SWS_PER_00352]) and MakeErrorCode ([SWS_PER_00351]). The declared class PerException is likely to serve as a C++ exception type for environments in which errors are not handled via ara::core::Result, but via exceptions (Interpretation).

Key error scenarios include:

  • Configuration and addressing errors: If the passed InstanceSpecifier does not correspond to any port interface configured in the model, opening fails with PerErrc::kStorageNotFound ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00311]). File accesses to non-existent files generate PerErrc::kFileNotFound ([SWS_PER_00311]).
  • Resource conflicts: If storages are open or administrative commands are running concurrently, operations such as OpenKeyValueStorage, OpenFileStorage, RecoverKeyValueStorage, RecoverAllFiles, ResetKeyValueStorage, ResetAllFiles, UpdatePersistency, CleanUpPersistency, or ResetPersistency fail with PerErrc::kResourceBusy ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00333], [SWS_PER_00334], [SWS_PER_00335], [SWS_PER_00336], [SWS_PER_00357], [SWS_PER_00358], [SWS_PER_00567]).
  • Integrity loss and recovery: In the event of structural damage (PerErrc::kIntegrityCorrupted) or failed redundancy checks (PerErrc::kValidationFailed), ara::per enables a best-effort recovery via RecoverKeyValueStorage ([SWS_PER_00333]) or RecoverAllFiles ([SWS_PER_00335]), respectively. Via RegisterRecoveryReportCallback ([SWS_PER_00433]), safety-relevant applications can automatically log corrective measures based on RecoveryReportKind (e.g., kKeyValueStorageRecovered, kFileRecovered) ([SWS_PER_00432]).
  • Storage limits and physical errors: If quotas or physical capacities are exceeded, PerErrc::kOutOfStorageSpace, PerErrc::kQuotaExceeded, or PerErrc::kTooManyFiles are reported ([SWS_PER_00311]). Hardware or file system errors result in PerErrc::kPhysicalStorageFailure ([SWS_PER_00311]).
  • Security and access modes: If cryptographic verifications or computations fail, the module returns PerErrc::kEncryptionFailed or PerErrc::kAuthenticationFailed ([SWS_PER_00311]). Write attempts to read-only storage areas are rejected with PerErrc::kIllegalWriteAccess ([SWS_PER_00311]).

Recovers a File Storage, including all files. RecoverAllFiles recovers a File Storage when the redundancy checks fail. Registers an application data update callback with Persistency. The provided callback function will be called by Persistency if an update of stored application data might be necessary. This method can be used to update the persistent data of the Adaptive Application during verification phase.

                                                                                              use
                                                                                              

                                                                                              The synchronous function ara::per::UpdatePersistency ([SWS_PER_00357], header ara/per/update.h) updates all key-value and file storages of an application after the installation of a new target configuration. It serves to update the persistent data of an Adaptive Application during the verification phase [SWS_PER_00357]. The function takes no input parameters and returns a ara::core::Result<void> [SWS_PER_00357].
                                                                                              


                                                                                              Error handling
                                                                                              

                                                                                              In case of an error, the returned Result contains a specific error code or a vendor-specific error [SWS_PER_00357]. A distinction is made between operations with and without rollback semantics:
                                                                                              

                                                                                                

                                                                                              • Rollback semantics: In case of kIntegrityCorrupted, kValidationFailed, kEncryptionFailed, kAuthenticationFailed, kTooManyFiles (exceeding maxNumberOfFiles), kQuotaExceeded (exceeding MaximumAllowedSize), and kResourceBusy, changes made are rolled back [SWS_PER_00357].
                                                                                                • 

                                                                                              • No rollback semantics: In case of physical storage errors (kPhysicalStorageFailure) and insufficient physical storage space (kOutOfStorageSpace), no rollback is guaranteed [SWS_PER_00357].
                                                                                                • 

                                                                                              


                                                                                              Concurrency and Limitations
                                                                                              

                                                                                              The function is specified as exception-safe, but explicitly as not thread-safe [SWS_PER_00357]. A call fails with kResourceBusy as soon as a SharedHandle of a key-value or file storage is still in use or maintenance functions such as CleanUpPersistency [SWS_PER_00567], ResetPersistency [SWS_PER_00358], RecoverKeyValueStorage [SWS_PER_00333], ResetKeyValueStorage [SWS_PER_00334], RecoverAllFiles [SWS_PER_00335], or ResetAllFiles [SWS_PER_00336] are executed in parallel [SWS_PER_00357]. Conversely, concurrent calls to OpenKeyValueStorage [SWS_PER_00052] and OpenFileStorage [SWS_PER_00116] from other threads during the update likewise fail with kResourceBusy.
                                                                                              


                                                                                              Interaction
                                                                                              

                                                                                              If a new target configuration was installed at runtime by UCM and reread via ReloadPersistencyManifest [SWS_PER_00577], closed storages are updated via UpdatePersistency. If callbacks were previously registered via RegisterDataUpdateIndication [SWS_PER_00578] or RegisterApplicationDataUpdateCallback [SWS_PER_00356], they are invoked synchronously in the context of UpdatePersistency [SWS_PER_00578].
