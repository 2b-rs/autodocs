Public interface of ara::log

The namespace bundles the context creation, log severity and auxiliary types of the logging framework. An application creates one logger context per logical group; Context ID and description distinguish groups within a process. SWS Log and Trace §7.1 “Necessary Parameters and Initialization” [SWS_LOG_00005]

The namespace provides context attachment and the two message entry points. Source: SWS Log and Trace §7.1 “Necessary Parameters and Initialization”; SWS Log and Trace §7.2 “Log Messages”.

Severity as a control variable

The log level is both a message property and a filter criterion. The default value comes from the configuration, can be overwritten per context and changed at runtime; The network binding maps the levels 1:1 to the LT protocol. {L71} {L77} {sws(LOG,"SWS_LOG_00234")}

Create the context deliberately

CreateLogger() returns the logger managed by the framework. At least one logger must exist before a processable message; framework ownership binds the context lifetime to the process. {sws(LOG,"SWS_LOG_00005")} {sws(LOG,"SWS_LOG_00006")}

Usage AI generated

Automatically generated usage note derived from this AUTOSAR R25-11 specification element—not official AUTOSAR text. Evidence: [SWS_…].

The free function ara::log::Arg [SWS_LOG_00201] creates a wrapper object of type Argument<T> for an argument to be logged. In addition to value arg, a name, a unit, and a formatting hint controlled through Format can optionally be specified. According to the contract, the call is ill-formed if T is neither arithmetic, bool, nor convertible to ara::core::StringView or ara::core::Span<const ara::core::Byte>, or if an unit other than nullptr is nevertheless passed for a convertible or Boolean type.
