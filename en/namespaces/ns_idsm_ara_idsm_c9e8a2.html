Context

The namespace ara::idsm provides the interface for the Intrusion Detection System Management (IdsM) within the AUTOSAR Adaptive Platform. The IdsM serves to detect, record, and forward security-relevant events (Security Events) throughout the overall vehicle network. Adaptive applications, communication stacks, and platform services act as decentralized security sensors that report suspicious activities or logged rule violations to the central IdsM subsystem.

Within the namespace, class EventReporter assumes the central role in transmitting security events to the IdsM. In order to enrich event reports with relevant metadata, the reporter collaborates with other specialized components:

  • ContextDataProvider provides mutable, sensor-specific context data that is passed to the IdsM as a raw data sequence via [SWS_AIDSM_10201] ContextDataType (type alias for ara::core::Span<const std::uint8_t>) or in versioned form as [SWS_AIDSM_10206] VersionedContextDataType.
  • TimestampProvider provides high-precision or sensor-specific timestamps via the type [SWS_AIDSM_10202] TimestampType (64-bit integer) to enable temporal correlation of events.
  • ReportingModeProvider controls the reporting behavior of the sensors based on the enumeration [SWS_AIDSM_10207] ReportingModeType.
  • QualifiedEventsReceiver enables higher-level analysis or response modules to receive security events qualified by the IdsM for further processing.
  • IdsmErrorDomain and IdsmException define the error semantics of the namespace.

Context diagram: Interaction between sensor applications, the interface classes of the ara::idsm namespace, and the IdsM subsystem. Sources: [SWS_AIDSM_10201], [SWS_AIDSM_10205], [SWS_AIDSM_10207].

Usage Path

A typical monitoring sequence comprises querying the active operating mode, preparing the event data, and subsequently reporting to the IdsM:

  1. Query reporting mode: Before an application performs computationally intensive context analyses or transmits events, it reads the current reporting mode via ReportingModeProvider. According to [SWS_AIDSM_10207], five modes of the enumeration ReportingModeType are available:
    • ReportingModeType::kOff: Event reporting is completely deactivated.
    • ReportingModeType::kBrief: Reduced event reporting without detailed context data.
    • ReportingModeType::kDetailed: Detailed reporting including all available context data.
    • ReportingModeType::kBriefBypassingFilters: Reduced reporting bypassing local filtering mechanisms.
    • ReportingModeType::kDetailedBypassingFilters: Full reporting bypassing local filtering mechanisms.
    Interpretation: The fine-grained distinction of reporting modes presumably allows the overall system to dynamically adapt the transmission volume to the current bus load and threat situation.
  2. Prepare event data: The specific event is identified via a 16-bit integer of type [SWS_AIDSM_10205] EventIdType. If multiple events of the same type have been prequalified, the count can be specified via [SWS_AIDSM_10203] CountType. In addition, timestamps can be determined via TimestampProvider ([SWS_AIDSM_10202]) and payload data via ContextDataProvider ([SWS_AIDSM_10201] or [SWS_AIDSM_10206], respectively).
  3. Report event: The application passes the data to EventReporter. Interpretation: The handover to the IdsM subsystem is presumably asynchronous in order not to block the execution paths of time-critical sensor applications.
  4. Receive qualified events: Registered modules receive qualified events via QualifiedEventsReceiver to initiate vehicle-wide security responses.

Sequence diagram: Call sequence for checking the reporting mode, preparing context data, and transmitting a security event. Sources: [SWS_AIDSM_10201], [SWS_AIDSM_10205], [SWS_AIDSM_10206], [SWS_AIDSM_10207].

Error Scenarios

Error handling in namespace ara::idsm follows the AUTOSAR Adaptive standard via error domains and result types:

  • Error domain and factory functions: The function [SWS_AIDSM_10702] GetIdsmErrorDomain() returns a reference to the static ara::core::ErrorDomain of domain IdsmErrorDomain. It is specified as constexpr, noexcept, and thread-safe. Error codes are created using [SWS_AIDSM_10703] MakeErrorCode() by specifying a value from IdsmErrc and optional support data (ara::core::ErrorDomain::SupportDataType).
  • Specific error codes: According to [SWS_AIDSM_10204], the enumeration IdsmErrc defines the code kUnknownEventId = 3. This error occurs when an event is reported with a EventIdType that is not known to the IdsM or not configured in the manifest.
  • Exception handling: If module APIs throw exceptions, the typed error IdsmException is used, which encapsulates the associated ara::core::ErrorCode.
