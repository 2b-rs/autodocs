Translation from the model into the binding space

ara::com::runtime::ResolveInstanceIDs translates a InstanceSpecifier that is unique in the executable to the technical InstanceIdentifier configured in the service instance manifest. The return value is a container because a specifier can point to multiple technical instances in multi-binding. EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers” and SWS CM §7.5.21 “Instance Specifier Translation” provide the semantics.

When you explicitly need the resolution

Most Find and Skeleton APIs accept the InstanceSpecifier directly. The explicit resolution is therefore particularly useful for cases in which the specific technical assignment must be consciously processed, such as diagnostics or special multi-binding strategies. EXP ARAComAPI §4.8.2 “When to use InstanceIdentifier versus InstanceSpecifier” describes this limit.

The process is documented in the module guide as an activity diagram: ara::com — Communication Management, activity diagram “Resolution of the InstanceSpecifier against the manifest”.

Use manifest resolution consciously

ResolveInstanceIDs() reads the deployment side mapping of a InstanceSpecifier and returns a InstanceIdentifierContainer. An empty container indicates a lack of assignment, a multi-valued container indicates multi-binding. EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers” explains the possible results.

Recommended process
  1. Provide specifier from the unique port context.
  2. Result and check container size.
  3. Use an explicit binding/failover strategy for multiple IDs.
  4. For standard discovery, it is preferable to use the specifier overload.
