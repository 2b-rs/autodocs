Context

The namespace ara::com::e2e provides data types, status enumerations, and error handling mechanisms for End-to-End protection (E2E) in the AUTOSAR Adaptive Platform. Its primary responsibility lies in providing standardized interfaces for evaluating the E2E integrity of transmitted data, as well as for reporting and handling transport-related error conditions in service-oriented communication.

The central interaction partners include skeleton and proxy instances of the communication layer as well as application-side error handling routines. On the server side, the interface enables the registration of an application-specific handler of type TransportFaultConditionHandler [SWS_CM_00092] for all methods of a skeleton AUTOSAR_AP_EXP_SWArchitecture p. 68 and dedicatedly for skeleton fields (Field Get/Set) AUTOSAR_AP_EXP_SWArchitecture p. 69. If a fault occurs in the transport channel, Communication Management notifies the registered handler, specifying the concrete error condition TransportFaultCondition [SWS_CM_00091].

Context diagram: Interaction between skeleton instance, communication runtime, and error handler. Sources: [SWS_CM_00091], [SWS_CM_00092], AUTOSAR_AP_EXP_SWArchitecture p. 68, AUTOSAR_AP_EXP_SWArchitecture p. 69

Usage Path

The typical usage path when processing incoming event samples comprises a two-stage validation consisting of individual sample check and state monitoring:

  1. Individual sample check: Upon receiving a sample, the result of the E2E profile check for the respective ara::com::SamplePtr is first evaluated via ProfileCheckStatus [SWS_CM_90421]. In this process, checksums, data lengths, and counter values are analyzed. If the check is active and successful, the query returns the status ProfileCheckStatus::kOk [SWS_CM_90421].
  2. State check of the state machine: Subsequently, the higher-level state of the E2E monitoring state machine is checked using SMState [SWS_CM_90422]. Only when SMState::kValid is present and the individual check ProfileCheckStatus has yielded no error may the checked sample be consumed and further processed by the application [SWS_CM_90422].
  3. Error registration on the skeleton: In parallel, a service provider registers a TransportFaultConditionHandler on the skeleton for methods AUTOSAR_AP_EXP_SWArchitecture p. 68 or field accesses AUTOSAR_AP_EXP_SWArchitecture p. 69 during initialization. Handlers that are no longer required can be deregistered again later AUTOSAR_AP_EXP_SWArchitecture p. 68, AUTOSAR_AP_EXP_SWArchitecture p. 69.

Sequence diagram: Validation sequence of received samples based on ProfileCheckStatus and SMState. Sources: [SWS_CM_90421], [SWS_CM_90422]

Error Scenarios

In the event of an error, the namespace differentiates between protocol-related E2E check errors, states of the monitoring state machine, and transport-related errors:

  • E2E error codes (ComE2EErrc): Erroneous checks or incorrect counter sequences are mapped via the enumeration ComE2EErrc [SWS_CM_10474]. These include repeated counters (kRepeated), invalid counter jumps (kWrongSequence), checksum or length errors (kError), the absence of new data (kNoNewData), and unspecified errors of remote services (kUnspecifiedE2EError) [SWS_CM_10474]. For integration into the platform-wide error model, GetComE2EErrorDomain() provides a reference to the ComE2EErrorDomain [SWS_CM_12510], AUTOSAR_AP_EXP_ARAComAPI p. 9, while MakeErrorCode() generates standardized error codes [SWS_CM_12511]. For exception handling, the exception class ComE2EException exists.
  • State errors of the E2E monitoring (SMState): If the state machine after evaluation is not in the status kValid, but in the states kInit (not yet sufficient error-free data since initialization), kInvalid (too many erroneous or too few valid transmissions within the time window), or kNoData, the data must not be used [SWS_CM_90422]. In the case of incompatible Quality of Service parameters, the state kIncompatibleQoS is signaled [SWS_CM_90422].
  • Transport-related fault conditions (TransportFaultCondition): If a resource shortage occurs at layer 4 or higher, kSampleRejected is reported [SWS_CM_00091]. When configured timeouts are exceeded, the system reports kDeadlineMissed, and when gaps in the packet sequence are detected, kSampleLost is reported [SWS_CM_00091]. These conditions are passed to the application via the registered TransportFaultConditionHandler together with the number of occurred errors [SWS_CM_00092].
