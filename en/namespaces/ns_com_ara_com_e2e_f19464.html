E2E states and error signals

ara::com::e2e provides the application-visible types for end-to-end evaluation. ProfileCheckStatus describes the checking of a specific sample; ComE2EErrc and the error domain represent error channels of the API. This view complements the safety processing of the underlying binding. SWS CM §7.4 “Safety” and [SWS_CM_90413] form the basis.

Handle transport errors separately

TransportFaultCondition and its handler model transport-related anomalies. They should not be confused with the profile status of a sample: a handler can signal a finding while the application separately evaluates the status of a received sample. (Interpretation: This separation follows the separately specified API types and their E2E role.)

Implication for consumers

For E2E protected events, status information is accessible via SamplePtr. Consumers therefore determine in advance which profile statuses they technically accept and how they report or demote transport errors. SWS CM §7.4.1 “End-to-end communication protection for SOMEIP” describes event-specific treatment.

The process at the recipient is documented in the module guide as an activity diagram: ara::com — Communication Management, activity diagram “E2E-protected event at receiver”.

Detect E2E errors via the appropriate domain

ComE2EErrc denotes error codes of the E2E error domain. Evaluate it through Result/Future where the respective API defines an error channel, and distinguish it from ComErrc.

Use together with sample status

For event data, ProfileCheckStatus also provides sample-specific information. A robust consumer design treats error code and profile status as separate signals. SWS CM §7.4 “Safety” provides the common framework.

Evaluate status directly on the sample

ProfileCheckStatus describes the result of the E2E profile check of a single received sample. The application reads it via SamplePtr::GetProfileCheckStatus() and then decides whether it technically accepts the user data. [SWS_CM_00042] proves access.

Do not derive a global statement

The status belongs to a sample, not automatically to the permanent state of the service connection. (Interpretation: The SWS updates the status in the respective SamplePtr.) [SWS_CM_90413] describes the assignment.

Understand transport condition as an event

TransportFaultCondition classifies an E2E/transport path condition that can be signaled via the associated handler. The specific reaction lies with the application or its security architecture.

Combine with sample testing

Retain the E2E status check on the sample: a transport indication does not replace the evaluation of ProfileCheckStatus. SWS CM §7.4 “Safety” assigns both aspects to the safety path.
