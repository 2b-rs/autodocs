Extension point for modeled tracing

apext::log::TraceArti is the extension point for modeled trace messages. The routing decision can be made for the message, namespace and executable at compile time, thereby avoiding runtime overhead. SWS Log and Trace §7.6 “Tracing” [SWS_LOG_20001] [SWS_LOG_20004]

Decouple trace and log

Depending on the configuration, the generated specialization leads only to the logger, only to ARTI, to both, or discards the message. (Interpretation: The namespace is therefore the deliberately narrow bridge between generated trace tool code and the standard log API.)

function TraceArti [SWS_LOG_20000] Upstream: RS_LT_00003

template <typename MsgId, typename... Params> void TraceArti (const MsgId &msg_id, const Params &...                       params) noexcept;

Handles a modeled message, specific to the used trace tool. This function is only called internally by the Logger framework when switching between Log and TraceArti. It represents the interface to trace tools. The runtime overhead of this function shall be kept as minimal as possible, e.g. by using specializations based on the MsgId.

Semantics by TraceArti

TraceArti is an API detail of the logging interface. Its use is in the context of Logger, LogStream and the configured reporting filter.

Classification in the message path

The logging API is designed to be no-throw; Errors in the framework should not burden the application process. The actual output depends on the configured sink. SWS Log and Trace §7.1 “Necessary Parameters and Initialization” SWS Log and Trace §7.7 “Output Bindings”
