Context

The namespace ara::exec provides the interfaces of the Execution Management module on the AUTOSAR Adaptive Platform. The module is responsible for the lifecycle of processes, controls system startup, and monitors the state transitions of configured function groups (Function Groups). The classes of the namespace encapsulate the interaction between three key actors: the application-specific processes, the central Execution Management, and the State Management.

For processes, the class ExecutionClient serves as the primary communication channel through which a started process reports its current execution state to Execution Management. State Management accesses Execution Management via the class StateClient in order to request defined state transitions between function groups (FunctionGroup) and their target states (FunctionGroupState). If an execution error occurs during the operation of a function group, this is represented via ExecutionErrorEvent with the corresponding error type ExecutionError [SWS_EM_02541].

Context diagram: Interaction between processes, Execution Management, and State Management. Sources: [SWS_EM_02000], [SWS_EM_02281]

Lifecycle

The lifecycle of a process is described by states that are partly managed implicitly by Execution Management and partly reported actively by the process [SWS_EM_02000]. The enumeration ExecutionState exclusively describes those states that the process can actively transmit to Execution Management. The only state value defined for this is ExecutionState::kRunning [SWS_EM_02000].

From the perspective of Execution Management, a process passes through the following phases:

  • Initializing: An implicit state that begins as soon as the process is scheduled by the operating system (before application-specific code is executed) and ends as soon as the process reports kRunning [SWS_EM_02000].
  • Running: The active execution state after successfully reporting ExecutionState::kRunning [SWS_EM_02000].
  • Terminating: Another implicit state that starts when Execution Management requests the termination of the process and concludes with the complete termination of the process [SWS_EM_02000].

State diagram: State phases of a process in Execution Management. Sources: [SWS_EM_02000]

Usage Path

The typical usage path of an application process comprises initialization and the subsequent signaling of operational readiness. After being started by Execution Management, the process executes its internal startup routines. As soon as initialization is complete and regular operation begins, the process creates an instance of ExecutionClient and transmits the state ExecutionState::kRunning [SWS_EM_02000].

Execution Management receives this report and validates the transition. Should a process attempt to report kRunning while it is already in the Running state, this is evaluated as an invalid transition [SWS_EM_02281]. Execution Management likewise monitors whether the report is made in time, as its absence can lead to the failure of function group transitions [SWS_EM_02281].

Sequence diagram: Signaling of kRunning via ExecutionClient. Sources: [SWS_EM_02000], [SWS_EM_02281]

Error Scenarios

Error conditions within the module are represented by the error domain ExecErrorDomain. The function GetExecErrorDomain() provides a thread-safe and exception-safe reference to the global domain instance [SWS_EM_02290]. The function MakeErrorCode() serves to create standardized error objects of type ara::core::ErrorCode [SWS_EM_02291] by specifying the error code and vendor-specific additional data.

The specific error causes are defined in the enumeration ExecErrc [SWS_EM_02281]:

  • kNoCommunication (=3): Communication error, for example when sending a request or retrieving a result. If this error occurs between Execution Management and State Management, the overall system may have to transition to an unrecoverable state (Unrecoverable State) [SWS_EM_02281].
  • kInvalidMetaModelIdentifier (=4): Invalid metamodel identifier in function calls [SWS_EM_02281].
  • kOperationCanceled (=5): A state transition to a function group was canceled by a newer request [SWS_EM_02281].
  • kOperationFailed (=6): The requested operation failed, for example because kRunning of a process was not reported in time [SWS_EM_02281].
  • kInvalidTransition (=9): An invalid state transition was requested, e.g., reporting kRunning again when the process is already running [SWS_EM_02281].
  • kIntegrityOrAuthenticityCheckFailed (=14): The integrity or authenticity check of a process to be started has failed [SWS_EM_02281].
  • kUnexpectedTermination (=15): A process was terminated unexpectedly during a state transition [SWS_EM_02281].
  • kInvalidArgument (=16): A passed argument is invalid [SWS_EM_02281].

For exception-based error handling, the module also provides the exception class ExecException.

ExecutionState enumeration

Defines the internal states of a Process. Scoped enumeration of uint32_t. Please note that ara::exec::ExecutionState includes only states reportable by the Process to Execution Management and therefore does not include enumerations e.g. the "Initializing" state mentioned in Figure 7.2 and Figure 7.12, which are an implied states for Execution Management. The Initializing state starts when Process is first scheduled (so no code executed yet) and ends when kRunning is reported ([SWS_EM_01004]). The Terminating state starts when termination is requested by Execution Management and ends when the Process terminates ([SWS_EM_01404]). For the reasons mentioned, Execution Management assumes that Process is in initializing state until kRunning will be reported by it.

<h4>Lifecycle</h4>
<p>The lifecycle of a process is described by states that are partly managed implicitly by Execution Management and partly reported actively by the process <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>. The enumeration <code>ExecutionState</code> exclusively describes those states that the process can actively transmit to Execution Management. The only state value defined for this is <code>ExecutionState::kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</p>
<p>From the perspective of Execution Management, a process passes through the following phases:</p>
<ul>
<li><strong>Initializing:</strong> An implicit state that begins as soon as the process is scheduled by the operating system (before application-specific code is executed) and ends as soon as the process reports <code>kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</li>
<li><strong>Running:</strong> The active execution state after successfully reporting <code>ExecutionState::kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</li>
<li><strong>Terminating:</strong> Another implicit state that starts when Execution Management requests the termination of the process and concludes with the complete termination of the process <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical usage path of an application process comprises initialization and the subsequent signaling of operational readiness. After being started by Execution Management, the process executes its internal startup routines. As soon as initialization is complete and regular operation begins, the process creates an instance of <code>ExecutionClient</code> and transmits the state <code>ExecutionState::kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</p>
<p>Execution Management receives this report and validates the transition. Should a process attempt to report <code>kRunning</code> while it is already in the <em>Running</em> state, this is evaluated as an invalid transition <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>. Execution Management likewise monitors whether the report is made in time, as its absence can lead to the failure of function group transitions <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</p>

<h4>Error Scenarios</h4>
<p>Error conditions within the module are represented by the error domain <code>ExecErrorDomain</code>. The function <code>GetExecErrorDomain()</code> provides a thread-safe and exception-safe reference to the global domain instance <a class="spec-record-ref" data-req="SWS_EM_02290" href="../spec/record.html?id=SWS_EM_02290">[SWS_EM_02290]</a>. The function <code>MakeErrorCode()</code> serves to create standardized error objects of type <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_EM_02291" href="../spec/record.html?id=SWS_EM_02291">[SWS_EM_02291]</a> by specifying the error code and vendor-specific additional data.</p>
<p>The specific error causes are defined in the enumeration <code>ExecErrc</code> <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>:</p>
<ul>
<li><code>kNoCommunication</code> (=3): Communication error, for example when sending a request or retrieving a result. If this error occurs between Execution Management and State Management, the overall system may have to transition to an unrecoverable state (<em>Unrecoverable State</em>) <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kInvalidMetaModelIdentifier</code> (=4): Invalid metamodel identifier in function calls <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kOperationCanceled</code> (=5): A state transition to a function group was canceled by a newer request <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kOperationFailed</code> (=6): The requested operation failed, for example because <code>kRunning</code> of a process was not reported in time <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kInvalidTransition</code> (=9): An invalid state transition was requested, e.g., reporting <code>kRunning</code> again when the process is already running <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kIntegrityOrAuthenticityCheckFailed</code> (=14): The integrity or authenticity check of a process to be started has failed <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kUnexpectedTermination</code> (=15): A process was terminated unexpectedly during a state transition <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>kInvalidArgument</code> (=16): A passed argument is invalid <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
</ul>
<p>For exception-based error handling, the module also provides the exception class <code>ExecException</code>.</p>
