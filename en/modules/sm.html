From machine target to running application

ara::sm determines machine and function group states; The actual process management is carried out via execution management. The concept thus separates the technical decision about a target state from the start, stop and sequence of the processes. [SWS_SM_00400] SWS StateManagement §7.1 “Responsibilities” SWS StateManagement §7.6 “Interaction with Execution Management”

Configurable state machines

A StateMachine bundles states, transitions and ActionLists. A controlling application requests a transition; State notifications allow other applications to monitor the current state. The controller is unique per StateMachine configuration. SWS StateManagement §7.7 “StateMachine” [SWS_SM_00619]

Update session as state coordination

UCM begins collaboration via RequestUpdateSession(). PrepareUpdate, VerifyUpdate and, if necessary, PrepareRollback then lead the affected StateMachines to the configured states. The decision as to whether an update is permitted is project-specific and depends on the machine or vehicle condition. Behavior in the event of an error

The error domain SmErrorDomain defines SmErrc::kRejected for problems of an S2R satellite when entering or leaving suspend mode. Separately, type UpdateStatusType describes the progress values of the update service: kRejected for a request outside an update session and kFailed for failed processing. ResetMachineNotifier is a field with getter and notifier for this purpose; State Management sets it to inform UCM during and after ResetMachine(). [SWS_SM_81240] [SWS_SM_91027] [SWS_SM_91106]

For the StateMachine path, a ExecutionError is used by Execution Management (via GetExecutionError() or undefinedStateCallback) or by Platform Health Management (via the RecoveryHandler) as the ErrorCode of the StateMachine that manages the affected Function Group. For a StateMachine not marked as ImpactedByUpdate, State Management sets the ongoing error handling, evaluates the ErrorRecoveryTable, ends the previous ActionList processing and immediately switches to the configured subsequent state. For errors that are not explicitly mapped, a ANY entry is mandatory. [SWS_SM_00670] [SWS_SM_00601] [SWS_SM_CONSTR_00014]

Activity diagram: a process error reported by Execution Management or Platform Health Management is processed as an ErrorCode by the responsible StateMachine; ErrorRecoveryTable determines its target state and its ActionList. Sources: SWS State Management §7.7.13 “StateMachine ErrorCode configuration and handling” [SWS_SM_00601] [SWS_SM_00670].

Errors of a StateClient::SetState() call with ExecErrc::kNoCommunication, kInvalidTransition or kInvalidMetaModelIdentifier are mapped to the configured functionGroupTransitionRequestFailedError; without configuration, the error value 1 should be used. When updating, RequestUpdateSession() can be rejected with kOperationRejected because of the machine status; while a session is already active, kNotAllowedMultipleUpdateSessions is mandatory. ResetMachine() is rejected without a previously successfully requested update session and sets the ResetMachineNotifier to kRejected outside of an update session. If the transition to ContinueUpdate fails after a reset, kFailed should be set. [SWS_SM_00671] [SWS_SM_00672] [SWS_SM_91102] [SWS_SM_91100] [SWS_SM_00661] [SWS_SM_00663]
