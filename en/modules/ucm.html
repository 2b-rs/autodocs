PackageManagement as an update limit

ara::ucm::PackageManagement receives software packages, processes them and controls their activation, verification and, if necessary, restoration. CurrentStatus makes the global UCM phase observable. SWS UCM Chapter 7 “Functional specification” [SWS_UCM_00131] [SWS_UCM_00019]

Decouple transfer and processing

A transfer begins with TransferStart, the return value of which determines the permitted block size. TransferData transfers the blocks and TransferExit completes the transfer with completeness and format checks. ProcessSwPackage then processes the packet; multiple transfers can be separate from sequential processing. SWS UCM §7.3 “Transfer and processing” [SWS_UCM_00272] [SWS_UCM_00275] [SWS_UCM_00276]

Package and update states from the PackageManagement flow. Sources: SWS UCM §7.5 “Activation and rollback”, [SWS_UCM_00300]. Partial interpretation: The state graph combines separate transfer, processing and update states into a reading order.

Activation with state management

Before activation, dependencies are checked and an update session is requested from SM. UCM calculates the order of the calls PrepareUpdate, VerifyUpdate and PrepareRollback; these calls may not occur in parallel. A rejected session request leads back to the preparation phase. [SWS_UCM_00257] [SWS_UCM_00260] [SWS_UCM_00258]

Sequence for activation and verification via SM. Sources: SWS UCM §7.5 “Activation and rollback”, SWS StateManagement §7.3 “Interaction with UCM”.

Rollback, observation, and vehicle context

Rollback is a separate transition with a defined false output kRollingBackFailed; If successful, the specified SM calls follow to return to a consistent set of software clusters. The Vehicle UCM specification extends this package-oriented flow to include the vehicle and campaign perspective, not a second local PackageManagement semantics. [SWS_UCM_00300] [SWS_UCM_00301] SWS Vehicle UCM Chapter 7 “Functional specification”

Recommended client sequence

  1. Adopt transfer ID and blockSize from TransferStart.
  2. Send blocks with monotonically increasing blockCounter and call TransferExit only afterward.
  3. Process the package, check the status, and trigger Activate only from the preparation phase.
  4. After verification, select Finish or, if necessary, Rollback.
