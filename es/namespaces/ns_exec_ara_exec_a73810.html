Controla el ciclo de vida del proceso, supervisa los estados de ejecución y coordina las transiciones de estado de grupos de funciones.

El espacio de nombres proporciona interfaces para la gestión de procesos y el control de grupos de funciones en la AUTOSAR Adaptive Platform. Los procesos utilizan el cliente para notificar su estado de ejecución kRunning a Execution Management tras una inicialización correcta [SWS_EM_02000]. State Management solicita transiciones de grupos de funciones a través de interfaces, mientras que los cambios de estado no permitidos o los errores de comunicación se registran a través de códigos de error estandarizados [SWS_EM_02281]. Es obligatorio un cumplimiento estricto del orden de transición.

Contexto

El espacio de nombres ara::exec proporciona las interfaces de Execution Management en la AUTOSAR Adaptive Platform. El módulo es responsable de iniciar, controlar y supervisar procesos, así como de coordinar estados del sistema y de grupos de funciones de nivel superior. Entre los actores centrales se encuentran los procesos de aplicación, State Management y el propio Execution Management. Los procesos utilizan la clase ExecutionClient para notificar su estado interno en tiempo de ejecución a Execution Management. State Management utiliza a su vez la interfaz StateClient para solicitar cambios de estado entre grupos de funciones (FunctionGroup y FunctionGroupState). Para eventos de error al nivel de un grupo de funciones se utiliza el alias de tipo ExecutionError [SWS_EM_02541], que se puede transportar mediante ExecutionErrorEvent.

Ciclo de vida

El ciclo de vida de ejecución de un proceso está controlado por Execution Management [SWS_EM_02000]. Tras la planificación (scheduling), un proceso recién iniciado se encuentra inicialmente en un estado implícito Initializing, en el cual todavía no se ha ejecutado código de programa aplicativo. Execution Management asume que este estado de inicialización continúa hasta que el proceso notifica activamente el estado ExecutionState::kRunning a través de su ExecutionClient [SWS_EM_02000]. La enumeración ExecutionState se limita estrictamente a aquellos estados que los procesos pueden reportar a Execution Management y, por lo tanto, contiene exclusivamente el estado kRunning [SWS_EM_02000]. Si Execution Management solicita la finalización, el proceso pasa a la fase Terminating, que concluye con la terminación definitiva del proceso [SWS_EM_02000].

Diagrama de estados: Ciclo de vida de un proceso desde la perspectiva de Execution Management con estados implícitos y la notificación de kRunning. Fuentes: [SWS_EM_02000]

Ruta de uso

Un flujo de uso típico se divide en las siguientes fases:

  • Tras el arranque del sistema, el proceso es creado por Execution Management y lleva a cabo su inicialización interna [SWS_EM_02000].
  • Tan pronto como la inicialización se completa con éxito, el proceso notifica el estado ExecutionState::kRunning a Execution Management a través de una instancia de ExecutionClient [SWS_EM_02000].
  • Execution Management confirma esta transición; sin embargo, si se notifica kRunning cuando el proceso ya se encuentra en estado de ejecución, esto se rechaza como una transición no válida ExecErrc::kInvalidTransition [SWS_EM_02281].
  • Durante el funcionamiento posterior, State Management solicita transiciones de estado coordinadas para grupos de funciones a través de StateClient según sea necesario.

Diagrama de secuencia: secuencia de llamadas durante la notificación de estado a través del ExecutionClient y tratamiento de transiciones erróneas. Fuentes: [SWS_EM_02000], [SWS_EM_02281]

Escenarios de error

Las situaciones de error se asignan en el espacio de nombres ara::exec a través del tipo de enumeración ExecErrc y el dominio de error ExecErrorDomain [SWS_EM_02281]. La función segura frente a hilos y excepciones GetExecErrorDomain() proporciona una referencia al objeto de dominio global [SWS_EM_02290]. Los objetos de error concretos del tipo ara::core::ErrorCode se crean mediante la función auxiliar MakeErrorCode() pasando el código de error y datos de contexto específicos del fabricante [SWS_EM_02291]; además, para el tratamiento de excepciones está disponible la clase ExecException.

Entre las causas de error especificadas se incluyen [SWS_EM_02281]:

  • ExecErrc::kNoCommunication: señaliza un error de comunicación entre el cliente y Execution Management o entre State Management y Execution Management. A nivel de sistema, es de suponer que dicho estado requiera entrar en un estado no recuperable [SWS_EM_02281]. Pregunta Q-ad08207b6a16c6f9 (abierta)
  • ExecErrc::kInvalidTransition: transición no válida, por ejemplo, si un proceso notifica repetidamente kRunning [SWS_EM_02281].
  • ExecErrc::kOperationFailed: una operación falla, por ejemplo, si una transición de grupo de funciones no puede completarse porque kRunning no se notificó a tiempo [SWS_EM_02281].
  • ExecErrc::kOperationCanceled: un cambio de estado de un grupo de funciones fue cancelado por una solicitud más reciente [SWS_EM_02281].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed: falla la comprobación de integridad o autenticidad de un proceso que se va a iniciar [SWS_EM_02281].
  • ExecErrc::kUnexpectedTermination: interrupción anormal durante una transición [SWS_EM_02281].
  • ExecErrc::kInvalidMetaModelIdentifier así como ExecErrc::kInvalidArgument: identificadores del metamodelo no permitidos o valores de parámetro no válidos [SWS_EM_02281].

Esta guía se basa en la especificación AUTOSAR Adaptive R25-11 para el módulo Execution Management (ara::exec).

ExecutionState enumeración

Defines the internal states of a Process. Scoped enumeration of uint32_t. Please note that ara::exec::ExecutionState includes only states reportable by the Process to Execution Management and therefore does not include enumerations e.g. the "Initializing" state mentioned in Figure 7.2 and Figure 7.12, which are an implied states for Execution Management. The Initializing state starts when Process is first scheduled (so no code executed yet) and ends when kRunning is reported ([SWS_EM_01004]). The Terminating state starts when termination is requested by Execution Management and ends when the Process terminates ([SWS_EM_01404]). For the reasons mentioned, Execution Management assumes that Process is in initializing state until kRunning will be reported by it.

La enumeración ExecErrc [SWS_EM_02281] define códigos de error para Execution Management en el espacio de nombres ara::exec basándose en el tipo base ara::core::ErrorDomain::CodeType. Se utiliza junto con MakeErrorCode [SWS_EM_02291] para la encapsulación en ara::core::ErrorCode y se entrega a los llamadores de forma síncrona mediante ara::core::Result o de forma asíncrona mediante ara::core::Future.

Los enumeradores cubren diferentes estados de error [SWS_EM_02281]:

  • kNoCommunication identifica errores de comunicación al enviar solicitudes o recuperar resultados [SWS_EM_02281]. Si esto ocurre entre Execution Management y State Management, el sistema puede entrar en un Unrecoverable State [SWS_EM_02281]. Los clientes como ExecutionClient o StateClient solo notan esto en la siguiente llamada al método, siendo limitadas las opciones de recuperación del lado del cliente [SWS_EM_02281].
  • kOperationCanceled y kOperationFailed se producen durante cambios de estado de grupos de funciones [SWS_EM_02281], por ejemplo en SetState [SWS_EM_02278] o cuando se cancela una transición de arranque de la máquina [SWS_EM_02279].
  • kInvalidTransition señala transiciones de proceso no permitidas, por ejemplo si un proceso notifica repetidamente kRunning [SWS_EM_02281], relevante en ReportExecutionState [SWS_EM_02003].
  • kIntegrityOrAuthenticityCheckFailed, kUnexpectedTermination, kInvalidMetaModelIdentifier así como kInvalidArgument gestionan errores en comprobaciones de integridad, interrupciones anómalas de procesos durante cambios de estado de grupos de funciones o parámetros de función no válidos [SWS_EM_02281].

Los llamadores evalúan estos códigos de error para determinar si las transiciones de estado se completaron con éxito, fueron desplazadas por solicitudes posteriores o fueron bloqueadas por errores de configuración [SWS_EM_02281].

  Procedencia
  

      

      

      La enumeración tipificada ara::exec::ExecutionState [SWS_EM_02000] define los estados internos de un proceso que este puede notificar activamente a Execution Management. Se basa en el tipo subyacente std::uint32_t y se proporciona en el espacio de nombres ara::exec a través del archivo de cabecera ara/exec/execution_client.h o del archivo de cabecera de reenvío ara/exec/exec_fwd.h.
      

      La especificación define para procesos el enumerador notificable:
      

        

      • kRunning = 0: Este estado es notificado por un proceso después de haber sido iniciado por Execution Management [SWS_EM_02000].
        • 

      

      La enumeración contiene exclusivamente estados que pueden notificarse activamente. Por lo tanto, no incluye estados implícitos de Execution Management como Initializing o Terminating [SWS_EM_02000]. La fase de inicialización comienza con la primera planificación del proceso y finaliza con la notificación de kRunning [SWS_EM_01004]; hasta dicha notificación, Execution Management asume que el proceso se encuentra en la fase de inicialización. La fase de terminación comienza con la solicitud de finalización y termina con la detención del proceso [SWS_EM_01404].
      

      La notificación de estado se realiza a través de la interfaz ara::exec::ExecutionClient::ReportExecutionState [SWS_EM_02003]. Este método toma el ExecutionState actual como parámetro, está declarado como noexcept y es tanto seguro para subprocesos como seguro frente a excepciones. Devuelve un ara::core::Result<void> que confirma el éxito o, en caso de error, encapsula un código de error [SWS_EM_02003].
