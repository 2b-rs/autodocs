Contexto

El namespace ara::rds proporciona dentro de la AUTOSAR Adaptive Platform (Release R25-11) interfaces funcionales y estructuras de datos para el streaming de datos en bruto (Raw Data Streams). La tarea principal del módulo consiste en transmitir y procesar de forma eficiente a través de conexiones de red tanto flujos de datos binarios genéricos como datagramas de flujo especializados y tipados. El namespace se divide en dos áreas funcionales esenciales: la transmisión cliente-servidor genérica de flujos binarios y la transmisión estandarizada según la norma IEEE 1722.

Para la comunicación genérica, el namespace define los endpoints centrales RawDataStreamServer y RawDataStreamClient. Mientras que el servidor es responsable de aceptar conexiones de red entrantes y leer o escribir flujos de datos, el cliente actúa como contraparte activa para el establecimiento de la conexión y el subsiguiente acceso de lectura y escritura. El resultado de una operación de lectura se encapsula en la clase auxiliar ReadDataResult.

Para flujos de datos multimedia críticos en el tiempo o sensibles al tiempo, ara::rds proporciona componentes dedicados para el protocolo IEEE 1722. El rol de envío de datos lo asume aquí IEEE1722RawDataStreamProducer, mientras que la recepción y el filtrado se realizan mediante IEEE1722RawDataStreamConsumer. Los datagramas transmitidos se representan mediante una serie de clases estructuradas, entre ellas la representación base IEEE1722Datagram, estructuras de cabecera comunes como IEEE1722DatagramAVTPDUCommonHeaderFields y IEEE1722DatagramAVTPDUCommonStreamHeaderFields, así como derivaciones específicas de formato como IEEE1722DatagramAAF, IEEE1722DatagramRVF, IEEE1722DatagramCRF, IEEE1722DatagramTSCF, IEEE1722DatagramNTSCF y IEEE1722Datagram61883_IIDC.

Diagrama de contexto: interacción de los endpoints de comunicación y procesadores de flujos en el namespace ara::rds. Fuentes: no hay registros SWS directos disponibles en el payload.

Ruta de uso

Una ruta de uso típica en el namespace ara::rds difiere según si se implementa una conexión de flujo punto a punto genérica o un streaming tipado según IEEE 1722. En una transmisión genérica, la aplicación servidora inicializa primero una instancia de RawDataStreamServer y espera solicitudes de conexión entrantes. En paralelo, la aplicación cliente crea un RawDataStreamClient que establece una conexión de red con el servidor.

Tras el establecimiento exitoso de la conexión, se produce el intercambio bidireccional de datos binarios. Interpretación: la transmisión de los datos binarios a través de la conexión de red probablemente se basa en protocolos de transporte como TCP o UDP, realizándose el intercambio de datos bien por bloques o bien con búfer. Las operaciones de lectura en los endpoints proporcionan como valor de retorno una instancia de ReadDataResult, que suministra los datos útiles leídos así como información relativa al estado del proceso de lectura. Una vez concluida la transmisión de datos, las partes involucradas cierran los flujos y las conexiones de manera ordenada.

En el caso de uso del streaming IEEE 1722, una aplicación emisora crea el IEEE1722RawDataStreamProducer. Este se alimenta con datagramas estructurados cuyas cabeceras se parametrizan mediante IEEE1722DatagramAVTPDUCommonHeaderFields o IEEE1722DatagramAVTPDUCommonStreamHeaderFields. Interpretación: las clases de datagramas específicas como IEEE1722DatagramAAF (audio) o IEEE1722DatagramRVF (vídeo) probablemente encapsulan payloads AVTP estandarizados para permitir un streaming de audio y vídeo determinista en la red del vehículo. En el lado receptor, el IEEE1722RawDataStreamConsumer suscribe los flujos de datos tipados y reenvía los datagramas recibidos a la aplicación procesadora.

Escenarios de error

Las situaciones de error durante la inicialización, el establecimiento de la conexión o la transmisión de datos en curso se señalan en el namespace ara::rds a través del modelo de errores uniforme de la AUTOSAR Adaptive Platform. Este se basa en la arquitectura de dominios ara::core::ErrorDomain y códigos de error del tipo ara::core::ErrorCode.

Un componente central es la enumeración RdsErrc [SWS_RDS_12367], que está definida como enum class RdsErrc : ara::core::ErrorDomain::CodeType y enumera los estados de error específicos de módulo de Raw Data Stream. Las declaraciones se encuentran en el archivo de cabecera #include "ara/rds/rds_error_domain.h".

Para asignar los códigos de error al dominio de errores de RDS, la cabecera proporciona la función GetRdsErrorDomain [SWS_RDS_11298], que devuelve una referencia al objeto de dominio global RdsErrorDomain. Para generar un código de error completo a partir de un valor de enumeración y datos adicionales opcionales, se utiliza la función MakeErrorCode [SWS_RDS_11299], declarada como constexpr ara::core::ErrorCode MakeErrorCode(RdsErrc code, ara::core::ErrorDomain::SupportDataType data) noexcept.

Los escenarios de error típicos comprenden fallos en el establecimiento de la conexión, interrupciones de la conexión durante el flujo de datos, desbordamientos de búfer o errores de formato al analizar cabeceras IEEE 1722. Si se producen tales estados, los métodos afectados devuelven típicamente un ara::core::ErrorCode correspondiente. Siempre que en el lado del llamante se utilicen excepciones o sea necesario transferir errores a un contexto de excepción, la clase RdsException representa el tipo de excepción asociado para el namespace.

Esta guía se basa en la especificación de AUTOSAR Adaptive Platform Release R25-11. Todas las indicaciones se fundamentan en las definiciones y entradas SWS contenidas en el payload de la especificación.
