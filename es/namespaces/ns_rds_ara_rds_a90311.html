Permite la transferencia de flujos de datos binarios sin procesar y datagramas IEEE 1722 a través de conexiones de red.

El espacio de nombres proporciona interfaces funcionales para el envío y la recepción de flujos de datos binarios sin procesar a través de conexiones de red, así como para flujos de audio y vídeo AVTP de tiempo crítico AUTOSAR_AP_SWS_RawDataStream §1. Las aplicaciones establecen conexiones punto a punto mediante clases de cliente y de servidor, o bien utilizan clases dedicadas de productor y consumidor para la transmisión de datagramas tipados. Las operaciones de lectura ponen a disposición los datos sin procesar recibidos de forma estructurada en objetos de resultado. Los estados erróneos durante la transmisión se señalizan mediante un dominio de errores específico del módulo y códigos de error estandarizados [SWS_RDS_12367].

Contexto

El espacio de nombres ara::rds proporciona, dentro de AUTOSAR Adaptive Platform, interfaces funcionales para la transmisión de flujos de datos binarios sin procesar (Raw Data Streams) a través de conexiones de red AUTOSAR_AP_SWS_RawDataStream §1. La arquitectura atiende dos patrones de comunicación complementarios: la transmisión punto a punto genérica de flujos de bytes no estructurados y la transmisión en flujo (streaming) de tiempo crítico de datagramas tipados según el estándar IEEE 1722 (Audio Video Transport Protocol, AVTP).

Para la transmisión de flujos de bytes, RawDataStreamClient y RawDataStreamServer constituyen los componentes centrales. El RawDataStreamClient inicia una conexión de red y gestiona las operaciones posteriores de lectura y escritura, mientras que el RawDataStreamServer recibe y administra las solicitudes de conexión entrantes. Los resultados de las operaciones de lectura se encapsulan en instancias de la clase ReadDataResult para entregar los bloques de datos recibidos de manera estructurada a la lógica de aplicación.

Para flujos de audio, vídeo y control de tiempo crítico, ara::rds define un modelo de transmisión en flujo tipado: IEEE1722RawDataStreamProducer sirve de fuente para la generación y emisión de datagramas IEEE 1722, mientras que IEEE1722RawDataStreamConsumer actúa como sumidero para su recepción. Las cargas útiles y las cabeceras de protocolo se representan mediante tipos de datagrama especializados, tales como IEEE1722DatagramAAF (audio), IEEE1722DatagramRVF (vídeo), IEEE1722DatagramCRF (Clock Reference), así como datagramas de control (IEEE1722Datagram61883_IIDC, IEEE1722DatagramNTSCF, IEEE1722DatagramTSCF y el datagrama base IEEE1722Datagram). Los campos de cabecera comunes están encapsulados por IEEE1722DatagramAVTPDUCommonHeaderFields y IEEE1722DatagramAVTPDUCommonStreamHeaderFields.

Diagrama de contexto: interacción de las clases de streaming de cliente/servidor y los componentes de streaming IEEE 1722 con el dominio de errores en ara::rds. Fuentes: [SWS_RDS_11298], [SWS_RDS_11299], [SWS_RDS_12367], AUTOSAR_AP_SWS_RawDataStream §1.

Ruta de uso

En el funcionamiento operativo ordinario de una comunicación de flujo de bytes, un proceso de servidor instancia en primer lugar RawDataStreamServer para esperar conexiones entrantes en la red. Un proceso de cliente genera una instancia de RawDataStreamClient y establece la conexión de red con el servidor. En cuanto la conexión está lista, los interlocutores de comunicación ejecutan llamadas de lectura o de escritura. Cada llamada de lectura devuelve un ReadDataResult, que pone a disposición los datos binarios leídos para su posterior procesamiento.

En el escenario AVTP, un productor de datos instancia un IEEE1722RawDataStreamProducer y configura las cabeceras de protocolo y de flujo deseadas mediante IEEE1722DatagramAVTPDUCommonStreamHeaderFields. Los datos útiles se empaquetan en datagramas específicos del dominio, tales como IEEE1722DatagramAAF o IEEE1722DatagramRVF. Interpretación: es previsible que la transmisión al IEEE1722RawDataStreamConsumer se efectúe típicamente a través de una red AVB/TSN, tras lo cual el consumidor recibe y decodifica los datagramas tipados. Pregunta Q-3502e4b3d8365e69 (abierta)

Escenarios de error

El tratamiento de errores en ara::rds se integra a la perfección en el modelo de Adaptive Platform y se apoya en dominios y códigos de error AUTOSAR_AP_SWS_RawDataStream §1. El módulo define el dominio de errores RdsErrorDomain, cuya instancia se puede obtener a través de la función GetRdsErrorDomain() [SWS_RDS_11298].

Las situaciones de error concretas, como interrupciones de transmisión o conflictos de conexión, se representan mediante la enumeración RdsErrc [SWS_RDS_12367]. Para la generación de objetos de error específicos del módulo, el espacio de nombres proporciona la función auxiliar MakeErrorCode(RdsErrc code, ara::core::ErrorDomain::SupportDataType data) [SWS_RDS_11299]. Interpretación: es previsible que las operaciones de E/S fallidas de las clases de streaming devuelvan un ara::core::ErrorCode correspondiente. Pregunta Q-16627290fe526e68 (abierta) Para las rutas de ejecución basadas en excepciones existe, además, el tipo especializado RdsException.
