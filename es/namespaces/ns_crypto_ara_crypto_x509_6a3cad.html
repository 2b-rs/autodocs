Contexto

Dentro del módulo crypto de AUTOSAR Adaptive Platform, el espacio de nombres ara::crypto::x509 proporciona interfaces y tipos de datos para la gestión de infraestructuras de clave pública (PKI) según el estándar X.509. La responsabilidad principal incluye la representación de certificados X.509 (Certificate), solicitudes de firma de certificados (CertSignRequest), nombres distinguidos (X509DN), así como la configuración y ejecución de la validación de rutas de certificación mediante CertificateValidationCtx y CertificateValidationResult. La información de estado del Online Certificate Status Protocol se mapea mediante OcspResponse. El X509Provider actúa como punto de entrada e interfaz de nivel superior.

Diagrama de contexto: interfaces principales y su interacción en el espacio de nombres ara::crypto::x509. Fuentes: [SWS_CRYPT_50107], [SWS_CRYPT_40203], [SWS_CRYPT_40001].

Ruta de uso

Un caso de uso típico consiste en la verificación de certificados entrantes en el marco de relaciones de comunicación seguras o en la comprobación de firmas e integridad de artefactos de código. Un Certificate define restricciones de uso mediante usos de clave estándar (X509KeyUsage [SWS_CRYPT_40101]) y finalidades de uso ampliadas (X509ExtendedKeyUsage [SWS_CRYPT_50097]).

Para fines de uso estándar, se dispone de máscaras de bits:

  • kConstrDigitalSignature [SWS_CRYPT_40151] para firmas digitales,
  • kConstrNonRepudiation [SWS_CRYPT_40152] para servicios de no repudio,
  • kConstrKeyEncipherment [SWS_CRYPT_40153] y kConstrDataEncipherment [SWS_CRYPT_40154] para cifrado de claves o de datos,
  • kConstrKeyAgreement [SWS_CRYPT_40155] para acuerdos de claves,
  • kConstrKeyCertSign [SWS_CRYPT_40156] y kConstrCrlSign [SWS_CRYPT_40157] para la firma de certificados o listas de revocación de certificados (CRL),
  • kConstrEncipherOnly [SWS_CRYPT_40158] y kConstrDecipherOnly [SWS_CRYPT_40159] para operaciones exclusivas de cifrado o descifrado.

Los fines de uso ampliados se especifican mediante los flags correspondientes, entre ellos kServerAuth [SWS_CRYPT_50098] y kClientAuth [SWS_CRYPT_50099] para autenticaciones TLS, kCodeSigning [SWS_CRYPT_50100] para código ejecutable, kEmailProtection [SWS_CRYPT_50101] para protección de correo electrónico, kTimeStamping [SWS_CRYPT_50102] para sellado de tiempo, así como kOCSPSigning [SWS_CRYPT_50103] para respuestas OCSP.

Interpretación: Un contexto de validación (CertificateValidationCtx) probablemente se obtenga a través del X509Provider. La validación se parametriza previamente mediante flags de bits del tipo CertificateValidationOptions [SWS_CRYPT_50107]:

  • Los periodos de validez se pueden excluir de la comprobación mediante kIgnoreNotBefore [SWS_CRYPT_50108] o kIgnoreNotAfter [SWS_CRYPT_50109].
  • Las extensiones críticas desconocidas se pueden tolerar de forma global mediante kIgnoreUnknownCriticalExtensions [SWS_CRYPT_50110].
  • Las comprobaciones de revocación se controlan mediante kIgnoreCrl [SWS_CRYPT_50111] para CRL o mediante flags de OCSP: por defecto, OCSP está inactivo (kOcspOff [SWS_CRYPT_50114]), pero se puede aplicar a toda la cadena de certificados (kOcspResponseCompleteChain [SWS_CRYPT_50112]) o exclusivamente al certificado de destino (kOcspResponseTargetOnly [SWS_CRYPT_50113]).

Tras la ejecución de la validación de la ruta, el contexto devuelve un CertificateValidationResult, del cual se deduce el resultado global.

Diagrama de secuencia: flujo típico de la validación de certificados a través del contexto de validación. Fuentes: [SWS_CRYPT_50107], [SWS_CRYPT_40203].

Escenarios de error

La evaluación del resultado de validación se realiza mediante la enumeración CertificateValidationStatus [SWS_CRYPT_40203]. Los posibles estados de error y valores de estado incluyen:

  • kValid: La validación de la ruta de certificación fue satisfactoria.
  • kInvalidSignature: No se pudo verificar una firma dentro de la cadena de certificados.
  • kNoPathToTrustedCertificate: No se pudo establecer una ruta completa hacia un certificado raíz de confianza.
  • kExpired o bien kFuture: El certificado ha caducado (notAfter) o aún no es válido en el momento actual (notBefore).
  • kRevoked: El certificado ha sido revocado mediante una CRL importada o una respuesta OCSP.
  • kUnknownOcspStatus: El estado del certificado es desconocido según la respuesta OCSP.
  • kUnknownCriticalExtension: Un certificado contiene una extensión crítica desconocida que no fue aprobada ni mediante el flag kIgnoreUnknownCriticalExtensions ni mediante la función IgnoreCriticalExtension().

Si se utiliza OCSP, la interfaz OcspResponse proporciona el estado mediante OcspResponseStatus [SWS_CRYPT_40001]. En este caso, kSuccessful señala una confirmación válida, mientras que los escenarios de error como solicitudes inadmisibles (kMalformedRequest), errores internos del emisor (kInternalError), sobrecarga temporal (kTryLater), firmas de solicitud obligatorias (kSigRequired) o falta de autorización (kUnauthorized) deben tratarse de forma diferenciada.

Esta guía resume la especificación del espacio de nombres ara::crypto::x509 para la versión R25-11 y se basa exclusivamente en las interfaces y enumeraciones definidas.

<h4>Contexto</h4>
<p>Dentro del módulo <code>crypto</code> de AUTOSAR Adaptive Platform, el espacio de nombres <code>ara::crypto::x509</code> proporciona interfaces y tipos de datos para la gestión de infraestructuras de clave pública (PKI) según el estándar X.509. La responsabilidad principal incluye la representación de certificados X.509 (<code>Certificate</code>), solicitudes de firma de certificados (<code>CertSignRequest</code>), nombres distinguidos (<code>X509DN</code>), así como la configuración y ejecución de la validación de rutas de certificación mediante <code>CertificateValidationCtx</code> y <code>CertificateValidationResult</code>. La información de estado del Online Certificate Status Protocol se mapea mediante <code>OcspResponse</code>. El <code>X509Provider</code> actúa como punto de entrada e interfaz de nivel superior.</p>

<h4>Ruta de uso</h4>
<p>Un caso de uso típico consiste en la verificación de certificados entrantes en el marco de relaciones de comunicación seguras o en la comprobación de firmas e integridad de artefactos de código. Un <code>Certificate</code> define restricciones de uso mediante usos de clave estándar (<code>X509KeyUsage</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40101" href="../spec/record.html?id=SWS_CRYPT_40101">[SWS_CRYPT_40101]</a>) y finalidades de uso ampliadas (<code>X509ExtendedKeyUsage</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50097" href="../spec/record.html?id=SWS_CRYPT_50097">[SWS_CRYPT_50097]</a>).</p>
<p>Para fines de uso estándar, se dispone de máscaras de bits:</p>
<ul>
<li><code>kConstrDigitalSignature</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40151" href="../spec/record.html?id=SWS_CRYPT_40151">[SWS_CRYPT_40151]</a> para firmas digitales,</li>
<li><code>kConstrNonRepudiation</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40152" href="../spec/record.html?id=SWS_CRYPT_40152">[SWS_CRYPT_40152]</a> para servicios de no repudio,</li>
<li><code>kConstrKeyEncipherment</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40153" href="../spec/record.html?id=SWS_CRYPT_40153">[SWS_CRYPT_40153]</a> y <code>kConstrDataEncipherment</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40154" href="../spec/record.html?id=SWS_CRYPT_40154">[SWS_CRYPT_40154]</a> para cifrado de claves o de datos,</li>
<li><code>kConstrKeyAgreement</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40155" href="../spec/record.html?id=SWS_CRYPT_40155">[SWS_CRYPT_40155]</a> para acuerdos de claves,</li>
<li><code>kConstrKeyCertSign</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40156" href="../spec/record.html?id=SWS_CRYPT_40156">[SWS_CRYPT_40156]</a> y <code>kConstrCrlSign</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40157" href="../spec/record.html?id=SWS_CRYPT_40157">[SWS_CRYPT_40157]</a> para la firma de certificados o listas de revocación de certificados (CRL),</li>
<li><code>kConstrEncipherOnly</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40158" href="../spec/record.html?id=SWS_CRYPT_40158">[SWS_CRYPT_40158]</a> y <code>kConstrDecipherOnly</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40159" href="../spec/record.html?id=SWS_CRYPT_40159">[SWS_CRYPT_40159]</a> para operaciones exclusivas de cifrado o descifrado.</li>
</ul>
<p>Los fines de uso ampliados se especifican mediante los flags correspondientes, entre ellos <code>kServerAuth</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50098" href="../spec/record.html?id=SWS_CRYPT_50098">[SWS_CRYPT_50098]</a> y <code>kClientAuth</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50099" href="../spec/record.html?id=SWS_CRYPT_50099">[SWS_CRYPT_50099]</a> para autenticaciones TLS, <code>kCodeSigning</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50100" href="../spec/record.html?id=SWS_CRYPT_50100">[SWS_CRYPT_50100]</a> para código ejecutable, <code>kEmailProtection</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50101" href="../spec/record.html?id=SWS_CRYPT_50101">[SWS_CRYPT_50101]</a> para protección de correo electrónico, <code>kTimeStamping</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50102" href="../spec/record.html?id=SWS_CRYPT_50102">[SWS_CRYPT_50102]</a> para sellado de tiempo, así como <code>kOCSPSigning</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50103" href="../spec/record.html?id=SWS_CRYPT_50103">[SWS_CRYPT_50103]</a> para respuestas OCSP.</p>
<p>Interpretación: Un contexto de validación (<code>CertificateValidationCtx</code>) probablemente se obtenga a través del <code>X509Provider</code>. La validación se parametriza previamente mediante flags de bits del tipo <code>CertificateValidationOptions</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50107" href="../spec/record.html?id=SWS_CRYPT_50107">[SWS_CRYPT_50107]</a>:</p>
<ul>

<li>Las extensiones críticas desconocidas se pueden tolerar de forma global mediante <code>kIgnoreUnknownCriticalExtensions</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50110" href="../spec/record.html?id=SWS_CRYPT_50110">[SWS_CRYPT_50110]</a>.</li>

<h4>Escenarios de error</h4>
<p>La evaluación del resultado de validación se realiza mediante la enumeración <code>CertificateValidationStatus</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40203" href="../spec/record.html?id=SWS_CRYPT_40203">[SWS_CRYPT_40203]</a>. Los posibles estados de error y valores de estado incluyen:</p>
<ul>
<li><code>kValid</code>: La validación de la ruta de certificación fue satisfactoria.</li>
<li><code>kInvalidSignature</code>: No se pudo verificar una firma dentro de la cadena de certificados.</li>
<li><code>kNoPathToTrustedCertificate</code>: No se pudo establecer una ruta completa hacia un certificado raíz de confianza.</li>
<li><code>kExpired</code> o bien <code>kFuture</code>: El certificado ha caducado (<code>notAfter</code>) o aún no es válido en el momento actual (<code>notBefore</code>).</li>
<li><code>kRevoked</code>: El certificado ha sido revocado mediante una CRL importada o una respuesta OCSP.</li>
<li><code>kUnknownOcspStatus</code>: El estado del certificado es desconocido según la respuesta OCSP.</li>
<li><code>kUnknownCriticalExtension</code>: Un certificado contiene una extensión crítica desconocida que no fue aprobada ni mediante el flag <code>kIgnoreUnknownCriticalExtensions</code> ni mediante la función <code>IgnoreCriticalExtension()</code>.</li>
</ul>
<p>Si se utiliza OCSP, la interfaz <code>OcspResponse</code> proporciona el estado mediante <code>OcspResponseStatus</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40001" href="../spec/record.html?id=SWS_CRYPT_40001">[SWS_CRYPT_40001]</a>. En este caso, <code>kSuccessful</code> señala una confirmación válida, mientras que los escenarios de error como solicitudes inadmisibles (<code>kMalformedRequest</code>), errores internos del emisor (<code>kInternalError</code>), sobrecarga temporal (<code>kTryLater</code>), firmas de solicitud obligatorias (<code>kSigRequired</code>) o falta de autorización (<code>kUnauthorized</code>) deben tratarse de forma diferenciada.</p>
