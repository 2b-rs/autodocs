Ofrece interfaces y estructuras de datos para la representación, configuración y validación de certificados X.509.

El espacio de nombres ara::crypto::x509 proporciona interfaces y tipos de datos para la gestión, definición de uso y validación de certificados X.509, así como respuestas OCSP en AUTOSAR Adaptive. A través del contexto de validación CertificateValidationCtx, se comprueban las rutas de certificación parametrizadas a partir de opciones como CertificateValidationOptions [SWS_CRYPT_50107]. El resultado se devuelve de forma estructurada mediante valores de estado como CertificateValidationStatus [SWS_CRYPT_40203], donde las comprobaciones de revocación en línea están inactivas de forma predeterminada y deben configurarse explícitamente.

Contexto

El espacio de nombres ara::crypto::x509 proporciona las interfaces y los tipos de datos centrales para el procesamiento y la validación de estructuras de certificados X.509 en la AUTOSAR Adaptive Platform. El modelo de interfaces abarca la representación de certificados digitales (Certificate), solicitudes de firma de certificados (CertSignRequest), nombres distinguidos (X509DN) y respuestas OCSP (OcspResponse). La instanciación y gestión de estos artefactos criptográficos se realiza típicamente a través de la interfaz de proveedor X509Provider (interpretación: el proveedor actúa como instancia factoría central para objetos X.509).

Para los certificados, el espacio de nombres define fines de uso de claves estandarizados mediante el tipo X509KeyUsage [SWS_CRYPT_40101]. Entre las constantes de bits se incluyen la generación de firmas digitales kConstrDigitalSignature [SWS_CRYPT_40151], no repudio kConstrNonRepudiation [SWS_CRYPT_40152], cifrado de claves kConstrKeyEncipherment [SWS_CRYPT_40153], cifrado de datos kConstrDataEncipherment [SWS_CRYPT_40154], acuerdo de claves kConstrKeyAgreement [SWS_CRYPT_40155], firma de certificados kConstrKeyCertSign [SWS_CRYPT_40156], firma de CRL kConstrCrlSign [SWS_CRYPT_40157], así como cifrado puro kConstrEncipherOnly [SWS_CRYPT_40158] y descifrado kConstrDecipherOnly [SWS_CRYPT_40159]. Adicionalmente, X509ExtendedKeyUsage [SWS_CRYPT_50097] describe fines de uso extendidos, tales como autenticación de servidor TLS kServerAuth [SWS_CRYPT_50098], autenticación de cliente TLS kClientAuth [SWS_CRYPT_50099], firma de código kCodeSigning [SWS_CRYPT_50100], protección de correo electrónico kEmailProtection [SWS_CRYPT_50101], servicios de sellado de tiempo kTimeStamping [SWS_CRYPT_50102] y firma de OCSP kOCSPSigning [SWS_CRYPT_50103].

Diagrama de contexto: interacción de las interfaces centrales para la gestión de certificados y validación de rutas. Fuentes: [SWS_CRYPT_40101], [SWS_CRYPT_50097]

Ruta de uso

El flujo operativo primario en el espacio de nombres consiste en la comprobación de rutas de certificación a través de CertificateValidationCtx. El comportamiento de validación se parametriza mediante máscaras de bits del tipo CertificateValidationOptions [SWS_CRYPT_50107]. De forma predeterminada, la comprobación de rutas se lleva a cabo sin la integración de consultas de estado de certificados en línea mediante la opción kOcspOff [SWS_CRYPT_50114]. Si la validez se debe verificar en línea, se puede activar o bien la comprobación de toda la cadena a través de kOcspResponseCompleteChain [SWS_CRYPT_50112], o bien exclusivamente para el certificado de destino mediante kOcspResponseTargetOnly [SWS_CRYPT_50113].

Para escenarios de comprobación específicos, otras opciones de validación permiten anular las comprobaciones predeterminadas: de este modo, se pueden ignorar los límites temporales de validez a través de kIgnoreNotBefore [SWS_CRYPT_50108] y kIgnoreNotAfter [SWS_CRYPT_50109]. Asimismo, la evaluación de listas de revocación de certificados (CRL) importadas previamente se puede desactivar con kIgnoreCrl [SWS_CRYPT_50111] o se puede suprimir la señalización de errores en caso de extensiones críticas desconocidas mediante kIgnoreUnknownCriticalExtensions [SWS_CRYPT_50110]. Tras realizar la validación, el contexto devuelve un objeto de resultado CertificateValidationResult (interpretación: la llamada de validación integra el certificado de destino, las opciones de comprobación y las respuestas OCSP opcionales, y encapsula el resultado en la clase de resultado).

Diagrama de secuencia: flujo de una validación de certificados mediante un contexto de comprobación y evaluación del resultado. Fuentes: [SWS_CRYPT_50107], [SWS_CRYPT_40203]

Escenarios de error

El resultado de una comprobación de ruta de certificación se desglosa en detalle mediante la enumeración CertificateValidationStatus [SWS_CRYPT_40203]. Una validación correcta se señaliza mediante kValid (= 0). Si la comprobación falla, valores de estado específicos indican la causa exacta:

  • kInvalidSignature (= 1): No se pudo verificar con éxito una firma dentro de la ruta de certificación.
  • kNoPathToTrustedCertificate (= 3): No se pudo construir ninguna ruta hacia un certificado raíz clasificado como de confianza.
  • kExpired (= 4): El certificado ha superado el periodo de validez (campo notAfter).
  • kFuture (= 5): El periodo de validez del certificado aún no ha comenzado según el campo notBefore.
  • kRevoked (= 6): El certificado ha sido revocado; este estado resulta de CRL importadas o de una comprobación OCSP activa mediante kOcspResponseCompleteChain o kOcspResponseTargetOnly.
  • kUnknownOcspStatus (= 7): Una respuesta OCSP integrada devuelve para el certificado el estado «unknown».
  • kUnknownCriticalExtension (= 8): Un certificado contiene una extensión crítica desconocida que no fue ignorada ni mediante kIgnoreUnknownCriticalExtensions ni por un tratamiento previo de excepciones.

OcspResponseStatus [SWS_CRYPT_40001] señaliza el resultado de la recuperación del protocolo siempre que se procesen consultas de estado en línea en el proceso de validación. Además de una confirmación de respuesta satisfactoria (kSuccessful = 0), pueden producirse errores de protocolo y del lado del servidor: solicitudes no válidas (kMalformedRequest = 1), errores internos del emisor (kInternalError = 2), sobrecarga temporal (kTryLater = 3), la necesidad de una firma (kSigRequired = 5) o falta de autorización (kUnauthorized = 6).
