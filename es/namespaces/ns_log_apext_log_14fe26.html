Contexto

El namespace apext::log representa una extensión específica de la plataforma dentro del módulo log de la AUTOSAR Adaptive Platform. Su tarea central consiste en proporcionar una interfaz estandarizada entre el framework de registro y herramientas externas de rastreo en tiempo de ejecución. El namespace incluye la función de interfaz TraceArti [SWS_LOG_20000], la cual se incluye a través del archivo de cabecera apext/log/trace_arti.h [SWS_LOG_20000].

En la interacción participan esencialmente tres componentes: el framework de registro de nivel superior, el namespace apext::log como capa de intermediación y la herramienta de rastreo utilizada en cada caso [SWS_LOG_20000]. El framework de registro conmuta internamente entre el registro estándar y el seguimiento de ejecución basado en ARTI, y reenvía los mensajes modelados a la interfaz [SWS_LOG_20000]. La herramienta de rastreo recibe finalmente estos datos y los procesa de forma específica para la herramienta [SWS_LOG_20000].

Diagrama de contexto: interacción entre el framework de registro, el namespace de extensión apext::log y la herramienta de rastreo. Fuentes: [SWS_LOG_20000]

Ciclo de vida

En la versión R25-11, apext::log no define clases independientes ni objetos con estado que tengan un ciclo complejo de instanciación o destrucción. La interacción se basa completamente en la función de plantilla libre TraceArti [SWS_LOG_20000]. La vida útil de los datos participantes está vinculada al momento de ejecución de la invocación correspondiente.

En lo que respecta a la concurrencia, la función TraceArti está especificada explícitamente como segura para subprocesos (thread-safe) [SWS_LOG_20000]. Por lo tanto, varios subprocesos de una aplicación o del framework de registro pueden invocar la función simultáneamente sin necesidad de implementar medidas de sincronización externas por parte del invocador. En cuanto a la seguridad frente a excepciones, se aplica la clasificación exception safe; la declaración de la función cuenta además con el especificador noexcept [SWS_LOG_20000]. Las llamadas de rastreo no deben desestabilizar el sistema en su conjunto en ningún momento mediante excepciones propagadas de forma incontrolada.

Ruta de uso

La función TraceArti no está diseñada para la invocación directa por parte de software de aplicación. Se invoca exclusivamente de forma interna por el framework de registro cuando este conmuta entre el registro normal y TraceArti [SWS_LOG_20000]. Interpretación: Los desarrolladores de aplicaciones probablemente no interactúan directamente con este namespace, sino que utilizan las interfaces regulares de registro de la plataforma, mientras que la conmutación se controla internamente en el framework.

El flujo regular de una invocación de rastreo se estructura de la siguiente manera:

  1. El framework de registro detecta un evento a registrar y decide sobre el reenvío al subsistema de rastreo [SWS_LOG_20000].
  2. El framework invoca apext::log::TraceArti(msg_id, params...) [SWS_LOG_20000]. Como parámetros se pasan un identificador que identifica el mensaje (msg_id) de un tipo definido por la implementación, así como argumentos cualesquiera específicos del mensaje (params...) [SWS_LOG_20000].
  3. La función procesa el mensaje modelado y transfiere los datos a la herramienta de rastreo conectada [SWS_LOG_20000].

Un objetivo arquitectónico central es la minimización del sobrecoste en tiempo de ejecución (runtime overhead), el cual debe ser lo menor posible [SWS_LOG_20000]. Para lograr esto, la especificación prevé explícitamente especializaciones de plantilla basadas en el tipo MsgId [SWS_LOG_20000]. De este modo, la serialización o el almacenamiento directo en el búfer de rastreo pueden adaptarse de forma óptima a la herramienta de destino en tiempo de compilación.

Escenarios de error

Para la invocación de TraceArti no hay definidos valores de retorno (void o None) y no están previstos códigos de error funcionales [SWS_LOG_20000]. En combinación con la garantía noexcept, esto significa que los problemas surgidos durante la generación del rastreo no se comunican al invocador mediante mensajes de error ni excepciones [SWS_LOG_20000]. Interpretación: Las posibles condiciones de error en la herramienta de rastreo, como por ejemplo desbordamientos de búfer o pérdidas de conexión, probablemente se gestionan o descartan internamente en la herramienta para no bloquear el flujo principal del programa.

Como condición previa esencial, la msg_id pasada debe coincidir con el modelo esperado por la herramienta de rastreo [SWS_LOG_20000]. Interpretación: Si para un ID de mensaje pasado no existiera una especialización de plantilla adecuada, esto debería dar lugar a errores de compilación o recurrir a una implementación genérica de reserva, lo que, no obstante, podría provocar potencialmente un mayor sobrecoste en tiempo de ejecución.

Esta guía se basa en la especificación de AUTOSAR Adaptive para el módulo log en la versión R25-11.
