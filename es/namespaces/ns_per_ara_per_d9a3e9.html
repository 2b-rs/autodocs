Permite el almacenamiento persistente y la gestión de datos de aplicación mediante almacenamiento clave-valor y de archivos.

El espacio de nombres ara::per proporciona interfaces para el almacenamiento persistente de datos al permitir que las aplicaciones adaptativas accedan a áreas de almacenamiento basadas en archivos y en pares clave-valor mediante identificadores de instancia ([SWS_PER_00052], [SWS_PER_00116]). Las aplicaciones gestionan almacenamientos abiertos mediante identificadores compartidos (handles), realizan actualizaciones coordinadas en caso de modificaciones del manifiesto y pueden reparar datos inconsistentes a través de mecanismos de recuperación ([SWS_PER_00333], [SWS_PER_00357]). Mientras que los accesos al almacenamiento se producen de forma concurrente a través de handles, los procedimientos administrativos como actualizaciones o reinicios de almacenamiento exigen la ausencia de accesos concurrentes ([SWS_PER_00311]).

Contexto

El espacio de nombres ara::per proporciona las interfaces del grupo funcional de persistencia para la AUTOSAR Adaptive Platform. Su responsabilidad principal es el almacenamiento duradero y persistente en memoria de datos de aplicación a través de reinicios del sistema y ciclos de vida de los procesos. El módulo distingue dos paradigmas de almacenamiento fundamentales: KeyValueStorage para pares clave-valor estructurados y FileStorage para acceso al almacenamiento basado en archivos. Las aplicaciones adaptativas acceden a estos recursos a través de prototipos de puerto configurados mediante ara::core::InstanceSpecifier ([SWS_PER_00052], [SWS_PER_00116]).

Interlocutores de interacción importantes del espacio de nombres son el Update and Configuration Management (UCM), que puede proporcionar configuraciones de destino (Target Configuration) actualizadas durante el tiempo de ejecución ([SWS_PER_00576], [SWS_PER_00577]), así como el medio de almacenamiento físico, en el que ara::per garantiza la consistencia, la redundancia y la seguridad de los datos ([SWS_PER_00311]).

Diagrama de contexto: interacción entre la aplicación, ara::per, Update Management y el almacenamiento físico. Fuentes: [SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00576]

Ciclo de vida

El acceso a los objetos de almacenamiento se regula mediante abstracciones de handle. La apertura de un almacenamiento a través de OpenKeyValueStorage o OpenFileStorage genera un SharedHandle ([SWS_PER_00052], [SWS_PER_00116]). Dado que varios subprocesos pueden acceder de forma concurrente al mismo almacenamiento, el recurso físico no se cierra necesariamente cuando un único SharedHandle sale de su ámbito; el cierre se efectúa solo cuando se han destruido todas las instancias referenciadoras de SharedHandle ([SWS_PER_00052], [SWS_PER_00116]).

Para los archivos dentro de un FileStorage, se realiza un seguimiento detallado de los estados de creación y modificación. La enumeración FileCreationState refleja si un archivo se creó durante la instalación (kCreatedDuringInstallation), durante una actualización (kCreatedDuringUpdate), mediante un reinicio (kCreatedDuringReset), a consecuencia de una recuperación (kCreatedDuringRecovery) o por la propia aplicación (kCreatedByApplication) ([SWS_PER_00435]). Análogamente, FileModificationState refleja cuándo y mediante qué proceso se modificó un archivo por última vez ([SWS_PER_00436]).

Para gestionar estados iniciales, el espacio de nombres proporciona funciones de reinicio: ResetKeyValueStorage ([SWS_PER_00334]) y ResetAllFiles ([SWS_PER_00336]) restablecen almacenamientos individuales a los valores definidos inicialmente en el manifiesto. Por el contrario, la operación global ResetPersistency ([SWS_PER_00358]) vacía completamente todos los almacenamientos clave-valor y de archivos; su regeneración tiene lugar en la siguiente llamada a OpenFileStorage o OpenKeyValueStorage.

En lo relativo a la concurrencia, las funciones de apertura (OpenFileStorage, OpenKeyValueStorage), las consultas de tamaño de almacenamiento (GetCurrentFileStorageSize, GetCurrentKeyValueStorageSize) así como las funciones de reinicio y recuperación relacionadas con el almacenamiento son seguras para subprocesos ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00405], [SWS_PER_00406], [SWS_PER_00333], [SWS_PER_00334], [SWS_PER_00335], [SWS_PER_00336]). Por el contrario, los procesos globales de actualización y limpieza como UpdatePersistency ([SWS_PER_00357]), CleanUpPersistency ([SWS_PER_00567]), ResetPersistency ([SWS_PER_00358]), CheckForManifestUpdate ([SWS_PER_00576]) y ReloadPersistencyManifest ([SWS_PER_00577]) están declarados como no seguros para subprocesos.

Ruta de uso

Un flujo de aplicación típico abarca la comprobación de actualizaciones de configuración, la aplicación de migraciones de datos y el posterior acceso al almacenamiento:

Antes o durante el funcionamiento regular, la aplicación comprueba mediante CheckForManifestUpdate si el UCM ha instalado una nueva configuración de destino ([SWS_PER_00576]). Si es el caso, se lee el nuevo manifiesto a través de ReloadPersistencyManifest ([SWS_PER_00577]). Durante la fase de verificación posterior, la aplicación inicia UpdatePersistency ([SWS_PER_00357]). Con el fin de controlar migraciones de datos específicas de la versión, la aplicación registra previamente mediante RegisterApplicationDataUpdateCallback una función de retrollamada que es informada sobre versiones de contrato más antiguas y ejecuta pasos de migración propios de la aplicación ([SWS_PER_00356]). Adicionalmente, las modificaciones de elementos se pueden supervisar mediante RegisterDataUpdateIndication ([SWS_PER_00578]). Tras concluir la actualización, CleanUpPersistency elimina copias de seguridad obsoletas y elementos heredados redundantes ([SWS_PER_00567]).

Para el acceso regular, la aplicación abre el recurso de destino a través de OpenKeyValueStorage ([SWS_PER_00052]) o OpenFileStorage ([SWS_PER_00116]). Los accesos a archivos en FileStorage se controlan mediante máscaras de bits de la enumeración OpenMode (p. ej., kAtTheBeginning, kAtTheEnd, kTruncate, kAppend), las cuales se combinan mediante los operadores operator| ([SWS_PER_00144]) y operator|= ([SWS_PER_00434]) ([SWS_PER_00147]). Los posicionamientos se realizan de forma relativa a Origin (kBeginning, kCurrent, kEnd) ([SWS_PER_00146]). El tamaño de almacenamiento ocupado actualmente puede determinarse en tiempo de ejecución a través de GetCurrentKeyValueStorageSize ([SWS_PER_00405]) y GetCurrentFileStorageSize ([SWS_PER_00406]).

Diagrama de secuencia: flujo para la comprobación de actualizaciones de manifiesto, realización de la actualización y posterior acceso a almacenamientos clave-valor. Fuentes: [SWS_PER_00052], [SWS_PER_00356], [SWS_PER_00357], [SWS_PER_00567], [SWS_PER_00576], [SWS_PER_00577]

Escenarios de error

Los errores en el espacio de nombres se señalizan de manera estandarizada a través de la enumeración PerErrc ([SWS_PER_00311]) en combinación con PerErrorDomain ([SWS_PER_00352]) y MakeErrorCode ([SWS_PER_00351]). La clase declarada PerException presumiblemente sirve como tipo de excepción C++ para entornos en los que los errores no se tratan a través de ara::core::Result, sino mediante excepciones (interpretación).

Los escenarios de error centrales comprenden:

  • Errores de configuración y de direccionamiento: Si el InstanceSpecifier proporcionado no se corresponde con ninguna interfaz de puerto configurada en el modelo, la apertura con PerErrc::kStorageNotFound falla ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00311]). Los accesos a archivos que no existen generan PerErrc::kFileNotFound ([SWS_PER_00311]).
  • Conflictos de recursos: Si los almacenamientos están abiertos o se están ejecutando simultáneamente comandos administrativos, operaciones como OpenKeyValueStorage, OpenFileStorage, RecoverKeyValueStorage, RecoverAllFiles, ResetKeyValueStorage, ResetAllFiles, UpdatePersistency, CleanUpPersistency o ResetPersistency fallan con PerErrc::kResourceBusy ([SWS_PER_00052], [SWS_PER_00116], [SWS_PER_00333], [SWS_PER_00334], [SWS_PER_00335], [SWS_PER_00336], [SWS_PER_00357], [SWS_PER_00358], [SWS_PER_00567]).
  • Pérdida de integridad y recuperación: En caso de daños estructurales (PerErrc::kIntegrityCorrupted) o comprobaciones de redundancia fallidas (PerErrc::kValidationFailed), ara::per permite una recuperación de máximo esfuerzo a través de RecoverKeyValueStorage ([SWS_PER_00333]) o RecoverAllFiles ([SWS_PER_00335]). A través de RegisterRecoveryReportCallback ([SWS_PER_00433]), las aplicaciones relevantes para la seguridad pueden registrar de forma automatizada medidas correctoras a partir de RecoveryReportKind (p. ej., kKeyValueStorageRecovered, kFileRecovered) ([SWS_PER_00432]).
  • Límites de almacenamiento y errores físicos: Si se superan cuotas o capacidades físicas, se notifican PerErrc::kOutOfStorageSpace, PerErrc::kQuotaExceeded o PerErrc::kTooManyFiles ([SWS_PER_00311]). Los errores de hardware o del sistema de archivos resultan en PerErrc::kPhysicalStorageFailure ([SWS_PER_00311]).
  • Seguridad y modos de acceso: Si fallan verificaciones o cálculos criptográficos, el módulo devuelve PerErrc::kEncryptionFailed o PerErrc::kAuthenticationFailed ([SWS_PER_00311]). Los intentos de escritura en áreas de almacenamiento protegidas contra escritura se rechazan con PerErrc::kIllegalWriteAccess ([SWS_PER_00311]).

Esta guía se basa exclusivamente en la especificación de AUTOSAR Adaptive R25-11.

                          La función síncrona CheckForManifestUpdate de la cabecera ara/per/update.h comprueba en el espacio de nombres ara::per si existen actualizaciones de la Persistency Target Configuration [SWS_PER_00576]. La función no acepta parámetros y devuelve un ara::core::Result<bool>: true si la configuración se ha actualizado desde la última lectura, o false si ha permanecido inalterada [SWS_PER_00576].

                              usar
                              

                              La función sincrónica CleanUpPersistency de ara/per/update.h sirve para eliminar datos de respaldo (Backup Data) y otros datos no utilizados en todos los almacenamientos clave-valor y de archivos de una instancia [SWS_PER_00567]. No recibe parámetros y devuelve el resultado a través del tipo de retorno ara::core::Result<void> [SWS_PER_00567].
                              

                              Concurrencia y restricciones
                              

                              La función no es segura para subprocesos (not thread-safe) y requiere acceso exclusivo a todos los recursos de almacenamiento [SWS_PER_00567]. Si todavía está abierto un ara::per::SharedHandle de un almacenamiento clave-valor o de archivos, la llamada falla con kResourceBusy [SWS_PER_00567]. Del mismo modo, las operaciones en paralelo como UpdatePersistency, ResetPersistency, RecoverKeyValueStorage, ResetKeyValueStorage, RecoverAllFiles o ResetAllFiles conducen al código de error kResourceBusy [SWS_PER_00567].
                              

                              Mientras se ejecuta CleanUpPersistency, las llamadas concurrentes para abrir almacenamientos mediante OpenKeyValueStorage [SWS_PER_00052] o OpenFileStorage [SWS_PER_00116], así como las funciones de recuperación y restablecimiento [SWS_PER_00333], [SWS_PER_00334], [SWS_PER_00335], [SWS_PER_00336], también fallan con kResourceBusy.
                              

                              Manejo de errores

                                                  La función síncrona ara::per::OpenFileStorage abre un almacenamiento de archivos para datos persistentes y lo pone a disposición a través de un handle de acceso compartido [SWS_PER_00116]. Como parámetro espera una referencia a un ara::core::InstanceSpecifier, el cual indica la ruta shortName de un prototipo de puerto tipado mediante un PersistencyFileStorageInterface. El valor de retorno es un ara::core::Result<ara::core::SharedHandle<FileStorage>> [SWS_PER_00116].

                                                                                              usar
                                                                                              

                                                                                              La función síncrona ara::per::UpdatePersistency ([SWS_PER_00357], encabezado ara/per/update.h) actualiza todos los Key-Value Storages y File Storages de una aplicación tras la instalación de una nueva configuración de destino. Sirve para actualizar los datos persistentes de una Adaptive Application durante la fase de verificación [SWS_PER_00357]. La función no toma parámetros de entrada y devuelve un ara::core::Result<void> [SWS_PER_00357].
                                                                                              


                                                                                              Manejo de errores
                                                                                              

                                                                                              En caso de error, el Result devuelto contiene un código de error específico o un error específico del fabricante [SWS_PER_00357]. Al respecto, se distingue entre operaciones con y sin semántica de rollback:
                                                                                              

                                                                                                

                                                                                              • Semántica de rollback: En caso de kIntegrityCorrupted, kValidationFailed, kEncryptionFailed, kAuthenticationFailed, kTooManyFiles (superación de maxNumberOfFiles), kQuotaExceeded (superación de MaximumAllowedSize) así como kResourceBusy, se revierten los cambios realizados [SWS_PER_00357].
                                                                                                • 

                                                                                              • Sin semántica de rollback: En caso de errores de almacenamiento físico (kPhysicalStorageFailure) así como espacio de almacenamiento físico insuficiente (kOutOfStorageSpace), no se garantiza el rollback [SWS_PER_00357].
                                                                                                • 

                                                                                              


                                                                                              Concurrencia y restricciones
                                                                                              

                                                                                              La función está especificada como segura ante excepciones (exception safe), pero expresamente como no segura para subprocesos (not thread-safe) [SWS_PER_00357]. Una llamada falla con kResourceBusy en cuanto un SharedHandle de un Key-Value Storage o File Storage sigue en uso o se ejecutan en paralelo funciones de mantenimiento como CleanUpPersistency [SWS_PER_00567], ResetPersistency [SWS_PER_00358], RecoverKeyValueStorage [SWS_PER_00333], ResetKeyValueStorage [SWS_PER_00334], RecoverAllFiles [SWS_PER_00335] o ResetAllFiles [SWS_PER_00336] [SWS_PER_00357]. A la inversa, las llamadas simultáneas a OpenKeyValueStorage [SWS_PER_00052] y OpenFileStorage [SWS_PER_00116] desde otros hilos durante la actualización también fallan con kResourceBusy.
                                                                                              


                                                                                              Interacción
                                                                                              

                                                                                              Si UCM instaló una nueva configuración de destino durante el funcionamiento y esta se leyó de nuevo a través de ReloadPersistencyManifest [SWS_PER_00577], los almacenamientos cerrados se actualizan mediante UpdatePersistency. Si previamente se registraron callbacks a través de RegisterDataUpdateIndication [SWS_PER_00578] o RegisterApplicationDataUpdateCallback [SWS_PER_00356], su invocación se realiza de forma síncrona en el contexto de UpdatePersistency [SWS_PER_00578].
