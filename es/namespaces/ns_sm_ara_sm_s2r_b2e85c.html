Contexto

El namespace ara::sm::s2r proporciona interfaces y mecanismos para la funcionalidad Suspend-to-RAM (S2R) dentro del módulo State Management (SM) (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»). El objetivo del funcionamiento de Suspend-to-RAM es la optimización significativa de los tiempos de arranque y parada al situar la Machine en un estado que permite un reinicio rápido en lugar de realizar un Shutdown completo con el consiguiente arranque en frío (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»).

La función principal en el namespace la asume la clase S2RHub (AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub»). El hub coordina la comunicación con instancias distribuidas de S2RSatellite. Las aplicaciones cuyas unidades ejecutables están configuradas como suspendToRamAware integran dicha instancia de satélite para recibir notificaciones sobre los ciclos de Suspend y Resume pendientes (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality», [SWS_SM_00710]). Los procesos declarados como suspendToRamNotSupported deben haberse detenido mediante flujos de trabajo de State Management (p. ej., finalización de los grupos de funciones afectados) antes de que el sistema operativo pase al estado de suspensión (AUTOSAR_AP_SWS_StateManagement §7.5 «Interaction with Suspend-to-RAM Functionality»).

Para el control del S2RHub existen dos enfoques mutuamente excluyentes ([SWS_SM_00684]):

  • Enfoque StateMachine: el Controller integra la funcionalidad S2RHub internamente a través de objetos ActionListItem asignados. En este modo de funcionamiento, se prohíbe el acceso a la API C++ del hub a las aplicaciones de control externas para evitar condiciones de carrera e inconsistencias de estado (AUTOSAR_AP_SWS_StateManagement §7.7 «StateMachine approach», [SWS_SM_00684]).
  • API C++ directa: una aplicación de control externa (como SMControlApplication) utiliza directamente los métodos de clase del S2RHub (AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub»).

Diagrama de contexto: interacción entre el control, S2RHub, S2RSatellite y aplicaciones adaptativas. Fuentes: AUTOSAR_AP_SWS_StateManagement §7.5.1 «S2R Hub», [SWS_SM_00710].

Ciclo de vida

La creación y liberación de instancias en el namespace ara::sm::s2r está estrictamente vinculada a comprobaciones de autorización (Identity and Access Management, IAM) y asignaciones configuradas:

  • Instanciación del hub: con el enfoque StateMachine, State Management crea una instancia de S2RHub tan pronto como finaliza un ActionListItem de los tipos EnterSuspendToRam, EnterSuspendToRamOS o LeaveSuspendToRam ([SWS_SM_00690]). Durante la ejecución del constructor ara::sm::s2r::S2RHub::S2RHub se comprueba si el contexto de proceso se corresponde con la asignación en SuspendToRamHubMapping.process ([SWS_SM_00706]). Solo los procesos autorizados mediante SuspendToRamHubMapping pueden activar procesos de suspensión mediante una instancia del hub identificada por SuspendToRamModuleInstantiation ([SWS_SM_00714]).
  • Creación de satélites: se instancia una instancia de satélite a través del método de fábrica ara::sm::s2r::S2RSatellite::Create ([SWS_SM_00716]).
  • Fase de registro: tras su creación, el satélite se registra en el hub mediante ara::sm::s2r::S2RSatellite::Offer ([SWS_SM_00710]). El hub valida el contexto de proceso frente a la configuración en SuspendToRamSatelliteMapping.process y rechaza los intentos de registro no autorizados ([SWS_SM_00715]). El satélite se considera registrado activamente a partir del registro correcto ([SWS_SM_00710]).
  • Cancelación de registro: el registro activo finaliza tan pronto como el satélite invoca ara::sm::s2r::S2RSatellite::StopOffer ([SWS_SM_00710], [SWS_SM_00713]).

Ruta de uso

El flujo de uso típico comprende la preparación del estado de reposo, el cambio al modo de suspensión, así como el despertar coordinado tras la reactivación de la Machine:

  1. Puesta a disposición: cada aplicación compatible con S2R inicializa su S2RSatellite y notifica al hub su disposición de recepción mediante Offer() ([SWS_SM_00710]).
  2. Solicitud de suspensión: para iniciar el estado de reposo se invoca ara::sm::s2r::S2RHub::RequestToEnterSuspendMode ([SWS_SM_00701]). En el enfoque StateMachine, esto tiene lugar a través del ActionListItem EnterSuspendToRam utilizando maxActionItemDuration como parámetro de tiempo de espera ([SWS_SM_00689]).
  3. Notificación a satélites: el hub se dirige a todos los satélites registrados activamente y desencadena su callback ara::sm::s2r::S2RSatellite::EnterSuspendMode ([SWS_SM_00701], [SWS_SM_00711]). RequestToEnterSuspendMode se bloquea hasta que todos los satélites a los que se ha dirigido hayan respondido, hayan cancelado su registro o se produzca un tiempo de espera de comunicación ([SWS_SM_00702]).
  4. Suspensión del sistema operativo: una vez preparados todos los satélites, se puede iniciar el comando de suspensión propiamente dicho del sistema operativo mediante EnterSuspendToRamOs ([SWS_SM_00692]).
  5. Solicitud de reactivación: tras la reactivación, el control invoca ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode ([SWS_SM_00703]). En el enfoque StateMachine, esto ocurre a través del ActionListItem LeaveSuspendToRam ([SWS_SM_00691]). De acuerdo con el constraint [SWS_SM_CONSTR_00035], LeaveSuspendToRam solo puede estar asignado a estados encargados de salir del modo de suspensión, pero no a los propios estados de reposo.
  6. Reactivación de satélites: el hub invoca ara::sm::s2r::S2RSatellite::LeaveSuspendMode en los satélites registrados ([SWS_SM_00703], [SWS_SM_00711]). La llamada retorna tan pronto como todos los satélites han respondido, se ha cancelado su registro o ha expirado el tiempo de espera ([SWS_SM_00707]).
  7. Cancelación de registro: si finaliza un proceso o satélite, la cancelación del registro en el hub se efectúa a través de StopOffer() ([SWS_SM_00710], [SWS_SM_00713]).

Diagrama de secuencia: secuencia de llamadas desde el registro, pasando por Suspend y Resume, hasta la cancelación del registro. Fuentes: [SWS_SM_00701], [SWS_SM_00702], [SWS_SM_00703], [SWS_SM_00707], [SWS_SM_00710], [SWS_SM_00711], [SWS_SM_00713].

Escenarios de error

En la interacción entre el hub y los satélites se especifican las siguientes condiciones de error y condiciones previas:

  • Infracción de IAM en la creación del hub: si el contexto de proceso de la entidad que invoca S2RHub::S2RHub no se corresponde con la configuración SuspendToRamHubMapping.process, se notifica la infracción InsufficientPermissionsViolation y se desencadena el evento de seguridad SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED ([SWS_SM_00706]).
  • Falta de autenticación en el satélite: si el conmutador de IAM «Force IAM switch» está activado, S2RSatellite::Create devuelve el código de error kAuthenticationRequired ([SWS_SM_00716]).
  • Rechazo de satélites no autorizados: si el contexto de proceso del satélite no coincide con SuspendToRamSatelliteMapping.process, el hub rechaza el registro ([SWS_SM_00715]).
  • Tiempo de espera de comunicación: si un satélite al que se ha dirigido no responde durante RequestToLeaveSuspendMode dentro del intervalo de tiempo especificado por timeout, el hub devuelve el código de error kCommunicationTimeout ([SWS_SM_00707]).
  • Rechazo por parte de los satélites: Si al salir del estado de reposo al menos una instancia de satélite responde negativamente con kRejected, el hub proporciona como resultado global kAtLeastOneHadIssuesToLeave ([SWS_SM_00707]). Solo se obtiene un resultado global positivo si todos los satélites confirman positivamente o se desregistran de forma regular mediante StopOffer ([SWS_SM_00707]).
  • Restricciones de configuración y de uso: La asignación de LeaveSuspendToRam a estados de suspensión de la StateMachine no está permitida ([SWS_SM_CONSTR_00035]). Asimismo, está prohibido el acceso simultáneo a la API de C++ de S2RHub cuando el enfoque de StateMachine está activo ([SWS_SM_00684]).

Esta guía se basa en la especificación AUTOSAR Adaptive R25-11. Todas las indicaciones se fundamentan en los requisitos SWS y las secciones de documentos referenciadas.

<li><strong>Solicitud de suspensión:</strong> para iniciar el estado de reposo se invoca <code>ara::sm::s2r::S2RHub::RequestToEnterSuspendMode</code> (<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>). En el enfoque StateMachine, esto tiene lugar a través del <code>ActionListItem</code> <code>EnterSuspendToRam</code> utilizando <code>maxActionItemDuration</code> como parámetro de tiempo de espera (<a class="spec-record-ref" data-req="SWS_SM_00689" href="../spec/record.html?id=SWS_SM_00689">[SWS_SM_00689]</a>).</li>
<li><strong>Notificación a satélites:</strong> el hub se dirige a todos los satélites registrados activamente y desencadena su callback <code>ara::sm::s2r::S2RSatellite::EnterSuspendMode</code> (<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>, <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>). <code>RequestToEnterSuspendMode</code> se bloquea hasta que todos los satélites a los que se ha dirigido hayan respondido, hayan cancelado su registro o se produzca un tiempo de espera de comunicación (<a class="spec-record-ref" data-req="SWS_SM_00702" href="../spec/record.html?id=SWS_SM_00702">[SWS_SM_00702]</a>).</li>
<li><strong>Suspensión del sistema operativo:</strong> una vez preparados todos los satélites, se puede iniciar el comando de suspensión propiamente dicho del sistema operativo mediante <code>EnterSuspendToRamOs</code> (<a class="spec-record-ref" data-req="SWS_SM_00692" href="../spec/record.html?id=SWS_SM_00692">[SWS_SM_00692]</a>).</li>
<li><strong>Solicitud de reactivación:</strong> tras la reactivación, el control invoca <code>ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode</code> (<a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a>). En el enfoque StateMachine, esto ocurre a través del <code>ActionListItem</code> <code>LeaveSuspendToRam</code> (<a class="spec-record-ref" data-req="SWS_SM_00691" href="../spec/record.html?id=SWS_SM_00691">[SWS_SM_00691]</a>). De acuerdo con el constraint <a class="spec-record-ref" data-req="SWS_SM_CONSTR_00035" href="../spec/record.html?id=SWS_SM_CONSTR_00035">[SWS_SM_CONSTR_00035]</a>, <code>LeaveSuspendToRam</code> solo puede estar asignado a estados encargados de salir del modo de suspensión, pero no a los propios estados de reposo.</li>
<li><strong>Reactivación de satélites:</strong> el hub invoca <code>ara::sm::s2r::S2RSatellite::LeaveSuspendMode</code> en los satélites registrados (<a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a>, <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>). La llamada retorna tan pronto como todos los satélites han respondido, se ha cancelado su registro o ha expirado el tiempo de espera (<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>Cancelación de registro:</strong> si finaliza un proceso o satélite, la cancelación del registro en el hub se efectúa a través de <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>, <a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>).</li>
</ol>

<h4>Escenarios de error</h4>
<p>En la interacción entre el hub y los satélites se especifican las siguientes condiciones de error y condiciones previas:</p>
<ul>
<li><strong>Infracción de IAM en la creación del hub:</strong> si el contexto de proceso de la entidad que invoca <code>S2RHub::S2RHub</code> no se corresponde con la configuración <code>SuspendToRamHubMapping.process</code>, se notifica la infracción <code>InsufficientPermissionsViolation</code> y se desencadena el evento de seguridad <code>SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED</code> (<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>).</li>
<li><strong>Falta de autenticación en el satélite:</strong> si el conmutador de IAM «Force IAM switch» está activado, <code>S2RSatellite::Create</code> devuelve el código de error <code>kAuthenticationRequired</code> (<a class="spec-record-ref" data-req="SWS_SM_00716" href="../spec/record.html?id=SWS_SM_00716">[SWS_SM_00716]</a>).</li>
<li><strong>Rechazo de satélites no autorizados:</strong> si el contexto de proceso del satélite no coincide con <code>SuspendToRamSatelliteMapping.process</code>, el hub rechaza el registro (<a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>).</li>
<li><strong>Tiempo de espera de comunicación:</strong> si un satélite al que se ha dirigido no responde durante <code>RequestToLeaveSuspendMode</code> dentro del intervalo de tiempo especificado por <code>timeout</code>, el hub devuelve el código de error <code>kCommunicationTimeout</code> (<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>Rechazo por parte de los satélites:</strong> Si al salir del estado de reposo al menos una instancia de satélite responde negativamente con <code>kRejected</code>, el hub proporciona como resultado global <code>kAtLeastOneHadIssuesToLeave</code> (<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>). Solo se obtiene un resultado global positivo si todos los satélites confirman positivamente o se desregistran de forma regular mediante <code>StopOffer</code> (<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>Restricciones de configuración y de uso:</strong> La asignación de <code>LeaveSuspendToRam</code> a estados de suspensión de la StateMachine no está permitida (<a class="spec-record-ref" data-req="SWS_SM_CONSTR_00035" href="../spec/record.html?id=SWS_SM_CONSTR_00035">[SWS_SM_CONSTR_00035]</a>). Asimismo, está prohibido el acceso simultáneo a la API de C++ de <code>S2RHub</code> cuando el enfoque de StateMachine está activo (<a class="spec-record-ref" data-req="SWS_SM_00684" href="../spec/record.html?id=SWS_SM_00684">[SWS_SM_00684]</a>).</li>
</ul>
