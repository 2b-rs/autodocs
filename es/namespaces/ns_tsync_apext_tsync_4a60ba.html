Proporciona interfaces y contenedores para el Freshness Value Management a fin de proteger la sincronización temporal.

El espacio de nombres apext::tsync proporciona interfaces y contenedores de datos para el Freshness Value Management de la sincronización temporal en Adaptive. A través de la interfaz FVM se encapsulan valores de actualidad en instancias de FVContainer para proteger los mensajes temporales contra ataques de repetición. Si durante la inicialización se produce un error no recuperable o un valor no está disponible temporalmente, esto se representa mediante los códigos de error de la TsyncFvmErrorDomain [SWS_TS_14202]. La instanciación de objetos de error estandarizados se lleva a cabo, a este respecto, de forma segura frente a excepciones y segura para subprocesos mediante MakeErrorCode [SWS_TS_14213].

Contexto

El espacio de nombres apext::tsync representa una extensión específica de la plataforma de la sincronización temporal de AUTOSAR Adaptive (ara::tsync). Su tarea principal es el Freshness Value Management (FVM), que proporciona mecanismos para garantizar la actualidad de las informaciones temporales a fin de evitar ataques de repetición y estados obsoletos en redes con sincronización temporal. Entre sus componentes principales se encuentran la interfaz FVM, el contenedor de datos FVContainer, el dominio de errores TsyncFvmErrorDomain y la clase de excepción TsyncFvmException.

La clase FVContainer encapsula un valor de actualidad gestionando su longitud en bits, así como el propio valor en forma de un vector de bytes. La interfaz FVM actúa como puente funcional para ara::tsync. Es probable que FVM funcione como una interfaz de abstracción a través de la cual las instancias de sincronización temporal de ara::tsync obtienen o verifican valores de frescura actuales. Pregunta Q-f92f53d92ec347e5 (abierta) El dominio de errores TsyncFvmErrorDomain y las funciones auxiliares asociadas garantizan la notificación de errores estandarizada [SWS_TS_14212].

Diagrama de contexto: componentes del espacio de nombres apext::tsync y su interacción con ara::tsync. Fuentes: [SWS_TS_14202], [SWS_TS_14212].

Ciclo de vida

El ciclo de vida de los componentes en el espacio de nombres apext::tsync se divide en fases de inicialización, funcionamiento y finalización. Para la fase de inicialización, la enumeración TsyncFvmErrc define el valor de error kFVInitializeFailed (= 2), que está especificado como error no recuperable (unrecoverable error) e indica que el Freshness Value Manager no se pudo utilizar [SWS_TS_14202]. El error kFVInitializeFailed sugiere presumiblemente que, antes de recuperar Freshness Values, se debe completar una fase de inicialización del FVM cuyo fallo impide cualquier uso posterior. Pregunta Q-d9c097d736bae053 (abierta)

Durante el funcionamiento normal, las instancias de FVContainer tienen una vida útil temporal: se instancian según las necesidades, se completan con el vector y la longitud en bits y se transfieren a las instancias de protocolo sincronizadoras. Por el contrario, el objeto de dominio de errores TsyncFvmErrorDomain posee una vida útil estática durante todo el periodo del proceso. La función GetTsyncFvmErrorDomain() devuelve una referencia al objeto de instancia global [SWS_TS_14212]. Tanto GetTsyncFvmErrorDomain() como la función de fábrica MakeErrorCode() están declaradas como constexpr y noexcept, y especificadas como seguras frente a excepciones y seguras para subprocesos [SWS_TS_14212], [SWS_TS_14213]. Esto permite una generación y consulta de errores concurrente sin bloqueos de sincronización.

Ruta de uso

La ruta de uso típica en la interacción con la sincronización temporal abarca la provisión y la evaluación de valores de actualidad:

  1. Un componente de ara::tsync solicita un valor de frescura actual a través de la interfaz FVM para proteger un mensaje temporal.
  2. Si la determinación del valor es correcta, FVM genera o completa una instancia de FVContainer con la longitud en bits y el vector de bytes del valor, y la devuelve al emisor de la llamada.
  3. Si el valor de frescura no se puede proporcionar temporalmente en tiempo de ejecución, FVM notifica el error recuperable kFVNotAvailable [SWS_TS_14202]. Para ello, a través de MakeErrorCode() se genera un objeto ara::core::ErrorCode adecuado con datos adicionales específicos del fabricante [SWS_TS_14213].
  4. El componente que realiza la llamada evalúa el resultado y decide si efectuar reintentos o aplicar medidas sustitutivas.

Diagrama de secuencia: consulta de un valor de actualidad y tratamiento de posibles estados de error. Fuentes: [SWS_TS_14202], [SWS_TS_14213].

Escenarios de error

El tratamiento de errores en apext::tsync se basa en la arquitectura de ara::core::ErrorDomain y ara::core::ErrorCode. Los códigos de error de la TsyncFvmErrorDomain se enumeran en la enumeración TsyncFvmErrc, cuyo tipo base es ara::core::ErrorDomain::CodeType [SWS_TS_14202]:

  • kFVNotAvailable (= 1): error recuperable (recoverable error) que señaliza que el Freshness Value no está disponible actualmente [SWS_TS_14202]. Los emisores de las llamadas pueden volver a realizar la solicitud u omitir el ciclo de procesamiento actual.
  • kFVInitializeFailed (= 2): error no recuperable (unrecoverable error) que indica que el Freshness Value Manager no se pudo inicializar o utilizar [SWS_TS_14202]. Esto conlleva la interrupción de los servicios de sincronización temporal dependientes.

La generación de objetos de error concretos se realiza mediante la función auxiliar MakeErrorCode(TsyncFvmErrc code, ara::core::ErrorDomain::SupportDataType data), que recibe el enumerador y datos adicionales específicos del fabricante [SWS_TS_14213]. Las declaraciones se encuentran en la cabecera apext/tsync/fvm_error_domain.h, mientras que las declaraciones anticipadas pueden obtenerse a través de apext/tsync/tsync_fwd.h [SWS_TS_14202]. Para rutas de error basadas en excepciones, el espacio de nombres proporciona la clase TsyncFvmException. Es previsible que TsyncFvmException se lance cuando los errores de la TsyncFvmErrorDomain se notifican en contextos de excepción en lugar de a través de ara::core::ErrorCode. Uso y semántica de errores

La enumeración TsyncFvmErrc define según [SWS_TS_14202] los códigos de error específicos para el dominio de error apext::tsync::TsyncFvmErrorDomain. Dentro del dominio, la enumeración también se proporciona a través del alias de tipo apext::tsync::TsyncFvmErrorDomain::Errc [SWS_TS_14206]. La enumeración distingue entre dos estados de error centrales del Freshness Value Manager (FVM):

  • kFVNotAvailable (= 1): Indica un error recuperable (Recoverable Error) cuando un valor de frescura requerido no está disponible [SWS_TS_14202]. Este código de error se produce en particular al consultar valores de frescura de transmisión mediante apext::tsync::FVM::GetTxFreshness [SWS_TS_14199].
  • kFVInitializeFailed (= 2): Indica un error no recuperable (Unrecoverable Error) cuando el Freshness Value Manager no está operativo y falla [SWS_TS_14202]. Es señalizado por apext::tsync::FVM::Initialize en caso de fallo en la inicialización [SWS_TS_14200].

Interacción y tratamiento de errores

Para el tratamiento de errores, se transfiere un enumerador junto con datos adicionales específicos del fabricante a un objeto ara::core::ErrorCode mediante la función auxiliar apext::tsync::MakeErrorCode [SWS_TS_14213]. Las funciones del FVM como Initialize [SWS_TS_14200], GetTxFreshness [SWS_TS_14199] y GetRxFreshness [SWS_TS_14198] encapsulan el resultado o los estados de error en ara::core::Result. Los componentes de aplicación y TimeSync evalúan el objeto Result para diferenciar entre fallos recuperables de valores de frescura individuales y errores graves de inicialización del FVM.
