Kontext

Der Namespace apext::tsync stellt plattformspezifische Erweiterungen (Platform Extensions) des AUTOSAR-Adaptive-Moduls tsync für das Freshness Value Management (FVM) bereit. In verteilten automobilen Steuergerätearchitekturen schützt das Freshness Value Management zeitkritische sowie sicherheitsrelevante Synchronisationsnachrichten vor Replay- und Verzögerungsangriffen, indem dynamische Frischewerte erzeugt, verwaltet und verifiziert werden.

Die Hauptaufgabe des Namespace liegt in der Bereitstellung der zentralen Schnittstelle FVM für das Modul ara::tsync sowie der zugehörigen Datenstrukturen. Frischewerte werden dabei durch die Container-Klasse FVContainer gekapselt, welche sowohl die Bitlänge des Werts als auch die eigentlichen Nutzdaten in Form eines Vektors aufnimmt. Zur standardisierten Fehlerbehandlung definiert der Namespace eine eigenständige Fehlerdomäne TsyncFvmErrorDomain mit zugehörigem Fehler-Enumerator TsyncFvmErrc [SWS_TS_14202], die Fehler-Fabrikfunktion MakeErrorCode [SWS_TS_14213] sowie die Exception-Klasse TsyncFvmException.

Kontextdiagramm: Zusammenspiel zwischen ara::tsync, der FVM-Schnittstelle, dem FVContainer und der Fehlerdomäne. Quellen: [SWS_TS_14202], [SWS_TS_14212], [SWS_TS_14213].

Lebenszyklus

Die Komponenten im Namespace apext::tsync unterliegen klar abgegrenzten Lebenszyklus- und Nebenläufigkeitsbedingungen:

  • Fehlerdomäne: Die Klasse TsyncFvmErrorDomain fungiert als globale, prozessweite Fehlerdomäne. Über die Funktion GetTsyncFvmErrorDomain() kann jederzeit eine Referenz auf das globale Instanzobjekt abgerufen werden. Die Funktion ist als constexpr, threadsicher und ausnahmesicher spezifiziert [SWS_TS_14212], womit die Fehlerdomäne über die gesamte Laufzeit der Anwendung hinweg verfügbar bleibt.
  • Manager-Instanz: Für den Freshness Value Manager ist eine Initialisierungsphase vorgesehen. Interpretation: Die Initialisierung des Freshness Value Managers dürfte eine distinkte Anlaufphase darstellen, deren Scheitern die Nutzbarkeit des Managers dauerhaft verhindert. Dies wird durch den Fehlercode TsyncFvmErrc::kFVInitializeFailed untermauert, der explizit als unkorrigierbarer Fehler („Unrecoverable Error“) definiert ist, nach welchem der FVM nicht mehr verwendet werden kann [SWS_TS_14202].
  • Datencontainer: Instanzen von FVContainer besitzen einen aufrufspezifischen Lebenszyklus. Sie werden zur Aufnahme von Frischewerten erzeugt, während der Prüfung oder Nachrichtenerstellung übergeben und können nach Abschluss des Vorgangs wieder zerstört werden.

Nutzungspfad

Ein typischer Nutzungspfad zur Absicherung von Synchronisationsnachrichten gliedert sich in folgende Interaktionsschritte:

  1. Anforderung: Interpretation: Die Schnittstelle FVM dürfte von Komponenten innerhalb von ara::tsync zur Anforderung und Prüfung von Frischewerten aufgerufen werden. Das übergeordnete Zeit-Modul bindet die Schnittstelle FVM ein, um für ausgehende oder eingehende Nachrichten Frischewerte bereitzustellen.
  2. Datenübergabe: Der Freshness Value Manager befüllt bei erfolgreicher Ermittlung eine Instanz von FVContainer mit der Bitlänge und dem Bytevektor des Frischewerts und übergibt diese an die aufrufende Zeit-Synchronisation.
  3. Fehlersignalisierung: Steht zur Laufzeit kein gültiger Wert zur Verfügung, erzeugt das Subsystem über MakeErrorCode [SWS_TS_14213] einen standardisierten Fehlercode vom Typ ara::core::ErrorCode unter Nutzung von TsyncFvmErrc::kFVNotAvailable [SWS_TS_14202].
  4. Fehlerbewertung: Der Aufrufer wertet das Ergebnis aus. Interpretation: Aufrufer dürften bei kFVNotAvailable einen erneuten Leseversuch unternehmen können, da es sich um einen behebbaren Fehlerzustand handelt.

Fehlerszenarien

Die Fehlerbehandlung in apext::tsync folgt dem AUTOSAR-Adaptive-Standardmuster über ara::core::ErrorCode:

  • TsyncFvmErrc::kFVNotAvailable (Wert 1): Kennzeichnet einen behebbaren Fehler („Recoverable Error“). Dieser Zustand signalisiert, dass der benötigte Frischewert temporär nicht abrufbar ist [SWS_TS_14202]. Die aufrufende Logik kann dies behandeln, indem der Abruf zu einem späteren Zeitpunkt wiederholt wird.
  • TsyncFvmErrc::kFVInitializeFailed (Wert 2): Kennzeichnet einen unkorrigierbaren Fehler („Unrecoverable Error“). Dieser Code zeigt an, dass die Initialisierung des Freshness Value Managers fehlgeschlagen ist und das Modul nicht einsatzfähig ist [SWS_TS_14202].

Die Konstruktion von Fehlercodes erfolgt über MakeErrorCode(TsyncFvmErrc, ara::core::ErrorDomain::SupportDataType) [SWS_TS_14213], welche herstellerspezifische Diagnosedaten einbindet und garantiert threadsicher sowie ausnahmesicher ausgeführt wird. Für Softwarepfade, die mit C++-Ausnahmen arbeiten, steht die abgeleitete Ausnahmeklasse TsyncFvmException bereit.

<h4>Lebenszyklus</h4>
<p>Die Komponenten im Namespace <code>apext::tsync</code> unterliegen klar abgegrenzten Lebenszyklus- und Nebenläufigkeitsbedingungen:</p>
<ul>
<li><strong>Fehlerdomäne:</strong> Die Klasse <code>TsyncFvmErrorDomain</code> fungiert als globale, prozessweite Fehlerdomäne. Über die Funktion <code>GetTsyncFvmErrorDomain()</code> kann jederzeit eine Referenz auf das globale Instanzobjekt abgerufen werden. Die Funktion ist als <code>constexpr</code>, threadsicher und ausnahmesicher spezifiziert <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>, womit die Fehlerdomäne über die gesamte Laufzeit der Anwendung hinweg verfügbar bleibt.</li>
<li><strong>Manager-Instanz:</strong> Für den Freshness Value Manager ist eine Initialisierungsphase vorgesehen. Interpretation: Die Initialisierung des Freshness Value Managers dürfte eine distinkte Anlaufphase darstellen, deren Scheitern die Nutzbarkeit des Managers dauerhaft verhindert. Dies wird durch den Fehlercode <code>TsyncFvmErrc::kFVInitializeFailed</code> untermauert, der explizit als unkorrigierbarer Fehler („Unrecoverable Error“) definiert ist, nach welchem der FVM nicht mehr verwendet werden kann <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>.</li>
<li><strong>Datencontainer:</strong> Instanzen von <code>FVContainer</code> besitzen einen aufrufspezifischen Lebenszyklus. Sie werden zur Aufnahme von Frischewerten erzeugt, während der Prüfung oder Nachrichtenerstellung übergeben und können nach Abschluss des Vorgangs wieder zerstört werden.</li>
</ul>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad zur Absicherung von Synchronisationsnachrichten gliedert sich in folgende Interaktionsschritte:</p>
<ol>
<li><strong>Anforderung:</strong> Interpretation: Die Schnittstelle <code>FVM</code> dürfte von Komponenten innerhalb von <code>ara::tsync</code> zur Anforderung und Prüfung von Frischewerten aufgerufen werden. Das übergeordnete Zeit-Modul bindet die Schnittstelle <code>FVM</code> ein, um für ausgehende oder eingehende Nachrichten Frischewerte bereitzustellen.</li>
<li><strong>Datenübergabe:</strong> Der Freshness Value Manager befüllt bei erfolgreicher Ermittlung eine Instanz von <code>FVContainer</code> mit der Bitlänge und dem Bytevektor des Frischewerts und übergibt diese an die aufrufende Zeit-Synchronisation.</li>
<li><strong>Fehlersignalisierung:</strong> Steht zur Laufzeit kein gültiger Wert zur Verfügung, erzeugt das Subsystem über <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a> einen standardisierten Fehlercode vom Typ <code>ara::core::ErrorCode</code> unter Nutzung von <code>TsyncFvmErrc::kFVNotAvailable</code> <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>.</li>
<li><strong>Fehlerbewertung:</strong> Der Aufrufer wertet das Ergebnis aus. Interpretation: Aufrufer dürften bei <code>kFVNotAvailable</code> einen erneuten Leseversuch unternehmen können, da es sich um einen behebbaren Fehlerzustand handelt.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Die Fehlerbehandlung in <code>apext::tsync</code> folgt dem AUTOSAR-Adaptive-Standardmuster über <code>ara::core::ErrorCode</code>:</p>
<ul>
<li><strong><code>TsyncFvmErrc::kFVNotAvailable</code> (Wert 1):</strong> Kennzeichnet einen behebbaren Fehler („Recoverable Error“). Dieser Zustand signalisiert, dass der benötigte Frischewert temporär nicht abrufbar ist <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Die aufrufende Logik kann dies behandeln, indem der Abruf zu einem späteren Zeitpunkt wiederholt wird.</li>
<li><strong><code>TsyncFvmErrc::kFVInitializeFailed</code> (Wert 2):</strong> Kennzeichnet einen unkorrigierbaren Fehler („Unrecoverable Error“). Dieser Code zeigt an, dass die Initialisierung des Freshness Value Managers fehlgeschlagen ist und das Modul nicht einsatzfähig ist <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>.</li>
</ul>

Für Softwarepfade, die mit C++-Ausnahmen arbeiten, steht die abgeleitete Ausnahmeklasse <code>TsyncFvmException</code> bereit.</p>
