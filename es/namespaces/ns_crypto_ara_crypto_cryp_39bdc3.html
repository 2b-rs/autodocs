Contexto

El namespace ara::crypto::cryp constituye el núcleo funcional del subsistema criptográfico en AUTOSAR Adaptive Platform. Su responsabilidad primordial radica en la provisión de interfaces estandarizadas para operaciones criptográficas, la encapsulación de estados algorítmicos y la conexión con estructuras subyacentes de claves y almacenamiento. La arquitectura del namespace se estructura en tres pilares funcionales: infraestructura de proveedores, contextos criptográficos y objetos criptográficos.

La infraestructura de proveedores se define mediante la interfaz CryptoProvider. Esta actúa como punto de entrada central para implementaciones concretas de primitivas criptográficas y administra al mismo tiempo el acceso al almacenamiento de claves.

El segundo pilar abarca los contextos criptográficos, los cuales se fundamentan en la interfaz base común CryptoContext o implementan el paradigma de un contexto de ejecución mutable:

  • Primitivas simétricas: interfaces como SymmetricCipherCtx para cifrado y descifrado simétrico, AuthCipherCtx para cifrado autenticado (AEAD), MessageAuthnCodeCtx para códigos de autenticación de mensajes, así como SymmetricKeyWrapperCtx para el empaquetado de claves simétricas.
  • Primitivas asimétricas: pares de interfaces para operaciones de cifrado (EncryptorPublicCtx, DecryptorPrivateCtx), generación y verificación de firmas (SignerPrivateCtx, VerifierPublicCtx), acuerdos de claves (KeyAgreementPrivateCtx), así como mecanismos de encapsulamiento asimétrico (KeyEncapsulatorPublicCtx, KeyDecapsulatorPrivateCtx).
  • Servicios auxiliares y de transformación: interfaces de contexto para funciones hash criptográficas (HashFunctionCtx), generadores de números pseudoaleatorios (RandomGeneratorCtx), procedimientos de derivación de claves (KeyDerivationFunctionCtx), así como la importación protegida de material sensible de claves (ProtectedKeyImportCtx).

El tercer pilar lo forman los objetos criptográficos (CryptoObject), que abstraen datos de claves y certificados. Entre ellos se incluyen SymmetricKey para procedimientos simétricos, así como PublicKey y PrivateKey para algoritmos asimétricos. La administración de estos objetos de clave se realiza a través de estructuras de almacenamiento como KeySlot y WriteableKeySlot dentro del proveedor.

Diagrama de contexto: interacción entre aplicación, CryptoProvider, contextos y objetos de clave. Fuentes: no se especifican referencias en el payload.

Ciclo de vida

El ciclo de vida dentro de ara::crypto::cryp viene determinado por la interacción de instancias de almacenamiento y de proveedores de larga duración con contextos operativos efímeros.

Los contextos criptográficos se instanciarían principalmente a través del CryptoProvider como fábrica central, ya que este proporciona la implementación concreta de primitivas criptográficas conforme al resumen de la especificación. Un CryptoContext está diseñado como una interfaz mutable. Tras su creación, un contexto se halla inicialmente en un estado inicial no configurado. Antes del procesamiento efectivo, deben asignarse parámetros específicos de la aplicación.

Interpretación: para preparar operaciones criptográficas, presumiblemente los contextos con estado (CryptoContext) deben vincularse a objetos de clave adecuados (CryptoObject tales como SymmetricKey o PrivateKey) para poder autorizar y ejecutar transformaciones. Tras finalizar el procesamiento de datos (p. ej., tras la lectura final de un resultado de firma o cifrado), un contexto puede liberarse o bien reutilizarse para una nueva ronda de cálculo mediante su restablecimiento.

Los propios objetos de clave están sujetos al ciclo de vida de las ubicaciones de almacenamiento: KeySlot proporciona posiciones de memoria de solo lectura, mientras que WriteableKeySlot posibilita la escritura y actualización persistente de claves, por ejemplo en interacción con ProtectedKeyImportCtx. Al descartar claves y contextos, los búferes sensibles subyacentes deben depurarse de forma segura.

Ruta de uso

Una ruta de flujo típica dentro de ara::crypto::cryp consiste en la generación de una firma digital para datos útiles empleando una clave privada asimétrica:

  1. Obtención de clave: la aplicación contacta con el CryptoProvider y accede al objeto PrivateKey depositado a través de un KeySlot asignado.
  2. Provisión de contexto: la aplicación solicita al CryptoProvider una instancia de SignerPrivateCtx configurada para el algoritmo de firma deseado.
  3. Inicialización: la clave privada se vincula al SignerPrivateCtx para pasar el contexto al estado listo para el cálculo.
  4. Procesamiento de datos: los datos que se van a firmar se transmiten al contexto de firma.
  5. Obtención del resultado: el contexto concluye el cálculo, entrega la firma generada a la aplicación y, a continuación, se restablece o se libera.

Diagrama de secuencia: orden de llamadas para la inicialización y generación de una firma. Fuentes: no se especifican referencias en el payload.
