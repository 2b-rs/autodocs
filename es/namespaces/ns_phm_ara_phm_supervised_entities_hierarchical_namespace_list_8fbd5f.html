Define enumeraciones de puntos de control con seguridad de tipos para la supervisión funcional a través de Platform Health Management.

Este espacio de nombres proporciona en Platform Health Management enumeraciones fuertemente tipadas para puntos de control de entidades supervisadas [SWS_PHM_00424]. Cada entidad supervisada recibe su propia enumeración delimitada con el tipo subyacente std::uint32_t, cuyos enumeradores declarados se notifican como puntos de control a la interfaz ara::phm::PhmSupervisedEntityInterface [SWS_PHM_00424], [SWS_PHM_00425]. Mediante la provisión estática en el espacio de nombres con seguridad de tipos se evita de manera fiable en tiempo de compilación la confusión de puntos de control entre diferentes entidades.

Contexto

El espacio de nombres de C++ namespace ara::phm::supervised_entities::{ <hierarchical-namespace-list-lower-skeleton>} sirve dentro de Platform Health Management (PHM) de la AUTOSAR Adaptive Platform como área dedicada para puntos de control (checkpoints) con seguridad de tipos de unidades funcionales supervisadas (Supervised Entities). Conforme a [SWS_PHM_00424], este espacio de nombres contiene enumeraciones delimitadas con el formato enum class {<phmssi-sn>} : std::uint32_t, las cuales definen los puntos de control discretos para la interfaz ara::phm::PhmSupervisedEntityInterface. Para cada elemento configurado de la lista de puntos de control existe una declaración de enumerador de C++ unívoca [SWS_PHM_00425]. La interacción une tres componentes funcionales clave: el software de aplicación supervisado (Supervised Entity), los puntos de control tipados modelados mediante el espacio de nombres y la interfaz de plataforma ara::phm::PhmSupervisedEntityInterface, a través de la cual se transmiten los eventos de supervisión al servicio de PHM.

Diagrama de contexto: interacción entre el software de aplicación supervisado, la enumeración tipada de puntos de control y la interfaz de plataforma. Fuentes: [SWS_PHM_00424], [SWS_PHM_00425]

Ciclo de vida

Los tipos y constantes dentro del espacio de nombres poseen carácter estático en tiempo de compilación. No están sujetos a ningún ciclo de vida dinámico en tiempo de ejecución por asignación o liberación en el montículo, sino que se proporcionan como enumeraciones delimitadas tipadas de C++11 con el tipo subyacente std::uint32_t [SWS_PHM_00424]. Interpretación: las definiciones se generan habitualmente de forma automatizada a partir de la descripción del servicio AUTOSAR durante el proceso de compilación, ya que las rutas y los identificadores dependen de los parámetros del modelo de la interfaz. Para la inclusión, el estándar proporciona por cada unidad supervisada un archivo de cabecera propio en #include "ara/phm/supervised_entities/{ <si-namespace-derived-directory-path-lower>}/{<phmssi-sn>}.h", mientras que las declaraciones de tipos generales se pueden declarar por adelantado a través de la cabecera de reenvío #include "ara/phm/phm_fwd.h" [SWS_PHM_00424]. Por consiguiente, las constantes de enumerador permanecen disponibles de forma inalterable para la aplicación a lo largo de toda la vida útil del proceso [SWS_PHM_00425].

Ruta de uso

La vía de uso típica para componentes de software que actúan como Supervised Entity se divide en tres pasos sucesivos:

  • Inclusión de encabezados: la aplicación incluye el encabezado generado de la entidad supervisada mediante la ruta de archivo ara/phm/supervised_entities/{ <si-namespace-derived-directory-path-lower>}/{<phmssi-sn>}.h o el reenvío central ara/phm/phm_fwd.h [SWS_PHM_00424].
  • Inicialización de la interfaz: la aplicación instancia o vincula la interfaz ara::phm::PhmSupervisedEntityInterface para la cual se declararon los checkpoints de la enumeración [SWS_PHM_00424].
  • Señalización de checkpoints: al pasar por puntos de control relevantes en el algoritmo, la aplicación selecciona el enumerador correspondiente {<symbol-phm-checkpoint>} del namespace [SWS_PHM_00425] y lo notifica a la instancia de ara::phm::PhmSupervisedEntityInterface [SWS_PHM_00424].

Mediante la vinculación al tipo base std::uint32_t [SWS_PHM_00424] y la asignación explícita de valor de cada punto de control [SWS_PHM_00425], se garantiza en tiempo de ejecución una identificación con seguridad de tipos y libre de confusiones de los pasos de programa correspondientes.

Escenarios de error

Los usos erróneos de este espacio de nombres resultan principalmente de configuraciones incorrectas relativas al modelo y a los tipos. Dado que se trata de un enum class [SWS_PHM_00424], el sistema de tipos de C++ impide conversiones de tipo implícitas; el uso de tipos de datos incorrectos o de enumeradores de Supervised Entities ajenas se intercepta así ya en tiempo de compilación. Pueden producirse errores en tiempo de ejecución si la configuración en la descripción del modelo no coincide exactamente con la lista de enumeradores: según [SWS_PHM_00425], debe declararse un enumerador correspondiente para cada checkpoint. Interpretación: si una aplicación transmitiera a ara::phm::PhmSupervisedEntityInterface un valor de std::uint32_t no configurado en el modelo debido a una conversión de tipo no permitida o a archivos de encabezado obsoletos, es probable que el servicio PHM no pueda asignar dicho checkpoint y lo considere una infracción de supervisión.
