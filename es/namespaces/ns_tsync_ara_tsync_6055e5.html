Contexto

El espacio de nombres de C++ ara::tsync representa la interfaz funcional del módulo Time Synchronization (tsync) en AUTOSAR Adaptive Platform. Permite a las aplicaciones el acceso homogéneo a bases de tiempo sincronizadas, así como la monitorización de los estados de sincronización y la calidad temporal. La arquitectura distingue principalmente entre consumidores y proveedores de información horaria:

  • SynchronizedTimeBaseConsumer sirve a las aplicaciones como punto de acceso a una base de tiempo configurada y referenciada mediante un InstanceSpecifier para recuperar marcas de tiempo o seguir cambios de estado.
  • SynchronizedTimeBaseProvider permite a las aplicaciones o componentes de plataforma actuar como fuente horaria y proporcionar una base de tiempo.
  • TimeBase funciona como un constructo de pseudorreloj para la tipificación conforme al estándar en el marco de std::chrono. Sobre esta base, el alias de tipo Timestamp ([SWS_TS_01251]) define instantes estandarizados como std::chrono::time_point<TimeBase, std::chrono::nanoseconds>.
  • SynchronizedTimeBaseStatus captura instantáneas del estado del sistema de una base de tiempo, incluida la información de comunicación y de saltos.
  • Las estructuras de datos de medición y validación (entre ellas TimeMasterMeasurementType, TimeSlaveMeasurementType, PdelayInitiatorMeasurementType, PdelayResponderMeasurementType y TimePrecisionMeasurement), así como las interfaces de retrollamada ConsumerTimeBaseValidationNotification y ProviderTimeBaseValidationNotification, admiten la verificación y evaluación de precisión de la distribución horaria.

Ciclo de vida y estados de sincronización

Las bases de tiempo pasan durante el funcionamiento en tiempo de ejecución por estados de sincronización discretos, representados mediante el enum SynchronizationStatus ([SWS_TS_01050]). Tras el arranque, una base de tiempo se encuentra inicialmente en el estado kNotSynchronizedUntilStartup (=0). Tan pronto como los mensajes de sincronización se procesan correctamente, la base de tiempo pasa al estado kSynchronized (=2) en caso de acoplamiento directo con el Time Master, o a kSynchToGateway (=3) si la sincronización se realiza indirectamente a través de una pasarela. Si no se produce la sincronización dentro de una ventana temporal definida, se adopta el estado kTimeOut (=1).

Paralelamente al estado de comunicación, el enum LeapJump ([SWS_TS_01051]) señala correcciones bruscas de la base de tiempo: kTimeLeapNone (=0) indica la evolución normal sin superación del valor umbral, mientras que kTimeLeapFuture (=1) identifica un salto hacia adelante y kTimeLeapPast (=2) un salto hacia atrás más allá del valor umbral configurado.

Diagrama de estados: estados de sincronización de una base de tiempo según SynchronizationStatus. Fuentes: [SWS_TS_01050]

Ruta de uso

Un flujo de uso típico del lado del consumidor se divide en instanciación, registro de funciones de retrollamada asíncronas y consulta cíclica o controlada por eventos de información horaria:

  1. Vincular el acceso: Una aplicación consumidora instancia un objeto del tipo SynchronizedTimeBaseConsumer especificando el InstanceSpecifier adecuado.
  2. Registrar notificaciones: Para recibir información sobre los cambios de estado, la aplicación pasa funciones de retrollamada al consumidor. Las firmas de las funciones están predeterminadas mediante alias de retrollamada:
    • SynchronizationNotifier ([SWS_TS_14222]) para la notificación ante un cambio del SynchronizationStatus (firma std::function<void(const SynchronizationStatus &)>, especificada como no segura para subprocesos).
    • SynchronizedTimeBaseNotifier ([SWS_TS_14221]) para la transmisión de instantáneas de estado completas mediante SynchronizedTimeBaseStatus (firma std::function<void(const SynchronizedTimeBaseStatus &)>, no segura para subprocesos).
    • TimePrecisionNotifier ([SWS_TS_14223]) para la evaluación periódica de datos de medición de precisión a través de TimePrecisionMeasurement (firma std::function<void(const TimePrecisionMeasurement &)>, no segura para subprocesos).
  3. Registrar marcas de tiempo y datos de usuario: La aplicación consulta instantes del tipo Timestamp ([SWS_TS_01251]) y puede transportar información adicional relativa a la aplicación a través de UserData.

Escenarios de error

El tratamiento de errores en ara::tsync sigue las convenciones de ara::core. Los errores se representan mediante el dominio de error TsyncErrorDomain y el enum de códigos de error TsyncErrc ([SWS_TS_00901]):

código de error Valor numérico Significado y causa
kDaemonConnectionLost 1 La operación solicitada falla porque se ha interrumpido la conexión con el demonio de Time Synchronization.
kLimitsExceeded 2 Un parámetro pasado supera el rango de valores permitido.
kFunctionNotSupported 3 La función solicitada no es compatible con la implementación o configuración actual.
kInvalidUserDataSize 4 La longitud de los datos de usuario pasados supera el tamaño máximo permitido (especificado por UserData::kMaxUserDataSize, por defecto 3 bytes).

Para la creación y comprobación de objetos de error, el espacio de nombres proporciona la función auxiliar segura para subprocesos y exenta de excepciones MakeErrorCode ([SWS_TS_00910]), así como el acceso al dominio de error global a través de GetTsyncErrorDomain ([SWS_TS_00909]). Como alternativa, la clase de excepción TsyncException señala situaciones excepcionales en contextos en los que se utilizan excepciones de C++.

Esta guía se basa en los requisitos y definiciones de tipos de la especificación ara::tsync (AUTOSAR Adaptive Platform R25-11).

<h4>Contexto</h4>
<p>
El espacio de nombres de C++ <code>ara::tsync</code> representa la interfaz funcional del módulo <em>Time Synchronization</em> (tsync) en AUTOSAR Adaptive Platform. Permite a las aplicaciones el acceso homogéneo a bases de tiempo sincronizadas, así como la monitorización de los estados de sincronización y la calidad temporal. La arquitectura distingue principalmente entre consumidores y proveedores de información horaria:
</p>
<ul>
<li><code>SynchronizedTimeBaseConsumer</code> sirve a las aplicaciones como punto de acceso a una base de tiempo configurada y referenciada mediante un <em>InstanceSpecifier</em> para recuperar marcas de tiempo o seguir cambios de estado.</li>
<li><code>SynchronizedTimeBaseProvider</code> permite a las aplicaciones o componentes de plataforma actuar como fuente horaria y proporcionar una base de tiempo.</li>
<li><code>TimeBase</code> funciona como un constructo de pseudorreloj para la tipificación conforme al estándar en el marco de <code>std::chrono</code>. Sobre esta base, el alias de tipo <code>Timestamp</code> (<a class="spec-record-ref" data-req="SWS_TS_01251" href="../spec/record.html?id=SWS_TS_01251">[SWS_TS_01251]</a>) define instantes estandarizados como <code>std::chrono::time_point&lt;TimeBase, std::chrono::nanoseconds&gt;</code>.</li>
<li><code>SynchronizedTimeBaseStatus</code> captura instantáneas del estado del sistema de una base de tiempo, incluida la información de comunicación y de saltos.</li>
<li>Las estructuras de datos de medición y validación (entre ellas <code>TimeMasterMeasurementType</code>, <code>TimeSlaveMeasurementType</code>, <code>PdelayInitiatorMeasurementType</code>, <code>PdelayResponderMeasurementType</code> y <code>TimePrecisionMeasurement</code>), así como las interfaces de retrollamada <code>ConsumerTimeBaseValidationNotification</code> y <code>ProviderTimeBaseValidationNotification</code>, admiten la verificación y evaluación de precisión de la distribución horaria.</li>
</ul>

<h4>Ciclo de vida y estados de sincronización</h4>
<p>
Las bases de tiempo pasan durante el funcionamiento en tiempo de ejecución por estados de sincronización discretos, representados mediante el enum <code>SynchronizationStatus</code> (<a class="spec-record-ref" data-req="SWS_TS_01050" href="../spec/record.html?id=SWS_TS_01050">[SWS_TS_01050]</a>). Tras el arranque, una base de tiempo se encuentra inicialmente en el estado <code>kNotSynchronizedUntilStartup</code> (=0). Tan pronto como los mensajes de sincronización se procesan correctamente, la base de tiempo pasa al estado <code>kSynchronized</code> (=2) en caso de acoplamiento directo con el Time Master, o a <code>kSynchToGateway</code> (=3) si la sincronización se realiza indirectamente a través de una pasarela. Si no se produce la sincronización dentro de una ventana temporal definida, se adopta el estado <code>kTimeOut</code> (=1).
</p>
<p>
Paralelamente al estado de comunicación, el enum <code>LeapJump</code> (<a class="spec-record-ref" data-req="SWS_TS_01051" href="../spec/record.html?id=SWS_TS_01051">[SWS_TS_01051]</a>) señala correcciones bruscas de la base de tiempo: <code>kTimeLeapNone</code> (=0) indica la evolución normal sin superación del valor umbral, mientras que <code>kTimeLeapFuture</code> (=1) identifica un salto hacia adelante y <code>kTimeLeapPast</code> (=2) un salto hacia atrás más allá del valor umbral configurado.
</p>

<h4>Ruta de uso</h4>
<p>
Un flujo de uso típico del lado del consumidor se divide en instanciación, registro de funciones de retrollamada asíncronas y consulta cíclica o controlada por eventos de información horaria:
</p>
<ol>
<li><strong>Vincular el acceso:</strong> Una aplicación consumidora instancia un objeto del tipo <code>SynchronizedTimeBaseConsumer</code> especificando el <em>InstanceSpecifier</em> adecuado.</li>

</li>
