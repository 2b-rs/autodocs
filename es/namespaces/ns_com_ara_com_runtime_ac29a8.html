namespace ara::com::runtime

Contexto

El namespace ara::com::runtime proporciona servicios básicos de tiempo de ejecución dentro de la gestión de comunicación (Communication Management) de la AUTOSAR Adaptive Platform [SWS_CM_00118]. Las declaraciones de este namespace deben incluirse a través del archivo de cabecera ara/com/runtime.h [SWS_CM_00118], AUTOSAR_AP_SWS_CommunicationManagement p. 39.

La responsabilidad central del namespace radica en la resolución de identificadores de tiempo de diseño y de modelo en identificadores concretos de tiempo de ejecución. En arquitecturas orientadas a servicios, una aplicación modela típicamente sus terminales de comunicación mediante puertos representados como ara::core::InstanceSpecifier [SWS_CM_00118]. El sistema en tiempo de ejecución debe asignar estos identificadores de metamodelo a las instancias reales en la pila de comunicación, las cuales existen como ara::com::InstanceIdentifier o bien agrupadas en ara::com::InstanceIdentifierContainer [SWS_CM_00118], AUTOSAR_AP_SWS_CommunicationManagement p. 40.

El namespace interactúa en este contexto esencialmente con tres interlocutores:

  • Aplicación adaptativa: Actúa como invocador y pasa la especificación del metamodelo que se mapeará al servicio en tiempo de ejecución [SWS_CM_00118].
  • Especificación de instancia de metamodelo (ara::core::InstanceSpecifier): Sirve como parámetro de entrada y ancla de identificación para la resolución [SWS_CM_00118].
  • Contenedor de instancias (ara::com::InstanceIdentifierContainer): Aloja los identificadores de instancia de tiempo de ejecución resultantes y refleja el resultado de la resolución [SWS_CM_00118].

Diagrama de contexto: interlocutores de interacción y flujo de datos en la resolución de instancias en ara::com::runtime. Fuentes: [SWS_CM_00118], AUTOSAR_AP_SWS_CommunicationManagement págs. 39–40.

Ruta de uso

La ruta de uso fundamental en el namespace ara::com::runtime está formada por la función libre ResolveInstanceIDs [SWS_CM_00118]. Esta permite a una aplicación determinar todos los identificadores de instancia de tiempo de ejecución correspondientes a partir de una especificación de metamodelo dada, sin que sea necesaria la codificación fija manual de direcciones de red o ID de servicios AUTOSAR_AP_SWS_CommunicationManagement p. 41.

La secuencia típica se realiza en los siguientes pasos:

  1. Suministro del identificador: La aplicación instancia o recibe un ara::core::InstanceSpecifier (parámetro metaModelIdentifier), que representa el puerto o el identificador de servicio buscado del metamodelo [SWS_CM_00118].
  2. Invocación de la función de resolución: La aplicación invoca sincrónicamente la función ara::com::runtime::ResolveInstanceIDs(metaModelIdentifier) [SWS_CM_00118]. La invocación está especificada como noexcept y segura frente a excepciones (exception safe) [SWS_CM_00118].
  3. Resolución en el sistema en tiempo de ejecución: El sistema traduce el InstanceSpecifier a los identificadores de instancia asignados. El tamaño o número de elementos del ara::com::InstanceIdentifierContainer resultante es proporcional a la cantidad de coincidencias encontradas en el sistema [SWS_CM_00118]. Si existen varias instancias configuradas para el mismo specifier, el contenedor contiene todos los identificadores coincidentes [SWS_CM_00118].
  4. Evaluación del resultado: El retorno se realiza a través del tipo por valor ara::core::Result<ara::com::InstanceIdentifierContainer> [SWS_CM_00118]. La aplicación invocadora comprueba si el resultado contiene un valor. En caso de éxito, el InstanceIdentifierContainer extraído puede utilizarse para instanciar proxies o skeletons de comunicación AUTOSAR_AP_SWS_CommunicationManagement p. 42.

Diagrama de secuencia: secuencia de invocación y bifurcación de la resolución de instancias mediante ResolveInstanceIDs. Fuentes: [SWS_CM_00118], AUTOSAR_AP_SWS_CommunicationManagement págs. 40–42.

Escenarios de error

Dado que la interfaz está declarada como noexcept, no se producen excepciones de C++ al invocar ResolveInstanceIDs [SWS_CM_00118]. Todas las situaciones de error se encapsulan en el tipo de retorno ara::core::Result según las especificaciones de la Adaptive Platform [SWS_CM_00118].

Para la función está definido el siguiente estado de error específico:

código de error Causa del error Semántica
ComErrc::kInstanceIDNotResolvable El ara::core::InstanceSpecifier pasado es formalmente válido, pero no pudo ser asignado a ningún ara::com::InstanceIdentifier existente [SWS_CM_00118]. Semántica de reversión (rollback_semantics) [SWS_CM_00118].

Las condiciones previas y posteriores son determinantes para un uso robusto:

  • Condición previa: La aplicación debe pasar un metaModelIdentifier bien definido [SWS_CM_00118]. Si este es formalmente no válido o no se encuentra en el sistema, la resolución falla.
  • Condición posterior en caso de error: Gracias a la semántica de reversión garantizada, el sistema permanece en un estado inalterado y coherente [SWS_CM_00118]. No se generan contenedores incompletos.
  • Tratamiento de errores: La aplicación debe gestionar el error explícitamente. Un fallo en la resolución con un InstanceSpecifier en principio válido se debería en la práctica a información de despliegue o mapeo incompleta en el manifiesto (interpretación). En este caso, la aplicación no debe intentar acceder a instancias de comunicación inexistentes, sino iniciar medidas sustitutivas o estados de error adecuados.

ResolveInstanceIDs función

Translates an ara::core::InstanceSpecifier to a ara::com:: InstanceIdentifierContainer. The length/size of the ara::com:: InstanceIdentifierContainer is relative to the number of matches.
