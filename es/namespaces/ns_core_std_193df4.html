Permite la integración de tipos ara::core en contenedores estándar y construcciones lingüísticas de la biblioteca estándar de C++.

En el módulo core, el espacio de nombres std proporciona especializaciones de plantilla de std::hash, std::tuple_size y std::tuple_element para tipos de datos de AUTOSAR Adaptive Platform. Esto hace posible el uso directo de tipos como ara::core::String, ara::core::Optional, ara::core::Variant, ara::core::Vector y ara::core::Array en contenedores estándar y con construcciones lingüísticas de tuplas de C++. Una condición de contorno es que, en el caso de tipos anidados, los tipos de datos contenidos también deben disponer de especializaciones válidas en tiempo de compilación.

Contexto

En el módulo core de AUTOSAR Adaptive Platform, el espacio de nombres std sirve para la integración fluida de tipos básicos específicos de la plataforma en la biblioteca estándar de C++. En lugar de introducir nuevos tipos, el espacio de nombres proporciona especializaciones de plantilla específicas de clases de utilidad estandarizadas. Los interlocutores de interacción comprenden tres componentes esenciales: los tipos genéricos de la biblioteca estándar de C++ (en particular, contenedores asociativos no ordenados y utilidades de tupla), las especializaciones de plantilla dentro de std, así como los tipos de datos ara::core::Array, ara::core::Monostate, ara::core::Optional, ara::core::String, ara::core::StringView, ara::core::Variant y ara::core::Vector definidos en el módulo core.

Diagrama de contexto: interacción de contenedores estándar, las especializaciones en std y los tipos ara::core. Fuentes: declaraciones de payload del módulo core

Las especializaciones de std::hash permiten emplear tipos de datos del núcleo adaptativo directamente como claves en contenedores estándar como std::unordered_map o std::unordered_set. Paralelamente, las especializaciones std::tuple_size y std::tuple_element para ara::core::Array amplían la compatibilidad con interfaces de metaprogramación y construcciones lingüísticas estandarizadas.

Ruta de uso

Una ruta de uso típica comienza con el empleo de un tipo de datos ara::core en código genérico de C++. Por ejemplo, una aplicación declara una tabla hash con claves del tipo ara::core::String o ara::core::Optional<T>. Al insertar, borrar o buscar, el contenedor accede implícitamente a std::hash<ara::core::String> o std::hash<ara::core::Optional<T>> para determinar el valor hash de la clave.

Las especializaciones cubren diferentes estructuras de datos:

  • Cadenas de caracteres y vistas: std::hash<ara::core::String> y std::hash<ara::core::StringView> calculan valores hash sobre la secuencia de caracteres contenida.
  • Tipos compuestos: std::hash<ara::core::Optional<T>>, std::hash<ara::core::Variant<...>> y std::hash<ara::core::Vector<T, Allocator>> permiten el cálculo de hash de estructuras de tipos complejas. Interpretación: es probable que las especializaciones para ara::core::Optional y ara::core::Variant se orienten al comportamiento semántico de los modelos estandarizados y generen valores deterministas para estados vacíos o no ocupados.
  • Tipos sin estado: std::hash<ara::core::Monostate> proporciona una función hash para estados vacíos, tal como se emplean típicamente en variantes.
  • Protocolo de tupla: para campos de datos fijos, std::tuple_size<ara::core::Array<T, N>> proporciona el número de elementos en tiempo de compilación, mientras que std::tuple_element<I, ara::core::Array<T, N>> determina el tipo de datos de la posición I. Interpretación: es probable que las especializaciones de std::tuple_size y std::tuple_element permitan con ello el uso de ara::core::Array con enlaces estructurados (Structured Bindings).

Escenarios de error

Dado que los elementos en el espacio de nombres std son exclusivamente especializaciones de plantilla, los escenarios de error se producen prioritariamente en tiempo de compilación. Las constelaciones de problemas típicas comprenden:

  • Capacidad de hash ausente de los tipos básicos: si se instancia std::hash para un tipo anidado como ara::core::Optional<T> o ara::core::Vector<T, Allocator>, también debe existir una especialización válida de std::hash para el tipo de elemento T. Si esta falta, se produce un error de compilación.
  • Indexación no válida en el protocolo de tupla: el acceso a std::tuple_element<I, ara::core::Array<T, N>> con un índice I >= N vulnera la precondición de la plantilla e interrumpe el proceso de compilación.

Interpretación: es probable que los escenarios de error se limiten esencialmente a errores en tiempo de compilación por especializaciones de tipos incompletas o violaciones de rango estáticas, ya que el extracto de la especificación no define códigos de error ni interfaces de excepción en tiempo de ejecución.

Esta guía se basa exclusivamente en las especializaciones de clases declaradas del módulo core para el Release R25-11.
