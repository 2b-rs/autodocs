Contexto

El espacio de nombres ara::log encapsula la funcionalidad para registro y rastreo dentro de las aplicaciones de AUTOSAR Adaptive Platform. Su responsabilidad principal consiste en proporcionar interfaces estandarizadas para la generación, parametrización y transmisión de mensajes de registro. En el centro de la arquitectura se encuentran cuatro componentes principales: la clase Logger representa un contexto de registro específico, mientras que LogStream encapsula el mensaje propiamente dicho y proporciona operadores de flujo para la vinculación de datos útiles. Para la transmisión de cargas útiles estructuradas, Argument sirve como contenedor con seguridad de tipos y Format como portador de especificaciones de formato.

El marco de trabajo actúa como intermediario entre el componente de software de aplicación y los sumideros de salida configurados. Si no existe un modelo de configuración correspondiente, el marco de trabajo escribe los mensajes de registro por defecto en la consola ([SWS_LOG_00021], [SWS_LOG_00263]). Además, ara::log interactúa con un backend DLT (Diagnostic Log and Trace). Para graduar la urgencia, la enumeración LogLevel define seis niveles de gravedad desde kFatal, pasando por kError, kWarn, kInfo y kDebug, hasta kVerbose ([SWS_LOG_00018]).

Ciclo de vida

Las instancias de la clase Logger no son construidas directamente por la aplicación, sino que se obtienen mediante las funciones de factoría estáticas CreateLogger ([SWS_LOG_00021], [SWS_LOG_00263], [SWS_LOG_00256]). El invocador recibe aquí una referencia (Logger&) a un objeto gestionado internamente. La propiedad (ownership) permanece de forma permanente dentro del marco de registro, por lo que la aplicación no debe realizar ninguna desasignación.

A través de RegisterConnectionStateHandler ([SWS_LOG_00205]), se puede registrar una retrollamada del tipo ConnectionStateHandler ([SWS_LOG_00265]) para recibir información sobre los cambios en el estado de conexión de clientes de análisis externos. El estado está representado por ClientState ([SWS_LOG_00098]):

  • kUnknown: el backend DLT aún no está operativo; no se puede determinar el estado.
  • kNotConnected: ningún cliente externo conectado.
  • kConnected: un cliente remoto está conectado activamente.

En cuanto a la concurrencia, RegisterConnectionStateHandler está especificado expresamente como no seguro para subprocesos ([SWS_LOG_00205]). Se puede almacenar como máximo una retrollamada; una llamada de registro adicional sobrescribe la función configurada previamente. La factoría CreateLogger y los operadores de flujo, en cambio, están implementados de manera segura para subprocesos ([SWS_LOG_00021], [SWS_LOG_00063]).

Diagrama de estados: estados de conexión de un cliente de registro externo en el ciclo de vida del backend. Fuentes: [SWS_LOG_00098], [SWS_LOG_00205].

Ruta de uso

El flujo típico en el registro se divide en la creación del contexto, la preparación de los datos útiles formateados y la entrega al flujo:

  1. Solicitar registrador: mediante CreateLogger se crea un contexto con ID de contexto, descripción y nivel de registro predeterminado opcional ([SWS_LOG_00021], [SWS_LOG_00263]). Como alternativa, el registrador puede instanciarse basado en manifiesto mediante un InstanceSpecifier ([SWS_LOG_00256]).
  2. Formatear argumentos: con ayuda de la función auxiliar Arg ([SWS_LOG_00201]), los valores pueden enriquecerse con atributos como nombre y unidad. Como indicación de formato, se pueden pasar objetos de formato genéricos. Para números enteros, están disponibles asistentes de formateo como Dec ([SWS_LOG_00211], [SWS_LOG_00212]), Hex ([SWS_LOG_00209], [SWS_LOG_00210]), Bin ([SWS_LOG_00215], [SWS_LOG_00216]), Oct ([SWS_LOG_00213], [SWS_LOG_00214]) o Dflt ([SWS_LOG_00208]). Para números de punto flotante, existen controles de precisión a través de DecFloat ([SWS_LOG_00217]), DecFloatMax ([SWS_LOG_00218]), EngFloat ([SWS_LOG_00219]), EngFloatMax ([SWS_LOG_00220]), HexFloat ([SWS_LOG_00221]), HexFloatMax ([SWS_LOG_00222]), AutoFloat ([SWS_LOG_00223]) y AutoFloatMax ([SWS_LOG_00224]) basados en la enumeración Fmt ([SWS_LOG_00206]).
  3. Serializar mensajes: los operadores de desplazamiento sobrecargados (operator<<) introducen tipos de datos formateados y estandarizados en el LogStream. Se admiten, entre otros, LogLevel ([SWS_LOG_00063]), core::ErrorCode ([SWS_LOG_00124]), intervalos de tiempo del tipo std::chrono::duration ([SWS_LOG_00125]), ara::core::InstanceSpecifier ([SWS_LOG_00126]), así como direcciones genéricas a través de const void* ([SWS_LOG_00127]).

Diagrama de secuencia: secuencia típica desde la creación del registrador y la preparación de los argumentos hasta la salida del mensaje. Fuentes: [SWS_LOG_00021], [SWS_LOG_00201], [SWS_LOG_00124].

Escenarios de error

En el espacio de nombres ara::log se establecen tanto restricciones de tipos estáticas como infracciones en tiempo de ejecución:

  • Restricciones de tipo en Arg: la llamada a Arg genera un error de compilación (ill-formed) si el tipo T no es ni aritmético ni bool y no se puede convertir a ara::core::StringView o ara::core::Span<const ara::core::Byte>. Además, la llamada no está permitida si T representa un bool, StringView o Span y, al mismo tiempo, el parámetro unit no es nullptr ([SWS_LOG_00201]).
  • Infracciones de manifiesto y de modelo en CreateLogger: si se llama a CreateLogger con un InstanceSpecifier ([SWS_LOG_00256]), pueden producirse las siguientes infracciones:
    • InstanceSpecifierMappingIntegrityViolation: el identificador no se puede resolver en el modelo del ejecutable o no hace referencia a ningún PortPrototype.
    • PortInterfaceMappingViolation: el tipo de mapeo no coincide con la interfaz esperada.
    • ProcessMappingViolation: aunque existe una referencia de instancia coincidente, falta el proceso modelado asociado para el proceso en tiempo de ejecución.
    • InstanceSpecifierAlreadyInUseViolation: el identificador ya ha sido ocupado en este proceso por una llamada al constructor.
  • Salida de códigos de error: al escribir un core::ErrorCode en un LogStream ([SWS_LOG_00124]), el sistema emite en la consola el nombre de dominio (ErrorCode::Domain().Name()) junto con el número de error numérico.

<h4>Contexto</h4>
<p>El espacio de nombres <code>ara::log</code> encapsula la funcionalidad para registro y rastreo dentro de las aplicaciones de AUTOSAR Adaptive Platform. Su responsabilidad principal consiste en proporcionar interfaces estandarizadas para la generación, parametrización y transmisión de mensajes de registro. En el centro de la arquitectura se encuentran cuatro componentes principales: la clase <code>Logger</code> representa un contexto de registro específico, mientras que <code>LogStream</code> encapsula el mensaje propiamente dicho y proporciona operadores de flujo para la vinculación de datos útiles. Para la transmisión de cargas útiles estructuradas, <code>Argument</code> sirve como contenedor con seguridad de tipos y <code>Format</code> como portador de especificaciones de formato.</p>
<p>El marco de trabajo actúa como intermediario entre el componente de software de aplicación y los sumideros de salida configurados. Si no existe un modelo de configuración correspondiente, el marco de trabajo escribe los mensajes de registro por defecto en la consola (<a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00263" href="../spec/record.html?id=SWS_LOG_00263">[SWS_LOG_00263]</a>). Además, <code>ara::log</code> interactúa con un backend DLT (Diagnostic Log and Trace). Para graduar la urgencia, la enumeración <code>LogLevel</code> define seis niveles de gravedad desde <code>kFatal</code>, pasando por <code>kError</code>, <code>kWarn</code>, <code>kInfo</code> y <code>kDebug</code>, hasta <code>kVerbose</code> (<a class="spec-record-ref" data-req="SWS_LOG_00018" href="../spec/record.html?id=SWS_LOG_00018">[SWS_LOG_00018]</a>).</p>

<h4>Ciclo de vida</h4>
<p>Las instancias de la clase <code>Logger</code> no son construidas directamente por la aplicación, sino que se obtienen mediante las funciones de factoría estáticas <code>CreateLogger</code> (<a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00263" href="../spec/record.html?id=SWS_LOG_00263">[SWS_LOG_00263]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00256" href="../spec/record.html?id=SWS_LOG_00256">[SWS_LOG_00256]</a>). El invocador recibe aquí una referencia (<code>Logger&amp;</code>) a un objeto gestionado internamente. La propiedad (ownership) permanece de forma permanente dentro del marco de registro, por lo que la aplicación no debe realizar ninguna desasignación.</p>
<p>A través de <code>RegisterConnectionStateHandler</code> (<a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>), se puede registrar una retrollamada del tipo <code>ConnectionStateHandler</code> (<a class="spec-record-ref" data-req="SWS_LOG_00265" href="../spec/record.html?id=SWS_LOG_00265">[SWS_LOG_00265]</a>) para recibir información sobre los cambios en el estado de conexión de clientes de análisis externos. El estado está representado por <code>ClientState</code> (<a class="spec-record-ref" data-req="SWS_LOG_00098" href="../spec/record.html?id=SWS_LOG_00098">[SWS_LOG_00098]</a>):</p>
<ul>
<li><code>kUnknown</code>: el backend DLT aún no está operativo; no se puede determinar el estado.</li>
<li><code>kNotConnected</code>: ningún cliente externo conectado.</li>
<li><code>kConnected</code>: un cliente remoto está conectado activamente.</li>
</ul>
<p>En cuanto a la concurrencia, <code>RegisterConnectionStateHandler</code> está especificado expresamente como no seguro para subprocesos (<a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>). Se puede almacenar como máximo una retrollamada; una llamada de registro adicional sobrescribe la función configurada previamente. La factoría <code>CreateLogger</code> y los operadores de flujo, en cambio, están implementados de manera segura para subprocesos (<a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00063" href="../spec/record.html?id=SWS_LOG_00063">[SWS_LOG_00063]</a>).</p>

<h4>Ruta de uso</h4>
<p>El flujo típico en el registro se divide en la creación del contexto, la preparación de los datos útiles formateados y la entrega al flujo:</p>
<ol>
<li><strong>Solicitar registrador:</strong> mediante <code>CreateLogger</code> se crea un contexto con ID de contexto, descripción y nivel de registro predeterminado opcional (<a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00263" href="../spec/record.html?id=SWS_LOG_00263">[SWS_LOG_00263]</a>). Como alternativa, el registrador puede instanciarse basado en manifiesto mediante un <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_LOG_00256" href="../spec/record.html?id=SWS_LOG_00256">[SWS_LOG_00256]</a>).</li>
<li><strong>Formatear argumentos:</strong> con ayuda de la función auxiliar <code>Arg</code> (<a class="spec-record-ref" data-req="SWS_LOG_00201" href="../spec/record.html?id=SWS_LOG_00201">[SWS_LOG_00201]</a>), los valores pueden enriquecerse con atributos como nombre y unidad. Como indicación de formato, se pueden pasar objetos de formato genéricos. Para números enteros, están disponibles asistentes de formateo como <code>Dec</code> (<a class="spec-record-ref" data-req="SWS_LOG_00211" href="../spec/record.html?id=SWS_LOG_00211">[SWS_LOG_00211]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00212" href="../spec/record.html?id=SWS_LOG_00212">[SWS_LOG_00212]</a>), <code>Hex</code> (<a class="spec-record-ref" data-req="SWS_LOG_00209" href="../spec/record.html?id=SWS_LOG_00209">[SWS_LOG_00209]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00210" href="../spec/record.html?id=SWS_LOG_00210">[SWS_LOG_00210]</a>), <code>Bin</code> (<a class="spec-record-ref" data-req="SWS_LOG_00215" href="../spec/record.html?id=SWS_LOG_00215">[SWS_LOG_00215]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00216" href="../spec/record.html?id=SWS_LOG_00216">[SWS_LOG_00216]</a>), <code>Oct</code> (<a class="spec-record-ref" data-req="SWS_LOG_00213" href="../spec/record.html?id=SWS_LOG_00213">[SWS_LOG_00213]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00214" href="../spec/record.html?id=SWS_LOG_00214">[SWS_LOG_00214]</a>) o <code>Dflt</code> (<a class="spec-record-ref" data-req="SWS_LOG_00208" href="../spec/record.html?id=SWS_LOG_00208">[SWS_LOG_00208]</a>). Para números de punto flotante, existen controles de precisión a través de <code>DecFloat</code> (<a class="spec-record-ref" data-req="SWS_LOG_00217" href="../spec/record.html?id=SWS_LOG_00217">[SWS_LOG_00217]</a>), <code>DecFloatMax</code> (<a class="spec-record-ref" data-req="SWS_LOG_00218" href="../spec/record.html?id=SWS_LOG_00218">[SWS_LOG_00218]</a>), <code>EngFloat</code> (<a class="spec-record-ref" data-req="SWS_LOG_00219" href="../spec/record.html?id=SWS_LOG_00219">[SWS_LOG_00219]</a>), <code>EngFloatMax</code> (<a class="spec-record-ref" data-req="SWS_LOG_00220" href="../spec/record.html?id=SWS_LOG_00220">[SWS_LOG_00220]</a>), <code>HexFloat</code> (<a class="spec-record-ref" data-req="SWS_LOG_00221" href="../spec/record.html?id=SWS_LOG_00221">[SWS_LOG_00221]</a>), <code>HexFloatMax</code> (<a class="spec-record-ref" data-req="SWS_LOG_00222" href="../spec/record.html?id=SWS_LOG_00222">[SWS_LOG_00222]</a>), <code>AutoFloat</code> (<a class="spec-record-ref" data-req="SWS_LOG_00223" href="../spec/record.html?id=SWS_LOG_00223">[SWS_LOG_00223]</a>) y <code>AutoFloatMax</code> (<a class="spec-record-ref" data-req="SWS_LOG_00224" href="../spec/record.html?id=SWS_LOG_00224">[SWS_LOG_00224]</a>) basados en la enumeración <code>Fmt</code> (<a class="spec-record-ref" data-req="SWS_LOG_00206" href="../spec/record.html?id=SWS_LOG_00206">[SWS_LOG_00206]</a>).</li>
<li><strong>Serializar mensajes:</strong> los operadores de desplazamiento sobrecargados (<code>operator&lt;&lt;</code>) introducen tipos de datos formateados y estandarizados en el <code>LogStream</code>. Se admiten, entre otros, <code>LogLevel</code> (<a class="spec-record-ref" data-req="SWS_LOG_00063" href="../spec/record.html?id=SWS_LOG_00063">[SWS_LOG_00063]</a>), <code>core::ErrorCode</code> (<a class="spec-record-ref" data-req="SWS_LOG_00124" href="../spec/record.html?id=SWS_LOG_00124">[SWS_LOG_00124]</a>), intervalos de tiempo del tipo <code>std::chrono::duration</code> (<a class="spec-record-ref" data-req="SWS_LOG_00125" href="../spec/record.html?id=SWS_LOG_00125">[SWS_LOG_00125]</a>), <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_LOG_00126" href="../spec/record.html?id=SWS_LOG_00126">[SWS_LOG_00126]</a>), así como direcciones genéricas a través de <code>const void*</code> (<a class="spec-record-ref" data-req="SWS_LOG_00127" href="../spec/record.html?id=SWS_LOG_00127">[SWS_LOG_00127]</a>).</li>
</ol>

<h4>Escenarios de error</h4>
<p>En el espacio de nombres <code>ara::log</code> se establecen tanto restricciones de tipos estáticas como infracciones en tiempo de ejecución:</p>
<ul>
<li><strong>Restricciones de tipo en <code>Arg</code>:</strong> la llamada a <code>Arg</code> genera un error de compilación (ill-formed) si el tipo <code>T</code> no es ni aritmético ni <code>bool</code> y no se puede convertir a <code>ara::core::StringView</code> o <code>ara::core::Span&lt;const ara::core::Byte&gt;</code>. Además, la llamada no está permitida si <code>T</code> representa un <code>bool</code>, <code>StringView</code> o <code>Span</code> y, al mismo tiempo, el parámetro <code>unit</code> no es <code>nullptr</code> (<a class="spec-record-ref" data-req="SWS_LOG_00201" href="../spec/record.html?id=SWS_LOG_00201">[SWS_LOG_00201]</a>).</li>
<li><strong>Infracciones de manifiesto y de modelo en <code>CreateLogger</code>:</strong> si se llama a <code>CreateLogger</code> con un <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_LOG_00256" href="../spec/record.html?id=SWS_LOG_00256">[SWS_LOG_00256]</a>), pueden producirse las siguientes infracciones:
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: el identificador no se puede resolver en el modelo del ejecutable o no hace referencia a ningún <code>PortPrototype</code>.</li>
<li><code>PortInterfaceMappingViolation</code>: el tipo de mapeo no coincide con la interfaz esperada.</li>
<li><code>ProcessMappingViolation</code>: aunque existe una referencia de instancia coincidente, falta el proceso modelado asociado para el proceso en tiempo de ejecución.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: el identificador ya ha sido ocupado en este proceso por una llamada al constructor.</li>
</ul>
</li>
<li><strong>Salida de códigos de error:</strong> al escribir un <code>core::ErrorCode</code> en un <code>LogStream</code> (<a class="spec-record-ref" data-req="SWS_LOG_00124" href="../spec/record.html?id=SWS_LOG_00124">[SWS_LOG_00124]</a>), el sistema emite en la consola el nombre de dominio (<code>ErrorCode::Domain().Name()</code>) junto con el número de error numérico.</li>
</ul>
