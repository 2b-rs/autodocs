Rol y contexto de sistema de la interfaz de servicio

La interfaz de servicio UpdateAllowedService representa una interfaz de comunicación estandarizada dentro del Functional Cluster State Management (SM) de la AUTOSAR Adaptive Platform ([SWS_SM_91025]). El servicio es proporcionado por el Functional Cluster State Management a través de un puerto definido para ello ([SWS_SM_91024]). Como consumidor del servicio actúa una SMControlApplication, que utiliza esta interfaz para interactuar directamente con el Controller o la StateMachine del State Management (AUTOSAR_AP_SWS_StateManagement §9.2.3 «StateMachine UpdateAllowed service», AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 «Interfaces for a SMControlApplication»).

En el contexto arquitectónico global, UpdateAllowedService pertenece a las interfaces dedicadas para una SMControlApplication (AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 «Defined interfaces»). La interfaz constituye el enlace entre la lógica de control de nivel superior de todo el vehículo y la interacción con el Update and Configuration Management (UCM), determinando a través del contenido del campo de servicio si las sesiones de actualización se habilitan o se bloquean (AUTOSAR_AP_SWS_StateManagement §«Rejection of update session», AUTOSAR_AP_SWS_StateManagement §9.2.3 «StateMachine UpdateAllowed service»).

Campos, métodos y semántica de comunicación

La definición funcional de UpdateAllowedService se concentra completamente en el campo UpdateAllowed ([SWS_SM_91108]). No se especifican métodos propios ni eventos aislados en la interfaz de servicio ([SWS_SM_91025], [SWS_SM_91108]). El campo es de tipo UpdateAllowedType e implementa la semántica de comunicación completa de ara::com, compuesta por getter, setter y notificador ([SWS_SM_91108]).

Las tres variantes del campo cubren las siguientes tareas:

  • Setter (HasSetter true): Es llamado por la SMControlApplication para determinar activamente si las actualizaciones de software están permitidas o no durante el funcionamiento del sistema ([SWS_SM_91108], AUTOSAR_AP_SWS_StateManagement §9.2.3 «StateMachine UpdateAllowed service»).
  • Getter (HasGetter true): Permite a la aplicación de control leer el estado de habilitación actualmente registrado en el State Management ([SWS_SM_91108]).
  • Notifier (HasNotifier true): Informa a los consumidores suscritos de forma asíncrona y basada en eventos sobre cualquier cambio de estado del campo ([SWS_SM_91108]).

Ciclo de vida y flujos de sesión en el proceso de actualización

En el uso práctico está previsto que la viabilidad de una campaña de actualización se evalúe fundamentalmente de antemano a nivel de todo el vehículo, de modo que el Update and Configuration Management (UCM) no invoque la solicitud de sesión RequestUpdateSession sin una sincronización previa (AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»). Sin embargo, dado que una campaña de actualización puede abarcar varias máquinas adaptativas y requerir un tiempo considerable, las circunstancias locales de una máquina pueden cambiar mientras tanto (AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»).

Por esta razón, antes del inicio de la fase de actualización local se requiere una llamada a RequestUpdateSession (AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»). El Modelled Process, que controla la StateMachine del tipo Controller en el State Management, comprueba durante esta llamada al método el valor actual del campo UpdateAllowed (AUTOSAR_AP_SWS_StateManagement §«Rejection of update session», AUTOSAR_AP_SWS_StateManagement §9.2.3 «StateMachine UpdateAllowed service»). La decisión sobre la concesión de una sesión de actualización depende directamente de la especificación establecida previamente mediante UpdateAllowedService ([SWS_SM_91108]).

Diagrama de secuencia: interacción entre SMControlApplication, State Management y UCM para la habilitación o el rechazo de una sesión de actualización. Fuentes: [SWS_SM_91108], [SWS_SM_00630], AUTOSAR_AP_SWS_StateManagement §«Rejection of update session», AUTOSAR_AP_SWS_StateManagement §9.2.3 «StateMachine UpdateAllowed service».

Tratamiento de errores y rechazo de una sesión de actualización

Si la SMControlApplication determina que las condiciones marco locales no permiten una actualización, lo señaliza a través del campo de servicio ([SWS_SM_91108], AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»). Si UpdateAllowed está establecido en el valor de enumeración kUpdateNotAllowed, el Modelled Process está obligado a rechazar de forma imperativa la solicitud de actualización del Update and Configuration Management ([SWS_SM_00630]).

El rechazo se produce a nivel de interfaz mediante la devolución del Application Error kOperationRejected del método RequestUpdateSession ([SWS_SM_00630]). Esto garantiza que no se pueda iniciar ninguna actualización mientras la lógica de aplicación de nivel superior lo prohíba a través del campo UpdateAllowed ([SWS_SM_00630], AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»).

Esta guía se basa exclusivamente en los extractos de especificación de AUTOSAR Adaptive Platform Release R25-11.

<p>El rechazo se produce a nivel de interfaz mediante la devolución del Application Error <code>kOperationRejected</code> del método <code>RequestUpdateSession</code> (<a class="spec-record-ref" data-req="SWS_SM_00630" href="../spec/record.html?id=SWS_SM_00630">[SWS_SM_00630]</a>). Esto garantiza que no se pueda iniciar ninguna actualización mientras la lógica de aplicación de nivel superior lo prohíba a través del campo <code>UpdateAllowed</code> (<a class="spec-record-ref" data-req="SWS_SM_00630" href="../spec/record.html?id=SWS_SM_00630">[SWS_SM_00630]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=80">AUTOSAR_AP_SWS_StateManagement §«Rejection of update session»</a>).</p>
