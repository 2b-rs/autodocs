Ancla causal: R20-11 Válido desde R20-11 Sintetizado para esta versión de especificación.

Controla salidas moduladas por ancho de pulsos del hardware del microcontrolador canal por canal mediante período y ciclo de trabajo.

Como módulo MCAL, el controlador de dispositivo PWM controla las salidas moduladas por ancho de pulsos del microcontrolador canal por canal y accede para ello directamente a sus registros. Según Pwm_Init, los Pwm User ajustan el ciclo de trabajo y, en canales con período variable, también el período. Pueden conmutar salidas al estado inactivo (Idle) y activar o desactivar notificaciones de flanco [SWS_Pwm_91000]. De manera opcional, el controlador de dispositivo gestiona cambios de dos fases del estado de potencia mediante preparación y establecimiento. En caso de detección de errores activa, notifica fallos como la falta de inicialización o canales no válidos y entonces no ejecuta nada [SWS_Pwm_00201].

El controlador de dispositivo PWM es un módulo MCAL y controla las salidas moduladas por ancho de pulsos del microcontrolador a través de sus registros. Por lo tanto, no requiere interfaces de módulos inferiores (SWS PWM Driver p. 44). Se inicializa de forma síncrona con Pwm_Init y un puntero al conjunto de configuración [SWS_Pwm_00095], al que el ECU State Manager llama como interfaz de inicialización opcional (SWS EcuM p. 152). Típicamente lo utiliza la IoHwAb, por ejemplo mediante un controlador de etapa de potencia (SWS IoHwAb p. 37).

Diagrama de contexto: EcuM inicializa el controlador de dispositivo, el Pwm User lo maneja y el controlador de dispositivo devuelve notificaciones y errores. Fuentes: [SWS_Pwm_00105], [SWS_Pwm_00198], [SWS_Pwm_00104]

El control se realiza mediante un ciclo de trabajo de 16 bits en el que 0x8000 representa el 100 % (SWS PWM Driver p. 18). Los servicios más importantes:

  • Pwm_SetDutyCycle modifica el ciclo de trabajo [SWS_Pwm_91000]. Con 0 % y 100 %, establece un nivel estático en función de la polaridad.
  • Pwm_SetPeriodAndDuty modifica adicionalmente el período, pero solo en canales de la clase PWM_VARIABLE_PERIOD [SWS_Pwm_00110].
  • Pwm_SetOutputToIdle conmuta inmediatamente al nivel Idle [SWS_Pwm_91002].
  • Pwm_GetOutputState lee el nivel interno [SWS_Pwm_00100].

Diagrama de estados: un canal cambia mediante la API entre modulación, nivel estático y estado inactivo (Idle). Fuentes: [SWS_Pwm_91000], [SWS_Pwm_91001], SWS PWM Driver p. 31

Las notificaciones de flanco se activan por canal con Pwm_EnableNotification [SWS_Pwm_91004] y llegan al Pwm User como Pwm_Notification_<#Channel> [SWS_Pwm_00105]. De manera opcional, el controlador de dispositivo también gestiona estados de potencia en dos fases. Pwm_PreparePowerState inicia la preparación [SWS_Pwm_00183], que el Pwm_Main_PowerTransitionManager periódico finaliza [SWS_Pwm_00189]. Después, Pwm_SetPowerState establece el estado [SWS_Pwm_00166].

Con la detección de errores activa, las funciones notifican errores como PWM_E_UNINIT, PWM_E_PARAM_CHANNEL o PWM_E_PERIOD_UNCHANGEABLE [SWS_Pwm_00201] y retornan sin efecto (SWS PWM Driver p. 44). En estos casos, Pwm_GetOutputState devuelve PWM_LOW [SWS_Pwm_30051]. Si se llama a Pwm_SetPowerState mientras el controlador de dispositivo todavía está en uso, se produce el error de tiempo de ejecución PWM_E_NOT_DISENGAGED [SWS_Pwm_00202].

Rol en el MCAL: controlador de dispositivo entre la unidad PWM y el Pwm User

El controlador de dispositivo PWM encapsula las salidas moduladas por ancho de pulsos del microcontrolador. Como módulo de la capa MCAL, accede directamente a los registros del microcontrolador y, por tanto, no requiere interfaces de módulos subyacentes (SWS PWM Driver p. 44). Por la misma razón, no proporciona callbacks para capas inferiores (SWS PWM Driver p. 40) ni ofrece interfaces de servicio (SWS PWM Driver p. 44). Sus servicios están disponibles a través de Pwm.h, tales como Pwm_Init [SWS_Pwm_00095], Pwm_SetDutyCycle [SWS_Pwm_91000] y Pwm_GetOutputState [SWS_Pwm_00100]. Importa los tipos estándar Std_ReturnType y Std_VersionInfoType desde Std_Types.h [SWS_Pwm_00094].

El ECU State Manager incluye Pwm_Init entre sus interfaces de inicialización opcionales (SWS EcuM p. 152). En el caso de uso de una etapa final de potencia, un controlador de etapa de potencia de la IoHwAb llama a servicios de PWM, DIO y SPI y, con ello, ajusta, entre otros, tensiones y frecuencias (SWS IoHwAb p. 37). En sentido inverso, el controlador de dispositivo llama a dos tipos de funciones: las notificaciones específicas de canal Pwm_Notification_<#Channel> [SWS_Pwm_00105] y, en la gestión de potencia, IoHwAb_Pwm_NotifyReadyForPowerState<#Mode> [SWS_Pwm_00198]. Opcionalmente, notifica errores de desarrollo a través de Det_ReportError [SWS_Pwm_00104]. Si el hardware ofrece mecanismos diferentes para canales distintos, esto no se abstrae mediante infijos de API específicos del fabricante, sino a través del número de canal (TPS BSWMDT p. 122).

Diagrama de contexto: el controlador Pwm es inicializado por EcuM y operado por el Pwm User. El planificador lo invoca cíclicamente, notifica eventos al Pwm User y errores a DET, y controla la unidad PWM mediante sus registros. Fuentes: [SWS_Pwm_00104], [SWS_Pwm_00105], [SWS_Pwm_00189], [SWS_Pwm_00198], SWS EcuM p. 152, SWS IoHwAb p. 37, RS PWM Driver p. 14

Modelo de señal: período, ciclo de trabajo, polaridad y clases de canal

Se accede a un canal mediante el identificador numérico Pwm_ChannelType [SWS_Pwm_00106]. El período es de tipo Pwm_PeriodType, un tipo dependiente de la implementación con 8 a 32 bits [SWS_Pwm_00107]. Tres conceptos determinan la señal (SWS PWM Driver p. 9):

  • La polaridad define el nivel inicial de cada período.
  • El ciclo de trabajo indica la proporción de este nivel inicial dentro del período.
  • El estado idle es el estado inicial tras Pwm_SetOutputToIdle o Pwm_DeInit.

El gráfico para la descripción de la señal compara ambas polaridades PWM_HIGH y PWM_LOW (SWS PWM Driver p. 7).

El ciclo de trabajo es un valor de 16 bits. 0x0000 representa el 0 % y 0x8000 el 100 %. Como ayuda de implementación, la especificación menciona AbsoluteDutyCycle = ((uint32)AbsolutePeriodTime * RelativeDutyCycle) >> 15; (SWS PWM Driver p. 18). De forma correspondiente, Pwm_SetDutyCycle y Pwm_SetPeriodAndDuty limitan el parámetro DutyCycle a Min=0x0000 y Max=0x8000 [SWS_Pwm_91000] [SWS_Pwm_91001].

La clase de canal Pwm_ChannelClassType define qué puede modificar un canal en tiempo de ejecución [SWS_Pwm_00110]:

  • PWM_VARIABLE_PERIOD: el período y el ciclo de trabajo son modificables.
  • PWM_FIXED_PERIOD: solo el ciclo de trabajo es modificable.
  • PWM_FIXED_PERIOD_SHIFTED: período fijo y desplazado que no se puede modificar; solo disponible si el hardware lo admite.

El diagrama de período desplazado muestra canales con el mismo período, cuyo inicio de período está desfasado en cada caso un tiempo fijo (SWS PWM Driver p. 23).

Ciclo de vida y control de la señal: desde Pwm_Init hasta el estado idle

Pwm_Init es síncrona y no reentrante. Mediante ConfigPtr, la función recibe un puntero al conjunto de configuración [SWS_Pwm_00095]. Su tipo Pwm_ConfigType tiene contenido específico del hardware [SWS_Pwm_00111]. Según el diagrama de inicialización, las salidas quedan posteriormente, según la configuración, en nivel bajo, en nivel alto o en estado de modulación. Las notificaciones solo se producen tras la primera llamada a Pwm_EnableNotification (SWS PWM Driver p. 46). Si se vuelve a invocar Pwm_Init en un controlador ya inicializado, debe notificarse el error de desarrollo PWM_E_ALREADY_INITIALIZED [SWS_Pwm_50002].

Pwm_DeInit también es síncrona y no reentrante [SWS_Pwm_00096]. La función desinicializa el módulo, establece las salidas en el estado idle y desactiva las interrupciones de PWM, así como las notificaciones de flanco. Puede habilitarse y deshabilitarse mediante PwmDeInitApi (SWS PWM Driver p. 27). Interpretación: después de esto, el módulo debería considerarse de nuevo como no inicializado, de modo que una nueva invocación de Pwm_Init resulta admisible.

Diagrama de estados: ciclo de vida del módulo con inicialización, desinicialización y errores ante un orden de llamada incorrecto. El retorno al estado «no inicializado» tras Pwm_DeInit es una interpretación. Fuentes: [SWS_Pwm_00095], [SWS_Pwm_00096], [SWS_Pwm_50002], [SWS_Pwm_20002], [SWS_Pwm_30051], SWS PWM Driver p. 27

Durante el funcionamiento, Pwm_SetDutyCycle establece el ciclo de trabajo de un canal [SWS_Pwm_91000]. Con 0 % y 100 %, la salida se establece de forma estática (SWS PWM Driver p. 28):

  • Al 0 %, el nivel es inverso a la polaridad configurada.
  • Al 100 %, el nivel coincide con la polaridad.
  • Con valores intermedios, se modula según el período, el ciclo de trabajo y la polaridad.

Según el diagrama, el controlador asume el nuevo ciclo de trabajo al final del período en curso si la implementación lo admite; de lo contrario, inmediatamente (SWS PWM Driver p. 37).

Pwm_SetPeriodAndDuty establece conjuntamente el período y el ciclo de trabajo [SWS_Pwm_91001]. En este caso se aplican tres reglas (SWS PWM Driver p. 30):

  • El período se actualiza al final del período si la implementación lo admite y está configurado mediante PwmPeriodUpdatedEndperiod.
  • Deben suprimirse los picos espurios en la salida.
  • El ciclo de trabajo se suministra para que la frecuencia y el ciclo de trabajo concuerden entre sí.

Diagrama de actividades: procesamiento de Pwm_SetDutyCycle y Pwm_SetPeriodAndDuty con comprobación de la clase de canal y tratamiento especial del 0 % y 100 %. Fuentes: [SWS_Pwm_40002], SWS PWM Driver p. 28, SWS PWM Driver p. 30, SWS PWM Driver p. 44

Pwm_SetOutputToIdle establece la salida inmediatamente en el estado idle configurado [SWS_Pwm_91002]. Los canales con período variable se vuelven a activar a continuación mediante Pwm_SetPeriodAndDuty (SWS PWM Driver p. 31). El diagrama «Setting Pwm output to idle» muestra exactamente esta secuencia (SWS PWM Driver p. 50). Pwm_GetOutputState lee el estado de salida interno de forma síncrona como PWM_HIGH o PWM_LOW [SWS_Pwm_00100] [SWS_Pwm_00108]. Un diagrama de la especificación de requisitos ubica el valor leído en la salida de la unidad PWM, es decir, antes de la lógica de puerto y no en el pin físico (RS PWM Driver p. 14).

Diagrama de estados: estados de salida de un canal (modulación, nivel estático, idle) y las API que alternan entre ellos. Fuentes: [SWS_Pwm_91000], [SWS_Pwm_91001], [SWS_Pwm_91002], SWS PWM Driver p. 28, SWS PWM Driver p. 31, SWS PWM Driver p. 46

Notificaciones de flanco por canal

Con Pwm_EnableNotification, el Pwm User habilita la notificación para un canal. El parámetro de tipo Pwm_EdgeNotificationType selecciona PWM_RISING_EDGE, PWM_FALLING_EDGE o PWM_BOTH_EDGES [SWS_Pwm_91004] [SWS_Pwm_00109]. La función descarta las interrupciones pendientes (SWS PWM Driver p. 35). Al igual que Pwm_DisableNotification [SWS_Pwm_91003], solo existe si PwmNotificationSupported está habilitado (SWS PWM Driver p. 34).

El controlador invoca la función configurada Pwm_Notification_<#Channel> de acuerdo con la última llamada a Pwm_EnableNotification o Pwm_DisableNotification. Al hacerlo, restablece el flag de interrupción correspondiente (SWS PWM Driver p. 42). La devolución de llamada no tiene parámetros y se da a conocer a través de Pwm_Externals.h. El hecho de que sea reentrante depende de la implementación del Pwm User [SWS_Pwm_00105].

Diagrama de secuencias: flujo desde la inicialización, pasando por la activación y desactivación de la notificación de flanco, hasta el cese de nuevas devoluciones de llamada. Fuentes: [SWS_Pwm_91004], [SWS_Pwm_91003], [SWS_Pwm_00105], SWS PWM Driver p. 52, SWS PWM Driver p. 42

Estados de potencia de los periféricos PWM

El control de estados de potencia es una función opcional. Se limita a los periféricos PWM y presupone que la aplicación, la gestión de modos y IoHwAb ya cumplen las condiciones marco de nivel superior (SWS PWM Driver p. 17). Si PwmLowPowerStatesSupport está activo, se generan las cuatro API de Power State (SWS PWM Driver p. 16). Pwm_PowerStateType reconoce PWM_FULL_POWER (0x00), así como el rango 1..255 para estados con consumo decreciente. En R20-11, el tipo se define como una enumeración [SWS_Pwm_00197]. Por el contrario, una versión posterior lo presenta como un tipo derivado de uint8 (SWS PWM Driver p. 25).

El cambio de estado de potencia se desarrolla en dos fases:

  1. Pwm_PreparePowerState inicia la preparación y proporciona en el parámetro de resultado PWM_SERVICE_ACCEPTED o un motivo de rechazo [SWS_Pwm_00183] [SWS_Pwm_00165]. Lo que no se pueda concluir de inmediato lo procesa la Pwm_Main_PowerTransitionManager llamada periódicamente [SWS_Pwm_00189] [SWS_Pwm_00190]. Su tasa de invocación es variable y solo envía devoluciones de llamada en modo asíncrono (SWS PWM Driver p. 41). El controlador notifica la preparación completada mediante IoHwAb_Pwm_NotifyReadyForPowerState<#Mode> [SWS_Pwm_00198].
  2. Pwm_SetPowerState sitúa el hardware en el estado preparado [SWS_Pwm_00166]. Los prerrequisitos, tales como establecer todos los canales en IDLE y cancelar todas las notificaciones, deben haber sido cumplidos previamente por los SWC responsables, como IoHwAb. La función no ejecuta estados intermedios implícitos (SWS PWM Driver p. 36).

Diagrama de estados: cambio en dos fases del estado de potencia con preparación, finalización y ajuste, así como los errores de secuencia. Fuentes: [SWS_Pwm_00183], [SWS_Pwm_00166], [SWS_Pwm_00165], [SWS_Pwm_00190], SWS PWM Driver p. 39, SWS IoHwAb p. 61

Pwm_GetCurrentPowerState [SWS_Pwm_00177] devuelve el estado actual y Pwm_GetTargetPowerState [SWS_Pwm_00180] el solicitado. Mientras no se esté ejecutando ninguna transición, ambos coinciden (SWS PWM Driver p. 38). La especificación de IoHwAb muestra la interacción entre BswM, RTE/SchM, IoHwAb, ADC y PWM para el caso asíncrono (SWS IoHwAb p. 60). En el caso síncrono, la preparación ya ha finalizado cuando retorna la API de preparación (SWS IoHwAb p. 61).

Diagrama de secuencias: cambio asíncrono a un estado de bajo consumo, controlado por IoHwAb. La secuencia está simplificada y se ha omitido ADC. Fuentes: [SWS_Pwm_00183], [SWS_Pwm_00189], [SWS_Pwm_00198], [SWS_Pwm_00166], SWS IoHwAb p. 57, SWS IoHwAb p. 60

Configuración, contenedores de canal y concurrencia

Los parámetros obligatorios de un canal son el canal de hardware asignado, los valores predeterminados de período y ciclo de trabajo, la polaridad, el nivel idle y la clase de canal. El desfase de fase, el canal de referencia y las propiedades específicas del microcontrolador son opcionales en la medida en que el hardware los proporcione (SWS PWM Driver p. 25). En el modelo de configuración, PwmChannelConfigSet contiene al menos un PwmChannel y PwmDutycycleDefault está limitado de 0 a 0x8000 (ECUC-Parameter p. 545). PwmChannelClass se asigna a Pwm_ChannelClassType. PwmChannelId se asigna al nombre simbólico del contenedor del canal (SWS PWM Driver p. 57).

Los servicios opcionales se habilitan y deshabilitan mediante configuración: PwmSetOutputToIdle (SWS PWM Driver p. 31), PwmGetOutputState (SWS PWM Driver p. 33), así como los mencionados arriba PwmDeInitApi y PwmNotificationSupported.

Para la concurrencia se aplica lo siguiente:

  • Los servicios de canal como Pwm_SetDutyCycle son reentrantes para números de canal diferentes [SWS_Pwm_91000].
  • Las API de estado de potencia no son reentrantes [SWS_Pwm_00183].
  • El módulo debe rechazar las configuraciones con asignaciones de partición que la implementación no admita [SWS_Pwm_00203].

La guía BSW Distribution Guide explica los niveles de reentrancia, hasta llegar a «multi-core reentrant» (BSW Distribution Guide p. 18).

Comportamiento en caso de error

Si la detección de errores de desarrollo está activa, las funciones notifican los errores detectados al Default Error Tracer. A continuación, omiten la función solicitada para no alterar ni los datos ni los registros de hardware (SWS PWM Driver p. 44). Los códigos de error son [SWS_Pwm_00201]:

  • PWM_E_INIT_FAILED (0x10)
  • PWM_E_UNINIT (0x11) para llamadas previas a la inicialización [SWS_Pwm_20002]
  • PWM_E_PARAM_CHANNEL (0x12) para canales no válidos [SWS_Pwm_30002]
  • PWM_E_PERIOD_UNCHANGEABLE (0x13) para cambios de período en canales con período fijo [SWS_Pwm_40002]
  • PWM_E_ALREADY_INITIALIZED (0x14)
  • PWM_E_PARAM_POINTER (0x15) para un parámetro NULL en Pwm_GetVersionInfo

Pwm_GetOutputState siempre debe devolver un valor. Antes de la inicialización o si el canal no es válido, este es PWM_LOW [SWS_Pwm_30051].

Diagrama de actividades: comprobaciones generales de las API de canal con la detección de errores de desarrollo activa, con cancelación sin efecto. Fuentes: [SWS_Pwm_20002], [SWS_Pwm_30002], [SWS_Pwm_30051], SWS PWM Driver p. 44

Las API de estado de potencia notifican además los errores mediante Std_ReturnType y el tipo de resultado Pwm_PowerStateRequestResultType. Los posibles valores son PWM_NOT_INIT, PWM_SEQUENCE_ERROR, PWM_HW_FAILURE, PWM_POWER_STATE_NOT_SUPP y PWM_TRANS_NOT_POSSIBLE [SWS_Pwm_00165]. Para un estado no admitido se define además PWM_E_POWER_STATE_NOT_SUPPORTED [SWS_Pwm_00174], y para un estado no alcanzable directamente, PWM_E_TRANSITION_NOT_POSSIBLE [SWS_Pwm_00175].

Si se invoca Pwm_SetPowerState mientras todavía hay canales fuera de IDLE o hay notificaciones registradas, se produce el error de tiempo de ejecución PWM_E_NOT_DISENGAGED (0x16) [SWS_Pwm_00202] (SWS PWM Driver p. 20). Pwm_Main_PowerTransitionManager simplemente retorna sin inicializar y no notifica deliberadamente ningún error de desarrollo. El motivo: las tareas periódicas pueden ejecutarse incluso antes de finalizar la inicialización (SWS PWM Driver p. 41).

función Pwm_Init [SWS_Pwm_00095] 📄 PDF

void Pwm_Init (const Pwm_ConfigType* ConfigPtr);

servicio para PWM inicialización.

La función síncrona Pwm_Init sirve como servicio central para la inicialización de todo el controlador PWM ([SWS_Pwm_00095]).   • Rango de valores 1..255: define modos de potencia escalonados con consumo de energía decreciente gradualmente («power modes with decreasing power consumptions») [SWS_Pwm_00197].

En cuanto al contexto de uso, es de prever que el tipo funcione como parámetro de transferencia al solicitar un modo de bajo consumo, así como valor de retorno en consultas de estado, dado que el tipo representa tanto estados activos como de destino [SWS_Pwm_00197].
