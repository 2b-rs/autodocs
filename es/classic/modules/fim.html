tipo FiM_ConfigType [SWS_Fim_00092] 📄 PDF

This type defines a data structure for the post build parameters of the FIM. At initialization the FIM gets a pointer to a structure of this type to get access to its configuration data, which is necessary for initializsation.

requirement SWS_Fim_00002 [SWS_Fim_00002] 📄 PDF

The configuration process shall guarantee that FunctionIds are unique per FiM. Two distinct functionalities with different dependencies on events shall never have the same FunctionId (see also [SWS_Fim_00007]).

requirement SWS_Fim_00003 [SWS_Fim_00003] 📄 PDF

The FiM module's environment shall use the FunctionId to directly point to the associated functionality information (permission status etc.)

requirement SWS_Fim_00007 [SWS_Fim_00007] 📄 PDF

FID numbers shall be unique per FiM.

requirement SWS_Fim_00008 [SWS_Fim_00008] 📄 PDF

The FiM module shall provide the possibility to modify the inhibit conditions by post-built configuration.

requirement SWS_Fim_00009 [SWS_Fim_00009] 📄 PDF

If the implementation uses status variables for the permission of the FIDs, the status variables shall be readable for tracking purposes by the calibra- tion system (to be defined by AUTOSAR) during the development phase of the ECU.

requirement SWS_Fim_00010 [SWS_Fim_00010] 📄 PDF

The flow of information starts with the API call of the Dem provid- ing changes of the event information. This information is processed and dependencies to FIDs are evaluated. Finally, the permission state of the FIDs is accessed via API through the RTE (Figure 7.1).

requirement SWS_Fim_00012 [SWS_Fim_00012] 📄 PDF

The FiM module shall calculate the inhibit status based on the actual status of the inhibit source and the calibrated mask which exists for each inhibit source (ref. 10.2.7). The FiM module shall inhibit the FID if the Monitor status is equal to the calibrated mask (=Defect, Tested, NotTested). The inhibition is deactivated if the mask of the event does not match anymore the calibrated value.

requirement SWS_Fim_00013 [SWS_Fim_00013] 📄 PDF

The configuration process of the FiM shall create data structures within the FiM module to store the inhibit relations (EventID - FID - applicable mask).

requirement SWS_Fim_00015 [SWS_Fim_00015] 📄 PDF

The FID permission state contains the information whether a functionality represented by its FID can be executed. If the permission state == TRUE, the functionality associated with the FID is permitted to be executed. If the permis- sion state == FALSE, the functionality associated with the FID is not allowed to be executed.

requirement SWS_Fim_00016 [SWS_Fim_00016] 📄 PDF

The configuration engineer shall provide at compile time the in- hibit conditions for each FID required for handling the dependencies of functionalities and events in the FiM module.

requirement SWS_Fim_00018 [SWS_Fim_00018] 📄 PDF

If Dem events status information is used, the FiM module shall compute the permission states for all FIDs at its initialization based on all restored monitor status information (not only events stored in the fault memory) of the Dem.

requirement SWS_Fim_00020 [SWS_Fim_00020] 📄 PDF

The FiM module shall ensure an immediate control of functionality by synchronously responding to an incoming permission query. The FiM module shall realize this behavior either by storing the permission state as a status variable or by evaluation of the event states upon permission query.

requirement SWS_Fim_00022 [SWS_Fim_00022] 📄 PDF

The purpose of the FiM module is to provide services to control (permit / inhibit) functionality within SW-Cs based on Dem events being supported as inhibit conditions.

requirement SWS_Fim_00025 [SWS_Fim_00025] 📄 PDF

The function FiM_GetFunctionPermission shall deliver the return value synchronously to enable direct use of this information for controlling and executing the underlying code in the software component.

requirement SWS_Fim_00043 [SWS_Fim_00043] 📄 PDF

The FiM shall compute the permission of a FID independently of the state of other FIDs.

requirement SWS_Fim_00044 [SWS_Fim_00044] 📄 PDF

The AUTOSAR Function Inhibition Manager (FiM) has inter- faces and dependencies on the Diagnostic Event Manager (Dem), the Software Com- ponents (SW-C) with FID interface, the ECU State Manager, the RTE and the BSW modules supposed to be inhibited by the FiM.

requirement SWS_Fim_00045 [SWS_Fim_00045] 📄 PDF

If development error detection is turned on the FiM module shall report an error to the DET if it has not successfully completed the initialization and has detected not permitted access.

requirement SWS_Fim_00055 [SWS_Fim_00055] 📄 PDF

If development error detection for the module FiM is enabled: the function FiM_GetFunctionPermission shall perform a plausibility check on the FID range. If a FID is out of range, the function shall raise a development error and return no permission (FALSE).

requirement SWS_Fim_00056 [SWS_Fim_00056] 📄 PDF

If development error detection for the module FiM is enabled: the function FiM_GetFunctionPermission shall check that the initialization of the module FiM has been completed. If the function detects that the initialization is not complete, it shall raise a development error and return no permission (FALSE).

requirement SWS_Fim_00057 [SWS_Fim_00057] 📄 PDF

If development error detection for the module FiM is enabled: the function FiM_DemTriggerOnMonitorStatus shall perform a plausibility check on the EventId. If the requested EventId is not existing in the Dem configuration, the function shall raise the development error FIM_E_EVENTID_OUT_OF_RANGE .

requirement SWS_Fim_00058 [SWS_Fim_00058] 📄 PDF

If development error detection for the module FiM is enabled: The function FiM_DemTriggerOnMonitorStatus shall check for complete initialization of the FiM. If the function detects that the initialization is not complete, it shall raise a development error.

requirement SWS_Fim_00059 [SWS_Fim_00059] 📄 PDF

A static status variable denoting if the FiM is initialized shall be initialized with value 0 before any APIs of the FiM is called. FiM_Init shall set the static status variable to a value not equal to 0.

requirement SWS_Fim_00061 [SWS_Fim_00061] 📄 PDF

The FiM configuration shall support summarizing events. A sum- marized event consists of multiple single diagnostic events.

requirement SWS_Fim_00062 [SWS_Fim_00062] 📄 PDF

Figure 10.1: FiM configuration

requirement SWS_Fim_00064 [SWS_Fim_00064] 📄 PDF

The FiM shall also be able to process the inhibit conditions of all FIDs associated to one summarized event if one of the Dem Events associated to this summarized event is reported to the FiM.

requirement SWS_Fim_00065 [SWS_Fim_00065] 📄 PDF

The Function Inhibition Manager shall use the FID - EventIDs - inhibition masks relations provided by the software components to determine the permission state for all configured FIDs.

requirement SWS_Fim_00066 [SWS_Fim_00066] 📄 PDF

The SW Components and the BSW shall use the function FiM_- GetFunctionPermission to query for the permission to execute a certain function- ality represented by the respective FID.

requirement SWS_Fim_00067 [SWS_Fim_00067] 📄 PDF

The FiM shall perform the evaluation of actual EventIds status in- formation cyclically for all the EventIds using the inhibition mask and then calculate the corresponding FID permission states. FiM shall access the monitor status information using the API Dem_GetMonitorStatus if Dem and FiM are implemented as sepa- rate modules. FiM shall access the monitor status structure of Dem if Dem and FiM are implemented as a bundle.

requirement SWS_Fim_00069 [SWS_Fim_00069] 📄 PDF

The function FiM_DemInit shall compute the permission state for all FIDs.

requirement SWS_Fim_00070 [SWS_Fim_00070] 📄 PDF

If FiM module polls monitor status (as defined in configuration parameter FiMEventUpdateTriggeredByDem = FALSE) and decides to do it in a cyclic manner, FiM_MainFunction shall be used to calculate the permission states of all EventIds using their inhibition masks. The API Dem_GetMonitorStatus shall be used to get status information of EventIds.

requirement SWS_Fim_00076 [SWS_Fim_00076] 📄 PDF

FIM_E_PARAM_POINTER 0x04 Invalid configuration set selection FIM_E_INIT_FAILED 0x05

requirement SWS_Fim_00082 [SWS_Fim_00082] 📄 PDF

The function FiM_DemInit shall access the EventId states via the function Dem_GetMonitorStatus and the component information via Dem_Get- ComponentFailed .

requirement SWS_Fim_00090 [SWS_Fim_00090] 📄 PDF

requirement SWS_Fim_00094 [SWS_Fim_00094] 📄 PDF

A client can query the FiM for execution permission for a specific function. The FIDs which represent the functions are not directly used by the client SW-C. Instead, the mechanism of "port-defined argument values" is used and every FID is mapped to a separate port that is responsible for the data exchange via RTE. Type FiM_FunctionIdType Port Defined Argument Value(s) Value {ecuc(FiM/FiMConfigSet/FiMFID/FiMFunctionId.value)} Variation Name = {ecuc(FiM/FiMConfigSet/FiMFID.SHORT-NAME)}

requirement SWS_Fim_00097 [SWS_Fim_00097] 📄 PDF

If Dem_GetMonitorStatus returns E_NOT_OK, the FIM shall not consider this event in its inhibition mask calculation

requirement SWS_Fim_00098 [SWS_Fim_00098] 📄 PDF

The Function Inhibition Manager shall use the FID - DemCom- ponentId - inhibition configuration to determine the permission state for the configured FID. Upon changes of the FAILED status of a DemComponent , the function status shall be recalculated. Whenever the component status is FAILED ( ComponentFailedStatus = TRUE), the FID is inhibited.

requirement SWS_Fim_00099 [SWS_Fim_00099] 📄 PDF

If the FIM is configured for cyclically polling the status, the FIM shall use the API Dem_GetComponentFailed to get the current FAILED status of a component.

requirement SWS_Fim_00100 [SWS_Fim_00100] 📄 PDF

If the FIM is configured for being triggered on eventStatus (Fi MCyclicEventEvaluation), the FIM shall accept the status changed information of a DemComponent by providing the function FiM_DemTriggerOnComponentStatus .

requirement SWS_Fim_00102 [SWS_Fim_00102] 📄 PDF

The initialization of Dem and Fim shall always follow the below order : step 0) Dem_PreInit step 1) Non-volatile memory data has to be available. step 2) FiM_Init (setting up internal variables); after FiM_Init , the Fim is not yet ready to be used. step 3) Dem_Init : do the internal DEM initialization and use FiM_DemInit to finally initialize the FIM

requirement SWS_Fim_00104 [SWS_Fim_00104] 📄 PDF

If FiM_GetFunctionPermission is called before the FiM is initialized, the FiM shall return E_NOT_OK.( FiM_DemInit ).

requirement SWS_Fim_00105 [SWS_Fim_00105] 📄 PDF

If a function (FID) is set to not available using the interface FiM_SetFunctionAvailable , its permission state FiM_GetFunctionPermis- sion shall always return FALSE

SWS_Fim_00002 requirement

The configuration process shall guarantee that FunctionIds are unique per FiM. Two distinct functionalities with different dependencies on events shall never have the same FunctionId (see also [SWS_Fim_00007]).

SWS_Fim_00003 requirement

The FiM module's environment shall use the FunctionId to directly point to the associated functionality information (permission status etc.)

SWS_Fim_00007 requirement

FID numbers shall be unique per FiM.

SWS_Fim_00008 requirement

The FiM module shall provide the possibility to modify the inhibit conditions by post-built configuration.

SWS_Fim_00009 requirement

If the implementation uses status variables for the permission of the FIDs, the status variables shall be readable for tracking purposes by the calibra- tion system (to be defined by AUTOSAR) during the development phase of the ECU.

SWS_Fim_00010 requirement

The flow of information starts with the API call of the Dem provid- ing changes of the event information. This information is processed and dependencies to FIDs are evaluated. Finally, the permission state of the FIDs is accessed via API through the RTE (Figure 7.1).

SWS_Fim_00012 requirement

The FiM module shall calculate the inhibit status based on the actual status of the inhibit source and the calibrated mask which exists for each inhibit source (ref. 10.2.7). The FiM module shall inhibit the FID if the Monitor status is equal to the calibrated mask (=Defect, Tested, NotTested). The inhibition is deactivated if the mask of the event does not match anymore the calibrated value.

SWS_Fim_00013 requirement

The configuration process of the FiM shall create data structures within the FiM module to store the inhibit relations (EventID - FID - applicable mask).

SWS_Fim_00015 requirement

The FID permission state contains the information whether a functionality represented by its FID can be executed. If the permission state == TRUE, the functionality associated with the FID is permitted to be executed. If the permis- sion state == FALSE, the functionality associated with the FID is not allowed to be executed.

SWS_Fim_00016 requirement

The configuration engineer shall provide at compile time the in- hibit conditions for each FID required for handling the dependencies of functionalities and events in the FiM module.

SWS_Fim_00018 requirement

If Dem events status information is used, the FiM module shall compute the permission states for all FIDs at its initialization based on all restored monitor status information (not only events stored in the fault memory) of the Dem.

SWS_Fim_00020 requirement

The FiM module shall ensure an immediate control of functionality by synchronously responding to an incoming permission query. The FiM module shall realize this behavior either by storing the permission state as a status variable or by evaluation of the event states upon permission query.

SWS_Fim_00022 requirement

The purpose of the FiM module is to provide services to control (permit / inhibit) functionality within SW-Cs based on Dem events being supported as inhibit conditions.

SWS_Fim_00025 requirement

The function FiM_GetFunctionPermission shall deliver the return value synchronously to enable direct use of this information for controlling and executing the underlying code in the software component.

SWS_Fim_00043 requirement

The FiM shall compute the permission of a FID independently of the state of other FIDs.

SWS_Fim_00044 requirement

The AUTOSAR Function Inhibition Manager (FiM) has inter- faces and dependencies on the Diagnostic Event Manager (Dem), the Software Com- ponents (SW-C) with FID interface, the ECU State Manager, the RTE and the BSW modules supposed to be inhibited by the FiM.

SWS_Fim_00045 requirement

If development error detection is turned on the FiM module shall report an error to the DET if it has not successfully completed the initialization and has detected not permitted access.

SWS_Fim_00055 requirement

If development error detection for the module FiM is enabled: the function FiM_GetFunctionPermission shall perform a plausibility check on the FID range. If a FID is out of range, the function shall raise a development error and return no permission (FALSE).

SWS_Fim_00056 requirement

If development error detection for the module FiM is enabled: the function FiM_GetFunctionPermission shall check that the initialization of the module FiM has been completed. If the function detects that the initialization is not complete, it shall raise a development error and return no permission (FALSE).

SWS_Fim_00057 requirement

If development error detection for the module FiM is enabled: the function FiM_DemTriggerOnMonitorStatus shall perform a plausibility check on the EventId. If the requested EventId is not existing in the Dem configuration, the function shall raise the development error FIM_E_EVENTID_OUT_OF_RANGE .

SWS_Fim_00058 requirement

If development error detection for the module FiM is enabled: The function FiM_DemTriggerOnMonitorStatus shall check for complete initialization of the FiM. If the function detects that the initialization is not complete, it shall raise a development error.

A static status variable denoting if the FiM is initialized shall be initialized with value 0 before any APIs of the FiM is called. FiM_Init shall set the static status variable to a value not equal to 0.
