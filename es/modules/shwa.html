Clasificación y finalidad

Safe Hardware Acceleration proporciona mecanismos para permitir que las aplicaciones adaptables ejecuten tareas paralelas en el hardware disponible. La arquitectura permite la combinación de Queue, dispositivos y Buffer; otros Functional Cluster también pueden usar la API SWS SHWA §7.1 «The Architecture of Safe Hardware Acceleration».

Datos, acceso y almacenamiento.

Buffer gestiona la asignación de memoria, mientras que Accessor expresa acceso de lectura/escritura escrito. Los modos de acceso y el enlace a una tarea Handler proporcionan al sistema de ejecución información para el movimiento y la sincronización de datos SWS SHWA §7.3 «Data Access Specifics» SWS SHWA §7.5 «Memory Allocation Specifics». El documento EXP adjunto agrupa Buffer, Accessor, Rango e Id como almacenamiento y gestión de datos EXP Safe Hardware Acceleration API §4.3.1.

Selección, ejecución y sincronización de dispositivos.

Dispositivo representa un dispositivo informático; Las clases de selector eligen dispositivos CPU, GPU o acelerador a través de clasificaciones. La cola pasa tareas y Event admite las dependencias u operaciones de espera en caso de ejecución fuera de orden SWS SHWA §7.4 «Device Specifics» SWS SHWA §7.6 «Task Queuing And Ordering Specifics».

Interpretación: Una ruta de aplicación sólida generalmente consiste en la selección de dispositivos, la creación de colas/controladores de errores, la creación de buffers/accesores, el envío de tareas y la sincronización adecuada basada en eventos o tiempos de espera. Este orden resume los conceptos individuales descritos.

La API no tiene excepciones; las operaciones con fallas usan ara::core::Result, mientras que los métodos de fábrica permiten el transporte de fallas durante la creación de objetos.
