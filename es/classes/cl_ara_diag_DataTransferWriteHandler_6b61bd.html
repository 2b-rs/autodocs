Procesa y almacena en la aplicación bloques de datos entrantes en transferencias de archivos de escritura.

La clase ara::diag::DataTransferWriteHandler sirve en AUTOSAR Adaptive para el procesamiento, por parte de la aplicación, de transferencias de archivos de escritura iniciadas por RequestWriteFile en los modos AddFile, ResumeFile o ReplaceFile [SWS_DM_01539]. Los paquetes de datos entrantes se escriben asíncronamente en la memoria mediante Write() y la sesión se finaliza a continuación mediante ExitWrite(). Una instancia está estrictamente vinculada a una única sesión de transferencia y bajo ninguna circunstancia debe destruirse antes de la invocación de ExitWrite() [SWS_DM_01541].

Contexto

La clase base abstracta ara::diag::DataTransferWriteHandler define en AUTOSAR Adaptive Platform la interfaz para transferencias de archivos de escritura [SWS_DM_01539] (AUTOSAR_AP_SWS_Diagnostics §8.10.6 «Class: DataTransferWriteHandler»). Sirve para el procesamiento del lado de la aplicación de transferencias de datos iniciadas en el marco de RequestWriteFile mediante los modos de funcionamiento AddFile, ResumeFile o ReplaceFile.

Dentro de la arquitectura de diagnóstico, el manejador interactúa con el cliente UDS externo, el middleware de diagnóstico y la aplicación. El cliente transmite bloques de datos segmentados que son recibidos por una implementación derivada del manejador y almacenados en la memoria de la aplicación [SWS_DM_01546]. Presumiblemente, Diagnostic Management de la plataforma asume en este proceso la coordinación del protocolo UDS y reenvía los datos útiles a la aplicación de destino a través de la interfaz del manejador.

Ciclo de vida

La instanciación de ara::diag::DataTransferWriteHandler se realiza exclusivamente mediante subclases especializadas de la aplicación: el constructor sin parámetros está definido con protected y noexcept=default [SWS_DM_01540], lo que impide la instanciación directa de la clase base. Una instancia del manejador está vinculada estrictamente a una única sesión de transferencia de archivos («one way usage i.e. per single file transfer session»). Por este motivo, el constructor de copia [SWS_DM_01544] (AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.2.1 «DataTransferWriteHandler») y el operador de asignación por copia [SWS_DM_01545] están eliminados (=delete).

Las operaciones de movimiento, en cambio, están permitidas: tanto el constructor de movimiento [SWS_DM_01542] (AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.1 «Move Constructor») como el operador de asignación por movimiento [SWS_DM_01543] están implementados con noexcept=default y se consideran seguros frente a excepciones (exception safe).

Para la destrucción de la instancia rige una precondición vinculante: bajo ninguna circunstancia debe destruirse una instancia de esta clase antes de haber invocado el método ExitWrite() [SWS_DM_01541] (AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.2 «Destructor»). El destructor virtual ~DataTransferWriteHandler() solo debe invocarse tras la ejecución completa de ExitWrite(). Las funciones miembro y el destructor están especificados como no seguros para subprocesos (not thread-safe) [SWS_DM_01541], [SWS_DM_01546], [SWS_DM_01547].

Diagrama de estados: ciclo de vida y secuencia de llamadas de una instancia de DataTransferWriteHandler. Fuentes: [SWS_DM_01541], [SWS_DM_01544].

Ruta de uso

El flujo regular de una transferencia de escritura comprende la recepción paso a paso de bloques de datos y la posterior finalización de la sesión:

  • Para cada segmento de datos entrante, el sistema de diagnóstico invoca el método virtual puro Write() [SWS_DM_01546] (AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.2 «Write»). Los datos se transfieren como ara::core::Span<ara::core::Byte>. La validez de esta área de memoria se mantiene hasta que se cumpla el Promise asociado o se cancele la operación. La aplicación añade los datos al búfer interno y devuelve un ara::core::Future<void>.
  • Una vez transferidos todos los segmentos, la plataforma invoca el método virtual puro ExitWrite() [SWS_DM_01547] (AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.1 «ExitWrite»). Se transfieren el motivo de finalización (DataTransferExitType), parámetros específicos del fabricante del vehículo (transferRequestParameterRecord), metaInfo, así como un CancellationHandler.
  • El método ExitWrite() devuelve un ara::core::Future<ara::core::Vector<ara::core::Byte>>. En caso de finalización correcta, los datos contenidos en él se insertan como transferResponseParameterRecord detrás del identificador de servicio en el mensaje de respuesta positiva de UDS [SWS_DM_01547].

Diagrama de secuencia: secuencia de llamadas de operaciones Write y ExitWrite durante una sesión de transferencia. Fuentes: [SWS_DM_01546], [SWS_DM_01547].

Escenarios de error

Los errores durante el procesamiento de datos y la transferencia se gestionan mediante valores de retorno y mecanismos de cancelación estandarizados:

  • Si falla la escritura de un bloque de datos o la finalización de la transferencia, se proporciona el Future respectivo con un ara::core::ErrorCode de DiagUdsNrcErrc [SWS_DM_01546], [SWS_DM_01547]. Esto da lugar a la generación de una respuesta negativa de UDS correspondiente (NRC conforme a ISO 14229-1) hacia el cliente.
  • Ambos métodos proporcionan un CancellationHandler. La aplicación puede verificar a través de cancellationHandler.IsCanceled() si la conversación se ha cancelado, o registrar mediante cancellationHandler.SetNotifier() una función de notificación que se ejecutará en caso de cancelación de la conversación [SWS_DM_01546], [SWS_DM_01547].
  • Si la instancia se destruye antes de invocar ExitWrite(), se produce una infracción de la regla especificada para el ciclo de vida [SWS_DM_01541], lo que presumiblemente conduce a un estado indefinido del sistema y a archivos incompletos. Además, un acceso concurrente no protegido provoca inconsistencias de datos, ya que la interfaz explícitamente no es segura para subprocesos.

En cuanto al ciclo de vida del objeto, existe una condición estricta de orden: una instancia de la clase de controlador solo debe destruirse después de haber llamado a ExitWrite() [SWS_DM_01541].

  Procedencia
  

                  

                  

                  El método Write de la interfaz ara::diag::DataTransferWriteHandler sirve para anexar bloques de datos recibidos al área de memoria de la aplicación durante una transferencia de archivos UDS [SWS_DM_01546]. La llamada la realiza la instancia del Diagnostic Server cuando se recibe una solicitud UDS TransferData (0x36) en el marco de una operación iniciada mediante RequestFileTransfer (0x38) [SWS_DM_01317].
                  

                  Parámetros y semántica
                  

                  Los contenidos del archivo que se van a escribir se pasan mediante requestData como ara::core::Span<ara::core::Byte>; el búfer referenciado permanece válido hasta que se cumple la promise asociada o se cancela el procesamiento [SWS_DM_01546]. El parámetro metaInfo proporciona metainformación de la solicitud de diagnóstico. A través de cancellationHandler se puede comprobar el estado de cancelación actual mediante IsCanceled o registrar un callback de notificación mediante SetNotifier [SWS_DM_01546].
                  

                  Tratamiento de errores y concurrencia
                  

                  El resultado se devuelve de forma asíncrona como ara::core::Future<void>. En caso de éxito, el future se completa vacío; en caso de errores, debe completarse con un Negative Response Code (NRC) adecuado de DiagUdsNrcErrc conforme a ISO 14229-1 [SWS_DM_01546]. La función está especificada como exception safe, pero expresamente como not thread-safe [SWS_DM_01546]; por lo tanto, es probable que el Diagnostic Server garantice llamadas secuenciales para la misma sesión.
                  

                  Interacción y secuencia
                  

                  El gestor de escritura se registra mediante constructores de plantilla dentro de DataTransferWriteSession [SWS_DM_01317]. Tan pronto como la transferencia concluye con RequestTransferExit (0x37), el servidor llama al método Exit del mismo gestor [SWS_DM_01318]. El elemento se diferencia de los métodos de escritura relacionados con DID, tal como están definidos en [SWS_DM_00598] o [SWS_DM_00637].
