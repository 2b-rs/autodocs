Proporciona una interfaz para el cifrado y descifrado simétrico autenticado con protección de integridad.

La interfaz ara::crypto::cryp::AuthCipherCtx sirve para el cifrado y descifrado autenticado de datos preservando la confidencialidad y la integridad [SWS_CRYPT_23911]. Tras configurar la clave, el procesamiento se realiza bien como una llamada única atómica o bien como una secuencia transmitida por flujo que consta de inicialización, datos de autenticación opcionales, actualizaciones de datos útiles y finalización. Como condición de seguridad crítica, el descifrado falla ante una etiqueta de autenticación no válida, de modo que los datos útiles descifrados solo deben procesarse tras una validación correcta [SWS_CRYPT_50075].

Contexto

La interfaz ara::crypto::cryp::AuthCipherCtx define la interfaz de programación estandarizada para operaciones de cifrado autenticado (Authenticated Encryption with Associated Data, AEAD) dentro de la AUTOSAR Adaptive Platform. Combina confidencialidad con protección de integridad, ya que, además del cifrado o descifrado real de los datos útiles, siempre se genera o valida una etiqueta de autenticación criptográfica. Actúan como interlocutores centrales las aplicaciones llamadoras y los objetos de clave: antes de su uso, un contexto se vincula a una instancia concreta de SymmetricKey [SWS_CRYPT_23911] o bien se configura con un KeySlot persistido o provisto [SWS_CRYPT_50072]. Además del procesamiento escalonado por flujo, la clase también admite llamadas únicas autosuficientes para procesar mensajes completos en un solo paso [SWS_CRYPT_50078].

Ciclo de vida

Los contextos se gestionan en el ámbito de la aplicación a través del tipo de puntero compartido ara::crypto::cryp::AuthCipherCtx::Sptr [SWS_CRYPT_20101]. (Interpretación: la creación de objetos se realiza normalmente a través de una fábrica de proveedores superior, ya que AuthCipherCtx está especificada como una interfaz pura). Todas las funciones miembro están declaradas como seguras contra excepciones (exception safe) y seguras para subprocesos (thread-safe) [SWS_CRYPT_23911], [SWS_CRYPT_24715]. El ciclo de vida funcional atraviesa estados claramente definidos:

  • No inicializado: inmediatamente después de la instanciación. Las llamadas para el procesamiento de datos se rechazan, ya que todavía no se ha asignado ninguna clave [SWS_CRYPT_50081].
  • Clave configurada: mediante la llamada exitosa a SetKey con un SymmetricKey [SWS_CRYPT_23911] o un KeySlot [SWS_CRYPT_50072], el contexto pasa al estado operativo. Desde este estado se pueden ejecutar directamente operaciones de disparo único.
  • Flujo activo: se accede mediante la llamada a Start especificando la dirección de transformación con vector de inicialización (IV) [SWS_CRYPT_24715] o sin IV explícito [SWS_CRYPT_50073].
  • Finalización / restablecimiento: una operación de flujo en curso se finaliza de forma regular mediante Finish [SWS_CRYPT_50075] o FinishEncrypt [SWS_CRYPT_50076], o bien se cancela prematuramente mediante Cancel [SWS_CRYPT_50077]. A continuación, el contexto vuelve a estar listo para nuevas secuencias de procesamiento.

Diagrama de estados: fases de estado del contexto desde la vinculación de claves hasta la finalización, pasando por el procesamiento de flujo. Fuentes: [SWS_CRYPT_23911], [SWS_CRYPT_50072], [SWS_CRYPT_24715], [SWS_CRYPT_50075], [SWS_CRYPT_50077].

Ruta de uso

Para el procesamiento continuo del flujo de datos, la interfaz requiere una secuencia ordenada de llamadas:

  1. Configuración: asignación de la clave mediante SetKey [SWS_CRYPT_23911] o SetKey con KeySlot [SWS_CRYPT_50072].
  2. Consulta de parámetros: determinación opcional de valores límite y tamaños de búfer mediante GetMinimumChunkSize [SWS_CRYPT_50162], GetMaximumChunkSize [SWS_CRYPT_50082], GetMinimumInputIvSize [SWS_CRYPT_50163], GetMaximumInputIvSize [SWS_CRYPT_50164], GetTagSize [SWS_CRYPT_50161] así como GetRequiredOutputBufferSize [SWS_CRYPT_50081].
  3. Inicio de la operación: invocación de Start especificando la dirección (cifrado o descifrado) así como proporcionando el IV [SWS_CRYPT_24715] o solicitando un IV propio del contexto [SWS_CRYPT_50073].
  4. Datos asociados (AAD): si deben incluirse datos adicionales en texto claro en el cálculo de integridad, estos se transmiten mediante UpdateAuthenticatedData [SWS_CRYPT_20313]. El tamaño máximo admisible de AAD se puede consultar mediante GetMaxAssociatedDataSize [SWS_CRYPT_20103]. Importante: los bloques AAD deben transmitirse obligatoriamente antes de los datos útiles propiamente dichos.
  5. Procesamiento de datos útiles: transferencia paso a paso de bloques de datos mediante UpdateConfidentialData [SWS_CRYPT_50074]. En el descifrado, el texto claro se devuelve antes de que se haya establecido su autenticidad; la aplicación solo debe utilizar estos datos tras una finalización correcta.
  6. Finalización: conclusión de la operación mediante Finish [SWS_CRYPT_50075] o FinishEncrypt [SWS_CRYPT_50076], con lo cual se procesa el bloque final y se calcula o verifica la etiqueta de autenticación.

Para cargas útiles compactas existen alternativas de llamada única (single-call): ProcessSingleCall procesa datos sin transferencia de IV [SWS_CRYPT_50078], ProcessSingleCallWithInputIv acepta un IV externo [SWS_CRYPT_50079], y EncryptSingleCallWithOutputIv devuelve al llamador un IV generado por el contexto [SWS_CRYPT_50080].

Diagrama de secuencia: secuencia de invocación de un cifrado autenticado en streaming. Fuentes: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Escenarios de error

Los métodos de AuthCipherCtx devuelven resultados mediante ara::core::Result y poseen semántica de reversión (rollback) en caso de error. Los códigos de error relevantes de ara::crypto::CryptoErrc son:

  • kUninitializedContext: se produce al invocar Start [SWS_CRYPT_24715], ProcessSingleCall [SWS_CRYPT_50078] o cálculos de búfer [SWS_CRYPT_50081] si aún no se ha configurado ninguna clave mediante SetKey.
  • kProcessingNotStarted: se notifica cuando se invocan UpdateAuthenticatedData [SWS_CRYPT_20313], UpdateConfidentialData [SWS_CRYPT_50074], Finish [SWS_CRYPT_50075] o Cancel [SWS_CRYPT_50077] sin un Start previo.
  • kInvalidUsageOrder: señala un orden de invocación erróneo cuando se invoca UpdateAuthenticatedData después de haber procesado ya datos útiles mediante UpdateConfidentialData [SWS_CRYPT_20313].
  • kAuthTagNotValid: indica en el descifrado en Finish [SWS_CRYPT_50075] o en métodos single-shot [SWS_CRYPT_50078] que la etiqueta calculada no coincide con la etiqueta proporcionada y que la comprobación de autenticidad ha fallado.
  • kUsageViolation: se produce cuando los atributos de uso de la clave no se corresponden con la operación solicitada (p. ej., falta de kAllowDataEncrypt o kAllowDataDecrypt) [SWS_CRYPT_23911], [SWS_CRYPT_50078].
  • kInsufficientCapacity / kInvalidInputSize: señalan búferes de salida dimensionados insuficientemente o longitudes no admisibles de entrada, IV o etiqueta [SWS_CRYPT_24715], [SWS_CRYPT_50074], [SWS_CRYPT_50075].
  • kEmptyKeySlot / kBusyResource: conciernen a estados de error al utilizar posiciones de almacenamiento de clave configuradas [SWS_CRYPT_24715], [SWS_CRYPT_50078].

Esta guía se basa exclusivamente en el estándar AUTOSAR Adaptive (Release R25-11) y resume los requisitos para la interfaz ara::crypto::cryp::AuthCipherCtx.

usar

El método Cancel() de la interfaz ara::crypto::cryp::AuthCipherCtx cancela una operación de streaming activa que se inició previamente mediante Start() y aún no ha concluido [SWS_CRYPT_50077]. La función se proporciona a través de la cabecera ara/crypto/cryp/auth_cipher_ctx.h y opera sincrónicamente sin parámetros de entrada [SWS_CRYPT_50077]. Devuelve un ara::core::Result<void>, que está vacío en caso de éxito.

Tratamiento de errores y condiciones límite

Una cancelación presupone que el procesamiento de datos se haya iniciado efectivamente con anterioridad mediante Start(). Si la operación de streaming no se inició, la llamada falla y devuelve el código de error ara::crypto::CryptoErrc::kProcessingNotStarted con semántica de reversión [SWS_CRYPT_50077].

concurrencia

La operación está declarada como noexcept y, según la especificación, está clasificada tanto como thread-safe como exception safe [SWS_CRYPT_50077].

Interacción

El patrón de cancelación implementado por Cancel() está estandarizado en el módulo crypt. Se han definido una semántica de interfaz idéntica y el mismo código de error ara::crypto::CryptoErrc::kProcessingNotStarted para los contextos de streaming correspondientes:

      El método síncrono EncryptSingleCallWithOutputIv de la interfaz ara::crypto::cryp::AuthCipherCtx ejecuta un cifrado autenticado en un solo paso y genera de forma autónoma un vector de inicialización [SWS_CRYPT_50080]. Procesa datos de entrada de dataIn así como datos adicionales opcionales authenticatedData y escribe el criptograma en el búfer dataOut. El vector de inicialización generado se almacena en el búfer ivOut, mientras que la etiqueta de autenticación se emite a través de tag [SWS_CRYPT_50080]. El tamaño de búfer para ivOut se puede determinar previamente mediante el método GetOutputIvSize [SWS_CRYPT_50165]. A pesar del componente del nombre Encrypt, es de suponer que el método probablemente también se pueda utilizar para el descifrado, ya que la especificación de errores detalla explícitamente el comportamiento para transformDirection == kDecrypt [SWS_CRYPT_50080].
      

      Para la llamada se aplican condiciones previas y restricciones esenciales:
      

        

      • El contexto debe haberse inicializado previamente con éxito mediante SetKey; de lo contrario, se notifica kUninitializedContext [SWS_CRYPT_50080].
        • 

      • La clave en el Key-Slot configurado debe ser compatible y presentar el permiso adecuado (p. ej., kAllowDataEncrypt); de lo contrario, se devuelve kUsageViolation o kIncompatibleObject [SWS_CRYPT_50080].
        • 

      • Si los búferes de salida dataOut o ivOut no son suficientes, la llamada falla con kInsufficientCapacity [SWS_CRYPT_50080].
        • 

      • Si el contexto no soporta el procesamiento en un solo paso o requiere una especificación externa de IV, se devuelve kUnsupported [SWS_CRYPT_50080].
        • 

      

      La operación está especificada como thread-safe así como segura frente a excepciones y garantiza semántica de reversión en caso de error [SWS_CRYPT_50080]. Para cifrados simétricos puros sin procesamiento de etiquetas existe un homólogo independiente en SymmetricCipherCtx [SWS_CRYPT_50049].
