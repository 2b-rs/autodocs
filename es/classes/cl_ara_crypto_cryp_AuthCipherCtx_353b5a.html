Contexto

La interfaz ara::crypto::cryp::AuthCipherCtx define el contexto para operaciones criptográficas con cifrado autenticado (Authenticated Encryption with Associated Data, AEAD). Combina la confidencialidad de los datos de usuario con la comprobación de integridad y la autenticidad mediante una etiqueta de autenticación criptográfica (Authentication Tag), así como datos adicionales asociados opcionales (Additional Authenticated Data, AAD). Las instancias se gestionan normalmente a través del alias de puntero inteligente AuthCipherCtx::Sptr [SWS_CRYPT_20101].

Como interlocutores intervienen, por un lado, la aplicación usuaria, que cifra y descifra flujos de datos o bloques individuales, y, por otro lado, la gestión de claves: el contexto opera directamente sobre una instancia de clave del tipo SymmetricKey [SWS_CRYPT_23911] o bien referencia una ubicación de almacenamiento persistente o administrada mediante KeySlot [SWS_CRYPT_50072]. Desde el punto de vista funcional, la interfaz admite tanto el streaming paso a paso como llamadas individuales atómicas (Single-Call).

Ciclo de vida

El contexto pasa por fases claramente definidas desde su creación hasta su reutilización:

  • No inicializado (Uninitialized): tras la instanciación, el contexto aún no está listo para su uso. Antes del procesamiento de datos, debe asignarse obligatoriamente una clave. De lo contrario, las llamadas para la transformación o inicialización se rechazarán con CryptoErrc::kUninitializedContext [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Configurado (Configured / Key Set): la asignación de la clave se realiza mediante SetKey() con un SymmetricKey [SWS_CRYPT_23911] o un KeySlot [SWS_CRYPT_50072]. En este estado se pueden consultar parámetros estáticos como los tamaños de etiqueta y de IV. Para operaciones Single-Call, este estado ya es suficiente.
  • Streaming activo (Processing): mediante la llamada a Start() —opcionalmente con un vector de inicialización (IV) explícito [SWS_CRYPT_24715] o bien sin él o con un IV propio del contexto [SWS_CRYPT_50073]—, el contexto pasa a la fase de streaming activa para una dirección de transformación (CryptoTransform). Aquí se pueden procesar sucesivamente datos adicionales y datos de usuario.
  • Finalización y retorno: el procesamiento se finaliza de forma regular mediante Finish() [SWS_CRYPT_50075] o FinishEncrypt() [SWS_CRYPT_50076]. La cancelación prematura de un flujo en curso es posible en cualquier momento mediante Cancel() [SWS_CRYPT_50077]. Tras la finalización o cancelación, el contexto permanece presumiblemente en el estado configurado y queda disponible para una nueva inicialización a través de Start().

Ruta de uso

Para el procesamiento hay disponibles dos vías: el procesamiento por streaming para datos de mayor tamaño o fragmentados y las operaciones atómicas Single-Call.

La secuencia típica de streaming se estructura de la siguiente manera:

  1. Configuración: vincular la clave mediante SetKey() [SWS_CRYPT_23911]. Previamente pueden determinarse límites, tales como los tamaños mínimos/máximos de chunk [SWS_CRYPT_50162], [SWS_CRYPT_50082], el tamaño de la etiqueta [SWS_CRYPT_50161], así como las longitudes de IV [SWS_CRYPT_50163], [SWS_CRYPT_50164], [SWS_CRYPT_50165].
  2. Inicio: inicialización de la operación mediante Start() especificando la dirección de transformación (cifrado o descifrado) y, en su caso, el IV [SWS_CRYPT_24715], [SWS_CRYPT_50073].
  3. Datos asociados (opcional): en caso de que deban autenticarse metadatos adicionales en texto no cifrado, estos deben pasarse mediante UpdateAuthenticatedData() [SWS_CRYPT_20313]. Esto debe realizarse obligatoriamente antes de cualquier dato confidencial de usuario. El tamaño máximo puede comprobarse mediante GetMaxAssociatedDataSize() [SWS_CRYPT_20103].
  4. Datos confidenciales de usuario: entrega gradual de chunks de datos mediante UpdateConfidentialData() [SWS_CRYPT_50074]. Los tamaños de búfer de salida requeridos pueden calcularse dinámicamente a través de GetRequiredOutputBufferSize() [SWS_CRYPT_50081].
  5. Finalización: llamada a Finish() [SWS_CRYPT_50075] o FinishEncrypt() [SWS_CRYPT_50076]. Durante este proceso se transforman los datos residuales, se finaliza la etiqueta de autenticación (se genera en el cifrado y se verifica en el descifrado) y, en caso necesario, se devuelve el IV generado.

Para datos compactos disponibles en un solo paso, ProcessSingleCall() [SWS_CRYPT_50078], ProcessSingleCallWithInputIv() [SWS_CRYPT_50079] y EncryptSingleCallWithOutputIv() [SWS_CRYPT_50080] ofrecen un procesamiento con estado mínimo sin necesidad de un Start() previo.

Diagrama de secuencia: flujo paso a paso de streaming de una transformación autenticada con AuthCipherCtx. Fuentes: [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Escenarios de error

Los métodos aseguran la secuencia correcta del protocolo y la seguridad criptográfica mediante códigos de error específicos:

  • Violación del orden en los datos adicionales: si se llama a UpdateAuthenticatedData() después de haber procesado ya datos confidenciales a través de UpdateConfidentialData(), la operación falla con CryptoErrc::kInvalidUsageOrder [SWS_CRYPT_20313].
  • Procesamiento sin inicio: si se llama a UpdateAuthenticatedData(), UpdateConfidentialData(), Finish(), FinishEncrypt() o Cancel() sin una llamada previa y exitosa a Start(), se devuelve el error CryptoErrc::kProcessingNotStarted [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50076], [SWS_CRYPT_50077].
  • Comprobaciones de claves y permisos: si el tipo de clave asignada no coincide con el contexto, SetKey() o Start() devuelve el error CryptoErrc::kIncompatibleObject [SWS_CRYPT_23911], [SWS_CRYPT_24715]. Si a la clave le faltan los indicadores de uso requeridos (kAllowDataEncrypt o kAllowDataDecrypt), esto da como resultado CryptoErrc::kUsageViolation [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_50078]. En caso de ranuras ocupadas o vacías, se notifica CryptoErrc::kBusyResource o CryptoErrc::kEmptyKeySlot [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Errores de búfer y de dimensión: si el búfer de salida proporcionado es demasiado pequeño para los datos transformados o el IV, los métodos fallan con CryptoErrc::kInsufficientCapacity [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50078]. Las longitudes no válidas de búferes de entrada, etiquetas o IV dan lugar a CryptoErrc::kInvalidInputSize [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_24715].
  • Autenticación fallida: si durante el descifrado falla la comprobación de la etiqueta de autenticación, Finish() [SWS_CRYPT_50075] o ProcessSingleCall() [SWS_CRYPT_50078] señalan el error CryptoErrc::kAuthTagNotValid. Aviso de seguridad importante: en streaming, UpdateConfidentialData() emite el texto no cifrado descifrado antes de comprobar la etiqueta; la aplicación solo debe continuar utilizando o liberar estos datos tras un Finish() exitoso [SWS_CRYPT_50074].

Esta guía se basa en las especificaciones para AUTOSAR Adaptive Platform Release R25-11 y resume los requisitos para la clase ara::crypto::cryp::AuthCipherCtx.
