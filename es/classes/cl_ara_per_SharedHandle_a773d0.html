clase ara::per::SharedHandle

[SWS_PER_00362] Upstream: RS_PER_00002, RS_AP_00122, RS_AP_00140

template <typename T> class SharedHandle final {...};

Handle to a File Storage or Key-Value Storage. A SharedHandle is returned by the functions OpenFileStorage() and OpenKeyValueStorage() and can be passed between threads as needed. It provides the abstraction that is necessary to allow thread-safe implementation of OpenFile Storage() and OpenKeyValueStorage().

Contexto

La clase plantilla ara::per::SharedHandle sirve en el módulo de persistencia (ara::per) como handle inteligente de acceso a instancias del almacenamiento de archivos o de clave-valor. Como abstracción genérica (template <typename T> class SharedHandle final), la clase encapsula el recurso de almacenamiento gestionado de tipo T y se proporciona como tipo de retorno de las funciones OpenFileStorage() y OpenKeyValueStorage().

La tarea principal de SharedHandle consiste en permitir el intercambio de handles de almacenamiento entre diferentes hilos de ejecución según sea necesario («can be passed between threads as needed»). Al mismo tiempo, la clase proporciona la abstracción necesaria para garantizar una implementación segura para hilos de las funciones de apertura de almacenamiento OpenFileStorage() y OpenKeyValueStorage(). Los interlocutores de interacción principales son los hilos de aplicación invocadores, las funciones fábrica creadoras de almacenamiento y el objeto de almacenamiento encapsulado.

Ciclo de vida

El ciclo de vida de un SharedHandle comienza habitualmente con el retorno mediante OpenFileStorage() o OpenKeyValueStorage(). Como alternativa, se puede crear un handle a partir de una instancia existente mediante el constructor de copia [SWS_PER_00369]. Interpretación: es probable que la clase implemente un concepto de propiedad compartida (shared ownership), en el que varias instancias de handle referencian conjuntamente el mismo almacenamiento subyacente.

En cuanto a su estado, un handle se encuentra bien en un estado válido (si representa un objeto válido de la clase plantilla) o bien en un estado vacío [SWS_PER_00398]. Un handle pasa al estado vacío en particular cuando se utiliza como origen (sh) en una construcción por movimiento [SWS_PER_00367] o en una asignación por movimiento [SWS_PER_00368]. En ambos casos, el objeto de origen queda invalidado y ya no debe utilizarse para accesos al almacenamiento [SWS_PER_00367], [SWS_PER_00368]. Un handle vacío puede volver a pasar al estado válido mediante una asignación de copia [SWS_PER_00370] o una asignación por movimiento [SWS_PER_00368] con un handle válido.

La liberación de la instancia de handle se produce de forma determinista a través del destructor ~SharedHandle() [SWS_PER_00568] al salir del ámbito correspondiente. Para la concurrencia rige una clara distinción: la consulta del estado mediante operator bool() [SWS_PER_00398] así como la desreferenciación a través de operator*() [SWS_PER_00402], [SWS_PER_00403] y operator->() [SWS_PER_00363], [SWS_PER_00364] son seguras para hilos (thread-safe). Por el contrario, las operaciones modificadoras en la misma instancia de handle —en concreto, los operadores de asignación [SWS_PER_00368], [SWS_PER_00370] así como el destructor [SWS_PER_00568]— están especificadas como no seguras para hilos (not thread-safe).

Diagrama de estados: ciclo de vida y transiciones de estado de SharedHandle entre los estados válido y vacío. Fuentes: [SWS_PER_00367], [SWS_PER_00368], [SWS_PER_00370], [SWS_PER_00398], [SWS_PER_00568]

Ruta de uso

Una ruta de uso típica para SharedHandle comprende los siguientes pasos:

  1. Obtener el handle: la aplicación invoca OpenFileStorage() o OpenKeyValueStorage() y recibe la instancia resultante de SharedHandle<T>.
  2. Comprobar el estado: antes de utilizar operadores de acceso, se comprueba el estado mediante el operador de conversión explícito operator bool() [SWS_PER_00398]. Este paso es estrictamente obligatorio, en particular tras operaciones de movimiento previas [SWS_PER_00367], [SWS_PER_00368].
  3. Acceder al objeto de almacenamiento: mediante operator*(), la aplicación obtiene una referencia al objeto subyacente (no constante [SWS_PER_00402] o constante [SWS_PER_00403]). A través del operador flecha operator->(), se pueden ejecutar directamente funciones miembro de la clase de almacenamiento encapsulada (no constante [SWS_PER_00363] o constante [SWS_PER_00364]).
  4. Transferencia entre hilos (opcional): para una división del trabajo, el handle se puede copiar ([SWS_PER_00369], [SWS_PER_00370]) o mover ([SWS_PER_00367], [SWS_PER_00368]) y transferir a otros hilos.
  5. Liberación de recursos: al final de su ciclo de vida, la instancia de handle se destruye mediante ~SharedHandle() [SWS_PER_00568].

Escenarios de error

Al utilizar SharedHandle, deben tenerse en cuenta las siguientes condiciones previas y escenarios de error:

  • Comportamiento indefinido con handle vacío: invocar operadores distintos de operator bool() sobre un handle vacío o invalidado da lugar a un comportamiento indefinido («undefined behavior») [SWS_PER_00398]. Por lo tanto, la especificación exige comprobar el estado mediante operator bool() [SWS_PER_00367], [SWS_PER_00368] antes de utilizar otros operadores.
  • Uso tras una operación de movimiento: tan pronto como un handle se pasa como argumento al constructor de movimiento [SWS_PER_00367] o al operador de asignación por movimiento [SWS_PER_00368], el objeto de origen queda invalidado y ya no debe utilizarse para accesos al almacenamiento.
  • Seguridad frente a excepciones (Exception Safety): todas las funciones miembro de SharedHandle —constructores ([SWS_PER_00367], [SWS_PER_00369]), operadores de asignación ([SWS_PER_00368], [SWS_PER_00370]), operadores de desreferenciación ([SWS_PER_00363], [SWS_PER_00364], [SWS_PER_00402], [SWS_PER_00403]), comprobación de estado [SWS_PER_00398] y destructor [SWS_PER_00568]— están anotadas con noexcept y declaradas como exception safe. Por lo tanto, los estados de error no se manifiestan en excepciones de C++, sino en el estado lógico del handle (operator bool() == false).
  • Carreras de datos en la asignación o destrucción: mientras que los accesos de lectura al objeto de almacenamiento referenciado son seguros para hilos ([SWS_PER_00363], [SWS_PER_00364], [SWS_PER_00402], [SWS_PER_00403], [SWS_PER_00398]), las asignaciones ([SWS_PER_00368], [SWS_PER_00370]) y la destrucción [SWS_PER_00568] en la misma instancia de handle no deben ejecutarse concurrentemente sin protección.

Esta guía se basa exclusivamente en los requisitos de especificación de AUTOSAR Adaptive R25-11 para ara::per::SharedHandle.
