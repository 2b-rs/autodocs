clase <SI-Namespace>::common::<SI>

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: f6b3f809e490 Procedencia

Proporciona metadatos estáticos comunes, información de versión e identificadores para una interfaz de servicio.

Como espacio de nombres común, la clase agrupa metadatos estáticos e identificadores para una interfaz en el módulo Communication Management de AUTOSAR Adaptive SWS CommunicationManagement §8.2.2.1 «Public Member Variables». Pone a disposición, a través de serviceIdentifier y serviceVersion, información básica para la identificación unívoca y el versionado del servicio [SWS_CM_11506]. Además, serviceContractVersionMajor y serviceContractVersionMinor definen la versión exacta del contrato de servicio para garantizar la compatibilidad de la interfaz. Interpretación: dado que todos los elementos declarados están disponibles estáticamente, se asume que la clase no requiere instanciación en tiempo de ejecución y se incluye de forma inmutable para todo el proceso.

Contexto

En AUTOSAR Adaptive Platform, la clase C++ <SI-Namespace>::common::<SI> del módulo com (Communication Management) desempeña el papel central de contenedor común de metadatos y espacio de nombres para una Service Interface definida SWS CommunicationManagement §8.2.2.1 «Public Member Variables». La clase reúne propiedades estáticas e identificadores de interfaz que se aplican de manera uniforme tanto para los consumidores como para los proveedores de servicios y que se ponen a disposición a través del archivo de encabezado #include "<SiNamespaceDerivedDirectoryPath>/<SiShortname>_common.h" [SWS_CM_11506].

Entre los principales interlocutores de interacción se encuentra el sistema funcional de gestión de la comunicación ara::com, cuyos tipos de datos básicos se integran. La clase expone el identificador de servicio serviceIdentifier del tipo const ara::com::ServiceIdentifierType [SWS_CM_11506] (SWS CommunicationManagement §8.2.2.1.3 «serviceIdentifier»), así como la versión de servicio serviceVersion del tipo const ara::com::ServiceVersionType [SWS_CM_11507] (SWS CommunicationManagement §8.2.2.1.4 «serviceVersion»). Interpretación: los componentes de la aplicación y de la plataforma utilizan esta definición de clase común como referencia vinculante para establecer instancias de servicio mediante identificadores y contratos de interfaz estandarizados.

Diagrama de contexto: clasificación de la clase de interfaz común en interacción con las aplicaciones de servicio y los tipos básicos de Communication Management. Fuentes: [SWS_CM_11506], [SWS_CM_11507], SWS CommunicationManagement §8.2.2.1 «Public Member Variables».

Ciclo de vida

En cuanto al ciclo de vida, <SI-Namespace>::common::<SI> difiere fundamentalmente de las clases de instancias dinámicas: no requiere instanciación explícita y no posee ningún estado gestionado dinámicamente. Todas las variables de interfaz definidas en la especificación están declaradas como elementos estáticos de clase SWS CommunicationManagement §8.2.2.1 «Public Member Variables».

El identificador serviceIdentifier [SWS_CM_11506] y el versionado serviceVersion [SWS_CM_11507] están declarados como static const. De forma complementaria, serviceContractVersionMajor [SWS_CM_11508] (SWS CommunicationManagement §8.2.2.1.1 «serviceContractVersionMajor») y serviceContractVersionMinor [SWS_CM_11509] (SWS CommunicationManagement §8.2.2.1.2 «serviceContractVersionMinor») definen los números de versión del contrato como valores estáticos std::uint32_t. Interpretación: la vida útil estática de estos símbolos corresponde a la duración total del proceso; se asume que su inicialización se produce durante la carga del módulo respectivo o de la biblioteca compartida. No existe destrucción dinámica ni liberación de recursos de memoria.

En cuanto a la concurrencia, las variables serviceIdentifier y serviceVersion cualificadas con const ofrecen seguridad de subprocesos sin restricciones durante los accesos de lectura simultáneos. Interpretación: dado que las variables de versión serviceContractVersionMajor y serviceContractVersionMinor representan estados de especificación contractuales, se asume que permanecen invariables en tiempo de ejecución, lo que permite accesos de lectura simultáneos desde múltiples subprocesos de ejecución sin sobrecarga de sincronización.

Ruta de uso

La ruta de uso típica incluye el acceso estático a metadatos e información de versión para garantizar la compatibilidad de la interfaz:

  • Inclusión de encabezado: la aplicación o la capa de comunicación generada incluye el archivo <SiNamespaceDerivedDirectoryPath>/<SiShortname>_common.h para obtener acceso al espacio de nombres <SI-Namespace>::common::<SI> [SWS_CM_11506].
  • Identificación del servicio: los componentes acceden directamente a través de <SI-Namespace>::common::<SI>::serviceIdentifier al identificador unívoco del servicio, por ejemplo, para la inicialización de instancias o para el registro en la infraestructura de comunicación [SWS_CM_11506] (SWS CommunicationManagement §8.2.2.1.3 «serviceIdentifier»).
  • Comparación de versiones: para verificar la compatibilidad de la interfaz entre interlocutores de comunicación, se leen serviceVersion [SWS_CM_11507], así como las versiones del contrato serviceContractVersionMajor [SWS_CM_11508] y serviceContractVersionMinor [SWS_CM_11509].

No existen condiciones previas para el acceso de lectura, ya que todas las constantes están disponibles ya al inicio del programa. No se especifican estados de error ni excepciones para el acceso de solo lectura a estas variables estáticas.

Esta guía se basa exclusivamente en la especificación AUTOSAR para Adaptive Communication Management (R25-11).
