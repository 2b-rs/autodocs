Contexto

La clase ara::diag::DoIPTriggerVehicleAnnouncement [SWS_DM_00820] proporciona una interfaz de programación dentro de AUTOSAR Adaptive Platform (módulo diag) a través de la cual una Adaptive Application puede iniciar el envío de mensajes de anuncio de vehículo DoIP (Vehicle Announcement Messages).

Según AUTOSAR_AP_SWS_Diagnostics p. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface», la responsabilidad principal del envío de estos mensajes recae directamente en el Diagnostic Manager (DM). La norma prevé que el DM envíe anuncios de vehículo de manera autónoma basándose en los escenarios definidos en la norma ISO 13400-2:

  • al iniciar la red como difusión (broadcast) a otras unidades de control y pasarelas basadas en IP,
  • al detectar un comprobador externo a través de una línea de activación (Activation Line).

Aunque el flujo regular según la norma ISO 13400-2 prevé una tramitación autónoma por parte del DM y, en principio, no contempla la activación manual por parte de una Adaptive Application (AUTOSAR_AP_SWS_Diagnostics p. 106 «About DiagnosticDoIPTriggerVehicleAnnouncementInterface»), la interfaz ara::diag::DoIPTriggerVehicleAnnouncement permite, no obstante, que una aplicación realice el disparo explícito. El DM actúa en este caso como ejecutor que envía los mensajes según la norma ISO 13400-2 en la interfaz de red especificada [SWS_DM_00815].

Ciclo de vida

La instanciación y la gestión del ciclo de vida de ara::diag::DoIPTriggerVehicleAnnouncement están bajo el control exclusivo del Diagnostic Manager:

  • Creación y destrucción: El constructor predeterminado está declarado como eliminado (DoIPTriggerVehicleAnnouncement() = delete) y protegido de forma privada [SWS_DM_02100]. Asimismo, el destructor es privado y está eliminado (~DoIPTriggerVehicleAnnouncement() noexcept = delete) [SWS_DM_02101]. Ambos métodos están implementados de manera específica por el fabricante [SWS_DM_02100], [SWS_DM_02101]. Por lo tanto, una Adaptive Application no puede instanciar sus propias instancias en la pila o en el montón.
  • Obtención de instancias: El acceso a la interfaz se realiza exclusivamente a través del método de fábrica estático GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]. Este devuelve un objeto de tipo ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>, que proporciona una referencia al objeto administrado por el DM.
  • Concurrencia: Tanto el método de fábrica GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] como el método TriggerVehicleAnnouncement() [SWS_DM_00822] están especificados explícitamente como no seguros para subprocesos (not thread-safe). Si varios subprocesos de una aplicación acceden a la interfaz, el invocador debe garantizar la sincronización. Ambos métodos están especificados como seguros frente a excepciones (exception safe) [SWS_DM_00821], [SWS_DM_00822].

Ruta de uso

El flujo típico para desencadenar un anuncio de vehículo se divide en los siguientes pasos:

  1. Solicitar referencia de interfaz: La Adaptive Application llama a la función estática ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821].
  2. Validar resultado: La aplicación comprueba el éxito del ara::core::Result devuelto y desempaqueta el std::reference_wrapper.
  3. Desencadenar anuncio: A través de la referencia obtenida, la aplicación llama al método TriggerVehicleAnnouncement(networkInterfaceId) [SWS_DM_00822]. El parámetro networkInterfaceId (tipo std::uint8_t) indica la interfaz de red de destino.
  4. Envío a través del DM: El Diagnostic Manager solicita el envío de los mensajes de anuncio según la norma ISO 13400-2 en la interfaz de red especificada [SWS_DM_00815] y confirma la ejecución a la aplicación con ara::core::Result<void> [SWS_DM_00822].

Diagrama de secuencia: patrón de interacción para el disparo explícito de anuncios de vehículo DoIP. Fuentes: [SWS_DM_00821], [SWS_DM_00822], [SWS_DM_00815].

Escenarios de error

Al llamar a TriggerVehicleAnnouncement() se aplican condiciones previas específicas relativas a la configuración de red:

  • Conflicto con interfaces controladas por línea de activación: Si la networkInterfaceId transmitida pertenece a una configuración en la que la propiedad isActivationLineDependent = TRUE está establecida, esta llamada al método representa un error [SWS_DM_00822]. El motivo de ello es que, según [SWS_DM_00816], el envío en dichas interfaces ya se realiza de forma totalmente automática a través del DM tan pronto como la línea de activación pasa a nivel alto y se ha asignado una dirección IP [SWS_DM_00822].
  • Ausencia de códigos de error estandarizados: Ni para GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821] ni para TriggerVehicleAnnouncement() [SWS_DM_00822] se han predefinido códigos de error específicos en la norma («This function does not specify any standardized errors»). Si, aun así, se produce un error (como la transmisión de una interfaz dependiente de la línea de activación o un error interno), el ara::core::Result transportará probablemente códigos de error específicos del fabricante.

Esta guía se basa en la especificación de AUTOSAR Adaptive Platform R25-11.
