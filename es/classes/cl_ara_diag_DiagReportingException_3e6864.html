Contexto

La clase ara::diag::DiagReportingException representa un tipo de excepción específico dentro del módulo de diagnóstico de la AUTOSAR Adaptive Platform ([SWS_DM_00987], AUTOSAR_AP_SWS_Diagnostics §8.11.8 «Class: DiagReportingException»). Según la definición de sintaxis, la clase hereda públicamente de ara::core::Exception y sirve para encapsular y notificar como excepción de C++ los errores producidos en el contexto de diagnóstico. Se declara en el archivo de cabecera ara/diag/diag_error_domain.h ([SWS_DM_00988]).

Como derivación de ara::core::Exception, DiagReportingException constituye el nexo de unión entre los códigos de error relacionados con el diagnóstico (ara::core::ErrorCode) y el mecanismo de tratamiento de errores basado en excepciones de AUTOSAR Adaptive. Los socios de interacción típicos son clases de diagnóstico o interfaces de notificación de diagnóstico que instancian y lanzan la excepción, así como componentes de aplicación o de plataforma de nivel superior que capturan y procesan estas excepciones en los bloques try-catch correspondientes.

Ciclo de vida

El ciclo de vida de ara::diag::DiagReportingException se corresponde con el ciclo de vida estándar de objetos de excepción de C++ en el procedimiento de desenrollado de pila (stack unwinding):

  • Creación: una instancia se crea explícitamente mediante el constructor DiagReportingException(ara::core::ErrorCode err) cuando se produce el correspondiente error de notificación ([SWS_DM_00988]). El constructor está declarado como explicit y noexcept. Esto asegura que durante la propia construcción de la excepción no puedan lanzarse más excepciones (seguridad frente a excepciones: exception safe).
  • Propiedad y propagación: el objeto de excepción se transfiere al sistema en tiempo de ejecución de C++ mediante la llamada a throw. Permanece bajo el control del entorno de ejecución hasta que queda vinculado por una cláusula catch adecuada (habitualmente por referencia, p. ej. const ara::diag::DiagReportingException& o const ara::core::Exception&).
  • Destrucción: cuando el flujo de control abandona el bloque catch de tratamiento, el objeto de excepción se libera automáticamente.
  • Concurrencia: la construcción está especificada conforme a la especificación como segura para subprocesos (thread-safe) ([SWS_DM_00988]).

Ruta de uso

La ruta típica de uso comprende la instanciación y el lanzamiento por parte de un componente de diagnóstico notificador, así como la captura y evaluación por parte del invocador:

  1. Detección de errores: una operación de diagnóstico falla o constata una condición de notificación errónea y genera un ara::core::ErrorCode correspondiente.
  2. Instanciación y lanzamiento: el componente instancia ara::diag::DiagReportingException con este código de error y lanza la excepción mediante throw ([SWS_DM_00988]). Es de suponer que esto también suceda internamente de manera alternativa a través de mecanismos de encapsulación como ara::core::Result::ValueOrThrow().
  3. Captura: la lógica de aplicación que realiza la llamada captura la excepción en un bloque try-catch.

Escenarios de error

Dado que DiagReportingException representa en sí misma el medio de soporte para la información de error, las precondiciones y poscondiciones relevantes se sitúan en su construcción:

  • Código de error válido como condición previa: Al constructor DiagReportingException(ara::core::ErrorCode err) se le debe pasar un ara::core::ErrorCode válido ([SWS_DM_00988]). El código de error transmite la causa concreta del error desde el dominio de error correspondiente (declarado mediante ara/diag/diag_error_domain.h).
  • Comportamiento durante la construcción: el constructor cuenta con el especificador noexcept ([SWS_DM_00988]). Si la transferencia o inicialización fallase, se garantiza que no se lanzará ninguna otra excepción para evitar una terminación mediante std::terminate durante un desenrollado de pila ya activo.
  • Excepciones no tratadas: si una DiagReportingException lanzada no es capturada a lo largo de la pila de llamadas por un manejador adecuado, esto provocará la llamada a std::terminate y, con ello, la terminación del proceso afectado.
