Contexto

En el módulo shwa de AUTOSAR Adaptive Platform, la clase ara::shwa::Event sirve como primitiva de sincronización para flujos de trabajo asíncronos. Encapsula el estado de ejecución de tareas y permite que las aplicaciones invocadoras se sincronicen de manera dirigida con la finalización de tareas dependientes o asociadas ([AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605]). Interpretación: es probable que la clase actúe como nexo de unión entre el componente de software de la aplicación y el acelerador de hardware o sistema de ejecución de tareas subyacente para coordinar los pasos de cálculo iniciados de forma asíncrona.

Además de la sincronización individual con eventos individuales, la interfaz también permite la manipulación conjunta de varios objetos de evento. Mediante la lectura de listas de eventos con GetWaitList() ([AP_SWS_SHWA_00603]), así como funciones estáticas de espera colectiva para vectores de eventos ([AP_SWS_SHWA_00605]), la clase interactúa con estructuras de contenedor (ara::core::Vector<Event>). De este modo, se pueden agregar dependencias antes de que las operaciones posteriores se ejecuten sobre conjuntos de datos modificados.

Ciclo de vida

Las instancias de ara::shwa::Event se crean a través de la ruta de factoría estática Event::Create() ([AP_SWS_SHWA_00602]). Esta función es segura para hilos (thread-safe), garantiza seguridad frente a excepciones (exception safe) y, en caso de éxito, entrega el objeto inicializado al llamador mediante un ara::core::Result<Event>. Debido a la calificación como final, queda excluida la herencia o la especialización polimórfica de la clase.

Durante el funcionamiento, las instancias están sujetas a reglas de concurrencia específicas: ni la consulta de listas de dependencias mediante GetWaitList() ([AP_SWS_SHWA_00603]) ni las llamadas de sincronización Wait() ([AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605]) o WaitFor() ([AP_SWS_SHWA_00606]) son seguras para hilos (not thread-safe). Por lo tanto, el acceso paralelo a la misma instancia desde varios hilos requiere obligatoriamente una sincronización por parte de la aplicación.

En cuanto al comportamiento ante errores, los métodos de sincronización no ofrecen semántica de reversión (no_rollback_semantics): en caso de fallos o tiempos de espera agotados durante el procesamiento de las tareas, los datos afectados por las tareas deben considerarse modificados de manera no intencionada ([AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605], [AP_SWS_SHWA_00606]).

Ruta de uso

Una ruta de uso típica incluye la instanciación, la gestión de dependencias y la sincronización bloqueante o con límite de tiempo:

  1. Creación: la aplicación inicializa un objeto de evento mediante Event::Create() ([AP_SWS_SHWA_00602]).
  2. Comprobación de dependencias: Interpretación: es probable que la aplicación pueda consultar eventos vinculados a través de GetWaitList() ([AP_SWS_SHWA_00603]) para determinar el estado de las cadenas de eventos.
  3. Sincronización: la aplicación se bloquea hasta que finalizan las operaciones pendientes:
    • A nivel de instancia mediante el método sin parámetros Wait() ([AP_SWS_SHWA_00604]).
    • De forma colectiva mediante la sobrecarga estática Wait(eventList) para varios eventos ([AP_SWS_SHWA_00605]).
    • Con límite de tiempo mediante el método estático WaitFor(ms) ([AP_SWS_SHWA_00606]), en caso de que se deba evitar un bloqueo indefinido. Interpretación: es probable que la firma estática sin parámetros de evento espere globalmente las tareas programadas en el contexto actual.
  4. Evaluación de resultados: el ara::core::Result<void> devuelto comprobará los errores producidos antes de seguir utilizando los datos útiles.

Diagrama de secuencia: secuencia de llamadas típica para la creación y sincronización de eventos. Fuentes: [AP_SWS_SHWA_00602], [AP_SWS_SHWA_00604], [AP_SWS_SHWA_00606].

Escenarios de error

Todas las interfaces de ara::shwa::Event utilizan ara::core::Result para la señalización de errores y no lanzan excepciones de C++ (noexcept, exception safe). Se especifican los siguientes códigos de error de ShwaErrorCode:

  • ShwaErrorCode::kRuntime: Error de tiempo de ejecución general que puede producirse durante la creación ([AP_SWS_SHWA_00602]), la consulta de listas ([AP_SWS_SHWA_00603]), así como en llamadas de espera ([AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605], [AP_SWS_SHWA_00606]).
  • ShwaErrorCode::kEventInvalidOperation: Señaliza una operación no permitida sobre el evento, como una espera errónea o no autorizada ([AP_SWS_SHWA_00603], [AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605], [AP_SWS_SHWA_00606]).
  • ShwaErrorCode::kTaskExecutionFailure: Indica que se ha producido un error durante la ejecución de la tarea asociada al evento ([AP_SWS_SHWA_00604], [AP_SWS_SHWA_00605], [AP_SWS_SHWA_00606]).
  • ShwaErrorCode::kTimedOut: Específico de WaitFor(ms) ([AP_SWS_SHWA_00606]), en caso de que el intervalo de tiempo especificado expire antes de la finalización de la tarea.

Por lo tanto, el acceso paralelo a la misma instancia desde varios hilos requiere obligatoriamente una sincronización por parte de la aplicación.</p>
<p>En cuanto al comportamiento ante errores, los métodos de sincronización no ofrecen semántica de reversión (<em>no_rollback_semantics</em>): en caso de fallos o tiempos de espera agotados durante el procesamiento de las tareas, los datos afectados por las tareas deben considerarse modificados de manera no intencionada (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00604" href="../spec/record.html?id=AP_SWS_SHWA_00604">[AP_SWS_SHWA_00604]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00605" href="../spec/record.html?id=AP_SWS_SHWA_00605">[AP_SWS_SHWA_00605]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00606" href="../spec/record.html?id=AP_SWS_SHWA_00606">[AP_SWS_SHWA_00606]</a>).</p>

<h4>Ruta de uso</h4>
<p>Una ruta de uso típica incluye la instanciación, la gestión de dependencias y la sincronización bloqueante o con límite de tiempo:</p>
<ol>
<li><strong>Creación:</strong> la aplicación inicializa un objeto de evento mediante <code>Event::Create()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00602" href="../spec/record.html?id=AP_SWS_SHWA_00602">[AP_SWS_SHWA_00602]</a>).</li>
<li><strong>Comprobación de dependencias:</strong> Interpretación: es probable que la aplicación pueda consultar eventos vinculados a través de <code>GetWaitList()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00603" href="../spec/record.html?id=AP_SWS_SHWA_00603">[AP_SWS_SHWA_00603]</a>) para determinar el estado de las cadenas de eventos.</li>
<li><strong>Sincronización:</strong> la aplicación se bloquea hasta que finalizan las operaciones pendientes:
<ul>
<li>A nivel de instancia mediante el método sin parámetros <code>Wait()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00604" href="../spec/record.html?id=AP_SWS_SHWA_00604">[AP_SWS_SHWA_00604]</a>).</li>
<li>De forma colectiva mediante la sobrecarga estática <code>Wait(eventList)</code> para varios eventos (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00605" href="../spec/record.html?id=AP_SWS_SHWA_00605">[AP_SWS_SHWA_00605]</a>).</li>
<li>Con límite de tiempo mediante el método estático <code>WaitFor(ms)</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00606" href="../spec/record.html?id=AP_SWS_SHWA_00606">[AP_SWS_SHWA_00606]</a>), en caso de que se deba evitar un bloqueo indefinido. Interpretación: es probable que la firma estática sin parámetros de evento espere globalmente las tareas programadas en el contexto actual.</li>
</ul>
</li>
<li><strong>Evaluación de resultados:</strong> el <code>ara::core::Result&lt;void&gt;</code> devuelto comprobará los errores producidos antes de seguir utilizando los datos útiles.</li>
</ol>

<h4>Escenarios de error</h4>
<p>Todas las interfaces de <code>ara::shwa::Event</code> utilizan <code>ara::core::Result</code> para la señalización de errores y no lanzan excepciones de C++ (<code>noexcept</code>, <em>exception safe</em>). Se especifican los siguientes códigos de error de <code>ShwaErrorCode</code>:</p>
<ul>
<li><code>ShwaErrorCode::kRuntime</code>: Error de tiempo de ejecución general que puede producirse durante la creación (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00602" href="../spec/record.html?id=AP_SWS_SHWA_00602">[AP_SWS_SHWA_00602]</a>), la consulta de listas (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00603" href="../spec/record.html?id=AP_SWS_SHWA_00603">[AP_SWS_SHWA_00603]</a>), así como en llamadas de espera (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00604" href="../spec/record.html?id=AP_SWS_SHWA_00604">[AP_SWS_SHWA_00604]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00605" href="../spec/record.html?id=AP_SWS_SHWA_00605">[AP_SWS_SHWA_00605]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00606" href="../spec/record.html?id=AP_SWS_SHWA_00606">[AP_SWS_SHWA_00606]</a>).</li>
<li><code>ShwaErrorCode::kEventInvalidOperation</code>: Señaliza una operación no permitida sobre el evento, como una espera errónea o no autorizada (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00603" href="../spec/record.html?id=AP_SWS_SHWA_00603">[AP_SWS_SHWA_00603]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00604" href="../spec/record.html?id=AP_SWS_SHWA_00604">[AP_SWS_SHWA_00604]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00605" href="../spec/record.html?id=AP_SWS_SHWA_00605">[AP_SWS_SHWA_00605]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00606" href="../spec/record.html?id=AP_SWS_SHWA_00606">[AP_SWS_SHWA_00606]</a>).</li>
<li><code>ShwaErrorCode::kTaskExecutionFailure</code>: Indica que se ha producido un error durante la ejecución de la tarea asociada al evento (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00604" href="../spec/record.html?id=AP_SWS_SHWA_00604">[AP_SWS_SHWA_00604]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00605" href="../spec/record.html?id=AP_SWS_SHWA_00605">[AP_SWS_SHWA_00605]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00606" href="../spec/record.html?id=AP_SWS_SHWA_00606">[AP_SWS_SHWA_00606]</a>).</li>

</ul>
