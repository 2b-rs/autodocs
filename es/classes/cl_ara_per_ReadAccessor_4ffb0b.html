clase ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Contexto

La clase ara::per::ReadAccessor sirve para la lectura secuencial de contenidos de archivos persistentes dentro del módulo per (Persistency) de la Adaptive Platform. Hereda virtualmente de FileAccessor y proporciona accesos de lectura tanto en modo binario como en modo texto. A través de esta abstracción, las aplicaciones acceden a los datos almacenados sin tener que gestionar directamente el almacenamiento físico. La interfaz ofrece operaciones granulares para inspeccionar caracteres o bytes individuales, así como métodos para la lectura por bloques o completa de contenidos y líneas.

Ciclo de vida

El ciclo de vida de una instancia de ara::per::ReadAccessor está sujeto a estrictas especificaciones relativas a la creación y a la gestión de recursos:

  • Creación: el constructor por defecto está explícitamente eliminado conforme a [SWS_PER_00461] (delete). Por lo tanto, queda excluida una inicialización directa sin parámetros por parte de la aplicación. Interpretación: en consecuencia, es probable que una instancia se cree a través de mecanismos de nivel superior del acceso a archivos de persistencia y se entregue al llamador.
  • Destrucción: el destructor ~ReadAccessor() está declarado como virtual, provisto de override y definido como noexcept [SWS_PER_00417]. Al destruirse el objeto, se liberan los descriptores de lectura subyacentes.
  • Concurrencia y seguridad frente a excepciones: todos los métodos de la clase están especificados como not thread-safe (p. ej., [SWS_PER_00417], [SWS_PER_00419]). Por tanto, el acceso simultáneo de varios subprocesos a la misma instancia requiere una sincronización externa. Al mismo tiempo, todas las operaciones de lectura son seguras frente a excepciones (exception safe) y están declaradas como noexcept; los errores se transmiten a través del tipo de retorno ara::core::Result.

Ruta de uso

El uso de ara::per::ReadAccessor distingue entre operaciones de inspección (sin cambio de posición) y operaciones de lectura consumidoras (con avance del puntero de archivo):

  • Inspección (Peeking): mediante PeekByte() [SWS_PER_00418] o PeekChar() [SWS_PER_00167] se puede consultar el byte o carácter presente en la posición actual, sin que se modifique la posición de lectura. Ambos métodos están declarados como const.
  • Lectura paso a paso: mediante GetByte() [SWS_PER_00419] o GetChar() [SWS_PER_00168] se lee el elemento actual y el puntero interno avanza una posición.
  • Lectura por bloques (modo binario): con ReadBinary(std::uint64_t n) [SWS_PER_00422] se lee una cantidad definida de bytes en un ara::core::Vector<ara::core::Byte>. Si se alcanza el final del archivo antes de llegar a n, el vector contiene menos bytes de los solicitados. La sobrecarga sin parámetros ReadBinary() [SWS_PER_00421] lee todos los bytes restantes hasta el final del archivo.
  • Modo texto y procesamiento de líneas: mediante ReadText(std::uint64_t n) [SWS_PER_00165] o ReadText() [SWS_PER_00420] se leen cadenas de caracteres en un ara::core::String. Para archivos de texto estructurados, ReadLine(char delimiter = '\n') [SWS_PER_00119] permite la lectura línea por línea hasta el delimitador. El delimitador no se incluye en la cadena resultante. Si la posición de lectura se encuentra dentro de un punto de código Unicode, el texto devuelto puede presentar puntos de código incompletos.

Diagrama de secuencia: flujo típico de un procesamiento de texto línea por línea, incluyendo inspección y detección del final de archivo. Fuentes: [SWS_PER_00167], [SWS_PER_00119]

Escenarios de error

Todos los métodos de lectura e inspección devuelven un ara::core::Result. Si se produce un error, se aplica una semántica de reversión: la posición actual de lectura del archivo no se modifica en caso de error (especificado, entre otros, en [SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00421], [SWS_PER_00119]). Se especifican los siguientes estados de error del dominio de errores PerErrc:

  • PerErrc::kEof: se devuelve cuando la posición de lectura actual ya se encuentra al final del archivo o el archivo está vacío ([SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00418], [SWS_PER_00167], [SWS_PER_00421], [SWS_PER_00422], [SWS_PER_00119], [SWS_PER_00165], [SWS_PER_00420]).
  • PerErrc::kPhysicalStorageFailure: se produce cuando falla el acceso físico de lectura al soporte de almacenamiento ([SWS_PER_00420]).
  • PerErrc::kValidationFailed: indica que no se puede garantizar la integridad o validez de los datos almacenados ([SWS_PER_00419]).
  • PerErrc::kEncryptionFailed: se devuelve cuando falla el descifrado de los datos útiles almacenados ([SWS_PER_00419]).
  • PerErrc::kAuthenticationFailed: se produce cuando falla la verificación del Message Authentication Code (MAC) de los datos almacenados ([SWS_PER_00419]).

ReadLine función

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ara::core::Result< ara::core::String > ReadLine (char delimiter=’\n’) noexcept;
ReadText función 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.
