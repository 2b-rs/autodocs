Sirve para la identificación de errores de Execution Management, así como para su correspondencia con textos de mensaje y objetos de excepción.

La clase ara::exec::ExecErrorDomain define el dominio de error para Execution Management y mapea códigos de error numéricos a mensajes descriptivos ([SWS_EM_02288]). Se crea de forma predeterminada ([SWS_EM_02286]) y permite lanzar excepciones ExecException con seguridad de tipos ([SWS_EM_02289]). Si las excepciones de C++ están deshabilitadas, la función ThrowAsException() está deshabilitada en tiempo de compilación de conformidad con [SWS_CORE_10304] ([SWS_EM_02289]).

Contexto

La clase ara::exec::ExecErrorDomain define el dominio de error específico para el clúster funcional Execution Management dentro de AUTOSAR Adaptive Platform. Como especialización final de la clase base ara::core::ErrorDomain, encapsula la asignación de causas de error específicas del dominio y constituye el puente entre códigos de error numéricos y descripciones semánticas de error. Además del tipo base ara::core::ErrorDomain, la clase interactúa estrechamente con ara::core::ErrorCode e instancia en caso de error objetos de excepción específicos del tipo ExecException ([SWS_EM_02289]). A través del método Name(), la clase proporciona un identificador textual del dominio que corresponde a la especificación ara::exec::ExecErrorDomain en [SWS_CORE_90023] ([SWS_EM_02287]).

Diagrama de contexto: integración de ExecErrorDomain y sus partes interactuantes en el sistema de errores. Fuentes: [SWS_EM_02287], [SWS_EM_02289], [SWS_CORE_90023]

Ciclo de vida

Los objetos de ara::exec::ExecErrorDomain se crean a través del constructor predeterminado ([SWS_EM_02286]). La construcción está declarada como noexcept y garantiza una seguridad frente a excepciones completa, así como seguridad para hilos ([SWS_EM_02286]). Dado que la clase no expone estados mutables y está declarada como final, todas las operaciones de lectura operan libres de efectos secundarios. Es de suponer que en aplicaciones reales se utilice típicamente una instancia global o estática del dominio de error (interpretación: de acuerdo con el modelo general de errores de Adaptive AUTOSAR), aunque una instanciación directa a través del constructor es posible en todo momento.

En cuanto a la concurrencia, todas las funciones miembro —en particular la consulta del nombre a través de Name() ([SWS_EM_02287]), la resolución del mensaje de error mediante Message() ([SWS_EM_02288]) y el lanzamiento de excepciones por medio de ThrowAsException() ([SWS_EM_02289])— están especificadas explícitamente como seguras para hilos. Por consiguiente, múltiples hilos de ejecución pueden consultar la misma instancia en paralelo y sin sincronización externa.

Ruta de uso

En la ruta de ejecución regular, el dominio sirve para traducir números de error en mensajes de diagnóstico comprensibles, así como para convertir códigos de error en objetos de excepción. Si se produce un error dentro de una operación de Execution Management, este se representa habitualmente como un ara::core::ErrorCode que internamente hace referencia a la instancia de ara::exec::ExecErrorDomain. Para la salida de texto, el llamador pasa el identificador numérico de error a Message() ([SWS_EM_02288]) y recibe un puntero a una cadena de caracteres inmutable (const char*) que describe la causa.

Si un componente llamador opta por un tratamiento de errores basado en excepciones, se recurre al método ThrowAsException() ([SWS_EM_02289]). La función recibe la referencia a un ara::core::ErrorCode, crea a partir de él una nueva instancia de ExecException y la lanza inmediatamente como excepción de C++ en el contexto de la llamada ([SWS_EM_02289]).

Diagrama de secuencia: flujo al lanzar una excepción de C++ a través de ThrowAsException. Fuentes: [SWS_EM_02289], [SWS_CORE_10304]

Escenarios de error

Los métodos para la consulta de información se distinguen por estrictas garantías: ni la construcción ([SWS_EM_02286]), ni la recuperación del nombre a través de Name() ([SWS_EM_02287]), ni la consulta del mensaje a través de Message() ([SWS_EM_02288]) lanzan excepciones (noexcept), y los tres están clasificados como seguros frente a excepciones («exception safe»). Para códigos de error desconocidos, es probable que Message() devuelva un texto de marcador de posición genérico o una cadena vacía (interpretación: el payload no define un comportamiento de error específico para valores de CodeType no válidos).

Un comportamiento particular se aplica a ThrowAsException(): esta función está especificada como noexcept(false) y explícitamente como no segura frente a excepciones («not exception safe»), ya que su propósito intrínseco consiste en lanzar un ExecException ([SWS_EM_02289]). Además, se aplica una condición esencial de la cadena de herramientas: conforme a [SWS_CORE_10304], ThrowAsException() no participa en la resolución de sobrecarga si las excepciones de C++ están deshabilitadas en el compilador ([SWS_EM_02289]). En entornos de sistema sin soporte para excepciones, esta ruta no está disponible en tiempo de compilación, de modo que los errores deben evaluarse obligatoriamente a través de valores de retorno.

El constructor por defecto ExecErrorDomain() inicializa una nueva instancia del dominio de errores ara::exec::ExecErrorDomain según [SWS_EM_02286]. La llamada se realiza de forma síncrona, no recibe parámetros y no tiene valor de retorno. La declaración se incluye a través de la cabecera ara/exec/exec_error_domain.h.

En lo que respecta a la robustez y concurrencia, el constructor está declarado como noexcept, se considera seguro frente a excepciones (exception safe) y está especificado como plenamente seguro para subprocesos (thread-safe) [SWS_EM_02286]. No se requiere ningún tratamiento de errores durante la creación del objeto, ya que la operación se ejecuta sin errores y no desencadena códigos de error ni excepciones.

En el sistema global, el objeto creado sirve para representar y describir errores específicos de módulo de Execution Management. A través de la instancia se puede consultar el nombre del dominio [SWS_EM_02287], determinar mensajes textuales para códigos de error [SWS_EM_02288] o lanzar errores como excepciones de C++ [SWS_EM_02289]. Rara vez debería ser necesaria una instanciación explícita mediante este constructor en módulos de aplicación, ya que a través de la función libre GetExecErrorDomain() ya se proporciona una referencia global a la instancia [SWS_EM_02290].
