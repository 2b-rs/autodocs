Señala la finalización correcta de una operación sin valor o transporta un código de error producido.

La clase ara::core::Result<void, E> especializa el patrón Result para operaciones sin valor de retorno y representa o bien una finalización correcta o bien un error ([SWS_CORE_00811]). Tras la ejecución, quien realiza la llamada comprueba el estado de éxito mediante HasValue() ([SWS_CORE_00851]) o operator bool() y, en caso de error, accede a la causa del error contenida. Como condición de contorno vinculante, el tipo de error E debe corresponder al tipo ara::core::ErrorCode, ya que los tipos divergentes se rechazan ya en tiempo de compilación.

Contexto

La clase de plantilla ara::core::Result<void, E> representa una especialización parcial del patrón Result para operaciones que en caso de éxito no transmiten ningún valor de retorno (void), sino que señalan exclusivamente el éxito o el fallo de una acción. Según la definición de tipo, el tipo de valor value_type se fija siempre como void ([SWS_CORE_00811]), mientras que error_type representa el tipo de error parametrizado E ([SWS_CORE_00812]). Para el tipo E rige la directriz funcional de que cualquier discrepancia respecto a ara::core::ErrorCode debe ser rechazada por la implementación como error de compilación.

En AUTOSAR Adaptive Platform, ara::core::Result<void, E> actúa como tipo de retorno estandarizado para procedimientos propensos a errores y comandos de control entre componentes invocadores e interfaces ejecutoras. En lugar del clásico tratamiento de excepciones de C++, la clase ofrece una transmisión de errores explícita y económica en recursos, que permite tanto la consulta directa de estado como encadenamientos funcionales en la ruta de llamada.

Ciclo de vida

Una instancia de ara::core::Result<void, E> se encuentra a lo largo de toda su vida útil en exactamente uno de dos estados discretos: el estado de valor (éxito) o el estado de error. La inicialización con un valor void se realiza a través del constructor por defecto Result() ([SWS_CORE_00821]) o del método de fábrica estático FromValue() ([SWS_CORE_00831]). Para la creación en estado de error están disponibles constructores explícitos para lvalues y rvalues del tipo de error E ([SWS_CORE_00823], [SWS_CORE_00824]). Complementariamente, las funciones de fábrica FromError() permiten la construcción a partir de lvalues de error ([SWS_CORE_00834]), rvalues ([SWS_CORE_00835]) o mediante construcción in-place directa a partir de paquetes de parámetros ([SWS_CORE_00836]).

Las instancias preexistentes se pueden situar posteriormente en el estado de valor mediante EmplaceValue() ([SWS_CORE_00843]) o asignarse directamente con un nuevo error mediante EmplaceError() ([SWS_CORE_00844]). Los constructores de copia y de movimiento ([SWS_CORE_00825], [SWS_CORE_00826]), así como los correspondientes operadores de asignación ([SWS_CORE_00841], [SWS_CORE_00842]), transfieren el estado entre instancias; Swap() intercambia los contenidos de dos objetos ([SWS_CORE_00845]).

El destructor ~Result() finaliza el ciclo de vida ([SWS_CORE_00827]) y es trivial si se cumple std::is_trivially_destructible<E>::value. En cuanto a la concurrencia, las operaciones de solo lectura son thread-safe, mientras que las operaciones que modifican el estado, como EmplaceValue(), EmplaceError(), asignaciones o Swap(), no son thread-safe.

Diagrama de estados: ciclo de vida y transiciones de estado entre el estado de valor y el estado de error. Fuentes: [SWS_CORE_00821], [SWS_CORE_00831], [SWS_CORE_00823], [SWS_CORE_00834], [SWS_CORE_00843], [SWS_CORE_00844]

Ruta de uso

El flujo regular comienza con la recepción de una instancia de ara::core::Result<void, E> procedente de una llamada a función. Quien realiza la llamada evalúa el resultado mediante HasValue() ([SWS_CORE_00851]) o la conversión operator bool() ([SWS_CORE_00852]). Si la ejecución ha tenido éxito, se puede encadenar funcionalmente una operación subsiguiente mediante Bind() ([SWS_CORE_00870]): Bind() ejecuta el invocable (callable) transferido solo si la instancia contiene un valor, y devuelve su resultado transformado. Si en su lugar hay un error presente, se omite la función invocada y el contenido de error se asume en el nuevo resultado.

Para la homogeneización en código genérico, la especialización proporciona interfaces que formalmente se corresponden con la clase Result general: Value() ([SWS_CORE_00855]), operator*() ([SWS_CORE_00853]) y ValueOr() ([SWS_CORE_00861]) no devuelven ningún valor y actúan como métodos no-op. Análogamente, Resolve() ([SWS_CORE_00867]) ejecuta un invocable transferido solo si existe un error, y permanece inactivo en caso de éxito.

Diagrama de secuencia: secuencia típica de llamada, comprobación de estado y tratamiento de error o encadenamiento. Fuentes: [SWS_CORE_00851], [SWS_CORE_00857], [SWS_CORE_00868], [SWS_CORE_00870]

Escenarios de error

Si la instancia se encuentra en estado de error, el error contenido se puede consultar como referencia a través de las sobrecargas de Error() ([SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876]). En este caso rige una precondición estricta: la llamada a Error() en una instancia que no contiene ningún error representa una ResultWithNoErrorViolation. A la inversa, la llamada a Value() ([SWS_CORE_00855]) o operator*() ([SWS_CORE_00853]) en una instancia en estado de error desencadena una ResultWithNoValueViolation.

Para evitar infracciones de precondición, se ofrecen métodos de consulta alternativos: Err() suministra el error empaquetado en un ara::core::Optional<E>, el cual permanece vacío en caso de éxito ([SWS_CORE_00868], [SWS_CORE_00869]). Con ErrorOr() se puede indicar un error por defecto que se devuelve si no se contiene ningún error ([SWS_CORE_00863], [SWS_CORE_00864]). Para comprobaciones respecto a determinados valores de error, CheckError() coteja el error interno con un valor de comparación ([SWS_CORE_00865]).

Si se prefiere un tratamiento de errores basado en excepciones, ValueOrThrow() ([SWS_CORE_00866]) lanza en caso de error la excepción asignada al error; si hay un valor presente, la llamada retorna normalmente. Si las excepciones de C++ están deshabilitadas en la cadena de herramientas (toolchain), ValueOrThrow() no participa en la resolución de sobrecargas ([SWS_CORE_00866]).

Esta guía se basa en la especificación ara::core::Result<void, E> en el Release R25-11 y ha sido generada automáticamente.

Uso y contexto de llamada

La función miembro Bind de la especialización ara::core::Result<void, E> de ara/core/result.h ejecuta un cálculo posterior sobre una instancia exitosa sin valor de resultado [SWS_CORE_00870]. Si hay un valor presente, se invoca el callable pasado f de forma síncrona y sin parámetros. El callable debe cumplir la interfaz Result<XXX, E> f() o bien XXX f(), debiendo ser XXX un tipo admisible para Result [SWS_CORE_00870]. Si el callable devuelve un Result, el tipo de retorno corresponde a decltype(f()); si devuelve directamente XXX, el resultado se empaqueta como Result<decltype(f()), E> [SWS_CORE_00870].

Tratamiento de errores y concurrencia

Si la instancia no contiene ningún valor, se devuelve un nuevo Result<XXX, E> en el que se copia el error original [SWS_CORE_00870]. Interpretación: en este caso es de prever que no se ejecute el callable f. En cuanto a la seguridad de ejecución, la función se considera not exception safe [SWS_CORE_00870]. La seguridad para subprocesos es condicional (conditional) y depende por completo de la seguridad para subprocesos del callable pasado f [SWS_CORE_00870]. Pregunta Q-6288a7106d2730c3 (abierta)

Interacción con requisitos relacionados

A diferencia de las funciones Result<T, E> primarias de [SWS_CORE_00768] y [SWS_CORE_00941], en las que el callable recibe el valor de la instancia mediante f(const T&), la presente sobrecarga [SWS_CORE_00870] vincula operaciones a resultados void y, por lo tanto, espera un callable sin parámetros.

      La función miembro EmplaceError de la especialización ara::core::Result<void, E> construye de forma síncrona un nuevo valor de error directamente in-place dentro de la instancia existente a partir de los argumentos pasados args [SWS_CORE_00844].       En cuanto al tratamiento de errores y la seguridad frente a excepciones, la operación está clasificada como condicionalmente segura frente a excepciones (conditionally exception safe) [SWS_CORE_00844]. Mediante el especificador noexcept(std::is_nothrow_constructible<E, Args...>::value) se garantiza la ausencia de excepciones, siempre que el tipo E pueda construirse con los tipos Args... sin excepciones [SWS_CORE_00844].

Si varios subprocesos acceden concurrentemente a la misma instancia de Result, presumiblemente se requiera un mecanismo de sincronización externo para evitar cambios de estado no coordinados.                                                                                               En cuanto a la concurrencia y el comportamiento ante excepciones, la función miembro está especificada como segura para subprocesos (thread-safe) y declarada con la sintaxis del especificador noexcept, lo que garantiza una seguridad total frente a excepciones ([SWS_CORE_00861]).                                                                                                   En caso de éxito, el método retorna normalmente; si, por el contrario, existe un estado de error, lanza una excepción del tipo de excepción vinculado al error contenido (noexcept(false)) [SWS_CORE_00866]. En lo relativo a la seguridad ante excepciones, la operación está especificada como not exception safe [SWS_CORE_00866].
                                                                                                  

                                                                                                  Para el contexto de llamada y la concurrencia se aplican las siguientes condiciones límite:

                                                                                                    •

                                                                                                    • 

                                                                                                  

                                                                                                  En interacción con el módulo core, esta especialización void complementa las sobrecargas genéricas de ara::core::Result<T, E> que devuelven referencias a valores contenidos ([SWS_CORE_00766], [SWS_CORE_00769], [SWS_CORE_00778]), así como las especializaciones para tipos de referencia ara::core::Result<T&, E> ([SWS_CORE_00938], [SWS_CORE_00949]).
