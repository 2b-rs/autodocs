Contexto

La interfaz ara::crypto::cryp::HashFunctionCtx define la abstracción estandarizada para funciones hash criptográficas dentro del módulo crypto de AUTOSAR Adaptive Platform [SWS_CRYPT_21101]. Su responsabilidad principal consiste en el cálculo de sumas de comprobación criptográficas y resúmenes de mensaje sobre flujos de bytes arbitrarios u objetos de clave estructurados.

Como interlocutor actúa principalmente el software de aplicación invocador, que proporciona datos de entrada mediante ReadOnlyMemRegion y recibe los valores hash calculados a través de ReadWriteMemRegion [SWS_CRYPT_50060]. Además de las áreas de memoria regulares, el contexto puede interactuar directamente con objetos criptográficos para incluir de forma segura material de clave del tipo CryptoObject::Sptr en el cálculo del digest [SWS_CRYPT_50057]. Asimismo, el contexto interactúa potencialmente con otras instancias de contexto del mismo algoritmo y proveedor criptográfico mediante la importación y exportación del estado de procesamiento interno [SWS_CRYPT_50065].

Ciclo de vida

El ciclo de vida y la propiedad de una instancia se gestionan habitualmente mediante el alias de tipo de puntero inteligente ara::crypto::cryp::HashFunctionCtx::Sptr (std::shared_ptr<HashFunctionCtx>) [SWS_CRYPT_21101]. Dado que HashFunctionCtx es una interfaz puramente abstracta, la creación de la instancia concreta probablemente se realice a través de un método de factoría de un proveedor criptográfico (interpretación). Todas las funciones miembro están declaradas como noexcept y especificadas como seguras frente a excepciones y seguras para subprocesos (entre otras, [SWS_CRYPT_50060], [SWS_CRYPT_50058]).

El flujo operativo sigue un modelo con estado con tres fases principales:

  • Listo / No iniciado: tras la creación, el contexto se encuentra en estado de reposo. En este estado se puede ejecutar un proceso de hash de un solo paso mediante CalculateHashDigest() [SWS_CRYPT_50060] o iniciar un cálculo iterativo mediante Start() sin vector de inicialización (IV) [SWS_CRYPT_50152] o con IV [SWS_CRYPT_50153]. Una importación mediante ImportContextState() sitúa el contexto directamente en el estado de la imagen importada [SWS_CRYPT_50065].
  • En procesamiento (streaming): tras un Start() correcto, el contexto acepta fragmentos de datos [SWS_CRYPT_21113] u objetos de clave [SWS_CRYPT_50057] mediante llamadas repetidas a Update(). En esta fase se puede consultar en cualquier momento un estado intermedio mediante GetIntermediateDigest() sin interrumpir el flujo de datos [SWS_CRYPT_50059]. Con ExportContextState() se puede serializar el estado de cálculo [SWS_CRYPT_50064]. Una llamada a Cancel() cancela la operación y restablece el procesamiento [SWS_CRYPT_50058]; del mismo modo, una nueva llamada a Start() cancela una operación en curso [SWS_CRYPT_50152].
  • Finalizado (Finished): la llamada a Finish() finaliza el cálculo [SWS_CRYPT_21115]. En este estado no se pueden introducir más datos mediante Update(). El valor hash final ahora se puede leer a través de GetDigest() [SWS_CRYPT_21116] o comprobar directamente contra una referencia mediante Compare() [SWS_CRYPT_50154]. Mediante un nuevo Start(), el contexto pasa nuevamente a una nueva fase de cálculo.

Diagrama de estados: ciclo de vida y transiciones de estado de una instancia de HashFunctionCtx. Fuentes: [SWS_CRYPT_50152], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116], [SWS_CRYPT_50058], [SWS_CRYPT_50060], [SWS_CRYPT_50065]

Ruta de uso

La interfaz admite dos patrones de uso:

1. Cálculo en un solo paso (Single-Call): si el mensaje completo ya se encuentra en la memoria, CalculateHashDigest() ejecuta la inicialización, la transformación y la generación del digest en un único paso atómico [SWS_CRYPT_50060].

2. Cálculo progresivo por streaming (Multi-Call): para datos transmitidos por streaming o mensajes que son mayores que el tamaño de bloque máximo GetMaximumChunkSize() [SWS_CRYPT_50062], la llamada se realiza normalmente en los siguientes pasos individuales:

  1. Dimensionamiento del búfer: la aplicación determina el tamaño de salida mediante GetDigestSize() [SWS_CRYPT_50061] y asigna un búfer adecuado.
  2. Inicio: llamada a Start() [SWS_CRYPT_50152] o Start(iv) [SWS_CRYPT_50153] para activar el cálculo.
  3. Alimentación de datos: transferencia secuencial de secciones de datos a través de Update(data) [SWS_CRYPT_21113] o de claves a través de Update(key) [SWS_CRYPT_50057].
  4. Finalización: llamada a Finish() para completar el cálculo del digest [SWS_CRYPT_21115].
  5. Procesamiento del resultado: el digest se escribe mediante GetDigest() en el búfer de destino proporcionado [SWS_CRYPT_21116] o bien se compara directamente mediante Compare() con un valor de referencia esperado [SWS_CRYPT_50154].

Diagrama de secuencias: flujo típico de un cálculo iterativo del valor hash mediante Start, Update, Finish y evaluación. Fuentes: [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116], [SWS_CRYPT_50154]

Escenarios de error

Todos los métodos devuelven un ara::core::Result e implementan semántica de reversión, de modo que el contexto permanece en un estado coherente en caso de error. Los códigos de error definidos cubren las siguientes áreas problemáticas:

  • Errores de secuencia:
    • ara::crypto::CryptoErrc::kProcessingNotStarted: se produce una llamada a Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) o Cancel() [SWS_CRYPT_50058] sin que el cálculo haya sido iniciado mediante Start().
    • ara::crypto::CryptoErrc::kInvalidUsageOrder: se llama a Finish() [SWS_CRYPT_21115] o GetIntermediateDigest() [SWS_CRYPT_50059] sin que el proceso de hash se haya iniciado previamente con éxito.
    • ara::crypto::CryptoErrc::kProcessingNotFinished: se llama a GetDigest() [SWS_CRYPT_21116] o Compare() [SWS_CRYPT_50154] antes de que el cálculo haya finalizado mediante Finish().
  • Problemas de búfer y de tamaño:
    • ara::crypto::CryptoErrc::kInsufficientCapacity: el búfer de salida proporcionado es demasiado pequeño para el resultado en CalculateHashDigest() [SWS_CRYPT_50060], GetDigest() [SWS_CRYPT_21116], GetIntermediateDigest() [SWS_CRYPT_50059] o ExportContextState() [SWS_CRYPT_50064].
    • ara::crypto::CryptoErrc::kInvalidInputSize: el tamaño de los datos de entrada o del IV no es válido ([SWS_CRYPT_50060], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50057]).
  • Incompatibilidad y falta de soporte:
    • ara::crypto::CryptoErrc::kUnsupported: la función o configuración no es compatible con el contexto, p. ej., llamadas individuales [SWS_CRYPT_50060], uso de IV en algoritmos sin IV o ausencia de IV en funciones que requieren IV ([SWS_CRYPT_50060], [SWS_CRYPT_50152], [SWS_CRYPT_50153]), resultados intermedios [SWS_CRYPT_50059], hash de claves [SWS_CRYPT_50057] o exportación/importación de estado ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]).
    • ara::crypto::CryptoErrc::kIncompatibleObject y ara::crypto::CryptoErrc::kUsageViolation: el objeto de clave transferido a Update() es incompatible o prohíbe su uso para el cálculo de hash (falta kAllowHashCalculation) [SWS_CRYPT_50057].
    • ara::crypto::CryptoErrc::kInvalidArgument: los datos de estado transferidos a ImportContextState() no son válidos [SWS_CRYPT_50065].
    • ara::crypto::CryptoErrc::kBusyResource: un recurso criptográfico de hardware o software requerido está ocupado ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).

Esta guía de clase se basa exclusivamente en la especificación AUTOSAR Adaptive R25-11 para el módulo crypto. Las afirmaciones sin referencias normativas explícitas representan interpretaciones contextuales.
