Calcula valores hash criptográficos sobre flujos de datos continuos o bloques de memoria individuales.

La clase ara::crypto::cryp::HashFunctionCtx proporciona la interfaz para el cálculo de valores hash criptográficos sobre bloques de memoria y flujos de datos ([SWS_CRYPT_50060]). Las operaciones de streaming requieren respetar el ciclo de procesamiento compuesto por inicialización mediante Start(), transferencia gradual de datos mediante Update(), finalización mediante Finish() y posterior lectura a través de GetDigest() ([SWS_CRYPT_21116]). Todos los métodos están especificados como seguros para subprocesos (thread-safe), garantizan semántica de reversión (rollback) y notifican errores de secuencia o de búfer de manera determinista mediante objetos de resultado.

Contexto

La clase ara::crypto::cryp::HashFunctionCtx define en el módulo crypto de la AUTOSAR Adaptive Platform la interfaz para calcular valores hash criptográficos y sumas de comprobación. Como especialización de CryptoContext, proporciona métodos para llamadas individuales sin estado, así como para procedimientos de streaming con estado. La gestión del ciclo de vida y de la propiedad se realiza típicamente a través del alias de tipo de puntero inteligente Sptr ([SWS_CRYPT_21101]), que está definido como std::shared_ptr<HashFunctionCtx>.

Entre los interlocutores principales se encuentran:

  • Aplicación invocadora: Controla el ciclo de vida del cálculo y transfiere datos de entrada por bloques o como mensaje completo.
  • Áreas de memoria: Los datos de entrada, los vectores de inicialización (IV) y los búferes de salida y de estado se transportan a través de ReadOnlyMemRegion y ReadWriteMemRegion.
  • Objetos de clave: A través de CryptoObject::Sptr pueden incluirse claves criptográficas directamente como fuente de datos en el cálculo del hash ([SWS_CRYPT_50057]).
  • Crypto Provider: Interpretación: es probable que las instancias de HashFunctionCtx se creen típicamente mediante un Crypto Provider asociado; el intercambio de estados de contexto exportados presupone obligatoriamente el mismo Crypto Provider y el mismo ID de algoritmo ([SWS_CRYPT_50065]).

Ciclo de vida

Una instancia de HashFunctionCtx pasa por varios estados discretos durante el procesamiento en streaming:

Diagrama de estados: transiciones de estado del contexto hash durante la inicialización, el procesamiento y la finalización. Fuentes: [SWS_CRYPT_50152], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50058], [SWS_CRYPT_21115], [SWS_CRYPT_50064], [SWS_CRYPT_50065]

Tras la creación, el contexto se encuentra en estado no iniciado. Mediante la llamada a Start() sin IV ([SWS_CRYPT_50152]) o a Start(iv) con vector de inicialización ([SWS_CRYPT_50153]), el contexto pasa a la fase de procesamiento activo. Los cálculos que ya se encuentren en ejecución se descartan implícitamente mediante una nueva llamada de inicio.

En el estado de procesamiento, los datos de entrada se acumulan mediante llamadas repetidas a Update() con fragmentos de datos sin procesar ([SWS_CRYPT_21113]) o claves ([SWS_CRYPT_50057]). A través de GetIntermediateDigest() se puede calcular un resultado intermedio sin finalizar el contexto ni interrumpir el flujo de datos ([SWS_CRYPT_50059]). Una operación de transmisión continua en curso se puede cancelar en cualquier momento mediante Cancel() ([SWS_CRYPT_50058]), lo que hace que el contexto vuelva al estado no iniciado.

La llamada a Finish() transfiere el contexto al estado «finalizado» ([SWS_CRYPT_21115]). Solo en este estado se puede extraer el valor hash resultante a través de GetDigest() ([SWS_CRYPT_21116]) o comprobar directamente contra un valor esperado mediante Compare() ([SWS_CRYPT_50154]).

Para interrumpir y reanudar cálculos posteriormente, se puede consultar el tamaño de búfer requerido mediante GetContextStateSize() ([SWS_CRYPT_50063]) y guardar el estado interno a través de ExportContextState() ([SWS_CRYPT_50064]). La reanudación se realiza a través de ImportContextState() ([SWS_CRYPT_50065]). Todos los métodos de interfaz están declarados como seguros frente a excepciones (exception safe) y seguros para subprocesos (thread-safe).

Ruta de uso

La clase admite dos modos de procesamiento: el cálculo directo en un solo paso y el procesamiento segmentado por transmisión continua.

El cálculo en un solo paso se realiza mediante CalculateHashDigest() ([SWS_CRYPT_50060]). Aquí se transfieren los datos de entrada, un IV opcional y el área de memoria de destino, calculándose el valor hash en una operación atómica.

Para volúmenes mayores de datos o flujos de datos continuos se utiliza la ruta de transmisión continua:

Diagrama de secuencia: Flujo típico del cálculo por transmisión continua mediante Start, Update, Finish y GetDigest. Fuentes: [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116]

  1. Comprobación de capacidad: Consulta del tamaño de salida mediante GetDigestSize() ([SWS_CRYPT_50061]) y del tamaño de bloque máximo a través de GetMaximumChunkSize() ([SWS_CRYPT_50062]).
  2. Inicialización: Preparación del contexto mediante la llamada a Start() ([SWS_CRYPT_50152]) o Start(iv) ([SWS_CRYPT_50153]).
  3. Transferencia de datos: Entrega sucesiva de bloques de datos a través de Update(data) ([SWS_CRYPT_21113]) o de claves mediante Update(key) ([SWS_CRYPT_50057]).
  4. Finalización: Finalización de la acumulación del valor hash mediante Finish() ([SWS_CRYPT_21115]).
  5. Evaluación del resultado: Lectura del valor hash calculado mediante GetDigest() ([SWS_CRYPT_21116]) o comparación in-situ con un valor de referencia a través de Compare() ([SWS_CRYPT_50154]).

Escenarios de error

Los métodos de HashFunctionCtx señalan errores a través de ara::core::Result y garantizan semántica de reversión en caso de fallos. Las causas típicas de error son:

  • Infracciones de secuencia:\nSi se invoca Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) o Cancel() ([SWS_CRYPT_50058]) sin una llamada previa y exitosa a Start(), se devuelve CryptoErrc::kProcessingNotStarted.\nSi se llama a Finish() ([SWS_CRYPT_21115]) o GetIntermediateDigest() ([SWS_CRYPT_50059]) sin inicialización previa, el contexto notifica CryptoErrc::kInvalidUsageOrder.\nLa obtención de resultados a través de GetDigest() ([SWS_CRYPT_21116]) o Compare() ([SWS_CRYPT_50154]) antes de la ejecución de Finish() falla con CryptoErrc::kProcessingNotFinished.
  • Problemas de búfer y de tamaño:\nSi el búfer de salida no es suficiente, CalculateHashDigest() ([SWS_CRYPT_50060]), GetDigest() ([SWS_CRYPT_21116]), GetIntermediateDigest() ([SWS_CRYPT_50059]) así como ExportContextState() ([SWS_CRYPT_50064]) devuelven el error CryptoErrc::kInsufficientCapacity.\nLas longitudes de entrada o de IV no compatibles dan lugar a CryptoErrc::kInvalidInputSize en CalculateHashDigest(), Start(iv) ([SWS_CRYPT_50153]) y Update().
  • Incompatibilidad y falta de compatibilidad con funciones:\nCryptoErrc::kUnsupported señala que no se admiten llamadas individuales ([SWS_CRYPT_50060]), que la presencia de un IV no coincide con la función hash ([SWS_CRYPT_50152], [SWS_CRYPT_50153]), que no se proporcionan resultados intermedios ([SWS_CRYPT_50059]), que no se admite la exportación/importación del contexto ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]) o que no está permitido el cálculo de hash de claves ([SWS_CRYPT_50057]).
  • Validación de objetos y permisos:\nEn las transferencias de claves a través de Update(key), una clave incompatible produce CryptoErrc::kIncompatibleObject y la falta de autorización para kAllowHashCalculation genera CryptoErrc::kUsageViolation ([SWS_CRYPT_50057]).\nLos contenidos de búfer no válidos en ImportContextState() producen CryptoErrc::kInvalidArgument ([SWS_CRYPT_50065]).
  • Cuellos de botella de recursos:\nSi un recurso criptográfico requerido está ocupado, Start() responde al intento con CryptoErrc::kBusyResource ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).

virtual ara::core::Result< std::size_t > CalculateHashDigest (ReadOnly MemRegion data, ReadWriteMemRegion digest, ara::core::Optional< Read OnlyMemRegion > iv) const noexcept=0;

Calculate the hash digest and write the the calculated digest into the provided output buffer.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: adb7aefb7feb Procedencia

El método CalculateHashDigest realiza un cálculo one-shot síncrono de un valor hash criptográfico y escribe el resultado en el búfer de salida proporcionado [SWS_CRYPT_50060]. Se pasan como parámetros el mensaje de entrada a procesar data, el búfer de destino digest y, opcionalmente, un vector de inicialización iv. En caso de ejecución correcta, la función devuelve a través del objeto de resultado ara::core::Result<std::size_t> el número real de bytes de digest escritos [SWS_CRYPT_50060].

Manejo de errores

Si el cálculo falla, la interfaz garantiza una semántica de reversión [SWS_CRYPT_50060]. El resultado puede contener los siguientes códigos de error:

  • ara::crypto::CryptoErrc::kInvalidInputSize: El tamaño de los datos pasados o del vector de inicialización no es compatible [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kUnsupported: El contexto no admite el cálculo mediante llamada única (single-call), o la transferencia del vector de inicialización no coincide con la configuración del contexto (IV requerido pero ausente, o bien IV transferido aunque no es compatible) [SWS_CRYPT_50060].
  • ara::crypto::CryptoErrc::kInsufficientCapacity: La capacidad del búfer de salida digest no es suficiente para el digest calculado [SWS_CRYPT_50060].

Concurrencia e interacción

La función está declarada como segura frente a excepciones (exception safe) y segura frente a hilos (thread-safe) [SWS_CRYPT_50060]. Para evitar de antemano errores relativos a longitudes de entrada no permitidas, el tamaño de búfer máximo permitido del contexto para una única llamada puede determinarse a través de GetMaximumChunkSize [SWS_CRYPT_50062].

          El método Compare de la clase ara::crypto::cryp::HashFunctionCtx ([SWS_CRYPT_50154]) compara de forma síncrona el tamaño y el contenido de un digest hash calculado previamente con un valor de referencia esperado. El valor nominal se transfiere a través del parámetro expected del tipo ReadOnlyMemRegion. En caso de éxito, la función devuelve un ara::core::Result<bool> que contiene true si y solo si la secuencia de bytes esperada es idéntica al digest calculado.
          
  
          El requisito previo para la llamada es que el cálculo del digest se haya concluido previamente con el método Finish(). Si este no es el caso, la llamada falla y devuelve el error ara::crypto::CryptoErrc::kProcessingNotFinished con semántica de reversión ([SWS_CRYPT_50154]).
