Permite a las aplicaciones la notificación segura para subprocesos de Security Events con datos de contexto opcionales al IdsM.

La clase ara::idsm::EventReporter sirve en AUTOSAR Adaptive como interfaz de programación central para notificar eventos de seguridad al Intrusion Detection System Manager [SWS_AIDSM_10101]. Tras la instanciación a través de un ara::core::InstanceSpecifier para el puerto modelado, las aplicaciones transmiten incidentes de manera flexible con contador, marca de tiempo o datos de contexto (versionados) [SWS_AIDSM_10301]. Todos los métodos están especificados explícitamente como seguros para subprocesos y permiten el uso paralelo desde múltiples hilos de aplicación. Dado que todas las interfaces cuentan con noexcept, los errores de transmisión no se notifican al invocador mediante excepciones de C++.

Contexto

La clase ara::idsm::EventReporter sirve en AUTOSAR Adaptive Platform como interfaz de programación primaria para que las aplicaciones funcionales notifiquen eventos relevantes para la seguridad (Security Events) a la gestión del sistema de detección de intrusiones (IdsM) [SWS_AIDSM_10101]. Dentro de la arquitectura de la plataforma, la clase asume un rol de intermediaria entre la lógica de detección específica de la aplicación y los servicios de seguridad de toda la plataforma. Entre las partes de interacción directa se encuentran componentes de software funcionales que identifican anomalías o incidentes críticos de seguridad, la instancia intermediaria EventReporter y el servicio IdsM de la Adaptive Platform, que se encarga del registro, filtrado y procesamiento posterior de eventos de seguridad.

Diagrama de contexto: integración de EventReporter entre la aplicación notificadora y el IdsM. Fuentes: [SWS_AIDSM_10101], [SWS_AIDSM_10301]

Ciclo de vida

La creación de un objeto EventReporter se realiza a través de su constructor transfiriendo un identificador de tipo ara::core::InstanceSpecifier [SWS_AIDSM_10301]. Este vincula la instancia a un puerto modelado en el manifiesto del tipo SecurityEventReportInterface [SWS_AIDSM_10301]. La propiedad recae en la aplicación usuaria; normalmente debería resultar conveniente un mantenimiento de larga duración a lo largo de todo el tiempo de ejecución del componente para evitar vinculaciones repetidas al puerto. En cuanto a la concurrencia, la especificación garantiza una seguridad total para subprocesos: tanto la construcción como todos los métodos para notificar eventos están diseñados como seguros para subprocesos [SWS_AIDSM_10301], [SWS_AIDSM_10302]. De este modo, varios hilos de aplicación pueden utilizar la misma instancia de reporter en paralelo sin necesidad de medidas de sincronización externas.

Ruta de uso

El flujo regular comprende la instanciación del reporter y la posterior notificación de incidentes a través del método ReportEvent. Tras la inicialización con el ara::core::InstanceSpecifier adecuado [SWS_AIDSM_10301], la aplicación selecciona una de las sobrecargas proporcionadas en función de la naturaleza del evento y del nivel de detalle de la información de contexto disponible:

  • Notificación sin contexto: para eventos simples sin datos complementarios, se utiliza la sobrecarga básica, que opcionalmente transmite un recuento de eventos (count, valor por defecto 1) [SWS_AIDSM_10302].
  • Notificación con marca de tiempo: si el evento debe dotarse de un momento de registro explícito, se dispone de una variante con TimestampType [SWS_AIDSM_10303].
  • Notificación con datos de contexto: para transferir datos de diagnóstico o detalles de incidentes, se puede invocar ReportEvent con parámetros de tipo ContextDataType, opcionalmente con o sin una marca de tiempo explícita [SWS_AIDSM_10304], [SWS_AIDSM_10305].
  • Notificación con datos de contexto versionados: si el formato de comunicación está definido de manera estructurada o dependiente de la versión, las sobrecargas con VersionedContextDataType —asimismo con o sin marca de tiempo— proporcionan la interfaz correspondiente [SWS_AIDSM_10306], [SWS_AIDSM_10307].

En cuanto se invoca ReportEvent, el reporter reenvía los datos al subsistema IdsM y regresa inmediatamente a la aplicación.

Diagrama de secuencia: secuencia de interacción típica desde la creación del reporter hasta la notificación del evento. Fuentes: [SWS_AIDSM_10301], [SWS_AIDSM_10304]

Escenarios de error

Como condición previa esencial para el envío de notificaciones, se requiere la construcción exitosa de EventReporter con un identificador de puerto válido definido en el modelo de plataforma [SWS_AIDSM_10301]. En relación con el tratamiento de errores y la seguridad frente a excepciones, todas las interfaces de la clase presentan una particularidad: el constructor y, sin excepción, todas las sobrecargas de ReportEvent están declarados como noexcept [SWS_AIDSM_10301], [SWS_AIDSM_10302], [SWS_AIDSM_10303], [SWS_AIDSM_10304], [SWS_AIDSM_10305], [SWS_AIDSM_10306], [SWS_AIDSM_10307]. No se lanzan excepciones de C++ ni se devuelven objetos de error como ara::core::Result. Si surgen problemas de infraestructura durante la transmisión al IdsM, como cuellos de botella en los búferes o fallos del servicio, es de esperar que se gestionen, descarten o registren internamente en el servicio de plataforma para no bloquear la aplicación notificadora.

Uso e instanciación

Para utilizar la clase se debe crear una instancia a través del constructor parametrizado, que recibe un identificador del tipo const ara::core::InstanceSpecifier& [SWS_AIDSM_10301]. Tratamiento de errores y concurrencia

Interpretación: de este modo, múltiples hilos probablemente puedan instanciar en paralelo instancias de notificador para sus respectivos puertos, sin que se requieran mecanismos de sincronización externos.

Interacción

La interacción con el IdsM se basa en la asignación de la instancia al puerto de modelado correspondiente: mediante la especificación como EventReporter para el SecurityEventReportInterface [SWS_AIDSM_10301], la clase representa la interfaz a través de la cual las aplicaciones adaptativas transmiten eventos de seguridad a la arquitectura de IdsM [SWS_AIDSM_10101].
