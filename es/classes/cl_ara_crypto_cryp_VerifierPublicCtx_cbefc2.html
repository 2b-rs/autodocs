Sirve para la verificación asimétrica de firmas digitales en un procedimiento de paso único o de streaming multietapa.

La interfaz ara::crypto::cryp::VerifierPublicCtx sirve para la verificación de firmas digitales mediante claves públicas asimétricas a través de una llamada One-Shot o un streaming de varios pasos ([SWS_CRYPT_24112], [SWS_CRYPT_50022]). Antes de la verificación, el contexto debe configurarse obligatoriamente con una clave válida cuyos derechos de uso asignados permitan la comprobación de la firma ([SWS_CRYPT_24115]). Todos los métodos de la interfaz están diseñados para ser seguros frente a excepciones y seguros para subprocesos (thread-safe).

Contexto

La interfaz ara::crypto::cryp::VerifierPublicCtx sirve para la verificación de firmas digitales basada en criptografía asimétrica utilizando una clave pública. Interactúa directamente con objetos de clave ([SWS_CRYPT_24115]) o almacenes de claves externalizados ([SWS_CRYPT_50018]) y proporciona métodos para comprobar firmas ya sea en un solo paso (One-Shot) o en streaming a través de varios pasos parciales.

Ciclo de vida

Las instancias del contexto de verificación se gestionan típicamente dentro de la aplicación mediante el alias de tipo de puntero inteligente ara::crypto::cryp::VerifierPublicCtx::Sptr, que está definido como std::shared_ptr<VerifierPublicCtx> ([SWS_CRYPT_24101]). Todos los métodos de la interfaz están declarados como seguros frente a excepciones (exception safe) y seguros para subprocesos (thread-safe).

El contexto pasa por fases operativas claramente delimitadas. Tras su instanciación, el contexto se encuentra en un estado no inicializado en el que las llamadas de verificación se rechazan con ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50019], [SWS_CRYPT_24112]). Solo mediante la asignación de una clave adecuada mediante SetKey() pasa el contexto al estado operativo ([SWS_CRYPT_24115], [SWS_CRYPT_50018]). A partir de este estado, se puede realizar una comprobación atómica o iniciar una sesión de streaming. Tras finalizar ([SWS_CRYPT_50022]) o cancelar ([SWS_CRYPT_50023]) una operación de streaming, es de suponer que el contexto vuelva a estar listo para nuevas comprobaciones.

Diagrama de estados: ciclo de vida y transiciones de estado del contexto de verificación. Fuentes: [SWS_CRYPT_24115], [SWS_CRYPT_50018], [SWS_CRYPT_50019], [SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_50023], [SWS_CRYPT_24112]

Ruta de uso

Para la verificación de firmas hay disponibles dos rutas de procesamiento complementarias:

  • Verificación One-Shot: si el mensaje completo se encuentra en la memoria, se puede llamar directamente a Verify() tras la asignación de la clave mediante SetKey() ([SWS_CRYPT_24115]) ([SWS_CRYPT_24112]). Si el algoritmo admite o requiere datos de contexto específicos de la aplicación, se utiliza la variante sobrecargada con un búfer de contexto adicional ([SWS_CRYPT_50024]). Ambas variantes devuelven un ara::core::Result<bool> cuyo valor booleano indica la validez de la firma.
  • Verificación por streaming: en el caso de grandes volúmenes de datos o de bloques de datos que llegan de forma escalonada, tras SetKey() se llama primero a Start() ([SWS_CRYPT_50019], opcionalmente con búfer de contexto según [SWS_CRYPT_50020]). A continuación, los fragmentos de datos se suministran de forma reiterada con Update() ([SWS_CRYPT_50021]). El tamaño máximo de búfer para secciones individuales puede determinarse previamente mediante GetMaximumChunkSize() ([SWS_CRYPT_50025]). La conclusión la constituye la llamada a Finish() transmitiendo la firma y su identificador de formato ([SWS_CRYPT_50022]). Un streaming en curso puede descartarse en cualquier momento mediante Cancel() ([SWS_CRYPT_50023]).

Diagrama de secuencias: flujo paso a paso de una verificación de firma en el procedimiento de streaming. Fuentes: [SWS_CRYPT_24115], [SWS_CRYPT_50019], [SWS_CRYPT_50021], [SWS_CRYPT_50022]

Escenarios de error

Todos los métodos de modificación de estado y de verificación operan con ara::core::Result y poseen semántica de reversión (rollback) en caso de errores:

  • Configuración de clave: si se transfiere una clave o KeySlot incompatible con el algoritmo, SetKey() devuelve el error CryptoErrc::kIncompatibleObject ([SWS_CRYPT_24115], [SWS_CRYPT_50018]). Si a la clave le falta el derecho de uso kAllowSigVerification, la llamada falla con CryptoErrc::kUsageViolation ([SWS_CRYPT_24115]). Además, SetKey() notifica CryptoErrc::kUnsupported si el contexto solo acepta la otra forma de clave respectivamente (KeySlot o PublicKey).
  • Errores de secuencia y de precondición: si se llama a Update(), Finish() o Cancel() sin una llamada previa exitosa a Start(), fallan con CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_50023]). La llamada a Start() o Verify() sin referencia previa a una clave provoca CryptoErrc::kUninitializedContext ([SWS_CRYPT_50019], [SWS_CRYPT_24112]). En caso de KeySlots referenciados pero vacíos, se notifica CryptoErrc::kEmptyKeySlot.
  • Errores de datos y de formato: los métodos responden a tamaños de búfer no válidos con CryptoErrc::kInvalidInputSize ([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_24112]). Los formatos de firma no compatibles generan CryptoErrc::kUnsupportedFormat, mientras que las firmas con errores estructurales desencadenan CryptoErrc::kInvalidArgument ([SWS_CRYPT_50022], [SWS_CRYPT_24112]). Si los recursos de hardware están ocupados, se devuelve CryptoErrc::kBusyResource.

Uso y semántica

El método Cancel() cancela una operación continua en streaming que se inició previamente mediante Start() y que aún no ha concluido [SWS_CRYPT_50023]. Está definido en la cabecera ara/crypto/cryp/verifier_public_ctx.h como método puramente virtual del contexto ara::crypto::cryp::VerifierPublicCtx [SWS_CRYPT_50023]. La llamada se realiza de forma síncrona y sin argumentos. Como valor de retorno sirve un ara::core::Result<void>, el cual está vacío en caso de éxito y confirma la cancelación correcta de la operación [SWS_CRYPT_50023].

Manejo de errores

Si el procesamiento de datos aún no ha comenzado mediante la llamada al método Start(), la operación de cancelación falla. En este escenario, la función devuelve un resultado de error con el código de error ara::crypto::CryptoErrc::kProcessingNotStarted garantizando semántica de reversión (rollback) [SWS_CRYPT_50023].

Concurrencia y restricciones

La especificación clasifica el método como seguro para subprocesos (thread-safe) y seguro frente a excepciones (exception safe) con la designación noexcept [SWS_CRYPT_50023]. Interpretación: tras la cancelación correcta, es probable que el contexto vuelva al estado inicial previo al comienzo del procesamiento, de modo que se pueda iniciar un nuevo proceso en streaming.

Interacción en el módulo crypt

Este patrón de cancelación uniforme con signatura y tratamiento de errores idénticos se aplica de forma coherente a todos los contextos de streaming del módulo crypt:

  • MessageAuthnCodeCtx para Message Authentication Codes [SWS_CRYPT_50027],
  • SignerPrivateCtx para la generación de firmas digitales [SWS_CRYPT_50041],
  • SymmetricCipherCtx para cifrado y descifrado simétrico [SWS_CRYPT_50046],
  • HashFunctionCtx para operaciones hash criptográficas [SWS_CRYPT_50058],
  • DecryptorPrivateCtx para descifrado asimétrico [SWS_CRYPT_50069],
  • AuthCipherCtx para cifrado autenticado [SWS_CRYPT_50077] así como
  • EncryptorPublicCtx para cifrado asimétrico [SWS_CRYPT_50089].

El valor de retorno es un ara::core::Result<bool>: contiene true en caso de verificación correcta, false en caso de firma errónea o un código de error correspondiente ([SWS_CRYPT_50024]).

                                        •

                                        • 
    
                                      • ara::crypto::CryptoErrc::kUnsupportedFormat o ara::crypto::CryptoErrc::kInvalidArgument, si el formato de firma especificado no es compatible o la firma no se corresponde con el formato ([SWS_CRYPT_50024]),
