Define el dominio de error para el reporte de diagnóstico y traduce códigos de error en mensajes textuales o excepciones.

La clase ara::diag::DiagReportingErrorDomain constituye el dominio de error estandarizado para informes de error en el área de diagnóstico de AUTOSAR Adaptive Platform ([SWS_DM_00996]). Asume la traducción de códigos de error numéricos en mensajes de texto deterministas y admite, en caso necesario, el lanzamiento de los objetos de excepción asociados ([SWS_DM_01001]). Dado que todas las funciones de consulta están diseñadas sin estado y son seguras para subprocesos, el dominio es adecuado para el uso concurrente. Como condición de contorno importante, el manejo de excepciones no participa en la resolución de sobrecarga cuando las excepciones de C++ están deshabilitadas.

Contexto

La clase ara::diag::DiagReportingErrorDomain representa el dominio de error para errores en el sistema de reporte de diagnóstico (Diagnostic Reporting) de AUTOSAR Adaptive ([SWS_DM_00996], AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»). Como implementación final, especializa la clase base ara::core::ErrorDomain y representa el enlace funcional entre la arquitectura de errores genérica y los estados de error relacionados con el diagnóstico. Entre los interlocutores centrales se encuentran los componentes de reporte de diagnóstico, así como instancias de ara::core::ErrorCode que transportan errores de esta área ([SWS_DM_01002]). La clase define el alias de tipo Errc para la enumeración de códigos de error ara::diag::DiagReportingErrc ([SWS_DM_00997], AUTOSAR_AP_SWS_Diagnostics §8.11.7.1.1 «Type Alias: Errc»), así como el alias de tipo Exception para la clase base de excepciones ara::diag::DiagReportingException ([SWS_DM_00998], AUTOSAR_AP_SWS_Diagnostics §8.11.7.1.2 «Type Alias: Exception»). A través del método Name() proporciona el nombre corto estandarizado del dominio de error conforme a [SWS_CORE_90023] ([SWS_DM_01000], AUTOSAR_AP_SWS_Diagnostics §8.11.7 «Class: DiagReportingErrorDomain»).

Diagrama de contexto: integración de DiagReportingErrorDomain en la arquitectura de errores con tipos base e identificadores. Fuentes: [SWS_DM_00996], [SWS_DM_00997], [SWS_DM_00998], [SWS_DM_01002].

Ciclo de vida

Las instancias de ara::diag::DiagReportingErrorDomain se crean a través del constructor predeterminado sin parámetros ([SWS_DM_00999], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Este está declarado como constexpr y noexcept, lo que garantiza una construcción segura en tiempo de compilación o durante el inicio del programa sin asignaciones dinámicas ni riesgos de excepción. Dado que la clase no encapsula datos de estado mutables, no existen transiciones dinámicas del ciclo de vida ni transferencias explícitas de propiedad. Interpretación: típicamente debería tratarse de objetos singleton de larga vida que permanecen disponibles globalmente en el proceso durante todo el tiempo de ejecución. Respecto a la concurrencia, tanto la construcción como todos los métodos de consulta están especificados explícitamente como thread-safe y exception safe ([SWS_DM_00999], [SWS_DM_01000], [SWS_DM_01001]), con lo que se permiten accesos paralelos de múltiples subprocesos sin sincronización externa.

Ruta de uso

La ruta de uso regular radica en la evaluación y resolución de errores de diagnóstico que se integran a través del encabezado #include "ara/diag/diag_error_domain.h" ([SWS_DM_00997], [SWS_DM_00999]). Si se produce un error al reportar información de diagnóstico, este se encapsula típicamente en un ara::core::ErrorCode que referencia el dominio. Para el registro o la visualización, el sistema consulta el método Message(errorCode) ([SWS_DM_01001], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 «Message»). Esta función recibe el valor numérico del error y devuelve el mensaje de texto correspondiente como puntero a una cadena de caracteres constante. La especificación garantiza de forma vinculante que nunca se devuelva un puntero nulo (never nullptr) ([SWS_DM_01001]), lo que permite un procesamiento posterior robusto en servicios de registro sin comprobaciones de puntero nulo. A través de Name() se puede obtener adicionalmente el identificador textual del dominio ([SWS_DM_01000]).

Escenarios de error

Para la escalación dirigida de errores, el dominio proporciona el método ThrowAsException(errorCode) ([SWS_DM_01002]). Este está declarado con noexcept(false) y clasificado formalmente como no seguro frente a excepciones ([SWS_DM_01002]), ya que su finalidad radica en la salida deliberada del flujo de control mediante una excepción. Interpretación: la función debería construir y lanzar internamente una instancia de excepción del tipo DiagReportingException con el errorCode transferido. Una precondición fundamental afecta a la configuración del compilador: si se deshabilitan las excepciones de C++ en la cadena de herramientas, ThrowAsException no participa en la resolución de sobrecarga conforme a [SWS_CORE_10304] ([SWS_DM_01002]). En tales entornos, una llamada falla ya en la compilación, de modo que las comprobaciones de error deben realizarse forzosamente de forma basada en valores mediante códigos de error. Las situaciones potenciales de fallo debidas a códigos de error no válidos son gestionadas por Message() asegurando que siempre se suministre un puntero de texto definido ([SWS_DM_01001]).

El constructor por defecto sin parámetros [SWS_DM_00999] inicializa una instancia del dominio de errores ara::diag::DiagReportingErrorDomain ([SWS_DM_00996], AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 «Default Constructor»). Está declarado como constexpr así como noexcept y crea el dominio de forma síncrona sin valor de retorno. La clase se debe incluir mediante el archivo de cabecera #include "ara/diag/diag_error_domain.h".

La operación está especificada como segura frente a hilos y segura frente a excepciones ([SWS_DM_00999]). Dado que el constructor está definido como noexcept, no se producen excepciones de tiempo de ejecución durante la instanciación. El dominio de errores creado sirve para la clasificación y asignación de errores procedentes de la enumeración DiagReportingErrc ([SWS_DM_00560], alias de tipo Errc en [SWS_DM_00997]), que representa causas de error específicas en la notificación de diagnósticos tales como kAlreadyOffered, kConfigurationMismatch, kDebouncingConfigurationInconsistent o kReportIgnored.

En interacción con el dominio de errores, las funciones miembro Name ([SWS_DM_01000]) y Message ([SWS_DM_01001]) devuelven el nombre de dominio así como los textos de error para los códigos de error pasados. Mediante ThrowAsException ([SWS_DM_01002]) se pueden convertir códigos de error en objetos de excepción del tipo base DiagReportingException ([SWS_DM_00998]), mientras que MakeErrorCode ([SWS_DM_01006]) sirve para crear nuevas instancias de ara::core::ErrorCode. Interpretación: Una instanciación manual mediante este constructor raramente debería ser necesaria en programas de aplicación, ya que el acceso se realiza habitualmente a través de la función singleton global GetDiagReportingDomain ([SWS_DM_01004]).

      usar
      

      El método Message de la clase ara::diag::DiagReportingErrorDomain ([SWS_DM_01001]) sirve para traducir de forma síncrona un código de error numérico (ara::core::ErrorDomain::CodeType errorCode) a un mensaje de texto descriptivo. Como valor de retorno, la función proporciona un puntero de tipo const char * que, según la especificación, nunca es nullptr ([SWS_DM_01001]). Debido al tipo de retorno sin mecanismo de liberación, el puntero probablemente apunte a memoria estática (interpretación). La interfaz se proporciona a través del archivo de cabecera #include "ara/diag/diag_error_domain.h" ([SWS_DM_01001]).
      


      Tratamiento de errores y concurrencia
      

      La función está definida como noexcept así como exception safe ([SWS_DM_01001]). Dado que se garantiza contractualmente que nunca se devuelve un puntero nulo, la función siempre genera una cadena de caracteres válida incluso para códigos de error desconocidos ([SWS_DM_01001]). En cuanto a la concurrencia, Message está especificado como thread-safe ([SWS_DM_01001]). Por lo tanto, las llamadas pueden realizarse en paralelo desde múltiples subprocesos sin sincronización adicional.
      


      Interacción
      

      El método sobrescribe como override el método base homónimo para la traducción de códigos de error en el contexto de Adaptive AUTOSAR ([SWS_DM_01001]). Este patrón de comportamiento uniforme también lo comparten otros dominios de error del módulo de diagnóstico, por ejemplo ara::diag::DiagErrorDomain ([SWS_DM_00522]), ara::diag::DiagUdsNrcErrorDomain ([SWS_DM_00534]), ara::diag::DiagOfferErrorDomain ([SWS_DM_00994]) y ara::diag::DiagSovdErrorDomain ([SWS_DM_01814]).
