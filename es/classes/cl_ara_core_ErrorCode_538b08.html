clase ara::core::ErrorCode

[SWS_CORE_00501] Upstream: RS_AP_00130, RS_AP_00140

class ErrorCode final {...};

Encapsulation of an error code. An ErrorCode contains a raw error code value and an Error Domain. The raw error code value is specific to this ErrorDomain.

Contexto

En la AUTOSAR Adaptive Platform, la clase ara::core::ErrorCode sirve como encapsulamiento central para la información de errores. Un ErrorCode combina un valor numérico bruto de error y un dominio de errores asociado (ara::core::ErrorDomain), interpretándose el valor de error concreto siempre de forma específica para el dominio respectivo. Como medio principal para la transmisión sincrónica y asincrónica de errores, la clase actúa como nexo entre los bloques funcionales llamados que señalan un error y los componentes llamadores que evalúan o reenvían dicho error.

En interacción con el sistema, ara::core::ErrorCode asume la responsabilidad de transportar datos de error de forma inmutable y, en caso necesario, proporcionar textos de error contextuales o excepciones de C++ específicas a través de la ErrorDomain referenciada. De este modo, se desacoplan la lógica de dominio y la representación: el dominio define el significado de los valores, mientras que el objeto ErrorCode encapsula la instancia concreta del error ocurrido.

Diagrama de contexto: integración de ara::core::ErrorCode en interacción con dominios de errores y lógica de aplicación. Fuentes: [SWS_CORE_00512], [SWS_CORE_00513], [SWS_CORE_00515], [SWS_CORE_00519]

Ciclo de vida

Las instancias de ara::core::ErrorCode se crean normalmente de forma directa en el lugar de detección del error. La clase proporciona dos constructores:

  • Un constructor de plantilla que acepta un valor de enumeración específico del dominio (EnumT), así como datos adicionales opcionales específicos del fabricante (ErrorDomain::SupportDataType) [SWS_CORE_00512]. Este constructor es constexpr y noexcept.
  • Un constructor con especificación explícita del valor bruto (ErrorDomain::CodeType), una referencia a la ErrorDomain asociada y datos adicionales opcionales [SWS_CORE_00513], que también está declarado como constexpr y noexcept.

La clase está declarada como final y no posee gestión dinámica de memoria. Dado que todos los métodos de lectura son constantes y seguros frente a excepciones, el objeto está concebido como un objeto de valor ligero (Value Object) (interpretación: probablemente previsto para la transferencia eficiente por valor mediante copia o movimiento). No existe un ciclo de vida con estados internos cambiantes; los valores de error contenidos y la referencia al dominio permanecen inmutables durante toda la vida útil del objeto. En cuanto a la concurrencia, la construcción y todas las operaciones de consulta están especificadas explícitamente como seguras para subprocesos (thread-safe) y seguras frente a excepciones (exception safe) [SWS_CORE_00512] [SWS_CORE_00513] [SWS_CORE_00514] [SWS_CORE_00515] [SWS_CORE_00516] [SWS_CORE_00518].

Ruta de uso

El flujo habitual de uso de ara::core::ErrorCode se divide en la creación, el transporte de retorno al consumidor y el diagnóstico posterior:

  1. Creación del error: si se produce un estado de error dentro de una función, esta crea un objeto ErrorCode indicando el error específico del dominio y datos de contexto opcionales [SWS_CORE_00512] [SWS_CORE_00513].
  2. Retorno: el objeto se devuelve a la parte llamadora.
  3. Consulta del valor: el llamador invoca Value() para consultar el valor bruto específico del dominio de tipo ErrorDomain::CodeType [SWS_CORE_00514].
  4. Identificación del dominio: mediante Domain(), el llamador obtiene una referencia a la ErrorDomain asociada [SWS_CORE_00515] para distinguir errores entre dominios.
  5. Datos adicionales y mensaje de texto: en caso necesario, el consumidor lee información adicional específica del fabricante a través de SupportData() [SWS_CORE_00516] o recupera mediante Message() una descripción textual del error como StringView [SWS_CORE_00518].

Diagrama de secuencia: creación, retorno y evaluación paso a paso de un ErrorCode. Fuentes: [SWS_CORE_00512], [SWS_CORE_00514], [SWS_CORE_00518]

Escenarios de error

Al utilizar ara::core::ErrorCode, deben tenerse en cuenta varias precondiciones y restricciones funcionales:

  • Restricción de tipo en la construcción: según [SWS_CORE_00512], el constructor de plantilla con EnumT solo participa en la resolución de sobrecarga si el parámetro de plantilla EnumT es realmente un tipo de enumeración (enum). Pasar otros tipos provoca un error en la resolución de sobrecarga durante la compilación.
  • Gestión de excepciones mediante ThrowAsException: el método ThrowAsException() convierte el objeto de error en una excepción de C++ concreta y la lanza [SWS_CORE_00519]. Se comporta como si se invocara this->Domain().ThrowAsException(*this). La excepción lanzada encapsula el objeto ErrorCode desencadenante.
  • Desactivación de excepciones de C++: si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador, ThrowAsException() no participa en la resolución de sobrecarga según la especificación [SWS_CORE_00519]. En tales configuraciones de la cadena de herramientas, las llamadas a este método provocan errores del compilador.
  • Seguridad frente a excepciones: mientras que casi todas las funciones miembro (constructores, Domain(), Value(), SupportData(), Message()) están especificadas como noexcept y seguras frente a excepciones (exception safe), ThrowAsException() está declarada explícitamente como noexcept(false) y no segura frente a excepciones (not exception safe) [SWS_CORE_00519], ya que, por definición, lanza una excepción.

Esta guía se basa en la especificación para AUTOSAR Adaptive Platform Release R25-11.

<h4>Contexto</h4>
<p>En la AUTOSAR Adaptive Platform, la clase <code>ara::core::ErrorCode</code> sirve como encapsulamiento central para la información de errores. Un <code>ErrorCode</code> combina un valor numérico bruto de error y un dominio de errores asociado (<code>ara::core::ErrorDomain</code>), interpretándose el valor de error concreto siempre de forma específica para el dominio respectivo. Como medio principal para la transmisión sincrónica y asincrónica de errores, la clase actúa como nexo entre los bloques funcionales llamados que señalan un error y los componentes llamadores que evalúan o reenvían dicho error.</p>
<p>En interacción con el sistema, <code>ara::core::ErrorCode</code> asume la responsabilidad de transportar datos de error de forma inmutable y, en caso necesario, proporcionar textos de error contextuales o excepciones de C++ específicas a través de la <code>ErrorDomain</code> referenciada. De este modo, se desacoplan la lógica de dominio y la representación: el dominio define el significado de los valores, mientras que el objeto <code>ErrorCode</code> encapsula la instancia concreta del error ocurrido.</p>

<h4>Ciclo de vida</h4>
<p>Las instancias de <code>ara::core::ErrorCode</code> se crean normalmente de forma directa en el lugar de detección del error. La clase proporciona dos constructores:</p>
<ul>
<li>Un constructor de plantilla que acepta un valor de enumeración específico del dominio (<code>EnumT</code>), así como datos adicionales opcionales específicos del fabricante (<code>ErrorDomain::SupportDataType</code>) <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>. Este constructor es <code>constexpr</code> y <code>noexcept</code>.</li>
<li>Un constructor con especificación explícita del valor bruto (<code>ErrorDomain::CodeType</code>), una referencia a la <code>ErrorDomain</code> asociada y datos adicionales opcionales <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>, que también está declarado como <code>constexpr</code> y <code>noexcept</code>.</li>
</ul>
<p>La clase está declarada como <code>final</code> y no posee gestión dinámica de memoria. Dado que todos los métodos de lectura son constantes y seguros frente a excepciones, el objeto está concebido como un objeto de valor ligero (Value Object) (interpretación: probablemente previsto para la transferencia eficiente por valor mediante copia o movimiento). No existe un ciclo de vida con estados internos cambiantes; los valores de error contenidos y la referencia al dominio permanecen inmutables durante toda la vida útil del objeto. En cuanto a la concurrencia, la construcción y todas las operaciones de consulta están especificadas explícitamente como seguras para subprocesos (thread-safe) y seguras frente a excepciones (exception safe) <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a> <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a> <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a> <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a> <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a> <a class="spec-record-ref" data-req="SWS_CORE_00518" href="../spec/record.html?id=SWS_CORE_00518">[SWS_CORE_00518]</a>.</p>

<h4>Ruta de uso</h4>
<p>El flujo habitual de uso de <code>ara::core::ErrorCode</code> se divide en la creación, el transporte de retorno al consumidor y el diagnóstico posterior:</p>
<ol>
<li><strong>Creación del error:</strong> si se produce un estado de error dentro de una función, esta crea un objeto <code>ErrorCode</code> indicando el error específico del dominio y datos de contexto opcionales <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a> <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>.</li>

<li><strong>Consulta del valor:</strong> el llamador invoca <code>Value()</code> para consultar el valor bruto específico del dominio de tipo <code>ErrorDomain::CodeType</code> <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a>.</li>
<li><strong>Identificación del dominio:</strong> mediante <code>Domain()</code>, el llamador obtiene una referencia a la <code>ErrorDomain</code> asociada <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a> para distinguir errores entre dominios.</li>

</ol>

<h4>Escenarios de error</h4>
<p>Al utilizar <code>ara::core::ErrorCode</code>, deben tenerse en cuenta varias precondiciones y restricciones funcionales:</p>
<ul>
<li><strong>Restricción de tipo en la construcción:</strong> según <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>, el constructor de plantilla con <code>EnumT</code> solo participa en la resolución de sobrecarga si el parámetro de plantilla <code>EnumT</code> es realmente un tipo de enumeración (enum). Pasar otros tipos provoca un error en la resolución de sobrecarga durante la compilación.</li>
<li><strong>Gestión de excepciones mediante ThrowAsException:</strong> el método <code>ThrowAsException()</code> convierte el objeto de error en una excepción de C++ concreta y la lanza <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. Se comporta como si se invocara <code>this-&gt;Domain().ThrowAsException(*this)</code>. La excepción lanzada encapsula el objeto <code>ErrorCode</code> desencadenante.</li>
<li><strong>Desactivación de excepciones de C++:</strong> si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador, <code>ThrowAsException()</code> no participa en la resolución de sobrecarga según la especificación <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. En tales configuraciones de la cadena de herramientas, las llamadas a este método provocan errores del compilador.</li>
<li><strong>Seguridad frente a excepciones:</strong> mientras que casi todas las funciones miembro (constructores, <code>Domain()</code>, <code>Value()</code>, <code>SupportData()</code>, <code>Message()</code>) están especificadas como <code>noexcept</code> y seguras frente a excepciones (exception safe), <code>ThrowAsException()</code> está declarada explícitamente como <code>noexcept(false)</code> y no segura frente a excepciones (not exception safe) <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>, ya que, por definición, lanza una excepción.</li>
</ul>
