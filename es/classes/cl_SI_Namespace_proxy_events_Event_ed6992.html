Propósito de uso

El proxy crea un contenedor de eventos para cada elemento de la interfaz de servicio modelado como un evento. Después de conectarse a la instancia de servicio, el consumidor se suscribe al evento; el proveedor envía datos a Communication Management, que notifica a los suscriptores. Luego, las muestras se recogen explícitamente a través de GetNewSamples(). EXP ARAComAPI §4.3 «Event and Trigger based communication» §5.3.5 «Events»

Modelo de suscripción, caché y recepción.

Subscribe(maxSampleCount) también establece el presupuesto máximo de la caché de muestra local. La llamada acepta el pedido de forma asincrónica; El estado de la suscripción se puede consultar o monitorear mediante un controlador de cambios de estado. Para aplicaciones cíclicas, el sondeo con GetNewSamples() es suficiente; Las aplicaciones reactivas registran un SetReceiveHandler() que solicita la recopilación cuando llegan nuevos datos. EXP ARAComAPI §5.3.5.1 «Event Subscription and Local Cache» §5.3.5.2 «Monitoring Event Subscription» §5.3.5.5 «Event-Driven vs Polling-Based access»

Propiedad de la muestra

El SamplePtr pasado a la callback transfiere la responsabilidad de una ranura de caché a la aplicación. Mientras se tenga un SamplePtr, esta ranura no se puede reutilizar; esto limita el número de muestras accesibles al mismo tiempo. EXP ARAComAPI §5.3.5.4 «Event Sample Management via SamplePtrs»
