Permite el uso de variantes con seguridad de tipos como claves en contenedores estándar no ordenados mediante valores hash.

La especialización de plantilla proporciona una función hash para tipos union con seguridad de tipos, con el fin de poder utilizarlos de forma fluida en contenedores asociativos de hash. Actúa como un adaptador de función conforme al estándar que lee el estado de una instancia y lo transforma en un valor hash unívoco. El requisito para su uso es la capacidad de generar hash de todos los tipos alternativos contenidos en la lista de tipos. Con un contenido inalterado, la evaluación funciona de forma segura en concurrencia y libre de efectos secundarios.

Contexto

La especialización de plantilla std::hash<ara::core::Variant<Types...>> amplía el marco de cálculo de hash estandarizado de la biblioteca estándar de C++ para el tipo de núcleo de AUTOSAR Adaptive ara::core::Variant. Dentro del módulo core, ara::core::Variant actúa como una unión con seguridad de tipos y optimizada en memoria que puede alojar exactamente una instancia de una lista definida de tipos alternativos en cualquier momento. Para poder utilizar tales estructuras de datos variantes como claves en contenedores asociativos de hash como std::unordered_map o std::unordered_set, es estrictamente necesaria una especialización correspondiente de std::hash.

La especialización media así a la perfección entre los requisitos funcionales de la AUTOSAR Adaptive Platform y los algoritmos y contenedores genéricos de la biblioteca estándar. Permite a los componentes de software indexar, reenviar o almacenar temporalmente de forma eficiente estructuras de datos polimórficas sin conversiones dinámicas de tipos ni functores contenedores personalizados.

Ciclo de vida

El ciclo de vida de la especialización de hash es sumamente ligero y se basa en las convenciones de los functores estándar de C++. La clase no posee variables de estado persistentes ni recursos referenciados. La creación se realiza por tanto de forma trivial a través del constructor predeterminado implícito, típicamente de forma directa en el punto de uso en la pila o como objeto temporal dentro de las operaciones del contenedor.

Dado que la especialización carece de estado, el objeto debería poder copiarse y moverse sin restricciones. La destrucción no requiere una liberación explícita de recursos ni lógica de destructores. En lo que respecta a la concurrencia, la invocación del functor es segura para hilos, siempre que la instancia de ara::core::Variant sobre la que se calcula el hash no sea modificada simultáneamente por otro hilo de ejecución. Varios hilos pueden utilizar la misma instancia del functor de hash o instancias paralelas al mismo tiempo sin necesidad de sincronización externa.

Ruta de uso

El uso típico se realiza indirectamente a través de contenedores asociativos de la biblioteca estándar o directamente mediante la ejecución explícita del operador de llamada operator(). Un caso de uso comienza con la provisión de una instancia inicializada de ara::core::Variant que contiene un valor alternativo concreto.

Al invocar la función hash, se consulta el estado actual de la variante. El cálculo debería realizarse en dos pasos conceptuales: en primer lugar, se determina el discriminador o índice del tipo actualmente contenido. A continuación, el valor concreto contenido en el variant se pasa a la especialización de std::hash adecuada para ese tipo. Finalmente, el índice de tipo y el hash del valor se combinan entre sí para generar el valor hash resultante de tipo std::size_t. Esto garantiza que las variantes con idéntico valor alternativo, pero diferente identidad de tipo, obtengan de forma fiable valores hash distintos.

Escenarios de error

La robustez del cálculo del hash depende en gran medida de los parámetros de plantilla y del estado de la variante pasada. Una condición previa fundamental es que para todos los tipos declarados en el paquete de parámetros Types... exista una especialización funcional de std::hash. Si falta dicha definición para un solo tipo, la compilación falla tan pronto como se instancia el functor de hash.

En tiempo de ejecución, el método presupone que la variante pasada no es inválida. Si el objeto variante subyacente hubiera entrado en un estado vacío debido a una asignación fallida previa por excepción, el comportamiento del cálculo del hash probablemente no esté definido o dé lugar a una excepción en tiempo de ejecución. Además, se espera que el cálculo del hash de los tipos alternativos individuales no lance excepciones para satisfacer los requisitos de las funciones hash estándar.
