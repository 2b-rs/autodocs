Sirve para el cálculo y la verificación basados en claves de Message Authentication Codes criptográficos.

La interfaz permite el cálculo y la verificación basados en claves de Message Authentication Codes para mensajes de cualquier longitud. Tras la inicialización con una clave simétrica mediante [SWS_CRYPT_22118], los digests MAC pueden procesarse bien en un único paso o bien en un procedimiento de streaming mediante llamadas de inicio, actualización y finalización. El resultado de verificación obtenido puede consultarse a continuación o cotejarse directamente con un valor nominal. Todos los métodos están especificados como seguros para subprocesos y señalan flujos defectuosos o capacidades de búfer insuficientes mediante valores de retorno estandarizados de acuerdo con [SWS_CRYPT_22116].

Contexto

La interfaz MessageAuthnCodeCtx define operaciones criptográficas para la generación y verificación de códigos de autenticación de mensajes basados en clave (Message Authentication Codes, MAC). Permite la comprobación de autenticidad e integridad de cantidades arbitrarias de datos, tanto a través de flujos incrementales de datos como a través de bloques de memoria contiguos individuales. La gestión de instancias se realiza a través del tipo de puntero inteligente suministrado Sptr [SWS_CRYPT_22101].

Como interlocutores centrales actúan los componentes de aplicación invocadores así como objetos de clave. Un contexto puede configurarse bien directamente con un objeto de clave simétrica SymmetricKey [SWS_CRYPT_22118] o bien a través de un espacio de almacenamiento lógico KeySlot [SWS_CRYPT_50026]. La transferencia de datos se realiza a través de estructuras de búfer como ReadOnlyMemRegion para datos de entrada así como ReadWriteMemRegion para digests MAC calculados.

Ciclo de vida

Una instancia de contexto atraviesa una secuencia de estados definida desde la inicialización hasta la puesta a disposición del resultado de MAC:

  • Uninitialized: tras la creación, el contexto aún no posee ninguna clave y rechaza las llamadas de cálculo.
  • Configured: mediante la llamada a SetKey() con una clave [SWS_CRYPT_22118] o un almacén de claves [SWS_CRYPT_50026] se inicializa el contexto. En este estado pueden ejecutarse métodos de llamada única (Single-Call) o iniciarse una sesión de streaming.
  • Processing: la llamada a Start() sin vector de inicialización [SWS_CRYPT_22111] o con IV [SWS_CRYPT_22110] abre el procesamiento en streaming. Mediante llamadas repetidas a Update() [SWS_CRYPT_22113] se introducen bloques de datos. Es posible una cancelación a través de Cancel() [SWS_CRYPT_50027].
  • Finished: el método Finish() [SWS_CRYPT_22115] concluye el cálculo. A continuación, el resultado puede consultarse o compararse.

Interpretación: tras la finalización o cancelación, el contexto permanece presumiblemente en el estado configurado y puede reutilizarse para nuevas operaciones. Todos los métodos de la interfaz están especificados como seguros para subprocesos y a prueba de excepciones.

Diagrama de estados: ciclo de vida y transiciones de estado del contexto MAC. Fuentes: [SWS_CRYPT_22118], [SWS_CRYPT_50026], [SWS_CRYPT_22110], [SWS_CRYPT_22111], [SWS_CRYPT_22113], [SWS_CRYPT_22115], [SWS_CRYPT_50027], [SWS_CRYPT_22116], [SWS_CRYPT_50029], [SWS_CRYPT_50031]

Ruta de uso

La interfaz admite dos rutas de uso típicas: streaming incremental y procesamiento de llamada única (Single-Call).

En la ruta de streaming, el invocador vincula primero la clave a través de SetKey() [SWS_CRYPT_22118]. Antes de comenzar, pueden consultarse parámetros del algoritmo como el tamaño de IV recomendado a través de GetRecommendedIvSize() [SWS_CRYPT_50135], así como el tamaño máximo de fragmento a través de GetMaximumChunkSize() [SWS_CRYPT_50033]. Tras la llamada a Start() [SWS_CRYPT_22110], los fragmentos de mensaje se procesan sucesivamente mediante Update() [SWS_CRYPT_22113]. Tan pronto como se han transferido todos los datos, Finish() concluye el cálculo [SWS_CRYPT_22115]. El digest generado se copia a continuación con GetDigest() en un búfer [SWS_CRYPT_22116], cuyo tamaño mínimo puede determinarse previamente mediante GetDigestSize() [SWS_CRYPT_50134]. Alternativamente, Compare() [SWS_CRYPT_50133] o CompareSubspan() [SWS_CRYPT_50028] permiten la comparación directa con un valor de referencia esperado.

Diagrama de secuencias: desarrollo del cálculo incremental de MAC en modo streaming. Fuentes: [SWS_CRYPT_22118], [SWS_CRYPT_22110], [SWS_CRYPT_22113], [SWS_CRYPT_22115], [SWS_CRYPT_22116]

Si el mensaje completo ya está disponible por completo, el cálculo puede realizarse sin streaming mediante Generate() [SWS_CRYPT_50029] o de forma truncada mediante GenerateSubspan() [SWS_CRYPT_50030] en un solo paso. Para la verificación están disponibles de forma análoga los métodos Verify() [SWS_CRYPT_50031] y VerifySubspan() [SWS_CRYPT_50032].

Escenarios de error

Los errores se señalan a través del tipo de retorno ara::core::Result y cubren las siguientes causas:

  • Errores de estado: una llamada a Start(), Generate() o Verify() sin una clave configurada falla con kUninitializedContext [SWS_CRYPT_22110] [SWS_CRYPT_50029]. Las llamadas a Update(), Finish() o Cancel() sin un inicio previo notifican kProcessingNotStarted [SWS_CRYPT_22113] [SWS_CRYPT_22115] [SWS_CRYPT_50027]. Un acceso al resultado antes de la finalización devuelve kProcessingNotFinished [SWS_CRYPT_22116] [SWS_CRYPT_50133].
  • Errores de clave y de permisos: si la clave transferida es incompatible con el contexto, se produce kIncompatibleObject [SWS_CRYPT_22118] [SWS_CRYPT_50026]. Si la clave carece del permiso kAllowMac, esto da lugar a kUsageViolation [SWS_CRYPT_22118] [SWS_CRYPT_22110]. Si la configuración hace referencia a un KeySlot vacío, se notifica kEmptyKeySlot [SWS_CRYPT_22110].
  • Errores de parámetros y de búfer: un búfer de salida demasiado pequeño se rechaza con kInsufficientCapacity [SWS_CRYPT_22116] [SWS_CRYPT_50029]. Longitudes de entrada o de IV no compatibles dan lugar a kInvalidInputSize [SWS_CRYPT_22113] [SWS_CRYPT_50133]. Si el algoritmo no admite modos o configuraciones de IV, se produce kUnsupported [SWS_CRYPT_22110] [SWS_CRYPT_50029]. Los recursos criptográficos de hardware ocupados se notifican con kBusyResource [SWS_CRYPT_22110].

      usar
      

      El método puramente virtual Compare de la clase ara::crypto::cryp::MessageAuthnCodeCtx sirve para cotejar el tamaño y el contenido de un Message Authentication Code (MAC) calculado con un digest esperado [SWS_CRYPT_50133]. Como parámetro, el digest MAC esperado se transfiere a través de ReadOnlyMemRegion expected. La función devuelve un ara::core::Result<bool> que contiene true si el valor MAC calculado coincide exactamente con el valor esperado, y en caso contrario false [SWS_CRYPT_50133].

      En caso de error, se devuelve un código de error en el objeto de resultado, aplicándose una semántica de reversión [SWS_CRYPT_50133]:
      

        

      • ara::crypto::CryptoErrc::kProcessingNotFinished: Se notifica si el cálculo del digest no se ha concluido previamente mediante la llamada al método Finish() [SWS_CRYPT_50133].
        • 

      • ara::crypto::CryptoErrc::kInvalidInputSize: Ocurre si el tamaño de búfer transferido del digest MAC esperado no es compatible con el contexto [SWS_CRYPT_50133].
        • 

      


      Concurrencia y restricciones
      

      El método está declarado como const, así como noexcept, y según la especificación es seguro frente a subprocesos (thread-safe) y seguro frente a excepciones (exception safe) [SWS_CRYPT_50133]. Una condición previa fundamental es el cálculo del digest completado con éxito previamente mediante Finish() [SWS_CRYPT_50133].

      A diferencia de Compare, que valida la coincidencia completa de todo el digest MAC [SWS_CRYPT_50133], CompareSubspan únicamente compara en el mismo contexto los bits más significativos (most significant bits) con el valor esperado [SWS_CRYPT_50028].
