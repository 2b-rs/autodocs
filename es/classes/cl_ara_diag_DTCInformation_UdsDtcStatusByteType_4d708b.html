Representa y comprueba el byte de estado de DTC UDS estandarizado en el módulo de diagnóstico con seguridad de tipos y sin excepciones.

La estructura ara::diag::DTCInformation::UdsDtcStatusByteType encapsula el byte de estado de error UDS estandarizado para la evaluación de entradas de diagnóstico [SWS_DM_00659]. Ofrece métodos de comprobación con seguridad de tipos para bits individuales, así como estados de prueba y de error combinados como IsFailedAndTested() [SWS_DM_02080]. Como tipo por valor constexpr y noexcept, opera con total seguridad frente a excepciones, pero requiere sincronización externa en caso de accesos de lectura concurrentes.

Contexto

La estructura de datos ara::diag::DTCInformation::UdsDtcStatusByteType define en el módulo diag de la AUTOSAR Adaptive Platform la representación del byte de estado de DTC UDS [SWS_DM_00659]. Como tipo anidado dentro del ámbito de ara::diag::DTCInformation, la estructura sirve para encapsular estados de diagnóstico de un Diagnostic Trouble Code (DTC) SWS Diagnostics §8.48.6 «Struct: UdsDtcStatusByteType». La estructura actúa como interfaz para aplicaciones de diagnóstico y componentes internos de diagnóstico con el fin de evaluar información de estado de forma detallada. Mediante funciones de consulta predefinidas, abstrae del enmascaramiento de bits manual y proporciona operaciones de comprobación con seguridad de tipos. La declaración está disponible a través del encabezado #include "ara/diag/dtc_information.h" [SWS_DM_02080]. En una arquitectura de sistema típica, es de suponer que el byte de estado se recibe como portador de información estructurada durante las consultas de diagnóstico procedentes de la gestión de diagnóstico de nivel superior.

Ciclo de vida

Como tipo por valor ligero, UdsDtcStatusByteType está sujeto a un ciclo de vida determinista sin gestión dinámica de recursos. La nueva creación se realiza a través del constructor variádico UdsDtcStatusByteType(bits...), el cual establece directamente los bits de estado pasados en el byte de estado [SWS_DM_02084]. Adicionalmente existen operaciones estándar de copia y movimiento: el constructor de copia está definido como default [SWS_DM_02085], complementado por un constructor de movimiento [SWS_DM_02086], así como los correspondientes operadores de asignación para semántica de copia y movimiento [SWS_DM_02087] [SWS_DM_02088].

En cuanto a la concurrencia, la especificación diferencia con claridad entre creación y uso: el constructor parametrizado, así como el constructor de movimiento, están especificados explícitamente como seguros para subprocesos (thread-safe) [SWS_DM_02084] [SWS_DM_02086]. Por el contrario, los operadores de asignación y todas las funciones miembro de consulta se consideran no seguras para subprocesos (not thread-safe) [SWS_DM_02080] [SWS_DM_02087]. Por lo tanto, un acceso concurrente de lectura o escritura a la misma instancia requiere mecanismos de protección externos. Dado que todas las funciones están declaradas como constexpr y noexcept, las instancias ya pueden construirse y evaluarse en tiempo de compilación.

Ruta de uso

El flujo regular abarca la provisión del objeto seguida de la consulta de estados de diagnóstico concretos. La inicialización se realiza ya sea mediante la especificación explícita de los bits establecidos o adoptando una instancia de estado existente [SWS_DM_02084]. Los parámetros de plantilla para bits de estado admitirían presumiblemente definiciones simbólicas de bits del estándar UDS.

Para evaluar bits individuales o múltiples sirven los métodos variádicos IsSet(bits...) y IsNotSet(bits...), los cuales comprueban si los bits especificados están establecidos o no establecidos, respectivamente [SWS_DM_02082] [SWS_DM_02083]. Como complemento, se dispone de métodos auxiliares especializados para combinaciones estandarizadas de estados UDS: IsFailedAndTested() comprueba si el DTC presenta el estado «Failed» y al mismo tiempo «Tested» [SWS_DM_02080], mientras que IsPassedAndTested() verifica la finalización exitosa sin fallos [SWS_DM_02081].

Diagrama de secuencia: flujo típico durante la inicialización y consulta del byte de estado de DTC. Fuentes: [SWS_DM_02084], [SWS_DM_02082], [SWS_DM_02080]

Escenarios de error

La estructura UdsDtcStatusByteType se caracteriza por una total seguridad frente a excepciones (exception safe) SWS Diagnostics §8.48.6 «Struct: UdsDtcStatusByteType». Todos los constructores, operadores de asignación y métodos de consulta están definidos como noexcept y no lanzan excepciones de C++. Además, no se utilizan códigos de error ni tipos de retorno como ara::core::Result. Los resultados de consulta negativos, por ejemplo cuando los bits requeridos no están establecidos o las pruebas aún no se han ejecutado, representan estados regulares del sistema y se señalizan directamente mediante el valor de retorno booleano false [SWS_DM_02080] [SWS_DM_02082].
