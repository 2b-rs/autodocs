Proporciona Negative Response Codes específicos de UDS para el tratamiento de errores estandarizado en funciones de diagnóstico.

El dominio de error ara::diag::DiagUdsNrcErrorDomain encapsula códigos de error del procesamiento de diagnóstico y los asigna a valores de error estandarizados de UDS [SWS_DM_00529]. Cuando un procesador de diagnóstico externo notifica un error correspondiente, el Diagnostic Server deriva de él un NRC de 1 byte y envía una respuesta negativa de UDS al tester [SWS_DM_02060]. Como condición de contorno fundamental, los valores de NRC derivados deben situarse estrictamente en el rango de valores entre 0x01 y 0xFE.

Contexto

La clase ara::diag::DiagUdsNrcErrorDomain representa el dominio de error estandarizado para errores originados en diferentes clases de diagnóstico (AUTOSAR_AP_SWS_Diagnostics §8.12.3 «Class: DiagUdsNrcErrorDomain»). Como especialización de la clase base ara::core::ErrorDomain [SWS_DM_00529], constituye el enlace fundamental entre el procesamiento de diagnóstico del lado de la aplicación y el protocolo UDS (Unified Diagnostic Services). Dentro de AUTOSAR Adaptive Platform, actúa de intermediaria entre los procesadores de diagnóstico externos o aplicaciones de software y el Diagnostic Server (Diagnostic Management, DM). Si un procesador de diagnóstico externo notifica un error de este dominio durante la ejecución de una orden, la Diagnostic Server Instance lo evalúa de forma específica [SWS_DM_02060]. Además, el dominio interactúa con la comprobación de condiciones ambientales configurables si falla la lectura de elementos de datos [SWS_DM_00970].

Ciclo de vida

La instanciación de ara::diag::DiagUdsNrcErrorDomain se realiza a través del constructor por defecto constexpr DiagUdsNrcErrorDomain() noexcept [SWS_DM_00532]. Este constructor está especificado como seguro frente a excepciones y seguro para subprocesos [SWS_DM_00532]. Debido al diseño constexpr y a la naturaleza de los dominios de error sin funciones adicionales, una instancia debería suministrarse típicamente como un objeto inmutable de ámbito de proceso (interpretación). Asimismo, los métodos de inspección constitutivos Name() [SWS_DM_00533] y Message() [SWS_DM_00534] son seguros para subprocesos y seguros frente a excepciones. Dado que el objeto no gestiona ningún estado mutable, su ciclo de vida está vinculado al contexto global de tiempo de ejecución de la aplicación de diagnóstico y permite un acceso de lectura concurrente sin restricciones.

Ruta de uso

La ruta típica de uso describe la señalización y transformación de un error de diagnóstico durante la ejecución de un servicio:

  1. Un procesador de diagnóstico externo ejecuta una función de diagnóstico y detecta una condición de error.
  2. La aplicación genera un ara::core::Result con un código de error del dominio ara::diag::DiagUdsNrcErrorDomain utilizando el tipo Errc (alias de DiagUdsNrcErrc) [SWS_DM_00530] y lo devuelve a la Diagnostic Server Instance [SWS_DM_02060].
  3. La Diagnostic Server Instance recibe el valor devuelto e identifica la presencia del dominio de error ara::diag::DiagUdsNrcErrorDomain [SWS_DM_02060].
  4. El DM deriva el NRC de UDS a partir del código de error DiagUdsNrcErrc, por ejemplo mediante una static_cast a un valor de NRC de 1 byte [SWS_DM_02059].
  5. El Diagnostic Server responde al tester de diagnóstico solicitante con una respuesta negativa de UDS (negative response) que contiene el valor de NRC derivado [SWS_DM_02060].

Diagrama de secuencia: Derivación y transmisión de un NRC de UDS ante una ejecución de diagnóstico errónea. Fuentes: [SWS_DM_02059], [SWS_DM_02060].

Se aplica un tratamiento especial para peticiones multi-DID: Si bien la aparición de un error de ara::diag::DiagUdsNrcErrorDomain en el resultado indica el fallo del procesador de diagnóstico externo para el elemento individual, puede dar lugar a una respuesta global positiva en caso de solicitarse múltiples DID, siempre que al menos un DID sea soportado en la sesión activa (AUTOSAR_AP_SWS_Diagnostics §7.3 «Multi-DID-Requests»).

Escenarios de error

En el uso y reenvío de errores mediante ara::diag::DiagUdsNrcErrorDomain rigen límites de valores estrictos y reglas de comportamiento:

  • Rango de validez: Los valores de NRC de UDS admisibles derivados de DiagUdsNrcErrc se sitúan exclusivamente en el rango de 0x01 a 0xFE [SWS_DM_02059].
  • Fallo en condiciones ambientales: Si la obtención de un dataElement falla porque un procesador externo notifica un error de ara::diag::DiagUdsNrcErrorDomain, el DM evalúa la expresión DiagnosticEnvConditionFormulaPart como no cumplida y emite un mensaje de Log and Trace [SWS_DM_00970].
  • Tratamiento de excepciones: El método ThrowAsException() convierte un ErrorCode en la excepción correspondiente del tipo Exception (alias de DiagUdsNrcException) [SWS_DM_00531], [SWS_DM_00535]. Esta operación está declarada como no segura frente a excepciones; si las excepciones de C++ están desactivadas, no participa en la resolución de sobrecargas [SWS_DM_00535].
  • Resolución de mensajes: El método Message() proporciona una cadena de texto descriptiva para cada código de error suministrado y garantiza no devolver nunca nullptr [SWS_DM_00534].

Esta guía se basa en la especificación AUTOSAR Adaptive R25-11 y resume los requisitos para el dominio de error DiagUdsNrcErrorDomain.

El constructor por defecto sin parámetros inicializa una instancia del dominio de errores ara::diag::DiagUdsNrcErrorDomain de forma síncrona y sin parámetros de entrada [SWS_DM_00532]. Gracias a la calificación como constexpr, la instanciación ya puede tener lugar en tiempo de compilación AUTOSAR_AP_SWS_Diagnostics §8.12.3.2.1.1 «Default Constructor». En la implementación práctica, sin embargo, es de prever que rara vez sea necesaria una instanciación manual directa de la clase de dominio [SWS_DM_00529] por parte del código de aplicación, ya que, por defecto, la referencia global se obtiene a través de la función GetDiagUdsNrcDomain() [SWS_DM_00536].

En lo relativo a concurrencia y seguridad frente a excepciones, el constructor está especificado como thread-safe y exception safe [SWS_DM_00532]. El dominio gestiona códigos de error del tipo de enumeración DiagUdsNrcErrc mediante el alias Errc [SWS_DM_00530], los cuales se generan mediante MakeErrorCode() [SWS_DM_00537]. Asimismo, la clase proporciona métodos como Name() [SWS_DM_00533], Message() [SWS_DM_00534] y ThrowAsException() [SWS_DM_00535] en el marco de DiagUdsNrcException [SWS_DM_00531].

En interacción con el Diagnostic Management, los errores de este dominio controlan el tratamiento de respuestas negativas. Si una interfaz ara::diag devuelve un error de DiagUdsNrcErrorDomain, el Diagnostic Server deriva a partir de ello una respuesta UDS negativa (NRC) con el valor del código de error en el rango válido de 0x01 a 0xFE [SWS_DM_02059], [SWS_DM_02060]. Si se produce un error de este tipo al consultar un elemento del entorno, el servidor evalúa la condición pertinente como no cumplida y emite un mensaje de registro y seguimiento (Log-and-Trace) [SWS_DM_00970].
