Contexto

La clase de plantilla ara::shwa::Accessor sirve en el módulo shwa como intermediario de acceso tipado y dimensional a áreas de memoria proporcionadas por ara::shwa::Buffer. Mediante sus parámetros de plantilla, configura el tipo de datos (DataT), la dimensionalidad (Dimensions), el modo de acceso (AccessModeType, modo de lectura por defecto), así como el área de memoria y el asignador. Encapsula los recursos de búfer físicos o virtuales y proporciona interfaces controladas de lectura y escritura.

En este caso, Accessor interactúa habitualmente con las siguientes entidades:

  • Aplicación: crea el Accessor, gestiona su propiedad exclusiva e inicia accesos a datos o consultas de propiedades.
  • ara::shwa::Buffer: actúa como base de memoria sobre cuya integridad se apoya el Accessor ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • TaskHandler: puede incluirse opcionalmente en la instanciación para sincronizar tareas de ejecución o procesamiento en relación con el acceso a la memoria ([AP_SWS_SHWA_00008]).

Diagrama de contexto: relaciones de componentes de ara::shwa::Accessor con la aplicación, el búfer y el TaskHandler. Fuentes: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]

Ciclo de vida

La vida útil y la instanciación de ara::shwa::Accessor siguen un estricto control de recursos y de propiedad:

  • Creación: el constructor predeterminado está eliminado ([AP_SWS_SHWA_00002]). Las instancias solo pueden instanciarse a través de los métodos de fábrica estáticos Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Estos validan la referencia de búfer transferida, así como las propiedades opcionales (PropertyList) y, en caso de éxito, devuelven un ara::core::Result<std::unique_ptr<Accessor>>.
  • Propiedad y destrucción: mediante el tipo de retorno std::unique_ptr, la propiedad queda vinculada de forma unívoca y exclusiva al emisor de la llamada. La clase impide totalmente la copia y el movimiento: tanto el constructor de copia ([AP_SWS_SHWA_00003]) y el operador de asignación por copia ([AP_SWS_SHWA_00004]) como el constructor de movimiento ([AP_SWS_SHWA_00005]) y el operador de asignación por movimiento ([AP_SWS_SHWA_00006]) están declarados como eliminados (delete). La eliminación de las operaciones de movimiento probablemente tenga por objeto garantizar que un Accessor permanezca firmemente ligado a su ubicación de origen y al búfer inicial durante toda su existencia. La destrucción se realiza automáticamente al liberar el std::unique_ptr.
  • Concurrencia: los métodos de creación Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]), así como los métodos de acceso síncronos Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]), están especificados explícitamente como seguros frente a hilos. En cambio, los operadores de índice operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) y los métodos de propiedades HasProperty ([AP_SWS_SHWA_00015]) y GetProperty ([AP_SWS_SHWA_00016]) no son seguros frente a hilos y requieren sincronización externa en caso de uso concurrente.

Ruta de uso

Un flujo regular en el uso de un Accessor comprende habitualmente las siguientes fases:

  1. Llamada a la fábrica: la aplicación llama a Create con una referencia a un Buffer existente y configuraciones opcionales o un TaskHandler ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Se comprueba si el resultado es correcto y se asume el std::unique_ptr contenido.
  2. Consulta de propiedades: opcionalmente, la aplicación verifica la presencia de determinadas capacidades a través de HasProperty<PropertyT>() ([AP_SWS_SHWA_00015]) y las lee mediante GetProperty<PropertyT>() ([AP_SWS_SHWA_00016]).
  3. Acceso de escritura: siempre que el AccessModeType lo prevea, los datos se escriben en el búfer a través de Set especificando un índice dimensional Id<Dimensions> ([AP_SWS_SHWA_00011]).
  4. Acceso de lectura: los datos se obtienen de forma segura frente a hilos a través de Get ([AP_SWS_SHWA_00012]). Para accesos directos por referencia sin seguridad frente a hilos, se puede utilizar alternativamente operator[] con ID de índice o índice correlativo ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]), el cual proporciona una referencia tipada ReferenceT ([AP_SWS_SHWA_00014]).
  5. Liberación: al salir del ámbito de aplicación, el emisor de la llamada destruye el std::unique_ptr, con lo que finaliza el acceso.

Diagrama de secuencia: secuencia típica de llamadas para la creación, configuración y uso de un ara::shwa::Accessor. Fuentes: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012], [AP_SWS_SHWA_00015], [AP_SWS_SHWA_00016]

Escenarios de error

Los métodos de Accessor transmiten estados de error a través del tipo ShwaErrorCode en el valor de retorno ara::core::Result:

  • ShwaErrorCode::kAccessorFailure: se produce en Create si la construcción o el uso del Accessor no son válidos ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • ShwaErrorCode::kIntegrityCorrupted: Se notifica mediante Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) y Set ([AP_SWS_SHWA_00011]) si la integridad estructural de la memoria asignada por el búfer está vulnerada o no es verificable.
  • ShwaErrorCode::kInvalidIndex: Se produce en Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]) cuando la operación no se puede ejecutar debido a un índice no válido o a la falta de un valor inicial.
  • ShwaErrorCode::kInvalidAccessMode: Señala en Set ([AP_SWS_SHWA_00011]) que el modo de acceso configurado no permite operaciones de escritura.
  • ShwaErrorCode::kResourceBusy: Se devuelve en Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]) cuando el recurso está ocupado temporalmente.
  • ShwaErrorCode::kFeatureNotSupported: Se produce en GetProperty cuando la propiedad solicitada no está implementada o admitida ([AP_SWS_SHWA_00016]).

En cuanto a la seguridad frente a excepciones, Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]), así como HasProperty ([AP_SWS_SHWA_00015]) y GetProperty ([AP_SWS_SHWA_00016]), están declaradas como seguras frente a excepciones (noexcept), mientras que las operaciones de acceso a datos Get ([AP_SWS_SHWA_00012]), Set ([AP_SWS_SHWA_00011]) y operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) se consideran no seguras frente a excepciones.
