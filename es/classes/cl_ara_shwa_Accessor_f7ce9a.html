Permite el acceso tipificado y controlado de lectura y escritura a áreas de memoria de un búfer.

La clase de plantilla permite el acceso tipificado y controlado a la memoria asignada de un búfer de datos subyacente. La instanciación se lleva a cabo exclusivamente a través de métodos de fábrica estáticos que devuelven la instancia como puntero único ([AP_SWS_SHWA_00007]). En tiempo de ejecución, los datos pueden procesarse a través de operaciones seguras de lectura y escritura o mediante operadores de índice ([AP_SWS_SHWA_00011]). Todas las operaciones de copia y de movimiento están inhibidas, mientras que las operaciones de datos individuales están sujetas a requisitos específicos de seguridad para hilos y tratamiento de errores.

Contexto

La clase de plantilla ara::shwa::Accessor constituye la interfaz de acceso central para el acceso tipificado a memoria en búferes de memoria compartida (Shared Memory) en AUTOSAR Adaptive Platform. Encapsula la lógica de direccionamiento y acceso a un ara::shwa::Buffer subyacente y lo parametriza estáticamente a través del tipo de datos (DataT), la dimensionalidad (Dimensions), el modo de acceso (AccessModeType), el dispositivo de destino (AccessTargetType), así como el asignador de memoria utilizado (AllocatorT). En escenarios avanzados, la clase integra un TaskHandler que presumiblemente controla tareas de procesamiento en el entorno del búfer.

Dentro del módulo, la clase opera en interacción con tres interlocutores centrales:

  • Aplicación / Invocador: solicita instancias a través de la interfaz de fábrica y lleva a cabo operaciones de lectura o escritura a través de métodos u operadores.
  • ara::shwa::Buffer: proporciona el área de memoria asignada y se pasa como referencia al Accessor durante su creación ([AP_SWS_SHWA_00007]).
  • TaskHandler: se registra según sea necesario durante la creación para coordinar tareas en el tratamiento de búferes ([AP_SWS_SHWA_00008]).

Diagrama de contexto: interlocutores de interacción de ara::shwa::Accessor. Fuentes: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008].

Ciclo de vida

El ciclo de vida de ara::shwa::Accessor está sujeto a estrictas restricciones semánticas que evitan la duplicación o el movimiento incontrolados de instancias de acceso. El constructor predeterminado está explícitamente eliminado ([AP_SWS_SHWA_00002]). Del mismo modo, tanto el constructor de copia ([AP_SWS_SHWA_00003]) como el constructor de movimiento ([AP_SWS_SHWA_00005]), así como todos los operadores de asignación por copia y por movimiento, están declarados como eliminados ([AP_SWS_SHWA_00004], [AP_SWS_SHWA_00006]). Queda así excluida una instanciación directa en la pila o una semántica por valor.

La creación de nuevas instancias se realiza exclusivamente a través del método de fábrica estático Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Este devuelve un ara::core::Result<std::unique_ptr<Accessor>>, con lo cual la propiedad se transfiere de forma exclusiva al invocador. El objeto se destruye automáticamente en cuanto el std::unique_ptr propietario sale de su ámbito de validez. Los métodos de creación están especificados como seguros para hilos (thread-safe) y seguros ante excepciones (exception safe) ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).

En cuanto a la concurrencia durante el funcionamiento continuo, los métodos de acceso explícitos Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]) están clasificados como seguros para hilos (thread-safe). Por el contrario, los accesos indexados mediante operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]), así como las consultas de propiedades a través de HasProperty ([AP_SWS_SHWA_00015]) y GetProperty ([AP_SWS_SHWA_00016]), no son seguros para hilos y requieren sincronización por parte de la aplicación.

Ruta de uso

Un flujo de uso regular se divide en la creación del objeto, la comprobación opcional de propiedades y las posteriores operaciones de lectura o escritura en el búfer:

  1. Instanciación mediante Factory: la aplicación invoca Accessor::Create y transfiere la referencia a un ara::shwa::Buffer, así como opcionalmente propiedades de configuración y un TaskHandler ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Tras comprobar el ara::core::Result, la aplicación asume el std::unique_ptr<Accessor>.
  2. Evaluar propiedades: a través del método de plantilla HasProperty<PropertyT>() se puede consultar si una característica específica está presente ([AP_SWS_SHWA_00015]). Las características presentes se leen a continuación con GetProperty<PropertyT>() ([AP_SWS_SHWA_00016]).
  3. Ejecutar acceso a datos: para el intercambio de datos propiamente dicho existen dos rutas de interfaz disponibles:
    • Acceso basado en métodos: las operaciones de escritura se realizan mediante Set(index, value) ([AP_SWS_SHWA_00011]) y las de lectura mediante Get(index) ([AP_SWS_SHWA_00012]), direccionadas en cada caso a través de un identificador dimensional (Id<Dimensions>).
    • Acceso basado en operadores: el operador de indexación operator[] permite el direccionamiento directo mediante Id<Dimensions> ([AP_SWS_SHWA_00009]) o un desplazamiento lineal de tipo std::size_t ([AP_SWS_SHWA_00010]). El tipo de retorno ReferenceT se resuelve en const DataT& para el acceso de lectura y en DataT& para el acceso de escritura ([AP_SWS_SHWA_00014]).

Diagrama de secuencia: secuencia típica de llamadas para la interacción con el búfer mediante Accessor. Fuentes: [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012], [AP_SWS_SHWA_00015]

Escenarios de error

Las operaciones erróneas se representan a través del ara::core::Result mediante códigos de error de ShwaErrorCode:

  • ShwaErrorCode::kAccessorFailure: se produce durante Create si las condiciones de construcción o los parámetros no son válidos ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • ShwaErrorCode::kIntegrityCorrupted: señala una integridad de memoria vulnerada del búfer. Esto puede ocurrir durante la instanciación ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) así como al escribir mediante Set ([AP_SWS_SHWA_00011]).
  • ShwaErrorCode::kInvalidIndex: se notifica en Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]) si no hay disponible un valor inicial válido o si el índice se encuentra fuera de los límites.
  • ShwaErrorCode::kInvalidAccessMode: se produce en Set si la combinación de los modos de acceso no es válida ([AP_SWS_SHWA_00011]); es de suponer que este sea el caso si se realiza una llamada de escritura en una clase instanciada para AccessMode::kRead.
  • ShwaErrorCode::kResourceBusy: indica en Get ([AP_SWS_SHWA_00012]) y Set ([AP_SWS_SHWA_00011]) que el recurso está ocupado actualmente. Para este error se garantiza una semántica de reversión (rollback), por lo que se conserva el estado anterior.
  • ShwaErrorCode::kFeatureNotSupported: se devuelve si una propiedad solicitada a través de GetProperty no es compatible ([AP_SWS_SHWA_00016]).

En cuanto a la seguridad frente a excepciones, Create, HasProperty y GetProperty están declarados con noexcept y especificados como seguros frente a excepciones ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008], [AP_SWS_SHWA_00015], [AP_SWS_SHWA_00016]). En cambio, las operaciones de acceso a datos Get, Set y operator[] se consideran no seguras frente a excepciones (not exception safe) ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012]).
