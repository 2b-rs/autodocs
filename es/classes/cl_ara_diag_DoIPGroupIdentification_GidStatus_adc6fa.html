Recibe datos de respuesta positiva de la identificación de grupos DoIP para su reenvío por parte de Diagnostic Management.

La estructura ara::diag::DoIPGroupIdentification::GidStatus sirve como contenedor de datos para los datos de respuesta positiva en la consulta de la identificación de grupos DoIP [SWS_DM_00721]. Es proporcionada por una Adaptive Application cuando Diagnostic Management solicita la identificación de grupos a través de la interfaz GetGidStatus si DoIpInstantiation.gid no está configurado [SWS_DM_00813]. La estructura transporta los valores de GID determinados directamente a Diagnostic Manager para su reenvío en el protocolo DoIP. Está estrictamente limitada a respuestas exitosas y no contiene mecanismos para escenarios de error.

Contexto

La estructura de datos ara::diag::DoIPGroupIdentification::GidStatus representa los datos de respuesta positiva para la identificación de grupos en el subsistema DoIP (Diagnostic over IP) de AUTOSAR Adaptive Platform [SWS_DM_00721], AUTOSAR_AP_SWS_Diagnostics §8.34.2 «Struct: GidStatus». Sirve como contenedor de resultados estandarizado para datos de identificación de grupo (GID) cuando clientes de diagnóstico externos solicitan información para la identificación del vehículo o de grupos a través de DoIP. En el conjunto del sistema interactúan tres interlocutores principales: el cliente DoIP externo, AUTOSAR Diagnostic Management (DM) y la Adaptive Application específica de la aplicación que ofrece la interfaz ara::diag::DoIPGroupIdentification. Siempre que el GID no esté almacenado estáticamente mediante el parámetro de configuración DoIpInstantiation.gid, el DM está obligado según la especificación a consultar el GID a través de la interfaz de aplicación [SWS_DM_00813], AUTOSAR_AP_SWS_Diagnostics §8.34.1 «Providing the GID in DoIP protocol messages using application interface».

Ciclo de vida

Como estructura de datos de C++ (struct), GidStatus no posee un ciclo de vida propio de proceso o servicio, sino que actúa como un mero objeto de transferencia de datos [SWS_DM_00721]. La Adaptive Application responsable instancia una instancia de GidStatus y la llena con los datos de identificación actuales en cuanto se invoca el método de consulta GetGidStatus [SWS_DM_00724], AUTOSAR_AP_SWS_Diagnostics §8.34.1.1.3.1 «GetGidStatus». Interpretación: la estructura debería crearse típicamente como un objeto de valor temporal en la pila y transferirse al DM como parte del valor de retorno mediante copia o semántica de movimiento, con lo cual su ciclo de vida finaliza tras el procesamiento del mensaje DoIP en el DM. Pregunta Q-4974fdbc2c6accbb (abierta) Dado que pueden producirse múltiples peticiones de diagnóstico o procesamientos paralelos de mensajes DoIP, los datos contenidos dentro de la estructura deben proporcionarse de forma segura para hilos o generarse aisladamente para cada contexto de consulta.

Ruta de uso

El uso típico de GidStatus se divide en una secuencia fija de interacción entre el cliente DoIP, Diagnostic Management y la Adaptive Application:

Diagrama de secuencias: flujo de provisión de GidStatus a través de GetGidStatus con GID no configurado. Fuentes: [SWS_DM_00721], [SWS_DM_00724], [SWS_DM_00813].

  1. Un cliente DoIP externo envía una petición de diagnóstico o de identificación al vehículo a través de la red DoIP.
  2. Diagnostic Management comprueba la configuración: si DoIpInstantiation.gid no está configurado, el DM solicita la identificación de grupos a la Adaptive Application a través de GetGidStatus [SWS_DM_00813], [SWS_DM_00724].
  3. La Adaptive Application determina las características de identificación de grupos, crea una instancia de GidStatus con los datos de respuesta positiva y la devuelve al DM [SWS_DM_00721].
  4. El DM extrae los datos de GidStatus y envía el mensaje de protocolo DoIP completo al cliente DoIP externo [SWS_DM_00813].

Escenarios de error

La especificación define GidStatus expresamente como datos de respuesta positiva («Response data of positive response message») [SWS_DM_00721], AUTOSAR_AP_SWS_Diagnostics §8.34.2 «Struct: GidStatus». Interpretación: si la Adaptive Application no está en condiciones de proporcionar la identificación de grupos, o si se produce un error interno, no debería devolverse ninguna instancia regular de GidStatus; en su lugar, el método GetGidStatus debería señalizar un error al DM mediante mecanismos de error estandarizados de la plataforma (como códigos de error en ara::core::Result). Pregunta Q-01181eb14d27eeb2 (abierta) Además, el contexto de interfaces DoIP relacionadas como ara::diag::DoIPPowerMode [SWS_DM_00814] pone de manifiesto que el DM utiliza valores por defecto o de sustitución definidos cuando las interfaces aún no se ofrecen [SWS_DM_01525]; para la identificación de grupos, la ausencia de datos de respuesta válidos requiere un tratamiento negativo correspondiente en el protocolo DoIP, ya que sin GID no se puede transmitir ninguna respuesta positiva válida [SWS_DM_00813].
