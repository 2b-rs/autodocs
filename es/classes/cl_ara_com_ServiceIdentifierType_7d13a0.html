clase ara::com::ServiceIdentifierType

[SWS_CM_11510] Upstream: RS_CM_00200, RS_CM_00500

class ServiceIdentifierType {...};

Contexto

La clase ara::com::ServiceIdentifierType sirve en el módulo Communication Management (com) de AUTOSAR Adaptive Platform como representación con seguridad de tipos de un identificador de servicio ([SWS_CM_11510]). Está anclada en el archivo de cabecera ara/com/service/service_identifier.h (SWS CommunicationManagement §8.10). Su responsabilidad principal consiste en identificar de manera unívoca los tipos de servicio en el framework de comunicación para que el software de aplicación pueda direccionarlos, ordenarlos y gestionarlos.

En la arquitectura del sistema, ara::com::ServiceIdentifierType interactúa con tres participantes esenciales:

  • Communication Management Software Provider: el tipo concreto no tiene por qué estar predeterminado de forma rígida, sino que el respectivo proveedor de software de la plataforma de comunicación puede sobrescribirlo e implementarlo específicamente (SWS CommunicationManagement §8.10.1). No obstante, es obligatorio cumplir los conceptos de C++ requeridos.
  • Interfaces de servicio: las definiciones de servicio proporcionan típicamente una constante estática denominada serviceIdentifier de tipo ara::com::ServiceIdentifierType (SWS CommunicationManagement §8), que representa el identificador de tipo unívoco del servicio respectivo.
  • Aplicación (Application): el software de aplicación utiliza instancias de ara::com::ServiceIdentifierType para asociar instancias encontradas, gestionar servicios en contenedores, comparar identificadores, así como generar información de registro y diagnóstico (SWS CommunicationManagement §8.10.1).

Diagrama de contexto: integración e interlocutores de ServiceIdentifierType. Fuentes: SWS CommunicationManagement §8.10.1, SWS CommunicationManagement §8, [SWS_CM_11510].

Ciclo de vida

ara::com::ServiceIdentifierType está diseñado como un objeto de valor ligero (Value Object) con semántica de valor regular. El objeto no pasa por fases de estado internas, por lo que su ciclo de vida está vinculado directamente a la validez de la región de memoria:

  • Creación y origen: las instancias existen bien como constantes estáticas del sistema de comunicación —como la constante serviceIdentifier (SWS CommunicationManagement §8)— o bien se crean en el contexto de la aplicación mediante copia.
  • Capacidad de copia y asignación: conforme a [SWS_CM_11510] y [SWS_CM_11513], el tipo cumple con el concepto [copyassignable] según la norma ISO/IEC 14882:2014. El operador de asignación operator= permite asignar y duplicar identificadores existentes en estructuras de datos definidas por el usuario (SWS CommunicationManagement §8.10.1.1.1.1).
  • Posesión y destrucción: la propiedad recae siempre en el contexto declarativo (principio RAII). No se contempla una gestión manual de recursos ni llamadas explícitas de liberación; la limpieza se lleva a cabo al salir del ámbito mediante el destructor de la implementación del proveedor.
  • Concurrencia: no hay mecanismos de sincronización integrados para operaciones de escritura (como asignaciones). Los accesos de lectura paralelos a instancias inmutables (const) no son críticos, mientras que los accesos modificadores deben sincronizarse externamente en caso de uso concurrente por parte de la aplicación (Interpretación).

Ruta de uso

El flujo típico al utilizar ara::com::ServiceIdentifierType se divide en los siguientes pasos sucesivos:

  1. Obtención del identificador: la aplicación accede a la constante estática serviceIdentifier del servicio de destino (SWS CommunicationManagement §8) o recibe una instancia a través de interfaces de Communication Management.
  2. Almacenamiento y estructuración: mediante el operador de asignación por copia operator= ([SWS_CM_11513]), el identificador de servicio se almacena en objetos o contenedores propios de la aplicación. Dado que el tipo cumple obligatoriamente el concepto [lessthancomparable] a través de operator< ([SWS_CM_11512]) (SWS CommunicationManagement §8.10.1), es adecuado como tipo de clave en contenedores asociativos ordenados.
  3. Comprobación de igualdad e identidad: para verificar si dos identificadores designan el mismo servicio, se utiliza el operador de igualdad operator== ([SWS_CM_11511]), que implementa el requisito de C++ [equalitycomparable]. Este devuelve true en caso de identidad y false en caso de desigualdad.
  4. Diagnóstico y registro: para fines de registro (logging) y seguimiento de la ejecución, la clase proporciona el método toString() ([SWS_CM_11514]). Este devuelve una representación legible en cadena de caracteres como ara::core::StringView, lo que permite el registro sin asignación obligatoria en el heap.

Escenarios de error

Dado que ara::com::ServiceIdentifierType es un objeto de valor, no se utilizan retornos de error a través de ara::core::Result ni códigos de error específicos de AUTOSAR. No obstante, deben tenerse en cuenta las siguientes particularidades específicas del sistema:

  • Seguridad frente a excepciones (Exception Safety): todas las funciones miembro —en particular operator= ([SWS_CM_11513]), operator< ([SWS_CM_11512]), operator== ([SWS_CM_11511]) y toString() ([SWS_CM_11514])— se identifican explícitamente en la especificación como not exception safe. En la práctica, esto significa que la especificación de AUTOSAR no prescribe ninguna garantía noexcept para las implementaciones del proveedor y que las aplicaciones no deben asumir una ausencia estricta de excepciones (Interpretación).
  • Precondiciones: los operadores presuponen que el argumento transferido other hace referencia a una instancia intacta y compatible con el tipo (SWS CommunicationManagement §8.10.1.1.2.1). La desreferenciación de punteros no válidos u objetos destruidos da lugar a un comportamiento indefinido.
  • Tiempo de vida de las vistas de cadenas: el método toString() devuelve un ara::core::StringView ([SWS_CM_11514]). Esta vista no tiene propiedad sobre los datos de caracteres subyacentes; si el búfer referenciado o el objeto de origen dejan de ser válidos, el acceso a la vista da lugar a referencias huérfanas (Dangling Pointers) (Interpretación).
