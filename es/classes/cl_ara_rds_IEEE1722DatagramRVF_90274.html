Encapsula metadatos y campos de encabezado de datagramas IEEE 1722 para flujos de datos de vídeo sin comprimir.

La clase ara::rds::IEEE1722DatagramRVF representa, dentro del módulo de AUTOSAR Raw Data Stream, datagramas IEEE 1722 específicos para el formato Raw Video Format destinados a la transmisión estructurada de flujos de vídeo sin comprimir SWS RawDataStream §1 «Raw Data Stream». Agrupa todos los metadatos relevantes para la imagen y la transmisión, como números de líneas, espacios de color, frecuencias de cuadro y bits de control de protocolo en campos opcionales protegidos. Como estructura de datos declarada como final, excluye cualquier herencia adicional, pero asegura una liberación determinista y libre de excepciones a través de punteros a la clase base mediante un destructor virtual [SWS_RDS_90292].

Contexto

La clase ara::rds::IEEE1722DatagramRVF representa, dentro del módulo funcional Raw Data Stream (rds) de la AUTOSAR Adaptive Platform, un datagrama IEEE 1722 concreto para el Raw Video Format (RVF) SWS RawDataStream §1 «Raw Data Stream». El Raw Video Format sirve para el transporte de flujos de vídeo sin comprimir a través de redes basadas en paquetes en el marco de Audio Video Bridging (AVB) y Time-Sensitive Networking (TSN). La estructura de datos se define en el archivo de encabezado ara/rds/raw_data_stream_IEEE1722.h [SWS_RDS_90276]. La definición de la clase incluye la palabra clave final e incorpora, mediante herencia protegida (protected), tanto la clase base genérica IEEE1722Datagram como AVTPDUCommonStreamHeaderFields [SWS_RDS_90276]. Gracias a esta composición, la estructura aúna campos fundamentales de encabezado de flujo AVTP con los campos de metadatos específicos requeridos para el procesamiento de líneas de vídeo individuales y tramas de imagen.

Diagrama de contexto: Integración de IEEE1722DatagramRVF en la jerarquía de clases con IEEE1722Datagram y AVTPDUCommonStreamHeaderFields. Fuentes: [SWS_RDS_90276], SWS RawDataStream §1 «Raw Data Stream»

Ciclo de vida

El ciclo de vida de una instancia de IEEE1722DatagramRVF viene determinado en gran medida por la canalización de procesamiento del Raw Data Stream. Para la limpieza correcta de las instancias, la clase declara un destructor virtual virtual ~IEEE1722DatagramRVF() noexcept [SWS_RDS_90292]. Aunque la clase en sí está marcada como final [SWS_RDS_90276] y, por tanto, no puede actuar como clase base para subclases derivadas, el diseño virtual del destructor asegura la liberación correcta en caso de que las instancias se referencien y destruyan polimórficamente mediante punteros a la clase base.

La indicación adicional noexcept en el destructor garantiza que, bajo ninguna circunstancia, puedan escapar excepciones durante el proceso de destrucción [SWS_RDS_90292]. En sistemas de automoción críticos para la seguridad, esta es una condición previa esencial para garantizar procesos de limpieza deterministas sin interrupciones abruptas del programa. La especificación de AUTOSAR no define primitivas de sincronización explícitas para el acceso concurrente a esta clase de datos; por consiguiente, el manejo seguro para subprocesos debe garantizarse, en caso necesario, en el nivel de los servicios de transmisión continua circundantes.

Ruta de uso

En el flujo de procesamiento práctico, la clase actúa como portadora de información para fotogramas de vídeo recibidos o que se van a enviar. En este contexto, la estructura agrupa numerosos campos que describen detalladamente las dimensiones de la imagen, la referencia temporal y la codificación de color. Para la estructura geométrica del vídeo están disponibles los píxeles activos active_pixels [SWS_RDS_90276], el número total de líneas de una imagen total_lines [SWS_RDS_90278], el número de línea line_number [SWS_RDS_90291] y el número de líneas por paquete de datos num_lines [SWS_RDS_90289].

Para la interpretación correcta del flujo de datos de píxeles, la clase encapsula además propiedades del formato de vídeo específicas del sistema: la profundidad de bits por píxel pixel_depth [SWS_RDS_90285], el formato de píxel pixel_format [SWS_RDS_90286], el espacio de color colorspace [SWS_RDS_90288] así como la frecuencia de refresco frame_rate [SWS_RDS_90287]. A esto se añaden bits de estado y de control específicos de AVTP del protocolo de transmisión: el campo ap [SWS_RDS_90279], el indicador f [SWS_RDS_90280], el campo ef [SWS_RDS_90281], campos de eventos como evt [SWS_RDS_90282] y pd [SWS_RDS_90283], el indicador i [SWS_RDS_90284] así como el número de secuencia i_seq_num [SWS_RDS_90290].

Llama la atención el encapsulamiento continuo de todas las variables en ara::core::Optional. Esta declaración sugiere que los datagramas pueden presentar encabezados incompletos o que ciertos metadatos solo se transmiten según sea necesario en función del perfil de empaquetado AVTP. Todos los atributos cuentan con el nivel de protección protected [SWS_RDS_90276], [SWS_RDS_90278]. Puesto que una derivación mediante código de usuario es imposible debido a final, es probable que el acceso de lectura y escritura a estos campos se implemente mediante clases auxiliares internas o instancias de controladores amigas del módulo RDS.

Esta guía se basa en la especificación AUTOSAR Adaptive Platform R25-11.
