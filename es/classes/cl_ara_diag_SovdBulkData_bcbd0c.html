Contexto

La clase base abstracta ara::diag::SovdBulkData constituye en la AUTOSAR Adaptive Platform la interfaz central para el manejo de datos masivos (Bulk Data) en el marco de Service-Oriented Vehicle Diagnostics (SOVD) [SWS_DM_01841], AUTOSAR_AP_SWS_Diagnostics p. 701. Es implementada por aplicaciones adaptativas para proporcionar o recibir datos de diagnóstico y operativos, tales como registros de errores, trazas o paquetes de software para clientes de diagnóstico externos.

En la interacción participan al menos tres partes:

  • Cliente SOVD: una entidad externa que solicita operaciones de Bulk Data mediante llamadas estandarizadas REST/HTTP según ISO 17978-3 o ASAM SOVD.
  • Diagnostic Management (DM): el AUTOSAR Diagnostic Server recibe solicitudes y las reenvía a la instancia registrada de ara::diag::SovdBulkData, siempre que el servicio haya sido habilitado previamente mediante Offer() [SWS_DM_01857].
  • Handler de la aplicación: la especialización de ara::diag::SovdBulkData específica de la aplicación que atiende los métodos virtuales de callback concretos para consultas de metadatos [SWS_DM_01791], [SWS_DM_01853], descarga de datos [SWS_DM_01792], [SWS_DM_01873], subida de datos [SWS_DM_01793], [SWS_DM_01854], así como la eliminación de datos [SWS_DM_01855], [SWS_DM_01856].

Diagrama de contexto: interacción entre el cliente SOVD, Diagnostic Management y el handler SovdBulkData. Fuentes: [SWS_DM_01841], [SWS_DM_01857], AUTOSAR_AP_SWS_Diagnostics p. 222, [SWS_DM_01791], [SWS_DM_01792].

Ciclo de vida

La clase ara::diag::SovdBulkData atraviesa un ciclo de vida claramente definido compuesto por instanciación, registro del servicio, funcionamiento operativo y destrucción:

  • Creación: la instanciación se realiza a través del constructor pasando un ara::core::InstanceSpecifier, que hace referencia a un PortPrototype de un DiagnosticSovdBulkDataInterface, así como un parámetro del tipo ConcurrencyType [SWS_DM_01847]. El propio constructor es seguro para hilos (thread-safe).
  • Semántica de copia y movimiento: la instancia representa una interfaz exclusiva por puerto. El constructor de copia [SWS_DM_01848] y el operador de asignación por copia [SWS_DM_01850] están eliminados (=delete). El constructor de movimiento [SWS_DM_01849] y el operador de asignación por movimiento [SWS_DM_01851] están especificados con visibilidad protegida (protected).
  • Gestión de estados: tras la creación, el objeto se encuentra en estado de reposo. La llamada a Offer() activa el reenvío de mensajes SOVD entrantes por parte del DM al handler [SWS_DM_01857]. Mediante StopOffer() se desactiva de nuevo este reenvío [SWS_DM_01858].
  • Destrucción: el destructor ~SovdBulkData() está declarado como virtual [SWS_DM_01852], AUTOSAR_AP_SWS_Diagnostics p. 702. Antes de destruir una instancia, es probable que en la práctica de la aplicación se llame regularmente a StopOffer() para concluir de forma ordenada las solicitudes pendientes.
  • Concurrencia: el ConcurrencyType pasado en el constructor determina si las implementaciones de los métodos virtuales específicas de la aplicación deben diseñarse como seguras para hilos (kConcurrent) o no seguras para hilos (kNotConcurrent) [SWS_DM_01847]. Los métodos de control Offer() y StopOffer(), así como el destructor, están especificados como no seguros para hilos (not thread-safe) y requieren llamadas desde un contexto protegido [SWS_DM_01857], [SWS_DM_01858], [SWS_DM_01852].

Ruta de uso

Una ruta de uso típica comprende el registro del handler y el procesamiento asíncrono de solicitudes de transferencia de Bulk Data, ilustrado a modo de ejemplo con la descarga de datos masivos:

  1. Inicialización y puesta a disposición: la aplicación instancia la clase handler derivada con el InstanceSpecifier configurado [SWS_DM_01847] e invoca Offer() para activar el enrutamiento en el DM [SWS_DM_01857].
  2. Recepción de solicitudes: un cliente externo envía una solicitud al método SOVD «Download Bulk Data». El DM delega la solicitud a RequestBulkDataDownload() y transfiere categoría, ID, cabecera HTTP Accept, metainformación, así como un CancellationHandler [SWS_DM_01792], [SWS_DM_01873].
  3. Procesamiento y respuesta: la implementación comprueba el recurso y devuelve de forma asíncrona un ara::core::Future. Este contiene bien una sesión de lectura (DataTransferReadSession) que incluye el BulkDataMetaDataDescriptor correspondiente, bien una redirección HTTP (HttpRedirect) [SWS_DM_01873].
  4. Gestión de cancelaciones: si el cliente desconecta la conexión prematuramente, el DM lo señala a través del CancellationHandler transferido, de modo que la aplicación pueda liberar recursos [SWS_DM_01873].
  5. Cancelación del registro del servicio: durante el apagado del componente, la aplicación invoca StopOffer(), con lo cual el DM deja de entregar más solicitudes [SWS_DM_01858].

Diagrama de secuencia: orden típico de llamadas durante la puesta a disposición y la ejecución de una descarga de Bulk Data. Fuentes: [SWS_DM_01792], [SWS_DM_01857], [SWS_DM_01858], [SWS_DM_01873].

Escenarios de error

Las situaciones de error pueden ocurrir en diferentes fases y se notifican a través de mecanismos específicos:

  • Infracciones de modelo y de puerto durante la construcción: el constructor está declarado como noexcept, pero realiza comprobaciones de integridad frente al modelo de AUTOSAR [SWS_DM_01847]. Las posibles infracciones comprenden:
    • InstanceSpecifierMappingIntegrityViolation: el identificador no se puede resolver en el contexto del ejecutable o no hace referencia a ningún PortPrototype.
    • PortInterfaceMappingViolation: el puerto referenciado no está tipado mediante un DiagnosticSovdBulkDataInterface.
    • ProcessMappingViolation: el proceso modelado no coincide con el proceso en tiempo de ejecución.
    • InstanceSpecifierAlreadyInUseViolation: el InstanceSpecifier ya está siendo utilizado por otra instancia en el proceso actual.
  • Errores de configuración y de estado en Offer(): el método Offer() devuelve un ara::core::Result<void> [SWS_DM_01857]. Los posibles códigos de error son:
    • DiagOfferErrc::kConfigurationMismatch: la configuración del monitor no coincide con la descripción de diagnóstico del DEXT.
    • DiagOfferErrc::kAlreadyOffered: la instancia de servicio ya fue registrada previamente.
  • Errores de protocolo y procesamiento de SOVD: los métodos puramente virtuales RequestBulkDataDownload, RequestBulkDataUpload, DeleteAllBulkData y DeleteSpecificBulkData señalan errores de forma asíncrona a través del ara::core::Future devuelto mediante códigos de error estandarizados de SOVD según ISO 17978-3 o ASAM SOVD 1.1 (utilizando DiagSovdErrc) [SWS_DM_01854], [SWS_DM_01855], [SWS_DM_01856], [SWS_DM_01873]. Por el contrario, para GetBulkDataMetaData no se han especificado códigos de error estandarizados [SWS_DM_01853].

Esta guía se basa exclusivamente en la especificación AUTOSAR Adaptive Platform R25-11 (módulo diag).

<h4>Ciclo de vida</h4>
<p>La clase <code>ara::diag::SovdBulkData</code> atraviesa un ciclo de vida claramente definido compuesto por instanciación, registro del servicio, funcionamiento operativo y destrucción:</p>
<ul>
<li><strong>Creación:</strong> la instanciación se realiza a través del constructor pasando un <code>ara::core::InstanceSpecifier</code>, que hace referencia a un <code>PortPrototype</code> de un <code>DiagnosticSovdBulkDataInterface</code>, así como un parámetro del tipo <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. El propio constructor es seguro para hilos (<em>thread-safe</em>).</li>
<li><strong>Semántica de copia y movimiento:</strong> la instancia representa una interfaz exclusiva por puerto. El constructor de copia <a class="spec-record-ref" data-req="SWS_DM_01848" href="../spec/record.html?id=SWS_DM_01848">[SWS_DM_01848]</a> y el operador de asignación por copia <a class="spec-record-ref" data-req="SWS_DM_01850" href="../spec/record.html?id=SWS_DM_01850">[SWS_DM_01850]</a> están eliminados (<code>=delete</code>). El constructor de movimiento <a class="spec-record-ref" data-req="SWS_DM_01849" href="../spec/record.html?id=SWS_DM_01849">[SWS_DM_01849]</a> y el operador de asignación por movimiento <a class="spec-record-ref" data-req="SWS_DM_01851" href="../spec/record.html?id=SWS_DM_01851">[SWS_DM_01851]</a> están especificados con visibilidad protegida (<code>protected</code>).</li>
<li><strong>Gestión de estados:</strong> tras la creación, el objeto se encuentra en estado de reposo. La llamada a <code>Offer()</code> activa el reenvío de mensajes SOVD entrantes por parte del DM al handler <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Mediante <code>StopOffer()</code> se desactiva de nuevo este reenvío <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
<li><strong>Destrucción:</strong> el destructor <code>~SovdBulkData()</code> está declarado como virtual <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=702">AUTOSAR_AP_SWS_Diagnostics p. 702</a>. Antes de destruir una instancia, es probable que en la práctica de la aplicación se llame regularmente a <code>StopOffer()</code> para concluir de forma ordenada las solicitudes pendientes.</li>
<li><strong>Concurrencia:</strong> el <code>ConcurrencyType</code> pasado en el constructor determina si las implementaciones de los métodos virtuales específicas de la aplicación deben diseñarse como seguras para hilos (<code>kConcurrent</code>) o no seguras para hilos (<code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. Los métodos de control <code>Offer()</code> y <code>StopOffer()</code>, así como el destructor, están especificados como no seguros para hilos (<em>not thread-safe</em>) y requieren llamadas desde un contexto protegido <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>, <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>, <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>.</li>
</ul>

<h4>Ruta de uso</h4>
<p>Una ruta de uso típica comprende el registro del handler y el procesamiento asíncrono de solicitudes de transferencia de Bulk Data, ilustrado a modo de ejemplo con la descarga de datos masivos:</p>
<ol>
<li><strong>Inicialización y puesta a disposición:</strong> la aplicación instancia la clase handler derivada con el <code>InstanceSpecifier</code> configurado <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a> e invoca <code>Offer()</code> para activar el enrutamiento en el DM <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>.</li>
<li><strong>Recepción de solicitudes:</strong> un cliente externo envía una solicitud al método SOVD «Download Bulk Data». El DM delega la solicitud a <code>RequestBulkDataDownload()</code> y transfiere categoría, ID, cabecera HTTP Accept, metainformación, así como un <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01792" href="../spec/record.html?id=SWS_DM_01792">[SWS_DM_01792]</a>, <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Procesamiento y respuesta:</strong> la implementación comprueba el recurso y devuelve de forma asíncrona un <code>ara::core::Future</code>. Este contiene bien una sesión de lectura (<code>DataTransferReadSession</code>) que incluye el <code>BulkDataMetaDataDescriptor</code> correspondiente, bien una redirección HTTP (<code>HttpRedirect</code>) <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Gestión de cancelaciones:</strong> si el cliente desconecta la conexión prematuramente, el DM lo señala a través del <code>CancellationHandler</code> transferido, de modo que la aplicación pueda liberar recursos <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Cancelación del registro del servicio:</strong> durante el apagado del componente, la aplicación invoca <code>StopOffer()</code>, con lo cual el DM deja de entregar más solicitudes <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
</ol>

<h4>Escenarios de error</h4>
<p>Las situaciones de error pueden ocurrir en diferentes fases y se notifican a través de mecanismos específicos:</p>
<ul>
<li><strong>Infracciones de modelo y de puerto durante la construcción:</strong> el constructor está declarado como <code>noexcept</code>, pero realiza comprobaciones de integridad frente al modelo de AUTOSAR <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. Las posibles infracciones comprenden:
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: el identificador no se puede resolver en el contexto del ejecutable o no hace referencia a ningún <code>PortPrototype</code>.</li>
  <li><code>PortInterfaceMappingViolation</code>: el puerto referenciado no está tipado mediante un <code>DiagnosticSovdBulkDataInterface</code>.</li>
  <li><code>ProcessMappingViolation</code>: el proceso modelado no coincide con el proceso en tiempo de ejecución.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: el <code>InstanceSpecifier</code> ya está siendo utilizado por otra instancia en el proceso actual.</li>
  </ul>
</li>
<li><strong>Errores de configuración y de estado en Offer():</strong> el método <code>Offer()</code> devuelve un <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Los posibles códigos de error son:
  <ul>
  <li><code>DiagOfferErrc::kConfigurationMismatch</code>: la configuración del monitor no coincide con la descripción de diagnóstico del DEXT.</li>
  <li><code>DiagOfferErrc::kAlreadyOffered</code>: la instancia de servicio ya fue registrada previamente.</li>
