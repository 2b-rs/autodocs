Contexto

La clase ara::diag::DiagnosticSovdArrayContentElementDataConstView forma parte del módulo de diagnóstico (ara::diag) de AUTOSAR Adaptive Platform en la versión R25-11 y se especifica en AUTOSAR_AP_SWS_Diagnostics §8.60.3 «Class: DiagnosticSovdArrayContentElementDataConstView» ([SWS_DM_02248]). Actúa como una vista inmutable (Const View) de un elemento de contenido SOVD (DiagnosticSovdContentElementData), cuyo tipo está configurado como array.

En el marco del diagnóstico vehicular orientado a servicios (SOVD), este objeto de vista encapsula el acceso de solo lectura a elementos de datos agregados. Los componentes de aplicación y de diagnóstico interactúan a través de esta interfaz para inspeccionar datos estructurados de campos de forma secuencial o aleatoria. Al prescindir de copias de datos propias, la clase proporciona acceso de lectura directo a los elementos a través de interfaces de punteros o iteradores como DiagnosticSovdArrayContentElementDataConstIterator ([SWS_DM_02254], [SWS_DM_02255]), así como mediante referencias constantes ([SWS_DM_02253]).

Ciclo de vida y concurrencia

Como vista especializada, la clase no posee por sí misma los contenidos de diagnóstico subyacentes. Interpretación: Es probable que el objeto esté concebido como un contenedor ligero sin propiedad (wrapper), cuya validez está estrictamente vinculada al ciclo de vida de la instancia de DiagnosticSovdContentElementData a la que hace referencia. La aplicación solicitante debe asegurarse de que la estructura de datos subyacente permanezca en la memoria durante el uso de la vista.

En cuanto a la seguridad de ejecución y la concurrencia, se aplican garantías estrictas:

  • Seguridad frente a excepciones: Todos los métodos de la interfaz —incluidos HasError ([SWS_DM_02249]), Size ([SWS_DM_02250]), Capacity ([SWS_DM_02251]), Empty ([SWS_DM_02252]), operator[] ([SWS_DM_02253]) y todos los accesos mediante iterador ([SWS_DM_02254], [SWS_DM_02255], [SWS_DM_02256], [SWS_DM_02257])— están declarados como noexcept y son completamente seguros frente a excepciones (exception safe).
  • Seguridad de subprocesos: Todas las funciones miembro están especificadas como thread-safe. Múltiples hilos de ejecución paralelos pueden acceder simultáneamente en modo de solo lectura a la misma instancia de la vista sin que se requieran mecanismos de sincronización adicionales en el nivel del llamador.

Ruta de uso

El flujo regular durante el procesamiento de un elemento de contenido de array SOVD comprende la validación del estado, la determinación de las dimensiones y el acceso de lectura propiamente dicho:

  1. Comprobación de errores: en primer lugar, el invocador comprueba a través de HasError() ([SWS_DM_02249]) si el contenido está libre de errores. El método devuelve un ara::core::Result<void>.
  2. Consultar metadatos: a través de Empty() ([SWS_DM_02252]) se consulta si contiene elementos. El número de elementos del array presentes se determina mediante Size() ([SWS_DM_02250]) y la capacidad disponible a través de Capacity() ([SWS_DM_02251]).
  3. Extracción de elementos: para el acceso a los elementos del array hay dos vías disponibles:
    • Acceso directo por índice: el operator[](std::size_t index) ([SWS_DM_02253]) devuelve un ara::core::Result<std::reference_wrapper<DiagnosticSovdContentElementData const>> si el índice es válido.
    • Iteradores: mediante Begin() y End() ([SWS_DM_02254], [SWS_DM_02255]), así como sus homólogos explícitamente constantes CBegin() y CEnd() ([SWS_DM_02256], [SWS_DM_02257]), se puede recorrer el array mediante DiagnosticSovdArrayContentElementDataConstIterator.

Diagrama de secuencia: secuencia típica de llamadas para la validación, consulta de dimensiones y lectura de elementos de contenido del array. Fuentes: [SWS_DM_02249], [SWS_DM_02250], [SWS_DM_02252], [SWS_DM_02253], [SWS_DM_02256], [SWS_DM_02257].

Escenarios de error

Las condiciones de error se notifican a través de ara::core::Result de conformidad con el estándar AUTOSAR Adaptive, en lugar de lanzar excepciones de C++:

  • Precondiciones del tipo de contenido: para todas las funciones de elemento ([SWS_DM_02250], [SWS_DM_02251], [SWS_DM_02252], [SWS_DM_02253], [SWS_DM_02254], [SWS_DM_02255], [SWS_DM_02256], [SWS_DM_02257]) se aplica la condición formal de especificación de que el DiagnosticSovdContentElementData subyacente debe ser efectivamente del tipo ArrayContentElementData.
  • Contenido de datos erróneo: si existe un error interno de datos o de procesamiento en el elemento, HasError() ([SWS_DM_02249]) devuelve un código de error del tipo ara::diag::DiagSovdErrc en el objeto Result.
  • Índice no válido o tipo incorrecto en el acceso a elementos: si al llamar a operator[](index) ([SWS_DM_02253]) el objeto de destino no coincide con el tipo requerido, el Result devuelto contiene el error correspondiente en lugar de una referencia válida.

Esta guía se basa en la especificación AUTOSAR Adaptive Platform Release R25-11.

  <h4>Contexto</h4>
  <p>La clase <code>ara::diag::DiagnosticSovdArrayContentElementDataConstView</code> forma parte del módulo de diagnóstico (<code>ara::diag</code>) de AUTOSAR Adaptive Platform en la versión R25-11 y se especifica en <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=768">AUTOSAR_AP_SWS_Diagnostics §8.60.3 «Class: DiagnosticSovdArrayContentElementDataConstView»</a> (<a class="spec-record-ref" data-req="SWS_DM_02248" href="../spec/record.html?id=SWS_DM_02248">[SWS_DM_02248]</a>). Actúa como una vista inmutable (Const View) de un elemento de contenido SOVD (<code>DiagnosticSovdContentElementData</code>), cuyo tipo está configurado como array.</p>
  <p>En el marco del diagnóstico vehicular orientado a servicios (SOVD), este objeto de vista encapsula el acceso de solo lectura a elementos de datos agregados. Los componentes de aplicación y de diagnóstico interactúan a través de esta interfaz para inspeccionar datos estructurados de campos de forma secuencial o aleatoria. Al prescindir de copias de datos propias, la clase proporciona acceso de lectura directo a los elementos a través de interfaces de punteros o iteradores como <code>DiagnosticSovdArrayContentElementDataConstIterator</code> (<a class="spec-record-ref" data-req="SWS_DM_02254" href="../spec/record.html?id=SWS_DM_02254">[SWS_DM_02254]</a>, <a class="spec-record-ref" data-req="SWS_DM_02255" href="../spec/record.html?id=SWS_DM_02255">[SWS_DM_02255]</a>), así como mediante referencias constantes (<a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a>).</p>

  <h4>Ciclo de vida y concurrencia</h4>
  <p>Como vista especializada, la clase no posee por sí misma los contenidos de diagnóstico subyacentes. Interpretación: Es probable que el objeto esté concebido como un contenedor ligero sin propiedad (wrapper), cuya validez está estrictamente vinculada al ciclo de vida de la instancia de <code>DiagnosticSovdContentElementData</code> a la que hace referencia. La aplicación solicitante debe asegurarse de que la estructura de datos subyacente permanezca en la memoria durante el uso de la vista.</p>
  <p>En cuanto a la seguridad de ejecución y la concurrencia, se aplican garantías estrictas:</p>
  <ul>
    <li><strong>Seguridad frente a excepciones:</strong> Todos los métodos de la interfaz —incluidos <code>HasError</code> (<a class="spec-record-ref" data-req="SWS_DM_02249" href="../spec/record.html?id=SWS_DM_02249">[SWS_DM_02249]</a>), <code>Size</code> (<a class="spec-record-ref" data-req="SWS_DM_02250" href="../spec/record.html?id=SWS_DM_02250">[SWS_DM_02250]</a>), <code>Capacity</code> (<a class="spec-record-ref" data-req="SWS_DM_02251" href="../spec/record.html?id=SWS_DM_02251">[SWS_DM_02251]</a>), <code>Empty</code> (<a class="spec-record-ref" data-req="SWS_DM_02252" href="../spec/record.html?id=SWS_DM_02252">[SWS_DM_02252]</a>), <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a>) y todos los accesos mediante iterador (<a class="spec-record-ref" data-req="SWS_DM_02254" href="../spec/record.html?id=SWS_DM_02254">[SWS_DM_02254]</a>, <a class="spec-record-ref" data-req="SWS_DM_02255" href="../spec/record.html?id=SWS_DM_02255">[SWS_DM_02255]</a>, <a class="spec-record-ref" data-req="SWS_DM_02256" href="../spec/record.html?id=SWS_DM_02256">[SWS_DM_02256]</a>, <a class="spec-record-ref" data-req="SWS_DM_02257" href="../spec/record.html?id=SWS_DM_02257">[SWS_DM_02257]</a>)— están declarados como <code>noexcept</code> y son completamente seguros frente a excepciones (<em>exception safe</em>).</li>
