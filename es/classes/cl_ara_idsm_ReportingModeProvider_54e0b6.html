Sirve para consultar y establecer los reporting modes para eventos de seguridad configurados en el IdsM.

La clase ara::idsm::ReportingModeProvider proporciona mecanismos para consultar y establecer reporting modes para eventos relevantes para la seguridad en el Intrusion Detection System Manager [SWS_AIDSM_10600]. La instanciación se lleva a cabo de forma segura para subprocesos mediante un ara::core::InstanceSpecifier para un PPort modelado [SWS_AIDSM_10601]. En tiempo de ejecución, los métodos GetReportingMode y SetReportingMode permiten leer y modificar el modo de un evento configurado. Dado que estos métodos no son seguros para subprocesos, el acceso concurrente debe sincronizarse externamente. En caso de ID de eventos desconocidos, los métodos devuelven el error IdsmErrc::kUnknownEventId.

Contexto

La clase ara::idsm::ReportingModeProvider está definida en la cabecera ara/idsm/reporting_mode_provider.h y sirve, dentro del módulo adaptativo idsm, para la provisión y el control dinámico de reporting modes para el Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10600]. En una arquitectura de vehículo interconectada, el IdsM monitoriza eventos relevantes para la seguridad (Security Events). A través del ReportingModeProvider, las aplicaciones o los servicios de plataforma pertinentes pueden dirigirse a eventos de seguridad configurados para determinar o definir de qué manera debe notificarse un evento al sistema IdsM. La vinculación a la arquitectura se efectúa a través de un PPort modelado que se especifica durante la instanciación [SWS_AIDSM_10601].

Ciclo de vida

La clase está declarada como final [SWS_AIDSM_10600], con lo cual quedan excluidas la herencia o la especialización polimórfica. La creación de un objeto se efectúa mediante el constructor explícito ReportingModeProvider(const ara::core::InstanceSpecifier& instance) [SWS_AIDSM_10601]. A través del parámetro instance se establece la vinculación con el PPort modelado concreto [SWS_AIDSM_10601]. Interpretación: la designación de instancia suministrada hace referencia presumiblemente al despliegue de interfaz configurado en el modelo AUTOSAR para el servicio IdsM.

Respecto a la concurrencia, el constructor está especificado como seguro para subprocesos (thread-safe) [SWS_AIDSM_10601]. Por el contrario, los dos métodos operativos para leer y escribir los modos de reporte están expresamente designados como no seguros para subprocesos (not thread-safe) [SWS_AIDSM_10602], [SWS_AIDSM_10603]. Si varios subprocesos acceden en paralelo a la misma instancia de ReportingModeProvider, el llamador debe sincronizar dicho acceso externamente. El ciclo de vida de la instancia se acopla típicamente a la duración de la aplicación consumidora, la cual crea el objeto, lo gestiona y lo destruye tras finalizar la interacción.

Ruta de uso

El uso típico se divide en la inicialización, la consulta del estado actual y la adaptación del modo de reporte según sea necesario.

En primer lugar, la aplicación instancia el proveedor para el puerto previsto especificando el correspondiente InstanceSpecifier [SWS_AIDSM_10601]. A continuación, mediante el método GetReportingMode se puede consultar el reporting mode actual para un evento concreto configurado [SWS_AIDSM_10602]. El método devuelve un ara::core::Result<ReportingModeType>, que encapsula el modo o notifica un error ocurrido [SWS_AIDSM_10602].

Si la situación de seguridad o la configuración de diagnóstico requiere una modificación, se invoca SetReportingMode [SWS_AIDSM_10603]. Esta llamada recibe el identificador eventId, así como el nuevo reportingMode, y devuelve un ara::core::Result<void> [SWS_AIDSM_10603]. La aplicación comprueba el resultado para asegurar la finalización correcta del cambio de configuración.

Diagrama de secuencia: ruta de uso típica para consultar y actualizar un modo de reporte a través del proveedor. Fuentes: [SWS_AIDSM_10601], [SWS_AIDSM_10602], [SWS_AIDSM_10603]

Escenarios de error

Todos los métodos de la clase están declarados con noexcept [SWS_AIDSM_10601], [SWS_AIDSM_10602], [SWS_AIDSM_10603]. Por lo tanto, el tratamiento de errores se lleva a cabo íntegramente sin excepciones de C++ mediante el modelo de errores propio de AUTOSAR ara::core::Result.

Tanto al consultar mediante GetReportingMode [SWS_AIDSM_10602] como al establecer mediante SetReportingMode [SWS_AIDSM_10603], se asume que el eventId suministrado corresponde a un evento de seguridad configurado. Si se pasa un identificador de evento desconocido o no registrado en el sistema, la operación falla y el Result contiene el código de error IdsmErrc::kUnknownEventId [SWS_AIDSM_10602], [SWS_AIDSM_10603]. Los componentes llamadores deben evaluar el Result antes de acceder al valor e iniciar el tratamiento de errores o el registro correspondiente en caso de fallo.

Esta guía se basa exclusivamente en la especificación de AUTOSAR para el módulo adaptativo idsm en la versión R25-11.
