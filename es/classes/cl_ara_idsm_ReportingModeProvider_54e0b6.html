Contexto

La clase ara::idsm::ReportingModeProvider está definida como una interfaz final en el módulo AUTOSAR Adaptive idsm ([SWS_AIDSM_10600]). Su responsabilidad principal consiste en proporcionar modos de informe (Reporting Modes) para eventos de seguridad configurados al Intrusion Detection System Manager (IdsM) ([SWS_AIDSM_10600]). Actúa en el lado de la aplicación como una instancia concreta de proveedor para un PPort declarado en el modelo del sistema ([SWS_AIDSM_10601]).

En el sistema global interactúan típicamente las siguientes partes:

  • Adaptive Application: Actúa como proveedor de modo y toma la decisión, en función de estados o de un diagnóstico externo, de qué modo de informe debe estar activo.
  • ReportingModeProvider: Encapsula la interfaz específica del puerto para consultar y actualizar los modos de eventos ([SWS_AIDSM_10602], [SWS_AIDSM_10603]).
  • Instancia de plataforma de IdsM: Interpretación: Recibe los Reporting Modes establecidos para controlar el filtrado y reenvío de los eventos de seguridad correspondientes en la red del vehículo.

Ciclo de vida

La creación de un objeto ReportingModeProvider se realiza obligatoriamente de forma explícita mediante la transmisión de un ara::core::InstanceSpecifier ([SWS_AIDSM_10601]). Este especificador establece la vinculación con el PPort modelado en el manifiesto de la aplicación. El constructor no lanza excepciones (noexcept) y está especificado explícitamente como seguro para hilos (thread-safe) ([SWS_AIDSM_10601]).

Con respecto a la propiedad y al tiempo de ejecución: es de esperar que la instancia se cree habitualmente durante la fase de inicialización de la aplicación y se mantenga a lo largo de toda su fase de funcionamiento. Con la destrucción del objeto finaliza la provisión de la interfaz para el puerto asignado. La concurrencia en tiempo de ejecución requiere especial atención: mientras que la instanciación es segura para hilos ([SWS_AIDSM_10601]), los métodos operativos GetReportingMode ([SWS_AIDSM_10602]) y SetReportingMode ([SWS_AIDSM_10603]) están designados como no seguros para hilos (not thread-safe). Si varios hilos de ejecución acceden a la misma instancia de proveedor, el invocador debe sincronizar el acceso de manera externa.

Ruta de uso

El uso típico se divide en la creación de la instancia, la consulta de los estados existentes y la conmutación dinámica del modo de informe:

  1. Instanciación: La aplicación inicializa el ReportingModeProvider con el correspondiente ara::core::InstanceSpecifier del PPort ([SWS_AIDSM_10601]).
  2. Consulta del modo actual: A través de GetReportingMode(eventId), la aplicación determina el modo de informe actualmente configurado para el evento especificado ([SWS_AIDSM_10602]).
  3. Establecimiento de un nuevo modo: Mediante SetReportingMode(eventId, reportingMode) se actualiza el modo deseado para el evento de seguridad en cuestión ([SWS_AIDSM_10603]).
  4. Evaluación del resultado: Dado que ambas llamadas devuelven ara::core::Result, la aplicación verifica en cada caso si la operación fue exitosa o si existe un error.

Diagrama de secuencia: Secuencia de llamadas y retornos durante la inicialización, consulta y actualización de un Reporting Mode. Fuentes: [SWS_AIDSM_10601], [SWS_AIDSM_10602], [SWS_AIDSM_10603]

Escenarios de error

Las interfaces de la clase operan completamente sin excepciones de C++ (noexcept) y notifican los estados de error a través del tipo de error ara::core::Result:

  • ID de evento desconocido (IdsmErrc::kUnknownEventId): Este error se devuelve tanto por GetReportingMode ([SWS_AIDSM_10602]) como por SetReportingMode ([SWS_AIDSM_10603]) en ara::core::Result si el eventId proporcionado (de tipo EventIdType) no se corresponde con ningún evento de seguridad configurado en el modelo del sistema para este PPort.
  • Precondiciones: La instancia de proveedor debe haber sido construida correctamente ([SWS_AIDSM_10601]), y el invocador debe asegurarse de que el identificador de evento consultado o modificado sea válido.
  • Poscondiciones: Tras una llamada exitosa a SetReportingMode, GetReportingMode devuelve el valor recién establecido para la misma eventId. En caso de error, el estado en IdsM permanece sin cambios.

Esta guía se basa en los requisitos de la especificación de AUTOSAR Adaptive R25-11 para el módulo idsm.
