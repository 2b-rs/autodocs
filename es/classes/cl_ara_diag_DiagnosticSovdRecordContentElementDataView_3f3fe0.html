Proporciona una vista estructurada para la gestión y lectura basadas en clave de registros de datos de diagnóstico SOVD.

La clase proporciona una vista estructurada de registros de datos SOVD del tipo RecordContentElementData para el diagnóstico de la Adaptive Platform (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView»). Permite añadir, leer y gestionar elementos de diagnóstico primitivos y complejos basados en claves mediante métodos seguros para subprocesos como Add u operator[] ([SWS_DM_02288]). El prerrequisito para todas las operaciones es que el elemento de datos subyacente sea del tipo Record requerido, ya que, de lo contrario, las llamadas se interrumpen con un error en el Result de retorno.

Contexto

La clase ara::diag::DiagnosticSovdRecordContentElementDataView actúa en el contexto de Service-Oriented Vehicle Diagnostics (SOVD) como una vista estructurada (View) sobre un elemento de datos de diagnóstico del tipo RecordContentElementData o ContentData (SWS Diagnostics §8.60.11 «Class: DiagnosticSovdRecordContentElementDataView», [SWS_DM_02270]). Permite a las aplicaciones de diagnóstico y al sistema de tiempo de ejecución de diagnóstico crear, leer y modificar registros basados en campos (Records) a partir de pares clave-valor ([SWS_DM_02288]). Como interlocutores de interacción actúan, por un lado, las implementaciones de servicios de diagnóstico que proporcionan o consumen datos de diagnóstico y, por otro lado, los objetos contenedores genéricos subyacentes del tipo DiagnosticSovdContentElementData. A través de interfaces estandarizadas, la View desacopla la manipulación específica de la aplicación de la forma de almacenamiento físico de los contenidos de diagnóstico.

Ciclo de vida

De acuerdo con su propósito como View, la instancia presumiblemente solo retiene una referencia a un objeto de datos existente del tipo DiagnosticSovdContentElementData (interpretación). De esto se deduce que el tiempo de vida del registro referenciado debe cubrir obligatoriamente la existencia de la View para evitar referencias no válidas. Según la especificación, todos los métodos declarados de la clase están diseñados como seguros para subprocesos (thread-safe) y seguros contra excepciones (exception safe) ([SWS_DM_02273], [SWS_DM_02288]). El ciclo de vida de los elementos de datos contenidos dentro del registro se puede gestionar dinámicamente: los elementos existentes se pueden eliminar por completo mediante Clear ([SWS_DM_02276]), suprimir de forma selectiva mediante Remove a partir de su clave ([SWS_DM_02287]) o extraer del contenedor mediante un iterador a través de Erase ([SWS_DM_02294]).

Ruta de uso

Un flujo de uso típico comprende la preparación de la memoria, la adición de elementos, la navegación y la lectura de campos:

  • Preparación de la memoria: Para evitar reasignaciones cuando se conoce el número de elementos, la capacidad se puede definir de forma preventiva con Reserve ([SWS_DM_02283]). La capacidad actual se puede consultar mediante Capacity ([SWS_DM_02274]).
  • Llenado del registro: A través de operaciones Add sobrecargadas se registran valores tipificados especificando una clave (key). Se admiten tipos de datos primitivos como std::int64_t ([SWS_DM_02288]), std::uint64_t ([SWS_DM_02289]), double ([SWS_DM_02290]), bool ([SWS_DM_02291]) y valores de cadena mediante ara::core::StringView ([SWS_DM_02292]). Del mismo modo, se pueden añadir elementos de diagnóstico anidados del tipo DiagnosticSovdContentElementData ([SWS_DM_02293]).
  • Comprobación y consulta: Antes del acceso, se puede verificar si está vacío con Empty ([SWS_DM_02275]) y consultar el número de elementos presentes con Size ([SWS_DM_02273]). La existencia de una clave se verifica mediante HasContentElement ([SWS_DM_02284]).
  • Acceso e iteración: El acceso a elementos concretos se realiza o bien directamente a través del operador de índice operator[], que devuelve una referencia al elemento de destino ([SWS_DM_02277], [SWS_DM_02278]), o bien mediante el método de búsqueda Find ([SWS_DM_02285], [SWS_DM_02286]). Para los recorridos, se dispone de iteradores a través de Begin, End, CBegin y CEnd ([SWS_DM_02279], [SWS_DM_02280], [SWS_DM_02281], [SWS_DM_02282]).

Diagrama de secuencia: flujo típico al rellenar y leer un elemento Record SOVD. Fuentes: [SWS_DM_02283], [SWS_DM_02288], [SWS_DM_02277], [SWS_DM_02271].

Escenarios de error

Las operaciones sobre el registro están sujetas a estrictas condiciones previas relativas al tipo de contenedor y a la validez de la clave:

  • Conflictos de tipos: Todos los métodos de acceso, inserción y borrado requieren que el elemento subyacente sea del tipo RecordContentElementData o ContentData. De lo contrario, operaciones como Add ([SWS_DM_02288]), operator[] ([SWS_DM_02277]), HasContentElement ([SWS_DM_02284]) y Remove ([SWS_DM_02287]) fallan y devuelven un ara::core::Result con estado de error.
  • Claves no encontradas: Un acceso a través de operator[] o un borrado mediante Remove devuelve un error si la clave solicitada no existe en el registro ([SWS_DM_02277], [SWS_DM_02287]).
  • Iteradores no válidos al borrar: El borrado mediante iterador a través de Erase devuelve el código de error DiagErrc::kInvalidArgument en caso de parámetros no válidos o vinculación de datos incorrecta ([SWS_DM_02294]).
  • Tratamiento explícito de errores: Además de los errores específicos de los métodos, el estado general del registro puede marcarse explícitamente como erróneo mediante SetError con un ara::core::ErrorCode ([SWS_DM_02272]). Los emisores de llamadas pueden comprobar la presencia de un error mediante HasError, que en caso de error devuelve un ara::diag::DiagSovdErrc correspondiente ([SWS_DM_02271]).
