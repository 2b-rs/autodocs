Propósito de uso

Esta clase de campo proxy final se genera para cada elemento modelado como un campo en ServiceInterface. El espacio de nombres, el nombre de la clase y el encabezado <SiNamespaceDerivedDirectoryPath>/<SiShortname>_proxy.h se derivan del modelo ServiceInterface de ARXML-Manifests. [SWS_CM_00008]

usar

Get() lee el valor del campo actual de forma asincrónica y solo está presente si Field tiene un Getter. Set() establece un nuevo valor de forma asincrónica y solo se crea si Setter está presente; Un error de aplicación se puede identificar mediante un valor de retorno que se desvía del valor solicitado. Ambas llamadas devuelven un ara::core::Future<FieldType>. [SWS_CM_00112] [SWS_CM_00113]

Para notificaciones de campo, primero llame a Subscribe(maxSampleCount), luego use GetNewSamples() para actualizar el caché de notificaciones local. La misma suscripción ya activa o pendiente no será nuevamente ejecutada; Unsubscribe() sin una suscripción existente sigue siendo ineficaz. El espacio libre en caché se puede consultar con GetFreeSampleCount(). Los controladores de estado de recepción y suscripción se pueden registrar, ejecutar en un contexto proporcionado y eliminar nuevamente. E2E y tratamiento de errores

La clase puede registrar o eliminar un fallo de transporte Handler. Las tres consultas de estado E2E proporcionan el estado de la última verificación E2E de una llamada Get(), GetNewSamples() o Set(). Los otros Operation mencionados son seguros para excepciones, solo GetNewSamples() no está especificado como seguro para excepciones; Subscription fallido o actualización de caché se muestra a través de ara::core::Result. Semántica de campo

A diferencia de un evento, un campo siempre tiene un valor actual; La notificación, Get() y Set() se pueden modelar opcionalmente en la interfaz de servicio. Por lo tanto, el contenedor de campo proxy combina notificaciones similares a eventos con solicitudes get/set similares a métodos. EXP ARAComAPI §5.3.7 «Fields» TPS Manifest §4.2 «Service Interface»
