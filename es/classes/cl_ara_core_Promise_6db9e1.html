Propósito de uso

ara::core::Promise<T, E> es la variante AUTOSAR de std::promise. El tipo de error debe ser ara::core::ErrorCode. Junto con Future, la clase puede proporcionar valores y errores de forma asincrónica y segura para subprocesos sin manejo de excepciones. [SWS_CORE_00340] [SWS_CORE_10800]

Ciclo de vida y propiedad

Está prohibido copiar (=delete), es posible moverlo. Mover la asignación y el destructor abandonan cualquier Shared State existente. [SWS_CORE_00350] [SWS_CORE_00351] [SWS_CORE_00342] [SWS_CORE_00343] [SWS_CORE_00349]

Interacción con otras clases.

get_future() devuelve el Future<T,E> correspondiente con el mismo estado compartido; esta llamada solo se permite una vez por promesa. set_value(), SetError() y SetResult() preparan el estado compartido. Limitaciones y Manejo de errores

La configuración repetida de valor, error o resultado y una llamada de establecimiento sin Shared State se especifican como Violation. [SWS_CORE_13015] [SWS_CORE_13016]

Proporcionar el resultado asincrónico

En el lado del esqueleto, un Promise puede proporcionar un valor ya calculado o puede insertarse en un trabajador asincrónico; el Future asociado se devuelve a la persona que llama. EXP ARAComAPI §5.4.6 «Methods»

Si se detecta un error de aplicación, el ErrorCode asociado se coloca en el Promise; Luego, el cliente puede procesarlo como Result a través de la ruta Future. EXP ARAComAPI §4.7 «Error Handling» EXP ARAComAPI §5.4.6 «Methods»

Tratado de Estado Común

El Promise completa el estado común observado en Future. El marco relevante es el concepto Future/Promise para valores asincrónicos o resultados de error definidos en Core. SWS Core §7.2 «Error handling» SWS Core §7.2.5.5 «Future and Promise»

Comportamiento en caso de error

Un Promise solo puede preparar su estado compartido una vez con valor, error o Result. Una llamada posterior a set_value(), SetError() o SetResult() cuando un valor o error ya está almacenado se especifica como una infracción de promise_already_satisfied. Un setter sin un estado compartido es su propia violación. [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356] [SWS_CORE_13015] [SWS_CORE_13016]

get_future() solo se puede llamar una vez por Shared State. La segunda llamada se establece como future_already_retrieved-Violation; Si falta el Shared State, se aplica el no_state-Violation. Estos casos no son errores de aplicación informados a través de Result en el contrato API. [SWS_CORE_00344] [SWS_CORE_13013] [SWS_CORE_13014]

El destructor y la asignación de movimiento abandonan un estado compartido existente. Si la página Future que ya se ha generado espera el resultado, GetResult() devuelve el error FutureErrc::kBrokenPromise; get() maneja la misma condición a modo de excepción. El proceso completo, incluida la configuración de un error y un tiempo de espera, se muestra en Fehlerpfad-Diagramm von Future. [SWS_CORE_00343] [SWS_CORE_00349] [SWS_CORE_00336] [SWS_CORE_00326]
