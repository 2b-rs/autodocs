Contexto

La clase de plantilla ara::core::Promise<T, E> proporciona la variante específica de AUTOSAR Adaptive de la clase estándar de C++ std::promise. Su cometido fundamental consiste en formar el extremo de escritura de un canal de sincronización asíncrono y gestionar un estado compartido (Shared State). A través de este Shared State, una ruta de ejecución generadora pasa el resultado de un cálculo asíncrono —ya sea un valor de tipo T, un error de tipo E o un ara::core::Result<T, E> coherente— a su homólogo de lectura ara::core::Future<T, E>, que se obtiene mediante get_future() [SWS_CORE_00344].

Una especificación central de AUTOSAR para la signatura de la plantilla es la asignación predeterminada E = ara::core::ErrorCode. Si la instanciación difiere de esto (E != ara::core::ErrorCode), la especificación exige obligatoriamente un error de compilación. Presumiblemente, esta definición sirve para la aplicación estricta del modelo de errores estandarizado de la Adaptive Platform, con el fin de que las interfaces asíncronas puedan colaborar de manera uniforme con ara::core::Result. En la colaboración intervienen típicamente tres entidades: la parte del programa generadora como propietaria del Promise, el Shared State gestionado para el acoplamiento de estados entre hilos y uno o varios consumidores que reciben el resultado asíncrono a través de ara::core::Future.

Ciclo de vida

El ciclo de vida de ara::core::Promise sigue una estricta semántica de solo movimiento (move-only) y controla la existencia del Shared State subyacente:

  • Creación: el constructor predeterminado Promise() construye una instancia con un Shared State nuevo y todavía no satisfecho [SWS_CORE_00341]. Está especificado como seguro frente a excepciones garantizado como noexcept, así como thread-safe [SWS_CORE_00341].
  • Protección contra copia y transferencia de propiedad: el constructor de copia [SWS_CORE_00350] y el operador de asignación por copia [SWS_CORE_00351] están explícitamente eliminados (= delete). El cambio de propiedad solo es posible mediante operaciones move. El constructor de movimiento asume el Shared State de la instancia de origen y es noexcept, aunque no thread-safe [SWS_CORE_00342]. El operador de asignación por movimiento abandona un Shared State mantenido previamente (abandons any shared state) y transfiere el estado de la otra instancia de forma análoga a un swap posterior [SWS_CORE_00343]. Además, dos instancias pueden intercambiar su estado a través de swap() [SWS_CORE_00352].
  • Acoplamiento de Future: a través de get_future() se asocia exactamente una instancia de ara::core::Future<T, E> con el mismo Shared State [SWS_CORE_00344]. Puesto que por cada Promise solo puede existir un Future, esta llamada solo está permitida una única vez [SWS_CORE_00344].
  • Transición de estado a Ready: la introducción de un valor a través de set_value() [SWS_CORE_00345], [SWS_CORE_00346], de un error a través de SetError() [SWS_CORE_00353], [SWS_CORE_00354] o de un resultado global a través de SetResult() [SWS_CORE_00355], [SWS_CORE_00356] cambia de forma irreversible el Shared State al estado ready. Todos estos métodos de satisfacción están declarados como thread-safe.
  • Destrucción: el destructor ~Promise() abandona y descarta el Shared State (abandons any shared state) [SWS_CORE_00349]. Interpretación: si la destrucción se produce antes de establecer un valor o un error, el Shared State huérfano debería cancelarse para los Futures en espera, de forma análoga al comportamiento de std::promise.

Diagrama de estados: fases del ciclo de vida y transiciones de estado del Shared State en ara::core::Promise. Fuentes: [SWS_CORE_00341], [SWS_CORE_00344], [SWS_CORE_00345], [SWS_CORE_00353], [SWS_CORE_00355], [SWS_CORE_00349].

Ruta de uso

El orden de llamada típico para la transmisión asíncrona de valores o errores comprende los siguientes pasos:

  1. Creación: el productor instancia ara::core::Promise<T, E> a través del constructor predeterminado [SWS_CORE_00341].
  2. Conectar el canal: antes de transferir la tarea asíncrona a un hilo en segundo plano, el productor llama a get_future() [SWS_CORE_00344] y pasa la instancia de ara::core::Future resultante al consumidor.
  3. Procesamiento asíncrono: el productor ejecuta el cálculo o la operación de E/S. El consumidor puede continuar trabajando en paralelo o esperar al Future.
  4. Establecer el resultado: tras finalizar la operación, el productor deposita el resultado en el Shared State. Según el desenlace, elige:
    • Valor exitoso: set_value() como copia [SWS_CORE_00345] o move [SWS_CORE_00346].
    • Estado de error: SetError() mediante move [SWS_CORE_00353] o copia [SWS_CORE_00354].
    • Objeto Result existente: SetResult() por copia [SWS_CORE_00355] o move [SWS_CORE_00356].
  5. Liberación: al establecerlo, el Shared State se marca como listo; el consumidor lee el valor. El Promise se destruye al salir del ámbito de validez [SWS_CORE_00349].

Diagrama de secuencia: secuencia típica de llamadas e interacción para la transmisión asíncrona de valores o errores. Fuentes: [SWS_CORE_00341], [SWS_CORE_00344], [SWS_CORE_00345], [SWS_CORE_00353], [SWS_CORE_00355].

Escenarios de error

La especificación define condiciones fijas de infracción (Violations) para llamadas no permitidas, así como requisitos de seguridad frente a excepciones:

  • Recuperación múltiple de Future: si se llama a get_future() más de una vez para el mismo Shared State, se produce la infracción IsoStdFutureErrcFutureAlreadyRetrievedViolation [SWS_CORE_00344].
  • Operaciones sin Shared State: si *this no posee ningún Shared State (por ejemplo, tras una operación move), las llamadas a métodos provocan infracciones documentadas:
    • get_future() notifica IsoStdFutureErrcNoStateViolation [SWS_CORE_00344].
    • set_value(), SetError() y SetResult() activan PromiseNoSharedStateToSetViolation ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Satisfacción múltiple (Double Satisfaction): si ya se ha depositado un valor, un error o un Result en el Shared State, cualquier llamada posterior a set_value(), SetError() o SetResult() provoca la infracción IsoStdFutureErrcPromiseAlreadySatisfiedViolation ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Error de compilación en caso de tipo de error divergente: si la plantilla de clase se instancia con un tipo para el cual se cumple E != ara::core::ErrorCode, la compilación se interrumpe obligatoriamente con un Compile Error.
  • Seguridad condicional frente a excepciones: los constructores, el destructor, la asignación, move, swap y get_future() son incondicionalmente noexcept y seguros frente a excepciones ([SWS_CORE_00341], [SWS_CORE_00342], [SWS_CORE_00343], [SWS_CORE_00344], [SWS_CORE_00349], [SWS_CORE_00352]). En cambio, los métodos set_value(), SetError() y SetResult() son condicionalmente seguros frente a excepciones (conditionally exception safe); su propiedad noexcept depende de si los constructores de copia o de movimiento de T y E están declarados como que no lanzan excepciones (std::is_nothrow_*_constructible) ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
