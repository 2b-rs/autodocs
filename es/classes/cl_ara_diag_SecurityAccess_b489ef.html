Contexto

La clase ara::diag::SecurityAccess define la interfaz para el tratamiento del servicio UDS 0x27 (SecurityAccess) en AUTOSAR Adaptive. Sirve como handler abstracto mediante el cual las aplicaciones proporcionan el procedimiento de semilla y clave para desbloquear funciones de diagnóstico protegidas. El interlocutor principal es el gestor central de diagnóstico (Diagnostic Management, DM), que recibe los mensajes de diagnóstico entrantes procedentes de testers de diagnóstico externos y, tras el registro, los reenvía a la instancia de ara::diag::SecurityAccess [SWS_DM_00766]. El software de aplicación deriva de esta clase e implementa los métodos virtuales puros para proporcionar una semilla ([SWS_DM_00764]), así como para la validación de la clave ([SWS_DM_00765]).

Diagrama de contexto: interacción entre el tester de diagnóstico, Diagnostic Management (DM) y la implementación de SecurityAccess específica de la aplicación. Fuentes: [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_00766]

Ciclo de vida

Las instancias de ara::diag::SecurityAccess representan un elemento de puerto único e inequívoco. En consecuencia, las operaciones de copia y de movimiento están explícitamente impedidas: no están disponibles ni el constructor de copia ni el constructor de movimiento, ni los correspondientes operadores de asignación ([SWS_DM_01615], [SWS_DM_01616], [SWS_DM_01617], [SWS_DM_01618]). La creación se realiza obligatoriamente a través del constructor parametrizado especificando un ara::core::InstanceSpecifier modelado, así como el modo de concurrencia ConcurrencyType [SWS_DM_00762].

Tras la instanciación, el objeto se encuentra en el estado «no ofrecido». La recepción activa de solicitudes debe activarse explícitamente mediante la llamada a Offer() [SWS_DM_00766]. A través de StopOffer() se puede interrumpir en cualquier momento el reenvío de solicitudes de diagnóstico por parte del DM [SWS_DM_00767]. Interpretación: Sería conveniente llamar explícitamente a StopOffer() antes de destruir la instancia mediante el destructor virtual ~SecurityAccess() [SWS_DM_00763], ya que el destructor está declarado como no seguro para hilos. Mediante el ConcurrencyType pasado al constructor (kConcurrent o kNotConcurrent), se determina si las funciones de callback derivadas deben implementarse de forma segura para hilos [SWS_DM_00762].

Ruta de uso

Un flujo típico de autenticación de seguridad comprende la puesta a disposición del servicio, la consulta de la semilla y la validación de la clave transmitida:

  1. Ofrecer servicio: la aplicación instancia la clase derivada y llama a Offer(), autorizando así al DM a reenviar solicitudes de diagnóstico para el nivel de seguridad asignado [SWS_DM_00766].
  2. Solicitar semilla: si el tester de diagnóstico envía un mensaje UDS para solicitar semilla (subfunción Request Seed), el DM reenvía esta llamada a GetSeed() [SWS_DM_00764]. El método recibe el registro de datos de carga útil (securityAccessDataRecord), metadatos de la solicitud (metaInfo), así como un cancellationHandler. La implementación devuelve un ara::core::Future que proporciona la semilla como vector de bytes. Los datos de carga útil transferidos siguen siendo válidos hasta que se cumpla la promesa asociada o se cancele la operación [SWS_DM_00764].
  3. Verificar clave: tras recibir la clave del tester (subfunción Send Key), el DM llama al método CompareKey() [SWS_DM_00765]. La clave que se va a comprobar se pasa como ara::core::Span. La aplicación valida la clave de forma asíncrona y comunica el resultado a través de ara::core::Future<KeyCompareResultType>.
  4. Finalizar servicio: si se desea desactivar la interfaz, la aplicación llama a StopOffer(), con lo cual el DM deja de entregar más solicitudes [SWS_DM_00767].

Diagrama de secuencia: flujo típico de autenticación de seguridad desde Offer pasando por GetSeed y CompareKey hasta StopOffer. Fuentes: [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_00766], [SWS_DM_00767]

Escenarios de error

Pueden producirse errores en el modelado, en la puesta a disposición del servicio, así como durante la ejecución de los métodos de autenticación:

  • Errores de modelo y de instanciación: en la llamada al constructor [SWS_DM_00762] pueden desencadenarse infracciones:
    • InstanceSpecifierMappingIntegrityViolation: El InstanceSpecifier no se puede resolver en el contexto del proceso o no hace referencia a un PortPrototype.
    • PortInterfaceMappingViolation: El PortPrototype no hace referencia a un DiagnosticSecurityLevelInterface.
    • ProcessMappingViolation: No existe ningún proceso modelado adecuado para la referencia de instancia.
    • InstanceSpecifierAlreadyInUseViolation: El InstanceSpecifier ya está siendo utilizado por otra instancia en el proceso en ejecución.
  • Conflictos de estado al ofrecer: si se llama a Offer() mientras el servicio ya se está ofreciendo, la llamada falla y devuelve el código de error DiagOfferErrc::kAlreadyOffered en el resultado [SWS_DM_00766].
  • Errores de diagnóstico (NRC): si la generación de semilla o la comparación de claves no pueden completarse con normalidad, la aplicación señaliza errores a través del ara::core::Future devuelto mediante los correspondientes Negative Response Codes (NRC según ISO 14229-1) utilizando DiagUdsNrcErrc ([SWS_DM_00764], [SWS_DM_00765]).
  • Contadores persistentes de intentos fallidos: tras cada fallo en la modificación del nivel de seguridad, el contador de intentos fallidos debe incrementarse y guardarse obligatoriamente de forma persistente para sobrevivir a los reinicios (AUTOSAR_AP_SWS_Diagnostics §4.1 p. 63).
  • Cancelación de conversaciones: si una conversación de diagnóstico se interrumpe de forma prematura, esto se puede consultar mediante cancellationHandler.IsCanceled() o monitorizar a través de SetNotifier ([SWS_DM_00764], [SWS_DM_00765]).

usar

El método puramente virtual CompareKey de la clase ara::diag::SecurityAccess ([SWS_DM_00765], cabecera #include "ara/diag/security_access.h") es implementado por la aplicación de diagnóstico para validar la clave transmitida por el cliente para desbloquear un nivel de seguridad en el marco del servicio UDS 0x27 (SecurityAccess) ([SWS_DM_00236], [SWS_DM_00765]).

  • key: ara::core::Span<const std::uint8_t> con la clave que se va a validar. La validez de los datos está garantizada hasta que se cumpla la promesa o se cancele el proceso ([SWS_DM_00765]).
  • metaInfo: Proporciona metainformación (MetaInfo) sobre la solicitud entrante ([SWS_DM_00765]).
  • cancellationHandler: Permite consultar la cancelación de la conversación mediante IsCanceled, así como registrar una función de notificación mediante SetNotifier ([SWS_DM_00765]).

El procesamiento se realiza de forma asíncrona mediante la devolución de un ara::core::Future<KeyCompareResultType> ([SWS_DM_00765]).

Manejo de errores

En caso de error, se debe proporcionar un código de respuesta negativa (NRC) adecuado según la norma ISO 14229-1 a través de DiagUdsNrcErrc ([SWS_DM_00765]). La instancia del servidor de diagnóstico cuenta los intentos fallidos para cambiar el nivel de seguridad ([SWS_DM_00270]) y los compara con los valores de umbral configurados ([SWS_DM_00271]).

Concurrencia y restricciones

La función está definida como noexcept y es segura frente a excepciones (exception safe) ([SWS_DM_00765]). La seguridad para subprocesos es condicional (conditional): el hecho de que el método deba diseñarse como seguro para subprocesos depende del ConcurrencyType transferido en el constructor ([SWS_DM_00765]).

Interacción

Junto con GetSeed, CompareKey constituye la implementación en el lado de la aplicación del procedimiento de semilla/clave para el servicio 0x27 (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.9 «Service 0x27 – SecurityAccess»). Si el desbloqueo se realiza con éxito, la instancia del servidor actualiza el estado de seguridad de la conversación ([SWS_DM_00846]) y notifica el evento de seguridad SEV_UDS_SECURITY_ACCESS_SUCCESSFUL al IdsM ([SWS_DM_02019]).

El parámetro specifier vincula la instancia a un PortPrototype de un DiagnosticSecurityLevelInterface. Mediante concurrencyType se especifica si el procesamiento posterior de accesos de seguridad debe realizarse de forma concurrente (kConcurrent) o secuencial (kNotConcurrent).
  
              
  
              Tratamiento de errores y validación de modelos
              
  
              
    El constructor no proporciona ningún valor de retorno regular; sin embargo, en caso de errores de modelado o configuración, desencadena violaciones de framework (Violations) definidas [SWS_DM_00762]:

                •

                •

                •

                • 
  
              
  
              Concurrencia y ciclo de vida
              
  
              
    Mientras que el constructor en sí es seguro para subprocesos ([SWS_DM_00762]), el destructor no es seguro para subprocesos ([SWS_DM_00763]). La construcción por copia y por movimiento, así como los operadores de asignación, están explícitamente eliminados ([SWS_DM_01615], [SWS_DM_01616], [SWS_DM_01617], [SWS_DM_01618]), por lo que cada instancia permanece vinculada de forma única a su puerto.
