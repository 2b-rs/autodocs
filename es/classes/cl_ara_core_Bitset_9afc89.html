Contexto

La plantilla de clase ara::core::Bitset<std::size_t N> proporciona en el módulo core de la AUTOSAR Adaptive Platform una adaptación del tipo estándar std::bitset para software vehicular relevante para la seguridad. La declaración se realiza a través del archivo de cabecera ara/core/bitset.h. Sirve para la gestión eficiente y la manipulación a nivel de bits de secuencias de bits de longitud fija N.

Frente al modelo de C++ ISO, ara::core::Bitset presenta adaptaciones específicas al modelo de programación tolerante a fallos y libre de excepciones de AUTOSAR. Esto afecta en particular a la interacción con tipos de datos específicos de la plataforma como ara::core::BasicString, la devolución de ara::core::Result para la notificación síncrona de errores en operaciones basadas en posiciones, así como funciones de conversión dedicadas a anchos fijos de tipos enteros.

Ciclo de vida

Las instancias de ara::core::Bitset se caracterizan por un comportamiento de ciclo de vida estrictamente regulado sin gestión dinámica de memoria para el vector de bits. La inicialización puede realizarse a través de diferentes vías:

  • Inicialización por defecto: El constructor por defecto sin parámetros [SWS_CORE_01713] está declarado como constexpr y noexcept y preasigna a todos los N bits el valor cero.
  • Inicialización entera: Mediante el constructor [SWS_CORE_01719] se puede crear un bitset a partir de un valor del tipo unsigned long long, también como constexpr y noexcept.
  • Inicialización a partir de cadenas de caracteres: Mediante ara::core::BasicString, el constructor [SWS_CORE_01749] permite el análisis sintáctico de una secuencia de caracteres. Este constructor está definido como noexcept. Además, existe un constructor para cadenas de texto de C clásicas mediante punteros del tipo const CharT* [SWS_CORE_01750], el cual está clasificado como no seguro frente a excepciones (not exception safe).

La clase implementa una semántica de valores completa. El constructor de copia [SWS_CORE_01714], el constructor de movimiento [SWS_CORE_01716], el operador de asignación por copia [SWS_CORE_01715] y el operador de asignación por movimiento [SWS_CORE_01717] están definidos explícitamente como noexcept=default. El destructor [SWS_CORE_01718] está declarado como seguro frente a excepciones y thread-safe.

Ruta de uso

Un flujo de procesamiento típico con ara::core::Bitset se divide en tres fases consecutivas:

  1. Creación e inicialización: La aplicación crea el bitset con el ancho de bits necesario en tiempo de compilación, por ejemplo mediante el constructor por defecto [SWS_CORE_01713] o mediante la conversión de una máscara de bits [SWS_CORE_01719].
  2. Manipulación y combinación de bits:
    • Las modificaciones globales se realizan mediante set() [SWS_CORE_01725], reset() [SWS_CORE_01727] y flip() [SWS_CORE_01730].
    • Las manipulaciones específicas de bits individuales en la posición pos se realizan mediante set(pos, val) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728] o flip(pos) [SWS_CORE_01731].
    • Las operaciones lógicas a nivel de bits están disponibles a través de operadores de asignación compuestos como operator&= [SWS_CORE_01720], operator|= [SWS_CORE_01721] y operatorˆ= [SWS_CORE_01722]. La inversión bit a bit se proporciona mediante operator~ [SWS_CORE_01729].
    • Los desplazamientos de bits se implementan mediante operator<<= [SWS_CORE_01723], operator>>= [SWS_CORE_01724] y los correspondientes operadores de desplazamiento [SWS_CORE_01747] y [SWS_CORE_01748].
    • Los accesos de lectura y escritura a bits individuales pueden realizarse directamente a través del indexado operator[] [SWS_CORE_01732] (constante) o [SWS_CORE_01733] (referencia).
  3. Evaluación y conversión:
    • Las comprobaciones de estado se llevan a cabo mediante all() [SWS_CORE_01744], any() [SWS_CORE_01745], none() [SWS_CORE_01746], count() [SWS_CORE_01740] y size() [SWS_CORE_01741]. La igualdad de dos instancias la comprueba operator== [SWS_CORE_01742]. Las posiciones individuales las comprueba test(pos) [SWS_CORE_01743].
    • Para la conversión inversa, ara::core::Bitset ofrece, además de to_ulong() [SWS_CORE_01734], to_ullong() [SWS_CORE_01735] y to_string() [SWS_CORE_01751], conversiones dedicadas y thread-safe a anchos fijos: to_uint8t() [SWS_CORE_01736], to_uint16t() [SWS_CORE_01737], to_uint32t() [SWS_CORE_01738] y to_uint64t() [SWS_CORE_01739].

Escenarios de error

En lugar de las excepciones estándar de C++, la Adaptive Platform utiliza en ara::core::Bitset un modelo coherente de infracciones y errores bajo una estricta declaración noexcept de la mayoría de los métodos:

  • Infracciones de posición (Out of Range): Los modificadores posicionados set(pos, val) [SWS_CORE_01726], reset(pos) [SWS_CORE_01728] y flip(pos) [SWS_CORE_01731] devuelven un ara::core::Result. Si pos no representa una posición de bit válida, se desencadena la infracción IsoStdOutOfRangeViolation (en lugar de std::out_of_range). La función de consulta test(pos) [SWS_CORE_01743] también desencadena IsoStdOutOfRangeViolation si la posición no es válida.
  • Errores de análisis sintáctico de cadenas: En el constructor a partir de ara::core::BasicString [SWS_CORE_01749], una posición inicial pos > size() conduce a la infracción IsoStdOutOfRangeViolation. Si la cadena de caracteres analizada contiene un carácter que no corresponde ni a cero ni a uno, se señala IsoStdInvalidArgumentViolation (en lugar de std::invalid_argument).
  • Desbordamientos de conversión: Si el valor entero representado en el bitset no se puede representar en el tipo de retorno respectivo, las funciones de conversión to_ulong() [SWS_CORE_01734], to_ullong() [SWS_CORE_01735] así como to_uint8t() [SWS_CORE_01736], to_uint16t() [SWS_CORE_01737], to_uint32t() [SWS_CORE_01738] y to_uint64t() [SWS_CORE_01739] desencadenan la infracción IsoStdOverflowErrorViolation (en lugar de std::overflow_error).
  • Seguridad frente a excepciones: Mientras que casi todas las funciones de la clase están especificadas como exception safe, el constructor a partir de const CharT* [SWS_CORE_01750] y to_string() [SWS_CORE_01751] están clasificados explícitamente como not exception safe, presumiblemente debido a asignaciones dinámicas de memoria en el procesamiento de cadenas de caracteres.

Esta guía se basa en las especificaciones de AUTOSAR Adaptive Platform R25-11 para el módulo core.
