Sirve para la devolución tolerante a fallos de una referencia a un objeto existente o de un código de error ocurrido.

La especialización ara::core::Result<T&, E> encapsula o bien una referencia sin propiedad a un resultado de operación exitoso del tipo T& ([SWS_CORE_00902]) o bien un código de error ocurrido del tipo E. Los usuarios comprueban típicamente la presencia de un valor mediante HasValue() ([SWS_CORE_00918]) antes de acceder al objeto de destino referenciado a través de operadores de desreferenciación o Value(). Dado que la instancia no posee por sí misma el objeto referenciado, es probable que el llamador deba asegurarse de que este permanezca válido en memoria durante todo el tiempo de uso del resultado.

Contexto

La especialización de plantilla ara::core::Result<T&, E> encapsula o bien una referencia a un resultado de operación exitoso del tipo value_type ([SWS_CORE_00902]) o bien un valor de error del tipo error_type ([SWS_CORE_00903]). Como estructura de retorno estandarizada en el módulo core, permite una programación robusta frente a fallos sin el uso obligatorio de excepciones de C++ en el flujo regular. Según la especificación, la implementación impone en tiempo de compilación que el tipo de error E se corresponda con el tipo ara::core::ErrorCode; una asignación discrepante da lugar a un error de compilación. Entre los socios de interacción se encuentran los servicios proveedores de datos, componentes llamadores para la comprobación del resultado, así como el objeto de destino gestionado externamente al cual se accede directamente a través de la referencia vinculada.

Ciclo de vida

Una instancia se inicializa deterministamente o bien con una referencia a un lvalue existente o bien con un error. La inicialización con una referencia se realiza a través del constructor [SWS_CORE_00908] o del método factoría estático FromValue [SWS_CORE_00904]; la transferencia de rvalues no está permitida. Los estados de error se crean a través de constructores ([SWS_CORE_00909], [SWS_CORE_00910]) o factorías como FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]). No existe un constructor por defecto. Los constructores de copia y movimiento ([SWS_CORE_00911], [SWS_CORE_00912]) asumen el estado actual de otra instancia.

En cuanto a las relaciones de propiedad, Result<T&, E> únicamente vincula una referencia y no asume ninguna propiedad ni gestión del ciclo de vida para el objeto de destino referenciado. Por tanto, es probable que el llamador deba garantizar que el objeto de destino permanezca válido durante todo el tiempo de existencia de la instancia de Result. Los cambios de estado durante el funcionamiento se llevan a cabo mediante operadores de asignación ([SWS_CORE_00914], [SWS_CORE_00915]), los cuales revinculan la referencia interna al nuevo destino o transfieren un error. Además, EmplaceError [SWS_CORE_00916] coloca la instancia directamente en un estado de error, mientras que Swap [SWS_CORE_00917] intercambia los contenidos de dos instancias. El destructor [SWS_CORE_00913] se comporta de forma trivial, siempre que E sea trivialmente destructible. Los accesos de lectura paralelos al valor o error son seguros para hilos, mientras que las operaciones que modifican el estado como asignaciones, Swap o EmplaceError no son seguras para hilos.

Diagrama de estados: fases de vida y transiciones de estado entre el estado de referencia y el de error. Fuentes: [SWS_CORE_00904], [SWS_CORE_00905], [SWS_CORE_00914], [SWS_CORE_00916], [SWS_CORE_00917].

Ruta de uso

El flujo regular incluye el control de estado así como la evaluación orientada a objetivos:

  • Comprobación de estado: antes del acceso, el llamador comprueba a través de HasValue() [SWS_CORE_00918] o el operador de conversión operator bool [SWS_CORE_00919] si hay un valor presente.
  • Acceso directo: en caso de éxito, Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator* ([SWS_CORE_00920], [SWS_CORE_00921]) y operator-> ([SWS_CORE_00922], [SWS_CORE_00923]) proporcionan la referencia o un puntero al objeto de destino.
  • Accesos opcionales y basados en contingencia: a través de Ok() ([SWS_CORE_00926], [SWS_CORE_00927]) la referencia se puede transferir a un ara::core::Optional. El método ValueOr() ([SWS_CORE_00933], [SWS_CORE_00934]) proporciona una copia del valor referenciado o un valor sustitutivo pasado.
  • Operaciones monádicas: con Bind() [SWS_CORE_00941] se aplica una función de transformación a la referencia y se empaqueta el resultado, mientras que los errores se reenvían automáticamente. Resolve() ([SWS_CORE_00939], [SWS_CORE_00940]) invoca en caso de errores una función de reemplazo que proporciona una referencia compatible.

Diagrama de secuencia: pasos típicos de consulta y acceso para valor y error. Fuentes: [SWS_CORE_00918], [SWS_CORE_00924], [SWS_CORE_00928].

Escenarios de error

Si la instancia se encuentra en estado de error, las sobrecargas de Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) conceden acceso al objeto de error. De forma complementaria, el error se puede obtener a través de Err() ([SWS_CORE_00931], [SWS_CORE_00932]) como Optional<E> o a través de ErrorOr() ([SWS_CORE_00935], [SWS_CORE_00936]) con un valor de contingencia. Para cotejos de error específicos, CheckError() [SWS_CORE_00937] compara el error contenido con un error de referencia.

La especificación define precondiciones estrictas para los accesos a elementos:

  • ResultWithNoValueViolation: una llamada a Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator* ([SWS_CORE_00920], [SWS_CORE_00921]) o operator-> ([SWS_CORE_00922], [SWS_CORE_00923]) sobre una instancia sin valor representa una violación de la especificación.
  • ResultWithNoErrorViolation: el acceso a Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) en presencia de un valor viola las precondiciones.
  • Gestión de excepciones: las llamadas ValueOrThrow() ([SWS_CORE_00938], [SWS_CORE_00949]) lanzan en caso de error la excepción asociada al error; solo participan en la resolución de sobrecargas si las excepciones de C++ están habilitadas en el compilador.

usar

La función miembro const T * operator-> () const noexcept permite el acceso de lectura síncrono al valor referenciado de un objeto ara::core::Result<T &, E> [SWS_CORE_00922]. No toma argumentos y devuelve como valor de retorno un puntero constante (const T *) al objeto de destino referenciado [SWS_CORE_00922]. Para su uso debe incluirse la cabecera #include "ara/core/result.h" [SWS_CORE_00922].

Manejo de errores

La operación está declarada como noexcept y posee la propiedad exception safe [SWS_CORE_00922]. Si el objeto no contiene ningún valor, se produce una violación de precondición (Violation) ResultWithNoValue [SWS_CORE_00922]. Por lo tanto, los llamadores deben asegurarse antes de la desreferenciación de que la instancia contenga efectivamente un valor válido.

Concurrencia y restricciones

La función está especificada como thread-safe [SWS_CORE_00922]. Dado que se trata de una función miembro constante, el acceso de lectura paralelo a la misma instancia es seguro. Sin embargo, el acceso al objeto de destino propiamente dicho está sujeto a las garantías de seguridad para subprocesos del tipo T.

Interacción

El operador constituye la contrapartida constante de la sobrecarga no constante T * operator-> () noexcept [SWS_CORE_00923]. Mientras que la variante no constante devuelve un puntero modificable T* [SWS_CORE_00923], esta versión impone el acceso inmutable a la instancia referenciada.
