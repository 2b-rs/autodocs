Contexto

La clase de plantilla ara::core::Result<T &, E> representa una especialización parcial del tipo de resultado genérico Result para referencias. Sirve en la AUTOSAR Adaptive Platform como tipo de retorno unificado para operaciones que, en caso de ejecución exitosa, no crean ni copian un nuevo valor en la pila del llamador, sino que proporcionan una referencia lvalue a un objeto existente (value_type según [SWS_CORE_00902]). Si se produce un error durante la ejecución, la instancia transporta en su lugar un objeto de error (error_type según [SWS_CORE_00903]).

Para el tipo de error E, la especificación exige una condición obligatoria: si la comprobación en tiempo de compilación resulta en E != ara::core::ErrorCode, la implementación debe generar un error de compilador. Interpretación: Es probable que esta restricción garantice que los errores estén vinculados de forma uniforme en toda la plataforma a los dominios y códigos de error de AUTOSAR Adaptive. En este sentido, la clase interactúa principalmente como medio de transferencia síncrono entre un componente invocado (productor) y el llamador (consumidor), lo que permite transmitir referencias sin asignación dinámica ni duplicación de objetos.

Ciclo de vida

Una instancia de ara::core::Result<T &, E> se encuentra en todo momento en exactamente uno de dos estados: contiene una referencia vinculada a un objeto lvalue del tipo T o bien un objeto de error del tipo E.

La creación se realiza, según el estado, a través de interfaces especializadas:

  • Estado de valor: La instanciación se realiza mediante el constructor [SWS_CORE_00908] o la función auxiliar estática FromValue [SWS_CORE_00904]. Ambas interfaces imponen que el argumento proporcionado sea un lvalue; pasar rvalues da lugar a un programa erróneo (ill-formed).
  • Estado de error: La asignación de un error se realiza mediante constructores de lvalue y rvalue ([SWS_CORE_00909], [SWS_CORE_00910]), construcción por copia y por movimiento ([SWS_CORE_00911], [SWS_CORE_00912]) o a través de FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]), donde [SWS_CORE_00907] permite la construcción directa in-place de un error mediante paquetes de parámetros.

Interpretación: Dado que Result<T &, E> solo vincula una referencia, no asume la propiedad del objeto de destino T; por lo tanto, el tiempo de vida de este debe superar el tiempo de vida de la instancia de Result, así como la evaluación. Por el contrario, el objeto de error E se encuentra en posesión directa de la instancia.

Los cambios de estado y las asignaciones se controlan mediante los operadores de asignación por copia y por movimiento ([SWS_CORE_00914], [SWS_CORE_00915]): si el objeto de origen asignado contiene un valor, la referencia interna se revincula (rebound) al destino del objeto de origen; si contiene un error, este se copia o se mueve. Además, mediante EmplaceError [SWS_CORE_00916] se puede construir un nuevo error in-place. Dos instancias pueden intercambiar su contenido mediante Swap [SWS_CORE_00917].

La destrucción se realiza mediante el destructor [SWS_CORE_00913], que es trivial siempre que se cumpla std::is_trivially_destructible<E>::value. En cuanto a la concurrencia, los accesos no mutables como HasValue [SWS_CORE_00918] son thread-safe, mientras que las operaciones modificadoras como EmplaceError [SWS_CORE_00916], las asignaciones y Swap [SWS_CORE_00917] están especificadas como no thread-safe.

Diagrama de estados: ciclo de vida y transiciones de estado entre vinculación de referencia y estado de error. Fuentes: [SWS_CORE_00904], [SWS_CORE_00905], [SWS_CORE_00913], [SWS_CORE_00914], [SWS_CORE_00916].

Ruta de uso

El uso típico de ara::core::Result<T &, E> se divide en creación, evaluación de estado y acceso condicional:

  1. Creación: El productor crea la instancia tras la ejecución de una operación; en caso de éxito, mediante FromValue [SWS_CORE_00904] o, en caso de error, mediante FromError ([SWS_CORE_00905], [SWS_CORE_00906], [SWS_CORE_00907]).
  2. Comprobación de estado: El consumidor comprueba el estado mediante HasValue() [SWS_CORE_00918] o el operador de conversión booleano operator bool() [SWS_CORE_00919]. Alternativamente, mediante CheckError() [SWS_CORE_00937] se puede comprobar directamente la igualdad con un código de error determinado.
  3. Acceso a valor o error:
    • Si hay un valor presente, el acceso se realiza mediante Value() ([SWS_CORE_00924], [SWS_CORE_00925]), el operador de desreferenciación operator*() ([SWS_CORE_00920], [SWS_CORE_00921]) o el operador de acceso a miembros operator->() ([SWS_CORE_00922], [SWS_CORE_00923]).
    • Si existe un error, la referencia al error se consulta mediante Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]).
  4. Transformación y procesamiento funcional posterior:
    • Bind() [SWS_CORE_00941] aplica un callable al valor referenciado y lo transforma, siempre que haya un valor presente; en caso de error, se devuelve un nuevo Result con el error copiado.
    • Resolve() ([SWS_CORE_00939], [SWS_CORE_00940]) proporciona el valor referenciado o, en caso de error, llama a un callable de reserva que devuelve una referencia compatible con el tipo.
    • A través de Ok() ([SWS_CORE_00926], [SWS_CORE_00927]) o Err() ([SWS_CORE_00931], [SWS_CORE_00932]), el estado puede transferirse a un ara::core::Optional.

Diagrama de secuencia: secuencia típica de interacción durante la provisión, validación y acceso a la referencia o al error. Fuentes: [SWS_CORE_00904], [SWS_CORE_00905], [SWS_CORE_00918], [SWS_CORE_00924], [SWS_CORE_00928].

Escenarios de error

Al trabajar con ara::core::Result<T &, E>, deben cumplirse las precondiciones para evitar errores en tiempo de ejecución:

  • Infracciones (Violations):
    • Si se llama a Value() ([SWS_CORE_00924], [SWS_CORE_00925]), operator*() ([SWS_CORE_00920], [SWS_CORE_00921]) o operator->() ([SWS_CORE_00922], [SWS_CORE_00923]) a pesar de que la instancia no contiene ningún valor, se produce una ResultWithNoValueViolation.
    • Si se llama a Error() ([SWS_CORE_00928], [SWS_CORE_00929], [SWS_CORE_00930]) a pesar de que la instancia contiene un valor, se produce una ResultWithNoErrorViolation.
  • Tratamiento de excepciones: Los métodos ValueOrThrow() ([SWS_CORE_00938], [SWS_CORE_00949]) proporcionan en caso de éxito la referencia al objeto, pero lanzan en caso de error la excepción asociada al error. Si las excepciones de C++ están desactivadas en la toolchain, estos métodos no participan en la resolución de sobrecargas.
  • Valores de reserva seguros: Para evitar infracciones (violations) y excepciones, se ofrecen ValueOr() ([SWS_CORE_00933], [SWS_CORE_00934]) y ErrorOr() ([SWS_CORE_00935], [SWS_CORE_00936]): ValueOr() proporciona una copia del objeto referenciado o un valor predeterminado especificado; ErrorOr() devuelve el error contenido o un error predeterminado.

<h4>Contexto</h4>
<p>La clase de plantilla <code>ara::core::Result&lt;T &amp;, E&gt;</code> representa una especialización parcial del tipo de resultado genérico <code>Result</code> para referencias. Sirve en la AUTOSAR Adaptive Platform como tipo de retorno unificado para operaciones que, en caso de ejecución exitosa, no crean ni copian un nuevo valor en la pila del llamador, sino que proporcionan una referencia lvalue a un objeto existente (<code>value_type</code> según <a class="spec-record-ref" data-req="SWS_CORE_00902" href="../spec/record.html?id=SWS_CORE_00902">[SWS_CORE_00902]</a>). Si se produce un error durante la ejecución, la instancia transporta en su lugar un objeto de error (<code>error_type</code> según <a class="spec-record-ref" data-req="SWS_CORE_00903" href="../spec/record.html?id=SWS_CORE_00903">[SWS_CORE_00903]</a>).</p>
<p>Para el tipo de error <code>E</code>, la especificación exige una condición obligatoria: si la comprobación en tiempo de compilación resulta en <code>E != ara::core::ErrorCode</code>, la implementación debe generar un error de compilador. Interpretación: Es probable que esta restricción garantice que los errores estén vinculados de forma uniforme en toda la plataforma a los dominios y códigos de error de AUTOSAR Adaptive. En este sentido, la clase interactúa principalmente como medio de transferencia síncrono entre un componente invocado (productor) y el llamador (consumidor), lo que permite transmitir referencias sin asignación dinámica ni duplicación de objetos.</p>

<h4>Ciclo de vida</h4>
<p>Una instancia de <code>ara::core::Result&lt;T &amp;, E&gt;</code> se encuentra en todo momento en exactamente uno de dos estados: contiene una referencia vinculada a un objeto lvalue del tipo <code>T</code> o bien un objeto de error del tipo <code>E</code>.</p>
<p>La creación se realiza, según el estado, a través de interfaces especializadas:</p>
<ul>
<li><strong>Estado de valor:</strong> La instanciación se realiza mediante el constructor <a class="spec-record-ref" data-req="SWS_CORE_00908" href="../spec/record.html?id=SWS_CORE_00908">[SWS_CORE_00908]</a> o la función auxiliar estática <code>FromValue</code> <a class="spec-record-ref" data-req="SWS_CORE_00904" href="../spec/record.html?id=SWS_CORE_00904">[SWS_CORE_00904]</a>. Ambas interfaces imponen que el argumento proporcionado sea un lvalue; pasar rvalues da lugar a un programa erróneo (<code>ill-formed</code>).</li>
<li><strong>Estado de error:</strong> La asignación de un error se realiza mediante constructores de lvalue y rvalue (<a class="spec-record-ref" data-req="SWS_CORE_00909" href="../spec/record.html?id=SWS_CORE_00909">[SWS_CORE_00909]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00910" href="../spec/record.html?id=SWS_CORE_00910">[SWS_CORE_00910]</a>), construcción por copia y por movimiento (<a class="spec-record-ref" data-req="SWS_CORE_00911" href="../spec/record.html?id=SWS_CORE_00911">[SWS_CORE_00911]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00912" href="../spec/record.html?id=SWS_CORE_00912">[SWS_CORE_00912]</a>) o a través de <code>FromError</code> (<a class="spec-record-ref" data-req="SWS_CORE_00905" href="../spec/record.html?id=SWS_CORE_00905">[SWS_CORE_00905]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00906" href="../spec/record.html?id=SWS_CORE_00906">[SWS_CORE_00906]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00907" href="../spec/record.html?id=SWS_CORE_00907">[SWS_CORE_00907]</a>), donde <a class="spec-record-ref" data-req="SWS_CORE_00907" href="../spec/record.html?id=SWS_CORE_00907">[SWS_CORE_00907]</a> permite la construcción directa in-place de un error mediante paquetes de parámetros.</li>
</ul>
<p>Interpretación: Dado que <code>Result&lt;T &amp;, E&gt;</code> solo vincula una referencia, no asume la propiedad del objeto de destino <code>T</code>; por lo tanto, el tiempo de vida de este debe superar el tiempo de vida de la instancia de <code>Result</code>, así como la evaluación. Por el contrario, el objeto de error <code>E</code> se encuentra en posesión directa de la instancia.</p>
<p>Los cambios de estado y las asignaciones se controlan mediante los operadores de asignación por copia y por movimiento (<a class="spec-record-ref" data-req="SWS_CORE_00914" href="../spec/record.html?id=SWS_CORE_00914">[SWS_CORE_00914]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00915" href="../spec/record.html?id=SWS_CORE_00915">[SWS_CORE_00915]</a>): si el objeto de origen asignado contiene un valor, la referencia interna se revincula (rebound) al destino del objeto de origen; si contiene un error, este se copia o se mueve. Además, mediante <code>EmplaceError</code> <a class="spec-record-ref" data-req="SWS_CORE_00916" href="../spec/record.html?id=SWS_CORE_00916">[SWS_CORE_00916]</a> se puede construir un nuevo error in-place. Dos instancias pueden intercambiar su contenido mediante <code>Swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00917" href="../spec/record.html?id=SWS_CORE_00917">[SWS_CORE_00917]</a>.</p>
<p>La destrucción se realiza mediante el destructor <a class="spec-record-ref" data-req="SWS_CORE_00913" href="../spec/record.html?id=SWS_CORE_00913">[SWS_CORE_00913]</a>, que es trivial siempre que se cumpla <code>std::is_trivially_destructible&lt;E&gt;::value</code>. En cuanto a la concurrencia, los accesos no mutables como <code>HasValue</code> <a class="spec-record-ref" data-req="SWS_CORE_00918" href="../spec/record.html?id=SWS_CORE_00918">[SWS_CORE_00918]</a> son thread-safe, mientras que las operaciones modificadoras como <code>EmplaceError</code> <a class="spec-record-ref" data-req="SWS_CORE_00916" href="../spec/record.html?id=SWS_CORE_00916">[SWS_CORE_00916]</a>, las asignaciones y <code>Swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00917" href="../spec/record.html?id=SWS_CORE_00917">[SWS_CORE_00917]</a> están especificadas como no thread-safe.</p>

<h4>Ruta de uso</h4>
<p>El uso típico de <code>ara::core::Result&lt;T &amp;, E&gt;</code> se divide en creación, evaluación de estado y acceso condicional:</p>
<ol>
<li><strong>Creación:</strong> El productor crea la instancia tras la ejecución de una operación; en caso de éxito, mediante <code>FromValue</code> <a class="spec-record-ref" data-req="SWS_CORE_00904" href="../spec/record.html?id=SWS_CORE_00904">[SWS_CORE_00904]</a> o, en caso de error, mediante <code>FromError</code> (<a class="spec-record-ref" data-req="SWS_CORE_00905" href="../spec/record.html?id=SWS_CORE_00905">[SWS_CORE_00905]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00906" href="../spec/record.html?id=SWS_CORE_00906">[SWS_CORE_00906]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00907" href="../spec/record.html?id=SWS_CORE_00907">[SWS_CORE_00907]</a>).</li>
<li><strong>Comprobación de estado:</strong> El consumidor comprueba el estado mediante <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00918" href="../spec/record.html?id=SWS_CORE_00918">[SWS_CORE_00918]</a> o el operador de conversión booleano <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00919" href="../spec/record.html?id=SWS_CORE_00919">[SWS_CORE_00919]</a>. Alternativamente, mediante <code>CheckError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00937" href="../spec/record.html?id=SWS_CORE_00937">[SWS_CORE_00937]</a> se puede comprobar directamente la igualdad con un código de error determinado.</li>
<li><strong>Acceso a valor o error:</strong>
<ul>
<li>Si hay un valor presente, el acceso se realiza mediante <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00924" href="../spec/record.html?id=SWS_CORE_00924">[SWS_CORE_00924]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00925" href="../spec/record.html?id=SWS_CORE_00925">[SWS_CORE_00925]</a>), el operador de desreferenciación <code>operator*()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00920" href="../spec/record.html?id=SWS_CORE_00920">[SWS_CORE_00920]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00921" href="../spec/record.html?id=SWS_CORE_00921">[SWS_CORE_00921]</a>) o el operador de acceso a miembros <code>operator-&gt;()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00922" href="../spec/record.html?id=SWS_CORE_00922">[SWS_CORE_00922]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00923" href="../spec/record.html?id=SWS_CORE_00923">[SWS_CORE_00923]</a>).</li>
<li>Si existe un error, la referencia al error se consulta mediante <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00928" href="../spec/record.html?id=SWS_CORE_00928">[SWS_CORE_00928]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00929" href="../spec/record.html?id=SWS_CORE_00929">[SWS_CORE_00929]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00930" href="../spec/record.html?id=SWS_CORE_00930">[SWS_CORE_00930]</a>).</li>
</ul>
</li>
<li><strong>Transformación y procesamiento funcional posterior:</strong>
<ul>
<li><code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00941" href="../spec/record.html?id=SWS_CORE_00941">[SWS_CORE_00941]</a> aplica un callable al valor referenciado y lo transforma, siempre que haya un valor presente; en caso de error, se devuelve un nuevo <code>Result</code> con el error copiado.</li>
<li><code>Resolve()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00939" href="../spec/record.html?id=SWS_CORE_00939">[SWS_CORE_00939]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00940" href="../spec/record.html?id=SWS_CORE_00940">[SWS_CORE_00940]</a>) proporciona el valor referenciado o, en caso de error, llama a un callable de reserva que devuelve una referencia compatible con el tipo.</li>
<li>A través de <code>Ok()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00926" href="../spec/record.html?id=SWS_CORE_00926">[SWS_CORE_00926]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00927" href="../spec/record.html?id=SWS_CORE_00927">[SWS_CORE_00927]</a>) o <code>Err()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00931" href="../spec/record.html?id=SWS_CORE_00931">[SWS_CORE_00931]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00932" href="../spec/record.html?id=SWS_CORE_00932">[SWS_CORE_00932]</a>), el estado puede transferirse a un <code>ara::core::Optional</code>.</li>
</ul>
</li>
</ol>
