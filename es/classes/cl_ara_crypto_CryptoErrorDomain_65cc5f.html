Sirve para la identificación y traducción textual de todos los códigos de error del módulo crypto.

La clase define el dominio de error central para todos los errores que pueden notificarse a través de las interfaces públicas en el espacio de nombres ara::crypto [SWS_CRYPT_19950]. Entre sus tareas fundamentales se encuentran la devolución del nombre de dominio unívoco, así como la traducción de códigos de error de la enumeración CryptoErrc a mensajes de error comprensibles [SWS_CRYPT_19953]. Todas las funciones de consulta están diseñadas de forma segura para subprocesos y segura frente a excepciones, mientras que el método para lanzar excepciones no participa en la resolución de sobrecargas cuando las excepciones de C++ están desactivadas [SWS_CRYPT_19954].

Contexto

La clase ara::crypto::CryptoErrorDomain actúa como dominio de error especializado dentro de AUTOSAR Adaptive Platform. Según su definición de clase, deriva de ara::core::ErrorDomain y está declarada como final. Su responsabilidad central consiste en representar todos los errores que pueden ser notificados por las interfaces públicas dentro del espacio de nombres ara::crypto. Asocia a los errores una identificación de dominio unívoca, que puede consultarse a través del método Name [SWS_CRYPT_19950].

Para una vinculación de tipos uniforme, la clase proporciona dos alias relacionados con tipos: como alias, Errc remite directamente a la enumeración CryptoErrc para códigos de error criptográficos [SWS_CRYPT_19903], mientras que Exception referencia la clase de excepción base CryptoException [SWS_CRYPT_19904]. Como interlocutores de interacción actúan primordialmente los bloques funcionales criptográficos que generan errores de este dominio, así como el software de aplicación que recibe y evalúa errores a través de los mecanismos base de ara::core.

Diagrama de contexto: Integración de CryptoErrorDomain en el tratamiento de errores entre las API de ara::crypto, la clase base ara::core::ErrorDomain y la aplicación. Fuentes: [SWS_CRYPT_19950], [SWS_CRYPT_19903], [SWS_CRYPT_19904].

Ciclo de vida

La creación de objetos de CryptoErrorDomain se realiza a través del constructor por defecto sin parámetros, el cual está especificado como constexpr y noexcept [SWS_CRYPT_19902]. Gracias a la declaración como constexpr, una instancia puede construirse ya en tiempo de compilación. Interpretación: En implementaciones típicas de la plataforma, el dominio de error probablemente debería existir como un singleton de larga vida o estático, de modo que los códigos de error puedan hacer referencia a la misma instancia de dominio a lo largo de todo el proceso sin asignación dinámica de memoria.

Tras la instanciación, el objeto posee un carácter constante y sin estado; una jerarquía de herencia por debajo de esta clase queda excluida mediante la palabra clave final. En cuanto a la concurrencia, tanto el constructor [SWS_CRYPT_19902] como los métodos de consulta Name [SWS_CRYPT_19950], Message [SWS_CRYPT_19953] y ThrowAsException [SWS_CRYPT_19954] están clasificados explícitamente como seguros para subprocesos (thread-safe). Por lo tanto, las instancias pueden ser utilizadas en paralelo por varios subprocesos sin sincronización externa.

Ruta de uso

El flujo regular en la interacción con CryptoErrorDomain se divide en los siguientes pasos:

  1. Una operación dentro del espacio de nombres ara::crypto falla y genera un objeto de error de tipo ara::core::ErrorCode, el cual está vinculado a CryptoErrorDomain.
  2. La aplicación llamadora o la rutina de tratamiento de errores comprueba el origen del error y, en caso necesario, puede obtener el nombre unívoco del dominio mediante Name() [SWS_CRYPT_19950].
  3. Para generar salidas de registro o mensajes de diagnóstico se invoca el método Message() con el errorCode pasado, el cual resuelve el código y devuelve el mensaje de texto correspondiente como const char* [SWS_CRYPT_19953].
  4. Si el llamador desea convertir el error en una excepción de C++, se realiza la llamada a ThrowAsException(), provocando el lanzamiento de una excepción adecuada basada en CryptoException [SWS_CRYPT_19954], [SWS_CRYPT_19904].

Diagrama de secuencia: Resolución de errores y salida de texto a través de las interfaces de CryptoErrorDomain. Fuentes: [SWS_CRYPT_19950], [SWS_CRYPT_19953].

Escenarios de error

En el tratamiento de errores, la clase presenta garantías diferenciadas en cuanto a la seguridad frente a excepciones. Los métodos Name [SWS_CRYPT_19950] y Message [SWS_CRYPT_19953] están declarados como noexcept y son completamente seguros frente a excepciones (exception safe). Si se pasara a Message un valor numérico que no esté definido en la enumeración CryptoErrc, presumiblemente se entregaría un mensaje genérico de reserva; queda descartada una interrupción por excepciones.

Por el contrario, el método ThrowAsException está especificado como no seguro frente a excepciones (not exception safe) y provisto del atributo [[noreturn]], ya que su propósito previsto reside en lanzar una excepción [SWS_CRYPT_19954]. Una condición de contorno esencial concierne a configuraciones de plataforma sin soporte de excepciones: si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador, ThrowAsException no participa en la resolución de sobrecargas [SWS_CRYPT_19954]. En tales sistemas, la llamada no es compilable y el tratamiento de errores debe procesarse obligatoriamente a través de mecanismos basados en valores de error, como objetos de resultado.

Esta guía se basa en la especificación AUTOSAR Adaptive Platform R25-11.

Uso y contexto de llamada

El constructor predeterminado CryptoErrorDomain() inicializa una instancia del dominio de errores para operaciones criptográficas [SWS_CRYPT_19902]. Está especificado como constexpr y noexcept, no toma argumentos y no tiene valor de retorno. La ejecución se realiza de forma síncrona y puede tener lugar en tiempo de compilación. En programas de aplicación, es probable que rara vez sea necesaria una instanciación manual, ya que el acceso al dominio se realiza de forma habitual mediante la función global GetCryptoErrorDomain() [SWS_CRYPT_19952].

Tratamiento de errores y concurrencia

La creación del objeto está definida como exception safe así como thread-safe [SWS_CRYPT_19902]. Puesto que el constructor está declarado con noexcept, no se producen errores ni excepciones durante la llamada; no existen mensajes de error a DET o DEM para este constructor.

Interacción en el módulo

El dominio creado forma el contexto para las descripciones de errores criptográficos:

  • Encapsula los códigos de error de la enumeración CryptoErrc [SWS_CRYPT_10099] mediante el alias de tipo Errc [SWS_CRYPT_19903].
  • A través de la función libre MakeErrorCode() se crean instancias de ara::core::ErrorCode que hacen referencia de forma fija a este dominio [SWS_CRYPT_19951].
  • Las funciones miembro del dominio permiten consultar el identificador mediante Name() [SWS_CRYPT_19950], resolver el texto a través de Message() [SWS_CRYPT_19953] y lanzar errores específicos del sistema mediante ThrowAsException() [SWS_CRYPT_19954] con el tipo base Exception [SWS_CRYPT_19904].
