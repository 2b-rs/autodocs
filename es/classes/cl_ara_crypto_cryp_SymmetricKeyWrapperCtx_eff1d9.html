Permite el empaquetado y desempaquetado seguro de claves mediante cifrado de clave simétrica.

El contexto SymmetricKeyWrapperCtx sirve para el empaquetado y desempaquetado criptográfico de claves mediante algoritmos simétricos. Antes de la ejecución de Wrap o UnwrapSymmetricKey, el contexto debe configurarse a través de SetKey con una clave de cifrado de clave (KEK) compatible [SWS_CRYPT_24018]. Todas las operaciones requieren las autorizaciones de uso correspondientes de los objetos de clave involucrados y notifican errores a través de ara::core::Result con semántica de reversión [SWS_CRYPT_24014]. La interfaz es segura frente a excepciones y está especificada como segura frente a subprocesos para el funcionamiento concurrente.

Contexto

La clase SymmetricKeyWrapperCtx define la interfaz estandarizada para algoritmos de envoltura de claves simétricas (Key Wrapping) dentro de AUTOSAR Adaptive Platform. Su responsabilidad central consiste en la protección criptográfica de claves durante la exportación, así como en la recuperación de claves empaquetadas para uso interno. En este contexto, la clase interactúa principalmente con claves de cifrado de claves (Key Encryption Keys, KEK), que se proporcionan bien como un objeto de clave volátil del tipo SymmetricKey o bien de forma persistente a través de un KeySlot [SWS_CRYPT_24018], [SWS_CRYPT_50034]. Durante el empaquetado, el contexto recibe un CryptoObject genérico [SWS_CRYPT_24014], mientras que la operación de desempaquetado genera y devuelve un nuevo objeto SymmetricKey listo para su uso [SWS_CRYPT_24016].

Ciclo de vida

Las instancias de SymmetricKeyWrapperCtx se gestionan a través del smart pointer tipado Sptr (un alias para std::shared_ptr<SymmetricKeyWrapperCtx>) [SWS_CRYPT_24001]. La creación efectiva de objetos debería llevarse a cabo a través de una factoría de proveedores competente, ya que la clase representa una interfaz abstracta con métodos virtuales puros. Todas las funciones miembro de la interfaz están especificadas como seguras frente a excepciones (exception safe), así como seguras para subprocesos (thread-safe), lo que posibilita su uso seguro en componentes de software concurrentes [SWS_CRYPT_24014], [SWS_CRYPT_24016].

A lo largo de su ciclo de vida, el contexto atraviesa dos fases esenciales: Inmediatamente después de la instanciación, se encuentra en un estado no inicializado. En esta fase, las operaciones criptográficas y los cálculos de búfer fallan con el error kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014]. Solo mediante la llamada exitosa a SetKey con una KEK o KeySlot compatible, el contexto pasa al estado operativo, en el que las claves se pueden empaquetar o desempaquetar de forma segura [SWS_CRYPT_24018], [SWS_CRYPT_50034].

Ruta de uso

El flujo regular para empaquetar una clave requiere una secuencia coordinada de configuración, verificación de búfer y ejecución. En primer lugar, la aplicación configura el contexto a través de SetKey con el objeto KEK deseado [SWS_CRYPT_24018] o vincula un KeySlot correspondiente [SWS_CRYPT_50034]. En el segundo paso, la aplicación determina mediante GetRequiredWrappedKeyBufferSize el tamaño máximo de búfer de salida requerido para el objeto de destino que se va a empaquetar [SWS_CRYPT_50035]. Una vez proporcionada una zona de memoria dimensionada adecuadamente (ReadWriteMemRegion), se realiza la llamada a Wrap, la cual escribe los datos de clave serializados y cifrados en el búfer y devuelve el número exacto de bytes [SWS_CRYPT_24014].

Diagrama de secuencias: Secuencia típica de llamadas para el empaquetado simétrico de claves. Fuentes: [SWS_CRYPT_24018], [SWS_CRYPT_50035], [SWS_CRYPT_24014]

Para el proceso complementario de desempaquetado, tras la configuración mediante SetKey, la aplicación pasa el búfer de entrada con los datos envueltos a UnwrapSymmetricKey [SWS_CRYPT_24016]. En este proceso, deben especificarse explícitamente el identificador de algoritmo de destino (targetAlgId), así como los indicadores de uso permitidos (allowedUsage) para la nueva clave simétrica que se va a generar [SWS_CRYPT_24016].

Escenarios de error

Los métodos de la clase señalan errores a través del tipo de retorno ara::core::Result con semántica de reversión (rollback). Entre los escenarios de error centrales se encuentran:

  • Falta de inicialización: Si se llama a GetRequiredWrappedKeyBufferSize, Wrap o UnwrapSymmetricKey antes de una asignación exitosa de clave, devuelven ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_50035], [SWS_CRYPT_24014], [SWS_CRYPT_24016].
  • Vulneración de derechos de uso: Al establecer la KEK, esta debe poseer al menos el permiso kAllowKeyWrapping o kAllowKeyUnwrapping; de lo contrario, SetKey falla con ara::crypto::CryptoErrc::kUsageViolation [SWS_CRYPT_24018]. En Wrap, la ausencia de kAllowKeyWrapping en la KEK o la ausencia de kAllowSecuredExport en el objeto que se va a empaquetar conduce asimismo a kUsageViolation [SWS_CRYPT_24014]. Durante el desempaquetado, se comprueba si la KEK permite kAllowKeyUnwrapping [SWS_CRYPT_24016].
  • Incompatibilidades y errores de búfer: Si el búfer de destino para Wrap es demasiado pequeño, se notifica ara::crypto::CryptoErrc::kInsufficientCapacity [SWS_CRYPT_24014]. Los formatos de clave erróneos o los tipos incompatibles dan lugar a ara::crypto::CryptoErrc::kInvalidArgument [SWS_CRYPT_24014], [SWS_CRYPT_24016]. Si el contexto solo admite slots o solo objetos de clave, SetKey notifica el error kUnsupported [SWS_CRYPT_24018], [SWS_CRYPT_50034].
  • Conflictos de recursos y slots vacíos: Si la operación accede a un recurso ocupado, se devuelve ara::crypto::CryptoErrc::kBusyResource; si el KeySlot referenciado está vacío, esto resulta en ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_24014], [SWS_CRYPT_24016].

      Uso y semántica
      

      La función miembro síncrona SetKey configura una instancia de ara::crypto::cryp::SymmetricKeyWrapperCtx de modo que el objeto SymmetricKey::Sptr pasado se utilice como Key Encryption Key (KEK) para operaciones de clave subsiguientes [SWS_CRYPT_24018]. La función está especificada como un método virtual puro con noexcept y devuelve un ara::core::Result<void> vacío, siempre que la asignación haya sido exitosa [SWS_CRYPT_24018].
      


      Tratamiento de errores y rollback
      

      Si se produce un error durante la configuración, se aplica una semántica de rollback vinculante, de modo que el estado del contexto permanece inalterado [SWS_CRYPT_24018]. Las posibles causas de error se representan mediante códigos de error de ara::crypto::CryptoErrc:
      

        

      • kIncompatibleObject: el objeto de clave pasado es incompatible con el contexto simétrico [SWS_CRYPT_24018].
        • 

      • kUsageViolation: el uso permitido de la clave no comprende ni kAllowKeyWrapping ni kAllowKeyUnwrapping [SWS_CRYPT_24018].
        • 

      • kUnsupported: la implementación del contexto admite exclusivamente el establecimiento de una clave mediante un KeySlot [SWS_CRYPT_24018].
        • 

      


      Concurrencia e interacción
      

      El método está especificado como thread-safe y seguro frente a excepciones (exception safe) [SWS_CRYPT_24018]. Si las claves se gestionan mediante ranuras o si el contexto admite exclusivamente KeySlots, existe para el mismo contexto de encapsulador la sobrecarga alternativa SetKey con KeySlot::Sptr [SWS_CRYPT_50034]. Esta configura el contexto para cargar la clave depositada en la ranura en el momento de ejecución del key-wrapping [SWS_CRYPT_50034].
      

      

      Esta nota de uso se basa en la especificación AUTOSAR Adaptive Platform Release R25-11.

              función UnwrapSymmetricKey [SWS_CRYPT_24016] Upstream: RS_CRYPTO_02115
              

              virtual ara::core::Result< SymmetricKey::Sptr > UnwrapSymmetricKey (ReadOnlyMemRegion wrappedKey, AlgId targetAlgId, AllowedUsageFlags allowedUsage) const noexcept=0;
              

              Unwrap a wrapped key using the previously set key encryption key and return an SymmetricKey.
              

              

              

              

              

              

              

              

              
  GENERADO POR IA
  no revisado
  Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: fe87df5f5eae
  Procedencia
  

              

              

              El método UnwrapSymmetricKey de la interfaz ara::crypto::cryp::SymmetricKeyWrapperCtx descifra una clave empaquetada utilizando la Key Encryption Key (KEK) establecida previamente y devuelve un nuevo objeto SymmetricKey [SWS_CRYPT_24016]. Como parámetros, la función síncrona recibe el búfer de entrada con los datos protegidos de la clave (wrappedKey), el identificador de algoritmo para la clave de destino (targetAlgId) así como indicadores de bits (flags) para sus tipos de transformación permitidos (allowedUsage) [SWS_CRYPT_24016].
              

              En caso de ejecución satisfactoria, el valor de retorno ara::core::Result<SymmetricKey::Sptr> contiene un puntero inteligente al objeto de clave generado o señala un error con semántica de reversión (rollback) [SWS_CRYPT_24016]. Las posibles causas de error son:
              

                

              • InvalidArgument: Los datos de clave transferidos en wrappedKey no se pueden desempaquetar, por ejemplo debido a un formato no válido o a un tamaño de búfer incorrecto [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUninitializedContext: El contexto de empaquetado (wrapper) todavía no se ha inicializado con una KEK adecuada [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUsageViolation: Las restricciones de uso de la KEK prohíben el desempaquetado (ausencia de kAllowKeyUnwrapping) [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kUnknownIdentifier: El valor transferido para targetAlgId no se conoce o no se admite [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kIncompatibleArguments: Los indicadores allowedUsage especificados son incompatibles con targetAlgId o con el tipo de clave [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kBusyResource: Un recurso del sistema requerido para la operación está ocupado actualmente [SWS_CRYPT_24016].
                • 

              • ara::crypto::CryptoErrc::kEmptyKeySlot: Un KeySlot configurado para la operación está vacío [SWS_CRYPT_24016].
