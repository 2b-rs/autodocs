Permite a las aplicaciones la provisión de marcas de tiempo específicas del sistema para eventos de seguridad de IdsM.

La clase ara::idsm::TimestampProvider proporciona una interfaz a través de la cual las aplicaciones pueden suministrar marcas de tiempo para el módulo IdsM mediante un PPort modelado [SWS_AIDSM_10400]. La activación y desactivación de las callbacks de consulta se realiza mediante los métodos Offer() y StopOffer() [SWS_AIDSM_10408] [SWS_AIDSM_10409]. Las instancias son no copiables, admiten semántica de movimiento y requieren sincronización externa en métodos sin seguridad para subprocesos garantizada.

Contexto

La clase ara::idsm::TimestampProvider sirve como interfaz para la provisión de marcas de tiempo para el módulo Intrusion Detection System Manager (IdsM) dentro de AUTOSAR Adaptive Platform [SWS_AIDSM_10400]. Los eventos y registros relevantes para la seguridad en IdsM requieren información temporal fiable, la cual se obtiene mediante esta clase proveedora desde la plataforma o desde una fuente de tiempo específica de la aplicación. Una instancia de TimestampProvider se vincula a un PPort modelado a través de un ara::core::InstanceSpecifier [SWS_AIDSM_10401]. Dado que el método GetTimestamp() está definido como función callback puramente virtual [SWS_AIDSM_10407], TimestampProvider actúa como clase base abstracta de la que deben derivarse implementaciones concretas.

Ciclo de vida

La creación de un proveedor de marcas de tiempo se realiza explícitamente a través del constructor indicando el ara::core::InstanceSpecifier correspondiente [SWS_AIDSM_10401]. Este constructor está declarado como seguro para subprocesos. Las operaciones de copia están completamente impedidas: tanto el constructor de copia [SWS_AIDSM_10404] como el operador de asignación por copia [SWS_AIDSM_10406] están eliminados (= delete). Por tanto, las instancias poseen una identidad unívoca y no pueden duplicarse.

En cambio, la clase admite semántica de movimiento: el constructor de movimiento transfiere recursos existentes de forma segura para subprocesos a un nuevo objeto [SWS_AIDSM_10403]. La asignación por movimiento mediante operator= también está disponible, pero a diferencia del constructor no es segura para subprocesos [SWS_AIDSM_10405]. El ciclo de vida de la provisión activa del servicio se controla explícitamente tras la instanciación: mediante el método Offer() se activa el registro para IdsM [SWS_AIDSM_10408]. Con StopOffer() se vuelve a impedir la provisión [SWS_AIDSM_10409]. La liberación de la instancia se realiza mediante el destructor virtual [SWS_AIDSM_10402], el cual está especificado como no seguro para subprocesos. Interpretación: antes de la destrucción de una instancia, normalmente debería llamarse a StopOffer() para garantizar que ya no se produzcan llamadas pendientes por parte de IdsM.

Ruta de uso

El uso típico requiere la derivación de una clase específica de la aplicación que sobrescriba el método GetTimestamp() y devuelva la marca de tiempo actual como TimestampType [SWS_AIDSM_10407]. Tan pronto como la instancia haya sido creada para el puerto correspondiente [SWS_AIDSM_10401], la aplicación señala la disponibilidad operativa mediante la llamada a Offer() [SWS_AIDSM_10408]. A partir de este momento, IdsM puede invocar de forma autónoma el método callback GetTimestamp() para ubicar temporalmente los eventos. Si se va a finalizar el servicio o a apagar el componente, StopOffer() retira la disponibilidad de la interfaz [SWS_AIDSM_10409].

Diagrama de secuencia: secuencia de interacción durante la inicialización, la consulta de marcas de tiempo por parte de IdsM y la finalización del proveedor. Fuentes: [SWS_AIDSM_10401], [SWS_AIDSM_10407], [SWS_AIDSM_10408], [SWS_AIDSM_10409]

Escenarios de error

Todos los métodos de la interfaz están declarados como noexcept y no lanzan excepciones C++. Los errores en la activación de la provisión del servicio se transmiten, en su lugar, mediante el tipo de retorno ara::core::Result<void> de Offer() [SWS_AIDSM_10408]. Interpretación: si el registro en el framework de comunicación o de plataforma falla (por ejemplo, debido a una configuración de puerto inadecuada), el Result devuelto contiene un código de error correspondiente que debe comprobarse antes de continuar con su uso.

El comportamiento de concurrencia requiere especial atención: ni el destructor [SWS_AIDSM_10402] ni los métodos Offer() [SWS_AIDSM_10408], StopOffer() [SWS_AIDSM_10409], operator=(&&) [SWS_AIDSM_10405] o GetTimestamp() [SWS_AIDSM_10407] están clasificados como seguros para subprocesos. Por lo tanto, los llamadores deben asegurarse de que las operaciones del ciclo de vida y los procesamientos de callbacks se ejecuten de manera sincronizada entre subprocesos y no se originen carreras de datos.

Esta guía se basa en los requisitos de la especificación AUTOSAR para el módulo idsm (R25-11).

  Procedencia
  

                                  

                                  

                                  La función miembro síncrona Offer pone a disposición el servicio de marca de tiempo y habilita al Intrusion Detection System Manager (IdsM) las llamadas posteriores a GetTimestamp [SWS_AIDSM_10408]. La declaración se realiza a través de la cabecera ara/idsm/timestamp_provider.h sin parámetros de transferencia [SWS_AIDSM_10408].
                                  
  
                                  Tratamiento de errores y semántica

El éxito de la puesta a disposición, así como los posibles estados de error, se transmiten al llamador encapsulados en el tipo de retorno ara::core::Result<void> [SWS_AIDSM_10408].
