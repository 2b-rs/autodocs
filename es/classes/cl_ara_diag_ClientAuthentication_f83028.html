Sirve a la aplicación para notificar estados de autenticación y roles de usuario activos al Diagnostic Server.

La interfaz permite a la aplicación informar al Diagnostic Server sobre el estado de autenticación, así como los roles de usuario activos de un cliente de diagnóstico [SWS_DM_01132]. A través de llamadas como Authenticate o OverrideDefaultRoles se controlan las transiciones de estado y se proporcionan identificadores para gestionar listas de acceso dinámicas [SWS_DM_01206]. Los cambios de estado derivados de tiempos de espera pueden supervisarse de forma asíncrona mediante un notificador. Dado que la clase no es segura para subprocesos y no permite copias, el acceso debe realizarse de forma sincronizada dentro de la aplicación.

Contexto

La clase ara::diag::ClientAuthentication sirve como interfaz central para que la aplicación informe a la instancia del Diagnostic Server sobre los estados de autenticación y los roles de usuario actualmente autenticados [SWS_DM_01132], SWS Diagnostics, p. 129. En esta interacción intervienen tres partes esenciales:

  • Aplicación (Application): realiza comprobaciones de autenticación —utilizando interfaces del Diagnostic Server o mediante mecanismos propios de la aplicación— y transmite roles de usuario al Diagnostic Server [SWS_DM_01142].
  • Diagnostic Server / Diagnostic Manager: gestiona las sesiones de diagnóstico y aplica derechos de acceso a los recursos de diagnóstico basándose en los roles y en el estado de autenticación [SWS_DM_01206].
  • Cliente de diagnóstico: un tester externo o cliente SOVD que dirige solicitudes de diagnóstico a la unidad de control [SWS_DM_01210], [SWS_DM_01470].

El número de instancias de ClientAuthentication queda determinado por el elemento de modelo DiagnosticExternalAuthenticationIdentification SWS Diagnostics, p. 129. Este elemento permite configurar una autenticación para un cliente con una dirección de origen fija o a través de un rango de direcciones, en caso de que la dirección de origen final aún no se conozca en tiempo de compilación SWS Diagnostics, p. 129. Interpretación: la asignación de clientes de diagnóstico a instancias concretas de ClientAuthentication se realiza en tiempo de ejecución a partir de estos rangos de direcciones de origen. En el caso de clientes SOVD, al validar el token de autorización mediante ara::diag::SovdAuthorization::ValidateAuthorization, el Diagnostic Server entrega directamente un objeto ClientAuthentication a la aplicación [SWS_DM_01470].

Diagrama de contexto: interlocutores de la interfaz de autenticación. Fuentes: [SWS_DM_01132], [SWS_DM_01202], [SWS_DM_01470], SWS Diagnostics, p. 129

Ciclo de vida

La aplicación obtiene una instancia de ClientAuthentication a través de métodos sobrecargados de ara::diag::ExternalAuthentication::Get [SWS_DM_01202] o en el contexto de la comprobación del token SOVD [SWS_DM_01470]. La clase posee semánticas estrictas de propiedad: el constructor de copia [SWS_DM_01139] y el operador de asignación por copia [SWS_DM_01140] están eliminados (=delete). Las operaciones de movimiento (constructor de movimiento [SWS_DM_01137] y operador de asignación por movimiento [SWS_DM_01138]) están predefinidas por defecto y declaradas como noexcept. El destructor es igualmente noexcept [SWS_DM_01136]. Todas las funciones miembro, así como el destructor, no son seguras para subprocesos (not thread-safe) [SWS_DM_01136], [SWS_DM_01141], [SWS_DM_01142], [SWS_DM_01143], [SWS_DM_01144].

El estado de autenticación se representa mediante el tipo enumerado DiagnosticAuthState [SWS_DM_01133]:

  • kDeAuthenticated (0x00): ningún cliente de diagnóstico está autenticado. Al arrancar el sistema, el cliente se encuentra por defecto en este estado [SWS_DM_01205]. En este caso, se consideran roles estándar aquellos roles (DiagnosticAuthRole) cuyo atributo isDefault esté configurado como TRUE [SWS_DM_01204], [SWS_DM_01134]. A través de OverrideDefaultRoles, estos roles estándar pueden sobrescribirse temporalmente durante un tiempo de expiración establecido [SWS_DM_01141], [SWS_DM_01209].
  • kAuthenticated (0x01): un cliente de diagnóstico está autenticado. Este estado se alcanza llamando a Authenticate, con lo cual se activan en el Diagnostic Server los roles de usuario transferidos [SWS_DM_01142], [SWS_DM_01206].

Se desencadena una transición de estado automática de kAuthenticated de vuelta a kDeAuthenticated cuando un cliente en la sesión predeterminada no envía más solicitudes tras la última confirmación de transmisión (TransmitConfirmation) y expira el tiempo de inactividad [SWS_DM_01210], o cuando se produce un tiempo de espera S3 [SWS_DM_01144], [SWS_DM_02077].

Diagrama de estados: ciclo de vida y transiciones de estado de la autenticación del cliente. Fuentes: [SWS_DM_01133], [SWS_DM_01204], [SWS_DM_01205], [SWS_DM_01206], [SWS_DM_01209], [SWS_DM_01210]

Ruta de uso

El flujo regular para la gestión de la autenticación del cliente comprende los siguientes pasos:

  1. Registrar notificador: la aplicación registra con SetNotifier una función de retrollamada del tipo ClientAuthenticationSetNotifier (std::function<void(DiagnosticAuthState)>) [SWS_DM_01144], [SWS_DM_02077]. De este modo se le informa cuando ocurren cambios de estado, como por ejemplo la transición a kDeAuthenticated por inactividad o un tiempo de espera S3 [SWS_DM_01144]. Una nueva llamada sobrescribe el notificador establecido previamente [SWS_DM_01144].
  2. Consultar estado: mediante el método GetState(), la aplicación puede consultar de forma síncrona el estado de autenticación actual del cliente [SWS_DM_01143].
  3. Notificar autenticación: una vez completada con éxito la autenticación, la aplicación llama a Authenticate con los roles de usuario que deben activarse (ara::core::Vector<DiagnosticAuthRole>) [SWS_DM_01142], [SWS_DM_01134]. El Diagnostic Server establece el estado en kAuthenticated y devuelve un ClientAuthenticationHandle [SWS_DM_01206].
  4. Gestionar derechos de acceso: mediante el ClientAuthenticationHandle obtenido, la aplicación puede configurar la lista de acceso dinámico (DynamicAccessList) para el cliente [SWS_DM_01213], SWS Diagnostics, p. 132. Al mismo tiempo, al utilizar este handle se actualiza la ventana de tiempo de inactividad del cliente SWS Diagnostics, p. 133.

Si el cliente se encuentra en el estado kDeAuthenticated, la aplicación puede invocar en su lugar OverrideDefaultRoles(defaultRoles, timeout) para activar temporalmente roles predeterminados alternativos; en caso de éxito, esta llamada también devuelve un ClientAuthenticationHandle [SWS_DM_01141], [SWS_DM_01209].

Diagrama de secuencia: flujo de llamadas y notificaciones durante la autenticación. Fuentes: [SWS_DM_01142], [SWS_DM_01144], [SWS_DM_01206], [SWS_DM_01210]

Escenarios de error

Los métodos Authenticate, OverrideDefaultRoles y GetState devuelven sus valores de retorno encapsulados en ara::core::Result y están especificados como seguros contra excepciones (exception safe) así como noexcept [SWS_DM_01141], [SWS_DM_01142], [SWS_DM_01143]. En caso de error, se notifica el siguiente código de error estandarizado:

  • DiagErrc::kServiceNotAvailable: se produce cuando la llamada no se puede ejecutar debido a que funcionalidades esenciales del Diagnostic Manager no están disponibles en ese momento [SWS_DM_01141], [SWS_DM_01142], [SWS_DM_01143]. Este error cuenta con semántica de reversión (rollback_semantics), por lo que no permanecen cambios de estado incompletos [SWS_DM_01141], [SWS_DM_01142], [SWS_DM_01143].

Para SetNotifier no se han definido códigos de error estandarizados [SWS_DM_01144]. Como condición previa esencial, OverrideDefaultRoles requiere que el cliente se encuentre en el estado kDeAuthenticated en el momento de la llamada [SWS_DM_01209].

Uso y llamada

La función ara::diag::ClientAuthentication::Authenticate es invocada por una aplicación para comunicar a la instancia de Diagnostic Server la autenticación satisfactoria de un cliente de diagnóstico [SWS_DM_01142]. Esto puede llevarse a cabo tras una autenticación a través de las interfaces del Diagnostic Server o mediante mecanismos propios de la aplicación [SWS_DM_01142].

Como parámetro de entrada, la función recibe userRoles (de tipo ara::core::Vector<DiagnosticAuthRole>). En caso de invocación satisfactoria, el estado de autenticación de la instancia cambia a kAuthenticated y los roles de usuario transferidos se adoptan de forma permanente [SWS_DM_01206]. Como valor de retorno proporciona un ara::core::Result<ClientAuthenticationHandle> [SWS_DM_01142]. Dado que se proporciona de inmediato un objeto Result, es probable que el procesamiento se realice de forma síncrona en el contexto del invocador.

Tratamiento de errores y concurrencia

El método está declarado como noexcept y se considera seguro frente a excepciones (exception safe) [SWS_DM_01142]. Si se produce un error debido a que funcionalidades fundamentales del Diagnostic Manager no están disponibles en el momento de la llamada, la operación falla con semántica de rollback y devuelve DiagErrc::kServiceNotAvailable en el objeto Result [SWS_DM_01142].

En lo que respecta a la concurrencia, el método está especificado expresamente como not thread-safe [SWS_DM_01142]. Por tanto, las invocaciones paralelas sobre el mismo objeto ClientAuthentication no están permitidas y deben ser sincronizadas por la aplicación.

Zusammenspiel y ciclo de vida

El ClientAuthenticationHandle obtenido permite a la aplicación definir o ampliar una DynamicAccessList para el cliente autenticado [SWS_DM_01142]. Además, la invocación inicia o referencia la supervisión de inactividad del cliente: si tras una autenticación satisfactoria en el estado de sesión estándar no se produce otra solicitud UDS durante un periodo de authenticationTimeout, la instancia de Diagnostic Server restablece automáticamente el cliente a kDeAuthenticated [SWS_DM_01210]. Para prevenir este timeout, la aplicación puede actualizar el temporizador a través del método Refresh del handle [SWS_DM_01155].

  Procedencia
  

                  

                  

                  
    Mediante el método síncrono OverrideDefaultRoles de la clase ara::diag::ClientAuthentication, una aplicación puede sobrescribir temporalmente los roles de autenticación estándar (defaultRoles) de un cliente de diagnóstico [SWS_DM_01141]. Los servicios de diagnóstico habilitados para los roles transferidos están a disposición del tester durante el intervalo de tiempo definido en el parámetro timeout [SWS_DM_01141]. El requisito para ello es que el cliente se encuentre en el estado kDeAuthenticated [SWS_DM_01209]. Interpretación: Si la invocación no se realiza en el estado kDeAuthenticated, es probable que la sobrescritura de roles sea rechazada o quede sin efecto, ya que la especificación prescribe el comportamiento exclusivamente para este estado inicial.
