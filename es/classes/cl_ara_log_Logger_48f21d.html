clase ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

Encapsula un contexto de registro para la captura segura para hilos de mensajes de protocolo formateados o modelados.

La clase ara::log::Logger representa un contexto para la captura de mensajes de registro dentro de un proceso de aplicación a través de flujos temporales o formatos de mensaje modelados [SWS_LOG_00064]. Dado que el constructor por defecto está eliminado, la creación y gestión del ciclo de vida se realiza íntegramente mediante el marco de registro [SWS_LOG_00259]. Antes de la preparación consumidora de tiempo de datos de mensaje, se puede consultar el nivel de notificación activo actualmente. Todas las interfaces de la clase están especificadas de forma segura para hilos y permiten la llamada sin sincronización desde múltiples hilos.

Contexto

La clase ara::log::Logger representa un contexto de registrador dentro de un proceso de aplicación o área de proceso en el módulo log. Dicho contexto encapsula un ID de contexto específico, una descripción asociada y un nivel de registro por defecto. Los desarrolladores de aplicaciones interactúan con instancias de registrador para transferir mensajes de registro al marco de registro, ya sea mediante objetos de flujo tales como LogStream [SWS_LOG_00064] o como mensajes modelados estructurados [SWS_LOG_00204]. Las instancias actúan como intermediarias entre los hilos internos de la aplicación y el backend de registro.

Diagrama de contexto: integración del registrador entre la aplicación, el marco de registro y LogStream. Fuentes: [SWS_LOG_00064], [SWS_LOG_00259].

Ciclo de vida

La gestión de las instancias está sujeta a una propiedad estricta por parte del marco de registro. Para garantizar el registro automático en el backend de registro durante la creación y la cancelación del registro durante el apagado del proceso de aplicación, el constructor por defecto está eliminado [SWS_LOG_00259]. Las aplicaciones no deben ni pueden instanciar directamente objetos Logger, sino que deben utilizar en su lugar las funciones de creación ara::log::CreateLogger. La destrucción y liberación se realiza a través del destructor [SWS_LOG_00260], que está controlado por el marco de registro, de modo que los usuarios no necesitan ocuparse del tiempo de vida.

Respecto a la concurrencia, todos los métodos de acceso están especificados como seguros para hilos (thread-safe), entre otros [SWS_LOG_00070], [SWS_LOG_00255] y [SWS_LOG_00260]. Gracias a ello, múltiples hilos concurrentes pueden utilizar el mismo contexto de registrador simultáneamente sin que se requieran mecanismos de sincronización adicionales en el lado de la aplicación.

Ruta de uso

El uso típico de un registrador comprende la verificación de la configuración actual, la adaptación de umbrales y la emisión de mensajes:

  • Verificación de la autorización de salida: antes de costosas preparaciones de datos de registro, se puede consultar mediante IsEnabled si un nivel de registro deseado se notifica activamente [SWS_LOG_00070].
  • Configuración: el umbral mínimo de notificación de una instancia de registrador se puede reconfigurar en tiempo de ejecución a través de SetThreshold [SWS_LOG_00255].
  • Registro basado en flujos: a través de métodos específicos para niveles de severidad individuales (LogFatal [SWS_LOG_00064], LogError [SWS_LOG_00065], LogWarn [SWS_LOG_00066], LogInfo [SWS_LOG_00067], LogDebug [SWS_LOG_00068] o LogVerbose [SWS_LOG_00069]), así como a través del dinámico WithLevel [SWS_LOG_00131], se crea un objeto LogStream. Este recibe datos a través del operador <<. Por lo general, el tiempo de vida del objeto de flujo finaliza con el punto y coma de la sentencia [SWS_LOG_00064].
  • Mensajes modelados: alternativamente, se pueden transferir mensajes tipificados y modelados directamente con Log [SWS_LOG_00204] o especificando atributos con LogWith [SWS_LOG_00133].

Diagrama de secuencia: secuencia típica en la verificación de umbrales y el registro basado en flujos. Fuentes: [SWS_LOG_00070], [SWS_LOG_00067], [SWS_LOG_00064].

Escenarios de error

Las interfaces de la clase están especificadas en gran medida como noexcept y seguras frente a excepciones (exception safe), lo que minimiza interrupciones inesperadas en tiempo de ejecución [SWS_LOG_00070], [SWS_LOG_00255]. No obstante, existen condiciones formales de error y casos límite:

  • Parámetros de modelo incorrectos: si se invoca Log con argumentos que no coinciden con la especificación del mensaje modelado, el programa en C++ está estructurado erróneamente (ill-formed) y falla en tiempo de compilación [SWS_LOG_00204].
  • Falta de propiedades de atributos: si la tupla para LogWith contiene tipos que no cumplen los criterios de atributo requeridos, la función no participa en la resolución de sobrecargas [SWS_LOG_00133]. La exclusión se realiza probablemente mediante SFINAE o conceptos.
  • Seguridad frente a excepciones durante el desmantelamiento: el destructor ~Logger está declarado como not exception safe [SWS_LOG_00260]. Es probable que esto se deba a que durante la cancelación del registro en el backend de registro pueden producirse errores que no deben propagarse mediante excepciones.

Esta guía se basa exclusivamente en la especificación de AUTOSAR para el módulo log en Adaptive Release R25-11.
