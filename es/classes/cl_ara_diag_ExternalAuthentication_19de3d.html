Sirve para recuperar instancias de autenticación para la administración del estado de clientes de diagnóstico externos.

La clase ara::diag::ExternalAuthentication proporciona una interfaz de puerto a través de la cual una aplicación adaptativa consulta instancias de ara::diag::ClientAuthentication para gestionar el estado de autenticación de clientes de diagnóstico externos [SWS_DM_01191]. Tras la vinculación a un puerto de servicio modelado, los objetos de autenticación se solicitan específicamente al Diagnostic Manager en función de la dirección de origen o de metainformación [SWS_DM_01200]. La instancia posee semántica de movimiento, prohíbe operaciones de copia y exige una desmantelación sincronizada debido a un destructor no seguro para hilos.

Contexto

La clase ara::diag::ExternalAuthentication actúa en la AUTOSAR Adaptive Platform como interfaz de puerto para la autenticación de clientes de diagnóstico externos [SWS_DM_01191], AUTOSAR_AP_SWS_Diagnostics §8.17 «Header: ara/diag/external_authentication.h». A través de este puerto, una aplicación adaptativa obtiene acceso a instancias específicas de ara::diag::ClientAuthentication, las cuales representan y gestionan el estado de autenticación del cliente de diagnóstico correspondiente [SWS_DM_01202].

La asignación y el número de instancias de cliente disponibles se definen en el modelo de software a través del elemento DiagnosticExternalAuthenticationIdentification. Esto permite a la aplicación establecer direcciones de origen fijas o rangos de direcciones configurados de tipo Address (alias de std::uint16_t [SWS_DM_01192]) para comprobadores de diagnóstico (testers) cuando la dirección de origen final solo se conoce en tiempo de ejecución AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 «Get ClientAuthentication Instance».

Entre los interlocutores participantes se incluyen:

  • La aplicación adaptativa, que crea la instancia de puerto y consulta estados de autenticación.
  • El Diagnostic Manager (DM), que controla las conexiones de diagnóstico y gestiona los estados de autenticación de los clientes [SWS_DM_01202].
  • Los objetos ara::diag::ClientAuthentication asignados al cliente solicitante.
  • El cliente de diagnóstico externo, cuya conexión se identifica a través de la dirección de origen o de metainformación.

Diagrama de contexto: integración de la clase de puerto entre la aplicación, el Diagnostic Manager y la autenticación de clientes. Fuentes: [SWS_DM_01191], [SWS_DM_01202], AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 «Get ClientAuthentication Instance».

Ciclo de vida

La creación de una instancia de ara::diag::ExternalAuthentication se realiza explícitamente pasando un ara::core::InstanceSpecifier al constructor [SWS_DM_01193]. Este identificador vincula el objeto al PortPrototype modelado de un DiagnosticExternalAuthenticationInterface.

En lo relativo a las relaciones de propiedad, la clase posee una semántica de movimiento pura: el constructor de movimiento [SWS_DM_01194] y el operador de asignación por movimiento [SWS_DM_01195] están disponibles (default), mientras que el constructor de copia [SWS_DM_01196] y el operador de asignación por copia [SWS_DM_01197] están eliminados (delete). Por lo tanto, un puerto representa un objeto de interfaz indivisible y no copiable.

Para la destrucción está disponible el destructor ~ExternalAuthentication() [SWS_DM_01198]. En cuanto a la concurrencia, el constructor y los métodos de consulta están especificados como seguros para hilos (thread-safe) y seguros frente a excepciones (exception safe) [SWS_DM_01193], [SWS_DM_01199], [SWS_DM_01200], [SWS_DM_01201]. El destructor, por el contrario, expresamente no es seguro para hilos (not thread-safe) [SWS_DM_01198]. Por consiguiente, la aplicación debe garantizar que no se produzcan más llamadas concurrentes antes de la destrucción del objeto.

Ruta de uso

El flujo típico comprende la inicialización del puerto y la subsiguiente recuperación de objetos de autenticación:

  1. La aplicación instancia ExternalAuthentication indicando el identificador de instancia [SWS_DM_01193].
  2. La aplicación solicita la instancia de autenticación para un cliente concreto. Para ello están disponibles los métodos sobrecargados Get(Address) utilizando la dirección del tester [SWS_DM_01200] o Get(const MetaInfo&) basándose en metadatos de solicitud recibidos [SWS_DM_01199]. Alternativamente, recupera mediante GetAll() una lista de todas las instancias gestionadas actualmente por el Diagnostic Manager [SWS_DM_01201].
  3. El Diagnostic Manager determina el objeto correspondiente y devuelve un ara::core::Result<ClientAuthentication> o un vector [SWS_DM_01202].
  4. La aplicación comprueba el resultado e interactúa a continuación con la instancia de ClientAuthentication obtenida, la cual probablemente actúe como un manejador (handle) del lado de la aplicación para el estado de la sesión de autenticación.

Diagrama de secuencia: secuencia de llamadas típica para la instanciación y consulta de una instancia de ClientAuthentication. Fuentes: [SWS_DM_01193], [SWS_DM_01200], [SWS_DM_01202].

Escenarios de error

Durante la instanciación mediante el constructor, los errores de configuración y modelado pueden provocar violaciones definidas [SWS_DM_01193]:

  • InstanceSpecifierMappingIntegrityViolation: el identificador no se puede resolver en el contexto del ejecutable o no hace referencia a ningún PortPrototype.
  • PortInterfaceMappingViolation: el PortPrototype referenciado no está tipado como DiagnosticExternalAuthenticationInterface.
  • ProcessMappingViolation: no existe una definición de proceso modelada adecuada para el proceso en tiempo de ejecución.
  • InstanceSpecifierAlreadyInUseViolation: otra instancia de puerto ya está utilizando el identificador en el mismo proceso.

En las llamadas a Get(const MetaInfo&) o Get(Address), el retorno a través de ara::core::Result puede contener el código de error DiagErrc::kServiceNotAvailable [SWS_DM_01199], [SWS_DM_01200]. Esto indica que funcionalidad esencial del Diagnostic Manager no está disponible temporalmente. La llamada GetAll() no devuelve ningún código de error en caso de ausencia de instancias, sino un vector vacío [SWS_DM_01201].

El constructor explícito [SWS_DM_01193] inicializa una instancia de la clase de puerto ara::diag::ExternalAuthentication [SWS_DM_01191] para la autenticación de clientes de diagnóstico externos (SWS Diagnostics §8.17 «Header: ara/diag/external_authentication.h»). Como parámetro, la función espera un ara::core::InstanceSpecifier que debe hacer referencia a un PortPrototype modelado en el manifiesto de una instancia de servicio DiagnosticExternalAuthenticationInterface [SWS_DM_01193].

La llamada síncrona está declarada como noexcept y especificada tanto thread-safe como exception-safe [SWS_DM_01193]. Dado que no se lanzan excepciones, los errores de modelado y configuración conducen a violaciones definidas del framework [SWS_DM_01193]:

  • InstanceSpecifierMappingIntegrityViolation: el identificador no puede resolverse en el contexto del ejecutable o hace referencia a un elemento de modelo distinto de un PortPrototype.
  • PortInterfaceMappingViolation: el PortPrototype referenciado no está tipificado mediante un DiagnosticExternalAuthenticationInterface.
  • ProcessMappingViolation: no existe ningún proceso de tiempo de ejecución modelado coincidente para la referencia.
  • InstanceSpecifierAlreadyInUseViolation: el identificador ya está siendo utilizado por otra instancia en el proceso en ejecución.

Las operaciones de copia están explícitamente deshabilitadas para ExternalAuthentication [SWS_DM_01196] [SWS_DM_01197], mientras que las operaciones de movimiento están soportadas [SWS_DM_01194] [SWS_DM_01195]. A diferencia del constructor, el destructor correspondiente no es seguro para subprocesos [SWS_DM_01198]. Tras una instanciación exitosa, el objeto sirve para consultar instancias de autenticación de clientes asociadas a través de métodos como Get o GetAll [SWS_DM_01201] [SWS_DM_01202].

El método síncrono ara::diag::ExternalAuthentication::Get sirve para que una aplicación adaptativa obtenga la instancia de ara::diag::ClientAuthentication responsable de una solicitud de diagnóstico [SWS_DM_01199]. Como parámetro se transfiere una referencia a metaInfo (const ara::diag::MetaInfo&), la cual proporciona metainformación procedente del contexto de la solicitud de diagnóstico SWS Diagnostics §7.3.1.1 «MetaInfo class». El valor de retorno de tipo ara::core::Result<ClientAuthentication> encapsula el correspondiente objeto de autenticación para gestionar el estado de autenticación del cliente [SWS_DM_01202].

              

              
Si se produce un error, el Result devuelto contiene el código de error específico DiagErrc::kServiceNotAvailable [SWS_DM_01199]. Este señala, con semántica de rollback, que la invocación no puede ejecutarse porque funciones esenciales del Diagnostic Manager (DM) no están disponibles en el momento de la llamada [SWS_DM_01199].

              

              
En lo que respecta a la concurrencia, la función está especificada como thread-safe, así como exception safe, y declarada con noexcept [SWS_DM_01199]. Por lo tanto, puede invocarse de manera segura desde hilos paralelos sin mecanismos de bloqueo en la aplicación.

              

              
El método interactúa con la variante sobrecargada Get(Address sourceAddress) [SWS_DM_01200], la cual permite la misma obtención directamente mediante la dirección de origen del cliente [SWS_DM_01202]. El número de instancias disponibles viene determinado por los elementos de modelo DiagnosticExternalAuthenticationIdentification SWS Diagnostics «Get ClientAuthentication Instance». Interpretación: Es de prever que la función determine internamente la dirección de origen requerida para la asignación a partir de los datos de transporte encapsulados en metaInfo.

                      usar

En caso de que no haya objetos de autenticación disponibles, esto no se trata como un error, sino que el método devuelve un vector vacío [SWS_DM_01201].

                      La especificación cataloga GetAll como segura para hilos (thread-safe) [SWS_DM_01201].
