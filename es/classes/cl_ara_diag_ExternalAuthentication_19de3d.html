Contexto y arquitectura

La clase ara::diag::ExternalAuthentication constituye en la Adaptive Platform la interfaz para que las aplicaciones adaptativas gestionen y consulten instancias de autenticación de comprobadores de diagnóstico [SWS_DM_01191]. En una arquitectura AUTOSAR, actúa como portal de acceso (puerto) al Diagnostic Manager (DM) para recuperar instancias de ara::diag::ClientAuthentication adaptadas a los clientes de diagnóstico solicitantes AUTOSAR_AP_SWS_Diagnostics p. 129.

En el metamodelo de AUTOSAR, el elemento DiagnosticExternalAuthenticationIdentification define direcciones de origen fijas o rangos de direcciones para clientes de diagnóstico, a partir de los cuales se deriva el número de objetos ara::diag::ClientAuthentication disponibles AUTOSAR_AP_SWS_Diagnostics p. 129. Las direcciones individuales del comprobador se asignan como un número entero de 16 bits mediante el alias de tipo estandarizado Address [SWS_DM_01192]. De este modo, ExternalAuthentication actúa directamente como mediador entre la aplicación adaptativa, el servidor de diagnóstico o Diagnostic Manager y los estados de autenticación de clientes representados.

Diagrama de contexto: interacción entre la aplicación adaptativa, ExternalAuthentication, Diagnostic Manager y ClientAuthentication. Fuentes: [SWS_DM_01191], [SWS_DM_01202], AUTOSAR_AP_SWS_Diagnostics p. 129

Ciclo de vida y concurrencia

Las instancias de ara::diag::ExternalAuthentication se crean explícitamente mediante un ara::core::InstanceSpecifier [SWS_DM_01193]. Este identificador debe hacer referencia a un PortPrototype definido en el manifiesto de ejecución que esté tipificado mediante un DiagnosticExternalAuthenticationInterface [SWS_DM_01193]. La construcción está especificada como segura frente a excepciones (exception safe) y segura para subprocesos (thread-safe) [SWS_DM_01193].

En cuanto a la propiedad, la clase tiene una semántica exclusiva: el constructor de copia [SWS_DM_01196] y el operador de asignación por copia [SWS_DM_01197] están eliminados (=delete). Sin embargo, un objeto se puede mover mediante el constructor de movimiento [SWS_DM_01194] o el operador de asignación por movimiento [SWS_DM_01195], estando ambos operadores declarados como noexcept.

La destrucción se realiza a través del destructor virtual o regular [SWS_DM_01198]. A diferencia de las llamadas a métodos regulares, el destructor está clasificado expresamente como no seguro para subprocesos (not thread-safe) [SWS_DM_01198]; por lo tanto, la aplicación debe garantizar que no se produzcan accesos concurrentes a la misma instancia durante el proceso de destrucción.

Ruta de uso para la autenticación de clientes

El flujo regular para la gestión de la autenticación externa se divide en las siguientes fases:

  1. Instanciación del puerto de autenticación: la aplicación instancia ExternalAuthentication especificando el InstanceSpecifier manifestado [SWS_DM_01193].
  2. Recuperación de la instancia de autenticación de clientes: según el contexto, la aplicación dispone de dos sobrecargas de Get, así como de una consulta colectiva:
    • Mediante la dirección de origen: Get(Address) recupera la instancia a partir de la dirección del comprobador (std::uint16_t) [SWS_DM_01192], [SWS_DM_01200].
    • Mediante metadatos de solicitud: Get(const MetaInfo&) determina la instancia a partir de los metadatos de UDS transportados de una solicitud de diagnóstico entrante [SWS_DM_01199].
    • Consulta colectiva: GetAll() devuelve como vector todas las instancias de ClientAuthentication gestionadas actualmente por el Diagnostic Manager [SWS_DM_01201].
  3. Gestión de estado en el Diagnostic Manager: El Diagnostic Manager transfiere a la aplicación la instancia de ClientAuthentication correspondiente, la cual es responsable de gestionar el estado de autenticación del cliente respectivo [SWS_DM_01202]. Probablemente, la aplicación utiliza este objeto a continuación para realizar comprobaciones de autenticación y autorizaciones de permisos para el tester correspondiente.

Diagrama de secuencia: secuencia de llamadas para la instanciación y consulta de objetos ClientAuthentication. Fuentes: [SWS_DM_01193], [SWS_DM_01200], [SWS_DM_01202]

Escenarios de error y condiciones previas

Pueden producirse errores tanto durante la resolución del modelo en la instanciación como durante el funcionamiento operativo:

  • Infracciones de modelo y de manifiesto (constructor): Si la resolución del InstanceSpecifier falla o la configuración del modelo no coincide con el proceso de ejecución, se producen infracciones en tiempo de ejecución estandarizadas de AUTOSAR [SWS_DM_01193]:
    • InstanceSpecifierMappingIntegrityViolation: El identificador no hace referencia a un PortPrototype o no puede resolverse en el contexto de la aplicación [SWS_DM_01193].
    • PortInterfaceMappingViolation: El puerto referenciado no está tipado por un DiagnosticExternalAuthenticationInterface [SWS_DM_01193].
    • ProcessMappingViolation: No existe ninguna asignación de proceso coincidente en tiempo de ejecución para el proceso modelado [SWS_DM_01193].
    • InstanceSpecifierAlreadyInUseViolation: El InstanceSpecifier ya se ha utilizado dentro del mismo proceso para una instancia de puerto existente [SWS_DM_01193].
  • Errores en tiempo de ejecución en consultas: Los métodos Get(Address) y Get(const MetaInfo&) devuelven un ara::core::Result<ClientAuthentication> [SWS_DM_01199], [SWS_DM_01200]. Si la funcionalidad esencial del Diagnostic Manager no está disponible actualmente, la llamada falla y devuelve el código de error DiagErrc::kServiceNotAvailable con semántica de rollback [SWS_DM_01199], [SWS_DM_01200].
  • Listas de resultados vacías: GetAll() no devuelve un objeto Result, sino directamente un vector ara::core::Vector<ClientAuthentication>. Si no hay clientes presentes o no hay instancias registradas, se devuelve una lista vacía [SWS_DM_01201].
