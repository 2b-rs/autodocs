Contexto

La interfaz ara::crypto::cryp::PrivateKey actúa en la AUTOSAR Adaptive Platform como una interfaz generalizada para claves privadas asimétricas (Generalized Asymmetric Private Key interface). Como especialización de la interfaz base ara::crypto::cryp::CryptoObject, encapsula el material de clave sensible de claves criptográficas privadas que se utilizan en procedimientos criptográficos asimétricos, como firmas digitales, protocolos de intercambio de claves o descifrado asimétrico. Entre los socios de interacción esenciales se encuentra la correspondiente representación de clave pública ara::crypto::cryp::PublicKey, que puede derivarse a través de la interfaz [SWS_CRYPT_22511]. Desde el punto de vista de la aplicación, PrivateKey actúa como un objeto criptográfico protegido cuya implementación real permanece oculta tras la definición abstracta de la interfaz para garantizar de forma fiable la confidencialidad del material de la clave privada dentro de la plataforma.

Ciclo de vida

Para la gestión y el control del ciclo de vida de las instancias, la interfaz define el alias de tipo ara::crypto::cryp::PrivateKey::Sptr como std::shared_ptr<PrivateKey> [SWS_CRYPT_22501]. El uso de un puntero compartido establece un modelo de propiedad compartida (shared ownership), mediante el cual el ciclo de vida de los objetos de clave puede gestionarse de forma flexible y segura a través de múltiples componentes de software. Dado que PrivateKey es una interfaz puramente virtual, es de suponer que la creación e inicialización concretas de instancias se realizan típicamente a través de métodos de creación especializados o mecanismos de almacenamiento de claves de la arquitectura criptográfica. La destrucción de las instancias se lleva a cabo de forma determinista mediante el recuento de referencias del puntero inteligente tan pronto como el último propietario libera su referencia.

En lo que respecta a la concurrencia, el método de consulta central GetPublicKey() se especifica expresamente como seguro para subprocesos (thread-safe) [SWS_CRYPT_22511]. Esto significa que múltiples hilos de ejecución concurrentes pueden operar en paralelo sobre la misma instancia de PrivateKey y obtener la clave pública asociada sin necesidad de mecanismos de sincronización o bloqueos de exclusión mutua por parte de la aplicación. Además, la interfaz garantiza para este acceso una seguridad frente a excepciones completa (exception safe) y está declarada con el especificador noexcept [SWS_CRYPT_22511], lo que favorece la estabilidad en tiempo de ejecución en contextos críticos para la seguridad.

Ruta de uso

Una ruta de uso típica comienza tan pronto como una aplicación dispone de un puntero válido del tipo ara::crypto::cryp::PrivateKey::Sptr [SWS_CRYPT_22501]. En sistemas criptográficos asimétricos a menudo es necesario extraer la clave pública correspondiente, por ejemplo para crear certificados, configurar contextos de verificación o distribuir la clave pública a interlocutores de comunicación. Para ello, la interfaz proporciona el método puramente virtual GetPublicKey() [SWS_CRYPT_22511].

La entidad que invoca llama a GetPublicKey() en la instancia constante. El método determina la clave pública correspondiente y la devuelve empaquetada en un ara::core::Result<PublicKey::Sptr> [SWS_CRYPT_22511]. A continuación, quien realiza la llamada comprueba si el objeto Result ha tenido éxito. En caso de éxito, el resultado contiene un puntero inteligente PublicKey::Sptr que representa la clave pública correspondiente [SWS_CRYPT_22511]. Posteriormente, este puntero puede pasarse de forma autónoma a rutinas de verificación o cifrado asimétrico, mientras que la clave privada permanece protegida.

Escenarios de error

El método GetPublicKey() está declarado como noexcept y sigue el enfoque de tratamiento funcional de errores de la Adaptive Platform a través de ara::core::Result en lugar de excepciones de C++ [SWS_CRYPT_22511]. No obstante, la especificación establece que para esta llamada no hay códigos de error estandarizados definidos (This function does not specify any standardized errors) [SWS_CRYPT_22511].

Interpretación: dado que el tipo de retorno sigue siendo ara::core::Result, es de suponer que las implementaciones concretas utilicen este mecanismo para señalar problemas inesperados en tiempo de ejecución —como la falta de memoria al asignar el nuevo objeto PublicKey o errores internos de hardware de un módulo de seguridad subyacente— mediante códigos de error específicos de la implementación. La precondición para una llamada exitosa es una instancia de PrivateKey correctamente inicializada y consistente. Si la derivación falla, el Result devuelve el estado de error correspondiente; de lo contrario, el objeto PublicKey::Sptr contenido es válido.
