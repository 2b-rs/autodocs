Definie el dominio de error de la Firewall para la traducción de códigos de error en textos descriptivos y excepciones específicas del módulo.

La clase representa el dominio de error del módulo Firewall y vincula códigos de error específicos del módulo con textos de error y excepciones [AP_SWS_Fw_83007]. Proporciona descripciones para códigos de error y permite el lanzamiento dirigido de excepciones específicas del módulo [AP_SWS_Fw_83011], [AP_SWS_Fw_83012]. Dado que el constructor predeterminado está eliminado, su uso se realiza a través de un dominio preinstanciado cuyas interfaces están implementadas de forma segura para hilos [AP_SWS_Fw_83009].

Contexto

La clase ara::fw::FwErrorDomain representa el dominio de error específico para el módulo Firewall (fw) dentro de AUTOSAR Adaptive Platform. Como especialización de ara::core::ErrorDomain, define el contexto semántico para todos los estados de error que pueden producirse en operaciones de la Firewall. Mediante la encapsulación en un dominio independiente se garantiza que los códigos de error del módulo Firewall puedan identificarse unívocamente en toda la plataforma y distinguirse de los errores de otros subsistemas.

Entre los componentes centrales de la interfaz se encuentran alias de tipos estandarizados: con Errc se referencia la enumeración subyacente FwErrc [AP_SWS_Fw_83007], mientras que Exception actúa como alias para la clase base de excepciones específica del módulo FwException [AP_SWS_Fw_83008]. A través del método Name(), la clase pone a disposición el identificador del dominio de error [AP_SWS_Fw_83010]. Las partes interactuantes principales son la implementación funcional de la Firewall, el software de aplicación y la infraestructura superior de tratamiento de errores de ara::core.

Ciclo de vida

La instanciación de ara::fw::FwErrorDomain está sujeta a pautas estrictas: el constructor predeterminado sin parámetros está declarado explícitamente como eliminado (FwErrorDomain() = delete) [AP_SWS_Fw_83009]. Con ello se impide la creación directa de instancias en la pila o en el montículo por parte de los usuarios. De conformidad con el estándar de la plataforma para dominios de error, la instancia del dominio existe típicamente como un singleton global al que las aplicaciones probablemente acceden a través de una función de acceso para toda la plataforma.

En cuanto a la relación de propiedad, el dominio de error permanece bajo el control del entorno de ejecución y presenta un tiempo de vida estático durante todo el tiempo de ejecución del proceso. Puesto que múltiples rutas de ejecución pueden acceder en paralelo a descripciones de error, los métodos centrales de inspección Name() y Message() están especificados como seguros para hilos (thread-safe) [AP_SWS_Fw_83010], [AP_SWS_Fw_83011]. Asimismo, la metodología ThrowAsException() garantiza la seguridad para hilos ante accesos simultáneos [AP_SWS_Fw_83012].

Ruta de uso

La ruta de uso típica se divide en la generación de errores del lado del módulo, la evaluación por parte del llamador y, dado el caso, la conversión en una excepción de C++. Si una operación de la Firewall falla, se transmite al llamador un error basado en la enumeración Errc [AP_SWS_Fw_83007] y encapsulado como ara::core::ErrorCode. A continuación, el usuario puede consultar textos de error detallados a través del dominio o controlar de forma determinista el tratamiento de errores.

Para fines de diagnóstico o registro cronológico, la aplicación pasa el código de error al método Message(), el cual devuelve la descripción textual correspondiente como puntero a caracteres constantes [AP_SWS_Fw_83011]. Si, en cambio, la ejecución debe continuarse mediante excepciones de C++, se invoca ThrowAsException() con el objeto de error respectivo, tras lo cual el método instancia y lanza una instancia de Exception (FwException) [AP_SWS_Fw_83008], [AP_SWS_Fw_83012].

Diagrama de secuencia: flujo típico del tratamiento de errores y lanzamiento de excepciones a través de FwErrorDomain. Fuentes: [AP_SWS_Fw_83007], [AP_SWS_Fw_83011], [AP_SWS_Fw_83012].

Escenarios de error

Los métodos para la consulta de información ofrecen estrictas garantías contra errores en tiempo de ejecución. Tanto Name() como Message() están declarados con noexcept, garantizando así que no se lancen excepciones durante la consulta de identificadores y textos de error [AP_SWS_Fw_83010], [AP_SWS_Fw_83011]. La precondición para Message() es la entrega de un valor de error válido de tipo CodeType [AP_SWS_Fw_83011].

Por el contrario, ThrowAsException() está anotada explícitamente con noexcept(false), ya que su tarea principal consiste en interrumpir deliberadamente el flujo de control regular mediante el lanzamiento de una FwException [AP_SWS_Fw_83012]. Según la especificación, esta función está clasificada como no segura frente a excepciones (not exception safe), dado que crea y emite una excepción. Por lo tanto, los llamadores deben asegurarse de que las llamadas a ThrowAsException() estén incrustadas en bloques try-catch correspondientes si se desea evitar una terminación prematura del programa.

Esta guía se basa exclusivamente en la definición de la interfaz de ara::fw::FwErrorDomain de la versión R25-11.

El alias de tipo Errc está definido, conforme a [AP_SWS_Fw_83007], como un alias para la enumeración de códigos de error FwErrc (using Errc = FwErrc;). El elemento está declarado en el ámbito de la clase ara::fw::FwErrorDomain y debe incluirse mediante el archivo de cabecera ara/fw/fw_error_domain.h [AP_SWS_Fw_83007].

En lo relativo a su uso, Errc no representa una invocación de función ejecutable y, por lo tanto, no dispone de parámetros, valores de retorno ni de semántica síncrona o asíncrona [AP_SWS_Fw_83007]. Más bien proporciona un identificador uniforme para la enumeración de las causas de error específicas del dominio. Interpretación: Es de prever que el alias ofrezca a los desarrolladores un acceso simplificado y coherente a los valores de la enumeración de FwErrc dentro de ara::fw::FwErrorDomain para tipificar y consultar estados de error [AP_SWS_Fw_83007].

Dado que se trata de un constructo exclusivo de tiempo de compilación, no existen restricciones en tiempo de ejecución relativas a reentrancia, seguridad para subprocesos u órdenes de invocación [AP_SWS_Fw_83007]. Los valores de error específicos o las vinculaciones con notificaciones de DET o DEM no están predeterminados en el elemento de especificación y se rigen por los valores de la enumeración subyacente [AP_SWS_Fw_83007].
