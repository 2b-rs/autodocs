Contexto

En la AUTOSAR Adaptive Platform (módulo rds), la clase de plantilla ara::rds::IEEE1722RawDataStreamConsumer proporciona la abstracción central para recibir datagramas tipificados de un flujo de datos IEEE 1722. Como Raw Data Stream Consumer, la clase encapsula la interacción con el punto final del flujo subyacente y pone a disposición los datagramas recibidos como objetos estructurados del tipo de datos parametrizado T. Los interlocutores típicos son el software de aplicación adaptativo, que procesa flujos de datos como datos brutos de sensores sensibles al tiempo, de audio o de vídeo, así como la infraestructura subyacente de plataforma y comunicación, que se vincula al Consumer mediante un ara::core::InstanceSpecifier.

Ciclo de vida

Las instancias de ara::rds::IEEE1722RawDataStreamConsumer no se crean mediante constructores predeterminados públicos, sino que se instancian exclusivamente a través del método de fábrica estático Create [SWS_RDS_90312]. Este método vincula el objeto Consumer a crear con una configuración de instancia transmitida y, en caso de éxito, devuelve el objeto inicializado en un ara::core::Result.

En cuanto a las relaciones de propiedad, la clase impone una estricta exclusividad del recurso de flujo de datos: el constructor de copia [SWS_RDS_90316] y el operador de asignación por copia [SWS_RDS_90317] están explícitamente eliminados (delete). Por lo tanto, queda excluida la duplicación de instancias de Consumer. En su lugar, la clase admite la semántica de movimiento: el constructor de movimiento [SWS_RDS_90314] y el operador de asignación por movimiento [SWS_RDS_90315] permiten una transferencia eficiente de la propiedad. Ambas operaciones están definidas como noexcept, pero especificadas expresamente como no seguras para subprocesos.

Tras la creación, el objeto se encuentra inicialmente en un estado no conectado. La conexión con el flujo de datos se establece explícitamente llamando a Connect [SWS_RDS_90319]. El método Shutdown [SWS_RDS_90320] sirve para una desconexión ordenada. Durante la destrucción del objeto, el destructor [SWS_RDS_90318] garantiza que una conexión aún activa se cierre automáticamente. El destructor también está especificado como no seguro para subprocesos.

Ruta de uso

El flujo regular para el uso del IEEE-1722 Stream Consumer se divide en una secuencia fija de fases:

  1. Creación: La aplicación solicita una instancia del Consumer mediante el método estático Create con el ara::core::InstanceSpecifier correspondiente [SWS_RDS_90312].
  2. Establecimiento de la conexión: Tras la provisión satisfactoria del objeto, se llama a Connect para vincular el Consumer al flujo de datos físico o lógico [SWS_RDS_90319].
  3. Recepción de datos: En funcionamiento activo, la aplicación consulta periódicamente datagramas a través de ReadData [SWS_RDS_90321]. Mediante el parámetro maxNumberOfDatagrams, el emisor de la llamada limita el volumen de lectura por llamada; el resultado se proporciona de forma síncrona como std::vector<T>.
  4. Desconexión y liberación: Para finalizar la transmisión de forma regular, la aplicación llama a Shutdown [SWS_RDS_90320]. De lo contrario, al salir del ámbito de validez, el destructor se encarga de cerrar la conexión [SWS_RDS_90318].

Diagrama de secuencia: Secuencia típica de llamadas desde la instanciación pasando por el establecimiento de la conexión y la recuperación de datos hasta el cierre. Fuentes: [SWS_RDS_90312], [SWS_RDS_90319], [SWS_RDS_90321], [SWS_RDS_90320].

Escenarios de error

Toda la interfaz está especificada como noexcept y no utiliza excepciones de C++. Los estados de error se señalan de conformidad con la plataforma a través del tipo de retorno ara::core::Result:

  • Instanciación fallida: Si el InstanceSpecifier transmitido no se puede resolver o el recurso de comunicación no se puede inicializar, Create devuelve un objeto Result erróneo [SWS_RDS_90312].
  • Error al establecer la conexión: Si el punto final del flujo no es accesible o falla el inicio de la conexión, Connect devuelve un código de error en ara::core::Result<void> [SWS_RDS_90319].
  • Error en la recepción de datos: Si falla la lectura de datagramas —interpretación: por ejemplo, porque la conexión no se estableció previamente o se interrumpió de forma inesperada—, el Result de retorno de ReadData contiene el código de error correspondiente [SWS_RDS_90321].
  • Accesos concurrentes: Dado que las operaciones de movimiento ([SWS_RDS_90314], [SWS_RDS_90315]) y la destrucción del objeto [SWS_RDS_90318] no son explícitamente seguras para subprocesos, el acceso concurrente sin sincronización externa provoca carreras de datos y un comportamiento indefinido del sistema.

Esta guía se basa en la especificación AUTOSAR Adaptive del módulo rds (Release R25-11).
