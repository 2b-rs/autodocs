Recibe datagramas de streaming IEEE 1722 tipificados a través de un extremo de comunicación configurado.

La clase plantilla ara::rds::IEEE1722RawDataStreamConsumer sirve para la recepción tipificada de datagramas de streaming IEEE 1722 en AUTOSAR Adaptive Platform. Las instancias se crean mediante el método estático Create() con un InstanceSpecifier [SWS_RDS_90312] y, a continuación, se conectan al flujo de datos mediante Connect(). A través del método ReadData() se pueden leer los datagramas entrantes hasta una cantidad máxima predeterminada [SWS_RDS_90321]. Las operaciones de copia están excluidas, de modo que la conexión solo se puede transferir mediante operaciones de movimiento cuya ejecución no es segura para hilos.

Contexto

La clase plantilla ara::rds::IEEE1722RawDataStreamConsumer actúa como receptor tipificado para datagramas de streaming IEEE 1722 dentro del módulo de flujo de datos sin procesar (rds) de AUTOSAR Adaptive Platform. Mediante el parámetro de plantilla T se define el tipo de datos útiles concreto de los datagramas. La clase encapsula el acceso al flujo de datos y vincula los extremos de comunicación a la infraestructura de comunicación configurada a través de un identificador de tipo ara::core::InstanceSpecifier [SWS_RDS_90312]. Las aplicaciones utilizan este Consumer para recibir flujos de datos útiles estructurados de AVTP o IEEE 1722 de forma directa y con un uso eficiente de los recursos.

Ciclo de vida

La instanciación de un Consumer se realiza exclusivamente a través del método de fábrica estático Create() [SWS_RDS_90312] indicando la instancia de destino. No está prevista una llamada directa al constructor para los usuarios. La clase implementa una semántica estricta de solo movimiento (Move-Only): la copia de instancias está explícitamente prohibida, ya que tanto el constructor de copia [SWS_RDS_90316] como el operador de asignación por copia [SWS_RDS_90317] están eliminados. Esto asegura que la conexión subyacente y los recursos de búfer permanezcan siempre bajo una propiedad unívoca.

Para permitir transferencias de propiedad entre contextos, la clase proporciona un constructor de movimiento [SWS_RDS_90314] así como un operador de asignación por movimiento [SWS_RDS_90315]. Ambas operaciones de movimiento están declaradas como no seguras para hilos, motivo por el cual los accesos concurrentes a la misma instancia deben sincronizarse. Al desmantelar la instancia, el destructor ~IEEE1722RawDataStreamConsumer() cierra automáticamente una conexión que aún pudiera existir [SWS_RDS_90318]; el destructor también está especificado como no seguro para hilos.

Ruta de uso

El flujo típico al utilizar un IEEE1722RawDataStreamConsumer comprende cuatro fases sucesivas:

  1. Creación: la aplicación crea la instancia del consumidor mediante el método de fábrica Create() con el ara::core::InstanceSpecifier deseado [SWS_RDS_90312].
  2. Establecimiento de la conexión: antes de recibir datos útiles, la aplicación conecta el consumidor con el flujo de datos configurado mediante la llamada a Connect() [SWS_RDS_90319].
  3. Recepción de datos: la aplicación llama de forma repetida o periódica a ReadData() [SWS_RDS_90321]. En este contexto, el parámetro maxNumberOfDatagrams especifica el número máximo de datagramas que se consultarán en la llamada. El resultado se devuelve como un vector del tipo de plantilla T.
  4. Cierre de la conexión: una vez finalizada la transmisión de datos, la aplicación finaliza la conexión explícitamente mediante Shutdown() [SWS_RDS_90320] o delega la limpieza en el destructor [SWS_RDS_90318].

Diagrama de secuencia: ruta de uso típica para la creación, conexión, consulta periódica de datagramas y finalización del consumidor. Fuentes: [SWS_RDS_90312], [SWS_RDS_90319], [SWS_RDS_90321], [SWS_RDS_90320], [SWS_RDS_90318].

Escenarios de error

Todas las funciones de interfaz regulares de la clase (Create() [SWS_RDS_90312], Connect() [SWS_RDS_90319], ReadData() [SWS_RDS_90321] y Shutdown() [SWS_RDS_90320]) están calificadas con noexcept y no señalan estados de error mediante excepciones de C++, sino a través del tipo de retorno ara::core::Result. Por lo tanto, las aplicaciones deben comprobar si el resultado correspondiente contiene un valor o un error antes de acceder a los valores de datos o realizar operaciones subsiguientes.

Las posibles constelaciones de error abarcan el fallo de la creación de la instancia si la configuración del InstanceSpecifier es defectuosa, así como interrupciones de la conexión o errores en el acceso a la red durante Connect() o ReadData(). Interpretación: es de prever que una llamada a ReadData() presuponga que previamente se haya completado con éxito un establecimiento de conexión mediante Connect(). Es de prever que las causas concretas de error se transmitan idiomáticamente como códigos de error en el ara::core::Result devuelto.
