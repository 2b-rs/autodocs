clase ara::exec::FunctionGroupState

[SWS_EM_02269] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150, RS_AP_00129

class FunctionGroupState final {...};

Class representing Function Group State defined in meta-model (ARXML). An instance of this class will represent Function Group State defined inside meta-model (ARXML). This class is intended to be an implementation specific representation, of information inside meta-model. Once created based on ARXML path, its internal value stays bounded to it for entire lifetime of a object.

Contexto

La clase ara::exec::FunctionGroupState representa, dentro de la AUTOSAR Adaptive Platform, un estado de un grupo de funciones (Function Group State) definido en el metamodelo (ARXML). En tiempo de ejecución, sirve como representación específica de la implementación de la información de estado modelada en el metamodelo ARXML. Cada instancia de esta clase está vinculada a un grupo de funciones concreto (FunctionGroup) e identifica el estado mediante el nombre corto (Short Name) de la declaración correspondiente del metamodelo (ModeDeclaration) [SWS_EM_02324]. Al ser una clase final (final), no está prevista para una jerarquía de herencia. Gracias a la vinculación directa con la ruta ARXML, constituye el puente tipado entre la configuración basada en modelos y los mecanismos en tiempo de ejecución del Execution Management.

Diagrama de contexto: integración de FunctionGroupState entre el grupo de funciones y el metamodelo. Fuentes: [SWS_EM_02324].

Ciclo de vida

El ciclo de vida de una instancia de FunctionGroupState comienza con la creación mediante el constructor parametrizado, pasando una referencia al grupo de funciones correspondiente, así como un ara::core::StringView para el identificador de estado [SWS_EM_02324]. Según la especificación, tras la inicialización, el valor interno del objeto permanece vinculado de forma inmutable a la ruta ARXML subyacente durante toda su vida útil. La clase presenta una semántica de valor completa y admite tanto la copia como el movimiento de instancias:

  • Mediante el constructor de copia [SWS_EM_02325] y el operador de asignación por copia [SWS_EM_02330] se pueden duplicar instancias, devolviendo la asignación una referencia al objeto de destino.
  • Mediante el constructor de movimiento [SWS_EM_02331] y el operador de asignación por movimiento [SWS_EM_02332] se pueden transferir recursos de manera eficiente a instancias nuevas o existentes.

La destrucción del objeto se produce de forma determinista mediante el destructor [SWS_EM_02272] en cuanto se sale del ámbito.

En lo que respecta a la concurrencia y a la seguridad para subprocesos, la clase está especificada de forma diferenciada: el constructor parametrizado está indicado explícitamente como seguro para subprocesos [SWS_EM_02324]. Del mismo modo, los operadores de comparación para el acceso de lectura están definidos como seguros para subprocesos ([SWS_EM_02273], [SWS_EM_02274]). Por el contrario, el constructor de copia [SWS_EM_02325], el constructor de movimiento [SWS_EM_02331], los operadores de asignación ([SWS_EM_02330], [SWS_EM_02332]) y el destructor [SWS_EM_02272] no son seguros para subprocesos. Por lo tanto, las operaciones de ciclo de vida que modifican la misma instancia requieren sincronización externa.

Ruta de uso

La ruta de uso típica comprende la instanciación, la transferencia como valor de estado y la posterior comparación lógica:

  1. Creación: La aplicación instancia un objeto de FunctionGroupState especificando una FunctionGroup existente, así como el nombre corto de la ModeDeclaration de destino [SWS_EM_02324].
  2. Transferencia y almacenamiento: Dado que la instancia representa el estado de destino de forma inmutable, se puede transferir mediante copia o movimiento a otros bloques funcionales o almacenarse en estructuras de datos ([SWS_EM_02325], [SWS_EM_02331], [SWS_EM_02330], [SWS_EM_02332]).
  3. Comprobación del valor de estado: Las aplicaciones comparan instancias mediante los operadores de igualdad y desigualdad. El operador operator== devuelve true si y solo si ambas instancias de FunctionGroupState representan exactamente el mismo elemento del metamodelo, y false en caso contrario [SWS_EM_02273]. De forma complementaria, operator!= devuelve false si y solo si se representa la misma entidad del metamodelo, y true en caso de desigualdad [SWS_EM_02274].
  4. Liberación: Al salir del ámbito, el destructor libera automáticamente todos los recursos vinculados [SWS_EM_02272].

Escenarios de error

El diseño de la interfaz de ara::exec::FunctionGroupState está concebido para una máxima robustez y una ejecución libre de excepciones:

  • Seguridad frente a excepciones y noexcept: Todas las funciones miembro —incluidos el constructor parametrizado [SWS_EM_02324], las operaciones de copia y movimiento ([SWS_EM_02325], [SWS_EM_02331], [SWS_EM_02330], [SWS_EM_02332]), los operadores de comparación ([SWS_EM_02273], [SWS_EM_02274]) y el destructor [SWS_EM_02272]— están declaradas con noexcept y especificadas como seguras frente a excepciones (exception safe). Por lo tanto, la clase no lanza excepciones de C++ bajo ninguna circunstancia.
  • Precondiciones y códigos de error: Las funciones miembro no devuelven códigos de error (como p. ej. a través de ara::core::Result). Una precondición esencial para el uso sin errores es que el nombre corto pasado al constructor se corresponda efectivamente con una ModeDeclaration definida en el metamodelo ARXML del grupo de funciones especificado [SWS_EM_02324]. Interpretación: Dado que el constructor no lanza excepciones ni devuelve códigos de error, cabe suponer que la validez del identificador del metamodelo se presupone como una precondición estricta para el emisor de la llamada; los identificadores no válidos conducen probablemente a que la instancia no pueda asignarse a ningún elemento de modelo válido y las comparaciones a través de operator== fallen.

<h4>Contexto</h4>
<p>La clase <code>ara::exec::FunctionGroupState</code> representa, dentro de la AUTOSAR Adaptive Platform, un estado de un grupo de funciones (Function Group State) definido en el metamodelo (ARXML). En tiempo de ejecución, sirve como representación específica de la implementación de la información de estado modelada en el metamodelo ARXML. Cada instancia de esta clase está vinculada a un grupo de funciones concreto (<code>FunctionGroup</code>) e identifica el estado mediante el nombre corto (Short Name) de la declaración correspondiente del metamodelo (<code>ModeDeclaration</code>) <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>. Al ser una clase final (<code>final</code>), no está prevista para una jerarquía de herencia. Gracias a la vinculación directa con la ruta ARXML, constituye el puente tipado entre la configuración basada en modelos y los mecanismos en tiempo de ejecución del Execution Management.</p>

<h4>Ciclo de vida</h4>
<p>El ciclo de vida de una instancia de <code>FunctionGroupState</code> comienza con la creación mediante el constructor parametrizado, pasando una referencia al grupo de funciones correspondiente, así como un <code>ara::core::StringView</code> para el identificador de estado <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>. Según la especificación, tras la inicialización, el valor interno del objeto permanece vinculado de forma inmutable a la ruta ARXML subyacente durante toda su vida útil. La clase presenta una semántica de valor completa y admite tanto la copia como el movimiento de instancias:</p>
<ul>
<li>Mediante el constructor de copia <a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a> y el operador de asignación por copia <a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a> se pueden duplicar instancias, devolviendo la asignación una referencia al objeto de destino.</li>
<li>Mediante el constructor de movimiento <a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a> y el operador de asignación por movimiento <a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a> se pueden transferir recursos de manera eficiente a instancias nuevas o existentes.</li>
</ul>
<p>La destrucción del objeto se produce de forma determinista mediante el destructor <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a> en cuanto se sale del ámbito.</p>
<p>En lo que respecta a la concurrencia y a la seguridad para subprocesos, la clase está especificada de forma diferenciada: el constructor parametrizado está indicado explícitamente como seguro para subprocesos <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>. Del mismo modo, los operadores de comparación para el acceso de lectura están definidos como seguros para subprocesos (<a class="spec-record-ref" data-req="SWS_EM_02273" href="../spec/record.html?id=SWS_EM_02273">[SWS_EM_02273]</a>, <a class="spec-record-ref" data-req="SWS_EM_02274" href="../spec/record.html?id=SWS_EM_02274">[SWS_EM_02274]</a>). Por el contrario, el constructor de copia <a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a>, el constructor de movimiento <a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a>, los operadores de asignación (<a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a>, <a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a>) y el destructor <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a> no son seguros para subprocesos. Por lo tanto, las operaciones de ciclo de vida que modifican la misma instancia requieren sincronización externa.</p>

<p>La ruta de uso típica comprende la instanciación, la transferencia como valor de estado y la posterior comparación lógica:</p>

<li><strong>Transferencia y almacenamiento:</strong> Dado que la instancia representa el estado de destino de forma inmutable, se puede transferir mediante copia o movimiento a otros bloques funcionales o almacenarse en estructuras de datos (<a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a>, <a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a>, <a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a>, <a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a>).</li>

</ul>
