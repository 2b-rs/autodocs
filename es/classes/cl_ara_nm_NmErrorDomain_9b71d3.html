Define el dominio de errores para el Network Management y traduce códigos de error en mensajes o excepciones.

El dominio de errores ara::nm::NmErrorDomain encapsula el tratamiento de errores del Network Management en la AUTOSAR Adaptive Platform e integra los códigos de error NmErrc, así como la clase de excepción NmException [SWS_ANM_01101]. Entre sus tareas principales se encuentran la provisión de mensajes de error legibles a través de Message() y el lanzamiento controlado de excepciones asignadas a través de ThrowAsException() [SWS_ANM_01108]. Como restricción central, la instanciación y todas las funciones miembro están implementadas de forma segura para subprocesos (thread-safe), lo que asegura la consulta concurrente de errores en todo el sistema.

Contexto

La clase ara::nm::NmErrorDomain actúa dentro de la AUTOSAR Adaptive Platform como dominio de errores específico del dominio para el subsistema de Network Management [SWS_ANM_01101]. Como especialización final de la clase base ara::core::ErrorDomain, proporciona el marco estandarizado para la identificación, descripción textual y reenvío de errores que puedan producirse durante el funcionamiento de las funciones de Network Management [SWS_ANM_01101].

Dentro del concepto de tratamiento de errores de NM, la clase vincula causas de error concretas con los mecanismos generales de tratamiento de errores del entorno de ejecución. Para ello, la clase define una asignación directa a los tipos relevantes a través de alias de tipo: a través del alias Errc integra la enumeración subyacente NmErrc, la cual declara los códigos de error específicos para el Network Management [SWS_ANM_01103]. Al mismo tiempo, referencia a través del alias Exception la clase de excepción especializada NmException, lo que permite transformar los errores, si es necesario, en el mecanismo de excepciones de C++ [SWS_ANM_01104]. Gracias a esta agrupación, NmErrorDomain sirve como nexo central entre los estados de error del módulo y el sistema base específico de errores de ara::core.

Ciclo de vida

La creación de una instancia de ara::nm::NmErrorDomain se realiza a través del constructor por defecto sin parámetros [SWS_ANM_01105]. Dado que la clase está especificada como final, se impide explícitamente cualquier subdivisión o especialización adicional mediante dominios de errores derivados [SWS_ANM_01101]. El constructor está declarado con noexcept, con lo que se garantiza que la instanciación del dominio de errores se lleve a cabo sin lanzar excepciones [SWS_ANM_01105].

En cuanto a la propiedad, una instancia de este dominio de errores típicamente debería existir como un objeto global de larga duración en la memoria para estar disponible de forma permanente a través de referencias en objetos de código de error. Una característica esencial en el ciclo de vida es el comportamiento de concurrencia: tanto la construcción de la instancia [SWS_ANM_01105] como todas las funciones de interfaz, tales como la consulta de nombre [SWS_ANM_01106], la generación de mensajes [SWS_ANM_01107] y el lanzamiento de excepciones [SWS_ANM_01108], están diseñadas como completamente seguras para subprocesos (thread-safe). Dado que las instancias de NmErrorDomain no presentan ningún estado modificable, pueden utilizarse de forma concurrente desde múltiples subprocesos sin medidas de sincronización adicionales.

Ruta de uso

La ruta de uso regular comienza tan pronto como se deba analizar, registrar o transformar en una excepción un estado de error en el Network Management. El dominio de errores proporciona para ello las funciones básicas de identificación y evaluación.

Para la identificación general del dominio, se puede llamar al método Name(), el cual devuelve el nombre del dominio como un puntero a cadena de caracteres constante [SWS_ANM_01106]. Si una aplicación o un sistema base desea determinar el significado textual de un código de error producido, se invoca el método Message() pasando el código de error [SWS_ANM_01107]. Este método devuelve el mensaje de error correspondiente como const char* y, gracias a su declaración noexcept, garantiza que el propio proceso de diagnóstico permanezca libre de excepciones [SWS_ANM_01107].

Si el flujo de control requiere lanzar una excepción específica del sistema, se recurre al método ThrowAsException() [SWS_ANM_01108]. Esta función recibe un objeto de error de tipo ara::core::ErrorCode y lanza la excepción adecuada de tipo NmException [SWS_ANM_01104], [SWS_ANM_01108]. En la práctica, la llamada suele realizarse primordialmente de forma indirecta a través de métodos auxiliares correspondientes de los objetos de error.

Diagrama de secuencias: transformación de un código de error de Network Management en una NmException específica del tipo a través del dominio de errores. Fuentes: [SWS_ANM_01104], [SWS_ANM_01108].

Escenarios de error

En el marco del tratamiento de errores, el dominio cubre todos los casos de error del módulo definidos por el tipo de enumeración NmErrc a través del alias Errc [SWS_ANM_01103]. El dominio en sí está diseñado para asegurar de forma determinista la evaluación de errores.

Al determinar mensajes de texto mediante Message(), la declaración como noexcept garantiza que no se lancen excepciones imprevistas, incluso en el caso de códigos de error no válidos [SWS_ANM_01107]. El único escenario previsto en el que la clase lanza activamente una excepción es la llamada explícita a ThrowAsException() [SWS_ANM_01108]. Mediante la declaración noexcept(false), el método indica que transfiere obligatoriamente el programa a una ruta de gestión de excepciones lanzando una instancia de NmException [SWS_ANM_01104], [SWS_ANM_01108]. Por lo tanto, los componentes llamantes deben asegurarse de capturar dichas llamadas mediante los bloques de excepción correspondientes si es necesario.

              El constructor por defecto NmErrorDomain() sirve para la construcción del dominio de errores para el Network Management ([SWS_ANM_01105]). La función está declarada en la cabecera ara/nm/nm_error_domain.h y crea una instancia de la clase NmErrorDomain, la cual hereda de ara::core::ErrorDomain ([SWS_ANM_01101]).
              

  
              Uso y concurrencia
              
  
              El constructor no acepta parámetros y carece de valor de retorno ([SWS_ANM_01105]). La instanciación se efectúa de manera síncrona. De acuerdo con la especificación, la llamada está catalogada como thread-safe, de modo que el dominio de errores también se puede crear de forma segura desde subprocesos paralelos ([SWS_ANM_01105]).
              

  
              Manejo de errores
              
  
              La función está especificada con el identificador noexcept ([SWS_ANM_01105]). Por consiguiente, no se producen excepciones durante la ejecución. Para esta construcción no se contemplan códigos de error específicos ni mecanismos de tratamiento de errores.
              

  
              Interacción
              
  
              La clase creada NmErrorDomain define el contexto específico de dominio para errores de Network Management ([SWS_ANM_01101]). Para suministrar el dominio en el sistema global sirve primariamente la función GetNmDomain(), que devuelve una referencia global de tipo const ara::core::ErrorDomain& ([SWS_ANM_01109]). Es de suponer que una instanciación directa a través del constructor NmErrorDomain() rara vez resulte necesaria en escenarios de aplicación típicos, ya que los componentes de aplicación y de plataforma consultan habitualmente la referencia singleton expuesta a través de GetNmDomain().
