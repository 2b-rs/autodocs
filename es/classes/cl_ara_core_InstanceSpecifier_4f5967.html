Encapsula rutas de shortName de AUTOSAR para la identificación segura en tipos y la comparación de elementos de modelo.

La clase ara::core::InstanceSpecifier sirve como envoltorio seguro en tipos alrededor de una ruta de shortName de AUTOSAR para la identificación inequívoca de instancias de modelo en la Adaptive Platform. La creación preferente se realiza de forma segura frente a excepciones a través del método de fábrica estático Create [SWS_CORE_08032], el cual valida una ruta y devuelve un ara::core::Result. Como condición de contorno fundamental, el método ToString [SWS_CORE_08041] garantiza la validez del StringView proporcionado únicamente durante la vida útil de la cadena de caracteres transferida originalmente, ya que no se gestiona un búfer propio. En tiempo de ejecución, el objeto admite operaciones de comparación completas para cotejos de modelos y almacenamiento ordenado en contenedores.

Contexto

La clase ara::core::InstanceSpecifier sirve como representación de un AUTOSAR Instance Specifier y encapsula una ruta completa de shortName de un elemento de modelo. Dentro de la Adaptive Platform actúa como una abstracción segura en tipos sobre cadenas de caracteres de ruta del metamodelo AUTOSAR. En lugar de utilizar cadenas de caracteres sin formato, este tipo encapsula las estructuras sintácticas de ruta y garantiza que las instancias se puedan direccionar de forma coherente. Como interlocutores principales actúan componentes de aplicación y servicios de plataforma que referencian de manera inequívoca, comparan o gestionan instancias de modelo en colecciones. Interpretación: dado que la especificación describe la clase como un envoltorio ligero de ruta de modelo, probablemente sirva sobre todo para la identificación y asignación de configuración de instancias de servicio y puntos de conexión de comunicación en tiempo de ejecución.

Ciclo de vida

Para la creación, ara::core::InstanceSpecifier ofrece dos rutas con diferentes semánticas de error y de excepciones: el método de fábrica estático Create [SWS_CORE_08032] y el constructor explícito [SWS_CORE_08021]. El método de fábrica Create recibe un ara::core::StringView, está especificado como noexcept así como seguro para hilos, y devuelve el resultado en un ara::core::Result<InstanceSpecifier>. Por el contrario, el constructor directo está declarado con noexcept(false) y lanza una ara::core::CoreException en caso de estructuras de ruta no válidas, con lo que no es seguro frente a excepciones [SWS_CORE_08021].

En cuanto a la vida útil y las relaciones de propiedad, existe una propiedad determinante: el método ToString devuelve un ara::core::StringView cuya validez está vinculada explícitamente a la vida útil de la memoria que servía de base al StringView transferido originalmente al construir [SWS_CORE_08041]. Por consiguiente, la clase no copia la cadena de caracteres subyacente en un área de memoria propia, sino que apunta a datos externos. Por lo tanto, los desarrolladores deben asegurarse de que la cadena de caracteres de origen permanezca en memoria durante todo el tiempo de uso del InstanceSpecifier y de las StringViews derivadas de él.

Para la gestión posterior en el ciclo de vida, están presentes el constructor de copia [SWS_CORE_08022], el constructor de movimiento [SWS_CORE_08023], la asignación por copia [SWS_CORE_08024] y la asignación por movimiento [SWS_CORE_08025]. Las cuatro operaciones están declaradas como noexcept y garantizan la seguridad frente a excepciones. Sin embargo, en cuanto a la concurrencia, debe tenerse en cuenta que únicamente el constructor de copia está clasificado como seguro para hilos. Las operaciones de movimiento, los operadores de asignación y el destructor [SWS_CORE_08029] no son seguros para hilos y exigen sincronización externa cuando la misma instancia se modifica o destruye de forma concurrente.

Ruta de uso

Un flujo de uso típico comprende la instanciación, la consulta de la representación de ruta y la comparación con otros identificadores. Preferentemente se invoca la función de fábrica no lanzadora Create [SWS_CORE_08032]. La aplicación transfiere la ruta cualificada del modelo como ara::core::StringView y comprueba si el objeto Result resultante ha tenido éxito.

Diagrama de secuencia: creación mediante el método de fábrica Create y posterior uso para consulta de ruta o tratamiento de errores. Fuentes: [SWS_CORE_08032], [SWS_CORE_08041]

Tras una inicialización correcta, el identificador se puede utilizar de múltiples formas:

  • Obtener la representación en cadena de caracteres: a través de ToString [SWS_CORE_08041], el invocador recibe una vista StringView sobre la ruta modelada.
  • Comprobación de igualdad y desigualdad: las instancias se pueden comparar directamente con otras instancias de InstanceSpecifier mediante operator== [SWS_CORE_08042] y operator!= [SWS_CORE_08044]. Además, las sobrecargas de operator== [SWS_CORE_08043] y operator!= [SWS_CORE_08045] permiten la comparación directa con un ara::core::StringView. Ambas comprobaciones solo devuelven igualdad si se designa exactamente el mismo elemento de modelo.
  • Ordenación y almacenamiento en contenedores: mediante el operador menor que operator< [SWS_CORE_08046] se pueden ordenar instancias lexicográficamente, lo que permite su uso como clave en contenedores ordenados como mapas.

Escenarios de error

Las condiciones de error en ara::core::InstanceSpecifier están estrictamente limitadas a la fase de construcción. Si se producen deficiencias sintácticas o semánticas en la ruta transferida, se identifican dos errores específicos:

  • CoreErrc::kInvalidMetaModelShortname: se señala si faltan elementos de ruta en el nombre transferido o si contienen caracteres no permitidos [SWS_CORE_08032], [SWS_CORE_08021].
  • CoreErrc::kInvalidMetaModelPath: ocurre cuando la cadena de caracteres no forma una ruta válida hacia un elemento de modelo [SWS_CORE_08032], [SWS_CORE_08021].

El modo de señalización de errores depende de la ruta de creación elegida. Si se utiliza el método de fábrica Create [SWS_CORE_08032], el código de error se devuelve en ara::core::Result; rige una semántica de reversión sin excepciones. Si, por el contrario, se invoca el constructor InstanceSpecifier [SWS_CORE_08021], se lanza una ara::core::CoreException con el código de error correspondiente. Todas las operaciones posteriores como ToString [SWS_CORE_08041], las asignaciones y los operadores de comparación [SWS_CORE_08042], [SWS_CORE_08044], [SWS_CORE_08046] no poseen estados de error definidos y están declaradas como noexcept.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 75e1ed5633e6 Procedencia

El método de fábrica estático ara::core::InstanceSpecifier::Create crea de forma síncrona una nueva instancia de ara::core::InstanceSpecifier según las reglas de sintaxis de [SWS_CORE_10200] y [SWS_CORE_10203] de acuerdo con [SWS_CORE_08032]. Como parámetro se pasa qualifiedShortName como ara::core::StringView, que representa la ruta basada en modelo [SWS_CORE_08032].

Valor de retorno y tratamiento de errores

La llamada devuelve un ara::core::Result<InstanceSpecifier> que, en caso de éxito, contiene el objeto sintácticamente válido [SWS_CORE_08032]. Si la creación falla, el objeto Result contiene un código de error de CoreErrc, que está asignado a la ara::core::CoreErrorDomain mediante [SWS_CORE_05290]:

  • CoreErrc::kInvalidMetaModelShortname: se produce cuando faltan elementos de ruta en qualifiedShortName o contienen caracteres no permitidos [SWS_CORE_08032].
  • CoreErrc::kInvalidMetaModelPath: se devuelve si qualifiedShortName no describe una ruta válida hacia un elemento de modelo [SWS_CORE_08032].

Concurrencia y seguridad

La función está declarada como noexcept y especificada como segura frente a excepciones (exception safe), así como segura para subprocesos (thread-safe) [SWS_CORE_08032]. Por lo tanto, los llamadores pueden utilizarla de forma concurrente desde múltiples contextos de ejecución sin sincronización externa. Dado que devuelve un Result, es probable que esté prevista para validaciones defensivas de rutas de modelos en tiempo de ejecución sin tratamiento de excepciones.
