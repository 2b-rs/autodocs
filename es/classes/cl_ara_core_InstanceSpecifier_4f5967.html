Contexto

La clase ara::core::InstanceSpecifier sirve en la AUTOSAR Adaptive Platform como encapsulación con seguridad de tipos de una ruta ShortName de AUTOSAR (ruta de metamodelo) para la identificación de elementos de modelo. Funciona como un identificador estandarizado con el que los componentes de software, los puertos de comunicación y las instancias de servicio pueden referenciarse y resolverse de forma unívoca dentro del sistema global.

En la interacción con otros componentes, ara::core::InstanceSpecifier interactúa esencialmente a través de las siguientes interfaces:

  • Vistas de cadenas de caracteres: Las especificaciones de ruta se pasan como ara::core::StringView y, si es necesario, se proporcionan de nuevo como tales mediante el método ToString() [SWS_CORE_08041].
  • Gestión de resultados y errores: El método de fábrica estático utiliza ara::core::Result para devolver instancias válidas o para señalar errores de validación [SWS_CORE_08032]. En la ruta de construcción basada en errores, por el contrario, se desencadena ara::core::CoreException [SWS_CORE_08021].
  • Contenedores y metamodelo: Mediante la provisión de un operador de orden estricto operator<, la clase puede emplearse como clave en contenedores ordenados (por ejemplo, mapas asociativos) para la gestión de identificadores de elementos de modelo [SWS_CORE_08046]. Además, los operadores de comparación permiten la comparación directa con otras instancias, así como con cadenas de caracteres de rutas en bruto [SWS_CORE_08042], [SWS_CORE_08043], [SWS_CORE_08044], [SWS_CORE_08045].

Ciclo de vida

La creación de una instancia de ara::core::InstanceSpecifier puede tener lugar a través de dos vías diferentes:

  1. Método de fábrica Create: El método estático Create recibe un ara::core::StringView y valida las reglas sintácticas de la estructura de la ruta [SWS_CORE_08032]. Es seguro frente a excepciones (noexcept), seguro para subprocesos (thread-safe) y devuelve un ara::core::Result<InstanceSpecifier>, el cual encapsula la instancia terminada en caso de éxito o un código de error correspondiente en caso de fallo.
  2. Construcción directa: El constructor explícito también recibe un ara::core::StringView, pero está especificado como noexcept(false) y señala errores de validación lanzando una excepción de tipo ara::core::CoreException [SWS_CORE_08021]. Este constructor es seguro para subprocesos.

Para la semántica de valores, la clase proporciona constructores y operadores de asignación estandarizados:

  • Copia: El constructor de copia [SWS_CORE_08022] está declarado como noexcept y es seguro para subprocesos. El operador de asignación de copia [SWS_CORE_08024] también es noexcept, pero no es seguro para subprocesos.
  • Movimiento: El constructor de movimiento [SWS_CORE_08023] así como el operador de asignación de movimiento [SWS_CORE_08025] son noexcept, pero no son seguros para subprocesos.
  • Destrucción: El destructor ~InstanceSpecifier() [SWS_CORE_08029] es noexcept y no es seguro para subprocesos.

En cuanto a la titularidad y al tiempo de vida, existe una limitación esencial: el tiempo de vida del ara::core::StringView devuelto por ToString() solo está garantizado durante el tiempo de vida de la cadena de caracteres subyacente que se pasó originalmente como ara::core::StringView al constructor o al método de creación [SWS_CORE_08041]. Interpretación: A partir de este requisito cabe deducir que ara::core::InstanceSpecifier no crea una copia profunda autónoma de la cadena, sino que internamente solo mantiene una vista o referencia al búfer original. Por lo tanto, los desarrolladores deben asegurarse de que el objeto de cadena transferido permanezca válido en la memoria durante todo el tiempo de uso del InstanceSpecifier y de las vistas derivadas de este.

Con respecto a la concurrencia, rige lo siguiente: las operaciones de solo lectura (entre ellas ToString(), operator==, operator!=, operator<, así como el constructor de copia) son completamente seguras para subprocesos. Las operaciones modificadoras (construcción por movimiento, operadores de asignación, así como la destrucción) no son seguras para subprocesos y no deben ejecutarse de forma concurrente sin protección sobre el mismo objeto.

Ruta de uso

Una ruta de uso típica incluye la validación de una ruta de modelo durante la configuración o inicialización, la creación del identificador y su posterior uso para la identificación o la ordenación.

  1. Instanciación validada: la aplicación llama a ara::core::InstanceSpecifier::Create() con una ruta de metamodelo [SWS_CORE_08032].
  2. Comprobación del resultado: el ara::core::Result devuelto se comprueba para detectar errores. Si hay caracteres no válidos o faltan elementos de la ruta, la lógica de ejecución se desvía al tratamiento de errores.
  3. Identificación y comparación: la instancia extraída se utiliza para comparaciones con identificadores esperados o vistas de cadenas de caracteres [SWS_CORE_08042], [SWS_CORE_08043].
  4. Almacenamiento en contenedores: si es necesario, la instancia se almacena en estructuras de datos asociativas; la ordenación se realiza mediante el operador de comparación léxica operator< [SWS_CORE_08046].
  5. Salida textual: para fines de registro o diagnóstico, se consulta una representación de cadena a través de ToString() [SWS_CORE_08041].

Diagrama de secuencia: validación, creación y uso típicos de InstanceSpecifier. Fuentes: [SWS_CORE_08032], [SWS_CORE_08041], [SWS_CORE_08046].

Escenarios de error

Durante la creación de un ara::core::InstanceSpecifier pueden producirse errores de validación con respecto a la ruta de nombres pasada:

  • CoreErrc::kInvalidMetaModelShortname: este error ocurre si falta uno de los elementos de ruta de qualifiedShortName o contiene caracteres no válidos [SWS_CORE_08032], [SWS_CORE_08021].
  • CoreErrc::kInvalidMetaModelPath: este error se notifica si el qualifiedShortName pasado no forma una ruta sintácticamente válida a un elemento del modelo [SWS_CORE_08032], [SWS_CORE_08021].

El tipo de señalización de errores depende de la interfaz seleccionada:

  • Al utilizar el método de fábrica Create, la operación se ejecuta con semántica de reversión; el ara::core::Result devuelto contiene el código de error correspondiente sin que se lancen excepciones [SWS_CORE_08032].
  • Al utilizar el constructor explícito, la aparición de uno de estos errores provoca que se lance una excepción del tipo ara::core::CoreException que transporta el código de error CoreErrc correspondiente [SWS_CORE_08021].

Como condición previa para una instanciación sin errores, la cadena de entrada siempre debe cumplir las reglas sintácticas especificadas para elementos de ruta y rutas de metamodelo [SWS_CORE_08032], [SWS_CORE_08021]. Por el contrario, los operadores de comparación y acceso no poseen estados de retorno erróneos y garantizan una evaluación sin errores tras una creación exitosa (noexcept).

Esta guía se basa exclusivamente en la especificación de AUTOSAR para ara::core::InstanceSpecifier en el release R25-11.

<h4>Contexto</h4>
<p>La clase <code>ara::core::InstanceSpecifier</code> sirve en la AUTOSAR Adaptive Platform como encapsulación con seguridad de tipos de una ruta ShortName de AUTOSAR (ruta de metamodelo) para la identificación de elementos de modelo. Funciona como un identificador estandarizado con el que los componentes de software, los puertos de comunicación y las instancias de servicio pueden referenciarse y resolverse de forma unívoca dentro del sistema global.</p>
<p>En la interacción con otros componentes, <code>ara::core::InstanceSpecifier</code> interactúa esencialmente a través de las siguientes interfaces:</p>
<ul>
<li><strong>Vistas de cadenas de caracteres:</strong> Las especificaciones de ruta se pasan como <code>ara::core::StringView</code> y, si es necesario, se proporcionan de nuevo como tales mediante el método <code>ToString()</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
<li><strong>Gestión de resultados y errores:</strong> El método de fábrica estático utiliza <code>ara::core::Result</code> para devolver instancias válidas o para señalar errores de validación <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. En la ruta de construcción basada en errores, por el contrario, se desencadena <code>ara::core::CoreException</code> <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>

<p>En cuanto a la titularidad y al tiempo de vida, existe una limitación esencial: el tiempo de vida del <code>ara::core::StringView</code> devuelto por <code>ToString()</code> solo está garantizado durante el tiempo de vida de la cadena de caracteres subyacente que se pasó originalmente como <code>ara::core::StringView</code> al constructor o al método de creación <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>. Interpretación: A partir de este requisito cabe deducir que <code>ara::core::InstanceSpecifier</code> no crea una copia profunda autónoma de la cadena, sino que internamente solo mantiene una vista o referencia al búfer original. Por lo tanto, los desarrolladores deben asegurarse de que el objeto de cadena transferido permanezca válido en la memoria durante todo el tiempo de uso del <code>InstanceSpecifier</code> y de las vistas derivadas de este.</p>
<p>Con respecto a la concurrencia, rige lo siguiente: las operaciones de solo lectura (entre ellas <code>ToString()</code>, <code>operator==</code>, <code>operator!=</code>, <code>operator&lt;</code>, así como el constructor de copia) son completamente seguras para subprocesos. Las operaciones modificadoras (construcción por movimiento, operadores de asignación, así como la destrucción) no son seguras para subprocesos y no deben ejecutarse de forma concurrente sin protección sobre el mismo objeto.</p>

<h4>Escenarios de error</h4>
<p>Durante la creación de un <code>ara::core::InstanceSpecifier</code> pueden producirse errores de validación con respecto a la ruta de nombres pasada:</p>
<ul>
<li><strong><code>CoreErrc::kInvalidMetaModelShortname</code>:</strong> este error ocurre si falta uno de los elementos de ruta de <code>qualifiedShortName</code> o contiene caracteres no válidos <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
<li><strong><code>CoreErrc::kInvalidMetaModelPath</code>:</strong> este error se notifica si el <code>qualifiedShortName</code> pasado no forma una ruta sintácticamente válida a un elemento del modelo <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>El tipo de señalización de errores depende de la interfaz seleccionada:</p>
<ul>
<li>Al utilizar el método de fábrica <code>Create</code>, la operación se ejecuta con semántica de reversión; el <code>ara::core::Result</code> devuelto contiene el código de error correspondiente sin que se lancen excepciones <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>.</li>
<li>Al utilizar el constructor explícito, la aparición de uno de estos errores provoca que se lance una excepción del tipo <code>ara::core::CoreException</code> que transporta el código de error <code>CoreErrc</code> correspondiente <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>Como condición previa para una instanciación sin errores, la cadena de entrada siempre debe cumplir las reglas sintácticas especificadas para elementos de ruta y rutas de metamodelo <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. Por el contrario, los operadores de comparación y acceso no poseen estados de retorno erróneos y garantizan una evaluación sin errores tras una creación exitosa (<code>noexcept</code>).</p>
