Permite a State Management solicitar y supervisar estados de comunicación de redes lógicas y físicas.

ara::nm::NetworkHandle representa un objeto de acceso móvil, no copiable, con el cual State Management solicita y supervisar el estado de comunicación de redes a través de un identificador de instancia [SWS_ANM_01000], [SWS_ANM_01001]. Además de consultas de estado síncronas, la clase permite definir solicitudes así como registrar notificadores para estados efectivos o solicitados [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]. La falta de disponibilidad del servicio o notificadores erróneos se notifican en este proceso mediante códigos de error estandarizados en el objeto de resultado.

Contexto

La clase ara::nm::NetworkHandle actúa en el módulo nm como objeto de acceso estandarizado para un identificador de red lógico o físico concreto, el cual se direcciona a través de un ara::core::InstanceSpecifier de un prototipo de puerto [SWS_ANM_01000], [SWS_ANM_01001]. El usuario principal de esta interfaz es el State Management (SM) funcional, el cual notifica y supervisa a través del handle la demanda de comunicación para Partial Network Clusters (PNC), VLAN o redes físicas [SWS_ANM_01000], [SWS_ANM_01009]. Como capa de mediación, el objeto encapsula la interacción entre el grupo de funciones solicitante y el subsistema de NM subyacente.

Diagrama de contexto: integración de NetworkHandle entre State Management y la gestión de red. Fuentes: [SWS_ANM_01000], [SWS_ANM_01001], [SWS_ANM_01009], [SWS_ANM_01010], [SWS_ANM_01020], [SWS_ANM_01007]

Ciclo de vida

Un ara::nm::NetworkHandle se instancia explícitamente indicando un ara::core::InstanceSpecifier válido para un NetworkManagementPortInterface; este constructor está especificado como thread-safe [SWS_ANM_01001]. La instancia posee semántica exclusiva: el constructor de copia y el operador de asignación por copia están explícitamente eliminados (= delete) [SWS_ANM_01005], [SWS_ANM_01006]. La clase admite semántica de movimiento a través de constructor de movimiento y asignación por movimiento, en donde la asignación no es segura para subprocesos [SWS_ANM_01003], [SWS_ANM_01004].

La destrucción se realiza a través del destructor no seguro para subprocesos ~NetworkHandle() [SWS_ANM_01002]. Los notificadores registrados antes de la destrucción deberían cancelarse presumiblemente por la aplicación para evitar accesos asíncronos a contextos no válidos (interpretación). Pregunta Q-7c4ae0961601196a (abierta) Respecto a los estados de red, el handle representa dos niveles elementales a través del enum NetworkStateType: kNoCom (al menos una red asignada no se encuentra en el estado de comunicación completa) y kFullCom (todas las redes asignadas están activas) [SWS_ANM_01358].

Ruta de uso

La secuencia regular comprende la instanciación, el registro opcional de notificadores, la solicitud del estado de red así como la posterior liberación:

  • Instanciación: creación del handle mediante el identificador de instancia [SWS_ANM_01001].
  • Registrar observadores: registro de funciones de retrollamada del tipo NetworkStateChangeNotifier [SWS_ANM_01020] bien para el estado efectivo real a través de RegisterNetworkStateChangeNotifier [SWS_ANM_01010] o bien para el estado solicitado a través de RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]. Ambos métodos existen también como variante de plantilla para especificar un contexto de ejecución definido por el usuario (ExecutorT) [SWS_ANM_01014], [SWS_ANM_01015]. Por cada handle puede estar activo como máximo un notificador por categoría.
  • Solicitar estado: solicitud de comunicación completa (NetworkStateType::kFullCom) o liberación (NetworkStateType::kNoCom) mediante SetNetworkRequestedState [SWS_ANM_01009].
  • Consultar estado: lectura síncrona del estado solicitado actualmente con GetNetworkRequestedState [SWS_ANM_01008] o del estado de red realmente efectivo con GetNetworkState [SWS_ANM_01007]. Ambas consultas son seguras para subprocesos.
  • Limpieza: cancelación explícita del registro de los manejadores de retrollamada a través de UnregisterNetworkStateChangeNotifier [SWS_ANM_01011] y UnregisterNetworkRequestedStateChangeNotifier [SWS_ANM_01013].

Diagrama de secuencias: ruta de uso típica para el registro de notificadores, solicitud de estado y consulta. Fuentes: [SWS_ANM_01001], [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]

Escenarios de error

Las llamadas a métodos en NetworkHandle señalan errores a través de ara::core::Result. Están especificados los siguientes casos de error:

  • NmErrc::kServiceNotAvailable: se produce en SetNetworkRequestedState [SWS_ANM_01009], GetNetworkRequestedState [SWS_ANM_01008] y GetNetworkState [SWS_ANM_01007] si el servicio de gestión de red subyacente no está disponible o no responde.
  • NmErrc::kInvalidHandler: es devuelto por los métodos de registro de notificadores [SWS_ANM_01010] [SWS_ANM_01012], [SWS_ANM_01014] [SWS_ANM_01015] si se pasa una función manejadora no válida o ya hay un notificador registrado.

En cuanto a la concurrencia, las consultas de estado de lectura GetNetworkState y GetNetworkRequestedState son thread-safe, mientras que las operaciones modificadoras así como los registros no son seguros para subprocesos y requieren sincronización externa [SWS_ANM_01007], [SWS_ANM_01008], [SWS_ANM_01009], [SWS_ANM_01010].

La clase NetworkHandle actúa como objeto de acceso a un identificador de red direccionado a través de un ara::core::InstanceSpecifier y está prevista para State Management [SWS_ANM_01000]. La instanciación se realiza mediante el paso del InstanceSpecifier de un prototipo de puerto NetworkManagementPortInterface [SWS_ANM_01001]. Dado que la clase está declarada como final, no se puede utilizar como clase base para derivaciones [SWS_ANM_01000].

Semántica de movimiento y concurrencia

Los objetos de esta clase poseen una semántica pura de movimiento: el constructor de copia [SWS_ANM_01005] y el operador de asignación por copia [SWS_ANM_01006] están eliminados (= delete). En su lugar, las instancias se pueden transferir mediante el constructor de movimiento [SWS_ANM_01003] y el operador de asignación por movimiento [SWS_ANM_01004].

En lo relativo a la seguridad para subprocesos rigen las siguientes especificaciones:

  • El constructor con InstanceSpecifier es seguro para subprocesos (thread-safe) [SWS_ANM_01001].
  • Para el constructor de movimiento, la seguridad para subprocesos está definida de forma específica de la implementación (implementation-defined) [SWS_ANM_01003].
  • El destructor [SWS_ANM_01002] y la asignación por movimiento [SWS_ANM_01004] están designados explícitamente como no seguros para subprocesos (not thread-safe). Interpretación: Dado que no se garantiza la seguridad para subprocesos, es probable que el contexto llamador sea responsable de una sincronización externa en caso de que varios subprocesos utilicen el mismo identificador.         •

        •

          La enumeración NetworkStateType representa el estado de una red en el módulo anm (Adaptive Network Management) [SWS_ANM_01358]. Distingue entre el estado inactivo kNoCom = 0 (siempre que no todas las redes asignadas estén en el estado FULL_COM) y el estado activo kFullCom = 1 (cuando todas las redes asignadas son FULL_COM) [SWS_ANM_01358].
          

  
          El tipo encuentra múltiples usos en las interfaces de ara/nm/network_handle.h:
          
  
            
    
          • Consulta de estado: El método GetNetworkState() devuelve de forma síncrona y segura para subprocesos el estado de red efectivo actual como ara::core::Result<NetworkStateType> [SWS_ANM_01007]. Asimismo, GetNetworkRequestedState() lee de forma segura para subprocesos el estado actualmente solicitado para un PNC, VLAN o red física [SWS_ANM_01008].
            • 
    
          • Solicitud de estado: Mediante SetNetworkRequestedState(NetworkStateType networkState) se solicita activamente (kFullCom) o se libera (kNoCom) un estado para un PNC, una VLAN o una red física [SWS_ANM_01009]. Esta operación está especificada como no segura para subprocesos [SWS_ANM_01009].
            • 
    
          • Notificación de eventos: Mediante la función envoltorio NetworkStateChangeNotifier (std::function<void(const NetworkStateType&)>) se pasa el tipo como parámetro para informar a la lógica de aplicación sobre cambios de estado [SWS_ANM_01020].
            • 
  
          

  
          Tratamiento de errores: Al consultar o establecer NetworkStateType mediante los métodos mencionados, en caso de error se puede devolver el código NmErrc::kServiceNotAvailable en ara::core::Result [SWS_ANM_01007] [SWS_ANM_01008] [SWS_ANM_01009].
