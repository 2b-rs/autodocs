Contexto

La estructura de datos ara::diag::DownloadService::OperationOutput ([SWS_DM_00785], AUTOSAR_AP_SWS_Diagnostics §8.14.2 «Struct: OperationOutput») sirve en el módulo de diagnóstico de AUTOSAR Adaptive como parámetro de salida para operaciones del servicio de descarga. Agrupa los datos útiles de un mensaje de respuesta positiva ([SWS_DM_00786]) que una aplicación de diagnóstico devuelve al Diagnostic Management Daemon (DM) tras la ejecución correcta de una operación de descarga. La puesta a disposición se realiza a través del encabezado ara/diag/download.h ([SWS_DM_00786]).

En el flujo global interactúan principalmente tres entidades:

  • el tester de diagnóstico externo, que solicita servicios de descarga de diagnóstico (por ejemplo, transferencia de datos o finalización de la descarga),
  • el Diagnostic Management Daemon (DM), que recibe la solicitud UDS entrante, la valida y la reenvía a la instancia de servicio competente, así como
  • la propia instancia de aplicación de ara::diag::DownloadService, que procesa la operación, recopila los datos de respuesta en OperationOutput y los devuelve al daemon.

Diagrama de contexto: integración de OperationOutput en la interacción entre el tester de diagnóstico, el Diagnostic Management Daemon y la aplicación DownloadService. Fuentes: [SWS_DM_00785], [SWS_DM_00786], AUTOSAR_AP_SWS_Diagnostics §8.14.2.

Ciclo de vida

Como struct pura de transferencia de datos (Plain Old Data / Data Transfer Object), OperationOutput no posee ningún ciclo de vida activo propio ni máquinas de estados internas ([SWS_DM_00785]). La lógica de aplicación instancia un ejemplar localmente en cuanto se ha ejecutado con éxito una operación de descarga (por ejemplo, en el marco de DownloadData o RequestDownloadExit) y se debe preparar una respuesta positiva ([SWS_DM_00786]).

La vida útil del objeto está ligada a la creación y entrega del resultado de la operación. La aplicación rellena el miembro responseData de tipo ara::core::Vector<std::uint8_t> ([SWS_DM_00786]) y transfiere la estructura —típicamente incrustada en un ara::core::Future o ara::core::Result— a la infraestructura de diagnóstico. Tras la serialización de los datos útiles en el mensaje de respuesta UDS positiva, finaliza la vida útil del objeto.

Ruta de uso

La ruta típica de llamada y procesamiento se desarrolla en los siguientes pasos:

  1. Recepción de la solicitud: el tester de diagnóstico envía una solicitud de descarga, que es recibida por el DM y transferida a la instancia registrada de ara::diag::DownloadService.
  2. Instanciación y llenado: si el procesamiento se realiza correctamente, la aplicación instancia OperationOutput y rellena responseData con los datos útiles puros de la respuesta ([SWS_DM_00786]). En este caso, el identificador de servicio (SID) no se almacena explícitamente en responseData, ya que el daemon lo antepone ([SWS_DM_00786]).
  3. Entrega del resultado: la estructura se devuelve al framework de diagnóstico como resultado de la operación.
  4. Envío al tester: el framework de diagnóstico construye a partir del SID y del contenido de responseData el telegrama de respuesta completo y lo transmite al tester de diagnóstico.

Diagrama de secuencia: secuencia desde el procesamiento de la solicitud hasta la puesta a disposición de los datos de respuesta a través de OperationOutput. Fuentes: [SWS_DM_00785], [SWS_DM_00786], AUTOSAR_AP_SWS_Diagnostics p. 74.

Escenarios de error

La estructura OperationOutput modela exclusivamente el caso de éxito de una respuesta positiva (positive response message, [SWS_DM_00786]). Si una operación de descarga falla o se vulnera una precondición, no se procesa ningún objeto OperationOutput válido, sino que la operación señaliza al framework de diagnóstico el valor de error correspondiente (Negative Response Code / NRC).

Un error de configuración por parte de la aplicación consiste en rellenar responseData con un desplazamiento de datos erróneo o con encabezados redundantes: según la operación concreta (como DownloadData o RequestDownloadExit), difiere la especificación sobre en qué posición de byte comienza la respuesta positiva tras el SID ([SWS_DM_00786]). Si el SID se duplica erróneamente en responseData, esto da lugar a un telegrama UDS con formato incorrecto en el bus.

Esta guía se basa en los requisitos de AUTOSAR Adaptive Platform R25-11.

<h4>Escenarios de error</h4>
<p>
La estructura <code>OperationOutput</code> modela exclusivamente el caso de éxito de una respuesta positiva (<em>positive response message</em>, <a class="spec-record-ref" data-req="SWS_DM_00786" href="../spec/record.html?id=SWS_DM_00786">[SWS_DM_00786]</a>). Si una operación de descarga falla o se vulnera una precondición, no se procesa ningún objeto <code>OperationOutput</code> válido, sino que la operación señaliza al framework de diagnóstico el valor de error correspondiente (Negative Response Code / NRC).
</p>
<p>
Un error de configuración por parte de la aplicación consiste en rellenar <code>responseData</code> con un desplazamiento de datos erróneo o con encabezados redundantes: según la operación concreta (como <code>DownloadData</code> o <code>RequestDownloadExit</code>), difiere la especificación sobre en qué posición de byte comienza la respuesta positiva tras el SID (<a class="spec-record-ref" data-req="SWS_DM_00786" href="../spec/record.html?id=SWS_DM_00786">[SWS_DM_00786]</a>). Si el SID se duplica erróneamente en <code>responseData</code>, esto da lugar a un telegrama UDS con formato incorrecto en el bus.
</p>
