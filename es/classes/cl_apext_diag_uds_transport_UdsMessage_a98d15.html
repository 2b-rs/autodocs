clase apext::diag::uds_transport::UdsMessage

[SWS_DM_00291] Upstream: RS_Diag_04147

class UdsMessage {...};

class represents an UDS message exchanged between DM generic core (UdsTransport ProtocolMgr) and a specific implementation of UdsTransportProtocolHandler on diagnostic request reception path or diagnostic response transmission path. UdsMessage provides the storage for UDS requests/responses.

Instances of UdsMessage (with optimized resource allocation) are only created by DM generic core, the UdsTransportProtocolHandler can read/write on it.

Contexto

La clase apext::diag::uds_transport::UdsMessage encapsula un mensaje UDS (Request o Response) y actúa como almacenamiento central para datos de diagnóstico que se intercambian entre el núcleo genérico del Diagnostic Management (UdsTransportProtocolMgr) y una implementación concreta del protocolo de transporte (UdsTransportProtocolHandler). La instancia proporciona el búfer de mensajes subyacente tanto en la ruta de recepción para peticiones de diagnóstico (RX) como en la ruta de transmisión para respuestas de diagnóstico (TX).

Además de los datos útiles puros, UdsMessage gestiona metadatos e información de direccionamiento. Mediante GetSa() se consulta la dirección de origen ([SWS_DM_00297]) y mediante GetTa() la dirección de destino ([SWS_DM_00298]) de tipo Address ([SWS_DM_00293]). El tipo de dirección de destino se determina mediante GetTaType() ([SWS_DM_00299]), donde el enum TargetAddressType distingue entre direccionamiento físico (kPhysical) y funcional (kFunctional) ([SWS_DM_00296]). Además, se puede adjuntar información adicional específica del canal (por ejemplo, metadatos predefinidos para plugins de DoIP) al mensaje a través del método AddMetaInfo() en forma de MetaInfoMap ([SWS_DM_00302], [SWS_DM_00294]).

Diagrama de contexto: interacción entre el núcleo de DM, el manejador del protocolo de transporte y UdsMessage. Fuentes: [SWS_DM_00385], [SWS_DM_09012].

Ciclo de vida

Las instancias de UdsMessage son creadas exclusivamente por el núcleo genérico del Diagnostic Management con una asignación de recursos optimizada. El constructor predeterminado UdsMessage() está declarado protegido (protected) ([SWS_DM_09012]) para evitar explícitamente que los manejadores de protocolos de transporte instancien instancias de forma autónoma.

La propiedad y la transferencia de objetos UdsMessage se regulan mediante punteros inteligentes. Para ello, la plataforma define los alias de tipo UdsMessagePtr para acceso de escritura ([SWS_DM_00303]) y UdsMessageConstPtr para acceso de lectura constante ([SWS_DM_00304]). Al aceptar un mensaje, el núcleo de DM transfiere la propiedad de la instancia al manejador mediante un UdsMessagePtr ([SWS_DM_00385]). Tras completar el llenado, el mensaje se transfiere de nuevo al núcleo de DM para su procesamiento ([SWS_DM_00345]). La liberación y destrucción se realiza de forma determinista a través del destructor virtual predeterminado ~UdsMessage() ([SWS_DM_09010]).

En cuanto a la concurrencia, los métodos para la consulta de direcciones (GetSa(), GetTa(), GetTaType()) están especificados como reentrantes ([SWS_DM_00297], [SWS_DM_00298], [SWS_DM_00299]). Por el contrario, los métodos para el acceso a datos útiles y metadatos (GetPayload() y AddMetaInfo()) no son seguros para subprocesos (unsafe) ([SWS_DM_00300], [SWS_DM_00301], [SWS_DM_00302]), ya que se permite a las implementaciones realizar asignaciones de búfer y de recursos en las llamadas a GetPayload().

Ruta de uso

El flujo típico en la ruta de recepción de diagnóstico (RX) se divide en los siguientes pasos:

  1. Anuncio: el UdsTransportProtocolHandler recibe una solicitud UDS desde la red y señala su recepción mediante la llamada a UdsTransportProtocolMgr::IndicateMessage() ([SWS_DM_00385]).
  2. Instanciación y provisión de búfer: si el DM puede procesar la solicitud, IndicateMessage() devuelve un std::pair ([SWS_DM_00309]) con el estado kIndicationOk y un UdsMessagePtr que posee la UdsMessage creada. El búfer asignado presenta un tamaño mínimo de un byte ([SWS_DM_00385]).
  3. Llenado de los datos útiles: el manejador llama a la sobrecarga no constante GetPayload() ([SWS_DM_00301]) y obtiene una referencia a uds_transport::ByteSpan&. El manejador llena el objeto UdsMessage con los datos UDS recibidos, comenzando por el ID de servicio (SID), bien hasta la capacidad máxima del mensaje o bien hasta la longitud completa de la solicitud UDS recibida ([SWS_DM_00388]).
  4. Adición de metadatos: en caso necesario, el manejador añade metadatos específicos del canal a través de AddMetaInfo() ([SWS_DM_00302]).
  5. Reenvío al núcleo del DM: en cuanto los datos útiles se han escrito por completo en UdsMessage, el manejador entrega el mensaje mediante UdsTransportProtocolMgr::HandleMessage() al núcleo genérico del DM para su posterior procesamiento de diagnóstico ([SWS_DM_00345]).
  6. Acceso de lectura en el núcleo del DM: el núcleo de diagnóstico lee los datos del mensaje (A_Data según ISO) en modo de solo lectura mediante la sobrecarga constante GetPayload() const ([SWS_DM_00300]).

Interpretación: en la ruta de respuesta de diagnóstico (TX), probablemente el propio núcleo genérico del DM llene de forma análoga el objeto UdsMessage con datos de respuesta y lo entregue al UdsTransportProtocolHandler para su transmisión.

Diagrama de secuencia: desarrollo de la aceptación de mensajes y el llenado del búfer en la ruta de recepción. Fuentes: [SWS_DM_00301], [SWS_DM_00302], [SWS_DM_00345], [SWS_DM_00385], [SWS_DM_00388].

Escenarios de error

Durante la interacción y la asignación del búfer pueden producirse las siguientes situaciones de error:

  • DM ocupado (Busy): si el DM ya está ocupado con el procesamiento activo de un servicio de la misma conversación, IndicateMessage() devuelve el estado kIndicationOccupied y un puntero nulo para UdsMessagePtr ([SWS_DM_00386]). En este caso no se proporciona UdsMessage. Una excepción a esto la constituyen las solicitudes funcionales TesterPresent con suppressPosRspMsgIndicationBit establecido (payload 0x3E 0x80), que son válidas en cualquier momento y pueden procesarse ([SWS_DM_00386], [SWS_DM_00126]).
  • Dirección de destino desconocida: si la dirección de destino del mensaje no se puede resolver, el DM lo señaliza mediante el resultado kIndicationUnknownTargetAddress y establece UdsMessagePtr en nullptr (AUTOSAR_AP_SWS_Diagnostics p. 100). No se produce ninguna asignación de un objeto de mensaje.
  • Limitación de búfer: la capacidad del objeto UdsMessage transferido está limitada por la asignación establecida por el DM. El manejador puede escribir en el búfer como máximo hasta el límite de capacidad ([SWS_DM_00388]).

Esta guía se basa en la especificación AUTOSAR Adaptive Platform R25-11 (módulo diag) y resume los requisitos para apext::diag::uds_transport::UdsMessage.
