Permite a la aplicación responder a solicitudes de lectura y escritura de diagnóstico para identificadores de datos específicos.

La interfaz <DataIdentifier-Namespace>::<DataIdentifierInterface> permite a las aplicaciones adaptativas proporcionar identificadores de datos de diagnóstico específicos del modelo frente a Diagnostic Management [SWS_DM_00585]. Tras la creación, Offer() habilita el reenvío de solicitudes que se procesan de forma asíncrona mediante Read() o Write() y, en caso necesario, se responden con códigos de error UDS [SWS_DM_00599] [SWS_DM_00640]. Dado que la instancia no se puede copiar ni mover, el servicio se finaliza explícitamente a través de StopOffer() antes de su destrucción [SWS_DM_01665] [SWS_DM_00600].

Contexto

La clase de C++ <DataIdentifier-Namespace>::<DataIdentifierInterface> actúa como interfaz funcional para identificadores de datos de diagnóstico (Data Identifiers, DID) en el módulo diag de la Adaptive Platform SWS Diagnostics p. 68. Conecta la capa de aplicación adaptativa con el Diagnostic Management (DM) central. Diagnostic Management recibe solicitudes de diagnóstico externas y las reenvía a la instancia registrada [SWS_DM_00599]. El software de aplicación proporciona la implementación concreta a través de clases derivadas para consultar o actualizar contenidos de datos mediante operaciones de lectura o escritura [SWS_DM_00640] [SWS_DM_00598].

Ciclo de vida

La creación se realiza a través del constructor parametrizado pasando un ara::core::InstanceSpecifier y el modo de concurrencia ara::diag::ConcurrencyType [SWS_DM_00585]. Este último determina si las llamadas a la instancia se pueden procesar de forma concurrente (kConcurrent) o no concurrente (kNotConcurrent) [SWS_DM_00585]. Dado que una instancia está ligada de forma fija a su configuración de modelo, tanto el constructor de copia como el de movimiento están explícitamente eliminados [SWS_DM_01665] [SWS_DM_01666]; lo mismo aplica para los operadores de asignación por copia y por movimiento [SWS_DM_01663] [SWS_DM_01664].

Tras la instanciación, la interfaz se encuentra en estado inactivo. Solo mediante la llamada a Offer() se activa el reenvío de solicitudes de diagnóstico por parte de Diagnostic Management [SWS_DM_00599]. El método StopOffer() finaliza de nuevo este reenvío [SWS_DM_00600]. La liberación de recursos se efectúa mediante el destructor virtual [SWS_DM_00586]. Interpretación: Antes de la destrucción del objeto, es de esperar que típicamente se invoque StopOffer() para evitar de forma ordenada reenvíos pendientes o nuevos entrantes del DM.

Ruta de uso

El flujo regular comprende la instanciación, el registro del servicio, el procesamiento asíncrono de solicitudes y la subsiguiente desactivación:

  1. Instanciación: La aplicación crea una instancia de la interfaz indicando el InstanceSpecifier y el ajuste deseado de ConcurrencyType [SWS_DM_00585].
  2. Habilitación del servicio: La aplicación invoca Offer(), con lo cual Diagnostic Management puede entregar solicitudes a este manejador [SWS_DM_00599].
  3. Procesamiento de solicitudes: En accesos de lectura, el DM invoca el método puramente virtual Read() [SWS_DM_00640]; en accesos de escritura, Write() [SWS_DM_00598]. Mediante el cancellationHandler suministrado, la aplicación puede monitorizar eventos de cancelación. Los resultados se proporcionan de forma asíncrona como ara::core::Future, que en Read() contiene un objeto ReadOutput con los datos de salida [SWS_DM_00579] [SWS_DM_00640] [SWS_DM_80013].
  4. Finalización del servicio: Mediante la invocación de StopOffer() se detiene el reenvío [SWS_DM_00600] antes de que el objeto sea destruido [SWS_DM_00586].

Diagrama de secuencia: flujo típico de provisión de DID desde la inicialización, pasando por la respuesta asíncrona a solicitudes, hasta la desactivación. Fuentes: [SWS_DM_00585], [SWS_DM_00599], [SWS_DM_00640], [SWS_DM_00600], [SWS_DM_00586].

Escenarios de error

Ya durante la creación del objeto, los errores de modelado pueden dar lugar a infracciones: si faltan vinculaciones de puertos o procesos, se producen InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation o ProcessMappingViolation [SWS_DM_00585]. Si se reutiliza el mismo InstanceSpecifier en el mismo proceso, el framework reporta InstanceSpecifierAlreadyInUseViolation [SWS_DM_00585].

Si se invoca Offer() a pesar de que el servicio ya se está ofreciendo, la llamada falla y devuelve el código de error DiagOfferErrc::kAlreadyOffered a través de ara::core::Result [SWS_DM_00599]. Si falla la ejecución de Read() o Write(), la implementación transmite errores de forma asíncrona en Future mediante códigos de error UDS ISO 14229-1 (DiagUdsNrcErrc) o ApApplicationError [SWS_DM_00640] [SWS_DM_00598] específicos de la aplicación. En cuanto a la seguridad frente a excepciones, el constructor y los métodos de procesamiento están especificados como exception safe [SWS_DM_00585] [SWS_DM_00599] [SWS_DM_00640] [SWS_DM_00598], mientras que el destructor no está identificado como exception safe [SWS_DM_00586].

Esta guía se basa en la especificación AUTOSAR para la Adaptive Platform (Release R25-11).

usar

La función constructora <DataIdentifierInterface> sirve para instanciar un identificador de datos a partir de un ara::core::InstanceSpecifier [SWS_DM_00585]. La declaración se realiza dentro del espacio de nombres <DataIdentifier-Namespace> a través del archivo de cabecera #include "<DataIdentifierDirectoryPath>/<DataIdentifierShortname>.h" [SWS_DM_00585]. La llamada síncrona está especificada como noexcept y posee las propiedades «exception safe» y «thread-safe» [SWS_DM_00585].

La función acepta los siguientes parámetros de entrada [SWS_DM_00585]:

  • instanceSpec (ara::core::InstanceSpecifier): Identificador de la instancia concreta de un servicio [SWS_DM_00585].
  • concurrencyType (ara::diag::ConcurrencyType): Determina si la interfaz se opera de forma segura para subprocesos con kConcurrent o no segura para subprocesos con kNotConcurrent [SWS_DM_00585].

Tratamiento de errores y reglas de modelado

La función no devuelve ningún valor y no lanza excepciones. En su lugar, los errores en la configuración o el modelado conducen a violaciones definidas [SWS_DM_00585]:

  • InstanceSpecifierMappingIntegrityViolation: El instanceSpec no se puede resolver en el contexto del ejecutable o no hace referencia a un PortPrototype [SWS_DM_00585].
  • PortInterfaceMappingViolation: Un PortPrototype tipificado mediante DiagnosticDataIdentifierInterface no es referenciado por un DiagnosticDataPortMapping [SWS_DM_00585].
  • ProcessMappingViolation: No existe ningún proceso modelado adecuado para la referencia de instancia respecto al proceso de ejecución actual [SWS_DM_00585].
  • InstanceSpecifierAlreadyInUseViolation: El constructor se invocó con un instanceSpec que ya está en uso en el proceso actual [SWS_DM_00585].

Interpretación: Dado que la función está declarada como noexcept, es de suponer que las violaciones detectadas se traten internamente en el framework como errores críticos de inicialización.

concurrencia

La propia función constructora se ejecuta de forma segura para subprocesos [SWS_DM_00585]. Mediante el argumento concurrencyType se controla si las llamadas posteriores a la interfaz de la instancia pueden realizarse de manera concurrente [SWS_DM_00585].

  Procedencia
  

              

              

              Uso y contexto de llamada
              
  
              El método síncrono Offer() permite al Diagnostic Management (DM) reenviar solicitudes de diagnóstico entrantes a la respectiva instancia de <DataIdentifierInterface> ([SWS_DM_00599]). La función no recibe parámetros de transferencia y está especificada como noexcept ([SWS_DM_00599]). Interpretación: la llamada se produciría típicamente durante la fase de inicialización de la aplicación, ya que el DM no puede entregar solicitudes antes de la puesta a disposición.
              

  
              Tratamiento de errores y valores de retorno
              
  
              Como valor de retorno se utiliza ara::core::Result<void> ([SWS_DM_00599]). Si el registro fue correcto, el resultado no contiene ningún valor. Si el manejador ya se había puesto a disposición previamente, la llamada falla y devuelve el código de error DiagOfferErrc::kAlreadyOffered con semántica de reversión (rollback) ([SWS_DM_00599]; cf. [SWS_DM_00514]).
              

  
              Concurrencia y restricciones
              
  
              La función garantiza seguridad frente a excepciones (exception safe), pero está especificada expresamente como no segura para subprocesos (not thread-safe) ([SWS_DM_00599]). Las llamadas paralelas en la misma instancia deben ser sincronizadas por la aplicación.
              

  
              Interacción
              
  
              El patrón de puesta a disposición se corresponde con el enfoque de activación uniforme en el DM: existen métodos Offer() análogos para identificadores genéricos ([SWS_DM_00638]), elementos de datos ([SWS_DM_00597]), rutinas ([SWS_DM_00557], [SWS_DM_00594]) y servicios DoIP ([SWS_DM_00725], [SWS_DM_00735]). Mientras no se haya ejecutado Offer(), el DM no reenvía peticiones al manejador y responde con valores predeterminados en el caso de servicios DoIP ([SWS_DM_01525], [SWS_DM_01527]).

  Procedencia
  

                  

                  

                  usar
                  

                  El método Read sirve para proporcionar datos de un identificador de datos de diagnóstico (DataIdentifier) en el rol de lectura de un DiagnosticDataIdentifierInterface [SWS_DM_00640]. La llamada la realiza de forma asíncrona el Diagnostic Manager (DM) en caso de solicitudes de diagnóstico externas AUTOSAR_AP_SWS_Diagnostics p. 143 §7.3.2.6.1 «NRCs created by application». Como parámetros se pasan metaInfo para evaluar las propiedades de la solicitud, así como un cancellationHandler [SWS_DM_00640]. La aplicación de procesamiento puede consultar el estado de cancelación mediante cancellationHandler.IsCanceled() o registrar una callback mediante cancellationHandler.SetNotifier() para el caso de que la sesión se interrumpa prematuramente [SWS_DM_00640]. El resultado se devuelve de forma asíncrona como ara::core::Future con un objeto ReadOutput [SWS_DM_00640], [SWS_DM_00579].
                  


                  Manejo de errores
                  

                  La función está especificada como exception safe y no debe propagar excepciones hacia el exterior [SWS_DM_00640].   Procedencia
  

                      

                      

                      El método StopOffer desinstala el reenvío de solicitudes de diagnóstico entrantes de Diagnostic Management (DM) a la instancia de interfaz concreta [SWS_DM_00600]. Mediante la llamada, la aplicación adaptativa señala que deja de estar disponible, de forma temporal o permanente, para procesar solicitudes correspondientes a este DataIdentifier.
                      

  
                      Uso y semántica
                      
  
                      La llamada se realiza de forma síncrona, no tiene parámetros y no devuelve ningún valor devuelto [SWS_DM_00600]. Como encabezado debe incluirse el archivo de interfaz generado #include "<DataIdentifierDirectoryPath>/<DataIdentifierShortname>.h" [SWS_DM_00600]. La nomenclatura sigue el patrón conocido de ara::com, pero representa una interfaz independiente del dominio de diagnóstico AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 «Monitors».
                      

  
                      Tratamiento de errores y concurrencia
                      
  
                        
    
                      • Seguridad frente a excepciones: La función está declarada con noexcept y garantiza una seguridad total frente a excepciones (exception safe) [SWS_DM_00600]. No se lanzan excepciones.
                        • 
    
                      • Seguridad de hilos: La operación está especificada como not thread-safe [SWS_DM_00600]. La llamada debe realizarse de forma sincronizada, de modo que no se produzca ningún acceso paralelo a la misma instancia de interfaz.
                        • 
  
                      

  
                      Interacción
                      
  
                      El comportamiento corresponde al patrón de desactivación uniforme de Diagnostic Management, tal como se define análogamente también para interfaces afines, como rutinas [SWS_DM_00558], elementos de datos genéricos [SWS_DM_00639] o servicios de descarga [SWS_DM_00793]. Las solicitudes entrantes de DM dirigidas a este DataIdentifier ya no se reenvían al manejador de la aplicación tras una desactivación correcta [SWS_DM_00600]; previsiblemente, DM generará a continuación los correspondientes códigos de respuesta negativos.
