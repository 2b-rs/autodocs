Contexto

La interfaz ara::crypto::cryp::SignerPrivateCtx define el contexto para operaciones criptográficas de firma mediante el uso de una clave privada en AUTOSAR Adaptive Platform. Como especialización de CryptoContext, encapsula la lógica algorítmica para la creación de firmas digitales sobre bloques de mensajes de cualquier tamaño.

Entre los interlocutores principales de la interfaz se encuentran:

  • Componente de aplicación que realiza la llamada: controla el proceso de firma, transfiere los datos de entrada y recibe el resultado de la firma.
  • Objetos de clave: El contexto requiere acceso a material de clave privada. Este se transfiere directamente como PrivateKey::Sptr [SWS_CRYPT_23515] o se vincula mediante una ranura de clave referenciada KeySlot::Sptr [SWS_CRYPT_50036].
  • Búferes de memoria: Los datos de entrada y los datos de contexto opcionales se proporcionan como ReadOnlyMemRegion, mientras que el valor de firma resultante se escribe en un búfer modificable del tipo ReadWriteMemRegion [SWS_CRYPT_23512], [SWS_CRYPT_50040].

Ciclo de vida

Las instancias de contexto se gestionan habitualmente como punteros inteligentes mediante el alias de tipo proporcionado ara::crypto::cryp::SignerPrivateCtx::Sptr (definido como std::shared_ptr<SignerPrivateCtx>) [SWS_CRYPT_23501]. Dado que la clase proporciona métodos de interfaz puramente virtuales, es probable que la creación de objetos se realice mediante un método de fábrica de un servicio criptográfico de nivel superior.

El ciclo de vida del contexto se divide en fases distintas:

  1. No inicializado: Inmediatamente después de la instanciación, el contexto no tiene asignada ninguna clave. En este estado, las llamadas directas de firma o inicio se rechazan con un error [SWS_CRYPT_23512], [SWS_CRYPT_50037].
  2. Configurado (listo): Al invocar SetKey() con un PrivateKey::Sptr [SWS_CRYPT_23515] o un KeySlot::Sptr [SWS_CRYPT_50036], el contexto pasa a estar operativo. A partir de este estado, se puede ejecutar una firma de un solo paso mediante Sign() o iniciar un procesamiento por streaming.
  3. Streaming activo: Una llamada a Start() [SWS_CRYPT_50037] o Start(context) [SWS_CRYPT_50038] sitúa el contexto en el procesamiento en curso. En esta fase, se pueden realizar actualizaciones iterativas mediante Update() [SWS_CRYPT_50039].
  4. Finalización o cancelación: La secuencia de streaming en curso finaliza de forma regular mediante Finish() [SWS_CRYPT_50040] o se descarta prematuramente a través de Cancel() [SWS_CRYPT_50041]. Tras ambos métodos, es de suponer que el contexto permanece en el estado configurado con la clave asignada, de modo que se puede iniciar directamente un nuevo cálculo de firma.

Todos los métodos de interfaz están declarados como noexcept, presentan el nivel de seguridad frente a excepciones exception safe y están diseñados según la especificación para ser thread-safe [SWS_CRYPT_50041].

Diagrama de estados: Ciclo de vida y estados de procesamiento de SignerPrivateCtx. Fuentes: [SWS_CRYPT_23515], [SWS_CRYPT_50036], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040], [SWS_CRYPT_50041], [SWS_CRYPT_23512]

Ruta de uso

La interfaz admite dos rutas de uso funcionales para el cálculo de firmas:

1. Generación de firmas basada en streaming: Esta ruta es adecuada para mensajes grandes o que llegan fragmentados. Antes de comenzar, se pueden determinar el tamaño de bloque máximo permitido mediante GetMaximumChunkSize() [SWS_CRYPT_50042] y la longitud de firma esperada para un formato de destino determinado mediante GetSignatureSize() [SWS_CRYPT_29004]. Tras asignar la clave mediante SetKey() [SWS_CRYPT_23515], el cálculo se inicializa con Start() [SWS_CRYPT_50037]. A continuación, se introducen partes del mensaje de forma secuencial a través de Update() [SWS_CRYPT_50039]. La llamada a Finish() [SWS_CRYPT_50040] completa la generación de la firma y escribe el resultado en el búfer proporcionado.

Diagrama de secuencia: Flujo típico de la generación de firmas por streaming. Fuentes: [SWS_CRYPT_23515], [SWS_CRYPT_29004], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040]

2. Generación de firma en una sola llamada: Si el mensaje completo ya se encuentra en un área de memoria contigua, se puede llamar alternativamente al método Sign() [SWS_CRYPT_23512]. Este procesa el mensaje, el formato deseado y los datos de contexto opcionales en un único paso atómico y escribe la firma directamente en el búfer de salida.

Escenarios de error

Los valores de retorno se transmiten mediante ara::core::Result. En caso de fallo, la semántica de reversión especificada garantiza que el estado del contexto no se corrompa de forma indefinida ante un error. Se definen las siguientes causas de error:
