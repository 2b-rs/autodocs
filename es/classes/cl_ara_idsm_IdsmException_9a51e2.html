Encapsula códigos de error de las interfaces de IdsM como excepción de C++ para el tratamiento estructurado de errores en aplicaciones.

La clase ara::idsm::IdsmException sirve como clase de excepción estandarizada de C++ para representar errores de las interfaces de programación de IdsM [SWS_AIDSM_10704]. Deriva de ara::core::Exception y encapsula un código de error específico para el análisis de causas. La instanciación se realiza a través de un constructor explícito con un ara::core::ErrorCode, garantizado como seguro para subprocesos y como noexcept [SWS_AIDSM_10705]. De este modo, la clase permite un tratamiento de excepciones determinista y seguro en flujos fallidos de IdsM.

Contexto

La clase ara::idsm::IdsmException actúa como clase de excepción dedicada para señalizar y tratar errores de las interfaces de programación del Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10704]. Está definida en la cabecera ara/idsm/idsm_error_domain.h y deriva públicamente de la clase base ara::core::Exception [SWS_AIDSM_10704]. Dentro de AUTOSAR Adaptive Platform, la clase interactúa principalmente con clústeres funcionales clientes, así como con las interfaces del módulo IdsM. Ofrece a los desarrolladores un mecanismo estandarizado de excepciones de C++ para interceptar estados de error de forma estructurada, en lugar de propagar mensajes de error exclusivamente mediante valores de retorno.

Ciclo de vida

La instanciación de ara::idsm::IdsmException se realiza a través de un constructor explícito que exige el paso de un ara::core::ErrorCode [SWS_AIDSM_10705]. Este constructor está declarado con el especificador noexcept, lo que garantiza que durante la construcción del objeto de excepción no se lancen más excepciones [SWS_AIDSM_10705]. En lo relativo a la concurrencia, la construcción se especifica expresamente como segura para subprocesos (thread-safe) [SWS_AIDSM_10705], de modo que los objetos de excepción también pueden instanciarse de forma segura en contextos de ejecución multihilo sin sincronización adicional.

Como objeto de excepción, IdsmException está sujeto a la semántica de valor típica de C++. La creación tiene lugar de inmediato al detectar una condición de error o al desempaquetar un resultado de operación defectuoso. El ciclo de vida está ligado a la evaluación en el bloque catch correspondiente; tras su finalización, el sistema de tiempo de ejecución destruye automáticamente el objeto de excepción.

Ruta de uso

El uso típico de la clase tiene lugar en el marco de llamadas síncronas a servicios de IdsM. Una aplicación invoca una función del módulo idsm. Si el entorno de ejecución de IdsM detecta una operación no válida o un error interno, genera el correspondiente ara::core::ErrorCode e instancia con él una ara::idsm::IdsmException [SWS_AIDSM_10705]. Esta excepción se lanza e interrumpe el flujo de control regular [SWS_AIDSM_10704].

La aplicación llamadora captura el objeto de forma específica como ara::idsm::IdsmException o de forma genérica como ara::core::Exception. En el gestor de excepciones se puede extraer el código de error encapsulado y evaluarlo para registro de diagnóstico, estrategias de mitigación o reinicios deterministas.

Escenarios de error

La clase ara::idsm::IdsmException sirve para representar errores de la API de IdsM y se utiliza cuando las llamadas a funciones fallan y este estado se notifica a través de la ruta de excepción [SWS_AIDSM_10704]. Una precondición esencial para la creación es la presencia de un objeto ara::core::ErrorCode válido que describa con precisión la causa del error [SWS_AIDSM_10705].

Un estado de error secundario durante la creación del objeto queda excluido gracias a la garantía noexcept del constructor [SWS_AIDSM_10705]. De este modo se evita provocar una terminación inesperada del programa mediante std::terminate en rutas de tratamiento de errores que ya son críticas. La poscondición de la llamada al constructor es un objeto de excepción inicializado que mantiene inalterado el código de error para el diagnóstico posterior.
