Contexto

La clase ara::per::FileStorage representa un almacenamiento de archivos persistente que gestiona un conjunto de archivos identificados mediante nombres de archivo únicos. Dentro de la AUTOSAR Adaptive Platform (módulo per), constituye la capa de abstracción central para la persistencia basada en archivos. Entre los interlocutores se encuentran la aplicación adaptativa, que solicita operaciones de lectura y escritura, así como los objetos de acceso generados por la instancia de almacenamiento (como ReadAccessor, WriteAccessor y ReadWriteAccessor), que se transfieren encapsulados mediante ara::core::UniqueHandle. Mientras que la transferencia de datos se realiza de forma desacoplada a través de los accesores respectivos, FileStorage controla las operaciones de gestión de nivel superior, como la creación de archivos, las comprobaciones de integridad, la restauración y el borrado.

Ciclo de vida

El ciclo de vida de una instancia de FileStorage está sujeto a condiciones restrictivas respecto a las operaciones de copia y movimiento. El constructor predeterminado está explícitamente eliminado ([SWS_PER_00460]). Del mismo modo, el constructor de copia ([SWS_PER_00328]), el operador de asignación de copia ([SWS_PER_00329]), el constructor de movimiento ([SWS_PER_00326]) y el operador de asignación de movimiento ([SWS_PER_00327]) están declarados como =delete. Por lo tanto, una instancia no se puede copiar ni mover. La creación de una instancia de FileStorage debería tener lugar a través de funciones factoría externas del entorno de ejecución de persistencia (Interpretación: dado que no hay constructores públicos disponibles, la provisión corresponde a la infraestructura de la plataforma).

El destructor ~FileStorage está definido como noexcept, pero expresamente no es seguro para subprocesos (not thread-safe) ([SWS_PER_00330]). Por lo tanto, antes de la destrucción del objeto debe garantizarse que hayan finalizado todos los accesos concurrentes a esta instancia. Durante la fase de funcionamiento regular, las llamadas a funciones de la instancia son seguras para subprocesos y seguras frente a excepciones. No obstante, en las consultas de estado de lectura deben tenerse en cuenta los efectos de concurrencia: las consultas como FileExists ([SWS_PER_00112]) o GetAllFileNames ([SWS_PER_00110]) solo son exactas si no se crean ni se borran archivos simultáneamente en otro subproceso. Del mismo modo, GetCurrentFileSize ([SWS_PER_00407]) y GetFileInfo ([SWS_PER_00438]) solo reflejan con precisión el estado actual del archivo si el archivo en cuestión no está abierto ni se está modificando en el momento de la consulta.

Ruta de uso

Una ruta de uso típica incluye la comprobación de existencia, la apertura del archivo deseado, el acceso a través de un handle RAII y el mantenimiento posterior:

  1. Determinar archivos y comprobar metadatos: antes del acceso, se puede verificar la existencia con FileExists ([SWS_PER_00112]) u obtener una lista de todos los archivos mediante GetAllFileNames ([SWS_PER_00110]). Los detalles sobre el tamaño del archivo y las marcas de tiempo los proporcionan GetCurrentFileSize ([SWS_PER_00407]) y GetFileInfo ([SWS_PER_00438]).
  2. Abrir archivo: para la apertura hay disponibles tres modos, cada uno de los cuales devuelve un ara::core::Result con un UniqueHandle:
    • Solo lectura: OpenFileReadOnly abre el archivo al principio ([SWS_PER_00376]), con el modo especificado ([SWS_PER_00114]) o con un búfer de bloques definido por el usuario para optimizar el rendimiento en caso de muchos accesos pequeños ([SWS_PER_00430]).
    • Solo escritura: OpenFileWriteOnly ([SWS_PER_00377], [SWS_PER_00115], [SWS_PER_00431]) trunca el archivo de forma predeterminada (kTruncate) y lo crea automáticamente en caso de que aún no exista.
    • Lectura y escritura: OpenFileReadWrite ([SWS_PER_00375], [SWS_PER_00113], [SWS_PER_00429]) sitúa la posición del archivo al principio, crea el archivo si no existe y, opcionalmente, también admite búferes personalizados.
  3. Procesamiento y cierre: el acceso al archivo se realiza a través del handle accesor devuelto. En cuanto el UniqueHandle sale del ámbito de validez, el archivo se cierra automáticamente ([SWS_PER_00114]).
  4. Administración: con DeleteFile ([SWS_PER_00111]) se eliminan los archivos que ya no se necesitan. Un archivo se puede restablecer a su estado de fábrica mediante ResetFile ([SWS_PER_00338]) o restaurar mediante RecoverFile ([SWS_PER_00337]) en caso de errores de redundancia.

Diagrama de secuencia: flujo típico de comprobación de existencia, apertura de solo lectura y liberación automática mediante RAII. Fuentes: [SWS_PER_00112], [SWS_PER_00376], [SWS_PER_00114].

Escenarios de error

Las llamadas a métodos notifican errores mediante códigos de error del tipo PerErrc. Los escenarios y las precondiciones esenciales son:

  • PerErrc::kResourceBusy: se produce cuando se va a abrir ([SWS_PER_00114], [SWS_PER_00113], [SWS_PER_00115]), eliminar ([SWS_PER_00111]), restaurar ([SWS_PER_00337]) o restablecer ([SWS_PER_00338]) un archivo mientras todavía está abierto o cuando se ejecuta en paralelo una operación de restauración, restablecimiento o eliminación sobre el mismo nombre de archivo.
  • PerErrc::kFileNotFound: se produce cuando un nombre de archivo no existe para operaciones de lectura ([SWS_PER_00114]), operaciones de eliminación ([SWS_PER_00111]), consultas de tamaño ([SWS_PER_00407]), consultas de metadatos ([SWS_PER_00438]) o restauraciones ([SWS_PER_00337]). En la apertura para escritura no se produce este error, ya que los archivos inexistentes se crean directamente ([SWS_PER_00113], [SWS_PER_00115]).
  • PerErrc::kIllegalWriteAccess: se devuelve cuando se intentan accesos de escritura o eliminación en un almacenamiento de solo lectura o cuando el archivo ya existe en el modo write-only-once ([SWS_PER_00111], [SWS_PER_00113], [SWS_PER_00115]).
  • Restricciones de recursos y cuotas: si el espacio de almacenamiento físico no es suficiente para archivos nuevos o inicializados, las operaciones fallan con PerErrc::kOutOfStorageSpace ([SWS_PER_00113], [SWS_PER_00337], [SWS_PER_00338]). Si se supera el tamaño máximo configurado, se notifica PerErrc::kQuotaExceeded ([SWS_PER_00337], [SWS_PER_00338]). Si la creación supera el número de archivos configurado maxNumberOfFiles, la llamada falla con PerErrc::kTooManyFiles ([SWS_PER_00113], [SWS_PER_00338]).
  • PerErrc::kInitValueNotAvailable: se produce en ResetFile cuando no se han definido contenidos iniciales de archivo ni en el Application Design ni en la Target Configuration ([SWS_PER_00338]).
  • Errores de hardware y de integridad: los fallos del soporte de almacenamiento (PerErrc::kPhysicalStorageFailure), las violaciones de integridad estructural (PerErrc::kIntegrityCorrupted), los errores de validación (PerErrc::kValidationFailed), así como los errores criptográficos y de autenticación (PerErrc::kEncryptionFailed, PerErrc::kAuthenticationFailed) señalan defectos o inconsistencias de seguridad de los datos persistentes.
