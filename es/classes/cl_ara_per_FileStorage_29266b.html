Papel en el modelo de almacenamiento.

FileStorage representa un conjunto configurado de archivos con nombre, similar a un directorio. Los archivos pueden preinstalarse, crearse durante una actualización o crearse y eliminarse en tiempo de ejecución. SWS Persistency §7.4 «File Storage specific Features»

Del Storage al archivo

Después de OpenFileStorage, FileExists y GetAllFileNames verifique el inventario. OpenFileReadOnly, OpenFileWriteOnly y OpenFileReadWrite generan el descriptor de acceso exclusivo apropiado; El manejo del contenido es entonces responsabilidad de ReadAccessor, WriteAccessor o ReadWriteAccessor.

Escribir, bloquear y restablecer

Un descriptor de acceso abierto vincula el archivo exclusivamente. Por lo tanto, no planifique DeleteFile, ResetFile y RecoverFile en paralelo con el acceso activo. Los límites de recursos, así como los datos redundantes y de respaldo, cuentan para el espacio de almacenamiento utilizado. SWS Persistency §7.2.6 «Resource Management Concepts»

estrategia de fracaso

Revise cada Result, en particular los derechos de acceso, el almacenamiento físico, la integridad, el cifrado, la autenticación, el espacio en disco y la contención de recursos. Una restauración no sustituye a un control de coherencia técnica. SWS Persistency §7.2.4 «Redundancy Concepts»

Resets a file of this File Storage to its initial content. ResetFile allows to reset a single file to its initial content. If the file is currently not available in the File Storage, it is re-created. Afterwards, the file will appear in both cases as if it was newly installed from the current Target Configuration.
