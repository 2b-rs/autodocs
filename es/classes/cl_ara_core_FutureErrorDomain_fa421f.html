Define el área de errores para la traducción y el tratamiento de excepciones de errores procedentes de Future y Promise.

La clase ara::core::FutureErrorDomain representa el dominio de error central para operaciones asíncronas en Future y Promise y ofrece alias de tipo para códigos de error y excepciones [SWS_CORE_00431], [SWS_CORE_00432]. Asume a través de Message() la traducción segura para subprocesos de valores de error numéricos a mensajes de texto legibles sin retorno de puntero nulo [SWS_CORE_00443]. Siempre que las excepciones estén activadas en el compilador, permite además el lanzamiento de objetos FutureException tipados [SWS_CORE_00444].

Contexto

La clase ara::core::FutureErrorDomain constituye el área de errores específica para todas las situaciones de error que surgen durante la comunicación asíncrona y la sincronización mediante ara::core::Future y ara::core::Promise. Deriva de forma final de la clase base general ara::core::ErrorDomain y encapsula la identificación así como la traducción textual de las causas de error específicas del dominio. Para una definición estructurada, la clase proporciona el alias de tipo Errc para la enumeración FutureErrc [SWS_CORE_00431], así como el alias Exception para el tipo de excepción FutureException [SWS_CORE_00432]. Mediante esta agrupación, el dominio actúa como enlace central entre los componentes asíncronos esenciales y el modelo superior de tratamiento de errores de AUTOSAR.

Diagrama de contexto: Clasificación del dominio de error entre componentes asíncronos, códigos de error y excepciones. Fuentes: [SWS_CORE_00431], [SWS_CORE_00432], [SWS_CORE_00444]

Ciclo de vida

La inicialización se realiza a través del constructor por defecto, que está declarado como constexpr y especificado como seguro frente a excepciones y seguro para subprocesos [SWS_CORE_00441]. Esto permite una instanciación ya en tiempo de compilación o durante la fase de inicialización estática de la aplicación. Dado que los dominios de error en el ecosistema AUTOSAR Adaptive típicamente se mantienen como instancias singleton globales o estáticas de larga vida, la instancia no está sujeta a transiciones de estado dinámicas; la especificación exige una seguridad para subprocesos completa para todas las interfaces de consulta [SWS_CORE_00442], [SWS_CORE_00443].

Ruta de uso

En el flujo operativo regular, una aplicación rara vez entra en contacto directo con una instancia de FutureErrorDomain. En su lugar, se recurre al dominio cuando debe formatearse o evaluarse una instancia de ara::core::ErrorCode. En primer lugar, el método Name() identifica el dominio mediante un nombre basado en caracteres [SWS_CORE_00442]. Para el registro o el análisis de errores, Message() traduce un código de error numérico del tipo base ErrorDomain::CodeType a una cadena de caracteres legible [SWS_CORE_00443]. La interfaz garantiza que el puntero devuelto nunca sea nullptr [SWS_CORE_00443]. Si la aplicación no procesa los errores mediante códigos de retorno, sino que emplea tratamiento de excepciones, el método ThrowAsException() convierte un objeto ErrorCode pasado directamente en la correspondiente FutureException [SWS_CORE_00444].

Diagrama de secuencia: Resolución de detalles de error y lanzamiento condicional de excepciones a través del dominio de error. Fuentes: [SWS_CORE_00443], [SWS_CORE_00444]

Escenarios de error

Los fallos dentro de esta clase se limitan al reenvío explícito de errores cuando el tratamiento de excepciones está activado. Mientras que Name(), Message() y el constructor están declarados como noexcept y son completamente seguros frente a excepciones [SWS_CORE_00441], [SWS_CORE_00442], [SWS_CORE_00443], ThrowAsException() está provisto explícitamente de noexcept(false) y no es seguro frente a excepciones, ya que por diseño lanza una FutureException [SWS_CORE_00444]. Una precondición esencial concierne a la configuración de la cadena de herramientas: si las excepciones de C++ están desactivadas en el compilador, según la directiva ThrowAsException() no debe participar en la resolución de sobrecargas [SWS_CORE_00444]. Los códigos de error inválidos o no reconocidos no provocan una caída o un puntero nulo en Message(), sino que presumiblemente se asignan a textos de marcador de posición genéricos, ya que la especificación estipula una devolución garantizada distinta de nullptr [SWS_CORE_00443]. El constructor por defecto FutureErrorDomain() inicializa una instancia del dominio de errores ara::core::FutureErrorDomain de forma síncrona y sin parámetros de entrada [SWS_CORE_00441]. Dado que la función está declarada como constexpr y noexcept, ofrece una completa seguridad frente a excepciones y puede evaluarse ya en tiempo de compilación [SWS_CORE_00441].

En cuanto a la ejecución y al tratamiento de errores se aplican las siguientes condiciones:

  • La inicialización es thread-safe y no lanza excepciones [SWS_CORE_00441]. No se prevén códigos de error específicos ni mensajes a administradores de diagnóstico o de errores.
  • La instancia resultante proporciona métodos elementales del dominio, a saber, Name() para el nombre del dominio [SWS_CORE_00442], Message() para traducir códigos de error a texto legible [SWS_CORE_00443], así como ThrowAsException() para lanzar las excepciones asociadas [SWS_CORE_00444]. Dentro del ámbito de la clase existen además los alias de tipo Errc [SWS_CORE_00431] y Exception [SWS_CORE_00432].

En la estructura de interfaces, la función GetFutureErrorDomain() proporciona una referencia a la instancia global central singleton [SWS_CORE_00480]. Por lo tanto, en los casos de uso, es probable que la instanciación manual directa mediante el constructor [SWS_CORE_00441] sirva primordialmente para la provisión interna de esta instancia o para fines especiales de prueba.       La función miembro Message de la clase ara::core::FutureErrorDomain sirve para la traducción síncrona de un código de error numérico a un mensaje de texto explicativo [SWS_CORE_00443]. La función se proporciona a través del archivo de cabecera #include "ara/core/future_error_domain.h". Como parámetro de entrada acepta errorCode del tipo ErrorDomain::CodeType. El valor de retorno es un puntero a una cadena terminada en nulo (const char *) con el mensaje de texto, el cual, conforme a la especificación, nunca es nullptr [SWS_CORE_00443].
      


      Concurrencia y restricciones
      

      La función está cualificada como noexcept, así como especificada como thread-safe y exception safe [SWS_CORE_00443]. Por tanto, puede invocarse de forma segura desde hilos concurrentes sin sincronización externa. Conforme a las directrices de la clase base ara::core::ErrorDomain, el puntero devuelto permanece de forma permanente bajo la propiedad de la respectiva subclase y bajo ninguna circunstancia debe ser liberado manualmente por el llamador [SWS_CORE_00153].
      


      Tratamiento de errores e interacción
      

      Message anula el método base puramente virtual Message de la clase base abstracta ara::core::ErrorDomain [SWS_CORE_00153], de forma análoga a la implementación en otros dominios de error como ara::core::CoreErrorDomain [SWS_CORE_05243]. Si el código proporcionado no procede de este dominio, según la interfaz base esto constituye una infracción (WrongDomainOfAnErrorCodeViolation) [SWS_CORE_00153]. En escenarios de uso típicos, es probable que los desarrolladores rara vez invoquen este método directamente en el dominio, ya que habitualmente los mensajes de error se consultan a través del método Message del objeto ara::core::ErrorCode [SWS_CORE_00518].               La función miembro ara::core::FutureErrorDomain::ThrowAsException convierte de forma síncrona una instancia pasada de ErrorCode en una excepción y la lanza como FutureException [SWS_CORE_00444]. La excepción lanzada encapsula en ello el código de error pasado [SWS_CORE_00444]. Con ello, la clase implementa la interfaz puramente virtual ThrowAsException de la clase base ara::core::ErrorDomain [SWS_CORE_00154].
              

              En lo relativo a la ejecución y las condiciones de contorno, aplican las siguientes especificaciones:
              

                

              • Llamada y parámetros: la función espera como parámetro de entrada una referencia a un objeto ErrorCode (errorCode) y no tiene valor de retorno, ya que interrumpe el flujo de control mediante el lanzamiento de la excepción [SWS_CORE_00444].
                • 

              • Comportamiento frente a errores y seguridad ante excepciones: la función está declarada con noexcept(false) y clasificada como not exception safe [SWS_CORE_00444]. Al llamarla, se lanza siempre la FutureException especificada [SWS_CORE_00444].
                • 

              • Concurrencia: la implementación está clasificada como thread-safe y, por lo tanto, puede llamarse de forma segura desde contextos de ejecución paralelos [SWS_CORE_00444].
                •
