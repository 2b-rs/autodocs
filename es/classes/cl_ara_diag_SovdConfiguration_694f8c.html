Propósito de uso

SovdConfiguration implementa una interfaz de configuración genérica SOVD. RequestGetConfiguration() devuelve una sesión de lectura con SovdConfigurationMetaInfo para un ID de configuración; RequestPutConfiguration() devuelve la sesión de escritura correspondiente. [SWS_DM_01860] [SWS_DM_01870] [SWS_DM_01871] Cuando se realiza una solicitud de escritura para una configuración SOVD modelada explícitamente, el Diagnostic Server llama a RequestPutConfiguration(). [SWS_DM_01788]

Generación y ciclo de vida

La clase se crea para un PortPrototype de DiagnosticSovdConfigurationInterface con ConcurrencyType. [SWS_DM_01864] Offer() y StopOffer() controlan el reenvío de DM; Offer puede suministrar kConfigurationMismatch o kAlreadyOffered. [SWS_DM_01872] [SWS_DM_01930] La instancia no se puede copiar ni asignar mediante copia, pero sí se puede mover y asignar. [SWS_DM_01866] [SWS_DM_01868] [SWS_DM_01867] [SWS_DM_01869]

Limitaciones y Manejo de errores

Ambas solicitudes de transferencia proporcionan códigos de error SOVD aplicables si fallan; la seguridad de sus hilos está determinada por el ConcurrencyType. [SWS_DM_01870] [SWS_DM_01871] El CancellationHandler informa sobre la finalización de la conversación. [SWS_DM_01870] [SWS_DM_01871] Offer y StopOffer no son seguros para subprocesos. [SWS_DM_01872] [SWS_DM_01930]

RequestGetConfiguration y RequestPutConfiguration reciben cada uno el ID de configuración, MetaInfo y CancellationHandler. [SWS_DM_01870] [SWS_DM_01871] La sesión de lectura se combina con metainformación, la sesión de escritura con los metadatos de devolución correspondientes. [SWS_DM_01870] [SWS_DM_01871] El constructor es seguro frente a excepciones y thread-safe, el destructor es seguro frente a excepciones y no thread-safe. [SWS_DM_01864] [SWS_DM_01865]

Ambos métodos de solicitud son funciones virtuales puras y, por lo tanto, los implementa la aplicación. [SWS_DM_01870] [SWS_DM_01871] La instancia creada tiene un destructor virtual seguro para excepciones. [SWS_DM_01865]
