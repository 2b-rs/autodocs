GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 628609b2fb26 Procedencia

Sirve para la provisión y el procesamiento del lado de la aplicación de recursos de configuración SOVD modelados explícitamente.

La interfaz ara::diag::SovdConfiguration actúa como manejador genérico para configuraciones SOVD modeladas explícitamente, al cual el servidor de diagnóstico reenvía los accesos entrantes de lectura y escritura [SWS_DM_01860], [SWS_DM_01787]. Tras la instanciación basada en puertos, la aplicación activa la recepción de mensajes mediante Offer y la finaliza según sea necesario con StopOffer [SWS_DM_01872], [SWS_DM_01930]. La provisión de datos se realiza de forma asíncrona a través de sesiones de lectura o escritura, señalizándose los errores funcionales conforme a ISO 17978-3 o ASAM SOVD 1.1 [SWS_DM_01870].

Contexto

La interfaz ara::diag::SovdConfiguration define el interfaz genérico para manejadores de configuración SOVD modelados explícitamente dentro de la arquitectura de diagnóstico de Adaptive AUTOSAR [SWS_DM_01860]. Siempre que al menos una configuración SOVD esté proyectada en el sistema, la instancia del servidor de diagnóstico de Diagnostic Management (DM) pone a disposición hacia el exterior el método estandarizado de SOVD Retrieve List of All Configurations Provided by the Entity según ASAM SOVD [SWS_DM_01429]. El servidor de diagnóstico reenvía los accesos de lectura y escritura entrantes dirigidos a dicha configuración explícita a la implementación concreta de ara::diag::SovdConfiguration: al llamarse al método SOVD Read Configuration, el servidor de diagnóstico llama al método RequestGetConfiguration [SWS_DM_01787], mientras que al llamarse a Write Configuration se ejecuta el método RequestPutConfiguration [SWS_DM_01788].

Diagrama de contexto: integración de ara::diag::SovdConfiguration entre el cliente SOVD externo, el servidor de diagnóstico (DM) y el manejador específico de la aplicación. Fuentes: [SWS_DM_01429], [SWS_DM_01787], [SWS_DM_01788], [SWS_DM_01860].

Ciclo de vida

La instanciación de ara::diag::SovdConfiguration se realiza del lado de la aplicación mediante la transferencia de un ara::core::InstanceSpecifier y la especificación de un ConcurrencyType (kConcurrent o kNotConcurrent) [SWS_DM_01864]. El InstanceSpecifier hace referencia a un prototipo de puerto de un DiagnosticSovdConfigurationInterface en el contexto del proceso [SWS_DM_01864]. La clase no debe copiarse (el constructor de copia y el operador de asignación por copia están declarados como delete) [SWS_DM_01866], [SWS_DM_01868], pero admite operaciones de movimiento protegidas [SWS_DM_01867], [SWS_DM_01869]. Para aceptar solicitudes del servidor de diagnóstico, la aplicación debe llamar explícitamente a Offer [SWS_DM_01872]. Mediante la llamada a StopOffer se desactiva de nuevo el reenvío de solicitudes [SWS_DM_01930]. Al destruirse la instancia mediante el destructor virtual [SWS_DM_01865], se libera el objeto; la liberación presupone que el manejador se haya desregistrado previamente de forma debida.

Diagrama de estados: fases del ciclo de vida de una instancia de SovdConfiguration desde la inicialización pasando por el estado Offer hasta StopOffer. Fuentes: [SWS_DM_01864], [SWS_DM_01872], [SWS_DM_01930], [SWS_DM_01865].

Ruta de uso

Una ruta de uso típica se inicia tras la construcción de la clase manejadora derivada con el registro en Diagnostic Management mediante Offer() [SWS_DM_01872]. En cuanto un cliente externo dirige una solicitud de configuración SOVD a la entidad, el servidor de diagnóstico la reenvía: ante una solicitud de lectura se invoca RequestGetConfiguration, transfiriéndose la configurationId, la metaInfo y un CancellationHandler [SWS_DM_01870]. El método devuelve un ara::core::Future que proporciona de forma asíncrona una tupla compuesta por una DataTransferReadSession y SovdConfigurationMetaInfo [SWS_DM_01870]. De forma análoga, el servidor reenvía las solicitudes de escritura a través de RequestPutConfiguration, el cual proporciona un Future con una DataTransferWriteSession y SovdConfigurationMetaInfo [SWS_DM_01871]. Antes de apagar el manejador, la aplicación llama a StopOffer() para dejar de admitir solicitudes [SWS_DM_01930].

Diagrama de secuencia: secuencia típica de interacción en la inicialización, despacho de un Read-Configuration-Request y posterior desregistro. Fuentes: [SWS_DM_01872], [SWS_DM_01787], [SWS_DM_01870], [SWS_DM_01930].

Escenarios de error

Ya durante la instanciación en el constructor pueden producirse violaciones de modelo y de mapeo si el InstanceSpecifier no puede resolverse en el modelo (InstanceSpecifierMappingIntegrityViolation), el prototipo de puerto referenciado no está tipificado mediante un DiagnosticSovdConfigurationInterface (PortInterfaceMappingViolation), no existe un proceso adecuado (ProcessMappingViolation) o el identificador ya está ocupado en el proceso actual (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01864]. Al llamar a Offer(), el método devuelve un ara::core::Result<void> que en caso de error notifica DiagOfferErrc::kConfigurationMismatch si la configuración no concuerda con el modelo DEXT, o DiagOfferErrc::kAlreadyOffered si el servicio ya se está ofreciendo [SWS_DM_01872]. En los métodos asíncronos del manejador RequestGetConfiguration y RequestPutConfiguration, la aplicación notifica estados de error a través del ara::core::Future empleando códigos de error estandarizados de SOVD según ISO 17978-3 o ASAM SOVD 1.1 [SWS_DM_01870], [SWS_DM_01871]. Además, el CancellationHandler señala si una comunicación en curso ha sido cancelada [SWS_DM_01870], [SWS_DM_01871].

Esta guía se basa exclusivamente en las especificaciones de la AUTOSAR Adaptive Platform Release R25-11.

función Offer [SWS_DM_01872] Upstream: RS_Diag_04261

ara::core::Result< void > Offer () noexcept;

This Offer will enable the DM to forward request messages to this handler.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: dd8ff181c42d Procedencia

usar

El método Offer de la clase ara::diag::SovdConfiguration sirve para activar el reenvío de solicitudes de diagnóstico por parte de Diagnostic Management (DM) al manejador configurado [SWS_DM_01872]. La llamada se realiza de forma síncrona, no recibe parámetros y notifica el resultado a través de ara::core::Result<void> [SWS_DM_01872]. Mientras un manejador no haya sido proporcionado mediante Offer, el DM no reenvía ninguna solicitud entrante, lo que corresponde al patrón de provisión fundamental de las interfaces de diagnóstico (cf. [SWS_DM_01525], [SWS_DM_00809]).

Manejo de errores

En caso de error, se devuelve un ara::core::Result con un código de error de la enumeración DiagOfferErrc, aplicándose una semántica de reversión [SWS_DM_01872]:

  • DiagOfferErrc::kAlreadyOffered: se notifica si el servicio ya se había ofrecido previamente [SWS_DM_01872].
  • DiagOfferErrc::kConfigurationMismatch: ocurre cuando la configuración no coincide con los datos de descripción DEXT [SWS_DM_01872].

Concurrencia y restricciones

La operación está declarada como noexcept y es segura frente a excepciones (exception safe), pero está especificada como no segura para hilos (not thread-safe) [SWS_DM_01872]. Las llamadas simultáneas a la misma instancia desde varios hilos deben ser evitadas por la aplicación invocadora. Una nueva llamada tras un ofrecimiento ya realizado probablemente sea confirmada con un error sin cambio de estado.

  Procedencia
  

      

      

      usar
      

      El método virtual puro RequestGetConfiguration de la clase ara::diag::SovdConfiguration es invocado por la Diagnostic Server Instance cuando se ejecuta el método SOVD «Read Configuration» para una configuración SOVD modelada explícitamente ([SWS_DM_01787], AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»). Como parámetros se transfieren el ID de configuración de la instancia que se va a leer (configurationId), la metainformación de la solicitud (metaInfo), así como un cancellationHandler que informa sobre una eventual cancelación de la conversación en curso ([SWS_DM_01870]).
      

      La función trabaja de forma asíncrona y devuelve un ara::core::Future que proporciona una tupla compuesta por una sesión de lectura de archivos (DataTransferReadSession) y la metainformación de configuración asociada (SovdConfigurationMetaInfo) ([SWS_DM_01870]). La interfaz está declarada como noexcept y especificada como segura frente a excepciones ([SWS_DM_01870]).
      

      Tratamiento de errores y concurrencia
      

      Si se produce un error durante el procesamiento, no se lanza ningún error de C++, sino que a través del Future se devuelve un código de error SOVD adecuado conforme a ISO 17978-3 o ASAM SOVD 1.1 ([SWS_DM_01870]).
      

      En cuanto a la seguridad para hilos, rige la directriz «conditional»: el ConcurrencyType transferido al constructor determina si la implementación concreta de la función debe diseñarse como segura para hilos o no segura para hilos ([SWS_DM_01870]).

  Procedencia
  

          

          

          El método de API ara::diag::SovdConfiguration::RequestPutConfiguration es invocado por el Diagnostic Server cuando se debe ejecutar el método «Write Configuration» a través de la interfaz SOVD para una configuración modelada explícitamente [SWS_DM_01788], [SWS_DM_01871].
          

          Invocación y parámetros
          

          La declaración se encuentra en el encabezado ara/diag/sovd_configuration.h. La llamada transfiere los siguientes parámetros de entrada [SWS_DM_01871]:
          

            

          • configurationId: ID de la instancia de configuración que se va a escribir como ara::core::String.
            • 

          • metaInfo: metainformación sobre la solicitud entrante (MetaInfo const &).
            • 

          • cancellationHandler: supervisa el proceso actual y señaliza en caso de que la comunicación haya sido cancelada.
            • 

          

          El método posee una semántica asíncrona y devuelve un ara::core::Future que, en caso de éxito, pone a disposición una tupla formada por una sesión de escritura (DataTransferWriteSession) y los metadatos correspondientes (SovdConfigurationMetaInfo) [SWS_DM_01871].
          

          Tratamiento de errores y concurrencia
          

          En caso de error, el Future se resuelve con un código de error SOVD adecuado conforme a ISO 17978-3 o ASAM SOVD 1.1 [SWS_DM_01871]. La función está declarada como noexcept y es segura frente a excepciones (exception safe). La seguridad para hilos es condicional (conditional): el ConcurrencyType especificado en el constructor determina si la implementación concreta debe diseñarse como segura para hilos [SWS_DM_01871].
          

          Interacción
          

          La función constituye la contraparte de escritura de RequestGetConfiguration, la cual se utiliza para el método SOVD «Read Configuration» [SWS_DM_01787] (AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 «Configuration – Explicit Configurations»).
