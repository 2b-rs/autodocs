Permite esperar la finalización de una operación asíncrona sin valor de retorno, así como la extracción del estado de error.

La clase ara::core::Future<void, E> permite la sincronización asíncrona y la comprobación de errores de operaciones sin valor de retorno en AUTOSAR Adaptive [SWS_CORE_06236]. Como tipo no copiable, permite esperar a la finalización, así como la recuperación de resultados a prueba de excepciones como ara::core::Result<void, E> [SWS_CORE_06236] o el procesamiento posterior asíncrono mediante una función de continuación [SWS_CORE_06231]. Tras extraer el resultado, el estado compartido se invalida, de modo que las invocaciones posteriores sin un estado válido constituyen una infracción [SWS_CORE_06236].

Contexto

La especialización de clase plantilla ara::core::Future<void, E> representa el extremo receptor de una operación asíncrona en AUTOSAR Adaptive que, al finalizar con éxito, no devuelve ningún valor, sino que señala puramente el acaecimiento del evento o un error producido. Conforme a la descripción de la clase, la implementación debe responder a la condición E != ara::core::ErrorCode con un error de compilación. La clase interactúa típicamente con un ara::core::Promise correspondiente que llena el estado compartido (shared state) [SWS_CORE_06236], así como con contextos de ejecución asíncronos al registrar funciones de continuación [SWS_CORE_06237].

Ciclo de vida

Las instancias de ara::core::Future<void, E> son objetos puramente con semántica de movimiento: el constructor de copia [SWS_CORE_06234] y el operador de asignación por copia [SWS_CORE_06235] están eliminados (delete). Un objeto creado mediante el constructor por defecto no posee estado compartido y se comporta de manera análoga a std::future [SWS_CORE_06222]. Mediante construcción por movimiento [SWS_CORE_06223] o asignación por movimiento [SWS_CORE_06225], una instancia asume la propiedad de un shared state procedente de otra instancia.

El ciclo de vida está marcado en gran medida por la condición del shared state. Mediante el método valid() se puede comprobar si la instancia está vinculada a un shared state y, por tanto, puede utilizarse [SWS_CORE_06227]. En cuanto el resultado se recupera mediante GetResult() [SWS_CORE_06236] o get() [SWS_CORE_06226], o se registra una continuación mediante then() [SWS_CORE_06231], el objeto Future pierde su shared state y valid() devuelve false. El destructor libera cualquier estado compartido remanente [SWS_CORE_06233]. En lo relativo a la concurrencia, las operaciones de comprobación y destrucción tales como valid() [SWS_CORE_06227], is_ready() [SWS_CORE_06232] y el destructor [SWS_CORE_06233] son seguras para subprocesos (thread-safe), mientras que las operaciones que modifican el estado como GetResult() [SWS_CORE_06236], get() [SWS_CORE_06226] y las funciones de espera [SWS_CORE_06228] no son seguras para subprocesos.

Diagrama de estados: transiciones de estado y validez de ara::core::Future<void, E>. Fuentes: [SWS_CORE_06222], [SWS_CORE_06226], [SWS_CORE_06227], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06233], [SWS_CORE_06236]

Ruta de uso

En la vía de uso síncrona, un consumidor espera a que finalice la operación asíncrona. Con is_ready() se puede consultar con bajo bloqueo si se dispone de un valor o de un error [SWS_CORE_06232]. Como alternativa, se puede esperar de forma bloqueante mediante wait() [SWS_CORE_06228], o por un tiempo limitado mediante wait_for() [SWS_CORE_06229] y wait_until() [SWS_CORE_06230]. Si el resultado está disponible, la consulta del valor se realiza preferentemente a prueba de excepciones mediante GetResult(), devolviéndose un ara::core::Result<void, E> [SWS_CORE_06236].

En la vía asíncrona, el método then() permite el registro de una función de continuación (continuation), que se ejecuta tan pronto como se disponga del resultado [SWS_CORE_06231]. En este proceso puede transferirse opcionalmente un contexto de ejecución (executor) [SWS_CORE_06237]. La continuación recibe el Result<void, E> como rvalue. El tipo de retorno de then() desempaqueta automáticamente los tipos Future o Result anidados (unwrapping) [SWS_CORE_06231].

Diagrama de secuencia: flujo síncrono para la consulta de resultados a través de GetResult. Fuentes: [SWS_CORE_06227], [SWS_CORE_06228], [SWS_CORE_06232], [SWS_CORE_06236]

Escenarios de error

Si se invoca una operación dependiente del estado (como GetResult(), is_ready(), wait(), wait_for(), wait_until() o then()) sobre una instancia no válida (valid() == false), se produce una infracción de precondición que se trata como FutureInvalidViolation [SWS_CORE_06228], [SWS_CORE_06229], [SWS_CORE_06230], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06236], [SWS_CORE_06237]. Al invocar get() sobre una instancia no válida, se desencadena en su lugar una FutureException con el código de error kNoState [SWS_CORE_06226]; get() no participa en la resolución de sobrecargas cuando las excepciones C++ están desactivadas [SWS_CORE_06226].

Si la promesa correspondiente se destruyó o abandonó el estado compartido sin establecer un resultado ni un error explícito, el código de error FutureErrc::kBrokenPromise se deposita en el shared state con arreglo a [SWS_CORE_00400] [SWS_CORE_06226], [SWS_CORE_06236]. GetResult() devuelve este código como error en Result<void, E> [SWS_CORE_06236]. Si una continuación registrada en then() lanza una excepción que no implementa una infracción, esto conduce a FutureContinuationHasThrownViolation [SWS_CORE_06231], [SWS_CORE_06237].

Esta guía se basa exclusivamente en la especificación AUTOSAR para ara::core::Future<void, E> en la Release R25-11.

                  La función miembro get de la especialización ara::core::Future<void, E> sirve para esperar el resultado de una operación asíncrona sin valor de retorno ([SWS_CORE_06226]). Se comporta como la función correspondiente de std::future y bloquea al llamante hasta que el resultado o un error esté disponible ([SWS_CORE_06226], [SWS_CORE_00336]). Tras la llamada, la instancia de future pierde su validez, de modo que rige valid() == false ([SWS_CORE_06226]).
                  
  
                  La función está declarada como no segura contra excepciones (not exception safe) ([SWS_CORE_06226]). Si se registró un error en el Promise vinculado, se lanza una excepción correspondiente ([SWS_CORE_06226]). Si el estado compartido se abandonó prematuramente, se produce el código de error kBrokenPromise conforme a [SWS_CORE_00400] ([SWS_CORE_06226]). Si se ejecuta get sobre una instancia que ya no es válida, la función lanza una FutureException con el código de error kNoState ([SWS_CORE_06226]).
                  
  
                  En lo relativo a la concurrencia, el método no es seguro entre hilos (not thread-safe) ([SWS_CORE_06226]). Por lo tanto, los accesos paralelos al mismo objeto requieren sincronización externa. Además, la función no participa en la resolución de sobrecargas si las excepciones de C++ están desactivadas en la toolchain del compilador ([SWS_CORE_06226]).
                  
  
                  En interacción con funciones afines, [SWS_CORE_00332] (is_ready) garantiza que get seguro que no bloquea si la operación ya ha finalizado. Para contextos sin excepciones, AUTOSAR ofrece como alternativa [SWS_CORE_00336] (GetResult), el cual notifica los errores a través de un tipo de resultado en lugar de lanzar excepciones.

                                              La función miembro wait de la especialización ara::core::Future<void, E> bloquea el hilo llamante de forma síncrona hasta que el resultado de la operación asíncrona esté disponible en forma de un valor o de un error [SWS_CORE_06228]. La función no toma parámetros, no devuelve ningún valor de retorno (void) y, conforme a la especificación, se comporta como la función correspondiente de std::future [SWS_CORE_06228].
                                              


                                              Con respecto al tratamiento de errores y las condiciones de contorno se aplican los siguientes requisitos:
                                              

                                                

                                              • Seguridad frente a excepciones y tratamiento de errores: La operación está declarada con noexcept y especificada como segura frente a excepciones (exception safe) [SWS_CORE_06228]. Si valid() devuelve para la instancia de Future false, se produce la violación FutureInvalidViolation [SWS_CORE_06228]. Es de esperar que la consecuencia concreta de esta violación esté implementada como un tratamiento de errores específico del sistema del entorno de ejecución de AUTOSAR.
                                                • 

                                              • Concurrencia: La función está clasificada como no segura para hilos (not thread-safe) [SWS_CORE_06228]. Por tanto, no se permite el acceso concurrente al mismo objeto Future sin sincronización externa.
                                                • 

                                              


                                              En interacción con las demás funciones del módulo core existen las siguientes posibilidades:
                                              

                                                

                                              • Con el método seguro para hilos is_ready se puede consultar de antemano si la operación ha finalizado; si se devuelve true, se garantiza que wait ya no bloqueará [SWS_CORE_06232].
                                                • 

                                              • Para evitar un bloqueo indefinido están disponibles las funciones con límite de tiempo wait_for con una duración relativa [SWS_CORE_06229], así como wait_until con un punto temporal absoluto [SWS_CORE_06230].
                                                • 

                                              • Para la clase plantilla primaria ara::core::Future se aplican los mismos requisitos de espera síncrona y restricciones [SWS_CORE_00328].
