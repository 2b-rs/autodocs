GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 88e47d85a572 Procedencia

Proporciona valores de frescura para la autenticación de mensajes transmitidos y recibidos de la sincronización temporal.

La clase apext::tsync::FVM sirve como interfaz del módulo para proporcionar valores de frescura para mensajes protegidos de sincronización temporal [SWS_TS_14199]. Antes de su uso operativo, la instancia debe inicializarse, tras lo cual pueden obtenerse valores de frescura tanto para el envío como para la verificación de mensajes recibidos [SWS_TS_14200]. En la recepción, los valores de frescura truncados se transfieren junto con un contador de intentos fallidos para reconstruir el valor completo para la comprobación del autenticador. Todos los métodos de la interfaz están especificados como seguros frente a excepciones y seguros para subprocesos.

Contexto

La clase apext::tsync::FVM representa una interfaz para la gestión de valores de frescura (Freshness Value Management) dentro del módulo tsync de AUTOSAR Adaptive Platform. Su responsabilidad principal consiste en proporcionar valores de frescura (Freshness Values) actuales para el servicio de sincronización temporal ara::tsync, de modo que los mensajes puedan protegerse criptográficamente contra ataques de repetición y de suplantación (spoofing) [SWS_TS_14198], [SWS_TS_14199].

Como interlocutor central de interacción actúa la funcionalidad TimeSync, la cual invoca a la FVM para obtener contenedores de valores de frescura (apext::tsync::FVContainer) tanto para mensajes protegidos salientes como recibidos [SWS_TS_14198], [SWS_TS_14199]. La declaración de la clase se incluye a través del archivo de encabezado #include "apext/tsync/fvm.h". Todos los métodos especificados están declarados como seguros para subprocesos y seguros frente a excepciones (noexcept), de modo que las llamadas pueden tener lugar en paralelo desde diferentes contextos de ejecución de la sincronización temporal [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200].

Ciclo de vida

El ciclo de vida funcional de una instancia de FVM se divide en una fase de inicialización explícita y la posterior fase de operación:

  • Inicialización: antes de utilizar las funciones de consulta, debe invocarse el método Initialize() [SWS_TS_14200]. En caso de finalización correcta, devuelve un ara::core::Result<void> vacío. Si la inicialización falla, devuelve el código de error TsyncFvmErrc::kFVInitializeFailed con semántica de reversión (rollback) [SWS_TS_14200].
  • Estado operativo: una inicialización correcta debería ser el requisito necesario para que las solicitudes posteriores de valores de frescura proporcionen resultados válidos. Una vez completada la inicialización, la instancia permanece en estado operativo y responde a las solicitudes para los ID de valor de frescura configurados.
  • Concurrencia: dado que todos los métodos están marcados como thread-safe, los accesos a los valores de frescura para el envío y la recepción pueden realizarse de manera concurrente sin mecanismos externos de bloqueo [SWS_TS_14198], [SWS_TS_14199].

Ruta de uso

La secuencia típica de llamadas por parte del componente TimeSync comprende la inicialización, así como la determinación continua de valores de frescura para la ruta de envío y de recepción:

  1. Inicialización del servicio: TimeSync ejecuta al inicio el método Initialize() y comprueba la ausencia de errores en el ara::core::Result devuelto [SWS_TS_14200].
  2. Envío de mensajes protegidos: antes de transmitir un mensaje, TimeSync invoca GetTxFreshness() con el FreshnessValueID correspondiente [SWS_TS_14199]. El objeto FVContainer obtenido proporciona el valor de frescura que se utiliza para calcular el autenticador [SWS_TS_14199].
  3. Recepción de mensajes protegidos: a la llegada de un mensaje, TimeSync invoca GetRxFreshness() y transfiere el FreshnessValueID, el valor truncado TruncatedFreshnessValue contenido en el mensaje, así como el número de intentos de autenticación realizados hasta el momento AuthVerifyAttempts [SWS_TS_14198]. La FVM determina a partir de ello el valor de frescura completo para la verificación del autenticador [SWS_TS_14198].

Diagrama de secuencia: secuencia típica de inicialización y consulta de los valores de frescura de envío y recepción por parte de TimeSync. Fuentes: [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200]

Escenarios de error

Todos los métodos de la interfaz señalan errores mediante ara::core::Result y están especificados con noexcept [SWS_TS_14198], [SWS_TS_14199], [SWS_TS_14200]. Los siguientes estados de error y condiciones previas son relevantes:

  • Inicialización fallida (TsyncFvmErrc::kFVInitializeFailed): se produce cuando la FVM no puede inicializarse [SWS_TS_14200]. Gracias a la semántica de reversión, el sistema permanece en el estado inicial definido y no inicializado.
  • Valor de frescura no disponible (TsyncFvmErrc::kFVNotAvailable): es devuelto por GetTxFreshness() o GetRxFreshness() cuando no hay ningún valor de frescura disponible para el ID solicitado [SWS_TS_14198], [SWS_TS_14199]. Las operaciones no modifican su estado en caso de error (semántica de reversión).
  • Intentos repetidos de verificación en la recepción: el parámetro AuthVerifyAttempts comienza en 0 y se incrementa con cada intento fallido de autenticación [SWS_TS_14198]. El incremento debería servir a la FVM para adaptar gradualmente una ventana interna de aceptación, con el fin de tolerar valores de frescura ligeramente desfasados en el tiempo.

Esta guía se basa exclusivamente en los requisitos de especificación de AUTOSAR R25-11 para el módulo tsync y ha sido generada de forma automatizada.

función GetRxFreshness [SWS_TS_14198] Upstream: RS_TS_20072

ara::core::Result< FVContainer > GetRxFreshness (std::uint16_t FreshnessValueID, const FVContainer &TruncatedFreshnessValue, std::uint16_t AuthVerifyAttempts) noexcept;

Used by TimeSync to obtain the current freshness value for received messages.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 37f7da507510 Procedencia

La interfaz síncrona GetRxFreshness de la clase apext::tsync::FVM (definida en apext/tsync/fvm.h) sirve a TimeSync para determinar el valor de frescura actual para los mensajes entrantes [SWS_TS_14198].

La llamada requiere tres parámetros [SWS_TS_14198]:

  • FreshnessValueID: Identificador numérico del valor de frescura (std::uint16_t) [SWS_TS_14198].
  • TruncatedFreshnessValue: El contenedor (apext::tsync::FVContainer) con los valores de frescura truncados procedentes del mensaje protegido recibido [SWS_TS_14198].
  • AuthVerifyAttempts: Contador de intentos de autenticación para este mensaje desde su última recepción; el valor comienza en 0 para el primer intento y se incrementa con cada intento de verificación fallido [SWS_TS_14198].

La función devuelve un ara::core::Result<FVContainer> [SWS_TS_14198]. En caso de éxito, este contiene un apext::tsync::FVContainer con el valor de frescura completo que TimeSync requiere para el cálculo posterior del autenticador [SWS_TS_14198]. Si el valor de frescura no está disponible, se notifica un error recuperable con el código de error TsyncFvmErrc::kFVNotAvailable y semántica de reversión [SWS_TS_14198].

La firma está declarada con noexcept; la implementación está especificada como segura contra excepciones (exception safe) y segura para hilos (thread-safe) [SWS_TS_14198].
