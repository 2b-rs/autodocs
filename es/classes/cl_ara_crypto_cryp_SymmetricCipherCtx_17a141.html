Contexto

La interfaz ara::crypto::cryp::SymmetricCipherCtx representa la abstracción central para las operaciones criptográficas simétricas de cifrado y descifrado dentro del módulo crypto de AUTOSAR Adaptive Platform. Permite la transformación segura de textos en claro y textos cifrados mediante el uso de materiales de clave simétricos. El ciclo de vida y el manejo de instancias de este contexto se gestionan típicamente a través del alias de tipo de puntero inteligente SymmetricCipherCtx::Sptr [SWS_CRYPT_50137].

En la arquitectura de la aplicación, SymmetricCipherCtx interactúa directamente con el emisor de la llamada, así como con objetos de clave criptográfica. El material de clave se proporciona directamente como un objeto de clave en memoria SymmetricKey::Sptr o se integra indirectamente a través de una ranura de clave gestionada KeySlot::Sptr. Según el algoritmo y el modo de operación, el contexto procesa vectores de inicialización (IV) o nonces, que son pasados por la aplicación o generados por el propio contexto.

Ciclo de vida

Una instancia de SymmetricCipherCtx pasa por estados claramente definidos, que se determinan mediante la provisión de claves y el modo de procesamiento:

  • No inicializado (Uninitialized): Tras su mera creación, el contexto no dispone de material de clave vinculado. Las llamadas para el procesamiento de datos se rechazan en este estado con el error CryptoErrc::kUninitializedContext. La transición al estado operativo se realiza mediante SetKey(), configurándose opcionalmente un KeySlot [SWS_CRYPT_50043] o un SymmetricKey [SWS_CRYPT_50138].
  • Inicializado / clave configurada (Ready): El contexto está configurado con una clave. Desde este estado, se pueden ejecutar llamadas individuales sin estado (procesamiento Single-Call) o iniciar una sesión de streaming de varias etapas.
  • Streaming activo (Processing): Mediante la llamada a Start() —ya sea con un vector de inicialización explícito [SWS_CRYPT_23625] o sin él o bien con un IV propio del contexto [SWS_CRYPT_50044]— se inicia el procesamiento por streaming. En este estado, se pueden transformar datos continuamente mediante Update() [SWS_CRYPT_50139]. Además, en los modos de operación compatibles, Seek() [SWS_CRYPT_23613] permite el reposicionamiento en el flujo de datos.
  • Finalización o cancelación: La transacción de streaming en curso se finaliza de forma regular mediante Finish() [SWS_CRYPT_50045] o FinishEncrypt() [SWS_CRYPT_23618], o bien se descarta mediante Cancel() [SWS_CRYPT_50046]. Tras una finalización correcta o tras una cancelación, el contexto regresa al estado básico inicializado.

Todos los métodos de la interfaz están especificados como seguros contra excepciones (exception safe) y seguros para subprocesos (thread-safe).

Ruta de uso

La especificación admite dos rutas de ejecución principales para tareas de cifrado y descifrado: la llamada individual sin estado y el procesamiento de bloques por streaming.

En el procesamiento por llamada individual (Single-Call), todos los datos se transforman en una sola operación. Para ello, en función del manejo del IV, se dispone de tres métodos:

  • ProcessSingleCall() [SWS_CRYPT_50047] para algoritmos que no esperan ni devuelven ningún IV.
  • ProcessSingleCallWithInputIv() [SWS_CRYPT_50048], cuando el emisor de la llamada especifica explícitamente el vector de inicialización.
  • EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049], cuando se produce el cifrado y el contexto devuelve el IV generado al emisor de la llamada.

En el procesamiento por streaming, la transformación se realiza de forma incremental a través de varios bloques de búfer. Antes de comenzar, se pueden determinar los límites del búfer: GetMinimumChunkSize() [SWS_CRYPT_50144] y GetMaximumChunkSize() [SWS_CRYPT_50050] definen los tamaños de bloque mínimo y máximo. Las longitudes admisibles de IV se pueden consultar con GetMinimumInputIvSize() [SWS_CRYPT_50141], GetMaximumInputIvSize() [SWS_CRYPT_50142] así como con GetOutputIvSize() [SWS_CRYPT_50143]. El tamaño del búfer de destino necesario se calcula en función de la situación mediante GetRequiredOutputBufferSize() [SWS_CRYPT_50140].

El flujo típico se divide en:

  1. Configuración de clave mediante SetKey() [SWS_CRYPT_50138].
  2. Inicio de la sesión de streaming mediante Start() indicando la dirección (CryptoTransform) y, opcionalmente, el IV [SWS_CRYPT_23625].
  3. Transformación repetida de bloques de datos mediante Update() [SWS_CRYPT_50139].
  4. Finalización definitiva mediante Finish() [SWS_CRYPT_50045] o FinishEncrypt() [SWS_CRYPT_23618] para obtener el IV generado.

Diagrama de secuencia: flujo típico de un cifrado incremental por streaming con cálculo de búfer y provisión de IV. Fuentes: [SWS_CRYPT_50138], [SWS_CRYPT_50140], [SWS_CRYPT_23625], [SWS_CRYPT_50139], [SWS_CRYPT_50045]

Escenarios de error

Los métodos de SymmetricCipherCtx devuelven en caso de operaciones fallidas códigos de error del enum ara::crypto::CryptoErrc con semántica de rollback:

  • CryptoErrc::kUninitializedContext: se produce en Start() [SWS_CRYPT_23625] [SWS_CRYPT_50044], ProcessSingleCall() [SWS_CRYPT_50047], ProcessSingleCallWithInputIv() [SWS_CRYPT_50048], EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049] o GetRequiredOutputBufferSize() [SWS_CRYPT_50140], si previamente no se configuró ninguna clave compatible.
  • CryptoErrc::kProcessingNotStarted: se desencadena cuando se invocan métodos relacionados con el streaming como Update() [SWS_CRYPT_50139], Finish() [SWS_CRYPT_50045], FinishEncrypt() [SWS_CRYPT_23618], Seek() [SWS_CRYPT_23613] o Cancel() [SWS_CRYPT_50046], sin que previamente se haya iniciado una operación de streaming mediante Start().
  • CryptoErrc::kInsufficientCapacity: indica en Update(), Finish(), FinishEncrypt() así como en las rutinas Single-Call que el búfer de salida o de IV proporcionado es demasiado pequeño.
  • CryptoErrc::kInvalidInputSize / CryptoErrc::kInvalidArgument: indica tamaños de búfer no admisibles, desalineaciones a nivel de bloque en Seek() o datos de entrada no válidos.
  • CryptoErrc::kUsageViolation / CryptoErrc::kIncompatibleObject / CryptoErrc::kEmptyKeySlot: se produce cuando los flags de uso de clave prohíben la dirección de transformación solicitada (p. ej., falta de kAllowDataEncryption o kAllowDataDecryption), el tipo de clave es incompatible o el KeySlot referenciado está vacío.
  • CryptoErrc::kUnsupported: indica que el streaming, las operaciones de búsqueda (seek), las llamadas individuales o la configuración de IV específica no son compatibles con el contexto o algoritmo concreto.

Esta guía se basa exclusivamente en los requisitos de especificación de AUTOSAR Adaptive Release R25-11.
