Permite consultar y monitorizar múltiples eventos de diagnóstico a través de handles de evento y notificaciones por callback.

La clase permite a las aplicaciones la consulta y monitorización asociadas al estado de múltiples eventos de diagnóstico a través de una interfaz común mediante handles de eventos [SWS_DM_01705]. Además del registro de callbacks de notificación, se dispone de métodos asíncronos para determinar el estado del evento, la eliminación de rebotes, el contador de fallos y el número de DTC [SWS_DM_01707], [SWS_DM_01709]. Las instancias no son copiables ni trasladables y, debido a que el destructor no es seguro para subprocesos, requieren una finalización ordenada de las operaciones activas antes de su liberación [SWS_DM_01706], [SWS_DM_02067].

Contexto

La clase ara::diag::MultipleEvent proporciona a la aplicación interfaces para consultar y monitorizar eventos de diagnóstico a través de interfaces para eventos múltiples [SWS_DM_01705]. A diferencia de las clases de eventos individuales, las operaciones en instancias de MultipleEvent direccionan eventos concretos mediante un identificador del tipo EventHandleType [SWS_DM_01707], [SWS_DM_01708]. La clase actúa como interfaz entre el componente de software usuario y el Diagnostic Management (DM) de Adaptive AUTOSAR AUTOSAR AP SWS Diagnostics, p. 69. A través del prototipo de puerto de un DiagnosticMultipleEventInterface, el objeto se vincula a la infraestructura de diagnóstico configurada [SWS_DM_01705].

Ciclo de vida

Una instancia de MultipleEvent se crea mediante un constructor explícito indicando un ara::core::InstanceSpecifier [SWS_DM_01705]. El constructor es seguro para subprocesos y verifica la vinculación modelada a un prototipo de puerto del tipo de interfaz DiagnosticMultipleEventInterface [SWS_DM_01705]. Si falla el mapeo o se reutiliza el mismo identificador de instancia dentro del proceso, la plataforma notifica las correspondientes infracciones como InstanceSpecifierAlreadyInUseViolation o PortInterfaceMappingViolation [SWS_DM_01705].

Las operaciones de copia y movimiento están completamente inhabilitadas para MultipleEvent: tanto el constructor de copia y de movimiento como los correspondientes operadores de asignación están declarados como eliminados [SWS_DM_02067], [SWS_DM_02068], [SWS_DM_02069], [SWS_DM_02070]. El objeto posee, por tanto, una identidad estricta y permanece en su lugar de creación. El destructor ~MultipleEvent() no está especificado como seguro para subprocesos [SWS_DM_01706]. Por lo tanto, antes de la destrucción, los componentes que invocan deben asegurarse de que ya no se ejecuten consultas asíncronas o notificaciones a través de la instancia AUTOSAR AP SWS Diagnostics, p. 78.

Ruta de uso

Tras la instanciación, la aplicación registra normalmente una función callback mediante SetEventStatusChangedNotifier para ser informada sobre los cambios de estado de un evento determinado (identificado mediante EventHandleType) [SWS_DM_01708]. Una nueva invocación de este método para el mismo evento sobrescribe el notificador previamente configurado [SWS_DM_01708]. Esta función de registro no es segura para subprocesos [SWS_DM_01708].

Durante el funcionamiento normal, se puede consultar de forma específica información de diagnóstico actual por cada manejador de evento. Todas las operaciones de lectura relacionadas con el estado devuelven sus datos de forma asíncrona en un ara::core::Future:

  • GetEventStatus devuelve el byte de estado actual del evento como EventStatusByte [SWS_DM_01707].
  • GetDebouncingStatus devuelve el estado de antirrebote (DebouncingState) del evento [SWS_DM_01710].
  • GetFaultDetectionCounter proporciona el contador actual de detección de errores (FaultDetectionCounter) como un valor entero de 8 bits con signo [SWS_DM_01711].
  • GetDTCNumber consulta el número DTC asignado en el DTCFormatType solicitado [SWS_DM_01709].

La seguridad para subprocesos de estas funciones de consulta depende de la configuración [SWS_DM_01707], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].

Diagrama de secuencia: ruta de uso típica para la observación y consulta de eventos de diagnóstico a través de MultipleEvent. Fuentes: [SWS_DM_01705], [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711]

Escenarios de error

Los métodos de MultipleEvent señalan estados de error a través del tipo DiagErrc, el cual se transporta encapsulado bien en un ara::core::Result o bien en el ara::core::Future devuelto [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709]. Se especifican los siguientes casos de error:

  • DiagErrc::kInvalidArgument: se produce cuando se pasan parámetros inadmisibles, por ejemplo un EventHandleType no válido o en caso de errores internos de antirrebote como kPreFailed [SWS_DM_01707], [SWS_DM_01708], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].
  • DiagErrc::kNoSuchDTC: es notificado por GetDTCNumber cuando no hay ningún DTC correspondiente configurado o asignado para el evento de diagnóstico solicitado [SWS_DM_01709].
  • DiagErrc::kServiceNotAvailable: se produce en operaciones de lectura cuando funcionalidades básicas esenciales de Diagnostic Management no están disponibles en tiempo de ejecución [SWS_DM_01707], [SWS_DM_01709], [SWS_DM_01710], [SWS_DM_01711].

En caso de error, las operaciones garantizan una semántica de reversión [SWS_DM_01707], [SWS_DM_01709].

Esta guía se basa exclusivamente en las especificaciones de AUTOSAR Adaptive R25-11.

A consecutive call of this method will overwrite the previous registered notifier.

                              usar
                              

                              El método ara::diag::MultipleEvent::SetEventStatusChangedNotifier [SWS_DM_01708] registra una función callback de tipo EventStatusByteNotifier que se invoca cuando cambia el estado de un evento de diagnóstico. Mediante el parámetro eventHandle se identifica el evento deseado dentro de la instancia. El método está especificado como noexcept y devuelve un ara::core::Result<void>. Una nueva llamada sobrescribe el notificador registrado previamente [SWS_DM_01708].
                              


                              Manejo de errores
                              

                              Si se produce un error durante el registro, el ara::core::Result devuelve el código de error correspondiente. Está especificado el error DiagErrc::kInvalidArgument, por ejemplo en el contexto de una eliminación de rebote interna como kPreFailed [SWS_DM_01708].
                              


                              Concurrencia y restricciones
                              

                              La operación está declarada como exception safe, pero categorizada expresamente como not thread-safe [SWS_DM_01708]. Por lo tanto, las llamadas simultáneas sobre la misma instancia deben sincronizarse externamente.
                              


                              Interacción
                              

                              Mientras que la clase ara::diag::Event con SetEventStatusChangedNotifier [SWS_DM_00650] gestiona eventos individuales sin handle, MultipleEvent agrupa varios eventos. Es de suponer que el Diagnostic Management (DM), de forma análoga a [SWS_DM_01029], provoca la invocación del notificador registrado AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.7 «Event status change notifications» con cada cambio de estado del evento asignado mediante eventHandle.
