Propósito de uso

MultipleEvent consolida operaciones en múltiples eventos de diagnóstico. El estado del evento, el estado antirrebote, Fault Detection Counter y el número DTC asociado se pueden consultar a través de un EventHandleType. [SWS_DM_01704] [SWS_DM_01707] [SWS_DM_01710] [SWS_DM_01711] [SWS_DM_01709] Se puede registrar un notificador de cambio de estado por identificador de evento; un registro posterior reemplaza al anterior. [SWS_DM_01708]

Limitaciones y Manejo de errores

Los Handles de Event se asignan a partir de Events mapeados y, si falta overrideId, en orden alfabético a partir de 0x010000. [SWS_DM_01733] Los Handles que no pertenecen a esta instancia conducen a kInvalidArgument. [SWS_DM_01734] Las consultas también pueden proporcionar kNoSuchDTC o kServiceNotAvailable; su seguridad para hilos depende de ConcurrencyType. [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711] El registro de Notifier no es seguro para hilos. [SWS_DM_01708]

La consulta DTC tiene en cuenta el DTCFormatType solicitado. [SWS_DM_01709] Para un Event sin un DTC asignado puede entregar kNoSuchDTC. [SWS_DM_01709] Todas las operaciones de consulta son seguras para excepciones. [SWS_DM_01707] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711] El registro del notificador de estado puede devolver un error si los argumentos no son válidos. [SWS_DM_01708]
