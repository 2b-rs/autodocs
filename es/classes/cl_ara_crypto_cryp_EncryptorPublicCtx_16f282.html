Cifra datos de forma asimétrica en un solo paso o mediante una operación de streaming multiparte.

La interfaz sirve para el cifrado asimétrico de datos en texto plano en AUTOSAR Adaptive Platform y se gestiona mediante el puntero inteligente proporcionado [SWS_CRYPT_50174]. Tras asignar una clave pública adecuada, los mensajes pueden transformarse de forma compacta en una sola pasada o continuamente a través de una sesión de streaming multiparte [SWS_CRYPT_50090]. Para una ejecución correcta, los tamaños de los búferes deben calcularse previamente, estando todas las operaciones del contexto especificadas como seguras frente a excepciones y seguras frente a hilos.

Contexto

La clase C++ ara::crypto::cryp::EncryptorPublicCtx proporciona la interfaz estandarizada para el cifrado asimétrico de datos en AUTOSAR Adaptive Platform. Sirve a las aplicaciones cliente para cifrar datos en texto plano con ayuda de una clave pública asimétrica. La configuración de la clave criptográfica puede realizarse directamente a través de un objeto de clave ([SWS_CRYPT_50175]) o mediante una referencia a un espacio de almacenamiento de claves (KeySlot, [SWS_CRYPT_50086]). La transferencia de datos se realiza a través de áreas de búfer eficientes en memoria (ReadOnlyMemRegion para datos en texto plano y ReadWriteMemRegion para la salida del criptograma).

Ciclo de vida

Las instancias del contexto se gestionan a través del puntero compartido std::shared_ptr<EncryptorPublicCtx> definido en el alias de tipo Sptr ([SWS_CRYPT_50174]). La propia creación no forma parte de esta definición de interfaz; presumiblemente, la instanciación se realiza a través de un componente factoría de nivel superior de la arquitectura Crypto. Pregunta Q-5b7490ba113bb861 (abierta) El objeto pasa por estados claramente definidos a lo largo de su ciclo de vida:

  • No inicializado: tras la instanciación, el contexto aún no posee ninguna clave. Las operaciones de procesamiento de datos no están permitidas en este estado.
  • Configurado (Listo): al llamar a SetKey() con un PublicKey ([SWS_CRYPT_50175]) o un KeySlot ([SWS_CRYPT_50086]), el contexto queda listo para su uso. A partir de este estado, se puede ejecutar un cifrado de un solo paso o iniciar una sesión de streaming.
  • Streaming activo: la llamada a Start() ([SWS_CRYPT_50087]) pasa el contexto al estado de streaming. Los bloques continuos de datos se procesan a través de Update() ([SWS_CRYPT_50176]). La sesión se concluye con Finish() ([SWS_CRYPT_50088]) o se cancela con Cancel() ([SWS_CRYPT_50089]), con lo que el contexto regresa al estado Configurado.

Todos los métodos de la clase están especificados como seguros frente a excepciones (exception safe) y seguros frente a hilos (thread-safe). Si se destruye el contexto mientras una operación de streaming aún no ha concluido, es de suponer que la implementación subyacente limpia los búferes asignados y descarta la sesión de forma implícita. Pregunta Q-3eadc946a0bdbdfd (abierta)

Ruta de uso

La clase admite dos modos de procesamiento: el procesamiento en un solo paso para conjuntos de datos completos y el streaming de varios pasos para flujos de datos segmentados. Antes de realizar cifrados, las aplicaciones deben tener en cuenta los límites del búfer:

  • Mediante GetMinimumChunkSize()` (<a class="spec-record-ref" data-req="SWS_CRYPT_50178">[SWS_CRYPT_50178]</a>) und <code>GetMaximumChunkSize() ([SWS_CRYPT_50091]) se pueden determinar los tamaños de entrada mínimos y máximos admitidos para llamadas individuales.
  • La capacidad necesaria del búfer de salida debe consultarse previamente con GetRequiredOutputBufferSize() ([SWS_CRYPT_50177]). El parámetro isFinal controla aquí si el cálculo se realiza para pasos intermedios (false) o para llamadas finales o pasos únicos (true).

El flujo típico de un cifrado por streaming se divide en los siguientes pasos:

  1. Asignación de clave mediante SetKey() con un PublicKey válido ([SWS_CRYPT_50175]).
  2. Inicialización de la sesión de streaming mediante una llamada a Start() ([SWS_CRYPT_50087]).
  3. Cálculo del tamaño de búfer de salida requerido para bloques intermedios con GetRequiredOutputBufferSize(inputSize, false) ([SWS_CRYPT_50177]).
  4. Transformación repetida de bloques de datos mediante Update() ([SWS_CRYPT_50176]).
  5. Determinación del tamaño del búfer para el último bloque (isFinal = true) y finalización de la operación mediante Finish() ([SWS_CRYPT_50088]).

Para datos compactos que pueden procesarse en una sola pasada, Encrypt() ([SWS_CRYPT_50090]) ofrece una llamada directa de un solo paso sin división en fases Start, Update y Finish.

Escenarios de error

Todos los métodos utilizan ara::core::Result para la señalización de errores y garantizan una semántica de reversión (rollback) en caso de error:

  • Errores de estado: una llamada a Start(), Encrypt() o GetRequiredOutputBufferSize() en un contexto no inicializado da lugar a ara::crypto::CryptoErrc::kUninitializedContext ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50177]). Si se llama a Update(), Finish() o Cancel() sin haber ejecutado previamente Start(), la operación falla con ara::crypto::CryptoErrc::kProcessingNotStarted ([SWS_CRYPT_50176], [SWS_CRYPT_50088], [SWS_CRYPT_50089]).
  • Errores de clave y de uso: si la clave o el KeySlot proporcionados son incompatibles con el contexto, se notifica ara::crypto::CryptoErrc::kIncompatibleObject ([SWS_CRYPT_50175], [SWS_CRYPT_50086], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Si el uso permitido de la clave no contiene el permiso kAllowDataEncryption, esto genera ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_50175], [SWS_CRYPT_50087], [SWS_CRYPT_50090]). Si un KeySlot referenciado está vacío, se notifica ara::crypto::CryptoErrc::kEmptyKeySlot ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).
  • Errores de búfer y de datos: si el búfer de salida proporcionado tiene una capacidad insuficiente, Encrypt(), Update() y Finish() responden con ara::crypto::CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). Las discrepancias respecto a los tamaños de fragmento permitidos dan lugar a ara::crypto::CryptoErrc::kInvalidInputSize, y los datos de entrada no válidos, a ara::crypto::CryptoErrc::kInvalidArgument.
  • Funciones no admitidas y escasez de recursos: si la implementación no admite streaming o una llamada de un solo paso, la operación falla con ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_50087], [SWS_CRYPT_50090], [SWS_CRYPT_50176], [SWS_CRYPT_50088]). En caso de recursos criptográficos bloqueados, se devuelve ara::crypto::CryptoErrc::kBusyResource ([SWS_CRYPT_50087], [SWS_CRYPT_50090]).

Esta guía se basa en los requisitos de la versión R25-11 de AUTOSAR Adaptive Platform y resume la especificación de la clase ara::crypto::cryp::EncryptorPublicCtx.

Tratamiento de errores y concurrencia

Si el procesamiento de datos no se inició previamente mediante Start(), la operación falla con el código de error ara::crypto::CryptoErrc::kProcessingNotStarted manteniendo la semántica de reversión (rollback) [SWS_CRYPT_50089]. Interacción en la pila criptográfica

El comportamiento de cancelación implementado mediante Cancel() sigue un patrón de diseño uniforme para operaciones de streaming con estado en el módulo criptográfico. Existen interfaces análogas con idéntica semántica de error para:

  • descifrado asimétrico en DecryptorPrivateCtx [SWS_CRYPT_50069],
  • códigos de autenticación de mensajes en MessageAuthnCodeCtx [SWS_CRYPT_50027], así como cálculos de hash en HashFunctionCtx [SWS_CRYPT_50058].

La llamada se realiza de forma síncrona y está especificada como noexcept, exception-safe y thread-safe. Como parámetro, la función toma a través de in (ReadOnlyMemRegion) el fragmento de texto plano final y escribe los datos resultantes del criptograma en el búfer de salida out (ReadWriteMemRegion).             •

            •
