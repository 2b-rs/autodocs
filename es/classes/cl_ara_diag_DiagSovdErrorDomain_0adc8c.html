Define el dominio de error para la identificación, traducción de texto y tratamiento de excepciones de errores procedentes de SOVD.

La clase ara::diag::DiagSovdErrorDomain encapsula el dominio de error estandarizado para errores de diagnóstico específicos de SOVD dentro de AUTOSAR Adaptive Platform ([SWS_DM_01809]). A través de sus funciones miembro seguras para subprocesos, permite la traducción fiable de códigos de error numéricos a mensajes de texto, así como el lanzamiento controlado de los tipos de excepción de C++ apropiados ([SWS_DM_01814]). Si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador, el método para lanzar excepciones no participa reglamentariamente en la resolución de sobrecargas.

Contexto

La clase ara::diag::DiagSovdErrorDomain representa el dominio de error específico para los estados de error resultantes del subsistema SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01809], AUTOSAR_AP_SWS_Diagnostics §8.51.3 «Class: DiagSovdErrorDomain»). Como especialización final de la clase de infraestructura base ara::core::ErrorDomain, integra los códigos de error y el tratamiento de excepciones asociado del contexto SOVD a la perfección en el modelo de errores uniforme de AUTOSAR Adaptive Platform ([SWS_DM_01809]).

Para una identificación estandarizada, la función miembro Name() proporciona el nombre corto (ApApplicationErrorDomain.SN) del dominio de error conforme a [SWS_CORE_90023] ([SWS_DM_01813], AUTOSAR_AP_SWS_Diagnostics §8.51.3 «Class: DiagSovdErrorDomain»). Además, la clase define dos alias de tipo centrales para su espacio de nombres: Errc actúa como alias para la enumeración subyacente DiagSovdErrc ([SWS_DM_01810], AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.1 «Type Alias: Errc») y Exception representa la clase de excepción base asociada DiagSovdException ([SWS_DM_01811], AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.2 «Type Alias: Exception»). En la práctica, el acceso al dominio se realiza mayoritariamente a través de la función libre ara::diag::GetDiagSovdErrorDomain ([SWS_DM_01816], AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 «GetDiagSovdErrorDomain»).

Ciclo de vida

La instanciación de ara::diag::DiagSovdErrorDomain se realiza a través del constructor por defecto sin parámetros constexpr DiagSovdErrorDomain() noexcept ([SWS_DM_01812], AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.1.1 «Default Constructor»). Gracias a la especificación como constexpr y noexcept, la creación es garantizadamente segura frente a excepciones y puede llevarse a cabo ya en tiempo de compilación o durante la inicialización estática. Interpretación: La provisión del constructor constexpr debería permitir a la plataforma mantener una instancia singleton de larga duración que se referencia a través de GetDiagSovdErrorDomain ([SWS_DM_01816]).

En lo que respecta a la concurrencia, todas las funciones miembro de la clase están declaradas explícitamente como seguras para subprocesos («thread-safe»). Esto se aplica tanto al constructor ([SWS_DM_01812]) como a las operaciones de lectura Name() ([SWS_DM_01813]) y Message() ([SWS_DM_01814]), así como al lanzamiento de excepciones a través de ThrowAsException() ([SWS_DM_01815]). De este modo, varios subprocesos pueden operar en paralelo y sin mecanismos de sincronización externos sobre la misma instancia de dominio.

Ruta de uso

El flujo regular para el uso de ara::diag::DiagSovdErrorDomain se divide en los siguientes pasos:

  • Obtención del dominio: Las entidades invocadoras obtienen una referencia al dominio de error típicamente a través de la función global ara::diag::GetDiagSovdErrorDomain ([SWS_DM_01816], AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 «GetDiagSovdErrorDomain») o crean una instancia propia según sea necesario a través del constructor por defecto ([SWS_DM_01812]).
  • Consulta del mensaje de error: Para traducir un código de error numérico de tipo ara::core::ErrorDomain::CodeType (correspondiente a Errc conforme a [SWS_DM_01810]) a texto legible, se invoca Message(errorCode) ([SWS_DM_01814], AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.2.1 «Message»). La función devuelve un puntero constante a una cadena de caracteres (const char*) que garantiza no ser nunca nullptr ([SWS_DM_01814]). Interpretación: Las cadenas de caracteres resultantes deberían ser literales estáticos, ya que la función está clasificada como noexcept.
  • Tratamiento de excepciones: Si, alternativamente, un estado de error debe propagarse mediante excepciones de C++, la aplicación pasa la instancia de ara::core::ErrorCode a ThrowAsException(errorCode) ([SWS_DM_01815]), lo que lanza una excepción del tipo correspondiente Exception (DiagSovdException) ([SWS_DM_01811]).

Diagrama de secuencia: Secuencia típica de interacción para la resolución de descripciones de error y el lanzamiento opcional de excepciones a través del dominio de error. Fuentes: [SWS_DM_01814], [SWS_DM_01815], [SWS_DM_01816].

Escenarios de error

En el marco del tratamiento de errores, la interfaz de ara::diag::DiagSovdErrorDomain presenta características de comportamiento específicas:

  • Retorno de texto garantizado: El método Message está declarado como noexcept y es completamente seguro frente a excepciones («exception safe») ([SWS_DM_01814]). Nunca falla y siempre devuelve una cadena de caracteres válida y no vacía ([SWS_DM_01814]).
  • Lanzamiento deliberado de excepciones: El método ThrowAsException está destinado a lanzar excepciones y, por lo tanto, cuenta con noexcept(false) así como con la clasificación «not exception safe» ([SWS_DM_01815]). Lanza la excepción correspondiente de tipo Exception (DiagSovdException) en función del ara::core::ErrorCode suministrado ([SWS_DM_01811], [SWS_DM_01815]).
  • Excepciones de C++ desactivadas: Conforme a [SWS_CORE_10304], ThrowAsException no participa en la resolución de sobrecargas si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador ([SWS_DM_01815]). En tales entornos, la función no está disponible y los errores deben evaluarse obligatoriamente mediante códigos de error.

Esta guía se basa exclusivamente en las directrices de especificación del módulo diag de AUTOSAR (Release R25-11).

Interacción y contexto de llamada

En escenarios de aplicación típicos, es probable que rara vez se requiera una instanciación manual directa mediante este constructor, ya que la interfaz funcional ara::diag::GetDiagSovdErrorDomain() ya proporciona una referencia a la instancia global del dominio de error [SWS_DM_01816].

La clase DiagSovdErrorDomain define el rango de error para SOVD y proporciona tipos y funciones esenciales:

  • Alias de tipos para códigos de error Errc [SWS_DM_01810] y tratamiento de excepciones Exception [SWS_DM_01811].
  • Creación de instancias de código de error a través de MakeErrorCode() [SWS_DM_01817].
  • Consulta de nombres a través de Name() [SWS_DM_01813] y traducción de texto mediante Message() [SWS_DM_01814], así como activación de excepciones a través de ThrowAsException() [SWS_DM_01815].

Tratamiento de errores y concurrencia

Como función noexcept sin parámetros, el constructor no lanza excepciones. Según la especificación, la llamada es segura frente a excepciones («exception safe») y concurrentemente segura para subprocesos («thread-safe») [SWS_DM_01812]. No se han definido precondiciones ni códigos de error específicos para el constructor.

              El método ThrowAsException de la clase ara::diag::DiagSovdErrorDomain ([SWS_DM_01815], declarado en la cabecera ara/diag/diag_sovd_error_domain.h; véase AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.2.3 «ThrowAsException») sirve para convertir de forma síncrona un código de error en el tipo de excepción de C++ asignado. Acepta el parámetro de entrada errorCode de tipo const ara::core::ErrorCode & y no posee valor de retorno (void). Al invocarse, lanza la excepción correspondiente al código de error de acuerdo con la signatura con noexcept(false).
              


              Tratamiento de errores y condiciones límite
              

              La especificación clasifica el método como «not exception safe» ([SWS_DM_01815]). Interpretación: Es probable que esta clasificación se justifique por el hecho de que, mediante el lanzamiento intencionado de una excepción, se abandona el flujo de control regular. Una condición de contorno fundamental afecta a la cadena de herramientas del compilador: según [SWS_CORE_10304], ThrowAsException no participa en la resolución de sobrecarga si las excepciones de C++ están deshabilitadas en el compilador.
              


              Concurrencia e interacción
              

              La función está clasificada como segura para subprocesos (thread-safe) ([SWS_DM_01815]) y permite la invocación concurrente. El comportamiento sigue el esquema estandarizado para dominios de error de diagnóstico en el módulo DM. Definiciones análogas aplican a ara::diag::DiagErrorDomain ([SWS_DM_00523], véase AUTOSAR_AP_SWS_Diagnostics §8.11.3.2.2.3 «ThrowAsException»), ara::diag::DiagOfferErrorDomain ([SWS_DM_00995], véase AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.3 «ThrowAsException»), ara::diag::DiagReportingErrorDomain ([SWS_DM_01002], véase AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.3 «ThrowAsException») así como a ara::diag::DiagUdsNrcErrorDomain ([SWS_DM_00535], véase AUTOSAR_AP_SWS_Diagnostics §8.12.3.2.2.3 «ThrowAsException»).
