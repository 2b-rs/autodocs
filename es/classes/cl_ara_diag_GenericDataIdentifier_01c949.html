Contexto

La clase ara::diag::GenericDataIdentifier define la interfaz genérica para el procesamiento de identificadores de datos (DID) dentro del clúster funcional Diagnostics de AUTOSAR Adaptive (diag). A diferencia de las interfaces DID con tipado específico, la variante genérica desacopla el procesamiento de datos de esquemas fijos: el identificador de 16 bits correspondiente se transmite dinámicamente a las rutinas de procesamiento en tiempo de ejecución [SWS_DM_00636], [SWS_DM_00637].

En la interacción participan esencialmente tres partes:

  • Diagnostic Management (DM): el sistema central de diagnóstico recibe solicitudes de servicio UDS externas (como ReadDataByIdentifier o WriteDataByIdentifier de conformidad con la norma ISO 14229-1) y las reenvía a las instancias de handler registradas [SWS_DM_00636], [SWS_DM_00637], [SWS_DM_00638].
  • Handler específico de la aplicación: una aplicación adaptativa deriva una clase de ara::diag::GenericDataIdentifier, implementa el método de lectura puramente virtual Read [SWS_DM_00636] y sobrescribe el método de escritura Write [SWS_DM_00637] si es necesario.
  • Puerto modelado: la conexión se realiza a través de un ara::core::InstanceSpecifier que hace referencia a un PortPrototype de una DiagnosticDataIdentifierGenericInterface definido en el manifiesto [SWS_DM_00634].

Ciclo de vida

La creación se realiza de forma explícita a través del constructor parametrizado, indicando el InstanceSpecifier y el modelo de concurrencia (DataIdentifierConcurrencyType) [SWS_DM_00634]. Una instancia de ara::diag::GenericDataIdentifier está estrictamente vinculada a su identidad modelada y no se puede copiar ni mover; los constructores y operadores de asignación correspondientes están eliminados [SWS_DM_01651], [SWS_DM_01652], [SWS_DM_01653], [SWS_DM_01654].

Tras la construcción, el objeto se encuentra en estado inactivo. Mediante la llamada a Offer() se activa el reenvío de solicitudes por parte de Diagnostic Management [SWS_DM_00638]. A través de StopOffer(), este reenvío se puede volver a desactivar en cualquier momento [SWS_DM_00639]. Interpretación: antes de la destrucción del objeto a través del destructor virtual [SWS_DM_00635], en la práctica debería realizarse siempre una llamada a StopOffer() para impedir de forma controlada las solicitudes de DM pendientes antes de desmantelar el handler.

En lo relativo a la concurrencia, los métodos de ciclo de vida Offer(), StopOffer() y el destructor están clasificados como no seguros para subprocesos [SWS_DM_00635], [SWS_DM_00638], [SWS_DM_00639]; deben llamarse de forma sincronizada desde el contexto de la aplicación. Por el contrario, la seguridad para subprocesos de los métodos de procesamiento Read y Write es condicional y se rige por el concurrencyType seleccionado en el constructor (kConcurrent o kNotConcurrent) [SWS_DM_00634], [SWS_DM_00636], [SWS_DM_00637].

Diagrama de estados: fases del ciclo de vida y transiciones de estado de GenericDataIdentifier. Fuentes: [SWS_DM_00634], [SWS_DM_00635], [SWS_DM_00638], [SWS_DM_00639]

Ruta de uso

Un flujo de uso típico comprende la puesta a disposición, la respuesta asíncrona a solicitudes de lectura y escritura, así como la desactivación final:

  1. Instanciación: la aplicación instancia la clase de handler derivada con el InstanceSpecifier deseado y el tipo de concurrencia [SWS_DM_00634].
  2. Ofrecer servicio: el handler llama a Offer() y comprueba que el ara::core::Result<void> devuelto no contenga errores [SWS_DM_00638].
  3. Procesamiento de solicitudes:
    • Si llega una solicitud de lectura, el DM llama al método Read(dataIdentifier, metaInfo, cancellationHandler) [SWS_DM_00636]. El método devuelve un ara::core::Future<OperationOutput>. Mediante el CancellationHandler se puede comprobar si la sesión se ha cancelado (IsCanceled()) o se puede registrar una devolución de llamada de notificación (SetNotifier) [SWS_DM_00636].
    • En el caso de solicitudes de escritura, el DM llama a Write(dataIdentifier, requestData, metaInfo, cancellationHandler) [SWS_DM_00637]. El ara::core::Span<const std::uint8_t> transmitido permanece válido hasta que se cumpla la promesa asociada o se cancele la operación [SWS_DM_00637]. La devolución se realiza a través de un ara::core::Future<void>.
  4. Finalizar servicio: antes del apagado, la aplicación llama a StopOffer() para suspender el reenvío de solicitudes adicionales [SWS_DM_00639].

Diagrama de secuencia: secuencia típica de interacción durante la puesta a disposición y la tramitación de solicitudes. Fuentes: [SWS_DM_00636], [SWS_DM_00637], [SWS_DM_00638], [SWS_DM_00639]

Escenarios de error

Pueden producirse errores durante la validación de la configuración, al registrar el servicio y durante el procesamiento continuo de solicitudes:

  • Infracciones de construcción (Violations):
    • InstanceSpecifierMappingIntegrityViolation: el identificador no se puede resolver en el contexto de modelo del ejecutable o no hace referencia a ningún PortPrototype [SWS_DM_00634].
    • PortInterfaceMappingViolation: Al Port tipificado por DiagnosticDataIdentifierGenericInterface (DEM) le falta la asignación en un DiagnosticDataPortMapping [SWS_DM_00634].
    • ProcessMappingViolation: no existe ningún proceso modelado coincidente para la InstanceRef en tiempo de ejecución [SWS_DM_00634].
    • InstanceSpecifierAlreadyInUseViolation: el InstanceSpecifier especificado ya está siendo utilizado por otra instancia dentro del proceso [SWS_DM_00634].
  • Error en Offer: si se llama a Offer() mientras el servicio ya está ofrecido activamente, el método devuelve el código de error DiagOfferErrc::kAlreadyOffered (semántica de rollback) [SWS_DM_00638].
  • Respuestas negativas de UDS (NRC): si falla el procesamiento dentro de Read o Write (p. ej., dataIdentifier desconocido o datos útiles inadmisibles), el handler completa el Future con un código de respuesta negativa de UDS (NRC) correspondiente de conformidad con la norma ISO 14229-1 a través de DiagUdsNrcErrc [SWS_DM_00636], [SWS_DM_00637].
  • Tratamiento de cancelaciones: si se cancela una conversación de diagnóstico en curso, Diagnostic Management lo señaliza a través del CancellationHandler, de modo que los cálculos en curso puedan finalizarse anticipadamente [SWS_DM_00636], [SWS_DM_00637].

<h4>Contexto</h4>
<p>La clase <code>ara::diag::GenericDataIdentifier</code> define la interfaz genérica para el procesamiento de identificadores de datos (DID) dentro del clúster funcional Diagnostics de AUTOSAR Adaptive (<code>diag</code>). A diferencia de las interfaces DID con tipado específico, la variante genérica desacopla el procesamiento de datos de esquemas fijos: el identificador de 16 bits correspondiente se transmite dinámicamente a las rutinas de procesamiento en tiempo de ejecución <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>, <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>.</p>
<p>En la interacción participan esencialmente tres partes:</p>
<ul>
<li><strong>Diagnostic Management (DM):</strong> el sistema central de diagnóstico recibe solicitudes de servicio UDS externas (como <em>ReadDataByIdentifier</em> o <em>WriteDataByIdentifier</em> de conformidad con la norma ISO 14229-1) y las reenvía a las instancias de handler registradas <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>, <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>, <a class="spec-record-ref" data-req="SWS_DM_00638" href="../spec/record.html?id=SWS_DM_00638">[SWS_DM_00638]</a>.</li>
<li><strong>Handler específico de la aplicación:</strong> una aplicación adaptativa deriva una clase de <code>ara::diag::GenericDataIdentifier</code>, implementa el método de lectura puramente virtual <code>Read</code> <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a> y sobrescribe el método de escritura <code>Write</code> <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a> si es necesario.</li>
<li><strong>Puerto modelado:</strong> la conexión se realiza a través de un <code>ara::core::InstanceSpecifier</code> que hace referencia a un <code>PortPrototype</code> de una <code>DiagnosticDataIdentifierGenericInterface</code> definido en el manifiesto <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
</ul>

<h4>Ciclo de vida</h4>
<p>La creación se realiza de forma explícita a través del constructor parametrizado, indicando el <code>InstanceSpecifier</code> y el modelo de concurrencia (<code>DataIdentifierConcurrencyType</code>) <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>. Una instancia de <code>ara::diag::GenericDataIdentifier</code> está estrictamente vinculada a su identidad modelada y no se puede copiar ni mover; los constructores y operadores de asignación correspondientes están eliminados <a class="spec-record-ref" data-req="SWS_DM_01651" href="../spec/record.html?id=SWS_DM_01651">[SWS_DM_01651]</a>, <a class="spec-record-ref" data-req="SWS_DM_01652" href="../spec/record.html?id=SWS_DM_01652">[SWS_DM_01652]</a>, <a class="spec-record-ref" data-req="SWS_DM_01653" href="../spec/record.html?id=SWS_DM_01653">[SWS_DM_01653]</a>, <a class="spec-record-ref" data-req="SWS_DM_01654" href="../spec/record.html?id=SWS_DM_01654">[SWS_DM_01654]</a>.</p>
<p>Tras la construcción, el objeto se encuentra en estado inactivo. Mediante la llamada a <code>Offer()</code> se activa el reenvío de solicitudes por parte de Diagnostic Management <a class="spec-record-ref" data-req="SWS_DM_00638" href="../spec/record.html?id=SWS_DM_00638">[SWS_DM_00638]</a>. A través de <code>StopOffer()</code>, este reenvío se puede volver a desactivar en cualquier momento <a class="spec-record-ref" data-req="SWS_DM_00639" href="../spec/record.html?id=SWS_DM_00639">[SWS_DM_00639]</a>. Interpretación: antes de la destrucción del objeto a través del destructor virtual <a class="spec-record-ref" data-req="SWS_DM_00635" href="../spec/record.html?id=SWS_DM_00635">[SWS_DM_00635]</a>, en la práctica debería realizarse siempre una llamada a <code>StopOffer()</code> para impedir de forma controlada las solicitudes de DM pendientes antes de desmantelar el handler.</p>
<p>En lo relativo a la concurrencia, los métodos de ciclo de vida <code>Offer()</code>, <code>StopOffer()</code> y el destructor están clasificados como no seguros para subprocesos <a class="spec-record-ref" data-req="SWS_DM_00635" href="../spec/record.html?id=SWS_DM_00635">[SWS_DM_00635]</a>, <a class="spec-record-ref" data-req="SWS_DM_00638" href="../spec/record.html?id=SWS_DM_00638">[SWS_DM_00638]</a>, <a class="spec-record-ref" data-req="SWS_DM_00639" href="../spec/record.html?id=SWS_DM_00639">[SWS_DM_00639]</a>; deben llamarse de forma sincronizada desde el contexto de la aplicación. Por el contrario, la seguridad para subprocesos de los métodos de procesamiento <code>Read</code> y <code>Write</code> es condicional y se rige por el <code>concurrencyType</code> seleccionado en el constructor (<code>kConcurrent</code> o <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>, <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>, <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>.</p>

<h4>Ruta de uso</h4>
<p>Un flujo de uso típico comprende la puesta a disposición, la respuesta asíncrona a solicitudes de lectura y escritura, así como la desactivación final:</p>
<ol>
<li><strong>Instanciación:</strong> la aplicación instancia la clase de handler derivada con el <code>InstanceSpecifier</code> deseado y el tipo de concurrencia <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
<li><strong>Ofrecer servicio:</strong> el handler llama a <code>Offer()</code> y comprueba que el <code>ara::core::Result&lt;void&gt;</code> devuelto no contenga errores <a class="spec-record-ref" data-req="SWS_DM_00638" href="../spec/record.html?id=SWS_DM_00638">[SWS_DM_00638]</a>.</li>
<li><strong>Procesamiento de solicitudes:</strong>
<ul>
<li>Si llega una solicitud de lectura, el DM llama al método <code>Read(dataIdentifier, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>. El método devuelve un <code>ara::core::Future&lt;OperationOutput&gt;</code>. Mediante el <code>CancellationHandler</code> se puede comprobar si la sesión se ha cancelado (<code>IsCanceled()</code>) o se puede registrar una devolución de llamada de notificación (<code>SetNotifier</code>) <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>.</li>
<li>En el caso de solicitudes de escritura, el DM llama a <code>Write(dataIdentifier, requestData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>. La devolución se realiza a través de un <code>ara::core::Future&lt;void&gt;</code>.</li>
</ul>
</li>
<li><strong>Finalizar servicio:</strong> antes del apagado, la aplicación llama a <code>StopOffer()</code> para suspender el reenvío de solicitudes adicionales <a class="spec-record-ref" data-req="SWS_DM_00639" href="../spec/record.html?id=SWS_DM_00639">[SWS_DM_00639]</a>.</li>
</ol>

<h4>Escenarios de error</h4>
<p>Pueden producirse errores durante la validación de la configuración, al registrar el servicio y durante el procesamiento continuo de solicitudes:</p>
<ul>
<li><strong>Infracciones de construcción (Violations):</strong>
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: el identificador no se puede resolver en el contexto de modelo del ejecutable o no hace referencia a ningún <code>PortPrototype</code> <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
<li><code>PortInterfaceMappingViolation</code>: Al Port tipificado por <code>DiagnosticDataIdentifierGenericInterface</code> (DEM) le falta la asignación en un <code>DiagnosticDataPortMapping</code> <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
<li><code>ProcessMappingViolation</code>: no existe ningún proceso modelado coincidente para la <code>InstanceRef</code> en tiempo de ejecución <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: el <code>InstanceSpecifier</code> especificado ya está siendo utilizado por otra instancia dentro del proceso <a class="spec-record-ref" data-req="SWS_DM_00634" href="../spec/record.html?id=SWS_DM_00634">[SWS_DM_00634]</a>.</li>
</ul>
</li>
<li><strong>Error en Offer:</strong> si se llama a <code>Offer()</code> mientras el servicio ya está ofrecido activamente, el método devuelve el código de error <code>DiagOfferErrc::kAlreadyOffered</code> (semántica de rollback) <a class="spec-record-ref" data-req="SWS_DM_00638" href="../spec/record.html?id=SWS_DM_00638">[SWS_DM_00638]</a>.</li>
<li><strong>Respuestas negativas de UDS (NRC):</strong> si falla el procesamiento dentro de <code>Read</code> o <code>Write</code> (p. ej., <code>dataIdentifier</code> desconocido o datos útiles inadmisibles), el handler completa el <code>Future</code> con un código de respuesta negativa de UDS (NRC) correspondiente de conformidad con la norma ISO 14229-1 a través de <code>DiagUdsNrcErrc</code> <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>, <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>.</li>
<li><strong>Tratamiento de cancelaciones:</strong> si se cancela una conversación de diagnóstico en curso, Diagnostic Management lo señaliza a través del <code>CancellationHandler</code>, de modo que los cálculos en curso puedan finalizarse anticipadamente <a class="spec-record-ref" data-req="SWS_DM_00636" href="../spec/record.html?id=SWS_DM_00636">[SWS_DM_00636]</a>, <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>.</li>
</ul>
