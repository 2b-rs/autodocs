Encapsula o bien un valor de éxito o bien un valor de error para la transmisión síncrona de resultados sin excepciones.

La clase representa un contenedor con seguridad de tipos que aloja o bien un valor útil o bien un código de error, con el fin de transmitir resultados de cálculo de forma síncrona y sin excepciones de C++ [SWS_CORE_00751]. Los llamadores crean instancias mediante constructores dedicados o funciones factoría y, a continuación, evalúan el resultado en función del estado mediante funciones de comprobación y acceso, tales como el acceso al valor o al error. Como restricción fundamental, el tipo de error subyacente debe corresponder obligatoriamente al código de error estándar, ya que las asignaciones de tipos discrepantes se rechazan en tiempo de compilación. Además, las funciones para el desencadenamiento de excepciones requieren un entorno de compilador con excepciones de C++ habilitadas [SWS_CORE_00766].

Contexto

La clase ara::core::Result es la construcción central de AUTOSAR Adaptive Platform para la devolución síncrona y tipificada de resultados de operaciones sin el uso obligatorio de excepciones de C++. Representa una unión etiquetada (Tagged Union) que en cualquier momento contiene o bien un valor útil del tipo value_type (T) o bien un error del tipo error_type (E) [SWS_CORE_00711] [SWS_CORE_00712]. Por defecto, ara::core::ErrorCode actúa como tipo para E; las implementaciones impiden definiciones de error discrepantes ya en tiempo de compilación mediante un error de compilación.

En la arquitectura de la aplicación, ara::core::Result media entre los servicios invocados y los consumidores. Los servicios instancian el objeto para devolver el estado, mientras que los consumidores inician un procesamiento posterior mediante pruebas de estado como [SWS_CORE_00751] o encadenamientos funcionales como [SWS_CORE_00768]. Además, el estado se puede transferir a ara::core::Optional mediante [SWS_CORE_00770] (Ok) y [SWS_CORE_00772] (Err).

Ciclo de vida

La inicialización de una instancia se realiza o bien directamente a través de constructores para valores ([SWS_CORE_00721], [SWS_CORE_00722]) o bien explícitamente para errores ([SWS_CORE_00723], [SWS_CORE_00724]). De forma complementaria, están disponibles funciones factoría estáticas: FromValue para lvalues, rvalues y argumentos in-place ([SWS_CORE_00731], [SWS_CORE_00732], [SWS_CORE_00733]), así como FromError para la creación de estados de error ([SWS_CORE_00734], [SWS_CORE_00735], [SWS_CORE_00736]).

ara::core::Result posee el dato contenido de forma exclusiva y gestiona su vida útil. Soporta semántica de valor completa mediante constructores de copia y movimiento ([SWS_CORE_00725], [SWS_CORE_00726]), así como los correspondientes operadores de asignación ([SWS_CORE_00741], [SWS_CORE_00742]). Un cambio de contenido de instancias existentes es posible mediante Swap [SWS_CORE_00745] o por sobrescritura in-place a través de EmplaceValue [SWS_CORE_00743] o bien EmplaceError [SWS_CORE_00744].

El destructor libera el elemento activo y se considera trivialmente destructible si tanto T como E son trivialmente destructibles [SWS_CORE_00727]. En cuanto a la concurrencia, los accesos puramente de lectura son seguros para hilos, mientras que las operaciones modificadoras como EmplaceValue, EmplaceError, asignaciones por movimiento o Swap no son seguras para hilos y requieren sincronización externa.

Diagrama de estados: transiciones de estado entre el estado de valor y el de error durante la vida útil de una instancia de Result. Fuentes: [SWS_CORE_00721], [SWS_CORE_00723], [SWS_CORE_00743], [SWS_CORE_00744], [SWS_CORE_00727]

Ruta de uso

El flujo regular incluye la creación, validación y extracción del resultado:

  1. Suministro: un servicio crea el resultado mediante [SWS_CORE_00731] o [SWS_CORE_00734] y devuelve la instancia por valor.
  2. Comprobación de estado: el llamador comprueba mediante HasValue() [SWS_CORE_00751] o el operador de conversión explícito operator bool() [SWS_CORE_00752] si hay un valor presente. Este último está deshabilitado si T es en sí mismo del tipo bool.
  3. Acceso a valor y error: si hay un valor presente, este se puede leer mediante Value() ([SWS_CORE_00755], [SWS_CORE_00756], [SWS_CORE_00775]) o los operadores operator* ([SWS_CORE_00753], [SWS_CORE_00759]) y operator-> ([SWS_CORE_00754], [SWS_CORE_00777]). En caso de error, el acceso se realiza mediante Error() ([SWS_CORE_00757], [SWS_CORE_00758], [SWS_CORE_00776]) o la comprobación específica de error con CheckError() [SWS_CORE_00765].
  4. Transformación funcional: como alternativa, Bind() [SWS_CORE_00768] permite un procesamiento posterior monádico: el invocable pasado solo se ejecuta si se contiene un valor útil; un error existente se propaga sin cambios a la nueva instancia de Result. Las alternativas de contingencia se pueden implementar con Resolve() [SWS_CORE_00767].

Diagrama de secuencia: flujo de llamadas típico en la consulta y evaluación de una instancia de Result. Fuentes: [SWS_CORE_00731], [SWS_CORE_00751], [SWS_CORE_00755], [SWS_CORE_00757], [SWS_CORE_00768]

Escenarios de error

El acceso a estados no activos viola las precondiciones de la clase:

  • La llamada a Value(), operator* o operator-> sin un valor contenido desencadena la violación del sistema documentada ResultWithNoValueViolation ([SWS_CORE_00755], [SWS_CORE_00753], [SWS_CORE_00754]).
  • La llamada a Error() en presencia de un valor útil provoca la violación ResultWithNoErrorViolation ([SWS_CORE_00757], [SWS_CORE_00776]).

Interpretación: es probable que el desencadenamiento de tal violación de precondición dé lugar típicamente a la terminación inmediata del proceso en entornos de ejecución, ya que el estándar clasifica estos estados como errores graves de programación. Para evitar terminaciones abruptas, se pueden utilizar métodos defensivos: ValueOr() ([SWS_CORE_00761], [SWS_CORE_00762]) y ErrorOr() ([SWS_CORE_00763], [SWS_CORE_00764]) devuelven un valor predeterminado especificado en caso de ausencia de elemento. Variantes opcionales como Ok() ([SWS_CORE_00770], [SWS_CORE_00771]) y Err() ([SWS_CORE_00772], [SWS_CORE_00773]) encapsulan el acceso sin excepciones.

Si se desea gestión de excepciones, ValueOrThrow() ([SWS_CORE_00766], [SWS_CORE_00769], [SWS_CORE_00778]) lanza en caso de error la excepción de C++ asignada al error. Si las excepciones de C++ están deshabilitadas en el compilador, ValueOrThrow() se elimina de la resolución de sobrecarga [SWS_CORE_00766]; del mismo modo, la sobrecarga lvalue no constante de operator* está deshabilitada en este caso [SWS_CORE_00774].

                                                                                                                                              usar
                                                                                                                                              

                                                                                                                                              La función miembro ValueOrThrow [SWS_CORE_00778] de la clase ara::core::Result (cabecera #include "ara/core/result.h") permite el acceso síncrono al valor contenido. Dado que la firma de la función cuenta con el calificador de referencia &, solo se puede invocar en instancias lvalue no constantes. No espera parámetros de entrada y devuelve una referencia modificable (T&) al valor encapsulado.
                                                                                                                                              

                                                                                                                                              Tratamiento de errores y condiciones límite
                                                                                                                                              

                                                                                                                                              Si el objeto no contiene un valor, sino un error, ValueOrThrow lanza de forma síncrona la excepción asociada al error (noexcept(false)) [SWS_CORE_00778]. La función está especificada como not exception safe [SWS_CORE_00778]; interpretación: esto indicaría presumiblemente que, al ocurrir un error, el flujo de control se interrumpe por el lanzamiento de la excepción y no se otorgan garantías adicionales de recuperación o reversión. Si las excepciones de C++ están desactivadas en la cadena de herramientas del compilador, la función obligatoriamente no participa en la resolución de sobrecargas [SWS_CORE_00778]. En cuanto a la concurrencia, la ejecución se indica como thread-safe [SWS_CORE_00778].
                                                                                                                                              

                                                                                                                                              Interacción
                                                                                                                                              

                                                                                                                                              La función forma parte de una familia de sobrecargas para el acceso al valor en ara::core::Result:
                                                                                                                                              

                                                                                                                                                

                                                                                                                                              • Para instancias constantes, se encuentra disponible la sobrecarga con retorno de const T& [SWS_CORE_00766].
                                                                                                                                                • 

                                                                                                                                              • Para objetos rvalue, existe una variante con semántica de movimiento que proporciona T&& [SWS_CORE_00769].
                                                                                                                                                • 

                                                                                                                                              • Para especializaciones con tipos de referencia (Result<T&, E>), están disponibles sobrecargas correspondientes para referencias modificables [SWS_CORE_00949], así como referencias constantes [SWS_CORE_00938].
                                                                                                                                                • 

                                                                                                                                              • En instancias sin valor (Result<void, E>), el método comprueba únicamente la presencia de un error y, en su caso, lanza la excepción [SWS_CORE_00866].
