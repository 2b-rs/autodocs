Encapsula datos binarios leídos y su recuento de bytes de un RawDataStream con propiedad exclusiva del búfer.

La estructura ara::rds::ReadDataResult encapsula el resultado de una operación de lectura de un flujo de datos sin procesar de AUTOSAR Adaptive Platform (AUTOSAR_AP_SWS_RawDataStream, p. 1). Es generada por los métodos ReadData y proporciona los datos binarios leídos en el búfer data junto con el recuento real de bytes numberOfBytes [SWS_RDS_11301]. Dado que el búfer se gestiona como std::unique_ptr, la estructura probablemente transfiere la propiedad exclusiva al invocador y excluye la copia. Los errores se notifican mediante el ara::core::Result contenedor, por lo que el resultado debe validarse antes de acceder a los datos.

Contexto

La clase ara::rds::ReadDataResult actúa en el módulo rds (RawDataStream) de AUTOSAR Adaptive Platform como un contenedor de resultados estructurado para recuperaciones de datos procedentes de flujos de datos (AUTOSAR_AP_SWS_RawDataStream, p. 1). Su responsabilidad principal consiste en entregar a la aplicación invocadora los bytes de datos sin procesar leídos de un flujo de datos brutos junto con el número de bytes realmente transferido. Como partes interactuantes en el conjunto del sistema aparecen las instancias de flujo, que ofrecen los métodos de lectura ReadData, así como el componente de aplicación respectivo que evalúa el flujo de datos y continúa procesando los datos [SWS_RDS_10486], [SWS_RDS_11322].

Ciclo de vida

Las instancias de ara::rds::ReadDataResult se crean en el marco de operaciones de lectura síncronas o con límite de tiempo. La creación se inicia cuando un invocador llama al método ReadData(std::size_t maxLength) [SWS_RDS_10486], [SWS_RDS_11322] o a la sobrecarga con supervisión temporal ReadData(std::size_t maxLength, std::chrono::milliseconds timeout) [SWS_RDS_11309], [SWS_RDS_11323].

Las relaciones de propiedad y el ciclo de vida de la memoria están determinados fundamentalmente por el elemento de datos contenido data, el cual está declarado como std::unique_ptr<ara::core::Byte[]> [SWS_RDS_11301]. Según la interpretación común de C++, esto significa que ReadDataResult probablemente esté concebido como un tipo de solo movimiento (move-only) y, por lo tanto, no se puede copiar, sino exclusivamente mover. El programa invocador asume la propiedad exclusiva del búfer de datos asignado al recibir el objeto. La destrucción de la instancia conlleva automáticamente la liberación de la memoria del montículo (heap) reservada para el array de bytes, a menos que el puntero se haya extraído previamente del objeto de forma explícita. Respecto a la concurrencia, no existe sincronización interna; el acceso concurrente a una instancia desde varios subprocesos sin bloqueos externos no es seguro para subprocesos.

Ruta de uso

El flujo habitual para el uso de ara::rds::ReadDataResult se divide en los siguientes pasos:

  • Solicitud de la operación de lectura: la aplicación invoca en el flujo ReadData con la cantidad máxima de datos deseada maxLength [SWS_RDS_10486], [SWS_RDS_11322], complementada opcionalmente con un valor de tiempo de espera (timeout) [SWS_RDS_11309], [SWS_RDS_11323].
  • Retorno del contenedor Result: el flujo lee los datos binarios del canal y, en caso de éxito, devuelve un objeto rellenado de tipo ara::core::Result<ReadDataResult> (AUTOSAR_AP_SWS_RawDataStream, p. 1).
  • Determinación del tamaño: la aplicación lee el campo numberOfBytes de [SWS_RDS_11302]. Interpretación: es de prever que este valor indique la cantidad de bytes efectivamente proporcionada en el búfer, que puede ser menor o igual a la solicitada maxLength.
  • Procesamiento de datos: se desreferencia el búfer data [SWS_RDS_11301] para procesar los bytes recibidos o transferirlos mediante semántica de movimiento a estructuras propias de la aplicación.

Diagrama de secuencia: Flujo típico de una operación de lectura con recepción y evaluación de ReadDataResult. Fuentes: [SWS_RDS_10486], [SWS_RDS_11301], [SWS_RDS_11302], AUTOSAR_AP_SWS_RawDataStream, p. 1

Escenarios de error

Los métodos para la creación de un ReadDataResult están declarados con noexcept [SWS_RDS_10486], [SWS_RDS_11309], [SWS_RDS_11322], [SWS_RDS_11323], por lo que en caso de error no se lanzan excepciones de C++. En su lugar, el tratamiento de errores se gestiona íntegramente a través del objeto de retorno ara::core::Result (AUTOSAR_AP_SWS_RawDataStream, p. 1).

Los escenarios de error típicos incluyen interrupciones del flujo, solicitudes de lectura no válidas o la expiración del tiempo de espera en llamadas de lectura con supervisión temporal [SWS_RDS_11309], [SWS_RDS_11323]. Interpretación: en tales fallos, el ara::core::Result probablemente no contenga un objeto ReadDataResult válido, sino el correspondiente código de error. Para la aplicación, esto significa, como condición previa para acceder a data [SWS_RDS_11301] y numberOfBytes [SWS_RDS_11302], comprobar siempre primero el estado de éxito del objeto Result superior para evitar el acceso a punteros no inicializados o zonas de memoria no válidas.
