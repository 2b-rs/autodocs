Contexto

La estructura ara::rds::ReadDataResult sirve en el módulo rds (Raw Data Stream) de la AUTOSAR Adaptive Platform como objeto de resultado y de transferencia de datos para operaciones de lectura. Su responsabilidad central consiste en transferir al emisor de la llamada el búfer de datos devuelto en una operación de lectura, junto con el número de bytes realmente transferidos, de forma agrupada y con seguridad de tipos. La estructura se define en el archivo de cabecera ara/rds/raw_data_stream.h [SWS_RDS_11301].

Como interlocutores esenciales intervienen la infraestructura de streaming del módulo rds, que proporciona datos mediante operaciones de lectura e instancia ara::rds::ReadDataResult, así como la aplicación Adaptive consumidora, que recibe el resultado de lectura y continúa procesándolo.

Ciclo de vida

El ciclo de vida de ara::rds::ReadDataResult está directamente vinculado a la ejecución de una operación de lectura. La instanciación se produce como valor de retorno de un proceso de lectura en un flujo de datos sin procesar. La propiedad de la memoria subyacente se regula a través del campo data, que está declarado como std::unique_ptr<ara::core::Byte[]> [SWS_RDS_11301]. Según la interpretación común, este tipo de puntero inteligente impone una semántica de solo movimiento para ara::rds::ReadDataResult; en consecuencia, la estructura puede moverse, pero no copiarse, con lo que la propiedad exclusiva del búfer asignado dinámicamente pasa al emisor de la llamada.

La destrucción sigue el patrón RAII (Resource Acquisition Is Initialization). Tan pronto como una instancia de ara::rds::ReadDataResult sale de su ámbito de validez, el destructor de std::unique_ptr desasigna automáticamente el búfer de bytes asignado, siempre que la propiedad no se haya transferido previamente a otro receptor de búfer mediante std::move. En lo relativo a la concurrencia, la estructura no posee mecanismos de sincronización interna al ser un mero contenedor de datos. En caso de accesos desde varios hilos, el software de aplicación debe garantizar la sincronización de forma externa.

Ruta de uso

Una ruta de uso típica para la recepción y el procesamiento de datos sin procesar comprende los siguientes pasos:

  1. Iniciar la operación de lectura: La aplicación Adaptive invoca una operación de lectura en una instancia de la interfaz de flujo según ara/rds/raw_data_stream.h [SWS_RDS_11301].
  2. Recibir el objeto de resultado: Al completarse con éxito la operación, el resultado se devuelve al emisor de la llamada en forma de una instancia de ara::rds::ReadDataResult mediante semántica de movimiento.
  3. Comprobar la longitud y el puntero: La aplicación lee el campo numberOfBytes de [SWS_RDS_11302] para determinar la cantidad de bytes válidos en el búfer de datos data [SWS_RDS_11301].
  4. Procesar los datos sin procesar: Los datos sin procesar contenidos en el búfer data se evalúan hasta el límite numberOfBytes, por ejemplo, entregándose a un analizador de protocolos o convirtiéndose en estructuras de datos propias de la aplicación.
  5. Transferir o liberar memoria: Si las etapas de procesamiento posteriores requieren el búfer de forma permanente, se puede extraer data mediante std::move; de lo contrario, el búfer se libera automáticamente al final del ámbito de validez.

Escenarios de error

Al manipular ara::rds::ReadDataResult, deben tenerse en cuenta las siguientes precondiciones, poscondiciones y situaciones excepcionales:

  • Resultados de lectura vacíos: Si numberOfBytes tiene el valor 0 [SWS_RDS_11302], no se ha recibido ningún byte durante la operación (por ejemplo, al llegar al final del flujo o en llamadas de lectura no bloqueantes sin datos pendientes). En este estado, según una interpretación plausible, data debería existir como nullptr o bien apuntar a un búfer sin contenido útil evaluable.
  • Desbordamiento de búfer durante el acceso: Dado que data está tipificado como un puntero de matriz dentro de std::unique_ptr [SWS_RDS_11301], no existe una verificación automática de límites. Un acceso más allá del valor del índice numberOfBytes [SWS_RDS_11302] da lugar a un comportamiento indefinido (desbordamiento de búfer).
  • Acceso tras una operación de movimiento: Si el campo data se extrajo mediante std::move, el puntero permanece en el estado nullptr. Las desreferenciaciones posteriores de data sin una comprobación previa de nulo provocan errores en tiempo de ejecución.
