Contexto

La interfaz ara::crypto::x509::X509Provider constituye la abstracción central en el subsistema criptográfico de AUTOSAR Adaptive para el procesamiento y la gestión de artefactos X.509. Su responsabilidad principal abarca el análisis sintáctico y la creación de certificados, cadenas de certificados, solicitudes de certificados (CSR), listas de revocación de certificados (CRL) y estructuras OCSP, así como la interacción con el almacén persistente de certificados.

Entre los interlocutores principales se encuentran:

  • Aplicaciones: inician operaciones de lectura, escritura, creación y validación para certificados y solicitudes de certificados.
  • Almacén persistente de certificados: almacena certificados en ranuras o grupos dedicados, direccionados mediante ara::core::InstanceSpecifier ([SWS_CRYPT_40621], [SWS_CRYPT_50127]).
  • Contextos criptográficos: crea contextos de validación (CertificateValidationCtx) ([SWS_CRYPT_50125]) y utiliza contextos de firma (cryp::SignerPrivateCtx) para la creación de solicitudes firmadas ([SWS_CRYPT_40640], [SWS_CRYPT_40626]).

Diagrama de contexto: integración de X509Provider en la gestión de certificados e interacciones criptográficas. Fuentes: [SWS_CRYPT_40621], [SWS_CRYPT_40641], [SWS_CRYPT_50125], [SWS_CRYPT_40640]

Ciclo de vida

Como interfaz abstracta, ara::crypto::x509::X509Provider se gestiona mediante punteros compartidos. El alias de tipo ara::crypto::x509::X509Provider::Sptr define para ello std::shared_ptr<X509Provider> ([SWS_CRYPT_40601]). La instanciación real de objetos de proveedor concretos probablemente se realice mediante rutinas de carga de nivel superior de la pila criptográfica (interpretación).

La interfaz impide la duplicación o el traslado de las instancias: el constructor de copia ([SWS_CRYPT_41013]), el constructor de movimiento ([SWS_CRYPT_41014]), así como los operadores de asignación ([SWS_CRYPT_30226], [SWS_CRYPT_30227]), están eliminados (=delete). El destructor virtual está definido como implementación predeterminada ([SWS_CRYPT_40604]).

En lo que respecta a la concurrencia, todas las funciones miembro virtuales están especificadas como seguras para subprocesos (thread-safe) y seguras frente a excepciones (exception safe). La clase en sí no define estados internos del ciclo de vida, sino que actúa como interfaz de fábrica y de servicio sin estado.

Ruta de uso

Una ruta de uso típica comprende el procesamiento de un certificado serializado, su almacenamiento persistente y la preparación de una validación de certificados:

  1. Analizar certificado: un área de memoria binaria o textual se lee mediante ParseCert ([SWS_CRYPT_40614]) o, en el caso de múltiples certificados, mediante ParseCertChain ([SWS_CRYPT_40616]) y se instancia como Certificate::Sptrc.
  2. Almacenar en el slot: el objeto de certificado se guarda de forma persistente a través de ImportCertificate en un slot modelado mediante InstanceSpecifier ([SWS_CRYPT_40621]). Para grupos de certificados, está disponible alternativamente ImportCertificateInGroup ([SWS_CRYPT_50127]).
  3. Cargar y limpiar: los certificados almacenados se pueden cargar con LoadCertificate ([SWS_CRYPT_40641]) o LoadCertificateGroup ([SWS_CRYPT_50126]), respectivamente. Un slot se vacía a través de ClearCertificateSlot ([SWS_CRYPT_40622]), mientras que los certificados de un grupo se eliminan mediante RemoveCertificateFromGroup ([SWS_CRYPT_50128]).
  4. Contexto de validación y comprobación de estado: para validaciones posteriores, CreateCertificateValidationCtx genera una instancia de contexto ([SWS_CRYPT_50125]). Para comprobar la revocación de certificados, se pueden leer listas de revocación mediante ImportCrl ([SWS_CRYPT_50183]) o eliminar mediante DeleteCrl ([SWS_CRYPT_50184]).
  5. Creación de solicitudes de certificado y OCSP: a partir de una cadena o búfer, se genera mediante CreateDn un Distinguished Name (X509DN) ([SWS_CRYPT_50186], [SWS_CRYPT_50187]), que a continuación se incorpora junto con un cryp::SignerPrivateCtx en CreateCertSignRequest ([SWS_CRYPT_40640]). De forma complementaria, se pueden crear solicitudes OCSP a través de CreateOcspRequest ([SWS_CRYPT_40626], [SWS_CRYPT_40627]) y procesar respuestas mediante ParseOcspResponse ([SWS_CRYPT_50185]).

Diagrama de secuencia: flujo de análisis, persistencia y creación de un contexto de validación. Fuentes: [SWS_CRYPT_40614], [SWS_CRYPT_40621], [SWS_CRYPT_50125]

Escenarios de error

Las llamadas señalan estados de error a través de ara::core::Result<T> con códigos de error de ara::crypto::CryptoErrc y garantizan la semántica de reversión en caso de error:

  • ara::crypto::CryptoErrc::kBusyResource: se produce cuando un recurso necesario está ocupado temporalmente y la operación no se puede ejecutar de inmediato ([SWS_CRYPT_40621], [SWS_CRYPT_40622], [SWS_CRYPT_50127], [SWS_CRYPT_50183]).
  • ara::crypto::CryptoErrc::kInvalidArgument: se notifica cuando los datos transmitidos no cumplen las especificaciones, por ejemplo, en caso de cadenas DN no válidas ([SWS_CRYPT_50186]), búferes de certificados defectuosos ([SWS_CRYPT_40614]) o si la clave pública en CreateCertSignRequest no coincide con la clave privada de firma ([SWS_CRYPT_40640]).
  • ara::crypto::CryptoErrc::kUnsupportedFormat: se devuelve si el formato transmitido para certificados, CRL o respuestas OCSP no es compatible ([SWS_CRYPT_40614], [SWS_CRYPT_50187], [SWS_CRYPT_50185]).
  • ara::crypto::CryptoErrc::kEmptyCertificateSlot: se produce cuando a través de LoadCertificate se hace referencia a un slot que no contiene ningún certificado persistido ([SWS_CRYPT_40641]).
  • ara::crypto::CryptoErrc::kInsufficientCapacity: notifica que la capacidad de un grupo de certificados se ha agotado ([SWS_CRYPT_50127]).
  • ara::crypto::CryptoErrc::kNoSuchValue: se notifica cuando un certificado que se debe eliminar de un grupo no existe allí ([SWS_CRYPT_50128]).
  • ara::crypto::CryptoErrc::kUninitializedContext, kEmptyKeySlot, kUsageViolation: señalan en CreateCertSignRequest o CreateOcspRequest errores de configuración del contexto de firma relativos a la asignación de claves o al uso permitido de claves ([SWS_CRYPT_40640], [SWS_CRYPT_40626]).

A nivel de arquitectura, los errores de modelado y de permisos dan lugar a violaciones documentadas: se produce una ProcessMappingViolation cuando el InstanceSpecifier transmitido no hace referencia a un prototipo de puerto modelado para el proceso actual. Una InsufficientPermissionsViolation señala la falta de permisos de escritura (writeAccess != True) al modificar slots o grupos de certificados ([SWS_CRYPT_40621], [SWS_CRYPT_50127], [SWS_CRYPT_50183], [SWS_CRYPT_50184]).

Esta guía se basa en la especificación AUTOSAR Adaptive R25-11 para el módulo crypto.
