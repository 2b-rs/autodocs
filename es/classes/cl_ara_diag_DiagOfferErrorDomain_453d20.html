Gestiona y traduce códigos de error y excepciones para ofertas de diagnóstico en el módulo diag.

La clase ara::diag::DiagOfferErrorDomain representa el dominio de error estandarizado para fallos al proporcionar servicios de diagnóstico dentro de AUTOSAR Adaptive Platform [SWS_DM_00989]. Como especialización de la clase base ara::core::ErrorDomain, asigna mensajes de texto legibles a códigos de error numéricos del tipo DiagOfferErrc y admite la conversión en objetos de excepción del tipo DiagException [SWS_DM_00994]. Todas las funciones miembro se ejecutan con seguridad de hilos, mientras que el disparo de excepciones no participa en la resolución de sobrecargas cuando las excepciones de C++ están deshabilitadas en el compilador.

Contexto

La clase ara::diag::DiagOfferErrorDomain define el dominio de error específico para estados de error que se producen en relación con ofertas de diagnóstico (Diagnostic Offers) en el módulo de AUTOSAR Adaptive diag [SWS_DM_00989]. Como clase final, especializa la clase general de plataforma ara::core::ErrorDomain (AUTOSAR_AP_SWS_Diagnostics §8.11.5 «Class: DiagOfferErrorDomain»). Su responsabilidad principal consiste en representar de forma tipada los estados erróneos al ofrecer servicios de diagnóstico y proporcionar una interfaz estandarizada tanto para la descripción textual como para el tratamiento de excepciones.

Dentro de la arquitectura de errores, ara::diag::DiagOfferErrorDomain interactúa estrechamente con ara::core::ErrorCode: las operaciones erróneas instancian códigos de error que vinculan el valor de enumeración correspondiente con el dominio de error. Para ello, la clase proporciona el alias de tipo Errc, que referencia al tipo de enumeración DiagOfferErrc [SWS_DM_00990]. Para el flujo de control tolerante a fallos, la clase establece a través del alias de tipo Exception una vinculación con la clase base de excepción DiagException [SWS_DM_00991].

Diagrama de contexto: integración de DiagOfferErrorDomain en la arquitectura de errores de ara::diag y ara::core. Fuentes: [SWS_DM_00989], [SWS_DM_00990], [SWS_DM_00991].

Ciclo de vida

La creación de una instancia de ara::diag::DiagOfferErrorDomain se realiza a través del constructor predeterminado sin parámetros, el cual está definido como constexpr y noexcept [SWS_DM_00992]. Este constructor se encuentra en el archivo de encabezado ara/diag/diag_error_domain.h (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.1.1 «Default Constructor»). Gracias a la especificación constexpr, el objeto de dominio ya puede construirse en tiempo de compilación. En sistemas AUTOSAR, es de esperar que el dominio de error se mantenga típicamente como un objeto estático o singleton disponible a nivel de todo el proceso, de modo que no se requieran asignaciones dinámicas.

Todas las funciones miembro de la clase están declaradas, sin excepción, como seguras para hilos (thread-safe) [SWS_DM_00992], [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995]. Esto permite un acceso concurrente y seguro desde múltiples hilos. Dado que la clase está declarada como final, no se permiten clases derivadas. La destrucción no está sujeta a requisitos especiales y se lleva a cabo con la liberación de la memoria estática al finalizar la aplicación.

Ruta de uso

La clase se utiliza típicamente de forma indirecta a través de ara::core::ErrorCode o directamente al evaluar los resultados de operaciones de diagnóstico:

  1. Una operación al ofrecer un servicio de diagnóstico falla, tras lo cual se genera un ara::core::ErrorCode con un valor del tipo DiagOfferErrc (alias Errc) [SWS_DM_00990].
  2. Para identificar el dominio se puede invocar el método Name(), el cual devuelve el identificador del dominio de error de la aplicación [SWS_DM_00993] (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.2 «Name»).
  3. Para obtener un mensaje de error legible con fines de registro o diagnóstico, se invoca Message() con el código de error; según la especificación, la cadena de caracteres C devuelta nunca es nullptr [SWS_DM_00994].
  4. Si la arquitectura de software gestiona los errores mediante excepciones, se invoca ThrowAsException() con el ErrorCode, lo que desencadena el lanzamiento de la excepción correspondiente [SWS_DM_00995].

Diagrama de secuencia: consulta típica de mensajes de error y lanzamiento de excepciones a través de DiagOfferErrorDomain. Fuentes: [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995].

Escenarios de error

El dominio en sí no reporta errores internos, sino que sirve para clasificar errores externos al proporcionar funcionalidades de diagnóstico. Las condiciones de error concretas se expresan mediante el tipo de enumeración DiagOfferErrc, el cual está asignado de forma fija al dominio a través de Errc [SWS_DM_00990]. Presumiblemente, estos valores de error cubren situaciones de configuración o de conflicto durante el registro de servicios de diagnóstico.

La función miembro Message() garantiza seguridad frente a excepciones (exception safe) y proporciona un mensaje de texto válido para cada valor de error suministrado [SWS_DM_00994]. Por el contrario, ThrowAsException() está clasificada como no segura frente a excepciones (not exception safe) y marcada con noexcept(false), ya que su cometido explícito consiste en lanzar una excepción del tipo base DiagException (alias Exception) [SWS_DM_00991], [SWS_DM_00995].

Existe una restricción central en plataformas o configuraciones de compilador sin soporte de excepciones: cuando las excepciones de C++ están deshabilitadas en la cadena de herramientas, la función ThrowAsException() no participa en la resolución de sobrecargas [SWS_DM_00995]. En este caso, la aplicación debe gestionar el tratamiento de errores exclusivamente por valor mediante códigos de error.
