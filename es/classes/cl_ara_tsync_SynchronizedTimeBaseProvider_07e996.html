Contexto

La clase ara::tsync::SynchronizedTimeBaseProvider proporciona acceso a una base de tiempo sincronizada que se direcciona mediante un identificador de instancia (ara::core::InstanceSpecifier) ([SWS_TS_01101]). Dentro de la arquitectura AUTOSAR Adaptive, sirve como interfaz dedicada para aplicaciones proveedoras de tiempo (Time Provider Applications). Su responsabilidad central comprende el establecimiento y la actualización de marcas de tiempo para el bus de comunicación ([SWS_TS_01107], [SWS_TS_01108]), el reajuste de las velocidades de reloj ([SWS_TS_01110]), la gestión de datos útiles específicos de la aplicación ([SWS_TS_01112]), así como la recepción de datos de validación ([SWS_TS_01114]).

En la interacción participan al menos tres partes: la aplicación proveedora, la instancia de la clase proveedora y el Time Sync Daemon, que gestiona la conexión y coordina la transmisión física en el bus ([SWS_TS_01107]).

Diagrama de contexto: participantes en la interacción de SynchronizedTimeBaseProvider durante la provisión de tiempo. Fuentes: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01108].

Ciclo de vida y concurrencia

La creación se realiza explícitamente mediante el constructor a través de un ara::core::InstanceSpecifier ([SWS_TS_01101]). En este caso, el PortPrototype vinculado debe estar obligatoriamente tipificado mediante un SynchronizedTimeBaseProviderInterface; de lo contrario, se produce un PortInterfaceMappingViolation ([SWS_TS_01101]).

Con respecto a las relaciones de propiedad, la clase implementa una semántica exclusiva de solo movimiento:

  • El constructor de copia ([SWS_TS_01104]) y el operador de asignación por copia ([SWS_TS_01105]) están eliminados (=delete), lo que excluye duplicados de la interfaz de acceso.
  • El constructor de movimiento ([SWS_TS_01102]) y el operador de asignación por movimiento ([SWS_TS_01103]) están disponibles y asegurados con noexcept.
  • La destrucción se realiza a través del destructor ([SWS_TS_01106]).

En cuanto a la seguridad para subprocesos, la interfaz distingue estrictamente entre operaciones de consulta y de modificación:

  • El constructor ([SWS_TS_01101]) y los métodos de lectura GetCurrentTime ([SWS_TS_01109]), GetRateDeviation ([SWS_TS_01111]) así como GetUserData ([SWS_TS_01113]) son seguros para subprocesos (thread-safe).
  • Las operaciones que modifican el estado como SetTime ([SWS_TS_01107]), UpdateTime ([SWS_TS_01108]), SetRateCorrection ([SWS_TS_01110]), SetUserData ([SWS_TS_01112]), RegisterTimeValidationNotification ([SWS_TS_01114]), UnregisterTimeValidationNotification ([SWS_TS_01115]), así como las operaciones de movimiento y el destructor ([SWS_TS_01106]), están clasificadas como no seguras para subprocesos (non_threadsafe) y requieren sincronización externa.

Ruta de uso

Una ruta de uso típica para proporcionar información horaria sincronizada es la siguiente:

  1. Instanciación: la aplicación crea la instancia del proveedor transfiriendo el InstanceSpecifier configurado ([SWS_TS_01101]).
  2. Registro de notificaciones: si se deben validar parámetros de sincronización, la aplicación registra un objeto de notificación a través de RegisterTimeValidationNotification ([SWS_TS_01114]). Solo puede haber registrado a lo sumo un notificador al mismo tiempo; las llamadas sucesivas sobrescriben el registro existente ([SWS_TS_01114]).
  3. Actualización horaria: para la transmisión se puede elegir entre dos mecanismos:
    • SetTime: actualiza la hora e inicia inmediatamente la transmisión en el bus ([SWS_TS_01107]).
    • UpdateTime: actualiza el valor de tiempo únicamente a nivel local; la transmisión real en el bus se realiza de forma controlada por ciclo en el siguiente intervalo de emisión ([SWS_TS_01108]).
  4. Corrección y estado: si es necesario, la velocidad del reloj se puede ajustar mediante SetRateCorrection ([SWS_TS_01110]). Además, se pueden leer valores de estado como la hora actual ([SWS_TS_01109]) o la desviación de velocidad ([SWS_TS_01111]).
  5. Cancelación del registro: antes de desmantelar la instancia, probablemente sea aconsejable una cancelación explícita del registro del notificador mediante UnregisterTimeValidationNotification ([SWS_TS_01115]).

Diagrama de secuencia: secuencia de llamadas típica para la provisión de tiempo y el registro de notificaciones. Fuentes: [SWS_TS_01101], [SWS_TS_01107], [SWS_TS_01114], [SWS_TS_01115].

Escenarios de error

Los métodos de modificación notifican errores a través de objetos de retorno del tipo ara::core::Result<void>. Las llamadas fallidas no poseen semántica de reversión (no_rollback_semantics):

Método código de error Condición y efecto
SetTime, UpdateTime, SetUserData TsyncErrc::kInvalidUserDataSize Los datos de usuario transferidos superan el límite superior definido por UserData::kMaxUserDataSize (actualmente 3 bytes) ([SWS_TS_01107], [SWS_TS_01108], [SWS_TS_01112]).
SetTime TsyncErrc::kDaemonConnectionLost La conexión con el Time Sync Daemon está interrumpida; no se puede ejecutar la acción ([SWS_TS_01107]).
SetRateCorrection TsyncErrc::kLimitsExceeded El factor de corrección vulnera el rango de valores permitido ([SWS_TS_01110]). Un factor inferior a 1.0 ralentiza el reloj; un valor superior a 1.0 lo acelera ([SWS_TS_01110]).
SetRateCorrection TsyncErrc::kFunctionNotSupported La corrección de velocidad no se admite para la base de tiempo direccionada ([SWS_TS_01110]).

Todos los métodos están especificados como seguros frente a excepciones (exception safe) y marcados con noexcept. Los métodos de lectura como GetCurrentTime ([SWS_TS_01109]) devuelven la hora sin errores, independientemente del estado de sincronización actual.
