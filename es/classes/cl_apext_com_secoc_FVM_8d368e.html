Proporciona a la gestión de comunicación una interfaz para la gestión de valores de frescura específicos del fabricante para SecOC.

La clase sirve como interfaz implementada por el OEM o el fabricante del stack para proporcionar y gestionar valores de frescura para SecOC en la gestión de comunicación [SWS_CM_11287]. Suministra valores de frescura a ara::com al enviar y recibir mensajes protegidos a través de GetTxFreshness() y GetRxFreshness(), y recibe el resultado de verificación a través de SetVerificationStatus() [SWS_CM_11274] [SWS_CM_11276]. Su ciclo de vida se gestiona completamente como un singleton por parte de ara::com [SWS_CM_11272].

Contexto

La clase apext::com::secoc::FVM define la interfaz estandarizada para el Freshness Value Management (FVM) dentro de la gestión de comunicación de AUTOSAR Adaptive [SWS_CM_11287]. Actúa como punto de extensión (interfaz de plugin) implementado por el OEM o el fabricante del stack para suministrar valores de frescura específicos de la aplicación para la protección precisa de mensajes AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM». Entre los interlocutores figuran la gestión de comunicación (ara::com), el módulo criptográfico de protección SecOC y la biblioteca de FVM específica del fabricante.

Diagrama de contexto: integración de la interfaz FVM entre la gestión de comunicación y la biblioteca de valores de frescura específica del fabricante. Fuentes: [SWS_CM_11272], [SWS_CM_11287], AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM»

Ciclo de vida

Dentro de la gestión de comunicación existe exactamente una única instancia de esta clase AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 «Class: FVM». Todo el ciclo de vida de la implementación de SecOC-FreshnessValueManager se controla completamente mediante ara::com [SWS_CM_11272]. La inicialización de la implementación de FVM se realiza obligatoriamente mediante la llamada al método Initialize() [SWS_CM_11273] [SWS_CM_11290]. Todos los métodos de la interfaz están declarados como seguros frente a excepciones (noexcept) [SWS_CM_11288]. Interpretación: Dado que la instanciación y la gestión del ciclo de vida se realizan internamente a través de ara::com, corresponde a la implementación concreta del plugin FVM la sincronización interna frente a llamadas concurrentes a través de múltiples canales de comunicación. Pregunta Q-02e8eaeef2145dbb (abierta)

Ruta de uso

En funcionamiento regular, la gestión de comunicación distingue entre el envío y la recepción de mensajes protegidos:

  • Operación de envío: Cuando un mensaje está configurado para la transmisión SecOC y posee una freshnessValueId, la gestión de comunicación invoca GetTxFreshness() con el ID del valor de frescura [SWS_CM_11274] [SWS_CM_11289]. En caso de retorno exitoso, el valor de frescura en FVContainer se utiliza para el cálculo del autenticador (MAC), el cual tiene lugar después de los cálculos para la protección E2E [SWS_CM_11274].
  • Operación de recepción: Siempre que la verificación de mensajes entrantes no se omita por configuración [SWS_CM_11372], SecOC invoca GetRxFreshness() antes de la comprobación E2E [SWS_CM_11276] [SWS_CM_11288]. En este proceso se transfieren el SecOCFreshnessValueID, el valor de frescura truncado recibido (SecOCTruncatedFreshnessValue), así como el número de intentos de verificación realizados hasta el momento (SecOCAuthVerifyAttempts) [SWS_CM_11288]. Tras el cotejo del autenticador calculado, la gestión de comunicación notifica el resultado a FVM vía SetVerificationStatus() indicando el VerificationStatus [SWS_CM_19999] [SWS_CM_11378].

Diagrama de secuencia: flujo de verificación en la recepción de un mensaje protegido con consulta de valor de frescura y retroalimentación de estado. Fuentes: [SWS_CM_11276], [SWS_CM_11288], [SWS_CM_19999], AUTOSAR_AP_SWS_CommunicationManagement §8.1 «SecOC secure channel reception»

Escenarios de error

Los errores se señalizan mediante tipos de retorno del tipo ara::core::Result:

  • Errores de inicialización: Si falla la preparación de la implementación de FVM, Initialize() devuelve el código de error ComSecOcFvmErrc::kFVInitializeFailed [SWS_CM_11290].
  • Valor de frescura no disponible: Si los valores de frescura de envío o recepción no se pueden determinar temporalmente, GetTxFreshness() y GetRxFreshness() devuelven el error ComSecOcFvmErrc::kFVNotAvailable [SWS_CM_11288] [SWS_CM_11289].
  • Reintentos en el envío: Si GetTxFreshness() devuelve el error recuperable kFVNotAvailable o falla el cálculo del autenticador, el sistema incrementa un Authentication Build Counter [SWS_CM_11275]. La protección del mensaje se reintenta de forma específica del fabricante; si el contador alcanza el límite configurado SecOCAuthenticationBuildAttempts, el mensaje se descarta [SWS_CM_11275] AUTOSAR_AP_SWS_CommunicationManagement §8.1 «SecOC secure message build attempts».
  • Mensajes de estado en fallos de verificación: A través de SetVerificationStatus() se notifican modos de error específicos como kSecOcVerificationFailure, kSecOcFreshnessFailure o kSecOcAuthenticationBuildFailure a FVM [SWS_CM_19999] [SWS_CM_11378].

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 2598e93ae192 Procedencia Preguntas abiertas (2)

La función miembro apext::com::secoc::FVM::GetRxFreshness sirve a la capa SecOC para determinar el valor de frescura completo para mensajes recibidos [SWS_CM_11288]. Como parámetros de entrada, la función espera el identificador SecOCFreshnessValueID, el valor de frescura truncado extraído del mensaje protegido en FVContainer conforme a [SWS_CM_11286], así como el contador SecOCAuthVerifyAttempts [SWS_CM_11288]. Este contador comienza con el valor 0 en el primer intento de verificación y se incrementa en cada intento fallido posterior del mismo mensaje [SWS_CM_11288].

El método está especificado como noexcept y seguro frente a excepciones (AUTOSAR_AP_SWS_CommunicationManagement §C.1.2.2.1.1 «GetRxFreshness»). Debido a la devolución directa de un ara::core::Result<FVContainer> sin tipo Future, la llamada debería procesarse de forma síncrona bloqueante. Pregunta Q-2609cb9ffeb0d41d (abierta) En caso de éxito, el resultado contiene el valor de frescura completo para la posterior verificación del autenticador mediante MAC [SWS_CM_11288]. Si el valor no se puede proporcionar, la función devuelve el código de error recuperable ComSecOcFvmErrc::kFVNotAvailable [SWS_CM_11288].

La determinación del valor de frescura es parte integrante de la ruta de recepción de SecOC: la autenticación de mensajes se realiza por principio antes de las comprobaciones E2E posteriores [SWS_CM_11276] y está acoplada al contador de intentos de autenticación [SWS_CM_11277]. En el estándar no se definen requisitos específicos de reentrancia o seguridad de subprocesos; por lo tanto, el comportamiento en llamadas paralelas debería depender de la implementación concreta del Freshness Value Manager. Pregunta Q-071e92f80c6e44db (abierta)

      La función síncrona de biblioteca apext::com::secoc::FVM::GetTxFreshness ([SWS_CM_11289]) sirve al procesamiento de SecOC para obtener el valor de frescura actual al enviar mensajes protegidos a través de Communication Management ([SWS_CM_11274], AUTOSAR_AP_SWS_CommunicationManagement p. 224 «SecOC secure channel sending»).
      


      Uso y contexto de llamada
      

      La llamada es realizada por ara::com, siempre que para el respectivo elemento de interfaz de servicio se haya configurado un freshnessValueId ([SWS_CM_11274]):
      

        
  
      • Parámetro: SecOCFreshnessValueID (tipo std::uint16_t) identifica el valor de frescura que se va a solicitar ([SWS_CM_11289]).
        • 
  
      • Valor de retorno: un ara::core::Result<FVContainer> ([SWS_CM_11289]). En caso de éxito, este contiene un apext::com::secoc::FVContainer ([SWS_CM_11286]), cuyo valor de frescura se utiliza para el posterior cálculo del autenticador o MAC ([SWS_CM_11274]).
        • 
  
      • Seguridad frente a excepciones: la función está declarada como noexcept ([SWS_CM_11289]).
        • 

      


      Tratamiento de errores y condiciones límite
      

      Si no se puede proporcionar un valor de frescura válido, la función devuelve un ara::core::Result con el código de error ComSecOcFvmErrc::kFVNotAvailable («Freshness Value not available») con semántica de reversión (rollback) ([SWS_CM_11289]). En el estándar Adaptive no se definen notificaciones específicas a DET o DEM para esta interfaz.
      


      Flujo y concurrencia
      

      Dentro del proceso de envío, la llamada está sujeta a un orden estricto ([SWS_CM_11274]):
      

        
  
      1. Previamente, el ciclo de vida del Freshness Value Manager debe haber sido gestionado por ara::com ([SWS_CM_11272]) y la instancia debe haber sido inicializada a través de apext::com::secoc::FVM::Initialize ([SWS_CM_11273]).
        2. 
  
      2. Al enviar, GetTxFreshness se realiza de forma posterior a los cálculos de protección E2E ([SWS_CM_11274]).
        3. 
  
      3. A continuación, se llevan a cabo el cálculo del MAC, truncamientos opcionales y la composición del mensaje protegido ([SWS_CM_11274]).
        4. 

      

      La especificación no dice nada acerca de la reentrancia; presumiblemente, no obstante, la implementación de FVM debe estar diseñada para ser segura para subprocesos o reentrante si flujos de comunicación paralelos solicitan valores de frescura al mismo tiempo. Pregunta Q-a1d3e04b91b6c24d (abierta)

          Uso y contexto de llamada
          

          La función síncrona de biblioteca Initialize dentro del ámbito apext::com::secoc::FVM sirve para inicializar la implementación de plugin específica del fabricante del Freshness Value Manager (FVM) para la comunicación relevante para la seguridad a través de SecOC [SWS_CM_11290]. La declaración está disponible a través de la cabecera apext/com/secoc/fvm.h SWS CommunicationManagement §C.1.2.2.1.3 «Initialize».
          

          La función no acepta parámetros y declara la seguridad frente a excepciones noexcept (exception safe) [SWS_CM_11290]. La gestión del ciclo de vida del FVM es asumida de forma vinculante por el middleware de comunicación ara::com [SWS_CM_11272], el cual realiza la inicialización del plugin de FVM mediante la llamada explícita a esta interfaz [SWS_CM_11273]. Interpretación: para los desarrolladores de aplicaciones no existe un contexto de llamada directa, ya que la provisión se realiza como plugin para la plataforma y el control recae por completo en ara::com. Pregunta Q-5b5c8b1a42c3bd3a (abierta)
          


          Manejo de errores
          

          El resultado de la operación se comunica a través del tipo de retorno ara::core::Result<void> [SWS_CM_11290]:
          

            

          • Éxito: en caso de inicialización correcta, el ara::core::Result contiene un valor vacío (value_type es void) [SWS_CM_11290].
            • 

          • Inicialización fallida: si el Freshness Value Manager no se pudo inicializar, se devuelve un objeto de error con el código de error específico ComSecOcFvmErrc::kFVInitializeFailed; en tal caso, se aplican semánticas de reversión para mantener un estado definido [SWS_CM_11290].
            • 

          


          Interacción y orden de ejecución
          

          La inicialización mediante Initialize constituye el requisito funcional previo para todos los demás servicios de FVM en el sistema [SWS_CM_11273]. Solo tras una ejecución correcta, ara::com puede acceder a la interfaz apext::com::secoc::FVM::GetTxFreshness en el marco de las operaciones de envío de SecOC tras el cálculo E2E, con el fin de consultar valores de actualidad para atributos freshnessValueId configurados [SWS_CM_11274].
