Contexto

La clase ara::idsm::ContextDataProvider sirve en el módulo idsm (Intrusion Detection System Manager) de AUTOSAR Adaptive Platform para proporcionar y enriquecer datos de contexto relevantes para la seguridad ([SWS_AIDSM_10500]). Al monitorizar eventos críticos para la seguridad, el IdsM requiere información adicional sobre el entorno y el estado de la aplicación para poder clasificar con precisión las anomalías o los incidentes de seguridad detectados. Como interfaz, ContextDataProvider define el método abstracto ModifyContextData ([SWS_AIDSM_10509]), a través del cual el IdsM consulta datos del componente de la aplicación según sea necesario.

La interacción tiene lugar entre tres componentes principales:

  • Adaptive Application / subclase proveedora: la aplicación implementa la lógica concreta del proveedor sobrescribiendo ModifyContextData ([SWS_AIDSM_10509]) y controla el ciclo de vida del objeto de provisión.
  • Clase base ContextDataProvider: gestiona la vinculación con el puerto del proveedor modelado en el manifiesto mediante un identificador de instancia ([SWS_AIDSM_10501]).
  • Servicio IdsM: el Intrusion Detection System accede a los datos de contexto en cuanto se ha activado la provisión a través de la interfaz ([SWS_AIDSM_10507]).

Ciclo de vida

La instanciación de ContextDataProvider se realiza explícitamente a través del constructor, pasando un ara::core::InstanceSpecifier, el número de bytes adicionales (additionalBytes) y el desplazamiento para los datos de contexto originales (originalContextDataOffset) ([SWS_AIDSM_10501]). Este constructor está especificado como seguro para subprocesos (thread-safe) ([SWS_AIDSM_10501]).

En cuanto a la semántica de propiedad y de valor, se aplican restricciones estrictas:

  • Copia prohibida: tanto el constructor de copia ([SWS_AIDSM_10504]) como el operador de asignación por copia ([SWS_AIDSM_10506]) están eliminados (= delete). Una instancia del proveedor está vinculada unívocamente a un puerto modelado y no se puede duplicar.
  • Movimiento permitido: la clase dispone de un constructor de movimiento seguro para subprocesos ([SWS_AIDSM_10503]). También se admite la asignación por movimiento mediante operator=, pero no es segura para subprocesos (not thread-safe) ([SWS_AIDSM_10505]).

Tras la construcción, la instancia se encuentra en un estado inactivo. Solo mediante la llamada explícita a Offer() ([SWS_AIDSM_10507]) se le indica al IdsM que el proveedor está listo y que se puede invocar ModifyContextData. Con StopOffer() ([SWS_AIDSM_10508]) se interrumpe de nuevo este servicio. La liberación de la instancia se realiza mediante el destructor virtual ~ContextDataProvider() ([SWS_AIDSM_10502]). Interpretación: para evitar condiciones de carrera durante la ejecución del destructor, probablemente debería invocarse StopOffer() antes de destruir el objeto, ya que ni la destrucción ni la desregistración son seguras para subprocesos ([SWS_AIDSM_10502], [SWS_AIDSM_10508]).

Ruta de uso

El flujo normal para la provisión de datos de contexto comprende las siguientes fases:

  1. Derivación: Interpretación: dado que ModifyContextData es un método virtual puro ([SWS_AIDSM_10509]), la aplicación crea su propia clase derivada y sobrescribe esta función.
  2. Creación: la clase proveedora derivada se instancia especificando el InstanceSpecifier para el puerto del proveedor modelado, el tamaño de búfer adicional y el desplazamiento ([SWS_AIDSM_10501]).
  3. Activación: la aplicación invoca Offer() ([SWS_AIDSM_10507]). Tras un registro correcto, el IdsM está autorizado a emitir llamadas de retrollamada al proveedor.
  4. Provisión de contexto: si se produce un evento de seguridad en el IdsM, el framework invoca ModifyContextData(contextData, event) ([SWS_AIDSM_10509]). La aplicación escribe la información contextual en el búfer de bytes proporcionado (ara::core::Span<std::uint8_t>) y devuelve el número de bytes modificados.
  5. Desactivación: antes del apagado del componente, la aplicación invoca StopOffer() ([SWS_AIDSM_10508]) para impedir llamadas adicionales por parte del IdsM y destruye la instancia ([SWS_AIDSM_10502]).

Diagrama de secuencia: flujo típico de inicialización, provisión (Offer), modificación de contexto controlada por eventos y desregistración (StopOffer). Fuentes: [SWS_AIDSM_10501], [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509].

Escenarios de error

Los métodos para la gestión del estado y la modificación de datos señalan estados de ejecución a través de ara::core::Result:

  • Fallo de Offer: el método Offer() devuelve ara::core::Result<void> ([SWS_AIDSM_10507]). Si el puerto del proveedor no se puede registrar (por ejemplo, debido a la falta de recursos del sistema o a un modelado incorrecto), el objeto de resultado contiene el código de error correspondiente. En este caso no se permiten llamadas del IdsM a ModifyContextData.
  • Fallo en ModifyContextData: la función de callback devuelve ara::core::Result<std::size_t> ([SWS_AIDSM_10509]). Si la capacidad del ara::core::Span<std::uint8_t> proporcionado no es suficiente o no se puede determinar el contexto para el EventIdType notificado, la clase derivada devuelve un resultado de error en lugar de transmitir un número de bytes.
  • Precondiciones y poscondiciones: ModifyContextData solo debe tener lugar entre un Offer() correcto ([SWS_AIDSM_10507]) y StopOffer() ([SWS_AIDSM_10508]). Dado que ni Offer(), ni StopOffer() ni ModifyContextData() son seguros para subprocesos ([SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]), la aplicación invocadora debe asegurarse de que las operaciones del ciclo de vida no se ejecuten de forma concurrente con ejecuciones de callback en curso.

<h4>Contexto</h4>
<p>La clase <code>ara::idsm::ContextDataProvider</code> sirve en el módulo <code>idsm</code> (Intrusion Detection System Manager) de AUTOSAR Adaptive Platform para proporcionar y enriquecer datos de contexto relevantes para la seguridad (<a class="spec-record-ref" data-req="SWS_AIDSM_10500" href="../spec/record.html?id=SWS_AIDSM_10500">[SWS_AIDSM_10500]</a>). Al monitorizar eventos críticos para la seguridad, el IdsM requiere información adicional sobre el entorno y el estado de la aplicación para poder clasificar con precisión las anomalías o los incidentes de seguridad detectados. Como interfaz, <code>ContextDataProvider</code> define el método abstracto <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), a través del cual el IdsM consulta datos del componente de la aplicación según sea necesario.</p>
<p>La interacción tiene lugar entre tres componentes principales:</p>
<ul>
<li><strong>Adaptive Application / subclase proveedora:</strong> la aplicación implementa la lógica concreta del proveedor sobrescribiendo <code>ModifyContextData</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>) y controla el ciclo de vida del objeto de provisión.</li>
<li><strong>Clase base ContextDataProvider:</strong> gestiona la vinculación con el puerto del proveedor modelado en el manifiesto mediante un identificador de instancia (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</li>
<li><strong>Servicio IdsM:</strong> el Intrusion Detection System accede a los datos de contexto en cuanto se ha activado la provisión a través de la interfaz (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>).</li>
</ul>

<h4>Ciclo de vida</h4>
<p>La instanciación de <code>ContextDataProvider</code> se realiza explícitamente a través del constructor, pasando un <code>ara::core::InstanceSpecifier</code>, el número de bytes adicionales (<code>additionalBytes</code>) y el desplazamiento para los datos de contexto originales (<code>originalContextDataOffset</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>). Este constructor está especificado como seguro para subprocesos (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</p>
<p>En cuanto a la semántica de propiedad y de valor, se aplican restricciones estrictas:</p>
<ul>
<li><strong>Copia prohibida:</strong> tanto el constructor de copia (<a class="spec-record-ref" data-req="SWS_AIDSM_10504" href="../spec/record.html?id=SWS_AIDSM_10504">[SWS_AIDSM_10504]</a>) como el operador de asignación por copia (<a class="spec-record-ref" data-req="SWS_AIDSM_10506" href="../spec/record.html?id=SWS_AIDSM_10506">[SWS_AIDSM_10506]</a>) están eliminados (<code>= delete</code>). Una instancia del proveedor está vinculada unívocamente a un puerto modelado y no se puede duplicar.</li>
<li><strong>Movimiento permitido:</strong> la clase dispone de un constructor de movimiento seguro para subprocesos (<a class="spec-record-ref" data-req="SWS_AIDSM_10503" href="../spec/record.html?id=SWS_AIDSM_10503">[SWS_AIDSM_10503]</a>). También se admite la asignación por movimiento mediante <code>operator=</code>, pero no es segura para subprocesos (<code>not thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10505" href="../spec/record.html?id=SWS_AIDSM_10505">[SWS_AIDSM_10505]</a>).</li>
</ul>
<p>Tras la construcción, la instancia se encuentra en un estado inactivo. Solo mediante la llamada explícita a <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) se le indica al IdsM que el proveedor está listo y que se puede invocar <code>ModifyContextData</code>. Con <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>) se interrumpe de nuevo este servicio. La liberación de la instancia se realiza mediante el destructor virtual <code>~ContextDataProvider()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>). Interpretación: para evitar condiciones de carrera durante la ejecución del destructor, probablemente debería invocarse <code>StopOffer()</code> antes de destruir el objeto, ya que ni la destrucción ni la desregistración son seguras para subprocesos (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>).</p>

<h4>Ruta de uso</h4>
<p>El flujo normal para la provisión de datos de contexto comprende las siguientes fases:</p>
<ol>
<li><strong>Derivación:</strong> Interpretación: dado que <code>ModifyContextData</code> es un método virtual puro (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), la aplicación crea su propia clase derivada y sobrescribe esta función.</li>
<li><strong>Creación:</strong> la clase proveedora derivada se instancia especificando el <code>InstanceSpecifier</code> para el puerto del proveedor modelado, el tamaño de búfer adicional y el desplazamiento (<a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>).</li>
<li><strong>Activación:</strong> la aplicación invoca <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>). Tras un registro correcto, el IdsM está autorizado a emitir llamadas de retrollamada al proveedor.</li>
<li><strong>Provisión de contexto:</strong> si se produce un evento de seguridad en el IdsM, el framework invoca <code>ModifyContextData(contextData, event)</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>). La aplicación escribe la información contextual en el búfer de bytes proporcionado (<code>ara::core::Span&lt;std::uint8_t&gt;</code>) y devuelve el número de bytes modificados.</li>
<li><strong>Desactivación:</strong> antes del apagado del componente, la aplicación invoca <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>) para impedir llamadas adicionales por parte del IdsM y destruye la instancia (<a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>).</li>
</ol>

<h4>Escenarios de error</h4>
<p>Los métodos para la gestión del estado y la modificación de datos señalan estados de ejecución a través de <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Fallo de Offer:</strong> el método <code>Offer()</code> devuelve <code>ara::core::Result&lt;void&gt;</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>). Si el puerto del proveedor no se puede registrar (por ejemplo, debido a la falta de recursos del sistema o a un modelado incorrecto), el objeto de resultado contiene el código de error correspondiente. En este caso no se permiten llamadas del IdsM a <code>ModifyContextData</code>.</li>
<li><strong>Fallo en ModifyContextData:</strong> la función de callback devuelve <code>ara::core::Result&lt;std::size_t&gt;</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>). Si la capacidad del <code>ara::core::Span&lt;std::uint8_t&gt;</code> proporcionado no es suficiente o no se puede determinar el contexto para el <code>EventIdType</code> notificado, la clase derivada devuelve un resultado de error en lugar de transmitir un número de bytes.</li>
<li><strong>Precondiciones y poscondiciones:</strong> <code>ModifyContextData</code> solo debe tener lugar entre un <code>Offer()</code> correcto (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>) y <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>). Dado que ni <code>Offer()</code>, ni <code>StopOffer()</code> ni <code>ModifyContextData()</code> son seguros para subprocesos (<a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>), la aplicación invocadora debe asegurarse de que las operaciones del ciclo de vida no se ejecuten de forma concurrente con ejecuciones de callback en curso.</li>
</ul>
