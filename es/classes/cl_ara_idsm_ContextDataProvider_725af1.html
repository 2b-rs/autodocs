Sirve como interfaz para la provisión y modificación de datos de contexto específicos de la aplicación para IdsM.

La clase abstracta ara::idsm::ContextDataProvider sirve para la provisión y modificación específicas de la aplicación de datos de contexto para el Intrusion Detection System Manager [SWS_AIDSM_10500]. Las aplicaciones derivan de la clase, implementan la callback ModifyContextData y controlan la habilitación para IdsM mediante los métodos Offer y StopOffer [SWS_AIDSM_10507]. La instancia no es copiable y, dado que métodos centrales no son seguros para subprocesos (thread-safe), es probable que el acceso concurrente requiera sincronización externa (interpretación).

Contexto

La clase ara::idsm::ContextDataProvider sirve para la provisión y modificación de datos de contexto para el subsistema Intrusion Detection System Manager (IdsM) [SWS_AIDSM_10500]. Dentro de la arquitectura de seguridad, la clase actúa como interfaz entre una aplicación relevante para la seguridad y el servicio IdsM. Dado que la función miembro ModifyContextData está especificada como puramente virtual [SWS_AIDSM_10509], ContextDataProvider representa una clase base abstracta. Una aplicación deriva una implementación propia para añadir datos de contexto específicos en caso de eventos relevantes para la seguridad. La vinculación con la configuración de la arquitectura se realiza mediante un ara::core::InstanceSpecifier para el puerto de proveedor modelado [SWS_AIDSM_10501].

Ciclo de vida

La creación de una instancia se realiza explícitamente a través del constructor indicando el identificador de puerto (ara::core::InstanceSpecifier), así como los parámetros de búfer additionalBytes y originalContextDataOffset [SWS_AIDSM_10501]. Este constructor está declarado como seguro para subprocesos [SWS_AIDSM_10501]. Para garantizar relaciones de propiedad inequívocas para el extremo de la interfaz, tanto el constructor de copia [SWS_AIDSM_10504] como el operador de asignación por copia [SWS_AIDSM_10506] están eliminados. La transferencia de la instancia es posible mediante semántica de movimiento: el constructor de movimiento es seguro para subprocesos [SWS_AIDSM_10503], mientras que el operador de asignación operator= con referencia rvalue está definido como no seguro para subprocesos [SWS_AIDSM_10505].

Tras la creación, la instancia se encuentra en estado inactivo. Solo mediante la llamada explícita a Offer() se activa el registro y se autoriza a IdsM a invocar ModifyContextData [SWS_AIDSM_10507]. Mediante StopOffer(), esta autorización puede revocarse en cualquier momento [SWS_AIDSM_10508]. Antes de la destrucción del objeto mediante el destructor virtual [SWS_AIDSM_10502], según la práctica habitual probablemente deba llamarse a StopOffer() para desactivar a tiempo callbacks en curso por parte de IdsM (interpretación). El destructor virtual está especificado como no seguro para subprocesos [SWS_AIDSM_10502].

Ruta de uso

Un caso de uso típico comienza con la definición de una clase específica de la aplicación que hereda de ContextDataProvider e implementa el método ModifyContextData [SWS_AIDSM_10509]. Tras la instanciación, la aplicación invoca Offer() para poner los datos de contexto a disposición de IdsM [SWS_AIDSM_10507]. Tan pronto como IdsM registra un evento de seguridad para el cual deben agregarse datos de contexto, el subsistema invoca la callback ModifyContextData [SWS_AIDSM_10509]. El método recibe el área de datos como ara::core::Span<std::uint8_t> así como el identificador EventIdType, actualiza el contenido del búfer y devuelve el número real de bytes como ara::core::Result<std::size_t> [SWS_AIDSM_10509]. Si se desea finalizar la provisión de datos, la aplicación invoca StopOffer() [SWS_AIDSM_10508].

Diagrama de secuencia: secuencia de interacción entre aplicación, ContextDataProvider e IdsM desde la activación mediante Offer, pasando por la callback, hasta la desactivación vía StopOffer. Fuentes: [SWS_AIDSM_10507], [SWS_AIDSM_10508], [SWS_AIDSM_10509]

Escenarios de error

Todos los métodos de la interfaz están declarados con noexcept; los errores se devuelven mediante el tipo ara::core::Result. La llamada a Offer() devuelve un ara::core::Result<void> [SWS_AIDSM_10507], que debe ser comprobado por la aplicación para capturar posibles errores en la provisión del servicio. Si el proveedor no puede escribir los datos de contexto solicitados en ModifyContextData, es probable que la implementación reporte un error específico del sistema en ara::core::Result<std::size_t> (interpretación) [SWS_AIDSM_10509].

En cuanto a la concurrencia, debe tenerse en cuenta que Offer() [SWS_AIDSM_10507], StopOffer() [SWS_AIDSM_10508], ModifyContextData() [SWS_AIDSM_10509], el operador de asignación [SWS_AIDSM_10505] y el destructor [SWS_AIDSM_10502] están especificados como no seguros para subprocesos. Si se realizan llamadas a estos métodos en paralelo desde múltiples subprocesos sin sincronización externa, es probable que esto provoque carreras de datos y un comportamiento impredecible (interpretación).

                              Uso y semántica
                              

                              La función puramente virtual ModifyContextData del encabezado ara/idsm/context_data_provider.h es llamada por el Intrusion Detection System Manager (IdsM) para proporcionar o modificar datos de contexto sobre un evento de seguridad [SWS_AIDSM_10509]. La función recibe un área de memoria modificable contextData del tipo ara::core::Span<std::uint8_t>, así como el identificador de evento event del tipo EventIdType. Como valor de retorno síncrono sirve un ara::core::Result<std::size_t>. El valor numérico contenido probablemente represente el número de bytes realmente escritos en el búfer.
                              


                              Zusammenspiel y ciclo de vida
                              

                              La llamada por parte del IdsM está sujeta al control del ciclo de vida del Context-Data-Provider:
                              

                                

                              • Habilitación: las llamadas a ModifyContextData por parte del IdsM solo se hacen posibles mediante la llamada previa a Offer [SWS_AIDSM_10507].
                                • 

                              • Finalización: mediante StopOffer se vuelven a impedir las llamadas del IdsM a ModifyContextData [SWS_AIDSM_10508].
                                • 

                              


                              Tratamiento de errores y concurrencia
