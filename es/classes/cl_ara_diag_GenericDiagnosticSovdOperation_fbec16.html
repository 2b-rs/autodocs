Propósito de uso

GenericDiagnosticSovdOperation es la interfaz de aplicación para una operación de diagnóstico SOVD genérica. El Administrador de diagnóstico (DM) llama a StartExecution cuando se recibe una solicitud SOVD para iniciar la operación especificada; Si es necesario, primero la validación del desafío de proximidad debe tener éxito. [SWS_DM_02203] [SWS_DM_02210] [SWS_DM_02174] La implementación proporciona de forma asíncrona una respuesta de inicio síncrona o asíncrona. Para una respuesta síncrona, el DM deriva los parámetros de la respuesta SOVD positiva del DiagnosticSovdContentData devuelto. [SWS_DM_02210] [SWS_DM_02176]

Generación y amp; destrucción

La instancia se crea con un InstanceSpecifier para un PortPrototype del DiagnosticDataIdentifierGenericInterface y un ConcurrencyType. Offer() activa el reenvío de solicitudes a través del DM, StopOffer() lo desactiva nuevamente. [SWS_DM_02204] [SWS_DM_02211] [SWS_DM_02212] Se rechaza una nueva oferta con DiagOfferErrc::kAlreadyOffered. [SWS_DM_02211]

Ciclo de vida y propiedad

La interfaz es móvil: se proporcionan construcción de movimiento y asignación de movimiento. [SWS_DM_02206] [SWS_DM_02207] El destructor es noexcept, seguro frente a excepciones y subprocesos. [SWS_DM_02205]

Limitaciones y Manejo de errores

Los datos del parámetro sovd_content_data solo permanecen válidos hasta que se cumpla el Promise o hasta que se procese un mensaje de aborto. El CancellationHandler no se puede almacenar ni utilizar más allá de la vida útil de esta operación. Los errores de ejecución se proporcionarán como un código de error SOVD aplicable. [SWS_DM_02210] Offer() y StopOffer() no son seguros para subprocesos; StartExecution es seguro para hilos. [SWS_DM_02211] [SWS_DM_02212] [SWS_DM_02210]

StartExecution puede devolver una respuesta de inicio síncrona o asíncrona como variante y es una función virtual pura que, por lo tanto, debe ser implementada por la aplicación. [SWS_DM_02210] El constructor en sí es seguro para excepciones y subprocesos. [SWS_DM_02204]

SOVD contexto

Para los casos de uso de SOVD correspondientes a UDS, reutilizar la misma instancia de puerto que el servicio UDS correspondiente es un principio rector; Se aplican las mismas reglas con respecto a la reentrada y la ejecución paralela.
