Propósito de uso

<SI>Proxy es el Proxy del lado del cliente de un Service Interface. La cadena de herramientas de generación la crea a partir del modelo ServiceInterface del ARXML-Manifest; De aquí se deriva el SI-Namespace jerárquico y el nombre de la clase. El Header declarado sigue el esquema <SiNamespaceDerivedDirectoryPath>/<SiShortname>_proxy.h. Para cada elemento de interfaz modelado como Event, Field o método, Proxy contiene un miembro correspondiente. [SWS_CM_00004] [SWS_CM_99445] [SWS_CM_99446] [SWS_CM_99447]

Generación y amp; destrucción

Se puede construir un proxy directamente a partir de un HandleType obtenido por FindService() o StartFindService(). Alternativamente, el Create() de fábrica seguro para excepciones ofrece un ara::core::Result con proxy o un ara::com::ComErrc coincidente. Se declara el destructor, pero no se garantiza su seguridad excepcional. [SWS_CM_00131] [SWS_CM_10438] [SWS_CM_99444]

Ciclo de vida y propiedad

Se prohíbe la construcción y asignación de copias (=delete); el Proxy es móvil. La asignación de Move es noexcept y es segura para excepciones, pero el constructor Move no está especificado como seguro frente a excepciones. GetHandle() devuelve el Handle utilizado para generarlo. [SWS_CM_00136] [SWS_CM_11551] [SWS_CM_00137] [SWS_CM_11552] [SWS_CM_10383]

Interacción con otras clases.

La búsqueda inmediata utilizando FindService() acepta InstanceIdentifier o InstanceSpecifier y devuelve identificadores coincidentes. La búsqueda de registro a través de StartFindService() llama a un controlador cuando se encuentran instancias de servicio coincidentes; el FindServiceHandle devuelto finaliza la monitorización con StopFindService(). Un controlador de estado puede observar cambios en la disponibilidad del servicio y ser reemplazado o eliminado en tiempo de ejecución; Las sobrecargas permiten un contexto de ejecución para esto. [SWS_CM_00122] [SWS_CM_00622] [SWS_CM_00123] [SWS_CM_00623] [SWS_CM_11352] [SWS_CM_11365] [SWS_CM_00125] [SWS_CM_01074] [SWS_CM_01076] [SWS_CM_01075]

Acceso al elemento & Manejo de errores

Para los elementos de interfaz generados, los eventos y las notificaciones de campo se activan con Subscribe() y se recuperan del caché local a través de GetNewSamples(). Los campos también permiten Get() y Set() asincrónicos. Los métodos no modelados como Fire-and-Forget devuelven un ara::core::Future cuando se los llama inmediatamente para evaluar el resultado o el error. [SWS_CM_11601] [SWS_CM_11610] [SWS_CM_00112] [SWS_CM_00113] [SWS_CM_00196]

Las consultas de búsqueda y estado, la fábrica, así como las operaciones de controlador y detención se especifican como seguras para excepciones. La búsqueda fallida, la creación de fábrica o la consulta de estado están representadas por ara::core::Result con un ComErrc correspondiente. [SWS_CM_00122] [SWS_CM_00622] [SWS_CM_10438] [SWS_CM_01073]

Incrustación arquitectónica

El proxy y el esqueleto son artefactos de código generados a partir de una definición formal de servicio: el proxy es la fachada local del consumidor, mientras que el esqueleto conecta la implementación del servicio con la capa de transporte de gestión de comunicaciones. EXP ARAComAPI §4.1 «Proxy/Skeleton Architecture»

Service Discovery y Handle

FindService() proporciona las instancias disponibles actualmente como identificadores, StartFindService() monitorea los cambios de disponibilidad y también informa inicialmente al controlador registrado con la lista actual, posiblemente vacía. El identificador encapsula la información de la dirección específica del enlace y deja abierta intencionalmente si varias instancias de proxy representan el mismo servicio.
