Sirve a las aplicaciones cliente como sustituto tipificado para la búsqueda de servicios y la interacción con una instancia de servicio.

La clase <SI>Proxy sirve a las aplicaciones cliente como sustituto tipificado para un Service Interface con el fin de transferir llamadas a métodos, eventos y campos [SWS_CM_99447]. Tras una búsqueda exitosa de servicios, la instancia se crea preferentemente a través del método de fábrica Create() libre de excepciones [SWS_CM_10438]. La clase posee semántica de solo movimiento y exige la liberación completa de todas las muestras de datos referenciadas antes de su destrucción para evitar violaciones de condiciones previas [SWS_CM_99444].

Contexto

La clase generada <SI>Proxy actúa dentro de la arquitectura de comunicación de AUTOSAR Adaptive Platform como un punto de conexión de cliente tipificado para un Service Interface definido. Encapsula la interacción de una aplicación cliente con una instancia remota o local de este servicio. Entre los interlocutores se encuentran el componente de software cliente, la propia instancia proxy y la gestión de comunicación subyacente (ara::com), que controla la vinculación de red y la transmisión de mensajes. A través de los elementos de datos dedicados events::<Event> [SWS_CM_99445], fields::<Field> [SWS_CM_99446] y methods::<Method> [SWS_CM_99447], el proxy proporciona acceso directo a eventos, campos y métodos de la interfaz de servicio.

Diagrama de contexto: integración del proxy de Service Interface entre la aplicación cliente y la gestión de comunicación. Fuentes: [SWS_CM_99445], [SWS_CM_99446], [SWS_CM_99447].

Ciclo de vida

La creación de una instancia proxy presupone una búsqueda de servicio realizada previamente con éxito que proporcione una instancia de identificador válida (HandleType). La creación preferida se realiza libre de excepciones mediante el método factoría estático Create() según el modismo de constructor con nombre (named constructor idiom) [SWS_CM_10438], que devuelve un ara::core::Result con el proxy o un código de error. Alternativamente, existe un constructor explícito <SI>Proxy(handle), especificado como no seguro frente a excepciones y que, en caso de error, puede lanzar una ara::com::ComException [SWS_CM_00131]. El identificador utilizado para la inicialización puede consultarse en cualquier momento mediante GetHandle() [SWS_CM_10383].

En cuanto a las relaciones de propiedad, el proxy posee semántica de solo movimiento: el constructor de copia [SWS_CM_00136] y el operador de asignación por copia [SWS_CM_11551] están explícitamente eliminados. La transferencia de la instancia solo está permitida mediante el constructor de movimiento [SWS_CM_00137] o el operador de asignación por movimiento seguro frente a excepciones [SWS_CM_11552]. Durante la vida útil, el estado de disponibilidad del servicio puede determinarse activamente mediante GetServiceState() [SWS_CM_01073]. Alternativamente, SetServiceStateChangeHandler() permite registrar una función de retrollamada ante cambios de estado [SWS_CM_01074], la cual puede vincularse opcionalmente a un contexto definido por el usuario mediante un ExecutorT [SWS_CM_01076]. El registro del manejador se puede anular mediante UnsetServiceStateChangeHandler() [SWS_CM_01075].

La destrucción se realiza a través del destructor ~<SI>Proxy() [SWS_CM_99444]. Este está declarado como no seguro frente a excepciones y exige como condición previa obligatoria que el cliente ya no retenga muestras de datos abiertas antes de la destrucción para evitar violaciones [SWS_CM_99444].

Ruta de uso

La ruta típica de uso se divide en cuatro fases:

  1. Búsqueda de servicios: el cliente busca instancias del servicio de forma síncrona a través de FindService() con un InstanceIdentifier [SWS_CM_00122] o un InstanceSpecifier [SWS_CM_00622] EXP ARAComAPI §2 «Service Interface Proxy» basado en modelo, o de forma asíncrona a través de StartFindService() [SWS_CM_00123] [SWS_CM_00623]. Para búsquedas asíncronas se puede pasar adicionalmente un ExecutorT [SWS_CM_11352] [SWS_CM_11365] EXP ARAComAPI §2 «Service Interface Proxy». Las búsquedas asíncronas deben detenerse mediante StopFindService() una vez encontrada la instancia deseada [SWS_CM_00125] EXP ARAComAPI §2 «Service Interface Proxy».
  2. Instanciación: a partir del ServiceHandleContainer determinado, se selecciona un identificador y se pasa a Create() para crear la instancia proxy [SWS_CM_10438]. Interpretación: es de suponer que el método factoría Create() constituya la ruta de instanciación primaria frente al constructor que lanza excepciones.
  3. Interacción: la aplicación interactúa con el servicio a través de llamadas a métodos (methods::<Method>) [SWS_CM_99447], supervisión de eventos (events::<Event>) [SWS_CM_99445] o accesos a campos (fields::<Field>) [SWS_CM_99446].
  4. Limpieza: tras finalizar las interacciones, se destruye la instancia proxy, debiéndose garantizar que no queden referencias a muestras no válidas [SWS_CM_99444].

Diagrama de secuencia: flujo típico de búsqueda de servicio, instanciación del proxy e interacción de métodos. Fuentes: [SWS_CM_00122], [SWS_CM_10438], [SWS_CM_99447], [SWS_CM_99444].

Escenarios de error

Los errores se notifican principalmente a través del tipo de error ara::com::ComErrc en ara::core::Result:

  • ComErrc::kServiceNotAvailable: se produce en Create() cuando un servicio ofrecido previamente ya no está disponible [SWS_CM_10438]. En caso de invocación directa del constructor, esto resulta en cambio en una ara::com::ComException [SWS_CM_00131].
  • ComErrc::kCommunicationFailure: lo notifican FindService() [SWS_CM_00122] [SWS_CM_00622], StartFindService() [SWS_CM_00123] [SWS_CM_00623], Create() [SWS_CM_10438] y GetServiceState() [SWS_CM_01073] cuando la vinculación de red detecta un error de comunicación recuperable o un error en la comunicación segura.

Adicionalmente se especifican las siguientes violaciones (Violations):

  • ErroneousServiceHandleViolation: el identificador pasado a Create() o al constructor no es válido o está corrupto [SWS_CM_10438] [SWS_CM_00131].
  • InsufficientPermissionsViolation: denegación del acceso durante la búsqueda de servicios o la instanciación por parte de Grant Enforcement [SWS_CM_00122] [SWS_CM_10438].
  • InvalidHandlerViolation: transferencia de una retrollamada no válida o vacía a StartFindService() [SWS_CM_00123] o SetServiceStateChangeHandler() [SWS_CM_01074].
  • InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation, ProcessMappingViolation, InstanceSpecifierAlreadyInUseViolation: se producen en llamadas de búsqueda basadas en modelo si la asignación de InstanceSpecifier es incorrecta o ya está en uso [SWS_CM_00622] [SWS_CM_00623].
  • DanglingSamplesViolation: destrucción del proxy cuando aún existen referencias a muestras de datos [SWS_CM_99444].

Esta guía se basa en las especificaciones de AUTOSAR para Adaptive Platform Release R25-11 y resume los mecanismos de comunicación del proxy de Service Interface.

Uso y semántica

El método de fábrica estático Create sirve, conforme a [SWS_CM_10438], para la creación libre de excepciones de una instancia de proxy (<SI>Proxy) según el modismo de constructor nombrado. Requiere como parámetro handle un handle de servicio determinado previamente según [SWS_CM_00131]. La llamada se realiza de forma síncrona y está declarada como noexcept. El resultado se devuelve en un ara::core::Result que, en caso de éxito, contiene la instancia de proxy lista para operar.

Manejo de errores

Si se produce un error durante la instanciación, Create devuelve a través de ara::core::Result un código de error de tipo ara::com::ComErrc [SWS_CM_10438]:

  • ComErrc::kServiceNotAvailable: El servicio ya no está disponible tras haber sido ofrecido previamente a través de OfferService().
  • ComErrc::kCommunicationFailure: El binding de red notifica un error de comunicación recuperable o el fallo de una conexión protegida.

Ambos errores presentan una semántica de reversión (rollback) [SWS_CM_10438]. En caso de errores estructurales o de seguridad, se aplican las vulneraciones especificadas (violations): Si el handle transferido es nulo o está corrupto, se produce una ErroneousServiceHandleViolation. Si el proceso invocador carece de los permisos necesarios para la instancia en el marco del Grant Enforcement, la solicitud se rechaza y se trata como InsufficientPermissionsViolation (SWS CommunicationManagement §8 «Security», [SWS_CM_10438]).

Concurrencia y condiciones de contorno

Interpretación: Dado que Create opera de forma síncrona y vincula recursos de comunicación, es de suponer que la llamada sea reentrante para handles diferentes, pero no debería ejecutarse en bucles de tiempo real estricto (hard real-time) críticos en el tiempo debido a posibles inicializaciones de red.

      El método estático FindService de la clase de proxy sirve para la localización síncrona de instancias de servicio disponibles mediante un ara::com::InstanceIdentifier ([SWS_CM_00122]). Este contenedor —implementado típicamente como ara::core::Vector ([SWS_CM_00304])— puede estar vacío, comprender un único manipulador de instancia o varios manipuladores en función del estado de provisión actual (ARAComAPI §6.5 «Service Discovery»).
      

      En caso de error, el ara::core::Result devuelve un código de error de ara::com::ComErrc, concretamente ComErrc::kCommunicationFailure, si el enlace de red notifica un error de transmisión recuperable o un problema en la comunicación segura ([SWS_CM_00122]). Además, el acceso está sujeto a una verificación de permisos; unos permisos insuficientes dan lugar a una InsufficientPermissionsViolation ([SWS_CM_00122]).
      

      En lo que respecta a la secuencia y a la concurrencia, se aplican las siguientes condiciones:
      

        

      • Contexto de llamada y sincronía: dado que la búsqueda se ejecuta inmediatamente, solo se encuentran aquellas instancias para las que se haya llamado previamente a OfferService() en el lado del servidor (ARAComAPI §6.5 «Service Discovery»).
        • 

      • Seguridad ante excepciones y reentrancia: la función está especificada como noexcept y segura ante excepciones ([SWS_CM_00122]). Puesto que el método es estático y no requiere un estado de objeto mutable, es de suponer que se puede invocar de forma reentrante y segura para subprocesos.
        • 

      • Procesamiento posterior: los manipuladores encontrados sirven para la instanciación de objetos de proxy a través del constructor Proxy(const HandleType &handle) ([SWS_CM_00131]). Para una búsqueda basada en modelos, se encuentra disponible alternativamente la sobrecarga con ara::core::InstanceSpecifier ([SWS_CM_00622]).

  Procedencia
  

                                                          

                                                          

                                                          La función estática de plantilla StartFindService inicia la búsqueda continua y asíncrona de instancias de servicio a partir de un ara::core::InstanceSpecifier mediante el registro de un manejador de notificaciones en un contexto de ejecución transferido [SWS_CM_11365]. A diferencia de las búsquedas únicas síncronas, inicia una actividad en segundo plano para supervisar la disponibilidad del servicio y devuelve un ara::com::FindServiceHandle EXP_ARAComAPI §5.3 «Proxy Class APIs».
                                                          

                                                          Parámetros y ejecución
                                                          

                                                          La función acepta tres parámetros [SWS_CM_11365]:
                                                          

                                                            

                                                          • handler: Función de devolución de llamada de tipo ara::com::FindServiceHandler conforme a [SWS_CM_00123], a la que se llama ante cambios en la disponibilidad de la instancia.
                                                            • 

                                                          • instance: El ara::core::InstanceSpecifier a buscar conforme a [SWS_CM_00123].
                                                            • 

                                                          • executor: Un contexto de ejecución del tipo de plantilla ExecutorT conforme a [SWS_CM_11360]. Interpretación: Es probable que el argumento de plantilla ExecutorT determine en qué contexto de hilo o tarea se ejecutará la devolución de llamada registrada.
                                                            • 

                                                          

                                                          Tratamiento de errores y condiciones límite
                                                          

                                                          La firma está declarada como noexcept y especificada como exception safe [SWS_CM_11365]. En la especificación se definen violaciones funcionales (Violations): InstanceSpecifierMappingIntegrityViolation (resolución fallida en el contexto de Executable o no es un PortPrototype), PortInterfaceMappingViolation y ProcessMappingViolation (asignaciones de PortInterface no coincidentes), InstanceSpecifierAlreadyInUseViolation, InvalidHandlerViolation (manejador inválido o inexistente), así como InsufficientPermissionsViolation en caso de falta de autorización de acceso [SWS_CM_11365].
                                                          

                                                          Interacción
                                                          

                                                          El FindServiceHandle obtenido sirve para finalizar de forma controlada la monitorización continua en segundo plano transfiriéndolo a StopFindService [SWS_CM_00125]. Los identificadores notificados al manejador se utilizan para instanciar proxies de servicio concretos mediante Proxy(handle) [SWS_CM_00131]. Para búsquedas mediante ara::com::InstanceIdentifier existe una sobrecarga alternativa [SWS_CM_11352].

  Procedencia
  

                                                              

                                                              

                                                              La función estática StopFindService de la clase proxy finaliza una búsqueda de servicio asincrónica iniciada previamente con StartFindService y detiene la recepción de nuevas notificaciones para el manejador suministrado [SWS_CM_00125]. Con ello se suspende la actividad en segundo plano en curso para la monitorización de la disponibilidad del servicio por parte del enlace técnico AP EXP ARAComAPI §5.3 «Proxy Class API’s».
                                                              

                                                              Uso y semántica
                                                              

                                                                

                                                              • Parámetros: como parámetro de entrada, la función espera un ara::com::FindServiceHandle obtenido previamente mediante uno de los métodos StartFindService ([SWS_CM_00123], [SWS_CM_00623], [SWS_CM_11352], [SWS_CM_11365], [SWS_CM_00125]).
                                                                • 

                                                              • Valor devuelto y seguridad frente a fallos: la función no tiene valor devuelto (void), está declarada con noexcept y especificada como segura frente a excepciones [SWS_CM_00125].
                                                                • 

                                                              • Concurrencia y contexto de llamada: una llamada a StopFindService está expresamente permitida también directamente dentro de la función de callback definida por el usuario FindServiceHandler [SWS_CM_00383] AP EXP ARAComAPI §5.3 «Proxy Class API’s». Para este propósito, se pasa al manejador el respectivo FindServiceHandle como parámetro [SWS_CM_00383]. Dado que el callback en sí no necesita ser reentrante, el implementador del binding debe garantizar la serialización de las llamadas sucesivas AP EXP ARAComAPI §5.3 «Proxy Class API’s».
