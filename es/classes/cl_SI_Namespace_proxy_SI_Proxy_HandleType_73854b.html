Handle for a specific AdaptivePlatformServiceInstance. It contains the information that is needed to create a service proxy. Encapsula información de direccionamiento de instancias de servicio encontradas para la gestión flexible y la construcción de proxies de servicio.

La clase HandleType representa una instancia de servicio encontrada y proporciona la información de dirección técnica requerida para la construcción de un proxy de servicio (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»). Dado que el constructor predeterminado está eliminado ([SWS_CM_00349]), el handle se obtiene mediante funciones de búsqueda como FindService y, gracias a su plena capacidad de copia, movimiento y comparación, puede gestionarse de forma flexible en contenedores. Tras la comprobación de la identidad de la instancia, sirve como parámetro de constructor obligatorio para la creación del proxy de comunicación propiamente dicho.

Contexto

La clase <SI-Namespace>::proxy::<SI>Proxy::HandleType representa un handle específico de instancia para una instancia de servicio encontrada de la Adaptive Platform (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»). Encapsula toda la información técnica de direccionamiento que Communication Management y su implementación de binding en la capa de transporte necesitan para establecer una relación de comunicación con una instancia de servicio concreta (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»). Como clase anidada del proxy de servicio generado, HandleType desacopla la detección de instancias de servicio de la creación de los objetos proxy propiamente dichos (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»). Dado que las instancias de proxy poseen estado y no son copiables ni asignables, esta indirección permite que la aplicación decida si crea varios proxies independientes para el mismo servicio o si reutiliza proxies existentes (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»).

Ciclo de vida

El constructor predeterminado de HandleType está explícitamente eliminado ([SWS_CM_00349]). Por consiguiente, las instancias no pueden ser instanciadas libremente por la aplicación, sino que se generan exclusivamente de manera controlada mediante mecanismos de Communication Management como FindService o controladores de búsqueda asíncronos (AUTOSAR_AP_EXP_ARAComAPI §5.3 «Proxy Class», AUTOSAR_AP_EXP_ARAComAPI §6.5 «Service Discovery»).

Un handle creado está concebido como un tipo de valor completo: implementa tanto el constructor de copia ([SWS_CM_00317]) como el constructor de movimiento ([SWS_CM_00318]), así como los correspondientes operadores de asignación ([SWS_CM_11532], [SWS_CM_11533]). Además, HandleType cumple los requisitos de equalitycomparable a través de operator== ([SWS_CM_11529]) y lessthancomparable a través de operator< ([SWS_CM_11530]). Estas propiedades permiten a la aplicación almacenar, ordenar y gestionar de manera flexible handles encontrados en contenedores estándar (como listas, conjuntos ordenados o memorias asociativas). La destrucción se produce de forma determinista mediante el destructor especificado como seguro frente a excepciones ([SWS_CM_11371]).

Ruta de uso

El flujo típico comienza con la búsqueda de servicios ofrecidos a través de los métodos estáticos FindService de la clase proxy (AUTOSAR_AP_EXP_ARAComAPI §6.5 «Service Discovery», ARAComAPI §6.5 «Service Discovery»). Como resultado, Communication Management devuelve un ara::com::ServiceHandleContainer que puede contener cero, uno o varios ejemplares de HandleType (AUTOSAR_AP_EXP_ARAComAPI §6.5 «Service Discovery»).

La aplicación puede seleccionar un handle del contenedor y consultar a través de GetInstanceId() la correspondiente ara::com::InstanceIdentifier ([SWS_CM_11531]). A continuación, la aplicación pasa el handle al constructor de la clase proxy, el cual genera a partir de él el objeto proxy de comunicación listo para su uso (AUTOSAR_AP_EXP_ARAComAPI §5.3.3 «Constructor and Handle Concept»). Escenarios de error

Al utilizar HandleType deben tenerse en cuenta condiciones límite definidas de los métodos. Las operaciones para copiar, mover y comparar, así como la consulta del ID de instancia GetInstanceId(), están clasificadas explícitamente como no seguras frente a excepciones (not exception safe) ([SWS_CM_00317], [SWS_CM_00318], [SWS_CM_11529], [SWS_CM_11530], [SWS_CM_11531], [SWS_CM_11532], [SWS_CM_11533]). Únicamente el destructor garantiza con noexcept una seguridad total frente a excepciones ([SWS_CM_11371]).

Si en una búsqueda de servicios no se determina ninguna instancia coincidente en la red, FindService devuelve un ServiceHandleContainer vacío (AUTOSAR_AP_EXP_ARAComAPI §6.5 «Service Discovery»). En este caso no existe ningún handle válido, por lo que debe omitirse la construcción de un proxy de servicio. La asignación y la comparación de handles inválidos o procedentes de objetos movidos probablemente provoquen un comportamiento indefinido a nivel de binding.

Esta guía se basa en los requisitos y documentos de concepto de AUTOSAR Adaptive Platform Release R25-11.
