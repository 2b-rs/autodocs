Papel en el servicio

HandleType es la prueba de una instancia de servicio encontrada, específica del enlace, pero encapsulada para el código de la aplicación. La búsqueda de servicios produce identificadores; la clase de proxy generada lo utiliza como entrada para su creación. EXP ARAComAPI §5.3.3 «Constructor and Handle Concept» y SWS CM §7.5.11 «Service proxy creation» ilustran la separación de búsqueda y proxy con estado.

Tratamiento práctico

La aplicación no crea el Handle en sí, sino que lo retiene de FindService o Find-Handler. GetInstanceId() proporciona la referencia de instancia vinculada a él, por ejemplo para comparar una instancia que vuelve a estar disponible. La forma detallada del Handle queda deliberadamente oculta por la unión de la red. [SWS_CM_11531] y EXP ARAComAPI §4.8.1 «Instance Identifiers and Instance Specifiers» son los documentos relevantes.

Secuencia: Discovery entrega identificadores; Esto crea un proxy utilizable. La reconexión automática de un proxy existente es un comportamiento de ejecución específico. Fuentes: SWS CM §7.5.10 «Find service», SWS CM §7.5.11 «Service proxy creation».

Consultar la referencia de instancia

GetInstanceId() proporciona el identificador con el que este identificador representa la instancia de servicio encontrada. Úselo para comparar identidades entre los identificadores informados por Discovery y los proxies ya establecidos, no para interpretar elementos internos vinculantes. EXP ARAComAPI §5.3.3 «Constructor and Handle Concept» explica la encapsulación.

Proceso típico
  1. Mango obtenido de FindService o manipulador.
  2. Utilice GetInstanceId() sólo como valor de comparación o diagnóstico.
  3. Controle la creación del proxy y administre la vida útil del proxy por separado.
