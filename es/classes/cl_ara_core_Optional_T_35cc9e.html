Encapsula una referencia opcional a un objeto y permite un acceso seguro sin asignación dinámica de memoria.

La especialización ara::core::Optional<T &> sirve como contenedor con seguridad de tipos para referencias a lvalue opcionales con el tipo de elemento T & [SWS_CORE_01151]. Permite reasignar o restablecer la referencia en tiempo de ejecución sin asignación dinámica de memoria [SWS_CORE_01164], [SWS_CORE_01165]. Antes de cada acceso mediante operadores de indirección o el método de acceso potencialmente generador de errores value(), es obligatorio comprobar la presencia de un objeto de destino válido [SWS_CORE_01172], [SWS_CORE_01173].

Contexto

La especialización de plantilla ara::core::Optional<T &> proporciona un contenedor con seguridad de tipos para una referencia a lvalue opcional. El tipo de elemento subyacente se define como T & mediante el alias de tipo value_type [SWS_CORE_01151]. A diferencia de la plantilla primaria para tipos por valor, esta especialización sirve como referencia reutilizable y revinculable (Rebindable Reference) que apunta a un objeto existente del tipo T o representa un estado desocupado. Interactúa directamente con componentes de software llamantes y el objeto de destino referenciado, sin ocupar memoria dinámica.

Ciclo de vida

Una instancia de ara::core::Optional<T &> se encuentra siempre en uno de dos estados bien controlados: Vacío (no asignado) u Ocupado (referencia a un objeto). El estado vacío se adopta mediante el constructor predeterminado [SWS_CORE_01152] o la inicialización con nullopt_t [SWS_CORE_01153]. La vinculación a una referencia tiene lugar durante la construcción mediante la transferencia de un valor compatible o una referencia [SWS_CORE_01156], así como a través de constructores de conversión [SWS_CORE_01157]. Los constructores de copia y de movimiento transfieren el estado del contenedor de origen [SWS_CORE_01154], [SWS_CORE_01155].

En tiempo de ejecución, el estado puede modificarse dinámicamente: la asignación de un valor o de una referencia revincula el Optional al objeto de destino transferido [SWS_CORE_01162], lo que también ocurre mediante operadores de asignación de otros contenedores Optional [SWS_CORE_01159], [SWS_CORE_01160], [SWS_CORE_01163] o el método emplace [SWS_CORE_01164]. La transición al estado vacío se produce llamando a reset [SWS_CORE_01165] o mediante la asignación de nullopt_t [SWS_CORE_01161]. Además, swap permite el intercambio atómico de dos instancias [SWS_CORE_01166]. El destructor predeterminado finaliza el tiempo de vida de la instancia envoltorio [SWS_CORE_01158], pero presumiblemente no afecta al objeto original referenciado, ya que semánticamente una referencia no establece propiedad.

Diagrama de estados: estados y transiciones de estado de una instancia de ara::core::Optional<T &>. Fuentes: [SWS_CORE_01152], [SWS_CORE_01153], [SWS_CORE_01156], [SWS_CORE_01161], [SWS_CORE_01162], [SWS_CORE_01164], [SWS_CORE_01165].

Ruta de uso

Un ciclo de uso típico abarca la creación, validación y el acceso de lectura o modificación al destino referenciado:

  1. Inicialización: Se crea una instancia vacía [SWS_CORE_01152] o se asigna con la referencia a un objeto existente [SWS_CORE_01156].
  2. Comprobación de estado: Antes de la indirección, el llamante comprueba la existencia de una referencia a través del operador de conversión explícito operator bool [SWS_CORE_01171] o del método has_value [SWS_CORE_01172].
  3. Acceso: Tras confirmarse la referencia, el acceso al objeto referenciado se realiza a través de los operadores de indirección operator* [SWS_CORE_01169], [SWS_CORE_01170] o del operador flecha operator-> [SWS_CORE_01167], [SWS_CORE_01168]. Alternativamente, value_or devuelve el valor referenciado o un valor predeterminado especificado [SWS_CORE_01175].
  4. Restablecimiento: Tras finalizar el procesamiento, la referencia se elimina explícitamente en caso necesario mediante reset [SWS_CORE_01165].

Diagrama de secuencia: flujo típico de inicialización, verificación e indirección de una referencia opcional. Fuentes: [SWS_CORE_01156], [SWS_CORE_01165], [SWS_CORE_01170], [SWS_CORE_01172].

Escenarios de error

Los errores ocurren principalmente ante intentos de acceso prematuros o no permitidos a instancias vacías. Si se llama a value() mientras el objeto no contiene ningún valor, se desencadena una infracción del tipo IsoStdBadOption-alAccessViolation [SWS_CORE_01173], [SWS_CORE_01174]. En consecuencia, value(), a diferencia de la mayoría de las demás operaciones de la clase, no está clasificado explícitamente como seguro contra excepciones (not exception safe).

Las indirecciones directas mediante operator* [SWS_CORE_01169], [SWS_CORE_01170] así como operator-> [SWS_CORE_01167], [SWS_CORE_01168] también documentan una infracción de la categoría IsoStdBadOption-alAccessViolation si la instancia no contiene ninguna referencia. Aunque estos operadores están declarados con noexcept, su uso exige obligatoriamente el cumplimiento de la precondición de que exista una referencia válida.

El operador de acceso a miembros operator-> de la clase de plantilla ara::core::Optional<T &> sirve para el acceso síncrono a miembros del objeto referenciado [SWS_CORE_01167]. La función está definida en la cabecera #include "ara/core/optional.h", pertenece al alcance de ara::core::Optional<T &> y no espera parámetros [SWS_CORE_01167]. Como valor de retorno se devuelve un puntero del tipo T const *, que permite un acceso directo de lectura al objeto de destino subyacente [SWS_CORE_01167]. Así, el tipo de retorno corresponde a un puntero a datos constantes, impidiendo accesos modificadores a través de este operador.

En cuanto al tratamiento de errores, el método está declarado como noexcept y clasificado como exception safe [SWS_CORE_01167]. Sin embargo, si la instancia no contiene un valor (If *this does not contain a value), la especificación documenta una IsoStdBadOptionalAccessViolation como infracción [SWS_CORE_01167]. En consecuencia, antes de la desreferenciación, el software de aplicación debe asegurarse de que la referencia opcional esté asignada de forma válida para evitar estados de error en tiempo de ejecución de manera fiable.

Para la concurrencia y el contexto de llamada, la especificación no menciona mecanismos de protección especiales; es probable que la operación const no ofrezca sincronización interna frente a modificaciones concurrentes [SWS_CORE_01167]. El comportamiento general se rige, según la especificación, por el uso correspondiente del estándar C++ para tipos opcionales (As per corresponding usage in [optional]) [SWS_CORE_01167].
