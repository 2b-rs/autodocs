[SWS_DM_01961] Upstream: RS_Diag_04251

class TransmitCertificate {...};

Class to implement the subfunction TransmitCertificate (29 04) of UDS service Authentication as interface to application. This class implements a so called generic interface, where the application has means to handle one ore more certificateEvaluationId transferred certificates.

Contexto

La clase ara::diag::TransmitCertificate proporciona la interfaz de programación para la subfunción UDS TransmitCertificate (0x29 04) del servicio Authentication (0x29) AUTOSAR_AP_SWS_Diagnostics §8.26.1 «Class: TransmitCertificate». Implementa una interfaz genérica a través de la cual una aplicación Adaptive puede recibir y evaluar uno o varios certificados identificados mediante un identificador de 16 bits (certificateEvaluationId).

En la arquitectura del sistema, ara::diag::TransmitCertificate actúa como enlace entre el AUTOSAR Adaptive Diagnostic Manager (DM) o la Diagnostic Server Instance y la lógica de aplicación concreta. Un comprobador de diagnóstico externo envía la solicitud de autenticación UDS al servidor, que reenvía la solicitud a la aplicación tras la activación [SWS_DM_01968], [SWS_DM_01251].

Diagrama de contexto: integración de TransmitCertificate entre el comprobador de diagnóstico, Diagnostic Manager y la lógica de aplicación. Fuentes: [SWS_DM_01968], [SWS_DM_01251], [SWS_DM_01249].

Ciclo de vida

La instanciación se realiza a través del constructor especificando un [SWS_DM_01962]:

  • specifier: Un ara::core::InstanceSpecifier que apunta a un PortPrototype, el cual se tipa a través de un DiagnosticAuthenticationPortMapping [SWS_DM_01962].
  • concurrencyType: Determina si la ejecución posterior de Process se trata como segura para subprocesos (kConcurrent) o no segura para subprocesos (kNotConcurrent) [SWS_DM_01962], [SWS_DM_01968].

Las operaciones de copia y de movimiento están completamente deshabilitadas: el constructor de copia [SWS_DM_01964], el constructor de movimiento [SWS_DM_01963], el operador de asignación por copia [SWS_DM_01966] y el operador de asignación por movimiento [SWS_DM_01965] están declarados como eliminados (=delete). Por lo tanto, una instancia de interfaz de autenticación existe como un objeto vinculado de forma exclusiva.

Tras la construcción, el ciclo de vida se divide en dos fases operativas:

  1. Suministro (Offered): Mediante la llamada a Offer(), se autoriza a Diagnostic Manager a reenviar los mensajes UDS entrantes para la subfunción al método Process() [SWS_DM_01969].
  2. Revocación (Stopped): La llamada a StopOffer() anula de nuevo el registro del reenvío [SWS_DM_01970].

El destructor es virtual y está declarado por defecto (noexcept = default) [SWS_DM_01967]. Mientras que el constructor es seguro para subprocesos, Offer() y StopOffer() están especificados como no seguros para subprocesos y no deben llamarse de forma concurrente no coordinada [SWS_DM_01962], [SWS_DM_01969], [SWS_DM_01970].

Ruta de uso

El flujo de funcionamiento normal incluye el registro en Diagnostic Manager, la recepción asíncrona de los datos del certificado y la finalización del procesamiento:

  1. Instanciación y habilitación: La aplicación instancia la clase derivada y activa la aceptación mediante Offer() [SWS_DM_01962], [SWS_DM_01969].
  2. Recepción y procesamiento: Al recibir una solicitud UDS, el Diagnostic Server reenvía los datos a través de Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler) [SWS_DM_01968]. El método devuelve un ara::core::Future<void>, con lo que se admite un procesamiento asíncrono. La semántica concreta y la evaluación del certificado corresponden por completo a la aplicación [SWS_DM_01968].
  3. Tratamiento de cancelaciones: La aplicación puede comprobar mediante cancellationHandler.IsCanceled() si se canceló la conversación de diagnóstico, o registrar a través de cancellationHandler.SetNotifier() una callback de notificación para eventos de cancelación [SWS_DM_01968].
  4. Respuesta positiva: Si la ejecución finaliza con éxito sin código de error, la Diagnostic Server Instance transmite una respuesta UDS positiva con el parámetro de retorno authenticationReturnParameter = 0x13 (CertificateVerified) al tester [SWS_DM_01251].
  5. Limpieza: Al finalizar, la recepción se termina mediante StopOffer() [SWS_DM_01970].

Diagrama de secuencia: Flujo típico de la transferencia y el procesamiento de certificados. Fuentes: [SWS_DM_01969], [SWS_DM_01968], [SWS_DM_01251], [SWS_DM_01970].

Escenarios de error

Se han definido condiciones de error específicas tanto durante la inicialización como durante el funcionamiento continuo:

  • Errores de manifiesto y de modelado durante la creación: El constructor notifica infracciones si el InstanceSpecifier no se puede resolver (InstanceSpecifierMappingIntegrityViolation), el PortPrototype referenciado no está tipado mediante un DiagnosticTransmitCertificateInterface (PortInterfaceMappingViolation), no existe asignación de proceso (ProcessMappingViolation) o el InstanceSpecifier ya está asignado en el proceso (InstanceSpecifierAlreadyInUseViolation) [SWS_DM_01962].
  • Registro múltiple: Una nueva llamada a Offer() cuando la provisión ya está activa produce el error DiagOfferErrc::kAlreadyOffered con semántica de rollback [SWS_DM_01969].
  • Rechazo en Process: Si la verificación del certificado falla en la aplicación o se produce un error de procesamiento, Process() devuelve el error correspondiente a través del ara::core::Future. En este caso, debe utilizarse un UDS-Negative-Response-Code (NRC) adecuado conforme a ISO 14229-1 mediante DiagUdsNrcErrc [SWS_DM_01968]. A continuación, la Diagnostic Server Instance genera una respuesta UDS negativa (NRC) al tester externo [SWS_DM_01249].

Esta guía se basa en la especificación de AUTOSAR Adaptive Platform R25-11 para el módulo Diagnostics.

<h4>Contexto</h4>
<p>
La clase <code>ara::diag::TransmitCertificate</code> proporciona la interfaz de programación para la subfunción UDS <em>TransmitCertificate</em> (<code>0x29 04</code>) del servicio <em>Authentication</em> (<code>0x29</code>) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=522">AUTOSAR_AP_SWS_Diagnostics §8.26.1 «Class: TransmitCertificate»</a>. Implementa una interfaz genérica a través de la cual una aplicación Adaptive puede recibir y evaluar uno o varios certificados identificados mediante un identificador de 16 bits (<code>certificateEvaluationId</code>).
</p>
<p>
En la arquitectura del sistema, <code>ara::diag::TransmitCertificate</code> actúa como enlace entre el AUTOSAR Adaptive Diagnostic Manager (DM) o la Diagnostic Server Instance y la lógica de aplicación concreta. Un comprobador de diagnóstico externo envía la solicitud de autenticación UDS al servidor, que reenvía la solicitud a la aplicación tras la activación <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>, <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>.
</p>

<h4>Ciclo de vida</h4>
<p>
La instanciación se realiza a través del constructor especificando un <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>:
</p>
<ul>
<li><code>specifier</code>: Un <code>ara::core::InstanceSpecifier</code> que apunta a un <code>PortPrototype</code>, el cual se tipa a través de un <code>DiagnosticAuthenticationPortMapping</code> <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>.</li>
<li><code>concurrencyType</code>: Determina si la ejecución posterior de <code>Process</code> se trata como segura para subprocesos (<code>kConcurrent</code>) o no segura para subprocesos (<code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
</ul>
<p>
Las operaciones de copia y de movimiento están completamente deshabilitadas: el constructor de copia <a class="spec-record-ref" data-req="SWS_DM_01964" href="../spec/record.html?id=SWS_DM_01964">[SWS_DM_01964]</a>, el constructor de movimiento <a class="spec-record-ref" data-req="SWS_DM_01963" href="../spec/record.html?id=SWS_DM_01963">[SWS_DM_01963]</a>, el operador de asignación por copia <a class="spec-record-ref" data-req="SWS_DM_01966" href="../spec/record.html?id=SWS_DM_01966">[SWS_DM_01966]</a> y el operador de asignación por movimiento <a class="spec-record-ref" data-req="SWS_DM_01965" href="../spec/record.html?id=SWS_DM_01965">[SWS_DM_01965]</a> están declarados como eliminados (<code>=delete</code>). Por lo tanto, una instancia de interfaz de autenticación existe como un objeto vinculado de forma exclusiva.
</p>
<p>
Tras la construcción, el ciclo de vida se divide en dos fases operativas:
</p>
<ol>
<li><strong>Suministro (Offered):</strong> Mediante la llamada a <code>Offer()</code>, se autoriza a Diagnostic Manager a reenviar los mensajes UDS entrantes para la subfunción al método <code>Process()</code> <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Revocación (Stopped):</strong> La llamada a <code>StopOffer()</code> anula de nuevo el registro del reenvío <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>
<p>
El destructor es virtual y está declarado por defecto (<code>noexcept = default</code>) <a class="spec-record-ref" data-req="SWS_DM_01967" href="../spec/record.html?id=SWS_DM_01967">[SWS_DM_01967]</a>. Mientras que el constructor es seguro para subprocesos, <code>Offer()</code> y <code>StopOffer()</code> están especificados como no seguros para subprocesos y no deben llamarse de forma concurrente no coordinada <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>, <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.
</p>

<h4>Ruta de uso</h4>
<p>
El flujo de funcionamiento normal incluye el registro en Diagnostic Manager, la recepción asíncrona de los datos del certificado y la finalización del procesamiento:
</p>
<ol>
<li><strong>Instanciación y habilitación:</strong> La aplicación instancia la clase derivada y activa la aceptación mediante <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Recepción y procesamiento:</strong> Al recibir una solicitud UDS, el Diagnostic Server reenvía los datos a través de <code>Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. El método devuelve un <code>ara::core::Future&lt;void&gt;</code>, con lo que se admite un procesamiento asíncrono. La semántica concreta y la evaluación del certificado corresponden por completo a la aplicación <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Tratamiento de cancelaciones:</strong> La aplicación puede comprobar mediante <code>cancellationHandler.IsCanceled()</code> si se canceló la conversación de diagnóstico, o registrar a través de <code>cancellationHandler.SetNotifier()</code> una callback de notificación para eventos de cancelación <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Respuesta positiva:</strong> Si la ejecución finaliza con éxito sin código de error, la Diagnostic Server Instance transmite una respuesta UDS positiva con el parámetro de retorno <code>authenticationReturnParameter = 0x13</code> (<em>CertificateVerified</em>) al tester <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>.</li>
<li><strong>Limpieza:</strong> Al finalizar, la recepción se termina mediante <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>
