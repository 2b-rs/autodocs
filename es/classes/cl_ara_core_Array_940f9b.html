Contexto

La clase plantilla ara::core::Array proporciona en la Adaptive Platform una adaptación conforme al estándar de std::array. Encapsula un array de tamaño fijo N con elementos del tipo T y evita asignaciones dinámicas de memoria en tiempo de ejecución. Como contenedor secuencial básico, ara::core::Array sirve a los clústeres funcionales y a las aplicaciones AUTOSAR como una estructura de datos de tipos seguros para la transferencia de datos útiles con un número de elementos estáticamente conocido.

La interfaz se alinea estrechamente con las especificaciones del estándar de C++, pero define adaptaciones específicas para el entorno de ejecución de AUTOSAR. Entre ellas se incluyen interfaces tipadas para indexación, iteradores y consultas de memoria. Los alias de tipo para referencias y punteros ([SWS_CORE_01210], [SWS_CORE_01211], [SWS_CORE_01217], [SWS_CORE_01218]), índices ([SWS_CORE_01214], [SWS_CORE_01215]) e iteradores tanto directos como inversos ([SWS_CORE_01212], [SWS_CORE_01213], [SWS_CORE_01219], [SWS_CORE_01220]) garantizan la interoperabilidad con algoritmos estándar e interfaces genéricas.

Ciclo de vida

Como tipo agregado, ara::core::Array vincula los elementos contenidos directamente a su propia representación en memoria. Las funciones miembro especiales declaradas implícitamente (como los constructores por defecto, de copia y de movimiento, así como los destructores) no se vuelven a declarar explícitamente según la especificación, sino que siguen el comportamiento estándar de los arrays de C++. Por tanto, la vida útil de todos los N elementos está indisolublemente ligada a la vida útil de la instancia del contenedor.

El dimensionamiento se establece en tiempo de compilación mediante el parámetro de plantilla N. Los métodos para consultar el tamaño como size() ([SWS_CORE_01262]), max_size() ([SWS_CORE_01263]) y empty() ([SWS_CORE_01264]) están declarados como constexpr y noexcept. El intercambio del contenido de dos instancias de iguales dimensiones se realiza mediante swap() ([SWS_CORE_01242]). La seguridad frente a excepciones de swap() depende condicionalmente de si el tipo de elemento T está designado mediante ara::core::is_nothrow_swappable<T>::value como no lanzador ([SWS_CORE_01242]). En cuanto a la concurrencia, ara::core::Array no ofrece sincronización interna; los accesos de escritura simultáneos a la misma instancia deben protegerse desde la aplicación (interpretación).

Ruta de uso

El uso típico de ara::core::Array se divide en inicialización, procesamiento de datos secuencial o de acceso aleatorio y transferencia a interfaces de bajo nivel:

  • Inicialización y llenado: El contenedor se puede poblar inicialmente o escribir homogéneamente con una copia de un valor mediante el método fill() ([SWS_CORE_01241]). La operación es noexcept siempre que el tipo de elemento sea seguro frente a asignaciones (std::is_nothrow_copy_assignable<T>::value).
  • Acceso aleatorio y directo a elementos: Para un acceso eficiente sin comprobación en tiempo de ejecución, se encuentra disponible operator[] ([SWS_CORE_01265], [SWS_CORE_01266]). Los elementos extremos pueden referenciarse mediante front() ([SWS_CORE_01267], [SWS_CORE_01268]) y back() ([SWS_CORE_01269], [SWS_CORE_01270]).
  • Procesamiento conforme a iteradores: Los algoritmos pueden iterar sobre la secuencia a través de iteradores hacia adelante (begin() / end() según [SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]), iteradores constantes (cbegin() / cend() según [SWS_CORE_01258], [SWS_CORE_01259]) o iteradores inversos (rbegin() / rend() / crbegin() / crend() según [SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261]).
  • Puente a la API de C: Mediante el método data() ([SWS_CORE_01271], [SWS_CORE_01272]) se proporciona un puntero directo al segmento de memoria contiguo subyacente, por ejemplo para transferirlo a controladores o rutinas de serialización.

Escenarios de error

En el ámbito del tratamiento de errores y la protección de valores límite, ara::core::Array difiere en aspectos esenciales del estándar ISO C++ para preservar las directrices de seguridad contra excepciones específicas de AUTOSAR:

Llamada / Situación Condición Reacción / Especificación
at(size_type n) n >= size() Lanzamiento de una IsoStdOutOfRangeViolation en lugar de std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]).
front() / back() empty() == true (d. h. N == 0) La llamada en un array vacío produce obligatoriamente un error en tiempo de compilación (Compile-Time Error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
Desreferenciación de begin() empty() == true La desreferenciación del iterador devuelto en un array vacío conduce a un comportamiento indefinido ([SWS_CORE_01250], [SWS_CORE_01251]).
data() size() == 0 Retorno de nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
operator[] n >= size() Sin comprobación de rango en tiempo de ejecución; conduce, como en el estándar C++, a un comportamiento indefinido (interpretación).

<h4>Contexto</h4>
<p>La clase plantilla <code>ara::core::Array</code> proporciona en la Adaptive Platform una adaptación conforme al estándar de <code>std::array</code>. Encapsula un array de tamaño fijo <code>N</code> con elementos del tipo <code>T</code> y evita asignaciones dinámicas de memoria en tiempo de ejecución. Como contenedor secuencial básico, <code>ara::core::Array</code> sirve a los clústeres funcionales y a las aplicaciones AUTOSAR como una estructura de datos de tipos seguros para la transferencia de datos útiles con un número de elementos estáticamente conocido.</p>
<p>La interfaz se alinea estrechamente con las especificaciones del estándar de C++, pero define adaptaciones específicas para el entorno de ejecución de AUTOSAR. Entre ellas se incluyen interfaces tipadas para indexación, iteradores y consultas de memoria. Los alias de tipo para referencias y punteros (<a class="spec-record-ref" data-req="SWS_CORE_01210" href="../spec/record.html?id=SWS_CORE_01210">[SWS_CORE_01210]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01211" href="../spec/record.html?id=SWS_CORE_01211">[SWS_CORE_01211]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01217" href="../spec/record.html?id=SWS_CORE_01217">[SWS_CORE_01217]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01218" href="../spec/record.html?id=SWS_CORE_01218">[SWS_CORE_01218]</a>), índices (<a class="spec-record-ref" data-req="SWS_CORE_01214" href="../spec/record.html?id=SWS_CORE_01214">[SWS_CORE_01214]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01215" href="../spec/record.html?id=SWS_CORE_01215">[SWS_CORE_01215]</a>) e iteradores tanto directos como inversos (<a class="spec-record-ref" data-req="SWS_CORE_01212" href="../spec/record.html?id=SWS_CORE_01212">[SWS_CORE_01212]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01213" href="../spec/record.html?id=SWS_CORE_01213">[SWS_CORE_01213]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01219" href="../spec/record.html?id=SWS_CORE_01219">[SWS_CORE_01219]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01220" href="../spec/record.html?id=SWS_CORE_01220">[SWS_CORE_01220]</a>) garantizan la interoperabilidad con algoritmos estándar e interfaces genéricas.</p>

<h4>Ciclo de vida</h4>
<p>Como tipo agregado, <code>ara::core::Array</code> vincula los elementos contenidos directamente a su propia representación en memoria. Las funciones miembro especiales declaradas implícitamente (como los constructores por defecto, de copia y de movimiento, así como los destructores) no se vuelven a declarar explícitamente según la especificación, sino que siguen el comportamiento estándar de los arrays de C++. Por tanto, la vida útil de todos los <code>N</code> elementos está indisolublemente ligada a la vida útil de la instancia del contenedor.</p>
<p>El dimensionamiento se establece en tiempo de compilación mediante el parámetro de plantilla <code>N</code>. Los métodos para consultar el tamaño como <code>size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01262" href="../spec/record.html?id=SWS_CORE_01262">[SWS_CORE_01262]</a>), <code>max_size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01263" href="../spec/record.html?id=SWS_CORE_01263">[SWS_CORE_01263]</a>) y <code>empty()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01264" href="../spec/record.html?id=SWS_CORE_01264">[SWS_CORE_01264]</a>) están declarados como <code>constexpr</code> y <code>noexcept</code>. El intercambio del contenido de dos instancias de iguales dimensiones se realiza mediante <code>swap()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). La seguridad frente a excepciones de <code>swap()</code> depende condicionalmente de si el tipo de elemento <code>T</code> está designado mediante <code>ara::core::is_nothrow_swappable&lt;T&gt;::value</code> como no lanzador (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). En cuanto a la concurrencia, <code>ara::core::Array</code> no ofrece sincronización interna; los accesos de escritura simultáneos a la misma instancia deben protegerse desde la aplicación (interpretación).</p>

<h4>Ruta de uso</h4>
<p>El uso típico de <code>ara::core::Array</code> se divide en inicialización, procesamiento de datos secuencial o de acceso aleatorio y transferencia a interfaces de bajo nivel:</p>
<ul>
<li><strong>Inicialización y llenado:</strong> El contenedor se puede poblar inicialmente o escribir homogéneamente con una copia de un valor mediante el método <code>fill()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>). La operación es <code>noexcept</code> siempre que el tipo de elemento sea seguro frente a asignaciones (<code>std::is_nothrow_copy_assignable&lt;T&gt;::value</code>).</li>
<li><strong>Acceso aleatorio y directo a elementos:</strong> Para un acceso eficiente sin comprobación en tiempo de ejecución, se encuentra disponible <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_CORE_01265" href="../spec/record.html?id=SWS_CORE_01265">[SWS_CORE_01265]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01266" href="../spec/record.html?id=SWS_CORE_01266">[SWS_CORE_01266]</a>). Los elementos extremos pueden referenciarse mediante <code>front()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>) y <code>back()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>).</li>
<li><strong>Procesamiento conforme a iteradores:</strong> Los algoritmos pueden iterar sobre la secuencia a través de iteradores hacia adelante (<code>begin()</code> / <code>end()</code> según <a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01252" href="../spec/record.html?id=SWS_CORE_01252">[SWS_CORE_01252]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01253" href="../spec/record.html?id=SWS_CORE_01253">[SWS_CORE_01253]</a>), iteradores constantes (<code>cbegin()</code> / <code>cend()</code> según <a class="spec-record-ref" data-req="SWS_CORE_01258" href="../spec/record.html?id=SWS_CORE_01258">[SWS_CORE_01258]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01259" href="../spec/record.html?id=SWS_CORE_01259">[SWS_CORE_01259]</a>) o iteradores inversos (<code>rbegin()</code> / <code>rend()</code> / <code>crbegin()</code> / <code>crend()</code> según <a class="spec-record-ref" data-req="SWS_CORE_01254" href="../spec/record.html?id=SWS_CORE_01254">[SWS_CORE_01254]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01255" href="../spec/record.html?id=SWS_CORE_01255">[SWS_CORE_01255]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01256" href="../spec/record.html?id=SWS_CORE_01256">[SWS_CORE_01256]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01257" href="../spec/record.html?id=SWS_CORE_01257">[SWS_CORE_01257]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01260" href="../spec/record.html?id=SWS_CORE_01260">[SWS_CORE_01260]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01261" href="../spec/record.html?id=SWS_CORE_01261">[SWS_CORE_01261]</a>).</li>
<li><strong>Puente a la API de C:</strong> Mediante el método <code>data()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>) se proporciona un puntero directo al segmento de memoria contiguo subyacente, por ejemplo para transferirlo a controladores o rutinas de serialización.</li>
</ul>
