Proporciona un contenedor secuencial de tamaño fijo con comprobación de límites con seguridad de tipos para AUTOSAR Adaptive.

La clase de plantilla ara::core::Array sirve como contenedor secuencial de tamaño fijo para elementos del tipo T y adapta el comportamiento de std::array para aplicaciones de AUTOSAR Adaptive Platform. Quienes realizan llamadas inicializan el contenedor con un número fijo de elementos, manipulan contenidos mediante métodos como fill() y acceden opcionalmente sin comprobación mediante operator[] o con comprobación de límites mediante at() a [SWS_CORE_01273]. Como condición de contorno relevante para la seguridad, un rebase de límites en at() desencadena la infracción específica IsoStdOutOfRangeViolation en lugar de std::out_of_range, mientras que las llamadas a front() o back() en instancias vacías fallan ya en tiempo de compilación [SWS_CORE_01267].

Contexto

La clase de plantilla ara::core::Array encapsula un contenedor secuencial con un tamaño N fijado estáticamente en tiempo de compilación para elementos del tipo T. Implementa el tipo estandarizado std::array en el módulo core de AUTOSAR Adaptive Platform y constituye una abstracción con seguridad de tipos para bloques de memoria contiguos. Al proporcionar alias de tipo estandarizados como value_type ([SWS_CORE_01216]), size_type ([SWS_CORE_01214]), difference_type ([SWS_CORE_01215]), así como tipos de puntero ([SWS_CORE_01217], [SWS_CORE_01218]) y tipos de referencia ([SWS_CORE_01210], [SWS_CORE_01211]), la clase actúa como interlocutor interoperable para algoritmos genéricos de C++ y flujos de datos internos de la plataforma.

Ciclo de vida

La creación y destrucción de una instancia de array sigue las reglas estándar para tipos agregados y de valor: se utilizan las funciones miembro especiales declaradas implícitamente del estándar ISO C++ y no se vuelven a declarar por separado. El array posee sus elementos directamente inline en la misma región de memoria. Por consiguiente, la vida útil de los elementos contenidos está vinculada inseparablemente a la vida útil del objeto de array que los envuelve; presumiblemente no tiene lugar ninguna asignación dinámica en la memoria libre (heap), lo que garantiza un comportamiento temporal y de memoria determinista.

El contenedor se encuentra siempre en un estado válido y gestiona exactamente N elementos. Si el array puede alojar elementos o si se presenta como caso especial con N = 0, se puede evaluar mediante empty() ([SWS_CORE_01264]), size() ([SWS_CORE_01262]), así como max_size() ([SWS_CORE_01263]). En cuanto a la concurrencia, es de suponer que los accesos de lectura concurrentes son seguros sin sincronización, mientras que las modificaciones de escritura paralelas requieren una coordinación externa por parte de quien realiza la llamada.

Ruta de uso

En casos de uso típicos, ara::core::Array atraviesa una secuencia de inicialización, llenado de elementos, acceso aleatorio o secuencial y, dado el caso, intercambio de contenido:

  • Inicialización y llenado: Todo el búfer de datos se puede asignar uniformemente con un valor predeterminado mediante fill() ([SWS_CORE_01241]).
  • Acceso aleatorio: Para accesos de alto rendimiento se encuentra disponible el operador de índice no verificado operator[] ([SWS_CORE_01265], [SWS_CORE_01266]). Si se requiere una comprobación de límites, se recurre a at() ([SWS_CORE_01273], [SWS_CORE_01274]).
  • Elementos extremos: El acceso directo al primer y al último elemento se realiza mediante front() ([SWS_CORE_01267], [SWS_CORE_01268]) y back() ([SWS_CORE_01269], [SWS_CORE_01270]).
  • Iteración: El recorrido del contenedor se realiza hacia adelante mediante begin() y end() ([SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253]) o mediante iteradores constantes como cbegin() y cend() ([SWS_CORE_01258], [SWS_CORE_01259]). Los tipos de iterador están definidos como punteros elementales T* o const T* ([SWS_CORE_01212], [SWS_CORE_01213]). Para recorridos inversos están disponibles rbegin(), rend(), crbegin() y crend() ([SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261], [SWS_CORE_01219], [SWS_CORE_01220]).
  • Acceso por puntero e intercambio: La región de memoria subyacente se puede transferir como puntero mediante data() ([SWS_CORE_01271], [SWS_CORE_01272]). Dos arrays de idéntica dimensión se pueden intercambiar mediante swap() ([SWS_CORE_01242]).

Diagrama de secuencia: orden típico de llamadas para el llenado, la comprobación de límites y el intercambio de instancias de array. Fuentes: [SWS_CORE_01241], [SWS_CORE_01273], [SWS_CORE_01242].

Escenarios de error

La especificación define precondiciones y poscondiciones estrictas para situaciones límite y de error:

  • Infracción de límites en acceso indizado: Si en at() el índice n se encuentra fuera de los límites del array (n >= size()), se desencadena IsoStdOutOfRangeViolation en lugar de la excepción estándar de C++ std::out_of_range ([SWS_CORE_01273], [SWS_CORE_01274]). Ambas sobrecargas están declaradas con noexcept.
  • Acceso a instancias vacías: La llamada a front() o back() en un array vacío (empty() == true, es decir, N = 0) provoca obligatoriamente un error en tiempo de compilación (Compile-Time Error) ([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
  • Comportamiento indefinido en iteradores: La desreferenciación del iterador devuelto por begin() en un array vacío representa un comportamiento indefinido ([SWS_CORE_01250], [SWS_CORE_01251]).
  • Caso especial de consulta de puntero: Si el tamaño del array es 0, la función miembro data() devuelve obligatoriamente nullptr ([SWS_CORE_01271], [SWS_CORE_01272]).
  • Seguridad frente a excepciones condicional: La operación swap() es noexcept solo si se cumple la condición relativa al tipo ara::core::is_nothrow_swappable<T>::value ([SWS_CORE_01242]). De forma correspondiente, la propiedad noexcept de fill() se determina mediante std::is_nothrow_copy_assignable<T>::value ([SWS_CORE_01241]).

La función miembro at de la clase ara::core::Array permite el acceso síncrono de lectura y escritura a un elemento del array en la posición especificada n con comprobación implícita de límites [SWS_CORE_01273]. La función devuelve una referencia modificable (reference) al elemento direccionado y puede evaluarse en tiempo de compilación (constexpr) [SWS_CORE_01273].

En caso de fallo, cuando el índice solicitado alcanza o supera el límite del contenedor (n >= size()), el comportamiento difiere del contenedor estándar de C++ std::array: en lugar de una excepción de tipo std::out_of_range, se desencadena una IsoStdOutOfRangeViolation [SWS_CORE_01273]. Dado que la firma está declarada como noexcept y clasificada como segura frente a excepciones, no se lanzan excepciones convencionales de C++ [SWS_CORE_01273]. Interpretación: El desencadenamiento de esta infracción en un contexto noexcept debería conducir de forma inmediata a la terminación controlada de la ejecución.

Para instancias de solo lectura existe la sobrecarga constante complementaria [SWS_CORE_01274], la cual proporciona una referencia constante. La misma semántica de errores mediante IsoStdOutOfRangeViolation se aplica de manera consistente también en contenedores afines como ara::core::Vector ([SWS_CORE_01354], [SWS_CORE_01355]), así como en ara::core::StringView [SWS_CORE_02133].

      La función miembro at de la clase ara::core::Array (cabecera #include "ara/core/array.h") permite el acceso indexado de lectura a un elemento individual del array [SWS_CORE_01274]. Acepta el índice n de tipo size_type y devuelve una referencia constante (const_reference) al elemento direccionado [SWS_CORE_01274]. Gracias a su declaración como constexpr y noexcept, la función puede utilizarse para expresiones constantes en tiempo de compilación y está especificada como segura frente a excepciones (exception safe) [SWS_CORE_01274]. Para accesos modificadores está disponible la sobrecarga no constante [SWS_CORE_01273].
      

      En caso de error, la semántica difiere de std::array: si el índice excede el tamaño del contenedor (n >= size()), no se desencadena ningún std::out_of_range, sino que se notifica la infracción IsoStdOutOfRangeViolation [SWS_CORE_01274]. Dado que la función está cualificada con noexcept, es probable que la notificación de esta infracción provoque la detención del programa a través del mecanismo de interrupción (abort) a nivel de plataforma, para el cual pueden registrarse manejadores personalizados [SWS_CORE_00054].
      

      Este patrón de tratamiento de errores se aplica de forma uniforme también en otros contenedores de ara::core, tales como ara::core::Vector [SWS_CORE_01354], ara::core::Map [SWS_CORE_01456] y ara::core::StringView [SWS_CORE_02133]. Sin embargo, mientras que ara::core::Vector y ara::core::BasicString en at no se consideran seguros frente a excepciones [SWS_CORE_01354] [SWS_CORE_03063], ara::core::Array garantiza seguridad frente a excepciones [SWS_CORE_01274].

El comportamiento se basa en el uso en [array], de modo que presumiblemente todos los elementos se establecen de forma sincrónica en el valor u mediante asignación por copia.
                                                              

                                                              Tratamiento de errores y seguridad frente a excepciones
                                                              

                                                              Según la especificación, la función está clasificada como condicionalmente segura frente a excepciones (conditionally exception safe) [SWS_CORE_01241]. Esto se implementa a través del identificador noexcept(std::is_nothrow_copy_assignable<T>::value). No se contemplan códigos de error específicos, un estado de error como valor de retorno ni notificaciones DET/DEM; las excepciones solo se producen si la asignación por copia del tipo T falla y no está declarada como noexcept.
