Contexto

La estructura de datos apext::com::secoc::FVContainer forma parte de las normativas Platform Extension Interfaces de la AUTOSAR Adaptive Platform en el módulo Communication Management ([SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). Las Platform Extension Interfaces son interfaces funcionales proporcionadas o utilizadas por un fabricante de vehículos (OEM) o integrador de sistemas para ampliar de forma específica la funcionalidad básica del sistema Adaptive (AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). Dentro de este concepto de extensión, FVContainer se define a través del encabezado apext/com/secoc/fvm.h y asume el rol de un contenedor de transporte estandarizado para valores de frescura (Freshness Values).

En el ámbito de la comunicación segura a bordo (Secure Onboard Communication, SecOC), la verificación y generación de valores de frescura es elemental para prevenir eficazmente ataques de repetición contra los mensajes transmitidos. La estructura FVContainer sirve como enlace dedicado entre los servicios de comunicación de la plataforma y el Freshness Value Manager (FVM) específico del fabricante. En lugar de parámetros de interfaz complejos, la estructura encapsula la información del valor de frescura en dos componentes elementales: la longitud exacta en bits del valor, así como los datos útiles propiamente dichos en forma de bytes ([SWS_CM_11344], [SWS_CM_11345]). Esto permite una transferencia flexible independientemente de si se intercambian valores completos o truncados.

Diagrama de contexto: integración de FVContainer en la interfaz entre Communication Management y la extensión de plataforma FVM. Fuentes: [SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer».

Ciclo de vida

La estructura FVContainer está concebida como un objeto de transferencia de datos puramente pasivo (Value Object) ([SWS_CM_11286]). No posee máquina de estados propia ni gestiona recursos activos en segundo plano o hilos. La instanciación se produce normalmente de forma directa en el contexto de una operación pendiente de envío o recepción de mensajes, ya sea en la pila del hilo invocador o como un objeto temporal dentro de la canalización de procesamiento.

En cuanto a las relaciones de propiedad, FVContainer está sujeta a las semánticas estándar de valores de C++. La instancia posee sus variables miembro de forma exclusiva. En una asignación o transferencia a métodos de interfaz, los valores se copian o se transfieren mediante semántica de movimiento. El elemento value encapsula un vector del tipo ara::core::Vector<std::uint8_t> ([SWS_CM_11345]), que gestiona su área de memoria de forma dinámica. La destrucción de FVContainer se produce de forma determinista al salir del ámbito circundante según los principios de RAII, liberándose automáticamente el búfer asignado dinámicamente del vector.

En lo relativo a la concurrencia, FVContainer no ofrece una seguridad de subprocesos inherente. Interpretación: Dado que la estructura no proporciona mecanismos internos de sincronización ni exclusiones mutuas (mútexes), los accesos concurrentes de varios hilos a la misma instancia deben serializarse por completo mediante el componente invocador.

Ruta de uso

El flujo de uso principal de FVContainer comprende el intercambio de datos entre el subsistema SecOC y las funciones del FVM durante la autenticación o verificación de mensajes. Según si el contenedor actúa como valor de entrada o de retorno, transporta valores de frescura completos o truncados ([SWS_CM_11345], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 «value»).

  1. Instanciación y preparación: El Communication Management crea una instancia local de FVContainer ([SWS_CM_11286]). En caso de una verificación de mensaje, el subsistema extrae el valor de frescura truncado (Truncated Freshness Value) del mensaje recibido y completa el vector value, así como la longitud en bits en length ([SWS_CM_11344], [SWS_CM_11345]).
  2. Llamada a la interfaz: La instancia se transfiere a la función de interfaz correspondiente del FVM (AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 «Struct: FVContainer»). Interpretación: El FVM reconstruye el valor de frescura completo a partir del valor truncado transferido y de contadores internos.
  3. Retorno y procesamiento posterior: El FVM devuelve el resultado en forma de una instancia de FVContainer recién creada o modificada ([SWS_CM_11345]). El sistema invocador lee la longitud real en bits de length ([SWS_CM_11344]) y la secuencia de bytes de value ([SWS_CM_11345]) para llevar a cabo de forma final la autenticación criptográfica (p. ej., cálculo de MAC).

Diagrama de secuencia: flujo de llamada típico para el procesamiento de valores de frescura con FVContainer como parámetro de entrada y salida. Fuentes: [SWS_CM_11344], [SWS_CM_11345], AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 «value».

Escenarios de error

Como estructura de datos pura, FVContainer no declara funciones miembro propias y, por lo tanto, no define códigos de error específicos ni lanza excepciones específicas de la plataforma ([SWS_CM_11286]). No obstante, existen precondiciones funcionales estrictas para el uso de los atributos contenidos:

  • Especificaciones de longitud inconsistentes: La variable length define la longitud del valor de frescura con precisión en bits ([SWS_CM_11344]), mientras que value contiene los datos en un vector de bytes ([SWS_CM_11345]). Aplica la precondición de que el tamaño del vector en bytes debe corresponder como mínimo al número de bits redondeado hacia arriba. Interpretación: Si length presenta un valor de 0 o la capacidad del vector no alcanza la longitud en bits indicada, la función del FVM invocada debe rechazar la entrada por considerarla no válida.
  • Errores de asignación de memoria: Al asignar o ampliar el vector value ([SWS_CM_11345]), puede producirse una excepción del tipo std::bad_alloc en caso de que se agoten los recursos de memoria del sistema. La capa invocadora debe garantizar a nivel de plataforma que dichos errores de asignación se capturen de forma controlada.
  • Valores de frescura no válidos: Si el FVM no puede determinar o verificar con éxito un valor de frescura, el sistema invocador no debe seguir utilizando los datos sin procesar restantes en FVContainer para no comprometer la integridad de la arquitectura de seguridad.
