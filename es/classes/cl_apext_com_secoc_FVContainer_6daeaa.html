Sirve como contenedor de datos para transferir valores de frescura y su longitud en bits en la comunicación segura a bordo.

La estructura apext::com::secoc::FVContainer sirve en el módulo Communication Management como contenedor de transporte para valores de frescura destinados a proteger la comunicación a bordo [SWS_CM_11286]. Encapsula la longitud en bits del valor en el campo length, así como el propio valor de frescura como vector de bytes en el campo value [SWS_CM_11344]. En función del contexto de uso, el vector transporta valores completos o truncados; debido a la ausencia de mecanismos internos de sincronización, se requiere una sincronización externa en caso de concurrencia.

Contexto

La estructura de datos apext::com::secoc::FVContainer forma parte de las interfaces de extensión de plataforma (Platform Extension Interfaces) del módulo Communication Management y está declarada en el encabezado apext/com/secoc/fvm.h [SWS_CM_11286]. De acuerdo con la arquitectura de AUTOSAR Adaptive Platform, las Platform Extension Interfaces sirven para ser utilizadas o implementadas por fabricantes de vehículos (OEM) o integradores con el fin de adaptar la funcionalidad de la plataforma a requisitos específicos del proyecto (AUTOSAR_AP_SWS_CommunicationManagement p. 536 §C «Platform Extension Interfaces»).

Dentro de la comunicación segura a bordo (Secure Onboard Communication, SecOC), apext::com::secoc::FVContainer sirve como contenedor estandarizado de transferencia de datos para valores de frescura (Freshness Values) [SWS_CM_11286]. La estructura agrupa dos informaciones relacionadas: la longitud exacta del valor de frescura en bits en el campo length [SWS_CM_11344], así como los datos brutos del valor de frescura como vector de bytes en el campo value [SWS_CM_11345]. Actúa en este contexto como interfaz directa entre AUTOSAR Communication Management y una implementación específica del fabricante del Freshness Value Manager (FVM).

Diagrama de contexto: integración de FVContainer como objeto de transferencia de datos entre Communication Management y la extensión de plataforma de la FVM. Fuentes: [SWS_CM_11286], AUTOSAR_AP_SWS_CommunicationManagement p. 536 §C «Platform Extension Interfaces».

Ciclo de vida

Como estructura C++ (struct) [SWS_CM_11286] con variables miembro exclusivamente públicas, apext::com::secoc::FVContainer sigue el patrón de diseño de un objeto de valor puro. La instanciación se realiza según las necesidades, bien en la pila o bien dinámicamente en el montículo por parte del invocador o del invocado, dependiendo de si un valor de frescura se transfiere a un método o se proporciona como valor de retorno [SWS_CM_11345].

El tiempo de vida de una instancia está vinculado principalmente al vector contenido ara::core::Vector<std::uint8_t> [SWS_CM_11345]. Al salir del ámbito de validez, se liberan de forma determinista todos los recursos de memoria asignados para el valor de frescura. Las operaciones de copia y movimiento siguen la semántica estándar de los tipos std::uint64_t [SWS_CM_11344] y ara::core::Vector [SWS_CM_11345]. La estructura no posee mecanismos internos de sincronización; por tanto, el acceso concurrente a través de los límites de los hilos debería ser responsabilidad exclusiva de los componentes usuarios (interpretación).

Ruta de uso

La ruta de uso típica abarca la creación, inicialización y posterior evaluación del contenedor durante el intercambio de valores de frescura para la protección o verificación de mensajes. Según si apext::com::secoc::FVContainer actúa como parámetro de método o como valor de retorno, el vector value contiene el valor de frescura completo o un valor truncado (truncated value) [SWS_CM_11345].

En el proceso de verificación o firma, Communication Management solicita primero un valor de frescura. El Freshness Value Manager instancia el contenedor, establece la longitud en bits significativa en el campo length [SWS_CM_11344] y rellena el vector value con los valores de bytes [SWS_CM_11345]. Tras la devolución del contenedor, Communication Management lee length y value, donde la longitud en bits define presumiblemente el límite exacto y se ignoran los bits de relleno no utilizados en el último byte del vector (interpretación).

Diagrama de secuencia: provisión y evaluación típicas del valor de frescura a través del FVContainer. Fuentes: [SWS_CM_11286], [SWS_CM_11344], [SWS_CM_11345].
