Sirve para la definición y resolución de códigos de error y excepciones dentro de State Management.

La clase ara::sm::SmErrorDomain representa el dominio de errores específico de dominio de State Management y asigna códigos de error funcionales a mensajes de texto legibles, así como a excepciones de C++ ([SWS_SM_81241]). En tiempo de ejecución, permite la identificación del dominio mediante métodos seguros para subprocesos, así como la traducción de valores de error individuales para el registro y el diagnóstico. Si se produce un error grave, a través de la interfaz también se puede lanzar una excepción tipificada ([SWS_SM_81250]). Si las excepciones de C++ están deshabilitadas en la cadena de herramientas (toolchain), la lógica de excepciones no está disponible y los errores deben procesarse en su lugar de forma puramente basada en valores.

Contexto

La clase ara::sm::SmErrorDomain define el dominio de errores específico para el clúster funcional de State Management en la Adaptive Platform ([SWS_SM_81241], SWS StateManagement §8.1.3 «Class: SmErrorDomain»). Como especialización de la arquitectura general de dominios de errores, hereda de ara::core::ErrorDomain según las especificaciones de [SWS_CORE_90023]. Su responsabilidad central consiste en encapsular semánticamente los estados de error de State Management, proporcionar identificadores de error estandarizados y garantizar la correspondencia entre códigos de error numéricos, textos de error y tipos de excepciones.

Entre los interlocutores principales se encuentran componentes internos de State Management que generan errores, así como servicios de aplicación y de plataforma de nivel superior que reciben errores a través de ara::core::ErrorCode. Mediante el alias de tipo público Errc, la clase hace referencia a la enumeración específica del dominio SmErrc ([SWS_SM_81245]). El alias de tipo Exception remite además a la clase base de excepciones asociada SmException ([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 «Type Alias: Exception»).

Ciclo de vida

Las instancias de ara::sm::SmErrorDomain se crean a través del constructor predeterminado sin parámetros ([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 «Default Constructor»). El constructor está declarado como noexcept y cuenta con la clasificación exception safe. Es de prever que una instancia de SmErrorDomain exista preferentemente como objeto estático o de larga duración en entornos de sistema típicos, ya que en el ecosistema de AUTOSAR Adaptive se requieren dominios de error en todo el proceso para interpretar los códigos de error.

En lo relativo a la concurrencia, las funciones centrales de la clase están especificadas para el funcionamiento concurrente: los métodos Name() ([SWS_SM_81248]) y Message() ([SWS_SM_81249]) están designados como thread-safe y exception safe. Por lo tanto, varios subprocesos de ejecución pueden consultar información de error en paralelo sin necesidad de sincronización externa.

Ruta de uso

La ruta de uso regular abarca la identificación del dominio de errores, la resolución de códigos de error en mensajes de diagnóstico legibles y, opcionalmente, la transformación en una excepción de C++. En primer lugar, una aplicación o componente de la plataforma puede obtener el nombre del dominio mediante Name(); este devuelve de forma invariable el identificador "Sm" ([SWS_SM_81248]).

Si se produce un error en State Management, su código se transfiere mediante Message(errorCode) ([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 «Message»). La función devuelve un puntero a la cadena de caracteres asociada (const char*), con lo que los sistemas de registro y diagnóstico reciben mensajes significativos. Si el subsistema que realiza la llamada está diseñado para una gestión de errores basada en excepciones, transfiere el objeto de error a ThrowAsException() ([SWS_SM_81250]), con lo que se instancia y se lanza la excepción correspondiente al código de error.

Diagrama de secuencia: secuencia típica al consultar información de error y al lanzar excepciones opcionalmente. Fuentes: [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

Escenarios de error

Los estados de error gestionados por el dominio se basan en el tipo de enumeración SmErrc, al que se le asigna un alias mediante Errc ([SWS_SM_81245]). Las situaciones de error se manifiestan como valores de retorno basados en ara::core::ErrorCode o a través de excepciones del tipo Exception (SmException, [SWS_SM_81246]).

Al llamar a ThrowAsException(), el método se considera por concepto como not exception safe, ya que lanza activamente la excepción vinculada al código de error ([SWS_SM_81250]). Una condición previa crítica para la disponibilidad de este método atañe a la configuración de la cadena de herramientas: conforme a [SWS_CORE_10304], ThrowAsException() no participa en la resolución de sobrecargas si las excepciones de C++ están deshabilitadas en la cadena de herramientas del compilador ([SWS_SM_81250]). Por consiguiente, en configuraciones de sistema sin soporte para excepciones, la gestión de errores debe procesarse estrictamente mediante códigos de retorno.

función Message [SWS_SM_81249] Upstream: RS_AP_00119, RS_AP_00159

const char * Message (CodeType errorCode) const noexcept override;

Returns the message associated with the error code.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: 5c30b05c668e Procedencia

La función miembro ara::sm::SmErrorDomain::Message sirve para determinar de forma síncrona el mensaje de error textual asignado a un código de error determinado del dominio de error de State Management [SWS_SM_81249]. Está declarada en el archivo de cabecera ara/sm/sm_error_domain.h dentro del ámbito de la clase ara::sm::SmErrorDomain y cuenta en la especificación con el estado DRAFT AUTOSAR_AP_SWS_StateManagement §8.1.3.2.2.1 «Message».

La interfaz posee los siguientes parámetros y valores de retorno [SWS_SM_81249]:

  • Parámetros: errorCode de tipo CodeType recibe el número de error numérico para el cual se solicita el mensaje de texto asociado.
  • Valor de retorno: Un puntero de tipo const char * al mensaje de error asignado al código de error transmitido.

Para la ejecución se aplican estrictas garantías respecto a la concurrencia y al tratamiento de excepciones: la función está especificada como thread-safe y exception safe, así como declarada con el identificador noexcept [SWS_SM_81249]. Por tanto, puede invocarse de forma segura desde subprocesos arbitrarios sin bloqueos sincronizadores ni bloques try-catch.

En el marco de la gestión de errores de AUTOSAR Adaptive, el método sobrescribe la función virtual del dominio de error base. Interpretación: Dado que el valor de retorno está definido como const char * sin interfaz de asignación, es de suponer que el puntero haga referencia típicamente a literales de cadena estáticos que siguen siendo válidos durante todo el tiempo de ejecución del proceso.

          usar
          

          
El constructor predeterminado SmErrorDomain() crea de forma síncrona una instancia del dominio de errores ara::sm::SmErrorDomain ([SWS_SM_81247]). La declaración se encuentra en el archivo de cabecera ara/sm/sm_error_domain.h. La llamada no requiere parámetros de transferencia y devuelve directamente el objeto de dominio inicializado (SWS StateManagement §8.1.3.2.1.1 «Default Constructor»).

          

          Manejo de errores
          

          
La función cuenta con el identificador noexcept y está clasificada como segura frente a excepciones (exception safe) ([SWS_SM_81247]). Durante la creación no se producen códigos de error y no se lanzan excepciones.

          

          Concurrencia y restricciones
          

          
La creación está especificada como thread-safe ([SWS_SM_81247]). Por consiguiente, las instancias pueden crearse concurrentemente en entornos multihilo sin necesidad de mecanismos de sincronización adicionales. No existen condiciones especiales de orden.

          

          Interacción
          

          
El objeto creado pertenece a la clase ara::sm::SmErrorDomain ([SWS_SM_81241]), la cual está especificada de conformidad con [SWS_CORE_90023]. Dentro del módulo State Management, el dominio de errores interactúa con los siguientes elementos:

          

            

          • Errc ([SWS_SM_81245]) y Exception ([SWS_SM_81246]) como sinónimos de tipo para códigos de error (SmErrc) y tratamiento de excepciones (SmException).

            •

            • 

          • ThrowAsException() ([SWS_SM_81250]) lanza el código de error como excepción, siempre que las excepciones de C++ estén habilitadas ([SWS_CORE_10304]).
            • 

          • GetSmDomain() ([SWS_SM_81251]) proporciona alternativamente una instancia global del dominio de errores.

              La función ara::sm::SmErrorDomain::ThrowAsException sirve para lanzar un código de error del dominio de error de State Management directamente como una excepción de C++ [SWS_SM_81250]. Está declarada en el archivo de cabecera ara/sm/sm_error_domain.h y sobrescribe la correspondiente función base para dominios de error (SWS StateManagement §8.1.3.2.2.3 «ThrowAsException»).
              

              Invocación y parámetros
              

              El método se invoca de forma síncrona y toma como único parámetro de transferencia una referencia constante a errorCode (de tipo ara::core::ErrorCode) [SWS_SM_81250]. No proporciona ningún valor de retorno (void), ya que instancia y lanza la excepción perteneciente al código de error transmitido, con lo cual se interrumpe el flujo regular de control en el punto de llamada [SWS_SM_81250].
              

              Concurrencia y condiciones de contorno
              

                

              • Seguridad de subprocesos: La función está especificada explícitamente como segura para subprocesos (thread-safe) y, por lo tanto, puede invocarse sin problemas desde subprocesos concurrentes [SWS_SM_81250].
                • 

              • Seguridad frente a excepciones: El comportamiento está documentado como not exception safe [SWS_SM_81250]; Interpretación: Es de suponer que esto se deba al hecho de que el lanzamiento de la excepción abandona el flujo regular de control y el método, por definición, falla o propaga una excepción.
                • 

              • Restricción del compilador: Según [SWS_CORE_10304], la función no participa en la resolución de sobrecarga (overload resolution) siempre que las excepciones de C++ estén desactivadas en la cadena de herramientas del compilador [SWS_SM_81250].
