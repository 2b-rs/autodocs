Define el dominio de error del módulo shwa para consultar mensajes de error y activar excepciones adecuadas.

La clase ara::shwa::ShwaErrorDomain proporciona el dominio de error específico del módulo para el módulo shwa y vincula códigos de error con descripciones, así como con tipos de excepción asociados [AP_SWS_SHWA_01305]. Además de la consulta textual de nombres de dominio y mensajes de error, ofrece a través de ThrowAsException() la posibilidad de lanzar errores de manera selectiva como excepciones [AP_SWS_SHWA_01310]. Los métodos de inspección están declarados como seguros para subprocesos y seguros frente a excepciones.

Contexto

La clase ara::shwa::ShwaErrorDomain representa el dominio de error específico para el módulo shwa en Adaptive Platform y se deriva de la clase base ara::core::ErrorDomain. Actúa como nexo central para la identificación inequívoca, denominación y descripción textual de las causas de error específicas del módulo. Típicamente, el dominio de error interactúa estrechamente con instancias de ara::core::ErrorCode, así como con el correspondiente tratamiento de excepciones a través de ShwaException. Mediante alias de tipo, la clase proporciona una asignación directa a los tipos de error específicos del módulo: Errc hace referencia a ShwaErrorCode [AP_SWS_SHWA_01305] y Exception a ShwaException [AP_SWS_SHWA_01306].

Diagrama de contexto: Integración de ShwaErrorDomain en la interacción con códigos de error, excepciones y la lógica de aplicación. Fuentes: [AP_SWS_SHWA_01305], [AP_SWS_SHWA_01306], [AP_SWS_SHWA_01310]

Ciclo de vida

La instanciación de ShwaErrorDomain se realiza a través del constructor predeterminado ShwaErrorDomain(), que está declarado como noexcept y garantiza tanto la seguridad para subprocesos (Thread Safety) como la seguridad frente a excepciones (Exception Safety) [AP_SWS_SHWA_01307]. Como representante de un dominio de error en el modelo de tratamiento de errores de AUTOSAR Adaptive, dicha instancia suele mantenerse con una larga vida útil (interpretación: probablemente como un objeto singleton estático o global) para cotejar contextos de error de forma recurrente. Salvo por la activación de excepciones, todos los métodos de lectura de la instancia son seguros para subprocesos y no lanzan excepciones.

Ruta de uso

En el flujo de procesamiento regular, cuando ocurre un error específico del módulo, un componente genera un ara::core::ErrorCode haciendo referencia al dominio de error. Para la salida de texto o el registro, el consumidor invoca el método Name() a fin de determinar el identificador del dominio de error [AP_SWS_SHWA_01308], o bien obtiene mediante Message(errorCode) la descripción de error asociada al código numérico [AP_SWS_SHWA_01309]. Si un código de error debe transferirse a la ruta de excepciones de C++, la lógica invocadora inicia ThrowAsException() [AP_SWS_SHWA_01310].

Diagrama de secuencia: Flujo típico durante la consulta de errores y la conversión a una excepción. Fuentes: [AP_SWS_SHWA_01308], [AP_SWS_SHWA_01309], [AP_SWS_SHWA_01310]

Escenarios de error

Los dominios de error en sí sirven para la clasificación de errores y sus funciones de inspección están diseñadas para ser ampliamente tolerantes a fallos. Tanto Name() [AP_SWS_SHWA_01308] como Message() [AP_SWS_SHWA_01309] están especificados como noexcept y exception-safe, de modo que incluso ante códigos de error desconocidos se devuelve un puntero definido a una cadena de caracteres (interpretación: probablemente un texto estático informativo o de marcador de posición). El único escenario de error con activación explícita lo representa el método ThrowAsException(errorCode) [AP_SWS_SHWA_01310]: está declarado con noexcept(false) como «not exception safe», ya que su propósito principal radica en el lanzamiento selectivo de una excepción del tipo Exception (ShwaException) [AP_SWS_SHWA_01306].
