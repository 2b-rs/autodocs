Almacena metadatos, condiciones e indicaciones de tamaño de un paquete de actualización de software para su provisión mediante el diagnóstico.

La estructura ara::diag::SovdSwUpdate::UpdatePackageDetails sirve como objeto de transferencia de datos estandarizado para metadatos de paquetes de actualización de software en el marco de ASAM SOVD [SWS_DM_01877]. Transporta identificadores de paquetes, tamaños, condiciones, así como componentes afectados desde la aplicación de implementación hacia la capa de protocolo SOVD de la instancia de diagnóstico AUTOSAR_AP_SWS_Diagnostics §7.4 «Figure 7.4: SOVD Software Update API - concept». La provisión de los datos se realiza principalmente como respuesta a consultas mediante GetUpdatePackageDetails. Dado que la estructura agrupa variables miembro puramente pasivas, no posee sincronización propia y requiere protección externa en caso de uso concurrente.

Contexto

La estructura ara::diag::SovdSwUpdate::UpdatePackageDetails está definida en la cabecera ara/diag/sovd_sw_update.h [SWS_DM_01877] y sirve como contenedor de datos estandarizado para información detallada sobre paquetes de actualización de software en el marco de Service-Oriented Vehicle Diagnostics (SOVD). Conforme a [SWS_DM_01796], la instancia del Diagnostic Server implementa los métodos de la API SOVD para actualizaciones de software de acuerdo con el estándar ASAM SOVD. Puesto que la lógica funcional de las actualizaciones de software no se procesa dentro del Functional Cluster Diagnostics, la tramitación corresponde primordialmente a la aplicación adaptativa, mientras que ara::diag::SovdSwUpdate se concentra en el manejo del protocolo SOVD subyacente AUTOSAR_AP_SWS_Diagnostics §7.4 «Figure 7.4: SOVD Software Update API - concept».

En esta arquitectura, UpdatePackageDetails actúa como interfaz para el intercambio de información entre la lógica de actualización específica del vehículo de la aplicación y la capa de protocolo SOVD. La estructura agrupa metadatos necesarios para la identificación, validación, planificación y visualización del proceso de actualización. Entre ellos se incluyen identificadores elementales como el ID del paquete id [SWS_DM_01878] y la denominación name [SWS_DM_01879] junto con la referencia de traducción translation_id [SWS_DM_01881]. Además, la estructura encapsula indicaciones de dimensionamiento y tiempo de ejecución como el tamaño del paquete size en bytes [SWS_DM_01893], la duración estimada de ejecución duration en segundos [SWS_DM_01891], así como el indicador opcional automated para procesos automatizados [SWS_DM_01882]. Para la trazabilidad y la gestión de componentes de destino, transporta datos de procedencia en origin [SWS_DM_01883], la lista de componentes actualizados en updated_components [SWS_DM_01894], así como elementos del sistema afectados en affected_components [SWS_DM_01895]. Las condiciones marco adicionales y las interacciones de usuario se proporcionan a través de preconditions [SWS_DM_01888], execution_conditions [SWS_DM_01890], notes [SWS_DM_01884] y user_activity [SWS_DM_01886] junto con sus respectivos identificadores de traducción preconditions_translation_id [SWS_DM_01889], notes_translation_id [SWS_DM_01885] y user_activity_translation_id [SWS_DM_01887].

Ruta de uso

El uso principal de UpdatePackageDetails se realiza en el marco de la determinación de información detallada sobre actualizaciones a través de SOVD. Un flujo típico se desarrolla de la siguiente manera:

  • Recepción de la solicitud: un cliente externo envía una solicitud para consultar los detalles del paquete al Diagnostic Server, que implementa los métodos de la API SOVD para actualizaciones de software [SWS_DM_01796].
  • Invocación del método: dado que la capa de protocolo delega la lógica de actualización en la aplicación AUTOSAR_AP_SWS_Diagnostics §7.4, el framework inicia la invocación de función GetUpdatePackageDetails [SWS_DM_01917].
  • Compilación de los datos: la aplicación determina las propiedades del paquete de actualización solicitado. Crea una instancia de UpdatePackageDetails [SWS_DM_01877] y asigna sus campos obligatorios y opcionales:
    • Establecimiento de los identificadores id [SWS_DM_01878] y name [SWS_DM_01879] así como translation_id [SWS_DM_01881].
    • Indicación de los valores métricos size [SWS_DM_01893] así como, de forma opcional, duration [SWS_DM_01891] y automated [SWS_DM_01882].
    • Definición de estructuras de destino y de dependencias mediante origin [SWS_DM_01883], updated_components [SWS_DM_01894] y affected_components [SWS_DM_01895].
    • Almacenamiento de condiciones previas y de ejecución, así como advertencias a través de preconditions [SWS_DM_01888], execution_conditions [SWS_DM_01890], notes [SWS_DM_01884] y user_activity [SWS_DM_01886] con las claves de traducción asociadas [SWS_DM_01889] [SWS_DM_01885] [SWS_DM_01887].
  • Retorno y serialización: la estructura completamente cumplimentada se entrega al framework de diagnóstico. Probablemente, el Diagnostic Server serializa los campos conforme a las prescripciones de ASAM SOVD en una respuesta de protocolo correspondiente y la envía al cliente.
