Contexto

La estructura de datos ara::diag::SovdSwUpdate::UpdatePackageDetails ([SWS_DM_01877], AUTOSAR_AP_SWS_Diagnostics §8.58.4 «Struct: UpdatePackageDetails») sirve dentro de la AUTOSAR Adaptive Platform en el módulo diag como portador de información estructurado para los metadatos y parámetros de ejecución de un paquete de actualización de software. Está declarada en el encabezado #include "ara/diag/sovd_sw_update.h" y representa un parámetro de interfaz esencial para flujos de diagnóstico y actualización relacionados con el software que se proporcionan a través del estándar ASAM SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01796]).

La integración arquitectónica sigue la división funcional de tareas de la actualización de software SOVD (AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»): dado que la lógica de negocio propiamente dicha para las actualizaciones de software no se ejecuta dentro del Functional Cluster Diagnostics, la implementación funcional recae principalmente en la aplicación correspondiente. La instancia ara::diag::SovdSwUpdate::SovdSwUpdate del Diagnostic Server se concentra en la gestión del protocolo SOVD subyacente según ASAM SOVD ([SWS_DM_01796]). En este contexto, UpdatePackageDetails actúa como un objeto de transferencia estandarizado con el cual la aplicación, a través de la función de API ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»), proporciona datos detallados del paquete al Diagnostic Server para que este pueda atender a clientes SOVD externos.

Diagrama de contexto: integración de UpdatePackageDetails en la interacción entre el cliente SOVD, el Diagnostic Server y la aplicación. Fuentes: [SWS_DM_01796], [SWS_DM_01877], [SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API».

Ciclo de vida

Como estructura de datos pasiva (struct) [SWS_DM_01877], UpdatePackageDetails no posee una máquina de estados propia ni controla fases de ciclo de vida autónomas. La creación se realiza mediante instanciación por parte de la aplicación en el momento de una consulta concreta, tras lo cual las variables miembro públicas se rellenan con los atributos estáticos y dinámicos del paquete:

  • Identificación y denominación: el campo id ([SWS_DM_01878]) almacena la ID unívoca del paquete. La denominación name ([SWS_DM_01879]) especifica el nombre del paquete, mientras que translation_id ([SWS_DM_01881]) proporciona una clave para representaciones localizadas.
  • Datos de tamaño y ejecución: el tamaño del paquete en bytes se define a través de size ([SWS_DM_01893]) como std::uint64_t. Los parámetros de control adicionales son la duración estimada de ejecución duration en segundos ([SWS_DM_01891], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 «duration») como ara::core::Optional<std::uint64_t>, así como el indicador automated ([SWS_DM_01882], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 «automated») como ara::core::Optional<bool>.
  • Condiciones previas y actividades del usuario: las condiciones para la ejecución se transmiten en preconditions ([SWS_DM_01888]) junto con preconditions_translation_id ([SWS_DM_01889]) y execution_conditions ([SWS_DM_01890]). Las acciones del operador requeridas las deposita la aplicación en user_activity ([SWS_DM_01886]) y user_activity_translation_id ([SWS_DM_01887]). Se pueden transferir indicaciones adicionales mediante notes ([SWS_DM_01884]) y notes_translation_id ([SWS_DM_01885]).
  • Relaciones entre componentes y origen: el vector affected_components ([SWS_DM_01895], AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 «affected_components») enumera los componentes afectados por el paquete, mientras que updated_components ([SWS_DM_01894]) designa los componentes actualizados explícitamente. La procedencia del paquete de actualización se comunica a través de origin ([SWS_DM_01883]).

En cuanto a la propiedad, la aplicación crea la instancia y la transfiere al llamador mediante el valor de retorno. La destrucción de la instancia se realiza automáticamente al salir del ámbito de acuerdo con la semántica estándar de C++ (RAII). La estructura no ofrece sincronización interna de subprocesos; en caso de accesos simultáneos de lectura o escritura a través de límites de subprocesos, la protección de la instancia corresponde al componente de software llamador.

Ruta de uso

El uso habitual de UpdatePackageDetails tiene lugar en el marco de los métodos estandarizados de SOVD para consultar detalles de actualizaciones de software ([SWS_DM_01796]). A menudo, el cliente recupera previamente una lista de todas las actualizaciones disponibles ([SWS_DM_01797]) antes de solicitar de forma específica los detalles del paquete.

El flujo de llamadas es el siguiente:

  1. Petición por parte del cliente SOVD: un cliente de diagnóstico externo envía una petición de los detalles de un determinado paquete de software a la Diagnostic Server Instance ([SWS_DM_01796]).
  2. Reenvío a la aplicación: el Diagnostic Server delega la determinación de los detalles en la aplicación registrada a través de ara::diag::SovdSwUpdate::GetUpdatePackageDetails ([SWS_DM_01917], AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»).
  3. Recopilación de los datos: la aplicación determina los metadatos del paquete, instancia UpdatePackageDetails ([SWS_DM_01877]) y completa datos de identificación como id ([SWS_DM_01878]) y size ([SWS_DM_01893]), así como dependencias como affected_components ([SWS_DM_01895]).
  4. Retorno: Interpretación: es probable que la aplicación devuelva el objeto UpdatePackageDetails cumplimentado directamente como resultado de la función de GetUpdatePackageDetails al Diagnostic Server.
  5. Respuesta de protocolo: Interpretación: presumiblemente, el Diagnostic Server asume la serialización de los atributos de C++ en el formato de respuesta estandarizado de SOVD y lo entrega al cliente solicitante ([SWS_DM_01796]).

Diagrama de secuencia: flujo de llamadas y de datos en la consulta de UpdatePackageDetails a través de GetUpdatePackageDetails. <p>La estructura de datos <code>ara::diag::SovdSwUpdate::UpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=751">AUTOSAR_AP_SWS_Diagnostics §8.58.4 «Struct: UpdatePackageDetails»</a>) sirve dentro de la AUTOSAR Adaptive Platform en el módulo <code>diag</code> como portador de información estructurado para los metadatos y parámetros de ejecución de un paquete de actualización de software. <p>La integración arquitectónica sigue la división funcional de tareas de la actualización de software SOVD (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.4 «SOVD Software Update API»</a>): dado que la lógica de negocio propiamente dicha para las actualizaciones de software no se ejecuta dentro del Functional Cluster Diagnostics, la implementación funcional recae principalmente en la aplicación correspondiente. <h4>Ciclo de vida</h4>
<p>Como estructura de datos pasiva (<code>struct</code>) <a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>, <code>UpdatePackageDetails</code> no posee una máquina de estados propia ni controla fases de ciclo de vida autónomas. La creación se realiza mediante instanciación por parte de la aplicación en el momento de una consulta concreta, tras lo cual las variables miembro públicas se rellenan con los atributos estáticos y dinámicos del paquete:</p>
<ul>
<li><strong>Identificación y denominación:</strong> el campo <code>id</code> (<a class="spec-record-ref" data-req="SWS_DM_01878" href="../spec/record.html?id=SWS_DM_01878">[SWS_DM_01878]</a>) almacena la ID unívoca del paquete. La denominación <code>name</code> (<a class="spec-record-ref" data-req="SWS_DM_01879" href="../spec/record.html?id=SWS_DM_01879">[SWS_DM_01879]</a>) especifica el nombre del paquete, mientras que <code>translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01881" href="../spec/record.html?id=SWS_DM_01881">[SWS_DM_01881]</a>) proporciona una clave para representaciones localizadas.</li>
<li><strong>Datos de tamaño y ejecución:</strong> el tamaño del paquete en bytes se define a través de <code>size</code> (<a class="spec-record-ref" data-req="SWS_DM_01893" href="../spec/record.html?id=SWS_DM_01893">[SWS_DM_01893]</a>) como <code>std::uint64_t</code>. Los parámetros de control adicionales son la duración estimada de ejecución <code>duration</code> en segundos (<a class="spec-record-ref" data-req="SWS_DM_01891" href="../spec/record.html?id=SWS_DM_01891">[SWS_DM_01891]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=752">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 «duration»</a>) como <code>ara::core::Optional&lt;std::uint64_t&gt;</code>, así como el indicador <code>automated</code> (<a class="spec-record-ref" data-req="SWS_DM_01882" href="../spec/record.html?id=SWS_DM_01882">[SWS_DM_01882]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=752">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 «automated»</a>) como <code>ara::core::Optional&lt;bool&gt;</code>.</li>
<li><strong>Condiciones previas y actividades del usuario:</strong> las condiciones para la ejecución se transmiten en <code>preconditions</code> (<a class="spec-record-ref" data-req="SWS_DM_01888" href="../spec/record.html?id=SWS_DM_01888">[SWS_DM_01888]</a>) junto con <code>preconditions_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01889" href="../spec/record.html?id=SWS_DM_01889">[SWS_DM_01889]</a>) y <code>execution_conditions</code> (<a class="spec-record-ref" data-req="SWS_DM_01890" href="../spec/record.html?id=SWS_DM_01890">[SWS_DM_01890]</a>). Las acciones del operador requeridas las deposita la aplicación en <code>user_activity</code> (<a class="spec-record-ref" data-req="SWS_DM_01886" href="../spec/record.html?id=SWS_DM_01886">[SWS_DM_01886]</a>) y <code>user_activity_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01887" href="../spec/record.html?id=SWS_DM_01887">[SWS_DM_01887]</a>). Se pueden transferir indicaciones adicionales mediante <code>notes</code> (<a class="spec-record-ref" data-req="SWS_DM_01884" href="../spec/record.html?id=SWS_DM_01884">[SWS_DM_01884]</a>) y <code>notes_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01885" href="../spec/record.html?id=SWS_DM_01885">[SWS_DM_01885]</a>).</li>
<li><strong>Relaciones entre componentes y origen:</strong> el vector <code>affected_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01895" href="../spec/record.html?id=SWS_DM_01895">[SWS_DM_01895]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=751">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 «affected_components»</a>) enumera los componentes afectados por el paquete, mientras que <code>updated_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01894" href="../spec/record.html?id=SWS_DM_01894">[SWS_DM_01894]</a>) designa los componentes actualizados explícitamente. La procedencia del paquete de actualización se comunica a través de <code>origin</code> (<a class="spec-record-ref" data-req="SWS_DM_01883" href="../spec/record.html?id=SWS_DM_01883">[SWS_DM_01883]</a>).</li>

<p>En cuanto a la propiedad, la aplicación crea la instancia y la transfiere al llamador mediante el valor de retorno. La destrucción de la instancia se realiza automáticamente al salir del ámbito de acuerdo con la semántica estándar de C++ (RAII). La estructura no ofrece sincronización interna de subprocesos; en caso de accesos simultáneos de lectura o escritura a través de límites de subprocesos, la protección de la instancia corresponde al componente de software llamador.</p>

<h4>Ruta de uso</h4>
<p>El uso habitual de <code>UpdatePackageDetails</code> tiene lugar en el marco de los métodos estandarizados de SOVD para consultar detalles de actualizaciones de software (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>). A menudo, el cliente recupera previamente una lista de todas las actualizaciones disponibles (<a class="spec-record-ref" data-req="SWS_DM_01797" href="../spec/record.html?id=SWS_DM_01797">[SWS_DM_01797]</a>) antes de solicitar de forma específica los detalles del paquete.</p>
<p>El flujo de llamadas es el siguiente:</p>
<ol>
<li><strong>Petición por parte del cliente SOVD:</strong> un cliente de diagnóstico externo envía una petición de los detalles de un determinado paquete de software a la Diagnostic Server Instance (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>).</li>
<li><strong>Reenvío a la aplicación:</strong> el Diagnostic Server delega la determinación de los detalles en la aplicación registrada a través de <code>ara::diag::SovdSwUpdate::GetUpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=742">AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 «GetUpdatePackageDetails»</a>).</li>
<li><strong>Recopilación de los datos:</strong> la aplicación determina los metadatos del paquete, instancia <code>UpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>) y completa datos de identificación como <code>id</code> (<a class="spec-record-ref" data-req="SWS_DM_01878" href="../spec/record.html?id=SWS_DM_01878">[SWS_DM_01878]</a>) y <code>size</code> (<a class="spec-record-ref" data-req="SWS_DM_01893" href="../spec/record.html?id=SWS_DM_01893">[SWS_DM_01893]</a>), así como dependencias como <code>affected_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01895" href="../spec/record.html?id=SWS_DM_01895">[SWS_DM_01895]</a>).</li>
<li><strong>Retorno:</strong> Interpretación: es probable que la aplicación devuelva el objeto <code>UpdatePackageDetails</code> cumplimentado directamente como resultado de la función de <code>GetUpdatePackageDetails</code> al Diagnostic Server.</li>
<li><strong>Respuesta de protocolo:</strong> Interpretación: presumiblemente, el Diagnostic Server asume la serialización de los atributos de C++ en el formato de respuesta estandarizado de SOVD y lo entrega al cliente solicitante (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>).</li>
</ol>
