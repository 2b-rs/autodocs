Genera datos aleatorios criptográficos y gestiona el estado interno del generador, así como su suministro de entropía.

La interfaz ara::crypto::cryp::RandomGeneratorCtx proporciona un contexto seguro para hilos para la generación de números pseudoaleatorios en búferes preparados [SWS_CRYPT_22915]. Según la implementación del contexto, el estado interno del generador debe inicializarse previamente a través de Seed mediante datos de entropía o claves ([SWS_CRYPT_22911], [SWS_CRYPT_22912]). En caso de falta de inicialización o si se agota la reserva de entropía, la función de generación responde a la llamada con los correspondientes códigos de error estandarizados [SWS_CRYPT_22915].

Contexto

La interfaz ara::crypto::cryp::RandomGeneratorCtx define el contexto criptográfico para generadores de números aleatorios dentro del módulo de Adaptive crypto. Como especialización de CryptoContext, la clase sirve para la generación de secuencias (pseudo)aleatorias criptográficamente seguras y para la gestión del estado interno del generador. Los servicios de aplicación acceden típicamente a instancias de esta interfaz para obtener material de claves, vectores de inicialización o valores aleatorios para protocolos relevantes para la seguridad. La provisión y el intercambio de instancias de contexto se efectúan primordialmente a través de punteros inteligentes compartidos, para lo cual está disponible el alias de tipo Sptr [SWS_CRYPT_22901].

Ciclo de vida

El tiempo de vida de un contexto de generador de números aleatorios se controla mediante conteo de referencias a través de std::shared_ptr ([SWS_CRYPT_22901]). Tras la instanciación, según la implementación subyacente, un generador se encuentra ya en un estado listo para operar o bien requiere una inicialización previa por parte de la aplicación. Para inicializar el estado interno del generador se utiliza el método Seed, al que se le suministra un área de memoria sin procesar mediante ReadOnlyMemRegion [SWS_CRYPT_22911] o un objeto de clave simétrica del tipo SymmetricKey::Sptr [SWS_CRYPT_22912]. Todas las funciones miembro centrales (Seed, AddEntropy y Generate) están declaradas según la especificación como seguras frente a excepciones (noexcept) y seguras para hilos ([SWS_CRYPT_22911], [SWS_CRYPT_22912], [SWS_CRYPT_22914], [SWS_CRYPT_22915]), por lo que se admiten llamadas paralelas desde múltiples hilos sin bloqueo interno en la aplicación.

Ruta de uso

El flujo de uso regular comprende la preparación del estado del generador, opcionalmente la incorporación de entropía adicional y la posterior obtención de datos aleatorios:

  • Inicialización del estado (seeding): si el contexto requiere un sembrado por parte del llamador, se ejecuta Seed con datos de entropía [SWS_CRYPT_22911] o una clave simétrica [SWS_CRYPT_22912]. Si la implementación está basada en hardware o tiene inicialización fija y no admite sembrado, la llamada falla.
  • Incorporación de entropía adicional: a través de AddEntropy [SWS_CRYPT_22914] se puede enriquecer en tiempo de ejecución el estado interno con entropía recién obtenida (pasada como ReadOnlyMemRegion).
  • Generación de secuencia aleatoria: el método Generate [SWS_CRYPT_22915] llena el búfer de salida suministrado ReadWriteMemRegion con datos pseudoaleatorios.

Diagrama de secuencias: flujo típico de inicialización del estado, suministro de entropía y generación aleatoria en RandomGeneratorCtx. Fuentes: [SWS_CRYPT_22911], [SWS_CRYPT_22912], [SWS_CRYPT_22914], [SWS_CRYPT_22915]

Escenarios de error

Las operaciones devuelven sus resultados en un ara::core::Result y poseen semánticas de reversión definidas en caso de error:

  • Contexto no inicializado: si la aplicación llama a Generate a pesar de que el contexto exige obligatoriamente un sembrado previo, la operación falla con ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_22915].
  • Falta de entropía: si el contexto no puede generar temporalmente la cantidad solicitada de bytes porque el depósito interno de entropía está agotado, Generate notifica el error ara::crypto::CryptoErrc::kBusyResource [SWS_CRYPT_22915]. En este caso, la aplicación puede repetir la llamada en un momento posterior o realizar un sembrado adicional.
  • Uso inadmisible de clave: si en Seed se pasa un SymmetricKey cuyos derechos de uso configurados no contienen el flag kAllowRngInit, la llamada es rechazada con ara::crypto::CryptoErrc::kUsageViolation [SWS_CRYPT_22912].
  • Funcionalidad no admitida: si una implementación concreta del contexto no admite por diseño el establecimiento de la semilla o la incorporación posterior de entropía, Seed ([SWS_CRYPT_22911], [SWS_CRYPT_22912]) y AddEntropy [SWS_CRYPT_22914] lo confirman con el código de error ara::crypto::CryptoErrc::kUnsupported.

Esta guía se basa en la especificación AUTOSAR Adaptive Platform R25-11 (módulo crypto) y se apoya exclusivamente en los requisitos de especificación indicados.

El método AddEntropy de la clase ara::crypto::cryp::RandomGeneratorCtx sirve para actualizar el estado interno de un generador de números aleatorios (RNG) incorporando valores de entropía adicionales proporcionados [SWS_CRYPT_22914]. La declaración está disponible a través del archivo de cabecera ara/crypto/cryp/random_generator_ctx.h [SWS_CRYPT_22914]. Como parámetro de entrada, la función espera un objeto del tipo ReadOnlyMemRegion denominado entropy, que encapsula el área de memoria con el valor de entropía que se agregará [SWS_CRYPT_22914].

La llamada se ejecuta de forma síncrona (interpretación: la interfaz entrega el resultado directamente sin un tipo de resultado asíncrono). Pregunta Q-6e56e1daaa526bf8 (abierta) El resultado se devuelve como ara::core::Result<void>, que en caso de éxito está vacío si el método es compatible y la entropía pudo incorporarse correctamente [SWS_CRYPT_22914]. Por el contrario, si el contexto concreto del generador de números aleatorios no admite la adición de entropía, la llamada falla y devuelve el código de error ara::crypto::CryptoErrc::kUnsupported con semántica de reversión garantizada [SWS_CRYPT_22914].

En lo relativo a la concurrencia y la seguridad contra fallos, la interfaz está especificada como segura para subprocesos (thread-safe), así como a prueba de excepciones (exception safe), y cuenta con el identificador noexcept [SWS_CRYPT_22914]. Por lo tanto, los llamadores pueden invocar la función de forma segura desde múltiples subprocesos, pero siempre deben evaluar el ara::core::Result devuelto para gestionar una falta de soporte para el suministro de entropía en el contexto correspondiente [SWS_CRYPT_22914].

      La función Generate de la interfaz ara::crypto::cryp::RandomGeneratorCtx sirve para llenar un búfer de salida provisto con una secuencia (pseudo)aleatoria [SWS_CRYPT_22915]. Como parámetro de entrada, el método recibe el área de memoria grabable output de tipo ReadWriteMemRegion, en la que se escriben directamente los bytes aleatorios generados [SWS_CRYPT_22915].
      

  
      En cuanto a la seguridad de ejecución y la concurrencia, el método está declarado como noexcept, se considera exception-safe y está explícitamente especificado como thread-safe [SWS_CRYPT_22915]. Esto permite la invocación concurrente desde múltiples subprocesos.
      

  
      Manejo de errores
      
  
      El tipo de retorno ara::core::Result<void> señala el éxito de la operación mediante un resultado vacío o, en caso de error, devuelve un código de error correspondiente con semántica de reversión [SWS_CRYPT_22915]:
      
  
        
    
      • ara::crypto::CryptoErrc::kUninitializedContext: Se produce si la aplicación debe inicializar o alimentar con entropía («seeded») el contexto previamente [SWS_CRYPT_22915].
        • 
    
      • ara::crypto::CryptoErrc::kBusyResource: Se devuelve cuando el contexto se ha quedado actualmente sin entropía («out-of-entropy») y, por lo tanto, no puede proporcionar la cantidad solicitada de bytes aleatorios [SWS_CRYPT_22915].
        • 
  
      

  
      Interacción y delimitación
      
  
      Mientras que RandomGeneratorCtx::Generate escribe bytes de datos aleatorios sin procesar en búferes [SWS_CRYPT_22915], en el módulo crypt existen otras funciones de generación con un enfoque diferente: así, CryptoProvider::GenerateSymmetricKey [SWS_CRYPT_20721] sirve para instanciar claves simétricas y CryptoProvider::GeneratePrivateKey [SWS_CRYPT_20722] para generar pares de claves asimétricas. Además, el método no debe confundirse con la función homónima Generate de MessageAuthnCodeCtx, que sirve para calcular un digest de MAC [SWS_CRYPT_50029].

El método Seed inicializa el estado interno de un generador de números aleatorios en el contexto de ara::crypto::cryp::RandomGeneratorCtx utilizando una clave simétrica [SWS_CRYPT_22912]. La llamada se realiza de forma síncrona y está especificada como segura para subprocesos y segura ante excepciones (exception safe y noexcept) [SWS_CRYPT_22912]. Como parámetro de entrada sirve un puntero inteligente a una clave (SymmetricKey::Sptr), cuyo valor de clave se adopta como semilla [SWS_CRYPT_22912].

              

              
En el tratamiento de errores, la función devuelve un ara::core::Result<void>, que está vacío en caso de éxito [SWS_CRYPT_22912]. Si la operación falla, se aplica una semántica de reversión; esto afecta en particular a los siguientes códigos de error:

              

                

              • ara::crypto::CryptoErrc::kUsageViolation: Se produce cuando el uso de clave permitido de la clave pasada no incluye el indicador kAllowRngInit [SWS_CRYPT_22912].
                • 

              • ara::crypto::CryptoErrc::kUnsupported: Se notifica si la instancia de contexto concreta no admite el establecimiento de una semilla mediante una clave simétrica [SWS_CRYPT_22912].
                • 

              

              
En interacción con la familia de interfaces, esta función representa la variante basada en clave, mientras que la sobrecarga según [SWS_CRYPT_22911] cubre la inicialización mediante una zona de memoria no estructurada (ReadOnlyMemRegion). Debido a la semántica de reversión (rollback), en caso de error el estado interno del generador permanece probablemente en el estado anterior (interpretación).
