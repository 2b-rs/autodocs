Contexto

La interfaz ara::crypto::cryp::RandomGeneratorCtx define el contexto criptográfico para generadores de números aleatorios dentro del módulo crypto de AUTOSAR Adaptive Platform. Como especialización de CryptoContext, representa la interfaz de programación uniforme para la generación de secuencias pseudoaleatorias criptográficas, así como para la gestión del estado interno del generador.

El interlocutor principal es el componente de aplicación usuario, que solicita datos aleatorios o proporciona entropía. Para la inicialización del estado del generador, la interfaz también puede interactuar con un objeto de clave simétrica del tipo SymmetricKey::Sptr [SWS_CRYPT_22912]. Todas las transferencias de datos para semillas, entropía adicional y las secuencias aleatorias generadas se realizan a través de áreas de memoria estructuradas (ReadOnlyMemRegion y ReadWriteMemRegion) [SWS_CRYPT_22911] [SWS_CRYPT_22914] [SWS_CRYPT_22915].

Ciclo de vida

Para la gestión de instancias, la interfaz define el alias de tipo Sptr como std::shared_ptr<RandomGeneratorCtx> [SWS_CRYPT_22901]. Esto establece un modelo de propiedad compartida a través del cual varios componentes de software pueden hacer referencia a una instancia de contexto común.

En lo que respecta al ciclo de vida interno, la especificación distingue estados funcionales:

  • No inicializado: si un contexto debe inicializarse explícitamente mediante la aplicación, permanece en estado no inicializado tras su creación. Las llamadas para la generación de datos se rechazan en esta fase con ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_22915].
  • Inicializado (listo): mediante la llamada exitosa a uno de los métodos Seed, se establece el estado interno y el generador pasa al estado operativo [SWS_CRYPT_22911] [SWS_CRYPT_22912]. Interpretación: si una instancia de contexto concreta debe ser sembrada obligatoriamente por la aplicación o si ya se inicializa de forma autónoma durante la instanciación, probablemente dependa de la implementación subyacente del controlador o del hardware.
  • Entropía agotada: durante el funcionamiento normal, el contexto puede entrar temporalmente en un estado de falta de entropía en el que la cantidad de bytes solicitada no puede suministrarse y Generate falla con ara::crypto::CryptoErrc::kBusyResource [SWS_CRYPT_22915]. Al suministrar nueva entropía mediante AddEntropy, se actualiza el estado interno [SWS_CRYPT_22914].

En cuanto a concurrencia y seguridad frente a excepciones, todos los métodos de la interfaz (Seed, AddEntropy, Generate) están especificados como seguros frente a excepciones (exception safe) y seguros para hilos (thread-safe), además de declarados con noexcept [SWS_CRYPT_22911] [SWS_CRYPT_22912] [SWS_CRYPT_22914] [SWS_CRYPT_22915]. Esto permite la llamada concurrente desde diferentes contextos de ejecución sin encapsulación mediante exclusión mutua por parte de la aplicación.

Ruta de uso

Una ruta de uso típica para generar datos aleatorios comprende las fases de inicialización, actualización opcional y generación real de datos:

  1. Inicialización (siembra): siempre que el generador requiera y admita una inicialización, la aplicación llama a Seed. En este caso, se pasa una secuencia de bytes como ReadOnlyMemRegion [SWS_CRYPT_22911] o se utiliza una clave simétrica SymmetricKey::Sptr [SWS_CRYPT_22912].
  2. Suministro opcional de entropía: si se dispone de valores de entropía adicionales, la aplicación puede llamar a AddEntropy para enriquecer el estado interno del generador mezclándolo con los datos transmitidos [SWS_CRYPT_22914].
  3. Generación de valores aleatorios: la aplicación proporciona un búfer escribible ReadWriteMemRegion y llama a Generate, con lo cual el búfer se llena con una secuencia pseudoaleatoria [SWS_CRYPT_22915].
  4. Comprobación de resultados: cada llamada devuelve un ara::core::Result<void>, que debe verificarse en busca de errores como cuellos de botella de recursos.

Diagrama de secuencia: secuencia típica de llamadas desde la inicialización y el enriquecimiento de entropía hasta la generación de datos. Fuentes: [SWS_CRYPT_22911], [SWS_CRYPT_22914], [SWS_CRYPT_22915].

Escenarios de error

Los métodos de la interfaz señalan errores mediante ara::core::Result utilizando los códigos de error de ara::crypto::CryptoErrc:

  • CryptoErrc::kUninitializedContext: se produce en Generate si el contexto debe ser sembrado obligatoriamente por la aplicación antes de generar valores aleatorios, pero esto aún no ha sucedido [SWS_CRYPT_22915].
  • CryptoErrc::kBusyResource: se produce en Generate si el contexto se ha quedado actualmente sin entropía («out-of-entropy») y, por lo tanto, no se puede suministrar la cantidad de bytes solicitada [SWS_CRYPT_22915].
  • CryptoErrc::kUsageViolation: se devuelve en Seed(SymmetricKey::Sptr) si los fines de uso permitidos de la clave transmitida no incluyen el derecho kAllowRngInit [SWS_CRYPT_22912].
  • CryptoErrc::kUnsupported: lo señalan Seed y AddEntropy si el generador concreto no admite el establecimiento de una semilla o la mezcla de entropía adicional [SWS_CRYPT_22911] [SWS_CRYPT_22912] [SWS_CRYPT_22914]. Para todos los métodos, se aplica una semántica de reversión en caso de error, de modo que el estado interno del generador permanece intacto.

Esta guía se basa en la especificación AUTOSAR Adaptive del módulo crypto para Release R25-11.
