Define el dominio de errores del Intrusion Detection System Manager para la asignación de códigos de error y excepciones.

La clase vincula el módulo Intrusion Detection System Manager al sistema de gestión de errores de la AUTOSAR Adaptive Platform y define códigos de error y excepciones específicos del dominio [SWS_AIDSM_10706]. Entre sus tareas principales se encuentran la identificación del dominio, el suministro de mensajes de error legibles para los códigos de error y la transformación de errores en excepciones tipadas mediante ThrowAsException [SWS_AIDSM_10712]. Dado que el constructor por defecto está eliminado, el acceso se realiza presumiblemente a través de una instancia global cuyas llamadas a métodos están especificadas como completamente seguras para subprocesos (thread-safe). Pregunta (abierta)

Contexto

La clase ara::idsm::IdsmErrorDomain actúa dentro de la AUTOSAR Adaptive Platform en el módulo idsm como dominio de errores central para la identificación y clasificación de estados de error específicos del sistema del Intrusion Detection System Manager [SWS_AIDSM_10706]. Como especialización final de la clase base ara::core::ErrorDomain, integra de forma homogénea el subsistema IdsM en el modelo unificado de tratamiento de errores de la Adaptive Platform [SWS_AIDSM_10706]. La clase se define en la cabecera ara/idsm/idsm_error_domain.h.

Dentro de la arquitectura de errores, la clase vincula definiciones de tipos relevantes para la gestión de errores del IdsM: a través del alias de tipo Errc referencia la enumeración de códigos de error específica del ámbito IdsmErrc [SWS_AIDSM_10707], mientras que el alias de tipo Exception está vinculado a la clase de excepción específica del módulo IdsmException [SWS_AIDSM_10708]. Además, proporciona a través del método sobrescrito Name() un identificador único del dominio para fines de diagnóstico y registro [SWS_AIDSM_10710].

Diagrama de contexto: clasificación de la IdsmErrorDomain entre clase base, códigos de error y excepciones. Fuentes: [SWS_AIDSM_10706], [SWS_AIDSM_10707], [SWS_AIDSM_10708], [SWS_AIDSM_10712]

Ciclo de vida

La creación de instancias de IdsmErrorDomain está sujeta a restricciones estrictas. El constructor por defecto está explícitamente eliminado (IdsmErrorDomain() = delete;) [SWS_AIDSM_10709]. Por lo tanto, los componentes y aplicaciones llamantes no pueden instanciar la clase mediante una creación de objetos convencional. En la práctica, la provisión de la instancia del dominio se realiza presumiblemente mediante una función de acceso estática del módulo como singleton de larga duración, como es habitual para los dominios de errores en la AUTOSAR Adaptive Platform. Pregunta Q-f791746dd8b5c3d5 (abierta)

Como dominio de errores puramente funcional, la clase no posee estados internos modificables ni atraviesa fases complejas de ciclo de vida o transiciones de estado. En cuanto a la concurrencia, todas las llamadas a métodos proporcionadas (Name(), Message() y ThrowAsException()) están especificadas explícitamente como thread-safe [SWS_AIDSM_10710], [SWS_AIDSM_10711], [SWS_AIDSM_10712]. Por lo tanto, las instancias del dominio de errores pueden utilizarse de forma segura y paralela desde múltiples subprocesos del sistema sin mecanismos de sincronización externos adicionales.

Ruta de uso

En el uso práctico, la clase sirve para la traducción e intermediación de errores del IdsM dentro del sistema de software a través de los siguientes pasos típicos:

  • Identificación y diagnóstico: mediante el método Name() se puede consultar el identificador del dominio de errores para determinar si un error presente procede del módulo IdsM [SWS_AIDSM_10710].
  • Mensaje de error textual: en presencia de un código de error específico de IdsmErrc (alias Errc), la llamada a Message(errorCode) devuelve una descripción legible de la causa del error como cadena de caracteres [SWS_AIDSM_10707], [SWS_AIDSM_10711].
  • Lanzamiento de excepciones: si una jerarquía de llamadas requiere una excepción en lugar de una gestión de errores basada en valores, el método ThrowAsException(errorCode) convierte un código de error directamente en la excepción correspondiente [SWS_AIDSM_10712].

A través de esta ruta de uso, el dominio admite tanto comprobaciones de errores basadas en valores mediante ara::core::ErrorCode como flujos de control clásicos basados en excepciones en caso de error.

Escenarios de error

Las condiciones de error dentro del módulo IdsM se representan mediante valores de la enumeración IdsmErrc, a los que se accede de forma tipada a través del alias Errc [SWS_AIDSM_10707]. El dominio de errores controla cómo se transforman estos códigos de error en situaciones de excepción.

El método ThrowAsException(const ara::core::ErrorCode& errorCode) está anotado con noexcept(false) y lanza la excepción correspondiente al código de error transferido [SWS_AIDSM_10712]. Dicho tipo es IdsmException, el cual está vinculado a través del alias Exception [SWS_AIDSM_10708]. Interpretación: en caso de error, la llamada no retorna de forma regular, sino que fuerza la salida del contexto de ejecución actual lanzando la excepción. Pregunta Q-52ca402c6c38a110 (abierta) En cambio, Name() y Message() garantizan, gracias a su declaración noexcept, que durante la simple consulta de nombre o mensaje nunca puedan lanzarse excepciones no intencionadas [SWS_AIDSM_10710], [SWS_AIDSM_10711].
