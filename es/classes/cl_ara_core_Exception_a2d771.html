Sirve como clase base para todas las excepciones de AUTOSAR y encapsula un código de error seguro para subprocesos para su evaluación.

La clase ara::core::Exception sirve como clase base común para todos los tipos de excepción de la Adaptive Platform e incrusta un ErrorCode en la jerarquía de excepciones estandarizada de C++ [SWS_CORE_00611]. Cuando se producen errores, transporta este código de error de forma segura para subprocesos a un manejador, que puede evaluarlo mediante Error() o el método estándar derivado what() [SWS_CORE_00613]. Todas las operaciones son estrictamente seguras frente a excepciones y están declaradas como noexcept. Para evitar el corte involuntario de objetos (object slicing) en tipos derivados, las operaciones de copia se implementan como protegidas.

Contexto

La clase ara::core::Exception sirve como clase base común para todos los tipos de excepción dentro de la AUTOSAR Adaptive Platform. Tiende un puente entre el tratamiento de excepciones de la biblioteca estándar de C++ y el modelo de errores de AUTOSAR: por un lado, deriva públicamente de std::exception y sobrescribe su función miembro virtual what() [SWS_CORE_00612]; por otro lado, transporta un objeto de error incrustado del tipo ara::core::ErrorCode [SWS_CORE_00611], [SWS_CORE_00613].

La responsabilidad principal de ara::core::Exception consiste en proporcionar información de error de forma estructurada a través de los límites de llamada en caso de excepción. Interpretación: la clase probablemente esté concebida como raíz común para clases de excepción específicas del dominio de la plataforma; sus operaciones de copia están especificadas como protected para evitar el corte involuntario de objetos (object slicing) en instancias derivadas [SWS_CORE_00614], [SWS_CORE_00618].

Diagrama de contexto: integración de ara::core::Exception entre std::exception, el ErrorCode encapsulado y las clases derivadas. Fuentes: [SWS_CORE_00611], [SWS_CORE_00612], [SWS_CORE_00614], [SWS_CORE_00618].

Ciclo de vida

La creación de una ara::core::Exception requiere obligatoriamente la indicación explícita de un código de error al llamar al constructor [SWS_CORE_00611]. Este constructor está definido como noexcept y, por lo tanto, no lanza excepciones por sí mismo.

La propiedad y las posibilidades de copia siguen reglas de protección estrictas: tanto el constructor de copia [SWS_CORE_00618] como el operador de asignación por copia [SWS_CORE_00614] poseen el modificador de acceso protected. Esto evita que las subclases polimórficas se copien de forma incompleta a través de interfaces de la clase base. En cambio, para la transferencia de recursos, el constructor de movimiento [SWS_CORE_00615] y el operador de asignación por movimiento con calificador de referencia & [SWS_CORE_00616] están disponibles públicamente como noexcept=default.

La destrucción se realiza de forma determinista a través del destructor virtual [SWS_CORE_00617], que está especificado como noexcept override=default y garantiza la limpieza adecuada de las instancias derivadas. Los accesos de lectura concurrentes a los métodos, así como la instanciación, están designados como seguros para subprocesos [SWS_CORE_00611], [SWS_CORE_00612], [SWS_CORE_00613].

Ruta de uso

El flujo regular abarca desde la detección del error y el lanzamiento de la excepción hasta el diagnóstico estructurado en el manejador de excepciones:

  • Creación y lanzamiento: un componente detecta una situación de error, instancia la excepción con el ErrorCode [SWS_CORE_00611] adecuado y lanza el objeto a través de throw.
  • Captura: un bloque de nivel superior captura el objeto por referencia (por ejemplo, como const ara::core::Exception& o de forma polimórfica como const std::exception&).
  • Salida de texto estandarizada: a través de what() se puede obtener una explicación textual como cadena terminada en nulo [SWS_CORE_00612]. Todas las garantías de tiempo de vida de std::exception::what se conservan por completo.
  • Comprobación detallada de errores: a través de la función miembro Error(), el manejador accede a una referencia constante del ErrorCode [SWS_CORE_00613] integrado para evaluar de forma automatizada dominios de error y códigos específicos del sistema.

Diagrama de secuencia: secuencia típica de llamadas desde la instanciación hasta la consulta de errores. Fuentes: [SWS_CORE_00611], [SWS_CORE_00612], [SWS_CORE_00613].

Escenarios de error

Dado que ara::core::Exception en sí mismo representa el objeto portador para estados de error, todas las operaciones están diseñadas para una máxima tolerancia a fallos:

  • Seguridad frente a excepciones: todas las funciones miembro —incluidos constructores, operadores de asignación, destructor y métodos de inspección— están declaradas explícitamente como noexcept y especificadas como seguras frente a excepciones (exception safe) [SWS_CORE_00611], [SWS_CORE_00612], [SWS_CORE_00613], [SWS_CORE_00614], [SWS_CORE_00615], [SWS_CORE_00616], [SWS_CORE_00617], [SWS_CORE_00618]. Esto evita excepciones secundarias fatales durante el tratamiento de excepciones.
  • Condiciones de tiempo de vida: la referencia proporcionada por Error() se vincula al objeto de excepción [SWS_CORE_00613]; no debe utilizarse más allá del tiempo de vida de la Exception. Para la devolución de what() se aplican las reglas de tiempo de vida de la biblioteca estándar [SWS_CORE_00612].
  • Prevención de estados de objeto no válidos: mediante la encapsulación de las operaciones de copia en el ámbito protected se evita que las subclases polimórficas se vuelvan inconsistentes accidentalmente por slicing [SWS_CORE_00614], [SWS_CORE_00618].

Esta guía se basa en la especificación AUTOSAR Adaptive Platform Release R25-11.
