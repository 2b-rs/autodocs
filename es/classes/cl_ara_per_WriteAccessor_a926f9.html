clase ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Sirve para la escritura en búfer de archivos binarios y de texto, así como para su sincronización en el almacenamiento físico.

La clase ara::per::WriteAccessor permite escribir contenidos de archivo binarios o textuales en el módulo de persistencia y proporciona métodos para accesos de escritura no formateados, así como un operador de flujo formateado [SWS_PER_00423]. Dado que las operaciones de escritura pueden almacenarse inicialmente en el búfer del sistema operativo, la llamada a SyncToFile() fuerza el volcado permanente al almacenamiento físico [SWS_PER_00122]. Todos los métodos son seguros frente a excepciones, pero no son seguros para subprocesos, por lo que los accesos concurrentes deben ser protegidos por la aplicación.

Contexto

ara::per::WriteAccessor es una clase final del módulo de persistencia (per) de la AUTOSAR Adaptive Platform y deriva virtualmente de FileAccessor. La clase proporciona operaciones de escritura para contenidos de archivo. Ofrece métodos para escritura no formateada y controlada con gestión de errores a través de ara::core::Result, así como un operador de flujo sobrecargado para escritura formateada. Como interlocutores actúan la aplicación llamante, el búfer de archivos interno del sistema operativo y el medio de almacenamiento físico.

Ciclo de vida

El constructor por defecto de WriteAccessor está explícitamente eliminado y no debe utilizarse [SWS_PER_00596]. (Interpretación: las instancias de WriteAccessor deberían crearse y suministrarse a través de métodos de factoría de unidades de gestión de persistencia de nivel superior, como el almacenamiento de archivos).

La destrucción se realiza a través del destructor virtual ~WriteAccessor() [SWS_PER_00597]. La clase y sus métodos están especificados como seguros frente a excepciones («exception safe») y declarados como noexcept. Con respecto a la concurrencia, WriteAccessor no es seguro para subprocesos («not thread-safe») [SWS_PER_00597]; los accesos paralelos a la misma instancia deben ser protegidos externamente por la aplicación.

Ruta de uso

El flujo regular comprende la escritura de datos en modo no formateado o formateado, el ajuste opcional del tamaño del archivo y el almacenamiento persistente final:

  • Escribir datos binarios: a través de WriteBinary() se escribe un rango de bytes (ara::core::Span<const ara::core::Byte>) en el archivo [SWS_PER_00423].
  • Escribir datos de texto: mediante WriteText() se pasan cadenas de caracteres a través de un ara::core::StringView [SWS_PER_00166]. Adicionalmente, se dispone de operator<< como función de conveniencia para casos de uso no críticos, en los que los errores que se produzcan se ignoran silenciosamente [SWS_PER_00125].
  • Forzar la persistencia: el momento del almacenamiento físico depende de la implementación de la persistencia; SyncToFile() vuelca de forma vinculante el búfer del sistema operativo al medio de almacenamiento [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Ajustar el tamaño del archivo: con SetFileSize() se puede truncar el archivo, eliminando los contenidos sobrantes; la posición del archivo permanece inalterada o se establece en la última posición válida o en 0 [SWS_PER_00428].

Diagrama de secuencias: operaciones de escritura con posterior sincronización en el almacenamiento físico. Fuentes: [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Escenarios de error

Los métodos WriteBinary(), WriteText(), SyncToFile() y SetFileSize() devuelven un ara::core::Result<void> que contiene códigos de error específicos en caso de fallos:

  • PerErrc::kPhysicalStorageFailure: el acceso al medio de almacenamiento físico falla [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. El estado del archivo es desconocido y puede estar completamente destruido (sin semántica de reversión).
  • PerErrc::kOutOfStorageSpace: espacio de almacenamiento físico insuficiente [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. Al escribir, la parte excedente se descarta y la posición queda al final del archivo (sin semántica de reversión).
  • PerErrc::kQuotaExceeded: el archivo superaría el tamaño máximo configurado (AllowedSize) [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (semántica de reversión).
  • PerErrc::kEncryptionFailed: el cifrado o descifrado falla [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. El búfer y la posición se actualizan, pero el archivo no puede persistirse y refleja una versión más antigua en el almacenamiento (semántica de reversión).
  • PerErrc::kAuthenticationFailed: el cálculo o la verificación del MAC falla [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (semántica de reversión).
  • PerErrc::kValidationFailed: no se puede garantizar la validez de los datos almacenados [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (semántica de reversión).
  • PerErrc::kInvalidSize: el nuevo tamaño de archivo en SetFileSize() es mayor que el tamaño de archivo actual [SWS_PER_00428] (semántica de reversión).

  Procedencia
  

      

      

      La función miembro SyncToFile de la clase ara::per::WriteAccessor (definida en #include "ara/per/write_accessor.h") transfiere el contenido actual del archivo de forma síncrona al almacenamiento físico [SWS_PER_00122]. La llamada no acepta parámetros de entrada y devuelve un ara::core::Result<void> que, en caso de éxito, está vacío o, en caso de error, contiene códigos de error específicos del módulo Persistency o errores específicos del fabricante [SWS_PER_00122].
      


      Durante la ejecución pueden producirse diferentes casos de error, algunos de los cuales poseen semántica de reversión (rollback) [SWS_PER_00122]:
      

        

      • StorageFailure: se produce cuando falla el acceso físico al medio de almacenamiento (sin semántica de reversión) [SWS_PER_00122].
        • 

      • PerErrc::kOutOfStorageSpace: se devuelve si el espacio de almacenamiento físico es insuficiente para el archivo modificado (sin semántica de reversión) [SWS_PER_00122].
        • 

      • PerErrc::kQuotaExceeded: se notifica cuando el archivo excede el tamaño máximo configurado AllowedSize del File Storage (con semántica de reversión) [SWS_PER_00122].
        • 

      • PerErrc::kEncryptionFailed: falla el cifrado de los datos almacenados (con semántica de reversión) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed: falla el cálculo del MAC para los datos (con semántica de reversión) [SWS_PER_00122].
        • 

      


      En cuanto a la seguridad de ejecución, el método está declarado como noexcept y especificado como exception safe [SWS_PER_00122]. Sin embargo, dado que está clasificado expresamente como not thread-safe, las llamadas simultáneas sobre la misma instancia de WriteAccessor deben sincronizarse presumiblemente por parte del llamador [SWS_PER_00122].

                  Writes the content of a StringView to the file. The time when the content is persisted depends on the implementation of Persistency. SyncTo File can be used to force Persistency to persist the file content. In case of an error, the file content might be corrupted, and the current position might or might not have changed.
