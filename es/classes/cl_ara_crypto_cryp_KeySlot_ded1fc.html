Gestiona una ubicación de memoria para claves criptográficas y permite consultas de metadatos, así como callbacks de modificación.

La interfaz encapsula una ubicación de memoria persistente o volátil para claves criptográficas y permite la consulta de metadatos de clave, así como del CryptoProvider responsable [SWS_CRYPT_30403]. Las aplicaciones pueden monitorizar cambios de contenido mediante un callback de observador registrable [SWS_CRYPT_30404]. Si el slot está vacío, los accesos al tipo de clave o a su algoritmo fallan con el código de error ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_50055]. Dado que la copia y el movimiento están prohibidos, el acceso se realiza de forma segura para hilos a través de punteros compartidos (shared pointers).

Contexto

La interfaz ara::crypto::cryp::KeySlot representa una ubicación de almacenamiento dedicada para claves criptográficas dentro de AUTOSAR Adaptive Platform. Como encapsulamiento de un slot lógico de clave, gestiona metadatos, información de tipo y la asignación de algoritmos soportados para la clave depositada en él. Una instancia interactúa habitualmente con tres partes: el software de aplicación, el cryp::CryptoProvider asociado, hacia el cual se puede obtener una referencia compartida a través de [SWS_CRYPT_30403], y un callback específico de la aplicación para la monitorización de contenido conforme a [SWS_CRYPT_30404].

Diagrama de contexto: interlocutores de la interfaz KeySlot. Fuentes: [SWS_CRYPT_30403], [SWS_CRYPT_30404]

Ciclo de vida

Un KeySlot está firmemente ligado al almacenamiento de claves que representa. En consecuencia, la interfaz impide la duplicación y el traslado de la instancia: tanto el constructor de copia [SWS_CRYPT_50149] como el constructor de movimiento [SWS_CRYPT_50150] están explícitamente eliminados. Lo mismo aplica al operador de asignación por copia [SWS_CRYPT_50147] y al operador de asignación por movimiento [SWS_CRYPT_50148].

Para la gestión de relaciones de propiedad y referencia, la clase define el alias de tipo de puntero inteligente Sptr como std::shared_ptr<KeySlot> [SWS_CRYPT_50151]. La liberación se efectúa a través de un destructor virtual por defecto [SWS_CRYPT_50146]. Interpretación: Dado que la interfaz no define constructores públicos, es de prever que las instancias concretas sean creadas por el CryptoProvider responsable y proporcionadas como Sptr. Pregunta Q-baef4cb1493c96cd (abierta) Todos los métodos provistos están declarados como seguros para hilos, con lo cual se admiten accesos concurrentes de lectura y monitorización desde múltiples contextos de ejecución.

Ruta de uso

La interacción típica con un KeySlot se divide en la configuración de la monitorización de contenido y la consulta de metadatos de clave almacenados:

  1. Registrar observador: La aplicación registra una función de callback así como un identificador específico de la aplicación mediante RegisterUpdateObserver keySlotIdentifier [SWS_CRYPT_30404]. En llamadas sucesivas, siempre se invoca únicamente el último callback suministrado en caso de actualizaciones o eliminaciones del contenido del slot.
  2. Consultar algoritmos soportados: A través de GetPossibleAlgIds, la aplicación determina una lista de todos los identificadores de algoritmo soportados por el slot [SWS_CRYPT_50056].
  3. Comprobar clave actual: Si hay una clave en el slot, GetCryptoObjectType devuelve el tipo de objeto de la clave [SWS_CRYPT_50054] y GetAlgId su identificador de algoritmo concreto [SWS_CRYPT_50055].
  4. Determinar el proveedor responsable: En caso necesario, se puede consultar el CryptoProvider administrador a través de GetCryptoProvider como puntero compartido [SWS_CRYPT_30403].
  5. Cancelar registro del observador: Una vez finalizada la monitorización, el registro se cancela a través de UnregisterUpdateObserver [SWS_CRYPT_30406].

Diagrama de secuencia: flujo típico para el registro, consulta de metadatos y cancelación del registro en un KeySlot. Fuentes: [SWS_CRYPT_30404], [SWS_CRYPT_50056], [SWS_CRYPT_50054], [SWS_CRYPT_50055], [SWS_CRYPT_30406]

Escenarios de error

Los métodos de consulta aseguran los estados de error a través del tipo de resultado ara::core::Result. En caso de que un KeySlot no contenga ninguna clave, las llamadas GetCryptoObjectType [SWS_CRYPT_50054] y GetAlgId [SWS_CRYPT_50055] devuelven respectivamente el código de error estandarizado ara::crypto::CryptoErrc::kEmptyKeySlot con semántica de reversión (rollback). Los métodos GetPossibleAlgIds [SWS_CRYPT_50056] y GetCryptoProvider [SWS_CRYPT_30403] no especifican códigos de error estandarizados. Para la gestión de observadores mediante RegisterUpdateObserver [SWS_CRYPT_30404] y UnregisterUpdateObserver [SWS_CRYPT_30406], en caso de fallo se prevén errores específicos de la implementación en el objeto de resultado.

                          El método RegisterUpdateObserver de la clase ara::crypto::cryp::KeySlot sirve para registrar una función de devolución de llamada específica de la aplicación que se notifica con cada actualización del contenido de una ranura de clave (key slot) [SWS_CRYPT_30404]. Como actualización se consideran aquí tanto las modificaciones de contenido como el vaciado completo de la ranura [SWS_CRYPT_30404].
