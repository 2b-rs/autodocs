Sirve como fábrica central para la creación y gestión de contextos criptográficos, algoritmos y objetos de clave.

La clase sirve como fábrica central para la provisión de primitivas criptográficas, así como para la creación y gestión de claves y contextos criptográficos ([SWS_CRYPT_20742], [SWS_CRYPT_20721]). Las instancias no son copiables ni trasladables y se gestionan a través de punteros compartidos ([SWS_CRYPT_20701], [SWS_CRYPT_41005]). Los errores, como algoritmos incompatibles o recursos agotados, se devuelven con seguridad de tipos mediante ara::core::Result ([SWS_CRYPT_30098]).

Contexto

La clase ara::crypto::cryp::CryptoProvider constituye la interfaz central para la provisión de operaciones y algoritmos criptográficos en la pila de AUTOSAR Adaptive. Como capa de abstracción, agrupa implementaciones concretas de primitivas criptográficas, así como el acceso a claves y estructuras de memoria. En una arquitectura de sistema típica, el CryptoProvider actúa como intermediario y fábrica entre la lógica de aplicación, los almacenes de claves persistentes y los contextos de procesamiento especializados. Las aplicaciones solicitan a través del proveedor contextos especializados para cifrado simétrico ([SWS_CRYPT_20742]), cifrado asimétrico ([SWS_CRYPT_20750], [SWS_CRYPT_20751]), firmas digitales ([SWS_CRYPT_20756], [SWS_CRYPT_20757]), funciones hash ([SWS_CRYPT_20747]), autenticación de mensajes ([SWS_CRYPT_20746]) o métodos de intercambio de claves ([SWS_CRYPT_20758], [SWS_CRYPT_20752]). Al mismo tiempo, el proveedor interactúa con los KeySlot subyacentes para instanciar claves almacenadas ([SWS_CRYPT_20762], [SWS_CRYPT_20764]).

Diagrama de contexto: integración del CryptoProvider como fábrica e intermediario entre aplicación, contextos y KeySlot. Fuentes: [SWS_CRYPT_20742], [SWS_CRYPT_20756], [SWS_CRYPT_20762].

Ciclo de vida

Las instancias de CryptoProvider poseen semánticas estrictas respecto a las operaciones de copia y movimiento: tanto el constructor de copia ([SWS_CRYPT_41005]) y el constructor de movimiento ([SWS_CRYPT_41006]) como los operadores de asignación correspondientes ([SWS_CRYPT_30216], [SWS_CRYPT_30217]) están explícitamente eliminados (delete). Por lo tanto, el ciclo de vida de una instancia se controla habitualmente mediante referencias o propiedad compartida, para lo cual se define el alias de tipo CryptoProvider::Sptr basado en std::shared_ptr ([SWS_CRYPT_20701]). La limpieza se efectúa a través del destructor virtual estándar ([SWS_CRYPT_20710]). Todos los métodos de interfaz del proveedor están especificados como seguros frente a excepciones (exception safe) y thread-safe (thread-safe), con lo que se permite el acceso concurrente desde múltiples hilos sin sincronización externa a nivel del proveedor.

Ruta de uso

Una ruta de uso típica comprende la provisión de claves, la instanciación del contexto criptográfico adecuado y la posterior ejecución de las transformaciones. En primer lugar, la aplicación genera o importa el material de clave necesario. Para ello, CryptoProvider ofrece métodos como GenerateSymmetricKey ([SWS_CRYPT_20721]), GeneratePrivateKey ([SWS_CRYPT_20722]), ImportPublicKey ([SWS_CRYPT_20732]) o la carga desde un KeySlot existente ([SWS_CRYPT_20762], [SWS_CRYPT_20763]). En función del algoritmo, se pueden determinar permisos por defecto mediante GetDefaultAllowedUsage ([SWS_CRYPT_20955]). En el siguiente paso, la aplicación crea el contexto correspondiente a través de los métodos de fábrica, por ejemplo un AuthCipherCtx ([SWS_CRYPT_20745]) o un SignerPrivateCtx ([SWS_CRYPT_20756]). De forma complementaria, el proveedor suministra datos aleatorios a través de GenerateRandomData ([SWS_CRYPT_30098]) o un valor de contador que crece monótonamente a través de GetSecureCounter ([SWS_CRYPT_20098]). Para el intercambio seguro, el material de clave se puede exportar protegido mediante ExportSecuredKey ([SWS_CRYPT_20728]).

Diagrama de secuencia: flujo para la generación de claves y la creación de un contexto de cifrado autenticado. Fuentes: [SWS_CRYPT_20721], [SWS_CRYPT_20745].

Escenarios de error

Los métodos de CryptoProvider reportan errores mediante el tipo de retorno ara::core::Result con valores de ara::crypto::CryptoErrc. En caso de operaciones fallidas rige la semántica de reversión (rollback). Entre los escenarios de error esenciales se encuentran:

  • Parámetros no válidos o incompatibles: Si se pasa un identificador de algoritmo no admitido, los métodos de creación de contexto y clave devuelven CryptoErrc::kUnknownIdentifier ([SWS_CRYPT_20741], [SWS_CRYPT_20742], [SWS_CRYPT_20721]). Si el algoritmo no se corresponde con la primitiva esperada (p. ej., algoritmo asimétrico en la solicitud de una función hash) o si los flags de uso no encajan con la configuración, se produce CryptoErrc::kInvalidArgument o CryptoErrc::kIncompatibleArguments ([SWS_CRYPT_20747], [SWS_CRYPT_20722], [SWS_CRYPT_50132]).
  • Errores de formato y almacenamiento de claves: Al cargar mediante KeySlot, un slot no ocupado da lugar a CryptoErrc::kEmptyKeySlot, mientras que tipos de clave ajenos o incorrectos desencadenan CryptoErrc::kIncompatibleObject ([SWS_CRYPT_20762], [SWS_CRYPT_20764]). Los formatos de serialización defectuosos provocan CryptoErrc::kUnsupportedFormat ([SWS_CRYPT_50014], [SWS_CRYPT_20732]).
  • Cuellos de botella de recursos y capacidad: Si el generador de números aleatorios está agotado temporalmente o si un recurso de hardware está bloqueado, se devuelve CryptoErrc::kBusyResource ([SWS_CRYPT_30098], [SWS_CRYPT_20721], [SWS_CRYPT_20098]). En caso de búferes de destino insuficientemente dimensionados para datos de identificación o exportaciones de claves, la interfaz reporta CryptoErrc::kInsufficientCapacity ([SWS_CRYPT_50015], [SWS_CRYPT_20728]).
  • Funcionalidades no admitidas: Si una implementación concreta del proveedor no admite funciones opcionales como identificación de proveedor, Secure Counter o RNG estándar, se reporta el error CryptoErrc::kUnsupported ([SWS_CRYPT_50015], [SWS_CRYPT_20098], [SWS_CRYPT_30098]).
