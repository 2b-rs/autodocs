Deriva de forma segura claves simétricas a partir de claves base y parámetros de contexto configurables.

La interfaz ara::crypto::cryp::KeyDerivationFunctionCtx sirve para derivar nuevas claves simétricas a partir de material de clave existente y parámetros de contexto configurables, como sales o contadores [SWS_CRYPT_21515]. Antes de la generación de la clave mediante DeriveKey, el contexto debe inicializarse mediante SetKey con una clave o KeySlot y configurarse opcionalmente a través de SetParameter [SWS_CRYPT_21525]. Como condición de seguridad esencial, la derivación solo debe tener lugar si el material de clave de origen está explícitamente autorizado para operaciones KDF y los flags de uso requeridos para la clave de destino son compatibles.

Contexto

La clase ara::crypto::cryp::KeyDerivationFunctionCtx proporciona la interfaz para funciones de derivación de claves (Key Derivation Functions, KDF) en el módulo criptográfico de AUTOSAR Adaptive. Su cometido principal consiste en derivar nuevas claves simétricas a partir de material de clave especificado y parámetros de contexto configurables [SWS_CRYPT_21515].

Los interlocutores habituales de interacción son los servicios de aplicación invocadores, el material de origen subyacente en forma de un SymmetricKey [SWS_CRYPT_21525] o un KeySlot [SWS_CRYPT_50010], así como el resultado de la derivación en forma de un nuevo SymmetricKey::Sptr [SWS_CRYPT_21515]. Se pueden transferir parámetros criptográficos adicionales como regiones de memoria, números enteros o claves auxiliares [SWS_CRYPT_50007] [SWS_CRYPT_50008] [SWS_CRYPT_50009].

Ciclo de vida

El ciclo de vida y la propiedad de las instancias se controlan a través del puntero inteligente tipado ara::crypto::cryp::KeyDerivationFunctionCtx::Sptr [SWS_CRYPT_21501]. La creación de una instancia de implementación concreta probablemente se realice mediante una factoría especializada o el CryptoProvider responsable, dado que la clase define una interfaz puramente virtual.

Un contexto recién creado se encuentra inicialmente en un estado incompleto. Solo tras la asignación correcta de una clave a través de SetKey [SWS_CRYPT_21525] [SWS_CRYPT_50010] y el establecimiento de los parámetros KDF necesarios mediante SetParameter [SWS_CRYPT_50007] [SWS_CRYPT_50008] [SWS_CRYPT_50009], el contexto está listo para el cálculo. Por lo que respecta a la concurrencia, los métodos de la interfaz están declarados como seguros para subprocesos y seguros frente a excepciones ([SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50007]).

Ruta de uso

La secuencia de llamadas típica para la derivación de claves comprende tres fases consecutivas:

  1. Asignar clave base: a través de SetKey se configura el material de clave de origen. En este paso se puede pasar bien un objeto de clave existente (SymmetricKey::Sptr) [SWS_CRYPT_21525], bien un espacio de almacenamiento de claves persistente (KeySlot::Sptr) [SWS_CRYPT_50010].
  2. Configurar parámetros de contexto: los valores específicos de la KDF, como sal, vectores de inicialización o contadores de iteraciones, se definen a través de SetParameter. Se admiten búferes de memoria (ReadOnlyMemRegion) [SWS_CRYPT_50007], enteros de 64 bits (std::uint64_t) [SWS_CRYPT_50008] y claves simétricas adicionales (SymmetricKey::Sptr) [SWS_CRYPT_50009].
  3. Derivar clave de destino: la llamada a DeriveKey ejecuta el cálculo criptográfico [SWS_CRYPT_21515]. El método espera el identificador del algoritmo de destino (AlgId), así como los flags de uso permitidos (AllowedUsageFlags), y devuelve un SymmetricKey::Sptr en caso de éxito.

Diagrama de secuencia: secuencia de llamadas típica para la derivación de una clave simétrica a través de KeyDerivationFunctionCtx. Fuentes: [SWS_CRYPT_21525], [SWS_CRYPT_50007], [SWS_CRYPT_21515].

Escenarios de error

Los métodos de la interfaz señalan las situaciones de error mediante ara::core::Result utilizando códigos de error definidos:

  • Inicialización incompleta: si se invoca DeriveKey sin una configuración suficiente, la llamada falla con ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_21515]. Si un KeySlot asignado está vacío en el momento de la ejecución, se notifica ara::crypto::CryptoErrc::kEmptyKeySlot [SWS_CRYPT_21515].
  • Vulneración de derechos de uso: la clave de origen debe permitir la operación kAllowKeyDerivation; de lo contrario, se genera ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_21525], [SWS_CRYPT_21515], [SWS_CRYPT_50009]). Si el destino incluye kAllowPlaintextExport, la clave de origen debe presentar adicionalmente kAllowDerivedPlaintextExport; de lo contrario, el resultado también es kUsageViolation [SWS_CRYPT_21515].
  • Incompatibilidad y argumentos no válidos: un algoritmo de destino no admitido produce UnknownIdentifier, y unos flags de uso incompatibles entre sí generan ara::crypto::CryptoErrc::kIncompatibleArguments [SWS_CRYPT_21515]. Ante objetos de clave o KeySlots inadecuados para el contexto, SetKey responde con ara::crypto::CryptoErrc::kIncompatibleObject ([SWS_CRYPT_21525], [SWS_CRYPT_50010]). Los valores de parámetro no válidos dan lugar a ara::crypto::CryptoErrc::kInvalidArgument ([SWS_CRYPT_50007], [SWS_CRYPT_50008]).
  • Funciones de interfaz no compatibles: si una implementación concreta admite exclusivamente KeySlot o exclusivamente SymmetricKey, la otra llamada a SetKey respectiva produce ara::crypto::CryptoErrc::kUnsupported ([SWS_CRYPT_21525], [SWS_CRYPT_50010]). Los nombres de parámetros desconocidos en SetParameter generan igualmente kUnsupported ([SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009]).
  • Conflictos de recursos: si un recurso criptográfico necesario para el cálculo está bloqueado, DeriveKey señala el código de error ara::crypto::CryptoErrc::kBusyResource [SWS_CRYPT_21515].

Esta guía ha sido elaborada por una IA. Todas las afirmaciones técnicas se basan exclusivamente en la especificación de AUTOSAR Adaptive (Release R25-11).

función DeriveKey [SWS_CRYPT_21515] Upstream: RS_CRYPTO_02102, RS_CRYPTO_02107, RS_CRYPTO_02108, RS_CRYPTO_02111, RS_CRYPTO_02115

virtual ara::core::Result< SymmetricKey::Sptr > DeriveKey (AlgId targetAlgId, AllowedUsageFlags allowedUsage) const noexcept=0;

Derive a symmetric key from the provided key material and provided context configuration, e.g., salt, context, IV, iteration count.

GENERADO POR IA no revisado Modelo: gemini-3.8-flash-medium · Effort: medium · Temperatura: nicht steuerbar · Prompt: ad7de7f8f0b6 Procedencia

El método DeriveKey de la clase ara::crypto::cryp::KeyDerivationFunctionCtx deriva de forma síncrona una nueva clave simétrica a partir del material de clave existente y de los parámetros almacenados en el contexto, como el vector de inicialización (IV), el salt o el contador de iteraciones [SWS_CRYPT_21515].

usar

En la llamada se pasan el identificador del algoritmo criptográfico deseado a través de targetAlgId y los indicadores de uso permitidos a través de allowedUsage [SWS_CRYPT_21515]. Como valor de retorno, la función proporciona de forma síncrona un ara::core::Result<SymmetricKey::Sptr> que, en caso de ejecución correcta, suministra un puntero inteligente al objeto de clave simétrica generado [SWS_CRYPT_21515].

Manejo de errores

Si la generación de claves falla, la función garantiza una semántica de reversión y devuelve el código de error correspondiente en ara::core::Result [SWS_CRYPT_21515]:

  • UnknownIdentifier: Se notifica si el valor pasado para targetAlgId no es compatible [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kIncompatibleArguments: Se produce cuando los indicadores de uso especificados en allowedUsage no son compatibles con el algoritmo de destino [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kUninitializedContext: El contexto no se inicializó suficientemente antes de la derivación de claves [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kBusyResource: Un recurso necesario para la derivación de claves está ocupado [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kEmptyKeySlot: Un KeySlot configurado para la operación está actualmente vacío [SWS_CRYPT_21515].
  • ara::crypto::CryptoErrc::kUsageViolation: Se produce si la autorización de uso de la clave de origen no contiene kAllowKeyDerivation o si el destino requiere kAllowPlaintextExport, pero el origen no permite kAllowDerivedPlaintextExport [SWS_CRYPT_21515].

Concurrencia y contexto de ejecución

El método está especificado como noexcept, ofrece seguridad ante excepciones (exception safe) y está diseñado como seguro para subprocesos (thread-safe) para llamadas simultáneas [SWS_CRYPT_21515].

          El método virtual SetKey configura el contexto KeyDerivationFunctionCtx para el uso de una clave almacenada en un KeySlot pasado tan pronto como se lleve a cabo la derivación de claves [SWS_CRYPT_50010]. Como parámetro, la función recibe un puntero inteligente KeySlot::Sptr que referencia una ranura con una clave simétrica [SWS_CRYPT_50010].
          

          La llamada se efectúa de manera síncrona y está especificada como segura ante excepciones (exception safe) y no lanzadora (noexcept) [SWS_CRYPT_50010]. La función devuelve un ara::core::Result<void>, que en caso de éxito está vacío o, en caso de error, encapsula un código de error correspondiente [SWS_CRYPT_50010]. Si se produce un error, se preserva el estado anterior mediante una semántica de reversión [SWS_CRYPT_50010]:
          

            

          • ara::crypto::CryptoErrc::kIncompatibleObject: Se devuelve si el keySlot proporcionado es incompatible con el contexto actual [SWS_CRYPT_50010].
            • 

          • ara::crypto::CryptoErrc::kUnsupported: Se produce cuando el contexto concreto solo admite el establecimiento de un SymmetricKey [SWS_CRYPT_50010].
            • 

          

          Para el acceso simultáneo desde varios hilos, el método está designado como seguro para subprocesos (thread-safe) [SWS_CRYPT_50010]. En cuanto a la interacción, la operación sirve como alternativa a la sobrecarga de SetKey con un SymmetricKey::Sptr, la cual recibe el material de clave directamente en lugar de una referencia de ranura [SWS_CRYPT_21525].
