Contexto

La clase ara::rds::RdsErrorDomain representa el dominio de errores central para el módulo Raw Data Stream (RDS) dentro de la AUTOSAR Adaptive Platform en la versión R25-11. Está declarada como final y hereda de la clase base ara::core::ErrorDomain. Su tarea principal es la identificación unívoca, clasificación y descripción textual de los errores que se producen en el ámbito funcional de RDS.

Como variante especializada de ara::core::ErrorDomain, RdsErrorDomain vincula varios tipos y componentes del sistema de errores:

  • La enumeración de errores RdsErrc, que está disponible directamente en el ámbito de la clase a través del alias tipificado Errc ([SWS_RDS_11326]).
  • El tipo de excepción RdsException, que está anclado dentro del dominio a través del alias Exception ([SWS_RDS_11327]).
  • El objeto de error estándar ara::core::ErrorCode, que asocia un código de error concreto de Errc con la instancia de RdsErrorDomain.
  • El código de aplicación y los servicios del framework, que consultan mensajes de error a través de Name() ([SWS_RDS_11295]) y Message() ([SWS_RDS_11296]) o reenvían errores para la gestión de excepciones.

Diagrama de contexto: Relaciones de tipos y socios de interacción de RdsErrorDomain. Fuentes: [SWS_RDS_11326], [SWS_RDS_11327], [SWS_RDS_11297]

Ciclo de vida

La creación de objetos de la clase RdsErrorDomain está sujeta a requisitos restrictivos: el constructor predeterminado está definido explícitamente como eliminado (RdsErrorDomain() = delete, [SWS_RDS_11294]). Por lo tanto, queda excluida una instanciación directa o múltiple por parte de aplicaciones de usuario en la pila o en el montón.

La provisión de la instancia del dominio probablemente se realice internamente a través de un objeto singleton estático o de larga duración, ya que en el modelo de errores de AUTOSAR Adaptive suele existir una única instancia global por dominio de errores. Mediante la declaración como final, se impide cualquier especialización por herencia.

En lo relativo a la concurrencia, la clase se comporta sin estado. Los métodos de inspección Name() ([SWS_RDS_11295]) y Message() ([SWS_RDS_11296]) están declarados como const noexcept. No modifican estados internos y permiten el acceso de lectura simultáneo y concurrente desde múltiples hilos sin sobrecarga de sincronización.

Ruta de uso

En funcionamiento normal, la clase rara vez es instanciada directamente por el código de aplicación, sino que sirve de backend para ara::core::ErrorCode y ara::core::Result. Un flujo típico de gestión de errores se desarrolla como sigue:

  1. Una operación dentro del módulo rds falla y genera un valor de error del tipo de enumeración Errc ([SWS_RDS_11326]).
  2. El valor de error se encapsula junto con RdsErrorDomain en un ara::core::ErrorCode y se entrega a la parte llamadora.
  3. La aplicación comprueba el objeto de error. A través de Name() ([SWS_RDS_11295]) se puede verificar que el error procede del dominio de errores de RDS.
  4. Para fines de diagnóstico o registro, el sistema invoca Message() ([SWS_RDS_11296]) para obtener el mensaje textual asignado al código de error.
  5. Si se elige un mecanismo de excepciones, la llamada a ErrorCode::ThrowAsException() delega en el método RdsErrorDomain::ThrowAsException() ([SWS_RDS_11297]), lo que desencadena una excepción del tipo Exception ([SWS_RDS_11327]).

Escenarios de error

RdsErrorDomain sirve propiamente para la gestión de situaciones de error y define garantías robustas para sus interfaces:

  • Códigos de error: Las causas específicas se representan mediante la enumeración RdsErrc, que está tipificada como Errc ([SWS_RDS_11326]).
  • Seguridad frente a excepciones de las consultas: Los métodos Name() ([SWS_RDS_11295]) y Message(CodeType errorCode) ([SWS_RDS_11296]) están especificados como noexcept. Garantizan que no se lancen excepciones adicionales incluso en caso de escasez de recursos o errores. Si se pasara un código de error desconocido, probablemente se devuelva un texto genérico de respaldo para mantener la garantía noexcept.
  • Lanzamiento de excepciones: El método ThrowAsException(const ara::core::ErrorCode &errorCode) está declarado con noexcept(false) ([SWS_RDS_11297]). Lanza de forma determinista una instancia de RdsException ([SWS_RDS_11327]). La condición previa es un objeto ErrorCode válido; no se produce un retorno normal.

<h4>Ciclo de vida</h4>
<p>La creación de objetos de la clase <code>RdsErrorDomain</code> está sujeta a requisitos restrictivos: el constructor predeterminado está definido explícitamente como eliminado (<code>RdsErrorDomain() = delete</code>, <a class="spec-record-ref" data-req="SWS_RDS_11294" href="../spec/record.html?id=SWS_RDS_11294">[SWS_RDS_11294]</a>). Por lo tanto, queda excluida una instanciación directa o múltiple por parte de aplicaciones de usuario en la pila o en el montón.</p>
<p>La provisión de la instancia del dominio probablemente se realice internamente a través de un objeto singleton estático o de larga duración, ya que en el modelo de errores de AUTOSAR Adaptive suele existir una única instancia global por dominio de errores. Mediante la declaración como <code>final</code>, se impide cualquier especialización por herencia.</p>
<p>En lo relativo a la concurrencia, la clase se comporta sin estado. Los métodos de inspección <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>) y <code>Message()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) están declarados como <code>const noexcept</code>. No modifican estados internos y permiten el acceso de lectura simultáneo y concurrente desde múltiples hilos sin sobrecarga de sincronización.</p>

<h4>Ruta de uso</h4>
<p>En funcionamiento normal, la clase rara vez es instanciada directamente por el código de aplicación, sino que sirve de backend para <code>ara::core::ErrorCode</code> y <code>ara::core::Result</code>. Un flujo típico de gestión de errores se desarrolla como sigue:</p>
<ol>
<li>Una operación dentro del módulo <code>rds</code> falla y genera un valor de error del tipo de enumeración <code>Errc</code> (<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>).</li>
<li>El valor de error se encapsula junto con <code>RdsErrorDomain</code> en un <code>ara::core::ErrorCode</code> y se entrega a la parte llamadora.</li>
<li>La aplicación comprueba el objeto de error. A través de <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>) se puede verificar que el error procede del dominio de errores de RDS.</li>
<li>Para fines de diagnóstico o registro, el sistema invoca <code>Message()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) para obtener el mensaje textual asignado al código de error.</li>
<li>Si se elige un mecanismo de excepciones, la llamada a <code>ErrorCode::ThrowAsException()</code> delega en el método <code>RdsErrorDomain::ThrowAsException()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>), lo que desencadena una excepción del tipo <code>Exception</code> (<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>).</li>
</ol>

<h4>Escenarios de error</h4>
<p><code>RdsErrorDomain</code> sirve propiamente para la gestión de situaciones de error y define garantías robustas para sus interfaces:</p>
<ul>
<li><strong>Códigos de error:</strong> Las causas específicas se representan mediante la enumeración <code>RdsErrc</code>, que está tipificada como <code>Errc</code> (<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>).</li>
<li><strong>Seguridad frente a excepciones de las consultas:</strong> Los métodos <code>Name()</code> (<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>) y <code>Message(CodeType errorCode)</code> (<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>) están especificados como <code>noexcept</code>. Garantizan que no se lancen excepciones adicionales incluso en caso de escasez de recursos o errores. Si se pasara un código de error desconocido, probablemente se devuelva un texto genérico de respaldo para mantener la garantía <code>noexcept</code>.</li>
<li><strong>Lanzamiento de excepciones:</strong> El método <code>ThrowAsException(const ara::core::ErrorCode &amp;errorCode)</code> está declarado con <code>noexcept(false)</code> (<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>). Lanza de forma determinista una instancia de <code>RdsException</code> (<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>). La condición previa es un objeto <code>ErrorCode</code> válido; no se produce un retorno normal.</li>
</ul>
