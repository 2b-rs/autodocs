Contexto

La estructura de datos ara::diag::HttpRedirect forma parte del clúster funcional de Diagnostics (diag) de AUTOSAR Adaptive Platform y se proporciona a través del encabezado ara/diag/sovd_http_redirect.h (AUTOSAR_AP_SWS_Diagnostics §8.55.1 «Struct: HttpRedirect»). Según [SWS_DM_01828], este tipo sirve para representar una redirección HTTP (HTTP-Redirect) en el marco de SOVD (Service-Oriented Vehicle Diagnostics).

La responsabilidad principal de HttpRedirect consiste en comunicar de forma transparente los cambios de dirección de los recursos de diagnóstico: si un recurso SOVD se ha movido dentro del vehículo o está disponible temporal o permanentemente bajo otro identificador de recursos uniforme (URI), el servidor SOVD utiliza esta estructura para indicar al cliente SOVD solicitante la nueva ubicación del recurso SOVD redirigido. La estructura de datos actúa en este caso como nexo entre la gestión interna de recursos del servidor de diagnóstico y la pila de protocolos de red, que traduce la información de redirección en respuestas HTTP estándar (por ejemplo, códigos de estado de la serie 3xx). Entre los interlocutores centrales se encuentran el cliente SOVD, el servidor SOVD y el recurso SOVD direccionado a través del URI de destino.

Diagrama de contexto: integración de HttpRedirect en la interacción entre el cliente SOVD y el servidor SOVD. Fuentes: [SWS_DM_01828], AUTOSAR_AP_SWS_Diagnostics §8.55.1 «Struct: HttpRedirect».

Ciclo de vida

Como estructura de C++ (struct) sin jerarquía de herencia ni métodos virtuales, ara::diag::HttpRedirect está especificada como un contenedor de datos puro (Value Object) (AUTOSAR_AP_SWS_Diagnostics §8.55.1 «Struct: HttpRedirect»). La vida útil de una instancia suele ser efímera y está directamente vinculada al procesamiento de una solicitud de diagnóstico individual.

Interpretación: dado que HttpRedirect está definida como una estructura de datos simple sin lógica de control definida por el usuario, la gestión del ciclo de vida se realiza según la semántica de valores clásica de C++, y las instancias se crean típicamente asignadas en la pila en el contexto de procesamiento de una solicitud entrante y se liberan automáticamente al salir del ámbito de validez. El servidor SOVD crea la instancia de forma situacional en el momento en que la ruta de la solicitud remite a un recurso reubicado.

La estructura posee exactamente un dato con la variable pública url de tipo ara::core::String ([SWS_DM_01829], AUTOSAR_AP_SWS_Diagnostics §8.55.1.1.1 «url»). No existen transiciones de estado internas ni estados del ciclo de vida; la validez del objeto viene determinada completamente por el valor de este campo de datos. Interpretación: ara::diag::HttpRedirect no ofrece sincronización interna ni seguridad frente a subprocesos; el acceso concurrente a la misma instancia desde varios subprocesos sin mecanismos de sincronización externos podría dar lugar a condiciones de carrera. No obstante, dado que las solicitudes en el servidor SOVD se procesan por regla general de forma aislada en subprocesos o tareas independientes por cada sesión de cliente, basta con utilizar instancias locales y seguras en subprocesos.

Ruta de uso

La secuencia típica en el uso de ara::diag::HttpRedirect abarca desde la detección de una reubicación de recursos hasta la redirección del cliente:

  1. Solicitud de recurso: un cliente SOVD externo o interno del vehículo envía una solicitud de diagnóstico a un extremo URI del servidor SOVD.
  2. Resolución de recursos: el servidor SOVD comprueba la ruta solicitada y constata que el recurso SOVD en cuestión se ha movido a otra ubicación o se proporciona bajo un URI diferente.
  3. Instanciación y asignación: el servidor SOVD instancia ara::diag::HttpRedirect y asigna a la variable miembro url el nuevo URI de destino ([SWS_DM_01829]).
  4. Respuesta al cliente: a partir de la información encapsulada en HttpRedirect, el servidor genera una respuesta de redirección HTTP y transmite la nueva ubicación del recurso al cliente SOVD ([SWS_DM_01828]).
  5. Redireccionamiento: el cliente SOVD evalúa la redirección y dirige su solicitud posterior a la nueva URL de destino.

Diagrama de secuencia: secuencia de una redirección de recursos SOVD a través de HttpRedirect. Fuentes: [SWS_DM_01828], [SWS_DM_01829], AUTOSAR_AP_SWS_Diagnostics §8.55.1 «Struct: HttpRedirect», AUTOSAR_AP_SWS_Diagnostics §8.55.1.1.1 «url».

Escenarios de error

Al utilizar ara::diag::HttpRedirect pueden presentarse diversas situaciones de error en la integración práctica:

  • Dirección de destino no válida: el miembro url requiere un URI de destino bien definido ([SWS_DM_01829]). Interpretación: la validación sintáctica y semántica de la dirección de destino en url corresponde a la lógica del servidor llamador, ya que la propia estructura de datos no proporciona métodos de verificación ni códigos de error. Si se establece una cadena de URI vacía o errónea, la redirección en el lado del cliente fallará.
  • Redirecciones circulares: si la URL transferida remite erróneamente a la dirección de origen solicitada o forma una cadena cerrada de redirecciones, los clientes sin detección de bucles entrarán en una redirección infinita.
  • Recursos de destino no alcanzables: si el URI de destino referenciado es formalmente correcto, pero el extremo de destino está inactivo o no existe, el cliente responderá a la llamada posterior con un error de conexión o un error 404. Por lo tanto, el servidor solo debe dotar a HttpRedirect de rutas válidas y accesibles.

Esta guía se basa en las especificaciones de AUTOSAR Adaptive Platform Release R25-11 para el módulo Diag.
