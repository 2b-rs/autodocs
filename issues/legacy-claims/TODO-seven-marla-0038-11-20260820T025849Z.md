## Design summary

`quarantine_artifact()` is the sanctioned way for a partial/failed/interrupted
artifact — including a fixed-path export that would otherwise be overwritten
in place — to become GC-eligible at all: it moves the artifact into
`output/logs/<task-id>/<request-id>/.partial/` and writes an
`artifact-quarantine@v1` side-car (state, error, source/output digest,
retry-eligible). GC (`plan_gc`/`gc`) walks `output/logs/<task-id>/**`,
classifying each attempt directory via the immutable `result.json`/
`transaction-journal.json` contract from Task `0038-10`
(`_src/tools/runner_transaction.py`, read-only inspection, not modified) into
tiers `successful-log`/`failed-trace`/`cache`/`scratch`, refuses anything with
a journal but no terminal `result.json` ("unfinalized-journal"), refuses any
non-empty file it does not recognize ("unknown-state" — this is what protects
a reused free-text `run-current.log`), prunes only genuinely empty
tombstones, guards against clock skew by never treating a future-dated
`finished_at` as old, never deletes whatever `current.json` currently points
at, and cross-checks every candidate against `items[].path` entries of any
`task-evidence-pack@v1` manifest (Task `0038-12`, `_src/tools/task_evidence_pack.py`,
read-only inspection) found under the scanned roots before allowing deletion
("permanent-manifest" tier). Real deletion requires an explicit `--apply`;
the default is always dry-run.
