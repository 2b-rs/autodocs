## 1. Objective & Scope

Task `0033-07.01` resolves baseline audit finding **`RRB-AUTH-001`** by implementing strict, authenticated, role-enforced queue and lifecycle transitions across all curation and review request workflows:
- **Principal & Session Binding**: Every privileged transition requires a cryptographically valid `AuthContext` (principal ID, role, session ID, timestamp).
- **Proposer / Decider Separation (4-Eyes Principle)**: Proposing roles (`ai_agent`, `requester`) are strictly prohibited from performing `accept`, `reject`, `apply`, or `close` actions.
- **Human Curation Authority**: Decisions (`accept` / `reject`) require authorized `curator` or `operator` credentials.
- **Factual Application Gate**: Items can only transition to `applied` by an `operator` after explicit human `accepted` status.
- **Rejection Terminality**: A `rejected` item cannot transition to `applied` or be normalized as an accepted change.
- **Concurrency & Anti-Staleness**: Validates `expected_version` at transition time to reject concurrent/stale modifications.

---

## 2. Implementation Summary

1. **`authenticated_lifecycle.py` Core Engine**:
   - `create_session(principal_id, role)`: Mints authenticated session context.
   - `validate_transition(item, action, auth, expected_version)`: Validates permissions, checks current state against allowed predecessors, enforces terminal boundaries, updates lifecycle fields, and appends a tamper-evident audit record to `history`.

2. **Role & Permission Topology (`ROLE_PERMISSIONS`)**:
   - `requester`: `submit` (`discovered` -> `queued`).
   - `ai_agent`: `claim` (`queued` -> `claimed`), `release` (`claimed` -> `queued`), `propose` (`claimed` -> `proposed`).
   - `curator`: `claim`, `release`, `accept` (`proposed`/`claimed` -> `accepted`), `reject` (`proposed`/`claimed`/`queued` -> `rejected`).
   - `operator`: `claim`, `release`, `accept`, `reject`, `apply` (`accepted` -> `applied`), `close` (`applied`/`rejected` -> `closed`).
   - `service`: `submit`, `publish` (`applied` -> `published`).

3. **Audit Trail & Provenance**:
   - Every transition appends `action`, `from_state`, `to_state`, `principal_id`, `role`, `session_id`, and ISO-8601 UTC `timestamp` to `item["history"]`.
