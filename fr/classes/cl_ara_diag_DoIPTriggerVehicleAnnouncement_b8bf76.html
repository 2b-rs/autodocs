Sert au déclenchement ciblé des annonces de véhicule DoIP sur une interface réseau spécifiée.

La classe [SWS_DM_00820] sert aux Adaptive Applications à déclencher explicitement auprès du Diagnostic Management l'envoi d'annonces de véhicule DoIP conformément à l'ISO 13400-2 sur une interface réseau donnée. L'accès ne s'effectue pas via une propre instanciation, mais de manière statique via une référence d'objet fournie par le système ([SWS_DM_00821]). Pour les interfaces dotées d'une commande dépendante d'une ligne d'activation, l'appel explicite n'est pas autorisé, car l'envoi s'y déroule de manière entièrement automatique ([SWS_DM_00822]).

Contexte

La classe ara::diag::DoIPTriggerVehicleAnnouncement ([SWS_DM_00820]) fournit dans l'en-tête ara/diag/doip_trigger_vehicle_announcement.h (AUTOSAR_AP_SWS_Diagnostics §8.36.1 « Class: DoIPTriggerVehicleAnnouncement ») une API permettant à une Adaptive Application de déclencher l'émission ciblée d'annonces de véhicule DoIP (« Vehicle Announcement Messages ») ([SWS_DM_00815], [SWS_DM_00822]).

Dans la communication DoIP selon l'ISO 13400-2, l'envoi d'annonces de véhicule est principalement une tâche interne du Diagnostic Management (DM) (AUTOSAR_AP_SWS_Diagnostics §« About DiagnosticDoIPTriggerVehicleAnnouncementInterface »). Par défaut, le DM envoie ces messages sous forme de broadcast à d'autres calculateurs IP et passerelles lors du démarrage du réseau, ainsi que lors de la détection de la connexion d'un testeur de diagnostic externe (AUTOSAR_AP_SWS_Diagnostics §« About DiagnosticDoIPTriggerVehicleAnnouncementInterface »). Via ara::diag::DoIPTriggerVehicleAnnouncement, la possibilité est néanmoins offerte aux applications de déclencher explicitement cet envoi pour une interface réseau spécifique ([SWS_DM_00815], [SWS_DM_00820]).

Diagramme de contexte : partenaires d'interaction lors du déclenchement d'annonces de véhicule DoIP via le Diagnostic Manager. Sources : [SWS_DM_00815], [SWS_DM_00820], AUTOSAR_AP_SWS_Diagnostics §« About DiagnosticDoIPTriggerVehicleAnnouncementInterface ».

Cycle de vie

La création et la destruction d'instances de la classe DoIPTriggerVehicleAnnouncement sont soumises à des exigences strictes : le constructeur par défaut ([SWS_DM_02100]) ainsi que le destructeur ([SWS_DM_02101]) sont déclarés comme delete, privés et spécifiques au constructeur dans leur forme concrète. Les applications ne peuvent donc ni instancier ni détruire directement des objets de cette classe.

L'accès à l'interface s'effectue de manière statique via la fonction GetDoIPTriggerVehicleAnnouncement() ([SWS_DM_00821]). Celle-ci renvoie un ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>, grâce auquel l'appelant obtient une référence vers l'objet de service fourni par le DM. Interprétation : en raison des constructeurs privés et supprimés et du renvoi d'une référence d'objet, la classe devrait être gérée en interne par le DM en tant que singleton à longue durée de vie.

En ce qui concerne la concurrence, ni l'interrogation d'interface GetDoIPTriggerVehicleAnnouncement() ni l'appel de méthode TriggerVehicleAnnouncement() ne sont spécifiés comme étant thread-safe (« not thread-safe ») ([SWS_DM_00821], [SWS_DM_00822]). Un accès simultané depuis plusieurs threads nécessite donc une synchronisation externe. Les deux méthodes sont spécifiées comme étant sûres vis-à-vis des exceptions (« exception safe ») ([SWS_DM_00821], [SWS_DM_00822]).

Parcours d'utilisation

Le déroulement type pour demander une annonce de véhicule DoIP se divise en plusieurs étapes :

  1. Récupérer l'instance : l'application appelle statiquement ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() ([SWS_DM_00821]).
  2. Évaluer le résultat : le ara::core::Result résultant est vérifié pour détecter d'éventuelles erreurs ; en cas de succès, la référence est dépaquetée.
  3. Demander l'annonce : via la méthode TriggerVehicleAnnouncement(networkInterfaceId), l'envoi est initié sur l'interface réseau souhaitée ([SWS_DM_00822]).
  4. Envoi du message par le DM : le DM traite la demande et envoie des messages d'annonce de véhicule conformément à l'ISO 13400-2 sur l'interface identifiée par networkInterfaceId ([SWS_DM_00815]).

Diagramme de séquence : ordre d'appel pour le déclenchement d'annonces de véhicule DoIP. Sources : [SWS_DM_00815], [SWS_DM_00821], [SWS_DM_00822].

Scénarios d'erreur

Un scénario d'erreur central lors de l'utilisation de TriggerVehicleAnnouncement concerne les interfaces réseau dépendantes d'une ligne d'activation : si la networkInterfaceId transmise appartient à une configuration d'interface (DoIPNetworkConfiguration) pour laquelle la propriété isActivationLineDependent = TRUE est définie, l'appel entraîne une erreur ([SWS_DM_00822]). Sur de telles interfaces, l'envoi de messages d'annonce est déjà déclenché automatiquement par le DM dès que la ligne d'activation est active et qu'une adresse IP a été attribuée ([SWS_DM_00816], [SWS_DM_00822]).

Aucun code d'erreur standardisé n'est spécifié pour les fonctions GetDoIPTriggerVehicleAnnouncement() et TriggerVehicleAnnouncement() ([SWS_DM_00821], [SWS_DM_00822]). Les éventuelles erreurs d'exécution ou états d'erreur spécifiques au constructeur sont véhiculés dans le ara::core::Result renvoyé et doivent être vérifiés par l'application appelante.

          Utilisation et sémantique
          

          La fonction prend en paramètre networkInterfaceId (std::uint8_t), qui identifie l'interface réseau cible, et renvoie un ara::core::Result<void> [SWS_DM_00822]. Elle est déclarée comme noexcept et ne lève aucune exception [SWS_DM_00822].

          Aucun code d'erreur standardisé n'est défini pour cette méthode [SWS_DM_00822]. Un cas d'erreur survient lorsque la networkInterfaceId transmise appartient à une configuration réseau présentant la propriété isActivationLineDependent = TRUE [SWS_DM_00822]. Interprétation : comme aucun code d'erreur standardisé n'existe, l'erreur devrait être signalée par un code d'erreur propre au fabricant dans l'objet Result.
          

          Concurrence et interaction
          

          L'opération est spécifiée comme non sûre vis-à-vis des threads (not thread-safe) [SWS_DM_00822]. De plus, la spécification note que l'annonce constitue principalement une fonctionnalité interne au DM et qu'un déclenchement explicite par une Adaptive Application n'est conceptuellement pas prévu AUTOSAR_AP_SWS_Diagnostics §7.x « About DiagnosticDoIPTriggerVehicleAnnouncementInterface ».
