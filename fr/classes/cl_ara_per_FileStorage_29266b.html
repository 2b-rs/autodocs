Rôle dans le modèle mémoire

FileStorage représente un ensemble configuré de fichiers nommés, semblable à un répertoire. Les fichiers peuvent être préinstallés, créés lors d'une mise à jour ou créés et supprimés au moment de l'exécution. SWS Persistency §7.4 « File Storage specific Features »

Du Storage au fichier

Après OpenFileStorage, FileExists et GetAllFileNames vérifient l’existence. OpenFileReadOnly, OpenFileWriteOnly et OpenFileReadWrite créent l’accesseur exclusif approprié ; le traitement du contenu relève ensuite de ReadAccessor, WriteAccessor ou ReadWriteAccessor.

Écrire, verrouiller et réinitialiser

Un accesseur ouvert lie le fichier exclusivement. Ne prévoyez donc pas DeleteFile, ResetFile et RecoverFile en parallèle avec un accès actif. Les limites de ressources ainsi que les données redondantes et de sauvegarde sont prises en compte dans l'espace de stockage utilisé. SWS Persistency §7.2.6 « Resource Management Concepts »

Stratégie d'échec

Vérifiez chaque Result, en particulier les droits d'accès, le stockage physique, l'intégrité, le cryptage, l'authentification, l'espace disque et les conflits de ressources. Une restauration ne remplace pas un contrôle de cohérence technique. SWS Persistency §7.2.4 « Redundancy Concepts »

Un File Storage gère un ensemble de fichiers nommés ; l’Accessor détient exclusivement l’accès concret ouvert. Sources : SWS Persistency §7.4 « File Storage specific Features » [SWS_PER_00113].

La récupération est le meilleur effort possible ; en cas d'erreur, un rapport peut nommer le stockage ou les éléments concernés. Source : SWS Persistency §7.2.4 « Redundancy Concepts ». Interprétation partielle : la séquence d'activités combine plusieurs procédures de redondance autorisées.
