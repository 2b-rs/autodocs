Contexte

La structure ara::rds::ReadDataResult sert, dans le module rds (Raw Data Stream) de l'AUTOSAR Adaptive Platform, d'objet de résultat et de transfert de données pour les opérations de lecture. Sa responsabilité centrale consiste à transmettre à l'appelant le tampon de données renvoyé lors d'une opération de lecture, groupé et avec sûreté de typage, accompagné du nombre d'octets réellement transférés. La structure est définie dans le fichier d'en-tête ara/rds/raw_data_stream.h [SWS_RDS_11301].

Les principaux partenaires d'interaction sont l'infrastructure de streaming du module rds, qui fournit des données via des opérations de lecture et instancie ara::rds::ReadDataResult, ainsi que l'application Adaptive consommatrice, qui réceptionne le résultat de lecture et le traite ultérieurement.

Cycle de vie

Le cycle de vie de ara::rds::ReadDataResult est directement lié à l'exécution d'une opération de lecture. L'instanciation s'effectue en tant que valeur de retour d'une opération de lecture sur un flux de données brutes. Les relations de propriété de la mémoire sous-jacente sont régies par le champ data, qui est déclaré comme std::unique_ptr<ara::core::Byte[]> [SWS_RDS_11301]. Selon l'interprétation courante, ce type de pointeur intelligent impose une sémantique move-only pour ara::rds::ReadDataResult ; la structure peut par conséquent être déplacée, mais non copiée, ce qui transfère la propriété exclusive du tampon alloué dynamiquement à l'appelant.

La destruction suit le modèle RAII (Resource Acquisition Is Initialization). Dès qu'une instance de ara::rds::ReadDataResult quitte sa portée, le tampon d'octets alloué est automatiquement désalloué par le destructeur de std::unique_ptr, à moins que la propriété n'ait été préalablement transférée via std::move à un autre destinataire de tampon. En ce qui concerne la concurrence, la structure ne possède aucun mécanisme de synchronisation interne, s'agissant d'un pur conteneur de données. En cas d'accès depuis plusieurs threads, la synchronisation doit être assurée de manière externe par le logiciel applicatif.

Parcours d'utilisation

Un chemin d'utilisation typique pour la réception et le traitement de données brutes comprend les étapes suivantes :

  1. Initier l'opération de lecture : l'application Adaptive appelle une opération de lecture sur une instance de l'interface de flux conformément à ara/rds/raw_data_stream.h [SWS_RDS_11301].
  2. Recevoir l'objet de résultat : en cas de réussite de l'opération, le résultat est renvoyé à l'appelant sous la forme d'une instance ara::rds::ReadDataResult par sémantique de déplacement (move).
  3. Vérifier la longueur et le pointeur : l'application lit le champ numberOfBytes [SWS_RDS_11302] afin de déterminer le nombre d'octets valides dans le tampon de données data [SWS_RDS_11301].
  4. Traiter les données brutes : les données brutes contenues dans le tampon data sont évaluées jusqu'à la limite numberOfBytes, par exemple transmises à un analyseur de protocole ou converties dans des structures de données propres à l'application.
  5. Transmettre ou libérer la mémoire : si des étapes de traitement en aval ont besoin durablement du tampon, data peut être extrait par std::move ; sinon, le tampon est automatiquement libéré à la fin de la portée.

Scénarios d'erreur

Lors de la manipulation de ara::rds::ReadDataResult, il convient de respecter les préconditions, postconditions ainsi que les situations d'exception suivantes :

  • Résultats de lecture vides : si numberOfBytes a la valeur 0 [SWS_RDS_11302], aucun octet n'a été reçu pendant l'opération (par exemple lorsque la fin du flux est atteinte ou lors d'appels de lecture non bloquants sans données en attente). Dans cet état, selon une interprétation plausible, data devrait soit être présent sous forme de nullptr, soit pointer vers un tampon sans charge utile exploitable.
  • Dépassement de tampon lors de l'accès : étant donné que data est typé comme pointeur de tableau au sein de std::unique_ptr [SWS_RDS_11301], aucun contrôle automatique de limites n'existe. Un accès au-delà de la valeur d'indice numberOfBytes [SWS_RDS_11302] entraîne un comportement indéfini (buffer overflow).
  • Accès après opération Move : si le champ data a été extrait au moyen de std::move, le pointeur reste dans l'état nullptr. Les déréférencements ultérieurs de data sans vérification préalable de nullité entraînent des erreurs d'exécution.

Ce guide de classe est basé sur la spécification de l'AUTOSAR Adaptive Platform R25-11 (module rds). Toutes les définitions s'appuient exclusivement sur les exigences indiquées.
