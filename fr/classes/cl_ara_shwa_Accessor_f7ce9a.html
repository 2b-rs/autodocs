Contexte

Dans le module shwa, la classe template ara::shwa::Accessor sert d'intermédiaire d'accès typé et dimensionnel aux zones de mémoire fournies par ara::shwa::Buffer. Par ses paramètres template, elle configure le type de données (DataT), la dimensionnalité (Dimensions), le mode d'accès (AccessModeType, mode lecture par défaut) ainsi que la zone de mémoire et l'allocateur. Elle encapsule les ressources de tampon physiques ou virtuelles et fournit des interfaces de lecture et d'écriture contrôlées.

Ce faisant, Accessor interagit généralement avec les partenaires suivants :

  • Application : crée l'Accessor, gère sa propriété exclusive et initie les accès aux données ou les interrogations de propriétés.
  • ara::shwa::Buffer : sert de fondement de mémoire sur l'intégrité duquel repose l'Accessor ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • TaskHandler : peut éventuellement être intégré lors de l'instanciation afin de synchroniser des tâches d'exécution ou de traitement liées à l'accès mémoire ([AP_SWS_SHWA_00008]).

Diagramme de contexte : relations entre les composants d'ara::shwa::Accessor et l'application, le tampon et TaskHandler. Sources : [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]

Cycle de vie

La durée de vie et l'instanciation de ara::shwa::Accessor suivent un contrôle strict des ressources et de la propriété :

  • Création : le constructeur par défaut est supprimé ([AP_SWS_SHWA_00002]). Les instances peuvent exclusivement être instanciées via les méthodes de fabrique statiques Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Celles-ci valident la référence de tampon transmise ainsi que les propriétés facultatives (PropertyList) et renvoient un ara::core::Result<std::unique_ptr<Accessor>> en cas de succès.
  • Propriété et destruction : grâce au type de retour std::unique_ptr, la propriété est liée de manière univoque et exclusive à l'appelant. La classe interdit totalement la copie et le déplacement : le constructeur de copie ([AP_SWS_SHWA_00003]) et l'opérateur d'assignation par copie ([AP_SWS_SHWA_00004]) ainsi que le constructeur de déplacement ([AP_SWS_SHWA_00005]) et l'opérateur d'assignation par déplacement ([AP_SWS_SHWA_00006]) sont tous déclarés comme supprimés (delete). La suppression des opérations de déplacement vise probablement à garantir qu'un Accessor reste fermement lié à son emplacement d'origine et au tampon initial pendant toute son existence. La destruction a lieu automatiquement lors de la libération du std::unique_ptr.
  • Concurrence : les méthodes de création Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) ainsi que les méthodes d'accès synchrones Get ([AP_SWS_SHWA_00012]) et Set ([AP_SWS_SHWA_00011]) sont explicitement spécifiées comme étant thread-safe. En revanche, les opérateurs d'indexation operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) et les méthodes de propriété HasProperty ([AP_SWS_SHWA_00015]) et GetProperty ([AP_SWS_SHWA_00016]) ne sont pas thread-safe et nécessitent une synchronisation externe en cas d'utilisation concurrente.

Parcours d'utilisation

Un déroulement normal lors de l'utilisation d'un Accessor comprend généralement les phases suivantes :

  1. Appel de fabrique : l'application appelle Create avec une référence vers un Buffer existant et des configurations facultatives ou un TaskHandler ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]). Le résultat est vérifié pour s'assurer du succès et le std::unique_ptr contenu est récupéré.
  2. Interrogation des propriétés : de manière optionnelle, l'application vérifie la présence de certaines capacités via HasProperty<PropertyT>() ([AP_SWS_SHWA_00015]) et les lit au moyen de GetProperty<PropertyT>() ([AP_SWS_SHWA_00016]).
  3. Accès en écriture : si le AccessModeType le prévoit, les données sont écrites dans le tampon via Set avec indication d'un index dimensionnel Id<Dimensions> ([AP_SWS_SHWA_00011]).
  4. Accès en lecture : Les données sont obtenues de manière thread-safe via Get ([AP_SWS_SHWA_00012]). Pour les accès directs par référence sans sécurité de thread, operator[] peut être utilisé en alternative avec un Index-ID ou un index continu ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]), qui fournit une référence typée ReferenceT ([AP_SWS_SHWA_00014]).
  5. Libération : lors de la sortie de la portée, l'appelant détruit le std::unique_ptr, ce qui met fin à l'accès.

Diagramme de séquence : séquence d'appels typique pour la création, la configuration et l'utilisation d'un ara::shwa::Accessor. Sources : [AP_SWS_SHWA_00007], [AP_SWS_SHWA_00011], [AP_SWS_SHWA_00012], [AP_SWS_SHWA_00015], [AP_SWS_SHWA_00016]

Scénarios d'erreur

Les méthodes de Accessor transmettent les états d'erreur via le type ShwaErrorCode dans la valeur de retour ara::core::Result :

  • ShwaErrorCode::kAccessorFailure : survient lors de Create lorsque la construction ou l'utilisation de l'Accessor n'est pas valide ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]).
  • ShwaErrorCode::kIntegrityCorrupted : est signalé par Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) et Set ([AP_SWS_SHWA_00011]) si l'intégrité structurelle de la mémoire allouée par le tampon est compromise ou non vérifiable.
  • ShwaErrorCode::kInvalidIndex : survient lors de Get ([AP_SWS_SHWA_00012]) et Set ([AP_SWS_SHWA_00011]) lorsque l'opération ne peut pas être exécutée en raison d'un index non valide ou d'une valeur initiale manquante.
  • ShwaErrorCode::kInvalidAccessMode : signale pour Set ([AP_SWS_SHWA_00011]) que le mode d'accès configuré n'autorise aucune opération d'écriture.
  • ShwaErrorCode::kResourceBusy : est renvoyé lors de Get ([AP_SWS_SHWA_00012]) et Set ([AP_SWS_SHWA_00011]) lorsque la ressource est temporairement occupée.
  • ShwaErrorCode::kFeatureNotSupported : survient lors de GetProperty lorsque la propriété demandée n'est pas implémentée ou prise en charge ([AP_SWS_SHWA_00016]).

Concernant la sécurité vis-à-vis des exceptions, Create ([AP_SWS_SHWA_00007], [AP_SWS_SHWA_00008]) ainsi que HasProperty ([AP_SWS_SHWA_00015]) et GetProperty ([AP_SWS_SHWA_00016]) sont déclarés comme sûrs vis-à-vis des exceptions (noexcept), tandis que les opérations d'accès aux données Get ([AP_SWS_SHWA_00012]), Set ([AP_SWS_SHWA_00011]) et operator[] ([AP_SWS_SHWA_00009], [AP_SWS_SHWA_00010]) sont répertoriées comme non sûres vis-à-vis des exceptions.
