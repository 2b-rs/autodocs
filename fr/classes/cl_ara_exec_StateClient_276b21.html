classe ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Demande auprès de l'Execution Management des changements d'état pour des groupes de fonctions, afin de piloter des processus sur une Machine.

L'interface ara::exec::StateClient permet au State Management de demander des changements d'état pour des groupes de fonctions auprès de l'Execution Management, afin de piloter l'exécution de processus assignés sur une Machine [SWS_EM_02278]. Lors de la création via Create(), un callback continuellement valide doit être enregistré pour les états indéfinis inattendus [SWS_EM_02276]. Outre des transitions d'état asynchrones, cette classe non copiable fournit des méthodes d'interrogation du résultat du démarrage de la Machine ainsi que d'analyse d'erreur lors d'erreurs d'exécution [SWS_EM_02279], [SWS_EM_02542].

Contexte

La classe ara::exec::StateClient constitue l'interface de l'Execution Management par laquelle le State Management demande et pilote les transitions d'état pour des groupes de fonctions (Function Groups). Le State Management utilise ce client pendant toute la durée de fonctionnement d'une Machine afin de démarrer ou d'arrêter des processus de manière ciblée. L'intégrateur affecte des composants logiciels à certains états d'un groupe de fonctions. Si le State Management souhaite exécuter ces logiciels, il demande via le StateClient auprès de l'Execution Management le passage à l'état de groupe de fonctions concerné ; l'arrêt s'effectue de manière analogue par une transition vers un état dans lequel le logiciel ne doit pas être actif [SWS_EM_02278].

Diagramme de contexte : interaction entre State Management, StateClient et Execution Management. Sources : [SWS_EM_02276], [SWS_EM_02278]

Cycle de vie

Les instances de StateClient peuvent être créées soit via le constructeur nommé Create() [SWS_EM_02276] sous la forme d'un ara::core::Result<StateClient>, soit via le constructeur régulier StateClient() [SWS_EM_02561]. Ces deux voies de construction exigent impérativement un paramètre de callback undefinedStateCallback de type std::function<void(const ara::exec::ExecutionErrorEvent&)>. Ce callback est déclenché par la bibliothèque StateClient lorsqu'un groupe de fonctions passe de manière inattendue et sans demande préalable par SetState() dans un état indéfini. L'appelant doit s'assurer que ce callback reste appelable pendant toute la durée de vie de l'instance StateClient, ce qui est particulièrement pertinent lors de liaisons d'objets via std::bind [SWS_EM_02276], [SWS_EM_02561].

Les opérations de copie sont explicitement interdites pour StateClient : le constructeur de copie [SWS_EM_02565] ainsi que l'opérateur d'affectation par copie [SWS_EM_02568] sont tous deux supprimés (=delete). Un transfert de propriété est exclusivement possible par sémantique de déplacement via le constructeur de déplacement [SWS_EM_02566] et l'affectation par déplacement [SWS_EM_02567]. En matière de concurrence, les méthodes fonctionnelles telles que SetState(), GetExecutionError() et GetInitialMachineStateTransitionResult() ainsi que la création sont conçues pour être thread-safe [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]. En revanche, les opérations de déplacement et le destructeur ~StateClient() ne sont pas thread-safe [SWS_EM_02277], [SWS_EM_02566], [SWS_EM_02567].

Parcours d'utilisation

Un cycle d'utilisation typique se divise en initialisation, interrogation du résultat de démarrage, changements d'état réguliers et surveillance des erreurs :

  1. Création : le State Management instancie StateClient en spécifiant un callback de signalement d'erreurs valide via Create() [SWS_EM_02276].
  2. Interroger le résultat initial du démarrage : avec GetInitialMachineStateTransitionResult(), le State Management demande le résultat de la transition d'état initiale vers l'état de startup [SWS_EM_02279]. Cette transition ayant lieu exactement une fois par cycle de vie de la Machine, le ara::core::Future<void> renvoyé reste stable et ne change plus jusqu'à un redémarrage.
  3. Demander un changement d'état : au moyen de SetState(), State Management ordonne des transitions d'état asynchrones pour des groupes de fonctions individuels [SWS_EM_02278]. La méthode retourne immédiatement et fournit un ara::core::Future<void> pour interroger l'achèvement. Dès que la demande est parvenue à Execution Management, elle est exécutée indépendamment de la durée de vie ultérieure de l'instance appelante.
  4. Analyser les états d'erreur : si un groupe de fonctions passe de manière inattendue dans un état indéfini, l'erreur d'exécution déclenchante peut être déterminée sous la forme d'un ara::exec::ExecutionErrorEvent via GetExecutionError() [SWS_EM_02542].

Diagramme de séquence : déroulement de la création, de l'interrogation de l'état initial, du changement d'état asynchrone et de l'analyse des erreurs. Sources : [SWS_EM_02276], [SWS_EM_02279], [SWS_EM_02278], [SWS_EM_02542]

Scénarios d'erreur

Les opérations de la classe communiquent les échecs via des codes d'erreur de ExecErrorDomain :

  • ExecErrc::kNoCommunication : signale des perturbations de communication avec Execution Management, par exemple en cas de connexion IPC interrompue. Se produit lors de Create() [SWS_EM_02276], SetState() [SWS_EM_02278], GetInitialMachineStateTransitionResult() [SWS_EM_02279] ainsi que GetExecutionError() [SWS_EM_02542]. La récupération prévue consiste en un nouvel appel.
  • ExecErrc::kInvalidArgument : est signalé par Create() et StateClient() si le callback transmis ne contient aucune fonction appelable [SWS_EM_02276], [SWS_EM_02561].
  • ExecErrc::kOperationCanceled : indique pour SetState() qu'une transition en cours a été interrompue par une demande plus récente [SWS_EM_02278]. Pour GetInitialMachineStateTransitionResult(), cette erreur survient lorsque la transition de démarrage initiale a été interrompue, par exemple par une séquence de Machine-Update interrompue [SWS_EM_02279].
  • ExecErrc::kInvalidTransition : la transition d'état demandée n'est pas autorisée, par exemple la transition vers l'état Off pour MachineFG, ou bien l'état n'existe plus après une mise à jour [SWS_EM_02278].
  • ExecErrc::kInvalidMetaModelIdentifier : l'état transmis n'existe pas dans le manifeste traité ou le processus ne possède pas de mappage vers le groupe de fonctions concerné [SWS_EM_02278], [SWS_EM_02542]. Si cette erreur survient lors de GetInitialMachineStateTransitionResult(), il manque au processus le mappage vers MachineFG, ce qui indique un problème de configuration [SWS_EM_02279].
  • ExecErrc::kOperationFailed : la transition a échoué [SWS_EM_02278]. Pour GetExecutionError(), le code indique que le groupe de fonctions ne se trouve pas dans un état indéfini et que le problème a probablement déjà été résolu [SWS_EM_02542].
  • ExecErrc::kIntegrityOrAuthenticityCheckFailed et ExecErrc::kUnexpectedTermination : échecs spécifiques pendant SetState() à la suite de contrôles d'intégrité ayant échoué ou de terminaisons inattendues de processus pendant la transition [SWS_EM_02278].

La méthode fabrique statique Create sert de constructeur nommé (Named Constructor) pour créer une instance de ara::exec::StateClient ([SWS_EM_02276]). undefinedStateCallback est transmis en tant que paramètre obligatoire. Ce rappel est déclenché par la bibliothèque cliente lorsqu'un groupe de fonctions passe de manière inattendue – c'est-à-dire sans demande préalable via SetState() – dans un état indéfini ([SWS_EM_02276]). À cette occasion, le groupe de fonctions concerné et l'erreur sont transmis au rappel via un ExecutionErrorEvent.

Des conditions-cadres strictes s'appliquent au contexte d'appel et à la durée de vie :

  • La fonction est thread-safe, exception-safe et déclarée comme noexcept ([SWS_EM_02276]).
  • Le undefinedStateCallback transmis doit rester invocable pendant toute la durée de vie de l'instance de StateClient créée ([SWS_EM_02276]). Cela requiert un soin particulier lors de liaisons à des instances d'objets (par exemple au moyen de std::bind).

L'instanciation s'effectue de manière synchrone et renvoie un ara::core::Result<StateClient> ([SWS_EM_02276]). En cas d'erreur, les codes d'erreur suivants sont définis :

  • ara::exec::ExecErrc::kInvalidArgument : est signalé lorsque l'argument transmis ne contient aucune fonction invocable (sémantique de rollback ; résolution par la fourniture d'une fonction valide) ([SWS_EM_02276]).
  • ara::exec::ExecErrc::kNoCommunication : signale une erreur de communication (sémantique sans rollback ; résolution par une nouvelle tentative) ([SWS_EM_02276]). Cela devrait vraisemblablement être dû à un échec de l'établissement de la connexion vers l'environnement d'exécution.

Le patron de construction correspond structurellement à l'approche d'initialisation de clients d'exécution apparentés tels que ara::exec::ExecutionClient ([SWS_EM_02562]), qui est également créé avec un rappel obligatoire via un constructeur nommé.

              ara::core::Future< void > SetState (const FunctionGroupState &state) const noexcept;
              

              Method to request state transition for a single Function Group. This method will request Execution Management to perform state transition and return immediately. Returned ara::core::Future can be used to determine result of requested transition.

              La méthode SetState sert à demander la transition d’état pour un groupe de fonctions individuel auprès d’Execution Management [SWS_EM_02278]. L’appel s’effectue de manière asynchrone : la méthode déclenche le changement et retourne immédiatement avec un ara::core::Future<void> qui permet de déterminer le résultat de la transition [SWS_EM_02278]. Un FunctionGroupState est transmis en paramètre, qui identifie l’état cible au sein du groupe de fonctions conformément au métamodèle [SWS_EM_02278].
              
  
              En cas d’échec de la transition, le Future fournit une erreur issue de l’ErrorDomain Exec [SWS_EM_02278]. Une sémantique de rollback s’applique pour ara::exec::ExecErrc::kInvalidTransition (par exemple lors de transitions interdites comme l’état Off pour MachineFG) et pour ara::exec::ExecErrc::kInvalidMetaModelIdentifier (en cas de mappage manquant ou de définition manquante dans le manifeste) [SWS_EM_02278]. Sont signalés sans sémantique de rollback : kOperationCanceled (évincé par une requête plus récente), kOperationFailed, kNoCommunication (connexion IPC perturbée), kIntegrityOrAuthenticityCheckFailed ainsi que kUnexpectedTermination [SWS_EM_02278].
              
  
              La méthode est thread-safe et sûre vis-à-vis des exceptions (noexcept) [SWS_EM_02278]. Le ara::core::Future retourné dépend de la durée de vie de l’instance appelante ; en revanche, Execution Management traite la requête reçue indépendamment de la durée de vie de l’instance de StateClient [SWS_EM_02278].
              
  
              En interaction avec l’instanciation via Create [SWS_EM_02276] ou le constructeur [SWS_EM_02561], un undefinedStateCallback intercepte les changements d’état inattendus qui surviennent sans appel préalable à SetState. Le résultat de la transition initiale vers l’état de démarrage peut être interrogé séparément via GetInitialMachineStateTransitionResult [SWS_EM_02279].

              Code d'erreurDescription
              ara::exec::ExecErrc::kOperationCanceledno_rollback_semantics if transition to the requested Function Group state was cancelled by a newer request. Recovery: Try again (error is informative, does not indicate a problem)
              ara::exec::ExecErrc::kOperationFailedno_rollback_semantics if transition to the requested Function Group state failed. Recovery: Try transition to another state
              ara::exec::ExecErrc::kNoCommunicationno_rollback_semantics if StateClient can’t communicate with Execution Management (e.g. IPC link is down). Rovery: Try again
              ara::exec::ExecErrc::kInvalidTransitionrollback_semantics if transition to the requested state is prohibited (e.g. Off state for MachineFG) or the requested Function Group State is invalid (e.g. does not exist anymore after a software update). Recovery: Eventually try transition to another state
              ara::exec::ExecErrc::kIntegrityOrAuthenticityCheckFailedno_rollback_semantics if an integrity or authenticity check failed during state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kUnexpectedTerminationno_rollback_semantics One of the processes terminated in an unexpected way during the state transition. Recovery: transition to another state
              ara::exec::ExecErrc::kInvalidMetaModelIdentifierrollback_semantics The given Function Group State couldn’t be found in the Processed Manifest or Process does not have a mapping to the Function Group of the requested Function Group State. Recovery: transition to another state
              

              Hinweise: Asynchronous nature of ara::exec::StateClient::SetState makes the returned ara:: core::Future dependable on lifetime of the instance from which it was received. It is expected that once state change request is received by Execution Management, it will be processed independently of lifetime of the instance from which it was requested. Please note that the qualified short names representing Function Groups and Function Group States could be quite long. They can be replaced by implementation specific data types to speed up any checks that have to be performed by the ara::exec::StateClient:: SetState method. This is enabled by the ara::exec::FunctionGroupState data-type.
