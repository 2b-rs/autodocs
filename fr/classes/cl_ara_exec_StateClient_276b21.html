classe ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

Contexte

La classe ara::exec::StateClient fait office d'interface fonctionnelle d'Execution Management vis-à-vis de State Management. Dans l'ensemble du système, il incombe à State Management de commander le cycle de vie d'une machine et de démarrer ainsi que d'arrêter les composants logiciels selon les besoins. Cela s'effectue via des transitions d'état de groupes de fonctions configurés (Function Groups), auxquels des processus logiciels concrets ont été attribués par l'intégrateur.

State Management utilise ara::exec::StateClient pour demander des transitions d'état pour des groupes de fonctions individuels auprès d'Execution Management [SWS_EM_02278]. Execution Management exécute ces transitions en démarrant ou en arrêtant le logiciel attribué au groupe de fonctions, et renvoie le résultat de la transition à State Management. Pour l'établissement de la connexion avec Execution Management, un canal IPC spécifique à la plateforme (tel que des sockets de domaine Unix) devrait être utilisé en arrière-plan, étant donné que la spécification ne limite pas plus précisément la technologie IPC exacte.

Cycle de vie

Pour l'instanciation de ara::exec::StateClient, AUTOSAR fournit deux voies de construction :

  • Méthode fabrique nommée : la fonction statique Create renvoie un ara::core::Result<StateClient> et encapsule les erreurs potentielles lors de la création sur la base de codes d'erreur et de manière sûre vis-à-vis des exceptions ([SWS_EM_02276]).
  • Constructeur standard : le constructeur direct est déclaré comme noexcept(false) et signale les erreurs en cas de défaillance via des exceptions ([SWS_EM_02561]).

Les deux voies de création requièrent la transmission d'un callback undefinedStateCallback avec la signature std::function<void(const ara::exec::ExecutionErrorEvent&)>. Ce callback est appelé par la bibliothèque StateClient si un groupe de fonctions passe de manière inattendue et sans demande préalable via SetState dans un état indéfini (Undefined Function Group State) ([SWS_EM_02276], [SWS_EM_02561]). En ce qui concerne la durée de vie, il est impératif de s'assurer que ce callback reste invocable pendant toute la durée de vie de l'instance StateClient ; cela s'applique en particulier lors de la liaison de méthodes d'instance via std::bind ([SWS_EM_02276], [SWS_EM_02561]).

Les opérations de copie sont totalement interdites : le constructeur de copie ainsi que l'opérateur d'affectation sont explicitement supprimés (delete) ([SWS_EM_02565], [SWS_EM_02568]). En revanche, la classe prend en charge la sémantique de déplacement : le constructeur de déplacement et l'opérateur d'affectation par déplacement sont définis comme noexcept ([SWS_EM_02566], [SWS_EM_02567]). Le destructeur est déclaré comme noexcept ([SWS_EM_02277]). Dès qu'un changement d'état a été reçu par Execution Management, il est traité indépendamment de la durée de vie de l'instance StateClient ; le ara::core::Future fourni par SetState dépend toutefois de la durée de vie de l'instance ([SWS_EM_02278]).

En ce qui concerne la concurrence, les méthodes d'instance SetState, GetExecutionError et GetInitialMachineStateTransitionResult ainsi que Create et le constructeur standard sont spécifiés comme thread-safe ([SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542], [SWS_EM_02561]). En revanche, les opérations de déplacement et le destructeur ne sont pas thread-safe ([SWS_EM_02566], [SWS_EM_02567], [SWS_EM_02277]).

Parcours d'utilisation

Un déroulement typique d'utilisation par State Management se divise selon les étapes suivantes :

  1. Création du client : State Management instancie StateClient via Create en enregistrant le callback d'erreur ([SWS_EM_02276]).
  2. Synchroniser l'état de démarrage : au début du fonctionnement de la machine, le résultat de la transition initiale de la machine vers l'état Startup est interrogé via GetInitialMachineStateTransitionResult() ([SWS_EM_02279]). La méthode renvoie un ara::core::Future<void>. Comme cette transition n'a lieu qu'une seule fois par cycle de vie de la machine, le résultat reste inchangé pendant le reste du temps d'exécution ([SWS_EM_02279]).
  3. Demander un changement d'état : à l'exécution, State Management demande des transitions pour des groupes de fonctions individuels via SetState(state) ([SWS_EM_02278]). La méthode retourne immédiatement et fournit un ara::core::Future<void>, qui indique le succès de la transition ou fournit une erreur de ExecErrorDomain.
  4. Analyser les états d'erreur : si un groupe de fonctions passe de manière imprévue dans un état indéfini, le callback enregistré est déclenché. State Management peut récupérer le ExecutionErrorEvent déclencheur via GetExecutionError(functionGroupState) tant que le groupe de fonctions demeure encore dans cet état ([SWS_EM_02542]).

Diagramme de séquence : déroulement depuis la création jusqu'à l'achèvement de la transition en passant par la demande d'état asynchrone. Sources : [SWS_EM_02276], [SWS_EM_02278], [SWS_EM_02279]

Scénarios d'erreur

Les méthodes de ara::exec::StateClient utilisent des codes d'erreur issus du domaine d'erreur d'Execution Management (ara::exec::ExecErrc). Les scénarios d'erreur suivants sont pertinents :

  • Échec de communication (ExecErrc::kNoCommunication) : survient lorsque la connexion entre le client et Execution Management est perturbée ou interrompue. Cette erreur est spécifiée pour toutes les opérations ([SWS_EM_02276], [SWS_EM_02561], [SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]). Une répétition de l'appel est la mesure de récupération prévue.
  • Transmission non valide et conflits de métamodèle :
    • ExecErrc::kInvalidArgument signale lors de la création que le undefinedStateCallback transmis n'est pas invocable ([SWS_EM_02276], [SWS_EM_02561]).
    • ExecErrc::kInvalidMetaModelIdentifier indique que l'état cible n'existe pas dans le manifeste ou que le processus appelant ne possède pas de mappage vers le groupe de fonctions concerné ([SWS_EM_02278], [SWS_EM_02279], [SWS_EM_02542]).
  • Échec ou interruption de transitions d'état :
    • ExecErrc::kOperationCanceled informe qu'une transition a été supplantée par une demande plus récente ou interrompue par State Management ([SWS_EM_02278], [SWS_EM_02279]).
    • ExecErrc::kInvalidTransition est renvoyé lorsque la transition n'est pas autorisée (par ex. passage à l'état Off pour MachineFG) ou que l'état n'existe plus après une mise à jour logicielle ([SWS_EM_02278]).
    • ExecErrc::kIntegrityOrAuthenticityCheckFailed signale l'échec des vérifications d'authenticité ou d'intégrité pendant le changement d'état ([SWS_EM_02278]).
    • ExecErrc::kUnexpectedTermination se produit lorsqu'un processus impliqué s'est terminé de manière inattendue pendant la transition ([SWS_EM_02278]).
    • ExecErrc::kOperationFailed indique l'échec général d'une transition ([SWS_EM_02278], [SWS_EM_02279]). Lors de l'appel de GetExecutionError, cette erreur indique en revanche que le groupe de fonctions ne se trouve pas dans un état indéfini et que le problème a peut-être déjà été résolu ([SWS_EM_02542]).

Ce guide est basé sur la spécification d'Execution Management pour l'AUTOSAR Adaptive Platform dans la version R25-11.

<h4>Contexte</h4>
<p>La classe <code>ara::exec::StateClient</code> fait office d'interface fonctionnelle d'Execution Management vis-à-vis de State Management. Dans l'ensemble du système, il incombe à State Management de commander le cycle de vie d'une machine et de démarrer ainsi que d'arrêter les composants logiciels selon les besoins. Cela s'effectue via des transitions d'état de groupes de fonctions configurés (<em>Function Groups</em>), auxquels des processus logiciels concrets ont été attribués par l'intégrateur.</p>
<p>State Management utilise <code>ara::exec::StateClient</code> pour demander des transitions d'état pour des groupes de fonctions individuels auprès d'Execution Management <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Execution Management exécute ces transitions en démarrant ou en arrêtant le logiciel attribué au groupe de fonctions, et renvoie le résultat de la transition à State Management. Pour l'établissement de la connexion avec Execution Management, un canal IPC spécifique à la plateforme (tel que des sockets de domaine Unix) devrait être utilisé en arrière-plan, étant donné que la spécification ne limite pas plus précisément la technologie IPC exacte.</p>

<p>Pour l'instanciation de <code>ara::exec::StateClient</code>, AUTOSAR fournit deux voies de construction :</p>
<ul>
<li><strong>Méthode fabrique nommée :</strong> la fonction statique <code>Create</code> renvoie un <code>ara::core::Result&lt;StateClient&gt;</code> et encapsule les erreurs potentielles lors de la création sur la base de codes d'erreur et de manière sûre vis-à-vis des exceptions (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Constructeur standard :</strong> le constructeur direct est déclaré comme <code>noexcept(false)</code> et signale les erreurs en cas de défaillance via des exceptions (<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
</ul>
<p>Les deux voies de création requièrent la transmission d'un callback <code>undefinedStateCallback</code> avec la signature <code>std::function&lt;void(const ara::exec::ExecutionErrorEvent&amp;)&gt;</code>. Ce callback est appelé par la bibliothèque StateClient si un groupe de fonctions passe de manière inattendue et sans demande préalable via <code>SetState</code> dans un état indéfini (<em>Undefined Function Group State</em>) (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). En ce qui concerne la durée de vie, il est impératif de s'assurer que ce callback reste invocable pendant toute la durée de vie de l'instance <code>StateClient</code> ; cela s'applique en particulier lors de la liaison de méthodes d'instance via <code>std::bind</code> (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</p>
<p>Les opérations de copie sont totalement interdites : le constructeur de copie ainsi que l'opérateur d'affectation sont explicitement supprimés (<code>delete</code>) (<a class="spec-record-ref" data-req="SWS_EM_02565" href="../spec/record.html?id=SWS_EM_02565">[SWS_EM_02565]</a>, <a class="spec-record-ref" data-req="SWS_EM_02568" href="../spec/record.html?id=SWS_EM_02568">[SWS_EM_02568]</a>). En revanche, la classe prend en charge la sémantique de déplacement : le constructeur de déplacement et l'opérateur d'affectation par déplacement sont définis comme <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>). Le destructeur est déclaré comme <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>). Dès qu'un changement d'état a été reçu par Execution Management, il est traité indépendamment de la durée de vie de l'instance <code>StateClient</code> ; le <code>ara::core::Future</code> fourni par <code>SetState</code> dépend toutefois de la durée de vie de l'instance (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</p>
<p>En ce qui concerne la concurrence, les méthodes d'instance <code>SetState</code>, <code>GetExecutionError</code> et <code>GetInitialMachineStateTransitionResult</code> ainsi que <code>Create</code> et le constructeur standard sont spécifiés comme thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). En revanche, les opérations de déplacement et le destructeur ne sont pas thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>, <a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>).</p>

<h4>Parcours d'utilisation</h4>
<p>Un déroulement typique d'utilisation par State Management se divise selon les étapes suivantes :</p>
<ol>
<li><strong>Création du client :</strong> State Management instancie <code>StateClient</code> via <code>Create</code> en enregistrant le callback d'erreur (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Synchroniser l'état de démarrage :</strong> au début du fonctionnement de la machine, le résultat de la transition initiale de la machine vers l'état Startup est interrogé via <code>GetInitialMachineStateTransitionResult()</code> (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). La méthode renvoie un <code>ara::core::Future&lt;void&gt;</code>. Comme cette transition n'a lieu qu'une seule fois par cycle de vie de la machine, le résultat reste inchangé pendant le reste du temps d'exécution (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><strong>Demander un changement d'état :</strong> à l'exécution, State Management demande des transitions pour des groupes de fonctions individuels via <code>SetState(state)</code> (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>). La méthode retourne immédiatement et fournit un <code>ara::core::Future&lt;void&gt;</code>, qui indique le succès de la transition ou fournit une erreur de <code>ExecErrorDomain</code>.</li>
<li><strong>Analyser les états d'erreur :</strong> si un groupe de fonctions passe de manière imprévue dans un état indéfini, le callback enregistré est déclenché. State Management peut récupérer le <code>ExecutionErrorEvent</code> déclencheur via <code>GetExecutionError(functionGroupState)</code> tant que le groupe de fonctions demeure encore dans cet état (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ol>

<h4>Scénarios d'erreur</h4>
<p>Les méthodes de <code>ara::exec::StateClient</code> utilisent des codes d'erreur issus du domaine d'erreur d'Execution Management (<code>ara::exec::ExecErrc</code>). Les scénarios d'erreur suivants sont pertinents :</p>
<ul>
<li><strong>Échec de communication (<code>ExecErrc::kNoCommunication</code>) :</strong> survient lorsque la connexion entre le client et Execution Management est perturbée ou interrompue. Cette erreur est spécifiée pour toutes les opérations (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>). Une répétition de l'appel est la mesure de récupération prévue.</li>
<li><strong>Transmission non valide et conflits de métamodèle :</strong>
<ul>
<li><code>ExecErrc::kInvalidArgument</code> signale lors de la création que le <code>undefinedStateCallback</code> transmis n'est pas invocable (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code> indique que l'état cible n'existe pas dans le manifeste ou que le processus appelant ne possède pas de mappage vers le groupe de fonctions concerné (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
<li><strong>Échec ou interruption de transitions d'état :</strong>
<ul>
<li><code>ExecErrc::kOperationCanceled</code> informe qu'une transition a été supplantée par une demande plus récente ou interrompue par State Management (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><code>ExecErrc::kInvalidTransition</code> est renvoyé lorsque la transition n'est pas autorisée (par ex. passage à l'état Off pour MachineFG) ou que l'état n'existe plus après une mise à jour logicielle (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code> signale l'échec des vérifications d'authenticité ou d'intégrité pendant le changement d'état (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kUnexpectedTermination</code> se produit lorsqu'un processus impliqué s'est terminé de manière inattendue pendant la transition (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kOperationFailed</code> indique l'échec général d'une transition (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). Lors de l'appel de <code>GetExecutionError</code>, cette erreur indique en revanche que le groupe de fonctions ne se trouve pas dans un état indéfini et que le problème a peut-être déjà été résolu (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
</ul>
<p class="ai-note">Ce guide est basé sur la spécification d'Execution Management pour l'AUTOSAR Adaptive Platform dans la version R25-11.</p>
