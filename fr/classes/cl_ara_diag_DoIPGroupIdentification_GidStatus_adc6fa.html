Contexte

La structure de données C++ ara::diag::DoIPGroupIdentification::GidStatus fait partie du module de diagnostic (diag) d'AUTOSAR Adaptive Platform dans la version R25-11 ([SWS_DM_00721], SWS Diagnostics §8.34.2 « Struct: GidStatus »). Elle agit en tant que support standardisé de données pour les données de réponse positive (« Response data of positive response message ») lors d'interrogations relatives à l'identification de groupe (Group Identification, GID) dans le cadre du protocole Diagnostic over IP (DoIP).

Dans le sous-système DoIP, l'identification de groupe sert à identifier des groupes logiques ou clusters de calculateurs et de nœuds de diagnostic dans le réseau du véhicule. Selon [SWS_DM_00813] (SWS Diagnostics §7 « Providing the GID in DoIP protocol messages using application interface »), le démon de Diagnostic Management (DM) est chargé de fournir le GID dans les messages de protocole DoIP sortants. Si le paramètre DoIpInstantiation.gid n'est pas préconfiguré statiquement, le Diagnostic Management doit demander l'identification de groupe à l'exécution via l'interface applicative. Pour cela, le DM appelle la fonction d'interface ara::diag::DoIPGroupIdentification::GetGidStatus ([SWS_DM_00724], SWS Diagnostics §8.34.1.1.3.1 « GetGidStatus »).

Dans cette interaction, la structure GidStatus représente le lien entre l'application adaptative fournisseuse et le Diagnostic Management. Elle encapsule les informations d'état et d'identification pertinentes pour le message de réponse positive, permettant ainsi au démon de composer le message DoIP conformément aux spécifications et de le transmettre au client externe demandeur.

Cycle de vie

En tant que structure de données (struct GidStatus), GidStatus ne possède pas de machine à états interne propre, mais se comporte comme un objet de transfert de données classique. Les instances de cette structure sont créées par l'application adaptative qui implémente et fournit le service ara::diag::DoIPGroupIdentification afin de répondre à l'appel de GetGidStatus ([SWS_DM_00724]).

Interprétation : dans la mesure où GidStatus est désignée dans la spécification exclusivement comme structure de résultat pour des messages de réponse positive, la durée de vie d'un objet devrait être étroitement liée à l'exécution et au retour de la méthode d'interrogation. L'application adaptative crée typiquement l'instance dans le contexte local ou la transmet par sémantique de déplacement ou via des wrappers de résultat à l'environnement d'exécution du Diagnostic Management. Dès que le Diagnostic Management a lu les valeurs de GID pour le message de protocole, l'instance est de nouveau détruite.

En ce qui concerne la concurrence, GidStatus ne présente aucun mécanisme de synchronisation interne. Comme les interrogations via GetGidStatus peuvent être traitées de manière asynchrone par le Diagnostic Management, il incombe à l'application implémentante de s'assurer que les données de diagnostic transmises au sein de GidStatus sont fournies de manière cohérente et thread-safe.

Parcours d'utilisation

Le déroulement d'utilisation typique de GidStatus intervient lors de la réponse dynamique aux requêtes d'identification DoIP. L'interaction entre le client DoIP externe, le Diagnostic Management et l'application adaptative se divise selon les phases suivantes :

  • 1. Requête par le client DoIP : un testeur de diagnostic externe ou un client DoIP envoie un message d'identification de véhicule ou de groupe au calculateur.
  • 2. Vérification de la configuration GID : le Diagnostic Management vérifie si l'identification de groupe est configurée de manière statique dans le modèle via DoIpInstantiation.gid ([SWS_DM_00813]).
  • 3. Interrogation de l'interface applicative : si aucune configuration statique n'est présente, le DM appelle la méthode ara::diag::DoIPGroupIdentification::GetGidStatus ([SWS_DM_00724]).
  • 4. Génération et renvoi de GidStatus : l'application adaptative détermine les données GID actuelles, instancie un objet de type GidStatus ([SWS_DM_00721]) et le renvoie au DM sous la forme d'une réponse positive.
  • 5. Assemblage de la réponse DoIP : le Diagnostic Management extrait les données d'identification de GidStatus, assemble le message de réponse DoIP conforme au standard et l'envoie au client DoIP.
