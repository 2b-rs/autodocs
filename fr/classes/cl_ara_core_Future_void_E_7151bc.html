Permet d'attendre l'achèvement d'une opération asynchrone sans valeur de retour ainsi que de récupérer l'état d'erreur.

La classe ara::core::Future<void, E> permet la synchronisation asynchrone et la vérification des erreurs d'opérations sans valeur de retour dans AUTOSAR Adaptive [SWS_CORE_06236]. En tant que type non copiable, elle permet d'attendre l'achèvement ainsi que de récupérer le résultat sans exception sous la forme ara::core::Result<void, E> [SWS_CORE_06236] ou de poursuivre le traitement asynchrone par une fonction de continuation [SWS_CORE_06231]. Après la récupération du résultat, l'état partagé est invalidé, de sorte que les appels ultérieurs sans état valide constituent une violation [SWS_CORE_06236].

Contexte

La spécialisation de classe template ara::core::Future<void, E> représente l'extrémité réceptrice d'une opération asynchrone dans AUTOSAR Adaptive qui, en cas d'achèvement réussi, ne renvoie aucune valeur mais signale uniquement la survenue de l'événement ou une erreur survenue. Selon la description de la classe, l'implémentation doit rejeter la condition E != ara::core::ErrorCode avec une erreur de compilation. La classe interagit typiquement avec un ara::core::Promise correspondant, qui remplit l'état partagé (shared state) [SWS_CORE_06236], ainsi qu'avec des contextes d'exécution asynchrones lors de l'enregistrement de fonctions de continuation [SWS_CORE_06237].

Cycle de vie

Les instances de ara::core::Future<void, E> sont des objets purement sémantiques de déplacement : le constructeur de copie [SWS_CORE_06234] ainsi que l'opérateur d'assignation par copie [SWS_CORE_06235] sont supprimés (delete). Un objet créé via le constructeur par défaut ne possède aucun état partagé et se comporte de manière analogue à std::future [SWS_CORE_06222]. Au moyen de la construction par déplacement [SWS_CORE_06223] ou de l'assignation par déplacement [SWS_CORE_06225], une instance prend possession d'un shared state provenant d'une autre instance.

Le cycle de vie est fortement déterminé par l'état du shared state. La méthode valid() permet de vérifier si l'instance est liée à un shared state et est donc utilisable [SWS_CORE_06227]. Dès que le résultat est récupéré au moyen de GetResult() [SWS_CORE_06236] ou get() [SWS_CORE_06226], ou qu'une continuation est enregistrée via then() [SWS_CORE_06231], l'objet Future perd son shared state et valid() renvoie false. Le destructeur libère un état partagé résiduel [SWS_CORE_06233]. En matière de concurrence, les opérations de vérification et de destruction telles que valid() [SWS_CORE_06227], is_ready() [SWS_CORE_06232] et le destructeur [SWS_CORE_06233] sont sûres pour les threads (thread-safe), tandis que les opérations modifiant l'état telles que GetResult() [SWS_CORE_06236], get() [SWS_CORE_06226] et les fonctions d'attente [SWS_CORE_06228] ne sont pas sûres pour les threads.

Parcours d'utilisation

Dans le chemin d'utilisation synchrone, un consommateur attend la fin de l'opération asynchrone. is_ready() permet de vérifier avec peu de blocage si une valeur ou une erreur est présente [SWS_CORE_06232]. Alternativement, il est possible d'attendre de manière bloquante au moyen de wait() [SWS_CORE_06228], ou pendant une durée limitée via wait_for() [SWS_CORE_06229] et wait_until() [SWS_CORE_06230]. Dès que le résultat est disponible, la récupération de la valeur s'effectue de préférence sans exception via GetResult(), renvoyant ainsi un ara::core::Result<void, E> [SWS_CORE_06236].

Dans le chemin asynchrone, la méthode then() permet l'enregistrement d'une fonction de continuation (continuation) qui est exécutée dès que le résultat est disponible [SWS_CORE_06231]. À cet égard, un contexte d'exécution (executor) peut optionnellement être transmis [SWS_CORE_06237]. La continuation reçoit le Result<void, E> en tant que rvalue. Le type de retour de then() déballe automatiquement les types Future ou Result imbriqués (unwrapping) [SWS_CORE_06231].

Scénarios d'erreur

Si une opération dépendante de l'état (telle que GetResult(), is_ready(), wait(), wait_for(), wait_until() ou then()) est appelée sur une instance invalide (valid() == false), il s'agit d'une violation de précondition traitée comme FutureInvalidViolation [SWS_CORE_06228], [SWS_CORE_06229], [SWS_CORE_06230], [SWS_CORE_06231], [SWS_CORE_06232], [SWS_CORE_06236], [SWS_CORE_06237]. En cas d'appel de get() sur une instance invalide, une FutureException avec le code d'erreur kNoState est levée à la place [SWS_CORE_06226] ; lorsque les exceptions C++ sont désactivées, get() ne participe pas à la résolution de surcharge [SWS_CORE_06226].

Si la Promise correspondante a été détruite ou a quitté l'état partagé sans définir de résultat ou d'erreur explicite, le code d'erreur FutureErrc::kBrokenPromise est consigné dans le shared state conformément à [SWS_CORE_00400] [SWS_CORE_06226], [SWS_CORE_06236]. Celui-ci est renvoyé par GetResult() en tant qu'erreur dans le Result<void, E> [SWS_CORE_06236]. Si une continuation enregistrée dans then() lève une exception qui n'implémente pas une violation, cela conduit à FutureContinuationHasThrownViolation [SWS_CORE_06231], [SWS_CORE_06237].

Ce guide est basé exclusivement sur la spécification AUTOSAR pour ara::core::Future<void, E> dans la Release R25-11.

                  La fonction membre get de la spécialisation ara::core::Future<void, E> sert à attendre le résultat d'une opération asynchrone sans valeur de retour ([SWS_CORE_06226]). Elle se comporte comme la fonction correspondante de std::future et bloque l'appelant jusqu'à ce que le résultat ou une erreur soit disponible ([SWS_CORE_06226], [SWS_CORE_00336]). Après l'appel, l'instance de future perd sa validité, de sorte que valid() == false s'applique ([SWS_CORE_06226]).
                  
  
                  La fonction est déclarée non sûre vis-à-vis des exceptions (not exception safe) ([SWS_CORE_06226]). Si une erreur a été consignée dans le Promise associé, une exception correspondante est déclenchée ([SWS_CORE_06226]). Si l'état partagé a été abandonné prématurément, le code d'erreur kBrokenPromise selon [SWS_CORE_00400] survient ([SWS_CORE_06226]). Si get est exécutée sur une instance déjà invalide, la fonction lève une FutureException avec le code d'erreur kNoState ([SWS_CORE_06226]).
                  
  
                  En matière de concurrence, la méthode n'est pas thread-safe (not thread-safe) ([SWS_CORE_06226]). Les accès parallèles au même objet nécessitent donc une synchronisation externe. De plus, la fonction ne participe pas à la résolution de surcharge lorsque les exceptions C++ sont désactivées dans la chaîne d'outils du compilateur ([SWS_CORE_06226]).
                  
  
                  En interaction avec des fonctions apparentées, [SWS_CORE_00332] (is_ready) garantit que get ne bloque pas si l'opération est déjà terminée. Pour les contextes sans exceptions, AUTOSAR propose comme alternative [SWS_CORE_00336] (GetResult), qui signale les erreurs via un type de résultat au lieu de lever des exceptions.

                                  template <typename F> auto then (F &&func) noexcept -> Future< <see below> >;
                                  

                                  Create a new Future with the content returned by func when passed the Result of this Future. func may be called in the context of this call or in the context of Promise::set_value() or Promise::SetError() or somewhere else. valid() == false on the original future object immediately after it returns. The Callable input argument "func" takes a Result<void,E> object as parameter. This will be the Result obtained via GetResult from the Future instance itself, on which .then() is being called. The Result is passed to func as an rvalue expression. The return type of then depends on the return type of func (aka continuation). Let U be the return type of the continuation (i.e. a type equivalent to std::invoke_result_ t<std::decay_t<F>,Result<void,E>>). • If U is Future<T2,E2> for some types T2, E2, then the return type of then() is Future<T2,E2>. This is known as implicit Future unwrapping. • If U is Result<T2,E2> for some types T2, E2, then the return type of then() is Future<T2,E2>. This is known as implicit Result unwrapping. • Otherwise it is Future<U,E>. Continuations that are registered with Future::then() are registered in the Future F that Future::then() returns. No such continuation shall be executed after the destructor of the Future F returns. A continuation that is already being executed shall run to completion. Note: that means that the destructor of Future might block until the currently running continuation has been completed. The continuation shall not throw, except for the purpose of implementing a Violation. Note: Exceptions can be used within the continuation, however if they do not realize a Violation, they must not escape the continuation. Note: Users who need to propagate information from closures’ exceptions should translate them to an error and return an ara::core::Result or ara::core::Future from the continuation with the error stored in it.

                                              La fonction membre wait de la spécialisation ara::core::Future<void, E> bloque le thread appelant de manière synchrone jusqu'à ce que le résultat de l'opération asynchrone soit disponible sous la forme d'une valeur ou d'une erreur [SWS_CORE_06228]. La fonction ne prend aucun paramètre, ne renvoie aucune valeur de retour (void) et se comporte conformément à la spécification comme la fonction correspondante de std::future [SWS_CORE_06228].
                                              


                                              Concernant le traitement des erreurs et les conditions aux limites, les exigences suivantes s'appliquent :
                                              

                                                

                                              • Sécurité vis-à-vis des exceptions et traitement des erreurs : L'opération est déclarée avec noexcept et spécifiée comme sûre vis-à-vis des exceptions (exception safe) [SWS_CORE_06228]. Si valid() renvoie false pour l'instance de future, la violation FutureInvalidViolation est présente [SWS_CORE_06228]. La conséquence concrète de cette violation devrait être mise en œuvre sous forme d'un traitement d'erreurs spécifique au système de l'environnement d'exécution AUTOSAR.
                                                • 

                                              • Concurrence : La fonction est classée comme non thread-safe (not thread-safe) [SWS_CORE_06228]. Un accès concurrent au même objet future sans synchronisation externe est donc inadmissible.
                                                • 

                                              


                                              En interaction avec les autres fonctions du module core, les possibilités suivantes existent :
                                              

                                                

                                              • La méthode thread-safe is_ready permet de vérifier au préalable si l'opération est terminée ; en cas de retour de true, wait est garanti de ne plus bloquer [SWS_CORE_06232].
                                                • 

                                              • Pour éviter un blocage infini, les fonctions limitées dans le temps wait_for avec une durée relative [SWS_CORE_06229] ainsi que wait_until avec un instant absolu [SWS_CORE_06230] sont disponibles.
                                                • 

                                              • Pour la classe de modèle primaire ara::core::Future, les mêmes exigences d'attente synchrone et restrictions s'appliquent [SWS_CORE_00328].

Le comportement correspond à l'interface générale de future [SWS_CORE_00329].
