Encapsule l'identifiant 16 bits et les données utiles associées d'un enregistrement d'instantané de DTC pour les requêtes de diagnostic.

La structure ara::diag::DTCInformation::SnapshotDataIdentifierType sert d'objet valeur pour l'encapsulation d'enregistrements d'instantanés d'un DTC ([SWS_DM_00660], AUTOSAR_AP_SWS_Diagnostics §8.48.3 « Struct: SnapshotDataIdentifierType »). Elle met à la disposition de l'application de diagnostic l'identifiant 16 bits dataIdentifier ainsi que les données brutes collectées dans data ([SWS_DM_02112], [SWS_DM_02113]). La structure étant passive, il incombe à l'appelant de vérifier l'exhaustivité et la validité des données utiles avant la désérialisation.

Contexte

La structure ara::diag::DTCInformation::SnapshotDataIdentifierType fait partie intégrante du module diag d'AUTOSAR Adaptive Platform et est fournie via l'en-tête ara/diag/dtc_information.h ([SWS_DM_00660], AUTOSAR_AP_SWS_Diagnostics §8.48.3 « Struct: SnapshotDataIdentifierType »). En tant que conteneur de données au sein de la portée de ara::diag::DTCInformation, elle encapsule les données d'un enregistrement d'instantané spécifique (Snapshot Record ou Freeze Frame) associé à un code d'erreur de diagnostic (Diagnostic Trouble Code, DTC) ([SWS_DM_02112], [SWS_DM_02113]).

Dans l'architecture de diagnostic, ce type sert d'intermédiaire entre le système de diagnostic (Diagnostic Management) et les services utilisateurs (AUTOSAR_AP_SWS_Diagnostics §7 « Diagnostic Management »). Pour ce faire, la structure regroupe deux attributs publics : l'identificateur de données de diagnostic 16 bits dataIdentifier pour l'identification de l'enregistrement ([SWS_DM_02112]) ainsi que le vecteur d'octets dynamique data contenant les données brutes effectives ([SWS_DM_02113], AUTOSAR_AP_SWS_Diagnostics §8.48.3.1 « Public Member Variables »).

Cycle de vie

SnapshotDataIdentifierType est un pur objet de transfert de données (Value Type). Les instances sont généralement créées dans le cadre de requêtes de diagnostic au cours desquelles le service de diagnostic sous-jacent rassemble les valeurs figées lors de l'apparition de l'erreur et les intègre dans la structure ([SWS_DM_00660], [SWS_DM_02113]). L'objet créé est ensuite transmis à l'appelant par sémantique de valeur ou de déplacement ; le type ne possède ni identité propre ni machine à états interne.

La durée de vie de l'instance est liée à la portée dans l'application consommatrice. Dès que l'objet quitte la portée, la mémoire dynamique allouée par le membre data de type ara::core::Vector<std::uint8_t> est libérée conformément à la sémantique RAII régulière du C++ ([SWS_DM_02113]). Les accès concurrents en lecture depuis plusieurs threads sont intrinsèquement sûrs, tandis que les accès modificateurs parallèles sur la même instance requièrent une synchronisation externe.

Parcours d'utilisation

Le déroulement typique commence par l'interrogation d'informations d'instantané de DTC par une application de diagnostic via les interfaces de ara::diag::DTCInformation (AUTOSAR_AP_SWS_Diagnostics §7 « Diagnostic Management »). L'instance de SnapshotDataIdentifierType est alors initialisée et renvoyée à l'application ([SWS_DM_00660]). Ensuite, l'appelant vérifie l'identifiant dataIdentifier ([SWS_DM_02112]) afin de déterminer le schéma de données, et extrait les valeurs mesurées à partir du vecteur de données brutes data ([SWS_DM_02113]).

Diagramme de séquence : déroulement typique de l'interrogation et de l'évaluation d'un enregistrement d'instantané via DTCInformation. Sources : [SWS_DM_00660], [SWS_DM_02112], [SWS_DM_02113], AUTOSAR_AP_SWS_Diagnostics §8.48.3 « Struct: SnapshotDataIdentifierType »

Scénarios d'erreur

En tant que structure de données passive, SnapshotDataIdentifierType ne lève elle-même aucune exception et ne signale aucun code d'erreur ([SWS_DM_00660]). Les situations d'erreur résultent principalement d'états de données inattendus :

  • Données utiles vides : si aucune valeur n'a pu être collectée au moment de l'erreur, le vecteur data peut être vide ([SWS_DM_02113]). Les applications consommatrices doivent valider la taille du vecteur avant d'accéder aux indices.
  • Identificateurs inconnus ou inattendus : si dataIdentifier ne correspond pas aux données de diagnostic configurées pour le véhicule ([SWS_DM_02112]), la désérialisation doit être rejetée.
  • Écarts de longueur : si le nombre d'octets dans data ne correspond pas à la longueur statique de données utiles attendue pour le DID concerné, cela indique des erreurs de transmission ou de mise en mémoire tampon ([SWS_DM_02113]).
