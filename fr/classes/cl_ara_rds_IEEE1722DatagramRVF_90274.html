Encapsule les métadonnées et les champs d’en-tête de datagrammes IEEE 1722 pour les flux de données vidéo non compressés.

La classe ara::rds::IEEE1722DatagramRVF représente, au sein du module AUTOSAR Raw Data Stream, des datagrammes IEEE 1722 spécifiques pour le Raw Video Format destinés à la transmission structurée de flux vidéo non compressés SWS RawDataStream §1 « Raw Data Stream ». Elle regroupe l’ensemble des métadonnées pertinentes pour l’image et la transmission, telles que les nombres de lignes, les espaces colorimétriques, les fréquences d’images ainsi que les bits de contrôle de protocole, dans des champs optionnels protégés. En tant que structure de données déclarée final, elle exclut tout héritage ultérieur, mais garantit, grâce à un destructeur virtuel, une libération déterministe et sans exception via des pointeurs de classe de base [SWS_RDS_90292].

Contexte

La classe ara::rds::IEEE1722DatagramRVF représente, au sein du module fonctionnel Raw Data Stream (rds) de l’AUTOSAR Adaptive Platform, un datagramme IEEE 1722 concret pour le Raw Video Format (RVF) SWS RawDataStream §1 « Raw Data Stream ». Dans le cadre d’Audio Video Bridging (AVB) et de Time-Sensitive Networking (TSN), le Raw Video Format sert au transport de flux vidéo non compressés sur des réseaux basés sur des paquets. La structure de données est définie dans le fichier d’en-tête ara/rds/raw_data_stream_IEEE1722.h [SWS_RDS_90276]. La définition de classe est pourvue du mot-clé final et intègre, via un héritage protégé (protected), aussi bien la classe de base générique IEEE1722Datagram que AVTPDUCommonStreamHeaderFields [SWS_RDS_90276]. Grâce à cette composition, la structure réunit les champs d’en-tête de flux AVTP de base avec les champs de métadonnées spécifiques nécessaires au traitement des lignes vidéo individuelles et des trames d’image.

Diagramme de contexte : intégration d’IEEE1722DatagramRVF dans la hiérarchie de classes avec IEEE1722Datagram et AVTPDUCommonStreamHeaderFields. Sources : [SWS_RDS_90276], SWS RawDataStream §1 « Raw Data Stream »

Cycle de vie

Le cycle de vie d’une instance de IEEE1722DatagramRVF est principalement déterminé par le pipeline de traitement du Raw Data Stream. Pour le nettoyage propre des instances, la classe déclare un destructeur virtuel virtual ~IEEE1722DatagramRVF() noexcept [SWS_RDS_90292]. Bien que la classe elle-même soit marquée comme final [SWS_RDS_90276] et ne puisse donc pas servir de classe de base pour d’autres sous-classes, la conception virtuelle du destructeur garantit une libération correcte si des instances sont référencées et détruites de manière polymorphe via des pointeurs de classe de base.

L’ajout noexcept sur le destructeur garantit qu’aucune exception ne peut s’échapper pendant l’opération de destruction, quelles que soient les circonstances [SWS_RDS_90292]. Dans les systèmes automobiles critiques pour la sécurité, il s’agit d’une condition préalable essentielle pour garantir des processus de nettoyage déterministes sans interruptions brutales de programme. La spécification AUTOSAR ne définit aucune primitive de synchronisation explicite pour l’accès concurrent pour cette classe de données ; par conséquent, une manipulation sûre vis-à-vis des threads doit être assurée, au besoin, au niveau des services de streaming environnants.

Parcours d'utilisation

Dans le déroulement pratique du traitement, la classe agit comme vecteur d’informations pour les trames vidéo reçues ou à envoyer. La structure regroupe ici de nombreux champs décrivant en détail les dimensions de l’image, la référence temporelle et le codage des couleurs. Pour la structure géométrique de la vidéo, les pixels actifs active_pixels [SWS_RDS_90276], le nombre total de lignes d’une image total_lines [SWS_RDS_90278], le numéro de ligne line_number [SWS_RDS_90291] et le nombre de lignes par paquet de données num_lines [SWS_RDS_90289] sont disponibles.

Pour une interprétation correcte du flux de données de pixels, la classe encapsule en outre des propriétés de format vidéo spécifiques au système : la profondeur de bits par pixel pixel_depth [SWS_RDS_90285], le format de pixel pixel_format [SWS_RDS_90286], l’espace colorimétrique colorspace [SWS_RDS_90288] ainsi que la fréquence de rafraîchissement d’image frame_rate [SWS_RDS_90287]. S’y ajoutent des bits de contrôle et de statut du protocole de transmission spécifiques à AVTP : le champ ap [SWS_RDS_90279], le drapeau f [SWS_RDS_90280], le champ ef [SWS_RDS_90281], des champs d’événements tels que evt [SWS_RDS_90282] et pd [SWS_RDS_90283], le drapeau i [SWS_RDS_90284] ainsi que le numéro de séquence i_seq_num [SWS_RDS_90290].

L’encapsulation systématique de toutes les variables dans ara::core::Optional est remarquable. Cette déclaration laisse supposer que les datagrammes peuvent présenter des en-têtes incomplets ou que certaines métadonnées ne sont transmises qu’en cas de besoin selon le profil de paquétisation AVTP. Tous les attributs sont pourvus du niveau de protection protected [SWS_RDS_90276], [SWS_RDS_90278]. Comme une dérivation par le code utilisateur est impossible en raison de final, l’accès en lecture et en écriture à ces champs devrait être réalisé via des classes utilitaires internes ou des instances de pilotes amies du module RDS.

Ce guide est basé sur la spécification AUTOSAR Adaptive Platform R25-11.
