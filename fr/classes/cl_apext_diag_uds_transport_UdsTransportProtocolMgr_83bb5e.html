classe apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

But d'utilisation

UdsTransportProtocolMgr gère l'interaction entre les instances de Diagnostic Server et les protocoles de transport UDS, tels que DoIP ou CAN. Il fournit au gestionnaire de transport une interface standardisée pour l'acceptation des messages, le transfert vers la couche session, l'envoi d'accusés de réception et la récupération du canal. [SWS_DM_00306]

Acceptation et propriété du message

Un gestionnaire signale le début d'un message reçu avec IndicateMessage(), y compris les adresses source et de destination, le type d'adresse, l'ID de canal global, la taille et un extrait de charge utile valide uniquement pendant l'invocation. Si le DM peut traiter la demande, il renvoie kIndicationOk et une mémoire appartenant au UdsMessagePtr. En cas d'occupation, de manque de ressources ou d'adresse cible inconnue, kIndicationOccupied, kIndicationOverflow ou kIndicationUnknownTargetAddress sont fournis avec des pointeurs nuls. [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

Après avoir rempli l'objet message renvoyé, le gestionnaire le transmet à la couche session via HandleMessage() ; Ce faisant, la propriété revient au noyau générique DM. Si IndicateMessage() n'a pas délivré de kIndicationOk, HandleMessage() ne peut pas être appelé. En cas d'erreur de transport prématurée, l'objet est renvoyé avec NotifyMessageFailure(). [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

Cycle de vie et transmission

TransmitConfirmation() signale kTransmitOk ou kTransmitFailed pour un transfert demandé par le DM via UdsTransportProtocolHandler::Transmit(). PeriodicTransmitConfirmation() confirme une liste ordonnée de messages envoyés périodiquement, ainsi que le nombre d’éléments envoyés avec succès. [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

Le DM ne peut traiter une récupération de canal qu'après le démarrage du gestionnaire associé. Après son arrêt, aucun autre appel du Manager, à l'exception de HandlerStopped(), n'est autorisé ; le DM attend ce callback avant de mettre fin au processus. [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

restrictions

Toutes les opérations du gestionnaire décrites dans l'extrait sont sécurisées pour les exceptions, mais pas pour les threads. L'identification d'un client de diagnostic est basée sur le tuple de l'adresse source et de l'ID de canal global. fonction HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

Bibliographie Diagnostics SWS : [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
