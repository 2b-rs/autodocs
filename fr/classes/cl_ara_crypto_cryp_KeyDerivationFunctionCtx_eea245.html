Contexte

La classe ara::crypto::cryp::KeyDerivationFunctionCtx définit l'interface pour les fonctions de dérivation de clé cryptographiques (Key Derivation Function, KDF) sur l'AUTOSAR Adaptive Platform. Elle fait partie du module crypto et étend l'interface de base CryptoContext avec des mécanismes permettant de générer de manière déterministe de nouvelles clés symétriques à partir du matériel de clé existant et de paramètres de contexte supplémentaires [SWS_CRYPT_21515].

Au sein de l'architecture cryptographique, l'interface interagit avec les instances suivantes :

  • Composant applicatif : contrôle le cycle de vie du contexte, définit les paramètres et déclenche le processus de dérivation.
  • Clé source ou magasin de clés : fournit le matériel de base cryptographique, soit directement sous forme d'objet de clé volatile SymmetricKey [SWS_CRYPT_21525], soit via un emplacement de clé référencé KeySlot [SWS_CRYPT_50010].
  • Clé cible : le résultat de la dérivation est un objet de clé symétrique autonome (SymmetricKey::Sptr), généré avec des restrictions d'algorithme et d'utilisation dédiées [SWS_CRYPT_21515].

Diagramme de contexte : interaction entre l'application, le contexte KDF, le matériel source et la clé cible dérivée. Sources : [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50010].

Cycle de vie

Les instances de KeyDerivationFunctionCtx sont référencées et gérées via le type de pointeur intelligent Sptr (défini comme std::shared_ptr<KeyDerivationFunctionCtx>) [SWS_CRYPT_21501]. (Interprétation : étant donné que la classe est une interface purement virtuelle, l'instanciation concrète devrait généralement s'effectuer via une méthode fabrique d'un fournisseur cryptographique compétent).

Après sa création, le contexte se trouve dans un état incomplètement initialisé. Avant d'exécuter une dérivation de clé, il est impératif de définir le matériel de clé de base ainsi que tous les paramètres requis pour l'algorithme. Si la dérivation est appelée prématurément, l'opération s'interrompt avec ara::crypto::CryptoErrc::kUninitializedContext [SWS_CRYPT_21515].

En matière de concurrence, toutes les méthodes de l'interface sont définies comme sûres vis-à-vis des threads et sûres face aux exceptions (noexcept) [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50010], [SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009]. En cas d'erreur, une sémantique de retour arrière s'applique, de sorte que le contexte demeure toujours dans un état défini.

Parcours d'utilisation

L'utilisation typique se divise en une phase séquentielle de configuration et d'exécution :

  1. Assigner la clé source : la clé de base est soit transmise au contexte via un objet clé direct au moyen de SetKey(SymmetricKey::Sptr) [SWS_CRYPT_21525], soit rattachée via un emplacement de clé géré au moyen de SetKey(KeySlot::Sptr) [SWS_CRYPT_50010].
  2. Configurer les paramètres KDF : selon le procédé KDF (par ex. HKDF ou PBKDF2), les données supplémentaires requises sont définies via les méthodes surchargées SetParameter :
    • Des zones de mémoire (ReadOnlyMemRegion) pour les données binaires telles que les sels, les étiquettes ou les données de contexte [SWS_CRYPT_50007],
    • Des valeurs entières (std::uint64_t) pour les compteurs ou les nombres d'itérations [SWS_CRYPT_50008],
    • Des objets clés supplémentaires (SymmetricKey::Sptr), si le procédé requiert du matériel de clé à plusieurs niveaux [SWS_CRYPT_50009].
  3. Déclencher la dérivation de clé : La méthode DeriveKey exécute la dérivation [SWS_CRYPT_21515]. L'ID d'algorithme cible (targetAlgId) et les flags d'utilisation souhaités (allowedUsage) de la nouvelle clé sont transmis comme paramètres.
  4. Vérifier le résultat : en cas de dérivation réussie, l'appel renvoie un ara::core::Result contenant un pointeur vers la nouvelle clé symétrique cible instanciée (SymmetricKey::Sptr) [SWS_CRYPT_21515].

Diagramme de séquence : déroulement typique de la dérivation de clé, de la configuration à la restitution de la clé. Sources : [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50007], [SWS_CRYPT_50008].

Scénarios d'erreur

Lors de la configuration et de la dérivation, le contexte contrôle rigoureusement les préconditions et les droits d'utilisation et signale les erreurs via ara::core::Result :

  • Initialisation incomplète : ara::crypto::CryptoErrc::kUninitializedContext survient lors de DeriveKey si des paramètres requis ou la clé de base sont manquants [SWS_CRYPT_21515].
  • Violations de droits (kUsageViolation) :
    • Est renvoyé lorsque la clé source fournie ne comporte pas l'indicateur kAllowKeyDerivation [SWS_CRYPT_21515], [SWS_CRYPT_21525], [SWS_CRYPT_50009].
    • Survient lors de DeriveKey lorsque kAllowPlaintextExport est requis pour la clé cible, mais que la clé source ne l'autorise pas via kAllowDerivedPlaintextExport [SWS_CRYPT_21515].
  • Incompatibilité (kIncompatibleObject, kIncompatibleArguments) :
    • kIncompatibleObject signale que le SymmetricKey ou le KeySlot transmis n'est pas compatible avec le contexte KDF [SWS_CRYPT_21525], [SWS_CRYPT_50010], [SWS_CRYPT_50009].
    • kIncompatibleArguments indique que les indicateurs allowedUsage spécifiés sont incompatibles avec le targetAlgId sélectionné [SWS_CRYPT_21515].
  • Valeurs ou paramètres non pris en charge (kUnsupported, UnknownIdentifier) :
    • UnknownIdentifier est déclenché lorsqu'un algorithme cible inconnu targetAlgId est transmis [SWS_CRYPT_21515].
    • kUnsupported signale qu'un nom de paramètre configuré n'est pas pris en charge par le contexte [SWS_CRYPT_50007], [SWS_CRYPT_50008], [SWS_CRYPT_50009], ou que l'implémentation prend en charge exclusivement des objets clés ou exclusivement des emplacements de clé [SWS_CRYPT_21525], [SWS_CRYPT_50010].
  • Arguments non valides (kInvalidArgument) : est renvoyé si une valeur de paramètre transmise est syntaxiquement ou sémantiquement non valide [SWS_CRYPT_50007], [SWS_CRYPT_50008].
  • Erreurs de ressources et de mémoire (kEmptyKeySlot, kBusyResource) :
    • kEmptyKeySlot survient lorsqu'un KeySlot configuré est vide au moment de l'exécution [SWS_CRYPT_21515].
    • kBusyResource indique qu'une ressource cryptographique interne requise est occupée [SWS_CRYPT_21515].

<h4>Contexte</h4>
<p>La classe <code>ara::crypto::cryp::KeyDerivationFunctionCtx</code> définit l'interface pour les fonctions de dérivation de clé cryptographiques (Key Derivation Function, KDF) sur l'AUTOSAR Adaptive Platform. Elle fait partie du module <code>crypto</code> et étend l'interface de base <code>CryptoContext</code> avec des mécanismes permettant de générer de manière déterministe de nouvelles clés symétriques à partir du matériel de clé existant et de paramètres de contexte supplémentaires <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</p>
<p>Au sein de l'architecture cryptographique, l'interface interagit avec les instances suivantes :</p>
<ul>
<li><strong>Composant applicatif</strong> : contrôle le cycle de vie du contexte, définit les paramètres et déclenche le processus de dérivation.</li>
<li><strong>Clé source ou magasin de clés</strong> : fournit le matériel de base cryptographique, soit directement sous forme d'objet de clé volatile <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, soit via un emplacement de clé référencé <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>.</li>
<li><strong>Clé cible</strong> : le résultat de la dérivation est un objet de clé symétrique autonome (<code>SymmetricKey::Sptr</code>), généré avec des restrictions d'algorithme et d'utilisation dédiées <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>

<h4>Cycle de vie</h4>
<p>Les instances de <code>KeyDerivationFunctionCtx</code> sont référencées et gérées via le type de pointeur intelligent <code>Sptr</code> (défini comme <code>std::shared_ptr&lt;KeyDerivationFunctionCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21501" href="../spec/record.html?id=SWS_CRYPT_21501">[SWS_CRYPT_21501]</a>. (Interprétation : étant donné que la classe est une interface purement virtuelle, l'instanciation concrète devrait généralement s'effectuer via une méthode fabrique d'un fournisseur cryptographique compétent).</p>
<p>Après sa création, le contexte se trouve dans un état incomplètement initialisé. Avant d'exécuter une dérivation de clé, il est impératif de définir le matériel de clé de base ainsi que tous les paramètres requis pour l'algorithme. Si la dérivation est appelée prématurément, l'opération s'interrompt avec <code>ara::crypto::CryptoErrc::kUninitializedContext</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</p>
<p>En matière de concurrence, toutes les méthodes de l'interface sont définies comme sûres vis-à-vis des threads et sûres face aux exceptions (<code>noexcept</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>. En cas d'erreur, une sémantique de retour arrière s'applique, de sorte que le contexte demeure toujours dans un état défini.</p>

<h4>Parcours d'utilisation</h4>
<p>L'utilisation typique se divise en une phase séquentielle de configuration et d'exécution :</p>
<ol>
<li><strong>Assigner la clé source</strong> : la clé de base est soit transmise au contexte via un objet clé direct au moyen de <code>SetKey(SymmetricKey::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, soit rattachée via un emplacement de clé géré au moyen de <code>SetKey(KeySlot::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>.</li>
<li><strong>Configurer les paramètres KDF</strong> : selon le procédé KDF (par ex. HKDF ou PBKDF2), les données supplémentaires requises sont définies via les méthodes surchargées <code>SetParameter</code> :
<ul>
<li>Des zones de mémoire (<code>ReadOnlyMemRegion</code>) pour les données binaires telles que les sels, les étiquettes ou les données de contexte <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>,</li>
<li>Des valeurs entières (<code>std::uint64_t</code>) pour les compteurs ou les nombres d'itérations <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>,</li>
<li>Des objets clés supplémentaires (<code>SymmetricKey::Sptr</code>), si le procédé requiert du matériel de clé à plusieurs niveaux <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
</ul>
</li>
<li><strong>Déclencher la dérivation de clé</strong> : La méthode <code>DeriveKey</code> exécute la dérivation <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>. L'ID d'algorithme cible (<code>targetAlgId</code>) et les flags d'utilisation souhaités (<code>allowedUsage</code>) de la nouvelle clé sont transmis comme paramètres.</li>
<li><strong>Vérifier le résultat</strong> : en cas de dérivation réussie, l'appel renvoie un <code>ara::core::Result</code> contenant un pointeur vers la nouvelle clé symétrique cible instanciée (<code>SymmetricKey::Sptr</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ol>

<h4>Scénarios d'erreur</h4>
<p>Lors de la configuration et de la dérivation, le contexte contrôle rigoureusement les préconditions et les droits d'utilisation et signale les erreurs via <code>ara::core::Result</code> :</p>
<ul>
<li><strong>Initialisation incomplète</strong> : <code>ara::crypto::CryptoErrc::kUninitializedContext</code> survient lors de <code>DeriveKey</code> si des paramètres requis ou la clé de base sont manquants <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
<li><strong>Violations de droits (<code>kUsageViolation</code>)</strong> :
<ul>
<li>Est renvoyé lorsque la clé source fournie ne comporte pas l'indicateur <code>kAllowKeyDerivation</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
<li>Survient lors de <code>DeriveKey</code> lorsque <code>kAllowPlaintextExport</code> est requis pour la clé cible, mais que la clé source ne l'autorise pas via <code>kAllowDerivedPlaintextExport</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>
</li>
<li><strong>Incompatibilité (<code>kIncompatibleObject</code>, <code>kIncompatibleArguments</code>)</strong> :
<ul>
<li><code>kIncompatibleObject</code> signale que le <code>SymmetricKey</code> ou le <code>KeySlot</code> transmis n'est pas compatible avec le contexte KDF <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>.</li>
<li><code>kIncompatibleArguments</code> indique que les indicateurs <code>allowedUsage</code> spécifiés sont incompatibles avec le <code>targetAlgId</code> sélectionné <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>
</li>
<li><strong>Valeurs ou paramètres non pris en charge (<code>kUnsupported</code>, <code>UnknownIdentifier</code>)</strong> :
<ul>
<li><code>UnknownIdentifier</code> est déclenché lorsqu'un algorithme cible inconnu <code>targetAlgId</code> est transmis <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
<li><code>kUnsupported</code> signale qu'un nom de paramètre configuré n'est pas pris en charge par le contexte <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50009" href="../spec/record.html?id=SWS_CRYPT_50009">[SWS_CRYPT_50009]</a>, ou que l'implémentation prend en charge exclusivement des objets clés ou exclusivement des emplacements de clé <a class="spec-record-ref" data-req="SWS_CRYPT_21525" href="../spec/record.html?id=SWS_CRYPT_21525">[SWS_CRYPT_21525]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50010" href="../spec/record.html?id=SWS_CRYPT_50010">[SWS_CRYPT_50010]</a>.</li>
</ul>
</li>
<li><strong>Arguments non valides (<code>kInvalidArgument</code>)</strong> : est renvoyé si une valeur de paramètre transmise est syntaxiquement ou sémantiquement non valide <a class="spec-record-ref" data-req="SWS_CRYPT_50007" href="../spec/record.html?id=SWS_CRYPT_50007">[SWS_CRYPT_50007]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50008" href="../spec/record.html?id=SWS_CRYPT_50008">[SWS_CRYPT_50008]</a>.</li>
<li><strong>Erreurs de ressources et de mémoire (<code>kEmptyKeySlot</code>, <code>kBusyResource</code>)</strong> :
<ul>
<li><code>kEmptyKeySlot</code> survient lorsqu'un <code>KeySlot</code> configuré est vide au moment de l'exécution <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
<li><code>kBusyResource</code> indique qu'une ressource cryptographique interne requise est occupée <a class="spec-record-ref" data-req="SWS_CRYPT_21515" href="../spec/record.html?id=SWS_CRYPT_21515">[SWS_CRYPT_21515]</a>.</li>
</ul>
</li>
