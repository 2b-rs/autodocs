But d'utilisation

MultipleEvent regroupe les opérations portant sur plusieurs événements de diagnostic. Un EventHandleType permet d'interroger l'état de l'événement, l'état de debounce, le Fault Detection Counter et le numéro DTC associé. [SWS_DM_01704] [SWS_DM_01707] [SWS_DM_01710] [SWS_DM_01711] [SWS_DM_01709] Un notifier de changement d'état peut être enregistré pour chaque handle d'événement ; un enregistrement ultérieur remplace le précédent. [SWS_DM_01708]

Cycle de vie et propriété

L'instance est créée pour un PortPrototype de DiagnosticMultipleEventInterface. [SWS_DM_01705] Elle n'est ni copiable, ni assignable, ni déplaçable ; les opérations correspondantes sont supprimées. [SWS_DM_02070] [SWS_DM_02067] [SWS_DM_02069] [SWS_DM_02068] Le destructeur est noexcept. [SWS_DM_01706]

Restrictions & traitement des erreurs

Les Event Handles sont attribués à partir des Events mappés et, en l’absence de overrideId, dans l’ordre alphabétique à partir de 0x010000. [SWS_DM_01733] Les handles n’appartenant pas à cette instance entraînent kInvalidArgument. [SWS_DM_01734] Les interrogations peuvent en outre fournir kNoSuchDTC ou kServiceNotAvailable ; leur sûreté des threads dépend de ConcurrencyType. [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711] L’enregistrement de Notifier n’est pas thread-safe. [SWS_DM_01708]

L’interrogation DTC tient compte du DTCFormatType demandé. [SWS_DM_01709] Pour un Event sans DTC associé, elle peut fournir kNoSuchDTC. [SWS_DM_01709] Toutes les opérations d’interrogation sont sûres vis-à-vis des exceptions. [SWS_DM_01707] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711] L’enregistrement du Notifier de statut peut fournir une erreur en cas d’arguments invalides. [SWS_DM_01708]

La classe est final et n’est donc pas destinée à être dérivée. [SWS_DM_01704] Le constructeur lui-même est sûr vis-à-vis des exceptions et thread-safe. [SWS_DM_01705]
