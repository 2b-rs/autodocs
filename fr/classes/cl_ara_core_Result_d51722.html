classe ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

But d'utilisation

Pour les appels synchrones, ara::core::Result<T,E> encapsule soit une valeur de type T, soit une erreur de type E ; E doit être ara::core::ErrorCode. Le type prend donc en charge la gestion des erreurs sans exception. [SWS_CORE_00701] [SWS_CORE_10600]

Génération et cycle de vie

Un résultat peut être généré à partir d'une valeur ou d'une erreur ainsi que via FromValue() et FromError(). Les opérations de copie et de déplacement sont disponibles et conditionnelles à noexcept ; la trivialité du destructeur dépend de T et E. [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

Interaction avec d'autres classes

HasValue(), Value(), Error(), Ok() et Err() autorisent l'accès au statut et au contenu. Bind() transforme une valeur contenue en un nouveau Result à l'aide d'un appelable, tandis que Resolve() appelle une fonction en cas d'erreur. [SWS_CORE_00751] [SWS_CORE_00755] [SWS_CORE_00757] [SWS_CORE_00770] [SWS_CORE_00772] [SWS_CORE_00768] [SWS_CORE_00767]

Restrictions & traitement des erreurs

L'accès à des erreurs sans erreur incluse ou à une valeur sans valeur incluse est défini comme une violation. ValueOrThrow() peut se déclencher et constitue la seule fonction de résultat exemptée d'utilisation sans initialisation de ara::core. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

Rôle dans le chemin d'erreur sans exception

Pour les erreurs récupérables, les interfaces doivent utiliser ara::core::Result ou ara::core::Future ; le type d’erreur Result est fixé à ara::core::ErrorCode. RS General §4.1.2 « Error handling » EXP InterfacesGuidelines §3.1.2 « Result »

En accès sans exception, l'appelant vérifie HasValue() puis lit Value() ou Error(). Ces observateurs peuvent être utilisés sans exceptions C++ ; ValueOrThrow(), en revanche, est la transition explicite vers un chemin basé sur les exceptions. EXP InterfacesGuidelines §3.1.2.3 « Advanced topics » EXP PlatformDesign §18.1.3 « Result » RS General §4.1.3 « The use of noexcept »

Diagramme d'activité : le flux habituel sans exception passe à la valeur ou à l'erreur après HasValue() ; ValueOrThrow() est le chemin d'exception affiché en option. Sources : EXP InterfacesGuidelines §3.1.2.3 « Advanced topics » EXP PlatformDesign §18.1.3 « Result ».

Noyau normatif : valeur ou erreur

La spécification Core mappe Result au modèle de gestion des erreurs : pour les erreurs récupérables, les API doivent renvoyer Result ou Future. Result sépare ainsi le chemin de valeur normale d'une erreur transportée sous forme de valeur de données. SWS Core §7.2 « Error handling » SWS Core §7.2.5.4 « Result »
