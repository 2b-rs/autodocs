Met à disposition des métadonnées et des informations d'intégrité pour les données volumineuses de diagnostic lors de la communication SOVD.

La structure ara::diag::SovdBulkData::BulkDataMetaDataDescriptor sert d'objet de transfert de données pour la description de données volumineuses pour la communication de diagnostic SOVD dans AUTOSAR Adaptive ([SWS_DM_01830]). Elle regroupe des informations d'identification, de localisation et de type telles que id, file_name et mimetype ainsi que des sommes de contrôle et des indications de taille facultatives (SWS Diagnostics §8.53.2 « Struct: BulkDataMetaDataDescriptor »). L'instance est renseignée avec des métadonnées par l'application de diagnostic fournisseuse et transmise au sous-système SOVD. S'agissant d'une structure C++ passive sans synchronisation propre, les accès concurrents en écriture doivent être sécurisés de manière externe par l'application appelante.

Contexte

La structure de données ara::diag::SovdBulkData::BulkDataMetaDataDescriptor fait partie intégrante du module diag de l'AUTOSAR Adaptive Platform et est mise à disposition via l'en-tête #include "ara/diag/sovd_bulk_data.h" ([SWS_DM_01830]). Elle définit le descripteur de métadonnées pour les données volumineuses de diagnostic (Bulk Data) qui sont transmises dans le cadre de SOVD (Service-Oriented Vehicle Diagnostics) (SWS Diagnostics §8.53.2 « Struct: BulkDataMetaDataDescriptor »). Lors de scénarios de diagnostic tels que la lecture de fichiers journaux volumineux, de tampons de trace ou de paquets de mise à jour, les clients de diagnostic requièrent des informations d'accompagnement structurées en plus du flux de données binaire. La structure regroupe ces métadonnées pour une identification univoque, une interprétation et un contrôle d'intégrité.

Dans l'interaction entre l'application de diagnostic, le système d'exécution ara::diag et les testeurs de diagnostic externes, la structure fait office d'objet de transfert de données passif (DTO). Le champ id définit l'identifiant univoque des données volumineuses ([SWS_DM_01831]). Pour la désignation, file_name est disponible pour le nom de fichier ([SWS_DM_01836]), name pour la désignation logique ([SWS_DM_01833]) ainsi que translation_id à des fins de localisation ([SWS_DM_01834]). Le type de média est déclaré par mimetype ([SWS_DM_01832]). La garantie d'intégrité est assurée par hash ([SWS_DM_01839]) et hash_algorithm ([SWS_DM_01840]), tandis que creation_date ([SWS_DM_01837]) et last_modified ([SWS_DM_01838]) définissent le positionnement temporel (SWS Diagnostics §8.53.2.1 « Public Member Variables »).

Cycle de vie

En tant que structure C++, BulkDataMetaDataDescriptor dispose d'attributs purement publics, sans constructeurs de logique métier propres ([SWS_DM_01830]). Interprétation : la structure devrait principalement être instanciée et renseignée comme objet valeur sur la pile ou le tas par l'application de diagnostic fournissant les données, afin d'être ensuite transmise au sous-système SOVD. Question Q-4a0434afda63d047 (ouverte) La durée de vie obéit aux règles standards des objets C++ ; les membres contenus du type ara::core::String ainsi que le champ de taille facultatif ara::core::Optional<std::uint64_t> sont libérés de manière déterministe lors de la destruction de l'instance ([SWS_DM_01835]).

La structure elle-même ne possède aucun état interne ni aucune transition d'état. Dans les environnements multithreads, la lecture concurrente d'une instance n'est pas critique ; les accès en écriture aux variables publiques doivent toutefois être synchronisés de manière externe par l'application appelante, car aucun mécanisme de protection intégré n'existe.

Parcours d'utilisation

L'ordre d'appel typique pour l'utilisation du descripteur de métadonnées dans le cadre d'un transfert de masse SOVD se décompose selon les étapes suivantes :

  1. Instanciation : l'application de diagnostic crée une instance de BulkDataMetaDataDescriptor ([SWS_DM_01830]).
  2. Attribuer l'identification et la désignation : l'objet de données volumineuses est décrit via id ([SWS_DM_01831]), name ([SWS_DM_01833]) et file_name ([SWS_DM_01836]). Si nécessaire, translation_id est consigné ([SWS_DM_01834]).
  3. Renseigner le type MIME et les horodatages : le format est défini au moyen de mimetype ([SWS_DM_01832]). Les indications de date creation_date ([SWS_DM_01837]) et last_modified ([SWS_DM_01838]) devraient, en pratique, être formatées sous forme de chaînes d'horodatage conformes à ISO-8601. Question Q-fa352dc221e9452a (ouverte)
  4. Consigner les valeurs de contrôle et la taille en octets : après la génération des données utiles, la somme de contrôle est inscrite dans hash ([SWS_DM_01839]) et l'algorithme dans hash_algorithm ([SWS_DM_01840]). Si le nombre d'octets est connu au préalable, size est renseigné ([SWS_DM_01835]) ; si le champ facultatif reste vide, cela signale probablement une taille de fichier encore variable au moment de la mise à disposition. Question Q-03f717e53701c9c0 (ouverte)
  5. Transmission au sous-système SOVD : le descripteur initialisé est transmis à ara::diag afin que les clients SOVD externes puissent récupérer les métadonnées.

Scénarios d'erreur

Puisque BulkDataMetaDataDescriptor est une structure de données passive, aucun code d'erreur n'est directement renvoyé par la structure. Les erreurs apparaissent lors du traitement ultérieur par ara::diag ou par le client :

  • Discrépance de somme de contrôle : si le hachage indiqué dans hash ([SWS_DM_01839]) ne correspond pas au contenu réel ou si hash_algorithm ([SWS_DM_01840]) est inconnu, la vérification échoue auprès du client.
  • Taille en octets divergente : si le champ facultatif size ([SWS_DM_01835]) est défini et diverge du nombre d'octets réellement reçu, le destinataire signale une erreur de transfert.
  • Type de média non valide : un mimetype ([SWS_DM_01832]) erroné ou vide entraîne des erreurs d'interprétation dans l'outil client.
  • Identification obligatoire manquante : si id ([SWS_DM_01831]) ou file_name ([SWS_DM_01836]) ne sont pas renseignés, l'enregistrement ne peut pas être adressé de manière univoque au sein du framework SOVD.
