But d'utilisation

ara::core::Future<T, E> représente le résultat ou l'erreur ultérieurement disponible d'un appel asynchrone. Le type d'erreur doit être ara::core::ErrorCode ; sinon, une erreur de compilation est requise. Avec Promise, ce type permet une gestion thread-safe et sans exception des valeurs et erreurs asynchrones. [SWS_CORE_00321] [SWS_CORE_10800]

Cycle de vie et propriété

La copie est interdite (=delete) ; La construction de déplacement et l'affectation de déplacement sont disponibles. Le destructeur abandonne tout état partagé. GetResult(), get() et then() invalident le Future d'origine. [SWS_CORE_00334] [SWS_CORE_00335] [SWS_CORE_00323] [SWS_CORE_00325] [SWS_CORE_00333] [SWS_CORE_00336] [SWS_CORE_00326] [SWS_CORE_00337]

Interaction avec d'autres classes

GetResult() se bloque jusqu'à ce qu'une valeur ou une erreur soit présente et renvoie un Result<T,E> non déclencheur. then() génère un Future ultérieur à partir d'une fonction via ce Result ; la surcharge avec Executor exécute la fonction dans son contexte d'exécution. [SWS_CORE_00336] [SWS_CORE_00331] [SWS_CORE_00337]

Restrictions & traitement des erreurs

Si le Promise correspondant est abandonné, GetResult() renvoie l'erreur FutureErrc::kBrokenPromise. is_ready() peut être vérifié avant le blocage ; avec true, get(), GetResult() et les appels d'attente ne bloquent pas. Les appels interdits sur des contrats à terme invalides sont considérés comme des violations. [SWS_CORE_00336] [SWS_CORE_00332] [SWS_CORE_13011]

Gestion des erreurs asynchrones

Future est le type de retour harmonisé pour les appels asynchrones qui peuvent renvoyer ou échouer. Contrairement à get(), GetResult() renvoie un Result avec une valeur ou une erreur après attente et ne déclenche pas d'exception. Utilisation avec ara::com

Pour la communication basée sur une méthode, le modèle Future/Promise active un comportement non bloquant. Pour l'arrivée d'un résultat, une attente de blocage, une suite avec then() et une interrogation via is_ready() sont disponibles ; Après un is_ready() réussi, l'accès ultérieur n'est pas bloqué. Comportement en cas d'erreur

GetResult() bloque jusqu'à ce qu'une valeur ou une erreur soit disponible et renvoie le contenu de l'état partagé sous la forme Result<T,E> ; une erreur définie par SetError() reste donc dans le chemin des résultats. Si l'état partagé a été abandonné par le Promise correspondant, GetResult() renvoie FutureErrc::kBrokenPromise à la place. En revanche, get() transporte une erreur dans l'état partagé comme exception ; si Future n'est pas valide, kNoState y est inclus. [SWS_CORE_00336] [SWS_CORE_00326] [SWS_CORE_00400]

wait_for() attend au plus la durée transmise, wait_until() au plus jusqu'à l'échéance. Les deux renvoient un FutureStatus ; kTimeout signifie exclusivement que le Shared State n'est pas devenu prêt dans le délai concerné. Un timeout doit donc être distingué d'une erreur transportée dans le résultat. [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00361]

L’erreur est lue sous forme de Result depuis l’état partagé ; le champ alternatif indique l’erreur résultant de l’abandon de Promise ainsi que le timeout d’attente distinct de celle-ci. Sources : [SWS_CORE_00336] [SWS_CORE_00329] [SWS_CORE_00330].

then() transmet à sa continuation exactement le Result que GetResult() fournirait pour ce Future ; la continuation peut ainsi évaluer l’erreur et la transmettre comme Result ou comme Future consécutif. Après then(), le Future d’origine n’est plus valide. Une Exception s’échappant de la continuation est spécifiée comme une Violation ; pour propager une erreur, elle doit être traduite en erreur. [SWS_CORE_00337] [SWS_CORE_00331]

template <typename F> auto then (F &&func) noexcept -> Future< <see below> >;

Create a new Future with the content returned by func when passed the Result of this Future. The callable func may be called in the context of this call or in the context of • Promise::set_result(const T&) • Promise::set_result(T&&) • Promise::SetError(E&&) • Promise::SetError(const E&) or somewhere else.

valid() ==FALSE on the original Future object immediately after it returns.

The Callable input argument func takes a Result<T,E> object as parameter. This will be the Result obtained via GetResult() from the Future instance itself, on which then(...) is being called. The Result is passed to func as an rvalue expression.

The return type of then(...) depends on the return type of func (aka continuation).

Let U be the return type of the continuation (i.e. a type equivalent to std::invoke_result_ t<std::decay_t<F>,Result<T,E>>). Return type deduction: • If U is Future<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. This is known as implicit Future unwrapping. • If U is Result<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. This is known as implicit Result unwrapping. • Otherwise it is Future<U,E> Continuations that are registered with then(...) are registered in the Future F that then (...) returns. No such continuation shall be executed after the destructor of the Future F returns. A continuation that is already being executed shall run to completion.

Note: that means that the destructor of Future might block until the currently running continuation has been completed.

The continuation shall not throw, except for the purpose of implementing a Violation.
