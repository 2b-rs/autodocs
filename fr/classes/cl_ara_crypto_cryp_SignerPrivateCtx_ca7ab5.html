Contexte

L'interface ara::crypto::cryp::SignerPrivateCtx définit le contexte pour les opérations de signature cryptographique à l'aide d'une clé privée sur l'AUTOSAR Adaptive Platform. En tant que spécialisation de CryptoContext, elle encapsule la logique algorithmique pour la création de signatures numériques sur des blocs de messages de taille arbitraire.

Parmi les principaux partenaires d'interaction de l'interface figurent :

  • Composant d'application appelant : pilote le processus de signature, transmet les données d'entrée et reçoit le résultat de la signature.
  • Objets de clé : Le contexte nécessite un accès au matériel de clé privée. Celui-ci est soit transmis directement sous forme de PrivateKey::Sptr [SWS_CRYPT_23515], soit rattaché via un emplacement de clé référencé KeySlot::Sptr [SWS_CRYPT_50036].
  • Tampons de mémoire : Les données d'entrée et les données de contexte optionnelles sont fournies sous forme de ReadOnlyMemRegion, tandis que la valeur de signature résultante est écrite dans un tampon accessible en écriture de type ReadWriteMemRegion [SWS_CRYPT_23512], [SWS_CRYPT_50040].

Cycle de vie

Les instances de contexte sont généralement gérées sous forme de pointeurs intelligents via l'alias de type fourni ara::crypto::cryp::SignerPrivateCtx::Sptr (défini comme std::shared_ptr<SignerPrivateCtx>) [SWS_CRYPT_23501]. Comme la classe fournit des méthodes d'interface purement virtuelles, la création de l'objet devrait s'effectuer via une méthode de fabrique d'un service cryptographique de niveau supérieur.

Le cycle de vie du contexte se divise en phases distinctes :

  1. Non initialisé : Immédiatement après l'instanciation, aucune clé n'est associée au contexte. Les appels directs de signature ou de démarrage sont rejetés avec une erreur dans cet état [SWS_CRYPT_23512], [SWS_CRYPT_50037].
  2. Configuré (prêt) : L'appel de SetKey() avec un PrivateKey::Sptr [SWS_CRYPT_23515] ou un KeySlot::Sptr [SWS_CRYPT_50036] rend le contexte opérationnel. À partir de cet état, il est possible soit d'exécuter une signature One-Shot via Sign(), soit d'initier un traitement en streaming.
  3. Streaming actif : Un appel de Start() [SWS_CRYPT_50037] ou de Start(context) [SWS_CRYPT_50038] place le contexte en cours de traitement. Dans cette phase, des mises à jour itératives peuvent être effectuées via Update() [SWS_CRYPT_50039].
  4. Finalisation ou interruption : La séquence de streaming en cours se termine normalement par Finish() [SWS_CRYPT_50040] ou est abandonnée prématurément via Cancel() [SWS_CRYPT_50041]. Après ces deux méthodes, le contexte demeure vraisemblablement dans l'état configuré avec la clé assignée, de sorte qu'un nouveau calcul de signature peut être directement démarré.

Toutes les méthodes d'interface sont déclarées comme noexcept, présentent le niveau de sécurité vis-à-vis des exceptions exception safe et sont conçues pour être thread-safe selon la spécification [SWS_CRYPT_50041].

Parcours d'utilisation

L'interface prend en charge deux voies d'utilisation fonctionnelles pour le calcul de signature :

1. Génération de signature basée sur le streaming : Cette voie convient aux messages volumineux ou arrivant de manière fragmentée. Avant de commencer, la taille maximale de bloc autorisée peut être déterminée via GetMaximumChunkSize() [SWS_CRYPT_50042] et la longueur de signature attendue pour un format cible particulier via GetSignatureSize() [SWS_CRYPT_29004]. Après l'assignation de la clé via SetKey() [SWS_CRYPT_23515], le calcul est initialisé par Start() [SWS_CRYPT_50037]. Ensuite, les fragments de message sont injectés séquentiellement via Update() [SWS_CRYPT_50039]. L'appel de Finish() [SWS_CRYPT_50040] finalise la génération de signature et écrit le résultat dans le tampon fourni.

Diagramme de séquence : déroulement typique de la génération de signature en streaming. Sources : [SWS_CRYPT_23515], [SWS_CRYPT_29004], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040]

2. Génération de signature Single-Call : Si le message complet est déjà présent dans une zone mémoire contiguë, il est possible d'appeler alternativement la méthode Sign() [SWS_CRYPT_23512]. Elle traite le message, le format souhaité et les données de contexte optionnelles en une seule étape atomique et écrit la signature directement dans le tampon de sortie.

<h4>Contexte</h4>
<p>L'interface <code>ara::crypto::cryp::SignerPrivateCtx</code> définit le contexte pour les opérations de signature cryptographique à l'aide d'une clé privée sur l'AUTOSAR Adaptive Platform. En tant que spécialisation de <code>CryptoContext</code>, elle encapsule la logique algorithmique pour la création de signatures numériques sur des blocs de messages de taille arbitraire.</p>
<p>Parmi les principaux partenaires d'interaction de l'interface figurent :</p>
<ul>
<li><strong>Composant d'application appelant :</strong> pilote le processus de signature, transmet les données d'entrée et reçoit le résultat de la signature.</li>
<li><strong>Objets de clé&#x202F;:</strong> Le contexte nécessite un accès au matériel de clé privée. Celui-ci est soit transmis directement sous forme de <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a>, soit rattaché via un emplacement de clé référencé <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>.</li>
<li><strong>Tampons de mémoire&#x202F;:</strong> Les données d'entrée et les données de contexte optionnelles sont fournies sous forme de <code>ReadOnlyMemRegion</code>, tandis que la valeur de signature résultante est écrite dans un tampon accessible en écriture de type <code>ReadWriteMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>.</li>
</ul>

<h4>Cycle de vie</h4>
<p>Les instances de contexte sont généralement gérées sous forme de pointeurs intelligents via l'alias de type fourni <code>ara::crypto::cryp::SignerPrivateCtx::Sptr</code> (défini comme <code>std::shared_ptr&lt;SignerPrivateCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>. Comme la classe fournit des méthodes d'interface purement virtuelles, la création de l'objet devrait s'effectuer via une méthode de fabrique d'un service cryptographique de niveau supérieur.</p>
<p>Le cycle de vie du contexte se divise en phases distinctes&#x202F;:</p>
<ol>
<li><strong>Non initialisé&#x202F;:</strong> Immédiatement après l'instanciation, aucune clé n'est associée au contexte. Les appels directs de signature ou de démarrage sont rejetés avec une erreur dans cet état <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>.</li>
<li><strong>Configuré (prêt)&#x202F;:</strong> L'appel de <code>SetKey()</code> avec un <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> ou un <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a> rend le contexte opérationnel. À partir de cet état, il est possible soit d'exécuter une signature One-Shot via <code>Sign()</code>, soit d'initier un traitement en streaming.</li>
<li><strong>Streaming actif&#x202F;:</strong> Un appel de <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a> ou de <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50038" href="../spec/record.html?id=SWS_CRYPT_50038">[SWS_CRYPT_50038]</a> place le contexte en cours de traitement. Dans cette phase, des mises à jour itératives peuvent être effectuées via <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>.</li>
<li><strong>Finalisation ou interruption&#x202F;:</strong> La séquence de streaming en cours se termine normalement par <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> ou est abandonnée prématurément via <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>. Après ces deux méthodes, le contexte demeure vraisemblablement dans l'état configuré avec la clé assignée, de sorte qu'un nouveau calcul de signature peut être directement démarré.</li>
</ol>
<p>Toutes les méthodes d'interface sont déclarées comme <code>noexcept</code>, présentent le niveau de sécurité vis-à-vis des exceptions <em>exception safe</em> et sont conçues pour être thread-safe selon la spécification <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>.</p>

<h4>Parcours d'utilisation</h4>
<p>L'interface prend en charge deux voies d'utilisation fonctionnelles pour le calcul de signature&#x202F;:</p>
<p><strong>1. Génération de signature basée sur le streaming&#x202F;:</strong> Cette voie convient aux messages volumineux ou arrivant de manière fragmentée. Avant de commencer, la taille maximale de bloc autorisée peut être déterminée via <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50042" href="../spec/record.html?id=SWS_CRYPT_50042">[SWS_CRYPT_50042]</a> et la longueur de signature attendue pour un format cible particulier via <code>GetSignatureSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_29004" href="../spec/record.html?id=SWS_CRYPT_29004">[SWS_CRYPT_29004]</a>. Après l'assignation de la clé via <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a>, le calcul est initialisé par <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>. Ensuite, les fragments de message sont injectés séquentiellement via <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>. L'appel de <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> finalise la génération de signature et écrit le résultat dans le tampon fourni.</p>
