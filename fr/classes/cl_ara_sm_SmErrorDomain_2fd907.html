Sert à la définition et à la résolution des codes d'erreur ainsi que des exceptions au sein du State Management.

La classe ara::sm::SmErrorDomain représente le domaine d'erreur spécifique au domaine du State Management et associe des codes d'erreur fonctionnels à des messages textuels lisibles ainsi qu'à des exceptions C++ ([SWS_SM_81241]). Au moment de l'exécution, elle permet, via des méthodes sûres pour les threads, l'identification du domaine ainsi que la traduction des différentes valeurs d'erreur pour la journalisation et le diagnostic. Si une erreur grave survient, une exception typée peut en outre être déclenchée via l'interface ([SWS_SM_81250]). Si les exceptions C++ sont désactivées dans la chaîne d'outils, la logique d'exception n'est pas disponible et les erreurs doivent alors être traitées uniquement sur la base des valeurs.

Contexte

La classe ara::sm::SmErrorDomain définit le domaine d'erreur spécifique pour le cluster fonctionnel du State Management sur l'Adaptive Platform ([SWS_SM_81241], SWS StateManagement §8.1.3 « Class: SmErrorDomain »). En tant que spécialisation de l'architecture générale des domaines d'erreur, elle hérite de ara::core::ErrorDomain conformément aux exigences de [SWS_CORE_90023]. Sa responsabilité centrale consiste à encapsuler sémantiquement les états d'erreur du State Management, à fournir des identifiants d'erreur standardisés et à garantir la correspondance entre les codes d'erreur numériques, les textes d'erreur et les types d'exceptions.

Les principaux partenaires d’interaction comprennent les composants internes de State Management, qui génèrent des erreurs, ainsi que les services d’application et de plateforme de niveau supérieur, qui reçoivent les erreurs via ara::core::ErrorCode. Par l’intermédiaire de l’alias de type public Errc, la classe référence l’énumération spécifique au domaine SmErrc ([SWS_SM_81245]). L’alias de type Exception renvoie en outre à la classe de base d’exception associée SmException ([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 « Type Alias: Exception »).

Cycle de vie

Les instances de ara::sm::SmErrorDomain sont créées via le constructeur par défaut sans paramètre ([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 « Default Constructor »). Le constructeur est déclaré comme noexcept et possède la classification exception safe. Dans les environnements système typiques, une instance de SmErrorDomain devrait de préférence exister sous la forme d’un objet statique ou à longue durée de vie, étant donné que les domaines d’erreur sont nécessaires à l’échelle du processus dans l’écosystème AUTOSAR Adaptive pour interpréter les codes d’erreur.

Concernant la concurrence, les fonctionnalités centrales de la classe sont spécifiées pour un fonctionnement concurrent : les méthodes Name() ([SWS_SM_81248]) et Message() ([SWS_SM_81249]) sont désignées comme thread-safe et exception safe. Plusieurs threads d’exécution peuvent ainsi interroger des informations d’erreur en parallèle sans qu’une synchronisation externe ne soit requise.

Parcours d'utilisation

Le chemin d’utilisation normal comprend l’identification du domaine d’erreur, la résolution des codes d’erreur en messages de diagnostic lisibles et, optionnellement, la transformation en une exception C++. Dans un premier temps, une application ou un composant de plateforme peut récupérer le nom du domaine via Name() ; celui-ci renvoie de manière invariable l’identifiant "Sm" ([SWS_SM_81248]).

Si une erreur se produit dans State Management, son code est transmis via Message(errorCode) ([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 « Message »). La fonction renvoie un pointeur vers la chaîne de caractères associée (const char*), ce qui permet aux systèmes de journalisation et de diagnostic d’obtenir des messages explicites. Si le sous-système appelant est conçu pour un traitement des erreurs basé sur les exceptions, il transmet l’objet d’erreur à ThrowAsException() ([SWS_SM_81250]), ce qui instancie et lève l’exception correspondant au code d’erreur.

Diagramme de séquence : séquence typique lors de la consultation des informations d’erreur et du déclenchement optionnel d’une exception. Sources : [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

Scénarios d'erreur

Les états d’erreur gérés par le domaine reposent sur le type énuméré SmErrc, qui est aliasé via Errc ([SWS_SM_81245]). Les situations d’erreur se manifestent soit sous forme de valeurs de retour basées sur ara::core::ErrorCode, soit par l’intermédiaire d’exceptions du type Exception (SmException, [SWS_SM_81246]).

Lors de l’appel de ThrowAsException(), la méthode est par conception considérée comme not exception safe, car elle lève activement l’exception associée au code d’erreur ([SWS_SM_81250]). Une précondition critique pour la disponibilité de cette méthode concerne la configuration de la chaîne d’outils : conformément à [SWS_CORE_10304], ThrowAsException() ne participe pas à la résolution de surcharge lorsque les exceptions C++ sont désactivées dans la chaîne d’outils du compilateur ([SWS_SM_81250]). Dans les configurations système sans prise en charge des exceptions, le traitement des erreurs doit par conséquent être géré strictement par le biais de codes de retour.

fonction Message [SWS_SM_81249] Upstream: RS_AP_00119, RS_AP_00159

const char * Message (CodeType errorCode) const noexcept override;

Returns the message associated with the error code.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 5c30b05c668e Provenance

La fonction membre ara::sm::SmErrorDomain::Message sert à déterminer de manière synchrone le message d'erreur textuel associé à un code d'erreur donné du domaine d'erreur du State Management [SWS_SM_81249]. Elle est déclarée dans le fichier d'en-tête ara/sm/sm_error_domain.h au sein de la portée de la classe ara::sm::SmErrorDomain et possède le statut DRAFT dans la spécification AUTOSAR_AP_SWS_StateManagement §8.1.3.2.2.1 « Message ».

L'interface possède les paramètres et valeurs de retour suivants [SWS_SM_81249] :

  • Paramètre : errorCode de type CodeType reçoit le numéro d'erreur numérique pour lequel le message textuel associé est demandé.
  • Valeur de retour : un pointeur de type const char * vers le message d'erreur associé au code d'erreur transmis.

Des garanties strictes concernant la concurrence et la gestion des exceptions s'appliquent à l'exécution : la fonction est spécifiée comme thread-safe et exception safe et déclarée avec l'identifiant noexcept [SWS_SM_81249]. Elle peut ainsi être appelée en toute sécurité depuis n'importe quel thread sans verrous de synchronisation ni blocs try-catch.

Dans le cadre de la gestion des erreurs d'AUTOSAR Adaptive, la méthode surcharge la fonction virtuelle du domaine d'erreur de base. Interprétation : la valeur de retour étant définie comme const char * sans interface d'allocation, le pointeur devrait typiquement faire référence à des littéraux de chaînes statiques qui restent valides pendant toute la durée d'exécution du processus.

          Utilisation
          

          
Le constructeur par défaut SmErrorDomain() crée de manière synchrone une instance du domaine d'erreur ara::sm::SmErrorDomain ([SWS_SM_81247]). La déclaration se trouve dans le fichier d'en-tête ara/sm/sm_error_domain.h. L'appel ne requiert aucun paramètre d'entrée et renvoie directement l'objet domaine initialisé (SWS StateManagement §8.1.3.2.1.1 « Default Constructor »).

          

          Gestion des erreurs
          

          
La fonction porte l'identifiant noexcept et est classée comme sûre vis-à-vis des exceptions (exception safe) ([SWS_SM_81247]). Lors de la création, aucun code d'erreur n'apparaît et aucune exception n'est levée.

          

          Concurrence et restrictions
          

          
La création est spécifiée comme thread-safe ([SWS_SM_81247]). Les instances peuvent donc être créées de manière concurrente dans des environnements multithreads sans nécessiter de mécanismes de synchronisation supplémentaires. Aucune condition d'ordonnancement particulière n'est requise.

          

          Interaction
          

          
L'objet créé appartient à la classe ara::sm::SmErrorDomain ([SWS_SM_81241]), qui est spécifiée conformément à [SWS_CORE_90023]. Au sein du module State Management, le domaine d'erreur interagit avec les éléments suivants :

          

            

          • Errc ([SWS_SM_81245]) et Exception ([SWS_SM_81246]) en tant que synonymes de type pour les codes d'erreur (SmErrc) et la gestion des exceptions (SmException).
            • 

          • Name() ([SWS_SM_81248]) fournit le nom de domaine "Sm".
            • 

          • Message() ([SWS_SM_81249]) traduit les codes d'erreur en descriptions textuelles.
            • 

          • ThrowAsException() ([SWS_SM_81250]) lève le code d'erreur sous forme d'exception si les exceptions C++ sont activées ([SWS_CORE_10304]).
            • 

          • GetSmDomain() ([SWS_SM_81251]) fournit alternativement une instance globale du domaine d'erreur.
            •
