Contexte

La classe ara::rds::RdsErrorDomain constitue le domaine d'erreur central pour le module Raw Data Stream (RDS) au sein de l'AUTOSAR Adaptive Platform dans la version R25-11. Elle est déclarée comme final et hérite de la classe de base ara::core::ErrorDomain. Sa tâche principale est l'identification univoque, la classification et la description textuelle des erreurs survenant dans le périmètre fonctionnel de RDS.

En tant que déclinaison spécialisée de ara::core::ErrorDomain, RdsErrorDomain relie plusieurs types et composants du système d'erreur :

  • L'énumération d'erreurs RdsErrc, qui est directement disponible dans la portée de la classe via l'alias typé Errc ([SWS_RDS_11326]).
  • Le type d'exception RdsException, qui est ancré au sein du domaine via l'alias Exception ([SWS_RDS_11327]).
  • L'objet d'erreur standard ara::core::ErrorCode, qui associe un code d'erreur concret issu de Errc à l'instance de RdsErrorDomain.
  • Le code d'application et les services de framework, qui interrogent les messages d'erreur via Name() ([SWS_RDS_11295]) et Message() ([SWS_RDS_11296]) ou transmettent les erreurs pour le traitement des exceptions.

Diagramme de contexte : relations de types et partenaires d'interaction de RdsErrorDomain. Sources : [SWS_RDS_11326], [SWS_RDS_11327], [SWS_RDS_11297]

Cycle de vie

La création d'objets de la classe RdsErrorDomain est soumise à des exigences restrictives : le constructeur par défaut est explicitement défini comme supprimé (RdsErrorDomain() = delete, [SWS_RDS_11294]). Une instanciation directe ou multiple par des applications utilisateur sur la pile ou le tas est ainsi exclue.

La mise à disposition de l'instance de domaine devrait s'effectuer en interne via un objet singleton durable ou statique, étant donné qu'une seule instance globale existe habituellement par domaine d'erreur dans le modèle d'erreur d'AUTOSAR Adaptive. La déclaration en tant que final empêche toute spécialisation par héritage.

En matière de concurrence, la classe se comporte de manière sans état. Les méthodes d'inspection Name() ([SWS_RDS_11295]) et Message() ([SWS_RDS_11296]) sont déclarées comme const noexcept. Elles ne modifient aucun état interne et permettent un accès simultané et concurrent en lecture depuis plusieurs threads sans coût de synchronisation.

Parcours d'utilisation

En fonctionnement régulier, la classe est rarement instanciée directement par le code d'application, mais sert de backend pour ara::core::ErrorCode et ara::core::Result. Un déroulement typique de gestion des erreurs se présente comme suit :

  1. Une opération au sein du module rds échoue et génère une valeur d'erreur du type énuméré Errc ([SWS_RDS_11326]).
  2. La valeur d'erreur est encapsulée conjointement avec la RdsErrorDomain dans un ara::core::ErrorCode et transmise à l'appelant.
  3. L'application vérifie l'objet d'erreur. Name() ([SWS_RDS_11295]) permet de vérifier que l'erreur provient du domaine d'erreur RDS.
  4. À des fins de diagnostic ou de journalisation, le système appelle Message() ([SWS_RDS_11296]) pour récupérer le message textuel associé au code d'erreur.
  5. Si un mécanisme d'exception est choisi, l'appel de ErrorCode::ThrowAsException() délègue à la méthode RdsErrorDomain::ThrowAsException() ([SWS_RDS_11297]), ce qui déclenche une exception de type Exception ([SWS_RDS_11327]).

Scénarios d'erreur

RdsErrorDomain sert elle-même au traitement des situations d'erreur et définit des garanties robustes pour ses interfaces :

  • Codes d'erreur : les causes spécifiques sont représentées par l'énumération RdsErrc, qui est typée en Errc ([SWS_RDS_11326]).
  • Sécurité d'exception des interrogations : les méthodes Name() ([SWS_RDS_11295]) et Message(CodeType errorCode) ([SWS_RDS_11296]) sont spécifiées noexcept. Elles garantissent qu'aucune autre exception n'est levée, même en cas de pénurie de ressources ou d'erreurs. Si un code d'erreur inconnu venait à être transmis, un texte de repli générique devrait probablement être renvoyé afin de préserver la garantie noexcept.
  • Déclenchement d'exceptions : la méthode ThrowAsException(const ara::core::ErrorCode &errorCode) est déclarée avec noexcept(false) ([SWS_RDS_11297]). Elle lève de manière déterministe une instance de RdsException ([SWS_RDS_11327]). La précondition est un objet ErrorCode valide ; aucun retour régulier n'a lieu.

Ce guide est basé sur la spécification relative au module rds pour la version R25-11 d'AUTOSAR Adaptive Platform.
