Contexte

La classe C++ <SI-Namespace>::proxy::fields::<Field> représente la contrepartie côté client d'un champ déclaré dans une interface de service. Dans l'AUTOSAR Adaptive Platform, un champ réunit les propriétés d'une valeur d'état interrogeable, d'une valeur d'état modifiable ainsi que d'un flux d'événements pour la notification des changements de valeur.

La classe interagit principalement avec la logique applicative appelante ainsi qu'avec le Communication Management sous-jacent. Selon la modélisation dans l'interface de service, la classe met à disposition différents éléments d'interface\u202f:

  • Getter\u202f: Si Field.hasGetter == TRUE est configuré dans l'interface, la méthode Get() existe pour l'interrogation asynchrone de la valeur ([SWS_CM_00112]\u202f; AUTOSAR_AP_EXP_ARAComAPI p. 10).
  • Setter\u202f: Si Field.hasSetter == TRUE est défini, la classe propose la méthode Set() pour la modification de valeur ([SWS_CM_00113]\u202f; AUTOSAR_AP_EXP_ARAComAPI p. 10).
  • Notifier\u202f: Les notifications entrantes concernant des valeurs de champ modifiées sont mises à disposition dans le cache de données local via des mécanismes de réception basés sur l'abonnement ([SWS_CM_11601], [SWS_CM_11610]).

De plus, la classe met à disposition des fonctions de surveillance pour la protection de bout en bout (E2E)\u202f: l'état de la machine à états E2E peut être récupéré séparément pour le getter ([SWS_CM_00145]), le setter ([SWS_CM_00146]) et le notifier ([SWS_CM_11612]).

Cycle de vie

La durée de vie d'une instance de <SI-Namespace>::proxy::fields::<Field> devrait être liée à la durée de vie de l'instance de proxy de service parente qui agrège le champ.

Il existe un cycle de vie de souscription explicite pour la fonctionnalité du notifier. Les états comprennent kNotSubscribed, kSubscriptionPending et kSubscribed. L'appel de Subscribe() demande la souscription en spécifiant la taille du tampon maxSampleCount ([SWS_CM_11601]). Si, lors de cet appel, le champ se trouve déjà dans les états kSubscribed ou kSubscriptionPending avec un quota inchangé, l'appel reste sans effet ([SWS_CM_11601]).

L'état actuel de la souscription peut être interrogé au moyen de GetSubscriptionState() ([SWS_CM_11604]). Les transitions d'état peuvent être surveillées en enregistrant un gestionnaire via SetSubscriptionStateChangeHandler() ([SWS_CM_00106], [SWS_CM_11607]), au choix également avec un exécuteur personnalisé ([SWS_CM_11608]). Le gestionnaire peut être supprimé via UnsetSubscriptionStateChangeHandler() ([SWS_CM_11609]).

L'arrêt des notifications s'effectue par Unsubscribe() ([SWS_CM_11602]). Si le champ n'est pas souscrit au moment de l'appel, la méthode retourne sans action ([SWS_CM_11602]). Pour les erreurs de transport sur le canal du notifier, un gestionnaire de défauts de transport peut également être enregistré ([SWS_CM_00109], [SWS_CM_00110]) et désenregistré ([SWS_CM_00126]).

Diagramme d'états\u202f: Transitions d'état de la souscription du notifier du champ de proxy. Sources\u202f: [SWS_CM_11601], [SWS_CM_11602], [SWS_CM_11604].

Parcours d'utilisation

L'interaction typique avec le champ comprend deux chemins de communication distincts\u202f:

  1. Abonnement et traitement des échantillons\u202f:
    • L'application réserve des emplacements de tampon pour les mises à jour avec Subscribe(maxSampleCount) ([SWS_CM_11601]).
    • Un callback déclenché lors de la réception de nouvelles données de champ est enregistré via SetReceiveHandler() ([SWS_CM_11605], facultativement avec un exécuteur selon [SWS_CM_11611]).
    • Dans le gestionnaire, l'application appelle GetNewSamples(f, maxNumberOfSamples) pour traiter les nouvelles valeurs dans le cache local ([SWS_CM_11610]). GetFreeSampleCount() permet d'interroger le nombre d'emplacements de cache libres restants ([SWS_CM_11603]).
    • Pour conclure, le gestionnaire est désenregistré via UnsetReceiveHandler() ([SWS_CM_11606]) et l'abonnement est résilié via Unsubscribe() ([SWS_CM_11602]).
  2. Récupération directe de valeur et modification\u202f:
    • Avec Get(), l'application demande la valeur actuelle et reçoit un ara::core::Future<FieldType> ([SWS_CM_00112]\u202f; alias de type FieldType selon [SWS_CM_11403]).
    • Avec Set(value), une nouvelle valeur est transmise au skeleton de service, ce qui est également synchronisé via un ara::core::Future<FieldType> ([SWS_CM_00113]).

Diagramme de séquence\u202f: Séquence typique de souscription, réception de notifier ainsi que d'appels Get et Set. Sources\u202f: [SWS_CM_00112], [SWS_CM_00113], [SWS_CM_11601], [SWS_CM_11605], [SWS_CM_11610], [SWS_CM_11602].

Scénarios d'erreur

Les méthodes de la classe sécurisent leur bon fonctionnement au moyen de codes d'erreur, d'exceptions et de restrictions d'accès\u202f:

  • Perturbations de communication (ComErrc::kCommunicationFailure)\u202f:\nSignalé par le binding réseau lors d'erreurs de transmission ou de perturbations de la communication sécurisée. Une sémantique de rollback s'applique à Get() ([SWS_CM_00112]). Pour Set(), aucune sémantique de rollback n'existe, car en cas de timeout de communication, l'état distant côté serveur peut demeurer incertain ([SWS_CM_00113]).
  • Violation de l'intervalle d'émission minimal (ComErrc::kMinimumSendIntervalViolationError) : Se produit lors de Get() ([SWS_CM_00112]) et Set() ([SWS_CM_00113]) si les demandes de transmission sont déclenchées plus rapidement que ce que permet l'intervalle d'émission minimal configuré (minimumSendInterval).
  • Limites de tampon (ComErrc::kMaxSampleCountNotRealizable et ComErrc::kMaxSamplesExceeded) : Subscribe() échoue lorsque le nombre d'échantillons demandé ne peut pas être fourni par le système ([SWS_CM_11601]). GetNewSamples() signale une erreur lorsque le nombre maximal d'échantillons est dépassé ([SWS_CM_11610]).
  • Violations de sécurité (InsufficientPermissionsViolation) : Déclenché par le Grant Enforcement lorsque le client ne dispose pas des droits suffisants pour exécuter Get() ([SWS_CM_00112]), Set() ([SWS_CM_00113]) ou Subscribe() ([SWS_CM_11601]).
  • Gestionnaires de rappel non valides (InvalidHandlerViolation) : Levé si un callable vide ou non valide est transmis lors de l'enregistrement via SetReceiveHandler() ([SWS_CM_11605], [SWS_CM_11611]), SetSubscriptionStateChangeHandler() ([SWS_CM_11607], [SWS_CM_11608]) ou SetTransportFaultConditionHandler() ([SWS_CM_00109], [SWS_CM_00110]).

Ce guide est basé sur les exigences de l'AUTOSAR Adaptive Platform Release R25-11.
