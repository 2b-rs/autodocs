Contexte

La classe template ara::core::Optional fournit une implémentation conforme aux normes du type de vocabulaire C++ std::optional<T> pour l'AUTOSAR Adaptive Platform. Elle sert de conteneur pour une valeur optionnelle de type value_type ([SWS_CORE_01102]), sans allouer de mémoire dynamique sur le tas. Les domaines d'application typiques dans l'environnement AUTOSAR comprennent les retours de fonction, les paramètres de configuration ou les éléments de message dont la présence ne peut être garantie à l'exécution, évitant ainsi l'utilisation de valeurs sentinelles ou de pointeurs bruts.

Cycle de vie

Un objet de ara::core::Optional se trouve à tout moment dans exactement l'un de deux états discrets : soit il ne contient aucune valeur (état vide), soit il détient une instance initialisée du type T (état occupé).

Diagramme d'états : cycle de vie et transitions d'état d'un objet ara::core::Optional. Sources : [SWS_CORE_01103], [SWS_CORE_01104], [SWS_CORE_01107], [SWS_CORE_01113], [SWS_CORE_01119], [SWS_CORE_01136]

La création dans l'état vide s'effectue via le constructeur par défaut ([SWS_CORE_01103]) ou par transmission de nullopt_t ([SWS_CORE_01104]) ; les deux sont déclarés inconditionnellement comme noexcept. Un état occupé peut être adopté directement via les constructeurs de copie et de déplacement ([SWS_CORE_01105], [SWS_CORE_01106]), par transmission directe de valeur ([SWS_CORE_01109], [SWS_CORE_01110], [SWS_CORE_01111]) ou par construction sur place au moyen de in_place_t ([SWS_CORE_01107], [SWS_CORE_01108]). Ces constructeurs sont conditionnellement sûrs vis-à-vis des exceptions (conditionally noexcept), selon que la construction du type T est elle-même garantie comme noexcept.

Les transitions d'état à l'exécution sont régies par les méthodes emplace ([SWS_CORE_01119], [SWS_CORE_01120]) pour la construction de la valeur sur place ainsi que par les opérateurs d'affectation ([SWS_CORE_01114], [SWS_CORE_01115], [SWS_CORE_01116], [SWS_CORE_01117], [SWS_CORE_01118]), dotés du ref-qualifier &. La transition de retour vers l'état vide est effectuée via reset() ([SWS_CORE_01136]) ou par l'affectation de nullopt_t ([SWS_CORE_01113]). Le recours à swap ([SWS_CORE_01121]) permet d'échanger deux instances. Le destructeur ([SWS_CORE_01112]) détruit la valeur contenue, si elle est présente, et est conditionnellement sûr vis-à-vis des exceptions conformément à std::is_nothrow_destructible<T>.

Parcours d'utilisation

Dans l'utilisation typique, les composants appelants vérifient d'abord la présence d'une valeur avant d'y accéder :

  • Vérification : la vérification s'effectue explicitement via has_value() ([SWS_CORE_01129]) ou via l'opérateur de conversion explicite operator bool() ([SWS_CORE_01128]).
  • Accès direct : si la présence d'une valeur est garantie, l'instance de T est accessible directement via operator* ([SWS_CORE_01124], [SWS_CORE_01125], [SWS_CORE_01126], [SWS_CORE_01127]) ou le déréférencement de pointeur operator-> ([SWS_CORE_01122], [SWS_CORE_01123]). De même, la fonction membre value() est disponible dans toutes les qualifications de référence et const ([SWS_CORE_01130], [SWS_CORE_01131], [SWS_CORE_01132], [SWS_CORE_01133]).
  • Valeur de repli (Fallback) : si une valeur par défaut doit être utilisée en cas d'absence de valeur, value_or() ([SWS_CORE_01134], [SWS_CORE_01135]) offre un moyen compact de renvoyer soit la valeur contenue, soit la valeur de remplacement transmise.

Scénarios d'erreur

Dans AUTOSAR, le comportement en cas d'erreur lors d'un accès non autorisé s'écarte délibérément de la norme ISO C++ :

  • Violation en cas d'accès à vide : tant value() que les opérateurs operator* et operator-> sont déclarés comme noexcept. Si *this ne contient aucune valeur (violation de précondition), une IsoStdBadOptionalAccessViolation est déclenchée ([SWS_CORE_01122], [SWS_CORE_01123], [SWS_CORE_01124], [SWS_CORE_01125], [SWS_CORE_01126], [SWS_CORE_01127], [SWS_CORE_01130], [SWS_CORE_01131], [SWS_CORE_01132], [SWS_CORE_01133]). Interprétation : étant donné que ces fonctions sont spécifiées comme noexcept, cette violation ne devrait pas être propagée comme une exception C++ interceptable dans l'environnement d'exécution AUTOSAR, mais conduit généralement à une interruption contrôlée ou à un chemin de traitement de sécurité.
  • Sécurité vis-à-vis des exceptions de value_or : les surcharges de value_or() sont explicitement spécifiées comme not exception safe ([SWS_CORE_01134], [SWS_CORE_01135]). Si la création ou la conversion de la valeur de repli échoue, des exceptions peuvent se propager vers l'extérieur.

Ce guide est basé exclusivement sur la spécification AUTOSAR pour ara::core::Optional (Release R25-11).

  <h4>Contexte</h4>
  <p>La classe template <code>ara::core::Optional</code> fournit une implémentation conforme aux normes du type de vocabulaire C++ <code>std::optional&lt;T&gt;</code> pour l'AUTOSAR Adaptive Platform. Elle sert de conteneur pour une valeur optionnelle de type <code>value_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01102" href="../spec/record.html?id=SWS_CORE_01102">[SWS_CORE_01102]</a>), sans allouer de mémoire dynamique sur le tas. Les domaines d'application typiques dans l'environnement AUTOSAR comprennent les retours de fonction, les paramètres de configuration ou les éléments de message dont la présence ne peut être garantie à l'exécution, évitant ainsi l'utilisation de valeurs sentinelles ou de pointeurs bruts.</p>

  <h4>Cycle de vie</h4>
  <p>Un objet de <code>ara::core::Optional</code> se trouve à tout moment dans exactement l'un de deux états discrets : soit il ne contient aucune valeur (état vide), soit il détient une instance initialisée du type <code>T</code> (état occupé).</p>

  <p>La création dans l'état vide s'effectue via le constructeur par défaut (<a class="spec-record-ref" data-req="SWS_CORE_01103" href="../spec/record.html?id=SWS_CORE_01103">[SWS_CORE_01103]</a>) ou par transmission de <code>nullopt_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01104" href="../spec/record.html?id=SWS_CORE_01104">[SWS_CORE_01104]</a>) ; les deux sont déclarés inconditionnellement comme <code>noexcept</code>. Un état occupé peut être adopté directement via les constructeurs de copie et de déplacement (<a class="spec-record-ref" data-req="SWS_CORE_01105" href="../spec/record.html?id=SWS_CORE_01105">[SWS_CORE_01105]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01106" href="../spec/record.html?id=SWS_CORE_01106">[SWS_CORE_01106]</a>), par transmission directe de valeur (<a class="spec-record-ref" data-req="SWS_CORE_01109" href="../spec/record.html?id=SWS_CORE_01109">[SWS_CORE_01109]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01110" href="../spec/record.html?id=SWS_CORE_01110">[SWS_CORE_01110]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01111" href="../spec/record.html?id=SWS_CORE_01111">[SWS_CORE_01111]</a>) ou par construction sur place au moyen de <code>in_place_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01107" href="../spec/record.html?id=SWS_CORE_01107">[SWS_CORE_01107]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01108" href="../spec/record.html?id=SWS_CORE_01108">[SWS_CORE_01108]</a>). Ces constructeurs sont conditionnellement sûrs vis-à-vis des exceptions (<code>conditionally noexcept</code>), selon que la construction du type <code>T</code> est elle-même garantie comme <code>noexcept</code>.</p>
  <p>Les transitions d'état à l'exécution sont régies par les méthodes <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01119" href="../spec/record.html?id=SWS_CORE_01119">[SWS_CORE_01119]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01120" href="../spec/record.html?id=SWS_CORE_01120">[SWS_CORE_01120]</a>) pour la construction de la valeur sur place ainsi que par les opérateurs d'affectation (<a class="spec-record-ref" data-req="SWS_CORE_01114" href="../spec/record.html?id=SWS_CORE_01114">[SWS_CORE_01114]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01115" href="../spec/record.html?id=SWS_CORE_01115">[SWS_CORE_01115]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01116" href="../spec/record.html?id=SWS_CORE_01116">[SWS_CORE_01116]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01117" href="../spec/record.html?id=SWS_CORE_01117">[SWS_CORE_01117]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01118" href="../spec/record.html?id=SWS_CORE_01118">[SWS_CORE_01118]</a>), dotés du ref-qualifier <code>&amp;</code>. La transition de retour vers l'état vide est effectuée via <code>reset()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01136" href="../spec/record.html?id=SWS_CORE_01136">[SWS_CORE_01136]</a>) ou par l'affectation de <code>nullopt_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01113" href="../spec/record.html?id=SWS_CORE_01113">[SWS_CORE_01113]</a>). Le recours à <code>swap</code> (<a class="spec-record-ref" data-req="SWS_CORE_01121" href="../spec/record.html?id=SWS_CORE_01121">[SWS_CORE_01121]</a>) permet d'échanger deux instances. Le destructeur (<a class="spec-record-ref" data-req="SWS_CORE_01112" href="../spec/record.html?id=SWS_CORE_01112">[SWS_CORE_01112]</a>) détruit la valeur contenue, si elle est présente, et est conditionnellement sûr vis-à-vis des exceptions conformément à <code>std::is_nothrow_destructible&lt;T&gt;</code>.</p>

  <h4>Parcours d'utilisation</h4>
  <p>Dans l'utilisation typique, les composants appelants vérifient d'abord la présence d'une valeur avant d'y accéder :</p>
  <ul>
    <li><strong>Vérification :</strong> la vérification s'effectue explicitement via <code>has_value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01129" href="../spec/record.html?id=SWS_CORE_01129">[SWS_CORE_01129]</a>) ou via l'opérateur de conversion explicite <code>operator bool()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01128" href="../spec/record.html?id=SWS_CORE_01128">[SWS_CORE_01128]</a>).</li>
    <li><strong>Accès direct :</strong> si la présence d'une valeur est garantie, l'instance de <code>T</code> est accessible directement via <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>) ou le déréférencement de pointeur <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>). De même, la fonction membre <code>value()</code> est disponible dans toutes les qualifications de référence et const (<a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>).</li>
    <li><strong>Valeur de repli (Fallback) :</strong> si une valeur par défaut doit être utilisée en cas d'absence de valeur, <code>value_or()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>) offre un moyen compact de renvoyer soit la valeur contenue, soit la valeur de remplacement transmise.</li>
  </ul>

  <h4>Scénarios d'erreur</h4>
  <p>Dans AUTOSAR, le comportement en cas d'erreur lors d'un accès non autorisé s'écarte délibérément de la norme ISO C++ :</p>
  <ul>
    <li><strong>Violation en cas d'accès à vide :</strong> tant <code>value()</code> que les opérateurs <code>operator*</code> et <code>operator-&gt;</code> sont déclarés comme <code>noexcept</code>. Si <code>*this</code> ne contient aucune valeur (violation de précondition), une <code>IsoStdBadOptionalAccessViolation</code> est déclenchée (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>). Interprétation : étant donné que ces fonctions sont spécifiées comme <code>noexcept</code>, cette violation ne devrait pas être propagée comme une exception C++ interceptable dans l'environnement d'exécution AUTOSAR, mais conduit généralement à une interruption contrôlée ou à un chemin de traitement de sécurité.</li>
    <li><strong>Sécurité vis-à-vis des exceptions de <code>value_or</code> :</strong> les surcharges de <code>value_or()</code> sont explicitement spécifiées comme <em>not exception safe</em> (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>). Si la création ou la conversion de la valeur de repli échoue, des exceptions peuvent se propager vers l'extérieur.</li>
  </ul>
