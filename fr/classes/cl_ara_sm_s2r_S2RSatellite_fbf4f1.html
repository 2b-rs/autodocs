Contexte

La classe abstraite ara::sm::s2r::S2RSatellite [SWS_SM_81002] constitue l'interface permettant aux Adaptive Applications de recevoir des notifications concernant la transition vers un état « préparé pour Suspend-to-RAM » ainsi que la sortie de cet état AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 « Interfaces for Suspend-to-Ram Notifications ». Elle sert de contrepartie au composant S2RHub, qui coordonne la communication avec tous les satellites enregistrés sur l'ensemble des instances AUTOSAR_AP_SWS_StateManagement §7.5.1 « S2R Hub ».

Les tâches typiques d'une application lors de l'entrée dans cet état comprennent la sauvegarde persistante de données, l'arrêt des services proposés ou l'interruption des activités de sécurité avant que le système d'exploitation n'effectue la suspension AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 « Interfaces for Suspend-to-Ram Notifications ». La communication entre S2RHub et les satellites est sécurisée via Identity and Access Management (IAM), de sorte que seuls les processus satellites autorisés sont enregistrés [SWS_SM_00715].

Diagramme de contexte : interaction entre S2RHub, S2RSatellite au sein d'une Adaptive Application et le système d'exploitation. Sources : AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 « Interfaces for Suspend-to-Ram Notifications », AUTOSAR_AP_SWS_StateManagement §7.5.1 « S2R Hub », [SWS_SM_00715].

Cycle de vie

Une instance de S2RSatellite peut être créée soit via le point d'entrée statique Create(), qui établit une connexion directe avec le S2RHub sur la même machine [SWS_SM_81014], soit via le constructeur paramétré avec un ara::core::InstanceSpecifier [SWS_SM_81003]. Le constructeur par défaut est supprimé [SWS_SM_81004]. Comme S2RSatellite est une classe abstraite, une sous-classe spécifique à l'application est instanciée, qui implémente les méthodes de rappel purement virtuelles.

Les opérations de copie sont explicitement interdites [SWS_SM_81007] [SWS_SM_81009]. Un objet peut toutefois être déplacé au moyen de la sémantique de déplacement (move) [SWS_SM_81006] [SWS_SM_81008]. Après l'instanciation, l'objet se trouve dans l'état non enregistré. En appelant Offer(), le satellite s'enregistre activement auprès du S2RHub et active la réception des appels de gestionnaires [SWS_SM_81012] [SWS_SM_00710]. L'état reste actif jusqu'à ce que StopOffer() annule l'enregistrement et désactive les appels [SWS_SM_81013] [SWS_SM_00713]. La libération des ressources s'effectue via le destructeur virtuel ~S2RSatellite() [SWS_SM_81005].

En ce qui concerne la concurrence, les méthodes de création ainsi que les opérations de déplacement sont spécifiées comme étant sûres au niveau des threads, tandis que Offer(), StopOffer(), le destructeur ainsi que les gestionnaires EnterSuspendMode() et LeaveSuspendMode() sont désignés comme non sûrs au niveau des threads [SWS_SM_81003] [SWS_SM_81005] [SWS_SM_81010] [SWS_SM_81011] [SWS_SM_81012] [SWS_SM_81013] [SWS_SM_81014].

Diagramme d'états : cycle de vie et phases d'enregistrement d'un objet S2RSatellite. Sources : [SWS_SM_81003], [SWS_SM_81005], [SWS_SM_81012], [SWS_SM_81013], [SWS_SM_00710].

Parcours d'utilisation

Le déroulement normal se divise en initialisation, enregistrement, traitement de Suspend/Resume et désenregistrement :

  1. Création : l'application crée une instance de sa classe dérivée, par exemple via S2RSatellite::Create() [SWS_SM_81014] ou via le constructeur avec InstanceSpecifier [SWS_SM_81003].
  2. Enregistrement (Offer) : l'application appelle Offer() sur [SWS_SM_81012]. Le satellite est ainsi enregistré auprès du S2RHub [SWS_SM_00710].
  3. Déclencheur Suspend : si le S2RHub déclenche la transition via RequestToEnterSuspendMode [SWS_SM_00701], l'environnement d'exécution appelle EnterSuspendMode() sur le satellite [SWS_SM_00711]. L'application effectue des préparatifs et signale l'achèvement de manière asynchrone via un ara::core::Future<void> [SWS_SM_81010].
  4. Déclencheur Resume : lors de la sortie de l'état Suspend, le S2RHub provoque via RequestToLeaveSuspendMode l'appel de LeaveSuspendMode() [SWS_SM_00703] [SWS_SM_00711]. L'application rétablit son fonctionnement normal et clôture le Future résultant [SWS_SM_81011].
  5. Désenregistrement (StopOffer) : avant l'arrêt de l'application, StopOffer() est appelé afin de bloquer les appels de gestionnaires et de désinscrire l'instance auprès du hub [SWS_SM_81013] [SWS_SM_00713].

Diagramme de séquence : interaction entre l'Adaptive Application, le S2RSatellite et le S2RHub pendant le cycle Suspend-to-RAM. Sources : [SWS_SM_00701], [SWS_SM_00703], [SWS_SM_00710], [SWS_SM_00711], [SWS_SM_81010], [SWS_SM_81011], [SWS_SM_81012], [SWS_SM_81013].

Scénarios d'erreur

En cas d'erreur, les méthodes signalent des codes d'erreur issus du domaine d'erreur SmErrc ou déclenchent des violations architecturales :

  • SmErrc::kAuthenticationRequired : est renvoyé par Create() lorsque le commutateur « Force IAM switch » est activé et qu'une authentification IAM est requise [SWS_SM_00716] [SWS_SM_81014]. Dans ce cas, le constructeur S2RSatellite(const ara::core::InstanceSpecifier&) doit être utilisé à la place [SWS_SM_81014].
  • SmErrc::kOfferFailed : se produit lors de l'appel de Offer() lorsque la communication avec le démon de State Management échoue [SWS_SM_81012].
  • SmErrc::kRejected : est signalé par l'application via le Future renvoyé en cas de difficultés lors de l'entrée dans le mode Suspend ([SWS_SM_81010]) ou lors de la sortie du mode Suspend ([SWS_SM_81011]). Une rétroaction négative lors de LeaveSuspendMode conduit au niveau du S2RHub au résultat global kAtLeastOneHadIssuesToLeave [SWS_SM_00707].
  • Violations de modèle et de contexte : lors de l'appel du constructeur avec InstanceSpecifier, des vérifications d'intégrité sont effectuées. Si celles-ci échouent, des violations spécifiques sont déclenchées, parmi lesquelles AraNotInitializedViolation, InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation, ProcessMappingViolation ainsi que InstanceSpecifierAlreadyInUseViolation [SWS_SM_81003].

Ce guide est basé exclusivement sur la spécification AUTOSAR pour le State Management dans la Release R25-11.
