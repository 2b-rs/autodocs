classe ara::exec::ExecutionClient

[SWS_EM_02001] Upstream: RS_EM_00103, RS_AP_00154, RS_AP_00150

The ara::exec::ExecutionClient API provides the functionality for a Process to report its Execution State to the Execution Management.

Contexte

La classe ara::exec::ExecutionClient permet à un processus au sein de l'AUTOSAR Adaptive Platform de signaler son état d'exécution interne (Execution State) à l'Execution Management [SWS_EM_02003]. De plus, l'instance prend en charge le traitement du signal du système d'exploitation SIGTERM [SWS_EM_02002]. Les partenaires d'interaction comprennent l'application elle-même, l'Execution Management en tant qu'entité de contrôle réceptrice, ainsi que le système d'exploitation, qui transmet les signaux de terminaison.

Diagramme de contexte : partenaires d'interaction et relations de communication d'ara::exec::ExecutionClient. Sources : [SWS_EM_02003], [SWS_EM_02562], [SWS_EM_02002]

Cycle de vie

Deux méthodes de construction sont disponibles pour l'instanciation de ara::exec::ExecutionClient :

  • Le constructeur nommé Create [SWS_EM_02562] crée un ara::core::Result<ExecutionClient>, est déclaré comme noexcept, sûr vis-à-vis des exceptions (exception safe) et sûr vis-à-vis des threads (thread-safe).
  • Le constructeur standard [SWS_EM_02560] est déclaré sûr vis-à-vis des threads, mais non sûr vis-à-vis des exceptions (noexcept(false)).

Les deux constructeurs exigent la transmission d'un callback terminationHandler de type std::function<void()> [SWS_EM_02562], [SWS_EM_02560]. Ce callback est exécuté dans un thread d'arrière-plan dès qu'un signal SIGTERM est reçu. Le terminationHandler doit rester appelable pendant toute la durée de vie de l'instance de ExecutionClient [SWS_EM_02562], [SWS_EM_02560].

En ce qui concerne les relations de propriété, la classe empêche la copie : le constructeur de copie [SWS_EM_02563] ainsi que l'opérateur d'assignation par copie [SWS_EM_02564] sont explicitement supprimés (=delete). Un transfert de propriété est exclusivement possible via la sémantique de déplacement : le constructeur de déplacement [SWS_EM_02580] et l'opérateur d'assignation par déplacement [SWS_EM_02581] sont présents, spécifiés comme noexcept et sûrs vis-à-vis des exceptions, mais ne sont pas sûrs vis-à-vis des threads.

Lors de la destruction via le destructeur [SWS_EM_02002], qui est également noexcept et non sûr vis-à-vis des threads, le gestionnaire SIGTERM est réinitialisé à son état d'origine.

Parcours d'utilisation

Un flux d'utilisation typique comprend les étapes suivantes :

  1. Création : L'application initialise le client via Create en spécifiant un callback pour une terminaison contrôlée [SWS_EM_02562].
  2. Notification d'état : Après avoir achevé l'initialisation interne, le processus signale son état à l'Execution Management via ReportExecutionState [SWS_EM_02003]. La méthode est sûre vis-à-vis des threads et sûre vis-à-vis des exceptions.
  3. Traitement des signaux : Si un signal SIGTERM arrive pendant l'exécution, ExecutionClient appelle le terminationHandler enregistré dans un thread d'arrière-plan distinct, par exemple pour définir des drapeaux globaux et réveiller les threads bloqués [SWS_EM_02562].
  4. Destruction : En quittant le cycle de vie, le destructeur restaure le gestionnaire de signaux d'origine [SWS_EM_02002].

Diagramme de séquence : flux d'appels et de signaux entre l'application, ExecutionClient et l'Execution Management. Sources : [SWS_EM_02562], [SWS_EM_02003], [SWS_EM_02002]

Scénarios d'erreur

Les méthodes de ExecutionClient signalent les états d'erreur via le type de retour ara::core::Result ou les codes d'erreur correspondants du domaine ara::exec::ExecErrc :

Code d'erreur Opérations concernées Signification et récupération
ara::exec::ExecErrc::kInvalidArgument Create [SWS_EM_02562], constructeur [SWS_EM_02560] Le terminationHandler transmis ne contient aucune fonction appelable. Sémantique de rollback. Récupération : répéter l'appel avec un callback valide.
ara::exec::ExecErrc::kNoCommunication Create [SWS_EM_02562], constructeur [SWS_EM_02560], ReportExecutionState [SWS_EM_02003] Erreur de communication lors de la connexion à l'Execution Management, par exemple accusé de réception manquant pour la notification. Aucune sémantique de rollback. Récupération : exécuter à nouveau l'appel (« try again »).
ara::exec::ExecErrc::kInvalidTransition ReportExecutionState [SWS_EM_02003] Transition d'état non autorisée (par exemple notification de kRunning lorsque le processus est déjà dans cet état). Sémantique de rollback. Récupération : aucune nouvelle notification requise.
