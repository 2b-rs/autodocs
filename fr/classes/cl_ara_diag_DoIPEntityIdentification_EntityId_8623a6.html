Capsule l'identifiant d'entité (EID) de six octets pour l'identification de véhicule DoIP selon l'ISO 13400-2.

La structure ara::diag::DoIPEntityIdentification::EntityId sert de conteneur de données pour l'identifiant d'entité (EID) de six octets d'une instance DoIP selon l'ISO 13400-2 ([SWS_DM_01496]). En cas de configuration correspondante, le Diagnostic Manager récupère cet identifiant auprès de l'application adaptative via la méthode ara::diag::DoIPEntityIdentification::GetEntityId afin de l'intégrer dans les messages de protocole DoIP tels que l'annonce de véhicule ([SWS_DM_01361]). Si l'interface n'est pas encore disponible ou si la récupération échoue, un repli sur la valeur de substitution fixe composée exclusivement d'octets de valeur 0xFF intervient comme contrainte obligatoire ([SWS_DM_01528]).

Contexte

La structure de données ara::diag::DoIPEntityIdentification::EntityId sert à la représentation de l'identifiant d'entité normalisé (Entity Identification, EID) pour la communication de diagnostic sur le protocole Internet (DoIP) selon l'ISO 13400-2 ([SWS_DM_01496], AUTOSAR_AP_SWS_Diagnostics §8.33 « Header: ara/diag/doip_entity_identification.h »). Au sein de l'Adaptive Platform AUTOSAR, elle est définie en tant que type de structure publique au sein de la classe d'API ara::diag::DoIPEntityIdentification ([SWS_DM_01362], [SWS_DM_01496]).

Sa responsabilité principale consiste à encapsuler la valeur d'identification d'exactement six octets d'une entité DoIP ([SWS_DM_01496]). Trois acteurs principaux interagissent au sein de l'architecture de plateforme : premièrement, l'application adaptative, qui gère l'identifiant d'entité ou le lit depuis le matériel. Deuxièmement, la classe d'interface ara::diag::DoIPEntityIdentification, qui propose la méthode de fourniture de l'identifiant ([SWS_DM_01362]). Troisièmement, le Diagnostic Manager (DM), qui récupère l'EID dans le cadre de l'identification de véhicule pour les messages DoIP sortants ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 « Providing EID in DoIP protocol messages using Application Interface »).

Diagramme de contexte : intégration d'EntityId entre le Diagnostic Manager, la classe d'interface et l'application adaptative. Sources : [SWS_DM_01361], [SWS_DM_01496].

Cycle de vie

En tant que structure de données avec l'unique membre entityIdentification de type ara::core::Array<std::uint8_t, 6>, EntityId présente les propriétés d'un objet valeur C++ léger ([SWS_DM_01496]). Interprétation : en l'absence d'allocation dynamique de ressources, la structure devrait supporter par défaut les opérations régulières de copie et de déplacement, et ne devrait être soumise à aucune transition d'état interne complexe.

L'instanciation de EntityId est effectuée par l'application adaptative dès que le Diagnostic Manager interroge les données d'identité via l'appel de ara::diag::DoIPEntityIdentification::GetEntityId ([SWS_DM_01361]). La durée de vie d'une instance est typiquement liée au cycle de retour et de traitement de l'appel de méthode. Alors que la classe de service englobante ara::diag::DoIPEntityIdentification dispose de constructeurs ([SWS_DM_01364], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.2.1 « DoIPEntityIdentification ») et de destructeurs ([SWS_DM_01365], AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.1.1 « Destructor ») explicites, l'objet valeur EntityId est automatiquement libéré lors de la sortie de portée après lecture des données de champ par le Diagnostic Manager.

Parcours d'utilisation

L'utilisation normale de EntityId suit une séquence définie dans le déroulement du protocole de diagnostic :

  • Vérification de la configuration : le Diagnostic Manager vérifie l'attribut DoIpNetworkConfiguration.eidRetrieval. Si DoIpEidRetrievalEnum.eidUseApi y est configuré, le DM doit obligatoirement récupérer l'identifiant via l'API ([SWS_DM_01361]).
  • Récupération par l'API : le Diagnostic Manager appelle la méthode ara::diag::DoIPEntityIdentification::GetEntityId ([SWS_DM_01361]).
  • Fourniture des données : l'application crée une instance de EntityId, remplit le membre entityIdentification avec l'identifiant de 6 octets selon l'ISO 13400-2 ([SWS_DM_01496]) et transmet la structure.
  • Utilisation dans le protocole : le Diagnostic Manager extrait l'identifiant et l'insère dans les messages DoIP tels que le message d'annonce de véhicule (Vehicle Announcement Message) ([SWS_DM_01361], AUTOSAR_AP_SWS_Diagnostics §8.33 « Providing EID in DoIP protocol messages using Application Interface »).

Diagramme de séquence : déroulement lors de la récupération et du traitement ultérieur d'EntityId, y compris le repli en cas d'erreur. Sources : [SWS_DM_01361], [SWS_DM_01496], [SWS_DM_01528].

Scénarios d'erreur

Un scénario d'erreur central se produit lorsque l'interface ara::diag::DoIPEntityIdentification n'est pas encore proposée par l'application adaptative au moment de l'interrogation requis ou que la récupération via GetEntityId échoue ([SWS_DM_01528], AUTOSAR_AP_SWS_Diagnostics §8.33 « Providing EID in DoIP protocol messages using Application Interface »).

Afin de ne pas bloquer durablement l'envoi des messages DoIP, la spécification prescrit dans ce cas un comportement de valeur de substitution obligatoire : le Diagnostic Manager doit transmettre, à la place des données applicatives régulières, un champ EID de 6 octets avec la valeur fixe 0xFF 0xFF 0xFF 0xFF 0xFF 0xFF ([SWS_DM_01528]). Au niveau des types, le tableau fixe ara::core::Array<std::uint8_t, 6> exclut les erreurs de longueur et les dépassements de tampon au moment de la compilation ([SWS_DM_01496]).
