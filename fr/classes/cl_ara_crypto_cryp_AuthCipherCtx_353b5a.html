Contexte

L’interface ara::crypto::cryp::AuthCipherCtx définit le contexte des opérations cryptographiques avec chiffrement authentifié (Authenticated Encryption with Associated Data, AEAD). Elle combine la confidentialité des données utiles avec le contrôle d’intégrité et l’authenticité via un tag d’authentification cryptographique (Authentication Tag) ainsi que des données associées optionnelles (Additional Authenticated Data, AAD). Les instances sont généralement gérées via l’alias de pointeur intelligent AuthCipherCtx::Sptr [SWS_CRYPT_20101].

Les partenaires d’interaction sont, d’une part, l’application utilisatrice qui chiffre et déchiffre des flux de données ou des blocs individuels, et, d’autre part, la gestion des clés : le contexte opère soit directement sur une instance de clé de type SymmetricKey [SWS_CRYPT_23911], soit référence un emplacement de stockage persistant ou géré via KeySlot [SWS_CRYPT_50072]. Sur le plan fonctionnel, l’interface prend en charge aussi bien le streaming pas à pas que les appels uniques atomiques (single-call).

Cycle de vie

De sa création à sa réutilisation, le contexte traverse des phases clairement définies :

  • Non initialisé (Uninitialized) : après l’instanciation, le contexte n’est pas encore prêt à l’emploi. Une clé doit impérativement être assignée avant le traitement des données. Sinon, les appels de transformation ou d’initialisation sont rejetés avec CryptoErrc::kUninitializedContext [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Configuré (Configured / Key Set) : l’assignation de la clé s’effectue via SetKey() avec un SymmetricKey [SWS_CRYPT_23911] ou un KeySlot [SWS_CRYPT_50072]. Dans cet état, des paramètres statiques tels que les tailles de tag et d’IV peuvent être interrogés. Cet état est déjà suffisant pour les opérations en appel unique (single-call).
  • Streaming actif (Processing) : par l’appel de Start() — au choix avec un vecteur d’initialisation (IV) explicite [SWS_CRYPT_24715] ou sans, respectivement avec l’IV propre au contexte [SWS_CRYPT_50073] —, le contexte passe dans la phase active de streaming pour une direction de transformation (CryptoTransform). Des données additionnelles et des données utiles peuvent y être traitées successivement.
  • Finalisation et retour : le traitement est finalisé de manière standard par Finish() [SWS_CRYPT_50075] ou FinishEncrypt() [SWS_CRYPT_50076]. Une interruption prématurée d’un flux en cours est possible à tout moment via Cancel() [SWS_CRYPT_50077]. Après la fin ou l’interruption, le contexte reste vraisemblablement dans l’état configuré et se tient prêt pour une nouvelle initialisation via Start().

Parcours d'utilisation

Deux voies sont disponibles pour le traitement : le traitement en streaming pour les données plus volumineuses ou fragmentées et les opérations atomiques en appel unique (single-call).

La séquence typique de streaming se déroule comme suit :

  1. Configuration : lier la clé via SetKey() [SWS_CRYPT_23911]. Des limites peuvent être déterminées au préalable, telles que les tailles minimales/maximales de blocs [SWS_CRYPT_50162], [SWS_CRYPT_50082], la taille du tag [SWS_CRYPT_50161] ainsi que les longueurs d’IV [SWS_CRYPT_50163], [SWS_CRYPT_50164], [SWS_CRYPT_50165].
  2. Démarrage : initialisation de l’opération par Start() en indiquant la direction de transformation (chiffrement ou déchiffrement) et le cas échéant l’IV [SWS_CRYPT_24715], [SWS_CRYPT_50073].
  3. Données associées (optionnel) : si des métadonnées supplémentaires en texte clair doivent être authentifiées, celles-ci doivent être transmises via UpdateAuthenticatedData() [SWS_CRYPT_20313]. Cela doit impérativement avoir lieu avant toute donnée utile confidentielle. La taille maximale peut être vérifiée via GetMaxAssociatedDataSize() [SWS_CRYPT_20103].
  4. Données utiles confidentielles : transmission pas à pas de blocs de données au moyen de UpdateConfidentialData() [SWS_CRYPT_50074]. Les tailles requises de tampon de sortie peuvent être calculées dynamiquement via GetRequiredOutputBufferSize() [SWS_CRYPT_50081].
  5. Finalisation : appel de Finish() [SWS_CRYPT_50075] ou FinishEncrypt() [SWS_CRYPT_50076]. Les données restantes sont alors transformées, le tag d’authentification est finalisé (généré lors du chiffrement, vérifié lors du déchiffrement) et, si nécessaire, l’IV généré est retourné.

Pour les données compactes disponibles en une seule étape, ProcessSingleCall() [SWS_CRYPT_50078], ProcessSingleCallWithInputIv() [SWS_CRYPT_50079] et EncryptSingleCallWithOutputIv() [SWS_CRYPT_50080] offrent un traitement à état réduit sans Start() préalable.

Diagramme de séquence : déroulement pas à pas du streaming d’une transformation authentifiée avec AuthCipherCtx. Sources : [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075].

Scénarios d'erreur

Les méthodes garantissent le respect de la séquence de protocole et la sécurité cryptographique via des codes d’erreur spécifiques :

  • Violation de l’ordre des données additionnelles : si UpdateAuthenticatedData() est appelé après que des données confidentielles ont déjà été traitées via UpdateConfidentialData(), l’opération échoue avec CryptoErrc::kInvalidUsageOrder [SWS_CRYPT_20313].
  • Traitement sans démarrage : si UpdateAuthenticatedData(), UpdateConfidentialData(), Finish(), FinishEncrypt() ou Cancel() sont appelés sans appel préalable réussi à Start(), l’erreur CryptoErrc::kProcessingNotStarted est retournée [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50076], [SWS_CRYPT_50077].
  • Vérifications de clé et de droits : si le type de clé assigné ne correspond pas au contexte, SetKey() ou Start() renvoie l’erreur CryptoErrc::kIncompatibleObject [SWS_CRYPT_23911], [SWS_CRYPT_24715]. Si les indicateurs d’utilisation requis (kAllowDataEncrypt ou kAllowDataDecrypt) manquent à la clé, cela entraîne CryptoErrc::kUsageViolation [SWS_CRYPT_23911], [SWS_CRYPT_24715], [SWS_CRYPT_50078]. En cas d’emplacements occupés ou vides, CryptoErrc::kBusyResource ou CryptoErrc::kEmptyKeySlot est signalé [SWS_CRYPT_24715], [SWS_CRYPT_50078].
  • Erreurs de tampon et de dimensions : si le tampon de sortie fourni est trop petit pour les données transformées ou l’IV, les méthodes échouent avec CryptoErrc::kInsufficientCapacity [SWS_CRYPT_50074], [SWS_CRYPT_50075], [SWS_CRYPT_50078]. Des longueurs non valides de tampons d’entrée, de tags ou d’IV entraînent CryptoErrc::kInvalidInputSize [SWS_CRYPT_20313], [SWS_CRYPT_50074], [SWS_CRYPT_24715].
  • Échec de l’authentification : si la vérification du tag d’authentification échoue lors du déchiffrement, Finish() [SWS_CRYPT_50075] ou ProcessSingleCall() [SWS_CRYPT_50078] signalent l’erreur CryptoErrc::kAuthTagNotValid. Consigne de sécurité importante : en mode streaming, UpdateConfidentialData() restitue le texte clair déchiffré dès avant la vérification du tag ; l’application ne doit réutiliser ou libérer ces données qu’après un Finish() réussi [SWS_CRYPT_50074].

Ce guide est basé sur les exigences de spécification pour l’AUTOSAR Adaptive Platform Release R25-11 et résume les exigences relatives à la classe ara::crypto::cryp::AuthCipherCtx.
