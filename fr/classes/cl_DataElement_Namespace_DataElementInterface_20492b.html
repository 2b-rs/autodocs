Contexte

La classe d'interface <DataElement-Namespace>::<DataElementInterface> fait partie du cluster fonctionnel Diagnostics (diag) de l'AUTOSAR Adaptive Platform (AUTOSAR_AP_SWS_Diagnostics p. 68). Elle sert de classe de base spécifique au type pour fournir des données de diagnostic dans le rôle de lecture (Read DataElement) conformément à [SWS_DM_00596].

Au sein de l'architecture de diagnostic, la classe interagit avec deux partenaires principaux :

  • Diagnostic Management (DM) : Le serveur de diagnostic central achemine les requêtes de diagnostic entrantes (par exemple des services UDS tels que ReadDataByIdentifier) vers les gestionnaires enregistrés ([SWS_DM_00597]).
  • Application adaptative : L'application concrète dérive de <DataElementInterface>, implémente la méthode purement virtuelle Read() ([SWS_DM_00596]) et renvoie les données de capteurs, les valeurs d'état ou les paramètres requis.
  • Modélisation de manifeste et d'instance : L'objet est lié à un port configuré dans le modèle via un ara::core::InstanceSpecifier ([SWS_DM_00587]).

Cycle de vie

Le cycle de vie d'une instance de <DataElement-Namespace>::<DataElementInterface> est contrôlé par la création, la fourniture explicite du service et la destruction :

  • Création : L'instanciation s'effectue via le constructeur en indiquant le ara::core::InstanceSpecifier et le mode de concurrence ara::diag::ConcurrencyType ([SWS_DM_00587]). Celui-ci détermine si l'implémentation doit fonctionner de manière thread-safe (kConcurrent) ou non thread-safe (kNotConcurrent). Le constructeur lui-même est thread-safe et sûr vis-à-vis des exceptions (noexcept).
  • Sémantique et propriété : Les instances de la classe ne doivent être ni copiées ni déplacées. Le constructeur de copie ([SWS_DM_01661]), le constructeur de déplacement ([SWS_DM_01662]) ainsi que les opérateurs d'affectation correspondants ([SWS_DM_01659], [SWS_DM_01660]) sont explicitement supprimés (= delete). L'identité et l'adresse mémoire restent liées pendant toute la durée de vie.
  • Mise à disposition (Offer) : Après la construction, l'objet se trouve à l'état inactif. L'appel de Offer() active l'acheminement des requêtes par le Diagnostic Management ([SWS_DM_00597]).
  • Retrait (StopOffer) : L'acheminement par le DM est désactivé via StopOffer() ([SWS_DM_00617]).
  • Destruction : Le destructeur virtuel ~<DataElementInterface>() termine le cycle de vie ([SWS_DM_00588]). Avant la libération, l'application devrait typiquement appeler StopOffer() afin de terminer de manière ordonnée les accès en attente.

En ce qui concerne la concurrence, les méthodes Offer(), StopOffer() et le destructeur sont spécifiés comme non thread-safe ([SWS_DM_00597], [SWS_DM_00617], [SWS_DM_00588]), raison pour laquelle les appels de méthodes administratifs simultanés sur la même instance doivent être synchronisés.

Parcours d'utilisation

Un déroulement d'utilisation normal s'articule en les phases suivantes :

  1. Dérivation et instanciation : L'application implémente une classe dérivée et redéfinit la fonction purement virtuelle Read() ([SWS_DM_00596]). Au démarrage, l'instance est créée avec le InstanceSpecifier correspondant ([SWS_DM_00587]).
  2. Activation : L'application appelle Offer(), ce qui enregistre le gestionnaire auprès du DM ([SWS_DM_00597]).
  3. Traitement de la requête : Dès qu'une requête de diagnostic arrive, le DM appelle la méthode Read(metaInfo, cancellationHandler) ([SWS_DM_00596]).
    • Le gestionnaire reçoit des métadonnées sur la requête via metaInfo.
    • Via cancellationHandler, le gestionnaire peut vérifier périodiquement avec IsCanceled() si la conversation de diagnostic en cours a été interrompue, ou enregistrer une fonction de notification via SetNotifier() ([SWS_DM_00596]).
  4. Retour du résultat : L'appel renvoie un ara::core::Future, qui est résolu avec la structure de sortie en cas de succès ([SWS_DM_00596], [SWS_DM_00581]). Les données de sortie sont transmises via les arguments de sortie déclarés tels que <DataElementOutArg> ([SWS_DM_80023]).
  5. Désactivation : Avant l'arrêt ou en cas d'interruption du service, l'application appelle StopOffer() ([SWS_DM_00617]).

Diagramme de séquence : Déroulement typique de l'instanciation, de l'enregistrement, de l'accès en lecture et du désenregistrement. Sources : [SWS_DM_00587], [SWS_DM_00597], [SWS_DM_00596], [SWS_DM_00617].

Scénarios d'erreur

Des erreurs peuvent survenir lors de l'instanciation, lors de l'enregistrement ainsi que pendant l'exécution de la tâche de lecture :

  • Erreurs de construction (violations de modèle) : Le constructeur signale les incohérences de configuration et de modèle via le concept de violation du framework ([SWS_DM_00587]) :
    • InstanceSpecifierMappingIntegrityViolation : l'identifiant ne peut pas être résolu dans le contexte de l'exécutable ou ne référence aucun PortPrototype.
    • PortInterfaceMappingViolation : Le PortPrototype référencé n'est pas relié à un DiagnosticDataElementInterface par un DiagnosticDataPortMapping.
    • ProcessMappingViolation : Aucun processus modélisé correspondant n'existe au moment de l'exécution pour l'identifiant d'instance.
    • InstanceSpecifierAlreadyInUseViolation : L'identifiant est déjà utilisé par une autre instance dans le processus.
  • Erreur d'offre : Si Offer() est appelée plusieurs fois alors que le service est déjà proposé, la méthode renvoie un ara::core::Result avec le code d'erreur DiagOfferErrc::kAlreadyOffered ([SWS_DM_00597]).
  • Erreurs d'exécution et de diagnostic dans Read() : Si la fourniture de données échoue, le ara::core::Future renvoyé est renseigné avec un code d'erreur ([SWS_DM_00596]) :
    • DiagUdsNrcErrc : Un Negative Response Code applicable selon l'ISO 14229-1 (par ex. en cas de valeurs non disponibles ou non valides).
    • ApApplicationError : Un code d'erreur de diagnostic spécifique à l'application.
  • Interruption : Si cancellationHandler.IsCanceled() signale la valeur true, le traitement doit être interrompu, car le client ou le DM n'accepte plus la transaction ([SWS_DM_00596]).

Ce guide est basé sur la spécification AUTOSAR Adaptive Platform pour le module Diagnostics (R25-11).
