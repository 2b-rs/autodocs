Gère et traduit les codes d'erreur ainsi que les exceptions pour les offres de diagnostic dans le module diag.

La classe ara::diag::DiagOfferErrorDomain représente le domaine d'erreur standardisé pour les erreurs survenant lors de la mise à disposition de services de diagnostic au sein de l'AUTOSAR Adaptive Platform [SWS_DM_00989]. En tant que spécialisation de la classe de base ara::core::ErrorDomain, elle associe des messages textuels lisibles aux codes d'erreur numériques du type DiagOfferErrc et prend en charge la conversion en objets d'exception du type DiagException [SWS_DM_00994]. Toutes les fonctions membres sont implémentées de manière thread-safe, tandis que le déclenchement d'exceptions ne participe pas à la résolution de surcharge lorsque les exceptions C++ sont désactivées dans le compilateur.

Contexte

La classe ara::diag::DiagOfferErrorDomain définit le domaine d'erreur spécifique pour les états d'erreur qui surviennent en relation avec les offres de diagnostic (Diagnostic Offers) dans le module diag d'AUTOSAR Adaptive [SWS_DM_00989]. En tant que classe finale, elle spécialise la classe générale de la plateforme ara::core::ErrorDomain (AUTOSAR_AP_SWS_Diagnostics §8.11.5 « Class: DiagOfferErrorDomain »). Sa responsabilité principale consiste à représenter de manière typée les états défaillants lors de la proposition de services de diagnostic et à fournir une interface standardisée pour la description textuelle ainsi que pour le traitement des exceptions.

Au sein de l'architecture d'erreur, ara::diag::DiagOfferErrorDomain interagit étroitement avec ara::core::ErrorCode : les opérations en échec instancient des codes d'erreur qui associent la valeur d'énumération correspondante au domaine d'erreur. Pour cela, la classe fournit l'alias de type Errc, qui référence le type d'énumération DiagOfferErrc [SWS_DM_00990]. Pour le flux de contrôle tolérant aux pannes, la classe établit une liaison avec la classe d'exception de base DiagException via l'alias de type Exception [SWS_DM_00991].

Diagramme de contexte : Intégration de DiagOfferErrorDomain dans l'architecture d'erreur d'ara::diag et d'ara::core. Sources : [SWS_DM_00989], [SWS_DM_00990], [SWS_DM_00991].

Cycle de vie

La création d'une instance de ara::diag::DiagOfferErrorDomain s'effectue via le constructeur par défaut sans paramètre, qui est défini comme constexpr et noexcept [SWS_DM_00992]. Ce constructeur se trouve dans le fichier d'en-tête ara/diag/diag_error_domain.h (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.1.1 « Default Constructor »). Grâce à la spécification constexpr, l'objet de domaine peut déjà être construit au moment de la compilation. Dans les systèmes AUTOSAR, le domaine d'erreur devrait typiquement être conservé en tant qu'objet statique disponible à l'échelle du processus ou en tant que singleton, de sorte qu'aucune allocation dynamique n'est nécessaire. Question Q-faf79fde5a4b617a (ouverte)

Toutes les fonctions membres de la classe sont, sans exception, déclarées thread-safe (thread-safe) [SWS_DM_00992], [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995]. Cela permet un accès parallèle sans crainte depuis plusieurs threads. La classe étant déclarée comme final, les classes dérivées sont interdites. La destruction n'est soumise à aucune exigence particulière et s'effectue avec la libération de la mémoire statique lors de la fermeture de l'application.

Parcours d'utilisation

La classe est typiquement utilisée indirectement via ara::core::ErrorCode ou directement lors de l'évaluation des résultats d'opérations de diagnostic :

  1. Une opération lors de la proposition d'un service de diagnostic échoue, à la suite de quoi un ara::core::ErrorCode avec une valeur du type DiagOfferErrc (alias Errc) est généré [SWS_DM_00990].
  2. Pour identifier le domaine, la méthode Name() peut être appelée, laquelle renvoie l'identifiant du domaine d'erreur d'application [SWS_DM_00993] (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.2 « Name »).
  3. Afin d'obtenir un message d'erreur lisible à des fins de journalisation ou de diagnostic, Message() est appelée avec le code d'erreur ; la chaîne C renvoyée n'est, conformément à la spécification, jamais nullptr [SWS_DM_00994].
  4. Si l'architecture logicielle traite les erreurs par le biais d'exceptions, ThrowAsException() est appelée avec le ErrorCode, ce qui déclenche la levée de l'exception correspondante [SWS_DM_00995].

Diagramme de séquence : Interrogation typique de messages d'erreur et déclenchement d'exceptions via DiagOfferErrorDomain. Sources : [SWS_DM_00993], [SWS_DM_00994], [SWS_DM_00995].

Scénarios d'erreur

Le domaine lui-même ne signale aucune erreur interne, mais sert à classifier les erreurs externes lors de la mise à disposition de fonctionnalités de diagnostic. Les conditions d'erreur concrètes sont exprimées via le type d'énumération DiagOfferErrc, qui est associé de manière fixe au domaine via Errc [SWS_DM_00990]. Vraisemblablement, ces valeurs d'erreur couvrent des situations de configuration ou de conflit lors de l'enregistrement de services de diagnostic. Question Q-0d1a5bceeb45cd08 (ouverte)

La fonction membre Message() est garantie sûre vis-à-vis des exceptions (exception safe) et fournit un message textuel valide pour chaque valeur d'erreur transmise [SWS_DM_00994]. En revanche, ThrowAsException() est classée comme non sûre vis-à-vis des exceptions (not exception safe) et marquée avec noexcept(false), étant donné que sa tâche explicite constitue le déclenchement d'une exception du type de base DiagException (alias Exception) [SWS_DM_00991], [SWS_DM_00995].

Une contrainte centrale existe pour les plateformes ou configurations de compilateur sans prise en charge des exceptions : si les exceptions C++ sont désactivées dans la chaîne d'outils, la fonction ThrowAsException() ne participe pas à la résolution de surcharge [SWS_DM_00995]. Dans ce cas, l'application doit gérer le traitement des erreurs exclusivement par valeur au moyen de codes d'erreur.

Le constructeur par défaut sans paramètre [SWS_DM_00992] sert à créer une instance de la classe ara::diag::DiagOfferErrorDomain (SWS Diagnostics §8.11.5 « Class: DiagOfferErrorDomain »). Il est déclaré via le fichier d'en-tête ara/diag/diag_error_domain.h et possède la signature constexpr DiagOfferErrorDomain() noexcept; (SWS Diagnostics §8.11.5.2.1.1 « Default Constructor »). L'appel s'effectue de manière synchrone, ne traite aucun paramètre d'entrée et ne fournit aucune valeur de retour, comme c'est le cas pour un constructeur [SWS_DM_00992].

En ce qui concerne la concurrence et la sécurité face aux erreurs, la fonction est spécifiée comme thread-safe ainsi que exception safe [SWS_DM_00992]. La spécification noexcept garantit qu'aucune exception n'est levée pendant l'exécution [SWS_DM_00992]. Des codes d'erreur spécifiques ou des notifications via DET ou DEM ne sont pas prévus pour ce constructeur.

Dans le contexte du module, le domaine représente les états d'erreur liés aux services de diagnostic, dont les codes d'erreur sont définis dans l'énumération DiagOfferErrc [SWS_DM_00559] et peuvent être référencés via l'alias de type Errc [SWS_DM_00990]. La classe fournit des méthodes standard telles que Name() [SWS_DM_00993], Message() [SWS_DM_00994] et ThrowAsException() [SWS_DM_00995]. Dans les cas d'application, un appel direct du constructeur devrait être rarement requis (interprétation), car une référence globale vers l'instance est déjà disponible avec la fonction ara::diag::GetDiagOfferDomain() [SWS_DM_01003], utilisée entre autres par ara::diag::MakeErrorCode() [SWS_DM_01005].               La fonction membre ThrowAsException du domaine d'erreur ara::diag::DiagOfferErrorDomain sert, conformément à [SWS_DM_00995], à convertir un code d'erreur transmis du type ara::core::ErrorCode en une exception C++ correspondante et à la déclencher (AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.3 « ThrowAsException »).
              

  
              Concernant la sémantique et la conception de l'interface, les propriétés suivantes s'appliquent :
              
  
                
    
              • Appel et paramètres : la méthode accepte une référence constante vers une instance de ara::core::ErrorCode, ne possède pas de valeur de retour (void) et est déclarée avec noexcept(false), puisqu'elle lève une exception par définition [SWS_DM_00995].
                • 
    
              • Restriction de compilation : conformément à [SWS_CORE_10304], la fonction ne participe pas à la résolution de surcharge (Overload Resolution) lorsque les exceptions C++ sont désactivées dans la chaîne d'outils du compilateur [SWS_DM_00995].
                • 
    
              • Sécurité et concurrence : la fonction est spécifiée comme thread-safe, ce qui autorise des appels parallèles au-delà des frontières des threads ; elle est toutefois explicitement désignée comme not exception safe [SWS_DM_00995].
                • 
    
              • Interaction : le concept correspond au modèle d'erreur standardisé pour les domaines d'erreur de diagnostic, tel qu'il est également implémenté de manière analogue dans ara::diag::DiagErrorDomain [SWS_DM_00523], ara::diag::DiagReportingErrorDomain [SWS_DM_01002], ara::diag::DiagUdsNrcErrorDomain [SWS_DM_00535] ainsi que ara::diag::DiagSovdErrorDomain [SWS_DM_01815]. La définition est intégrée via le fichier d'en-tête #include "ara/diag/diag_error_domain.h" [SWS_DM_00995].
                • 
  
              

  
              En raison de la classification comme not exception safe, aucune protection interne supplémentaire contre les erreurs au sein de la méthode ne devrait intervenir lors de l'opération de déclenchement dans le contexte système (interprétation : les développeurs doivent intercepter les exceptions dans le contexte applicatif appelant).
