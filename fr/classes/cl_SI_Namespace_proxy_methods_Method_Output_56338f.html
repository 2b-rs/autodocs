Contexte

La structure <SI-Namespace>::proxy::methods::<Method>::Output sert dans l'Adaptive Platform (module com) d'encapsulation pour les paramètres de sortie (arguments out) d'un appel de méthode au niveau client ou proxy ([SWS_CM_99333], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output »). Lorsqu'une méthode d'interface de service définit plusieurs valeurs de retour ou des arguments de sortie spécifiques, la plateforme regroupe ces paramètres dans une structure Output générée, au lieu de transporter des valeurs individuelles non liées.

Les composants suivants participent principalement à l'interaction :

  • Application cliente appelante : Initie l'appel de méthode via l'instance de proxy et évalue les données de résultat après achèvement.
  • Proxy de méthode : L'objet fonction <SI-Namespace>::proxy::methods::<Method> qui, lors de l'appel, sérialise les paramètres et déclenche la communication.
  • Conteneur de retour : Un objet ara::core::Future qui, en cas de succès, contient la structure Output instanciée (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output »).
  • Homologue skeleton : Du côté du fournisseur de services existe le pendant typé {<hierarchical-namespace-list-lower-skeleton>}::skeleton::{<service-interface-name>}Skeleton::{<method-name>}Output ([SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.4.6 « Struct: {<method-name>}Output »), qui est également fourni par le fournisseur de services via un Future (AUTOSAR_AP_SWS_CommunicationManagement §8.4.6).

Diagramme de contexte : Intégration de la structure Output dans le chemin d'appel et de retour de la méthode proxy. Sources : [SWS_CM_99333], [SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output ».

Cycle de vie

Le cycle de vie et la gestion d'état d'une instance de Output sont étroitement liés à l'objet ara::core::Future parent et à la communication asynchrone :

  • Création : L'objet Output n'est pas instancié manuellement par le code applicatif. Il est créé par la couche de communication après réception et désérialisation réussies du message de réponse du fournisseur de services et inséré dans le ara::core::Future associé (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output »).
  • Propriété et transmission : L'objet reste dans le Future jusqu'à ce que l'application appelante récupère le résultat via get() ou GetResult(). Grâce à cette récupération, l'instance de Output passe sous la propriété du contexte client appelant.
  • Interruption et destruction : Si l'appelant détruit prématurément l'objet ara::core::Future retourné, son destructeur provoque l'interruption de l'appel de méthode ([SWS_CM_00194], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). Dans ce cas, aucune instance de Output n'est fournie à l'application et le traitement est abandonné.

Parcours d'utilisation

Le déroulement normal de l'utilisation de la structure Output se divise dans les phases suivantes :

  1. Appel de méthode : L'application appelle l'objet méthode proxy operator()(...) avec les arguments d'entrée définis.
  2. Réception de l'objet Future : Comme valeur de retour immédiate, l'appelant reçoit un objet de type ara::core::Future<Output> (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output »).
  3. Synchronisation et interrogation : L'appelant bloque de manière synchrone ou attend de manière asynchrone l'achèvement et demande le résultat via get() ou GetResult() ([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6).
  4. Traitement : En cas d'exécution réussie, l'application extrait l'objet Output ([SWS_CM_99333]) et lit les champs membres des paramètres de sortie qu'il contient.

Diagramme de séquence : Appel d'une méthode proxy et évaluation de la structure Output via l'objet Future. Sources : [SWS_CM_99333], [SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output ».

Scénarios d'erreur

En cas d'erreur, la structure Output n'est pas transmise à l'appelant :

  • Erreurs d'infrastructure et de Future : si l'appel de méthode échoue, le ara::core::Future résultant ne contient aucun objet Output, mais un code d'erreur, par exemple ara::core::FutureErrc (AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 « Struct: Output ») ou ara::com::ComErrc ou ApApplicationError (AUTOSAR_AP_SWS_CommunicationManagement §8.4.6).
  • Erreurs d'application vérifiées (Checked Errors) : si une erreur vérifiée définie survient pendant le traitement de l'appel de méthode, le ara::core::ErrorCode correspondant est retourné dans le contexte de l'appel de GetResult() ou de get() ([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). Aucune instance de Output n'est construite dans ce chemin.
  • Méthodes Fire-and-Forget : selon la spécification, il n'existe aucune erreur vérifiée pour les appels Fire-and-Forget ([SWS_CM_90436], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6) ; de par leur conception, de telles méthodes ne possèdent pas non plus de structure Output, car aucune valeur de retour n'est transmise.
