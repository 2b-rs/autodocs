But d'utilisation

ara::core::Promise<T, E> est la variante AUTOSAR de std::promise. Le type d'erreur doit être ara::core::ErrorCode. Avec Future, la classe peut fournir des valeurs et des erreurs de manière asynchrone et thread-safe sans gestion d'exception. [SWS_CORE_00340] [SWS_CORE_10800]

Cycle de vie et propriété

La copie est interdite (=delete), le déplacement est possible. L'affectation par déplacement et le destructeur abandonnent un éventuel Shared State existant. [SWS_CORE_00350] [SWS_CORE_00351] [SWS_CORE_00342] [SWS_CORE_00343] [SWS_CORE_00349]

Interaction avec d'autres classes

get_future() renvoie le Future<T,E> correspondant avec le même état partagé ; cet appel n'est autorisé qu'une seule fois par promesse. set_value(), SetError() et SetResult() préparent l'état partagé. Restrictions & traitement des erreurs

Fourniture du résultat asynchrone

Du côté Skeleton, un Promise peut fournir une valeur déjà calculée ou être déplacé dans un Worker asynchrone ; le Future associé est renvoyé à l'appelant. EXP ARAComAPI §5.4.6 « Methods »

Si une erreur d'application est détectée, le ErrorCode associé est placé dans le Promise ; le client peut ensuite le traiter comme Result en utilisant le chemin Future. EXP ARAComAPI §4.7 « Error Handling » EXP ARAComAPI §5.4.6 « Methods »

Traité d'État commun

Le Promise complète l'état commun observé en Future. Le cadre pertinent est le concept Future/Promise pour les valeurs asynchrones ou les résultats d'erreur définis dans Core. SWS Core §7.2 « Error handling » SWS Core §7.2.5.5 « Future and Promise »

Comportement en cas d'erreur

Un Promise ne peut préparer son état partagé qu'une seule fois avec une valeur, une erreur ou un Result. Un appel ultérieur à set_value(), SetError() ou SetResult() lorsqu'une valeur ou une erreur est déjà stockée est spécifié comme une violation promise_already_satisfied. Un setter sans état partagé constitue sa propre violation. [SWS_CORE_00345] [SWS_CORE_00346] [SWS_CORE_00353] [SWS_CORE_00354] [SWS_CORE_00355] [SWS_CORE_00356] [SWS_CORE_13015] [SWS_CORE_13016]

get_future() ne peut être appelé qu'une seule fois par Shared State. Le deuxième appel est défini comme violation future_already_retrieved ; Si le Shared State est manquant, la violation no_state s'applique. Ces cas ne sont pas des erreurs d'application signalées via Result dans le contrat API. [SWS_CORE_00344] [SWS_CORE_13013] [SWS_CORE_13014]

Le destructeur et l'affectation de déplacement abandonnent un état partagé existant. Si la page Future déjà sortie attend alors le résultat, GetResult() renvoie l'erreur FutureErrc::kBrokenPromise ; get() gère la même condition sur une base exceptionnelle. Le processus complet, y compris la définition d'une erreur et d'un délai d'attente, est affiché dans Fehlerpfad-Diagramm von Future.
