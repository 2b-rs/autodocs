But d'utilisation

L’interface traite des données génériques SOVD Content. Le Diagnostic Manager utilise l’instance représentée via DiagnosticSovdContentPortMapping pour lire les données SOVD. Read fournit DiagnosticSovdContentData de manière asynchrone pour un nom de contenu ; Write prend en charge de telles données pour « Write a Data Value ». [SWS_DM_02186] [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_02164]

Interaction avec d'autres classes

Pour une requête de lecture, le gestionnaire appelle Read et forme la réponse SOVD à partir des éléments de contenu agrégés. Pour une requête d'écriture, il appelle Write avec DiagnosticSovdContentData, dont les éléments sont construits en utilisant SetName et SetContent. [SWS_DM_01432] [SWS_DM_02166]

Cycle de vie et propriété

Le constructeur obtient InstanceSpecifier et SovdContentConcurrencyType. La classe est mobile ; La construction du déplacement et l'affectation du déplacement sont spécifiées. [SWS_DM_02187] [SWS_DM_02189] [SWS_DM_02190]

Restrictions & traitement des erreurs

Read et Write renvoient une erreur SOVD si le résultat est négatif. Le CancellationHandler ne peut pas être stocké ou utilisé au-delà de la durée de vie de l’opération en cours. Offer active le transfert de requête, StopOffer le termine ; une interface qui propose déjà des rapports DiagOfferErrc::kAlreadyOffered. Les fonctions présentées sont thread-safe. [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_02193] [SWS_DM_02194]

Règles relatives aux paramètres et aux résultats Read reçoit le Content Name, la MetaInfo et le CancellationHandler et renvoie soit des données abstraites de contenu SOVD pour une réponse positive, soit une erreur SOVD. Write reçoit les mêmes informations de contexte ainsi que les données de contenu à écrire ; ces données restent valides jusqu’à l’accomplissement de la Future ou à l’annulation. Le constructeur et le destructeur sont exception-safe et thread-safe. [SWS_DM_02187] [SWS_DM_02188] [SWS_DM_02191] [SWS_DM_02192]

Les opérations asynchrones sont des points d'interface purement virtuels ; Le traitement du béton met donc en œuvre l'application fournie. La réponse externe est formée par le Gestionnaire de Diagnostic sur la base des futurs réalisés. [SWS_DM_02191] [SWS_DM_02192] [SWS_DM_01432]

contexte SOVD

L'architecture décrit GenericDiagnosticSovdContent comme interface pour les données SOVD : Read est appelé pour « Read Single Data Value », Write pour « Write a Data Value » de l'instance de contenu SOVD spécifiée. EXP SWArchitecture §9.8.1.1.10 Les données SOVD sont méthodiquement dérivées de DiagnosticDataIdentifier. EXP SOVD §3.1 « Common use cases in SOVD and UDS »
