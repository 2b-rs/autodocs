Sert à l'identification et à la traduction textuelle de tous les codes d'erreur du module crypto.

La classe définit le domaine d'erreur central pour toutes les erreurs pouvant être signalées via les interfaces publiques dans l'espace de noms ara::crypto [SWS_CRYPT_19950]. Parmi ses tâches principales figurent le renvoi du nom de domaine unique ainsi que la traduction des codes d'erreur de l'énumération CryptoErrc en messages d'erreur compréhensibles [SWS_CRYPT_19953]. Toutes les fonctions d'interrogation sont conçues pour être thread-safe et sûres vis-à-vis des exceptions, tandis que la méthode de déclenchement d'exceptions ne participe pas à la résolution de surcharge lorsque les exceptions C++ sont désactivées [SWS_CRYPT_19954].

Contexte

La classe ara::crypto::CryptoErrorDomain fait office de domaine d'erreur spécialisé au sein de la plateforme AUTOSAR Adaptive. Conformément à sa définition de classe, elle dérive de ara::core::ErrorDomain et est déclarée final. Sa responsabilité centrale consiste à représenter l'ensemble des erreurs pouvant être signalées par les interfaces publiques au sein de l'espace de noms ara::crypto. Elle associe aux erreurs une identification de domaine unique qui peut être interrogée via la méthode Name [SWS_CRYPT_19950].

Pour une liaison de type uniforme, la classe met à disposition deux alias associés aux types : Errc renvoie directement, en tant qu'alias, à l'énumération CryptoErrc pour les codes d'erreur cryptographiques [SWS_CRYPT_19903], tandis que Exception référence la classe d'exception de base CryptoException [SWS_CRYPT_19904]. Les partenaires d'interaction sont principalement les blocs fonctionnels cryptographiques qui génèrent des erreurs de ce domaine, ainsi que le logiciel d'application qui reçoit et évalue les erreurs via les mécanismes de base de ara::core.

Diagramme de contexte : intégration de la CryptoErrorDomain dans la gestion des erreurs entre les API ara::crypto, la classe de base ara::core::ErrorDomain et l'application. Sources : [SWS_CRYPT_19950], [SWS_CRYPT_19903], [SWS_CRYPT_19904].

Cycle de vie

La création d'objets de la CryptoErrorDomain s'effectue via le constructeur standard sans paramètre, qui est spécifié comme constexpr et noexcept [SWS_CRYPT_19902]. Grâce à la déclaration en constexpr, une instance peut être construite dès la compilation. Interprétation : dans les implémentations types de la plateforme, le domaine d'erreur devrait exister sous la forme d'un singleton durable ou statique, afin que les codes d'erreur puissent référencer la même instance de domaine tout au long du processus, sans allocation dynamique de mémoire. Question Q-eace74191b79fa03 (ouverte)

Après l'instanciation, l'objet possède un caractère constant et sans état ; toute hiérarchie d'héritage sous cette classe est exclue par le mot-clé final. En ce qui concerne la concurrence, tant le constructeur [SWS_CRYPT_19902] que les méthodes d'interrogation Name [SWS_CRYPT_19950], Message [SWS_CRYPT_19953] et ThrowAsException [SWS_CRYPT_19954] sont explicitement classés comme sûrs au niveau des threads (thread-safe). Les instances peuvent donc être utilisées en parallèle par plusieurs threads sans synchronisation externe.

Parcours d'utilisation

Le déroulement régulier de l'interaction avec la CryptoErrorDomain se décompose selon les étapes suivantes :

  1. Une opération au sein de l'espace de noms ara::crypto échoue et génère un objet d'erreur de type ara::core::ErrorCode, qui est lié à la CryptoErrorDomain.
  2. L'application appelante ou la routine de traitement des erreurs vérifie l'origine de l'erreur et peut, si nécessaire, obtenir le nom unique du domaine au moyen de Name() [SWS_CRYPT_19950].
  3. Pour générer des sorties de journalisation ou des messages de diagnostic, la méthode Message() est appelée avec le errorCode transmis, ce qui résout le code et renvoie le message textuel associé sous la forme const char* [SWS_CRYPT_19953].
  4. Si l'appelant souhaite convertir l'erreur en exception C++, l'appel de ThrowAsException() est effectué, ce qui déclenche une exception appropriée sur la base de CryptoException [SWS_CRYPT_19954], [SWS_CRYPT_19904].

Diagramme de séquence : résolution d'erreur et émission de texte via les interfaces de la CryptoErrorDomain. Sources : [SWS_CRYPT_19950], [SWS_CRYPT_19953].

Scénarios d'erreur

Lors de la gestion des erreurs, la classe présente des garanties différenciées en matière de sécurité vis-à-vis des exceptions. Les méthodes Name [SWS_CRYPT_19950] et Message [SWS_CRYPT_19953] sont déclarées noexcept et sont totalement sûres vis-à-vis des exceptions (exception safe). Si une valeur numérique non définie dans l'énumération CryptoErrc devait être transmise à Message, un message de repli générique devrait vraisemblablement être fourni ; une interruption par des exceptions est exclue. Question Q-6f2a8707283aa64e (ouverte)

En revanche, la méthode ThrowAsException est spécifiée comme non sûre vis-à-vis des exceptions (not exception safe) et pourvue de l'attribut [[noreturn]], étant donné que sa fonction prévue consiste à lever une exception [SWS_CRYPT_19954]. Une contrainte essentielle concerne les configurations de plateforme sans prise en charge des exceptions : si les exceptions C++ sont désactivées dans la chaîne d'outils du compilateur, ThrowAsException ne participe pas à la résolution de surcharge [SWS_CRYPT_19954]. Dans de tels systèmes, l'appel ne peut pas être compilé et le traitement des erreurs doit obligatoirement être géré via des mécanismes basés sur des valeurs d'erreur, tels que des objets de résultat.

Ce guide est basé sur la spécification AUTOSAR Adaptive Platform R25-11.

Utilisation et contexte d'appel

Le constructeur par défaut CryptoErrorDomain() initialise une instance du domaine d'erreur pour les opérations cryptographiques [SWS_CRYPT_19902]. Il est spécifié comme constexpr et noexcept, n'accepte aucun argument et ne possède aucune valeur de retour. L'exécution s'effectue de manière synchrone et peut avoir lieu au moment de la compilation. Dans les programmes applicatifs, une instanciation manuelle devrait rarement être nécessaire, car l'accès au domaine s'effectue régulièrement via la fonction globale GetCryptoErrorDomain() [SWS_CRYPT_19952]. Question Q-1e029d80fb7bf7d1 (ouverte)

Gestion des erreurs et concurrence

La création de l'objet est définie comme exception safe ainsi que thread-safe [SWS_CRYPT_19902]. Étant donné que le constructeur est déclaré avec noexcept, aucune erreur ni exception ne survient lors de l'appel ; il n'existe pas de messages d'erreur vers DET ou DEM pour ce constructeur.

Interaction au sein du module

Le domaine créé constitue le contexte pour les descriptions d'erreurs cryptographiques :

  • Il encapsule les codes d'erreur de l'énumération CryptoErrc [SWS_CRYPT_10099] via l'alias de type Errc [SWS_CRYPT_19903].
  • Des instances de ara::core::ErrorCode référençant de manière fixe ce domaine sont créées via la fonction libre MakeErrorCode() [SWS_CRYPT_19951].
  • Les fonctions membres du domaine permettent l'interrogation de l'identifiant via Name() [SWS_CRYPT_19950], la résolution textuelle via Message() [SWS_CRYPT_19953] ainsi que la levée d'erreurs spécifiques au système via ThrowAsException() [SWS_CRYPT_19954] avec le type de base Exception [SWS_CRYPT_19904].
