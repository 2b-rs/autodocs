Contexte

L'interface ara::crypto::cryp::HashFunctionCtx définit l'abstraction standardisée pour les fonctions de hachage cryptographiques au sein du module crypto de l'AUTOSAR Adaptive Platform [SWS_CRYPT_21101]. Sa responsabilité principale réside dans le calcul de sommes de contrôle cryptographiques et de condensats de message sur des flux d'octets quelconques ou des objets de clés structurés.

Le logiciel applicatif appelant fait principalement office de partenaire d'interaction ; il fournit les données d'entrée via ReadOnlyMemRegion et reçoit les valeurs de hachage calculées via ReadWriteMemRegion [SWS_CRYPT_50060]. En plus des zones de mémoire standard, le contexte peut interagir directement avec des objets cryptographiques afin d'inclure de manière sécurisée du matériel de clé de type CryptoObject::Sptr dans le calcul du condensat [SWS_CRYPT_50057]. En outre, le contexte interagit potentiellement avec d'autres instances de contexte du même algorithme et du même fournisseur cryptographique via l'importation et l'exportation de l'état de traitement interne [SWS_CRYPT_50065].

Cycle de vie

La durée de vie et la propriété d'une instance sont habituellement gérées via l'alias de type de pointeur intelligent ara::crypto::cryp::HashFunctionCtx::Sptr (std::shared_ptr<HashFunctionCtx>) [SWS_CRYPT_21101]. Étant donné que HashFunctionCtx est une interface purement abstraite, la création de l'instance concrète devrait s'effectuer via une méthode fabrique d'un fournisseur cryptographique (interprétation). Toutes les fonctions membres sont déclarées comme noexcept et spécifiées comme sûres vis-à-vis des exceptions et sûres pour les threads (notamment [SWS_CRYPT_50060], [SWS_CRYPT_50058]).

Le déroulement opérationnel suit un modèle à états comportant trois phases principales :

  • Prêt / Non démarré : après sa création, le contexte se trouve à l'état de repos. Dans cet état, il est possible soit d'exécuter une opération de hachage en une seule étape via CalculateHashDigest() [SWS_CRYPT_50060], soit d'initier un calcul itératif via Start() sans vecteur d'initialisation (IV) [SWS_CRYPT_50152] ou avec IV [SWS_CRYPT_50153]. Une importation au moyen de ImportContextState() fait passer le contexte directement dans l'état de l'image importée [SWS_CRYPT_50065].
  • En cours de traitement (streaming) : après un Start() réussi, le contexte reçoit des fragments de données [SWS_CRYPT_21113] ou des objets clés [SWS_CRYPT_50057] par des appels répétés de Update(). Durant cette phase, un état intermédiaire peut être interrogé à tout moment via GetIntermediateDigest() sans interrompre le flux de données [SWS_CRYPT_50059]. ExportContextState() permet de sérialiser l'état de calcul [SWS_CRYPT_50064]. Un appel à Cancel() interrompt l'opération et réinitialise le traitement [SWS_CRYPT_50058] ; de même, un nouvel appel à Start() interrompt une opération en cours [SWS_CRYPT_50152].
  • Terminé (Finished) : l'appel de Finish() finalise le calcul [SWS_CRYPT_21115]. Dans cet état, aucune donnée supplémentaire ne peut être injectée via Update(). La valeur de hachage finale peut désormais être lue via GetDigest() [SWS_CRYPT_21116] ou comparée directement à une référence avec Compare() [SWS_CRYPT_50154]. Un nouveau Start() fait repasser le contexte dans une nouvelle phase de calcul.

Parcours d'utilisation

L'interface prend en charge deux modèles d'utilisation :

1. Calcul en une seule étape (Single-Call) : lorsque l'intégralité du message se trouve déjà en mémoire, CalculateHashDigest() exécute l'initialisation, la transformation et la génération du condensat en une seule étape atomique [SWS_CRYPT_50060].

2. Calcul progressif en streaming (Multi-Call) : pour les données diffusées en continu ou les messages plus volumineux que la taille de bloc maximale GetMaximumChunkSize() [SWS_CRYPT_50062], l'appel s'effectue typiquement selon les étapes individuelles suivantes :

  1. Dimensionnement de tampon : l'application détermine la taille de sortie via GetDigestSize() [SWS_CRYPT_50061] et alloue un tampon approprié.
  2. Démarrage : appel de Start() [SWS_CRYPT_50152] ou Start(iv) [SWS_CRYPT_50153] pour activer le calcul.
  3. Alimentation en données : transmission séquentielle de segments de données via Update(data) [SWS_CRYPT_21113] ou de clés via Update(key) [SWS_CRYPT_50057].
  4. Finalisation : appel de Finish() pour achever le calcul du condensat [SWS_CRYPT_21115].
  5. Traitement du résultat : soit le condensat est écrit au moyen de GetDigest() dans le tampon cible fourni [SWS_CRYPT_21116], soit il est directement comparé à une valeur de référence attendue au moyen de Compare() [SWS_CRYPT_50154].

Diagramme de séquence : déroulement typique d'un calcul itératif de valeur de hachage via Start, Update, Finish et évaluation. Sources : [SWS_CRYPT_50152], [SWS_CRYPT_21113], [SWS_CRYPT_21115], [SWS_CRYPT_21116], [SWS_CRYPT_50154]

Scénarios d'erreur

Toutes les méthodes renvoient un ara::core::Result et implémentent une sémantique de rollback, de sorte que le contexte reste dans un état cohérent en cas d'erreur. Les codes d'erreur définis couvrent les domaines de problèmes suivants :

  • Erreurs de séquence :
    • ara::crypto::CryptoErrc::kProcessingNotStarted : un appel à Update() ([SWS_CRYPT_21113], [SWS_CRYPT_50057]) ou à Cancel() [SWS_CRYPT_50058] a lieu sans que le calcul ait été initié par Start().
    • ara::crypto::CryptoErrc::kInvalidUsageOrder : Finish() [SWS_CRYPT_21115] ou GetIntermediateDigest() [SWS_CRYPT_50059] est appelé sans que le processus de hachage ait été préalablement démarré avec succès.
    • ara::crypto::CryptoErrc::kProcessingNotFinished : GetDigest() [SWS_CRYPT_21116] ou Compare() [SWS_CRYPT_50154] est appelé avant que le calcul n'ait été finalisé par Finish().
  • Problèmes de tampon et de taille :
    • ara::crypto::CryptoErrc::kInsufficientCapacity : le tampon de sortie fourni est trop petit pour le résultat dans CalculateHashDigest() [SWS_CRYPT_50060], GetDigest() [SWS_CRYPT_21116], GetIntermediateDigest() [SWS_CRYPT_50059] ou ExportContextState() [SWS_CRYPT_50064].
    • ara::crypto::CryptoErrc::kInvalidInputSize : la taille des données d'entrée ou de l'IV n'est pas valide ([SWS_CRYPT_50060], [SWS_CRYPT_50153], [SWS_CRYPT_21113], [SWS_CRYPT_50057]).
  • Incompatibilité et absence de prise en charge :
    • ara::crypto::CryptoErrc::kUnsupported : la fonction ou la configuration n'est pas prise en charge par le contexte, par ex. les appels uniques [SWS_CRYPT_50060], l'utilisation d'IV pour les algorithmes sans IV ou l'absence d'IV pour les fonctions requérant un IV ([SWS_CRYPT_50060], [SWS_CRYPT_50152], [SWS_CRYPT_50153]), les résultats intermédiaires [SWS_CRYPT_50059], le hachage de clés [SWS_CRYPT_50057] ou l'exportation/importation d'état ([SWS_CRYPT_50063], [SWS_CRYPT_50064], [SWS_CRYPT_50065]).
    • ara::crypto::CryptoErrc::kIncompatibleObject et ara::crypto::CryptoErrc::kUsageViolation : l'objet clé transmis à Update() est incompatible ou interdit son utilisation pour le calcul de hachage (kAllowHashCalculation manquant) [SWS_CRYPT_50057].
    • ara::crypto::CryptoErrc::kInvalidArgument : les données d'état transmises à ImportContextState() ne sont pas valides [SWS_CRYPT_50065].
    • ara::crypto::CryptoErrc::kBusyResource : une ressource cryptographique matérielle ou logicielle requise est occupée ([SWS_CRYPT_50152], [SWS_CRYPT_50153]).

Ce guide de classe repose exclusivement sur la spécification AUTOSAR Adaptive R25-11 pour le module crypto. Les affirmations sans références normatives explicites constituent des interprétations contextuelles.
