classe ara::per::WriteAccessor

[SWS_PER_00595] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class WriteAccessor final :              public virtual FileAccessor {...};

WriteAccessor is used to write file data. It provides the WriteBinary and WriteText methods featuring a Result for controlled, unformatted writing, and the operator<< method for simple formatted writing. It also provides SyncToFile() to flush the buffer of the operating system to the physical storage.

Sert à l'écriture mise en mémoire tampon de fichiers binaires et texte ainsi qu'à leur synchronisation sur la mémoire physique.

La classe ara::per::WriteAccessor permet l'écriture de contenus de fichiers binaires ou textuels dans le module de persistance et fournit des méthodes pour des accès en écriture non formatés ainsi qu'un opérateur de flux formaté [SWS_PER_00423]. Comme les opérations d'écriture peuvent dans un premier temps être mises en mémoire tampon dans le système d'exploitation, l'appel de SyncToFile() force le vidage permanent (flush) sur la mémoire physique [SWS_PER_00122]. Toutes les méthodes sont sûres du point de vue des exceptions (exception safe), mais ne sont pas sûres au niveau des threads (not thread-safe), raison pour laquelle les accès concurrents doivent être protégés par l'application.

Contexte

ara::per::WriteAccessor est une classe finale du module de persistance (per) de l'AUTOSAR Adaptive Platform et dérive virtuellement de FileAccessor. La classe fournit des opérations d'écriture pour les contenus de fichiers. Elle propose des méthodes pour une écriture non formatée et contrôlée avec traitement des erreurs via ara::core::Result ainsi qu'un opérateur de flux surchargé pour l'écriture formatée. Les partenaires d'interaction sont l'application appelante, le tampon de fichiers interne du système d'exploitation ainsi que le support de stockage physique.

Cycle de vie

Le constructeur par défaut de WriteAccessor est explicitement supprimé et ne doit pas être utilisé [SWS_PER_00596]. (Interprétation : les instances de WriteAccessor devraient être créées et mises à disposition via des méthodes fabriques d'unités de gestion de persistance de niveau supérieur telles que le File-Storage.)

La destruction s'effectue via le destructeur virtuel ~WriteAccessor() [SWS_PER_00597]. La classe et ses méthodes sont spécifiées comme sûres du point de vue des exceptions (« exception safe ») et déclarées comme noexcept. Concernant la concurrence, WriteAccessor n'est pas sûre au niveau des threads (« not thread-safe ») [SWS_PER_00597] ; les accès parallèles à la même instance doivent être sécurisés de manière externe par l'application.

Parcours d'utilisation

Le déroulement régulier comprend l'écriture de données en mode non formaté ou formaté, l'adaptation optionnelle de la taille du fichier et le stockage persistant final :

  • Écrire des données binaires : via WriteBinary(), une plage d'octets (ara::core::Span<const ara::core::Byte>) est écrite dans le fichier [SWS_PER_00423].
  • Écrire des données textuelles : au moyen de WriteText(), des chaînes de caractères sont transmises via un ara::core::StringView [SWS_PER_00166]. En complément, operator<< est disponible comme fonction de commodité pour les cas d'utilisation non critiques, les erreurs survenues étant alors silencieusement ignorées [SWS_PER_00125].
  • Forcer la persistance : le moment du stockage physique dépend de l'implémentation de la persistance ; SyncToFile() vide de manière contraignante le tampon du système d'exploitation sur le support de stockage [SWS_PER_00122], [SWS_PER_00423], [SWS_PER_00166].
  • Ajuster la taille du fichier : SetFileSize() permet de tronquer le fichier, ce qui supprime les contenus excédentaires ; la position dans le fichier reste inchangée ou est fixée à la dernière position valide, respectivement à 0 [SWS_PER_00428].

Diagramme de séquence : opérations d'écriture suivies d'une synchronisation sur la mémoire physique. Sources : [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]

Scénarios d'erreur

Les méthodes WriteBinary(), WriteText(), SyncToFile() et SetFileSize() renvoient un ara::core::Result<void> qui contient des codes d'erreur spécifiques en cas d'échec :

  • PerErrc::kPhysicalStorageFailure : l'accès au support de stockage physique échoue [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. L'état du fichier est inconnu et peut être totalement corrompu (aucune sémantique de rollback).
  • PerErrc::kOutOfStorageSpace : espace de stockage physique insuffisant [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122]. Lors de l'écriture, la partie excédentaire est rejetée et la position se trouve à la fin du fichier (aucune sémantique de rollback).
  • PerErrc::kQuotaExceeded : le fichier dépasserait la taille maximale configurée (AllowedSize) [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122] (sémantique de rollback).
  • PerErrc::kEncryptionFailed : le chiffrement ou le déchiffrement échoue [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428]. Bien que le tampon et la position soient mis à jour, le fichier ne peut pas être rendu persistant et reflète une version antérieure sur la mémoire (sémantique de rollback).
  • PerErrc::kAuthenticationFailed : le calcul ou la vérification du MAC échoue [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00122], [SWS_PER_00428] (sémantique de rollback).
  • PerErrc::kValidationFailed : la validité des données stockées ne peut pas être garantie [SWS_PER_00423], [SWS_PER_00166], [SWS_PER_00428] (sémantique de rollback).
  • PerErrc::kInvalidSize : la nouvelle taille de fichier lors de SetFileSize() est supérieure à la taille actuelle du fichier [SWS_PER_00428] (sémantique de rollback).

      La fonction membre SyncToFile de la classe ara::per::WriteAccessor (définie dans #include "ara/per/write_accessor.h") transfère le contenu actuel du fichier de manière synchrone sur la mémoire physique [SWS_PER_00122]. L'appel n'accepte aucun paramètre de transmission et renvoie un ara::core::Result<void> qui est vide en cas de succès ou qui contient en cas d'erreur des codes d'erreur spécifiques du module Persistency ou des erreurs spécifiques au constructeur [SWS_PER_00122].
      


      Lors de l'exécution, différents cas d'erreur peuvent survenir, dont certains possèdent une sémantique de retour arrière (rollback) [SWS_PER_00122] :
      

        

      • StorageFailure : survient lorsque l'accès physique au support de stockage échoue (pas de sémantique de retour arrière) [SWS_PER_00122].
        • 

      • PerErrc::kOutOfStorageSpace : est renvoyé si l'espace de stockage physique est insuffisant pour le fichier modifié (pas de sémantique de retour arrière) [SWS_PER_00122].
        • 

      • PerErrc::kQuotaExceeded : est signalé lorsque le fichier dépasse la taille maximale configurée AllowedSize du File Storage (avec sémantique de retour arrière) [SWS_PER_00122].
        • 

      • PerErrc::kEncryptionFailed : en cas d'échec du chiffrement des données stockées (avec sémantique de retour arrière) [SWS_PER_00122].
        • 

      • PerErrc::kAuthenticationFailed : en cas d'échec du calcul du MAC pour les données (avec sémantique de retour arrière) [SWS_PER_00122].
        • 

      


      Concernant la sécurité d'exécution, la méthode est déclarée comme noexcept et spécifiée comme exception safe [SWS_PER_00122]. Cependant, étant donné qu'elle est expressément classifiée comme not thread-safe, les appels simultanés sur la même instance de WriteAccessor doivent vraisemblablement être synchronisés par l'appelant [SWS_PER_00122].

              La fonction WriteBinary de la classe ara::per::WriteAccessor écrit le contenu d'une séquence d'octets (ara::core::Span<const ara::core::Byte>) dans un fichier [SWS_PER_00423]. L'instant de la persistance effective sur le support de stockage dépend de l'implémentation de Persistency ; via SyncToFile, la persistance synchrone peut être forcée [SWS_PER_00423]. La fonction est déclarée comme noexcept et est considérée comme sûre face aux exceptions [SWS_PER_00423].
              

              En matière de concurrence, WriteBinary est spécifiée comme non sûre pour les threads (not thread-safe) [SWS_PER_00423]. Les accès parallèles au même accesseur doivent être synchronisés au niveau de l'application.
              

              En cas d'erreur, un code d'erreur est renvoyé dans ara::core::Result<void>, le contenu du fichier pouvant être corrompu et la position actuelle pouvant avoir changé [SWS_PER_00423] :
