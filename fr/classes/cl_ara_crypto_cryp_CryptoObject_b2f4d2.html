Contexte

L'interface ara::crypto::cryp::CryptoObject sert d'interface de base commune pour tous les objets cryptographiques pouvant être reconnus et gérés par un CryptoProvider. En héritant de ara::crypto::Serializable, elle définit le fondement uniforme pour les objets sérialisables au sein de l'architecture cryptographique de l'AUTOSAR Adaptive Platform, tels que le matériel de clé et les métadonnées associées.

L'interface regroupe les propriétés fondamentales d'identification et de contrôle des ressources cryptographiques. Parmi les principaux partenaires d'interaction figurent :

  • Application : Utilise l'interface pour interroger les identifiants d'algorithme et les restrictions d'utilisation ainsi que pour déclencher le stockage dans un slot de clé.
  • CryptoProvider : Fournit le contexte d'exécution pour les objets cryptographiques. Conformément à [SWS_CRYPT_20517], il existe une liaison logique avec le provider respectif ; des incompatibilités surviennent lorsque les structures cibles sont associées à un autre provider.
  • WriteableKeySlot : Représente l'emplacement de stockage sous-jacent dans lequel l'objet est transféré de manière persistante via Save() ([SWS_CRYPT_20517]).

Diagramme de contexte : partenaires d'interaction de CryptoObject lors de la gestion et de la persistance. Sources : [SWS_CRYPT_20517]

Cycle de vie

Le cycle de vie et la gestion de la mémoire d'un CryptoObject suivent les prescriptions relatives aux ressources de la plateforme adaptative :

  • Propriété : Pour la gestion des instances, la classe fournit l'alias de type Sptr ([SWS_CRYPT_20501]), qui est défini comme std::shared_ptr<CryptoObject>. Cela permet l'utilisation partagée avec comptage de références des objets au-delà des limites des composants.
  • Création : Comme il s'agit d'une interface purement virtuelle, CryptoObject ne peut pas être instancié directement ; la création d'instances concrètes devrait typiquement s'effectuer via des méthodes factory d'un CryptoProvider.
  • Persistance : Un CryptoObject peut être conservé à l'état volatil au moment de l'exécution ou être stocké de façon permanente dans un WriteableKeySlot via la méthode Save() ([SWS_CRYPT_20517]). En cas d'exécution réussie, le matériel de clé ainsi que les métadonnées sont écrits ; les données préalablement présentes dans le slot sont alors entièrement écrasées.
  • Concurrence et sécurité : Toutes les méthodes (GetAlgId(), GetAllowedUsage(), Save()) sont déclarées comme noexcept et spécifient la sécurité vis-à-vis des exceptions (exception safe) ainsi que la sécurité des threads (thread-safe) ([SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]). Les appels parallèles de plusieurs threads sont donc autorisés sans synchronisation externe.

Parcours d'utilisation

Un cas d'utilisation typique réside dans la validation des propriétés de l'objet et son enregistrement ultérieur dans un slot de clé permanent :

  1. Interroger l'algorithme : L'application appelle GetAlgId() ([SWS_CRYPT_20505]) afin d'obtenir l'identifiant d'algorithme sous forme de ara::crypto::AlgIdString au sein d'un ara::core::Result.
  2. Vérifier les règles d'utilisation : Les AllowedUsageFlags sont déterminées au moyen de GetAllowedUsage() ([SWS_CRYPT_50092]). Avant un enregistrement, il convient de vérifier si l'autorisation kAllowPersist est présente ([SWS_CRYPT_20517]).
  3. Effectuer l'enregistrement : Si l'objet remplit tous les critères, la méthode Save() est appelée en transmettant un WriteableKeySlot::Sptr ([SWS_CRYPT_20517]).
  4. Vérifier le résultat : La méthode renvoie un ara::core::Result<void> qui permet d'évaluer le succès ou des codes d'erreur spécifiques.

Diagramme de séquence : séquence typique de validation et d'enregistrement d'un CryptoObject. Sources : [SWS_CRYPT_20505], [SWS_CRYPT_50092], [SWS_CRYPT_20517]

Scénarios d'erreur

Le simple contrôle d'état par le biais de méthodes d'interrogation se distingue sensiblement des opérations d'écriture liées aux ressources :

  • Méthodes d'interrogation : Aucun code d'erreur standardisé n'est défini pour GetAlgId() ([SWS_CRYPT_20505]) et GetAllowedUsage() ([SWS_CRYPT_50092]).
  • Incompatibilité (kIncompatibleObject) : Si Save() échoue parce que la clé ne correspond pas au slot cible (par ex. AlgId incompatibles ou provenance d'un CryptoProvider différent), ara::crypto::CryptoErrc::kIncompatibleObject est renvoyé ([SWS_CRYPT_20517]).
  • Violation de droits (kUsageViolation) : Si l'utilisation autorisée de la clé ne contient pas le droit kAllowPersist, la persistance est refusée avec ara::crypto::CryptoErrc::kUsageViolation ([SWS_CRYPT_20517]).
  • Ressource occupée (kBusyResource) : Si l'opération d'écriture ne peut temporairement pas être effectuée, Save() renvoie l'erreur ara::crypto::CryptoErrc::kBusyResource ([SWS_CRYPT_20517]).
  • Garantie de rollback : Pour toutes les erreurs lors de Save(), la sémantique de rollback s'applique (rollback_semantics) ([SWS_CRYPT_20517]), de sorte que l'état initial du slot de clé reste inchangé en cas d'échec.
