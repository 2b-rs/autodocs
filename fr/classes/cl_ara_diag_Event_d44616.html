But d'utilisation

La dernière classe propose des opérations pour un événement de diagnostic. Il lit l'octet d'état, l'état anti-rebond, le compteur de détection de défauts, l'état du test terminé et le numéro DTC de manière asynchrone dans le format souhaité. Interaction avec d'autres classes

SetEventStatusChangedNotifier enregistre une fonction de rappel pour chaque changement d'état ; un nouvel appel écrase le notificateur précédent. Le gestionnaire de diagnostic traite les bits d'état Event correspondant aux bits d'état UDS-DTC et, pour GetEventStatus, fournit l'état actuel des Event associés. Restrictions & traitement des erreurs

Pour GetDTCNumber, le gestionnaire renvoie DiagErrc::kNoSuchDTC s'il n'existe aucun mappage événement-DTC UDS ; les requêtes peuvent également signaler kServiceNotAvailable. La plupart des requêtes d'état et le notificateur ne sont pas thread-safe ; GetDTCNumber est thread-safe. Contexte fonctionnel Le Manager actualise les bits d’état d’événement à partir des résultats de test signalés via Monitor::ReportMonitorAction. Pour kResetTestFailed, seul le bit kTestFailed est réinitialisé. Au redémarrage d’un OperationCycle associé, le Manager remet kTestFailedThisOperationCycle à zéro et fixe kTestNotCompletedThisOperationCycle à un ; l’effacement d’un DTC réinitialise également des bits d’état d’événement prédéfinis. [SWS_DM_01025] [SWS_DM_01026] [SWS_DM_01027] [SWS_DM_01028]

La valeur de retour de GetTestComplete est vraie si et seulement si le FDC vaut -128 ou 127. L'API fournit les informations d'état via ara::core::Future dans chaque cas. [SWS_DM_00655] [SWS_DM_00649] [SWS_DM_00654] [SWS_DM_00656]

Intégration architecturale
