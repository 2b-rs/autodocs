Définit le domaine d'erreur pour le Network Management et traduit les codes d'erreur en messages ou exceptions.

Le domaine d'erreur ara::nm::NmErrorDomain encapsule la gestion des erreurs du Network Management dans l'AUTOSAR Adaptive Platform et intègre les codes d'erreur NmErrc ainsi que la classe d'exception NmException [SWS_ANM_01101]. Ses tâches principales comprennent la fourniture de messages d'erreur lisibles via Message() ainsi que le déclenchement contrôlé des exceptions associées via ThrowAsException() [SWS_ANM_01108]. En tant que contrainte centrale, l'instanciation et l'ensemble des fonctions membres sont implémentées de manière thread-safe (thread-safe), ce qui sécurise une interrogation concurrente des erreurs dans tout le système.

Contexte

La classe ara::nm::NmErrorDomain fait office, au sein de l'AUTOSAR Adaptive Platform, de domaine d'erreur spécifique au domaine pour le sous-système du Network Management [SWS_ANM_01101]. En tant que spécialisation finale de la classe de base ara::core::ErrorDomain, elle fournit le cadre standardisé pour l'identification, la description textuelle et la transmission des erreurs pouvant survenir lors du fonctionnement des fonctions de Network Management [SWS_ANM_01101].

Au sein du concept de gestion des erreurs de NM, la classe relie les causes concrètes d'erreurs aux mécanismes généraux de traitement des erreurs de l'environnement d'exécution. Pour ce faire, la classe définit via des alias de type une association directe avec les types pertinents : via l'alias Errc, elle intègre l'énumération sous-jacente NmErrc, qui déclare les codes d'erreur spécifiques au Network Management [SWS_ANM_01103]. En même temps, elle référence, via l'alias Exception, la classe d'exception spécialisée NmException, ce qui permet au besoin de convertir les erreurs dans le mécanisme d'exception C++ [SWS_ANM_01104]. Grâce à ce regroupement, NmErrorDomain sert de lien central entre les états d'erreur du module et le système de base spécifique aux erreurs de ara::core.

Cycle de vie

La création d'une instance de ara::nm::NmErrorDomain s'effectue via le constructeur par défaut sans paramètre [SWS_ANM_01105]. La classe étant spécifiée comme final, toute subdivision ou spécialisation ultérieure par des domaines d'erreur dérivés est explicitement empêchée [SWS_ANM_01101]. Le constructeur est déclaré avec noexcept, garantissant ainsi que l'instanciation du domaine d'erreur s'accomplit sans lever d'exceptions [SWS_ANM_01105].

En ce qui concerne les relations de propriété, une instance de ce domaine d'erreur devrait typiquement exister en tant qu'objet global à longue durée de vie en mémoire, afin d'être disponible en permanence via des références dans les objets de code d'erreur. Question Q-27fedf008cefcdc7 (ouverte) Une caractéristique essentielle de son cycle de vie réside dans son comportement vis-à-vis de la concurrence : aussi bien la construction de l'instance [SWS_ANM_01105] que l'ensemble des fonctions d'interface telles que l'interrogation du nom [SWS_ANM_01106], la génération de messages [SWS_ANM_01107] et le déclenchement d'exceptions [SWS_ANM_01108] sont conçues pour être entièrement thread-safe (thread-safe). Comme les instances de NmErrorDomain ne présentent aucun état modifiable, elles peuvent être utilisées de manière concurrente depuis plusieurs threads sans mesures de synchronisation supplémentaires.

Parcours d'utilisation

Le chemin d'utilisation régulier débute dès qu'un état d'erreur doit être analysé, consigné dans le journal ou converti en exception dans le Network Management. Le domaine d'erreur fournit à cet effet les fonctions de base d'identification et d'évaluation.

Pour l'identification générale du domaine, la méthode Name() peut être appelée, laquelle renvoie le nom du domaine sous forme de pointeur de chaîne de caractères constant [SWS_ANM_01106]. Lorsqu'une application ou un système de base souhaite déterminer la signification textuelle d'un code d'erreur survenu, la méthode Message() est appelée en lui transmettant le code d'erreur [SWS_ANM_01107]. Cette méthode renvoie le message d'erreur associé sous forme de const char* et garantit, par sa déclaration noexcept, que l'opération de diagnostic elle-même reste sûre vis-à-vis des exceptions [SWS_ANM_01107].

Si le flux de contrôle nécessite de lever une exception spécifique au système, la méthode ThrowAsException() est utilisée [SWS_ANM_01108]. Cette fonction reçoit un objet d'erreur de type ara::core::ErrorCode et lève l'exception correspondante de type NmException [SWS_ANM_01104], [SWS_ANM_01108]. Dans la pratique, l'appel devrait principalement s'effectuer de manière indirecte via des méthodes utilitaires correspondantes d'objets d'erreur. Question Q-70e50ac95d89f400 (ouverte)

Diagramme de séquence : conversion d'un code d'erreur de gestion de réseau en une NmException spécifique au type via le domaine d'erreur. Sources : [SWS_ANM_01104], [SWS_ANM_01108].

Scénarios d'erreur

Dans le cadre du traitement des erreurs, le domaine couvre tous les cas d'erreur du module qui sont définis par le type d'énumération NmErrc via l'alias Errc [SWS_ANM_01103]. Le domaine lui-même est conçu pour sécuriser de manière déterministe l'évaluation des erreurs.

Lors de la détermination des messages textuels via Message(), la déclaration en tant que noexcept garantit qu'aucune exception imprévue n'est levée, même en cas de codes d'erreur non valides [SWS_ANM_01107]. Le seul scénario prévu dans lequel la classe déclenche activement une exception est l'appel explicite de ThrowAsException() [SWS_ANM_01108]. Via la déclaration noexcept(false), la méthode signale qu'elle fait obligatoirement basculer le programme dans un chemin de traitement d'exception en levant une instance de NmException [SWS_ANM_01104], [SWS_ANM_01108]. Les composants appelants doivent donc s'assurer que de tels appels sont interceptés si nécessaire par des blocs d'exception appropriés.

              Le constructeur par défaut NmErrorDomain() sert à la construction du domaine d'erreur pour le Network Management ([SWS_ANM_01105]). La fonction est déclarée dans l'en-tête ara/nm/nm_error_domain.h et crée une instance de la classe NmErrorDomain, qui hérite de ara::core::ErrorDomain ([SWS_ANM_01101]).
              

  
              Utilisation et concurrence
              
  
              Le constructeur ne prend aucun paramètre et n'a aucune valeur de retour ([SWS_ANM_01105]). L'instanciation s'effectue de manière synchrone. Conformément à la spécification, l'appel est classé comme thread-safe, de sorte que le domaine d'erreur peut également être créé en toute sécurité depuis des threads parallèles ([SWS_ANM_01105]).
              

  
              Gestion des erreurs
              
  
              La fonction est spécifiée avec l'identificateur noexcept ([SWS_ANM_01105]). Par conséquent, aucune exception ne survient lors de l'exécution. Aucun code d'erreur spécifique ni mécanisme de traitement des erreurs n'est prévu pour cette construction.
              

  
              Interaction
              
  
              La classe créée NmErrorDomain définit le contexte spécifique au domaine pour les erreurs du Network Management ([SWS_ANM_01101]). La mise à disposition du domaine dans l'ensemble du système est principalement assurée par la fonction GetNmDomain(), qui renvoie une référence globale de type const ara::core::ErrorDomain& ([SWS_ANM_01109]). Une instanciation directe via le constructeur NmErrorDomain() ne devrait que rarement être nécessaire dans les scénarios d'utilisation typiques, dans la mesure où les composants applicatifs et de plate-forme récupèrent habituellement la référence singleton exposée via GetNmDomain().
