Signale l'achèvement réussi d'une opération sans valeur ou transporte un code d'erreur survenu.

La classe ara::core::Result<void, E> spécialise le patron Result pour les opérations sans valeur de retour et représente soit un achèvement réussi, soit une erreur ([SWS_CORE_00811]). Après l'exécution, l'appelant vérifie le statut de succès via HasValue() ([SWS_CORE_00851]) ou operator bool() et accède à la cause de l'erreur contenue en cas d'erreur. Comme contrainte obligatoire, le type d'erreur E doit correspondre au type ara::core::ErrorCode, car les types divergents sont rejetés dès la compilation.

Contexte

La classe modèle ara::core::Result<void, E> représente une spécialisation partielle du patron Result pour les opérations qui, en cas de succès, ne transmettent aucune valeur de retour (void), mais signalent exclusivement la réussite ou l'échec d'une action. Selon la définition du type, le type de valeur value_type est toujours fixé à void ([SWS_CORE_00811]), tandis que error_type représente le type d'erreur paramétré E ([SWS_CORE_00812]). Pour le type E, la consigne fonctionnelle stipule que toute divergence par rapport à ara::core::ErrorCode doit être rejetée par l'implémentation sous forme d'erreur de compilation.

Dans l'AUTOSAR Adaptive Platform, ara::core::Result<void, E> agit comme type de retour standardisé pour les procédures sujettes aux erreurs et les commandes de contrôle entre les composants appelants et les interfaces exécutantes. Au lieu des traitements d'exceptions C++ classiques, la classe offre une transmission d'erreur explicite et économe en ressources, qui permet aussi bien l'interrogation directe de l'état que des enchaînements fonctionnels dans le chemin d'appel.

Cycle de vie

Une instance de ara::core::Result<void, E> se trouve durant toute sa durée de vie dans exactement un de deux états discrets : l'état valeur (succès) ou l'état erreur. L'initialisation avec une valeur void s'effectue via le constructeur par défaut Result() ([SWS_CORE_00821]) ou la méthode de fabrique statique FromValue() ([SWS_CORE_00831]). Pour la création à l'état d'erreur, des constructeurs explicites pour les lvalues et rvalues du type d'erreur E sont disponibles ([SWS_CORE_00823], [SWS_CORE_00824]). En complément, les fonctions de fabrique FromError() permettent la construction à partir de lvalues d'erreur ([SWS_CORE_00834]), de rvalues ([SWS_CORE_00835]) ou par construction directe sur place à partir de packs de paramètres ([SWS_CORE_00836]).

Les instances déjà existantes peuvent être ultérieurement basculées vers l'état valeur via EmplaceValue() ([SWS_CORE_00843]) ou être directement affectées d'une nouvelle erreur via EmplaceError() ([SWS_CORE_00844]). Les constructeurs de copie et de déplacement ([SWS_CORE_00825], [SWS_CORE_00826]) ainsi que les opérateurs d'assignation correspondants ([SWS_CORE_00841], [SWS_CORE_00842]) transfèrent l'état entre instances ; Swap() échange les contenus de deux objets ([SWS_CORE_00845]).

Le destructeur ~Result() termine le cycle de vie ([SWS_CORE_00827]) et est trivial si std::is_trivially_destructible<E>::value s'applique. Concernant la concurrence, les opérations de simple lecture sont sûres au niveau des threads, tandis que les opérations modifiant l'état telles que EmplaceValue(), EmplaceError(), les assignations ou Swap() ne sont pas sûres au niveau des threads.

Diagramme d'états : Cycle de vie et transitions d'état entre l'état valeur et l'état erreur. Sources : [SWS_CORE_00821], [SWS_CORE_00831], [SWS_CORE_00823], [SWS_CORE_00834], [SWS_CORE_00843], [SWS_CORE_00844]

Parcours d'utilisation

Le déroulement régulier commence par la réception d'une instance ara::core::Result<void, E> issue d'un appel de fonction. L'appelant évalue le résultat via HasValue() ([SWS_CORE_00851]) ou la conversion operator bool() ([SWS_CORE_00852]). En cas d'exécution réussie, une opération ultérieure peut être enchaînée de manière fonctionnelle via Bind() ([SWS_CORE_00870]) : Bind() n'exécute le callable transmis que si l'instance contient une valeur, et renvoie son résultat transformé. En présence d'une erreur, la fonction appelée est ignorée et le contenu de l'erreur est repris dans le nouveau résultat.

Pour l'uniformisation dans le code générique, la spécialisation fournit des interfaces qui correspondent formellement à la classe Result générale : Value() ([SWS_CORE_00855]), operator*() ([SWS_CORE_00853]) et ValueOr() ([SWS_CORE_00861]) ne renvoient aucune valeur et agissent comme des méthodes sans effet (no-op). De manière analogue, Resolve() ([SWS_CORE_00867]) n'exécute un callable transmis que si une erreur est présente, et reste inactif en cas de succès.

Diagramme de séquence : Séquence typique d'appel, de vérification d'état et de traitement d'erreur ou d'enchaînement. Sources : [SWS_CORE_00851], [SWS_CORE_00857], [SWS_CORE_00868], [SWS_CORE_00870]

Scénarios d'erreur

Si l'instance se trouve dans l'état d'erreur, l'erreur contenue peut être interrogée sous forme de référence via les surcharges de Error() ([SWS_CORE_00857], [SWS_CORE_00858], [SWS_CORE_00876]). Une précondition stricte s'applique ici : l'appel de Error() sur une instance qui ne contient pas d'erreur constitue une ResultWithNoErrorViolation. Inversement, l'appel de Value() ([SWS_CORE_00855]) ou operator*() ([SWS_CORE_00853]) sur une instance à l'état d'erreur déclenche une ResultWithNoValueViolation.

Afin d'éviter des violations de préconditions, d'autres méthodes d'interrogation sont proposées : Err() fournit l'erreur encapsulée dans un ara::core::Optional<E> qui reste vide en cas de succès ([SWS_CORE_00868], [SWS_CORE_00869]). Avec ErrorOr(), une erreur par défaut peut être spécifiée pour être renvoyée si aucune erreur n'est contenue ([SWS_CORE_00863], [SWS_CORE_00864]). Pour vérifier des valeurs d'erreur spécifiques, CheckError() compare l'erreur interne à une valeur de comparaison ([SWS_CORE_00865]).

Si une gestion des erreurs basée sur des exceptions est préférée, ValueOrThrow() ([SWS_CORE_00866]) lève en cas d'erreur l'exception associée à l'erreur ; en présence d'une valeur, l'appel se termine normalement. Si les exceptions C++ sont désactivées dans la chaîne d'outils, ValueOrThrow() ne participe pas à la résolution de surcharge ([SWS_CORE_00866]).

Ce guide est basé sur la spécification ara::core::Result<void, E> dans la version R25-11 et a été généré automatiquement.

Utilisation et contexte d'appel

La fonction membre Bind de la spécialisation ara::core::Result<void, E> issue de ara/core/result.h exécute un calcul consécutif sur une instance de succès sans valeur de résultat [SWS_CORE_00870]. Si une valeur est présente, le callable transmis f est appelé de manière synchrone et sans paramètre. Le callable doit satisfaire soit l'interface Result<XXX, E> f() soit XXX f(), où XXX doit être un type admissible pour Result [SWS_CORE_00870]. Si le callable fournit un Result, le type de retour correspond à decltype(f()) ; s'il renvoie directement XXX, le résultat est encapsulé sous forme de Result<decltype(f()), E> [SWS_CORE_00870].

Gestion des erreurs et concurrence

Si l'instance ne contient aucune valeur, un nouveau Result<XXX, E> est renvoyé, dans lequel l'erreur d'origine est copiée [SWS_CORE_00870]. Interprétation : dans ce cas, l'exécution du callable f ne devrait pas avoir lieu. Question Q-6288a7106d2730c3 (ouverte) Concernant la sécurité d'exécution, la fonction est considérée comme not exception safe [SWS_CORE_00870]. La sécurité vis-à-vis des threads est conditionnelle (conditional) et dépend entièrement de la sécurité vis-à-vis des threads du callable transmis f [SWS_CORE_00870].

Interaction avec des exigences connexes

Contrairement aux fonctions primaires Result<T, E> issues de [SWS_CORE_00768] et [SWS_CORE_00941], pour lesquelles le callable reçoit la valeur de l'instance par f(const T&), la présente surcharge [SWS_CORE_00870] lie les opérations à des résultats void et attend par conséquent un callable sans paramètre.

En ce qui concerne la sécurité vis-à-vis des exceptions, l'opération est spécifiée comme not exception safe [SWS_CORE_00866].
                                                                                                  

                                                                                                  Pour le contexte d'appel et la concurrence, les conditions aux limites suivantes s'appliquent :

                                                                                                    •

                                                                                                    •
