But d'utilisation

Le proxy crée un wrapper d'événement pour chaque élément d'interface de service modélisé comme un événement. Après s'être connecté à l'instance de service, le consommateur s'abonne à l'événement ; le fournisseur envoie des données à Communication Management, qui en informe les abonnés. Les échantillons sont ensuite explicitement récupérés via GetNewSamples(). EXP ARAComAPI §4.3 « Event and Trigger based communication » §5.3.5 « Events »

Modèle d'abonnement, de cache et de réception

Subscribe(maxSampleCount) configure également le budget maximal du cache local de samples. L'appel accepte la demande de manière asynchrone ; le Subscription State peut être interrogé ou observé au moyen d'un gestionnaire de changement d'état. Pour les applications cycliques, l'interrogation avec GetNewSamples() suffit ; les applications réactives enregistrent un SetReceiveHandler() qui invite à récupérer les nouvelles données. EXP ARAComAPI §5.3.5.1 « Event Subscription and Local Cache » §5.3.5.2 « Monitoring Event Subscription » §5.3.5.5 « Event-Driven vs Polling-Based access »

Propriété des samples

Le SamplePtr transmis au rappel transfère la responsabilité d'un emplacement de cache à l'application. Tant qu'un SamplePtr est conservé, cet emplacement ne peut pas être réutilisé ; cela limite le nombre d'échantillons accessibles en même temps. EXP ARAComAPI §5.3.5.4 « Event Sample Management via SamplePtrs »
