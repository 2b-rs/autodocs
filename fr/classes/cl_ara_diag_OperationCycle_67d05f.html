Contexte de cycle pour le traitement des événements

OperationCycle rend visibles les modifications apportées à un cycle de fonctionnement configuré côté application. Le DM utilise des cycles d'opération dans le traitement du statut Event et de la mémoire d'erreur ; Le cycle est donc le contexte temporel dans lequel sont interprétés les résultats des tests et certains bits d'état SWS Diagnostics §7.3.4.3 « Operation Cycles Management » SWS Diagnostics §7.3.4.1.6 « Event Status processing ».

Les Operation Cycles fournissent le contexte temporel pour le traitement des états Event et DTC ; l’interface signale les changements de cycle à l’application. Sources : SWS Diagnostics §7.3.4.3 « Operation Cycles Management », SWS Diagnostics §7.3.4.1.6 « Event Status processing », SWS Diagnostics §7.3.4.4 « Event memory ». Interprétation partielle : les noms d’état résument le rôle temporel de l’API Operation Cycle.

Notifiant en tant que transfert d'état

SetNotifier enregistre un callback pour les changements d'Operation Cycle ; un enregistrement ultérieur remplace le callback existant [SWS_DM_00755]. L'implémentation du notifier ne devrait reprendre que l'état de cycle ou démarrer/arrêter ses propres chemins de vérification, et ne pas écrire elle-même des bits d'état d'événement.

Classer le redémarrage sémantiquement

RestartOperationCycle est un ordre DM explicite pour redémarrer un cycle d'opération. La question de savoir si et quelles conséquences d'événement/DTC en découlent dépend du traitement des événements configuré. Par conséquent, attribuez d'abord clairement le cycle notifié ou configuré et utilisez ensuite le redémarrage ; les actions de surveillance continueront d'être signalées via Monitor.
