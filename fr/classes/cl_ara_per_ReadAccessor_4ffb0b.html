classe ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Contexte

Au sein du module per (Persistency) de l'Adaptive Platform, la classe ara::per::ReadAccessor sert à la lecture séquentielle de contenus de fichiers persistants. Elle hérite virtuellement de FileAccessor et fournit des accès en lecture aussi bien en mode binaire qu'en mode texte. Grâce à cette abstraction, les applications accèdent aux données enregistrées sans devoir gérer directement le stockage physique. L'interface offre des opérations granulaires pour l'inspection de caractères ou d'octets individuels ainsi que des méthodes pour la lecture par blocs ou intégrale de contenus et de lignes.

Cycle de vie

Le cycle de vie d'une instance de ara::per::ReadAccessor est soumis à des règles strictes concernant la création et la gestion des ressources :

  • Création : le constructeur par défaut est explicitement supprimé conformément à [SWS_PER_00461] (delete). Une initialisation directe sans paramètre par l'application est donc exclue. Interprétation : une instance devrait par conséquent être créée via des mécanismes de niveau supérieur d'accès aux fichiers de persistance et transmise à l'appelant.
  • Destruction : le destructeur ~ReadAccessor() est déclaré virtuel, doté de override et défini comme noexcept [SWS_PER_00417]. Lors de la destruction de l'objet, les descripteurs de lecture sous-jacents sont libérés.
  • Concurrence et sécurité vis-à-vis des exceptions : l'ensemble des méthodes de la classe sont spécifiées comme not thread-safe (par exemple [SWS_PER_00417], [SWS_PER_00419]). L'accès simultané de plusieurs threads à la même instance requiert donc une synchronisation externe. Parallèlement, toutes les opérations de lecture sont sûres vis-à-vis des exceptions (exception safe) et déclarées comme noexcept ; les erreurs sont véhiculées par le type de retour ara::core::Result.

Parcours d'utilisation

L'utilisation de ara::per::ReadAccessor distingue les opérations d'inspection (sans modification de position) des opérations de lecture consommatrices (avec progression du curseur de fichier) :

  • Inspection (Peeking) : au moyen de PeekByte() [SWS_PER_00418] ou de PeekChar() [SWS_PER_00167], l'octet ou le caractère présent à la position actuelle peut être interrogé sans que la position de lecture ne soit modifiée. Les deux méthodes sont déclarées comme const.
  • Lecture pas à pas : via GetByte() [SWS_PER_00419] ou GetChar() [SWS_PER_00168], l'élément actuel est lu et le curseur interne est avancé d'une position.
  • Lecture par blocs (mode binaire) : avec ReadBinary(std::uint64_t n) [SWS_PER_00422], un nombre défini d'octets est lu dans un ara::core::Vector<ara::core::Byte>. Si la fin du fichier est atteinte avant d'atteindre n, le vecteur contient moins d'octets que demandé. La surcharge sans paramètre ReadBinary() [SWS_PER_00421] lit tous les octets restants jusqu'à la fin du fichier.
  • Mode texte et traitement de lignes : au moyen de ReadText(std::uint64_t n) [SWS_PER_00165] ou de ReadText() [SWS_PER_00420], des chaînes de caractères sont lues dans un ara::core::String. Pour les fichiers texte structurés, ReadLine(char delimiter = '\n') [SWS_PER_00119] permet la lecture ligne par ligne jusqu'au délimiteur. Le délimiteur n'est pas inclus dans la chaîne résultante. Si la position de lecture se trouve au sein d'un point de code Unicode, le texte renvoyé peut présenter des points de code incomplets.

Diagramme de séquence : déroulement typique d'un traitement de texte ligne par ligne, incluant l'inspection et la détection de la fin du fichier. Sources : [SWS_PER_00167], [SWS_PER_00119]

Scénarios d'erreur

Toutes les méthodes de lecture et d'inspection renvoient un ara::core::Result. En cas d'erreur survenue, une sémantique de rollback s'applique : la position de lecture actuelle du fichier n'est pas modifiée en cas d'erreur (spécifié notamment dans [SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00421], [SWS_PER_00119]). Les états d'erreur suivants issus du domaine d'erreur PerErrc sont spécifiés :

  • PerErrc::kEof : est renvoyé lorsque la position de lecture actuelle se trouve déjà à la fin du fichier ou que le fichier est vide ([SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00418], [SWS_PER_00167], [SWS_PER_00421], [SWS_PER_00422], [SWS_PER_00119], [SWS_PER_00165], [SWS_PER_00420]).
  • PerErrc::kPhysicalStorageFailure : se produit lorsque l'accès physique en lecture au support de stockage échoue ([SWS_PER_00420]).
  • PerErrc::kValidationFailed : indique que l'intégrité ou la validité des données enregistrées ne peut pas être garantie ([SWS_PER_00419]).
  • PerErrc::kEncryptionFailed : est renvoyé lorsque le déchiffrement des données utiles enregistrées échoue ([SWS_PER_00419]).
  • PerErrc::kAuthenticationFailed : se produit lorsque la vérification du Message Authentication Code (MAC) des données enregistrées échoue ([SWS_PER_00419]).

ReadLine fonction

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ara::core::Result< ara::core::String > ReadLine (char delimiter=’\n’) noexcept;
ReadText fonction 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.
