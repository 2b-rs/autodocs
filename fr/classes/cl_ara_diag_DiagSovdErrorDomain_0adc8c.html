Définit le domaine d'erreur pour l'identification, la traduction textuelle et le traitement des exceptions des erreurs issues de SOVD.

La classe ara::diag::DiagSovdErrorDomain encapsule le domaine d'erreur standardisé pour les erreurs de diagnostic spécifiques à SOVD au sein d'AUTOSAR Adaptive Platform ([SWS_DM_01809]). Par le biais de ses fonctions membres sûres pour les threads, elle permet la traduction fiable de codes d'erreur numériques en messages textuels ainsi que le déclenchement contrôlé de types d'exceptions C++ appropriés ([SWS_DM_01814]). Si les exceptions C++ sont désactivées dans la chaîne d'outils du compilateur, la méthode de déclenchement d'exceptions ne participe pas à la résolution de surcharge, conformément aux règles.

Contexte

La classe ara::diag::DiagSovdErrorDomain représente le domaine d'erreur spécifique pour les états d'erreur résultant du sous-système SOVD (Service-Oriented Vehicle Diagnostics) ([SWS_DM_01809], AUTOSAR_AP_SWS_Diagnostics §8.51.3 « Class: DiagSovdErrorDomain »). En tant que spécialisation finale de la classe d'infrastructure de base ara::core::ErrorDomain, elle intègre de manière transparente les codes d'erreur et les traitements d'exception associés du contexte SOVD dans le modèle d'erreur unifié d'AUTOSAR Adaptive Platform ([SWS_DM_01809]).

À des fins d'identification standardisée, la fonction membre Name() met à disposition le nom court (ApApplicationErrorDomain.SN) du domaine d'erreur conformément à [SWS_CORE_90023] ([SWS_DM_01813], AUTOSAR_AP_SWS_Diagnostics §8.51.3 « Class: DiagSovdErrorDomain »). De plus, la classe définit deux alias de type centraux pour son espace de noms : Errc fait office d'alias pour l'énumération sous-jacente DiagSovdErrc ([SWS_DM_01810], AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.1 « Type Alias: Errc ») et Exception représente la classe d'exception de base associée DiagSovdException ([SWS_DM_01811], AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.2 « Type Alias: Exception »). Dans la pratique, l'accès au domaine s'effectue généralement via la fonction libre ara::diag::GetDiagSovdErrorDomain ([SWS_DM_01816], AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 « GetDiagSovdErrorDomain »).

Cycle de vie

L'instanciation de ara::diag::DiagSovdErrorDomain s'effectue via le constructeur par défaut sans paramètre constexpr DiagSovdErrorDomain() noexcept ([SWS_DM_01812], AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.1.1 « Default Constructor »). Grâce à sa spécification en tant que constexpr et noexcept, la création est garantie sûre face aux exceptions et peut s'effectuer dès la compilation ou pendant l'initialisation statique. Interprétation : la mise à disposition du constructeur constexpr devrait permettre à la plateforme de maintenir une instance singleton de longue durée référencée via GetDiagSovdErrorDomain ([SWS_DM_01816]).

Concernant la concurrence, l'ensemble des fonctions membres de la classe sont explicitement déclarées comme sûres pour les threads (« thread-safe »). Cela s'applique au constructeur ([SWS_DM_01812]) tout comme aux opérations de lecture Name() ([SWS_DM_01813]) et Message() ([SWS_DM_01814]) ainsi qu'au déclenchement d'exceptions via ThrowAsException() ([SWS_DM_01815]). Plusieurs threads peuvent ainsi opérer en parallèle et sans mécanismes de synchronisation externes sur la même instance de domaine.

Parcours d'utilisation

Le déroulement normal pour l'utilisation de ara::diag::DiagSovdErrorDomain se divise selon les étapes suivantes :

  • Obtention du domaine : les appelants obtiennent généralement une référence au domaine d'erreur via la fonction globale ara::diag::GetDiagSovdErrorDomain ([SWS_DM_01816], AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 « GetDiagSovdErrorDomain ») ou créent au besoin leur propre instance via le constructeur par défaut ([SWS_DM_01812]).
  • Consultation du message d'erreur : pour traduire un code d'erreur numérique de type ara::core::ErrorDomain::CodeType (correspondant à Errc selon [SWS_DM_01810]) en texte lisible, Message(errorCode) est appelée ([SWS_DM_01814], AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.2.1 « Message »). La fonction renvoie un pointeur constant vers une chaîne de caractères (const char*) qui est garanti de ne jamais être nullptr ([SWS_DM_01814]). Interprétation : les chaînes de caractères résultantes devraient être des littéraux statiques, étant donné que la fonction est classifiée comme noexcept.
  • Traitement des exceptions : si un état d'erreur doit alternativement être propagé via des exceptions C++, l'application transmet l'instance de ara::core::ErrorCode à ThrowAsException(errorCode) ([SWS_DM_01815]), ce qui déclenche une exception de type correspondant du type Exception (DiagSovdException) ([SWS_DM_01811]).

Diagramme de séquence : séquence d'interaction typique pour la résolution de descriptions d'erreur et le déclenchement optionnel d'exceptions via le domaine d'erreur. Sources : [SWS_DM_01814], [SWS_DM_01815], [SWS_DM_01816].

Scénarios d'erreur

Dans le cadre du traitement des erreurs, l'interface de ara::diag::DiagSovdErrorDomain présente des caractéristiques de comportement spécifiques :

  • Retour textuel garanti : la méthode Message est déclarée comme noexcept et totalement sûre face aux exceptions (« exception safe ») ([SWS_DM_01814]). Elle n'échoue jamais et renvoie toujours une chaîne de caractères valide et non vide ([SWS_DM_01814]).
  • Déclenchement ciblé d'exceptions : la méthode ThrowAsException est destinée à lever des exceptions et porte donc noexcept(false) ainsi que la classification « not exception safe » ([SWS_DM_01815]). En fonction du ara::core::ErrorCode transmis, elle déclenche l'exception correspondante de type Exception (DiagSovdException) ([SWS_DM_01811], [SWS_DM_01815]).
  • Exceptions C++ désactivées : conformément à [SWS_CORE_10304], ThrowAsException ne participe pas à la résolution de surcharge lorsque les exceptions C++ sont désactivées dans la chaîne d'outils du compilateur ([SWS_DM_01815]). Dans de tels environnements, la fonction n'est pas disponible et les erreurs doivent obligatoirement être évaluées au moyen de codes d'erreur.

Ce guide se base exclusivement sur les prescriptions de spécification du module AUTOSAR diag (version R25-11).

Utilisation

Le constructeur par défaut initialise une instance du domaine d'erreurs ara::diag::DiagSovdErrorDomain [SWS_DM_01812] conformément à AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.1.1 « Default Constructor ». La fonction est déclarée comme constexpr ainsi que noexcept et nécessite l'inclusion de l'en-tête #include "ara/diag/diag_sovd_error_domain.h" [SWS_DM_01812].

Interaction et contexte d'appel

Dans les scénarios d'utilisation typiques, une instanciation manuelle directe via ce constructeur devrait être rarement requise, étant donné que l'interface fonctionnelle ara::diag::GetDiagSovdErrorDomain() fournit déjà une référence vers l'instance globale du domaine d'erreurs [SWS_DM_01816].

La classe DiagSovdErrorDomain définit le domaine d'erreurs pour SOVD et met à disposition des types et des fonctions essentiels :

  • Alias de types pour les codes d'erreur Errc [SWS_DM_01810] et la gestion des exceptions Exception [SWS_DM_01811].
  • Création d'instances de codes d'erreur via MakeErrorCode() [SWS_DM_01817].
  • Interrogation de nom via Name() [SWS_DM_01813] et traduction de texte via Message() [SWS_DM_01814] ainsi que déclenchement d'exceptions via ThrowAsException() [SWS_DM_01815].

Gestion des erreurs et concurrence

En tant que fonction noexcept sans paramètre, le constructeur ne lève aucune exception. Selon la spécification, l'appel est sûr vis-à-vis des exceptions (« exception safe ») et thread-safe en accès concurrent (« thread-safe ») [SWS_DM_01812]. Aucune précondition ni aucun code d'erreur spécifique n'est défini pour le constructeur.

          Utilisation
          

          
La méthode Name de la classe ara::diag::DiagSovdErrorDomain renvoie le nom court (ApApplicationErrorDomain.SN) du domaine d'erreurs SOVD de manière synchrone sous la forme d'une chaîne C (const char*) ([SWS_DM_01813] ; AUTOSAR_AP_SWS_Diagnostics §7 « Diagnostics »). La fonction n'attend aucun paramètre d'entrée et est fournie via l'en-tête ara/diag/diag_sovd_error_domain.h ([SWS_DM_01813]). Interprétation : le pointeur retourné devrait pointer vers une chaîne de caractères immuable, conservée de manière statique, qui reste valide pendant toute la durée d'exécution.

          

          Gestion des erreurs et concurrence
          

          
La fonction est déclarée comme noexcept et est considérée comme sans danger au niveau des exceptions (exception safe) ([SWS_DM_01813]). Elle ne signale aucun code d'erreur et ne génère d'entrées ni DET, ni DEM. Pour la concurrence, la méthode est spécifiée comme sûre pour les threads (thread-safe) ([SWS_DM_01813]). Elle possède ainsi des propriétés réentrantes et peut être appelée depuis n'importe quel thread sans mécanismes de synchronisation externes.

          

          Interaction
          

          
L'interface suit le modèle d'interrogation de noms unifié pour les domaines d'erreurs dans le diagnostic adaptatif. Des implémentations correspondantes se trouvent dans ara::diag::DiagErrorDomain ([SWS_DM_00521]), ara::diag::DiagUdsNrcErrorDomain ([SWS_DM_00533]), ara::diag::DiagOfferErrorDomain ([SWS_DM_00993]) ainsi que ara::diag::DiagReportingErrorDomain ([SWS_DM_01000]). Elle sert typiquement à la journalisation ainsi qu'à l'identification des domaines d'erreurs dans le contexte SOVD.

              La méthode ThrowAsException de la classe ara::diag::DiagSovdErrorDomain ([SWS_DM_01815], déclarée dans l'en-tête ara/diag/diag_sovd_error_domain.h ; voir AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.2.3 « ThrowAsException ») sert à convertir de manière synchrone un code d'erreur dans le type d'exception C++ assigné. Elle accepte le paramètre d'entrée errorCode de type const ara::core::ErrorCode & et ne possède aucune valeur de retour (void). Lors de l'appel, elle lève l'exception correspondant au code d'erreur selon la signature avec noexcept(false).
              


              Gestion des erreurs et conditions limites
              

              La spécification classe la méthode comme « not exception safe » ([SWS_DM_01815]). Interprétation : cette classification devrait s'expliquer par le fait que la levée intentionnelle d'une exception entraîne la sortie du flux de contrôle régulier. Une contrainte centrale concerne la chaîne d'outils du compilateur : selon [SWS_CORE_10304], ThrowAsException ne participe pas à la résolution de surcharge dès lors que les exceptions C++ sont désactivées dans le compilateur.
              


              Concurrence et interaction
              

              La fonction est classée comme sûre pour les threads (thread-safe) ([SWS_DM_01815]) et autorise l'appel concurrent. Le comportement suit le schéma standardisé pour les domaines d'erreurs de diagnostic dans le module DM. Des définitions analogues s'appliquent à ara::diag::DiagErrorDomain ([SWS_DM_00523], voir AUTOSAR_AP_SWS_Diagnostics §8.11.3.2.2.3 « ThrowAsException »), ara::diag::DiagOfferErrorDomain ([SWS_DM_00995], voir AUTOSAR_AP_SWS_Diagnostics §8.11.5.2.2.3 « ThrowAsException »), ara::diag::DiagReportingErrorDomain ([SWS_DM_01002], voir AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.3 « ThrowAsException ») ainsi qu'à ara::diag::DiagUdsNrcErrorDomain ([SWS_DM_00535], voir AUTOSAR_AP_SWS_Diagnostics §8.12.3.2.2.3 « ThrowAsException »).
