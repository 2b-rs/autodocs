Contexte

La classe C++ ara::rds::RawDataStreamClient fait partie du cluster fonctionnel Raw Data Stream (rds) de l'AUTOSAR Adaptive Platform dans la version R25-11. Elle sert de point de terminaison côté client pour la lecture et l'écriture de flux de données brutes binaires via une connexion réseau sous-jacente. Par l'intermédiaire d'un artefact de modélisation, identifié par ara::core::InstanceSpecifier, le client se lie à un port de communication concret et encapsule l'établissement de la connexion ainsi que le transport de données pour des flux d'octets spécifiques à l'application.

Cycle de vie

Une instance de ara::rds::RawDataStreamClient ne peut pas être instanciée via des constructeurs ordinaires. Le constructeur par défaut n'est pas accessible publiquement, et le constructeur de copie [SWS_RDS_11303] ainsi que l'opérateur d'affectation par copie [SWS_RDS_11304] sont tous deux explicitement supprimés (move-only). La création s'effectue à la place via la méthode de fabrique statique Create [SWS_RDS_10482] en transmettant le ara::core::InstanceSpecifier compétent. Create est spécifié comme thread-safe et retourne en cas de succès une instance de client initialisée dans un ara::core::Result.

La propriété est exclusive : le déplacement d'instances est possible via le constructeur de déplacement [SWS_RDS_11305] et l'opérateur d'affectation par déplacement [SWS_RDS_11306]. Les deux opérations sont déclarées avec noexcept, mais ne sont pas thread-safe.

Après la création, le client se trouve à l'état déconnecté. La connexion réseau active est ensuite établie via Connect [SWS_RDS_10484], [SWS_RDS_11307]. L'arrêt de la connexion s'effectue de manière ordonnée via Shutdown [SWS_RDS_10485]. Le destructeur ~RawDataStreamClient [SWS_RDS_10483] garantit qu'une connexion encore ouverte est automatiquement arrêtée lors de la sortie de la portée. Il est spécifié comme non thread-safe.

Parcours d'utilisation

Le déroulement régulier de la transmission de données binaires se divise en création, établissement de la connexion, transfert des données utiles et fermeture de la connexion :

  1. Instanciation : l'application crée le client de manière synchrone au moyen de Create(instance) [SWS_RDS_10482].
  2. Établissement de la connexion : avant le premier échange de données, la connexion est établie. À cet effet, soit la variante bloquante Connect() [SWS_RDS_10484], soit la surcharge avec temporisation Connect(timeout) [SWS_RDS_11307] comportant un timeout de type std::chrono::milliseconds est disponible.
  3. Envoyer des données : l'écriture s'effectue via WriteData(data, maxLength) [SWS_RDS_10487] ou WriteData(data, maxLength, timeout) [SWS_RDS_11310]. Les données utiles sont transmises en tant que std::unique_ptr<ara::core::Byte[]>, ce qui transfère la gestion exclusive du tampon mémoire à l'opération d'envoi.
  4. Recevoir des données : la lecture de données s'effectue à l'aide de ReadData(maxLength) [SWS_RDS_10486] ou de la variante avec surveillance temporelle ReadData(maxLength, timeout) [SWS_RDS_11309]. En cas de réception réussie, un ReadDataResult est renvoyé.
  5. Fermeture de la connexion : après l'achèvement de la transmission de données, l'application ferme explicitement la connexion réseau via Shutdown() [SWS_RDS_10485].

Diagramme de séquence : séquence d'appels typique depuis la création jusqu'à la fermeture de la connexion, en passant par le transfert de données. Sources : [SWS_RDS_10482], [SWS_RDS_10484], [SWS_RDS_10487], [SWS_RDS_10486], [SWS_RDS_10485]

Scénarios d'erreur

Toutes les interfaces fonctionnelles de ara::rds::RawDataStreamClient renoncent aux exceptions C++ et signalent le succès ou l'échec via le type de retour ara::core::Result avec une garantie noexcept :

  • Échec de l'établissement de la connexion : si le client ne parvient pas à établir de connexion avec l'entité distante ou si le délai spécifié expire, Connect échoue et fournit un code d'erreur appartenant au domaine d'erreur RdsErrc dans le ara::core::Result<void> [SWS_RDS_10484].
  • Erreurs lors des opérations d'écriture et de lecture : si la connexion est interrompue pendant le transfert ou si le délai d'attente de WriteData ou de ReadData est dépassé, l'objet résultat respectif contient le code d'erreur correspondant [SWS_RDS_10486], [SWS_RDS_10487], [SWS_RDS_11309], [SWS_RDS_11310].
  • Erreur de configuration : si le ara::core::InstanceSpecifier transmis n'est pas présent dans le modèle système ou n'est associé à aucun port de communication valide, Create échoue dès le départ et fournit une cause d'erreur correspondante dans l'objet Result [SWS_RDS_10482].

<h4>Contexte</h4>
<p>La classe C++ <code>ara::rds::RawDataStreamClient</code> fait partie du cluster fonctionnel <em>Raw Data Stream</em> (<code>rds</code>) de l'AUTOSAR Adaptive Platform dans la version R25-11. Elle sert de point de terminaison côté client pour la lecture et l'écriture de flux de données brutes binaires via une connexion réseau sous-jacente. Par l'intermédiaire d'un artefact de modélisation, identifié par <code>ara::core::InstanceSpecifier</code>, le client se lie à un port de communication concret et encapsule l'établissement de la connexion ainsi que le transport de données pour des flux d'octets spécifiques à l'application.</p>

<h4>Cycle de vie</h4>
<p>Une instance de <code>ara::rds::RawDataStreamClient</code> ne peut pas être instanciée via des constructeurs ordinaires. Le constructeur par défaut n'est pas accessible publiquement, et le constructeur de copie <a class="spec-record-ref" data-req="SWS_RDS_11303" href="../spec/record.html?id=SWS_RDS_11303">[SWS_RDS_11303]</a> ainsi que l'opérateur d'affectation par copie <a class="spec-record-ref" data-req="SWS_RDS_11304" href="../spec/record.html?id=SWS_RDS_11304">[SWS_RDS_11304]</a> sont tous deux explicitement supprimés (<em>move-only</em>). La création s'effectue à la place via la méthode de fabrique statique <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a> en transmettant le <code>ara::core::InstanceSpecifier</code> compétent. <code>Create</code> est spécifié comme thread-safe et retourne en cas de succès une instance de client initialisée dans un <code>ara::core::Result</code>.</p>
<p>La propriété est exclusive : le déplacement d'instances est possible via le constructeur de déplacement <a class="spec-record-ref" data-req="SWS_RDS_11305" href="../spec/record.html?id=SWS_RDS_11305">[SWS_RDS_11305]</a> et l'opérateur d'affectation par déplacement <a class="spec-record-ref" data-req="SWS_RDS_11306" href="../spec/record.html?id=SWS_RDS_11306">[SWS_RDS_11306]</a>. Les deux opérations sont déclarées avec <code>noexcept</code>, mais ne sont pas thread-safe.</p>
<p>Après la création, le client se trouve à l'état déconnecté. La connexion réseau active est ensuite établie via <code>Connect</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11307" href="../spec/record.html?id=SWS_RDS_11307">[SWS_RDS_11307]</a>. L'arrêt de la connexion s'effectue de manière ordonnée via <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_10485" href="../spec/record.html?id=SWS_RDS_10485">[SWS_RDS_10485]</a>. Le destructeur <code>~RawDataStreamClient</code> <a class="spec-record-ref" data-req="SWS_RDS_10483" href="../spec/record.html?id=SWS_RDS_10483">[SWS_RDS_10483]</a> garantit qu'une connexion encore ouverte est automatiquement arrêtée lors de la sortie de la portée. Il est spécifié comme non thread-safe.</p>

<h4>Parcours d'utilisation</h4>
<p>Le déroulement régulier de la transmission de données binaires se divise en création, établissement de la connexion, transfert des données utiles et fermeture de la connexion :</p>
<ol>
  <li><strong>Instanciation :</strong> l'application crée le client de manière synchrone au moyen de <code>Create(instance)</code> <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a>.</li>
  <li><strong>Établissement de la connexion :</strong> avant le premier échange de données, la connexion est établie. À cet effet, soit la variante bloquante <code>Connect()</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a>, soit la surcharge avec temporisation <code>Connect(timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11307" href="../spec/record.html?id=SWS_RDS_11307">[SWS_RDS_11307]</a> comportant un timeout de type <code>std::chrono::milliseconds</code> est disponible.</li>
  <li><strong>Envoyer des données :</strong> l'écriture s'effectue via <code>WriteData(data, maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_10487" href="../spec/record.html?id=SWS_RDS_10487">[SWS_RDS_10487]</a> ou <code>WriteData(data, maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11310" href="../spec/record.html?id=SWS_RDS_11310">[SWS_RDS_11310]</a>. Les données utiles sont transmises en tant que <code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code>, ce qui transfère la gestion exclusive du tampon mémoire à l'opération d'envoi.</li>
  <li><strong>Recevoir des données :</strong> la lecture de données s'effectue à l'aide de <code>ReadData(maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_10486" href="../spec/record.html?id=SWS_RDS_10486">[SWS_RDS_10486]</a> ou de la variante avec surveillance temporelle <code>ReadData(maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11309" href="../spec/record.html?id=SWS_RDS_11309">[SWS_RDS_11309]</a>. En cas de réception réussie, un <code>ReadDataResult</code> est renvoyé.</li>
  <li><strong>Fermeture de la connexion :</strong> après l'achèvement de la transmission de données, l'application ferme explicitement la connexion réseau via <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_10485" href="../spec/record.html?id=SWS_RDS_10485">[SWS_RDS_10485]</a>.</li>
</ol>

<h4>Scénarios d'erreur</h4>
<p>Toutes les interfaces fonctionnelles de <code>ara::rds::RawDataStreamClient</code> renoncent aux exceptions C++ et signalent le succès ou l'échec via le type de retour <code>ara::core::Result</code> avec une garantie <code>noexcept</code> :</p>
<ul>
  <li><strong>Échec de l'établissement de la connexion :</strong> si le client ne parvient pas à établir de connexion avec l'entité distante ou si le délai spécifié expire, <code>Connect</code> échoue et fournit un code d'erreur appartenant au domaine d'erreur <code>RdsErrc</code> dans le <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_RDS_10484" href="../spec/record.html?id=SWS_RDS_10484">[SWS_RDS_10484]</a>.</li>
  <li><strong>Erreurs lors des opérations d'écriture et de lecture :</strong> si la connexion est interrompue pendant le transfert ou si le délai d'attente de <code>WriteData</code> ou de <code>ReadData</code> est dépassé, l'objet résultat respectif contient le code d'erreur correspondant <a class="spec-record-ref" data-req="SWS_RDS_10486" href="../spec/record.html?id=SWS_RDS_10486">[SWS_RDS_10486]</a>, <a class="spec-record-ref" data-req="SWS_RDS_10487" href="../spec/record.html?id=SWS_RDS_10487">[SWS_RDS_10487]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11309" href="../spec/record.html?id=SWS_RDS_11309">[SWS_RDS_11309]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11310" href="../spec/record.html?id=SWS_RDS_11310">[SWS_RDS_11310]</a>.</li>
  <li><strong>Erreur de configuration :</strong> si le <code>ara::core::InstanceSpecifier</code> transmis n'est pas présent dans le modèle système ou n'est associé à aucun port de communication valide, <code>Create</code> échoue dès le départ et fournit une cause d'erreur correspondante dans l'objet <code>Result</code> <a class="spec-record-ref" data-req="SWS_RDS_10482" href="../spec/record.html?id=SWS_RDS_10482">[SWS_RDS_10482]</a>.</li>
</ul>
