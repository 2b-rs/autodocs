Point d’extension pour le tracing modélisé

apext::log::TraceArti est le point d’extension pour les messages Trace modélisés. La décision de routage peut être prise dès la compilation pour le message, le namespace et l’Executable, évitant ainsi une surcharge à l’exécution. SWS Log and Trace §7.6 « Tracing » [SWS_LOG_20001] [SWS_LOG_20004]

Découpler Trace et Log

Selon la configuration, la spécialisation générée n'achemine le message que vers le Logger, seulement vers ARTI, vers les deux, ou le rejette. (Interprétation : l'espace de noms constitue donc le pont délibérément étroit entre le code généré par l'outil Trace et l'API Log standard.)

fonction TraceArti [SWS_LOG_20000] Upstream: RS_LT_00003

template <typename MsgId, typename... Params> void TraceArti (const MsgId &msg_id, const Params &...                       params) noexcept;

Handles a modeled message, specific to the used trace tool. This function is only called internally by the Logger framework when switching between Log and TraceArti. It represents the interface to trace tools. The runtime overhead of this function shall be kept as minimal as possible, e.g. by using specializations based on the MsgId.
