Traduction du modèle dans l'espace de reliure

ara::com::runtime::ResolveInstanceIDs traduit un InstanceSpecifier unique dans l'exécutable en InstanceIdentifier technique configuré dans le Manifest de l'instance de service. La valeur de retour est un conteneur car un spécificateur peut pointer vers plusieurs instances techniques dans une liaison multiple. EXP ARAComAPI §4.8.1 « Instance Identifiers and Instance Specifiers » et SWS CM §7.5.21 « Instance Specifier Translation » fournissent la sémantique.

Lorsque vous avez explicitement besoin de la résolution

La plupart des API Find et Skeleton acceptent directement le InstanceSpecifier. La résolution explicite est donc particulièrement utile dans les cas dans lesquels la mission technique spécifique doit être traitée consciemment, comme par exemple les diagnostics ou les stratégies multi-liaison spéciales. EXP ARAComAPI §4.8.2 « When to use InstanceIdentifier versus InstanceSpecifier » décrit cette limite.

Le processus est documenté dans le guide du module sous la forme d'un diagramme d'activités : ara::com — Communication Management, diagramme d’activité « Résolution du InstanceSpecifier par rapport au manifeste ».

Utiliser délibérément la résolution du Manifest

ResolveInstanceIDs() lit l’affectation côté deployment d’un InstanceSpecifier et renvoie un InstanceIdentifierContainer. Un conteneur vide indique une affectation manquante, un conteneur à plusieurs valeurs indique un Multi-Binding. EXP ARAComAPI §4.8.1 « Instance Identifiers and Instance Specifiers » explique les résultats possibles.

Déroulement recommandé
  1. Fournir le Specifier à partir du contexte de port univoque.
  2. Result et vérifiez la taille du conteneur.
  3. En présence de plusieurs ID, appliquer une stratégie explicite de Binding/Failover.
  4. Pour la découverte standard, il est préférable d'utiliser la surcharge de spécificateur.
