Mappe les signaux de la RTE sur des I-PDU et gère leur émission, leur réception ainsi que leur surveillance via le PDU Router.

COM assemble les signaux et groupes de signaux de la RTE dans des I-PDU et les transmet au bus exclusivement via le PDU Router. Inversement, il désassemble les I-PDU reçues depuis Com_RxIndication et notifie la RTE [SWS_Com_00123]. L'émission s'effectue selon des modes de transmission configurés, Com_MainFunctionTx prenant en charge les parts cycliques. La communication n'a lieu que pour les I-PDU dont le groupe d'I-PDU est démarré, généralement par le BswM [SWS_Com_91001]. Les groupes arrêtés conduisent à COM_SERVICE_NOT_AVAILABLE ; la surveillance d'échéance (deadline monitoring) détecte les confirmations manquantes.

COM fait l'intermédiaire entre la RTE orientée signaux et la pile de communication orientée I-PDU. La RTE écrit des signaux avec Com_SendSignal et des groupes de signaux avec Com_SendSignalGroup [SWS_Com_00197] [SWS_Com_00200]. La lecture s'effectue via les API Receive correspondantes [SWS_Com_00198]. Vers le bas, le PDU Router constitue l'unique interface (RS COM p. 12). Le PduR appelle Com_RxIndication, Com_TxConfirmation et Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001].

Diagramme de contexte : intégration de COM entre RTE, BswM, J1939Rm et PduR. Sources : SWS PduR p. 24, SWS BswM p. 93

Après Com_Init, la communication inter-ECU n'est pas encore autorisée [SWS_Com_00432]. Elle est débloquée via des groupes d'I-PDU, que le BswM pilote le plus souvent avec Com_IpduGroupStart et Com_IpduGroupStop [SWS_Com_91001] [SWS_Com_91002]. Une I-PDU est active tant qu'au moins l'un de ses groupes est démarré [SWS_Com_00771]. Lors de l'arrêt, COM rejette les ordres d'émission en attente [SWS_Com_00777].

Lors de l'émission, la Transmission Mode Selection choisit entre deux modes configurés (TPS SystemTemplate p. 274). Com_MainFunctionTx prend en charge les parts cycliques [SWS_Com_00399]. Sur CAN, la transmission est directe ; sur FlexRay, le FrIf récupère les données par TriggerTransmit (SWS PduR p. 101). À la réception, COM rejette les signaux dont l'Update-Bit n'est pas armé ainsi que des groupes entiers de signaux si un signal de groupe est filtré [SWS_Com_00802] [SWS_Com_00836]. Pour les chaînes de transformateurs (transformers), l'accès par tableau via Com_SendSignalGroupArray est disponible [SWS_Com_00851].

Diagramme de séquence : émettre un groupe de signaux sur CAN (direct) ou FlexRay (TriggerTransmit), suivi de la confirmation à la RTE. Sources : SWS COM p. 87, SWS RTE p. 329

En cas d'erreur :

  • Les erreurs de développement telles que COM_E_UNINIT ou COM_E_PARAM_POINTER sont transmises au DET [SWS_Com_00442] [SWS_Com_00804].
  • En cas de groupe arrêté, les API renvoient COM_SERVICE_NOT_AVAILABLE [SWS_Com_00865].
  • Si une confirmation d'émission fait défaut, la surveillance d'échéance d'émission le signale via la ComTimeoutNotification [SWS_Com_00304].

Rôle de COM entre RTE et PDU Router

Le module AUTOSAR COM assure l'intermédiaire entre la vue orientée signaux de la RTE et la vue orientée I-PDU de la pile de communication. Les signaux et groupes de signaux sont insérés dans des I-PDU via Com_SendSignal et Com_SendSignalGroup [SWS_Com_00197] [SWS_Com_00200]. Ils sont relus à l'aide de Com_ReceiveSignal et Com_ReceiveSignalGroup [SWS_Com_00198] [SWS_Com_00201]. Vers le bas, le PDU Router est l'unique interface de COM (RS COM p. 12). COM y appelle PduR_ComTransmit [SWS_Com_00669]. Inversement, COM met à disposition du PduR les callbacks Com_RxIndication, Com_TxConfirmation et Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001]. Le PduR convertit alors les identifiants d'I-PDU entre module source et module de destination (SWS PduR p. 33).

Outre la RTE, d'autres modules du logiciel de base utilisent les interfaces de COM :

  • Le BswM contrôle via des interfaces optionnelles les groupes d'I-PDU, la surveillance de deadline de réception et les modes d'émission (SWS BswM p. 93).
  • Le J1939Rm déclenche de manière ciblée des I-PDU via Com_TriggerIPDUSendWithMetaData [SWS_Com_00858] (SWS J1939Rm p. 62).
  • COM signale les erreurs au DET [SWS_Com_00670].

Diagramme de contexte : COM se situe entre la RTE, le BswM et le J1939Rm en haut, et le PduR en bas. COM n'accède aux modules d'interface et de TP qu'exclusivement via le PduR. Sources : RS COM p. 12, SWS PduR p. 24, SWS BswM p. 93

Cycle de vie : initialisation, groupes d'I-PDU et état

Com_Init initialise les interfaces internes et externes ainsi que les variables avec une configuration de type Com_ConfigType. La communication inter-ECU n'est pas encore activée après cela [SWS_Com_00432] [SWS_Com_00825]. Com_GetStatus renvoie COM_UNINIT ou COM_INIT ; après une réinitialisation, COM_UNINIT s'applique [SWS_Com_00194] [SWS_Com_00819]. Com_DeInit arrête tous les groupes d'I-PDU démarrés et replace le module dans l'état non initialisé [SWS_Com_00130].

La communication est activée par groupe d'I-PDU :

  • Com_IpduGroupStart démarre un groupe, sur demande avec réinitialisation des données d'I-PDU. Com_IpduGroupStop l'arrête à nouveau [SWS_Com_91001] [SWS_Com_91002].
  • Une I-PDU est active tant qu'au moins un de ses groupes est démarré [SWS_Com_00771].
  • Les I-PDU sans affectation de groupe sont déjà démarrées par Com_Init, et ce de la même manière qu'avec initialize = true [SWS_Com_00840].
  • Lors de l'arrêt, COM abandonne les demandes d'émission en attente, y compris les répétitions [SWS_Com_00777]. COM ignore les confirmations d'émission ultérieures pour l'I-PDU arrêtée [SWS_Com_00800].

Généralement, le BswM commute les groupes via l'action BswMPduGroupSwitch. Son paramètre BswMPduGroupSwitchReinit correspond à l'argument initialize (SWS BswM p. 165). La composante d'émission cyclique commence après le timeOffset configuré à partir de Com_IpduGroupStart (TPS SystemTemplate p. 268).

Émission : du signal à l'I-PDU sur le bus

Com_SendSignal fonctionne de manière asynchrone [SWS_Com_00197]. Pour les données devant être transmises de façon atomique, la RTE procède en deux étapes : elle écrit d'abord tous les signaux de groupe avec Com_SendSignal. Ensuite, elle déclenche la transmission du groupe avec Com_SendSignalGroup (SWS RTE p. 329). COM positionne alors l'Update-Bit du groupe [SWS_Com_00801].

Les modes de transmission déterminent quand et à quelle fréquence une I-PDU est émise :

  • Deux modes (True/False) sont configurés statiquement par I-PDU. La Transmission Mode Selection choisit entre eux, y compris au moment de l'exécution (TPS SystemTemplate p. 274).
  • Alternativement, Com_SwitchIpduTxMode définit le mode de manière explicite [SWS_Com_00784]. Les émissions cycliques sont alors décalées de ComTxModeTimeOffset [SWS_Com_00881].
  • Com_TriggerIPDUSend déclenche une émission unique indépendamment du mode de transmission, mais uniquement pour les I-PDU démarrées [SWS_Com_00348] [SWS_Com_00861] (TPS SystemTemplate p. 371).
  • ComMinimumDelayTime impose un intervalle minimal entre deux émissions [SWS_Com_00828].

Com_MainFunctionTx prend en charge toutes les activités d'émission qui ne sont pas traitées directement dans les fonctions appelées par la RTE [SWS_Com_00399]. Si une ComPreparationNotification est configurée, elle appelle Com_CbkTxPrep avant le traitement de l'I-PDU [SWS_Com_00886] [SWS_Com_91013]. Un Com_TxIpduCallout peut empêcher la poursuite du traitement d'une I-PDU avec false [SWS_Com_00346].

Le déroulement diffère selon le système de bus :

  • CAN : L'I-PDU est directement transmise via PduR_ComTransmit.
  • FlexRay : Après PduR_ComTransmit, le FrIf ne récupère les données qu'au créneau d'émission par Com_TriggerTransmit (SWS PduR p. 101).
  • LIN : Les trames qui ne sont pas des trames sporadiques sont exclusivement récupérées par TriggerTransmit conformément au schedule (SWS PduR p. 88).

Com_TriggerTransmit ne copie rien et renvoie E_NOT_OK si le tampon proposé est trop petit ou si l'I-PDU est arrêtée [SWS_Com_00869] [SWS_Com_00884]. Avec Com_TxConfirmation, COM interrompt les temporisateurs de deadline d'émission en cours [SWS_Com_00880]. De plus, il signale chaque émission réussie via la notification configurée [SWS_Com_00883]. Avec un traitement IMMEDIATE, cela se produit immédiatement ; avec DEFERRED, cela a lieu de manière différée via un indicateur (SWS COM p. 91).

Réception : indication, dépaquetage et notification

Le PduR appelle Com_RxIndication avec l'ID d'I-PDU, la longueur, le pointeur de données et les MetaData [SWS_Com_00123]. Le chemin est identique pour CanIf, FrIf et LinIf ; le PduR n'effectue aucune mise en mémoire tampon (SWS PduR p. 97). L'I-PDU subit ensuite les vérifications suivantes :

  • Un Com_RxIpduCallout configuré est toujours appelé, et ce avant le traitement de compteur et avec l'I-PDU complète [SWS_Com_00889] [SWS_Com_00816]. S'il renvoie false, l'I-PDU n'est pas traitée davantage [SWS_Com_00700].
  • COM abandonne les signaux dont l'Update-Bit n'est pas positionné [SWS_Com_00802].
  • Si l'Update-Bit est absent parce que l'I-PDU reçue est plus courte que prévu, il est considéré comme positionné [SWS_Com_00794].
  • Si COM filtre un signal de groupe, il élimine l'ensemble du groupe de signaux [SWS_Com_00836].

Diagramme d'activité : décisions lors du traitement d'une I-PDU reçue jusqu'à la notification. Sources : [SWS_Com_00889] [SWS_Com_00700] [SWS_Com_00802] [SWS_Com_00794] [SWS_Com_00836] [SWS_Com_00726] ; l'ordre Update-Bit avant le filtre est une interprétation.

La façon dont COM notifie la RTE dépend du type de traitement. En cas d'IMMEDIATE, COM appelle les callbacks de la RTE directement dans le contexte de l'indication. En cas de DEFERRED, COM ne positionne dans un premier temps qu'un indicateur et copie les données (SWS COM p. 92). La vérification de cet indicateur devrait avoir lieu dans Com_MainFunctionRx, qui prend en charge le traitement de réception non effectué directement dans Com_RxIndication [SWS_Com_00398]. Pour les groupes de signaux, COM n'informe qu'une fois que tous les signaux de groupe sont dépaquetés. La RTE appelle alors exactement une fois Com_ReceiveSignalGroup puis Com_ReceiveSignal pour chaque signal de groupe (SWS RTE p. 329). COM mémorise les MetaData reçues pour la RTE [SWS_Com_00888].

Diagramme de séquence : indication par le PduR, notification IMMEDIATE par rapport à DEFERRED et récupération du groupe de signaux par la RTE. Sources : SWS COM p. 92, SWS RTE p. 329, [SWS_Com_00123]

Grandes I-PDU, tableaux de groupes de signaux et métadonnées

Les grandes I-PDU sont transmises via des protocoles de transport. Pour cela, COM met à disposition sa propre interface TP, compatible avec l'interface TP supérieure du PduR (SWS PduR p. 24) :

  • Réception : Com_StartOfReception, Com_CopyRxData et Com_TpRxIndication [SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650].
  • Émission : Com_CopyTxData et Com_TpTxConfirmation [SWS_Com_00693] [SWS_Com_00725].

Certaines règles particulières s'appliquent au fonctionnement TP :

  • Lors de TpSduLength = 0, COM signale la longueur maximale configurée [SWS_Com_00874].
  • Si une grande I-PDU est déclenchée à nouveau alors qu'elle est encore en cours de transmission, COM abandonne la demande supplémentaire [SWS_Com_00863].
  • Si Com_TriggerIPDUSend déclenche une émission alors que le tampon est verrouillé, COM met la demande en attente et l'émet ultérieurement [SWS_Com_00867].

Diagramme de séquence : réception segmentée d'une grande I-PDU via CanTp et PduR, simplifiée sans SecOC. Sources : SWS SecOC p. 111, [SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650] [SWS_Com_00838]

Pour les chaînes de transformateurs, la RTE accède aux groupes de signaux sous forme de tableau d'octets. Il existe pour cela Com_SendSignalGroupArray et Com_ReceiveSignalGroupArray [SWS_Com_00851] [SWS_Com_00854]. Les règles associées :

  • Étendue du tableau : Il commence à l'offset d'octet du signal de groupe ayant la plus petite ComBitPosition. Il se termine au dernier octet du signal de groupe ayant la plus grande ComBitPosition [SWS_Com_00844] [SWS_Com_00845].
  • Traitement : Lors de l'émission, COM traite l'appel concernant les Transfer Properties et la Transmission Mode Selection comme Com_SendSignalGroup [SWS_Com_00847]. Seul un ensemble restreint de filtres est pris en charge [SWS_Com_00848].
  • Conditions préalables : Les données doivent avoir une taille fixe, être alignées sur les octets et ne contenir aucun signal étranger [SWS_Com_00841]. Pour de tels groupes, les API de signaux individuels et de groupes ne sont pas autorisées [SWS_Com_00843].

Le COM Based Transformer sérialise les données exactement de la même manière que COM le ferait lui-même. D'autres transformateurs complètent ensuite le CRC et le compteur de séquence (SWS ComXf p. 14, EXP LSA p. 103).

Diagramme de séquence : la RTE exécute la chaîne de transformateurs et transmet le résultat avec un seul appel de Com_SendSignalGroupArray. Sources : SWS ComXf p. 14, [SWS_Com_00846] [SWS_Com_00847]

Les MetaData d'une I-PDU d'émission proviennent de la dernière transmission par la RTE ou, si aucune n'est disponible, de ComMetaDataDefault. Les MetaData transmises avec Com_TriggerIPDUSendWithMetaData ne s'appliquent qu'à l'émission ainsi déclenchée [SWS_Com_00887] [SWS_Com_00862].

Configuration, ordonnancement et passerelle de signaux

COM dispose de trois types de Main Functions : Com_MainFunctionRx, Com_MainFunctionTx et Com_MainFunctionRouteSignals. Chacune peut être instanciée plusieurs fois et est réentrante pour différentes instances [SWS_Com_00398] [SWS_Com_00399] [SWS_Com_00400]. Elles sont appelées sans paramètre par le BSW Scheduler (SWS BSWGeneral p. 79). Leurs périodes sont décrites par le EcuInstance via comConfigurationRxTimeBase, comConfigurationTxTimeBase et comConfigurationGwTimeBase (TR Interoperability p. 98). La notification associée Rte_COMCbkTxPrep_<mn> est liée à une instance particulière de Com_MainFunctionTx (SWS RTE p. 832).

La passerelle de signaux fait partie intégrante de COM (SRS Gateway p. 11). Elle retransmet les signaux reçus dans Com_MainFunctionRouteSignals [SWS_Com_00400]. Ce faisant, elle traverse des étapes de traitement définies du côté réception et du côté émission [SWS_Com_00872] [SWS_Com_00873]. Elle peut également mapper des signaux de groupe individuels sur des signaux autonomes [SWS_Com_00833].

La configuration est soumise à plusieurs contraintes :

  • Les types de données issus de [SWS_Com_00675] sont pris en charge. Les signaux de type UINT8_N et UINT8_DYN doivent être alignés sur les octets [SWS_Com_00105].
  • Toutes les I-PDU d'un groupe ont la même direction [SWS_Com_00871].
  • Si une valeur invalide est configurée pour un signal de réception, une ComDataInvalidAction doit également être configurée [SWS_Com_00859].

Les ID de signal, de groupe et de groupe d'I-PDU sont des valeurs de uint16 basées sur zéro [SWS_Com_00820] [SWS_Com_00821] [SWS_Com_00822]. Leurs noms symboliques sont dérivés de ComHandleId (TPS ECUConfiguration p. 138).

Comportement en cas d'erreur

COM signale les erreurs de développement via Det_ReportError avec le ModuleId 50 [SWS_Com_00442]. Sont définis :

  • COM_E_PARAM pour les paramètres incorrects [SWS_Com_00803].
  • COM_E_UNINIT pour les appels avant Com_Init ou après Com_DeInit. Les fonctions d'état, de version et les Main Functions sont exclues [SWS_Com_00804].
  • COM_E_PARAM_POINTER pour les pointeurs nuls [SWS_Com_00805].
  • COM_E_INIT_FAILED pour une sélection de configuration non valide [SWS_Com_00837].
  • Comme erreur d'exécution, COM_E_SKIPPED_TRANSMISSION pour les demandes d'émission rejetées [SWS_Com_00864].

Les API de signaux renvoient COM_SERVICE_NOT_AVAILABLE si le groupe d'I-PDU est arrêté ou en présence d'une erreur de développement [SWS_Com_00865]. Com_ReceiveSignalGroupArray copie néanmoins les dernières données connues [SWS_Com_00857].

Pour la surveillance de deadline d'émission, les règles suivantes s'appliquent :

  • Le temporisateur démarre lorsqu'un signal est transmis à la couche inférieure. La première fois, il est chargé avec ComFirstTimeout, ensuite avec ComTimeout [SWS_Com_00878] [SWS_Com_00879].
  • À son expiration, COM appelle la ComTimeoutNotification [SWS_Com_00304].
  • Dans le mode de transmission NONE, la surveillance est désactivée [SWS_Com_00835].

Du côté réception, il existe les mécanismes suivants :

  • Le BswM désactive et réactive le monitoring de deadline via Com_DisableReceptionDM et Com_EnableReceptionDM [SWS_Com_91003] [SWS_Com_91004] (SWS BswM p. 148).
  • Lorsqu'un temporisateur de réception expire, SUBSTITUTE remplace les valeurs par ComTimeoutSubstitutionValue [SWS_Com_00875] [SWS_Com_00876].
  • Si une réception TP échoue ou si le callout renvoie false, COM traite tous les signaux de l'I-PDU comme invalides [SWS_Com_00838] [SWS_Com_00839].
  • Si le compteur d'I-PDU présente un écart, COM appelle Com_CbkCounterErr [SWS_Com_00726].
