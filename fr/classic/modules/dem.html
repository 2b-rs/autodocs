Rôle du DEM dans la pile de diagnostic

Le Diagnostic Event Manager collecte tous les événements de diagnostic d'un calculateur. Il existe exactement un module DEM par ECU [SWS_Dem_00126]. Chaque événement est représenté par un EventId unique et un nom associé [SWS_Dem_00153]. Dans le type Dem_EventIdType, la valeur 0 n'est pas autorisée [SWS_Dem_00925]. Du côté entrée, les SW-C et les modules BSW signalent leurs résultats de test via Dem_SetEventStatus [SWS_Dem_00183]. Du côté sortie, le DCM utilise le DEM pour lire et effacer les codes d'erreur, l'état et les données associées SWS DCM p. 103.

Autres partenaires du DEM :

  • Le NvM prend en charge le stockage persistant [SWS_Dem_00164] [SWS_Dem_00329].
  • Le FiM est informé des changements d'état [SWS_Dem_00029] [SWS_Dem_01132].
  • Les moniteurs sont réinitialisés via InitMonitorForEvent, chacun avec un motif issu de Dem_InitMonitorReasonType [SWS_Dem_00003] [SWS_Dem_00942].
  • La prise en charge de J1939 est disponible lorsque DemGeneralJ1939 est configuré [SWS_Dem_00845].

Démarrage, fonctionnement et arrêt

Le DEM fait la distinction entre un mode pré-initialisé et le fonctionnement totalement initialisé [SWS_Dem_00169].

  • Dem_PreInit initialise les états internes nécessaires au traitement des événements [SWS_Dem_00180]. Le filtrage anti-rebond interne au DEM en fait partie [SWS_Dem_01213].
  • À partir de cet instant, les signalements filtrés sont possibles [SWS_Dem_01212].
  • Le DEM met en mémoire tampon dans une file d'attente les signalements qui arrivent avant Dem_Init [SWS_Dem_00167]. La taille de celle-ci est configurable [SWS_Dem_00207] [SWS_Dem_01079].
  • Ces signalements précoces ne déclenchent aucun callback d'état de moniteur [SWS_Dem_01289] SWS DEM p. 169.

Dem_Init reçoit un pointeur vers Dem_ConfigType et initialise ou réinitialise le module [SWS_Dem_00181] [SWS_Dem_00924].

  • Ce n'est qu'à ce moment-là que l'état du moniteur est initialisé. Auparavant, Dem_GetMonitorStatus renvoie la valeur E_NOT_OK [SWS_Dem_01326].
  • Après Dem_Init, le DEM est pleinement opérationnel [SWS_Dem_00340].
  • Un redémarrage d'un cycle de fonctionnement demandé auparavant n'est traité qu'ensuite [SWS_Dem_01318].
  • Dem_MainFunction effectue toutes les tâches non pilotées par événement [SWS_Dem_00125] [SWS_Dem_00266].
  • Dem_Shutdown clôture les opérations ouvertes [SWS_Dem_00102]. Les données non volatiles modifiées sont déclenchées vers la NVRAM au plus tard pendant l'arrêt [SWS_Dem_00341].

Du résultat de moniteur à l'événement qualifié

Dem_SetEventStatus transmet des valeurs de Dem_EventStatusType [SWS_Dem_00926] :

  • DEM_EVENT_STATUS_PASSED et DEM_EVENT_STATUS_FAILED sont déjà des résultats qualifiés.
  • …_PREPASSED et …_PREFAILED sont des résultats préliminaires que le DEM filtre en interne SWS DEM p. 351.

L'algorithme de filtrage anti-rebond est configuré par événement [SWS_Dem_00413]. Le choix comprend le filtrage par compteur [SWS_Dem_00414], temporel [SWS_Dem_00426] ou interne au moniteur [SWS_Dem_00437].

Filtrage anti-rebond basé sur compteur :

  • Les résultats préliminaires incrémentent ou décrémentent le compteur interne du pas configuré [SWS_Dem_00418] [SWS_Dem_00419].
  • Les résultats qualifiés définissent directement le compteur [SWS_Dem_00420] [SWS_Dem_00421].
  • Des seuils définissent l'état défaillant ou sain [SWS_Dem_00416] [SWS_Dem_00417].
  • Un comportement de saut est configurable en option [SWS_Dem_00422] [SWS_Dem_00424].
  • Le compteur est mis en correspondance de manière linéaire avec le Fault Detection Counter (−128…+127) [SWS_Dem_00415] SWS DEM p. 108.

Lors du filtrage anti-rebond temporel, un résultat préliminaire démarre un temporisateur [SWS_Dem_00428] [SWS_Dem_00432].

Diagramme d'activité : lors du filtrage anti-rebond basé sur compteur, l'état signalé détermine la variation du compteur ; l'atteinte d'un seuil qualifie l'événement. Sources : [SWS_Dem_00415]–[SWS_Dem_00421], SWS DEM p. 108, [SWS_Dem_00414], [SWS_Dem_00424], [SWS_Dem_00422]

Le traitement se divise en deux parties :

  • Le filtrage anti-rebond basé sur compteur [SWS_Dem_01279] et les bits 0 et 1 de l'état du moniteur [SWS_Dem_01280] s'exécutent de manière synchrone dans le contexte de l'appelant.
  • En revanche, le DEM calcule l'état UDS de manière asynchrone [SWS_Dem_01285].

Conditions d'autorisation et d'enregistrement :

  • Les conditions d'autorisation sont vérifiées par événement [SWS_Dem_00447] et définies via Dem_SetEnableCondition [SWS_Dem_00201].
  • Tant qu'une condition d'autorisation n'est pas remplie, les signalements ne sont pas acceptés [SWS_Dem_00449] DEXT p. 198. Selon DemDebounceBehavior, le filtrage anti-rebond est alors réinitialisé ou figé [SWS_Dem_00654] [SWS_Dem_00655].
  • Les conditions d'enregistrement régissent en revanche uniquement le stockage de l'événement dans la mémoire [SWS_Dem_00459] [SWS_Dem_00556].

Autres interventions dans le traitement des événements :

  • Dem_ResetEventDebounceStatus réinitialise le filtrage anti-rebond ou le fige [SWS_Dem_00684] [SWS_Dem_00685]. La qualification de l'événement n'en est pas affectée SWS DEM p. 267.
  • Dem_ResetEventStatus réinitialise TestFailed de manière asynchrone [SWS_Dem_00187].

Diagramme de séquence : la vérification de l'autorisation, le filtrage anti-rebond et l'état du moniteur s'exécutent de manière synchrone, l'état UDS et les callbacks de manière asynchrone. Sources : [SWS_Dem_00449], [SWS_Dem_01279], [SWS_Dem_01280], [SWS_Dem_01285], [SWS_Dem_00016], SWS DEM p. 85

Mémoire d'événements, octet d'état et cycles de fonctionnement

Le DEM gère par défaut tous les bits d'état UDS [SWS_Dem_00006]. Chaque transition de bit est définie individuellement, par exemple pour TestFailed [SWS_Dem_00386], ConfirmedDTC [SWS_Dem_00391] et WarningIndicatorRequested [SWS_Dem_00395] SWS DEM p. 88.

Structure de la mémoire d'événements :

  • Il existe une mémoire primaire [SWS_Dem_00010] et, en option, des mémoires définies par l'utilisateur [SWS_Dem_00548].
  • Celles-ci sont organisées en ensembles de mémoires d'événements [SWS_Dem_01247].
  • Le déclencheur de la création d'une entrée est configurable [SWS_Dem_00783]–[SWS_Dem_00786] SWS DEM p. 94.

Lorsque la mémoire est pleine :

  • Le DEM définit un indicateur de dépassement [SWS_Dem_00397], qui est lisible via Dem_GetEventMemoryOverflow [SWS_Dem_00559].
  • Il recherche un candidat conformément à la stratégie d'éviction [SWS_Dem_00400] [SWS_Dem_00401].
  • S'il n'y a aucun candidat, il rejette la demande de stockage [SWS_Dem_00407].

Les Freeze Frames et les Extended Data Records sont enregistrés selon le déclencheur configuré [SWS_Dem_00799]–[SWS_Dem_00802] [SWS_Dem_00809]. Un Freeze Frame pré-enregistré a alors la priorité [SWS_Dem_00464].

Diagramme d'activité : le stockage des événements s'effectue via la condition d'enregistrement, l'entrée libre, le dépassement et l'éviction. Sources : [SWS_Dem_00459], [SWS_Dem_00397], [SWS_Dem_00406]–[SWS_Dem_00409], SWS DEM p. 94, [SWS_Dem_00783], [SWS_Dem_00786], [SWS_Dem_00401], [SWS_Dem_00809]

Vieillissement (Aging) :

  • Chaque entrée possède un compteur de vieillissement [SWS_Dem_00019].
  • Le vieillissement commence après l'achèvement de la guérison [SWS_Dem_00698] SWS DEM p. 133.
  • Lorsque le seuil est atteint, ConfirmedDTC est réinitialisé [SWS_Dem_00498] et les données d'événement sont supprimées [SWS_Dem_01075].

Cycles de fonctionnement :

  • Dem_RestartOperationCycle fonctionne de manière asynchrone et réinitialise les moniteurs concernés [SWS_Dem_00194] [SWS_Dem_00679].
  • Il n'y a pas de file d'attente pour les redémarrages [SWS_Dem_01316].
  • Les cycles dépendants sont qualifiés avec Dem_SetCycleQualified [SWS_Dem_01221] [SWS_Dem_91001].

Accès à la mémoire des défauts selon le principe « sélectionner et interroger »

De nombreux services DCM fonctionnent selon le même modèle : un client sélectionne d'abord un DTC ou un groupe de DTC, puis appelle des fonctions qui opèrent sur cette sélection SWS DEM p. 215.

  • Dem_SelectDTC définit la cible entre autres pour Dem_ClearDTC, Dem_GetStatusOfDTC et Dem_SelectFreezeFrameData [SWS_Dem_91016] [SWS_Dem_01253].
  • La sélection se rapporte à la mémoire d'événements associée au ClientId [SWS_Dem_01254].
  • Les clients avec des ClientId différents sont autorisés à fonctionner en parallèle [SWS_Dem_01251].
  • Si le même client appelle à nouveau Dem_SelectDTC alors que l'opération précédente est toujours en cours, il reçoit DEM_BUSY [SWS_Dem_01306].

Lecture des Freeze Frames et des Extended Data :

  • Dem_SelectFreezeFrameData et Dem_SelectExtendedDataRecord s'appuient sur la sélection du DTC [SWS_Dem_01268] [SWS_Dem_01272].
  • Ensuite, des fonctions de taille et Next fournissent les données [SWS_Dem_00074] [SWS_Dem_00071] [SWS_Dem_00075]. Un Freeze Frame a le format {RecordNumber, NumOfDIDs, DID, data…} SWS DEM p. 225.
  • Si un enregistrement valide mais non stocké est demandé, le DEM renvoie E_OK avec un tampon vide [SWS_Dem_00630].
  • Afin que les données restent cohérentes, le DCM verrouille la mise à jour pendant la lecture avec Dem_DisableDTCRecordUpdate et lève le verrou avec Dem_EnableDTCRecordUpdate [SWS_Dem_00270] [SWS_Dem_00271].

Diagramme de séquence : les Freeze Frames sont sélectionnés et lus avec la mise à jour verrouillée ; DEM_PENDING conduit à des appels répétés. Sources : [SWS_Dem_01253], [SWS_Dem_01268], [SWS_Dem_00238], [SWS_Dem_00236], [SWS_Dem_00270], SWS DEM p. 290, [SWS_Dem_00071], [SWS_Dem_00271]

Fonctions de filtrage :

  • Dem_SetDTCFilter définit les critères de filtrage pour les interrogations ultérieures [SWS_Dem_00057]. Chaque appel redémarre l'itération [SWS_Dem_00649].
  • Ensuite, Dem_GetNumberOfFilteredDTC et Dem_GetNextFilteredDTC fournissent les correspondances [SWS_Dem_00061] [SWS_Dem_00216].
  • Au format OBD, Dem_GetNextFilteredDTC ne renvoie pas DEM_PENDING [SWS_Dem_00653].

Effacement et DTC-Setting :

  • Dem_ClearDTC interroge facultativement DemClearEventAllowed [SWS_Dem_00665] [SWS_Dem_00515] et réinitialise les moniteurs concernés [SWS_Dem_00680].
  • Dem_DisableDTCSetting empêche le stockage des événements concernés [SWS_Dem_00079] [SWS_Dem_00626].

Blocs fonctionnels dépendant de la configuration : OBD, J1939, composants

OBD :

  • Les API OBD ne sont disponibles que si DemOBDSupport est différent de DEM_OBD_NO_OBD_SUPPORT SWS DEM p. 315.
  • L'ECU maître calcule le PID $31/$4D/$4E pour l'ensemble du véhicule [SWS_Dem_00703] et est le seul à le signaler au Scan-Tool [SWS_Dem_00704].
  • Les ECU primaires reçoivent les valeurs via un SW-C qui appelle Dem_SetDataOfPID… [SWS_Dem_00735] [SWS_Dem_00736] SWS DEM p. 170.
  • L'état des conditions de dénominateur IUMPR est transmis entre les ECU [SWS_Dem_00714] [SWS_Dem_00716].
  • L'application signale les résultats de test (DTR) via Dem_SetDTR [SWS_Dem_00756].

Diagramme de collaboration : les valeurs PID sont calculées de manière centralisée dans l'ECU maître et distribuées aux ECU primaires. Sources : [SWS_Dem_00703], [SWS_Dem_00704], [SWS_Dem_00735], SWS DEM p. 170, [SWS_Dem_00736]

J1939 : pour le J1939Dcm, il existe des fonctions propres de filtrage avec état combiné des voyants [SWS_Dem_00855] [SWS_Dem_00857] et d'effacement [SWS_Dem_00878].

Composants (DemComponent) :

  • Chaque composant a un état FAILED et peut avoir des dépendances orientées vers d'autres composants [SWS_Dem_01118] [SWS_Dem_01119] [SWS_Dem_01120].
  • Si un composant tombe en panne, les composants dépendants sont également considérés comme défaillants [SWS_Dem_01124].
  • Le FiM interroge cet état via Dem_GetComponentFailed [SWS_Dem_01131].
  • Les composants non disponibles sont traités comme s'ils n'existaient pas dans le système [SWS_Dem_01134]. Après le démarrage, tous les composants sont disponibles [SWS_Dem_01239].

Disponibilité et suppression :

  • Dem_SetEventAvailable permet de masquer des événements au moment de l'exécution [SWS_Dem_01080] [SWS_Dem_01108]. En VARIANT-POST-BUILD, cette fonction n'est pas disponible [SWS_Dem_01106].
  • Un DTC supprimé est invisible pour l'outil de diagnostic [SWS_Dem_01100], mais continue à être traité en interne [SWS_Dem_01102].

Comportement en cas d'erreur

Les erreurs de développement (DET) sont définies dans [SWS_Dem_00173], notamment DEM_E_PARAM_POINTER, DEM_E_UNINIT et DEM_E_WRONG_CONDITION SWS DEM p. 238.

  • Les appels avant l'initialisation complète signalent DEM_E_UNINIT [SWS_Dem_00124]. Une règle propre s'applique à Dem_SetEventStatus et Dem_ResetEventDebounceStatus [SWS_Dem_00364].
  • Les appels après l'arrêt sont également détectés [SWS_Dem_00368].
  • Des conditions préalables manquantes signalent DEM_E_WRONG_CONDITION [SWS_Dem_00518].

Valeurs de retour en cours d'exécution :

  • Des sélections non valides entraînent DEM_WRONG_DTC ou DEM_WRONG_DTCORIGIN [SWS_Dem_01261] [SWS_Dem_01262].
  • En l'absence de sélection ou de filtre, le DEM renvoie E_NOT_OK [SWS_Dem_01299] [SWS_Dem_01300].
  • En cas de DEM_PENDING, l'appelant doit refaire une demande ultérieurement SWS DEM p. 289.

Rejets côté événement :

  • Dem_ResetEventStatus refuse si l'événement a déjà été testé au cours du cycle en cours [SWS_Dem_00638].
  • Dem_PrestoreFreezeFrame refuse si aucune mémoire n'est libre [SWS_Dem_00808].
  • Lorsque le DTC-Setting est désactivé, le bit WIR reste inchangé [SWS_Dem_00836].
  • Les modules BSW sont autorisés à ignorer la valeur de retour de Dem_SetEventStatus SWS DEM p. 273.

Erreurs de persistance :

  • Le DEM vérifie la validité et l'intégrité des données NvM [SWS_Dem_00339].
  • En cas d'erreurs de lecture, il réinitialise les données concernées [SWS_Dem_00578]. Le traitement des erreurs d'écriture est régi par [SWS_Dem_00579].
  • Les données pré-enregistrées incohérentes sont ignorées [SWS_Dem_01323].

Std_ReturnType Dem_ClearDTC (uint8 ClientId);

efface unique DTCs, ainsi que groupes de DTCs.

Utilisation et déroulement

La fonction Dem_ClearDTC supprime de manière asynchrone des DTC individuels ainsi que des groupes de DTC configurés [SWS_Dem_00665]. L'appelant est identifié par le paramètre ClientId [SWS_Dem_00665]. Avant l'appel, le DTC ou le groupe à supprimer, y compris DTCOrigin et DTCFormat, doit avoir été sélectionné via Dem_SelectDTC [SWS_Dem_01253]. Tant que l'opération de suppression est en cours, l'API fournit DEM_PENDING, ce qui requiert un nouvel appel ultérieurement ; ce n'est qu'après un achèvement réussi que E_OK est renvoyé [SWS_Dem_00665].

Gestion des erreurs et valeurs de retour

Si une erreur survient, des valeurs de retour spécifiques sont disponibles [SWS_Dem_00665] :

  • E_NOT_OK : Aucun DTC n'a été sélectionné au préalable [SWS_Dem_00665].
  • DEM_WRONG_DTC : Le DTC n'existe pas dans le format sélectionné [SWS_Dem_00665], le DTC sélectionné est supprimé [SWS_Dem_01100] ou la suppression est restreinte par DemClearDTCLimitation à DEM_ONLY_CLEAR_ALL_DTCS alors qu'un autre groupe a été sélectionné [SWS_Dem_00670].
  • DEM_WRONG_DTCORIGIN : L'emplacement mémoire spécifié n'existe pas [SWS_Dem_00665].
  • DEM_CLEAR_FAILED ou DEM_CLEAR_MEMORY_ERROR : La suppression a échoué ou une erreur est survenue lors de la suppression de blocs NVRAM [SWS_Dem_00665].
  • DEM_CLEAR_BUSY : Un autre client effectue déjà une opération de suppression [SWS_Dem_00665].
  • DEM_BUSY : Une autre opération dépendante de Dem_SelectDTC est déjà en cours pour le même client [SWS_Dem_00665].

Concurrence et interaction

Dem_ClearDTC est réentrante pour différentes valeurs de ClientId, mais n'est pas réentrante pour la même ClientId [SWS_Dem_00665]. Le DEM traite en interne les appels parallèles de plusieurs clients [SWS_Dem_00661] ; si une opération de suppression est déjà en cours, le client demandeur reçoit DEM_PENDING [SWS_Dem_00664].

Lorsqu'un DTC combiné est supprimé, le DEM nettoie tous les événements associés [SWS_Dem_00440]. Le module déclenche alors pour les événements concernés le callback InitMonitorForEvent avec le motif DEM_INIT_MONITOR_CLEAR [SWS_Dem_00680]. Si DemTriggerMonitorInitBeforeClearOk est configuré sur TRUE, E_OK n'est renvoyé que lorsque cette initialisation a été initiée [SWS_Dem_00573]. De plus, l'indicateur de dépassement de la mémoire est réinitialisé dès que tous les DTC qu'elle contient sont supprimés [SWS_Dem_00399].

La fonction synchrone Dem_ClearPrestoredFreezeFrame ([SWS_Dem_00193]) efface une trame figée précédemment préenregistrée (Prestored Freeze Frame) d'un événement spécifique. L'identification de l'événement transmise via EventId (type Dem_EventIdType) sert de paramètre de transmission. La fonction renvoie E_OK si l'effacement a réussi, et E_NOT_OK en cas d'erreur ([SWS_Dem_00193]). Elle doit être appelée exclusivement via la RTE, raison pour laquelle aucune déclaration de fonction n'est fournie via Dem.h ([SWS_Dem_00193]).

Configuration et disponibilité : L'interface n'est disponible que si au moins un événement est configuré dans le système pour le préenregistrement de trames figées (DemFFPrestorageSupported == true) ; dans le cas contraire, l'API n'est pas fournie par le module DEM ([SWS_Dem_00193], [SWS_Dem_00334]).

Concurrence et restrictions :

  • Réentrance : La fonction est réentrante pour des appels avec des ID d'événement différents (EventId), mais n'est pas réentrante pour des appels avec le même EventId ([SWS_Dem_00193]).
  • Événements non disponibles : Si un événement est déclaré comme non disponible, il est traité par le DEM comme s'il n'était pas configuré dans le système ; Dem_ClearPrestoredFreezeFrame fait partie des API concernées ([SWS_Dem_01108]).

Interaction lors du déclenchement multi-événements :

  • Si l'API est appelée avec un EventId configuré comme événement maître (DemMultiEventTriggeringMasterEventRef), le DEM transmet l'appel de manière synchrone avec les mêmes paramètres à tous les événements esclaves associés (DemMultiEventTriggeringSlaveEventRef) ([SWS_Dem_01250]).
