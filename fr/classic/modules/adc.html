Commande les convertisseurs analogique-numérique du microcontrôleur via des groupes de canaux et fournit leurs valeurs brutes.

Le pilote ADC encapsule dans le MCAL les convertisseurs analogique-numérique du microcontrôleur et convertit toujours les canaux sous forme de groupes configurés : déclenchés par logiciel ou par matériel, uniques ou continus [SWS_Adc_00515]. Après Adc_Init, des utilisateurs tels que l'IoHwAb lancent des conversions. Ils détectent la fin par interrogation d'état ou par notification, puis lisent les valeurs brutes à l'aide de Adc_ReadGroup ou Adc_GetStreamLastPointer. Le pilote prend optionnellement en charge les changements d'état de puissance à deux niveaux. Principale contrainte : aucune conversion de groupe ne doit démarrer sans mémoire tampon de résultat préalablement configurée avec Adc_SetupResultBuffer [SWS_Adc_91000].

Le pilote ADC encapsule dans le MCAL les convertisseurs analogique-numérique du microcontrôleur. L'EcuM l'initialise avec Adc_Init [SWS_Adc_00365]. L'utilisateur typique est l'IoHwAb ; elle reçoit la notification IoHwAb_AdcNotification<#groupID> après la fin d'une conversion de groupe [SWS_Adc_00082]. Avant la première conversion, une mémoire tampon de résultat suffisamment grande doit être configurée avec Adc_SetupResultBuffer après chaque réinitialisation [SWS_Adc_91000].

Diagramme de contexte : EcuM initialise, IoHwAb commande et reçoit les notifications, les erreurs sont transmises au DET, les conversions s'exécutent dans la périphérie. Sources : SWS IoHwAb p. 55, [SWS_Adc_00377]

Le pilote convertit toujours les canaux sous forme de groupes configurés. Chaque groupe possède trois réglages :

  • Source de déclenchement : logicielle ou matérielle [SWS_Adc_00514].
  • Mode de conversion : One-Shot ou Continuous ; Continuous uniquement avec déclenchement logiciel [SWS_Adc_00515].
  • Mode d'accès : Single ou Streaming avec mémoire tampon linéaire ou circulaire [SWS_Adc_00528], [SWS_Adc_00519].

L'état de groupe indique la progression avec ADC_IDLE, ADC_BUSY, ADC_COMPLETED et ADC_STREAM_COMPLETED [SWS_Adc_00513].

Diagramme d'états : état de groupe lors d'une conversion continue en streaming ; une mémoire tampon linéaire se termine en ADC_IDLE après lecture. Sources : SWS ADC p. 39

Adc_StartGroupConversion démarre et Adc_StopGroupConversion arrête les groupes déclenchés par logiciel. Les groupes déclenchés par matériel sont commutés via Adc_EnableHardwareTrigger et Adc_DisableHardwareTrigger [SWS_Adc_00367], [SWS_Adc_91001]. L'utilisateur détecte la fin par Scrutation de Adc_GetGroupStatus ou par notification ; il doit activer cette dernière séparément SWS ADC p. 57. Les valeurs brutes non mises à l'échelle sont lues avec Adc_ReadGroup ou Adc_GetStreamLastPointer [SWS_Adc_00369], [SWS_Adc_00375].

Des mécanismes de priorité, de mise en file d'attente et de préemption régulent les demandes concurrentes [SWS_Adc_00522], [SWS_Adc_00523]. En l'absence des deux, le pilote rejette une seconde demande avec ADC_E_BUSY [SWS_Adc_91006]. Le pilote change optionnellement d'état de puissance en deux étapes : préparation avec Adc_PreparePowerState, commutation avec Adc_SetPowerState. Les parties asynchrones s'exécutent dans Adc_Main_PowerTransitionManager [SWS_Adc_00478], [SWS_Adc_00479].

Rôle du pilote ADC entre l'IoHwAb et le matériel de conversion

Le pilote ADC est le module MCAL dédié aux convertisseurs analogique-numérique du microcontrôleur. Adc_Init initialise les unités matérielles ADC et le pilote [SWS_Adc_00365]. Tous les autres services opèrent sur des groupes de canaux référencés par un ID numérique (Adc_GroupType) [SWS_Adc_00507]. L'utilisateur typique est l'I/O Hardware Abstraction : elle démarre les conversions pour le compte d'un SWC de capteur et est notifiée après achèvement via IoHwAb_AdcNotification<#groupID> [SWS_Adc_00082], SWS IoHwAb p. 55. L'EcuM initialise le pilote, pour lequel Adc_Init constitue une interface optionnelle SWS EcuM p. 142.

Le pilote se situe au niveau architectural le plus bas. Il n'offre donc aucun rappel pour les modules sous-jacents SWS ADC p. 79. L'API de l'ADC n'accède pas directement aux registres de résultat matériels. Les résultats parviennent toujours à l'utilisateur via les mémoires tampons de l'application SWS ADC p. 27. Le pilote signale les erreurs via Det_ReportError [SWS_Adc_00377]. Les passages de documents cités proviennent principalement de R23-11 à R25-11. Les exigences sont normatives pour R20-11.

Diagramme de contexte : le pilote ADC assure l'intermédiation entre EcuM, IoHwAb, DET et les périphériques de conversion ; les notifications ne remontent que vers le haut. Sources : SWS IoHwAb p. 55, [SWS_Adc_00082], [SWS_Adc_00480], [SWS_Adc_00377]

L'implémentation doit rejeter les configurations présentant des affectations de partition non prises en charge [SWS_Adc_00531]. Les partitions référencées via AdcKernelEcucPartitionRef doivent être un sous-ensemble des partitions de AdcEcucPartitionRef [SWS_Adc_CONSTR_00001]. Interprétation : cela devrait recouvrir la division entre une partie noyau proche des interruptions et une partie interface, comme le montre l'exemple de mappage mémoire pour Adc SWS MemMap p. 57.

Cycle de vie : initialisation, mémoire tampon de résultat et désinitialisation

Après la réinitialisation, le pilote se trouve dans ADC_UNINIT. Adc_Init mène à ADC_INIT, Adc_DeInit ramène en arrière SWS ADC p. 31. Adc_Init est synchrone et non réentrant. Dans la variante PB, ConfigPtr pointe vers le jeu de configuration ; la variante PC exige NULL_PTR [SWS_Adc_00365]. Adc_ConfigType est une structure spécifique à l'implémentation [SWS_Adc_00505]. Le configurateur crée les noms symboliques pour les canaux et les groupes dans l'en-tête de configuration SWS ADC p. 123.

Diagramme d'états : Adc_Init et Adc_DeInit basculent entre ADC_UNINIT et ADC_INIT ; One-Shot et Continuous sont des options de configuration pour chaque groupe. Sources : SWS ADC p. 31, SWS ADC p. 91

Après chaque réinitialisation, l'utilisateur doit transmettre l'adresse de début du tampon de résultats avec Adc_SetupResultBuffer avant la première conversion d'un groupe. L'application s'assure que le tampon peut recevoir tous les résultats du groupe [SWS_Adc_91000]. Aucune conversion ne doit démarrer sans pointeur de tampon initialisé de manière valide SWS ADC p. 54.

Adc_DeInit ramène toutes les unités matérielles dans un état comparable au reset à la mise sous tension (power-on reset) [SWS_Adc_00366]. Le service masque toutes les interruptions et notifications utilisées. Il n'est autorisé que si tous les groupes sont dans ADC_IDLE, et peut être désactivé via AdcDeInitApi SWS ADC p. 59.

Groupes de canaux : modes de déclenchement, de conversion et d'accès

Un groupe rassemble des canaux [SWS_Adc_00517], [SWS_Adc_00506]. Il est configuré selon trois axes :

  • Source de déclenchement : ADC_TRIGG_SRC_SW ou ADC_TRIGG_SRC_HW [SWS_Adc_00514].
  • Mode de conversion : ADC_CONV_MODE_ONESHOT convertit chaque canal exactement une fois par déclenchement. ADC_CONV_MODE_CONTINUOUS convertit en continu et n'est possible qu'avec un déclenchement logiciel [SWS_Adc_00515].
  • Mode d'accès : ADC_ACCESS_MODE_SINGLE ou ADC_ACCESS_MODE_STREAMING [SWS_Adc_00528]. En streaming, Adc_StreamNumSampleType définit le nombre de cycles [SWS_Adc_00518]. Un tampon linéaire arrête la conversion dès qu'il est plein ; un tampon circulaire fonctionne en boucle [SWS_Adc_00519].

Le prédiviseur, le temps de conversion, le temps d'échantillonnage et la résolution ne sont pas des types d'API [SWS_Adc_00509], [SWS_Adc_00510], [SWS_Adc_00511], [SWS_Adc_00512]. Pour les déclenchements matériels, le front et le rechargement de temporisateur peuvent être configurés si le matériel le prend en charge [SWS_Adc_00520], [SWS_Adc_00521]. Les résultats sont des valeurs brutes non mises à l'échelle, alignées à gauche ou à droite [SWS_Adc_00508], [SWS_Adc_00525].

La progression d'un groupe est décrite par Adc_StatusType [SWS_Adc_00513] :

  • ADC_IDLE : non démarré.
  • ADC_BUSY : conversion en cours.
  • ADC_COMPLETED : un cycle est terminé, mais pas le dernier.
  • ADC_STREAM_COMPLETED : tampon de résultats complet.

Les transitions dépendent de la configuration SWS ADC p. 39.

Diagramme d'états : état de groupe lors d'une conversion continue déclenchée par logiciel avec streaming ; le tampon linéaire se termine dans ADC_IDLE après lecture, le tampon circulaire continue de tourner. Sources : SWS ADC p. 39, SWS ADC p. 70, [SWS_Adc_00513]

Du démarrage au résultat : séquences de conversion typiques

Dans le cas le plus simple, une conversion one-shot se déroule en trois étapes SWS ADC p. 91 :

  1. Adc_StartGroupConversion démarre le groupe de manière asynchrone [SWS_Adc_00367].
  2. Adc_GetGroupStatus interroge l'état [SWS_Adc_00374].
  3. Adc_ReadGroup lit les résultats [SWS_Adc_00369].

Le démarrage réinitialise le pointeur de tampon à l'adresse de base. Il n'active pas automatiquement la notification SWS ADC p. 57.

Diagramme de séquence : configuration du tampon, démarrage, scrutation de l'état, lecture. Sources : SWS ADC p. 91, [SWS_Adc_91000]

Au lieu de scruter, l'utilisateur peut appeler préalablement Adc_EnableGroupNotification [SWS_Adc_91003]. AdcGrpNotifCapability active ce service SWS ADC p. 67. En conversion continue, le pilote signale chaque cycle achevé. Cela ne se termine qu'avec Adc_StopGroupConversion [SWS_Adc_00368], SWS ADC p. 92.

Diagramme de séquence : à chaque cycle achevé succèdent une notification et une lecture, jusqu'à ce que l'utilisateur arrête. Sources : SWS ADC p. 92, [SWS_Adc_00082]

Adc_EnableHardwareTrigger active les groupes déclenchés par matériel [SWS_Adc_91001]. Ensuite, le groupe effectue une conversion à chaque événement de déclenchement SWS ADC p. 62. Adc_DisableHardwareTrigger [SWS_Adc_91002] a plusieurs effets SWS ADC p. 65 :

  • Il supprime les requêtes en attente.
  • Il interrompt une conversion en cours si le matériel le prend en charge.
  • Il désactive la notification.
  • Il réinitialise le groupe à ADC_IDLE.

En cas de streaming linéaire, le déclenchement se désactive dès que le tampon est plein SWS ADC p. 95.

Diagramme de séquence : chaque événement de déclenchement déclenche une conversion ; une notification n'est émise que si elle est active. Sources : SWS ADC p. 93

Deux voies existent pour la lecture :

  • Adc_ReadGroup copie les valeurs du dernier cycle complet dans l'ordre croissant des canaux. Si aucun résultat n'est disponible, il renvoie E_NOT_OK [SWS_Adc_00369], SWS ADC p. 61.
  • Adc_GetStreamLastPointer fournit le nombre d'échantillons valides par canal ainsi qu'un pointeur vers le résultat le plus récent du premier canal du groupe [SWS_Adc_00375]. L'utilisateur doit alors prendre en compte lui-même l'organisation du tampon par canal SWS ADC p. 27.

Groupes concurrents : priorité, mise en file d'attente et préemption

Adc_PriorityImplementationType régit les requêtes simultanées : aucun mécanisme, matériel uniquement, ou matériel et logiciel [SWS_Adc_00522]. Les priorités vont de 0 (la plus basse) à 255 [SWS_Adc_00516]. Si un groupe est interrompu par un groupe de priorité supérieure, son cycle redémarre (ADC_GROUP_REPL_ABORT_RESTART) ou reprend (ADC_GROUP_REPL_SUSPEND_RESUME). Les résultats des cycles précédents sont conservés dans les deux cas [SWS_Adc_00523].

Sans priorité ni mise en file d'attente, le pilote rejette une deuxième requête avec ADC_E_BUSY SWS ADC p. 95. Avec une file d'attente logicielle, il l'enregistre et la démarre ultérieurement SWS ADC p. 96. Avec priorisation, le groupe de priorité supérieure préempte celui en cours SWS ADC p. 97, SWS ADC p. 98. Adc_StopGroupConversion supprime également une requête de démarrage en attente SWS ADC p. 58.

Diagramme d'activité : le fait qu'une requête soit rejetée, enregistrée ou priorisée lorsque le convertisseur est occupé dépend du mécanisme de priorité et de la mise en file d'attente. Sources : [SWS_Adc_00522], [SWS_Adc_00523], SWS ADC p. 99

États de puissance du matériel ADC

La gestion de puissance est optionnelle et limitée aux périphériques ADC. Les couches supérieures satisfont aux contraintes architecturales ; le pilote vérifie uniquement l'ordre des appels SWS ADC p. 39. Adc_PowerStateType reconnaît ADC_FULL_POWER (0) et les états 1..255 avec une consommation décroissante [SWS_Adc_00526]. Adc_PowerStateRequestResultType signale le résultat de chaque requête [SWS_Adc_00527].

La transition s'effectue en deux étapes :

  1. Préparer : Adc_PreparePowerState démarre la préparation [SWS_Adc_00478]. Les parties asynchrones s'exécutent dans le cyclique Adc_Main_PowerTransitionManager [SWS_Adc_00498], [SWS_Adc_00479]. Sa période est fixée par AdcMainSchedulePeriod [SWS_Adc_00500]. En mode asynchrone, il signale l'état prêt via IoHwAb_Adc_NotifyReadyForPowerState<#Mode> [SWS_Adc_00501], [SWS_Adc_00480].
  2. Basculer : Adc_SetPowerState active l'état préparé [SWS_Adc_00475]. Les travaux préalables tels que les canaux au repos incombent aux utilisateurs. Il n'existe pas d'états intermédiaires implicites SWS ADC p. 81.

Diagramme de séquence : transition d'état de puissance asynchrone, coordonnée par l'IoHwAb. Sources : SWS IoHwAb p. 57, SWS IoHwAb p. 57, [SWS_Adc_00479]

Pour Adc_SetPowerState, l'interprétation suivante s'applique en outre probablement : l'état normal utilise les mêmes conteneurs de configuration que Adc_Init, les autres états n'utilisant que des reconfigurations spécifiques aux transitions [SWS_Adc_00483], [SWS_Adc_00484], [SWS_Adc_00485]. Adc_GetCurrentPowerState et Adc_GetTargetPowerState fournissent l'état réel et l'état cible [SWS_Adc_00476], [SWS_Adc_00477]. Sans transition en cours, les deux concordent SWS ADC p. 77.

Comportement en cas d'erreur

Le pilote signale les erreurs de développement via Det_ReportError [SWS_Adc_00377]. [SWS_Adc_91005] mentionne notamment :

  • ADC_E_UNINIT
  • ADC_E_ALREADY_INITIALIZED
  • ADC_E_PARAM_POINTER
  • ADC_E_PARAM_GROUP
  • ADC_E_WRONG_CONV_MODE
  • ADC_E_WRONG_TRIGG_SRC
  • ADC_E_NOTIF_CAPABILITY

Deux exemples : en cas de groupe inconnu, les services de notification signalent ADC_E_PARAM_GROUP et retournent sans effet SWS ADC p. 68. Adc_GetVersionInfo vérifie son pointeur sur NULL SWS ADC p. 80.

Les erreurs d'exécution sont ADC_E_BUSY (conversion en cours, déclencheur actif ou requête déjà dans la file d'attente), ADC_E_IDLE, ADC_E_NOT_DISENGAGED et ADC_E_TRANSITION_NOT_POSSIBLE [SWS_Adc_91006]. Les services avec valeur de retour signalent en outre l'échec avec E_NOT_OK, comme Adc_ReadGroup et Adc_SetupResultBuffer [SWS_Adc_00369], [SWS_Adc_91000].

Des erreurs spécifiques s'appliquent à la gestion de puissance :

  • ADC_E_UNINIT : appel avant l'initialisation [SWS_Adc_00486], [SWS_Adc_00496].
  • ADC_E_POWER_STATE_NOT_SUPPORTED : état non pris en charge [SWS_Adc_00488], [SWS_Adc_00497].
  • ADC_E_TRANSITION_NOT_POSSIBLE : état cible non atteignable directement [SWS_Adc_00489], [SWS_Adc_00498].
  • ADC_E_NOT_DISENGAGED : canaux encore actifs ou notifications encore enregistrées [SWS_Adc_00487].

Result distingue en outre ADC_SEQUENCE_ERROR et ADC_HW_FAILURE [SWS_Adc_00527]. Avant l'initialisation, Adc_Main_PowerTransitionManager retourne sans notification DET [SWS_Adc_00502].

initialise le ADC matériel unités et pilote.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: 8695b1caa4ff Provenance

La fonction synchrone Adc_Init (ID de service 0x00) sert à la configuration initiale et à la mise en service de toutes les unités matérielles ADC ainsi que du pilote ADC conformément à [SWS_Adc_00365]. L'interface est mise à disposition via le fichier d'en-tête Adc.h et ne possède aucune valeur de retour.

Paramètres et variantes de configuration

La transmission des données de configuration s'effectue via le paramètre pointeur ConfigPtr de type const Adc_ConfigType* [SWS_Adc_00365]. L'argument requis dépend de la variante de build choisie :

  • En cas d'utilisation de la configuration post-build (Variant PB), ConfigPtr doit pointer vers la structure de données correspondante avec les valeurs d'initialisation.
  • Si la variante de précompilation (Variant PC) est utilisée, l'interface exige explicitement la transmission d'un NULL_PTR [SWS_Adc_00365].

Concurrence et intégration système

La fonction Adc_Init est spécifiée comme non réentrante (Non Reentrant) [SWS_Adc_00365]. Interprétation : Étant donné que les unités matérielles sont configurées de manière globale et qu'il n'y a pas de réentrance, l'appel devrait typiquement avoir lieu de manière centralisée lors de l'initialisation du système, avant que d'autres fonctions du module ou conversions ne soient initiées.

Concernant la gestion de l'énergie, il existe un couplage direct avec des exigences connexes : si l'état d'énergie normal (normal Power State) est demandé en fonctionnement, l'API correspondante doit recourir à des paramètres de configuration situés dans les mêmes conteneurs que les paramètres d'initialisation de Adc_Init [SWS_Adc_00483].
