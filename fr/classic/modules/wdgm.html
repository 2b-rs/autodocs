Surveille le déroulement et la synchronisation temporelle du logiciel via des points de contrôle (checkpoints) et commande en fonction de cela le déclenchement des watchdogs.

Le Watchdog Manager surveille l'exécution du logiciel. Les Supervised Entities signalent des points de contrôle via WdgM_CheckpointReached [SWS_WdgM_00263]. Le cyclique WdgM_MainFunction évalue l'Alive, la Deadline et la Logical Supervision et consolide les résultats en statuts locaux et un statut global. Tant que tout est en ordre, le WdgM applique une condition de déclenchement valide via la Watchdog Interface. Si le statut global atteint STOPPED, le pilote ne déclenche plus et une réinitialisation par watchdog s'ensuit [SWS_WdgM_00360]. Les changements de mode ne sont autorisés qu'avec un statut global OK ou FAILED.

Le Watchdog Manager surveille l'exécution des Supervised Entities et ne laisse les watchdogs matériels continuer à être déclenchés que tant que la surveillance est correcte. La temporisation du déclenchement elle-même incombe au pilote de watchdog. Le WdgM ne définit qu'une condition de déclenchement (SWS WdgM p. 56) via la Watchdog Interface. Il requiert impérativement pour cela WdgIf_SetMode, WdgIf_SetTriggerCondition, GetElapsedValue et Det_ReportRuntimeError [SWS_WdgM_00161].

Après WdgM_Init, la surveillance commence avec le premier appel de WdgM_MainFunction [SWS_WdgM_00406]. Les entités signalent des points de contrôle via WdgM_CheckpointReached [SWS_WdgM_00263]. Chaque appel incrémente l'Alive Counter et vérifie immédiatement la Deadline et la Logical Supervision (SWS WdgM p. 79). La fonction principale évalue périodiquement les Alive Counters et les délais d'expiration de deadline [SWS_WdgM_00404].

Diagramme de séquence : les points de contrôle sont acquis sur événement, l'évaluation et le déclenchement s'effectuent de manière cyclique. Sources : SWS WdgM p. 32, [SWS_WdgM_00263]

Un statut local est généré par entité à partir des résultats. FAILED est alors récupérable, EXPIRED ne l'est pas [SWS_WdgM_00359]. À partir de là, le WdgM forme un statut global qui s'intensifie via EXPIRED vers STOPPED. Dans STOPPED, le pilote ne déclenche plus et une réinitialisation par watchdog s'ensuit [SWS_WdgM_00360]. Le WdgM signale les changements d'état via des ports de mode locaux et un port de mode global [SWS_WdgM_00197] [SWS_WdgM_00198].

Diagramme d'états : Global Supervision Status de DEACTIVATED à STOPPED ; deux transitions sont signalées comme interprétation. Sources : [SWS_WdgM_00387], [SWS_WdgM_00360]

Les changements de mode par WdgM_SetMode ne sont possibles qu'avec un statut global OK ou FAILED [SWS_WdgM_00145]. Si WdgMOffModeEnabled est FALSE, le WdgM refuse un mode Off [SWS_WdgM_00031]. En cas d'échec de WdgIf_SetMode, le statut global passe à STOPPED (SWS WdgM p. 57). Après une réinitialisation, WdgM_GetFirstExpiredSEID fournit dès avant WdgM_Init l'entité qui a expiré en premier [SWS_WdgM_00346] [SWS_WdgM_00348].

Rôle : surveillance logicielle entre les Supervised Entities et le watchdog matériel

Le Watchdog Manager (WdgM) surveille l'exécution des Supervised Entities, c'est-à-dire des SW-C, CDD ou processus BSW. Selon le résultat, il décide si les watchdogs matériels continuent d'être déclenchés. La temporisation réelle du déclenchement incombe au pilote de watchdog. Le WdgM applique uniquement, via la Watchdog Interface, une condition de déclenchement qui ordonne au pilote de poursuivre le déclenchement (SWS WdgM p. 56). Il requiert impérativement pour cela WdgIf_SetMode, WdgIf_SetTriggerCondition, GetElapsedValue et Det_ReportRuntimeError [SWS_WdgM_00161]. Il utilise de manière optionnelle Dem_SetEventStatus, Det_ReportError, Mcu_PerformReset et BswM_WdgM_RequestPartitionReset [SWS_WdgM_00162].

Les Supervised Entities signalent des points de contrôle via WdgM_CheckpointReached [SWS_WdgM_00263]. Les modules de gestion de mode contrôlent le cycle de vie avec WdgM_Init, WdgM_SetMode et WdgM_DeInit [SWS_WdgM_00151] [SWS_WdgM_00154] [SWS_WdgM_00261]. L'évaluation cyclique est assurée par WdgM_MainFunction à partir de SchM_WdgM.h [SWS_WdgM_00159]. Le concept de sécurité attribue au WdgM la surveillance logique du flux de programme par le biais de points de contrôle et de transitions autorisées (SafetyConceptStatusReport p. 15).

Diagramme de contexte : le WdgM relie les notifications de points de contrôle de l'application à la pile de watchdog ainsi qu'à Os, DET, DEM, Mcu et BswM. Sources : [SWS_WdgM_00161], [SWS_WdgM_00162], SWS WdgM p. 85

Cycle de vie : initialisation, changements de mode et désinitialisation

Le Global Supervision Status est préaffecté statiquement avec WDGM_GLOBAL_STATUS_DEACTIVATED [SWS_WdgM_00387]. Dans cet état, les services rejettent les requêtes avec WDGM_E_UNINIT ou retournent sans effet [SWS_WdgM_00253] [SWS_WdgM_00395]. WdgM_Init reçoit un pointeur vers WdgM_ConfigType [SWS_WdgM_00355]. La fonction initialise toutes les variables du module et établit le mode initial (SWS WdgM p. 74). Interprétation : ensuite, le statut global devrait être WDGM_GLOBAL_STATUS_OK, car les entités actives dans le mode initial démarrent localement avec OK (SWS WdgM p. 30).

Un nouvel appel de WdgM_Init en dehors de DEACTIVATED reste sans effet [SWS_WdgM_00390]. Une réinitialisation s'effectue donc via WdgM_DeInit suivi de WdgM_Init (SWS WdgM p. 74). La surveillance et le Watchdog Handling ne commencent qu'avec le premier appel de WdgM_MainFunction après l'initialisation [SWS_WdgM_00406].

WdgM_SetMode bascule vers un autre mode configuré [SWS_WdgM_00154], mais uniquement avec un statut global OK ou FAILED [SWS_WdgM_00145]. Pour les entités désactivées dans le nouveau mode :

  • Elles passent à WDGM_LOCAL_STATUS_DEACTIVATED [SWS_WdgM_00315].
  • Leurs résultats sont à nouveau considérés comme corrects [SWS_WdgM_00315].
  • Leur compteur d'erreurs est remis à 0 [SWS_WdgM_00315].

Les entités restant actives conservent leur état [SWS_WdgM_00182]. Pour chaque watchdog, le WdgM définit les paramètres de mode via WdgIf_SetMode [SWS_WdgM_00186]. Tant qu'un changement est en cours, WdgM_GetMode fournit encore l'ancien mode (SWS WdgM p. 77).

Diagramme d'activité : un changement de mode passe par la vérification de statut, la protection contre le mode Off et la définition des modes de watchdog ; si cette dernière échoue, il se termine dans STOPPED. Sources : [SWS_WdgM_00145], [SWS_WdgM_00031], [SWS_WdgM_00186], [SWS_WdgM_00139] ; l'ordre de vérification est une interprétation

Lors de la transition vers SLEEP, l'EcuM appelle WdgM_DeInit. La fonction bascule d'abord vers un mode de veille défini par l'intégrateur. Ainsi, malgré les watchdogs fenêtrés, la condition de déclenchement autorise le reste de l'arrêt sans reset. Ensuite, le module se désinitialise (SWS WdgM p. 59). La surveillance et le Watchdog Handling s'arrêtent alors [SWS_WdgM_00407]. Pendant SLEEP, le BswM ou l'EcuM doivent prendre en charge le déclenchement.

Diagramme de séquence : du démarrage à la désinitialisation avant SLEEP, en passant par le changement de mode. Sources : SWS WdgM p. 102, [SWS_WdgM_00406], [SWS_WdgM_00408], [SWS_WdgM_00407]

Points de contrôle et les trois fonctions de surveillance

Une Supervised Entity signale un Checkpoint avec WdgM_CheckpointReached(SEID, CheckpointID) [SWS_WdgM_00263]. Les deux identifiants sont de type uint16. Un Checkpoint n'est unique que grâce à la paire constituée de la SE-ID et de la Checkpoint-ID [SWS_WdgM_00356] [SWS_WdgM_00357]. L'appel accomplit trois tâches (SWS WdgM p. 79) :

  • Il incrémente l'Alive Counter du Checkpoint.
  • Il vérifie la Deadline Supervision quant à une arrivée trop précoce ou trop tardive.
  • Il exécute la Logical Supervision.

Si l'entité est désactivée dans le mode actuel, le service renvoie E_NOT_OK et signale WDGM_E_SEDEACTIVATED [SWS_WdgM_00319].

L'Alive Supervision vérifie les séquences cycliques. La fonction principale évalue les Alive Counters au rythme de WdgMSupervisionReferenceCycle, un multiple du Supervision Cycle (SWS WdgM p. 42). La Deadline Supervision vérifie si les limites WdgMDeadlineMin/WdgMDeadlineMax sont respectées entre le Checkpoint de début et de fin. Les horodatages sont fournis par GetElapsedValue avec l'OS-Counter de l'entité ; la mise à l'échelle s'effectue via OsSecondsPerTick [SWS_WdgM_00373] [SWS_WdgM_00374]. Si l'horodatage initial est 0, la vérification se termine avec succès sans mesure [SWS_WdgM_00354]. Si le Checkpoint de fin est manquant, WdgM_MainFunction détecte un timeout, pour autant que WdgMEnableTimeoutDetection soit défini [SWS_WdgM_00403] [SWS_WdgM_00404].

La Logical Supervision vérifie l'ordre des Checkpoints. Il existe pour chaque graphe un Activity Flag que WdgM_Init met à false. Un graphe commence à un Initial Checkpoint (SWS WdgM p. 51). Les graphes internes appartiennent à une entité et s'appliquent dans tous les modes. Les graphes externes relient plusieurs entités et sont configurés par mode (SWS WdgM p. 46, [SWS_WdgM_00366]).

Diagramme de séquence : les Checkpoints sont acquis de manière événementielle, l'évaluation et le déclenchement s'effectuent de façon cyclique dans la fonction principale. Sources : SWS WdgM p. 32, [SWS_WdgM_00263], [SWS_WdgM_00404], [SWS_WdgM_00197]

Statut de surveillance local et global

À partir des trois résultats, le WdgM détermine le Local Supervision Status pour chaque entité (SWS WdgM p. 30). WDGM_LOCAL_STATUS_FAILED est réversible : si l'entité adopte à nouveau un comportement normal, elle revient à OK. Si les échecs dépassent une limite, elle bascule vers WDGM_LOCAL_STATUS_EXPIRED [SWS_WdgM_00359]. Cette tolérance ne s'applique qu'à l'Alive Supervision. En cas d'erreurs de Deadline ou Logical, le premier résultat incorrect conduit dès lors à EXPIRED (SWS WdgM p. 30).

Diagramme d'états : cycle de vie du Local Supervision Status d'une Supervised Entity. Sources : SWS WdgM p. 30, [SWS_WdgM_00359], [SWS_WdgM_00315]

Pour l'ensemble du logiciel, il existe un Global Supervision Status avec les valeurs DEACTIVATED, OK, FAILED, EXPIRED et STOPPED (SWS WdgM p. 36). EXPIRED signifie : la limite d'erreurs est dépassée, mais le pilote déclenche encore. Dans STOPPED, le pilote a pour consigne de ne plus déclencher, et un reset du watchdog s'ensuit [SWS_WdgM_00360]. WdgMExpiredSupervisionCycleTol définit la durée pendant laquelle le WdgM reste dans EXPIRED en multiples du Supervision Cycle (SWS WdgM p. 36).

Diagramme d'états : escalade du Global Supervision Status jusqu'au reset ; les deux transitions signalées comme interprétation ne sont pas formellement documentées. Sources : [SWS_WdgM_00387], [SWS_WdgM_00360], SWS WdgM p. 36, SWS WdgM p. 57

Ports, messages d'état et services d'interrogation

Pour chaque Supervised Entity, le WdgM met à disposition un port de surveillance [SWS_WdgM_00146]. Il s'appelle localSupervision_{SupervisedEntityCheckpointName} et porte la SE-ID et la Checkpoint-ID comme arguments définis par le port [SWS_WdgM_00147] [SWS_WdgM_00333]. Le statut local est interrogé via localSupervisonStatus_{SupervisedEntityName} [SWS_WdgM_91003] [SWS_WdgM_91004]. Les requêtes globales telles que GetGlobalStatus ou GetFirstExpiredSEID passent par globalSupervision [SWS_WdgM_91002] [SWS_WdgM_91001].

Le WdgM notifie de lui-même les changements d'état via des Mode-Ports : mode_{SupervisedEntityName} pour chaque entité et une seule fois globalmode [SWS_WdgM_00149] [SWS_WdgM_00150]. Tous deux utilisent le Mode Declaration Group WdgM_Mode avec les valeurs SUPERVISION_OK à SUPERVISION_DEACTIVATED [SWS_WdgM_00334]. Les changements locaux sont notifiés immédiatement, les globaux une seule fois chacun [SWS_WdgM_00197] [SWS_WdgM_00199]. Le Mode-Port local et le Mode-Port global ont des interfaces distinctes. Ainsi, les ports locaux peuvent être adressés via l'Indirect Port API sans que le port global n'apparaisse dans cette liste (SWS WdgM p. 101).

Diagramme de collaboration : les SW-C et les utilisateurs globaux sont reliés au WdgM via des Service-Ports et des Mode-Ports. Sources : SWS WdgM p. 99, [SWS_WdgM_00147], [SWS_WdgM_00149], [SWS_WdgM_00150], [SWS_WdgM_91002]

Les services d'interrogation et WdgM_CheckpointReached sont réentrants. WdgM_SetMode et WdgM_PerformReset ne le sont pas [SWS_WdgM_00175] [SWS_WdgM_00263] [SWS_WdgM_00154] [SWS_WdgM_00264]. Les modules BSW qui commandent ou interrogent le WdgM de manière globale le décrivent via GlobalSupervisionNeeds (TPS BSWMDT p. 257).

Configuration : modes, Supervised Entities et déclenchements de watchdog

Le WdgM prend en charge VARIANT-PRE-COMPILE et VARIANT-POST-BUILD (SWS WdgM p. 97). Les paramètres compatibles post-build se trouvent dans WdgM_ConfigType [SWS_WdgM_00355]. L'ECU Integrator effectue la configuration de manière descendante et évalue pour cela les ServiceNeeds issues de l'ECU Extract (TR Methodology p. 389). SupervisedEntityNeeds décrivent pour chaque entité, entre autres, l'activation au démarrage, la désactivation autorisée, les temps de cycle d'Alive et les cycles d'erreur tolérés (SWC-Template p. 716).

Un WdgMMode comprend les parties suivantes (SWS WdgM p. 119) :

  • WdgMModeId
  • WdgMExpiredSupervisionCycleTol
  • Conteneurs pour l'Alive Supervision, la Deadline Supervision et la Logical Supervision externe
  • Conteneurs pour les paramètres de statut locaux
  • WdgMTrigger

Un déclencheur définit WdgMWatchdogMode (FAST/SLOW/OFF) et WdgMTriggerConditionValue (SWS WdgM p. 125). WdgMGeneral contient des commutateurs tels que WdgMDevErrorDetect et WdgMImmediateReset (SWS WdgM p. 107). Pour la Deadline Supervision, chaque entité requiert un OS-Counter (SWS WdgM p. 46).

Comportement en cas d'erreur

Lorsque WdgMDevErrorDetect est actif, le WdgM signale les erreurs de développement au DET, telles que WDGM_E_UNINIT, WDGM_E_PARAM_SEID, WDGM_E_INV_POINTER ou WDGM_E_CPID [SWS_WdgM_00004]. Si le module n'est pas initialisé, un schéma fixe s'applique : avec vérification, WDGM_E_UNINIT est signalé ; sans vérification, le service retourne sans effet [SWS_WdgM_00279] [SWS_WdgM_00394]. Comme erreurs d'exécution, on trouve WDGM_E_DISABLE_NOT_ALLOWED, WDGM_E_SEDEACTIVATED et WDGM_E_SET_MODE [SWS_WdgM_00402].

Si WdgMOffModeEnabled est FALSE, WdgM_SetMode refuse un mode avec WDGIF_OFF_MODE. Le service signale alors WDGM_E_DISABLE_NOT_ALLOWED et renvoie E_NOT_OK [SWS_WdgM_00031]. WdgM_Init se comporte exactement de la même manière pour un tel mode initial [SWS_WdgM_00030]. Si WdgIf_SetMode échoue, le WdgM signale WDGM_E_SET_MODE et définit le statut global sur STOPPED [SWS_WdgM_00139]. Le reset suit immédiatement si un Immediate Reset est configuré, sinon à l'expiration du premier watchdog (SWS WdgM p. 57).

Si le statut global atteint STOPPED, le WdgM signale l'événement DEM WDGM_E_SUPERVISION comme erreur [SWS_WdgM_00375]. Après le démarrage, il signale optionnellement ce même événement comme PASSED [SWS_WdgM_00408]. Après un redémarrage, WdgM_GetFirstExpiredSEID fournit l'entité ayant atteint EXPIRED en premier [SWS_WdgM_00346]. Le service est déjà disponible avant WdgM_Init [SWS_WdgM_00348]. Il lit la valeur en double inversé depuis la RAM non initialisée et renvoie E_NOT_OK en cas d'incohérence [SWS_WdgM_00349]. WdgM_Init efface la valeur [SWS_WdgM_00370]. Vraisemblablement, le WdgM l'écrit lors de la première transition d'une entité vers EXPIRED.

WdgM_PerformReset met la condition de déclenchement de tous les pilotes à 0 et ne la met plus à jour par la suite (SWS WdgM p. 82). L'EcuM exécute ce service comme l'une de ses cibles de reset (SWS EcuM p. 72).

fonction WdgM_Init [SWS_WdgM_00151] 📄 PDF

void WdgM_Init (const WdgM_ConfigType* ConfigPtr);

initialise le Watchdog Manager.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: c034e317eda3 Provenance

Utilisation

La fonction WdgM_Init initialise le Watchdog Manager de manière synchrone et est non réentrante [SWS_WdgM_00151]. Le seul paramètre transmis est ConfigPtr, qui pointe vers les données de configuration post-build (WdgM_ConfigType) [SWS_WdgM_00151]. La fonction ne possède formellement aucune valeur de retour (void) [SWS_WdgM_00151].

Gestion des erreurs et conditions limites

Avant l'initialisation, le Watchdog Manager doit se trouver dans l'état WDGM_GLOBAL_STATUS_DEACTIVATED : si le paramètre de configuration de développement WdgMDevErrorDetect est désactivé et que le module n'est pas dans cet état, WdgM_Init retourne sans effet [SWS_WdgM_00390].

Si le commutateur de configuration WdgMOffModeEnabled n'est pas activé et que le mode initial spécifié via ConfigPtr désactiverait le watchdog (WDGIF_OFF_MODE), la fonction s'interrompt sans autre action et signale l'erreur d'exécution WDGM_E_DISABLE_NOT_ALLOWED au Default Error Tracer (DET) [SWS_WdgM_00030]. Le retour avec E_NOT_OK exigé dans la spécification devrait être interprété comme une interruption interne sur erreur, étant donné que la signature impose void [SWS_WdgM_00151].

Interaction et ordre d'appel

  • Diagnostic d'erreurs avant l'initialisation : la fonction WdgM_GetFirstExpiredSEID() doit déjà être disponible avant l'appel de WdgM_Init afin de lire la Supervised Entity ID (SEID) ayant préalablement expiré [SWS_WdgM_00348].
  • Nettoyage de la RAM : pendant l'initialisation, WdgM_Init efface la valeur de SEID doublement inversée de la première entité ayant expiré, enregistrée dans la RAM non initialisée [SWS_WdgM_00370].
  • Notification d'état au DEM : lors du premier appel de WdgM_MainFunction suivant WdgM_Init, le module signale au DEM [SWS_WdgM_00408] l'état PASSED pour WDGM_E_SUPERVISION lorsque le paramètre WdgMDemStoppedSupervisionReport est activé.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: f81345e92521 Provenance

Utilisation

La fonction synchrone WdgM_DeInit sert à la désinitialisation du Watchdog Manager [SWS_WdgM_00261]. L'interface possède le service ID 0x01, est mise à disposition via le fichier d'en-tête WdgM.h, et ne reçoit aucun paramètre d'entrée ni ne renvoie de valeur de retour à l'appelant [SWS_WdgM_00261]. Le contexte d'appel prévu est probablement la séquence d'arrêt ordonnée du calculateur, dans laquelle les surveillances actives sont arrêtées de manière contrôlée avant la mise hors tension.

Périmètre fonctionnel et interaction

Dans le cadre de la désinitialisation, le module WdgM arrête totalement les fonctions de surveillance (Supervision Functions) pour l'ensemble des algorithmes de surveillance configurés (Supervision Algorithms) et met fin en même temps à la gestion du watchdog (Watchdog Handling) [SWS_WdgM_00407].

Gestion des erreurs et conditions limites

Si le Watchdog Manager se trouve déjà dans l'état global WDGM_GLOBAL_STATUS_DEACTIVATED au moment de l'appel, le comportement dépend du paramètre de configuration WdgMDevErrorDetect : si cette détection de développement est désactivée, WdgM_DeInit retourne immédiatement et sans aucun effet [SWS_WdgM_00388].

En ce qui concerne la concurrence, il est établi que la fonction est non réentrante [SWS_WdgM_00261]. L'appel ne doit donc en aucun cas être effectué de manière interruptive ou parallèle à partir de plusieurs contextes.

Utilisation et sémantique

La fonction WdgM_SetMode sert à basculer de manière synchrone le Watchdog Manager dans l'un des modes de fonctionnement configurés ([SWS_WdgM_00154]). Elle attend comme paramètre de transmission Mode de type WdgM_ModeType. La valeur de retour Std_ReturnType signale par E_OK la réussite du changement de mode et par E_NOT_OK un échec ([SWS_WdgM_00154]).

Restrictions et traitement des erreurs

La fonction n'est pas réentrante (Non Reentrant) ([SWS_WdgM_00154]). L'exécution est liée à l'état global actuel du Watchdog Manager :

  • Si le module ne se trouve ni dans l'état WDGM_GLOBAL_STATUS_OK ni dans WDGM_GLOBAL_STATUS_FAILED, la fonction retourne sans exécuter aucune action ([SWS_WdgM_00145]).
  • Si le paramètre de configuration WdgMDevErrorDetect est désactivé, un appel dans l'état WDGM_GLOBAL_STATUS_DEACTIVATED reste sans aucun effet ([SWS_WdgM_00392]).

Interaction et répercussions

En présence d'un état global valide (WDGM_GLOBAL_STATUS_OK ou WDGM_GLOBAL_STATUS_FAILED), WdgM_SetMode met à jour les entités surveillées ainsi que les watchdogs :

  • Pour chaque Supervised Entity activée dans le mode cible, l'état actuel est conservé ([SWS_WdgM_00182]).
  • Pour chaque Supervised Entity désactivée dans le mode cible, l'état local passe à WDGM_LOCAL_STATUS_DEACTIVATED ; les résultats de Active, Deadline et Logical Supervision sont définis sur correct et le compteur de cycles erronés est réinitialisé à 0 ([SWS_WdgM_00315]). Le passage à un mode comportant la désactivation de l'entité assainit en outre les erreurs qui avaient auparavant conduit à WDGM_GLOBAL_STATUS_FAILED ([SWS_WdgM_00182]).
  • Enfin, les paramètres de mode de watchdog configurés sont activés pour chaque watchdog matériel via l'interface WdgIf_SetMode ([SWS_WdgM_00186]).
