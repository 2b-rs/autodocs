Objectif et limites du système

ara::per rend les données persistantes configurées accessibles aux applications adaptatives. Le modèle distingue les stockages clé-valeur comme des ensembles de paires clé-valeur typées et les stockages de fichiers comme des ensembles de fichiers nommés ; les deux peuvent être combinés par application. SWS Persistency §7.1 « The Architecture of Persistency »

L'instance de stockage ne peut pas être librement sélectionnée, mais est référencée à une interface de persistance manifestée par un ara::core::InstanceSpecifier. Les droits d'accès peuvent être en lecture seule, en lecture/écriture, en écriture seule ou – pour les applications – en écriture seule. SWS Persistency §7.1.1 « Configuration of Persistency »

Décision : clé ou fichier

Choisissez KeyValueStorage pour les états adressables et typés avec une limite de synchronisation explicite ; choisissez FileStorage pour un contenu de type fichier et une lecture ou une écriture basée sur les accesseurs. Les valeurs initiales et les fichiers initiaux peuvent être inclus avec l'installation ou la mise à jour. SWS Persistency §7.1.2 « Configuration of Key-Value Storages » SWS Persistency §7.1.3 « Configuration of File Storages »

Interprétation : le choix relève d’une décision de modèle de données : de petits états logiquement séparés bénéficient de clés ; des contenus cohérents ou de type flux conviennent davantage à l’interface de fichier. Il découle des différents modèles d’accès décrits dans la spécification.

Modèle d'exploitation et pérennité des données

Un stockage clé-valeur ouvert fonctionne initialement sur des données temporaires. SyncToStorage écrit en permanence toutes les modifications depuis l'ouverture ou la dernière synchronisation et met à jour la redondance configurée ; Sans synchronisation, les modifications sont ignorées lorsque vous fermez ou redémarrez. SWS Persistency §7.3 « Key-Value Storage specific Features »

Pour les fichiers, le fichier spécifique est ouvert via un accesseur. Les accès en écriture peuvent être spécifiquement transférés vers la mémoire physique via SyncToFile ; La propriété de l'accesseur est exclusive. SWS Persistency §7.4 « File Storage specific Features »

Protection, récupération et ressources

La redondance peut garantir l'intégrité via des sommes de contrôle ou des copies multiples ; Dans le cas de résultats irrécupérables, un rappel du rapport de récupération peut informer l'application. Une restauration peut entraîner des données initiales ou plus anciennes et doit donc être vérifiée par un professionnel. SWS Persistency §7.2.4 « Redundancy Concepts »

Le maximum configuré limite la mémoire réelle utilisée. Les requêtes de taille incluent des métadonnées ainsi que des besoins de redondance et de sauvegarde et peuvent être inexactes pour le stockage ouvert ou les opérations parallèles. SWS Persistency §7.2.6 « Resource Management Concepts »

Installation, mise à jour et rollback

La configuration cible peut apporter des valeurs et des fichiers prédéfinis. Pendant la phase de vérification, UpdatePersistency peut exécuter des modifications en fonction des nouvelles données de configuration ; après une finalisation réussie, supprimez les données de sauvegarde CleanUpPersistency. Si une ancienne configuration est activée, une restauration ou une nouvelle installation aura lieu en fonction de la version de sauvegarde enregistrée. SWS Persistency §7.2.5 « Installation and Update of Persistent Data »

L'ouverture nécessite une persistance configurée et initialisée. Sources : SWS Persistency §7.1 « The Architecture of Persistency » SWS Persistency §7.3 « Key-Value Storage specific Features ».

La limite de persistance affecte toutes les clés qui ont changé depuis leur ouverture ou leur dernière synchronisation ; La redondance configurée pour la mise à jour en fait partie. Source : SWS Persistency §7.3 « Key-Value Storage specific Features ».

La récupération est le meilleur effort possible ; en cas d'erreur, un rapport peut nommer le stockage ou les éléments concernés. Source : SWS Persistency §7.2.4 « Redundancy Concepts ». Interprétation partielle : la séquence d'activités combine plusieurs procédures de redondance autorisées.

La mise à jour, la finalisation et le rollback sont ancrés dans le versionnement de la Target Configuration. Sources : SWS Persistency §7.2.5 « Installation and Update of Persistent Data ». Interprétation partielle : l'agencement présente le déroulement opérationnel prévu, non la signalisation d'un seul appel d'API.
