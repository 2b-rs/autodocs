<h4>Context and role</h4>
<p>The class <code>ara::log::LogStream</code> represents a formatted logging message within the AUTOSAR Adaptive Platform and provides stream operators for assembling log messages. As a rule, application processes do not interact with this class directly via constructors. Instead, the primary interfaces of the logging API (for example, a <code>Logger</code> context) provide specific logging methods that configure and return temporary instances of <code>ara::log::LogStream</code> with the appropriate severity level.</p>
<p>The interaction typically occurs between three parties: the application feeding data into the stream, the <code>LogStream</code> object buffering the payload and metadata, and the underlying logging framework to which the buffer is passed for final processing. Direct instantiation or prolonged retention of a <code>LogStream</code> object is intended exclusively for assembling log messages across lines or statements.</p>

<h4>Lifecycle and ownership</h4>
<p>The lifecycle of <code>ara::log::LogStream</code> is designed for strict binding to the creation scope and restrictive ownership:</p>
<ul>
  <li><strong>Creation and move semantics:</strong> The move constructor <a class="spec-record-ref" data-req="SWS_LOG_00176" href="../spec/record.html?id=SWS_LOG_00176">[SWS_LOG_00176]</a> is declared as <code>noexcept</code>, but is typically not defined. This specification requirement allows a C++14-compliant compiler to return instances directly from factory methods of the logging API to the caller via Return Value Optimization (RVO).</li>
  <li><strong>Copy and assignment restrictions:</strong> The copy constructor <a class="spec-record-ref" data-req="SWS_LOG_00174" href="../spec/record.html?id=SWS_LOG_00174">[SWS_LOG_00174]</a> as well as the copy assignment operator <a class="spec-record-ref" data-req="SWS_LOG_00175" href="../spec/record.html?id=SWS_LOG_00175">[SWS_LOG_00175]</a> and the move assignment operator <a class="spec-record-ref" data-req="SWS_LOG_00177" href="../spec/record.html?id=SWS_LOG_00177">[SWS_LOG_00177]</a> are deleted (<code>= delete</code>). Instances can therefore neither be duplicated nor moved subsequently.</li>
  <li><strong>Destruction and buffer handover:</strong> The standard case is a one-statement scope in which the temporary object is destroyed at the end of the statement. The destructor <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a> is defined as <code>noexcept</code> and ensures that the internal message buffer is handed over to the logging framework for further processing.</li>
  <li><strong>Multi-line reuse via flush:</strong> If a <code>LogStream</code> object is held locally across multiple statements, the method <code>Flush()</code> <a class="spec-record-ref" data-req="SWS_LOG_00039" href="../spec/record.html?id=SWS_LOG_00039">[SWS_LOG_00039]</a> must be called to send the current buffer content to the logging framework and initiate a new message stream. It should be noted that <code>Flush()</code> does not clear the buffer, but forwards its current state.</li>
  <li><strong>Concurrency:</strong> According to the interface definitions, <code>ara::log::LogStream</code> is not thread-safe (<code>not thread-safe</code>). An instance must not be populated or manipulated concurrently from multiple threads without protection.</li>
</ul>

<h4>Usage Path and Operator Chaining</h4>
<p>The standard usage path is via the fluent interface of the overloaded shift operators (<code>operator&lt;&lt;</code>) and metadata methods, each returning a reference to <code>*this</code>:</p>
<ol>
  <li><strong>Metadata enrichment:</strong> Context information can be attached before or during streaming. <code>WithLocation()</code> <a class="spec-record-ref" data-req="SWS_LOG_00129" href="../spec/record.html?id=SWS_LOG_00129">[SWS_LOG_00129]</a> inserts the source file and line number, <code>WithTag()</code> <a class="spec-record-ref" data-req="SWS_LOG_00132" href="../spec/record.html?id=SWS_LOG_00132">[SWS_LOG_00132]</a> appends a tag to the message, and <code>WithPrivacy()</code> <a class="spec-record-ref" data-req="SWS_LOG_00258" href="../spec/record.html?id=SWS_LOG_00258">[SWS_LOG_00258]</a> configures the privacy level.</li>
  <li><strong>Feeding payload data:</strong> Overloads of <code>operator&lt;&lt;</code> accept standard data types:
    <ul>
      <li>Boolean values via <a class="spec-record-ref" data-req="SWS_LOG_00040" href="../spec/record.html?id=SWS_LOG_00040">[SWS_LOG_00040]</a>.</li>
      <li>Signed integer types (8 to 64 bits) via <a class="spec-record-ref" data-req="SWS_LOG_00045" href="../spec/record.html?id=SWS_LOG_00045">[SWS_LOG_00045]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00046" href="../spec/record.html?id=SWS_LOG_00046">[SWS_LOG_00046]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00047" href="../spec/record.html?id=SWS_LOG_00047">[SWS_LOG_00047]</a>, and <a class="spec-record-ref" data-req="SWS_LOG_00048" href="../spec/record.html?id=SWS_LOG_00048">[SWS_LOG_00048]</a>.</li>
      <li>Unsigned integers (8 to 64 bits) via <a class="spec-record-ref" data-req="SWS_LOG_00041" href="../spec/record.html?id=SWS_LOG_00041">[SWS_LOG_00041]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00042" href="../spec/record.html?id=SWS_LOG_00042">[SWS_LOG_00042]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00043" href="../spec/record.html?id=SWS_LOG_00043">[SWS_LOG_00043]</a>, and <a class="spec-record-ref" data-req="SWS_LOG_00044" href="../spec/record.html?id=SWS_LOG_00044">[SWS_LOG_00044]</a>.</li>
      <li>Floating-point types (<code>float</code>, <code>double</code>) via <a class="spec-record-ref" data-req="SWS_LOG_00049" href="../spec/record.html?id=SWS_LOG_00049">[SWS_LOG_00049]</a> and <a class="spec-record-ref" data-req="SWS_LOG_00050" href="../spec/record.html?id=SWS_LOG_00050">[SWS_LOG_00050]</a>.</li>
      <li>Character strings as null-terminated UTF-8 strings via <a class="spec-record-ref" data-req="SWS_LOG_00051" href="../spec/record.html?id=SWS_LOG_00051">[SWS_LOG_00051]</a> or as <code>ara::core::StringView</code> via <a class="spec-record-ref" data-req="SWS_LOG_00062" href="../spec/record.html?id=SWS_LOG_00062">[SWS_LOG_00062]</a>.</li>
      <li>Binary sequences via <code>ara::core::Span&lt;const ara::core::Byte&gt;</code> via <a class="spec-record-ref" data-req="SWS_LOG_00128" href="../spec/record.html?id=SWS_LOG_00128">[SWS_LOG_00128]</a>.</li>
      <li>Attributed arguments via <code>ara::log::Argument&lt;T&gt;</code> via <a class="spec-record-ref" data-req="SWS_LOG_00203" href="../spec/record.html?id=SWS_LOG_00203">[SWS_LOG_00203]</a>.</li>
    </ul>
  </li>
  <li><strong>Extensibility:</strong> Application-defined types can be seamlessly integrated by providing free stream operators that map custom structures to the existing base operators.</li>
  <li><strong>Completion:</strong> When leaving the statement or function scope, the destructor <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a> automatically triggers the flush operation to the logging framework.</li>
</ol>

<h4>Error Scenarios and Boundary Conditions</h4>
<p>The interfaces of <code>ara::log::LogStream</code> do not throw exceptions and guarantee exception safety:</p>
<ul>
  <li><strong>noexcept guarantee:</strong> All methods and operators (<a class="spec-record-ref" data-req="SWS_LOG_00039" href="../spec/record.html?id=SWS_LOG_00039">[SWS_LOG_00039]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00129" href="../spec/record.html?id=SWS_LOG_00129">[SWS_LOG_00129]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00132" href="../spec/record.html?id=SWS_LOG_00132">[SWS_LOG_00132]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00258" href="../spec/record.html?id=SWS_LOG_00258">[SWS_LOG_00258]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00262" href="../spec/record.html?id=SWS_LOG_00262">[SWS_LOG_00262]</a>, as well as the overloads of <code>operator&lt;&lt;</code>) are marked with <code>noexcept</code>.</li>
