<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient als generische Schnittstelle zum anwendungsseitigen Lesen und Schreiben von SOVD-Diagnosedaten.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::GenericDiagnosticSovdContent</code> stellt eine generische Schnittstelle für adaptive Anwendungen bereit, um SOVD-Ressourcen im AUTOSAR-System anzubinden <a class="spec-record-ref" data-req="SWS_DM_02186" href="../spec/record.html?id=SWS_DM_02186">[SWS_DM_02186]</a>. Nach der Instanziierung aktiviert die Anwendung den Empfang von Diagnoseanfragen über <code>Offer()</code>, woraufhin das Diagnostic Management eingehende Lese- und Schreibzugriffe asynchron an <code>Read()</code> und <code>Write()</code> weiterleitet <a class="spec-record-ref" data-req="SWS_DM_02193" href="../spec/record.html?id=SWS_DM_02193">[SWS_DM_02193]</a>. Vor dem Beenden muss die Bereitstellung mittels <code>StopOffer()</code> deaktiviert werden, während laufende Zugriffe den übergebenen Abbruch-Handler beachten müssen.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::GenericDiagnosticSovdContent</code> stellt das generische Programmierinterface bereit, über das adaptive Anwendungen Datenressourcen für die serviceorientierte Fahrzeugdiagnose (SOVD) gemäß ASAM SOVD anbieten und verarbeiten <a class="spec-record-ref" data-req="SWS_DM_02186" href="../spec/record.html?id=SWS_DM_02186">[SWS_DM_02186]</a>. In einem typischen Diagnoseszenario sind drei wesentliche Komponenten beteiligt: der externe SOVD-Client, das Diagnostic Management (DM) und der anwendungsspezifische Handler der adaptiven Anwendung.</p>
<p>SOVD-Daten werden über <code>DiagnosticSovdContent</code> strukturiert, welches aus einem oder mehreren Elementen vom Typ <code>DiagnosticSovdContentElement</code> besteht <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=205">SWS Diagnostics §7.3.3.3 „Definition of SOVD data“</a>. Das DM greift auf das Interface <code>ara::diag::GenericDiagnosticSovdContent</code> zurück, um Lese- oder Schreibanfragen für die gesamten Inhalte auszuführen und dabei die vorgegebenen Datenkonvertierungsregeln anzuwenden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=205">SWS Diagnostics §7.3.3.3 „Definition of SOVD data“</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung erfolgt über den Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code>, der auf einen PortPrototype eines <code>DiagnosticDataIdentifierGenericInterface</code> verweist, sowie eines Nebenläufigkeitsmodus vom Typ <code>SovdContentConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_02187" href="../spec/record.html?id=SWS_DM_02187">[SWS_DM_02187]</a>. Die Klasse ist threadsicher und ausnahmesicher konzipiert <a class="spec-record-ref" data-req="SWS_DM_02187" href="../spec/record.html?id=SWS_DM_02187">[SWS_DM_02187]</a>.</p>
<p>Verschiebekonstruktor und Verschiebezuweisungsoperator sind mit geschützter Sichtbarkeit (<code>protected</code>) definiert <a class="spec-record-ref" data-req="SWS_DM_02189" href="../spec/record.html?id=SWS_DM_02189">[SWS_DM_02189]</a>, <a class="spec-record-ref" data-req="SWS_DM_02190" href="../spec/record.html?id=SWS_DM_02190">[SWS_DM_02190]</a>. Interpretation: Die geschützte Deklaration deutet darauf hin, dass Instanzen als abgeleitete Klassenhierarchien implementiert werden und ein direktes Verschieben von außen verhindert werden soll. <a class="interp-q interp-q-open" data-q="Q-57d60744ffc54899" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-57d60744ffc54899" title="Frage Q-57d60744ffc54899 (offen): Die geschützte Sichtbarkeit von Move-Konstruktor und Move-Zuweisung dient der Absicherung der Klassenhierarchie vor unkontrolliertem Verschieben außerhalb abgeleiteter Klassen.">Frage Q-57d60744ffc54899 (offen)</a> Zur Freigabe existiert ein virtueller Destruktor <a class="spec-record-ref" data-req="SWS_DM_02188" href="../spec/record.html?id=SWS_DM_02188">[SWS_DM_02188]</a>.</p>
<p>Nach der Konstruktion befindet sich die Instanz im Zustand der Nichtbereitstellung. Erst durch den Aufruf von <code>Offer()</code> wird das DM autorisiert, eintreffende Diagnoseanfragen an die Instanz weiterzuleiten <a class="spec-record-ref" data-req="SWS_DM_02193" href="../spec/record.html?id=SWS_DM_02193">[SWS_DM_02193]</a>. Vor dem Herunterfahren oder bei Dienstende wird die Weiterleitung über <code>StopOffer()</code> wieder entzogen <a class="spec-record-ref" data-req="SWS_DM_02194" href="../spec/record.html?id=SWS_DM_02194">[SWS_DM_02194]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Freischaltung des Dienstes, die Entgegennahme asynchroner Anforderungen und die abschließende Abmeldung:</p>
<ul>
<li>Die Anwendung instanziiert ihre Implementierung von <code>GenericDiagnosticSovdContent</code> und registriert sich über <code>Offer()</code> beim DM <a class="spec-record-ref" data-req="SWS_DM_02193" href="../spec/record.html?id=SWS_DM_02193">[SWS_DM_02193]</a>.</li>
<li>Empfängt das DM eine Leseanfrage des Clients („Read a data resource from an Entity“), ruft es die Methode <code>Read()</code> auf <a class="spec-record-ref" data-req="SWS_DM_01432" href="../spec/record.html?id=SWS_DM_01432">[SWS_DM_01432]</a>, <a class="spec-record-ref" data-req="SWS_DM_02191" href="../spec/record.html?id=SWS_DM_02191">[SWS_DM_02191]</a>. Die Methode liefert ein <code>ara::core::Future&lt;DiagnosticSovdContentData&gt;</code> zurück, welches entweder die abstrakten Inhaltsdaten oder einen SOVD-Fehler bereitstellt <a class="spec-record-ref" data-req="SWS_DM_02191" href="../spec/record.html?id=SWS_DM_02191">[SWS_DM_02191]</a>. Aus diesen Daten bildet das DM die SOVD-Antwort <a class="spec-record-ref" data-req="SWS_DM_01432" href="../spec/record.html?id=SWS_DM_01432">[SWS_DM_01432]</a>, <a class="spec-record-ref" data-req="SWS_DM_02164" href="../spec/record.html?id=SWS_DM_02164">[SWS_DM_02164]</a>, <a class="spec-record-ref" data-req="SWS_DM_02165" href="../spec/record.html?id=SWS_DM_02165">[SWS_DM_02165]</a>.</li>
<li>Empfängt das DM eine Schreibanfrage („Write a data resource from an Entity“), delegiert es diese über <code>Write()</code> an den Handler <a class="spec-record-ref" data-req="SWS_DM_01431" href="../spec/record.html?id=SWS_DM_01431">[SWS_DM_01431]</a>, <a class="spec-record-ref" data-req="SWS_DM_02166" href="../spec/record.html?id=SWS_DM_02166">[SWS_DM_02166]</a>, <a class="spec-record-ref" data-req="SWS_DM_02192" href="../spec/record.html?id=SWS_DM_02192">[SWS_DM_02192]</a>. Die Daten bleiben gültig, bis das zugehörige Promise erfüllt oder der Vorgang abgebrochen wird <a class="spec-record-ref" data-req="SWS_DM_02192" href="../spec/record.html?id=SWS_DM_02192">[SWS_DM_02192]</a>.</li>
<li>Zum Beenden des Handlings ruft die Anwendung <code>StopOffer()</code> auf <a class="spec-record-ref" data-req="SWS_DM_02194" href="../spec/record.html?id=SWS_DM_02194">[SWS_DM_02194]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Wird <code>Offer()</code> aufgerufen, obwohl der Dienst bereits angeboten wird, schlägt die Operation mit dem Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> fehl <a class="spec-record-ref" data-req="SWS_DM_02193" href="../spec/record.html?id=SWS_DM_02193">[SWS_DM_02193]</a>.</p>
<p>Treten bei der Datenermittlung in <code>Read()</code> oder beim Schreiben in <code>Write()</code> anwendungsspezifische Fehler auf, wird das zurückgegebene <code>ara::core::Future</code> mit einem entsprechenden SOVD-Fehler erfüllt <a class="spec-record-ref" data-req="SWS_DM_02191" href="../spec/record.html?id=SWS_DM_02191">[SWS_DM_02191]</a>, <a class="spec-record-ref" data-req="SWS_DM_02192" href="../spec/record.html?id=SWS_DM_02192">[SWS_DM_02192]</a>, woraufhin das DM eine negative SOVD-Antwort an den Client übermittelt.</p>
<p>Zusätzlich wird beiden Aufrufen ein <code>ara::diag::CancellationHandler</code> übergeben, der signalisiert, falls die Operation vorzeitig abgebrochen wird <a class="spec-record-ref" data-req="SWS_DM_02191" href="../spec/record.html?id=SWS_DM_02191">[SWS_DM_02191]</a>, <a class="spec-record-ref" data-req="SWS_DM_02192" href="../spec/record.html?id=SWS_DM_02192">[SWS_DM_02192]</a>.
