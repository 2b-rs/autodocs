<h4>Context</h4>
<p>The C++ class <code>ara::diag::SovdServiceValidation</code> <a class="spec-record-ref" data-req="SWS_DM_01822" href="../spec/record.html?id=SWS_DM_01822">[SWS_DM_01822]</a> serves to implement manufacturer- and supplier-specific checks for Service-Oriented Vehicle Diagnostics (SOVD) within an AUTOSAR Adaptive application. It provides the interface through which incoming SOVD requests are validated prior to actual execution.</p>
<p>Essentially three components are involved in the validation:</p>
<ul>
<li><strong>SOVD client:</strong> Initiates diagnostic operations via HTTP-based SOVD service calls on resources or resource collections.</li>
<li><strong>Diagnostic Server (DM):</strong> Receives the client's requests, checks preconfigured environmental conditions, and delegates the functional validation to the application's configured port mappings <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=197">AUTOSAR_AP_SWS_Diagnostics §7.3.3.2.3 “SOVD – Validation of Environmental Conditions”</a>.</li>
<li><strong>Adaptive Application:</strong> Provides the application-specific validation logic via an instance of <code>ara::diag::SovdServiceValidation</code> and returns the validation result to the Diagnostic Server.</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::diag::SovdServiceValidation</code> is divided into the phases creation, offering, operation, and destruction:</p>
<ul>
<li><strong>Instantiation:</strong> Creation is performed via the constructor <code>SovdServiceValidation</code> <a class="spec-record-ref" data-req="SWS_DM_01823" href="../spec/record.html?id=SWS_DM_01823">[SWS_DM_01823]</a>. This binds the instance to a <code>ara::core::InstanceSpecifier</code> that references a <code>PortPrototype</code> of a <code>DiagnosticSovdServiceValidationInterface</code> in the manifest. The parameter <code>ConcurrencyType</code> declares whether the interface is provided thread-safe (<code>kConcurrent</code>) or non-thread-safe (<code>kNotConcurrent</code>). The constructor is exception-safe and thread-safe.</li>
<li><strong>Activation (Offer):</strong> After creation, Diagnostic Management does not yet forward any requests. Only by calling <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01825" href="../spec/record.html?id=SWS_DM_01825">[SWS_DM_01825]</a> is the handler registered and forwarding activated. <code>Offer()</code> is not thread-safe.</li>
<li><strong>Deactivation (StopOffer):</strong> The forwarding of requests by the DM is stopped via <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01826" href="../spec/record.html?id=SWS_DM_01826">[SWS_DM_01826]</a>. This operation is also not thread-safe.</li>
<li><strong>Destruction:</strong> The virtual destructor <code>~SovdServiceValidation()</code> <a class="spec-record-ref" data-req="SWS_DM_01824" href="../spec/record.html?id=SWS_DM_01824">[SWS_DM_01824]</a> terminates the lifetime of the instance. Prior to destruction, the offer is typically to be deregistered via <code>StopOffer()</code>. The destructor is not thread-safe.</li>
<li><strong>Concurrency:</strong> Thread safety during the execution of <code>Validate</code> is conditional <a class="spec-record-ref" data-req="SWS_DM_01827" href="../spec/record.html?id=SWS_DM_01827">[SWS_DM_01827]</a> and depends on the <code>ConcurrencyType</code> specified in the constructor.</li>
</ul>

<h4>Usage Path</h4>
<p>Interpretation: Applications typically derive their own handler class from <code>ara::diag::SovdServiceValidation</code> and override the virtual method <code>Validate</code> <a class="spec-record-ref" data-req="SWS_DM_01827" href="../spec/record.html?id=SWS_DM_01827">[SWS_DM_01827]</a>.</p>
<p>The typical sequence of an SOVD request validation is as follows:</p>
<ol>
<li><strong>Offering:</strong> The application initializes the derived instance and enables reception via <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01825" href="../spec/record.html?id=SWS_DM_01825">[SWS_DM_01825]</a>.</li>
<li><strong>Environmental checks of the DM:</strong> Prior to executing an SOVD method, the Diagnostic Server instance checks the assigned environmental conditions <a class="spec-record-ref" data-req="SWS_DM_01468" href="../spec/record.html?id=SWS_DM_01468">[SWS_DM_01468]</a>. Only if this evaluation yields <code>TRUE</code> does the server continue processing <a class="spec-record-ref" data-req="SWS_DM_01467" href="../spec/record.html?id=SWS_DM_01467">[SWS_DM_01467]</a>; in case of <code>FALSE</code>, execution is denied <a class="spec-record-ref" data-req="SWS_DM_01466" href="../spec/record.html?id=SWS_DM_01466">[SWS_DM_01466]</a>.</li>
<li><strong>Invocation of Validate:</strong> The DM calls <code>Validate</code> for each configured port mapping in <code>DiagnosticServiceValidationConfiguration</code> in the defined order <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=197">AUTOSAR_AP_SWS_Diagnostics §7.3.3.2.3 “SOVD – Validation of Environmental Conditions”</a>. The HTTP method (<code>requestMethod</code>) and <code>ara::diag::MetaInfo</code> with the path of the target resource are passed.</li>
<li><strong>Resource collections:</strong> If a request concerns a resource collection (Resource Collection), <code>Validate</code> is called multiple times: once for the collection itself and once for each resource contained in the collection <a class="spec-record-ref" data-req="SWS_DM_01827" href="../spec/record.html?id=SWS_DM_01827">[SWS_DM_01827]</a>.</li>
<li><strong>Asynchronous result and abort:</strong> The method returns an <code>ara::core::Future&lt;void&gt;</code>. As soon as a call of <code>Validate</code> fails for any contained resource, the DM aborts processing immediately and sends an error to the SOVD client without delay <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=197">AUTOSAR_AP_SWS_Diagnostics §7.3.3.2.3 “SOVD – Validation of Environmental Conditions”</a>.</li>
<li><strong>End of service:</strong> After completion of operation, the service is deactivated with <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01826" href="../spec/record.html?id=SWS_DM_01826">[SWS_DM_01826]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>During instantiation, activation, and validation, the following errors and exception conditions can occur:</p>
<ul>
<li><strong>Construction violations:</strong> When calling the constructor <a class="spec-record-ref" data-req="SWS_DM_01823" href="../spec/record.html?id=SWS_DM_01823">[SWS_DM_01823]</a>, inconsistencies in the manifest lead to model violations:
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved or does not reference a <code>PortPrototype</code>.</li>
<li><code>PortInterfaceMappingViolation</code>: The PortPrototype is not typed as <code>DiagnosticSovdServiceValidationInterface</code>.</li>
<li><code>ProcessMappingViolation</code>: No matching modeled process exists at runtime for the instance identifier.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The identifier is already used in the process.</li>
</ul>
</li>
<li><strong>Errors during Offer:</strong> The return value <code>ara::core::Result&lt;void&gt;</code> of <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01825" href="../spec/record.html?id=SWS_DM_01825">[SWS_DM_01825]</a> can fail with the following errors from <code>DiagOfferErrc</code>:
<ul>
<li><code>DiagOfferErrc::kAlreadyOffered</code>: The service has already been offered via this interface.</li>
<li><code>DiagOfferErrc::kConfigurationMismatch</code>: The configuration does not match the DEXT model data.</li>
</ul>
</li>
<li><strong>Validation errors:</strong> The method <code>Validate()</code> <a class="spec-record-ref" data-req="SWS_DM_01827" href="../spec/record.html?id=SWS_DM_01827">[SWS_DM_01827]</a> reports failures asynchronously via the error state of the <code>ara::core::Future</code> with codes from <code>DiagSovdErrc</code>:
<ul>
<li><code>DiagSovdErrc::kInsufficientAccessRights</code>: The DEM client lacks the required permissions for resource access.</li>
<li><code>DiagSovdErrc::kPreconditionNotFulfilled</code>: The preconditions for executing the method are not fulfilled.</li>
<li><code>DiagSovdErrc::kTemporarilyNotAvailable</code>: The request cannot be served temporarily (for example, if access tokens must be verified online and the authentication server is not reachable).</li>
<li><code>DiagSovdErrc::kSovdServerMisconfigured</code>: The SOVD server is configured incorrectly (e.g., missing configuration files).</li>
<li>Further application-specific errors from <code>DiagSovdErrc</code>.</li>
</ul>
</li>
</ul>
