<h4>Verwendung</h4>
  <p>
    Die rein virtuelle Methode <code>ara::diag::SecurityAccess::GetSeed</code> wird von der Diagnose-Server-Instanz aufgerufen, sobald eine UDS-Anfrage für den Dienst <code>0x27 SecurityAccess</code> empfangen wird und der übermittelte Subfunktionswert mit der konfigurierten <code>requestSeedId</code> übereinstimmt <a class="spec-record-ref" data-req="SWS_DM_00863" href="../spec/record.html?id=SWS_DM_00863">[SWS_DM_00863]</a>. Dies ist Bestandteil der standardkonformen Realisierung des Dienstes <code>0x27</code> gemäß ISO 14229-1 <a class="spec-record-ref" data-req="SWS_DM_00236" href="../spec/record.html?id=SWS_DM_00236">[SWS_DM_00236]</a>.
  </p>
  <p>
    Der Aufruf übergibt die vom Diagnose-Client bereitgestellten Nutzdaten über den Parameter <code>securityAccessDataRecord</code> (als <code>ara::core::Span</code>), die Kontextinformationen in <code>metaInfo</code> sowie ein Objekt vom Typ <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>. Hat der Client keine Daten gesendet, wird der Daten-Span leer übergeben <a class="spec-record-ref" data-req="SWS_DM_00863" href="../spec/record.html?id=SWS_DM_00863">[SWS_DM_00863]</a>. Die übergebenen Daten bleiben gültig, bis das zugehörige Promise erfüllt oder die Verarbeitung abgebrochen wird <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>.
  </p>
  <h4>Asynchrone Semantik und Nebenläufigkeit</h4>
  <p>
    Die Funktion liefert asynchron ein <code>ara::core::Future&lt;ara::core::Vector&lt;std::uint8_t&gt;&gt;</code> zurück, welches den generierten Seed enthält <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>. Über den <code>cancellationHandler</code> kann die Applikation mittels <code>IsCanceled</code> prüfen, ob die Konversation abgebrochen wurde, oder via <code>SetNotifier</code> eine Benachrichtigung registrieren <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>. Auch ein statischer Seed-Mechanismus gemäß ISO 14229-1 muss applikationsseitig in <code>GetSeed</code> implementiert werden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=161">SWS Diagnostics §7.3.2.8.9 „Service 0x27 – SecurityAccess“</a>.
  </p>
  <p>
    Hinsichtlich der Nebenläufigkeit ist die Methode bedingt thread-sicher: Ob die Implementierung thread-sicher sein muss, wird über den <code>ConcurrencyType</code> festgelegt, der dem Konstruktor von <code>SecurityAccess</code> übergeben wird <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=514">SWS Diagnostics §8.24.2.1.3.2 „GetSeed“</a>.
  </p>
  <h4>Fehlerbehandlung</h4>
  <p>
    Kann kein gültiger Seed ermittelt werden, ist das Future mit einem passenden Negative Response Code (NRC) gemäß ISO 14229-1 über <code>DiagUdsNrcErrc</code> abzuschließen <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>. Die Schnittstelle ist als <code>noexcept</code> deklariert und ausnahmesicher <a class="spec-record-ref" data-req="SWS_DM_00764" href="../spec/record.html?id=SWS_DM_00764">[SWS_DM_00764]</a>.
  </p>
