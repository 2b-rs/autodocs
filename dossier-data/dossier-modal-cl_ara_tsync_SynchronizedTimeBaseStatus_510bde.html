<h4>Context</h4>
<p>The class <code>ara::tsync::SynchronizedTimeBaseStatus</code> represents an immutable snapshot of a point in time including the associated status information of a synchronized time base in module <code>tsync</code> of the AUTOSAR Adaptive Platform. Its central task is to consistently freeze timestamps, correction values, and synchronization states present at the time of creation and make them available to querying software components.</p>
<p>The interaction partners acting here are, on the one hand, application program components that need to evaluate time and quality information, and on the other hand, the underlying time base that creates the status object. In addition, the class forms a bridge to higher-level synchronization sources: It transports user-defined data (<code>UserData</code>) received from the time master of the time base (<a class="spec-record-ref" data-req="SWS_TS_01056" href="../spec/record.html?id=SWS_TS_01056">[SWS_TS_01056]</a>). For chronological classification, the object refers on the one hand to the synchronized time (<a class="spec-record-ref" data-req="SWS_TS_01055" href="../spec/record.html?id=SWS_TS_01055">[SWS_TS_01055]</a>) and on the other hand to the local monotonic system clock <code>ara::core::SteadyClock</code> (<a class="spec-record-ref" data-req="SWS_TS_14176" href="../spec/record.html?id=SWS_TS_14176">[SWS_TS_14176]</a>).</p>

Consequently, users cannot create instances directly without parameters. Interpretation: The creation of an instance is typically likely to take place internally by the respective time base component as soon as a status query is triggered.</li>
<li><strong>Copy and move:</strong> The class provides both a move constructor (<a class="spec-record-ref" data-req="SWS_TS_01057" href="../spec/record.html?id=SWS_TS_01057">[SWS_TS_01057]</a>) and a copy constructor (<a class="spec-record-ref" data-req="SWS_TS_01058" href="../spec/record.html?id=SWS_TS_01058">[SWS_TS_01058]</a>). The copy constructor is explicitly specified to enable return-by-value from retrieval functions (<a class="spec-record-ref" data-req="SWS_TS_01058" href="../spec/record.html?id=SWS_TS_01058">[SWS_TS_01058]</a>). <h4>Usage Path</h4>
<p>The typical call sequence for evaluating a time base status is divided into the following steps:</p>
<ol>
<li><strong>Receive snapshot:</strong> An application receives the status object via return by value (<a class="spec-record-ref" data-req="SWS_TS_01058" href="../spec/record.html?id=SWS_TS_01058">[SWS_TS_01058]</a>).</li>
<li><strong>Check synchronization status:</strong> <code>GetSynchronizationStatus()</code> (<a class="spec-record-ref" data-req="SWS_TS_01053" href="../spec/record.html?id=SWS_TS_01053">[SWS_TS_01053]</a>) is used to determine the status in which the time base was during object creation.</li>
<li><strong>Query creation times:</strong>
<ul>
<li><code>GetCreationTime()</code> (<a class="spec-record-ref" data-req="SWS_TS_01055" href="../spec/record.html?id=SWS_TS_01055">[SWS_TS_01055]</a>) returns the synchronized timestamp of the creation time wrapped in a <code>ara::core::Optional&lt;ara::tsync::Timestamp&gt;</code>.</li>
<li><code>GetCreationLocalTime()</code> (<a class="spec-record-ref" data-req="SWS_TS_14176" href="../spec/record.html?id=SWS_TS_14176">[SWS_TS_14176]</a>) returns the local timestamp based on <code>ara::core::SteadyClock</code> to establish a relation to the local time.</li>
</ul>
</li>
<li><strong>Examine time jumps and rate corrections:</strong>
<ul>
<li><code>GetLeapJump()</code> (<a class="spec-record-ref" data-req="SWS_TS_01054" href="../spec/record.html?id=SWS_TS_01054">[SWS_TS_01054]</a>) is used to determine the direction of a time jump up to the previous object creation.</li>
<li><code>GetRateCorrected()</code> (<a class="spec-record-ref" data-req="SWS_TS_14226" href="../spec/record.html?id=SWS_TS_14226">[SWS_TS_14226]</a>) indicates whether a rate correction was calculated for the synchronized time base.</li>
<li><code>GetRateExceeded()</code> (<a class="spec-record-ref" data-req="SWS_TS_14229" href="../spec/record.html?id=SWS_TS_14229">[SWS_TS_14229]</a>) signals whether the rate deviation exceeds the limit value <code>rateCorrectionThreshold</code>.</li>
</ul>
</li>
<li><strong>Read user data:</strong> User-specific payload received from the Time Master is queried via <code>GetUserData()</code> (<a class="spec-record-ref" data-req="SWS_TS_01056" href="../spec/record.html?id=SWS_TS_01056">[SWS_TS_01056]</a>).</li>
</ol>
