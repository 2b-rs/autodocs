<h4>Context</h4>
<p>
The C++ namespace <code>ara::tsync</code> represents the functional interface of the <em>Time Synchronization</em> (tsync) module in the AUTOSAR Adaptive Platform. It provides applications with uniform access to synchronized time bases as well as the monitoring of synchronization states and time quality. The architecture primarily distinguishes between consumers and providers of time information:
</p>
<ul>
<li><code>SynchronizedTimeBaseConsumer</code> serves applications as an access point to a configured time base referenced via an <em>InstanceSpecifier</em> in order to retrieve timestamps or track state changes.</li>
<li><code>SynchronizedTimeBaseProvider</code> enables applications or platform components to act as a time source and provide a time base.</li>
<li><code>TimeBase</code> functions as a pseudo-clock construct for standards-compliant typing within the framework of <code>std::chrono</code>. Based on this, the type alias <code>Timestamp</code> (<a class="spec-record-ref" data-req="SWS_TS_01251" href="../spec/record.html?id=SWS_TS_01251">[SWS_TS_01251]</a>) defines standardized points in time as <code>std::chrono::time_point&lt;TimeBase, std::chrono::nanoseconds&gt;</code>.</li>
<li><code>SynchronizedTimeBaseStatus</code> captures snapshots of the system state of a time base, including communication and jump information.</li>
<li>Measurement and validation data structures (including <code>TimeMasterMeasurementType</code>, <code>TimeSlaveMeasurementType</code>, <code>PdelayInitiatorMeasurementType</code>, <code>PdelayResponderMeasurementType</code>, and <code>TimePrecisionMeasurement</code>) as well as the callback interfaces <code>ConsumerTimeBaseValidationNotification</code> and <code>ProviderTimeBaseValidationNotification</code> support the verification and precision assessment of the time distribution.</li>
</ul>

<h4>Lifecycle and synchronization states</h4>
<p>
During runtime operation, time bases pass through discrete synchronization states that are represented via the enum <code>SynchronizationStatus</code> (<a class="spec-record-ref" data-req="SWS_TS_01050" href="../spec/record.html?id=SWS_TS_01050">[SWS_TS_01050]</a>). After startup, a time base is initially in state <code>kNotSynchronizedUntilStartup</code> (=0). As soon as synchronization messages are processed successfully, the time base transitions either to state <code>kSynchronized</code> (=2) in the case of direct coupling to the Time Master or to <code>kSynchToGateway</code> (=3) if synchronization takes place indirectly via a gateway. If synchronization fails to occur within a defined time window, the state <code>kTimeOut</code> (=1) is entered.
</p>
<p>
In parallel with the communication state, the enum <code>LeapJump</code> (<a class="spec-record-ref" data-req="SWS_TS_01051" href="../spec/record.html?id=SWS_TS_01051">[SWS_TS_01051]</a>) signals abrupt corrections of the time base: <code>kTimeLeapNone</code> (=0) indicates regular progress without exceeding a threshold, while <code>kTimeLeapFuture</code> (=1) marks a forward jump and <code>kTimeLeapPast</code> (=2) marks a backward jump beyond the configured threshold.
</p>

<h4>Usage Path</h4>
<p>
A typical usage workflow on the consumer side is divided into instantiation, registration of asynchronous callback functions, and cyclic or event-driven querying of time information:
</p>
<ol>
<li><strong>Bind access:</strong> A consumer application instantiates an object of type <code>SynchronizedTimeBaseConsumer</code> by specifying the appropriate <em>InstanceSpecifier</em>.</li>
<li><strong>Register notifications:</strong> To be informed about status changes, the application passes callback functions to the consumer. The function signatures are predefined via callback aliases:
<ul>
<li><code>SynchronizationNotifier</code> (<a class="spec-record-ref" data-req="SWS_TS_14222" href="../spec/record.html?id=SWS_TS_14222">[SWS_TS_14222]</a>) for notification upon a change of the <code>SynchronizationStatus</code> (signature <code>std::function&lt;void(const SynchronizationStatus &amp;)&gt;</code>, specified as non-thread-safe).</li>
<li><code>SynchronizedTimeBaseNotifier</code> (<a class="spec-record-ref" data-req="SWS_TS_14221" href="../spec/record.html?id=SWS_TS_14221">[SWS_TS_14221]</a>) for transmitting complete status snapshots via <code>SynchronizedTimeBaseStatus</code> (signature <code>std::function&lt;void(const SynchronizedTimeBaseStatus &amp;)&gt;</code>, non-thread-safe).</li>
<li><code>TimePrecisionNotifier</code> (<a class="spec-record-ref" data-req="SWS_TS_14223" href="../spec/record.html?id=SWS_TS_14223">[SWS_TS_14223]</a>) for the periodic evaluation of precision measurement data via <code>TimePrecisionMeasurement</code> (signature <code>std::function&lt;void(const TimePrecisionMeasurement &amp;)&gt;</code>, non-thread-safe).</li>
</ul>
</li>
<li><strong>Record timestamps and user data:</strong> The application queries points in time of type <code>Timestamp</code> (<a class="spec-record-ref" data-req="SWS_TS_01251" href="../spec/record.html?id=SWS_TS_01251">[SWS_TS_01251]</a>) and can transport application-related additional information via <code>UserData</code>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>
Error handling in <code>ara::tsync</code> is guided by the conventions of <code>ara::core</code>. Errors are mapped via the error domain <code>TsyncErrorDomain</code> and the error code enum <code>TsyncErrc</code> (<a class="spec-record-ref" data-req="SWS_TS_00901" href="../spec/record.html?id=SWS_TS_00901">[SWS_TS_00901]</a>):

For creating and checking error objects, the namespace provides the thread-safe and exception-safe helper function <code>MakeErrorCode</code> (<a class="spec-record-ref" data-req="SWS_TS_00910" href="../spec/record.html?id=SWS_TS_00910">[SWS_TS_00910]</a>) as well as access to the global error domain via <code>GetTsyncErrorDomain</code> (<a class="spec-record-ref" data-req="SWS_TS_00909" href="../spec/record.html?id=SWS_TS_00909">[SWS_TS_00909]</a>). Alternatively, the exception class <code>TsyncException</code> signals exceptional situations in contexts where C++ exceptions are used.
