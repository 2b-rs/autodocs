<p class="ai-level ai-oneliner-lead" data-ai-level="1">Stellt einen sequenziellen Container mit fester Größe und typsicherer Bereichsprüfung für AUTOSAR Adaptive bereit.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Template-Klasse <code>ara::core::Array</code> dient als sequenzieller Festgrößen-Container für Elemente des Typs <code>T</code> und adaptiert das Verhalten von <code>std::array</code> für AUTOSAR Adaptive Platform Anwendungen. Aufrufer initialisieren den Container mit fester Elementanzahl, manipulieren Inhalte über Methoden wie <code>fill()</code> und greifen wahlweise ungeprüft über <code>operator[]</code> oder bereichsgeprüft über <code>at()</code> zu <a class="spec-record-ref" data-req="SWS_CORE_01273" href="../spec/record.html?id=SWS_CORE_01273">[SWS_CORE_01273]</a>. Als sicherheitsrelevante Randbedingung löst eine Bereichsüberschreitung bei <code>at()</code> die spezifische Verletzung <code>IsoStdOutOfRangeViolation</code> anstelle von <code>std::out_of_range</code> aus, während Aufrufe von <code>front()</code> oder <code>back()</code> auf leeren Instanzen bereits zur Übersetzungszeit fehlschlagen <a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>.</p>

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Array</code> kapselt einen sequenziellen Container mit statisch zur Übersetzungszeit festgelegter Größe <code>N</code> für Elemente des Typs <code>T</code>. Sie implementiert den standardisierten Typ <code>std::array</code> im Modul <code>core</code> der AUTOSAR Adaptive Platform und stellt eine typsichere Abstraktion für zusammenhängende Speicherblöcke dar. Durch die Bereitstellung standardisierter Typ-Aliase wie <code>value_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01216" href="../spec/record.html?id=SWS_CORE_01216">[SWS_CORE_01216]</a>), <code>size_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01214" href="../spec/record.html?id=SWS_CORE_01214">[SWS_CORE_01214]</a>), <code>difference_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01215" href="../spec/record.html?id=SWS_CORE_01215">[SWS_CORE_01215]</a>) sowie Zeigertypen (<a class="spec-record-ref" data-req="SWS_CORE_01217" href="../spec/record.html?id=SWS_CORE_01217">[SWS_CORE_01217]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01218" href="../spec/record.html?id=SWS_CORE_01218">[SWS_CORE_01218]</a>) und Referenztypen (<a class="spec-record-ref" data-req="SWS_CORE_01210" href="../spec/record.html?id=SWS_CORE_01210">[SWS_CORE_01210]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01211" href="../spec/record.html?id=SWS_CORE_01211">[SWS_CORE_01211]</a>) fungiert die Klasse als interoperabler Interaktionspartner für generische C++-Algorithmen und plattforminterne Datenflüsse.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung und Vernichtung einer Array-Instanz folgt den standardmäßigen Regeln für Aggregat- und Werttypen: Die implizit deklarierten speziellen Memberfunktionen des ISO-C++-Standards werden verwendet und nicht gesondert re-deklariert. Das Array besitzt seine Elemente direkt inline im selben Speicherbereich. Die Lebensdauer der enthaltenen Elemente ist folglich untrennbar an die Lebensdauer des umschließenden Array-Objekts gekoppelt; es findet vermutlich keine dynamische Allokation auf dem Freispeicher (Heap) statt, was für deterministisches Zeit- und Speicherverhalten sorgt. <a class="interp-q interp-q-open" data-q="Q-945fdce67844d6a6" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-945fdce67844d6a6" title="Frage Q-945fdce67844d6a6 (offen): Vermutlich keine dynamische Heap-Allokation">Frage Q-945fdce67844d6a6 (offen)</a></p>
<p>Der Container befindet sich stets in einem gültigen Zustand und verwaltet exakt <code>N</code> Elemente. Ob das Array Elemente aufnehmen kann oder als Sonderfall mit <code>N = 0</code> vorliegt, lässt sich über <code>empty()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01264" href="../spec/record.html?id=SWS_CORE_01264">[SWS_CORE_01264]</a>), <code>size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01262" href="../spec/record.html?id=SWS_CORE_01262">[SWS_CORE_01262]</a>) sowie <code>max_size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01263" href="../spec/record.html?id=SWS_CORE_01263">[SWS_CORE_01263]</a>) evaluieren. Bezüglich der Nebenläufigkeit dürfte gelten, dass nebenläufige lesende Zugriffe ohne Synchronisation sicher sind, während parallele schreibende Modifikationen einer externen Koordinierung durch den Aufrufer bedürfen. <a class="interp-q interp-q-open" data-q="Q-7abd5842b7560a04" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-7abd5842b7560a04" title="Frage Q-7abd5842b7560a04 (offen): Nebenläufige modifizierende Zugriffe dürften externe Synchronisation erfordern">Frage Q-7abd5842b7560a04 (offen)</a></p>

<h4>Nutzungspfad</h4>
<p>In typischen Anwendungsfällen durchläuft <code>ara::core::Array</code> eine Abfolge von Initialisierung, Elementbefüllung, wahlfreiem oder sequentiellem Zugriff sowie gegebenenfalls Inhaltsaustausch:</p>
<ul>
<li><strong>Initialisierung und Befüllung:</strong> Der gesamte Datenpuffer kann über <code>fill()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>) einheitlich mit einem vorgegebenen Wert belegt werden.</li>
<li><strong>Wahlfreier Zugriff:</strong> Für performante Zugriffe steht der unüberprüfte Indexoperator <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_CORE_01265" href="../spec/record.html?id=SWS_CORE_01265">[SWS_CORE_01265]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01266" href="../spec/record.html?id=SWS_CORE_01266">[SWS_CORE_01266]</a>) zur Verfügung. Wenn eine Bereichsüberprüfung erforderlich ist, wird <code>at()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01273" href="../spec/record.html?id=SWS_CORE_01273">[SWS_CORE_01273]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01274" href="../spec/record.html?id=SWS_CORE_01274">[SWS_CORE_01274]</a>) herangezogen.</li>
<li><strong>Randelemente:</strong> Der direkte Zugriff auf das erste und letzte Element erfolgt über <code>front()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>) und <code>back()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>).</li>
<li><strong>Iteration:</strong> Das Durchlaufen des Containers erfolgt vorwärts über <code>begin()</code> und <code>end()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01252" href="../spec/record.html?id=SWS_CORE_01252">[SWS_CORE_01252]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01253" href="../spec/record.html?id=SWS_CORE_01253">[SWS_CORE_01253]</a>) oder über konstante Iteratoren wie <code>cbegin()</code> und <code>cend()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01258" href="../spec/record.html?id=SWS_CORE_01258">[SWS_CORE_01258]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01259" href="../spec/record.html?id=SWS_CORE_01259">[SWS_CORE_01259]</a>). Die Iteratortypen sind als elementare Zeiger <code>T*</code> bzw. <code>const T*</code> definiert (<a class="spec-record-ref" data-req="SWS_CORE_01212" href="../spec/record.html?id=SWS_CORE_01212">[SWS_CORE_01212]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01213" href="../spec/record.html?id=SWS_CORE_01213">[SWS_CORE_01213]</a>). Für umgekehrte Traversierungen stehen <code>rbegin()</code>, <code>rend()</code>, <code>crbegin()</code> und <code>crend()</code> bereit (<a class="spec-record-ref" data-req="SWS_CORE_01254" href="../spec/record.html?id=SWS_CORE_01254">[SWS_CORE_01254]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01255" href="../spec/record.html?id=SWS_CORE_01255">[SWS_CORE_01255]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01256" href="../spec/record.html?id=SWS_CORE_01256">[SWS_CORE_01256]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01257" href="../spec/record.html?id=SWS_CORE_01257">[SWS_CORE_01257]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01260" href="../spec/record.html?id=SWS_CORE_01260">[SWS_CORE_01260]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01261" href="../spec/record.html?id=SWS_CORE_01261">[SWS_CORE_01261]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01219" href="../spec/record.html?id=SWS_CORE_01219">[SWS_CORE_01219]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01220" href="../spec/record.html?id=SWS_CORE_01220">[SWS_CORE_01220]</a>).</li>
<li><strong>Zeigerzugriff und Austausch:</strong> Der zugrundeliegende Speicherbereich kann über <code>data()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>) als Zeiger übergeben werden. Zwei gleich dimensionierte Arrays lassen sich mittels <code>swap()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>) austauschen.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Spezifikation definiert strenge Vor- und Nachbedingungen für Grenz- und Fehlersituationen:</p>
<ul>
<li><strong>Bereichsverletzung bei indiziertem Zugriff:</strong> Wenn bei <code>at()</code> der Index <code>n</code> außerhalb der Array-Grenzen liegt (<code>n &gt;= size()</code>), wird <code>IsoStdOutOfRangeViolation</code> ausgelöst anstelle der C++-Standard-Ausnahme <code>std::out_of_range</code> (<a class="spec-record-ref" data-req="SWS_CORE_01273" href="../spec/record.html?id=SWS_CORE_01273">[SWS_CORE_01273]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01274" href="../spec/record.html?id=SWS_CORE_01274">[SWS_CORE_01274]</a>). Beide Überladungen sind mit <code>noexcept</code> deklariert.</li>
<li><strong>Zugriff auf leere Instanzen:</strong> Das Aufrufen von <code>front()</code> oder <code>back()</code> auf einem leeren Array (<code>empty() == true</code>, also <code>N = 0</code>) führt verpflichtend zu einem Übersetzungszeitfehler (Compile-Time Error) (<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>).</li>
<li><strong>Undefiniertes Verhalten bei Iteratoren:</strong> Das Dereferenzieren des von <code>begin()</code> zurückgegebenen Iterators auf einem leeren Array stellt undefiniertes Verhalten dar (<a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>).</li>
<li><strong>Sonderfall Zeigerabruf:</strong> Ist die Größe des Arrays <code>0</code>, liefert die Elementfunktion <code>data()</code> zwingend <code>nullptr</code> (<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>).</li>
<li><strong>Bedingte Ausnahme-Sicherheit:</strong> Die Operation <code>swap()</code> ist nur dann <code>noexcept</code>, wenn die typbezogene Bedingung <code>ara::core::is_nothrow_swappable&lt;T&gt;::value</code> erfüllt ist (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). Entsprechend bestimmt sich die <code>noexcept</code>-Eigenschaft von <code>fill()</code> über <code>std::is_nothrow_copy_assignable&lt;T&gt;::value</code> (<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>).</li>
</ul>
