<h4>Context</h4>
<p>The template class <code>ara::core::Array</code> provides a standard-compliant adaptation of <code>std::array</code> in the Adaptive Platform. It encapsulates a fixed-size array <code>N</code> with elements of type <code>T</code> and avoids dynamic memory allocations at runtime. As a fundamental sequential container, <code>ara::core::Array</code> serves functional clusters and AUTOSAR applications as a type-safe data structure for passing payload data with a statically known number of elements.</p>
<p>The interface is closely aligned with the requirements of the C++ standard, but defines specific adaptations for the AUTOSAR runtime environment. These include typed interfaces for indexing, iterators, and memory queries. The type aliases for references and pointers (<a class="spec-record-ref" data-req="SWS_CORE_01210" href="../spec/record.html?id=SWS_CORE_01210">[SWS_CORE_01210]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01211" href="../spec/record.html?id=SWS_CORE_01211">[SWS_CORE_01211]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01217" href="../spec/record.html?id=SWS_CORE_01217">[SWS_CORE_01217]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01218" href="../spec/record.html?id=SWS_CORE_01218">[SWS_CORE_01218]</a>), indices (<a class="spec-record-ref" data-req="SWS_CORE_01214" href="../spec/record.html?id=SWS_CORE_01214">[SWS_CORE_01214]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01215" href="../spec/record.html?id=SWS_CORE_01215">[SWS_CORE_01215]</a>), and forward as well as reverse iterators (<a class="spec-record-ref" data-req="SWS_CORE_01212" href="../spec/record.html?id=SWS_CORE_01212">[SWS_CORE_01212]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01213" href="../spec/record.html?id=SWS_CORE_01213">[SWS_CORE_01213]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01219" href="../spec/record.html?id=SWS_CORE_01219">[SWS_CORE_01219]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01220" href="../spec/record.html?id=SWS_CORE_01220">[SWS_CORE_01220]</a>) ensure interoperability with standard algorithms and generic interfaces.</p>

<h4>Lifecycle</h4>
<p>As an aggregate type, <code>ara::core::Array</code> directly binds the contained elements to its own memory representation. The implicitly declared special member functions (such as default, copy, and move constructors as well as destructors) are not explicitly re-declared according to the specification, but follow the standard behavior of C++ arrays. The lifetime of all <code>N</code> elements is thus inextricably linked to the lifetime of the container instance.</p>
<p>Dimensioning is determined at compile time via the template parameter <code>N</code>. Size query methods such as <code>size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01262" href="../spec/record.html?id=SWS_CORE_01262">[SWS_CORE_01262]</a>), <code>max_size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01263" href="../spec/record.html?id=SWS_CORE_01263">[SWS_CORE_01263]</a>), and <code>empty()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01264" href="../spec/record.html?id=SWS_CORE_01264">[SWS_CORE_01264]</a>) are declared as <code>constexpr</code> and <code>noexcept</code>. Exchanging the content of two equally dimensioned instances is performed via <code>swap()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). The exception safety of <code>swap()</code> conditionally depends on whether the element type <code>T</code> is specified as non-throwing via <code>ara::core::is_nothrow_swappable&lt;T&gt;::value</code> (<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>). With regard to concurrency, <code>ara::core::Array</code> provides no internal synchronization; concurrent write accesses to the same instance must be synchronized by the application (Interpretation).</p>

<h4>Usage Path</h4>
<p>The typical usage of <code>ara::core::Array</code> is divided into initialization, sequential or random data processing, and passing to low-level interfaces:</p>
<ul>
<li><strong>Initialization and filling:</strong> The container can be initially populated or homogeneously written with a copy of a value via the method <code>fill()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>). The operation is <code>noexcept</code> provided that the element type is assignment-safe (<code>std::is_nothrow_copy_assignable&lt;T&gt;::value</code>).</li>
<li><strong>Random and direct element access:</strong> For performant access without runtime checks, <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_CORE_01265" href="../spec/record.html?id=SWS_CORE_01265">[SWS_CORE_01265]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01266" href="../spec/record.html?id=SWS_CORE_01266">[SWS_CORE_01266]</a>) is available. The boundary elements can be referenced via <code>front()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>) and <code>back()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>).</li>
<li><strong>Iterator-compliant processing:</strong> Algorithms can iterate over the sequence using forward iterators (<code>begin()</code> / <code>end()</code> acc. to <a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01252" href="../spec/record.html?id=SWS_CORE_01252">[SWS_CORE_01252]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01253" href="../spec/record.html?id=SWS_CORE_01253">[SWS_CORE_01253]</a>), constant iterators (<code>cbegin()</code> / <code>cend()</code> acc. to <a class="spec-record-ref" data-req="SWS_CORE_01258" href="../spec/record.html?id=SWS_CORE_01258">[SWS_CORE_01258]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01259" href="../spec/record.html?id=SWS_CORE_01259">[SWS_CORE_01259]</a>), or reverse iterators (<code>rbegin()</code> / <code>rend()</code> / <code>crbegin()</code> / <code>crend()</code> acc. to <a class="spec-record-ref" data-req="SWS_CORE_01254" href="../spec/record.html?id=SWS_CORE_01254">[SWS_CORE_01254]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01255" href="../spec/record.html?id=SWS_CORE_01255">[SWS_CORE_01255]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01256" href="../spec/record.html?id=SWS_CORE_01256">[SWS_CORE_01256]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01257" href="../spec/record.html?id=SWS_CORE_01257">[SWS_CORE_01257]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01260" href="../spec/record.html?id=SWS_CORE_01260">[SWS_CORE_01260]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01261" href="../spec/record.html?id=SWS_CORE_01261">[SWS_CORE_01261]</a>).</li>
<li><strong>C-API bridge:</strong> The method <code>data()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>) provides a direct pointer to the underlying contiguous memory segment, for example for passing to drivers or serialization routines.</li>
</ul>
