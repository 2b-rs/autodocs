<p class="ai-level ai-oneliner-lead" data-ai-level="1">Verarbeitet und speichert eingehende Datenblöcke bei schreibenden Dateitransfers in der Anwendung.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::DataTransferWriteHandler</code> dient in AUTOSAR Adaptive der anwendungsseitigen Verarbeitung von schreibenden Dateitransfers, die durch <code>RequestWriteFile</code> in den Modi <code>AddFile</code>, <code>ResumeFile</code> oder <code>ReplaceFile</code> angestoßen wurden <a class="spec-record-ref" data-req="SWS_DM_01539" href="../spec/record.html?id=SWS_DM_01539">[SWS_DM_01539]</a>. Eingehende Datenpakete werden asynchron über <code>Write()</code> in den Speicher geschrieben und die Sitzung anschließend mittels <code>ExitWrite()</code> abgeschlossen. Eine Instanz ist strikt an eine einzelne Übertragungssitzung gebunden und darf keinesfalls vor dem Aufruf von <code>ExitWrite()</code> zerstört werden <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die abstrakte Basisklasse <code>ara::diag::DataTransferWriteHandler</code> definiert in der AUTOSAR Adaptive Platform die Schnittstelle für schreibende Dateitransfers <a class="spec-record-ref" data-req="SWS_DM_01539" href="../spec/record.html?id=SWS_DM_01539">[SWS_DM_01539]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=387">AUTOSAR_AP_SWS_Diagnostics §8.10.6 „Class: DataTransferWriteHandler“</a>). Sie dient der anwendungsseitigen Verarbeitung von Datenübertragungen, die im Rahmen von <code>RequestWriteFile</code> über die Betriebsmodi <code>AddFile</code>, <code>ResumeFile</code> oder <code>ReplaceFile</code> angestoßen wurden.</p>
<p>Innerhalb der Diagnosearchitektur interagiert der Handler mit dem externen UDS-Client, der Diagnose-Middleware und der Anwendung. Der Client übermittelt segmentierte Datenblöcke, die von einer abgeleiteten Implementierung des Handlers entgegengenommen und im Anwendungsspeicher abgelegt werden <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>. Vermutlich übernimmt das Diagnose-Management der Plattform dabei die UDS-Protokollkoordination und reicht die Nutzdaten über die Handler-Schnittstelle an die Zielanwendung weiter. <a class="interp-q interp-q-open" data-q="Q-484dc9dd80e56af4" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-484dc9dd80e56af4" title="Frage Q-484dc9dd80e56af4 (offen): Die Vermittlung und Protokollabwicklung zwischen dem externen UDS-Client und dem Handler dürfte durch das Diagnose-Management der Plattform erfolgen.">Frage Q-484dc9dd80e56af4 (offen)</a></p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>ara::diag::DataTransferWriteHandler</code> erfolgt ausschließlich durch spezialisierte Unterklassen der Anwendung: Der parameterlose Konstruktor ist mit <code>protected</code> und <code>noexcept=default</code> definiert <a class="spec-record-ref" data-req="SWS_DM_01540" href="../spec/record.html?id=SWS_DM_01540">[SWS_DM_01540]</a>, was eine direkte Instanziierung der Basisklasse verhindert. Eine Handler-Instanz ist strikt an eine einzelne Dateiübertragungssitzung gebunden („one way usage i.e. per single file transfer session“). Aus diesem Grund sind der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01544" href="../spec/record.html?id=SWS_DM_01544">[SWS_DM_01544]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.2.1 „DataTransferWriteHandler“</a>) und der Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01545" href="../spec/record.html?id=SWS_DM_01545">[SWS_DM_01545]</a> gelöscht (<code>=delete</code>).</p>
<p>Verschiebeoperationen sind hingegen zulässig: Sowohl der Verschiebekonstruktor <a class="spec-record-ref" data-req="SWS_DM_01542" href="../spec/record.html?id=SWS_DM_01542">[SWS_DM_01542]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.1 „Move Constructor“</a>) als auch der Verschiebezuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01543" href="../spec/record.html?id=SWS_DM_01543">[SWS_DM_01543]</a> sind mit <code>noexcept=default</code> implementiert und gelten als ausnahmesicher (<code>exception safe</code>).</p>
<p>Für den Abbau der Instanz gilt eine bindende Vorbedingung: Eine Instanz dieser Klasse darf keinesfalls zerstört werden, bevor die Methode <code>ExitWrite()</code> aufgerufen wurde <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.2 „Destructor“</a>). Erst nach vollständiger Durchführung von <code>ExitWrite()</code> darf der virtuelle Destruktor <code>~DataTransferWriteHandler()</code> aufgerufen werden. Die Elementfunktionen und der Destruktor sind als nicht threadsicher (<code>not thread-safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>, <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>, <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf eines schreibenden Transfers umfasst das schrittweise Empfangen von Datenblöcken und den anschließenden Abschluss der Sitzung:</p>
<ul>
  <li>Für jedes eintreffende Datensegment ruft das Diagnosesystem die rein virtuelle Methode <code>Write()</code> auf <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=390">AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.2 „Write“</a>). Die Daten werden als <code>ara::core::Span&lt;ara::core::Byte&gt;</code> übergeben. Die Gültigkeit dieses Speicherbereichs bleibt bestehen, bis das zugehörige <code>Promise</code> erfüllt oder die Operation abgebrochen wird. Die Anwendung hängt die Daten an den internen Puffer an und liefert ein <code>ara::core::Future&lt;void&gt;</code> zurück.</li>
  <li>Nachdem alle Segmente übertragen wurden, ruft die Plattform die rein virtuelle Methode <code>ExitWrite()</code> auf <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.1 „ExitWrite“</a>). Übergeben werden der Beendigungsgrund (<code>DataTransferExitType</code>), fahrzeugherstellerspezifische Parameter (<code>transferRequestParameterRecord</code>), <code>metaInfo</code> sowie ein <code>CancellationHandler</code>.</li>
  <li>Die Methode <code>ExitWrite()</code> gibt ein <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code> zurück. Bei erfolgreichem Abschluss werden die darin enthaltenen Daten als <code>transferResponseParameterRecord</code> hinter der Service-ID in die positive UDS-Antwortnachricht eingefügt <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Fehler während der Datenverarbeitung und des Transfers werden über standardisierte Rückgabewerte und Abbruchmechanismen verwaltet:</p>
<ul>
