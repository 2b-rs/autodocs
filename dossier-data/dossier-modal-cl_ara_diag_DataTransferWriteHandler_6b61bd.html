<h4>Context</h4>
<p>Within the adaptive diagnostics architecture (<code>ara::diag</code>), the class <code>ara::diag::DataTransferWriteHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01539" href="../spec/record.html?id=SWS_DM_01539">[SWS_DM_01539]</a> acts as a specialized interface for handling incoming write transfers <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=387">AUTOSAR AP SWS Diagnostics §8.10.6 “Class: DataTransferWriteHandler”</a>. It serves to process data transfers initiated by a diagnostic <code>RequestWriteFile</code> request in the operating modes <code>AddFile</code>, <code>ResumeFile</code>, or <code>ReplaceFile</code>.</p>
<p>Three key entities are involved in executing a write transfer:</p>
<ul>
  <li>The external <strong>UDS client</strong>, which requests the file transfer and transmits the write data block by block via diagnostic messages <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>.</li>
  <li>The platform's <strong>diagnostic management</strong> (<code>ara::diag</code>), which manages communication at the transport and protocol levels and coordinates the transfer.</li>
  <li>The concrete <strong>application software</strong>, which inherits from <code>DataTransferWriteHandler</code> and persists or processes the transferred file blocks in local storage <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>Instances of <code>DataTransferWriteHandler</code> are subject to a strict, session-bound lifecycle. They are designed exclusively for one-way use during a single file transfer session ("one way usage i.e. per single file transfer session") <a class="spec-record-ref" data-req="SWS_DM_01544" href="../spec/record.html?id=SWS_DM_01544">[SWS_DM_01544]</a>, <a class="spec-record-ref" data-req="SWS_DM_01545" href="../spec/record.html?id=SWS_DM_01545">[SWS_DM_01545]</a>.</p>
<ul>
  <li><strong>Creation:</strong> The default constructor <code>DataTransferWriteHandler()</code> is <code>protected</code> and declared as <code>default</code> and <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_01540" href="../spec/record.html?id=SWS_DM_01540">[SWS_DM_01540]</a>. Consequently, instantiation always takes place via an application-specifically derived subclass; interpretation: The handler instance is likely provided by the application logic at the start of the write request.</li>
  <li><strong>Copying and moving:</strong> Duplicating the handler is prohibited: Both the copy constructor <a class="spec-record-ref" data-req="SWS_DM_01544" href="../spec/record.html?id=SWS_DM_01544">[SWS_DM_01544]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01545" href="../spec/record.html?id=SWS_DM_01545">[SWS_DM_01545]</a> are explicitly deleted (<code>=delete</code>) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR AP SWS Diagnostics §8.10.6.1.2 “Constructors”</a>. Conversely, move semantics are fully supported; move constructor <a class="spec-record-ref" data-req="SWS_DM_01542" href="../spec/record.html?id=SWS_DM_01542">[SWS_DM_01542]</a> and move assignment <a class="spec-record-ref" data-req="SWS_DM_01543" href="../spec/record.html?id=SWS_DM_01543">[SWS_DM_01543]</a> are defined with <code>=default</code> and <code>noexcept</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”</a>.</li>
  <li><strong>Destruction and precondition:</strong> The virtual destructor <code>~DataTransferWriteHandler()</code> is exception-safe (<code>noexcept</code>) <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”</a>. It is an explicit precondition that an instance of the class must not be destroyed before the termination method <code>ExitWrite()</code> has been called <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>.</li>
  <li><strong>Concurrency:</strong> The methods <code>Write()</code>, <code>ExitWrite()</code> and the destructor are specified as not thread-safe (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>, <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>, <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>. Interpretation: Calls to a handler instance are likely to be made sequentially from the same processing context of the diagnostic framework.</li>
</ul>

<h4>Usage Path</h4>
<p>The regular sequence of a file write transfer is divided into repeated data intake and orderly session termination:</p>
<ol>
  <li><strong>Reception of file contents:</strong> As soon as a first or subsequent file block arrives from the UDS client, the diagnostic system calls the method <code>Write(requestData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=390">AUTOSAR AP SWS Diagnostics §8.10.6.1.3.2 “Write”</a>. The application accepts the raw data (<code>ara::core::Span&lt;ara::core::Byte&gt;</code>) and writes it into the designated buffer. The passed data remains valid until the returned <code>ara::core::Future&lt;void&gt;</code> is fulfilled or the operation is canceled <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>.</li>
  <li><strong>Iterative transfer:</strong> This step is repeated sequentially for each subsequent chunk of the file.</li>
  <li><strong>Terminating the transfer session:</strong> After all blocks have arrived or upon cancellation, the platform calls <code>ExitWrite(exitType, transferRequestParameterRecord, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR AP SWS Diagnostics §8.10.6.1.3.1 “ExitWrite”</a>. In doing so, the termination reason (<code>DataTransferExitType</code>) as well as manufacturer-specific parameters are passed.</li>
  <li><strong>Final response:</strong> The method returns a <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code>. Upon successful completion, the data contained therein is placed as <code>transferResponseParameterRecord</code> directly after the SID in the positive response message <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>.</li>
  <li><strong>Releasing the instance:</strong> Only after <code>ExitWrite()</code> has been called may the handler be destroyed <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error and cancellation states are controlled asynchronously via the <code>Future</code> returns and the <code>CancellationHandler</code>:</p>
<ul>
  <li><strong>Negative Response Codes (NRC):</strong> If a write operation or termination cannot be executed successfully, the application signals this by completing the <code>ara::core::Future</code> with a corresponding error code (<code>ErrorCode</code> from <code>DiagUdsNrcErrc</code> in accordance with ISO 14229-1) <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>, <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>. This causes the diagnostic framework to send a UDS Negative Response Message.</li>
  <li><strong>Cancellation handling:</strong> The parameters <code>cancellationHandler</code> in <code>Write()</code> and <code>ExitWrite()</code> allow the application to query via <code>cancellationHandler.IsCanceled()</code> before or during time-consuming write operations whether the session has been canceled <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>, <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>. Alternatively, a notification function can be registered via <code>cancellationHandler.SetNotifier</code> that is actively called in the event of a connection abort.</li>
  <li><strong>Premature destruction:</strong> If the instance of <code>DataTransferWriteHandler</code> is destroyed before <code>ExitWrite()</code> has been executed, the calling component violates the contractual precondition of the interface <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>.</li>
</ul>
