  <h4>Context</h4>
  <p>The class <code>ara::diag::DataTransferReadSharedDataHandler</code> serves to handle UDS data transfer sessions initiated via <code>RequestReadFile</code> or <code>RequestReadDirectory</code> (<a class="spec-record-ref" data-req="SWS_DM_01497" href="../spec/record.html?id=SWS_DM_01497">[SWS_DM_01497]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=382">AUTOSAR_AP_SWS_Diagnostics §8.10.5 “Class: DataTransferReadSharedDataHandler”</a>). Its central characteristic compared to sequential streaming methods lies in the use of shared memory areas (shared data): The application provides the entire file or directory data to be read out in memory at once and provides AraDiag with a direct view of it (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>).</p>
  <p>Essentially three components are involved in the interaction (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>):</p>
  <ul>
    <li><strong>UDS Client (diagnostic tester):</strong> Initiates the read request via the diagnostic interface, requests data blocks, and signals the end of the transfer.</li>
    <li><strong>AraDiag:</strong> Manages the UDS transfer session, forwards calls to the handler, reads from the provided memory area, and controls the release.</li>
    <li><strong>Application (handler implementation):</strong> Implements the concrete derivation of <code>ara::diag::DataTransferReadSharedDataHandler</code>, allocates the data buffer, and keeps it valid until released by AraDiag.</li>
  </ul>

  <h4>Lifecycle</h4>
  <p>Instances of <code>ara::diag::DataTransferReadSharedDataHandler</code> have a strict lifetime binding to a single file transfer session (<a class="spec-record-ref" data-req="SWS_DM_01501" href="../spec/record.html?id=SWS_DM_01501">[SWS_DM_01501]</a>). The class provides a default constructor (<a class="spec-record-ref" data-req="SWS_DM_01498" href="../spec/record.html?id=SWS_DM_01498">[SWS_DM_01498]</a>). To prevent accidental multiple use or shared ownership during a transfer, the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01501" href="../spec/record.html?id=SWS_DM_01501">[SWS_DM_01501]</a>) and copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01503" href="../spec/record.html?id=SWS_DM_01503">[SWS_DM_01503]</a>) are explicitly deleted. Moving instances, on the other hand, is permitted via the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01500" href="../spec/record.html?id=SWS_DM_01500">[SWS_DM_01500]</a>) and move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01502" href="../spec/record.html?id=SWS_DM_01502">[SWS_DM_01502]</a>) (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=383">AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.1 “Special Member Functions”</a>).</p>
  <p>Buffer management is subject to clear ownership: The entire memory area to be read is allocated by the application (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>). AraDiag merely obtains a temporary view via <code>ara::core::Span&lt;ara::core::Byte&gt;</code>. The application is obliged to keep the referenced memory area unchanged in memory until AraDiag signals via the passed <code>ReleaseHandler</code> (by means of polling or a registered notifier) that the memory may be safely released (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>).</p>
  <p>A binding precondition applies to destruction: An instance of the handler must never be destroyed before <code>ExitRead()</code> has been called (<a class="spec-record-ref" data-req="SWS_DM_01499" href="../spec/record.html?id=SWS_DM_01499">[SWS_DM_01499]</a>). The destructor is declared virtual (<a class="spec-record-ref" data-req="SWS_DM_01499" href="../spec/record.html?id=SWS_DM_01499">[SWS_DM_01499]</a>). All constructors and assignment operators are specified as exception-safe (<code>exception safe</code>) (<a class="spec-record-ref" data-req="SWS_DM_01498" href="../spec/record.html?id=SWS_DM_01498">[SWS_DM_01498]</a>, <a class="spec-record-ref" data-req="SWS_DM_01500" href="../spec/record.html?id=SWS_DM_01500">[SWS_DM_01500]</a>, <a class="spec-record-ref" data-req="SWS_DM_01502" href="../spec/record.html?id=SWS_DM_01502">[SWS_DM_01502]</a>). With regard to concurrency, the method calls are classified as non-thread-safe (<code>not thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>, <a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>).</p>

  <h4>Usage Path</h4>
  <p>A regular flow is divided into the following call steps:</p>
  <ol>
    <li><strong>Provision of data:</strong> AraDiag calls the pure virtual method <code>Read()</code> (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=384">AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.3 “Member Functions”</a>). The application saves the passed <code>ReleaseHandler</code>, checks the <code>CancellationHandler</code> if applicable, and allocates the memory for the file or directory data. It returns a <code>ara::core::Future</code> that resolves to a <code>ara::core::Span&lt;ara::core::Byte&gt;</code> (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>).</li>
    <li><strong>Data transfer and buffer release:</strong> AraDiag serves the client's UDS transfer queries from the provided span. As soon as AraDiag no longer requires the memory, the notifier of the <code>ReleaseHandler</code> is triggered (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>). The application can now deallocate the buffer.</li>
    <li><strong>Session termination:</strong> After completion of the transfers, AraDiag calls <code>ExitRead()</code> (<a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>). The termination reason (<code>DataTransferExitType</code>), manufacturer-specific request parameters (<code>transfer_request_parameter_record</code>), as well as context data (<code>MetaInfo</code>) and a <code>CancellationHandler</code> are passed (<a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>). The application terminates the transfer session and returns a <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code> with the positive response data (<a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>).</li>
    <li><strong>Object destruction:</strong> Only after <code>ExitRead()</code> has been called is the handler instance released (<a class="spec-record-ref" data-req="SWS_DM_01499" href="../spec/record.html?id=SWS_DM_01499">[SWS_DM_01499]</a>).</li>
  </ol>

  <h4>Error Scenarios</h4>
  <p>If errors occur during processing, the handler signals this via the return futures:</p>
  <ul>
    <li><strong>UDS error during <code>Read()</code>:</strong> If loading or providing the file fails, the future of <code>Read()</code> is not resolved with a span, but completed with an error code from <code>DiagUdsNrcErrc</code> in accordance with ISO 14229-1 (Negative Response Code, NRC) (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>).</li>
    <li><strong>UDS error during <code>ExitRead()</code>:</strong> If the session cannot be completed successfully, the future of <code>ExitRead()</code> is likewise completed with a matching error code from <code>DiagUdsNrcErrc</code> (<a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>).</li>
    <li><strong>Cancellation of the diagnostic conversation:</strong> Both <code>Read()</code> and <code>ExitRead()</code> receive a <code>CancellationHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_01504" href="../spec/record.html?id=SWS_DM_01504">[SWS_DM_01504]</a>, <a class="spec-record-ref" data-req="SWS_DM_01505" href="../spec/record.html?id=SWS_DM_01505">[SWS_DM_01505]</a>). Via <code>cancellation_handler.IsCanceled()</code>, the application can query a cancellation or register a callback function using <code>cancellation_handler.SetNotifier()</code> to immediately abort asynchronous computations in the event of premature session cancellation.</li>
    <li><strong>Premature destruction:</strong> If the instance is destroyed before <code>ExitRead()</code> is called, this constitutes a violation of the specification requirement (<a class="spec-record-ref" data-req="SWS_DM_01499" href="../spec/record.html?id=SWS_DM_01499">[SWS_DM_01499]</a>).</li>
  </ul>
