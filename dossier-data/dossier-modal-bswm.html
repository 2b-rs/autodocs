<p class="ai-level ai-oneliner-lead" data-ai-level="1">Arbitriert Modusanforderungen und -anzeigen per Regeln und löst daraus Aktionen in der Basissoftware aus.</p>
<div class="ai-level" data-ai-level="2">
<p>Der BSW Mode Manager nimmt Modusanzeigen von BSW-Modulen und Modusanforderungen von SW-Cs entgegen. Er arbitriert sie über konfigurierte Regeln, deren Ergebnis True- oder False-Aktionslisten auslöst <a class="spec-record-ref" data-req="SWS_BswM_00035" href="../../spec/record.html?id=SWS_BswM_00035">[SWS_BswM_00035]</a>. Nach <code>BswM_Init</code> steuert er so die weitere Initialisierung der Basissoftware, das ECU Mode Handling mit dem EcuM und die Kommunikationsfreigabe, etwa von I-PDU-Gruppen oder Ethernet-Port-Gruppen. Regeln mit <code>BSWM_DEFERRED</code>-Eingängen wertet <code>BswM_MainFunction</code> zyklisch aus, alle anderen sofort <a class="spec-record-ref" data-req="SWS_BswM_00075" href="../../spec/record.html?id=SWS_BswM_00075">[SWS_BswM_00075]</a>. Ungültige oder vor der Initialisierung eintreffende Anforderungen werden bei aktivem DET ignoriert und gemeldet.</p>

</div>
<div class="ai-level" data-ai-level="3">
<p>Der BSW Mode Manager (BswM) ist die zentrale Arbitrierungsinstanz der Basissoftware. Er nimmt Modusanzeigen von BSW-Modulen wie EcuM, ComM, den Bus-State-Managern, NvM, DCM oder Sd entgegen, außerdem Modusanforderungen von SW-Cs. Daraus entscheidet er über konfigurierte Regeln, was geschehen soll <a class="spec-record-ref" data-req="SWS_BswM_00035" href="../../spec/record.html?id=SWS_BswM_00035">[SWS_BswM_00035]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration">SWS BswM S. 26</a>. Eingänge kommen als C-APIs, als SW-C-Ports oder als Ereignisse an. Jede C-API ist über Referenzparameter einem konkreten Request-Port zugeordnet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_8_8_API_to_Request_Port_Mappings.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_8_8_API_to_Request_Port_Mappings">SWS BswM S. 87</a>.</p>

<h4>Rolle des BswM: zentrale Modus-Arbitrierung der Basissoftware</h4>
<p>Der BSW Mode Manager (BswM) nimmt Modusanforderungen und Modusanzeigen entgegen. Daraus arbitriert er über konfigurierte Regeln, welche Aktionen auszuführen sind <a class="spec-record-ref" data-req="SWS_BswM_00035" href="../../spec/record.html?id=SWS_BswM_00035">[SWS_BswM_00035]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration">SWS BswM S. 26</a>. Modusanforderungen stammen meist von Anwendungs-SW-Cs, können aber auch von BSW-Modulen wie dem DCM kommen. Modusanzeigen liefern stets andere BSW-Module, etwa die busspezifischen State Manager und der EcuM. Beide Arten behandelt der BswM gleich und fasst sie unter dem Begriff „mode arbitration request“ zusammen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_1_3_Requirements_of_Mode_Arbitration">SWS BswM S. 26</a>.</p>
<p>Der BswM ist als Service-Komponente modelliert, die ECU-lokale Mode Requests bedient <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_6_4_Component_Type_and_Internal_Behavior.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_6_4_Component_Type_and_Internal_Behavior">SWS BswM S. 48</a>. Er hat keine Pflichtschnittstellen zu anderen Modulen <a class="spec-record-ref" data-req="SWS_BswM_00007" href="../../spec/record.html?id=SWS_BswM_00007">[SWS_BswM_00007]</a>. Seine Aktionen rufen Funktionen anderer BSW-Module auf. Dafür nennt die Spezifikation eine Liste optionaler Schnittstellen, etwa <code>Com_IpduGroupStart</code>, <code>Com_IpduGroupStop</code> oder die Steuerung der Empfangsüberwachung von I-PDU-Gruppen <a class="spec-record-ref" data-req="SWS_BswM_00008" href="../../spec/record.html?id=SWS_BswM_00008">[SWS_BswM_00008]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_COMM_SECTION_8_6_2_Optional_Interfaces_BSWMODEMANAGER.html" data-snip="SNIP_CLASSIC_COMM_SECTION_8_6_2_Optional_Interfaces_BSWMODEMANAGER">SWS BswM S. 93</a>. Die Systemgrenze ist damit klar gezogen: Die meldenden Module berichten nur ihren Zustand. Die Reaktion darauf bestimmt allein die konfigurierte Logik im BswM <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior">Mode-Mgmt-Guide S. 32</a>.</p>

<h4>Eingänge: Modusanzeigen über C-APIs, Ports und Ereignisse</h4>
<p>Der Container <code>BswMModeRequestSource</code> legt fest, wie ein Eingang ankommt. Es gibt drei Arten <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_1_Interface_of_the_BSWM.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_1_Interface_of_the_BSWM">Mode-Mgmt-Guide S. 18</a>:</p>
<ul>
<li>eine C-API, die ein BSW-Modul direkt aufruft und die der BswM intern in einen Mode Request übersetzt,</li>

Laut Änderungshistorie brachte R20-11 folgende Neuerungen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_General_Overview">SWS BswM S. 2</a>:</p>
<ul>

<li>neue Benachrichtigung <code>BswMNmStateChangeNotification</code>,</li>
<li>Unterstützung der Ethernet-Port-Gruppen-Schaltung.</li>
</ul>
<p><code>BswM_WdgM_RequestPartitionReset</code> wird erst in R21-11 obsolet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_General_Overview">SWS BswM S. 2</a>.</p>

<h4>Regeln und Aktionslisten: vom Eingang zur Aktion</h4>
<p>Das Verhalten des BswM wird über Regeln und Aktionslisten konfiguriert. Eine Regel ist ein logischer Ausdruck über die aktuellen Werte der Mode-Request-Ports. Je nach Ergebnis führt ihre Auswertung die True- oder die False-Aktionsliste aus <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior">Mode-Mgmt-Guide S. 32</a>. Eine Aktionsliste kann enthalten <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_FIGURE_Figure_7_2_BSWMODEMANAGER.html" data-snip="SNIP_CLASSIC_BSWM_FIGURE_Figure_7_2_BSWMODEMANAGER">SWS BswM S. 31</a>:</p>
<ul>
<li>atomare Aktionen,</li>
<li>verschachtelte Aktionslisten,</li>
<li>Verweise auf Regeln, die dann im Kontext dieser Liste ausgewertet werden.</li>
</ul>
<p>Aktionen dürfen nur im Kontext einer Aktionsliste aufgerufen werden <a class="spec-record-ref" data-req="SWS_BswM_00147" href="../../spec/record.html?id=SWS_BswM_00147">[SWS_BswM_00147]</a>. Ein Schaubild der Spezifikation zeigt eine Beispielregel. Sie verknüpft per AND eine Mode-Bedingung (<code>MyModeRequestPort</code> gleich <code>MODE_A</code>) mit dem Event-Port <code>ComMInitiateReset</code> <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-710ae2db93ca79f2.html" data-snip="FIG-710ae2db93ca79f2">SWS BswM S. 25</a>.</p>
<p>Wann eine Regel ausgewertet wird, bestimmt <code>BswMRequestProcessing</code> je Port:</p>
<ul>
<li><strong><code>BSWM_IMMEDIATE</code>:</strong> Jede Regel, die den Port referenziert, wird sofort verarbeitet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior">Mode-Mgmt-Guide S. 32</a>. Für SW-C-Ports registriert der BswM dazu ein Runnable, das die RTE beim Datenempfang startet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_6_4_Component_Type_and_Internal_Behavior.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_6_4_Component_Type_and_Internal_Behavior">SWS BswM S. 48</a>.</li>
<li><strong><code>BSWM_DEFERRED</code>:</strong> Der BswM liest den Wert zyklisch. <code>BswM_MainFunction</code> <a class="spec-record-ref" data-req="SWS_BswM_00053" href="../../spec/record.html?id=SWS_BswM_00053">[SWS_BswM_00053]</a> wertet alle Regeln aus, die mindestens einen solchen Eingang verwenden <a class="spec-record-ref" data-req="SWS_BswM_00075" href="../../spec/record.html?id=SWS_BswM_00075">[SWS_BswM_00075]</a>.</li>
</ul>

<p>Über <code>BswMModeInitValue</code> erhält ein Port bei der Initialisierung einen Startwert. Fehlt er, gilt die Bedingung bis zur ersten Aktualisierung als undefiniert. Regeln mit undefinierten Bedingungen werden nicht arbitriert <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_1_4_Arbitration_Behavior_after_Initialization.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_1_4_Arbitration_Behavior_after_Initialization">SWS BswM S. 30</a>. Die Beispiele des Leitfadens setzen deshalb Startwerte, etwa <code>CANSM_BSWM_NO_COMMUNICATION</code> für CanSM-Anzeigen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_3_2_2_2_4_BswMCanSMIndication.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_3_2_2_2_4_BswMCanSMIndication">Mode-Mgmt-Guide S. 24</a>.</p>
<p>Für Wartezeiten bietet der BswM Timer. Ein <code>BswMTimer</code> ist eine interne Mode Request Source und lässt sich nur über die Aktion <code>BswMTimerControl</code> steuern; eine externe Schnittstelle gibt es nicht <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_3_Waiting_Functionality.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_3_Waiting_Functionality">SWS BswM S. 37</a>. Sein Ablauf <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_3_Waiting_Functionality.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_3_Waiting_Functionality">SWS BswM S. 37</a>:</p>
<ul>
<li>Bei der Initialisierung werden alle Timer gestoppt.</li>
<li><code>BSWM_TIMER_START</code> lädt den Timer mit <code>BswMTimerValue</code> und setzt <code>BSWM_TIMER_STARTED</code>.</li>
<li>In jedem Lauf von <code>BswM_MainFunction</code> wird um deren Zykluszeit dekrementiert.</li>
</ul>
<p>Timer werden unabhängig von ihrer Konfiguration immer DEFERRED verarbeitet <a class="spec-record-ref" data-req="SWS_BswM_00220" href="../../spec/record.html?id=SWS_BswM_00220">[SWS_BswM_00220]</a>. <h4>Hochlauf, Initialisierungsketten und Herunterfahren</h4>
<p><code>BswM_Init</code> <a class="spec-record-ref" data-req="SWS_BswM_00002" href="../../spec/record.html?id=SWS_BswM_00002">[SWS_BswM_00002]</a> erhält einen Zeiger auf die Post-Build-Konfiguration <code>BswM_ConfigType</code> <a class="spec-record-ref" data-req="SWS_BswM_00213" href="../../spec/record.html?id=SWS_BswM_00213">[SWS_BswM_00213]</a>. Vorausgesetzt werden nur OS und SchM <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_8_3_16_BswM_Init.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_8_3_16_BswM_Init">SWS BswM S. 69</a>. <h4>Zusammenspiel mit dem EcuM: ECU Mode Handling und Wakeup-Quellen</h4>
<p>Beim ECU Mode Handling arbitriert der EcuM die RUN- und POST_RUN-Anforderungen der SW-Cs. Eine eigene Zustandsmaschine besitzt er nicht; nur der BswM entscheidet, wann ein Übergang erfolgt <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWM_SECTION_7_10_EcuM_Mode_Handling.html" data-snip="SNIP_CLASSIC_BSWM_SECTION_7_10_EcuM_Mode_Handling">SWS EcuM S. 99</a>. Der Ablauf <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_ECU_Mode_Handling.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_ECU_Mode_Handling">Mode-Mgmt-Guide S. 34</a>:</p>
<ol>
<li>Der EcuM meldet das Ergebnis des RUN Request Protocol über <code>BswM_EcuM_RequestedState</code> <a class="spec-record-ref" data-req="SWS_BswM_91004" href="../../spec/record.html?id=SWS_BswM_91004">[SWS_BswM_91004]</a>.</li>
<li>Der BswM setzt den Zustand per <code>EcuM_SetState</code>.</li>
<li>Der EcuM meldet den entsprechenden Modus an die RTE.</li>
<li>Nach der Rückmeldung der RTE ruft der EcuM <code>BswM_EcuM_CurrentState</code> auf <a class="spec-record-ref" data-req="SWS_BswM_91003" href="../../spec/record.html?id=SWS_BswM_91003">[SWS_BswM_91003]</a>.</li>
</ol>
<p>Die Zustände sind <code>ECUM_STATE_STARTUP</code>, <code>ECUM_STATE_APP_RUN</code>, <code>ECUM_STATE_APP_POST_RUN</code>, <code>ECUM_STATE_SHUTDOWN</code> und <code>ECUM_STATE_SLEEP</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_ECU_Mode_Handling.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_ECU_Mode_Handling">Mode-Mgmt-Guide S. 34</a>. Diese Kopplung erlaubt es, SW-Cs wiederzuverwenden, die für den EcuM mit fester Zustandsmaschine entworfen wurden. Eine Kompatibilitäts-SW-C ist dafür nicht nötig <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-f372e62ffe0460b6.html" data-snip="FIG-f372e62ffe0460b6">Mode-Mgmt-Guide S. 61</a>.</p>

<h4>Kommunikationssteuerung: Busse, Partial Networks, Diagnose und Dienste</h4>
<p>Ein typischer Anwendungsfall ist die Freigabe von I-PDU-Gruppen. Im Leitfaden aktiviert eine Regel auf einer CanSM-Anzeige die I-PDU-Gruppen eines CAN-Kanals <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_3_Configuration_of_the_BswM_behavior">Mode-Mgmt-Guide S. 32</a>. Die CanSM meldet dafür die Zustände <code>CANSM_BSWM_NO_COMMUNICATION</code>, <code>CANSM_BSWM_SILENT_COMMUNICATION</code>, <code>CANSM_BSWM_FULL_COMMUNICATION</code> und <code>CANSM_BSWM_BUS_OFF</code> <a class="spec-record-ref" data-req="SWS_BswM_00049" href="../../spec/record.html?id=SWS_BswM_00049">[SWS_BswM_00049]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_2_1_ModeDeclarationGroups_de_ned_by_the_standardized_interface_of_the.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_2_2_1_ModeDeclarationGroups_de_ned_by_the_standardized_interface_of_the">Mode-Mgmt-Guide S. 22</a>. Den Zustand FULL_COMMUNICATION meldet sie zum Beispiel beim Effekt <code>E_TX_ON</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_COMM_SECTION_7_2_23_13_Effect_E_TX_ON.html" data-snip="SNIP_CLASSIC_COMM_SECTION_7_2_23_13_Effect_E_TX_ON">SWS CanSM S. 65</a>.</p>
<p>Für Partial Networks meldet ComM jeden Zustandswechsel eines PNC über <code>BswM_ComM_CurrentPNCMode</code> <a class="spec-record-ref" data-req="SWS_BswM_00148" href="../../spec/record.html?id=SWS_BswM_00148">[SWS_BswM_00148]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_COMM_SECTION_7_1_3_ComM_PNC_state_machine.html" data-snip="SNIP_CLASSIC_COMM_SECTION_7_1_3_ComM_PNC_state_machine">SWS ComM S. 35</a>. Damit schaltet der BswM Ethernet-Switch-Port-Gruppen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_4_6_Ethernet_switch_port_group_switching.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_4_6_Ethernet_switch_port_group_switching">Mode-Mgmt-Guide S. 49</a>:</p>
<ul>
<li>Er kennt die Zuordnung von PNC zu <code>EthIfSwitchPortGroup</code>.</li>
<li>Er ruft <code>EthIf_SwitchPortGroupRequestMode</code> mit <code>ETH_MODE_ACTIVE</code> oder <code>ETH_MODE_DOWN</code> auf.</li>
<li>Den resultierenden Link-Zustand der Gruppe meldet EthIf über <code>BswM_EthIf_PortGroupLinkStateChg</code> zurück <a class="spec-record-ref" data-req="SWS_BswM_91001" href="../../spec/record.html?id=SWS_BswM_91001">[SWS_BswM_91001]</a>, <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-273bba1fa7b57b61.html" data-snip="FIG-273bba1fa7b57b61">SWS EthIf S. 92</a>.</li>
</ul>
