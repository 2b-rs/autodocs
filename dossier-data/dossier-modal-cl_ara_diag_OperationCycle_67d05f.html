<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht das Überwachen von Diagnose-Betriebszyklen sowie das Auslösen eines Zyklusneustarts über modellierte Ports.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::OperationCycle</code> stellt der Anwendung Funktionen zur Steuerung und Überwachung von Diagnose-Betriebszyklen bereit <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>. Instanzen werden über einen <code>ara::core::InstanceSpecifier</code> an einen modellierten Port gebunden, sind weder kopier- noch verschiebbar und dürfen pro Bezeichner nur einfach im Prozess existieren. Über <code>SetNotifier</code> kann eine Benachrichtigung für Zyklusänderungen hinterlegt und mittels <code>RestartOperationCycle</code> ein Neustart des Betriebszyklus ausgelöst werden <a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>. Mit Ausnahme des threadsicheren Konstruktors sind alle Methoden sowie der Destruktor nicht threadsicher und erfordern bei parallelem Zugriff anwendungsseitige Synchronisation.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::OperationCycle</code> realisiert das <code>DiagnosticOperationCycleInterface</code> innerhalb der AUTOSAR-Adaptive-Diagnose und stellt Funktionen zur Handhabung und Steuerung von Betriebszyklen bereit. Sie dient als Schnittstelle zwischen der adaptiven Anwendung und dem Diagnose-Management, um Zustände von Betriebszyklen zu überwachen oder gezielt zurückzusetzen.</p>
<p>Die Anbindung an das Gesamtsystem erfolgt über einen <code>ara::core::InstanceSpecifier</code>, welcher beim Konstruktoraufruf übergeben wird <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>. Dieser Bezeichner referenziert einen im Modell definierten <code>PortPrototype</code>. Das Modell schreibt hierbei eine eindeutige Zuordnung vor: Ein durch ein <code>DiagnosticOperationCyclePortMapping</code> referenzierter <code>PortPrototype</code> muss durch das <code>DiagnosticOperationCycleInterface</code> typisiert sein <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>. Neben der Steuerung interagiert die Klasse über eine Callback-Schnittstelle vom Typ <code>ara::diag::OperationCycle::OperationCycleSetNotifier</code> (definiert als <code>std::function&lt;void(void)&gt;</code>), über die Benachrichtigungen bei einer Änderung des Betriebszyklus an die Anwendung übermittelt werden <a class="spec-record-ref" data-req="SWS_DM_02078" href="../spec/record.html?id=SWS_DM_02078">[SWS_DM_02078]</a>, <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung von <code>ara::diag::OperationCycle</code> erfolgt explizit durch Angabe der Port-Instanzspezifikation über den Konstruktor <code>OperationCycle(const ara::core::InstanceSpecifier &amp;specifier)</code> <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>. Der Konstruktor ist als ausnahmesicher (exception safe) und threadsicher (thread-safe) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</p>
<p>Hinsichtlich der Besitz- und Kopiersemantik ist die Klasse als striktes Einzelobjekt modelliert, das eine feste 1:1-Bindung an den modellierten Port darstellt. Kopieren und Verschieben sind vollständig unterbunden:</p>
<ul>
<li>Der Kopierkonstruktor ist gelöscht (<code>delete</code>), um Vervielfältigungen auszuschließen <a class="spec-record-ref" data-req="SWS_DM_01598" href="../spec/record.html?id=SWS_DM_01598">[SWS_DM_01598]</a>.</li>
<li>Der Move-Konstruktor ist gelöscht (<code>delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01599" href="../spec/record.html?id=SWS_DM_01599">[SWS_DM_01599]</a>.</li>
<li>Der Kopierzuweisungsoperator ist gelöscht (<code>delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01596" href="../spec/record.html?id=SWS_DM_01596">[SWS_DM_01596]</a>.</li>
<li>Der Move-Zuweisungsoperator ist gelöscht (<code>delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01597" href="../spec/record.html?id=SWS_DM_01597">[SWS_DM_01597]</a>.</li>
</ul>
<p>Zusätzlich untersagt das Framework die Mehrfachbelegung: Ein <code>InstanceSpecifier</code> darf innerhalb desselben Prozesses nicht wiederholt für eine Instanziierung verwendet werden <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>. Die Freigabe erfolgt im Destruktor <code>~OperationCycle()</code> <a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>. Im Unterschied zum Konstruktor ist der Destruktor nicht threadsicher (not thread-safe), wenngleich er als ausnahmesicher deklariert ist <a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>. Auch die weiteren Methoden der Klasse sowie der Callback-Typ sind nicht threadsicher <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>, <a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>, <a class="spec-record-ref" data-req="SWS_DM_02078" href="../spec/record.html?id=SWS_DM_02078">[SWS_DM_02078]</a>, sodass parallele Zugriffe auf dieselbe Instanz anwendungsseitig synchronisiert werden müssen.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad umfasst die Instanziierung, die optionale Registrierung eines Handlers für Zyklusänderungen, das wiederholte Triggern des Zyklusneustarts sowie die Freigabe:</p>
<ol>
<li><strong>Instanziierung:</strong> Die Anwendung erzeugt das Objekt <code>OperationCycle</code> unter Übergabe des entsprechenden <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</li>
<li><strong>Notifier registrieren:</strong> Über die Methode <code>SetNotifier</code> hinterlegt die Anwendung eine Callback-Funktion vom Typ <code>OperationCycleSetNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>, <a class="spec-record-ref" data-req="SWS_DM_02078" href="../spec/record.html?id=SWS_DM_02078">[SWS_DM_02078]</a>. Diese Funktion wird aufgerufen, wenn sich der Betriebszyklus ändert. Ein aufeinanderfolgender Aufruf von <code>SetNotifier</code> überschreibt den zuvor registrierten Notifier vollständig <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>.</li>
<li><strong>Betriebszyklus neustarten:</strong> Mittels <code>RestartOperationCycle()</code> löst die Anwendung den Neustart des Betriebszyklus aus <a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>. Das Diagnose-Management aktualisiert den Zyklus und benachrichtigt bei Statuswechseln den hinterlegten Callback <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>. Die Benachrichtigung dürfte hierbei asynchron im Kontext des Diagnose-Managements erfolgen.</li>
<li><strong>Zerstörung:</strong> Beim Herunterfahren der Softwarekomponente wird das Objekt über den Destruktor zerstört <a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Fehler bei der Initialisierung werden durch das Framework als Verletzungen (Violations) signalisiert, da der Konstruktor als <code>noexcept</code> deklariert ist <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>:</p>
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: Der <code>InstanceSpecifier</code> lässt sich im Kontext des Executables nicht auflösen oder verweist auf ein Element, das kein <code>PortPrototype</code> ist <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</li>
<li><code>PortInterfaceMappingViolation</code>: Der durch <code>DiagnosticOperationCyclePortMapping</code> referenzierte <code>PortPrototype</code> ist nicht durch ein <code>DiagnosticOperationCycleInterface</code> typisiert <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</li>
<li><code>ProcessMappingViolation</code>: Eine passende Instanzreferenz existiert zwar, es wurde jedoch kein passender modellierter Prozess für den Laufzeitprozess gefunden <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: Der Konstruktor wurde mit einem <code>InstanceSpecifier</code> aufgerufen, der innerhalb des aktuellen Prozesses bereits verwendet wird <a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>.</li>
</ul>
<p>Im regulären Betrieb geben die Methoden <code>SetNotifier</code> und <code>RestartOperationCycle</code> ein <code>ara::core::Result&lt;void&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>, <a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>. Die Verwendung des <code>Result</code>-Typs dürfte primär der einheitlichen Schnittstellengestaltung dienen und Raum für implementierungsspezifische Fehlerzustände bieten.</p>
