<h4>Context</h4>
<p>The class <code>ara::diag::OperationCycle</code> represents the C++ interface of the <code>DiagnosticOperationCycleInterface</code> according to <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=81">AUTOSAR_AP_SWS_Diagnostics p. 81</a>. It provides application software with functional mechanisms for controlling and monitoring operation cycles. In diagnostics, operation cycles are authoritative reference periods and state windows on the basis of which fault checks, debouncings, and qualifications of diagnostic trouble codes (DTCs) are evaluated.</p>
<p>Essentially three entities are involved in the interaction:</p>
<ul>
<li><strong>Application software:</strong> Instantiates the class object based on a port identifier, registers callback functions for monitoring cycle changes if required, and triggers the restart of the cycle when relevant operating conditions occur.</li>
<li><strong>ara::diag::OperationCycle:</strong> Acts as a local proxy in the application's process, binds the configured port, and forwards calls to the platform subsystem.</li>
<li><strong>Diagnostic Management:</strong> Manages the overall state of the operation cycle, coordinates dependent diagnostic monitors, and reports status transitions back to registered instances.</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance is created via the explicit constructor <code>OperationCycle(const ara::core::InstanceSpecifier &amp;specifier)</code> (<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>). The constructor is declared as <code>noexcept</code> and is considered exception safe.</p>
<p>With regard to ownership and semantics, the class is designed as a strictly bound single instance:</p>
<ul>
<li>The copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01598" href="../spec/record.html?id=SWS_DM_01598">[SWS_DM_01598]</a>) and the assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01596" href="../spec/record.html?id=SWS_DM_01596">[SWS_DM_01596]</a>) are explicitly deleted (<code>=delete</code>), thereby precluding duplication of the interface binding.</li>
<li>Likewise, the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01599" href="../spec/record.html?id=SWS_DM_01599">[SWS_DM_01599]</a>) and the move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01597" href="../spec/record.html?id=SWS_DM_01597">[SWS_DM_01597]</a>) are deleted (<code>=delete</code>). Thus, an existing instance cannot be moved to other scopes.</li>
</ul>
<p>The instance is released via the virtual destructor <code>~OperationCycle()</code> (<a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>), which is likewise implemented as <code>noexcept</code>.</p>
<p>Different guarantees apply to concurrency: While instantiation via the constructor is specified as thread-safe (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>), the destructor (<a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>) as well as all regular method calls are designated as not thread-safe (<code>not thread-safe</code>). If multiple application threads access the same <code>OperationCycle</code> object, access must be synchronized by the caller.</p>

<h4>Usage Path</h4>
<p>The regular workflow for monitoring and controlling an operation cycle is divided into the following steps:</p>
<ol>
<li><strong>Instantiation:</strong> The application creates the object by passing the <code>ara::core::InstanceSpecifier</code>, which references the corresponding <code>PortPrototype</code> in the manifest (<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>).</li>
<li><strong>Notification registration:</strong> A callback of type <code>OperationCycleSetNotifier</code> (defined as <code>std::function&lt;void(void)&gt;</code>, <a class="spec-record-ref" data-req="SWS_DM_02078" href="../spec/record.html?id=SWS_DM_02078">[SWS_DM_02078]</a>) is registered via <code>SetNotifier()</code> (<a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>). A subsequent call to <code>SetNotifier()</code> completely overwrites a previously configured notifier.</li>
<li><strong>Request restart:</strong> As soon as the operation cycle is to be restarted (e.g., after a terminal change or end of driving cycle), the application calls <code>RestartOperationCycle()</code> (<a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>).</li>
<li><strong>Event feedback:</strong> Interpretation: The execution of the registered notifier upon a status change of the operation cycle is likely performed asynchronously by the diagnostic subsystem, as no synchronous context is specified. As soon as the cycle status has been adapted in the system, the configured callback function is called.</li>
</ol>

<h4>Error Scenarios</h4>
<p>During instantiation, configuration and model conflicts can occur that are reported via specific runtime violations (<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>):</p>
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The specified <code>InstanceSpecifier</code> cannot be resolved in the model context of the executable or refers to a model element that is not an <code>PortPrototype</code>.</li>
<li><code>PortInterfaceMappingViolation</code>: The <code>PortPrototype</code> referenced by an <code>DiagnosticOperationCyclePortMapping</code> is not typed as <code>DiagnosticOperationCycleInterface</code> in the design model.</li>
<li><code>ProcessMappingViolation</code>: Although a matching instance reference (<code>InstanceRef</code>) exists, the mapping to a modeled process (<code>Process</code>) that corresponds to the running process is missing.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The constructor was called with an <code>InstanceSpecifier</code> that is already used by an existing instance within the same process.</li>
</ul>
<p>For the operational calls <code>RestartOperationCycle()</code> (<a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>) and <code>SetNotifier()</code> (<a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>), the API returns a <code>ara::core::Result&lt;void&gt;</code> in each case. The interface specification specifies no standardized error codes for either function. Both methods are declared as <code>noexcept</code>.</p>
