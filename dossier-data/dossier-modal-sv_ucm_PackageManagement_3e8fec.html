<h4>Role and system context of the service interface</h4>
<p>The service interface <code>PackageManagement</code> forms the core functional interface of Update and Configuration Management (UCM) on the AUTOSAR Adaptive Platform. The UCM instance acts as the service provider, whose unique module identifier can be queried via the method <code>GetId</code> (<a class="spec-record-ref" data-req="SWS_UCM_00343" href="../spec/record.html?id=SWS_UCM_00343">[SWS_UCM_00343]</a>). Interpretation: A higher-level control entity such as State Management, an OTA client, or a diagnostic application typically acts as the service consumer, controlling the installation, updating, and uninstallation of software clusters and communicating with the UCM via standardized <code>ara::com</code> proxy and skeleton structures.</p>
<p>Via the service field <code>CurrentStatus</code>, the interface provides the current overall state of the UCM both for synchronous state queries and via asynchronous value change notifications (<a class="spec-record-ref" data-req="SWS_UCM_00361" href="../spec/record.html?id=SWS_UCM_00361">[SWS_UCM_00361]</a>). The method <code>GetProgress</code>, which provides the current execution progress (<a class="spec-record-ref" data-req="SWS_UCM_00360" href="../spec/record.html?id=SWS_UCM_00360">[SWS_UCM_00360]</a>), serves for fine-grained monitoring of active operations in the package management state machine.</p>

<h4>Methods, events, and fields</h4>
<p>All methods of the service interface <code>PackageManagement</code> are designed with synchronous or asynchronous feedback (no fire-and-forget methods) and provide results via return values and error types in the communication model of <code>ara::com</code> (<a class="spec-record-ref" data-req="SWS_UCM_00345" href="../spec/record.html?id=SWS_UCM_00345">[SWS_UCM_00345]</a>). Software packages can be provided either via a block-based transfer using <code>TransferStart</code> (<a class="spec-record-ref" data-req="SWS_UCM_00345" href="../spec/record.html?id=SWS_UCM_00345">[SWS_UCM_00345]</a>), <code>TransferData</code> (<a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>), and <code>TransferExit</code> (<a class="spec-record-ref" data-req="SWS_UCM_00347" href="../spec/record.html?id=SWS_UCM_00347">[SWS_UCM_00347]</a>), or by registering a package already available in the file system or as a download path via <code>RegisterSoftwarePackage</code> (<a class="spec-record-ref" data-req="SWS_UCM_00344" href="../spec/record.html?id=SWS_UCM_00344">[SWS_UCM_00344]</a>). An ongoing or completed transfer can be discarded via <code>DeleteTransfer</code> if necessary (<a class="spec-record-ref" data-req="SWS_UCM_00348" href="../spec/record.html?id=SWS_UCM_00348">[SWS_UCM_00348]</a>).</p>
<p>Further processing and activation of provided software packages take place via the methods <code>ProcessSwPackage</code> (<a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>), <code>Activate</code> (<a class="spec-record-ref" data-req="SWS_UCM_00352" href="../spec/record.html?id=SWS_UCM_00352">[SWS_UCM_00352]</a>), and <code>Finish</code> (<a class="spec-record-ref" data-req="SWS_UCM_00354" href="../spec/record.html?id=SWS_UCM_00354">[SWS_UCM_00354]</a>). Long-running background operations can be suspended using <code>Suspend</code> (<a class="spec-record-ref" data-req="SWS_UCM_00397" href="../spec/record.html?id=SWS_UCM_00397">[SWS_UCM_00397]</a>) and resumed via <code>Resume</code> (<a class="spec-record-ref" data-req="SWS_UCM_00398" href="../spec/record.html?id=SWS_UCM_00398">[SWS_UCM_00398]</a>). If necessary, ongoing package processing can be canceled via <code>Cancel</code> (<a class="spec-record-ref" data-req="SWS_UCM_00351" href="../spec/record.html?id=SWS_UCM_00351">[SWS_UCM_00351]</a>).</p>
<p>For system inspection, the service provides a series of query methods: <code>GetSwPackages</code> lists the software packages available in the UCM (<a class="spec-record-ref" data-req="SWS_UCM_00359" href="../spec/record.html?id=SWS_UCM_00359">[SWS_UCM_00359]</a>), <code>GetSwClusterInfo</code> returns the installed clusters in state <code>kPresent</code> (<a class="spec-record-ref" data-req="SWS_UCM_00357" href="../spec/record.html?id=SWS_UCM_00357">[SWS_UCM_00357]</a>), <code>GetSwClusterChangeInfo</code> reports pending changes for clusters in states <code>kAdded</code>, <code>kUpdating</code>, or <code>kRemoved</code> (<a class="spec-record-ref" data-req="SWS_UCM_00356" href="../spec/record.html?id=SWS_UCM_00356">[SWS_UCM_00356]</a>), and <code>GetSwClusterManifestInfo</code> returns manifest details for a specific cluster (<a class="spec-record-ref" data-req="SWS_UCM_00358" href="../spec/record.html?id=SWS_UCM_00358">[SWS_UCM_00358]</a>). Historical actions of the UCM can be read out based on a time range via <code>GetHistory</code> (<a class="spec-record-ref" data-req="SWS_UCM_00355" href="../spec/record.html?id=SWS_UCM_00355">[SWS_UCM_00355]</a>). In addition, field <code>CurrentStatus</code> continuously provides status changes via getter and notifier (<a class="spec-record-ref" data-req="SWS_UCM_00361" href="../spec/record.html?id=SWS_UCM_00361">[SWS_UCM_00361]</a>).</p>

<h4>Lifecycle, session sequences, and state dependencies</h4>
<p>A standard update cycle follows a strictly sequential sequence: First, the consumer initiates data transfer using <code>TransferStart</code> and receives a transfer ID as well as the permitted block size (<a class="spec-record-ref" data-req="SWS_UCM_00345" href="../spec/record.html?id=SWS_UCM_00345">[SWS_UCM_00345]</a>). Then, payload data is transmitted sequentially via <code>TransferData</code> (<a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>) and the transmission is concluded with validation by <code>TransferExit</code> (<a class="spec-record-ref" data-req="SWS_UCM_00347" href="../spec/record.html?id=SWS_UCM_00347">[SWS_UCM_00347]</a>). After successful transfer, <code>ProcessSwPackage</code> triggers the extraction and verification of manifests (<a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>). The actual activation of the extracted software clusters is triggered with <code>Activate</code> (<a class="spec-record-ref" data-req="SWS_UCM_00352" href="../spec/record.html?id=SWS_UCM_00352">[SWS_UCM_00352]</a>) before <code>Finish</code> cleans up temporary source data and completes the cycle (<a class="spec-record-ref" data-req="SWS_UCM_00354" href="../spec/record.html?id=SWS_UCM_00354">[SWS_UCM_00354]</a>).</p>

<p>If reverting the processed packages is necessary prior to activation, the method <code>RevertProcessedSwPackages</code> allows rolling back the changes made (<a class="spec-record-ref" data-req="SWS_UCM_00350" href="../spec/record.html?id=SWS_UCM_00350">[SWS_UCM_00350]</a>). If a critical error occurs after activation, <code>Rollback</code> allows returning the system to the state prior to package processing (<a class="spec-record-ref" data-req="SWS_UCM_00353" href="../spec/record.html?id=SWS_UCM_00353">[SWS_UCM_00353]</a>). Long-running operations can be paused at any time during active states via <code>Suspend</code> and resumed via <code>Resume</code> (<a class="spec-record-ref" data-req="SWS_UCM_00397" href="../spec/record.html?id=SWS_UCM_00397">[SWS_UCM_00397]</a>, <a class="spec-record-ref" data-req="SWS_UCM_00398" href="../spec/record.html?id=SWS_UCM_00398">[SWS_UCM_00398]</a>).</p>

<h4>Error handling and Application Errors</h4>
<p>Method calls that do not match the current state of the UCM state machine are consistently rejected with the Application Error <code>kOperationNotPermitted</code>, including in <code>Activate</code> (<a class="spec-record-ref" data-req="SWS_UCM_00352" href="../spec/record.html?id=SWS_UCM_00352">[SWS_UCM_00352]</a>), <code>ProcessSwPackage</code> (<a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>), <code>TransferData</code> (<a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>), and <code>Finish</code> (<a class="spec-record-ref" data-req="SWS_UCM_00354" href="../spec/record.html?id=SWS_UCM_00354">[SWS_UCM_00354]</a>). If the UCM instance is already busy with another processing task, <code>ProcessSwPackage</code> responds with <code>kServiceBusy</code> (<a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>).</p>
<p>During data transfer, integrity and format checks are performed. Invalid transfer IDs lead to <code>kTransferIdInvalid</code> (<a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>, <a class="spec-record-ref" data-req="SWS_UCM_00348" href="../spec/record.html?id=SWS_UCM_00348">[SWS_UCM_00348]</a>, <a class="spec-record-ref" data-req="SWS_UCM_00351" href="../spec/record.html?id=SWS_UCM_00351">[SWS_UCM_00351]</a>). Discrepancies in package size, block numbering, or block size result in <code>kSizeIncorrect</code>, <code>kBlockIncorrect</code>, or <code>kBlockSizeIncorrect</code>, while insufficient memory space leads to <code>kMemoryInsufficient</code> (<a class="spec-record-ref" data-req="SWS_UCM_00345" href="../spec/record.html?id=SWS_UCM_00345">[SWS_UCM_00345]</a>, <a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>). If completing the transfer fails due to missing data, <code>TransferExit</code> reports the error <code>kDataInsufficient</code> (<a class="spec-record-ref" data-req="SWS_UCM_00347" href="../spec/record.html?id=SWS_UCM_00347">[SWS_UCM_00347]</a>).</p>
<p>Package content validations are signaled via error codes such as <code>kAuthenticationFailed</code>, <code>kPackageManifestInvalid</code>, <code>kPackageInconsistent</code>, and <code>kPackageVersionIncompatible</code> (<a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a>, <a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>). Protection of the base infrastructure is ensured by rejecting attempts to remove the <code>PLATFORM_CORE</code> software cluster with <code>kSwclRemovalDenied</code> (<a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a>). Errors reported by State Management during cluster activation lead to <code>kUpdateSessionRejected</code> or <code>kVerificationFailed</code>, while incomplete dependencies are rejected with <code>kDependencyMissing</code> (<a class="spec-record-ref" data-req="SWS_UCM_00352" href="../spec/record.html?id=SWS_UCM_00352">[SWS_UCM_00352]</a>).</p>
