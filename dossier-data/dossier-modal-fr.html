<h4>Role in the FlexRay stack and system boundary</h4>
<p>The FlexRay driver (Fr) provides unified access to one or more FlexRay Communication Controllers (CC). Its only user is the FlexRay Interface (FrIf). The only exception is initialization: EcuM calls <code>Fr_Init</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules.html" data-snip="SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules">SWS FrDriver p. 15</a>. All services except <code>Fr_Init</code> and <code>Fr_GetVersionInfo</code> address the controller via <code>Fr_CtrlIdx</code>, the "Index of FlexRay CC within the context of the FlexRay Driver" (<a class="spec-record-ref" data-req="SWS_Fr_00017" href="../../spec/record.html?id=SWS_Fr_00017">[SWS_Fr_00017]</a>, <a class="spec-record-ref" data-req="SWS_Fr_00032" href="../../spec/record.html?id=SWS_Fr_00032">[SWS_Fr_00032]</a>, <a class="spec-record-ref" data-req="SWS_Fr_00070" href="../../spec/record.html?id=SWS_Fr_00070">[SWS_Fr_00070]</a>).</p>
<p>Downwards, Fr accesses the CC hardware. Outwards, the module mandatorily requires <code>Dem_SetEventStatus</code> and <code>Det_ReportRuntimeError</code> <a class="spec-record-ref" data-req="SWS_Fr_00390" href="../../spec/record.html?id=SWS_Fr_00390">[SWS_Fr_00390]</a>. Optionally, it uses <code>Det_ReportError</code> as well as <code>SchM_Enter_Fr</code>/<code>SchM_Exit_Fr</code> <a class="spec-record-ref" data-req="SWS_Fr_00391" href="../../spec/record.html?id=SWS_Fr_00391">[SWS_Fr_00391]</a>. The CC shares some resources with other components, such as PLL or memory mapping. Fr does not configure these itself; their initialization must occur before that of Fr <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules.html" data-snip="SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules">SWS FrDriver p. 15</a>.</p>
<p>FrIf distinguishes between mandatory and optional services among the Fr services:</p>
<ul>
<li>Mandatory services include, among others, <code>Fr_ControllerInit</code>, <code>Fr_GetPOCStatus</code>, <code>Fr_ReceiveRxLPdu</code>, <code>Fr_CheckTxLPduStatus</code>, and the absolute timer services <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_8_1_Mandatory_Interfaces.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_8_1_Mandatory_Interfaces">SWS FrIf p. 95</a>.</li>
<li>Optional services include, among others, <code>Fr_AllSlots</code>, <code>Fr_CancelTxLPdu</code>, and the diagnostic services <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_8_2_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_8_2_Optional_Interfaces">SWS FrIf p. 97</a>.</li>
</ul>
<p>Many FrIf functions directly encapsulate an Fr service. Thus, <code>FrIf_GetPOCStatus</code> wraps the function <code>Fr_GetPOCStatus</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FRIF_SECTION_8_3_13_FrIf_GetPOCStatus.html" data-snip="SNIP_CLASSIC_FRIF_SECTION_8_3_13_FrIf_GetPOCStatus">SWS FrIf p. 67</a>.</p>

<h4>POC state machine: which service triggers which transition</h4>
<p>A FlexRay CC internally executes the Protocol Operation Control (POC) state machine. Its transitions are caused by hardware events and by CHI commands from the host. Only five services trigger such commands: <code>Fr_StartCommunication</code>, <code>Fr_HaltCommunication</code>, <code>Fr_AbortCommunication</code>, <code>Fr_SendWUP</code>, and <code>Fr_ControllerInit</code>. All other services must not change the POC state <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_7_4_POC_state_machine_control.html" data-snip="SNIP_CLASSIC_FR_SECTION_7_4_POC_state_machine_control">SWS FrDriver p. 23</a>. The states are mapped by <code>Fr_POCStateType</code> <a class="spec-record-ref" data-req="SWS_Fr_00505" href="../../spec/record.html?id=SWS_Fr_00505">[SWS_Fr_00505]</a>. The individual transitions:</p>
<ul>
<li><code>Fr_ControllerInit</code> transitions from any state to POC:config, configures cluster, node, and buffer parameters, and ends in POC:ready <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit">SWS FrDriver p. 41</a>.</li>
<li><code>Fr_StartCommunication</code> sends the command <code>RUN</code> and transitions to the POC:startup transitional state. Whether the CC reaches normal active or normal passive afterwards is not guaranteed <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_3_Fr_StartCommunication.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_3_Fr_StartCommunication">SWS FrDriver p. 42</a>.</li>
<li><code>Fr_SendWUP</code> leads via POC:wakeup and subsequently back to POC:ready <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_8_Fr_SendWUP.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_8_Fr_SendWUP">SWS FrDriver p. 48</a>.</li>
<li><code>Fr_HaltCommunication</code> sends <code>DEFERRED_HALT</code>; POC:halt is reached only at the end of the current cycle <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_6_Fr_HaltCommunication.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_6_Fr_HaltCommunication">SWS FrDriver p. 45</a>.</li>
<li><code>Fr_AbortCommunication</code> sends <code>FREEZE</code> and transitions immediately and from any state to POC:halt; in doing so, <code>vPOC!Freeze</code> is set <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_7_Fr_AbortCommunication.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_7_Fr_AbortCommunication">SWS FrDriver p. 47</a>.</li>
</ul>
<p>A special case is <code>Fr_SetWakeupChannel</code>. The function transitions briefly to POC:config with <code>CONFIG</code> and back to POC:ready with <code>CONFIG_COMPLETE</code> <a class="spec-record-ref" data-req="SWS_Fr_00091" href="../../spec/record.html?id=SWS_Fr_00091">[SWS_Fr_00091]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_9_Fr_SetWakeupChannel.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_9_Fr_SetWakeupChannel">SWS FrDriver p. 49</a>. It is missing from the list of state-changing services. In net terms, the CC remains in POC:ready, but the intermediate step must be observed.</p>

<h4>From Fr_Init to Communication in All Slots</h4>
<p><code>Fr_Init</code> is synchronous and non-reentrant <a class="spec-record-ref" data-req="SWS_Fr_00032" href="../../spec/record.html?id=SWS_Fr_00032">[SWS_Fr_00032]</a>. The function stores the configuration address for all subsequent calls <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_1_Fr_Init.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_1_Fr_Init">SWS FrDriver p. 39</a>. In R20-11, <code>Fr_ConfigType</code> is an implementation-specific post-build type, “derived from void” <a class="spec-record-ref" data-req="SWS_Fr_91001" href="../../spec/record.html?id=SWS_Fr_91001">[SWS_Fr_91001]</a>. Later document versions describe it as a structure <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_3_1_Fr_ConfigType.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_3_1_Fr_ConfigType">SWS FrDriver p. 34</a>. The change history locates this change in R22-11 <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_FR_SECTION_General_Overview">SWS FrDriver p. 1</a>. For R20-11, the requirement text applies.</p>
<p>Afterwards, <code>Fr_ControllerInit</code> brings each CC to POC:ready and ensures that no more transmission requests are pending <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit">SWS FrDriver p. 41</a>. For a wakeup, <code>Fr_SetWakeupChannel</code> selects the channel; only <code>FR_CHANNEL_A</code> and <code>FR_CHANNEL_B</code> are valid <a class="spec-record-ref" data-req="SWS_Fr_00091" href="../../spec/record.html?id=SWS_Fr_00091">[SWS_Fr_00091]</a>. Subsequently, <code>Fr_SendWUP</code> sends the wakeup pattern in POC:ready. This does not necessarily wake all nodes <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_8_Fr_SendWUP.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_8_Fr_SendWUP">SWS FrDriver p. 48</a>. Retries are handled by FrSM: it waits for FR_READY and evaluates <code>vPOC!WakeupStatus</code>, such as <code>FR_WAKEUP_RECEIVED_HEADER</code> or <code>FR_WAKEUP_TRANSMITTED</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FRSM_SECTION_7_3_8_Wakeup_Pattern_Transmission.html" data-snip="SNIP_CLASSIC_FRSM_SECTION_7_3_8_Wakeup_Pattern_Transmission">SWS FrSM p. 27</a>. <code>Fr_GetWakeupRxStatus</code> reports a received wakeup bit-coded per channel <a class="spec-record-ref" data-req="SWS_Fr_00587" href="../../spec/record.html?id=SWS_Fr_00587">[SWS_Fr_00587]</a>.</p>
<p>To start, <code>Fr_AllowColdstart</code> is called (permitted in POC:ready or POC:startup) and then <code>Fr_StartCommunication</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_4_Fr_AllowColdstart.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_4_Fr_AllowColdstart">SWS FrDriver p. 43</a>, <a class="spec-record-ref" data-req="SWS_Fr_00010" href="../../spec/record.html?id=SWS_Fr_00010">[SWS_Fr_00010]</a>. Both services are asynchronous. The caller is therefore expected to observe success via repeated <code>Fr_GetPOCStatus</code> (interpretation). The sequence is presumably controlled by FrSM via FrIf; its states are mapped to POC states <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FRSM_SECTION_7_3_2_States.html" data-snip="SNIP_CLASSIC_FRSM_SECTION_7_3_2_States">SWS FrSM p. 18</a>. As soon as the CC is synchronous to the global time, <code>Fr_AllSlots</code> requests the change from keyslot-only mode to all-slots mode for the next cycle <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_5_Fr_AllSlots.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_5_Fr_AllSlots">SWS FrDriver p. 44</a>. Until then, <code>SlotMode</code> indicates the value <code>FR_SLOTMODE_ALL_PENDING</code> <a class="spec-record-ref" data-req="SWS_Fr_00506" href="../../spec/record.html?id=SWS_Fr_00506">[SWS_Fr_00506]</a>.</p>

<h4>LPdu Data Path: Transmit, Confirm, Cancel, Receive</h4>
<p>All parameters for transmission and reception are located in the FrIf configuration (<code>FrIfLPdu</code>, <code>FrIfFrameTriggering</code>). FrIf merely passes the <code>Fr_LPduIdx</code> to Fr <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_7_6_Configuration_description.html" data-snip="SNIP_CLASSIC_FR_SECTION_7_6_Configuration_description">SWS FrDriver p. 25</a>. <code>Fr_TransmitTxLPdu</code> is asynchronous and receives the buffer pointer and length of the LSdu <a class="spec-record-ref" data-req="SWS_Fr_00092" href="../../spec/record.html?id=SWS_Fr_00092">[SWS_Fr_00092]</a>. Via <code>Fr_SlotAssignmentPtr</code>, the caller can query cycle, slot ID, and channel (<code>Fr_SlotAssignmentType</code>); an <code>NULL_PTR</code> dispenses with this <a class="spec-record-ref" data-req="SWS_Fr_91002" href="../../spec/record.html?id=SWS_Fr_91002">[SWS_Fr_91002]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_11_Fr_TransmitTxLPdu.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_11_Fr_TransmitTxLPdu">SWS FrDriver p. 53</a>.</p>
<p>The confirmation originates in the FrIf job list. There, the TX_CONFIRMATION operation calls <code>Fr_CheckTxLPduStatus</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_7_6_5_2_ProvideTxConfirmation.html" data-snip="SNIP_CLASSIC_FR_SECTION_7_6_5_2_ProvideTxConfirmation">SWS FrIf p. 38</a>. The return status is <code>FR_TRANSMITTED</code>, <code>FR_TRANSMITTED_CONFLICT</code>, or <code>FR_NOT_TRANSMITTED</code> <a class="spec-record-ref" data-req="SWS_Fr_00511" href="../../spec/record.html?id=SWS_Fr_00511">[SWS_Fr_00511]</a>. Only upon <code>FR_TRANSMITTED</code> does FrIf confirm the contained PDUs <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-981e0249d7cdb64c.html" data-snip="FIG-981e0249d7cdb64c">SWS FrIf p. 112</a>. <code>Fr_CancelTxLPdu</code> cancels a pending transmission in the hardware buffer and returns <code>E_OK</code>. If nothing is pending, the function returns <code>E_NOT_OK</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_12_Fr_CancelTxLPdu.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_12_Fr_CancelTxLPdu">SWS FrDriver p. 54</a>.</p>

</ul>

<h4>Global Time, Absolute Timers, and Cluster Diagnosis</h4>
<p><code>Fr_GetGlobalTime</code> returns cycle and macrotick. The function may only be called when the CC is synchronous, and is also permitted within an exclusive area <a class="spec-record-ref" data-req="SWS_Fr_00042" href="../../spec/record.html?id=SWS_Fr_00042">[SWS_Fr_00042]</a>. Time values must be consistent and valid <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_18_Fr_GetGlobalTime.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_18_Fr_GetGlobalTime">SWS FrDriver p. 67</a>. For data consistency, Fr uses the mechanisms of the BSW scheduler <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules.html" data-snip="SNIP_CLASSIC_FR_SECTION_5_Dependencies_to_other_modules">SWS FrDriver p. 15</a>.</p>
<p>Absolute timers are addressed per CC via <code>Fr_AbsTimerIdx</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_10_2_4_FrAbsoluteTimer.html" data-snip="SNIP_CLASSIC_DEM_SECTION_10_2_4_FrAbsoluteTimer">SWS FrDriver p. 104</a>. Overview of the services:</p>
<ul>
<li><code>Fr_SetAbsoluteTimer</code> programs cycle and offset in macroticks; the CC must be synchronous at this time <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_25_Fr_SetAbsoluteTimer.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_25_Fr_SetAbsoluteTimer">SWS FrDriver p. 79</a>.</li>
<li><code>Fr_EnableAbsoluteTimerIRQ</code> and <code>Fr_DisableAbsoluteTimerIRQ</code> switch the interrupt line (<a class="spec-record-ref" data-req="SWS_Fr_00034" href="../../spec/record.html?id=SWS_Fr_00034">[SWS_Fr_00034]</a>, <a class="spec-record-ref" data-req="SWS_Fr_00035" href="../../spec/record.html?id=SWS_Fr_00035">[SWS_Fr_00035]</a>).</li>
<li><code>Fr_GetAbsoluteTimerIRQStatus</code> reports <code>TRUE</code> when an interrupt is pending <a class="spec-record-ref" data-req="SWS_Fr_00108" href="../../spec/record.html?id=SWS_Fr_00108">[SWS_Fr_00108]</a>.</li>
<li><code>Fr_AckAbsoluteTimerIRQ</code> resets the interrupt condition <a class="spec-record-ref" data-req="SWS_Fr_00036" href="../../spec/record.html?id=SWS_Fr_00036">[SWS_Fr_00036]</a>.</li>
<li><code>Fr_CancelAbsoluteTimer</code> stops the timer <a class="spec-record-ref" data-req="SWS_Fr_00095" href="../../spec/record.html?id=SWS_Fr_00095">[SWS_Fr_00095]</a>.</li>
</ul>

<h4>Behavior in the event of an error</h4>
<p>A uniform convention applies to all services: <code>E_OK</code> signifies success with validly written output parameters. In the case of <code>E_NOT_OK</code>, the output parameters remain unchanged <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_Function_definitions.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_Function_definitions">SWS FrDriver p. 36</a>.</p>
<p><strong>Hardware error:</strong> If a service detects an error in the CC hardware, it calls <code>Dem_SetEventStatus(FR_E_CTRL_TESTRESULT, DEM_EVENT_STATUS_FAILED)</code> and returns <code>E_NOT_OK</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_4_Fr_AllowColdstart.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_4_Fr_AllowColdstart">SWS FrDriver p. 43</a>. A PASS is reported when <code>Fr_ControllerInit</code> has successfully verified the registers <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_7_7_5_Extended_Production_Errors.html" data-snip="SNIP_CLASSIC_FR_SECTION_7_7_5_Extended_Production_Errors">SWS FrDriver p. 26</a>. Protocol errors on the network are explicitly not covered by this event <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_det_AUTOSAR_SWS_Flex_P28_211.html" data-snip="SNIP_det_AUTOSAR_SWS_Flex_P28_211">SWS FrDriver p. 28</a>.</p>
<p><strong>Protocol errors:</strong> For this purpose, <code>FR_E_LPDU_SLOTSTATUS</code> exists per LPdu. It reports syntax, content, and boundary violations in the slot status <a class="spec-record-ref" data-req="SWS_Fr_00600" href="../../spec/record.html?id=SWS_Fr_00600">[SWS_Fr_00600]</a>.</p>
<p><strong>Development errors:</strong> When error detection is activated, the codes <code>FR_E_INV_CTRL_IDX</code>, <code>FR_E_INV_TIMER_IDX</code>, <code>FR_E_INV_CYCLE</code>, <code>FR_E_INV_LPDU_IDX</code>, <code>FR_E_PARAM_POINTER</code>, and <code>FR_E_INIT_FAILED</code> apply, among others <a class="spec-record-ref" data-req="SWS_Fr_91003" href="../../spec/record.html?id=SWS_Fr_91003">[SWS_Fr_91003]</a>. For calls prior to initialization, <code>FR_E_INIT_FAILED</code> is likely reported (“Fr module was not initialized”). This is an interpretation because the relevant requirement text is truncated in the payload <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_10_Fr_GetPOCStatus.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_10_Fr_GetPOCStatus">SWS FrDriver p. 51</a>. Two specific cases are documented:</p>
<ul>
<li><code>Fr_GetSyncFrameList</code> reports error <code>FR_E_INV_FRAMELIST_SIZE</code> when <code>Fr_ListSize</code> &gt; 15 <a class="spec-record-ref" data-req="SWS_Fr_00667" href="../../spec/record.html?id=SWS_Fr_00667">[SWS_Fr_00667]</a>.</li>
<li><code>Fr_GetVersionInfo</code> reports error <code>FR_E_PARAM_POINTER</code> upon <code>NULL_PTR</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_31_Fr_GetVersionInfo.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_31_Fr_GetVersionInfo">SWS FrDriver p. 86</a>.</li>
</ul>
<p><strong>Runtime error:</strong> As the only runtime error, <code>FR_E_INV_POCSTATE</code> is defined (0x09; the CC is not in the expected POC state) <a class="spec-record-ref" data-req="SWS_Fr_91004" href="../../spec/record.html?id=SWS_Fr_91004">[SWS_Fr_91004]</a>. For such notifications, <code>Det_ReportRuntimeError</code> is designated as a mandatory interface <a class="spec-record-ref" data-req="SWS_Fr_00390" href="../../spec/record.html?id=SWS_Fr_00390">[SWS_Fr_00390]</a>. The chapter on error classification was revised in R20-11 <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_FR_SECTION_General_Overview">SWS FrDriver p. 1</a>.</p>
<p><strong>Recovery:</strong> <code>Fr_AbortCommunication</code> stops the CC immediately. <code>Fr_ControllerInit</code> leads from any state, including POC:halt, via POC:config back to POC:ready <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit.html" data-snip="SNIP_CLASSIC_FR_SECTION_8_4_2_Fr_ControllerInit">SWS FrDriver p. 41</a>. If a CC enters HALT due to an error during wakeup, FrSM aborts the wakeup transmission <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FRSM_SECTION_7_3_8_Wakeup_Pattern_Transmission.html" data-snip="SNIP_CLASSIC_FRSM_SECTION_7_3_8_Wakeup_Pattern_Transmission">SWS FrSM p. 27</a>.</p>
