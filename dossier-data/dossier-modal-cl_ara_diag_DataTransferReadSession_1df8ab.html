<h4>Context</h4>
<p>
The class <code>ara::diag::DataTransferReadSession</code> encapsulates all read variants of the data transfer within the diagnostic module of the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_DM_01548" href="../spec/record.html?id=SWS_DM_01548">[SWS_DM_01548]</a>). In diagnostic sequences where data is transferred from the vehicle to the diagnostic tester—for example, in file-based transfers such as reading files (<a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a>) or reading file directories (<a class="spec-record-ref" data-req="SWS_DM_01315" href="../spec/record.html?id=SWS_DM_01315">[SWS_DM_01315]</a>)—the session object acts as a link between the diagnostic server instance and the application-specific transfer handlers.
</p>
<p>
The functional interaction involves at least three components:
</p>
<ul>
<li><strong>Diagnostic Server instance:</strong> Receives incoming diagnostic requests (UDS services) and coordinates the transfer steps (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>, <a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>).</li>
<li><strong>DataTransferReadSession:</strong> Represents the active read session and links the registered handlers via specialized template constructors (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=185">AUTOSAR_AP_SWS_Diagnostics §7.7 “Realization of TransferData and RequestTransferExit”</a>).</li>
<li><strong>Handler classes:</strong> Provide the domain-specific read and completion logic (<code>Read</code> and <code>Exit</code> methods) that are called by the diagnostic server in the context of the session (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>, <a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>
The lifecycle and ownership concept of <code>ara::diag::DataTransferReadSession</code> enforces the unique binding to a single, well-defined transfer session (<a class="spec-record-ref" data-req="SWS_DM_01548" href="../spec/record.html?id=SWS_DM_01548">[SWS_DM_01548]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=378">AUTOSAR_AP_SWS_Diagnostics §8.10.4 “Class: DataTransferReadSession”</a>):
</p>
<ul>
<li><strong>Creation:</strong> The parameterless default constructor is deleted (<code>delete</code> according to <a class="spec-record-ref" data-req="SWS_DM_01549" href="../spec/record.html?id=SWS_DM_01549">[SWS_DM_01549]</a>) to exclude uninitialized instances without handler binding. Creation takes place instead via template constructors that register vendor-specific handlers (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=185">AUTOSAR_AP_SWS_Diagnostics §7.7 “Realization of TransferData and RequestTransferExit”</a>).</li>
<li><strong>Exclusivity and non-copyability:</strong> To prevent multiple ownership and concurrency conflicts on the same transfer, both the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01553" href="../spec/record.html?id=SWS_DM_01553">[SWS_DM_01553]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01554" href="../spec/record.html?id=SWS_DM_01554">[SWS_DM_01554]</a>) are deleted. An instance of <code>ara::diag::DataTransferReadSession</code> is by definition a non-copyable single instance.</li>
<li><strong>Move semantics:</strong> The class provides a move constructor (<a class="spec-record-ref" data-req="SWS_DM_01551" href="../spec/record.html?id=SWS_DM_01551">[SWS_DM_01551]</a>) and a move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01552" href="../spec/record.html?id=SWS_DM_01552">[SWS_DM_01552]</a>). Both are implemented as <code>default</code> and explicitly declared as <code>noexcept</code>, which enables an efficient and exception-safe transfer of ownership.</li>
<li><strong>Destruction:</strong> The destructor is specified as <code>noexcept=default</code> (<a class="spec-record-ref" data-req="SWS_DM_01550" href="../spec/record.html?id=SWS_DM_01550">[SWS_DM_01550]</a>) and ensures the clean release of session resources upon termination.</li>
</ul>

<h4>Usage Path</h4>
<p>
The regular operational flow of a read data transfer follows a fixed sequence of UDS services and interface calls:
</p>
<ol>
<li><strong>Initialization of the read session:</strong> Upon receipt of an initiating service request (such as <code>RequestFileTransfer</code> with read intent according to <a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a> or <a class="spec-record-ref" data-req="SWS_DM_01315" href="../spec/record.html?id=SWS_DM_01315">[SWS_DM_01315]</a>), the Diagnostic Server instance instantiates the <code>DataTransferReadSession</code> via the appropriate template constructor, passing the specific read handler. Interpretation: The server instance is likely to maintain the lifetime of the session object for the duration of the read transfer.</li>
<li><strong>Data transfer (TransferData 0x36):</strong> As soon as the diagnostic tester successively requests data blocks by means of <code>TransferData (0x36)</code>, the Diagnostic Server instance calls the <code>Read</code> method of the handler that was registered via the template constructor of the <code>DataTransferReadSession</code> (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>). The read data is transmitted to the tester in the diagnostic response.</li>
<li><strong>Termination of the transfer (RequestTransferExit 0x37):</strong> After completion of the data blocks, the tester sends the service <code>RequestTransferExit (0x37)</code>. The diagnostic server then calls the <code>Exit</code> method of the registered handler of the <code>DataTransferReadSession</code> (<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>).</li>
<li><strong>Session cleanup:</strong> After successful feedback of the exit call, the session object is destroyed (<a class="spec-record-ref" data-req="SWS_DM_01550" href="../spec/record.html?id=SWS_DM_01550">[SWS_DM_01550]</a>), which completes the read cycle.</li>
</ol>

<h4>Error Scenarios</h4>
<p>
At the level of interface definition and control flow, the following error sources and integrity rules are relevant:
</p>
<ul>
<li><strong>Invalid instantiation or copy attempts:</strong> Since the default constructor (<a class="spec-record-ref" data-req="SWS_DM_01549" href="../spec/record.html?id=SWS_DM_01549">[SWS_DM_01549]</a>) as well as copy operations (<a class="spec-record-ref" data-req="SWS_DM_01553" href="../spec/record.html?id=SWS_DM_01553">[SWS_DM_01553]</a>, <a class="spec-record-ref" data-req="SWS_DM_01554" href="../spec/record.html?id=SWS_DM_01554">[SWS_DM_01554]</a>) are deleted, any erroneous usage in the application code is already prevented at compile time by the compiler.</li>
<li><strong>Exception safety during transfer phases:</strong> The <code>noexcept</code> guarantees for move operations (<a class="spec-record-ref" data-req="SWS_DM_01551" href="../spec/record.html?id=SWS_DM_01551">[SWS_DM_01551]</a>, <a class="spec-record-ref" data-req="SWS_DM_01552" href="../spec/record.html?id=SWS_DM_01552">[SWS_DM_01552]</a>) and for destruction (<a class="spec-record-ref" data-req="SWS_DM_01550" href="../spec/record.html?id=SWS_DM_01550">[SWS_DM_01550]</a>) ensure that stack unwinding and resource cleanups proceed without additional exceptions even in the event of an error.</li>
<li><strong>Misconfiguration of handlers:</strong> If a registered handler does not provide the required signatures for <code>Read</code> or <code>Exit</code>, the processing of <code>TransferData (0x36)</code> (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>) or <code>RequestTransferExit (0x37)</code> (<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>) fails, whereupon the diagnostic server aborts the transfer with a negative response code.</li>
</ul>
