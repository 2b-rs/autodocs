<h4>Context</h4>
<p>The interface class <code>ara::diag::FileTransferService</code> (<a class="spec-record-ref" data-req="SWS_DM_01320" href="../spec/record.html?id=SWS_DM_01320">[SWS_DM_01320]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=467">AUTOSAR_AP_SWS_Diagnostics §8.18 “Header: ara/diag/file_transfer.h”</a>) provides the functional abstraction for file-based diagnostic transfers in AUTOSAR Adaptive. It serves to implement the UDS service 0x38 (RequestFileTransfer) and enables the standardized exchange of files and directory information across process boundaries (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=183">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”</a>).</p>
<p>Three main components are involved in the file transfer sequences:</p>
<ul>
<li><strong>Diagnostic client:</strong> Initiates file operations via standardized UDS service calls (RequestFileTransfer 0x38, TransferData 0x36, and RequestTransferExit 0x37).</li>
<li><strong>Diagnostic Management (Diagnostic Server Instance):</strong> Receives the diagnostic messages of the client, handles protocol processing, and forwards the requests to the registered service instance (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=184">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Realization of modeOfOperation”</a>).</li>
<li><strong>Adaptive Application:</strong> Implements the functional callback methods of <code>ara::diag::FileTransferService</code>, creates data sessions, and accesses the local file system.</li>
</ul>
<p>The architecture supports different strategies for data exchange (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=183">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”</a>):</p>
<ul>
<li><strong>Simple:</strong> Copies the data between the Adaptive Application and Diagnostic Management; suitable for smaller file sizes.</li>
<li><strong>Zero Copy:</strong> Avoids memory copies between the application and Diagnostic Management for resource efficiency with large amounts of data.</li>
<li><strong>OS File System Handle:</strong> Passing native operating system file handles for direct transfer without copying overhead in the diagnostic stack.</li>
</ul>

<h4>Lifecycle</h4>
<p>The class <code>ara::diag::FileTransferService</code> acts as a base class for application-specific diagnostic handlers. Upon instantiation, the constructor expects a <code>ara::core::InstanceSpecifier</code> referencing a modeled PortPrototype of type <code>DiagnosticRequestFileTransferInterface</code>, as well as the definition of concurrency via <code>ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>).</p>
<p>The instance and ownership relationships are strictly regulated:</p>
<ul>
<li><strong>Copy protection:</strong> The class represents a unique instance; copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01327" href="../spec/record.html?id=SWS_DM_01327">[SWS_DM_01327]</a>) and copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01329" href="../spec/record.html?id=SWS_DM_01329">[SWS_DM_01329]</a>) are deleted (<code>delete</code>).</li>
<li><strong>Movability:</strong> Move constructor (<a class="spec-record-ref" data-req="SWS_DM_01328" href="../spec/record.html?id=SWS_DM_01328">[SWS_DM_01328]</a>) and move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01330" href="../spec/record.html?id=SWS_DM_01330">[SWS_DM_01330]</a>) are defined in scope <code>protected</code>.</li>
<li><strong>Destruction:</strong> The virtual destructor <code>~FileTransferService()</code> (<a class="spec-record-ref" data-req="SWS_DM_01326" href="../spec/record.html?id=SWS_DM_01326">[SWS_DM_01326]</a>) ensures proper cleanup of derived classes.</li>
</ul>
<p>The functional lifecycle is actively controlled by the application:</p>
<ol>
<li><strong>Provided:</strong> After creation, Diagnostic Management does not yet forward any requests to the instance.</li>
<li><strong>Active (Offered):</strong> By calling <code>Offer()</code>, Diagnostic Management is authorized to forward requests to the service handler (<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>).</li>
<li><strong>Deactivated:</strong> Calling <code>StopOffer()</code> revokes authorization and prevents the forwarding of new requests (<a class="spec-record-ref" data-req="SWS_DM_01337" href="../spec/record.html?id=SWS_DM_01337">[SWS_DM_01337]</a>).</li>
</ol>
<p>With regard to thread safety, AUTOSAR differentiates: The callbacks of the interface align their concurrency behavior with the <code>ConcurrencyType</code> (<code>kConcurrent</code> or <code>kNotConcurrent</code>) passed in the constructor (<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>). In contrast, administrative methods such as <code>Offer()</code>, <code>StopOffer()</code>, and the destructor are specified as not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_01326" href="../spec/record.html?id=SWS_DM_01326">[SWS_DM_01326]</a>, <a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>, <a class="spec-record-ref" data-req="SWS_DM_01337" href="../spec/record.html?id=SWS_DM_01337">[SWS_DM_01337]</a>).</p>

<h4>Usage Path</h4>
<p>The interface covers all operating modes defined in UDS service 0x38 via dedicated pure virtual methods:</p>
<ul>
<li><code>RequestReadFile</code>: Called for <code>modeOfOperation</code> ReadFile (0x04) (<a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a>, <a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>).</li>
<li><code>RequestWriteFile</code>: Called for <code>modeOfOperation</code> ReplaceFile (0x03) with <code>WriteFileMode::kReplace</code> (<a class="spec-record-ref" data-req="SWS_DM_01313" href="../spec/record.html?id=SWS_DM_01313">[SWS_DM_01313]</a>, <a class="spec-record-ref" data-req="SWS_DM_01324" href="../spec/record.html?id=SWS_DM_01324">[SWS_DM_01324]</a>, <a class="spec-record-ref" data-req="SWS_DM_01333" href="../spec/record.html?id=SWS_DM_01333">[SWS_DM_01333]</a>) as well as for kAdd.</li>
<li><code>RequestResumeWriteFile</code>: Called for <code>modeOfOperation</code> ResumeFile (0x06) (<a class="spec-record-ref" data-req="SWS_DM_01316" href="../spec/record.html?id=SWS_DM_01316">[SWS_DM_01316]</a>, <a class="spec-record-ref" data-req="SWS_DM_01334" href="../spec/record.html?id=SWS_DM_01334">[SWS_DM_01334]</a>).</li>
<li><code>RequestReadDirectory</code>: Called for <code>modeOfOperation</code> ReadDir (0x05) (<a class="spec-record-ref" data-req="SWS_DM_01315" href="../spec/record.html?id=SWS_DM_01315">[SWS_DM_01315]</a>, <a class="spec-record-ref" data-req="SWS_DM_01332" href="../spec/record.html?id=SWS_DM_01332">[SWS_DM_01332]</a>).</li>
<li><code>DeleteFile</code>: Performs the complete deletion of a file for <code>modeOfOperation</code> DeleteFile (<a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>).</li>
</ul>
<p>A typical usage path for reading a file (<code>ReadFile</code>) takes place in the following steps:</p>
<ol>
<li><strong>Offering:</strong> The application instantiates its derived service class and activates the interface using <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>).</li>
<li><strong>Initial transfer request:</strong> The diagnostic client sends the UDS command 0x38 (ReadFile). The Diagnostic Server forwards the call to the application via <code>RequestReadFile(fileName, dataFormatIdentifier, metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a>, <a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>).</li>
<li><strong>Session establishment:</strong> The application checks the request and asynchronously returns a <code>ara::core::Future</code> that contains a tuple of an initialized <code>DataTransferReadSession</code> and the file sizes (<code>FileSizes</code>) (<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>). Diagnostic Management responds positively to the UDS request.</li>
<li><strong>Block transfer:</strong> For each subsequent TransferData request (0x36) from the client, the Diagnostic Server calls the read methods of the handlers registered in the session (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>).</li>
<li><strong>Transfer termination:</strong> After the complete transfer, the client sends RequestTransferExit (0x37). The Diagnostic Server then calls the session's <code>Exit</code> method (<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>) and completes the process.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error conditions are intercepted and reported in different layers of the system:</p>
<ul>
<li><strong>Construction and modeling errors:</strong> If the configuration does not correspond to the system model, the instantiation fails (<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>):
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved or does not point to a PortPrototype.</li>
  <li><code>PortInterfaceMappingViolation</code>: The DEM port typed by <code>DiagnosticRequestFileTransferInterface</code> is missing the <code>DiagnosticServiceGenericMapping</code>.</li>
  <li><code>ProcessMappingViolation</code>: No matching runtime process exists for the modeled process.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already being used within the process.</li>
  </ul>
</li>
<li><strong>Multiple offering:</strong> A repeated call to <code>Offer()</code> on an already active instance returns an error with <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>).</li>
<li><strong>Diagnostic negative responses (NRC):</strong> If file operations cannot be executed successfully in the virtual methods, the application signals this via the returned <code>ara::core::Future</code> with a UDS Negative Response Code (NRC) from the error domain <code>DiagUdsNrcErrc</code> according to ISO 14229-1 (<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>, <a class="spec-record-ref" data-req="SWS_DM_01332" href="../spec/record.html?id=SWS_DM_01332">[SWS_DM_01332]</a>, <a class="spec-record-ref" data-req="SWS_DM_01333" href="../spec/record.html?id=SWS_DM_01333">[SWS_DM_01333]</a>, <a class="spec-record-ref" data-req="SWS_DM_01334" href="../spec/record.html?id=SWS_DM_01334">[SWS_DM_01334]</a>, <a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>).</li>
<li><strong>Operation cancellation:</strong> Via the parameter <code>CancellationHandler</code>, the application can continuously check the cancellation status with <code>cancellationHandler.IsCanceled()</code> during asynchronous file operations or register a notification via <code>cancellationHandler.SetNotifier()</code> to immediately release resources in the event of an early session termination (<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>, <a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>).</li>
</ul>
