<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient der standardisierten Anbindung und Verwaltung externer UDS-Transportprotokolle im Diagnose-Management.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Namespace <code>apext::diag::uds_transport</code> stellt die C++-Transportschnittstelle zur Entkopplung des generischen Diagnose-Managements von spezifischen UDS-Transportprotokollen bereit <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 „UDS Transport Layer“</a>. Protokoll-Plugins leiten sich von der Basisklasse <code>UdsTransportProtocolHandler</code> ab und durchlaufen einen strikten Lebenszyklus aus Konstruktion, Initialisierung, Start und geordnetem Stoppen <a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>. Eingehende Nachrichten werden über <code>IndicateMessage</code> gemeldet und erhalten bei freien Kapazitäten einen speicherverwalteten <code>UdsMessagePtr</code> zur Nutzdatenübernahme. Eine zentrale Randbedingung ist, dass nach dem Stoppen keine weiteren Aufrufe an das Diagnose-Management außer der Bestätigungsmeldung erfolgen dürfen.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Der Namespace <code>apext::diag::uds_transport</code> definiert die standardisierte C++-Transportschnittstelle (Transport Protocol API) für das Diagnose-Management (DM) in der AUTOSAR Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 „UDS Transport Layer“</a>. Die Architektur trennt den generischen Kern des Diagnose-Managements funktional von konkreten Netzwerk- und Transportschichten ab. Auf diese Weise können standardisierte Protokolle wie DoIP sowie künftige oder herstellerspezifische Transportprotokolle (beispielsweise für CAN, CAN-FD oder FlexRay) als modulare Plugins integriert werden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 „UDS Transport Layer“</a>.</p>
<p>Die zentrale Vermittlungsinstanz bildet die Klasse <code>UdsTransportProtocolMgr</code>, welche die Interaktion zwischen den Instanzen des Diagnostic Server und den angebundenen Transportprotokollen koordiniert. Konkrete Protokoll-Plugins leiten sich von der abstrakten Basisklasse <code>UdsTransportProtocolHandler</code> ab <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1 „Support of UDS Transport Layer“</a> <a class="spec-record-ref" data-req="SWS_DM_00315" href="../spec/record.html?id=SWS_DM_00315">[SWS_DM_00315]</a>. Einzelne Handler-Instanzen werden über <code>UdsTransportProtocolHandlerID</code> adressiert <a class="spec-record-ref" data-req="SWS_DM_00336" href="../spec/record.html?id=SWS_DM_00336">[SWS_DM_00336]</a>, während Kommunikationskanäle über den Typ <code>ChannelID</code> identifiziert werden <a class="spec-record-ref" data-req="SWS_DM_00337" href="../spec/record.html?id=SWS_DM_00337">[SWS_DM_00337]</a>. Zur Unterstützung periodischer Datenabfragen nach ISO-Dienst 0x2A bindet die Schnittstelle zusätzlich die Klasse <code>UdsTransportProtocolPeriodicHandler</code> ein.</p>

<h4>Lebenszyklus</h4>
<p>Das Diagnose-Management steuert den Lebenszyklus jeder <code>UdsTransportProtocolHandler</code>-Instanz in einer fest vorgegebenen Reihenfolge <a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>:</p>
<ol>
<li><strong>Erzeugung:</strong> Das DM instanziiert das Protokoll-Plugin über den Konstruktor <code>UdsTransportProtocolHandler::UdsTransportProtocolHandler</code> <a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>.</li>
<li><strong>Initialisierung:</strong> Das DM ruft <code>UdsTransportProtocolHandler::Initialize</code> auf <a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>. Bis auf die Abfrage von <code>GetPeriodicHandler</code> darf das DM vor der erfolgreichen Rückgabe von <code>kInitializeOk</code> keine weiteren Methoden auf dem Handler aufrufen <a class="spec-record-ref" data-req="SWS_DM_01746" href="../spec/record.html?id=SWS_DM_01746">[SWS_DM_01746]</a>.</li>
<li><strong>Start und Betrieb:</strong> Nach erfolgreicher Initialisierung wird der Handler mit <code>UdsTransportProtocolHandler::Start</code> aktiviert. Erst nach diesem Aufruf verarbeitet das DM Meldungen über reaktivierte Kanäle via <code>UdsTransportProtocolMgr::ChannelReestablished</code> <a class="spec-record-ref" data-req="SWS_DM_01744" href="../spec/record.html?id=SWS_DM_01744">[SWS_DM_01744]</a>.</li>
<li><strong>Terminierung:</strong> Wechselt das DM in den Zustand <code>ApplicationState.kTerminating</code>, ruft es für alle aktiven Plugins <code>UdsTransportProtocolHandler::Stop</code> auf <a class="spec-record-ref" data-req="SWS_DM_00333" href="../spec/record.html?id=SWS_DM_00333">[SWS_DM_00333]</a>. Nach Rückkehr dieses Aufrufs darf das Plugin ausschließlich <code>UdsTransportProtocolMgr::HandlerStopped</code> aufrufen <a class="spec-record-ref" data-req="SWS_DM_01741" href="../spec/record.html?id=SWS_DM_01741">[SWS_DM_01741]</a>. Das DM wartet aktiv auf diese Bestätigung <a class="spec-record-ref" data-req="SWS_DM_00340" href="../spec/record.html?id=SWS_DM_00340">[SWS_DM_00340]</a>.</li>
</ol>

<h4>Nutzungspfad</h4>
<p>Im laufenden Betrieb erfolgt die Weiterleitung eingehender Diagnosenachrichten über ein abgestimmtes Zusammenspiel von Handler und Manager:</p>
<ol>
<li><strong>Nachrichtenindikation:</strong> Empfängt der Handler Daten auf einem Kanal (<code>ChannelID</code> <a class="spec-record-ref" data-req="SWS_DM_00337" href="../spec/record.html?id=SWS_DM_00337">[SWS_DM_00337]</a>), ruft er <code>UdsTransportProtocolMgr::IndicateMessage</code> auf. Dabei kann er Vorab-Nutzdaten in <code>payloadInfo</code> übergeben; empfohlen werden mindestens die ersten zwei Bytes zur frühzeitigen Erkennung funktionaler Anfragen <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 „UDS Transport Layer“</a>.</li>
<li><strong>Pufferallokation:</strong> Ist das DM aufnahmebereit, antwortet <code>IndicateMessage</code> mit einem <code>std::pair</code> aus <code>IndicationResult::kIndicationOk</code> und einem gültigen Smart-Pointer <code>UdsMessagePtr</code> <a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a> <a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>. Das referenzierte <code>UdsMessage</code>-Objekt besitzt eine Mindestkapazität von einem Byte <a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>. Der Puffer wird als <code>std::unique_ptr</code> mit einem spezifischen Deleter des DM-Kerns verwaltet und ist nicht threadsicher <a class="spec-record-ref" data-req="SWS_DM_00303" href="../spec/record.html?id=SWS_DM_00303">[SWS_DM_00303]</a>. Für Lesezugriffe existiert das konstante Äquivalent <code>UdsMessageConstPtr</code> <a class="spec-record-ref" data-req="SWS_DM_00304" href="../spec/record.html?id=SWS_DM_00304">[SWS_DM_00304]</a>.</li>
<li><strong>Datenübergabe:</strong> Der Handler schreibt die empfangenen Diagnosedaten in den bereitgestellten Puffer, dessen Bytefolge über den Typ <code>ByteSpan</code> (Alias für <code>ara::core::Span&lt;ara::core::Byte&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00338" href="../spec/record.html?id=SWS_DM_00338">[SWS_DM_00338]</a>) typisiert ist. Vermutlich dient die Bereitstellung der separaten Klasse <code>UdsTransportProtocolPeriodicHandler</code> über <code>GetPeriodicHandler</code> der Entkoppelung des periodischen Übertragungsdienstes 0x2A vom regulären UDS-Nachrichtenpfad. <a class="interp-q interp-q-open" data-q="Q-230ef0b7c384c594" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-230ef0b7c384c594" title="Frage Q-230ef0b7c384c594 (offen): Vermutlich dient die Bereitstellung der separaten Klasse UdsTransportProtocolPeriodicHandler über GetPeriodicHandler der Entkoppelung des periodischen Übertragungsdienstes 0x2A vom regulären UDS-Nachrichtenpfad.">Frage Q-230ef0b7c384c594 (offen)</a></li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Die Spezifikation definiert konkrete Fehlerzustände und Vorbedingungen für die Transportanbindung:</p>
<ul>
<li><strong>Fehlgeschlagene Initialisierung:</strong> Liefert <code>UdsTransportProtocolHandler::Initialize</code> das Ergebnis <code>kInitializeFailed</code>, bricht das DM den Initialisierungsprozess für diesen Handler sofort ab und ruft keine weiteren Methoden an ihm auf <a class="spec-record-ref" data-req="SWS_DM_01745" href="../spec/record.html?id=SWS_DM_01745">[SWS_DM_01745]</a>.</li>
<li><strong>Abweisung bei belegtem Diagnosekern:</strong> Wenn das DM durch eine laufende Servicebearbeitung derselben Tester-Present-Konversation blockiert ist und es sich nicht um ein funktionales Tester-Present mit <code>payloadInfo</code> <code>0x3E 0x80</code> handelt, liefert <code>IndicateMessage</code> das Ergebnis <code>kIndicationOccupied</code> zusammen mit einem <code>nullptr</code> anstelle eines Nachrichtenpuffers zurück <a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>.</li>
<li><strong>Unerlaubte Aufrufe nach Terminierung:</strong> Ruft ein Plugin nach Rückkehr von <code>Stop</code> eine andere Methode von <code>UdsTransportProtocolMgr</code> als <code>HandlerStopped</code> auf, verletzt dies die Protokollvorgaben <a class="spec-record-ref" data-req="SWS_DM_01741" href="../spec/record.html?id=SWS_DM_01741">[SWS_DM_01741]</a>. Ebenso ignoriert das DM Signale wie <code>ChannelReestablished</code>, wenn sie vor dem erfolgreichen Aufruf von <code>Start</code> eingehen <a class="spec-record-ref" data-req="SWS_DM_01744" href="../spec/record.html?id=SWS_DM_01744">[SWS_DM_01744]</a>.</li>
</ul>
