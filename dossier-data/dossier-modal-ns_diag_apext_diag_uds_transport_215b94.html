<h4>Context</h4>
<p>The namespace <code>apext::diag::uds_transport</code> provides the C++ transport layer interface (Transport Protocol API) of the Diagnostic Management (DM) in the AUTOSAR Adaptive Platform (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 “UDS Transport Layer”</a>). The interface decouples the generic DM core from specific transmission technologies such as DoIP, CAN, CAN-FD, or manufacturer-specific transport protocols (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 “UDS Transport Layer”</a>).</p>
<p>The architecture distributes responsibility across four core classes and central type definitions:</p>
<ul>
<li><code>UdsTransportProtocolMgr</code>: Acts as an intermediary between the diagnostic server instances of the DM core and the attached UDS transport protocols.</li>
<li><code>UdsTransportProtocolHandler</code>: Defines the abstract base class for transport-specific plugin implementations (<a class="spec-record-ref" data-req="SWS_DM_00315" href="../spec/record.html?id=SWS_DM_00315">[SWS_DM_00315]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”</a>). Each handler plugin is identified via an identifier of type <code>UdsTransportProtocolHandlerID</code> (<a class="spec-record-ref" data-req="SWS_DM_00336" href="../spec/record.html?id=SWS_DM_00336">[SWS_DM_00336]</a>).</li>
<li><code>UdsMessage</code>: Represents the UDS message exchanged between the DM core (via <code>UdsTransportProtocolMgr</code>) and the transport plugin. The smart pointer aliases <code>UdsMessagePtr</code> (<a class="spec-record-ref" data-req="SWS_DM_00303" href="../spec/record.html?id=SWS_DM_00303">[SWS_DM_00303]</a>) for mutable messages and <code>UdsMessageConstPtr</code> (<a class="spec-record-ref" data-req="SWS_DM_00304" href="../spec/record.html?id=SWS_DM_00304">[SWS_DM_00304]</a>) for read-only messages serve to safely transfer memory and ownership.</li>
<li><code>UdsTransportProtocolPeriodicHandler</code>: Provides a specialized handler class to support periodic UDS message transmissions according to ISO service 0x2A.</li>
</ul>
<p>In addition, the type alias <code>ChannelID</code> (<a class="spec-record-ref" data-req="SWS_DM_00337" href="../spec/record.html?id=SWS_DM_00337">[SWS_DM_00337]</a>) designates logical transmission channels of the network, while <code>ByteSpan</code> (<a class="spec-record-ref" data-req="SWS_DM_00338" href="../spec/record.html?id=SWS_DM_00338">[SWS_DM_00338]</a>) is used for memory-efficient views of buffer areas.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a transport protocol implementation is completely controlled by the DM core and follows a strict sequence of operating phases (<a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1.1 “Initialization, Starting and Stopping of a UDS TransportLayer”</a>):</p>
<ol>
<li><strong>Instantiation:</strong> The DM creates the plugin instance via the constructor <code>UdsTransportProtocolHandler::UdsTransportProtocolHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>).</li>
<li><strong>Initialization:</strong> The DM executes <code>UdsTransportProtocolHandler::Initialize</code> (<a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>). Only after this call has successfully returned <code>kInitializeOk</code> is the DM allowed to call further methods of the handler (<a class="spec-record-ref" data-req="SWS_DM_01746" href="../spec/record.html?id=SWS_DM_01746">[SWS_DM_01746]</a>). An exception is <code>GetPeriodicHandler</code>, which may be queried in advance (<a class="spec-record-ref" data-req="SWS_DM_01746" href="../spec/record.html?id=SWS_DM_01746">[SWS_DM_01746]</a>). Interpretation: This is likely intended to provide the periodic handler for service 0x2A early, prior to the regular start of operation. If the initialization fails with <code>kInitializeFailed</code>, the DM aborts the process and calls no further methods on the instance (<a class="spec-record-ref" data-req="SWS_DM_01745" href="../spec/record.html?id=SWS_DM_01745">[SWS_DM_01745]</a>).</li>
<li><strong>Operating phase:</strong> After successful initialization, the handler is started. Only after the start call does the <code>UdsTransportProtocolMgr</code> process channel events such as <code>ChannelReestablished</code> (<a class="spec-record-ref" data-req="SWS_DM_01744" href="../spec/record.html?id=SWS_DM_01744">[SWS_DM_01744]</a>).</li>
<li><strong>Termination:</strong> If the overall system transitions to the state <code>ApplicationState.kTerminating</code>, the DM calls the method <code>Stop</code> on all started handlers (<a class="spec-record-ref" data-req="SWS_DM_00333" href="../spec/record.html?id=SWS_DM_00333">[SWS_DM_00333]</a>). As soon as <code>Stop</code> has returned, the plugin may only call <code>HandlerStopped</code> on the <code>UdsTransportProtocolMgr</code> (<a class="spec-record-ref" data-req="SWS_DM_01741" href="../spec/record.html?id=SWS_DM_01741">[SWS_DM_01741]</a>). The DM actively waits for this confirmation (<a class="spec-record-ref" data-req="SWS_DM_00340" href="../spec/record.html?id=SWS_DM_00340">[SWS_DM_00340]</a>).</li>
</ol>

<h4>Usage Path</h4>
<p>The typical sequence when receiving a UDS diagnostic message involves multiple components of the namespace:</p>
<ol>
<li>The transport protocol plugin receives diagnostic bytes via a logical network channel (<code>ChannelID</code>, <a class="spec-record-ref" data-req="SWS_DM_00337" href="../spec/record.html?id=SWS_DM_00337">[SWS_DM_00337]</a>).</li>
<li>The plugin reports the start of reception to the DM via <code>UdsTransportProtocolMgr::IndicateMessage</code> (<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>). In doing so, the plugin can pass payload already received in advance in <code>payloadInfo</code>; at least the first two bytes are recommended for the early detection of functional requests (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=94">AUTOSAR_AP_SWS_Diagnostics §7.1 “UDS Transport Layer”</a>).</li>
<li>If the DM is capable of processing, <code>IndicateMessage</code> returns a <code>std::pair</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=98">AUTOSAR_AP_SWS_Diagnostics §7.1.1.1 “Support of UDS Transport Layer”</a>, <a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>) with the result <code>kIndicationOk</code> and a valid <code>UdsMessagePtr</code> (<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>). The allocated message has a capacity of at least one byte in accordance with the processing request of the DM (<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>).</li>
<li>The plugin transfers the payload arriving via the network into the buffer of the <code>UdsMessage</code> object and forwards the message for further processing.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The specification defines concrete error conditions and precondition violations:</p>
<ul>
<li><strong>Initialization abort:</strong> If <code>Initialize</code> returns the status <code>kInitializeFailed</code>, the DM aborts the initialization and calls no further methods on this handler (<a class="spec-record-ref" data-req="SWS_DM_01745" href="../spec/record.html?id=SWS_DM_01745">[SWS_DM_01745]</a>).</li>
<li><strong>Occupied Diagnostic Server (IndicationOccupied):</strong> If the DM is occupied by the active processing of a service of the same Tester Present conversation, a call to <code>IndicateMessage</code> is rejected (<a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>). The DM returns a <code>std::pair</code> with <code>kIndicationOccupied</code> and <code>UdsMessagePtr</code> equal to <code>nullptr</code> (<a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>). An exception is functional Tester Present requests (with <code>payloadInfo</code> <code>0x3E 0x80</code> and set <code>suppressPosRspMsgIndicationBit</code>), which may be processed at any time (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=99">AUTOSAR_AP_SWS_Diagnostics §7.1.1.1 “Support of UDS Transport Layer”</a>, <a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>).</li>
<li><strong>Method call prior to initialization:</strong> With the exception of <code>GetPeriodicHandler</code>, the DM must not call any methods on <code>UdsTransportProtocolHandler</code> before <code>Initialize</code> has responded with <code>kInitializeOk</code> (<a class="spec-record-ref" data-req="SWS_DM_01746" href="../spec/record.html?id=SWS_DM_01746">[SWS_DM_01746]</a>).</li>
<li><strong>Impermissible calls after termination:</strong> After <code>Stop</code> returns, the plugin may only call <code>HandlerStopped</code> on the <code>UdsTransportProtocolMgr</code>; all other method calls are impermissible (<a class="spec-record-ref" data-req="SWS_DM_01741" href="../spec/record.html?id=SWS_DM_01741">[SWS_DM_01741]</a>).</li>
</ul>
