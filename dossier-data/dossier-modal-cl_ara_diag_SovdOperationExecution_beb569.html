<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient als Schnittstelle zur Steuerung, Statusabfrage und kontrollierten Terminierung laufender SOVD-Operationsausführungen.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle dient der anwendungsspezifischen Steuerung und Überwachung einer laufenden SOVD-Operation im Diagnostic Management <a class="spec-record-ref" data-req="SWS_DM_02197" href="../spec/record.html?id=SWS_DM_02197">[SWS_DM_02197]</a>. Über geschützte Methoden verarbeitet sie Statusabfragen sowie Anforderungen zur Ausführung spezieller Fähigkeiten oder zum Abbruch der Operation. Alle Rückgaben erfolgen asynchron über Futures, wobei Fehler zwingend als standardisierte SOVD-Fehlercodes nach ISO 17978-3 übermittelt werden <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>. Zudem müssen Implementierungen threadsicher sein und übergebene Cancellation-Handler strikt an die Operationslebensdauer binden.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::SovdOperationExecution</code> definiert die Programmierschnittstelle zur Steuerung und Überwachung laufender SOVD-Operationsausführungen (Service-Oriented Vehicle Diagnostics) innerhalb des Moduls <code>diag</code> der AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_02197" href="../spec/record.html?id=SWS_DM_02197">[SWS_DM_02197]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=861">SWS Diagnostics §8.62.5 „Class: SovdOperationExecution“</a>. Sie fungiert als Bindeglied zwischen dem Diagnostic Management (DM) und der ausführenden Anwendungslogik für diagnosebezogene Routinen nach ASAM SOVD und ISO 17978-3.</p>
<p>Wenn ein externer SOVD-Client das Starten einer Operation initiiert <a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a> und die optionale Validierung der Proximity Challenge erfolgreich durchlaufen wurde <a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>, instanziiert bzw. bindet das DM die Ausführung an eine eindeutige Kennung (<code>execution-id</code>) <a class="spec-record-ref" data-req="SWS_DM_02177" href="../spec/record.html?id=SWS_DM_02177">[SWS_DM_02177]</a>. Alle nachfolgenden Methodenaufrufe zu dieser laufenden Operation – insbesondere Statusabfragen und Abbruchbefehle – leitet das DM an diejenige Instanz von <code>ara::diag::SovdOperationExecution</code> weiter, die dieser Kennung zugewiesen ist <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Klasse besitzt einen als <code>noexcept=default</code> deklarierten Standardkonstruktor <a class="spec-record-ref" data-req="SWS_DM_02198" href="../spec/record.html?id=SWS_DM_02198">[SWS_DM_02198]</a> sowie einen virtuellen Destruktor, der ebenfalls als <code>noexcept=default</code> definiert ist <a class="spec-record-ref" data-req="SWS_DM_02199" href="../spec/record.html?id=SWS_DM_02199">[SWS_DM_02199]</a>. Da sämtliche fachlichen Methoden – <code>ExecuteCapability</code> <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>, <code>GetStatus</code> <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a> und <code>Terminate</code> <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a> – rein virtuell (<code>= 0</code>) und geschützt (<code>protected</code>) sind, ist die Klasse nicht direkt instanziierbar. Interpretation: Anwendungsentwickler leiten eigene Klassen von <code>SovdOperationExecution</code> ab, um die anwendungsspezifischen Routinen zu implementieren. <a class="interp-q interp-q-open" data-q="Q-c1d622c7aa17382d" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-c1d622c7aa17382d" title="Frage Q-c1d622c7aa17382d (offen): Die Klasse dient als Basisklasse für anwendungsspezifische Operations-Handler">Frage Q-c1d622c7aa17382d (offen)</a></p>
<p>Jede aktive Operationsausführung wird im DM einer <code>execution-id</code> zugeordnet <a class="spec-record-ref" data-req="SWS_DM_02177" href="../spec/record.html?id=SWS_DM_02177">[SWS_DM_02177]</a>, <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>. Die Spezifikation hebt hervor, dass Operationen in vielen Fällen lediglich eine einzige gleichzeitige Instanz erlauben <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=218">SWS Diagnostics §7.3.3.5.5.6 „Operations – Terminate execution of an operation“</a>. Alle Schnittstellenmethoden sind als threadsicher (<code>thread-safe</code>) und ausnahmesicher (<code>exception safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>.</p>
<p>Hinsichtlich des Speichermanagements und der Lebensdauern gelten strenge Vorgaben: Der Parameter <code>sovd_content_data</code> bleibt solange gültig, bis das zugehörige Promise erfüllt oder die Verarbeitung über den <code>cancellation_handler</code> abgebrochen wurde <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>. Das Objekt <code>cancellation_handler</code> selbst darf unter keinen Umständen über die Lebensdauer der jeweiligen Operation hinaus gespeichert oder aufgerufen werden <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Ablauf zur Begleitung einer SOVD-Operation gliedert sich in folgende Schritte:</p>
<ul>
<li><strong>Fähigkeiten anfordern:</strong> Das DM kann für eine laufende Operation über die Methode <code>ExecuteCapability</code> Aktionen wie Ausführen, Einfrieren oder Zurücksetzen anfordern <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>.</li>
<li><strong>Status abfragen:</strong> Empfängt das DM den SOVD-Aufruf „Read the Status of an operation“ und gelingt die geforderte Proximity-Validierung <a class="spec-record-ref" data-req="SWS_DM_02173" href="../spec/record.html?id=SWS_DM_02173">[SWS_DM_02173]</a>, ruft es <code>GetStatus</code> der zugewiesenen <code>SovdOperationExecution</code>-Instanz auf <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>. Nach erfolgreicher Rückkehr antwortet das DM dem Client mit den Attributen <code>status</code> (aus <code>GetStatusResponse.status</code>), <code>capability</code> (Wert <code>execute</code>) und <code>parameters</code> (abgeleitet aus <code>GetStatusResponse.Parameters</code>) <a class="spec-record-ref" data-req="SWS_DM_02181" href="../spec/record.html?id=SWS_DM_02181">[SWS_DM_02181]</a>.</li>
<li><strong>Operation terminieren:</strong> Geht beim Diagnostic Server die SOVD-Methode „Terminate execution of an Operation“ ein <a class="spec-record-ref" data-req="SWS_DM_01392" href="../spec/record.html?id=SWS_DM_01392">[SWS_DM_01392]</a>, wird nach Validierung der Proximity-Antwort <a class="spec-record-ref" data-req="SWS_DM_01391" href="../spec/record.html?id=SWS_DM_01391">[SWS_DM_01391]</a> die Methode <code>Terminate</code> unter Angabe des Grundes (<code>TerminateOperationExecutionReason</code>) an der Instanz aufgerufen <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Alle auszuführenden Methoden (<code>ExecuteCapability</code>, <code>GetStatus</code>, <code>Terminate</code>) arbeiten asynchron und geben ein <code>ara::core::Future</code> zurück <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>. Schlägt die Verarbeitung innerhalb der Anwendung fehl, muss das Future mit einem anwendbaren SOVD-Fehlercode gemäß ISO 17978-3 bzw. ASAM SOVD 1.1 erfüllt werden <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>.</p>
<p>Wird eine laufende Anforderung seitens des Diagnose-Frameworks storniert, signalisiert das DM dies über das mitgegebene Objekt <code>ara::diag::CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>. Die Implementierung muss den Abbruchzustand dieses Handlers berücksichtigen und die Bearbeitung unverzüglich beenden, um blockierende Zustände zu verhindern.</p>
