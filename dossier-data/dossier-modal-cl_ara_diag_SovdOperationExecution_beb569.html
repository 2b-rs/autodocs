<h4>Context</h4>
<p>In AUTOSAR Adaptive, the <code>ara::diag::SovdOperationExecution</code> class forms the interface for controlling and state monitoring of an ongoing SOVD operation execution (<em lang="en">Service-Oriented Vehicle Diagnostics</em>) <a class="spec-record-ref" data-req="SWS_DM_02197" href="../spec/record.html?id=SWS_DM_02197">[SWS_DM_02197]</a>. It acts as a link between the central diagnostic server (Diagnostic Management, DM) and the application-specific implementation of the diagnostic operation.</p>
<p>In the overall system, three primary partners interact with each other:</p>
<ul>
<li><strong>SOVD client:</strong> Initiates diagnostic methods via the SOVD protocol according to ASAM SOVD or ISO 17978-3 (for example, starting, querying the execution status, or terminating an operation) <a class="spec-record-ref" data-req="SWS_DM_01392" href="../spec/record.html?id=SWS_DM_01392">[SWS_DM_01392]</a>, <a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>.</li>
<li><strong>Diagnostic Management (DM):</strong> Processes incoming SOVD requests, performs upstream security and proximity checks, and forwards actions to the associated instance of <code>SovdOperationExecution</code> based on a unique <code>execution-id</code> <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>, <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>.</li>
<li><strong>Adaptive application (subclass):</strong> Implements the pure virtual methods to provide the actual execution logic in the vehicle, report status changes, and process control commands such as freezing or resetting.</li>
</ul>

<h4>Lifecycle</h4>
<p>The <code>SovdOperationExecution</code> class is designed as an abstract base interface. Its default constructor is protected (<code>protected</code>) and defined as <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_02198" href="../spec/record.html?id=SWS_DM_02198">[SWS_DM_02198]</a>. The virtual destructor is public and likewise declared as <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_02199" href="../spec/record.html?id=SWS_DM_02199">[SWS_DM_02199]</a>. A concrete instance is likely created by the Adaptive application as soon as a SOVD operation is started and remains assigned to an allocated <code>execution-id</code> for the duration of the execution <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>. As noted in <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=218">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.6 “Operations – Terminate execution of an operation”</a>, diagnostic operations often allow only a single active instance at a time.</p>
<p>With regard to concurrency and resource management, strict requirements apply:</p>
<ul>
<li><strong>Thread safety:</strong> All functional methods (<code>ExecuteCapability</code>, <code>GetStatus</code>, <code>Terminate</code>) are specified as exception-safe (<code>exception safe</code>) and thread-safe (<code>thread-safe</code>). They each return a <code>ara::core::Future</code>, which enables concurrent and asynchronous processing by the application.</li>
<li><strong>Validity of content data:</strong> The data object <code>DiagnosticSovdContentData</code> passed to <code>ExecuteCapability</code> remains valid exactly until the associated promise is fulfilled or processing is canceled <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>.</li>
<li><strong>Lifetime of the cancellation handler:</strong> The passed <code>ara::diag::CancellationHandler</code> must under no circumstances be stored or referenced beyond the lifetime of the respective method call <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>, <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical flow of an SOVD operation execution comprises providing the status, optional capability calls during execution, and the final termination:</p>
<ol>
<li><strong>Status query:</strong> If an SOVD request for the method <em>Read the Status of an operation</em> arrives at the DM, the DM determines the instance based on the <code>execution-id</code> and calls <code>SovdOperationExecution::GetStatus</code> <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>, <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>. After successful return of <code>GetStatusResponse</code>, the DM generates the SOVD response with the status value, the property <code>capability=execute</code>, as well as the parameters from <code>DiagnosticSovdContentData</code> <a class="spec-record-ref" data-req="SWS_DM_02181" href="../spec/record.html?id=SWS_DM_02181">[SWS_DM_02181]</a>.</li>
<li><strong>Execution of capabilities:</strong> For the targeted control of sub-capabilities (such as <em>execute</em>, <em>freeze</em>, or <em>reset</em>), the DM calls the method <code>ExecuteCapability</code> <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>. The application processes the command and returns a <code>OperationExecutionStatus</code> via the future.</li>
<li><strong>Termination:</strong> If the DM receives the SOVD method <em>Terminate execution of an Operation</em> <a class="spec-record-ref" data-req="SWS_DM_01392" href="../spec/record.html?id=SWS_DM_01392">[SWS_DM_01392]</a>, it calls <code>SovdOperationExecution::Terminate</code> with the reason <code>TerminateOperationExecutionReason</code> <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>. The terminating future (<code>ara::core::Future&lt;void&gt;</code>) completes the execution.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors during operation execution are handled via the asynchronous return values and preceding protocol checks:</p>
<ul>
<li><strong>SOVD error codes:</strong> If a call to <code>ExecuteCapability</code>, <code>GetStatus</code>, or <code>Terminate</code> fails, the application signals this via the returned future with an applicable SOVD error code according to ISO 17978-3 or ASAM SOVD 1.1 <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>, <a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>, <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>. The DM then formulates the negative SOVD response to the client.</li>
<li><strong>Failed proximity validation:</strong> Incoming client requests for <code>Terminate</code> or <code>Read the Status of an operation</code> are subject, if configured, to a validation of the proximity challenge (<em lang="en">proximity_response</em>) <a class="spec-record-ref" data-req="SWS_DM_01391" href="../spec/record.html?id=SWS_DM_01391">[SWS_DM_01391]</a>, <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>, <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>. If this check is not successful, the DM does not call the methods of <code>SovdOperationExecution</code>.</li>
<li><strong>Cancellation handling via CancellationHandler:</strong> If an ongoing process is canceled by the DM, the DM signals this via the object <code>ara::diag::CancellationHandler</code>. The application must immediately stop processing; provided content data (<code>sovd_content_data</code>) loses its validity upon cancellation <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>.</li>
</ul>
