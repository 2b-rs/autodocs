<div class="ai-level" data-ai-level="2">
<p>Die Template-Klasse <code>ara::core::Variant</code> dient als typsichere Union zur Speicherung und Verwaltung genau eines Wertes aus einer vorgegebenen Typenmenge <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a>. Sie unterstützt flexible Konstruktions-, Zuweisungs- und Emplace-Mechanismen und erlaubt die Bestimmung der aktiven Alternative über <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a>. Wichtigste Besonderheit gegenüber dem Standard sind die modifizierten, bedingten Noexcept-Spezifikationen sämtlicher modifizierender Operationen sowie die Absicherung gegen den Zustand <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>.</p>

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Variant</code> stellt eine typsichere Union für die AUTOSAR Adaptive Platform dar, die über den Header <code>ara/core/variant.h</code> eingebunden wird. Sie kapselt die Verwaltung genau eines Wertes aus einer zur Übersetzungszeit definierten Typenliste (<code>template &lt;typename... Types&gt; class Variant</code>). Die Definition orientiert sich grundlegend am Verhalten von <code>std::variant</code> aus dem C++-Standard [variant], weist jedoch spezifische AUTOSAR-Abweichungen hinsichtlich der Ausnahmespezifikation auf. Die Beschreibung der Klasse verweist im Metadatenbestand auf <code>[basic.string]</code>; Interpretation: hierbei dürfte es sich um eine redaktionelle Unstimmigkeit handeln, da sämtliche Anforderungen konsistent den Standardabschnitt [variant] referenzieren.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Variant</code> durchläuft deterministische Lebenszyklusphasen von der Initialisierung über Wertwechsel bis zur Zerstörung. Die Erzeugung erfolgt entweder über den parameterlosen Default-Konstruktor <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a>, der die erste Alternative initialisiert, über Kopier- und Verschiebekonstruktoren <a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01651" href="../spec/record.html?id=SWS_CORE_01651">[SWS_CORE_01651]</a> oder über direkte Wertübergabe <a class="spec-record-ref" data-req="SWS_CORE_01652" href="../spec/record.html?id=SWS_CORE_01652">[SWS_CORE_01652]</a>. Zudem stehen Überladungen für die In-Place-Konstruktion mittels <code>in_place_type_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01654" href="../spec/record.html?id=SWS_CORE_01654">[SWS_CORE_01654]</a> sowie <code>in_place_index_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01655" href="../spec/record.html?id=SWS_CORE_01655">[SWS_CORE_01655]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01656" href="../spec/record.html?id=SWS_CORE_01656">[SWS_CORE_01656]</a> zur Verfügung, auch in Kombination mit Initialisierungslisten.</p>
<p>Im regulären Zustand hält das Objekt stets eine gültige Alternative, deren nullbasierter Index mit der Methode <code>index()</code> ermittelt werden kann <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a>. Scheitert ein Wertwechsel während einer Konstruktion oder Zuweisung durch das Auslösen einer Ausnahme, geht die Instanz in den Zustand <code>valueless_by_exception()</code> über <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>. Das Objekt verbleibt in diesem Zustand, bis durch eine erfolgreiche Neuinitialisierung wieder eine gültige Alternative belegt wird. Der Destruktor zerstört das aktuell gehaltene Objekt ordnungsgemäß und ist bedingt ausnahmesicher deklariert <a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungsablauf umfasst die Instanziierung, das Zuweisen oder Ersetzen des Inhalts, die Abfrage des Zustands und den Werteaustausch:</p>
<ul>
<li><strong>Initialisierung:</strong> Erzeugung einer Instanz über einen der Konstruktoren, beispielsweise per direkter Wertübergabe <a class="spec-record-ref" data-req="SWS_CORE_01652" href="../spec/record.html?id=SWS_CORE_01652">[SWS_CORE_01652]</a> oder explizit typbezogen mittels <code>in_place_type_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>.</li>
<li><strong>Werteaktualisierung und Neubelegung:</strong> Zuweisung eines neuen Wertes über den Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>, den Verschiebezuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_01659" href="../spec/record.html?id=SWS_CORE_01659">[SWS_CORE_01659]</a> oder die generische Wertzuweisung <a class="spec-record-ref" data-req="SWS_CORE_01660" href="../spec/record.html?id=SWS_CORE_01660">[SWS_CORE_01660]</a>. Alternativ kann der Wert direkt vor Ort via <code>emplace</code> nach Typ <a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01662" href="../spec/record.html?id=SWS_CORE_01662">[SWS_CORE_01662]</a> oder nach Index <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01664" href="../spec/record.html?id=SWS_CORE_01664">[SWS_CORE_01664]</a> neu konstruiert werden.</li>
<li><strong>Zustandsprüfung:</strong> Abfrage des aktiven Typindex über <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a> sowie Absicherung gegen vorherige Fehler über <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>.</li>
<li><strong>Objekttausch:</strong> Effizienter Austausch zweier Variant-Instanzen über die Elementfunktion <code>swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a>.</li>
</ul>
<p>Da das vorliegende Spezifikations-Record-Set ausschließlich Elementfunktionen umfasst, fehlen direkte Leseoperationen wie ein Wertzugriff; vermutlich werden Zugriffs- und Besuchsfunktionen (analog zu <code>std::get</code> oder <code>std::visit</code>) als freie Hilfsfunktionen im Namensraum <code>ara::core</code> bereitgestellt.</p>

<h4>Fehlerszenarien</h4>
<p>Im Zentrum der Fehlerbehandlung steht die Eigenschaft der bedingten Ausnahmesicherheit (<em>conditionally exception safe</em>). Während die Standardbibliothek für <code>std::variant</code> feste Noexcept-Regeln vorsieht, weicht AUTOSAR gezielt ab: Sämtliche Konstruktoren <a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, Zuweisungsoperatoren <a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>, <code>emplace</code>-Operationen <a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>, die Tauschfunktion <code>swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a> sowie der Destruktor <a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a> sind bedingt <code>noexcept</code>. Ihre Ausnahmegarantie hängt direkt von den Noexcept-Eigenschaften der zugrundeliegenden Typkonstruktoren ab.</p>
<p>Wirft die Konstruktion eines neuen Wertes während einer Zuweisung oder eines <code>emplace</code>-Aufrufs eine Ausnahme, kann die Variante in einen ungültigen Zwischenzustand geraten. Dieser wird über <code>valueless_by_exception()</code> signalisiert <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>. Ausschließlich die beiden Abfragefunktionen <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a> und <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a> bieten eine uneingeschränkte <code>noexcept</code>-Garantie und sind vollständig ausnahmesicher.</p>
