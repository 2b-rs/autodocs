<h4>Context</h4>
<p>The template class <code>ara::core::Variant</code> provides a type-safe union (sum type) in the <code>core</code> module of the AUTOSAR Adaptive Platform. The implementation is conceptually based on the type <code>std::variant</code> from the C++ standard, but defines platform-specific deviations and clarifications regarding exception handling and the conditions for <code>noexcept</code>. At any given time, a <code>ara::core::Variant</code> either manages exactly one value from the declared type list <code>Types...</code> or is in the valueless state as a result of an error.</p>
<p>Typical interaction partners are functional Adaptive Applications and service interfaces that pass polymorphic data structures in a type-safe manner without dynamic memory allocation or inheritance hierarchies. Inclusion is performed via the header file <code>ara/core/variant.h</code>, as specified in the associated specification requirements such as <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a>.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::core::Variant</code> is divided into the phases of creation, state transformation, error state, and destruction:</p>
<ul>
<li><strong>Default construction:</strong> The parameterless default constructor <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a> initializes the instance with the first alternative (index 0), provided that it is default-constructible. Execution is <code>constexpr</code> and conditionally <code>noexcept</code>.</li>
<li><strong>Value and move construction:</strong> An instance can be instantiated by taking a value <a class="spec-record-ref" data-req="SWS_CORE_01652" href="../spec/record.html?id=SWS_CORE_01652">[SWS_CORE_01652]</a>, via the copy constructor <a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>, or via the move constructor <a class="spec-record-ref" data-req="SWS_CORE_01651" href="../spec/record.html?id=SWS_CORE_01651">[SWS_CORE_01651]</a>. All three operations are subject to specific <code>noexcept</code> conditions.</li>
<li><strong>In-place construction:</strong> To avoid temporary copies, constructors with placeholder tags are available: type-based via <code>in_place_type_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01654" href="../spec/record.html?id=SWS_CORE_01654">[SWS_CORE_01654]</a>) or index-based via <code>in_place_index_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01655" href="../spec/record.html?id=SWS_CORE_01655">[SWS_CORE_01655]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01656" href="../spec/record.html?id=SWS_CORE_01656">[SWS_CORE_01656]</a>). These constructors are declared as <code>explicit</code> and <code>constexpr</code>.</li>
<li><strong>Value modification and state transition:</strong> During the usage phase, the contained value can be replaced via assignment operators (<a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01659" href="../spec/record.html?id=SWS_CORE_01659">[SWS_CORE_01659]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01660" href="../spec/record.html?id=SWS_CORE_01660">[SWS_CORE_01660]</a>), via type-based <code>emplace</code> methods (<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01662" href="../spec/record.html?id=SWS_CORE_01662">[SWS_CORE_01662]</a>), via index-based <code>emplace</code> methods (<a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01664" href="../spec/record.html?id=SWS_CORE_01664">[SWS_CORE_01664]</a>), or by <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a>.</li>
<li><strong>Destruction:</strong> The destructor <a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a> destroys the currently active alternative. It is conditionally declared <code>noexcept</code>.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical usage path includes in-place initialization, querying the active type, and changing the held alternative:</p>
<ol>
<li><strong>Initialization:</strong> The object is specifically initialized with an alternative, for example via <code>in_place_type_t</code> according to <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, in order to forward arguments directly to the constructor of the target type.</li>
<li><strong>Status check:</strong> Before access, the application checks the zero-based index of the currently held alternative via the method <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a>. In addition, <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a> can be used to verify whether the instance is in an intact state.</li>
<li><strong>Reassignment:</strong> If an alternative type is to be placed in the same memory area, <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a> or <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>) is called. This destroys the previous alternative and creates the new value directly in place.</li>
<li><strong>Destruction:</strong> When leaving the scope, the destructor <a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a> is called, which properly cleans up the active alternative.</li>
</ol>

<h4>Error Scenarios</h4>
<p>In the area of error scenarios and exception handling, <code>ara::core::Variant</code> is characterized by the following properties:</p>
<ul>
<li><strong>valueless_by_exception state:</strong> If during a value assignment (<a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01659" href="../spec/record.html?id=SWS_CORE_01659">[SWS_CORE_01659]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01660" href="../spec/record.html?id=SWS_CORE_01660">[SWS_CORE_01660]</a>) or a re-initialization via <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>) the constructor of the new alternative throws an exception and the old alternative has already been destroyed, the object remains in the state without a value. This state is queried via <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>. In this state, <code>index()</code> returns the value <code>variant_npos</code>. Recovery is only possible through another successful assignment or <code>emplace</code>.</li>
<li><strong>Conditional noexcept guarantees:</strong> Almost all constructing and modifying methods (e.g., <a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>) have the status <em>conditionally exception safe</em> and are provided with conditional <code>noexcept</code> clauses (for example, based on <code>std::is_nothrow_constructible</code>). They guarantee freedom from exceptions exclusively when the involved operations of the user types themselves are <code>noexcept</code>.</li>
<li><strong>Unrestricted guarantees:</strong> The query methods <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a> and <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a> are unconditionally declared as <code>noexcept</code> and offer unrestricted exception safety (<em>exception safe</em>).</li>
<li><strong>Swap modifications:</strong> For <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a>, the conditions for exception safety are modified compared to the standard to ensure controlled handling in AUTOSAR environments.</li>
