<h4>Kontext</h4>
<p>Die Datenstruktur <code>ara::diag::DTCInformation::UdsDtcStatusByteType</code> definiert im Modul <code>diag</code> der AUTOSAR Adaptive Platform die Repräsentation des UDS-DTC-Statusbytes <a class="spec-record-ref" data-req="SWS_DM_00659" href="../spec/record.html?id=SWS_DM_00659">[SWS_DM_00659]</a>. Als geschachtelter Typ innerhalb des Gültigkeitsbereichs von <code>ara::diag::DTCInformation</code> dient die Struktur der Kapselung von Diagnosezuständen eines Diagnostic Trouble Code (DTC) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=675">SWS Diagnostics §8.48.6 „Struct: UdsDtcStatusByteType“</a>. Die Struktur fungiert als Schnittstelle für Diagnoseanwendungen und interne Diagnosekomponenten, um Statusinformationen feingranular auszuwerten. Durch vordefinierte Abfragefunktionen abstrahiert sie von manuellen Bitmaskierungen und stellt typsichere Prüfoperationen bereit. Die Deklaration ist über den Header <code>#include "ara/diag/dtc_information.h"</code> verfügbar <a class="spec-record-ref" data-req="SWS_DM_02080" href="../spec/record.html?id=SWS_DM_02080">[SWS_DM_02080]</a>. In einer typischen Systemarchitektur dürfte das Statusbyte als strukturierter Informationsträger bei Diagnoseabfragen aus der übergeordneten Diagnoseverwaltung empfangen werden.</p>

<h4>Lebenszyklus</h4>
<p>Als leichtgewichtiger Wertetyp unterliegt <code>UdsDtcStatusByteType</code> einem deterministischen Lebenszyklus ohne dynamische Ressourcenverwaltung. Die Neuerzeugung erfolgt über den variadischen Konstruktor <code>UdsDtcStatusByteType(bits...)</code>, welcher die übergebenen Statusbits unmittelbar im Statusbyte setzt <a class="spec-record-ref" data-req="SWS_DM_02084" href="../spec/record.html?id=SWS_DM_02084">[SWS_DM_02084]</a>. Zusätzlich existieren standardmäßige Kopier- und Verschiebeoperationen: Der Kopierkonstruktor ist als <code>default</code> definiert <a class="spec-record-ref" data-req="SWS_DM_02085" href="../spec/record.html?id=SWS_DM_02085">[SWS_DM_02085]</a>, ergänzt durch einen Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_02086" href="../spec/record.html?id=SWS_DM_02086">[SWS_DM_02086]</a> sowie entsprechende Zuweisungsoperatoren für Kopier- und Move-Semantik <a class="spec-record-ref" data-req="SWS_DM_02087" href="../spec/record.html?id=SWS_DM_02087">[SWS_DM_02087]</a> <a class="spec-record-ref" data-req="SWS_DM_02088" href="../spec/record.html?id=SWS_DM_02088">[SWS_DM_02088]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit differenziert die Spezifikation klar zwischen Erzeugung und Nutzung: Der parameterisierte Konstruktor sowie der Move-Konstruktor sind explizit als threadsicher (<code>thread-safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_02084" href="../spec/record.html?id=SWS_DM_02084">[SWS_DM_02084]</a> <a class="spec-record-ref" data-req="SWS_DM_02086" href="../spec/record.html?id=SWS_DM_02086">[SWS_DM_02086]</a>. Dagegen gelten die Zuweisungsoperatoren und alle abfragenden Elementfunktionen als nicht threadsicher (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_02080" href="../spec/record.html?id=SWS_DM_02080">[SWS_DM_02080]</a> <a class="spec-record-ref" data-req="SWS_DM_02087" href="../spec/record.html?id=SWS_DM_02087">[SWS_DM_02087]</a>. Ein nebenläufiger Lese- oder Schreibzugriff auf dieselbe Instanz bedarf daher externer Schutzmechanismen. Da sämtliche Funktionen als <code>constexpr</code> und <code>noexcept</code> deklariert sind, können Instanzen bereits zur Übersetzungszeit konstruiert und ausgewertet werden.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Bereitstellung des Objekts gefolgt von der Abfrage konkreter Diagnosezustände. Die Initialisierung erfolgt entweder durch explizite Angabe der gesetzten Bits oder durch Übernahme einer bestehenden Statusinstanz <a class="spec-record-ref" data-req="SWS_DM_02084" href="../spec/record.html?id=SWS_DM_02084">[SWS_DM_02084]</a>. Die Template-Parameter für Statusbits dürften dabei symbolische Bitdefinitionen des UDS-Standards aufnehmen.</p>
<p>Zur Auswertung einzelner oder mehrerer Bits dienen die variadischen Methoden <code>IsSet(bits...)</code> und <code>IsNotSet(bits...)</code>, welche prüfen, ob die angegebenen Bits gesetzt bzw. nicht gesetzt sind <a class="spec-record-ref" data-req="SWS_DM_02082" href="../spec/record.html?id=SWS_DM_02082">[SWS_DM_02082]</a> <a class="spec-record-ref" data-req="SWS_DM_02083" href="../spec/record.html?id=SWS_DM_02083">[SWS_DM_02083]</a>. Ergänzend stehen spezialisierte Hilfsmethoden für standardisierte UDS-Zustandskombinationen bereit: <code>IsFailedAndTested()</code> prüft, ob das DTC den Zustand „Failed“ und gleichzeitig „Tested“ aufweist <a class="spec-record-ref" data-req="SWS_DM_02080" href="../spec/record.html?id=SWS_DM_02080">[SWS_DM_02080]</a>, während <code>IsPassedAndTested()</code> den erfolgreichen Abschluss ohne Fehler verifiziert <a class="spec-record-ref" data-req="SWS_DM_02081" href="../spec/record.html?id=SWS_DM_02081">[SWS_DM_02081]</a>.</p>
