<h4>Context</h4>
<p>Struct <code>ara::diag::DTCInformation::SnapshotDataRecordType</code> is a central data type of the diagnostic module (<code>diag</code>) in the AUTOSAR Adaptive Platform in release R25-11 <a class="spec-record-ref" data-req="SWS_DM_00661" href="../spec/record.html?id=SWS_DM_00661">[SWS_DM_00661]</a>. It is defined as an embedded data structure in the scope of interface class <code>ara::diag::DTCInformation</code> and is available via header file <code>ara/diag/dtc_information.h</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=672">AUTOSAR_AP_SWS_Diagnostics §8.48.4 “Struct: SnapshotDataRecordType”</a>. The primary role of this type is to encapsulate snapshot data (freeze frame records) captured by the diagnostic system when a Diagnostic Trouble Code (DTC) occurs and is stored.</p>
<p>Technically, <code>SnapshotDataRecordType</code> represents the data structure for snapshot records in accordance with diagnostic requirements <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=1109">AUTOSAR_AP_SWS_Diagnostics §p. 1109</a>. Each snapshot record represents a specific set of environmental conditions and measured values at the time of fault occurrence. For this purpose, the structure contains two essential attributes:</p>
<ul>
<li><code>snapshotRecordNumber</code>: An integer identifier of type <code>std::uint8_t</code> defining a unique record number for a snapshot entry <a class="spec-record-ref" data-req="SWS_DM_02114" href="../spec/record.html?id=SWS_DM_02114">[SWS_DM_02114]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=673">AUTOSAR_AP_SWS_Diagnostics §8.48.4.1.2 “snapshotRecordNumber”</a>.</li>
<li><code>snapshotDataIdentifiers</code>: A vector of type <code>ara::core::Vector&lt;SnapshotDataIdentifierType&gt;</code> containing the list of captured Diagnostic Data Identifiers (Data Identifiers, DIDs) and their associated payload <a class="spec-record-ref" data-req="SWS_DM_02115" href="../spec/record.html?id=SWS_DM_02115">[SWS_DM_02115]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=672">AUTOSAR_AP_SWS_Diagnostics §8.48.4.1.1 “snapshotDataIdentifiers”</a>.</li>
</ul>
<p>Interaction partners of this data structure are typically the diagnostic management of the Adaptive Platform as well as diagnostic applications evaluating detailed state and fault contexts via <code>DTCInformation</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=75">AUTOSAR_AP_SWS_Diagnostics §p. 75</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=83">AUTOSAR_AP_SWS_Diagnostics §p. 83</a>.</p>

<h4>Lifecycle</h4>
<p>As a pure value type (<code>struct</code>) without its own virtual methods or complex state machines, <code>ara::diag::DTCInformation::SnapshotDataRecordType</code> is subject to the regular value and RAII semantics of modern C++ <a class="spec-record-ref" data-req="SWS_DM_00661" href="../spec/record.html?id=SWS_DM_00661">[SWS_DM_00661]</a>. Instantiation is generally carried out by the runtime environment of the diagnostic subsystem when stored snapshot entries are read from the fault memory and converted into adaptive data types.</p>
<p>Regarding ownership, the instance fully owns all data stored within it. Through the use of <code>ara::core::Vector</code> for the identifiers <a class="spec-record-ref" data-req="SWS_DM_02115" href="../spec/record.html?id=SWS_DM_02115">[SWS_DM_02115]</a>, the object manages its dynamic memory area independently. Copy and move operations follow the standard behavior of the container and the primitive data type <code>std::uint8_t</code> <a class="spec-record-ref" data-req="SWS_DM_02114" href="../spec/record.html?id=SWS_DM_02114">[SWS_DM_02114]</a>. <p>The structure defines no internal synchronization mechanisms for concurrent access. Concurrent reading by multiple threads is thread-safe as long as no competing write accesses take place. Modifications to an instance must be synchronized externally by calling application layers if needed.</p>

<h4>Usage Path</h4>
<p>Typical deployment of <code>SnapshotDataRecordType</code> occurs in the context of diagnostic queries of fault memory data. A diagnostic application interacts with the query functions of <code>DTCInformation</code> to determine detailed fault causes and accompanying circumstances.</p>
<ol>
<li><strong>Querying snapshots:</strong> The application initiates a query of snapshot records for a specific fault code via the diagnostic interface. Interpretation: The diagnostic system then generates a collection of <code>SnapshotDataRecordType</code> instances as a result.</li>
<li><strong>Identifying the record:</strong> The caller evaluates the record number <code>snapshotRecordNumber</code> from <a class="spec-record-ref" data-req="SWS_DM_02114" href="../spec/record.html?id=SWS_DM_02114">[SWS_DM_02114]</a> to determine the context of the snapshot (for example, whether it is the first occurring fault or the most recent occurrence).</li>
<li><strong>Reading diagnostic identifiers:</strong> By iterating over vector <code>snapshotDataIdentifiers</code>, the application accesses the individual <code>SnapshotDataIdentifierType</code> elements <a class="spec-record-ref" data-req="SWS_DM_02115" href="../spec/record.html?id=SWS_DM_02115">[SWS_DM_02115]</a>. In doing so, stored measured variables such as speeds, temperatures, supply voltages, or timestamps are read.</li>
<li><strong>Processing and forwarding:</strong> The extracted values are either evaluated internally in the ECU or transmitted via downstream UDS diagnostic services to an external diagnostic tester tool.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Since <code>SnapshotDataRecordType</code> is designed as a passive data container <a class="spec-record-ref" data-req="SWS_DM_00661" href="../spec/record.html?id=SWS_DM_00661">[SWS_DM_00661]</a>, the structure itself does not raise any specific exception handling or error codes. Nevertheless, various error situations can occur in practical application that must be taken into account during processing:</p>
<ul>
<li><strong>Empty record list:</strong> If no environmental data was configured for a DTC or no measured values were available at the time of triggering, vector <code>snapshotDataIdentifiers</code> is likely empty (<a class="spec-record-ref" data-req="SWS_DM_02115" href="../spec/record.html?id=SWS_DM_02115">[SWS_DM_02115]</a>). Calling code must check whether the vector contains values before accessing elements.</li>
<li><strong>Invalid or unexpected record number:</strong> If the received <code>snapshotRecordNumber</code> does not match the expected values, this presumably indicates a differing configuration of the diagnostic memory <a class="spec-record-ref" data-req="SWS_DM_02114" href="../spec/record.html?id=SWS_DM_02114">[SWS_DM_02114]</a>.</li>
<li><strong>Memory bottlenecks during allocation:</strong> Because container <code>ara::core::Vector</code> claims dynamic memory for the DIDs, memory allocations can fail in resource-constrained systems, which must be intercepted by the surrounding runtime environment.</li>
</ul>
