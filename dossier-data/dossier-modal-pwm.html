<h4>Role of the PWM driver between timer hardware and IoHwAb</h4>
<p>The PWM driver belongs to the MCAL. It accesses the microcontroller registers directly and therefore requires no underlying interfaces (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces">PWM-SWS p. 44</a>). As a module of the lowest layer, it offers no callbacks for lower modules (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_4_Callback_notifications.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_4_Callback_notifications">PWM-SWS p. 40</a>). Likewise, it does not provide service interfaces (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_Service_Interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_Service_Interfaces">PWM-SWS p. 44</a>). It offers its services via <code>Pwm.h</code>, for example <code>Pwm_Init</code> <a class="spec-record-ref" data-req="SWS_Pwm_00095" href="../../spec/record.html?id=SWS_Pwm_00095">[SWS_Pwm_00095]</a>. It obtains the standard types from <code>Std_Types.h</code> <a class="spec-record-ref" data-req="SWS_Pwm_00094" href="../../spec/record.html?id=SWS_Pwm_00094">[SWS_Pwm_00094]</a>. The file structure is shown in the header diagram (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-47b7196afd92a1b0.html" data-snip="FIG-47b7196afd92a1b0">PWM-SWS p. 12</a>).</p>
<p>Typical users include a power stage driver of the I/O Hardware Abstraction. It sets voltages and frequencies via the PWM driver and makes these outputs visible to software components via signal abstraction (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_FIGURE_Figure_7_7.html" data-snip="SNIP_CLASSIC_PWM_FIGURE_Figure_7_7">IoHwAb-SWS p. 37</a>). The ECU State Manager lists <code>Pwm_Init</code> among its optional interfaces (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces">EcuM-SWS p. 152</a>). Upwards, the driver calls only three types of services:</p>
<ul>
<li>configured channel callbacks <code>Pwm_Notification_&lt;#Channel&gt;</code> <a class="spec-record-ref" data-req="SWS_Pwm_00105" href="../../spec/record.html?id=SWS_Pwm_00105">[SWS_Pwm_00105]</a>,</li>
<li><code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_Pwm_00104" href="../../spec/record.html?id=SWS_Pwm_00104">[SWS_Pwm_00104]</a>,</li>
<li>ready notifications to the IoHwAb <a class="spec-record-ref" data-req="SWS_Pwm_00198" href="../../spec/record.html?id=SWS_Pwm_00198">[SWS_Pwm_00198]</a>.</li>
</ul>
<p>Differences between the channels of a microcontroller are not abstracted via vendor API infixes, but via the passed channel number (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_FIGURE_Figure_7_2.html" data-snip="SNIP_CLASSIC_PWM_FIGURE_Figure_7_2">BSWMDT p. 122</a>). A release difference must be noted: The R24-11 version lists <code>Det_ReportRuntimeError</code> as a mandatory interface (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces">PWM-SWS p. 44</a>). For R20-11, the payload only substantiates <code>Det_ReportError</code> as an optional interface <a class="spec-record-ref" data-req="SWS_Pwm_00104" href="../../spec/record.html?id=SWS_Pwm_00104">[SWS_Pwm_00104]</a>. The runtime error itself is defined in R20-11 <a class="spec-record-ref" data-req="SWS_Pwm_00202" href="../../spec/record.html?id=SWS_Pwm_00202">[SWS_Pwm_00202]</a>.</p>

<h4>Channel model: polarity, period, duty cycle, and channel class</h4>
<p>A channel is addressed via the numeric identifier <code>Pwm_ChannelType</code> <a class="spec-record-ref" data-req="SWS_Pwm_00106" href="../../spec/record.html?id=SWS_Pwm_00106">[SWS_Pwm_00106]</a>. The period has the type <code>Pwm_PeriodType</code>, which is chosen efficiently with 8 to 32 bits depending on the platform <a class="spec-record-ref" data-req="SWS_Pwm_00107" href="../../spec/record.html?id=SWS_Pwm_00107">[SWS_Pwm_00107]</a>. The basic terms are defined in the glossary (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_2_Acronyms_and_abbreviations~fffffc000000.html" data-snip="SNIP_CLASSIC_PWM_SECTION_2_Acronyms_and_abbreviations">PWM-SWS p. 9</a>):</p>
<ul>
<li>The <strong>polarity</strong> determines the level at the start of the period.</li>
<li>The <strong>duty cycle</strong> specifies the proportion of this starting level in the period.</li>
<li>The <strong>idle state</strong> is the level after <code>Pwm_SetOutputToIdle</code> or <code>Pwm_DeInit</code>.</li>
</ul>
<p>The signal description in the specification shows this for <code>PWM_HIGH</code> and <code>PWM_LOW</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-dd99542ceb7058f4.html" data-snip="FIG-dd99542ceb7058f4">PWM-SWS p. 7</a>).</p>
<p>The duty cycle is 16 bits wide: <code>0x0000</code> stands for 0%, <code>0x8000</code> for 100%. As the conversion, the specification recommends <code>AbsoluteDutyCycle = ((uint32)AbsolutePeriodTime * RelativeDutyCycle) &gt;&gt; 15</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling">PWM-SWS p. 18</a>). The services limit the parameter accordingly to Min=0x0000 and Max=0x8000 <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a> <a class="spec-record-ref" data-req="SWS_Pwm_91001" href="../../spec/record.html?id=SWS_Pwm_91001">[SWS_Pwm_91001]</a>.</p>
<p>The channel class <code>Pwm_ChannelClassType</code> defines what can be changed at runtime <a class="spec-record-ref" data-req="SWS_Pwm_00110" href="../../spec/record.html?id=SWS_Pwm_00110">[SWS_Pwm_00110]</a>:</p>
<ul>
<li><code>PWM_VARIABLE_PERIOD</code>: period and duty cycle,</li>
<li><code>PWM_FIXED_PERIOD</code>: only the duty cycle,</li>
<li><code>PWM_FIXED_PERIOD_SHIFTED</code>: a fixed, phase-shifted period, provided that the hardware supports this.</li>
</ul>
<p>The diagram for the shifted period shows channels with the same period and offset starting edges (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-7047bb635bd81ab1.html" data-snip="FIG-7047bb635bd81ab1">PWM-SWS p. 23</a>). The class is configured per channel via <code>PwmChannelClass</code> in container <code>PwmChannel</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_10_2_4_PwmChannel.html" data-snip="SNIP_CLASSIC_PWM_SECTION_10_2_4_PwmChannel">PWM-SWS p. 57</a>).</p>
<p>Mandatory parameters of a channel are (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType">PWM-SWS p. 25</a>):</p>
<ul>
<li>the assigned hardware channel,</li>
<li>the default period and the default duty cycle,</li>
<li>the polarity and the idle level,</li>
<li>the channel class.</li>
</ul>
<p>Phase shift and reference channel are optional. <code>Pwm_ConfigType</code> combines the initialization data; its content is hardware-specific <a class="spec-record-ref" data-req="SWS_Pwm_00111" href="../../spec/record.html?id=SWS_Pwm_00111">[SWS_Pwm_00111]</a>.</p>

<h4>Lifecycle: from Pwm_Init to Pwm_DeInit</h4>
<p><code>Pwm_Init</code> is synchronous, non-reentrant, and receives a pointer to the configuration set <a class="spec-record-ref" data-req="SWS_Pwm_00095" href="../../spec/record.html?id=SWS_Pwm_00095">[SWS_Pwm_00095]</a>. Afterwards, depending on the configuration, the outputs are low, high, or in modulation. Notifications remain disabled until the first <code>Pwm_EnableNotification</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-42d2a53302c293d5.html" data-snip="FIG-42d2a53302c293d5">PWM-SWS p. 46</a>). A second call when the driver is already initialized reports <code>PWM_E_ALREADY_INITIALIZED</code> <a class="spec-record-ref" data-req="SWS_Pwm_50002" href="../../spec/record.html?id=SWS_Pwm_50002">[SWS_Pwm_50002]</a>. <p><code>Pwm_DeInit</code> is also synchronous and non-reentrant <a class="spec-record-ref" data-req="SWS_Pwm_00096" href="../../spec/record.html?id=SWS_Pwm_00096">[SWS_Pwm_00096]</a>. The function de-initializes the module, sets the outputs to the idle state, and disables PWM interrupts as well as edge notifications. <h4>Setting and querying the signal at runtime</h4>
<p><code>Pwm_SetDutyCycle</code> sets the duty cycle of a channel. According to the API table, the service is asynchronous and reentrant for different channels <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a>. At 0% and 100%, the output is set statically: at 0%, it is inverse to the polarity; at 100%, equal to the polarity. In between, the driver modulates according to period, duty cycle, and polarity (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_3_Pwm_SetDutyCycle.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_3_Pwm_SetDutyCycle">PWM-SWS p. 28</a>). The new value is applied at the end of the running period if the implementation supports this, otherwise immediately (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-8cc28a0526026be2.html" data-snip="FIG-8cc28a0526026be2">PWM-SWS p. 37</a>).</p>

<p><code>Pwm_SetPeriodAndDuty</code> sets period and duty cycle together <a class="spec-record-ref" data-req="SWS_Pwm_91001" href="../../spec/record.html?id=SWS_Pwm_91001">[SWS_Pwm_91001]</a>. <h4>Edge notifications per channel</h4>
<p><code>Pwm_EnableNotification</code> enables notification for a channel. The parameter of type <code>Pwm_EdgeNotificationType</code> selects <code>PWM_RISING_EDGE</code>, <code>PWM_FALLING_EDGE</code>, or <code>PWM_BOTH_EDGES</code> <a class="spec-record-ref" data-req="SWS_Pwm_91004" href="../../spec/record.html?id=SWS_Pwm_91004">[SWS_Pwm_91004]</a> <a class="spec-record-ref" data-req="SWS_Pwm_00109" href="../../spec/record.html?id=SWS_Pwm_00109">[SWS_Pwm_00109]</a>. Pending interrupts are discarded in doing so (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_8_Pwm_EnableNotification.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_8_Pwm_EnableNotification">PWM-SWS p. 35</a>). <code>Pwm_DisableNotification</code> disables the notification again <a class="spec-record-ref" data-req="SWS_Pwm_91003" href="../../spec/record.html?id=SWS_Pwm_91003">[SWS_Pwm_91003]</a>. Both services are only available when <code>PwmNotificationSupported</code> is enabled (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_7_Pwm_DisableNotification.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_7_Pwm_DisableNotification">PWM-SWS p. 34</a>).</p>
<p>The driver calls callback <code>Pwm_Notification_&lt;#Channel&gt;</code> according to the latest enable or disable call of the channel. It is declared in <code>Pwm_Externals.h</code>; its reentrancy depends on the user implementation <a class="spec-record-ref" data-req="SWS_Pwm_00105" href="../../spec/record.html?id=SWS_Pwm_00105">[SWS_Pwm_00105]</a>. The driver itself resets the associated interrupt flag (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_3_Configurable_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_3_Configurable_interfaces">PWM-SWS p. 42</a>). The diagram shows the sequence (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_9_7_Using_the_PWM_notifications.html" data-snip="SNIP_CLASSIC_PWM_SECTION_9_7_Using_the_PWM_notifications">PWM-SWS p. 48</a>):</p>
<ol>
<li>After <code>Pwm_Init</code>, the channel modulates without notifying.</li>
<li>After the enable, callbacks follow at the selected edges.</li>
<li>After the disable, no more callbacks occur.</li>
</ol>

<h4>Optional power states and Power Transition Manager</h4>
<p>Power state control is optional. Its services are only generated if <code>PwmLowPowerStatesSupport</code> is set (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_3_2_Requirements.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_3_2_Requirements">PWM-SWS p. 16</a>). The driver only takes care of the PWM peripherals. The remaining boundary conditions must already have been fulfilled by the application, mode management, and IoHwAb; however, the driver itself checks the call sequence (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_3_1_Background.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_3_1_Background">PWM-SWS p. 17</a>). <code>Pwm_PowerStateType</code> provides <code>PWM_FULL_POWER</code> (0x00) and the values 1..255 for states with decreasing consumption <a class="spec-record-ref" data-req="SWS_Pwm_00197" href="../../spec/record.html?id=SWS_Pwm_00197">[SWS_Pwm_00197]</a>. In R20-11, the type is an enumeration; later versions derive it from <code>uint8</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType">PWM-SWS p. 25</a>).</p>
<p>A state transition proceeds in three steps:</p>
<ol>
<li><code>Pwm_PreparePowerState</code> starts preparation for the target state <a class="spec-record-ref" data-req="SWS_Pwm_00183" href="../../spec/record.html?id=SWS_Pwm_00183">[SWS_Pwm_00183]</a>.</li>
<li>The cyclically called <code>Pwm_Main_PowerTransitionManager</code> carries out the steps that cannot be completed immediately <a class="spec-record-ref" data-req="SWS_Pwm_00189" href="../../spec/record.html?id=SWS_Pwm_00189">[SWS_Pwm_00189]</a> <a class="spec-record-ref" data-req="SWS_Pwm_00190" href="../../spec/record.html?id=SWS_Pwm_00190">[SWS_Pwm_00190]</a>. Once preparation is finished, it calls <code>IoHwAb_Pwm_NotifyReadyForPowerState&lt;#Mode&gt;</code> <a class="spec-record-ref" data-req="SWS_Pwm_00198" href="../../spec/record.html?id=SWS_Pwm_00198">[SWS_Pwm_00198]</a>. This ready notification only exists in asynchronous mode. Before initialization, the function returns without a DET report (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_5_1_Pwm_Main_PowerTransitionManager.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_5_1_Pwm_Main_PowerTransitionManager">PWM-SWS p. 41</a>).</li>
<li><code>Pwm_SetPowerState</code> sets the hardware to the prepared state <a class="spec-record-ref" data-req="SWS_Pwm_00166" href="../../spec/record.html?id=SWS_Pwm_00166">[SWS_Pwm_00166]</a>. Before this, the responsible SWCs, such as the IoHwAb, must have set the channels to idle and deregistered notifications. The driver does not pass through intermediate states implicitly (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_9_Pwm_SetPowerState.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_9_Pwm_SetPowerState">PWM-SWS p. 36</a>).</li>
</ol>
<p><code>Pwm_GetCurrentPowerState</code> returns the current state <a class="spec-record-ref" data-req="SWS_Pwm_00177" href="../../spec/record.html?id=SWS_Pwm_00177">[SWS_Pwm_00177]</a>, <code>Pwm_GetTargetPowerState</code> the requested state <a class="spec-record-ref" data-req="SWS_Pwm_00180" href="../../spec/record.html?id=SWS_Pwm_00180">[SWS_Pwm_00180]</a>. If no transition is in progress, both match (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_11_Pwm_GetTargetPowerState.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_11_Pwm_GetTargetPowerState">PWM-SWS p. 38</a>). In synchronous operation, preparation is complete as soon as the prepare call returns (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-159e4a185665089b.html" data-snip="FIG-159e4a185665089b">IoHwAb-SWS p. 61</a>). In asynchronous operation, it continues running in the background (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-7d9b529a545f1032.html" data-snip="FIG-7d9b529a545f1032">IoHwAb-SWS p. 60</a>).</p>
