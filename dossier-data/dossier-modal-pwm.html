<p class="ai-level ai-oneliner-lead" data-ai-level="1">Steuert pulsweitenmodulierte Ausgänge der Mikrocontroller-Hardware kanalweise über Periode und Tastgrad.</p>
<div class="ai-level" data-ai-level="2">
<p>Der PWM-Treiber steuert als MCAL-Modul die pulsweitenmodulierten Ausgänge des Mikrocontrollers kanalweise und greift dafür direkt auf dessen Register zu. Nach <code>Pwm_Init</code> setzen Pwm User Tastgrad und, bei Kanälen mit variabler Periode, auch die Periode. Sie können Ausgänge in den Idle-Zustand schalten und Flankenbenachrichtigungen ein- oder ausschalten <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a>. Optional verwaltet der Treiber zweiphasige Wechsel des Leistungszustands über Vorbereiten und Setzen. Fehler wie fehlende Initialisierung oder ungültige Kanäle meldet er bei aktiver Fehlererkennung und führt dann nichts aus <a class="spec-record-ref" data-req="SWS_Pwm_00201" href="../../spec/record.html?id=SWS_Pwm_00201">[SWS_Pwm_00201]</a>.</p>

<div class="ai-level" data-ai-level="3">
<p>Der PWM-Treiber ist ein MCAL-Modul und steuert die pulsweitenmodulierten Ausgänge des Mikrocontrollers über dessen Register. Schnittstellen tieferer Module braucht er deshalb nicht (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces">SWS PWM Driver S. 44</a>). Initialisiert wird er synchron mit <code>Pwm_Init</code> und einem Zeiger auf das Konfigurationsset <a class="spec-record-ref" data-req="SWS_Pwm_00095" href="../../spec/record.html?id=SWS_Pwm_00095">[SWS_Pwm_00095]</a>, das der ECU State Manager als optionale Initialisierungsschnittstelle aufruft (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces">SWS EcuM S. 152</a>). Genutzt wird er typischerweise von der IoHwAb, etwa durch einen Power-Stage-Treiber (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_FIGURE_Figure_7_7.html" data-snip="SNIP_CLASSIC_PWM_FIGURE_Figure_7_7">SWS IoHwAb S. 37</a>).</p>

<p>Gesteuert wird über einen 16-Bit-Tastgrad, bei dem <code>0x8000</code> für 100 % steht (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling">SWS PWM Driver S. 18</a>). <ul>
<li><code>Pwm_SetDutyCycle</code> ändert den Tastgrad <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a>. Bei 0 % und 100 % setzt es abhängig von der Polarität einen statischen Pegel.</li>
<li><code>Pwm_SetPeriodAndDuty</code> ändert zusätzlich die Periode, aber nur bei Kanälen der Klasse <code>PWM_VARIABLE_PERIOD</code> <a class="spec-record-ref" data-req="SWS_Pwm_00110" href="../../spec/record.html?id=SWS_Pwm_00110">[SWS_Pwm_00110]</a>.</li>
<li><code>Pwm_SetOutputToIdle</code> schaltet sofort auf den Idle-Pegel <a class="spec-record-ref" data-req="SWS_Pwm_91002" href="../../spec/record.html?id=SWS_Pwm_91002">[SWS_Pwm_91002]</a>.</li>
<li><code>Pwm_GetOutputState</code> liest den internen Pegel <a class="spec-record-ref" data-req="SWS_Pwm_00100" href="../../spec/record.html?id=SWS_Pwm_00100">[SWS_Pwm_00100]</a>.</li>
</ul>

<h4>Rolle im MCAL: Treiber zwischen PWM-Einheit und Pwm User</h4>
<p>Der PWM-Treiber kapselt die pulsweitenmodulierten Ausgänge des Mikrocontrollers. Als Modul der MCAL-Schicht greift er direkt auf die Register des Mikrocontrollers zu und benötigt deshalb keine Schnittstellen tieferliegender Module (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_1_Mandatory_interfaces">SWS PWM Driver S. 44</a>). Aus demselben Grund stellt er keine Callbacks für untere Schichten bereit (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_4_Callback_notifications.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_4_Callback_notifications">SWS PWM Driver S. 40</a>) und bietet auch keine Service-Interfaces an (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_Service_Interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_Service_Interfaces">SWS PWM Driver S. 44</a>). Seine Dienste sind über <code>Pwm.h</code> verfügbar, etwa <code>Pwm_Init</code> <a class="spec-record-ref" data-req="SWS_Pwm_00095" href="../../spec/record.html?id=SWS_Pwm_00095">[SWS_Pwm_00095]</a>, <code>Pwm_SetDutyCycle</code> <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a> und <code>Pwm_GetOutputState</code> <a class="spec-record-ref" data-req="SWS_Pwm_00100" href="../../spec/record.html?id=SWS_Pwm_00100">[SWS_Pwm_00100]</a>. Die Standardtypen <code>Std_ReturnType</code> und <code>Std_VersionInfoType</code> importiert er aus <code>Std_Types.h</code> <a class="spec-record-ref" data-req="SWS_Pwm_00094" href="../../spec/record.html?id=SWS_Pwm_00094">[SWS_Pwm_00094]</a>.</p>
<p>Der ECU State Manager führt <code>Pwm_Init</code> unter seinen optionalen Initialisierungsschnittstellen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_1_Optional_Interfaces">SWS EcuM S. 152</a>). Im Anwendungsfall einer Leistungsendstufe ruft ein Power-Stage-Treiber der IoHwAb Dienste von PWM, DIO und SPI auf und stellt damit unter anderem Spannungen und Frequenzen ein (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_FIGURE_Figure_7_7.html" data-snip="SNIP_CLASSIC_PWM_FIGURE_Figure_7_7">SWS IoHwAb S. 37</a>). In Gegenrichtung ruft der Treiber zwei Arten von Funktionen auf: die kanalspezifischen Benachrichtigungen <code>Pwm_Notification_&lt;#Channel&gt;</code> <a class="spec-record-ref" data-req="SWS_Pwm_00105" href="../../spec/record.html?id=SWS_Pwm_00105">[SWS_Pwm_00105]</a> und, im Leistungsmanagement, <code>IoHwAb_Pwm_NotifyReadyForPowerState&lt;#Mode&gt;</code> <a class="spec-record-ref" data-req="SWS_Pwm_00198" href="../../spec/record.html?id=SWS_Pwm_00198">[SWS_Pwm_00198]</a>. Entwicklungsfehler meldet er optional über <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_Pwm_00104" href="../../spec/record.html?id=SWS_Pwm_00104">[SWS_Pwm_00104]</a>. Bietet die Hardware für verschiedene Kanäle unterschiedliche Mechanismen, wird das nicht über herstellerspezifische API-Infixe abstrahiert, sondern über die Kanalnummer (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_FIGURE_Figure_6_2.html" data-snip="SNIP_CLASSIC_PWM_FIGURE_Figure_6_2">TPS BSWMDT S. 122</a>).</p>

<h4>Signalmodell: Periode, Tastgrad, Polarität und Kanalklassen</h4>
<p>Ein Kanal wird über den numerischen Bezeichner <code>Pwm_ChannelType</code> angesprochen <a class="spec-record-ref" data-req="SWS_Pwm_00106" href="../../spec/record.html?id=SWS_Pwm_00106">[SWS_Pwm_00106]</a>. Die Periode ist vom Typ <code>Pwm_PeriodType</code>, einem implementierungsspezifischen Typ mit 8 bis 32 Bit <a class="spec-record-ref" data-req="SWS_Pwm_00107" href="../../spec/record.html?id=SWS_Pwm_00107">[SWS_Pwm_00107]</a>. Drei Begriffe bestimmen das Signal (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_2_Acronyms_and_abbreviations~fffffc000000.html" data-snip="SNIP_CLASSIC_PWM_SECTION_2_Acronyms_and_abbreviations">SWS PWM Driver S. 9</a>):</p>
<ul>
<li>Die Polarität legt den Startpegel jeder Periode fest.</li>
<li>Der Tastgrad gibt den Anteil dieses Startpegels an der Periode an.</li>
<li>Der Idle-Zustand ist der Ausgangszustand nach <code>Pwm_SetOutputToIdle</code> oder <code>Pwm_DeInit</code>.</li>
</ul>
<p>Das Schaubild zur Signalbeschreibung stellt beide Polaritäten <code>PWM_HIGH</code> und <code>PWM_LOW</code> gegenüber (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-dd99542ceb7058f4.html" data-snip="FIG-dd99542ceb7058f4">SWS PWM Driver S. 7</a>).</p>
<p>Der Tastgrad ist ein 16-Bit-Wert. <code>0x0000</code> steht für 0 % und <code>0x8000</code> für 100 %. Als Umsetzungshilfe nennt die Spezifikation <code>AbsoluteDutyCycle = ((uint32)AbsolutePeriodTime * RelativeDutyCycle) &gt;&gt; 15;</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_4_Duty_Cycle_Resolution_and_scaling">SWS PWM Driver S. 18</a>). Entsprechend begrenzen <code>Pwm_SetDutyCycle</code> und <code>Pwm_SetPeriodAndDuty</code> den Parameter <code>DutyCycle</code> auf Min=0x0000 und Max=0x8000 <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a> <a class="spec-record-ref" data-req="SWS_Pwm_91001" href="../../spec/record.html?id=SWS_Pwm_91001">[SWS_Pwm_91001]</a>.</p>
<p>Die Kanalklasse <code>Pwm_ChannelClassType</code> legt fest, was ein Kanal zur Laufzeit ändern darf <a class="spec-record-ref" data-req="SWS_Pwm_00110" href="../../spec/record.html?id=SWS_Pwm_00110">[SWS_Pwm_00110]</a>:</p>
<ul>
<li><code>PWM_VARIABLE_PERIOD</code>: Periode und Tastgrad sind änderbar.</li>
<li><code>PWM_FIXED_PERIOD</code>: Nur der Tastgrad ist änderbar.</li>
<li><code>PWM_FIXED_PERIOD_SHIFTED</code>: Feste, verschobene Periode, die nicht geändert werden kann; nur verfügbar, wenn die Hardware das unterstützt.</li>
</ul>
<p>Das Schaubild zur verschobenen Periode zeigt Kanäle mit gleicher Periode, deren Periodenbeginn jeweils um eine feste Zeit versetzt ist (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-7047bb635bd81ab1.html" data-snip="FIG-7047bb635bd81ab1">SWS PWM Driver S. 23</a>).</p>

<h4>Lebenszyklus und Signalsteuerung: von Pwm_Init bis zum Idle-Zustand</h4>
<p><code>Pwm_Init</code> ist synchron und nicht reentrant. Die Funktion erhält mit <code>ConfigPtr</code> einen Zeiger auf das Konfigurationsset <a class="spec-record-ref" data-req="SWS_Pwm_00095" href="../../spec/record.html?id=SWS_Pwm_00095">[SWS_Pwm_00095]</a>. Dessen Typ <code>Pwm_ConfigType</code> hat hardwarespezifischen Inhalt <a class="spec-record-ref" data-req="SWS_Pwm_00111" href="../../spec/record.html?id=SWS_Pwm_00111">[SWS_Pwm_00111]</a>. Laut Schaubild zur Initialisierung stehen die Ausgänge danach je nach Konfiguration auf Low, auf High oder im Modulationszustand. Benachrichtigungen treten erst nach dem ersten Aufruf von <code>Pwm_EnableNotification</code> auf (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-42d2a53302c293d5.html" data-snip="FIG-42d2a53302c293d5">SWS PWM Driver S. 46</a>). Wird <code>Pwm_Init</code> auf einem bereits initialisierten Treiber erneut aufgerufen, ist der Entwicklungsfehler <code>PWM_E_ALREADY_INITIALIZED</code> zu melden <a class="spec-record-ref" data-req="SWS_Pwm_50002" href="../../spec/record.html?id=SWS_Pwm_50002">[SWS_Pwm_50002]</a>.</p>
<p><code>Pwm_DeInit</code> ist ebenfalls synchron und nicht reentrant <a class="spec-record-ref" data-req="SWS_Pwm_00096" href="../../spec/record.html?id=SWS_Pwm_00096">[SWS_Pwm_00096]</a>. Die Funktion de-initialisiert das Modul, setzt die Ausgänge in den Idle-Zustand und schaltet PWM-Interrupts sowie Flankenbenachrichtigungen ab. Über <code>PwmDeInitApi</code> lässt sie sich ein- und ausschalten (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_2_Pwm_DeInit.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_2_Pwm_DeInit">SWS PWM Driver S. 27</a>). Interpretation: Danach dürfte das Modul wieder als nicht initialisiert gelten, sodass ein erneuter Aufruf von <code>Pwm_Init</code> zulässig ist. <a class="interp-q interp-q-open" data-q="Q-a892974ddbe644e0" data-q-status="open" href="../../versions.html?tab=q&amp;id=Q-a892974ddbe644e0" title="Frage Q-a892974ddbe644e0 (offen): Nach Pwm_DeInit gilt das Modul wieder als nicht initialisiert und kann erneut mit Pwm_Init gestartet werden">Frage Q-a892974ddbe644e0 (offen)</a></p>

<p>Im Betrieb setzt <code>Pwm_SetDutyCycle</code> den Tastgrad eines Kanals <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a>. <li>Bei 0 % ist der Pegel invers zur konfigurierten Polarität.</li>

<li>Bei Werten dazwischen wird gemäß Periode, Tastgrad und Polarität moduliert.</li>
</ul>
<p>Laut Schaubild übernimmt der Treiber den neuen Tastgrad am Ende der laufenden Periode, sofern die Implementierung das unterstützt, sonst sofort (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-8cc28a0526026be2.html" data-snip="FIG-8cc28a0526026be2">SWS PWM Driver S. 37</a>).</p>
<p><code>Pwm_SetPeriodAndDuty</code> setzt Periode und Tastgrad gemeinsam <a class="spec-record-ref" data-req="SWS_Pwm_91001" href="../../spec/record.html?id=SWS_Pwm_91001">[SWS_Pwm_91001]</a>. <ul>
<li>Die Periode wird am Periodenende aktualisiert, wenn die Implementierung das unterstützt und es über <code>PwmPeriodUpdatedEndperiod</code> konfiguriert ist.</li>
<li>Störspitzen am Ausgang sind zu unterdrücken.</li>
<li>Der Tastgrad wird mitgegeben, damit Frequenz und Tastgrad zueinander passen.</li>
</ul>

<h4>Flankenbenachrichtigungen je Kanal</h4>
<p>Mit <code>Pwm_EnableNotification</code> schaltet der Pwm User die Benachrichtigung für einen Kanal ein. Der Parameter vom Typ <code>Pwm_EdgeNotificationType</code> wählt <code>PWM_RISING_EDGE</code>, <code>PWM_FALLING_EDGE</code> oder <code>PWM_BOTH_EDGES</code> <a class="spec-record-ref" data-req="SWS_Pwm_91004" href="../../spec/record.html?id=SWS_Pwm_91004">[SWS_Pwm_91004]</a> <a class="spec-record-ref" data-req="SWS_Pwm_00109" href="../../spec/record.html?id=SWS_Pwm_00109">[SWS_Pwm_00109]</a>. Die Funktion verwirft anstehende Interrupts (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_8_Pwm_EnableNotification.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_8_Pwm_EnableNotification">SWS PWM Driver S. 35</a>). Sie existiert ebenso wie <code>Pwm_DisableNotification</code> <a class="spec-record-ref" data-req="SWS_Pwm_91003" href="../../spec/record.html?id=SWS_Pwm_91003">[SWS_Pwm_91003]</a> nur, wenn <code>PwmNotificationSupported</code> eingeschaltet ist (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_7_Pwm_DisableNotification.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_7_Pwm_DisableNotification">SWS PWM Driver S. 34</a>).</p>
<p>Der Treiber ruft die konfigurierte Funktion <code>Pwm_Notification_&lt;#Channel&gt;</code> entsprechend dem letzten Aufruf von <code>Pwm_EnableNotification</code> bzw. <code>Pwm_DisableNotification</code> auf. Dabei setzt er das zugehörige Interrupt-Flag zurück (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_6_3_Configurable_interfaces.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_6_3_Configurable_interfaces">SWS PWM Driver S. 42</a>). Der Callback hat keine Parameter und wird über <code>Pwm_Externals.h</code> bekannt gemacht. Ob er reentrant ist, hängt von der Implementierung des Pwm User ab <a class="spec-record-ref" data-req="SWS_Pwm_00105" href="../../spec/record.html?id=SWS_Pwm_00105">[SWS_Pwm_00105]</a>.</p>

<h4>Leistungszustände der PWM-Peripherie</h4>
<p>Die Steuerung von Leistungszuständen ist eine optionale Funktion. Sie beschränkt sich auf die PWM-Peripherie und setzt voraus, dass Anwendung, Modusverwaltung und IoHwAb die übergeordneten Randbedingungen bereits erfüllen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_3_1_Background.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_3_1_Background">SWS PWM Driver S. 17</a>). Ist <code>PwmLowPowerStatesSupport</code> aktiv, werden die vier Power-State-APIs erzeugt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_7_3_2_Requirements.html" data-snip="SNIP_CLASSIC_PWM_SECTION_7_3_2_Requirements">SWS PWM Driver S. 16</a>). <code>Pwm_PowerStateType</code> kennt <code>PWM_FULL_POWER</code> (0x00) sowie den Bereich 1..255 für Zustände mit abnehmendem Verbrauch. In R20-11 ist der Typ als Aufzählung definiert <a class="spec-record-ref" data-req="SWS_Pwm_00197" href="../../spec/record.html?id=SWS_Pwm_00197">[SWS_Pwm_00197]</a>. Eine spätere Fassung führt ihn dagegen als von <code>uint8</code> abgeleiteten Typ (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType">SWS PWM Driver S. 25</a>).</p>
<p>Der Wechsel des Leistungszustands läuft in zwei Phasen ab:</p>
<ol>
<li><code>Pwm_PreparePowerState</code> startet die Vorbereitung und liefert im Ergebnisparameter <code>PWM_SERVICE_ACCEPTED</code> oder einen Ablehnungsgrund <a class="spec-record-ref" data-req="SWS_Pwm_00183" href="../../spec/record.html?id=SWS_Pwm_00183">[SWS_Pwm_00183]</a> <a class="spec-record-ref" data-req="SWS_Pwm_00165" href="../../spec/record.html?id=SWS_Pwm_00165">[SWS_Pwm_00165]</a>. Was sich nicht sofort abschließen lässt, erledigt die zyklisch aufgerufene <code>Pwm_Main_PowerTransitionManager</code> <a class="spec-record-ref" data-req="SWS_Pwm_00189" href="../../spec/record.html?id=SWS_Pwm_00189">[SWS_Pwm_00189]</a> <a class="spec-record-ref" data-req="SWS_Pwm_00190" href="../../spec/record.html?id=SWS_Pwm_00190">[SWS_Pwm_00190]</a>. Ihre Aufrufrate ist variabel, und Callbacks verschickt sie nur im asynchronen Modus (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_5_1_Pwm_Main_PowerTransitionManager.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_5_1_Pwm_Main_PowerTransitionManager">SWS PWM Driver S. 41</a>). Die abgeschlossene Vorbereitung meldet der Treiber mit <code>IoHwAb_Pwm_NotifyReadyForPowerState&lt;#Mode&gt;</code> <a class="spec-record-ref" data-req="SWS_Pwm_00198" href="../../spec/record.html?id=SWS_Pwm_00198">[SWS_Pwm_00198]</a>.</li>
<li><code>Pwm_SetPowerState</code> versetzt die Hardware in den vorbereiteten Zustand <a class="spec-record-ref" data-req="SWS_Pwm_00166" href="../../spec/record.html?id=SWS_Pwm_00166">[SWS_Pwm_00166]</a>. Vorleistungen wie das Setzen aller Kanäle auf IDLE und das Abmelden aller Benachrichtigungen müssen die verantwortlichen SWCs, etwa die IoHwAb, bereits erbracht haben. Implizite Zwischenzustände führt die Funktion nicht aus (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_9_Pwm_SetPowerState.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_9_Pwm_SetPowerState">SWS PWM Driver S. 36</a>).</li>
</ol>

<h4>Konfiguration, Kanalcontainer und Nebenläufigkeit</h4>
<p>Pflichtparameter eines Kanals sind der zugeordnete Hardwarekanal, Vorgabewerte für Periode und Tastgrad, Polarität, Idle-Pegel und Kanalklasse. Phasenverschiebung, Referenzkanal und mikrocontrollerspezifische Eigenschaften sind optional, soweit die Hardware sie bietet (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_2_8_Pwm_PowerStateType">SWS PWM Driver S. 25</a>). Im Konfigurationsmodell enthält <code>PwmChannelConfigSet</code> mindestens einen <code>PwmChannel</code>, und <code>PwmDutycycleDefault</code> ist auf 0 bis 0x8000 begrenzt (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-8bad3385375e60dd.html" data-snip="FIG-8bad3385375e60dd">ECUC-Parameter S. 545</a>). <code>PwmChannelClass</code> wird auf <code>Pwm_ChannelClassType</code> abgebildet. <code>PwmChannelId</code> wird dem symbolischen Namen des Kanal-Containers zugewiesen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_10_2_4_PwmChannel.html" data-snip="SNIP_CLASSIC_PWM_SECTION_10_2_4_PwmChannel">SWS PWM Driver S. 57</a>).</p>
<p>Optionale Dienste werden per Konfiguration ein- und ausgeschaltet: <code>PwmSetOutputToIdle</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_5_Pwm_SetOutputToIdle.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_5_Pwm_SetOutputToIdle">SWS PWM Driver S. 31</a>), <code>PwmGetOutputState</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_3_6_Pwm_GetOutputState.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_3_6_Pwm_GetOutputState">SWS PWM Driver S. 33</a>) sowie die oben genannten <code>PwmDeInitApi</code> und <code>PwmNotificationSupported</code>.</p>
<p>Für die Nebenläufigkeit gilt:</p>
<ul>
<li>Kanaldienste wie <code>Pwm_SetDutyCycle</code> sind reentrant für unterschiedliche Kanalnummern <a class="spec-record-ref" data-req="SWS_Pwm_91000" href="../../spec/record.html?id=SWS_Pwm_91000">[SWS_Pwm_91000]</a>.</li>
<li>Die Leistungszustands-APIs sind nicht reentrant <a class="spec-record-ref" data-req="SWS_Pwm_00183" href="../../spec/record.html?id=SWS_Pwm_00183">[SWS_Pwm_00183]</a>.</li>
<li>Konfigurationen mit Partitionszuordnungen, die die Implementierung nicht unterstützt, muss das Modul zurückweisen <a class="spec-record-ref" data-req="SWS_Pwm_00203" href="../../spec/record.html?id=SWS_Pwm_00203">[SWS_Pwm_00203]</a>.</li>
</ul>
<p>Die Reentranzstufen bis hin zu „multi-core reentrant“ erläutert der BSW-Distribution-Guide (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_2_2_6_Concurrency_safe_implementation_of_modules.html" data-snip="SNIP_CLASSIC_PWM_SECTION_2_2_6_Concurrency_safe_implementation_of_modules">BSW Distribution Guide S. 18</a>).</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Ist die Entwicklungsfehlererkennung aktiv, melden die Funktionen erkannte Fehler an den Default Error Tracer. Anschließend überspringen sie die angeforderte Funktion, damit weder Daten noch Hardwareregister verfälscht werden (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_PWM_SECTION_8_7_API_parameter_checking.html" data-snip="SNIP_CLASSIC_PWM_SECTION_8_7_API_parameter_checking">SWS PWM Driver S. 44</a>). Die Fehlercodes sind <a class="spec-record-ref" data-req="SWS_Pwm_00201" href="../../spec/record.html?id=SWS_Pwm_00201">[SWS_Pwm_00201]</a>:</p>
<ul>
<li><code>PWM_E_INIT_FAILED</code> (0x10)</li>
<li><code>PWM_E_UNINIT</code> (0x11) für Aufrufe vor der Initialisierung <a class="spec-record-ref" data-req="SWS_Pwm_20002" href="../../spec/record.html?id=SWS_Pwm_20002">[SWS_Pwm_20002]</a></li>
<li><code>PWM_E_PARAM_CHANNEL</code> (0x12) für ungültige Kanäle <a class="spec-record-ref" data-req="SWS_Pwm_30002" href="../../spec/record.html?id=SWS_Pwm_30002">[SWS_Pwm_30002]</a></li>
<li><code>PWM_E_PERIOD_UNCHANGEABLE</code> (0x13) für Periodenänderungen an Kanälen mit fester Periode <a class="spec-record-ref" data-req="SWS_Pwm_40002" href="../../spec/record.html?id=SWS_Pwm_40002">[SWS_Pwm_40002]</a></li>
<li><code>PWM_E_ALREADY_INITIALIZED</code> (0x14)</li>
<li><code>PWM_E_PARAM_POINTER</code> (0x15) für einen NULL-Parameter an <code>Pwm_GetVersionInfo</code></li>
</ul>
<p><code>Pwm_GetOutputState</code> muss immer einen Wert zurückgeben. Vor der Initialisierung oder bei ungültigem Kanal ist das <code>PWM_LOW</code> <a class="spec-record-ref" data-req="SWS_Pwm_30051" href="../../spec/record.html?id=SWS_Pwm_30051">[SWS_Pwm_30051]</a>.</p>
