<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::rds::IEEE1722Datagram</code> dient im Modul <code>rds</code> als Basisklasse zur Kapselung von IEEE-1722-Streaming-Datagrammen (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_RawDataStream&amp;page=1">AUTOSAR_AP_SWS_RawDataStream S. 1</a>). Sie verwaltet über das geschützte Attribut <code>data</code> den dynamischen Byte-Puffer im exklusiven Besitz und hält mit <code>stream_data_length</code> die jeweilige Nutzdatenlänge vor. Die Freigabe der allokierten Pufferressourcen erfolgt deterministisch und ausnahmefrei über den virtuellen Destruktor <code>~IEEE1722Datagram()</code> <a class="spec-record-ref" data-req="SWS_RDS_90228" href="../spec/record.html?id=SWS_RDS_90228">[SWS_RDS_90228]</a>. Eine interne Synchronisation für nebenläufige Zugriffe existiert nicht, sodass threadübergreifende Nutzungen extern abgesichert werden müssen.</p>

<h4>Lebenszyklus</h4>
<p>Der Lebenszyklus einer Datagramm-Instanz wird maßgeblich durch die Verwaltung des zugehörigen Datenpuffers und das RAII-Paradigma bestimmt. Das Attribut <code>data</code> ist als <code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code> geschützt deklariert <a class="spec-record-ref" data-req="SWS_RDS_90226" href="../spec/record.html?id=SWS_RDS_90226">[SWS_RDS_90226]</a>. Dies etabliert ein exklusives Besitzverhältnis: Ein Datagramm besitzt seinen Byte-Puffer exklusiv, wodurch unbeabsichtigtes Kopieren großer Datenmengen auf Typ-Ebene unterbunden wird.</p>
<p>Zusammen mit dem Puffer wird die Länge der gültigen Nutzdaten über das geschützte Feld <code>stream_data_length</code> vom Typ <code>std::uint16_t</code> geführt <a class="spec-record-ref" data-req="SWS_RDS_90227" href="../spec/record.html?id=SWS_RDS_90227">[SWS_RDS_90227]</a>. Die Freigabe der Ressourcen erfolgt deterministisch: Die Klasse stellt einen virtuellen Destruktor <code>~IEEE1722Datagram() noexcept</code> bereit <a class="spec-record-ref" data-req="SWS_RDS_90228" href="../spec/record.html?id=SWS_RDS_90228">[SWS_RDS_90228]</a>. Dieser stellt sicher, dass bei der Zerstörung abgeleiteter Instanzen über einen Zeiger auf die Basisklasse sämtliche Ressourcen vollständig und ohne Speicherlecks freigegeben werden.</p>
<p>Hinsichtlich der Nebenläufigkeit enthält die Basisklasse keine internen Synchronisationsmechanismen. Vermutlich erfordert der gleichzeitige Zugriff auf dieselbe Datagramm-Instanz aus mehreren Threads eine externe Koordination durch die anwendende Komponente. <a class="interp-q interp-q-unmatched" data-q-status="unmatched" href="../versions.html?tab=q&amp;qsub=class:adaptive:cl_ara_rds_IEEE1722Datagram_90225&amp;qst=open" title="Annahmen und Fragen zu diesem Text (Versions- &amp; Provenienz-Explorer)">Frage (offen)</a></p>

<h4>Nutzungspfad</h4>
<p>In einem typischen Verarbeitungsablauf innerhalb des Raw-Data-Streamings erfolgt die Nutzung über konkrete Protokollausprägungen wie <code>IEEE1722DatagramAAF</code> <a class="spec-record-ref" data-req="SWS_RDS_90273" href="../spec/record.html?id=SWS_RDS_90273">[SWS_RDS_90273]</a> oder <code>IEEE1722DatagramTSCF</code> <a class="spec-record-ref" data-req="SWS_RDS_90275" href="../spec/record.html?id=SWS_RDS_90275">[SWS_RDS_90275]</a>:</p>
<ul>
<li><strong>Erzeugung und Pufferallokation:</strong> Eine spezialisierte Datagramm-Instanz wird instanziiert, und der geschützte Datenpuffer <code>data</code> wird als <code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code> mit dem erforderlichen Speicherbereich initialisiert <a class="spec-record-ref" data-req="SWS_RDS_90226" href="../spec/record.html?id=SWS_RDS_90226">[SWS_RDS_90226]</a>.</li>
<li><strong>Längenfestlegung:</strong> Die tatsächliche Nutzdatenlänge des Streams wird in <code>stream_data_length</code> hinterlegt <a class="spec-record-ref" data-req="SWS_RDS_90227" href="../spec/record.html?id=SWS_RDS_90227">[SWS_RDS_90227]</a>.</li>
<li><strong>Übergabe und Verarbeitung:</strong> Interpretation: Das Datagramm dürfte vorzugsweise mittels Move-Semantik durch die Verarbeitungspipeline des Moduls <code>rds</code> transportiert werden, um unnötige Kopieroperationen von Streaming-Daten zu vermeiden. <a class="interp-q interp-q-open" data-q="Q-ff084c9788ec5cdc" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-ff084c9788ec5cdc" title="Frage Q-ff084c9788ec5cdc (offen): Die Übergabe von Datagrammen erfolgt vorzugsweise per Move-Semantik">Frage Q-ff084c9788ec5cdc (offen)</a></li>
<li><strong>Zerstörung:</strong> Nach Abschluss der Verarbeitung verlässt das Datagramm seinen Gültigkeitsbereich; der virtuelle Destruktor <code>~IEEE1722Datagram()</code> wird aufgerufen und der Puffer automatisch deallokiert <a class="spec-record-ref" data-req="SWS_RDS_90228" href="../spec/record.html?id=SWS_RDS_90228">[SWS_RDS_90228]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Fehler im Umgang mit <code>ara::rds::IEEE1722Datagram</code> können insbesondere bei der Speicherverwaltung und Grenzwertprüfung auftreten:</p>
<ul>
<li><strong>Speicherallokationsfehler:</strong> Schlägt die Allokation des dynamischen Byte-Arrays für <code>data</code> fehl, kann dies zu einer Standard-Speicherausnahme (<code>std::bad_alloc</code>) führen, bevor das Datagramm gültig bereitgestellt wird <a class="spec-record-ref" data-req="SWS_RDS_90226" href="../spec/record.html?id=SWS_RDS_90226">[SWS_RDS_90226]</a>.</li>
<li><strong>Längeninkonsistenz:</strong> Wird für <code>stream_data_length</code> ein Wert eingetragen, der die reale Größe des über <code>data</code> allokierten Speichers überschreitet, drohen bei lesenden Zugriffen Pufferüberläufe <a class="spec-record-ref" data-req="SWS_RDS_90227" href="../spec/record.html?id=SWS_RDS_90227">[SWS_RDS_90227]</a>. Abgeleitete Klassen müssen die Konsistenz zwischen Pufferallokation und Längenangabe sicherstellen.</li>
<li><strong>Ausnahmesicherheit beim Abbau:</strong> Der Destruktor ist explizit als <code>noexcept</code> deklariert <a class="spec-record-ref" data-req="SWS_RDS_90228" href="../spec/record.html?id=SWS_RDS_90228">[SWS_RDS_90228]</a>. Dadurch ist garantiert, dass bei der Zerstörung des Objekts keine Ausnahmen propagiert werden, was für die Stabilität von RAII-Ketten essenziell ist.</li>
</ul>
