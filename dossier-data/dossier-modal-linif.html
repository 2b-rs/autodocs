<div class="ai-level" data-ai-level="2">
<p>Das LIN Interface verbindet die oberen Kommunikationsmodule mit LIN-Treiber und Transceiver und enthält auch das LIN-Transportprotokoll. Als Master arbeitet ein Kanal Schedule-Tabellen ab, die über <code>LinIf_ScheduleRequest</code> gewählt werden <a class="spec-record-ref" data-req="SWS_LinIf_00202" href="../../spec/record.html?id=SWS_LinIf_00202">[SWS_LinIf_00202]</a>. Als Slave reagiert er dagegen nur auf die Header-Meldungen des Treibers <a class="spec-record-ref" data-req="SWS_LinIf_91004" href="../../spec/record.html?id=SWS_LinIf_91004">[SWS_LinIf_91004]</a>. Daneben steuert es je Kanal das Schlafen und Wecken, die Diagnose-Übertragung und im Slave die Node Configuration. Welche Dienste verfügbar sind, hängt vom konfigurierten Knotentyp der Kanäle ab.</p>

</div>
<div class="ai-level" data-ai-level="3">
<p>Das LIN Interface (LinIf) vermittelt zwischen den oberen Kommunikationsmodulen und dem LIN-Treiber und enthält zugleich das LIN-Transportprotokoll <a class="spec-record-ref" data-req="SWS_LinIf_00351" href="../../spec/record.html?id=SWS_LinIf_00351">[SWS_LinIf_00351]</a>. Nach oben ruft es in R20-11 die konfigurierbaren Callouts <code>&lt;User_TriggerTransmit&gt;</code>, <code>&lt;User_TxConfirmation&gt;</code> und <code>&lt;User_RxIndication&gt;</code> auf <a class="spec-record-ref" data-req="SWS_LinIf_00528" href="../../spec/record.html?id=SWS_LinIf_00528">[SWS_LinIf_00528]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00529" href="../../spec/record.html?id=SWS_LinIf_00529">[SWS_LinIf_00529]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00530" href="../../spec/record.html?id=SWS_LinIf_00530">[SWS_LinIf_00530]</a>; Nutzer ist der PduR oder ein CDD. Moduswechsel meldet es über <code>&lt;User&gt;_…Confirmation</code>-Callouts an den LinSM zurück <a class="spec-record-ref" data-req="SWS_LinIf_00521" href="../../spec/record.html?id=SWS_LinIf_00521">[SWS_LinIf_00521]</a>. Nach unten nutzt es Lin und optional LinTrcv <a class="spec-record-ref" data-req="SWS_LinIf_00359" href="../../spec/record.html?id=SWS_LinIf_00359">[SWS_LinIf_00359]</a>.</p>

<h4>Rolle des LIN Interface zwischen Nutzern, Treiber und Transceiver</h4>
<p>Das LIN Interface (LinIf) vermittelt zwischen den oberen Kommunikationsmodulen und dem LIN-Treiber. Es enthält zugleich das LIN-Transportprotokoll: Auch dessen Dienste wie <code>LinTp_Init</code> und <code>LinTp_Transmit</code> sind über <code>LinIf.h</code> verfügbar <a class="spec-record-ref" data-req="SWS_LinIf_00350" href="../../spec/record.html?id=SWS_LinIf_00350">[SWS_LinIf_00350]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00351" href="../../spec/record.html?id=SWS_LinIf_00351">[SWS_LinIf_00351]</a>. Nach unten nutzt LinIf Treiberdienste wie <code>Lin_GoToSleepInternal</code>, <code>Lin_Wakeup</code> und <code>Lin_WakeupInternal</code> <a class="spec-record-ref" data-req="SWS_LinIf_00359" href="../../spec/record.html?id=SWS_LinIf_00359">[SWS_LinIf_00359]</a>. Optional kommt der LIN Transceiver Driver hinzu, dessen Modus- und Weckdienste LinIf für alle Transceiver auf eine einheitliche Schnittstelle abbildet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_5_2_2_LIN_Transceiver_Driver.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_5_2_2_LIN_Transceiver_Driver">SWS LinIf S. 24</a>. Dazu reichen <code>LinIf_SetTrcvMode</code>, <code>LinIf_GetTrcvMode</code>, <code>LinIf_GetTrcvWakeupReason</code> und <code>LinIf_SetTrcvWakeupMode</code> die Aufrufe an den Transceiver-Treiber weiter <a class="spec-record-ref" data-req="SWS_LinIf_00544" href="../../spec/record.html?id=SWS_LinIf_00544">[SWS_LinIf_00544]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00545" href="../../spec/record.html?id=SWS_LinIf_00545">[SWS_LinIf_00545]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00547" href="../../spec/record.html?id=SWS_LinIf_00547">[SWS_LinIf_00547]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00550" href="../../spec/record.html?id=SWS_LinIf_00550">[SWS_LinIf_00550]</a>.</p>
<p>Nach oben ruft LinIf seine Nutzer über konfigurierbare Callouts auf: <code>&lt;User_TriggerTransmit&gt;</code>, <code>&lt;User_TxConfirmation&gt;</code> und <code>&lt;User_RxIndication&gt;</code> <a class="spec-record-ref" data-req="SWS_LinIf_00528" href="../../spec/record.html?id=SWS_LinIf_00528">[SWS_LinIf_00528]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00529" href="../../spec/record.html?id=SWS_LinIf_00529">[SWS_LinIf_00529]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00530" href="../../spec/record.html?id=SWS_LinIf_00530">[SWS_LinIf_00530]</a>. Nutzer ist entweder der PduR, dann ist <code>PduR_LinIfTriggerTransmit</code> einzutragen <a class="spec-record-ref" data-req="SWS_LinIf_00722" href="../../spec/record.html?id=SWS_LinIf_00722">[SWS_LinIf_00722]</a>, oder ein CDD, dessen Callback-Header LinIf einbindet <a class="spec-record-ref" data-req="SWS_LinIf_00669" href="../../spec/record.html?id=SWS_LinIf_00669">[SWS_LinIf_00669]</a>. Moduswechsel meldet LinIf über <code>&lt;User&gt;_ScheduleRequestConfirmation</code>, <code>&lt;User&gt;_GotoSleepConfirmation</code> und <code>&lt;User&gt;_WakeupConfirmation</code> zurück <a class="spec-record-ref" data-req="SWS_LinIf_00520" href="../../spec/record.html?id=SWS_LinIf_00520">[SWS_LinIf_00520]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00521" href="../../spec/record.html?id=SWS_LinIf_00521">[SWS_LinIf_00521]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00522" href="../../spec/record.html?id=SWS_LinIf_00522">[SWS_LinIf_00522]</a>. Empfänger dieser Meldungen ist der LinSM <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_1_5_Goto_sleep.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_1_5_Goto_sleep">SWS LinSM S. 24</a>. Außerdem benötigt LinIf die Dienste <code>BswM_LinTp_RequestMode</code>, <code>Com_SendSignal</code> und <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_LinIf_00360" href="../../spec/record.html?id=SWS_LinIf_00360">[SWS_LinIf_00360]</a>. Ab R24-11 ersetzt der LSduR den PduR bzw. CDD als oberen Nutzer <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_General_Overview">SWS LinIf S. 1</a>. <h4>Master-Kanal: Schedule-Tabellen bestimmen den Busverkehr</h4>
<p>Im Master bildet die Schedule-Tabelle die Grundlage aller Kommunikation. Jeder Kanal besitzt einen leeren <code>NULL_SCHEDULE</code>, und die Abstände zwischen Frames sind Vielfache von <code>LinIfMainFunctionPeriod</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_2_Schedules_Master_only.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_2_Schedules_Master_only">SWS LinIf S. 44</a>. <code>LinIf_SchHandleType</code> kodiert den <code>NULL_SCHEDULE</code> als 0x00 und die übrigen Tabellen als Index 1..255. Der Index ist je Kanal eindeutig, aber nicht je Steuergerät <a class="spec-record-ref" data-req="SWS_LinIf_00197" href="../../spec/record.html?id=SWS_LinIf_00197">[SWS_LinIf_00197]</a>. <code>LinIf_ScheduleRequest</code> arbeitet asynchron <a class="spec-record-ref" data-req="SWS_LinIf_00202" href="../../spec/record.html?id=SWS_LinIf_00202">[SWS_LinIf_00202]</a>; den vollzogenen Wechsel meldet <code>&lt;User&gt;_ScheduleRequestConfirmation</code> <a class="spec-record-ref" data-req="SWS_LinIf_00520" href="../../spec/record.html?id=SWS_LinIf_00520">[SWS_LinIf_00520]</a>. In der Konfiguration erhält jede Tabelle einen <code>LinIfRunMode</code>, nämlich <code>RUN_CONTINUOUS</code> oder <code>RUN_ONCE</code> <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c98732e3c39983e8.html" data-snip="FIG-c98732e3c39983e8">ECUC-Parameter S. 265</a>. Der Parameter <code>Schedule</code> wurde erst in R22-11 umbenannt <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_General_Overview">SWS LinIf S. 1</a>.</p>
<p><code>LinIf_Transmit</code> <a class="spec-record-ref" data-req="SWS_LinIf_00201" href="../../spec/record.html?id=SWS_LinIf_00201">[SWS_LinIf_00201]</a> löst keine sofortige Sendung aus. Es markiert nur Sporadic Frames (Master) bzw. Event-triggered Frames (Slave) als anstehend <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_8_2_3_LinIf_Transmit.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_8_2_3_LinIf_Transmit">SWS LinIf S. 79</a>. Für andere Frames liefert es dennoch <code>E_OK</code> <a class="spec-record-ref" data-req="SWS_LinIf_00700" href="../../spec/record.html?id=SWS_LinIf_00700">[SWS_LinIf_00700]</a>, während eines <code>NULL_SCHEDULE</code> dagegen <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_LinIf_00719" href="../../spec/record.html?id=SWS_LinIf_00719">[SWS_LinIf_00719]</a>. Ist ein Sende-Slot fällig, holt LinIf die Daten über <code>&lt;User_TriggerTransmit&gt;</code> und übergibt sie mit <code>Lin_SendFrame</code> an den Treiber <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_1_3_1_1_Header_and_response.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_1_3_1_1_Header_and_response">SWS LinIf S. 37</a>. Liefert der Nutzer <code>E_NOT_OK</code>, entfällt der Frame <a class="spec-record-ref" data-req="SWS_LinIf_00706" href="../../spec/record.html?id=SWS_LinIf_00706">[SWS_LinIf_00706]</a>. Den Ausgang prüft LinIf mit <code>Lin_GetStatus</code>, frühestens nach der maximalen Frame-Länge und spätestens beim nächsten Tabelleneintrag <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_1_2_1_3_Status_check.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_1_2_1_3_Status_check">SWS LinIf S. 35</a>. <code>LIN_TX_ERROR</code> und <code>LIN_TX_BUSY</code> führen zu <code>&lt;User_TxConfirmation&gt;</code> mit <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_LinIf_00728" href="../../spec/record.html?id=SWS_LinIf_00728">[SWS_LinIf_00728]</a>, <code>LIN_TX_OK</code> führt zu <code>E_OK</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_1_3_1_2_Status_check.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_1_3_1_2_Status_check">SWS LinIf S. 40</a>.</p>

<h4>Slave-Kanal: Reaktion auf die Header des Masters</h4>
<p>Ein Slave kennt keinen Schedule. Er reagiert ausschließlich auf <code>LinIf_HeaderIndication</code> <a class="spec-record-ref" data-req="SWS_LinIf_91004" href="../../spec/record.html?id=SWS_LinIf_91004">[SWS_LinIf_91004]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_1_3_2_Frame_transmission_in_slave_nodes.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_1_3_2_Frame_transmission_in_slave_nodes">SWS LinIf S. 39</a>. LinIf wertet zunächst die PID aus:</p>
<ul>
<li><strong>Sende-Frame:</strong> <code>&lt;User_TriggerTransmit&gt;</code> schreibt direkt in den Treiberpuffer <a class="spec-record-ref" data-req="SWS_LinIf_00738" href="../../spec/record.html?id=SWS_LinIf_00738">[SWS_LinIf_00738]</a>. Danach setzt LinIf <code>Cs</code> und <code>Dl</code> und meldet <code>LIN_FRAMERESPONSE_TX</code> <a class="spec-record-ref" data-req="SWS_LinIf_00739" href="../../spec/record.html?id=SWS_LinIf_00739">[SWS_LinIf_00739]</a>. Liefert der Nutzer <code>E_NOT_OK</code>, meldet LinIf <code>LIN_FRAMERESPONSE_IGNORE</code> <a class="spec-record-ref" data-req="SWS_LinIf_00740" href="../../spec/record.html?id=SWS_LinIf_00740">[SWS_LinIf_00740]</a>.</li>
<li><strong>Empfangs-Frame:</strong> LinIf meldet <code>LIN_FRAMERESPONSE_RX</code> <a class="spec-record-ref" data-req="SWS_LinIf_00733" href="../../spec/record.html?id=SWS_LinIf_00733">[SWS_LinIf_00733]</a>.</li>
<li><strong>Irrelevanter Frame:</strong> LinIf meldet <code>LIN_FRAMERESPONSE_IGNORE</code> <a class="spec-record-ref" data-req="SWS_LinIf_00748" href="../../spec/record.html?id=SWS_LinIf_00748">[SWS_LinIf_00748]</a>.</li>
</ul>
<p>Nach einem erfolgreichen Empfang ruft der Treiber <code>LinIf_RxIndication</code> auf, und LinIf reicht die Daten an <code>&lt;User_RxIndication&gt;</code> weiter <a class="spec-record-ref" data-req="SWS_LinIf_91005" href="../../spec/record.html?id=SWS_LinIf_91005">[SWS_LinIf_91005]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00734" href="../../spec/record.html?id=SWS_LinIf_00734">[SWS_LinIf_00734]</a>. Nach einem erfolgreichen Senden ruft der Treiber <code>LinIf_TxConfirmation</code> auf, und LinIf bestätigt mit <code>E_OK</code> <a class="spec-record-ref" data-req="SWS_LinIf_91006" href="../../spec/record.html?id=SWS_LinIf_91006">[SWS_LinIf_91006]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00741" href="../../spec/record.html?id=SWS_LinIf_00741">[SWS_LinIf_00741]</a>. Bei Event-triggered Frames steht die PID des zugehörigen Unconditional Frames im ersten Datenbyte <a class="spec-record-ref" data-req="SWS_LinIf_00731" href="../../spec/record.html?id=SWS_LinIf_00731">[SWS_LinIf_00731]</a>. Das Pending-Flag wird nach erfolgreicher Übertragung gelöscht <a class="spec-record-ref" data-req="SWS_LinIf_00732" href="../../spec/record.html?id=SWS_LinIf_00732">[SWS_LinIf_00732]</a>.</p>
<p>Das <code>response_error</code>-Signal verwaltet LinIf je Slave-Kanal selbstständig <a class="spec-record-ref" data-req="SWS_LinIf_00763" href="../../spec/record.html?id=SWS_LinIf_00763">[SWS_LinIf_00763]</a> und aktualisiert es über <code>Com_SendSignal</code> <a class="spec-record-ref" data-req="SWS_LinIf_00764" href="../../spec/record.html?id=SWS_LinIf_00764">[SWS_LinIf_00764]</a>. Nach erfolgreicher Übertragung wird es gelöscht <a class="spec-record-ref" data-req="SWS_LinIf_00747" href="../../spec/record.html?id=SWS_LinIf_00747">[SWS_LinIf_00747]</a>. Jede Änderung kann optional über <code>&lt;User_ResponseErrorSignalChanged&gt;</code> gemeldet werden <a class="spec-record-ref" data-req="SWS_LinIf_00765" href="../../spec/record.html?id=SWS_LinIf_00765">[SWS_LinIf_00765]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00766" href="../../spec/record.html?id=SWS_LinIf_00766">[SWS_LinIf_00766]</a>. NAD und PID-Liste lassen sich zur Laufzeit lesen und schreiben <a class="spec-record-ref" data-req="SWS_LinIf_00829" href="../../spec/record.html?id=SWS_LinIf_00829">[SWS_LinIf_00829]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00833" href="../../spec/record.html?id=SWS_LinIf_00833">[SWS_LinIf_00833]</a> <a class="spec-record-ref" data-req="SWS_LinIf_91002" href="../../spec/record.html?id=SWS_LinIf_91002">[SWS_LinIf_91002]</a> <a class="spec-record-ref" data-req="SWS_LinIf_91003" href="../../spec/record.html?id=SWS_LinIf_91003">[SWS_LinIf_91003]</a>. Ausgenommen bleiben die PIDs von MRF und SRF <a class="spec-record-ref" data-req="SWS_LinIf_00809" href="../../spec/record.html?id=SWS_LinIf_00809">[SWS_LinIf_00809]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00824" href="../../spec/record.html?id=SWS_LinIf_00824">[SWS_LinIf_00824]</a>. Typische Quelle dieser Werte ist der nichtflüchtige Speicher <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_6_2_1_Node_Model.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_6_2_1_Node_Model">SWS LinIf S. 57</a>.</p>

<h4>Schlafen und Wecken eines LIN-Kanals</h4>
<p>Der Master sendet auf Anforderung ein Go-to-sleep-Kommando. Der Slave schläft ein, wenn er dieses Kommando empfängt oder der Bus inaktiv bleibt <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_4_2_Go_to_sleep_process.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_4_2_Go_to_sleep_process">SWS LinIf S. 48</a>. Als Go-to-sleep-Kommando gilt im Slave ein MRF mit NAD 0 <a class="spec-record-ref" data-req="SWS_LinIf_00750" href="../../spec/record.html?id=SWS_LinIf_00750">[SWS_LinIf_00750]</a>. Die Bus-Idle-Überwachung läuft im Zustand <code>LINIF_CHANNEL_OPERATIONAL</code> <a class="spec-record-ref" data-req="SWS_LinIf_00751" href="../../spec/record.html?id=SWS_LinIf_00751">[SWS_LinIf_00751]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00752" href="../../spec/record.html?id=SWS_LinIf_00752">[SWS_LinIf_00752]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00753" href="../../spec/record.html?id=SWS_LinIf_00753">[SWS_LinIf_00753]</a>. Jeder Treiber-Callback startet den Timer neu <a class="spec-record-ref" data-req="SWS_LinIf_00754" href="../../spec/record.html?id=SWS_LinIf_00754">[SWS_LinIf_00754]</a>. In beiden Fällen ruft LinIf <code>&lt;User&gt;_GotoSleepIndication</code> auf <a class="spec-record-ref" data-req="SWS_LinIf_00756" href="../../spec/record.html?id=SWS_LinIf_00756">[SWS_LinIf_00756]</a>. Ruft der Nutzer daraufhin <code>LinIf_GotoSleep</code> <a class="spec-record-ref" data-req="SWS_LinIf_00204" href="../../spec/record.html?id=SWS_LinIf_00204">[SWS_LinIf_00204]</a>, folgt sofort <code>Lin_GoToSleepInternal</code> <a class="spec-record-ref" data-req="SWS_LinIf_00757" href="../../spec/record.html?id=SWS_LinIf_00757">[SWS_LinIf_00757]</a>. Danach löscht LinIf das Weckflag <a class="spec-record-ref" data-req="SWS_LinIf_00758" href="../../spec/record.html?id=SWS_LinIf_00758">[SWS_LinIf_00758]</a> und bestätigt mit <code>TRUE</code> <a class="spec-record-ref" data-req="SWS_LinIf_00759" href="../../spec/record.html?id=SWS_LinIf_00759">[SWS_LinIf_00759]</a>. Im Master versendet die MainFunction laut Schaubild das Kommando über <code>Lin_GoToSleep</code> und bestätigt nach der Statusprüfung <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-51b4cb14f4361f7b.html" data-snip="FIG-51b4cb14f4361f7b">SWS LinIf (Abb.) S. 93</a> <a class="spec-record-ref" data-req="SWS_LinIf_00521" href="../../spec/record.html?id=SWS_LinIf_00521">[SWS_LinIf_00521]</a>.</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Entwicklungsfehler meldet LinIf an den DET, unter anderem mit <code>LINIF_E_UNINIT</code>, <code>LINIF_E_NONEXISTENT_CHANNEL</code>, <code>LINIF_E_PARAMETER</code>, <code>LINIF_E_PARAM_POINTER</code> und <code>LINIF_E_SCHEDULE_REQUEST_ERROR</code> <a class="spec-record-ref" data-req="SWS_LinIf_00376" href="../../spec/record.html?id=SWS_LinIf_00376">[SWS_LinIf_00376]</a>. Die Callbacks prüfen Kanal und Zeiger <a class="spec-record-ref" data-req="SWS_LinIf_00843" href="../../spec/record.html?id=SWS_LinIf_00843">[SWS_LinIf_00843]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00844" href="../../spec/record.html?id=SWS_LinIf_00844">[SWS_LinIf_00844]</a>. Unerwartete Aufrufe von <code>LinIf_RxIndication</code> oder <code>LinIf_TxConfirmation</code> ohne vorherigen Header ignoriert LinIf <a class="spec-record-ref" data-req="SWS_LinIf_00848" href="../../spec/record.html?id=SWS_LinIf_00848">[SWS_LinIf_00848]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00852" href="../../spec/record.html?id=SWS_LinIf_00852">[SWS_LinIf_00852]</a>.</p>
<p>Als Laufzeitfehler kennt LinIf <code>LINIF_E_RESPONSE</code> und <code>LINIF_E_NC_NO_RESPONSE</code> <a class="spec-record-ref" data-req="SWS_LinIf_00729" href="../../spec/record.html?id=SWS_LinIf_00729">[SWS_LinIf_00729]</a>. Ruft der Treiber im Slave <code>LinIf_LinErrorIndication</code> auf, gilt der Frame als verloren. LinIf meldet dann <code>LINIF_E_RESPONSE</code>, außer bei <code>LIN_ERR_HEADER</code> <a class="spec-record-ref" data-req="SWS_LinIf_00735" href="../../spec/record.html?id=SWS_LinIf_00735">[SWS_LinIf_00735]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00743" href="../../spec/record.html?id=SWS_LinIf_00743">[SWS_LinIf_00743]</a>. Zusätzlich bestätigt es den Sendeversuch mit <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_LinIf_00742" href="../../spec/record.html?id=SWS_LinIf_00742">[SWS_LinIf_00742]</a> und setzt bei Response-Fehlern das <code>response_error</code>-Signal <a class="spec-record-ref" data-req="SWS_LinIf_00736" href="../../spec/record.html?id=SWS_LinIf_00736">[SWS_LinIf_00736]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00744" href="../../spec/record.html?id=SWS_LinIf_00744">[SWS_LinIf_00744]</a>. Ein neuer Header, während noch eine Response erwartet wird, macht den alten Frame ungültig <a class="spec-record-ref" data-req="SWS_LinIf_00846" href="../../spec/record.html?id=SWS_LinIf_00846">[SWS_LinIf_00846]</a>. Bei aktivem Mirroring meldet LinIf solche Fehler mit umgesetztem Statuscode <a class="spec-record-ref" data-req="SWS_LinIf_00869" href="../../spec/record.html?id=SWS_LinIf_00869">[SWS_LinIf_00869]</a> <a class="spec-record-ref" data-req="SWS_LinIf_00870" href="../../spec/record.html?id=SWS_LinIf_00870">[SWS_LinIf_00870]</a>.</p>
