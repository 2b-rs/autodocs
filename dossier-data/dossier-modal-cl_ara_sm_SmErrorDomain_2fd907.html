<h4>Context</h4>
<p>The class <code>ara::sm::SmErrorDomain</code> defines the domain-specific error domain for the functional cluster State Management (SM) within the AUTOSAR Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=117">SWS StateManagement §8.1.3 “Class: SmErrorDomain”</a>. According to the class definition in <a class="spec-record-ref" data-req="SWS_SM_81241" href="../spec/record.html?id=SWS_SM_81241">[SWS_SM_81241]</a>, the class declared as <code>final</code> derives directly from the base infrastructure <code>ara::core::ErrorDomain</code>. It acts as a connecting element between the internal error states of State Management and the general error handling mechanism of the Adaptive Core Library.</p>

<p>Within the system architecture, <code>SmErrorDomain</code> handles the identification, categorization, and textual translation of errors that occur during interactions with State Management. Important interaction partners here are:</p>
<ul>
<li>The base class <code>ara::core::ErrorDomain</code>, whose interfaces are overridden and provided by <code>SmErrorDomain</code>.</li>
<li>Error objects of type <code>ara::core::ErrorCode</code>, which hold a reference to the instance of <code>SmErrorDomain</code> in order to encapsulate domain-specific error codes.</li>
<li>The enumeration of error causes, referenced via the type alias <code>Errc</code> <a class="spec-record-ref" data-req="SWS_SM_81245" href="../spec/record.html?id=SWS_SM_81245">[SWS_SM_81245]</a>, which refers to the enumeration type <code>SmErrc</code>.</li>
<li>Application components and functional clusters that evaluate return values or, when exception handling is enabled, use the type alias <code>Exception</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a>, which references the base exception class <code>SmException</code>.</li>
</ul>

<p>Via the member function <code>Name()</code>, the domain uniquely identifies itself by the string <code>"Sm"</code> <a class="spec-record-ref" data-req="SWS_SM_81248" href="../spec/record.html?id=SWS_SM_81248">[SWS_SM_81248]</a>, allowing diagnostic and logging services to unambiguously assign the origin of errors to State Management.</p>

<h4>Lifecycle</h4>
<p>The creation of an instance of <code>SmErrorDomain</code> takes place via the default constructor <code>SmErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_SM_81247" href="../spec/record.html?id=SWS_SM_81247">[SWS_SM_81247]</a>, which is declared as <code>noexcept</code>. The specification assigns the properties “exception safe” and “thread-safe” to the constructor, so that during instantiation neither exceptions are thrown nor synchronization problems arise.</p>

<p>With regard to concurrency, all member functions of the class are specified as thread-safe: both the name query <code>Name()</code> <a class="spec-record-ref" data-req="SWS_SM_81248" href="../spec/record.html?id=SWS_SM_81248">[SWS_SM_81248]</a> and text resolution <code>Message()</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a> as well as throwing exceptions <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a> can be called concurrently from different threads. The class has no mutable state and defines its methods as <code>const</code>. In AUTOSAR Adaptive, error domains are typically held as long-lived instances; the lifetime of a <code>SmErrorDomain</code> instance is therefore likely to typically encompass the entire execution time of the process (interpretation).</p>

<h4>Usage Path</h4>
<p>In typical application scenarios, <code>SmErrorDomain</code> is not used in isolation, but is addressed indirectly via the error handling of State Management operations. The typical usage workflow is divided into the following steps:</p>
<ol>
<li>A State Management operation fails and returns a <code>ara::core::Result</code> containing an object of type <code>ara::core::ErrorCode</code> with reference to <code>SmErrorDomain</code>.</li>
<li>The caller queries the description of the occurred error via the error code. The <code>ErrorCode</code> delegates the call internally to <code>SmErrorDomain::Message(CodeType errorCode)</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a>.</li>
<li>The function <code>Message()</code> returns the associated error text as <code>const char*</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=119">SWS StateManagement §8.1.3.2.2.1 “Message”</a>.</li>
<li>In environments with enabled exception handling, the error code can be raised as an exception via <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a>, throwing an exception object of type <code>Exception</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The class <code>SmErrorDomain</code> itself serves to represent errors and defines type aliases for the error system of the State Management module:</p>
<ul>
<li><code>Errc</code>: Alias for the enumeration <code>SmErrc</code> <a class="spec-record-ref" data-req="SWS_SM_81245" href="../spec/record.html?id=SWS_SM_81245">[SWS_SM_81245]</a>, which defines the specific numeric error codes of the module.</li>
<li><code>Exception</code>: Alias for <code>SmException</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a>, the base class for all State Management-related exceptions.</li>
</ul>

<p>When using the interfaces, the following specific preconditions and postconditions must be taken into account:</p>
<ul>
<li><strong>Exception safety when raising</strong>: The member function <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a> is classified as <em>not exception safe</em>. This corresponds to the intended behavior, as the function throws an exception object and does not return regularly.</li>
<li><strong>Disabled C++ exceptions</strong>: If C++ exceptions are disabled in the toolchain, <code>ThrowAsException()</code> does not participate in overload resolution according to <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a>. In this case, a call results in a compilation error.</li>
<li><strong>Error code resolution</strong>: The function <code>Message()</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a> accepts a numeric code. For unknown or invalid values outside of <code>SmErrc</code>, the implementation presumably returns a static default notice text (interpretation) without throwing exceptions, as the method is declared as <code>noexcept</code>.</li>
</ul>
