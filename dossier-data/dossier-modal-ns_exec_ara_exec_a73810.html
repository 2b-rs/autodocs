<h4>Kontext</h4>
<p>Der Namespace <code>ara::exec</code> stellt die Schnittstellen des Execution Management auf der AUTOSAR Adaptive Platform bereit. Das Modul verantwortet das Starten, Steuern und Überwachen von Prozessen sowie die Koordination übergeordneter System- und Funktionsgruppenzustände. Zu den zentralen Akteuren gehören die Anwendungsprozesse, das State Management und das Execution Management selbst. Prozesse verwenden die Klasse <code>ExecutionClient</code>, um ihren internen Laufzeitzustand an das Execution Management zu melden. Das State Management nutzt wiederum das Interface <code>StateClient</code>, um Zustandswechsel zwischen Funktionsgruppen (<code>FunctionGroup</code> und <code>FunctionGroupState</code>) anzufordern. Für Fehlerereignisse auf Ebene einer Funktionsgruppe wird der Typalias <code>ExecutionError</code> verwendet <a class="spec-record-ref" data-req="SWS_EM_02541" href="../spec/record.html?id=SWS_EM_02541">[SWS_EM_02541]</a>, der über <code>ExecutionErrorEvent</code> transportiert werden kann.</p>

<h4>Lebenszyklus</h4>
<p>Der Ausführungslebenszyklus eines Prozesses wird durch das Execution Management gesteuert <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>. Nach dem Scheduling befindet sich ein neu gestarteter Prozess zunächst in einem impliziten Zustand <code>Initializing</code>, in dem noch kein applikativer Programmcode ausgeführt wurde. Das Execution Management nimmt an, dass dieser Initialisierungszustand andauert, bis der Prozess über seinen <code>ExecutionClient</code> aktiv den Zustand <code>ExecutionState::kRunning</code> meldet <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>. Die Enumeration <code>ExecutionState</code> beschränkt sich strikt auf jene Zustände, die von Prozessen an das Execution Management berichtet werden können, und enthält daher ausschließlich den Zustand <code>kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>. Fordert das Execution Management die Beendigung an, wechselt der Prozess in die Phase <code>Terminating</code>, die mit dem endgültigen Terminieren des Prozesses abschließt <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungsablauf gliedert sich in folgende Phasen:</p>
<ul>
<li>Nach dem Systemstart wird der Prozess vom Execution Management erzeugt und nimmt seine interne Initialisierung vor <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</li>
<li>Sobald die Initialisierung erfolgreich abgeschlossen ist, meldet der Prozess über eine Instanz von <code>ExecutionClient</code> den Zustand <code>ExecutionState::kRunning</code> an das Execution Management <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>.</li>
<li>Das Execution Management quittiert diesen Übergang; wird <code>kRunning</code> jedoch gemeldet, wenn sich der Prozess bereits im laufenden Zustand befindet, wird dies als unzulässiger Übergang <code>ExecErrc::kInvalidTransition</code> abgewiesen <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li>Im weiteren Betrieb fordert das State Management bei Bedarf über <code>StateClient</code> koordinierte Zustandsübergänge für Funktionsgruppen an.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Fehlersituationen werden im Namespace <code>ara::exec</code> über den Enumerationstyp <code>ExecErrc</code> und die Fehlerdomäne <code>ExecErrorDomain</code> abgebildet <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>. Eine Referenz auf das globale Domänenobjekt liefert die thread- und ausnahmesichere Funktion <code>GetExecErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_EM_02290" href="../spec/record.html?id=SWS_EM_02290">[SWS_EM_02290]</a>. Konkrete Fehlerobjekte vom Typ <code>ara::core::ErrorCode</code> werden über die Hilfsfunktion <code>MakeErrorCode()</code> unter Übergabe des Fehlercodes und herstellerspezifischer Kontextdaten erzeugt <a class="spec-record-ref" data-req="SWS_EM_02291" href="../spec/record.html?id=SWS_EM_02291">[SWS_EM_02291]</a>; für Ausnahmebehandlungen steht zudem die Klasse <code>ExecException</code> zur Verfügung.</p>
<p>Zu den spezifizierten Fehlerursachen zählen unter anderem <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>:</p>
<ul>
<li><code>ExecErrc::kNoCommunication</code>: Signalisiert Kommunikationsfehler zwischen Client und Execution Management oder zwischen State Management und Execution Management. Auf Systemebene dürfte ein solcher Zustand vermutlich den Eintritt in einen nicht behebbaren Zustand erfordern <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kInvalidTransition</code>: Ungültiger Übergang, beispielsweise wenn ein Prozess wiederholt <code>kRunning</code> meldet <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kOperationFailed</code>: Eine Operation schlägt fehl, etwa wenn ein Funktionsgruppenübergang nicht abgeschlossen werden kann, weil <code>kRunning</code> nicht rechtzeitig gemeldet wurde <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kOperationCanceled</code>: Ein Zustandswechsel einer Funktionsgruppe wurde durch eine neuere Anforderung abgebrochen <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code>: Die Integritäts- oder Authentizitätsprüfung eines zu startenden Prozesses schlägt fehl <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kUnexpectedTermination</code>: Abnormaler Abbruch während eines Übergangs <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code> sowie <code>ExecErrc::kInvalidArgument</code>: Unzulässige Metamodell-Bezeichner oder ungültige Parameterwerte <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>.</li>
</ul><!-- annahmen: 1) Die Klassen ExecutionClient und StateClient dürften als Interprozess-Schnittstellen (IPC) zum zentralen Execution Management implementiert sein – Begründung: SWS_EM_02281 behandelt Kommunikationsfehler (kNoCommunication) bei API-Aufrufen durch Applikationen, nennt jedoch keine konkrete IPC-Technologie. 2) Bei schwerwiegenden Kommunikationsausfällen dürfte das Gesamtsystem vermutlich in einen Unrecoverable State versetzt werden – Begründung: SWS_EM_02281 nennt den Unrecoverable State als mögliche Konsequenz auf Systemebene bei kNoCommunication. -->
