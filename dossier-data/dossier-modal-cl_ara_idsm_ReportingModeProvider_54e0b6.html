<h4>Context</h4>
<p>The class <code>ara::idsm::ReportingModeProvider</code> is defined as a final interface in the AUTOSAR Adaptive module <code>idsm</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10600" href="../spec/record.html?id=SWS_AIDSM_10600">[SWS_AIDSM_10600]</a>). Its main responsibility is to provide reporting modes for configured security events to the Intrusion Detection System Manager (IdsM) (<a class="spec-record-ref" data-req="SWS_AIDSM_10600" href="../spec/record.html?id=SWS_AIDSM_10600">[SWS_AIDSM_10600]</a>). In doing so, it acts on the application side as a concrete provider instance for a PPort declared in the system model (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>).</p>
<p>The following parties typically interact in the overall system:</p>
<ul>
<li><strong>Adaptive Application:</strong> Acts as a mode provider and decides, based on states or external diagnostics, which reporting mode should be active.</li>
<li><strong><code>ReportingModeProvider</code>:</strong> Encapsulates the port-specific interface for querying and updating the event modes (<a class="spec-record-ref" data-req="SWS_AIDSM_10602" href="../spec/record.html?id=SWS_AIDSM_10602">[SWS_AIDSM_10602]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10603" href="../spec/record.html?id=SWS_AIDSM_10603">[SWS_AIDSM_10603]</a>).</li>
<li><strong>IdsM platform instance:</strong> Interpretation: Receives the set reporting modes in order to control the filtering and forwarding of the corresponding security events in the vehicle network.</li>
</ul>

<h4>Lifecycle</h4>
<p>Creation of a <code>ReportingModeProvider</code> object is strictly explicit via the passing of a <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>). This specifier establishes the binding to the modeled PPort in the application manifest. The constructor throws no exceptions (<code>noexcept</code>) and is explicitly specified as thread-safe (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>).</p>
<p>Regarding ownership and runtime: The instance is typically expected to be created during the initialization phase of the application and held throughout its entire operating phase. With the destruction of the object, the provision of the interface for the associated port ends. Concurrency at runtime requires special attention: While instantiation is thread-safe (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>), the operational methods <code>GetReportingMode</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10602" href="../spec/record.html?id=SWS_AIDSM_10602">[SWS_AIDSM_10602]</a>) and <code>SetReportingMode</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10603" href="../spec/record.html?id=SWS_AIDSM_10603">[SWS_AIDSM_10603]</a>) are designated as not thread-safe (<code>not thread-safe</code>). If multiple threads of execution access the same provider instance, the caller must synchronize access externally.</p>

<h4>Usage Path</h4>
<p>Typical usage is divided into creating the instance, querying existing states, and dynamically switching the reporting mode:</p>
<ol>
<li><strong>Instantiation:</strong> The application initializes the <code>ReportingModeProvider</code> with the corresponding <code>ara::core::InstanceSpecifier</code> of the PPort (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>).</li>
<li><strong>Querying the current mode:</strong> Via <code>GetReportingMode(eventId)</code>, the application determines the currently configured reporting mode for the specified event (<a class="spec-record-ref" data-req="SWS_AIDSM_10602" href="../spec/record.html?id=SWS_AIDSM_10602">[SWS_AIDSM_10602]</a>).</li>
<li><strong>Setting a new mode:</strong> Using <code>SetReportingMode(eventId, reportingMode)</code>, the desired mode for the relevant security event is updated (<a class="spec-record-ref" data-req="SWS_AIDSM_10603" href="../spec/record.html?id=SWS_AIDSM_10603">[SWS_AIDSM_10603]</a>).</li>
<li><strong>Evaluating the result:</strong> Since both calls return <code>ara::core::Result</code>, the application verifies in each case whether the operation was successful or an error occurred.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The interfaces of the class operate entirely without C++ exceptions (<code>noexcept</code>) and report error conditions via the error type <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Unknown event ID (<code>IdsmErrc::kUnknownEventId</code>):</strong> This error is returned in <code>ara::core::Result</code> by both <code>GetReportingMode</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10602" href="../spec/record.html?id=SWS_AIDSM_10602">[SWS_AIDSM_10602]</a>) and <code>SetReportingMode</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10603" href="../spec/record.html?id=SWS_AIDSM_10603">[SWS_AIDSM_10603]</a>) if the passed <code>eventId</code> (of type <code>EventIdType</code>) does not correspond to any security event configured for this PPort in the system model.</li>
<li><strong>Preconditions:</strong> The provider instance must have been properly constructed (<a class="spec-record-ref" data-req="SWS_AIDSM_10601" href="../spec/record.html?id=SWS_AIDSM_10601">[SWS_AIDSM_10601]</a>), and the caller must ensure that the queried or modified event identifier is valid.</li>
<li><strong>Postconditions:</strong> After a successful call to <code>SetReportingMode</code>, <code>GetReportingMode</code> returns the newly set value for the same <code>eventId</code>. In the event of an error, the state in the IdsM remains unchanged.</li>
</ul>
