<h4>Context</h4>
<p>The C++ structure <code>ara::diag::CounterBased</code> represents the configuration parameters for counter-based debouncing (<em>counter-based debouncing</em>) within the AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_00538" href="../spec/record.html?id=SWS_DM_00538">[SWS_DM_00538]</a>. It serves as a data structure for defining counter thresholds, step sizes, and jump values for diagnostic monitors <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=613">AUTOSAR_AP_SWS_Diagnostics §8.41.2 “Struct: CounterBased”</a>.</p>
<p>Several components interact in counter-based debouncing:</p>
<ul>
<li><strong>Diagnostic Monitor (application):</strong> The application-specific monitoring function determines local fault states and reports them cyclically via monitor actions (e.g. <code>kPrefailed</code> or <code>kPrepassed</code>) to Diagnostic Management <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=239">AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.1 “Counter-based debouncing”</a>.</li>
<li><strong>ara::diag::Monitor:</strong> Forms the interface to the diagnostic infrastructure and accepts the debouncing parameters in the form of <code>ara::diag::CounterBased</code> during instantiation <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a>.</li>
<li><strong>Diagnostic Management (DM):</strong> Manages the internal debouncing counter per event, increments or decrements it based on the step sizes <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>, <a class="spec-record-ref" data-req="SWS_DM_00876" href="../spec/record.html?id=SWS_DM_00876">[SWS_DM_00876]</a>, and ultimately qualifies the event as defective (<code>kFinallyDefective</code>) <a class="spec-record-ref" data-req="SWS_DM_00024" href="../spec/record.html?id=SWS_DM_00024">[SWS_DM_00024]</a>.</li>
<li><strong>Diagnostic Extract (DEXT):</strong> Contains modeled debouncing parameters. If debouncing parameters are present in the DEXT for the event, they take precedence over the values passed in the C++ constructor <a class="spec-record-ref" data-req="SWS_DM_01099" href="../spec/record.html?id=SWS_DM_01099">[SWS_DM_01099]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p><code>ara::diag::CounterBased</code> is declared as a pure data container (value object) without its own member functions <a class="spec-record-ref" data-req="SWS_DM_00538" href="../spec/record.html?id=SWS_DM_00538">[SWS_DM_00538]</a>. The lifecycle of the structure is divided into the following phases:</p>
<ul>
<li><strong>Instantiation and population:</strong> The application creates an instance of <code>ara::diag::CounterBased</code> (typically locally on the stack or as a static configuration structure) and initializes the counter thresholds (<code>failedThreshold</code> <a class="spec-record-ref" data-req="SWS_DM_00621" href="../spec/record.html?id=SWS_DM_00621">[SWS_DM_00621]</a>, <code>passedThreshold</code> <a class="spec-record-ref" data-req="SWS_DM_00622" href="../spec/record.html?id=SWS_DM_00622">[SWS_DM_00622]</a>), the step sizes (<code>failedStepsize</code> <a class="spec-record-ref" data-req="SWS_DM_00623" href="../spec/record.html?id=SWS_DM_00623">[SWS_DM_00623]</a>, <code>passedStepsize</code> <a class="spec-record-ref" data-req="SWS_DM_00624" href="../spec/record.html?id=SWS_DM_00624">[SWS_DM_00624]</a>), as well as the jump attributes (<code>failedJumpValue</code> <a class="spec-record-ref" data-req="SWS_DM_00625" href="../spec/record.html?id=SWS_DM_00625">[SWS_DM_00625]</a>, <code>passedJumpValue</code> <a class="spec-record-ref" data-req="SWS_DM_00626" href="../spec/record.html?id=SWS_DM_00626">[SWS_DM_00626]</a>, <code>useJumpToFailed</code> <a class="spec-record-ref" data-req="SWS_DM_00627" href="../spec/record.html?id=SWS_DM_00627">[SWS_DM_00627]</a>, and <code>useJumpToPassed</code> <a class="spec-record-ref" data-req="SWS_DM_00628" href="../spec/record.html?id=SWS_DM_00628">[SWS_DM_00628]</a>).</li>
<li><strong>Passing to the monitor:</strong> The populated structure is passed as an argument to the constructor of <code>ara::diag::Monitor</code> <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a> on <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=607">AUTOSAR_AP_SWS_Diagnostics §8.40.1.1.2.2 “Monitor”</a>.</li>
<li><strong>Ownership and passing:</strong> Interpretation: Since it is an elementary C++ structure without dynamic memory management, the values are copied when the constructor is called; the original instance does not remain in the possession of the monitor and can be safely discarded after the constructor call returns.</li>
<li><strong>Validity period:</strong> If corresponding debouncing parameters are missing in the DEXT, Diagnostic Management adopts the passed values for the internal debouncing algorithm <a class="spec-record-ref" data-req="SWS_DM_01101" href="../spec/record.html?id=SWS_DM_01101">[SWS_DM_01101]</a>. These remain active for the entire lifetime of the respective monitor.</li>
<li><strong>Concurrency:</strong> The structure itself provides no thread synchronization. However, since it is fully initialized prior to being passed and is subsequently only passed by value, creation and passing are concurrency-safe as long as no concurrent write accesses occur before the constructor call.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical procedure for using <code>ara::diag::CounterBased</code> includes parameterization, registration, and subsequent event processing at runtime:</p>
<ol>
<li><strong>Configuration of debouncing parameters:</strong> The application populates the members of <code>ara::diag::CounterBased</code>. For example, <code>failedStepsize</code> is set to the step size per error report <a class="spec-record-ref" data-req="SWS_DM_00623" href="../spec/record.html?id=SWS_DM_00623">[SWS_DM_00623]</a> and <code>failedThreshold</code> to the threshold for qualified errors <a class="spec-record-ref" data-req="SWS_DM_00621" href="../spec/record.html?id=SWS_DM_00621">[SWS_DM_00621]</a>. If a jump is to occur upon a transition from a passed to a failed state, <code>useJumpToFailed</code> is set to <code>true</code> and the jump value is stored in <code>failedJumpValue</code> <a class="spec-record-ref" data-req="SWS_DM_00625" href="../spec/record.html?id=SWS_DM_00625">[SWS_DM_00625]</a>, <a class="spec-record-ref" data-req="SWS_DM_00627" href="../spec/record.html?id=SWS_DM_00627">[SWS_DM_00627]</a>.</li>
<li><strong>Monitor initialization:</strong> The application module instantiates <code>ara::diag::Monitor</code>, passing the <code>ara::core::InstanceSpecifier</code>, the initialization notification, and the <code>CounterBased</code> structure <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a>.</li>
<li><strong>Parameter adoption by the DM:</strong> Diagnostic Management checks whether debouncing parameters are stored in the DEXT. If none are present there, the DM definitively falls back on the values from <code>CounterBased</code> <a class="spec-record-ref" data-req="SWS_DM_01101" href="../spec/record.html?id=SWS_DM_01101">[SWS_DM_01101]</a>.</li>
<li><strong>Reporting monitor actions:</strong> If the monitoring detects a fault symptom, it calls <code>ara::diag::Monitor::ReportMonitorAction</code> with <code>kPrefailed</code> <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>.</li>
<li><strong>Counter adjustment and qualification:</strong> If <code>counterJumpUp</code> (corresponds to <code>useJumpToFailed</code>) is active and the counter is below <code>failedJumpValue</code>, the DM first sets the counter to the jump value <a class="spec-record-ref" data-req="SWS_DM_00022" href="../spec/record.html?id=SWS_DM_00022">[SWS_DM_00022]</a>. The counter is then incremented by <code>failedStepsize</code> <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>. If the debouncing counter reaches or exceeds <code>failedThreshold</code>, the event is processed as <code>kFinallyDefective</code> <a class="spec-record-ref" data-req="SWS_DM_00024" href="../spec/record.html?id=SWS_DM_00024">[SWS_DM_00024]</a>. For passed reports (<code>kPrepassed</code>), the jump <a class="spec-record-ref" data-req="SWS_DM_00023" href="../spec/record.html?id=SWS_DM_00023">[SWS_DM_00023]</a> and decrement logic <a class="spec-record-ref" data-req="SWS_DM_00876" href="../spec/record.html?id=SWS_DM_00876">[SWS_DM_00876]</a> apply analogously.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When handling <code>ara::diag::CounterBased</code>, certain error situations and special cases occur:</p>
<ul>
<li><strong>Override by DEXT configuration:</strong> If debouncing parameters are declared in the DEXT, Diagnostic Management completely ignores any values from the monitor constructor <a class="spec-record-ref" data-req="SWS_DM_01099" href="../spec/record.html?id=SWS_DM_01099">[SWS_DM_01099]</a>. A misconfiguration in the DEXT can thus result in changes maintained in the source code to <code>CounterBased</code> remaining without effect, without a compiler or runtime error being signaled.</li>
<li><strong>Saturation of the debouncing counter:</strong> If the internal counter exceeds the threshold <code>failedThreshold</code> after incrementation, the DM strictly limits the counter value to this threshold <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>. Unlimited further counting or an integer overflow is thereby prevented.</li>
<li><strong>Inconsistent value assignment:</strong> Interpretation: The structure <code>CounterBased</code> has no integrated validation functions. If implausible values are configured (such as <code>failedStepsize == 0</code> or thresholds where <code>failedThreshold &lt;= passedThreshold</code> is), this is presumably likely to lead to malfunctions only during further processing in the DM or at runtime, since the struct stores the values unchecked.</li>
</ul>
