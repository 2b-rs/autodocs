<div class="ai-level" data-ai-level="2">
<p>Die Template-Klasse <code>ara::phm::SupervisedEntity</code> dient der Funktionsüberwachung im Platform Health Management und ermöglicht Anwendungen das Melden definierter Checkpoints <a class="spec-record-ref" data-req="SWS_PHM_01127" href="../spec/record.html?id=SWS_PHM_01127">[SWS_PHM_01127]</a>. Die Instanz ist an einen <code>InstanceSpecifier</code> gebunden, verschiebbar, aber nicht kopierbar <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a>, <a class="spec-record-ref" data-req="SWS_PHM_01212" href="../spec/record.html?id=SWS_PHM_01212">[SWS_PHM_01212]</a>. Während <code>ReportCheckpoint()</code> threadsicher ist, sind die asynchrone Aktivierung via <code>Enable()</code>, die Deaktivierung via <code>Disable()</code> und der Destruktor nicht threadsicher <a class="spec-record-ref" data-req="SWS_PHM_01130" href="../spec/record.html?id=SWS_PHM_01130">[SWS_PHM_01130]</a>, <a class="spec-record-ref" data-req="SWS_PHM_01211" href="../spec/record.html?id=SWS_PHM_01211">[SWS_PHM_01211]</a>.</p>

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::phm::SupervisedEntity</code> repräsentiert eine zu überwachende Funktionseinheit im Platform Health Management (PHM) von AUTOSAR Adaptive <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a>. Sie dient einer Applikation als Schnittstelle, um das Erreichen definierter Kontrollpunkte (Checkpoints) an das PHM zu melden <a class="spec-record-ref" data-req="SWS_PHM_01127" href="../spec/record.html?id=SWS_PHM_01127">[SWS_PHM_01127]</a>. Anhand der gemeldeten Checkpoints überwacht das PHM-Subsystem das zeitliche und logische Verhalten der Entität. Die Zuordnung zur Architektur und den zugehörigen Modellierungselementen erfolgt über einen <code>ara::core::InstanceSpecifier</code>, der auf einen entsprechenden Port verweist <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a>. Zudem gestattet die Klasse der Anwendung, die Überwachung bei Bedarf gezielt zu aktivieren oder zu deaktivieren <a class="spec-record-ref" data-req="SWS_PHM_01130" href="../spec/record.html?id=SWS_PHM_01130">[SWS_PHM_01130]</a>, <a class="spec-record-ref" data-req="SWS_PHM_01380" href="../spec/record.html?id=SWS_PHM_01380">[SWS_PHM_01380]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Ein Objekt vom Typ <code>ara::phm::SupervisedEntity</code> wird explizit unter Angabe eines <code>ara::core::InstanceSpecifier</code> instanziiert <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a>. Die Klasse implementiert eine Move-Semantik: Der Move-Konstruktor <a class="spec-record-ref" data-req="SWS_PHM_01214" href="../spec/record.html?id=SWS_PHM_01214">[SWS_PHM_01214]</a> sowie der Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_PHM_01215" href="../spec/record.html?id=SWS_PHM_01215">[SWS_PHM_01215]</a> übertragen die Ressource und sind als threadsicher und ausnahmesicher spezifiziert. Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_PHM_01212" href="../spec/record.html?id=SWS_PHM_01212">[SWS_PHM_01212]</a> und Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_PHM_01213" href="../spec/record.html?id=SWS_PHM_01213">[SWS_PHM_01213]</a> sind gelöscht (<code>delete</code>), sodass Instanzen an ihren Besitzer gebunden bleiben. Der Destruktor <code>~SupervisedEntity()</code> gibt die Entität frei und ist als nicht threadsicher deklariert <a class="spec-record-ref" data-req="SWS_PHM_01211" href="../spec/record.html?id=SWS_PHM_01211">[SWS_PHM_01211]</a>; die Zerstörung muss daher synchronisiert erfolgen, wenn mehrere Threads beteiligt sind.</p>
<p>Nach der Erzeugung kann die Überwachung über <code>Enable()</code> <a class="spec-record-ref" data-req="SWS_PHM_01130" href="../spec/record.html?id=SWS_PHM_01130">[SWS_PHM_01130]</a> eingeschaltet bzw. über <code>Disable()</code> <a class="spec-record-ref" data-req="SWS_PHM_01380" href="../spec/record.html?id=SWS_PHM_01380">[SWS_PHM_01380]</a> ausgesetzt werden. Beide Steuerungsfunktionen liefern ein <code>ara::core::Future&lt;void&gt;</code> zurück und sind nicht threadsicher, während das reguläre Melden von Checkpoints über <code>ReportCheckpoint()</code> threadsicher ausgeführt werden kann <a class="spec-record-ref" data-req="SWS_PHM_01127" href="../spec/record.html?id=SWS_PHM_01127">[SWS_PHM_01127]</a>.</p>

<p>Zunächst instanziiert die Anwendung das Objekt mit dem konfigurierten <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a>. Falls die Überwachung aktiviert werden soll (abhängig vom Zustand der Funktionsgruppe), ruft die Anwendung <code>Enable()</code> auf und synchronisiert sich bei Bedarf über das zurückgegebene <code>ara::core::Future&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_PHM_01130" href="../spec/record.html?id=SWS_PHM_01130">[SWS_PHM_01130]</a>. Während der Ausführung meldet die Anwendung erreichte Kontrollpunkte über <code>ReportCheckpoint(checkpointId)</code> <a class="spec-record-ref" data-req="SWS_PHM_01127" href="../spec/record.html?id=SWS_PHM_01127">[SWS_PHM_01127]</a>. Vor dem Beenden oder bei Funktionszustandswechseln kann die Überwachung über <code>Disable()</code> ausgesetzt werden <a class="spec-record-ref" data-req="SWS_PHM_01380" href="../spec/record.html?id=SWS_PHM_01380">[SWS_PHM_01380]</a>, bevor die Instanz schließlich zerstört wird <a class="spec-record-ref" data-req="SWS_PHM_01211" href="../spec/record.html?id=SWS_PHM_01211">[SWS_PHM_01211]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Fehlerbedingungen werden in <code>ara::phm::SupervisedEntity</code> primär über asynchrone Fehlercodes in Rückgabewerten sowie über gemeldete Systemverletzungen (Violations) signalisiert:</p>
<ul>
  <li><strong>Laufzeitfehler bei Zustandssteuerung:</strong> Versucht ein Aufrufer <code>Enable()</code> <a class="spec-record-ref" data-req="SWS_PHM_01130" href="../spec/record.html?id=SWS_PHM_01130">[SWS_PHM_01130]</a> oder <code>Disable()</code> <a class="spec-record-ref" data-req="SWS_PHM_01380" href="../spec/record.html?id=SWS_PHM_01380">[SWS_PHM_01380]</a> aufzurufen, während bereits eine Anforderung zur Aktivierung oder Deaktivierung läuft, scheitert der Aufruf. Das resultierende <code>ara::core::Future</code> meldet in diesem Fall den Fehlercode <code>PhmErrc::kServiceNotReady</code> (Rollback-Semantik).</li>
  <li><strong>Konstruktionsverletzungen:</strong> Beim Aufruf des Konstruktors <a class="spec-record-ref" data-req="SWS_PHM_01123" href="../spec/record.html?id=SWS_PHM_01123">[SWS_PHM_01123]</a> werden strenge Vorbedingungen geprüft:
    <ul>
      <li><code>AraNotInitializedViolation</code>: Die ARA-Laufzeitumgebung ist noch nicht initialisiert.</li>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: Der Bezeichner kann im Kontext der Executable nicht aufgelöst werden oder verweist nicht auf einen <code>PortPrototype</code>.</li>
      <li><code>PortInterfaceMappingViolation</code>: Der mit <code>PhmSupervisedEntityInterface</code> typisierte <code>PortPrototype</code> wird von keinem <code>SupervisionCheckpoint</code> referenziert.</li>
      <li><code>ProcessMappingViolation</code>: Der aufrufende Prozess ist im Modell nicht für die entsprechenden Kontrollpunkte autorisiert.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: Der Bezeichner wird im selben Prozess bereits von einer anderen Instanz verwendet.</li>
    </ul>
  </li>
  <li><strong>Verletzung bei Checkpoint-Meldung:</strong> Wird <code>ReportCheckpoint()</code> von einem Prozess aufgerufen, der im Modell nicht über <code>SupervisionCheckpoint.process</code> zugeordnet ist, führt dies zu einer <code>InsufficientPermissionsViolation</code> <a class="spec-record-ref" data-req="SWS_PHM_01127" href="../spec/record.html?id=SWS_PHM_01127">[SWS_PHM_01127]</a>.</li>
</ul>
