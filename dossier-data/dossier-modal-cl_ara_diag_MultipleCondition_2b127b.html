<h4>Context</h4>
<p>The class <code>ara::diag::MultipleCondition</code> (<a class="spec-record-ref" data-req="SWS_DM_01730" href="../spec/record.html?id=SWS_DM_01730">[SWS_DM_01730]</a>) provides a bundled interface for managing multiple diagnostic conditions (Diagnostic Conditions) in the module <em>diag</em> of the AUTOSAR Adaptive Platform. While individual conditions are typically mapped via the class <code>ara::diag::Condition</code>, <code>ara::diag::MultipleCondition</code> enables the control and querying of multiple conditions via a common port interface (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>).</p>
<p>Functionally, both interfaces have the same semantics and offer similar operations (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>). The essential difference is that in <code>ara::diag::MultipleCondition</code>, each operation accepts an additional identifier of type <code>ConditionHandleType</code> (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>).</p>
<p>The central interaction partners of the class include:</p>
<ul>
<li><strong>Adaptive Application</strong>: Instantiates the class and controls the states of the assigned conditions using <code>SetCondition</code> or reads them out via <code>GetCondition</code> (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>).</li>
<li><strong>Diagnostic Management (DM)</strong>: Acts as a platform subsystem, processes state changes, and provides the condition information for diagnostic workflows (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>).</li>
<li><strong>Manifest modeling</strong>: Each <code>DiagnosticCondition</code> defined in the system requires a mapping via a <code>DiagnosticMultipleConditionPortMapping</code> to specify that the multiple condition interface can be used for this condition (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>). The assigned <code>PortPrototype</code> must strictly be typed by a <code>DiagnosticMultipleConditionInterface</code> (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance is created via the explicit constructor <code>MultipleCondition(const ara::core::InstanceSpecifier &amp;specifier)</code> (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>). During instantiation, the object is bound to the <code>PortPrototype</code> referenced by the <code>InstanceSpecifier</code>. The constructor is specified to be exception-safe (<em>exception safe</em>) and thread-safe (<em>thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>).</p>
<p>Regarding ownership and transferability, the class is strictly bound to its place of creation:</p>
<ul>
<li>The copy constructor is deleted: <code>MultipleCondition(MultipleCondition &amp;) = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02072" href="../spec/record.html?id=SWS_DM_02072">[SWS_DM_02072]</a>).</li>
<li>The copy assignment operator is deleted: <code>operator=(MultipleCondition &amp;) = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02073" href="../spec/record.html?id=SWS_DM_02073">[SWS_DM_02073]</a>).</li>
<li>The move constructor is deleted: <code>MultipleCondition(MultipleCondition &amp;&amp;) noexcept = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02071" href="../spec/record.html?id=SWS_DM_02071">[SWS_DM_02071]</a>).</li>
<li>The move assignment operator is deleted: <code>operator=(MultipleCondition &amp;&amp;) = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02074" href="../spec/record.html?id=SWS_DM_02074">[SWS_DM_02074]</a>).</li>
</ul>
<p>Instances of <code>ara::diag::MultipleCondition</code> can thus be neither copied nor moved (<em>pinned object</em>). They must remain at a fixed memory address throughout their entire period of use.</p>
<p>Destruction takes place via the destructor <code>~MultipleCondition() noexcept</code> (<a class="spec-record-ref" data-req="SWS_DM_01737" href="../spec/record.html?id=SWS_DM_01737">[SWS_DM_01737]</a>). This is exception-safe, but explicitly declared as <em>not thread-safe</em> (<a class="spec-record-ref" data-req="SWS_DM_01737" href="../spec/record.html?id=SWS_DM_01737">[SWS_DM_01737]</a>). The calling application must therefore ensure that no concurrent accesses to the object take place during the destruction process.</p>
<p>For the thread safety of ongoing operations (<code>GetCondition</code> and <code>SetCondition</code>), conditional synchronization (<em>conditional thread-safety</em>) applies: Whether the methods must be implemented thread-safe or not thread-safe is determined by the <code>ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>). Interpretation: Since the C++ constructor in <a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a> does not feature a <code>ConcurrencyType</code> argument, this property is likely configured in the software design via the port model and evaluated via the <code>InstanceSpecifier</code>.</p>

<h4>Usage Path</h4>
<p>The typical sequence for using <code>ara::diag::MultipleCondition</code> is divided into the phases of instantiation, identification of the individual condition, and execution of write and read operations:</p>
<ol>
<li><strong>Instantiation and port binding</strong>: The application instantiates <code>MultipleCondition</code> specifying the matching <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>).</li>
<li><strong>Condition addressing via handles</strong>: The individual conditions are addressed via numerical values of type <code>ConditionHandleType</code> (<a class="spec-record-ref" data-req="SWS_DM_01735" href="../spec/record.html?id=SWS_DM_01735">[SWS_DM_01735]</a>). Unless a <code>DiagnosticMultipleConditionPortMapping.overrideId</code> is defined in the model, the Diagnostic Manager assigns handles in alphabetical order of the <code>DiagnosticCondition</code> short name starting at <code>0x010000</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>).</li>
<li><strong>Set state (SetCondition)</strong>: The application updates the status of a condition synchronously via <code>SetCondition(conditionHandle, condition)</code> (<a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>). The call returns a <code>ara::core::Result&lt;void&gt;</code> informing about success or failure.</li>
<li><strong>Query state (GetCondition)</strong>: To read out the current status, the application calls <code>GetCondition(conditionHandle)</code> (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>). The call returns a <code>ara::core::Future&lt;ConditionType&gt;</code>. The application can subsequently resolve and evaluate the result asynchronously.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error cases when working with <code>ara::diag::MultipleCondition</code> are divided into configuration and modeling violations during instantiation as well as runtime errors during method calls:</p>
<ul>
<li><strong>Initialization errors (violations)</strong> (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>):
<ul>
