<div class="ai-level" data-ai-level="2">
<p>Die Template-Klasse kapselt die speicherressourcenbasierte dynamische Allokation für adaptive Anwendungen und Container als vollständig ausnahmefreie Implementierung polymorpher Allokatoren <a class="spec-record-ref" data-req="SWS_CORE_06541" href="../spec/record.html?id=SWS_CORE_06541">[SWS_CORE_06541]</a>. Zur flexiblen Steuerung des Objektlebenszyklus delegiert die Instanz sämtliche Speicheranforderungen an eine austauschbare Speicherressource, wobei fehlgeschlagene Allokationen deterministisch Nullzeiger anstelle von C++-Exceptions zurückliefern <a class="spec-record-ref" data-req="SWS_CORE_06547" href="../spec/record.html?id=SWS_CORE_06547">[SWS_CORE_06547]</a>. Als wesentliche funktionale Randbedingungen ist die reguläre Kopierzuweisung explizit unterbunden, während fehlerhafte Freigabeoperationen im laufenden Betrieb stets stillschweigend ignoriert werden.</p>

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::PolymorphicAllocator</code> realisiert in AUTOSAR Adaptive die Schnittstelle zur zustandsbehafteten, polymorphen Speicherallokation gemäß dem C++-Standardmuster und definiert den zugrunde liegenden Elementtyp <code>value_type</code> <a class="spec-record-ref" data-req="SWS_CORE_06572" href="../spec/record.html?id=SWS_CORE_06572">[SWS_CORE_06572]</a>. Sie vermittelt als Adapter zwischen aufrufenden Komponenten – wie Containern oder Anwendungsstrukturen – und einer konkreten Speicherressource. Über die Methode <code>resource()</code> lässt sich der Zeiger auf die genutzte <code>MemoryResource</code> jederzeit abfragen <a class="spec-record-ref" data-req="SWS_CORE_06557" href="../spec/record.html?id=SWS_CORE_06557">[SWS_CORE_06557]</a>. Durch diese Kapselung wird die Anforderung von Speicher semantisch von der konkreten Implementierung der Speicherverwaltung getrennt.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen des Allokators werden entweder standardmäßig <a class="spec-record-ref" data-req="SWS_CORE_06541" href="../spec/record.html?id=SWS_CORE_06541">[SWS_CORE_06541]</a> oder mit einem Zeiger auf eine spezifische <code>MemoryResource</code> konstruiert <a class="spec-record-ref" data-req="SWS_CORE_06542" href="../spec/record.html?id=SWS_CORE_06542">[SWS_CORE_06542]</a>. Da der Allokator die Speicherressource lediglich referenziert, liegt die Verantwortung für deren Lebensdauer vermutlich beim Aufrufer. Neben dem regulären Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_06543" href="../spec/record.html?id=SWS_CORE_06543">[SWS_CORE_06543]</a> gestattet ein Konvertierungskonstruktor die Initialisierung aus Allokatoren für andere Elementtypen <code>U</code> <a class="spec-record-ref" data-req="SWS_CORE_06544" href="../spec/record.html?id=SWS_CORE_06544">[SWS_CORE_06544]</a>.</p>
<p>In Bezug auf Eigentumsübergänge ist der reguläre Kopierzuweisungsoperator gelöscht (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_CORE_06545" href="../spec/record.html?id=SWS_CORE_06545">[SWS_CORE_06545]</a>. Demgegenüber definiert AUTOSAR explizit einen Move-Konstruktor <a class="spec-record-ref" data-req="SWS_CORE_06546" href="../spec/record.html?id=SWS_CORE_06546">[SWS_CORE_06546]</a> sowie einen Standard-Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00066" href="../spec/record.html?id=SWS_CORE_00066">[SWS_CORE_00066]</a>. Bei Kopieroperationen von Containern erzeugt die Methode <code>select_on_container_copy_construction()</code> eine entsprechende Allokator-Instanz <a class="spec-record-ref" data-req="SWS_CORE_06573" href="../spec/record.html?id=SWS_CORE_06573">[SWS_CORE_06573]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit sind die Standard- und Konvertierungskonstruktoren sowie die Abfrage der Speicherressource als thread-safe spezifiziert (<a class="spec-record-ref" data-req="SWS_CORE_06541" href="../spec/record.html?id=SWS_CORE_06541">[SWS_CORE_06541]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06542" href="../spec/record.html?id=SWS_CORE_06542">[SWS_CORE_06542]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06544" href="../spec/record.html?id=SWS_CORE_06544">[SWS_CORE_06544]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06557" href="../spec/record.html?id=SWS_CORE_06557">[SWS_CORE_06557]</a>). Dagegen sind Move-Operationen (<a class="spec-record-ref" data-req="SWS_CORE_06546" href="../spec/record.html?id=SWS_CORE_06546">[SWS_CORE_06546]</a>), Kopierselektionen (<a class="spec-record-ref" data-req="SWS_CORE_06573" href="../spec/record.html?id=SWS_CORE_06573">[SWS_CORE_06573]</a>) sowie alle Allokations-, Konstruktions- und Deallokationsoperationen als nicht thread-safe deklariert.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Bereitstellung von Speicher, die Konstruktion von Objekten sowie deren spätere Zerstörung und Freigabe:</p>
<ul>
<li><strong>Speicherallokation:</strong> Rohspeicher für <code>n</code> Objekte des Typs <code>Tp</code> wird mittels <code>allocate()</code> angefordert <a class="spec-record-ref" data-req="SWS_CORE_06547" href="../spec/record.html?id=SWS_CORE_06547">[SWS_CORE_06547]</a>. Alternativ stehen <code>allocate_bytes()</code> für bytegenaue Allokation mit Ausrichtung <a class="spec-record-ref" data-req="SWS_CORE_06549" href="../spec/record.html?id=SWS_CORE_06549">[SWS_CORE_06549]</a> sowie das Template <code>allocate_object()</code> für typisierte Allokationen bereit <a class="spec-record-ref" data-req="SWS_CORE_06551" href="../spec/record.html?id=SWS_CORE_06551">[SWS_CORE_06551]</a>.</li>
<li><strong>Objektinitialisierung:</strong> Die Methode <code>construct()</code> erzeugt Objekte auf dem zuvor allokierten Speicherbereich <a class="spec-record-ref" data-req="SWS_CORE_06555" href="../spec/record.html?id=SWS_CORE_06555">[SWS_CORE_06555]</a>. Als kombinierte Operation bietet <code>new_object()</code> die Allokation und In-Place-Konstruktion in einem Aufruf <a class="spec-record-ref" data-req="SWS_CORE_06553" href="../spec/record.html?id=SWS_CORE_06553">[SWS_CORE_06553]</a>.</li>
<li><strong>Destruktion und Freigabe:</strong> Die Zerstörung erfolgt über <code>destroy()</code> <a class="spec-record-ref" data-req="SWS_CORE_06556" href="../spec/record.html?id=SWS_CORE_06556">[SWS_CORE_06556]</a>, gefolgt von der Freigabe über <code>deallocate()</code> <a class="spec-record-ref" data-req="SWS_CORE_06548" href="../spec/record.html?id=SWS_CORE_06548">[SWS_CORE_06548]</a>, <code>deallocate_bytes()</code> <a class="spec-record-ref" data-req="SWS_CORE_06550" href="../spec/record.html?id=SWS_CORE_06550">[SWS_CORE_06550]</a> oder <code>deallocate_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06552" href="../spec/record.html?id=SWS_CORE_06552">[SWS_CORE_06552]</a>. Beides lässt sich alternativ mit <code>delete_object()</code> zusammenfassen <a class="spec-record-ref" data-req="SWS_CORE_06554" href="../spec/record.html?id=SWS_CORE_06554">[SWS_CORE_06554]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Klasse unterscheidet sich in wesentlichen Fehlerbehandlungsmechanismen vom ISO-C++-Standard, um strenge Anforderungen an ausnahmefreie Systeme zu erfüllen:</p>
<ul>
<li><strong>Ausbleiben von Exceptions bei Allokation:</strong> Sämtliche Allokationsmethoden (<code>allocate()</code> <a class="spec-record-ref" data-req="SWS_CORE_06547" href="../spec/record.html?id=SWS_CORE_06547">[SWS_CORE_06547]</a>, <code>allocate_bytes()</code> <a class="spec-record-ref" data-req="SWS_CORE_06549" href="../spec/record.html?id=SWS_CORE_06549">[SWS_CORE_06549]</a> und <code>allocate_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06551" href="../spec/record.html?id=SWS_CORE_06551">[SWS_CORE_06551]</a>) sind <code>noexcept</code>. Schlägt eine Speicherreservierung fehl, wird anstelle einer Ausnahme ein <code>nullptr</code> zurückgegeben. Der Aufrufer dürfte den Zeiger zwingend vor der weiteren Nutzung validieren müssen.</li>
<li><strong>Bedingte Ausnahmesicherheit:</strong> Konstruktions- und Destruktionsroutinen (<code>construct()</code> <a class="spec-record-ref" data-req="SWS_CORE_06555" href="../spec/record.html?id=SWS_CORE_06555">[SWS_CORE_06555]</a>, <code>destroy()</code> <a class="spec-record-ref" data-req="SWS_CORE_06556" href="../spec/record.html?id=SWS_CORE_06556">[SWS_CORE_06556]</a>, <code>new_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06553" href="../spec/record.html?id=SWS_CORE_06553">[SWS_CORE_06553]</a> und <code>delete_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06554" href="../spec/record.html?id=SWS_CORE_06554">[SWS_CORE_06554]</a>) sind bedingt <code>noexcept</code>, abhängig von <code>std::is_nothrow_constructible</code> bzw. <code>std::is_nothrow_destructible</code> der betroffenen Typen. Bei Fehlschlag von <code>new_object()</code> wird ebenfalls <code>nullptr</code> zurückgeliefert <a class="spec-record-ref" data-req="SWS_CORE_06553" href="../spec/record.html?id=SWS_CORE_06553">[SWS_CORE_06553]</a>.</li>
<li><strong>Fehlerunterdrückung bei Deallokation:</strong> Schlagen Freigabeoperationen fehl, werden aufgetretene Fehler in <code>deallocate()</code> <a class="spec-record-ref" data-req="SWS_CORE_06548" href="../spec/record.html?id=SWS_CORE_06548">[SWS_CORE_06548]</a>, <code>deallocate_bytes()</code> <a class="spec-record-ref" data-req="SWS_CORE_06550" href="../spec/record.html?id=SWS_CORE_06550">[SWS_CORE_06550]</a>, <code>deallocate_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06552" href="../spec/record.html?id=SWS_CORE_06552">[SWS_CORE_06552]</a> und <code>delete_object()</code> <a class="spec-record-ref" data-req="SWS_CORE_06554" href="../spec/record.html?id=SWS_CORE_06554">[SWS_CORE_06554]</a> ausnahmslos stillschweigend ignoriert.</li>
</ul>
