<h4>Context</h4>
<p>The template class <code>ara::per::SharedHandle</code> serves in the persistence module (<code>ara::per</code>) as a smart access handle to instances of the file or key-value storage. As a generic abstraction (<code>template &lt;typename T&gt; class SharedHandle final</code>), the class encapsulates the managed storage resource of type <code>T</code> and is provided as the return type of the functions <code>OpenFileStorage()</code> and <code>OpenKeyValueStorage()</code>.</p>
<p>The primary task of <code>SharedHandle</code> is to enable the as-needed exchange of storage handles between different execution threads (<em>“can be passed between threads as needed”</em>). At the same time, the class provides the necessary abstraction to ensure a thread-safe implementation of the storage opening functions <code>OpenFileStorage()</code> and <code>OpenKeyValueStorage()</code>. The central interaction partners are calling application threads, the storage-creating factory functions, and the encapsulated storage object.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a <code>SharedHandle</code> typically begins with its return by <code>OpenFileStorage()</code> or <code>OpenKeyValueStorage()</code>. Alternatively, a handle can be created from an existing instance via the copy constructor <a class="spec-record-ref" data-req="SWS_PER_00369" href="../spec/record.html?id=SWS_PER_00369">[SWS_PER_00369]</a>. Interpretation: The class likely realizes a shared-ownership concept in which multiple handle instances jointly reference the same underlying storage.</p>
<p>In terms of its state, a handle is either in a valid state (when it represents a valid object of the template class) or in an empty state <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a>. In particular, a handle transitions to the empty state when it is used as a source (<code>sh</code>) in a move construction <a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a> or a move assignment <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>. In both cases, the source object is invalidated and may no longer be used for storage accesses <a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a>, <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>. An empty handle can be returned to the valid state by a copy assignment <a class="spec-record-ref" data-req="SWS_PER_00370" href="../spec/record.html?id=SWS_PER_00370">[SWS_PER_00370]</a> or a move assignment <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a> with a valid handle.</p>
<p>The release of the handle instance occurs deterministically via the destructor <code>~SharedHandle()</code> <a class="spec-record-ref" data-req="SWS_PER_00568" href="../spec/record.html?id=SWS_PER_00568">[SWS_PER_00568]</a> upon leaving the respective scope. For concurrency, a clear distinction applies: Querying the state via <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a> as well as dereferencing via <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_PER_00402" href="../spec/record.html?id=SWS_PER_00402">[SWS_PER_00402]</a>, <a class="spec-record-ref" data-req="SWS_PER_00403" href="../spec/record.html?id=SWS_PER_00403">[SWS_PER_00403]</a> and <code>operator-&gt;()</code> <a class="spec-record-ref" data-req="SWS_PER_00363" href="../spec/record.html?id=SWS_PER_00363">[SWS_PER_00363]</a>, <a class="spec-record-ref" data-req="SWS_PER_00364" href="../spec/record.html?id=SWS_PER_00364">[SWS_PER_00364]</a> are thread-safe (<code>thread-safe</code>). In contrast, modifying operations on the same handle instance—namely the assignment operators <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>, <a class="spec-record-ref" data-req="SWS_PER_00370" href="../spec/record.html?id=SWS_PER_00370">[SWS_PER_00370]</a> and the destructor <a class="spec-record-ref" data-req="SWS_PER_00568" href="../spec/record.html?id=SWS_PER_00568">[SWS_PER_00568]</a>—are specified as not thread-safe (<code>not thread-safe</code>).</p>

<h4>Usage Path</h4>
<p>A typical usage path for <code>SharedHandle</code> comprises the following steps:</p>
<ol>
<li><strong>Obtain handle:</strong> The application calls <code>OpenFileStorage()</code> or <code>OpenKeyValueStorage()</code> and receives the resulting instance of <code>SharedHandle&lt;T&gt;</code>.</li>
<li><strong>Check state:</strong> Prior to using access operators, the state is checked via the explicit conversion operator <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a>. This step is mandatory, especially after preceding move operations <a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a>, <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>.</li>
<li><strong>Access storage object:</strong> Via <code>operator*()</code>, the application receives a reference to the underlying object (non-const <a class="spec-record-ref" data-req="SWS_PER_00402" href="../spec/record.html?id=SWS_PER_00402">[SWS_PER_00402]</a> or const <a class="spec-record-ref" data-req="SWS_PER_00403" href="../spec/record.html?id=SWS_PER_00403">[SWS_PER_00403]</a>). Via the arrow operator <code>operator-&gt;()</code>, member functions of the encapsulated storage class can be executed directly (non-const <a class="spec-record-ref" data-req="SWS_PER_00363" href="../spec/record.html?id=SWS_PER_00363">[SWS_PER_00363]</a> or const <a class="spec-record-ref" data-req="SWS_PER_00364" href="../spec/record.html?id=SWS_PER_00364">[SWS_PER_00364]</a>).</li>
<li><strong>Thread transfer (optional):</strong> For division of labor, the handle can be copied (<a class="spec-record-ref" data-req="SWS_PER_00369" href="../spec/record.html?id=SWS_PER_00369">[SWS_PER_00369]</a>, <a class="spec-record-ref" data-req="SWS_PER_00370" href="../spec/record.html?id=SWS_PER_00370">[SWS_PER_00370]</a>) or moved (<a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a>, <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>) and passed to other threads.</li>
<li><strong>Resource cleanup:</strong> At the end of its lifetime, the handle instance is destroyed by <code>~SharedHandle()</code> <a class="spec-record-ref" data-req="SWS_PER_00568" href="../spec/record.html?id=SWS_PER_00568">[SWS_PER_00568]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using <code>SharedHandle</code>, the following preconditions and error scenarios must be observed:</p>
<ul>
<li><strong>Undefined behavior with empty handle:</strong> Calling operators other than <code>operator bool()</code> on an empty or invalidated handle leads to undefined behavior (<em>“undefined behavior”</em>) <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a>. Therefore, the specification requires checking the state by means of <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a>, <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a> before using further operators.</li>
<li><strong>Usage after move operation:</strong> As soon as a handle has been passed as an argument to the move constructor <a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a> or the move assignment operator <a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>, the source object is invalid and may no longer be used for storage accesses.</li>
<li><strong>Exception safety:</strong> All member functions of <code>SharedHandle</code>—constructors (<a class="spec-record-ref" data-req="SWS_PER_00367" href="../spec/record.html?id=SWS_PER_00367">[SWS_PER_00367]</a>, <a class="spec-record-ref" data-req="SWS_PER_00369" href="../spec/record.html?id=SWS_PER_00369">[SWS_PER_00369]</a>), assignment operators (<a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>, <a class="spec-record-ref" data-req="SWS_PER_00370" href="../spec/record.html?id=SWS_PER_00370">[SWS_PER_00370]</a>), dereferencing operators (<a class="spec-record-ref" data-req="SWS_PER_00363" href="../spec/record.html?id=SWS_PER_00363">[SWS_PER_00363]</a>, <a class="spec-record-ref" data-req="SWS_PER_00364" href="../spec/record.html?id=SWS_PER_00364">[SWS_PER_00364]</a>, <a class="spec-record-ref" data-req="SWS_PER_00402" href="../spec/record.html?id=SWS_PER_00402">[SWS_PER_00402]</a>, <a class="spec-record-ref" data-req="SWS_PER_00403" href="../spec/record.html?id=SWS_PER_00403">[SWS_PER_00403]</a>), status check <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a>, and destructor <a class="spec-record-ref" data-req="SWS_PER_00568" href="../spec/record.html?id=SWS_PER_00568">[SWS_PER_00568]</a>—are annotated with <code>noexcept</code> and declared as <code>exception safe</code>. Error states are therefore not expressed in C++ exceptions, but in the logical handle state (<code>operator bool() == false</code>).</li>
<li><strong>Data races during assignment or destruction:</strong> While read accesses to the referenced storage object are thread-safe (<a class="spec-record-ref" data-req="SWS_PER_00363" href="../spec/record.html?id=SWS_PER_00363">[SWS_PER_00363]</a>, <a class="spec-record-ref" data-req="SWS_PER_00364" href="../spec/record.html?id=SWS_PER_00364">[SWS_PER_00364]</a>, <a class="spec-record-ref" data-req="SWS_PER_00402" href="../spec/record.html?id=SWS_PER_00402">[SWS_PER_00402]</a>, <a class="spec-record-ref" data-req="SWS_PER_00403" href="../spec/record.html?id=SWS_PER_00403">[SWS_PER_00403]</a>, <a class="spec-record-ref" data-req="SWS_PER_00398" href="../spec/record.html?id=SWS_PER_00398">[SWS_PER_00398]</a>), assignments (<a class="spec-record-ref" data-req="SWS_PER_00368" href="../spec/record.html?id=SWS_PER_00368">[SWS_PER_00368]</a>, <a class="spec-record-ref" data-req="SWS_PER_00370" href="../spec/record.html?id=SWS_PER_00370">[SWS_PER_00370]</a>) and destruction <a class="spec-record-ref" data-req="SWS_PER_00568" href="../spec/record.html?id=SWS_PER_00568">[SWS_PER_00568]</a> on the same handle instance must not be executed concurrently without protection.</li>
</ul>
