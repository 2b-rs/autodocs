<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient dem gepufferten Schreiben von Binär- und Textdateien sowie deren Synchronisation auf den physischen Speicher.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::per::WriteAccessor</code> ermöglicht das Schreiben binärer oder textueller Dateiinhalte im Persistenzmodul und stellt Methoden für unformatierte Schreibzugriffe sowie einen formatierten Stream-Operator bereit <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>. Da Schreibvorgänge zunächst im Betriebssystem gepuffert werden können, erzwingt der Aufruf von <code>SyncToFile()</code> das dauerhafte Flashen auf den physischen Speicher <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>. Sämtliche Methoden sind ausnahmesicher, jedoch nicht threadsicher, weshalb nebenläufige Zugriffe durch die Anwendung geschützt werden müssen.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p><code>ara::per::WriteAccessor</code> ist eine finale Klasse des Persistenzmoduls (<code>per</code>) der AUTOSAR Adaptive Platform und leitet virtuell von <code>FileAccessor</code> ab. Die Klasse stellt Schreiboperationen für Dateiinhalte bereit. Sie bietet Methoden für unformatiertes, kontrolliertes Schreiben mit Fehlerbehandlung über <code>ara::core::Result</code> sowie einen überladenen Stream-Operator für formatiertes Schreiben. Als Interaktionspartner fungieren die aufrufende Anwendung, der interne Dateipuffer des Betriebssystems sowie das physische Speichermedium.</p>

<h4>Lebenszyklus</h4>
<p>Der Standardkonstruktor von <code>WriteAccessor</code> ist explizit gelöscht und darf nicht verwendet werden <a class="spec-record-ref" data-req="SWS_PER_00596" href="../spec/record.html?id=SWS_PER_00596">[SWS_PER_00596]</a>. (Interpretation: Instanzen von <code>WriteAccessor</code> dürften über Fabrikmethoden übergeordneter Persistenz-Verwaltungseinheiten wie dem File-Storage erzeugt und bereitgestellt werden.)</p>
<p>Die Zerstörung erfolgt über den virtuellen Destruktor <code>~WriteAccessor()</code> <a class="spec-record-ref" data-req="SWS_PER_00597" href="../spec/record.html?id=SWS_PER_00597">[SWS_PER_00597]</a>. Die Klasse und ihre Methoden sind als ausnahmesicher („exception safe“) spezifiziert und als <code>noexcept</code> deklariert. Bezüglich der Nebenläufigkeit ist <code>WriteAccessor</code> nicht threadsicher („not thread-safe“) <a class="spec-record-ref" data-req="SWS_PER_00597" href="../spec/record.html?id=SWS_PER_00597">[SWS_PER_00597]</a>; parallele Zugriffe auf dieselbe Instanz müssen von der Anwendung extern abgesichert werden.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst das Schreiben von Daten in unformatiertem oder formatiertem Modus, das optionale Anpassen der Dateigröße und die abschließende persistente Speicherung:</p>
<ul>
<li><strong>Binärdaten schreiben:</strong> Über <code>WriteBinary()</code> wird ein Byte-Bereich (<code>ara::core::Span&lt;const ara::core::Byte&gt;</code>) in die Datei geschrieben <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>.</li>
<li><strong>Textdaten schreiben:</strong> Mittels <code>WriteText()</code> werden Zeichenketten über einen <code>ara::core::StringView</code> übergeben <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>. Ergänzend steht <code>operator&lt;&lt;</code> als Komfortfunktion für unkritische Anwendungsfälle zur Verfügung, wobei auftretende Fehler stillschweigend ignoriert werden <a class="spec-record-ref" data-req="SWS_PER_00125" href="../spec/record.html?id=SWS_PER_00125">[SWS_PER_00125]</a>.</li>
<li><strong>Persistierung erzwingen:</strong> Der Zeitpunkt der physischen Speicherung hängt von der Persistenz-Implementierung ab; <code>SyncToFile()</code> flasht den Puffer des Betriebssystems verbindlich auf das Speichermedium <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>, <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>.</li>
<li><strong>Dateigröße anpassen:</strong> Mit <code>SetFileSize()</code> kann die Datei verkürzt werden, wodurch überstehende Inhalte entfernt werden; die Dateiposition bleibt unverändert oder wird auf die letzte gültige Position bzw. 0 gesetzt <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Methoden <code>WriteBinary()</code>, <code>WriteText()</code>, <code>SyncToFile()</code> und <code>SetFileSize()</code> geben ein <code>ara::core::Result&lt;void&gt;</code> zurück, das bei Fehlschlägen spezifische Fehlercodes enthält:</p>
<ul>
<li><code>PerErrc::kPhysicalStorageFailure</code>: Zugriff auf das physische Speichermedium schlägt fehl <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>, <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>. Der Zustand der Datei ist unbekannt und kann komplett zerstört sein (keine Rollback-Semantik).</li>
<li><code>PerErrc::kOutOfStorageSpace</code>: Unzureichender physischer Speicherplatz <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>. Beim Schreiben wird der überschreitende Anteil verworfen und die Position steht am Dateiende (keine Rollback-Semantik).</li>
<li><code>PerErrc::kQuotaExceeded</code>: Die Datei würde die konfigurierte Maximalgröße (<code>AllowedSize</code>) überschreiten <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a> (Rollback-Semantik).</li>
<li><code>PerErrc::kEncryptionFailed</code>: Ver- oder Entschlüsselung schlägt fehl <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>, <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a>. Puffer und Position werden zwar aktualisiert, die Datei kann aber nicht persistiert werden und spiegelt auf dem Speicher eine ältere Version wider (Rollback-Semantik).</li>
<li><code>PerErrc::kAuthenticationFailed</code>: Berechnung oder Prüfung des MAC schlägt fehl <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00122" href="../spec/record.html?id=SWS_PER_00122">[SWS_PER_00122]</a>, <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a> (Rollback-Semantik).</li>
<li><code>PerErrc::kValidationFailed</code>: Gültigkeit der gespeicherten Daten kann nicht gewährleistet werden <a class="spec-record-ref" data-req="SWS_PER_00423" href="../spec/record.html?id=SWS_PER_00423">[SWS_PER_00423]</a>, <a class="spec-record-ref" data-req="SWS_PER_00166" href="../spec/record.html?id=SWS_PER_00166">[SWS_PER_00166]</a>, <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a> (Rollback-Semantik).</li>
<li><code>PerErrc::kInvalidSize</code>: Die neue Dateigröße bei <code>SetFileSize()</code> ist größer als die aktuelle Dateigröße <a class="spec-record-ref" data-req="SWS_PER_00428" href="../spec/record.html?id=SWS_PER_00428">[SWS_PER_00428]</a> (Rollback-Semantik).</li>
</ul>
