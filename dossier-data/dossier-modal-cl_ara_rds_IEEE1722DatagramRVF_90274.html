<h4>Kontext</h4>
<p>Die Klasse <code>ara::rds::IEEE1722DatagramRVF</code> repräsentiert innerhalb des Funktionsmoduls Raw Data Stream (rds) der AUTOSAR Adaptive Platform ein konkretes IEEE-1722-Datagramm für das Raw Video Format (RVF) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_RawDataStream&amp;page=1">SWS RawDataStream §1 „Raw Data Stream“</a>. Das Raw Video Format dient im Rahmen von Audio Video Bridging (AVB) und Time-Sensitive Networking (TSN) dem Transport unkomprimierter Videoströme über paketbasierte Netzwerke. Definiert wird die Datenstruktur in der Header-Datei <code>ara/rds/raw_data_stream_IEEE1722.h</code> <a class="spec-record-ref" data-req="SWS_RDS_90276" href="../spec/record.html?id=SWS_RDS_90276">[SWS_RDS_90276]</a>. Die Klassendefinition ist mit dem Schlüsselwort <code>final</code> versehen und bindet über geschützte Vererbung (<code>protected</code>) sowohl die generische Basisklasse <code>IEEE1722Datagram</code> als auch <code>AVTPDUCommonStreamHeaderFields</code> ein <a class="spec-record-ref" data-req="SWS_RDS_90276" href="../spec/record.html?id=SWS_RDS_90276">[SWS_RDS_90276]</a>. Durch diese Zusammensetzung vereint die Struktur grundlegende AVTP-Stream-Header-Felder mit den spezifischen Metadatenfeldern, die für die Verarbeitung einzelner Videozeilen und Bildraster erforderlich sind.</p>

<h4>Lebenszyklus</h4>
<p>Der Lebenszyklus einer Instanz von <code>IEEE1722DatagramRVF</code> wird maßgeblich durch die Verarbeitungspipeline des Raw Data Streams bestimmt. Für das saubere Aufräumen von Instanzen deklariert die Klasse einen virtuellen Destruktor <code>virtual ~IEEE1722DatagramRVF() noexcept</code> <a class="spec-record-ref" data-req="SWS_RDS_90292" href="../spec/record.html?id=SWS_RDS_90292">[SWS_RDS_90292]</a>. Obwohl die Klasse selbst als <code>final</code> markiert ist <a class="spec-record-ref" data-req="SWS_RDS_90276" href="../spec/record.html?id=SWS_RDS_90276">[SWS_RDS_90276]</a> und daher nicht als Basisklasse für weiterführende Unterklassen fungieren kann, sichert die virtuelle Auslegung des Destruktors die korrekte Freigabe ab, falls Instanzen polymorph über Basisklassenzeiger referenziert und zerstört werden.</p>
<p>Der Zusatz <code>noexcept</code> am Destruktor garantiert, dass während des Zerstörungsvorgangs unter keinen Umständen Ausnahmen entweichen können <a class="spec-record-ref" data-req="SWS_RDS_90292" href="../spec/record.html?id=SWS_RDS_90292">[SWS_RDS_90292]</a>. Dies ist in sicherheitskritischen automobilen Systemen eine essenzielle Vorbedingung für die Gewährleistung deterministischer Aufräumvorgänge ohne plötzliche Programmabbrüche. Die AUTOSAR-Spezifikation definiert für diese Datenklasse keine expliziten Synchronisationsprimitive für den nebenläufigen Zugriff; daher muss ein thread-sicherer Umgang bei Bedarf auf Ebene der umgebenden Streaming-Dienste sichergestellt werden.</p>

<h4>Nutzungspfad</h4>
<p>Im praktischen Verarbeitungsablauf fungiert die Klasse als Informationsträger für empfangene oder zu sendende Video-Frames. Hierbei bündelt die Struktur zahlreiche Felder, die Bilddimensionen, Zeitbezug und Farbkodierung detailliert beschreiben. Für die geometrische Struktur des Videos stehen die aktiven Pixel <code>active_pixels</code> <a class="spec-record-ref" data-req="SWS_RDS_90276" href="../spec/record.html?id=SWS_RDS_90276">[SWS_RDS_90276]</a>, die Gesamtzahl der Zeilen eines Bildes <code>total_lines</code> <a class="spec-record-ref" data-req="SWS_RDS_90278" href="../spec/record.html?id=SWS_RDS_90278">[SWS_RDS_90278]</a>, die Zeilennummer <code>line_number</code> <a class="spec-record-ref" data-req="SWS_RDS_90291" href="../spec/record.html?id=SWS_RDS_90291">[SWS_RDS_90291]</a> und die Zeilenanzahl pro Datenpaket <code>num_lines</code> <a class="spec-record-ref" data-req="SWS_RDS_90289" href="../spec/record.html?id=SWS_RDS_90289">[SWS_RDS_90289]</a> bereit.</p>
<p>Zur korrekten Interpretation des Pixeldatenstroms kapselt die Klasse zudem systemspezifische Videoformateigenschaften: die Bittiefe pro Pixel <code>pixel_depth</code> <a class="spec-record-ref" data-req="SWS_RDS_90285" href="../spec/record.html?id=SWS_RDS_90285">[SWS_RDS_90285]</a>, das Pixelformat <code>pixel_format</code> <a class="spec-record-ref" data-req="SWS_RDS_90286" href="../spec/record.html?id=SWS_RDS_90286">[SWS_RDS_90286]</a>, den Farbraum <code>colorspace</code> <a class="spec-record-ref" data-req="SWS_RDS_90288" href="../spec/record.html?id=SWS_RDS_90288">[SWS_RDS_90288]</a> sowie die Bildwiederholrate <code>frame_rate</code> <a class="spec-record-ref" data-req="SWS_RDS_90287" href="../spec/record.html?id=SWS_RDS_90287">[SWS_RDS_90287]</a>. Hinzu kommen AVTP-spezifische Kontroll- und Statusbits des Übertragungsprotokolls: das Feld <code>ap</code> <a class="spec-record-ref" data-req="SWS_RDS_90279" href="../spec/record.html?id=SWS_RDS_90279">[SWS_RDS_90279]</a>, das Flag <code>f</code> <a class="spec-record-ref" data-req="SWS_RDS_90280" href="../spec/record.html?id=SWS_RDS_90280">[SWS_RDS_90280]</a>, das Feld <code>ef</code> <a class="spec-record-ref" data-req="SWS_RDS_90281" href="../spec/record.html?id=SWS_RDS_90281">[SWS_RDS_90281]</a>, Ereignisfelder wie <code>evt</code> <a class="spec-record-ref" data-req="SWS_RDS_90282" href="../spec/record.html?id=SWS_RDS_90282">[SWS_RDS_90282]</a> und <code>pd</code> <a class="spec-record-ref" data-req="SWS_RDS_90283" href="../spec/record.html?id=SWS_RDS_90283">[SWS_RDS_90283]</a>, das Flag <code>i</code> <a class="spec-record-ref" data-req="SWS_RDS_90284" href="../spec/record.html?id=SWS_RDS_90284">[SWS_RDS_90284]</a> sowie die Sequenznummer <code>i_seq_num</code> <a class="spec-record-ref" data-req="SWS_RDS_90290" href="../spec/record.html?id=SWS_RDS_90290">[SWS_RDS_90290]</a>.</p>
