<h4>Context</h4>
<p>The template class <code>ara::shwa::Accessor</code> serves in module <code>shwa</code> as a typed and dimensional access mediator to memory areas provided by <code>ara::shwa::Buffer</code>. Via its template parameters, it configures the data type (<code>DataT</code>), dimensionality (<code>Dimensions</code>), access mode (<code>AccessModeType</code>, read mode by default), as well as the memory area and allocator. It encapsulates the physical or virtual buffer resources and provides controlled read and write interfaces.</p>
<p>In doing so, <code>Accessor</code> typically interacts with the following partners:</p>
<ul>
<li><strong>Application:</strong> Creates the accessor, manages its exclusive ownership, and initiates data accesses or property queries.</li>
<li><strong><code>ara::shwa::Buffer</code>:</strong> Acts as a storage foundation on whose integrity the accessor relies (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>).</li>
<li><strong><code>TaskHandler</code>:</strong> Can optionally be integrated during instantiation to synchronize execution or processing tasks in connection with the memory access (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifetime and instantiation of <code>ara::shwa::Accessor</code> follow a strict resource and ownership control:</p>
<ul>
<li><strong>Creation:</strong> The default constructor is deleted (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00002" href="../spec/record.html?id=AP_SWS_SHWA_00002">[AP_SWS_SHWA_00002]</a>). Instances can only be instantiated via the static factory methods <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>). These validate the passed buffer reference and optional properties (<code>PropertyList</code>) and return a <code>ara::core::Result&lt;std::unique_ptr&lt;Accessor&gt;&gt;</code> upon success.</li>
<li><strong>Ownership and destruction:</strong> Through the return type <code>std::unique_ptr</code>, ownership is uniquely and exclusively bound to the caller. The class completely prevents copying and moving: Both the copy constructor (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00003" href="../spec/record.html?id=AP_SWS_SHWA_00003">[AP_SWS_SHWA_00003]</a>) and copy assignment operator (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00004" href="../spec/record.html?id=AP_SWS_SHWA_00004">[AP_SWS_SHWA_00004]</a>) as well as the move constructor (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00005" href="../spec/record.html?id=AP_SWS_SHWA_00005">[AP_SWS_SHWA_00005]</a>) and move assignment operator (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00006" href="../spec/record.html?id=AP_SWS_SHWA_00006">[AP_SWS_SHWA_00006]</a>) are declared as deleted (<code>delete</code>). Deleting the move operations is presumably intended to ensure that an accessor remains firmly bound to its location of origin and the initial buffer throughout its entire existence. Destruction occurs automatically upon releasing the <code>std::unique_ptr</code>.</li>
<li><strong>Concurrency:</strong> The creation methods <code>Create</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>) as well as the synchronous access methods <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>) and <code>Set</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>) are explicitly specified as thread-safe. In contrast, the index operators <code>operator[]</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00009" href="../spec/record.html?id=AP_SWS_SHWA_00009">[AP_SWS_SHWA_00009]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00010" href="../spec/record.html?id=AP_SWS_SHWA_00010">[AP_SWS_SHWA_00010]</a>) and the property methods <code>HasProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00015" href="../spec/record.html?id=AP_SWS_SHWA_00015">[AP_SWS_SHWA_00015]</a>) and <code>GetProperty</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>) are not thread-safe and require external synchronization when used concurrently.</li>
</ul>

<h4>Usage Path</h4>
<p>A regular flow when using a <code>Accessor</code> typically includes the following phases:</p>
<ol>
<li><strong>Factory call:</strong> The application calls <code>Create</code> with a reference to an existing <code>Buffer</code> and optional configurations or a <code>TaskHandler</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00007" href="../spec/record.html?id=AP_SWS_SHWA_00007">[AP_SWS_SHWA_00007]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00008" href="../spec/record.html?id=AP_SWS_SHWA_00008">[AP_SWS_SHWA_00008]</a>). The result is checked for success and the contained <code>std::unique_ptr</code> is taken over.</li>
<li><strong>Property query:</strong> Optionally, the application verifies the presence of certain capabilities via <code>HasProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00015" href="../spec/record.html?id=AP_SWS_SHWA_00015">[AP_SWS_SHWA_00015]</a>) and reads them out using <code>GetProperty&lt;PropertyT&gt;()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00016" href="../spec/record.html?id=AP_SWS_SHWA_00016">[AP_SWS_SHWA_00016]</a>).</li>
<li><strong>Write access:</strong> If the <code>AccessModeType</code> provides for this, data is written into the buffer via <code>Set</code> specifying a dimensional index <code>Id&lt;Dimensions&gt;</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00011" href="../spec/record.html?id=AP_SWS_SHWA_00011">[AP_SWS_SHWA_00011]</a>).</li>
<li><strong>Read access:</strong> Data is obtained in a thread-safe manner via <code>Get</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00012" href="../spec/record.html?id=AP_SWS_SHWA_00012">[AP_SWS_SHWA_00012]</a>). For direct reference accesses without thread safety, <code>operator[]</code> with index ID or sequential index can alternatively be used (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00009" href="../spec/record.html?id=AP_SWS_SHWA_00009">[AP_SWS_SHWA_00009]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00010" href="../spec/record.html?id=AP_SWS_SHWA_00010">[AP_SWS_SHWA_00010]</a>), which provides a typed reference <code>ReferenceT</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00014" href="../spec/record.html?id=AP_SWS_SHWA_00014">[AP_SWS_SHWA_00014]</a>).</li>
<li><strong>Release:</strong> When leaving the scope of application, the caller destroys the <code>std::unique_ptr</code>, thereby terminating access.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of <code>Accessor</code> transmit error states via the type <code>ShwaErrorCode</code> in the return value <code>ara::core::Result</code>:</p>
<ul>
