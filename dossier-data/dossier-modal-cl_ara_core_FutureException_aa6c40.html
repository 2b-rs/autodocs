<h4>Context</h4>
<p>In module <code>core</code> of the AUTOSAR Adaptive Platform, the class <code>ara::core::FutureException</code> acts as a specialized exception type for error states in the context of asynchronous operations. According to the specification, this exception is thrown by <code>ara::core::Future</code> and <code>ara::core::Promise</code> to report occurred error conditions to callers in a structured manner. In the overall architecture of the Adaptive Platform, the class is likely to form a functional bridge between error-code-based error handling and the modeled exception mechanism: It derives from the base class <code>Exception</code> and encapsulates a concrete error state in the form of an <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>.</p>
<p>Typically, a producing context via <code>ara::core::Promise</code>, a consuming context via <code>ara::core::Future</code>, and the higher-level application are involved in the asynchronous interaction. If asynchronous processing fails or an invalid state is queried, <code>ara::core::FutureException</code> serves as the signal carrier. Being provided via the header file <code>ara/core/future_error_domain.h</code>, the exception is closely linked with the domain-specific error definitions for asynchronous workflows <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::core::FutureException</code> begins with its creation via the constructor specified for this purpose, which accepts an initializing <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>. The declaration as <code>explicit</code> prevents unintended implicit type conversions of error codes into exception objects and ensures that creation always occurs deliberately <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>. The constructor is also declared as <code>noexcept</code> and thus guarantees complete exception safety during object creation <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>.</p>
<p>Regarding operation in concurrent systems, the class is classified as <code>thread-safe</code> according to the specification <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>. This property is essential for its intended purpose, as <code>ara::core::Promise</code> and <code>ara::core::Future</code> are regularly executed in separate threads. When an exception is thrown, the object is instantiated in the C++ runtime system. Ownership is transferred along the call hierarchy to the handling <code>catch</code> block during stack unwinding, where the exception object is automatically destroyed after exiting the exception block.</p>

<h4>Usage Path</h4>
<p>The regular usage path of <code>ara::core::FutureException</code> unfolds along the call chain of asynchronous tasks. Typically, an application component initiates an asynchronous operation whose result is managed via an associated pair of <code>ara::core::Promise</code> and <code>ara::core::Future</code>. If an error situation occurs during task execution or result retrieval, the exception is thrown.</p>
<p>In a typical flow, a consumer attempts to retrieve the result via a <code>ara::core::Future</code>. If no valid result is present in the underlying <code>ara::core::Promise</code> or an error state has been stored, this access leads to the throwing of a <code>ara::core::FutureException</code>. Here, the constructor strictly requires passing the associated error code <code>err</code> <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>. The consuming application catches the exception in a suitable exception handler. Presumably, callers can evaluate the encapsulated <code>ara::core::ErrorCode</code> to accurately determine the concrete cause of the error within the error domain and initiate adequate countermeasures.</p>

<h4>Error Scenarios</h4>
<p>When using and handling <code>ara::core::FutureException</code>, the following error scenarios and system safety guarantees are decisive:</p>
<ul>
<li><strong>Exception-safe instantiation:</strong> Since the constructor is designated with <code>noexcept</code>, object creation of the exception itself never fails and throws no further secondary exceptions <a class="spec-record-ref" data-req="SWS_CORE_00412" href="../spec/record.html?id=SWS_CORE_00412">[SWS_CORE_00412]</a>. This ensures a deterministic transition into exception handling even under load.</li>

An exception object without a stored error code can therefore not be created.</li>
<li><strong>Unhandled exceptions:</strong> If a <code>ara::core::FutureException</code> thrown by <code>ara::core::Future</code> or <code>ara::core::Promise</code> is not caught by a matching <code>catch</code> block of the application, the standard runtime behavior of C++ applies, leading to termination of the process. Since the class inherits publicly from <code>Exception</code>, it can be caught both specifically and polymorphically via base class references.</li>
</ul>
