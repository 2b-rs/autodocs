<div class="ai-level" data-ai-level="2">
<p>Die Klasse dient als durch OEM oder Stack-Hersteller implementierte Schnittstelle zur Bereitstellung und Verwaltung von Frischewerten für SecOC im Kommunikationsmanagement <a class="spec-record-ref" data-req="SWS_CM_11287" href="../spec/record.html?id=SWS_CM_11287">[SWS_CM_11287]</a>. Sie versorgt <code>ara::com</code> beim Senden und Empfangen gesicherter Botschaften über <code>GetTxFreshness()</code> und <code>GetRxFreshness()</code> mit Frischewerten und nimmt über <code>SetVerificationStatus()</code> das Verifikationsergebnis entgegen <a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a> <a class="spec-record-ref" data-req="SWS_CM_11276" href="../spec/record.html?id=SWS_CM_11276">[SWS_CM_11276]</a>. Ihr Lebenszyklus wird dabei vollständig als Singleton von <code>ara::com</code> verwaltet <a class="spec-record-ref" data-req="SWS_CM_11272" href="../spec/record.html?id=SWS_CM_11272">[SWS_CM_11272]</a>.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>apext::com::secoc::FVM</code> definiert die standardisierte Schnittstelle für das Freshness Value Management (FVM) innerhalb des Kommunikationsmanagements von AUTOSAR Adaptive <a class="spec-record-ref" data-req="SWS_CM_11287" href="../spec/record.html?id=SWS_CM_11287">[SWS_CM_11287]</a>. Sie fungiert als Erweiterungspunkt (Plugin-Schnittstelle), der durch den OEM oder den Stack-Hersteller implementiert wird, um anwendungsspezifische Frischewerte für die nachrichtengenaue Absicherung bereitzustellen <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=537">AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 „Class: FVM“</a>. Zu den Interaktionspartnern gehören das Kommunikationsmanagement (<code>ara::com</code>), das kryptografische Absicherungsmodul SecOC sowie die spezifische FVM-Bibliothek des Herstellers.</p>

<h4>Lebenszyklus</h4>
<p>Innerhalb des Kommunikationsmanagements existiert genau eine einzige Instanz dieser Klasse <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=537">AUTOSAR_AP_SWS_CommunicationManagement §C.1.2 „Class: FVM“</a>. Der gesamte Lebenszyklus der SecOC-FreshnessValueManager-Implementierung wird vollständig durch <code>ara::com</code> gesteuert <a class="spec-record-ref" data-req="SWS_CM_11272" href="../spec/record.html?id=SWS_CM_11272">[SWS_CM_11272]</a>. Die Initialisierung der FVM-Implementierung erfolgt verpflichtend über den Aufruf der Methode <code>Initialize()</code> <a class="spec-record-ref" data-req="SWS_CM_11273" href="../spec/record.html?id=SWS_CM_11273">[SWS_CM_11273]</a> <a class="spec-record-ref" data-req="SWS_CM_11290" href="../spec/record.html?id=SWS_CM_11290">[SWS_CM_11290]</a>. Sämtliche Methoden der Schnittstelle sind als ausnahmesicher (<code>noexcept</code>) deklariert <a class="spec-record-ref" data-req="SWS_CM_11288" href="../spec/record.html?id=SWS_CM_11288">[SWS_CM_11288]</a>. Interpretation: Da die Instanzierung und Lebenszyklusverwaltung intern durch <code>ara::com</code> erfolgt, obliegt der konkreten FVM-Plugin-Implementierung die interne Synchronisation gegen nebenläufige Aufrufe durch mehrere Kommunikationskanäle.</p>

<h4>Nutzungspfad</h4>
<p>Im laufenden Betrieb unterscheidet das Kommunikationsmanagement zwischen dem Senden und dem Empfangen gesicherter Nachrichten:</p>
<ul>
<li><strong>Sendeoperation:</strong> Wenn eine Nachricht für die SecOC-Übertragung konfiguriert ist und eine <code>freshnessValueId</code> besitzt, ruft das Kommunikationsmanagement <code>GetTxFreshness()</code> mit der Frischewert-ID auf <a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a> <a class="spec-record-ref" data-req="SWS_CM_11289" href="../spec/record.html?id=SWS_CM_11289">[SWS_CM_11289]</a>. Bei erfolgreicher Rückgabe wird der Frischewert im <code>FVContainer</code> für die Berechnung des Authenticators (MAC) herangezogen, welche nach den Berechnungen zur E2E-Absicherung stattfindet <a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>.</li>
<li><strong>Empfangsoperation:</strong> Sofern die Verifikation eingehender Nachrichten nicht durch die Konfiguration umgangen wird <a class="spec-record-ref" data-req="SWS_CM_11372" href="../spec/record.html?id=SWS_CM_11372">[SWS_CM_11372]</a>, ruft SecOC vor der E2E-Prüfung <code>GetRxFreshness()</code> auf <a class="spec-record-ref" data-req="SWS_CM_11276" href="../spec/record.html?id=SWS_CM_11276">[SWS_CM_11276]</a> <a class="spec-record-ref" data-req="SWS_CM_11288" href="../spec/record.html?id=SWS_CM_11288">[SWS_CM_11288]</a>. Dabei werden die <code>SecOCFreshnessValueID</code>, der empfangene gekürzte Frischewert (<code>SecOCTruncatedFreshnessValue</code>) sowie die Anzahl bisheriger Verifikationsversuche (<code>SecOCAuthVerifyAttempts</code>) übergeben <a class="spec-record-ref" data-req="SWS_CM_11288" href="../spec/record.html?id=SWS_CM_11288">[SWS_CM_11288]</a>. Nach Abgleich des berechneten Authenticators meldet das Kommunikationsmanagement das Ergebnis via <code>SetVerificationStatus()</code> unter Angabe des <code>VerificationStatus</code> zurück an die FVM <a class="spec-record-ref" data-req="SWS_CM_19999" href="../spec/record.html?id=SWS_CM_19999">[SWS_CM_19999]</a> <a class="spec-record-ref" data-req="SWS_CM_11378" href="../spec/record.html?id=SWS_CM_11378">[SWS_CM_11378]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Fehler werden über Rückgabetypen des Typs <code>ara::core::Result</code> signalisiert:</p>
<ul>
<li><strong>Initialisierungsfehler:</strong> Schlägt die Vorbereitung der FVM-Implementierung fehl, liefert <code>Initialize()</code> den Fehlercode <code>ComSecOcFvmErrc::kFVInitializeFailed</code> <a class="spec-record-ref" data-req="SWS_CM_11290" href="../spec/record.html?id=SWS_CM_11290">[SWS_CM_11290]</a>.</li>
<li><strong>Nicht verfügbarer Frischewert:</strong> Können Sende- oder Empfangsfrischewerte temporär nicht ermittelt werden, geben <code>GetTxFreshness()</code> und <code>GetRxFreshness()</code> den Fehler <code>ComSecOcFvmErrc::kFVNotAvailable</code> zurück <a class="spec-record-ref" data-req="SWS_CM_11288" href="../spec/record.html?id=SWS_CM_11288">[SWS_CM_11288]</a> <a class="spec-record-ref" data-req="SWS_CM_11289" href="../spec/record.html?id=SWS_CM_11289">[SWS_CM_11289]</a>.</li>
<li><strong>Wiederholversuche beim Senden:</strong> Liefert <code>GetTxFreshness()</code> den wiederherstellbaren Fehler <code>kFVNotAvailable</code> oder misslingt die Authenticator-Berechnung, inkrementiert das System einen <code>Authentication Build Counter</code> <a class="spec-record-ref" data-req="SWS_CM_11275" href="../spec/record.html?id=SWS_CM_11275">[SWS_CM_11275]</a>. Das Sichern der Nachricht wird herstellerspezifisch wiederholt; erreicht der Zähler das konfigurierte Limit <code>SecOCAuthenticationBuildAttempts</code>, wird die Nachricht verworfen <a class="spec-record-ref" data-req="SWS_CM_11275" href="../spec/record.html?id=SWS_CM_11275">[SWS_CM_11275]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=225">AUTOSAR_AP_SWS_CommunicationManagement §8.1 „SecOC secure message build attempts“</a>.</li>
<li><strong>Statusmeldungen bei Verifikationsfehlschlägen:</strong> Über <code>SetVerificationStatus()</code> werden spezifische Fehlermodi wie <code>kSecOcVerificationFailure</code>, <code>kSecOcFreshnessFailure</code> oder <code>kSecOcAuthenticationBuildFailure</code> an die FVM gemeldet <a class="spec-record-ref" data-req="SWS_CM_19999" href="../spec/record.html?id=SWS_CM_19999">[SWS_CM_19999]</a> <a class="spec-record-ref" data-req="SWS_CM_11378" href="../spec/record.html?id=SWS_CM_11378">[SWS_CM_11378]</a>.</li>
</ul>
