<h4>Context</h4>
<p>The class <code>apext::diag::uds_transport::UdsTransportProtocolPeriodicHandler</code> is a specialized interface of the AUTOSAR Adaptive Platform in the module <code>diag</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=966">AUTOSAR_AP_SWS_Diagnostics §C.3 “Header: apext/diag/uds_transport/protocol_periodic_handler.h”</a>. It serves to provide standardized support for the UDS service 0x2A (\"ReadDataByPeriodicIdentifier\") at the transport protocol level <a class="spec-record-ref" data-req="SWS_DM_01064" href="../spec/record.html?id=SWS_DM_01064">[SWS_DM_01064]</a>.</p>
<p>Within the diagnostic architecture, the class mediates between the higher-level diagnostic management and the concrete transport connection. Its main responsibility is to provide channel-specific capacity limits for periodic transmissions and to pass ordered sequences of periodic diagnostic messages in batches to the underlying network. Participating interaction partners are:</p>
<ul>
<li><strong>UDS service handler (0x2A):</strong> Controls the periodic reading of measured values and initiates the periodic transmission process.</li>
<li><strong>Transport protocol handler:</strong> Implements the protocol-specific transmission (e.g., via DoIP) as a concrete derivation of the interface.</li>
<li><strong>Transmission channel (<code>ChannelID</code>):</strong> Represents the concrete logical or physical connection via which the periodic messages are transmitted <a class="spec-record-ref" data-req="SWS_DM_01066" href="../spec/record.html?id=SWS_DM_01066">[SWS_DM_01066]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical transmission cycle for periodic diagnostic messages comprises determining the connection parameters, preparing the message list, and calling the transmission:</p>
<ol>
<li><strong>Determine channel limits:</strong> Prior to the first transmission, the caller determines via <code>GetMaxPayloadLength(channelId)</code> the maximum permissible payload length per periodic message for the channel <a class="spec-record-ref" data-req="SWS_DM_01066" href="../spec/record.html?id=SWS_DM_01066">[SWS_DM_01066]</a>. In addition, <code>GetNumberOfPeriodicMessages(channelId)</code> provides the implementation- and connection-specific number of possible periodic messages <a class="spec-record-ref" data-req="SWS_DM_01065" href="../spec/record.html?id=SWS_DM_01065">[SWS_DM_01065]</a>.</li>
<li><strong>Assemble message list:</strong> The messages to be transmitted are aggregated in a <code>ara::core::Vector&lt;UdsMessageConstPtr&gt;</code> in the desired transmission order.</li>
<li><strong>Initiate periodic transmission:</strong> The list is passed to the handler via <code>PeriodicTransmit(channelId, messages)</code> <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>. The messages are transmitted sequentially in the specified order <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=968">AUTOSAR_AP_SWS_Diagnostics §C.3.1.1.2.3 “PeriodicTransmit”</a>.</li>
<li><strong>Process confirmation:</strong> After the transmission process is completed, the confirmation (\"PeriodicTransmit Confirmation\") is called to report the result <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Since all methods of the interface are <code>noexcept</code>, errors are not reported via C++ exceptions. Error handling is directly integrated into the transmission protocol:</p>
<ul>
<li><strong>Transmission abort on single error:</strong> If the transmission of a single message within the passed list fails, the entire further transmission process is aborted immediately <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>. Subsequent messages in the list are no longer sent.</li>
<li><strong>Error feedback via confirmation:</strong> The PeriodicTransmit Confirmation is also called in case of an error <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>. As parameters, it receives the exact number of messages successfully sent prior to the abort as well as the original message list. Based on the transmitted count, the caller can accurately identify at which index the error occurred and initiate countermeasures if necessary.</li>
<li><strong>Violation of preconditions:</strong> Since <code>PeriodicTransmit</code> has no return value (<code>void</code>), the caller must ensure in advance that the <code>channelId</code> is valid and that the message sizes comply with the limits reported via <code>GetMaxPayloadLength</code> <a class="spec-record-ref" data-req="SWS_DM_01066" href="../spec/record.html?id=SWS_DM_01066">[SWS_DM_01066]</a>, <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>.</li>
</ul>
