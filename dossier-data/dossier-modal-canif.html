<h4>Role of CanIf: hardware-independent hub between CAN drivers and communication stack</h4>
<p>The CAN Interface (CanIf) takes over all hardware-independent tasks of CAN communication of an ECU. The underlying CAN drivers thus only deal with access to and control of the respective CAN hardware. CanIf processes transmit requests, transmit confirmations, receive and error indications as well as start and stop of the CAN controllers. Its data APIs operate on CAN L-SDUs, its control APIs are related to the CAN controller (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_FIGURE_Figure_1_1.html" data-snip="SNIP_CLASSIC_CANIF_FIGURE_Figure_1_1">SWS CanIf p. 13</a>). CanIf never accesses hardware-specific communication buffers directly, but exclusively via services of the CanDrv <a class="spec-record-ref" data-req="SWS_CANIF_00023" href="../../spec/record.html?id=SWS_CANIF_00023">[SWS_CANIF_00023]</a>.</p>
<p>Downwards, CanIf serves one or more CanDrv. In link-time configuration, this is done via a set of function pointers per driver <a class="spec-record-ref" data-req="SWS_CANIF_00378" href="../../spec/record.html?id=SWS_CANIF_00378">[SWS_CANIF_00378]</a>. In addition, CanIf combines the APIs of multiple CanTrcv into a uniform interface without containing transceiver logic itself (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_5_5_Lower_layers_CAN_Transceiver_Driver.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_5_5_Lower_layers_CAN_Transceiver_Driver">SWS CanIf p. 21</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00358" href="../../spec/record.html?id=SWS_CANIF_00358">[SWS_CANIF_00358]</a>). Upwards, there are configurable users:</p>
<ul>
<li>PduR, CanNm, CanTp, Xcp, and CDDs as data users (<a class="spec-record-ref" data-req="SWS_CANIF_00439" href="../../spec/record.html?id=SWS_CANIF_00439">[SWS_CANIF_00439]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00445" href="../../spec/record.html?id=SWS_CANIF_00445">[SWS_CANIF_00445]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00448" href="../../spec/record.html?id=SWS_CANIF_00448">[SWS_CANIF_00448]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00555" href="../../spec/record.html?id=SWS_CANIF_00555">[SWS_CANIF_00555]</a>),</li>
<li>CanSM as control instance for controller and transceiver modes <a class="spec-record-ref" data-req="SWS_CANIF_00711" href="../../spec/record.html?id=SWS_CANIF_00711">[SWS_CANIF_00711]</a>,</li>
<li>EcuM for initialization and wake-up (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_8_Initialization.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_8_Initialization">SWS CanIf p. 40</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00563" href="../../spec/record.html?id=SWS_CANIF_00563">[SWS_CANIF_00563]</a>).</li>
</ul>

<h4>Configuration, abstraction IDs, and initialization</h4>
<p><code>CanIf_Init()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00001" href="../../spec/record.html?id=SWS_CANIF_00001">[SWS_CANIF_00001]</a> reads the CAN configuration from containers and parameters. This allows the configuration to be changed without rebuilding the module (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_5_6_Configuration.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_5_6_Configuration">SWS CanIf p. 22</a>). <code>CanIf_ConfigType</code> <a class="spec-record-ref" data-req="SWS_CANIF_00144" href="../../spec/record.html?id=SWS_CANIF_00144">[SWS_CANIF_00144]</a> contains the public parameters and the definition of each L-PDU/L-SDU <a class="spec-record-ref" data-req="SWS_CANIF_00523" href="../../spec/record.html?id=SWS_CANIF_00523">[SWS_CANIF_00523]</a>. The initialization has the following effects:</p>
<ul>
<li>Variables, flags, and all transmit buffers are reset (<a class="spec-record-ref" data-req="SWS_CANIF_00085" href="../../spec/record.html?id=SWS_CANIF_00085">[SWS_CANIF_00085]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00387" href="../../spec/record.html?id=SWS_CANIF_00387">[SWS_CANIF_00387]</a>).</li>
<li>Each channel is set to <code>CANIF_OFFLINE</code> <a class="spec-record-ref" data-req="SWS_CANIF_00864" href="../../spec/record.html?id=SWS_CANIF_00864">[SWS_CANIF_00864]</a>.</li>
<li>Dynamic Tx CanIds receive the value from <code>CanIfTxPduCanId</code> <a class="spec-record-ref" data-req="SWS_CANIF_00857" href="../../spec/record.html?id=SWS_CANIF_00857">[SWS_CANIF_00857]</a>.</li>
</ul>
<p>The controllers remain in the STOPPED state afterwards (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_8_Initialization.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_8_Initialization">SWS CanIf p. 40</a>). Before <code>CanIf_Init()</code>, all services except <code>CanIf_Init()</code> and <code>CanIf_GetVersionInfo()</code> return the value <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_CANIF_00661" href="../../spec/record.html?id=SWS_CANIF_00661">[SWS_CANIF_00661]</a>.</p>
<p>CanIf assigns its own abstraction IDs starting at 0:</p>
<ul>
<li><code>ControllerId</code> for controllers <a class="spec-record-ref" data-req="SWS_CANIF_00653" href="../../spec/record.html?id=SWS_CANIF_00653">[SWS_CANIF_00653]</a>,</li>
<li><code>TransceiverId</code> for transceivers <a class="spec-record-ref" data-req="SWS_CANIF_00655" href="../../spec/record.html?id=SWS_CANIF_00655">[SWS_CANIF_00655]</a>.</li>
</ul>
<p>For access to hardware objects, CanIf uses HTH (transmission) and HRH (reception) (<a class="spec-record-ref" data-req="SWS_CANIF_00662" href="../../spec/record.html?id=SWS_CANIF_00662">[SWS_CANIF_00662]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00291" href="../../spec/record.html?id=SWS_CANIF_00291">[SWS_CANIF_00291]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00292" href="../../spec/record.html?id=SWS_CANIF_00292">[SWS_CANIF_00292]</a>). Per CanDrv, HTH and HRH form a common number range <a class="spec-record-ref" data-req="SWS_CANIF_00115" href="../../spec/record.html?id=SWS_CANIF_00115">[SWS_CANIF_00115]</a>. HRHs of type BasicCAN require a software filter (<a class="spec-record-ref" data-req="SWS_CANIF_00663" href="../../spec/record.html?id=SWS_CANIF_00663">[SWS_CANIF_00663]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_7_BasicCAN_and_FullCAN_reception.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_7_BasicCAN_and_FullCAN_reception">SWS CanIf p. 38</a>).</p>
<p>The target callbacks of the upper layers are configured. If no name is specified, the call is omitted; the assignment to the receiver is performed via the L-SDU ID (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_6_3_Configurable_interfaces.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_6_3_Configurable_interfaces">SWS CanIf p. 133</a>). However, a BusOff user is mandatory <a class="spec-record-ref" data-req="SWS_CANIF_00524" href="../../spec/record.html?id=SWS_CANIF_00524">[SWS_CANIF_00524]</a>. Optional services can be switched off at compile time, such as:</p>
<ul>
<li><code>CanIf_ReadRxPduData()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00330" href="../../spec/record.html?id=SWS_CANIF_00330">[SWS_CANIF_00330]</a>,</li>
<li><code>CanIf_SetDynamicTxId()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00357" href="../../spec/record.html?id=SWS_CANIF_00357">[SWS_CANIF_00357]</a>,</li>
<li><code>CanIf_TriggerTransmit()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00884" href="../../spec/record.html?id=SWS_CANIF_00884">[SWS_CANIF_00884]</a>,</li>
<li><code>CanIf_EnableBusMirroring()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00911" href="../../spec/record.html?id=SWS_CANIF_00911">[SWS_CANIF_00911]</a>.</li>
</ul>
<p>Before <code>CanIf_DeInit()</code> <a class="spec-record-ref" data-req="SWS_CANIF_91002" href="../../spec/record.html?id=SWS_CANIF_91002">[SWS_CANIF_91002]</a>, the caller must ensure that no transmissions and no transmit confirmations are pending anymore (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_3_2_CanIf_DeInit.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_3_2_CanIf_DeInit">SWS CanIf p. 81</a>).</p>

<h4>Transmit path: from CanIf_Transmit via buffering to confirmation</h4>
<p><code>CanIf_Transmit()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00005" href="../../spec/record.html?id=SWS_CANIF_00005">[SWS_CANIF_00005]</a> determines the matching HTH for <code>TxPduId</code> and calls <code>Can_Write()</code>. As <code>swPduHandle</code>, CanIf passes the ID that is returned later in the confirmation <a class="spec-record-ref" data-req="SWS_CANIF_00318" href="../../spec/record.html?id=SWS_CANIF_00318">[SWS_CANIF_00318]</a>. If <code>Can_Write()</code> returns <code>E_OK</code>, <code>CanIf_Transmit()</code> also returns <code>E_OK</code> <a class="spec-record-ref" data-req="SWS_CANIF_00162" href="../../spec/record.html?id=SWS_CANIF_00162">[SWS_CANIF_00162]</a>. The request is rejected if the controller is not in <code>CAN_CS_STARTED</code> and the transmit path is neither online nor offline-active (<a class="spec-record-ref" data-req="SWS_CANIF_00317" href="../../spec/record.html?id=SWS_CANIF_00317">[SWS_CANIF_00317]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00677" href="../../spec/record.html?id=SWS_CANIF_00677">[SWS_CANIF_00677]</a>).</p>
<p>When buffering is activated <a class="spec-record-ref" data-req="SWS_CANIF_00063" href="../../spec/record.html?id=SWS_CANIF_00063">[SWS_CANIF_00063]</a>, CanIf stores an L-PDU rejected with <code>CAN_BUSY</code> in the assigned <code>CanIfTxBuffer</code> (<a class="spec-record-ref" data-req="SWS_CANIF_00381" href="../../spec/record.html?id=SWS_CANIF_00381">[SWS_CANIF_00381]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00836" href="../../spec/record.html?id=SWS_CANIF_00836">[SWS_CANIF_00836]</a>). A buffer size greater than zero is a prerequisite <a class="spec-record-ref" data-req="SWS_CANIF_00835" href="../../spec/record.html?id=SWS_CANIF_00835">[SWS_CANIF_00835]</a>. If the same L-PDU is already buffered, it is overwritten <a class="spec-record-ref" data-req="SWS_CANIF_00068" href="../../spec/record.html?id=SWS_CANIF_00068">[SWS_CANIF_00068]</a>. If the buffer is full, the call returns <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_CANIF_00837" href="../../spec/record.html?id=SWS_CANIF_00837">[SWS_CANIF_00837]</a>. In principle, an L-PDU is located in exactly one place only: either in the hardware object or in the CanIf buffer (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_11_1_General_behavior.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_11_1_General_behavior">SWS CanIf p. 43</a>).</p>

</ul>

<h4>Receive path: software filter, data length check, and forwarding</h4>
<p>Upon each reception, CanDrv calls <code>CanIf_RxIndication(Mailbox, PduInfoPtr)</code> (<a class="spec-record-ref" data-req="SWS_CANIF_00006" href="../../spec/record.html?id=SWS_CANIF_00006">[SWS_CANIF_00006]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_13_Receive_data_flow.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_13_Receive_data_flow">SWS CanIf p. 48</a>). CanIf checks the L-PDU in two stages:</p>
<ol>
<li><strong>Software filter</strong>, if configured. If it rejects the L-PDU, processing ends <a class="spec-record-ref" data-req="SWS_CANIF_00389" href="../../spec/record.html?id=SWS_CANIF_00389">[SWS_CANIF_00389]</a>. The assignment to the L-SDU also takes into account the two most significant ID bits <a class="spec-record-ref" data-req="SWS_CANIF_00877" href="../../spec/record.html?id=SWS_CANIF_00877">[SWS_CANIF_00877]</a>. A single CanId has precedence over a range <a class="spec-record-ref" data-req="SWS_CANIF_00852" href="../../spec/record.html?id=SWS_CANIF_00852">[SWS_CANIF_00852]</a>.</li>
<li><strong>Data length check</strong> <a class="spec-record-ref" data-req="SWS_CANIF_00390" href="../../spec/record.html?id=SWS_CANIF_00390">[SWS_CANIF_00390]</a>. Any length that is at least equal to the configured one is accepted <a class="spec-record-ref" data-req="SWS_CANIF_00026" href="../../spec/record.html?id=SWS_CANIF_00026">[SWS_CANIF_00026]</a>. Shorter L-PDUs lead to a runtime error <code>CANIF_E_INVALID_DATA_LENGTH</code> <a class="spec-record-ref" data-req="SWS_CANIF_00168" href="../../spec/record.html?id=SWS_CANIF_00168">[SWS_CANIF_00168]</a>.</li>
</ol>
<p>Accepted L-PDUs go to the configured <code>&lt;User_RxIndication&gt;</code>, together with the received length (<a class="spec-record-ref" data-req="SWS_CANIF_00056" href="../../spec/record.html?id=SWS_CANIF_00056">[SWS_CANIF_00056]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00135" href="../../spec/record.html?id=SWS_CANIF_00135">[SWS_CANIF_00135]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00829" href="../../spec/record.html?id=SWS_CANIF_00829">[SWS_CANIF_00829]</a>). For dynamic L-SDUs, CanIf stores the received CanId in MetaDataItem <code>CAN_ID_32</code> <a class="spec-record-ref" data-req="SWS_CANIF_00848" href="../../spec/record.html?id=SWS_CANIF_00848">[SWS_CANIF_00848]</a>. Two query paths are optional:</p>
<ul>
<li>A receive buffer from which <code>CanIf_ReadRxPduData()</code> reads (<a class="spec-record-ref" data-req="SWS_CANIF_00199" href="../../spec/record.html?id=SWS_CANIF_00199">[SWS_CANIF_00199]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00194" href="../../spec/record.html?id=SWS_CANIF_00194">[SWS_CANIF_00194]</a>).</li>
<li>Notification status according to the “read and consume” principle: The status is set upon reception and reset upon reading (<a class="spec-record-ref" data-req="SWS_CANIF_00392" href="../../spec/record.html?id=SWS_CANIF_00392">[SWS_CANIF_00392]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00394" href="../../spec/record.html?id=SWS_CANIF_00394">[SWS_CANIF_00394]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_16_Read_Tx_Rx_notification_status.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_16_Read_Tx_Rx_notification_status">SWS CanIf p. 55</a>).</li>
</ul>
<p>In channel mode <code>CANIF_OFFLINE</code>, receive notifications are omitted <a class="spec-record-ref" data-req="SWS_CANIF_00073" href="../../spec/record.html?id=SWS_CANIF_00073">[SWS_CANIF_00073]</a>.</p>

<h4>Controller, PDU channel, and transceiver modes</h4>
<p><code>CanIf_SetControllerMode()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00003" href="../../spec/record.html?id=SWS_CANIF_00003">[SWS_CANIF_00003]</a> operates asynchronously. It calls <code>Can_SetControllerMode()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00308" href="../../spec/record.html?id=SWS_CANIF_00308">[SWS_CANIF_00308]</a>. CanDrv reports the actual transition later via <code>CanIf_ControllerModeIndication()</code>, and CanIf forwards it to CanSM (<a class="spec-record-ref" data-req="SWS_CANIF_00699" href="../../spec/record.html?id=SWS_CANIF_00699">[SWS_CANIF_00699]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00711" href="../../spec/record.html?id=SWS_CANIF_00711">[SWS_CANIF_00711]</a>). If a transition fails, the upper layers must track this. They can query the mode via <code>CanIf_GetControllerMode()</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_7_18_3_Controller_Mode_Transitions.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_7_18_3_Controller_Mode_Transitions">SWS CanIf p. 55</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00229" href="../../spec/record.html?id=SWS_CANIF_00229">[SWS_CANIF_00229]</a>).</p>
<p>Each channel has a PDU channel mode of type <code>CanIf_PduModeType</code> <a class="spec-record-ref" data-req="SWS_CANIF_00137" href="../../spec/record.html?id=SWS_CANIF_00137">[SWS_CANIF_00137]</a>. <code>CanIf_SetPduMode()</code> accepts requests only in <code>CAN_CS_STARTED</code> (<a class="spec-record-ref" data-req="SWS_CANIF_00008" href="../../spec/record.html?id=SWS_CANIF_00008">[SWS_CANIF_00008]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00874" href="../../spec/record.html?id=SWS_CANIF_00874">[SWS_CANIF_00874]</a>). CanIf triggers some transitions itself: <code>CAN_CS_SLEEP</code> leads to <code>CANIF_OFFLINE</code> <a class="spec-record-ref" data-req="SWS_CANIF_00865" href="../../spec/record.html?id=SWS_CANIF_00865">[SWS_CANIF_00865]</a>, STOPPED or BusOff to <code>CANIF_TX_OFFLINE</code> <a class="spec-record-ref" data-req="SWS_CANIF_00866" href="../../spec/record.html?id=SWS_CANIF_00866">[SWS_CANIF_00866]</a>. An R20-11 text excerpt describes <code>CANIF_TX_OFFLINE_ACTIVE</code> as “without listening” (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_Can_AUTOSAR_SWS_CANI_P58_387.html" data-snip="SNIP_Can_AUTOSAR_SWS_CANI_P58_387">SWS CanIf p. 58</a>). However, <a class="spec-record-ref" data-req="SWS_CANIF_00137" href="../../spec/record.html?id=SWS_CANIF_00137">[SWS_CANIF_00137]</a> is authoritative, and according to it, the receive path remains active.</p>

<h4>Wake-up detection and validation</h4>
<p>The integration code calls <code>CanIf_CheckWakeup()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00219" href="../../spec/record.html?id=SWS_CANIF_00219">[SWS_CANIF_00219]</a>. CanIf then queries <code>Can_CheckWakeup()</code> and <code>CanTrcv_CheckWakeup()</code>, respectively <a class="spec-record-ref" data-req="SWS_CANIF_00395" href="../../spec/record.html?id=SWS_CANIF_00395">[SWS_CANIF_00395]</a>. If at least one driver reports <code>E_OK</code>, CanIf returns <code>E_OK</code>, otherwise <code>E_NOT_OK</code> (<a class="spec-record-ref" data-req="SWS_CANIF_00720" href="../../spec/record.html?id=SWS_CANIF_00720">[SWS_CANIF_00720]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00678" href="../../spec/record.html?id=SWS_CANIF_00678">[SWS_CANIF_00678]</a>). The service is only available if wake-up support is configured (<a class="spec-record-ref" data-req="SWS_CANIF_00180" href="../../spec/record.html?id=SWS_CANIF_00180">[SWS_CANIF_00180]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_1_Wake_up_detection.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_1_Wake_up_detection">SWS CanIf p. 56</a>).</p>
<p>The following applies to validation:</p>
<ol>
<li>With <code>CanIfPublicWakeupCheckValidSupport</code>, CanIf stores the first valid <code>CanIf_RxIndication()</code> call of a started controller. Depending on the configuration, only NM messages count <a class="spec-record-ref" data-req="SWS_CANIF_00286" href="../../spec/record.html?id=SWS_CANIF_00286">[SWS_CANIF_00286]</a>.</li>
<li><code>CanIf_CheckValidation()</code> reports this event via <code>&lt;User_ValidateWakeupEvent&gt;(sources)</code>, typically <code>EcuM_ValidateWakeupEvent</code> (<a class="spec-record-ref" data-req="SWS_CANIF_00179" href="../../spec/record.html?id=SWS_CANIF_00179">[SWS_CANIF_00179]</a>, <a class="spec-record-ref" data-req="SWS_CANIF_00563" href="../../spec/record.html?id=SWS_CANIF_00563">[SWS_CANIF_00563]</a>).</li>
<li>Upon <code>CAN_CS_SLEEP</code>, the stored event is cleared <a class="spec-record-ref" data-req="SWS_CANIF_00756" href="../../spec/record.html?id=SWS_CANIF_00756">[SWS_CANIF_00756]</a>.</li>
</ol>
<p>As long as validation is ongoing, the channel must not be set to <code>CANIF_ONLINE</code> or <code>CANIF_TX_OFFLINE</code>. Otherwise, upper layers will already receive receive indications (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_2_Wake_up_Validation.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_2_Wake_up_Validation">SWS CanIf p. 60</a>).</p>

<h4>Behavior in the event of an error</h4>
<p><strong>BusOff.</strong> CanDrv reports a BusOff via <code>CanIf_ControllerBusOff()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00218" href="../../spec/record.html?id=SWS_CANIF_00218">[SWS_CANIF_00218]</a>. CanIf responds as follows:</p>
<ul>
<li>It calls <code>CanSM_ControllerBusOff()</code> <a class="spec-record-ref" data-req="SWS_CANIF_00724" href="../../spec/record.html?id=SWS_CANIF_00724">[SWS_CANIF_00724]</a>.</li>
<li>It sets the channel to <code>CANIF_TX_OFFLINE</code> <a class="spec-record-ref" data-req="SWS_CANIF_00866" href="../../spec/record.html?id=SWS_CANIF_00866">[SWS_CANIF_00866]</a>.</li>
<li>Upon entering STOPPED, it clears the transmit buffers <a class="spec-record-ref" data-req="SWS_CANIF_00485" href="../../spec/record.html?id=SWS_CANIF_00485">[SWS_CANIF_00485]</a>.</li>
<li>For each pending confirmation, it calls <code>&lt;User_TxConfirmation&gt;(id, E_NOT_OK)</code> <a class="spec-record-ref" data-req="SWS_CANIF_00739" href="../../spec/record.html?id=SWS_CANIF_00739">[SWS_CANIF_00739]</a>.</li>
<li>It additionally reports the security event <code>CANIF_SEV_ERRORSTATE_BUSOFF</code> <a class="spec-record-ref" data-req="SWS_CANIF_00918" href="../../spec/record.html?id=SWS_CANIF_00918">[SWS_CANIF_00918]</a>.</li>
</ul>
<p>CanSM controls the restart with <code>CanIf_SetControllerMode(…STARTED)</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_9_12_BusOff_recovery.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_9_12_BusOff_recovery">SWS CanIf p. 160</a>).
