<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::KeyEncapsulatorPublicCtx</code> represents the public KEM (Key Encapsulation Mechanism) context within the <code>crypto</code> module of the AUTOSAR Adaptive Platform. Its primary responsibility is to prepare symmetric keys for secure transport or export using asymmetric encapsulation schemes. In doing so, either a symmetric key already present in memory can be wrapped, or a new symmetric key can be generated at runtime and encapsulated in the same step.</p>
<p>The direct interaction partners of the context include:</p>
<ul>
<li><strong>Caller (application):</strong> Controls the configuration, determines the buffer sizes, and initiates the encapsulation.</li>
<li><strong>Public encapsulation key:</strong> Is bound either as a direct instance (<code>PublicKey</code>) or indirectly via a key slot (<code>KeySlot</code>).</li>
<li><strong>Symmetric key (<code>SymmetricKey</code>):</strong> Serves as input for encapsulating existing key material or is returned as the result of a dynamic generation.</li>
<li><strong>Output buffer (<code>ReadWriteMemRegion</code>):</strong> Receives the resulting ciphertext data of the encapsulated key.</li>
</ul>

<h4>Lifecycle</h4>
<p>The context is operated as a long-lived interface object; for lifecycle and ownership management, the class defines the smart pointer alias <code>Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21801" href="../spec/record.html?id=SWS_CRYPT_21801">[SWS_CRYPT_21801]</a>. Instantiation of the context is likely performed via a provider or factory component of the crypto stack.</p>
<p>After creation, the context is in an uninitialized state. To be operational, an encapsulation key must be assigned to it. This is done either by passing a <code>PublicKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a> or by assigning a <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a> whose key is evaluated when performing the encapsulation. After successful configuration, the context is ready for operation and can be used repeatedly for encapsulation operations. All methods are specified as exception-safe (<code>exception safe</code>) and thread-safe (<code>thread-safe</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>. If an error occurs during an operation, defined rollback semantics ensure that the context state remains unchanged and consistent.</p>

<h4>Usage Path</h4>
<p>The typical sequence for key encapsulation is divided into three successive phases:</p>
<ol>
<li><strong>Configuration:</strong> The encapsulation key is registered using <code>SetKey</code>, either as a direct public key <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a> or via a key slot <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>.</li>
<li><strong>Buffer sizing:</strong> The application calls <code>GetRequiredOutputBufferSize</code> with the desired <code>AlgId</code> to calculate the maximum byte size of the capsule in the current context state <a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>, and allocates a corresponding <code>ReadWriteMemRegion</code> buffer.</li>
<li><strong>Encapsulation:</strong> One of the two <code>Encapsulate</code> overloads is executed:
<ul>
<li><em>Encapsulate existing key:</em> Passing the existing symmetric key <code>key</code> and the buffer <code>encapsulatedKey</code>; the return value is the actual capsule size in bytes <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>.</li>
<li><em>Generate and encapsulate new key:</em> Specifying the algorithm identifier <code>algId</code>, the usage flags <code>allowedUsage</code>, and the output buffer; the return value is a pair consisting of the capsule size and the pointer to the newly generated <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
</ul>
</li>
</ol>

<h4>Error Scenarios</h4>
<p>Operations signal error cases via return values of type <code>ara::core::Result</code>. In particular, the following error codes from <code>ara::crypto::CryptoErrc</code> can occur:</p>
<ul>
<li><code>kUninitializedContext</code>: Occurs when <code>GetRequiredOutputBufferSize</code> or <code>Encapsulate</code> is called before the context has been linked to a key or slot via <code>SetKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>.</li>
<li><code>kUsageViolation</code>: Signals insufficient usage rights. This happens when the encapsulation key does not possess the <code>kAllowKeyWrapping</code> right, or when, during encapsulation of an existing key, its usage rules prohibit export via <code>kAllowSecuredExport</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>.</li>
<li><code>kIncompatibleObject</code>: The passed key object or key slot is not compatible with this specific KEM context <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>.</li>
<li><code>kInsufficientCapacity</code> / <code>kInvalidInputSize</code>: The passed memory region <code>encapsulatedKey</code> provides insufficient capacity for the ciphertext, or the size of the key to be encapsulated is not supported by the algorithm <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
<li><code>kUnsupported</code>: The selected operating mode is not supported by the concrete context implementation—for example, if only <code>KeySlot</code> instead of <code>PublicKey</code> is accepted <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>, only <code>PublicKey</code> instead of <code>KeySlot</code> is permitted <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>, or if the context supports exclusively key generation or exclusively encapsulation of externally passed keys <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
<li><code>kEmptyKeySlot</code>: A <code>KeySlot</code> previously registered via <code>SetKey</code> is empty at the time <code>Encapsulate</code> is called <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
<li><code>kUnknownIdentifier</code>: The algorithm identifier <code>algId</code> passed to <code>Encapsulate</code> is unknown to the system or invalid <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
<li><code>kBusyResource</code>: A crypto or hardware resource required for the encapsulation operation is currently busy <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>.</li>
</ul>
