<p class="ai-level ai-oneliner-lead" data-ai-level="1">Koordiniert Netzanforderungen und überwacht den Kommunikationsstatus von Teilnetzen für das übergeordnete State Management.</p>
<div class="ai-level" data-ai-level="2">
<p>Das funktionale Cluster Network Management stellt für das State Management Schnittstellen zur Verfügung, um logische Netzwerk-Handles, Teilnetze und physische Kommunikationskanäle koordiniert anzufordern und deren Status abzufragen (<a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34">EXP_SWArchitecture S. 77</a>). Über die Klasse <code>NetworkHandle</code> werden Soll- und Ist-Zustände zwischen <code>kNoCom</code> und <code>kFullCom</code> gesteuert sowie asynchrone Notifier registriert (<a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>). Die Nutzung der Schnittstelle ist ausschließlich dem State Management vorbehalten, während Fehler einheitlich über <code>NmErrorDomain</code> gemeldet werden (<a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01111" href="../spec/record.html?id=SWS_ANM_01111">[SWS_ANM_01111]</a>).</p>

<div class="ai-level" data-ai-level="3">
<p>Das funktionale Cluster Network Management (NM) stellt der AUTOSAR Adaptive Platform Mechanismen zur Anforderung und Statusüberwachung von Kommunikationsnetzen und Teilnetzen bereit. Die Programmierschnittstelle richtet sich exklusiv an das funktionale Cluster State Management, das über logische Instanzen der Klasse <code>NetworkHandle</code> Netzressourcen steuert und von physischen Busstrukturen wie Ethernet oder CAN entkoppelt wird (<a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34">EXP_SWArchitecture S. 77</a>, <a class="docref internal-spec-ref" href="../../spec/figures/FIG-bd314a91ffbffccd.html" data-snip="FIG-bd314a91ffbffccd">EXP_PlatformDesign S. 60</a>).</p>

<p>Ein <code>NetworkHandle</code> wird über einen <code>ara::core::InstanceSpecifier</code> initialisiert und unterstützt Verschiebeoperationen, während Kopierkonstruktor und Kopierzuweisung gelöscht sind (<a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01003" href="../spec/record.html?id=SWS_ANM_01003">[SWS_ANM_01003]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01005" href="../spec/record.html?id=SWS_ANM_01005">[SWS_ANM_01005]</a>). Das Modul unterscheidet zwischen dem gesetzten Anforderungszustand (<code>SetNetworkRequestedState</code>, <code>GetNetworkRequestedState</code>) und dem tatsächlich aktiven Netzwerkzustand (<code>GetNetworkState</code>), jeweils repräsentiert durch <code>NetworkStateType</code> mit den Zuständen <code>kNoCom</code> und <code>kFullCom</code> (<a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>).</p>

<h4>Systemische Rolle und funktionale Architekturabgrenzung</h4>
<p>Das funktionale Cluster Network Management (NM) stellt innerhalb der AUTOSAR Adaptive Platform die koordinierte Verwaltung von Kommunikationsnetzwerken und Teilnetzen (Partial Networks, PN) bereit. Die Programmierschnittstelle des Moduls ist nicht für beliebige Adaptive Applications vorgesehen, sondern dient spezifisch dem funktionalen Cluster State Management (SM), um Kommunikationsfähigkeiten bedarfsgerecht anzufordern oder freizugeben (<a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34">EXP_SWArchitecture S. 77</a>). Das State Management fungiert als zentraler System-Orchestrator der Maschine und steuert Funktionsgruppen sowie Plattformzustände, während das Network Management die tatsächliche Busüberwachung, Teilnetzlogik und Bus-Keep-Alive-Zustände kapselt (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-a83a638138b1a3bc.html" data-snip="FIG-a83a638138b1a3bc">SWS_NetworkManagement S. 13</a>, <a class="docref internal-spec-ref" href="../../spec/figures/FIG-bd314a91ffbffccd.html" data-snip="FIG-bd314a91ffbffccd">EXP_PlatformDesign S. 60</a>).</p>
<p>Architektonisch entkoppelt das Network Management über logische Netzwerk-Handles (<code>NetworkHandle</code>) übergeordnete Zustandssteuerungen von der physischen Netzwerktopologie wie Ethernet- oder CAN-Netzwerken (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-bd314a91ffbffccd.html" data-snip="FIG-bd314a91ffbffccd">EXP_PlatformDesign S. 60</a>). Eine Netzanforderung durch das State Management wird intern auf kanalspezifische Zustandsmaschinen und Partial Network State Machines (PNSM) abgebildet, wodurch die Kommunikation auf den physischen Kanälen synchronisiert und bedarfsgesteuert aktiviert oder heruntergefahren wird (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-9c745b2146ed27bd.html" data-snip="FIG-9c745b2146ed27bd">SWS_NetworkManagement S. 18</a>, <a class="docref internal-spec-ref" href="../../spec/figures/FIG-93effc9d7f15f2fc.html" data-snip="FIG-93effc9d7f15f2fc">SWS_StateManagement S. 17</a>).</p>

<h4>Instanziierung und Ressourcenverwaltung über NetworkHandle</h4>
<p>Der funktionale Zugriff auf ein konkretes Teilnetz oder einen physischen Kommunikationskanal erfolgt über Instanzen der Klasse <code>NetworkHandle</code> (<a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>). Ein <code>NetworkHandle</code> wird explizit durch Übergabe eines <code>ara::core::InstanceSpecifier</code> konstruiert, welcher den zugeordneten Port-Prototyp eines <code>NetworkManagementPortInterface</code> eindeutig referenziert (<a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>). Die Initialisierung über diesen Konstruktor ist als threadsicher spezifiziert (<a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>).</p>
<p>Das Schnittstellendesign von <code>NetworkHandle</code> folgt strengen Lebenszyklus- und Eigentumsregeln: Kopierkonstruktor und Kopierzuweisungsoperator sind explizit gelöscht (<code>= delete</code>), womit ein unkoordiniertes Duplizieren von Handle-Instanzen unterbunden wird (<a class="spec-record-ref" data-req="SWS_ANM_01005" href="../spec/record.html?id=SWS_ANM_01005">[SWS_ANM_01005]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01006" href="../spec/record.html?id=SWS_ANM_01006">[SWS_ANM_01006]</a>). Dagegen werden Verschiebekonstruktor und Verschiebezuweisung bereitgestellt, um Ressourcen kontrolliert transferieren zu können (<a class="spec-record-ref" data-req="SWS_ANM_01003" href="../spec/record.html?id=SWS_ANM_01003">[SWS_ANM_01003]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01004" href="../spec/record.html?id=SWS_ANM_01004">[SWS_ANM_01004]</a>). Interpretation: Da das Kopieren verboten und lediglich Verschiebeoperationen erlaubt sind, dürfte die Architektur eine exklusive Besitzsemantik je Handle-Instanz erzwingen, um konkurrierende Notifier-Registrierungen auf demselben Objekt auszuschließen. <a class="interp-q interp-q-open" data-q="Q-912cb5d1ddff2896" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-912cb5d1ddff2896" title="Frage Q-912cb5d1ddff2896 (offen): Exklusive Besitzsemantik bei NetworkHandle">Frage Q-912cb5d1ddff2896 (offen)</a> Destruktor und Verschiebezuweisung sind explizit als nicht threadsicher definiert, weshalb die Lebenszyklusverwaltung eines Handles im State Management synchronisiert erfolgen muss (<a class="spec-record-ref" data-req="SWS_ANM_01002" href="../spec/record.html?id=SWS_ANM_01002">[SWS_ANM_01002]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01004" href="../spec/record.html?id=SWS_ANM_01004">[SWS_ANM_01004]</a>).</p>

<h4>Steuerung und Abfrage von Kommunikationszuständen</h4>
<p>Das Modul unterscheidet strikt zwischen dem angeforderten Soll-Zustand (Requested State) und dem tatsächlich aktiven Ist-Zustand (Network State) eines Netzwerk-Handles (<a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>). Beide Zustände werden über die Enumeration <code>NetworkStateType</code> mit den Ausprägungen <code>kNoCom</code> (Wert 0) und <code>kFullCom</code> (Wert 1) repräsentiert (<a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>). Der Gesamtzustand ist definitionsgemäß nur dann <code>kFullCom</code>, wenn ausnahmslos alle dem Handle zugeordneten Teil- oder Vollnetze im Kommunikationszustand FULL_COM sind; andernfalls lautet der Status <code>kNoCom</code> (<a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>).</p>
<p>Über die Methode <code>SetNetworkRequestedState</code> fordert das State Management die Aktivierung (<code>kFullCom</code>) oder Freigabe (<code>kNoCom</code>) des zugehörigen PNC-, VLAN- oder physikalischen Netzes an (<a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34">EXP_SWArchitecture S. 77</a>). Mit <code>GetNetworkRequestedState</code> kann der zuletzt gesetzte Anforderungswert synchron abgefragt werden (<a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>). Der tatsächliche, busrelevante Betriebszustand wird hingegen mit <code>GetNetworkState</code> ausgelesen, wobei beide Abfragemethoden als threadsicher deklariert sind und ihr Ergebnis in einem <code>ara::core::Result</code> kapseln (<a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>).</p>

<h4>Ereignisbasierte Zustandsüberwachung und Benachrichtigungsmechanismen</h4>
<p>Da Zustandswechsel auf Netzwerkebene durch externe Busteilnehmer, Botschafts-Timeouts oder asynchrone Hochlaufzeiten verzögert eintreffen, stellt <code>NetworkHandle</code> asynchrone Benachrichtigungsmechanismen über Callback-Funktionen vom Typ <code>NetworkStateChangeNotifier</code> (<code>std::function&lt;void(const NetworkStateType&amp;)&gt;</code>) bereit (<a class="spec-record-ref" data-req="SWS_ANM_01020" href="../spec/record.html?id=SWS_ANM_01020">[SWS_ANM_01020]</a>). Für Änderungen des effektiven Netzwerkzustands dient <code>RegisterNetworkStateChangeNotifier</code> (<a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>), während Änderungen des angeforderten Zustands über <code>RegisterNetworkRequestedStateChangeNotifier</code> überwacht werden (<a class="spec-record-ref" data-req="SWS_ANM_01012" href="../spec/record.html?id=SWS_ANM_01012">[SWS_ANM_01012]</a>).</p>
<p>Pro Handle und Überwachungsart kann maximal ein Notifier registriert werden; jeder nachfolgende Registrierungsaufruf überschreibt den zuvor registrierten Callback (<a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_9_34">EXP_SWArchitecture S. 77</a>). Mit <code>UnregisterNetworkStateChangeNotifier</code> sowie <code>UnregisterNetworkRequestedStateChangeNotifier</code> können bestehende Registrierungen explizit wieder aufgehoben werden (<a class="spec-record-ref" data-req="SWS_ANM_01011" href="../spec/record.html?id=SWS_ANM_01011">[SWS_ANM_01011]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01013" href="../spec/record.html?id=SWS_ANM_01013">[SWS_ANM_01013]</a>). Für eine erweiterte Ablaufsteuerung stehen template-basierte Registrierungsmethoden zur Verfügung, die einen benutzerdefinierten Executor (<code>ExecutorT&amp;&amp; executor</code>) entgegennehmen, um die Benachrichtigung in einem spezifischen Ausführungskontext oder Thread abzuarbeiten (<a class="spec-record-ref" data-req="SWS_ANM_01014" href="../spec/record.html?id=SWS_ANM_01014">[SWS_ANM_01014]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01015" href="../spec/record.html?id=SWS_ANM_01015">[SWS_ANM_01015]</a>).</p>

<h4>Manifest-Modellierung und Zuordnungskonfiguration</h4>
<p>Die Einbindung des Network Managements in die Adaptive Application erfolgt über standardisierte Metamodell-Elemente im Manifest. Die Schnittstelle <code>NetworkManagementPortInterface</code> spezialisiert die fundamentale Metaklasse <code>PortInterface</code> und definiert somit formale Port-Prototypen (<code>PPortPrototype</code>, <code>RPortPrototype</code>) zur Interaktion mit dem Cluster (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-4272450f7b4c4bc8.html" data-snip="FIG-4272450f7b4c4bc8">TPS_ManifestSpecification S. 263</a>).</p>
<p>Im Deployment-Manifest wird die Bindung zwischen Applikationsinstanzen und dem logischen Netzwerk-Management über das Mapping-Element <code>NetworkHandlePortMapping</code> deklariert (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-766c05b8b5730a1c.html" data-snip="FIG-766c05b8b5730a1c">TPS_ManifestSpecification S. 620</a>). Dieses verknüpft einen Port-Prototyp innerhalb eines Prozesses (<code>Process</code>) mit einem logischen <code>NmNetworkHandle</code> (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-766c05b8b5730a1c.html" data-snip="FIG-766c05b8b5730a1c">TPS_ManifestSpecification S. 620</a>). Zudem wird über das Metamodell-Element <code>NmInteractsWithSmMapping</code> die koordinative Kopplung zwischen dem Cluster State Management (über <code>StateManagementStateRequest</code>) und dem Netzwerk-Handle (<code>NmNetworkHandle</code>) verbindlich konfiguriert (<a class="docref internal-spec-ref" href="../../spec/figures/FIG-50de203e97969070.html" data-snip="FIG-50de203e97969070">TPS_ManifestSpecification S. 875</a>).</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Zur einheitlichen Fehlerbehandlung implementiert das Modul eine eigene Fehlerdomäne gemäß der AUTOSAR-Adaptive-Fehlerarchitektur. Die Klasse <code>NmErrorDomain</code> erbt von <code>ara::core::ErrorDomain</code> und identifiziert Fehler der Netzwerkverwaltung über die statische Domänenabfrage <code>GetNmDomain</code> sowie die Identifikationsmethoden <code>Name</code> und <code>Message</code> (<a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01105" href="../spec/record.html?id=SWS_ANM_01105">[SWS_ANM_01105]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01106" href="../spec/record.html?id=SWS_ANM_01106">[SWS_ANM_01106]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01109" href="../spec/record.html?id=SWS_ANM_01109">[SWS_ANM_01109]</a>).</p>
<p>Die spezifischen Fehlerursachen sind in der Enumeration <code>NmErrc</code> definiert (<a class="spec-record-ref" data-req="SWS_ANM_01111" href="../spec/record.html?id=SWS_ANM_01111">[SWS_ANM_01111]</a>). Der Fehlercode <code>NmErrc::kServiceNotAvailable</code> (Code 1) signalisiert, dass der zugrunde liegende Plattformdienst oder Daemon nicht erreichbar ist; er kann bei den Methoden <code>GetNetworkState</code>, <code>GetNetworkRequestedState</code> und <code>SetNetworkRequestedState</code> auftreten (<a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01111" href="../spec/record.html?id=SWS_ANM_01111">[SWS_ANM_01111]</a>). Der Fehlercode <code>NmErrc::kInvalidHandler</code> (Code 2) wird gemeldet, wenn ein ungültiger Notifier-Handler an eine der Registrierungsmethoden übergeben wurde (<a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01012" href="../spec/record.html?id=SWS_ANM_01012">[SWS_ANM_01012]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01014" href="../spec/record.html?id=SWS_ANM_01014">[SWS_ANM_01014]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01015" href="../spec/record.html?id=SWS_ANM_01015">[SWS_ANM_01015]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01111" href="../spec/record.html?id=SWS_ANM_01111">[SWS_ANM_01111]</a>).</p>
<p>Fehlercodes werden über <code>MakeErrorCode</code> in reguläre <code>ara::core::ErrorCode</code>-Objekte überführt (<a class="spec-record-ref" data-req="SWS_ANM_01110" href="../spec/record.html?id=SWS_ANM_01110">[SWS_ANM_01110]</a>). Falls in Ausführungsumgebungen C++-Exceptions zulässig und konfiguriert sind, können diese Fehler über <code>ThrowAsException</code> als Ausnahme vom Typ <code>NmException</code> ausgelöst werden (<a class="spec-record-ref" data-req="SWS_ANM_01100" href="../spec/record.html?id=SWS_ANM_01100">[SWS_ANM_01100]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>). Zur Vereinfachung stehen die Typaliase <code>Errc</code> und <code>Exception</code> zur Verfügung (<a class="spec-record-ref" data-req="SWS_ANM_01103" href="../spec/record.html?id=SWS_ANM_01103">[SWS_ANM_01103]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01104" href="../spec/record.html?id=SWS_ANM_01104">[SWS_ANM_01104]</a>).</p>
