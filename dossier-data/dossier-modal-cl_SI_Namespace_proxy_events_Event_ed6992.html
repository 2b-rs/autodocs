<h4>Context</h4>
<p>The generated C++ class <code>&lt;SI-Namespace&gt;::proxy::events::&lt;Event&gt;</code> represents the receive-side interface for a specific service event within a service proxy in AUTOSAR Adaptive (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">AUTOSAR_AP_EXP_ARAComAPI p. 10</a>). Its primary responsibility consists in managing the event subscription, registering notification callbacks, and providing type-safe access to incoming event data via the type alias <code>SampleType</code> <a class="spec-record-ref" data-req="SWS_CM_11401" href="../spec/record.html?id=SWS_CM_11401">[SWS_CM_11401]</a>.</p>
<p>The class primarily interacts with three parties:</p>
<ul>
  <li><strong>Application software:</strong> Initiates the subscription via methods such as <code>Subscribe</code> <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a> and <code>Unsubscribe</code> <a class="spec-record-ref" data-req="SWS_CM_00151" href="../spec/record.html?id=SWS_CM_00151">[SWS_CM_00151]</a>, sets callbacks, and processes received data samples using functors in <code>GetNewSamples</code> <a class="spec-record-ref" data-req="SWS_CM_00701" href="../spec/record.html?id=SWS_CM_00701">[SWS_CM_00701]</a>.</li>
  <li><strong>Communication Management (runtime environment):</strong> Monitors the connection and subscription status, receives the serialized event data, and triggers the registered <code>EventReceiveHandler</code> upon data arrival <a class="spec-record-ref" data-req="SWS_CM_00181" href="../spec/record.html?id=SWS_CM_00181">[SWS_CM_00181]</a>.</li>
  <li><strong>Execution context (ExecutorT):</strong> Optionally allows passing a user-defined execution context so that notifications, state transitions, and error handlers are processed specifically in dedicated threads or worker queues <a class="spec-record-ref" data-req="SWS_CM_11354" href="../spec/record.html?id=SWS_CM_11354">[SWS_CM_11354]</a>, <a class="spec-record-ref" data-req="SWS_CM_11356" href="../spec/record.html?id=SWS_CM_11356">[SWS_CM_11356]</a>, <a class="spec-record-ref" data-req="SWS_CM_00100" href="../spec/record.html?id=SWS_CM_00100">[SWS_CM_00100]</a>.</li>
  <li><strong>End-to-End protection (E2E):</strong> Enables monitoring of transport errors via <code>SetTransportFaultConditionHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00099" href="../spec/record.html?id=SWS_CM_00099">[SWS_CM_00099]</a> as well as querying the E2E state after evaluating received samples <a class="spec-record-ref" data-req="SWS_CM_11554" href="../spec/record.html?id=SWS_CM_11554">[SWS_CM_11554]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance of <code>&lt;SI-Namespace&gt;::proxy::events::&lt;Event&gt;</code> is instantiated as part of the parent service proxy and shares its lifetime; ownership thus lies with the proxy object. The functional lifecycle is largely determined by the internal state of the subscription (<code>SubscriptionState</code>), which can be queried at any time via <code>GetSubscriptionState</code> <a class="spec-record-ref" data-req="SWS_CM_00316" href="../spec/record.html?id=SWS_CM_00316">[SWS_CM_00316]</a>.</p>
<p>Initially, the event is in the state of no subscription. Calling <code>Subscribe(maxSampleCount)</code> <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a> initiates the transition: depending on the communication state, the instance changes to the state <code>kSubscriptionPending</code> or directly to <code>kSubscribed</code> <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a>. State changes are reported to the callback registered via <code>SetSubscriptionStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00333" href="../spec/record.html?id=SWS_CM_00333">[SWS_CM_00333]</a> or <a class="spec-record-ref" data-req="SWS_CM_11354" href="../spec/record.html?id=SWS_CM_11354">[SWS_CM_11354]</a>, respectively. If <code>Subscribe</code> is called again with the same buffer value, the call has no effect <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a>.</p>
<p>Termination takes place via <code>Unsubscribe</code> <a class="spec-record-ref" data-req="SWS_CM_00151" href="../spec/record.html?id=SWS_CM_00151">[SWS_CM_00151]</a>, whereby the event returns to the unsubscribed state. If the event was not subscribed, the call has no effect <a class="spec-record-ref" data-req="SWS_CM_00151" href="../spec/record.html?id=SWS_CM_00151">[SWS_CM_00151]</a>. To release resources, registered handlers can be explicitly removed via <code>UnsetSubscriptionStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00334" href="../spec/record.html?id=SWS_CM_00334">[SWS_CM_00334]</a>, <code>UnsetReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00183" href="../spec/record.html?id=SWS_CM_00183">[SWS_CM_00183]</a>, and <code>UnsetTransportFaultConditionHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00105" href="../spec/record.html?id=SWS_CM_00105">[SWS_CM_00105]</a>. All API methods are declared as <code>noexcept</code>.</p>

<h4>Usage Path</h4>
<p>A typical usage path for event-driven processing of data samples is divided into the following steps:</p>
<ol>
  <li><strong>Configure handler:</strong> The application first registers a receive handler via <code>SetReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00181" href="../spec/record.html?id=SWS_CM_00181">[SWS_CM_00181]</a> or in conjunction with an execution context via <code>SetReceiveHandler(handler, executor)</code> <a class="spec-record-ref" data-req="SWS_CM_11356" href="../spec/record.html?id=SWS_CM_11356">[SWS_CM_11356]</a>. Optionally, handlers for state changes <a class="spec-record-ref" data-req="SWS_CM_00333" href="../spec/record.html?id=SWS_CM_00333">[SWS_CM_00333]</a> or E2E transport errors <a class="spec-record-ref" data-req="SWS_CM_00099" href="../spec/record.html?id=SWS_CM_00099">[SWS_CM_00099]</a> can be set.</li>
  <li><strong>Activate subscription:</strong> Via <code>Subscribe(maxSampleCount)</code> <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a>, the application informs the middleware of the maximum number of samples that may be held simultaneously in the local cache.</li>
  <li><strong>Notification and data retrieval:</strong> As soon as new data is available, Communication Management triggers the registered handler <a class="spec-record-ref" data-req="SWS_CM_00181" href="../spec/record.html?id=SWS_CM_00181">[SWS_CM_00181]</a>. Inside it, the application calls <code>GetNewSamples</code> <a class="spec-record-ref" data-req="SWS_CM_00701" href="../spec/record.html?id=SWS_CM_00701">[SWS_CM_00701]</a>. A passed callable functor receives each new data item as a typed pointer <code>ara::com::SamplePtr&lt;SampleType const&gt;</code>. The return value provides information about the total number of processed samples.</li>
  <li><strong>Check buffer and state:</strong> The application can query free cache slots via <code>GetFreeSampleCount</code> <a class="spec-record-ref" data-req="SWS_CM_00705" href="../spec/record.html?id=SWS_CM_00705">[SWS_CM_00705]</a> and, after <code>GetNewSamples</code>, evaluate the result of the E2E check with <code>GetE2EStateMachineState</code> <a class="spec-record-ref" data-req="SWS_CM_11554" href="../spec/record.html?id=SWS_CM_11554">[SWS_CM_11554]</a>.</li>
  <li><strong>Deactivation:</strong> After processing is complete, the application deregisters the handlers (<a class="spec-record-ref" data-req="SWS_CM_00183" href="../spec/record.html?id=SWS_CM_00183">[SWS_CM_00183]</a>, <a class="spec-record-ref" data-req="SWS_CM_00334" href="../spec/record.html?id=SWS_CM_00334">[SWS_CM_00334]</a>, <a class="spec-record-ref" data-req="SWS_CM_00105" href="../spec/record.html?id=SWS_CM_00105">[SWS_CM_00105]</a>) and cancels the subscription with <code>Unsubscribe</code> <a class="spec-record-ref" data-req="SWS_CM_00151" href="../spec/record.html?id=SWS_CM_00151">[SWS_CM_00151]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The interface methods signal error conditions primarily via <code>ara::core::Result</code> as well as via specified API violations:</p>
<ul>
  <li><code>ComErrc::kMaxSamplesExceeded</code>: Returned by <code>GetNewSamples</code> if the application holds more <code>ara::com::SamplePtr</code> instances at the same time than previously guaranteed in <code>Subscribe</code>. No rollback semantics apply here, and subsequent samples may have been dropped <a class="spec-record-ref" data-req="SWS_CM_00701" href="../spec/record.html?id=SWS_CM_00701">[SWS_CM_00701]</a>.</li>
  <li><code>ComErrc::kMaxSampleCountNotRealizable</code>: Occurs with <code>Subscribe</code> if, during a resubscription, a different <code>maxSampleCount</code> is passed than was agreed for the currently existing subscription <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a>.</li>
  <li><code>InsufficientPermissionsViolation</code>: Triggered if grant enforcement denies access to the event subscription upon calling <code>Subscribe</code> <a class="spec-record-ref" data-req="SWS_CM_00141" href="../spec/record.html?id=SWS_CM_00141">[SWS_CM_00141]</a>.</li>
  <li><code>InvalidHandlerViolation</code>: Occurs if an invalid or empty handler is passed to the registration methods <code>SetReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00181" href="../spec/record.html?id=SWS_CM_00181">[SWS_CM_00181]</a>, <a class="spec-record-ref" data-req="SWS_CM_11356" href="../spec/record.html?id=SWS_CM_11356">[SWS_CM_11356]</a>, <code>SetSubscriptionStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00333" href="../spec/record.html?id=SWS_CM_00333">[SWS_CM_00333]</a>, <a class="spec-record-ref" data-req="SWS_CM_11354" href="../spec/record.html?id=SWS_CM_11354">[SWS_CM_11354]</a>, or <code>SetTransportFaultConditionHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00099" href="../spec/record.html?id=SWS_CM_00099">[SWS_CM_00099]</a>, <a class="spec-record-ref" data-req="SWS_CM_00100" href="../spec/record.html?id=SWS_CM_00100">[SWS_CM_00100]</a>.</li>
  <li><code>DanglingSamplesViolation</code>: Signals upon calling <code>Unsubscribe</code> that open samples (dangling samples) still exist in the application context and the preconditions for unsubscribing were violated <a class="spec-record-ref" data-req="SWS_CM_00151" href="../spec/record.html?id=SWS_CM_00151">[SWS_CM_00151]</a>.</li>
</ul>
