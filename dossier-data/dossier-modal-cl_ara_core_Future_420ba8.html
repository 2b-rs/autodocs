<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht den synchronen oder asynchronen Empfang von Werten und Fehlern aus einer nebenläufigen Operation.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::core::Future</code> dient als Empfänger-Handle für das Ergebnis einer asynchronen Operation und verwaltet den Zugriff auf einen gemeinsamen Zustand <a class="spec-record-ref" data-req="SWS_CORE_00327" href="../spec/record.html?id=SWS_CORE_00327">[SWS_CORE_00327]</a>. Konsumenten können den Zustand nicht-blockierend prüfen, synchron auf die Fertigstellung warten oder das Ergebnis über <code>GetResult()</code> ausnahmefrei als <code>ara::core::Result</code> entgegennehmen <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a>. Da Kopieroperationen gelöscht sind, wird der Besitz exklusiv verwaltet, und nach der Ergebnisabholung oder Weiterleitung mittels Continuation wird das Objekt unmittelbar ungültig.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Future</code> stellt das Empfänger-Endelement für Ergebnisse asynchroner Operationen innerhalb der AUTOSAR Adaptive Platform dar. Sie ermöglicht den kontrollierten Zugriff auf einen gemeinsamen Zustand (Shared State), der von einer erzeugenden Instanz asynchron befüllt wird <a class="spec-record-ref" data-req="SWS_CORE_00327" href="../spec/record.html?id=SWS_CORE_00327">[SWS_CORE_00327]</a>. Konzeptionell implementiert die Klasse <code>std::future</code> aus dem C++17-Standard ISO/IEC 14882:2017 [11], integriert sich jedoch nahtlos in das fehlerausnahmebasierte Konzept der Plattform: Für den Template-Parameter <code>E</code> ist zwingend der Fehlertyp <code>ara::core::ErrorCode</code> vorgegeben; jede abweichende Spezifikation führt zu einem Übersetzungsfehler. Zu den primären Interaktionspartnern zählen der asynchrone Erzeuger (wie ein assoziiertes Promise), welcher den Wert oder Fehler bereitstellt, die <code>Future</code>-Instanz als exklusiver Empfänger sowie ein Konsument oder Ausführungskontext (<code>ExecutorT</code>), an den Folgeaufgaben übergeben werden <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung, Zustandsverwaltung und Vernichtung von <code>ara::core::Future</code> unterliegt strengen Regeln zur Gewährleistung deterministischer Besitzverhältnisse:</p>
<ul>
<li><strong>Erzeugung:</strong> Der Standardkonstruktor erzeugt eine leere Instanz ohne Shared State, für die <code>valid() == false</code> gilt <a class="spec-record-ref" data-req="SWS_CORE_00322" href="../spec/record.html?id=SWS_CORE_00322">[SWS_CORE_00322]</a> <a class="spec-record-ref" data-req="SWS_CORE_00327" href="../spec/record.html?id=SWS_CORE_00327">[SWS_CORE_00327]</a>. Interpretation: Gültige Instanzen entstehen regulär durch asynchrone Plattform-Schnittstellen oder gekoppelte Promise-Objekte.</li>
<li><strong>Besitz und Übertragung:</strong> Kopierkonstruktor und Kopierzuweisungsoperator sind explizit gelöscht (<code>delete</code>), sodass ein Duplizieren des Zugriffsgriffs ausgeschlossen ist <a class="spec-record-ref" data-req="SWS_CORE_00334" href="../spec/record.html?id=SWS_CORE_00334">[SWS_CORE_00334]</a> <a class="spec-record-ref" data-req="SWS_CORE_00335" href="../spec/record.html?id=SWS_CORE_00335">[SWS_CORE_00335]</a>. Das Verschieben (Move) von Instanzen ist über den Move-Konstruktor und Move-Zuweisungsoperator möglich und überträgt die Eigentümerschaft am Shared State vollständig <a class="spec-record-ref" data-req="SWS_CORE_00323" href="../spec/record.html?id=SWS_CORE_00323">[SWS_CORE_00323]</a> <a class="spec-record-ref" data-req="SWS_CORE_00325" href="../spec/record.html?id=SWS_CORE_00325">[SWS_CORE_00325]</a>.</li>
<li><strong>Zustände und Übergänge:</strong> Der Zustand gliedert sich in ungültig (<code>valid() == false</code>), gültig-ausstehend (<code>valid() == true</code>, <code>is_ready() == false</code>) und bereit (<code>valid() == true</code>, <code>is_ready() == true</code>) <a class="spec-record-ref" data-req="SWS_CORE_00327" href="../spec/record.html?id=SWS_CORE_00327">[SWS_CORE_00327]</a> <a class="spec-record-ref" data-req="SWS_CORE_00332" href="../spec/record.html?id=SWS_CORE_00332">[SWS_CORE_00332]</a>. Nach erfolgreicher Ergebnisabholung via <code>GetResult()</code> oder <code>get()</code> sowie nach Weiterleitung mittels <code>then()</code> verliert das Objekt seinen Zustand und wird unmittelbar ungültig (<code>valid() == false</code>) <a class="spec-record-ref" data-req="SWS_CORE_00326" href="../spec/record.html?id=SWS_CORE_00326">[SWS_CORE_00326]</a> <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</li>
<li><strong>Zerstörung:</strong> Der Destruktor <code>~Future()</code> gibt einen noch gehaltenen Shared State auf <a class="spec-record-ref" data-req="SWS_CORE_00333" href="../spec/record.html?id=SWS_CORE_00333">[SWS_CORE_00333]</a>. Falls Fortsetzungen registriert wurden, blockiert der Destruktor der zurückgegebenen Instanz so lange, bis eine bereits laufende Fortsetzungsfunktion vollständig ausgeführt wurde <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</li>
<li><strong>Nebenläufigkeit:</strong> Die Statusmethoden <code>valid()</code> und <code>is_ready()</code> sind threadsicher <a class="spec-record-ref" data-req="SWS_CORE_00327" href="../spec/record.html?id=SWS_CORE_00327">[SWS_CORE_00327]</a> <a class="spec-record-ref" data-req="SWS_CORE_00332" href="../spec/record.html?id=SWS_CORE_00332">[SWS_CORE_00332]</a>. Alle übrigen Schnittstellen – inklusive <code>wait()</code>, <code>wait_for()</code>, <code>wait_until()</code>, <code>GetResult()</code>, <code>get()</code>, <code>then()</code> und der Destruktor – sind für dieselbe Instanz nicht threadsicher <a class="spec-record-ref" data-req="SWS_CORE_00323" href="../spec/record.html?id=SWS_CORE_00323">[SWS_CORE_00323]</a> <a class="spec-record-ref" data-req="SWS_CORE_00325" href="../spec/record.html?id=SWS_CORE_00325">[SWS_CORE_00325]</a> <a class="spec-record-ref" data-req="SWS_CORE_00326" href="../spec/record.html?id=SWS_CORE_00326">[SWS_CORE_00326]</a> <a class="spec-record-ref" data-req="SWS_CORE_00328" href="../spec/record.html?id=SWS_CORE_00328">[SWS_CORE_00328]</a> <a class="spec-record-ref" data-req="SWS_CORE_00329" href="../spec/record.html?id=SWS_CORE_00329">[SWS_CORE_00329]</a> <a class="spec-record-ref" data-req="SWS_CORE_00330" href="../spec/record.html?id=SWS_CORE_00330">[SWS_CORE_00330]</a> <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00333" href="../spec/record.html?id=SWS_CORE_00333">[SWS_CORE_00333]</a> <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</li>
</ul>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad zur Ergebnisverarbeitung gliedert sich in folgende Phasen:</p>
<ol>
<li><strong>Statusprüfung und Synchronisation:</strong> Mit <code>is_ready()</code> kann vorab ermittelt werden, ob das asynchrone Ergebnis bereits vorliegt <a class="spec-record-ref" data-req="SWS_CORE_00332" href="../spec/record.html?id=SWS_CORE_00332">[SWS_CORE_00332]</a>. Ist dies der Fall, blockieren nachfolgende Abrufe garantiert nicht mehr <a class="spec-record-ref" data-req="SWS_CORE_00332" href="../spec/record.html?id=SWS_CORE_00332">[SWS_CORE_00332]</a>. Andernfalls kann mit <code>wait()</code> unbegrenzt <a class="spec-record-ref" data-req="SWS_CORE_00328" href="../spec/record.html?id=SWS_CORE_00328">[SWS_CORE_00328]</a> oder zeitbeschränkt via <code>wait_for()</code> bzw. <code>wait_until()</code> synchronisiert werden <a class="spec-record-ref" data-req="SWS_CORE_00329" href="../spec/record.html?id=SWS_CORE_00329">[SWS_CORE_00329]</a> <a class="spec-record-ref" data-req="SWS_CORE_00330" href="../spec/record.html?id=SWS_CORE_00330">[SWS_CORE_00330]</a>.</li>
<li><strong>Ergebnisextraktion:</strong> In AUTOSAR Adaptive Applikationen ist der Aufruf von <code>GetResult()</code> maßgeblich: Die Methode blockiert bei Bedarf, löst jedoch niemals Ausnahmen aus und übergibt den Wert oder Fehler als <code>ara::core::Result&lt;T, E&gt;</code> per Move <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a>. Die Methode <code>get()</code> bietet STL-Konformität, wirft im Fehlerfall C++-Ausnahmen und nimmt bei deaktivierter Ausnahmebehandlung der Toolchain nicht an der Überladungsauflösung teil <a class="spec-record-ref" data-req="SWS_CORE_00326" href="../spec/record.html?id=SWS_CORE_00326">[SWS_CORE_00326]</a>.</li>
<li><strong>Asynchrone Verkettung (Continuations):</strong> Anstelle synchronen Blockierens kann über <code>then()</code> ein Callback registriert werden, optional unter Zuweisung an einen Ausführungskontext (Executor) <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>. Der Callback nimmt das Ergebnis als <code>Result&lt;T, E&gt;</code>-Rvalue entgegen. Liefert die Fortsetzungsfunktion selbst ein <code>Future</code> oder <code>Result</code> zurück, führt <code>then()</code> ein automatisches Unwrapping durch und liefert direkt ein entsprechendes <code>Future&lt;T2, E2&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Im Umgang mit <code>ara::core::Future</code> sind folgende Fehlersituationen spezifiziert:</p>
<ul>
<li><strong>Aufruf auf ungültiger Instanz:</strong> Der Aufruf von <code>is_ready()</code>, <code>wait()</code>, <code>wait_for()</code>, <code>wait_until()</code>, <code>GetResult()</code> oder <code>then()</code> bei einer ungültigen Instanz (<code>valid() == false</code>) stellt eine <code>FutureInvalidViolation</code> dar <a class="spec-record-ref" data-req="SWS_CORE_00328" href="../spec/record.html?id=SWS_CORE_00328">[SWS_CORE_00328]</a> <a class="spec-record-ref" data-req="SWS_CORE_00329" href="../spec/record.html?id=SWS_CORE_00329">[SWS_CORE_00329]</a> <a class="spec-record-ref" data-req="SWS_CORE_00330" href="../spec/record.html?id=SWS_CORE_00330">[SWS_CORE_00330]</a> <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00332" href="../spec/record.html?id=SWS_CORE_00332">[SWS_CORE_00332]</a> <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>. Beim Aufruf von <code>get()</code> wird in diesem Fall eine <code>FutureException</code> mit dem Fehlercode <code>kNoState</code> geworfen <a class="spec-record-ref" data-req="SWS_CORE_00326" href="../spec/record.html?id=SWS_CORE_00326">[SWS_CORE_00326]</a>.</li>
<li><strong>Verlassener Shared State (Broken Promise):</strong> Wird der Shared State vom assoziierten Promise vorzeitig aufgegeben, liefert <code>GetResult()</code> ein <code>Result</code> mit dem standardisierten Fehlercode <code>FutureErrc::kBrokenPromise</code> <a class="spec-record-ref" data-req="SWS_CORE_00336" href="../spec/record.html?id=SWS_CORE_00336">[SWS_CORE_00336]</a>. Beim Aufruf von <code>get()</code> wird die entsprechende Ausnahme ausgelöst <a class="spec-record-ref" data-req="SWS_CORE_00326" href="../spec/record.html?id=SWS_CORE_00326">[SWS_CORE_00326]</a>.</li>
<li><strong>Ausnahmen in Fortsetzungsfunktionen:</strong> Eine registrierte Continuation darf keine Ausnahmen werfen, außer zur Umsetzung einer Violation. Löst sie dennoch eine Ausnahme aus, führt dies zu einer <code>FutureContinuationHasThrownViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>. Ausnahmen in Closures müssen abgefangen und als Fehlerzustand in Form eines <code>Result</code> oder <code>Future</code> zurückgegeben werden <a class="spec-record-ref" data-req="SWS_CORE_00331" href="../spec/record.html?id=SWS_CORE_00331">[SWS_CORE_00331]</a> <a class="spec-record-ref" data-req="SWS_CORE_00337" href="../spec/record.html?id=SWS_CORE_00337">[SWS_CORE_00337]</a>.</li>
</ul>
