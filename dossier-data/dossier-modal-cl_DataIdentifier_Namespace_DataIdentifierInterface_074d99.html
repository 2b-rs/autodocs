<h4>Context</h4>
<p>In the <code>diag</code> module of the AUTOSAR Adaptive Platform, the C++ class <code>&lt;DataIdentifierInterface&gt;</code> serves as a server-side base interface for diagnostic data identifiers (Data Identifiers, DIDs) according to ISO 14229-1 (UDS). The interface defines the standardized bridge between the platform's diagnostic management and the application-specific routines for providing or updating diagnostic data.</p>
<p>The interaction typically involves three core components:</p>
<ul>
<li><strong>Diagnostic Manager (DM):</strong> Receives UDS service requests (such as Service 0x22 <em>ReadDataByIdentifier</em> or Service 0x2E <em>WriteDataByIdentifier</em>) from external diagnostic testers and forwards them to the matching registered interface instance (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>, <a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>).</li>
<li><strong>Application handler:</strong> A concrete Adaptive application class derives from <code>&lt;DataIdentifierInterface&gt;</code> and implements the pure virtual methods <code>Read</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>) as well as <code>Write</code> (<a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
<li><strong>Diagnostic tester (client):</strong> Sends UDS requests to the vehicle electronic control unit and receives the responses aggregated by the Diagnostic Manager.</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance is created via the parameterized constructor by passing a <code>ara::core::InstanceSpecifier</code> and the mode <code>ara::diag::ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>). Via the concurrency type, the caller specifies whether the implementation is designed to be concurrency-safe (<code>kConcurrent</code>) or not concurrency-safe (<code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</p>
<p>Instances of <code>&lt;DataIdentifierInterface&gt;</code> have a unique identity and must neither be copied nor moved. Accordingly, both the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01665" href="../spec/record.html?id=SWS_DM_01665">[SWS_DM_01665]</a>) and the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01666" href="../spec/record.html?id=SWS_DM_01666">[SWS_DM_01666]</a>) as well as the associated assignment operators (<a class="spec-record-ref" data-req="SWS_DM_01663" href="../spec/record.html?id=SWS_DM_01663">[SWS_DM_01663]</a>, <a class="spec-record-ref" data-req="SWS_DM_01664" href="../spec/record.html?id=SWS_DM_01664">[SWS_DM_01664]</a>) are deleted (<code>=delete</code>).</p>
<p>With regard to service states, the class distinguishes two phases:</p>
<ul>
<li><strong>Inactive (Not offered):</strong> After construction, the object is present locally, but does not accept any diagnostic requests.</li>
<li><strong>Active (Offered):</strong> Only the explicit call to the method <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>) activates the forwarding of requests by the Diagnostic Manager to this instance.</li>
<li><strong>Deactivated:</strong> Calling <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>) stops the forwarding, and the instance transitions back to the inactive state.</li>
</ul>
<p>Destruction takes place via the virtual destructor <code>~&lt;DataIdentifierInterface&gt;()</code> (<a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>). This is not thread-safe and not exception-safe; prior to destruction, <code>StopOffer()</code> should presumably be called to terminate pending forwardings in the Diagnostic Manager in an orderly manner.</p>

<h4>Usage Path</h4>
<p>The regular procedure for providing and processing diagnostic read requests follows a defined sequence of steps:</p>
<ol>
<li><strong>Construction:</strong> The application instantiates the derived DID class and links it to the modeled port prototype via the <code>instanceSpec</code> (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</li>
<li><strong>Offering:</strong> The application calls <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>). The method returns a <code>ara::core::Result&lt;void&gt;</code> indicating the success of registration with the Diagnostic Manager.</li>
<li><strong>Processing:</strong> If a UDS read request for this DID is received by the Diagnostic Manager, it delegates the call to the virtual method <code>Read(metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>). For write requests, the DM analogously calls <code>Write(..., metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
<li><strong>Cancellation handling and return:</strong> During asynchronous execution, the implementation can check via <code>cancellationHandler.IsCanceled()</code> whether the conversation was cancelled, or register a notifier via <code>cancellationHandler.SetNotifier(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>). The result is provided as <code>ara::core::Future</code>, which in the event of success contains the generated output object <code>&lt;DataIdentifier&gt;ReadOutput</code> with the output arguments (<a class="spec-record-ref" data-req="SWS_DM_00579" href="../spec/record.html?id=SWS_DM_00579">[SWS_DM_00579]</a>, <a class="spec-record-ref" data-req="SWS_DM_80013" href="../spec/record.html?id=SWS_DM_80013">[SWS_DM_80013]</a>).</li>
<li><strong>Deregistration:</strong> If the service is no longer required, the application calls <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors can occur during initialization, during service offering, and during method processing:</p>
<ul>
<li><strong>Construction violations:</strong> If the resolution or binding of the <code>InstanceSpecifier</code> in the model fails, the framework throws defined violations (<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>):
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not reference a PortPrototype.</li>
  <li><code>PortInterfaceMappingViolation</code>: A PortPrototype typed by <code>DiagnosticDataIdentifierInterface</code> is not referenced by a <code>DiagnosticDataPortMapping</code>.</li>
  <li><code>ProcessMappingViolation</code>: At runtime, no matching modeled process exists for the available <code>InstanceRef</code>.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another constructor call within this process.</li>
  </ul>
</li>
<li><strong>Error during Offer:</strong> If the service is already offered, <code>Offer()</code> fails and returns a <code>ara::core::Result</code> with the error code <code>ara::diag::DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>).</li>
<li><strong>Processing and UDS errors:</strong> If a read or write request cannot be carried out successfully, the handler sets the returned <code>ara::core::Future</code> to a corresponding Negative Response Code (NRC) via <code>ara::diag::DiagUdsNrcErrc</code> according to ISO 14229-1 or to a <code>ApApplicationError</code> (<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
</ul>
