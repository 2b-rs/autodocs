<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>&lt;DataIdentifier-Namespace&gt;::&lt;DataIdentifierInterface&gt;</code> ermöglicht adaptiven Anwendungen die Bereitstellung modellspezifischer Diagnose-Datenbezeichner gegenüber dem Diagnostic Management <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>. Nach der Erzeugung schaltet <code>Offer()</code> die Weiterleitung von Anfragen frei, die über <code>Read()</code> oder <code>Write()</code> asynchron bearbeitet und bei Bedarf mit UDS-Fehlercodes beantwortet werden <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a> <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>. Da die Instanz weder kopier- noch verschiebbar ist, wird der Dienst vor der Zerstörung explizit über <code>StopOffer()</code> beendet <a class="spec-record-ref" data-req="SWS_DM_01665" href="../spec/record.html?id=SWS_DM_01665">[SWS_DM_01665]</a> <a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>.</p>

<h4>Kontext</h4>
<p>Die C++-Klasse <code>&lt;DataIdentifier-Namespace&gt;::&lt;DataIdentifierInterface&gt;</code> fungiert als funktionale Schnittstelle für Diagnose-Datenbezeichner (Data Identifiers, DIDs) im Modul <code>diag</code> der Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=68">SWS Diagnostics S. 68</a>. Sie verbindet die adaptive Anwendungsschicht mit dem zentralen Diagnostic Management (DM). Das Diagnostic Management empfängt externe Diagnoseanfragen und leitet diese an die registrierte Instanz weiter <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>. Die Anwendungssoftware stellt über abgeleitete Klassen die konkrete Implementierung bereit, um Dateninhalte über Lese- oder Schreiboperationen abzufragen oder zu aktualisieren <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a> <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung erfolgt über den parametrisierten Konstruktor unter Übergabe eines <code>ara::core::InstanceSpecifier</code> und des Nebenläufigkeitsmodus <code>ara::diag::ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>. Letzterer legt fest, ob Aufrufe an die Instanz nebenläufig (<code>kConcurrent</code>) oder nicht nebenläufig (<code>kNotConcurrent</code>) verarbeitet werden dürfen <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>. Da eine Instanz fest an ihre Modellkonfiguration gebunden ist, sind sowohl Kopier- als auch Verschiebekonstruktor explizit gelöscht <a class="spec-record-ref" data-req="SWS_DM_01665" href="../spec/record.html?id=SWS_DM_01665">[SWS_DM_01665]</a> <a class="spec-record-ref" data-req="SWS_DM_01666" href="../spec/record.html?id=SWS_DM_01666">[SWS_DM_01666]</a>; gleiches gilt für die Kopier- und Verschiebezuweisungsoperatoren <a class="spec-record-ref" data-req="SWS_DM_01663" href="../spec/record.html?id=SWS_DM_01663">[SWS_DM_01663]</a> <a class="spec-record-ref" data-req="SWS_DM_01664" href="../spec/record.html?id=SWS_DM_01664">[SWS_DM_01664]</a>.</p>
<p>Nach der Instanziierung befindet sich die Schnittstelle im inaktiven Zustand. Erst durch den Aufruf von <code>Offer()</code> wird die Weiterleitung von Diagnoseanfragen durch das Diagnostic Management scharfgeschaltet <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>. Die Methode <code>StopOffer()</code> beendet diese Weiterleitung wieder <a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>. Die Freigabe der Ressourcen erfolgt über den virtuellen Destruktor <a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>. Interpretation: Vor der Zerstörung des Objekts dürfte typischerweise <code>StopOffer()</code> aufgerufen werden, um offene oder neu eingehende Weiterleitungen des DM geordnet zu verhindern.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Instanziierung, die Dienstanmeldung, die asynchrone Bearbeitung von Anfragen und die anschließende Deaktivierung:</p>
<ol>
<li><strong>Instanziierung:</strong> Die Anwendung erzeugt eine Instanz der Schnittstelle unter Angabe des <code>InstanceSpecifier</code> und der gewünschten <code>ConcurrencyType</code>-Einstellung <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>.</li>
<li><strong>Dienstfreigabe:</strong> Die Anwendung ruft <code>Offer()</code> auf, wodurch das Diagnostic Management Anfragen an diesen Handler zustellen kann <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>.</li>
<li><strong>Anfragebearbeitung:</strong> Bei Lesezugriffen ruft das DM die rein virtuelle Methode <code>Read()</code> auf <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, bei Schreibzugriffen <code>Write()</code> <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>. Über den übergebenen <code>cancellationHandler</code> kann die Applikation Abbruchereignisse überwachen. Die Ergebnisse werden asynchron als <code>ara::core::Future</code> bereitgestellt, das bei <code>Read()</code> ein <code>ReadOutput</code>-Objekt mit den Ausgabedaten enthält <a class="spec-record-ref" data-req="SWS_DM_00579" href="../spec/record.html?id=SWS_DM_00579">[SWS_DM_00579]</a> <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a> <a class="spec-record-ref" data-req="SWS_DM_80013" href="../spec/record.html?id=SWS_DM_80013">[SWS_DM_80013]</a>.</li>
<li><strong>Dienstbeendigung:</strong> Durch Aufruf von <code>StopOffer()</code> wird die Weiterleitung gestoppt <a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>, bevor das Objekt zerstört wird <a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Bereits bei der Objekterzeugung können Modellierungsfehler zu Verletzungen führen: Fehlen Port- oder Prozessverknüpfungen, treten <code>InstanceSpecifierMappingIntegrityViolation</code>, <code>PortInterfaceMappingViolation</code> oder <code>ProcessMappingViolation</code> auf <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>. Wird derselbe <code>InstanceSpecifier</code> im selben Prozess wiederverwendet, meldet das Framework <code>InstanceSpecifierAlreadyInUseViolation</code> <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>.</p>
<p>Wird <code>Offer()</code> aufgerufen, obwohl der Dienst bereits angeboten wird, schlägt der Aufruf fehl und liefert über das <code>ara::core::Result</code> den Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> zurück <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>. Schlägt die Ausführung von <code>Read()</code> oder <code>Write()</code> fehl, übermittelt die Implementierung Fehler asynchron im <code>Future</code> mittels ISO 14229-1 UDS-Fehlercodes (<code>DiagUdsNrcErrc</code>) oder anwendungsspezifischer <code>ApApplicationError</code> <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a> <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>. Hinsichtlich der Ausnahmesicherheit sind Konstruktor und Bearbeitungsmethoden als exception safe spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a> <a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a> <a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a> <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>, während der Destruktor nicht als exception safe ausgewiesen ist <a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>.</p>
