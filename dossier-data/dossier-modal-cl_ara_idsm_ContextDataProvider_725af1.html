<h4>Kontext</h4>
<p>Die Klasse <code>ara::idsm::ContextDataProvider</code> dient der Bereitstellung und Modifikation von Kontextdaten für das Intrusion Detection System Manager (IdsM) Subsystem <a class="spec-record-ref" data-req="SWS_AIDSM_10500" href="../spec/record.html?id=SWS_AIDSM_10500">[SWS_AIDSM_10500]</a>. Innerhalb der Sicherheitsarchitektur fungiert die Klasse als Schnittstelle zwischen einer sicherheitsrelevanten Anwendung und dem IdsM-Dienst. Da die Mitgliedsfunktion <code>ModifyContextData</code> als rein virtuell spezifiziert ist <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>, stellt <code>ContextDataProvider</code> eine abstrakte Basisklasse dar. Eine Anwendung leitet eine eigene Implementierung ab, um bei sicherheitsrelevanten Ereignissen spezifische Kontextdaten zu ergänzen. Die Bindung an die Architekturkonfiguration erfolgt über einen <code>ara::core::InstanceSpecifier</code> für den modellierten Provider-Port <a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung einer Instanz erfolgt explizit über den Konstruktor unter Angabe des Port-Bezeichners (<code>ara::core::InstanceSpecifier</code>) sowie der Pufferparameter <code>additionalBytes</code> und <code>originalContextDataOffset</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>. Dieser Konstruktor ist als threadsicher deklariert <a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>. Um eindeutige Besitzverhältnisse für den Schnittstellenendpunkt zu garantieren, sind sowohl der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_AIDSM_10504" href="../spec/record.html?id=SWS_AIDSM_10504">[SWS_AIDSM_10504]</a> als auch der Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_AIDSM_10506" href="../spec/record.html?id=SWS_AIDSM_10506">[SWS_AIDSM_10506]</a> gelöscht. Eine Übergabe der Instanz ist über Move-Semantik möglich: Der Verschiebekonstruktor ist threadsicher <a class="spec-record-ref" data-req="SWS_AIDSM_10503" href="../spec/record.html?id=SWS_AIDSM_10503">[SWS_AIDSM_10503]</a>, während der Zuweisungsoperator <code>operator=</code> mit Rvalue-Referenz als nicht threadsicher definiert ist <a class="spec-record-ref" data-req="SWS_AIDSM_10505" href="../spec/record.html?id=SWS_AIDSM_10505">[SWS_AIDSM_10505]</a>.</p>

<p>Nach der Erzeugung befindet sich die Instanz im inaktiven Zustand. Erst durch den expliziten Aufruf von <code>Offer()</code> wird die Registrierung aktiviert und IdsM autorisiert, <code>ModifyContextData</code> aufzurufen <a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>. Über <code>StopOffer()</code> kann diese Autorisierung jederzeit wieder entzogen werden <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>. Vor der Zerstörung des Objekts über den virtuellen Destruktor <a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a> dürfte nach gängiger Praxis <code>StopOffer()</code> aufgerufen werden müssen, um laufende Callbacks durch IdsM rechtzeitig abzustellen (Interpretation). Der virtuelle Destruktor ist als nicht threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Anwendungsfall beginnt mit der Definition einer anwendungsspezifischen Klasse, die von <code>ContextDataProvider</code> erbt und die Methode <code>ModifyContextData</code> implementiert <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>. Nach der Instanziierung ruft die Anwendung <code>Offer()</code> auf, um die Kontextdaten für IdsM bereitzustellen <a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>. Sobald IdsM ein Sicherheitsereignis registriert, für das Kontextdaten ergänzt werden sollen, ruft das Subsystem den Callback <code>ModifyContextData</code> auf <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>. Die Methode erhält den Datenbereich als <code>ara::core::Span&lt;std::uint8_t&gt;</code> sowie die Kennung <code>EventIdType</code>, aktualisiert den Pufferinhalt und meldet die tatsächliche Bytezahl als <code>ara::core::Result&lt;std::size_t&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>. Soll die Datenbereitstellung beendet werden, ruft die Anwendung <code>StopOffer()</code> auf <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Alle Methoden der Schnittstelle sind mit <code>noexcept</code> deklariert; Fehler werden über den Typ <code>ara::core::Result</code> zurückgegeben. Der Aufruf von <code>Offer()</code> gibt ein <code>ara::core::Result&lt;void&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>, das von der Anwendung geprüft werden muss, um eventuelle Fehler bei der Dienstbereitstellung abzufangen. Kann der Provider die angeforderten Kontextdaten in <code>ModifyContextData</code> nicht schreiben, dürfte die Implementierung einen systemspezifischen Fehler im <code>ara::core::Result&lt;std::size_t&gt;</code> melden (Interpretation) <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>.</p>

<p>Bezüglich der Nebenläufigkeit ist zu beachten, dass <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a>, <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>, <code>ModifyContextData()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>, der Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_AIDSM_10505" href="../spec/record.html?id=SWS_AIDSM_10505">[SWS_AIDSM_10505]</a> und der Destruktor <a class="spec-record-ref" data-req="SWS_AIDSM_10502" href="../spec/record.html?id=SWS_AIDSM_10502">[SWS_AIDSM_10502]</a> als nicht threadsicher spezifiziert sind.
