<div class="ai-level" data-ai-level="2">
<p>Je ECU gibt es genau einen Diagnostic Event Manager <a class="spec-record-ref" data-req="SWS_Dem_00126" href="../../spec/record.html?id=SWS_Dem_00126">[SWS_Dem_00126]</a>. Er nimmt Testergebnisse von Diagnosemonitoren entgegen, entprellt sie und pflegt daraus UDS-Statusbits sowie Ereignisspeichereinträge mit Freeze Frames und Extended Data. DCM und J1939Dcm filtern, lesen und löschen diese Daten über clientbezogene APIs. Meist folgen sie dabei dem Muster „auswählen, dann anfordern“ <a class="spec-record-ref" data-req="SWS_Dem_01253" href="../../spec/record.html?id=SWS_Dem_01253">[SWS_Dem_01253]</a>. Wichtigste Randbedingung ist der Lebenszyklus: Vor <code>Dem_Init</code> werden Meldungen nur gepuffert, voll funktionsfähig ist das Modul erst danach.</p>

<p>Der Lebenszyklus trennt einen Vorinitialisierungsmodus von der vollen Funktion <a class="spec-record-ref" data-req="SWS_Dem_00169" href="../../spec/record.html?id=SWS_Dem_00169">[SWS_Dem_00169]</a>. Nach <code>Dem_PreInit</code> gemeldete Ergebnisse werden gepuffert und lösen noch keine Monitorstatus-Callbacks aus (<a class="spec-record-ref" data-req="SWS_Dem_00167" href="../../spec/record.html?id=SWS_Dem_00167">[SWS_Dem_00167]</a>, <a class="spec-record-ref" data-req="SWS_Dem_01289" href="../../spec/record.html?id=SWS_Dem_01289">[SWS_Dem_01289]</a>). Mit <code>Dem_Init</code> wird der DEM voll funktionsfähig <a class="spec-record-ref" data-req="SWS_Dem_00340" href="../../spec/record.html?id=SWS_Dem_00340">[SWS_Dem_00340]</a>. <code>Dem_Shutdown</code> schließt ausstehende Operationen ab und gibt geänderte Daten an NvM (<a class="spec-record-ref" data-req="SWS_Dem_00102" href="../../spec/record.html?id=SWS_Dem_00102">[SWS_Dem_00102]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00341" href="../../spec/record.html?id=SWS_Dem_00341">[SWS_Dem_00341]</a>).</p>
<p>Monitore melden mit <code>Dem_SetEventStatus</code> qualifizierte oder vorläufige Ergebnisse <a class="spec-record-ref" data-req="SWS_Dem_00926" href="../../spec/record.html?id=SWS_Dem_00926">[SWS_Dem_00926]</a>. <h4>Lebenszyklus: Vorinitialisierung, Betrieb und Shutdown</h4>
<p>Der DEM unterscheidet einen Vorinitialisierungsmodus und einen voll initialisierten Modus <a class="spec-record-ref" data-req="SWS_Dem_00169" href="../../spec/record.html?id=SWS_Dem_00169">[SWS_Dem_00169]</a>. <code>Dem_PreInit</code> initialisiert die für die Event-Verarbeitung nötigen Zustände <a class="spec-record-ref" data-req="SWS_Dem_00180" href="../../spec/record.html?id=SWS_Dem_00180">[SWS_Dem_00180]</a>, darunter die interne Entprellung <a class="spec-record-ref" data-req="SWS_Dem_01213" href="../../spec/record.html?id=SWS_Dem_01213">[SWS_Dem_01213]</a>. Danach gemeldete Events landen in einem Puffer <a class="spec-record-ref" data-req="SWS_Dem_00167" href="../../spec/record.html?id=SWS_Dem_00167">[SWS_Dem_00167]</a> und lösen noch keine Monitorstatus-Callbacks aus <a class="spec-record-ref" data-req="SWS_Dem_01289" href="../../spec/record.html?id=SWS_Dem_01289">[SWS_Dem_01289]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_FIGURE_Figure_7_42.html" data-snip="SNIP_CLASSIC_DEM_FIGURE_Figure_7_42">SWS DEM Abb. 7.42 S. 169</a>.</p>
<p><code>Dem_Init</code> übernimmt den Post-Build-Zeiger auf <code>Dem_ConfigType</code> (<a class="spec-record-ref" data-req="SWS_Dem_00181" href="../../spec/record.html?id=SWS_Dem_00181">[SWS_Dem_00181]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00924" href="../../spec/record.html?id=SWS_Dem_00924">[SWS_Dem_00924]</a>). Die Funktion initialisiert oder reinitialisiert das Modul <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_8_3_2_2_Dem_Init.html" data-snip="SNIP_CLASSIC_DEM_SECTION_8_3_2_2_Dem_Init">SWS DEM S. 260</a>. Danach ist der DEM voll funktionsfähig <a class="spec-record-ref" data-req="SWS_Dem_00340" href="../../spec/record.html?id=SWS_Dem_00340">[SWS_Dem_00340]</a>. Der Monitorstatus wird aus vorab gemeldeten Ergebnissen oder dem NvM-Stand gebildet <a class="spec-record-ref" data-req="SWS_Dem_01326" href="../../spec/record.html?id=SWS_Dem_01326">[SWS_Dem_01326]</a>. Erst dann folgt <code>FiM_DemInit</code> <a class="spec-record-ref" data-req="SWS_Dem_01325" href="../../spec/record.html?id=SWS_Dem_01325">[SWS_Dem_01325]</a>. Ein vor <code>Dem_Init</code> angestoßener Zyklus-Neustart wird nachgeholt <a class="spec-record-ref" data-req="SWS_Dem_01318" href="../../spec/record.html?id=SWS_Dem_01318">[SWS_Dem_01318]</a>.</p>
<p>Im Betrieb bearbeitet <code>Dem_MainFunction</code> alle nicht ereignisgetriebenen Funktionen <a class="spec-record-ref" data-req="SWS_Dem_00125" href="../../spec/record.html?id=SWS_Dem_00125">[SWS_Dem_00125]</a>. <code>Dem_Shutdown</code> schließt ausstehende Operationen ab <a class="spec-record-ref" data-req="SWS_Dem_00102" href="../../spec/record.html?id=SWS_Dem_00102">[SWS_Dem_00102]</a>. Geänderte nichtflüchtige Daten gehen spätestens dann an NvM <a class="spec-record-ref" data-req="SWS_Dem_00341" href="../../spec/record.html?id=SWS_Dem_00341">[SWS_Dem_00341]</a>. Interpretation: Weil <code>Dem_Init</code> laut <a class="spec-record-ref" data-req="SWS_Dem_00181" href="../../spec/record.html?id=SWS_Dem_00181">[SWS_Dem_00181]</a> auch reinitialisiert, dürfte ein Neustart nach <code>Dem_Shutdown</code> über einen erneuten <code>Dem_Init</code>-Aufruf erfolgen.</p>

<h4>Vom Monitor-Report zum qualifizierten Ergebnis</h4>
<p>Monitore melden Testergebnisse mit <code>Dem_SetEventStatus</code>, sobald ein neues Ergebnis vorliegt (<a class="spec-record-ref" data-req="SWS_Dem_00330" href="../../spec/record.html?id=SWS_Dem_00330">[SWS_Dem_00330]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_7_7_1_Event_status_management.html" data-snip="SNIP_CLASSIC_DEM_SECTION_7_7_1_Event_status_management">SWS DEM S. 81</a>). <code>Dem_EventStatusType</code> unterscheidet drei Arten von Meldungen <a class="spec-record-ref" data-req="SWS_Dem_00926" href="../../spec/record.html?id=SWS_Dem_00926">[SWS_Dem_00926]</a>:
<ul>
<li>qualifizierte Ergebnisse (<code>DEM_EVENT_STATUS_PASSED</code>/<code>_FAILED</code>),</li>
<li>Vorergebnisse für die interne Entprellung (<code>_PREPASSED</code>/<code>_PREFAILED</code>),</li>
<li><code>DEM_EVENT_STATUS_FDC_THRESHOLD_REACHED</code>.</li>
</ul></p>
<p>Die Entprellung ist je Event konfigurierbar <a class="spec-record-ref" data-req="SWS_Dem_00413" href="../../spec/record.html?id=SWS_Dem_00413">[SWS_Dem_00413]</a>:
<ul>
<li>zählerbasiert <a class="spec-record-ref" data-req="SWS_Dem_00414" href="../../spec/record.html?id=SWS_Dem_00414">[SWS_Dem_00414]</a>,</li>
<li>zeitbasiert <a class="spec-record-ref" data-req="SWS_Dem_00426" href="../../spec/record.html?id=SWS_Dem_00426">[SWS_Dem_00426]</a>,</li>
<li>monitorintern <a class="spec-record-ref" data-req="SWS_Dem_00437" href="../../spec/record.html?id=SWS_Dem_00437">[SWS_Dem_00437]</a>.</li>
</ul>
Zähler- bzw. Timerwerte bildet der DEM linear auf den Fault Detection Counter von -128 bis +127 ab (<a class="spec-record-ref" data-req="SWS_Dem_00415" href="../../spec/record.html?id=SWS_Dem_00415">[SWS_Dem_00415]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00427" href="../../spec/record.html?id=SWS_Dem_00427">[SWS_Dem_00427]</a>). Die zählerbasierte Entprellung und der Monitorstatus laufen synchron im Aufrufkontext (<a class="spec-record-ref" data-req="SWS_Dem_01279" href="../../spec/record.html?id=SWS_Dem_01279">[SWS_Dem_01279]</a>, <a class="spec-record-ref" data-req="SWS_Dem_01280" href="../../spec/record.html?id=SWS_Dem_01280">[SWS_Dem_01280]</a>). Das UDS-Statusbyte berechnet der DEM dagegen asynchron <a class="spec-record-ref" data-req="SWS_Dem_01285" href="../../spec/record.html?id=SWS_Dem_01285">[SWS_Dem_01285]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_7_7_1_2_Monitor_status_and_UDS_status_update.html" data-snip="SNIP_CLASSIC_DEM_SECTION_7_7_1_2_Monitor_status_and_UDS_status_update">SWS DEM S. 83</a>.</p>

<h4>Freigabebedingungen, Betriebszyklen und Verfügbarkeit</h4>
<p>Enable Conditions und ein abgeschaltetes DTC-Setting blockieren die Verarbeitung von Statusmeldungen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_7_7_1_2_Monitor_status_and_UDS_status_update.html" data-snip="SNIP_CLASSIC_DEM_SECTION_7_7_1_2_Monitor_status_and_UDS_status_update">SWS DEM S. 83</a>. Die Regeln dazu stehen in <a class="spec-record-ref" data-req="SWS_Dem_00449" href="../../spec/record.html?id=SWS_Dem_00449">[SWS_Dem_00449]</a> und <a class="spec-record-ref" data-req="SWS_Dem_00079" href="../../spec/record.html?id=SWS_Dem_00079">[SWS_Dem_00079]</a>. <code>DemDebounceBehavior</code> legt fest, ob die Entprellung dabei zurückgesetzt <a class="spec-record-ref" data-req="SWS_Dem_00654" href="../../spec/record.html?id=SWS_Dem_00654">[SWS_Dem_00654]</a> oder eingefroren wird <a class="spec-record-ref" data-req="SWS_Dem_00655" href="../../spec/record.html?id=SWS_Dem_00655">[SWS_Dem_00655]</a>. Storage Conditions verhindern dagegen nur die Ablage im Speicher (<a class="spec-record-ref" data-req="SWS_Dem_00455" href="../../spec/record.html?id=SWS_Dem_00455">[SWS_Dem_00455]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00556" href="../../spec/record.html?id=SWS_Dem_00556">[SWS_Dem_00556]</a>).</p>
<p><code>Dem_RestartOperationCycle</code> arbeitet asynchron. Die betroffenen Monitore werden über <code>InitMonitorForEvent</code> reinitialisiert <a class="spec-record-ref" data-req="SWS_Dem_00679" href="../../spec/record.html?id=SWS_Dem_00679">[SWS_Dem_00679]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_8_3_3_21_Dem_RestartOperationCycle.html" data-snip="SNIP_CLASSIC_DEM_SECTION_8_3_3_21_Dem_RestartOperationCycle">SWS DEM S. 274</a>. Neustarts werden nicht gepuffert <a class="spec-record-ref" data-req="SWS_Dem_01316" href="../../spec/record.html?id=SWS_Dem_01316">[SWS_Dem_01316]</a>. Weitere Auslöser für <code>InitMonitorForEvent</code> sind:
<ul>
<li>das Löschen <a class="spec-record-ref" data-req="SWS_Dem_00680" href="../../spec/record.html?id=SWS_Dem_00680">[SWS_Dem_00680]</a>,</li>
<li>wieder erfüllte Enable Conditions <a class="spec-record-ref" data-req="SWS_Dem_00681" href="../../spec/record.html?id=SWS_Dem_00681">[SWS_Dem_00681]</a>,</li>
<li>Storage Conditions <a class="spec-record-ref" data-req="SWS_Dem_01113" href="../../spec/record.html?id=SWS_Dem_01113">[SWS_Dem_01113]</a>.</li>
</ul>
Bei gleichzeitigen Auslösern wird der Callback nur einmal aufgerufen, mit dem höchstpriorisierten Grund <a class="spec-record-ref" data-req="SWS_Dem_01046" href="../../spec/record.html?id=SWS_Dem_01046">[SWS_Dem_01046]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_FIGURE_Figure_7_2.html" data-snip="SNIP_CLASSIC_DEM_FIGURE_Figure_7_2">SWS DEM S. 47</a>.</p>
<p>Mit <code>Dem_SetEventAvailable</code> markierte, nicht verfügbare Events behandelt der DEM, als wären sie nicht konfiguriert <a class="spec-record-ref" data-req="SWS_Dem_01108" href="../../spec/record.html?id=SWS_Dem_01108">[SWS_Dem_01108]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_7_4_8_Availability_of_events_visibility_and_computation.html" data-snip="SNIP_CLASSIC_DEM_SECTION_7_4_8_Availability_of_events_visibility_and_computation">SWS DEM S. 66</a>. In VARIANT-POST-BUILD fehlt diese API <a class="spec-record-ref" data-req="SWS_Dem_01106" href="../../spec/record.html?id=SWS_Dem_01106">[SWS_Dem_01106]</a>. Ein unterdrückter DTC ist dagegen nur für den Tester unsichtbar, die Event-Verarbeitung läuft weiter <a class="spec-record-ref" data-req="SWS_Dem_01102" href="../../spec/record.html?id=SWS_Dem_01102">[SWS_Dem_01102]</a>.</p>

<h4>Ereignisspeicher: Ablage, Umgebungsdaten und Verdrängung</h4>
<p>Der DEM führt den primären Ereignisspeicher <a class="spec-record-ref" data-req="SWS_Dem_00010" href="../../spec/record.html?id=SWS_Dem_00010">[SWS_Dem_00010]</a> und optional benutzerdefinierte Speicher mit gleichem Verhalten <a class="spec-record-ref" data-req="SWS_Dem_01063" href="../../spec/record.html?id=SWS_Dem_01063">[SWS_Dem_01063]</a>. Ein Eintrag bündelt Zähler, Freeze Frames und Extended Data <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-6106514039963249.html" data-snip="FIG-6106514039963249">SWS DEM Abb. 7.13 S. 77</a>. <code>DemEventMemoryEntryStorageTrigger</code> bestimmt, wann ein Eintrag entsteht:
<ul>
<li>bei TestFailed oder FDC-Schwelle <a class="spec-record-ref" data-req="SWS_Dem_00783" href="../../spec/record.html?id=SWS_Dem_00783">[SWS_Dem_00783]</a>,</li>
<li>bei Pending <a class="spec-record-ref" data-req="SWS_Dem_00784" href="../../spec/record.html?id=SWS_Dem_00784">[SWS_Dem_00784]</a>,</li>
<li>bei Confirmed <a class="spec-record-ref" data-req="SWS_Dem_00785" href="../../spec/record.html?id=SWS_Dem_00785">[SWS_Dem_00785]</a>.</li>
</ul>
Durch Aging werden die ereignisbezogenen Daten entfernt <a class="spec-record-ref" data-req="SWS_Dem_01075" href="../../spec/record.html?id=SWS_Dem_01075">[SWS_Dem_01075]</a>.</p>
<p>Freeze Frames sind ereignisspezifisch und bestehen aus konfigurierten DIDs (<a class="spec-record-ref" data-req="SWS_Dem_00039" href="../../spec/record.html?id=SWS_Dem_00039">[SWS_Dem_00039]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00040" href="../../spec/record.html?id=SWS_Dem_00040">[SWS_Dem_00040]</a>). Bei volatilen Daten erfasst der Monitor sie vorab mit <code>Dem_PrestoreFreezeFrame</code>. Diese Daten nutzt der DEM bei der Ablage <a class="spec-record-ref" data-req="SWS_Dem_00464" href="../../spec/record.html?id=SWS_Dem_00464">[SWS_Dem_00464]</a> <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-6bd176f00e1eb3a4.html" data-snip="FIG-6bd176f00e1eb3a4">SWS DEM Abb. 7.37 S. 128</a>. Extended Data Records werden auf konfigurierte Trigger erfasst <a class="spec-record-ref" data-req="SWS_Dem_00809" href="../../spec/record.html?id=SWS_Dem_00809">[SWS_Dem_00809]</a>. Sie können interne Werte wie Occurrence Counter enthalten <a class="spec-record-ref" data-req="SWS_Dem_00471" href="../../spec/record.html?id=SWS_Dem_00471">[SWS_Dem_00471]</a>.</p>
<p>Fehlt ein freier Eintrag, prüft der DEM eine Verdrängung <a class="spec-record-ref" data-req="SWS_Dem_00400" href="../../spec/record.html?id=SWS_Dem_00400">[SWS_Dem_00400]</a>. <code>DEM_DISPLACEMENT_NONE</code> schließt sie aus <a class="spec-record-ref" data-req="SWS_Dem_00402" href="../../spec/record.html?id=SWS_Dem_00402">[SWS_Dem_00402]</a>. Ohne Kandidaten wird die Ablage verworfen <a class="spec-record-ref" data-req="SWS_Dem_00407" href="../../spec/record.html?id=SWS_Dem_00407">[SWS_Dem_00407]</a>. Andernfalls wird der Eintrag entfernt und die Statusbits werden angepasst (<a class="spec-record-ref" data-req="SWS_Dem_00408" href="../../spec/record.html?id=SWS_Dem_00408">[SWS_Dem_00408]</a>, <a class="spec-record-ref" data-req="SWS_Dem_00409" href="../../spec/record.html?id=SWS_Dem_00409">[SWS_Dem_00409]</a>). Einen Überlauf zeigt der DEM je Speicher an <a class="spec-record-ref" data-req="SWS_Dem_00397" href="../../spec/record.html?id=SWS_Dem_00397">[SWS_Dem_00397]</a>.</p>
