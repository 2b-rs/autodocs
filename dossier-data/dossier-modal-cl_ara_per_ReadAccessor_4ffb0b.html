<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht das blockweise, zeilenweise oder zeichenbasierte Lesen persistierter Datei- und Binärdaten.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::per::ReadAccessor</code> stellt synchrone Methoden zum sequenziellen und zeilenbasierten Lesen von Dateien im Binär- und Textmodus bereit <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>, <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>. Neben dem konsumierenden Lesen erlaubt sie die zeigerneutrale Vorschau auf folgende Bytes oder Zeichen. Da Instanzen nicht threadsicher sind, müssen parallele Zugriffe extern koordiniert werden, während im Fehlerfall eine Rollback-Garantie die Lesezeigerposition schützt <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>.</p>

<h4>Kontext und Aufgabenbereich</h4>
<p>Die Klasse <code>ara::per::ReadAccessor</code> stellt eine Schnittstelle zum synchronen Lesen von Dateiinhalten innerhalb der Persistenzverwaltung (Modul <code>per</code>) bereit und leitet virtuell von <code>FileAccessor</code> ab. Sie abstrahiert den Lesezugriff auf persistierte Datenspeicher und stellt sowohl binäre als auch textuelle Zugriffsmethoden bereit. Anwendungen können über spezialisierte Funktionen einzelne Bytes oder Zeichen prüfen und abrufen sowie zusammenhängende Blöcke oder vollständige Zeilen einlesen.</p>

<h4>Lebenszyklus und Nebenläufigkeit</h4>
<p>Der Standardkonstruktor von <code>ReadAccessor</code> ist gelöscht <a class="spec-record-ref" data-req="SWS_PER_00461" href="../spec/record.html?id=SWS_PER_00461">[SWS_PER_00461]</a>; die Instanziierung erfolgt daher typischerweise vermittelt über übergeordnete Öffnungs- und Zugriffsmechanismen des Persistenzmoduls. Die Freigabe der Schnittstelle und der gebundenen Zugriffsressourcen erfolgt über den virtuellen Destruktor <code>~ReadAccessor()</code> <a class="spec-record-ref" data-req="SWS_PER_00417" href="../spec/record.html?id=SWS_PER_00417">[SWS_PER_00417]</a>. Instanzen von <code>ReadAccessor</code> besitzen einen internen Lesezeiger, der die aktuelle Position in der Datei verwaltet. Sämtliche Methoden der Klasse sind explizit als nicht threadsicher (<code>not thread-safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, weshalb gleichzeitige Leseoperationen auf derselben Instanz von Aufrufern extern synchronisiert werden müssen.</p>

<h4>Nutzungspfade für Binär- und Textdaten</h4>
<p>Für binäre Dateioperationen bietet die Klasse Funktionen zum vorschaubaren oder sequenziellen Auslesen. Mit <code>PeekByte()</code> kann das Byte an der aktuellen Leseposition inspiziert werden, ohne den Lesezeiger zu verändern <a class="spec-record-ref" data-req="SWS_PER_00418" href="../spec/record.html?id=SWS_PER_00418">[SWS_PER_00418]</a>. Dagegen liest <code>GetByte()</code> genau ein Byte aus und rückt die Position vor <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>. Größere Datenblöcke lassen sich über <code>ReadBinary(n)</code> in einen <code>ara::core::Vector&lt;ara::core::Byte&gt;</code> einlesen, wobei die Position entsprechend angepasst wird; wird das Dateiende vorzeitig erreicht, enthält der Vektor weniger Bytes als angefordert <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a>. Mittels <code>ReadBinary()</code> können alle verbleibenden Bytes bis zum Dateiende in einem Schritt bezogen werden <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>.</p>

<p>Im Textmodus stellt <code>PeekChar()</code> eine zeichenbasierte Vorschau bereit <a class="spec-record-ref" data-req="SWS_PER_00167" href="../spec/record.html?id=SWS_PER_00167">[SWS_PER_00167]</a>, während <code>GetChar()</code> das nächste Zeichen konsumiert <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a>. Das zeilenweise Lesen erfolgt über <code>ReadLine()</code>, das bis zu einem Trennzeichen liest (Standard: <code>'\n'</code>, ASCII 0x0a); das Trennzeichen wird dabei nicht in den Ergebnisstring übernommen <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>. Abschnitte von <code>n</code> Zeichen oder der gesamte Restinhalt lassen sich über die Überladungen von <code>ReadText()</code> auslesen <a class="spec-record-ref" data-req="SWS_PER_00165" href="../spec/record.html?id=SWS_PER_00165">[SWS_PER_00165]</a>, <a class="spec-record-ref" data-req="SWS_PER_00420" href="../spec/record.html?id=SWS_PER_00420">[SWS_PER_00420]</a>. Befindet sich der Lesezeiger inmitten eines Mehrbyte-Zeichens, können die resultierenden Zeichenketten unvollständige Unicode-Codepunkte aufweisen <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>, <a class="spec-record-ref" data-req="SWS_PER_00165" href="../spec/record.html?id=SWS_PER_00165">[SWS_PER_00165]</a>.</p>

<h4>Fehlerszenarien und Fehlerbehandlung</h4>
<p>Alle Leseoperationen von <code>ReadAccessor</code> liefern ihre Werte gekapselt in einem <code>ara::core::Result</code> zurück und sind als ausnahmesicher (<code>exception safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>. Tritt während eines Zugriffs ein Fehler auf, greift eine strikte Rollback-Semantik: Die aktuelle Position des Lesezeigers bleibt im Fehlerfall stets unverändert <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>, <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a>. Typische dokumentierte Fehlerzustände umfassen:</p>
<ul>
<li><code>PerErrc::kPhysicalStorageFailure</code> bei Fehlern des physischen Speichermediums <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, <a class="spec-record-ref" data-req="SWS_PER_00420" href="../spec/record.html?id=SWS_PER_00420">[SWS_PER_00420]</a>,</li>
<li><code>PerErrc::kEof</code>, falls der Lesezeiger am Dateiende steht oder die Datei leer ist <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a>,</li>
<li><code>PerErrc::kValidationFailed</code>, wenn die Gültigkeit der Daten nicht verifiziert werden kann <a class="spec-record-ref" data-req="SWS_PER_00418" href="../spec/record.html?id=SWS_PER_00418">[SWS_PER_00418]</a>, <a class="spec-record-ref" data-req="SWS_PER_00119" href="../spec/record.html?id=SWS_PER_00119">[SWS_PER_00119]</a>,</li>
<li><code>PerErrc::kEncryptionFailed</code> bei fehlschlagender Entschlüsselung <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>, <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a> sowie</li>
<li><code>PerErrc::kAuthenticationFailed</code>, sofern die MAC-Überprüfung gespeicherter Daten fehlschlägt <a class="spec-record-ref" data-req="SWS_PER_00167" href="../spec/record.html?id=SWS_PER_00167">[SWS_PER_00167]</a>, <a class="spec-record-ref" data-req="SWS_PER_00421" href="../spec/record.html?id=SWS_PER_00421">[SWS_PER_00421]</a>.</li>
</ul>
