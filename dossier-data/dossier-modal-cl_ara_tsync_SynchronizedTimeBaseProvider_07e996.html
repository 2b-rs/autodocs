<div class="ai-level" data-ai-level="2">
<p>Die Move-Only-Klasse <code>ara::tsync::SynchronizedTimeBaseProvider</code> dient Zeit-Provider-Anwendungen zur Einspeisung, Ratenkorrektur und Validierung einer synchronisierten Zeitbasis <a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a> <a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>. Aktualisierungen können entweder sofortige Busübertragungen auslösen oder als lokales Update für den nächsten Übertragungszyklus eingeplant werden <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a> <a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a>. Während Lesezugriffe threadsicher sind, erfordern alle verändernden Methoden sowie die Notifier-Registrierung thread-lokalen oder synchronisierten Aufruf <a class="spec-record-ref" data-req="SWS_TS_01109" href="../spec/record.html?id=SWS_TS_01109">[SWS_TS_01109]</a> <a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::tsync::SynchronizedTimeBaseProvider</code> stellt für Zeit-Provider-Anwendungen den aktiven Steuerungszugang zu einer synchronisierten Zeitbasis bereit, die über einen <code>ara::core::InstanceSpecifier</code> modelliert ist <a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>. In AUTOSAR Adaptive fungiert die Instanz als Schnittstelle zwischen der bereitstellenden Applikationslogik, dem lokalen Time-Sync-Daemon und den angebundenen Kommunikationsbussen. Über diese Komponente speist die Anwendung neue Zeitwerte und anwenderspezifische Nutzdaten in das System ein, gleicht Driften über Ratenkorrekturen aus und erfasst Validierungsparameter <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a> <a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a> <a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung erfolgt explizit über einen <code>ara::core::InstanceSpecifier</code>, der auf einen PortPrototype verweisen muss, welcher durch ein <code>SynchronizedTimeBaseProviderInterface</code> typisiert ist <a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>. Der Konstruktor ist ausnahmesicher und threadsicher deklariert <a class="spec-record-ref" data-req="SWS_TS_01101" href="../spec/record.html?id=SWS_TS_01101">[SWS_TS_01101]</a>. Ein Objekt der Klasse ist ein exklusives Move-Only-Objekt: Kopierkonstruktor und Kopierzuweisungsoperator sind explizit gelöscht <a class="spec-record-ref" data-req="SWS_TS_01104" href="../spec/record.html?id=SWS_TS_01104">[SWS_TS_01104]</a> <a class="spec-record-ref" data-req="SWS_TS_01105" href="../spec/record.html?id=SWS_TS_01105">[SWS_TS_01105]</a>, während Move-Konstruktion und Move-Zuweisung unterstützt werden <a class="spec-record-ref" data-req="SWS_TS_01102" href="../spec/record.html?id=SWS_TS_01102">[SWS_TS_01102]</a> <a class="spec-record-ref" data-req="SWS_TS_01103" href="../spec/record.html?id=SWS_TS_01103">[SWS_TS_01103]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit gilt eine strikte Trennung: Reine Leseoperationen auf den Status wie <code>GetCurrentTime()</code>, <code>GetRateDeviation()</code> und <code>GetUserData()</code> sind threadsicher und können nebenläufig ausgeführt werden <a class="spec-record-ref" data-req="SWS_TS_01109" href="../spec/record.html?id=SWS_TS_01109">[SWS_TS_01109]</a> <a class="spec-record-ref" data-req="SWS_TS_01111" href="../spec/record.html?id=SWS_TS_01111">[SWS_TS_01111]</a> <a class="spec-record-ref" data-req="SWS_TS_01113" href="../spec/record.html?id=SWS_TS_01113">[SWS_TS_01113]</a>. Alle modifizierenden Operationen, die Registrierung von Benachrichtigungen sowie die Zerstörung des Objekts über den Destruktor sind dagegen nicht threadsicher und erfordern anwendungsseitige Synchronisation <a class="spec-record-ref" data-req="SWS_TS_01106" href="../spec/record.html?id=SWS_TS_01106">[SWS_TS_01106]</a> <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a> <a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Einsatz gliedert sich in die Registrierung für Validierungsrückmeldungen sowie die zyklische oder ereignisgesteuerte Zeitübermittlung:</p>
<ul>
<li><strong>Validierung registrieren:</strong> Bei Bedarf hinterlegt die Provider-Anwendung über <code>RegisterTimeValidationNotification()</code> ein Benachrichtigungsobjekt, um neu aufgezeichnete Zeit-Synchronisations-Datenblöcke zu empfangen <a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>. Es kann maximal ein Benachrichtigungsempfänger aktiv sein; eine Neu-Registrierung überschreibt eine bestehende <a class="spec-record-ref" data-req="SWS_TS_01114" href="../spec/record.html?id=SWS_TS_01114">[SWS_TS_01114]</a>, während <code>UnregisterTimeValidationNotification()</code> die Bindung löst <a class="spec-record-ref" data-req="SWS_TS_01115" href="../spec/record.html?id=SWS_TS_01115">[SWS_TS_01115]</a>.</li>
<li><strong>Zeitwert setzen:</strong> Bei einer sofort erforderlichen Verteilung ruft die Anwendung <code>SetTime()</code> auf. Dies setzt den lokalen Zeitwert und stößt unmittelbar die Übertragung auf den Bus an <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>. Soll die Busübertragung stattdessen erst im nächsten regulären Zyklus erfolgen, wird <code>UpdateTime()</code> genutzt, wodurch die Uhr zunächst nur lokal aktualisiert wird <a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a>.</li>
<li><strong>Korrektur und Nutzdaten:</strong> Über <code>SetRateCorrection()</code> kann die Drift der lokalen Uhr durch einen Korrekturfaktor angepasst werden (Werte kleiner 1.0 verlangsamen die Uhr, Werte größer 1.0 beschleunigen sie) <a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>. Zusätzliche anwenderspezifische Zeitbasis-Daten lassen sich via <code>SetUserData()</code> aktualisieren <a class="spec-record-ref" data-req="SWS_TS_01112" href="../spec/record.html?id=SWS_TS_01112">[SWS_TS_01112]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Methoden mit Rückgabewert <code>ara::core::Result&lt;void&gt;</code> signalisieren Fehlschläge über Fehlercodes des Typs <code>TsyncErrc</code> ohne Rollback-Semantik:</p>
<ul>
<li><code>TsyncErrc::kInvalidUserDataSize</code>: Tritt bei <code>SetTime()</code>, <code>UpdateTime()</code> und <code>SetUserData()</code> auf, wenn die übergebenen <code>UserData</code> die Maximallänge von <code>UserData::kMaxUserDataSize</code> (derzeit 3 Bytes) überschreiten <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a> <a class="spec-record-ref" data-req="SWS_TS_01108" href="../spec/record.html?id=SWS_TS_01108">[SWS_TS_01108]</a> <a class="spec-record-ref" data-req="SWS_TS_01112" href="../spec/record.html?id=SWS_TS_01112">[SWS_TS_01112]</a>.</li>
<li><code>TsyncErrc::kDaemonConnectionLost</code>: Tritt bei <code>SetTime()</code> auf, falls die IPC-Verbindung zum Time-Sync-Daemon zum Aufrufzeitpunkt unterbrochen ist <a class="spec-record-ref" data-req="SWS_TS_01107" href="../spec/record.html?id=SWS_TS_01107">[SWS_TS_01107]</a>.</li>
<li><code>TsyncErrc::kLimitsExceeded</code>: Wird von <code>SetRateCorrection()</code> zurückgegeben, wenn der angeforderte Ratenkorrekturfaktor außerhalb des zulässigen Wertebereichs liegt <a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>.</li>
<li><code>TsyncErrc::kFunctionNotSupported</code>: Wird von <code>SetRateCorrection()</code> gemeldet, wenn die zugrunde liegende Plattform oder Zeitbasis keine Ratenkorrektur unterstützt <a class="spec-record-ref" data-req="SWS_TS_01110" href="../spec/record.html?id=SWS_TS_01110">[SWS_TS_01110]</a>.</li>
</ul>
