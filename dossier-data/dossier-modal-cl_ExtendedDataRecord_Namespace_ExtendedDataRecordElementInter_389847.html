  <h4>Context</h4>
  <p>The interface <code>&lt;ExtendedDataRecord-Namespace&gt;::&lt;ExtendedDataRecordElementInterface&gt;</code> serves in the AUTOSAR Adaptive Platform within the functional cluster <code>diag</code> to provide data for so-called Extended Data Records (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=68">AUTOSAR_AP_SWS_Diagnostics p. 68</a>). These records are collected during diagnostic events and permanently saved in non-volatile memory by Diagnostic Management (DM) (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</p>
  <p>The interface defines the provider role on the application side: An adaptive application implements the pure virtual method <code>Read</code> to pass the requested values to the Diagnostic Manager upon corresponding diagnostic requests (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>). At least three system components are involved in the interaction: the application-specific interface implementation, the Diagnostic Manager as mediator of incoming diagnostic requests (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>), and the non-volatile memory in which the DM persists the retrieved data for the diagnostic context (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</p>

  <h4>Lifecycle</h4>
  <p>Instantiation takes place via the constructor by specifying a <code>ara::core::InstanceSpecifier</code> and the concurrency mode <code>ara::diag::ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>). The parameter <code>concurrencyType</code> determines whether the implementation is operated thread-safe (<code>kConcurrent</code>) or not thread-safe (<code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>). The class has a strict binding to its identity: copy constructor and copy assignment operator are deleted (<a class="spec-record-ref" data-req="SWS_DM_02147" href="../spec/record.html?id=SWS_DM_02147">[SWS_DM_02147]</a>, <a class="spec-record-ref" data-req="SWS_DM_02148" href="../spec/record.html?id=SWS_DM_02148">[SWS_DM_02148]</a>). Likewise, move constructor and move assignment operator are deleted (<a class="spec-record-ref" data-req="SWS_DM_02149" href="../spec/record.html?id=SWS_DM_02149">[SWS_DM_02149]</a>, <a class="spec-record-ref" data-req="SWS_DM_02150" href="../spec/record.html?id=SWS_DM_02150">[SWS_DM_02150]</a>). An instance is therefore bound to its location and cannot be transferred.</p>
  <p>After successful construction, the instance initially remains in the inactive state (<em>NotOffered</em>). By calling <code>Offer()</code>, the forwarding of requests by Diagnostic Management is activated, causing the instance to transition to the <em>Offered</em> state (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>). Calling <code>Offer()</code> again in the <em>Offered</em> state leads to an error (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>). Via the method <code>StopOffer()</code>, forwarding is deactivated again and the object returns to the <em>NotOffered</em> state (<a class="spec-record-ref" data-req="SWS_DM_02153" href="../spec/record.html?id=SWS_DM_02153">[SWS_DM_02153]</a>).</p>
  <p>Destruction takes place via the virtual destructor (<a class="spec-record-ref" data-req="SWS_DM_02151" href="../spec/record.html?id=SWS_DM_02151">[SWS_DM_02151]</a>). While the constructor is declared as thread-safe (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>), the destructor is explicitly not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_02151" href="../spec/record.html?id=SWS_DM_02151">[SWS_DM_02151]</a>). Interpretation: Terminating the service offering via <code>StopOffer()</code> must presumably be completed before calling the destructor in order to prevent concurrent read accesses during object decay.</p>

  <h4>Usage Path</h4>
  <p>The typical sequence for providing and answering diagnostic requests is as follows:</p>
  <ol>
    <li><strong>Instantiation:</strong> The deriving provider class is created by passing <code>ara::core::InstanceSpecifier</code> and the desired <code>concurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_02158" href="../spec/record.html?id=SWS_DM_02158">[SWS_DM_02158]</a>).</li>
    <li><strong>Announce offering:</strong> The application calls <code>Offer()</code>. Only after a successful return are incoming diagnostic requests forwarded from the DM to the instance (<a class="spec-record-ref" data-req="SWS_DM_02152" href="../spec/record.html?id=SWS_DM_02152">[SWS_DM_02152]</a>).</li>
    <li><strong>Query data record (Read):</strong> If Diagnostic Management requests the data element, it calls the method <code>Read(metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>):
      <ul>
        <li>The request provides context information via <code>metaInfo</code> (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
        <li>Via <code>cancellationHandler.IsCanceled()</code> or by registering a notifier function using <code>cancellationHandler.SetNotifier()</code>, the application can handle a premature termination of the conversation (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
        <li>The method returns a <code>ara::core::Future</code> with the structure <code>ReadOutput</code> (<a class="spec-record-ref" data-req="SWS_DM_02154" href="../spec/record.html?id=SWS_DM_02154">[SWS_DM_02154]</a>, <a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>). If the data is not available at the time of retrieval, the implementation must always return a value and pad the data with a fill pattern (e.g., <code>0xFF</code>) (<a class="spec-record-ref" data-req="SWS_DM_02156" href="../spec/record.html?id=SWS_DM_02156">[SWS_DM_02156]</a>).</li>
      </ul>
    </li>
    <li><strong>Stop offering service:</strong> Prior to shutdown or in maintenance states, the application calls <code>StopOffer()</code> to stop forwarding requests (<a class="spec-record-ref" data-req="SWS_DM_02153" href="../spec/record.html?id=SWS_DM_02153">[SWS_DM_02153]</a>).</li>
  </ol>
