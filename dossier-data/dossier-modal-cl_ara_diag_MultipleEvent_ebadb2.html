<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht das Abfragen und Überwachen mehrerer Diagnoseereignisse über Ereignis-Handles und Callback-Benachrichtigungen.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse ermöglicht Anwendungen die zustandsbezogene Abfrage und Überwachung mehrerer Diagnoseereignisse über eine gemeinsame Schnittstelle anhand von Event-Handles <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>. Neben der Registrierung von Benachrichtigungs-Callbacks stehen asynchrone Methoden zur Ermittlung von Event-Status, Entprellung, Fehlerzähler und DTC-Nummer bereit <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>. Instanzen sind weder kopier- noch verschiebbar und erfordern wegen des nicht threadsicheren Destruktors eine geordnete Beendigung aktiver Operationen vor der Freigabe <a class="spec-record-ref" data-req="SWS_DM_01706" href="../spec/record.html?id=SWS_DM_01706">[SWS_DM_01706]</a>, <a class="spec-record-ref" data-req="SWS_DM_02067" href="../spec/record.html?id=SWS_DM_02067">[SWS_DM_02067]</a>.</p>
<p class="ai-level-more-inline"><button type="button" class="ai-level-step ai-level-more" data-ai-level-step="1" title="Ausführlichere Fassung zeigen">mehr ›</button></p>
</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::MultipleEvent</code> stellt der Anwendung Schnittstellen bereit, um Diagnoseereignisse über Schnittstellen für Mehrfachereignisse abzufragen und zu überwachen <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>. Im Unterschied zu Einzel-Event-Klassen adressieren Operationen auf Instanzen von <code>MultipleEvent</code> konkrete Ereignisse über einen Bezeichner vom Typ <code>EventHandleType</code> <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>. Die Klasse fungiert als Schnittstelle zwischen der anwendenden Softwarekomponente und dem Diagnose-Management (DM) von Adaptive AUTOSAR <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=69">AUTOSAR AP SWS Diagnostics, S. 69</a>. Über den Port-Prototyp eines <code>DiagnosticMultipleEventInterface</code> wird das Objekt an die konfigurierte Diagnose-Infrastruktur gebunden <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>MultipleEvent</code> wird über einen expliziten Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code> erzeugt <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>. Der Konstruktor ist threadsicher und verifiziert die modellierte Bindung an einen Port-Prototyp vom Schnittstellentyp <code>DiagnosticMultipleEventInterface</code> <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>. Schlägt das Mapping fehl oder wird dieselbe Instanzkennung innerhalb des Prozesses wiederverwendet, meldet die Plattform entsprechende Verletzungen wie <code>InstanceSpecifierAlreadyInUseViolation</code> oder <code>PortInterfaceMappingViolation</code> <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>.</p>
<p>Kopier- und Verschiebeoperationen sind für <code>MultipleEvent</code> vollständig unterbunden: Sowohl der Copy- und Move-Konstruktor als auch die entsprechenden Zuweisungsoperatoren sind als gelöscht deklariert <a class="spec-record-ref" data-req="SWS_DM_02067" href="../spec/record.html?id=SWS_DM_02067">[SWS_DM_02067]</a>, <a class="spec-record-ref" data-req="SWS_DM_02068" href="../spec/record.html?id=SWS_DM_02068">[SWS_DM_02068]</a>, <a class="spec-record-ref" data-req="SWS_DM_02069" href="../spec/record.html?id=SWS_DM_02069">[SWS_DM_02069]</a>, <a class="spec-record-ref" data-req="SWS_DM_02070" href="../spec/record.html?id=SWS_DM_02070">[SWS_DM_02070]</a>. Das Objekt besitzt somit strikte Identität und verbleibt an seinem Erzeugungsort. Der Destruktor <code>~MultipleEvent()</code> ist nicht threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01706" href="../spec/record.html?id=SWS_DM_01706">[SWS_DM_01706]</a>. Aufrufende Komponenten müssen daher vor der Zerstörung sicherstellen, dass keine asynchronen Abfragen oder Benachrichtigungen mehr über die Instanz laufen <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=78">AUTOSAR AP SWS Diagnostics, S. 78</a>.</p>

<h4>Nutzungspfad</h4>
<p>Nach der Instanziierung registriert die Anwendung typischerweise eine Callback-Funktion mittels <code>SetEventStatusChangedNotifier</code>, um über Statusänderungen eines bestimmten Ereignisses (identifiziert via <code>EventHandleType</code>) informiert zu werden <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>. Ein erneuter Aufruf dieser Methode für dasselbe Event überschreibt den zuvor gesetzten Notifier <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>. Diese Registrierungsfunktion ist nicht threadsicher <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>.</p>
<p>Im laufenden Betrieb können aktuelle Diagnoseinformationen gezielt pro Event-Handle abgefragt werden. Alle zustandsbezogenen Leseoperationen liefern ihre Daten asynchron in einem <code>ara::core::Future</code> zurück:</p>
<ul>
<li><code>GetEventStatus</code> liefert das aktuelle Statusbyte des Ereignisses als <code>EventStatusByte</code> <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>.</li>
<li><code>GetDebouncingStatus</code> gibt den Entprellzustand (<code>DebouncingState</code>) des Ereignisses zurück <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a>.</li>
<li><code>GetFaultDetectionCounter</code> liefert den aktuellen Fehlererkennungszähler (<code>FaultDetectionCounter</code>) als vorzeichenbehafteten 8-Bit-Ganzzahlwert <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</li>
<li><code>GetDTCNumber</code> fragt die zugeordnete DTC-Nummer im angeforderten <code>DTCFormatType</code> ab <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>.</li>
</ul>
<p>Die Threadsicherheit dieser Abfragefunktionen hängt von der Konfiguration ab <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>, <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a>, <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Methoden von <code>MultipleEvent</code> signalisieren Fehlerzustände über den Typ <code>DiagErrc</code>, der entweder in einem <code>ara::core::Result</code> oder im zurückgegebenen <code>ara::core::Future</code> gekapselt transportiert wird <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>. Folgende Fehlerfälle sind spezifiziert:</p>
<ul>
<li><code>DiagErrc::kInvalidArgument</code>: Tritt auf, wenn unzulässige Parameter übergeben werden, beispielsweise ein ungültiges <code>EventHandleType</code> oder bei internen Entprellfehlern wie <code>kPreFailed</code> <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>, <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a>, <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</li>
<li><code>DiagErrc::kNoSuchDTC</code>: Wird von <code>GetDTCNumber</code> gemeldet, wenn für das angefragte Diagnoseereignis kein korrespondierender DTC konfiguriert oder zugeordnet ist <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>.</li>
<li><code>DiagErrc::kServiceNotAvailable</code>: Tritt bei Leseoperationen auf, wenn essentielle Basisfunktionalitäten des Diagnose-Managements zur Ausführungszeit nicht verfügbar sind <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>, <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a>, <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</li>
</ul>
<p>Im Fehlerfall garantieren die Operationen Rollback-Semantik <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>, <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>.</p>
