<h4>Context</h4>
<p>The class <code>ara::diag::MultipleEvent</code> provides operations for diagnostic events via multiple event interfaces. In contrast to dedicated single-event interfaces, <code>MultipleEvent</code> enables bundled interaction with multiple diagnostic events via a common port, where the concrete event is addressed on each method call via an identifier of type <code>EventHandleType</code>. The class acts as an adapter between the adaptive application software and the central Diagnostic Management (DM) of the AUTOSAR Adaptive Platform.</p>
<p>Essentially three components are involved in the interaction: the using software component, the instance of <code>ara::diag::MultipleEvent</code>, and the underlying Diagnostic Management service. The application initializes the instance by specifying a model reference and uses it for status queries, debouncing checks, and notifier registrations regarding concrete event handles <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a> <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a> <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::diag::MultipleEvent</code> is created via its explicit constructor, which takes a <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>. This identifier must refer to a <code>PortPrototype</code> of a <code>DiagnosticMultipleEventInterface</code> declared in the AUTOSAR model. The constructor is declared exception-safe (<em>exception safe</em>) and thread-safe <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>.</p>
<p>The class has strict semantics regarding identity and resource binding: Both the copy constructor and the assignment operator are explicitly deleted (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_02070" href="../spec/record.html?id=SWS_DM_02070">[SWS_DM_02070]</a> <a class="spec-record-ref" data-req="SWS_DM_02067" href="../spec/record.html?id=SWS_DM_02067">[SWS_DM_02067]</a>. Likewise, the move constructor and the move assignment operator are deleted <a class="spec-record-ref" data-req="SWS_DM_02069" href="../spec/record.html?id=SWS_DM_02069">[SWS_DM_02069]</a> <a class="spec-record-ref" data-req="SWS_DM_02068" href="../spec/record.html?id=SWS_DM_02068">[SWS_DM_02068]</a>. An instance of <code>MultipleEvent</code> is therefore neither copyable nor movable; it remains fixed at its storage location, typically as a long-lived member of an application component.</p>
<p>The destructor <code>~MultipleEvent()</code> is exception-safe, but specified as not thread-safe <a class="spec-record-ref" data-req="SWS_DM_01706" href="../spec/record.html?id=SWS_DM_01706">[SWS_DM_01706]</a>. Consequently, the instance may only be released once no concurrent query or registration operations are taking place on the object. Regarding the thread safety of the status query methods, conditional behavior applies: Whether the query methods must be executed thread-safe is determined via the concurrency type provided in the constructor <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a> <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a> <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a> <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</p>

<h4>Usage Path</h4>
<p>The typical usage path comprises the instantiation of the interface, the optional registration of change notifications, and the querying of event-specific diagnostic data:</p>
<ol>
<li><strong>Instantiation:</strong> The application creates the <code>MultipleEvent</code> object by passing the configured <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>.</li>
<li><strong>Register notifier:</strong> A callback of type <code>EventStatusByteNotifier</code> for a specific <code>eventHandle</code> is registered via <code>SetEventStatusChangedNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>. A renewed call overwrites the previously registered notifier. The method returns a <code>ara::core::Result&lt;void&gt;</code> and is not thread-safe <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>.</li>
<li><strong>Query status and fault counters:</strong> The current status (<code>EventStatusByte</code>) is queried by means of <code>GetEventStatus(eventHandle)</code> <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>. Additional diagnostic information can be determined asynchronously via <code>GetDebouncingStatus(eventHandle)</code> for the debouncing status <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a> as well as <code>GetFaultDetectionCounter(eventHandle)</code> for the fault detection counter <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</li>
<li><strong>Read DTC mapping:</strong> Using <code>GetDTCNumber(eventHandle, dtcFormat)</code>, the DTC number assigned to the event can be determined in the requested format (<code>DTCFormatType</code>) <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a>.</li>
</ol>
<p>All query methods return a <code>ara::core::Future</code>, which makes calls non-blocking and allows results to be received asynchronously via the Future interface <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a> <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a> <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a> <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>.</p>

<h4>Error Scenarios</h4>
<p>Error conditions occur both during initialization and during regular operation:</p>
<ul>
<li><strong>Modeling and instantiation errors:</strong> The constructor reports model-related violations if the <code>InstanceSpecifier</code> cannot be resolved in the context of the process (<code>InstanceSpecifierMappingIntegrityViolation</code>), the referenced <code>PortPrototype</code> is not typed by a <code>DiagnosticMultipleEventInterface</code> (<code>PortInterfaceMappingViolation</code>), the mapping to the process runtime is missing (<code>ProcessMappingViolation</code>), or the identifier is already in use within the process (<code>InstanceSpecifierAlreadyInUseViolation</code>) <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>.</li>
