<p class="ai-level ai-oneliner-lead" data-ai-level="1">Steuert externe CAN-Transceiver: Betriebsmodi, Wake-up-Erkennung und selektives Aufwecken über Wake-up-Frames.</p>
<div class="ai-level" data-ai-level="2">
<p>CanTrcv steuert externe CAN-Transceiver und bildet sie auf ein generisches Modusmodell mit NORMAL, STANDBY und SLEEP ab. Moduswechsel fordert CanIf asynchron an; erreichte Modi meldet der Treiber über eine Indikation zurück <a class="spec-record-ref" data-req="SWS_CanTrcv_00158" href="../../spec/record.html?id=SWS_CanTrcv_00158">[SWS_CanTrcv_00158]</a>. Zusätzlich erkennt er Wake-ups, meldet sie an EcuM und unterstützt bei geeigneter Hardware das selektive Aufwecken über Wake-up-Frames. Wichtigste Randbedingung: SLEEP ist nur aus STANDBY erreichbar <a class="spec-record-ref" data-req="SWS_CanTrcv_00104" href="../../spec/record.html?id=SWS_CanTrcv_00104">[SWS_CanTrcv_00104]</a>, und während gesperrter Benachrichtigung dürfen keine Wake-ups verloren gehen.</p>

</div>
<div class="ai-level" data-ai-level="3">
<p>Der CAN Transceiver Driver (CanTrcv) kapselt externe CAN-Transceiver hinter einem generischen Modusmodell. Dadurch bleiben ComM und EcuM von der konkreten Hardware entkoppelt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_FIGURE_Figure_7_1.html" data-snip="SNIP_CLASSIC_CANTRCV_FIGURE_Figure_7_1">SWS CanTrcv S. 19</a>). Für jeden Transceiver-Hardwaretyp gibt es eine Treiberinstanz <a class="spec-record-ref" data-req="SWS_CanTrcv_00016" href="../../spec/record.html?id=SWS_CanTrcv_00016">[SWS_CanTrcv_00016]</a>. Der Treiber wird über CanIf angesprochen und steuert die Hardware über Dio und Spi, die vor <code>CanTrcv_Init</code> initialisiert sein müssen <a class="spec-record-ref" data-req="SWS_CanTrcv_00099" href="../../spec/record.html?id=SWS_CanTrcv_00099">[SWS_CanTrcv_00099]</a>. Nach Init liegt jeder Transceiver, je Kanal konfiguriert, in STANDBY oder SLEEP <a class="spec-record-ref" data-req="SWS_CanTrcv_00148" href="../../spec/record.html?id=SWS_CanTrcv_00148">[SWS_CanTrcv_00148]</a>. <code>CanTrcv_DeInit</code> führt nach NOT_ACTIVE <a class="spec-record-ref" data-req="SWS_CanTrcv_91003" href="../../spec/record.html?id=SWS_CanTrcv_91003">[SWS_CanTrcv_91003]</a>.</p>
<p><code>CanTrcv_SetOpMode</code> schaltet zwischen NORMAL, STANDBY und SLEEP um <a class="spec-record-ref" data-req="SWS_CanTrcv_00102" href="../../spec/record.html?id=SWS_CanTrcv_00102">[SWS_CanTrcv_00102]</a>. SLEEP ist nur aus STANDBY zulässig <a class="spec-record-ref" data-req="SWS_CanTrcv_00104" href="../../spec/record.html?id=SWS_CanTrcv_00104">[SWS_CanTrcv_00104]</a>. Ein Wechsel in den aktuellen Modus ist kein Fehler <a class="spec-record-ref" data-req="SWS_CanTrcv_00161" href="../../spec/record.html?id=SWS_CanTrcv_00161">[SWS_CanTrcv_00161]</a>. Die Funktion arbeitet asynchron: Sobald der Zielmodus erreicht ist, meldet CanTrcv das über <code>CanIf_TrcvModeIndication</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00158" href="../../spec/record.html?id=SWS_CanTrcv_00158">[SWS_CanTrcv_00158]</a>.</p>

Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-08c9d90c8e17592e.html" data-snip="FIG-08c9d90c8e17592e">SWS CanTrcv S. 19</a>, <a class="spec-record-ref" data-req="SWS_CanTrcv_00148" href="../../spec/record.html?id=SWS_CanTrcv_00148">[SWS_CanTrcv_00148]</a></p>
<p>Wake-ups prüft CanIf über <code>CanTrcv_CheckWakeup</code>. Diese Funktion meldet erkannte Wake-ups per <code>EcuM_SetWakeupEvent</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00146" href="../../spec/record.html?id=SWS_CanTrcv_00146">[SWS_CanTrcv_00146]</a>. <code>CanTrcv_MainFunction</code> durchsucht die Busse in STANDBY und SLEEP <a class="spec-record-ref" data-req="SWS_CanTrcv_00112" href="../../spec/record.html?id=SWS_CanTrcv_00112">[SWS_CanTrcv_00112]</a>. <code>CanTrcv_SetWakeupMode</code> kann die Benachrichtigung sperren, freigeben oder gespeicherte Wake-ups löschen. Dabei darf kein Wake-up verloren gehen <a class="spec-record-ref" data-req="SWS_CanTrcv_00095" href="../../spec/record.html?id=SWS_CanTrcv_00095">[SWS_CanTrcv_00095]</a>.</p>
<p>PN-fähige Transceiver (<code>CanTrcvHwPnSupport</code>) wecken zusätzlich über konfigurierte Wake-up-Frames <a class="spec-record-ref" data-req="SWS_CanTrcv_00175" href="../../spec/record.html?id=SWS_CanTrcv_00175">[SWS_CanTrcv_00175]</a>. Beim Shutdown löscht CanSM zuerst das WUF-Flag und schaltet dann nach STANDBY <a class="spec-record-ref" data-req="SWS_CanTrcv_00194" href="../../spec/record.html?id=SWS_CanTrcv_00194">[SWS_CanTrcv_00194]</a>. Anschließend lässt CanSM das Wake-Flag asynchron prüfen <a class="spec-record-ref" data-req="SWS_CanTrcv_00224" href="../../spec/record.html?id=SWS_CanTrcv_00224">[SWS_CanTrcv_00224]</a>.</p>
<p>Im Fehlerfall gilt:</p>
<ul>
<li>Bei aktivierter DET werden Entwicklungsfehler gemeldet, bei abgeschalteter DET liefern die APIs <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00050" href="../../spec/record.html?id=SWS_CanTrcv_00050">[SWS_CanTrcv_00050]</a>.</li>
<li>Gestörte Hardwarekommunikation meldet der Treiber als Laufzeitfehler <code>CANTRCV_E_NO_TRCV_CONTROL</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_91006" href="../../spec/record.html?id=SWS_CanTrcv_91006">[SWS_CanTrcv_91006]</a>.</li>

<h4>Rolle: Treiber für externe CAN-Transceiver unterhalb von CanIf</h4>
<p>Der CAN Transceiver Driver (CanTrcv) steuert externe CAN-Transceiver-Bausteine an. Er bildet deren Hardwarezustände auf ein generisches Betriebsmodusmodell ab. Dieses Modell soll viele verfügbare Transceiver einheitlich abdecken. Laut Spezifikation nimmt es dafür in Kauf, für einen konkreten Baustein ein oder zwei Zustände zu viel zu haben, entkoppelt damit aber ComM und EcuM von der Hardware (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_FIGURE_Figure_7_1.html" data-snip="SNIP_CLASSIC_CANTRCV_FIGURE_Figure_7_1">SWS CanTrcv S. 19</a>). Die Transceiver-Hardware muss dazu eine Schnittstelle bieten, die sich auf dieses Modell abbilden lässt <a class="spec-record-ref" data-req="SWS_CanTrcv_00098" href="../../spec/record.html?id=SWS_CanTrcv_00098">[SWS_CanTrcv_00098]</a>.</p>
<p>Nach oben ist CanIf der unmittelbare Partner:</p>
<ul>
<li><code>CanIf_SetTrcvMode</code> ruft <code>CanTrcv_SetOpMode</code> auf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_3_14_CanIf_SetTrcvMode.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_3_14_CanIf_SetTrcvMode">SWS CanIf S. 95</a>).</li>
<li><code>CanIf_GetTrcvMode</code> ruft <code>CanTrcv_GetOpMode</code> auf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_3_15_CanIf_GetTrcvMode.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_3_15_CanIf_GetTrcvMode">SWS CanIf S. 97</a>).</li>
<li><code>CanIf_GetTrcvWakeupReason</code> ruft <code>CanTrcv_GetBusWuReason</code> auf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_3_16_CanIf_GetTrcvWakeupReason.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_3_16_CanIf_GetTrcvWakeupReason">SWS CanIf S. 98</a>).</li>
</ul>
<p>Rückmeldungen laufen über <code>CanIf_TrcvModeIndication</code>, das zu den Pflichtschnittstellen gehört <a class="spec-record-ref" data-req="SWS_CanTrcv_00085" href="../../spec/record.html?id=SWS_CanTrcv_00085">[SWS_CanTrcv_00085]</a>. Für die PN-Indikationen sind weitere CanIf-Callbacks gelistet <a class="spec-record-ref" data-req="SWS_CanTrcv_00086" href="../../spec/record.html?id=SWS_CanTrcv_00086">[SWS_CanTrcv_00086]</a>. Nach unten nutzt CanTrcv Dio und Spi zur Hardwareansteuerung sowie Icu, DEM und EcuM-Typen, wie die Importliste zeigt <a class="spec-record-ref" data-req="SWS_CanTrcv_00084" href="../../spec/record.html?id=SWS_CanTrcv_00084">[SWS_CanTrcv_00084]</a>. Wartezeiten bei Zustandswechseln realisiert der Treiber mit <code>Tm_BusyWait1us16bit</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00230" href="../../spec/record.html?id=SWS_CanTrcv_00230">[SWS_CanTrcv_00230]</a>. <code>CanTrcv_MainFunction</code> und <code>CanTrcv_MainFunctionDiagnostics</code> ruft der BSW-Scheduler auf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_8_4_Scheduled_functions.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_8_4_Scheduled_functions">SWS CanTrcv S. 47</a>).</p>

<h4>Initialisierung, Lebenszyklus und Deinitialisierung</h4>
<p>Vor dem Aufruf von <code>CanTrcv_Init</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00001" href="../../spec/record.html?id=SWS_CanTrcv_00001">[SWS_CanTrcv_00001]</a> muss die Umgebung alle benutzten Treiber initialisiert haben, insbesondere Spi und Dio <a class="spec-record-ref" data-req="SWS_CanTrcv_00099" href="../../spec/record.html?id=SWS_CanTrcv_00099">[SWS_CanTrcv_00099]</a>. Die Dokumentstelle ergänzt zwei Zeitvorgaben: Die Initialisierung soll früh nach dem Power-up erfolgen, und die unterlagerten Dienste sollen kurz und synchron sein (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_7_Preconditions_for_driver_initialization.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_7_Preconditions_for_driver_initialization">SWS CanTrcv S. 26</a>).</p>
<p><code>CanTrcv_Init</code> initialisiert alle angeschlossenen Transceiver gemäß ihrer Initialisierungssequenzen und der Konfiguration aus <code>ConfigPtr</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00180" href="../../spec/record.html?id=SWS_CanTrcv_00180">[SWS_CanTrcv_00180]</a>. Der Inhalt von <code>CanTrcv_ConfigType</code> ist hardwarespezifisch <a class="spec-record-ref" data-req="SWS_CanTrcv_00209" href="../../spec/record.html?id=SWS_CanTrcv_00209">[SWS_CanTrcv_00209]</a>. Danach befindet sich jeder Transceiver in <code>CANTRCV_TRCVMODE_SLEEP</code> oder <code>CANTRCV_TRCVMODE_STANDBY</code>; das ist je Transceiver konfigurierbar <a class="spec-record-ref" data-req="SWS_CanTrcv_00148" href="../../spec/record.html?id=SWS_CanTrcv_00148">[SWS_CanTrcv_00148]</a>.</p>
<p>Die Initialisierung prüft zugleich auf Wake-ups:</p>
<ul>
<li>Unterstützt die Hardware es, prüft <code>CanTrcv_Init</code>, ob Transceiver-Aktivität das Aufwachen ausgelöst hat. Das Ergebnis meldet sie per <code>EcuM_SetWakeupEvent</code> mit der Quelle aus <code>CanTrcvWakeupSourceRef</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00167" href="../../spec/record.html?id=SWS_CanTrcv_00167">[SWS_CanTrcv_00167]</a>.</li>
<li>Bei PN-fähigen Transceivern wird zusätzlich die Konfigurationssequenz erneut ausgeführt, wenn das POR- oder SYSERR-Flag gesetzt ist. Sonst bleibt die im Transceiver gespeicherte Konfiguration gültig <a class="spec-record-ref" data-req="SWS_CanTrcv_00182" href="../../spec/record.html?id=SWS_CanTrcv_00182">[SWS_CanTrcv_00182]</a>.</li>
<li>Ein gesetztes POR-Flag wird außerdem über <code>CanTrcvPorWakeupSourceRef</code> als Wake-up gemeldet <a class="spec-record-ref" data-req="SWS_CanTrcv_00183" href="../../spec/record.html?id=SWS_CanTrcv_00183">[SWS_CanTrcv_00183]</a>.</li>
</ul>
<p>Die POR-Meldung passt zu Transceivern mit integrierter Spannungsversorgung. Bei ihnen sieht ein passives Wecken für die ECU wie ein Power-on-Reset aus (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_6_7_Wakeup_Sources_with_Integrated_Power_Control.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_6_7_Wakeup_Sources_with_Integrated_Power_Control">SWS EcuM S. 70</a>).</p>

<h4>Betriebsmodi NORMAL, STANDBY und SLEEP</h4>
<p><code>CanTrcv_TrcvModeType</code> definiert die drei Modi <a class="spec-record-ref" data-req="SWS_CanTrcv_00163" href="../../spec/record.html?id=SWS_CanTrcv_00163">[SWS_CanTrcv_00163]</a>. <code>CanTrcv_SetOpMode</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00002" href="../../spec/record.html?id=SWS_CanTrcv_00002">[SWS_CanTrcv_00002]</a> schaltet den internen Zustand des adressierten Transceivers auf einen dieser Modi <a class="spec-record-ref" data-req="SWS_CanTrcv_00102" href="../../spec/record.html?id=SWS_CanTrcv_00102">[SWS_CanTrcv_00102]</a>. Für die Übergänge gilt:</p>
<ul>
<li>Aus NORMAL fordert der Nutzer nur STANDBY oder NORMAL an <a class="spec-record-ref" data-req="SWS_CanTrcv_00103" href="../../spec/record.html?id=SWS_CanTrcv_00103">[SWS_CanTrcv_00103]</a>.</li>
<li>Aus STANDBY fordert er nur SLEEP oder STANDBY an <a class="spec-record-ref" data-req="SWS_CanTrcv_00104" href="../../spec/record.html?id=SWS_CanTrcv_00104">[SWS_CanTrcv_00104]</a>.</li>
<li>NORMAL ist laut Schaubild aus allen drei Modi erreichbar (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-08c9d90c8e17592e.html" data-snip="FIG-08c9d90c8e17592e">SWS CanTrcv S. 19</a>).</li>
<li>Ein Wechsel in den aktuellen Modus ist erlaubt und kein Fehler <a class="spec-record-ref" data-req="SWS_CanTrcv_00161" href="../../spec/record.html?id=SWS_CanTrcv_00161">[SWS_CanTrcv_00161]</a>.</li>
<li>Unterstützt die Hardware den angeforderten Modus nicht, liefert die Funktion <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00105" href="../../spec/record.html?id=SWS_CanTrcv_00105">[SWS_CanTrcv_00105]</a>.</li>
</ul>

<h4>Wake-up: Erkennung, Ursache und Benachrichtigungssteuerung</h4>
<p>Ein Wake-up wird per Interrupt oder per Polling erkannt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_9_2_3_CAN_Wakeup_Sequences.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_9_2_3_CAN_Wakeup_Sequences">SWS EcuM S. 179</a>). CanIf fragt dabei über <code>CanIf_CheckWakeup</code> die Funktion <code>CanTrcv_CheckWakeup</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00143" href="../../spec/record.html?id=SWS_CanTrcv_00143">[SWS_CanTrcv_00143]</a> ab (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_1_Wake_up_detection.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_18_4_1_Wake_up_detection">SWS CanIf S. 56</a>). Unterstützt die Hardware es, validiert diese Funktion einen Wake-up durch Transceiver-Aktivität und meldet ihn per <code>EcuM_SetWakeupEvent</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00146" href="../../spec/record.html?id=SWS_CanTrcv_00146">[SWS_CanTrcv_00146]</a>.</p>
<p><code>CanTrcv_MainFunction</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00013" href="../../spec/record.html?id=SWS_CanTrcv_00013">[SWS_CanTrcv_00013]</a> durchsucht alle Busse in STANDBY und SLEEP nach Wake-ups und setzt ein Wake-up-Flag <a class="spec-record-ref" data-req="SWS_CanTrcv_00112" href="../../spec/record.html?id=SWS_CanTrcv_00112">[SWS_CanTrcv_00112]</a>. Vermutlich ist sie vor allem bei Polling-Konfiguration relevant; das Konfigurationsschaubild sieht dafür den Wert <code>CanTrcvWakeUpByPolling</code> vor (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-eace18b4a0a75b76.html" data-snip="FIG-eace18b4a0a75b76">ECUC-Parameter S. 185</a>).</p>
<p><code>CanTrcv_GetBusWuReason</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00007" href="../../spec/record.html?id=SWS_CanTrcv_00007">[SWS_CanTrcv_00007]</a> liefert die vom Transceiver erkannte Weckursache <a class="spec-record-ref" data-req="SWS_CanTrcv_00107" href="../../spec/record.html?id=SWS_CanTrcv_00107">[SWS_CanTrcv_00107]</a>. Mögliche Werte sind etwa <code>CANTRCV_WU_BY_BUS</code>, <code>CANTRCV_WU_INTERNALLY</code> oder <code>CANTRCV_WU_RESET</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00165" href="../../spec/record.html?id=SWS_CanTrcv_00165">[SWS_CanTrcv_00165]</a>. Wie fein sich die Ursachen unterscheiden lassen, hängt stark von der Hardware ab (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_8_3_4_CanTrcv_GetBusWuReason.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_8_3_4_CanTrcv_GetBusWuReason">SWS CanTrcv S. 35</a>).</p>
<p>Für Wake-up-Interrupts nutzt der Treiber ICU-Kanäle. <code>Icu_EnableNotification</code> und <code>Icu_DisableNotification</code> ruft er nur auf, wenn <code>CanTrcvIcuChannelRef</code> konfiguriert ist <a class="spec-record-ref" data-req="SWS_CanTrcv_00171" href="../../spec/record.html?id=SWS_CanTrcv_00171">[SWS_CanTrcv_00171]</a>. Beim Wechsel nach STANDBY aktiviert er die Kanäle <a class="spec-record-ref" data-req="SWS_CanTrcv_00172" href="../../spec/record.html?id=SWS_CanTrcv_00172">[SWS_CanTrcv_00172]</a>. Die Dokumentstelle aus R24-11 nennt zusätzlich das Deaktivieren beim Wechsel nach NORMAL (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_4_Enabling_Disabling_wakeup_notification.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_4_Enabling_Disabling_wakeup_notification">SWS CanTrcv S. 23</a>).</p>

<h4>Selektives Aufwecken (Partial Networking)</h4>
<p>Beim Partial Networking bleiben Knoten im Low-Power-Modus, bis vordefinierte Wake-up-Frames (WUF) sie wecken. PN-fähige Transceiver reagieren also nicht nur auf das Wake-up-Pattern (WUP), sondern auch auf diese Frames (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANTRCV_SECTION_7_10_Transceivers_with_selective_wakeup_functionality.html" data-snip="SNIP_CLASSIC_CANTRCV_SECTION_7_10_Transceivers_with_selective_wakeup_functionality">SWS CanTrcv S. 27</a>). Ob die Hardware das kann, zeigt <code>CanTrcvHwPnSupport</code> an <a class="spec-record-ref" data-req="SWS_CanTrcv_00174" href="../../spec/record.html?id=SWS_CanTrcv_00174">[SWS_CanTrcv_00174]</a>. Nur wenn dieser Parameter TRUE ist, existieren der Container <code>CanTrcvPartialNetwork</code> und fünf APIs: <code>CanTrcv_GetTrcvSystemData</code>, <code>CanTrcv_ClearTrcvWufFlag</code>, <code>CanTrcv_ReadTrcvTimeoutFlag</code>, <code>CanTrcv_ClearTrcvTimeoutFlag</code> und <code>CanTrcv_ReadTrcvSilenceFlag</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00175" href="../../spec/record.html?id=SWS_CanTrcv_00175">[SWS_CanTrcv_00175]</a>.</p>
<p>Auf welche Frames der Transceiver reagiert, legen <code>CanTrcvPnFrameCanId</code>, <code>CanTrcvPnFrameCanIdMask</code> und <code>CanTrcvPnFrameDataMask</code> fest <a class="spec-record-ref" data-req="SWS_CanTrcv_00177" href="../../spec/record.html?id=SWS_CanTrcv_00177">[SWS_CanTrcv_00177]</a>. <code>CanTrcv_SetPNActivationState</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00219" href="../../spec/record.html?id=SWS_CanTrcv_00219">[SWS_CanTrcv_00219]</a> schaltet die PN-Weckfunktion mit <code>PN_ENABLED</code> ein <a class="spec-record-ref" data-req="SWS_CanTrcv_00221" href="../../spec/record.html?id=SWS_CanTrcv_00221">[SWS_CanTrcv_00221]</a> und mit <code>PN_DISABLED</code> aus <a class="spec-record-ref" data-req="SWS_CanTrcv_00222" href="../../spec/record.html?id=SWS_CanTrcv_00222">[SWS_CanTrcv_00222]</a>.</p>
<p>Zentral ist der Shutdown-Ablauf:</p>
<ol>
<li>CanSM löscht über <code>CanTrcv_ClearTrcvWufFlag</code> das WUF-Flag, damit beim Eintritt in den Low-Power-Modus kein Frame-Wake-up verloren geht. Anschließend kommt der Transceiver nach STANDBY <a class="spec-record-ref" data-req="SWS_CanTrcv_00194" href="../../spec/record.html?id=SWS_CanTrcv_00194">[SWS_CanTrcv_00194]</a>.</li>
<li>CanTrcv bestätigt das Löschen mit <code>CanIf_ClearTrcvWufFlagIndication</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00195" href="../../spec/record.html?id=SWS_CanTrcv_00195">[SWS_CanTrcv_00195]</a>.</li>
<li>Zuletzt fordert CanSM die asynchrone Prüfung <code>CanTrcv_CheckWakeFlag</code> an <a class="spec-record-ref" data-req="SWS_CanTrcv_00223" href="../../spec/record.html?id=SWS_CanTrcv_00223">[SWS_CanTrcv_00223]</a>. Das Ergebnis meldet CanTrcv per <code>CanIf_CheckTrcvWakeFlagIndication</code> <a class="spec-record-ref" data-req="SWS_CanTrcv_00224" href="../../spec/record.html?id=SWS_CanTrcv_00224">[SWS_CanTrcv_00224]</a>.</li>
</ol>

<h4>Konfiguration und Instanzbezug</h4>
<p>Für jeden Transceiver-Hardwaretyp gibt es eine Treiberinstanz, die alle Bausteine dieses Typs bedient <a class="spec-record-ref" data-req="SWS_CanTrcv_00016" href="../../spec/record.html?id=SWS_CanTrcv_00016">[SWS_CanTrcv_00016]</a>. Das CanIf-Schaubild zeigt den Fall gleicher Controller mit unterschiedlichen Transceivertypen, der dann zwei Transceiver-Treiber erfordert (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c1a643342dcdd1dc.html" data-snip="FIG-c1a643342dcdd1dc">SWS CanIf S. 34</a>). Jeden Kanal beschreibt ein Container <code>CanTrcvChannel</code> (Multiplizität 1..*). Er enthält unter anderem <code>CanTrcvHwPnSupport</code>, <code>CanTrcvInitState</code>, <code>CanTrcvWakeupByBusUsed</code> und die Wake-up-Quellreferenzen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_10_2_4_CanTrcvChannel.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_10_2_4_CanTrcvChannel">SWS CanTrcv S. 70</a>).</p>
<p>Ein Unterschied zwischen den Quellen betrifft den Zustand nach Init. Das Konfigurationsschaubild nennt <code>CanTrcvOpModeNormal</code> als Default von <code>CanTrcvInitState</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c3039d7eb0bfc7dc.html" data-snip="FIG-c3039d7eb0bfc7dc">ECUC-Parameter S. 187</a>). Normativ für R20-11 ist jedoch <a class="spec-record-ref" data-req="SWS_CanTrcv_00148" href="../../spec/record.html?id=SWS_CanTrcv_00148">[SWS_CanTrcv_00148]</a>, das nach Init nur SLEEP oder STANDBY vorsieht. Konfigurationen mit nicht unterstützten Partitionszuordnungen muss der Treiber zurückweisen <a class="spec-record-ref" data-req="SWS_CanTrcv_00231" href="../../spec/record.html?id=SWS_CanTrcv_00231">[SWS_CanTrcv_00231]</a>.</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Die Entwicklungsfehler aus <a class="spec-record-ref" data-req="SWS_CanTrcv_00050" href="../../spec/record.html?id=SWS_CanTrcv_00050">[SWS_CanTrcv_00050]</a> folgen einem einheitlichen Muster. Bei aktivierter DET melden die APIs:</p>
<ul>
<li><code>CANTRCV_E_UNINIT</code> bei Aufruf vor Init, etwa <a class="spec-record-ref" data-req="SWS_CanTrcv_00122" href="../../spec/record.html?id=SWS_CanTrcv_00122">[SWS_CanTrcv_00122]</a> und <a class="spec-record-ref" data-req="SWS_CanTrcv_00124" href="../../spec/record.html?id=SWS_CanTrcv_00124">[SWS_CanTrcv_00124]</a>;</li>
<li><code>CANTRCV_E_INVALID_TRANSCEIVER</code> bei ungültiger ID, etwa <a class="spec-record-ref" data-req="SWS_CanTrcv_00123" href="../../spec/record.html?id=SWS_CanTrcv_00123">[SWS_CanTrcv_00123]</a> und <a class="spec-record-ref" data-req="SWS_CanTrcv_00129" href="../../spec/record.html?id=SWS_CanTrcv_00129">[SWS_CanTrcv_00129]</a>;</li>
<li><code>CANTRCV_E_PARAM_POINTER</code> bei NULL-Zeigern, etwa <a class="spec-record-ref" data-req="SWS_CanTrcv_00132" href="../../spec/record.html?id=SWS_CanTrcv_00132">[SWS_CanTrcv_00132]</a> und <a class="spec-record-ref" data-req="SWS_CanTrcv_00133" href="../../spec/record.html?id=SWS_CanTrcv_00133">[SWS_CanTrcv_00133]</a>;</li>
<li><code>CANTRCV_E_TRCV_NOT_NORMAL</code> bzw. <code>CANTRCV_E_TRCV_NOT_STANDBY</code> bei unzulässigen Übergängen <a class="spec-record-ref" data-req="SWS_CanTrcv_00120" href="../../spec/record.html?id=SWS_CanTrcv_00120">[SWS_CanTrcv_00120]</a> <a class="spec-record-ref" data-req="SWS_CanTrcv_00121" href="../../spec/record.html?id=SWS_CanTrcv_00121">[SWS_CanTrcv_00121]</a>;</li>
<li>Parameterfehler bei ungültigem Modus <a class="spec-record-ref" data-req="SWS_CanTrcv_00087" href="../../spec/record.html?id=SWS_CanTrcv_00087">[SWS_CanTrcv_00087]</a> oder ungültigem Wake-up-Modus <a class="spec-record-ref" data-req="SWS_CanTrcv_00089" href="../../spec/record.html?id=SWS_CanTrcv_00089">[SWS_CanTrcv_00089]</a>.</li>
