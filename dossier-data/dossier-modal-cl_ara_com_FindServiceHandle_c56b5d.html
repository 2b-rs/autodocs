<h4>Context</h4>
<p>The class <code>ara::com::FindServiceHandle</code> represents an identifier for an ongoing, asynchronous service search within AUTOSAR Adaptive Communication Management (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=9">AUTOSAR_AP_EXP_ARAComAPI p. 9</a>). The specific internal definition and structure of the type is designed implementation-specifically for the respective Communication Management. The primary responsibility of the handle is to provide the application software with a unique reference through which background-active monitoring of service instances can be specifically addressed and terminated again (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=34">AUTOSAR_AP_EXP_ARAComAPI p. 34</a>).</p>
<p>Essentially three components are involved in the interaction:</p>
<ul>
<li><strong>Application software:</strong> Initiates the search, manages the returned handle, and requests the stop of the search activity if required.</li>
<li><strong>Proxy class (e.g., ServiceProxy):</strong> Provides the interface methods <code>StartFindService</code> and <code>StopFindService</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>).</li>
<li><strong>Communication Management:</strong> Executes the background monitoring via technical bindings and informs the attached callback handler upon changes in service availability (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=34">AUTOSAR_AP_EXP_ARAComAPI p. 34</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of <code>ara::com::FindServiceHandle</code> is subject to strict semantic requirements regarding instantiation and management:</p>
<ul>
<li><strong>Creation:</strong> The default constructor is explicitly deleted (<a class="spec-record-ref" data-req="SWS_CM_00353" href="../spec/record.html?id=SWS_CM_00353">[SWS_CM_00353]</a>). Consequently, an application cannot create instances in an uninitialized state. Valid instances are created exclusively as the return value of the static call <code>StartFindService</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>).</li>
<li><strong>Copying and assignment:</strong> The handle supports the copy assignment operator <code>operator=</code> (<a class="spec-record-ref" data-req="SWS_CM_11528" href="../spec/record.html?id=SWS_CM_11528">[SWS_CM_11528]</a>). This allows the handle to be passed on internally within the application or transferred into data structures.</li>
<li><strong>Comparability and management:</strong> For storage and organization in application-owned containers, the class implements <code>operator==</code> (<a class="spec-record-ref" data-req="SWS_CM_11526" href="../spec/record.html?id=SWS_CM_11526">[SWS_CM_11526]</a>) and <code>operator&lt;</code> (<a class="spec-record-ref" data-req="SWS_CM_11527" href="../spec/record.html?id=SWS_CM_11527">[SWS_CM_11527]</a>). The type thus satisfies the standardized C++ concepts <em>equalitycomparable</em> and <em>lessthancomparable</em>, which supports ordered storage in standard containers (such as search trees or maps).</li>
<li><strong>Termination:</strong> The active role of the handle ends as soon as it is passed to Communication Management via the method <code>StopFindService</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>). A handle deregistered in this way is likely to be without function for the application going forward.</li>
</ul>

<h4>Usage Path</h4>
<p>The regular usage path comprises asynchronous registration, the reception of availability messages, and the subsequent termination of the search:</p>
<ol>
<li><strong>Starting the search:</strong> The application defines a callback function (<code>FindServiceHandler</code>) and calls <code>StartFindService</code> on the proxy class (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>).</li>
<li><strong>Handle reception:</strong> The call returns a <code>ara::core::Result&lt;ara::com::FindServiceHandle&gt;</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>). The application checks the result and stores the contained handle.</li>
<li><strong>Background monitoring:</strong> Communication Management continuously monitors the appearance of matching service instances and calls the registered handler asynchronously (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=34">AUTOSAR_AP_EXP_ARAComAPI p. 34</a>).</li>
<li><strong>Stopping the search:</strong> If the application no longer requires notifications, it passes the stored <code>FindServiceHandle</code> to <code>StopFindService</code> to finally stop the background activity (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=34">AUTOSAR_AP_EXP_ARAComAPI p. 34</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>When handling <code>ara::com::FindServiceHandle</code>, the following preconditions and error situations are relevant:</p>
<ul>
<li><strong>Failure during search start:</strong> If the background search cannot be started, the <code>ara::core::Result</code> returned by <code>StartFindService</code> contains a corresponding error code instead of a valid handle (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=30">AUTOSAR_AP_EXP_ARAComAPI p. 30</a>). In this case, no handle is created.</li>
<li><strong>Exception safety:</strong> The specified operators <code>operator==</code> (<a class="spec-record-ref" data-req="SWS_CM_11526" href="../spec/record.html?id=SWS_CM_11526">[SWS_CM_11526]</a>), <code>operator&lt;</code> (<a class="spec-record-ref" data-req="SWS_CM_11527" href="../spec/record.html?id=SWS_CM_11527">[SWS_CM_11527]</a>), and <code>operator=</code> (<a class="spec-record-ref" data-req="SWS_CM_11528" href="../spec/record.html?id=SWS_CM_11528">[SWS_CM_11528]</a>) are explicitly declared as <em>not exception safe</em> in the interface specification.</li>
<li><strong>Invalid or repeated usage:</strong> The standard does not define a separate return of error states for <code>StopFindService</code>; passing an invalid or already stopped handle presumably has no effect or lies outside the valid call path.</li>
</ul>
