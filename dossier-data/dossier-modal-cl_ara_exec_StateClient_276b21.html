<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>ara::exec::StateClient</code> ermöglicht dem State Management das Anfordern von Zustandswechseln für Funktionsgruppen beim Execution Management, um die Ausführung zugeordneter Prozesse auf einer Machine zu steuern <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Bei der Erzeugung via <code>Create()</code> muss ein durchgehend gültiger Callback für unerwartete undefinierte Zustände registriert werden <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>. Neben asynchronen Zustandsübergängen bietet die nicht kopierbare Klasse Methoden zur Abfrage des Machine-Hochlaufergebnisses sowie zur Fehleranalyse bei Ausführungsfehlern <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::exec::StateClient</code> bildet die Schnittstelle des Execution Management, über die das State Management Zustandsübergänge für Funktionsgruppen (Function Groups) anfordert und steuert. Das State Management verwendet diesen Client während der gesamten Betriebszeit einer Machine, um Prozesse gezielt zu starten oder zu beenden. Der Integrator weist Softwarekomponenten bestimmten Zuständen einer Funktionsgruppe zu. Möchte das State Management diese Software ausführen, fordert es über den <code>StateClient</code> beim Execution Management den Wechsel in den betreffenden Funktionsgruppenzustand an; das Stoppen erfolgt analog durch Übergang in einen Zustand, in dem die Software nicht aktiv sein soll <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>StateClient</code> können entweder über den benannten Konstruktor <code>Create()</code> <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a> als <code>ara::core::Result&lt;StateClient&gt;</code> oder über den regulären Konstruktor <code>StateClient()</code> <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a> erzeugt werden. Beide Konstruktionspfade verlangen zwingend einen Callback-Parameter <code>undefinedStateCallback</code> vom Typ <code>std::function&lt;void(const ara::exec::ExecutionErrorEvent&amp;)&gt;</code>. Dieser Callback wird durch die StateClient-Bibliothek ausgelöst, wenn eine Funktionsgruppe unerwartet und ohne vorherige Anforderung durch <code>SetState()</code> in einen undefinierten Zustand wechselt. Der Aufrufer muss sicherstellen, dass dieser Callback über die gesamte Lebensdauer der <code>StateClient</code>-Instanz aufrufbar bleibt, was insbesondere bei Objektbindungen via <code>std::bind</code> relevant ist <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>.</p>

<p>Kopieroperationen sind für <code>StateClient</code> explizit unterbunden: Sowohl der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_EM_02565" href="../spec/record.html?id=SWS_EM_02565">[SWS_EM_02565]</a> als auch der Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_EM_02568" href="../spec/record.html?id=SWS_EM_02568">[SWS_EM_02568]</a> sind gelöscht (<code>=delete</code>). Eine Übertragung des Besitzes ist ausschließlich über Move-Semantik via Move-Konstruktor <a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a> und Move-Zuweisung <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a> möglich. Hinsichtlich der Nebenläufigkeit sind die fachlichen Methoden wie <code>SetState()</code>, <code>GetExecutionError()</code> und <code>GetInitialMachineStateTransitionResult()</code> sowie die Erzeugung threadsicher ausgelegt <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>. Dagegen sind die Move-Operationen und der Destruktor <code>~StateClient()</code> nicht threadsicher <a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>, <a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Anwendungszyklus gliedert sich in Initialisierung, Abfrage des Hochlaufergebnisses, reguläre Zustandswechsel und Fehlerüberwachung:</p>
<ol>
<li><strong>Erzeugung:</strong> Das State Management instanziiert <code>StateClient</code> unter Angabe eines gültigen Fehlersignalisierungs-Callbacks via <code>Create()</code> <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>.</li>
<li><strong>Initiales Hochlaufergebnis abfragen:</strong> Mit <code>GetInitialMachineStateTransitionResult()</code> fordert das State Management das Ergebnis des initialen Zustandsübergangs in den Startup-Zustand an <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>. Da dieser Übergang genau einmal pro Lebenszyklus der Machine stattfindet, bleibt das gelieferte <code>ara::core::Future&lt;void&gt;</code> stabil und ändert sich bis zu einem Neustart nicht mehr.</li>
<li><strong>Zustandswechsel anfordern:</strong> Mittels <code>SetState()</code> beauftragt das State Management asynchrone Zustandsübergänge für einzelne Funktionsgruppen <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Die Methode kehrt sofort zurück und liefert ein <code>ara::core::Future&lt;void&gt;</code> zur Abfrage des Abschlusses. Sobald der Auftrag beim Execution Management eingegangen ist, wird er unabhängig von der weiteren Lebensdauer der aufrufenden Instanz ausgeführt.</li>
<li><strong>Fehlerzustände untersuchen:</strong> Gelangt eine Funktionsgruppe unerwartet in einen undefinierten Zustand, kann über <code>GetExecutionError()</code> der auslösende Ausführungsfehler in Form eines <code>ara::exec::ExecutionErrorEvent</code> ermittelt werden <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Die Operationen der Klasse kommunizieren Fehlschläge über Fehlercodes der <code>ExecErrorDomain</code>:</p>
<ul>
<li><code>ExecErrc::kNoCommunication</code>: Signalisiert Kommunikationsstörungen zum Execution Management, beispielsweise bei unterbrochener IPC-Verbindung. Tritt bei <code>Create()</code> <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <code>SetState()</code> <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <code>GetInitialMachineStateTransitionResult()</code> <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a> sowie <code>GetExecutionError()</code> <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a> auf. Die vorgesehene Wiederherstellung besteht im erneuten Aufruf.</li>
<li><code>ExecErrc::kInvalidArgument</code>: Wird von <code>Create()</code> und <code>StateClient()</code> gemeldet, falls der übergebene Callback keine aufrufbare Funktion enthält <a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>.</li>
<li><code>ExecErrc::kOperationCanceled</code>: Zeigt bei <code>SetState()</code> an, dass ein laufender Übergang durch eine neuere Anforderung abgebrochen wurde <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Bei <code>GetInitialMachineStateTransitionResult()</code> tritt dieser Fehler auf, wenn der initiale Startübergang abgebrochen wurde, etwa durch eine unterbrochene Machine-Update-Sequenz <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>.</li>
<li><code>ExecErrc::kInvalidTransition</code>: Der angeforderte Zustandsübergang ist unzulässig, beispielsweise der Übergang in den Off-Zustand für MachineFG, oder der Zustand existiert nach einem Update nicht mehr <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>.</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code>: Der übergebene Zustand existiert nicht im verarbeiteten Manifest oder der Prozess besitzt kein Mapping auf die betreffende Funktionsgruppe <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>. Tritt dieser Fehler bei <code>GetInitialMachineStateTransitionResult()</code> auf, fehlt dem Prozess das Mapping zu MachineFG, was auf ein Konfigurationsproblem hinweist <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>.</li>
<li><code>ExecErrc::kOperationFailed</code>: Der Übergang ist fehlgeschlagen <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Bei <code>GetExecutionError()</code> zeigt der Code an, dass sich die Funktionsgruppe nicht in einem undefinierten Zustand befindet und das Problem vermutlich bereits behoben wurde <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>.</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code> und <code>ExecErrc::kUnexpectedTermination</code>: Spezifische Fehlschläge während <code>SetState()</code> infolge gescheiterter Integritätsprüfungen oder unerwarteter Prozessbeendigungen während der Transition <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>.</li>
</ul>
