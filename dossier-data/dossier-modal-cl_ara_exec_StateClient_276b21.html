<h4>Context</h4>
<p>The class <code>ara::exec::StateClient</code> acts as the functional interface of Execution Management to State Management. In the overall system, State Management is responsible for controlling the lifecycle of a machine and starting and stopping software components as needed. This is done via state transitions of configured Function Groups (<em>Function Groups</em>) to which concrete software processes were assigned by the integrator.</p>
<p>State Management uses <code>ara::exec::StateClient</code> to request state transitions for individual Function Groups from Execution Management <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>. Execution Management executes these transitions by starting or terminating the software assigned to the Function Group and reports the result of the transition back to State Management. To establish the connection to Execution Management, a platform-specific IPC channel (such as Unix domain sockets) is presumably used in the background, since the specification does not further narrow down the exact IPC technology.</p>

<h4>Lifecycle</h4>
<p>For the instantiation of <code>ara::exec::StateClient</code>, AUTOSAR provides two construction paths:</p>
<ul>
<li><strong>Named factory method:</strong> The static function <code>Create</code> returns a <code>ara::core::Result&lt;StateClient&gt;</code> and encapsulates potential errors during creation based on error codes and in an exception-safe manner (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Regular constructor:</strong> The direct constructor is declared as <code>noexcept(false)</code> and signals errors in the event of an error via exceptions (<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
</ul>
<p>Both creation paths require passing a callback <code>undefinedStateCallback</code> with the signature <code>std::function&lt;void(const ara::exec::ExecutionErrorEvent&amp;)&gt;</code>. This callback is called by the StateClient library if a Function Group transitions unexpectedly and without a prior request via <code>SetState</code> into an undefined state (<em>Undefined Function Group State</em>) (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). With regard to lifetime, it must mandatorily be ensured that this callback remains callable over the entire lifetime of the <code>StateClient</code> instance; this applies in particular when binding instance methods via <code>std::bind</code> (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</p>
<p>Copy operations are completely prevented: Both the copy constructor and the copy assignment operator are explicitly deleted (<code>delete</code>) (<a class="spec-record-ref" data-req="SWS_EM_02565" href="../spec/record.html?id=SWS_EM_02565">[SWS_EM_02565]</a>, <a class="spec-record-ref" data-req="SWS_EM_02568" href="../spec/record.html?id=SWS_EM_02568">[SWS_EM_02568]</a>). In contrast, the class supports move semantics: move constructor and move assignment operator are defined as <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>). The destructor is declared as <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>). As soon as a state change has been received by Execution Management, it is processed independently of the lifetime of the <code>StateClient</code> instance; however, the <code>ara::core::Future</code> returned by <code>SetState</code> depends on the lifetime of the instance (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</p>
<p>Regarding concurrency, the instance methods <code>SetState</code>, <code>GetExecutionError</code>, and <code>GetInitialMachineStateTransitionResult</code> as well as <code>Create</code> and the regular constructor are specified as thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>). The move operations and the destructor, on the other hand, are not thread-safe (<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>, <a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>, <a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>).</p>

<h4>Usage Path</h4>
<p>A typical usage sequence by State Management is divided into the following steps:</p>
<ol>
<li><strong>Client creation:</strong> State Management instantiates <code>StateClient</code> via <code>Create</code> while registering the error callback (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>).</li>
<li><strong>Synchronize startup state:</strong> At the beginning of machine operation, the result of the machine's initial transition into the startup state is queried via <code>GetInitialMachineStateTransitionResult()</code> (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). The method returns a <code>ara::core::Future&lt;void&gt;</code>. Since this transition occurs exactly once per machine lifecycle, the result remains unchanged over the remaining runtime (<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><strong>Request state change:</strong> At runtime, State Management requests transitions for individual Function Groups via <code>SetState(state)</code> (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>). The method returns immediately and provides a <code>ara::core::Future&lt;void&gt;</code>, which indicates the success of the transition or provides an error of the <code>ExecErrorDomain</code>.</li>
<li><strong>Analyze error states:</strong> If a Function Group transitions unexpectedly into an undefined state, the registered callback is triggered. State Management can retrieve the triggering <code>ExecutionErrorEvent</code> via <code>GetExecutionError(functionGroupState)</code> as long as the Function Group still remains in this state (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of <code>ara::exec::StateClient</code> use error codes from the error domain of Execution Management (<code>ara::exec::ExecErrc</code>). The following error scenarios are relevant:</p>
<ul>
<li><strong>Communication failure (<code>ExecErrc::kNoCommunication</code>):</strong> Occurs when the connection between client and Execution Management is disrupted or interrupted. This error is specified for all operations (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>, <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>). Repeating the call is the intended recovery measure.</li>
<li><strong>Invalid arguments and metamodel conflicts:</strong>
<ul>
<li><code>ExecErrc::kInvalidArgument</code> signals during creation that the passed <code>undefinedStateCallback</code> is not callable (<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>, <a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>).</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code> indicates that the target state does not exist in the manifest or the calling process has no mapping to the Function Group in question (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>, <a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
<li><strong>Failure or cancellation of state transitions:</strong>
<ul>
<li><code>ExecErrc::kOperationCanceled</code> informs that a transition was preempted by a newer request or canceled by State Management (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>).</li>
<li><code>ExecErrc::kInvalidTransition</code> is returned if the transition is invalid (e.g., transition to the Off state for MachineFG) or if the state no longer exists after a software update (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code> reports the failure of authenticity or integrity checks during the state transition (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kUnexpectedTermination</code> occurs if a participating process terminated unexpectedly during the transition (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>).</li>
<li><code>ExecErrc::kOperationFailed</code> indicates the general failure of a transition (<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>, <a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>). When calling <code>GetExecutionError</code>, however, this error indicates that the function group is not in an undefined state and the problem may have already been resolved (<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>).</li>
</ul>
</li>
</ul>
