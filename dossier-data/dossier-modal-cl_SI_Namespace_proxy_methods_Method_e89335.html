<h4>Context</h4>
<p>Within the framework of AUTOSAR Adaptive Communication Management (<code>ara::com</code>), the generated class <code>&lt;SI-Namespace&gt;::proxy::methods::&lt;Method&gt;</code> encapsulates a specific service proxy method. It is generated for each client-server operation defined in <code>ServiceInterface</code> for which <code>ClientServerOperation.fireAndForget == FALSE</code> is configured <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. In contrast to unidirectional fire-and-forget operations, this class implements the classic request-response pattern with feedback to the caller.</p>
<p>The following partners are essentially involved in the interaction:</p>
<ul>
<li><strong>Application client:</strong> Calls the method and evaluates the result or any errors asynchronously or synchronously via a <code>ara::core::Future</code> object <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong>Method proxy (<code>&lt;Method&gt;</code>):</strong> Serves as a typed call interface on the client side, accepts input arguments, and initiates the transmission <a class="spec-record-ref" data-req="SWS_CM_00191" href="../spec/record.html?id=SWS_CM_00191">[SWS_CM_00191]</a>, <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. In addition, it manages the state of the end-to-end protection (E2E) <a class="spec-record-ref" data-req="SWS_CM_00148" href="../spec/record.html?id=SWS_CM_00148">[SWS_CM_00148]</a>.</li>
<li><strong>Network binding / communication infrastructure:</strong> Takes over the transmission of the request to the remote system, monitors communication boundaries, and reports transmission or security errors <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong>Remote service:</strong> Processes the operation on the server side and returns output data or application errors <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The class is declared as <code>final</code> (<code>class &lt;Method&gt; final</code>). It is provided via the generated proxy header file <code>#include "&lt;SiNamespaceDerivedDirectoryPath&gt;/&lt;SiShortname&gt;_proxy.h"</code> <a class="spec-record-ref" data-req="SWS_CM_00148" href="../spec/record.html?id=SWS_CM_00148">[SWS_CM_00148]</a>, <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. Interpretation: The instantiation and lifetime of the method objects are bound to the lifetime of the higher-level service proxy instance, of which they form a component.</p>
<p>Regarding concurrency and execution, the call via <code>operator()</code> behaves non-blockingly: It initiates the method call and returns immediately to the caller ("return immediately") <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. Both methods of the class (<code>operator()</code> and <code>GetE2EStateMachineState()</code>) are declared as <code>noexcept</code> and guarantee complete exception safety <a class="spec-record-ref" data-req="SWS_CM_00148" href="../spec/record.html?id=SWS_CM_00148">[SWS_CM_00148]</a>, <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</p>
<p>For E2E state monitoring, the instance has an internal lifecycle: The method <code>GetE2EStateMachineState()</code> returns the current state <code>ara::com::e2e::SMState</code> of the specific method class, which was determined during the last call of <code>operator()</code> by executing the internal function <code>E2E_Check()</code> <a class="spec-record-ref" data-req="SWS_CM_00148" href="../spec/record.html?id=SWS_CM_00148">[SWS_CM_00148]</a>.</p>

<h4>Usage Path</h4>
<p>The regular sequence of a method call is divided into the following steps:</p>
<ol>
<li><strong>Method call:</strong> The client calls <code>operator()</code> on the method instance of the proxy and passes the defined input arguments according to <a class="spec-record-ref" data-req="SWS_CM_00191" href="../spec/record.html?id=SWS_CM_00191">[SWS_CM_00191]</a> and <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong>Future return:</strong> The call returns immediately and delivers a <code>ara::core::Future&lt;Output&gt;</code> to the caller <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong>Synchronization / evaluation:</strong> The caller decides independently on synchronous or asynchronous behavior (Interpretation: e.g., through blocking waiting or asynchronous querying of the future) <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. In case of success, the <code>Future</code> object contains the output structure <code>Output</code> according to <a class="spec-record-ref" data-req="SWS_CM_99333" href="../spec/record.html?id=SWS_CM_99333">[SWS_CM_99333]</a>.</li>
<li><strong>E2E state check:</strong> If E2E protection is present, the application can query the status <code>ara::com::e2e::SMState</code> resulting from the last call via <code>GetE2EStateMachineState()</code> <a class="spec-record-ref" data-req="SWS_CM_00148" href="../spec/record.html?id=SWS_CM_00148">[SWS_CM_00148]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>If the method call fails, the returned <code>ara::core::Future</code> provides a corresponding error code from <code>ara::core::FutureErrc</code> or Communication Management <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>. The following error cases are specified:</p>
<ul>
<li><strong><code>CommunicationFailure</code>:</strong> The network binding reports a recoverable communication error or the failure of secure communication. If a communication timeout occurs, this can lead to an undefined state on the remote server side <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong><code>ComErrc::kUnknownApplicationError</code>:</strong> The remote service returned an unconfigured application error (rollback semantics) <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong><code>ComErrc::kServiceNotAvailable</code>:</strong> The service is not available, even though it had previously been offered via <code>OfferService()</code> (rollback semantics) <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong><code>ComE2EErrc::kUnspecifiedE2EError</code>:</strong> The peer has reported an unspecified E2E error (rollback semantics) <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong><code>ComErrc::kMinimumSendIntervalViolationError</code>:</strong> Violation of the minimum transmission interval. The send request for the service instance element was issued faster than permitted by the configured interval <code>ServiceInterfaceDeploymentElement.minimumSendInterval</code> (rollback semantics) <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
<li><strong>Access violation (Grant Enforcement):</strong> If the client lacks the required access rights, the call is refused as <code>InsufficientPermissionsViolation</code> ("Refused by Grant Enforcement") <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</li>
</ul>
<p>Since <code>operator()</code> is declared with <code>noexcept</code>, no C++ exceptions are thrown; <code>ComErrc::k no_rollback_semantics</code> applies to the operation itself <a class="spec-record-ref" data-req="SWS_CM_00196" href="../spec/record.html?id=SWS_CM_00196">[SWS_CM_00196]</a>.</p>
