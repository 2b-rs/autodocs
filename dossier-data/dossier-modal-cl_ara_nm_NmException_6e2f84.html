<h4>Context</h4>
<p>
Within the AUTOSAR Adaptive Platform, the class <code>ara::nm::NmException</code> serves as a specialized exception type for API errors of the Network Management (<code>nm</code>) module <a class="spec-record-ref" data-req="SWS_ANM_01100" href="../spec/record.html?id=SWS_ANM_01100">[SWS_ANM_01100]</a>. It is declared in header <code>ara/nm/nm_error_domain.h</code> <a class="spec-record-ref" data-req="SWS_ANM_01100" href="../spec/record.html?id=SWS_ANM_01100">[SWS_ANM_01100]</a> and derives publicly from the general base class <code>ara::core::Exception</code> <a class="spec-record-ref" data-req="SWS_ANM_01100" href="../spec/record.html?id=SWS_ANM_01100">[SWS_ANM_01100]</a>.
</p>
<p>
The functional role of <code>ara::nm::NmException</code> is to report error conditions from the Network Management subsystem to calling application layers in a structured manner. By inheriting from <code>ara::core::Exception</code>, the class integrates into the platform's fundamental error handling model and enables calling components to catch Network Management errors selectively via typed C++ exception handling blocks and distinguish them from general system errors.
</p>

<h4>Lifecycle</h4>
<p>
An instance of <code>ara::nm::NmException</code> is created via an explicit constructor that accepts an error code of type <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a>. This constructor is defined as <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a>, guaranteeing that no further exceptions can occur during construction of the exception object itself. Furthermore, the constructor is specified as thread-safe (<code>thread-safe</code>) <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a>, which permits concurrent instantiation of exception objects across different threads without manual synchronization.
</p>
<p>
Regarding ownership, <code>ara::nm::NmException</code> follows the regular C++ exception lifecycle. The exception object is typically created at the time of the error, thrown by value, and managed in the runtime environment's exception storage. Presumably, the instance is automatically released after leaving the responsible <code>catch</code> block. Since the class has no internal operating modes or transitions, it does not possess its own state machine.
</p>

<h4>Usage Path</h4>
<p>
The typical usage path for <code>ara::nm::NmException</code> comprises error detection in the subsystem, throwing the exception, and catching it in the calling component:
</p>
<ol>
<li><strong>Error detection:</strong> During processing of an operation, Network Management detects an erroneous condition and creates an associated <code>ara::core::ErrorCode</code>.</li>
<li><strong>Throwing the exception:</strong> The subsystem instantiates <code>ara::nm::NmException</code> with the corresponding <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a> and throws the object.</li>
<li><strong>Catching by the caller:</strong> The calling application catches the exception selectively with a block such as <code>catch (const ara::nm::NmException&amp; e)</code> or generically via <code>catch (const ara::core::Exception&amp; e)</code>.</li>
<li><strong>Error handling:</strong> The application reacts to the error, for example by logging or transitioning to a safe fallback operation.</li>
</ol>
<p>
Interpretation: In the AUTOSAR Adaptive Platform, error handling is primarily performed via result-based types such as <code>ara::core::Result</code>. Presumably, <code>ara::nm::NmException</code> is thrown primarily when calling interfaces explicitly convert erroneous result objects into exceptions or when APIs are operated in environments with enabled C++ exceptions.
</p>

<h4>Error Scenarios</h4>
<p>
As a dedicated error object, <code>ara::nm::NmException</code> encapsulates Network Management error scenarios. For proper error handling, the following points are essential:
</p>
<ul>
<li><strong>Encapsulation of the error code:</strong> The constructor strictly requires passing a <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a>. Base class <code>ara::core::Exception</code> is expected to provide this code so that the caller can evaluate the exact cause of the error.</li>
<li><strong>Prevention of unhandled exceptions:</strong> If a thrown <code>ara::nm::NmException</code> is not caught in the call stack, this leads to a call to <code>std::terminate</code> and thus to termination of the process. Therefore, with exceptions enabled, NM interactions must be enclosed by corresponding handlers.</li>
<li><strong>No secondary exceptions during creation:</strong> The <code>noexcept</code> guarantee of constructor <a class="spec-record-ref" data-req="SWS_ANM_01102" href="../spec/record.html?id=SWS_ANM_01102">[SWS_ANM_01102]</a> prevents a nested exception from arising during error handling, which enhances stability in critical error situations.</li>
</ul>
