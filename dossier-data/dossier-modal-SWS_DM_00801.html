<h4>Verwendung und Aufrufkontext</h4>
<p>Die Methode <code>RequestUploadExit</code> der Klasse <code>ara::diag::UploadService</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=532">SWS Diagnostics §8.27.1.1.3.3 „RequestUploadExit“</a>) wird von der Diagnose-Server-Instanz aufgerufen, wenn die Beendigung eines Datentransfers über den UDS-Dienst <code>RequestTransferExit</code> (0x37) verarbeitet werden soll <a class="spec-record-ref" data-req="SWS_DM_00141" href="../spec/record.html?id=SWS_DM_00141">[SWS_DM_00141]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>.</p>

<p>Die Schnittstelle nimmt folgende Parameter entgegen <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>:</p>
<ul>
<li><code>transferRequestParameterRecord</code>: Enthält herstellerspezifische Parameter zur Unterstützung des Transfers im Format <code>ara::core::Span&lt;const std::uint8_t&gt;</code>. Die Daten bleiben gültig, bis das zugehörige Promise erfüllt oder die Bearbeitung abgebrochen wird. Interpretation: Die Auswertung dieser Parameter dürfte vorrangig herstellerspezifischen Validierungen beim Abschluss des Uploads dienen. <a class="interp-q interp-q-open" data-q="Q-d3989837f58761d7" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-d3989837f58761d7" title="Frage Q-d3989837f58761d7 (offen): Interpretation: Die Auswertung von transferRequestParameterRecord dürfte vorrangig herstellerspezifischen Validierungen beim Abschluss des Uploads dienen.">Frage Q-d3989837f58761d7 (offen)</a></li>
<li><code>metaInfo</code>: Übergibt Meta-Informationen der aktuellen Diagnoseanforderung.</li>
<li><code>cancellationHandler</code>: Ermöglicht das Abfragen des Abbruchstatus via <code>cancellationHandler.IsCanceled()</code> oder das Registrieren eines Benachrichtigungs-Callbacks mittels <code>cancellationHandler.SetNotifier()</code>.</li>
</ul>

<h4>Rückgabewerte und Fehlerbehandlung</h4>
<p>Die Ausführung erfolgt asynchron und liefert ein <code>ara::core::Future&lt;OperationOutput&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>. Im Erfolgsfall wird das Future mit einer Instanz von <code>OperationOutput</code> erfüllt. Die darin übergebenen Daten aus <code>responseData</code> werden nach der Service-ID als <code>transferResponseParameterRecord</code> in die positive Diagnoseantwort eingefügt <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>. Im Fehlerfall ist das Future mit einem passenden Fehlercode aus <code>DiagUdsNrcErrc</code> gemäß ISO 14229-1 zu komplettieren <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>.</p>

<h4>Nebenläufigkeit und Einschränkungen</h4>
<p>Die Methode ist als <code>noexcept</code> spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>.
