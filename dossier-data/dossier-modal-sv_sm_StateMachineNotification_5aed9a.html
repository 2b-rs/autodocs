<h4>Role and system context of the service interface</h4>
<p>The service interface <code>StateMachineNotification</code> is a fundamental ara::com service interface of the State Management (SM) functional cluster in the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_SM_91028" href="../spec/record.html?id=SWS_SM_91028">[SWS_SM_91028]</a>). If configured in a project-specific manner for a state machine, State Management instantiates a dedicated service instance of <code>StateMachineNotification</code> for this instance of <code>StateMachine</code> (<a class="spec-record-ref" data-req="SWS_SM_00665" href="../spec/record.html?id=SWS_SM_00665">[SWS_SM_00665]</a>). In this communication relationship, State Management acts as a service provider (skeleton), while interested applications act as consumers (proxies).</p>
<p>The primary purpose is interaction with regular Adaptive Applications (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">AUTOSAR_AP_SWS_StateManagement §7 “StateMachineNotification service interface”</a>). Since in real vehicle projects not every internal state machine is relevant to the application layer, there is no obligation to mandatorily provide a notification interface for every instance (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">AUTOSAR_AP_SWS_StateManagement §7 “StateMachineNotification service interface”</a>). While active state requests are made via the complementary interface <code>StateMachineService</code> (<a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>), <code>StateMachineNotification</code> serves purely observational state monitoring.</p>

<h4>Fields and Notification Semantics</h4>
<p>The interface <code>StateMachineNotification</code> does not define any RPC methods or isolated events, but provides the state information via a central field: <code>CurrentState</code> of data type <code>StateMachineStateNameType</code> (<a class="spec-record-ref" data-req="SWS_SM_91109" href="../spec/record.html?id=SWS_SM_91109">[SWS_SM_91109]</a>). According to the field specification, <code>CurrentState</code> has a getter (<code>HasGetter = true</code>) and a notifier (<code>HasNotifier = true</code>), but prohibits write access by applications (<code>HasSetter = false</code>) (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=142">AUTOSAR_AP_SWS_StateManagement §8 “Definition of Field StateMachineNotification.CurrentState”</a>, <a class="spec-record-ref" data-req="SWS_SM_91109" href="../spec/record.html?id=SWS_SM_91109">[SWS_SM_91109]</a>). Adaptive Applications can thus be informed asynchronously about state changes via the notifier or query the current status synchronously at any time.</p>
<p>As soon as a state transition is initiated, the value of the field <code>CurrentState</code> immediately changes to the transition value <code>"inTransition"</code> (<a class="spec-record-ref" data-req="SWS_SM_00616" href="../spec/record.html?id=SWS_SM_00616">[SWS_SM_00616]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=67">AUTOSAR_AP_SWS_StateManagement §7 “Value of configured StateMachineNotification::CurrentState field”</a>). This intermediate state signals to consumers that the state machine is not stable and actions are in progress.</p>
<p>Only when all associated actions within the processed <code>ActionList</code> have been completely executed does State Management set the field <code>CurrentState</code> to the newly reached target state (<a class="spec-record-ref" data-req="SWS_SM_00617" href="../spec/record.html?id=SWS_SM_00617">[SWS_SM_00617]</a>). Subscribed clients receive a corresponding notification via the notifier for both changes.</p>

<h4>Lifecycle and Service Offering</h4>
<p>Starting a state machine is a multi-step process (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=59">AUTOSAR_AP_SWS_StateManagement §7 “Completeness of controlled StateMachines”</a>). In addition to initializing and providing the interfaces for the application layer, the state machine must trigger the execution of the <code>ActionList</code> that corresponds to the initial state (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=59">AUTOSAR_AP_SWS_StateManagement §7 “Completeness of controlled StateMachines”</a>, <a class="spec-record-ref" data-req="SWS_SM_CONSTR_00016" href="../spec/record.html?id=SWS_SM_CONSTR_00016">[SWS_SM_CONSTR_00016]</a>). From the perspective of a higher-level controller (<code>Controller</code>), the <code>StateMachine</code> is only considered started once it exists and its associated services are offered (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=59">AUTOSAR_AP_SWS_StateManagement §7 “Completeness of controlled StateMachines”</a>).</p>
<p>The provision of the ara::com service <code>StateMachineNotification</code> occurs at the exact time when the <code>ActionListItem</code> <code>"StartStateMachine"</code> has been successfully processed (<a class="spec-record-ref" data-req="SWS_SM_00618" href="../spec/record.html?id=SWS_SM_00618">[SWS_SM_00618]</a>). As soon as the service is available via <code>OfferService</code>, applications can bind the proxy and subscribe to the field (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=45">AUTOSAR_AP_SWS_StateManagement §7 “StateMachine service interfaces - Offer”</a>). If the state machine is shut down or stopped, the service is no longer offered (StopOffer) (<a class="spec-record-ref" data-req="SWS_SM_00619" href="../spec/record.html?id=SWS_SM_00619">[SWS_SM_00619]</a>).</p>

<h4>State Monitoring and Error Behavior</h4>
<p>State transitions can be triggered by different sources, including Platform Health Management, Execution Management, or a <code>SMControlApplication</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=67">AUTOSAR_AP_SWS_StateManagement §7 “Value of configured StateMachineNotification::CurrentState field”</a>). The transition value <code>"inTransition"</code> is set regardless of the trigger and remains in place even if a subsequent transition for error recovery is initiated directly due to an error message (<a class="spec-record-ref" data-req="SWS_SM_00616" href="../spec/record.html?id=SWS_SM_00616">[SWS_SM_00616]</a>).</p>
<p>Since <code>StateMachineNotification</code> is designed as a pure notification interface without methods (<a class="spec-record-ref" data-req="SWS_SM_91028" href="../spec/record.html?id=SWS_SM_91028">[SWS_SM_91028]</a>, <a class="spec-record-ref" data-req="SWS_SM_91109" href="../spec/record.html?id=SWS_SM_91109">[SWS_SM_91109]</a>), no functional Application Errors exist. Interpretation: Possible errors when reading the field (getter) are limited to communication and infrastructure errors of the ara::com runtime environment.</p>
