<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::rds::RawDataStreamServer</code> ermöglicht Server-Anwendungen das Entgegennehmen einer Client-Verbindung sowie das Lesen und Schreiben binärer Datenströme über modellierte Ports <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_RawDataStream&amp;page=1">SWS RawDataStream S. 1</a>. Nach der Erzeugung über die statische Fabrikmethode <code>Create</code> wartet die Anwendung synchron oder zeitbeschränkt auf eine Verbindung, um anschließend Daten über <code>ReadData</code> und <code>WriteData</code> auszutauschen <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>. Da die Klasse reine Move-Semantik besitzt und alle Operationen <code>noexcept</code> deklariert sind, erfolgt die Fehlerbehandlung ausschließlich über <code>ara::core::Result</code>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::rds::RawDataStreamServer</code> stellt in der AUTOSAR Adaptive Platform (Modul <code>rds</code>) das serverseitige Gegenstück für stromorientierte Datenübertragungen dar <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_RawDataStream&amp;page=1">SWS RawDataStream S. 1</a>. Ihre Hauptaufgabe besteht darin, eingehende Client-Verbindungen an einem modellierten Kommunikationsport entgegenzunehmen und den anschließenden bidirektionalen Austausch unstrukturierter Rohdaten über binäre Datenströme abzuwickeln.</p>
<p>Zu den zentralen Interaktionspartnern gehören:</p>
<ul>
<li>die übergeordnete Server-Anwendung, welche die Instanz erzeugt, Verbindungen abwartet und die Datenübertragung initiiert,</li>
<li>das AUTOSAR-Laufzeitsystem, an welches der Server über einen <code>ara::core::InstanceSpecifier</code> für einen modellierten Port gebunden wird <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>,</li>
<li>der externe Client, der eine Verbindung zum Server aufbaut <a class="spec-record-ref" data-req="SWS_RDS_11318" href="../spec/record.html?id=SWS_RDS_11318">[SWS_RDS_11318]</a> und Nutzdaten austauscht <a class="spec-record-ref" data-req="SWS_RDS_11322" href="../spec/record.html?id=SWS_RDS_11322">[SWS_RDS_11322]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11324" href="../spec/record.html?id=SWS_RDS_11324">[SWS_RDS_11324]</a>.</li>
</ul>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung eines <code>RawDataStreamServer</code> erfolgt nicht über gewöhnliche Konstruktoren, sondern ausschließlich über die statische Fabrikmethode <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>. Diese bindet den Server an den per <code>ara::core::InstanceSpecifier</code> angegebenen Port.</p>
<p>Hinsichtlich der Besitzverhältnisse erzwingt die Klasse eine strikte Move-Only-Semantik. Der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_RDS_11316" href="../spec/record.html?id=SWS_RDS_11316">[SWS_RDS_11316]</a> und der Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_RDS_11317" href="../spec/record.html?id=SWS_RDS_11317">[SWS_RDS_11317]</a> sind explizit gelöscht (<code>delete</code>). Eine Übergabe von Ressourcen an andere Gültigkeitsbereiche ist daher nur über den Move-Konstruktor <a class="spec-record-ref" data-req="SWS_RDS_11314" href="../spec/record.html?id=SWS_RDS_11314">[SWS_RDS_11314]</a> oder den Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_RDS_11315" href="../spec/record.html?id=SWS_RDS_11315">[SWS_RDS_11315]</a> möglich.</p>
<p>Interpretation: Nach erfolgreicher Erzeugung befindet sich die Server-Instanz in einem initialen Zustand der Bereitschaft, in dem noch keine aktive Verbindung besteht. <a class="interp-q interp-q-open" data-q="Q-5d536f7c10a62342" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-5d536f7c10a62342" title="Frage Q-5d536f7c10a62342 (offen): Initialer Zustand nach Create">Frage Q-5d536f7c10a62342 (offen)</a> Über <code>WaitForConnection</code> <a class="spec-record-ref" data-req="SWS_RDS_11318" href="../spec/record.html?id=SWS_RDS_11318">[SWS_RDS_11318]</a> oder die zeitüberwachte Variante <code>WaitForConnection(timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11319" href="../spec/record.html?id=SWS_RDS_11319">[SWS_RDS_11319]</a> wartet der Server auf einen Client und wechselt bei Erfolg in den Zustand einer aktiven Verbindung. Die Verbindung kann zur Laufzeit gezielt durch den Aufruf von <code>Shutdown</code> geschlossen werden <a class="spec-record-ref" data-req="SWS_RDS_11320" href="../spec/record.html?id=SWS_RDS_11320">[SWS_RDS_11320]</a>.</p>
<p>Beim Zerstören der Server-Instanz gewährleistet der Destruktor <code>~RawDataStreamServer</code>, dass eine noch offene Verbindung automatisch ordnungsgemäß heruntergefahren und geschlossen wird <a class="spec-record-ref" data-req="SWS_RDS_11313" href="../spec/record.html?id=SWS_RDS_11313">[SWS_RDS_11313]</a>.</p>
<p>Bezüglich der Nebenläufigkeit ist die Erzeugungsmethode <code>Create</code> als threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>. Die Verschiebeoperationen <a class="spec-record-ref" data-req="SWS_RDS_11314" href="../spec/record.html?id=SWS_RDS_11314">[SWS_RDS_11314]</a>, <a class="spec-record-ref" data-req="SWS_RDS_11315" href="../spec/record.html?id=SWS_RDS_11315">[SWS_RDS_11315]</a> sowie der Destruktor <a class="spec-record-ref" data-req="SWS_RDS_11313" href="../spec/record.html?id=SWS_RDS_11313">[SWS_RDS_11313]</a> sind hingegen explizit als nicht threadsicher (<code>not thread-safe</code>) ausgewiesen und erfordern externen Synchronisationsschutz bei gleichzeitigem Zugriff aus mehreren Threads.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Nutzungspfad einer Server-Anwendung umfasst die Schritte Initialisierung, Warten auf Verbindungen, bidirektionalen Datentransfer und Verbindungsabbau:</p>
<ol>
<li><strong>Server erzeugen:</strong> Die Anwendung instanziiert den Server über <code>ara::rds::RawDataStreamServer::Create(instance)</code> für den konfigurierten Port <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>.</li>
<li><strong>Auf Verbindung warten:</strong> Die Anwendung blockiert mittels <code>WaitForConnection()</code> <a class="spec-record-ref" data-req="SWS_RDS_11318" href="../spec/record.html?id=SWS_RDS_11318">[SWS_RDS_11318]</a> oder mit konfigurierter Maximaldauer via <code>WaitForConnection(timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11319" href="../spec/record.html?id=SWS_RDS_11319">[SWS_RDS_11319]</a>, bis ein Client die Verbindung aufgebaut hat.</li>
<li><strong>Daten empfangen und senden:</strong> Nach erfolgreicher Verbindung liest die Anwendung Binärdaten mittels <code>ReadData(maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_11322" href="../spec/record.html?id=SWS_RDS_11322">[SWS_RDS_11322]</a> oder zeitüberwacht via <code>ReadData(maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11323" href="../spec/record.html?id=SWS_RDS_11323">[SWS_RDS_11323]</a> aus. Zum Senden von Binärdaten wird <code>WriteData</code> aufgerufen, wahlweise ohne Wartezeitbegrenzung <a class="spec-record-ref" data-req="SWS_RDS_11324" href="../spec/record.html?id=SWS_RDS_11324">[SWS_RDS_11324]</a> oder mit Zeitüberwachung <a class="spec-record-ref" data-req="SWS_RDS_11325" href="../spec/record.html?id=SWS_RDS_11325">[SWS_RDS_11325]</a>. Das Senden via <code>WriteData</code> überträgt vermutlich den Besitz des bereitgestellten Byte-Puffers (<code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code>) an den Server. <a class="interp-q interp-q-open" data-q="Q-eec0fea4a5ffaf40" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-eec0fea4a5ffaf40" title="Frage Q-eec0fea4a5ffaf40 (offen): Besitzübergang bei WriteData">Frage Q-eec0fea4a5ffaf40 (offen)</a></li>
<li><strong>Verbindung trennen:</strong> Ist die Datenübertragung abgeschlossen, beendet die Anwendung die Sitzung explizit über <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_11320" href="../spec/record.html?id=SWS_RDS_11320">[SWS_RDS_11320]</a>.</li>
</ol>
