<h4>Context</h4>
<p>In module <code>rds</code> of the AUTOSAR Adaptive Platform, the class <code>ara::rds::RawDataStreamServer</code> forms the server-side interface for accepting connections as well as the subsequent bidirectional exchange of unformatted binary data streams. It encapsulates the communication connection to a remote peer via a software port identified by a <code>ara::core::InstanceSpecifier</code>. The primary responsibility of the class lies in waiting for client connections as well as the synchronous and time-monitored reading and writing of byte sequences.</p>

<h4>Lifecycle</h4>
<p>The instantiation of <code>ara::rds::RawDataStreamServer</code> does not occur via a public constructor, but exclusively via the static factory method <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>. This method expects a <code>ara::core::InstanceSpecifier</code> and is declared as thread-safe.</p>
<p>With regard to the ownership and copy model, it is a move-only type:</p>
<ul>
<li>The copy constructor <a class="spec-record-ref" data-req="SWS_RDS_11316" href="../spec/record.html?id=SWS_RDS_11316">[SWS_RDS_11316]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_RDS_11317" href="../spec/record.html?id=SWS_RDS_11317">[SWS_RDS_11317]</a> are explicitly deleted (<code>delete</code>).</li>
<li>A transfer of the resource is possible via the move constructor <a class="spec-record-ref" data-req="SWS_RDS_11314" href="../spec/record.html?id=SWS_RDS_11314">[SWS_RDS_11314]</a> and the move assignment operator <a class="spec-record-ref" data-req="SWS_RDS_11315" href="../spec/record.html?id=SWS_RDS_11315">[SWS_RDS_11315]</a>. Both operations are defined as <code>noexcept</code>, but are explicitly designated as not thread-safe.</li>
</ul>
<p>The lifecycle of a connection ends either through the explicit call of <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_11320" href="../spec/record.html?id=SWS_RDS_11320">[SWS_RDS_11320]</a> or implicitly when the destructor <a class="spec-record-ref" data-req="SWS_RDS_11313" href="../spec/record.html?id=SWS_RDS_11313">[SWS_RDS_11313]</a> is called. The destructor is <code>noexcept</code> as well as not thread-safe and ensures that a still open connection is closed and shut down when the object is destroyed.</p>

<h4>Usage Path</h4>
<p>The typical workflow when using a <code>RawDataStreamServer</code> is divided into the phases of creation, connection acceptance, data exchange, and connection teardown:</p>
<ol>
<li><strong>Creation:</strong> The application creates the server instance via <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_11312" href="../spec/record.html?id=SWS_RDS_11312">[SWS_RDS_11312]</a>, specifying the modeled port.</li>
<li><strong>Connection acceptance:</strong> The application waits for the arrival of an incoming client connection. This takes place either blocking via <code>WaitForConnection()</code> <a class="spec-record-ref" data-req="SWS_RDS_11318" href="../spec/record.html?id=SWS_RDS_11318">[SWS_RDS_11318]</a> or with a maximum time period via <code>WaitForConnection(timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11319" href="../spec/record.html?id=SWS_RDS_11319">[SWS_RDS_11319]</a>.</li>
<li><strong>Data transfer:</strong> As soon as the connection is established, data can be received and sent:
<ul>
<li>Binary data is read using <code>ReadData(maxLength)</code> <a class="spec-record-ref" data-req="SWS_RDS_11322" href="../spec/record.html?id=SWS_RDS_11322">[SWS_RDS_11322]</a> or time-limited via <code>ReadData(maxLength, timeout)</code> <a class="spec-record-ref" data-req="SWS_RDS_11323" href="../spec/record.html?id=SWS_RDS_11323">[SWS_RDS_11323]</a>. A <code>ara::core::Result&lt;ReadDataResult&gt;</code> is returned as the result.</li>
<li>Binary data is sent via <code>WriteData</code>, optionally without timeout <a class="spec-record-ref" data-req="SWS_RDS_11324" href="../spec/record.html?id=SWS_RDS_11324">[SWS_RDS_11324]</a> or with timeout <a class="spec-record-ref" data-req="SWS_RDS_11325" href="../spec/record.html?id=SWS_RDS_11325">[SWS_RDS_11325]</a>. The payload is passed to the method as <code>std::unique_ptr&lt;ara::core::Byte[]&gt;</code>.</li>
</ul>
</li>
<li><strong>Connection teardown:</strong> After completion of the data transmission, the connection is closed in an orderly manner by <code>Shutdown()</code> <a class="spec-record-ref" data-req="SWS_RDS_11320" href="../spec/record.html?id=SWS_RDS_11320">[SWS_RDS_11320]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>All state-modifying and data-transferring functions dispense with C++ exceptions and are declared as <code>noexcept</code>. Instead, they signal success or error via <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Connection establishment failure:</strong> If the connection cannot be established within the specified deadline, <code>WaitForConnection</code> with timeout <a class="spec-record-ref" data-req="SWS_RDS_11319" href="../spec/record.html?id=SWS_RDS_11319">[SWS_RDS_11319]</a> returns a corresponding error result.</li>
<li><strong>Failure and timeouts during data operations:</strong> For read and write operations with timeout (<a class="spec-record-ref" data-req="SWS_RDS_11323" href="../spec/record.html?id=SWS_RDS_11323">[SWS_RDS_11323]</a> and <a class="spec-record-ref" data-req="SWS_RDS_11325" href="../spec/record.html?id=SWS_RDS_11325">[SWS_RDS_11325]</a>), an error is returned in the <code>Result</code> if the specified time period is exceeded.</li>
<li><strong>Preconditions:</strong> A call to <code>ReadData</code> or <code>WriteData</code> presumably requires a previously successfully established connection via <code>WaitForConnection</code>; otherwise, the operation is likely to be rejected with an error in the <code>ara::core::Result</code>.</li>
<li><strong>State after shutdown:</strong> After execution of <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_11320" href="../spec/record.html?id=SWS_RDS_11320">[SWS_RDS_11320]</a>, the connection is closed; subsequent calls to read and write methods are likely to fail.</li>
</ul>
