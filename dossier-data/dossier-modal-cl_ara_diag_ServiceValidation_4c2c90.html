<h4>Context</h4>
<p>The class <code>ara::diag::ServiceValidation</code> represents the functional interface element for manufacturer- and supplier-specific validation of incoming diagnostic requests in the AUTOSAR Adaptive module <code>diag</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. Depending on the modeling of the attribute <code>DiagnosticServiceValidationMapping.category</code>, validation via the method <code>Validate</code> is performed either as a manufacturer check or as a supplier check within the negative response code (NRC) order according to Chapter 8.7 of ISO 14229-1 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</p>
<p>Essentially three parties are involved in the interaction:</p>
<ul>
<li><strong>Adaptive application:</strong> Implements the concrete validation logic by specializing the virtual methods <code>Validate</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> and <code>Confirmation</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>.</li>
<li><strong>Diagnostic Management (DM):</strong> Receives UDS requests, forwards them to the instance for preliminary checking after successful activation by <code>Offer</code> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>, and reports the overall completion back via <code>Confirmation</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>.</li>
<li><strong>Diagnostic tester:</strong> Initiates diagnostic messages whose raw data and meta-information are the subject of the check <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The instantiation of <code>ServiceValidation</code> is performed explicitly by passing a <code>ara::core::InstanceSpecifier</code>, which must reference a modeled <code>PortPrototype</code> of a <code>DiagnosticServiceValidationInterface</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. The constructor is specified as thread-safe <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. An instance of <code>ServiceValidation</code> must be neither copied nor moved: copy constructor <a class="spec-record-ref" data-req="SWS_DM_01689" href="../spec/record.html?id=SWS_DM_01689">[SWS_DM_01689]</a>, copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01687" href="../spec/record.html?id=SWS_DM_01687">[SWS_DM_01687]</a>, move constructor <a class="spec-record-ref" data-req="SWS_DM_01690" href="../spec/record.html?id=SWS_DM_01690">[SWS_DM_01690]</a>, and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01688" href="../spec/record.html?id=SWS_DM_01688">[SWS_DM_01688]</a> are explicitly deleted (<code>= delete</code>).</p>
<p>After construction, the instance is in the <em>Not offered</em> state. Calling <code>Offer()</code> enables the forwarding of incoming requests by Diagnostic Management <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>. If processing is to be paused or terminated, calling <code>StopOffer()</code> prevents the forwarding of further diagnostic messages <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>. The enablement can be reactivated by a renewed <code>Offer()</code>. Final destruction occurs via the virtual destructor <code>~ServiceValidation()</code> <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a>.</p>
<p>With regard to concurrency, the methods <code>Offer</code>, <code>StopOffer</code>, <code>Validate</code>, <code>Confirmation</code> and the destructor are classified as not thread-safe <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>. Calls to these operations must be synchronized by the application in the event of concurrent access.</p>

<h4>Usage Path</h4>
<p>The typical sequence for securing diagnostic services is divided into the following steps:</p>
<ol>
<li><strong>Instantiation:</strong> The application creates the instance while binding to the modeled port <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
<li><strong>Enablement:</strong> Call of <code>Offer()</code>. Diagnostic Management is instructed to forward incoming diagnostic messages to this instance <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>.</li>
<li><strong>Validation:</strong> For each incoming diagnostic request, the DM calls the method <code>Validate</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>. The request data (including service identifier) is passed as <code>ara::core::Span&lt;const std::uint8_t&gt;</code>, and the context via <code>MetaInfo</code>. The lifetime of the request data remains valid until the associated promise is fulfilled or processing is canceled via the CancellationHandler <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>.</li>
<li><strong>Asynchronous result:</strong> The method returns a <code>ara::core::Future&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>. Upon successful validation, the future is resolved without error. If the request is invalid, the future is completed with a suitable Negative Response Code (NRC) from <code>DiagUdsNrcErrc</code> according to ISO 14229-1 <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>.</li>
<li><strong>Confirmation of completion:</strong> As soon as the processing of the diagnostic request is completely finished, the DM calls <code>Confirmation</code> to transmit the overall result (<code>status</code>) and the <code>metaInfo</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>.</li>
<li><strong>Deregistration:</strong> Before shutting down, the application calls <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>. Interpretation: After calling <code>StopOffer()</code>, ongoing validation requests whose future has not yet been fulfilled are likely either discarded or canceled by the DM.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error situations can occur in various phases and are signaled via specific mechanisms:</p>
<ul>
<li><strong>Construction and model violations:</strong> If binding of the <code>InstanceSpecifier</code> fails, the framework reports defined violations <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>:
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved or does not point to a PortPrototype.</li>
<li><code>PortInterfaceMappingViolation</code>: The PortPrototype is not typed by a <code>DiagnosticServiceValidationInterface</code>.</li>
<li><code>ProcessMappingViolation</code>: No matching modeled process exists for the reference for the current runtime process.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another instance in the running process.</li>
</ul>
</li>
<li><strong>Faulty enablement:</strong> If <code>Offer()</code> is called while the service is already being offered, the call fails and returns the error code <code>DiagOfferErrc::kAlreadyOffered</code> with rollback semantics in the return value <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>.</li>
<li><strong>Validation error:</strong> If the check detects a violated condition (e.g., insufficient preconditions or security requirements), the error is transmitted via <code>DiagUdsNrcErrc</code> in the <code>ara::core::Future&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>. Since <code>Validate</code> is declared as <code>noexcept</code>, no C++ exceptions may be thrown.</li>
<li><strong>Exception safety:</strong> All methods of the class are specified as exception-safe (<code>exception safe</code>) and annotated with <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a> <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>. Error states are without exception mapped via return types and platform notifications.</li>
</ul>
