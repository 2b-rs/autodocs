<p class="ai-level ai-oneliner-lead" data-ai-level="1">Validiert eingehende Diagnoseanforderungen im Diagnostic Management anhand von Hersteller- oder Zuliefererprüfungen.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::ServiceValidation</code> dient der anwendungsspezifischen Validierung eingehender UDS-Diagnoseanforderungen im Diagnostic Management anhand von Hersteller- oder Zuliefererkriterien <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. Nach der Erzeugung muss der Dienst mittels <code>Offer()</code> aktiviert werden, damit Anfragedaten asynchron zur Prüfung an <code>Validate()</code> weitergeleitet und anschließend über <code>Confirmation()</code> bestätigt werden <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>. Als wesentliche Randbedingung ist die Instanz an einen Port gebunden, weder kopier- noch verschiebbar und abseits des Konstruktors nicht threadsicher.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::ServiceValidation</code> stellt die Programmierschnittstelle für das Modellierungselement <code>DiagnosticServiceValidationInterface</code> innerhalb des AUTOSAR-Adaptive-Diagnosestacks bereit. Über diese Schnittstelle kann eine Anwendung anwendungsspezifische Prüfungen für eingehende Diagnoseanforderungen implementieren. Die Instanz interagiert direkt mit dem Diagnostic Management (DM), welches autorisiert wird, eingehende Diagnoseanforderungen an die Validierungslogik weiterzuleiten <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>.</p>
<p>Die funktionale Zuordnung der Validierung wird über das Modellierungsattribut <code>DiagnosticServiceValidationMapping.category</code> gesteuert. In Abhängigkeit von dieser Kategorie wird die Validierungsmethode <code>Validate()</code> im Rahmen der UDS-Reaktionsregeln gemäß ISO 14229-1 (Kapitel 8.7) entweder im Kontext einer Herstellerprüfung („Manufacturer Check“) oder einer Zuliefererprüfung („Supplier Check“) aufgerufen <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. Das DM dürfte eingehende Anforderungsnachrichten vor der eigentlichen Serviceausführung dieser Validierungsprüfung unterziehen, um unzulässige Anfragen frühzeitig zu filtern.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung erfolgt explizit über den Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code>, welcher auf einen im Systemmodell definierten <code>PortPrototype</code> verweisen muss <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. <code>ara::diag::ServiceValidation</code> ist als nicht kopierbare und nicht verschiebbare Einzelinstanz ausgelegt: Sowohl der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01689" href="../spec/record.html?id=SWS_DM_01689">[SWS_DM_01689]</a> als auch der Verschiebekonstruktor <a class="spec-record-ref" data-req="SWS_DM_01690" href="../spec/record.html?id=SWS_DM_01690">[SWS_DM_01690]</a> sowie die Zuweisungsoperatoren für Kopie <a class="spec-record-ref" data-req="SWS_DM_01687" href="../spec/record.html?id=SWS_DM_01687">[SWS_DM_01687]</a> und Verschiebung <a class="spec-record-ref" data-req="SWS_DM_01688" href="../spec/record.html?id=SWS_DM_01688">[SWS_DM_01688]</a> sind als gelöscht (<code>=delete</code>) deklariert.</p>
<p>Nach der Initialisierung befindet sich das Objekt im Ruhezustand. Erst durch den Aufruf von <code>Offer()</code> wird die Weiterleitung von Diagnoseanforderungen vom DM an den Handler freigeschaltet <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>. Die Dienstanbietung kann während der Laufzeit über <code>StopOffer()</code> beendet werden, wodurch das DM die Weiterleitung wieder deaktiviert <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>. Die Freigabe der Ressourcen erfolgt über den virtuellen Destruktor <code>~ServiceValidation()</code> <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit ist ausschließlich der Konstruktor als threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>. Die Methoden <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>, <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>, <code>Validate()</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>, <code>Confirmation()</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> sowie der Destruktor <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> sind als nicht threadsicher klassifiziert, jedoch ausnahmesicher (<code>noexcept</code>).</p>

<h4>Nutzungspfad</h4>
<p>Die konkrete Validierungslogik wird vermutlich durch Ableitung von <code>ara::diag::ServiceValidation</code> und Überschreiben der virtuellen Schnittstellenmethoden durch die Anwendung bereitgestellt. Der typische Betriebsablauf gliedert sich in folgende Phasen:</p>
<ol>
  <li><strong>Instanziierung:</strong> Erzeugen der Instanz unter Übergabe des <code>InstanceSpecifier</code>, der den konfigurierten Port referenziert <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
  <li><strong>Dienstanbietung:</strong> Aufruf von <code>Offer()</code> zur Aktivierung der Anforderungsweiterleitung durch das DM <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>.</li>
  <li><strong>Validierung:</strong> Bei jeder eingehenden Diagnoseanforderung ruft das DM die Methode <code>Validate()</code> auf <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>. Übergeben werden die Rohdaten (einschließlich Service Identifier, SID) als <code>ara::core::Span&lt;const std::uint8_t&gt;</code> sowie die <code>MetaInfo</code> der Anfrage <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>. Die Daten bleiben gültig, bis das zurückgegebene <code>ara::core::Future&lt;void&gt;</code> erfüllt ist oder die Verarbeitung durch einen Cancellation-Handler abgebrochen wird <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>.</li>
  <li><strong>Bestätigung:</strong> Sobald die Bearbeitung der Diagnoseanforderung abgeschlossen ist, informiert das DM den Handler über die Methode <code>Confirmation()</code> unter Übergabe des Ergebnisstatus (<code>ConfirmationStatusType</code>) und der <code>MetaInfo</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>.</li>
  <li><strong>Deaktivierung:</strong> Beenden der Anforderungsverarbeitung mittels <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Fehlerbedingungen treten sowohl bei der statischen Konfigurationsprüfung während der Konstruktion als auch zur Laufzeit auf:</p>
<ul>
  <li><strong>Konstruktionsverletzungen:</strong> Der Konstruktor meldet spezifische Modellierungsfehler als Violations <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>:
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: Der Bezeichner lässt sich im Kontext der Executable nicht auflösen oder verweist nicht auf einen <code>PortPrototype</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
      <li><code>PortInterfaceMappingViolation</code>: Der referenzierte <code>PortPrototype</code> ist nicht durch ein <code>DiagnosticServiceValidationInterface</code> typisiert <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
      <li><code>ProcessMappingViolation</code>: Für den Prozess existiert kein passender modellierter <code>Process</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: Der <code>InstanceSpecifier</code> wird im laufenden Prozess bereits von einer anderen Instanz genutzt <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>.</li>
    </ul>
  </li>
  <li><strong>Dienstanbietung:</strong> Wird <code>Offer()</code> aufgerufen, wenn der Dienst bereits aktiv angeboten wird, liefert der Rückgabewert <code>ara::core::Result&lt;void&gt;</code> den Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> zurück <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>.</li>
  <li><strong>Validierungsfehler:</strong> Schlägt die inhaltliche Überprüfung der Anforderung fehl, signalisiert die Anwendung die Ablehnung über das zurückgegebene <code>ara::core::Future&lt;void&gt;</code> durch Setzen eines entsprechenden Negative Response Code (NRC) aus ISO 14229-1 via <code>DiagUdsNrcErrc</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>.</li>
</ul>
