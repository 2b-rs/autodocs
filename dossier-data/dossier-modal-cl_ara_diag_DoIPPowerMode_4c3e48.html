<h4>Context</h4>
<p>The class <code>ara::diag::DoIPPowerMode</code> defines the C++ interface for the DoIP power mode (<code>DiagnosticDoIPPowerModeInterface</code>) within the diagnostic module of the AUTOSAR Adaptive Platform (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=74">AUTOSAR AP SWS Diagnostics, p. 74</a>). Its primary responsibility is to provide the current power status for the Diagnostic-over-IP protocol (DoIP) to the Diagnostic Management (DM) <a class="spec-record-ref" data-req="SWS_DM_00734" href="../spec/record.html?id=SWS_DM_00734">[SWS_DM_00734]</a>.</p>
<p>Essentially three components are involved in the interaction:</p>
<ul>
<li><strong>Application software (diagnostic handler):</strong> Specializes the abstract base class <code>ara::diag::DoIPPowerMode</code> and implements the method <code>GetDoIPPowerMode()</code> to determine the system-specific power status <a class="spec-record-ref" data-req="SWS_DM_00734" href="../spec/record.html?id=SWS_DM_00734">[SWS_DM_00734]</a>.</li>
<li><strong>Diagnostic Management (DM):</strong> Manages the diagnostic protocols and retrieves the current power status via the registered interface as soon as this is required by the DoIP protocol <a class="spec-record-ref" data-req="SWS_DM_00735" href="../spec/record.html?id=SWS_DM_00735">[SWS_DM_00735]</a>.</li>
<li><strong>AUTOSAR runtime environment / model mapping:</strong> Maps the instance via a <code>ara::core::InstanceSpecifier</code> to the <code>PortPrototype</code> declared in the software model <a class="spec-record-ref" data-req="SWS_DM_00732" href="../spec/record.html?id=SWS_DM_00732">[SWS_DM_00732]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::diag::DoIPPowerMode</code> is initialized by the constructor specifying a modeled <code>ara::core::InstanceSpecifier</code> as well as the concurrency behavior <code>ConcurrencyType</code> (<code>kConcurrent</code> or <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_00732" href="../spec/record.html?id=SWS_DM_00732">[SWS_DM_00732]</a>. According to the specification, <code>DoIPPowerMode</code> is designed as a unique instance: both copy constructor <a class="spec-record-ref" data-req="SWS_DM_01645" href="../spec/record.html?id=SWS_DM_01645">[SWS_DM_01645]</a> and copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01643" href="../spec/record.html?id=SWS_DM_01643">[SWS_DM_01643]</a> as well as move constructor <a class="spec-record-ref" data-req="SWS_DM_01646" href="../spec/record.html?id=SWS_DM_01646">[SWS_DM_01646]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01644" href="../spec/record.html?id=SWS_DM_01644">[SWS_DM_01644]</a> are explicitly deleted (<code>=delete</code>).</p>
<p>After construction, the instance is initially in the inactive state (not offered). Only by calling <code>Offer()</code> is the forwarding of incoming DoIP requests by the DM to the handler activated <a class="spec-record-ref" data-req="SWS_DM_00735" href="../spec/record.html?id=SWS_DM_00735">[SWS_DM_00735]</a>. This forwarding can be deactivated again at any time using <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00736" href="../spec/record.html?id=SWS_DM_00736">[SWS_DM_00736]</a>. Destruction takes place via the virtual destructor <code>~DoIPPowerMode()</code> <a class="spec-record-ref" data-req="SWS_DM_00733" href="../spec/record.html?id=SWS_DM_00733">[SWS_DM_00733]</a>. Before destroying an active instance, <code>StopOffer()</code> should presumably be called explicitly in order to cleanly tear down open forwarding relationships in the DM.</p>
<p>With regard to concurrency, the constructor is designed to be thread-safe <a class="spec-record-ref" data-req="SWS_DM_00732" href="../spec/record.html?id=SWS_DM_00732">[SWS_DM_00732]</a>, whereas <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00735" href="../spec/record.html?id=SWS_DM_00735">[SWS_DM_00735]</a>, <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00736" href="../spec/record.html?id=SWS_DM_00736">[SWS_DM_00736]</a>, and the destructor <a class="spec-record-ref" data-req="SWS_DM_00733" href="../spec/record.html?id=SWS_DM_00733">[SWS_DM_00733]</a> are not thread-safe. The thread safety of <code>GetDoIPPowerMode()</code> is conditional: it depends on the <code>ConcurrencyType</code> selected in the constructor <a class="spec-record-ref" data-req="SWS_DM_00734" href="../spec/record.html?id=SWS_DM_00734">[SWS_DM_00734]</a>. With <code>ConcurrencyType::kConcurrent</code>, the DM is likely to initiate queries in parallel across multiple worker threads, which is why the derived implementation must be thread-safe.</p>

<h4>Usage Path</h4>
<p>A typical use case comprises the provision of the DoIP power mode by a diagnostic application and is divided into the following phases:</p>
<ol>
<li><strong>Derivation and instantiation:</strong> The application derives a concrete handler class from <code>ara::diag::DoIPPowerMode</code> and implements the pure virtual method <code>GetDoIPPowerMode()</code> <a class="spec-record-ref" data-req="SWS_DM_00734" href="../spec/record.html?id=SWS_DM_00734">[SWS_DM_00734]</a>. When creating the instance, the <code>InstanceSpecifier</code> of the port and the desired concurrency model (<code>kConcurrent</code> or <code>kNotConcurrent</code>) are passed <a class="spec-record-ref" data-req="SWS_DM_00732" href="../spec/record.html?id=SWS_DM_00732">[SWS_DM_00732]</a>.</li>
<li><strong>Service offer (Offer):</strong> The application calls <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00735" href="../spec/record.html?id=SWS_DM_00735">[SWS_DM_00735]</a>. The DM registers the handler for DoIP power requests and returns a <code>ara::core::Result&lt;void&gt;</code>.</li>
<li><strong>Request processing:</strong> As soon as the DoIP protocol requires the status, the DM calls the method <code>GetDoIPPowerMode()</code> <a class="spec-record-ref" data-req="SWS_DM_00734" href="../spec/record.html?id=SWS_DM_00734">[SWS_DM_00734]</a>. The implementation returns a <code>ara::core::Future&lt;PowerModeType&gt;</code>, through which the determined mode is provided asynchronously.</li>
<li><strong>Termination (StopOffer):</strong> As soon as the application shuts down or withdraws the handler, it calls <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00736" href="../spec/record.html?id=SWS_DM_00736">[SWS_DM_00736]</a>. As a result, no further requests are forwarded. Subsequently, the instance is destroyed <a class="spec-record-ref" data-req="SWS_DM_00733" href="../spec/record.html?id=SWS_DM_00733">[SWS_DM_00733]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
