<p class="ai-level ai-oneliner-lead" data-ai-level="1">Leitet Speicheraufträge des NVRAM-Managers per Geräteindex an Flash-EEPROM-Emulation oder EEPROM-Abstraktion weiter.</p>
<div class="ai-level" data-ai-level="2">
<p>MemIf leitet die Speicheraufträge des NVRAM Managers an Fee- oder Ea-Module weiter und verbirgt deren Anzahl hinter einer einheitlichen API <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE">SWS MemIf S. 7</a>. Der Parameter <code>DeviceIndex</code> wählt das Modul; ist nur eines konfiguriert, wird er ignoriert und MemIf als Makrosatz umgesetzt <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>. Die Dienste nehmen Aufträge synchron an und reichen den Rückgabewert weiter, während die Speicheroperation asynchron darunter abläuft. Status und Ergebnis liefern <code>MemIf_GetStatus</code> und <code>MemIf_GetJobResult</code>. Bei aktiver Entwicklungsfehlererkennung liefern fehlerhafte Aufrufe <code>E_NOT_OK</code> bzw. <code>MEMIF_JOB_FAILED</code>.</p>

<div class="ai-level" data-ai-level="3">
<p>Das Memory Abstraction Interface ersetzt die früheren Treiber-Schnittstellenschichten für Flash und EEPROM. Es erlaubt dem NVRAM Manager, über eine einheitliche API mehrere Abstraktionsmodule anzusprechen: die Flash EEPROM Emulation (Fee) und die EEPROM Abstraction (Ea) <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER">SRS MemHwAb S. 5</a>. MemIf verbirgt die Anzahl dieser Module und bietet eine virtuelle Segmentierung auf einem linearen Adressraum <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE">SWS MemIf S. 7</a>.</p>

<p class="diagram-note">Kontextdiagramm: MemIf vermittelt zwischen NvM und Fee/Ea; Fertigmeldungen gehen direkt von Fee/Ea an den NvM. Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-584d2e8102693d79.html" data-snip="FIG-584d2e8102693d79">SWS Fee S. 6</a>, <a class="spec-record-ref" data-req="SWS_MemIf_00047" href="../../spec/record.html?id=SWS_MemIf_00047">[SWS_MemIf_00047]</a></p>
<p>Eigene Speicherlogik hat MemIf nicht. Der Parameter <code>DeviceIndex</code> wählt das Modul; ist nur eines konfiguriert, wird er ignoriert und MemIf als Makrosatz umgesetzt. Bei mehreren Modulen erfolgt die Verteilung etwa über Funktionszeigertabellen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>. In R20-11 ist <code>DeviceIndex</code> vom Typ <code>uint8</code> <a class="spec-record-ref" data-req="SWS_MemIf_00039" href="../../spec/record.html?id=SWS_MemIf_00039">[SWS_MemIf_00039]</a>; spätere Fassungen verwenden <code>uint16</code>.</p>
<p>Die Dienste nehmen Aufträge synchron an und reichen den Rückgabewert des Moduls weiter <a class="spec-record-ref" data-req="SWS_MemIf_00040" href="../../spec/record.html?id=SWS_MemIf_00040">[SWS_MemIf_00040]</a>. Die Speicheroperation läuft danach asynchron in der Hauptfunktion der unteren Schicht. Das Jobergebnis bezieht sich stets auf den letzten Auftrag und unterscheidet unter anderem abgebrochene, inkonsistente und ungültige Blöcke <a class="spec-record-ref" data-req="SWS_MemIf_00065" href="../../spec/record.html?id=SWS_MemIf_00065">[SWS_MemIf_00065]</a>. <code>MemIf_SetMode</code> wirkt auf alle Module zugleich <a class="spec-record-ref" data-req="SWS_MemIf_00038" href="../../spec/record.html?id=SWS_MemIf_00038">[SWS_MemIf_00038]</a>.</p>

<h4>Rolle im Speicherstapel: Weiche zwischen NvM und Fee/Ea</h4>
<p>Das Memory Abstraction Interface (MemIf) ersetzt die früheren Treiber-Schnittstellenschichten für Flash und EEPROM. Es erlaubt dem NVRAM Manager (NvM), über eine einzige API mehrere Speicherabstraktionsmodule anzusprechen: die Flash EEPROM Emulation (Fee) und die EEPROM Abstraction (Ea) <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER">SRS MemHwAb S. 5</a>. Nach oben verbirgt MemIf, wie viele Fee- und Ea-Module darunter liegen. Es bietet eine virtuelle Segmentierung auf einem einheitlichen linearen Adressraum <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYABSTRACTIONINTERFACE">SWS MemIf S. 7</a>. Fee und Ea liefern die blockbasierte Adressierung und eine „virtuell unbegrenzte“ Zahl von Lösch-Schreib-Zyklen. Deshalb muss der NvM nicht geändert werden, wenn Treiber oder Baustein wechseln <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER">SRS MemHwAb S. 5</a>.</p>
<p>MemIf enthält selbst keine Speicherlogik. Seine API ist auf die API der Abstraktionsmodule abzubilden, und das funktionale Verhalten legen deren Spezifikationen bzw. die der Speichertreiber fest <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>. Entsprechend benötigt MemIf die Dienste der Abstraktionsmodule, für Ea etwa <code>Ea_Read</code>, <code>Ea_Cancel</code>, <code>Ea_GetStatus</code> und <code>Ea_GetJobResult</code> <a class="spec-record-ref" data-req="SWS_MemIf_00047" href="../../spec/record.html?id=SWS_MemIf_00047">[SWS_MemIf_00047]</a>. Optional nutzt es <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_MemIf_00048" href="../../spec/record.html?id=SWS_MemIf_00048">[SWS_MemIf_00048]</a>. Die in <code>MemIf.h</code> definierten Typen <code>MemIf_StatusType</code>, <code>MemIf_JobResultType</code> und <code>MemIf_ModeType</code> bilden das gemeinsame Vokabular des Stapels <a class="spec-record-ref" data-req="SWS_MemIf_00064" href="../../spec/record.html?id=SWS_MemIf_00064">[SWS_MemIf_00064]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00065" href="../../spec/record.html?id=SWS_MemIf_00065">[SWS_MemIf_00065]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00066" href="../../spec/record.html?id=SWS_MemIf_00066">[SWS_MemIf_00066]</a>. So liefert etwa <code>Fls_GetJobResult</code> direkt <code>MemIf_JobResultType</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_6_Fls_GetJobResult.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_6_Fls_GetJobResult">SWS Fls S. 36</a>.</p>
<p>Die Abbildungen jüngerer Releases zeigen unterhalb von Ea und Fee zusätzlich die Module MemAcc und Mem <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-607bf2d10fae231b.html" data-snip="FIG-607bf2d10fae231b">SWS Ea S. 42</a>. Für R20-11 dürfte vermutlich die ältere Übersicht maßgeblich sein, in der Fee auf den Flash-Treiber und Ea auf den EEPROM-Treiber aufsetzen <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-584d2e8102693d79.html" data-snip="FIG-584d2e8102693d79">SWS Fee S. 6</a>. Für MemIf ist der Unterschied ohne Belang, da es nur bis zur Abstraktionsebene weiterleitet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>.</p>

<h4>Geräteauswahl über DeviceIndex: Makros oder Verteiltabelle</h4>
<p>Der Parameter <code>DeviceIndex</code> wählt das Abstraktionsmodul und damit den Speicherbaustein. Ist nur ein Modul konfiguriert, wird er ignoriert <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>. In diesem Fall ist MemIf als Satz von Makros umzusetzen, etwa <code>#define MemIf_Write(DeviceIndex, BlockNumber, DataPtr) Fee_Write(BlockNumber, DataPtr)</code>. Bei mehreren Modulen sind die Aufrufe über effiziente Mechanismen zu verteilen; als eine Lösung nennt die Spezifikation Tabellen von Funktionszeigern, die über <code>DeviceIndex</code> indiziert werden <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf S. 17</a>. Ersetzt eine herstellerspezifische Bibliothek alle benötigten Fee- und Ea-Module, besteht MemIf nur aus Makros <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER">SRS MemHwAb S. 5</a>.</p>
<p>In R20-11 ist <code>DeviceIndex</code> vom Typ <code>uint8</code> <a class="spec-record-ref" data-req="SWS_MemIf_00039" href="../../spec/record.html?id=SWS_MemIf_00039">[SWS_MemIf_00039]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00041" href="../../spec/record.html?id=SWS_MemIf_00041">[SWS_MemIf_00041]</a>. Spätere Fassungen der Spezifikation führen ihn als <code>uint16</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_1_MemIf_Read.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_1_MemIf_Read">SWS MemIf S. 18</a>. Normativ für dieses Release ist <code>uint8</code>.</p>

<h4>Auftragsablauf: synchrone Annahme, asynchrone Ausführung</h4>
<p>Alle MemIf-Dienste sind synchron spezifiziert. Jeder ruft die gleichnamige Funktion des gewählten Moduls auf und gibt deren Rückgabewert zurück, so etwa Read, Write und InvalidateBlock <a class="spec-record-ref" data-req="SWS_MemIf_00039" href="../../spec/record.html?id=SWS_MemIf_00039">[SWS_MemIf_00039]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00040" href="../../spec/record.html?id=SWS_MemIf_00040">[SWS_MemIf_00040]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00044" href="../../spec/record.html?id=SWS_MemIf_00044">[SWS_MemIf_00044]</a>. Die eigentliche Speicheroperation läuft danach asynchron in der zyklisch aufgerufenen Hauptfunktion der unteren Schicht. Die Ea-Sequenz zeigt dazu eine Schleife über <code>Eep_MainFunction</code> im BSW-Task <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-5dcc697f7998a885.html" data-snip="FIG-5dcc697f7998a885">SWS Ea S. 41</a>. Laut Fee-Spezifikation gilt dieses Muster auch für die übrigen asynchronen Dienste <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_2_Fee_Write.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_2_Fee_Write">SWS Fee S. 48</a>.</p>
<p>Vom Auftragsende erfährt der NvM je nach Stackkonfiguration auf einem von zwei Wegen. Entweder ruft das Abstraktionsmodul einen Callback wie <code>NvM_JobEndNotification</code> bzw. <code>NvM_JobErrorNotification</code>, oder der NvM pollt <code>MemIf_GetJobResult</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_2_Fee_Write.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_2_Fee_Write">SWS Fee S. 48</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_6_2_2_2_5_NVRAM_Manager.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_6_2_2_2_5_NVRAM_Manager">EXP ErrorDescription S. 45</a>. MemIf selbst stellt keine Callback-Funktion bereit; seine API besteht aus den folgenden Diensten <a class="spec-record-ref" data-req="SWS_MemIf_00038" href="../../spec/record.html?id=SWS_MemIf_00038">[SWS_MemIf_00038]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00046" href="../../spec/record.html?id=SWS_MemIf_00046">[SWS_MemIf_00046]</a>.</p>

<h4>Abbrechen laufender Aufträge</h4>
<p><code>MemIf_Cancel</code> ruft die Cancel-Funktion des gewählten Moduls auf <a class="spec-record-ref" data-req="SWS_MemIf_00041" href="../../spec/record.html?id=SWS_MemIf_00041">[SWS_MemIf_00041]</a>. Der Abbruch selbst ist synchron, bezüglich der Hardware aber asynchron: Die Hardware kann noch nachlaufen, wenn der Aufruf bereits zurückgekehrt ist <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_3_Fee_Cancel.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_3_Fee_Cancel">SWS Fee S. 45</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_3_Ea_Cancel.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_3_Ea_Cancel">SWS Ea S. 44</a>. Das Jobergebnis lautet danach <code>MEMIF_JOB_CANCELED</code> <a class="spec-record-ref" data-req="SWS_MemIf_00065" href="../../spec/record.html?id=SWS_MemIf_00065">[SWS_MemIf_00065]</a>, was Fee ausdrücklich als Fehlschlag wertet <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FEE_SECTION_8_3_6_Fee_GetJobResult.html" data-snip="SNIP_CLASSIC_FEE_SECTION_8_3_6_Fee_GetJobResult">SWS Fee S. 31</a>.</p>
<p>Für den Flash-Pfad zeigt die Treiberspezifikation die Kette <code>MemIf_Cancel</code> → <code>Fee_Cancel</code> → <code>Fls_Cancel</code> mit anschließenden Fehlerbenachrichtigungen. Sie fordert außerdem, <code>Fls_Cancel</code> nicht während einer laufenden <code>Fls_MainFunction</code> aufzurufen. Dafür gibt es zwei Wege: Die Jobfunktionen von NvM und Flash-Treiber werden synchronisiert, oder der Task der <code>Fls_MainFunction</code> wird nicht unterbrochen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job">SWS Fls S. 58</a>.</p>

<h4>Aufrufregeln, Reentranz und Einbettung in die BSW</h4>
<p>Mit Ausnahme von <code>MemIf_GetVersionInfo</code> sind alle Dienste nicht reentrant <a class="spec-record-ref" data-req="SWS_MemIf_00045" href="../../spec/record.html?id=SWS_MemIf_00045">[SWS_MemIf_00045]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00040" href="../../spec/record.html?id=SWS_MemIf_00040">[SWS_MemIf_00040]</a>. Parallele Aufrufe aus mehreren Kontexten müssen daher ausgeschlossen werden. Da Status und Jobergebnis je Modul nur den letzten Auftrag widerspiegeln, sollte der Aufrufer einen neuen Auftrag erst nach Abschluss des vorigen erteilen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_6_Fls_GetJobResult.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_6_Fls_GetJobResult">SWS Fls S. 36</a>.</p>
<p>Das Memory-Mapping-Beispiel eines ICC2-Clusters „MEM“ führt MemIf gemeinsam mit dem NvM. Dort ist <code>MemIf_SetMode</code> als <code>BswCalledEntity</code> modelliert, und MemIf hat das Section-Präfix <code>MEMIF</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_7_3_3_Code_Section_in_ICC2_cluster.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_7_3_3_Code_Section_in_ICC2_cluster">SWS MemoryMapping S. 50</a>. Der BSW Distribution Guide nennt MEMIF neben FLS und FEE als Beispiel für „Type I“; der Geltungsbereich lässt sich per <code>SwAddrMethod</code> mit lokalem Scope auf einen Kern begrenzen <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_2_8.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_2_8">EXP BSWDistributionGuide S. 31</a>. Vermutlich ist MemIf in Mehrkernsystemen damit kernlokal zu betreiben.</p>

<h4>Verhalten im Fehlerfall</h4>
<p>MemIf kennt zwei Entwicklungsfehler. <code>MEMIF_E_PARAM_DEVICE</code> (0x01) steht für einen falschen DeviceIndex, <code>MEMIF_E_PARAM_POINTER</code> (0x02) für einen NULL-Zeiger <a class="spec-record-ref" data-req="SWS_MemIf_00006" href="../../spec/record.html?id=SWS_MemIf_00006">[SWS_MemIf_00006]</a>. Gemeldet werden sie über das optionale <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_MemIf_00048" href="../../spec/record.html?id=SWS_MemIf_00048">[SWS_MemIf_00048]</a>. Spezifische Fehlercodes werden laut Tracing-Tabelle nicht über die API zurückgegeben <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_6_Requirements_Tracing.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_6_Requirements_Tracing">SWS MemIf S. 12</a>.</p>
<p>Ist die Entwicklungsfehlererkennung aktiv und wird ein Fehler erkannt, liefern Read, Write, InvalidateBlock und EraseImmediateBlock <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_MemIf_00039" href="../../spec/record.html?id=SWS_MemIf_00039">[SWS_MemIf_00039]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00040" href="../../spec/record.html?id=SWS_MemIf_00040">[SWS_MemIf_00040]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00044" href="../../spec/record.html?id=SWS_MemIf_00044">[SWS_MemIf_00044]</a> <a class="spec-record-ref" data-req="SWS_MemIf_00046" href="../../spec/record.html?id=SWS_MemIf_00046">[SWS_MemIf_00046]</a>. <code>MemIf_GetJobResult</code> liefert in diesem Fall <code>MEMIF_JOB_FAILED</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_5_MemIf_GetJobResult.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_5_MemIf_GetJobResult">SWS MemIf S. 21</a>. Sonst wird der Wert des Moduls unverändert weitergereicht.</p>
