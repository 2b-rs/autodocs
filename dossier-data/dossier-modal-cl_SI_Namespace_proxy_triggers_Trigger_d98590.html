<h4>Context</h4>
<p>The generated class <code>&lt;SI-Namespace&gt;::proxy::triggers::&lt;Trigger&gt;</code> represents the client-side interface for a trigger element defined in a <code>ServiceInterface</code> in the role <em>trigger</em> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=39">AUTOSAR AP SWS CommunicationManagement p. 39</a>. In contrast to event-based mechanisms (Events), which transmit serialized payload data, a trigger serves solely to notify about the occurrence of an event without application data. The interaction partners include the proxy application (client), the Communication Management middleware (<code>ara::com</code>) for transmitting signals, and optional execution contexts (<code>ExecutorT</code>) for decoupling asynchronous tasks <a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>, <a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a>. Furthermore, an interface to End-to-End protection (E2E) exists for the purpose of receiving transport errors <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>.</p>

<h4>Lifecycle</h4>
<p>The trigger instance is presumably firmly bound as a member object to the lifetime of the higher-level service proxy and is instantiated and released together with it. The class is declared as <code>final</code>. The functional lifecycle is determined significantly by the subscription state (<code>ara::com::SubscriptionState</code>) <a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>:</p>
<ul>
<li><strong>Not subscribed:</strong> Initial state of the instance. A call to <code>Unsubscribe()</code> in this state has no effect and returns immediately <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>.</li>
<li><strong>Subscription requested:</strong> Calling <code>Subscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a> initiates the subscription with Communication Management. The state transitions to <code>kSubscriptionPending</code> or directly to <code>kSubscribed</code>. If the trigger is already in <code>kSubscribed</code> or <code>kSubscriptionPending</code> when <code>Subscribe()</code> is called, the method returns without taking action <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>.</li>
<li><strong>Subscribed (<code>kSubscribed</code>):</strong> Trigger signals from the service provider are actively accepted. The current state can be queried synchronously via <code>GetSubscriptionState()</code> <a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>. State changes can be tracked asynchronously via a registered handler <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>.</li>
<li><strong>Unsubscription:</strong> Calling <code>Unsubscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a> stops delivery and returns the trigger to the unsubscribed state.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical call sequence for using a proxy trigger is divided into configuration, subscription, signal processing, and cleanup:</p>
<ol>
<li><strong>Handler registration:</strong> If needed, the application registers notification callbacks in advance. Via <code>SetReceiveHandler()</code>, a parameterless function is registered that is called by Communication Management when a trigger arrives <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>. For execution in a dedicated thread context, a template overload with <code>ExecutorT</code> is available <a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>. Subscription status changes can be monitored via <code>SetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>, <a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a>, while transport errors are reported via <code>SetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>, <a class="spec-record-ref" data-req="SWS_CM_00107" href="../spec/record.html?id=SWS_CM_00107">[SWS_CM_00107]</a>.</li>
<li><strong>Activate subscription:</strong> The application calls <code>Subscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a> to start signaling.</li>
<li><strong>Signal retrieval and counter update:</strong> When a trigger arrives, Communication Management calls the <code>TriggerReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>. Within the handler or cyclically, the application calls <code>GetNewTriggers()</code> <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>. This method reads out the number of triggers that have arrived since the previous call and updates the counter. A return value of <code>0</code> indicates that no new trigger has been received since then <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>.</li>
<li><strong>Stop subscription and deregister:</strong> To stop reception, the application calls <code>Unsubscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>. Registered handlers can be reset via <code>UnsetReceiveHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_11614" href="../spec/record.html?id=SWS_CM_11614">[SWS_CM_11614]</a>, <code>UnsetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01108" href="../spec/record.html?id=SWS_CM_01108">[SWS_CM_01108]</a>, and <code>UnsetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00108" href="../spec/record.html?id=SWS_CM_00108">[SWS_CM_00108]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The methods of the trigger class are mostly declared with <code>noexcept</code> and designated as exception-safe <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>, <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>, <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>, <a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>. The following error cases and violations are defined:</p>
<ul>
<li><strong>Invalid callback (<code>InvalidHandlerViolation</code>):</strong> If a non-existent or empty callable object (null handler) is passed to <code>SetReceiveHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>, <a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>, <code>SetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>, <a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a>, or <code>SetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>, <a class="spec-record-ref" data-req="SWS_CM_00107" href="../spec/record.html?id=SWS_CM_00107">[SWS_CM_00107]</a>, the system reports an <code>InvalidHandlerViolation</code>.</li>
<li><strong>Missing access permissions (<code>InsufficientPermissionsViolation</code>):</strong> If grant enforcement denies access permission to the trigger element, the call to <code>Subscribe()</code> is rejected with an <code>InsufficientPermissionsViolation</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>.</li>
<li><strong>Exception safety when removing the receive handler:</strong> In contrast to the methods <code>UnsetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01108" href="../spec/record.html?id=SWS_CM_01108">[SWS_CM_01108]</a> and <code>UnsetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00108" href="../spec/record.html?id=SWS_CM_00108">[SWS_CM_00108]</a>, <code>UnsetReceiveHandler()</code> is specified as <em>not exception safe</em> <a class="spec-record-ref" data-req="SWS_CM_11614" href="../spec/record.html?id=SWS_CM_11614">[SWS_CM_11614]</a>.</li>
<li><strong>Transport errors at network level:</strong> Errors during end-to-end transmission are signaled asynchronously via the handler registered via <code>SetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>.</li>
