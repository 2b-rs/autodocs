<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::CryptoObject</code> serves as a common base interface for all cryptographic objects that can be recognized and managed by a <code>CryptoProvider</code>. Through inheritance from <code>ara::crypto::Serializable</code>, it defines the uniform foundation for serializable objects within the cryptography architecture of the AUTOSAR Adaptive Platform, such as key material and associated metadata.</p>
<p>The interface bundles basic identification and control properties for cryptographic resources. The primary interaction partners include:</p>
<ul>
<li><strong>Application</strong>: Uses the interface to query algorithm identifiers and usage restrictions as well as to initiate storage in a key slot.</li>
<li><strong><code>CryptoProvider</code></strong>: Provides the execution context for cryptographic objects. According to <a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>, there is a logical binding to the respective provider; incompatibilities occur if target structures are assigned to a different provider.</li>
<li><strong><code>WriteableKeySlot</code></strong>: Represents the underlying storage location to which the object is persistently transferred via <code>Save()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle and memory management of a <code>CryptoObject</code> follow the specifications for adaptive platform resources:</p>
<ul>
<li><strong>Ownership</strong>: For instance management, the class provides the type alias <code>Sptr</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20501" href="../spec/record.html?id=SWS_CRYPT_20501">[SWS_CRYPT_20501]</a>), which is defined as <code>std::shared_ptr&lt;CryptoObject&gt;</code>. This enables the shared, reference-counted use of objects across component boundaries.</li>
<li><strong>Creation</strong>: Since it is a purely virtual interface, <code>CryptoObject</code> cannot be instantiated directly; the creation of concrete instances is likely typically done via factory methods of a <code>CryptoProvider</code>.</li>
<li><strong>Persistence</strong>: A <code>CryptoObject</code> can be kept in a volatile state at runtime or stored permanently in a <code>WriteableKeySlot</code> via the <code>Save()</code> method (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>). Upon successful execution, both the key material and the metadata are written; data previously present in the slot is completely overwritten in the process.</li>
<li><strong>Concurrency and safety</strong>: All methods (<code>GetAlgId()</code>, <code>GetAllowedUsage()</code>, <code>Save()</code>) are declared as <code>noexcept</code> and specify exception safety (<code>exception safe</code>) as well as thread safety (<code>thread-safe</code>) (<a class="spec-record-ref" data-req="SWS_CRYPT_20505" href="../spec/record.html?id=SWS_CRYPT_20505">[SWS_CRYPT_20505]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50092" href="../spec/record.html?id=SWS_CRYPT_50092">[SWS_CRYPT_50092]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>). Parallel calls from multiple threads are therefore permitted without external synchronization.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical use case consists of validating the object properties and subsequently storing them in a permanent key slot:</p>
<ol>
<li><strong>Query algorithm</strong>: The application calls <code>GetAlgId()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20505" href="../spec/record.html?id=SWS_CRYPT_20505">[SWS_CRYPT_20505]</a>) to obtain the algorithm identifier as <code>ara::crypto::AlgIdString</code> within a <code>ara::core::Result</code>.</li>
<li><strong>Check usage rules</strong>: The <code>AllowedUsageFlags</code> are determined using <code>GetAllowedUsage()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50092" href="../spec/record.html?id=SWS_CRYPT_50092">[SWS_CRYPT_50092]</a>). Prior to storage, it must be checked whether the permission <code>kAllowPersist</code> is included (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
<li><strong>Perform storage</strong>: If the object meets all criteria, the <code>Save()</code> method is called, passing a <code>WriteableKeySlot::Sptr</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
<li><strong>Check result</strong>: The method returns a <code>ara::core::Result&lt;void&gt;</code>, which can be used to evaluate success or specific error codes.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Pure state checking via query methods differs significantly from resource-related write operations:</p>
<ul>
<li><strong>Query methods</strong>: No standardized error codes are defined for <code>GetAlgId()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20505" href="../spec/record.html?id=SWS_CRYPT_20505">[SWS_CRYPT_20505]</a>) and <code>GetAllowedUsage()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50092" href="../spec/record.html?id=SWS_CRYPT_50092">[SWS_CRYPT_50092]</a>).</li>
<li><strong>Incompatibility (<code>kIncompatibleObject</code>)</strong>: If <code>Save()</code> fails because the key does not match the target slot (e.g. incompatible <code>AlgId</code> or origin from a different <code>CryptoProvider</code>), <code>ara::crypto::CryptoErrc::kIncompatibleObject</code> is returned (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
<li><strong>Usage violation (<code>kUsageViolation</code>)</strong>: If the permitted usage of the key does not include the right <code>kAllowPersist</code>, persistence is refused with <code>ara::crypto::CryptoErrc::kUsageViolation</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
<li><strong>Busy resource (<code>kBusyResource</code>)</strong>: If the write operation cannot be performed temporarily, <code>Save()</code> returns the error <code>ara::crypto::CryptoErrc::kBusyResource</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>).</li>
<li><strong>Rollback guarantee</strong>: For all errors with <code>Save()</code>, rollback semantics apply (<code>rollback_semantics</code>) (<a class="spec-record-ref" data-req="SWS_CRYPT_20517" href="../spec/record.html?id=SWS_CRYPT_20517">[SWS_CRYPT_20517]</a>), so that the original state of the key slot remains unchanged in case of failures.</li>
</ul>
