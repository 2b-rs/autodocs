<h4>Context</h4>
<p>
The C++ class <code>&lt;SI-Namespace&gt;::proxy::fields::&lt;Field&gt;</code> represents the client-side representation of a field declared in a service interface. In the AUTOSAR Adaptive Platform, a field combines properties of a queryable state value, a modifiable state value, and an event stream for notification of value changes.
</p>
<p>
The class interacts primarily with the calling application logic and the underlying Communication Management. Depending on the modeling in the service interface, the class provides different interface elements:
</p>
<ul>
<li><strong>Getter:</strong> If <code>Field.hasGetter == TRUE</code> is configured in the interface, the method <code>Get()</code> exists for asynchronous value querying (<a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>; <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">AUTOSAR_AP_EXP_ARAComAPI p. 10</a>).</li>
<li><strong>Setter:</strong> If <code>Field.hasSetter == TRUE</code> is defined, the class provides the method <code>Set()</code> for changing the value (<a class="spec-record-ref" data-req="SWS_CM_00113" href="../spec/record.html?id=SWS_CM_00113">[SWS_CM_00113]</a>; <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">AUTOSAR_AP_EXP_ARAComAPI p. 10</a>).</li>
<li><strong>Notifier:</strong> Incoming notifications about changed field values are provided in the local data cache via subscription-based reception mechanisms (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>, <a class="spec-record-ref" data-req="SWS_CM_11610" href="../spec/record.html?id=SWS_CM_11610">[SWS_CM_11610]</a>).</li>
</ul>
<p>
In addition, the class provides monitoring functions for End-to-End protection (E2E): The state of the E2E state machine can be retrieved separately for the getter (<a class="spec-record-ref" data-req="SWS_CM_00145" href="../spec/record.html?id=SWS_CM_00145">[SWS_CM_00145]</a>), the setter (<a class="spec-record-ref" data-req="SWS_CM_00146" href="../spec/record.html?id=SWS_CM_00146">[SWS_CM_00146]</a>), and the notifier (<a class="spec-record-ref" data-req="SWS_CM_11612" href="../spec/record.html?id=SWS_CM_11612">[SWS_CM_11612]</a>).
</p>

<h4>Lifecycle</h4>
<p>
The lifetime of an instance of <code>&lt;SI-Namespace&gt;::proxy::fields::&lt;Field&gt;</code> is presumably bound to the lifetime of the parent service proxy instance that aggregates the field.
</p>
<p>
An explicit subscription lifecycle exists for the notifier functionality. The states include <code>kNotSubscribed</code>, <code>kSubscriptionPending</code>, and <code>kSubscribed</code>. Calling <code>Subscribe()</code> requests the subscription, specifying the buffer size <code>maxSampleCount</code> (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>). If the field is already in states <code>kSubscribed</code> or <code>kSubscriptionPending</code> with an unchanged quota upon this call, the call has no effect (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>).
</p>
<p>
The current subscription state can be queried using <code>GetSubscriptionState()</code> (<a class="spec-record-ref" data-req="SWS_CM_11604" href="../spec/record.html?id=SWS_CM_11604">[SWS_CM_11604]</a>). State transitions can be monitored by registering a handler via <code>SetSubscriptionStateChangeHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_11607" href="../spec/record.html?id=SWS_CM_11607">[SWS_CM_00106]</a>, <a class="spec-record-ref" data-req="SWS_CM_11607" href="../spec/record.html?id=SWS_CM_11607">[SWS_CM_11607]</a>), optionally also with a custom executor (<a class="spec-record-ref" data-req="SWS_CM_11608" href="../spec/record.html?id=SWS_CM_11608">[SWS_CM_11608]</a>). The handler can be removed again via <code>UnsetSubscriptionStateChangeHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_11609" href="../spec/record.html?id=SWS_CM_11609">[SWS_CM_11609]</a>).
</p>
<p>
Notifications are terminated by <code>Unsubscribe()</code> (<a class="spec-record-ref" data-req="SWS_CM_11602" href="../spec/record.html?id=SWS_CM_11602">[SWS_CM_11602]</a>). If the field is not subscribed at the time of the call, the method returns without action (<a class="spec-record-ref" data-req="SWS_CM_11602" href="../spec/record.html?id=SWS_CM_11602">[SWS_CM_11602]</a>). For transport errors on the notifier channel, a transport fault handler can also be registered (<a class="spec-record-ref" data-req="SWS_CM_00109" href="../spec/record.html?id=SWS_CM_00109">[SWS_CM_00109]</a>, <a class="spec-record-ref" data-req="SWS_CM_00110" href="../spec/record.html?id=SWS_CM_00110">[SWS_CM_00110]</a>) and deregistered again (<a class="spec-record-ref" data-req="SWS_CM_00126" href="../spec/record.html?id=SWS_CM_00126">[SWS_CM_00126]</a>).
</p>

<h4>Usage Path</h4>
<p>
Typical interaction with the field comprises two separate communication paths:
</p>
<ol>
<li><strong>Subscription and sample processing:</strong>
<ul>
<li>The application reserves buffer slots for updates using <code>Subscribe(maxSampleCount)</code> (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>).</li>
<li>Via <code>SetReceiveHandler()</code>, a callback is registered that is triggered upon arrival of new field data (<a class="spec-record-ref" data-req="SWS_CM_11605" href="../spec/record.html?id=SWS_CM_11605">[SWS_CM_11605]</a>, optionally with an executor according to <a class="spec-record-ref" data-req="SWS_CM_11611" href="../spec/record.html?id=SWS_CM_11611">[SWS_CM_11611]</a>).</li>
<li>In the handler, the application calls <code>GetNewSamples(f, maxNumberOfSamples)</code> to process the new values in the local cache (<a class="spec-record-ref" data-req="SWS_CM_11610" href="../spec/record.html?id=SWS_CM_11610">[SWS_CM_11610]</a>). The number of remaining free cache slots can be queried with <code>GetFreeSampleCount()</code> (<a class="spec-record-ref" data-req="SWS_CM_11603" href="../spec/record.html?id=SWS_CM_11603">[SWS_CM_11603]</a>).</li>
<li>Finally, the handler is deregistered via <code>UnsetReceiveHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_11606" href="../spec/record.html?id=SWS_CM_11606">[SWS_CM_11606]</a>) and the subscription is terminated via <code>Unsubscribe()</code> (<a class="spec-record-ref" data-req="SWS_CM_11602" href="../spec/record.html?id=SWS_CM_11602">[SWS_CM_11602]</a>).</li>
</ul>
</li>
<li><strong>Direct value query and modification:</strong>
<ul>
<li>Using <code>Get()</code>, the application requests the current value and receives a <code>ara::core::Future&lt;FieldType&gt;</code> (<a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>; type alias <code>FieldType</code> according to <a class="spec-record-ref" data-req="SWS_CM_11403" href="../spec/record.html?id=SWS_CM_11403">[SWS_CM_11403]</a>).</li>
<li>Using <code>Set(value)</code>, a new value is transmitted to the service skeleton, which is also synchronized via a <code>ara::core::Future&lt;FieldType&gt;</code> (<a class="spec-record-ref" data-req="SWS_CM_00113" href="../spec/record.html?id=SWS_CM_00113">[SWS_CM_00113]</a>).</li>
</ul>
</li>
</ol>

<h4>Error Scenarios</h4>
<p>
The methods of the class ensure their functionality via error codes, exceptions, and access restrictions:
</p>
<ul>
<li><strong>Communication errors (<code>ComErrc::kCommunicationFailure</code>):</strong>
Reported by the network binding in case of transmission errors or disruptions of secure communication. For <code>Get()</code>, rollback semantics apply (<a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>). For <code>Set()</code>, no rollback semantics exist because, in the case of a communication timeout, the remote state on the server side may remain uncertain (<a class="spec-record-ref" data-req="SWS_CM_00113" href="../spec/record.html?id=SWS_CM_00113">[SWS_CM_00113]</a>).</li>
<li><strong>Minimum send interval violation (<code>ComErrc::kMinimumSendIntervalViolationError</code>):</strong>
Occurs for <code>Get()</code> (<a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>) and <code>Set()</code> (<a class="spec-record-ref" data-req="SWS_CM_00113" href="../spec/record.html?id=SWS_CM_00113">[SWS_CM_00113]</a>) if transmission requests are triggered faster than the configured minimum send interval (<code>minimumSendInterval</code>) allows.</li>
<li><strong>Buffer limits (<code>ComErrc::kMaxSampleCountNotRealizable</code> and <code>ComErrc::kMaxSamplesExceeded</code>):</strong>
<code>Subscribe()</code> fails if the requested sample count cannot be provided by the system (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>). <code>GetNewSamples()</code> reports an error if the maximum sample count is exceeded (<a class="spec-record-ref" data-req="SWS_CM_11610" href="../spec/record.html?id=SWS_CM_11610">[SWS_CM_11610]</a>).</li>
<li><strong>Security violations (<code>InsufficientPermissionsViolation</code>):</strong>
Triggered by grant enforcement if the client does not have sufficient permissions to execute <code>Get()</code> (<a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>), <code>Set()</code> (<a class="spec-record-ref" data-req="SWS_CM_00113" href="../spec/record.html?id=SWS_CM_00113">[SWS_CM_00113]</a>), or <code>Subscribe()</code> (<a class="spec-record-ref" data-req="SWS_CM_11601" href="../spec/record.html?id=SWS_CM_11601">[SWS_CM_11601]</a>).</li>
<li><strong>Invalid callback handlers (<code>InvalidHandlerViolation</code>):</strong>
Thrown if an empty or invalid callable is passed during registration via <code>SetReceiveHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_11605" href="../spec/record.html?id=SWS_CM_11605">[SWS_CM_11605]</a>, <a class="spec-record-ref" data-req="SWS_CM_11611" href="../spec/record.html?id=SWS_CM_11611">[SWS_CM_11611]</a>), <code>SetSubscriptionStateChangeHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_11607" href="../spec/record.html?id=SWS_CM_11607">[SWS_CM_11607]</a>, <a class="spec-record-ref" data-req="SWS_CM_11608" href="../spec/record.html?id=SWS_CM_11608">[SWS_CM_11608]</a>), or <code>SetTransportFaultConditionHandler()</code> (<a class="spec-record-ref" data-req="SWS_CM_00109" href="../spec/record.html?id=SWS_CM_00109">[SWS_CM_00109]</a>, <a class="spec-record-ref" data-req="SWS_CM_00110" href="../spec/record.html?id=SWS_CM_00110">[SWS_CM_00110]</a>).</li>
</ul>
