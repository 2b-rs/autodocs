<h4>Kontext</h4>
<p>Die Klasse <code>ara::idsm::IdsmErrorDomain</code> fungiert innerhalb der AUTOSAR Adaptive Platform im Modul <code>idsm</code> als zentrale Fehlerdomäne zur Identifikation und Klassifikation systemspezifischer Fehlerzustände des Intrusion Detection System Managers <a class="spec-record-ref" data-req="SWS_AIDSM_10706" href="../spec/record.html?id=SWS_AIDSM_10706">[SWS_AIDSM_10706]</a>. Als finale Spezialisierung der Basisklasse <code>ara::core::ErrorDomain</code> integriert sie das IdsM-Subsystem nahtlos in das einheitliche Fehlerbehandlungsmodell der Adaptive Platform <a class="spec-record-ref" data-req="SWS_AIDSM_10706" href="../spec/record.html?id=SWS_AIDSM_10706">[SWS_AIDSM_10706]</a>. Definiert wird die Klasse im Header <code>ara/idsm/idsm_error_domain.h</code>.</p>
<p>Innerhalb der Fehlerarchitektur verknüpft die Klasse relevante Typdefinitionen für die IdsM-Fehlerbehandlung: Über den Typalias <code>Errc</code> referenziert sie die bereichsspezifische Fehlercode-Enumeration <code>IdsmErrc</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10707" href="../spec/record.html?id=SWS_AIDSM_10707">[SWS_AIDSM_10707]</a>, während der Typalias <code>Exception</code> an die modulspezifische Ausnahmeklasse <code>IdsmException</code> gebunden ist <a class="spec-record-ref" data-req="SWS_AIDSM_10708" href="../spec/record.html?id=SWS_AIDSM_10708">[SWS_AIDSM_10708]</a>. Zudem stellt sie über die überschriebene Methode <code>Name()</code> einen eindeutigen Bezeichner der Domäne für Diagnose- und Protokollierungszwecke bereit <a class="spec-record-ref" data-req="SWS_AIDSM_10710" href="../spec/record.html?id=SWS_AIDSM_10710">[SWS_AIDSM_10710]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung von Instanzen der <code>IdsmErrorDomain</code> unterliegt strengen Einschränkungen. Der Standardkonstruktor ist explizit gelöscht (<code>IdsmErrorDomain() = delete;</code>) <a class="spec-record-ref" data-req="SWS_AIDSM_10709" href="../spec/record.html?id=SWS_AIDSM_10709">[SWS_AIDSM_10709]</a>. Aufrufende Komponenten und Anwendungen können die Klasse daher nicht über eine gewöhnliche Objekterzeugung instanziieren. Die Bereitstellung der Domäneninstanz dürfte in der Praxis vermutlich über eine statische Zugriffsfunktion des Moduls als langlebiges Singleton erfolgen, wie es für Fehlerdomänen in der AUTOSAR Adaptive Platform üblich ist. <a class="interp-q interp-q-open" data-q="Q-f791746dd8b5c3d5" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-f791746dd8b5c3d5" title="Frage Q-f791746dd8b5c3d5 (offen): Die Bereitstellung der Domäneninstanz dürfte über eine statische Zugriffsfunktion erfolgen">Frage Q-f791746dd8b5c3d5 (offen)</a></p>
<p>Als rein funktionale Fehlerdomäne besitzt die Klasse keine veränderlichen internen Zustände und durchläuft keine komplexen Lebenszyklusphasen oder Zustandsübergänge. Hinsichtlich der Nebenläufigkeit sind sämtliche bereitgestellten Methodenaufrufe (<code>Name()</code>, <code>Message()</code> sowie <code>ThrowAsException()</code>) explizit als thread-safe spezifiziert <a class="spec-record-ref" data-req="SWS_AIDSM_10710" href="../spec/record.html?id=SWS_AIDSM_10710">[SWS_AIDSM_10710]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10711" href="../spec/record.html?id=SWS_AIDSM_10711">[SWS_AIDSM_10711]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10712" href="../spec/record.html?id=SWS_AIDSM_10712">[SWS_AIDSM_10712]</a>. Instanzen der Fehlerdomäne können somit ohne zusätzliche externe Synchronisationsmechanismen parallel von mehreren Threads des Systems sicher genutzt werden.</p>

<h4>Nutzungspfad</h4>
<p>Im praktischen Einsatz dient die Klasse der Übersetzung und Vermittlung von IdsM-Fehlern innerhalb des Softwaresystems über die folgenden typischen Schritte:</p>
<ul>
<li>Identifikation und Diagnose: Über die Methode <code>Name()</code> kann der Bezeichner der Fehlerdomäne abgefragt werden, um festzustellen, ob ein vorliegender Fehler aus dem IdsM-Modul stammt <a class="spec-record-ref" data-req="SWS_AIDSM_10710" href="../spec/record.html?id=SWS_AIDSM_10710">[SWS_AIDSM_10710]</a>.</li>
<li>Textuelle Fehlermeldung: Bei Vorliegen eines spezifischen Fehlercodes aus <code>IdsmErrc</code> (alias <code>Errc</code>) liefert der Aufruf von <code>Message(errorCode)</code> eine lesbare Beschreibung der Fehlerursache als Zeichenkette zurück <a class="spec-record-ref" data-req="SWS_AIDSM_10707" href="../spec/record.html?id=SWS_AIDSM_10707">[SWS_AIDSM_10707]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10711" href="../spec/record.html?id=SWS_AIDSM_10711">[SWS_AIDSM_10711]</a>.</li>
<li>Ausnahmeauslösung: Benötigt eine Aufrufhierarchie eine Ausnahme statt einer wertbasierten Fehlerbehandlung, wandelt die Methode <code>ThrowAsException(errorCode)</code> einen Fehlercode direkt in die entsprechende Ausnahme um <a class="spec-record-ref" data-req="SWS_AIDSM_10712" href="../spec/record.html?id=SWS_AIDSM_10712">[SWS_AIDSM_10712]</a>.</li>
</ul>
<p>Durch diesen Nutzungspfad unterstützt die Domäne sowohl wertbasierte Fehlerprüfungen über <code>ara::core::ErrorCode</code> als auch klassische ausnahmebasierte Kontrollflüsse im Fehlerfall.</p>

<h4>Fehlerszenarien</h4>
<p>Fehlerbedingungen innerhalb des IdsM-Moduls werden über Werte der Enumeration <code>IdsmErrc</code> repräsentiert, auf welche typisiert über das Alias <code>Errc</code> zugegriffen wird <a class="spec-record-ref" data-req="SWS_AIDSM_10707" href="../spec/record.html?id=SWS_AIDSM_10707">[SWS_AIDSM_10707]</a>. Die Fehlerdomäne steuert, wie diese Fehlercodes in Ausnahmesituationen überführt werden.</p>
<p>Die Methode <code>ThrowAsException(const ara::core::ErrorCode&amp; errorCode)</code> ist mit <code>noexcept(false)</code> annotiert und wirft die zum übergebenen Fehlercode gehörige Exception <a class="spec-record-ref" data-req="SWS_AIDSM_10712" href="../spec/record.html?id=SWS_AIDSM_10712">[SWS_AIDSM_10712]</a>. Bei diesem Typ handelt es sich um <code>IdsmException</code>, welche über den Alias <code>Exception</code> angebunden ist <a class="spec-record-ref" data-req="SWS_AIDSM_10708" href="../spec/record.html?id=SWS_AIDSM_10708">[SWS_AIDSM_10708]</a>. Interpretation: Der Aufruf kehrt im Fehlerfall nicht regulär zurück, sondern erzwingt das Verlassen des aktuellen Ausführungskontexts durch das Auslösen der Ausnahme. <a class="interp-q interp-q-open" data-q="Q-52ca402c6c38a110" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-52ca402c6c38a110" title="Frage Q-52ca402c6c38a110 (offen): Interpretation: ThrowAsException kehrt nicht regulär zurück">Frage Q-52ca402c6c38a110 (offen)</a> Demgegenüber garantieren <code>Name()</code> und <code>Message()</code> durch ihre <code>noexcept</code>-Deklaration, dass während der reinen Namens- oder Meldungsabfrage niemals unbeabsichtigte Ausnahmen geworfen werden können <a class="spec-record-ref" data-req="SWS_AIDSM_10710" href="../spec/record.html?id=SWS_AIDSM_10710">[SWS_AIDSM_10710]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10711" href="../spec/record.html?id=SWS_AIDSM_10711">[SWS_AIDSM_10711]</a>.</p>
