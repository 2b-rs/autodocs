<h4>Context</h4>
<p>In the AUTOSAR Adaptive module <code>diag</code>, the class <code>ara::diag::DataTransferWriteSession</code> serves to encapsulate all variants of diagnostic write transfer (<a class="spec-record-ref" data-req="SWS_DM_01555" href="../spec/record.html?id=SWS_DM_01555">[SWS_DM_01555]</a>). It acts as a standardized link between the diagnostic server instance (<em>Diagnostic Server instance</em>) and application-specific handlers that execute the actual write logic.</p>
<p>The class is embedded particularly in file and data transfer sequences according to UDS. If, for example, a file transfer is requested via <code>RequestFileTransfer</code> with mode <code>ReplaceFile</code> (0x03), the server instance initiates the write preparation (<a class="spec-record-ref" data-req="SWS_DM_01313" href="../spec/record.html?id=SWS_DM_01313">[SWS_DM_01313]</a>). As soon as subsequent data segments arrive via the service <code>TransferData</code> (0x36), the diagnostic server calls the corresponding <code>Write</code> method of the handler that was bound to the <code>DataTransferWriteSession</code> via template constructors (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>). Upon completion of the transfer via <code>RequestTransferExit</code> (0x37), the <code>Exit</code> method of this handler is called accordingly (<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>).</p>

<h4>Lifecycle</h4>
<p>The class <code>ara::diag::DataTransferWriteSession</code> models a unique, non-shareable session instance with clearly defined ownership:</p>
<ul>
<li><strong>Creation:</strong> The parameterless default constructor is deleted (<a class="spec-record-ref" data-req="SWS_DM_01339" href="../spec/record.html?id=SWS_DM_01339">[SWS_DM_01339]</a>). Instantiation takes place instead via template constructors with passing of the respective handler (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=185">SWS Diagnostics p. 185</a>). This ensures that no incompletely configured session objects can be created.</li>
<li><strong>Copy restriction:</strong> The copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01559" href="../spec/record.html?id=SWS_DM_01559">[SWS_DM_01559]</a>) and copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01560" href="../spec/record.html?id=SWS_DM_01560">[SWS_DM_01560]</a>) are explicitly deleted. An instance must not be copied (<em>single not copy-able instance</em>) to prevent multiple executions or inconsistent write states on the same data channel.</li>
<li><strong>Moveability:</strong> Move constructor (<a class="spec-record-ref" data-req="SWS_DM_01557" href="../spec/record.html?id=SWS_DM_01557">[SWS_DM_01557]</a>) and move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01558" href="../spec/record.html?id=SWS_DM_01558">[SWS_DM_01558]</a>) are defined as <code>noexcept = default</code>. They enable the efficient transfer of ownership of an existing session, for example when returning from creation functions.</li>
<li><strong>Destruction:</strong> The destructor is specified as <code>noexcept = default</code> (<a class="spec-record-ref" data-req="SWS_DM_01556" href="../spec/record.html?id=SWS_DM_01556">[SWS_DM_01556]</a>). The session instance is likely released after completion of the transfer and invocation of the exit routine by the diagnostic server.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical sequence of a write data transfer is divided into three consecutive phases:</p>
<ol>
<li><strong>Session establishment:</strong> After arrival of an initial transfer request (e.g., <code>RequestFileTransfer</code> with write reference such as <code>ReplaceFile</code>, <a class="spec-record-ref" data-req="SWS_DM_01313" href="../spec/record.html?id=SWS_DM_01313">[SWS_DM_01313]</a>), the server instance creates the <code>DataTransferWriteSession</code> while registering the target handler (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=185">SWS Diagnostics p. 185</a>).</li>
<li><strong>Blockwise write transfer:</strong> For each incoming UDS message <code>TransferData</code> (0x36), the diagnostic server instance calls the <code>Write</code> method of the handler registered in the session (<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>). This handler processes the transmitted payload data blocks continuously.</li>
<li><strong>Session termination:</strong> If the diagnostic tester terminates the transfer with <code>RequestTransferExit</code> (0x37), the diagnostic server calls the <code>Exit</code> method of the registered handler (<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>) to perform final validations and end the write transaction. Subsequently, the session object is destroyed (<a class="spec-record-ref" data-req="SWS_DM_01556" href="../spec/record.html?id=SWS_DM_01556">[SWS_DM_01556]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>The interface design eliminates typical application errors already at compile time:</p>
<ul>
<li><strong>Missing handler binding:</strong> Since default construction is deleted (<a class="spec-record-ref" data-req="SWS_DM_01339" href="../spec/record.html?id=SWS_DM_01339">[SWS_DM_01339]</a>), no session can be created without a registered handler.</li>
<li><strong>Aliasing conflicts:</strong> The prohibition of copy operations (<a class="spec-record-ref" data-req="SWS_DM_01559" href="../spec/record.html?id=SWS_DM_01559">[SWS_DM_01559]</a>, <a class="spec-record-ref" data-req="SWS_DM_01560" href="../spec/record.html?id=SWS_DM_01560">[SWS_DM_01560]</a>) prevents multiple owners from transmitting write requests in parallel to the same transfer endpoint.</li>
<li><strong>Exception safety:</strong> The move operations (<a class="spec-record-ref" data-req="SWS_DM_01557" href="../spec/record.html?id=SWS_DM_01557">[SWS_DM_01557]</a>, <a class="spec-record-ref" data-req="SWS_DM_01558" href="../spec/record.html?id=SWS_DM_01558">[SWS_DM_01558]</a>) and destruction (<a class="spec-record-ref" data-req="SWS_DM_01556" href="../spec/record.html?id=SWS_DM_01556">[SWS_DM_01556]</a>) provide strict no-throw guarantees through <code>noexcept</code>, so that no secondary exceptions occur even during stack unwinding in error cases.</li>
<li><strong>Runtime errors with data blocks:</strong> If individual write blocks or the termination in the handler fail, error forwarding is likely carried out via return values of the <code>Write</code> or <code>Exit</code> methods to the diagnostic server, which subsequently generates negative UDS responses.</li>
</ul>
