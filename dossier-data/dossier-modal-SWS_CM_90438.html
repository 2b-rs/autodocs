<div class="ai-level" data-ai-level="4">
<p>Die Methode <code>Allocate</code> wird auf Skeleton-Ebene für ein Event aufgerufen (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>; <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=63">AUTOSAR_AP_EXP_ARAComAPI §5.4.1 „Skeleton Class API’s“</a>), um Speicher für die Übertragung von Event-Daten zu allozieren, wenn das Communication Management (ara::com) für die Verwaltung der Daten verantwortlich ist (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>). Sie liefert eine Instanz vom Typ <code>ara::com::SampleAllocateePtr&lt;SampleType&gt;</code> zurück (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>). Dieser Zeigertyp verhält sich konzeptionell wie ein <code>std::unique_ptr&lt;T&gt;</code>, sodass zu jedem Zeitpunkt nur eine Partei Eigentümer des Zeigers ist (<a class="docref internal-spec-ref" href="../spec/record.html?doc=ARAComAPI&amp;page=1">ARAComAPI §6 „Event Allocate/Send sample Binding implementer hint“</a>).</p>

<p>Hinsichtlich der Fehlerbehandlung und Ausnahme-Sicherheit ist <code>Allocate</code> als <em>not exception safe</em> spezifiziert (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>). Die Spezifikation definiert zwei mögliche Verletzungen (Violations):</p>
<ul>
  <li><code>SampleAllocationViolation</code>: Es stehen nicht genügend Speicherressourcen zur Verfügung, um die Daten zu allozieren (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>).</li>
  <li><code>AllocateUsageViolation</code>: Die Allokation erfolgte unzulässigerweise über einen benutzerdefinierten Allokator (<a class="spec-record-ref" data-req="SWS_CM_90438" href="../spec/record.html?id=SWS_CM_90438">[SWS_CM_90438]</a>).</li>
</ul>

<p>Das Konzept hinter <code>Allocate</code> zielt primär auf die Unterstützung von Zero-Copy-Mechanismen ab, insbesondere bei Shared-Memory-basiertem IPC-Transport, wobei eine strikte Synchronisation zwischen Lesern und Schreibern vorausgesetzt wird (<a class="docref internal-spec-ref" href="../spec/record.html?doc=ARAComAPI&amp;page=1">ARAComAPI §6 „Event Allocate/Send sample Binding implementer hint“</a>). Implementierer müssen beachten, dass Serialisierungsanforderungen Zero-Copy zunichtemachen können, sofern Datentypen im Deployment nicht binärkompatibel konfiguriert sind oder eine Erkennungslogik dies ausschließt (<a class="docref internal-spec-ref" href="../spec/record.html?doc=ARAComAPI&amp;page=1">ARAComAPI §6 „Event Allocate/Send sample Binding implementer hint“</a>).</p>

<p>Im Zusammenspiel mit dem Senden von Events wird der über <code>Allocate</code> erhaltene Speicherzeiger an <code>Send(ara::com::SampleAllocateePtr&lt;SampleType&gt; data)</code> übergeben (<a class="spec-record-ref" data-req="SWS_CM_90437" href="../spec/record.html?id=SWS_CM_90437">[SWS_CM_90437]</a>). Nach dem Aufruf von <code>Send</code> darf die Dienstanwendung nicht mehr auf die Daten zugreifen, sobald das Communication Management die Daten an alle abonnierenden Anwendungen versendet (<a class="spec-record-ref" data-req="SWS_CM_90437" href="../spec/record.html?id=SWS_CM_90437">[SWS_CM_90437]</a>).</p>
