<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::KeySlot</code> represents a storage slot for cryptographic keys within the crypto architecture of the AUTOSAR Adaptive Platform. It serves as an encapsulation for managing and inspecting persisted or provided key objects, without necessarily exposing cryptographic key values directly in plain text in the application. The direct interaction partners include the consuming application and the responsible <code>ara::crypto::cryp::CryptoProvider</code>, which can be queried via <a class="spec-record-ref" data-req="SWS_CRYPT_30403" href="../spec/record.html?id=SWS_CRYPT_30403">[SWS_CRYPT_30403]</a>.</p>

<p>Via the interface, an application can determine metadata of the key currently in the slot, including the object type via <a class="spec-record-ref" data-req="SWS_CRYPT_50054" href="../spec/record.html?id=SWS_CRYPT_50054">[SWS_CRYPT_50054]</a> and the algorithm identifier via <a class="spec-record-ref" data-req="SWS_CRYPT_50055" href="../spec/record.html?id=SWS_CRYPT_50055">[SWS_CRYPT_50055]</a>. In addition, <a class="spec-record-ref" data-req="SWS_CRYPT_50056" href="../spec/record.html?id=SWS_CRYPT_50056">[SWS_CRYPT_50056]</a> provides a list of all algorithms supported by this specific slot. Furthermore, applications can register observers to be informed of updates to the content.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>KeySlot</code> are designed as long-lived resources whose lifetime is managed via reference counting. The standard alias <code>ara::crypto::cryp::KeySlot::Sptr</code> defines a shared pointer to the interface for this purpose in accordance with <a class="spec-record-ref" data-req="SWS_CRYPT_50151" href="../spec/record.html?id=SWS_CRYPT_50151">[SWS_CRYPT_50151]</a>. To prevent accidental duplication or inconsistent states of the physical or logical key storage, both the copy constructor <a class="spec-record-ref" data-req="SWS_CRYPT_50149" href="../spec/record.html?id=SWS_CRYPT_50149">[SWS_CRYPT_50149]</a> and the move constructor <a class="spec-record-ref" data-req="SWS_CRYPT_50150" href="../spec/record.html?id=SWS_CRYPT_50150">[SWS_CRYPT_50150]</a> are explicitly deleted (<code>=delete</code>). Likewise, the deleted assignment operators prevent subsequent copying <a class="spec-record-ref" data-req="SWS_CRYPT_50147" href="../spec/record.html?id=SWS_CRYPT_50147">[SWS_CRYPT_50147]</a> or moving <a class="spec-record-ref" data-req="SWS_CRYPT_50148" href="../spec/record.html?id=SWS_CRYPT_50148">[SWS_CRYPT_50148]</a>.</p>

<p>Destruction occurs virtually via the standard destructor <a class="spec-record-ref" data-req="SWS_CRYPT_50146" href="../spec/record.html?id=SWS_CRYPT_50146">[SWS_CRYPT_50146]</a> as soon as the last <code>std::shared_ptr</code> reference to the slot is released. Regarding concurrency, the methods of <code>KeySlot</code> are specified as thread-safe, enabling concurrent read and observer operations from multiple threads without external synchronization.</p>

<h4>Usage Path</h4>
<p>A typical usage path comprises checking the slot properties, reading the current content status, and registering for content changes:</p>
<ol>
<li><strong>Determine associated CryptoProvider:</strong> The application calls <code>GetCryptoProvider()</code> to obtain a shared pointer instance of the responsible provider (<a class="spec-record-ref" data-req="SWS_CRYPT_30403" href="../spec/record.html?id=SWS_CRYPT_30403">[SWS_CRYPT_30403]</a>).</li>
<li><strong>Query supported algorithms:</strong> Via <code>GetPossibleAlgIds()</code>, a vector of all algorithm identifiers that the slot can in principle accommodate is retrieved (<a class="spec-record-ref" data-req="SWS_CRYPT_50056" href="../spec/record.html?id=SWS_CRYPT_50056">[SWS_CRYPT_50056]</a>).</li>
<li><strong>Check current key state:</strong> Using <code>GetCryptoObjectType()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50054" href="../spec/record.html?id=SWS_CRYPT_50054">[SWS_CRYPT_50054]</a>) and <code>GetAlgId()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50055" href="../spec/record.html?id=SWS_CRYPT_50055">[SWS_CRYPT_50055]</a>), the application validates whether a matching key is already located in the slot.</li>
<li><strong>Register update observer:</strong> To be notified of modifications or emptying of the slot, the application registers a callback via <code>RegisterUpdateObserver()</code> and passes an application-specific identifier (<a class="spec-record-ref" data-req="SWS_CRYPT_30404" href="../spec/record.html?id=SWS_CRYPT_30404">[SWS_CRYPT_30404]</a>). If the method is called multiple times, the new callback replaces the previous one.</li>
<li><strong>Deregister observer:</strong> If the application no longer requires events, <code>UnregisterUpdateObserver()</code> removes the registered callback (<a class="spec-record-ref" data-req="SWS_CRYPT_30406" href="../spec/record.html?id=SWS_CRYPT_30406">[SWS_CRYPT_30406]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of <code>KeySlot</code> signal error states via the return type <code>ara::core::Result</code>. In doing so, specific standardized error codes occur:</p>
<ul>
<li><strong>Empty key storage (<code>CryptoErrc::kEmptyKeySlot</code>):</strong> If <code>GetCryptoObjectType()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50054" href="../spec/record.html?id=SWS_CRYPT_50054">[SWS_CRYPT_50054]</a>) or <code>GetAlgId()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50055" href="../spec/record.html?id=SWS_CRYPT_50055">[SWS_CRYPT_50055]</a>) is called on a KeySlot that currently contains no key, the call fails and returns <code>ara::crypto::CryptoErrc::kEmptyKeySlot</code>. The operation has rollback semantics, so the state of the slot remains unchanged.</li>
<li><strong>Implementation-specific errors:</strong> The methods <code>RegisterUpdateObserver()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_30404" href="../spec/record.html?id=SWS_CRYPT_30404">[SWS_CRYPT_30404]</a>) and <code>UnregisterUpdateObserver()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_30406" href="../spec/record.html?id=SWS_CRYPT_30406">[SWS_CRYPT_30406]</a>) do not specify fixed standard error codes, but can return implementation-specific error codes in <code>ara::core::Result&lt;void&gt;</code> in case of an error.</li>
<li><strong>Error-free queries:</strong> No standardized error codes are defined for <code>GetCryptoProvider()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_30403" href="../spec/record.html?id=SWS_CRYPT_30403">[SWS_CRYPT_30403]</a>) and <code>GetPossibleAlgIds()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50056" href="../spec/record.html?id=SWS_CRYPT_50056">[SWS_CRYPT_50056]</a>); they normally return the result object with the pointer or the vector.</li>
</ul>
