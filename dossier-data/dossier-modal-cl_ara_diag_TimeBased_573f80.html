<h4>Context</h4>
<p>
The data structure <code>ara::diag::TimeBased</code> represents the configuration parameters for time-based debouncing algorithms in the diagnostic management of the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_DM_00539" href="../spec/record.html?id=SWS_DM_00539">[SWS_DM_00539]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=617">AUTOSAR_AP_SWS_Diagnostics §8.41.3 “Struct: TimeBased”</a>). It is provided via the header file <code>ara/diag/monitor_types.h</code> and defines the time limits <code>failedMs</code> (<a class="spec-record-ref" data-req="SWS_DM_00629" href="../spec/record.html?id=SWS_DM_00629">[SWS_DM_00629]</a>) as well as <code>passedMs</code> (<a class="spec-record-ref" data-req="SWS_DM_00630" href="../spec/record.html?id=SWS_DM_00630">[SWS_DM_00630]</a>).
</p>
<p>
In the system network, <code>ara::diag::TimeBased</code> acts as a link between application-specific fault monitoring and Diagnostic Management (DM). A diagnostic application function uses the structure to pass the required threshold values for time-based fault qualification to the constructor of the class <code>ara::diag::Monitor</code> (<a class="spec-record-ref" data-req="SWS_DM_00550" href="../spec/record.html?id=SWS_DM_00550">[SWS_DM_00550]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=608">AUTOSAR_AP_SWS_Diagnostics §8.40.1.1.2.3 “Monitor(...)”</a>). The actual debouncing logic and the maintenance of the internal timers are handled by the DM, provided that a <code>DiagEventDebounceTimeBased</code> is modeled for the respective event via <code>DiagnosticEventToDebounceAlgorithmMapping</code> (<a class="spec-record-ref" data-req="SWS_DM_00015" href="../spec/record.html?id=SWS_DM_00015">[SWS_DM_00015]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=243">AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.2 “Time-based debouncing”</a>). Based on the configured threshold values, the DM calculates the status <code>kTestFailed</code> as well as the Fault Detection Counter (FDC) (<a class="spec-record-ref" data-req="SWS_DM_00030" href="../spec/record.html?id=SWS_DM_00030">[SWS_DM_00030]</a>).
</p>

<h4>Lifecycle</h4>
<p>
As a plain data struct (POD), <code>ara::diag::TimeBased</code> has no independent dynamic lifecycle and does not manage any operating system resources (<a class="spec-record-ref" data-req="SWS_DM_00539" href="../spec/record.html?id=SWS_DM_00539">[SWS_DM_00539]</a>). The structure is typically instantiated during the initialization phase of the application-specific diagnostic monitor, populated with the desired time values in milliseconds, and passed by value to the constructor of <code>ara::diag::Monitor</code> (<a class="spec-record-ref" data-req="SWS_DM_00550" href="../spec/record.html?id=SWS_DM_00550">[SWS_DM_00550]</a>).
</p>
<p>
Interpretation: Since <code>ara::diag::TimeBased</code> serves merely as a configuration container, the instance does not necessarily remain in the application's memory after the constructor call is completed, but can be discarded. The time thresholds are persistently registered in the DM for the associated event. The functional lifecycle of the debouncing timer maintained in the DM begins at system startup with deterministic initialization to the counter value <code>0</code> (<a class="spec-record-ref" data-req="SWS_DM_00085" href="../spec/record.html?id=SWS_DM_00085">[SWS_DM_00085]</a>). In multithreading scenarios, instantiating the structure requires no synchronization; thread-safe execution is ensured by local creation in the initialization thread prior to registration.
</p>

<h4>Usage Path</h4>
<p>
The typical usage of <code>ara::diag::TimeBased</code> is divided into configuration during initialization and subsequent event reporting at runtime:
</p>
<ol>
<li><strong>Configuration:</strong> The application instantiates <code>ara::diag::TimeBased</code> and sets <code>failedMs</code> (duration in milliseconds until evaluation as defective) (<a class="spec-record-ref" data-req="SWS_DM_00629" href="../spec/record.html?id=SWS_DM_00629">[SWS_DM_00629]</a>) and <code>passedMs</code> (duration until evaluation as healed) (<a class="spec-record-ref" data-req="SWS_DM_00630" href="../spec/record.html?id=SWS_DM_00630">[SWS_DM_00630]</a>).</li>
<li><strong>Monitor creation:</strong> The structure is passed to <code>ara::diag::Monitor::Monitor</code> together with the <code>ara::core::InstanceSpecifier</code> and the initialization callback (<a class="spec-record-ref" data-req="SWS_DM_00550" href="../spec/record.html?id=SWS_DM_00550">[SWS_DM_00550]</a>).</li>
<li><strong>Event monitoring:</strong> At runtime, the application reports status changes via <code>ara::diag::Monitor::ReportMonitorAction</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=244">AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.2 “Time-based debouncing”</a>):
<ul>
<li>If <code>kPrepassed</code> is reported, the DM starts the debouncing timer to qualify the event as <code>kFinallyHealed</code> after <code>passedMs</code> has elapsed (<a class="spec-record-ref" data-req="SWS_DM_00878" href="../spec/record.html?id=SWS_DM_00878">[SWS_DM_00878]</a>).</li>
<li>If <code>kFailed</code> is reported, the DM directly sets the timer to the value of <code>failedMs</code> (or <code>timeFailedThreshold</code>, respectively) and classifies the event as <code>kFinallyDefective</code> (<a class="spec-record-ref" data-req="SWS_DM_00033" href="../spec/record.html?id=SWS_DM_00033">[SWS_DM_00033]</a>).</li>
<li>In the case of a direct <code>kPassed</code>, the DM sets the timer to the corresponding threshold value (<a class="spec-record-ref" data-req="SWS_DM_00036" href="../spec/record.html?id=SWS_DM_00036">[SWS_DM_00036]</a>).</li>
<li>If unstable operating conditions are present, debouncing can be paused with the action <code>kFreezeDebouncing</code> (<a class="spec-record-ref" data-req="SWS_DM_00880" href="../spec/record.html?id=SWS_DM_00880">[SWS_DM_00880]</a>). If a new report <code>kPrepassed</code> or <code>kPrefailed</code> arrives after freezing, the DM resumes the timer from the frozen state (<a class="spec-record-ref" data-req="SWS_DM_00038" href="../spec/record.html?id=SWS_DM_00038">[SWS_DM_00038]</a>).</li>
</ul>
</li>
</ol>

<h4>Error Scenarios</h4>
<p>
When configuring and executing time-based debouncing, specific boundary conditions and protective mechanisms must be observed:
</p>
<ul>
<li><strong>Timer start restrictions:</strong> The timer for qualification as <code>kFinallyHealed</code> is only started upon reporting of <code>kPrepassed</code> if the timer is not already running toward healing and the event is not already qualified as <code>kFinallyHealed</code> (<a class="spec-record-ref" data-req="SWS_DM_00878" href="../spec/record.html?id=SWS_DM_00878">[SWS_DM_00878]</a>). Repeated calls without a state change remain ineffective.</li>
<li><strong>Unsupported counter persistence:</strong> For time-based debouncing, permanent storage of the timer value across system startups is not supported (<code>debounceCounterStorage is not supported for time-based debouncing</code>) (<a class="spec-record-ref" data-req="SWS_DM_00085" href="../spec/record.html?id=SWS_DM_00085">[SWS_DM_00085]</a>). After a restart of the DM, the timer always mandatorily starts at <code>0</code>.</li>
<li><strong>Restriction of freeze requests:</strong> Freezing via <code>kFreezeDebouncing</code> is technically and functionally permitted exclusively for events with time-based debouncing (<a class="spec-record-ref" data-req="SWS_DM_00880" href="../spec/record.html?id=SWS_DM_00880">[SWS_DM_00880]</a>). For other debouncing mechanisms, this action is rejected or not supported by the DM.</li>
<li><strong>Parameter value range:</strong> The time values <code>failedMs</code> and <code>passedMs</code> must be chosen consistently with the higher-level system requirements (<a class="spec-record-ref" data-req="SWS_DM_00629" href="../spec/record.html?id=SWS_DM_00629">[SWS_DM_00629]</a>, <a class="spec-record-ref" data-req="SWS_DM_00630" href="../spec/record.html?id=SWS_DM_00630">[SWS_DM_00630]</a>). Implausibly small values or values set to zero are likely to lead to an immediate change in fault states.</li>
</ul>
