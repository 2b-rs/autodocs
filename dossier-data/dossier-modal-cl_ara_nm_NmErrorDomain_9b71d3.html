<p class="ai-level ai-oneliner-lead" data-ai-level="1">Definiert die Fehlerdomäne für das Network Management und übersetzt Fehlercodes in Meldungen oder Exceptions.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Fehlerdomäne <code>ara::nm::NmErrorDomain</code> kapselt die Fehlerbehandlung des Network Managements in der AUTOSAR Adaptive Platform und bindet die Fehlercodes <code>NmErrc</code> sowie die Ausnahmeklasse <code>NmException</code> ein <a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>. Zu ihren Hauptaufgaben gehören das Bereitstellen lesbarer Fehlermeldungen über <code>Message()</code> sowie das kontrollierte Auslösen zugeordneter Ausnahmen über <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. Als zentrale Randbedingung sind die Instanziierung und sämtliche Memberfunktionen threadsicher (<code>thread-safe</code>) implementiert, wodurch eine nebenläufige Fehlerabfrage im Gesamtsystem abgesichert ist.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::nm::NmErrorDomain</code> fungiert innerhalb der AUTOSAR Adaptive Platform als domänenspezifische Fehlerdomäne für das Subsystem des Network Managements <a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>. Als finale Spezialisierung der Basisklasse <code>ara::core::ErrorDomain</code> stellt sie den standardisierten Rahmen zur Identifikation, textuellen Beschreibung und Weiterleitung von Fehlern bereit, die während des Betriebs von Network-Management-Funktionen auftreten können <a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>.</p>
<p>Innerhalb des NM-Fehlerbehandlungskonzepts verknüpft die Klasse konkrete Fehlerursachen mit den allgemeinen Fehlerbehandlungsmechanismen der Laufzeitumgebung. Hierbei definiert die Klasse über Typ-Aliase eine direkte Zuordnung zu den relevanten Typen: Über den Alias <code>Errc</code> bindet sie die zugrunde liegende Aufzählung <code>NmErrc</code> ein, welche die spezifischen Fehlercodes für das Network Management deklariert <a class="spec-record-ref" data-req="SWS_ANM_01103" href="../spec/record.html?id=SWS_ANM_01103">[SWS_ANM_01103]</a>. Gleichzeitig referenziert sie über den Alias <code>Exception</code> die spezialisierte Ausnahmeklasse <code>NmException</code>, wodurch Fehler bei Bedarf in den C++-Ausnahmemechanismus überführt werden können <a class="spec-record-ref" data-req="SWS_ANM_01104" href="../spec/record.html?id=SWS_ANM_01104">[SWS_ANM_01104]</a>. Durch diese Bündelung dient <code>NmErrorDomain</code> als zentrales Bindeglied zwischen den Fehlerzuständen des Moduls und dem fehlerspezifischen Basissystem von <code>ara::core</code>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung einer Instanz von <code>ara::nm::NmErrorDomain</code> erfolgt über den parameterlosen Standardkonstruktor <a class="spec-record-ref" data-req="SWS_ANM_01105" href="../spec/record.html?id=SWS_ANM_01105">[SWS_ANM_01105]</a>. Da die Klasse als <code>final</code> spezifiziert ist, wird eine weitere Untergliederung oder Spezialisierung durch abgeleitete Fehlerdomänen explizit unterbunden <a class="spec-record-ref" data-req="SWS_ANM_01101" href="../spec/record.html?id=SWS_ANM_01101">[SWS_ANM_01101]</a>. Der Konstruktor ist mit <code>noexcept</code> deklariert, womit die Instanziierung der Fehlerdomäne garantiert ohne das Auslösen von Ausnahmen vollzogen wird <a class="spec-record-ref" data-req="SWS_ANM_01105" href="../spec/record.html?id=SWS_ANM_01105">[SWS_ANM_01105]</a>.</p>
<p>Hinsichtlich der Besitzverhältnisse dürfte eine Instanz dieser Fehlerdomäne typischerweise als langlebiges globales Objekt im Speicher existieren, um über Referenzen in Fehlercode-Objekten dauerhaft verfügbar zu sein. Ein wesentliches Merkmal im Lebenszyklus ist das Nebenläufigkeitsverhalten: Sowohl die Konstruktion der Instanz <a class="spec-record-ref" data-req="SWS_ANM_01105" href="../spec/record.html?id=SWS_ANM_01105">[SWS_ANM_01105]</a> als auch sämtliche Schnittstellenfunktionen wie die Namensabfrage <a class="spec-record-ref" data-req="SWS_ANM_01106" href="../spec/record.html?id=SWS_ANM_01106">[SWS_ANM_01106]</a>, die Meldungserzeugung <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a> und das Auslösen von Ausnahmen <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a> sind vollumfänglich threadsicher (<code>thread-safe</code>) ausgelegt. Da Instanzen von <code>NmErrorDomain</code> keinen veränderlichen Zustand aufweisen, können sie ohne zusätzliche Synchronisationsmaßnahmen nebenläufig aus mehreren Threads genutzt werden.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Nutzungspfad setzt ein, sobald im Network Management ein Fehlerzustand analysiert, protokolliert oder in eine Ausnahme überführt werden soll. Die Fehlerdomäne stellt hierfür die grundlegenden Identifikations- und Auswertefunktionen bereit.</p>
<p>Zur allgemeinen Identifikation der Domäne kann die Methode <code>Name()</code> aufgerufen werden, welche den Namen der Domäne als konstanten Zeichenkettenzeiger zurückliefert <a class="spec-record-ref" data-req="SWS_ANM_01106" href="../spec/record.html?id=SWS_ANM_01106">[SWS_ANM_01106]</a>. Wenn eine Anwendung oder ein Basissystem die textuelle Bedeutung eines aufgetretenen Fehlercodes ermitteln möchte, wird die Methode <code>Message()</code> unter Übergabe des Fehlercodes aufgerufen <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a>. Diese Methode gibt die zugehörige Fehlermeldung als <code>const char*</code> zurück und garantiert durch ihre <code>noexcept</code>-Deklaration, dass der Diagnosevorgang selbst ausnahmesicher bleibt <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a>.</p>
<p>Erfordert der Kontrollfluss das Werfen einer systemspezifischen Ausnahme, wird die Methode <code>ThrowAsException()</code> herangezogen <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. Diese Funktion nimmt ein Fehlerobjekt vom Typ <code>ara::core::ErrorCode</code> entgegen und wirft die dazu passende Exception vom Typ <code>NmException</code> <a class="spec-record-ref" data-req="SWS_ANM_01104" href="../spec/record.html?id=SWS_ANM_01104">[SWS_ANM_01104]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. Der Aufruf dürfte in der Praxis primär indirekt über entsprechende Hilfsmethoden von Fehlerobjekten erfolgen.</p>

<h4>Fehlerszenarien</h4>
<p>Im Rahmen der Fehlerbehandlung deckt die Domäne alle Fehlerfälle des Moduls ab, die durch den Enumerations-Typ <code>NmErrc</code> über den Alias <code>Errc</code> definiert werden <a class="spec-record-ref" data-req="SWS_ANM_01103" href="../spec/record.html?id=SWS_ANM_01103">[SWS_ANM_01103]</a>. Die Domäne selbst ist darauf ausgelegt, die Auswertung von Fehlern deterministisch abzusichern.</p>
<p>Bei der Ermittlung von Textmeldungen über <code>Message()</code> stellt die Deklaration als <code>noexcept</code> sicher, dass selbst bei ungültigen Fehlercodes keine unvorhergesehenen Ausnahmen geworfen werden <a class="spec-record-ref" data-req="SWS_ANM_01107" href="../spec/record.html?id=SWS_ANM_01107">[SWS_ANM_01107]</a>. Das einzige vorgesehene Szenario, in dem die Klasse aktiv eine Ausnahme auslöst, ist der explizite Aufruf von <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. Über die Deklaration <code>noexcept(false)</code> signalisiert die Methode, dass sie das Programm zwingend in einen Ausnahmebehandlungspfad überführt, indem sie eine Instanz von <code>NmException</code> wirft <a class="spec-record-ref" data-req="SWS_ANM_01104" href="../spec/record.html?id=SWS_ANM_01104">[SWS_ANM_01104]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01108" href="../spec/record.html?id=SWS_ANM_01108">[SWS_ANM_01108]</a>. Aufrufende Komponenten müssen daher sicherstellen, dass solche Aufrufe bei Bedarf durch entsprechende Ausnahmeblöcke gefangen werden.</p>
