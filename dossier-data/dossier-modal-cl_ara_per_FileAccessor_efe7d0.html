<h4>Context</h4>
<p>In the Persistency module of the AUTOSAR Adaptive Platform, class <code>ara::per::FileAccessor</code> forms the common base for file-based access classes. It bundles the methods for querying and modifying the current file position as well as for determining the current file size, and is extended by the specialized classes <code>ReadAccessor</code> and <code>WriteAccessor</code>. Through this abstraction, read and write file accesses share the same standardized interface for position management, avoiding redundant control logic.</p>
<p>Application components typically interact with <code>FileAccessor</code> via instances of the derived access objects, but can handle position- and state-related checks generically via the common base interface.</p>

<h4>Lifecycle</h4>
<p>The lifecycle management of <code>ara::per::FileAccessor</code> is strictly regulated and prevents direct instantiations as well as any duplication. The parameterless default constructor is explicitly deleted <a class="spec-record-ref" data-req="SWS_PER_00589" href="../spec/record.html?id=SWS_PER_00589">[SWS_PER_00589]</a>. Likewise, the copy constructor <a class="spec-record-ref" data-req="SWS_PER_00592" href="../spec/record.html?id=SWS_PER_00592">[SWS_PER_00592]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_PER_00593" href="../spec/record.html?id=SWS_PER_00593">[SWS_PER_00593]</a> are deleted, so that instances can be copied neither shallowly nor deeply.</p>
<p>Furthermore, the move constructor <a class="spec-record-ref" data-req="SWS_PER_00590" href="../spec/record.html?id=SWS_PER_00590">[SWS_PER_00590]</a> and the move assignment operator <a class="spec-record-ref" data-req="SWS_PER_00591" href="../spec/record.html?id=SWS_PER_00591">[SWS_PER_00591]</a> are also deleted. Interpretation: Since all default, copy, and move operations are deleted, <code>FileAccessor</code> is likely to act exclusively as a protected base class whose instantiation and lifetime are bound to the concrete child classes <code>ReadAccessor</code> and <code>WriteAccessor</code>, respectively. This prevents accidental slicing during polymorphic handling.</p>
<p>Resources are cleaned up via the virtual destructor <code>~FileAccessor()</code> <a class="spec-record-ref" data-req="SWS_PER_00594" href="../spec/record.html?id=SWS_PER_00594">[SWS_PER_00594]</a>. The declaration as <code>virtual</code> and <code>noexcept</code> ensures that during destruction via pointers or references to the base class, the destructors of the derived classes are called properly and in an exception-safe manner <a class="spec-record-ref" data-req="SWS_PER_00594" href="../spec/record.html?id=SWS_PER_00594">[SWS_PER_00594]</a>.</p>
<p>With regard to concurrency, the destructor as well as all methods are specified as not thread-safe (<em>not thread-safe</em>) <a class="spec-record-ref" data-req="SWS_PER_00162" href="../spec/record.html?id=SWS_PER_00162">[SWS_PER_00162]</a>, <a class="spec-record-ref" data-req="SWS_PER_00424" href="../spec/record.html?id=SWS_PER_00424">[SWS_PER_00424]</a>, <a class="spec-record-ref" data-req="SWS_PER_00107" href="../spec/record.html?id=SWS_PER_00107">[SWS_PER_00107]</a>, <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>, <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>, <a class="spec-record-ref" data-req="SWS_PER_00594" href="../spec/record.html?id=SWS_PER_00594">[SWS_PER_00594]</a>. If multiple threads access the same instance concurrently, the calling application must ensure external synchronization.</p>

<h4>Usage Path</h4>
<p>A typical usage path of <code>FileAccessor</code> comprises determining the file state, navigating to defined positions, and validating file boundaries:</p>
<ol>
<li><strong>Size query:</strong> Via <code>GetSize()</code>, the application determines the current total size of the file in bytes <a class="spec-record-ref" data-req="SWS_PER_00424" href="../spec/record.html?id=SWS_PER_00424">[SWS_PER_00424]</a>. This provides the frame of reference for valid positions.</li>
<li><strong>Position query:</strong> By means of <code>GetPosition()</code>, the application queries the current position in bytes relative to the beginning of the file <a class="spec-record-ref" data-req="SWS_PER_00162" href="../spec/record.html?id=SWS_PER_00162">[SWS_PER_00162]</a>. The reported position can also be at the end of the file.</li>
<li><strong>Absolute positioning:</strong> With <code>SetPosition()</code>, the application sets the file pointer to an absolute byte position from the beginning of the file <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>.</li>
<li><strong>Relative shift:</strong> Alternatively, <code>MovePosition()</code> enables moving the position relative to an origin <code>origin</code> <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>:
<ul>
<li><code>Origin::kBeginning</code>: Positive offset from the beginning of the file.</li>
<li><code>Origin::kCurrent</code>: Positive or negative offset from the current position; an offset of <code>0</code> leaves the position unchanged.</li>
<li><code>Origin::kEnd</code>: Negative offset relative to the end of the file; an offset of <code>0</code> sets the position exactly to the end of the file.</li>
</ul>
Upon a successful call, the new position from the beginning of the file is provided in the return value <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>.</li>
<li><strong>End-of-file check:</strong> Via <code>IsEof()</code>, the application checks whether the current position has reached the end of the file <a class="spec-record-ref" data-req="SWS_PER_00107" href="../spec/record.html?id=SWS_PER_00107">[SWS_PER_00107]</a>. The function returns <code>true</code> if the pointer is at the end of the file, otherwise <code>false</code>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error handling in <code>ara::per::FileAccessor</code> follows the error-model-based approach of the AUTOSAR Adaptive Platform via <code>ara::core::Result</code>. All methods are declared as <code>noexcept</code> and exception-safe (<em>exception safe</em>), which is why no C++ exceptions are thrown <a class="spec-record-ref" data-req="SWS_PER_00162" href="../spec/record.html?id=SWS_PER_00162">[SWS_PER_00162]</a>, <a class="spec-record-ref" data-req="SWS_PER_00424" href="../spec/record.html?id=SWS_PER_00424">[SWS_PER_00424]</a>, <a class="spec-record-ref" data-req="SWS_PER_00107" href="../spec/record.html?id=SWS_PER_00107">[SWS_PER_00107]</a>, <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>, <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>.</p>
<p>Errors primarily occur when range boundaries are violated:</p>
<ul>
<li><strong>Exceedance during absolute positioning:</strong> If the application passes a value to <code>SetPosition()</code> that lies beyond the end of the file, the call fails and returns the error code <code>PerErrc::kInvalidPosition</code> <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>.</li>
<li><strong>Boundary violation during relative shift:</strong> If the calculation in <code>MovePosition()</code> results in a position less than zero or beyond the end of the file, the operation is rejected with <code>PerErrc::kInvalidPosition</code> <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>.</li>
<li><strong>Rollback semantics:</strong> In the event of an error, both <code>SetPosition()</code> and <code>MovePosition()</code> guarantee strict rollback semantics (<em>rollback_semantics</em>): The current file position is not modified in the event of an error <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>, <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>.</li>
<li><strong>Vendor-specific errors:</strong> In addition to <code>PerErrc::kInvalidPosition</code>, vendor-specific error codes can also be returned in <code>ara::core::Result</code> <a class="spec-record-ref" data-req="SWS_PER_00163" href="../spec/record.html?id=SWS_PER_00163">[SWS_PER_00163]</a>, <a class="spec-record-ref" data-req="SWS_PER_00164" href="../spec/record.html?id=SWS_PER_00164">[SWS_PER_00164]</a>.</li>
</ul>
