<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient dem gesicherten Entpacken und Importieren geschützter kryptografischer Schlüssel und Daten in einer Anwendung.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle ermöglicht das sichere Entpacken und Importieren geschützter kryptografischer Daten und Schlüssel mithilfe eines konfigurierten Transportschlüssels <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>. Das entpackte Schlüsselmaterial kann entweder direkt in einen persistenten Schlüsselsteckplatz geschrieben oder typisiert als Schlüsselobjekt in den Speicher geladen werden <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>. Sämtliche Methoden arbeiten threadsicher und folgen einer strikten Rollback-Fehlersemantik, während <code>Reset</code> das rückstandslose Löschen interner Puffer gewährleistet <a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::crypto::cryp::ProtectedKeyImportCtx</code> stellt einen kryptografischen Kontext bereit, um geschützte Datenstrukturen wie geheimes Schlüsselmaterial sicher in das System zu importieren und zu entpacken. Der Kontext fungiert als Vermittler zwischen einer anfordernden Anwendung, einem Schutzmechanismus auf Basis eines Transportschlüssels und den Zielstrukturen der AUTOSAR-Kryptografie. Eingehende serialisierte Datenpakete werden durch den Kontext authentifiziert, entschlüsselt und geparst <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>. Als Quellen für den benötigten Transportschlüssel dienen entweder eigenständige symmetrische Schlüsselobjekte <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> oder Schlüsselsteckplätze eines Schlüsselspeichers <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>. Als Senke können entpackte Schlüsselobjekte direkt an die aufrufende Anwendung übergeben oder unmittelbar in einen beschreibbaren Schlüsselsteckplatz serialisiert werden <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Der Kontext wird für den gemeinsamen Zugriff üblicherweise über den bereitgestellten Smart-Pointer-Typ <code>Sptr</code> verwaltet <a class="spec-record-ref" data-req="SWS_CRYPT_50085" href="../spec/record.html?id=SWS_CRYPT_50085">[SWS_CRYPT_50085]</a>; Instanzen dürften dabei von einer zuständigen Krypto-Treiberkomponente bereitgestellt werden. Vor der eigentlichen Verarbeitung befindet sich der Kontext in einem unkonfigurierten Initialzustand, in dem noch kein Transportschlüssel zugewiesen ist. Die Zuweisung eines Transportschlüssels erfolgt über die Methode <code>SetKey</code>, wodurch der Kontext in den betriebsbereiten Zustand übergeht <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>.</p>
<p>Nach erfolgreicher Ausführung der Operation <code>Import</code> hält der Kontext die entpackten Daten und Metadaten in internen Puffern vor, sodass der Objekttyp identifiziert und Schlüsselobjekte ausgelesen werden können <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>. Über die Methode <code>Reset</code> wird der Kontext wieder in seinen Initialzustand zurückversetzt: Alle internen Puffer mit zuvor importierten Daten werden vollständig bereinigt und der hinterlegte Transportschlüssel wird entfernt <a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>. Sämtliche Schnittstellenmethoden sind als ausnahmesicher und threadsicher spezifiziert, wodurch konkurrierende Zugriffe aus mehreren Ausführungskontexten beherrschbar bleiben <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Arbeitsablauf beginnt mit der Konfiguration des Transportschlüssels. Hierzu ruft die Anwendung <code>SetKey</code> entweder mit einem <code>SymmetricKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> oder mit einem <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a> auf. Im nächsten Schritt wird die Methode <code>Import</code> ausgeführt, der das serialisierte Datenpaket als <code>ReadOnlyMemRegion</code> übergeben wird <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>. Sofern der Schlüssel persistent abgelegt werden soll, kann optional direkt ein <code>WriteableKeySlot::Sptr</code> übergeben werden, in den das entpackte Material geschrieben wird <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>.</p>
<p>Wurde kein Ziel-Slot angegeben oder soll der Schlüssel flüchtig genutzt werden, ermittelt die Anwendung über <code>GetCryptoObjectType</code> die Kategorie des zuletzt importierten Objekts <a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>. Anhand dieses Typs ruft die Anwendung die typgerechte Abrufmethode auf: <code>GetPrivateKey</code> für private Schlüssel <a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>, <code>GetPublicKey</code> für öffentliche Schlüssel <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a> oder <code>GetSymmetricKey</code> für symmetrisches Schlüsselmaterial <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>. Erfordert das verwendete Importprotokoll eine Rückmeldung an den Absender – wie beispielsweise bei den Kontrollblöcken M4 und M5 einer SHE-LoadKey-Sequenz –, kann diese über <code>GetResponse</code> in einen bereitgestellten Puffer geschrieben werden <a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>. Nach Abschluss der Verarbeitungssequenz versetzt ein Aufruf von <code>Reset</code> den Kontext wieder in den Ausgangszustand <a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Tritt während eines Methodenaufrufs ein Fehler auf, greift eine strikte Rollback-Semantik, die den Zustand vor dem Aufruf bewahrt. Bei der Konfiguration via <code>SetKey</code> schlägt der Aufruf mit <code>CryptoErrc::kUsageViolation</code> fehl, falls das Nutzungsflag des Schlüssels die Berechtigung <code>kAllowKeyUnwrapping</code> nicht enthält <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>. Ist das Schlüsselobjekt oder der referenzierte Slot grundsätzlich nicht als Transportschlüssel verwendbar, wird <code>CryptoErrc::kIncompatibleObject</code> gemeldet <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>.</p>
<p>Beim Aufruf von <code>Import</code> führen Größenabweichungen der Eingabedaten zu <code>CryptoErrc::kInvalidInputSize</code> und Formatverletzungen zu <code>CryptoErrc::kInvalidArgument</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>. Schlägt die Integritäts- oder Authentizitätsprüfung der Schutzschicht (z. B. durch einen ungültigen Message Authentication Code oder eine fehlerhafte Signatur) fehl, liefert der Aufruf <code>CryptoErrc::kAuthTagNotValid</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>. Ist die Kryptokomponente vorübergehend belegt, wird dies über <code>CryptoErrc::kBusyResource</code> signalisiert <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>.</p>
<p>Vorbedingung für das Auslesen importierter Schlüssel ist die erfolgreiche Durchführung von <code>Import</code>; andernfalls antworten <code>GetPrivateKey</code>, <code>GetPublicKey</code> und <code>GetSymmetricKey</code> mit <code>CryptoErrc::kProcessingNotFinished</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>. Stimmt der angeforderte Schlüsseltyp nicht mit dem tatsächlich entpackten Objekt überein oder wurde noch kein Objekt importiert, quittieren die Abrufmethoden dies mit <code>CryptoErrc::kNoSuchValue</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>. Bietet der Ausgabepuffer bei <code>GetResponse</code> nicht genügend Kapazität, resultiert dies in <code>CryptoErrc::kInsufficientCapacity</code> <a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>. Unterstützt die konkrete Implementierung eine Teilfunktion nicht (z. B. bestimmte Schlüsseltypen oder das Zurücksetzen), wird einheitlich <code>CryptoErrc::kUnsupported</code> zurückgegeben <a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>.</p>
