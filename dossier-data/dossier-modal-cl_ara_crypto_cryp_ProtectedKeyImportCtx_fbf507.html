<h4>Context</h4>
<p>The class <code>ara::crypto::cryp::ProtectedKeyImportCtx</code> defines a specialized interface for the secure loading and unpacking of cryptographic keys and associated metadata (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>). It is used when key material is to be transferred to and provided in the application environment in protected, encrypted, or authenticated form (for example, as a wrapped key token).</p>
<p>In interaction with other components, the context acts as an interface between the processing application, the cryptographic source and transport structures, and the resulting key objects:</p>
<ul>
<li><strong>Transport key:</strong> For decrypting and authenticating the data, the context requires a transport key. This is either passed directly as a symmetric key object <code>ara::crypto::cryp::SymmetricKey</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>) or referenced via a <code>ara::crypto::keys::KeySlot</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
<li><strong>Input data:</strong> The protected, serialized key data is provided to the context via a read-only memory area (<code>ReadOnlyMemRegion</code>) (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
<li><strong>Target storage or volatile keys:</strong> After a successful import, the unpacked key material can either be stored directly in a persistent write key slot (<code>WriteableKeySlot</code>) (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>) or obtained via typed query methods as a volatile smart pointer to private keys (<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>), symmetric keys (<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>), or public keys (<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>).</li>
<li><strong>Protocol responses:</strong> If the underlying import scenario supports an authentication or confirmation protocol (for example, the return values M4 and M5 of a SHE LoadKey transaction), the context returns this response data to the application (<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>Instances of <code>ProtectedKeyImportCtx</code> are managed as shared pointers via the typed alias <code>Sptr</code>, which is defined as <code>std::shared_ptr&lt;ProtectedKeyImportCtx&gt;</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50085" href="../spec/record.html?id=SWS_CRYPT_50085">[SWS_CRYPT_50085]</a>). Interpretation: The actual instantiation is likely to occur via a corresponding factory method of the CryptoProvider, since it is an abstract interface.</p>
<p>In operational operation, the context passes through several discrete states:</p>
<ol>
<li><strong>Initial state:</strong> After creation or after an explicit cleanup, no configured key import key exists, and internal data buffers are empty (<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</li>
<li><strong>Configured:</strong> By binding a transport key via <code>SetKey()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>), the context is prepared to process protected data packets.</li>
<li><strong>Data available:</strong> After successful execution of <code>Import()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>), the context holds the parsed key objects and any resulting response messages. The getter methods can be called from this state.</li>
<li><strong>Reset:</strong> A call to <code>Reset()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>) removes the configured transport key, clears all cached data from internal buffers, and returns the context to the initial state.</li>
</ol>
<p>With regard to concurrency, all interface methods of the context are specified as exception safe and thread-safe (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</p>

<h4>Usage Path</h4>
<p>A typical sequence for performing a protected key import is divided into the following steps:</p>
<ol>
<li><strong>Configure transport key:</strong> The application configures the context by calling <code>SetKey()</code> with a symmetric key object (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>) or a key slot (<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>). The provided key must have the corresponding usage permission.</li>
<li><strong>Execute import:</strong> The method <code>Import()</code> is called with the data buffer of the serialized data (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>). If a <code>WriteableKeySlot</code> is additionally specified, the context serializes the unpacked key material directly into this slot.</li>
<li><strong>Identify object type:</strong> <code>GetCryptoObjectType()</code> can be used to query which kind of crypto object was unpacked (<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>).</li>
<li><strong>Retrieve key and protocol response:</strong> Depending on the object type, the application requests the key via <code>GetSymmetricKey()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>), <code>GetPrivateKey()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>), or <code>GetPublicKey()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>). If the import protocol provides for a confirmation message, it is transferred via <code>GetResponse()</code> into a provided buffer (<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
<li><strong>Completion and buffer cleanup:</strong> After successful extraction, <code>Reset()</code> is called to ensure that sensitive residual data is removed from internal buffers and the context is cleanly reset (<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>All operations return a <code>ara::core::Result</code> and use defined rollback semantics in case of errors, which preserves the state prior to the call:</p>
<ul>
<li><strong>Key configuration errors:</strong>
  <ul>
  <li><code>CryptoErrc::kUsageViolation</code>: Occurs when the usage flags of the transport key do not contain the bit <code>kAllowKeyUnwrapping</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  <li><code>CryptoErrc::kIncompatibleObject</code>: The passed object or the key contained in the KeySlot cannot be used as a transport key (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  <li><code>CryptoErrc::kUnsupported</code>: The context implementation exclusively supports the respective other <code>SetKey()</code> variant (e.g., only <code>KeySlot</code> instead of a key object) (<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  </ul>
</li>
<li><strong>Errors during import:</strong>
  <ul>
  <li><code>CryptoErrc::kInvalidInputSize</code>: The passed memory area <code>serialized</code> has an unexpected size and cannot be unpacked (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kInvalidArgument</code>: The data format of <code>serialized</code> does not correspond to the required import format (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kAuthTagNotValid</code>: The authentication feature (signature or MAC) is invalid; data integrity could not be confirmed (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kBusyResource</code>: The operation cannot be executed temporarily because internal resources are occupied (<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  </ul>
</li>
<li><strong>Errors during result retrieval:</strong>
  <ul>
  <li><code>CryptoErrc::kProcessingNotFinished</code>: A call to <code>GetPrivateKey()</code>, <code>GetPublicKey()</code>, or <code>GetSymmetricKey()</code> fails if no successful <code>Import()</code> call took place beforehand (<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>).</li>
  <li><code>CryptoErrc::kNoSuchValue</code>: Returned if no object has been imported so far or if the most recently imported object does not match the queried key type (<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>).</li>
  <li><code>CryptoErrc::kInsufficientCapacity</code>: The output buffer passed for <code>GetResponse()</code> is not sufficient to hold the protocol response (<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
  <li><code>CryptoErrc::kUnsupported</code>: Signals that the context does not support a specific function—such as determining the object type (<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>), generating responses (<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>), or resetting the state (<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</li>
  </ul>
</li>
</ul>
