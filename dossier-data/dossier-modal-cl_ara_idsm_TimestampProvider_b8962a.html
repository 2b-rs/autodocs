<h4>Context</h4>
<p>The class <code>ara::idsm::TimestampProvider</code> is an abstract interface within the AUTOSAR Adaptive module <code>idsm</code> that serves to provide timestamps for the Intrusion Detection System Manager (IdsM) <a class="spec-record-ref" data-req="SWS_AIDSM_10400" href="../spec/record.html?id=SWS_AIDSM_10400">[SWS_AIDSM_10400]</a>. In the overall system, the class assumes the mediator role between a concrete time-providing source and the IdsM platform component. Typical safety events and security events must be recorded accurately in time, for which the IdsM relies on a configured instance of a timestamp provider.</p>
<p>The primary interaction partners are the application-specific provider implementation, the IdsM subsystem, and the underlying manifest model. The connection to the modeling is established via an instance identifier representing the assigned PPort <a class="spec-record-ref" data-req="SWS_AIDSM_10401" href="../spec/record.html?id=SWS_AIDSM_10401">[SWS_AIDSM_10401]</a>. This port instantiation defines which communication endpoint the provider is responsible for.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::idsm::TimestampProvider</code> is divided into the phases of creation, active service provision, deactivation, and destruction:</p>
<ul>
  <li><strong>Creation:</strong> The object is initialized with an <code>ara::core::InstanceSpecifier</code> that references the modeled PPort <a class="spec-record-ref" data-req="SWS_AIDSM_10401" href="../spec/record.html?id=SWS_AIDSM_10401">[SWS_AIDSM_10401]</a>. This constructor is declared as <code>explicit</code> and thread-safe (<em>thread-safe</em>).</li>
  <li><strong>Ownership and Copy Semantics:</strong> Since the instance is bound to a concrete port modeling and manages resources of the service, both the copy constructor <a class="spec-record-ref" data-req="SWS_AIDSM_10404" href="../spec/record.html?id=SWS_AIDSM_10404">[SWS_AIDSM_10404]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_AIDSM_10406" href="../spec/record.html?id=SWS_AIDSM_10406">[SWS_AIDSM_10406]</a> are deleted (<code>= delete</code>). Duplication of the provider instance is therefore ruled out.</li>
  <li><strong>Move Semantics:</strong> The class supports move operations. The move constructor is thread-safe <a class="spec-record-ref" data-req="SWS_AIDSM_10403" href="../spec/record.html?id=SWS_AIDSM_10403">[SWS_AIDSM_10403]</a>. Move assignment, on the other hand, is specified as not thread-safe <a class="spec-record-ref" data-req="SWS_AIDSM_10405" href="../spec/record.html?id=SWS_AIDSM_10405">[SWS_AIDSM_10405]</a> and therefore requires external synchronization if objects are moved concurrently.</li>
  <li><strong>State Transition:</strong> After creation, the provider is in an idle state. Calling <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10408" href="../spec/record.html?id=SWS_AIDSM_10408">[SWS_AIDSM_10408]</a> activates the service, which signals to the IdsM that timestamps can be queried via the callback method. Calling <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10409" href="../spec/record.html?id=SWS_AIDSM_10409">[SWS_AIDSM_10409]</a> prevents subsequent calls again.</li>
  <li><strong>Destruction:</strong> Release is performed via the virtual destructor <a class="spec-record-ref" data-req="SWS_AIDSM_10402" href="../spec/record.html?id=SWS_AIDSM_10402">[SWS_AIDSM_10402]</a>. This is not thread-safe. Prior to destruction, <code>StopOffer()</code> should presumably always be called to prevent the IdsM from accessing the object while the destructor is running.</li>
</ul>

<h4>Usage Path</h4>
<p>The regular use of <code>ara::idsm::TimestampProvider</code> takes place in a firmly defined sequence of integration and call steps:</p>
<ol>
  <li><strong>Derivation:</strong> An application derives its own provider class from <code>ara::idsm::TimestampProvider</code> and implements the pure virtual method <code>GetTimestamp()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10407" href="../spec/record.html?id=SWS_AIDSM_10407">[SWS_AIDSM_10407]</a>. In this method, the current timestamp of type <code>TimestampType</code> is determined and returned.</li>
  <li><strong>Instantiation:</strong> The derived class is instantiated and passes the matching <code>ara::core::InstanceSpecifier</code> instance to the base class constructor <a class="spec-record-ref" data-req="SWS_AIDSM_10401" href="../spec/record.html?id=SWS_AIDSM_10401">[SWS_AIDSM_10401]</a>.</li>
  <li><strong>Service Offer:</strong> Prior to the first acquisition of security events, the application calls <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10408" href="../spec/record.html?id=SWS_AIDSM_10408">[SWS_AIDSM_10408]</a>. Only then is the interface enabled for the IdsM.</li>
  <li><strong>Retrieval by IdsM:</strong> As soon as the IdsM requires timestamps for events, it autonomously calls the callback <code>GetTimestamp()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10407" href="../spec/record.html?id=SWS_AIDSM_10407">[SWS_AIDSM_10407]</a>.</li>
  <li><strong>Termination:</strong> For an orderly shutdown of the service, the application calls <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10409" href="../spec/record.html?id=SWS_AIDSM_10409">[SWS_AIDSM_10409]</a>, ensuring that no further timestamp queries are made by the IdsM. The object can then be destroyed <a class="spec-record-ref" data-req="SWS_AIDSM_10402" href="../spec/record.html?id=SWS_AIDSM_10402">[SWS_AIDSM_10402]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using the class, concurrency, return values, and exception guarantees must be taken into account in particular:</p>
<ul>
  <li><strong>Failure During Service Activation:</strong> The method <code>Offer()</code> returns an <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10408" href="../spec/record.html?id=SWS_AIDSM_10408">[SWS_AIDSM_10408]</a>. Interpretation: In case of an error, the returned result is likely to contain an error code if the modeled PPort is invalid or internal registration with the IdsM fails. Applications must evaluate the result prior to further operations.</li>
  <li><strong>Concurrency:</strong> Essential methods such as <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10408" href="../spec/record.html?id=SWS_AIDSM_10408">[SWS_AIDSM_10408]</a>, <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10409" href="../spec/record.html?id=SWS_AIDSM_10409">[SWS_AIDSM_10409]</a>, <code>GetTimestamp()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10407" href="../spec/record.html?id=SWS_AIDSM_10407">[SWS_AIDSM_10407]</a> as well as the move assignment operator <a class="spec-record-ref" data-req="SWS_AIDSM_10405" href="../spec/record.html?id=SWS_AIDSM_10405">[SWS_AIDSM_10405]</a> and the destructor <a class="spec-record-ref" data-req="SWS_AIDSM_10402" href="../spec/record.html?id=SWS_AIDSM_10402">[SWS_AIDSM_10402]</a> are specified as not thread-safe. Parallel calls to these operations without external synchronization lead to undefined behavior.</li>
  <li><strong>No Exceptions (noexcept):</strong> All methods of the class including <code>GetTimestamp()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10407" href="../spec/record.html?id=SWS_AIDSM_10407">[SWS_AIDSM_10407]</a> and <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10409" href="../spec/record.html?id=SWS_AIDSM_10409">[SWS_AIDSM_10409]</a> are declared with <code>noexcept</code>. The concrete implementation of <code>GetTimestamp()</code> in derived classes must not propagate any C++ exceptions to the outside.</li>
</ul>
