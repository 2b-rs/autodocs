<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht adaptiven Anwendungen die Bereitstellung der DoIP-Entity-Identifikation für das Diagnosemanagement.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::DoIPEntityIdentification</code> ermöglicht adaptiven Anwendungen die dynamische Bereitstellung der Entity-Identifikation (EID) für das DoIP-Diagnoseprotokoll <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>. Nach der Instanziierung aktiviert die Anwendung die Weiterleitung mittels <code>Offer()</code> und beantwortet Abfragen des Diagnostic Managements über die rein virtuelle Methode <code>GetEntityId()</code> asynchron mittels Future <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>, <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Ist die Schnittstelle bei einer Abfrage noch nicht bereitgestellt, versendet das Diagnosemanagement ersatzweise einen standardisierten <code>0xFF</code>-Wert <a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::DoIPEntityIdentification</code> dient der dynamischen Bereitstellung der Entity-Identifikation (EID) für das DoIP-Protokoll (Diagnostic over IP) <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>. In einer AUTOSAR-Adaptive-Umgebung bildet sie die funktionale Brücke zwischen einer individuellen adaptiven Anwendung und dem Diagnostic Management (DM) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics, S. 107</a>. Ist in der Konfiguration <code>DoIpNetworkConfiguration.eidRetrieval</code> auf den Modus <code>DoIpEidRetrievalEnum.eidUseApi</code> eingestellt, fordert das Diagnostic Management die EID über diese Programmierschnittstelle an <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>. Die Bindung an die Software-Architektur erfolgt über einen <code>ara::core::InstanceSpecifier</code>, der auf einen PortPrototype eines <code>DiagnosticDoIPEntityIdentificationInterface</code> verweist <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung erfolgt über den expliziten Konstruktor, dem neben dem <code>InstanceSpecifier</code> der Parameter <code>ConcurrencyType</code> (<code>kConcurrent</code> oder <code>kNotConcurrent</code>) übergeben wird <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. Letzterer legt fest, ob nachfolgende Abrufe an die Schnittstelle threadsicher abgewickelt werden müssen <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>, <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>. Nach der Konstruktion verbleibt das Objekt zunächst im inaktiven Zustand. Durch den Aufruf von <code>Offer()</code> wird die Schnittstelle für das Diagnostic Management freigeschaltet und die Weiterleitung von Anfragen an den Handler aktiviert <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Vor der Zerstörung des Objekts oder bei Beendigung des Betriebs unterbindet <code>StopOffer()</code> die Weiterleitung wieder <a class="spec-record-ref" data-req="SWS_DM_01368" href="../spec/record.html?id=SWS_DM_01368">[SWS_DM_01368]</a>. Die Zerstörung erfolgt schließlich über den virtuellen Destruktor <a class="spec-record-ref" data-req="SWS_DM_01365" href="../spec/record.html?id=SWS_DM_01365">[SWS_DM_01365]</a>. Weder <code>Offer()</code>, <code>StopOffer()</code> noch der Destruktor sind threadsicher und erfordern daher eine koordinierte Synchronisation im Anwendungscode <a class="spec-record-ref" data-req="SWS_DM_01365" href="../spec/record.html?id=SWS_DM_01365">[SWS_DM_01365]</a>, <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>, <a class="spec-record-ref" data-req="SWS_DM_01368" href="../spec/record.html?id=SWS_DM_01368">[SWS_DM_01368]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Im typischen Nutzungsszenario leitet die adaptive Anwendung eine eigene Implementierungsklasse von <code>ara::diag::DoIPEntityIdentification</code> ab und überschreibt die rein virtuelle Methode <code>GetEntityId()</code> <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>. Nach Instanziierung mit gültigem Bezeichner meldet die Anwendung den Handler mittels <code>Offer()</code> an <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Sobald das Diagnostic Management zur Zusammenstellung von DoIP-Nachrichten die Entity-ID benötigt, ruft es <code>GetEntityId()</code> auf <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>, <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>. Die Methode liefert ein <code>ara::core::Future&lt;EntityId&gt;</code> zurück, wodurch die Identifikationsdaten asynchron ermittelt und bereitgestellt werden können <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>. Endet der Funktionsbetrieb, nimmt die Anwendung das Angebot über <code>StopOffer()</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01368" href="../spec/record.html?id=SWS_DM_01368">[SWS_DM_01368]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Fehlerhafte Modellkonfigurationen bei der Konstruktion führen zu spezifischen Laufzeitverletzungen: Kann der <code>InstanceSpecifier</code> im Modell nicht aufgelöst werden oder verweist nicht auf einen PortPrototype, resultiert eine <code>InstanceSpecifierMappingIntegrityViolation</code> <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. Verweist das Port-Mapping nicht auf ein <code>DiagnosticDoIPEntityIdentificationInterface</code>, liegt eine <code>PortInterfaceMappingViolation</code> vor, während ein fehlender Prozessabgleich eine <code>ProcessMappingViolation</code> auslöst <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. Wird derselbe Bezeichner im Prozess mehrfach verwendet, folgt eine <code>InstanceSpecifierAlreadyInUseViolation</code> <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>.</p>
<p>Wird <code>Offer()</code> aufgerufen, wenn der Dienst bereits aktiv offeriert wird, liefert die Methode ein <code>ara::core::Result</code> mit dem Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Kann das Diagnostic Management die EID nicht abfragen – etwa weil die Schnittstelle zum Anfragezeitpunkt noch nicht offeriert wurde –, greift ein definierter Protokoll-Fallback: Das Diagnostic Management versendet in DoIP-Nachrichten ersatzweise einen 6-Byte-EID-Wert von <code>0xFF 0xFF 0xFF 0xFF 0xFF 0xFF</code> <a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>.</p>
