<h4>Context</h4>
<p>The class <code>ara::diag::DoIPEntityIdentification</code> provides the interface in the AUTOSAR Adaptive diagnostic module through which an application-specific Entity Identification (EID) for the DoIP protocol (Diagnostic over IP) can be obtained. If the retrieval method <code>DoIpNetworkConfiguration.eidRetrieval</code> is set to the value <code>DoIpEidRetrievalEnum.eidUseApi</code> in the configuration for a DoIP network, the Diagnostic Management Daemon (DM) requests the identifier via this interface <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>.</p>
<p>The class serves as an abstract base interface for an Adaptive Application (AA). The primary interaction partners include the application itself, which instantiates a concrete derived class and overrides the method <code>GetEntityId</code>, as well as the Diagnostic Management Daemon, which forwards requests to the registered handler <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>, <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Binding to the AUTOSAR model is performed via an <code>ara::core::InstanceSpecifier</code> that must reference an <code>PortPrototype</code> with the interface <code>DiagnosticDoIPEntityIdentificationInterface</code> <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::diag::DoIPEntityIdentification</code> is subject to a fixed phase structure from creation through service offering to deregistration and destruction:</p>
<ul>
<li><strong>Creation:</strong> The application creates the object by specifying the <code>InstanceSpecifier</code> and the <code>ConcurrencyType</code> (<code>kConcurrent</code> or <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. The constructor is specified as <code>thread-safe</code>. It links the instance with the declared model port.</li>
<li><strong>Activation:</strong> After successful construction, the handler is activated via the method <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. Only through this call is the Diagnostic Management Daemon authorized to forward EID requests to the object. <code>Offer()</code> is <code>not thread-safe</code> and requires sequential execution relative to lifecycle operations.</li>
<li><strong>Operation and concurrency:</strong> As soon as the service is offered, the DM can call the pure virtual method <code>GetEntityId()</code> <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>. The thread safety of this method is conditional and depends on the <code>ConcurrencyType</code> selected in the constructor: If <code>kConcurrent</code> was selected, the implementation must be reentrant and thread-safe; with <code>kNotConcurrent</code>, the runtime environment serializes requests <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>, <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>.</li>
<li><strong>Deactivation:</strong> The method <code>StopOffer()</code> terminates the forwarding of requests by the DM <a class="spec-record-ref" data-req="SWS_DM_01368" href="../spec/record.html?id=SWS_DM_01368">[SWS_DM_01368]</a>. <code>StopOffer()</code> is also specified as <code>not thread-safe</code>.</li>
<li><strong>Destruction:</strong> The virtual destructor <code>~DoIPEntityIdentification()</code> releases remaining resources <a class="spec-record-ref" data-req="SWS_DM_01365" href="../spec/record.html?id=SWS_DM_01365">[SWS_DM_01365]</a>. An object should always be deregistered using <code>StopOffer()</code> prior to destruction to rule out asynchronous accesses while the destructor is running.</li>
</ul>

<p>A typical usage path comprises class derivation by the application, implementation of the asynchronous response logic, and starting and stopping the service offering:</p>
<ol>
<li><strong>Class derivation and instantiation:</strong> The application derives a class from <code>DoIPEntityIdentification</code> and overrides <code>GetEntityId()</code>. Subsequently, it instantiates the object with the appropriate <code>InstanceSpecifier</code> and the concurrency model <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>.</li>
<li><strong>Offering the service:</strong> The call to <code>Offer()</code> registers the handler <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>. The method returns a <code>ara::core::Result&lt;void&gt;</code>, which confirms the success of the offer.</li>
<li><strong>EID determination by DM:</strong> When the DoIP subsystem of the DM needs to construct a DoIP protocol message (such as Vehicle Announcement or Identification Responses), it calls <code>GetEntityId()</code> <a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics §DoIP</a>. The application returns the result asynchronously via a <code>ara::core::Future&lt;EntityId&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_01366" href="../spec/record.html?id=SWS_DM_01366">[SWS_DM_01366]</a>.</li>
<li><strong>Stopping the service:</strong> Prior to shutting down the application or upon state changes, the application calls <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01368" href="../spec/record.html?id=SWS_DM_01368">[SWS_DM_01368]</a>, followed by the destruction of the object <a class="spec-record-ref" data-req="SWS_DM_01365" href="../spec/record.html?id=SWS_DM_01365">[SWS_DM_01365]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using the interface, error states and fallback mechanisms are provided on several levels:</p>
<ul>
<li><strong>Construction violations:</strong> If the resolution of the <code>InstanceSpecifier</code> fails or it does not refer to a matching <code>PortPrototype</code>, the system reports a <code>InstanceSpecifierMappingIntegrityViolation</code> <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. If the port is not typed by a <code>DiagnosticDoIPEntityIdentificationInterface</code>, a <code>PortInterfaceMappingViolation</code> occurs <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>. If the referenced process does not match the runtime process, a <code>ProcessMappingViolation</code> is present, and if an identifier that is already in use is reused, an <code>InstanceSpecifierAlreadyInUseViolation</code> follows <a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>.</li>
<li><strong>Multiple offering:</strong> If <code>Offer()</code> is called while the service is already being offered, the method returns an error code <code>DiagOfferErrc::kAlreadyOffered</code> (rollback semantics) <a class="spec-record-ref" data-req="SWS_DM_01367" href="../spec/record.html?id=SWS_DM_01367">[SWS_DM_01367]</a>.</li>
<li><strong>Fallback in case of missing or failing EID retrieval:</strong> If the Diagnostic Management daemon cannot retrieve the EID via the application—for example, because the instance has not yet been registered via <code>Offer()</code> at the required time or the retrieval fails—a standardized protocol fallback takes effect <a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>. In this case, the DM uses a 6-byte EID substitute value filled with <code>0xFF</code> (<code>0xFF 0xFF 0xFF 0xFF 0xFF 0xFF</code>) for DoIP messages <a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>.</li>
</ul>
