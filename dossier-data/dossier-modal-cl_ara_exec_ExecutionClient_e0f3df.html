<h4>Context</h4>
<p>The class <code>ara::exec::ExecutionClient</code> is used by a process within the AUTOSAR Adaptive Platform to report its internal execution state (Execution State) to Execution Management <a class="spec-record-ref" data-req="SWS_EM_02003" href="../spec/record.html?id=SWS_EM_02003">[SWS_EM_02003]</a>. In addition, the instance assumes responsibility for handling the operating system signal <code>SIGTERM</code> <a class="spec-record-ref" data-req="SWS_EM_02002" href="../spec/record.html?id=SWS_EM_02002">[SWS_EM_02002]</a>. The interaction partners include the application itself, Execution Management as the receiving control entity, and the operating system, which transmits termination signals.</p>

<h4>Lifecycle</h4>
<p>Two construction approaches are available for instantiating <code>ara::exec::ExecutionClient</code>:</p>
<ul>
<li>The named constructor <code>Create</code> <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a> creates a <code>ara::core::Result&lt;ExecutionClient&gt;</code>, is declared as <code>noexcept</code>, exception safe, and thread-safe.</li>
<li>The regular constructor <a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a> is declared thread-safe, but not exception safe (<code>noexcept(false)</code>).</li>
</ul>
<p>Both constructors require passing a <code>terminationHandler</code> callback of type <code>std::function&lt;void()&gt;</code> <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>, <a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a>. This callback is executed in a background thread as soon as a <code>SIGTERM</code> signal is received. The <code>terminationHandler</code> must remain callable throughout the entire lifetime of the <code>ExecutionClient</code> instance <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>, <a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a>.</p>
<p>Regarding ownership, the class prevents copying: Both the copy constructor <a class="spec-record-ref" data-req="SWS_EM_02563" href="../spec/record.html?id=SWS_EM_02563">[SWS_EM_02563]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_EM_02564" href="../spec/record.html?id=SWS_EM_02564">[SWS_EM_02564]</a> are explicitly deleted (<code>=delete</code>). Transfer of ownership is possible exclusively via move semantics: The move constructor <a class="spec-record-ref" data-req="SWS_EM_02580" href="../spec/record.html?id=SWS_EM_02580">[SWS_EM_02580]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_EM_02581" href="../spec/record.html?id=SWS_EM_02581">[SWS_EM_02581]</a> are present, specified as <code>noexcept</code> and exception safe, but not thread-safe.</p>
<p>During destruction via the destructor <a class="spec-record-ref" data-req="SWS_EM_02002" href="../spec/record.html?id=SWS_EM_02002">[SWS_EM_02002]</a>, which is likewise <code>noexcept</code> and not thread-safe, the <code>SIGTERM</code> handler is reset to its original state.</p>

<h4>Usage Path</h4>
<p>A typical usage sequence comprises the following steps:</p>
<ol>
<li><strong>Creation:</strong> The application initializes the client via <code>Create</code>, specifying a callback for controlled termination <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>.</li>
<li><strong>State reporting:</strong> After internal initialization is complete, the process reports its state to Execution Management via <code>ReportExecutionState</code> <a class="spec-record-ref" data-req="SWS_EM_02003" href="../spec/record.html?id=SWS_EM_02003">[SWS_EM_02003]</a>. The method is thread-safe and exception safe.</li>
<li><strong>Signal handling:</strong> If a <code>SIGTERM</code> signal arrives during execution, <code>ExecutionClient</code> calls the registered <code>terminationHandler</code> in a separate background thread, for example to set global flags and wake up blocked threads <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>.</li>
<li><strong>Destruction:</strong> When exiting the lifecycle, the destructor restores the original signal handler <a class="spec-record-ref" data-req="SWS_EM_02002" href="../spec/record.html?id=SWS_EM_02002">[SWS_EM_02002]</a>.</li>
</ol>
