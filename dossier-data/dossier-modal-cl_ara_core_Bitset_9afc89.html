<p class="ai-level ai-oneliner-lead" data-ai-level="1">Bietet eine standardkonforme, typsichere Bitfeld-Abstraktion fester Größe mit Noexcept-Garantien für Adaptive Core.</p>
<div class="ai-level" data-ai-level="2">
<p>Das Klassentemplate <code>ara::core::Bitset</code> stellt eine an AUTOSAR Adaptive angepasste Implementierung von <code>std::bitset</code> für Bitsequenzen fester Größe bereit <a class="spec-record-ref" data-req="SWS_CORE_01741" href="../spec/record.html?id=SWS_CORE_01741">[SWS_CORE_01741]</a>. Es bietet umfassende Operationen zur Bit-Manipulation, logische Verknüpfungen und optimierte Konvertierungen in skalare Ganzzahltypen mit strikten Noexcept-Garantien <a class="spec-record-ref" data-req="SWS_CORE_01738" href="../spec/record.html?id=SWS_CORE_01738">[SWS_CORE_01738]</a>. Positionsbasierte Modifikationen melden ungültige Indizes über <code>ara::core::Result</code> anstelle von C++-Ausnahmen, während Konvertierungen Überlauffehler deterministisch behandeln. Dadurch eignet sich die Klasse vor allem für ressourceneffiziente und ausfallsichere Steuergerätefunktionen.</p>

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Bitset</code> stellt innerhalb der Adaptive Platform eine Implementierung des C++-Standardtyps <code>std::bitset</code> für Bitfolgen mit zur Übersetzungszeit festgelegter Länge <code>N</code> bereit <a class="spec-record-ref" data-req="SWS_CORE_01741" href="../spec/record.html?id=SWS_CORE_01741">[SWS_CORE_01741]</a>. Im AUTOSAR-Ökosystem dient die Klasse der performanten und typsicheren Handhabung von Bitfeldern, Statusmasken und Flag-Registern auf Steuergeräten. Sie integriert sich nahtlos in das Typsystem des Moduls <code>core</code>, indem sie anstelle von <code>std::basic_string</code> den plattformspezifischen Typ <code>ara::core::BasicString</code> unterstützt <a class="spec-record-ref" data-req="SWS_CORE_01749" href="../spec/record.html?id=SWS_CORE_01749">[SWS_CORE_01749]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01751" href="../spec/record.html?id=SWS_CORE_01751">[SWS_CORE_01751]</a>. Zudem erweitert AUTOSAR das standardisierte Interface um dedizierte Konvertierungsfunktionen in vorzeichenlose Festbreiten-Ganzzahltypen wie <code>std::uint8_t</code>, <code>std::uint16_t</code>, <code>std::uint32_t</code> und <code>std::uint64_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01736" href="../spec/record.html?id=SWS_CORE_01736">[SWS_CORE_01736]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01737" href="../spec/record.html?id=SWS_CORE_01737">[SWS_CORE_01737]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01738" href="../spec/record.html?id=SWS_CORE_01738">[SWS_CORE_01738]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01739" href="../spec/record.html?id=SWS_CORE_01739">[SWS_CORE_01739]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung einer Instanz erfolgt flexibel über mehrere Konstruktoren. Der Standardkonstruktor initialisiert alle <code>N</code> Bits als Nullwerte und ist als <code>constexpr</code> sowie <code>noexcept</code> deklariert <a class="spec-record-ref" data-req="SWS_CORE_01713" href="../spec/record.html?id=SWS_CORE_01713">[SWS_CORE_01713]</a>. Alternativ kann ein Bitset aus einem Skalarwert des Typs <code>unsigned long long</code> <a class="spec-record-ref" data-req="SWS_CORE_01719" href="../spec/record.html?id=SWS_CORE_01719">[SWS_CORE_01719]</a> oder textbasiert aus <code>ara::core::BasicString</code> <a class="spec-record-ref" data-req="SWS_CORE_01749" href="../spec/record.html?id=SWS_CORE_01749">[SWS_CORE_01749]</a> bzw. einem nullterminierten Zeichenketten-Zeiger <code>const CharT*</code> <a class="spec-record-ref" data-req="SWS_CORE_01750" href="../spec/record.html?id=SWS_CORE_01750">[SWS_CORE_01750]</a> instanziiert werden. Kopier- und Verschiebekonstruktor sind vorhanden und als <code>noexcept=default</code> definiert <a class="spec-record-ref" data-req="SWS_CORE_01714" href="../spec/record.html?id=SWS_CORE_01714">[SWS_CORE_01714]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01716" href="../spec/record.html?id=SWS_CORE_01716">[SWS_CORE_01716]</a>. Ebenso werden die entsprechenden Zuweisungsoperatoren bereitgestellt <a class="spec-record-ref" data-req="SWS_CORE_01715" href="../spec/record.html?id=SWS_CORE_01715">[SWS_CORE_01715]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01717" href="../spec/record.html?id=SWS_CORE_01717">[SWS_CORE_01717]</a>. Der Destruktor ist als <code>noexcept</code> und thread-safe spezifiziert <a class="spec-record-ref" data-req="SWS_CORE_01718" href="../spec/record.html?id=SWS_CORE_01718">[SWS_CORE_01718]</a>. Hinsichtlich der Nebenläufigkeit sind die Ganzzahl-Konvertierungsfunktionen ebenfalls thread-safe <a class="spec-record-ref" data-req="SWS_CORE_01736" href="../spec/record.html?id=SWS_CORE_01736">[SWS_CORE_01736]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01737" href="../spec/record.html?id=SWS_CORE_01737">[SWS_CORE_01737]</a>, während modifizierende Zugriffe auf dieselbe Bitset-Instanz synchronisiert werden müssen.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad umfasst die Instanziierung, die anschließende Manipulation einzelner Bits oder Bitmasken sowie das abschließende Auswerten oder Konvertieren des Bitfelds:</p>
<ul>
<li><strong>Erzeugung:</strong> Das Bitset wird typischerweise mit einem Initialwert erzeugt <a class="spec-record-ref" data-req="SWS_CORE_01719" href="../spec/record.html?id=SWS_CORE_01719">[SWS_CORE_01719]</a> oder per Standardkonstruktor initialisiert <a class="spec-record-ref" data-req="SWS_CORE_01713" href="../spec/record.html?id=SWS_CORE_01713">[SWS_CORE_01713]</a>.</li>
<li><strong>Manipulation:</strong> Einzelne Bits lassen sich über positionsbasierte Aufrufe von <code>set</code> <a class="spec-record-ref" data-req="SWS_CORE_01726" href="../spec/record.html?id=SWS_CORE_01726">[SWS_CORE_01726]</a>, <code>reset</code> <a class="spec-record-ref" data-req="SWS_CORE_01728" href="../spec/record.html?id=SWS_CORE_01728">[SWS_CORE_01728]</a> und <code>flip</code> <a class="spec-record-ref" data-req="SWS_CORE_01731" href="../spec/record.html?id=SWS_CORE_01731">[SWS_CORE_01731]</a> modifizieren. Für das gesamte Bitfeld stehen parameterlose Varianten von <code>set</code> <a class="spec-record-ref" data-req="SWS_CORE_01725" href="../spec/record.html?id=SWS_CORE_01725">[SWS_CORE_01725]</a>, <code>reset</code> <a class="spec-record-ref" data-req="SWS_CORE_01727" href="../spec/record.html?id=SWS_CORE_01727">[SWS_CORE_01727]</a> und <code>flip</code> <a class="spec-record-ref" data-req="SWS_CORE_01730" href="../spec/record.html?id=SWS_CORE_01730">[SWS_CORE_01730]</a> sowie bitweise Verknüpfungs- und Shift-Operatoren wie <code>operator&amp;=</code> <a class="spec-record-ref" data-req="SWS_CORE_01720" href="../spec/record.html?id=SWS_CORE_01720">[SWS_CORE_01720]</a>, <code>operator|=</code> <a class="spec-record-ref" data-req="SWS_CORE_01721" href="../spec/record.html?id=SWS_CORE_01721">[SWS_CORE_01721]</a>, <code>operatorˆ=</code> <a class="spec-record-ref" data-req="SWS_CORE_01722" href="../spec/record.html?id=SWS_CORE_01722">[SWS_CORE_01722]</a>, <code>operator~</code> <a class="spec-record-ref" data-req="SWS_CORE_01729" href="../spec/record.html?id=SWS_CORE_01729">[SWS_CORE_01729]</a>, <code>operator&lt;&lt;=</code> <a class="spec-record-ref" data-req="SWS_CORE_01723" href="../spec/record.html?id=SWS_CORE_01723">[SWS_CORE_01723]</a> und <code>operator&gt;&gt;=</code> <a class="spec-record-ref" data-req="SWS_CORE_01724" href="../spec/record.html?id=SWS_CORE_01724">[SWS_CORE_01724]</a> zur Verfügung.</li>
<li><strong>Auswertung:</strong> Der Status kann über <code>test</code> <a class="spec-record-ref" data-req="SWS_CORE_01743" href="../spec/record.html?id=SWS_CORE_01743">[SWS_CORE_01743]</a>, <code>operator[]</code> <a class="spec-record-ref" data-req="SWS_CORE_01732" href="../spec/record.html?id=SWS_CORE_01732">[SWS_CORE_01732]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01733" href="../spec/record.html?id=SWS_CORE_01733">[SWS_CORE_01733]</a> oder Prädikate wie <code>all</code> <a class="spec-record-ref" data-req="SWS_CORE_01744" href="../spec/record.html?id=SWS_CORE_01744">[SWS_CORE_01744]</a>, <code>any</code> <a class="spec-record-ref" data-req="SWS_CORE_01745" href="../spec/record.html?id=SWS_CORE_01745">[SWS_CORE_01745]</a>, <code>none</code> <a class="spec-record-ref" data-req="SWS_CORE_01746" href="../spec/record.html?id=SWS_CORE_01746">[SWS_CORE_01746]</a> sowie <code>count</code> <a class="spec-record-ref" data-req="SWS_CORE_01740" href="../spec/record.html?id=SWS_CORE_01740">[SWS_CORE_01740]</a> abgefragt werden.</li>
<li><strong>Konvertierung:</strong> Zur Weiterverarbeitung kann der Bitfeldinhalt in numerische Festbreitentypen überführt werden, beispielsweise über <code>to_uint32t</code> <a class="spec-record-ref" data-req="SWS_CORE_01738" href="../spec/record.html?id=SWS_CORE_01738">[SWS_CORE_01738]</a>, oder mittels <code>to_string</code> als Zeichenkette exportiert werden <a class="spec-record-ref" data-req="SWS_CORE_01751" href="../spec/record.html?id=SWS_CORE_01751">[SWS_CORE_01751]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Im Gegensatz zu <code>std::bitset</code> verwendet <code>ara::core::Bitset</code> ein fehlertolerantes, deterministisches Fehlerbehandlungskonzept ohne Ausnahmen (<code>noexcept</code>):</p>
<ul>
<li><strong>Bereichsüberschreitung bei Positionszugriffen:</strong> Bei den manipulierenden Funktionen <code>set(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01726" href="../spec/record.html?id=SWS_CORE_01726">[SWS_CORE_01726]</a>, <code>reset(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01728" href="../spec/record.html?id=SWS_CORE_01728">[SWS_CORE_01728]</a> und <code>flip(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01731" href="../spec/record.html?id=SWS_CORE_01731">[SWS_CORE_01731]</a> wird der Rückgabetyp <code>Result&lt;Bitset&lt;N&gt;&amp;&gt;</code> verwendet. Liegt <code>pos</code> außerhalb des gültigen Bereichs, wird <code>IsoStdOutOfRangeViolation</code> anstelle von <code>std::out_of_range</code> gemeldet. Interpretation: Die konsequente Verwendung von <code>ara::core::Result</code> und <code>noexcept</code> dürfte der Einhaltung der strengen No-Exception-Vorgaben in sicherheitskritischen Bereichen der Adaptive Platform dienen. Auch die Prüffunktion <code>test(pos)</code> weist bei ungültigem <code>pos</code> auf <code>IsoStdOutOfRangeViolation</code> hin <a class="spec-record-ref" data-req="SWS_CORE_01743" href="../spec/record.html?id=SWS_CORE_01743">[SWS_CORE_01743]</a>.</li>
<li><strong>Ungültige Zeichenketten:</strong> Bei der Konstruktion aus <code>ara::core::BasicString</code> <a class="spec-record-ref" data-req="SWS_CORE_01749" href="../spec/record.html?id=SWS_CORE_01749">[SWS_CORE_01749]</a> wird bei <code>pos &gt; size()</code> eine <code>IsoStdOutOfRangeViolation</code> und bei Zeichen ungleich <code>0</code> bzw. <code>1</code> eine <code>IsoStdInvalidArgumentViolation</code> (anstelle von <code>std::invalid_argument</code>) ausgelöst.</li>
<li><strong>Numerischer Überlauf:</strong> Kann der repräsentierte Bitzustand nicht im angeforderten Zieltyp abgebildet werden, melden die Konvertierungsfunktionen <code>to_uint8t</code> <a class="spec-record-ref" data-req="SWS_CORE_01736" href="../spec/record.html?id=SWS_CORE_01736">[SWS_CORE_01736]</a>, <code>to_uint16t</code> <a class="spec-record-ref" data-req="SWS_CORE_01737" href="../spec/record.html?id=SWS_CORE_01737">[SWS_CORE_01737]</a>, <code>to_uint32t</code> <a class="spec-record-ref" data-req="SWS_CORE_01738" href="../spec/record.html?id=SWS_CORE_01738">[SWS_CORE_01738]</a>, <code>to_uint64t</code> <a class="spec-record-ref" data-req="SWS_CORE_01739" href="../spec/record.html?id=SWS_CORE_01739">[SWS_CORE_01739]</a>, <code>to_ulong</code> <a class="spec-record-ref" data-req="SWS_CORE_01734" href="../spec/record.html?id=SWS_CORE_01734">[SWS_CORE_01734]</a> und <code>to_ullong</code> <a class="spec-record-ref" data-req="SWS_CORE_01735" href="../spec/record.html?id=SWS_CORE_01735">[SWS_CORE_01735]</a> jeweils <code>IsoStdOverflowErrorViolation</code> statt <code>std::overflow_error</code>.</li>
