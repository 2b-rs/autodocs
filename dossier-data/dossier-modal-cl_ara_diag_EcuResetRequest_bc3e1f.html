<h4>Context</h4>
<p>The interface class <code>ara::diag::EcuResetRequest</code> serves to connect applications to the UDS diagnostic service <em>ECUReset</em> (Service 0x11) according to ISO 14229-1 in the AUTOSAR Adaptive diagnostic module. It acts as a service interface through which Diagnostic Management (DM) delegates incoming diagnostic requests for executing an ECU reset to the responsible application or platform process. The process that instantiates and implements this interface takes over checking the admissibility of the requested reset and subsequently performing the system restart.</p>
<p>The interaction partners include Diagnostic Management (DM) as the mediator of UDS messages and the implementing application or platform process. Via specific subfunctions of Service 0x11, the DM controls either the enabling and disabling of the rapid power shutdown mode (<em>RapidPowerShutdown</em>) via <code>EnableRapidShutdown</code> (<a class="spec-record-ref" data-req="SWS_DM_01020" href="../spec/record.html?id=SWS_DM_01020">[SWS_DM_01020]</a>, <a class="spec-record-ref" data-req="SWS_DM_01021" href="../spec/record.html?id=SWS_DM_01021">[SWS_DM_01021]</a>) or requests regular reset actions via the separate phases <code>RequestReset</code> and <code>ExecuteReset</code> (<a class="spec-record-ref" data-req="SWS_DM_01013" href="../spec/record.html?id=SWS_DM_01013">[SWS_DM_01013]</a>, <a class="spec-record-ref" data-req="SWS_DM_01014" href="../spec/record.html?id=SWS_DM_01014">[SWS_DM_01014]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=150">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2 “Calling ExecuteReset() if positive response shall be sent before reset”</a>).</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::diag::EcuResetRequest</code> is bound to a concrete port prototype of a modeled <code>DiagnosticEcuResetInterface</code> via an <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_01010" href="../spec/record.html?id=SWS_DM_01010">[SWS_DM_01010]</a>). The class is designed as a single instance: neither copy nor move constructors are permitted (<a class="spec-record-ref" data-req="SWS_DM_01621" href="../spec/record.html?id=SWS_DM_01621">[SWS_DM_01621]</a>, <a class="spec-record-ref" data-req="SWS_DM_01622" href="../spec/record.html?id=SWS_DM_01622">[SWS_DM_01622]</a>), and assignment operators are deleted (<a class="spec-record-ref" data-req="SWS_DM_01619" href="../spec/record.html?id=SWS_DM_01619">[SWS_DM_01619]</a>, <a class="spec-record-ref" data-req="SWS_DM_01620" href="../spec/record.html?id=SWS_DM_01620">[SWS_DM_01620]</a>). This ensures that a reset port endpoint remains uniquely identified and bound within the process context.</p>
<p>After construction, the handler must be explicitly registered with Diagnostic Management via <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01016" href="../spec/record.html?id=SWS_DM_01016">[SWS_DM_01016]</a>). Only this call activates the forwarding of UDS reset requests to the virtual methods of the instance. If forwarding is to be paused or terminated, this is done via <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01017" href="../spec/record.html?id=SWS_DM_01017">[SWS_DM_01017]</a>). Upon destruction of the instance via the virtual destructor <code>~EcuResetRequest()</code> (<a class="spec-record-ref" data-req="SWS_DM_01011" href="../spec/record.html?id=SWS_DM_01011">[SWS_DM_01011]</a>), the handler must be deregistered. All methods of the class are specified as not thread-safe (<em>not thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_DM_01010" href="../spec/record.html?id=SWS_DM_01010">[SWS_DM_01010]</a>, <a class="spec-record-ref" data-req="SWS_DM_01016" href="../spec/record.html?id=SWS_DM_01016">[SWS_DM_01016]</a>, <a class="spec-record-ref" data-req="SWS_DM_01017" href="../spec/record.html?id=SWS_DM_01017">[SWS_DM_01017]</a>); calls must therefore be made from an orderly thread context.</p>

<h4>Usage Path</h4>
<p>The typical sequence for handling an ECU reset request is divided into the registration phase and multi-stage execution:</p>
<ol>
  <li><strong>Instantiation and release:</strong> The concrete derivation of <code>ara::diag::EcuResetRequest</code> is created with the <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_01010" href="../spec/record.html?id=SWS_DM_01010">[SWS_DM_01010]</a>). The application then calls <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01016" href="../spec/record.html?id=SWS_DM_01016">[SWS_DM_01016]</a>).</li>
  <li><strong>Evaluation of the reset request:</strong> Incoming EcuReset subfunctions (excluding RapidPowerShutdown) trigger the invocation of <code>RequestReset(resetType, id, metaInfo, cancellationHandler)</code> in the DM (<a class="spec-record-ref" data-req="SWS_DM_01013" href="../spec/record.html?id=SWS_DM_01013">[SWS_DM_01013]</a>). The instantiating process carefully checks whether the overall system or subsystems can be safely restarted. In case of approval, the application signals this via the returned <code>ara::core::Future&lt;void&gt;</code>. Once accepted, a reset binds the process to this decision for the subsequent trigger (<a class="spec-record-ref" data-req="SWS_DM_01013" href="../spec/record.html?id=SWS_DM_01013">[SWS_DM_01013]</a>).</li>
  <li><strong>Execution of the reset:</strong> If <code>DiagnosticEcuResetClass.respondToReset</code> is not present in the diagnostic configuration or is set to <code>respondBeforeReset</code>, Diagnostic Management first sends the positive UDS response and only then calls <code>ExecuteReset(metaInfo)</code> (<a class="spec-record-ref" data-req="SWS_DM_01023" href="../spec/record.html?id=SWS_DM_01023">[SWS_DM_01023]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=150">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.2</a>). The process then performs the actual reset (<a class="spec-record-ref" data-req="SWS_DM_01014" href="../spec/record.html?id=SWS_DM_01014">[SWS_DM_01014]</a>). If, on the other hand, <code>respondAfterReset</code> is configured and <code>RequestReset</code> was error-free, the positive response occurs only after the actual restart (<a class="spec-record-ref" data-req="SWS_DM_00360" href="../spec/record.html?id=SWS_DM_00360">[SWS_DM_00360]</a>).</li>
  <li><strong>Special case RapidPowerShutdown:</strong> For the subfunctions <code>EnableRapidPowerShutdown</code> and <code>DisableRapidPowerShutdown</code>, the DM instead calls <code>EnableRapidShutdown(enable, metaInfo, cancellationHandler)</code> with <code>true</code> or <code>false</code>, respectively (<a class="spec-record-ref" data-req="SWS_DM_01012" href="../spec/record.html?id=SWS_DM_01012">[SWS_DM_01012]</a>, <a class="spec-record-ref" data-req="SWS_DM_01020" href="../spec/record.html?id=SWS_DM_01020">[SWS_DM_01020]</a>, <a class="spec-record-ref" data-req="SWS_DM_01021" href="../spec/record.html?id=SWS_DM_01021">[SWS_DM_01021]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=149">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.5.1</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>When handling <code>ara::diag::EcuResetRequest</code>, functional and configuration-related errors can occur:</p>
<ul>
  <li><strong>Model and instantiation violations:</strong> When calling the constructor, the consistency of the <code>InstanceSpecifier</code> is checked (<a class="spec-record-ref" data-req="SWS_DM_01010" href="../spec/record.html?id=SWS_DM_01010">[SWS_DM_01010]</a>). If the mapping fails or the port type does not match, specific violations occur:
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not reference a PortPrototype.</li>
      <li><code>PortInterfaceMappingViolation</code>: The PortPrototype with <code>DiagnosticEcuResetInterface</code> is not referenced by a <code>DiagnosticServiceGenericMapping</code>.</li>
      <li><code>ProcessMappingViolation</code>: No matching modeled process exists at runtime for the instance reference.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The identifier is already used by another instance in the running process.</li>
    </ul>
  </li>
  <li><strong>Multiple registration:</strong> A repeated call to <code>Offer()</code> on an already registered instance fails with the error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_01016" href="../spec/record.html?id=SWS_DM_01016">[SWS_DM_01016]</a>).</li>
  <li><strong>Rejection of the reset:</strong> If a reset in <code>RequestReset</code> or a mode change in <code>EnableRapidShutdown</code> cannot currently be performed (e.g., due to invalid vehicle states), the application returns an appropriate UDS NRC (Negative Response Code) via <code>DiagUdsNrcErrc</code> through the <code>ara::core::Future</code> (<a class="spec-record-ref" data-req="SWS_DM_01012" href="../spec/record.html?id=SWS_DM_01012">[SWS_DM_01012]</a>, <a class="spec-record-ref" data-req="SWS_DM_01013" href="../spec/record.html?id=SWS_DM_01013">[SWS_DM_01013]</a>).</li>
  <li><strong>Effect of errors in ExecuteReset:</strong> If <code>DiagnosticEcuResetClass.respondToReset</code> is set to <code>respondBeforeReset</code> (or is missing), the positive response was already transmitted to the diagnostic tester prior to calling <code>ExecuteReset</code>. An error returned by <code>ExecuteReset</code> in this state no longer has any effect on the UDS communication (<a class="spec-record-ref" data-req="SWS_DM_01014" href="../spec/record.html?id=SWS_DM_01014">[SWS_DM_01014]</a>).</li>
  <li><strong>Cancellation of ongoing conversations:</strong> Via the passed <code>CancellationHandler</code> object, the application can check during asynchronous processing whether the conversation has been canceled (<code>IsCanceled()</code>), or register a callback via <code>SetNotifier</code> (<a class="spec-record-ref" data-req="SWS_DM_01012" href="../spec/record.html?id=SWS_DM_01012">[SWS_DM_01012]</a>, <a class="spec-record-ref" data-req="SWS_DM_01013" href="../spec/record.html?id=SWS_DM_01013">[SWS_DM_01013]</a>).</li>
</ul>
