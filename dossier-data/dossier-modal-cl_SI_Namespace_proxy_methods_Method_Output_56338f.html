<h4>Context</h4>
<p>In the Adaptive Platform (module <code>com</code>), the structure <code>&lt;SI-Namespace&gt;::proxy::methods::&lt;Method&gt;::Output</code> serves as an encapsulation for the output parameters (<code>out</code> arguments) of a method call at the client or proxy level (<a class="spec-record-ref" data-req="SWS_CM_99333" href="../spec/record.html?id=SWS_CM_99333">[SWS_CM_99333]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=349">AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”</a>). If a service interface method defines multiple return values or specific output arguments, the platform bundles these parameters into a generated <code>Output</code> structure instead of transporting individual values unattached.</p>
<p>Essentially, the following components are involved in the interaction:</p>
<ul>
<li><strong>Calling client application</strong>: Initiates the method call via the proxy instance and evaluates the result data after completion.</li>
<li><strong>Method proxy</strong>: The function object <code>&lt;SI-Namespace&gt;::proxy::methods::&lt;Method&gt;</code>, which serializes the parameters upon invocation and triggers communication.</li>
<li><strong>Return container</strong>: A <code>ara::core::Future</code> object, which contains the instantiated <code>Output</code> structure in case of success (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=349">AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”</a>).</li>
<li><strong>Skeleton counterpart</strong>: On the service provider side, the typed counterpart <code>{&lt;hierarchical-namespace-list-lower-skeleton&gt;}::skeleton::{&lt;service-interface-name&gt;}Skeleton::{&lt;method-name&gt;}Output</code> (<a class="spec-record-ref" data-req="SWS_CM_99556" href="../spec/record.html?id=SWS_CM_99556">[SWS_CM_99556]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=411">AUTOSAR_AP_SWS_CommunicationManagement §8.4.6 “Struct: {&lt;method-name&gt;}Output”</a>) exists, which is also provided by the service provider via a future (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=407">AUTOSAR_AP_SWS_CommunicationManagement §8.4.6</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifetime and state management of a <code>Output</code> instance is tightly coupled to the parent <code>ara::core::Future</code> object and the asynchronous communication:</p>
<ul>
<li><strong>Creation</strong>: The <code>Output</code> object is not instantiated manually by application code. It is created by the communication layer after successful reception and deserialization of the service provider's response message and inserted into the associated <code>ara::core::Future</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=349">AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”</a>).</li>
<li><strong>Ownership and transfer</strong>: The object remains in the future until the calling application retrieves the result via <code>get()</code> or <code>GetResult()</code>. Through this retrieval, the <code>Output</code> instance is transferred into the ownership of the calling client context.</li>
<li><strong>Cancellation and destruction</strong>: If the caller destroys the returned <code>ara::core::Future</code> object prematurely, its destructor causes the cancellation of the method call (<a class="spec-record-ref" data-req="SWS_CM_00194" href="../spec/record.html?id=SWS_CM_00194">[SWS_CM_00194]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=298">AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6</a>). In this case, no <code>Output</code> instance is delivered to the application, and processing is discarded.</li>
</ul>

<h4>Usage Path</h4>
<p>The regular workflow for using the <code>Output</code> structure is divided into the following phases:</p>
<ol>
<li><strong>Method call</strong>: The application calls the proxy method object <code>operator()(...)</code> with the defined input arguments.</li>
<li><strong>Receipt of the future object</strong>: As an immediate return, the caller receives an object of type <code>ara::core::Future&lt;Output&gt;</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=349">AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”</a>).</li>
<li><strong>Synchronization and query</strong>: The caller blocks synchronously or waits asynchronously for completion and requests the result via <code>get()</code> or <code>GetResult()</code> (<a class="spec-record-ref" data-req="SWS_CM_10371" href="../spec/record.html?id=SWS_CM_10371">[SWS_CM_10371]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=298">AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6</a>).</li>
<li><strong>Processing</strong>: Upon successful execution, the application extracts the <code>Output</code> object (<a class="spec-record-ref" data-req="SWS_CM_99333" href="../spec/record.html?id=SWS_CM_99333">[SWS_CM_99333]</a>) and reads the member fields of the output parameters contained within it.</li>
</ol>

<h4>Error Scenarios</h4>
<p>In error cases, the <code>Output</code> structure is not passed to the caller:</p>
<ul>
<li><strong>Infrastructure and future errors</strong>: If the method call is not successful, the resulting <code>ara::core::Future</code> does not contain a <code>Output</code> object, but an error code, for example <code>ara::core::FutureErrc</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=349">AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”</a>) or <code>ara::com::ComErrc</code> or <code>ApApplicationError</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=407">AUTOSAR_AP_SWS_CommunicationManagement §8.4.6</a>).</li>
<li><strong>Checked application errors (Checked Errors)</strong>: If a defined checked error occurs during the processing of the method call, the corresponding <code>ara::core::ErrorCode</code> is returned in the context of the call to <code>GetResult()</code> or <code>get()</code> (<a class="spec-record-ref" data-req="SWS_CM_10371" href="../spec/record.html?id=SWS_CM_10371">[SWS_CM_10371]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=298">AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6</a>). In this path, no <code>Output</code> instance is constructed.</li>
<li><strong>Fire-and-forget methods</strong>: According to the specification, no checked errors exist for fire-and-forget calls (<a class="spec-record-ref" data-req="SWS_CM_90436" href="../spec/record.html?id=SWS_CM_90436">[SWS_CM_90436]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=298">AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6</a>); by design, such methods also do not have a <code>Output</code> structure, because no return values are transmitted.</li>
</ul>
