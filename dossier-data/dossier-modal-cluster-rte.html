<div class="ai-level" data-ai-level="2">
<p>Das Modulcluster Runtime Environment (RTE) realisiert den AUTOSAR Virtual Functional Bus auf dem Steuergerät und stellt standardisierte APIs für die typisierte Sender-Receiver- und Client-Server-Kommunikation von Software-Komponenten bereit <a class="spec-record-ref" data-req="SWS_Rte_01091" href="../spec/record.html?id=SWS_Rte_01091">[SWS_Rte_01091]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01102" href="../spec/record.html?id=SWS_Rte_01102">[SWS_Rte_01102]</a>. Es integriert den Basic Software Scheduler (SchM) zur zyklischen Einplanung der Basissoftware-Module und koppelt an OS/IOC sowie den Kommunikationsstack (COM, LdCom) an <a class="spec-record-ref" data-req="SWS_Rte_01376" href="../spec/record.html?id=SWS_Rte_01376">[SWS_Rte_01376]</a>, <a class="spec-record-ref" data-req="SWS_Rte_04546" href="../spec/record.html?id=SWS_Rte_04546">[SWS_Rte_04546]</a>. Dabei garantiert die RTE Datenkonsistenz und deterministische Modusübergänge durch konfigurierbare Schutzbereiche, Pufferung und definierte 10-Stufen-Transitionsabläufe <a class="spec-record-ref" data-req="SWS_Rte_02665" href="../spec/record.html?id=SWS_Rte_02665">[SWS_Rte_02665]</a>, <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</p>

<div class="ai-level" data-ai-level="3">
<p>Das Modulcluster Runtime Environment (RTE) bildet die Realisierung des Virtual Functional Bus (VFB) auf Steuergeräteebene. Es entkoppelt AUTOSAR Software-Komponenten (SWCs) vollständig von der zugrunde liegenden Basissoftware und koordiniert über den Basic Software Scheduler (SchM) die Einplanung von BSW-Modulen <a class="spec-record-ref" data-req="SWS_Rte_04546" href="../spec/record.html?id=SWS_Rte_04546">[SWS_Rte_04546]</a>, <a class="spec-record-ref" data-req="SWS_Rte_05165" href="../spec/record.html?id=SWS_Rte_05165">[SWS_Rte_05165]</a>. Das Cluster wickelt sowohl partitionsinterne Zugriffe als auch partitionsübergreifende Datenflüsse über das OS-IOC sowie den Steuergerätebus über die Module COM und LdCom ab <a class="spec-record-ref" data-req="SWS_Rte_01376" href="../spec/record.html?id=SWS_Rte_01376">[SWS_Rte_01376]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02736" href="../spec/record.html?id=SWS_Rte_02736">[SWS_Rte_02736]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_OS_SECTION_3_7_RTE_Configuration_interaction_with_other_BSW_Modules.html" data-snip="SNIP_CLASSIC_OS_SECTION_3_7_RTE_Configuration_interaction_with_other_BSW_Modules">SWS_RTE S. 106</a>.</p>

<h4>Systemarchitektur &amp; Rolle des Modulclusters</h4>
<p>Das Modulcluster der Runtime Environment (RTE) bildet das funktionale und kommunikative Rückgrat der AUTOSAR Classic Platform. Es stellt die konkrete Realisierung des Virtual Functional Bus (VFB) auf einem Steuergerät dar und entkoppelt Software-Komponenten (SWCs) vollständig von der zugrunde liegenden Basissoftware (BSW) sowie der Mikrocontroller-Hardware <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_OS_SECTION_3_7_RTE_Configuration_interaction_with_other_BSW_Modules.html" data-snip="SNIP_CLASSIC_OS_SECTION_3_7_RTE_Configuration_interaction_with_other_BSW_Modules">SWS_RTE S. 106</a>. Innerhalb des Clusters übernimmt die eigentliche RTE die Vermittlung der anwendungsbezogenen Inter- und Intra-ECU-Kommunikation, während der integrierte Basic Software Scheduler (SchM) die Ablaufsteuerung, Konsistenzsicherung und zyklische Einplanung der BSW-Module steuert <a class="spec-record-ref" data-req="SWS_Rte_04546" href="../spec/record.html?id=SWS_Rte_04546">[SWS_Rte_04546]</a>, <a class="spec-record-ref" data-req="SWS_Rte_05165" href="../spec/record.html?id=SWS_Rte_05165">[SWS_Rte_05165]</a>.</p>
<p>Die Architektur spannt standardisierte Schnittstellen zwischen Anwendungs-SWCs, Sensor-/Aktor-Komponenten und den BSW-Schichten auf. Für die fahrzeugweite Vernetzung stützt sich das RTE-Cluster unmittelbar auf den Kommunikationsstack ab: Signalorientierte Botschaften werden an das Modul COM übergeben, während große Datenmengen über das LdCom-Modul (Large Data COM) abgewickelt werden <a class="spec-record-ref" data-req="SWS_Rte_01376" href="../spec/record.html?id=SWS_Rte_01376">[SWS_Rte_01376]</a>, <a class="spec-record-ref" data-req="SWS_Rte_04527" href="../spec/record.html?id=SWS_Rte_04527">[SWS_Rte_04527]</a>. Die Prozess- und Speicherisolation über Partitions- und Core-Grenzen hinweg wird durch das AUTOSAR Betriebssystem (OS) und dessen Inter-OS-Application-Communication-Mechanismus (IOC) bereitgestellt <a class="spec-record-ref" data-req="SWS_Rte_02736" href="../spec/record.html?id=SWS_Rte_02736">[SWS_Rte_02736]</a>. Kalibrierdaten und Speicherblöcke koppeln über standardisierte Deskriptoren an NVRAM Manager (NvM) und Kalibriertools an <a class="spec-record-ref" data-req="SWS_Rte_03961" href="../spec/record.html?id=SWS_Rte_03961">[SWS_Rte_03961]</a>, <a class="spec-record-ref" data-req="SWS_Rte_05118" href="../spec/record.html?id=SWS_Rte_05118">[SWS_Rte_05118]</a>.</p>

<h4>Zusammenspiel &amp; Interaktionspfade zwischen den Modulen</h4>
<p>Das Zusammenspiel im RTE-Cluster unterscheidet strikt zwischen Sender-Receiver- (S/R) und Client-Server-Kommunikation (C/S). Bei der S/R-Kommunikation unterstützt die RTE sowohl implizite als auch explizite Lese- und Schreibsemantiken: Bei implizitem Zugriff (`Rte_IRead`, `Rte_IWrite`) erstellt die RTE zu Beginn der Runnable-Ausführung eine lokale Kopie, die über die gesamte Laufzeit konsistent gehalten wird <a class="spec-record-ref" data-req="SWS_Rte_06000" href="../spec/record.html?id=SWS_Rte_06000">[SWS_Rte_06000]</a>, <a class="spec-record-ref" data-req="SWS_Rte_03744" href="../spec/record.html?id=SWS_Rte_03744">[SWS_Rte_03744]</a>. Bei explizitem Zugriff (`Rte_Read`, `Rte_Write`, `Rte_Send`, `Rte_Receive`) erfolgt der Datenaustausch direkt synchron oder über Warteschlangen <a class="spec-record-ref" data-req="SWS_Rte_01091" href="../spec/record.html?id=SWS_Rte_01091">[SWS_Rte_01091]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01092" href="../spec/record.html?id=SWS_Rte_01092">[SWS_Rte_01092]</a>. Für Ereignisse mit Warteschlangen (`swImplPolicy = queued`) richtet die RTE empfängerseitig FIFO-Warteschlangen ein; läuft ein solcher Puffer über, wird das Element verworfen und ein Fehlerzustand gesetzt <a class="spec-record-ref" data-req="SWS_Rte_02521" href="../spec/record.html?id=SWS_Rte_02521">[SWS_Rte_02521]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02523" href="../spec/record.html?id=SWS_Rte_02523">[SWS_Rte_02523]</a>.</p>
<p>Führt der Datenpfad über Steuergerätegrenzen (Inter-ECU), transformiert und serialisiert die RTE zusammengesetzte Datenstrukturen und ruft `Com_SendSignal` beziehungsweise `Com_SendSignalGroup` auf, um die atomare PDU-Übertragung im COM-Modul sicherzustellen <a class="spec-record-ref" data-req="SWS_Rte_04527" href="../spec/record.html?id=SWS_Rte_04527">[SWS_Rte_04527]</a>. Bei großen Datenarrays greift die RTE alternativ auf `LdCom_Transmit` zurück und sperrt bei Transportprotokollen (TP) den zugehörigen Puffer bis zur Bestätigung über Callbacks <a class="spec-record-ref" data-req="SWS_Rte_01377" href="../spec/record.html?id=SWS_Rte_01377">[SWS_Rte_01377]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01379" href="../spec/record.html?id=SWS_Rte_01379">[SWS_Rte_01379]</a>. Auf Empfängerseite empfängt die RTE Daten asynchron über COM-Callbacks und leitet daraus Aktivierungsereignisse für Applikations-Runnables ab <a class="spec-record-ref" data-req="SWS_Rte_03530" href="../spec/record.html?id=SWS_Rte_03530">[SWS_Rte_03530]</a>, <a class="spec-record-ref" data-req="SWS_Rte_03531" href="../spec/record.html?id=SWS_Rte_03531">[SWS_Rte_03531]</a>. Sind noch keine Busdaten eingetroffen, liefert die RTE konfigurierte Initialwerte aus <a class="spec-record-ref" data-req="SWS_Rte_06009" href="../spec/record.html?id=SWS_Rte_06009">[SWS_Rte_06009]</a>, <a class="spec-record-ref" data-req="SWS_Rte_06010" href="../spec/record.html?id=SWS_Rte_06010">[SWS_Rte_06010]</a>.</p>

<h4>Synchronisation, Reentranz und Task-Kontexte</h4>
<p>Die Ausführung von Programmcode im RTE-Cluster erfolgt innerhalb von OS-Tasks oder ISR-Kontexten. Die RTE unterscheidet zwischen einfachen Runnables (Kategorie 1 ohne blockierende OS-Aufrufe) und erweiterten Runnables (Kategorie 2 mit Wartepunkten), die durch Events wie `DataReceivedEvent` oder COM-Callbacks aus dem Zustand `WaitPoint` geweckt werden <a class="spec-record-ref" data-req="SWS_Rte_03532" href="../spec/record.html?id=SWS_Rte_03532">[SWS_Rte_03532]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_STD_SECTION_4_3_1_5_2_Explicit.html" data-snip="SNIP_CLASSIC_STD_SECTION_4_3_1_5_2_Explicit">SWS_RTE S. 304</a>. Die nebenläufige Aktivierung derselben Instanz einer Runnable Entity ist strikt verboten, es sei denn, das Attribut `canBeInvokedConcurrently` ist explizit auf `TRUE` gesetzt <a class="spec-record-ref" data-req="SWS_Rte_03523" href="../spec/record.html?id=SWS_Rte_03523">[SWS_Rte_03523]</a>. Bei multi-instanziierten SWCs setzt AUTOSAR konsequent auf Code-Sharing: Mehrere Instanzen teilen sich denselben ausführbaren Code, greifen jedoch über instanzspezifische Deskriptoren auf getrennte Daten und Per-Instance-Memory (PIM) zu <a class="spec-record-ref" data-req="SWS_Rte_02002" href="../spec/record.html?id=SWS_Rte_02002">[SWS_Rte_02002]</a>, <a class="spec-record-ref" data-req="SWS_Rte_03015" href="../spec/record.html?id=SWS_Rte_03015">[SWS_Rte_03015]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02301" href="../spec/record.html?id=SWS_Rte_02301">[SWS_Rte_02301]</a>.</p>
<p>Zur Absicherung kritischer Abschnitte generiert die RTE sogenannte Exclusive Areas (`Rte_Enter`, `Rte_Exit`). Der zugrunde liegende Synchronisationsmechanismus wird über den Parameter `RteExclusiveAreaImplMechanism` konfiguriert <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>. Hierbei stehen fünf definierte Strategien zur Verfügung:
<ul>
  <li><code>ALL_INTERRUPT_BLOCKING</code>: Globales Sperren aller Hardware-Interrupts <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</li>
  <li><code>OS_INTERRUPT_BLOCKING</code>: Selektives Sperren von OS-spezifischen Interrupts (Kategorie 2) <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</li>
  <li><code>OS_RESOURCE</code>: Nutzung von OSEK-/AUTOSAR-Betriebssystem-Ressourcen mit Prioritäts-Decken-Protokoll <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</li>
  <li><code>OS_SPINLOCK</code>: Mehrkernfähige Synchronisation über OS-Spinlocks zur Koordination zwischen Tasks und ISRs unterschiedlicher Kerne <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</li>
  <li><code>NONE</code>: Verzicht auf interne Sperren, sofern die Datenkonsistenz bereits durch strikte Task-Priorisierung oder Einplanung sichergestellt ist <a class="spec-record-ref" data-req="SWS_Rte_03504" href="../spec/record.html?id=SWS_Rte_03504">[SWS_Rte_03504]</a>.</li>
</ul>
Werden Daten zwischen verschiedenen Speicherschutz-Partitionen übergeben, prüft die RTE Pointer-Parameter, um unberechtigte Speicherzugriffe aus nicht vertrauenswürdigen Partitionen zu unterbinden <a class="spec-record-ref" data-req="SWS_Rte_02752" href="../spec/record.html?id=SWS_Rte_02752">[SWS_Rte_02752]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02753" href="../spec/record.html?id=SWS_Rte_02753">[SWS_Rte_02753]</a>.</p>

<h4>Typische Lebenszyklen und Betriebsmodi</h4>
<p>Der Lebenszyklus des Systems unterliegt einer strikten Phaseneinteilung zwischen Initialisierung, regulärem Betrieb und kontrolliertem Herunterfahren. Beim Systemstart wird zunächst der SchM-Teil initialisiert: Das EcuM ruft auf jedem Prozessorkern `SchM_Start` auf, bevor BSW-Module wie das BswM gestartet werden <a class="spec-record-ref" data-req="SWS_Rte_04546" href="../spec/record.html?id=SWS_Rte_04546">[SWS_Rte_04546]</a>, <a class="spec-record-ref" data-req="SWS_Rte_04548" href="../spec/record.html?id=SWS_Rte_04548">[SWS_Rte_04548]</a>. Anschließend aktiviert `SchM_StartTiming` die periodischen BSW-Events und MainFunctions <a class="spec-record-ref" data-req="SWS_Rte_04549" href="../spec/record.html?id=SWS_Rte_04549">[SWS_Rte_04549]</a>, <a class="spec-record-ref" data-req="SWS_Rte_04551" href="../spec/record.html?id=SWS_Rte_04551">[SWS_Rte_04551]</a>. Gemäß Design-Constraint dürfen `SchM_Start` und `SchM_StartTiming` pro Kern genau einmal aufgerufen werden <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_RTE_SECTION_6_7_3_SchM_StartTiming.html" data-snip="SNIP_CLASSIC_RTE_SECTION_6_7_3_SchM_StartTiming">SWS_RTE S. 928</a>. Danach schaltet `Rte_Start` die Anwendungs-RTE frei; scheitert die interne Ressourcenallokation, bricht die Initialisierung mit `RTE_E_LIMIT` ab <a class="spec-record-ref" data-req="SWS_Rte_01261" href="../spec/record.html?id=SWS_Rte_01261">[SWS_Rte_01261]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01262" href="../spec/record.html?id=SWS_Rte_01262">[SWS_Rte_01262]</a>.</p>
<p>Betriebsmodi werden über Mode-Declaration-Groups abgebildet. Löst ein Mode Manager über `Rte_Switch` einen Moduswechsel aus, wird dieser in einer FIFO-Warteschlange abgelegt <a class="spec-record-ref" data-req="SWS_Rte_02631" href="../spec/record.html?id=SWS_Rte_02631">[SWS_Rte_02631]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02718" href="../spec/record.html?id=SWS_Rte_02718">[SWS_Rte_02718]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02719" href="../spec/record.html?id=SWS_Rte_02719">[SWS_Rte_02719]</a>. Jede Modusmaschine durchläuft während der Umschaltung eine verbindliche 10-stufige Sequenz <a class="spec-record-ref" data-req="SWS_Rte_02665" href="../spec/record.html?id=SWS_Rte_02665">[SWS_Rte_02665]</a>: Zuerst werden Modus-Deaktivierungen für den Zielmodus wirksam geschaltet und laufende Entitäten abgewartet (Schritte 1–2). Es folgt die sequenzielle Ausführung und Terminierung von OnExit- (Schritte 3–4), OnTransition- (Schritte 5–6) und OnEntry-Executable-Entities (Schritte 7–8). Abschließend wird die Deaktivierung des vorherigen Modus aufgehoben und der neue Modus aktiviert (Schritt 9), bevor der Moduswechsel über `ModeSwitchedAckEvent` bzw. `Rte_SwitchAck` quittiert wird (Schritt 10) <a class="spec-record-ref" data-req="SWS_Rte_02665" href="../spec/record.html?id=SWS_Rte_02665">[SWS_Rte_02665]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02679" href="../spec/record.html?id=SWS_Rte_02679">[SWS_Rte_02679]</a>, <a class="spec-record-ref" data-req="SWS_Rte_02725" href="../spec/record.html?id=SWS_Rte_02725">[SWS_Rte_02725]</a>. Über `RteModeToScheduleTableMapping` können Betriebsmodi zudem direkt an OS-Schedule-Tables gekoppelt werden <a class="spec-record-ref" data-req="SWS_Rte_05146" href="../spec/record.html?id=SWS_Rte_05146">[SWS_Rte_05146]</a>.</p>

<h4>Fehlerbehandlung, Statusüberwachung und Datenvalidierung</h4>
<p>Fehlerzustände und Schnittstellenstatus werden in der RTE einheitlich über den skalaren Typ `Std_ReturnType` an den Aufrufer übermittelt <a class="spec-record-ref" data-req="SWS_Rte_01034" href="../spec/record.html?id=SWS_Rte_01034">[SWS_Rte_01034]</a>, <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_STD_SECTION_1_Returned_by_AUTOSAR_Services_to_indicate_a.html" data-snip="SNIP_CLASSIC_STD_SECTION_1_Returned_by_AUTOSAR_Services_to_indicate_a">SWS_RTE S. 586</a>. Die RTE differenziert zwischen Applikationsfehlern (Fehlerwerte 1–63), unmittelbaren Infrastrukturfehlern (Werte 128–255) sowie überlagerten Statusbits wie Datenverlust (`RTE_E_LOST_DATA = 64`) oder Veralterung (`RTE_E_MAX_AGE_EXCEEDED = 64`) <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_CLASSIC_STD_SECTION_1_Returned_by_AUTOSAR_Services_to_indicate_a.html" data-snip="SNIP_CLASSIC_STD_SECTION_1_Returned_by_AUTOSAR_Services_to_indicate_a">SWS_RTE S. 586</a>. Typische Infrastruktur-Rückgabewerte umfassen gestoppte Kommunikation (`RTE_E_COM_STOPPED = 128`), Kommunikations- und Antwort-Timeouts (`RTE_E_TIMEOUT = 129`), fehlende Daten (`RTE_E_NO_DATA = 131`) und Ressourcenüberläufe (`RTE_E_LIMIT = 130`) <a class="spec-record-ref" data-req="SWS_Rte_01060" href="../spec/record.html?id=SWS_Rte_01060">[SWS_Rte_01060]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01061" href="../spec/record.html?id=SWS_Rte_01061">[SWS_Rte_01061]</a>, <a class="spec-record-ref" data-req="SWS_Rte_01064" href="../spec/record.html?id=SWS_Rte_01064">[SWS_Rte_01064]</a>. Bei aktiver Wertebereichsprüfung quittiert die RTE Bereichsüberschreitungen mit `RTE_E_OUT_OF_RANGE` <a class="spec-record-ref" data-req="SWS_Rte_03845" href="../spec/record.html?id=SWS_Rte_03845">[SWS_Rte_03845]</a>, <a class="spec-record-ref" data-req="SWS_Rte_03846" href="../spec/record.html?id=SWS_Rte_03846">[SWS_Rte_03846]</a>.</p>
<p>Zur Behandlung unplausibler oder fehlerhafter Signale stellt die RTE Mechanismen zur Dateninvalidation bereit. Sendeseitig markiert `Rte_Invalidate` das Signal mit einem definierten Ersatzwert <a class="spec-record-ref" data-req="SWS_Rte_01206" href="../spec/record.html?id=SWS_Rte_01206">[SWS_Rte_01206]</a>, <a class="spec-record-ref" data-req="SWS_Rte_05024" href="../spec/record.html?id=SWS_Rte_05024">[SWS_Rte_05024]</a>. Empfängerseitig steuert das Attribut `handleInvalid` die Ersatzstrategie: Bei `keep` wird der bisherige Wert beibehalten und ein `DataReceiveErrorEvent` ausgelöst, während bei `replace` eine automatische Substitution durch den `initValue` erfolgt <a class="spec-record-ref" data-req="SWS_Rte_05030" href="../spec/record.html?id=SWS_Rte_05030">[SWS_Rte_05030]</a>, <a class="spec-record-ref" data-req="SWS_Rte_05049" href="../spec/record.html?id=SWS_Rte_05049">[SWS_Rte_05049]</a>. Kommunikationsausfälle auf Netzwerkebene werden über `aliveTimeout` überwacht; läuft die Überwachungszeit ab, meldet das COM-Modul via `Rte_COMCbkRxTOut` einen Empfangstimeout an die RTE, woraufhin abhängige Komponenten informiert oder Fallback-Werte aktiviert werden <a class="spec-record-ref" data-req="SWS_Rte_08061" href="../spec/record.html?id=SWS_Rte_08061">[SWS_Rte_08061]</a>.</p>
