<p class="ai-level ai-oneliner-lead" data-ai-level="1">Verwaltet persistente Dateien und öffnet sie über RAII-basierte Handles für blockweises Lesen und Schreiben.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::per::FileStorage</code> ermöglicht das Verwalten und Öffnen einer Menge konfigurierter persistenter Dateien über eindeutige Dateinamen <a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a>. Der eigentliche Lese- und Schreibzugriff erfolgt über <code>UniqueHandle</code>-geführte Accessoren, welche die Datei beim Verlassen des Gültigkeitsbereichs automatisch wieder schließen <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>. Da bereits geöffnete Dateien vor konkurrierenden Lösch- oder Wiederherstellungsoperationen geschützt sind, schlagen solche Parallelzugriffe mit <code>PerErrc::kResourceBusy</code> fehl <a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::per::FileStorage</code> kapselt den Zugriff auf eine konfigurierte Sammlung persistenter Dateien, die über eindeutige Dateinamen identifiziert werden. Sie fungiert als zentrale Schnittstelle für Anwendungen, um Dateioperationen wie das Auflisten vorhandener Dateien über <code>GetAllFileNames</code> <a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a>, die Prüfung auf Existenz mittels <code>FileExists</code> <a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a> sowie das Abfragen von Metadaten und Dateigrößen über <code>GetFileInfo</code> <a class="spec-record-ref" data-req="SWS_PER_00438" href="../spec/record.html?id=SWS_PER_00438">[SWS_PER_00438]</a> und <code>GetCurrentFileSize</code> <a class="spec-record-ref" data-req="SWS_PER_00407" href="../spec/record.html?id=SWS_PER_00407">[SWS_PER_00407]</a> durchzuführen. Ein direkter Lese- oder Schreibzugriff auf Byte-Ebene erfolgt dabei nicht auf der Speicherinstanz selbst, sondern vermittelt über spezielle Accessor-Objekte, die von den Öffnungsmethoden als <code>UniqueHandle</code> bereitgestellt werden <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a> <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a> <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>FileStorage</code> unterliegt strengen Beschränkungen: Sowohl der Standardkonstruktor <a class="spec-record-ref" data-req="SWS_PER_00460" href="../spec/record.html?id=SWS_PER_00460">[SWS_PER_00460]</a> als auch Kopier- und Verschiebekonstruktoren <a class="spec-record-ref" data-req="SWS_PER_00328" href="../spec/record.html?id=SWS_PER_00328">[SWS_PER_00328]</a> <a class="spec-record-ref" data-req="SWS_PER_00326" href="../spec/record.html?id=SWS_PER_00326">[SWS_PER_00326]</a> sowie Kopier- und Verschiebezuweisungsoperatoren <a class="spec-record-ref" data-req="SWS_PER_00329" href="../spec/record.html?id=SWS_PER_00329">[SWS_PER_00329]</a> <a class="spec-record-ref" data-req="SWS_PER_00327" href="../spec/record.html?id=SWS_PER_00327">[SWS_PER_00327]</a> sind explizit gelöscht. Eine Instanz von <code>FileStorage</code> dürfte daher typischerweise über plattformseitige Fabrikfunktionen des Persistenzmoduls geöffnet und bereitgestellt werden. <a class="interp-q interp-q-unmatched" data-q-status="unmatched" href="../versions.html?tab=q&amp;qsub=class:adaptive:cl_ara_per_FileStorage_29266b&amp;qst=open" title="Annahmen und Fragen zu diesem Text (Versions- &amp; Provenienz-Explorer)">Frage (offen)</a> Der Destruktor <code>~FileStorage</code> ist ausnahmesicher (<code>noexcept</code>), jedoch explizit als nicht threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_PER_00330" href="../spec/record.html?id=SWS_PER_00330">[SWS_PER_00330]</a>, weshalb sichergestellt sein muss, dass während der Zerstörung keine nebenläufigen Aufrufe auf dem Objekt stattfinden.</p>
<p>Im laufenden Betrieb sind die regulären Dateioperationen wie <code>FileExists</code>, <code>DeleteFile</code> oder das Öffnen von Dateien threadsicher ausgelegt <a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a> <a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a> <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a>. Allerdings ist zu beachten, dass Ergebnisse von Statusabfragen wie <code>GetAllFileNames</code> <a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a> oder <code>FileExists</code> <a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a> nur dann präzise Gültigkeit besitzen, wenn nicht zeitgleich in einem anderen Thread Dateien hinzugefügt oder gelöscht werden. Ähnliches gilt für <code>GetFileInfo</code>: Modifikations- und Zugriffszeiten sowie der Bearbeitungsstatus sind nur verlässlich akkurat, solange die Zieldatei nicht geöffnet ist <a class="spec-record-ref" data-req="SWS_PER_00438" href="../spec/record.html?id=SWS_PER_00438">[SWS_PER_00438]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad umfasst die Prüfung, das gezielte Öffnen, die Datenverarbeitung über das Accessor-Handle und die abschließende Bereinigung:</p>
<ol>
<li><strong>Dateistatus prüfen:</strong> Vor dem Zugriff kann optional über <code>FileExists</code> ermittelt werden, ob eine gewünschte Datei vorhanden ist <a class="spec-record-ref" data-req="SWS_PER_00112" href="../spec/record.html?id=SWS_PER_00112">[SWS_PER_00112]</a>, oder über <code>GetAllFileNames</code> der Bestand abgefragt werden <a class="spec-record-ref" data-req="SWS_PER_00110" href="../spec/record.html?id=SWS_PER_00110">[SWS_PER_00110]</a>.</li>
<li><strong>Datei öffnen:</strong> Je nach beabsichtigtem Zugriffsmodus stellt die Klasse dedizierte Methoden bereit. Für reinen Lesezugriff stehen <code>OpenFileReadOnly</code>-Überladungen zur Verfügung <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a> <a class="spec-record-ref" data-req="SWS_PER_00376" href="../spec/record.html?id=SWS_PER_00376">[SWS_PER_00376]</a> <a class="spec-record-ref" data-req="SWS_PER_00430" href="../spec/record.html?id=SWS_PER_00430">[SWS_PER_00430]</a>. Für Lese- und Schreibzugriff dient <code>OpenFileReadWrite</code> <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a> <a class="spec-record-ref" data-req="SWS_PER_00375" href="../spec/record.html?id=SWS_PER_00375">[SWS_PER_00375]</a> <a class="spec-record-ref" data-req="SWS_PER_00429" href="../spec/record.html?id=SWS_PER_00429">[SWS_PER_00429]</a>, wobei eine nicht existierende Datei automatisch neu angelegt wird. Für reines Schreiben existiert <code>OpenFileWriteOnly</code> <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a> <a class="spec-record-ref" data-req="SWS_PER_00377" href="../spec/record.html?id=SWS_PER_00377">[SWS_PER_00377]</a> <a class="spec-record-ref" data-req="SWS_PER_00431" href="../spec/record.html?id=SWS_PER_00431">[SWS_PER_00431]</a>, welches die Datei standardmäßig abschneidet (<code>kTruncate</code>) oder neu erzeugt. Zur Leistungssteigerung bei vielen kleinen Zugriffen erlauben Überladungen die Übergabe eines anwenderdefinierten Puffers für blockweises Lesen bzw. Schreiben <a class="spec-record-ref" data-req="SWS_PER_00430" href="../spec/record.html?id=SWS_PER_00430">[SWS_PER_00430]</a> <a class="spec-record-ref" data-req="SWS_PER_00429" href="../spec/record.html?id=SWS_PER_00429">[SWS_PER_00429]</a> <a class="spec-record-ref" data-req="SWS_PER_00431" href="../spec/record.html?id=SWS_PER_00431">[SWS_PER_00431]</a>.</li>
<li><strong>Datei schließen und Ressourcen freigeben:</strong> Das von den Öffnungsmethoden zurückgegebene <code>ara::core::Result</code> kapselt ein <code>UniqueHandle</code> auf den jeweiligen Accessor. Die Datei wird automatisch geschlossen, sobald dieses <code>UniqueHandle</code> seinen Gültigkeitsbereich verlässt <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a> <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a> <a class="spec-record-ref" data-req="SWS_PER_00115" href="../spec/record.html?id=SWS_PER_00115">[SWS_PER_00115]</a>. Vermutlich wird hierbei auch die dateibezogene Belegungsmarkierung in <code>FileStorage</code> aufgehoben. <a class="interp-q interp-q-unmatched" data-q-status="unmatched" href="../versions.html?tab=q&amp;qsub=class:adaptive:cl_ara_per_FileStorage_29266b&amp;qst=open" title="Annahmen und Fragen zu diesem Text (Versions- &amp; Provenienz-Explorer)">Frage (offen)</a></li>
<li><strong>Wartung und Bereinigung:</strong> Nicht mehr benötigte Dateien werden mit <code>DeleteFile</code> gelöscht <a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a>. Bei Integritätsverletzungen bietet <code>RecoverFile</code> eine Best-Effort-Wiederherstellung redundanter Daten <a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a>, während <code>ResetFile</code> eine Datei auf ihren initialen Bereitstellungsinhalt zurücksetzt oder bei Fehlen neu anlegt <a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Methoden von <code>FileStorage</code> signalisieren Fehler über <code>ara::core::Result</code> unter Verwendung des Fehler-Enums <code>PerErrc</code>. Zu den wichtigsten Fehlersituationen zählen:</p>
<ul>
<li><strong>Ressourcenkonflikte (<code>PerErrc::kResourceBusy</code>):</strong> Eine Datei kann nicht geöffnet, gelöscht, wiederhergestellt oder zurückgesetzt werden, wenn sie bereits geöffnet ist oder parallel ein <code>DeleteFile</code>, <code>RecoverFile</code> bzw. <code>ResetFile</code> auf demselben Dateinamen ausgeführt wird <a class="spec-record-ref" data-req="SWS_PER_00111" href="../spec/record.html?id=SWS_PER_00111">[SWS_PER_00111]</a> <a class="spec-record-ref" data-req="SWS_PER_00114" href="../spec/record.html?id=SWS_PER_00114">[SWS_PER_00114]</a> <a class="spec-record-ref" data-req="SWS_PER_00113" href="../spec/record.html?id=SWS_PER_00113">[SWS_PER_00113]</a> <a class="spec-record-ref" data-req="SWS_PER_00337" href="../spec/record.html?id=SWS_PER_00337">[SWS_PER_00337]</a> <a class="spec-record-ref" data-req="SWS_PER_00338" href="../spec/record.html?id=SWS_PER_00338">[SWS_PER_00338]</a>.</li>
