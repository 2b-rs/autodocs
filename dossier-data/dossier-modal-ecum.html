<p class="ai-level ai-oneliner-lead" data-ai-level="1">Steuert Hochlauf, Abschalten, Schlafphasen und Weckquellen des Steuergeräts im Zusammenspiel mit dem BswM.</p>
<div class="ai-level" data-ai-level="2">
<p>Der ECU State Manager steuert den Lebenszyklus eines Classic-Steuergeräts. Er initialisiert die Basissoftware bis zum OS-Start, führt die ECU in die Shutdown-Ziele SLEEP, RESET oder OFF und verwaltet die Weckquellen samt Validierung <a class="spec-record-ref" data-req="SWS_EcuM_04136" href="../../spec/record.html?id=SWS_EcuM_04136">[SWS_EcuM_04136]</a>. Hardwarenahe Schritte übernimmt der Integration Code über Callouts. Die RUN- und POST_RUN-Anforderungen der Nutzer arbitriert der EcuM, doch über die Zustandsübergänge entscheidet der BswM und meldet sie per <code>EcuM_SetState</code> zurück <a class="spec-record-ref" data-req="SWS_EcuM_04116" href="../../spec/record.html?id=SWS_EcuM_04116">[SWS_EcuM_04116]</a>. Wichtigste Randbedingung ist, dass in der SLEEP-Phase kein Weckereignis verloren gehen darf.</p>

<div class="ai-level" data-ai-level="3">
<p>Der ECU State Manager (EcuM) ist in der Classic Platform für Hochlauf, Abschalten und Schlafphasen des Steuergeräts zuständig. <code>EcuM_Init</code> führt die StartPreOS-Sequenz mit den Init-Blöcken 0 und 1 aus. Dabei wählt und prüft der EcuM die Post-Build-Konfiguration und ruft schließlich <code>StartOS</code> auf. Danach startet <code>EcuM_StartupTwo</code> den SchM und den BswM <a class="spec-record-ref" data-req="SWS_EcuM_02684" href="../../spec/record.html?id=SWS_EcuM_02684">[SWS_EcuM_02684]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02906" href="../../spec/record.html?id=SWS_EcuM_02906">[SWS_EcuM_02906]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02932" href="../../spec/record.html?id=SWS_EcuM_02932">[SWS_EcuM_02932]</a>. Hardwarenahe Schritte liefert der Integration Code als Callouts, zum Beispiel <code>EcuM_AL_DriverInitZero</code> <a class="spec-record-ref" data-req="SWS_EcuM_02905" href="../../spec/record.html?id=SWS_EcuM_02905">[SWS_EcuM_02905]</a>.</p>

<p class="diagram-note">Zustandsdiagramm: Die ECU durchläuft STARTUP, UP, SHUTDOWN und SLEEP. Aus SLEEP kehrt sie über WakeupRestart nach UP zurück. Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-4c52e2f7f4bd0e4a.html" data-snip="FIG-4c52e2f7f4bd0e4a">RS ModeManagement S. 15</a>, <a class="spec-record-ref" data-req="SWS_EcuM_91005" href="../../spec/record.html?id=SWS_EcuM_91005">[SWS_EcuM_91005]</a>, <a class="spec-record-ref" data-req="SWS_EcuM_02963" href="../../spec/record.html?id=SWS_EcuM_02963">[SWS_EcuM_02963]</a></p>
<p>Über Zustandsübergänge entscheidet der EcuM nicht selbst. Er sammelt die RUN- und POST_RUN-Anforderungen der konfigurierten Nutzer und meldet das Ergebnis dem BswM. Dessen Zustandswechsel übernimmt er über <code>EcuM_SetState</code> und gibt sie an die RTE weiter <a class="spec-record-ref" data-req="SWS_EcuM_04144" href="../../spec/record.html?id=SWS_EcuM_04144">[SWS_EcuM_04144]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04117" href="../../spec/record.html?id=SWS_EcuM_04117">[SWS_EcuM_04117]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04116" href="../../spec/record.html?id=SWS_EcuM_04116">[SWS_EcuM_04116]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_10_EcuM_Mode_Handling.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_10_EcuM_Mode_Handling">SWS EcuM S. 103</a>. <code>EcuM_SelectShutdownTarget</code> speichert das Ziel SLEEP, RESET oder OFF nur für später <a class="spec-record-ref" data-req="SWS_EcuM_02585" href="../../spec/record.html?id=SWS_EcuM_02585">[SWS_EcuM_02585]</a>. Beim Abschalten deinitialisiert OffPreOS den BswM und den SchM, prüft die Weckereignisse und beendet das OS. Der Shutdown-Hook ruft dann <code>EcuM_Shutdown</code>, das mit <code>EcuM_AL_Reset</code> oder <code>EcuM_AL_SwitchOff</code> endet <a class="spec-record-ref" data-req="SWS_EcuM_03021" href="../../spec/record.html?id=SWS_EcuM_03021">[SWS_EcuM_03021]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04074" href="../../spec/record.html?id=SWS_EcuM_04074">[SWS_EcuM_04074]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04075" href="../../spec/record.html?id=SWS_EcuM_04075">[SWS_EcuM_04075]</a>.</p>
<p>Die SLEEP-Phase beginnt mit <code>EcuM_GoDownHaltPoll</code>. Zuerst aktiviert GoSleep die Weckquellen des Schlafmodus. Danach folgt entweder Halt mit RAM-Hash-Prüfung oder Poll mit einer Schleife über <code>EcuM_SleepActivity</code> und <code>EcuM_CheckWakeup</code>. Den Abschluss bildet WakeupRestart mit <code>EcuM_AL_DriverRestart</code> <a class="spec-record-ref" data-req="SWS_EcuM_91002" href="../../spec/record.html?id=SWS_EcuM_91002">[SWS_EcuM_91002]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02389" href="../../spec/record.html?id=SWS_EcuM_02389">[SWS_EcuM_02389]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02863" href="../../spec/record.html?id=SWS_EcuM_02863">[SWS_EcuM_02863]</a> <a class="spec-record-ref" data-req="SWS_EcuM_03020" href="../../spec/record.html?id=SWS_EcuM_03020">[SWS_EcuM_03020]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02963" href="../../spec/record.html?id=SWS_EcuM_02963">[SWS_EcuM_02963]</a>. In dieser Phase darf kein Weckereignis verloren gehen <a class="spec-record-ref" data-req="SWS_EcuM_02188" href="../../spec/record.html?id=SWS_EcuM_02188">[SWS_EcuM_02188]</a>.</p>
<p>Weckquellen sind einzelne Bits in <code>EcuM_WakeupSourceType</code> und haben jeweils einen der Zustände NONE, PENDING, VALIDATED oder EXPIRED <a class="spec-record-ref" data-req="SWS_EcuM_04040" href="../../spec/record.html?id=SWS_EcuM_04040">[SWS_EcuM_04040]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04091" href="../../spec/record.html?id=SWS_EcuM_04091">[SWS_EcuM_04091]</a>. Treiber melden Ereignisse mit <code>EcuM_SetWakeupEvent</code>. Ist eine Validierung konfiguriert, startet der EcuM einen Timeout. Nur ein <code>EcuM_ValidateWakeupEvent</code> vor dessen Ablauf führt zu VALIDATED; bei konfiguriertem Kanalbezug wird dann auch ComM informiert. <h4>Rolle und Systemgrenze des ECU State Managers</h4>
<p>Der ECU State Manager (EcuM) gibt in der Classic Platform den Rahmen für den Lebenszyklus des Steuergeräts vor. Er initialisiert die Basissoftware bis zum Start des Betriebssystems. Danach führt er die ECU kontrolliert in eines der Shutdown-Ziele SLEEP, RESET oder OFF <a class="spec-record-ref" data-req="SWS_EcuM_04136" href="../../spec/record.html?id=SWS_EcuM_04136">[SWS_EcuM_04136]</a>. Seine Zustände legt <code>EcuM_StateType</code> fest: STARTUP, RUN, POST_RUN, SHUTDOWN und SLEEP <a class="spec-record-ref" data-req="SWS_EcuM_91005" href="../../spec/record.html?id=SWS_EcuM_91005">[SWS_EcuM_91005]</a>. Den SW-Cs meldet er sie über die Mode-Declaration-Group <code>EcuM_Mode</code>, deren Initialmodus STARTUP ist <a class="spec-record-ref" data-req="SWS_EcuM_04107" href="../../spec/record.html?id=SWS_EcuM_04107">[SWS_EcuM_04107]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04132" href="../../spec/record.html?id=SWS_EcuM_04132">[SWS_EcuM_04132]</a>.</p>

<p class="diagram-note">Zustandsdiagramm: Die ECU durchläuft STARTUP, UP, SHUTDOWN und SLEEP. Aus SLEEP kehrt sie über WakeupRestart nach UP zurück, nach einem Hardware-Reset oder Power-Cycle startet sie in STARTUP neu. Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-4c52e2f7f4bd0e4a.html" data-snip="FIG-4c52e2f7f4bd0e4a">RS ModeManagement S. 15</a>, <a class="spec-record-ref" data-req="SWS_EcuM_91005" href="../../spec/record.html?id=SWS_EcuM_91005">[SWS_EcuM_91005]</a>, <a class="spec-record-ref" data-req="SWS_EcuM_02963" href="../../spec/record.html?id=SWS_EcuM_02963">[SWS_EcuM_02963]</a>, <a class="spec-record-ref" data-req="SWS_EcuM_04001" href="../../spec/record.html?id=SWS_EcuM_04001">[SWS_EcuM_04001]</a></p>
<p>Über die Zustandsübergänge entscheidet nicht der EcuM selbst. Er besitzt keine eigene Zustandsmaschine, arbitriert nur die Anforderungen und überlässt die Übergänge dem BSW Mode Manager (BswM) <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_10_EcuM_Mode_Handling.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_10_EcuM_Mode_Handling">SWS EcuM S. 103</a>. Hardwarenahe und projektspezifische Schritte lagert er in Callouts des Integration Code aus, die über <code>EcuM_Externals.h</code> bereitstehen. Beispiele sind <code>EcuM_AL_DriverInitZero</code> und <code>EcuM_AL_SwitchOff</code> <a class="spec-record-ref" data-req="SWS_EcuM_02905" href="../../spec/record.html?id=SWS_EcuM_02905">[SWS_EcuM_02905]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02920" href="../../spec/record.html?id=SWS_EcuM_02920">[SWS_EcuM_02920]</a>. Die Schnittstellen der Nachbarmodule sind in den Tabellen der importierten Funktionen aufgeführt, etwa <code>BswM_EcuM_CurrentWakeup</code>, <code>Can_Init</code> und <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_EcuM_02858" href="../../spec/record.html?id=SWS_EcuM_02858">[SWS_EcuM_02858]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02859" href="../../spec/record.html?id=SWS_EcuM_02859">[SWS_EcuM_02859]</a>.</p>

<h4>Hochlauf: StartPreOS, StartPostOS und Konfigurationsdaten</h4>
<p>Vor <code>EcuM_Init</code> setzt der EcuM nur eine minimale MCU-Initialisierung voraus: Ein Stack ist eingerichtet und die C-Variablen sind initialisiert <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_3_1_Activities_before_EcuM_Init.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_3_1_Activities_before_EcuM_Init">SWS EcuM S. 39</a>. <code>EcuM_Init</code> führt die StartPreOS-Sequenz aus und kehrt nicht zurück, weil sie <code>StartOS</code> aufruft <a class="spec-record-ref" data-req="SWS_EcuM_02811" href="../../spec/record.html?id=SWS_EcuM_02811">[SWS_EcuM_02811]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02684" href="../../spec/record.html?id=SWS_EcuM_02684">[SWS_EcuM_02684]</a>. Dabei werden alle Module initialisiert, die für den OS-Start nötig sind <a class="spec-record-ref" data-req="SWS_EcuM_02603" href="../../spec/record.html?id=SWS_EcuM_02603">[SWS_EcuM_02603]</a>.</p>
<p>Init Block 0 (<code>EcuM_AL_DriverInitZero</code>) bereitet das Laden der Post-Build-Daten vor. Er darf deshalb nur Module verwenden, die zur Pre-Compile- oder Link-Zeit konfiguriert sind <a class="spec-record-ref" data-req="SWS_EcuM_02905" href="../../spec/record.html?id=SWS_EcuM_02905">[SWS_EcuM_02905]</a>. Anschließend liefert <code>EcuM_DeterminePbConfiguration</code> einen Zeiger auf <code>EcuM_ConfigType</code>. Diese Struktur referenziert die Konfigurationen aller weiteren BSW-Module <a class="spec-record-ref" data-req="SWS_EcuM_02906" href="../../spec/record.html?id=SWS_EcuM_02906">[SWS_EcuM_02906]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02801" href="../../spec/record.html?id=SWS_EcuM_02801">[SWS_EcuM_02801]</a>. Sie enthält einen Variantenbezeichner und einen Hash. Den Hash prüft der EcuM gegen <code>ECUM_CONFIGCONSISTENCY_HASH</code>, und zwar für alle post-build-konfigurierbaren Module, bevor das erste davon initialisiert wird <a class="spec-record-ref" data-req="SWS_EcuM_02794" href="../../spec/record.html?id=SWS_EcuM_02794">[SWS_EcuM_02794]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02798" href="../../spec/record.html?id=SWS_EcuM_02798">[SWS_EcuM_02798]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02796" href="../../spec/record.html?id=SWS_EcuM_02796">[SWS_EcuM_02796]</a>.</p>
<p>Init Block 1 (<code>EcuM_AL_DriverInitOne</code>) initialisiert die Treiber nach einem Power-on-Reset, darunter die MCU <a class="spec-record-ref" data-req="SWS_EcuM_02907" href="../../spec/record.html?id=SWS_EcuM_02907">[SWS_EcuM_02907]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_8_5_2_4_EcuM_AL_DriverInitOne.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_8_5_2_4_EcuM_AL_DriverInitOne">SWS EcuM S. 146</a>. Die Reihenfolge in beiden Blöcken legen <code>EcuMDriverInitListZero</code> und <code>EcuMDriverInitListOne</code> fest. Jede Init-Funktion erhält ihre Parameter aus dem zugehörigen <code>EcuMModuleService</code>-Container <a class="spec-record-ref" data-req="SWS_EcuM_02559" href="../../spec/record.html?id=SWS_EcuM_02559">[SWS_EcuM_02559]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02730" href="../../spec/record.html?id=SWS_EcuM_02730">[SWS_EcuM_02730]</a>. Den Reset-Grund des Mcu-Treibers übersetzt der EcuM in eine Weckquelle und merkt sie sich. Lässt sich der Grund nicht bestimmen, setzt er <code>ECUM_WKSOURCE_RESET</code> <a class="spec-record-ref" data-req="SWS_EcuM_02623" href="../../spec/record.html?id=SWS_EcuM_02623">[SWS_EcuM_02623]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02601" href="../../spec/record.html?id=SWS_EcuM_02601">[SWS_EcuM_02601]</a>. Ist <code>EcuMResetLoopDetection</code> gesetzt, ruft der EcuM bei jedem Start den Callout <code>EcuM_LoopDetection</code> auf <a class="spec-record-ref" data-req="SWS_EcuM_04137" href="../../spec/record.html?id=SWS_EcuM_04137">[SWS_EcuM_04137]</a>.</p>

<h4>RUN und POST_RUN: Nutzeranforderungen und Arbitrierung mit dem BswM</h4>
<p>Ist <code>EcuMModeHandling</code> aktiv, können Nutzer RUN und POST_RUN anfordern und wieder freigeben <a class="spec-record-ref" data-req="SWS_EcuM_04115" href="../../spec/record.html?id=SWS_EcuM_04115">[SWS_EcuM_04115]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04130" href="../../spec/record.html?id=SWS_EcuM_04130">[SWS_EcuM_04130]</a>. Dazu dienen <code>EcuM_RequestRUN</code>, <code>EcuM_ReleaseRUN</code>, <code>EcuM_RequestPOST_RUN</code> und <code>EcuM_ReleasePOST_RUN</code>. Alle vier erwarten eine konfigurierte Nutzerkennung vom Typ <code>EcuM_UserType</code> <a class="spec-record-ref" data-req="SWS_EcuM_04124" href="../../spec/record.html?id=SWS_EcuM_04124">[SWS_EcuM_04124]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04127" href="../../spec/record.html?id=SWS_EcuM_04127">[SWS_EcuM_04127]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04128" href="../../spec/record.html?id=SWS_EcuM_04128">[SWS_EcuM_04128]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04129" href="../../spec/record.html?id=SWS_EcuM_04129">[SWS_EcuM_04129]</a>. Der EcuM verfolgt Anforderungen je Nutzer, und ein Nutzer kann sie nicht schachteln. RUN- und POST_RUN-Anforderungen führt er in getrennten Variablen <a class="spec-record-ref" data-req="SWS_EcuM_04126" href="../../spec/record.html?id=SWS_EcuM_04126">[SWS_EcuM_04126]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04125" href="../../spec/record.html?id=SWS_EcuM_04125">[SWS_EcuM_04125]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_8_3_3_4_EcuM_RequestPOST_RUN.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_8_3_3_4_EcuM_RequestPOST_RUN">SWS EcuM S. 116</a>. SW-Cs erreichen diese Dienste über den Port <code>StateRequest_{UserName}</code> <a class="spec-record-ref" data-req="SWS_EcuM_04135" href="../../spec/record.html?id=SWS_EcuM_04135">[SWS_EcuM_04135]</a>.</p>
<p>Die erste RUN- oder POST_RUN-Anforderung meldet der EcuM dem BswM mit <code>BswM_EcuM_RequestedState(ECUM_STATE_APP_RUN, ECUM_RUNSTATUS_REQUESTED)</code>. Die letzte Freigabe von RUN bzw. POST_RUN meldet er mit dem jeweiligen Zustand und <code>ECUM_RUNSTATUS_RELEASED</code> <a class="spec-record-ref" data-req="SWS_EcuM_04144" href="../../spec/record.html?id=SWS_EcuM_04144">[SWS_EcuM_04144]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04117" href="../../spec/record.html?id=SWS_EcuM_04117">[SWS_EcuM_04117]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04119" href="../../spec/record.html?id=SWS_EcuM_04119">[SWS_EcuM_04119]</a>. Der BswM wertet seine Regeln aus und setzt den neuen Zustand mit <code>EcuM_SetState</code>. Der EcuM zeigt der RTE daraufhin den passenden Modus an und meldet nach deren Rückmeldung <code>BswM_EcuM_CurrentState</code> <a class="spec-record-ref" data-req="SWS_EcuM_04122" href="../../spec/record.html?id=SWS_EcuM_04122">[SWS_EcuM_04122]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04116" href="../../spec/record.html?id=SWS_EcuM_04116">[SWS_EcuM_04116]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04143" href="../../spec/record.html?id=SWS_EcuM_04143">[SWS_EcuM_04143]</a>. Der Mode-Management-Guide zeigt passende BswM-Regeln, zum Beispiel den Wechsel nach POST_RUN, sobald RUN freigegeben ist <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_2_Running.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_2_Running">Mode-Management-Guide S. 34</a>.</p>

<h4>Shutdown-Ziele und das Abschalten über OffPreOS und OffPostOS</h4>
<p><code>EcuM_SelectShutdownTarget</code> speichert Ziel und Modus nur für die spätere SHUTDOWN- oder SLEEP-Phase und stößt selbst nichts an <a class="spec-record-ref" data-req="SWS_EcuM_02822" href="../../spec/record.html?id=SWS_EcuM_02822">[SWS_EcuM_02822]</a> <a class="spec-record-ref" data-req="SWS_EcuM_00624" href="../../spec/record.html?id=SWS_EcuM_00624">[SWS_EcuM_00624]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02585" href="../../spec/record.html?id=SWS_EcuM_02585">[SWS_EcuM_02585]</a>. Der Modusparameter wählt beim Ziel SLEEP einen konfigurierten Schlafmodus und beim Ziel RESET einen Reset-Modus. Bei OFF wird er ignoriert <a class="spec-record-ref" data-req="SWS_EcuM_02979" href="../../spec/record.html?id=SWS_EcuM_02979">[SWS_EcuM_02979]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02185" href="../../spec/record.html?id=SWS_EcuM_02185">[SWS_EcuM_02185]</a>. Zu den Reset-Modi gehören mindestens <code>Mcu_PerformReset</code>, <code>WdgM_PerformReset</code> und das Umschalten eines I/O-Pins <a class="spec-record-ref" data-req="SWS_EcuM_04005" href="../../spec/record.html?id=SWS_EcuM_04005">[SWS_EcuM_04005]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04044" href="../../spec/record.html?id=SWS_EcuM_04044">[SWS_EcuM_04044]</a>. Die Ursache eines Shutdowns wird mit <code>EcuM_SelectShutdownCause</code> festgehalten <a class="spec-record-ref" data-req="SWS_EcuM_04007" href="../../spec/record.html?id=SWS_EcuM_04007">[SWS_EcuM_04007]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04050" href="../../spec/record.html?id=SWS_EcuM_04050">[SWS_EcuM_04050]</a>. <code>EcuM_GetLastShutdownTarget</code> liefert das Ziel, aus dem zuletzt geweckt oder hochgefahren wurde. Dieser Wert bleibt bis zum nächsten Shutdown unverändert <a class="spec-record-ref" data-req="SWS_EcuM_02156" href="../../spec/record.html?id=SWS_EcuM_02156">[SWS_EcuM_02156]</a>.</p>
<p>Die SHUTDOWN-Phase endet entweder in OFF oder in RESET <a class="spec-record-ref" data-req="SWS_EcuM_03022" href="../../spec/record.html?id=SWS_EcuM_03022">[SWS_EcuM_03022]</a>. Wann das Ziel gesetzt wird, bestimmt in der Regel der BswM <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_7_Shutdown_Targets.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_7_Shutdown_Targets">SWS EcuM S. 66</a>. In OffPreOS werden BswM und SchM deinitialisiert und die Weckereignisse geprüft. Stehen Ereignisse an, wird RESET als Ziel gesetzt. Die letzte Aktion ist <code>ShutdownOS</code> <a class="spec-record-ref" data-req="SWS_EcuM_03021" href="../../spec/record.html?id=SWS_EcuM_03021">[SWS_EcuM_03021]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02952" href="../../spec/record.html?id=SWS_EcuM_02952">[SWS_EcuM_02952]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_4_1_Activities_in_the_OffPreOS_Sequence.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_4_1_Activities_in_the_OffPreOS_Sequence">SWS EcuM S. 49</a>.</p>
<p>Anschließend ruft der Shutdown-Hook <code>EcuM_Shutdown</code> auf, das nicht zurückkehrt. Nach <code>EcuM_OnGoOffTwo</code> folgt beim Ziel RESET <code>EcuM_AL_Reset</code> und beim Ziel OFF <code>EcuM_AL_SwitchOff</code> <a class="spec-record-ref" data-req="SWS_EcuM_02953" href="../../spec/record.html?id=SWS_EcuM_02953">[SWS_EcuM_02953]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02917" href="../../spec/record.html?id=SWS_EcuM_02917">[SWS_EcuM_02917]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04074" href="../../spec/record.html?id=SWS_EcuM_04074">[SWS_EcuM_04074]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04075" href="../../spec/record.html?id=SWS_EcuM_04075">[SWS_EcuM_04075]</a>. Interpretation: Auch bei RESET und OFF dürfte der BswM die Phase über <code>EcuM_GoDownHaltPoll</code> auslösen, denn dessen Rückgabebeschreibung unterscheidet nach dem Shutdown-Ziel <a class="spec-record-ref" data-req="SWS_EcuM_91002" href="../../spec/record.html?id=SWS_EcuM_91002">[SWS_EcuM_91002]</a>. <a class="interp-q interp-q-open" data-q="Q-29bca5a7c6e82c98" data-q-status="open" href="../../versions.html?tab=q&amp;id=Q-29bca5a7c6e82c98" title="Frage Q-29bca5a7c6e82c98 (offen): EcuM_GoDownHaltPoll löst vermutlich auch bei den Zielen RESET und OFF die SHUTDOWN-Phase aus (Text Abschnitt Shutdown sowie Notiz in diag-shutdown)">Frage Q-29bca5a7c6e82c98 (offen)</a></p>

<h4>SLEEP-Phase: GoSleep, Halt oder Poll und WakeupRestart</h4>
<p>Ist SLEEP als Ziel gewählt, leitet <code>EcuM_GoDownHaltPoll</code> die SLEEP-Phase ein. Der Aufrufer muss das passende Ziel vorher gesetzt haben <a class="spec-record-ref" data-req="SWS_EcuM_91002" href="../../spec/record.html?id=SWS_EcuM_91002">[SWS_EcuM_91002]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_STD_SECTION_7_5_SLEEP_Phase.html" data-snip="SNIP_CLASSIC_STD_SECTION_7_5_SLEEP_Phase">SWS EcuM S. 54</a>. In GoSleep aktiviert der EcuM per <code>EcuM_EnableWakeupSources</code> alle Weckquellen aus <code>EcuMWakeupSourceMask</code> des Ziel-Schlafmodus. Auf Mehrkern-ECUs belegt er zusätzlich die kernspezifische Ressource <code>RES_AUTOSAR_ECUM</code>. Anders als beim Shutdown bleibt das OS aktiv <a class="spec-record-ref" data-req="SWS_EcuM_02389" href="../../spec/record.html?id=SWS_EcuM_02389">[SWS_EcuM_02389]</a> <a class="spec-record-ref" data-req="SWS_EcuM_03010" href="../../spec/record.html?id=SWS_EcuM_03010">[SWS_EcuM_03010]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02951" href="../../spec/record.html?id=SWS_EcuM_02951">[SWS_EcuM_02951]</a>. Kein Weckereignis darf verloren gehen. Ist schon während GoSleep eines eingetreten, werden Halt und Poll übersprungen <a class="spec-record-ref" data-req="SWS_EcuM_02188" href="../../spec/record.html?id=SWS_EcuM_02188">[SWS_EcuM_02188]</a>.</p>
<p>Schlafmodi, die den Mikrocontroller anhalten, durchlaufen die Halt-Sequenz. Davor ruft der EcuM <code>EcuM_GenerateRamHash</code> auf, danach <code>EcuM_CheckRamHash</code> <a class="spec-record-ref" data-req="SWS_EcuM_02960" href="../../spec/record.html?id=SWS_EcuM_02960">[SWS_EcuM_02960]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02863" href="../../spec/record.html?id=SWS_EcuM_02863">[SWS_EcuM_02863]</a>. Schlafmodi mit reduziertem Takt nutzen dagegen die Poll-Sequenz. Sie ruft <code>EcuM_SleepActivity</code> und <code>EcuM_CheckWakeup</code> in einer blockierenden Schleife auf, bis ein Ereignis als pending oder validiert gemeldet ist <a class="spec-record-ref" data-req="SWS_EcuM_02962" href="../../spec/record.html?id=SWS_EcuM_02962">[SWS_EcuM_02962]</a> <a class="spec-record-ref" data-req="SWS_EcuM_03020" href="../../spec/record.html?id=SWS_EcuM_03020">[SWS_EcuM_03020]</a>. In R20-11 ist <code>EcuM_CheckWakeup</code> noch ein Callout. Erst ab R21-11 heißt dieser Callout <code>EcuM_CheckWakeupHook</code> <a class="spec-record-ref" data-req="SWS_EcuM_02929" href="../../spec/record.html?id=SWS_EcuM_02929">[SWS_EcuM_02929]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_8_5_4_5_EcuM_CheckWakeupHook.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_8_5_4_5_EcuM_CheckWakeupHook">SWS EcuM S. 145</a>.</p>
<p>Ein Weckereignis führt in die WakeupRestart-Sequenz <a class="spec-record-ref" data-req="SWS_EcuM_02963" href="../../spec/record.html?id=SWS_EcuM_02963">[SWS_EcuM_02963]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_5_5_Activities_in_the_WakeupRestart_Sequence.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_5_5_Activities_in_the_WakeupRestart_Sequence">SWS EcuM S. 56</a>:</p>
<ol>
<li>Die MCU kehrt in den Normalmodus zurück.</li>
<li><code>EcuM_DisableWakeupSources</code> deaktiviert die gerade anstehenden Weckquellen; alle anderen bleiben scharf <a class="spec-record-ref" data-req="SWS_EcuM_02922" href="../../spec/record.html?id=SWS_EcuM_02922">[SWS_EcuM_02922]</a>.</li>
<li><code>EcuM_AL_DriverRestart</code> initialisiert die betroffenen Treiber neu <a class="spec-record-ref" data-req="SWS_EcuM_02923" href="../../spec/record.html?id=SWS_EcuM_02923">[SWS_EcuM_02923]</a>.</li>
<li>Der Scheduler wird wieder freigegeben.</li>
</ol>
<p>Tritt während des Schlafs ein Hardware-Reset oder ein Power-Cycle auf, beginnt die ECU dagegen neu in STARTUP <a class="spec-record-ref" data-req="SWS_EcuM_04001" href="../../spec/record.html?id=SWS_EcuM_04001">[SWS_EcuM_04001]</a>.</p>

<h4>Weckquellen: Zustände, Validierung und Abfrage</h4>
<p>Der EcuM verwaltet bis zu 32 Weckquellen als Bitmaske vom Typ <code>EcuM_WakeupSourceType</code>. Fünf Bits sind vordefiniert, darunter <code>ECUM_WKSOURCE_POWER</code> und <code>ECUM_WKSOURCE_RESET</code>. Weitere Quellen erhalten über <code>EcuMWakeupSourceId</code> die Bits 5 bis 31 <a class="spec-record-ref" data-req="SWS_EcuM_04040" href="../../spec/record.html?id=SWS_EcuM_04040">[SWS_EcuM_04040]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02165" href="../../spec/record.html?id=SWS_EcuM_02165">[SWS_EcuM_02165]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02166" href="../../spec/record.html?id=SWS_EcuM_02166">[SWS_EcuM_02166]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_6_3_Internal_Representation_of_Wakeup_States.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_6_3_Internal_Representation_of_Wakeup_States">SWS EcuM S. 63</a>. Jede Quelle befindet sich in einem der Zustände NONE, PENDING, VALIDATED oder EXPIRED <a class="spec-record-ref" data-req="SWS_EcuM_04091" href="../../spec/record.html?id=SWS_EcuM_04091">[SWS_EcuM_04091]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04041" href="../../spec/record.html?id=SWS_EcuM_04041">[SWS_EcuM_04041]</a>. Jeden Zustandswechsel meldet der EcuM dem BswM als Mode-Request <a class="spec-record-ref" data-req="SWS_EcuM_04003" href="../../spec/record.html?id=SWS_EcuM_04003">[SWS_EcuM_04003]</a>.</p>

<p class="diagram-note">Zustandsdiagramm: Eine Weckquelle geht von NONE über PENDING nach VALIDATED oder EXPIRED. Jeder Zustandswechsel wird dem BswM gemeldet, und <code>EcuM_ClearWakeupEvent</code> setzt die Quelle auf NONE zurück. Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-407eea1386f12f08.html" data-snip="FIG-407eea1386f12f08">SWS EcuM S. 60</a>, <a class="spec-record-ref" data-req="SWS_EcuM_04091" href="../../spec/record.html?id=SWS_EcuM_04091">[SWS_EcuM_04091]</a>, <a class="spec-record-ref" data-req="SWS_EcuM_02683" href="../../spec/record.html?id=SWS_EcuM_02683">[SWS_EcuM_02683]</a></p>
<p>Ein Treiber meldet ein erkanntes Ereignis genau einmal mit <code>EcuM_SetWakeupEvent</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_6_4_4_Requirements_for_Drivers_with_Wakeup_Sources.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_6_4_4_Requirements_for_Drivers_with_Wakeup_Sources">SWS EcuM S. 71</a>. Die Funktion darf auch aus Interrupt-Kontext und aus OS-freiem Kontext aufgerufen werden. Sie setzt die übergebenen Bits per ODER in die Pending-Variable. Quellen, die nicht zum gewählten Schlafmodus gehören, ignoriert sie <a class="spec-record-ref" data-req="SWS_EcuM_02826" href="../../spec/record.html?id=SWS_EcuM_02826">[SWS_EcuM_02826]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02171" href="../../spec/record.html?id=SWS_EcuM_02171">[SWS_EcuM_02171]</a> <a class="spec-record-ref" data-req="SWS_EcuM_01117" href="../../spec/record.html?id=SWS_EcuM_01117">[SWS_EcuM_01117]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04138" href="../../spec/record.html?id=SWS_EcuM_04138">[SWS_EcuM_04138]</a>.</p>
<p>Muss das Ereignis validiert werden, startet der EcuM einen quellenspezifischen Timeout gemäß <code>EcuMValidationTimeout</code>. Wird dieselbe Quelle erneut gemeldet, startet der Timeout nicht neu <a class="spec-record-ref" data-req="SWS_EcuM_02975" href="../../spec/record.html?id=SWS_EcuM_02975">[SWS_EcuM_02975]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02565" href="../../spec/record.html?id=SWS_EcuM_02565">[SWS_EcuM_02565]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02709" href="../../spec/record.html?id=SWS_EcuM_02709">[SWS_EcuM_02709]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02712" href="../../spec/record.html?id=SWS_EcuM_02712">[SWS_EcuM_02712]</a>. Ist für eine Quelle keine Validierung konfiguriert, wirkt <code>EcuM_SetWakeupEvent</code> zugleich wie <code>EcuM_ValidateWakeupEvent</code>. Die fünf vordefinierten Quellen werden nie validiert <a class="spec-record-ref" data-req="SWS_EcuM_02566" href="../../spec/record.html?id=SWS_EcuM_02566">[SWS_EcuM_02566]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02625" href="../../spec/record.html?id=SWS_EcuM_02625">[SWS_EcuM_02625]</a>.</p>
<p>Die Validierung selbst läuft in <code>EcuM_MainFunction</code>, die dafür den Callout <code>EcuM_CheckValidation</code> aufruft <a class="spec-record-ref" data-req="SWS_EcuM_02539" href="../../spec/record.html?id=SWS_EcuM_02539">[SWS_EcuM_02539]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02925" href="../../spec/record.html?id=SWS_EcuM_02925">[SWS_EcuM_02925]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_6_4_Activities_in_the_WakeupValidation_Sequence.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_6_4_Activities_in_the_WakeupValidation_Sequence">SWS EcuM S. 64</a>. <code>EcuM_ValidateWakeupEvent</code> hat folgende Wirkung <a class="spec-record-ref" data-req="SWS_EcuM_02710" href="../../spec/record.html?id=SWS_EcuM_02710">[SWS_EcuM_02710]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04078" href="../../spec/record.html?id=SWS_EcuM_04078">[SWS_EcuM_04078]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04079" href="../../spec/record.html?id=SWS_EcuM_04079">[SWS_EcuM_04079]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02645" href="../../spec/record.html?id=SWS_EcuM_02645">[SWS_EcuM_02645]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04140" href="../../spec/record.html?id=SWS_EcuM_04140">[SWS_EcuM_04140]</a>:</p>
<ul>
<li>Sie stoppt den Timeout und setzt die Bits in der Validated-Variable.</li>
<li>Sie meldet dem BswM <code>ECUM_WKSTATUS_VALIDATED</code>.</li>
<li>Ist ein Kanal oder PNC konfiguriert, ruft sie <code>ComM_EcuM_WakeUpIndication</code> bzw. <code>ComM_EcuM_PNCWakeUpIndication</code> auf.</li>
</ul>
<p>Läuft der Timeout ab, setzt die Hauptfunktion das Expired-Bit und meldet <code>ECUM_WKSTATUS_EXPIRED</code> <a class="spec-record-ref" data-req="SWS_EcuM_04081" href="../../spec/record.html?id=SWS_EcuM_04081">[SWS_EcuM_04081]</a> <a class="spec-record-ref" data-req="SWS_EcuM_04082" href="../../spec/record.html?id=SWS_EcuM_04082">[SWS_EcuM_04082]</a>. Im Zustand RUN wirkt die Validierung nur für Kommunikationskanäle <a class="spec-record-ref" data-req="SWS_EcuM_02790" href="../../spec/record.html?id=SWS_EcuM_02790">[SWS_EcuM_02790]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02791" href="../../spec/record.html?id=SWS_EcuM_02791">[SWS_EcuM_02791]</a>.</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Unbehebbare Fehler meldet der EcuM über den Callout <code>EcuM_ErrorHook</code> mit dem zugehörigen Fehlercode <a class="spec-record-ref" data-req="SWS_EcuM_04033" href="../../spec/record.html?id=SWS_EcuM_04033">[SWS_EcuM_04033]</a> <a class="spec-record-ref" data-req="SWS_EcuM_02904" href="../../spec/record.html?id=SWS_EcuM_02904">[SWS_EcuM_02904]</a>. <ul>
<li><code>ECUM_E_CONFIGURATION_DATA_INCONSISTENT</code> bei inkonsistenten Post-Build-Daten.</li>
<li><code>ECUM_E_RAM_CHECK_FAILED</code>, wenn die RAM-Prüfung nach dem Wecken fehlschlägt.</li>
</ul>
<p>Schlägt ein OS-Aufruf fehl, behält der EcuM den angeforderten Zustand bei und ruft ebenfalls den ErrorHook auf <a class="spec-record-ref" data-req="SWS_EcuM_04139" href="../../spec/record.html?id=SWS_EcuM_04139">[SWS_EcuM_04139]</a>. Einen eigenen Code <code>ECUM_E_OS_CALL_FAILED</code> und den Hinweis, dass der Hook nicht zurückkehrt, enthält erst eine spätere Fassung der Spezifikation <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ECUM_SECTION_7_12_ErrorHook.html" data-snip="SNIP_CLASSIC_ECUM_SECTION_7_12_ErrorHook">SWS EcuM S. 102</a>. Fehler während der Initialisierung ignoriert der EcuM, zum Beispiel die Rückgabewerte von Init-Funktionen <a class="spec-record-ref" data-req="SWS_EcuM_02980" href="../../spec/record.html?id=SWS_EcuM_02980">[SWS_EcuM_02980]</a>.</p>
