<h4>Context</h4>
<p>The interface class <code>&lt;DataElement-Namespace&gt;::&lt;DataElementInterface&gt;</code> is part of the <em>Diagnostics</em> functional cluster (<code>diag</code>) of the AUTOSAR Adaptive Platform (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=68">AUTOSAR_AP_SWS_Diagnostics p. 68</a>). It serves as a type-specific base class for providing diagnostic data in the role of reading (Read DataElement) according to <a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>.</p>
<p>Within the diagnostic architecture, the class interacts with two essential partners:</p>
<ul>
<li><strong>Diagnostic Management (DM):</strong> The central diagnostic server forwards incoming diagnostic requests (for example, UDS services such as <em>ReadDataByIdentifier</em>) to registered handlers (<a class="spec-record-ref" data-req="SWS_DM_00597" href="../spec/record.html?id=SWS_DM_00597">[SWS_DM_00597]</a>).</li>
<li><strong>Adaptive Application:</strong> The concrete application derives from <code>&lt;DataElementInterface&gt;</code>, implements the pure virtual method <code>Read()</code> (<a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>), and returns the requested sensor data, status values, or parameters.</li>
<li><strong>Manifest and instance modeling:</strong> The object is bound to a port configured in the model via a <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_00587" href="../spec/record.html?id=SWS_DM_00587">[SWS_DM_00587]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>&lt;DataElement-Namespace&gt;::&lt;DataElementInterface&gt;</code> is controlled by creation, explicit service offering, and destruction:</p>
<ul>
<li><strong>Creation:</strong> Instantiation is performed via the constructor, specifying the <code>ara::core::InstanceSpecifier</code> and the concurrency mode <code>ara::diag::ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00587" href="../spec/record.html?id=SWS_DM_00587">[SWS_DM_00587]</a>). This defines whether the implementation is to be operated thread-safely (<code>kConcurrent</code>) or non-thread-safely (<code>kNotConcurrent</code>). The constructor itself is thread-safe and exception-safe (<code>noexcept</code>).</li>
<li><strong>Semantics and ownership:</strong> Instances of the class may neither be copied nor moved. The copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01661" href="../spec/record.html?id=SWS_DM_01661">[SWS_DM_01661]</a>), the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01662" href="../spec/record.html?id=SWS_DM_01662">[SWS_DM_01662]</a>), and the corresponding assignment operators (<a class="spec-record-ref" data-req="SWS_DM_01659" href="../spec/record.html?id=SWS_DM_01659">[SWS_DM_01659]</a>, <a class="spec-record-ref" data-req="SWS_DM_01660" href="../spec/record.html?id=SWS_DM_01660">[SWS_DM_01660]</a>) are explicitly deleted (<code>= delete</code>). The identity and memory address remain bound throughout the entire lifetime.</li>
<li><strong>Offering (Offer):</strong> After construction, the object is in the inactive state. Calling <code>Offer()</code> enables the forwarding of requests by the Diagnostic Management (<a class="spec-record-ref" data-req="SWS_DM_00597" href="../spec/record.html?id=SWS_DM_00597">[SWS_DM_00597]</a>).</li>
<li><strong>Revocation (StopOffer):</strong> Forwarding by the DM is deactivated via <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00617" href="../spec/record.html?id=SWS_DM_00617">[SWS_DM_00617]</a>).</li>
<li><strong>Destruction:</strong> The virtual destructor <code>~&lt;DataElementInterface&gt;()</code> terminates the lifecycle (<a class="spec-record-ref" data-req="SWS_DM_00588" href="../spec/record.html?id=SWS_DM_00588">[SWS_DM_00588]</a>). Prior to release, the application would typically call <code>StopOffer()</code> to orderly terminate pending accesses.</li>
</ul>
<p>With regard to concurrency, the methods <code>Offer()</code>, <code>StopOffer()</code>, and the destructor are specified as non-thread-safe (<a class="spec-record-ref" data-req="SWS_DM_00597" href="../spec/record.html?id=SWS_DM_00597">[SWS_DM_00597]</a>, <a class="spec-record-ref" data-req="SWS_DM_00617" href="../spec/record.html?id=SWS_DM_00617">[SWS_DM_00617]</a>, <a class="spec-record-ref" data-req="SWS_DM_00588" href="../spec/record.html?id=SWS_DM_00588">[SWS_DM_00588]</a>), which is why concurrent administrative method calls on the same instance must be synchronized.</p>

<h4>Usage Path</h4>
<p>A regular usage sequence is divided into the following phases:</p>
<ol>
<li><strong>Derivation and instantiation:</strong> The application implements a derived class and overrides the pure virtual function <code>Read()</code> (<a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>). At startup, the instance is created with the corresponding <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_00587" href="../spec/record.html?id=SWS_DM_00587">[SWS_DM_00587]</a>).</li>
<li><strong>Activation:</strong> The application calls <code>Offer()</code>, whereby the handler is registered with the DM (<a class="spec-record-ref" data-req="SWS_DM_00597" href="../spec/record.html?id=SWS_DM_00597">[SWS_DM_00597]</a>).</li>
<li><strong>Request processing:</strong> As soon as a diagnostic request arrives, the DM calls the method <code>Read(metaInfo, cancellationHandler)</code> (<a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>).
<ul>
<li>The handler receives metadata about the request via <code>metaInfo</code>.</li>
<li>Via <code>cancellationHandler</code>, the handler can check cyclically with <code>IsCanceled()</code> whether the ongoing diagnostic conversation has been canceled, or register a notification function via <code>SetNotifier()</code> (<a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>).</li>
</ul>
</li>
<li><strong>Result return:</strong> The call returns a <code>ara::core::Future</code>, which in case of success is resolved with the output structure (<a class="spec-record-ref" data-req="SWS_DM_00596" href="../spec/record.html?id=SWS_DM_00596">[SWS_DM_00596]</a>, <a class="spec-record-ref" data-req="SWS_DM_00581" href="../spec/record.html?id=SWS_DM_00581">[SWS_DM_00581]</a>). The output data is passed via the declared out arguments such as <code>&lt;DataElementOutArg&gt;</code> (<a class="spec-record-ref" data-req="SWS_DM_80023" href="../spec/record.html?id=SWS_DM_80023">[SWS_DM_80023]</a>).</li>
<li><strong>Deactivation:</strong> Prior to shutdown or upon service interruption, the application calls <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00617" href="../spec/record.html?id=SWS_DM_00617">[SWS_DM_00617]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors can occur during instantiation, registration, and the execution of the read request:</p>
<ul>
<li><strong>Construction errors (model violations):</strong> The constructor reports configuration and model inconsistencies via the framework's violation concept (<a class="spec-record-ref" data-req="SWS_DM_00587" href="../spec/record.html?id=SWS_DM_00587">[SWS_DM_00587]</a>):
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not reference a PortPrototype.</li>
<li><code>PortInterfaceMappingViolation</code>: The referenced PortPrototype is not linked to a <code>DiagnosticDataElementInterface</code> via a <code>DiagnosticDataPortMapping</code>.</li>
<li><code>ProcessMappingViolation</code>: No matching modeled process exists at runtime for the instance identifier.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The identifier is already used by another instance in the process.</li>
</ul>
</li>
<li><strong>Offer errors:</strong> If <code>Offer()</code> is called multiple times while the service is already being offered, the method returns a <code>ara::core::Result</code> with the error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00597" href="../spec/record.html?id=SWS_DM_00597">[SWS_DM_00597]</a>).</li>
