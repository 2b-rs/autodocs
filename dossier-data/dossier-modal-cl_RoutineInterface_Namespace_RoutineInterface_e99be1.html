<h4>Context</h4>
<p>The class <code>&lt;RoutineInterface-Namespace&gt;::&lt;RoutineInterface&gt;</code> forms the central C++ interface in the AUTOSAR Adaptive module <code>diag</code> for providing and controlling diagnostic routines (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=68">AUTOSAR AP SWS Diagnostics p. 68</a>). In the context of the UDS service <em>RoutineControl</em> (service 0x31 according to ISO 14229-1), an application-specific derivative of this class acts as a server-side handler. The class accepts requests that are forwarded from the central <em>Diagnostic Management</em> (DM) to the application (<a class="spec-record-ref" data-req="SWS_DM_00594" href="../spec/record.html?id=SWS_DM_00594">[SWS_DM_00594]</a>). The interface defines the three essential control operations of a routine: starting via <code>Start</code> (<a class="spec-record-ref" data-req="SWS_DM_00591" href="../spec/record.html?id=SWS_DM_00591">[SWS_DM_00591]</a>), stopping via <code>Stop</code> (<a class="spec-record-ref" data-req="SWS_DM_00592" href="../spec/record.html?id=SWS_DM_00592">[SWS_DM_00592]</a>), and querying results via <code>RequestResult</code> (<a class="spec-record-ref" data-req="SWS_DM_00593" href="../spec/record.html?id=SWS_DM_00593">[SWS_DM_00593]</a>). The functional connection in the system is established via a <code>PortPrototype</code> of type <code>DiagnosticRoutineInterface</code>, which must be referenced in the model via an <code>DiagnosticServiceGenericMapping</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</p>

<h4>Lifecycle</h4>
<p>A routine handler is created via the parameterized constructor specifying an <code>ara::core::InstanceSpecifier</code> and the desired concurrency <code>ara::diag::ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>). The parameter <code>concurrencyType</code> determines whether the interface is implemented thread-safe (<code>kConcurrent</code>) or not thread-safe (<code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>). The constructor call itself is declared as thread-safe and <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</p>
<p>With regard to object semantics, <code>&lt;RoutineInterface&gt;</code> has a unique identity: The copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01669" href="../spec/record.html?id=SWS_DM_01669">[SWS_DM_01669]</a>), the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01670" href="../spec/record.html?id=SWS_DM_01670">[SWS_DM_01670]</a>), the copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01667" href="../spec/record.html?id=SWS_DM_01667">[SWS_DM_01667]</a>), and the move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01668" href="../spec/record.html?id=SWS_DM_01668">[SWS_DM_01668]</a>) are explicitly deleted (<code>=delete</code>). Duplicating or moving instances is therefore precluded.</p>
<p>After construction, the instance is in the inactive state. Only by calling <code>Offer()</code> is the forwarding of incoming diagnostic requests by Diagnostic Management to this handler activated (<a class="spec-record-ref" data-req="SWS_DM_00594" href="../spec/record.html?id=SWS_DM_00594">[SWS_DM_00594]</a>). Calling <code>StopOffer()</code> deactivates the forwarding of requests again (<a class="spec-record-ref" data-req="SWS_DM_00595" href="../spec/record.html?id=SWS_DM_00595">[SWS_DM_00595]</a>). The instance is released via the virtual destructor <code>~&lt;RoutineInterface&gt;()</code>, which is specified as <code>noexcept</code> and not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_00590" href="../spec/record.html?id=SWS_DM_00590">[SWS_DM_00590]</a>). Before calling the destructor, <code>StopOffer()</code> should probably be called to cleanly unregister pending forwardings of the DM prior to object destruction.</p>

<h4>Usage Path</h4>
<p>The typical usage path is divided into initialization, request processing, and termination:</p>
<ol>
<li><strong>Instantiation:</strong> The application derives an implementation class from <code>&lt;RoutineInterface&gt;</code>, overrides the pure virtual methods, and creates the instance with the associated <code>InstanceSpecifier</code> as well as specifying <code>ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</li>
<li><strong>Service offering (Offer):</strong> The application calls <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00594" href="../spec/record.html?id=SWS_DM_00594">[SWS_DM_00594]</a>), authorizing the DM to forward routine requests.</li>
<li><strong>Processing of control operations:</strong>
<ul>
<li><strong>Start routine:</strong> When a start request arrives, the DM calls the method <code>Start(...)</code> with the modeled input arguments, <code>ara::diag::MetaInfo</code>, and a <code>ara::diag::CancellationHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_00591" href="../spec/record.html?id=SWS_DM_00591">[SWS_DM_00591]</a>). The method returns a <code>ara::core::Future</code> with the associated <code>StartOutput</code> object (<a class="spec-record-ref" data-req="SWS_DM_00581" href="../spec/record.html?id=SWS_DM_00581">[SWS_DM_00581]</a>, <a class="spec-record-ref" data-req="SWS_DM_80003" href="../spec/record.html?id=SWS_DM_80003">[SWS_DM_80003]</a>).</li>
<li><strong>Request results:</strong> Intermediate or final results of the routine are queried using <code>RequestResult(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_00593" href="../spec/record.html?id=SWS_DM_00593">[SWS_DM_00593]</a>). The returned <code>ara::core::Future</code> provides the <code>RequestResultOutput</code> object (<a class="spec-record-ref" data-req="SWS_DM_00583" href="../spec/record.html?id=SWS_DM_00583">[SWS_DM_00583]</a>, <a class="spec-record-ref" data-req="SWS_DM_80005" href="../spec/record.html?id=SWS_DM_80005">[SWS_DM_80005]</a>).</li>
<li><strong>Stop routine:</strong> An active routine execution is stopped by calling <code>Stop(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_00592" href="../spec/record.html?id=SWS_DM_00592">[SWS_DM_00592]</a>), which returns a <code>ara::core::Future</code> with the <code>StopOutput</code> object (<a class="spec-record-ref" data-req="SWS_DM_00582" href="../spec/record.html?id=SWS_DM_00582">[SWS_DM_00582]</a>, <a class="spec-record-ref" data-req="SWS_DM_80004" href="../spec/record.html?id=SWS_DM_80004">[SWS_DM_80004]</a>).</li>
<li><strong>Cancellation handling:</strong> Via the passed <code>cancellationHandler</code>, the handler can query the cancellation status using <code>IsCanceled()</code> or register a callback via <code>SetNotifier(...)</code> in case the diagnostic conversation is cancelled prematurely (<a class="spec-record-ref" data-req="SWS_DM_00591" href="../spec/record.html?id=SWS_DM_00591">[SWS_DM_00591]</a>, <a class="spec-record-ref" data-req="SWS_DM_00592" href="../spec/record.html?id=SWS_DM_00592">[SWS_DM_00592]</a>, <a class="spec-record-ref" data-req="SWS_DM_00593" href="../spec/record.html?id=SWS_DM_00593">[SWS_DM_00593]</a>).</li>
</ul>
</li>
<li><strong>Stop service offering (StopOffer):</strong> If the handler is no longer to service requests, the application calls <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00595" href="../spec/record.html?id=SWS_DM_00595">[SWS_DM_00595]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error situations can occur both during instantiation and provision as well as during actual routine execution:</p>
<ul>
<li><strong>Integrity and model violations during construction:</strong>
Although the constructor is declared as <code>noexcept</code>, violations are triggered in the event of configuration errors (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>):
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The <code>InstanceSpecifier</code> cannot be resolved in the model context of the executable or does not refer to a <code>PortPrototype</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</li>
<li><code>PortInterfaceMappingViolation</code>: The <code>PortPrototype</code> of type <code>DiagnosticRoutineInterface</code> is not referenced by an <code>DiagnosticServiceGenericMapping</code> (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</li>
<li><code>ProcessMappingViolation</code>: A modeled <code>InstanceRef</code> exists, but no modeled process matches the current runtime process (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The specified <code>InstanceSpecifier</code> is already used by another instance in this process (<a class="spec-record-ref" data-req="SWS_DM_00589" href="../spec/record.html?id=SWS_DM_00589">[SWS_DM_00589]</a>).</li>
</ul>
</li>
<li><strong>Errors during offering (Offer):</strong>
If <code>Offer()</code> is called even though the service is already offered, the method returns a <code>ara::core::Result&lt;void&gt;</code> with the error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00594" href="../spec/record.html?id=SWS_DM_00594">[SWS_DM_00594]</a>). The call is specified as not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_00594" href="../spec/record.html?id=SWS_DM_00594">[SWS_DM_00594]</a>).</li>
<li><strong>Domain errors during operation execution:</strong>
If the operations <code>Start</code>, <code>Stop</code>, or <code>RequestResult</code> fail, the methods do not throw exceptions (all methods are <code>noexcept</code>). Instead, the error is transported asynchronously via the returned <code>ara::core::Future</code>. For this purpose, the implementation must provide a suitable UDS Negative Response Code (NRC) according to ISO 14229-1 via <code>ara::diag::DiagUdsNrcErrc</code> or a <code>Ap ApplicationError</code> (<a class="spec-record-ref" data-req="SWS_DM_00591" href="../spec/record.html?id=SWS_DM_00591">[SWS_DM_00591]</a>, <a class="spec-record-ref" data-req="SWS_DM_00592" href="../spec/record.html?id=SWS_DM_00592">[SWS_DM_00592]</a>, <a class="spec-record-ref" data-req="SWS_DM_00593" href="../spec/record.html?id=SWS_DM_00593">[SWS_DM_00593]</a>).</li>
</ul>
