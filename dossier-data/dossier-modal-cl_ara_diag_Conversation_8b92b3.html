<h4>Context</h4>
<p>The class <code>ara::diag::Conversation</code> represents an active diagnostic connection within the AUTOSAR Adaptive Diagnostic Management. It serves as a central abstraction for diagnostic applications and service handlers to inspect and control the context and states of an ongoing UDS or DoIP communication <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=80">AUTOSAR_AP_SWS_Diagnostics p. 80</a>.</p>
<p>The core tasks include providing the current activity status, the unique identification properties of the conversation, as well as the active diagnostic session (<code>SessionControlType</code>) and the security level (<code>SecurityLevelType</code>). In addition, the interface allows registering notifier callbacks upon state transitions and resetting a session to the default session.</p>
<p>The interaction essentially takes place between three participants: The application software (e.g. a diagnostic service handler) retrieves conversation references via static methods and queries properties. The instance of <code>ara::diag::Conversation</code> holds and provides the connection properties, while the underlying Diagnostic Management (DM) is responsible for protocol processing and reports status changes to the conversation.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a conversation instance is controlled by strict semantic rules. The class is declared as <code>final</code> and prevents any form of duplication or pass-by-value: The copy constructor <a class="spec-record-ref" data-req="SWS_DM_02090" href="../spec/record.html?id=SWS_DM_02090">[SWS_DM_02090]</a>, the move constructor <a class="spec-record-ref" data-req="SWS_DM_02092" href="../spec/record.html?id=SWS_DM_02092">[SWS_DM_02092]</a>, the copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_02091" href="../spec/record.html?id=SWS_DM_02091">[SWS_DM_02091]</a>, and the move assignment operator <a class="spec-record-ref" data-req="SWS_DM_02093" href="../spec/record.html?id=SWS_DM_02093">[SWS_DM_02093]</a> are explicitly deleted.</p>
<p>Interpretation: Since no public constructors are provided and only long-lived references are issued, the creation and destruction of <code>Conversation</code> objects rests entirely with the internal runtime environment of the Diagnostic Management. Applications obtain existing instances via static query functions:</p>
<ul>
<li><code>GetConversation</code> returns the reference to a conversation based on the provided <code>MetaInfo</code> of a request <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>.</li>
<li><code>GetAllConversations</code> returns a vector of reference wrappers of all possible conversations <a class="spec-record-ref" data-req="SWS_DM_00782" href="../spec/record.html?id=SWS_DM_00782">[SWS_DM_00782]</a>.</li>
<li><code>GetCurrentActiveConversations</code> filters out all conversations with the status <code>kActive</code> <a class="spec-record-ref" data-req="SWS_DM_00783" href="../spec/record.html?id=SWS_DM_00783">[SWS_DM_00783]</a>.</li>
</ul>
<p>Regarding concurrency, the following applies: Pure query operations such as <code>GetActivityStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00694" href="../spec/record.html?id=SWS_DM_00694">[SWS_DM_00694]</a>, <code>GetConversationIdentifier</code> <a class="spec-record-ref" data-req="SWS_DM_00700" href="../spec/record.html?id=SWS_DM_00700">[SWS_DM_00700]</a>, <code>GetDiagnosticSession</code> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a>, <code>GetDiagnosticSecurityLevel</code> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a> as well as the ShortName converters <a class="spec-record-ref" data-req="SWS_DM_00707" href="../spec/record.html?id=SWS_DM_00707">[SWS_DM_00707]</a> and <a class="spec-record-ref" data-req="SWS_DM_00708" href="../spec/record.html?id=SWS_DM_00708">[SWS_DM_00708]</a> are thread-safe and exception-safe. In contrast, mutating calls such as <code>ResetToDefaultSession</code> <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a> and the notifier registrations <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a>, <a class="spec-record-ref" data-req="SWS_DM_00697" href="../spec/record.html?id=SWS_DM_00697">[SWS_DM_00697]</a>, and <a class="spec-record-ref" data-req="SWS_DM_00699" href="../spec/record.html?id=SWS_DM_00699">[SWS_DM_00699]</a> are not thread-safe (<em>not thread-safe</em>) and must be called in a synchronized manner.</p>

<h4>Usage Path</h4>
<p>The typical sequence for using a conversation instance by a diagnostic service handler is divided into the following steps:</p>
<ol>
<li><strong>Determine conversation:</strong> During request processing, the instance is obtained via <code>ara::diag::Conversation::GetConversation(metaInfo)</code> <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>.</li>
<li><strong>Register state observers:</strong> If required, the caller registers notification functions via <code>SetActivityNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a> <a class="spec-record-ref" data-req="SWS_DM_02126" href="../spec/record.html?id=SWS_DM_02126">[SWS_DM_02126]</a>, <code>SetDiagnosticSessionNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00697" href="../spec/record.html?id=SWS_DM_00697">[SWS_DM_00697]</a> <a class="spec-record-ref" data-req="SWS_DM_02127" href="../spec/record.html?id=SWS_DM_02127">[SWS_DM_02127]</a>, or <code>SetSecurityLevelNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00699" href="../spec/record.html?id=SWS_DM_00699">[SWS_DM_00699]</a> <a class="spec-record-ref" data-req="SWS_DM_02128" href="../spec/record.html?id=SWS_DM_02128">[SWS_DM_02128]</a>. A subsequent call always overwrites the previously registered notifier.</li>
<li><strong>Check session and security level:</strong> The handler checks the access authorization via <code>GetDiagnosticSession</code> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a> and <code>GetDiagnosticSecurityLevel</code> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a>. The identifiers can be resolved into StringViews for tracing or log outputs using <code>GetDiagnosticSessionShortName</code> <a class="spec-record-ref" data-req="SWS_DM_00707" href="../spec/record.html?id=SWS_DM_00707">[SWS_DM_00707]</a> and <code>GetDiagnosticSecurityLevelShortName</code> <a class="spec-record-ref" data-req="SWS_DM_00708" href="../spec/record.html?id=SWS_DM_00708">[SWS_DM_00708]</a>, respectively.</li>
<li><strong>Reset session state:</strong> When the application logic or an error condition forces the return to the default state, <code>ResetToDefaultSession()</code> is called <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of the class signal error conditions via return objects of type <code>ara::core::Result</code>. All operations are declared with <code>noexcept</code>, which is why no C++ exceptions occur:</p>
<ul>
<li><strong>Service not available (<code>DiagErrc::kServiceNotAvailable</code>):</strong> Returned by <code>GetConversation</code> <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>, <code>GetActivityStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00694" href="../spec/record.html?id=SWS_DM_00694">[SWS_DM_00694]</a>, <code>GetConversationIdentifier</code> <a class="spec-record-ref" data-req="SWS_DM_00700" href="../spec/record.html?id=SWS_DM_00700">[SWS_DM_00700]</a>, <code>GetDiagnosticSession</code> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a>, and <code>GetDiagnosticSecurityLevel</code> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a> if essential functionality of the Diagnostic Management is currently not available.</li>
<li><strong>Invalid argument (<code>DiagErrc::kInvalidArgument</code>):</strong> Occurs with <code>GetDiagnosticSessionShortName</code> <a class="spec-record-ref" data-req="SWS_DM_00707" href="../spec/record.html?id=SWS_DM_00707">[SWS_DM_00707]</a> and <code>GetDiagnosticSecurityLevelShortName</code> <a class="spec-record-ref" data-req="SWS_DM_00708" href="../spec/record.html?id=SWS_DM_00708">[SWS_DM_00708]</a> if an undefined enum value is passed.</li>
<li><strong>Methods without standardized error codes:</strong> No standardized error codes are defined for <code>ResetToDefaultSession</code> <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a> as well as the methods <code>SetActivityNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a>, <code>SetDiagnosticSessionNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00697" href="../spec/record.html?id=SWS_DM_00697">[SWS_DM_00697]</a>, and <code>SetSecurityLevelNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00699" href="../spec/record.html?id=SWS_DM_00699">[SWS_DM_00699]</a>; however, the returned <code>ara::core::Result&lt;void&gt;</code> allows implementation-specific errors.</li>
</ul>
