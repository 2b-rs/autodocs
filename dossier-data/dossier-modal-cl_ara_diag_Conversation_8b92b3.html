<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht die Überwachung aktiver Diagnosekanäle sowie die Kontrolle von Diagnosesitzung und Sicherheitsstufe.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::Conversation</code> repräsentiert einen Diagnosekommunikationskanal zur Überwachung von Aktivitätsstatus, Diagnosesitzung und Sicherheitsstufe sowie zum Zurücksetzen auf die Standardsitzung <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a> <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a>. Anwendungen beziehen Instanzen ausschließlich als Referenzen über statische Suchfunktionen, da eigene Instanziierungen sowie Kopier- und Verschiebevorgänge gelöscht sind <a class="spec-record-ref" data-req="SWS_DM_02090" href="../spec/record.html?id=SWS_DM_02090">[SWS_DM_02090]</a>. Während lesende Statusabfragen thread-safe ausgeführt werden können, erfordern Callback-Registrierungen und das Rücksetzen der Sitzung externe Synchronisation.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::Conversation</code> repräsentiert die Schnittstelle zu einem Kommunikationskanal zwischen einem externen Diagnosetester und der Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=80">SWS Diagnostics §8.2 „Conversation“</a>. Sie dient als Bindeglied zwischen der Anwendung und dem internen Diagnostik-Management (DM), um laufende Diagnoseaktivitäten nachzuvollziehen und zu steuern. Über ihre Instanzen erhalten Adaptive Anwendungen Einblick in den aktuellen Verbindungszustand <a class="spec-record-ref" data-req="SWS_DM_00694" href="../spec/record.html?id=SWS_DM_00694">[SWS_DM_00694]</a>, die aktive Diagnosesitzung <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a>, die Sicherheitsstufe <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a> sowie die Identifikationsmerkmale des Kanals <a class="spec-record-ref" data-req="SWS_DM_00700" href="../spec/record.html?id=SWS_DM_00700">[SWS_DM_00700]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>ara::diag::Conversation</code> werden vollständig durch den Diagnostic Management Daemon instanziiert und verwaltet. Ein manuelles Erzeugen, Kopieren oder Verschieben durch die Anwendung ist ausgeschlossen: Sowohl der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_02090" href="../spec/record.html?id=SWS_DM_02090">[SWS_DM_02090]</a> und Verschiebekonstruktor <a class="spec-record-ref" data-req="SWS_DM_02092" href="../spec/record.html?id=SWS_DM_02092">[SWS_DM_02092]</a> als auch die Zuweisungsoperatoren <a class="spec-record-ref" data-req="SWS_DM_02091" href="../spec/record.html?id=SWS_DM_02091">[SWS_DM_02091]</a> <a class="spec-record-ref" data-req="SWS_DM_02093" href="../spec/record.html?id=SWS_DM_02093">[SWS_DM_02093]</a> sind gelöscht (<code>=delete</code>). Die Lebensdauer der referenzierten Objekte dürfte daher unmittelbar an den Laufzeitzustand des Diagnosesubsystems gekoppelt sein.</p>
<p>Der Zugriff auf bestehende Instanzen erfolgt ausschließlich über statische Abfragefunktionen. Mit <code>GetAllConversations()</code> lassen sich Referenzen auf sämtliche konfigurierten Verbindungen abrufen <a class="spec-record-ref" data-req="SWS_DM_00782" href="../spec/record.html?id=SWS_DM_00782">[SWS_DM_00782]</a>, während <code>GetCurrentActiveConversations()</code> eine Liste aller aktuell aktiven Kanäle liefert, deren Aktivitätsstatus <code>kActive</code> entspricht <a class="spec-record-ref" data-req="SWS_DM_00783" href="../spec/record.html?id=SWS_DM_00783">[SWS_DM_00783]</a>. Zudem kann über <code>GetConversation(metaInfo)</code> eine spezifische Verbindung anhand der Metadaten einer laufenden Diagnoseanfrage aufgelöst werden <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit sind sämtliche lesenden Zugriffe auf Status und Identifikatoren als thread-safe spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00694" href="../spec/record.html?id=SWS_DM_00694">[SWS_DM_00694]</a> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a>. Das Registrieren von Benachrichtigungs-Callbacks sowie das Rücksetzen der Sitzung gelten hingegen als nicht thread-sicher (not thread-safe) <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a> <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a> und erfordern anwendungsseitige Synchronisation.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Anwendungsfall umfasst das Ermitteln der Verbindung, die Registrierung von Benachrichtigungsfunktionen und die gezielte Überwachung oder Manipulation des Sitzungszustands:</p>
<ul>
<li><strong>Referenz beschaffen:</strong> Bei einer eintreffenden Diagnoseanfrage wird die zugehörige Instanz mittels <code>GetConversation(metaInfo)</code> bezogen <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>.</li>
<li><strong>Zustandsüberwachung einrichten:</strong> Über die Registrierungsmethoden <code>SetActivityNotifier()</code> <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a> <a class="spec-record-ref" data-req="SWS_DM_02126" href="../spec/record.html?id=SWS_DM_02126">[SWS_DM_02126]</a>, <code>SetDiagnosticSessionNotifier()</code> <a class="spec-record-ref" data-req="SWS_DM_00697" href="../spec/record.html?id=SWS_DM_00697">[SWS_DM_00697]</a> <a class="spec-record-ref" data-req="SWS_DM_02127" href="../spec/record.html?id=SWS_DM_02127">[SWS_DM_02127]</a> und <code>SetSecurityLevelNotifier()</code> <a class="spec-record-ref" data-req="SWS_DM_00699" href="../spec/record.html?id=SWS_DM_00699">[SWS_DM_00699]</a> <a class="spec-record-ref" data-req="SWS_DM_02128" href="../spec/record.html?id=SWS_DM_02128">[SWS_DM_02128]</a> wird die Anwendung bei Änderungen benachrichtigt. Ein wiederholter Aufruf überschreibt den zuvor registrierten Callback.</li>
<li><strong>Status abfragen:</strong> Der augenblickliche Zustand lässt sich synchron mit <code>GetDiagnosticSession()</code> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a> oder <code>GetDiagnosticSecurityLevel()</code> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a> ermitteln. Mittels <code>GetDiagnosticSessionShortName()</code> <a class="spec-record-ref" data-req="SWS_DM_00707" href="../spec/record.html?id=SWS_DM_00707">[SWS_DM_00707]</a> und <code>GetDiagnosticSecurityLevelShortName()</code> <a class="spec-record-ref" data-req="SWS_DM_00708" href="../spec/record.html?id=SWS_DM_00708">[SWS_DM_00708]</a> können die Enums in lesbare Kurzbezeichner aufgelöst werden.</li>
<li><strong>Sitzung zurücksetzen:</strong> Erfordert die Logik einen Abbruch oder ein Zurückfallen in den Grundzustand, versetzt <code>ResetToDefaultSession()</code> den Kanal zurück in die Standardsitzung <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a>.</li>
</ul>
