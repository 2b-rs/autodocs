<p class="ai-level ai-oneliner-lead" data-ai-level="1">Bietet eine Schnittstelle zur authentifizierten symmetrischen Ver- und Entschlüsselung mit Integritätsschutz.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>ara::crypto::cryp::AuthCipherCtx</code> dient der authentifizierten Ver- und Entschlüsselung von Daten unter Wahrung der Vertraulichkeit und Integrität <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a>. Nach Konfiguration des Schlüssels erfolgt die Verarbeitung entweder als atomarer Einzelaufruf oder als gestreamte Abfolge aus Initialisierung, optionalen Authentifizierungsdaten, Nutzdaten-Updates und Finalisierung. Als kritische Sicherheitsbedingung schlägt die Entschlüsselung bei ungültigem Authentifizierungs-Tag fehl, sodass entschlüsselte Nutzdaten erst nach erfolgreicher Validierung verarbeitet werden dürfen <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a>.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::crypto::cryp::AuthCipherCtx</code> definiert die standardisierte Programmierschnittstelle für authentifizierte Chiffrieroperationen (Authenticated Encryption with Associated Data, AEAD) innerhalb der AUTOSAR Adaptive Platform. Sie verbindet Vertraulichkeit mit Integritätsschutz, indem neben der eigentlichen Ver- oder Entschlüsselung von Nutzdaten stets ein kryptografischer Authentifizierungs-Tag generiert bzw. validiert wird. Als zentrale Interaktionspartner fungieren aufrufende Applikationen sowie Schlüsselobjekte: Ein Kontext wird vor der Nutzung entweder an eine konkrete Instanz von <code>SymmetricKey</code> gebunden <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a> oder mit einem persistierten bzw. bereitgestellten <code>KeySlot</code> konfiguriert <a class="spec-record-ref" data-req="SWS_CRYPT_50072" href="../spec/record.html?id=SWS_CRYPT_50072">[SWS_CRYPT_50072]</a>. Neben schrittweiser Streaming-Verarbeitung unterstützt die Klasse auch autarke Einzelaufrufe zur Verarbeitung vollständiger Nachrichten in einem Schritt <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Kontexte werden im Anwendungsbereich über den gemeinsamen Zeigertyp <code>ara::crypto::cryp::AuthCipherCtx::Sptr</code> verwaltet <a class="spec-record-ref" data-req="SWS_CRYPT_20101" href="../spec/record.html?id=SWS_CRYPT_20101">[SWS_CRYPT_20101]</a>. (Interpretation: Die Objekterzeugung erfolgt typischerweise über eine übergeordnete Provider-Fabrik, da <code>AuthCipherCtx</code> als reine Schnittstelle spezifiziert ist). <a class="interp-q interp-q-open" data-q="Q-23125789874cf2f3" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-23125789874cf2f3" title="Frage Q-23125789874cf2f3 (offen): Die Erzeugung von AuthCipherCtx-Instanzen erfolgt typischerweise über eine übergeordnete Provider-Fabrikmethode">Frage Q-23125789874cf2f3 (offen)</a> Alle Mitgliedsfunktionen sind als ausnahmesicher (<em>exception safe</em>) und threadsicher (<em>thread-safe</em>) deklariert <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>. Der funktionale Lebenszyklus durchläuft klar definierte Zustände:</p>
<ul>
<li><strong>Uninitialisiert:</strong> Unmittelbar nach der Instanziierung. Aufrufe zur Datenverarbeitung werden abgewiesen, da noch kein Schlüssel zugewiesen wurde <a class="spec-record-ref" data-req="SWS_CRYPT_50081" href="../spec/record.html?id=SWS_CRYPT_50081">[SWS_CRYPT_50081]</a>.</li>
<li><strong>Schlüssel konfiguriert:</strong> Durch erfolgreichen Aufruf von <code>SetKey</code> mit einem <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a> oder einem <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50072" href="../spec/record.html?id=SWS_CRYPT_50072">[SWS_CRYPT_50072]</a> wechselt der Kontext in den einsatzbereiten Zustand. Aus diesem Zustand heraus können Single-Shot-Operationen direkt ausgeführt werden.</li>
<li><strong>Streaming aktiv:</strong> Wird durch Aufruf von <code>Start</code> unter Angabe der Transformationsrichtung mit Initialisierungsvektor (IV) <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a> oder ohne expliziten IV <a class="spec-record-ref" data-req="SWS_CRYPT_50073" href="../spec/record.html?id=SWS_CRYPT_50073">[SWS_CRYPT_50073]</a> betreten.</li>
<li><strong>Abschluss / Reset:</strong> Eine laufende Streaming-Operation wird regulär durch <code>Finish</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a> oder <code>FinishEncrypt</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50076" href="../spec/record.html?id=SWS_CRYPT_50076">[SWS_CRYPT_50076]</a> abgeschlossen oder über <code>Cancel</code> vorzeitig abgebrochen <a class="spec-record-ref" data-req="SWS_CRYPT_50077" href="../spec/record.html?id=SWS_CRYPT_50077">[SWS_CRYPT_50077]</a>. Danach steht der Kontext wieder für neue Verarbeitungssequenzen bereit.</li>
</ul>

<h4>Nutzungspfad</h4>
<p>Für die kontinuierliche Datenstromverarbeitung erfordert die Schnittstelle eine geordnete Abfolge von Aufrufen:</p>
<ol>
<li><strong>Konfiguration:</strong> Zuweisung des Schlüssels über <code>SetKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a> bzw. <code>SetKey</code> mit KeySlot <a class="spec-record-ref" data-req="SWS_CRYPT_50072" href="../spec/record.html?id=SWS_CRYPT_50072">[SWS_CRYPT_50072]</a>.</li>
<li><strong>Parameterabfrage:</strong> Optionales Ermitteln von Grenzwerten und Puffergrößen über <code>GetMinimumChunkSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50162" href="../spec/record.html?id=SWS_CRYPT_50162">[SWS_CRYPT_50162]</a>, <code>GetMaximumChunkSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50082" href="../spec/record.html?id=SWS_CRYPT_50082">[SWS_CRYPT_50082]</a>, <code>GetMinimumInputIvSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50163" href="../spec/record.html?id=SWS_CRYPT_50163">[SWS_CRYPT_50163]</a>, <code>GetMaximumInputIvSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50164" href="../spec/record.html?id=SWS_CRYPT_50164">[SWS_CRYPT_50164]</a>, <code>GetTagSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50161" href="../spec/record.html?id=SWS_CRYPT_50161">[SWS_CRYPT_50161]</a> sowie <code>GetRequiredOutputBufferSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50081" href="../spec/record.html?id=SWS_CRYPT_50081">[SWS_CRYPT_50081]</a>.</li>
<li><strong>Start der Operation:</strong> Aufruf von <code>Start</code> unter Festlegung der Richtung (Verschlüsselung oder Entschlüsselung) sowie Bereitstellung des IV <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a> oder Anforderung eines kontexteigenen IV <a class="spec-record-ref" data-req="SWS_CRYPT_50073" href="../spec/record.html?id=SWS_CRYPT_50073">[SWS_CRYPT_50073]</a>.</li>
<li><strong>Assoziierte Daten (AAD):</strong> Falls zusätzliche Klartextdaten in die Integritätsberechnung einfließen sollen, werden diese über <code>UpdateAuthenticatedData</code> übergeben <a class="spec-record-ref" data-req="SWS_CRYPT_20313" href="../spec/record.html?id=SWS_CRYPT_20313">[SWS_CRYPT_20313]</a>. Die maximal zulässige AAD-Größe lässt sich per <code>GetMaxAssociatedDataSize</code> abfragen <a class="spec-record-ref" data-req="SWS_CRYPT_20103" href="../spec/record.html?id=SWS_CRYPT_20103">[SWS_CRYPT_20103]</a>. Wichtig: AAD-Blöcke müssen zwingend vor den eigentlichen Nutzdaten übermittelt werden.</li>
<li><strong>Nutzdatenverarbeitung:</strong> Schrittweise Übergabe von Datenblöcken über <code>UpdateConfidentialData</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>. Bei der Entschlüsselung wird der Klartext zurückgegeben, bevor dessen Authentizität feststeht; die Anwendung darf diese Daten erst nach erfolgreicher Finalisierung verwenden.</li>
<li><strong>Finalisierung:</strong> Beenden der Operation mittels <code>Finish</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a> oder <code>FinishEncrypt</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50076" href="../spec/record.html?id=SWS_CRYPT_50076">[SWS_CRYPT_50076]</a>, wodurch der finale Block verarbeitet und der Authentifizierungs-Tag berechnet bzw. verifiziert wird.</li>
</ol>
<p>Für kompakte Payloads existieren Single-Call-Alternativen: <code>ProcessSingleCall</code> verarbeitet Daten ohne IV-Übergabe <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>, <code>ProcessSingleCallWithInputIv</code> akzeptiert einen externen IV <a class="spec-record-ref" data-req="SWS_CRYPT_50079" href="../spec/record.html?id=SWS_CRYPT_50079">[SWS_CRYPT_50079]</a>, und <code>EncryptSingleCallWithOutputIv</code> gibt einen vom Kontext generierten IV an den Aufrufer zurück <a class="spec-record-ref" data-req="SWS_CRYPT_50080" href="../spec/record.html?id=SWS_CRYPT_50080">[SWS_CRYPT_50080]</a>.</p>
