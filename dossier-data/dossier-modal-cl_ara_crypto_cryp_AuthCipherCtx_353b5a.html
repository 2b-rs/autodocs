<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::AuthCipherCtx</code> defines the context for cryptographic operations with authenticated encryption (Authenticated Encryption with Associated Data, AEAD). It combines the confidentiality of payload data with integrity checking and authenticity via a cryptographic authentication tag as well as optional additional authenticated data (AAD). Instances are typically managed via the smart pointer alias <code>AuthCipherCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20101" href="../spec/record.html?id=SWS_CRYPT_20101">[SWS_CRYPT_20101]</a>.</p>
<p>Interaction partners are, on one side, the utilizing application, which encrypts and decrypts data streams or single blocks, and on the other side, the key management: The context either operates directly on a key instance of type <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a> or references a persistent or managed storage slot via <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50072" href="../spec/record.html?id=SWS_CRYPT_50072">[SWS_CRYPT_50072]</a>. Functionally, the interface supports both step-by-step streaming and atomic single calls.</p>

<h4>Lifecycle</h4>
<p>From creation to reuse, the context goes through clearly defined phases:</p>
<ul>
<li><strong>Not initialized (Uninitialized):</strong> After instantiation, the context is not yet ready for use. A key must strictly be assigned before data processing. Otherwise, calls for transformation or initialization are rejected with <code>CryptoErrc::kUninitializedContext</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>.</li>
<li><strong>Configured (Configured / Key Set):</strong> The key is assigned via <code>SetKey()</code> with a <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a> or a <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50072" href="../spec/record.html?id=SWS_CRYPT_50072">[SWS_CRYPT_50072]</a>. In this state, static parameters such as tag and IV sizes can be queried. For single-call operations, this state is already sufficient.</li>
<li><strong>Streaming active (Processing):</strong> By calling <code>Start()</code> – either with an explicit initialization vector (IV) <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a> or without an IV or with the context's own IV <a class="spec-record-ref" data-req="SWS_CRYPT_50073" href="../spec/record.html?id=SWS_CRYPT_50073">[SWS_CRYPT_50073]</a> – the context transitions to the active streaming phase for a transformation direction (<code>CryptoTransform</code>). Here, additional data and payload data can be processed successively.</li>
<li><strong>Completion and return:</strong> The processing is regularly finalized by <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a> or <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50076" href="../spec/record.html?id=SWS_CRYPT_50076">[SWS_CRYPT_50076]</a>. Premature abort of an ongoing stream is possible at any time via <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50077" href="../spec/record.html?id=SWS_CRYPT_50077">[SWS_CRYPT_50077]</a>. After termination or abort, the context presumably remains in the configured state and is ready for re-initialization via <code>Start()</code>.</li>
</ul>

<h4>Usage Path</h4>
<p>Two paths are available for processing: streaming processing for larger or fragmented data and atomic single-call operations.</p>
<p>The typical streaming sequence is as follows:</p>
<ol>
<li><strong>Configuration:</strong> Bind key via <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a>. Limits can be determined in advance, such as minimum/maximum chunk sizes <a class="spec-record-ref" data-req="SWS_CRYPT_50162" href="../spec/record.html?id=SWS_CRYPT_50162">[SWS_CRYPT_50162]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50082" href="../spec/record.html?id=SWS_CRYPT_50082">[SWS_CRYPT_50082]</a>, the tag size <a class="spec-record-ref" data-req="SWS_CRYPT_50161" href="../spec/record.html?id=SWS_CRYPT_50161">[SWS_CRYPT_50161]</a>, as well as IV lengths <a class="spec-record-ref" data-req="SWS_CRYPT_50163" href="../spec/record.html?id=SWS_CRYPT_50163">[SWS_CRYPT_50163]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50164" href="../spec/record.html?id=SWS_CRYPT_50164">[SWS_CRYPT_50164]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50165" href="../spec/record.html?id=SWS_CRYPT_50165">[SWS_CRYPT_50165]</a>.</li>
<li><strong>Start:</strong> Initialization of the operation by <code>Start()</code> specifying the transformation direction (encryption or decryption) and, if applicable, the IV <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50073" href="../spec/record.html?id=SWS_CRYPT_50073">[SWS_CRYPT_50073]</a>.</li>
<li><strong>Associated data (optional):</strong> If additional plaintext metadata is to be authenticated, it must be passed via <code>UpdateAuthenticatedData()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20313" href="../spec/record.html?id=SWS_CRYPT_20313">[SWS_CRYPT_20313]</a>. This must strictly happen before any confidential payload data. The maximum size can be checked via <code>GetMaxAssociatedDataSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20103" href="../spec/record.html?id=SWS_CRYPT_20103">[SWS_CRYPT_20103]</a>.</li>
<li><strong>Confidential payload data:</strong> Step-by-step passing of data chunks using <code>UpdateConfidentialData()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>. Required output buffer sizes can be calculated dynamically via <code>GetRequiredOutputBufferSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50081" href="../spec/record.html?id=SWS_CRYPT_50081">[SWS_CRYPT_50081]</a>.</li>
<li><strong>Completion:</strong> Call of <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a> or <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50076" href="../spec/record.html?id=SWS_CRYPT_50076">[SWS_CRYPT_50076]</a>. In this process, remaining data is transformed, the authentication tag is finalized (generated for encryption, verified for decryption), and the generated IV is returned if needed.</li>
</ol>
<p>For compact data available in a single step, <code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>, <code>ProcessSingleCallWithInputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50079" href="../spec/record.html?id=SWS_CRYPT_50079">[SWS_CRYPT_50079]</a>, and <code>EncryptSingleCallWithOutputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50080" href="../spec/record.html?id=SWS_CRYPT_50080">[SWS_CRYPT_50080]</a> provide low-state processing without prior <code>Start()</code>.</p>

<h4>Error Scenarios</h4>
<p>The methods ensure the correct protocol sequence and cryptographic security via specific error codes:</p>
<ul>
<li><strong>Sequence violation for additional data:</strong> If <code>UpdateAuthenticatedData()</code> is called after confidential data has already been processed via <code>UpdateConfidentialData()</code>, the operation fails with <code>CryptoErrc::kInvalidUsageOrder</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20313" href="../spec/record.html?id=SWS_CRYPT_20313">[SWS_CRYPT_20313]</a>.</li>
<li><strong>Processing without start:</strong> If <code>UpdateAuthenticatedData()</code>, <code>UpdateConfidentialData()</code>, <code>Finish()</code>, <code>FinishEncrypt()</code>, or <code>Cancel()</code> are called without a prior successful <code>Start()</code> call, the error <code>CryptoErrc::kProcessingNotStarted</code> is returned <a class="spec-record-ref" data-req="SWS_CRYPT_20313" href="../spec/record.html?id=SWS_CRYPT_20313">[SWS_CRYPT_20313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50076" href="../spec/record.html?id=SWS_CRYPT_50076">[SWS_CRYPT_50076]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50077" href="../spec/record.html?id=SWS_CRYPT_50077">[SWS_CRYPT_50077]</a>.</li>
<li><strong>Key and permission checks:</strong> If the assigned key type does not match the context, <code>SetKey()</code> or <code>Start()</code> returns the error <code>CryptoErrc::kIncompatibleObject</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>. If the key lacks the required usage flags (<code>kAllowDataEncrypt</code> or <code>kAllowDataDecrypt</code>), this results in <code>CryptoErrc::kUsageViolation</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23911" href="../spec/record.html?id=SWS_CRYPT_23911">[SWS_CRYPT_23911]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>. For occupied or empty slots, <code>CryptoErrc::kBusyResource</code> or <code>CryptoErrc::kEmptyKeySlot</code> is reported <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>.</li>
<li><strong>Buffer and dimension errors:</strong> If the provided output buffer is too small for the transformed data or the IV, methods fail with <code>CryptoErrc::kInsufficientCapacity</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a>. Invalid lengths of input buffers, tags, or IVs lead to <code>CryptoErrc::kInvalidInputSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20313" href="../spec/record.html?id=SWS_CRYPT_20313">[SWS_CRYPT_20313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24715" href="../spec/record.html?id=SWS_CRYPT_24715">[SWS_CRYPT_24715]</a>.</li>
<li><strong>Failed authentication:</strong> If the verification of the authentication tag fails during decryption, <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50075" href="../spec/record.html?id=SWS_CRYPT_50075">[SWS_CRYPT_50075]</a> or <code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50078" href="../spec/record.html?id=SWS_CRYPT_50078">[SWS_CRYPT_50078]</a> signal the error <code>CryptoErrc::kAuthTagNotValid</code>. Important security note: During streaming, <code>UpdateConfidentialData()</code> already outputs the decrypted plaintext before the tag is checked; the application may only further use or release this data after successful <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50074" href="../spec/record.html?id=SWS_CRYPT_50074">[SWS_CRYPT_50074]</a>.</li>
</ul>
