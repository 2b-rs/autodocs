  <h4>Context</h4>
  <p>The class <code>ara::diag::DataTransferReadByPullHandler</code> serves the standardized handling of read data transfers initiated by diagnostic requests such as <code>RequestReadFile</code> or <code>RequestReadDirectory</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=367">AUTOSAR_AP_SWS_Diagnostics §8.10.2 “Class: DataTransferReadByPullHandler”</a>, <a class="spec-record-ref" data-req="SWS_DM_01506" href="../spec/record.html?id=SWS_DM_01506">[SWS_DM_01506]</a>. It acts as an interface between the diagnostic framework <em>AraDiag</em> and the actual application implementation.</p>
  <p>The transfer concept is based on a pull mechanism: AraDiag sequentially requests data chunks from the application implementation in order to subsequently transfer them to the UDS client (diagnostic tester) <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>. The class encapsulates the application-specific provision of file or directory contents in the context of the UDS transfer services.</p>

  <h4>Lifecycle</h4>
  <p>Strict rules apply to instances of <code>DataTransferReadByPullHandler</code> regarding creation, ownership, and destruction:</p>
  <ul>
    <li><strong>Creation:</strong> The default constructor is declared as <code>protected</code> and <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_01507" href="../spec/record.html?id=SWS_DM_01507">[SWS_DM_01507]</a>. Interpretation: Since the class contains pure virtual interface methods and the default constructor is protected, the application software likely implements and instantiates its own derived handler class.</li>
    <li><strong>Non-copyability:</strong> Both the copy constructor <a class="spec-record-ref" data-req="SWS_DM_01509" href="../spec/record.html?id=SWS_DM_01509">[SWS_DM_01509]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01512" href="../spec/record.html?id=SWS_DM_01512">[SWS_DM_01512]</a> are explicitly deleted (<code>=delete</code>). A handler is intended for exactly one single file transfer session (<em>single file transfer session</em>) and must not be copied <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=369">AUTOSAR_AP_SWS_Diagnostics §8.10.2.1.2 “Constructors”</a>.</li>
    <li><strong>Moveability:</strong> Move constructor <a class="spec-record-ref" data-req="SWS_DM_01508" href="../spec/record.html?id=SWS_DM_01508">[SWS_DM_01508]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01511" href="../spec/record.html?id=SWS_DM_01511">[SWS_DM_01511]</a> are defined as <code>noexcept=default</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=368">AUTOSAR_AP_SWS_Diagnostics §8.10.2.1.1 “Special Member Functions”</a>, so that a transfer of ownership is supported.</li>
    <li><strong>Destruction condition:</strong> The destructor is virtual and specified as <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_01510" href="../spec/record.html?id=SWS_DM_01510">[SWS_DM_01510]</a>. A central invariant is that an instance must under no circumstances be destroyed before <code>ExitRead()</code> has been called <a class="spec-record-ref" data-req="SWS_DM_01510" href="../spec/record.html?id=SWS_DM_01510">[SWS_DM_01510]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=368">AUTOSAR_AP_SWS_Diagnostics §8.10.2.1.1.2 “Destructor”</a>.</li>
    <li><strong>Concurrency:</strong> The virtual interface methods <code>Read()</code> and <code>ExitRead()</code> are classified as not thread-safe (<em>not thread-safe</em>) <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>, <a class="spec-record-ref" data-req="SWS_DM_01514" href="../spec/record.html?id=SWS_DM_01514">[SWS_DM_01514]</a>.</li>
  </ul>

  <h4>Usage Path</h4>
  <p>The typical call sequence of a pull-based read data transfer comprises two main phases:</p>
  <ol>
    <li><strong>Pull read loop:</strong> During the ongoing transfer, AraDiag repeatedly calls the method <code>Read()</code> on the handler <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>. In doing so, AraDiag passes a memory view <code>response_data</code> (of type <code>ara::core::Span&lt;const ara::core::Byte&gt;</code>) to a pre-allocated buffer as well as <code>meta_info</code> and a <code>cancellation_handler</code>. The application implementation compiles the content of the next data block and copies it into it up to the maximum size of the span <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>.</li>
    <li><strong>Chunk return:</strong> <code>Read()</code> returns a <code>ara::core::Future&lt;std::uint32_t&gt;</code>. The future is fulfilled with the number of bytes actually written to the buffer <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>. AraDiag embeds this payload in the positive UDS response directly after the <code>blockSequenceCounter</code> as <code>transferResponseParameterRecord</code> <a class="spec-record-ref" data-req="SWS_DM_01513" href="../spec/record.html?id=SWS_DM_01513">[SWS_DM_01513]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=370">AUTOSAR_AP_SWS_Diagnostics §8.10.2.1.3.2 “Read”</a>.</li>
    <li><strong>Session termination:</strong> As soon as all data has been transferred or the transfer is to be ended, AraDiag calls <code>ExitRead()</code> <a class="spec-record-ref" data-req="SWS_DM_01514" href="../spec/record.html?id=SWS_DM_01514">[SWS_DM_01514]</a>. Passed are the termination reason (<code>exit_type</code> of type <code>DataTransferExitType</code>), vehicle manufacturer-specific parameters (<code>transfer_request_parameter_record</code>), as well as metadata and the cancellation handler <a class="spec-record-ref" data-req="SWS_DM_01514" href="../spec/record.html?id=SWS_DM_01514">[SWS_DM_01514]</a>.</li>
    <li><strong>End of transaction:</strong> The application acknowledges the session end via a <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code>. Upon positive acknowledgment, the data contained in the vector is placed after the service ID (SID) as <code>transferResponseParameterRecord</code> into the positive UDS response <a class="spec-record-ref" data-req="SWS_DM_01514" href="../spec/record.html?id=SWS_DM_01514">[SWS_DM_01514]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=369">AUTOSAR_AP_SWS_Diagnostics §8.10.2.1.3.1 “ExitRead”</a>. Only after this call may the handler instance be destructed <a class="spec-record-ref" data-req="SWS_DM_01510" href="../spec/record.html?id=SWS_DM_01510">[SWS_DM_01510]</a>.</li>
  </ol>

  <h4>Error Scenarios</h4>
  <p>The specification defines clear requirements for error states and exceptional situations:</p>
  <ul>
    <li><strong>UDS error codes (NRC):</strong> If an error occurs while reading a data block or terminating the transfer, the respective future is not fulfilled regularly.
