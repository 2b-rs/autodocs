  <h4>Usage and Call Context</h4>
  <p>
    The synchronous callback function <code>CanTp_RxIndication</code> (<a class="spec-record-ref" data-req="SWS_CanTp_00214" href="../../spec/record.html?id=SWS_CanTp_00214">[SWS_CanTp_00214]</a>) signals the reception of an N-PDU by an underlying communication interface module to the CAN transport module. The identifier <code>RxPduId</code> as well as <code>PduInfoPtr</code> with pointers to buffer data (<code>SduDataPtr</code>), SDU length (<code>SduLength</code>), and metadata are passed. The function is reentrant for different PDU IDs, but non-reentrant for the same PDU ID (<a class="spec-record-ref" data-req="SWS_CanTp_00214" href="../../spec/record.html?id=SWS_CanTp_00214">[SWS_CanTp_00214]</a>). It may be called directly in the interrupt context, for example from the CAN receive ISR (<a class="spec-record-ref" data-req="SWS_CanTp_00235" href="../../spec/record.html?id=SWS_CanTp_00235">[SWS_CanTp_00235]</a>).
  </p>

  <h4>Error Handling and Validation</h4>
  <p>
    If development error detection is enabled and a NULL pointer is passed as <code>PduInfoPtr</code>, <code>CanTp_RxIndication</code> reports the error <code>CANTP_E_PARAM_POINTER</code> to the DET and terminates execution without doing anything (<a class="spec-record-ref" data-req="SWS_CanTp_00322" href="../../spec/record.html?id=SWS_CanTp_00322">[SWS_CanTp_00322]</a>).
  </p>
  <p>
    When padding check is enabled for frames with up to 8 bytes of payload, specific consistency rules apply:
  </p>
  <ul>
    <li>If an SF N-PDU with <code>SduLength &lt; 8</code> is received at <code>CanTpRxPaddingActivation == CANTP_ON</code>, the reception is discarded and the runtime error <code>CANTP_E_PADDING</code> is reported to the DET (<a class="spec-record-ref" data-req="SWS_CanTp_00345" href="../../spec/record.html?id=SWS_CanTp_00345">[SWS_CanTp_00345]</a>).</li>
    <li>If the last CF N-PDU of an ongoing transmission does not have exactly 8 bytes when padding is active (<code>SduLength != 8</code>), CanTp aborts the reception via <code>PduR_CanTpRxIndication()</code> with the return value <code>E_NOT_OK</code> and reports <code>CANTP_E_PADDING</code> (<a class="spec-record-ref" data-req="SWS_CanTp_00346" href="../../spec/record.html?id=SWS_CanTp_00346">[SWS_CanTp_00346]</a>).</li>
    <li>If an FC N-PDU with <code>SduLength &lt; 8</code> arrives during a transmission session with <code>CanTpTxPaddingActivation == CANTP_ON</code>, CanTp aborts the transmission session via <code>PduR_CanTpTxConfirmation()</code> with <code>E_NOT_OK</code> and reports <code>CANTP_E_PADDING</code> to the DET (<a class="spec-record-ref" data-req="SWS_CanTp_00349" href="../../spec/record.html?id=SWS_CanTp_00349">[SWS_CanTp_00349]</a>).</li>
  </ul>

  <h4>Generic Connections</h4>
  <p>
    If it is a generic connection (N-PDU with metadata), the CanTp module saves the addressing data from the metadata upon invocation for SF or FF frames (for Normal Fixed and Mixed 29-bit: <code>N_SA</code> and <code>N_TA</code>) for upward connection initiation as well as for subsequent FC and CF identification (<a class="spec-record-ref" data-req="SWS_CanTp_00330" href="../../spec/record.html?id=SWS_CanTp_00330">[SWS_CanTp_00330]</a>). For subsequent CF (<a class="spec-record-ref" data-req="SWS_CanTp_00333" href="../../spec/record.html?id=SWS_CanTp_00333">[SWS_CanTp_00333]</a>) and FC frames (<a class="spec-record-ref" data-req="SWS_CanTp_00336" href="../../spec/record.html?id=SWS_CanTp_00336">[SWS_CanTp_00336]</a>), CanTp matches the received metadata against these stored reference values.
  </p>
