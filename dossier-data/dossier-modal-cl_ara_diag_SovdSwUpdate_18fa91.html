<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient als Schnittstelle zur Abwicklung von Software-Updates über das ASAM-SOVD-Protokoll im AUTOSAR-Diagnoseserver.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse stellt die anwendungsseitige Schnittstelle zur Abwicklung standardisierter Software-Updates über das SOVD-Protokoll gemäß ASAM SOVD bereit <a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>. Nach der Instanziierung aktiviert die Anwendung die Weiterleitung von Diagnoseanfragen an die spezifischen Update-Handler über die Methode <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>. Über asynchrone Methoden werden Pakete registriert, vorbereitet, automatisiert oder manuell installiert sowie wieder gelöscht. Sämtliche datenübertragungs- und lebenszyklusrelevanten Vorgänge werden dabei nicht-blockierend über Futures verarbeitet.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::SovdSwUpdate</code> definiert die Schnittstelle zur Umsetzung von standardisierten Software-Updates gemäß ASAM SOVD innerhalb der AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_01874" href="../spec/record.html?id=SWS_DM_01874">[SWS_DM_01874]</a>. Da die eigentliche Geschäftslogik von Software-Aktualisierungen nicht im Funktionscluster Diagnostic Management (DM) angesiedelt ist, verbleibt die Ausführung bei der jeweiligen Applikation, während sich <code>ara::diag::SovdSwUpdate</code> auf die standardkonforme Abwicklung des zugrunde liegenden SOVD-Protokolls konzentriert <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.4 „SOVD Software Update API - concept“</a>. Für den Upload von Update-Dateien werden hierbei Übertragungsstrategien eingesetzt, wie sie für den UDS-Dienst 0x38 (RequestFileTransfer) spezifiziert sind <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.4 „SOVD Software Update API - concept“</a>, <a class="spec-record-ref" data-req="SWS_DM_01923" href="../spec/record.html?id=SWS_DM_01923">[SWS_DM_01923]</a>.</p>
<p>An den Abläufen sind drei wesentliche Komponenten beteiligt: der externe SOVD-Client, die Instanz des Diagnostic Servers (DM) zur Protokoll- und Routenverwaltung sowie die anwendungsspezifische Handler-Implementierung von <code>ara::diag::SovdSwUpdate</code> <a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>, <a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>ara::diag::SovdSwUpdate</code> erfolgt über den Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code>, der auf einen Port-Prototyp eines modellierten <code>DiagnosticSovdUpdateInterface</code> verweist, sowie eines Nebenläufigkeitsmodus (<code>ConcurrencyType</code>: <code>kConcurrent</code> oder <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>. Der Konstruktor ist threadsicher und ausnahmesicher spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>. Als Repräsentant einer eindeutigen Schnittstelleninstanz sind Kopierkonstruktor und Kopierzuweisungsoperator gelöscht (<code>=delete</code>) und geschützt <a class="spec-record-ref" data-req="SWS_DM_01912" href="../spec/record.html?id=SWS_DM_01912">[SWS_DM_01912]</a>, <a class="spec-record-ref" data-req="SWS_DM_01914" href="../spec/record.html?id=SWS_DM_01914">[SWS_DM_01914]</a>. Move-Konstruktion und Move-Zuweisung sind geschützt verfügbar, jedoch nicht threadsicher <a class="spec-record-ref" data-req="SWS_DM_01913" href="../spec/record.html?id=SWS_DM_01913">[SWS_DM_01913]</a>, <a class="spec-record-ref" data-req="SWS_DM_01915" href="../spec/record.html?id=SWS_DM_01915">[SWS_DM_01915]</a>.</p>
<p>Die Zerstörung des Objekts wird über den virtuellen Destruktor <code>~SovdSwUpdate()</code> abgewickelt, der als nicht threadsicher gilt <a class="spec-record-ref" data-req="SWS_DM_01911" href="../spec/record.html?id=SWS_DM_01911">[SWS_DM_01911]</a>. Ob die virtuellen Callback-Methoden der Klasse nebenläufig ausgeführt werden müssen, hängt direkt vom beim Konstruktor übergebenen <code>ConcurrencyType</code> ab <a class="spec-record-ref" data-req="SWS_DM_01910" href="../spec/record.html?id=SWS_DM_01910">[SWS_DM_01910]</a>, <a class="spec-record-ref" data-req="SWS_DM_01916" href="../spec/record.html?id=SWS_DM_01916">[SWS_DM_01916]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Interpretation: Da die bereitgestellten Schnittstellenmethoden rein virtuell (<code>=0</code>) deklariert sind, dürfte eine abgeleitete Anwendungsklasse diese implementieren, um die eigentliche Update-Ausführung vorzunehmen, während die Basisklasse die Plattform-Anbindung regelt. <a class="interp-q interp-q-open" data-q="Q-10500d9fc58503ea" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-10500d9fc58503ea" title="Frage Q-10500d9fc58503ea (offen): Die rein virtuellen Methoden werden in einer anwendungsspezifischen Subklasse implementiert.">Frage Q-10500d9fc58503ea (offen)</a></p>
<p>Der reguläre Ablauf gliedert sich in folgende Phasen:</p>
<ul>
<li><strong>Bereitstellung:</strong> Nach Erzeugung des Objekts ruft die Anwendung <code>Offer()</code> auf, um dem Diagnostic Management die Weiterleitung eingehender SOVD-Nachrichten an diese Instanz zu ermöglichen <a class="spec-record-ref" data-req="SWS_DM_01924" href="../spec/record.html?id=SWS_DM_01924">[SWS_DM_01924]</a>.</li>
<li><strong>Auskunft und Registrierung:</strong> Über <code>GetAllUpdates()</code> können vorhandene Update-Pakete abgefragt werden <a class="spec-record-ref" data-req="SWS_DM_01797" href="../spec/record.html?id=SWS_DM_01797">[SWS_DM_01797]</a>, <a class="spec-record-ref" data-req="SWS_DM_01916" href="../spec/record.html?id=SWS_DM_01916">[SWS_DM_01916]</a>. Soll ein neues Paket übertragen werden, fordert der Diagnostic Server über <code>RequestUpdatePackageRegistration()</code> eine Registrierung an, die asynchron eine Schreibsitzung (<code>DataTransferWriteSession</code>) zusammen mit einer Update-Paket-ID bereitstellt <a class="spec-record-ref" data-req="SWS_DM_01923" href="../spec/record.html?id=SWS_DM_01923">[SWS_DM_01923]</a>. Details und Status werden über <code>GetUpdatePackageDetails()</code> und <code>GetUpdatePackageStatus()</code> ermittelt <a class="spec-record-ref" data-req="SWS_DM_01802" href="../spec/record.html?id=SWS_DM_01802">[SWS_DM_01802]</a>, <a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>, <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>.</li>
<li><strong>Installation oder Löschung:</strong> Die Installation kann entweder automatisiert mittels <code>PutUpdatePackageAutomated()</code> angestoßen werden <a class="spec-record-ref" data-req="SWS_DM_01799" href="../spec/record.html?id=SWS_DM_01799">[SWS_DM_01799]</a>, <a class="spec-record-ref" data-req="SWS_DM_01918" href="../spec/record.html?id=SWS_DM_01918">[SWS_DM_01918]</a> oder in zwei Schritten über <code>PrepareUpdatePackage()</code> <a class="spec-record-ref" data-req="SWS_DM_01800" href="../spec/record.html?id=SWS_DM_01800">[SWS_DM_01800]</a>, <a class="spec-record-ref" data-req="SWS_DM_01919" href="../spec/record.html?id=SWS_DM_01919">[SWS_DM_01919]</a> gefolgt von <code>ExecuteUpdatePackage()</code> <a class="spec-record-ref" data-req="SWS_DM_01801" href="../spec/record.html?id=SWS_DM_01801">[SWS_DM_01801]</a>, <a class="spec-record-ref" data-req="SWS_DM_01920" href="../spec/record.html?id=SWS_DM_01920">[SWS_DM_01920]</a> erfolgen. Nicht mehr benötigte Pakete werden über <code>DeleteUpdatePackage()</code> entfernt <a class="spec-record-ref" data-req="SWS_DM_01922" href="../spec/record.html?id=SWS_DM_01922">[SWS_DM_01922]</a>.</li>
<li><strong>Beendigung:</strong> Vor dem Herunterfahren deaktiviert die Anwendung die Nachrichtenweiterleitung durch Aufruf von <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01925" href="../spec/record.html?id=SWS_DM_01925">[SWS_DM_01925]</a>.</li>
</ul>
