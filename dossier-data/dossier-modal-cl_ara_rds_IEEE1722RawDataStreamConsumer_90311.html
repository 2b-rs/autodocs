<h4>Context</h4>
<p>In the AUTOSAR Adaptive Platform (module <code>rds</code>), the template class <code>ara::rds::IEEE1722RawDataStreamConsumer</code> provides the central abstraction for receiving typed datagrams of an IEEE 1722 data stream. As a Raw Data Stream consumer, the class encapsulates interaction with the underlying stream endpoint and provides received datagrams as structured objects of the parameterized data type <code>T</code>. Typical interaction partners are the adaptive application software, which processes data streams such as audio, video, or time-sensitive raw sensor data, and the underlying platform and communication infrastructure, which is bound to the consumer via a <code>ara::core::InstanceSpecifier</code>.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>ara::rds::IEEE1722RawDataStreamConsumer</code> are not created via public default constructors, but are instantiated exclusively via the static factory method <code>Create</code> <a class="spec-record-ref" data-req="SWS_RDS_90312" href="../spec/record.html?id=SWS_RDS_90312">[SWS_RDS_90312]</a>. This method binds the consumer object to be created to a passed instance configuration and, in the case of success, returns the initialized object in a <code>ara::core::Result</code>.</p>
<p>With regard to ownership, the class enforces strict exclusivity of the data stream resource: The copy constructor <a class="spec-record-ref" data-req="SWS_RDS_90316" href="../spec/record.html?id=SWS_RDS_90316">[SWS_RDS_90316]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_RDS_90317" href="../spec/record.html?id=SWS_RDS_90317">[SWS_RDS_90317]</a> are explicitly deleted (<code>delete</code>). Duplication of consumer instances is therefore ruled out. Instead, the class supports move semantics: Move constructor <a class="spec-record-ref" data-req="SWS_RDS_90314" href="../spec/record.html?id=SWS_RDS_90314">[SWS_RDS_90314]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_RDS_90315" href="../spec/record.html?id=SWS_RDS_90315">[SWS_RDS_90315]</a> enable efficient transfer of ownership. Both operations are defined as <code>noexcept</code>, but explicitly specified as not thread-safe.</p>
<p>After creation, the object is initially in an unconnected state. The connection to the data stream is explicitly established by calling <code>Connect</code> <a class="spec-record-ref" data-req="SWS_RDS_90319" href="../spec/record.html?id=SWS_RDS_90319">[SWS_RDS_90319]</a>. The method <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_90320" href="../spec/record.html?id=SWS_RDS_90320">[SWS_RDS_90320]</a> is used for an orderly disconnection. During object destruction, the destructor <a class="spec-record-ref" data-req="SWS_RDS_90318" href="../spec/record.html?id=SWS_RDS_90318">[SWS_RDS_90318]</a> ensures that a connection that is still active is automatically shut down. The destructor is also specified as not thread-safe.</p>

<h4>Usage Path</h4>
<p>The regular sequence for using the IEEE 1722 stream consumer is divided into a fixed series of phases:</p>
<ol>
<li><strong>Creation:</strong> The application requests an instance of the consumer via the static method <code>Create</code> with the matching <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_RDS_90312" href="../spec/record.html?id=SWS_RDS_90312">[SWS_RDS_90312]</a>.</li>
<li><strong>Connection establishment:</strong> After successful provision of the object, <code>Connect</code> is called to connect the consumer to the physical or logical data stream <a class="spec-record-ref" data-req="SWS_RDS_90319" href="../spec/record.html?id=SWS_RDS_90319">[SWS_RDS_90319]</a>.</li>
<li><strong>Data reception:</strong> In active operation, the application periodically queries datagrams via <code>ReadData</code> <a class="spec-record-ref" data-req="SWS_RDS_90321" href="../spec/record.html?id=SWS_RDS_90321">[SWS_RDS_90321]</a>. Via the parameter <code>maxNumberOfDatagrams</code>, the caller limits the read volume per call; the result is provided synchronously as <code>std::vector&lt;T&gt;</code>.</li>
<li><strong>Connection teardown and release:</strong> To regularly terminate the transmission, the application calls <code>Shutdown</code> <a class="spec-record-ref" data-req="SWS_RDS_90320" href="../spec/record.html?id=SWS_RDS_90320">[SWS_RDS_90320]</a>. Otherwise, the destructor ensures that the connection is closed when leaving scope <a class="spec-record-ref" data-req="SWS_RDS_90318" href="../spec/record.html?id=SWS_RDS_90318">[SWS_RDS_90318]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The entire interface is specified as <code>noexcept</code> and does not use C++ exceptions. Error conditions are signaled in a platform-compliant manner via the return type <code>ara::core::Result</code>:</p>
<ul>
<li><strong>Failed instantiation:</strong> If the passed <code>InstanceSpecifier</code> cannot be resolved or the communication resource cannot be initialized, <code>Create</code> returns an erroneous <code>Result</code> object <a class="spec-record-ref" data-req="SWS_RDS_90312" href="../spec/record.html?id=SWS_RDS_90312">[SWS_RDS_90312]</a>.</li>
<li><strong>Error during connection establishment:</strong> If the stream endpoint is not reachable or establishing the connection fails, <code>Connect</code> returns an error code in <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_RDS_90319" href="../spec/record.html?id=SWS_RDS_90319">[SWS_RDS_90319]</a>.</li>
<li><strong>Error during data reception:</strong> If reading datagrams fails—Interpretation: for example because the connection was not established beforehand or was aborted unexpectedly—the return <code>Result</code> of <code>ReadData</code> contains the corresponding error code <a class="spec-record-ref" data-req="SWS_RDS_90321" href="../spec/record.html?id=SWS_RDS_90321">[SWS_RDS_90321]</a>.</li>
<li><strong>Concurrent accesses:</strong> Since move operations (<a class="spec-record-ref" data-req="SWS_RDS_90314" href="../spec/record.html?id=SWS_RDS_90314">[SWS_RDS_90314]</a>, <a class="spec-record-ref" data-req="SWS_RDS_90315" href="../spec/record.html?id=SWS_RDS_90315">[SWS_RDS_90315]</a>) and the destruction of the object <a class="spec-record-ref" data-req="SWS_RDS_90318" href="../spec/record.html?id=SWS_RDS_90318">[SWS_RDS_90318]</a> are explicitly not thread-safe, concurrent access without external synchronization leads to data races and undefined system behavior.</li>
</ul>
