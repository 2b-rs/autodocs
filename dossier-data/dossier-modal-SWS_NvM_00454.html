<h4>Verwendung und Semantik</h4>
<p>
Die Funktion <code>NvM_ReadBlock</code> dient dem asynchronen Kopieren von Nutzdaten aus dem NV-Speicher in den zugehörigen RAM-Block <a class="spec-record-ref" data-req="SWS_NvM_00010" href="../../spec/record.html?id=SWS_NvM_00010">[SWS_NvM_00010]</a>, <a class="spec-record-ref" data-req="SWS_NvM_00454" href="../../spec/record.html?id=SWS_NvM_00454">[SWS_NvM_00454]</a>. Der Aufruf ist reentrant <a class="spec-record-ref" data-req="SWS_NvM_00454" href="../../spec/record.html?id=SWS_NvM_00454">[SWS_NvM_00454]</a>. Er übernimmt die Parameter, reiht den Leseauftrag in die interne Job-Queue ein und gibt unmittelbar <code>E_OK</code> bei erfolgreicher Annahme bzw. <code>E_NOT_OK</code> bei Ablehnung zurück <a class="spec-record-ref" data-req="SWS_NvM_00195" href="../../spec/record.html?id=SWS_NvM_00195">[SWS_NvM_00195]</a>, <a class="spec-record-ref" data-req="SWS_NvM_00454" href="../../spec/record.html?id=SWS_NvM_00454">[SWS_NvM_00454]</a>.
</p>
<p>
Wird ein Zeiger <code>NvM_DstPtr</code> übergeben, können Daten abweichend von der Blockkonfiguration in einen temporären RAM-Puffer gelesen werden; ein unzulässiger <code>NULL</code>-Zeiger führt in diesem Szenario zu einem DET-Fehler <a class="spec-record-ref" data-req="SWS_NvM_00196" href="../../spec/record.html?id=SWS_NvM_00196">[SWS_NvM_00196]</a>, <a class="spec-record-ref" data-req="SWS_NvM_00278" href="../../spec/record.html?id=SWS_NvM_00278">[SWS_NvM_00278]</a>. Ein konfigurierter permanenter RAM-Block wird direkt beim Einreihen oder bei Start der Jobverarbeitung als ungültig markiert <a class="spec-record-ref" data-req="SWS_NvM_00198" href="../../spec/record.html?id=SWS_NvM_00198">[SWS_NvM_00198]</a>. Erst nach erfolgreichem Kopiervorgang gilt der RAM-Block als gültig sowie unverändert <a class="spec-record-ref" data-req="SWS_NvM_00200" href="../../spec/record.html?id=SWS_NvM_00200">[SWS_NvM_00200]</a>, und das Auftragsergebnis wechselt auf <code>NVM_REQ_OK</code> <a class="spec-record-ref" data-req="SWS_NvM_00206" href="../../spec/record.html?id=SWS_NvM_00206">[SWS_NvM_00206]</a>.
</p>
<h4>Fehlerbehandlung und Datenintegrität</h4>
<p>
Ist für den Block eine Prüfsumme aktiviert (<code>NvMCalRamBlockCrC == TRUE</code>), fordert der Job nach dem Kopieren eine Neuberechnung an <a class="spec-record-ref" data-req="SWS_NvM_00201" href="../../spec/record.html?id=SWS_NvM_00201">[SWS_NvM_00201]</a>:
</p>
<ul>
<li>Bei CRC-Fehlern wird <code>NVM_E_INTEGRITY_FAILED</code> an das DEM gemeldet <a class="spec-record-ref" data-req="SWS_NvM_00203" href="../../spec/record.html?id=SWS_NvM_00203">[SWS_NvM_00203]</a>. Sofern vorhanden, werden Standardwerte geladen und das Ergebnis auf <code>NVM_REQ_RESTORED_DEFAULTS</code> gesetzt <a class="spec-record-ref" data-req="SWS_NvM_00202" href="../../spec/record.html?id=SWS_NvM_00202">[SWS_NvM_00202]</a>. Fehlen ROM-Daten und Initialisierungs-Callbacks, resultiert <code>NVM_REQ_INTEGRITY_FAILED</code> <a class="spec-record-ref" data-req="SWS_NvM_00204" href="../../spec/record.html?id=SWS_NvM_00204">[SWS_NvM_00204]</a>.</li>
<li>Meldet der Speichertreiber <code>MEMIF_JOB_FAILED</code> und sind keine Ersatzwerte verfügbar, endet der Auftrag mit <code>NVM_REQ_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_NvM_00359" href="../../spec/record.html?id=SWS_NvM_00359">[SWS_NvM_00359]</a>.</li>
</ul>
<h4>Besonderheiten der Blocktypen</h4>
<ul>
<li><strong>Redundant:</strong> Schlägt das Lesen der ersten Kopie fehl, wird automatisch die zweite NV-Kopie herangezogen <a class="spec-record-ref" data-req="SWS_NvM_00199" href="../../spec/record.html?id=SWS_NvM_00199">[SWS_NvM_00199]</a>. Sind beide Kopien ungültig, wird der Gesamtblock invalidiert <a class="spec-record-ref" data-req="SWS_NvM_00317" href="../../spec/record.html?id=SWS_NvM_00317">[SWS_NvM_00317]</a>.</li>
<li><strong>Dataset:</strong> Ist der über den Datensatz-Index selektierte Block als ungültig markiert, unterbleibt das Kopieren in das RAM <a class="spec-record-ref" data-req="SWS_NvM_00355" href="../../spec/record.html?id=SWS_NvM_00355">[SWS_NvM_00355]</a>.</li>
<li><strong>Write-Once:</strong> Konsistent gelesene Blöcke mit gesetztem <code>NVM_WRITE_BLOCK_ONCE</code> werden dauerhaft schreibgeschützt <a class="spec-record-ref" data-req="SWS_NvM_00316" href="../../spec/record.html?id=SWS_NvM_00316">[SWS_NvM_00316]</a>.</li>
</ul>
