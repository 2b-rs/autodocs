<p class="ai-level ai-oneliner-lead" data-ai-level="1">Löst abstrakte Instanz-Spezifizierer zur Laufzeit in konkrete Bezeichner für die Dienstkommunikation auf.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Namespace <code>ara::com::runtime</code> stellt zentrale Laufzeitdienste zur Auflösung von Kommunikationsendpunkten im Kommunikationsmanagement bereit <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=39">AUTOSAR_AP_SWS_CommunicationManagement S. 39</a>. Seine Kernfunktion <code>ResolveInstanceIDs</code> übersetzt abstrakte Modellbezeichner vom Typ <code>ara::core::InstanceSpecifier</code> in konkrete, für Proxies und Skeletons nutzbare <code>ara::com::InstanceIdentifierContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Schlägt die Zuordnung eines formal gültigen Bezeichners im Deployment fehl, liefert die ausnahmesichere Funktion den Fehlercode <code>ComErrc::kInstanceIDNotResolvable</code> innerhalb eines <code>ara::core::Result</code> zurück. Aufrufer müssen daher das Result-Objekt vor der Dienstinstanziierung auswerten.</p>

<h4>Kontext</h4>
<p>Der Namespace <code>ara::com::runtime</code> stellt zentrale Laufzeitfunktionalitäten für das Kommunikationsmanagement (<code>ara::com</code>) der AUTOSAR Adaptive Platform bereit <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=39">AUTOSAR_AP_SWS_CommunicationManagement S. 39</a>. Seine primäre funktionale Verantwortung besteht in der Entkopplung der abstrakten Software-Architektur von der konkreten Kommunikationsinfrastruktur zur Laufzeit. Während Applikationen und Softwarekomponenten in ihren Schnittstellen über abstrakte Modellbezeichner (<code>ara::core::InstanceSpecifier</code>) an Ports gebunden sind, benötigt die Kommunikations-Middleware für den Aufbau von Verbindungen konkrete Adressierungs- und Instanzierungsdaten in Form von <code>ara::com::InstanceIdentifier</code>-Objekten <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>.</p>
<p>Die im Header <code>ara/com/runtime.h</code> deklarierte Funktion <code>ResolveInstanceIDs</code> bildet die Brücke zwischen diesen beiden Abstraktionsebenen <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Sie nimmt einen <code>ara::core::InstanceSpecifier</code> entgegen und transformiert ihn in einen <code>ara::com::InstanceIdentifierContainer</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=40">AUTOSAR_AP_SWS_CommunicationManagement S. 40</a>. Interpretation: Die konkrete Zuordnung dürfte intern auf den im Ausführungskontext hinterlegten Manifest- und Deployment-Konfigurationen basieren, wodurch Anwendungscode portabel und frei von fest verdrahteten Netzwerk- oder Protokolladressen bleibt. <a class="interp-q interp-q-open" data-q="Q-8fab6de1c39a065a" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-8fab6de1c39a065a" title="Frage Q-8fab6de1c39a065a (offen): Die Zuordnung von ara::core::InstanceSpecifier zu konkreten ara::com::InstanceIdentifier-Objekten dürfte intern auf den im Manifest hinterlegten Deployment-Beschreibungen basieren.">Frage Q-8fab6de1c39a065a (offen)</a></p>

<h4>Nutzungspfad</h4>
<p>Der typische Einsatz des Namespace <code>ara::com::runtime</code> erfolgt während der Initialisierungs- und Startphase einer adaptiven Anwendung, bevor Kommunikationsbeziehungen über Service-Proxies oder Service-Skeletons etabliert werden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=41">AUTOSAR_AP_SWS_CommunicationManagement S. 41</a>. Ein Service Consumer oder Provider durchläuft dabei einen deterministischen Auflösungspfad:</p>
<ul>
<li><strong>Spezifizierer ermitteln:</strong> Die Anwendung instanziiert oder referenziert den für den jeweiligen Kommunikationsport definierten Bezeichner vom Typ <code>ara::core::InstanceSpecifier</code>.</li>
<li><strong>Instanzen auflösen:</strong> Der Bezeichner wird an die Funktion <code>ara::com::runtime::ResolveInstanceIDs</code> übergeben <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>.</li>
<li><strong>Ergebnis prüfen:</strong> Der Aufruf liefert ein Objekt des Typs <code>ara::core::Result&lt;ara::com::InstanceIdentifierContainer&gt;</code> zurück, das auf erfolgreiche Ausführung oder Fehlerzustände geprüft wird <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>.</li>
<li><strong>Container verarbeiten:</strong> Bei Erfolg enthält der <code>ara::com::InstanceIdentifierContainer</code> eine Anzahl von Instanzbezeichnern, die proportional zur Anzahl der gefundenen Treffer im Deployment ist <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Die Anwendung kann gezielt eine Instanz auswählen oder über alle verfügbaren Instanzen iterieren.</li>
<li><strong>Proxy oder Skeleton instanziieren:</strong> Die aufgelösten <code>ara::com::InstanceIdentifier</code>-Objekte werden anschließend zur Erzeugung konkreter Proxy- oder Skeleton-Instanzen verwendet <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=42">AUTOSAR_AP_SWS_CommunicationManagement S. 42</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Schnittstellen im Namespace <code>ara::com::runtime</code> folgen dem plattformweiten Paradigma robuster, ausnahmefreier Fehlerbehandlung. Entsprechend der Spezifikation ist <code>ResolveInstanceIDs</code> als <code>noexcept</code> deklariert und besitzt die Ausnahme-Sicherheitsstufe <em>exception safe</em> <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Fehler werden daher niemals über C++-Exceptions signalisiert, sondern vollständig über den Fehlermonaden <code>ara::core::Result</code> transportiert <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=47">AUTOSAR_AP_SWS_CommunicationManagement S. 47</a>.</p>
<p>Das zentrale spezifizierte Fehlerszenario betrifft den Fehlercode <code>ComErrc::kInstanceIDNotResolvable</code> <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Dieser Fehler tritt auf, wenn der übergebene <code>ara::core::InstanceSpecifier</code> formal gültig ist, jedoch in der aktuellen Systemkonfiguration oder im Manifest keinem existierenden <code>ara::com::InstanceIdentifier</code> zugeordnet werden kann <a class="spec-record-ref" data-req="SWS_CM_00118" href="../spec/record.html?id=SWS_CM_00118">[SWS_CM_00118]</a>. Dies deutet in der Praxis auf Diskrepanzen zwischen Modellierung und Deployment hin, etwa wenn ein Service Provider auf einer anderen Maschine nicht deployt wurde oder das Binding im Manifest fehlt.
