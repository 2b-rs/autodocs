<p class="ai-level ai-oneliner-lead" data-ai-level="1">Kapselt einen Logging-Kontext zur threadsicheren Erfassung formatierter oder modellierter Protokollnachrichten.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::log::Logger</code> repräsentiert einen Kontext für das Erfassen von Log-Nachrichten innerhalb eines Anwendungsprozesses über temporäre Streams oder modellierte Nachrichtenformate <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>. Da der Standardkonstruktor gelöscht ist, erfolgt die Erzeugung und Verwaltung des Lebenszyklus vollständig durch das Logging-Framework <a class="spec-record-ref" data-req="SWS_LOG_00259" href="../spec/record.html?id=SWS_LOG_00259">[SWS_LOG_00259]</a>. Vor der zeitintensiven Aufbereitung von Meldungsdaten kann der aktuell aktive Meldegrad abgefragt werden. Sämtliche Schnittstellen der Klasse sind threadsicher spezifiziert und erlauben den synchronisationsfreien Aufruf aus mehreren Threads.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::log::Logger</code> repräsentiert einen Logger-Kontext innerhalb eines Anwendungsprozesses oder Prozessbereichs im Modul <code>log</code>. Ein solcher Kontext kapselt eine spezifische Kontext-ID, eine zugehörige Beschreibung sowie einen Standard-Log-Level. Anwendungsentwickler interagieren mit Logger-Instanzen, um Log-Nachrichten entweder über Stream-Objekte wie <code>LogStream</code> <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a> oder als strukturierte, modellierte Meldungen an das Logging-Framework zu übergeben <a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>. Die Instanzen agieren als Vermittler zwischen den anwendungsinternen Threads und dem Logging-Backend.</p>

<h4>Lebenszyklus</h4>
<p>Die Verwaltung der Instanzen unterliegt einer strikten Eigentümerschaft durch das Logging-Framework. Um die automatische Registrierung am Logging-Backend bei der Erzeugung und die Deregistrierung beim Herunterfahren des Anwendungsprozesses sicherzustellen, ist der Standardkonstruktor gelöscht <a class="spec-record-ref" data-req="SWS_LOG_00259" href="../spec/record.html?id=SWS_LOG_00259">[SWS_LOG_00259]</a>. Anwendungen dürfen und können <code>Logger</code>-Objekte nicht direkt instanziieren, sondern müssen stattdessen die Erzeugungsfunktionen <code>ara::log::CreateLogger</code> nutzen. Die Zerstörung und Freigabe erfolgt über den Destruktor <a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>, der vom Logging-Framework gesteuert wird, sodass sich Anwender nicht um die Lebensdauer kümmern müssen.</p>
<p>Hinsichtlich der Nebenläufigkeit sind sämtliche Zugriffsmethoden als threadsicher (<code>thread-safe</code>) spezifiziert, unter anderem <a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a> und <a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>. Dadurch können mehrere nebenläufige Threads denselben Logger-Kontext gleichzeitig verwenden, ohne dass zusätzliche Synchronisationsmechanismen auf Anwendungsseite erforderlich sind.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Einsatz eines Loggers umfasst die Überprüfung der aktuellen Konfiguration, die Anpassung von Schwellwerten und das Absetzen von Meldungen:</p>
<ul>
<li><strong>Prüfung der Ausgabeberechtigung:</strong> Vor aufwendigen Vorbereitungen von Protokolldaten kann mit <code>IsEnabled</code> abgefragt werden, ob ein gewünschter Log-Level aktiv gemeldet wird <a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>.</li>
<li><strong>Konfiguration:</strong> Der minimale Melde-Schwellwert einer Logger-Instanz lässt sich zur Laufzeit über <code>SetThreshold</code> neu konfigurieren <a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>.</li>
<li><strong>Stream-basiertes Logging:</strong> Über spezifische Methoden für einzelne Schweregrade – <code>LogFatal</code> <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>, <code>LogError</code> <a class="spec-record-ref" data-req="SWS_LOG_00065" href="../spec/record.html?id=SWS_LOG_00065">[SWS_LOG_00065]</a>, <code>LogWarn</code> <a class="spec-record-ref" data-req="SWS_LOG_00066" href="../spec/record.html?id=SWS_LOG_00066">[SWS_LOG_00066]</a>, <code>LogInfo</code> <a class="spec-record-ref" data-req="SWS_LOG_00067" href="../spec/record.html?id=SWS_LOG_00067">[SWS_LOG_00067]</a>, <code>LogDebug</code> <a class="spec-record-ref" data-req="SWS_LOG_00068" href="../spec/record.html?id=SWS_LOG_00068">[SWS_LOG_00068]</a> oder <code>LogVerbose</code> <a class="spec-record-ref" data-req="SWS_LOG_00069" href="../spec/record.html?id=SWS_LOG_00069">[SWS_LOG_00069]</a> – sowie über das dynamische <code>WithLevel</code> <a class="spec-record-ref" data-req="SWS_LOG_00131" href="../spec/record.html?id=SWS_LOG_00131">[SWS_LOG_00131]</a> wird ein <code>LogStream</code>-Objekt erzeugt. Dieses nimmt Daten über den Operator <code>&lt;&lt;</code> entgegen. Üblicherweise endet die Lebensdauer des Stream-Objekts mit dem Semikolon der Anweisung <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>.</li>
<li><strong>Modellierte Nachrichten:</strong> Alternativ können typisierte und modellierte Nachrichten direkt mit <code>Log</code> <a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a> oder unter Angabe von Attributen mit <code>LogWith</code> <a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a> übergeben werden.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Schnittstellen der Klasse sind weitgehend als <code>noexcept</code> und ausnahmesicher (<code>exception safe</code>) spezifiziert, was unerwartete Laufzeitunterbrechungen minimiert <a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>.
