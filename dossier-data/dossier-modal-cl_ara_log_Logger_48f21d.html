<h4>Context</h4>
<p>The class <code>ara::log::Logger</code> represents a logging context within an AUTOSAR Adaptive application process or process area. Such a context encapsulates central properties for logging: a context ID, an associated context ID description, and a configurable default log level. Log output within the system is differentiated and controlled via these contexts.</p>
<p>In the system architecture, <code>ara::log::Logger</code> acts as an intermediary between three parties:</p>
<ul>
<li><strong>Application Process:</strong> Uses instances of <code>ara::log::Logger</code> to issue messages, dynamically query filter thresholds, or adjust them.</li>
<li><strong>Logging framework:</strong> Holds strict ownership ("strong ownership") of all logger instances, controls their creation via factory functions such as <code>ara::log::CreateLogger</code>, and handles the housekeeping.</li>
<li><strong>Logging backend:</strong> Receives the actual log data; logger contexts are automatically registered with the backend during the initialization phase and deregistered during orderly process shutdown.</li>
</ul>

<h4>Lifecycle</h4>
<p>The management of instances of <code>ara::log::Logger</code> is subject to strict control by the framework to ensure seamless synchronization with the logging backend:</p>
<ul>
<li><strong>Creation and ownership:</strong> The default constructor is explicitly deleted (<code>Logger() = delete</code>, <a class="spec-record-ref" data-req="SWS_LOG_00259" href="../spec/record.html?id=SWS_LOG_00259">[SWS_LOG_00259]</a>). Direct instantiation by the application is prohibited. Creation takes place in a controlled manner via functions such as <code>ara::log::CreateLogger</code>. Ownership remains with the logging framework.</li>
<li><strong>Registration and cleanup:</strong> A logger context is automatically registered with the logging backend upon its creation. When the process terminates, deregistration occurs automatically, relieving application developers of manual lifecycle management.</li>
<li><strong>Destruction:</strong> The destructor <code>~Logger()</code> is specified (<a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>). It is declared as thread-safe, but designated as not exception safe ("not exception safe") (<a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>).</li>
<li><strong>Concurrency:</strong> All methods for logging and threshold querying are specified as thread-safe (<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>). Multiple threads can use the same logger instance in parallel.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical procedure for issuing log messages is divided into the following phases:</p>
<ol>
<li><strong>Checking or configuring the filter threshold:</strong> The application can set the filter threshold of an instance at runtime via <code>SetThreshold(threshold)</code> (<a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>). Prior to computationally intensive preparations of log data, <code>IsEnabled(logLevel)</code> can be used to query whether the desired log level satisfies the configured reporting threshold (<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>). If the check yields <code>false</code>, the preparation can be skipped.</li>
<li><strong>Initiating stream-based logging:</strong> For text logging, the class provides specific methods for each severity level:
<ul>
<li><code>LogFatal()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>)</li>
<li><code>LogError()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00065" href="../spec/record.html?id=SWS_LOG_00065">[SWS_LOG_00065]</a>)</li>
<li><code>LogWarn()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00066" href="../spec/record.html?id=SWS_LOG_00066">[SWS_LOG_00066]</a>)</li>
<li><code>LogInfo()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00067" href="../spec/record.html?id=SWS_LOG_00067">[SWS_LOG_00067]</a>)</li>
<li><code>LogDebug()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00068" href="../spec/record.html?id=SWS_LOG_00068">[SWS_LOG_00068]</a>)</li>
<li><code>LogVerbose()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00069" href="../spec/record.html?id=SWS_LOG_00069">[SWS_LOG_00069]</a>)</li>
<li><code>WithLevel(logLevel)</code> (<a class="spec-record-ref" data-req="SWS_LOG_00131" href="../spec/record.html?id=SWS_LOG_00131">[SWS_LOG_00131]</a>) for programmatically determining the urgency.</li>
</ul>
Each of these methods returns a <code>LogStream</code> object that accepts arguments via the stream operator <code>&lt;&lt;</code> (<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>).</li>
<li><strong>Stream lifetime and output:</strong> By default, the lifetime of the <code>LogStream</code> object is limited to a single statement and ends with the semicolon after the last argument (<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>). If required, the stream can be assigned to a variable in order to extend its lifetime across multiple statements (<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>).</li>
<li><strong>Outputting modeled messages:</strong> As an alternative to streaming, pre-modeled messages can be output via <code>Log(id, args...)</code> (<a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>). If additional attributes are to be passed, the call is made via <code>LogWith(attrs, msgId, params...)</code> with an attribute tuple (<a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error handling in <code>ara::log::Logger</code> is predominantly based on static type checking at compile time and strict exception safety:</p>
<ul>
<li><strong>Mismatched arguments in modeled messages:</strong> If the template function <code>Log(id, args...)</code> is called with parameters that do not correspond exactly to the definition of the modeled message, the program is ill-formed ("ill-formed") (<a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>). This leads to a compile-time error.</li>
<li><strong>Invalid attributes with LogWith:</strong> For <code>LogWith(attrs, msgId, params...)</code>, the function is excluded from overload resolution via SFINAE if an element of the attribute tuple does not represent a valid attribute (<a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>).</li>
<li><strong>Exception guarantees:</strong> All logging and query functions (including <code>IsEnabled</code>, <code>SetThreshold</code>, all <code>Log*</code> methods, <code>WithLevel</code>, <code>Log</code>, and <code>LogWith</code>) are specified as exception safe ("exception safe") and declared with <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00131" href="../spec/record.html?id=SWS_LOG_00131">[SWS_LOG_00131]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>).
