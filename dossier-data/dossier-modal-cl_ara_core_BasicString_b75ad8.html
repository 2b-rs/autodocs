<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::core::BasicString</code> stellt im Modul <code>core</code> eine speicherallokatorbewusste Zeichenkettenimplementierung auf Basis des C++-PMR-Standards bereit <a class="spec-record-ref" data-req="SWS_CORE_03005" href="../spec/record.html?id=SWS_CORE_03005">[SWS_CORE_03005]</a>. Sie übernimmt die dynamische Pufferverwaltung, unterstützt Operationen von der Reservierung bis zum Anhängen und arbeitet nahtlos mit <code>StringView</code> zusammen. Als wesentliche sicherheitsrelevante Randbedingung werden fehlerhafte Zugriffe nicht durch STL-Exceptions, sondern durch AUTOSAR-spezifische Violations wie <code>IsoStdOutOfRangeViolation</code> gemeldet <a class="spec-record-ref" data-req="SWS_CORE_03063" href="../spec/record.html?id=SWS_CORE_03063">[SWS_CORE_03063]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::core::BasicString</code> bildet im Modul <code>core</code> der AUTOSAR Adaptive Platform eine Implementierung des C++-Standardtyps <code>std::pmr::basic_string</code> ab (definiert in der Header-Datei <code>#include "ara/core/string.h"</code>). Sie stellt ein dynamisches Zeichenketten-Klassen-Template dar, das über den Typparameter <code>Allocator</code> parametrisiert wird <a class="spec-record-ref" data-req="SWS_CORE_03005" href="../spec/record.html?id=SWS_CORE_03005">[SWS_CORE_03005]</a>. Gegenüber dem allgemeinen Standard <code>[basic.string]</code> weist die AUTOSAR-Spezifikation wesentliche Spezialisierungen auf: Der Zeichentyp <code>traits_type</code> ist verbindlich auf <code>std::char_traits&lt;char&gt;</code> festgelegt <a class="spec-record-ref" data-req="SWS_CORE_03003" href="../spec/record.html?id=SWS_CORE_03003">[SWS_CORE_03003]</a>, <code>size_type</code> ist auf <code>std::size_t</code> spezialisiert <a class="spec-record-ref" data-req="SWS_CORE_03012" href="../spec/record.html?id=SWS_CORE_03012">[SWS_CORE_03012]</a> und <code>charT</code> wird durch <code>value_type</code> ersetzt <a class="spec-record-ref" data-req="SWS_CORE_03004" href="../spec/record.html?id=SWS_CORE_03004">[SWS_CORE_03004]</a>. Wichtigste Interaktionspartner sind der allozierende Speichermanager (über <code>allocator_type</code>) sowie die Referenzklasse <code>StringView</code>, mit der <code>BasicString</code> über direkte Konvertierungsoperatoren <a class="spec-record-ref" data-req="SWS_CORE_03301" href="../spec/record.html?id=SWS_CORE_03301">[SWS_CORE_03301]</a> und Konstruktoren <a class="spec-record-ref" data-req="SWS_CORE_03302" href="../spec/record.html?id=SWS_CORE_03302">[SWS_CORE_03302]</a> eng zusammenarbeitet.</p>

<h4>Lebenszyklus</h4>
<p>Der Lebenszyklus einer Instanz beginnt mit deren Konstruktion. Neben der Standardkonstruktion <a class="spec-record-ref" data-req="SWS_CORE_03024" href="../spec/record.html?id=SWS_CORE_03024">[SWS_CORE_03024]</a> kann ein spezifischer Allokator explizit übergeben werden <a class="spec-record-ref" data-req="SWS_CORE_03025" href="../spec/record.html?id=SWS_CORE_03025">[SWS_CORE_03025]</a>. Zeichenketten lassen sich ferner aus C-Strings <a class="spec-record-ref" data-req="SWS_CORE_03029" href="../spec/record.html?id=SWS_CORE_03029">[SWS_CORE_03029]</a>, Teilstrings <a class="spec-record-ref" data-req="SWS_CORE_03026" href="../spec/record.html?id=SWS_CORE_03026">[SWS_CORE_03026]</a>, Initialisierungslisten <a class="spec-record-ref" data-req="SWS_CORE_03032" href="../spec/record.html?id=SWS_CORE_03032">[SWS_CORE_03032]</a>, Iteratoren <a class="spec-record-ref" data-req="SWS_CORE_03031" href="../spec/record.html?id=SWS_CORE_03031">[SWS_CORE_03031]</a> oder Ansichten wie <code>StringView</code> <a class="spec-record-ref" data-req="SWS_CORE_03302" href="../spec/record.html?id=SWS_CORE_03302">[SWS_CORE_03302]</a> erzeugen. Kopieroperationen <a class="spec-record-ref" data-req="SWS_CORE_03020" href="../spec/record.html?id=SWS_CORE_03020">[SWS_CORE_03020]</a> fordern neuen dynamischen Speicher über den Allokator an. Für ressourcenschonende Besitzübergaben steht eine Verschiebekonstruktion zur Verfügung, welche als <code>noexcept</code> deklariert ist <a class="spec-record-ref" data-req="SWS_CORE_03022" href="../spec/record.html?id=SWS_CORE_03022">[SWS_CORE_03022]</a>.</p>
<p>Während der Lebensdauer verwaltet die Instanz ihren Speicherbereich eigenständig. Der Inhalt kann über Zuweisungen (<a class="spec-record-ref" data-req="SWS_CORE_03021" href="../spec/record.html?id=SWS_CORE_03021">[SWS_CORE_03021]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03084" href="../spec/record.html?id=SWS_CORE_03084">[SWS_CORE_03084]</a>), Größenanpassungen via <code>resize</code> (<a class="spec-record-ref" data-req="SWS_CORE_03058" href="../spec/record.html?id=SWS_CORE_03058">[SWS_CORE_03058]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03059" href="../spec/record.html?id=SWS_CORE_03059">[SWS_CORE_03059]</a>) oder das Zurücksetzen mittels <code>clear</code> <a class="spec-record-ref" data-req="SWS_CORE_03057" href="../spec/record.html?id=SWS_CORE_03057">[SWS_CORE_03057]</a> modifiziert werden. Zwei Zeichenketten können über <code>swap</code> effizient vertauscht werden, was bedingt ausnahmesicher ist <a class="spec-record-ref" data-req="SWS_CORE_03412" href="../spec/record.html?id=SWS_CORE_03412">[SWS_CORE_03412]</a>. Am Lebenszyklusende gibt der Destruktor <code>~BasicString()</code> <a class="spec-record-ref" data-req="SWS_CORE_03038" href="../spec/record.html?id=SWS_CORE_03038">[SWS_CORE_03038]</a> den allokierten Speicher über den zugeordneten Allokator frei. Hinsichtlich Nebenläufigkeit bietet <code>BasicString</code> keine eigene Thread-Synchronisation; nebenläufige modifizierende Zugriffe auf dieselbe Instanz erfordern daher externe Absicherung.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad umfasst die Instanziierung, die optionale Pufferreservierung, das schrittweise Modifizieren sowie den abschließenden lesenden Zugriff oder die Übergabe:</p>
<ul>
<li><strong>Erzeugung:</strong> Die Instanz wird erzeugt, beispielsweise unter expliziter Übergabe einer Allokatorinstanz <a class="spec-record-ref" data-req="SWS_CORE_03025" href="../spec/record.html?id=SWS_CORE_03025">[SWS_CORE_03025]</a> oder aus einer bestehenden Zeichenkettenansicht <a class="spec-record-ref" data-req="SWS_CORE_03302" href="../spec/record.html?id=SWS_CORE_03302">[SWS_CORE_03302]</a>.</li>
<li><strong>Kapazitätsreservierung:</strong> Um wiederholte Neuallokationen bei sukzessivem Textaufbau zu vermeiden, kann vorab Pufferkapazität mit <code>reserve</code> angefordert werden <a class="spec-record-ref" data-req="SWS_CORE_03054" href="../spec/record.html?id=SWS_CORE_03054">[SWS_CORE_03054]</a>.</li>
<li><strong>Modifikation:</strong> Textinhalte werden über <code>append</code> (<a class="spec-record-ref" data-req="SWS_CORE_03076" href="../spec/record.html?id=SWS_CORE_03076">[SWS_CORE_03076]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03308" href="../spec/record.html?id=SWS_CORE_03308">[SWS_CORE_03308]</a>) oder <code>operator+=</code> (<a class="spec-record-ref" data-req="SWS_CORE_03072" href="../spec/record.html?id=SWS_CORE_03072">[SWS_CORE_03072]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03307" href="../spec/record.html?id=SWS_CORE_03307">[SWS_CORE_03307]</a>) angehängt. Zeichenweises Einfügen oder Ersetzen erfolgt über <code>insert</code> <a class="spec-record-ref" data-req="SWS_CORE_03093" href="../spec/record.html?id=SWS_CORE_03093">[SWS_CORE_03093]</a> und <code>replace</code> <a class="spec-record-ref" data-req="SWS_CORE_03106" href="../spec/record.html?id=SWS_CORE_03106">[SWS_CORE_03106]</a>.</li>
<li><strong>Auslesen und Inspektion:</strong> Der Inhalt wird über <code>data</code> <a class="spec-record-ref" data-req="SWS_CORE_03070" href="../spec/record.html?id=SWS_CORE_03070">[SWS_CORE_03070]</a>, den Null-terminierten Zeiger <code>c_str</code> <a class="spec-record-ref" data-req="SWS_CORE_03069" href="../spec/record.html?id=SWS_CORE_03069">[SWS_CORE_03069]</a>, Elementzugriffe via <code>operator[]</code> <a class="spec-record-ref" data-req="SWS_CORE_03061" href="../spec/record.html?id=SWS_CORE_03061">[SWS_CORE_03061]</a> oder die Konvertierung nach <code>StringView</code> <a class="spec-record-ref" data-req="SWS_CORE_03301" href="../spec/record.html?id=SWS_CORE_03301">[SWS_CORE_03301]</a> ausgelesen.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Spezifikation definiert für unzulässige Aufrufe spezifische Violation-Typen anstelle von Standard-Exceptions:</p>
<ul>
<li><strong>IsoStdOutOfRangeViolation:</strong> Wird ausgelöst, wenn eine übergebene Index- oder Offset-Position die aktuelle Größe überschreitet. Dies betrifft den indizierten Elementzugriff über <code>at</code> (<a class="spec-record-ref" data-req="SWS_CORE_03063" href="../spec/record.html?id=SWS_CORE_03063">[SWS_CORE_03063]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03064" href="../spec/record.html?id=SWS_CORE_03064">[SWS_CORE_03064]</a>), die Teilstring-Erstellung mit <code>substr</code> <a class="spec-record-ref" data-req="SWS_CORE_03345" href="../spec/record.html?id=SWS_CORE_03345">[SWS_CORE_03345]</a>, Bereichslöschungen via <code>erase</code> <a class="spec-record-ref" data-req="SWS_CORE_03102" href="../spec/record.html?id=SWS_CORE_03102">[SWS_CORE_03102]</a>, das Pufferkopieren mittels <code>copy</code> <a class="spec-record-ref" data-req="SWS_CORE_03410" href="../spec/record.html?id=SWS_CORE_03410">[SWS_CORE_03410]</a> sowie positionierte Einfüge- und Ersetzungsoperationen (<a class="spec-record-ref" data-req="SWS_CORE_03094" href="../spec/record.html?id=SWS_CORE_03094">[SWS_CORE_03094]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03107" href="../spec/record.html?id=SWS_CORE_03107">[SWS_CORE_03107]</a>).</li>
<li><strong>IsoStdLengthErrorViolation:</strong> Wird hervorgerufen, sobald eine angeforderte String-Länge oder Puffererweiterung die maximale Kapazität <code>max_size()</code> <a class="spec-record-ref" data-req="SWS_CORE_03053" href="../spec/record.html?id=SWS_CORE_03053">[SWS_CORE_03053]</a> übersteigt. Relevante Schnittstellen sind <code>reserve</code> <a class="spec-record-ref" data-req="SWS_CORE_03054" href="../spec/record.html?id=SWS_CORE_03054">[SWS_CORE_03054]</a>, <code>resize</code> (<a class="spec-record-ref" data-req="SWS_CORE_03058" href="../spec/record.html?id=SWS_CORE_03058">[SWS_CORE_03058]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03059" href="../spec/record.html?id=SWS_CORE_03059">[SWS_CORE_03059]</a>), <code>append</code> <a class="spec-record-ref" data-req="SWS_CORE_03078" href="../spec/record.html?id=SWS_CORE_03078">[SWS_CORE_03078]</a>, <code>assign</code> <a class="spec-record-ref" data-req="SWS_CORE_03088" href="../spec/record.html?id=SWS_CORE_03088">[SWS_CORE_03088]</a>, <code>insert</code> <a class="spec-record-ref" data-req="SWS_CORE_03095" href="../spec/record.html?id=SWS_CORE_03095">[SWS_CORE_03095]</a> und <code>replace</code> <a class="spec-record-ref" data-req="SWS_CORE_03108" href="../spec/record.html?id=SWS_CORE_03108">[SWS_CORE_03108]</a>.</li>
</ul>
<p>Bezüglich der Exception-Sicherheit sind die meisten allozierenden und modifizierenden Methoden als nicht ausnahmesicher („not exception safe“) ausgewiesen, da Speicherknappheit oder fehlerhafte Parameter das Fehlschlagen der Operation nach sich ziehen können. Ausnahmegarantien bieten primär <code>noexcept</code> deklarierte Operationen wie die Verschiebekonstruktion <a class="spec-record-ref" data-req="SWS_CORE_03022" href="../spec/record.html?id=SWS_CORE_03022">[SWS_CORE_03022]</a> sowie bedingt die Verschiebezuweisung <a class="spec-record-ref" data-req="SWS_CORE_03023" href="../spec/record.html?id=SWS_CORE_03023">[SWS_CORE_03023]</a> und <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_03412" href="../spec/record.html?id=SWS_CORE_03412">[SWS_CORE_03412]</a>. Die Ersetzung von Standard-Exceptions durch <code>IsoStdOutOfRangeViolation</code> und <code>IsoStdLengthErrorViolation</code> dürfte dem plattformweiten Ansatz geschuldet sein, Fehler in sicherheitsrelevanten Ausführungsumgebungen deterministisch abzubilden.</p>
