  <h4>Context</h4>
  <p>The template class <code>ara::core::BasicString</code> provides a dynamically modifiable string in the AUTOSAR module <code>core</code>. The specification defines the type as an implementation of the concept <code>std::pmr::basic_string</code> from the ISO C++ standard <code>[basic.string]</code>. The fundamental design feature is the decoupling of data management and memory allocation strategy via the template parameter <code>Allocator</code>, which is exposed via the type alias <code>allocator_type</code> <a class="spec-record-ref" data-req="SWS_CORE_03005" href="../spec/record.html?id=SWS_CORE_03005">[SWS_CORE_03005]</a>. The default value of the template parameter in an AUTOSAR Adaptive runtime environment likely refers to a polymorphic allocator.</p>
  <p>Essential interaction partners of <code>BasicString</code>, in addition to the assigned allocator, are primarily the non-owning string view <code>ara::core::StringView</code> and the calling application component. Via conversion operators such as <code>operator StringView()</code> <a class="spec-record-ref" data-req="SWS_CORE_03301" href="../spec/record.html?id=SWS_CORE_03301">[SWS_CORE_03301]</a> and corresponding constructors <a class="spec-record-ref" data-req="SWS_CORE_03302" href="../spec/record.html?id=SWS_CORE_03302">[SWS_CORE_03302]</a>, seamless data exchange without unnecessary dynamic memory allocations is enabled.</p>

  <h4>Lifecycle</h4>
  <p>The lifecycle of an instance of <code>BasicString</code> comprises creation, buffer management, state modification, and deallocation:</p>
  <ul>
    <li><strong>Creation and allocator binding:</strong> Instantiation is carried out via the default constructor <a class="spec-record-ref" data-req="SWS_CORE_03024" href="../spec/record.html?id=SWS_CORE_03024">[SWS_CORE_03024]</a> or explicitly by passing an allocator instance <a class="spec-record-ref" data-req="SWS_CORE_03025" href="../spec/record.html?id=SWS_CORE_03025">[SWS_CORE_03025]</a>. Additional overloads allow initialization from C strings <a class="spec-record-ref" data-req="SWS_CORE_03028" href="../spec/record.html?id=SWS_CORE_03028">[SWS_CORE_03028]</a>, <code>StringView</code> <a class="spec-record-ref" data-req="SWS_CORE_03302" href="../spec/record.html?id=SWS_CORE_03302">[SWS_CORE_03302]</a>, or iterator ranges <a class="spec-record-ref" data-req="SWS_CORE_03031" href="../spec/record.html?id=SWS_CORE_03031">[SWS_CORE_03031]</a>. The assigned allocator can be queried via <code>get_allocator()</code> <a class="spec-record-ref" data-req="SWS_CORE_03415" href="../spec/record.html?id=SWS_CORE_03415">[SWS_CORE_03415]</a>.</li>
    <li><strong>Ownership and move semantics:</strong> In addition to the copy constructor <a class="spec-record-ref" data-req="SWS_CORE_03020" href="../spec/record.html?id=SWS_CORE_03020">[SWS_CORE_03020]</a>, the class has a default move constructor <a class="spec-record-ref" data-req="SWS_CORE_03022" href="../spec/record.html?id=SWS_CORE_03022">[SWS_CORE_03022]</a> as well as a variant with allocator binding <a class="spec-record-ref" data-req="SWS_CORE_03034" href="../spec/record.html?id=SWS_CORE_03034">[SWS_CORE_03034]</a>. For the move assignment operator <a class="spec-record-ref" data-req="SWS_CORE_03023" href="../spec/record.html?id=SWS_CORE_03023">[SWS_CORE_03023]</a> and for <code>swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_03412" href="../spec/record.html?id=SWS_CORE_03412">[SWS_CORE_03412]</a>, the exception and noexcept guarantee depends on whether allocators are equal or are propagated during move/swap operations (<code>propagate_on_container_move_assignment</code> and <code>is_always_equal</code>, respectively).</li>
    <li><strong>Destruction:</strong> At the end of the lifetime, the destructor <code>~BasicString()</code> <a class="spec-record-ref" data-req="SWS_CORE_03038" href="../spec/record.html?id=SWS_CORE_03038">[SWS_CORE_03038]</a> releases the allocated memory via the bound allocator.</li>
    <li><strong>Concurrency:</strong> Individual instances presumably offer no built-in protection against concurrent write accesses; concurrent modifications require synchronization on the application side.</li>
  </ul>

  <h4>Usage Path</h4>
  <p>A typical usage path comprises instantiation with defined allocator binding, preparatory capacity reservation, incremental modifications, and handover-ready provision:</p>
  <ol>
    <li><strong>Initialization:</strong> Creation of the string object with or without allocator argument <a class="spec-record-ref" data-req="SWS_CORE_03025" href="../spec/record.html?id=SWS_CORE_03025">[SWS_CORE_03025]</a>.</li>
    <li><strong>Capacity planning:</strong> Advance reservation of memory space via <code>reserve()</code> <a class="spec-record-ref" data-req="SWS_CORE_03054" href="../spec/record.html?id=SWS_CORE_03054">[SWS_CORE_03054]</a> to avoid reallocations during frequent write operations.</li>
    <li><strong>Composition:</strong> Appending content via <code>append()</code> (<a class="spec-record-ref" data-req="SWS_CORE_03076" href="../spec/record.html?id=SWS_CORE_03076">[SWS_CORE_03076]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03308" href="../spec/record.html?id=SWS_CORE_03308">[SWS_CORE_03308]</a>), <code>operator+=</code> (<a class="spec-record-ref" data-req="SWS_CORE_03072" href="../spec/record.html?id=SWS_CORE_03072">[SWS_CORE_03072]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03307" href="../spec/record.html?id=SWS_CORE_03307">[SWS_CORE_03307]</a>), <code>push_back()</code> <a class="spec-record-ref" data-req="SWS_CORE_03083" href="../spec/record.html?id=SWS_CORE_03083">[SWS_CORE_03083]</a>, or <code>insert()</code> <a class="spec-record-ref" data-req="SWS_CORE_03310" href="../spec/record.html?id=SWS_CORE_03310">[SWS_CORE_03310]</a>.</li>
    <li><strong>Inspection and forwarding:</strong> Querying the dimensions via <code>size()</code> <a class="spec-record-ref" data-req="SWS_CORE_03052" href="../spec/record.html?id=SWS_CORE_03052">[SWS_CORE_03052]</a> or <code>empty()</code> <a class="spec-record-ref" data-req="SWS_CORE_03051" href="../spec/record.html?id=SWS_CORE_03051">[SWS_CORE_03051]</a>, accessing the raw data buffer via <code>c_str()</code> <a class="spec-record-ref" data-req="SWS_CORE_03069" href="../spec/record.html?id=SWS_CORE_03069">[SWS_CORE_03069]</a> / <code>data()</code> <a class="spec-record-ref" data-req="SWS_CORE_03070" href="../spec/record.html?id=SWS_CORE_03070">[SWS_CORE_03070]</a>, or converting into a non-owning view via <code>operator StringView()</code> <a class="spec-record-ref" data-req="SWS_CORE_03301" href="../spec/record.html?id=SWS_CORE_03301">[SWS_CORE_03301]</a>.</li>
    <li><strong>Cleanup:</strong> Clearing the content via <code>clear()</code> <a class="spec-record-ref" data-req="SWS_CORE_03057" href="../spec/record.html?id=SWS_CORE_03057">[SWS_CORE_03057]</a> or releasing unused capacity via <code>shrink_to_fit()</code> <a class="spec-record-ref" data-req="SWS_CORE_03056" href="../spec/record.html?id=SWS_CORE_03056">[SWS_CORE_03056]</a>.</li>
  </ol>

  <h4>Error Scenarios</h4>
  <p>A key deviation of <code>ara::core::BasicString</code> from the ISO C++ standard concerns the behavior in error conditions: Instead of standard C++ exceptions, AUTOSAR defines dedicated violations:</p>
  <ul>
    <li><strong>Out of range violations (IsoStdOutOfRangeViolation):</strong> Occurs instead of <code>std::out_of_range</code>. Is triggered when indices are outside the valid range, for example during indexed access via <code>at(pos)</code> with <code>pos &gt;= size()</code> (<a class="spec-record-ref" data-req="SWS_CORE_03063" href="../spec/record.html?id=SWS_CORE_03063">[SWS_CORE_03063]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03064" href="../spec/record.html?id=SWS_CORE_03064">[SWS_CORE_03064]</a>), when creating substrings with <code>substr(pos)</code> for <code>pos &gt;     <li><strong>Length restrictions (IsoStdLengthErrorViolation):</strong> Occurs instead of <code>std::length_error</code>.     <li><strong>Unchecked direct access:</strong> In accordance with the ISO C++ specification, the subscript operator <code>operator[]</code> (<a class="spec-record-ref" data-req="SWS_CORE_03061" href="../spec/record.html?id=SWS_CORE_03061">[SWS_CORE_03061]</a>, <a class="spec-record-ref" data-req="SWS_CORE_03062" href="../spec/record.html?id=SWS_CORE_03062">[SWS_CORE_03062]</a>) does not perform any bounds checking.
