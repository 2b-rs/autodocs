<h4>Context</h4>
<p>In the <code>shwa</code> (Shared Hardware Accelerator) module, the <code>ara::shwa::Queue</code> class forms the central interface for execution scheduling on hardware accelerators. A queue encapsulates the connection to a specific execution device (<code>Device</code>) or a hardware unit addressed via a <code>DeviceSelector</code> and coordinates the submission and synchronization of work orders.</p>
<p>In the overall system, <code>ara::shwa::Queue</code> interacts with the following participants:</p>
<ul>
<li><strong>Application:</strong> Creates the queue via factory methods and controls the dispatching of tasks as well as the synchronization.</li>
<li><strong><code>Device</code> / <code>DeviceSelector</code>:</strong> Represents the target device to which the queue is bound and whose properties it reflects <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00910" href="../spec/record.html?id=AP_SWS_SHWA_00910">[AP_SWS_SHWA_00910]</a>.</li>
<li><strong><code>ErrorHandler</code>:</strong> Receives feedback on asynchronously occurred errors during task processing <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00912" href="../spec/record.html?id=AP_SWS_SHWA_00912">[AP_SWS_SHWA_00912]</a>.</li>
<li><strong><code>Event</code>:</strong> Is created when scheduling a task (<code>Submit</code>) and serves as a control and synchronization object for subsequent operations <a class="spec-record-ref" data-req="AP_SWS_SHWA_00912" href="../spec/record.html?id=AP_SWS_SHWA_00912">[AP_SWS_SHWA_00912]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00913" href="../spec/record.html?id=AP_SWS_SHWA_00913">[AP_SWS_SHWA_00913]</a>.</li>
<li><strong><code>PropertyList</code>:</strong> Passes optional configuration parameters during the creation of the queue <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The <code>ara::shwa::Queue</code> class has strictly controlled instantiation and ownership semantics:</p>
<ul>
<li><strong>Creation:</strong> The default constructor is explicitly deleted <a class="spec-record-ref" data-req="AP_SWS_SHWA_00902" href="../spec/record.html?id=AP_SWS_SHWA_00902">[AP_SWS_SHWA_00902]</a>. New instances can only be created via the static factory methods <code>Create</code>, which return a <code>ara::core::Result&lt;std::unique_ptr&lt;Queue&gt;&gt;</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>. Creation binds the queue to a <code>Device</code> or a <code>DeviceSelector</code>, links an <code>ErrorHandler</code>, and evaluates optional <code>PropertyList</code> properties.</li>
<li><strong>Ownership and identity:</strong> <code>ara::shwa::Queue</code> is neither copyable nor movable. Both the copy constructor <a class="spec-record-ref" data-req="AP_SWS_SHWA_00903" href="../spec/record.html?id=AP_SWS_SHWA_00903">[AP_SWS_SHWA_00903]</a> and the copy assignment operator <a class="spec-record-ref" data-req="AP_SWS_SHWA_00904" href="../spec/record.html?id=AP_SWS_SHWA_00904">[AP_SWS_SHWA_00904]</a>, the move constructor <a class="spec-record-ref" data-req="AP_SWS_SHWA_00905" href="../spec/record.html?id=AP_SWS_SHWA_00905">[AP_SWS_SHWA_00905]</a>, and the move assignment operator <a class="spec-record-ref" data-req="AP_SWS_SHWA_00906" href="../spec/record.html?id=AP_SWS_SHWA_00906">[AP_SWS_SHWA_00906]</a> are deleted. Therefore, the lifecycle of the instance is managed exclusively via the returned <code>std::unique_ptr</code>.</li>
<li><strong>Destruction:</strong> If the queue is released or destroyed, the object is considered invalid. Calls to methods on destroyed or invalid queues are rejected with the error <code>ShwaErrorCode::kInvalidObject</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00913" href="../spec/record.html?id=AP_SWS_SHWA_00913">[AP_SWS_SHWA_00913]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00914" href="../spec/record.html?id=AP_SWS_SHWA_00914">[AP_SWS_SHWA_00914]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00917" href="../spec/record.html?id=AP_SWS_SHWA_00917">[AP_SWS_SHWA_00917]</a>.</li>
<li><strong>Concurrency:</strong> The creation methods <code>Create</code> are thread-safe (<em>thread-safe</em>) <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>. In contrast, all regular member functions of the created instance (<code>GetDevice</code>, <code>GetProperty</code>, <code>HasProperty</code>, <code>IsInOrder</code>, <code>Submit</code>, <code>Wait</code>, <code>WaitFor</code>) are not thread-safe (<em>not thread-safe</em>). Concurrent access to the same queue instance from multiple threads therefore requires external synchronization by the application.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical workflow when using <code>ara::shwa::Queue</code> includes instantiation, property checking, task submission, and synchronization:</p>
<ol>
<li><strong>Creating the queue:</strong> The application calls <code>Queue::Create</code> with the desired <code>Device</code> (or <code>DeviceSelector</code>), an <code>ErrorHandler</code>, and optionally a <code>PropertyList</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00908" href="../spec/record.html?id=AP_SWS_SHWA_00908">[AP_SWS_SHWA_00908]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00909" href="../spec/record.html?id=AP_SWS_SHWA_00909">[AP_SWS_SHWA_00909]</a>.</li>
<li><strong>Querying properties:</strong> Before task submission, it can be checked whether tasks are processed strictly sequentially (<code>IsInOrder</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00911" href="../spec/record.html?id=AP_SWS_SHWA_00911">[AP_SWS_SHWA_00911]</a>), which <code>Device</code> is assigned (<code>GetDevice</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00910" href="../spec/record.html?id=AP_SWS_SHWA_00910">[AP_SWS_SHWA_00910]</a>), or whether specific feature properties are present (<code>HasProperty</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00915" href="../spec/record.html?id=AP_SWS_SHWA_00915">[AP_SWS_SHWA_00915]</a>, <code>GetProperty</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00916" href="../spec/record.html?id=AP_SWS_SHWA_00916">[AP_SWS_SHWA_00916]</a>).</li>
<li><strong>Enqueuing tasks (<code>Submit</code>):</strong> A work task is submitted to the queue via <code>Submit</code>. The configuration <code>cfg</code> (interpretation: task-specific kernel or command configuration) is passed either with a task-specific <code>ErrorHandler</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00912" href="../spec/record.html?id=AP_SWS_SHWA_00912">[AP_SWS_SHWA_00912]</a> or coupled to a secondary queue (<code>secondaryQueue</code>) <a class="spec-record-ref" data-req="AP_SWS_SHWA_00913" href="../spec/record.html?id=AP_SWS_SHWA_00913">[AP_SWS_SHWA_00913]</a>. Both variants return an <code>ara::core::Result&lt;Event&gt;</code>.</li>
<li><strong>Synchronizing task completion:</strong> The application waits for the completion of the enqueued tasks either indefinitely by means of <code>Wait()</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00914" href="../spec/record.html?id=AP_SWS_SHWA_00914">[AP_SWS_SHWA_00914]</a> or time-limited with a millisecond timeout via <code>WaitFor(ms)</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00917" href="../spec/record.html?id=AP_SWS_SHWA_00917">[AP_SWS_SHWA_00917]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of <code>ara::shwa::Queue</code> use <code>ara::core::Result</code> with error codes from the <code>ShwaErrorCode</code> domain for error indication:</p>
