<p class="ai-level ai-oneliner-lead" data-ai-level="1">Steuert die Analog-Digital-Wandler des Mikrocontrollers über Kanalgruppen und liefert deren Rohwerte.</p>
<div class="ai-level" data-ai-level="2">
<p>Der ADC-Treiber kapselt im MCAL die Analog-Digital-Wandler des Mikrocontrollers und wandelt Kanäle stets als konfigurierte Gruppen: software- oder hardwaregetriggert, einmalig oder fortlaufend <a class="spec-record-ref" data-req="SWS_Adc_00515" href="../../spec/record.html?id=SWS_Adc_00515">[SWS_Adc_00515]</a>. Nach <code>Adc_Init</code> starten Nutzer wie die IoHwAb Wandlungen. Den Abschluss erkennen sie per Statusabfrage oder Benachrichtigung, dann lesen sie die Rohwerte mit <code>Adc_ReadGroup</code> oder <code>Adc_GetStreamLastPointer</code>. Optional unterstützt der Treiber zweistufige Leistungszustandswechsel. Wichtigste Randbedingung: Ohne zuvor mit <code>Adc_SetupResultBuffer</code> eingerichteten Ergebnispuffer darf keine Gruppenwandlung starten <a class="spec-record-ref" data-req="SWS_Adc_91000" href="../../spec/record.html?id=SWS_Adc_91000">[SWS_Adc_91000]</a>.</p>

<div class="ai-level" data-ai-level="3">
<p>Der ADC-Treiber kapselt im MCAL die Analog-Digital-Wandler des Mikrocontrollers. Der EcuM initialisiert ihn mit <code>Adc_Init</code> <a class="spec-record-ref" data-req="SWS_Adc_00365" href="../../spec/record.html?id=SWS_Adc_00365">[SWS_Adc_00365]</a>. Typischer Nutzer ist die IoHwAb; sie erhält nach Abschluss einer Gruppenwandlung die Benachrichtigung <code>IoHwAb_AdcNotification&lt;#groupID&gt;</code> <a class="spec-record-ref" data-req="SWS_Adc_00082" href="../../spec/record.html?id=SWS_Adc_00082">[SWS_Adc_00082]</a>. Vor der ersten Wandlung muss nach jedem Reset mit <code>Adc_SetupResultBuffer</code> ein ausreichend großer Ergebnispuffer eingerichtet werden <a class="spec-record-ref" data-req="SWS_Adc_91000" href="../../spec/record.html?id=SWS_Adc_91000">[SWS_Adc_91000]</a>.</p>

</ul>

<h4>Rolle des ADC-Treibers zwischen IoHwAb und Wandlerhardware</h4>
<p>Der ADC-Treiber ist das MCAL-Modul für die Analog-Digital-Wandler des Mikrocontrollers. <code>Adc_Init</code> initialisiert ADC-Hardware-Units und Treiber <a class="spec-record-ref" data-req="SWS_Adc_00365" href="../../spec/record.html?id=SWS_Adc_00365">[SWS_Adc_00365]</a>. Alle weiteren Dienste arbeiten auf Kanalgruppen, die über eine numerische ID (<code>Adc_GroupType</code>) angesprochen werden <a class="spec-record-ref" data-req="SWS_Adc_00507" href="../../spec/record.html?id=SWS_Adc_00507">[SWS_Adc_00507]</a>. Typischer Nutzer ist die I/O Hardware Abstraction: Sie startet im Auftrag einer Sensor-SWC Wandlungen und wird nach Abschluss über <code>IoHwAb_AdcNotification&lt;#groupID&gt;</code> benachrichtigt <a class="spec-record-ref" data-req="SWS_Adc_00082" href="../../spec/record.html?id=SWS_Adc_00082">[SWS_Adc_00082]</a>, <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-a418e2fa072ee8a7.html" data-snip="FIG-a418e2fa072ee8a7">SWS IoHwAb S. 55</a>. Den Treiber initialisiert der EcuM, für den <code>Adc_Init</code> eine optionale Schnittstelle ist <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_OS_SECTION_8_7_1_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_OS_SECTION_8_7_1_Optional_Interfaces">SWS EcuM S. 142</a>.</p>
<p>Der Treiber liegt auf der untersten Architekturebene. Er bietet deshalb keine Callbacks für tiefere Module an <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_8_4_Callback_notifications.html" data-snip="SNIP_CLASSIC_ADC_SECTION_8_4_Callback_notifications">SWS ADC S. 79</a>. Die ADC-API greift nicht direkt auf die Hardware-Ergebnisregister zu. Ergebnisse gelangen immer über Puffer der Anwendung zum Nutzer <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_7_1_3_3_Example_Adc_GetStreamLastPointer_Usage.html" data-snip="SNIP_CLASSIC_ADC_SECTION_7_1_3_3_Example_Adc_GetStreamLastPointer_Usage">SWS ADC S. 27</a>. Fehler meldet der Treiber über <code>Det_ReportError</code> <a class="spec-record-ref" data-req="SWS_Adc_00377" href="../../spec/record.html?id=SWS_Adc_00377">[SWS_Adc_00377]</a>. Die zitierten Dokumentstellen stammen überwiegend aus R23-11 bis R25-11. Normativ für R20-11 sind die Requirements.</p>

<h4>Kanalgruppen: Trigger, Wandlungs- und Zugriffsmodus</h4>
<p>Eine Gruppe bündelt Kanäle <a class="spec-record-ref" data-req="SWS_Adc_00517" href="../../spec/record.html?id=SWS_Adc_00517">[SWS_Adc_00517]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00506" href="../../spec/record.html?id=SWS_Adc_00506">[SWS_Adc_00506]</a>. Sie wird auf drei Achsen konfiguriert:</p>
<ul>
<li><strong>Triggerquelle:</strong> <code>ADC_TRIGG_SRC_SW</code> oder <code>ADC_TRIGG_SRC_HW</code> <a class="spec-record-ref" data-req="SWS_Adc_00514" href="../../spec/record.html?id=SWS_Adc_00514">[SWS_Adc_00514]</a>.</li>
<li><strong>Wandlungsmodus:</strong> <code>ADC_CONV_MODE_ONESHOT</code> wandelt jeden Kanal genau einmal je Trigger. <code>ADC_CONV_MODE_CONTINUOUS</code> wandelt fortlaufend und ist nur mit Software-Trigger möglich <a class="spec-record-ref" data-req="SWS_Adc_00515" href="../../spec/record.html?id=SWS_Adc_00515">[SWS_Adc_00515]</a>.</li>
<li><strong>Zugriffsmodus:</strong> <code>ADC_ACCESS_MODE_SINGLE</code> oder <code>ADC_ACCESS_MODE_STREAMING</code> <a class="spec-record-ref" data-req="SWS_Adc_00528" href="../../spec/record.html?id=SWS_Adc_00528">[SWS_Adc_00528]</a>. Beim Streaming legt <code>Adc_StreamNumSampleType</code> die Zahl der Runden fest <a class="spec-record-ref" data-req="SWS_Adc_00518" href="../../spec/record.html?id=SWS_Adc_00518">[SWS_Adc_00518]</a>. Ein linearer Puffer stoppt die Wandlung, sobald er voll ist; ein zirkulärer läuft um <a class="spec-record-ref" data-req="SWS_Adc_00519" href="../../spec/record.html?id=SWS_Adc_00519">[SWS_Adc_00519]</a>.</li>
</ul>
<p>Prescaler, Wandlungszeit, Abtastzeit und Auflösung sind keine API-Typen <a class="spec-record-ref" data-req="SWS_Adc_00509" href="../../spec/record.html?id=SWS_Adc_00509">[SWS_Adc_00509]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00510" href="../../spec/record.html?id=SWS_Adc_00510">[SWS_Adc_00510]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00511" href="../../spec/record.html?id=SWS_Adc_00511">[SWS_Adc_00511]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00512" href="../../spec/record.html?id=SWS_Adc_00512">[SWS_Adc_00512]</a>. Für Hardware-Trigger lassen sich Flanke und Timer-Reload einstellen, sofern die Hardware das unterstützt <a class="spec-record-ref" data-req="SWS_Adc_00520" href="../../spec/record.html?id=SWS_Adc_00520">[SWS_Adc_00520]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00521" href="../../spec/record.html?id=SWS_Adc_00521">[SWS_Adc_00521]</a>. Ergebnisse sind unskalierte Rohwerte, links- oder rechtsbündig ausgerichtet <a class="spec-record-ref" data-req="SWS_Adc_00508" href="../../spec/record.html?id=SWS_Adc_00508">[SWS_Adc_00508]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00525" href="../../spec/record.html?id=SWS_Adc_00525">[SWS_Adc_00525]</a>.</p>
<p>Den Fortschritt einer Gruppe beschreibt <code>Adc_StatusType</code> <a class="spec-record-ref" data-req="SWS_Adc_00513" href="../../spec/record.html?id=SWS_Adc_00513">[SWS_Adc_00513]</a>:</p>
<ul>
<li><code>ADC_IDLE</code>: nicht gestartet.</li>
<li><code>ADC_BUSY</code>: Wandlung läuft.</li>
<li><code>ADC_COMPLETED</code>: eine Runde ist fertig, aber nicht die letzte.</li>
<li><code>ADC_STREAM_COMPLETED</code>: Ergebnispuffer vollständig.</li>

<h4>Konkurrierende Gruppen: Priorität, Queuing und Verdrängung</h4>
<p>Gleichzeitige Anforderungen regelt <code>Adc_PriorityImplementationType</code>: kein Mechanismus, nur Hardware oder Hardware und Software <a class="spec-record-ref" data-req="SWS_Adc_00522" href="../../spec/record.html?id=SWS_Adc_00522">[SWS_Adc_00522]</a>. Prioritäten reichen von 0 (niedrigste) bis 255 <a class="spec-record-ref" data-req="SWS_Adc_00516" href="../../spec/record.html?id=SWS_Adc_00516">[SWS_Adc_00516]</a>. Wird eine Gruppe von einer höher priorisierten unterbrochen, startet ihre Runde neu (<code>ADC_GROUP_REPL_ABORT_RESTART</code>) oder wird fortgesetzt (<code>ADC_GROUP_REPL_SUSPEND_RESUME</code>). Ergebnisse früherer Runden bleiben in beiden Fällen erhalten <a class="spec-record-ref" data-req="SWS_Adc_00523" href="../../spec/record.html?id=SWS_Adc_00523">[SWS_Adc_00523]</a>.</p>
<p>Ohne Priorität und ohne Queuing weist der Treiber eine zweite Anforderung mit <code>ADC_E_BUSY</code> ab <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_9_7_No_Priority_Mechanism_No_Queuing.html" data-snip="SNIP_CLASSIC_DET_SECTION_9_7_No_Priority_Mechanism_No_Queuing">SWS ADC S. 95</a>. Mit Software-Queuing speichert er sie und startet sie später <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_9_8_No_Priority_Mechanism_SW_Queuing.html" data-snip="SNIP_CLASSIC_ADC_SECTION_9_8_No_Priority_Mechanism_SW_Queuing">SWS ADC S. 96</a>. Mit Priorisierung verdrängt die höher priorisierte Gruppe die laufende <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_9_9_HW_SW_Priority_Mechanism_SW_Queuing.html" data-snip="SNIP_CLASSIC_ADC_SECTION_9_9_HW_SW_Priority_Mechanism_SW_Queuing">SWS ADC S. 97</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_9_10_HW_Priority_Mechanism_HW_Queuing.html" data-snip="SNIP_CLASSIC_ADC_SECTION_9_10_HW_Priority_Mechanism_HW_Queuing">SWS ADC S. 98</a>. <code>Adc_StopGroupConversion</code> entfernt auch eine wartende Start-Anforderung <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_8_3_5_Adc_StopGroupConversion.html" data-snip="SNIP_CLASSIC_ADC_SECTION_8_3_5_Adc_StopGroupConversion">SWS ADC S. 58</a>.</p>

<h4>Leistungszustände der ADC-Hardware</h4>
<p>Die Leistungssteuerung ist optional und auf die ADC-Peripherie beschränkt. Architekturbedingte Randbedingungen erfüllen die oberen Schichten; der Treiber prüft nur die Aufrufreihenfolge <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_7_4_1_Background.html" data-snip="SNIP_CLASSIC_ADC_SECTION_7_4_1_Background">SWS ADC S. 39</a>. <code>Adc_PowerStateType</code> kennt <code>ADC_FULL_POWER</code> (0) und die Zustände 1..255 mit abnehmendem Verbrauch <a class="spec-record-ref" data-req="SWS_Adc_00526" href="../../spec/record.html?id=SWS_Adc_00526">[SWS_Adc_00526]</a>. Das Ergebnis jeder Anfrage meldet <code>Adc_PowerStateRequestResultType</code> <a class="spec-record-ref" data-req="SWS_Adc_00527" href="../../spec/record.html?id=SWS_Adc_00527">[SWS_Adc_00527]</a>.</p>
<p>Der Wechsel erfolgt in zwei Stufen:</p>
<ol>
<li><strong>Vorbereiten:</strong> <code>Adc_PreparePowerState</code> startet die Vorbereitung <a class="spec-record-ref" data-req="SWS_Adc_00478" href="../../spec/record.html?id=SWS_Adc_00478">[SWS_Adc_00478]</a>. Asynchrone Anteile laufen im zyklischen <code>Adc_Main_PowerTransitionManager</code> <a class="spec-record-ref" data-req="SWS_Adc_00498" href="../../spec/record.html?id=SWS_Adc_00498">[SWS_Adc_00498]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00479" href="../../spec/record.html?id=SWS_Adc_00479">[SWS_Adc_00479]</a>. Dessen Periode legt <code>AdcMainSchedulePeriod</code> fest <a class="spec-record-ref" data-req="SWS_Adc_00500" href="../../spec/record.html?id=SWS_Adc_00500">[SWS_Adc_00500]</a>. Im asynchronen Modus meldet er die Bereitschaft über <code>IoHwAb_Adc_NotifyReadyForPowerState&lt;#Mode&gt;</code> <a class="spec-record-ref" data-req="SWS_Adc_00501" href="../../spec/record.html?id=SWS_Adc_00501">[SWS_Adc_00501]</a>, <a class="spec-record-ref" data-req="SWS_Adc_00480" href="../../spec/record.html?id=SWS_Adc_00480">[SWS_Adc_00480]</a>.</li>
<li><strong>Umschalten:</strong> <code>Adc_SetPowerState</code> aktiviert den vorbereiteten Zustand <a class="spec-record-ref" data-req="SWS_Adc_00475" href="../../spec/record.html?id=SWS_Adc_00475">[SWS_Adc_00475]</a>. Vorarbeiten wie ruhende Kanäle obliegen den Nutzern. Implizite Zwischenzustände gibt es nicht <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ADC_SECTION_8_3_14_Adc_SetPowerState.html" data-snip="SNIP_CLASSIC_ADC_SECTION_8_3_14_Adc_SetPowerState">SWS ADC S. 81</a>.</li>
</ol>
