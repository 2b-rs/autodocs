  <h4>Context</h4>
  <p>
    The class <code>ara::nm::NetworkHandle</code> represents the central access object for managing and monitoring a network handle <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>. It is primarily designed for use by functional components such as State Management <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>. Binding to a concrete logical or physical communication resource takes place via an <code>ara::core::InstanceSpecifier</code> that references a corresponding <code>NetworkManagementPortInterface</code> port prototype <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>.
  </p>
  <p>
    Within the system environment, the class interacts with at least three parties:
  </p>
  <ul>
    <li><strong>State Management:</strong> Requests network states, queries the current status, and registers notification callbacks <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>.</li>
    <li><strong><code>NetworkHandle</code>:</strong> Serves as a typed C++ interface and encapsulation of port communication <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>.</li>
    <li><strong>Network Management Service (NM):</strong> Manages the actual Partial Network Clusters (PNC), VLANs, or physical networks and reports their effective states back to the handle <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>.</li>
  </ul>

  <h4>Lifecycle</h4>
  <p>
    An <code>NetworkHandle</code> is explicitly instantiated based on an <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>. Construction is thread-safe. With regard to ownership, the class enforces strict move-only semantics: the copy constructor <a class="spec-record-ref" data-req="SWS_ANM_01005" href="../spec/record.html?id=SWS_ANM_01005">[SWS_ANM_01005]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_ANM_01006" href="../spec/record.html?id=SWS_ANM_01006">[SWS_ANM_01006]</a> are deleted (<code>= delete</code>). Instances can only be transferred via the move constructor <a class="spec-record-ref" data-req="SWS_ANM_01003" href="../spec/record.html?id=SWS_ANM_01003">[SWS_ANM_01003]</a> (whose thread safety is implementation-defined) or the non-thread-safe move assignment <a class="spec-record-ref" data-req="SWS_ANM_01004" href="../spec/record.html?id=SWS_ANM_01004">[SWS_ANM_01004]</a>.
  </p>
  <p>
    The destructor is defined as <code>noexcept</code> and not thread-safe <a class="spec-record-ref" data-req="SWS_ANM_01002" href="../spec/record.html?id=SWS_ANM_01002">[SWS_ANM_01002]</a>. When destroying the instance, it must be ensured that no concurrent accesses take place anymore.
  </p>
  <p>
    The network resources controlled via the handle pass through the states defined by <code>NetworkStateType</code> <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>:
  </p>
  <ul>
    <li><code>kNoCom</code> (0): Non-communication; occurs as soon as at least one of the assigned networks is not in state <code>FULL_COM</code> <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>.</li>
    <li><code>kFullCom</code> (1): Full communication; is active when all assigned networks are fully activated <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>.</li>
  </ul>
  <p>
    The interface methodically distinguishes between the target state requested by the caller (<a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>) and the actually established, effective network state (<a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>).
  </p>

  <h4>Usage Path</h4>
  <p>
    A typical workflow comprises instantiation, registration of state observers, requesting communication, and subsequent release:
  </p>
  <ol>
    <li><strong>Instantiation:</strong> State Management creates the object via the <code>InstanceSpecifier</code> of the port <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>.</li>
    <li><strong>Register notifier:</strong> For asynchronous notification, the application registers an <code>NetworkStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01020" href="../spec/record.html?id=SWS_ANM_01020">[SWS_ANM_01020]</a>. This is possible for the effective state via <code>RegisterNetworkStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a> or for the requested state via <code>RegisterNetworkRequestedStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01012" href="../spec/record.html?id=SWS_ANM_01012">[SWS_ANM_01012]</a>. Optionally, a dedicated <code>ExecutorT</code> for the execution context can be specified via corresponding template variants <a class="spec-record-ref" data-req="SWS_ANM_01014" href="../spec/record.html?id=SWS_ANM_01014">[SWS_ANM_01014]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01015" href="../spec/record.html?id=SWS_ANM_01015">[SWS_ANM_01015]</a>. A maximum of one notifier may be active per handle at any time.</li>
    <li><strong>Request network:</strong> Activation of the PNC, VLAN, or network is initiated via <code>SetNetworkRequestedState(NetworkStateType::kFullCom)</code> <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>.</li>
    <li><strong>Monitor state:</strong> In addition to receiving callbacks, the current state can be queried synchronously using <code>GetNetworkState()</code> <a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a> and the requested state via <code>GetNetworkRequestedState()</code> <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>. Both queries are thread-safe.</li>
    <li><strong>Release network and unregister:</strong> When the requirement ends, the caller sets the state to <code>kNoCom</code> <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a> and cancels registered notifiers via <code>UnregisterNetworkStateChangeNotifier()</code> <a class="spec-record-ref" data-req="SWS_ANM_01011" href="../spec/record.html?id=SWS_ANM_01011">[SWS_ANM_01011]</a> or <code>UnregisterNetworkRequestedStateChangeNotifier()</code> <a class="spec-record-ref" data-req="SWS_ANM_01013" href="../spec/record.html?id=SWS_ANM_01013">[SWS_ANM_01013]</a>.</li>
  </ol>

  <h4>Error Scenarios</h4>
  <p>
    All essential operations return results in error scenarios via <code>ara::core::Result</code>:
  </p>
  <ul>
    <li><code>NmErrc::kServiceNotAvailable</code>: Occurs with <code>GetNetworkState()</code> <a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <code>GetNetworkRequestedState()</code> <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a>, and <code>SetNetworkRequestedState()</code> <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a> if the NM service is not reachable or operational.</li>
    <li><code>NmErrc::kInvalidHandler</code>: Returned by the registration methods <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01012" href="../spec/record.html?id=SWS_ANM_01012">[SWS_ANM_01012]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01014" href="../spec/record.html?id=SWS_ANM_01014">[SWS_ANM_01014]</a>, and <a class="spec-record-ref" data-req="SWS_ANM_01015" href="../spec/record.html?id=SWS_ANM_01015">[SWS_ANM_01015]</a> if an invalid notification function was passed (interpretation: presumably also when attempting multiple registration without prior deregistration).</li>
  </ul>
  <p>
    <strong>Pre- and postconditions as well as concurrency:</strong> While read operations are thread-safe, writing methods (<code>SetNetworkRequestedState</code>) as well as notifier registrations and deregistrations are specified as <em>not thread-safe</em> <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01011" href="../spec/record.html?id=SWS_ANM_01011">[SWS_ANM_01011]</a>. They require external synchronization when an instance is shared. Before destroying the handle, notifiers should be unregistered to avoid accesses to invalid contexts.
