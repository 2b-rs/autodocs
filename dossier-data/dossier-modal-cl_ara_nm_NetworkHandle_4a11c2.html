<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht dem State Management das Anfordern und Überwachen von Kommunikationszuständen logischer und physischer Netze.</p>
<div class="ai-level" data-ai-level="2">
<p><code>ara::nm::NetworkHandle</code> stellt ein verschiebbares, nicht kopierbares Zugriffsobjekt dar, mit dem das State Management über einen Instanzbezeichner den Kommunikationszustand von Netzen anfordert und überwacht <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>. Neben synchronen Statusabfragen ermöglicht die Klasse das Setzen von Anforderungen sowie das Registrieren von Notifiern für effektive oder angeforderte Zustände <a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a>. Fehlende Dienstverfügbarkeit oder fehlerhafte Notifier werden dabei über standardisierte Fehlercodes im Ergebnisobjekt gemeldet.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::nm::NetworkHandle</code> fungiert im Modul <code>nm</code> als standardisiertes Zugriffsobjekt für ein konkretes logisches oder physisches Netzwerkhandle, das über einen <code>ara::core::InstanceSpecifier</code> eines Port-Prototyps adressiert wird <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>. Primärer Nutzer dieser Schnittstelle ist das funktionale State Management (SM), welches über das Handle den Kommunikationsbedarf für Partial Network Cluster (PNC), VLANs oder physische Netze anmeldet und überwacht <a class="spec-record-ref" data-req="SWS_ANM_01000" href="../spec/record.html?id=SWS_ANM_01000">[SWS_ANM_01000]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>. Als Vermittlungsschicht kapselt das Objekt die Interaktion zwischen der anfordernden Funktionsgruppe und dem zugrundeliegenden NM-Subsystem.</p>

<h4>Lebenszyklus</h4>
<p>Ein <code>ara::nm::NetworkHandle</code> wird explizit unter Angabe eines gültigen <code>ara::core::InstanceSpecifier</code> für ein <code>NetworkManagementPortInterface</code> instanziiert; dieser Konstruktor ist thread-safe spezifiziert <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>. Die Instanz besitzt exklusive Semantik: Kopierkonstruktor und Kopierzuweisungsoperator sind explizit gelöscht (<code>= delete</code>) <a class="spec-record-ref" data-req="SWS_ANM_01005" href="../spec/record.html?id=SWS_ANM_01005">[SWS_ANM_01005]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01006" href="../spec/record.html?id=SWS_ANM_01006">[SWS_ANM_01006]</a>. Die Klasse unterstützt Move-Semantik über Verschiebekonstruktor und Verschiebezuweisung, wobei die Zuweisung nicht threadsicher ist <a class="spec-record-ref" data-req="SWS_ANM_01003" href="../spec/record.html?id=SWS_ANM_01003">[SWS_ANM_01003]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01004" href="../spec/record.html?id=SWS_ANM_01004">[SWS_ANM_01004]</a>.</p>
<p>Die Zerstörung erfolgt über den nicht threadsicheren Destruktor <code>~NetworkHandle()</code> <a class="spec-record-ref" data-req="SWS_ANM_01002" href="../spec/record.html?id=SWS_ANM_01002">[SWS_ANM_01002]</a>. Vor der Zerstörung registrierte Notifier sollten vermutlich durch die Applikation deregistriert werden, um asynchrone Zugriffe auf ungültige Kontexte zu vermeiden (Interpretation). <a class="interp-q interp-q-open" data-q="Q-7c4ae0961601196a" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-7c4ae0961601196a" title="Frage Q-7c4ae0961601196a (offen): Vor Zerstörung der Handle-Instanz sollten registrierte Notifier deregistriert werden">Frage Q-7c4ae0961601196a (offen)</a> Bezüglich der Netzwerkzustände bildet das Handle zwei elementare Stufen über das Enum <code>NetworkStateType</code> ab: <code>kNoCom</code> (mindestens ein zugeordnetes Netz befindet sich nicht im Zustand voller Kommunikation) und <code>kFullCom</code> (alle zugeordneten Netze sind aktiv) <a class="spec-record-ref" data-req="SWS_ANM_01358" href="../spec/record.html?id=SWS_ANM_01358">[SWS_ANM_01358]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Instanziierung, die optionale Registrierung von Notifiern, die Anforderung des Netzwerkzustands sowie die spätere Freigabe:</p>
<ul>
<li><strong>Instanziierung:</strong> Erzeugen des Handles mittels Instanzbezeichner <a class="spec-record-ref" data-req="SWS_ANM_01001" href="../spec/record.html?id=SWS_ANM_01001">[SWS_ANM_01001]</a>.</li>
<li><strong>Beobachter registrieren:</strong> Registrieren von Rückruffunktionen vom Typ <code>NetworkStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01020" href="../spec/record.html?id=SWS_ANM_01020">[SWS_ANM_01020]</a> entweder für den tatsächlichen effektiven Zustand über <code>RegisterNetworkStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01010" href="../spec/record.html?id=SWS_ANM_01010">[SWS_ANM_01010]</a> oder für den angeforderten Zustand über <code>RegisterNetworkRequestedStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01012" href="../spec/record.html?id=SWS_ANM_01012">[SWS_ANM_01012]</a>. Beide Methoden existieren auch als Template-Variante zur Angabe eines benutzerdefinierten Ausführungskontexts (<code>ExecutorT</code>) <a class="spec-record-ref" data-req="SWS_ANM_01014" href="../spec/record.html?id=SWS_ANM_01014">[SWS_ANM_01014]</a>, <a class="spec-record-ref" data-req="SWS_ANM_01015" href="../spec/record.html?id=SWS_ANM_01015">[SWS_ANM_01015]</a>. Pro Handle kann maximal ein Notifier je Kategorie aktiv sein.</li>
<li><strong>Zustand anfordern:</strong> Anfordern von voller Kommunikation (<code>NetworkStateType::kFullCom</code>) oder Freigabe (<code>NetworkStateType::kNoCom</code>) via <code>SetNetworkRequestedState</code> <a class="spec-record-ref" data-req="SWS_ANM_01009" href="../spec/record.html?id=SWS_ANM_01009">[SWS_ANM_01009]</a>.</li>
<li><strong>Zustand abfragen:</strong> Synchrones Auslesen des aktuell angeforderten Zustands mit <code>GetNetworkRequestedState</code> <a class="spec-record-ref" data-req="SWS_ANM_01008" href="../spec/record.html?id=SWS_ANM_01008">[SWS_ANM_01008]</a> oder des tatsächlich wirksamen Netzwerkzustands mit <code>GetNetworkState</code> <a class="spec-record-ref" data-req="SWS_ANM_01007" href="../spec/record.html?id=SWS_ANM_01007">[SWS_ANM_01007]</a>. Beide Abfragen sind threadsicher.</li>
<li><strong>Bereinigung:</strong> Explizites Abmelden der Callback-Handler über <code>UnregisterNetworkStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01011" href="../spec/record.html?id=SWS_ANM_01011">[SWS_ANM_01011]</a> und <code>UnregisterNetworkRequestedStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_ANM_01013" href="../spec/record.html?id=SWS_ANM_01013">[SWS_ANM_01013]</a>.</li>
</ul>
