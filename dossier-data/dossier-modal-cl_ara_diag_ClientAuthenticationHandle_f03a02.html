<p class="ai-level ai-oneliner-lead" data-ai-level="1">Verwaltet dynamische Diagnoserechte, Sitzungstimer und die Rücknahme der Authentifizierung eines Diagnose-Clients.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::ClientAuthenticationHandle</code> dient der Anwendung zur Verwaltung einer aktiven Authentifizierungssitzung eines Diagnose-Clients <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>. Über dieses Handle konfiguriert die Anwendung dynamische Zugriffslisten und erneuert die Inaktivitätstimer des Clients <a class="spec-record-ref" data-req="SWS_DM_01213" href="../spec/record.html?id=SWS_DM_01213">[SWS_DM_01213]</a>. Das Objekt folgt strikter Move-Semantik ohne Kopiermöglichkeit und meldet Fehler bei nicht verfügbarer Diagnoseverwaltung über <code>DiagErrc::kServiceNotAvailable</code>. Durch den Aufruf von <code>Revoke</code> können erteilte Rollen und Zusatzrechte jederzeit kontrolliert zurückgenommen werden.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die API-Klasse <code>ara::diag::ClientAuthenticationHandle</code> ist in der Header-Datei <code>ara/diag/client_authentication_handle.h</code> definiert <a class="spec-record-ref" data-req="SWS_DM_01145" href="../spec/record.html?id=SWS_DM_01145">[SWS_DM_01145]</a>. Sie fungiert als zentrales Steuerungsobjekt, das einer Diagnose-Anwendung durch die Instanz des Diagnostic Servers bereitgestellt wird, sobald ein Client erfolgreich authentifiziert wurde oder dessen Standardrollen temporär überschrieben wurden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=132">AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 „ClientAuthenticationHandle“</a>.</p>
<p>Beim Systemstart befindet sich ein Client standardmäßig im Zustand <code>kDeAuthenticated</code> <a class="spec-record-ref" data-req="SWS_DM_01205" href="../spec/record.html?id=SWS_DM_01205">[SWS_DM_01205]</a> mit vorkonfigurierten Standardrollen <a class="spec-record-ref" data-req="SWS_DM_01204" href="../spec/record.html?id=SWS_DM_01204">[SWS_DM_01204]</a>. Ruft die Anwendung <code>ara::diag::ClientAuthentication::Authenticate</code> auf, versetzt der Diagnostic Server den Client in den Zustand <code>kAuthenticated</code> und liefert ein <code>ara::diag::ClientAuthenticationHandle</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>. Ebenso wird beim Aufruf von <code>ara::diag::ClientAuthentication::OverrideDefaultRoles</code> zur temporären Anpassung der Rollen ein solches Handle erzeugt <a class="spec-record-ref" data-req="SWS_DM_01209" href="../spec/record.html?id=SWS_DM_01209">[SWS_DM_01209]</a>. Über das Handle steuert die Anwendung den Authentifizierungsstatus und die dynamische Zugriffsliste (<code>DynamicAccessList</code>), welche einem authentifizierten Client zusätzliche Zugriffsrechte auf Diagnoseressourcen jenseits des Diagnose-Extrakts einräumt <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=132">AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 „ClientAuthenticationHandle“</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>ara::diag::ClientAuthenticationHandle</code> erfolgt regulär durch Fabrikmethoden des Diagnostic Servers im Zuge von <code>Authenticate</code> <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a> oder <code>OverrideDefaultRoles</code> <a class="spec-record-ref" data-req="SWS_DM_01209" href="../spec/record.html?id=SWS_DM_01209">[SWS_DM_01209]</a>. Ergänzend stellt die Klasse einen parameterlosen Default-Konstruktor bereit <a class="spec-record-ref" data-req="SWS_DM_01146" href="../spec/record.html?id=SWS_DM_01146">[SWS_DM_01146]</a>; ein derart erzeugtes Objekt dürfte vermutlich als ungebundener Platzhalter fungieren, bis ihm per Move-Zuweisung ein aktives Handle übertragen wird. <a class="interp-q interp-q-open" data-q="Q-74f44c072616cce9" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-74f44c072616cce9" title="Frage Q-74f44c072616cce9 (offen): Ein über den Default-Konstruktor erzeugtes Handle fungiert als ungebundener Platzhalter ohne zugeordnete Client-Sitzung.">Frage Q-74f44c072616cce9 (offen)</a></p>
<p>Hinsichtlich der Besitzverhältnisse implementiert die Klasse strikte Move-Semantik: Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_01148" href="../spec/record.html?id=SWS_DM_01148">[SWS_DM_01148]</a> und Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01149" href="../spec/record.html?id=SWS_DM_01149">[SWS_DM_01149]</a> sind als <code>noexcept = default</code> definiert. Das Kopieren ist vollständig unterbunden, da Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01150" href="../spec/record.html?id=SWS_DM_01150">[SWS_DM_01150]</a> und Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01151" href="../spec/record.html?id=SWS_DM_01151">[SWS_DM_01151]</a> gelöscht (<code>=delete</code>) sind. Die Freigabe der Instanz erfolgt über den Destruktor <code>~ClientAuthenticationHandle()</code> <a class="spec-record-ref" data-req="SWS_DM_01147" href="../spec/record.html?id=SWS_DM_01147">[SWS_DM_01147]</a>.</p>
<p>Bezüglich der Nebenläufigkeit ist der Default-Konstruktor als threadsicher (<code>thread-safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01146" href="../spec/record.html?id=SWS_DM_01146">[SWS_DM_01146]</a>. Dagegen sind der Destruktor <a class="spec-record-ref" data-req="SWS_DM_01147" href="../spec/record.html?id=SWS_DM_01147">[SWS_DM_01147]</a> sowie sämtliche zustandsverändernden Methodenaufrufe als nicht threadsicher (<code>not thread-safe</code>) ausgewiesen <a class="spec-record-ref" data-req="SWS_DM_01152" href="../spec/record.html?id=SWS_DM_01152">[SWS_DM_01152]</a>, <a class="spec-record-ref" data-req="SWS_DM_01153" href="../spec/record.html?id=SWS_DM_01153">[SWS_DM_01153]</a>, <a class="spec-record-ref" data-req="SWS_DM_01154" href="../spec/record.html?id=SWS_DM_01154">[SWS_DM_01154]</a>, <a class="spec-record-ref" data-req="SWS_DM_01155" href="../spec/record.html?id=SWS_DM_01155">[SWS_DM_01155]</a>. Ein nebenläufiger Zugriff auf dasselbe Handle erfordert daher anwendungsseitige Synchronisation.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Ablauf zur Laufzeit umfasst die Konfiguration dynamischer Rechte, das Aufrechterhalten der Autorisierung und die kontrollierte Beendigung:</p>
<ol>
<li><strong>Handle erhalten:</strong> Die Anwendung initiiert die Authentifizierung an <code>ara::diag::ClientAuthentication</code> und empfängt die Handle-Instanz <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>.</li>
<li><strong>Zugriffsliste setzen oder erweitern:</strong> Über die Methode <code>Set</code> ersetzt die Anwendung die dynamische Zugriffsliste einer Diagnose-Konversation vollständig <a class="spec-record-ref" data-req="SWS_DM_01153" href="../spec/record.html?id=SWS_DM_01153">[SWS_DM_01153]</a>, <a class="spec-record-ref" data-req="SWS_DM_01213" href="../spec/record.html?id=SWS_DM_01213">[SWS_DM_01213]</a>. Alternativ fügt <code>Append</code> zusätzliche Diagnosemuster an eine bestehende Zugriffsliste an <a class="spec-record-ref" data-req="SWS_DM_01152" href="../spec/record.html?id=SWS_DM_01152">[SWS_DM_01152]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=133">AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 „DynamicAccessList Creation and Update“</a>.</li>
<li><strong>Aktivität erneuern:</strong> Bei Inaktivität in der Standard-Sitzung droht nach Verstreichen des Inaktivitäts-Timeouts der automatische Rückfall in <code>kDeAuthenticated</code> <a class="spec-record-ref" data-req="SWS_DM_01210" href="../spec/record.html?id=SWS_DM_01210">[SWS_DM_01210]</a>. Durch den Aufruf von <code>Refresh</code> verlängert die Anwendung die durch <code>Authenticate</code> oder <code>OverrideDefaultRoles</code> gestarteten Timer <a class="spec-record-ref" data-req="SWS_DM_01155" href="../spec/record.html?id=SWS_DM_01155">[SWS_DM_01155]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=133">AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 „ClientAuthenticationHandle“</a>.</li>
<li><strong>Berechtigungen widerrufen:</strong> Mit <code>Revoke</code> de-authentifiziert die Anwendung den Client explizit, löscht die zugehörige <code>DynamicAccessList</code> und setzt überschriebene Standardrollen zurück <a class="spec-record-ref" data-req="SWS_DM_01154" href="../spec/record.html?id=SWS_DM_01154">[SWS_DM_01154]</a>.</li>
</ol>
