<h4>Context</h4>
<p>The abstract class <code>ara::sm::s2r::S2RSatellite</code> <a class="spec-record-ref" data-req="SWS_SM_81002" href="../spec/record.html?id=SWS_SM_81002">[SWS_SM_81002]</a> forms the interface for Adaptive Applications to receive notifications about the transition to a \"prepared for Suspend-to-RAM\" state and leaving this state <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>. It serves as the counterpart to component <code>S2RHub</code>, which coordinates communication across instances with all registered satellites <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=35">AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”</a>.</p>
<p>Typical tasks of an application when entering this state include persisting data, stopping offered services, or terminating security activities before the operating system performs the suspend <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>. Communication between <code>S2RHub</code> and the satellites is secured via Identity and Access Management (IAM), so that only authorized satellite processes are registered <a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>S2RSatellite</code> can be created either via the static entry point <code>Create()</code>, which establishes a direct connection to <code>S2RHub</code> on the same machine <a class="spec-record-ref" data-req="SWS_SM_81014" href="../spec/record.html?id=SWS_SM_81014">[SWS_SM_81014]</a>, or via the parameterized constructor with a <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_SM_81003" href="../spec/record.html?id=SWS_SM_81003">[SWS_SM_81003]</a>. The default constructor is deleted <a class="spec-record-ref" data-req="SWS_SM_81004" href="../spec/record.html?id=SWS_SM_81004">[SWS_SM_81004]</a>. Since <code>S2RSatellite</code> is an abstract class, an application-specific subclass is instantiated that implements the pure virtual callback methods.</p>
<p>Copy operations are explicitly prohibited <a class="spec-record-ref" data-req="SWS_SM_81007" href="../spec/record.html?id=SWS_SM_81007">[SWS_SM_81007]</a> <a class="spec-record-ref" data-req="SWS_SM_81009" href="../spec/record.html?id=SWS_SM_81009">[SWS_SM_81009]</a>. However, an object can be moved via move semantics <a class="spec-record-ref" data-req="SWS_SM_81006" href="../spec/record.html?id=SWS_SM_81006">[SWS_SM_81006]</a> <a class="spec-record-ref" data-req="SWS_SM_81008" href="../spec/record.html?id=SWS_SM_81008">[SWS_SM_81008]</a>. After instantiation, the object is in the unregistered state. By calling <code>Offer()</code>, the satellite actively registers with <code>S2RHub</code> and enables the reception of handler calls <a class="spec-record-ref" data-req="SWS_SM_81012" href="../spec/record.html?id=SWS_SM_81012">[SWS_SM_81012]</a> <a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>. The state remains active until <code>StopOffer()</code> cancels the registration and deactivates calls <a class="spec-record-ref" data-req="SWS_SM_81013" href="../spec/record.html?id=SWS_SM_81013">[SWS_SM_81013]</a> <a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>. Resources are released via the virtual destructor <code>~S2RSatellite()</code> <a class="spec-record-ref" data-req="SWS_SM_81005" href="../spec/record.html?id=SWS_SM_81005">[SWS_SM_81005]</a>.</p>
<p>With regard to concurrency, the creation methods and move operations are specified as thread-safe, whereas <code>Offer()</code>, <code>StopOffer()</code>, the destructor, and the handlers <code>EnterSuspendMode()</code> and <code>LeaveSuspendMode()</code> are designated as not thread-safe <a class="spec-record-ref" data-req="SWS_SM_81003" href="../spec/record.html?id=SWS_SM_81003">[SWS_SM_81003]</a> <a class="spec-record-ref" data-req="SWS_SM_81005" href="../spec/record.html?id=SWS_SM_81005">[SWS_SM_81005]</a> <a class="spec-record-ref" data-req="SWS_SM_81010" href="../spec/record.html?id=SWS_SM_81010">[SWS_SM_81010]</a> <a class="spec-record-ref" data-req="SWS_SM_81011" href="../spec/record.html?id=SWS_SM_81011">[SWS_SM_81011]</a> <a class="spec-record-ref" data-req="SWS_SM_81012" href="../spec/record.html?id=SWS_SM_81012">[SWS_SM_81012]</a> <a class="spec-record-ref" data-req="SWS_SM_81013" href="../spec/record.html?id=SWS_SM_81013">[SWS_SM_81013]</a> <a class="spec-record-ref" data-req="SWS_SM_81014" href="../spec/record.html?id=SWS_SM_81014">[SWS_SM_81014]</a>.</p>

<h4>Usage Path</h4>
<p>The regular sequence is divided into initialization, registration, suspend/resume handling, and deregistration:</p>
<ol>
  <li><strong>Creation:</strong> The application creates an instance of its derived class, for example via <code>S2RSatellite::Create()</code> <a class="spec-record-ref" data-req="SWS_SM_81014" href="../spec/record.html?id=SWS_SM_81014">[SWS_SM_81014]</a> or via the constructor with <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_SM_81003" href="../spec/record.html?id=SWS_SM_81003">[SWS_SM_81003]</a>.</li>
  <li><strong>Registration (Offer):</strong> The application calls <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_SM_81012" href="../spec/record.html?id=SWS_SM_81012">[SWS_SM_81012]</a>. This registers the satellite with <code>S2RHub</code> <a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>.</li>
  <li><strong>Suspend trigger:</strong> If the <code>S2RHub</code> initiates the change via <code>RequestToEnterSuspendMode</code> <a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>, the runtime environment calls <code>EnterSuspendMode()</code> on the satellite <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>. The application performs preparations and signals completion asynchronously via a <code>ara::core::Future&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_SM_81010" href="../spec/record.html?id=SWS_SM_81010">[SWS_SM_81010]</a>.</li>
  <li><strong>Resume trigger:</strong> When exiting the suspend state, the <code>S2RHub</code> triggers the call of <code>LeaveSuspendMode()</code> via <code>RequestToLeaveSuspendMode</code> <a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a> <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>. The application restores its regular operation and completes the resulting future <a class="spec-record-ref" data-req="SWS_SM_81011" href="../spec/record.html?id=SWS_SM_81011">[SWS_SM_81011]</a>.</li>
  <li><strong>Deregistration (StopOffer):</strong> Before terminating the application, <code>StopOffer()</code> is called to block handler calls and unregister the instance at the hub <a class="spec-record-ref" data-req="SWS_SM_81013" href="../spec/record.html?id=SWS_SM_81013">[SWS_SM_81013]</a> <a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>In the event of an error, the methods report error codes from the error domain <code>SmErrc</code> or trigger architectural violations:</p>
<ul>
  <li><code>SmErrc::kAuthenticationRequired</code>: Is returned by <code>Create()</code> if the \"Force IAM switch\" is set and IAM authentication is required <a class="spec-record-ref" data-req="SWS_SM_00716" href="../spec/record.html?id=SWS_SM_00716">[SWS_SM_00716]</a> <a class="spec-record-ref" data-req="SWS_SM_81014" href="../spec/record.html?id=SWS_SM_81014">[SWS_SM_81014]</a>. In this case, the constructor <code>S2RSatellite(const ara::core::InstanceSpecifier&amp;)</code> must be used instead <a class="spec-record-ref" data-req="SWS_SM_81014" href="../spec/record.html?id=SWS_SM_81014">[SWS_SM_81014]</a>.</li>
  <li><code>SmErrc::kOfferFailed</code>: Occurs when calling <code>Offer()</code> if communication with the State Management daemon fails <a class="spec-record-ref" data-req="SWS_SM_81012" href="../spec/record.html?id=SWS_SM_81012">[SWS_SM_81012]</a>.</li>
  <li><code>SmErrc::kRejected</code>: Is signaled by the application via the returned future if difficulties arise when entering suspend mode (<a class="spec-record-ref" data-req="SWS_SM_81010" href="../spec/record.html?id=SWS_SM_81010">[SWS_SM_81010]</a>) or leaving suspend mode (<a class="spec-record-ref" data-req="SWS_SM_81011" href="../spec/record.html?id=SWS_SM_81011">[SWS_SM_81011]</a>). Negative feedback for <code>LeaveSuspendMode</code> leads to the overall result <code>kAtLeastOneHadIssuesToLeave</code> on the <code>S2RHub</code> <a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>.</li>
  <li><strong>Model and context violations:</strong> When calling the constructor with <code>InstanceSpecifier</code>, integrity checks are performed. If these fail, specific violations are triggered, including <code>AraNotInitializedViolation</code>, <code>InstanceSpecifierMappingIntegrityViolation</code>, <code>PortInterfaceMappingViolation</code>, <code>ProcessMappingViolation</code>, and <code>InstanceSpecifierAlreadyInUseViolation</code> <a class="spec-record-ref" data-req="SWS_SM_81003" href="../spec/record.html?id=SWS_SM_81003">[SWS_SM_81003]</a>.</li>
</ul>
