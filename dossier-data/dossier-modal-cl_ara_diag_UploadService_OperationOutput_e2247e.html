<p class="ai-level ai-oneliner-lead" data-ai-level="1">Nimmt die Nutzdaten einer positiven Antwortnachricht für Diagnose-Upload-Operationen auf.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Struktur <code>ara::diag::UploadService::OperationOutput</code> dient als Ausgabeparameter zur Rückgabe von Nutzdaten einer positiven Diagnoseantwort bei Upload-Diensten <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Die Anwendungssoftware instanziiert das Objekt nach erfolgreicher Durchführung einer Upload-Operation und befüllt das Mitglied <code>responseData</code> mit den zu sendenden Datenbytes <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Dabei darf der Inhalt von <code>responseData</code> keinen Service Identifier (SID) enthalten und muss den operationsspezifischen Vorgaben von Diensten wie <code>UploadData</code> oder <code>RequestUploadExit</code> entsprechen. Interpretation: Im Fehlerfall wird die Struktur nicht verwendet, sondern ein negativer Antwortstatus signalisiert.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
  <p>Die Struktur <code>ara::diag::UploadService::OperationOutput</code> fungiert als Datenbehälter für die Nutzdaten einer erfolgreichen Diagnoseoperation im Rahmen des fahrzeugseitigen Upload-Dienstes <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Ihre primäre Verantwortung besteht darin, die Daten für eine positive Antwortnachricht („positive response message“) zu kapseln und an die Plattform weiterzuleiten <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</p>
  <p>Im Gesamtsystem interagieren hierbei drei Komponenten: Der externe Diagnose-Client (Tester), die Diagnose-Laufzeitumgebung des Adaptive-Systems (<code>ara::diag</code>) sowie die anwendungsspezifische Implementierung des <code>UploadService</code> <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Sobald der Tester eine UDS-Dienstoperation anfordert, delegiert <code>ara::diag</code> die Bearbeitung an den zuständigen Dienstanbieter der Anwendung, welcher das Ergebnis über <code>OperationOutput</code> an die Plattformschicht zurückreicht <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</p>

  <h4>Lebenszyklus</h4>
  <p>Die Struktur <code>OperationOutput</code> ist als reines Datentransferobjekt ohne eigene Zustandslogik konzipiert und wird über den Header <code>#include "ara/diag/upload.h"</code> bereitgestellt <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Ihr Lebenszyklus gliedert sich in folgende Phasen:</p>
  <ul>
    <li><strong>Erzeugung:</strong> Die Instanziierung erfolgt anwendungsseitig innerhalb der ausführenden Diagnoseoperation, sobald die geforderten Upload-Daten erfolgreich zusammengestellt wurden. Interpretation: Das Objekt wird vermutlich lokal auf dem Stack der Dienstanwendung angelegt.</li>
    <li><strong>Befüllung:</strong> Die Anwendungslogik weist dem öffentlichen Mitglied <code>responseData</code> vom Typ <code>ara::core::Vector&lt;std::uint8_t&gt;</code> die bereitzustellenden Nutzdaten zu <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</li>
    <li><strong>Besitzübergang:</strong> Das Objekt wird als Operationsergebnis an <code>ara::diag</code> übergeben. Interpretation: Diese Übergabe dürfte per Wert oder Move-Semantik geschehen, womit die Verantwortung für die Daten auf die Plattform übergeht.</li>
    <li><strong>Zerstörung:</strong> Nach der Serialisierung der Nutzdaten in die UDS-Antwortnachricht wird die Struktur durch die Laufzeitumgebung freigegeben.</li>
  </ul>
  <p>Hinsichtlich Nebenläufigkeit bietet <code>OperationOutput</code> keine interne Synchronisation. Da Instanzen jedoch dediziert je Operationsaufruf erzeugt und thread-lokal verarbeitet werden, ist keine geteilte Zustandsverwaltung erforderlich.</p>

  <h4>Nutzungspfad</h4>
  <p>Der reguläre Ablauf zur Bereitstellung von Antwortdaten über <code>OperationOutput</code> umfasst eine feste Abfolge von Interaktionsschritten:</p>
  <ol>
    <li>Ein externer Tester sendet eine Upload-Anforderung (wie <code>UploadData</code> oder <code>RequestUploadExit</code>) an das Steuergerät <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</li>
    <li>Die Diagnoseverwaltung <code>ara::diag</code> verarbeitet den Protokollkopf und ruft die korrespondierende Operation der Anwendungsinstanz von <code>UploadService</code> auf <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</li>
    <li>Die Anwendung verarbeitet die Anfrage, erzeugt eine Instanz von <code>OperationOutput</code> und befüllt <code>responseData</code> mit den Nutzdaten <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Dabei darf <code>responseData</code> ausschließlich die Nutzdaten ohne den Service Identifier (SID) enthalten <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Je nach Operation variiert der geforderte Inhalt sowie die Anfangsposition der Daten in der positiven Antwortnachricht <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</li>
    <li>Die Struktur wird an <code>ara::diag</code> zurückgegeben.</li>
    <li>Die Plattformschicht generiert die vollständige UDS-Antwortnachricht und übermittelt diese an den Tester <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</li>
  </ol>

  <h4>Fehlerszenarien</h4>
  <p>Die Struktur <code>OperationOutput</code> ist ausschließlich für erfolgreiche Ausführungen und positive Antwortnachrichten spezifiziert <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Schlägt eine Operation fehl (beispielsweise aufgrund ungültiger Adressbereiche oder Sequenzfehler bei <code>UploadData</code>), kommt <code>OperationOutput</code> nicht zum Einsatz. Interpretation: Fehlerhafte Abläufe werden vermutlich über separate Diagnose-Fehlercodes (NRCs) an <code>ara::diag</code> gemeldet, sodass das Erzeugen oder Befüllen der Ausgabestruktur entfällt.</p>
  <p>Als Vorbedingung für die Rückgabe gilt, dass <code>responseData</code> exakt die von der jeweiligen Dienstoperation geforderten Bytes umfasst und keine vorangestellten Protokollkennungen enthält <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. Als Nachbedingung übernimmt die Diagnose-Verwaltung die Daten zur Finalisierung der Buskommunikation <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>.</p>
