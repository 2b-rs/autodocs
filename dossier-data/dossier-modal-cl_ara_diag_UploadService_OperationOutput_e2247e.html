<h4>Error Scenarios</h4>
<p>The structure <code>ara::diag::UploadService::OperationOutput</code> is by definition intended exclusively for the success case (“positive response message”) <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. In the context of errors, the following peculiarities arise:</p>
<ul>
<li><strong>Negative UDS responses (NRC):</strong> If errors occur during the execution of the upload operation (e.g., invalid sequences or memory errors), <code>OperationOutput</code> is not used. Interpretation: In error cases, the application is likely to return a corresponding error code via the error mechanism of the Adaptive Platform (such as <code>ara::core::Result</code>) instead, whereupon Diagnostic Management generates a negative response (Negative Response Code) without using payload data from <code>OperationOutput</code>.</li>
<li><strong>Inconsistent payload data structure:</strong> The precondition for a valid response message is the correct structuring of <code>responseData</code> according to the requirements of the respective operation <a class="spec-record-ref" data-req="SWS_DM_00796" href="../spec/record.html?id=SWS_DM_00796">[SWS_DM_00796]</a>. If header bytes such as the SID are inadvertently prepended or the content deviates from the protocol expectations, this results in malformed UDS messages on the diagnostic channel.</li>
</ul>
