<h4>Context</h4>
<p>In the AUTOSAR Adaptive Platform, the abstract base class <code>ara::diag::SovdBulkData</code> forms the central interface for handling bulk data within the scope of Service-Oriented Vehicle Diagnostics (SOVD) <a class="spec-record-ref" data-req="SWS_DM_01841" href="../spec/record.html?id=SWS_DM_01841">[SWS_DM_01841]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=701">AUTOSAR_AP_SWS_Diagnostics p. 701</a>. It is implemented by adaptive applications to provide or receive diagnostic and operational data such as fault logs, traces, or software packages for external diagnostic clients.</p>
<p>At least three parties are involved in the interaction:</p>
<ul>
<li><strong>SOVD client:</strong> An external entity that requests bulk data operations via standardized REST/HTTP calls in accordance with ISO 17978-3 or ASAM SOVD.</li>
<li><strong>Diagnostic Management (DM):</strong> The AUTOSAR diagnostic server receives requests and forwards them to the registered instance of <code>ara::diag::SovdBulkData</code>, provided the service was previously offered via <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>.</li>
<li><strong>Application handler:</strong> The application-specific specialization of <code>ara::diag::SovdBulkData</code>, which serves the concrete virtual callback methods for metadata queries <a class="spec-record-ref" data-req="SWS_DM_01791" href="../spec/record.html?id=SWS_DM_01791">[SWS_DM_01791]</a>, <a class="spec-record-ref" data-req="SWS_DM_01853" href="../spec/record.html?id=SWS_DM_01853">[SWS_DM_01853]</a>, data download <a class="spec-record-ref" data-req="SWS_DM_01792" href="../spec/record.html?id=SWS_DM_01792">[SWS_DM_01792]</a>, <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>, data upload <a class="spec-record-ref" data-req="SWS_DM_01793" href="../spec/record.html?id=SWS_DM_01793">[SWS_DM_01793]</a>, <a class="spec-record-ref" data-req="SWS_DM_01854" href="../spec/record.html?id=SWS_DM_01854">[SWS_DM_01854]</a>, as well as data deletion <a class="spec-record-ref" data-req="SWS_DM_01855" href="../spec/record.html?id=SWS_DM_01855">[SWS_DM_01855]</a>, <a class="spec-record-ref" data-req="SWS_DM_01856" href="../spec/record.html?id=SWS_DM_01856">[SWS_DM_01856]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The class <code>ara::diag::SovdBulkData</code> undergoes a clearly defined lifecycle consisting of instantiation, service offering, operational operation, and destruction:</p>
<ul>
<li><strong>Creation:</strong> Instantiation takes place via the constructor, passing an <code>ara::core::InstanceSpecifier</code> referencing a <code>PortPrototype</code> of a <code>DiagnosticSovdBulkDataInterface</code>, as well as a parameter of type <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. The constructor itself is thread-safe (<em>thread-safe</em>).</li>
<li><strong>Copy and move semantics:</strong> The instance represents an exclusive interface per port. Copy constructor <a class="spec-record-ref" data-req="SWS_DM_01848" href="../spec/record.html?id=SWS_DM_01848">[SWS_DM_01848]</a> and copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01850" href="../spec/record.html?id=SWS_DM_01850">[SWS_DM_01850]</a> are deleted (<code>=delete</code>). Move constructor <a class="spec-record-ref" data-req="SWS_DM_01849" href="../spec/record.html?id=SWS_DM_01849">[SWS_DM_01849]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01851" href="../spec/record.html?id=SWS_DM_01851">[SWS_DM_01851]</a> are specified with protected (<code>protected</code>) visibility.</li>
<li><strong>State management:</strong> After creation, the object is in an idle state. Calling <code>Offer()</code> activates the forwarding of incoming SOVD messages by the DM to the handler <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Via <code>StopOffer()</code>, this forwarding is deactivated again <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
<li><strong>Destruction:</strong> The destructor <code>~SovdBulkData()</code> is declared virtual <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=702">AUTOSAR_AP_SWS_Diagnostics p. 702</a>. In application practice, <code>StopOffer()</code> is likely to be called regularly before destroying an instance in order to complete pending requests in an orderly manner.</li>
<li><strong>Concurrency:</strong> The <code>ConcurrencyType</code> passed in the constructor determines whether the application-specific implementations of the virtual methods must be designed thread-safe (<code>kConcurrent</code>) or not thread-safe (<code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. The control methods <code>Offer()</code> and <code>StopOffer()</code> as well as the destructor are specified as not thread-safe (<em>not thread-safe</em>) and require calls from a protected context <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>, <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>, <a class="spec-record-ref" data-req="SWS_DM_01852" href="../spec/record.html?id=SWS_DM_01852">[SWS_DM_01852]</a>.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical usage path comprises the registration of the handler and the asynchronous processing of bulk data transfer requests, exemplified by the download of bulk data:</p>
<ol>
<li><strong>Initialization and offering:</strong> The application instantiates the derived handler class with the configured <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a> and calls <code>Offer()</code> to activate routing in the DM <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>.</li>
<li><strong>Request reception:</strong> An external client sends a request to the SOVD method "Download Bulk Data". The DM delegates the request to <code>RequestBulkDataDownload()</code>, passing category, ID, HTTP Accept header, meta-information, and a <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01792" href="../spec/record.html?id=SWS_DM_01792">[SWS_DM_01792]</a>, <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Processing and response:</strong> The implementation checks the resource and asynchronously returns a <code>ara::core::Future</code>. This contains either a read session (<code>DataTransferReadSession</code>) including the associated <code>BulkDataMetaDataDescriptor</code> or an HTTP redirect (<code>HttpRedirect</code>) <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Cancellation handling:</strong> If the client disconnects prematurely, the DM signals this via the passed <code>CancellationHandler</code>, allowing the application to release resources <a class="spec-record-ref" data-req="SWS_DM_01873" href="../spec/record.html?id=SWS_DM_01873">[SWS_DM_01873]</a>.</li>
<li><strong>Service unregistration:</strong> When shutting down the component, the application calls <code>StopOffer()</code>, whereby the DM no longer delivers any further requests <a class="spec-record-ref" data-req="SWS_DM_01858" href="../spec/record.html?id=SWS_DM_01858">[SWS_DM_01858]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error situations can occur in different phases and are reported via specific mechanisms:</p>
<ul>
<li><strong>Model and port violations during construction:</strong> The constructor is declared as <code>noexcept</code>, but performs integrity checks against the AUTOSAR model <a class="spec-record-ref" data-req="SWS_DM_01847" href="../spec/record.html?id=SWS_DM_01847">[SWS_DM_01847]</a>. Possible violations include:
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the context of the executable or does not reference a <code>PortPrototype</code>.</li>
  <li><code>PortInterfaceMappingViolation</code>: The referenced port is not typed by a <code>DiagnosticSovdBulkDataInterface</code>.</li>
  <li><code>ProcessMappingViolation</code>: The modeled process does not match the runtime process.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another instance in the current process.</li>
  </ul>
</li>
<li><strong>Configuration and state errors during Offer():</strong> The method <code>Offer()</code> returns a <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_01857" href="../spec/record.html?id=SWS_DM_01857">[SWS_DM_01857]</a>. Possible error codes are:
  <ul>
  <li><code>DiagOfferErrc::kConfigurationMismatch</code>: The configuration of the monitor does not match the DEXT diagnostic description.</li>
  <li><code>DiagOfferErrc::kAlreadyOffered</code>: The service instance was already registered previously.</li>
  </ul>
</li>
