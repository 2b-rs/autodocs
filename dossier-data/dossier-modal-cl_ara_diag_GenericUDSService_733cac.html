<h4>Context</h4>
<p>The class <code>ara::diag::GenericUDSService</code> represents a generic service interface for diagnostic processing in the AUTOSAR Adaptive standard. It serves as an application-side base for processing UDS (Unified Diagnostic Services) diagnostic requests for which no specialized service classes are modeled or used.</p>
<p>In the overall system, <code>ara::diag::GenericUDSService</code> acts at the interface between the following components:</p>
<ul>
<li><strong>Diagnostic Management (DM):</strong> The central diagnostic subsystem of the AUTOSAR Adaptive Platform receives diagnostic messages from external diagnostic testers and, once released, forwards them to the registered service handler <a class="spec-record-ref" data-req="SWS_DM_00619" href="../spec/record.html?id=SWS_DM_00619">[SWS_DM_00619]</a> <a class="spec-record-ref" data-req="SWS_DM_00620" href="../spec/record.html?id=SWS_DM_00620">[SWS_DM_00620]</a>.</li>
<li><strong>Application-specific service handler:</strong> The concrete application derives from <code>GenericUDSService</code> and implements the pure virtual method <code>HandleMessage</code> to evaluate and respond to the actual payload of the UDS request <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
<li><strong>Platform modeling:</strong> The assignment to the communication endpoints is performed declaratively via a <code>ara::core::InstanceSpecifier</code> that refers to a modeled <code>PortPrototype</code> of a <code>DiagnosticGenericUdsInterface</code> <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>An instance of <code>GenericUDSService</code> is created via the explicit constructor, specifying a <code>ara::core::InstanceSpecifier</code> as well as the concurrency behavior <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a>:</p>
<ul>
<li><strong>Concurrency mode:</strong> Via <code>ConcurrencyType::kConcurrent</code> or <code>ConcurrencyType::kNotConcurrent</code>, the caller specifies whether the subsequent processing in <code>HandleMessage</code> must be thread-safe or non-thread-safe <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a> <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
<li><strong>Model checks:</strong> The constructor checks the validity of the port mapping, the process assignment, and whether the specifier is already used within the process <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a>.</li>
</ul>
<p>With regard to semantics and ownership, <code>GenericUDSService</code> is defined as a unique instance. Copy and move constructors as well as the corresponding assignment operators are explicitly deleted (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01657" href="../spec/record.html?id=SWS_DM_01657">[SWS_DM_01657]</a> <a class="spec-record-ref" data-req="SWS_DM_01658" href="../spec/record.html?id=SWS_DM_01658">[SWS_DM_01658]</a> <a class="spec-record-ref" data-req="SWS_DM_01655" href="../spec/record.html?id=SWS_DM_01655">[SWS_DM_01655]</a> <a class="spec-record-ref" data-req="SWS_DM_01656" href="../spec/record.html?id=SWS_DM_01656">[SWS_DM_01656]</a>.</p>
<p>The operational lifecycle is divided into two main states:</p>
<ol>
<li><strong>NichtAngeboten (initial state):</strong> After construction, forwarding by Diagnostic Management is deactivated.</li>
<li><strong>Offered:</strong> By calling <code>Offer()</code>, the instance authorizes the DM to deliver incoming UDS messages <a class="spec-record-ref" data-req="SWS_DM_00619" href="../spec/record.html?id=SWS_DM_00619">[SWS_DM_00619]</a>.</li>
<li><strong>Return to NichtAngeboten:</strong> By means of <code>StopOffer()</code>, forwarding is prevented again during operation <a class="spec-record-ref" data-req="SWS_DM_00620" href="../spec/record.html?id=SWS_DM_00620">[SWS_DM_00620]</a>.</li>
</ol>
<p>The destructor is virtual and declared as <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_00584" href="../spec/record.html?id=SWS_DM_00584">[SWS_DM_00584]</a>. While the constructor itself is thread-safe, <code>Offer()</code>, <code>StopOffer()</code>, and the destructor are not thread-safe (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a> <a class="spec-record-ref" data-req="SWS_DM_00619" href="../spec/record.html?id=SWS_DM_00619">[SWS_DM_00619]</a> <a class="spec-record-ref" data-req="SWS_DM_00620" href="../spec/record.html?id=SWS_DM_00620">[SWS_DM_00620]</a> <a class="spec-record-ref" data-req="SWS_DM_00584" href="../spec/record.html?id=SWS_DM_00584">[SWS_DM_00584]</a>. Before destroying the service object, forwarding should presumably be terminated explicitly via <code>StopOffer()</code> (interpretation).</p>

<h4>Usage Path</h4>
<p>Typical usage of <code>GenericUDSService</code> includes configuration, provision, and asynchronous response to UDS requests:</p>
<ol>
<li><strong>Initialization and start:</strong> The application instantiates the derived class with the appropriate <code>InstanceSpecifier</code> and starts service readiness by <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a> <a class="spec-record-ref" data-req="SWS_DM_00619" href="../spec/record.html?id=SWS_DM_00619">[SWS_DM_00619]</a>.</li>
<li><strong>Incoming request:</strong> As soon as a UDS request arrives, Diagnostic Management delegates it to <code>HandleMessage(sid, requestData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>:
<ul>
<li><code>sid</code> provides the UDS service identifier (Service Identifier).</li>
<li><code>requestData</code> provides the request data after the SID as <code>ara::core::Span</code>. The data remains valid until the associated promise is fulfilled or processing is canceled <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
<li><code>metaInfo</code> contains context information about the request.</li>
<li><code>cancellationHandler</code> allows checking for cancellation via <code>IsCanceled()</code> or registering a notifier function via <code>SetNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
</ul>
</li>
<li><strong>Result return:</strong> The method returns a <code>ara::core::Future&lt;OperationOutput&gt;</code>. Upon successful processing, the result contains the response payload in <code>OperationOutput</code>, otherwise a diagnostic error code <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
<li><strong>Deregistration:</strong> When shutting down the component, the application calls <code>StopOffer()</code> to stop message forwarding <a class="spec-record-ref" data-req="SWS_DM_00620" href="../spec/record.html?id=SWS_DM_00620">[SWS_DM_00620]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using <code>GenericUDSService</code>, error states can occur at various levels:</p>
<ul>
<li><strong>Misconfiguration during instantiation:</strong> The constructor is declared as <code>noexcept</code>, but leads to architectural violations (violations) in the case of invalid configurations <a class="spec-record-ref" data-req="SWS_DM_00616" href="../spec/record.html?id=SWS_DM_00616">[SWS_DM_00616]</a>:
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the model or does not reference a <code>PortPrototype</code>.</li>
<li><code>PortInterfaceMappingViolation</code>: The port with type <code>DiagnosticGenericUdsInterface</code> is not connected by a <code>DiagnosticServiceGenericMapping</code>.</li>
<li><code>ProcessMappingViolation</code>: No matching process found in the execution model.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: The identifier was already used for a constructor call within the same process.</li>
</ul>
</li>
<li><strong>Service already offered:</strong> If <code>Offer()</code> is called multiple times without an intervening <code>StopOffer()</code>, the call fails and returns a <code>ara::core::Result</code> with the error code <code>DiagOfferErrc::kAlreadyOffered</code> (while maintaining rollback semantics) <a class="spec-record-ref" data-req="SWS_DM_00619" href="../spec/record.html?id=SWS_DM_00619">[SWS_DM_00619]</a>.</li>
<li><strong>UDS error responses (Negative Response Codes):</strong> If the processing of a UDS message fails in <code>HandleMessage</code>, the handler must transmit an appropriate UDS NRC according to ISO 14229-1 via the error type <code>DiagUdsNrcErrc</code> in the returned <code>ara::core::Future</code> <a class="spec-record-ref" data-req="SWS_DM_00618" href="../spec/record.html?id=SWS_DM_00618">[SWS_DM_00618]</a>.</li>
</ul>
