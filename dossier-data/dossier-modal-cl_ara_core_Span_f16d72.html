<h4>Context</h4>
<p>Within the AUTOSAR Adaptive Platform (module <code>core</code>), the class <code>ara::core::Span</code> implements the standardized concept <code>std::span</code> according to <code>[views.span]</code>. It serves as a lightweight, non-owning view of a contiguous sequence of objects in memory. This abstraction allows functions and interfaces to access buffers without making assumptions about the specific container type or having to copy data.</p>
<p>The primary interaction partners include:</p>
<ul>
<li><strong>Memory sources and containers:</strong> Instances of <code>ara::core::Span</code> can be constructed via raw memory pointers and counts <a class="spec-record-ref" data-req="SWS_CORE_01942" href="../spec/record.html?id=SWS_CORE_01942">[SWS_CORE_01942]</a>, pointer pairs <a class="spec-record-ref" data-req="SWS_CORE_01943" href="../spec/record.html?id=SWS_CORE_01943">[SWS_CORE_01943]</a>, native C arrays <a class="spec-record-ref" data-req="SWS_CORE_01944" href="../spec/record.html?id=SWS_CORE_01944">[SWS_CORE_01944]</a>, fixed AUTOSAR arrays of type <code>ara::core::Array</code> <a class="spec-record-ref" data-req="SWS_CORE_01945" href="../spec/record.html?id=SWS_CORE_01945">[SWS_CORE_01945]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01946" href="../spec/record.html?id=SWS_CORE_01946">[SWS_CORE_01946]</a>, as well as arbitrary compatible containers <a class="spec-record-ref" data-req="SWS_CORE_01947" href="../spec/record.html?id=SWS_CORE_01947">[SWS_CORE_01947]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01948" href="../spec/record.html?id=SWS_CORE_01948">[SWS_CORE_01948]</a>.</li>
<li><strong>Derived subviews:</strong> Existing spans allow the creation of further views of subsequences via the methods <code>first()</code> <a class="spec-record-ref" data-req="SWS_CORE_01961" href="../spec/record.html?id=SWS_CORE_01961">[SWS_CORE_01961]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01962" href="../spec/record.html?id=SWS_CORE_01962">[SWS_CORE_01962]</a>, <code>last()</code> <a class="spec-record-ref" data-req="SWS_CORE_01963" href="../spec/record.html?id=SWS_CORE_01963">[SWS_CORE_01963]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01964" href="../spec/record.html?id=SWS_CORE_01964">[SWS_CORE_01964]</a>, and <code>subspan()</code> <a class="spec-record-ref" data-req="SWS_CORE_01965" href="../spec/record.html?id=SWS_CORE_01965">[SWS_CORE_01965]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01966" href="../spec/record.html?id=SWS_CORE_01966">[SWS_CORE_01966]</a>.</li>
<li><strong>Consuming algorithms:</strong> Processing components access the elements randomly via the index operator <code>operator[]</code> <a class="spec-record-ref" data-req="SWS_CORE_01970" href="../spec/record.html?id=SWS_CORE_01970">[SWS_CORE_01970]</a>, via pointers <code>data()</code> <a class="spec-record-ref" data-req="SWS_CORE_01971" href="../spec/record.html?id=SWS_CORE_01971">[SWS_CORE_01971]</a>, or via standard iterators (<a class="spec-record-ref" data-req="SWS_CORE_01972" href="../spec/record.html?id=SWS_CORE_01972">[SWS_CORE_01972]</a> to <a class="spec-record-ref" data-req="SWS_CORE_01979" href="../spec/record.html?id=SWS_CORE_01979">[SWS_CORE_01979]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The class <code>ara::core::Span</code> has pure value semantics (value type) without complex state transitions. The default constructor <a class="spec-record-ref" data-req="SWS_CORE_01941" href="../spec/record.html?id=SWS_CORE_01941">[SWS_CORE_01941]</a> creates an empty view. Via parameterized constructors, the span is bound to an existing memory region, for example via pointer and element count <a class="spec-record-ref" data-req="SWS_CORE_01942" href="../spec/record.html?id=SWS_CORE_01942">[SWS_CORE_01942]</a> or references to containers <a class="spec-record-ref" data-req="SWS_CORE_01945" href="../spec/record.html?id=SWS_CORE_01945">[SWS_CORE_01945]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01947" href="../spec/record.html?id=SWS_CORE_01947">[SWS_CORE_01947]</a>. The copy constructor <a class="spec-record-ref" data-req="SWS_CORE_01949" href="../spec/record.html?id=SWS_CORE_01949">[SWS_CORE_01949]</a>, the assignment operator <a class="spec-record-ref" data-req="SWS_CORE_01952" href="../spec/record.html?id=SWS_CORE_01952">[SWS_CORE_01952]</a>, and the conversion of compatible spans <a class="spec-record-ref" data-req="SWS_CORE_01950" href="../spec/record.html?id=SWS_CORE_01950">[SWS_CORE_01950]</a> are declared as <code>constexpr</code> and <code>noexcept</code>.</p>
<p>In terms of ownership, <code>ara::core::Span</code> does not own the referenced memory. The destructor is declared as <code>default</code> <a class="spec-record-ref" data-req="SWS_CORE_01951" href="../spec/record.html?id=SWS_CORE_01951">[SWS_CORE_01951]</a> and does not perform any memory deallocation. Interpretation: Allocation and lifetime management remain entirely with the calling component or the underlying container. Accordingly, copying or assigning a span results in a shallow copy, where only pointer and length information are duplicated.</p>
<p>With regard to concurrency, all member functions are qualified as <code>noexcept</code> and <code>const</code>. Multiple threads can use the same span or parallel views of the same memory region for reading concurrently. Interpretation: Concurrent read accesses are likely free of data races, whereas modifying accesses to the underlying data via non-const element references <a class="spec-record-ref" data-req="SWS_CORE_01970" href="../spec/record.html?id=SWS_CORE_01970">[SWS_CORE_01970]</a> require external synchronization by the user.</p>

<h4>Usage Path</h4>
<p>A typical usage path comprises providing a memory region, setting up the view, functional decomposition, and accessing the elements:</p>
<ol>
<li><strong>Create view:</strong> A data source, such as a <code>ara::core::Array</code>, is instantiated. Subsequently, a <code>ara::core::Span</code> is created that references this memory region <a class="spec-record-ref" data-req="SWS_CORE_01945" href="../spec/record.html?id=SWS_CORE_01945">[SWS_CORE_01945]</a>. Alternatively, a dynamic buffer can be passed via base pointer and element count <a class="spec-record-ref" data-req="SWS_CORE_01942" href="../spec/record.html?id=SWS_CORE_01942">[SWS_CORE_01942]</a>.</li>
<li><strong>Check and pass view:</strong> The span is passed efficiently by value to a processing function. The function can check via <code>empty()</code> <a class="spec-record-ref" data-req="SWS_CORE_01969" href="../spec/record.html?id=SWS_CORE_01969">[SWS_CORE_01969]</a> whether elements are present and determine the dimensions via <code>size()</code> <a class="spec-record-ref" data-req="SWS_CORE_01967" href="../spec/record.html?id=SWS_CORE_01967">[SWS_CORE_01967]</a> or <code>size_bytes()</code> <a class="spec-record-ref" data-req="SWS_CORE_01968" href="../spec/record.html?id=SWS_CORE_01968">[SWS_CORE_01968]</a>.</li>
<li><strong>Form subranges:</strong> If needed, the processing function isolates subranges, for instance with <code>subspan(offset, count)</code> <a class="spec-record-ref" data-req="SWS_CORE_01966" href="../spec/record.html?id=SWS_CORE_01966">[SWS_CORE_01966]</a> or via prefix and suffix methods such as <code>first()</code> <a class="spec-record-ref" data-req="SWS_CORE_01962" href="../spec/record.html?id=SWS_CORE_01962">[SWS_CORE_01962]</a> and <code>last()</code> <a class="spec-record-ref" data-req="SWS_CORE_01964" href="../spec/record.html?id=SWS_CORE_01964">[SWS_CORE_01964]</a>.</li>
<li><strong>Element access:</strong> The elements are read or modified via <code>front()</code> <a class="spec-record-ref" data-req="SWS_CORE_01959" href="../spec/record.html?id=SWS_CORE_01959">[SWS_CORE_01959]</a>, <code>back()</code> <a class="spec-record-ref" data-req="SWS_CORE_01960" href="../spec/record.html?id=SWS_CORE_01960">[SWS_CORE_01960]</a>, the index operator <code>operator[]</code> <a class="spec-record-ref" data-req="SWS_CORE_01970" href="../spec/record.html?id=SWS_CORE_01970">[SWS_CORE_01970]</a>, or pointer-based via <code>data()</code> <a class="spec-record-ref" data-req="SWS_CORE_01971" href="../spec/record.html?id=SWS_CORE_01971">[SWS_CORE_01971]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The interface of <code>ara::core::Span</code> reports errors neither via error codes (such as <code>ara::core::ErrorCode</code>) nor via C++ exceptions. All constructors, assignment operators, and access methods are without exception declared as <code>noexcept</code> and specified as exception-safe (<code>exception safe</code>) (<a class="spec-record-ref" data-req="SWS_CORE_01941" href="../spec/record.html?id=SWS_CORE_01941">[SWS_CORE_01941]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01967" href="../spec/record.html?id=SWS_CORE_01967">[SWS_CORE_01967]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01970" href="../spec/record.html?id=SWS_CORE_01970">[SWS_CORE_01970]</a>). Faulty calls instead lead directly to undefined behavior:</p>
<ul>
