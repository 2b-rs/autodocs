  <h4>Context</h4>
  <p>
    The interface <code>ara::crypto::cryp::VerifierPublicCtx</code> forms the standardized abstraction in the Adaptive AUTOSAR platform for the verification of digital signatures using asymmetric cryptography (public-key methods). It inherits from the base context <code>CryptoContext</code> and encapsulates the state as well as the mathematical operations of a signature verification algorithm.
  </p>
  <p>
    Essentially three components and objects are involved in the signature verification:
  </p>
  <ul>
    <li><strong>Calling application:</strong> Controls the verification process, provides message data as well as signatures, and evaluates the verification result.</li>
    <li><strong>Key sources:</strong> The class processes public keys either as an independent key object via <code>PublicKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24115" href="../spec/record.html?id=SWS_CRYPT_24115">[SWS_CRYPT_24115]</a> or via a managed key slot <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50018" href="../spec/record.html?id=SWS_CRYPT_50018">[SWS_CRYPT_50018]</a>.</li>
    <li><strong>Cryptographic context (VerifierPublicCtx):</strong> Executes the cryptographic signature comparison either as a single-step verification (one-shot) <a class="spec-record-ref" data-req="SWS_CRYPT_24112" href="../spec/record.html?id=SWS_CRYPT_24112">[SWS_CRYPT_24112]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50024" href="../spec/record.html?id=SWS_CRYPT_50024">[SWS_CRYPT_50024]</a> or as a multi-step streaming verification <a class="spec-record-ref" data-req="SWS_CRYPT_50019" href="../spec/record.html?id=SWS_CRYPT_50019">[SWS_CRYPT_50019]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50021" href="../spec/record.html?id=SWS_CRYPT_50021">[SWS_CRYPT_50021]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50022" href="../spec/record.html?id=SWS_CRYPT_50022">[SWS_CRYPT_50022]</a>.</li>
  </ul>

  <h4>Lifecycle</h4>
  <p>
    For referencing and lifetime management, the interface defines the smart pointer alias <code>Sptr</code> as <code>std::shared_ptr&lt;VerifierPublicCtx&gt;</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24101" href="../spec/record.html?id=SWS_CRYPT_24101">[SWS_CRYPT_24101]</a>. All interface methods are declared as <code>noexcept</code>, offer complete exception safety (<em>exception safe</em>), and are specified as thread-safe (<em>thread-safe</em>) for concurrent access.
  </p>
  <p>
    The lifecycle of a context goes through three main phases:
  </p>
  <ol>
    <li>
      <strong>Uninitialized (Uninitialized):</strong> After creation, the context does not yet have a binding to a public key. Calls to verification methods fail with an error at this stage.
    </li>
    <li>
      <strong>Ready / Configured (Configured):</strong> By assigning a key via <code>SetKey()</code> with <code>PublicKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24115" href="../spec/record.html?id=SWS_CRYPT_24115">[SWS_CRYPT_24115]</a> or <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50018" href="../spec/record.html?id=SWS_CRYPT_50018">[SWS_CRYPT_50018]</a>, the context becomes ready for use. In this phase, one-shot checks can be performed or streaming sessions can be initialized.
    </li>
    <li>
      <strong>Streaming active (Streaming):</strong> Calling <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50019" href="../spec/record.html?id=SWS_CRYPT_50019">[SWS_CRYPT_50019]</a> or <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50020" href="../spec/record.html?id=SWS_CRYPT_50020">[SWS_CRYPT_50020]</a> puts the context into ongoing data processing. Subsequently, message parts are fed in via <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50021" href="../spec/record.html?id=SWS_CRYPT_50021">[SWS_CRYPT_50021]</a>. The phase ends regularly via <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50022" href="../spec/record.html?id=SWS_CRYPT_50022">[SWS_CRYPT_50022]</a> or prematurely via <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50023" href="../spec/record.html?id=SWS_CRYPT_50023">[SWS_CRYPT_50023]</a>. Interpretation: It is assumed that after completion or cancellation of the streaming phase, the context remains in the configured state and can be restarted with the existing key.
    </li>
  </ol>

  <h4>Usage Path</h4>
  <p>
    Two alternative usage patterns are available for signature verification:
  </p>
  <p>
    <strong>1. Multi-step streaming verification:</strong> This pattern is suitable for large amounts of data or messages received in fragments:
  </p>
  <ul>
    <li><strong>Key binding:</strong> Assignment of the key via <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24115" href="../spec/record.html?id=SWS_CRYPT_24115">[SWS_CRYPT_24115]</a> or <a class="spec-record-ref" data-req="SWS_CRYPT_50018" href="../spec/record.html?id=SWS_CRYPT_50018">[SWS_CRYPT_50018]</a>.</li>
    <li><strong>Query buffer limits:</strong> Optionally, <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50025" href="../spec/record.html?id=SWS_CRYPT_50025">[SWS_CRYPT_50025]</a> determines the maximum processable block size in bytes for subsequent calls.</li>
    <li><strong>Initialization:</strong> Start of the verification via <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50019" href="../spec/record.html?id=SWS_CRYPT_50019">[SWS_CRYPT_50019]</a> or <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50020" href="../spec/record.html?id=SWS_CRYPT_50020">[SWS_CRYPT_50020]</a>, provided that the algorithm requires application-specific context data.</li>
    <li><strong>Data input:</strong> Single or multiple passing of the message parts via <code>Update(data)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50021" href="../spec/record.html?id=SWS_CRYPT_50021">[SWS_CRYPT_50021]</a>.</li>
    <li><strong>Completion and evaluation:</strong> Call of <code>Finish(signature, signatureFormat)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50022" href="../spec/record.html?id=SWS_CRYPT_50022">[SWS_CRYPT_50022]</a>. The returned <code>ara::core::Result&lt;bool&gt;</code> contains <code>true</code> if the signature is intact and <code>false</code> in case of invalidity.</li>
    <li><strong>Abort:</strong> If an error occurs during transmission, the operation can be aborted via <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50023" href="../spec/record.html?id=SWS_CRYPT_50023">[SWS_CRYPT_50023]</a>.</li>
  </ul>
