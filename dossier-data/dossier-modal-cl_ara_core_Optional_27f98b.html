  <h4>Context</h4>
  <p>The template class <code>ara::core::Optional</code> provides a standard-compliant implementation of the C++ vocabulary type <code>std::optional&lt;T&gt;</code> for the AUTOSAR Adaptive Platform. It serves as a container for an optionally present value of type <code>value_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01102" href="../spec/record.html?id=SWS_CORE_01102">[SWS_CORE_01102]</a>) without allocating dynamic memory on the heap. Typical areas of application in the AUTOSAR environment include function returns, configuration parameters, or message elements whose presence cannot be guaranteed at runtime, thereby avoiding the use of sentinel values or raw pointers.</p>

  <h4>Lifecycle</h4>
  <p>An object of <code>ara::core::Optional</code> is at any time in exactly one of two discrete states: either it contains no value (empty state) or it holds an initialized instance of type <code>T</code> (engaged state).</p>

  <p>Creation into the empty state occurs via the default constructor (<a class="spec-record-ref" data-req="SWS_CORE_01103" href="../spec/record.html?id=SWS_CORE_01103">[SWS_CORE_01103]</a>) or by passing <code>nullopt_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01104" href="../spec/record.html?id=SWS_CORE_01104">[SWS_CORE_01104]</a>); both are unconditionally declared as <code>noexcept</code>. An engaged state can be assumed directly via copy and move constructors (<a class="spec-record-ref" data-req="SWS_CORE_01105" href="../spec/record.html?id=SWS_CORE_01105">[SWS_CORE_01105]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01106" href="../spec/record.html?id=SWS_CORE_01106">[SWS_CORE_01106]</a>), by direct value passing (<a class="spec-record-ref" data-req="SWS_CORE_01109" href="../spec/record.html?id=SWS_CORE_01109">[SWS_CORE_01109]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01110" href="../spec/record.html?id=SWS_CORE_01110">[SWS_CORE_01110]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01111" href="../spec/record.html?id=SWS_CORE_01111">[SWS_CORE_01111]</a>), or in-place construction using <code>in_place_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01107" href="../spec/record.html?id=SWS_CORE_01107">[SWS_CORE_01107]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01108" href="../spec/record.html?id=SWS_CORE_01108">[SWS_CORE_01108]</a>). These constructors are conditionally exception-safe (<code>conditionally noexcept</code>), depending on whether the construction of type <code>T</code> itself is guaranteed to be <code>noexcept</code>.</p>
  <p>State transitions at runtime are controlled by the methods <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01119" href="../spec/record.html?id=SWS_CORE_01119">[SWS_CORE_01119]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01120" href="../spec/record.html?id=SWS_CORE_01120">[SWS_CORE_01120]</a>) for constructing the value in place and the assignment operators (<a class="spec-record-ref" data-req="SWS_CORE_01114" href="../spec/record.html?id=SWS_CORE_01114">[SWS_CORE_01114]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01115" href="../spec/record.html?id=SWS_CORE_01115">[SWS_CORE_01115]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01116" href="../spec/record.html?id=SWS_CORE_01116">[SWS_CORE_01116]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01117" href="../spec/record.html?id=SWS_CORE_01117">[SWS_CORE_01117]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01118" href="../spec/record.html?id=SWS_CORE_01118">[SWS_CORE_01118]</a>), which are provided with the ref-qualifier <code>&amp;</code>. The transition back to the empty state is performed via <code>reset()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01136" href="../spec/record.html?id=SWS_CORE_01136">[SWS_CORE_01136]</a>) or the assignment of <code>nullopt_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01113" href="../spec/record.html?id=SWS_CORE_01113">[SWS_CORE_01113]</a>). Two instances can be swapped using <code>swap</code> (<a class="spec-record-ref" data-req="SWS_CORE_01121" href="../spec/record.html?id=SWS_CORE_01121">[SWS_CORE_01121]</a>). The destructor (<a class="spec-record-ref" data-req="SWS_CORE_01112" href="../spec/record.html?id=SWS_CORE_01112">[SWS_CORE_01112]</a>) destroys the contained value, if present, and is conditionally exception-safe according to <code>std::is_nothrow_destructible&lt;T&gt;</code>.</p>

  <h4>Usage Path</h4>
  <p>In typical use, calling components first check for the presence of a value before accessing it:</p>
  <ul>
    <li><strong>Check:</strong> The check is performed explicitly via <code>has_value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01129" href="../spec/record.html?id=SWS_CORE_01129">[SWS_CORE_01129]</a>) or via the explicit conversion operator <code>operator bool()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01128" href="../spec/record.html?id=SWS_CORE_01128">[SWS_CORE_01128]</a>).</li>
    <li><strong>Direct access:</strong> If a value is guaranteed to be present, the instance of <code>T</code> can be accessed directly via <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>) or pointer dereferencing <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>). Likewise, the member function <code>value()</code> is available in all reference and const qualifications (<a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>).</li>
    <li><strong>Fallback value (fallback):</strong> If a default value is to be used in the absence of a value, <code>value_or()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>) provides a compact way to return either the contained value or the passed replacement value.</li>
  </ul>

  <h4>Error Scenarios</h4>
  <p>In AUTOSAR, the error behavior upon unauthorized access deliberately deviates from the ISO C++ standard:</p>
  <ul>
    <li><strong>Violation on empty access:</strong> Both <code>value()</code> and the operators <code>operator*</code> and <code>operator-&gt;</code> are declared as <code>noexcept</code>. If <code>*this</code> does not contain a value (precondition violation), a <code>IsoStdBadOptionalAccessViolation</code> is triggered (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>). Interpretation: Since these functions are specified as <code>noexcept</code>, this violation is unlikely to be propagated as a catchable C++ exception in the AUTOSAR runtime environment, but typically leads to a controlled termination or safety handling path.</li>
    <li><strong>Exception safety of <code>value_or</code>:</strong> The overloads of <code>value_or()</code> are explicitly specified as <em>not exception safe</em> (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>). If the creation or conversion of the fallback value fails, exceptions can escape to the outside.</li>
  </ul>
