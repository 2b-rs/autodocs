<p class="ai-level ai-oneliner-lead" data-ai-level="1">Kapselt einen optional vorhandenen Wert typsicher im Stack-Speicher und ermöglicht zustandsabhängigen Zugriff.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::core::Optional</code> stellt eine standardkonforme Implementierung von <code>std::optional&lt;T&gt;</code> bereit, um Werte des Typs <code>value_type</code> typsicher und allokationsfrei im Stack zu kapseln <a class="spec-record-ref" data-req="SWS_CORE_01102" href="../spec/record.html?id=SWS_CORE_01102">[SWS_CORE_01102]</a>. Anwendungen prüfen den Belegungszustand über <code>has_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_01129" href="../spec/record.html?id=SWS_CORE_01129">[SWS_CORE_01129]</a> und greifen über <code>value()</code> oder Operatoren auf den Inhalt zu. Ein Zugriff auf leere Instanzen ist strikt zu vermeiden, da er trotz <code>noexcept</code>-Deklaration die Plattformverletzung <code>IsoStdBadOptionalAccessViolation</code> auslöst <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::core::Optional</code> stellt eine standardkonforme Implementierung des Containers <code>std::optional&lt;T&gt;</code> für die Adaptive Platform bereit. Sie dient als typsichere Hülle zur Kapselung eines optionalen Werts vom Typ <code>value_type</code> <a class="spec-record-ref" data-req="SWS_CORE_01102" href="../spec/record.html?id=SWS_CORE_01102">[SWS_CORE_01102]</a>. Durch den Einsatz entfällt die Notwendigkeit von fehleranfälligen Sentinel-Werten, speziellen Fehlerflags oder dynamischen Speicherallokationen (wie Nullzeigern) zur Kennzeichnung abwesender Daten. Die Speicherung des Objekts erfolgt direkt innerhalb des Stack-Speichers der Instanz, wodurch deterministisches Ressourcenmanagement und Cache-Lokalität im AUTOSAR-Laufzeitumfeld gewährleistet werden.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Optional</code> befindet sich zu jedem Zeitpunkt in einem von zwei diskreten Zuständen: uninitialisiert (leer) oder belegt mit einem Wert vom Typ <code>T</code>. Der leere Ausgangszustand wird über den Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_01103" href="../spec/record.html?id=SWS_CORE_01103">[SWS_CORE_01103]</a> oder die explizite Initialisierung mit <code>nullopt_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01104" href="../spec/record.html?id=SWS_CORE_01104">[SWS_CORE_01104]</a> eingenommen. Die Initialisierung mit einem konkreten Wert erfolgt entweder über Kopier- und Move-Konstruktoren <a class="spec-record-ref" data-req="SWS_CORE_01105" href="../spec/record.html?id=SWS_CORE_01105">[SWS_CORE_01105]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01106" href="../spec/record.html?id=SWS_CORE_01106">[SWS_CORE_01106]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01109" href="../spec/record.html?id=SWS_CORE_01109">[SWS_CORE_01109]</a>, typkonvertierende Konstruktoren <a class="spec-record-ref" data-req="SWS_CORE_01110" href="../spec/record.html?id=SWS_CORE_01110">[SWS_CORE_01110]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01111" href="../spec/record.html?id=SWS_CORE_01111">[SWS_CORE_01111]</a> oder direkt in-place via <code>in_place_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01107" href="../spec/record.html?id=SWS_CORE_01107">[SWS_CORE_01107]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01108" href="../spec/record.html?id=SWS_CORE_01108">[SWS_CORE_01108]</a>, wodurch temporäre Kopien vollständig vermieden werden.</p>
<p>Im laufenden Betrieb kann der Zustand mehrfach wechseln: Die Methoden <code>emplace</code> konstruieren einen neuen Wert direkt im Speicher des Objekts und verwerfen einen eventuell zuvor existierenden Zustand <a class="spec-record-ref" data-req="SWS_CORE_01119" href="../spec/record.html?id=SWS_CORE_01119">[SWS_CORE_01119]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01120" href="../spec/record.html?id=SWS_CORE_01120">[SWS_CORE_01120]</a>. Ebenso führen Zuweisungsoperatoren, die über Ref-Qualifier <code>&amp;</code> strikt an Lvalues gebunden sind, in den belegten Zustand <a class="spec-record-ref" data-req="SWS_CORE_01114" href="../spec/record.html?id=SWS_CORE_01114">[SWS_CORE_01114]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01115" href="../spec/record.html?id=SWS_CORE_01115">[SWS_CORE_01115]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01116" href="../spec/record.html?id=SWS_CORE_01116">[SWS_CORE_01116]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01117" href="../spec/record.html?id=SWS_CORE_01117">[SWS_CORE_01117]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01118" href="../spec/record.html?id=SWS_CORE_01118">[SWS_CORE_01118]</a>. Das Zurücksetzen in den leeren Zustand erfolgt deterministisch über <code>reset()</code> <a class="spec-record-ref" data-req="SWS_CORE_01136" href="../spec/record.html?id=SWS_CORE_01136">[SWS_CORE_01136]</a> oder durch die Zuweisung von <code>nullopt_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01113" href="../spec/record.html?id=SWS_CORE_01113">[SWS_CORE_01113]</a>. Zudem können zwei Instanzen über <code>swap</code> effizient ihre Zustände und Dateninhalte tauschen <a class="spec-record-ref" data-req="SWS_CORE_01121" href="../spec/record.html?id=SWS_CORE_01121">[SWS_CORE_01121]</a>. Beim Erreichen des Lebensendes zerstört der Destruktor das eventuell enthaltene Objekt; seine <code>noexcept</code>-Garantie ist dabei direkt an die Destruierbarkeit von Typ <code>T</code> gekoppelt <a class="spec-record-ref" data-req="SWS_CORE_01112" href="../spec/record.html?id=SWS_CORE_01112">[SWS_CORE_01112]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Verifikation der Belegung und das anschließende Auslesen des Werts. Zur Zustandsabfrage stehen <code>has_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_01129" href="../spec/record.html?id=SWS_CORE_01129">[SWS_CORE_01129]</a> und der explizite Konvertierungsoperator <code>operator bool</code> <a class="spec-record-ref" data-req="SWS_CORE_01128" href="../spec/record.html?id=SWS_CORE_01128">[SWS_CORE_01128]</a> zur Verfügung.</p>
<p>Liegt ein Wert vor, kann auf diesen über die Dereferenzierungsoperatoren <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>) oder <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>) zugegriffen werden. Ergänzend ermöglicht die Methode <code>value()</code> den qualifizierten Zugriff auf Lvalues und Rvalues (<a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>). Soll bei fehlender Belegung ein vordefinierter Ersatzwert herangezogen werden, bietet <code>value_or</code> eine direkte Ausweichstrategie (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>). Nach Abschluss der Verarbeitung kann das Behältnis bei Bedarf über <code>reset()</code> bereinigt werden <a class="spec-record-ref" data-req="SWS_CORE_01136" href="../spec/record.html?id=SWS_CORE_01136">[SWS_CORE_01136]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Ein fehlerhafter Zugriff liegt vor, wenn eine leere Instanz dereferenziert oder deren Wert unberechtigt angefordert wird. Die Zugriffsmethoden <code>value()</code>, <code>operator*</code> und <code>operator-&gt;</code> sind in AUTOSAR Adaptive als <code>noexcept</code> deklariert, lösen jedoch im leeren Zustand die Verletzung <code>IsoStdBadOptionalAccessViolation</code> aus (<a class="spec-record-ref" data-req="SWS_CORE_01122" href="../spec/record.html?id=SWS_CORE_01122">[SWS_CORE_01122]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01123" href="../spec/record.html?id=SWS_CORE_01123">[SWS_CORE_01123]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01124" href="../spec/record.html?id=SWS_CORE_01124">[SWS_CORE_01124]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01125" href="../spec/record.html?id=SWS_CORE_01125">[SWS_CORE_01125]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01126" href="../spec/record.html?id=SWS_CORE_01126">[SWS_CORE_01126]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01127" href="../spec/record.html?id=SWS_CORE_01127">[SWS_CORE_01127]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01130" href="../spec/record.html?id=SWS_CORE_01130">[SWS_CORE_01130]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01131" href="../spec/record.html?id=SWS_CORE_01131">[SWS_CORE_01131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01132" href="../spec/record.html?id=SWS_CORE_01132">[SWS_CORE_01132]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01133" href="../spec/record.html?id=SWS_CORE_01133">[SWS_CORE_01133]</a>). Interpretation: Da die Methoden als noexcept deklariert sind, dürfte das Auslösen der IsoStdBadOptionalAccessViolation nicht als fangbare Standard-Ausnahme propagiert werden, sondern führt vermutlich über den plattformspezifischen Verletzungsmechanismus zum sofortigen Programmabbruch. Aufrufer müssen daher den Belegungsstatus zwingend vor dem Auslesen validieren.</p>
<p>Ein weiteres Fehlerszenario betrifft die Ausnahmebehandlung bei der Typkonstruktion: Konstruktoren, Zuweisungsoperatoren, <code>swap</code> und <code>emplace</code> besitzen bedingte <code>noexcept</code>-Spezifikationen, die davon abhängen, ob die entsprechenden Typoperationen von <code>T</code> selbst als noexcept deklariert sind (<a class="spec-record-ref" data-req="SWS_CORE_01105" href="../spec/record.html?id=SWS_CORE_01105">[SWS_CORE_01105]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01114" href="../spec/record.html?id=SWS_CORE_01114">[SWS_CORE_01114]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01119" href="../spec/record.html?id=SWS_CORE_01119">[SWS_CORE_01119]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01121" href="../spec/record.html?id=SWS_CORE_01121">[SWS_CORE_01121]</a>). Die Fallback-Methode <code>value_or</code> ist zudem explizit als nicht ausnahmesicher („not exception safe“) ausgewiesen (<a class="spec-record-ref" data-req="SWS_CORE_01134" href="../spec/record.html?id=SWS_CORE_01134">[SWS_CORE_01134]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01135" href="../spec/record.html?id=SWS_CORE_01135">[SWS_CORE_01135]</a>), sodass bei der Erzeugung des Rückgabewerts auftretende Fehler an den Aufrufer weitergereicht werden.</p>
