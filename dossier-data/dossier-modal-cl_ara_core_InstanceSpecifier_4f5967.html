<h4>Context</h4>
<p>The class <code>ara::core::InstanceSpecifier</code> serves in the AUTOSAR Adaptive Platform as a type-safe encapsulation of an AUTOSAR ShortName path (metamodel path) for identifying model elements. It acts as a standardized identifier with which software components, communication ports, and service instances can be uniquely referenced and resolved within the overall system.</p>
<p>In interaction with other components, <code>ara::core::InstanceSpecifier</code> essentially interacts via the following interfaces:</p>
<ul>
<li><strong>String views:</strong> Path specifications are passed as <code>ara::core::StringView</code> and, if required, provided again as such via the method <code>ToString()</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
<li><strong>Result and error handling:</strong> The static factory method uses <code>ara::core::Result</code> to return valid instances or to signal validation errors <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. In the error-based construction path, on the other hand, <code>ara::core::CoreException</code> is thrown <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
<li><strong>Containers and metamodel:</strong> By providing a strict ordering operator <code>operator&lt;</code>, the class can be used as a key in ordered containers (for example, associative maps) to manage model element identifiers <a class="spec-record-ref" data-req="SWS_CORE_08046" href="../spec/record.html?id=SWS_CORE_08046">[SWS_CORE_08046]</a>. In addition, comparison operators allow direct comparison with further instances as well as with raw path strings <a class="spec-record-ref" data-req="SWS_CORE_08042" href="../spec/record.html?id=SWS_CORE_08042">[SWS_CORE_08042]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08043" href="../spec/record.html?id=SWS_CORE_08043">[SWS_CORE_08043]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08044" href="../spec/record.html?id=SWS_CORE_08044">[SWS_CORE_08044]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08045" href="../spec/record.html?id=SWS_CORE_08045">[SWS_CORE_08045]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The creation of an instance of <code>ara::core::InstanceSpecifier</code> can take place via two different paths:</p>
<ol>
<li><strong>Factory method <code>Create</code>:</strong> The static method <code>Create</code> takes a <code>ara::core::StringView</code> and validates the syntactic rules of the path structure <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. It is exception-safe (<code>noexcept</code>), thread-safe (<code>thread-safe</code>), and returns a <code>ara::core::Result&lt;InstanceSpecifier&gt;</code> that encapsulates the finished instance in case of success or a corresponding error code in case of error.</li>
<li><strong>Direct construction:</strong> The explicit constructor also accepts a <code>ara::core::StringView</code>, but is specified as <code>noexcept(false)</code> and signals validation errors by throwing an exception of type <code>ara::core::CoreException</code> <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. This constructor is thread-safe.</li>
</ol>
<p>For value semantics, the class provides standardized constructors and assignment operators:</p>
<ul>
<li><strong>Copy:</strong> The copy constructor <a class="spec-record-ref" data-req="SWS_CORE_08022" href="../spec/record.html?id=SWS_CORE_08022">[SWS_CORE_08022]</a> is declared as <code>noexcept</code> and is thread-safe. The copy assignment operator <a class="spec-record-ref" data-req="SWS_CORE_08024" href="../spec/record.html?id=SWS_CORE_08024">[SWS_CORE_08024]</a> is also <code>noexcept</code>, but not thread-safe.</li>
<li><strong>Move:</strong> The move constructor <a class="spec-record-ref" data-req="SWS_CORE_08023" href="../spec/record.html?id=SWS_CORE_08023">[SWS_CORE_08023]</a> as well as the move assignment operator <a class="spec-record-ref" data-req="SWS_CORE_08025" href="../spec/record.html?id=SWS_CORE_08025">[SWS_CORE_08025]</a> are <code>noexcept</code>, but not thread-safe.</li>
<li><strong>Destruction:</strong> The destructor <code>~InstanceSpecifier()</code> <a class="spec-record-ref" data-req="SWS_CORE_08029" href="../spec/record.html?id=SWS_CORE_08029">[SWS_CORE_08029]</a> is <code>noexcept</code> and not thread-safe.</li>
</ul>
<p>Regarding ownership and lifetime, there is a significant restriction: The lifetime of the <code>ara::core::StringView</code> returned by <code>ToString()</code> is guaranteed only for the lifetime of the underlying string that was originally passed to the constructor or the creation method as <code>ara::core::StringView</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>. Interpretation: From this requirement, it likely follows that <code>ara::core::InstanceSpecifier</code> does not create an autonomous deep copy of the string, but internally only holds a view or reference to the original buffer. Developers must therefore ensure that the passed string object remains valid in memory throughout the entire duration of use of the <code>InstanceSpecifier</code> and the views derived from it.</p>
<p>Regarding concurrency, the following applies: Pure read operations (including <code>ToString()</code>, <code>operator==</code>, <code>operator!=</code>, <code>operator&lt;</code>, and the copy constructor) are completely thread-safe. Modifying operations (move construction, assignment operators, and destruction) are not thread-safe and must not be executed concurrently on the same object without protection.</p>

<h4>Usage Path</h4>
<p>A typical usage path comprises the validation of a model path during configuration or initialization, the creation of the identifier, and its subsequent use for identification or sorting.</p>
<ol>
<li><strong>Validated instantiation:</strong> The application calls <code>ara::core::InstanceSpecifier::Create()</code> with a metamodel path <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>.</li>
<li><strong>Result check:</strong> The returned <code>ara::core::Result</code> is checked for errors. In the case of invalid characters or missing path elements, the control logic branches to error handling.</li>
<li><strong>Identification and comparison:</strong> The extracted instance is used for comparisons with expected identifiers or string views <a class="spec-record-ref" data-req="SWS_CORE_08042" href="../spec/record.html?id=SWS_CORE_08042">[SWS_CORE_08042]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08043" href="../spec/record.html?id=SWS_CORE_08043">[SWS_CORE_08043]</a>.</li>
<li><strong>Storage in containers:</strong> If required, the instance is stored in associative data structures; sorting is performed via the lexical comparison operator <code>operator&lt;</code> <a class="spec-record-ref" data-req="SWS_CORE_08046" href="../spec/record.html?id=SWS_CORE_08046">[SWS_CORE_08046]</a>.</li>
<li><strong>Textual output:</strong> For logging or diagnostic purposes, a string representation is queried via <code>ToString()</code> <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>During the creation of an <code>ara::core::InstanceSpecifier</code>, validation errors regarding the passed name path can occur:</p>
<ul>
<li><strong><code>CoreErrc::kInvalidMetaModelShortname</code>:</strong> This error occurs when one of the path elements of the <code>qualifiedShortName</code> is missing or contains invalid characters <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
<li><strong><code>CoreErrc::kInvalidMetaModelPath</code>:</strong> This error is reported when the passed <code>qualifiedShortName</code> does not form a syntactically valid path to a model element <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>The type of error signaling depends on the selected interface:</p>
<ul>
<li>When using the factory method <code>Create</code>, the operation is executed with rollback semantics; the returned <code>ara::core::Result</code> contains the respective error code without exceptions being thrown <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>.</li>
<li>When using the explicit constructor, the occurrence of one of these errors leads to an exception of type <code>ara::core::CoreException</code> being thrown, which transports the matching <code>CoreErrc</code> error code <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>
</ul>
<p>As a precondition for error-free instantiation, the input string must always satisfy the specified syntactic rules for path elements and metamodel paths <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>, <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. In contrast, the comparison and access operators have no erroneous return states and guarantee error-free evaluation after successful creation (<code>noexcept</code>).</p>
