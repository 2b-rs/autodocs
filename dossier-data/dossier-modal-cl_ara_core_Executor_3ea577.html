<h4>Context</h4>
<p>The class <code>ara::core::Executor</code> provides an interface for an execution context that executes callable objects (callables) asynchronously in a guaranteed thread-safe environment. Within the <code>core</code> module of the AUTOSAR Adaptive Platform, the class abstracts the decoupling of invocation and actual execution, allowing applications to initiate background work without having to directly manage their own thread structures or synchronization primitives.</p>
<p>Essentially three parties are involved in the interaction with <code>ara::core::Executor</code>:</p>
<ul>
<li><strong>Caller</strong>: Submits a callable entity (such as a function object, lambda, or function pointer) along with the associated arguments.</li>
<li><strong>Execution context (executor instance and background worker)</strong>: Accepts the task and executes the callable asynchronously as well as thread-safe.</li>
<li><strong>Return channel (<code>ara::core::Future</code>)</strong>: For tasks requiring synchronization, calling <code>execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>) returns a Future object via which the caller can later access the calculation result or occurred errors. For pure fire-and-forget tasks via <code>oneway_execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>), this return channel is completely omitted.</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of an instance of <code>ara::core::Executor</code> is determined by construction, value transfer, and destruction. The specification defines specific properties regarding thread safety and exception safety:</p>
<ul>
<li><strong>Copying</strong>: The copy constructor (<a class="spec-record-ref" data-req="SWS_CORE_00009" href="../spec/record.html?id=SWS_CORE_00009">[SWS_CORE_00009]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_CORE_00017" href="../spec/record.html?id=SWS_CORE_00017">[SWS_CORE_00017]</a>) are declared as thread-safe (<em>thread-safe</em>), but explicitly as not exception safe (<em>not exception safe</em>). An instance may thus be copied concurrently, but callers must take precautions against failing copy operations.</li>
<li><strong>Move</strong>: The move constructor (<a class="spec-record-ref" data-req="SWS_CORE_00015" href="../spec/record.html?id=SWS_CORE_00015">[SWS_CORE_00015]</a>) as well as the move assignment operator (<a class="spec-record-ref" data-req="SWS_CORE_00018" href="../spec/record.html?id=SWS_CORE_00018">[SWS_CORE_00018]</a>) are declared with <code>noexcept</code> and are exception-safe (<em>exception safe</em>). However, they are not thread-safe (<em>not thread-safe</em>), so that moving an executor must take place exclusively without concurrent access.</li>
<li><strong>Destruction</strong>: The destructor <code>~Executor()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00019" href="../spec/record.html?id=SWS_CORE_00019">[SWS_CORE_00019]</a>) is <code>noexcept</code>, exception safe, and thread-safe. It ensures the orderly destruction of the instance even in multithreading scenarios.</li>
</ul>

<h4>Usage Path</h4>
<p>For asynchronous task processing, <code>ara::core::Executor</code> offers two different paths:</p>
<ol>
<li><strong>Asynchronous execution with result monitoring (<code>execute</code>)</strong>:
The caller passes the callable <code>f</code> and its arguments <code>p...</code> to the template method <code>execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>). The function immediately returns an object of type <code>ara::core::Future&lt;std::invoke_result_t&lt;std::decay_t&lt;F&gt;, std::decay_t&lt;P&gt;...&gt;&gt;</code>. The execution of <code>f</code> takes place concurrently in the background. The caller queries the result via the future at the appropriate time. It should be noted that <code>execute</code> itself is declared as not thread-safe (<em>not thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>); concurrent calls to <code>execute</code> on the same executor instance must therefore be synchronized on the caller side.</li>
<li><strong>One-way execution without return channel (<code>oneway_execute</code>)</strong>:
If the caller requires neither a result nor error monitoring, <code>oneway_execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>) is used. This method has fire-and-forget semantics, returns <code>void</code>, and does not create a future. In contrast to <code>execute</code>, <code>oneway_execute</code> is directly declared as thread-safe (<em>thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error handling differs depending on the chosen execution method and lifecycle operation:</p>
<ul>
<li><strong>No synchronous error codes</strong>: Neither <code>execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>) nor <code>oneway_execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>) defines standardized error codes during the call itself; both methods are declared with <code>noexcept</code>.</li>
<li><strong>Error forwarding via future for <code>execute</code></strong>: If an error occurs during the asynchronous execution of the callable, it is stored in the <code>ara::core::Future</code> returned by <code>execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>). Upon successful processing, the future contains the computed value, and in the event of an error, an error code (<code>ErrorCode</code>).</li>
<li><strong>Error handling for <code>oneway_execute</code></strong>: Since no return channel exists, errors that occur during the asynchronous execution of a callable passed via <code>oneway_execute</code> (<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>) cannot be propagated to the caller. They must be caught within the function object itself.</li>
<li><strong>Failing copy operations</strong>: Since the copy constructor (<a class="spec-record-ref" data-req="SWS_CORE_00009" href="../spec/record.html?id=SWS_CORE_00009">[SWS_CORE_00009]</a>) and copy assignment (<a class="spec-record-ref" data-req="SWS_CORE_00017" href="../spec/record.html?id=SWS_CORE_00017">[SWS_CORE_00017]</a>) are designated as not exception safe, copy operations can fail, whereas move operations (<a class="spec-record-ref" data-req="SWS_CORE_00015" href="../spec/record.html?id=SWS_CORE_00015">[SWS_CORE_00015]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00018" href="../spec/record.html?id=SWS_CORE_00018">[SWS_CORE_00018]</a>) are guaranteed to be exception safe by <code>noexcept</code>.</li>
</ul>
