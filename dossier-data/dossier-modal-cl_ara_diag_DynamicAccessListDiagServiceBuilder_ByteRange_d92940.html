<h4>Context</h4>
<p>The class <code>ara::diag::DynamicAccessListDiagServiceBuilder::ByteRange</code> is defined as a nested class within <code>ara::diag::DynamicAccessListDiagServiceBuilder</code> (<a class="spec-record-ref" data-req="SWS_DM_01182" href="../spec/record.html?id=SWS_DM_01182">[SWS_DM_01182]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=448">AUTOSAR_AP_SWS_Diagnostics §8.15.2 “Class: ByteRange”</a>). It represents a closed interval of single-byte values (<code>closed range</code>) and acts as an atomic pattern element (<code>pattern element</code>) when defining dynamic access lists (<code>DynamicAccessList</code>).</p>
<p>In the overall diagnostic system, the class interacts with two main partners:</p>
<ul>
<li><strong>Diagnostic application:</strong> Creates instances of <code>ByteRange</code> to specify the permitted byte values at specific positions of a diagnostic request, and reads configured limits if needed.</li>
<li><strong>DynamicAccessListDiagServiceBuilder:</strong> Serves as the recipient of the range objects. Via member functions such as <code>Add(ByteRange)</code> (<a class="spec-record-ref" data-req="SWS_DM_01177" href="../spec/record.html?id=SWS_DM_01177">[SWS_DM_01177]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=444">AUTOSAR_AP_SWS_Diagnostics §8.15.1.2.3.1 “Add(ByteRange)”</a>) or <code>EndsWith(ByteRange)</code> (<a class="spec-record-ref" data-req="SWS_DM_01180" href="../spec/record.html?id=SWS_DM_01180">[SWS_DM_01180]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=447">AUTOSAR_AP_SWS_Diagnostics §8.15.1.2.3.6 “EndsWith(ByteRange)”</a>), the builder accepts <code>ByteRange</code> objects to incrementally construct the search or release pattern for incoming UDS services.</li>
</ul>

<h4>Lifecycle</h4>
<p><code>ByteRange</code> is modeled as a final C++ value type (<code>class ByteRange final</code>). The class encapsulates values exclusively and does not manage dynamic operating system or heap resources. Accordingly, the lifecycle is straightforward:</p>
<ul>
<li><strong>Creation:</strong> Instances are initialized via the parameterized constructor <code>ByteRange(Byte min, Byte max)</code> (<a class="spec-record-ref" data-req="SWS_DM_01183" href="../spec/record.html?id=SWS_DM_01183">[SWS_DM_01183]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=450">AUTOSAR_AP_SWS_Diagnostics §8.15.2.1.2.1 “ByteRange”</a>). The parameters specify the lower and upper limits of the value range to be matched.</li>
<li><strong>Copying and moving:</strong> The class possesses full value semantics. It provides a copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01184" href="../spec/record.html?id=SWS_DM_01184">[SWS_DM_01184]</a>) as well as a move constructor (<a class="spec-record-ref" data-req="SWS_DM_01185" href="../spec/record.html?id=SWS_DM_01185">[SWS_DM_01185]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=449">AUTOSAR_AP_SWS_Diagnostics §8.15.2.1.1.1 “Move Constructor”</a>). Likewise, copy and move assignment operators (<a class="spec-record-ref" data-req="SWS_DM_01186" href="../spec/record.html?id=SWS_DM_01186">[SWS_DM_01186]</a>, <a class="spec-record-ref" data-req="SWS_DM_01187" href="../spec/record.html?id=SWS_DM_01187">[SWS_DM_01187]</a>) exist, each of which is provided with a reference qualifier (<code>&amp;</code>).</li>
<li><strong>Destruction:</strong> The destructor <code>~ByteRange()</code> (<a class="spec-record-ref" data-req="SWS_DM_01188" href="../spec/record.html?id=SWS_DM_01188">[SWS_DM_01188]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=449">AUTOSAR_AP_SWS_Diagnostics §8.15.2.1.1.2 “Destructor”</a>) releases the object. Since no dynamic resources are allocated, cleanup is trivial.</li>
<li><strong>Concurrency:</strong> Regarding thread safety, the specification distinguishes clearly between reading and modifying accesses: The constructors (<a class="spec-record-ref" data-req="SWS_DM_01183" href="../spec/record.html?id=SWS_DM_01183">[SWS_DM_01183]</a>, <a class="spec-record-ref" data-req="SWS_DM_01184" href="../spec/record.html?id=SWS_DM_01184">[SWS_DM_01184]</a>, <a class="spec-record-ref" data-req="SWS_DM_01185" href="../spec/record.html?id=SWS_DM_01185">[SWS_DM_01185]</a>) as well as the inspectors <code>GetMin()</code> (<a class="spec-record-ref" data-req="SWS_DM_01189" href="../spec/record.html?id=SWS_DM_01189">[SWS_DM_01189]</a>) and <code>GetMax()</code> (<a class="spec-record-ref" data-req="SWS_DM_01190" href="../spec/record.html?id=SWS_DM_01190">[SWS_DM_01190]</a>) are declared as <em>thread-safe</em>. In contrast, the assignment operators (<a class="spec-record-ref" data-req="SWS_DM_01186" href="../spec/record.html?id=SWS_DM_01186">[SWS_DM_01186]</a>, <a class="spec-record-ref" data-req="SWS_DM_01187" href="../spec/record.html?id=SWS_DM_01187">[SWS_DM_01187]</a>) and the destructor (<a class="spec-record-ref" data-req="SWS_DM_01188" href="../spec/record.html?id=SWS_DM_01188">[SWS_DM_01188]</a>) are <em>not thread-safe</em>. A concurrent assignment or destruction on the same instance therefore requires external synchronization.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical usage of <code>ByteRange</code> comprises creation, optional verification of the limits, and integration into a diagnostic pattern:</p>
<ol>
<li><strong>Define range:</strong> The application instantiates <code>ByteRange</code> specifying the desired byte limits via <code>ByteRange(min, max)</code> (<a class="spec-record-ref" data-req="SWS_DM_01183" href="../spec/record.html?id=SWS_DM_01183">[SWS_DM_01183]</a>). If a single fixed byte value is to be checked, <code>min</code> and <code>max</code> are set to the same value.</li>
<li><strong>Query limits (optional):</strong> If needed, the configured threshold values can be read via <code>GetMin()</code> (<a class="spec-record-ref" data-req="SWS_DM_01189" href="../spec/record.html?id=SWS_DM_01189">[SWS_DM_01189]</a>) and <code>GetMax()</code> (<a class="spec-record-ref" data-req="SWS_DM_01190" href="../spec/record.html?id=SWS_DM_01190">[SWS_DM_01190]</a>).</li>
<li><strong>Configure pattern in builder:</strong> The <code>ByteRange</code> instance is passed to <code>DynamicAccessListDiagServiceBuilder</code>. Calling <code>Add(ByteRange)</code> (<a class="spec-record-ref" data-req="SWS_DM_01177" href="../spec/record.html?id=SWS_DM_01177">[SWS_DM_01177]</a>) extends the pattern by another byte condition. By means of <code>EndsWith(ByteRange)</code> (<a class="spec-record-ref" data-req="SWS_DM_01180" href="../spec/record.html?id=SWS_DM_01180">[SWS_DM_01180]</a>), it can be specified that the pattern terminates with this value range.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The interface of <code>ByteRange</code> is characterized by maximum robustness and simplicity:</p>
<ul>
<li><strong>Freedom from exceptions:</strong> All constructors, assignment operators, inspectors, and the destructor are declared with <code>noexcept</code> and specified as exception-safe (<em>exception safe</em>) (<a class="spec-record-ref" data-req="SWS_DM_01183" href="../spec/record.html?id=SWS_DM_01183">[SWS_DM_01183]</a> to <a class="spec-record-ref" data-req="SWS_DM_01190" href="../spec/record.html?id=SWS_DM_01190">[SWS_DM_01190]</a>). Neither C++ exceptions are thrown nor are error codes (such as <code>ara::core::Result</code>) reported back.</li>
<li><strong>Validity of interval limits:</strong> The specification does not define an error signal if <code>min &gt; max</code> is passed during constructor invocation. Presumably, it is the responsibility of the applying component to ensure that <code>min &lt;= max</code> is satisfied; Interpretation: An inverse interval would likely be treated as an unmatchable sub-range in the downstream matching process of the <code>DynamicAccessListDiagServiceBuilder</code>.</li>
<li><strong>Concurrency conflicts:</strong> Since assignments (<a class="spec-record-ref" data-req="SWS_DM_01186" href="../spec/record.html?id=SWS_DM_01186">[SWS_DM_01186]</a>, <a class="spec-record-ref" data-req="SWS_DM_01187" href="../spec/record.html?id=SWS_DM_01187">[SWS_DM_01187]</a>) and destruction (<a class="spec-record-ref" data-req="SWS_DM_01188" href="../spec/record.html?id=SWS_DM_01188">[SWS_DM_01188]</a>) are not thread-safe, concurrent unprotected write and read accesses lead to data races, which must be avoided on the application side through mutexes or isolated instances.</li>
</ul>
