  <h4>Context</h4>
  <p>The template class <code>ara::core::Optional&lt;T&amp;&gt;</code> provides a partial specialization of <code>ara::core::Optional</code> for lvalue references of type <code>T&amp;</code>. Via the defined type alias <code>value_type</code> (<a class="spec-record-ref" data-req="SWS_CORE_01151" href="../spec/record.html?id=SWS_CORE_01151">[SWS_CORE_01151]</a>), the specialization binds an optional reference to an existing object. In contrast to the primary template class for value types, this specialization allows an optional reference to an external object to be held without having to use dynamic memory allocation or raw C pointers with null pointer semantics. In software architectures of the AUTOSAR Adaptive Platform, it acts as a type-safe wrapper for interfaces where return values or parameters can optionally refer to an already existing instance.</p>

  <h4>Lifecycle</h4>
  <p>The lifecycle of an instance of <code>ara::core::Optional&lt;T&amp;&gt;</code> is characterized by two disjoint states: the disengaged state (empty) and the engaged state (referencing). By default, the object can be initialized in the disengaged state without an assigned value via the default constructor (<a class="spec-record-ref" data-req="SWS_CORE_01152" href="../spec/record.html?id=SWS_CORE_01152">[SWS_CORE_01152]</a>) or via the literal <code>nullopt_t</code> (<a class="spec-record-ref" data-req="SWS_CORE_01153" href="../spec/record.html?id=SWS_CORE_01153">[SWS_CORE_01153]</a>). A direct transition to the engaged state occurs during construction by passing a reference value via the constructor template (<a class="spec-record-ref" data-req="SWS_CORE_01156" href="../spec/record.html?id=SWS_CORE_01156">[SWS_CORE_01156]</a>) or by conversion from another compatible <code>Optional</code> instance (<a class="spec-record-ref" data-req="SWS_CORE_01157" href="../spec/record.html?id=SWS_CORE_01157">[SWS_CORE_01157]</a>). Copy and move constructors are implemented by default and declared as <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_CORE_01154" href="../spec/record.html?id=SWS_CORE_01154">[SWS_CORE_01154]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01155" href="../spec/record.html?id=SWS_CORE_01155">[SWS_CORE_01155]</a>).</p>
  <p>At runtime, an existing instance can dynamically change its state. The methods <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01164" href="../spec/record.html?id=SWS_CORE_01164">[SWS_CORE_01164]</a>) and the assignment operators for compatible types (<a class="spec-record-ref" data-req="SWS_CORE_01162" href="../spec/record.html?id=SWS_CORE_01162">[SWS_CORE_01162]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01163" href="../spec/record.html?id=SWS_CORE_01163">[SWS_CORE_01163]</a>) transition the object into the engaged state or rebind it to a new reference. Copy and move assignments are also present as default implementations (<a class="spec-record-ref" data-req="SWS_CORE_01159" href="../spec/record.html?id=SWS_CORE_01159">[SWS_CORE_01159]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01160" href="../spec/record.html?id=SWS_CORE_01160">[SWS_CORE_01160]</a>). Resetting to the disengaged state occurs explicitly via <code>reset()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01165" href="../spec/record.html?id=SWS_CORE_01165">[SWS_CORE_01165]</a>) or by assigning <code>nullopt</code> (<a class="spec-record-ref" data-req="SWS_CORE_01161" href="../spec/record.html?id=SWS_CORE_01161">[SWS_CORE_01161]</a>). In addition, <code>swap</code> (<a class="spec-record-ref" data-req="SWS_CORE_01166" href="../spec/record.html?id=SWS_CORE_01166">[SWS_CORE_01166]</a>) allows swapping the contents of two instances. The destructor is specified as <code>noexcept=default</code> (<a class="spec-record-ref" data-req="SWS_CORE_01158" href="../spec/record.html?id=SWS_CORE_01158">[SWS_CORE_01158]</a>). Interpretation: Because it is a reference specialization, the class presumably does not manage the lifetime of the target object; the target object is therefore expected to exist and be destroyed independently of the container.</p>

  <h4>Usage Path</h4>
  <p>A typical usage path comprises the creation, validation, and conditional data access to the referenced object:</p>
  <ul>
    <li><strong>Creation and engagement:</strong> A component creates the object either initially empty (<a class="spec-record-ref" data-req="SWS_CORE_01152" href="../spec/record.html?id=SWS_CORE_01152">[SWS_CORE_01152]</a>) or binds it directly to an instance (<a class="spec-record-ref" data-req="SWS_CORE_01156" href="../spec/record.html?id=SWS_CORE_01156">[SWS_CORE_01156]</a>). Afterwards, the reference can be set anew via <code>emplace</code> (<a class="spec-record-ref" data-req="SWS_CORE_01164" href="../spec/record.html?id=SWS_CORE_01164">[SWS_CORE_01164]</a>) or value assignment (<a class="spec-record-ref" data-req="SWS_CORE_01162" href="../spec/record.html?id=SWS_CORE_01162">[SWS_CORE_01162]</a>).</li>
    <li><strong>State check:</strong> Before accessing the target object, the caller checks for the presence of a value. The boolean conversion operator <code>operator bool()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01171" href="../spec/record.html?id=SWS_CORE_01171">[SWS_CORE_01171]</a>) as well as the method <code>has_value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01172" href="../spec/record.html?id=SWS_CORE_01172">[SWS_CORE_01172]</a>) are available for this purpose, both of which are specified as <code>constexpr noexcept</code>.</li>
    <li><strong>Dereferencing and access:</strong> When the state is assured, the reference can be accessed via <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_01169" href="../spec/record.html?id=SWS_CORE_01169">[SWS_CORE_01169]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01170" href="../spec/record.html?id=SWS_CORE_01170">[SWS_CORE_01170]</a>) or members of the target object can be accessed directly via the arrow operator <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_01167" href="../spec/record.html?id=SWS_CORE_01167">[SWS_CORE_01167]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01168" href="../spec/record.html?id=SWS_CORE_01168">[SWS_CORE_01168]</a>). In addition, <code>value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01173" href="../spec/record.html?id=SWS_CORE_01173">[SWS_CORE_01173]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01174" href="../spec/record.html?id=SWS_CORE_01174">[SWS_CORE_01174]</a>) enables direct access to <code>T&amp;</code> and <code>const T&amp;</code>, respectively.</li>
    <li><strong>Fallback value:</strong> If a fallback value is required when no object is referenced, <code>value_or</code> (<a class="spec-record-ref" data-req="SWS_CORE_01175" href="../spec/record.html?id=SWS_CORE_01175">[SWS_CORE_01175]</a>) can be called to return either the value of the reference or a passed replacement value.</li>
    <li><strong>Release:</strong> If the reference is no longer valid or is to be reset, the instance is transitioned back to the disengaged state by means of <code>reset()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01165" href="../spec/record.html?id=SWS_CORE_01165">[SWS_CORE_01165]</a>).</li>
  </ul>

  <h4>Error Scenarios</h4>
  <p>Erroneous usages primarily arise from erroneous accesses to an uninitialized or empty object (precondition violation: <em>If *this does not contain a value</em>):</p>
  <ul>
    <li><strong>Triggering access violations:</strong> The unprotected call of the access method <code>value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01173" href="../spec/record.html?id=SWS_CORE_01173">[SWS_CORE_01173]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01174" href="../spec/record.html?id=SWS_CORE_01174">[SWS_CORE_01174]</a>) on a disengaged instance violates the precondition and leads to a <code>IsoStdBadOptionalAccessViolation</code>. The specification explicitly classifies the method as <em>not exception safe</em>.</li>
    <li><strong>Dereferencing without a value:</strong> For the operators <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_01169" href="../spec/record.html?id=SWS_CORE_01169">[SWS_CORE_01169]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01170" href="../spec/record.html?id=SWS_CORE_01170">[SWS_CORE_01170]</a>) and <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_01167" href="../spec/record.html?id=SWS_CORE_01167">[SWS_CORE_01167]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01168" href="../spec/record.html?id=SWS_CORE_01168">[SWS_CORE_01168]</a>) as well, the precondition is defined that a value must be contained. In the event of a violation, a <code>IsoStdBadOptionalAccessViolation</code> is also documented, although the operators are declared with <code>noexcept</code>.</li>
  </ul>
  <p>To avoid these error conditions, the caller must always check with <code>has_value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_01172" href="../spec/record.html?id=SWS_CORE_01172">[SWS_CORE_01172]</a>) prior to dereferencing or resort to the safe alternative <code>value_or</code> (<a class="spec-record-ref" data-req="SWS_CORE_01175" href="../spec/record.html?id=SWS_CORE_01175">[SWS_CORE_01175]</a>).</p>
