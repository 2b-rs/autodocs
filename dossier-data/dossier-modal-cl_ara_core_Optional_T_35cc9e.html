<p class="ai-level ai-oneliner-lead" data-ai-level="1">Kapselt eine optionale Referenz auf ein Objekt und ermöglicht sicheren Zugriff ohne dynamische Speicherallokation.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Spezialisierung <code>ara::core::Optional&lt;T &amp;&gt;</code> dient als typsicherer Behälter für optionale Lvalue-Referenzen mit dem Elementtyp <code>T &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_01151" href="../spec/record.html?id=SWS_CORE_01151">[SWS_CORE_01151]</a>. Sie ermöglicht das Neubelegen oder Zurücksetzen des Verweises zur Laufzeit ohne dynamische Speicherallokation <a class="spec-record-ref" data-req="SWS_CORE_01164" href="../spec/record.html?id=SWS_CORE_01164">[SWS_CORE_01164]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01165" href="../spec/record.html?id=SWS_CORE_01165">[SWS_CORE_01165]</a>. Vor jedem Zugriff über Dereferenzierungsoperatoren oder die potentiell fehlerwerfende Zugriffsmethode <code>value()</code> ist das Vorhandensein eines gültigen Zielobjekts zwingend zu überprüfen <a class="spec-record-ref" data-req="SWS_CORE_01172" href="../spec/record.html?id=SWS_CORE_01172">[SWS_CORE_01172]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01173" href="../spec/record.html?id=SWS_CORE_01173">[SWS_CORE_01173]</a>.</p>
<p class="ai-level-more-inline"><button type="button" class="ai-level-step ai-level-more" data-ai-level-step="1" title="Ausführlichere Fassung zeigen">mehr ›</button></p>
</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Template-Spezialisierung <code>ara::core::Optional&lt;T &amp;&gt;</code> stellt einen typsicheren Behälter für eine optionale Lvalue-Referenz bereit. Der zugrunde liegende Elementtyp wird durch den Typalias <code>value_type</code> als <code>T &amp;</code> festgelegt <a class="spec-record-ref" data-req="SWS_CORE_01151" href="../spec/record.html?id=SWS_CORE_01151">[SWS_CORE_01151]</a>. Im Unterschied zur primären Schablone für Werttypen dient diese Spezialisierung als wiederverwendbare, neu bindbare Referenz (Rebindable Reference), die entweder auf ein existierendes Objekt vom Typ <code>T</code> verweist oder einen unbesetzten Zustand repräsentiert. Sie interagiert direkt mit aufrufenden Softwarekomponenten und dem referenzierten Zielobjekt, ohne dynamischen Speicher zu belegen.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Optional&lt;T &amp;&gt;</code> befindet sich stets in einem von zwei wohlkontrollierten Zuständen: <em>Leer</em> (nicht belegt) oder <em>Belegt</em> (referenziert ein Objekt). Der leere Zustand wird über den Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_01152" href="../spec/record.html?id=SWS_CORE_01152">[SWS_CORE_01152]</a> oder die Initialisierung mit <code>nullopt_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01153" href="../spec/record.html?id=SWS_CORE_01153">[SWS_CORE_01153]</a> eingenommen. Die Bindung an eine Referenz erfolgt bei der Konstruktion durch Übergabe eines kompatiblen Werts oder einer Referenz <a class="spec-record-ref" data-req="SWS_CORE_01156" href="../spec/record.html?id=SWS_CORE_01156">[SWS_CORE_01156]</a> sowie über Konvertierungskonstruktoren <a class="spec-record-ref" data-req="SWS_CORE_01157" href="../spec/record.html?id=SWS_CORE_01157">[SWS_CORE_01157]</a>. Kopier- und Verschiebekonstruktoren übertragen den Zustand des Quellbehälters <a class="spec-record-ref" data-req="SWS_CORE_01154" href="../spec/record.html?id=SWS_CORE_01154">[SWS_CORE_01154]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01155" href="../spec/record.html?id=SWS_CORE_01155">[SWS_CORE_01155]</a>.</p>

<p>Zur Laufzeit kann der Zustand dynamisch modifiziert werden: Die Zuweisung eines Werts oder einer Referenz bindet das <code>Optional</code> neu an das übergebene Zielobjekt <a class="spec-record-ref" data-req="SWS_CORE_01162" href="../spec/record.html?id=SWS_CORE_01162">[SWS_CORE_01162]</a>, was auch über Zuweisungsoperatoren anderer <code>Optional</code>-Behälter <a class="spec-record-ref" data-req="SWS_CORE_01159" href="../spec/record.html?id=SWS_CORE_01159">[SWS_CORE_01159]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01160" href="../spec/record.html?id=SWS_CORE_01160">[SWS_CORE_01160]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01163" href="../spec/record.html?id=SWS_CORE_01163">[SWS_CORE_01163]</a> oder die Methode <code>emplace</code> <a class="spec-record-ref" data-req="SWS_CORE_01164" href="../spec/record.html?id=SWS_CORE_01164">[SWS_CORE_01164]</a> geschieht. Ein Übergang in den leeren Zustand erfolgt über den Aufruf von <code>reset</code> <a class="spec-record-ref" data-req="SWS_CORE_01165" href="../spec/record.html?id=SWS_CORE_01165">[SWS_CORE_01165]</a> oder durch Zuweisung von <code>nullopt_t</code> <a class="spec-record-ref" data-req="SWS_CORE_01161" href="../spec/record.html?id=SWS_CORE_01161">[SWS_CORE_01161]</a>. Ferner gestattet <code>swap</code> das atomare Vertauschen zweier Instanzen <a class="spec-record-ref" data-req="SWS_CORE_01166" href="../spec/record.html?id=SWS_CORE_01166">[SWS_CORE_01166]</a>. Der Standarddestruktor beendet die Lebensdauer der Wrapper-Instanz <a class="spec-record-ref" data-req="SWS_CORE_01158" href="../spec/record.html?id=SWS_CORE_01158">[SWS_CORE_01158]</a>, berührt dabei aber vermutlich nicht das referenzierte Originalobjekt, da eine Referenz semantisch keinen Besitz begründet. <a class="interp-q interp-q-open" data-q="Q-3ba25e19c4b098ed" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-3ba25e19c4b098ed" title="Frage Q-3ba25e19c4b098ed (offen): Die Zerstörung des Wrappers zerstört nicht das referenzierte Zielobjekt">Frage Q-3ba25e19c4b098ed (offen)</a></p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Anwendungszyklus umfasst die Erzeugung, Validierung und den lesenden oder modifizierenden Zugriff auf das referenzierte Ziel:</p>
<ol>
  <li><strong>Initialisierung:</strong> Eine Instanz wird leer erzeugt <a class="spec-record-ref" data-req="SWS_CORE_01152" href="../spec/record.html?id=SWS_CORE_01152">[SWS_CORE_01152]</a> oder mit der Referenz auf ein bestehendes Objekt belegt <a class="spec-record-ref" data-req="SWS_CORE_01156" href="../spec/record.html?id=SWS_CORE_01156">[SWS_CORE_01156]</a>.</li>
  <li><strong>Zustandsprüfung:</strong> Vor der Dereferenzierung prüft der Aufrufer das Vorhandensein eines Verweises über den expliziten Konvertierungsoperator <code>operator bool</code> <a class="spec-record-ref" data-req="SWS_CORE_01171" href="../spec/record.html?id=SWS_CORE_01171">[SWS_CORE_01171]</a> oder die Methode <code>has_value</code> <a class="spec-record-ref" data-req="SWS_CORE_01172" href="../spec/record.html?id=SWS_CORE_01172">[SWS_CORE_01172]</a>.</li>
  <li><strong>Zugriff:</strong> Bei bestätigtem Verweis erfolgt der Zugriff auf das referenzierte Objekt über die Dereferenzierungsoperatoren <code>operator*</code> <a class="spec-record-ref" data-req="SWS_CORE_01169" href="../spec/record.html?id=SWS_CORE_01169">[SWS_CORE_01169]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01170" href="../spec/record.html?id=SWS_CORE_01170">[SWS_CORE_01170]</a> oder den Pfeil-Operator <code>operator-&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_01167" href="../spec/record.html?id=SWS_CORE_01167">[SWS_CORE_01167]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01168" href="../spec/record.html?id=SWS_CORE_01168">[SWS_CORE_01168]</a>. Alternativ liefert <code>value_or</code> den referenzierten Wert oder einen angegebenen Standardwert zurück <a class="spec-record-ref" data-req="SWS_CORE_01175" href="../spec/record.html?id=SWS_CORE_01175">[SWS_CORE_01175]</a>.</li>
  <li><strong>Rücksetzen:</strong> Nach Abschluss der Verarbeitung wird der Verweis bei Bedarf über <code>reset</code> explizit entfernt <a class="spec-record-ref" data-req="SWS_CORE_01165" href="../spec/record.html?id=SWS_CORE_01165">[SWS_CORE_01165]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Fehler treten primär bei vorzeitigen oder unzulässigen Zugriffsversuchen auf leere Instanzen auf. Wird <code>value()</code> aufgerufen, während das Objekt keinen Wert enthält, wird eine Verletzung des Typs <code>IsoStdBadOption-alAccessViolation</code> ausgelöst <a class="spec-record-ref" data-req="SWS_CORE_01173" href="../spec/record.html?id=SWS_CORE_01173">[SWS_CORE_01173]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01174" href="../spec/record.html?id=SWS_CORE_01174">[SWS_CORE_01174]</a>. Dementsprechend ist <code>value()</code> im Gegensatz zu den meisten anderen Operationen der Klasse explizit nicht als ausnahmesicher (<em>not exception safe</em>) eingestuft.</p>

<p>Auch die direkten Dereferenzierungen mittels <code>operator*</code> <a class="spec-record-ref" data-req="SWS_CORE_01169" href="../spec/record.html?id=SWS_CORE_01169">[SWS_CORE_01169]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01170" href="../spec/record.html?id=SWS_CORE_01170">[SWS_CORE_01170]</a> sowie <code>operator-&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_01167" href="../spec/record.html?id=SWS_CORE_01167">[SWS_CORE_01167]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01168" href="../spec/record.html?id=SWS_CORE_01168">[SWS_CORE_01168]</a> dokumentieren eine Verletzung der Kategorie <code>IsoStdBadOption-alAccessViolation</code>, falls die Instanz keinen Verweis hält. Obwohl diese Operatoren mit <code>noexcept</code> deklariert sind, verlangt ihre Nutzung zwingend die Einhaltung der Vorbedingung, dass ein gültiger Verweis existiert.</p>
