<h4>Context</h4>
<p>
Within the module <code>shwa</code>, the class <code>ara::shwa::DeviceSelector</code> provides an abstract interface for strategies for selecting and evaluating hardware or sensor/actuator devices (<code>Device</code>). As an interface definition, it acts as a link between application components or hardware managers and concrete selection implementations. According to the functional descriptions, a <code>DeviceSelector</code> evaluates or selects devices according to a defined selector strategy (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>). Due to its design as an abstract base class with pure virtual methods, applications can encapsulate and interchangeably integrate custom evaluation or assignment strategies.
</p>

<h4>Lifecycle</h4>
<p>
Because <code>ara::shwa::DeviceSelector</code> declares pure virtual functions, the class cannot be directly instantiated. Concrete implementations must be derived from it. The destructor is virtual and declared with <code>noexcept = default</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00402" href="../spec/record.html?id=AP_SWS_SHWA_00402">[AP_SWS_SHWA_00402]</a>). This ensures that derived instances can be safely destroyed via pointers or references to the base class without causing resource leaks or undefined behavior. Destruction is exception-safe (<em>exception safe</em>) (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00402" href="../spec/record.html?id=AP_SWS_SHWA_00402">[AP_SWS_SHWA_00402]</a>).
</p>
<p>
With regard to concurrency, the evaluating calls <code>SelectDevice</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>) and <code>operator()</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>) are specified as <em>not thread-safe</em>. If multiple threads access the same selector instance in parallel, the necessary synchronization is therefore the responsibility of the caller.
</p>

<h4>Usage Path</h4>
<p>
The interface supports two typical usage patterns for device selection:
</p>
<ul>
<li><strong>Direct selection:</strong> Calling <code>SelectDevice()</code> directly determines and returns a reference to a selected <code>Device</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>). This path is used when the selector itself knows or manages the inventory of available devices and autonomously selects the most suitable device.</li>
<li><strong>Evaluation of individual devices (functor):</strong> Via the call operator <code>operator()(const Device&amp; device)</code>, a concrete device is passed and evaluated with an integer score (<code>int</code>) based on the selector strategy (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>). This enables its use in filter, sort, or predicate functions, for example when an external list of devices is evaluated step by step.</li>
</ul>
<p>
A typical flow for selecting a device comprises providing a derived selector instance, calling <code>SelectDevice()</code>, checking the <code>ara::core::Result</code> for success, and subsequently using the selected device.
</p>

<h4>Error Scenarios</h4>
<p>
Both selection methods return results in the error protection type <code>ara::core::Result</code> and are declared as <code>noexcept</code> (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>). They offer exception safety (<em>exception safe</em>) and possess no rollback semantics (<em>no_rollback_semantics</em>). The following error codes from the context <code>ShwaErrorCode</code> are specified for <code>SelectDevice</code> and <code>operator()</code>:
</p>
<ul>
<li><code>ShwaErrorCode::kResourceBusy</code>: Execution could not be performed because a required resource is currently occupied (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>). In this case, the caller can retry the operation after a wait time or fall back on alternative resources.</li>
<li><code>ShwaErrorCode::kFeatureNotSupported</code>: The requested feature or specific selection requirement is not supported (<a class="spec-record-ref" data-req="AP_SWS_SHWA_00403" href="../spec/record.html?id=AP_SWS_SHWA_00403">[AP_SWS_SHWA_00403]</a>, <a class="spec-record-ref" data-req="AP_SWS_SHWA_00404" href="../spec/record.html?id=AP_SWS_SHWA_00404">[AP_SWS_SHWA_00404]</a>).</li>
</ul>
<p>
Before accessing the selected <code>Device</code> or the evaluation score, the caller must always ensure via <code>HasValue()</code> that the operation was successful.
</p>
