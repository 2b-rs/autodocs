<div class="ai-level" data-ai-level="2">
<p>Der Intrusion Detection System Manager erfasst als zentraler Plattformdienst sicherheitsrelevante Ereignisse von funktionalen Clustern und Anwendungen über standardisierte Instanzen der Klasse <a class="spec-record-ref" data-req="SWS_AIDSM_10101" href="../spec/record.html?id=SWS_AIDSM_10101">[SWS_AIDSM_10101]</a> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-3385240044ff428e.html" data-snip="FIG-3385240044ff428e">AUTOSAR_AP_EXP_SWArchitecture S. 124</a>. Eingehende Meldungen können mit Zeitstempeln und Kontextdaten angereichert, gefiltert und als qualifizierte Sicherheitsereignisse an autorisierte Empfänger weitergeleitet werden <a class="spec-record-ref" data-req="SWS_AIDSM_10800" href="../spec/record.html?id=SWS_AIDSM_10800">[SWS_AIDSM_10800]</a>. Die Anbindung aller Schnittstellen und Ereignis-IDs erfordert eine konsistente Modellierung über das AUTOSAR-Manifest <a class="docref internal-spec-ref" href="../../spec/figures/FIG-5c37527c55b50d06.html" data-snip="FIG-5c37527c55b50d06">AUTOSAR_AP_TPS_ManifestSpecification S. 257</a>.</p>

<div class="ai-level" data-ai-level="3">
<p>Der Intrusion Detection System Manager (IdsM) fungiert in der AUTOSAR Adaptive Platform als zentraler daemon-basierter Functional Cluster zur Aggregation, Filterung und Bewertung sicherheitsrelevanter Ereignisse <a class="docref internal-spec-ref" href="../../spec/figures/FIG-4ae7357b99bb35fe.html" data-snip="FIG-4ae7357b99bb35fe">AUTOSAR_AP_EXP_PlatformDesign S. 95</a>. Sowohl funktionale Cluster wie Communication Management, Firewall und Diagnostic Management als auch anwendungsspezifische Komponenten melden Sicherheitsvorfälle threadsicher über standardisierte Instanzen der Klasse <a class="spec-record-ref" data-req="SWS_AIDSM_10101" href="../spec/record.html?id=SWS_AIDSM_10101">[SWS_AIDSM_10101]</a> an den IdsM <a class="docref internal-spec-ref" href="../../spec/figures/FIG-2b75259e9d1b0547.html" data-snip="FIG-2b75259e9d1b0547">AUTOSAR_AP_SWS_IntrusionDetectionSystemManager S. 13</a>.</p>

<h4>Rolle und Systemgrenzen des Intrusion Detection System Manager</h4>
<p>Der Intrusion Detection System Manager (IdsM) bildet die zentrale Plattforminstanz zur Erfassung, Vorfilterung und Qualifizierung sicherheitsrelevanter Ereignisse (Security Events) auf einer AUTOSAR Adaptive Platform <a class="docref internal-spec-ref" href="../../spec/figures/FIG-4ae7357b99bb35fe.html" data-snip="FIG-4ae7357b99bb35fe">AUTOSAR_AP_EXP_PlatformDesign S. 95</a>. Gemäß den Cybersicherheitsanforderungen der ISO/SAE 21434 fungiert der IdsM auf POSIX-basierten Steuergeräten als eigenständiger Hintergrunddienst (daemon-based Functional Cluster) <a class="docref internal-spec-ref" href="../../spec/figures/FIG-3385240044ff428e.html" data-snip="FIG-3385240044ff428e">AUTOSAR_AP_EXP_SWArchitecture S. 124</a>. Seine Kernaufgabe besteht darin, Anomalien und potenzielle Angriffsversuche zu sammeln, anhand konfigurierter Regeln wie Ratenbegrenzungen oder Schwellwerten zu bewerten und zu qualifizierten Sicherheitsereignissen (Qualified Security Events) zusammenzuführen <a class="docref internal-spec-ref" href="../../spec/figures/FIG-155f243b5b6ee2c7.html" data-snip="FIG-155f243b5b6ee2c7">AUTOSAR_EXP_SWArchitecture S. 97</a>.</p>

<p>Die Architektur des IdsM ist auf Interoperabilität mit anderen funktionalen Clustern ausgelegt. Plattformdienste wie Communication Management <a class="docref internal-spec-ref" href="../../spec/figures/FIG-8913c2072a6e4e17.html" data-snip="FIG-8913c2072a6e4e17">AUTOSAR_AP_SWS_CommunicationManagement S. 34</a>, Firewall <a class="docref internal-spec-ref" href="../../spec/figures/FIG-581fe21980f174e8.html" data-snip="FIG-581fe21980f174e8">AUTOSAR_AP_SWS_Firewall S. 11</a> und Diagnostic Management <a class="docref internal-spec-ref" href="../../spec/figures/FIG-28c2b84cdf772200.html" data-snip="FIG-28c2b84cdf772200">AUTOSAR_AP_SWS_Diagnostics S. 67</a> sowie anwendungsspezifische Prozesse fungieren als Security-Sensoren <a class="docref internal-spec-ref" href="../../spec/figures/FIG-2b75259e9d1b0547.html" data-snip="FIG-2b75259e9d1b0547">AUTOSAR_AP_SWS_IntrusionDetectionSystemManager S. 13</a>. Die nachfolgende Übersicht veranschaulicht die Einbettung des IdsM-Daemons in das Laufzeitumfeld der Adaptive Platform.</p>

<h4>Ereignismeldung über EventReporter und Interaktionsformen</h4>
<p>Die primäre Eingangs-Schnittstelle zur Übermittlung von Sicherheitsvorfällen wird durch die Klasse <a class="spec-record-ref" data-req="SWS_AIDSM_10101" href="../spec/record.html?id=SWS_AIDSM_10101">[SWS_AIDSM_10101]</a> realisiert. Eine meldende Einheit instanziiert diese Klasse unter Angabe eines definierten Ports mittels <code>ara::core::InstanceSpecifier</code> threadsicher über den Konstruktor <a class="spec-record-ref" data-req="SWS_AIDSM_10301" href="../spec/record.html?id=SWS_AIDSM_10301">[SWS_AIDSM_10301]</a>. Hierdurch wird die Anbindung an das im Manifest definierte <code>SecurityEventReportInterface</code> hergestellt <a class="docref internal-spec-ref" href="../../spec/figures/FIG-5c37527c55b50d06.html" data-snip="FIG-5c37527c55b50d06">AUTOSAR_AP_TPS_ManifestSpecification S. 257</a>. Die eigentliche Übermittlung erfolgt über überladene Varianten der synchronen Methode <code>ReportEvent</code>, die jeweils threadsicher ausgeführt werden können <a class="spec-record-ref" data-req="SWS_AIDSM_10302" href="../spec/record.html?id=SWS_AIDSM_10302">[SWS_AIDSM_10302]</a>.</p>

<p>Abhängig von der Art des Ereignisses und den verfügbaren Sensordaten bietet die Schnittstelle abgestufte Meldeformen. Die Basismethode übermittelt lediglich eine Wiederholungsanzahl vom Typ <a class="spec-record-ref" data-req="SWS_AIDSM_10203" href="../spec/record.html?id=SWS_AIDSM_10203">[SWS_AIDSM_10203]</a> (Standardwert 1) ohne weitere Metadaten <a class="spec-record-ref" data-req="SWS_AIDSM_10302" href="../spec/record.html?id=SWS_AIDSM_10302">[SWS_AIDSM_10302]</a>. Für zeitkritische Vorgänge kann ein sensorspezifischer Zeitstempel vom Typ <a class="spec-record-ref" data-req="SWS_AIDSM_10202" href="../spec/record.html?id=SWS_AIDSM_10202">[SWS_AIDSM_10202]</a> direkt mitgegeben werden <a class="spec-record-ref" data-req="SWS_AIDSM_10303" href="../spec/record.html?id=SWS_AIDSM_10303">[SWS_AIDSM_10303]</a>. Zudem lassen sich unveränderliche Nutzdaten als Byte-Span vom Typ <a class="spec-record-ref" data-req="SWS_AIDSM_10201" href="../spec/record.html?id=SWS_AIDSM_10201">[SWS_AIDSM_10201]</a> entweder allein <a class="spec-record-ref" data-req="SWS_AIDSM_10304" href="../spec/record.html?id=SWS_AIDSM_10304">[SWS_AIDSM_10304]</a> oder kombiniert mit Zeitstempel übergeben <a class="spec-record-ref" data-req="SWS_AIDSM_10305" href="../spec/record.html?id=SWS_AIDSM_10305">[SWS_AIDSM_10305]</a>. Für strukturierte Ereignisformate existieren Überladungen mit versionierten Kontextdaten vom Typ <a class="spec-record-ref" data-req="SWS_AIDSM_10206" href="../spec/record.html?id=SWS_AIDSM_10206">[SWS_AIDSM_10206]</a>, die ein Wertepaar aus Kontextdaten-Span und einem 16-Bit-Versionsindikator darstellen <a class="spec-record-ref" data-req="SWS_AIDSM_10306" href="../spec/record.html?id=SWS_AIDSM_10306">[SWS_AIDSM_10306]</a>, optional ergänzt um einen expliziten Zeitstempel <a class="spec-record-ref" data-req="SWS_AIDSM_10307" href="../spec/record.html?id=SWS_AIDSM_10307">[SWS_AIDSM_10307]</a>.</p>

<p>Ein typisches Szenario für diesen Meldepfad ist das Verwerfen unzulässiger Netzwerkpakete durch den TCP/IP-Stack und die Firewall: Das Betriebssystem meldet blockierte Pakete an den Firewall-Daemon, welcher daraufhin unverzüglich <code>ReportEvent</code> aufruft <a class="docref internal-spec-ref" href="../../spec/figures/FIG-b1273965639f62af.html" data-snip="FIG-b1273965639f62af">AUTOSAR_AP_EXP_SWArchitecture S. 232</a>. <h4>Erweiterte Kontextdaten und Zeitstempel über Provider-Schnittstellen</h4>
<p>Um meldende Prozesse nicht mit aufwendigen Zeitabfragen oder statischen Kontextinformationen zu belasten, unterstützt die Architektur eine Kontrollfluss-Inversion über Provider-Schnittstellen <a class="docref internal-spec-ref" href="../../spec/figures/FIG-ddfa8a49650771f4.html" data-snip="FIG-ddfa8a49650771f4">AUTOSAR_AP_EXP_SWArchitecture S. 122</a>. Anwendungen können als Zeitstempel-Dienstleister agieren, indem sie von der abstrakten Klasse <a class="spec-record-ref" data-req="SWS_AIDSM_10400" href="../spec/record.html?id=SWS_AIDSM_10400">[SWS_AIDSM_10400]</a> ableiten. Nach der Instanziierung über den Konstruktor <a class="spec-record-ref" data-req="SWS_AIDSM_10401" href="../spec/record.html?id=SWS_AIDSM_10401">[SWS_AIDSM_10401]</a> schaltet die Anwendung den Dienst mit <code>Offer()</code> aktiv <a class="spec-record-ref" data-req="SWS_AIDSM_10408" href="../spec/record.html?id=SWS_AIDSM_10408">[SWS_AIDSM_10408]</a>. Ab diesem Zeitpunkt kann der IdsM bei Bedarf die reine virtuelle Methode <code>GetTimestamp()</code> aufrufen, um den aktuellen Zeitwert abzufragen <a class="spec-record-ref" data-req="SWS_AIDSM_10407" href="../spec/record.html?id=SWS_AIDSM_10407">[SWS_AIDSM_10407]</a>. Die Bereitstellung wird mit <code>StopOffer()</code> beendet <a class="spec-record-ref" data-req="SWS_AIDSM_10409" href="../spec/record.html?id=SWS_AIDSM_10409">[SWS_AIDSM_10409]</a>.</p>

<p>In analoger Weise ermöglicht die Basisklasse <a class="spec-record-ref" data-req="SWS_AIDSM_10500" href="../spec/record.html?id=SWS_AIDSM_10500">[SWS_AIDSM_10500]</a> die dynamische Anreicherung oder Modifikation von Kontextdaten. Der Konstruktor erwartet neben dem <code>InstanceSpecifier</code> die Größenangabe zusätzlicher Bytes sowie den Offset für die ursprünglichen Kontextdaten <a class="spec-record-ref" data-req="SWS_AIDSM_10501" href="../spec/record.html?id=SWS_AIDSM_10501">[SWS_AIDSM_10501]</a>. Nach Freigabe durch <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10507" href="../spec/record.html?id=SWS_AIDSM_10507">[SWS_AIDSM_10507]</a> ruft der IdsM-Daemon bei Ereigniseingang die Methode <code>ModifyContextData</code> auf <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>. Hierbei wird ein beschreibbarer Byte-Span übergeben, in den die Anwendung modifizierte Daten schreibt und die resultierende Datengröße als <code>ara::core::Result&lt;std::size_t&gt;</code> zurückmeldet <a class="spec-record-ref" data-req="SWS_AIDSM_10509" href="../spec/record.html?id=SWS_AIDSM_10509">[SWS_AIDSM_10509]</a>. Mit <code>StopOffer()</code> wird die Entgegennahme weiterer Modifikationsanfragen deaktiviert <a class="spec-record-ref" data-req="SWS_AIDSM_10508" href="../spec/record.html?id=SWS_AIDSM_10508">[SWS_AIDSM_10508]</a>.</p>

<h4>Manifest-Modellierung, Port-Bindung und Deployment</h4>
<p>Die Einbindung aller Schnittstellen in das Gesamtsystem erfolgt deklarativ über das AUTOSAR-Manifest. Das Reporting wird über ein <code>SecurityEventReportInterface</code> modelliert, welches über ein <code>SecurityEventReportToSecurityEventDefinitionMapping</code> mit einer formalen <code>SecurityEventDefinition</code> verknüpft wird <a class="docref internal-spec-ref" href="../../spec/figures/FIG-a73c343dfcc20c83.html" data-snip="FIG-a73c343dfcc20c83">AUTOSAR_AP_TPS_ManifestSpecification S. 146</a>. Diese explizite Entkopplung gestattet es, standardisierte Software-Komponenten wiederzuverwenden und projektspezifische Ereignis-IDs erst auf Konfigurationsebene zuzuordnen <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_PLATFORM_FIGURE_Figure_3_35_MANIFESTSPECIFICATION.html" data-snip="SNIP_ADAPTIVE_PLATFORM_FIGURE_Figure_3_35_MANIFESTSPECIFICATION">TPS_ManifestSpecification S. 146</a>.</p>

<h4>Verhalten im Fehlerfall und Diagnosebehandlung</h4>
<p>Fehlersituationen innerhalb des IdsM-Moduls werden nach dem standardisierten AUTOSAR-Fehlerbehandlungskonzept über die Fehlerdomäne <a class="spec-record-ref" data-req="SWS_AIDSM_10706" href="../spec/record.html?id=SWS_AIDSM_10706">[SWS_AIDSM_10706]</a> abgewickelt. Diese wird über die globale Funktion <code>GetIdsmErrorDomain()</code> referenziert <a class="spec-record-ref" data-req="SWS_AIDSM_10702" href="../spec/record.html?id=SWS_AIDSM_10702">[SWS_AIDSM_10702]</a>. Konkrete API-Fehler werden durch die Enumeration <a class="spec-record-ref" data-req="SWS_AIDSM_10204" href="../spec/record.html?id=SWS_AIDSM_10204">[SWS_AIDSM_10204]</a> (Alias <a class="spec-record-ref" data-req="SWS_AIDSM_10707" href="../spec/record.html?id=SWS_AIDSM_10707">[SWS_AIDSM_10707]</a>) repräsentiert. Tritt beispielsweise beim Abfragen oder Setzen eines Reporting-Modus eine unbekannte Ereignis-ID auf, geben die Operationen <code>GetReportingMode</code> und <code>SetReportingMode</code> ein fehlerhaftes <code>ara::core::Result</code> mit dem Code <code>IdsmErrc::kUnknownEventId</code> zurück <a class="spec-record-ref" data-req="SWS_AIDSM_10602" href="../spec/record.html?id=SWS_AIDSM_10602">[SWS_AIDSM_10602]</a>, <a class="spec-record-ref" data-req="SWS_AIDSM_10603" href="../spec/record.html?id=SWS_AIDSM_10603">[SWS_AIDSM_10603]</a>.</p>

<p>Zur Umwandlung in strukturierte Fehlerobjekte dient die Hilfsfunktion <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10703" href="../spec/record.html?id=SWS_AIDSM_10703">[SWS_AIDSM_10703]</a>. Die Fehlerdomäne implementiert die Schnittstellen zur Abfrage des Domänennamens <a class="spec-record-ref" data-req="SWS_AIDSM_10710" href="../spec/record.html?id=SWS_AIDSM_10710">[SWS_AIDSM_10710]</a> sowie der beschreibenden Textmeldung <a class="spec-record-ref" data-req="SWS_AIDSM_10711" href="../spec/record.html?id=SWS_AIDSM_10711">[SWS_AIDSM_10711]</a>. Sofern Ausnahmen im System aktiviert sind, kann ein Fehlercode über <code>ThrowAsException</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10712" href="../spec/record.html?id=SWS_AIDSM_10712">[SWS_AIDSM_10712]</a> als Ausnahme vom Typ <a class="spec-record-ref" data-req="SWS_AIDSM_10704" href="../spec/record.html?id=SWS_AIDSM_10704">[SWS_AIDSM_10704]</a> (Alias <a class="spec-record-ref" data-req="SWS_AIDSM_10708" href="../spec/record.html?id=SWS_AIDSM_10708">[SWS_AIDSM_10708]</a>) geworfen werden, deren Konstruktor den zugrundeliegenden <code>ErrorCode</code> kapselt <a class="spec-record-ref" data-req="SWS_AIDSM_10705" href="../spec/record.html?id=SWS_AIDSM_10705">[SWS_AIDSM_10705]</a>.</p>
