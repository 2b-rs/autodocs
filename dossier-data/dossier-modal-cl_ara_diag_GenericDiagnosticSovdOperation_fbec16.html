<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht Anwendungen die Bearbeitung und Beantwortung generischer SOVD-Operationsanfragen des Diagnostic Managers.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Basisklasse dient der Implementierung generischer SOVD-Operationshandler zur Bearbeitung von Ausführungsanforderungen im Diagnostic Management <a class="spec-record-ref" data-req="SWS_DM_02203" href="../spec/record.html?id=SWS_DM_02203">[SWS_DM_02203]</a>. Nach der Instanziierung aktiviert die Anwendung den Empfang über <code>Offer()</code>, woraufhin der Diagnostic Manager eingehende Anfragen über die asynchrone Schnittstelle <code>StartExecution</code> weiterleitet <a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a> <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>. Übergebene Inhaltsdaten und der Abbruch-Handler sind strikt an die Dauer der Operation gebunden <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::GenericDiagnosticSovdOperation</code> stellt eine generische Schnittstelle für die Ausführung von Operationen im Rahmen von ASAM SOVD (Service-Oriented Vehicle Diagnostics) bereit <a class="spec-record-ref" data-req="SWS_DM_02203" href="../spec/record.html?id=SWS_DM_02203">[SWS_DM_02203]</a>. Sie fungiert als Bindeglied zwischen der diagnostischen Plattform und der anwendungsspezifischen Implementierung diagnostischer Routinen oder Aktionen. Wenn ein externer SOVD-Client eine Operationsausführung anfordert, stellt die Instanz des Diagnostic Server die entsprechende SOVD-Methode bereit <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=217">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 „Operations – Start execution of an operation“</a> <a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>. Sobald die Autorisierung beziehungsweise die Überprüfung einer erforderlichen Proximity Challenge erfolgreich abgeschlossen ist, leitet der Diagnostic Manager (DM) den Aufruf an die Methode <code>StartExecution</code> der registrierten Handler-Instanz weiter <a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung einer Instanz erfolgt über den Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code>, der auf einen PortPrototype verweist, sowie eines Nebenläufigkeitstyps (<code>ConcurrencyType</code>) <a class="spec-record-ref" data-req="SWS_DM_02204" href="../spec/record.html?id=SWS_DM_02204">[SWS_DM_02204]</a>. Da Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_02206" href="../spec/record.html?id=SWS_DM_02206">[SWS_DM_02206]</a> und Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_02207" href="../spec/record.html?id=SWS_DM_02207">[SWS_DM_02207]</a> als <code>protected</code> deklariert sind, ist die Klasse als Basisklasse für abgeleitete anwendungsspezifische Handler konzipiert. Nach der Instanziierung befindet sich das Objekt im inaktiven Zustand und nimmt keine Anfragen entgegen. Über <code>Offer()</code> wird die Weiterleitung von Anfragen durch den Diagnostic Manager aktiviert <a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>. Mit <code>StopOffer()</code> kann diese Weiterleitung wieder deaktiviert werden <a class="spec-record-ref" data-req="SWS_DM_02212" href="../spec/record.html?id=SWS_DM_02212">[SWS_DM_02212]</a>. Beim Abbau der Instanz sorgt der virtuelle Destruktor für eine ordnungsgemäße Bereinigung <a class="spec-record-ref" data-req="SWS_DM_02205" href="../spec/record.html?id=SWS_DM_02205">[SWS_DM_02205]</a>. Konstruktor, Destruktor und Move-Operationen sind als threadsicher spezifiziert, während <code>Offer()</code> und <code>StopOffer()</code> nicht threadsicher sind und typischerweise während der Initialisierungs- oder Shutdown-Phase des Prozesses aufgerufen werden sollten.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst das Anbieten des Handlers, die Entgegennahme von Operationsanfragen sowie die asynchrone Bereitstellung der Antwort:</p>
<ol>
<li><strong>Dienst anbieten:</strong> Die Anwendung ruft <code>Offer()</code> auf, wodurch der Diagnostic Manager autorisiert wird, eingehende SOVD-Anfragen an das Objekt weiterzuleiten <a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>.</li>
<li><strong>Start der Operation:</strong> Nach Eintreffen der SOVD-Methode und bestandener Prüfung der Proximity Challenge ruft der DM die rein virtuelle Methode <code>StartExecution</code> auf <a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a> <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>. Dabei werden der Name der SOVD-Operation (<code>sovd_operation_name</code>), Nutzdaten (<code>sovd_content_data</code>), Metainformationen (<code>meta_info</code>) sowie ein <code>CancellationHandler</code> übergeben <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>.</li>
<li><strong>Ergebnisrückgabe:</strong> Die Methode liefert ein <code>ara::core::Future</code> zurück, das entweder eine synchrone Antwort (<code>StartSynchronousExecutionResponse</code>) oder eine asynchrone Antwort (<code>StartAsynchronousExecutionResponse</code>) enthält <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>. Bei einer synchronen Operation übernimmt der DM die Daten aus dem Ergebnis zur Erzeugung des SOVD-Response-Bodys <a class="spec-record-ref" data-req="SWS_DM_02176" href="../spec/record.html?id=SWS_DM_02176">[SWS_DM_02176]</a>.</li>
<li><strong>Dienst beenden:</strong> Vor der Zerstörung des Objekts beendet die Anwendung die Weiterleitung mittels <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_02212" href="../spec/record.html?id=SWS_DM_02212">[SWS_DM_02212]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Bei der Verwendung der Schnittstelle können administrative sowie protokollspezifische Fehler auftreten:</p>
<ul>
<li><strong>Bereits angeboten:</strong> Ein erneuter Aufruf von <code>Offer()</code> auf einer bereits angebotenen Instanz schlägt mit dem Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> fehl <a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>.</li>
<li><strong>SOVD-Fehler:</strong> Schlägt die Ausführung der Operation fehl, ist im <code>ara::core::Future</code> ein entsprechender negativer Antwortcode gemäß ISO 17978-3 bzw. ASAM SOVD 1.1 zurückzugeben <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>.</li>
<li><strong>Abbruch:</strong> Über das übergebene Objekt <code>cancellation_handler</code> wird die Anwendung benachrichtigt, falls die laufende Anforderung abgebrochen wird. Die Spezifikation untersagt ausdrücklich, diesen Handler über die Lebensdauer der laufenden Operation hinaus zu speichern oder darauf zuzugreifen <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>. Zudem bleiben die übergebenen Eingangsdaten in <code>sovd_content_data</code> nur gültig, bis das zugehörige Promise erfüllt oder die Verarbeitung abgebrochen wurde <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>.</li>
</ul>
