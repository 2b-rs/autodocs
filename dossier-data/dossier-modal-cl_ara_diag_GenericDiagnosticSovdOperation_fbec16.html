<h4>Context</h4>
<p>The class <code>ara::diag::GenericDiagnosticSovdOperation</code> defines the generic programming interface for executing SOVD operations (Service-Oriented Vehicle Diagnostics) within the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_DM_02203" href="../spec/record.html?id=SWS_DM_02203">[SWS_DM_02203]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=856">AUTOSAR_AP_SWS_Diagnostics §8.62.2 “Class: GenericDiagnosticSovdOperation”</a>). As a functional interface, it mediates between the server's internal Diagnostic Management (DM) and the specific routines of an Adaptive Application.</p>
<p>According to the specification, the server instance provides the “Start Execution of an Operation” method according to ASAM SOVD for configured SOVD operations (<a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>). If a corresponding request from an external SOVD client is received and any required proximity challenge is successfully verified (<a class="spec-record-ref" data-req="SWS_DM_02173" href="../spec/record.html?id=SWS_DM_02173">[SWS_DM_02173]</a>), the DM immediately delegates the call to the <code>StartExecution</code> method of the registered class instance (<a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=217">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operations – Start execution of an operation”</a>). The class thus acts as an application-side endpoint for processing parameterized diagnostic operations.</p>

<h4>Lifecycle</h4>
<p>The instantiation of <code>ara::diag::GenericDiagnosticSovdOperation</code> takes place via the constructor by specifying an <code>ara::core::InstanceSpecifier</code> and the concurrency model <code>ConcurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_02204" href="../spec/record.html?id=SWS_DM_02204">[SWS_DM_02204]</a>). Since the move constructor (<a class="spec-record-ref" data-req="SWS_DM_02206" href="../spec/record.html?id=SWS_DM_02206">[SWS_DM_02206]</a>) and move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_02207" href="../spec/record.html?id=SWS_DM_02207">[SWS_DM_02207]</a>) are declared as <code>protected</code> and the central execution method is pure virtual, the class is likely designed exclusively as a base class for derived, application-specific handlers.</p>
<p>After construction, the object initially remains inactive. Explicitly calling <code>Offer()</code> enables the forwarding of incoming SOVD requests by the DM to the instance (<a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>). If the service is no longer to be provided or shutdown of the application is pending, <code>StopOffer()</code> disables forwarding again (<a class="spec-record-ref" data-req="SWS_DM_02212" href="../spec/record.html?id=SWS_DM_02212">[SWS_DM_02212]</a>). Upon destruction via the virtual destructor (<a class="spec-record-ref" data-req="SWS_DM_02205" href="../spec/record.html?id=SWS_DM_02205">[SWS_DM_02205]</a>), all bindings must be properly dismantled. With regard to thread safety, <code>Offer()</code> and <code>StopOffer()</code> are specified as not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>, <a class="spec-record-ref" data-req="SWS_DM_02212" href="../spec/record.html?id=SWS_DM_02212">[SWS_DM_02212]</a>), while the execution method <code>StartExecution</code> and the destructor are designed to be thread-safe (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>, <a class="spec-record-ref" data-req="SWS_DM_02205" href="../spec/record.html?id=SWS_DM_02205">[SWS_DM_02205]</a>).</p>

<h4>Usage Path</h4>
<p>The regular sequence comprises provision, processing of a diagnostic request, and subsequent deregistration:</p>
<ol>
  <li><strong>Instantiation and registration:</strong> The derived class is instantiated by specifying the target port prototype (<a class="spec-record-ref" data-req="SWS_DM_02204" href="../spec/record.html?id=SWS_DM_02204">[SWS_DM_02204]</a>). Subsequently, the application activates message processing using <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>).</li>
  <li><strong>Incoming request:</strong> An SOVD client initiates an execution via the DM (<a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>). After checking any access conditions, the DM calls <code>StartExecution</code> (<a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>, <a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>).</li>
  <li><strong>Processing:</strong> The application receives the operation name <code>sovd_operation_name</code>, the payload <code>sovd_content_data</code>, additional information <code>meta_info</code>, and a <code>cancellation_handler</code> (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>). The payload remains valid until the returned <code>ara::core::Promise</code> is fulfilled or the operation is cancelled.</li>
  <li><strong>Result return:</strong> The operation returns a <code>ara::core::Future</code> that contains a variant of <code>StartSynchronousExecutionResponse</code> or <code>StartAsynchronousExecutionResponse</code> (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>). In the case of synchronous processing, the DM uses this to formulate the response data for the SOVD client (<a class="spec-record-ref" data-req="SWS_DM_02176" href="../spec/record.html?id=SWS_DM_02176">[SWS_DM_02176]</a>).</li>
  <li><strong>Deregistration:</strong> Before termination, the application calls <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_02212" href="../spec/record.html?id=SWS_DM_02212">[SWS_DM_02212]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error states can occur both during service registration and during operation processing:</p>
<ul>
  <li><strong>Service readiness:</strong> If <code>Offer()</code> is called even though the handler is already registered, the call fails and returns the error <code>DiagOfferErrc::kAlreadyOffered</code> with rollback semantics (<a class="spec-record-ref" data-req="SWS_DM_02211" href="../spec/record.html?id=SWS_DM_02211">[SWS_DM_02211]</a>).</li>
  <li><strong>Operation failure:</strong> If an operation cannot be executed successfully, the returned <code>ara::core::Future</code> is to be completed with a corresponding SOVD error code according to ISO 17978-3 or ASAM SOVD 1.1 (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>).</li>
  <li><strong>Cancellation condition:</strong> If an ongoing operation is canceled, the DM signals this via the passed <code>cancellation_handler</code> object (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>). This object must not be stored or used beyond the lifetime of the operation (<a class="spec-record-ref" data-req="SWS_DM_02210" href="../spec/record.html?id=SWS_DM_02210">[SWS_DM_02210]</a>).</li>
</ul>
