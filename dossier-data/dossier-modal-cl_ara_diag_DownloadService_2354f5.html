  <h4>Context</h4>
  <p>In the module <code>diag</code> of the AUTOSAR Adaptive Platform, the class <code>ara::diag::DownloadService</code> provides the central C++ interface for handling diagnostic downloads <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=74">AUTOSAR_AP_SWS_Diagnostics, p. 74</a>. It serves as an application-side service handler that encapsulates download operations for a specific diagnostic interface. The primary interaction takes place between the AUTOSAR Diagnostic Management (DM) and the concrete application implementation. Interpretation: The Diagnostic Management receives UDS requests from an external diagnostic tester in accordance with ISO 14229-1 and forwards them to the instance as soon as the service is offered.</p>
  <p>After activation via <code>Offer()</code>, the class acts as an interface for the standardized phases of a diagnostic download: request (RequestDownload), segmented data transfer (TransferData via <code>DownloadData</code>), and completion (RequestTransferExit via <code>RequestDownloadExit</code>). The application implements the pure virtual methods <a class="spec-record-ref" data-req="SWS_DM_00789" href="../spec/record.html?id=SWS_DM_00789">[SWS_DM_00789]</a>, <a class="spec-record-ref" data-req="SWS_DM_00790" href="../spec/record.html?id=SWS_DM_00790">[SWS_DM_00790]</a>, and <a class="spec-record-ref" data-req="SWS_DM_00791" href="../spec/record.html?id=SWS_DM_00791">[SWS_DM_00791]</a> to receive, verify, and store data blocks in the target memory.</p>

  <h4>Lifecycle</h4>
  <p>An instance of <code>DownloadService</code> is created via the constructor <code>DownloadService(const ara::core::InstanceSpecifier&amp;, ConcurrencyType)</code> <a class="spec-record-ref" data-req="SWS_DM_00787" href="../spec/record.html?id=SWS_DM_00787">[SWS_DM_00787]</a>. The <code>InstanceSpecifier</code> links the instance to a <code>PortPrototype</code> of an <code>DiagnosticDownloadInterface</code> defined in the design model. Via the argument <code>concurrencyType</code>, it is specified whether the implemented service methods are called concurrently (<code>kConcurrent</code>) or non-concurrently (<code>kNotConcurrent</code>), which forms the specification for the thread safety of the application logic <a class="spec-record-ref" data-req="SWS_DM_00787" href="../spec/record.html?id=SWS_DM_00787">[SWS_DM_00787]</a>. The constructor itself is implemented in a thread-safe manner.</p>
  <p>With regard to ownership and copy semantics, <code>DownloadService</code> is designed as unique: both copy constructor <a class="spec-record-ref" data-req="SWS_DM_01649" href="../spec/record.html?id=SWS_DM_01649">[SWS_DM_01649]</a> and assignment operator <a class="spec-record-ref" data-req="SWS_DM_01647" href="../spec/record.html?id=SWS_DM_01647">[SWS_DM_01647]</a> as well as move constructor <a class="spec-record-ref" data-req="SWS_DM_01650" href="../spec/record.html?id=SWS_DM_01650">[SWS_DM_01650]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01648" href="../spec/record.html?id=SWS_DM_01648">[SWS_DM_01648]</a> are deleted (<code>delete</code>).</p>
  <p>The operational lifecycle is divided into the following states and transitions:</p>
  <ul>
    <li><strong>Instantiated (inactive):</strong> After construction, the instance is ready, but does not yet forward any diagnostic requests.</li>
    <li><strong>Offered (active):</strong> The call to <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00792" href="../spec/record.html?id=SWS_DM_00792">[SWS_DM_00792]</a> authorizes the DM to forward incoming diagnostic download requests to the virtual handler methods of the instance.</li>
    <li><strong>Stopped:</strong> By means of <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00793" href="../spec/record.html?id=SWS_DM_00793">[SWS_DM_00793]</a>, the forwarding of requests is deactivated; the instance returns to the inactive state.</li>
    <li><strong>Destruction:</strong> The virtual destructor <code>~DownloadService()</code> <a class="spec-record-ref" data-req="SWS_DM_00788" href="../spec/record.html?id=SWS_DM_00788">[SWS_DM_00788]</a> releases the resources. Since the destructor is not thread-safe, the service should be stopped beforehand.</li>
  </ul>

  <h4>Usage Path</h4>
  <p>After successful instantiation and offering via <code>Offer()</code>, a download process typically goes through three sequential steps via asynchronous interface calls:</p>
  <ol>
    <li><strong>Download initialization (RequestDownload):</strong> The DM calls <code>RequestDownload(...)</code> <a class="spec-record-ref" data-req="SWS_DM_00789" href="../spec/record.html?id=SWS_DM_00789">[SWS_DM_00789]</a>. The data format identifier (<code>dataFormatIdentifier</code>), the address and length format (<code>addressAndLengthFormatIdentifier</code>), the target address and size as a byte span (<code>memoryAddressAndSize</code>), as well as <code>metaInfo</code> and a <code>cancellationHandler</code> are passed. The data in <code>memoryAddressAndSize</code> remains valid until the associated promise is fulfilled or processing is canceled. The method returns a <code>ara::core::Future&lt;void&gt;</code>, which is successfully provided upon positive validation.</li>
    <li><strong>Blockwise data transfer (DownloadData):</strong> For each subsequent transfer request, the DM calls <code>DownloadData(...)</code> <a class="spec-record-ref" data-req="SWS_DM_00790" href="../spec/record.html?id=SWS_DM_00790">[SWS_DM_00790]</a>. The payload is passed in <code>transferRequestParameterRecord</code>. The application processes the data and signals the result via a <code>ara::core::Future&lt;OperationOutput&gt;</code>. Data in <code>OperationOutput.responseData</code> is placed after the block sequence counter in the positive UDS response.</li>
    <li><strong>Transfer completion (RequestDownloadExit):</strong> To terminate the download, the DM calls <code>RequestDownloadExit(...)</code> <a class="spec-record-ref" data-req="SWS_DM_00791" href="../spec/record.html?id=SWS_DM_00791">[SWS_DM_00791]</a>. After a final integrity check (e.g., checksum validation), the application returns a <code>ara::core::Future&lt;OperationOutput&gt;</code> whose optional response data is placed after the service ID.</li>
  </ol>
  <p>All three methods receive a <code>cancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_00789" href="../spec/record.html?id=SWS_DM_00789">[SWS_DM_00789]</a>. Via <code>cancellationHandler.IsCanceled()</code>, the application can check the cancellation status; with <code>cancellationHandler.SetNotifier(...)</code>, a callback can be registered to react immediately to a cancellation of the diagnostic conversation. Interpretation: In the event of a premature cancellation, the application terminates internal buffering and cancels ongoing write operations.</p>

  <h4>Error Scenarios</h4>
  <p>Errors can occur during creation and configuration as well as during service provision and data processing:</p>
  <ul>
    <li><strong>Modeling and initialization errors:</strong> Modeling violations can be triggered during constructor invocation <a class="spec-record-ref" data-req="SWS_DM_00787" href="../spec/record.html?id=SWS_DM_00787">[SWS_DM_00787]</a>:
      <ul>
        <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The <code>InstanceSpecifier</code> cannot be resolved in the model within the execution context or does not reference a <code>PortPrototype</code>.</li>
        <li><code>PortInterfaceMappingViolation</code>: A <code>PortPrototype</code> typed with <code>DiagnosticDownloadInterface</code> is not mapped to a <code>DiagnosticServiceGenericMapping</code> in a type-compliant manner.</li>
        <li><code>ProcessMappingViolation</code>: No matching modeled <code>Process</code> exists for the <code>InstanceRef</code>.</li>
        <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The <code>InstanceSpecifier</code> is already used by another instance within this process.</li>
      </ul>
    </li>
    <li><strong>Error when offering the service:</strong> A repeated call to <code>Offer()</code> when the service is already offered fails and returns the error code <code>DiagOfferErrc::kAlreadyOffered</code> <a class="spec-record-ref" data-req="SWS_DM_00792" href="../spec/record.html?id=SWS_DM_00792">[SWS_DM_00792]</a>.</li>
