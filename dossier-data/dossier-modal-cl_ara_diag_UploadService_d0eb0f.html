<h4>Context</h4>
<p>The class <code>ara::diag::UploadService</code> represents the functional service interface for upload diagnostic services within the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>). It acts as a standardized handler in the header <code>ara/diag/upload.h</code> to which the central Diagnostic Management daemon (DM) forwards incoming UDS diagnostic requests (<a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>).</p>
<p>In the diagnostic architecture, three essential roles interact in the context of the upload service:</p>
<ul>
<li><strong>External diagnostic tester / client:</strong> Initiates the upload transaction via the standardized Unified Diagnostic Services protocol (ISO 14229-1), requests data blocks step by step, and completes the transfer (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>, <a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>).</li>
<li><strong>Diagnostic Management (DM):</strong> Receives and validates the transport and session parameters at platform level, determines the responsible port, and delegates the functional execution to the registered instance of <code>ara::diag::UploadService</code> (<a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>).</li>
<li><strong>Application-specific handler:</strong> A concrete derivation of <code>ara::diag::UploadService</code> that reads out, segments, and provides the requested memory areas as response data at the application level (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>, <a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The instantiation of <code>ara::diag::UploadService</code> takes place explicitly via binding to a modeled interface port using <code>ara::core::InstanceSpecifier</code> and specifying the concurrency behavior via the parameter <code>concurrencyType</code> (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>). The class has strict singleton or unique semantics per port: Both the copy and move constructors as well as all assignment operators are deleted (<code>=delete</code>), so that an instance can neither be copied nor moved (<a class="spec-record-ref" data-req="SWS_DM_01671" href="../spec/record.html?id=SWS_DM_01671">[SWS_DM_01671]</a>, <a class="spec-record-ref" data-req="SWS_DM_01672" href="../spec/record.html?id=SWS_DM_01672">[SWS_DM_01672]</a>, <a class="spec-record-ref" data-req="SWS_DM_01673" href="../spec/record.html?id=SWS_DM_01673">[SWS_DM_01673]</a>, <a class="spec-record-ref" data-req="SWS_DM_01674" href="../spec/record.html?id=SWS_DM_01674">[SWS_DM_01674]</a>).</p>
<p>After successful construction, the object initially remains in the inactive state (stopped). The method call <code>Offer()</code> signals to the DM that the handler is ready and requests may be forwarded from now on (<a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>). Forwarding can be suspended at any time by <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00803" href="../spec/record.html?id=SWS_DM_00803">[SWS_DM_00803]</a>). Calling <code>StopOffer()</code> before destroying the object is likely recommended in practice (interpretation) in order to prevent hanging calls during shutdown. The instance is released via the virtual destructor <code>~UploadService()</code> (<a class="spec-record-ref" data-req="SWS_DM_00798" href="../spec/record.html?id=SWS_DM_00798">[SWS_DM_00798]</a>).</p>
<p>With regard to concurrency, the constructor is thread-safe (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>). In contrast, <code>Offer()</code>, <code>StopOffer()</code>, and the destructor are specified as not thread-safe (<code>not thread-safe</code>) and must therefore not be called concurrently in an uncoordinated manner (<a class="spec-record-ref" data-req="SWS_DM_00798" href="../spec/record.html?id=SWS_DM_00798">[SWS_DM_00798]</a>, <a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>, <a class="spec-record-ref" data-req="SWS_DM_00803" href="../spec/record.html?id=SWS_DM_00803">[SWS_DM_00803]</a>). The thread safety of the handler methods themselves depends conditionally on the selected <code>ConcurrencyType</code> (<code>kConcurrent</code> or <code>kNotConcurrent</code>) (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>, <a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>, <a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>).</p>

<h4>Usage Path</h4>
<p>A typical use case comprises the step-by-step processing of a complete UDS upload transaction:</p>
<ol>
<li><strong>Offering:</strong> The application instance calls <code>Offer()</code> to activate the forwarding of requests by the DM (<a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>).</li>
<li><strong>Start of the upload session (RequestUpload):</strong> As soon as a UDS request is received, the DM calls the method <code>RequestUpload()</code> (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>). The application evaluates <code>dataFormatIdentifier</code>, <code>addressAndLengthFormatIdentifier</code>, and the content of <code>memoryAddressAndSize</code>. The referenced memory data remains valid until the returned <code>ara::core::Future&lt;void&gt;</code> is fulfilled or the execution is canceled via the passed <code>CancellationHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>).</li>
<li><strong>Blockwise data transfer (UploadData):</strong> The DM repeatedly calls <code>UploadData()</code> in a loop (<a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>). Via the parameter <code>numBytesToReturn</code>, the DM signals the maximum buffer capacity for this block. The application asynchronously returns a <code>ara::core::Future&lt;OperationOutput&gt;</code>. The format of the payload data in <code>OperationOutput.responseData</code> is presumably subject to application-specific agreements (interpretation), since the specification merely specifies that this data is placed directly after the UDS Block Sequence Counter (<a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>).</li>
<li><strong>Ending the session (RequestUploadExit):</strong> Finally, the DM calls <code>RequestUploadExit()</code> and passes manufacturer-specific parameters in the <code>transferRequestParameterRecord</code> (<a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>). After confirmation by the returned <code>ara::core::Future&lt;OperationOutput&gt;</code>, the transfer is complete.</li>
</ol>
<p>During all processing steps, the application can check via the <code>CancellationHandler</code> using <code>IsCanceled()</code> whether the conversation was canceled, or configure a callback for the cancellation via <code>SetNotifier()</code> (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>, <a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>).</p>

<h4>Error Scenarios</h4>
<p>Errors can occur both during instantiation and offering as well as during functional request processing:</p>
<ul>
<li><strong>Modeling and mapping violations:</strong> When the constructor is called, the consistency of the model is validated (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>). If the resolution of the <code>InstanceSpecifier</code> fails or it does not point to a <code>PortPrototype</code>, an <code>InstanceSpecifierMappingIntegrityViolation</code> is raised. An <code>PortInterfaceMappingViolation</code> occurs if the port typed by <code>DiagnosticUploadInterface</code> is not referenced by an <code>DiagnosticServiceGenericMapping</code>. If the mapping to the runtime process is missing, an <code>ProcessMappingViolation</code> follows. If the same <code>InstanceSpecifier</code> is used multiple times in the process, this results in an <code>InstanceSpecifierAlreadyInUseViolation</code> (<a class="spec-record-ref" data-req="SWS_DM_00797" href="../spec/record.html?id=SWS_DM_00797">[SWS_DM_00797]</a>).</li>
<li><strong>State error during registration:</strong> If <code>Offer()</code> is called while the service is already being offered, the call fails and returns the error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_00802" href="../spec/record.html?id=SWS_DM_00802">[SWS_DM_00802]</a>).</li>
<li><strong>Negative diagnostic responses (NRC):</strong> If the application cannot serve a request in <code>RequestUpload()</code>, <code>UploadData()</code>, or <code>RequestUploadExit()</code> positively (e.g. invalid address range or invalid block length), the returned future is not fulfilled with a regular result, but readied with a corresponding UDS NRC error code from <code>DiagUdsNrcErrc</code> according to ISO 14229-1 (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>, <a class="spec-record-ref" data-req="SWS_DM_00800" href="../spec/record.html?id=SWS_DM_00800">[SWS_DM_00800]</a>, <a class="spec-record-ref" data-req="SWS_DM_00801" href="../spec/record.html?id=SWS_DM_00801">[SWS_DM_00801]</a>).</li>
<li><strong>Premature cancellation:</strong> If the client or the system cancels the diagnostic conversation, this is signaled via the <code>CancellationHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_00799" href="../spec/record.html?id=SWS_DM_00799">[SWS_DM_00799]</a>). The application must then discard ongoing preparations and terminate processing.</li>
</ul>
