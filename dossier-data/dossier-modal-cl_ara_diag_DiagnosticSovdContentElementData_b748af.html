<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::DiagnosticSovdContentElementData</code> dient als vielseitiger Datencontainer zur Repräsentation strukturierter SOVD-Diagnoseinhalte in der AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_02307" href="../spec/record.html?id=SWS_DM_02307">[SWS_DM_02307]</a>. Sie kapselt primitive Typen, Arrays sowie schlüsselbasierte Records, die über statische Fabrikmethoden erzeugt und modular zusammengestellt werden. Operationen werden über <code>ara::core::Result</code> typsicher abgesichert und melden bei Typkonflikten oder ungültigen Schlüsseln Fehlerzustände zurück <a class="spec-record-ref" data-req="SWS_DM_02317" href="../spec/record.html?id=SWS_DM_02317">[SWS_DM_02317]</a>. Alle Zugriffe sind als thread-safe spezifiziert, setzen jedoch die strikte Einhaltung der typgebundenen Schnittstellenregeln voraus.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::DiagnosticSovdContentElementData</code> repräsentiert innerhalb der AUTOSAR Adaptive Platform Dateninhalte von SOVD-Elementen (Service-Oriented Vehicle Diagnostics) <a class="spec-record-ref" data-req="SWS_DM_02307" href="../spec/record.html?id=SWS_DM_02307">[SWS_DM_02307]</a>. Diagnoseressourcen werden nach ASAM SOVD als strukturierte Daten modelliert, die aus einzelnen oder aggregierten Inhaltselementen bestehen (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=205">AUTOSAR_AP_SWS_Diagnostics, S. 205</a>).</p>
<p>Der Diagnostic Management Dämon (DM) nutzt die Schnittstelle <code>ara::diag::GenericDiagnosticSovdContent</code>, um Diagnosedaten bei Methodenaufrufen wie <em>Read a data resource</em> <a class="spec-record-ref" data-req="SWS_DM_01432" href="../spec/record.html?id=SWS_DM_01432">[SWS_DM_01432]</a> oder <em>Write a data resource</em> <a class="spec-record-ref" data-req="SWS_DM_01431" href="../spec/record.html?id=SWS_DM_01431">[SWS_DM_01431]</a>, <a class="spec-record-ref" data-req="SWS_DM_02166" href="../spec/record.html?id=SWS_DM_02166">[SWS_DM_02166]</a> zu verarbeiten. <code>DiagnosticSovdContentElementData</code> fungiert hierbei als generischer Container zur Kapselung typisierter Diagnoseinhalte zwischen dem DM und den implementierenden Diagnoseanwendungen (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=206">AUTOSAR_AP_SWS_Diagnostics, S. 206</a>).</p>

<h4>Lebenszyklus</h4>
<p>Objekte von <code>DiagnosticSovdContentElementData</code> werden über statische Fabrikmethoden instanziiert, die die zugrunde liegende Datenvariante und den Inhaltstyp festlegen <a class="spec-record-ref" data-req="SWS_DM_02315" href="../spec/record.html?id=SWS_DM_02315">[SWS_DM_02315]</a>. Die Klasse bildet vermutlich ein variantenbasiertes Strukturmuster ab (Interpretation: Die separaten Fabriken und typgebundenen Prüfungen deuten auf eine interne Union- oder Tagged-Variant-Struktur hin), bei dem eine Instanz entweder ein Primitiv, ein Array oder ein Record ist.</p>
<p>Zur Erzeugung primitiver Elemente stehen typisierte Konstruktionsmethoden bereit:</p>
<ul>
  <li>Ganzzahlen: <code>CreatePrimitiveContentSignedInt</code> <a class="spec-record-ref" data-req="SWS_DM_02308" href="../spec/record.html?id=SWS_DM_02308">[SWS_DM_02308]</a> und <code>CreatePrimitiveContentUnsignedInt</code> <a class="spec-record-ref" data-req="SWS_DM_02309" href="../spec/record.html?id=SWS_DM_02309">[SWS_DM_02309]</a>,</li>
  <li>Fließkommazahlen: <code>CreatePrimitiveContentDouble</code> <a class="spec-record-ref" data-req="SWS_DM_02310" href="../spec/record.html?id=SWS_DM_02310">[SWS_DM_02310]</a>,</li>
  <li>Booleans: <code>CreatePrimitiveContentBool</code> <a class="spec-record-ref" data-req="SWS_DM_02311" href="../spec/record.html?id=SWS_DM_02311">[SWS_DM_02311]</a>,</li>
  <li>Zeichenketten: <code>CreatePrimitiveContentString</code> <a class="spec-record-ref" data-req="SWS_DM_02312" href="../spec/record.html?id=SWS_DM_02312">[SWS_DM_02312]</a>.</li>
</ul>
<p>Zusammengesetzte Typen werden über <code>CreateArrayContentElement</code> <a class="spec-record-ref" data-req="SWS_DM_02313" href="../spec/record.html?id=SWS_DM_02313">[SWS_DM_02313]</a> für Sequenzen oder <code>CreateRecordContentElement</code> <a class="spec-record-ref" data-req="SWS_DM_02314" href="../spec/record.html?id=SWS_DM_02314">[SWS_DM_02314]</a> für Schlüssel-Wert-Strukturen erzeugt. Der Destruktor verwaltet die Freigabe und unterstützt Move- sowie Copy-Operationen <a class="spec-record-ref" data-req="SWS_DM_02316" href="../spec/record.html?id=SWS_DM_02316">[SWS_DM_02316]</a>. Während Konstruktions- und speicherallokierende Schreiboperationen als nicht ausnahmesicher deklariert sind, sind lesende Zugriffe und Destruktion ausnahmesicher sowie die Methodenaufrufe laut Spezifikation thread-safe.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Ablauf umfasst das Erzeugen, schrittweise Befüllen und anschließende Auslesen strukturierter Datenelemente. Soll beispielsweise ein diagnostischer Datensatz aufgebaut werden, erzeugt die Anwendung zunächst eine Record-Instanz über <code>CreateRecordContentElement</code> <a class="spec-record-ref" data-req="SWS_DM_02314" href="../spec/record.html?id=SWS_DM_02314">[SWS_DM_02314]</a>.</p>
<p>Anschließend werden Felder mit eindeutigem Schlüssel über überladene <code>Add</code>-Methoden registriert, etwa für primitive Ganzzahlen <a class="spec-record-ref" data-req="SWS_DM_02368" href="../spec/record.html?id=SWS_DM_02368">[SWS_DM_02368]</a>, Zeichenketten <a class="spec-record-ref" data-req="SWS_DM_02372" href="../spec/record.html?id=SWS_DM_02372">[SWS_DM_02372]</a> oder geschachtelte Unterelemente <a class="spec-record-ref" data-req="SWS_DM_02373" href="../spec/record.html?id=SWS_DM_02373">[SWS_DM_02373]</a>. Vor dem lesenden Zugriff kann das Vorhandensein eines Feldes mit <code>HasContentElement</code> geprüft werden <a class="spec-record-ref" data-req="SWS_DM_02364" href="../spec/record.html?id=SWS_DM_02364">[SWS_DM_02364]</a>, ehe der Zugriff über <code>Find</code> <a class="spec-record-ref" data-req="SWS_DM_02365" href="../spec/record.html?id=SWS_DM_02365">[SWS_DM_02365]</a> oder den Index-Operator <a class="spec-record-ref" data-req="SWS_DM_02357" href="../spec/record.html?id=SWS_DM_02357">[SWS_DM_02357]</a> erfolgt. Für Listen werden analog Elemente per <code>PushBack</code> angehängt <a class="spec-record-ref" data-req="SWS_DM_02346" href="../spec/record.html?id=SWS_DM_02346">[SWS_DM_02346]</a>, <a class="spec-record-ref" data-req="SWS_DM_02351" href="../spec/record.html?id=SWS_DM_02351">[SWS_DM_02351]</a> und über Iteratoren durchlaufen <a class="spec-record-ref" data-req="SWS_DM_02341" href="../spec/record.html?id=SWS_DM_02341">[SWS_DM_02341]</a>, <a class="spec-record-ref" data-req="SWS_DM_02342" href="../spec/record.html?id=SWS_DM_02342">[SWS_DM_02342]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Fehlerhafte Operationen werden über den Rückgabetyp <code>ara::core::Result</code> angezeigt. Typverletzungen führen zu Fehlern, wenn typspezifische Methoden auf unpassenden Varianten aufgerufen werden – beispielsweise Array-Operationen wie <code>Capacity</code> <a class="spec-record-ref" data-req="SWS_DM_02336" href="../spec/record.html?id=SWS_DM_02336">[SWS_DM_02336]</a> oder <code>Clear</code> <a class="spec-record-ref" data-req="SWS_DM_02338" href="../spec/record.html?id=SWS_DM_02338">[SWS_DM_02338]</a> auf Record- oder Primitiv-Instanzen.</p>
<p>Ebenso schlagen Zugriffe auf nicht vorhandene Schlüssel bei <code>Find</code> <a class="spec-record-ref" data-req="SWS_DM_02365" href="../spec/record.html?id=SWS_DM_02365">[SWS_DM_02365]</a> oder <code>Remove</code> <a class="spec-record-ref" data-req="SWS_DM_02367" href="../spec/record.html?id=SWS_DM_02367">[SWS_DM_02367]</a> fehl. Bei fehlerhaften Eingabewerten wird in spezifischen Fällen der Fehlercode <code>DiagErrc::kInvalidArgument</code> zurückgeliefert <a class="spec-record-ref" data-req="SWS_DM_02327" href="../spec/record.html?id=SWS_DM_02327">[SWS_DM_02327]</a>, <a class="spec-record-ref" data-req="SWS_DM_02337" href="../spec/record.html?id=SWS_DM_02337">[SWS_DM_02337]</a>, <a class="spec-record-ref" data-req="SWS_DM_02344" href="../spec/record.html?id=SWS_DM_02344">[SWS_DM_02344]</a>. Zusätzlich erlaubt die Klasse, ein Element gezielt als fehlerhaft zu markieren: Mittels <code>SetError</code> wird ein <code>ara::core::ErrorCode</code> hinterlegt <a class="spec-record-ref" data-req="SWS_DM_02318" href="../spec/record.html?id=SWS_DM_02318">[SWS_DM_02318]</a>, was nachfolgend über <code>HasError</code> verifiziert werden kann <a class="spec-record-ref" data-req="SWS_DM_02317" href="../spec/record.html?id=SWS_DM_02317">[SWS_DM_02317]</a>.</p>
