<div class="ai-level" data-ai-level="2">
<p>Der NVRAM Manager (NvM) ist der einzige Zugang zum nichtflüchtigen Speicher. Er kopiert NVRAM-Blöcke implizit zwischen RAM und NV-Speicher <a class="spec-record-ref" data-req="SWS_NvM_00038" href="../../spec/record.html?id=SWS_NvM_00038">[SWS_NvM_00038]</a>. Beim Start füllt das vom BswM angestoßene <code>NvM_ReadAll</code> die RAM-Blöcke, beim Shutdown sichert <code>NvM_WriteAll</code> geänderte Blöcke. Einzelaufträge wie <code>NvM_WriteBlock</code> werden asynchron eingereiht, priorisiert bearbeitet und per Status oder Callback quittiert <a class="spec-record-ref" data-req="SWS_NvM_00185" href="../../spec/record.html?id=SWS_NvM_00185">[SWS_NvM_00185]</a>. Lesefehler fängt der NvM über Wiederholungen, redundante Kopien und Defaultdaten ab; den Blockstatus müssen Anwender dennoch selbst prüfen.</p>

<div class="ai-level" data-ai-level="3">
<p>Der NVRAM Manager (NvM) ist der einzige Zugang zum nichtflüchtigen Speicher <a class="spec-record-ref" data-req="SWS_NvM_00384" href="../../spec/record.html?id=SWS_NvM_00384">[SWS_NvM_00384]</a>. Er kopiert Blöcke implizit zwischen NVRAM und RAM; die Anwendung arbeitet direkt mit den RAM-Daten <a class="spec-record-ref" data-req="SWS_NvM_00038" href="../../spec/record.html?id=SWS_NvM_00038">[SWS_NvM_00038]</a>. Nach unten nutzt er die Memory Abstraction Interface mit Fee bzw. Ea <a class="spec-record-ref" data-req="SWS_NvM_00051" href="../../spec/record.html?id=SWS_NvM_00051">[SWS_NvM_00051]</a>. Zustände meldet er an den BswM, Fehler an DEM und DET <a class="spec-record-ref" data-req="SWS_NvM_00745" href="../../spec/record.html?id=SWS_NvM_00745">[SWS_NvM_00745]</a> <a class="spec-record-ref" data-req="SWS_NvM_00592" href="../../spec/record.html?id=SWS_NvM_00592">[SWS_NvM_00592]</a>.</p>

Den RAM-Block gleicht der NvM implizit direkt ab oder explizit über einen RAM-Mirror mit Callbacks <a class="spec-record-ref" data-req="SWS_NvM_00511" href="../../spec/record.html?id=SWS_NvM_00511">[SWS_NvM_00511]</a>.</p>
<p>Der Lebenszyklus verläuft in drei Schritten:</p>
<ul>
<li>Der BswM ruft <code>NvM_Init</code> exklusiv auf <a class="spec-record-ref" data-req="SWS_NvM_00693" href="../../spec/record.html?id=SWS_NvM_00693">[SWS_NvM_00693]</a>.</li>
<li><code>NvM_ReadAll</code> prüft zuerst die Konfigurations-ID und füllt dann die RAM-Blöcke <a class="spec-record-ref" data-req="SWS_NvM_00073" href="../../spec/record.html?id=SWS_NvM_00073">[SWS_NvM_00073]</a> <a class="spec-record-ref" data-req="SWS_NvM_00718" href="../../spec/record.html?id=SWS_NvM_00718">[SWS_NvM_00718]</a>.</li>
<li>Zum Shutdown sichert <code>NvM_WriteAll</code> geänderte Blöcke <a class="spec-record-ref" data-req="SWS_NvM_00092" href="../../spec/record.html?id=SWS_NvM_00092">[SWS_NvM_00092]</a>. <code>NvM_CancelWriteAll</code> bricht nicht-destruktiv ab <a class="spec-record-ref" data-req="SWS_NvM_00238" href="../../spec/record.html?id=SWS_NvM_00238">[SWS_NvM_00238]</a>.</li>
</ul>
<p>Einzelaufträge wie <code>NvM_WriteBlock</code> werden eingereiht und stehen danach auf <code>NVM_REQ_PENDING</code> <a class="spec-record-ref" data-req="SWS_NvM_00185" href="../../spec/record.html?id=SWS_NvM_00185">[SWS_NvM_00185]</a>. Optional nutzt der NvM eine eigene Warteschlange für Immediate-Aufträge <a class="spec-record-ref" data-req="SWS_NvM_00378" href="../../spec/record.html?id=SWS_NvM_00378">[SWS_NvM_00378]</a>. Das Ergebnis liefert <code>NvM_GetErrorStatus</code> oder ein konfigurierter Callback <a class="spec-record-ref" data-req="SWS_NvM_00015" href="../../spec/record.html?id=SWS_NvM_00015">[SWS_NvM_00015]</a> <a class="spec-record-ref" data-req="SWS_NvM_00740" href="../../spec/record.html?id=SWS_NvM_00740">[SWS_NvM_00740]</a>.</p>

<h4>Rolle im Speicherstack: einziger Zugang zum nichtflüchtigen Speicher</h4>
<p>Der NVRAM Manager (NvM) bündelt den Zugriff auf nichtflüchtige Daten. Die Umgebung spricht den nichtflüchtigen Speicher ausschließlich über den NvM an, der dafür eine Callback-Schnittstelle bereitstellt <a class="spec-record-ref" data-req="SWS_NvM_00384" href="../../spec/record.html?id=SWS_NvM_00384">[SWS_NvM_00384]</a>. Der Zugriff ist implizit: Der NvM kopiert Blöcke zwischen NVRAM und gemeinsam genutztem RAM. Die Anwendung arbeitet unter Beachtung von Synchronisationsregeln direkt mit den RAM-Daten <a class="spec-record-ref" data-req="SWS_NvM_00038" href="../../spec/record.html?id=SWS_NvM_00038">[SWS_NvM_00038]</a> <a class="spec-record-ref" data-req="SWS_NvM_00692" href="../../spec/record.html?id=SWS_NvM_00692">[SWS_NvM_00692]</a>. Ein Block wird über seine konfigurierte Block-ID ausgewählt <a class="spec-record-ref" data-req="SWS_NvM_00069" href="../../spec/record.html?id=SWS_NvM_00069">[SWS_NvM_00069]</a> <a class="spec-record-ref" data-req="SWS_NvM_00471" href="../../spec/record.html?id=SWS_NvM_00471">[SWS_NvM_00471]</a>. Upper Layer binden dafür nur <code>NvM.h</code> ein <a class="spec-record-ref" data-req="SWS_NvM_00691" href="../../spec/record.html?id=SWS_NvM_00691">[SWS_NvM_00691]</a>. Das Schaubild zum impliziten Aktualisieren zeigt die Arbeitsteilung: Andere Teile der Basissoftware lösen das Sichern und Wiederherstellen aller Blöcke abhängig vom ECU-Zustand aus. Die SW-C greift nur auf den Inhalt ihrer RAM-Blöcke zu (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-aa99edecf6728f01.html" data-snip="FIG-aa99edecf6728f01">SWS NvM S. 121</a>).</p>
<p>Nach unten arbeitet der NvM gegen die Memory Abstraction Interface. Zusammen mit Fee bzw. Ea stellt sie einen virtuellen linearen 32-Bit-Adressraum bereit <a class="spec-record-ref" data-req="SWS_NvM_00051" href="../../spec/record.html?id=SWS_NvM_00051">[SWS_NvM_00051]</a> <a class="spec-record-ref" data-req="SWS_NvM_00465" href="../../spec/record.html?id=SWS_NvM_00465">[SWS_NvM_00465]</a>. Prüfsummen bildet der NvM über das Crc-Modul <a class="spec-record-ref" data-req="SWS_NvM_00466" href="../../spec/record.html?id=SWS_NvM_00466">[SWS_NvM_00466]</a>. Das Ende eines Lower-Layer-Jobs erfährt er auf zwei Wegen:</p>
<ul>
<li>per Polling über <code>MemIf_GetJobResult</code>,</li>
<li>bei abgeschaltetem Polling über <code>NvM_JobEndNotification</code> und <code>NvM_JobErrorNotification</code> <a class="spec-record-ref" data-req="SWS_NvM_00440" href="../../spec/record.html?id=SWS_NvM_00440">[SWS_NvM_00440]</a> <a class="spec-record-ref" data-req="SWS_NvM_00441" href="../../spec/record.html?id=SWS_NvM_00441">[SWS_NvM_00441]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_1_2_5_NVRAM_Manager.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_1_2_5_NVRAM_Manager">Error Description S. 43</a>).</li>
</ul>
<p>Produktionsfehler gehen an den DEM <a class="spec-record-ref" data-req="SWS_NvM_00592" href="../../spec/record.html?id=SWS_NvM_00592">[SWS_NvM_00592]</a>, Entwicklungsfehler an den DET <a class="spec-record-ref" data-req="SWS_NvM_00614" href="../../spec/record.html?id=SWS_NvM_00614">[SWS_NvM_00614]</a>. Auftragszustände meldet der NvM an den BswM <a class="spec-record-ref" data-req="SWS_NvM_00745" href="../../spec/record.html?id=SWS_NvM_00745">[SWS_NvM_00745]</a> <a class="spec-record-ref" data-req="SWS_NvM_00746" href="../../spec/record.html?id=SWS_NvM_00746">[SWS_NvM_00746]</a>.</p>

<h4>Aufbau eines NVRAM-Blocks und die drei Verwaltungstypen</h4>
<p>Ein NVRAM-Block besteht aus den Pflichtbestandteilen NV-Block, RAM-Block und Administrative Block. Ein ROM-Block mit Defaultdaten ist optional <a class="spec-record-ref" data-req="SWS_NvM_00138" href="../../spec/record.html?id=SWS_NvM_00138">[SWS_NvM_00138]</a> <a class="spec-record-ref" data-req="SWS_NvM_00139" href="../../spec/record.html?id=SWS_NvM_00139">[SWS_NvM_00139]</a> <a class="spec-record-ref" data-req="SWS_NvM_00020" href="../../spec/record.html?id=SWS_NvM_00020">[SWS_NvM_00020]</a>. Die Zusammensetzung legt der Blockdeskriptor zur Konfigurationszeit fest <a class="spec-record-ref" data-req="SWS_NvM_00140" href="../../spec/record.html?id=SWS_NvM_00140">[SWS_NvM_00140]</a>. Die einzelnen Bestandteile:</p>
<ul>
<li>Der NV-Block trägt die Nutzdaten sowie optional CRC und Header <a class="spec-record-ref" data-req="SWS_NvM_00125" href="../../spec/record.html?id=SWS_NvM_00125">[SWS_NvM_00125]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-3608b5aafa36a683.html" data-snip="FIG-3608b5aafa36a683">SWS NvM S. 39</a>).</li>
<li>Der RAM-Block darf ohne Adressbeschränkung im globalen RAM liegen <a class="spec-record-ref" data-req="SWS_NvM_00088" href="../../spec/record.html?id=SWS_NvM_00088">[SWS_NvM_00088]</a>.</li>
<li>Der Administrative Block ist für die Anwendung unsichtbar. Er hält den Datensatzindex, die Attribute und das Fehler-/Statusfeld <a class="spec-record-ref" data-req="SWS_NvM_00134" href="../../spec/record.html?id=SWS_NvM_00134">[SWS_NvM_00134]</a> <a class="spec-record-ref" data-req="SWS_NvM_00135" href="../../spec/record.html?id=SWS_NvM_00135">[SWS_NvM_00135]</a> <a class="spec-record-ref" data-req="SWS_NvM_00136" href="../../spec/record.html?id=SWS_NvM_00136">[SWS_NvM_00136]</a>.</li>
</ul>
<p>Der NvM unterstützt die Typen <code>NVM_BLOCK_NATIVE</code>, <code>NVM_BLOCK_REDUNDANT</code> und <code>NVM_BLOCK_DATASET</code> <a class="spec-record-ref" data-req="SWS_NvM_00137" href="../../spec/record.html?id=SWS_NvM_00137">[SWS_NvM_00137]</a>. Sie unterscheiden sich in der Zahl der NV- und ROM-Blöcke <a class="spec-record-ref" data-req="SWS_NvM_00557" href="../../spec/record.html?id=SWS_NvM_00557">[SWS_NvM_00557]</a> <a class="spec-record-ref" data-req="SWS_NvM_00558" href="../../spec/record.html?id=SWS_NvM_00558">[SWS_NvM_00558]</a> <a class="spec-record-ref" data-req="SWS_NvM_00559" href="../../spec/record.html?id=SWS_NvM_00559">[SWS_NvM_00559]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-7595a9284b6a80b7.html" data-snip="FIG-7595a9284b6a80b7">SWS NvM S. 10</a>). Bei Dataset-Blöcken gilt:</p>
<ul>
<li><code>NvM_SetDataIndex</code> wählt das Element. Indizes ab <code>NvMNvBlockNum</code> adressieren ROM-Blöcke <a class="spec-record-ref" data-req="SWS_NvM_00014" href="../../spec/record.html?id=SWS_NvM_00014">[SWS_NvM_00014]</a> <a class="spec-record-ref" data-req="SWS_NvM_00445" href="../../spec/record.html?id=SWS_NvM_00445">[SWS_NvM_00445]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_2_3_Dataset_NVRAM_block.html" data-snip="SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_2_3_Dataset_NVRAM_block">NV Data Handling S. 10</a>).</li>
<li>Der Index wird nicht persistent gespeichert; <code>NvM_Init</code> setzt ihn auf null <a class="spec-record-ref" data-req="SWS_NvM_00160" href="../../spec/record.html?id=SWS_NvM_00160">[SWS_NvM_00160]</a> <a class="spec-record-ref" data-req="SWS_NvM_00192" href="../../spec/record.html?id=SWS_NvM_00192">[SWS_NvM_00192]</a>.</li>
<li>Für das korrekte Setzen ist die SW-C verantwortlich <a class="spec-record-ref" data-req="SWS_NvM_00695" href="../../spec/record.html?id=SWS_NvM_00695">[SWS_NvM_00695]</a>.</li>
</ul>

<h4>Lebenszyklus: NvM_Init, NvM_ReadAll und NvM_WriteAll</h4>
<p>Der BswM ruft <code>NvM_Init</code> exklusiv auf <a class="spec-record-ref" data-req="SWS_NvM_00693" href="../../spec/record.html?id=SWS_NvM_00693">[SWS_NvM_00693]</a>. <code>NvM_Init</code> setzt Warteschlangen und Zustandsautomaten zurück und signalisiert intern „INIT DONE“ <a class="spec-record-ref" data-req="SWS_NvM_00399" href="../../spec/record.html?id=SWS_NvM_00399">[SWS_NvM_00399]</a>. Es initialisiert weder RAM-Blöcke noch unterlagerte Module <a class="spec-record-ref" data-req="SWS_NvM_00091" href="../../spec/record.html?id=SWS_NvM_00091">[SWS_NvM_00091]</a> <a class="spec-record-ref" data-req="SWS_NvM_00193" href="../../spec/record.html?id=SWS_NvM_00193">[SWS_NvM_00193]</a>. Der Konfigurationszeiger ist stets <code>NULL_PTR</code> <a class="spec-record-ref" data-req="SWS_NvM_00881" href="../../spec/record.html?id=SWS_NvM_00881">[SWS_NvM_00881]</a>. Erst danach verarbeitet <code>NvM_MainFunction</code> Aufträge <a class="spec-record-ref" data-req="SWS_NvM_00257" href="../../spec/record.html?id=SWS_NvM_00257">[SWS_NvM_00257]</a>.</p>
<p>Die RAM-Blöcke füllt anschließend <code>NvM_ReadAll</code> <a class="spec-record-ref" data-req="SWS_NvM_00718" href="../../spec/record.html?id=SWS_NvM_00718">[SWS_NvM_00718]</a>. Der Aufruf signalisiert den Auftrag nur. Die Bearbeitung wird zurückgestellt, bis die Einzelblockaufträge erledigt sind <a class="spec-record-ref" data-req="SWS_NvM_00243" href="../../spec/record.html?id=SWS_NvM_00243">[SWS_NvM_00243]</a>. Danach läuft der Job in drei Schritten:</p>
<ol>
<li>Zuerst vergleicht er die gespeicherte mit der kompilierten Konfigurations-ID <a class="spec-record-ref" data-req="SWS_NvM_00073" href="../../spec/record.html?id=SWS_NvM_00073">[SWS_NvM_00073]</a>. Bei Abweichung hängt das Verhalten von <code>NvMDynamicConfiguration</code> ab: Mit <code>NvMDynamicConfiguration == FALSE</code> wird die Abweichung ignoriert <a class="spec-record-ref" data-req="SWS_NvM_00248" href="../../spec/record.html?id=SWS_NvM_00248">[SWS_NvM_00248]</a>. Andernfalls erhalten nicht änderungsresistente Blöcke Defaultdaten <a class="spec-record-ref" data-req="SWS_NvM_00249" href="../../spec/record.html?id=SWS_NvM_00249">[SWS_NvM_00249]</a> <a class="spec-record-ref" data-req="SWS_NvM_00674" href="../../spec/record.html?id=SWS_NvM_00674">[SWS_NvM_00674]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_4_5_Resistant_to_changed_software.html" data-snip="SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_4_5_Resistant_to_changed_software">NV Data Handling S. 15</a>).</li>
<li>Dann iteriert er über die Anwenderblöcke außer den Block-IDs 0 und 1 <a class="spec-record-ref" data-req="SWS_NvM_00244" href="../../spec/record.html?id=SWS_NvM_00244">[SWS_NvM_00244]</a>. Dabei verarbeitet er nur Blöcke mit permanentem RAM-Block oder expliziter Synchronisation <a class="spec-record-ref" data-req="SWS_NvM_00118" href="../../spec/record.html?id=SWS_NvM_00118">[SWS_NvM_00118]</a>.</li>
<li>Zum Schluss setzt er das Gesamtergebnis auf <code>NVM_REQ_OK</code> oder <code>NVM_REQ_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_NvM_00895" href="../../spec/record.html?id=SWS_NvM_00895">[SWS_NvM_00895]</a> <a class="spec-record-ref" data-req="SWS_NvM_00301" href="../../spec/record.html?id=SWS_NvM_00301">[SWS_NvM_00301]</a>.</li>
</ol>
<p>Im Mode-Management-Beispiel startet die BswM-Regel <code>NvMReadAllFinished</code> die restliche Initialisierung erst nach Abschluss von <code>NvM_ReadAll</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_Startup.html" data-snip="SNIP_CLASSIC_MODEMANAGEMENTGUIDE_SECTION_3_3_1_Startup">Mode Management Guide S. 31</a>).</p>

<li>Geschützte und gesperrte Blöcke überspringt er ohne Fehlermeldung <a class="spec-record-ref" data-req="SWS_NvM_00434" href="../../spec/record.html?id=SWS_NvM_00434">[SWS_NvM_00434]</a> <a class="spec-record-ref" data-req="SWS_NvM_00750" href="../../spec/record.html?id=SWS_NvM_00750">[SWS_NvM_00750]</a>.</li>
<li>Andere Aufträge unterbrechen ihn nicht <a class="spec-record-ref" data-req="SWS_NvM_00567" href="../../spec/record.html?id=SWS_NvM_00567">[SWS_NvM_00567]</a>.</li>
</ul>
<p>Anwender markieren geänderte Blöcke mit <code>NvM_SetRamBlockStatus(…, TRUE)</code>, sofern die API aktiviert ist <a class="spec-record-ref" data-req="SWS_NvM_00406" href="../../spec/record.html?id=SWS_NvM_00406">[SWS_NvM_00406]</a> <a class="spec-record-ref" data-req="SWS_NvM_00408" href="../../spec/record.html?id=SWS_NvM_00408">[SWS_NvM_00408]</a>. Bei Dirty-Flag-Blöcken übernimmt die RTE diesen Aufruf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVDATAHANDLING_SECTION_5_3_1_2_2_Storing_at_Shutdown.html" data-snip="SNIP_CLASSIC_NVDATAHANDLING_SECTION_5_3_1_2_2_Storing_at_Shutdown">NV Data Handling S. 41</a>).</p>
<p><code>NvM_CancelWriteAll</code> ist dem BswM vorbehalten <a class="spec-record-ref" data-req="SWS_NvM_00703" href="../../spec/record.html?id=SWS_NvM_00703">[SWS_NvM_00703]</a> und bleibt ohne laufendes <code>NvM_WriteAll</code> wirkungslos <a class="spec-record-ref" data-req="SWS_NvM_00233" href="../../spec/record.html?id=SWS_NvM_00233">[SWS_NvM_00233]</a>. Der aktuelle Block wird nicht-destruktiv abgeschlossen <a class="spec-record-ref" data-req="SWS_NvM_00238" href="../../spec/record.html?id=SWS_NvM_00238">[SWS_NvM_00238]</a>. Die restlichen Blöcke und das Multiblock-Ergebnis erhalten <code>NVM_REQ_CANCELED</code> <a class="spec-record-ref" data-req="SWS_NvM_00236" href="../../spec/record.html?id=SWS_NvM_00236">[SWS_NvM_00236]</a> <a class="spec-record-ref" data-req="SWS_NvM_00237" href="../../spec/record.html?id=SWS_NvM_00237">[SWS_NvM_00237]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-6ac8a97c1cd29029.html" data-snip="FIG-6ac8a97c1cd29029">SWS NvM S. 161</a>).</p>
<p>Zwei weitere Multiblock-Aufträge ergänzen den Lebenszyklus:</p>
<ul>
<li><code>NvM_ValidateAll</code> setzt Blöcke mit automatischer Validierung auf „VALID / CHANGED“ <a class="spec-record-ref" data-req="SWS_NvM_00856" href="../../spec/record.html?id=SWS_NvM_00856">[SWS_NvM_00856]</a>.</li>
<li><code>NvM_FirstInitAll</code> beschreibt Blöcke mit Defaultdaten oder invalidiert sie, wenn keine vorhanden sind <a class="spec-record-ref" data-req="SWS_NvM_00913" href="../../spec/record.html?id=SWS_NvM_00913">[SWS_NvM_00913]</a> <a class="spec-record-ref" data-req="SWS_NvM_00919" href="../../spec/record.html?id=SWS_NvM_00919">[SWS_NvM_00919]</a>.</li>
</ul>

<h4>Einzelaufträge: Warteschlangen, Prioritäten und Rückmeldung</h4>
<p>Einzelblockaufträge wie <code>NvM_ReadBlock</code>, <code>NvM_WriteBlock</code> oder <code>NvM_RestoreBlockDefaults</code> sind asynchron. Die Funktion übernimmt die Parameter, reiht den Auftrag ein und kehrt zurück <a class="spec-record-ref" data-req="SWS_NvM_00195" href="../../spec/record.html?id=SWS_NvM_00195">[SWS_NvM_00195]</a> <a class="spec-record-ref" data-req="SWS_NvM_00208" href="../../spec/record.html?id=SWS_NvM_00208">[SWS_NvM_00208]</a> <a class="spec-record-ref" data-req="SWS_NvM_00224" href="../../spec/record.html?id=SWS_NvM_00224">[SWS_NvM_00224]</a>. Danach steht das Blockergebnis auf <code>NVM_REQ_PENDING</code> <a class="spec-record-ref" data-req="SWS_NvM_00185" href="../../spec/record.html?id=SWS_NvM_00185">[SWS_NvM_00185]</a>. Bei Warteschlangenüberlauf liefert die Funktion <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_NvM_00184" href="../../spec/record.html?id=SWS_NvM_00184">[SWS_NvM_00184]</a>. Ein Block wird nur eingereiht, wenn er nicht schon ansteht oder bearbeitet wird <a class="spec-record-ref" data-req="SWS_NvM_00385" href="../../spec/record.html?id=SWS_NvM_00385">[SWS_NvM_00385]</a>.</p>
<p>Andere Dienste wirken synchron im Kontext des Aufrufers, etwa <code>NvM_SetDataIndex</code> <a class="spec-record-ref" data-req="SWS_NvM_00448" href="../../spec/record.html?id=SWS_NvM_00448">[SWS_NvM_00448]</a> und <code>NvM_GetErrorStatus</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-a355421bd6922c61.html" data-snip="FIG-a355421bd6922c61">SWS NvM S. 158</a>). <code>NvM_CancelJobs</code> entfernt anstehende Aufträge eines Blocks; ein laufender Job wird jedoch fortgesetzt <a class="spec-record-ref" data-req="SWS_NvM_00536" href="../../spec/record.html?id=SWS_NvM_00536">[SWS_NvM_00536]</a> <a class="spec-record-ref" data-req="SWS_NvM_00537" href="../../spec/record.html?id=SWS_NvM_00537">[SWS_NvM_00537]</a>.</p>
<p>Die Bearbeitung erfolgt serialisiert nach Priorität <a class="spec-record-ref" data-req="SWS_NvM_00162" href="../../spec/record.html?id=SWS_NvM_00162">[SWS_NvM_00162]</a>. Ist <code>NvMJobPrioritization</code> aktiv, nutzt der NvM zwei Warteschlangen, eine davon für Immediate-Schreibaufträge (Crash-Daten) <a class="spec-record-ref" data-req="SWS_NvM_00564" href="../../spec/record.html?id=SWS_NvM_00564">[SWS_NvM_00564]</a> <a class="spec-record-ref" data-req="SWS_NvM_00378" href="../../spec/record.html?id=SWS_NvM_00378">[SWS_NvM_00378]</a>. Ein solcher <code>NvM_WriteBlock</code> bricht einen anstehenden Job destruktiv ab <a class="spec-record-ref" data-req="SWS_NvM_00300" href="../../spec/record.html?id=SWS_NvM_00300">[SWS_NvM_00300]</a>. <code>NvM_MainFunction</code> startet den abgebrochenen Job danach neu <a class="spec-record-ref" data-req="SWS_NvM_00258" href="../../spec/record.html?id=SWS_NvM_00258">[SWS_NvM_00258]</a>. Ohne Priorisierung arbeitet der NvM in Eingangsreihenfolge, ohne Immediate-Jobs <a class="spec-record-ref" data-req="SWS_NvM_00379" href="../../spec/record.html?id=SWS_NvM_00379">[SWS_NvM_00379]</a>. Aufträge, die während eines Multiblock-Auftrags eingehen, werden eingereiht und anschließend ausgeführt <a class="spec-record-ref" data-req="SWS_NvM_00568" href="../../spec/record.html?id=SWS_NvM_00568">[SWS_NvM_00568]</a> <a class="spec-record-ref" data-req="SWS_NvM_00569" href="../../spec/record.html?id=SWS_NvM_00569">[SWS_NvM_00569]</a>.</p>
<p>Jeder asynchrone Auftrag hinterlegt sein Ergebnis im Fehler-/Statusfeld <a class="spec-record-ref" data-req="SWS_NvM_00175" href="../../spec/record.html?id=SWS_NvM_00175">[SWS_NvM_00175]</a>. <code>NvM_GetErrorStatus</code> liest dieses Feld aus <a class="spec-record-ref" data-req="SWS_NvM_00015" href="../../spec/record.html?id=SWS_NvM_00015">[SWS_NvM_00015]</a>. Darüber hinaus gibt es zwei optionale Rückmeldewege:</p>
<ul>
<li>Ist ein Callback konfiguriert, ruft <code>NvM_MainFunction</code> <code>NvM_SingleBlockCallbackFunction</code> auf <a class="spec-record-ref" data-req="SWS_NvM_00740" href="../../spec/record.html?id=SWS_NvM_00740">[SWS_NvM_00740]</a> <a class="spec-record-ref" data-req="SWS_NvM_00347" href="../../spec/record.html?id=SWS_NvM_00347">[SWS_NvM_00347]</a>. Ohne Callback gibt es keine asynchrone Benachrichtigung <a class="spec-record-ref" data-req="SWS_NvM_00742" href="../../spec/record.html?id=SWS_NvM_00742">[SWS_NvM_00742]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-cb39b272e9de20bd.html" data-snip="FIG-cb39b272e9de20bd">SWS NvM S. 160</a>).</li>
<li>Mit <code>NvMBswMBlockStatusInformation</code> meldet der NvM Annahme und Ergebnis an den BswM <a class="spec-record-ref" data-req="SWS_NvM_00890" href="../../spec/record.html?id=SWS_NvM_00890">[SWS_NvM_00890]</a> <a class="spec-record-ref" data-req="SWS_NvM_00891" href="../../spec/record.html?id=SWS_NvM_00891">[SWS_NvM_00891]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-52d6e49d413f96ca.html" data-snip="FIG-52d6e49d413f96ca">SWS NvM S. 162</a>).</li>
</ul>

<h4>RAM-Block-Synchronisation und Blockzustand</h4>
<p>Der NvM kennt zwei Arten, Daten mit dem RAM-Block der Anwendung abzugleichen. Bei <strong>impliziter Synchronisation</strong> arbeitet er direkt auf diesem RAM-Block. Die Anwendung stellt den Block bereit und greift bis zum Auftragsende nicht darauf zu <a class="spec-record-ref" data-req="SWS_NvM_00698" href="../../spec/record.html?id=SWS_NvM_00698">[SWS_NvM_00698]</a> <a class="spec-record-ref" data-req="SWS_NvM_00699" href="../../spec/record.html?id=SWS_NvM_00699">[SWS_NvM_00699]</a>. Übergibt sie <code>NULL_PTR</code>, nutzt der NvM den permanenten RAM-Block <a class="spec-record-ref" data-req="SWS_NvM_00898" href="../../spec/record.html?id=SWS_NvM_00898">[SWS_NvM_00898]</a> <a class="spec-record-ref" data-req="SWS_NvM_00900" href="../../spec/record.html?id=SWS_NvM_00900">[SWS_NvM_00900]</a>. Ein temporärer Block per Zeiger ist trotzdem möglich <a class="spec-record-ref" data-req="SWS_NvM_00278" href="../../spec/record.html?id=SWS_NvM_00278">[SWS_NvM_00278]</a>. Die PRAM-Dienste arbeiten stets auf dem permanenten RAM-Block <a class="spec-record-ref" data-req="SWS_NvM_00765" href="../../spec/record.html?id=SWS_NvM_00765">[SWS_NvM_00765]</a> <a class="spec-record-ref" data-req="SWS_NvM_00794" href="../../spec/record.html?id=SWS_NvM_00794">[SWS_NvM_00794]</a>. Im RTE-Szenario ist dieser Block ein Per-Instance-Memory (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVDATAHANDLING_SECTION_5_2_Case_2_Application_SW_C_accessing_NVRAM_blocks_which.html" data-snip="SNIP_CLASSIC_NVDATAHANDLING_SECTION_5_2_Case_2_Application_SW_C_accessing_NVRAM_blocks_which">NV Data Handling S. 32</a>).</p>
<p>Bei <strong>expliziter Synchronisation</strong> (<code>NvMBlockUseSyncMechanism</code>) läuft der Austausch über einen internen RAM-Mirror <a class="spec-record-ref" data-req="SWS_NvM_00511" href="../../spec/record.html?id=SWS_NvM_00511">[SWS_NvM_00511]</a>. Davon gibt es genau einen, bemessen nach dem größten betroffenen Block <a class="spec-record-ref" data-req="SWS_NvM_00513" href="../../spec/record.html?id=SWS_NvM_00513">[SWS_NvM_00513]</a>. Der NvM ruft <code>NvMWriteRamBlockToNvCallback</code> bzw. <code>NvMReadRamBlockFromNvCallback</code> auf <a class="spec-record-ref" data-req="SWS_NvM_00515" href="../../spec/record.html?id=SWS_NvM_00515">[SWS_NvM_00515]</a> <a class="spec-record-ref" data-req="SWS_NvM_00516" href="../../spec/record.html?id=SWS_NvM_00516">[SWS_NvM_00516]</a>. Liefert ein Callback <code>E_NOT_OK</code>, wiederholt er den Aufruf im nächsten Zyklus, bis zu <code>NvMRepeatMirrorOperations</code>-mal <a class="spec-record-ref" data-req="SWS_NvM_00579" href="../../spec/record.html?id=SWS_NvM_00579">[SWS_NvM_00579]</a> <a class="spec-record-ref" data-req="SWS_NvM_00840" href="../../spec/record.html?id=SWS_NvM_00840">[SWS_NvM_00840]</a>. Bis zum Callback darf die Anwendung den RAM-Block noch ändern <a class="spec-record-ref" data-req="SWS_NvM_00705" href="../../spec/record.html?id=SWS_NvM_00705">[SWS_NvM_00705]</a>. Ein Block nutzt entweder explizite Synchronisation oder einen permanenten RAM-Block, nicht beides <a class="spec-record-ref" data-req="SWS_NvM_00904" href="../../spec/record.html?id=SWS_NvM_00904">[SWS_NvM_00904]</a>. Der Mechanismus erlaubt geteilte Blöcke über eine NvBlockSwComponentType (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_3_2_Explicit_synchronization.html" data-snip="SNIP_CLASSIC_NVDATAHANDLING_SECTION_4_1_3_2_Explicit_synchronization">NV Data Handling S. 12</a>).</p>

<h4>Konfiguration, Schutzmechanismen und Partitionsbezug</h4>
<p>Für begrenzte Ressourcen gibt es drei API-Konfigurationsklassen <a class="spec-record-ref" data-req="SWS_NvM_00149" href="../../spec/record.html?id=SWS_NvM_00149">[SWS_NvM_00149]</a>. Klasse 1 unterstützt keine Dataset-Blöcke <a class="spec-record-ref" data-req="SWS_NvM_00365" href="../../spec/record.html?id=SWS_NvM_00365">[SWS_NvM_00365]</a>. Die Deskriptortabellen werden generiert <a class="spec-record-ref" data-req="SWS_NvM_00143" href="../../spec/record.html?id=SWS_NvM_00143">[SWS_NvM_00143]</a>. Den Speicherbedarf deklarieren die Anwender zur Konfigurationszeit <a class="spec-record-ref" data-req="SWS_NvM_00030" href="../../spec/record.html?id=SWS_NvM_00030">[SWS_NvM_00030]</a>. BSW-Module tun das über <code>NvBlockNeeds</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWMODULEDESCRIPTIONTEMPLATE_SECTION_13_2_1_2_Nvm_Use_Case_Temporary_RAM_Block.html" data-snip="SNIP_CLASSIC_BSWMODULEDESCRIPTIONTEMPLATE_SECTION_13_2_1_2_Nvm_Use_Case_Temporary_RAM_Block">BSWMD Template S. 241</a>). Der ECU-Integrator leitet daraus die NvM-Konfiguration ab (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_NVM_FIGURE_Figure_3_132.html" data-snip="SNIP_CLASSIC_NVM_FIGURE_Figure_3_132">Methodology S. 444</a>).</p>
<p>Für einzelne Blöcke stehen mehrere Schutzmechanismen zur Verfügung:</p>
<ul>
<li>Ein Attributfeld verwaltet den Schreibschutz <a class="spec-record-ref" data-req="SWS_NvM_00054" href="../../spec/record.html?id=SWS_NvM_00054">[SWS_NvM_00054]</a>; <code>NvMBlockWriteProt</code> aktiviert ihn als Voreinstellung <a class="spec-record-ref" data-req="SWS_NvM_00326" href="../../spec/record.html?id=SWS_NvM_00326">[SWS_NvM_00326]</a>.</li>
<li>Blöcke mit <code>NvMWriteBlockOnce</code> werden nur einmal beschrieben <a class="spec-record-ref" data-req="SWS_NvM_00397" href="../../spec/record.html?id=SWS_NvM_00397">[SWS_NvM_00397]</a>. Schreibaufträge vor dem ersten Lesen weist der NvM ab <a class="spec-record-ref" data-req="SWS_NvM_00952" href="../../spec/record.html?id=SWS_NvM_00952">[SWS_NvM_00952]</a>.</li>
<li>Für gesperrte Blöcke (<code>NvM_SetBlockLockStatus</code>) liefert <code>NvM_WriteBlock</code> <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_NvM_00749" href="../../spec/record.html?id=SWS_NvM_00749">[SWS_NvM_00749]</a>. Die Sperre ändern weder <code>NvM_SetRamBlockStatus</code> noch <code>NvM_SetBlockProtection</code> <a class="spec-record-ref" data-req="SWS_NvM_00754" href="../../spec/record.html?id=SWS_NvM_00754">[SWS_NvM_00754]</a>.</li>
<li>Optional sind außerdem ein Static-Block-ID-Header <a class="spec-record-ref" data-req="SWS_NvM_00522" href="../../spec/record.html?id=SWS_NvM_00522">[SWS_NvM_00522]</a>, ein CRC-Vergleich gegen unnötiges Schreiben <a class="spec-record-ref" data-req="SWS_NvM_00849" href="../../spec/record.html?id=SWS_NvM_00849">[SWS_NvM_00849]</a> und Verschlüsselung über den CSM <a class="spec-record-ref" data-req="SWS_NvM_00976" href="../../spec/record.html?id=SWS_NvM_00976">[SWS_NvM_00976]</a>.</li>
</ul>
<p>Bei Partitionierung ruft der NvM Schnittstellen im Kontext der jeweils zugeordneten Partition auf. Allgemeine Funktionen laufen in der Master-Partition <a class="spec-record-ref" data-req="SWS_NvM_00969" href="../../spec/record.html?id=SWS_NvM_00969">[SWS_NvM_00969]</a>. <code>NvM_ReadAll</code> und <code>NvM_WriteAll</code> bietet nur der Master an <a class="spec-record-ref" data-req="SWS_NvM_00970" href="../../spec/record.html?id=SWS_NvM_00970">[SWS_NvM_00970]</a> <a class="spec-record-ref" data-req="SWS_NvM_00971" href="../../spec/record.html?id=SWS_NvM_00971">[SWS_NvM_00971]</a> <a class="spec-record-ref" data-req="SWS_NvM_CONSTR00974" href="../../spec/record.html?id=SWS_NvM_CONSTR00974">[SWS_NvM_CONSTR00974]</a>. SW-Cs erreichen den NvM über blockbezogene Ports:</p>
<ul>
<li><code>PS_{Block}</code> (Service) <a class="spec-record-ref" data-req="SWS_NvM_00847" href="../../spec/record.html?id=SWS_NvM_00847">[SWS_NvM_00847]</a></li>
<li><code>PAdmin_{Block}</code> (Administration) <a class="spec-record-ref" data-req="SWS_NvM_00843" href="../../spec/record.html?id=SWS_NvM_00843">[SWS_NvM_00843]</a></li>
<li><code>PM_{Block}</code> (Mirror) <a class="spec-record-ref" data-req="SWS_NvM_00844" href="../../spec/record.html?id=SWS_NvM_00844">[SWS_NvM_00844]</a></li>
<li><code>PNJF_{Block}</code> (Benachrichtigung Job-Ende) <a class="spec-record-ref" data-req="SWS_NvM_00846" href="../../spec/record.html?id=SWS_NvM_00846">[SWS_NvM_00846]</a></li>
</ul>
<h4>Verhalten im Fehlerfall</h4>
<p>Beim Lesen wertet der NvM die Meldungen der MemIf unterschiedlich aus:</p>
<ul>
<li>Eine CRC-Abweichung meldet er als <code>NVM_E_INTEGRITY_FAILED</code> <a class="spec-record-ref" data-req="SWS_NvM_00203" href="../../spec/record.html?id=SWS_NvM_00203">[SWS_NvM_00203]</a>.</li>
<li><code>MEMIF_JOB_FAILED</code> meldet er als <code>NVM_E_REQ_FAILED</code> <a class="spec-record-ref" data-req="SWS_NvM_00654" href="../../spec/record.html?id=SWS_NvM_00654">[SWS_NvM_00654]</a>.</li>
<li><code>MEMIF_BLOCK_INVALID</code> ergibt nur <code>NVM_REQ_NV_INVALIDATED</code>, ohne DEM-Meldung <a class="spec-record-ref" data-req="SWS_NvM_00341" href="../../spec/record.html?id=SWS_NvM_00341">[SWS_NvM_00341]</a> <a class="spec-record-ref" data-req="SWS_NvM_00652" href="../../spec/record.html?id=SWS_NvM_00652">[SWS_NvM_00652]</a>.</li>
</ul>
<p>Danach greifen mehrere Wiederherstellungsstufen:</p>
<ol>
<li>Bei CRC-Fehlern folgen konfigurierte Lesewiederholungen <a class="spec-record-ref" data-req="SWS_NvM_00526" href="../../spec/record.html?id=SWS_NvM_00526">[SWS_NvM_00526]</a>.</li>
<li>Bei redundanten Blöcken liest der NvM die zweite Kopie und versucht, die Redundanz wiederherzustellen <a class="spec-record-ref" data-req="SWS_NvM_00199" href="../../spec/record.html?id=SWS_NvM_00199">[SWS_NvM_00199]</a> <a class="spec-record-ref" data-req="SWS_NvM_00531" href="../../spec/record.html?id=SWS_NvM_00531">[SWS_NvM_00531]</a>. Misslingt das, meldet er <code>NVM_E_LOSS_OF_REDUNDANCY</code> <a class="spec-record-ref" data-req="SWS_NvM_00546" href="../../spec/record.html?id=SWS_NvM_00546">[SWS_NvM_00546]</a>.</li>
<li>Zuletzt lädt der NvM Defaultdaten mit dem Ergebnis <code>NVM_REQ_RESTORED_DEFAULTS</code> <a class="spec-record-ref" data-req="SWS_NvM_00202" href="../../spec/record.html?id=SWS_NvM_00202">[SWS_NvM_00202]</a>. Der NV-Inhalt bleibt dabei unverändert <a class="spec-record-ref" data-req="SWS_NvM_00172" href="../../spec/record.html?id=SWS_NvM_00172">[SWS_NvM_00172]</a>.</li>
</ol>
<p>Fehlen Defaultdaten, bleibt der RAM-Block ungültig <a class="spec-record-ref" data-req="SWS_NvM_00658" href="../../spec/record.html?id=SWS_NvM_00658">[SWS_NvM_00658]</a> <a class="spec-record-ref" data-req="SWS_NvM_00204" href="../../spec/record.html?id=SWS_NvM_00204">[SWS_NvM_00204]</a>. Interpretation: Die Reihenfolge der Stufen dürfte der Aufzählung in der Error Description folgen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_8_2_5_NVRAM_Manager.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_8_2_5_NVRAM_Manager">Error Description S. 62</a>). Diese Quelle weicht in zwei Punkten von den Requirements ab. Sie nennt <code>NVM_REQ_RESTORED_FROM_ROM</code> statt <code>NVM_REQ_RESTORED_DEFAULTS</code>. Außerdem fasst sie das endgültige Scheitern pauschal als <code>NVM_E_REQ_FAILED</code> zusammen. Normativ sind die oben genannten Requirements.</p>
