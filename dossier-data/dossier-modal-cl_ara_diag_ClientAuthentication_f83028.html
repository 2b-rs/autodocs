<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient der Anwendung zur Meldung von Authentifizierungszuständen und aktiven Benutzerrollen an den Diagnostic Server.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle ermöglicht es der Anwendung, den Diagnostic Server über den Authentifizierungsstatus sowie aktive Benutzerrollen eines Diagnose-Clients zu informieren <a class="spec-record-ref" data-req="SWS_DM_01132" href="../spec/record.html?id=SWS_DM_01132">[SWS_DM_01132]</a>. Über Aufrufe wie <code>Authenticate</code> oder <code>OverrideDefaultRoles</code> werden Zustandswechsel gesteuert und Handles zur Verwaltung dynamischer Zugriffslisten bereitgestellt <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>. Zustandsänderungen infolge von Timeouts lassen sich über einen Notifier asynchron überwachen. Da die Klasse nicht threadsicher ist und keine Kopien erlaubt, muss der Zugriff innerhalb der Anwendung synchronisiert erfolgen.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::ClientAuthentication</code> dient als zentrale Schnittstelle für die Anwendung, um die Instanz des Diagnostic Server über Authentifizierungszustände und die aktuell authentifizierten Benutzerrollen zu unterrichten <a class="spec-record-ref" data-req="SWS_DM_01132" href="../spec/record.html?id=SWS_DM_01132">[SWS_DM_01132]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=129">SWS Diagnostics, S. 129</a>. An diesem Zusammenspiel sind drei wesentliche Parteien beteiligt:</p>
<ul>
<li><strong>Anwendung (Application):</strong> Führt Authentifizierungsprüfungen durch – entweder unter Nutzung von Schnittstellen des Diagnostic Server oder über anwendungseigene Mechanismen – und übermittelt Benutzerrollen an den Diagnostic Server <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>.</li>
<li><strong>Diagnostic Server / Diagnostic Manager:</strong> Verwaltet die Diagnosesitzungen und setzt Zugriffsrechte auf diagnostische Ressourcen basierend auf den Rollen und dem Authentifizierungsstatus durch <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>.</li>
<li><strong>Diagnose-Client:</strong> Ein externer Tester oder SOVD-Client, der Diagnoseanfragen an das Steuergerät richtet <a class="spec-record-ref" data-req="SWS_DM_01210" href="../spec/record.html?id=SWS_DM_01210">[SWS_DM_01210]</a>, <a class="spec-record-ref" data-req="SWS_DM_01470" href="../spec/record.html?id=SWS_DM_01470">[SWS_DM_01470]</a>.</li>
</ul>
<p>Die Anzahl der Instanzen von <code>ClientAuthentication</code> wird durch das Modellelement <code>DiagnosticExternalAuthenticationIdentification</code> festgelegt <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=129">SWS Diagnostics, S. 129</a>. Dieses Element erlaubt es, eine Authentifizierung für einen Client mit einer festen Quelladresse oder über einen Adressbereich zu konfigurieren, falls die finale Quelladresse zur Compile-Zeit noch nicht bekannt ist <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=129">SWS Diagnostics, S. 129</a>. Interpretation: Die Zuordnung von Diagnose-Clients zu konkreten Instanzen von <code>ClientAuthentication</code> erfolgt zur Laufzeit anhand dieser Quelladressbereiche. Im Fall von SOVD-Clients übergibt der Diagnostic Server bei der Validierung des Autorisierungs-Tokens über <code>ara::diag::SovdAuthorization::ValidateAuthorization</code> direkt ein <code>ClientAuthentication</code>-Objekt an die Anwendung <a class="spec-record-ref" data-req="SWS_DM_01470" href="../spec/record.html?id=SWS_DM_01470">[SWS_DM_01470]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Anwendung erhält eine Instanz von <code>ClientAuthentication</code> über überladene Methoden von <code>ara::diag::ExternalAuthentication::Get</code> <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a> oder im Kontext der SOVD-Tokenprüfung <a class="spec-record-ref" data-req="SWS_DM_01470" href="../spec/record.html?id=SWS_DM_01470">[SWS_DM_01470]</a>. Die Klasse besitzt strikte Eigentumssemantiken: Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01139" href="../spec/record.html?id=SWS_DM_01139">[SWS_DM_01139]</a> und Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01140" href="../spec/record.html?id=SWS_DM_01140">[SWS_DM_01140]</a> sind gelöscht (<code>=delete</code>). Verschiebeoperationen (Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_01137" href="../spec/record.html?id=SWS_DM_01137">[SWS_DM_01137]</a> und Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01138" href="../spec/record.html?id=SWS_DM_01138">[SWS_DM_01138]</a>) sind als Standard vordefiniert und als <code>noexcept</code> deklariert. Der Destruktor ist ebenfalls <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_01136" href="../spec/record.html?id=SWS_DM_01136">[SWS_DM_01136]</a>. Sämtliche Elementfunktionen sowie der Destruktor sind nicht threadsicher (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_01136" href="../spec/record.html?id=SWS_DM_01136">[SWS_DM_01136]</a>, <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a>, <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>.</p>

<p>Der Authentifizierungsstatus wird über den Aufzählungstyp <code>DiagnosticAuthState</code> abgebildet <a class="spec-record-ref" data-req="SWS_DM_01133" href="../spec/record.html?id=SWS_DM_01133">[SWS_DM_01133]</a>:</p>
<ul>
<li><code>kDeAuthenticated</code> (0x00): Kein Diagnose-Client ist authentifiziert. Beim Systemstart befindet sich der Client standardmäßig in diesem Zustand <a class="spec-record-ref" data-req="SWS_DM_01205" href="../spec/record.html?id=SWS_DM_01205">[SWS_DM_01205]</a>. Hierbei gelten diejenigen Rollen (<code>DiagnosticAuthRole</code>) als Standardrollen, deren Attribut <code>isDefault</code> auf <code>TRUE</code> konfiguriert ist <a class="spec-record-ref" data-req="SWS_DM_01204" href="../spec/record.html?id=SWS_DM_01204">[SWS_DM_01204]</a>, <a class="spec-record-ref" data-req="SWS_DM_01134" href="../spec/record.html?id=SWS_DM_01134">[SWS_DM_01134]</a>. Über <code>OverrideDefaultRoles</code> können diese Standardrollen temporär für einen festgelegten Timeout überschrieben werden <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01209" href="../spec/record.html?id=SWS_DM_01209">[SWS_DM_01209]</a>.</li>
<li><code>kAuthenticated</code> (0x01): Ein Diagnose-Client ist authentifiziert. Dieser Zustand wird durch Aufruf von <code>Authenticate</code> erreicht, wodurch die übergebenen Benutzerrollen im Diagnostic Server aktiviert werden <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>.</li>
</ul>
<p>Ein automatischer Zustandsübergang von <code>kAuthenticated</code> zurück zu <code>kDeAuthenticated</code> wird ausgelöst, wenn ein Client in der Standard-Sitzung nach der letzten Übertragungsbestätigung (<code>TransmitConfirmation</code>) keine weiteren Anfragen sendet und die Inaktivitätszeit abläuft <a class="spec-record-ref" data-req="SWS_DM_01210" href="../spec/record.html?id=SWS_DM_01210">[SWS_DM_01210]</a>, oder wenn ein S3-Timeout auftritt <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>, <a class="spec-record-ref" data-req="SWS_DM_02077" href="../spec/record.html?id=SWS_DM_02077">[SWS_DM_02077]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf zur Verwaltung der Client-Authentifizierung umfasst folgende Schritte:</p>
<ol>
<li><strong>Notifier registrieren:</strong> Die Anwendung registriert mit <code>SetNotifier</code> eine Callback-Funktion vom Typ <code>ClientAuthenticationSetNotifier</code> (<code>std::function&lt;void(DiagnosticAuthState)&gt;</code>) <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>, <a class="spec-record-ref" data-req="SWS_DM_02077" href="../spec/record.html?id=SWS_DM_02077">[SWS_DM_02077]</a>. Dadurch wird sie informiert, wenn Statuswechsel – beispielsweise der Übergang zu <code>kDeAuthenticated</code> durch Inaktivität oder einen S3-Timeout – eintreten <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>. Ein erneuter Aufruf überschreibt den zuvor gesetzten Notifier <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>.</li>
<li><strong>Zustand abfragen:</strong> Über die Methode <code>GetState()</code> kann die Anwendung den aktuellen Authentifizierungszustand des Clients synchron abfragen <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a>.</li>
<li><strong>Authentifizierung melden:</strong> Sobald die Authentifizierung erfolgreich abgeschlossen wurde, ruft die Anwendung <code>Authenticate</code> mit den zu aktivierenden Benutzerrollen (<code>ara::core::Vector&lt;DiagnosticAuthRole&gt;</code>) auf <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01134" href="../spec/record.html?id=SWS_DM_01134">[SWS_DM_01134]</a>. Der Diagnostic Server setzt den Zustand auf <code>kAuthenticated</code> und liefert ein <code>ClientAuthenticationHandle</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>.</li>
<li><strong>Zugriffsrechte verwalten:</strong> Über das erhaltene <code>ClientAuthenticationHandle</code> kann die Anwendung die dynamische Zugriffsliste (<code>DynamicAccessList</code>) für den Client konfigurieren <a class="spec-record-ref" data-req="SWS_DM_01213" href="../spec/record.html?id=SWS_DM_01213">[SWS_DM_01213]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=132">SWS Diagnostics, S. 132</a>. Zugleich wird durch die Nutzung dieses Handles das Inaktivitätszeitfenster des Clients aufgefrischt <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=133">SWS Diagnostics, S. 133</a>.</li>
</ol>
<p>Befindet sich der Client im Zustand <code>kDeAuthenticated</code>, kann die Anwendung stattdessen <code>OverrideDefaultRoles(defaultRoles, timeout)</code> aufrufen, um temporär alternative Standardrollen zu aktivieren; auch dieser Aufruf gibt bei Erfolg ein <code>ClientAuthenticationHandle</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01209" href="../spec/record.html?id=SWS_DM_01209">[SWS_DM_01209]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Die Methoden <code>Authenticate</code>, <code>OverrideDefaultRoles</code> und <code>GetState</code> liefern ihre Rückgabewerte gekapselt in <code>ara::core::Result</code> zurück und sind ausnahmesicher (<code>exception safe</code>) sowie <code>noexcept</code> spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a>. Im Fehlerfall wird folgender standardisierter Fehlercode gemeldet:</p>
<ul>
<li><code>DiagErrc::kServiceNotAvailable</code>: Tritt auf, wenn der Aufruf nicht ausgeführt werden kann, weil essenzielle Funktionalitäten des Diagnostic Managers zurzeit nicht verfügbar sind <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a>. Dieser Fehler besitzt Rollback-Semantik (<code>rollback_semantics</code>), womit keine unvollständigen Zustandsänderungen verbleiben <a class="spec-record-ref" data-req="SWS_DM_01141" href="../spec/record.html?id=SWS_DM_01141">[SWS_DM_01141]</a>, <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a>.</li>
</ul>
<p>Für <code>SetNotifier</code> sind keine standardisierten Fehlercodes definiert <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>.
