<p class="ai-level ai-oneliner-lead" data-ai-level="1">Bietet Schnittstellen und Container für das Freshness Value Management zur Absicherung der Zeitsynchronisation.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Namespace <code>apext::tsync</code> stellt Schnittstellen und Datencontainer für das Freshness Value Management der Adaptive-Zeitsynchronisation bereit. Über die Schnittstelle <code>FVM</code> werden Aktualitätswerte in <code>FVContainer</code>-Instanzen gekapselt, um Zeitnachrichten gegen Replay-Angriffe abzusichern. Tritt bei der Initialisierung ein nicht behebbarer Fehler auf oder ist ein Wert temporär nicht verfügbar, wird dies über die Fehlercodes der <code>TsyncFvmErrorDomain</code> abgebildet <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Die Instanziierung standardisierter Fehlerobjekte erfolgt dabei ausnahmesicher und threadsicher über <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>.</p>

<h4>Kontext</h4>
<p>Der Namespace <code>apext::tsync</code> stellt eine plattformspezifische Erweiterung der AUTOSAR-Adaptive-Zeitsynchronisation (<code>ara::tsync</code>) dar. Seine zentrale Aufgabe ist das Freshness Value Management (FVM), das Mechanismen zur Gewährleistung der Aktualität von Zeitinformationen bereitstellt, um Replay-Angriffe und veraltete Zustände in zeitsynchronisierten Netzwerken zu verhindern. Zu den Kernbestandteilen gehören die Schnittstelle <code>FVM</code>, der Datencontainer <code>FVContainer</code>, die Fehlerdomäne <code>TsyncFvmErrorDomain</code> sowie die Ausnahmeklasse <code>TsyncFvmException</code>.</p>
<p>Die Klasse <code>FVContainer</code> kapselt einen Aktualitätswert, indem sie dessen Länge in Bits sowie den Wert selbst in Form eines Byte-Vektors verwaltet. Die Schnittstelle <code>FVM</code> fungiert als funktionale Brücke für <code>ara::tsync</code>. <code>FVM</code> dürfte als Abstraktionsschnittstelle fungieren, über die zeitsynchronisierende Instanzen von <code>ara::tsync</code> aktuelle Frischewerte beziehen oder verifizieren. <a class="interp-q interp-q-open" data-q="Q-f92f53d92ec347e5" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-f92f53d92ec347e5" title="Frage Q-f92f53d92ec347e5 (offen): FVM dürfte als Abstraktionsschnittstelle fungieren, über die zeitsynchronisierende Instanzen von ara::tsync aktuelle Frischewerte beziehen oder verifizieren.">Frage Q-f92f53d92ec347e5 (offen)</a> Die Fehlerdomäne <code>TsyncFvmErrorDomain</code> und zugehörige Hilfsfunktionen stellen die standardisierte Fehlerberichterstattung sicher <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Der Lebenszyklus der Komponenten im Namespace <code>apext::tsync</code> gliedert sich in Initialisierungs-, Betriebs- und Beendigungsphasen. Für die Initialisierungsphase definiert die Enumeration <code>TsyncFvmErrc</code> den Fehlerwert <code>kFVInitializeFailed</code> (= 2), der als nicht behebbarer Fehler (unrecoverable error) spezifiziert ist und anzeigt, dass der Freshness Value Manager nicht verwendet werden konnte <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Der Fehler <code>kFVInitializeFailed</code> deutet vermutlich darauf hin, dass vor dem Abruf von Freshness Values eine Initialisierungsphase des FVM durchlaufen werden muss, deren Fehlschlag eine weitere Verwendung ausschließt. <a class="interp-q interp-q-open" data-q="Q-d9c097d736bae053" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-d9c097d736bae053" title="Frage Q-d9c097d736bae053 (offen): Der Fehler kFVInitializeFailed deutet vermutlich darauf hin, dass vor dem Abruf von Freshness Values eine Initialisierungsphase des FVM durchlaufen werden muss, deren Fehlschlag eine weitere Verwendung ausschließt.">Frage Q-d9c097d736bae053 (offen)</a></p>
<p>Im laufenden Betrieb besitzen <code>FVContainer</code>-Instanzen eine temporäre Lebensdauer: Sie werden bei Bedarf instanziiert, mit dem Vektor und der Bitlänge befüllt und an die synchronisierenden Protokollinstanzen übergeben. Demgegenüber besitzt das Fehlerdomänen-Objekt <code>TsyncFvmErrorDomain</code> eine statische Lebensdauer über den gesamten Prozesszeitraum. Die Funktion <code>GetTsyncFvmErrorDomain()</code> gibt eine Referenz auf das globale Instanzobjekt zurück <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>. Sowohl <code>GetTsyncFvmErrorDomain()</code> als auch die Fabrikfunktion <code>MakeErrorCode()</code> sind als <code>constexpr</code> und <code>noexcept</code> deklariert sowie als ausnahmesicher und threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>, <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>. Dies erlaubt eine nebenläufige Fehlererzeugung und -abfrage ohne Synchronisationssperren.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Nutzungspfad im Zusammenspiel mit der Zeitsynchronisation umfasst die Bereitstellung und Auswertung von Aktualitätswerten:</p>
<ol>
<li>Eine Komponente aus <code>ara::tsync</code> fordert zur Absicherung einer Zeitbotschaft einen aktuellen Frischewert über die Schnittstelle <code>FVM</code> an.</li>
<li>Bei erfolgreicher Wertermittlung erzeugt bzw. befüllt <code>FVM</code> eine Instanz von <code>FVContainer</code> mit der Bitlänge und dem Byte-Vektor des Werts und liefert diese an den Aufrufer zurück.</li>
<li>Kann der Frischewert zur Laufzeit temporär nicht bereitgestellt werden, meldet <code>FVM</code> den behebbaren Fehler <code>kFVNotAvailable</code> <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Hierzu wird über <code>MakeErrorCode()</code> ein passendes <code>ara::core::ErrorCode</code>-Objekt mit herstellerspezifischen Zusatzdaten erzeugt <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>.</li>
<li>Die aufrufende Komponente wertet das Ergebnis aus und entscheidet über Wiederholungsversuche oder Ersatzmaßnahmen.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Die Fehlerbehandlung in <code>apext::tsync</code> basiert auf der Architektur von <code>ara::core::ErrorDomain</code> und <code>ara::core::ErrorCode</code>. Die Fehlercodes der <code>TsyncFvmErrorDomain</code> sind in der Enumeration <code>TsyncFvmErrc</code> aufgeführt, deren Basistyp <code>ara::core::ErrorDomain::CodeType</code> ist <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>:</p>
<ul>
<li><code>kFVNotAvailable</code> (= 1): Behebbarer Fehler (recoverable error), der signalisiert, dass der Freshness Value gegenwärtig nicht verfügbar ist <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Aufrufer können die Anfrage erneut stellen oder den aktuellen Verarbeitungszyklus überspringen.</li>
<li><code>kFVInitializeFailed</code> (= 2): Nicht behebbarer Fehler (unrecoverable error), der besagt, dass der Freshness Value Manager nicht initialisiert oder verwendet werden konnte <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. Dies führt zum Abbruch der abhängigen Zeitsynchronisationsdienste.</li>
</ul>
<p>Die Erzeugung konkreter Fehlerobjekte erfolgt über die Hilfsfunktion <code>MakeErrorCode(TsyncFvmErrc code, ara::core::ErrorDomain::SupportDataType data)</code>, die den Enumerator und herstellerspezifische Zusatzdaten entgegennimmt <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>.
