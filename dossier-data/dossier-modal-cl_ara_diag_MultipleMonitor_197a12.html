<h4>Context</h4>
<p>The <code>ara::diag::MultipleMonitor</code> class serves to implement monitor operations via bundled monitor interfaces (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>). It acts as a central mediator between the application-specific diagnostic and functional logic and the diagnostic system (Diagnostic Management, DM). While a simple monitor maps only a single fault monitoring path, <code>MultipleMonitor</code> enables managing and reporting the status of multiple monitors via a shared interface port (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>, <a class="spec-record-ref" data-req="SWS_DM_01698" href="../spec/record.html?id=SWS_DM_01698">[SWS_DM_01698]</a>).</p>

<p>The binding to the AUTOSAR model takes place via a port instance (<code>PortPrototype</code>) of type <code>DiagnosticMultipleMonitorInterface</code> (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>). Via this port, the monitoring instance registers and forwards commands as well as feedback, such as debouncing controls and qualification status, to the DM or receives requests from the diagnostic system (<a class="spec-record-ref" data-req="SWS_DM_01698" href="../spec/record.html?id=SWS_DM_01698">[SWS_DM_01698]</a>, <a class="spec-record-ref" data-req="SWS_DM_01699" href="../spec/record.html?id=SWS_DM_01699">[SWS_DM_01699]</a>).</p>

<h4>Lifecycle</h4>
<p>An instance of <code>MultipleMonitor</code> has a strict object identity and is bound to a firmly defined execution context. The constructor requires an <code>ara::core::InstanceSpecifier</code> that addresses the corresponding port in the system model (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>). To prevent side effects and multiple bindings, both the copy constructor and the move constructor (Move) and the associated assignment operators are explicitly deleted (<a class="spec-record-ref" data-req="SWS_DM_02065" href="../spec/record.html?id=SWS_DM_02065">[SWS_DM_02065]</a>, <a class="spec-record-ref" data-req="SWS_DM_02066" href="../spec/record.html?id=SWS_DM_02066">[SWS_DM_02066]</a>, <a class="spec-record-ref" data-req="SWS_DM_02063" href="../spec/record.html?id=SWS_DM_02063">[SWS_DM_02063]</a>, <a class="spec-record-ref" data-req="SWS_DM_02064" href="../spec/record.html?id=SWS_DM_02064">[SWS_DM_02064]</a>). A transfer of the instance between scopes is thus precluded.</p>

<p>After instantiation, the object is in the initialization state: each monitor managed within it must be configured exactly once via one of the overloads of <code>ConfigureMonitor</code> before its first use (<a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>, <a class="spec-record-ref" data-req="SWS_DM_01697" href="../spec/record.html?id=SWS_DM_01697">[SWS_DM_01697]</a>, <a class="spec-record-ref" data-req="SWS_DM_01702" href="../spec/record.html?id=SWS_DM_01702">[SWS_DM_01702]</a>, <a class="spec-record-ref" data-req="SWS_DM_01973" href="../spec/record.html?id=SWS_DM_01973">[SWS_DM_01973]</a>). As soon as the monitors are initialized, a call to <code>Offer()</code> activates the forwarding of requests from Diagnostic Management (<a class="spec-record-ref" data-req="SWS_DM_01699" href="../spec/record.html?id=SWS_DM_01699">[SWS_DM_01699]</a>). The forwarding can be suspended again via <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_01700" href="../spec/record.html?id=SWS_DM_01700">[SWS_DM_01700]</a>). Regarding thread safety, construction is thread-safe (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>), whereas configuration and offering methods (<code>ConfigureMonitor</code>, <code>Offer</code>, <code>StopOffer</code>) are not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>, <a class="spec-record-ref" data-req="SWS_DM_01699" href="../spec/record.html?id=SWS_DM_01699">[SWS_DM_01699]</a>, <a class="spec-record-ref" data-req="SWS_DM_01700" href="../spec/record.html?id=SWS_DM_01700">[SWS_DM_01700]</a>). Reporting via <code>ReportMonitorAction</code> is protected depending on the concurrency model defined in the design or constructor (<a class="spec-record-ref" data-req="SWS_DM_01698" href="../spec/record.html?id=SWS_DM_01698">[SWS_DM_01698]</a>).</p>

<h4>Usage Path</h4>
<p>The regular procedure for using <code>MultipleMonitor</code> is divided into the phases of creation, individual monitor configuration, offering, and ongoing event reporting:</p>
<ol>
  <li><strong>Creation:</strong> The application instantiates <code>MultipleMonitor</code> by specifying the <code>InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>).</li>
  <li><strong>Monitor configuration:</strong> For each monitored event or each <code>monitorHandle</code>, the appropriate debouncing strategy is defined. AUTOSAR provides four dedicated overloads of <code>ConfigureMonitor</code> for this purpose:
    <ul>
      <li>Monitor-internal debouncing with registration of a callback to determine the Fault Detection Counter (FDC) (<a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>).</li>
      <li>Time-based debouncing by passing parameters of type <code>TimeBased</code> (<a class="spec-record-ref" data-req="SWS_DM_01697" href="../spec/record.html?id=SWS_DM_01697">[SWS_DM_01697]</a>).</li>
      <li>Counter-based debouncing using parameters of type <code>CounterBased</code> (<a class="spec-record-ref" data-req="SWS_DM_01702" href="../spec/record.html?id=SWS_DM_01702">[SWS_DM_01702]</a>).</li>
      <li>Operation without debouncing, where only the optional <code>InitMonitorNotifier</code> is registered (<a class="spec-record-ref" data-req="SWS_DM_01973" href="../spec/record.html?id=SWS_DM_01973">[SWS_DM_01973]</a>).</li>
    </ul>
    Each overload may be called only exactly once per monitor handle (<a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>, <a class="spec-record-ref" data-req="SWS_DM_01697" href="../spec/record.html?id=SWS_DM_01697">[SWS_DM_01697]</a>, <a class="spec-record-ref" data-req="SWS_DM_01702" href="../spec/record.html?id=SWS_DM_01702">[SWS_DM_01702]</a>, <a class="spec-record-ref" data-req="SWS_DM_01973" href="../spec/record.html?id=SWS_DM_01973">[SWS_DM_01973]</a>).
  </li>
  <li><strong>Service offering:</strong> By calling <code>Offer()</code>, the interface is activated so that the Diagnostic Management daemon can deliver requests to this handler (<a class="spec-record-ref" data-req="SWS_DM_01699" href="../spec/record.html?id=SWS_DM_01699">[SWS_DM_01699]</a>).</li>
  <li><strong>Status reporting:</strong> During ongoing operation, the application logic transmits test results, debouncing control commands, or pre-storage commands via <code>ReportMonitorAction(monitorHandle, action)</code> (<a class="spec-record-ref" data-req="SWS_DM_01698" href="../spec/record.html?id=SWS_DM_01698">[SWS_DM_01698]</a>).</li>
  <li><strong>Deactivation:</strong> Prior to shutdown or upon temporary deactivation of diagnostic forwarding, <code>StopOffer()</code> is called (<a class="spec-record-ref" data-req="SWS_DM_01700" href="../spec/record.html?id=SWS_DM_01700">[SWS_DM_01700]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error situations for <code>MultipleMonitor</code> are signaled partly via standardized platform violations and partly via <code>ara::core::Result</code> with specific error codes:</p>
<ul>
  <li><strong>Model and process violations during construction:</strong>
    If the assignment of the <code>InstanceSpecifier</code> fails, documented runtime violations occur (<a class="spec-record-ref" data-req="SWS_DM_01695" href="../spec/record.html?id=SWS_DM_01695">[SWS_DM_01695]</a>):
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: The identifier cannot be resolved in the model of the executable or does not refer to a <code>PortPrototype</code>.</li>
      <li><code>PortInterfaceMappingViolation</code>: The referenced port is not typed by a <code>DiagnosticMultipleMonitorInterface</code>.</li>
      <li><code>ProcessMappingViolation</code>: No matching process context exists at runtime for the modeled process.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: The identifier is already occupied by another instance in the running process.</li>
    </ul>
  </li>
  <li><strong>Configuration errors:</strong>
    In the event of an error, a call to <code>ConfigureMonitor</code> returns <code>DiagErrc::kInvalidArgument</code> (<a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>, <a class="spec-record-ref" data-req="SWS_DM_01697" href="../spec/record.html?id=SWS_DM_01697">[SWS_DM_01697]</a>, <a class="spec-record-ref" data-req="SWS_DM_01702" href="../spec/record.html?id=SWS_DM_01702">[SWS_DM_01702]</a>, <a class="spec-record-ref" data-req="SWS_DM_01973" href="../spec/record.html?id=SWS_DM_01973">[SWS_DM_01973]</a>). This occurs, for example, if invalid parameters or contradictory debouncing states (e.g. <code>kPreFailed</code> for internal debouncing) are passed.
  </li>
  <li><strong>Offering errors:</strong>
    If <code>Offer()</code> is called while the service is already being offered, the operation fails with error code <code>DiagOfferErrc::kAlreadyOffered</code> (<a class="spec-record-ref" data-req="SWS_DM_01699" href="../spec/record.html?id=SWS_DM_01699">[SWS_DM_01699]</a>).
  </li>
  <li><strong>Invalid monitor handles during reporting:</strong>
    If an unconfigured or incorrect <code>monitorHandle</code> is passed to <code>ReportMonitorAction</code>, the call does not abort; instead, the call is silently ignored according to the specification (<a class="spec-record-ref" data-req="SWS_DM_01698" href="../spec/record.html?id=SWS_DM_01698">[SWS_DM_01698]</a>).
  </li>
</ul>
