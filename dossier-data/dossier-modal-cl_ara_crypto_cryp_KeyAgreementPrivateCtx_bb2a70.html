<h4>Context</h4>
<p>The <code>ara::crypto::cryp::KeyAgreementPrivateCtx</code> interface defines the context for asymmetric key agreement procedures based on a private key. It inherits from base class <code>CryptoContext</code> and serves to compute a shared symmetric secret from its own private key and the peer's public key as part of a cryptographic handshake or key exchange protocol <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</p>
<p>Within the crypto architecture, the context interacts with several central entities:</p>
<ul>
<li><strong>Application layer:</strong> Configures the context, initiates the key computation, and typically manages the instance via typed smart pointer <code>KeyAgreementPrivateCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21301" href="../spec/record.html?id=SWS_CRYPT_21301">[SWS_CRYPT_21301]</a>.</li>
<li><strong>Local key material:</strong> The private key is either provided as a direct key object of type <code>PrivateKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a> or connected via a referenced key slot (<code>KeySlot</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>.</li>
<li><strong>Peer key:</strong> The public key of the peer is passed as <code>PublicKey::Sptr</code> into the agreement call <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong>Target key (result):</strong> As a result, the context yields a shared symmetric key (<code>SymmetricKey::Sptr</code>) for further cryptographic use <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>Instances of <code>KeyAgreementPrivateCtx</code> are operated as interface objects. Referencing and sharing take place by default via smart pointer type <code>ara::crypto::cryp::KeyAgreementPrivateCtx::Sptr</code>, which is defined as an alias for <code>std::shared_ptr&lt;KeyAgreementPrivateCtx&gt;</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21301" href="../spec/record.html?id=SWS_CRYPT_21301">[SWS_CRYPT_21301]</a>. The concrete instantiation is likely performed via a higher-level factory component or a crypto provider, as the class represents a purely abstract interface.</p>
<p>With regard to its life phases, the context distinguishes between the following states:</p>
<ul>
<li><strong>Uninitialized state:</strong> After creation, the context does not yet have a key assignment. A call to <code>AgreeKey</code> fails in this state with error <code>UninitializedContext</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong>Key binding and configuration:</strong> Via the overloads of <code>SetKey</code>, the context is bound to a private key <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a> or a <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>. If the algorithm requires additional control data, these are configured via <code>SetParameter</code> as a memory region <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a> or an integer value <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>. Only when all necessary parameters are available is the initialization considered complete <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong>Operational state:</strong> The context is available for computing keys.</li>
</ul>
<p>Regarding concurrency and exception safety, the interface guarantees robust behavior: all member functions (<code>SetKey</code>, <code>SetParameter</code>, <code>AgreeKey</code>) are declared as exception-safe (<em>exception safe</em>) as well as <code>noexcept</code>. In addition, all methods are thread-safe (<em>thread-safe</em>), so that concurrent accesses by multiple application threads are supported <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>.</p>

<h4>Usage Path</h4>
<p>The typical sequence for deriving a shared symmetric key is divided into key binding, optional parameterization, and key agreement:</p>
<ol>
<li><strong>Configure key:</strong> The application assigns its own private key to the context. This is done either directly by passing a <code>PrivateKey::Sptr</code> via <code>SetKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a> or by assigning a <code>KeySlot::Sptr</code> via <code>SetKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>. When assigning a <code>KeySlot</code>, the private key contained therein is read out only at the execution time of the agreement <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>.</li>
<li><strong>Configure parameters (optional):</strong> If the key agreement procedure requires additional domain or protocol parameters, these are passed using <code>SetParameter</code>—either as a byte region (<code>ReadOnlyMemRegion</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a> or as a 64-bit integer (<code>std::uint64_t</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>. Which identifiers are supported is likely to depend on the concrete algorithm.</li>
<li><strong>Agree key:</strong> The call to <code>AgreeKey</code> accepts the public key of the peer (<code>otherSideKey</code>), the target algorithm ID (<code>targetAlgId</code>), and the allowed usage flags (<code>allowedUsage</code>) and executes the key agreement algorithm <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong>Check result:</strong> Upon successful completion, <code>AgreeKey</code> returns a pointer to the computed symmetric key (<code>SymmetricKey::Sptr</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors are communicated via return type <code>ara::core::Result</code>. All interface methods have rollback semantics (<em>rollback semantics</em>), ensuring that the internal state of the context remains intact in the event of an error <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>.</p>
<p>Relevant error codes include:</p>
<ul>
<li><strong><code>UninitializedContext</code>:</strong> Reported for <code>AgreeKey</code> if no key was assigned beforehand or required parameters via <code>SetParameter</code> are missing <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong><code>CryptoErrc::kIncompatibleObject</code>:</strong> Occurs when a passed key (<code>PrivateKey</code> or peer <code>PublicKey</code>) or a <code>KeySlot</code> is not compatible with the context or algorithm <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>.</li>
<li><strong><code>CryptoErrc::kUsageViolation</code>:</strong> Indicates that the permitted usage of the private or public key does not include the right <code>kAllowKeyAgreement</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>.</li>
<li><strong><code>CryptoErrc::kUnsupported</code>:</strong> Returned if the context implementation exclusively supports <code>KeySlot</code> or exclusively <code>PrivateKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>, or if a specified parameter identifier is not supported <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>.</li>
<li><strong><code>CryptoErrc::kInvalidArgument</code> and <code>CryptoErrc::kUnknownIdentifier</code>:</strong> <code>kInvalidArgument</code> indicates invalid flags in <code>allowedUsage</code> for a symmetric key <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a> or invalid parameter values in <code>SetParameter</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>. <code>kUnknownIdentifier</code> reports an unknown <code>targetAlgId</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
<li><strong><code>CryptoErrc::kEmptyKeySlot</code> and <code>CryptoErrc::kBusyResource</code>:</strong> <code>kEmptyKeySlot</code> occurs when an assigned <code>KeySlot</code> contains no key at the execution time of <code>AgreeKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. In case of temporary overload of required crypto resources, <code>kBusyResource</code> is reported <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
</ul>
