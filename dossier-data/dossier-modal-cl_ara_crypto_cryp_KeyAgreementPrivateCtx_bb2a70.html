<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>ara::crypto::cryp::KeyAgreementPrivateCtx</code> dient zur Ausführung kryptografischer Schlüsselvereinbarungsverfahren auf Basis eines lokalen privaten Schlüssels und des öffentlichen Schlüssels einer Gegenstelle <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Nach Zuweisung des eigenen Schlüssels und optionaler Parameter berechnet die Methode <code>AgreeKey</code> ein gemeinsames Geheimnis und liefert dieses als symmetrisches Schlüsselobjekt zurück. Eine zentrale Randbedingung ist die vollständige Initialisierung vor der Ausführung, da fehlende Parameter oder fehlende Berechtigungen für <code>kAllowKeyAgreement</code> zum Abbruch mit entsprechenden Fehlercodes führen <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Alle Operationen sind dabei thread-sicher ausgelegt.</p>

<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::crypto::cryp::KeyAgreementPrivateCtx</code> dient im Modul crypto der Adaptive Platform zur Ausführung asymmetrischer Schlüsselvereinbarungsverfahren (Key Agreement). Ihre zentrale Verantwortung liegt in der Berechnung eines gemeinsamen symmetrischen Schlüssels aus einem lokalen privaten Schlüssel und dem öffentlichen Schlüssel eines Kommunikationspartners <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Als spezialisierter Kryptokontext interagiert die Klasse mit mehreren Schlüssel- und Speicherabstraktionen: Der eigene private Schlüssel kann entweder direkt als <code>PrivateKey</code>-Objekt <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a> oder referenziert über einen <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a> gebunden werden. Die Gegenseite steuert ihren öffentlichen Schlüssel in Form eines <code>PublicKey</code> bei, während das Ergebnis als eigenständiges <code>SymmetricKey</code>-Objekt bereitgestellt wird <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Ergänzend können algorithmusspezifische Konfigurationsparameter als Speicherbereich oder Ganzzahl übergeben werden <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Lebenszyklus und Besitzverhältnisse von <code>KeyAgreementPrivateCtx</code> basieren auf Shared Pointern; die Spezifikation stellt hierfür den Typ-Alias <code>KeyAgreementPrivateCtx::Sptr</code> bereit <a class="spec-record-ref" data-req="SWS_CRYPT_21301" href="../spec/record.html?id=SWS_CRYPT_21301">[SWS_CRYPT_21301]</a>. Interpretation: Die Instanziierung dürfte über eine übergeordnete Factory eines CryptoProviders erfolgen, da die Klasse eine rein virtuelle Schnittstelle ohne Konstruktorspezifikation darstellt. <a class="interp-q interp-q-open" data-q="Q-22dca518675fba51" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-22dca518675fba51" title="Frage Q-22dca518675fba51 (offen): Die Instanziierung von KeyAgreementPrivateCtx erfolgt vermutlich über eine Provider-Factory">Frage Q-22dca518675fba51 (offen)</a> Nach der Erzeugung befindet sich die Instanz in einem nicht betriebsbereiten Grundzustand. Erst durch die Konfiguration eines privaten Schlüssels mittels <code>SetKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a> und die Zuweisung aller für das gewählte Schema notwendigen Parameter <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a> wird der Kontext initialisiert.</p>
<p>Wird eine Schlüsselberechnung vor Abschluss dieser Konfigurationsschritte angestoßen, schlägt der Aufruf fehl <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Bezüglich der Nebenläufigkeit sind alle Mitgliedsfunktionen als thread-sicher (<code>thread-safe</code>) sowie ausnahmesicher (<code>exception safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a>. Da die Ausführungsfunktion <code>AgreeKey</code> als <code>const</code> deklariert ist <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>, kann derselbe initialisierte Kontext parallel für Vereinbarungen mit verschiedenen Gegenstellen verwendet werden.</p>

<h4>Nutzungspfad</h4>
<p>Die praktische Verwendung gliedert sich in eine sequentielle Abfolge von Konfiguration und Berechnung:</p>
<ul>
<li><strong>Schlüsselzuweisung:</strong> Zunächst bindet die Anwendung den eigenen privaten Schlüssel an den Kontext. Dies erfolgt entweder über <code>SetKey(PrivateKey::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21313" href="../spec/record.html?id=SWS_CRYPT_21313">[SWS_CRYPT_21313]</a> für ein geladenes Schlüsselobjekt oder über <code>SetKey(KeySlot::Sptr)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50053" href="../spec/record.html?id=SWS_CRYPT_50053">[SWS_CRYPT_50053]</a> für einen Schlüsselplatz, dessen Inhalt erst zum Zeitpunkt der Vereinbarung ausgewertet wird.</li>
<li><strong>Parameterdefinition:</strong> Falls der Zielalgorithmus zusätzliche Initialisierungsdaten verlangt, werden diese per <code>SetParameter</code> als Puffer <code>ReadOnlyMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50051" href="../spec/record.html?id=SWS_CRYPT_50051">[SWS_CRYPT_50051]</a> oder als 64-Bit-Ganzzahl <code>std::uint64_t</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50052" href="../spec/record.html?id=SWS_CRYPT_50052">[SWS_CRYPT_50052]</a> übergeben.</li>
<li><strong>Schlüsselvereinbarung:</strong> Mit <code>AgreeKey</code> wird der kryptografische Algorithmus ausgeführt <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>. Die aufrufende Komponente übergibt den öffentlichen Schlüssel der Gegenstelle (<code>otherSideKey</code>), den Bezeichner des gewünschten Zielalgorithmus (<code>targetAlgId</code>) sowie die zulässigen Verwendungsflags (<code>allowedUsage</code>).</li>
<li><strong>Ergebnisübernahme:</strong> Bei erfolgreichem Abschluss liefert <code>AgreeKey</code> ein <code>SymmetricKey</code>-Objekt, das das berechnete gemeinsame Geheimnis enthält <a class="spec-record-ref" data-req="SWS_CRYPT_21312" href="../spec/record.html?id=SWS_CRYPT_21312">[SWS_CRYPT_21312]</a>.</li>
</ul>
