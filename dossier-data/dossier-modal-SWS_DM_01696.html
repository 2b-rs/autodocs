<h4>Verwendung</h4>
<p>Die Methode <code>ara::diag::MultipleMonitor::ConfigureMonitor</code> initialisiert einen Diagnosemonitor für die monitor-interne Entprellung <a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>. Über den Parameter <code>monitorHandle</code> wird der zu konfigurierende Monitor adressiert, während mit <code>initMonitor</code> ein Notifier-Callback für Reinitialisierungen und mit <code>getFaultDetectionCounter</code> eine Funktion zur Abfrage des aktuellen Fehlerzählwerts (FDC) registriert werden <a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>. Die Ausführung erfolgt synchron und gibt ein <code>ara::core::Result&lt;void&gt;</code> zurück <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=636">AUTOSAR_AP_SWS_Diagnostics §8.44.2.1.3.4 „ConfigureMonitor“</a>.</p>

<h4>Fehlerbehandlung und Nebenläufigkeit</h4>
<p>Im Fehlerfall wird das Fehlerergebnis <code>DiagErrc::kInvalidArgument</code> zurückgeliefert <a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>. Dies dürfte insbesondere dann auftreten, wenn ungültige Funktionszeiger übergeben werden oder inkompatible Zustände bei interner Entprellung vorliegen (Interpretation). Die Operation ist als <code>noexcept</code> sowie ausnahmesicher (exception safe) spezifiziert, jedoch ausdrücklich als nicht threadsicher (not thread-safe) gekennzeichnet <a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>. Aufrufe auf derselben Monitor-Instanz müssen daher anwendungsseitig synchronisiert werden.</p>

<h4>Reihenfolge und Zusammenspiel</h4>
<p>Jede Überladung von <code>ConfigureMonitor</code> darf für einen Monitor nur genau einmal aufgerufen werden; der Monitor ist erst nach diesem Initialisierungsschritt einsatzbereit <a class="spec-record-ref" data-req="SWS_DM_01696" href="../spec/record.html?id=SWS_DM_01696">[SWS_DM_01696]</a>. Bei monitor-interner Entprellung verarbeitet die Diagnostic-Monitor-Anwendung die Entprelllogik eigenständig und übermittelt lediglich finale Ergebnisse an das Diagnostic Management <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=246">AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.3 „Monitor-internal debouncing“</a>. Für andere Entprellmechanismen stehen alternative Überladungen für zeitbasierte <a class="spec-record-ref" data-req="SWS_DM_01697" href="../spec/record.html?id=SWS_DM_01697">[SWS_DM_01697]</a>, zählerbasierte <a class="spec-record-ref" data-req="SWS_DM_01702" href="../spec/record.html?id=SWS_DM_01702">[SWS_DM_01702]</a> oder unentprellte Überwachungen <a class="spec-record-ref" data-req="SWS_DM_01973" href="../spec/record.html?id=SWS_DM_01973">[SWS_DM_01973]</a> bereit.</p>
