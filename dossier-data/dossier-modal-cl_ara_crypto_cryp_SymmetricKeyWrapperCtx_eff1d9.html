<h4>Context</h4>
<p>The class <code>ara::crypto::cryp::SymmetricKeyWrapperCtx</code> defines the interface for cryptographic contexts that provide symmetric key wrapping algorithms. Its core responsibility is to protect secret key material before transmission or storage by encrypting it with a Key Encryption Key (KEK) (wrap), or to convert already protected key material back into usable key objects (unwrap).</p>
<p>In the overall system, the context interacts with several cryptographic entities: It is managed by an application and referenced as <code>std::shared_ptr</code> via the type alias <code>Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24001" href="../spec/record.html?id=SWS_CRYPT_24001">[SWS_CRYPT_24001]</a>. To execute cryptographic transformations, the context requires a KEK, which is either passed as a concrete key object <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a> or provided via a <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50034" href="../spec/record.html?id=SWS_CRYPT_50034">[SWS_CRYPT_50034]</a>. When wrapping, the context encapsulates an arbitrary <code>CryptoObject</code> into a byte buffer <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>; when unwrapping, it reconstructs a full <code>SymmetricKey</code> object from a buffer <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>.</p>

<h4>Lifecycle</h4>
<p>Since <code>SymmetricKeyWrapperCtx</code> represents an abstract interface with pure virtual methods, a concrete instance is typically likely to be created via a factory of the crypto provider and held in application scope as <code>Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24001" href="../spec/record.html?id=SWS_CRYPT_24001">[SWS_CRYPT_24001]</a>. The lifecycle is divided into two main phases:</p>
<ul>
<li><strong>Uninitialized:</strong> Immediately after instantiation, no key is assigned to the context yet. Any attempt to query buffer sizes or perform key operations fails <a class="spec-record-ref" data-req="SWS_CRYPT_50035" href="../spec/record.html?id=SWS_CRYPT_50035">[SWS_CRYPT_50035]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>.</li>
<li><strong>Configured / ready:</strong> Calling <code>SetKey</code> with a compatible <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a> or a <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50034" href="../spec/record.html?id=SWS_CRYPT_50034">[SWS_CRYPT_50034]</a> sets the KEK. The context is now ready for wrapping and unwrapping operations.</li>
</ul>
<p>With regard to concurrency and fault tolerance, all methods are specified as exception-safe and thread-safe <a class="spec-record-ref" data-req="SWS_CRYPT_50035" href="../spec/record.html?id=SWS_CRYPT_50035">[SWS_CRYPT_50035]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50034" href="../spec/record.html?id=SWS_CRYPT_50034">[SWS_CRYPT_50034]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>. After completion of operations, the context is released by resetting the shared pointer.</p>

<h4>Usage Path</h4>
<p>A typical use case is the secure wrapping (key wrapping) of a key for export or transport:</p>
<ol>
<li><strong>Configuration:</strong> The application initializes the context via <code>SetKey</code> with the suitable KEK <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a> or a corresponding <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50034" href="../spec/record.html?id=SWS_CRYPT_50034">[SWS_CRYPT_50034]</a>.</li>
<li><strong>Capacity calculation:</strong> Prior to performing the wrapping, the application calls <code>GetRequiredWrappedKeyBufferSize</code> to determine the maximum required buffer size in bytes for the <code>CryptoObject</code> to be wrapped <a class="spec-record-ref" data-req="SWS_CRYPT_50035" href="../spec/record.html?id=SWS_CRYPT_50035">[SWS_CRYPT_50035]</a>.</li>
<li><strong>Execution:</strong> The application provides a writable memory region (<code>ReadWriteMemRegion</code>) of appropriate size and executes <code>Wrap</code>. Upon success, the method returns the exact number of written bytes in the return result <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>.</li>
</ol>
<p>In the inverse procedure (unwrapping), the application passes the wrapped data as <code>ReadOnlyMemRegion</code> to <code>UnwrapSymmetricKey</code>, specifies the target algorithm ID <code>targetAlgId</code> as well as the permitted usage flags <code>allowedUsage</code>, and directly receives a <code>SymmetricKey::Sptr</code> to the restored key object <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>.</p>

<h4>Error Scenarios</h4>
<p>The methods report errors via the return type <code>ara::core::Result</code> with rollback semantics. The most relevant error causes include:</p>
<ul>
<li><strong><code>CryptoErrc::kUninitializedContext</code>:</strong> Occurs when <code>GetRequiredWrappedKeyBufferSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50035" href="../spec/record.html?id=SWS_CRYPT_50035">[SWS_CRYPT_50035]</a>, <code>Wrap</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>, or <code>UnwrapSymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a> are called without previously configuring a KEK via <code>SetKey</code>.</li>
<li><strong><code>CryptoErrc::kUsageViolation</code>:</strong> Signals a violation of key permissions. This occurs if the KEK lacks the flags <code>kAllowKeyWrapping</code> or <code>kAllowKeyUnwrapping</code> during <code>SetKey</code> or during execution <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>, or if the target object to be wrapped does not permit <code>kAllowSecuredExport</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>.</li>
<li><strong><code>CryptoErrc::kIncompatibleObject</code> and <code>CryptoErrc::kUnsupported</code>:</strong> Are returned by <code>SetKey</code> if the provided key object or KeySlot is incompatible, or if the context implementation exclusively supports the respective other overload <a class="spec-record-ref" data-req="SWS_CRYPT_24018" href="../spec/record.html?id=SWS_CRYPT_24018">[SWS_CRYPT_24018]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50034" href="../spec/record.html?id=SWS_CRYPT_50034">[SWS_CRYPT_50034]</a>.</li>
<li><strong><code>CryptoErrc::kInsufficientCapacity</code>:</strong> Is reported for <code>Wrap</code> if the passed buffer <code>wrappedKey</code> is smaller than the actually required output capacity <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>.</li>
<li><strong><code>CryptoErrc::kEmptyKeySlot</code>:</strong> Occurs if during <code>Wrap</code> or <code>UnwrapSymmetricKey</code> a <code>KeySlot</code> is configured that does not contain a key at execution time <a class="spec-record-ref" data-req="SWS_CRYPT_24014" href="../spec/record.html?id=SWS_CRYPT_24014">[SWS_CRYPT_24014]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_24016" href="../spec/record.html?id=SWS_CRYPT_24016">[SWS_CRYPT_24016]</a>.</li>
