<h4>Context</h4>
<p>According to <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=709">AUTOSAR_AP_SWS_Diagnostics §8.53.2 “Struct: BulkDataMetaDataDescriptor”</a>, the data structure <a class="spec-record-ref" data-req="SWS_DM_01830" href="../spec/record.html?id=SWS_DM_01830">[SWS_DM_01830]</a> <code>ara::diag::SovdBulkData::BulkDataMetaDataDescriptor</code> defines the descriptive metadata for diagnostic bulk data within the framework of SOVD (Service-Oriented Vehicle Diagnostics). In the module <code>diag</code> of the AUTOSAR Adaptive Platform, extensive diagnostic datasets such as log files, trace recordings, or memory dumps are managed via standardized interfaces. To make such datasets discoverable, interpretable, and verifiable for external diagnostic testers or cloud services, this descriptor bundles all administrative and technical accompanying information.</p>

<p>The descriptor acts as an information carrier between the diagnostic-capable application (Adaptive Application) and the SOVD subsystem. According to <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=710">AUTOSAR_AP_SWS_Diagnostics §8.53.2.1 “Public Member Variables”</a>, the structure comprises the following categories of information:</p>
<ul>
<li><strong>Identification and naming:</strong> The attributes <code>id</code> <a class="spec-record-ref" data-req="SWS_DM_01831" href="../spec/record.html?id=SWS_DM_01831">[SWS_DM_01831]</a> and <code>name</code> <a class="spec-record-ref" data-req="SWS_DM_01833" href="../spec/record.html?id=SWS_DM_01833">[SWS_DM_01833]</a> ensure unique addressing and human-readable naming. The optional string <code>translation_id</code> <a class="spec-record-ref" data-req="SWS_DM_01834" href="../spec/record.html?id=SWS_DM_01834">[SWS_DM_01834]</a> serves for language-specific localization.</li>
<li><strong>File properties:</strong> The file name is specified via <code>file_name</code> <a class="spec-record-ref" data-req="SWS_DM_01836" href="../spec/record.html?id=SWS_DM_01836">[SWS_DM_01836]</a>. The attribute <code>mimetype</code> <a class="spec-record-ref" data-req="SWS_DM_01832" href="../spec/record.html?id=SWS_DM_01832">[SWS_DM_01832]</a> specifies the standardized data format, while <code>size</code> <a class="spec-record-ref" data-req="SWS_DM_01835" href="../spec/record.html?id=SWS_DM_01835">[SWS_DM_01835]</a> specifies the file size in bytes as <code>ara::core::Optional&lt;std::uint64_t&gt;</code>.</li>
<li><strong>Timestamps:</strong> The fields <code>creation_date</code> <a class="spec-record-ref" data-req="SWS_DM_01837" href="../spec/record.html?id=SWS_DM_01837">[SWS_DM_01837]</a> and <code>last_modified</code> <a class="spec-record-ref" data-req="SWS_DM_01838" href="../spec/record.html?id=SWS_DM_01838">[SWS_DM_01838]</a> document the temporal life cycle of the data.</li>
<li><strong>Integrity assurance:</strong> The cryptographic digest <code>hash</code> <a class="spec-record-ref" data-req="SWS_DM_01839" href="../spec/record.html?id=SWS_DM_01839">[SWS_DM_01839]</a> and the calculation method <code>hash_algorithm</code> <a class="spec-record-ref" data-req="SWS_DM_01840" href="../spec/record.html?id=SWS_DM_01840">[SWS_DM_01840]</a> allow the recipient to verify data integrity.</li>
</ul>

<h4>Lifecycle</h4>
<p>As a pure C++ struct, <code>BulkDataMetaDataDescriptor</code> follows classical value semantics (Value Object). The structure has no active background processes or state machines of its own:</p>
<ul>
<li><strong>Creation:</strong> Instances are typically instantiated by the providing Adaptive Application on the stack or in the heap and populated with the properties of the dataset to be provided.</li>
<li><strong>Ownership and forwarding:</strong> The structure consists of standard C++ and AUTOSAR value types (<code>ara::core::String</code> and <code>ara::core::Optional</code>). It supports regular copy and move operations. When passed to diagnostic interfaces, ownership of the instance or a copy is transferred to the processing SOVD component.</li>
<li><strong>Destruction:</strong> All contained resources are released automatically when leaving the scope in accordance with the lifetime rules of the member types.</li>
<li><strong>Concurrency:</strong> The structure provides no built-in protection against concurrent access. If descriptor instances are shared across thread boundaries, read and write accesses must be protected by external synchronization mechanisms.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical sequence for providing diagnostic data using the metadata descriptor is as follows:</p>
<ol>
<li><strong>Preparation of payload data:</strong> The application collects or generates bulk data (e.g., a memory dump or an error log) and stores it in the file system or a buffer.</li>
<li><strong>Descriptor initialization:</strong> An instance of <code>BulkDataMetaDataDescriptor</code> is created. The application assigns the basic identifiers, including the identifier <code>id</code> <a class="spec-record-ref" data-req="SWS_DM_01831" href="../spec/record.html?id=SWS_DM_01831">[SWS_DM_01831]</a>, the designation <code>name</code> <a class="spec-record-ref" data-req="SWS_DM_01833" href="../spec/record.html?id=SWS_DM_01833">[SWS_DM_01833]</a>, and the destination file name <code>file_name</code> <a class="spec-record-ref" data-req="SWS_DM_01836" href="../spec/record.html?id=SWS_DM_01836">[SWS_DM_01836]</a>.</li>
<li><strong>Format and size specification:</strong> The application specifies the MIME type via <code>mimetype</code> <a class="spec-record-ref" data-req="SWS_DM_01832" href="../spec/record.html?id=SWS_DM_01832">[SWS_DM_01832]</a>. If the total size is already known, the field <code>size</code> <a class="spec-record-ref" data-req="SWS_DM_01835" href="../spec/record.html?id=SWS_DM_01835">[SWS_DM_01835]</a> is populated with the byte value.</li>
<li><strong>Checksum determination:</strong> A checksum is determined over the data content. The algorithm name (e.g., SHA-256) is stored in <code>hash_algorithm</code> <a class="spec-record-ref" data-req="SWS_DM_01840" href="../spec/record.html?id=SWS_DM_01840">[SWS_DM_01840]</a> and the resulting check value is entered in <code>hash</code> <a class="spec-record-ref" data-req="SWS_DM_01839" href="../spec/record.html?id=SWS_DM_01839">[SWS_DM_01839]</a>.</li>
<li><strong>Timestamps and localization:</strong> The attributes <code>creation_date</code> <a class="spec-record-ref" data-req="SWS_DM_01837" href="../spec/record.html?id=SWS_DM_01837">[SWS_DM_01837]</a> and <code>last_modified</code> <a class="spec-record-ref" data-req="SWS_DM_01838" href="../spec/record.html?id=SWS_DM_01838">[SWS_DM_01838]</a> are populated. If required, <code>translation_id</code> <a class="spec-record-ref" data-req="SWS_DM_01834" href="../spec/record.html?id=SWS_DM_01834">[SWS_DM_01834]</a> is set for language-dependent user interfaces.</li>
<li><strong>Handoff:</strong> The fully populated descriptor is passed to the SOVD services of module <code>diag</code> so that clients can query the file information and initiate the download.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Since it is a pure data structure without methods of its own, <code>BulkDataMetaDataDescriptor</code> does not throw platform-specific error codes (such as <code>ara::core::ErrorCode</code>):</p>
<ul>
<li><strong>Incomplete initialization:</strong> Interpretation: If mandatory fields such as <code>id</code> or <code>file_name</code> are not populated or are populated incorrectly, the higher-level SOVD runtime environment is likely to reject the registration or provision of the bulk data object.</li>
<li><strong>Checksum discrepancy:</strong> If the value specified in <code>hash</code> <a class="spec-record-ref" data-req="SWS_DM_01839" href="../spec/record.html?id=SWS_DM_01839">[SWS_DM_01839]</a> does not match the actual payload data or if the algorithm declared in <code>hash_algorithm</code> <a class="spec-record-ref" data-req="SWS_DM_01840" href="../spec/record.html?id=SWS_DM_01840">[SWS_DM_01840]</a> is invalid on the client or server side, the validation fails during transfer.</li>
<li><strong>Missing value for size specification:</strong> Since <code>size</code> <a class="spec-record-ref" data-req="SWS_DM_01835" href="../spec/record.html?id=SWS_DM_01835">[SWS_DM_01835]</a> is of type <code>ara::core::Optional</code>, processing components must check via <code>has_value()</code> whether a size specification is present before accessing it, in order to avoid faulty accesses when the data size is still undetermined (e.g., with data streams).</li>
</ul>
