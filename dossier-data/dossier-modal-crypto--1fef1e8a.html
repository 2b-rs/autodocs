<h4>Rolle und Systemgrenze von FC Crypto</h4>
<p>Der Functional Cluster Cryptography (FC Crypto) bietet Anwendungen und anderen Functional Clusters über die standardisierte CryptoAPI drei Gruppen von Funktionen: kryptografische Operationen, Schlüsselverwaltung und Zertifikatsbehandlung. Die Implementierung liegt vollständig im Cluster. Dazu gehören auch die Konfiguration und die Vermittlung der Aufrufe <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_crypto_AUTOSAR_AP_SWS_C_P30_99.html" data-snip="SNIP_crypto_AUTOSAR_AP_SWS_C_P30_99">SWS Crypto S. 30</a>. Die Funktionen verteilen sich auf drei Provider: Crypto Provider, Key Storage Provider und X.509 Certificate Management Provider <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_crypto_AUTOSAR_AP_SWS_C_P29_98.html" data-snip="SNIP_crypto_AUTOSAR_AP_SWS_C_P29_98">SWS Crypto S. 29</a>.</p>
<p>Den Zugang bilden folgende Fabrikfunktionen:</p>
<ul>
<li><code>LoadCryptoProvider</code> <a class="spec-record-ref" data-req="SWS_CRYPT_20099" href="../spec/record.html?id=SWS_CRYPT_20099">[SWS_CRYPT_20099]</a></li>
<li><code>LoadKeySlot</code> und <code>LoadWriteableKeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50004" href="../spec/record.html?id=SWS_CRYPT_50004">[SWS_CRYPT_50004]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50005" href="../spec/record.html?id=SWS_CRYPT_50005">[SWS_CRYPT_50005]</a></li>
<li><code>LoadX509Provider</code> <a class="spec-record-ref" data-req="SWS_CRYPT_40099" href="../spec/record.html?id=SWS_CRYPT_40099">[SWS_CRYPT_40099]</a></li>
<li><code>LoadFormatter</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50200" href="../spec/record.html?id=SWS_CRYPT_50200">[SWS_CRYPT_50200]</a></li>
</ul>
<p>Das Schaubild der gemeinsamen Schnittstellen nennt zusätzlich <code>LoadKeyStorageProvider</code> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-dfe3fd1f2bfca194.html" data-snip="FIG-dfe3fd1f2bfca194">EXP SWArch S. 97</a>. Unter den R25-11-Requirements des Payloads ist diese Funktion nicht enthalten.</p>
<p>Laut Referenzarchitektur leistet die API mehr als Ver- und Entschlüsselung:</p>
<ul>
<li>Sie arbeitet mit verschlüsselten Schlüsseln oder Schlüssel-Handles.</li>
<li>Sie verwaltet Schlüssel auch dann sicher, wenn eine Anwendung kompromittiert ist.</li>
<li>Sie beschränkt den Zugriff auf Schlüssel und die damit erlaubten Operationen.</li>
</ul>

Die Implementierung ist vom Code der Konsumenten isoliert. Back-end-Key-Storage-Provider, etwa einer je HSM, bleiben hinter der öffentlichen CryptoAPI verborgen <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_7_7.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_7_7">SWS Crypto S. 87</a>. <h4>Zertifikate mit dem X.509 Provider</h4>
<p>Der X.509 Provider übernimmt die Grundfunktionen der Zertifikatsverwaltung:</p>
<ul>
<li>Er parst Zertifikate und Ketten <a class="spec-record-ref" data-req="SWS_CRYPT_40614" href="../spec/record.html?id=SWS_CRYPT_40614">[SWS_CRYPT_40614]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_40616" href="../spec/record.html?id=SWS_CRYPT_40616">[SWS_CRYPT_40616]</a>.</li>
<li>Er speichert sie in Slots oder Gruppen <a class="spec-record-ref" data-req="SWS_CRYPT_40621" href="../spec/record.html?id=SWS_CRYPT_40621">[SWS_CRYPT_40621]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50127" href="../spec/record.html?id=SWS_CRYPT_50127">[SWS_CRYPT_50127]</a>.</li>
<li>Er lädt sie über InstanceSpecifier <a class="spec-record-ref" data-req="SWS_CRYPT_40641" href="../spec/record.html?id=SWS_CRYPT_40641">[SWS_CRYPT_40641]</a>.</li>
</ul>
<p>Er hält außerdem die Root-Zertifikate und die CAs des Zertifizierungspfads <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_crypto_AUTOSAR_AP_SWS_C_P90_165.html" data-snip="SNIP_crypto_AUTOSAR_AP_SWS_C_P90_165">SWS Crypto S. 90</a>.</p>
<p>Validiert wird mit einem <code>CertificateValidationCtx</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50125" href="../spec/record.html?id=SWS_CRYPT_50125">[SWS_CRYPT_50125]</a> in vier Schritten:</p>
<ol>
<li>Vertrauenswürdige und nicht vertrauenswürdige Zertifikate hinzufügen <a class="spec-record-ref" data-req="SWS_CRYPT_50117" href="../spec/record.html?id=SWS_CRYPT_50117">[SWS_CRYPT_50117]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50118" href="../spec/record.html?id=SWS_CRYPT_50118">[SWS_CRYPT_50118]</a>.</li>
<li>Optionen und Referenzzeit setzen <a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50121" href="../spec/record.html?id=SWS_CRYPT_50121">[SWS_CRYPT_50121]</a>.</li>
<li>Gemäß RFC 5280 prüfen <a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>.</li>
<li>Das Ergebnis auswerten: Status, fehlschlagendes Zertifikat und gefundene Kette <a class="spec-record-ref" data-req="SWS_CRYPT_50094" href="../spec/record.html?id=SWS_CRYPT_50094">[SWS_CRYPT_50094]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50095" href="../spec/record.html?id=SWS_CRYPT_50095">[SWS_CRYPT_50095]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50096" href="../spec/record.html?id=SWS_CRYPT_50096">[SWS_CRYPT_50096]</a>.</li>
</ol>
<p>Sperrinformationen kommen auf zwei Wegen in die Prüfung:</p>
<ul>
<li>CRLs werden importiert und gelöscht <a class="spec-record-ref" data-req="SWS_CRYPT_50183" href="../spec/record.html?id=SWS_CRYPT_50183">[SWS_CRYPT_50183]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50184" href="../spec/record.html?id=SWS_CRYPT_50184">[SWS_CRYPT_50184]</a>.</li>

</ul>

<h4>Konfiguration im Manifest</h4>
<p>Die <code>CryptoModuleInstantiation</code> konfiguriert den Crypto Stack einer Maschine und aggregiert <code>CryptoCertificate</code>-Elemente <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_12_42.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_12_42">TPS Manifest S. 646</a>. In R23-11 und R24-11 aggregiert sie zusätzlich <code>CryptoProvider</code>-Elemente <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_10_43.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_10_43">TPS Manifest S. 609</a>.</p>
<p>Auf Anwendungsseite typisieren CryptoInterfaces die Ports <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_4_53.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_4_53">TPS Manifest S. 244</a>. <code>CryptoKeySlotInterface</code> beschreibt etwa <code>cryptoAlgId</code> und <code>slotType</code> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-5b0a7108571bc6d1.html" data-snip="FIG-5b0a7108571bc6d1">TPS Manifest S. 245</a>. Die Wahl des Interfaces hängt davon ab, was die Anwendung mit dem Schlüssel tut <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_3_67.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_3_67">TPS Manifest S. 168</a>:</p>
<ul>
<li>Wer Schlüssel ändert, nutzt <code>CryptoKeySlotInterface</code>.</li>
<li>Wer Schlüssel nur verwendet, nutzt <code>CryptoKeySlotClientInterface</code>.</li>
</ul>
<p>Mappings verknüpfen das Modell mit den Laufzeitobjekten:</p>
<ul>
<li><code>CryptoKeySlotToPortPrototypeMapping</code> verknüpft Key Slot, Port und Prozess <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_10_45.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_10_45">TPS Manifest S. 614</a>.</li>
<li><code>CryptoCertificateToPortPrototypeMapping</code> leistet dasselbe für Zertifikate <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_12_46.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_12_46">TPS Manifest S. 655</a>.</li>
<li><code>ComKeyToCryptoKeySlotMapping</code> ordnet Schlüssel anderer Module einem <code>CryptoKeySlot</code> zu <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_15_4.html" data-snip="SNIP_ADAPTIVE_CRYPTO_FIGURE_Figure_15_4">TPS Manifest S. 864</a>.</li>
</ul>
