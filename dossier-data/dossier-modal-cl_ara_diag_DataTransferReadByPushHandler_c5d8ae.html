<h4>Context</h4>
<p>The class <code>ara::diag::DataTransferReadByPushHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01515" href="../spec/record.html?id=SWS_DM_01515">[SWS_DM_01515]</a> provides the standardized interface for diagnostic data transfers in the Adaptive module <code>diag</code> that are initiated by a UDS service such as <code>RequestReadFile</code> or <code>RequestReadDirectory</code> and in which the payload is actively provided (“pushed”) by the application implementation <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=373">AUTOSAR_AP_SWS_Diagnostics §8.10.3 “Class: DataTransferReadByPushHandler”</a>.</p>
<p>In the overall system, three main actors interact:</p>
<ul>
<li><strong>UDS client (diagnostic tester):</strong> Initiates the file or directory transfer via the vehicle diagnostic protocol and requests data blocks sequentially.</li>
<li><strong>Diagnostic Management (<code>ara::diag</code>):</strong> Processes the UDS requests, manages the diagnostic session, and forwards read and termination calls to the application-specific handler <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>.</li>
<li><strong>Application handler:</strong> Implements the class derived from <code>ara::diag::DataTransferReadByPushHandler</code>, reads the data from local memory, and transfers ownership of the payload blocks to <code>ara::diag</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of a handler instance is tightly bound to the duration of a single file transfer session:</p>
<ul>
<li><strong>Creation:</strong> The default constructor is declared as <code>protected</code> <a class="spec-record-ref" data-req="SWS_DM_01516" href="../spec/record.html?id=SWS_DM_01516">[SWS_DM_01516]</a>. Interpretation: The class is designed as a pure base class that must be derived from by the application-specific implementation in order to provide the pure virtual methods.</li>
<li><strong>Ownership and non-copyability:</strong> Copy constructor <a class="spec-record-ref" data-req="SWS_DM_01518" href="../spec/record.html?id=SWS_DM_01518">[SWS_DM_01518]</a> and copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01521" href="../spec/record.html?id=SWS_DM_01521">[SWS_DM_01521]</a> are deleted (<code>=delete</code>). A handler is intended exclusively for exactly one read transfer (“only one way usage i.e. per single file transfer session”).</li>
<li><strong>Moveability:</strong> Move constructor <a class="spec-record-ref" data-req="SWS_DM_01517" href="../spec/record.html?id=SWS_DM_01517">[SWS_DM_01517]</a> and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01520" href="../spec/record.html?id=SWS_DM_01520">[SWS_DM_01520]</a> are defined as default (<code>=default</code>) and are exception-safe (<code>noexcept</code>).</li>
<li><strong>Destruction:</strong> The virtual destructor <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a> has a strict precondition: An instance must under no circumstances be destroyed before the call to <code>ExitRead()</code> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=374">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.1.2 “Destructor”</a>. Interpretation: The destruction prohibition ensures the protocol consistency of the UDS session in Diagnostic Management.</li>
<li><strong>Concurrency:</strong> The methods <code>Read</code> and <code>ExitRead</code> are specified as not thread-safe (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. Parallel calls on the same instance must be avoided on the application side.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical sequence of a read transfer comprises the following steps:</p>
<ol>
<li><strong>Initialization:</strong> Upon arrival of a read request (<code>RequestReadFile</code> or <code>RequestReadDirectory</code>), the application instantiates its concrete handler via the protected constructor <a class="spec-record-ref" data-req="SWS_DM_01516" href="../spec/record.html?id=SWS_DM_01516">[SWS_DM_01516]</a>.</li>
<li><strong>Data transfer (<code>Read</code>):</strong> Diagnostic Management repeatedly calls the pure virtual method <code>Read()</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=376">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.2 “Read”</a>. In doing so, <code>recommended_number_bytes_to_return</code> for throughput optimization, <code>meta_info</code>, and a <code>cancellation_handler</code> are passed. The application compiles the next chunk and transfers its ownership to <code>ara::diag</code> via a <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code>. The payload is placed in the positive UDS response after the <code>blockSequenceCounter</code> as <code>transferResponseParameterRecord</code>.</li>
<li><strong>Termination (<code>ExitRead</code>):</strong> To conclude the transfer, Diagnostic Management calls <code>ExitRead()</code> <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=375">AUTOSAR_AP_SWS_Diagnostics §8.10.3.1.3.1 “ExitRead”</a>. Passed are the termination reason (<code>exit_type</code> of type <code>DataTransferExitType</code>), vehicle manufacturer-specific parameters (<code>transfer_request_parameter_record</code> as <code>ara::core::Span&lt;const ara::core::Byte&gt;</code>), <code>meta_info</code>, and <code>cancellation_handler</code>. The application acknowledges the termination asynchronously via the return future.</li>
<li><strong>Release:</strong> Only after <code>ExitRead()</code> has been completed may the destruction of the handler object take place <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>For error handling and exceptional conditions, the following requirements must be observed:</p>
<ul>
<li><strong>Negative Response Codes (NRC):</strong> Both core methods (<code>Read</code> and <code>ExitRead</code>) are declared as <code>noexcept</code> and do not throw C++ exceptions <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. If an error occurs, the returned <code>ara::core::Future</code> is resolved with a <code>ara::core::ErrorCode</code> from the domain <code>DiagUdsNrcErrc</code> according to ISO 14229-1 to transmit a specific NRC to the client.</li>
<li><strong>Cancellation handling:</strong> The methods receive a <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. The application can query the cancellation status via <code>cancellation_handler.IsCanceled()</code> or register a notification function via <code>cancellation_handler.SetNotifier()</code>. If cancellation is signaled, further data preparation should be aborted.</li>
<li><strong>Validity period of parameters:</strong> The parameter <code>transfer_request_parameter_record</code> passed in <code>ExitRead()</code> is only valid until the associated promise has been fulfilled or processing has been canceled by the <code>CancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01523" href="../spec/record.html?id=SWS_DM_01523">[SWS_DM_01523]</a>. Access outside this time window is impermissible.</li>
<li><strong>Violation of the destruction precondition:</strong> If the instance is destroyed before <code>ExitRead()</code> is called, this constitutes an explicit specification violation <a class="spec-record-ref" data-req="SWS_DM_01519" href="../spec/record.html?id=SWS_DM_01519">[SWS_DM_01519]</a>, which can lead to inconsistent behavior in Diagnostic Management.</li>
</ul>
