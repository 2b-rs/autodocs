<p class="ai-level ai-oneliner-lead" data-ai-level="1">Verwaltet Schlüssel und Zertifikate eines Steuergeräts: Aktualisierung, Parsing und Prüfung von Zertifikatsketten.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Key Manager verwaltet im AUTOSAR-Crypto-Stack das Schlüsselmaterial und die Zertifikate eines Steuergeräts und setzt dazu auf den CSM auf. Das Crypto-Key-Submodul nimmt Schlüssel in einer optionalen Sitzung aus KeyM_Start, KeyM_Prepare, KeyM_Update und KeyM_Finalize entgegen; herstellerspezifische Key Handler lassen sich einbinden. Das Zertifikats-Submodul legt Zertifikate ab, parst sie und prüft sie asynchron gegen eine konfigurierte Kette; das Ergebnis meldet ein Callback <a class="spec-record-ref" data-req="SWS_KeyM_00153" href="../../spec/record.html?id=SWS_KeyM_00153">[SWS_KeyM_00153]</a>. Ein Zertifikat wird erst nach fehlerfreier Prüfung gültig, und erst dann wird sein öffentlicher Schlüssel im CSM freigeschaltet <a class="spec-record-ref" data-req="SWS_KeyM_00170" href="../../spec/record.html?id=SWS_KeyM_00170">[SWS_KeyM_00170]</a>.</p>

<div class="ai-level" data-ai-level="3">
<p>Der Key Manager verwaltet im Crypto-Stack das Schlüsselmaterial und die Zertifikate eines Steuergeräts. Dafür hat er zwei Submodule: Das Crypto-Key-Submodul nimmt Schlüssel von einem Key Master im Fahrzeug oder im Backend entgegen, meist über Diagnosekommandos. Das Zertifikats-Submodul legt Zertifikate ab, parst sie und prüft sie gegen ihre Kette (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_1_Crypto_key_submodule.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_1_Crypto_key_submodule">SWS KeyM S. 24</a>). Nach unten nutzt KeyM den CSM, Pflicht sind Csm_KeyElementGet, Csm_KeyElementSet und Csm_KeySetValid <a class="spec-record-ref" data-req="SWS_KeyM_00076" href="../../spec/record.html?id=SWS_KeyM_00076">[SWS_KeyM_00076]</a>.</p>
<p>Schlüsseloperationen können sitzungsartig ablaufen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_1_1_General_behavior.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_1_1_General_behavior">SWS KeyM S. 25</a>). <code>KeyM_Start()</code> öffnet die Sitzung, <code>KeyM_Prepare()</code> liefert synchron Daten für den Key Server, und <code>KeyM_Finalize()</code> schließt die Sitzung. <code>KeyM_Update()</code> läuft asynchron und meldet sich über <code>KeyM_CryptoKeyUpdateCallbackNotification()</code> zurück (<a class="spec-record-ref" data-req="SWS_KeyM_00052" href="../../spec/record.html?id=SWS_KeyM_00052">[SWS_KeyM_00052]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00077" href="../../spec/record.html?id=SWS_KeyM_00077">[SWS_KeyM_00077]</a>). Optional übernimmt ein Key Handler herstellerspezifische Schritte. <code>KeyM_KH_Update()</code> wird dabei so lange aufgerufen, bis er <code>KEYM_KH_UPDATE_FINISH</code> meldet (<a class="spec-record-ref" data-req="SWS_KeyM_00092" href="../../spec/record.html?id=SWS_KeyM_00092">[SWS_KeyM_00092]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00096" href="../../spec/record.html?id=SWS_KeyM_00096">[SWS_KeyM_00096]</a>).</p>

<p>Zertifikate werden auf zwei Wegen eingebracht. Dauerhaft geschieht das über <code>KeyM_ServiceCertificate()</code>, das der Key Master anstößt <a class="spec-record-ref" data-req="SWS_KeyM_00021" href="../../spec/record.html?id=SWS_KeyM_00021">[SWS_KeyM_00021]</a>. Temporär übergibt ein Aufrufer ein Zertifikat zur Prüfung mit <code>KeyM_SetCertificate()</code> <a class="spec-record-ref" data-req="SWS_KeyM_00057" href="../../spec/record.html?id=SWS_KeyM_00057">[SWS_KeyM_00057]</a>. Jedes Zertifikat führt einen Status nach <code>KeyM_CertificateStatusType</code> <a class="spec-record-ref" data-req="SWS_KeyM_91003" href="../../spec/record.html?id=SWS_KeyM_91003">[SWS_KeyM_91003]</a>. Erst nach fehlerfreier Prüfung wird es <code>KEYM_CERTIFICATE_VALID</code>, und erst dann wird sein öffentlicher Schlüssel im CSM freigeschaltet <a class="spec-record-ref" data-req="SWS_KeyM_00170" href="../../spec/record.html?id=SWS_KeyM_00170">[SWS_KeyM_00170]</a>.</p>

<h4>Rolle im Crypto-Stack: Schlüssel- und Zertifikatsverwaltung oberhalb des CSM</h4>
<p>Der Key Manager (KeyM) ist ein Dienstmodul im AUTOSAR-Crypto-Stack und besteht aus zwei Submodulen. Das Crypto-Key-Submodul initialisiert, aktualisiert und pflegt das Schlüsselmaterial eines Steuergeräts. Das Zertifikats-Submodul legt Zertifikate ab, parst sie und prüft sie gegen ihre Kette (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-eb10eba460c97521.html" data-snip="FIG-eb10eba460c97521">SWS KeyM S. 23</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CAN_FIGURE_Figure_7_2_KEYMANAGER.html" data-snip="SNIP_CLASSIC_CAN_FIGURE_Figure_7_2_KEYMANAGER">SWS KeyM S. 28</a>). Ein typischer Anwendungsfall des Crypto-Key-Submoduls ist die Verteilung von Schlüsseln für die gesicherte Onboard-Kommunikation an CSM-Schlüssel. Die Daten liefert ein Key Master, der im Fahrzeug oder in einem Backend sitzt; die Kommunikation läuft meist über Diagnosekommandos (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_1_Crypto_key_submodule.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_1_Crypto_key_submodule">SWS KeyM S. 24</a>).</p>
<p>Nach unten setzt KeyM auf den CSM auf. Als Pflichtschnittstellen nennt <a class="spec-record-ref" data-req="SWS_KeyM_00076" href="../../spec/record.html?id=SWS_KeyM_00076">[SWS_KeyM_00076]</a> Csm_KeyElementGet, Csm_KeyElementSet und Csm_KeySetValid. Daneben listet <a class="spec-record-ref" data-req="SWS_KeyM_00078" href="../../spec/record.html?id=SWS_KeyM_00078">[SWS_KeyM_00078]</a> Csm_KeyDerive, Csm_SignatureVerify, Det_ReportError und IdsM_SetSecurityEvent. Für die zeitliche Gültigkeitsprüfung importiert KeyM Typen des StbM <a class="spec-record-ref" data-req="SWS_KeyM_00037" href="../../spec/record.html?id=SWS_KeyM_00037">[SWS_KeyM_00037]</a>. Nach oben bietet KeyM C-APIs und RTE-Service-Interfaces für Zertifikate, Zertifikatselemente und Crypto Keys an (<a class="spec-record-ref" data-req="SWS_KeyM_00082" href="../../spec/record.html?id=SWS_KeyM_00082">[SWS_KeyM_00082]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00083" href="../../spec/record.html?id=SWS_KeyM_00083">[SWS_KeyM_00083]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00084" href="../../spec/record.html?id=SWS_KeyM_00084">[SWS_KeyM_00084]</a>). Herstellerspezifische Logik wird über konfigurierbare Key-Handler-Funktionen eingebunden, etwa über <code>KeyM_KH_Start()</code> <a class="spec-record-ref" data-req="SWS_KeyM_00067" href="../../spec/record.html?id=SWS_KeyM_00067">[SWS_KeyM_00067]</a>.</p>

<h4>Initialisierung, Taktung und sicherer Abbau</h4>
<p><code>KeyM_Init()</code> initialisiert das Modul <a class="spec-record-ref" data-req="SWS_KeyM_00043" href="../../spec/record.html?id=SWS_KeyM_00043">[SWS_KeyM_00043]</a>. Der Inhalt von <code>KeyM_ConfigType</code> ist implementierungsspezifisch <a class="spec-record-ref" data-req="SWS_KeyM_00157" href="../../spec/record.html?id=SWS_KeyM_00157">[SWS_KeyM_00157]</a>, und der Konfigurationszeiger soll stets <code>NULL_PTR</code> sein <a class="spec-record-ref" data-req="SWS_KeyM_00158" href="../../spec/record.html?id=SWS_KeyM_00158">[SWS_KeyM_00158]</a>. Nach der Initialisierung haben alle Zertifikate den Status <code>KEYM_CERTIFICATE_NOT_AVAILABLE</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_2_4_Operation_mode.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_2_4_Operation_mode">SWS KeyM S. 34</a>). <code>KeyM_Deinit()</code> setzt das Modul in den uninitialisierten Zustand zurück <a class="spec-record-ref" data-req="SWS_KeyM_00047" href="../../spec/record.html?id=SWS_KeyM_00047">[SWS_KeyM_00047]</a>. Die zugehörige Dokumentstelle fordert zusätzlich, dass das Crypto-Key-Submodul Schlüsselmaterial und Zwischenergebnisse im RAM aktiv überschreibt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_8_3_1_2_KeyM_Deinit.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_8_3_1_2_KeyM_Deinit">SWS KeyM S. 49</a>).</p>
<p>Im Betrieb wird <code>KeyM_MainFunction()</code> periodisch im konfigurierten Intervall aufgerufen <a class="spec-record-ref" data-req="SWS_KeyM_00074" href="../../spec/record.html?id=SWS_KeyM_00074">[SWS_KeyM_00074]</a>. <code>KeyM_MainBackgroundFunction()</code> läuft, wenn das präemptive Betriebssystem keine andere Aufgabe hat. Sie kann zeitaufwendige synchrone Funktionen wie <code>KeyM_KH_Update()</code> aufrufen <a class="spec-record-ref" data-req="SWS_KeyM_00075" href="../../spec/record.html?id=SWS_KeyM_00075">[SWS_KeyM_00075]</a>. Die Periode ist ein Parameter des Containers KeyMGeneral (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-21d8290a2dc9642f.html" data-snip="FIG-21d8290a2dc9642f">SWS KeyM S. 131</a>). <code>KeyM_GetVersionInfo()</code> liefert die Versionsinformation <a class="spec-record-ref" data-req="SWS_KeyM_00049" href="../../spec/record.html?id=SWS_KeyM_00049">[SWS_KeyM_00049]</a>.</p>

<h4>Schlüsselsitzung: von KeyM_Start bis KeyM_Finalize</h4>
<p>Schlüsseloperationen lassen sich sitzungsartig konfigurieren. <code>KeyM_Start()</code> öffnet die Sitzung. Danach nimmt KeyM <code>KeyM_Prepare()</code> und <code>KeyM_Update()</code> an, bis <code>KeyM_Finalize()</code> die Sitzung schließt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_1_1_General_behavior.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_1_1_General_behavior">SWS KeyM S. 25</a>). <code>KeyM_StartType</code> unterscheidet den OEM-Produktionsmodus und den Werkstattmodus; der Produktionsmodus hat die höheren Rechte <a class="spec-record-ref" data-req="SWS_KeyM_00038" href="../../spec/record.html?id=SWS_KeyM_00038">[SWS_KeyM_00038]</a>. Standardmäßig wertet <code>KeyM_Start()</code> keine Eingabedaten aus. Ist KeyMCryptoKeyHandlerStartFinalizeEnabled gesetzt, ruft es <code>KeyM_KH_Start()</code> mit denselben Parametern auf und übernimmt dessen Rückgabewert, etwa für OEM-spezifische Signaturprüfungen (<a class="spec-record-ref" data-req="SWS_KeyM_00050" href="../../spec/record.html?id=SWS_KeyM_00050">[SWS_KeyM_00050]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00067" href="../../spec/record.html?id=SWS_KeyM_00067">[SWS_KeyM_00067]</a>).</p>
<p>Die einzelnen Schritte der Sitzung:</p>
<ul>
<li><code>KeyM_Prepare()</code> arbeitet synchron und liefert vor allem Informationen für den Key Server <a class="spec-record-ref" data-req="SWS_KeyM_00051" href="../../spec/record.html?id=SWS_KeyM_00051">[SWS_KeyM_00051]</a>. Sind KeyMCryptoKeyPrepareFunctionEnabled und KeyMCryptoKeyHandlerPrepareEnabled gesetzt, ruft KeyM sofort <code>KeyM_KH_Prepare()</code> auf (<a class="spec-record-ref" data-req="SWS_KeyM_00068" href="../../spec/record.html?id=SWS_KeyM_00068">[SWS_KeyM_00068]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_8_7_3_2_KeyM_KH_Prepare.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_8_7_3_2_KeyM_KH_Prepare">SWS KeyM S. 82</a>).</li>
<li><code>KeyM_Update()</code> ist asynchron. Das Ende meldet <code>KeyM_CryptoKeyUpdateCallbackNotification()</code> (<a class="spec-record-ref" data-req="SWS_KeyM_00052" href="../../spec/record.html?id=SWS_KeyM_00052">[SWS_KeyM_00052]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00077" href="../../spec/record.html?id=SWS_KeyM_00077">[SWS_KeyM_00077]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00150" href="../../spec/record.html?id=SWS_KeyM_00150">[SWS_KeyM_00150]</a>). Der Aufrufer darf den übergebenen Ergebnispuffer bis zu diesem Callback nicht anfassen; der Callback gibt denselben Zeiger zurück <a class="spec-record-ref" data-req="SWS_KeyM_00156" href="../../spec/record.html?id=SWS_KeyM_00156">[SWS_KeyM_00156]</a>.</li>
<li><code>KeyM_Finalize()</code> ist ebenfalls asynchron und versetzt die Schlüsseloperation in den Ruhezustand (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_8_3_2_4_KeyM_Finalize.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_8_3_2_4_KeyM_Finalize">SWS KeyM S. 56</a>). Mit aktiviertem Key Handler delegiert es an <code>KeyM_KH_Finalize()</code> (<a class="spec-record-ref" data-req="SWS_KeyM_00053" href="../../spec/record.html?id=SWS_KeyM_00053">[SWS_KeyM_00053]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00070" href="../../spec/record.html?id=SWS_KeyM_00070">[SWS_KeyM_00070]</a>). <code>KeyM_CryptoKeyFinalizeCallbackNotification()</code> meldet, ob alle Schlüssel erfolgreich validiert wurden (<a class="spec-record-ref" data-req="SWS_KeyM_00079" href="../../spec/record.html?id=SWS_KeyM_00079">[SWS_KeyM_00079]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00080" href="../../spec/record.html?id=SWS_KeyM_00080">[SWS_KeyM_00080]</a>).</li>
</ul>
<p>Außerhalb der Sitzung prüft <code>KeyM_Verify()</code> Schlüssel synchron oder asynchron <a class="spec-record-ref" data-req="SWS_KeyM_00054" href="../../spec/record.html?id=SWS_KeyM_00054">[SWS_KeyM_00054]</a>. Bei KeyMCryptoKeyVerifyAsyncMode = TRUE kommt das Ergebnis über <code>KeyM_CryptoKeyVerifyCallbackNotification()</code> (<a class="spec-record-ref" data-req="SWS_KeyM_00081" href="../../spec/record.html?id=SWS_KeyM_00081">[SWS_KeyM_00081]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00151" href="../../spec/record.html?id=SWS_KeyM_00151">[SWS_KeyM_00151]</a>). Ein Key Handler lässt sich über <code>KeyM_KH_Verify()</code> einbinden <a class="spec-record-ref" data-req="SWS_KeyM_00071" href="../../spec/record.html?id=SWS_KeyM_00071">[SWS_KeyM_00071]</a>.</p>

<h4>KeyM_Update im Detail: Schlüsselauswahl und Key-Handler-Schleife</h4>
<p>Zuerst bestimmt KeyM den Zielschlüssel:</p>
<ul>
<li>Mit Schlüsselnamen sucht KeyM den KeyMCryptoKey-Container mit passendem KeyMCryptoKeyName <a class="spec-record-ref" data-req="SWS_KeyM_00091" href="../../spec/record.html?id=SWS_KeyM_00091">[SWS_KeyM_00091]</a>.</li>
<li>Ohne gültigen Namen und bei definierten KeyMCryptoKeyCryptoProps deutet KeyM die RequestData als SHE-Werte M1M2M3 und gleicht die Bits 121..124 ab <a class="spec-record-ref" data-req="SWS_KeyM_00154" href="../../spec/record.html?id=SWS_KeyM_00154">[SWS_KeyM_00154]</a>.</li>
<li>Lässt sich keine KeyID ermitteln und ist kein Update-Key-Handler aktiv, endet der Aufruf mit <code>KEYM_E_PARAMETER_MISMATCH</code> <a class="spec-record-ref" data-req="SWS_KeyM_00155" href="../../spec/record.html?id=SWS_KeyM_00155">[SWS_KeyM_00155]</a>.</li>
</ul>
<p>Mit KeyMCryptoKeyHandlerUpdateEnabled ruft <code>KeyM_Update()</code> die Funktion <code>KeyM_KH_Update()</code> auf. Es übergibt die Anfragedaten, den Namen und die gefundene KeymId, sonst 0xFFFFFFFFul <a class="spec-record-ref" data-req="SWS_KeyM_00092" href="../../spec/record.html?id=SWS_KeyM_00092">[SWS_KeyM_00092]</a>. Dazu stellt KeyM einen internen Puffer bereit, den es bis zur Rückkehr des Handlers nicht anfasst <a class="spec-record-ref" data-req="SWS_KeyM_00097" href="../../spec/record.html?id=SWS_KeyM_00097">[SWS_KeyM_00097]</a>. Die Rückmeldung des Handlers steuert den weiteren Ablauf <a class="spec-record-ref" data-req="SWS_KeyM_00055" href="../../spec/record.html?id=SWS_KeyM_00055">[SWS_KeyM_00055]</a>:</p>
<ul>

<h4>Zertifikate: dauerhafte und temporäre Ablage, Hierarchie und Status</h4>
<p>Für dauerhaft gespeicherte Zertifikate gibt es <code>KeyM_ServiceCertificate()</code>. Das Zertifikats-Submodul stellt die Funktion bereit, wenn KeyMServiceCertificateFunctionEnabled und KeyMCertificateManagerEnabled gesetzt sind; aufgerufen wird sie vom Key Master <a class="spec-record-ref" data-req="SWS_KeyM_00021" href="../../spec/record.html?id=SWS_KeyM_00021">[SWS_KeyM_00021]</a>. <code>KeyM_ServiceCertificateType</code> unterscheidet folgende Dienste <a class="spec-record-ref" data-req="SWS_KeyM_00039" href="../../spec/record.html?id=SWS_KeyM_00039">[SWS_KeyM_00039]</a>:</p>
<ul>
<li>CSR anfordern und signiertes CSR zurückgeben,</li>
<li>Root- und Zwischenzertifikate setzen oder aktualisieren,</li>
<li>CRL bereitstellen oder aktualisieren.</li>
</ul>
<p>Der Dienst läuft asynchron und meldet sich über <code>KeyM_ServiceCertificateCallbackNotification()</code> (<a class="spec-record-ref" data-req="SWS_KeyM_00056" href="../../spec/record.html?id=SWS_KeyM_00056">[SWS_KeyM_00056]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00149" href="../../spec/record.html?id=SWS_KeyM_00149">[SWS_KeyM_00149]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00152" href="../../spec/record.html?id=SWS_KeyM_00152">[SWS_KeyM_00152]</a>). Versuche, Root- oder Zwischenzertifikate zu installieren oder zu aktualisieren, sind als Sicherheitsereignisse definiert (<a class="spec-record-ref" data-req="SWS_KeyM_00172" href="../../spec/record.html?id=SWS_KeyM_00172">[SWS_KeyM_00172]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_4_Security_Events.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_4_Security_Events">SWS KeyM S. 38</a>).</p>

<p class="diagram-note">Strukturdiagramm: In einer dreistufigen Kette verweist jedes KeyMCertificate auf sein oberes Zertifikat (Root auf sich selbst) sowie auf CSM-Job und CSM-Schlüssel für die Signaturprüfung. Quellen: <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-184e708d9b59a652.html" data-snip="FIG-184e708d9b59a652">SWS KeyM S. 22</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_2_3_Certificate_configuration.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_2_3_Certificate_configuration">SWS KeyM S. 31</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00170" href="../../spec/record.html?id=SWS_KeyM_00170">[SWS_KeyM_00170]</a></p>
<p>Jedes Zertifikat hat einen Status vom Typ <code>KeyM_CertificateStatusType</code> <a class="spec-record-ref" data-req="SWS_KeyM_91003" href="../../spec/record.html?id=SWS_KeyM_91003">[SWS_KeyM_91003]</a>, den <code>KeyM_CertGetStatus()</code> abfragt <a class="spec-record-ref" data-req="SWS_KeyM_00066" href="../../spec/record.html?id=SWS_KeyM_00066">[SWS_KeyM_00066]</a>. Der Lebenszyklus:</p>
<ul>
<li>Nach <code>KeyM_Init()</code> gilt <code>KEYM_CERTIFICATE_NOT_AVAILABLE</code>.</li>
<li><code>KeyM_SetCertificate()</code> mit certDataLength = 0 setzt Zertifikat und Status zurück (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_2_4_Operation_mode.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_2_4_Operation_mode">SWS KeyM S. 34</a>).</li>
<li>Gesetzte Daten durchlaufen das Parsing (NOT_PARSED → PARSED_NOT_VALIDATED) und danach die Prüfung (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-8e89b05254c6216d.html" data-snip="FIG-8e89b05254c6216d">SWS KeyM S. 24</a>).</li>
<li>Erst nach fehlerfreier Prüfung schaltet KeyM den öffentlichen Schlüssel per <code>Csm_KeySetValid()</code> frei und setzt <code>KEYM_CERTIFICATE_VALID</code> <a class="spec-record-ref" data-req="SWS_KeyM_00170" href="../../spec/record.html?id=SWS_KeyM_00170">[SWS_KeyM_00170]</a>.</li>
</ul>
<p>Interpretation: <code>KEYM_E_CERTIFICATE_INVALID_CONTENT</code> dürfte zu den Parsing-Fehlern und <code>KEYM_E_CERTIFICATE_REVOKED</code> zu den Prüffehlern zählen. Ausdrücklich belegt ist das nur für INVALID_FORMAT und INVALID_TYPE (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-1a22d27c48ec5ec8.html" data-snip="FIG-1a22d27c48ec5ec8">SWS KeyM S. 33</a>).</p>

<h4>Zertifikatsprüfung und Zugriff auf Zertifikatsinhalte</h4>
<p>Für die Prüfung gibt es drei asynchrone, nicht reentrante Aufträge:</p>
<ul>
<li><code>KeyM_VerifyCertificate()</code> ermittelt die zugehörige Kette selbst (<a class="spec-record-ref" data-req="SWS_KeyM_00060" href="../../spec/record.html?id=SWS_KeyM_00060">[SWS_KeyM_00060]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_8_3_3_5_KeyM_VerifyCertificate.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_8_3_3_5_KeyM_VerifyCertificate">SWS KeyM S. 68</a>).</li>
<li><code>KeyM_VerifyCertificates()</code> prüft ein unteres gegen ein oberes Zertifikat <a class="spec-record-ref" data-req="SWS_KeyM_00059" href="../../spec/record.html?id=SWS_KeyM_00059">[SWS_KeyM_00059]</a>.</li>
<li><code>KeyM_VerifyCertificateChain()</code> erhält eine nach PKI-Reihenfolge sortierte Zertifikatsliste <a class="spec-record-ref" data-req="SWS_KeyM_00061" href="../../spec/record.html?id=SWS_KeyM_00061">[SWS_KeyM_00061]</a>.</li>
</ul>
<p>Hat KeyM den Auftrag mit E_OK angenommen und ist KeyMCertificateVerifyCallbackNotificationFunc konfiguriert, meldet der Callback das Ergebnis als <code>KeyM_CertificateStatusType</code> (<a class="spec-record-ref" data-req="SWS_KeyM_00153" href="../../spec/record.html?id=SWS_KeyM_00153">[SWS_KeyM_00153]</a>, <a class="spec-record-ref" data-req="SWS_KeyM_00073" href="../../spec/record.html?id=SWS_KeyM_00073">[SWS_KeyM_00073]</a>). Ist diese Funktion NULL, gibt es stattdessen den Required Port KeyMCertificateNotification <a class="spec-record-ref" data-req="SWS_KeyM_00161" href="../../spec/record.html?id=SWS_KeyM_00161">[SWS_KeyM_00161]</a>. Laut den vorliegenden DCM-Dokumentstellen aus späteren Releases nutzt der DCM diesen Weg für die Authentifizierung (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_7_4_2_10_2_Verify_Certificates.html" data-snip="SNIP_CLASSIC_DCM_SECTION_7_4_2_10_2_Verify_Certificates">SWS DCM S. 147</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_8_4_11_Dcm_KeyMAsyncCertificateVerifyFinished.html" data-snip="SNIP_CLASSIC_DCM_SECTION_8_4_11_Dcm_KeyMAsyncCertificateVerifyFinished">SWS DCM S. 245</a>).</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Bei aktivierter Entwicklungsfehlererkennung prüft KeyM bei jedem Aufruf:</p>
<ul>
<li>den Initialisierungszustand (<code>KEYM_E_UNINIT</code>) <a class="spec-record-ref" data-req="SWS_KeyM_00144" href="../../spec/record.html?id=SWS_KeyM_00144">[SWS_KeyM_00144]</a>,</li>
<li>die Größe der Ergebnispuffer (<code>KEYM_E_SMALL_BUFFER</code>) <a class="spec-record-ref" data-req="SWS_KeyM_00145" href="../../spec/record.html?id=SWS_KeyM_00145">[SWS_KeyM_00145]</a>,</li>
<li>Null-Zeiger (<code>KEYM_E_PARAM_POINTER</code>) <a class="spec-record-ref" data-req="SWS_KeyM_00146" href="../../spec/record.html?id=SWS_KeyM_00146">[SWS_KeyM_00146]</a>.</li>
</ul>
<p>Weitere Entwicklungsfehler sind <code>KEYM_E_INIT_FAILED</code> und <code>KEYM_E_CONFIG_FAILURE</code> <a class="spec-record-ref" data-req="SWS_KeyM_00036" href="../../spec/record.html?id=SWS_KeyM_00036">[SWS_KeyM_00036]</a>. Ist die Speicherklasse eines Zertifikats KEYM_STORAGE_IN_CSM oder KEYM_STORAGE_IN_NVM, meldet KeyM <code>KEYM_E_CONFIG_FAILURE</code>; ohne Entwicklungsmodus gibt es E_NOT_OK zurück <a class="spec-record-ref" data-req="SWS_KeyM_00166" href="../../spec/record.html?id=SWS_KeyM_00166">[SWS_KeyM_00166]</a>. Interpretation: Das betrifft vermutlich den temporären Ablageweg über <code>KeyM_SetCertificate()</code>, der laut Dokumentstelle für den RAM gedacht ist (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_7_2_3_Certificate_configuration.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_7_2_3_Certificate_configuration">SWS KeyM S. 31</a>).</p>
<p>Laufzeitfehler treten auf drei Ebenen auf:</p>
<ul>
<li>Synchrone Rückgaben nutzen KeyM-Codes wie <code>KEYM_E_BUSY</code>, <code>KEYM_E_PENDING</code>, <code>KEYM_E_KEY_CERT_SIZE_MISMATCH</code> oder <code>KEYM_E_PARAMETER_MISMATCH</code> <a class="spec-record-ref" data-req="SWS_KeyM_00040" href="../../spec/record.html?id=SWS_KeyM_00040">[SWS_KeyM_00040]</a>. Prüfaufträge lehnen schon bei der Annahme leere Zertifikatsplätze (<code>KEYM_E_KEY_CERT_EMPTY</code>) und ungültige obere Zertifikate (<code>KEYM_E_CERT_INVALID_CHAIN_OF_TRUST</code>) ab (<a class="spec-record-ref" data-req="SWS_KeyM_00060" href="../../spec/record.html?id=SWS_KeyM_00060">[SWS_KeyM_00060]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_KEYM_SECTION_8_3_3_5_KeyM_VerifyCertificate.html" data-snip="SNIP_CLASSIC_KEYM_SECTION_8_3_3_5_KeyM_VerifyCertificate">SWS KeyM S. 68</a>).</li>
<li>Asynchrone Schlüssel- und Zertifikatsdienste melden ihr Ergebnis als <code>KeyM_ResultType</code>, etwa <code>KEYM_RT_KEY_CERT_WRITE_FAIL</code> oder <code>KEYM_RT_CERT_INVALID_CHAIN_OF_TRUST</code> <a class="spec-record-ref" data-req="SWS_KeyM_91008" href="../../spec/record.html?id=SWS_KeyM_91008">[SWS_KeyM_91008]</a>.</li>
