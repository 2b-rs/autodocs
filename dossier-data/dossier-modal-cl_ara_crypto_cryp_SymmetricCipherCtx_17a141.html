<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient als Schnittstelle für symmetrische Verschlüsselungs- und Entschlüsselungsoperationen in Datenströmen oder Einzelaufrufen.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::crypto::cryp::SymmetricCipherCtx</code> dient als threadsichere Schnittstelle für symmetrische Verschlüsselungs- und Entschlüsselungsoperationen in AUTOSAR Adaptive <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>. Nach Konfiguration eines Schlüssels über <code>SetKey()</code> können Daten entweder in einem einzelnen Aufruf oder schrittweise in einem Streaming-Zyklus aus <code>Start()</code>, <code>Update()</code> und <code>Finish()</code> verarbeitet werden <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>. Alle Methoden sind als <code>noexcept</code> spezifiziert und signalisieren Fehler wie fehlende Initialisierung oder zu kleine Puffer über <code>ara::core::Result</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::crypto::cryp::SymmetricCipherCtx</code> kapselt symmetrische kryptografische Transformationen, welche sowohl Verschlüsselungs- als auch Entschlüsselungsoperationen umfassen. Innerhalb der Krypto-Architektur agiert die Klasse als Ausführungskontext für symmetrische Algorithmen und kooperiert mit Schlüsselobjekten sowie Speicherpuffern. Zur Konfiguration des kryptografischen Schlüssels interagiert die Klasse entweder direkt mit flüchtigen Schlüsseln über <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a> oder mit persistent bzw. isoliert verwalteten Schlüsseln über <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50043" href="../spec/record.html?id=SWS_CRYPT_50043">[SWS_CRYPT_50043]</a>. Zu verarbeitende Klar- und Chiffretexte sowie Initialisierungsvektoren (IV) werden über Speicherbereiche vom Typ <code>ReadOnlyMemRegion</code> und <code>ReadWriteMemRegion</code> übergeben und empfangen <a class="spec-record-ref" data-req="SWS_CRYPT_50048" href="../spec/record.html?id=SWS_CRYPT_50048">[SWS_CRYPT_50048]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Lebenszyklus und Besitzverhältnisse der Schnittstelle werden primär über den typisierten Smart-Pointer-Alias <code>Sptr</code> (<code>std::shared_ptr&lt;SymmetricCipherCtx&gt;</code>) gesteuert <a class="spec-record-ref" data-req="SWS_CRYPT_50137" href="../spec/record.html?id=SWS_CRYPT_50137">[SWS_CRYPT_50137]</a>. Die Bereitstellung einer konkreten Instanz dürfte in der Praxis über eine übergeordnete Krypto-Fabrikmethode erfolgen (Interpretation), da die Schnittstellendefinition selbst keine Erzeugungsfunktionen ausweist.</p>
<p>Nach der Instanziierung durchläuft der Kontext mehrere Betriebsphasen:</p>
<ul>
<li><strong>Nicht initialisiert:</strong> Unmittelbar nach der Instanziierung ist dem Kontext kein Schlüssel zugeordnet. Jeder Verarbeitungsaufruf in dieser Phase führt zum Fehler <code>CryptoErrc::kUninitializedContext</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a>.</li>
<li><strong>Initialisiert / Schlüssel gebunden:</strong> Durch Aufruf von <code>SetKey()</code> mit einem <code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a> oder <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50043" href="../spec/record.html?id=SWS_CRYPT_50043">[SWS_CRYPT_50043]</a> wird der Kontext einsatzbereit. Aus diesem Zustand heraus können entweder zustandslose Single-Call-Operationen ausgeführt oder ein zustandsbehafteter Streaming-Prozess gestartet werden.</li>
<li><strong>Streaming-Verarbeitung:</strong> Ein Aufruf von <code>Start()</code> leitet eine schrittweise Transformation ein <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a>. In dieser Phase können Daten über <code>Update()</code> transformiert <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a> und die Position via <code>Seek()</code> modifiziert werden <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a>. Der Streaming-Zustand wird regulär durch <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a> bzw. <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a> beendet oder vorzeitig via <code>Cancel()</code> verworfen <a class="spec-record-ref" data-req="SWS_CRYPT_50046" href="../spec/record.html?id=SWS_CRYPT_50046">[SWS_CRYPT_50046]</a>. Danach kehrt der Kontext in den initialisierten Grundzustand zurück.</li>
</ul>
<p>Sämtliche Methoden von <code>SymmetricCipherCtx</code> sind als <code>noexcept</code> deklariert, gewährleisten Ausnahme-Sicherheit („exception safe“) und sind für den nebenläufigen Zugriff als threadsicher („thread-safe“) spezifiziert <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Vor der eigentlichen Datentransformation empfiehlt sich die Bestimmung der geforderten Puffer- und Chunkgrößen. Über <code>GetMinimumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50144" href="../spec/record.html?id=SWS_CRYPT_50144">[SWS_CRYPT_50144]</a> und <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50050" href="../spec/record.html?id=SWS_CRYPT_50050">[SWS_CRYPT_50050]</a> lassen sich die zulässigen Grenzen für Eingabeblöcke ermitteln. Falls Initialisierungsvektoren erforderlich sind, können deren Längengrenzen mittels <code>GetMinimumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50141" href="../spec/record.html?id=SWS_CRYPT_50141">[SWS_CRYPT_50141]</a>, <code>GetMaximumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50142" href="../spec/record.html?id=SWS_CRYPT_50142">[SWS_CRYPT_50142]</a> oder <code>GetOutputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50143" href="../spec/record.html?id=SWS_CRYPT_50143">[SWS_CRYPT_50143]</a> abgefragt werden. Die maximal notwendige Zielpuffergröße für eine Operation wird mittels <code>GetRequiredOutputBufferSize()</code> berechnet <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a>.</p>
<p>Für die schrittweise Stream-Verschlüsselung oder -Entschlüsselung gilt folgender Standardablauf:</p>
<ol>
<li><strong>Schlüssel konfigurieren:</strong> Bindung des kryptografischen Schlüssels an den Kontext via <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a>.</li>
<li><strong>Transformation starten:</strong> Aufruf von <code>Start()</code> unter Angabe von Transformationsrichtung (Verschlüsselung oder Entschlüsselung) und optionalem IV <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a> bzw. ohne IV <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>.</li>
<li><strong>Datenblöcke transformieren:</strong> Wiederholter Aufruf von <code>Update()</code> zur schrittweisen Übergabe von Eingabedaten und Entnahme der Ausgabedaten <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>. Bei Bedarf kann innerhalb des Datenstroms über <code>Seek()</code> navigiert werden <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a>.</li>
<li><strong>Abschluss:</strong> Finalisierung über <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a> oder über <code>FinishEncrypt()</code>, sofern der vom Kontext erzeugte IV zurückgegeben werden soll <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>.</li>
</ol>
<p>Alternativ zu diesem Streaming-Muster unterstützt die Schnittstelle synchrone Einzelaufrufe. Liegt die gesamte Nutzlast vor, kann die Operation direkt über <code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a>, <code>ProcessSingleCallWithInputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50048" href="../spec/record.html?id=SWS_CRYPT_50048">[SWS_CRYPT_50048]</a> oder für kontexteigene IV-Generierung über <code>EncryptSingleCallWithOutputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a> ausgeführt werden.</p>

<h4>Fehlerszenarien</h4>
<p>Methoden der Klasse signalisieren Fehler über <code>ara::core::Result</code> mit Codes der Fehlerdomäne <code>ara::crypto::CryptoErrc</code>. Wesentliche Fehlerbedingungen umfassen:</p>
<ul>
<li><code>CryptoErrc::kUninitializedContext</code>: Tritt auf, wenn Verarbeitungsaufrufe wie <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>, Single-Call-Routinen <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a> oder <code>GetRequiredOutputBufferSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a> aufgerufen werden, bevor ein Schlüssel über <code>SetKey()</code> hinterlegt wurde.</li>
<li><code>CryptoErrc::kProcessingNotStarted</code>: Wird ausgelöst, wenn Streaming-Funktionen wie <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>, <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a>, <code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>, <code>Seek()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a> oder <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50046" href="../spec/record.html?id=SWS_CRYPT_50046">[SWS_CRYPT_50046]</a> ohne vorherigen erfolgreichen <code>Start()</code>-Aufruf ausgeführt werden.</li>
<li><code>CryptoErrc::kInsufficientCapacity</code>: Der bereitgestellte Zielpuffer für Daten oder IVs ist kleiner als die minimal benötigte Kapazität <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a>.</li>
