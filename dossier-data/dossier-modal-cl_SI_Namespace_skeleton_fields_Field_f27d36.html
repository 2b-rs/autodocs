<h4>Context</h4>
<p>The C++ class <code>&lt;Field&gt;</code> in namespace <code>&lt;SI-Namespace&gt;::skeleton::fields</code> represents the server-side interface of a single field defined in a ServiceInterface in the role <em>field</em> (module <code>com</code> of the AUTOSAR Adaptive Platform). A field combines state data with optional read (Get), write (Set), and notification mechanisms (Notifier). The associated data type is provided via the type alias <code>FieldType</code> (<a class="spec-record-ref" data-req="SWS_CM_11402" href="../spec/record.html?id=SWS_CM_11402">[SWS_CM_11402]</a>).</p>
<p>The class mediates between the following main interaction partners:</p>
<ul>
<li><strong>Provider application:</strong> The actual service implementation. It registers callback functions for incoming read and write operations and initiates value updates.</li>
<li><strong>Skeleton field instance (<code>&lt;Field&gt;</code>):</strong> Manages the registered callbacks, monitors invocation conditions, and acts as a link between service logic and transmission infrastructure.</li>
<li><strong>Communication layer and clients:</strong> Forwards remote read and write requests from service clients and transmits Notifier notifications to active subscribers.</li>
</ul>
<p>In addition, an execution context such as <code>ara::core::Executor</code> can be integrated via the template argument <code>ExecutorT</code>, in which the registered handlers are executed asynchronously (<a class="spec-record-ref" data-req="SWS_CM_11360" href="../spec/record.html?id=SWS_CM_11360">[SWS_CM_11360]</a>, <a class="spec-record-ref" data-req="SWS_CM_11362" href="../spec/record.html?id=SWS_CM_11362">[SWS_CM_11362]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=11">EXP ARAComAPI p. 11</a>).</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a Field instance comprises configuration, operational, and termination phases:</p>
<ul>
<li><strong>Creation and ownership:</strong> For each field modeled in the ServiceInterface, an instance of <code>&lt;Field&gt;</code> exists as part of the service skeleton. Its lifetime is likely firmly coupled to the lifetime of the enclosing skeleton instance.</li>
<li><strong>Configuration and registration:</strong> Prior to activating the service offering, the service implementation registers the required callbacks. If <code>Field.hasGetter == TRUE</code> is configured in the model, <code>RegisterGetHandler</code> is available (<a class="spec-record-ref" data-req="SWS_CM_00114" href="../spec/record.html?id=SWS_CM_00114">[SWS_CM_00114]</a>). If <code>Field.hasSetter == TRUE</code> is set, <code>RegisterSetHandler</code> is provided (<a class="spec-record-ref" data-req="SWS_CM_00116" href="../spec/record.html?id=SWS_CM_00116">[SWS_CM_00116]</a>). Both methods also exist in an overload with a <code>ExecutorT</code> parameter for context-bound execution (<a class="spec-record-ref" data-req="SWS_CM_11360" href="../spec/record.html?id=SWS_CM_11360">[SWS_CM_11360]</a>, <a class="spec-record-ref" data-req="SWS_CM_11362" href="../spec/record.html?id=SWS_CM_11362">[SWS_CM_11362]</a>). Optionally, an E2E error handler can be registered using <code>SetTransportFaultConditionHandler</code> to monitor transport errors (<a class="spec-record-ref" data-req="SWS_CM_00096" href="../spec/record.html?id=SWS_CM_00096">[SWS_CM_00096]</a>, <a class="spec-record-ref" data-req="SWS_CM_00097" href="../spec/record.html?id=SWS_CM_00097">[SWS_CM_00097]</a>).</li>
<li><strong>Operational phase:</strong> Incoming Get and Set requests are served via the registered callbacks. In the event of state changes, the service implementation calls the method <code>Update()</code> (<a class="spec-record-ref" data-req="SWS_CM_00119" href="../spec/record.html?id=SWS_CM_00119">[SWS_CM_00119]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=11">EXP ARAComAPI p. 11</a>). If <code>Field.hasNotifier == TRUE</code> is defined in the interface model, <code>Update()</code> transmits the new value to all subscribers and updates the internal state of the field.</li>
<li><strong>Cleanup:</strong> A previously set transport error handler can be explicitly removed again via <code>UnsetTransportFaultConditionHandler</code> (<a class="spec-record-ref" data-req="SWS_CM_00098" href="../spec/record.html?id=SWS_CM_00098">[SWS_CM_00098]</a>). The release of the Field instance occurs upon destruction of the skeleton.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical sequence when using a fully equipped field (getter, setter, and notifier active) comprises the following steps:</p>
<ol>
<li><strong>Register Get handler:</strong> The application registers a function of type <code>std::function&lt;ara::core::Future&lt;FieldType&gt;()&gt;</code> (<a class="spec-record-ref" data-req="SWS_CM_00114" href="../spec/record.html?id=SWS_CM_00114">[SWS_CM_00114]</a>) via <code>RegisterGetHandler</code> that asynchronously provides the current state upon incoming read requests.</li>
<li><strong>Register Set handler:</strong> Via <code>RegisterSetHandler</code>, the application passes a callable of type <code>std::function&lt;ara::core::Future&lt;FieldType&gt;(value)&gt;</code> (<a class="spec-record-ref" data-req="SWS_CM_00116" href="../spec/record.html?id=SWS_CM_00116">[SWS_CM_00116]</a>) that checks and accepts new values and returns the resulting field value.</li>
<li><strong>Update and publish values:</strong> If the field value changes on the server side, the service implementation calls <code>Update(value)</code> (<a class="spec-record-ref" data-req="SWS_CM_00119" href="../spec/record.html?id=SWS_CM_00119">[SWS_CM_00119]</a>). The communication infrastructure sends the update to all registered subscribers.</li>
<li><strong>Process requests:</strong> If read or write requests from clients are received via the communication layer, the middleware forwards them to the previously registered handlers. If an executor was configured (<a class="spec-record-ref" data-req="SWS_CM_11360" href="../spec/record.html?id=SWS_CM_11360">[SWS_CM_11360]</a>, <a class="spec-record-ref" data-req="SWS_CM_11362" href="../spec/record.html?id=SWS_CM_11362">[SWS_CM_11362]</a>), execution takes place within its context.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using the Field class, the following error and exception conditions are specified:</p>
<ul>
<li><strong>Invalid handlers (<code>InvalidHandlerViolation</code>):</strong> If a callable that does not exist or is null is passed to <code>RegisterGetHandler</code> (<a class="spec-record-ref" data-req="SWS_CM_00114" href="../spec/record.html?id=SWS_CM_00114">[SWS_CM_00114]</a>, <a class="spec-record-ref" data-req="SWS_CM_11360" href="../spec/record.html?id=SWS_CM_11360">[SWS_CM_11360]</a>), <code>RegisterSetHandler</code> (<a class="spec-record-ref" data-req="SWS_CM_00116" href="../spec/record.html?id=SWS_CM_00116">[SWS_CM_00116]</a>, <a class="spec-record-ref" data-req="SWS_CM_11362" href="../spec/record.html?id=SWS_CM_11362">[SWS_CM_11362]</a>), or <code>SetTransportFaultConditionHandler</code> (<a class="spec-record-ref" data-req="SWS_CM_00096" href="../spec/record.html?id=SWS_CM_00096">[SWS_CM_00096]</a>, <a class="spec-record-ref" data-req="SWS_CM_00097" href="../spec/record.html?id=SWS_CM_00097">[SWS_CM_00097]</a>), an <code>InvalidHandlerViolation</code> is present.</li>
<li><strong>Violation of the minimum transmission interval:</strong> The <code>Update()</code> method returns a <code>ara::core::Result&lt;void&gt;</code> (<a class="spec-record-ref" data-req="SWS_CM_00119" href="../spec/record.html?id=SWS_CM_00119">[SWS_CM_00119]</a>).
