<h4>Context</h4>
<p>The class <code>ara::core::ErrorDomain</code> forms the central control instance for error values within the error handling model of AUTOSAR Adaptive. It defines the scope as well as the mapping of domain-specific, numeric error codes (<code>CodeType</code> as <code>std::int32_t</code> <a class="spec-record-ref" data-req="SWS_CORE_00122" href="../spec/record.html?id=SWS_CORE_00122">[SWS_CORE_00122]</a>) to meaningful text messages. As a base class, it serves to specify concrete error domains. The class is designed as a Literal Type, and derived classes shall also be implemented as Literal Types.</p>
<p>In the system architecture, <code>ara::core::ErrorDomain</code> acts as a link between error codes, concrete subclasses, the caller (client), and the exception mechanism. In addition to the integer error code, an <code>ara::core::ErrorCode</code> always encapsulates a reference to its controlling error domain. This prevents identical numeric values from different functional areas from being erroneously equated. If required, the domain handles text resolution or converts error codes directly into typed exceptions (<code>ara::core::Exception</code>).</p>

<h4>Lifecycle</h4>
<p>The creation of an <code>ara::core::ErrorDomain</code> occurs exclusively via derived subclasses, as the constructor is declared protected (<code>protected</code>) <a class="spec-record-ref" data-req="SWS_CORE_00135" href="../spec/record.html?id=SWS_CORE_00135">[SWS_CORE_00135]</a>. It accepts a domain-specific identifier (<code>IdType</code> as <code>std::uint64_t</code> <a class="spec-record-ref" data-req="SWS_CORE_00121" href="../spec/record.html?id=SWS_CORE_00121">[SWS_CORE_00121]</a>), which must strictly be system-wide unique. Through the qualification as <code>constexpr</code> and <code>noexcept</code>, initialization can already take place at compile time.</p>
<p>With regard to ownership and copy semantics, the class prevents any duplication and movement: Both copy and move constructors (<a class="spec-record-ref" data-req="SWS_CORE_00131" href="../spec/record.html?id=SWS_CORE_00131">[SWS_CORE_00131]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00132" href="../spec/record.html?id=SWS_CORE_00132">[SWS_CORE_00132]</a>) as well as the associated assignment operators (<a class="spec-record-ref" data-req="SWS_CORE_00133" href="../spec/record.html?id=SWS_CORE_00133">[SWS_CORE_00133]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00134" href="../spec/record.html?id=SWS_CORE_00134">[SWS_CORE_00134]</a>) are defined as deleted (<code>= delete</code>). Instances of concrete subclasses are therefore likely to be provided as permanent, immutable singleton objects in typical AUTOSAR Adaptive systems.</p>
<p>The destructor is standardized as trivial (<code>= default</code>) and declared <code>protected</code> <a class="spec-record-ref" data-req="SWS_CORE_00136" href="../spec/record.html?id=SWS_CORE_00136">[SWS_CORE_00136]</a>. It is intentionally designed as non-virtual so that the class preserves the properties of a Literal Type; polymorphic destruction via base class pointers is neither intended nor required in the system concept. Return values of inspector methods such as <code>Name()</code> <a class="spec-record-ref" data-req="SWS_CORE_00152" href="../spec/record.html?id=SWS_CORE_00152">[SWS_CORE_00152]</a> and <code>Message()</code> <a class="spec-record-ref" data-req="SWS_CORE_00153" href="../spec/record.html?id=SWS_CORE_00153">[SWS_CORE_00153]</a> return pointers to constant null-terminated strings (<code>const char*</code>). These strings remain the property of the subclass and must not be freed by calling clients. All member functions of the class are specified as thread-safe (<code>thread-safe</code>).</p>

<h4>Usage Path</h4>
<p>The typical usage flow for checking, text resolution, and forwarding of errors comprises the following steps:</p>
<ol>
<li><strong>Identity check and domain comparison:</strong> The unique identifier of the domain is queried via <code>Id()</code> <a class="spec-record-ref" data-req="SWS_CORE_00151" href="../spec/record.html?id=SWS_CORE_00151">[SWS_CORE_00151]</a>. When comparing two instances via <code>operator==</code> <a class="spec-record-ref" data-req="SWS_CORE_00137" href="../spec/record.html?id=SWS_CORE_00137">[SWS_CORE_00137]</a> or <code>operator!=</code> <a class="spec-record-ref" data-req="SWS_CORE_00138" href="../spec/record.html?id=SWS_CORE_00138">[SWS_CORE_00138]</a>, the equality of the identifiers determined via <code>Id()</code> determines the result.</li>
<li><strong>Querying name and error text:</strong> The symbolic name of the domain can be determined by means of <code>Name()</code> <a class="spec-record-ref" data-req="SWS_CORE_00152" href="../spec/record.html?id=SWS_CORE_00152">[SWS_CORE_00152]</a>. For a specific code, <code>Message(errorCode)</code> returns the associated text message as a null-terminated string that is never <code>nullptr</code> <a class="spec-record-ref" data-req="SWS_CORE_00153" href="../spec/record.html?id=SWS_CORE_00153">[SWS_CORE_00153]</a>.</li>
<li><strong>Triggering exception handling:</strong> If an error state is alternatively to be propagated as an exception, <code>ThrowAsException(errorCode)</code> is called <a class="spec-record-ref" data-req="SWS_CORE_00154" href="../spec/record.html?id=SWS_CORE_00154">[SWS_CORE_00154]</a>. The domain determines the appropriate exception type, creates a corresponding <code>ara::core::Exception</code> object with the passed <code>ErrorCode</code>, and throws it.</li>
</ol>

<h4>Error Scenarios</h4>
<p>In practical use and when implementing custom domains, the following error conditions and restrictions are relevant:</p>
<ul>
<li><strong>Violation of domain affiliation:</strong> If an error code that does not originate from the called domain is passed to the method <code>Message(errorCode)</code>, a specified violation occurs (<code>WrongDomainOfAn-ErrorCodeViolation</code>) <a class="spec-record-ref" data-req="SWS_CORE_00153" href="../spec/record.html?id=SWS_CORE_00153">[SWS_CORE_00153]</a>. Callers must ensure that the domain of the code matches the instance.</li>
<li><strong>Exception safety and toolchain configuration:</strong> While the inspectors and operators of the class are declared exception-safe (<code>exception safe</code>) and <code>noexcept</code>, <code>ThrowAsException</code> is explicitly annotated with <code>noexcept(false)</code> and classified as not exception-safe (<code>not exception safe</code>) <a class="spec-record-ref" data-req="SWS_CORE_00154" href="../spec/record.html?id=SWS_CORE_00154">[SWS_CORE_00154]</a>. If C++ exceptions are disabled in the compiler toolchain, this function must not participate in overload resolution according to the specification <a class="spec-record-ref" data-req="SWS_CORE_00154" href="../spec/record.html?id=SWS_CORE_00154">[SWS_CORE_00154]</a>.</li>
<li><strong>Additional domain data:</strong> To provide vendor-specific additional information, the class provides the type alias <code>SupportDataType</code> <a class="spec-record-ref" data-req="SWS_CORE_00123" href="../spec/record.html?id=SWS_CORE_00123">[SWS_CORE_00123]</a>, whose structure and evaluation are defined in a vendor-specific manner.</li>
</ul>
