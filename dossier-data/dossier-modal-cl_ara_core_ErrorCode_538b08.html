<h4>Context</h4>
<p>In the AUTOSAR Adaptive Platform, the class <code>ara::core::ErrorCode</code> serves as a central encapsulation for error information. An <code>ErrorCode</code> combines a raw numerical error value and an associated error domain (<code>ara::core::ErrorDomain</code>), with the specific error value always being interpreted specifically for the respective domain. As the primary medium for synchronous and asynchronous error transmission, the class acts as a link between called function blocks that signal an error and calling components that evaluate or forward this error.</p>
<p>In interaction with the system, <code>ara::core::ErrorCode</code> assumes the responsibility of transporting error data immutably and, if required, providing context-related error texts or specific C++ exceptions via the referenced <code>ErrorDomain</code>. This decouples domain logic and representation: the domain defines the meaning of the values, while the <code>ErrorCode</code> object encapsulates the specific instance of the occurred error.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>ara::core::ErrorCode</code> typically arise directly at the point of error detection. The class provides two constructors:</p>
<ul>
<li>A templated constructor that accepts a domain-specific enumeration value (<code>EnumT</code>) and optional vendor-specific additional data (<code>ErrorDomain::SupportDataType</code>) <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>. This constructor is <code>constexpr</code> and <code>noexcept</code>.</li>
<li>A constructor with explicit specification of the raw value (<code>ErrorDomain::CodeType</code>), a reference to the associated <code>ErrorDomain</code>, and optional additional data <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>, which is also declared as <code>constexpr</code> and <code>noexcept</code>.</li>
</ul>
<p>The class is declared as <code>final</code> and has no dynamic memory management. Since all read methods are const and exception safe, the object is designed as a lightweight value object (interpretation: presumably intended for efficient passing by value via copy or move). A lifecycle with changing internal states does not exist; the contained error values and the domain reference remain immutable throughout the entire lifetime of the object. With regard to concurrency, construction and all query operations are explicitly specified as thread-safe and exception safe <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a> <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a> <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a> <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a> <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a> <a class="spec-record-ref" data-req="SWS_CORE_00518" href="../spec/record.html?id=SWS_CORE_00518">[SWS_CORE_00518]</a>.</p>

<h4>Usage Path</h4>
<p>The regular flow for using <code>ara::core::ErrorCode</code> is divided into creation, return transport to the consumer, and subsequent diagnosis:</p>
<ol>
<li><strong>Error creation:</strong> If an error state occurs within a function, the function creates an <code>ErrorCode</code> object specifying the domain-specific error and optional context data <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a> <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>.</li>
<li><strong>Return:</strong> The object is returned to the caller.</li>
<li><strong>Value query:</strong> The caller invokes <code>Value()</code> to query the domain-specific raw value of type <code>ErrorDomain::CodeType</code> <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a>.</li>
<li><strong>Domain identification:</strong> By means of <code>Domain()</code>, the caller obtains a reference to the associated <code>ErrorDomain</code> <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a> to distinguish errors across domains.</li>
<li><strong>Additional data and text message:</strong> If required, the consumer reads vendor-specific additional information via <code>SupportData()</code> <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a> or retrieves a textual description of the error as <code>StringView</code> by means of <code>Message()</code> <a class="spec-record-ref" data-req="SWS_CORE_00518" href="../spec/record.html?id=SWS_CORE_00518">[SWS_CORE_00518]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using <code>ara::core::ErrorCode</code>, several functional preconditions and boundary conditions must be observed:</p>
<ul>
<li><strong>Type constraint during construction:</strong> In accordance with <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>, the templated constructor with <code>EnumT</code> only participates in overload resolution if the template parameter <code>EnumT</code> is indeed an enumeration type (enum). Passing other types leads to an overload resolution error at compile time.</li>
<li><strong>Exception handling via ThrowAsException:</strong> The method <code>ThrowAsException()</code> converts the error object into a concrete C++ exception and throws it <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. It behaves as if <code>this-&gt;Domain().ThrowAsException(*this)</code> were called. The thrown exception encapsulates the triggering <code>ErrorCode</code> object.</li>
<li><strong>Disabling of C++ exceptions:</strong> If C++ exceptions are disabled in the compiler toolchain, <code>ThrowAsException()</code> does not participate in overload resolution according to the specification <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. Calls to this method result in compiler errors in such toolchain configurations.</li>
<li><strong>Exception safety:</strong> While almost all member functions (constructors, <code>Domain()</code>, <code>Value()</code>, <code>SupportData()</code>, <code>Message()</code>) are specified as <code>noexcept</code> and exception safe, <code>ThrowAsException()</code> is explicitly declared as <code>noexcept(false)</code> and not exception safe <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>, as it throws an exception by definition.</li>
</ul>
