<h4>Kontext</h4>
<p>Die Klasse <code>ara::core::ErrorCode</code> dient als zentrale Kapselung für Fehlerinformationen in der AUTOSAR Adaptive Platform. Ein Fehlercode bündelt stets einen domänenspezifischen Rohfehlerwert vom Typ <code>ErrorDomain::CodeType</code> mit einer zugehörigen Fehlerdomäne <code>ara::core::ErrorDomain</code> <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>. Die Fehlerdomäne definiert den semantischen Kontext, in dem der Rohwert zu interpretieren ist, und stellt die Verbindung zwischen numerischem Code und fachlicher Bedeutung her <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a>. Zusätzlich kann ein <code>ErrorCode</code> herstellerspezifische Zusatzdaten vom Typ <code>ErrorDomain::SupportDataType</code> aufnehmen, um erweiterten Kontext zur Fehlerentstehung ohne dynamische Speicherallokation bereitzustellen <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung eines <code>ErrorCode</code> erfolgt entweder über einen aufzählbaren Typ oder über die explizite Angabe von Rohwert und Fehlerdomäne. Für typsichere Aufzählungswerte existiert ein Konstruktor-Template, das per SFINAE ausschließlich an der Überladungsauflösung teilnimmt, wenn das Argument ein C++-Enum-Typ ist <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>. Alternativ nimmt der direkte Konstruktor einen numerischen Rohwert, eine Referenz auf die zuständige <code>ErrorDomain</code> sowie optionale Zusatzdaten entgegen <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>.</p>
<p>Beide Konstruktoren sind als <code>constexpr</code> und <code>noexcept</code> deklariert. Dies garantiert eine vollständige Ausnahmesicherheit bei der Erzeugung und gestattet die Konstruktion bereits zur Übersetzungszeit <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00513" href="../spec/record.html?id=SWS_CORE_00513">[SWS_CORE_00513]</a>. Interpretation: Da <code>ErrorCode</code> lediglich elementare Daten und eine Referenz auf die langlebige Domäne verwaltet, verhält sich die Klasse als leichtgewichtiger Werttyp, der frei kopiert und thread-übergreifend ausgelesen werden kann. Sämtliche beobachtenden Operationen sind als thread-sicher und ausnahmesicher spezifiziert <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungsablauf umfasst die Erzeugung bei Erkennung eines Fehlerzustands, die Inspektion relevanter Metadaten durch den Aufrufer sowie bei Bedarf die Weiterleitung in eine Ausnahmebehandlung:</p>
<ul>
<li><strong>Erzeugung:</strong> Der Fehler wird über einen domänenspezifischen Aufzählungswert und optionale Kontextdaten konstruiert <a class="spec-record-ref" data-req="SWS_CORE_00512" href="../spec/record.html?id=SWS_CORE_00512">[SWS_CORE_00512]</a>.</li>
<li><strong>Identifikation:</strong> Der Aufrufer fragt den numerischen Rohwert mittels <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a> und die zugeordnete Fehlerdomäne via <code>Domain()</code> <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a> ab.</li>
<li><strong>Diagnose:</strong> Ergänzende herstellerspezifische Daten werden über <code>SupportData()</code> gelesen <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a>, während <code>Message()</code> eine menschenlesbare Beschreibung als <code>StringView</code> liefert <a class="spec-record-ref" data-req="SWS_CORE_00518" href="../spec/record.html?id=SWS_CORE_00518">[SWS_CORE_00518]</a>.</li>
<li><strong>Ausnahmeauslösung:</strong> Soll der Fehler in einer auf Ausnahmen basierenden Kontrollstruktur propagiert werden, löst der Aufrufer über <code>ThrowAsException()</code> die zugehörige Ausnahme aus <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Die Klasse <code>ara::core::ErrorCode</code> fungiert als Brücke zwischen ausnahmefreiem und ausnahmebasiertem Fehlermanagement. Die Methoden <code>Value()</code>, <code>Domain()</code>, <code>SupportData()</code> und <code>Message()</code> besitzen die Zusicherung <code>noexcept</code> und können selbst unter Ressourcenengpässen ohne Risiko von Folgefehlern aufgerufen werden <a class="spec-record-ref" data-req="SWS_CORE_00514" href="../spec/record.html?id=SWS_CORE_00514">[SWS_CORE_00514]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00515" href="../spec/record.html?id=SWS_CORE_00515">[SWS_CORE_00515]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00516" href="../spec/record.html?id=SWS_CORE_00516">[SWS_CORE_00516]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00518" href="../spec/record.html?id=SWS_CORE_00518">[SWS_CORE_00518]</a>.</p>
<p>Ein eigenständiges Fehlerszenario stellt die Methode <code>ThrowAsException()</code> dar, die explizit als <code>noexcept(false)</code> und <code>not exception safe</code> deklariert ist <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. Ihr Verhalten entspricht dem Aufruf <code>this-&gt;Domain().ThrowAsException(*this)</code>; sie ermittelt über die verknüpfte <code>ErrorDomain</code> den adäquaten Ausnahmetyp und wirft eine Ausnahme, die die aktuelle <code>ErrorCode</code>-Instanz kapselt <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>. Eine wesentliche Randbedingung besteht darin, dass <code>ThrowAsException()</code> nicht an der Überladungsauflösung teilnimmt, falls in der Compiler-Toolchain C++-Ausnahmen deaktiviert sind <a class="spec-record-ref" data-req="SWS_CORE_00519" href="../spec/record.html?id=SWS_CORE_00519">[SWS_CORE_00519]</a>.</p>
