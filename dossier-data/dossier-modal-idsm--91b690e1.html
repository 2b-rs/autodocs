<p class="ai-level ai-oneliner-lead" data-ai-level="1">Sammelt Sicherheitsereignisse der Sensoren, filtert sie und leitet qualifizierte Ereignisse an Senken weiter.</p>
<div class="ai-level" data-ai-level="2">
<p>Der IdsM sammelt Security Events, die BSW-Module, CDDs und SW-Cs melden, puffert sie und verarbeitet sie asynchron in <code>IdsM_MainFunction</code> <a class="spec-record-ref" data-req="SWS_IdsM_00702" href="../../spec/record.html?id=SWS_IdsM_00702">[SWS_IdsM_00702]</a>. Reporting Mode und eine Filterkette aus Block-State-, Sampling-, Aggregations- und Schwellwertfiltern machen daraus qualifizierte Ereignisse <a class="spec-record-ref" data-req="SWS_IdsM_01004" href="../../spec/record.html?id=SWS_IdsM_01004">[SWS_IdsM_01004]</a>. Diese gehen über den PduR an einen IdsR oder werden in DEM/Sem gespeichert. Zeitstempel, Signatur und Diagnosezugriff sind optional. Die Bedeutung der Kontextdaten bewertet der IdsM nicht; die Reaktion auf Angriffe liegt außerhalb des Moduls.</p>
<p class="ai-level-more-inline"><button type="button" class="ai-level-step ai-level-more" data-ai-level-step="1" title="Ausführlichere Fassung zeigen">mehr ›</button></p>
</div>
<div class="ai-level" data-ai-level="3">
<p>Der IdsM nimmt Security Events (SEv) von Sicherheitssensoren entgegen, also von BSW-Modulen, CDDs und SW-Cs. Über eine Filterkette macht er daraus Qualified Security Events (QSEv) <a class="spec-record-ref" data-req="SWS_IdsM_00902" href="../../spec/record.html?id=SWS_IdsM_00902">[SWS_IdsM_00902]</a>. QSEvs sendet er über den PduR an einen IdsR, speichert sie in DEM/Sem oder beides <a class="spec-record-ref" data-req="SWS_IdsM_01202" href="../../spec/record.html?id=SWS_IdsM_01202">[SWS_IdsM_01202]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01600" href="../../spec/record.html?id=SWS_IdsM_01600">[SWS_IdsM_01600]</a>. Die Bedeutung der Kontextdaten bewertet er nicht. Die Reaktion auf Angriffe liegt außerhalb des Moduls, etwa in einem SOC <a class="spec-record-ref" data-req="SWS_IdsM_CONSTR_00001" href="../../spec/record.html?id=SWS_IdsM_CONSTR_00001">[SWS_IdsM_CONSTR_00001]</a>.</p>

<p>Sensoren melden über <code>IdsM_SetSecurityEvent</code> oder eine von fünf Varianten mit Kontextdaten (bis 1500 Byte), Zähler und Zeitstempel <a class="spec-record-ref" data-req="SWS_IdsM_00300" href="../../spec/record.html?id=SWS_IdsM_00300">[SWS_IdsM_00300]</a> <a class="spec-record-ref" data-req="SWS_IdsM_00404" href="../../spec/record.html?id=SWS_IdsM_00404">[SWS_IdsM_00404]</a> <a class="spec-record-ref" data-req="SWS_IdsM_00501" href="../../spec/record.html?id=SWS_IdsM_00501">[SWS_IdsM_00501]</a>. Dabei verwenden sie immer den symbolischen Namen des <code>IdsMEvent</code> <a class="spec-record-ref" data-req="SWS_IdsM_00607" href="../../spec/record.html?id=SWS_IdsM_00607">[SWS_IdsM_00607]</a>. Der Melde-Dienst puffert das SEv nur. Die eigentliche Verarbeitung läuft asynchron in <code>IdsM_MainFunction</code> <a class="spec-record-ref" data-req="SWS_IdsM_00702" href="../../spec/record.html?id=SWS_IdsM_00702">[SWS_IdsM_00702]</a>. Fehlt ein freier Event Buffer, löst der IdsM einen internen SEv aus, sofern dieser konfiguriert ist <a class="spec-record-ref" data-req="SWS_IdsM_00703" href="../../spec/record.html?id=SWS_IdsM_00703">[SWS_IdsM_00703]</a>.</p>
<p>Die Qualifizierung beginnt mit dem Reporting Mode. Mögliche Werte sind OFF, BRIEF, DETAILED und die Varianten, die die Filter umgehen <a class="spec-record-ref" data-req="SWS_IdsM_01002" href="../../spec/record.html?id=SWS_IdsM_01002">[SWS_IdsM_01002]</a> <a class="spec-record-ref" data-req="SWS_IdsM_91013" href="../../spec/record.html?id=SWS_IdsM_91013">[SWS_IdsM_91013]</a>. Danach laufen die aktiven Filter in fester Reihenfolge: Block State, Forward Every n-th, Aggregation, Threshold <a class="spec-record-ref" data-req="SWS_IdsM_01004" href="../../spec/record.html?id=SWS_IdsM_01004">[SWS_IdsM_01004]</a>. Verwirft ein Filter das SEv, endet die Auswertung <a class="spec-record-ref" data-req="SWS_IdsM_01005" href="../../spec/record.html?id=SWS_IdsM_01005">[SWS_IdsM_01005]</a>. Vor dem Senden an den IdsR greifen zusätzlich Raten- und Verkehrsbegrenzung <a class="spec-record-ref" data-req="SWS_IdsM_01070" href="../../spec/record.html?id=SWS_IdsM_01070">[SWS_IdsM_01070]</a>. Diese dürften auch für die Bypass-Modi gelten (Interpretation).</p>

<h4>Rolle: vom gemeldeten Sicherheitsereignis zum qualifizierten Ereignis</h4>
<p>Der Intrusion Detection System Manager (IdsM) sammelt Security Events (SEv). Diese erkennen und melden Sicherheitssensoren, also BSW-Module, Complex Device Drivers oder SW-Cs <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_IDSM_SECTION_2_Acronyms_and_Abbreviations.html" data-snip="SNIP_CLASSIC_IDSM_SECTION_2_Acronyms_and_Abbreviations">SWS IdsM S. 10</a>. Der IdsM prüft jedes SEv gegen eine konfigurierbare Folge von Filtern, die Filterkette. Besteht das SEv diese Prüfung, wird es zum Qualified Security Event (QSEv) <a class="spec-record-ref" data-req="SWS_IdsM_00902" href="../../spec/record.html?id=SWS_IdsM_00902">[SWS_IdsM_00902]</a>. Nur QSEvs werden weiterbehandelt. Sie gehen über den PduR an einen IdsR auf einem anderen Steuergerät, werden in DEM/Sem abgelegt oder beides <a class="spec-record-ref" data-req="SWS_IdsM_01202" href="../../spec/record.html?id=SWS_IdsM_01202">[SWS_IdsM_01202]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01600" href="../../spec/record.html?id=SWS_IdsM_01600">[SWS_IdsM_01600]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_IDSM_SECTION_7_8_Reporting_and_Persistence_of_SEVs.html" data-snip="SNIP_CLASSIC_IDSM_SECTION_7_8_Reporting_and_Persistence_of_SEVs">SWS IdsM S. 35</a>.</p>
<p>Die Systemgrenze ist eng gezogen. Der IdsM kennt die Bedeutung der Kontextdaten nicht und entscheidet deshalb nicht selbst, ob ein System kompromittiert ist. Erkennung und Reaktion liegen außerhalb des Moduls, etwa in einem SOC <a class="spec-record-ref" data-req="SWS_IdsM_CONSTR_00001" href="../../spec/record.html?id=SWS_IdsM_CONSTR_00001">[SWS_IdsM_CONSTR_00001]</a>. Pflicht-Schnittstellen zu anderen Modulen gibt es nicht <a class="spec-record-ref" data-req="SWS_IdsM_91023" href="../../spec/record.html?id=SWS_IdsM_91023">[SWS_IdsM_91023]</a>. Jede Kopplung wird über die Konfiguration zugeschaltet. Das zeigen die bedingten Header-Einbindungen:</p>
<ul>
<li><code>Det.h</code> bei <code>IdsMDevErrorDetect</code></li>
<li><code>Dem.h</code> bei <code>IdsMSinkDem</code></li>
<li><code>Dcm.h</code> bei <code>IdsMDiagnosticSupport</code></li>
<li><code>NvM.h</code> bei <code>IdsMNvmBlockDescriptor</code></li>
<li><code>PduR.h</code> bei <code>IdsMSinkIdsR</code></li>
</ul>
<p>Belege für diese Einbindungen: <a class="spec-record-ref" data-req="SWS_IdsM_00101" href="../../spec/record.html?id=SWS_IdsM_00101">[SWS_IdsM_00101]</a> bis <a class="spec-record-ref" data-req="SWS_IdsM_00105" href="../../spec/record.html?id=SWS_IdsM_00105">[SWS_IdsM_00105]</a>.</p>

<h4>Qualifizierung: Reporting Mode, Filterkette und Instanzgrenzen</h4>
<p>Zuerst wertet der IdsM den Reporting Mode aus. Jedes SEv hat genau einen Reporting-Mode-Filter. Dieser Filter ist Pflicht, hängt direkt am SEv und gehört nicht zur Filterkette <a class="spec-record-ref" data-req="SWS_IdsM_01010" href="../../spec/record.html?id=SWS_IdsM_01010">[SWS_IdsM_01010]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01011" href="../../spec/record.html?id=SWS_IdsM_01011">[SWS_IdsM_01011]</a>. Der Startwert kommt aus <code>IdsMReportingModeFilter</code> <a class="spec-record-ref" data-req="SWS_IdsM_01012" href="../../spec/record.html?id=SWS_IdsM_01012">[SWS_IdsM_01012]</a>. Die Filterkette folgt erst danach <a class="spec-record-ref" data-req="SWS_IdsM_01002" href="../../spec/record.html?id=SWS_IdsM_01002">[SWS_IdsM_01002]</a>. <code>IdsM_Filters_ReportingModeType</code> kennt diese Modi <a class="spec-record-ref" data-req="SWS_IdsM_91013" href="../../spec/record.html?id=SWS_IdsM_91013">[SWS_IdsM_91013]</a>:</p>
<ul>
<li><code>IDSM_REPORTING_MODE_OFF</code>: Das Ereignis wird nicht gemeldet.</li>
<li><code>IDSM_REPORTING_MODE_BRIEF</code>: Meldung ohne Kontextdaten.</li>
<li><code>IDSM_REPORTING_MODE_DETAILED</code>: Meldung mit Kontextdaten.</li>
<li>Die beiden Varianten <code>…_BYPASSING_FILTERS</code>: Meldung wie BRIEF oder DETAILED, aber ungefiltert.</li>
</ul>
<p>Die Filterkette ist dem SEv zugeordnet <a class="spec-record-ref" data-req="SWS_IdsM_01001" href="../../spec/record.html?id=SWS_IdsM_01001">[SWS_IdsM_01001]</a> <a class="spec-record-ref" data-req="SWS_IdsM_00903" href="../../spec/record.html?id=SWS_IdsM_00903">[SWS_IdsM_00903]</a>. Jede <code>IdsMFilterChain</code> braucht mindestens einen Filter <a class="spec-record-ref" data-req="SWS_IdsM_CONSTR_00002" href="../../spec/record.html?id=SWS_IdsM_CONSTR_00002">[SWS_IdsM_CONSTR_00002]</a>. Die aktiven Filter laufen in fester Reihenfolge <a class="spec-record-ref" data-req="SWS_IdsM_01004" href="../../spec/record.html?id=SWS_IdsM_01004">[SWS_IdsM_01004]</a>. Verwirft ein Filter das SEv, endet die Auswertung sofort. Andernfalls geht das SEv an den nächsten Filter <a class="spec-record-ref" data-req="SWS_IdsM_00904" href="../../spec/record.html?id=SWS_IdsM_00904">[SWS_IdsM_00904]</a> <a class="spec-record-ref" data-req="SWS_IdsM_00905" href="../../spec/record.html?id=SWS_IdsM_00905">[SWS_IdsM_00905]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01005" href="../../spec/record.html?id=SWS_IdsM_01005">[SWS_IdsM_01005]</a>. Die vier Filter in dieser Reihenfolge:</p>
<ol>
<li><strong>Block State:</strong> Der BswM meldet den aktuellen Zustand über <code>IdsM_BswM_StateChanged</code> als Bitmaske vom Typ <code>IdsM_Filters_BlockStateType</code>. Ist dieser Zustand in <code>IdsMBlockState</code> referenziert, verwirft der Filter das SEv <a class="spec-record-ref" data-req="SWS_IdsM_01022" href="../../spec/record.html?id=SWS_IdsM_01022">[SWS_IdsM_01022]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01023" href="../../spec/record.html?id=SWS_IdsM_01023">[SWS_IdsM_01023]</a> <a class="spec-record-ref" data-req="SWS_IdsM_91017" href="../../spec/record.html?id=SWS_IdsM_91017">[SWS_IdsM_91017]</a>. Ein Filter kann bis zu 16 Zustände referenzieren <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-f5c365589c0279e9.html" data-snip="FIG-f5c365589c0279e9">SWS IdsM S. 85</a>.</li>
<li><strong>Forward Every n-th:</strong> Das erste SEv geht weiter, danach jedes n-te laut <code>IdsMNthParameter</code>. Die Daten bleiben dabei unverändert <a class="spec-record-ref" data-req="SWS_IdsM_01031" href="../../spec/record.html?id=SWS_IdsM_01031">[SWS_IdsM_01031]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01032" href="../../spec/record.html?id=SWS_IdsM_01032">[SWS_IdsM_01032]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01033" href="../../spec/record.html?id=SWS_IdsM_01033">[SWS_IdsM_01033]</a>.</li>
<li><strong>Event Aggregation:</strong> Während des Intervalls gibt der Filter nichts weiter. Am Intervallende entsteht ein einziges SEv mit dem Summenzähler <a class="spec-record-ref" data-req="SWS_IdsM_01043" href="../../spec/record.html?id=SWS_IdsM_01043">[SWS_IdsM_01043]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01046" href="../../spec/record.html?id=SWS_IdsM_01046">[SWS_IdsM_01046]</a>. Kontextdaten und Zeitstempel stammen vom ersten oder letzten SEv des Intervalls, je nach <code>IdsMContextDataSourceSelector</code> <a class="spec-record-ref" data-req="SWS_IdsM_01047" href="../../spec/record.html?id=SWS_IdsM_01047">[SWS_IdsM_01047]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01049" href="../../spec/record.html?id=SWS_IdsM_01049">[SWS_IdsM_01049]</a>. Ein Beispiel zeigt <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-cb3e945ecec1699f.html" data-snip="FIG-cb3e945ecec1699f">SWS IdsM S. 40</a>.</li>
<li><strong>Event Threshold:</strong> Der Filter verwirft SEvs, solange die Zählersumme im laufenden Intervall unter <code>IdsMEventThresholdNumber</code> liegt. Mit Ablauf des Intervalls wird die Summe zurückgesetzt <a class="spec-record-ref" data-req="SWS_IdsM_01061" href="../../spec/record.html?id=SWS_IdsM_01061">[SWS_IdsM_01061]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01062" href="../../spec/record.html?id=SWS_IdsM_01062">[SWS_IdsM_01062]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01063" href="../../spec/record.html?id=SWS_IdsM_01063">[SWS_IdsM_01063]</a>. Ein Beispiel zeigt <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-75b636b0230bda5d.html" data-snip="FIG-75b636b0230bda5d">SWS IdsM S. 41</a>.</li>
</ol>
<p>Alle Intervalle sind Vielfache von <code>IdsMMainFunctionPeriod</code>. Aggregations- und Schwellwertintervall laufen ab dem ersten Aufruf der Main Function <a class="spec-record-ref" data-req="SWS_IdsM_01050" href="../../spec/record.html?id=SWS_IdsM_01050">[SWS_IdsM_01050]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01051" href="../../spec/record.html?id=SWS_IdsM_01051">[SWS_IdsM_01051]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01065" href="../../spec/record.html?id=SWS_IdsM_01065">[SWS_IdsM_01065]</a>.</p>
<p>Vor dem Senden an den IdsR wirken zwei Begrenzungen für die gesamte IdsM-Instanz <a class="spec-record-ref" data-req="SWS_IdsM_01070" href="../../spec/record.html?id=SWS_IdsM_01070">[SWS_IdsM_01070]</a>:</p>
<ul>
<li>Die Ratenbegrenzung erlaubt höchstens <code>IdsMRateLimitationMaximumEvents</code> QSEvs je Intervall <a class="spec-record-ref" data-req="SWS_IdsM_01081" href="../../spec/record.html?id=SWS_IdsM_01081">[SWS_IdsM_01081]</a>.</li>
<li>Die Verkehrsbegrenzung erlaubt höchstens <code>IdsMTrafficLimitationMaximumBytes</code> Byte je Intervall <a class="spec-record-ref" data-req="SWS_IdsM_01091" href="../../spec/record.html?id=SWS_IdsM_01091">[SWS_IdsM_01091]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01093" href="../../spec/record.html?id=SWS_IdsM_01093">[SWS_IdsM_01093]</a>.</li>
</ul>
<p>Interne SEvs des IdsM durchlaufen diese Instanzfilter nicht. Ereignisspezifische Filter dürfen sie aber haben <a class="spec-record-ref" data-req="SWS_IdsM_00803" href="../../spec/record.html?id=SWS_IdsM_00803">[SWS_IdsM_00803]</a> <a class="spec-record-ref" data-req="SWS_IdsM_00804" href="../../spec/record.html?id=SWS_IdsM_00804">[SWS_IdsM_00804]</a>. Interpretation: Die Bypass-Modi umgehen nur die Filterkette. Raten- und Verkehrsbegrenzung dürften auch für sie gelten, denn <a class="spec-record-ref" data-req="SWS_IdsM_01070" href="../../spec/record.html?id=SWS_IdsM_01070">[SWS_IdsM_01070]</a> verlangt diese Begrenzungen vor jeder Übertragung an den IdsR.</p>

<h4>Zeitstempel, IDS-Nachricht und Senken</h4>
<p>Der Zeitstempel ist optional und wird global über <code>IdsMTimestampOption</code> gesteuert <a class="spec-record-ref" data-req="SWS_IdsM_01100" href="../../spec/record.html?id=SWS_IdsM_01100">[SWS_IdsM_01100]</a>:</p>
<ul>
<li><strong>None:</strong> Die Funktion ist abgeschaltet. Mitgemeldete Zeitstempel werden ignoriert <a class="spec-record-ref" data-req="SWS_IdsM_01103" href="../../spec/record.html?id=SWS_IdsM_01103">[SWS_IdsM_01103]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01106" href="../../spec/record.html?id=SWS_IdsM_01106">[SWS_IdsM_01106]</a>.</li>

<li><strong>Custom:</strong> Der IdsM fragt die Applikation über das Interface <code>IdsM_CustomTimestamp</code> (Operation <code>Get</code>) am Port <code>CustomTimestamp</code> <a class="spec-record-ref" data-req="SWS_IdsM_01109" href="../../spec/record.html?id=SWS_IdsM_01109">[SWS_IdsM_01109]</a> <a class="spec-record-ref" data-req="SWS_IdsM_01111" href="../../spec/record.html?id=SWS_IdsM_01111">[SWS_IdsM_01111]</a>.</li>
</ul>
