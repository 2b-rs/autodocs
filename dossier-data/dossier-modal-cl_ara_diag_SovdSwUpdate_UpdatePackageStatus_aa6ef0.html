<div class="ai-level" data-ai-level="2">
<p>Die Struktur <code>ara::diag::SovdSwUpdate::UpdatePackageStatus</code> stellt Status-, Phasen- und Fortschrittsinformationen eines Software-Aktualisierungsprozesses für SOVD-Diagnoseanwendungen bereit <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a>. Sie wird durch den Aufruf von <code>GetUpdatePackageStatus</code> bezogen und ermöglicht die kontinuierliche Überwachung von Ausführungsphasen, prozentualen Fortschritten sowie Einzelschritten. Im Falle eines Fehlers signalisiert die Struktur den Fehlschlag und transportiert über das optionale Fehlerfeld den genauen Fehlercode aus der Domäne <code>DiagSovdErrc</code> <a class="spec-record-ref" data-req="SWS_DM_01909" href="../spec/record.html?id=SWS_DM_01909">[SWS_DM_01909]</a>. Als reines Datenübertragungsobjekt erfordert die Struktur vermutlich eine anwendungsseitige Synchronisation bei nebenläufigem Zugriff.</p>

<h4>Kontext</h4>
<p>Die Datenstruktur <code>ara::diag::SovdSwUpdate::UpdatePackageStatus</code> ist Bestandteil des Moduls <code>diag</code> der AUTOSAR Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=759">SWS Diagnostics §8.58.5 „Struct: UpdatePackageStatus“</a> <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a>. Sie fungiert im Rahmen von Service-Oriented Vehicle Diagnostics (SOVD) als standardisierter Informationsträger zur Erfassung und Bereitstellung des aktuellen Zustands eines Software-Aktualisierungspakets. Über die API-Funktion <code>ara::diag::SovdSwUpdate::GetUpdatePackageStatus</code> wird das Statusobjekt von der Diagnoseschnittstelle generiert und an abfragende Instanzen übergeben <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=743">SWS Diagnostics §8.58.2.1.3.5 „GetUpdatePackageStatus“</a> <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>.</p>
<p>Innerhalb der Systemarchitektur dient die Struktur als Entkopplungselement zwischen der ausführenden Service-Komponente <code>SovdSwUpdate</code> und externen oder internen Diagnose-Clients. Während der Service die eigentliche Paketverarbeitung und Installation steuert, kapselt <code>UpdatePackageStatus</code> eine Momentaufnahme über Verarbeitungsphasen, Fortschritte und eventuelle Fehlerzustände <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Als reiner Datenbehälter (<code>struct</code>) besitzt <code>UpdatePackageStatus</code> keine eigene interne Zustandslogik und betreibt kein eigenständiges Ressourcenmanagement <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=759">SWS Diagnostics §8.58.5 „Struct: UpdatePackageStatus“</a> <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a>. Instanzen werden im Zuge des Aufrufs von <code>GetUpdatePackageStatus</code> erzeugt, mit den aktuellen Statuswerten befüllt und per Wert an den Aufrufer zurückgeliefert <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>. Die Lebensdauer ist an den Scope des Empfängers gebunden und endet mit dessen Zerstörung.</p>
<p>Obwohl das C++-Objekt passiv ist, repräsentieren seine Member-Variablen den Lebenszyklus des zugrunde liegenden Aktualisierungsprozesses. Das Feld <code>phase</code> vom Typ <code>SovdUpdatePhase</code> beschreibt die aktuelle Phase des Gesamtprozesses <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=760">SWS Diagnostics §8.58.5.1.2 „phase“</a> <a class="spec-record-ref" data-req="SWS_DM_01903" href="../spec/record.html?id=SWS_DM_01903">[SWS_DM_01903]</a>, während die Variable <code>status</code> vom Typ <code>SovdUpdateStatus</code> den konkreten Zustand dieser Phase angibt <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=761">SWS Diagnostics §8.58.5.1.4 „status“</a> <a class="spec-record-ref" data-req="SWS_DM_01904" href="../spec/record.html?id=SWS_DM_01904">[SWS_DM_01904]</a>. Da keine internen Mutexe oder Synchronisationsmechanismen spezifiziert sind, erfordert ein nebenläufiger Zugriff auf dieselbe Instanz eine externe Absicherung durch den Verwender.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Nutzungspfad umfasst die zyklische oder anlassbezogene Überwachung einer Paketaktualisierung durch einen Diagnose-Client:</p>
<ul>

<li><strong>Phasen- und Statusbewertung:</strong> Nach Erhalt des Objekts <a class="spec-record-ref" data-req="SWS_DM_01902" href="../spec/record.html?id=SWS_DM_01902">[SWS_DM_01902]</a> prüft der Client die Variablen <code>phase</code> <a class="spec-record-ref" data-req="SWS_DM_01903" href="../spec/record.html?id=SWS_DM_01903">[SWS_DM_01903]</a> und <code>status</code> <a class="spec-record-ref" data-req="SWS_DM_01904" href="../spec/record.html?id=SWS_DM_01904">[SWS_DM_01904]</a>, um festzustellen, ob der Ablauf regulär fortschreitet oder abgeschlossen ist.</li>
<li><strong>Fortschrittsanalyse:</strong> Liegt ein prozentualer Gesamtfortschritt vor, wird dieser über das optionale Member <code>progress</code> ausgewertet <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=761">SWS Diagnostics §8.58.5.1.3 „progress“</a> <a class="spec-record-ref" data-req="SWS_DM_01905" href="../spec/record.html?id=SWS_DM_01905">[SWS_DM_01905]</a>. Zusätzliche Teilphasen können über den Vektor <code>subprogress</code> eingesehen werden <a class="spec-record-ref" data-req="SWS_DM_01906" href="../spec/record.html?id=SWS_DM_01906">[SWS_DM_01906]</a>.</li>
<li><strong>Schrittanzeige:</strong> Zur Protokollierung oder Benutzerführung werden die textuelle Schrittbezeichnung <code>step</code> <a class="spec-record-ref" data-req="SWS_DM_01907" href="../spec/record.html?id=SWS_DM_01907">[SWS_DM_01907]</a> sowie der Lokalisierungsschlüssel <code>step_translation_id</code> herangezogen <a class="spec-record-ref" data-req="SWS_DM_01908" href="../spec/record.html?id=SWS_DM_01908">[SWS_DM_01908]</a>.</li>

<h4>Fehlerszenarien</h4>
<p>Fehler im Update-Ablauf werden über spezifische Attribute der Datenstruktur transparent gemacht:</p>
<ul>
<li><strong>Fehlgeschlagener Status:</strong> Weist der Prozess ein Problem auf, nimmt das Feld <code>status</code> den Zustand „failed“ an <a class="spec-record-ref" data-req="SWS_DM_01904" href="../spec/record.html?id=SWS_DM_01904">[SWS_DM_01904]</a>.</li>
<li><strong>Fehlerdetail:</strong> In diesem Fehlerfall spezifiziert das Feld <code>error</code> vom Typ <code>ara::core::Optional&lt;ara::diag::DiagSovdErrc&gt;</code> den aufgetretenen Fehlercode <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=760">SWS Diagnostics §8.58.5.1.1 „error“</a> <a class="spec-record-ref" data-req="SWS_DM_01909" href="../spec/record.html?id=SWS_DM_01909">[SWS_DM_01909]</a>.</li>
<li><strong>Regulärer Ablauf:</strong> Sofern kein Fehler vorliegt, dürfte das optionale Feld <code>error</code> unbesetzt bleiben, da es laut Spezifikation explizit an den Zustand „failed“ gekoppelt ist <a class="spec-record-ref" data-req="SWS_DM_01909" href="../spec/record.html?id=SWS_DM_01909">[SWS_DM_01909]</a>.</li>
<li><strong>Schnittstellenfehler:</strong> Schlägt der API-Aufruf <code>GetUpdatePackageStatus</code> auf Plattformebene fehl, dürfte anstelle eines Statusobjekts ein plattformspezifischer Fehlerzustand zurückgegeben werden <a class="spec-record-ref" data-req="SWS_DM_01921" href="../spec/record.html?id=SWS_DM_01921">[SWS_DM_01921]</a>.</li>
</ul>
