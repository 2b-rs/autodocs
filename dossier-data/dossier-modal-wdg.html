<p class="ai-level ai-oneliner-lead" data-ai-level="1">Bedient die Watchdog-Hardware gemäß einer befristeten Triggerbedingung und schaltet ihre Betriebsmodi um.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Watchdog-Treiber steuert die interne oder externe Watchdog-Hardware im Auftrag des Watchdog Managers. Dieser setzt über das Watchdog Interface nur eine befristete Triggerbedingung. Solange sie gilt, triggert der Treiber die Hardware selbst; danach läuft der Watchdog ab <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>. <code>Wdg_Init</code> setzt Standardmodus und Timeout aus der Konfiguration, und <code>Wdg_SetMode</code> wechselt zwischen OFF-, SLOW- und FAST-Modus <a class="spec-record-ref" data-req="SWS_Wdg_00160" href="../../spec/record.html?id=SWS_Wdg_00160">[SWS_Wdg_00160]</a>. Ein Timeout von 0 löst einen nahezu sofortigen Reset aus, und abschalten lässt sich der Watchdog nur, wenn die Konfiguration es erlaubt.</p>
<p class="ai-level-more-inline"><button type="button" class="ai-level-step ai-level-more" data-ai-level-step="1" title="Ausführlichere Fassung zeigen">mehr ›</button></p>
</div>
<div class="ai-level" data-ai-level="3">
<p>Der Watchdog-Treiber Wdg steuert die Watchdog-Hardware über vier synchrone Dienste: <code>Wdg_Init</code>, <code>Wdg_SetMode</code>, <code>Wdg_SetTriggerCondition</code> und <code>Wdg_GetVersionInfo</code> (<a class="spec-record-ref" data-req="SWS_Wdg_00106" href="../../spec/record.html?id=SWS_Wdg_00106">[SWS_Wdg_00106]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00107" href="../../spec/record.html?id=SWS_Wdg_00107">[SWS_Wdg_00107]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00155" href="../../spec/record.html?id=SWS_Wdg_00155">[SWS_Wdg_00155]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00109" href="../../spec/record.html?id=SWS_Wdg_00109">[SWS_Wdg_00109]</a>). EcuM ruft <code>Wdg_Init</code> auf. Der Watchdog Manager erreicht den Treiber nur über das Watchdog Interface, das die Instanz per <code>DeviceIndex</code> wählt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDG_SECTION_8_3_Function_definitions_WATCHDOGINTERFACE.html" data-snip="SNIP_CLASSIC_WDG_SECTION_8_3_Function_definitions_WATCHDOGINTERFACE">SWS WdgIf S. 17</a>). Interne Instanzen greifen direkt auf die Hardware zu, externe über SPI oder DIO (<a class="spec-record-ref" data-req="SWS_Wdg_00161" href="../../spec/record.html?id=SWS_Wdg_00161">[SWS_Wdg_00161]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00076" href="../../spec/record.html?id=SWS_Wdg_00076">[SWS_Wdg_00076]</a>). Beide bieten dieselbe API <a class="spec-record-ref" data-req="SWS_Wdg_00077" href="../../spec/record.html?id=SWS_Wdg_00077">[SWS_Wdg_00077]</a>.</p>

<p>Kern des Moduls ist die Triggerbedingung. Sie gilt als Erlaubnis, den Watchdog für die nächsten n Millisekunden zu bedienen. Solange sie gültig ist, triggert der Treiber selbst; danach läuft der Watchdog ab <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>. <code>Wdg_SetTriggerCondition</code> setzt den Zähler zurück und rechnet die Millisekunden modusabhängig in einen Zählerwert um (<a class="spec-record-ref" data-req="SWS_Wdg_00136" href="../../spec/record.html?id=SWS_Wdg_00136">[SWS_Wdg_00136]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00139" href="../../spec/record.html?id=SWS_Wdg_00139">[SWS_Wdg_00139]</a>). Die interne Bedienroutine triggert und dekrementiert, solange der Zähler größer als null ist. Bei null triggert sie nicht mehr (<a class="spec-record-ref" data-req="SWS_Wdg_00134" href="../../spec/record.html?id=SWS_Wdg_00134">[SWS_Wdg_00134]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00135" href="../../spec/record.html?id=SWS_Wdg_00135">[SWS_Wdg_00135]</a>). Ein Timeout von 0 erzwingt einen (nahezu) sofortigen Reset, und ein abgelaufener Zähler lässt sich nicht neu laden <a class="spec-record-ref" data-req="SWS_Wdg_00140" href="../../spec/record.html?id=SWS_Wdg_00140">[SWS_Wdg_00140]</a>.</p>

<h4>Rolle im Watchdog-Stack: der Treiber, der das Triggern selbst übernimmt</h4>
<p>Der Watchdog-Treiber Wdg steuert die Watchdog-Hardware über eine kleine, synchrone API mit vier Diensten, die alle über <code>Wdg.h</code> verfügbar sind: <code>Wdg_Init</code> (Service-ID 0x00), <code>Wdg_SetMode</code> (0x01), <code>Wdg_SetTriggerCondition</code> (0x03) und <code>Wdg_GetVersionInfo</code> (0x04). Nur <code>Wdg_GetVersionInfo</code> ist reentrant (<a class="spec-record-ref" data-req="SWS_Wdg_00106" href="../../spec/record.html?id=SWS_Wdg_00106">[SWS_Wdg_00106]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00107" href="../../spec/record.html?id=SWS_Wdg_00107">[SWS_Wdg_00107]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00155" href="../../spec/record.html?id=SWS_Wdg_00155">[SWS_Wdg_00155]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00109" href="../../spec/record.html?id=SWS_Wdg_00109">[SWS_Wdg_00109]</a>). Eine Schnittstelle zur De-Initialisierung gibt es bewusst nicht. Wenn Hardware und Umgebung ein Abschalten zulassen, geschieht es über <code>Wdg_SetMode</code> mit dem OFF-Modus <a class="spec-record-ref" data-req="SWS_Wdg_00031" href="../../spec/record.html?id=SWS_Wdg_00031">[SWS_Wdg_00031]</a>.</p>
<p>Die Dienste werden von der Basissoftware aufgerufen. Der ECU State Manager ruft <code>Wdg_Init</code> auf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_2_Structural_Description_of_the_ECU_Manager.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_2_Structural_Description_of_the_ECU_Manager">SWS EcuM S. 34</a>). Der Watchdog Manager benötigt <code>WdgIf_SetMode</code> und <code>WdgIf_SetTriggerCondition</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_OS_SECTION_8_6_1_Mandatory_interfaces_WATCHDOGMANAGER.html" data-snip="SNIP_CLASSIC_OS_SECTION_8_6_1_Mandatory_interfaces_WATCHDOGMANAGER">SWS WdgM S. 86</a>). Das Watchdog Interface bildet diese Aufrufe auf den Treiber ab und wählt die Instanz über einen nullbasierten <code>DeviceIndex</code> vom Typ <code>uint8</code>. Ist nur ein Treiber konfiguriert, darf diese Abbildung keinen Laufzeit-Overhead verursachen, etwa durch Makros (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDG_SECTION_8_3_Function_definitions_WATCHDOGINTERFACE.html" data-snip="SNIP_CLASSIC_WDG_SECTION_8_3_Function_definitions_WATCHDOGINTERFACE">SWS WdgIf S. 17</a>). Das zeitliche Triggern liegt vollständig im Treiber. Der Watchdog Manager setzt nur die Triggerbedingung (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling">SWS WdgM S. 56</a>; <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>).</p>
<p>Zur Hardware hin unterscheiden sich die Instanzen. Eine Instanz für einen internen Watchdog greift direkt auf die Hardware zu <a class="spec-record-ref" data-req="SWS_Wdg_00161" href="../../spec/record.html?id=SWS_Wdg_00161">[SWS_Wdg_00161]</a>. Eine Instanz für einen externen Watchdog nutzt die API eines Handlers oder Treibers, etwa SPI oder DIO <a class="spec-record-ref" data-req="SWS_Wdg_00076" href="../../spec/record.html?id=SWS_Wdg_00076">[SWS_Wdg_00076]</a>. Optional verwendet Wdg <code>Det_ReportError</code> für Entwicklungsfehler und <code>Dem_SetEventStatus</code> für Monitorstatus <a class="spec-record-ref" data-req="SWS_Wdg_00111" href="../../spec/record.html?id=SWS_Wdg_00111">[SWS_Wdg_00111]</a>.</p>

<h4>Vom Systemstart zum überwachten Betrieb</h4>
<p><code>Wdg_Init</code> erhält einen Zeiger auf einen Konfigurationssatz vom Typ <code>Wdg_ConfigType</code>. Diese Struktur ist hardwareabhängig (<a class="spec-record-ref" data-req="SWS_Wdg_00106" href="../../spec/record.html?id=SWS_Wdg_00106">[SWS_Wdg_00106]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00171" href="../../spec/record.html?id=SWS_Wdg_00171">[SWS_Wdg_00171]</a>). Die Funktion initialisiert Treiber und Hardware und setzt den Standardmodus und die Timeout-Periode aus diesem Satz <a class="spec-record-ref" data-req="SWS_Wdg_00001" href="../../spec/record.html?id=SWS_Wdg_00001">[SWS_Wdg_00001]</a>. Außerdem initialisiert sie alle globalen Variablen <a class="spec-record-ref" data-req="SWS_Wdg_00100" href="../../spec/record.html?id=SWS_Wdg_00100">[SWS_Wdg_00100]</a>. Sie beschreibt nur die Controllerregister, die andere Hardwaremodule weder beeinflussen noch von ihnen abhängen. Gemeinsam genutzte Register initialisiert ein übergreifendes Systemmodul <a class="spec-record-ref" data-req="SWS_Wdg_00101" href="../../spec/record.html?id=SWS_Wdg_00101">[SWS_Wdg_00101]</a>. Bei aktivierter Entwicklungsfehlererkennung wechselt der interne Zustand nach erfolgreicher Initialisierung von <code>WDG_UNINIT</code> nach <code>WDG_IDLE</code> <a class="spec-record-ref" data-req="SWS_Wdg_00019" href="../../spec/record.html?id=SWS_Wdg_00019">[SWS_Wdg_00019]</a>.</p>
<p>Abbildung 9.1 der Spezifikation zeigt die Arbeitsteilung: EcuM initialisiert Wdg direkt, danach steuert WdgM über WdgIf Triggerbedingung und Modus (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-57a24908c6098394.html" data-snip="FIG-57a24908c6098394">SWS Wdg Abb. 9.1 S. 34</a>). Für Integratoren ist wichtig: Ab <code>Wdg_Init</code> gelten der konfigurierte Standardmodus und die initiale Timeout-Periode <a class="spec-record-ref" data-req="SWS_Wdg_00001" href="../../spec/record.html?id=SWS_Wdg_00001">[SWS_Wdg_00001]</a>. Ist dieser Modus nicht OFF, muss die steuernde Instanz die Triggerbedingung innerhalb des Zeitfensters erneuern, sonst läuft der Watchdog ab <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>.</p>

<h4>Triggerbedingung: befristete Erlaubnis zum Bedienen</h4>
<p>Die Hardware wird nicht durch einzelne Triggeraufrufe von außen bedient. Stattdessen gilt eine Triggerbedingung: Solange sie gültig ist, bedient der Treiber die Hardware selbst. Wird sie ungültig, stellt er das Triggern ein, und der Watchdog läuft ab <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>. Die Spezifikation beschreibt die Bedingung als „Erlaubnis, den Watchdog für die nächsten n Millisekunden zu bedienen“. Die steuernde Instanz muss sie innerhalb dieses Fensters erneuern <a class="spec-record-ref" data-req="SWS_Wdg_00144" href="../../spec/record.html?id=SWS_Wdg_00144">[SWS_Wdg_00144]</a>.</p>
<p><code>Wdg_SetTriggerCondition(uint16 timeout)</code> setzt den Timeout-Zähler entsprechend dem übergebenen Wert zurück (<a class="spec-record-ref" data-req="SWS_Wdg_00155" href="../../spec/record.html?id=SWS_Wdg_00155">[SWS_Wdg_00155]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00136" href="../../spec/record.html?id=SWS_Wdg_00136">[SWS_Wdg_00136]</a>). Der Wert wird als Millisekunden interpretiert. Der Treiber rechnet ihn intern in einen Zählerwert um <a class="spec-record-ref" data-req="SWS_Wdg_00138" href="../../spec/record.html?id=SWS_Wdg_00138">[SWS_Wdg_00138]</a> und berücksichtigt dabei den aktuellen Modus <a class="spec-record-ref" data-req="SWS_Wdg_00139" href="../../spec/record.html?id=SWS_Wdg_00139">[SWS_Wdg_00139]</a>. Der Wert 0 ist zulässig: Er beendet das Triggern (nahezu) sofort und löst damit einen (nahezu) sofortigen Watchdog-Reset aus. Steht der gespeicherte Zähler bereits auf 0, ignoriert die Funktion jeden neuen Wert <a class="spec-record-ref" data-req="SWS_Wdg_00140" href="../../spec/record.html?id=SWS_Wdg_00140">[SWS_Wdg_00140]</a>. Ein abgelaufener Zähler lässt sich also nicht mehr neu laden.</p>
<p>Das eigentliche Triggern erledigt eine treiberinterne Bedienroutine. Ist der Triggerzähler größer als null, dekrementiert sie ihn und triggert die Hardware <a class="spec-record-ref" data-req="SWS_Wdg_00134" href="../../spec/record.html?id=SWS_Wdg_00134">[SWS_Wdg_00134]</a>. Hat er null erreicht, tut sie nichts, und der Watchdog läuft ab <a class="spec-record-ref" data-req="SWS_Wdg_00135" href="../../spec/record.html?id=SWS_Wdg_00135">[SWS_Wdg_00135]</a>. Wird die Bedienung als Interruptroutine umgesetzt, gehören die Interrupt-Rahmen in <code>Wdg_Irq.c</code> <a class="spec-record-ref" data-req="SWS_Wdg_00079" href="../../spec/record.html?id=SWS_Wdg_00079">[SWS_Wdg_00079]</a>. Abbildung 9.2 zeigt dafür einen Timer-Interrupt, der das Triggern zeitlich unabhängig vom Aufruf über WdgIf auslöst (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-10a29405f31a4750.html" data-snip="FIG-10a29405f31a4750">SWS Wdg Abb. 9.2 S. 31</a>).</p>

<h4>Betriebsmodi OFF, SLOW und FAST</h4>
<p><code>Wdg_SetMode</code> schaltet Treiber und Hardware vom aktuellen Modus in <code>WDGIF_OFF_MODE</code>, <code>WDGIF_SLOW_MODE</code> oder <code>WDGIF_FAST_MODE</code>. Jeder Modus entspricht einer statisch konfigurierten Einstellung, etwa Toggle- oder Window-Watchdog mit unterschiedlichen Timeout-Perioden <a class="spec-record-ref" data-req="SWS_Wdg_00160" href="../../spec/record.html?id=SWS_Wdg_00160">[SWS_Wdg_00160]</a>. Die hardwarespezifischen Parameter je Modus stehen im Konfigurationssatz, der an <code>Wdg_Init</code> übergeben wird <a class="spec-record-ref" data-req="SWS_Wdg_00051" href="../../spec/record.html?id=SWS_Wdg_00051">[SWS_Wdg_00051]</a>. Den Typ <code>WdgIf_ModeType</code> importiert Wdg aus <code>WdgIf.h</code> <a class="spec-record-ref" data-req="SWS_Wdg_00105" href="../../spec/record.html?id=SWS_Wdg_00105">[SWS_Wdg_00105]</a>. Ein älteres Konfigurationsmodell zeigt dazu die Container <code>WdgSettingsFast</code>, <code>WdgSettingsSlow</code> und <code>WdgSettingsOff</code> sowie <code>WdgDefaultMode</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-0b58f40a48e8e52d.html" data-snip="FIG-0b58f40a48e8e52d">ECUC-Parameter Abb. 5.21 S. 377</a>).</p>
<p><code>Wdg_SetMode</code> liefert <code>E_OK</code> nur, wenn der Wechsel vollständig ausgeführt ist und alle Parameter von Treiber und Hardware die neuen Werte haben <a class="spec-record-ref" data-req="SWS_Wdg_00103" href="../../spec/record.html?id=SWS_Wdg_00103">[SWS_Wdg_00103]</a>. WdgIf reicht diesen Rückgabewert unverändert weiter (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_STD_SECTION_8_3_1_WdgIf_SetMode.html" data-snip="SNIP_CLASSIC_STD_SECTION_8_3_1_WdgIf_SetMode">SWS WdgIf S. 18</a>). Ob der Watchdog abgeschaltet werden darf, bestimmt der Pre-Compile-Parameter <code>WdgDisableAllowed</code>. Steht er auf <code>OFF</code>, wird eine Initialisierung mit abschaltendem Standardmodus abgelehnt <a class="spec-record-ref" data-req="SWS_Wdg_00025" href="../../spec/record.html?id=SWS_Wdg_00025">[SWS_Wdg_00025]</a>. Der Fehler <code>WDG_E_DISABLE_REJECTED</code> deckt laut seiner Beschreibung auch einen entsprechenden Moduswechsel ab <a class="spec-record-ref" data-req="SWS_Wdg_00179" href="../../spec/record.html?id=SWS_Wdg_00179">[SWS_Wdg_00179]</a>.</p>

<h4>Interne Zustände, exklusive Bereiche und Aktivierungscodes</h4>
<p>Bei aktivierter Entwicklungsfehlererkennung führt Wdg einen internen Zustand: <code>WDG_UNINIT</code> bis zur erfolgreichen Initialisierung, danach <code>WDG_IDLE</code> <a class="spec-record-ref" data-req="SWS_Wdg_00019" href="../../spec/record.html?id=SWS_Wdg_00019">[SWS_Wdg_00019]</a>. <code>Wdg_SetMode</code> und die Bedienroutine setzen während ihrer Ausführung <code>WDG_BUSY</code>. Als letzte Operation vor der Rückkehr setzen sie wieder <code>WDG_IDLE</code> (<a class="spec-record-ref" data-req="SWS_Wdg_00018" href="../../spec/record.html?id=SWS_Wdg_00018">[SWS_Wdg_00018]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00052" href="../../spec/record.html?id=SWS_Wdg_00052">[SWS_Wdg_00052]</a>). Beide prüfen vorher, ob der Zustand <code>WDG_IDLE</code> ist. Andernfalls unterbleibt der Moduswechsel bzw. das Triggern, und <code>WDG_E_DRIVER_STATE</code> wird gemeldet (<a class="spec-record-ref" data-req="SWS_Wdg_00017" href="../../spec/record.html?id=SWS_Wdg_00017">[SWS_Wdg_00017]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00035" href="../../spec/record.html?id=SWS_Wdg_00035">[SWS_Wdg_00035]</a>). So werden Aufrufe vor der Initialisierung erkannt, ebenso Überschneidungen von Moduswechsel und Triggern.</p>
<p>Müssen für Datenkonsistenz Interrupts gesperrt werden, etwa beim Moduswechsel oder in der Triggerroutine, soll dies möglichst über einen exklusiven Bereich des BSW-Schedulers geschehen. Der interne Treiber darf als MCAL-Modul Interrupts auch direkt sperren <a class="spec-record-ref" data-req="SWS_Wdg_00040" href="../../spec/record.html?id=SWS_Wdg_00040">[SWS_Wdg_00040]</a>. Der Leitfaden zur BSW-Verteilung erklärt den Hintergrund: In MCAL-Treibern können Main Function, Service-API und ISR in eigenen Ausführungskontexten auf gemeinsame Peripherieregister zugreifen (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDG_SECTION_2_5_9_Separation_Strategies_and_Mapping_of_Elements.html" data-snip="SNIP_CLASSIC_WDG_SECTION_2_5_9_Separation_Strategies_and_Mapping_of_Elements">BSW Distribution Guide S. 36</a>).</p>
<p>Manche Hardware verlangt einen konfigurierbaren oder veränderlichen Aktivierungscode. Dann verwaltet Wdg den Code intern und übergibt jeweils den korrekten Wert. Die Hardware aktualisiert daraufhin die interne Variable mit dem nächsten erwarteten Code <a class="spec-record-ref" data-req="SWS_Wdg_00093" href="../../spec/record.html?id=SWS_Wdg_00093">[SWS_Wdg_00093]</a>. Der Triggerzyklus muss so gewählt sein, dass diese Aktualisierung garantiert stattfinden kann <a class="spec-record-ref" data-req="SWS_Wdg_00094" href="../../spec/record.html?id=SWS_Wdg_00094">[SWS_Wdg_00094]</a>. Ein konfigurierbarer Anfangscode gehört in den Konfigurationssatz. Bei hardwarefest vorgegebenem Code entfällt diese Anforderung <a class="spec-record-ref" data-req="SWS_Wdg_00095" href="../../spec/record.html?id=SWS_Wdg_00095">[SWS_Wdg_00095]</a>.</p>

<h4>Interne und externe Watchdogs: Instanzen, Dateien, Konfiguration</h4>
<p>Ein Steuergerät kann mehrere Wdg-Instanzen haben, etwa eine für einen internen und eine für einen externen Watchdog. Dann werden API-Namen und instanzspezifische Typnamen <a class="spec-record-ref" data-req="SWS_Wdg_00172" href="../../spec/record.html?id=SWS_Wdg_00172">[SWS_Wdg_00172]</a> sowie Code- und Header-Dateinamen nach SRS_BSW_00347 erweitert (<a class="spec-record-ref" data-req="SWS_Wdg_00169" href="../../spec/record.html?id=SWS_Wdg_00169">[SWS_Wdg_00169]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00170" href="../../spec/record.html?id=SWS_Wdg_00170">[SWS_Wdg_00170]</a>). Abbildung 1 zeigt die Dateistruktur mit Platzhaltern wie <code>Wdg&lt;xxx&gt;.h</code> und <code>Wdg_&lt;xxx&gt;PBcfg.c</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-595d3224912e7b80.html" data-snip="FIG-595d3224912e7b80">SWS Wdg Abb. 1 S. 11</a>). Ein externer Wdg muss denselben Funktionsumfang mit semantisch identischer API bieten wie ein interner <a class="spec-record-ref" data-req="SWS_Wdg_00077" href="../../spec/record.html?id=SWS_Wdg_00077">[SWS_Wdg_00077]</a>. Sein Quellcode muss unabhängig von der Mikrocontrollerplattform sein <a class="spec-record-ref" data-req="SWS_Wdg_00055" href="../../spec/record.html?id=SWS_Wdg_00055">[SWS_Wdg_00055]</a>. Ein Beispiel aus dem Safety-Umfeld ist ein externer Window-Watchdog, der per SPI angebunden ist (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-4d91c10beb7b4cca.html" data-snip="FIG-4d91c10beb7b4cca">EXP SafetyUseCase Abb. 4.1 S. 20</a>).</p>
<p>Die Codedateistruktur ist nicht vollständig vorgegeben. Bei Bedarf umfasst sie <code>Wdg_Lcfg.c</code> für Link-Time-Parameter und <code>Wdg_PBcfg.c</code> für Post-Build-Parameter <a class="spec-record-ref" data-req="SWS_Wdg_00079" href="../../spec/record.html?id=SWS_Wdg_00079">[SWS_Wdg_00079]</a>. Wdg prüft die Konfiguration spätestens zur Compile-Zeit statisch <a class="spec-record-ref" data-req="SWS_Wdg_00086" href="../../spec/record.html?id=SWS_Wdg_00086">[SWS_Wdg_00086]</a>. Ob der Code aus ROM oder RAM läuft, legt eine statische Konfiguration fest <a class="spec-record-ref" data-req="SWS_Wdg_00168" href="../../spec/record.html?id=SWS_Wdg_00168">[SWS_Wdg_00168]</a>. Für externe Hardware nimmt Wdg die Zugriffsparameter, etwa SPI-Kanal oder DIO-Port, in seine veröffentlichten Parameter und seine Konfigurationsparameter auf <a class="spec-record-ref" data-req="SWS_Wdg_00078" href="../../spec/record.html?id=SWS_Wdg_00078">[SWS_Wdg_00078]</a>. Jüngere Releases modellieren das als Auswahlreferenz <code>WdgExternalContainerRef</code> auf eine DIO-Kanalgruppe, eine SPI-Sequenz oder eine I2C-Sequenz. I2C wird in R20-11 nicht ausdrücklich genannt (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_10_2_2_WdgSettingsFast.html" data-snip="SNIP_CLASSIC_DEM_SECTION_10_2_2_WdgSettingsFast">SWS Wdg S. 40</a>). Gegen den Maximalwert <code>WdgMaxTimeout</code> prüft <code>Wdg_SetTriggerCondition</code> <a class="spec-record-ref" data-req="SWS_Wdg_00146" href="../../spec/record.html?id=SWS_Wdg_00146">[SWS_Wdg_00146]</a>. Das Modell der veröffentlichten Informationen enthält daneben <code>WdgMinTimeout</code> und <code>WdgResolution</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c139a9bf0a318e1e.html" data-snip="FIG-c139a9bf0a318e1e">ECUC-Parameter Abb. 5.22 S. 380</a>).</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Wdg unterscheidet Entwicklungsfehler, die überwiegend nur bei aktivierter Entwicklungsfehlererkennung geprüft werden, von erweiterten Produktionsfehlern. Die Fehlercodes sind festgelegt <a class="spec-record-ref" data-req="SWS_Wdg_00010" href="../../spec/record.html?id=SWS_Wdg_00010">[SWS_Wdg_00010]</a>:</p>
<ul>
<li><code>WDG_E_DRIVER_STATE</code> (0x10)</li>
<li><code>WDG_E_PARAM_MODE</code> (0x11)</li>
<li><code>WDG_E_PARAM_CONFIG</code> (0x12)</li>
<li><code>WDG_E_PARAM_TIMEOUT</code> (0x13)</li>
<li><code>WDG_E_PARAM_POINTER</code> (0x14)</li>
<li><code>WDG_E_INIT_FAILED</code> (0x15, ungültige Auswahl des Konfigurationssatzes)</li>
</ul>
<p>Für Entwicklungsfehler fordert Wdg optional <code>Det_ReportError</code> an <a class="spec-record-ref" data-req="SWS_Wdg_00111" href="../../spec/record.html?id=SWS_Wdg_00111">[SWS_Wdg_00111]</a>. Die Fehlerfälle der einzelnen Dienste:</p>
<ul>
<li><strong>Initialisierung:</strong> Liegt der Konfigurationssatz außerhalb der zulässigen Grenzen, unterbleibt die Initialisierung mit <code>WDG_E_PARAM_CONFIG</code> <a class="spec-record-ref" data-req="SWS_Wdg_00090" href="../../spec/record.html?id=SWS_Wdg_00090">[SWS_Wdg_00090]</a>. Würde der Standardmodus den Watchdog abschalten, obwohl <code>WdgDisableAllowed==OFF</code> gilt, unterbleibt sie mit <code>WDG_E_DISABLE_REJECTED</code> <a class="spec-record-ref" data-req="SWS_Wdg_00025" href="../../spec/record.html?id=SWS_Wdg_00025">[SWS_Wdg_00025]</a>.</li>
<li><strong>Moduswechsel:</strong> Ein falscher Zustand führt zu <code>WDG_E_DRIVER_STATE</code> <a class="spec-record-ref" data-req="SWS_Wdg_00017" href="../../spec/record.html?id=SWS_Wdg_00017">[SWS_Wdg_00017]</a>. Ein Modus außerhalb des Bereichs oder unzulässige Hardwareeinstellungen führen zu <code>WDG_E_PARAM_MODE</code> (<a class="spec-record-ref" data-req="SWS_Wdg_00091" href="../../spec/record.html?id=SWS_Wdg_00091">[SWS_Wdg_00091]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00092" href="../../spec/record.html?id=SWS_Wdg_00092">[SWS_Wdg_00092]</a>). In allen drei Fällen findet kein Wechsel statt, und die Funktion liefert <code>E_NOT_OK</code>. Scheitert der Wechsel selbst, etwa an inkonsistenten Einstellungen oder verletzten Zeitbedingungen, liefert sie <code>E_NOT_OK</code> und meldet <code>WDG_E_MODE_FAILED</code> <a class="spec-record-ref" data-req="SWS_Wdg_00016" href="../../spec/record.html?id=SWS_Wdg_00016">[SWS_Wdg_00016]</a>.</li>
<li><strong>Triggerbedingung:</strong> Überschreitet der Timeout <code>WdgMaxTimeout</code>, wird der Zähler nicht neu geladen, und <code>WDG_E_PARAM_TIMEOUT</code> wird gemeldet <a class="spec-record-ref" data-req="SWS_Wdg_00146" href="../../spec/record.html?id=SWS_Wdg_00146">[SWS_Wdg_00146]</a>.</li>
<li><strong>Versionsabfrage:</strong> Ein ungültiger Zeiger fällt unter <code>WDG_E_PARAM_POINTER</code> <a class="spec-record-ref" data-req="SWS_Wdg_00010" href="../../spec/record.html?id=SWS_Wdg_00010">[SWS_Wdg_00010]</a>. Die Nullzeiger-Prüfung für <code>Wdg_GetVersionInfo</code> beschreibt eine Dokumentstelle aus jüngeren Releases (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDG_SECTION_8_3_4_Wdg_GetVersionInfo.html" data-snip="SNIP_CLASSIC_WDG_SECTION_8_3_4_Wdg_GetVersionInfo">SWS Wdg S. 30</a>).</li>
</ul>
<p>Die Produktionsfehler <code>WDG_E_MODE_FAILED</code> und <code>WDG_E_DISABLE_REJECTED</code> betreffen Initialisierung und Moduswechsel. Ihre Überwachungsfrequenz hängt von der oberen Schicht ab (<a class="spec-record-ref" data-req="SWS_Wdg_00178" href="../../spec/record.html?id=SWS_Wdg_00178">[SWS_Wdg_00178]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00179" href="../../spec/record.html?id=SWS_Wdg_00179">[SWS_Wdg_00179]</a>). Sie werden mit FAILED gemeldet, wenn Setzen bzw. Abschalten des Modus scheitert, und mit PASSED, wenn es gelingt (<a class="spec-record-ref" data-req="SWS_Wdg_00180" href="../../spec/record.html?id=SWS_Wdg_00180">[SWS_Wdg_00180]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00181" href="../../spec/record.html?id=SWS_Wdg_00181">[SWS_Wdg_00181]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00182" href="../../spec/record.html?id=SWS_Wdg_00182">[SWS_Wdg_00182]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00183" href="../../spec/record.html?id=SWS_Wdg_00183">[SWS_Wdg_00183]</a>). Diese Meldungen dürften über das optional angeforderte <code>Dem_SetEventStatus</code> laufen <a class="spec-record-ref" data-req="SWS_Wdg_00111" href="../../spec/record.html?id=SWS_Wdg_00111">[SWS_Wdg_00111]</a>. Der gravierendste Fall erscheint bewusst nicht als Rückgabewert: Bleibt die Triggerbedingung aus oder wird 0 gesetzt, läuft der Watchdog ab, und das Steuergerät wird zurückgesetzt (<a class="spec-record-ref" data-req="SWS_Wdg_00135" href="../../spec/record.html?id=SWS_Wdg_00135">[SWS_Wdg_00135]</a>, <a class="spec-record-ref" data-req="SWS_Wdg_00140" href="../../spec/record.html?id=SWS_Wdg_00140">[SWS_Wdg_00140]</a>).</p>
