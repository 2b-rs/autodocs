<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::SignerPrivateCtx</code> defines the context for cryptographic signature operations using a private key on the AUTOSAR Adaptive Platform. As a specialization of <code>CryptoContext</code>, it encapsulates the algorithm logic for creating digital signatures over message blocks of arbitrary size.</p>
<p>The primary interaction partners of the interface include:</p>
<ul>
<li><strong>Calling application component:</strong> Controls the signature process, passes the input data, and receives the signature result.</li>
<li><strong>Key objects:</strong> The context requires access to private key material. This is either passed directly as <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> or bound via a referenced key slot <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>.</li>
<li><strong>Memory buffers:</strong> Input data and optional context data are provided as <code>ReadOnlyMemRegion</code>, while the resulting signature value is written to a writable buffer of type <code>ReadWriteMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>.</li>
</ul>

<h4>Lifecycle</h4>
<p>Context instances are typically managed as smart pointers via the provided type alias <code>ara::crypto::cryp::SignerPrivateCtx::Sptr</code> (defined as <code>std::shared_ptr&lt;SignerPrivateCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>. Since the class provides pure virtual interface methods, object creation is likely performed via a factory method of a higher-level crypto service.</p>
<p>The lifecycle of the context is divided into distinct phases:</p>
<ol>
<li><strong>Uninitialized:</strong> Immediately after instantiation, no key is assigned to the context. Direct signature or start calls are rejected with an error in this state <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>.</li>
<li><strong>Configured (Ready):</strong> By calling <code>SetKey()</code> with a <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> or a <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>, the context becomes ready for operation. From this state, either a one-shot signature can be executed via <code>Sign()</code> or streaming processing can be initiated.</li>
<li><strong>Streaming active:</strong> A call to <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a> or <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50038" href="../spec/record.html?id=SWS_CRYPT_50038">[SWS_CRYPT_50038]</a> puts the context into ongoing processing. In this phase, iterative updates can be performed via <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>.</li>
<li><strong>Completion or abort:</strong> The ongoing streaming sequence ends regularly via <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> or is aborted prematurely via <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>. After both methods, the context presumably remains in the configured state with an assigned key, so that a new signature calculation can be started directly.</li>
</ol>
<p>All interface methods are declared as <code>noexcept</code>, have the exception safety level <em>exception safe</em>, and are designed to be thread-safe according to the specification <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>.</p>

<h4>Usage Path</h4>
<p>The interface supports two functional usage paths for signature calculation:</p>
<p><strong>1. Streaming-based signature generation:</strong> This path is suitable for large or fragmented incoming messages. Before starting, the maximum permissible block size can be determined via <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50042" href="../spec/record.html?id=SWS_CRYPT_50042">[SWS_CRYPT_50042]</a> and the expected signature length for a specific target format via <code>GetSignatureSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_29004" href="../spec/record.html?id=SWS_CRYPT_29004">[SWS_CRYPT_29004]</a>. After assigning the key via <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a>, the calculation is initialized by <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>. Subsequently, partial messages are fed in sequentially via <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a>. Calling <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a> completes the signature generation and writes the result to the provided buffer.</p>

<p><strong>2. Single-call signature generation:</strong> If the complete message is already available in a contiguous memory area, the method <code>Sign()</code> can alternatively be called <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>. It processes the message, the desired format, and optional context data in a single atomic step and writes the signature directly into the output buffer.</p>
