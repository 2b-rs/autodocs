<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient der digitalen Signaturerstellung unter Verwendung privater kryptografischer Schlüssel im Einzelschritt- oder Streaming-Verfahren.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>ara::crypto::cryp::SignerPrivateCtx</code> kapselt private Schlüssel für digitale Signaturoperationen auf der Adaptive Platform <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>. Nach Konfiguration des Schlüssels über <code>SetKey()</code> können Nachrichten entweder in einem Einzelschritt per <code>Sign()</code> oder mehrstufig via <code>Start()</code>, <code>Update()</code> und <code>Finish()</code> signiert werden <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>. Sämtliche Aufrufe sind threadsicher und signalisieren Fehler wie unzureichende Pufferkapazitäten oder ungültige Kontextzustände über <code>ara::core::Result</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::crypto::cryp::SignerPrivateCtx</code> repräsentiert den kryptografischen Ausführungskontext für digitale Signaturoperationen unter Verwendung eines privaten Schlüssels auf der AUTOSAR Adaptive Platform. Die Klasse erbt von <code>CryptoContext</code> und kapselt asymmetrische Signaturalgorithmen. Zur Anbindung des erforderlichen Schlüsselmaterials interagiert der Kontext entweder direkt mit einem privaten Schlüsselobjekt über <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> oder mit einem verwalteten Schlüsselsteckplatz über <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>. Aufrufer verwalten Instanzen dieser Schnittstelle typischerweise über den definierten Smart-Pointer-Typ-Alias <code>ara::crypto::cryp::SignerPrivateCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>SignerPrivateCtx</code> werden als zustandsbehaftete Objekte betrieben und über Shared-Pointer-Strukturen (<code>std::shared_ptr</code>) verwaltet <a class="spec-record-ref" data-req="SWS_CRYPT_23501" href="../spec/record.html?id=SWS_CRYPT_23501">[SWS_CRYPT_23501]</a>. Vor der Durchführung kryptografischer Berechnungen befindet sich die Instanz in einem uninitialisierten Zustand und verlangt die Zuweisung eines passenden Schlüssels. Über die Methode <code>SetKey()</code> wird dem Kontext entweder ein konkreter privater Schlüssel zugewiesen <a class="spec-record-ref" data-req="SWS_CRYPT_23515" href="../spec/record.html?id=SWS_CRYPT_23515">[SWS_CRYPT_23515]</a> oder ein <code>KeySlot</code> hinterlegt, dessen Schlüsselwert zum Startzeitpunkt der Signaturberechnung herangezogen wird <a class="spec-record-ref" data-req="SWS_CRYPT_50036" href="../spec/record.html?id=SWS_CRYPT_50036">[SWS_CRYPT_50036]</a>. Sobald ein Schlüssel erfolgreich gebunden wurde, geht der Kontext in den betriebsbereiten Zustand über. Sämtliche Schnittstellenmethoden sind als ausnahmesicher (exception safe) und threadsicher (thread-safe) spezifiziert <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a>.</p>

<p>Innerhalb der Datenverarbeitung unterscheidet die Schnittstelle zwischen der Einmalsignierung und mehrstufigen Streaming-Verfahren. Eine Streaming-Signaturoperation wird durch <code>Start()</code> initiiert <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50038" href="../spec/record.html?id=SWS_CRYPT_50038">[SWS_CRYPT_50038]</a>, schrittweise mit Datenblöcken über <code>Update()</code> versorgt <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a> und durch <code>Finish()</code> finalisiert <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>. Alternativ kann ein laufendes Streaming jederzeit über <code>Cancel()</code> abgebrochen werden, womit die Instanz in den betriebsbereiten Zustand zurückkehrt <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Anwendungen können Signaturen entweder in einem Einzelschritt (Single-Call) oder als fortlaufenden Datenstrom (Streaming) erzeugen. Vor der Ausführung ermittelt die Anwendung über <code>GetSignatureSize()</code> die erwartete Puffergröße für das gewünschte Signaturformat <code>FormatId</code> <a class="spec-record-ref" data-req="SWS_CRYPT_29004" href="../spec/record.html?id=SWS_CRYPT_29004">[SWS_CRYPT_29004]</a> sowie über <code>GetMaximumChunkSize()</code> die maximal zulässige Blockgröße einzelner Einleseoperationen <a class="spec-record-ref" data-req="SWS_CRYPT_50042" href="../spec/record.html?id=SWS_CRYPT_50042">[SWS_CRYPT_50042]</a>.</p>

<p>Im Einzelschrittpfad wird die vollständige Nachricht mittels <code>Sign()</code> direkt signiert. Die Methode nimmt die Eingabenachricht, den Zielpuffer <code>ReadWriteMemRegion</code>, das Signaturformat sowie einen optionalen algorithmusspezifischen Kontextwert entgegen und liefert die tatsächliche Anzahl geschriebener Bytes zurück <a class="spec-record-ref" data-req="SWS_CRYPT_23512" href="../spec/record.html?id=SWS_CRYPT_23512">[SWS_CRYPT_23512]</a>.</p>

<p>Für größere Datenmengen oder fragmentierte Nachrichten folgt der Streaming-Pfad einem dreiphasigen Muster:</p>
<ol>
  <li><strong>Initialisierung:</strong> Aufruf von <code>Start()</code> ohne Parameter <a class="spec-record-ref" data-req="SWS_CRYPT_50037" href="../spec/record.html?id=SWS_CRYPT_50037">[SWS_CRYPT_50037]</a> oder mit einem anwendungsspezifischen Kontextpuffer <code>ReadOnlyMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50038" href="../spec/record.html?id=SWS_CRYPT_50038">[SWS_CRYPT_50038]</a>.</li>
  <li><strong>Verarbeitung:</strong> Wiederholte Zufuhr von Teilnachrichten über <code>Update()</code>, wobei jeder Block die durch <code>GetMaximumChunkSize()</code> vorgegebene Obergrenze einhalten muss <a class="spec-record-ref" data-req="SWS_CRYPT_50039" href="../spec/record.html?id=SWS_CRYPT_50039">[SWS_CRYPT_50039]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50042" href="../spec/record.html?id=SWS_CRYPT_50042">[SWS_CRYPT_50042]</a>.</li>
  <li><strong>Abschluss oder Abbruch:</strong> Finalisierung der Signaturerzeugung und Schreiben in den Zielspeicher via <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50040" href="../spec/record.html?id=SWS_CRYPT_50040">[SWS_CRYPT_50040]</a>, oder vorzeitiger Abbruch des laufenden Vorgangs mittels <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50041" href="../spec/record.html?id=SWS_CRYPT_50041">[SWS_CRYPT_50041]</a>.</li>
</ol>
