<h4>Verwendung und Semantik</h4>
<p>Die Funktion <code>Get</code> ist eine parameterlose Elementfunktion der Klasse <code>ara::com::SamplePtr</code> aus dem Header <code>ara/com/service/sample_ptr.h</code> <a class="spec-record-ref" data-req="SWS_CM_11546" href="../spec/record.html?id=SWS_CM_11546">[SWS_CM_11546]</a>. Sie liefert synchron einen Rohzeiger vom Typ <code>T*</code> auf das durch die Instanz verwaltete Objekt zurück <a class="spec-record-ref" data-req="SWS_CM_11546" href="../spec/record.html?id=SWS_CM_11546">[SWS_CM_11546]</a>. Im Unterschied zu asynchronen Abfragen von Service-Feldern, die ein <code>ara::core::Future</code> bereitstellen <a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>, erfolgt dieser Zugriff unmittelbar im aufrufenden Thread.</p>
<h4>Fehlerbehandlung und Randbedingungen</h4>
<p>Die Methode ist als <code>noexcept</code> deklariert und als ausnahmesicher (<em>exception safe</em>) spezifiziert <a class="spec-record-ref" data-req="SWS_CM_11546" href="../spec/record.html?id=SWS_CM_11546">[SWS_CM_11546]</a>; Fehlerzustände über C++-Exceptions treten nicht auf. Falls die Instanz aktuell kein Objekt verwaltet, dürfte der zurückgegebene Zeiger vermutlich <code>nullptr</code> sein. <a class="interp-q interp-q-open" data-q="Q-d850bd8ee144369a" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-d850bd8ee144369a" title="Frage Q-d850bd8ee144369a (offen): Wenn SamplePtr kein Objekt hält, dürfte Get() vermutlich nullptr zurückgeben">Frage Q-d850bd8ee144369a (offen)</a> Vor der Weiterverarbeitung des referenzierten Datums muss sichergestellt sein, dass die E2E-Überwachung den Zustand <code>ara::com::e2e::SMState::kValid</code> aufweist und die Statusprüfung des Profils keinen Fehler ergab <a class="spec-record-ref" data-req="SWS_CM_90422" href="../spec/record.html?id=SWS_CM_90422">[SWS_CM_90422]</a>.</p>
<h4>Zusammenspiel und Abgrenzung</h4>
<p>Im Kommunikationsmanagement dient <code>Get</code> dem direkten Datenzugriff auf empfangene Werte (Samples), wie sie im Rahmen des Sample-Managements bereitgestellt werden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">AUTOSAR_AP_EXP_ARAComAPI §10 „GetNewSamples“</a>. Diese Funktion ist klar von anderen <code>Get</code>-Operationen abzugrenzen:</p>
<ul>
<li><strong>Feld-Getter:</strong> Das Abrufen von Service-Feldern am Proxy geschieht über <code>Get()</code> mit Rückgabe eines <code>ara::core::Future</code> <a class="spec-record-ref" data-req="SWS_CM_00112" href="../spec/record.html?id=SWS_CM_00112">[SWS_CM_00112]</a>, wofür serverseitig ein Handler registriert werden kann <a class="spec-record-ref" data-req="SWS_CM_00114" href="../spec/record.html?id=SWS_CM_00114">[SWS_CM_00114]</a>.</li>
<li><strong>E2E-Zustand:</strong> Der Überwachungszustand eines Feld-Getters wird separat über <code>GetE2EStateMachineStateGetter</code> ermittelt <a class="spec-record-ref" data-req="SWS_CM_00145" href="../spec/record.html?id=SWS_CM_00145">[SWS_CM_00145]</a>.</li>
</ul>
