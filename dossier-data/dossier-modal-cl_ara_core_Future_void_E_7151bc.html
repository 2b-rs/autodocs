<h4>Context</h4>
<p>The template specialization <code>ara::core::Future&lt;void, E&gt;</code> represents the receiver endpoint for asynchronous operations that do not return a payload value, but exclusively signal successful completion or the occurrence of an error. The specification strictly requires the type <code>ara::core::ErrorCode</code> for the error template parameter <code>E</code>; deviating types lead to a compile error.</p>
<p>In the AUTOSAR Adaptive architecture, <code>Future&lt;void, E&gt;</code> typically interacts with an asynchronous producer (such as a corresponding promise object) and the calling application code. The producer determines via the shared state when the operation is complete. The consumer queries the status via <code>Future&lt;void, E&gt;</code>, blocks synchronously until completion, or registers non-blocking continuations for subsequent processing.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::core::Future&lt;void, E&gt;</code> is a move-only object: The copy constructor <a class="spec-record-ref" data-req="SWS_CORE_06234" href="../spec/record.html?id=SWS_CORE_06234">[SWS_CORE_06234]</a> and the assignment operator by copy <a class="spec-record-ref" data-req="SWS_CORE_06235" href="../spec/record.html?id=SWS_CORE_06235">[SWS_CORE_06235]</a> are deleted (<code>delete</code>). Ownership of the shared state can be transferred exclusively by move construction <a class="spec-record-ref" data-req="SWS_CORE_06223" href="../spec/record.html?id=SWS_CORE_06223">[SWS_CORE_06223]</a> or move assignment <a class="spec-record-ref" data-req="SWS_CORE_06225" href="../spec/record.html?id=SWS_CORE_06225">[SWS_CORE_06225]</a>.</p>
<p>The lifecycle is divided into the following phases and states:</p>
<ul>
<li><strong>Invalid (no shared state):</strong> If a future is created via the default constructor <a class="spec-record-ref" data-req="SWS_CORE_06222" href="../spec/record.html?id=SWS_CORE_06222">[SWS_CORE_06222]</a>, it has no shared state. The method <code>valid()</code> returns <code>false</code> <a class="spec-record-ref" data-req="SWS_CORE_06227" href="../spec/record.html?id=SWS_CORE_06227">[SWS_CORE_06227]</a>. The instance also falls back into this state as soon as the state has been consumed by moving, by retrieving the result by means of <code>GetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_06236" href="../spec/record.html?id=SWS_CORE_06236">[SWS_CORE_06236]</a> or <code>get()</code> <a class="spec-record-ref" data-req="SWS_CORE_06226" href="../spec/record.html?id=SWS_CORE_06226">[SWS_CORE_06226]</a>, or by registering a continuation via <code>then()</code> <a class="spec-record-ref" data-req="SWS_CORE_06231" href="../spec/record.html?id=SWS_CORE_06231">[SWS_CORE_06231]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06237" href="../spec/record.html?id=SWS_CORE_06237">[SWS_CORE_06237]</a>.</li>
<li><strong>Valid and pending:</strong> After linking with a producer, <code>valid() == true</code> is <a class="spec-record-ref" data-req="SWS_CORE_06227" href="../spec/record.html?id=SWS_CORE_06227">[SWS_CORE_06227]</a>. As long as the operation is active, <code>is_ready()</code> reports the value <code>false</code> <a class="spec-record-ref" data-req="SWS_CORE_06232" href="../spec/record.html?id=SWS_CORE_06232">[SWS_CORE_06232]</a>.</li>
<li><strong>Ready:</strong> As soon as the producer has stored successful completion or an error (or aborts the operation), <code>is_ready() == true</code> reports <a class="spec-record-ref" data-req="SWS_CORE_06232" href="../spec/record.html?id=SWS_CORE_06232">[SWS_CORE_06232]</a>. Calls to <code>GetResult()</code> or the wait functions are guaranteed no longer to block in this state.</li>
<li><strong>Destruction:</strong> The destructor <code>~Future()</code> <a class="spec-record-ref" data-req="SWS_CORE_06233" href="../spec/record.html?id=SWS_CORE_06233">[SWS_CORE_06233]</a> abandons the shared state (abandons shared state). If a continuation was previously passed via <code>then()</code> to a future derived therefrom, the destructor of that returned object blocks, if applicable, until an already running continuation function has completely finished <a class="spec-record-ref" data-req="SWS_CORE_06231" href="../spec/record.html?id=SWS_CORE_06231">[SWS_CORE_06231]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06237" href="../spec/record.html?id=SWS_CORE_06237">[SWS_CORE_06237]</a>.</li>
</ul>
<p>With regard to concurrency, checks such as <code>valid()</code> <a class="spec-record-ref" data-req="SWS_CORE_06227" href="../spec/record.html?id=SWS_CORE_06227">[SWS_CORE_06227]</a>, <code>is_ready()</code> <a class="spec-record-ref" data-req="SWS_CORE_06232" href="../spec/record.html?id=SWS_CORE_06232">[SWS_CORE_06232]</a>, and the destructor <a class="spec-record-ref" data-req="SWS_CORE_06233" href="../spec/record.html?id=SWS_CORE_06233">[SWS_CORE_06233]</a> are thread-safe. State-modifying operations and value retrievals (<code>GetResult</code>, <code>get</code>, <code>wait*</code>, <code>then</code>, move operations) are not thread-safe with respect to the same object and require external synchronization.</p>

<h4>Usage Path</h4>
<p>For evaluating an asynchronous operation without a return value, two main usage paths are available: synchronous waiting and asynchronous chaining.</p>
<ol>
<li><strong>Synchronous retrieval via <code>GetResult()</code>:</strong> The consumer can optionally check whether the result is available using <code>is_ready()</code> <a class="spec-record-ref" data-req="SWS_CORE_06232" href="../spec/record.html?id=SWS_CORE_06232">[SWS_CORE_06232]</a>, or wait for the event using <code>wait()</code> <a class="spec-record-ref" data-req="SWS_CORE_06228" href="../spec/record.html?id=SWS_CORE_06228">[SWS_CORE_06228]</a>, <code>wait_for()</code> <a class="spec-record-ref" data-req="SWS_CORE_06229" href="../spec/record.html?id=SWS_CORE_06229">[SWS_CORE_06229]</a>, or <code>wait_until()</code> <a class="spec-record-ref" data-req="SWS_CORE_06230" href="../spec/record.html?id=SWS_CORE_06230">[SWS_CORE_06230]</a>, respectively. The actual retrieval is performed via <code>GetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_06236" href="../spec/record.html?id=SWS_CORE_06236">[SWS_CORE_06236]</a>. This blocks until completion if necessary and returns a <code>ara::core::Result&lt;void, E&gt;</code> without ever throwing C++ exceptions. After the call, the future is no longer valid (<code>valid() == false</code>). Alternatively, the method <code>get()</code> <a class="spec-record-ref" data-req="SWS_CORE_06226" href="../spec/record.html?id=SWS_CORE_06226">[SWS_CORE_06226]</a> exists, which, however, throws errors as an exception and is omitted if exceptions are disabled on the toolchain side.</li>
<li><strong>Reactive chaining via <code>then()</code>:</strong> Instead of blocking waiting, a continuation can be registered using <code>then()</code> <a class="spec-record-ref" data-req="SWS_CORE_06231" href="../spec/record.html?id=SWS_CORE_06231">[SWS_CORE_06231]</a>. To the passed Callable (DEM), the result is passed as an Rvalue expression of type <code>Result&lt;void, E&gt;</code>. Optionally, an explicit execution context can be specified via <code>then(func, executor)</code> <a class="spec-record-ref" data-req="SWS_CORE_06237" href="../spec/record.html?id=SWS_CORE_06237">[SWS_CORE_06237]</a>. The original Future object becomes invalid immediately with the call (<code>valid() == false</code>). The method returns a new Future object and automatically unwraps nested <code>Future</code> or <code>Result</code> types (Unwrapping).</li>
</ol>

<h4>Error Scenarios</h4>
<p>The specification defines strict preconditions and standardized error cases when interacting with <code>Future&lt;void, E&gt;</code>:</p>
<ul>
<li><strong>Invalid future (FutureInvalidViolation):</strong> A precondition of almost all methods (such as <code>is_ready()</code> <a class="spec-record-ref" data-req="SWS_CORE_06232" href="../spec/record.html?id=SWS_CORE_06232">[SWS_CORE_06232]</a>, <code>GetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_06236" href="../spec/record.html?id=SWS_CORE_06236">[SWS_CORE_06236]</a>, <code>wait()</code> <a class="spec-record-ref" data-req="SWS_CORE_06228" href="../spec/record.html?id=SWS_CORE_06228">[SWS_CORE_06228]</a>, <code>wait_for()</code> <a class="spec-record-ref" data-req="SWS_CORE_06229" href="../spec/record.html?id=SWS_CORE_06229">[SWS_CORE_06229]</a>, <code>wait_until()</code> <a class="spec-record-ref" data-req="SWS_CORE_06230" href="../spec/record.html?id=SWS_CORE_06230">[SWS_CORE_06230]</a>, as well as <code>then()</code> <a class="spec-record-ref" data-req="SWS_CORE_06231" href="../spec/record.html?id=SWS_CORE_06231">[SWS_CORE_06231]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06237" href="../spec/record.html?id=SWS_CORE_06237">[SWS_CORE_06237]</a>) is that the instance is valid (<code>valid() == true</code>). If one of these methods is called on an invalid instance, this triggers a <code>FutureInvalidViolation</code>. For <code>get()</code>, this leads to a <code>FutureException</code> with the error code <code>kNoState</code> <a class="spec-record-ref" data-req="SWS_CORE_06226" href="../spec/record.html?id=SWS_CORE_06226">[SWS_CORE_06226]</a> in exception mode.</li>
<li><strong>Abandoned Shared State (Broken Promise):</strong> If the associated promise is destroyed or the shared state is abandoned without setting a value or explicit error, <code>GetResult()</code> reports the error code <code>FutureErrc::kBrokenPromise</code> <a class="spec-record-ref" data-req="SWS_CORE_06236" href="../spec/record.html?id=SWS_CORE_06236">[SWS_CORE_06236]</a> in the returned <code>Result&lt;void, E&gt;</code>. For <code>get()</code>, a corresponding exception is thrown <a class="spec-record-ref" data-req="SWS_CORE_06226" href="../spec/record.html?id=SWS_CORE_06226">[SWS_CORE_06226]</a>.</li>
<li><strong>Exceptions in continuations (FutureContinuationHasThrownViolation):</strong> The callable passed to <code>then()</code> must not let exceptions escape to the outside, unless for deliberately triggering a violation. If a continuation nevertheless throws an impermissible exception, a <code>FutureContinuationHasThrownViolation</code> is triggered <a class="spec-record-ref" data-req="SWS_CORE_06231" href="../spec/record.html?id=SWS_CORE_06231">[SWS_CORE_06231]</a>, <a class="spec-record-ref" data-req="SWS_CORE_06237" href="../spec/record.html?id=SWS_CORE_06237">[SWS_CORE_06237]</a>. Errors in continuations must instead be returned as <code>ara::core::Result</code> or <code>ara::core::Future</code> containing an error code.</li>
</ul>
