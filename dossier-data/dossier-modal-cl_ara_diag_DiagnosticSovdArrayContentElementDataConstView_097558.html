<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht den thread-sicheren, schreibgeschützten Zugriff auf Array-Elemente eines SOVD-Diagnosedatenobjekts.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::DiagnosticSovdArrayContentElementDataConstView</code> bietet eine schreibgeschützte Sicht auf ein <code>DiagnosticSovdContentElementData</code> vom Typ Array zur effizienten Diagnoseabfrage <a class="spec-record-ref" data-req="SWS_DM_02248" href="../spec/record.html?id=SWS_DM_02248">[SWS_DM_02248]</a>. Anwendungen prüfen zunächst mittels <code>HasError()</code> den Integritätsstatus und greifen anschließend entweder wahlfrei über <code>operator[]</code> oder iterativ über <code>CBegin()</code> und <code>CEnd()</code> auf die Feldelemente zu <a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a>. Alle Operationen sind thread-safe sowie ausnahmesicher (<code>noexcept</code>) ausgeführt, setzen jedoch die fortlaufende Gültigkeit des referenzierten Basiselements voraus.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::DiagnosticSovdArrayContentElementDataConstView</code> stellt eine schreibgeschützte Sicht (<code>const view</code>) auf ein Diagnose-Datenelement vom Typ Array innerhalb der Adaptive AUTOSAR Diagnosearchitektur für SOVD (Service-Oriented Vehicle Diagnostics) bereit <a class="spec-record-ref" data-req="SWS_DM_02248" href="../spec/record.html?id=SWS_DM_02248">[SWS_DM_02248]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=768">AUTOSAR_AP_SWS_Diagnostics §8.60.3 „Class: DiagnosticSovdArrayContentElementDataConstView“</a>). Sie ermöglicht den kontrollierten Lesezugriff auf sequenzielle Elemente eines Diagnoseinhalts, ohne dass der zugrunde liegende Datenpuffer kopiert werden muss.</p>

<p>Zu den primären Interaktionspartnern der Klasse zählen:</p>
<ul>
<li>die aufrufende Diagnose-Anwendung, welche Felddaten auswertet,</li>
<li>das referenzierte <code>DiagnosticSovdContentElementData</code>, welches die konkreten Feldelemente speichert und auf das bei wahlfreiem Zugriff über <a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a> referenziert wird,</li>
<li>der Hilfstyp <code>DiagnosticSovdArrayContentElementDataConstIterator</code>, welcher für standardkonforme Iterationen über die Feldelemente erzeugt wird <a class="spec-record-ref" data-req="SWS_DM_02254" href="../spec/record.html?id=SWS_DM_02254">[SWS_DM_02254]</a>.</li>
</ul>

<h4>Lebenszyklus</h4>
<p>Die Klasse ist über den Header <code>#include "ara/diag/diagnostic_sovd_content_element_data.h"</code> verfügbar <a class="spec-record-ref" data-req="SWS_DM_02248" href="../spec/record.html?id=SWS_DM_02248">[SWS_DM_02248]</a>. Als reine Sichtklasse besitzt sie keine Eigentümerschaft an den eigentlichen Array-Daten. Interpretation: Die Lebensdauer einer View-Instanz ist an die Gültigkeit des zugrunde liegenden <code>DiagnosticSovdContentElementData</code> gebunden; das Datenobjekt muss für die Dauer der View-Verwendung im Speicher verbleiben.</p>

<p>Hinsichtlich der Nebenläufigkeit sind sämtliche Elementfunktionen der Klasse explizit als thread-safe deklariert <a class="spec-record-ref" data-req="SWS_DM_02250" href="../spec/record.html?id=SWS_DM_02250">[SWS_DM_02250]</a>, <a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a>. Mehrere Threads können somit simultan lesend auf dieselbe View-Instanz zugreifen (Interpretation: solange das zugrunde liegende Datenobjekt nicht nebenläufig durch Schreiboperationen verändert wird). Zudem garantieren alle Methoden vollständige Exception-Sicherheit (<code>exception safe</code>) und sind ausnahmslos mit <code>noexcept</code> spezifiziert <a class="spec-record-ref" data-req="SWS_DM_02249" href="../spec/record.html?id=SWS_DM_02249">[SWS_DM_02249]</a>, <a class="spec-record-ref" data-req="SWS_DM_02251" href="../spec/record.html?id=SWS_DM_02251">[SWS_DM_02251]</a>. Da es sich um eine unveränderliche Sicht handelt, weist die Klasse keine internen Zustandstransitionen oder komplexen Lebenszyklusphasen auf.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf zur Nutzung der Felddaten gliedert sich in Integritätsprüfung, Dimensionsabfrage und Datenextraktion:</p>
<ol>
<li><strong>Integritätsprüfung:</strong> Vor dem Zugriff sollte die Anwendung über <code>HasError()</code> verifizieren, ob das Inhaltselement fehlerfrei vorliegt <a class="spec-record-ref" data-req="SWS_DM_02249" href="../spec/record.html?id=SWS_DM_02249">[SWS_DM_02249]</a>.</li>
<li><strong>Dimensionsabfrage:</strong> Über <code>Empty()</code> lässt sich prüfen, ob das Array Elemente enthält (<a class="spec-record-ref" data-req="SWS_DM_02252" href="../spec/record.html?id=SWS_DM_02252">[SWS_DM_02252]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=771">AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.5 „Empty“</a>). Die aktuelle Elementanzahl liefert <code>Size()</code> <a class="spec-record-ref" data-req="SWS_DM_02250" href="../spec/record.html?id=SWS_DM_02250">[SWS_DM_02250]</a>, während <code>Capacity()</code> die reservierte Kapazität des Arrays zurückgibt (<a class="spec-record-ref" data-req="SWS_DM_02251" href="../spec/record.html?id=SWS_DM_02251">[SWS_DM_02251]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=770">AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.4 „Capacity“</a>).</li>
<li><strong>Datenzugriff:</strong> Für den Zugriff auf Feldelemente stehen zwei Wege bereit:
<ul>
<li><em>Wahlfreier Zugriff per Index:</em> Über <code>operator[](std::size_t index)</code> wird eine Referenz auf das Zielelement angefordert, gekapselt in <code>ara::core::Result&lt;std::reference_wrapper&lt;DiagnosticSovdContentElementData const&gt;&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_02253" href="../spec/record.html?id=SWS_DM_02253">[SWS_DM_02253]</a>.</li>
<li><em>Sequenzielle Iteration:</em> Für lineare Durchläufe stellen <code>Begin()</code> (<a class="spec-record-ref" data-req="SWS_DM_02254" href="../spec/record.html?id=SWS_DM_02254">[SWS_DM_02254]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=769">AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.1 „Begin“</a>) und <code>End()</code> <a class="spec-record-ref" data-req="SWS_DM_02255" href="../spec/record.html?id=SWS_DM_02255">[SWS_DM_02255]</a> sowie deren explizit konstante Varianten <code>CBegin()</code> (<a class="spec-record-ref" data-req="SWS_DM_02256" href="../spec/record.html?id=SWS_DM_02256">[SWS_DM_02256]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=769">AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.2 „CBegin“</a>) und <code>CEnd()</code> (<a class="spec-record-ref" data-req="SWS_DM_02257" href="../spec/record.html?id=SWS_DM_02257">[SWS_DM_02257]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=770">AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.3 „CEnd“</a>) jeweils einen <code>DiagnosticSovdArrayContentElementDataConstIterator</code> bereit.</li>
</ul>
</li>
</ol>
