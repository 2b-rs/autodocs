<h4>Context</h4>
<p>The <code>ara::diag::ReleaseHandler</code> class provides a mechanism to monitor the status of a shared resource and coordinate the cancellation of ongoing processing (<a class="spec-record-ref" data-req="SWS_DM_01340" href="../spec/record.html?id=SWS_DM_01340">[SWS_DM_01340]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=504">AUTOSAR_AP_SWS_Diagnostics §8.23.1 “Class: ReleaseHandler”</a>). Within the <code>diag</code> module of the AUTOSAR Adaptive Platform, it acts as a link between the higher-level diagnostic framework and the executing diagnostic handlers or data transfer routines.</p>
<p>In diagnostic sequences, resources are frequently shared between multiple components or long-running tasks are executed asynchronously. <code>ReleaseHandler</code> encapsulates a shared state (\"shared state\") that indicates whether the respective resource is still in use or whether processing should be canceled. Interpretation: The instance is likely created primarily by the diagnostic framework and passed to the application, so that the application logic can react specifically to external cancellation or release requests without having to know internal management details of the diagnostic server.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of <code>ReleaseHandler</code> is characterized by strict move semantics without copyability:</p>
<ul>
<li><strong>Creation:</strong> The default constructor is explicitly deleted (<code>=delete</code>) (<a class="spec-record-ref" data-req="SWS_DM_01530" href="../spec/record.html?id=SWS_DM_01530">[SWS_DM_01530]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=505">AUTOSAR_AP_SWS_Diagnostics §8.23.1.2.1.1 “Default Constructor”</a>). Users therefore cannot instantiate instances by default; object creation is the responsibility of the system.</li>
<li><strong>Ownership and transfer:</strong> Duplicating instances is prevented because both the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01534" href="../spec/record.html?id=SWS_DM_01534">[SWS_DM_01534]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01535" href="../spec/record.html?id=SWS_DM_01535">[SWS_DM_01535]</a>) are deleted. Instead, the class implements move semantics: via the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01532" href="../spec/record.html?id=SWS_DM_01532">[SWS_DM_01532]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=506">AUTOSAR_AP_SWS_Diagnostics §8.23.1.2.1.2 “Move Constructor”</a>) and the move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01533" href="../spec/record.html?id=SWS_DM_01533">[SWS_DM_01533]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=506">AUTOSAR_AP_SWS_Diagnostics §8.23.1.2.1.3 “Move Assignment Operator”</a>), ownership can be transferred exclusively to downstream program parts.</li>
<li><strong>Destruction:</strong> The destructor is specified as <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_DM_01531" href="../spec/record.html?id=SWS_DM_01531">[SWS_DM_01531]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=507">AUTOSAR_AP_SWS_Diagnostics §8.23.1.2.1.4 “Destructor”</a>) and terminates the lifecycle of the object regularly upon leaving the scope.</li>
<li><strong>Concurrency:</strong> With respect to thread safety, the specification clearly distinguishes between read and modifying accesses. The query method <code>MayRelease()</code> is classified as thread-safe (<a class="spec-record-ref" data-req="SWS_DM_01536" href="../spec/record.html?id=SWS_DM_01536">[SWS_DM_01536]</a>), as is the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01532" href="../spec/record.html?id=SWS_DM_01532">[SWS_DM_01532]</a>). In contrast, registering notifications via <code>SetNotifier(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>), move assignment (<a class="spec-record-ref" data-req="SWS_DM_01533" href="../spec/record.html?id=SWS_DM_01533">[SWS_DM_01533]</a>), and the destructor (<a class="spec-record-ref" data-req="SWS_DM_01531" href="../spec/record.html?id=SWS_DM_01531">[SWS_DM_01531]</a>) are expressly defined as \"not thread-safe\". Modifications must therefore not take place unprotected in parallel with other operations.</li>
</ul>

<h4>Usage Path</h4>
<p>Typical usage is divided into a registration phase and a query or notification phase:</p>
<ol>
<li><strong>Taking over the instance:</strong> The application takes over the provided instance into its local processing context via a move operation (<a class="spec-record-ref" data-req="SWS_DM_01532" href="../spec/record.html?id=SWS_DM_01532">[SWS_DM_01532]</a>).</li>
<li><strong>Registering a notifier:</strong> If asynchronous notification is desired, the application passes a callable callback object of type <code>ReleaseHandlerSetNotifier</code> (<code>std::function&lt;void(void)&gt;</code>) using <code>SetNotifier(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>) (<a class="spec-record-ref" data-req="SWS_DM_02079" href="../spec/record.html?id=SWS_DM_02079">[SWS_DM_02079]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=505">AUTOSAR_AP_SWS_Diagnostics §8.23.1.1.1 “Type Alias: ReleaseHandlerSetNotifier”</a>). Calling <code>SetNotifier(...)</code> again overwrites the previously registered notifier (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>).</li>
<li><strong>State monitoring:</strong> During processing, two ways are available to check the release:
<ul>
<li><em>Synchronous query (polling):</em> Calling <code>MayRelease()</code> (<a class="spec-record-ref" data-req="SWS_DM_01536" href="../spec/record.html?id=SWS_DM_01536">[SWS_DM_01536]</a>) returns <code>true</code> as soon as the shared resource is no longer in use, otherwise <code>false</code>.</li>
<li><em>Asynchronous callback:</em> As soon as the resource is ready for release or a cancellation is signaled, the framework triggers the notifier registered via <code>SetNotifier(...)</code> (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>).</li>
</ul>
</li>
<li><strong>Resource cleanup:</strong> After receiving the release confirmation, the application terminates processing and releases the shared resource.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When using <code>ReleaseHandler</code>, defined preconditions and exception guarantees must be complied with:</p>
<ul>
<li><strong>Exception safety:</strong> All methods of the class (<code>MayRelease</code>, <code>SetNotifier</code>, move constructor, move assignment, destructor) are exception-safe (\"exception safe\") and declared with <code>noexcept</code> (<a class="spec-record-ref" data-req="SWS_DM_01536" href="../spec/record.html?id=SWS_DM_01536">[SWS_DM_01536]</a>, <a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>, <a class="spec-record-ref" data-req="SWS_DM_01532" href="../spec/record.html?id=SWS_DM_01532">[SWS_DM_01532]</a>, <a class="spec-record-ref" data-req="SWS_DM_01533" href="../spec/record.html?id=SWS_DM_01533">[SWS_DM_01533]</a>, <a class="spec-record-ref" data-req="SWS_DM_01531" href="../spec/record.html?id=SWS_DM_01531">[SWS_DM_01531]</a>). No error codes are transported via return values, and no C++ exceptions are thrown.</li>
<li><strong>Preconditions for notifiers:</strong> Two strict preconditions apply to the <code>SetNotifier(...)</code> method: The passed notifier must contain a callable object and must not throw any exceptions itself (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>). Passing an empty function object violates this precondition.</li>
<li><strong>Concurrency conflicts:</strong> Because <code>SetNotifier(...)</code> and the assignment operator are not thread-safe (<a class="spec-record-ref" data-req="SWS_DM_01537" href="../spec/record.html?id=SWS_DM_01537">[SWS_DM_01537]</a>, <a class="spec-record-ref" data-req="SWS_DM_01533" href="../spec/record.html?id=SWS_DM_01533">[SWS_DM_01533]</a>), a concurrent call from multiple threads without external synchronization leads to undefined behavior.</li>
</ul>
