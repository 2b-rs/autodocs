<h4>Role and system context of the service interface</h4>
<p>The service interface <code>StateMachineService</code> forms the authoritative control interface of the Functional Cluster State Management (SM) on the AUTOSAR Adaptive Platform (<a class="spec-record-ref" data-req="SWS_SM_91021" href="../spec/record.html?id=SWS_SM_91021">[SWS_SM_91021]</a>, <a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>). The cluster State Management acts as a provider and provides a dedicated ara::com-based service for each configured instance of a state machine (<code>StateMachine</code>) (<a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>). A control application, the <code>SMControlApplication</code>, acts as the consumer, which interacts with the respective state machine via a corresponding proxy to actively request state transitions (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 “Interfaces for a SMControlApplication”</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=141">AUTOSAR_AP_SWS_StateManagement §9.2.2 “StateMachine service”</a>).</p>
<p>Architecturally, State Management strictly distinguishes between this active control interaction and passive notifications: While <code>StateMachineService</code> exclusively serves the <code>SMControlApplication</code> for influencing states (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”</a>), the separately configurable service interface <code>StateMachineNotification</code> informs regular Adaptive Applications about state changes that have occurred (<a class="spec-record-ref" data-req="SWS_SM_00665" href="../spec/record.html?id=SWS_SM_00665">[SWS_SM_00665]</a>).</p>

<h4>Methods, events, and fields</h4>
<p>The service interface <code>StateMachineService</code> defines neither fields nor events, but concentrates entirely on a synchronous method interaction with feedback (<a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>). The method <code>RequestTransition</code> is specified as the central operation, which must be called by the <code>SMControlApplication</code> to initiate a state change in the referenced <code>StateMachine</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>
<p>The method is not modeled as fire-and-forget (<code>Fire &amp; Forget false</code>) and processes a single input parameter (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>):</p>
<ul>
<li><code>TransitionRequest</code> (Direction: <code>IN</code>, Type: <code>TransitionRequestType</code>): Contains the concrete request value stored as a trigger in the <code>TransitionRequestTable</code> configured for the state machine (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">AUTOSAR_AP_SWS_StateManagement §7.8 “TransitionRequestTable”</a>).</li>
</ul>
<p>Interpretation: Since no output parameter (OUT) is declared, a successful method call in ara::com is expected to provide an empty result (<code>void</code>) via a Future object, confirming the error-free completion of the transition to the <code>SMControlApplication</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<h4>Lifecycle, offering, and execution conditions</h4>
<p>The offering (Offer) of the <code>StateMachineService</code> is directly bound to the internal lifecycle of the respective <code>StateMachine</code>: Each configured service instance must be offered via ara::com as soon as the action item <code>ActionListItem</code> with the command <code>StartStateMachine</code> has been executed successfully (<a class="spec-record-ref" data-req="SWS_SM_00618" href="../spec/record.html?id=SWS_SM_00618">[SWS_SM_00618]</a>). This allows the <code>SMControlApplication</code> to request a transition immediately after the successful creation of the state machine, even if the state machine is concurrently still processing its initial <code>ActionList</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=45">AUTOSAR_AP_SWS_StateManagement §7.8 “StateMachine service interfaces - Offer”</a>).</p>
<p>The offering of the service is stopped accordingly (StopOffer) as soon as the <code>StateMachine</code> is terminated and the service may no longer be available (<a class="spec-record-ref" data-req="SWS_SM_00619" href="../spec/record.html?id=SWS_SM_00619">[SWS_SM_00619]</a>). During regular runtime, the execution of transitions also depends on higher-level platform states: If, for example, an update session takes place via Update and Configuration Management, transition requests are blocked (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<h4>Error handling and Application Errors</h4>
<p>If a transition request cannot be performed, the <code>RequestTransition</code> method returns a dedicated Application Error (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>). The interface specifies six distinct error codes for this purpose (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>):</p>
<table>
<thead>
<tr>
<th>Application Error</th>
<th>Meaning and cause</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>kInvalidValue</code></td>
<td>The passed value <code>TransitionRequest</code> is not assigned to any transition in the <code>TransitionRequestTable</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kTransitionNotAllowed</code></td>
<td>The requested state transition is inadmissible starting from the current state of the <code>StateMachine</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kRecoveryTransitionOngoing</code></td>
<td>The request is not executed because a recovery transition (Recovery) is currently active (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kTransitionFailed</code></td>
<td>An error occurred during the transition to the requested target state (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kOperationCanceled</code></td>
<td>The request was preempted by a newer subsequent request and aborted as a result (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
<tr>
<td><code>kUpdateInProgress</code></td>
<td>The requested operation is not permitted because an update session is currently being executed (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</td>
</tr>
</tbody>
</table>
<p>The calling <code>SMControlApplication</code> must handle these error codes separately, for example to wait for the result of the subsequent request in the case of <code>kOperationCanceled</code> or to repeat the call at a later point in time in the case of <code>kRecoveryTransitionOngoing</code> or <code>kUpdateInProgress</code> (<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>
