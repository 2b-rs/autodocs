<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht Steuerungsanwendungen die Anforderung von Zustandswechseln für konfigurierte Zustandsmaschinen.</p>
<div class="ai-level" data-ai-level="2">
<p>Das Service-Interface <code>StateMachineService</code> wird von State Management für jede konfigurierte Zustandsmaschine bereitgestellt, damit eine <code>SMControlApplication</code> über die Methode <code>RequestTransition</code> gezielt Zustandswechsel anfordern kann <a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>. Der Dienst wird unmittelbar nach erfolgreicher Abarbeitung des Startschritts der Zustandsmaschine angeboten und quittiert Anforderungen ohne Fire-and-Forget-Semantik. Anforderungen werden jedoch mit spezifischen Fehlern abgewiesen, falls der übergebene Wert ungültig ist, der Übergang aus dem aktuellen Zustand unzulässig ist oder zeitgleich eine Update- bzw. Recovery-Sitzung aktiv ist <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Rolle und Systemkontext der Service-Schnittstelle</h4>
<p>Das Service-Interface <code>StateMachineService</code> wird vom funktionalen Cluster <em>State Management</em> (SM) über einen standardisierten Service-Port bereitgestellt <a class="spec-record-ref" data-req="SWS_SM_91021" href="../spec/record.html?id=SWS_SM_91021">[SWS_SM_91021]</a>. Gemäß der formalen Schnittstellendefinition <a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a> instanziiert und bietet State Management diesen <code>ara::com</code>-basierten Dienst für jede einzelne konfigurierte Instanz einer <code>StateMachine</code> an <a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>.</p>
<p>Als primärer Consumer dieser Schnittstelle fungiert eine <code>SMControlApplication</code>, welche über den Dienst unmittelbar mit der Zustandsmaschine interagiert, um Zustandswechsel anzufordern <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=141">SWS StateManagement §9.2.2 „StateMachine service“</a>. Während Benachrichtigungen über eingetretene Zustände an reguläre adaptive Anwendungen primär über das separate Service-Interface <code>StateMachineNotification</code> erfolgen <a class="spec-record-ref" data-req="SWS_SM_00665" href="../spec/record.html?id=SWS_SM_00665">[SWS_SM_00665]</a>, bildet <code>StateMachineService</code> die aktive Kontrollschnittstelle zur Initiierung von Transitionen.</p>

<h4>Methoden und Aufrufsemantik</h4>
<p>Die Schnittstelle definiert die Methode <code>RequestTransition</code>, die von der <code>SMControlApplication</code> aufgerufen werden muss, um eine Zustandsänderung in der referenzierten <code>StateMachine</code> herbeizuführen <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>. Die Methode erwartet den Eingabeparameter <code>TransitionRequest</code> vom Typ <code>TransitionRequestType</code>, der den geforderten Übergangswert innerhalb der zugrundeliegenden <code>TransitionRequestTable</code> repräsentiert <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">SWS StateManagement §7.x „TransitionRequestTable“</a>.</p>
<p>Für <code>RequestTransition</code> ist die Eigenschaft <em>Fire &amp; Forget</em> auf <code>false</code> gesetzt <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>. Die aufrufende Anwendung erhält somit eine verbindliche Quittierung der Anfrage. Interpretation: Innerhalb des <code>ara::com</code>-Proxy-Skeleton-Musters dürfte die Rückmeldung typischerweise über ein <code>ara::core::Future</code> bzw. ein entsprechendes Ergebnisobjekt bereitgestellt werden, das im Erfolgsfall auflöst oder im Fehlerfall einen spezifischen Fehlerstatus übermittelt.</p>

<h4>Lebenszyklus und Zustandsabhängigkeiten</h4>
<p>Jeder für eine zu startende <code>StateMachine</code> konfigurierte <code>ara::com</code>-Dienst – einschließlich <code>StateMachineService</code> – muss verfügbar sein und angeboten werden (Offer), sobald das <code>ActionListItem</code> „StartStateMachine“ erfolgreich abgearbeitet wurde <a class="spec-record-ref" data-req="SWS_SM_00618" href="../spec/record.html?id=SWS_SM_00618">[SWS_SM_00618]</a>. Dies gestattet es der <code>SMControlApplication</code>, sofort nach erfolgreicher Erzeugung der Zustandsmaschine eine Transition anzufordern, selbst wenn die Zustandsmaschine zu diesem Zeitpunkt noch die initiale <code>ActionList</code> verarbeitet <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=45">SWS StateManagement §7.x „StateMachine service interfaces - Offer“</a>.</p>
<p>Das Anbieten des Dienstes wird beendet (StopOffer), sobald die Verarbeitung zum Stoppen der jeweiligen Zustandsmaschine erfolgt <a class="spec-record-ref" data-req="SWS_SM_00619" href="../spec/record.html?id=SWS_SM_00619">[SWS_SM_00619]</a>. Aufrufe unterliegen zudem funktionalen Vorbedingungen: Läuft im System aktuell eine Update-Sitzung, ist die Einleitung von Zustandswechseln prinzipiell unzulässig <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</p>

<h4>Fehlerbehandlung und Application Errors</h4>
<p>Bei der Ausführung von <code>RequestTransition</code> können spezifische Application Errors auftreten, die von State Management an den Aufrufer zurückgemeldet werden <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>:</p>
<ul>
<li><code>kInvalidValue</code>: Der übergebene Wert ist in der <code>TransitionRequestTable</code> keiner Transition zugeordnet <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
<li><code>kTransitionNotAllowed</code>: Der angeforderte Zustandsübergang ist ausgehend vom aktuellen Zustand der <code>StateMachine</code> nicht erlaubt <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
<li><code>kRecoveryTransitionOngoing</code>: Die Anforderung wird verworfen, da gegenwärtig eine Fehlerbehebung (Recovery) ausgeführt wird <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
<li><code>kTransitionFailed</code>: Während der Ausführung des Übergangs in den Zielzustand ist ein Fehler aufgetreten <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
<li><code>kOperationCanceled</code>: Die Anfrage wurde abgebrochen, da sie durch eine neuere Anforderung ersetzt wurde <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
<li><code>kUpdateInProgress</code>: Die Operation ist verboten, da aktuell eine Update-Sitzung aktiv ist <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>.</li>
</ul>
