<h4>Context</h4>
<p>
The class <code>ara::rds::RdsException</code> represents the central exception type for the Raw Data Stream (RDS) functional cluster in the AUTOSAR Adaptive Platform. It acts as a specialized information carrier when error conditions within raw data streaming are propagated to higher-level call layers not via local return values, but via the C++ exception mechanism. According to its inheritance hierarchy, <code>RdsException</code> derives publicly from <code>ara::core::Exception</code>. As a result, it seamlessly integrates into the unified error handling model of the Adaptive Platform, which primarily builds upon value types such as <code>ara::core::ErrorCode</code> and <code>ara::core::Result</code>, but mandates compatible exception classes for exception-based control flows.
</p>
<p>
The essential interaction partners of the class comprise three domains:
</p>
<ul>
<li><strong>RDS functional cluster:</strong> In the event of severe protocol or transmission errors in the raw data stream, creates corresponding error states and encapsulates them in an associated <code>ara::core::ErrorCode</code>.</li>
<li><strong>Base architecture (<code>ara::core</code>):</strong> Provides the common base class with <code>ara::core::Exception</code> and the underlying value type with <code>ara::core::ErrorCode</code>. Interpretation: Via the base functionality of <code>ara::core::Exception</code>, <code>RdsException</code> is likely to provide methods for inspecting the error code.</li>
<li><strong>Application software:</strong> Catches the exception in defined <code>catch</code> blocks to initiate controlled recovery or degradation strategies for the affected data stream.</li>
</ul>

<h4>Lifecycle</h4>
<p>
The lifecycle of an instance of <code>ara::rds::RdsException</code> begins deterministically with its initialization via the explicit constructor <a class="spec-record-ref" data-req="SWS_RDS_11292" href="../spec/record.html?id=SWS_RDS_11292">[SWS_RDS_11292]</a>. This takes a <code>ara::core::ErrorCode</code> as its sole parameter and is declared as <code>noexcept</code>. The <code>noexcept</code> guarantee ensures that construction is guaranteed not to be interrupted by further exceptions, even under adverse runtime conditions—such as resource constraints.
</p>
<p>
After construction, the exception object remains in an immutable state. It owns the passed error code and acts as a pure value object. Propagation occurs via the C++ runtime stack within the scope of a <code>throw</code> statement. Ownership of the object lies with the C++ runtime environment during stack unwinding until it is bound at the appropriate catch site.
</p>
<p>
Regarding concurrency and multi-threaded operation: Since exception instances are typically instantiated thread-locally and caught as a const reference (<code>const ara::rds::RdsException&amp;</code>), no shared state exists between threads. Presumably, no explicit mutex synchronization at the exception instance level is therefore required for working with <code>RdsException</code>. Destruction takes place automatically by the C++ runtime as soon as the catching block is exited.
</p>

<h4>Usage Path</h4>
<p>
The typical usage path is divided into the sequence of error detection, exception creation, propagation, and handling:
</p>
<ol>
<li><strong>Error identification in the data stream:</strong> Within an RDS processing routine, a read, write, or configuration operation fails. The error is initially formulated as a <code>ara::core::ErrorCode</code>, the declaration of which is anchored in header <code>ara/rds/rds_error_domain.h</code> <a class="spec-record-ref" data-req="SWS_RDS_11292" href="../spec/record.html?id=SWS_RDS_11292">[SWS_RDS_11292]</a>.</li>
<li><strong>Instantiation:</strong> If the calling location is to be notified via exception, the exception is created explicitly with the occurred error code: <code>RdsException(errorCode)</code> <a class="spec-record-ref" data-req="SWS_RDS_11292" href="../spec/record.html?id=SWS_RDS_11292">[SWS_RDS_11292]</a>. Presumably, this also happens automatically when applications call the method <code>Value()</code> on an erroneous <code>ara::core::Result</code>.</li>
<li><strong>Throwing the exception:</strong> The instance is introduced into the control flow by means of <code>throw</code>, which forces exiting the current context.</li>
<li><strong>Catching and evaluating:</strong> The calling layer catches the object specifically as <code>ara::rds::RdsException</code> or polymorphically as <code>ara::core::Exception</code> and reads out the underlying error code to initiate targeted diagnostic and recovery measures.</li>
</ol>

<h4>Error Scenarios</h4>
<p>
As a dedicated error class, <code>ara::rds::RdsException</code> itself has no complex error modes. Thanks to being specified as <code>noexcept</code>, its constructor cannot fail <a class="spec-record-ref" data-req="SWS_RDS_11292" href="../spec/record.html?id=SWS_RDS_11292">[SWS_RDS_11292]</a>.
</p>
<p>
A critical scenario in interaction with the Adaptive Platform arises when the interface between error-code-based and exception-based handling is insufficiently coordinated. If a <code>RdsException</code> is thrown in a thread for which no comprehensive <code>catch</code> handler is registered, this leads to a call to <code>std::terminate</code> and thus to uncontrolled termination of the process. Applications using Raw Data Stream interfaces must therefore ensure that either non-throwing APIs are primarily chosen (e.g., inspecting <code>ara::core::Result</code> without calling throwing helper methods) or calls are completely protected by corresponding exception handling blocks.
</p>
