<h4>Context</h4>
<p>The class <code>ara::diag::DoIPActivationLine</code> (<a class="spec-record-ref" data-req="SWS_DM_00830" href="../spec/record.html?id=SWS_DM_00830">[SWS_DM_00830]</a>) defines the programming interface for the <code>DiagnosticDoIPActivationLineInterface</code> within the <code>diag</code> module of the AUTOSAR Adaptive Platform. In vehicle networks, a dedicated activation line (DoIP Activation Line) serves to selectively switch DoIP communication on a physical network interface on or off in order to save quiescent current or control diagnostic connections close to the hardware.</p>
<p>Via <code>ara::diag::DoIPActivationLine</code>, an Adaptive Application (AA) binds the detection and control of this activation line to the Diagnostic Management (DM). Through this, an application can indirectly request the sending of DoIP Vehicle Announcement messages (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics p. 107</a>), since the DM reacts to status changes of activation-line-controlled network interfaces (<a class="spec-record-ref" data-req="SWS_DM_00816" href="../spec/record.html?id=SWS_DM_00816">[SWS_DM_00816]</a>).</p>

<h4>Lifecycle</h4>
<p>The instantiation of <code>ara::diag::DoIPActivationLine</code> is performed via the parameterized constructor by passing an <code>ara::core::InstanceSpecifier</code> (<a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>). This identifier links the object to a PortPrototype of type <code>DiagnosticDoIPActivationLineInterface</code> declared in the AUTOSAR model.</p>
<p>Regarding ownership and lifecycle semantics, the class is designed as a strict single instance per interface configuration. Both the copy constructor (<a class="spec-record-ref" data-req="SWS_DM_01633" href="../spec/record.html?id=SWS_DM_01633">[SWS_DM_01633]</a>) and the copy assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01631" href="../spec/record.html?id=SWS_DM_01631">[SWS_DM_01631]</a>) are deleted (<code>=delete</code>). Likewise, the move constructor (<a class="spec-record-ref" data-req="SWS_DM_01634" href="../spec/record.html?id=SWS_DM_01634">[SWS_DM_01634]</a>) and the move assignment operator (<a class="spec-record-ref" data-req="SWS_DM_01632" href="../spec/record.html?id=SWS_DM_01632">[SWS_DM_01632]</a>) are explicitly deleted. Thus, an instance can neither be copied nor moved.</p>
<p>After object creation, the interface is in the quiescent state. Via the method <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>), the application reports the availability of the interface to the DM so that it can listen for line changes. With <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a>), the provision of the line status to the DM is deactivated again. Cleanup is performed via the virtual destructor <code>~DoIPActivationLine()</code> (<a class="spec-record-ref" data-req="SWS_DM_00832" href="../spec/record.html?id=SWS_DM_00832">[SWS_DM_00832]</a>).</p>
<p>Regarding concurrency, the constructor (<a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>) as well as the query methods <code>GetActivationLineState()</code> (<a class="spec-record-ref" data-req="SWS_DM_00835" href="../spec/record.html?id=SWS_DM_00835">[SWS_DM_00835]</a>) and <code>GetNetworkInterfaceId()</code> (<a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a>) are specified as thread-safe. In contrast, <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>), <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a>), and <code>UpdateActivationLineState()</code> (<a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a>) are declared as not thread-safe and require application-side synchronization.</p>

<h4>Usage Path</h4>
<p>Since <code>GetActivationLineState()</code> (<a class="spec-record-ref" data-req="SWS_DM_00835" href="../spec/record.html?id=SWS_DM_00835">[SWS_DM_00835]</a>) and <code>GetNetworkInterfaceId()</code> (<a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a>) are pure virtual methods, the Adaptive Application derives a concrete implementation class. The typical call sequence comprises the following steps:</p>
<ol>
<li><strong>Instantiation:</strong> The derived object is created with the <code>ara::core::InstanceSpecifier</code> of the target port (<a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>).</li>
<li><strong>Service offering:</strong> The application calls <code>Offer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>). Interpretation: Following successful registration, the DM presumably initially queries the interface ID via <code>GetNetworkInterfaceId()</code> (<a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a>) and the current state via <code>GetActivationLineState()</code> (<a class="spec-record-ref" data-req="SWS_DM_00835" href="../spec/record.html?id=SWS_DM_00835">[SWS_DM_00835]</a>) in order to initialize the internal DoIP network state.</li>
<li><strong>State update:</strong> If the physical level of the activation line changes, the application reports this via <code>UpdateActivationLineState(bool)</code> (<a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a>). The DM receives this status change (<a class="spec-record-ref" data-req="SWS_DM_00816" href="../spec/record.html?id=SWS_DM_00816">[SWS_DM_00816]</a>) and then controls the activation of the DoIP connection.</li>
<li><strong>Service termination:</strong> Prior to shutdown, the application calls <code>StopOffer()</code> (<a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a>), as a result of which the DM no longer processes any further line changes, and destroys the instance (<a class="spec-record-ref" data-req="SWS_DM_00832" href="../spec/record.html?id=SWS_DM_00832">[SWS_DM_00832]</a>).</li>
</ol>

</li>

</ul>
