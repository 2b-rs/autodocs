<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient der Übermittlung und Verwaltung des Zustands einer DoIP-Aktivierungsleitung an den Diagnostic Manager.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::DoIPActivationLine</code> ermöglicht es einer Anwendung, den Zustand einer DoIP-Aktivierungsleitung bereitzustellen und Änderungen an den Diagnostic Manager zu übermitteln <a class="spec-record-ref" data-req="SWS_DM_00830" href="../spec/record.html?id=SWS_DM_00830">[SWS_DM_00830]</a>. Nach der portbasierten Instanziierung wird der Dienst mittels <code>Offer()</code> aktiviert, woraufhin der DM Leitungsstatus und Netzwerk-ID abfragt und Statuswechsel über <code>UpdateActivationLineState()</code> entgegennimmt <a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a>. Als zentrale Randbedingung muss die zugehörige Netzwerkschnittstelle im Modell als aktivierungsleitungsabhängig konfiguriert sein <a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a>.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::DoIPActivationLine</code> repräsentiert die Schnittstelle <code>DiagnosticDoIPActivationLineInterface</code> gemäß <a class="spec-record-ref" data-req="SWS_DM_00830" href="../spec/record.html?id=SWS_DM_00830">[SWS_DM_00830]</a>. Sie ermöglicht einer Adaptive Application (AA), den physikalischen oder logischen Zustand einer DoIP-Aktivierungsleitung an den Diagnostic Manager (DM) zu melden und bereitzustellen. Über diese Aktivierungsleitung steuert eine Anwendung indirekt das Aussenden von DoIP-Fahrzeug-Ankündigungsnachrichten (Vehicle Announcement Messages), wie in <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics, S. 107</a> spezifiziert, ohne den Versand explizit selbst zu triggern.</p>
<p>An der Interaktion sind im Wesentlichen drei Komponenten beteiligt: die implementierende Adaptive Application, die Instanz von <code>ara::diag::DoIPActivationLine</code> als Service-Schnittstelle sowie der Diagnostic Manager des Basissystems. Erkennt der DM über diese Schnittstelle eine Zustandsänderung der Aktivierungsleitung, benachrichtigt er abhängige Netzwerk-Schnittstellen und leitet standardisierte DoIP-Abläufe ein <a class="spec-record-ref" data-req="SWS_DM_00816" href="../spec/record.html?id=SWS_DM_00816">[SWS_DM_00816]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::diag::DoIPActivationLine</code> wird über einen <code>ara::core::InstanceSpecifier</code> erzeugt, der auf einen <code>PortPrototype</code> verweist <a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>. Die Klasse bildet eine eindeutige Instanz ab: Kopier- und Move-Konstruktoren sowie Kopier- und Move-Zuweisungsoperatoren sind gelöscht (<code>=delete</code>), wodurch ein Verschieben oder Duplizieren ausgeschlossen ist (<a class="spec-record-ref" data-req="SWS_DM_01631" href="../spec/record.html?id=SWS_DM_01631">[SWS_DM_01631]</a>, <a class="spec-record-ref" data-req="SWS_DM_01632" href="../spec/record.html?id=SWS_DM_01632">[SWS_DM_01632]</a>, <a class="spec-record-ref" data-req="SWS_DM_01633" href="../spec/record.html?id=SWS_DM_01633">[SWS_DM_01633]</a>, <a class="spec-record-ref" data-req="SWS_DM_01634" href="../spec/record.html?id=SWS_DM_01634">[SWS_DM_01634]</a>).</p>
<p>Nach der Instanziierung befindet sich das Objekt im Zustand „nicht angeboten“. Durch den Aufruf von <code>Offer()</code> wird die Bereitstellung aktiviert, sodass der DM auf Zustandsänderungen der Aktivierungsleitung lauschen kann <a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>. Mittels <code>StopOffer()</code> wird diese Bereitstellung wieder deaktiviert <a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a>. Der virtuelle Destruktor ist als Standarddestruktor deklariert und gibt die Ressourcen frei <a class="spec-record-ref" data-req="SWS_DM_00832" href="../spec/record.html?id=SWS_DM_00832">[SWS_DM_00832]</a>. Bezüglich der Nebenläufigkeit sind der Konstruktor <a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a> sowie die reinen Leseabfragen <code>GetActivationLineState()</code> <a class="spec-record-ref" data-req="SWS_DM_00835" href="../spec/record.html?id=SWS_DM_00835">[SWS_DM_00835]</a> und <code>GetNetworkInterfaceId()</code> <a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a> threadsicher ausgeführt, während <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>, <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a> und <code>UpdateActivationLineState()</code> <a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a> nicht threadsicher sind.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Ableitung und Registrierung einer anwendungsspezifischen Klasse sowie die kontinuierliche Zustandsübermittlung:</p>
<ol>
<li><strong>Instanziierung:</strong> Die Adaptive Application instanziiert die abgeleitete Klasse unter Angabe des passenden <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>.</li>
<li><strong>Dienst anbieten:</strong> Die Anwendung ruft <code>Offer()</code> auf, um die Schnittstelle für den DM freizugeben <a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>.</li>
<li><strong>Netzwerk- und Initialabfrage:</strong> Der DM ermittelt über die pure-virtual-Methode <code>GetNetworkInterfaceId()</code> die zugehörige Interface-ID <a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a> und fragt mit <code>GetActivationLineState()</code> den aktuellen Leitungszustand ab <a class="spec-record-ref" data-req="SWS_DM_00835" href="../spec/record.html?id=SWS_DM_00835">[SWS_DM_00835]</a>. Beide Methoden liefern ein <code>ara::core::Future</code> zurück.</li>
<li><strong>Zustandsaktualisierung:</strong> Ändert sich der physikalische Zustand der Leitung (z. B. Pegelwechsel an einer Hardware-Leitung), informiert die Anwendung den DM synchron über <code>UpdateActivationLineState()</code> <a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a>. Dies veranlasst den DM zu Folgeaktionen wie Zustandsmeldungen an Netzwerk-Interfaces <a class="spec-record-ref" data-req="SWS_DM_00816" href="../spec/record.html?id=SWS_DM_00816">[SWS_DM_00816]</a>.</li>
<li><strong>Beendigung:</strong> Vor dem Herunterfahren oder bei Deaktivierung ruft die Anwendung <code>StopOffer()</code> auf <a class="spec-record-ref" data-req="SWS_DM_00837" href="../spec/record.html?id=SWS_DM_00837">[SWS_DM_00837]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Beim Einsatz von <code>ara::diag::DoIPActivationLine</code> können funktionale und konfigurationsseitige Fehler auftreten:</p>
<ul>
<li><strong>Modell- und Portverletzungen bei Erzeugung:</strong> Der Konstruktor prüft die Gültigkeit des <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_00831" href="../spec/record.html?id=SWS_DM_00831">[SWS_DM_00831]</a>. Schlägt die Auflösung fehl, werden standardisierte Verletzungsmeldungen ausgelöst: <code>InstanceSpecifierMappingIntegrityViolation</code> (ungültiges Modellelement), <code>PortInterfaceMappingViolation</code> (Port nicht durch <code>DiagnosticDoIPActivationLineInterface</code> typisiert), <code>ProcessMappingViolation</code> (fehlender Prozessbezug) oder <code>InstanceSpecifierAlreadyInUseViolation</code> (Specifier innerhalb des Prozesses bereits vergeben).</li>
<li><strong>Mehrfachanbieten:</strong> Wird <code>Offer()</code> aufgerufen, während der Dienst bereits angeboten wird, schlägt die Operation mit dem Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> fehl <a class="spec-record-ref" data-req="SWS_DM_00836" href="../spec/record.html?id=SWS_DM_00836">[SWS_DM_00836]</a>.</li>
<li><strong>Konfigurationsinkonsistenz der Netzwerkschnittstelle:</strong> Meldet die Anwendung über <code>GetNetworkInterfaceId()</code> eine Interface-ID, deren zugehörige <code>DoIpNetworkConfiguration</code> die Eigenschaft <code>isActivationLineDependent = 'FALSE'</code> besitzt, gilt dies laut Spezifikation explizit als schwerwiegender Konfigurationsfehler <a class="spec-record-ref" data-req="SWS_DM_00833" href="../spec/record.html?id=SWS_DM_00833">[SWS_DM_00833]</a>.</li>
<li><strong>Ausnahmesicherheit:</strong> Während der Konstruktor, die Getter, <code>Offer()</code>, <code>StopOffer()</code> und der Destruktor als ausnahmesicher (exception safe) spezifiziert sind, ist <code>UpdateActivationLineState()</code> explizit als nicht ausnahmesicher (not exception safe) ausgewiesen <a class="spec-record-ref" data-req="SWS_DM_00834" href="../spec/record.html?id=SWS_DM_00834">[SWS_DM_00834]</a>. Fehler innerhalb dieses Aufrufs müssen von der aufrufenden Anwendung daher sorgfältig behandelt werden.</li>
</ul>
