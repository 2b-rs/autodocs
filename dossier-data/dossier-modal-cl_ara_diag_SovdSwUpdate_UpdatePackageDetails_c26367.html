<h4>Context</h4>
<p>The data structure <code>ara::diag::SovdSwUpdate::UpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=751">AUTOSAR_AP_SWS_Diagnostics §8.58.4 “Struct: UpdatePackageDetails”</a>) serves within the AUTOSAR Adaptive Platform in the <code>diag</code> module as a structured information carrier for the metadata and execution parameters of a software update package. It is declared in the header <code>#include "ara/diag/sovd_sw_update.h"</code> and represents an essential interface entity for software-related diagnostic and update processes provided via the ASAM SOVD (Service-Oriented Vehicle Diagnostics) standard (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>).</p>
<p>The architectural embedding follows the functional division of responsibilities of the SOVD software update (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API”</a>): Since the actual business logic for software updates is not executed within the Diagnostics Functional Cluster, the domain implementation lies primarily with the respective application. The <code>ara::diag::SovdSwUpdate::SovdSwUpdate</code> instance of the diagnostic server focuses on handling the underlying SOVD protocol in accordance with ASAM SOVD (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>). In this context, <code>UpdatePackageDetails</code> acts as a standardized transfer object with which the application provides detailed package data to the diagnostic server via the API function <code>ara::diag::SovdSwUpdate::GetUpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=742">AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”</a>) so that it can serve external SOVD clients.</p>

<h4>Lifecycle</h4>
<p>As a passive data structure (<code>struct</code>) <a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>, <code>UpdatePackageDetails</code> possesses no state machine of its own and controls no autonomous life cycles. It is instantiated by the application at the moment of a concrete query, whereupon the public member variables are populated with the static and dynamic package attributes:</p>
<ul>
<li><strong>Identification and naming:</strong> The field <code>id</code> (<a class="spec-record-ref" data-req="SWS_DM_01878" href="../spec/record.html?id=SWS_DM_01878">[SWS_DM_01878]</a>) stores the unique ID of the package. The designation <code>name</code> (<a class="spec-record-ref" data-req="SWS_DM_01879" href="../spec/record.html?id=SWS_DM_01879">[SWS_DM_01879]</a>) specifies the package name, while <code>translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01881" href="../spec/record.html?id=SWS_DM_01881">[SWS_DM_01881]</a>) provides a key for localized representations.</li>
<li><strong>Size and execution details:</strong> The size of the package in bytes is defined via <code>size</code> (<a class="spec-record-ref" data-req="SWS_DM_01893" href="../spec/record.html?id=SWS_DM_01893">[SWS_DM_01893]</a>) as <code>std::uint64_t</code>. Additional control variables are the estimated execution duration <code>duration</code> in seconds (<a class="spec-record-ref" data-req="SWS_DM_01891" href="../spec/record.html?id=SWS_DM_01891">[SWS_DM_01891]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=752">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 “duration”</a>) as <code>ara::core::Optional&lt;std::uint64_t&gt;</code> as well as the designation <code>automated</code> (<a class="spec-record-ref" data-req="SWS_DM_01882" href="../spec/record.html?id=SWS_DM_01882">[SWS_DM_01882]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=752">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 “automated”</a>) as <code>ara::core::Optional&lt;bool&gt;</code>.</li>
<li><strong>Preconditions and user activities:</strong> Conditions for execution are conveyed in <code>preconditions</code> (<a class="spec-record-ref" data-req="SWS_DM_01888" href="../spec/record.html?id=SWS_DM_01888">[SWS_DM_01888]</a>) along with <code>preconditions_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01889" href="../spec/record.html?id=SWS_DM_01889">[SWS_DM_01889]</a>) as well as <code>execution_conditions</code> (<a class="spec-record-ref" data-req="SWS_DM_01890" href="../spec/record.html?id=SWS_DM_01890">[SWS_DM_01890]</a>). Required operator actions are deposited by the application in <code>user_activity</code> (<a class="spec-record-ref" data-req="SWS_DM_01886" href="../spec/record.html?id=SWS_DM_01886">[SWS_DM_01886]</a>) and <code>user_activity_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01887" href="../spec/record.html?id=SWS_DM_01887">[SWS_DM_01887]</a>). Additional notes can be passed via <code>notes</code> (<a class="spec-record-ref" data-req="SWS_DM_01884" href="../spec/record.html?id=SWS_DM_01884">[SWS_DM_01884]</a>) and <code>notes_translation_id</code> (<a class="spec-record-ref" data-req="SWS_DM_01885" href="../spec/record.html?id=SWS_DM_01885">[SWS_DM_01885]</a>).</li>
<li><strong>Component relationships and origin:</strong> The components affected by the package are listed in the vector <code>affected_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01895" href="../spec/record.html?id=SWS_DM_01895">[SWS_DM_01895]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=751">AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 “affected_components”</a>), while <code>updated_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01894" href="../spec/record.html?id=SWS_DM_01894">[SWS_DM_01894]</a>) designates the explicitly updated components. The origin of the update package is communicated via <code>origin</code> (<a class="spec-record-ref" data-req="SWS_DM_01883" href="../spec/record.html?id=SWS_DM_01883">[SWS_DM_01883]</a>).</li>
</ul>
<p>Regarding ownership, the instance is created by the application and passed to the caller via return value. The instance is destroyed automatically after leaving the scope according to standard C++ semantics (RAII). The structure provides no internal thread synchronization; in the case of concurrent read or write accesses across thread boundaries, protecting the instance is the responsibility of the calling software component.</p>

<h4>Usage Path</h4>
<p>The regular use of <code>UpdatePackageDetails</code> takes place in the course of the standardized SOVD methods for querying software update details (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>). Often, the client first retrieves a list of all available updates (<a class="spec-record-ref" data-req="SWS_DM_01797" href="../spec/record.html?id=SWS_DM_01797">[SWS_DM_01797]</a>) before specifically requesting package details.</p>
<p>The call sequence is as follows:</p>
<ol>
<li><strong>Request by SOVD client:</strong> An external diagnostic client sends a request for the details of a specific software package to the Diagnostic Server Instance (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>).</li>
<li><strong>Forwarding to the application:</strong> The Diagnostic Server delegates the determination of details via <code>ara::diag::SovdSwUpdate::GetUpdatePackageDetails</code> to the registered application (<a class="spec-record-ref" data-req="SWS_DM_01917" href="../spec/record.html?id=SWS_DM_01917">[SWS_DM_01917]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=742">AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”</a>).</li>
<li><strong>Compilation of data:</strong> The application determines the metadata of the package, instantiates <code>UpdatePackageDetails</code> (<a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a>), and populates identification data such as <code>id</code> (<a class="spec-record-ref" data-req="SWS_DM_01878" href="../spec/record.html?id=SWS_DM_01878">[SWS_DM_01878]</a>) and <code>size</code> (<a class="spec-record-ref" data-req="SWS_DM_01893" href="../spec/record.html?id=SWS_DM_01893">[SWS_DM_01893]</a>) as well as dependencies such as <code>affected_components</code> (<a class="spec-record-ref" data-req="SWS_DM_01895" href="../spec/record.html?id=SWS_DM_01895">[SWS_DM_01895]</a>).</li>
<li><strong>Return:</strong> Interpretation: The application is likely to return the populated <code>UpdatePackageDetails</code> object directly to the Diagnostic Server as the function result of <code>GetUpdatePackageDetails</code>.</li>
<li><strong>Protocol response:</strong> Interpretation: The Diagnostic Server presumably handles the serialization of the C++ attributes into the standardized SOVD response format and delivers it to the requesting client (<a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a>).</li>
</ol>
