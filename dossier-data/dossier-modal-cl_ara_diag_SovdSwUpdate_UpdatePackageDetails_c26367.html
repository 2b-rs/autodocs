<h4>Kontext</h4>
<p>Die Struktur <code>ara::diag::SovdSwUpdate::UpdatePackageDetails</code> ist im Header <code>ara/diag/sovd_sw_update.h</code> definiert <a class="spec-record-ref" data-req="SWS_DM_01877" href="../spec/record.html?id=SWS_DM_01877">[SWS_DM_01877]</a> und dient als standardisierter Datencontainer für Detailinformationen zu Software-Update-Paketen im Rahmen von Service-Oriented Vehicle Diagnostics (SOVD). Gemäß <a class="spec-record-ref" data-req="SWS_DM_01796" href="../spec/record.html?id=SWS_DM_01796">[SWS_DM_01796]</a> implementiert die Instanz des Diagnostic Servers die SOVD-API-Methoden für Software-Updates entsprechend dem Standard ASAM SOVD. Da die funktionale Logik von Software-Updates nicht innerhalb des Functional Clusters Diagnostics verarbeitet wird, obliegt die Abwicklung primär der adaptiven Applikation, während sich <code>ara::diag::SovdSwUpdate</code> auf die Behandlung des zugrundeliegenden SOVD-Protokolls konzentriert <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=223">AUTOSAR_AP_SWS_Diagnostics §7.4 „Figure 7.4: SOVD Software Update API - concept“</a>.</p>

Die Struktur bündelt Metadaten, die zur Identifikation, Validierung, Planung und Anzeige des Update-Vorgangs erforderlich sind. Hierzu zählen elementare Identifikatoren wie die Paket-ID <code>id</code> <a class="spec-record-ref" data-req="SWS_DM_01878" href="../spec/record.html?id=SWS_DM_01878">[SWS_DM_01878]</a> und die Bezeichnung <code>name</code> <a class="spec-record-ref" data-req="SWS_DM_01879" href="../spec/record.html?id=SWS_DM_01879">[SWS_DM_01879]</a> nebst Übersetzungsreferenz <code>translation_id</code> <a class="spec-record-ref" data-req="SWS_DM_01881" href="../spec/record.html?id=SWS_DM_01881">[SWS_DM_01881]</a>.
