<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient der schlüsselbasierten Berechnung und Verifikation kryptografischer Message Authentication Codes.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle ermöglicht die schlüsselbasierte Berechnung und Verifikation von Message Authentication Codes für Nachrichten beliebiger Länge. Nach der Initialisierung mit einem symmetrischen Schlüssel über <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a> können MAC-Digests entweder in einem einzigen Schritt oder im Streaming-Verfahren über Start-, Aktualisierungs- und Abschlussaufrufe verarbeitet werden. Das resultierende Prüfergebnis lässt sich anschließend abrufen oder direkt mit einem Sollwert abgleichen. Alle Methoden sind als threadsicher spezifiziert und signalisieren fehlerhafte Abläufe oder unzureichende Pufferkapazitäten über standardisierte Rückgabewerte gemäß <a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Schnittstelle <code class="mono">MessageAuthnCodeCtx</code> definiert kryptografische Operationen zur Generierung und Verifikation schlüsselbasierter Nachrichtenauthentifizierungscodes (Message Authentication Codes, MAC). Sie erlaubt die Authentizitäts- und Integritätsprüfung beliebiger Datenmengen sowohl über inkrementelle Datenströme als auch über einzelne zusammenhängende Speicherblöcke. Die Verwaltung von Instanzen erfolgt über den bereitgestellten Smart-Pointer-Typ <code class="mono">Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22101" href="../spec/record.html?id=SWS_CRYPT_22101">[SWS_CRYPT_22101]</a>.</p>
<p>Als zentrale Interaktionspartner treten aufrufende Anwendungskomponenten sowie Schlüsselobjekte auf. Ein Kontext kann entweder direkt mit einem symmetrischen Schlüsselobjekt <code class="mono">SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a> oder über einen logischen Speicherplatz <code class="mono">KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50026" href="../spec/record.html?id=SWS_CRYPT_50026">[SWS_CRYPT_50026]</a> konfiguriert werden. Die Datenübergabe erfolgt über Pufferstrukturen wie <code class="mono">ReadOnlyMemRegion</code> für Eingangsdaten sowie <code class="mono">ReadWriteMemRegion</code> für berechnete MAC-Digests.</p>

<h4>Lebenszyklus</h4>
<p>Eine Kontextinstanz durchläuft eine definierte Zustandsabfolge von der Initialisierung bis zur Bereitstellung des MAC-Ergebnisses:</p>
<ul>
<li><strong>Uninitialized:</strong> Nach der Erzeugung besitzt der Kontext noch keinen Schlüssel und lehnt Berechnungsaufrufe ab.</li>
<li><strong>Configured:</strong> Durch Aufruf von <code class="mono">SetKey()</code> mit einem Schlüssel <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a> oder einem Schlüsselspeicher <a class="spec-record-ref" data-req="SWS_CRYPT_50026" href="../spec/record.html?id=SWS_CRYPT_50026">[SWS_CRYPT_50026]</a> wird der Kontext initialisiert. In diesem Zustand können Single-Call-Methoden ausgeführt oder eine Streaming-Sitzung gestartet werden.</li>
<li><strong>Processing:</strong> Der Aufruf von <code class="mono">Start()</code> ohne Initialisierungsvektor <a class="spec-record-ref" data-req="SWS_CRYPT_22111" href="../spec/record.html?id=SWS_CRYPT_22111">[SWS_CRYPT_22111]</a> oder mit IV <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a> eröffnet die Streaming-Verarbeitung. Mittels wiederholtem <code class="mono">Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a> werden Datenblöcke eingespeist. Ein Abbruch ist über <code class="mono">Cancel()</code> möglich <a class="spec-record-ref" data-req="SWS_CRYPT_50027" href="../spec/record.html?id=SWS_CRYPT_50027">[SWS_CRYPT_50027]</a>.</li>
<li><strong>Finished:</strong> Die Methode <code class="mono">Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a> schließt die Berechnung ab. Anschließend kann das Ergebnis abgefragt oder verglichen werden.</li>
</ul>
<p>Interpretation: Nach dem Abschluss oder Abbruch verbleibt der Kontext vermutlich im konfigurierten Zustand und kann für erneute Operationen wiederverwendet werden. Sämtliche Methoden der Schnittstelle sind als threadsicher und ausnahmesicher spezifiziert.</p>

<h4>Nutzungspfad</h4>
<p>Die Schnittstelle unterstützt zwei typische Nutzungspfade: inkrementelles Streaming und Single-Call-Verarbeitung.</p>
<p>Im Streaming-Pfad bindet der Anrufer zunächst den Schlüssel über <code class="mono">SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a>. Vor Beginn können Algorithmenparameter wie die empfohlene IV-Größe über <code class="mono">GetRecommendedIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50135" href="../spec/record.html?id=SWS_CRYPT_50135">[SWS_CRYPT_50135]</a> sowie die maximale Chunk-Größe über <code class="mono">GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50033" href="../spec/record.html?id=SWS_CRYPT_50033">[SWS_CRYPT_50033]</a> abgefragt werden. Nach dem Aufruf von <code class="mono">Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a> werden Nachrichtenfragmente sukzessive per <code class="mono">Update()</code> verarbeitet <a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a>. Sobald alle Daten übergeben wurden, schließt <code class="mono">Finish()</code> die Berechnung ab <a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a>. Der erzeugte Digest wird anschließend mit <code class="mono">GetDigest()</code> in einen Puffer kopiert <a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a>, dessen Mindestgröße vorab über <code class="mono">GetDigestSize()</code> ermittelt werden kann <a class="spec-record-ref" data-req="SWS_CRYPT_50134" href="../spec/record.html?id=SWS_CRYPT_50134">[SWS_CRYPT_50134]</a>. Alternativ erlaubt <code class="mono">Compare()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50133" href="../spec/record.html?id=SWS_CRYPT_50133">[SWS_CRYPT_50133]</a> oder <code class="mono">CompareSubspan()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50028" href="../spec/record.html?id=SWS_CRYPT_50028">[SWS_CRYPT_50028]</a> den direkten Abgleich gegen einen erwarteten Referenzwert.</p>

<h4>Fehlerszenarien</h4>
<p>Fehler werden über den Rückgabetyp <code class="mono">ara::core::Result</code> signalisiert und decken folgende Ursachen ab:</p>
<ul>
<li><strong>Zustandsfehler:</strong> Ein Aufruf von <code class="mono">Start()</code>, <code class="mono">Generate()</code> oder <code class="mono">Verify()</code> ohne konfigurierten Schlüssel schlägt mit <code class="mono">kUninitializedContext</code> fehl <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>. Aufrufe von <code class="mono">Update()</code>, <code class="mono">Finish()</code> oder <code class="mono">Cancel()</code> ohne vorherigen Start melden <code class="mono">kProcessingNotStarted</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_22115" href="../spec/record.html?id=SWS_CRYPT_22115">[SWS_CRYPT_22115]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50027" href="../spec/record.html?id=SWS_CRYPT_50027">[SWS_CRYPT_50027]</a>. Ein Zugriff auf das Ergebnis vor Abschluss liefert <code class="mono">kProcessingNotFinished</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50133" href="../spec/record.html?id=SWS_CRYPT_50133">[SWS_CRYPT_50133]</a>.</li>
<li><strong>Schlüssel- und Rechtefehler:</strong> Ist der übergebene Schlüssel inkompatibel zum Kontext, tritt <code class="mono">kIncompatibleObject</code> auf <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50026" href="../spec/record.html?id=SWS_CRYPT_50026">[SWS_CRYPT_50026]</a>. Fehlt dem Schlüssel die Berechtigung <code class="mono">kAllowMac</code>, führt dies zu <code class="mono">kUsageViolation</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22118" href="../spec/record.html?id=SWS_CRYPT_22118">[SWS_CRYPT_22118]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>. Verweist die Konfiguration auf einen leeren KeySlot, wird <code class="mono">kEmptyKeySlot</code> gemeldet <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>.</li>
<li><strong>Parameter- und Pufferfehler:</strong> Ein zu kleiner Ausgabepuffer wird mit <code class="mono">kInsufficientCapacity</code> abgewiesen <a class="spec-record-ref" data-req="SWS_CRYPT_22116" href="../spec/record.html?id=SWS_CRYPT_22116">[SWS_CRYPT_22116]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>. Nicht unterstützte Eingabe- oder IV-Längen führen zu <code class="mono">kInvalidInputSize</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22113" href="../spec/record.html?id=SWS_CRYPT_22113">[SWS_CRYPT_22113]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50133" href="../spec/record.html?id=SWS_CRYPT_50133">[SWS_CRYPT_50133]</a>. Werden Modi oder IV-Konfigurationen vom Algorithmus nicht unterstützt, resultiert <code class="mono">kUnsupported</code> <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a> <a class="spec-record-ref" data-req="SWS_CRYPT_50029" href="../spec/record.html?id=SWS_CRYPT_50029">[SWS_CRYPT_50029]</a>. Belegte kryptografische Hardwareressourcen werden mit <code class="mono">kBusyResource</code> gemeldet <a class="spec-record-ref" data-req="SWS_CRYPT_22110" href="../spec/record.html?id=SWS_CRYPT_22110">[SWS_CRYPT_22110]</a>.</li>
</ul>
