<h4>Context</h4>
<p>The namespace <code>ara::core</code> forms the fundamental basis of all functional clusters of the AUTOSAR Adaptive Platform. It provides fundamental data types, error handling mechanisms, asynchronous synchronization primitives, and infrastructure for memory management. Key types include error and result containers such as <code>Result</code>, <code>ErrorCode</code>, and <code>ErrorDomain</code>, asynchronous interaction elements such as <code>Promise</code> and <code>Future</code>, as well as interfaces for managing memory resources via <code>MemoryResource</code> and <code>PolymorphicAllocator</code>. In addition, with <code>InstanceSpecifier</code>, the namespace provides a model abstraction for paths to model elements that can be compared using equality operators <a class="spec-record-ref" data-req="SWS_CORE_08081" href="../spec/record.html?id=SWS_CORE_08081">[SWS_CORE_08081]</a>.</p>
<p>Within an Adaptive Application, components primarily interact with error domains such as the global Core error domain <a class="spec-record-ref" data-req="SWS_CORE_05280" href="../spec/record.html?id=SWS_CORE_05280">[SWS_CORE_05280]</a> and the Future error domain <a class="spec-record-ref" data-req="SWS_CORE_00480" href="../spec/record.html?id=SWS_CORE_00480">[SWS_CORE_00480]</a>. For memory management, global default memory resources can be queried <a class="spec-record-ref" data-req="SWS_CORE_06565" href="../spec/record.html?id=SWS_CORE_06565">[SWS_CORE_06565]</a> and set anew <a class="spec-record-ref" data-req="SWS_CORE_06564" href="../spec/record.html?id=SWS_CORE_06564">[SWS_CORE_06564]</a>, with predefined resources such as <code>NewDeleteResource</code> <a class="spec-record-ref" data-req="SWS_CORE_06562" href="../spec/record.html?id=SWS_CORE_06562">[SWS_CORE_06562]</a> or <code>NullMemoryResource</code> <a class="spec-record-ref" data-req="SWS_CORE_06563" href="../spec/record.html?id=SWS_CORE_06563">[SWS_CORE_06563]</a> being available.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of the entire ARA framework within an operating system process is controlled deterministically via <code>ara::core</code>. Prior to any interaction with ARA interfaces (with the exception of a few explicitly released basic types), the framework must be initialized via <code>Initialize</code> <a class="spec-record-ref" data-req="SWS_CORE_10003" href="../spec/record.html?id=SWS_CORE_10003">[SWS_CORE_10003]</a>. The function accepts the command line arguments <code>argc</code> and <code>argv</code>, which may contain vendor-specific configuration details and may be modified by the call.</p>
<p>After successful initialization, the framework is in the active operating state. Before terminating the application, the framework must be shut down in an orderly manner via <code>Deinitialize</code> <a class="spec-record-ref" data-req="SWS_CORE_10002" href="../spec/record.html?id=SWS_CORE_10002">[SWS_CORE_10002]</a>. After this call, any further interaction with ARA interfaces is impermissible. Both <code>Initialize</code> and <code>Deinitialize</code> are not thread-safe and may only be executed when static initialization is complete and no destruction of static data has begun <a class="spec-record-ref" data-req="SWS_CORE_10003" href="../spec/record.html?id=SWS_CORE_10003">[SWS_CORE_10003]</a>, <a class="spec-record-ref" data-req="SWS_CORE_10002" href="../spec/record.html?id=SWS_CORE_10002">[SWS_CORE_10002]</a>. Interpretation: A renewed initialization cycle within the same process after deinitialization has taken place is likely not intended by the standard as a regular operational case.</p>

<h4>Usage Path</h4>
<p>A typical use case comprises the initialization of the framework, the asynchronous execution of a task with result passing, and orderly deinitialization:</p>
<ol>
<li><strong>Framework initialization:</strong> The application starts in <code>main()</code> and calls <code>Initialize(argc, argv)</code> <a class="spec-record-ref" data-req="SWS_CORE_10003" href="../spec/record.html?id=SWS_CORE_10003">[SWS_CORE_10003]</a>. The result is returned as <code>Result&lt;void&gt;</code> and checked for errors.</li>
<li><strong>Creation of asynchronous endpoints:</strong> For a background job, the application creates a <code>Promise</code> and requests the associated <code>Future</code>.</li>
<li><strong>Concurrent processing:</strong> The <code>Promise</code> is passed to a worker context, which performs the computation and writes the result (or an error) to the shared state.</li>
<li><strong>Synchronization and querying:</strong> The caller monitors the state of the <code>Future</code> using <code>wait_for()</code> or <code>wait_until()</code>, which provides the status as <code>FutureStatus</code> (<a class="spec-record-ref" data-req="SWS_CORE_00361" href="../spec/record.html?id=SWS_CORE_00361">[SWS_CORE_00361]</a>: <code>kReady</code> or <code>kTimeout</code>). As soon as <code>kReady</code> is signaled, the application retrieves the result.</li>
<li><strong>Result evaluation:</strong> The result is available as <code>Result</code> and can be compared via equality operators <a class="spec-record-ref" data-req="SWS_CORE_00780" href="../spec/record.html?id=SWS_CORE_00780">[SWS_CORE_00780]</a> or analyzed for error states.</li>
<li><strong>Shutdown:</strong> Prior to process termination, <code>Deinitialize()</code> is called <a class="spec-record-ref" data-req="SWS_CORE_10002" href="../spec/record.html?id=SWS_CORE_10002">[SWS_CORE_10002]</a> to release all framework resources.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Errors are mapped in <code>ara::core</code> in a structured manner via error codes and error domains:</p>
<ul>
<li><strong>Initialization errors:</strong> A repeated call to <code>Initialize</code> fails with the error code <code>CoreErrc::kAlreadyInitialized</code> <a class="spec-record-ref" data-req="SWS_CORE_10003" href="../spec/record.html?id=SWS_CORE_10003">[SWS_CORE_10003]</a>, <a class="spec-record-ref" data-req="SWS_CORE_05200" href="../spec/record.html?id=SWS_CORE_05200">[SWS_CORE_05200]</a>. A call to <code>Deinitialize</code> without prior initialization or when initialization is already completed returns <code>CoreErrc::kNotInitialized</code> <a class="spec-record-ref" data-req="SWS_CORE_10002" href="../spec/record.html?id=SWS_CORE_10002">[SWS_CORE_10002]</a>, <a class="spec-record-ref" data-req="SWS_CORE_05200" href="../spec/record.html?id=SWS_CORE_05200">[SWS_CORE_05200]</a>. Other errors in the domain, such as <code>kInvalidArgument</code>, <code>kInvalidMetaModelShortname</code>, or <code>kInvalidMetaModelPath</code>, can be generated via <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_CORE_05200" href="../spec/record.html?id=SWS_CORE_05200">[SWS_CORE_05200]</a>, <a class="spec-record-ref" data-req="SWS_CORE_05290" href="../spec/record.html?id=SWS_CORE_05290">[SWS_CORE_05290]</a>.</li>
<li><strong>Asynchrony errors:</strong> Specific errors of <code>FutureErrorDomain</code> can occur when using <code>Future</code> <a class="spec-record-ref" data-req="SWS_CORE_00400" href="../spec/record.html?id=SWS_CORE_00400">[SWS_CORE_00400]</a>. If a shared state is abandoned prematurely, this results in <code>FutureErrc::kBrokenPromise</code>; access without a valid shared state generates <code>FutureErrc::kNoState</code>. Corresponding error codes can be instantiated via <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_CORE_00490" href="../spec/record.html?id=SWS_CORE_00490">[SWS_CORE_00490]</a>.</li>
<li><strong>Comparison of error and result values:</strong> Two <code>ErrorCode</code> instances are equal if and only if their function values for <code>Value()</code> and <code>Domain()</code> match; <code>SupportData()</code> is not used for the comparison <a class="spec-record-ref" data-req="SWS_CORE_00571" href="../spec/record.html?id=SWS_CORE_00571">[SWS_CORE_00571]</a>. A <code>Result</code> that contains a value is always unequal to a <code>Result</code> with an error <a class="spec-record-ref" data-req="SWS_CORE_00780" href="../spec/record.html?id=SWS_CORE_00780">[SWS_CORE_00780]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00781" href="../spec/record.html?id=SWS_CORE_00781">[SWS_CORE_00781]</a>.</li>
<li><strong>Fatal errors and process termination:</strong> Unrecoverable errors lead to a call to <code>Abort</code> <a class="spec-record-ref" data-req="SWS_CORE_00052" href="../spec/record.html?id=SWS_CORE_00052">[SWS_CORE_00052]</a>. This function never returns and does not unwind the stack (destructors of automatic variables are not called). In advance, user-defined termination handlers of type <code>AbortHandler</code> <a class="spec-record-ref" data-req="SWS_CORE_00050" href="../spec/record.html?id=SWS_CORE_00050">[SWS_CORE_00050]</a> can be registered via <code>AddAbortHandler</code> <a class="spec-record-ref" data-req="SWS_CORE_00054" href="../spec/record.html?id=SWS_CORE_00054">[SWS_CORE_00054]</a> (at least 8 handlers supported) or <code>SetAbortHandler</code> <a class="spec-record-ref" data-req="SWS_CORE_00051" href="../spec/record.html?id=SWS_CORE_00051">[SWS_CORE_00051]</a>.</li>
</ul>
