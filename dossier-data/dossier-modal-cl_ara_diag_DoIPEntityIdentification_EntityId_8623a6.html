<p class="ai-level ai-oneliner-lead" data-ai-level="1">Kapselt die sechs Byte lange Entitätskennung (EID) für die DoIP-Fahrzeugidentifikation gemäß ISO 13400-2.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Struktur <code>ara::diag::DoIPEntityIdentification::EntityId</code> dient als Datenbehälter für die sechs Byte lange Entitätskennung (EID) einer DoIP-Instanz gemäß ISO 13400-2 (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>). Bei entsprechender Konfiguration ruft der Diagnostic Manager diese Kennung über die Methode <code>ara::diag::DoIPEntityIdentification::GetEntityId</code> von der adaptiven Anwendung ab, um sie in DoIP-Protokollnachrichten wie die Fahrzeugankündigung einzubetten (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>). Sollte die Schnittstelle noch nicht bereitstehen oder der Abruf fehlschlagen, greift als zwingende Randbedingung ein Fallback auf den festen Ersatzwert aus lauter Bytes mit dem Wert <code>0xFF</code> (<a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>).</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Datenstruktur <code>ara::diag::DoIPEntityIdentification::EntityId</code> dient der Repräsentation der standardisierten Entitätskennung (Entity Identification, EID) für die Diagnosekommunikation über das Internet-Protokoll (DoIP) gemäß ISO 13400-2 (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=576">AUTOSAR_AP_SWS_Diagnostics §8.33 „Header: ara/diag/doip_entity_identification.h“</a>). Innerhalb der AUTOSAR Adaptive Platform ist sie als öffentlicher Strukturtyp innerhalb der API-Klasse <code>ara::diag::DoIPEntityIdentification</code> definiert (<a class="spec-record-ref" data-req="SWS_DM_01362" href="../spec/record.html?id=SWS_DM_01362">[SWS_DM_01362]</a>, <a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>).</p>
<p>Ihre primäre Verantwortung besteht in der Kapselung des exakt sechs Byte langen Identifikationswerts einer DoIP-Entität (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>). In der Plattformarchitektur interagieren dabei drei Hauptakteure: Erstens die adaptive Anwendung, welche die Entitätskennung verwaltet oder aus der Hardware liest. Zweitens die Schnittstellenklasse <code>ara::diag::DoIPEntityIdentification</code>, welche die Methode zur Bereitstellung der Kennung anbietet (<a class="spec-record-ref" data-req="SWS_DM_01362" href="../spec/record.html?id=SWS_DM_01362">[SWS_DM_01362]</a>). Drittens der Diagnostic Manager (DM), der die EID im Rahmen der Fahrzeugidentifikation für ausgehende DoIP-Nachrichten abruft (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“</a>).</p>

<h4>Lebenszyklus</h4>
<p>Als Datenstruktur mit dem einzigen Member <code>entityIdentification</code> vom Typ <code>ara::core::Array&lt;std::uint8_t, 6&gt;</code> weist <code>EntityId</code> die Eigenschaften eines leichtgewichtigen C++-Wertobjekts auf (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>). Interpretation: Mangels dynamischer Ressourcenallokation dürfte die Struktur standardmäßig reguläre Kopier- und Verschiebeoperationen unterstützen und keinen komplexen internen Zustandsübergängen unterliegen. <a class="interp-q interp-q-open" data-q="Q-4a6f7d6e7368b436" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-4a6f7d6e7368b436" title="Frage Q-4a6f7d6e7368b436 (offen): Wertsemantik: EntityId dürfte als reines C++-Wertobjekt standardmäßig kopierbar und verschiebbar sein, da das einzige Element ein ara::core::Array fester Größe ist.">Frage Q-4a6f7d6e7368b436 (offen)</a></p>
<p>Die Instanziierung von <code>EntityId</code> erfolgt durch die adaptive Anwendung, sobald der Diagnostic Manager die Identitätsdaten über den Aufruf von <code>ara::diag::DoIPEntityIdentification::GetEntityId</code> abfragt (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>). Die Lebensdauer einer Instanz ist typischerweise an den Rückgabe- und Verarbeitungszyklus des Methodenaufrufs gebunden. Während die umgebende Service-Klasse <code>ara::diag::DoIPEntityIdentification</code> über explizite Konstruktoren (<a class="spec-record-ref" data-req="SWS_DM_01364" href="../spec/record.html?id=SWS_DM_01364">[SWS_DM_01364]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=577">AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.2.1 „DoIPEntityIdentification“</a>) und Destruktoren (<a class="spec-record-ref" data-req="SWS_DM_01365" href="../spec/record.html?id=SWS_DM_01365">[SWS_DM_01365]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=577">AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.1.1 „Destructor“</a>) verfügt, wird das Wertobjekt <code>EntityId</code> nach Auslesen der Felddaten durch den Diagnostic Manager beim Verlassen des Gültigkeitsbereichs automatisch freigegeben.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Einsatz von <code>EntityId</code> folgt einer definierten Sequenz im Diagnoseprotokollablauf:</p>
<ul>
  <li><strong>Konfigurationsprüfung:</strong> Der Diagnostic Manager prüft das Attribut <code>DoIpNetworkConfiguration.eidRetrieval</code>. Ist dort <code>DoIpEidRetrievalEnum.eidUseApi</code> hinterlegt, muss der DM die Kennung zwingend über die API abrufen (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>).</li>
  <li><strong>Abruf per API:</strong> Der Diagnostic Manager ruft die Methode <code>ara::diag::DoIPEntityIdentification::GetEntityId</code> auf (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>).</li>
  <li><strong>Datenbereitstellung:</strong> Die Anwendung erzeugt eine Instanz von <code>EntityId</code>, befüllt das Member <code>entityIdentification</code> mit der 6-Byte-Kennung gemäß ISO 13400-2 (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>) und übergibt die Struktur.</li>
  <li><strong>Protokollverwendung:</strong> Der Diagnostic Manager entnimmt die Kennung und setzt sie in DoIP-Nachrichten wie der Fahrzeugankündigung (Vehicle Announcement Message) ein (<a class="spec-record-ref" data-req="SWS_DM_01361" href="../spec/record.html?id=SWS_DM_01361">[SWS_DM_01361]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“</a>).</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Ein zentrales Fehlerszenario entsteht, wenn die Schnittstelle <code>ara::diag::DoIPEntityIdentification</code> zum geforderten Abfragezeitpunkt von der adaptiven Anwendung noch nicht angeboten wird oder der Abruf über <code>GetEntityId</code> fehlschlägt (<a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=107">AUTOSAR_AP_SWS_Diagnostics §8.33 „Providing EID in DoIP protocol messages using Application Interface“</a>).</p>
<p>Um das Senden der DoIP-Nachrichten nicht dauerhaft zu blockieren, schreibt die Spezifikation in diesem Fall ein verbindliches Ersatzwertverhalten vor: Der Diagnostic Manager muss anstelle der regulären Anwendungsdaten ein 6-Byte-EID-Feld mit dem festen Wert <code>0xFF 0xFF 0xFF 0xFF 0xFF 0xFF</code> übertragen (<a class="spec-record-ref" data-req="SWS_DM_01528" href="../spec/record.html?id=SWS_DM_01528">[SWS_DM_01528]</a>). Auf Typebene schließt das feste Array <code>ara::core::Array&lt;std::uint8_t, 6&gt;</code> Längenfehler und Pufferüberläufe zur Übersetzungszeit aus (<a class="spec-record-ref" data-req="SWS_DM_01496" href="../spec/record.html?id=SWS_DM_01496">[SWS_DM_01496]</a>).</p>
