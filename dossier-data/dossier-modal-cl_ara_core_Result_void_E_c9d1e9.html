<h4>Context</h4>
<p>The template class specialization <code>ara::core::Result&lt;void, E&gt;</code> represents the result of operations that do not return a payload value upon successful execution, but exclusively signal success or the occurrence of an error. Within the AUTOSAR Adaptive Platform, it serves as a standardized return type for functions with void semantics and enables structured error handling without C++ exceptions. The value type is fixed via type alias as <code>value_type = void</code> <a class="spec-record-ref" data-req="SWS_CORE_00811" href="../spec/record.html?id=SWS_CORE_00811">[SWS_CORE_00811]</a>, while the error type is parameterized via the type alias <code>error_type = E</code> <a class="spec-record-ref" data-req="SWS_CORE_00812" href="../spec/record.html?id=SWS_CORE_00812">[SWS_CORE_00812]</a>. The implementation enforces at compile time that conditions with <code>E != ara::core::ErrorCode</code> lead to a compiler error.</p>
<p>As a standardized result type, the class forms the interface between calling application components and executing platform or application services. It ensures that valueless operations use the same consistent interface philosophy and functional further processing as value-carrying specializations of <code>ara::core::Result</code>.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::core::Result&lt;void, E&gt;</code> is at any time in exactly one of two distinct states: It represents either a successful execution (state with void value) or an error state with an error object of type <code>E</code> contained.</p>
<p>The creation of a success instance takes place via the parameterless default constructor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> or the static factory method <code>FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a>. An error state is established during construction by passing an error object as an lvalue <a class="spec-record-ref" data-req="SWS_CORE_00823" href="../spec/record.html?id=SWS_CORE_00823">[SWS_CORE_00823]</a> or rvalue <a class="spec-record-ref" data-req="SWS_CORE_00824" href="../spec/record.html?id=SWS_CORE_00824">[SWS_CORE_00824]</a>. In addition, the static methods <code>FromError()</code> provide factories that create errors by copy <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>, by move <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a>, or in-place from arguments <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>. The latter overload is constrained via SFINAE and only participates if <code>E</code> is constructible from the arguments and the first argument represents neither <code>E</code> nor a specialization of <code>Result</code> <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>.</p>
<p>The class has complete value and move semantics via the copy constructor <a class="spec-record-ref" data-req="SWS_CORE_00825" href="../spec/record.html?id=SWS_CORE_00825">[SWS_CORE_00825]</a>, copy assignment operator <a class="spec-record-ref" data-req="SWS_CORE_00841" href="../spec/record.html?id=SWS_CORE_00841">[SWS_CORE_00841]</a>, move constructor <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a>, and move assignment operator <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>. Existing instances can be overwritten in a state-modifying manner: <code>EmplaceValue()</code> puts the instance into the state with void value <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, while <code>EmplaceError()</code> constructs an error in-place <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>. Two instances can be swapped using <code>Swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>.</p>
<p>The destructor <code>~Result()</code> is trivial if <code>std::is_trivially_destructible&lt;E&gt;::value</code> is satisfied <a class="spec-record-ref" data-req="SWS_CORE_00827" href="../spec/record.html?id=SWS_CORE_00827">[SWS_CORE_00827]</a>. Regarding concurrency, non-modifying accesses such as <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> and the lvalue error access <code>Error() const &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a> are thread-safe. Modifying calls such as <code>EmplaceValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>, <code>EmplaceError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>, <code>Swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>, as well as move operations <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a> are explicitly not thread-safe.</p>

<h4>Usage Path</h4>
<p>A typical usage workflow is divided into the creation of the return value by the service provider, the check by the caller, and the conditional further processing:</p>
<ol>
<li><strong>Creation of the result:</strong> A function successfully completes an operation and creates the return object via <code>Result::FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> or the default constructor <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a>. If the operation fails, it returns the result via <code>Result::FromError(...)</code> <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>.</li>
<li><strong>State check:</strong> The caller evaluates the presence of success via <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> or the boolean conversion <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00852" href="../spec/record.html?id=SWS_CORE_00852">[SWS_CORE_00852]</a>, which return <code>true</code> on success and <code>false</code> in case of an error. Specific error values can be directly compared with <code>CheckError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00865" href="../spec/record.html?id=SWS_CORE_00865">[SWS_CORE_00865]</a>.</li>
<li><strong>Monadic chaining:</strong> In the event of a successful outcome, a subsequent function can be called via <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>. The passed callable is only executed if the instance contains a void value; if an error is present, the function is not called and the existing error content is copied into the new result object <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>.</li>
<li><strong>Error query and resolution:</strong> The method <code>Resolve()</code> takes no action in case of success, but calls a passed callable with <code>const E&amp;</code> in case of an error <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a>. A contained error can also be queried via <code>Err()</code> as <code>ara::core::Optional&lt;E&gt;</code> <a class="spec-record-ref" data-req="SWS_CORE_00868" href="../spec/record.html?id=SWS_CORE_00868">[SWS_CORE_00868]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00869" href="../spec/record.html?id=SWS_CORE_00869">[SWS_CORE_00869]</a> or safeguarded with a fallback error using <code>ErrorOr()</code> <a class="spec-record-ref" data-req="SWS_CORE_00863" href="../spec/record.html?id=SWS_CORE_00863">[SWS_CORE_00863]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00864" href="../spec/record.html?id=SWS_CORE_00864">[SWS_CORE_00864]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>When accessing instances of <code>ara::core::Result&lt;void, E&gt;</code>, strict preconditions apply to prevent runtime violations:</p>
<ul>
<li><strong>Access to missing value (ResultWithNoValueViolation):</strong> The methods <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a> and <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a> exist for generic programming and return <code>void</code>. If the instance contains no value (i.e., stores an error), calling either function triggers a <code>ResultWithNoValueViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a>. The function <code>ValueOr()</code> generically performs no action and causes no violation <a class="spec-record-ref" data-req="SWS_CORE_00861" href="../spec/record.html?id=SWS_CORE_00861">[SWS_CORE_00861]</a>.</li>
<li><strong>Access to missing error (ResultWithNoErrorViolation):</strong> Direct access to the error object via the overloads of <code>Error()</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00858" href="../spec/record.html?id=SWS_CORE_00858">[SWS_CORE_00858]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00876" href="../spec/record.html?id=SWS_CORE_00876">[SWS_CORE_00876]</a> requires that the instance contains an error. If a void value is present instead, this leads to a <code>ResultWithNoErrorViolation</code>.</li>
<li><strong>Exception throwing via ValueOrThrow:</strong> <code>ValueOrThrow()</code> throws the exception associated with the contained error if no value is present <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>. If C++ exceptions are disabled in the compiler toolchain, this function does not participate in overload resolution <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>.</li>
<li><strong>Exception safety of function objects:</strong> The operations <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a> and <code>Resolve()</code> <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a> are specified as not exception-safe; their thread safety conditionally depends on the thread safety of the respectively passed callable.</li>
</ul>
