<h4>Kontext</h4>
<p>Die Klasse <code>apext::com::secoc::ComSecOcFvmException</code> ist eine spezialisierte Ausnahmeklasse der AUTOSAR Adaptive Platform im Modul <code>com</code> <a class="spec-record-ref" data-req="SWS_CM_12512" href="../spec/record.html?id=SWS_CM_12512">[SWS_CM_12512]</a>. Sie dient primär dazu, Fehlerzustände zu signalisieren, die innerhalb des SecOC Freshness Value Managers (FVM) auftreten (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=547">AUTOSAR_AP_SWS_CommunicationManagement §C.2.4 „Class: ComSecOcFvmException“</a>). Durch die Ableitung von der Standard-Basisklasse <code>ara::core::Exception</code> fügt sich <code>ComSecOcFvmException</code> in das allgemeine Fehlerbehandlungsmodell der Adaptive Platform ein und fungiert als standardisierter Informationsträger für Ausnahmebedingungen bei der Absicherung der Kommunikation mittels SecOC.</p>
<p>Als Interaktionspartner treten im Wesentlichen drei Komponenten auf: der SecOC Freshness Value Manager selbst, welcher die Ausnahme im Fehlerfall auslöst, die aufrufende funktionale Kommunikationsschicht bzw. Applikation, welche SecOC-gesicherte Daten verarbeitet, sowie die FVM-Fehlerdomäne, die über die Header-Datei <code>apext/com/secoc/fvm_error_domain.h</code> eingebunden wird <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Die Klasse stellt somit das Bindeglied zwischen den internen Fehlerzuständen des Freshness-Managements und den übergeordneten Softwareschichten dar.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>ComSecOcFvmException</code> erfolgt bedarfsgesteuert genau dann, wenn bei der Ermittlung oder Überprüfung von Freshness-Werten ein nicht behebbarer Fehler festgestellt wird. Hierfür stellt die Klasse einen expliziten Konstruktor bereit, der einen <code>ara::core::ErrorCode</code> entgegennimmt <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>.</p>
<p>Dieser Konstruktor ist als <code>noexcept</code> deklariert <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Dies garantiert, dass die Objekterzeugung selbst unter keinen Umständen fehlschlägt oder weitere Ausnahmen wirft, wodurch die Spezifikation der Exception-Sicherheit (exception safe) eingehalten wird <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Bezüglich des Lebenszyklus und der Besitzverhältnisse wird die Ausnahme per Wert erzeugt und geworfen. Auf Empfängerseite dürfte sie vermutlich als konstante Referenz (<code>const ComSecOcFvmException&amp;</code> oder polymorph als <code>const ara::core::Exception&amp;</code>) abgefangen werden. <a class="interp-q interp-q-open" data-q="Q-d170140b08fe9ca0" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-d170140b08fe9ca0" title="Frage Q-d170140b08fe9ca0 (offen): Auf Empfängerseite dürfte die Ausnahme vermutlich per const-Referenz abgefangen werden">Frage Q-d170140b08fe9ca0 (offen)</a></p>
<p>Sobald der entsprechende Ausnahmebehandlungsblock (<code>catch</code>) abgearbeitet ist, wird die Exception-Instanz automatisch zerstört. Hinsichtlich der Nebenläufigkeit dürften Instanzen der Exception thread-lokal im Ausnahmekontext des jeweiligen Threads verarbeitet werden. <a class="interp-q interp-q-open" data-q="Q-bd368a082b887d14" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-bd368a082b887d14" title="Frage Q-bd368a082b887d14 (offen): Instanzen der Exception dürften thread-lokal verarbeitet werden">Frage Q-bd368a082b887d14 (offen)</a></p>

<p>Der typische Nutzungspfad erstreckt sich von der Erkennung eines Freshness-Fehlers bis zur gezielten Reaktion durch die übergeordnete Kommunikationsschicht.</p>

<p>Zunächst fordert das Kommunikationsmodul oder die Anwendung im Rahmen der SecOC-Verarbeitung einen Freshness-Wert beim Freshness Value Manager an oder übergibt einen solchen zur Validierung. Schlägt diese Operation fehl – beispielsweise aufgrund von Synchronisationsproblemen oder ungültigen Zählerständen –, instanziiert der Freshness Value Manager die Ausnahmeklasse <code>ComSecOcFvmException</code> unter Übergabe des konkreten Fehlercodes <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Unmittelbar nach der Konstruktion wird die Ausnahme geworfen. Der Aufrufer fängt die Ausnahme im passenden Handler ab und kann den enthaltenen <code>ara::core::ErrorCode</code> abfragen, um angemessen auf die Beeinträchtigung der Kommunikationssicherheit zu reagieren <a class="spec-record-ref" data-req="SWS_CM_12512" href="../spec/record.html?id=SWS_CM_12512">[SWS_CM_12512]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Da <code>ComSecOcFvmException</code> selbst das Transportmedium für Fehlersignalisierungen darstellt, konzentrieren sich die Fehlerszenarien auf die semantischen Inhalte des gekapselten Fehlercodes. Die Klasse nimmt zur Erzeugung zwingend einen <code>ara::core::ErrorCode</code> entgegen <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Die Header-Zuordnung zu <code>apext/com/secoc/fvm_error_domain.h</code> belegt, dass diese Fehlercodes aus einer dedizierten FVM-Fehlerdomäne stammen <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>.</p>
<p>Als wesentliche Vorbedingung für die Erzeugung gilt, dass der auslösende Kontext einen initialisierten Fehlercode bereitstellt. Als Nachbedingung enthält das resultierende Objekt die vollständigen Fehlerinformationen der jeweiligen Fehlerdomäne. Ein kritisches Fehlerszenario der sekundären Ausnahmeentstehung während der Exception-Erzeugung wird durch die <code>noexcept</code>-Garantie des Konstruktors ausgeschlossen <a class="spec-record-ref" data-req="SWS_CM_12513" href="../spec/record.html?id=SWS_CM_12513">[SWS_CM_12513]</a>. Dadurch wird zuverlässig verhindert, dass ein vorzeitiger Abbruch des Prozesses via <code>std::terminate</code> infolge eines Fehlschlags im Fehlerbehandlungspfad eintritt.</p>
