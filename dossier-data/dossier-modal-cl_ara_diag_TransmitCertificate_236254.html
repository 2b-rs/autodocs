<h4>Context</h4>
<p>
The class <code>ara::diag::TransmitCertificate</code> provides the programming interface for the UDS subfunction <em>TransmitCertificate</em> (<code>0x29 04</code>) of the service <em>Authentication</em> (<code>0x29</code>) <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=522">AUTOSAR_AP_SWS_Diagnostics §8.26.1 “Class: TransmitCertificate”</a>. It implements a generic interface via which an Adaptive Application can receive and evaluate one or more certificates identified by a 16-bit identifier (<code>certificateEvaluationId</code>).
</p>
<p>
In the system architecture, <code>ara::diag::TransmitCertificate</code> acts as a link between the AUTOSAR Adaptive Diagnostic Manager (DM) or the Diagnostic Server Instance and the concrete application logic. An external diagnostic tester sends the UDS authentication request to the server, which forwards the request to the application after activation <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>, <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>.
</p>

<h4>Lifecycle</h4>
<p>
Instantiation takes place via the constructor by specifying a <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>:
</p>
<ul>
<li><code>specifier</code>: A <code>ara::core::InstanceSpecifier</code> that references a <code>PortPrototype</code> which is typed via a <code>DiagnosticAuthenticationPortMapping</code> <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>.</li>
<li><code>concurrencyType</code>: Defines whether the subsequent execution of <code>Process</code> is treated as thread-safe (<code>kConcurrent</code>) or non-thread-safe (<code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
</ul>
<p>
Copy and move operations are completely prevented: copy constructor <a class="spec-record-ref" data-req="SWS_DM_01964" href="../spec/record.html?id=SWS_DM_01964">[SWS_DM_01964]</a>, move constructor <a class="spec-record-ref" data-req="SWS_DM_01963" href="../spec/record.html?id=SWS_DM_01963">[SWS_DM_01963]</a>, copy assignment operator <a class="spec-record-ref" data-req="SWS_DM_01966" href="../spec/record.html?id=SWS_DM_01966">[SWS_DM_01966]</a>, and move assignment operator <a class="spec-record-ref" data-req="SWS_DM_01965" href="../spec/record.html?id=SWS_DM_01965">[SWS_DM_01965]</a> are declared as deleted (<code>=delete</code>). An authentication interface instance thus exists as a uniquely bound object.
</p>
<p>
Following construction, the life cycle is divided into two operating phases:
</p>
<ol>
<li><strong>Provision (Offered):</strong> By calling <code>Offer()</code>, the Diagnostic Manager is authorized to forward incoming UDS messages for the subfunction to the method <code>Process()</code> <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Revocation (Stopped):</strong> Calling <code>StopOffer()</code> deregisters the forwarding again <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>
<p>
The destructor is virtual and declared as default (<code>noexcept = default</code>) <a class="spec-record-ref" data-req="SWS_DM_01967" href="../spec/record.html?id=SWS_DM_01967">[SWS_DM_01967]</a>. While the constructor is thread-safe, <code>Offer()</code> and <code>StopOffer()</code> are specified as not thread-safe and must not be called concurrently without coordination <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>, <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.
</p>

<h4>Usage Path</h4>
<p>
The regular operational sequence comprises registration with the Diagnostic Manager, asynchronous receipt of the certificate data, and completion of processing:
</p>
<ol>
<li><strong>Instantiation and release:</strong> The application instantiates the derived class and activates acceptance via <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Reception and processing:</strong> Upon receipt of a UDS request, the Diagnostic Server forwards the data via <code>Process(certificateEvaluationId, certificateData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. The method returns a <code>ara::core::Future&lt;void&gt;</code>, thereby supporting asynchronous processing. The concrete semantics and evaluation of the certificate are entirely the responsibility of the application <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Cancellation handling:</strong> The application can check via <code>cancellationHandler.IsCanceled()</code> whether the diagnostic conversation was canceled, or register a notification callback for cancellation events via <code>cancellationHandler.SetNotifier()</code> <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Positive response:</strong> If the execution completes successfully without an error code, the Diagnostic Server Instance transmits a positive UDS response with the return parameter <code>authenticationReturnParameter = 0x13</code> (<em>CertificateVerified</em>) to the tester <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>.</li>
<li><strong>Cleanup:</strong> Upon termination, reception is stopped via <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>
Specific error conditions are defined both during initialization and during ongoing operation:
</p>
<ul>
<li><strong>Manifest and modeling errors during creation:</strong> The constructor reports violations if the <code>InstanceSpecifier</code> cannot be resolved (<code>InstanceSpecifierMappingIntegrityViolation</code>), the referenced <code>PortPrototype</code> is not typed by a <code>DiagnosticTransmitCertificateInterface</code> (<code>PortInterfaceMappingViolation</code>), no process mapping exists (<code>ProcessMappingViolation</code>), or the <code>InstanceSpecifier</code> is already assigned in the process (<code>InstanceSpecifierAlreadyInUseViolation</code>) <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>.</li>
<li><strong>Multiple registration:</strong> A renewed call to <code>Offer()</code> when offering is already active leads to error <code>DiagOfferErrc::kAlreadyOffered</code> with rollback semantics <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Rejection in process:</strong> If the verification of the certificate fails in the application or a processing error occurs, <code>Process()</code> returns a corresponding error via the <code>ara::core::Future</code>. In this case, an appropriate UDS Negative Response Code (NRC) according to ISO 14229-1 must be used via <code>DiagUdsNrcErrc</code> <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. The Diagnostic Server Instance then generates a negative UDS response (NRC) to the external tester <a class="spec-record-ref" data-req="SWS_DM_01249" href="../spec/record.html?id=SWS_DM_01249">[SWS_DM_01249]</a>.</li>
</ul>
