<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht der Anwendung die Entgegennahme und Prüfung von Diagnose-Zertifikaten im UDS-Dienst Authentication.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::TransmitCertificate</code> implementiert die Anwendungsschnittstelle für die UDS-Unterfunktion <em>TransmitCertificate</em> (<code>0x29 0x04</code>) des Dienstes <em>Authentication</em> <a class="spec-record-ref" data-req="SWS_DM_01961" href="../spec/record.html?id=SWS_DM_01961">[SWS_DM_01961]</a>. Nach der Freigabe über <code>Offer()</code> nimmt die Anwendung übertragene Zertifikatsdaten in der asynchronen Methode <code>Process()</code> entgegen und leitet die anwendungsspezifische Verifizierung ein <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Bei erfolgreicher Prüfung veranlasst das Diagnose-Management eine positive UDS-Antwort mit dem Rückgabeparameter <code>0x13</code> (<code>CertificateVerified</code>), während Fehler als negative Antwort mit entsprechendem NRC beantwortet werden. Die Instanz ist fest an ein Port-Interface gebunden und darf weder kopiert noch verschoben werden.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::TransmitCertificate</code> <a class="spec-record-ref" data-req="SWS_DM_01961" href="../spec/record.html?id=SWS_DM_01961">[SWS_DM_01961]</a> im Header <code>ara/diag/transmit_certificate.h</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=522">AUTOSAR_AP_SWS_Diagnostics §8.26 „Header: ara/diag/transmit_certificate.h“</a>) stellt die Schnittstelle der Adaptive-Anwendung zur Realisierung der UDS-Unterfunktion <em>TransmitCertificate</em> (<code>0x29 0x04</code>) des Dienstes <em>Authentication</em> dar. Als generische Schnittstelle ermöglicht sie es der Anwendung, ein oder mehrere übermittelte Zertifikate anhand einer 16-Bit-Kennung (<code>certificateEvaluationId</code>) entgegenzunehmen und zu verarbeiten.</p>
<p>An der Interaktion sind drei Hauptkomponenten beteiligt:</p>
<ul>
<li>Der externe <strong>Diagnosetester</strong>, der die UDS-Anfrage zur Zertifikatsübermittlung an das Fahrzeug sendet <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li>Der <strong>Diagnostic Server</strong> (Diagnose-Management, DM) der Adaptive Platform, welcher eingehende Diagnoseanfragen filtert, weiterleitet und die abschließenden UDS-Antworten generiert <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a>, <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li>Die <strong>Adaptive-Anwendung</strong>, welche eine von <code>ara::diag::TransmitCertificate</code> abgeleitete Instanz bereitstellt, die Zertifikatsprüfung vornimmt und das Ergebnis asynchron an den Server zurückliefert <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
</ul>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>ara::diag::TransmitCertificate</code> werden über den Konstruktor unter Angabe eines <code>ara::core::InstanceSpecifier</code> sowie des Nebenläufigkeitsmodus <code>ConcurrencyType</code> erzeugt <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>. Der <code>InstanceSpecifier</code> muss im Manifest auf einen <code>PortPrototype</code> verweisen, der durch ein <code>DiagnosticTransmitCertificateInterface</code> typisiert ist <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>. Schlägt diese Zuordnung fehl oder wird die Instanzkennung im aktuellen Prozess mehrfach verwendet, treten Laufzeitverletzungen wie <code>InstanceSpecifierMappingIntegrityViolation</code>, <code>PortInterfaceMappingViolation</code>, <code>ProcessMappingViolation</code> oder <code>InstanceSpecifierAlreadyInUseViolation</code> auf <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>.</p>
<p>Die Klasse unterliegt strengen Besitz- und Instanziierungsregeln: Ein Authentifizierungs-Handler ist als eindeutige, nicht kopierbare und nicht verschiebbare Instanz ausgelegt. Dementsprechend sind der Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01964" href="../spec/record.html?id=SWS_DM_01964">[SWS_DM_01964]</a>, der Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01966" href="../spec/record.html?id=SWS_DM_01966">[SWS_DM_01966]</a> sowie der Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_01963" href="../spec/record.html?id=SWS_DM_01963">[SWS_DM_01963]</a> und der Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01965" href="../spec/record.html?id=SWS_DM_01965">[SWS_DM_01965]</a> explizit gelöscht (<code>=delete</code>).</p>
<p>Der Konstruktor selbst ist threadsicher und ausnahmesicher spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>. Die Freigabe erfolgt über den virtuellen Standard-Destruktor <a class="spec-record-ref" data-req="SWS_DM_01967" href="../spec/record.html?id=SWS_DM_01967">[SWS_DM_01967]</a>. Ob die eigentliche Ausführungsmethode <code>Process</code> threadsicher implementiert werden muss, hängt vom gewählten <code>concurrencyType</code> ab (<code>kConcurrent</code> oder <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01962" href="../spec/record.html?id=SWS_DM_01962">[SWS_DM_01962]</a>, <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Registrierung des Handlers, die Verarbeitung eingehender Zertifikate und die spätere Deregistrierung:</p>
<ol>
<li><strong>Dienst anbieten (<code>Offer</code>):</strong> Die Anwendung ruft <code>Offer()</code> auf, um dem Diagnose-Management zu signalisieren, dass Anfragen für die konfigurierte Schnittstelle an diesen Handler weitergeleitet werden dürfen <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>.</li>
<li><strong>Anfrage empfangen (<code>Process</code>):</strong> Trifft beim Diagnostic Server ein UDS-Request der Unterfunktion <code>TransmitCertificate</code> ein, leitet dieser die Daten an die rein virtuelle Methode <code>Process()</code> der Anwendung weiter <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Die Methode erhält die 16-Bit-Kennung <code>certificateEvaluationId</code>, die Rohdaten des Zertifikats als <code>ara::core::Span&lt;ara::core::Byte const&gt;</code>, Metadaten (<code>metaInfo</code>) sowie einen <code>cancellationHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
<li><strong>Auswertung und Aktion:</strong> Da AUTOSAR keine feste Semantik für die Zertifikate vorschreibt, obliegt die Prüfung und das Ableiten erforderlicher Maßnahmen vollständig der Anwendung <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Interpretation: Die Anwendung dürfte das übermittelte Zertifikat typischerweise kryptografisch verifizieren oder zur Aktualisierung eines internen Schlüsselspeichers nutzen. <a class="interp-q interp-q-open" data-q="Q-34844f9257d074c6" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-34844f9257d074c6" title="Frage Q-34844f9257d074c6 (offen): Die Verifizierung und Speicherung des Zertifikats erfolgt anwendungsspezifisch">Frage Q-34844f9257d074c6 (offen)</a></li>
<li><strong>Ergebnisübermittlung:</strong> Die Methode liefert ein <code>ara::core::Future&lt;void&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Schließt die Anwendung das Future erfolgreich ohne Fehler ab, übermittelt der Diagnostic Server eine positive UDS-Antwort an den Tester, in der der Parameter <code>authenticationReturnParameter</code> (RV) auf den Wert <code>0x13</code> (<code>CertificateVerified</code>) gesetzt wird <a class="spec-record-ref" data-req="SWS_DM_01251" href="../spec/record.html?id=SWS_DM_01251">[SWS_DM_01251]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=170">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8 „Successful verification of transmitCertificate“</a>).</li>
<li><strong>Dienst beenden (<code>StopOffer</code>):</strong> Soll der Handler keine weiteren Anfragen empfangen, beendet die Anwendung die Weiterleitung durch Aufruf von <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Fehlerzustände können in verschiedenen Phasen des Lebenszyklus auftreten:</p>
<ul>
<li><strong>Bereits aktives Angebot:</strong> Wird <code>Offer()</code> aufgerufen, obwohl der Dienst für diese Instanz bereits aktiv angeboten wird, schlägt der Aufruf fehl und liefert im <code>ara::core::Result&lt;void&gt;</code> den Fehlercode <code>DiagOfferErrc::kAlreadyOffered</code> mit Rollback-Semantik zurück <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>. <code>Offer()</code> und <code>StopOffer()</code> sind nicht threadsicher und dürfen nicht nebenläufig aufgerufen werden <a class="spec-record-ref" data-req="SWS_DM_01969" href="../spec/record.html?id=SWS_DM_01969">[SWS_DM_01969]</a>, <a class="spec-record-ref" data-req="SWS_DM_01970" href="../spec/record.html?id=SWS_DM_01970">[SWS_DM_01970]</a>.</li>
<li><strong>Fehlgeschlagene Zertifikatsprüfung:</strong> Stellt die Anwendung bei der Auswertung in <code>Process()</code> einen Fehler fest, schließt sie das Future mit einem entsprechenden Fehlercode aus <code>DiagUdsNrcErrc</code> gemäß ISO 14229-1 ab <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Der Diagnostic Server fängt diesen Rückgabewert ab und sendet eine negative Diagnoseantwort (Negative Response) an den Tester, deren Negative Response Code (NRC) exakt dem übermittelten Fehlercode entspricht <a class="spec-record-ref" data-req="SWS_DM_01249" href="../spec/record.html?id=SWS_DM_01249">[SWS_DM_01249]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=170">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8 „Handling Negative return values of ara::diag::TransmitCertificate::Process method“</a>).</li>
<li><strong>Abbruch laufender Konversationen:</strong> Während der asynchronen Verarbeitung kann die Anwendung den Status über <code>cancellationHandler.IsCanceled()</code> abfragen, um festzustellen, ob die Diagnosekonversation abgebrochen wurde <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>. Ergänzend kann über <code>cancellationHandler.SetNotifier(...)</code> eine Rückruffunktion registriert werden, die bei einem Abbruch sofort benachrichtigt wird <a class="spec-record-ref" data-req="SWS_DM_01968" href="../spec/record.html?id=SWS_DM_01968">[SWS_DM_01968]</a>.</li>
</ul>
