<h4>Context</h4>
<p>The class <code>apext::diag::uds_transport::UdsTransportProtocolMgr</code> forms the standardized interface for coordination between instances of the Diagnostic Server (DM Core or session layer) and various UDS transport protocols such as DoIP or CAN (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”</a>). Concrete transport protocols are implemented as subclasses of the abstract base class <code>apext::diag::uds_transport::UdsTransportProtocolHandler</code> (<a class="spec-record-ref" data-req="SWS_DM_00315" href="../spec/record.html?id=SWS_DM_00315">[SWS_DM_00315]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1 “Support of UDS Transport Layer”</a>).</p>
<p>In this intermediary role, the manager class essentially interacts with three components:</p>
<ul>
<li><strong>UDS Transport Protocol Handlers (Transport Layer):</strong> Announce the start of incoming messages (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>), hand over completely received requests (<a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>), acknowledge transmit requests (<a class="spec-record-ref" data-req="SWS_DM_00312" href="../spec/record.html?id=SWS_DM_00312">[SWS_DM_00312]</a>), and signal channel as well as status changes (<a class="spec-record-ref" data-req="SWS_DM_00313" href="../spec/record.html?id=SWS_DM_00313">[SWS_DM_00313]</a>, <a class="spec-record-ref" data-req="SWS_DM_00314" href="../spec/record.html?id=SWS_DM_00314">[SWS_DM_00314]</a>).</li>
<li><strong>Diagnostic Server Core (Session Layer):</strong> Accepts valid UDS requests for further diagnostic processing and manages the allocation of message buffers (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>, <a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>).</li>
<li><strong>Periodic transport handlers:</strong> Transmit confirmations of the successful transmission of periodic message chains (<a class="spec-record-ref" data-req="SWS_DM_01069" href="../spec/record.html?id=SWS_DM_01069">[SWS_DM_01069]</a>).</li>
</ul>

<h4>Lifecycle</h4>
<p>The lifecycle of a transport protocol implementation is controlled by the Diagnostic Manager (DM) in a strictly defined sequence from construction and initialization to stopping (<a class="spec-record-ref" data-req="SWS_DM_00329" href="../spec/record.html?id=SWS_DM_00329">[SWS_DM_00329]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=95">AUTOSAR_AP_SWS_Diagnostics §7.1.1.1 “Initialization, Starting and Stopping of a UDS TransportLayer”</a>). The class <code>UdsTransportProtocolMgr</code> declares a virtual default destructor (<a class="spec-record-ref" data-req="SWS_DM_01524" href="../spec/record.html?id=SWS_DM_01524">[SWS_DM_01524]</a>).</p>
<p>During ongoing operation, deactivation phases are synchronized: Once a handler has closed its network connections and released resources in response to a stop, it notifies the manager via the callback <code>HandlerStopped</code>, specifying its <code>handlerId</code> (<a class="spec-record-ref" data-req="SWS_DM_00314" href="../spec/record.html?id=SWS_DM_00314">[SWS_DM_00314]</a>).</p>
<p>Regarding memory and ownership semantics, a clear transfer model applies to message buffers: At the start of a transmission, the DM Core creates the message object and passes its pointer to the handler (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>). After complete reception, the handler transfers ownership of the message back to the generic DM Core using <code>unique_ptr</code> semantics via <code>HandleMessage</code> (<a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>).</p>
<p>All interface methods are specified as exception-safe (<code>noexcept</code>), but as not thread-safe (<em>not thread-safe</em>) (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>, <a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>, <a class="spec-record-ref" data-req="SWS_DM_00312" href="../spec/record.html?id=SWS_DM_00312">[SWS_DM_00312]</a>). Interpretation: Calls to the manager must therefore presumably be synchronized by the calling transport and session components.</p>

<h4>Usage Path</h4>
<p>The regular sequence for processing incoming UDS diagnostic requests is divided into the following steps:</p>
<ol>
<li><strong>Message indication:</strong> Provided the handler supports indication, it calls <code>IndicateMessage</code> upon arrival of initial data (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>). In doing so, source and target address, addressing type (physical or functional), expected total size, and the <code>GlobalChannelIdentifier</code> (<a class="spec-record-ref" data-req="SWS_DM_09021" href="../spec/record.html?id=SWS_DM_09021">[SWS_DM_09021]</a>) are transmitted. Via <code>payloadInfo</code>, the first bytes can already be passed so that the DM can, for example, detect functional TesterPresent requests at an early stage (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>).</li>
<li><strong>Buffer provision:</strong> The manager returns a pair consisting of <code>IndicationResult</code> and an allocated <code>UdsMessagePtr</code> (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>). If the result is <code>IndicationResult::kIndicationOk</code> (<a class="spec-record-ref" data-req="SWS_DM_00384" href="../spec/record.html?id=SWS_DM_00384">[SWS_DM_00384]</a>), the handler fills the buffer with the incoming data.</li>
<li><strong>Handover to session layer:</strong> After complete reception, the handler hands the message over to the manager via <code>HandleMessage</code> (<a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>), which corresponds to the service <code>T_Data.ind</code> according to ISO 14229-2. The call returns immediately; further evaluation takes place asynchronously in the session layer (<a class="spec-record-ref" data-req="SWS_DM_00311" href="../spec/record.html?id=SWS_DM_00311">[SWS_DM_00311]</a>).</li>
<li><strong>Transmission acknowledgement:</strong> For sent UDS responses, the handler later confirms success via <code>TransmitConfirmation</code> with the result <code>kTransmitOk</code> (<a class="spec-record-ref" data-req="SWS_DM_00312" href="../spec/record.html?id=SWS_DM_00312">[SWS_DM_00312]</a>, <a class="spec-record-ref" data-req="SWS_DM_00307" href="../spec/record.html?id=SWS_DM_00307">[SWS_DM_00307]</a>), corresponding to <code>T_Data.con</code> according to ISO 14229-2.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error conditions during transport or buffer allocation are caught via defined status values and error interfaces:</p>
<ul>
<li><strong>Failure during indication:</strong> If the DM Core cannot accept an indicated message, it reports this via the enum <code>IndicationResult</code> (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>, <a class="spec-record-ref" data-req="SWS_DM_00384" href="../spec/record.html?id=SWS_DM_00384">[SWS_DM_00384]</a>):
  <ul>
  <li><code>kIndicationOccupied</code>: The server or diagnostic session is currently busy (<a class="spec-record-ref" data-req="SWS_DM_00384" href="../spec/record.html?id=SWS_DM_00384">[SWS_DM_00384]</a>).</li>
  <li><code>kIndicationOverflow</code>: The transmitted message size exceeds the buffer capacity (<a class="spec-record-ref" data-req="SWS_DM_00384" href="../spec/record.html?id=SWS_DM_00384">[SWS_DM_00384]</a>).</li>
  <li><code>kIndicationUnknownTargetAddress</code>: The targeted destination address is not configured (<a class="spec-record-ref" data-req="SWS_DM_00384" href="../spec/record.html?id=SWS_DM_00384">[SWS_DM_00384]</a>).</li>
  </ul>
</li>
<li><strong>Cancellation of reception:</strong> If a connection abort or transmission error occurs after successful <code>IndicateMessage</code>, the handler calls <code>NotifyMessageFailure</code> (<a class="spec-record-ref" data-req="SWS_DM_00310" href="../spec/record.html?id=SWS_DM_00310">[SWS_DM_00310]</a>). The previously received <code>UdsMessage</code> object is returned to the DM without calling <code>HandleMessage</code> (<a class="spec-record-ref" data-req="SWS_DM_00310" href="../spec/record.html?id=SWS_DM_00310">[SWS_DM_00310]</a>).</li>
<li><strong>Transmit transmission error:</strong> If an outgoing message cannot be sent at the network level, the handler reports the result <code>TransmissionResult::kTransmitFailed</code> via <code>TransmitConfirmation</code> (<a class="spec-record-ref" data-req="SWS_DM_00312" href="../spec/record.html?id=SWS_DM_00312">[SWS_DM_00312]</a>, <a class="spec-record-ref" data-req="SWS_DM_00307" href="../spec/record.html?id=SWS_DM_00307">[SWS_DM_00307]</a>).</li>
