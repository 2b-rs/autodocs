<h4>EthIf as Intermediary Between Ethernet Users and Hardware Drivers</h4>
<p>The Ethernet Interface (EthIf) provides upper layers with uniform access to Ethernet controller, transceiver, and switch drivers. For switches, EthIf uses one or more Ethernet Switch Drivers <a class="spec-record-ref" data-req="SWS_EthIf_00228" href="../../spec/record.html?id=SWS_EthIf_00228">[SWS_EthIf_00228]</a>. Each access is forwarded via <code>EthIfSwitchIdx</code> to the responsible EthSwt driver with its <code>EthSwtIdx</code> <a class="spec-record-ref" data-req="SWS_EthIf_00224" href="../../spec/record.html?id=SWS_EthIf_00224">[SWS_EthIf_00224]</a>. For controllers, the same principle applies: The indexing diagram maps the contiguous EthIf controller index to the pair of driver and driver-local controller index <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-d08e28a2da25511f.html" data-snip="FIG-d08e28a2da25511f">SWS EthIf p. 18</a>.</p>
<p>EthIf manages the following hardware representations:</p>
<ul>
<li>physical controllers,</li>
<li>virtual <code>EthIfController</code>, such as for VLANs,</li>
<li>transceivers,</li>
<li>switches,</li>
<li>switch port groups.</li>
</ul>
<p>A <code>EthIfController</code> connects a physical controller with the hardware through which it communicates <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_7_1_10_Handling_of_maintained_Ethernet_hardware.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_7_1_10_Handling_of_maintained_Ethernet_hardware">SWS EthIf p. 31</a>. This representation originates from R24-11. R20-11 also uses the same terms, for example in <a class="spec-record-ref" data-req="SWS_EthIf_00264" href="../../spec/record.html?id=SWS_EthIf_00264">[SWS_EthIf_00264]</a> and <a class="spec-record-ref" data-req="SWS_EthIf_00266" href="../../spec/record.html?id=SWS_EthIf_00266">[SWS_EthIf_00266]</a>.</p>

<h4>Startup: From EthIf_Init to Active Controller</h4>
<p><code>EthIf_Init</code> receives a pointer to the implementation-specific configuration <a class="spec-record-ref" data-req="SWS_EthIf_00024" href="../../spec/record.html?id=SWS_EthIf_00024">[SWS_EthIf_00024]</a>. <code>EthIf_ConfigType</code> is defined as a post-build structure <a class="spec-record-ref" data-req="SWS_EthIf_00149" href="../../spec/record.html?id=SWS_EthIf_00149">[SWS_EthIf_00149]</a>. If development error detection is enabled, the services check whether <code>EthIf_Init</code> has already been called (e.g. <a class="spec-record-ref" data-req="SWS_EthIf_00155" href="../../spec/record.html?id=SWS_EthIf_00155">[SWS_EthIf_00155]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00273" href="../../spec/record.html?id=SWS_EthIf_00273">[SWS_EthIf_00273]</a>).</p>
<p>Communication is requested via <code>EthIf_SetControllerMode</code>, an asynchronous, non-reentrant service <a class="spec-record-ref" data-req="SWS_EthIf_00034" href="../../spec/record.html?id=SWS_EthIf_00034">[SWS_EthIf_00034]</a>. <code>EthIf_GetControllerMode</code> provides the current mode <a class="spec-record-ref" data-req="SWS_EthIf_00039" href="../../spec/record.html?id=SWS_EthIf_00039">[SWS_EthIf_00039]</a>. What EthIf does upon <code>ETH_MODE_ACTIVE</code> depends on the reference of <code>EthIfController</code>:</p>
<ul>
<li><strong>Transceiver in mode <code>ETH_MODE_DOWN</code>:</strong> EthIf calls, among others, <code>EthTrcv_SetTransceiverMode</code> with <code>ETH_MODE_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_EthIf_00266" href="../../spec/record.html?id=SWS_EthIf_00266">[SWS_EthIf_00266]</a>.</li>
<li><strong>Port group of type “control”:</strong> EthIf controls all ports of the group in a fixed order <a class="spec-record-ref" data-req="SWS_EthIf_00264" href="../../spec/record.html?id=SWS_EthIf_00264">[SWS_EthIf_00264]</a>.</li>
<li><strong>Switch:</strong> EthIf controls all ports of the switch (DRAFT) <a class="spec-record-ref" data-req="SWS_EthIf_00478" href="../../spec/record.html?id=SWS_EthIf_00478">[SWS_EthIf_00478]</a>.</li>
</ul>
<p><code>ETH_MODE_DOWN</code> acts in a mirror-image manner and affects only currently active hardware (<a class="spec-record-ref" data-req="SWS_EthIf_00484" href="../../spec/record.html?id=SWS_EthIf_00484">[SWS_EthIf_00484]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00485" href="../../spec/record.html?id=SWS_EthIf_00485">[SWS_EthIf_00485]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00265" href="../../spec/record.html?id=SWS_EthIf_00265">[SWS_EthIf_00265]</a>). For <code>ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST</code>, by contrast, EthIf forwards upon every call, regardless of the current mode (<a class="spec-record-ref" data-req="SWS_EthIf_00479" href="../../spec/record.html?id=SWS_EthIf_00479">[SWS_EthIf_00479]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00481" href="../../spec/record.html?id=SWS_EthIf_00481">[SWS_EthIf_00481]</a>).</p>
<p>The feedback arrives asynchronously:</p>
<ul>
<li><code>EthIf_CtrlModeIndication</code> follows a preceding <code>Eth_SetControllerMode</code> and may arrive directly within the triggering call <a class="spec-record-ref" data-req="SWS_EthIf_00231" href="../../spec/record.html?id=SWS_EthIf_00231">[SWS_EthIf_00231]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_4_3_EthIf_CtrlModeIndication.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_4_3_EthIf_CtrlModeIndication">SWS EthIf p. 154</a>. EthIf forwards it to EthSM via <code>EthSM_CtrlModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00252" href="../../spec/record.html?id=SWS_EthIf_00252">[SWS_EthIf_00252]</a>.</li>
<li>Transceivers report via <code>EthIf_TrcvModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00232" href="../../spec/record.html?id=SWS_EthIf_00232">[SWS_EthIf_00232]</a>.</li>
<li>For a switch port, EthIf derives from the EthSwtPort configuration whether the notification arrives from the transceiver or from the switch via <code>EthIf_SwitchPortModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_91055" href="../../spec/record.html?id=SWS_EthIf_91055">[SWS_EthIf_91055]</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_5_5_EthIf_SwitchPortModeIndication.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_5_5_EthIf_SwitchPortModeIndication">SWS EthIf p. 170</a>.</li>
</ul>

<h4>Transmitting and Receiving Frames</h4>
<p>Transmission proceeds in two steps:</p>
<ol>
<li><code>EthIf_ProvideTxBuffer</code> reserves a buffer with the responsible driver <a class="spec-record-ref" data-req="SWS_EthIf_00067" href="../../spec/record.html?id=SWS_EthIf_00067">[SWS_EthIf_00067]</a>.</li>
<li><code>EthIf_Transmit</code> initiates the transmission of the filled buffer <a class="spec-record-ref" data-req="SWS_EthIf_00075" href="../../spec/record.html?id=SWS_EthIf_00075">[SWS_EthIf_00075]</a>.</li>
</ol>
<p>The VLAN configuration alters parameter handling:</p>
<ul>
<li>Without configured <code>EthIfVlanID</code>, <code>FrameType</code> and <code>Priority</code> remain unused during buffer retrieval <a class="spec-record-ref" data-req="SWS_EthIf_00146" href="../../spec/record.html?id=SWS_EthIf_00146">[SWS_EthIf_00146]</a>.</li>
<li>With a configured VLAN ID, EthIf passes the value 0x8100 instead of <code>FrameType</code> during transmission <a class="spec-record-ref" data-req="SWS_EthIf_00250" href="../../spec/record.html?id=SWS_EthIf_00250">[SWS_EthIf_00250]</a>.</li>
</ul>
<p>Confirmations run via <code>EthIf_TxConfirmation</code>. Their <code>Result</code> is forwarded to <code>&lt;UL&gt;_TxConfirmation</code> (<a class="spec-record-ref" data-req="SWS_EthIf_00091" href="../../spec/record.html?id=SWS_EthIf_00091">[SWS_EthIf_00091]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00255" href="../../spec/record.html?id=SWS_EthIf_00255">[SWS_EthIf_00255]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00106" href="../../spec/record.html?id=SWS_EthIf_00106">[SWS_EthIf_00106]</a>). In polling mode, <code>EthIf_MainFunctionTx</code> generates the confirmations and additionally checks transceiver state changes <a class="spec-record-ref" data-req="SWS_EthIf_00113" href="../../spec/record.html?id=SWS_EthIf_00113">[SWS_EthIf_00113]</a>.</p>

<h4>Switch Ports, Port Groups, and Link State</h4>
<p>Port groups are addressed via the zero-based index <code>EthIf_SwitchPortGroupIdxType</code> <a class="spec-record-ref" data-req="SWS_EthIf_91101" href="../../spec/record.html?id=SWS_EthIf_91101">[SWS_EthIf_91101]</a>. <code>EthIf_SwitchPortGroupRequestMode</code> requests their mode asynchronously <a class="spec-record-ref" data-req="SWS_EthIf_91102" href="../../spec/record.html?id=SWS_EthIf_91102">[SWS_EthIf_91102]</a>:</p>
<ul>
<li><strong><code>ETH_MODE_ACTIVE</code>:</strong> EthIf connects the ports via <code>EthSwt_SetSwitchPortMode</code> and <code>EthSwt_PortLinkStateRequest</code> <a class="spec-record-ref" data-req="SWS_EthIf_00272" href="../../spec/record.html?id=SWS_EthIf_00272">[SWS_EthIf_00272]</a>.</li>
<li><strong><code>ETH_MODE_DOWN</code>:</strong> The timer <code>EthIfSwitchOffPortTimedelay</code> starts for a port only when all groups referencing the port have requested DOWN <a class="spec-record-ref" data-req="SWS_EthIf_00270" href="../../spec/record.html?id=SWS_EthIf_00270">[SWS_EthIf_00270]</a>. After expiry, <code>EthSwt_PortLinkStateRequest</code> with <code>ETHTRCV_LINK_STATE_DOWN</code> and <code>EthSwt_SetSwitchPortMode</code> with <code>ETH_MODE_DOWN</code> follow <a class="spec-record-ref" data-req="SWS_EthIf_00271" href="../../spec/record.html?id=SWS_EthIf_00271">[SWS_EthIf_00271]</a>.</li>
<li><strong>Repeated ACTIVE request while shutdown timer is running:</strong> <a class="spec-record-ref" data-req="SWS_EthIf_00483" href="../../spec/record.html?id=SWS_EthIf_00483">[SWS_EthIf_00483]</a> governs this case; presumably the timer is stopped.</li>
</ul>
<p><code>EthIf_StartAllPorts</code> activates all affected ports <a class="spec-record-ref" data-req="SWS_EthIf_00275" href="../../spec/record.html?id=SWS_EthIf_00275">[SWS_EthIf_00275]</a>. EthIf deactivates ports again that were not requested with ACTIVE by the expiry of <code>EthIfPortStartupActiveTime</code> <a class="spec-record-ref" data-req="SWS_EthIf_00276" href="../../spec/record.html?id=SWS_EthIf_00276">[SWS_EthIf_00276]</a>.</p>

<p>EthIf merges the link states of the hardware:</p>
<ul>
<li>Controllers without a transceiver are considered <code>ETHTRCV_LINK_STATE_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_EthIf_00229" href="../../spec/record.html?id=SWS_EthIf_00229">[SWS_EthIf_00229]</a>.</li>
<li>Upon every change, EthIf calls <code>&lt;User&gt;_TrcvLinkStateChg</code> for each affected controller <a class="spec-record-ref" data-req="SWS_EthIf_00230" href="../../spec/record.html?id=SWS_EthIf_00230">[SWS_EthIf_00230]</a>.</li>
<li>For switches without a port group, the state of the host port counts <a class="spec-record-ref" data-req="SWS_EthIf_00260" href="../../spec/record.html?id=SWS_EthIf_00260">[SWS_EthIf_00260]</a>.</li>
<li>For port groups, EthIf forms an accumulated state <a class="spec-record-ref" data-req="SWS_EthIf_00259" href="../../spec/record.html?id=SWS_EthIf_00259">[SWS_EthIf_00259]</a>. It is reported to EthSM <a class="spec-record-ref" data-req="SWS_EthIf_00262" href="../../spec/record.html?id=SWS_EthIf_00262">[SWS_EthIf_00262]</a> or, without an assigned controller, to BswM <a class="spec-record-ref" data-req="SWS_EthIf_00261" href="../../spec/record.html?id=SWS_EthIf_00261">[SWS_EthIf_00261]</a>.</li>
</ul>
<p><code>EthIf_MainFunctionState</code> polls <a class="spec-record-ref" data-req="SWS_EthIf_00407" href="../../spec/record.html?id=SWS_EthIf_00407">[SWS_EthIf_00407]</a> at the rate of <code>EthIfMainFunctionStatePeriod</code>. For active links, the function reads the signal quality (<a class="spec-record-ref" data-req="SWS_EthIf_00408" href="../../spec/record.html?id=SWS_EthIf_00408">[SWS_EthIf_00408]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00409" href="../../spec/record.html?id=SWS_EthIf_00409">[SWS_EthIf_00409]</a>). The current, highest, and lowest values since the last clear are stored <a class="spec-record-ref" data-req="SWS_EthIf_91057" href="../../spec/record.html?id=SWS_EthIf_91057">[SWS_EthIf_91057]</a>.</p>

<h4>Wake-up check and sleep indication</h4>
<p><code>EthIf_CheckWakeup</code> is asynchronous and reentrant. The service requests the affected hardware to check a signaled wake-up <a class="spec-record-ref" data-req="SWS_EthIf_00244" href="../../spec/record.html?id=SWS_EthIf_00244">[SWS_EthIf_00244]</a>. According to the specification, the integration code calls it <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_3_4_EthIf_CheckWakeup.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_3_4_EthIf_CheckWakeup">SWS EthIf p. 56</a>. EthIf forwards to:</p>
<ul>
<li><code>EthTrcv_CheckWakeup</code> of all affected transceivers <a class="spec-record-ref" data-req="SWS_EthIf_00245" href="../../spec/record.html?id=SWS_EthIf_00245">[SWS_EthIf_00245]</a>,</li>
<li><code>EthSwt_SwitchCheckWakeup</code> of all affected switches <a class="spec-record-ref" data-req="SWS_EthIf_00500" href="../../spec/record.html?id=SWS_EthIf_00500">[SWS_EthIf_00500]</a>.</li>
</ul>
<p>The service can be disabled via <code>EthIfWakeUpSupport</code> <a class="spec-record-ref" data-req="SWS_EthIf_00248" href="../../spec/record.html?id=SWS_EthIf_00248">[SWS_EthIf_00248]</a>.</p>
<p>Two services provide the wake-up reason (both DRAFT):</p>
<ul>
<li><code>EthIf_GetPhyWakeupReason</code> via <code>EthTrcv_GetBusWuReason</code> <a class="spec-record-ref" data-req="SWS_EthIf_00486" href="../../spec/record.html?id=SWS_EthIf_00486">[SWS_EthIf_00486]</a>,</li>
<li>for switch ports, the call of <code>EthSwt_GetSwitchPortWakeupReason</code> <a class="spec-record-ref" data-req="SWS_EthIf_00490" href="../../spec/record.html?id=SWS_EthIf_00490">[SWS_EthIf_00490]</a>.</li>
</ul>
<p>EthIf forwards sleep notifications via <code>EthIf_SleepIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_91006" href="../../spec/record.html?id=SWS_EthIf_91006">[SWS_EthIf_91006]</a> to <code>EthSM_SleepIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00497" href="../../spec/record.html?id=SWS_EthIf_00497">[SWS_EthIf_00497]</a>. <code>EthIf_SetTransceiverWakeupMode</code> and <code>EthIf_GetTransceiverWakeupMode</code> are obsolete in R20-11 (<a class="spec-record-ref" data-req="SWS_EthIf_00233" href="../../spec/record.html?id=SWS_EthIf_00233">[SWS_EthIf_00233]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00238" href="../../spec/record.html?id=SWS_EthIf_00238">[SWS_EthIf_00238]</a>).</p>

<h4>Diagnostic, timestamp, and wireless services as pass-throughs</h4>
<p>A large part of the API passes calls through to a driver:</p>
<ul>
<li><strong>To EthTrcv:</strong> test mode, loopback, cable diagnostics, and PHY identifier (<a class="spec-record-ref" data-req="SWS_EthIf_00324" href="../../spec/record.html?id=SWS_EthIf_00324">[SWS_EthIf_00324]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_91018" href="../../spec/record.html?id=SWS_EthIf_91018">[SWS_EthIf_91018]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_91014" href="../../spec/record.html?id=SWS_EthIf_91014">[SWS_EthIf_91014]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00334" href="../../spec/record.html?id=SWS_EthIf_00334">[SWS_EthIf_00334]</a>).</li>
<li><strong>To EthSwt:</strong> port mode, counters, statistics, port mirroring, and configuration data (<a class="spec-record-ref" data-req="SWS_EthIf_00415" href="../../spec/record.html?id=SWS_EthIf_00415">[SWS_EthIf_00415]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00432" href="../../spec/record.html?id=SWS_EthIf_00432">[SWS_EthIf_00432]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00436" href="../../spec/record.html?id=SWS_EthIf_00436">[SWS_EthIf_00436]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00448" href="../../spec/record.html?id=SWS_EthIf_00448">[SWS_EthIf_00448]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00454" href="../../spec/record.html?id=SWS_EthIf_00454">[SWS_EthIf_00454]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00468" href="../../spec/record.html?id=SWS_EthIf_00468">[SWS_EthIf_00468]</a>).</li>
</ul>
<p>Two services do more than pass through. <code>EthIf_RunPortCableDiagnostic</code> ensures that the associated <code>EthIfController</code> is in <code>ETH_MODE_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_EthIf_00464" href="../../spec/record.html?id=SWS_EthIf_00464">[SWS_EthIf_00464]</a>. <code>EthIf_GetPortMacAddr</code> queries all switch drivers and returns <code>E_NOT_OK</code> if no port or multiple ports match <a class="spec-record-ref" data-req="SWS_EthIf_00191" href="../../spec/record.html?id=SWS_EthIf_00191">[SWS_EthIf_00191]</a>.</p>
<p>Three services are available for time synchronization (<a class="spec-record-ref" data-req="SWS_EthIf_00160" href="../../spec/record.html?id=SWS_EthIf_00160">[SWS_EthIf_00160]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00166" href="../../spec/record.html?id=SWS_EthIf_00166">[SWS_EthIf_00166]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00172" href="../../spec/record.html?id=SWS_EthIf_00172">[SWS_EthIf_00172]</a>):</p>
<ul>
<li><code>EthIf_EnableEgressTimeStamp</code> activates egress timestamping of a transmit buffer.</li>
<li><code>EthIf_GetEgressTimeStamp</code> and <code>EthIf_GetIngressTimeStamp</code> read the timestamps.</li>
</ul>
<p>All three can be configured via <code>EthIfGlobalTimeSupport</code> (<a class="spec-record-ref" data-req="SWS_EthIf_00164" href="../../spec/record.html?id=SWS_EthIf_00164">[SWS_EthIf_00164]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00170" href="../../spec/record.html?id=SWS_EthIf_00170">[SWS_EthIf_00170]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00176" href="../../spec/record.html?id=SWS_EthIf_00176">[SWS_EthIf_00176]</a>). According to a passage from R23-11, the ingress query must occur within the Rx indication <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_3_25_EthIf_GetIngressTimeStamp.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_3_25_EthIf_GetIngressTimeStamp">SWS EthIf p. 76</a>. <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-cbcadeed7ab76217.html" data-snip="FIG-cbcadeed7ab76217">SWS TimeSync p. 55</a> shows the interaction with EthTSyn.</p>
<p>For switches, <code>EthIf_SetSwitchMgmtInfo</code> sets management information <a class="spec-record-ref" data-req="SWS_EthIf_91003" href="../../spec/record.html?id=SWS_EthIf_91003">[SWS_EthIf_91003]</a>. <code>EthIf_SwitchEnableTimeStamping</code> calls <code>EthSwt_PortEnableTimeStamp</code> for each port of the group <a class="spec-record-ref" data-req="SWS_EthIf_00387" href="../../spec/record.html?id=SWS_EthIf_00387">[SWS_EthIf_00387]</a>. This is enabled via <code>EthIfSwitchManagementSupport</code> <a class="spec-record-ref" data-req="SWS_EthIf_00279" href="../../spec/record.html?id=SWS_EthIf_00279">[SWS_EthIf_00279]</a>.</p>
<p>Differences from later releases:</p>
<ul>
<li><code>EthIf_GetCurrentTime</code> <a class="spec-record-ref" data-req="SWS_EthIf_00154" href="../../spec/record.html?id=SWS_EthIf_00154">[SWS_EthIf_00154]</a> is obsolete as of R23-11 <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_3_17_EthIf_GetCurrentTime.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_3_17_EthIf_GetCurrentTime">SWS EthIf p. 68</a>.</li>
<li>R25-11 addresses <code>EthIf_EnableEgressTimeStamp</code> via a <code>PduId</code> instead of via <code>CtrlIdx</code>/<code>BufIdx</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_4_6_3_EthIf_EnableEgressTimeStamp.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_4_6_3_EthIf_EnableEgressTimeStamp">SWS EthIf p. 155</a>.</li>
</ul>
<p>Wireless functions are enabled via <code>EthIfEnableWEthApi</code> <a class="spec-record-ref" data-req="SWS_EthIf_00340" href="../../spec/record.html?id=SWS_EthIf_00340">[SWS_EthIf_00340]</a> and forwarded to WEth or WEthTrcv (<a class="spec-record-ref" data-req="SWS_EthIf_00341" href="../../spec/record.html?id=SWS_EthIf_00341">[SWS_EthIf_00341]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00353" href="../../spec/record.html?id=SWS_EthIf_00353">[SWS_EthIf_00353]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00360" href="../../spec/record.html?id=SWS_EthIf_00360">[SWS_EthIf_00360]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00366" href="../../spec/record.html?id=SWS_EthIf_00366">[SWS_EthIf_00366]</a>). Many optional services can be disabled at compile time, for instance via <code>EthIfStoreConfigurationApi</code> <a class="spec-record-ref" data-req="SWS_EthIf_00216" href="../../spec/record.html?id=SWS_EthIf_00216">[SWS_EthIf_00216]</a> or <code>EthIfVerifyConfigApi</code> <a class="spec-record-ref" data-req="SWS_EthIf_00305" href="../../spec/record.html?id=SWS_EthIf_00305">[SWS_EthIf_00305]</a>.</p>

<h4>Behavior in the event of an error</h4>
<p><a class="spec-record-ref" data-req="SWS_EthIf_00017" href="../../spec/record.html?id=SWS_EthIf_00017">[SWS_EthIf_00017]</a> defines the development error codes, e.g., <code>ETHIF_E_INV_CTRL_IDX</code> (0x01) and <code>ETHIF_E_INV_TRCV_IDX</code> (0x02). A three-stage check is typical:</p>
<ol>
<li><strong>Initialization:</strong> <code>ETHIF_E_UNINIT</code>.</li>
<li><strong>Index:</strong> <code>ETHIF_E_INV_CTRL_IDX</code>, <code>ETHIF_E_INV_TRCV_IDX</code>, <code>ETHIF_E_INV_SWT_IDX</code>, <code>ETHIF_E_INV_PORT_IDX</code>.</li>
<li><strong>Pointer:</strong> <code>ETHIF_E_PARAM_POINTER</code>.</li>
</ol>
<p>Examples are the timestamp services (<a class="spec-record-ref" data-req="SWS_EthIf_00167" href="../../spec/record.html?id=SWS_EthIf_00167">[SWS_EthIf_00167]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00168" href="../../spec/record.html?id=SWS_EthIf_00168">[SWS_EthIf_00168]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00169" href="../../spec/record.html?id=SWS_EthIf_00169">[SWS_EthIf_00169]</a>) and the switch port wake-up reason query (<a class="spec-record-ref" data-req="SWS_EthIf_00491" href="../../spec/record.html?id=SWS_EthIf_00491">[SWS_EthIf_00491]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00492" href="../../spec/record.html?id=SWS_EthIf_00492">[SWS_EthIf_00492]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00493" href="../../spec/record.html?id=SWS_EthIf_00493">[SWS_EthIf_00493]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00494" href="../../spec/record.html?id=SWS_EthIf_00494">[SWS_EthIf_00494]</a>). For many services, it explicitly applies: if DET is disabled, the function returns <code>E_NOT_OK</code> instead (<a class="spec-record-ref" data-req="SWS_EthIf_00325" href="../../spec/record.html?id=SWS_EthIf_00325">[SWS_EthIf_00325]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00326" href="../../spec/record.html?id=SWS_EthIf_00326">[SWS_EthIf_00326]</a>).</p>
<p>Two special cases in error detection:</p>
<ul>
<li><code>EthIf_SwitchPortGroupRequestMode</code> rejects port groups that are assigned to a <code>EthIfController</code>. The service then reports <code>ETHIF_E_INV_PORT_GROUP_IDX</code> and returns <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_EthIf_00274" href="../../spec/record.html?id=SWS_EthIf_00274">[SWS_EthIf_00274]</a>.</li>
<li><a class="spec-record-ref" data-req="SWS_EthIf_00319" href="../../spec/record.html?id=SWS_EthIf_00319">[SWS_EthIf_00319]</a> deviantly specifies the error code <code>ETHIF_E_NOTINIT</code>.</li>
</ul>
<p>In the receive path, EthIf discards invalid frames:</p>
<ul>
<li>Frames with an invalid CtrlIdx/VLAN are counted by measurement index <code>ETHIF_MEAS_DROP_CRTLIDX</code>. If the VLAN is not active, all VLAN-tagged frames are also counted (<a class="spec-record-ref" data-req="SWS_EthIf_00309" href="../../spec/record.html?id=SWS_EthIf_00309">[SWS_EthIf_00309]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00317" href="../../spec/record.html?id=SWS_EthIf_00317">[SWS_EthIf_00317]</a>).</li>
<li>If <code>EthIfEnableSecurityEventReporting</code> is set, EthIf reports security events to the IdsM, such as <code>ETHIF_SEV_DROP_INV_VLAN</code> (<a class="spec-record-ref" data-req="SWS_EthIf_00502" href="../../spec/record.html?id=SWS_EthIf_00502">[SWS_EthIf_00502]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00503" href="../../spec/record.html?id=SWS_EthIf_00503">[SWS_EthIf_00503]</a>).</li>
</ul>
<p><code>EthIf_GetAndResetMeasurementData</code> reads the counters <a class="spec-record-ref" data-req="SWS_EthIf_91011" href="../../spec/record.html?id=SWS_EthIf_91011">[SWS_EthIf_91011]</a>.
