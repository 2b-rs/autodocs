<p class="ai-level ai-oneliner-lead" data-ai-level="1">Vermittelt Frames, Moduswechsel und Link-Zustände zwischen Ethernet-Treibern, Switches und dem Kommunikationsstack.</p>
<div class="ai-level" data-ai-level="2">
<p>Das Ethernet Interface vermittelt zwischen EthSM und Upper Layern auf der einen Seite und den Treibern für Controller, Transceiver und Switches auf der anderen. Über das asynchrone <code>EthIf_SetControllerMode</code> schaltet es Controller samt referenzierter Hardware <a class="spec-record-ref" data-req="SWS_EthIf_00034" href="../../spec/record.html?id=SWS_EthIf_00034">[SWS_EthIf_00034]</a>. Es sendet Frames in zwei Schritten, verteilt Empfangsindikationen und meldet Linkzustände an EthSM oder BswM. Port-Gruppen schaltet es verzögert ab, Wake-up-Prüfungen leitet es an Transceiver und Switches weiter. Wichtigste Randbedingung: Bei aktivierter Fehlererkennung setzt fast jeder Dienst ein vorheriges <code>EthIf_Init</code> voraus, andernfalls wird <code>ETHIF_E_UNINIT</code> gemeldet <a class="spec-record-ref" data-req="SWS_EthIf_00155" href="../../spec/record.html?id=SWS_EthIf_00155">[SWS_EthIf_00155]</a>.</p>

</div>
<div class="ai-level" data-ai-level="3">
<p>Das Ethernet Interface verbindet die Nutzer des Ethernet-Stacks mit den Treibern für Controller, Transceiver und Switches. Auf Switches greift es über einen oder mehrere Ethernet Switch Driver zu <a class="spec-record-ref" data-req="SWS_EthIf_00228" href="../../spec/record.html?id=SWS_EthIf_00228">[SWS_EthIf_00228]</a>. Nach oben steuert der EthSM die Controller-Modi und erhält Modus- und Linkmeldungen <a class="spec-record-ref" data-req="SWS_EthIf_00252" href="../../spec/record.html?id=SWS_EthIf_00252">[SWS_EthIf_00252]</a>. Der BswM erhält die Linkzustände eigenständiger Port-Gruppen <a class="spec-record-ref" data-req="SWS_EthIf_00261" href="../../spec/record.html?id=SWS_EthIf_00261">[SWS_EthIf_00261]</a>.</p>

<h4>Rolle von EthIf zwischen Ethernet-Treibern und Kommunikationsstack</h4>
<p>Das Ethernet Interface ist die hardwareunabhängige Vermittlungsschicht zwischen den Nutzern des Ethernet-Stacks und den Treibern für Controller (Eth), Transceiver (EthTrcv) und Switches (EthSwt). Für Switches nutzt EthIf einen oder mehrere Ethernet Switch Driver, welche die Eigenheiten der jeweiligen Hardware kapseln <a class="spec-record-ref" data-req="SWS_EthIf_00228" href="../../spec/record.html?id=SWS_EthIf_00228">[SWS_EthIf_00228]</a>. Zugriffe über <code>EthIfSwitchIdx</code> verteilt EthIf an das zuständige EthSwt-Modul mit dessen <code>EthSwtIdx</code> <a class="spec-record-ref" data-req="SWS_EthIf_00224" href="../../spec/record.html?id=SWS_EthIf_00224">[SWS_EthIf_00224]</a>. Mit <code>EthIfEnableWEthApi</code> kommen drahtlose Controller- und Transceiver-Treiber hinzu <a class="spec-record-ref" data-req="SWS_EthIf_00340" href="../../spec/record.html?id=SWS_EthIf_00340">[SWS_EthIf_00340]</a>. Die Schichtung zeigen die Schaubilder <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-c5df8468b5047636.html" data-snip="FIG-c5df8468b5047636">EthSwt-SWS S. 5</a> und <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-be76e19dad708101.html" data-snip="FIG-be76e19dad708101">Eth-SWS S. 18</a>.</p>
<p>Nach oben arbeitet EthIf mit mehreren Partnern zusammen:</p>
<ul>
<li>Der EthSM steuert die Controller-Modi und erhält Modus- und Linkmeldungen <a class="spec-record-ref" data-req="SWS_EthIf_00252" href="../../spec/record.html?id=SWS_EthIf_00252">[SWS_EthIf_00252]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00262" href="../../spec/record.html?id=SWS_EthIf_00262">[SWS_EthIf_00262]</a>.</li>
<li>Der BswM erhält die Linkzustände von Port-Gruppen ohne Controllerbezug <a class="spec-record-ref" data-req="SWS_EthIf_00261" href="../../spec/record.html?id=SWS_EthIf_00261">[SWS_EthIf_00261]</a>.</li>
<li>Upper Layer senden Frames und erhalten Empfangsindikationen sowie Sendebestätigungen <a class="spec-record-ref" data-req="SWS_EthIf_00104" href="../../spec/record.html?id=SWS_EthIf_00104">[SWS_EthIf_00104]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00106" href="../../spec/record.html?id=SWS_EthIf_00106">[SWS_EthIf_00106]</a>.</li>
<li>Der Integration Code stößt Wake-up-Prüfungen über <code>EthIf_CheckWakeup</code> an <a class="spec-record-ref" data-req="SWS_EthIf_00244" href="../../spec/record.html?id=SWS_EthIf_00244">[SWS_EthIf_00244]</a>.</li>
</ul>

<p><code>EthIf_Init</code> <a class="spec-record-ref" data-req="SWS_EthIf_00024" href="../../spec/record.html?id=SWS_EthIf_00024">[SWS_EthIf_00024]</a> übernimmt eine implementierungsspezifische Post-Build-Struktur vom Typ <code>EthIf_ConfigType</code> <a class="spec-record-ref" data-req="SWS_EthIf_00149" href="../../spec/record.html?id=SWS_EthIf_00149">[SWS_EthIf_00149]</a>. Fast alle Dienste prüfen bei aktivierter Fehlererkennung, ob die Initialisierung erfolgt ist. Andernfalls melden sie <code>ETHIF_E_UNINIT</code>, etwa nach <a class="spec-record-ref" data-req="SWS_EthIf_00155" href="../../spec/record.html?id=SWS_EthIf_00155">[SWS_EthIf_00155]</a> oder <a class="spec-record-ref" data-req="SWS_EthIf_00273" href="../../spec/record.html?id=SWS_EthIf_00273">[SWS_EthIf_00273]</a>.</p>
<p>Den Kommunikationsstart löst <code>EthIf_SetControllerMode</code> aus; der Dienst arbeitet asynchron <a class="spec-record-ref" data-req="SWS_EthIf_00034" href="../../spec/record.html?id=SWS_EthIf_00034">[SWS_EthIf_00034]</a>. EthIf schaltet dabei die referenzierte Hardware mit:</p>
<ul>
<li>Steht ein referenzierter EthIfTransceiver auf <code>ETH_MODE_DOWN</code>, folgen <code>EthTrcv_SetTransceiverMode</code> und weitere Aufrufe in fester Reihenfolge <a class="spec-record-ref" data-req="SWS_EthIf_00266" href="../../spec/record.html?id=SWS_EthIf_00266">[SWS_EthIf_00266]</a>.</li>
<li>Bei einer Port-Gruppe vom Typ „control“ werden deren Ports geschaltet <a class="spec-record-ref" data-req="SWS_EthIf_00264" href="../../spec/record.html?id=SWS_EthIf_00264">[SWS_EthIf_00264]</a>.</li>
<li>Bei direktem Switch-Bezug werden alle Ports des Switches geschaltet (DRAFT) <a class="spec-record-ref" data-req="SWS_EthIf_00478" href="../../spec/record.html?id=SWS_EthIf_00478">[SWS_EthIf_00478]</a>.</li>
</ul>
<p>Controller und übrige Hardware werden unabhängig voneinander gesteuert <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_7_1_9_2_Switching_of_EthIfController_and_the_corresponding_Ethernet_hardware.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_7_1_9_2_Switching_of_EthIfController_and_the_corresponding_Ethernet_hardware">EthIf-SWS S. 30</a>. Die Rückmeldung kommt asynchron: Der Treiber ruft <code>EthIf_CtrlModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00231" href="../../spec/record.html?id=SWS_EthIf_00231">[SWS_EthIf_00231]</a>, und EthIf meldet weiter an <code>EthSM_CtrlModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00252" href="../../spec/record.html?id=SWS_EthIf_00252">[SWS_EthIf_00252]</a>. Transceiver melden über <code>EthIf_TrcvModeIndication</code> <a class="spec-record-ref" data-req="SWS_EthIf_00232" href="../../spec/record.html?id=SWS_EthIf_00232">[SWS_EthIf_00232]</a>.</p>
<p>Beim Abschalten mit <code>ETH_MODE_DOWN</code> fährt EthIf nur aktive Transceiver bzw. Switch-Ports herunter <a class="spec-record-ref" data-req="SWS_EthIf_00484" href="../../spec/record.html?id=SWS_EthIf_00484">[SWS_EthIf_00484]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00485" href="../../spec/record.html?id=SWS_EthIf_00485">[SWS_EthIf_00485]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00265" href="../../spec/record.html?id=SWS_EthIf_00265">[SWS_EthIf_00265]</a>. <code>ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST</code> leitet EthIf dagegen bei jedem Aufruf weiter, unabhängig vom aktuellen Modus <a class="spec-record-ref" data-req="SWS_EthIf_00479" href="../../spec/record.html?id=SWS_EthIf_00479">[SWS_EthIf_00479]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00480" href="../../spec/record.html?id=SWS_EthIf_00480">[SWS_EthIf_00480]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00481" href="../../spec/record.html?id=SWS_EthIf_00481">[SWS_EthIf_00481]</a>. Ältere Regeln zum Switch-Shutdown sind in R20-11 OBSOLETE <a class="spec-record-ref" data-req="SWS_EthIf_00256" href="../../spec/record.html?id=SWS_EthIf_00256">[SWS_EthIf_00256]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00257" href="../../spec/record.html?id=SWS_EthIf_00257">[SWS_EthIf_00257]</a>.</p>

<h4>Frames senden und empfangen: Puffer, VLAN und Bestätigungen</h4>
<p>Senden erfolgt in zwei Schritten:</p>
<ol>
<li><code>EthIf_ProvideTxBuffer</code> <a class="spec-record-ref" data-req="SWS_EthIf_00067" href="../../spec/record.html?id=SWS_EthIf_00067">[SWS_EthIf_00067]</a> liefert Pufferindex und Pufferzeiger. Ohne konfigurierte <code>EthIfVlanID</code> bleiben <code>FrameType</code> und <code>Priority</code> unbenutzt <a class="spec-record-ref" data-req="SWS_EthIf_00146" href="../../spec/record.html?id=SWS_EthIf_00146">[SWS_EthIf_00146]</a>.</li>
<li><code>EthIf_Transmit</code> <a class="spec-record-ref" data-req="SWS_EthIf_00075" href="../../spec/record.html?id=SWS_EthIf_00075">[SWS_EthIf_00075]</a> stößt das Senden des gefüllten Puffers an. Bei VLAN-Controllern übergibt EthIf statt des FrameType den Wert <code>0x8100</code> an <code>Eth_Transmit</code> <a class="spec-record-ref" data-req="SWS_EthIf_00250" href="../../spec/record.html?id=SWS_EthIf_00250">[SWS_EthIf_00250]</a>.</li>
</ol>
<p>Die Dokumentstelle aus R23-11 ergänzt eine Bedingung: Weitergeleitet wird nur, wenn der zuletzt akzeptierte Modus <code>ETH_MODE_ACTIVE</code> oder <code>ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST</code> ist <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_3_51_EthIf_Transmit.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_3_51_EthIf_Transmit">EthIf-SWS S. 101</a>. Silent Communication per <code>ETH_MODE_TX_OFFLINE</code> ist erst dort beschrieben <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_7_1_10_Communication_control.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_7_1_10_Communication_control">EthIf-SWS S. 34</a>. Sie gehört nicht zu den R20-11-Requirements im Payload.</p>
<p><code>EthIf_TxConfirmation</code> <a class="spec-record-ref" data-req="SWS_EthIf_00091" href="../../spec/record.html?id=SWS_EthIf_00091">[SWS_EthIf_00091]</a> reicht das Ergebnis über <code>&lt;UL&gt;_TxConfirmation</code> an den Upper Layer durch <a class="spec-record-ref" data-req="SWS_EthIf_00255" href="../../spec/record.html?id=SWS_EthIf_00255">[SWS_EthIf_00255]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00106" href="../../spec/record.html?id=SWS_EthIf_00106">[SWS_EthIf_00106]</a>. Im Polling-Modus erzeugt <code>EthIf_MainFunctionTx</code> die Bestätigungen und prüft zusätzlich Zustandswechsel der Transceiver <a class="spec-record-ref" data-req="SWS_EthIf_00113" href="../../spec/record.html?id=SWS_EthIf_00113">[SWS_EthIf_00113]</a>. Im Interrupt-Modus ruft die ISR des Treibers direkt zurück <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-398a026bccb0cfe2.html" data-snip="FIG-398a026bccb0cfe2">EthIf-SWS S. 88</a>. Die PDU-basierte Signatur von <code>EthIf_Transmit</code> ab R24-11 <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_4_1_13_EthIf_Transmit.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_4_1_13_EthIf_Transmit">EthIf-SWS S. 97</a> gilt für R20-11 nicht.</p>

<h4>Link-Zustand, Port-Gruppen und Signalqualität</h4>
<p>Controller ohne Transceiver-Referenz verhalten sich so, als wäre der Link <code>ETHTRCV_LINK_STATE_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_EthIf_00229" href="../../spec/record.html?id=SWS_EthIf_00229">[SWS_EthIf_00229]</a>. Ändert sich der Link, ruft EthIf für jeden betroffenen EthIfController <code>&lt;User&gt;_TrcvLinkStateChg</code> auf <a class="spec-record-ref" data-req="SWS_EthIf_00230" href="../../spec/record.html?id=SWS_EthIf_00230">[SWS_EthIf_00230]</a>, <a class="spec-record-ref" data-req="SWS_EthIf_00108" href="../../spec/record.html?id=SWS_EthIf_00108">[SWS_EthIf_00108]</a>. Ohne Port-Gruppe meldet EthIf den Zustand des Host-Ports an den EthSM <a class="spec-record-ref" data-req="SWS_EthIf_00260" href="../../spec/record.html?id=SWS_EthIf_00260">[SWS_EthIf_00260]</a>.</p>
<p>Bei Port-Gruppen akkumuliert EthIf den Zustand über die Ports. <code>ETHTRCV_LINK_STATE_DOWN</code> gilt beispielsweise, wenn ein Host- oder Uplink-Port down ist <a class="spec-record-ref" data-req="SWS_EthIf_00259" href="../../spec/record.html?id=SWS_EthIf_00259">[SWS_EthIf_00259]</a>. Das Ergebnis geht an den EthSM, wenn die Gruppe einem Controller zugeordnet ist <a class="spec-record-ref" data-req="SWS_EthIf_00262" href="../../spec/record.html?id=SWS_EthIf_00262">[SWS_EthIf_00262]</a>, sonst an den BswM <a class="spec-record-ref" data-req="SWS_EthIf_00261" href="../../spec/record.html?id=SWS_EthIf_00261">[SWS_EthIf_00261]</a>.</p>
<p>Die Abfrage erfolgt zyklisch in <code>EthIf_MainFunctionState</code> <a class="spec-record-ref" data-req="SWS_EthIf_91104" href="../../spec/record.html?id=SWS_EthIf_91104">[SWS_EthIf_91104]</a> mit der Periode <code>EthIfMainFunctionStatePeriod</code> <a class="spec-record-ref" data-req="SWS_EthIf_00407" href="../../spec/record.html?id=SWS_EthIf_00407">[SWS_EthIf_00407]</a>. Fehlt dieser Parameter, übernimmt laut Schaubild <code>EthIf_MainFunctionRx</code> die Abfrage <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-e9cc4258f9d6866c.html" data-snip="FIG-e9cc4258f9d6866c">EthIf-SWS S. 89</a>.</p>
<p>Für aktive Links pollt EthIf zusätzlich die Signalqualität, und zwar über <code>EthSwt_GetPortSignalQuality</code> <a class="spec-record-ref" data-req="SWS_EthIf_00408" href="../../spec/record.html?id=SWS_EthIf_00408">[SWS_EthIf_00408]</a> bzw. <code>EthTrcv_GetPhySignalQuality</code> <a class="spec-record-ref" data-req="SWS_EthIf_00409" href="../../spec/record.html?id=SWS_EthIf_00409">[SWS_EthIf_00409]</a>. Aktueller, höchster und niedrigster Wert liegen in <code>EthIf_SignalQualityResultType</code> <a class="spec-record-ref" data-req="SWS_EthIf_91057" href="../../spec/record.html?id=SWS_EthIf_91057">[SWS_EthIf_91057]</a>. Gelesen werden sie über <a class="spec-record-ref" data-req="SWS_EthIf_91056" href="../../spec/record.html?id=SWS_EthIf_91056">[SWS_EthIf_91056]</a>, zurückgesetzt über <a class="spec-record-ref" data-req="SWS_EthIf_00400" href="../../spec/record.html?id=SWS_EthIf_00400">[SWS_EthIf_00400]</a> und <a class="spec-record-ref" data-req="SWS_EthIf_00404" href="../../spec/record.html?id=SWS_EthIf_00404">[SWS_EthIf_00404]</a>. Die Regel zur Aktualisierung beschreibt <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ETHIF_SECTION_8_6_5_EthIf_MainFunctionState.html" data-snip="SNIP_CLASSIC_ETHIF_SECTION_8_6_5_EthIf_MainFunctionState">EthIf-SWS S. 176</a>.</p>
