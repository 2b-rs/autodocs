<p>Die Methode <code>Write</code> der Klasse <code>ara::diag::GenericDataIdentifier</code> wird vom Diagnostic Management aufgerufen, sobald eine UDS-Anfrage des Dienstes <code>WriteDataByIdentifier</code> (0x2E) empfangen wird <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>. Voraussetzung für den Aufruf ist, dass der angeforderte Datenbezeichner unterstützt wird und die jeweilige Diagnose-Session sowie Sicherheitsstufe die Ausführung gestatten <a class="spec-record-ref" data-req="SWS_DM_00186" href="../spec/record.html?id=SWS_DM_00186">[SWS_DM_00186]</a>, <a class="spec-record-ref" data-req="SWS_DM_00415" href="../spec/record.html?id=SWS_DM_00415">[SWS_DM_00415]</a>, <a class="spec-record-ref" data-req="SWS_DM_00416" href="../spec/record.html?id=SWS_DM_00416">[SWS_DM_00416]</a>.</p>
<p>Der Aufruf erfolgt mit folgenden Parametern <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>:</p>
<ul>
<li><code>dataIdentifier</code>: Die 16-Bit-Kennung des zu schreibenden Datenbezeichners.</li>
<li><code>requestData</code>: Ein <code>ara::core::Span</code> mit den Rohdaten der Anfrage ohne DID-Präfix. Der Puffer bleibt gültig, bis das zugehörige Promise erfüllt oder die Bearbeitung abgebrochen wird.</li>
<li><code>metaInfo</code>: Zusätzliche Metadaten zur Diagnoseanforderung.</li>
<li><code>cancellationHandler</code>: Dient der Überwachung eines vorzeitigen Abbruchs der Konversation per <code>IsCanceled</code> sowie der Registrierung einer Abbruchbenachrichtigung über <code>SetNotifier</code>.</li>
</ul>
<p>Die Ausführung erfolgt asynchron und gibt ein <code>ara::core::Future&lt;void&gt;</code> zurück <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>. Bei erfolgreicher Verarbeitung wird das Promise mit <code>void</code> für eine positive Antwortnachricht erfüllt. Tritt ein Fehler auf, ist das Future mit einem passenden negativen UDS-Rückgabewert (NRC) gemäß ISO 14229-1 über <code>DiagUdsNrcErrc</code> abzuschließen <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>. Die Methode ist als <code>noexcept</code> deklariert und muss ausnahmesicher implementiert werden <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit ist die Thread-Sicherheit bedingt: Ob <code>Write</code> threadsicher implementiert werden muss, hängt vom <code>ConcurrencyType</code> ab, der bei der Instanziierung im Konstruktor übergeben wurde <a class="spec-record-ref" data-req="SWS_DM_00637" href="../spec/record.html?id=SWS_DM_00637">[SWS_DM_00637]</a>. Eine parallele Ausführung von Lese- und Schreibzugriffen wird über das Flag <code>readWrite</code> gesteuert <a class="spec-record-ref" data-req="SWS_DM_00939" href="../spec/record.html?id=SWS_DM_00939">[SWS_DM_00939]</a>.</p>
