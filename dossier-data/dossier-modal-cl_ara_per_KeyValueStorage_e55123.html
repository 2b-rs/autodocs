<h4>Context</h4>
<p>The class <code>ara::per::KeyValueStorage</code> provides a persistent key-value storage within the AUTOSAR Adaptive Platform. Its primary responsibility is the encapsulation and management of a set of unique keys with their respective assigned data values. The class acts as a transactional interface between user processes and the physical storage medium. Read and write operations are executed decoupled via transactional semantics so that modifications are permanently committed to physical storage only through an explicit synchronization step <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</p>

<h4>Lifecycle</h4>
<p>Instances of <code>ara::per::KeyValueStorage</code> are subject to strict ownership and lifecycle rules. Both the default constructor <a class="spec-record-ref" data-req="SWS_PER_00459" href="../spec/record.html?id=SWS_PER_00459">[SWS_PER_00459]</a> and copy and move constructors <a class="spec-record-ref" data-req="SWS_PER_00324" href="../spec/record.html?id=SWS_PER_00324">[SWS_PER_00324]</a>, <a class="spec-record-ref" data-req="SWS_PER_00322" href="../spec/record.html?id=SWS_PER_00322">[SWS_PER_00322]</a> as well as the assignment operators <a class="spec-record-ref" data-req="SWS_PER_00325" href="../spec/record.html?id=SWS_PER_00325">[SWS_PER_00325]</a>, <a class="spec-record-ref" data-req="SWS_PER_00323" href="../spec/record.html?id=SWS_PER_00323">[SWS_PER_00323]</a> are specified as deleted (<code>=delete</code>). Object creation is performed via the function <code>OpenKeyValueStorage()</code> <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a>. Presumably, instance management is handled by the caller via pointer-based ownership structures such as smart pointers.</p>
<p>During operation, the class is designed to be thread-safe: all functional interfaces can be called in parallel from multiple threads, whereby concurrent calls may lead to mutual delays <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>. Upon destruction via the destructor <a class="spec-record-ref" data-req="SWS_PER_00050" href="../spec/record.html?id=SWS_PER_00050">[SWS_PER_00050]</a>, this protection ends: the destructor itself is explicitly specified as not thread-safe and requires coordinated release without concurrent accesses.</p>

<h4>Usage Path</h4>
<p>A typical usage path comprises the validation of existing keys, setting or updating values, and final persistent storage:</p>
<ol>
<li><strong>Check and query:</strong> Before an update, the presence of a key can be checked using <code>KeyExists</code> <a class="spec-record-ref" data-req="SWS_PER_00043" href="../spec/record.html?id=SWS_PER_00043">[SWS_PER_00043]</a>. Already existing keys can be listed with <code>GetAllKeys</code> <a class="spec-record-ref" data-req="SWS_PER_00042" href="../spec/record.html?id=SWS_PER_00042">[SWS_PER_00042]</a>, their byte size determined via <code>GetCurrentValueSize</code> <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a>, or their content read in via <code>GetValue</code> <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>, <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>.</li>
<li><strong>Transactional writing:</strong> Values are stored in a typed manner or overwritten via <code>SetValue</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>. Similarly, <code>RemoveKey</code> <a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a> or <code>RemoveAllKeys</code> <a class="spec-record-ref" data-req="SWS_PER_00048" href="../spec/record.html?id=SWS_PER_00048">[SWS_PER_00048]</a> remove entries. All changes initially take effect only within the running transaction.</li>
<li><strong>Completion or discarding:</strong> Calling <code>SyncToStorage</code> <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a> writes all pending changes permanently to physical storage. If unsaved modifications since the last sync or open are to be reverted, <code>DiscardPendingChanges</code> <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a> serves this purpose. In case of defects or misconfigurations, keys can be reset to the configured initial value via <code>ResetKey</code> <a class="spec-record-ref" data-req="SWS_PER_00426" href="../spec/record.html?id=SWS_PER_00426">[SWS_PER_00426]</a> or recovered via <code>RecoverKey</code> <a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a> after integrity errors.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Methods of <code>KeyValueStorage</code> signal errors via <code>ara::core::Result</code> with specific error codes from <code>PerErrc</code>:</p>
<ul>
<li><strong>Key and type errors:</strong> If a caller attempts to access non-existent entries, <code>GetValue</code>, <code>GetCurrentValueSize</code>, <code>RemoveKey</code>, and <code>RecoverKey</code> return the error <code>PerErrc::kKeyNotFound</code> <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>, <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a>, <a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a>, <a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a>. If the template data type in <code>SetValue</code> or <code>GetValue</code> does not match the stored type, the API acknowledges this with <code>PerErrc::kDataTypeMismatch</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>. If no initial value exists for a key, <code>ResetKey</code> returns the code <code>PerErrc::kInitValueNotAvailable</code> <a class="spec-record-ref" data-req="SWS_PER_00426" href="../spec/record.html?id=SWS_PER_00426">[SWS_PER_00426]</a>.</li>
<li><strong>Access and capacity limits:</strong> If a storage is write-protected or configured as <code>write-only-once</code> and the key already exists, every write operation (such as <code>SetValue</code>, <code>RemoveKey</code>, <code>SyncToStorage</code>) results in <code>PerErrc::kIllegalWriteAccess</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>. Exceeding the storage volume leads to <code>PerErrc::kOutOfStorageSpace</code> or, when reaching the configured limit, to <code>PerErrc::kQuotaExceeded</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</li>
<li><strong>Hardware, integrity, and security errors:</strong> A failure of the storage medium manifests as <code>PerErrc::kPhysicalStorageFailure</code>. If checksums, validations, encryption or decryption, or MAC checks fail, the operations report <code>PerErrc::kIntegrityCorrupted</code>, <code>PerErrc::kValidationFailed</code>, <code>PerErrc::kEncryptionFailed</code>, or <code>PerErrc::kAuthenticationFailed</code>, respectively, <a class="spec-record-ref" data-req="SWS_PER_00042" href="../spec/record.html?id=SWS_PER_00042">[SWS_PER_00042]</a>, <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</li>
</ul>
