Instanzen sind weder kopier- noch verschiebbar und bieten threadsichere Zugriffsmethoden, erfordern beim Zerstören jedoch den Ausschluss nebenläufiger Aufrufe <a class="spec-record-ref" data-req="SWS_PER_00322" href="../spec/record.html?id=SWS_PER_00322">[SWS_PER_00322]</a>, <a class="spec-record-ref" data-req="SWS_PER_00050" href="../spec/record.html?id=SWS_PER_00050">[SWS_PER_00050]</a>. Bei Hardwaredefekten während der Synchronisation greift keine automatische Rollback-Semantik mehr <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</p>

<h4>Kontext</h4>
<p>Die Klasse <code>ara::per::KeyValueStorage</code> stellt einen typisierten Schlüssel-Wert-Speicher innerhalb der AUTOSAR Adaptive Plattform bereit, der persistente Daten als Menge von Schlüsseln mit zugeordneten Werten verwaltet. Sie dient Anwendungen als primäre Schnittstelle zur persistenten Ablage und zum Abruf konfigurierter Anwendungsdaten. Zugriffe erfolgen mit Transaktionssemantik über einen internen Transaktionszustand statt direkt auf dem physischen Speichermedium, wie etwa für Leseoperationen in <a class="spec-record-ref" data-req="SWS_PER_00042" href="../spec/record.html?id=SWS_PER_00042">[SWS_PER_00042]</a>, <a class="spec-record-ref" data-req="SWS_PER_00043" href="../spec/record.html?id=SWS_PER_00043">[SWS_PER_00043]</a>, <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>, <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a> und <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a> spezifiziert ist. Modifizierende Operationen wirken sich zunächst rein transaktional aus und verändern den physischen Speicher erst bei einer expliziten Synchronisation <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a>, <a class="spec-record-ref" data-req="SWS_PER_00048" href="../spec/record.html?id=SWS_PER_00048">[SWS_PER_00048]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung und Eigentümerschaft von <code>ara::per::KeyValueStorage</code> unterliegt strengen Einschränkungen: Sowohl der Standardkonstruktor <a class="spec-record-ref" data-req="SWS_PER_00459" href="../spec/record.html?id=SWS_PER_00459">[SWS_PER_00459]</a> als auch der Kopier- und der Move-Konstruktor <a class="spec-record-ref" data-req="SWS_PER_00324" href="../spec/record.html?id=SWS_PER_00324">[SWS_PER_00324]</a>, <a class="spec-record-ref" data-req="SWS_PER_00322" href="../spec/record.html?id=SWS_PER_00322">[SWS_PER_00322]</a> sind gelöscht (<code>=delete</code>). Ebenso sind Kopier- und Move-Zuweisungsoperatoren explizit entfernt <a class="spec-record-ref" data-req="SWS_PER_00325" href="../spec/record.html?id=SWS_PER_00325">[SWS_PER_00325]</a>, <a class="spec-record-ref" data-req="SWS_PER_00323" href="../spec/record.html?id=SWS_PER_00323">[SWS_PER_00323]</a>. Instanzen können somit weder kopiert noch verschoben werden. Die Erzeugung eines Speicherobjekts erfolgt über die Initialisierung via <code>OpenKeyValueStorage()</code>, welche zugleich den Ausgangspunkt für anstehende Änderungen definiert <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a>. Der Destruktor <a class="spec-record-ref" data-req="SWS_PER_00050" href="../spec/record.html?id=SWS_PER_00050">[SWS_PER_00050]</a> ist als ausnahmesicher, jedoch explizit als nicht threadsicher spezifiziert; die Zerstörung darf daher erst stattfinden, wenn keine parallelen Zugriffe mehr laufen. Im regulären Betrieb sind sämtliche Zugriffsmethoden threadsicher ausgelegt, können sich jedoch bei gleichzeitigen Schreib- oder Synchronisationsaufrufen anderer Threads verzögern <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>, <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad umfasst das Setzen oder Aktualisieren von Datenwerten, optionales Prüfen oder Lesen des aktuellen Transaktionsstands und das abschließende persistente Schreiben oder Verwerfen der Änderungen. Mit <code>SetValue&lt;T&gt;()</code> wird ein Schlüssel-Wert-Paar im aktuellen Transaktionskontext zugewiesen oder überschrieben <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>. Existierende Schlüssel können über <code>KeyExists()</code> geprüft <a class="spec-record-ref" data-req="SWS_PER_00043" href="../spec/record.html?id=SWS_PER_00043">[SWS_PER_00043]</a>, deren Bytegröße über <code>GetCurrentValueSize()</code> ermittelt <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a> und deren Werte über die typsicheren Überladungen von <code>GetValue&lt;T&gt;()</code> ausgelesen werden <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>, <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>. Erst der Aufruf von <code>SyncToStorage()</code> überträgt sämtliche aufgelaufenen Änderungen atomar auf das physische Speichermedium <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>. Sollen nicht synchronisierte Änderungen hingegen verworfen werden, setzt <code>DiscardPendingChanges()</code> den Zustand auf den Stand des letzten <code>SyncToStorage()</code> bzw. des Öffnens zurück <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Sämtliche Methoden geben Fehler über <code>ara::core::Result</code> zurück. Dabei wird präzise zwischen Operationen mit Rollback-Garantie und Fehlern ohne Rollback unterschieden:</p>
<ul>
<li><strong>Konfigurations- und Schreibschutzfehler:</strong> Bei Aufruf schreibender Methoden auf einem schreibgeschützten Speicher oder bei bereits vorhandenem Schlüssel in Write-Only-Once-Konfigurationen schlägt die Operation mit <code>PerErrc::kIllegalWriteAccess</code> fehl <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a>, <a class="spec-record-ref" data-req="SWS_PER_00048" href="../spec/record.html?id=SWS_PER_00048">[SWS_PER_00048]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>.</li>
<li><strong>Typkonflikte und Schlüsselverfügbarkeit:</strong> Stimmt der Datentyp beim Überschreiben oder Lesen nicht mit dem gespeicherten Typ überein, tritt <code>PerErrc::kDataTypeMismatch</code> auf <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>, <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>, <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>. Nicht gefundene Schlüssel melden <code>PerErrc::kKeyNotFound</code> <a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>, <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a>. Bei <code>ResetKey()</code> wird <code>PerErrc::kInitValueNotAvailable</code> ausgelöst, falls kein Initialwert definiert ist <a class="spec-record-ref" data-req="SWS_PER_00426" href="../spec/record.html?id=SWS_PER_00426">[SWS_PER_00426]</a>.</li>
<li><strong>Speicherplatz- und Quotenverletzungen:</strong> Übersteigt der neue Datenumfang das konfigurierte Limit <code>maximumAllowedSize</code>, wird <code>PerErrc::kQuotaExceeded</code> gemeldet <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>. Reicht der physische Speicher nicht aus, liefert <code>SyncToStorage()</code> oder <code>RecoverKey()</code> den Fehler <code>PerErrc::kOutOfStorageSpace</code> ohne Rollback-Semantik <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>, <a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a>.</li>
<li><strong>Integritäts-, Krypto- und Hardwarefehler:</strong> Physische Zugriffsfehler (<code>PerErrc::kPhysicalStorageFailure</code>) besitzen bei Lesevorgängen und <code>SetValue()</code> Rollback-Semantik <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>, bei <code>SyncToStorage()</code> hingegen keine Rollback-Semantik <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>. Strukturkorruption (<code>PerErrc::kIntegrityCorrupted</code>), Entschlüsselungsfehler (<code>PerErrc::kEncryptionFailed</code>) oder fehlgeschlagene MAC-Prüfungen (<code>PerErrc::kAuthenticationFailed</code>) werden von Lese-, Schreib- und Wiederherstellungsoperationen wie <code>RecoverKey()</code> signalisiert <a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a>.</li>
