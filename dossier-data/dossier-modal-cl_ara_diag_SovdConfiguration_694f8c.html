<div class="ai-level" data-ai-level="2">
<p>Die Schnittstelle <code>ara::diag::SovdConfiguration</code> dient als generischer Handler für explizit modellierte SOVD-Konfigurationen, an den der Diagnostic Server eingehende Lese- und Schreibzugriffe weiterleitet <a class="spec-record-ref" data-req="SWS_DM_01860" href="../spec/record.html?id=SWS_DM_01860">[SWS_DM_01860]</a>, <a class="spec-record-ref" data-req="SWS_DM_01787" href="../spec/record.html?id=SWS_DM_01787">[SWS_DM_01787]</a>. Nach der portbasierten Instanziierung aktiviert die Anwendung den Nachrichtenempfang über <code>Offer</code> und beendet ihn bei Bedarf mit <code>StopOffer</code> <a class="spec-record-ref" data-req="SWS_DM_01872" href="../spec/record.html?id=SWS_DM_01872">[SWS_DM_01872]</a>, <a class="spec-record-ref" data-req="SWS_DM_01930" href="../spec/record.html?id=SWS_DM_01930">[SWS_DM_01930]</a>. Die Datenbereitstellung erfolgt asynchron über Lese- bzw. Schreibsitzungen, wobei fachliche Fehler nach ISO 17978-3 bzw. ASAM SOVD 1.1 signalisiert werden <a class="spec-record-ref" data-req="SWS_DM_01870" href="../spec/record.html?id=SWS_DM_01870">[SWS_DM_01870]</a>.</p>

<h4>Kontext</h4>
<p>Die Schnittstelle <code>ara::diag::SovdConfiguration</code> definiert das generische Interface für explizit modellierte SOVD-Konfigurations-Handler innerhalb der Adaptive AUTOSAR-Diagnosearchitektur <a class="spec-record-ref" data-req="SWS_DM_01860" href="../spec/record.html?id=SWS_DM_01860">[SWS_DM_01860]</a>. Sofern mindestens eine SOVD-Konfiguration im System projektiert ist, stellt die Diagnostic-Server-Instanz des Diagnostic Management (DM) nach außen die standardisierte SOVD-Methode <em>Retrieve List of All Configurations Provided by the Entity</em> gemäß ASAM SOVD bereit <a class="spec-record-ref" data-req="SWS_DM_01429" href="../spec/record.html?id=SWS_DM_01429">[SWS_DM_01429]</a>. Eingehende Lese- und Schreibzugriffe auf eine solche explizite Konfiguration leitet der Diagnostic Server an die konkrete Implementierung von <code>ara::diag::SovdConfiguration</code> weiter: Beim Aufruf der SOVD-Methode <em>Read Configuration</em> ruft der Diagnostic Server die Methode <code>RequestGetConfiguration</code> auf <a class="spec-record-ref" data-req="SWS_DM_01787" href="../spec/record.html?id=SWS_DM_01787">[SWS_DM_01787]</a>, während beim Aufruf von <em>Write Configuration</em> die Methode <code>RequestPutConfiguration</code> ausgeführt wird <a class="spec-record-ref" data-req="SWS_DM_01788" href="../spec/record.html?id=SWS_DM_01788">[SWS_DM_01788]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Die Instanziierung von <code>ara::diag::SovdConfiguration</code> erfolgt anwendungsseitig durch Übergabe eines <code>ara::core::InstanceSpecifier</code> sowie der Angabe eines <code>ConcurrencyType</code> (<code>kConcurrent</code> oder <code>kNotConcurrent</code>) <a class="spec-record-ref" data-req="SWS_DM_01864" href="../spec/record.html?id=SWS_DM_01864">[SWS_DM_01864]</a>. Der <code>InstanceSpecifier</code> referenziert einen Port-Prototyp eines <code>DiagnosticSovdConfigurationInterface</code> im Prozesskontext <a class="spec-record-ref" data-req="SWS_DM_01864" href="../spec/record.html?id=SWS_DM_01864">[SWS_DM_01864]</a>. Die Klasse darf nicht kopiert werden (Kopierkonstruktor und Kopierzuweisungsoperator sind als <code>delete</code> deklariert) <a class="spec-record-ref" data-req="SWS_DM_01866" href="../spec/record.html?id=SWS_DM_01866">[SWS_DM_01866]</a>, <a class="spec-record-ref" data-req="SWS_DM_01868" href="../spec/record.html?id=SWS_DM_01868">[SWS_DM_01868]</a>, unterstützt jedoch geschützte Move-Operationen <a class="spec-record-ref" data-req="SWS_DM_01867" href="../spec/record.html?id=SWS_DM_01867">[SWS_DM_01867]</a>, <a class="spec-record-ref" data-req="SWS_DM_01869" href="../spec/record.html?id=SWS_DM_01869">[SWS_DM_01869]</a>. Um Anfragen vom Diagnostic Server entgegenzunehmen, muss die Anwendung explizit <code>Offer</code> aufrufen <a class="spec-record-ref" data-req="SWS_DM_01872" href="../spec/record.html?id=SWS_DM_01872">[SWS_DM_01872]</a>. Mit dem Aufruf von <code>StopOffer</code> wird die Weiterleitung von Anfragen wieder deaktiviert <a class="spec-record-ref" data-req="SWS_DM_01930" href="../spec/record.html?id=SWS_DM_01930">[SWS_DM_01930]</a>. Bei Zerstörung der Instanz über den virtuellen Destruktor <a class="spec-record-ref" data-req="SWS_DM_01865" href="../spec/record.html?id=SWS_DM_01865">[SWS_DM_01865]</a> wird das Objekt freigegeben; die Freigabe setzt voraus, dass der Handler zuvor ordnungsgemäß deregistriert wurde.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Nutzungspfad beginnt nach der Konstruktion der abgeleiteten Handler-Klasse mit dem Registrieren beim Diagnostic Management mittels <code>Offer()</code> <a class="spec-record-ref" data-req="SWS_DM_01872" href="../spec/record.html?id=SWS_DM_01872">[SWS_DM_01872]</a>. Sobald ein externer Client eine SOVD-Konfigurationsanfrage an die Entität richtet, leitet der Diagnostic Server diese weiter: Bei einer Leseanforderung wird <code>RequestGetConfiguration</code> aufgerufen, wobei die <code>configurationId</code>, die <code>metaInfo</code> und ein <code>CancellationHandler</code> übergeben werden <a class="spec-record-ref" data-req="SWS_DM_01870" href="../spec/record.html?id=SWS_DM_01870">[SWS_DM_01870]</a>. Die Methode liefert ein <code>ara::core::Future</code> zurück, das asynchron ein Tupel aus einer <code>DataTransferReadSession</code> und <code>SovdConfigurationMetaInfo</code> bereitstellt <a class="spec-record-ref" data-req="SWS_DM_01870" href="../spec/record.html?id=SWS_DM_01870">[SWS_DM_01870]</a>. Analog leitet der Server Schreibanfragen über <code>RequestPutConfiguration</code> weiter, welches ein Future mit einer <code>DataTransferWriteSession</code> und <code>SovdConfigurationMetaInfo</code> liefert <a class="spec-record-ref" data-req="SWS_DM_01871" href="../spec/record.html?id=SWS_DM_01871">[SWS_DM_01871]</a>. Vor dem Herunterfahren des Handlers ruft die Anwendung <code>StopOffer()</code> auf, um keine weiteren Anforderungen mehr anzunehmen <a class="spec-record-ref" data-req="SWS_DM_01930" href="../spec/record.html?id=SWS_DM_01930">[SWS_DM_01930]</a>.</p>

<h4>Fehlerszenarien</h4>
<p>Bereits bei der Instanziierung im Konstruktor können Modell- und Mapping-Verletzungen auftreten, falls der <code>InstanceSpecifier</code> im Modell nicht aufgelöst werden kann (<code>InstanceSpecifierMappingIntegrityViolation</code>), der referenzierte Port-Prototyp nicht durch ein <code>DiagnosticSovdConfigurationInterface</code> typisiert ist (<code>PortInterfaceMappingViolation</code>), kein passender Prozess existiert (<code>ProcessMappingViolation</code>) oder der Bezeichner im aktuellen Prozess bereits belegt ist (<code>InstanceSpecifierAlreadyInUseViolation</code>) <a class="spec-record-ref" data-req="SWS_DM_01864" href="../spec/record.html?id=SWS_DM_01864">[SWS_DM_01864]</a>. Beim Aufruf von <code>Offer()</code> gibt die Methode ein <code>ara::core::Result&lt;void&gt;</code> zurück, welches im Fehlerfall <code>DiagOfferErrc::kConfigurationMismatch</code> meldet, wenn die Konfiguration nicht zum DEXT-Modell passt, oder <code>DiagOfferErrc::kAlreadyOffered</code>, falls der Service bereits angeboten wird <a class="spec-record-ref" data-req="SWS_DM_01872" href="../spec/record.html?id=SWS_DM_01872">[SWS_DM_01872]</a>. In den asynchronen Handler-Methoden <code>RequestGetConfiguration</code> und <code>RequestPutConfiguration</code> meldet die Anwendung Fehlerzustände über das <code>ara::core::Future</code> unter Verwendung standardisierter SOVD-Fehlercodes gemäß ISO 17978-3 bzw. ASAM SOVD 1.1 <a class="spec-record-ref" data-req="SWS_DM_01870" href="../spec/record.html?id=SWS_DM_01870">[SWS_DM_01870]</a>, <a class="spec-record-ref" data-req="SWS_DM_01871" href="../spec/record.html?id=SWS_DM_01871">[SWS_DM_01871]</a>. Zudem signalisiert der <code>CancellationHandler</code>, ob eine laufende Kommunikation abgebrochen wurde <a class="spec-record-ref" data-req="SWS_DM_01870" href="../spec/record.html?id=SWS_DM_01870">[SWS_DM_01870]</a>, <a class="spec-record-ref" data-req="SWS_DM_01871" href="../spec/record.html?id=SWS_DM_01871">[SWS_DM_01871]</a>.</p>
