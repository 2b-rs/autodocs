<p class="ai-level ai-oneliner-lead" data-ai-level="1">Ermöglicht die Erstellung von Logging-Kontexten, formatierter Nachrichtenströme und die Client-Zustandsüberwachung.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Namespace <code>ara::log</code> stellt adaptive Protokollierungsdienste bereit, indem er Kontext-Logger verwaltet und Nachrichtenströme typisiert auf Senken wie das DLT-Back-End oder die Konsole ausgibt <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>. Anwendungen beziehen Logger über Fabrikfunktionen, bereiten formatierte Nutzdaten über Argument-Wrapper auf und speisen Daten threadsicher in Log-Nachrichten ein. Als wesentliche Randbedingung verbleibt der Besitz aller Logger-Instanzen beim Framework, während die Registrierung des Verbindungsstatus-Handlers explizit nicht threadsicher ist <a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>.</p>

<h4>Kontext</h4>
<p>Der Namespace <code>ara::log</code> stellt die zentrale Protokollierungsinfrastruktur für adaptive Anwendungen bereit. Seine Kernverantwortung umfasst die Verwaltung von Protokollierungskontexten über die Klasse <code>Logger</code>, die strukturierte Erzeugung von Log-Nachrichten über <code>LogStream</code> sowie die typisierte Übergabe formatierter Nutzdaten über <code>Argument</code> und <code>Format</code>. Das Framework agiert als Bindeglied zwischen den anwendungsseitigen Log-Aufrufen und den Zielsenken: Als primäre Senke dient das DLT-Back-End (Diagnostic Log and Trace), dessen Konnektivitätsstatus über die Enumeration <code>ClientState</code> repräsentiert wird <a class="spec-record-ref" data-req="SWS_LOG_00098" href="../spec/record.html?id=SWS_LOG_00098">[SWS_LOG_00098]</a>. Steht kein Modell zur Verfügung, fungiert standardmäßig die Konsole als Senke <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>. Statusänderungen externer Gegenstellen können über Rückruffunktionen des Typs <code>ConnectionStateHandler</code> überwacht werden <a class="spec-record-ref" data-req="SWS_LOG_00265" href="../spec/record.html?id=SWS_LOG_00265">[SWS_LOG_00265]</a>.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>Logger</code> werden nicht direkt von der Anwendung konstruiert, sondern durch die Fabrikfunktionen <code>CreateLogger</code> instanziiert und im Logging-Framework registriert <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00263" href="../spec/record.html?id=SWS_LOG_00263">[SWS_LOG_00263]</a>. Die Besitzverhältnisse sind eindeutig festgelegt: Der Besitz verbleibt vollständig beim Logging-Framework („Ownership stays within the Logging framework“), welches Referenzen (<code>Logger&amp;</code>) an den Aufrufer ausgibt <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>. Alternativ kann die Erstellung modellbasiert anhand eines <code>ara::core::InstanceSpecifier</code> erfolgen <a class="spec-record-ref" data-req="SWS_LOG_00256" href="../spec/record.html?id=SWS_LOG_00256">[SWS_LOG_00256]</a>. Interpretation: Da das Framework den Besitz behält, dürfte die Lebensdauer registrierter Logger an den übergeordneten Prozess gebunden sein.</p>
<p>Hinsichtlich der Nebenläufigkeit ist die Erzeugung von Loggern über <code>CreateLogger</code> threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>. Dagegen ist die Registrierung von Verbindungszustand-Handlern über <code>RegisterConnectionStateHandler</code> explizit nicht threadsicher („not thread-safe“) <a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>; sie muss daher typischerweise während der Initialisierungsphase vor dem Start nebenläufiger Aktivitäten erfolgen. Zudem kann stets nur ein einzelner Handler aktiv sein; eine Neu-Registrierung ersetzt vorherige Callbacks unverzüglich <a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>. Der Verbindungslebenszyklus externer Gegenstellen durchläuft die Stufen <code>kUnknown</code> (DLT-Back-End noch nicht aktiv), <code>kNotConnected</code> und <code>kConnected</code> <a class="spec-record-ref" data-req="SWS_LOG_00098" href="../spec/record.html?id=SWS_LOG_00098">[SWS_LOG_00098]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Konfiguration der Überwachung, den Bezug des Loggers und die formatierte Nachrichtenausgabe:</p>
<ul>
<li>Registrierung des Verbindungs-Callbacks mittels <code>RegisterConnectionStateHandler</code> <a class="spec-record-ref" data-req="SWS_LOG_00205" href="../spec/record.html?id=SWS_LOG_00205">[SWS_LOG_00205]</a>.</li>
<li>Bezug der <code>Logger</code>-Referenz über <code>CreateLogger</code> unter Angabe einer Kontext-ID, einer Beschreibung und optional eines Standard-Schweregrads aus <code>LogLevel</code> (z.&nbsp;B. <code>kWarn</code> oder <code>kInfo</code>) <a class="spec-record-ref" data-req="SWS_LOG_00018" href="../spec/record.html?id=SWS_LOG_00018">[SWS_LOG_00018]</a>, <a class="spec-record-ref" data-req="SWS_LOG_00021" href="../spec/record.html?id=SWS_LOG_00021">[SWS_LOG_00021]</a>.</li>
<li>Erzeugung strukturierter Argumente mittels <code>Arg</code> unter Beigabe von Bezeichner, Einheit und Formatierhinweisen <a class="spec-record-ref" data-req="SWS_LOG_00201" href="../spec/record.html?id=SWS_LOG_00201">[SWS_LOG_00201]</a>. Hierfür stehen Hilfsfunktionen wie <code>Dflt</code> <a class="spec-record-ref" data-req="SWS_LOG_00208" href="../spec/record.html?id=SWS_LOG_00208">[SWS_LOG_00208]</a>, ganzzahlige Formate wie <code>Dec</code> <a class="spec-record-ref" data-req="SWS_LOG_00211" href="../spec/record.html?id=SWS_LOG_00211">[SWS_LOG_00211]</a>, <code>Hex</code> <a class="spec-record-ref" data-req="SWS_LOG_00209" href="../spec/record.html?id=SWS_LOG_00209">[SWS_LOG_00209]</a>, <code>Bin</code> <a class="spec-record-ref" data-req="SWS_LOG_00215" href="../spec/record.html?id=SWS_LOG_00215">[SWS_LOG_00215]</a> und <code>Oct</code> <a class="spec-record-ref" data-req="SWS_LOG_00213" href="../spec/record.html?id=SWS_LOG_00213">[SWS_LOG_00213]</a> sowie Fließkommaformate wie <code>DecFloat</code> <a class="spec-record-ref" data-req="SWS_LOG_00217" href="../spec/record.html?id=SWS_LOG_00217">[SWS_LOG_00217]</a>, <code>EngFloat</code> <a class="spec-record-ref" data-req="SWS_LOG_00219" href="../spec/record.html?id=SWS_LOG_00219">[SWS_LOG_00219]</a>, <code>HexFloat</code> <a class="spec-record-ref" data-req="SWS_LOG_00221" href="../spec/record.html?id=SWS_LOG_00221">[SWS_LOG_00221]</a> oder <code>AutoFloat</code> <a class="spec-record-ref" data-req="SWS_LOG_00223" href="../spec/record.html?id=SWS_LOG_00223">[SWS_LOG_00223]</a> bereit, welche die Spezifizierer aus <code>Fmt</code> kapseln <a class="spec-record-ref" data-req="SWS_LOG_00206" href="../spec/record.html?id=SWS_LOG_00206">[SWS_LOG_00206]</a>.</li>
<li>Übertragen von Nutzdaten in den <code>LogStream</code> über überladene Operatoren <code>operator&lt;&lt;</code>, unter anderem für <code>LogLevel</code> <a class="spec-record-ref" data-req="SWS_LOG_00063" href="../spec/record.html?id=SWS_LOG_00063">[SWS_LOG_00063]</a>, <code>ara::core::ErrorCode</code> <a class="spec-record-ref" data-req="SWS_LOG_00124" href="../spec/record.html?id=SWS_LOG_00124">[SWS_LOG_00124]</a>, <code>std::chrono::duration</code> <a class="spec-record-ref" data-req="SWS_LOG_00125" href="../spec/record.html?id=SWS_LOG_00125">[SWS_LOG_00125]</a>, <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_LOG_00126" href="../spec/record.html?id=SWS_LOG_00126">[SWS_LOG_00126]</a> und Zeiger <code>const void*</code> <a class="spec-record-ref" data-req="SWS_LOG_00127" href="../spec/record.html?id=SWS_LOG_00127">[SWS_LOG_00127]</a>.</li>
</ul>
