<h4>Context</h4>
<p>The interface <code>ara::crypto::cryp::HashFunctionCtx</code> defines the standardized abstraction for cryptographic hash functions within the module <code>crypto</code> of the AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_CRYPT_21101" href="../spec/record.html?id=SWS_CRYPT_21101">[SWS_CRYPT_21101]</a>. Its primary responsibility consists in calculating cryptographic checksums and message digests over arbitrary byte streams or structured key objects.</p>
<p>The calling application software primarily acts as an interaction partner, providing input data via <code>ReadOnlyMemRegion</code> and receiving calculated hash values via <code>ReadWriteMemRegion</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>. In addition to regular memory areas, the context can interact directly with cryptographic objects to securely include key material of type <code>CryptoObject::Sptr</code> in the digest calculation <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>. Furthermore, the context potentially interacts with other context instances of the same algorithm and crypto provider via the import and export of the internal processing state <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>.</p>

<h4>Lifecycle</h4>
<p>The lifetime and ownership of an instance are typically managed via the smart pointer type alias <code>ara::crypto::cryp::HashFunctionCtx::Sptr</code> (<code>std::shared_ptr&lt;HashFunctionCtx&gt;</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_21101" href="../spec/record.html?id=SWS_CRYPT_21101">[SWS_CRYPT_21101]</a>. Since <code>HashFunctionCtx</code> is a purely abstract interface, the concrete instance is likely created via a factory method of a crypto provider (interpretation). All member functions are declared as <code>noexcept</code> and specified as exception-safe and thread-safe (among others, <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50058" href="../spec/record.html?id=SWS_CRYPT_50058">[SWS_CRYPT_50058]</a>).</p>
<p>The operational flow follows a stateful model with three main phases:</p>
<ul>
<li><strong>Ready / Not started:</strong> After creation, the context is in the idle state. In this state, either a single-step hash operation can be executed via <code>CalculateHashDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a> or an iterative calculation can be initiated via <code>Start()</code> without an initialization vector (IV) <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a> or with an IV <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a>, respectively. An import via <code>ImportContextState()</code> transitions the context directly into the state of the imported image <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>.</li>
<li><strong>In processing (streaming):</strong> After successful <code>Start()</code>, the context accepts data fragments <a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a> or key objects <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a> via repeated calls to <code>Update()</code>. In this phase, an intermediate state can be queried at any time via <code>GetIntermediateDigest()</code> without interrupting the data flow <a class="spec-record-ref" data-req="SWS_CRYPT_50059" href="../spec/record.html?id=SWS_CRYPT_50059">[SWS_CRYPT_50059]</a>. With <code>ExportContextState()</code>, the computation state can be serialized <a class="spec-record-ref" data-req="SWS_CRYPT_50064" href="../spec/record.html?id=SWS_CRYPT_50064">[SWS_CRYPT_50064]</a>. A call to <code>Cancel()</code> aborts the operation and resets processing <a class="spec-record-ref" data-req="SWS_CRYPT_50058" href="../spec/record.html?id=SWS_CRYPT_50058">[SWS_CRYPT_50058]</a>; likewise, a renewed call to <code>Start()</code> aborts an ongoing operation <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a>.</li>
<li><strong>Finished:</strong> The call to <code>Finish()</code> completes the calculation <a class="spec-record-ref" data-req="SWS_CRYPT_21115" href="../spec/record.html?id=SWS_CRYPT_21115">[SWS_CRYPT_21115]</a>. In this state, no further data can be fed via <code>Update()</code>. The final hash value can now be read out via <code>GetDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a> or checked directly against a reference using <code>Compare()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50154" href="../spec/record.html?id=SWS_CRYPT_50154">[SWS_CRYPT_50154]</a>. A renewed <code>Start()</code> transitions the context back into a new calculation phase.</li>
</ul>

<h4>Usage Path</h4>
<p>The interface supports two usage patterns:</p>
<p><strong>1. Single-step calculation (single-call):</strong> If the entire message is already present in memory, <code>CalculateHashDigest()</code> performs the initialization, transformation, and digest generation in a single atomic step <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>.</p>
<p><strong>2. Step-by-step streaming calculation (multi-call):</strong> For streamed data or messages that are larger than the maximum block size <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50062" href="../spec/record.html?id=SWS_CRYPT_50062">[SWS_CRYPT_50062]</a>, the call typically occurs in the following individual steps:</p>
<ol>
<li><strong>Buffer dimensioning:</strong> The application determines the output size via <code>GetDigestSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50061" href="../spec/record.html?id=SWS_CRYPT_50061">[SWS_CRYPT_50061]</a> and allocates a suitable buffer.</li>
<li><strong>Starting:</strong> Call to <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a> or <code>Start(iv)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a>, respectively, to activate the calculation.</li>
<li><strong>Feeding data:</strong> Sequential passing of data sections via <code>Update(data)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a> or keys via <code>Update(key)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>.</li>
<li><strong>Finishing:</strong> Call to <code>Finish()</code> to complete the digest calculation <a class="spec-record-ref" data-req="SWS_CRYPT_21115" href="../spec/record.html?id=SWS_CRYPT_21115">[SWS_CRYPT_21115]</a>.</li>
<li><strong>Result processing:</strong> Either the digest is written into the provided destination buffer using <code>GetDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a>, or it is compared directly with an expected reference value using <code>Compare()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50154" href="../spec/record.html?id=SWS_CRYPT_50154">[SWS_CRYPT_50154]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>All methods return a <code>ara::core::Result</code> and implement rollback semantics so that the context remains in a consistent state in case of errors. The defined error codes cover the following problem areas:</p>
<ul>
<li><strong>Sequence errors:</strong>
<ul>
<li><code>ara::crypto::CryptoErrc::kProcessingNotStarted</code>: A call to <code>Update()</code> (<a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>) or <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50058" href="../spec/record.html?id=SWS_CRYPT_50058">[SWS_CRYPT_50058]</a> occurs without the calculation having been initiated by <code>Start()</code>.</li>
<li><code>ara::crypto::CryptoErrc::kInvalidUsageOrder</code>: <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21115" href="../spec/record.html?id=SWS_CRYPT_21115">[SWS_CRYPT_21115]</a> or <code>GetIntermediateDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50059" href="../spec/record.html?id=SWS_CRYPT_50059">[SWS_CRYPT_50059]</a> is called without the hashing process having been started successfully beforehand.</li>
<li><code>ara::crypto::CryptoErrc::kProcessingNotFinished</code>: <code>GetDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a> or <code>Compare()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50154" href="../spec/record.html?id=SWS_CRYPT_50154">[SWS_CRYPT_50154]</a> is called before the calculation has been completed by <code>Finish()</code>.</li>
</ul>
</li>
<li><strong>Buffer and size issues:</strong>
<ul>
<li><code>ara::crypto::CryptoErrc::kInsufficientCapacity</code>: The provided output buffer is too small for the result in <code>CalculateHashDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>, <code>GetDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a>, <code>GetIntermediateDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50059" href="../spec/record.html?id=SWS_CRYPT_50059">[SWS_CRYPT_50059]</a>, or <code>ExportContextState()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50064" href="../spec/record.html?id=SWS_CRYPT_50064">[SWS_CRYPT_50064]</a>.</li>
<li><code>ara::crypto::CryptoErrc::kInvalidInputSize</code>: The size of the input data or the IV is invalid (<a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>).</li>
</ul>
</li>
<li><strong>Incompatibility and missing support:</strong>
<ul>
<li><code>ara::crypto::CryptoErrc::kUnsupported</code>: The function or configuration is not supported by the context, e.g., single calls <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>, IV usage for algorithms without IV or missing IV for functions requiring an IV (<a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a>), intermediate results <a class="spec-record-ref" data-req="SWS_CRYPT_50059" href="../spec/record.html?id=SWS_CRYPT_50059">[SWS_CRYPT_50059]</a>, key hashing <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>, or state export/import (<a class="spec-record-ref" data-req="SWS_CRYPT_50063" href="../spec/record.html?id=SWS_CRYPT_50063">[SWS_CRYPT_50063]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50064" href="../spec/record.html?id=SWS_CRYPT_50064">[SWS_CRYPT_50064]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>).</li>
<li><code>ara::crypto::CryptoErrc::kIncompatibleObject</code> and <code>ara::crypto::CryptoErrc::kUsageViolation</code>: The key object passed to <code>Update()</code> is incompatible or prohibits usage for hash calculation (missing <code>kAllowHashCalculation</code>) <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>.</li>
<li><code>ara::crypto::CryptoErrc::kInvalidArgument</code>: The state data passed to <code>ImportContextState()</code> is invalid <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>.</li>
<li><code>ara::crypto::CryptoErrc::kBusyResource</code>: A required cryptographic hardware or software resource is busy (<a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a>).</li>
</ul>
</li>
</ul>
