<p>Die rein virtuelle Methode <code>Read</code> der Klasse <code>ara::diag::DataTransferReadByPushHandler</code> dient dem asynchronen Auslesen von Datenblöcken für Datei- oder Verzeichnisinformationen aus der Anwendung <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>. Die Anwendung stellt den jeweiligen Daten-Chunk zusammen und übergibt dessen Eigentum als <code>ara::core::Vector&lt;ara::core::Byte&gt;</code> an das Diagnosemodul.</p>
<h4>Verwendung und Aufrufkontext</h4>
<p>Der Aufruf erfolgt durch den Diagnostic Server zur Bereitstellung von Antwortdaten für UDS-Clients über die Header-Datei <code>ara/diag/data_transfer.h</code> <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>. Die Methode erwartet drei Parameter:</p>
<ul>
<li><code>recommended_number_bytes_to_return</code>: Die empfohlene Anzahl an Bytes für optimalen Durchsatz. Dieser Wert dürfte sich vermutlich an der internen Puffer- oder PDU-Größe des Diagnostic Management orientieren. <a class="interp-q interp-q-open" data-q="Q-1a8c1270b192b96f" data-q-status="open" href="../versions.html?tab=q&amp;id=Q-1a8c1270b192b96f" title="Frage Q-1a8c1270b192b96f (offen): Die empfohlene Bytezahl recommended_number_bytes_to_return orientiert sich an Puffer- oder PDU-Größen.">Frage Q-1a8c1270b192b96f (offen)</a></li>
<li><code>meta_info</code>: Zusätzliche Meta-Informationen der eingehenden Diagnoseanfrage (<code>MetaInfo</code>).</li>
<li><code>cancellation_handler</code>: Ermöglicht das Abfragen des Abbruchstatus via <code>cancellation_handler.IsCanceled()</code> oder das Registrieren einer Benachrichtigung mittels <code>cancellation_handler.SetNotifier()</code> bei Verbindungsabbrüchen.</li>
</ul>
<p>Als Rückgabewert dient ein <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code>. Bei erfolgreicher Verarbeitung werden die Daten als <code>transferResponseParameterRecord</code> hinter dem Sequenzzähler in die positive Antwortnachricht eingebettet <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>.</p>
<h4>Fehlerbehandlung und Nebenläufigkeit</h4>
<p>Schlägt die Verarbeitung fehl, wird das Future mit einem Fehlercode aus <code>DiagUdsNrcErrc</code> erfüllt, der eine passende NRC gemäß ISO 14229-1 abbildet <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>. Wird die Schnittstelle vom Dienst noch nicht oder nicht mehr mittels <code>offer()</code> angeboten, beantwortet der Diagnostic Manager den Request mit NRC 0x94 (<code>ResourceTemporarilyNotAvailable</code>) <a class="spec-record-ref" data-req="SWS_DM_01257" href="../spec/record.html?id=SWS_DM_01257">[SWS_DM_01257]</a>. Die Methode ist als ausnahmesicher (<em>exception safe</em>), jedoch als nicht threadsicher (<em>not thread-safe</em>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01522" href="../spec/record.html?id=SWS_DM_01522">[SWS_DM_01522]</a>, weshalb gleichzeitige Aufrufe anwendungsseitig zu synchronisieren sind.</p>
