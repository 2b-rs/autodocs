<h4>Rolle des DCM zwischen Tester, Basissoftware und Anwendung</h4>
<p>Der DCM nimmt Diagnoseanfragen eines externen Testers entgegen und beantwortet sie. Er implementiert die UDS-Dienste nach Tabelle 7.5 <a class="spec-record-ref" data-req="SWS_Dcm_00442" href="../../spec/record.html?id=SWS_Dcm_00442">[SWS_Dcm_00442]</a> sowie OBD-Dienste wie $01 <a class="spec-record-ref" data-req="SWS_Dcm_00243" href="../../spec/record.html?id=SWS_Dcm_00243">[SWS_Dcm_00243]</a> und $09 <a class="spec-record-ref" data-req="SWS_Dcm_00421" href="../../spec/record.html?id=SWS_Dcm_00421">[SWS_Dcm_00421]</a>. Intern arbeiten drei Submodule zusammen:</p>
<ul>
<li>Das <strong>DSL</strong>-Submodul hält die aktive Sitzung <a class="spec-record-ref" data-req="SWS_Dcm_00022" href="../../spec/record.html?id=SWS_Dcm_00022">[SWS_Dcm_00022]</a> und den aktiven Security-Level <a class="spec-record-ref" data-req="SWS_Dcm_00020" href="../../spec/record.html?id=SWS_Dcm_00020">[SWS_Dcm_00020]</a>.</li>
<li>Das <strong>DSD</strong>-Submodul analysiert den Service-Identifier <a class="spec-record-ref" data-req="SWS_Dcm_00192" href="../../spec/record.html?id=SWS_Dcm_00192">[SWS_Dcm_00192]</a> und sucht die ausführende DSP-Funktion <a class="spec-record-ref" data-req="SWS_Dcm_00221" href="../../spec/record.html?id=SWS_Dcm_00221">[SWS_Dcm_00221]</a>.</li>
<li>Das <strong>DSP</strong>-Submodul führt den Dienst aus und meldet das Ende an das DSD <a class="spec-record-ref" data-req="SWS_Dcm_00222" href="../../spec/record.html?id=SWS_Dcm_00222">[SWS_Dcm_00222]</a>.</li>
</ul>
<p>Zur Systemgrenze gehören mehrere Nachbarmodule und Schnittstellen:</p>
<ul>
<li><strong>Mode-Manager:</strong> Der DCM verwaltet die Diagnosemodi <a class="spec-record-ref" data-req="SWS_Dcm_00775" href="../../spec/record.html?id=SWS_Dcm_00775">[SWS_Dcm_00775]</a>. Dazu stellt er ModeDeclarationGroups bereit, etwa <code>DcmDiagnosticSessionControl</code> <a class="spec-record-ref" data-req="SWS_Dcm_91019" href="../../spec/record.html?id=SWS_Dcm_91019">[SWS_Dcm_91019]</a>, <code>DcmEcuReset</code> <a class="spec-record-ref" data-req="SWS_Dcm_00777" href="../../spec/record.html?id=SWS_Dcm_00777">[SWS_Dcm_00777]</a>, <code>DcmControlDTCSetting</code> <a class="spec-record-ref" data-req="SWS_Dcm_00781" href="../../spec/record.html?id=SWS_Dcm_00781">[SWS_Dcm_00781]</a> und <code>DcmSecurityAccess</code> <a class="spec-record-ref" data-req="SWS_Dcm_01327" href="../../spec/record.html?id=SWS_Dcm_01327">[SWS_Dcm_01327]</a>. Für CommunicationControl gibt es eine eigene Gruppe je Netzwerk <a class="spec-record-ref" data-req="SWS_Dcm_00780" href="../../spec/record.html?id=SWS_Dcm_00780">[SWS_Dcm_00780]</a>.</li>
<li><strong>DEM:</strong> Fehlerspeicherzugriffe laufen über den DEM, z. B. erst <code>Dem_SetDTCFilter</code>, dann <code>Dem_GetNextFilteredDTC</code> <a class="spec-record-ref" data-req="SWS_Dcm_00835" href="../../spec/record.html?id=SWS_Dcm_00835">[SWS_Dcm_00835]</a>.</li>
<li><strong>NvM:</strong> Hier liegen persistente Daten wie DDDID-Definitionen <a class="spec-record-ref" data-req="SWS_Dcm_00867" href="../../spec/record.html?id=SWS_Dcm_00867">[SWS_Dcm_00867]</a>.</li>
<li><strong>ComM:</strong> Er meldet Kommunikationsmodi per Callback <a class="spec-record-ref" data-req="SWS_Dcm_00356" href="../../spec/record.html?id=SWS_Dcm_00356">[SWS_Dcm_00356]</a>.</li>
<li><strong>CSM/KeyM:</strong> Sie beantworten Krypto- und Zertifikatsaufträge asynchron <a class="spec-record-ref" data-req="SWS_Dcm_91076" href="../../spec/record.html?id=SWS_Dcm_91076">[SWS_Dcm_91076]</a> <a class="spec-record-ref" data-req="SWS_Dcm_91077" href="../../spec/record.html?id=SWS_Dcm_91077">[SWS_Dcm_91077]</a>.</li>
</ul>

<h4>Initialisierung, Hauptfunktion und Bootloader-Übergang</h4>
<p><code>Dcm_Init</code> <a class="spec-record-ref" data-req="SWS_Dcm_00037" href="../../spec/record.html?id=SWS_Dcm_00037">[SWS_Dcm_00037]</a> erhält einen Zeiger auf <code>Dcm_ConfigType</code> mit den Post-Build-Parametern (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_8_2_3_Dcm_ConfigType.html" data-snip="SNIP_CLASSIC_DCM_SECTION_8_2_3_Dcm_ConfigType">SWS DCM S. 275</a>). Die Funktion belegt alle globalen Variablen mit Konfigurationswerten <a class="spec-record-ref" data-req="SWS_Dcm_00334" href="../../spec/record.html?id=SWS_Dcm_00334">[SWS_Dcm_00334]</a>. Danach gilt folgender Startzustand:</p>
<ul>
<li>Security-Level ist <code>DCM_SEC_LEV_LOCKED</code> <a class="spec-record-ref" data-req="SWS_Dcm_00033" href="../../spec/record.html?id=SWS_Dcm_00033">[SWS_Dcm_00033]</a>.</li>
<li>Aktiv ist die Default-Sitzung 0x01 <a class="spec-record-ref" data-req="SWS_Dcm_00034" href="../../spec/record.html?id=SWS_Dcm_00034">[SWS_Dcm_00034]</a>.</li>
<li>Alle ROE-Ereignisse stehen auf „ROE cleared“ <a class="spec-record-ref" data-req="SWS_Dcm_00872" href="../../spec/record.html?id=SWS_Dcm_00872">[SWS_Dcm_00872]</a>.</li>
<li>ActiveDiagnostic steht auf <code>DCM_COMM_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_Dcm_01069" href="../../spec/record.html?id=SWS_Dcm_01069">[SWS_Dcm_01069]</a>.</li>
<li>Die Attempt-Counter werden über <code>Xxx_GetSecurityAttemptCounter</code> gelesen <a class="spec-record-ref" data-req="SWS_Dcm_01154" href="../../spec/record.html?id=SWS_Dcm_01154">[SWS_Dcm_01154]</a>.</li>
</ul>
<p>Beim Start fragt der DCM außerdem <code>Dcm_GetProgConditions</code> ab <a class="spec-record-ref" data-req="SWS_Dcm_00536" href="../../spec/record.html?id=SWS_Dcm_00536">[SWS_Dcm_00536]</a>. Der Rückgabewert <code>DCM_WARM_START</code> <a class="spec-record-ref" data-req="SWS_Dcm_00987" href="../../spec/record.html?id=SWS_Dcm_00987">[SWS_Dcm_00987]</a> zeigt einen Rücksprung aus dem Bootloader an. In diesem Fall kann noch eine Antwort ($50/$51) fällig sein <a class="spec-record-ref" data-req="SWS_Dcm_00537" href="../../spec/record.html?id=SWS_Dcm_00537">[SWS_Dcm_00537]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_8_5_4_Dcm_GetProgConditions.html" data-snip="SNIP_CLASSIC_DCM_SECTION_8_5_4_Dcm_GetProgConditions">SWS DCM S. 299</a>).</p>
<p>Laufende Arbeit erledigt <code>Dcm_MainFunction</code> <a class="spec-record-ref" data-req="SWS_Dcm_00053" href="../../spec/record.html?id=SWS_Dcm_00053">[SWS_Dcm_00053]</a>. Gibt eine Operation <code>DCM_E_PENDING</code> zurück, ruft der DCM sie erneut auf, z. B. im nächsten Zyklus <a class="spec-record-ref" data-req="SWS_Dcm_00760" href="../../spec/record.html?id=SWS_Dcm_00760">[SWS_Dcm_00760]</a>.</p>
<p>Der Weg in den Bootloader verläuft so:</p>
<ol>
<li>Der Tester fordert per 0x10 eine Sitzung an, die einen Bootloader-Sprung auslöst <a class="spec-record-ref" data-req="SWS_Dcm_00532" href="../../spec/record.html?id=SWS_Dcm_00532">[SWS_Dcm_00532]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00592" href="../../spec/record.html?id=SWS_Dcm_00592">[SWS_Dcm_00592]</a>.</li>
<li>Je nach Konfiguration sendet der DCM zuerst NRC 0x78 <a class="spec-record-ref" data-req="SWS_Dcm_00535" href="../../spec/record.html?id=SWS_Dcm_00535">[SWS_Dcm_00535]</a>.</li>
<li>Interpretation: Danach dürfte <code>DcmEcuReset</code> auf <code>JUMPTOBOOTLOADER</code> wechseln. Daraufhin ruft der DCM <code>Dcm_SetProgConditions</code> auf <a class="spec-record-ref" data-req="SWS_Dcm_00720" href="../../spec/record.html?id=SWS_Dcm_00720">[SWS_Dcm_00720]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00543" href="../../spec/record.html?id=SWS_Dcm_00543">[SWS_Dcm_00543]</a>.</li>
<li>Bei <code>E_OK</code> folgt ein weiterer Moduswechsel <a class="spec-record-ref" data-req="SWS_Dcm_00719" href="../../spec/record.html?id=SWS_Dcm_00719">[SWS_Dcm_00719]</a>.</li>
</ol>
<p><code>Dcm_ProgConditionsType</code> überträgt dabei u. a. ConnectionId, TesterAddress, Sid und ResponseRequired <a class="spec-record-ref" data-req="SWS_Dcm_00988" href="../../spec/record.html?id=SWS_Dcm_00988">[SWS_Dcm_00988]</a>.</p>

<h4>Der Weg einer Anfrage durch DSL, DSD und DSP</h4>
<p><strong>Empfang.</strong> Der PduR beginnt den Empfang mit <code>Dcm_StartOfReception</code> <a class="spec-record-ref" data-req="SWS_Dcm_00094" href="../../spec/record.html?id=SWS_Dcm_00094">[SWS_Dcm_00094]</a>. Mit <code>Dcm_CopyRxData</code> kopiert er die Daten in den DCM-Puffer <a class="spec-record-ref" data-req="SWS_Dcm_00443" href="../../spec/record.html?id=SWS_Dcm_00443">[SWS_Dcm_00443]</a>. Den Abschluss meldet er mit <code>Dcm_TpRxIndication</code> <a class="spec-record-ref" data-req="SWS_Dcm_00093" href="../../spec/record.html?id=SWS_Dcm_00093">[SWS_Dcm_00093]</a>. Das DSL reicht die Anfrage nur bei <code>E_OK</code> an das DSD weiter <a class="spec-record-ref" data-req="SWS_Dcm_00111" href="../../spec/record.html?id=SWS_Dcm_00111">[SWS_Dcm_00111]</a>. Bei generischen Verbindungen speichert der DCM die Quelladresse aus den MetaData <a class="spec-record-ref" data-req="SWS_Dcm_00848" href="../../spec/record.html?id=SWS_Dcm_00848">[SWS_Dcm_00848]</a>.</p>
<p><strong>Prüfung im DSD.</strong> Die Reihenfolge der Prüfungen richtet sich nach ISO 14229-1 <a class="spec-record-ref" data-req="SWS_Dcm_00827" href="../../spec/record.html?id=SWS_Dcm_00827">[SWS_Dcm_00827]</a>:</p>
<ul>
<li>Ein unbekannter Service-Identifier führt zu NRC 0x11 <a class="spec-record-ref" data-req="SWS_Dcm_00197" href="../../spec/record.html?id=SWS_Dcm_00197">[SWS_Dcm_00197]</a>.</li>
<li>Eine nicht unterstützte Subfunktion führt zu NRC 0x12 <a class="spec-record-ref" data-req="SWS_Dcm_00273" href="../../spec/record.html?id=SWS_Dcm_00273">[SWS_Dcm_00273]</a>.</li>
<li>Geprüft werden außerdem Sitzung <a class="spec-record-ref" data-req="SWS_Dcm_00211" href="../../spec/record.html?id=SWS_Dcm_00211">[SWS_Dcm_00211]</a>, Security-Level <a class="spec-record-ref" data-req="SWS_Dcm_00217" href="../../spec/record.html?id=SWS_Dcm_00217">[SWS_Dcm_00217]</a> und Modusregeln <a class="spec-record-ref" data-req="SWS_Dcm_00773" href="../../spec/record.html?id=SWS_Dcm_00773">[SWS_Dcm_00773]</a>.</li>
<li>Die Anwendung kann über <code>Xxx_Indication</code> eingreifen <a class="spec-record-ref" data-req="SWS_Dcm_00218" href="../../spec/record.html?id=SWS_Dcm_00218">[SWS_Dcm_00218]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01341" href="../../spec/record.html?id=SWS_Dcm_01341">[SWS_Dcm_01341]</a>.</li>
<li>Ist das suppressPosRspMsgIndicationBit gesetzt, unterbleibt die positive Antwort <a class="spec-record-ref" data-req="SWS_Dcm_00200" href="../../spec/record.html?id=SWS_Dcm_00200">[SWS_Dcm_00200]</a>.</li>
</ul>

<h4>Asynchrone Callouts, OpStatus und Response Pending</h4>
<p>Asynchrone Anwendungsschnittstellen erhalten einen <code>Dcm_OpStatusType</code> <a class="spec-record-ref" data-req="SWS_Dcm_00984" href="../../spec/record.html?id=SWS_Dcm_00984">[SWS_Dcm_00984]</a>:</p>
<ul>
<li>Beim ersten Aufruf ist der Wert <code>DCM_INITIAL</code> <a class="spec-record-ref" data-req="SWS_Dcm_00527" href="../../spec/record.html?id=SWS_Dcm_00527">[SWS_Dcm_00527]</a>.</li>
<li>Nach einem <code>DCM_E_PENDING</code> folgt <code>DCM_PENDING</code> <a class="spec-record-ref" data-req="SWS_Dcm_00530" href="../../spec/record.html?id=SWS_Dcm_00530">[SWS_Dcm_00530]</a>.</li>
<li>Ein Abbruch erfolgt mit <code>DCM_CANCEL</code> <a class="spec-record-ref" data-req="SWS_Dcm_00735" href="../../spec/record.html?id=SWS_Dcm_00735">[SWS_Dcm_00735]</a>. Den Rückgabewert dieses Aufrufs ignoriert der DCM <a class="spec-record-ref" data-req="SWS_Dcm_01413" href="../../spec/record.html?id=SWS_Dcm_01413">[SWS_Dcm_01413]</a>.</li>
</ul>
<p>Ob eine Schnittstelle synchron oder asynchron arbeitet, legt die Konfiguration fest. Ein Beispiel ist <code>Xxx_ReadData</code>: Es gibt eine synchrone Variante <a class="spec-record-ref" data-req="SWS_Dcm_00793" href="../../spec/record.html?id=SWS_Dcm_00793">[SWS_Dcm_00793]</a> und eine asynchrone <a class="spec-record-ref" data-req="SWS_Dcm_91006" href="../../spec/record.html?id=SWS_Dcm_91006">[SWS_Dcm_91006]</a>. Speicherzugriffe nutzen eigene Rückgabetypen wie <code>Dcm_ReturnReadMemoryType</code> <a class="spec-record-ref" data-req="SWS_Dcm_00985" href="../../spec/record.html?id=SWS_Dcm_00985">[SWS_Dcm_00985]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_8_5_1_Dcm_ReadMemory.html" data-snip="SNIP_CLASSIC_DCM_SECTION_8_5_1_Dcm_ReadMemory">SWS DCM S. 281</a>).</p>
<p><strong>Response Pending.</strong> Das DSL überwacht die Zeitgrenzen P2ServerMax und P2*ServerMax <a class="spec-record-ref" data-req="SWS_Dcm_00027" href="../../spec/record.html?id=SWS_Dcm_00027">[SWS_Dcm_00027]</a>. Braucht die Verarbeitung länger, sendet es NRC 0x78 <a class="spec-record-ref" data-req="SWS_Dcm_00024" href="../../spec/record.html?id=SWS_Dcm_00024">[SWS_Dcm_00024]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_STD_SECTION_9_2_2_Process_Busy_behavior.html" data-snip="SNIP_CLASSIC_STD_SECTION_9_2_2_Process_Busy_behavior">SWS DCM S. 433</a>). Die Anwendung kann NRC 0x78 auch sofort erzwingen, indem sie <code>DCM_E_FORCE_RCRRP</code> zurückgibt <a class="spec-record-ref" data-req="SWS_Dcm_00528" href="../../spec/record.html?id=SWS_Dcm_00528">[SWS_Dcm_00528]</a>. Nach der Sendebestätigung ruft der DCM die Operation dann mit <code>DCM_FORCE_RCRRP_OK</code> auf <a class="spec-record-ref" data-req="SWS_Dcm_00529" href="../../spec/record.html?id=SWS_Dcm_00529">[SWS_Dcm_00529]</a>. Wie viele NRC 0x78 in Folge erlaubt sind, ist begrenzt <a class="spec-record-ref" data-req="SWS_Dcm_00120" href="../../spec/record.html?id=SWS_Dcm_00120">[SWS_Dcm_00120]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01567" href="../../spec/record.html?id=SWS_Dcm_01567">[SWS_Dcm_01567]</a>.</p>

<h4>Sitzung, Security-Level und Authentifizierung als Zugangskontrolle</h4>
<p><strong>Sitzungen.</strong> Der DCM implementiert UDS 0x10 <a class="spec-record-ref" data-req="SWS_Dcm_00250" href="../../spec/record.html?id=SWS_Dcm_00250">[SWS_Dcm_00250]</a>. Ein nicht konfigurierter Sitzungstyp führt zu NRC 0x12 <a class="spec-record-ref" data-req="SWS_Dcm_00307" href="../../spec/record.html?id=SWS_Dcm_00307">[SWS_Dcm_00307]</a>. Die neue Sitzung wird erst in der Sendebestätigung wirksam. Gleichzeitig setzt der DCM die neuen P2-Werte und führt den Moduswechsel durch <a class="spec-record-ref" data-req="SWS_Dcm_00311" href="../../spec/record.html?id=SWS_Dcm_00311">[SWS_Dcm_00311]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_7_4_2_2_Service_0x10_Diagnostic_Session_Control.html" data-snip="SNIP_CLASSIC_DCM_SECTION_7_4_2_2_Service_0x10_Diagnostic_Session_Control">SWS DCM S. 107</a>). In die Default-Sitzung kehrt der DCM auf zwei Wegen zurück:</p>
<ul>
<li>bei einem S3Server-Timeout <a class="spec-record-ref" data-req="SWS_Dcm_00140" href="../../spec/record.html?id=SWS_Dcm_00140">[SWS_Dcm_00140]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_STD_SECTION_9_2_2_Update_Diagnostic_Session_Control_when_timeout_occurs.html" data-snip="SNIP_CLASSIC_STD_SECTION_9_2_2_Update_Diagnostic_Session_Control_when_timeout_occurs">SWS DCM S. 492</a>),</li>
<li>wenn die Anwendung <code>Dcm_ResetToDefaultSession</code> aufruft <a class="spec-record-ref" data-req="SWS_Dcm_01062" href="../../spec/record.html?id=SWS_Dcm_01062">[SWS_Dcm_01062]</a>.</li>
</ul>
<p>Ein Sitzungswechsel hat Nebenwirkungen:</p>
<ul>
<li>Aktive IO-Kontrollen werden beendet <a class="spec-record-ref" data-req="SWS_Dcm_00858" href="../../spec/record.html?id=SWS_Dcm_00858">[SWS_Dcm_00858]</a>.</li>
<li>In der Default-Sitzung stoppen periodische DIDs <a class="spec-record-ref" data-req="SWS_Dcm_01107" href="../../spec/record.html?id=SWS_Dcm_01107">[SWS_Dcm_01107]</a>.</li>
<li>Gestartete ROE-Ereignisse wechseln nach „ROE stopped“ <a class="spec-record-ref" data-req="SWS_Dcm_00879" href="../../spec/record.html?id=SWS_Dcm_00879">[SWS_Dcm_00879]</a>.</li>
</ul>

<p><strong>Beim Empfang.</strong></p>
