<p class="ai-level ai-oneliner-lead" data-ai-level="1">Nimmt Diagnoseanfragen von Testern entgegen, prüft sie und beantwortet sie mit Daten aus Fehlerspeicher und Anwendung.</p>
<div class="ai-level" data-ai-level="2">
<p>Der DCM ist der Diagnose-Server des Steuergeräts: Er empfängt UDS- und OBD-Anfragen über den PduR, prüft sie und lässt sie vom DSP oder von Anwendungs-Callouts ausführen. Erst nach vollständigem Empfang wird eine Anfrage weitergereicht <a class="spec-record-ref" data-req="SWS_Dcm_00111" href="../../spec/record.html?id=SWS_Dcm_00111">[SWS_Dcm_00111]</a>. Zuvor prüft der DSD Dienst, Sitzung, Security-Level und Modusbedingungen. Dauert die Bearbeitung zu lange, hält der DCM die P2-Zeitschranken mit NRC 0x78 ein <a class="spec-record-ref" data-req="SWS_Dcm_00024" href="../../spec/record.html?id=SWS_Dcm_00024">[SWS_Dcm_00024]</a>. Senden darf er nur in den vom ComM freigegebenen Kommunikationsmodi.</p>

</div>
<div class="ai-level" data-ai-level="3">
<p>Der DCM bearbeitet die Diagnoseanfragen externer Tester. Er implementiert UDS-Dienste wie DiagnosticSessionControl, ReadDataByIdentifier und RoutineControl <a class="spec-record-ref" data-req="SWS_Dcm_00250" href="../../spec/record.html?id=SWS_Dcm_00250">[SWS_Dcm_00250]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00253" href="../../spec/record.html?id=SWS_Dcm_00253">[SWS_Dcm_00253]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00257" href="../../spec/record.html?id=SWS_Dcm_00257">[SWS_Dcm_00257]</a> sowie OBD-Dienste <a class="spec-record-ref" data-req="SWS_Dcm_00243" href="../../spec/record.html?id=SWS_Dcm_00243">[SWS_Dcm_00243]</a>. Intern verwaltet die DSL Kommunikation und Zeiten <a class="spec-record-ref" data-req="SWS_Dcm_00027" href="../../spec/record.html?id=SWS_Dcm_00027">[SWS_Dcm_00027]</a>, der DSD prüft und verteilt Anfragen <a class="spec-record-ref" data-req="SWS_Dcm_00178" href="../../spec/record.html?id=SWS_Dcm_00178">[SWS_Dcm_00178]</a>, und der DSP führt die Dienste aus. Daten holt der DCM vom DEM, aus Anwendungs-Callouts und über RTE-Ports <a class="spec-record-ref" data-req="SWS_Dcm_01263" href="../../spec/record.html?id=SWS_Dcm_01263">[SWS_Dcm_01263]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00793" href="../../spec/record.html?id=SWS_Dcm_00793">[SWS_Dcm_00793]</a>.</p>

<h4>Rolle im Diagnose-Stack: DSL, DSD und DSP</h4>
<p>Der DCM beantwortet Diagnoseanfragen externer Tester. Er implementiert UDS-Dienste wie DiagnosticSessionControl (0x10), ReadDataByIdentifier (0x22) und RoutineControl (0x31) <a class="spec-record-ref" data-req="SWS_Dcm_00250" href="../../spec/record.html?id=SWS_Dcm_00250">[SWS_Dcm_00250]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00253" href="../../spec/record.html?id=SWS_Dcm_00253">[SWS_Dcm_00253]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00257" href="../../spec/record.html?id=SWS_Dcm_00257">[SWS_Dcm_00257]</a> sowie OBD-Dienste wie $01 <a class="spec-record-ref" data-req="SWS_Dcm_00243" href="../../spec/record.html?id=SWS_Dcm_00243">[SWS_Dcm_00243]</a>. Intern besteht er aus drei Submodulen:</p>
<ul>
<li>Die <strong>DSL</strong> verwaltet Empfang, Senden und die Protokollzeiten nach ISO 14229-2 <a class="spec-record-ref" data-req="SWS_Dcm_00027" href="../../spec/record.html?id=SWS_Dcm_00027">[SWS_Dcm_00027]</a>.</li>
<li>Der <strong>DSD</strong> prüft und verteilt Anfragen <a class="spec-record-ref" data-req="SWS_Dcm_00178" href="../../spec/record.html?id=SWS_Dcm_00178">[SWS_Dcm_00178]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00221" href="../../spec/record.html?id=SWS_Dcm_00221">[SWS_Dcm_00221]</a>.</li>
<li>Der <strong>DSP</strong> führt die Dienste aus und stellt die Antwortdaten zusammen <a class="spec-record-ref" data-req="SWS_Dcm_00039" href="../../spec/record.html?id=SWS_Dcm_00039">[SWS_Dcm_00039]</a>.</li>
</ul>
<p>Nach unten stellt der DCM Callbacks für PduR (Transportdaten) und ComM (Kommunikationsmodi) bereit. Das Schaubild <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-05c7c208dffe7fa6.html" data-snip="FIG-05c7c208dffe7fa6">SWS DCM S. 209</a> verwendet dafür noch ältere Namen wie Dcm_RxIndication. Normativ sind in R20-11 die Namen <code>Dcm_TpRxIndication</code> und <code>Dcm_ComM_NoComModeEntered</code> <a class="spec-record-ref" data-req="SWS_Dcm_00093" href="../../spec/record.html?id=SWS_Dcm_00093">[SWS_Dcm_00093]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00356" href="../../spec/record.html?id=SWS_Dcm_00356">[SWS_Dcm_00356]</a>.</p>

<ul>

<li>Anwendungsdaten und Routinen erreicht er über konfigurierbare Callouts und Ports wie <code>Xxx_ReadData</code> oder <code>Xxx_Start</code> <a class="spec-record-ref" data-req="SWS_Dcm_00793" href="../../spec/record.html?id=SWS_Dcm_00793">[SWS_Dcm_00793]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01203" href="../../spec/record.html?id=SWS_Dcm_01203">[SWS_Dcm_01203]</a>.</li>

<li>Das Security-Level ist <code>DCM_SEC_LEV_LOCKED</code> <a class="spec-record-ref" data-req="SWS_Dcm_00033" href="../../spec/record.html?id=SWS_Dcm_00033">[SWS_Dcm_00033]</a>.</li>
<li>Die Default Session ist aktiv <a class="spec-record-ref" data-req="SWS_Dcm_00034" href="../../spec/record.html?id=SWS_Dcm_00034">[SWS_Dcm_00034]</a>.</li>
<li>Alle ROE-Ereignisse stehen auf „ROE cleared“ <a class="spec-record-ref" data-req="SWS_Dcm_00872" href="../../spec/record.html?id=SWS_Dcm_00872">[SWS_Dcm_00872]</a>.</li>
<li>ActiveDiagnostic steht auf <code>DCM_COMM_ACTIVE</code> <a class="spec-record-ref" data-req="SWS_Dcm_01069" href="../../spec/record.html?id=SWS_Dcm_01069">[SWS_Dcm_01069]</a>.</li>
</ul>
<p>Weitere Startaufgaben hängen von der Konfiguration ab:</p>
<ul>
<li><code>Dcm_GetProgConditions</code> erkennt eine Rückkehr aus dem Bootloader <a class="spec-record-ref" data-req="SWS_Dcm_00536" href="../../spec/record.html?id=SWS_Dcm_00536">[SWS_Dcm_00536]</a>.</li>
<li>Bei <code>DcmDDDIDStorage</code> = TRUE werden DDDID-Definitionen aus dem NvM wiederhergestellt <a class="spec-record-ref" data-req="SWS_Dcm_00867" href="../../spec/record.html?id=SWS_Dcm_00867">[SWS_Dcm_00867]</a>.</li>
<li>Fehlversuchszähler werden über <code>Xxx_GetSecurityAttemptCounter</code> gelesen <a class="spec-record-ref" data-req="SWS_Dcm_01154" href="../../spec/record.html?id=SWS_Dcm_01154">[SWS_Dcm_01154]</a>.</li>
<li>Bei konfiguriertem <code>DcmVinRef</code> wird die VIN einmalig mit <code>Dcm_GetVin</code> geholt <a class="spec-record-ref" data-req="SWS_Dcm_01174" href="../../spec/record.html?id=SWS_Dcm_01174">[SWS_Dcm_01174]</a>.</li>
</ul>
<p><code>Dcm_MainFunction</code> <a class="spec-record-ref" data-req="SWS_Dcm_00053" href="../../spec/record.html?id=SWS_Dcm_00053">[SWS_Dcm_00053]</a> treibt alle asynchronen Abläufe. Gibt eine Operation <code>DCM_E_PENDING</code> zurück, wird sie etwa im nächsten MainFunction-Zyklus erneut angestoßen <a class="spec-record-ref" data-req="SWS_Dcm_00760" href="../../spec/record.html?id=SWS_Dcm_00760">[SWS_Dcm_00760]</a>. Interpretation: Die Funktion dürfte vom BSW-Scheduler zyklisch aufgerufen werden.</p>

<h4>Von der Anfrage zur Antwort</h4>
<p>Der Empfang verläuft in drei Schritten (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DCM_SECTION_7_2_4_2_Forward_requests_from_the_PduR_module_to_the_DSD_submodule.html" data-snip="SNIP_CLASSIC_DCM_SECTION_7_2_4_2_Forward_requests_from_the_PduR_module_to_the_DSD_submodule">SWS DCM S. 55</a>):</p>
<ol>
<li><code>Dcm_StartOfReception</code> meldet die Gesamtlänge, den ersten Frame und die Metadaten <a class="spec-record-ref" data-req="SWS_Dcm_00094" href="../../spec/record.html?id=SWS_Dcm_00094">[SWS_Dcm_00094]</a>. Ist die Anfrage zu groß, liefert der DCM <code>BUFREQ_E_OVFL</code> <a class="spec-record-ref" data-req="SWS_Dcm_00444" href="../../spec/record.html?id=SWS_Dcm_00444">[SWS_Dcm_00444]</a>. Bei Länge 0 liefert er <code>BUFREQ_E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_Dcm_00642" href="../../spec/record.html?id=SWS_Dcm_00642">[SWS_Dcm_00642]</a>.</li>
<li><code>Dcm_CopyRxData</code> kopiert die Segmente in den DCM-Puffer <a class="spec-record-ref" data-req="SWS_Dcm_00443" href="../../spec/record.html?id=SWS_Dcm_00443">[SWS_Dcm_00443]</a>.</li>
<li>Erst nach <code>Dcm_TpRxIndication</code> mit <code>E_OK</code> leitet die DSL die Anfrage an den DSD weiter <a class="spec-record-ref" data-req="SWS_Dcm_00111" href="../../spec/record.html?id=SWS_Dcm_00111">[SWS_Dcm_00111]</a>.</li>
</ol>
<p>Der DSD prüft die Anfrage in mehreren Stufen:</p>
<ul>
<li>Er sucht den Service-Identifier in der aktiven Service-Tabelle; fehlt er, folgt eine negative Antwort <a class="spec-record-ref" data-req="SWS_Dcm_00196" href="../../spec/record.html?id=SWS_Dcm_00196">[SWS_Dcm_00196]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00197" href="../../spec/record.html?id=SWS_Dcm_00197">[SWS_Dcm_00197]</a>.</li>
<li>Er prüft Sitzung, Security-Level und Modusbedingungen <a class="spec-record-ref" data-req="SWS_Dcm_00211" href="../../spec/record.html?id=SWS_Dcm_00211">[SWS_Dcm_00211]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00217" href="../../spec/record.html?id=SWS_Dcm_00217">[SWS_Dcm_00217]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00773" href="../../spec/record.html?id=SWS_Dcm_00773">[SWS_Dcm_00773]</a>.</li>
<li>Die Gesamtreihenfolge der Prüfungen folgt ISO 14229-1 <a class="spec-record-ref" data-req="SWS_Dcm_00827" href="../../spec/record.html?id=SWS_Dcm_00827">[SWS_Dcm_00827]</a>.</li>
<li>Konfigurierte Hersteller- und Zulieferer-Benachrichtigungen (<code>Xxx_Indication</code>) können eine Anfrage ablehnen <a class="spec-record-ref" data-req="SWS_Dcm_00218" href="../../spec/record.html?id=SWS_Dcm_00218">[SWS_Dcm_00218]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00516" href="../../spec/record.html?id=SWS_Dcm_00516">[SWS_Dcm_00516]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01341" href="../../spec/record.html?id=SWS_Dcm_01341">[SWS_Dcm_01341]</a>.</li>
</ul>

<h4>Anwendungsschnittstellen, OpStatus und Response Pending</h4>
<p>Asynchrone Schnittstellen tragen einen <code>Dcm_OpStatusType</code> <a class="spec-record-ref" data-req="SWS_Dcm_00984" href="../../spec/record.html?id=SWS_Dcm_00984">[SWS_Dcm_00984]</a>:</p>
<ul>
<li>Der erste Aufruf erfolgt mit <code>DCM_INITIAL</code> <a class="spec-record-ref" data-req="SWS_Dcm_00527" href="../../spec/record.html?id=SWS_Dcm_00527">[SWS_Dcm_00527]</a>.</li>
<li>Nach <code>DCM_E_PENDING</code> folgt ein erneuter Aufruf mit <code>DCM_PENDING</code> <a class="spec-record-ref" data-req="SWS_Dcm_00530" href="../../spec/record.html?id=SWS_Dcm_00530">[SWS_Dcm_00530]</a>.</li>
<li>Bei Abbruch wird mit <code>DCM_CANCEL</code> aufgerufen; dessen Rückgabewerte werden ignoriert <a class="spec-record-ref" data-req="SWS_Dcm_01413" href="../../spec/record.html?id=SWS_Dcm_01413">[SWS_Dcm_01413]</a>.</li>
<li>Ausgabedaten und ErrorCode gelten erst nach dem letzten Aufruf <a class="spec-record-ref" data-req="SWS_Dcm_01187" href="../../spec/record.html?id=SWS_Dcm_01187">[SWS_Dcm_01187]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01188" href="../../spec/record.html?id=SWS_Dcm_01188">[SWS_Dcm_01188]</a>.</li>
</ul>
<p>Ob die synchrone oder die asynchrone Variante gilt, legt die Konfiguration fest (<code>DcmDspDataUsePort</code>). Ein Beispiel ist <code>Xxx_ReadData</code> <a class="spec-record-ref" data-req="SWS_Dcm_00793" href="../../spec/record.html?id=SWS_Dcm_00793">[SWS_Dcm_00793]</a> <a class="spec-record-ref" data-req="SWS_Dcm_91006" href="../../spec/record.html?id=SWS_Dcm_91006">[SWS_Dcm_91006]</a>.</p>
<p>Braucht die Anwendung mehr Zeit, sendet der DCM NRC 0x78 <a class="spec-record-ref" data-req="SWS_Dcm_00024" href="../../spec/record.html?id=SWS_Dcm_00024">[SWS_Dcm_00024]</a>, um die Zeitschranken P2ServerMax und P2*ServerMax einzuhalten <a class="spec-record-ref" data-req="SWS_Dcm_00027" href="../../spec/record.html?id=SWS_Dcm_00027">[SWS_Dcm_00027]</a>. Die Zahl solcher Antworten ist begrenzt und konfigurierbar <a class="spec-record-ref" data-req="SWS_Dcm_00120" href="../../spec/record.html?id=SWS_Dcm_00120">[SWS_Dcm_00120]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01567" href="../../spec/record.html?id=SWS_Dcm_01567">[SWS_Dcm_01567]</a>. Die Anwendung kann NRC 0x78 auch selbst anstoßen: Sie gibt <code>DCM_E_FORCE_RCRRP</code> zurück und wird nach der Sendebestätigung erneut aufgerufen <a class="spec-record-ref" data-req="SWS_Dcm_00528" href="../../spec/record.html?id=SWS_Dcm_00528">[SWS_Dcm_00528]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00529" href="../../spec/record.html?id=SWS_Dcm_00529">[SWS_Dcm_00529]</a>. Speicher-Callouts verhalten sich analog <a class="spec-record-ref" data-req="SWS_Dcm_00839" href="../../spec/record.html?id=SWS_Dcm_00839">[SWS_Dcm_00839]</a>.</p>

<h4>Sitzungen, Security Access und Kommunikationsmodi</h4>
<p>Sitzungswechsel laufen über Dienst 0x10:</p>
<ul>
<li>Ein nicht konfigurierter Sitzungstyp führt zu NRC 0x12 <a class="spec-record-ref" data-req="SWS_Dcm_00307" href="../../spec/record.html?id=SWS_Dcm_00307">[SWS_Dcm_00307]</a>.</li>
<li>Erst in der Sendebestätigung setzt der DCM die neue Sitzung, die neuen P2-Werte und den Modus DcmDiagnosticSessionControl <a class="spec-record-ref" data-req="SWS_Dcm_00311" href="../../spec/record.html?id=SWS_Dcm_00311">[SWS_Dcm_00311]</a>.</li>
<li>Zurück in die Default Session führen der S3Server-Timeout <a class="spec-record-ref" data-req="SWS_Dcm_00140" href="../../spec/record.html?id=SWS_Dcm_00140">[SWS_Dcm_00140]</a> oder <code>Dcm_ResetToDefaultSession</code> <a class="spec-record-ref" data-req="SWS_Dcm_00520" href="../../spec/record.html?id=SWS_Dcm_00520">[SWS_Dcm_00520]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01062" href="../../spec/record.html?id=SWS_Dcm_01062">[SWS_Dcm_01062]</a>.</li>
<li>Beim Wechsel in die Default Session stoppt der DCM IO-Controls und periodische DIDs <a class="spec-record-ref" data-req="SWS_Dcm_00628" href="../../spec/record.html?id=SWS_Dcm_00628">[SWS_Dcm_00628]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01107" href="../../spec/record.html?id=SWS_Dcm_01107">[SWS_Dcm_01107]</a>.</li>
<li>Beim Verlassen einer Sitzung gehen gestartete ROE-Ereignisse in „ROE stopped“ <a class="spec-record-ref" data-req="SWS_Dcm_00879" href="../../spec/record.html?id=SWS_Dcm_00879">[SWS_Dcm_00879]</a>.</li>
<li>ComM wird über aktive oder inaktive Diagnose informiert <a class="spec-record-ref" data-req="SWS_Dcm_01376" href="../../spec/record.html?id=SWS_Dcm_01376">[SWS_Dcm_01376]</a> <a class="spec-record-ref" data-req="SWS_Dcm_01377" href="../../spec/record.html?id=SWS_Dcm_01377">[SWS_Dcm_01377]</a>.</li>
</ul>

<h4>Verhalten im Fehlerfall</h4>
<p>Fehler werden meist in negative Antworten übersetzt. Wo kein spezieller Code vorgesehen ist, sendet der DCM NRC 0x10 <a class="spec-record-ref" data-req="SWS_Dcm_00271" href="../../spec/record.html?id=SWS_Dcm_00271">[SWS_Dcm_00271]</a>. Die einzelnen Fälle:</p>
<ul>
<li><strong>Empfang:</strong> Bei <code>Dcm_TpRxIndication</code> mit einem Ergebnis ungleich <code>E_OK</code> wertet der DCM die Daten nicht aus <a class="spec-record-ref" data-req="SWS_Dcm_00344" href="../../spec/record.html?id=SWS_Dcm_00344">[SWS_Dcm_00344]</a>.</li>
<li><strong>Senden:</strong> Nach <code>Dcm_TpTxConfirmation</code> gibt der DCM den Sendepuffer frei und beendet die Zeitüberwachung <a class="spec-record-ref" data-req="SWS_Dcm_00352" href="../../spec/record.html?id=SWS_Dcm_00352">[SWS_Dcm_00352]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00353" href="../../spec/record.html?id=SWS_Dcm_00353">[SWS_Dcm_00353]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_5_3_5_2_3_DCM.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_5_3_5_2_3_DCM">ErrorDescription S. 26</a>).</li>
<li><strong>Anwendung:</strong> <code>E_NOT_OK</code> oder <code>DCM_READ_FAILED</code> führen zu einer NRC mit dem Wert aus ErrorCode <a class="spec-record-ref" data-req="SWS_Dcm_00678" href="../../spec/record.html?id=SWS_Dcm_00678">[SWS_Dcm_00678]</a> <a class="spec-record-ref" data-req="SWS_Dcm_00644" href="../../spec/record.html?id=SWS_Dcm_00644">[SWS_Dcm_00644]</a>.
