<h4>Context</h4>
<p>The namespace <code>ara::idsm</code> provides the interface for the Intrusion Detection System Management (IdsM) within the AUTOSAR Adaptive Platform. The IdsM serves to detect, record, and forward security-relevant events (Security Events) throughout the overall vehicle network. Adaptive applications, communication stacks, and platform services act as decentralized security sensors that report suspicious activities or logged rule violations to the central IdsM subsystem.</p>

<p>Within the namespace, class <code>EventReporter</code> assumes the central role in transmitting security events to the IdsM. In order to enrich event reports with relevant metadata, the reporter collaborates with other specialized components:</p>
<ul>
<li><code>ContextDataProvider</code> provides mutable, sensor-specific context data that is passed to the IdsM as a raw data sequence via <a class="spec-record-ref" data-req="SWS_AIDSM_10201" href="../spec/record.html?id=SWS_AIDSM_10201">[SWS_AIDSM_10201]</a> <code>ContextDataType</code> (type alias for <code>ara::core::Span&lt;const std::uint8_t&gt;</code>) or in versioned form as <a class="spec-record-ref" data-req="SWS_AIDSM_10206" href="../spec/record.html?id=SWS_AIDSM_10206">[SWS_AIDSM_10206]</a> <code>VersionedContextDataType</code>.</li>
<li><code>TimestampProvider</code> provides high-precision or sensor-specific timestamps via the type <a class="spec-record-ref" data-req="SWS_AIDSM_10202" href="../spec/record.html?id=SWS_AIDSM_10202">[SWS_AIDSM_10202]</a> <code>TimestampType</code> (64-bit integer) to enable temporal correlation of events.</li>
<li><code>ReportingModeProvider</code> controls the reporting behavior of the sensors based on the enumeration <a class="spec-record-ref" data-req="SWS_AIDSM_10207" href="../spec/record.html?id=SWS_AIDSM_10207">[SWS_AIDSM_10207]</a> <code>ReportingModeType</code>.</li>
<li><code>QualifiedEventsReceiver</code> enables higher-level analysis or response modules to receive security events qualified by the IdsM for further processing.</li>
<li><code>IdsmErrorDomain</code> and <code>IdsmException</code> define the error semantics of the namespace.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical monitoring sequence comprises querying the active operating mode, preparing the event data, and subsequently reporting to the IdsM:</p>
<ol>
<li><strong>Query reporting mode:</strong> Before an application performs computationally intensive context analyses or transmits events, it reads the current reporting mode via <code>ReportingModeProvider</code>. According to <a class="spec-record-ref" data-req="SWS_AIDSM_10207" href="../spec/record.html?id=SWS_AIDSM_10207">[SWS_AIDSM_10207]</a>, five modes of the enumeration <code>ReportingModeType</code> are available:
<ul>
<li><code>ReportingModeType::kOff</code>: Event reporting is completely deactivated.</li>
<li><code>ReportingModeType::kBrief</code>: Reduced event reporting without detailed context data.</li>
<li><code>ReportingModeType::kDetailed</code>: Detailed reporting including all available context data.</li>
<li><code>ReportingModeType::kBriefBypassingFilters</code>: Reduced reporting bypassing local filtering mechanisms.</li>
<li><code>ReportingModeType::kDetailedBypassingFilters</code>: Full reporting bypassing local filtering mechanisms.</li>
</ul>
Interpretation: The fine-grained distinction of reporting modes presumably allows the overall system to dynamically adapt the transmission volume to the current bus load and threat situation.</li>
<li><strong>Prepare event data:</strong> The specific event is identified via a 16-bit integer of type <a class="spec-record-ref" data-req="SWS_AIDSM_10205" href="../spec/record.html?id=SWS_AIDSM_10205">[SWS_AIDSM_10205]</a> <code>EventIdType</code>. If multiple events of the same type have been prequalified, the count can be specified via <a class="spec-record-ref" data-req="SWS_AIDSM_10203" href="../spec/record.html?id=SWS_AIDSM_10203">[SWS_AIDSM_10203]</a> <code>CountType</code>. In addition, timestamps can be determined via <code>TimestampProvider</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10202" href="../spec/record.html?id=SWS_AIDSM_10202">[SWS_AIDSM_10202]</a>) and payload data via <code>ContextDataProvider</code> (<a class="spec-record-ref" data-req="SWS_AIDSM_10201" href="../spec/record.html?id=SWS_AIDSM_10201">[SWS_AIDSM_10201]</a> or <a class="spec-record-ref" data-req="SWS_AIDSM_10206" href="../spec/record.html?id=SWS_AIDSM_10206">[SWS_AIDSM_10206]</a>, respectively).</li>
<li><strong>Report event:</strong> The application passes the data to <code>EventReporter</code>. Interpretation: The handover to the IdsM subsystem is presumably asynchronous in order not to block the execution paths of time-critical sensor applications.</li>
<li><strong>Receive qualified events:</strong> Registered modules receive qualified events via <code>QualifiedEventsReceiver</code> to initiate vehicle-wide security responses.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Error handling in namespace <code>ara::idsm</code> follows the AUTOSAR Adaptive standard via error domains and result types:</p>
<ul>
<li><strong>Error domain and factory functions:</strong> The function <a class="spec-record-ref" data-req="SWS_AIDSM_10702" href="../spec/record.html?id=SWS_AIDSM_10702">[SWS_AIDSM_10702]</a> <code>GetIdsmErrorDomain()</code> returns a reference to the static <code>ara::core::ErrorDomain</code> of domain <code>IdsmErrorDomain</code>. It is specified as <code>constexpr</code>, <code>noexcept</code>, and thread-safe. Error codes are created using <a class="spec-record-ref" data-req="SWS_AIDSM_10703" href="../spec/record.html?id=SWS_AIDSM_10703">[SWS_AIDSM_10703]</a> <code>MakeErrorCode()</code> by specifying a value from <code>IdsmErrc</code> and optional support data (<code>ara::core::ErrorDomain::SupportDataType</code>).</li>
<li><strong>Specific error codes:</strong> According to <a class="spec-record-ref" data-req="SWS_AIDSM_10204" href="../spec/record.html?id=SWS_AIDSM_10204">[SWS_AIDSM_10204]</a>, the enumeration <code>IdsmErrc</code> defines the code <code>kUnknownEventId = 3</code>. This error occurs when an event is reported with a <code>EventIdType</code> that is not known to the IdsM or not configured in the manifest.</li>
<li><strong>Exception handling:</strong> If module APIs throw exceptions, the typed error <code>IdsmException</code> is used, which encapsulates the associated <code>ara::core::ErrorCode</code>.</li>
</ul>
