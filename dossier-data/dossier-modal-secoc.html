<p class="ai-level ai-oneliner-lead" data-ai-level="1">Sichert I-PDUs mit Authenticator und Freshness Value gegen Manipulation und Replay neben dem PDU-Router ab.</p>
<div class="ai-level" data-ai-level="2">
<p>SecOC schützt I-PDUs gegen Manipulation und Replay. Dazu fügt es beim Senden einen Authenticator und einen Freshness Value an und prüft beides beim Empfang. Die Annahme einer PDU und die kryptographische Verarbeitung sind entkoppelt: Erst die zyklischen Hauptfunktionen authentifizieren beziehungsweise verifizieren in sechs Schritten (<a class="spec-record-ref" data-req="SWS_SecOC_00040" href="../../spec/record.html?id=SWS_SecOC_00040">[SWS_SecOC_00040]</a>). Die Kryptographie liefert der CSM, den Freshness Value ein externer Freshness Manager. Begrenzte Wiederholversuche entscheiden, wann eine empfangene PDU verworfen und ein Verifikationsstatus gemeldet wird (<a class="spec-record-ref" data-req="SWS_SecOC_00241" href="../../spec/record.html?id=SWS_SecOC_00241">[SWS_SecOC_00241]</a>).</p>
<p class="ai-level-more-inline"><button type="button" class="ai-level-step ai-level-more" data-ai-level-step="1" title="Ausführlichere Fassung zeigen">mehr ›</button></p>
</div>
<div class="ai-level" data-ai-level="3">
<p>SecOC sichert I-PDUs im Kommunikationsstapel ab. Es sitzt neben dem PduR und hängt an jede <em>Authentic I-PDU</em> den Authenticator und einen gegebenenfalls gekürzten Freshness Value an. So entsteht eine <em>Secured I-PDU</em> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_2_Relationship_to_PduR.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_2_Relationship_to_PduR">SWS SecOC S. 39</a>). Der Authenticator wird über Data Identifier, Nutzdaten und vollständigen Freshness Value berechnet (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_1_1_2_Data_covered_by_Authenticator.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_1_1_2_Data_covered_by_Authenticator">SWS SecOC S. 29</a>). Die Kryptographie liefert der CSM (<a class="spec-record-ref" data-req="SWS_SecOC_00138" href="../../spec/record.html?id=SWS_SecOC_00138">[SWS_SecOC_00138]</a>), den Freshness Value ein Freshness Manager über RTE oder C-Funktion (<a class="spec-record-ref" data-req="SWS_SecOC_91001" href="../../spec/record.html?id=SWS_SecOC_91001">[SWS_SecOC_91001]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00230" href="../../spec/record.html?id=SWS_SecOC_00230">[SWS_SecOC_00230]</a>).</p>

<p class="diagram-note">Kontextdiagramm: SecOC zwischen PduR, CSM, Freshness Manager, Anwendung, DET und IdsM. Quellen: <a class="spec-record-ref" data-req="SWS_SecOC_00138" href="../../spec/record.html?id=SWS_SecOC_00138">[SWS_SecOC_00138]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_91001" href="../../spec/record.html?id=SWS_SecOC_91001">[SWS_SecOC_91001]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00273" href="../../spec/record.html?id=SWS_SecOC_00273">[SWS_SecOC_00273]</a></p>
<p>Senden und Empfangen sind entkoppelt. Bei <code>SecOC_[If|Tp]Transmit</code> kopiert SecOC nur die Nutzdaten. Erst die zyklische <code>SecOC_MainFunctionTx</code> berechnet die Authentication Information und stößt die Übertragung über den PduR an (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_4_Authentication_of_outgoing_PDUs.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_4_Authentication_of_outgoing_PDUs">SWS SecOC S. 40</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00176" href="../../spec/record.html?id=SWS_SecOC_00176">[SWS_SecOC_00176]</a>). Empfangene Secured I-PDUs puffert SecOC vollständig und prüft sie in <code>SecOC_MainFunctionRx</code> in sechs Schritten, vom Parsen bis zur Weitergabe nach oben (<a class="spec-record-ref" data-req="SWS_SecOC_00040" href="../../spec/record.html?id=SWS_SecOC_00040">[SWS_SecOC_00040]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00255" href="../../spec/record.html?id=SWS_SecOC_00255">[SWS_SecOC_00255]</a>). Das Modul arbeitet nur im Zustand <code>SECOC_INIT</code>, den <code>SecOC_Init</code> herstellt und <code>SecOC_DeInit</code> wieder aufhebt (<a class="spec-record-ref" data-req="SWS_SecOC_00162" href="../../spec/record.html?id=SWS_SecOC_00162">[SWS_SecOC_00162]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00161" href="../../spec/record.html?id=SWS_SecOC_00161">[SWS_SecOC_00161]</a>).</p>
<p>Wiederholungen beim Empfang steuern zwei Zähler (<a class="spec-record-ref" data-req="SWS_SecOC_00237" href="../../spec/record.html?id=SWS_SecOC_00237">[SWS_SecOC_00237]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00239" href="../../spec/record.html?id=SWS_SecOC_00239">[SWS_SecOC_00239]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00240" href="../../spec/record.html?id=SWS_SecOC_00240">[SWS_SecOC_00240]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00241" href="../../spec/record.html?id=SWS_SecOC_00241">[SWS_SecOC_00241]</a>):</p>
<ul>
<li>Der Build-Zähler zählt vorübergehende Engpässe wie <code>E_BUSY</code>.</li>
<li>Der Verify-Zähler zählt fehlgeschlagene MAC-Vergleiche.</li>
<li>Erreicht einer sein Limit, wird die PDU verworfen.</li>
</ul>

<h4>Rolle neben dem PduR und Systemgrenze</h4>
<p>SecOC steht in der Schichtenarchitektur neben dem PDU-Router. Es überführt eine <em>Authentic I-PDU</em> in eine <em>Secured I-PDU</em>, indem es Authentication Information direkt hinter die Nutzdaten anfügt: den Authenticator und den gegebenenfalls gekürzten Freshness Value (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_2_Relationship_to_PduR.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_2_Relationship_to_PduR">SWS SecOC S. 39</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_4_1_Authentication_during_direct_transmission.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_4_1_Authentication_during_direct_transmission">SWS SecOC S. 43</a>). Kein anderes Modul darf von SecOC abhängen, sodass ein System auch ohne SecOC gebaut werden kann. MetaData einer Authentic PDU erscheinen unverändert in der Secured PDU und umgekehrt (<a class="spec-record-ref" data-req="SWS_SecOC_00212" href="../../spec/record.html?id=SWS_SecOC_00212">[SWS_SecOC_00212]</a>).</p>
<p>Der Authenticator wird über die Verkettung dreier Teile berechnet: <code>SecOCDataId</code>, gesicherter Teil der Authentic I-PDU und vollständiger Freshness Value (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_1_1_2_Data_covered_by_Authenticator.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_1_1_2_Data_covered_by_Authenticator">SWS SecOC S. 29</a>). Die Kryptographie liefert der CSM, etwa mit <code>Csm_MacGenerate</code> und <code>Csm_MacVerify</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00138" href="../../spec/record.html?id=SWS_SecOC_00138">[SWS_SecOC_00138]</a>). Den Freshness Value stellt ein Freshness Manager bereit, entweder über den RTE-Port <code>FreshnessManagement</code> oder über C-Funktionen (<a class="spec-record-ref" data-req="SWS_SecOC_91001" href="../../spec/record.html?id=SWS_SecOC_91001">[SWS_SecOC_91001]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00230" href="../../spec/record.html?id=SWS_SecOC_00230">[SWS_SecOC_00230]</a>). Weitere Empfänger von Meldungen sind:</p>
<ul>
<li>DET für Entwicklungs- und Laufzeitfehler (<a class="spec-record-ref" data-req="SWS_SecOC_00101" href="../../spec/record.html?id=SWS_SecOC_00101">[SWS_SecOC_00101]</a>),</li>
<li>der IdsM für Security Events (<a class="spec-record-ref" data-req="SWS_SecOC_00273" href="../../spec/record.html?id=SWS_SecOC_00273">[SWS_SecOC_00273]</a>),</li>
<li>Software-Komponenten für Verifikationsergebnisse (<a class="spec-record-ref" data-req="SWS_SecOC_00271" href="../../spec/record.html?id=SWS_SecOC_00271">[SWS_SecOC_00271]</a>).</li>
</ul>

<h4>Initialisierung, Modulzustand und zyklische Hauptfunktionen</h4>
<p>Der Modulzustand <code>SecOC_StateType</code> kennt <code>SECOC_UNINIT</code> und <code>SECOC_INIT</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00162" href="../../spec/record.html?id=SWS_SecOC_00162">[SWS_SecOC_00162]</a>).</p>
<ul>
<li><code>SecOC_Init</code> erhält eine implementierungsspezifische <code>SecOC_ConfigType</code> und führt bei Erfolg nach <code>SECOC_INIT</code>. Bei Zuordnung zu mehreren Partitionen ist je Partition eine Init-Funktion möglich (<a class="spec-record-ref" data-req="SWS_SecOC_00106" href="../../spec/record.html?id=SWS_SecOC_00106">[SWS_SecOC_00106]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00104" href="../../spec/record.html?id=SWS_SecOC_00104">[SWS_SecOC_00104]</a>).</li>
<li><code>SecOC_DeInit</code> verwirft alle gepufferten I-PDUs und setzt das Modul in den nicht initialisierten Zustand zurück (<a class="spec-record-ref" data-req="SWS_SecOC_00161" href="../../spec/record.html?id=SWS_SecOC_00161">[SWS_SecOC_00161]</a>). Dabei werden auch interne Variablen und Puffer gelöscht (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_8_3_2_SecOC_DeInit.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_8_3_2_SecOC_DeInit">SWS SecOC S. 65</a>).</li>
<li>Ein Aufruf ohne vorherige Initialisierung meldet <code>SECOC_E_UNINIT</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00101" href="../../spec/record.html?id=SWS_SecOC_00101">[SWS_SecOC_00101]</a>).</li>
</ul>
<p>Die eigentliche Verarbeitung leisten <code>SecOC_MainFunctionTx</code> und <code>SecOC_MainFunctionRx</code>. Je konfigurierter Instanz entsteht eine eigene Funktion <code>…_&lt;shortName&gt;</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00176" href="../../spec/record.html?id=SWS_SecOC_00176">[SWS_SecOC_00176]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00171" href="../../spec/record.html?id=SWS_SecOC_00171">[SWS_SecOC_00171]</a>). Ihre Periode ist konfigurierbar (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_5_SecOCMainFunctionTx.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_5_SecOCMainFunctionTx">SWS SecOC S. 130</a>, <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_4_SecOCMainFunctionRx.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_4_SecOCMainFunctionRx">SWS SecOC S. 129</a>). Jede <code>SecOCTxPduProcessing</code> läuft in der referenzierten Instanz (<a class="spec-record-ref" data-req="SWS_SecOC_00276" href="../../spec/record.html?id=SWS_SecOC_00276">[SWS_SecOC_00276]</a>).</p>

Andernfalls authentifiziert sie alle neuen Authentic I-PDUs im selben Aufruf und stößt deren Übertragung sofort über den PduR an (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_8_6_2_SecOC_MainFunctionTx.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_8_6_2_SecOC_MainFunctionTx">SWS SecOC S. 84</a>).</p>

<h4>Senden: vom Authentic zum Secured I-PDU</h4>
<p>Der Sendepfad ist entkoppelt und läuft in zwei Stufen ab (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_4_Authentication_of_outgoing_PDUs.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_4_Authentication_of_outgoing_PDUs">SWS SecOC S. 40</a>):</p>
<ol>
<li>Die obere Schicht ruft <code>PduR_&lt;Up&gt;Transmit</code>, der PduR ruft <code>SecOC_[If|Tp]Transmit</code>. SecOC kopiert die Authentic I-PDU vollständig in eigenen Speicher und kehrt zurück (<a class="spec-record-ref" data-req="SWS_SecOC_00252" href="../../spec/record.html?id=SWS_SecOC_00252">[SWS_SecOC_00252]</a>).</li>
<li>Im nächsten Lauf der Hauptfunktion entsteht die Secured I-PDU, und SecOC stößt ihre Übertragung über den PduR an.</li>
</ol>
<p>Bestätigungen der unteren Schicht gibt SecOC über <code>PduR_SecOC[If|Tp]TxConfirmation</code> nach oben weiter (<a class="spec-record-ref" data-req="SWS_SecOC_00063" href="../../spec/record.html?id=SWS_SecOC_00063">[SWS_SecOC_00063]</a>).</p>
<p>Die Authentifizierung umfasst sechs Schritte: vorbereiten, DataToAuthenticator bilden, Authenticator erzeugen, Secured I-PDU zusammensetzen, Freshness Counter erhöhen, senden. Data Id (16 Bit) und Freshness Value gehen dabei in Big Endian ein (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_1_2_Authentication_of_I_PDUs.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_1_2_Authentication_of_I_PDUs">SWS SecOC S. 33</a>).</p>
<p>Ist die Frischequelle eine C-Funktion (<code>CFUNC</code>), holt SecOC den Wert über <code>SecOC_GetTxFreshness</code>. Soll der Freshness Manager den gekürzten Wert selbst liefern, dient dazu <code>SecOC_GetTxFreshnessTruncData</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00231" href="../../spec/record.html?id=SWS_SecOC_00231">[SWS_SecOC_00231]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00230" href="../../spec/record.html?id=SWS_SecOC_00230">[SWS_SecOC_00230]</a>). Den Sendeanstoß meldet SecOC mit <code>SecOC_SPduTxConfirmation</code> beziehungsweise über RTE (<a class="spec-record-ref" data-req="SWS_SecOC_00232" href="../../spec/record.html?id=SWS_SecOC_00232">[SWS_SecOC_00232]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00233" href="../../spec/record.html?id=SWS_SecOC_00233">[SWS_SecOC_00233]</a>). Ungenutzte Bereiche werden mit <code>SecOCTxPduUnusedAreasDefault</code> gefüllt (<a class="spec-record-ref" data-req="SWS_SecOC_00269" href="../../spec/record.html?id=SWS_SecOC_00269">[SWS_SecOC_00269]</a>).</p>

<h4>Empfangen und Verifizieren</h4>
<p>Die Verifikation umfasst sechs Schritte (<a class="spec-record-ref" data-req="SWS_SecOC_00040" href="../../spec/record.html?id=SWS_SecOC_00040">[SWS_SecOC_00040]</a>):</p>
<ol>
<li>Authentic I-PDU, Freshness Value und Authenticator parsen,</li>
<li>Freshness Value beim Freshness Manager abfragen,</li>
<li>die zu prüfenden Daten bilden,</li>
<li>die Authentication Information prüfen,</li>
<li>den Freshness Manager bestätigen,</li>
<li>die Authentic I-PDU an die obere Schicht weiterreichen.</li>
</ol>
<p>SecOC kopiert die Secured I-PDU zunächst in eigenen Speicher und prüft sie im nächsten Lauf der Hauptfunktion (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_5_Verification_of_incoming_PDUs.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_5_Verification_of_incoming_PDUs">SWS SecOC S. 50</a>). Über Bus-Interfaces kommt sie per <code>SecOC_RxIndication</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00124" href="../../spec/record.html?id=SWS_SecOC_00124">[SWS_SecOC_00124]</a>). Ist eine I-PDU statischer Länge kürzer als konfiguriert, wird sie stillschweigend verworfen (<a class="spec-record-ref" data-req="SWS_SecOC_00268" href="../../spec/record.html?id=SWS_SecOC_00268">[SWS_SecOC_00268]</a>). Die Länge der Authentic I-PDU stammt aus der Konfiguration, von der unteren Schicht oder aus dem Header (<a class="spec-record-ref" data-req="SWS_SecOC_00257" href="../../spec/record.html?id=SWS_SecOC_00257">[SWS_SecOC_00257]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00258" href="../../spec/record.html?id=SWS_SecOC_00258">[SWS_SecOC_00258]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00259" href="../../spec/record.html?id=SWS_SecOC_00259">[SWS_SecOC_00259]</a>).</p>

<h4>Freshness Manager, Verifikationsstatus und Override</h4>
<p>SecOC verwaltet die Frische nicht selbst. Je nach <code>SecOCQueryFreshnessValue</code> (RTE oder CFUNC) und <code>SecOCUseAuthDataFreshness</code> fragt es <code>GetRxFreshness</code> oder <code>GetRxFreshnessAuthData</code> ab. Im zweiten Fall übergibt es zusätzlich einen konfigurierten Ausschnitt der empfangenen PDU (<a class="spec-record-ref" data-req="SWS_SecOC_00244" href="../../spec/record.html?id=SWS_SecOC_00244">[SWS_SecOC_00244]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00245" href="../../spec/record.html?id=SWS_SecOC_00245">[SWS_SecOC_00245]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00246" href="../../spec/record.html?id=SWS_SecOC_00246">[SWS_SecOC_00246]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00247" href="../../spec/record.html?id=SWS_SecOC_00247">[SWS_SecOC_00247]</a>). Mitgegeben werden außerdem der gekürzte Freshness Value und die Zahl der bisherigen Verifikationsversuche (<a class="spec-record-ref" data-req="SWS_SecOC_91007" href="../../spec/record.html?id=SWS_SecOC_91007">[SWS_SecOC_91007]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_91006" href="../../spec/record.html?id=SWS_SecOC_91006">[SWS_SecOC_91006]</a>).</p>
<p>Die Werte liegen als <code>SecOC_FreshnessArrayType</code> vor (<a class="spec-record-ref" data-req="SWS_SecOC_91012" href="../../spec/record.html?id=SWS_SecOC_91012">[SWS_SecOC_91012]</a>), mit dem höchstwertigen Bit im ersten Byte, also Big Endian (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_8_5_3_SecOC_GetTxFreshness.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_8_5_3_SecOC_GetTxFreshness">SWS SecOC S. 80</a>). Der Rückgabewert <code>E_BUSY</code> bedeutet, dass der Wert vorübergehend nicht verfügbar ist (<a class="spec-record-ref" data-req="SWS_SecOC_91002" href="../../spec/record.html?id=SWS_SecOC_91002">[SWS_SecOC_91002]</a>).</p>
<p>Das Ergebnis jedes Versuchs fasst <code>SecOC_VerificationStatusType</code> zusammen: <code>freshnessValueID</code> plus ein Wert aus <code>SecOC_VerificationResultType</code>, etwa <code>SECOC_FRESHNESSFAILURE</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00160" href="../../spec/record.html?id=SWS_SecOC_00160">[SWS_SecOC_00160]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00149" href="../../spec/record.html?id=SWS_SecOC_00149">[SWS_SecOC_00149]</a>). Gemeldet wird es je nach Modus <code>BOTH</code>, <code>FAILURE_ONLY</code> oder <code>NONE</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00271" href="../../spec/record.html?id=SWS_SecOC_00271">[SWS_SecOC_00271]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_91016" href="../../spec/record.html?id=SWS_SecOC_91016">[SWS_SecOC_91016]</a>). Optional wird nur der Endstatus weitergegeben (<a class="spec-record-ref" data-req="SWS_SecOC_00272" href="../../spec/record.html?id=SWS_SecOC_00272">[SWS_SecOC_00272]</a>). Der Freshness Manager erhält das Ergebnis per <code>SecOC_VerificationStatusCallout</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00119" href="../../spec/record.html?id=SWS_SecOC_00119">[SWS_SecOC_00119]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00243" href="../../spec/record.html?id=SWS_SecOC_00243">[SWS_SecOC_00243]</a>).</p>
<p><code>SecOC_VerifyStatusOverride</code> übersteuert die Verifikation gezielt (<a class="spec-record-ref" data-req="SWS_SecOC_00122" href="../../spec/record.html?id=SWS_SecOC_00122">[SWS_SecOC_00122]</a>). In R20-11 kennt <code>SecOC_OverrideStatusType</code> unter anderem <code>…DROP_UNTIL_NOTICE</code>, <code>…DROP_UNTIL_LIMIT</code>, <code>…CANCEL</code> und <code>…PASS_UNTIL_NOTICE</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00991" href="../../spec/record.html?id=SWS_SecOC_00991">[SWS_SecOC_00991]</a>). R23-11 ergänzt <code>…SKIP_UNTIL_LIMIT</code> und <code>…PASS_UNTIL_LIMIT</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_8_8_5_4_SecOC_OverrideStatusType.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_8_8_5_4_SecOC_OverrideStatusType">SWS SecOC S. 102</a>). Auf der Sendeseite schaltet <code>SecOC_SendDefaultAuthenticationInformation</code> das Default-Muster je Freshness Value ID ein oder aus (<a class="spec-record-ref" data-req="SWS_SecOC_91013" href="../../spec/record.html?id=SWS_SecOC_91013">[SWS_SecOC_91013]</a>).</p>

<h4>Konfiguration und Instanzbezug</h4>
<p>Die Konfiguration gliedert sich in drei Container:</p>
<ul>
<li><code>SecOCGeneral</code> für allgemeine Parameter, etwa <code>SecOCDefaultAuthenticationInformationPattern</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_2_SecOCGeneral.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_2_SecOCGeneral">SWS SecOC S. 124</a>),</li>
<li>je Sende-PDU ein <code>SecOCTxPduProcessing</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_14_SecOCTxPduProcessing.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_14_SecOCTxPduProcessing">SWS SecOC S. 155</a>),</li>
<li>je Empfangs-PDU ein <code>SecOCRxPduProcessing</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_7_SecOCRxPduProcessing.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_7_SecOCRxPduProcessing">SWS SecOC S. 140</a>).</li>
</ul>
<p>Zentrale Parameter sind <code>SecOCDataId</code>, <code>SecOCFreshnessValueId</code>, die Freshness- und Authenticator-Längen sowie die <code>CsmJob</code>-Referenz (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-dcde7205be9da3fd.html" data-snip="FIG-dcde7205be9da3fd">SWS SecOC S. 106</a>). Arbeitet ein CSM-Job asynchron, braucht SecOC dafür herstellerspezifische Callbacks (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_8_4_9_CSM_callback_interfaces.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_8_4_9_CSM_callback_interfaces">SWS SecOC S. 78</a>).</p>
<p>Einige Ports gibt es nur bei passender Konfiguration:</p>
<ul>
<li><code>SendDefaultAuthenticationInformation</code> nur, wenn ein Default-Muster gesetzt ist (<a class="spec-record-ref" data-req="SWS_SecOC_91020" href="../../spec/record.html?id=SWS_SecOC_91020">[SWS_SecOC_91020]</a>),</li>
<li><code>FreshnessManagement</code> nur bei Abfrage über RTE (<a class="spec-record-ref" data-req="SWS_SecOC_91001" href="../../spec/record.html?id=SWS_SecOC_91001">[SWS_SecOC_91001]</a>).</li>
</ul>
<p>Security Events werden nur gemeldet, wenn <code>SecOCEnableSecurityEventReporting</code> gesetzt ist (<a class="spec-record-ref" data-req="SWS_SecOC_00273" href="../../spec/record.html?id=SWS_SecOC_00273">[SWS_SecOC_00273]</a>).</p>

<h4>Verhalten im Fehlerfall</h4>
<p>Auf der Sendeseite gilt:</p>
<ul>
<li>Bei behebbaren CSM-Fehlern wie <code>E_BUSY</code> oder <code>QUEUE_FULL</code> behält SecOC die Authentic I-PDU und versucht es im nächsten Lauf erneut (<a class="spec-record-ref" data-req="SWS_SecOC_00151" href="../../spec/record.html?id=SWS_SecOC_00151">[SWS_SecOC_00151]</a>).</li>
<li>Ist das Versuchslimit erreicht, meldet es <code>SECOC_E_CRYPTO_FAILURE</code> an DET (<a class="spec-record-ref" data-req="SWS_SecOC_00155" href="../../spec/record.html?id=SWS_SecOC_00155">[SWS_SecOC_00155]</a>).</li>
<li>Bei erreichtem Limit, Freshness-<code>E_NOT_OK</code> oder einem nicht behebbaren Fehler verwendet SecOC das Default-Muster, sofern es freigegeben ist (<a class="spec-record-ref" data-req="SWS_SecOC_00229" href="../../spec/record.html?id=SWS_SecOC_00229">[SWS_SecOC_00229]</a>).</li>
<li>Ist kein Muster konfiguriert, bricht SecOC den Auftrag ab (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_10_1_2_SecOCGeneral.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_10_1_2_SecOCGeneral">SWS SecOC S. 124</a>).</li>
<li>Bei konfiguriertem, aber nicht freigegebenem Muster dürfte SecOC ebenso abbrechen.</li>
</ul>

<p>Abbrüche und Fehler der Nachbarschichten behandelt SecOC so:</p>
<ul>
<li><code>SecOC_[If|Tp]CancelTransmit</code> gibt SecOC sofort nach unten weiter und gibt alle Puffer frei (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SECOC_SECTION_7_4_4_Error_handling_and_cancelation_of_transmission.html" data-snip="SNIP_CLASSIC_SECOC_SECTION_7_4_4_Error_handling_and_cancelation_of_transmission">SWS SecOC S. 48</a>, <a class="spec-record-ref" data-req="SWS_SecOC_91009" href="../../spec/record.html?id=SWS_SecOC_91009">[SWS_SecOC_91009]</a>).</li>
<li>Meldet die untere Schicht <code>E_NOT_OK</code>, unterlässt SecOC lediglich die Bestätigung nach oben.</li>
<li>Liefert der Datenabruf beim TP-Senden <code>BUFREQ_E_BUSY</code>, wiederholt SecOC ihn im nächsten Lauf (<a class="spec-record-ref" data-req="SWS_SecOC_00260" href="../../spec/record.html?id=SWS_SecOC_00260">[SWS_SecOC_00260]</a>).</li>
<li><code>BUFREQ_E_NOT_OK</code> führt beim Senden wie beim Empfangen zum sofortigen Abbruch (<a class="spec-record-ref" data-req="SWS_SecOC_00266" href="../../spec/record.html?id=SWS_SecOC_00266">[SWS_SecOC_00266]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00267" href="../../spec/record.html?id=SWS_SecOC_00267">[SWS_SecOC_00267]</a>).</li>
</ul>
<p>Auf der Empfangsseite führt SecOC je PDU einen Build-Zähler und einen Verify-Zähler, beide beginnen bei 0 (<a class="spec-record-ref" data-req="SWS_SecOC_00234" href="../../spec/record.html?id=SWS_SecOC_00234">[SWS_SecOC_00234]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00235" href="../../spec/record.html?id=SWS_SecOC_00235">[SWS_SecOC_00235]</a>):</p>
<ul>
<li><code>E_BUSY</code> oder ein behebbarer CSM-Fehler erhöht den Build-Zähler; SecOC wiederholt im nächsten Lauf (<a class="spec-record-ref" data-req="SWS_SecOC_00236" href="../../spec/record.html?id=SWS_SecOC_00236">[SWS_SecOC_00236]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00237" href="../../spec/record.html?id=SWS_SecOC_00237">[SWS_SecOC_00237]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00238" href="../../spec/record.html?id=SWS_SecOC_00238">[SWS_SecOC_00238]</a>).</li>
<li>Erreicht der Build-Zähler sein Limit, folgt <code>SECOC_AUTHENTICATIONBUILDFAILURE</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00240" href="../../spec/record.html?id=SWS_SecOC_00240">[SWS_SecOC_00240]</a>).</li>
<li>Ein falscher MAC erhöht den Verify-Zähler und setzt den Build-Zähler zurück (<a class="spec-record-ref" data-req="SWS_SecOC_00239" href="../../spec/record.html?id=SWS_SecOC_00239">[SWS_SecOC_00239]</a>).</li>
<li>Bei erreichtem Verify-Limit oder einem harten Fehler gilt <code>SECOC_VERIFICATIONFAILURE</code>, bei Erfolg <code>SECOC_VERIFICATIONSUCCESS</code> (<a class="spec-record-ref" data-req="SWS_SecOC_00241" href="../../spec/record.html?id=SWS_SecOC_00241">[SWS_SecOC_00241]</a>, <a class="spec-record-ref" data-req="SWS_SecOC_00242" href="../../spec/record.html?id=SWS_SecOC_00242">[SWS_SecOC_00242]</a>).</li>
</ul>
