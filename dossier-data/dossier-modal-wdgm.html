<p class="ai-level ai-oneliner-lead" data-ai-level="1">Überwacht Ablauf und Timing der Software über Checkpoints und steuert davon abhängig das Triggern der Watchdogs.</p>
<div class="ai-level" data-ai-level="2">
<p>Der Watchdog Manager überwacht die Ausführung der Software. Supervised Entities melden Checkpoints über <code>WdgM_CheckpointReached</code> <a class="spec-record-ref" data-req="SWS_WdgM_00263" href="../../spec/record.html?id=SWS_WdgM_00263">[SWS_WdgM_00263]</a>. Die zyklische <code>WdgM_MainFunction</code> bewertet Alive-, Deadline- und Logical Supervision und verdichtet die Ergebnisse zu lokalen Status und einem globalen Status. Solange alles in Ordnung ist, setzt der WdgM über das Watchdog Interface eine gültige Triggerbedingung. Erreicht der globale Status STOPPED, triggert der Treiber nicht mehr, und ein Watchdog-Reset folgt <a class="spec-record-ref" data-req="SWS_WdgM_00360" href="../../spec/record.html?id=SWS_WdgM_00360">[SWS_WdgM_00360]</a>. Moduswechsel sind nur bei globalem Status OK oder FAILED zulässig.</p>

<div class="ai-level" data-ai-level="3">
<p>Der Watchdog Manager überwacht die Ausführung von Supervised Entities und lässt die Hardware-Watchdogs nur weiter triggern, solange die Überwachung in Ordnung ist. Das Trigger-Timing selbst liegt im Watchdog-Treiber. Der WdgM setzt über das Watchdog Interface nur eine Triggerbedingung (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling">SWS WdgM S. 56</a>). Zwingend benötigt er dafür <code>WdgIf_SetMode</code>, <code>WdgIf_SetTriggerCondition</code>, <code>GetElapsedValue</code> und <code>Det_ReportRuntimeError</code> <a class="spec-record-ref" data-req="SWS_WdgM_00161" href="../../spec/record.html?id=SWS_WdgM_00161">[SWS_WdgM_00161]</a>.</p>
<p>Nach <code>WdgM_Init</code> beginnt die Überwachung mit dem ersten Aufruf von <code>WdgM_MainFunction</code> <a class="spec-record-ref" data-req="SWS_WdgM_00406" href="../../spec/record.html?id=SWS_WdgM_00406">[SWS_WdgM_00406]</a>. Entities melden Checkpoints über <code>WdgM_CheckpointReached</code> <a class="spec-record-ref" data-req="SWS_WdgM_00263" href="../../spec/record.html?id=SWS_WdgM_00263">[SWS_WdgM_00263]</a>. Jeder Aufruf erhöht den Alive Counter und prüft sofort Deadline und Logical Supervision (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_8_3_6_WdgM_CheckpointReached.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_8_3_6_WdgM_CheckpointReached">SWS WdgM S. 79</a>). Die Hauptfunktion wertet zyklisch die Alive Counter und Deadline-Timeouts aus <a class="spec-record-ref" data-req="SWS_WdgM_00404" href="../../spec/record.html?id=SWS_WdgM_00404">[SWS_WdgM_00404]</a>.</p>

<p>Aus den Ergebnissen entsteht je Entity ein lokaler Status. FAILED ist dabei heilbar, EXPIRED nicht <a class="spec-record-ref" data-req="SWS_WdgM_00359" href="../../spec/record.html?id=SWS_WdgM_00359">[SWS_WdgM_00359]</a>. Daraus bildet der WdgM einen globalen Status, der über EXPIRED nach STOPPED eskaliert. In STOPPED triggert der Treiber nicht mehr, und ein Watchdog-Reset folgt <a class="spec-record-ref" data-req="SWS_WdgM_00360" href="../../spec/record.html?id=SWS_WdgM_00360">[SWS_WdgM_00360]</a>. Statusänderungen meldet der WdgM über lokale Mode-Ports und einen globalen Mode-Port <a class="spec-record-ref" data-req="SWS_WdgM_00197" href="../../spec/record.html?id=SWS_WdgM_00197">[SWS_WdgM_00197]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00198" href="../../spec/record.html?id=SWS_WdgM_00198">[SWS_WdgM_00198]</a>.</p>

<h4>Rolle: Software-Überwachung zwischen Supervised Entities und Hardware-Watchdog</h4>
<p>Der Watchdog Manager (WdgM) überwacht die Ausführung von Supervised Entities, also von SW-Cs, CDDs oder BSW-Abläufen. Abhängig vom Ergebnis entscheidet er, ob die Hardware-Watchdogs weiter getriggert werden. Das eigentliche Trigger-Timing liegt im Watchdog-Treiber. Der WdgM setzt über das Watchdog Interface nur eine Triggerbedingung, die den Treiber zum Weitertriggern anweist (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_4_Watchdog_Handling">SWS WdgM S. 56</a>). Zwingend benötigt er dafür <code>WdgIf_SetMode</code>, <code>WdgIf_SetTriggerCondition</code>, <code>GetElapsedValue</code> und <code>Det_ReportRuntimeError</code> <a class="spec-record-ref" data-req="SWS_WdgM_00161" href="../../spec/record.html?id=SWS_WdgM_00161">[SWS_WdgM_00161]</a>. Optional nutzt er <code>Dem_SetEventStatus</code>, <code>Det_ReportError</code>, <code>Mcu_PerformReset</code> und <code>BswM_WdgM_RequestPartitionReset</code> <a class="spec-record-ref" data-req="SWS_WdgM_00162" href="../../spec/record.html?id=SWS_WdgM_00162">[SWS_WdgM_00162]</a>.</p>
<p>Supervised Entities melden Checkpoints über <code>WdgM_CheckpointReached</code> <a class="spec-record-ref" data-req="SWS_WdgM_00263" href="../../spec/record.html?id=SWS_WdgM_00263">[SWS_WdgM_00263]</a>. Mode-Management-Module steuern den Lebenszyklus mit <code>WdgM_Init</code>, <code>WdgM_SetMode</code> und <code>WdgM_DeInit</code> <a class="spec-record-ref" data-req="SWS_WdgM_00151" href="../../spec/record.html?id=SWS_WdgM_00151">[SWS_WdgM_00151]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00154" href="../../spec/record.html?id=SWS_WdgM_00154">[SWS_WdgM_00154]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00261" href="../../spec/record.html?id=SWS_WdgM_00261">[SWS_WdgM_00261]</a>. Die zyklische Auswertung leistet <code>WdgM_MainFunction</code> aus <code>SchM_WdgM.h</code> <a class="spec-record-ref" data-req="SWS_WdgM_00159" href="../../spec/record.html?id=SWS_WdgM_00159">[SWS_WdgM_00159]</a>. Das Sicherheitskonzept ordnet dem WdgM die logische Programmflussüberwachung über Checkpoints und erlaubte Transitionen zu (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_SAFETYCONCEPTSTATUSREPORT_SECTION_01_AUTOSAR_SWS_Wat.html" data-snip="SNIP_CLASSIC_SAFETYCONCEPTSTATUSREPORT_SECTION_01_AUTOSAR_SWS_Wat">SafetyConceptStatusReport S. 15</a>).</p>

<h4>Lebenszyklus: Initialisierung, Moduswechsel und Deinitialisierung</h4>
<p>Der Global Supervision Status ist statisch mit <code>WDGM_GLOBAL_STATUS_DEACTIVATED</code> vorbelegt <a class="spec-record-ref" data-req="SWS_WdgM_00387" href="../../spec/record.html?id=SWS_WdgM_00387">[SWS_WdgM_00387]</a>. In diesem Zustand weisen Dienste mit <code>WDGM_E_UNINIT</code> ab oder kehren wirkungslos zurück <a class="spec-record-ref" data-req="SWS_WdgM_00253" href="../../spec/record.html?id=SWS_WdgM_00253">[SWS_WdgM_00253]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00395" href="../../spec/record.html?id=SWS_WdgM_00395">[SWS_WdgM_00395]</a>. <code>WdgM_Init</code> erhält einen Zeiger auf <code>WdgM_ConfigType</code> <a class="spec-record-ref" data-req="SWS_WdgM_00355" href="../../spec/record.html?id=SWS_WdgM_00355">[SWS_WdgM_00355]</a>. Die Funktion initialisiert alle Modulvariablen und stellt den Initial-Modus her (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_8_3_1_WdgM_Init.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_8_3_1_WdgM_Init">SWS WdgM S. 74</a>). Interpretation: Danach dürfte der globale Status <code>WDGM_GLOBAL_STATUS_OK</code> sein, weil die im Initial-Modus aktiven Entities lokal mit OK starten (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_FIGURE_Figure_7_2.html" data-snip="SNIP_CLASSIC_WDGM_FIGURE_Figure_7_2">SWS WdgM S. 30</a>).</p>
<p>Ein erneuter <code>WdgM_Init</code>-Aufruf außerhalb von DEACTIVATED bleibt ohne Wirkung <a class="spec-record-ref" data-req="SWS_WdgM_00390" href="../../spec/record.html?id=SWS_WdgM_00390">[SWS_WdgM_00390]</a>. Eine Re-Initialisierung erfolgt daher über <code>WdgM_DeInit</code> und anschließendes <code>WdgM_Init</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_8_3_1_WdgM_Init.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_8_3_1_WdgM_Init">SWS WdgM S. 74</a>). Überwachung und Watchdog Handling beginnen erst mit dem ersten Aufruf von <code>WdgM_MainFunction</code> nach der Initialisierung <a class="spec-record-ref" data-req="SWS_WdgM_00406" href="../../spec/record.html?id=SWS_WdgM_00406">[SWS_WdgM_00406]</a>.</p>
<p><code>WdgM_SetMode</code> wechselt in einen anderen konfigurierten Modus <a class="spec-record-ref" data-req="SWS_WdgM_00154" href="../../spec/record.html?id=SWS_WdgM_00154">[SWS_WdgM_00154]</a>, allerdings nur bei globalem Status OK oder FAILED <a class="spec-record-ref" data-req="SWS_WdgM_00145" href="../../spec/record.html?id=SWS_WdgM_00145">[SWS_WdgM_00145]</a>. Für Entities, die im neuen Modus deaktiviert sind, gilt:</p>
<ul>
<li>Sie wechseln nach <code>WDGM_LOCAL_STATUS_DEACTIVATED</code> <a class="spec-record-ref" data-req="SWS_WdgM_00315" href="../../spec/record.html?id=SWS_WdgM_00315">[SWS_WdgM_00315]</a>.</li>
<li>Ihre Ergebnisse gelten wieder als korrekt <a class="spec-record-ref" data-req="SWS_WdgM_00315" href="../../spec/record.html?id=SWS_WdgM_00315">[SWS_WdgM_00315]</a>.</li>
<li>Ihr Fehlzähler wird auf 0 gesetzt <a class="spec-record-ref" data-req="SWS_WdgM_00315" href="../../spec/record.html?id=SWS_WdgM_00315">[SWS_WdgM_00315]</a>.</li>
</ul>
<p>Aktiv bleibende Entities behalten ihren Zustand <a class="spec-record-ref" data-req="SWS_WdgM_00182" href="../../spec/record.html?id=SWS_WdgM_00182">[SWS_WdgM_00182]</a>. Für jeden Watchdog setzt der WdgM die Modusparameter über <code>WdgIf_SetMode</code> <a class="spec-record-ref" data-req="SWS_WdgM_00186" href="../../spec/record.html?id=SWS_WdgM_00186">[SWS_WdgM_00186]</a>. <h4>Checkpoints und die drei Überwachungsfunktionen</h4>
<p>Eine Supervised Entity meldet einen Checkpoint mit <code>WdgM_CheckpointReached(SEID, CheckpointID)</code> <a class="spec-record-ref" data-req="SWS_WdgM_00263" href="../../spec/record.html?id=SWS_WdgM_00263">[SWS_WdgM_00263]</a>. Beide Kennungen sind vom Typ <code>uint16</code>. Ein Checkpoint ist nur durch das Paar aus SE-ID und Checkpoint-ID eindeutig <a class="spec-record-ref" data-req="SWS_WdgM_00356" href="../../spec/record.html?id=SWS_WdgM_00356">[SWS_WdgM_00356]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00357" href="../../spec/record.html?id=SWS_WdgM_00357">[SWS_WdgM_00357]</a>. Der Aufruf leistet drei Dinge (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_8_3_6_WdgM_CheckpointReached.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_8_3_6_WdgM_CheckpointReached">SWS WdgM S. 79</a>):</p>
<ul>
<li>Er erhöht den Alive Counter des Checkpoints.</li>
<li>Er prüft die Deadline Supervision auf zu frühes oder zu spätes Eintreffen.</li>
<li>Er führt die Logical Supervision aus.</li>
</ul>
<p>Ist die Entity im aktuellen Modus deaktiviert, liefert der Dienst <code>E_NOT_OK</code> und meldet <code>WDGM_E_SEDEACTIVATED</code> <a class="spec-record-ref" data-req="SWS_WdgM_00319" href="../../spec/record.html?id=SWS_WdgM_00319">[SWS_WdgM_00319]</a>.</p>
<p><strong>Alive Supervision</strong> prüft zyklische Abläufe. Die Hauptfunktion wertet die Alive Counter im Takt der <code>WdgMSupervisionReferenceCycle</code> aus, einem Vielfachen des Supervision Cycle (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_2_1_2_Alive_Supervision_Algorithm.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_2_1_2_Alive_Supervision_Algorithm">SWS WdgM S. 42</a>). <strong>Deadline Supervision</strong> prüft, ob zwischen Start- und End-Checkpoint die Grenzen <code>WdgMDeadlineMin</code>/<code>WdgMDeadlineMax</code> eingehalten werden. Die Zeitstempel liefert <code>GetElapsedValue</code> mit dem OS-Counter der Entity; skaliert wird über <code>OsSecondsPerTick</code> <a class="spec-record-ref" data-req="SWS_WdgM_00373" href="../../spec/record.html?id=SWS_WdgM_00373">[SWS_WdgM_00373]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00374" href="../../spec/record.html?id=SWS_WdgM_00374">[SWS_WdgM_00374]</a>. Ist der Start-Zeitstempel 0, endet die Prüfung ohne Messung erfolgreich <a class="spec-record-ref" data-req="SWS_WdgM_00354" href="../../spec/record.html?id=SWS_WdgM_00354">[SWS_WdgM_00354]</a>. Fehlt der End-Checkpoint, erkennt <code>WdgM_MainFunction</code> einen Timeout, sofern <code>WdgMEnableTimeoutDetection</code> gesetzt ist <a class="spec-record-ref" data-req="SWS_WdgM_00403" href="../../spec/record.html?id=SWS_WdgM_00403">[SWS_WdgM_00403]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00404" href="../../spec/record.html?id=SWS_WdgM_00404">[SWS_WdgM_00404]</a>.</p>

<h4>Ports, Statusmeldungen und Abfragedienste</h4>
<p>Für jede Supervised Entity stellt der WdgM einen Supervision-Port bereit <a class="spec-record-ref" data-req="SWS_WdgM_00146" href="../../spec/record.html?id=SWS_WdgM_00146">[SWS_WdgM_00146]</a>. Er heißt <code>localSupervision_{SupervisedEntityCheckpointName}</code> und trägt SE-ID und Checkpoint-ID als port-definierte Argumente <a class="spec-record-ref" data-req="SWS_WdgM_00147" href="../../spec/record.html?id=SWS_WdgM_00147">[SWS_WdgM_00147]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00333" href="../../spec/record.html?id=SWS_WdgM_00333">[SWS_WdgM_00333]</a>. Den lokalen Status fragt man über <code>localSupervisonStatus_{SupervisedEntityName}</code> ab <a class="spec-record-ref" data-req="SWS_WdgM_91003" href="../../spec/record.html?id=SWS_WdgM_91003">[SWS_WdgM_91003]</a> <a class="spec-record-ref" data-req="SWS_WdgM_91004" href="../../spec/record.html?id=SWS_WdgM_91004">[SWS_WdgM_91004]</a>. Globale Abfragen wie <code>GetGlobalStatus</code> oder <code>GetFirstExpiredSEID</code> laufen über <code>globalSupervision</code> <a class="spec-record-ref" data-req="SWS_WdgM_91002" href="../../spec/record.html?id=SWS_WdgM_91002">[SWS_WdgM_91002]</a> <a class="spec-record-ref" data-req="SWS_WdgM_91001" href="../../spec/record.html?id=SWS_WdgM_91001">[SWS_WdgM_91001]</a>.</p>
<p>Statusänderungen meldet der WdgM von sich aus über Mode-Ports: je Entity <code>mode_{SupervisedEntityName}</code> und einmal <code>globalmode</code> <a class="spec-record-ref" data-req="SWS_WdgM_00149" href="../../spec/record.html?id=SWS_WdgM_00149">[SWS_WdgM_00149]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00150" href="../../spec/record.html?id=SWS_WdgM_00150">[SWS_WdgM_00150]</a>. Beide nutzen die Mode Declaration Group <code>WdgM_Mode</code> mit den Werten <code>SUPERVISION_OK</code> bis <code>SUPERVISION_DEACTIVATED</code> <a class="spec-record-ref" data-req="SWS_WdgM_00334" href="../../spec/record.html?id=SWS_WdgM_00334">[SWS_WdgM_00334]</a>. Lokale Änderungen werden sofort gemeldet, globale jeweils nur einmal <a class="spec-record-ref" data-req="SWS_WdgM_00197" href="../../spec/record.html?id=SWS_WdgM_00197">[SWS_WdgM_00197]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00199" href="../../spec/record.html?id=SWS_WdgM_00199">[SWS_WdgM_00199]</a>. Lokaler und globaler Mode-Port haben verschiedene Interfaces. So lassen sich die lokalen Ports über die Indirect Port API ansprechen, ohne dass der globale Port in dieser Liste erscheint (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_8_7_2_3_Port_Interfaces.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_8_7_2_3_Port_Interfaces">SWS WdgM S. 101</a>).</p>

<h4>Konfiguration: Modi, Supervised Entities und Watchdog-Trigger</h4>

<h4>Verhalten im Fehlerfall</h4>
<p>Bei aktivem <code>WdgMDevErrorDetect</code> meldet der WdgM Entwicklungsfehler an den DET, etwa <code>WDGM_E_UNINIT</code>, <code>WDGM_E_PARAM_SEID</code>, <code>WDGM_E_INV_POINTER</code> oder <code>WDGM_E_CPID</code> <a class="spec-record-ref" data-req="SWS_WdgM_00004" href="../../spec/record.html?id=SWS_WdgM_00004">[SWS_WdgM_00004]</a>. Bei nicht initialisiertem Modul gilt ein festes Muster: Mit Prüfung wird <code>WDGM_E_UNINIT</code> gemeldet, ohne Prüfung kehrt der Dienst wirkungslos zurück <a class="spec-record-ref" data-req="SWS_WdgM_00279" href="../../spec/record.html?id=SWS_WdgM_00279">[SWS_WdgM_00279]</a> <a class="spec-record-ref" data-req="SWS_WdgM_00394" href="../../spec/record.html?id=SWS_WdgM_00394">[SWS_WdgM_00394]</a>. Als Laufzeitfehler gibt es <code>WDGM_E_DISABLE_NOT_ALLOWED</code>, <code>WDGM_E_SEDEACTIVATED</code> und <code>WDGM_E_SET_MODE</code> <a class="spec-record-ref" data-req="SWS_WdgM_00402" href="../../spec/record.html?id=SWS_WdgM_00402">[SWS_WdgM_00402]</a>.</p>
<p>Ist <code>WdgMOffModeEnabled</code> FALSE, lehnt <code>WdgM_SetMode</code> einen Modus mit <code>WDGIF_OFF_MODE</code> ab. Der Dienst meldet dann <code>WDGM_E_DISABLE_NOT_ALLOWED</code> und liefert <code>E_NOT_OK</code> <a class="spec-record-ref" data-req="SWS_WdgM_00031" href="../../spec/record.html?id=SWS_WdgM_00031">[SWS_WdgM_00031]</a>. <code>WdgM_Init</code> verhält sich bei einem solchen Initial-Modus genauso <a class="spec-record-ref" data-req="SWS_WdgM_00030" href="../../spec/record.html?id=SWS_WdgM_00030">[SWS_WdgM_00030]</a>. Scheitert <code>WdgIf_SetMode</code>, meldet der WdgM <code>WDGM_E_SET_MODE</code> und setzt den globalen Status auf STOPPED <a class="spec-record-ref" data-req="SWS_WdgM_00139" href="../../spec/record.html?id=SWS_WdgM_00139">[SWS_WdgM_00139]</a>. Der Reset folgt sofort, wenn ein Immediate Reset konfiguriert ist, sonst beim Ablauf des ersten Watchdogs (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_WDGM_SECTION_7_5_2_Effect_on_Watchdogs.html" data-snip="SNIP_CLASSIC_WDGM_SECTION_7_5_2_Effect_on_Watchdogs">SWS WdgM S. 57</a>).</p>
<p>Erreicht der globale Status STOPPED, meldet der WdgM das DEM-Event <code>WDGM_E_SUPERVISION</code> als Fehler <a class="spec-record-ref" data-req="SWS_WdgM_00375" href="../../spec/record.html?id=SWS_WdgM_00375">[SWS_WdgM_00375]</a>.
