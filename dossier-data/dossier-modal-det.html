<h4>Role of the Default Error Tracer and its system boundary</h4>
<p>In the Classic stack, the Default Error Tracer (DET) receives error messages centrally. It provides three reporting services. <code>Det_ReportError</code> serves for development errors <a class="spec-record-ref" data-req="SWS_Det_00009" href="../../spec/record.html?id=SWS_Det_00009">[SWS_Det_00009]</a>, <code>Det_ReportRuntimeError</code> for runtime errors <a class="spec-record-ref" data-req="SWS_Det_01001" href="../../spec/record.html?id=SWS_Det_01001">[SWS_Det_01001]</a>. For transient faults, R20-11 also provides <code>Det_ReportTransientFault</code> <a class="spec-record-ref" data-req="SWS_Det_01003" href="../../spec/record.html?id=SWS_Det_01003">[SWS_Det_01003]</a>. In addition, there are the management services <code>Det_Init</code>, <code>Det_Start</code>, and <code>Det_GetVersionInfo</code> <a class="spec-record-ref" data-req="SWS_Det_00008" href="../../spec/record.html?id=SWS_Det_00008">[SWS_Det_00008]</a> <a class="spec-record-ref" data-req="SWS_Det_00010" href="../../spec/record.html?id=SWS_Det_00010">[SWS_Det_00010]</a> <a class="spec-record-ref" data-req="SWS_Det_00011" href="../../spec/record.html?id=SWS_Det_00011">[SWS_Det_00011]</a>. All services are available via <code>Det.h</code>.</p>
<p>The DET does not evaluate messages functionally itself. It distributes them to configured error hooks and callouts (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_7_2_Error_Hooks.html" data-snip="SNIP_CLASSIC_DET_SECTION_7_2_Error_Hooks">SWS DET p. 16</a>). According to the error description valid for R20-11, it thus reaches the DEM and the RTE via integrator-specific code (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_4_1_2_3_DET.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_4_1_2_3_DET">ErrorDescription p. 10</a>). In addition, optional forwarding to the Dlt via <code>Dlt_DetForwardErrorTrace</code> is provided <a class="spec-record-ref" data-req="SWS_Det_00211" href="../../spec/record.html?id=SWS_Det_00211">[SWS_Det_00211]</a>.</p>

<h4>Startup: Det_Init and Det_Start in the startup sequence of the EcuM</h4>
<p>The EcuM lists <code>Det_Init</code> and <code>Det_ReportError</code> among its optional interfaces (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_OS_SECTION_8_7_1_Optional_Interfaces.html" data-snip="SNIP_CLASSIC_OS_SECTION_8_7_1_Optional_Interfaces">SWS EcuM p. 142</a>). <code>Det_Init</code> has the service ID 0x00 and is synchronous and non-reentrant. The parameter <code>ConfigPtr</code> points to the selected configuration set <a class="spec-record-ref" data-req="SWS_Det_00008" href="../../spec/record.html?id=SWS_Det_00008">[SWS_Det_00008]</a>. Its type <code>Det_ConfigType</code> has an implementation-specific structure <a class="spec-record-ref" data-req="SWS_Det_00210" href="../../spec/record.html?id=SWS_Det_00210">[SWS_Det_00210]</a>. <code>Det_Start</code> (0x02) starts the tracer and is likewise synchronous and non-reentrant <a class="spec-record-ref" data-req="SWS_Det_00010" href="../../spec/record.html?id=SWS_Det_00010">[SWS_Det_00010]</a>.</p>
<p>According to the initialization diagram, the EcuM first calls <code>Det_Init</code> and then <code>Det_Start</code> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-340834e54c620c3b.html" data-snip="FIG-340834e54c620c3b">SWS DET Abb. Initialisierung p. 32</a>). The sources do not specify which services already take effect between the two calls. This point remains open here. <code>Det_GetVersionInfo</code> (0x03) is reentrant and writes the version information to the passed pointer <a class="spec-record-ref" data-req="SWS_Det_00011" href="../../spec/record.html?id=SWS_Det_00011">[SWS_Det_00011]</a>.</p>

<h4>Three reporting paths with a common numbering scheme</h4>
<p>All three reporting services have the same parameters: <code>ModuleId</code> (uint16), <code>InstanceId</code>, <code>ApiId</code>, and <code>ErrorId</code> or <code>FaultId</code>, respectively (each uint8) <a class="spec-record-ref" data-req="SWS_Det_00009" href="../../spec/record.html?id=SWS_Det_00009">[SWS_Det_00009]</a> <a class="spec-record-ref" data-req="SWS_Det_01001" href="../../spec/record.html?id=SWS_Det_01001">[SWS_Det_01001]</a> <a class="spec-record-ref" data-req="SWS_Det_01003" href="../../spec/record.html?id=SWS_Det_01003">[SWS_Det_01003]</a>.</p>
<ul>
<li>The <code>ModuleId</code> originates from the list of basic software modules. The BSW only uses the range 0..255.</li>
<li>The <code>InstanceId</code> counts from 0. A module with only one instance passes 0.</li>
<li><code>ApiId</code> and <code>ErrorId</code> are defined by the SWS of the reporting module (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_3_BSW.html" data-snip="SNIP_CLASSIC_DET_SECTION_3_BSW">EXP LSA p. 157</a>).</li>
</ul>
<p>Which service applies depends on the error type:</p>
<ul>
<li>A BSW module reports development errors via <code>Det_ReportError</code> with its module ID. This applies only if development error detection is configured (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_7_2_2_4_Reporting.html" data-snip="SNIP_CLASSIC_DET_SECTION_7_2_2_4_Reporting">SWS BSWGeneral p. 57</a>). A query such as <code>#if (SPI_DEV_ERROR_DETECT == ON)</code> is typical for this (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_1_SC_D.html" data-snip="SNIP_CLASSIC_DET_SECTION_1_SC_D">EXP LSA p. 113</a>). An example is an invalid parameter in CanIf (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_CANIF_SECTION_8_3_18_CanIf_CheckWakeup.html" data-snip="SNIP_CLASSIC_CANIF_SECTION_8_3_18_CanIf_CheckWakeup">SWS CanIf p. 101</a>).</li>
<li>Runtime errors such as <code>ADC_E_BUSY</code> run via <code>Det_ReportRuntimeError</code> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_9_7_No_Priority_Mechanism_No_Queuing.html" data-snip="SNIP_CLASSIC_DET_SECTION_9_7_No_Priority_Mechanism_No_Queuing">SWS Adc p. 95</a>).</li>
<li>Transient faults run via the transient fault service (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_7_2_4_4_Reporting.html" data-snip="SNIP_CLASSIC_DET_SECTION_7_2_4_4_Reporting">SWS BSWGeneral p. 53</a>).</li>
</ul>
<p>In its module description, a module declares this need as <code>ErrorTracerNeeds</code>. Each of the three services is an optional role there (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_BSWMODULEDESCRIPTIONTEMPLATE_SECTION_13_4_1_Default_Error_Tracer_Service_use_Case_report_failure.html" data-snip="SNIP_CLASSIC_BSWMODULEDESCRIPTIONTEMPLATE_SECTION_13_4_1_Default_Error_Tracer_Service_use_Case_report_failure">TPS BSWMDT p. 266</a>).</p>
<p>Release note: <code>Det_ReportTransientFault</code> is normative in R20-11 <a class="spec-record-ref" data-req="SWS_Det_01003" href="../../spec/record.html?id=SWS_Det_01003">[SWS_Det_01003]</a>. Later versions list the service as obsolete (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_8_1_3_5_Det_ReportTransientFault.html" data-snip="SNIP_CLASSIC_DET_SECTION_8_1_3_5_Det_ReportTransientFault">SWS DET p. 24</a>). With R24-11, transient faults were completely removed (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_DET_SECTION_General_Overview">SWS DET p. 1</a>).</p>

<h4>Connection of SW-Cs via the Service Port DETService</h4>
<p>SW-Cs reach the DET via the RTE. For each configured module instance, the DET provides a port <code>Det_{Name}</code> with the interface <code>DETService</code> <a class="spec-record-ref" data-req="SWS_Det_00205" href="../../spec/record.html?id=SWS_Det_00205">[SWS_Det_00205]</a>. The operations <code>ReportError</code> and <code>ReportRuntimeError</code> call the C API with the module ID of the port <a class="spec-record-ref" data-req="SWS_Det_00202" href="../../spec/record.html?id=SWS_Det_00202">[SWS_Det_00202]</a>. The required types uint8 and uint16 are AUTOSAR data types <a class="spec-record-ref" data-req="SWS_Det_00200" href="../../spec/record.html?id=SWS_Det_00200">[SWS_Det_00200]</a>.</p>
<p><code>ModuleId</code> and <code>InstanceId</code> are not passed by the SW-C itself. <h4>Configuration of Hook Lists and Callout Signatures</h4>
<p>Notification is configured in the container <code>DetNotification</code> (0..1). It contains the lists <code>DetErrorHook</code> and <code>DetReportRuntimeErrorCallout</code> (0..* each). In the present later version, they have the configuration class Pre-compile (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_10_2_3_DetNotification.html" data-snip="SNIP_CLASSIC_DET_SECTION_10_2_3_DetNotification">SWS DET p. 37</a>). R20-11 additionally contains the list <code>DetReportTransientFaultCallout</code> <a class="spec-record-ref" data-req="SWS_Det_00501" href="../../spec/record.html?id=SWS_Det_00501">[SWS_Det_00501]</a>. A hook must have the same type as <code>Det_ReportError</code>, i.e. <code>Std_ReturnType (*f)(uint16, uint8, uint8, uint8)</code>.</p>
<p>In general, callouts have the same signature as the associated function. Multiple callouts for the same service carry the same ID (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_8_1_5_Callout_Functions_Configurable_Interfaces.html" data-snip="SNIP_CLASSIC_DET_SECTION_8_1_5_Callout_Functions_Configurable_Interfaces">SWS DET p. 25</a>). The error description of R20-11 limits what such handlers may do: store the event, call the DEM, or execute short, appropriate actions (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_4_1_2_3_DET.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_4_1_2_3_DET">ErrorDescription p. 10</a>). All three callout interfaces are specified as reentrant <a class="spec-record-ref" data-req="SWS_Det_00181" href="../../spec/record.html?id=SWS_Det_00181">[SWS_Det_00181]</a> <a class="spec-record-ref" data-req="SWS_Det_00184" href="../../spec/record.html?id=SWS_Det_00184">[SWS_Det_00184]</a> <a class="spec-record-ref" data-req="SWS_Det_00187" href="../../spec/record.html?id=SWS_Det_00187">[SWS_Det_00187]</a>.</p>

<h4>Behavior in the event of an error</h4>
<p>In R20-11, \"Not Applicable: The function never returns\" is stated for <code>Det_ReportError</code> under Sync/Async <a class="spec-record-ref" data-req="SWS_Det_00009" href="../../spec/record.html?id=SWS_Det_00009">[SWS_Det_00009]</a>. Development errors are therefore treated like assertions. After the hooks, the normal control flow does not continue, for example via an infinite loop or a halt. If only one hook is configured, it may take over exception handling (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_4_2_6_Fault_Operation_and_Error_Detection.html" data-snip="SNIP_CLASSIC_DET_SECTION_4_2_6_Fault_Operation_and_Error_Detection">RS BSWGeneral p. 33</a>).</p>
<p>The flow diagram deviates from this: it shows a return arrow and designates the behavior as implementation-specific (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-cbbd7f328ab57a31.html" data-snip="FIG-cbbd7f328ab57a31">SWS DET Abb. ReportError p. 36</a>). Only R21-11 clarified the call behavior (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_General_Overview.html" data-snip="SNIP_CLASSIC_DET_SECTION_General_Overview">SWS DET p. 1</a>). For R20-11, the requirement is decisive.</p>
<p>For runtime errors, the reporting module continues, because <code>Det_ReportRuntimeError</code> always returns <code>E_OK</code> <a class="spec-record-ref" data-req="SWS_Det_01001" href="../../spec/record.html?id=SWS_Det_01001">[SWS_Det_01001]</a> (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_8_1_3_4_Det_ReportRuntimeError.html" data-snip="SNIP_CLASSIC_DET_SECTION_8_1_3_4_Det_ReportRuntimeError">SWS DET p. 23</a>). For transient faults, the reporting module receives the result of the callouts as return value <a class="spec-record-ref" data-req="SWS_Det_01003" href="../../spec/record.html?id=SWS_Det_01003">[SWS_Det_01003]</a> (<a class="docref internal-spec-ref" href="../../../spec/figures/FIG-bbc808d9443291d2.html" data-snip="FIG-bbc808d9443291d2">SWS DET Abb. Transient mit Hook p. 36</a>).</p>
<p>The DET itself knows only one development error of its own: <code>DET_E_PARAM_POINTER</code> (0x01). It occurs when <code>Det_GetVersionInfo</code> is called with a null pointer <a class="spec-record-ref" data-req="SWS_Det_00301" href="../../spec/record.html?id=SWS_Det_00301">[SWS_Det_00301]</a>. The DET reports this error to all functions configured in the callouts. Runtime and production errors are not applicable to the DET (<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DET_SECTION_7_5_Error_Classification.html" data-snip="SNIP_CLASSIC_DET_SECTION_7_5_Error_Classification">SWS DET p. 18</a>).</p>
