<p class="ai-level ai-oneliner-lead" data-ai-level="1">Dient dem Abruf von Authentifizierungsinstanzen zur Verwaltung des Status externer Diagnose-Clients.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse <code>ara::diag::ExternalAuthentication</code> stellt eine Port-Schnittstelle bereit, über die eine adaptive Anwendung Instanzen von <code>ara::diag::ClientAuthentication</code> zur Verwaltung des Authentifizierungszustands externer Diagnose-Clients abfragt <a class="spec-record-ref" data-req="SWS_DM_01191" href="../spec/record.html?id=SWS_DM_01191">[SWS_DM_01191]</a>. Nach der Bindung an einen modellierten Service-Port werden die Authentifizierungsobjekte anhand der Quelladresse oder von Metainformationen gezielt vom Diagnostic Manager angefordert <a class="spec-record-ref" data-req="SWS_DM_01200" href="../spec/record.html?id=SWS_DM_01200">[SWS_DM_01200]</a>. Die Instanz besitzt Move-Semantik, verbietet Kopiervorgänge und verlangt aufgrund eines nicht threadsicheren Destruktors einen synchronisierten Abbau.</p>

</div>
<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::ExternalAuthentication</code> fungiert in der AUTOSAR Adaptive Platform als Port-Schnittstelle für die Authentifizierung externer Diagnose-Clients <a class="spec-record-ref" data-req="SWS_DM_01191" href="../spec/record.html?id=SWS_DM_01191">[SWS_DM_01191]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=461">AUTOSAR_AP_SWS_Diagnostics §8.17 „Header: ara/diag/external_authentication.h“</a>. Über diesen Port erhält eine adaptive Anwendung Zugriff auf spezifische Instanzen von <code>ara::diag::ClientAuthentication</code>, welche den Authentifizierungszustand des jeweiligen Diagnose-Clients abbilden und verwalten <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a>.</p>
<p>Die Zuordnung und Anzahl verfügbarer Client-Instanzen wird im Software-Modell über das Element <code>DiagnosticExternalAuthenticationIdentification</code> definiert. Dieses erlaubt es der Anwendung, feste Quelladressen oder konfigurierte Adressbereiche des Typs <code>Address</code> (Alias für <code>std::uint16_t</code> <a class="spec-record-ref" data-req="SWS_DM_01192" href="../spec/record.html?id=SWS_DM_01192">[SWS_DM_01192]</a>) für Diagnose-Tester festzulegen, wenn die finale Quelladresse erst zur Laufzeit bekannt ist <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=129">AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 „Get ClientAuthentication Instance“</a>.</p>
<p>Zu den beteiligten Interaktionspartnern gehören:</p>
<ul>
<li>Die <strong>adaptive Applikation</strong>, welche die Port-Instanz erzeugt und Authentifizierungszustände abfragt.</li>
<li>Der <strong>Diagnostic Manager (DM)</strong>, der die Diagnoseverbindungen steuert und die Authentifizierungszustände der Clients verwaltet <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a>.</li>
<li>Die <strong><code>ara::diag::ClientAuthentication</code></strong>-Objekte, die dem anfragenden Client zugeordnet sind.</li>
<li>Der <strong>externe Diagnose-Client</strong>, dessen Verbindung über Quelladresse oder Metainformationen identifiziert wird.</li>
</ul>

<h4>Lebenszyklus</h4>
<p>Die Erzeugung einer <code>ara::diag::ExternalAuthentication</code>-Instanz erfolgt explizit durch Übergabe eines <code>ara::core::InstanceSpecifier</code> an den Konstruktor <a class="spec-record-ref" data-req="SWS_DM_01193" href="../spec/record.html?id=SWS_DM_01193">[SWS_DM_01193]</a>. Dieser Bezeichner bindet das Objekt an den modellierten <code>PortPrototype</code> eines <code>DiagnosticExternalAuthenticationInterface</code>.</p>
<p>Hinsichtlich der Besitzverhältnisse besitzt die Klasse reine Move-Semantik: Move-Konstruktor <a class="spec-record-ref" data-req="SWS_DM_01194" href="../spec/record.html?id=SWS_DM_01194">[SWS_DM_01194]</a> und Move-Zuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01195" href="../spec/record.html?id=SWS_DM_01195">[SWS_DM_01195]</a> sind vorhanden (<code>default</code>), während Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_DM_01196" href="../spec/record.html?id=SWS_DM_01196">[SWS_DM_01196]</a> und Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_DM_01197" href="../spec/record.html?id=SWS_DM_01197">[SWS_DM_01197]</a> gelöscht sind (<code>delete</code>). Ein Port repräsentiert damit ein unteilbares, nicht kopierbares Schnittstellen-Objekt.</p>
<p>Für die Zerstörung steht der Destruktor <code>~ExternalAuthentication()</code> zur Verfügung <a class="spec-record-ref" data-req="SWS_DM_01198" href="../spec/record.html?id=SWS_DM_01198">[SWS_DM_01198]</a>. Im Hinblick auf die Nebenläufigkeit sind der Konstruktor sowie die Abfragemethoden als threadsicher (<code>thread-safe</code>) und ausnahmesicher (<code>exception safe</code>) spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01193" href="../spec/record.html?id=SWS_DM_01193">[SWS_DM_01193]</a>, <a class="spec-record-ref" data-req="SWS_DM_01199" href="../spec/record.html?id=SWS_DM_01199">[SWS_DM_01199]</a>, <a class="spec-record-ref" data-req="SWS_DM_01200" href="../spec/record.html?id=SWS_DM_01200">[SWS_DM_01200]</a>, <a class="spec-record-ref" data-req="SWS_DM_01201" href="../spec/record.html?id=SWS_DM_01201">[SWS_DM_01201]</a>. Der Destruktor ist hingegen ausdrücklich nicht threadsicher (<code>not thread-safe</code>) <a class="spec-record-ref" data-req="SWS_DM_01198" href="../spec/record.html?id=SWS_DM_01198">[SWS_DM_01198]</a>. Die Anwendung muss daher sicherstellen, dass vor dem Abbau des Objekts keine nebenläufigen Aufrufe mehr stattfinden.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Ablauf umfasst die Initialisierung des Ports und den anschließenden Abruf von Authentifizierungsobjekten:</p>
<ol>
<li>Die Applikation instanziiert <code>ExternalAuthentication</code> unter Angabe des Instanzbezeichners <a class="spec-record-ref" data-req="SWS_DM_01193" href="../spec/record.html?id=SWS_DM_01193">[SWS_DM_01193]</a>.</li>
<li>Die Applikation fordert die Authentifizierungsinstanz für einen konkreten Client an. Hierfür stehen die überladenen Methoden <code>Get(Address)</code> unter Verwendung der Tester-Adresse <a class="spec-record-ref" data-req="SWS_DM_01200" href="../spec/record.html?id=SWS_DM_01200">[SWS_DM_01200]</a> oder <code>Get(const MetaInfo&amp;)</code> anhand empfangener Anforderungs-Metadaten <a class="spec-record-ref" data-req="SWS_DM_01199" href="../spec/record.html?id=SWS_DM_01199">[SWS_DM_01199]</a> zur Verfügung. Alternativ ruft sie mittels <code>GetAll()</code> eine Liste aller aktuell vom Diagnostic Manager geführten Instanzen ab <a class="spec-record-ref" data-req="SWS_DM_01201" href="../spec/record.html?id=SWS_DM_01201">[SWS_DM_01201]</a>.</li>
<li>Der Diagnostic Manager ermittelt das entsprechende Objekt und liefert ein <code>ara::core::Result&lt;ClientAuthentication&gt;</code> bzw. einen Vektor zurück <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a>.</li>
<li>Die Applikation prüft das Ergebnis und interagiert anschließend mit der erhaltenen <code>ClientAuthentication</code>-Instanz, welche vermutlich als anwendungsseitiges Handle für den Zustand der Authentifizierungssitzung fungiert.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Bei der Instanziierung über den Konstruktor können Konfigurations- und Modellierungsfehler zu definierten Verletzungen führen <a class="spec-record-ref" data-req="SWS_DM_01193" href="../spec/record.html?id=SWS_DM_01193">[SWS_DM_01193]</a>:</p>
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: Der Bezeichner kann im Kontext des Executables nicht aufgelöst werden oder referenziert kein <code>PortPrototype</code>.</li>
<li><code>PortInterfaceMappingViolation</code>: Der referenzierte <code>PortPrototype</code> ist nicht als <code>DiagnosticExternalAuthenticationInterface</code> typisiert.</li>
<li><code>ProcessMappingViolation</code>: Es existiert keine passende modellierte Prozessdefinition für den Laufzeitprozess.</li>
