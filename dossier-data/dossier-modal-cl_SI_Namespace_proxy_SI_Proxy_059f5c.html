<h4>Context</h4>
<p>The generated proxy class <code>&lt;SI-Namespace&gt;::proxy::&lt;SI&gt;Proxy</code> acts as the primary client-side representative of an AUTOSAR Adaptive service interface within module <code>com</code>. Its central responsibility is to find service instances, establish communication channels, and provide type-safe access to the communication entities defined in the service interface. For this purpose, the class holds dedicated member variables for events via <code>events::&lt;Event&gt;</code> <a class="spec-record-ref" data-req="SWS_CM_99445" href="../spec/record.html?id=SWS_CM_99445">[SWS_CM_99445]</a>, fields via <code>fields::&lt;Field&gt;</code> <a class="spec-record-ref" data-req="SWS_CM_99446" href="../spec/record.html?id=SWS_CM_99446">[SWS_CM_99446]</a>, and methods via <code>methods::&lt;Method&gt;</code> <a class="spec-record-ref" data-req="SWS_CM_99447" href="../spec/record.html?id=SWS_CM_99447">[SWS_CM_99447]</a>.</p>
<p>The primary interaction partners include the local client application, the underlying communication infrastructure (network binding), and registered callback functions for monitoring the service status or for asynchronous search operations.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of a proxy is divided into service discovery, instantiation, state monitoring, and controlled release:</p>
<ul>
  <li><strong>Finding:</strong> Prior to object creation, matching instances are searched for. This is done either synchronously via <code>FindService</code> with <code>ara::com::InstanceIdentifier</code> <a class="spec-record-ref" data-req="SWS_CM_00122" href="../spec/record.html?id=SWS_CM_00122">[SWS_CM_00122]</a> or <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_CM_00622" href="../spec/record.html?id=SWS_CM_00622">[SWS_CM_00622]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">EXP ARAComAPI p. 10</a>, respectively, or asynchronously via <code>StartFindService</code> <a class="spec-record-ref" data-req="SWS_CM_00123" href="../spec/record.html?id=SWS_CM_00123">[SWS_CM_00123]</a>, <a class="spec-record-ref" data-req="SWS_CM_00623" href="../spec/record.html?id=SWS_CM_00623">[SWS_CM_00623]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">EXP ARAComAPI p. 10</a>. For asynchronous searches, a user-defined execution context can be passed via <code>ExecutorT</code> <a class="spec-record-ref" data-req="SWS_CM_11352" href="../spec/record.html?id=SWS_CM_11352">[SWS_CM_11352]</a>, <a class="spec-record-ref" data-req="SWS_CM_11365" href="../spec/record.html?id=SWS_CM_11365">[SWS_CM_11365]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">EXP ARAComAPI p. 10</a>. Ongoing searches are stopped with <code>StopFindService</code> <a class="spec-record-ref" data-req="SWS_CM_00125" href="../spec/record.html?id=SWS_CM_00125">[SWS_CM_00125]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=10">EXP ARAComAPI p. 10</a>.</li>
  <li><strong>Creation:</strong> The recommended, exception-free creation takes place via the static factory method <code>Create</code> (Named Constructor Idiom) specifying a valid <code>HandleType</code> and returns a <code>ara::core::Result&lt;&lt;SI&gt;Proxy&gt;</code> <a class="spec-record-ref" data-req="SWS_CM_10438" href="../spec/record.html?id=SWS_CM_10438">[SWS_CM_10438]</a>. Alternatively, an explicit constructor <code>&lt;SI&gt;Proxy(const HandleType&amp;)</code> exists that can throw exceptions in case of errors <a class="spec-record-ref" data-req="SWS_CM_00131" href="../spec/record.html?id=SWS_CM_00131">[SWS_CM_00131]</a>.</li>
  <li><strong>Semantics:</strong> Proxy instances have move-only semantics: The copy constructor <a class="spec-record-ref" data-req="SWS_CM_00136" href="../spec/record.html?id=SWS_CM_00136">[SWS_CM_00136]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_CM_11551" href="../spec/record.html?id=SWS_CM_11551">[SWS_CM_11551]</a> are deleted (<code>=delete</code>). A transfer of resources is permissible exclusively via the move constructor <a class="spec-record-ref" data-req="SWS_CM_00137" href="../spec/record.html?id=SWS_CM_00137">[SWS_CM_00137]</a> or the noexcept move assignment operator <a class="spec-record-ref" data-req="SWS_CM_11552" href="../spec/record.html?id=SWS_CM_11552">[SWS_CM_11552]</a>, respectively. The underlying handle can be queried via <code>GetHandle</code> <a class="spec-record-ref" data-req="SWS_CM_10383" href="../spec/record.html?id=SWS_CM_10383">[SWS_CM_10383]</a>.</li>
  <li><strong>State management:</strong> The availability state of the connected service instance can be queried synchronously via <code>GetServiceState</code> <a class="spec-record-ref" data-req="SWS_CM_01073" href="../spec/record.html?id=SWS_CM_01073">[SWS_CM_01073]</a>. For asynchronous state tracking, a <code>ServiceStateHandler</code> is registered using <code>SetServiceStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01074" href="../spec/record.html?id=SWS_CM_01074">[SWS_CM_01074]</a> (optionally with execution context <code>ExecutorT</code> <a class="spec-record-ref" data-req="SWS_CM_01076" href="../spec/record.html?id=SWS_CM_01076">[SWS_CM_01076]</a>). Deregistration is performed via <code>UnsetServiceStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01075" href="../spec/record.html?id=SWS_CM_01075">[SWS_CM_01075]</a>.</li>
  <li><strong>Destruction:</strong> The destructor <code>~&lt;SI&gt;Proxy()</code> ends the lifetime <a class="spec-record-ref" data-req="SWS_CM_99444" href="../spec/record.html?id=SWS_CM_99444">[SWS_CM_99444]</a>. Prior to destruction, all held data samples must be released to avoid violations.</li>
</ul>

<h4>Usage Path</h4>
<p>A typical usage path comprises the synchronous search for a service instance, proxy-based instantiation, monitoring of state changes, and the final cleanup:</p>
<ol>
  <li><strong>Determine service:</strong> Call to <code>&lt;SI&gt;Proxy::FindService(instance)</code> to determine available service handles in a <code>ara::com::ServiceHandleContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00122" href="../spec/record.html?id=SWS_CM_00122">[SWS_CM_00122]</a>, <a class="spec-record-ref" data-req="SWS_CM_00622" href="../spec/record.html?id=SWS_CM_00622">[SWS_CM_00622]</a>.</li>
  <li><strong>Create proxy:</strong> Passing the selected handle to <code>&lt;SI&gt;Proxy::Create(handle)</code> for exception-free construction <a class="spec-record-ref" data-req="SWS_CM_10438" href="../spec/record.html?id=SWS_CM_10438">[SWS_CM_10438]</a>.</li>
  <li><strong>Monitor state:</strong> Registering a change handler via <code>SetServiceStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01074" href="../spec/record.html?id=SWS_CM_01074">[SWS_CM_01074]</a> and querying the current status via <code>GetServiceState</code> <a class="spec-record-ref" data-req="SWS_CM_01073" href="../spec/record.html?id=SWS_CM_01073">[SWS_CM_01073]</a>.</li>
  <li><strong>Perform communication:</strong> Interacting with the members for methods <a class="spec-record-ref" data-req="SWS_CM_99447" href="../spec/record.html?id=SWS_CM_99447">[SWS_CM_99447]</a>, events <a class="spec-record-ref" data-req="SWS_CM_99445" href="../spec/record.html?id=SWS_CM_99445">[SWS_CM_99445]</a>, and fields <a class="spec-record-ref" data-req="SWS_CM_99446" href="../spec/record.html?id=SWS_CM_99446">[SWS_CM_99446]</a>.</li>
  <li><strong>Release resources:</strong> Deregistering the state handler with <code>UnsetServiceStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01075" href="../spec/record.html?id=SWS_CM_01075">[SWS_CM_01075]</a> and controlled destruction of the object <a class="spec-record-ref" data-req="SWS_CM_99444" href="../spec/record.html?id=SWS_CM_99444">[SWS_CM_99444]</a>.</li>
</ol>
