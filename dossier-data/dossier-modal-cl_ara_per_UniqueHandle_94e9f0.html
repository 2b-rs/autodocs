<h4>Context</h4>
<p>The template class <code>ara::per::UniqueHandle</code> represents a type-safe, owning pointer (smart pointer) for access resources to the file system in the persistence module (<code>per</code>) of the AUTOSAR Adaptive Platform. In particular, it encapsulates instances of <code>ReadAccessor</code> or <code>ReadWriteAccessor</code>, which are obtained via factory functions such as <code>OpenFileReadOnly()</code>, <code>OpenFileWriteOnly()</code>, or <code>OpenFileReadWrite()</code>.</p>
<p>In interaction with the persistence subsystem, <code>UniqueHandle</code> serves to decouple the application logic from manual storage and descriptor management. According to the \"Resource Acquisition Is Initialization\" (RAII) paradigm, the class guarantees exclusive ownership (Unique Ownership): at any time, at most one active handle exists for the underlying accessor instance.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of <code>UniqueHandle</code> is characterized by strict transfer of ownership and the prohibition of duplication:</p>
<ul>
<li><strong>Creation:</strong> Instances typically arise as the return value of the file opening functions of the persistence module. Since both the copy constructor <a class="spec-record-ref" data-req="SWS_PER_00373" href="../spec/record.html?id=SWS_PER_00373">[SWS_PER_00373]</a> and the copy assignment operator <a class="spec-record-ref" data-req="SWS_PER_00374" href="../spec/record.html?id=SWS_PER_00374">[SWS_PER_00374]</a> are deleted (<code>= delete</code>), accidental copying of resources is precluded.</li>
<li><strong>Ownership transfer:</strong> Transfer of the resource occurs exclusively via move semantics. Both the move constructor <a class="spec-record-ref" data-req="SWS_PER_00371" href="../spec/record.html?id=SWS_PER_00371">[SWS_PER_00371]</a> and the move assignment operator <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a> invalidate the source object. The source transitions to the \"empty\" state and cannot be used further for resource access.</li>
<li><strong>State query:</strong> Via the explicit conversion operator <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_PER_00399" href="../spec/record.html?id=SWS_PER_00399">[SWS_PER_00399]</a>, it can be checked whether the handle is valid (<code>true</code>) or in the empty or invalidated state (<code>false</code>).</li>
<li><strong>Destruction:</strong> The destructor <code>~UniqueHandle()</code> <a class="spec-record-ref" data-req="SWS_PER_00569" href="../spec/record.html?id=SWS_PER_00569">[SWS_PER_00569]</a> concludes the lifecycle. Interpretation: It is likely to be assumed that this destroys the encapsulated accessor object and releases the associated file resource.</li>
<li><strong>Concurrency:</strong> Access methods on existing instances (<code>operator*</code>, <code>operator-&gt;</code>, <code>operator bool</code>) are designated as thread-safe <a class="spec-record-ref" data-req="SWS_PER_00360" href="../spec/record.html?id=SWS_PER_00360">[SWS_PER_00360]</a>, <a class="spec-record-ref" data-req="SWS_PER_00361" href="../spec/record.html?id=SWS_PER_00361">[SWS_PER_00361]</a>, <a class="spec-record-ref" data-req="SWS_PER_00400" href="../spec/record.html?id=SWS_PER_00400">[SWS_PER_00400]</a>, <a class="spec-record-ref" data-req="SWS_PER_00401" href="../spec/record.html?id=SWS_PER_00401">[SWS_PER_00401]</a>, <a class="spec-record-ref" data-req="SWS_PER_00399" href="../spec/record.html?id=SWS_PER_00399">[SWS_PER_00399]</a>. In contrast, the move assignment operator <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a> and the destructor <a class="spec-record-ref" data-req="SWS_PER_00569" href="../spec/record.html?id=SWS_PER_00569">[SWS_PER_00569]</a> are not thread-safe and require external synchronization in the case of shared access.</li>
</ul>

<h4>Usage Path</h4>
<p>The regular workflow when working with <code>UniqueHandle</code> is divided into the following phases:</p>
<ol>
<li><strong>Acquisition:</strong> The application calls a factory function such as <code>OpenFileReadOnly()</code> and receives the returned <code>UniqueHandle</code>.</li>
<li><strong>State check:</strong> Prior to using further operators, the state of the handle must mandatorily be checked via <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_PER_00371" href="../spec/record.html?id=SWS_PER_00371">[SWS_PER_00371]</a>, <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a>, <a class="spec-record-ref" data-req="SWS_PER_00399" href="../spec/record.html?id=SWS_PER_00399">[SWS_PER_00399]</a>.</li>
<li><strong>Resource access:</strong> In the event of a positive check result, the application accesses the encapsulated accessor object via the arrow operator <code>operator-&gt;()</code> <a class="spec-record-ref" data-req="SWS_PER_00360" href="../spec/record.html?id=SWS_PER_00360">[SWS_PER_00360]</a>, <a class="spec-record-ref" data-req="SWS_PER_00361" href="../spec/record.html?id=SWS_PER_00361">[SWS_PER_00361]</a> or the dereference operator <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_PER_00400" href="../spec/record.html?id=SWS_PER_00400">[SWS_PER_00400]</a>, <a class="spec-record-ref" data-req="SWS_PER_00401" href="../spec/record.html?id=SWS_PER_00401">[SWS_PER_00401]</a>. Both operators are each available as const and non-const variants.</li>
<li><strong>Completion:</strong> If the handle leaves the scope, the destructor <a class="spec-record-ref" data-req="SWS_PER_00569" href="../spec/record.html?id=SWS_PER_00569">[SWS_PER_00569]</a> automatically releases the managed resource. Alternatively, the instance can be transferred to other data structures via a move operation <a class="spec-record-ref" data-req="SWS_PER_00371" href="../spec/record.html?id=SWS_PER_00371">[SWS_PER_00371]</a>, <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a>.</li>
</ol>

<h4>Error Scenarios</h4>
<p>The member functions of <code>UniqueHandle</code> are declared with <code>noexcept</code> and throw no C++ exceptions (exception safety: exception safe) <a class="spec-record-ref" data-req="SWS_PER_00371" href="../spec/record.html?id=SWS_PER_00371">[SWS_PER_00371]</a>, <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a>, <a class="spec-record-ref" data-req="SWS_PER_00360" href="../spec/record.html?id=SWS_PER_00360">[SWS_PER_00360]</a>, <a class="spec-record-ref" data-req="SWS_PER_00361" href="../spec/record.html?id=SWS_PER_00361">[SWS_PER_00361]</a>, <a class="spec-record-ref" data-req="SWS_PER_00400" href="../spec/record.html?id=SWS_PER_00400">[SWS_PER_00400]</a>, <a class="spec-record-ref" data-req="SWS_PER_00401" href="../spec/record.html?id=SWS_PER_00401">[SWS_PER_00401]</a>, <a class="spec-record-ref" data-req="SWS_PER_00399" href="../spec/record.html?id=SWS_PER_00399">[SWS_PER_00399]</a>, <a class="spec-record-ref" data-req="SWS_PER_00569" href="../spec/record.html?id=SWS_PER_00569">[SWS_PER_00569]</a>. In case of incorrect usage, however, severe error states threaten:</p>
<ul>
<li><strong>Undefined behavior with empty handle:</strong> If an empty handle or one invalidated by a move is dereferenced using operators other than <code>operator bool()</code>, this leads directly to undefined behavior (Undefined Behavior) <a class="spec-record-ref" data-req="SWS_PER_00399" href="../spec/record.html?id=SWS_PER_00399">[SWS_PER_00399]</a>.</li>
<li><strong>Violation of the verification duty:</strong> According to <a class="spec-record-ref" data-req="SWS_PER_00371" href="../spec/record.html?id=SWS_PER_00371">[SWS_PER_00371]</a> and <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a>, the state must mandatorily be validated via <code>operator bool()</code> prior to any further access. If this check is omitted following an ownership transfer, memory access errors threaten.</li>
<li><strong>Copy attempts at compile time:</strong> Calling the copy constructor <a class="spec-record-ref" data-req="SWS_PER_00373" href="../spec/record.html?id=SWS_PER_00373">[SWS_PER_00373]</a> or the copy assignment operator <a class="spec-record-ref" data-req="SWS_PER_00374" href="../spec/record.html?id=SWS_PER_00374">[SWS_PER_00374]</a> leads to compiler errors, thereby preventing unintentional multiple referencing at an early stage.</li>
<li><strong>Data races during assignment:</strong> Since <code>operator=(&amp;&amp;)</code> <a class="spec-record-ref" data-req="SWS_PER_00372" href="../spec/record.html?id=SWS_PER_00372">[SWS_PER_00372]</a> and <code>~UniqueHandle()</code> <a class="spec-record-ref" data-req="SWS_PER_00569" href="../spec/record.html?id=SWS_PER_00569">[SWS_PER_00569]</a> are not thread-safe, moving or destroying an instance concurrently from multiple threads without external synchronization leads to data races and a corrupted program state.</li>
</ul>
