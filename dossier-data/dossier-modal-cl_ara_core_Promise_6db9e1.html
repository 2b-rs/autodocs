<h4>Context</h4>
<p>The template class <code>ara::core::Promise&lt;T, E&gt;</code> provides the AUTOSAR-Adaptive-specific variant of the C++ standard class <code>std::promise</code>. Its core task is to form the writing end of an asynchronous synchronization channel and manage a shared state. Via this shared state, a producing execution path passes the result of an asynchronous computation—either a value of type <code>T</code>, an error of type <code>E</code>, or a composite <code>ara::core::Result&lt;T, E&gt;</code>—to the reading counterpart <code>ara::core::Future&lt;T, E&gt;</code>, which is obtained via <code>get_future()</code> <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</p>
<p>A central AUTOSAR requirement of the template signature is the default assignment <code>E = ara::core::ErrorCode</code>. If the instantiation deviates from this (<code>E != ara::core::ErrorCode</code>), the specification mandatorily requires a compilation error. This stipulation presumably serves the strict enforcement of the standardized error model of the Adaptive Platform so that asynchronous interfaces can work uniformly with <code>ara::core::Result</code>. Three entities are typically involved in the collaboration: the producing program part as owner of the <code>Promise</code>, the managed shared state for cross-thread state coupling, and one or more consumers that receive the asynchronous result via <code>ara::core::Future</code>.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of <code>ara::core::Promise</code> follows strict move-only semantics and controls the existence of the underlying shared state:</p>
<ul>
<li><strong>Creation:</strong> The default constructor <code>Promise()</code> constructs an instance with a new, not yet satisfied shared state <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>. It is specified as <code>noexcept</code> guaranteed exception-safe and thread-safe <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>.</li>
<li><strong>Copy protection and transfer of ownership:</strong> Copy constructor <a class="spec-record-ref" data-req="SWS_CORE_00350" href="../spec/record.html?id=SWS_CORE_00350">[SWS_CORE_00350]</a> and copy assignment operator <a class="spec-record-ref" data-req="SWS_CORE_00351" href="../spec/record.html?id=SWS_CORE_00351">[SWS_CORE_00351]</a> are explicitly deleted (<code>= delete</code>). A transfer of ownership is only possible via move operations. The move constructor takes over the shared state of the source instance and is <code>noexcept</code>, but not thread-safe <a class="spec-record-ref" data-req="SWS_CORE_00342" href="../spec/record.html?id=SWS_CORE_00342">[SWS_CORE_00342]</a>. The move assignment operator abandons a previously held shared state (<em>abandons any shared state</em>) and transfers the state of the other instance analogously to a subsequent <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00343" href="../spec/record.html?id=SWS_CORE_00343">[SWS_CORE_00343]</a>. Two instances can also swap their state via <code>swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00352" href="../spec/record.html?id=SWS_CORE_00352">[SWS_CORE_00352]</a>.</li>
<li><strong>Future coupling:</strong> Exactly one instance of <code>ara::core::Future&lt;T, E&gt;</code> is associated with the same shared state via <code>get_future()</code> <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>. Since only one future may exist per promise, this call is permissible only once <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</li>
<li><strong>State transition to ready:</strong> Supplying a value via <code>set_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>, an error via <code>SetError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>, or an overall result via <code>SetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a> irreversibly switches the shared state to the status <em>ready</em>. All of these satisfaction methods are declared thread-safe.</li>
<li><strong>Destruction:</strong> The destructor <code>~Promise()</code> abandons and discards the shared state (<em>abandons any shared state</em>) <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>. Interpretation: If destruction occurs before setting a value or error, the orphaned shared state is likely aborted for waiting futures, analogous to the behavior of <code>std::promise</code>.</li>
</ul>

<h4>Usage Path</h4>
<p>The typical call sequence for asynchronous value or error transmission comprises the following steps:</p>
<ol>
<li><strong>Creation:</strong> The producer instantiates <code>ara::core::Promise&lt;T, E&gt;</code> via the default constructor <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>.</li>
<li><strong>Connect channel:</strong> Prior to passing the asynchronous task to a background thread, the producer calls <code>get_future()</code> <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a> and passes the resulting <code>ara::core::Future</code> instance to the consumer.</li>
<li><strong>Asynchronous processing:</strong> The producer executes the computation or the I/O operation. The consumer can continue working in parallel or wait for the <code>Future</code>.</li>
<li><strong>Set result:</strong> After completion of the operation, the producer stores the result in the shared state. Depending on the outcome, it selects:
<ul>
<li>Successful value: <code>set_value()</code> as copy <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a> or move <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>.</li>
<li>Error state: <code>SetError()</code> by move <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a> or copy <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>.</li>
<li>Existing Result object: <code>SetResult()</code> via copy <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a> or move <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>.</li>
</ul>
</li>
<li><strong>Release:</strong> By setting the result, the shared state is marked as ready; the consumer reads the value. The <code>Promise</code> is destroyed upon leaving the scope <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>.</li>
</ol>
