<h4>Kontext</h4>
<p>Die Klasse <code>ara::diag::DiagnosticServiceDynamicAccessList</code> dient einer adaptiven Anwendung (AA) dazu, eine dynamische Zugriffsliste (<code>DynamicAccessList</code>) für Diagnosedienste aufzubauen <a class="spec-record-ref" data-req="SWS_DM_01156" href="../spec/record.html?id=SWS_DM_01156">[SWS_DM_01156]</a>. Sie fungiert als Fabrik und Verwaltungseinheit für Dienstmuster, indem sie Instanzen von <code>DynamicAccessListDiagServiceBuilder</code> erzeugt <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>, <a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>. In der Architektur interagiert die Anwendung direkt mit der Liste, um Zugriffsregeln anhand von Dienstkennungen (SID) oder Byte-Sequenzen zu definieren, welche die Grundlage für die dynamische Zugriffskontrolle im Diagnosesubsystem bilden <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=428">SWS Diagnostics §8.13.1 „Class: DiagnosticServiceDynamicAccessList“</a>.</p>

<h4>Lebenszyklus</h4>
<p>Instanzen von <code>DiagnosticServiceDynamicAccessList</code> werden über den parameterlosen Standardkonstruktor erzeugt <a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>. Die Klasse ist als <code>final</code> deklariert <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=428">SWS Diagnostics §8.13.1 „Class: DiagnosticServiceDynamicAccessList“</a>. Sie unterstützt vollwertige Wertsemantik: Objekte können sowohl kopiert als auch verschoben werden, wofür entsprechende Kopier- und Verschiebekonstruktoren <a class="spec-record-ref" data-req="SWS_DM_01159" href="../spec/record.html?id=SWS_DM_01159">[SWS_DM_01159]</a>, <a class="spec-record-ref" data-req="SWS_DM_01160" href="../spec/record.html?id=SWS_DM_01160">[SWS_DM_01160]</a> sowie Zuweisungsoperatoren <a class="spec-record-ref" data-req="SWS_DM_01161" href="../spec/record.html?id=SWS_DM_01161">[SWS_DM_01161]</a>, <a class="spec-record-ref" data-req="SWS_DM_01162" href="../spec/record.html?id=SWS_DM_01162">[SWS_DM_01162]</a> bereitstehen. Nach der Initialisierung befindet sich das Objekt im Zustand zur Musteraufnahme, ehe es am Ende seiner Lebensdauer über den Destruktor bereinigt wird <a class="spec-record-ref" data-req="SWS_DM_01158" href="../spec/record.html?id=SWS_DM_01158">[SWS_DM_01158]</a>.</p>
<p>Hinsichtlich der Nebenläufigkeit sind die Konstruktoren (Standard-, Kopier- und Verschiebekonstruktor) explizit als threadsicher spezifiziert <a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>, <a class="spec-record-ref" data-req="SWS_DM_01159" href="../spec/record.html?id=SWS_DM_01159">[SWS_DM_01159]</a>, <a class="spec-record-ref" data-req="SWS_DM_01160" href="../spec/record.html?id=SWS_DM_01160">[SWS_DM_01160]</a>. Sämtliche manipulierenden Methoden wie Zuweisungen, Speicherreservierungen und Builder-Erzeugungen sowie der Destruktor sind hingegen als nicht threadsicher definiert <a class="spec-record-ref" data-req="SWS_DM_01161" href="../spec/record.html?id=SWS_DM_01161">[SWS_DM_01161]</a>, <a class="spec-record-ref" data-req="SWS_DM_01162" href="../spec/record.html?id=SWS_DM_01162">[SWS_DM_01162]</a>, <a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>, <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>, <a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>, <a class="spec-record-ref" data-req="SWS_DM_01158" href="../spec/record.html?id=SWS_DM_01158">[SWS_DM_01158]</a>. Ein nebenläufiger Zugriff auf dasselbe Objekt bedarf daher anwendungsseitiger Synchronisation.</p>

<h4>Nutzungspfad</h4>
<p>Der typische Ablauf beim Aufbau einer dynamischen Dienstzugriffsliste umfasst die folgenden Phasen:</p>
<ul>
<li><strong>Speichervoraballokation:</strong> Vor dem Hinzufügen von Dienstmustern kann die Anwendung mit <code>Reserve</code> Speicher für alle erwarteten Dienstmuster vorab reservieren <a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>. Die übergebenen Parameter <code>numberOfServiceHeads</code> und <code>maxServiceHeadSize</code> erlauben eine Worst-Case-Abschätzung des benötigten Speichers, um spätere dynamische Reallokationen zu minimieren.</li>
<li><strong>Erzeugung von Mustern:</strong> Die Anwendung ruft <code>MakeServiceBuilder</code> auf, um ein Diagnosedienstmuster einzuleiten. Dies geschieht entweder anhand eines einzelnen SID-Bytes <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a> oder einer Byte-Sequenz <code>serviceHead</code> für tiefergehende Musterprüfungen <a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>.</li>
<li><strong>Musterkonfiguration:</strong> Die Methode liefert ein Objekt vom Typ <code>DynamicAccessListDiagServiceBuilder</code> zurück <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>, welches die Anwendung anschließend konfiguriert.</li>
</ul>

<h4>Fehlerszenarien</h4>
<p>Alle öffentlichen Elementfunktionen und Konstruktoren der Klasse sind als <code>noexcept</code> deklariert und garantieren strikte Ausnahmesicherheit (<em>exception safe</em>) <a class="spec-record-ref" data-req="SWS_DM_01157" href="../spec/record.html?id=SWS_DM_01157">[SWS_DM_01157]</a>, <a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>, <a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>. Fehlerzustände in Form von C++-Ausnahmen oder Rückgabe von <code>ara::core::Result</code> mit Fehlercodes treten an dieser Schnittstelle nicht auf. Bei der Speicherreservierung via <code>Reserve</code> darf die Angabe eine Schätzung sein; eine Unterschätzung führt nicht zum Funktionsabbruch, dürfte jedoch spätere Neuallokationen erforderlich machen <a class="spec-record-ref" data-req="SWS_DM_01163" href="../spec/record.html?id=SWS_DM_01163">[SWS_DM_01163]</a>. Anwendungsentwickler müssen sicherstellen, dass die nicht threadsicheren Funktionen <code>Reserve</code>, <code>MakeServiceBuilder</code> und die Zuweisungsoperatoren niemals ohne externe Verriegelung gleichzeitig mit demselben Objekt ausgeführt werden.</p>
