<h4>Context</h4>
<p>The template class <code>ara::core::Result</code> represents a value type that contains either a successful result of type <code>value_type</code> (<code>T</code>) (<a class="spec-record-ref" data-req="SWS_CORE_00711" href="../spec/record.html?id=SWS_CORE_00711">[SWS_CORE_00711]</a>) or an error of type <code>error_type</code> (<code>E</code>) (<a class="spec-record-ref" data-req="SWS_CORE_00712" href="../spec/record.html?id=SWS_CORE_00712">[SWS_CORE_00712]</a>). By default, <code>E = ErrorCode</code> is defined. If the error type deviates (<code>E != ara::core::ErrorCode</code>), the specification strictly requires a compiler error.</p>
<p>As a central idiom of the AUTOSAR Adaptive Platform, <code>ara::core::Result</code> serves for the fault-tolerant return of values from interface calls without relying on C++ exceptions. Callers and services interact via this type in that the producer sets the state and the receiver either directly checks, transforms, or resolves the contained state.</p>

<h4>Lifecycle</h4>
<p>An instance of <code>ara::core::Result</code> is at any time in exactly one of two disjoint states: it contains either a valid value or an error. Creation is performed either via direct constructors for values (<a class="spec-record-ref" data-req="SWS_CORE_00721" href="../spec/record.html?id=SWS_CORE_00721">[SWS_CORE_00721]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00722" href="../spec/record.html?id=SWS_CORE_00722">[SWS_CORE_00722]</a>) or errors (<a class="spec-record-ref" data-req="SWS_CORE_00723" href="../spec/record.html?id=SWS_CORE_00723">[SWS_CORE_00723]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00724" href="../spec/record.html?id=SWS_CORE_00724">[SWS_CORE_00724]</a>), or via explicit static factories:</p>
<ul>
<li><code>FromValue</code>: Creates an instance from an lvalue, rvalue, or constructs the value directly in-place based on passed arguments (<a class="spec-record-ref" data-req="SWS_CORE_00731" href="../spec/record.html?id=SWS_CORE_00731">[SWS_CORE_00731]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00732" href="../spec/record.html?id=SWS_CORE_00732">[SWS_CORE_00732]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00733" href="../spec/record.html?id=SWS_CORE_00733">[SWS_CORE_00733]</a>).</li>
<li><code>FromError</code>: Creates an instance from an error lvalue, rvalue, or in-place via argument pack (<a class="spec-record-ref" data-req="SWS_CORE_00734" href="../spec/record.html?id=SWS_CORE_00734">[SWS_CORE_00734]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00735" href="../spec/record.html?id=SWS_CORE_00735">[SWS_CORE_00735]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00736" href="../spec/record.html?id=SWS_CORE_00736">[SWS_CORE_00736]</a>).</li>
</ul>
<p>Existing instances can be transferred via copy or move (<a class="spec-record-ref" data-req="SWS_CORE_00725" href="../spec/record.html?id=SWS_CORE_00725">[SWS_CORE_00725]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00726" href="../spec/record.html?id=SWS_CORE_00726">[SWS_CORE_00726]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00741" href="../spec/record.html?id=SWS_CORE_00741">[SWS_CORE_00741]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00742" href="../spec/record.html?id=SWS_CORE_00742">[SWS_CORE_00742]</a>) or swapped using <code>Swap</code> (<a class="spec-record-ref" data-req="SWS_CORE_00745" href="../spec/record.html?id=SWS_CORE_00745">[SWS_CORE_00745]</a>). A subsequent state change within an existing instance is possible via <code>EmplaceValue</code> (<a class="spec-record-ref" data-req="SWS_CORE_00743" href="../spec/record.html?id=SWS_CORE_00743">[SWS_CORE_00743]</a>) or <code>EmplaceError</code> (<a class="spec-record-ref" data-req="SWS_CORE_00744" href="../spec/record.html?id=SWS_CORE_00744">[SWS_CORE_00744]</a>), which discard the previous content and construct the new element in-place.</p>
<p>The destructor <code>~Result()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00727" href="../spec/record.html?id=SWS_CORE_00727">[SWS_CORE_00727]</a>) releases the respectively contained value or error; it is trivial if both <code>T</code> and <code>E</code> are trivially destructible. Read accesses are thread-safe, whereas modifying operations (such as <code>EmplaceValue</code>, <code>EmplaceError</code>, rvalue extractions, and assignments) are not thread-safe.</p>

<h4>Usage Path</h4>
<p>The typical processing of a received <code>ara::core::Result</code> follows a fixed sequence of state checking, targeted value or error access, or functional chaining:</p>
<ol>
<li><strong>State check:</strong> The caller checks via <code>HasValue()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00751" href="../spec/record.html?id=SWS_CORE_00751">[SWS_CORE_00751]</a>) or the conversion operator <code>operator bool()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00752" href="../spec/record.html?id=SWS_CORE_00752">[SWS_CORE_00752]</a>) whether a result value is present. The bool operator is disabled here if <code>T</code> itself is the type <code>bool</code>.</li>
<li><strong>Direct value access:</strong> If a value is present, access is performed via <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00756" href="../spec/record.html?id=SWS_CORE_00756">[SWS_CORE_00756]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00775" href="../spec/record.html?id=SWS_CORE_00775">[SWS_CORE_00775]</a>) or pointer-like operators such as <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00759" href="../spec/record.html?id=SWS_CORE_00759">[SWS_CORE_00759]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00774" href="../spec/record.html?id=SWS_CORE_00774">[SWS_CORE_00774]</a>) and <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00777" href="../spec/record.html?id=SWS_CORE_00777">[SWS_CORE_00777]</a>).</li>
<li><strong>Error handling:</strong> If no value is present, the error can be read out via <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00758" href="../spec/record.html?id=SWS_CORE_00758">[SWS_CORE_00758]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>) or directly compared for equality with an expected error using <code>CheckError()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00765" href="../spec/record.html?id=SWS_CORE_00765">[SWS_CORE_00765]</a>).</li>
<li><strong>Chaining and transformation:</strong> A transformation (callable) can be applied to the contained value via <code>Bind</code> (<a class="spec-record-ref" data-req="SWS_CORE_00768" href="../spec/record.html?id=SWS_CORE_00768">[SWS_CORE_00768]</a>). If a value is present, <code>Bind</code> returns the transformed new <code>ara::core::Result</code>; if an error is present, it is directly adopted into the new <code>Result</code>. Alternatively, <code>Resolve</code> (<a class="spec-record-ref" data-req="SWS_CORE_00767" href="../spec/record.html?id=SWS_CORE_00767">[SWS_CORE_00767]</a>) allows an error to be resolved by the return value of a callable.</li>
<li><strong>Optional conversion:</strong> Value or error can be extracted as <code>ara::core::Optional</code> via <code>Ok()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00770" href="../spec/record.html?id=SWS_CORE_00770">[SWS_CORE_00770]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00771" href="../spec/record.html?id=SWS_CORE_00771">[SWS_CORE_00771]</a>) and <code>Err()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00772" href="../spec/record.html?id=SWS_CORE_00772">[SWS_CORE_00772]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00773" href="../spec/record.html?id=SWS_CORE_00773">[SWS_CORE_00773]</a>).</li>
</ol>

<h4>Error Scenarios</h4>
<p>When calling access methods, strict preconditions are defined, non-compliance with which leads to standardized violations:</p>
<ul>
<li><strong><code>ResultWithNoValueViolation</code>:</strong> Occurs when the value is accessed via <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00756" href="../spec/record.html?id=SWS_CORE_00756">[SWS_CORE_00756]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00775" href="../spec/record.html?id=SWS_CORE_00775">[SWS_CORE_00775]</a>), <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00759" href="../spec/record.html?id=SWS_CORE_00759">[SWS_CORE_00759]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00774" href="../spec/record.html?id=SWS_CORE_00774">[SWS_CORE_00774]</a>), or <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00777" href="../spec/record.html?id=SWS_CORE_00777">[SWS_CORE_00777]</a>) even though the instance contains no value.</li>
<li><strong><code>ResultWithNoErrorViolation</code>:</strong> Occurs when an error is queried via <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00758" href="../spec/record.html?id=SWS_CORE_00758">[SWS_CORE_00758]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>), but the instance holds a valid value.</li>
</ul>
<p>To avoid violations without prior branching, <code>ValueOr</code> (<a class="spec-record-ref" data-req="SWS_CORE_00761" href="../spec/record.html?id=SWS_CORE_00761">[SWS_CORE_00761]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00762" href="../spec/record.html?id=SWS_CORE_00762">[SWS_CORE_00762]</a>) and <code>ErrorOr</code> (<a class="spec-record-ref" data-req="SWS_CORE_00763" href="../spec/record.html?id=SWS_CORE_00763">[SWS_CORE_00763]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00764" href="../spec/record.html?id=SWS_CORE_00764">[SWS_CORE_00764]</a>) provide the return of a passed default value or default error in case of missing content.</p>
<p>If an error code is to be converted into a C++ exception, <code>ValueOrThrow()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00766" href="../spec/record.html?id=SWS_CORE_00766">[SWS_CORE_00766]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00769" href="../spec/record.html?id=SWS_CORE_00769">[SWS_CORE_00769]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00778" href="../spec/record.html?id=SWS_CORE_00778">[SWS_CORE_00778]</a>) is available. This method throws the exception type associated with the error if no value is present. If C++ exceptions are disabled in the compiler toolchain, <code>ValueOrThrow()</code> does not participate in overload resolution.</p>
