<p class="ai-level ai-oneliner-lead" data-ai-level="1">Kapselt entweder einen Erfolgs- oder einen Fehlerwert zur synchronen, ausnahmefreien Ergebnisübermittlung.</p>
<div class="ai-level" data-ai-level="2">
<p>Die Klasse stellt einen typsicheren Behälter dar, der entweder einen Nutzwert oder einen Fehlercode aufnimmt, um Rechenergebnisse synchron und ohne C++-Ausnahmen zu übermitteln <a class="spec-record-ref" data-req="SWS_CORE_00751" href="../spec/record.html?id=SWS_CORE_00751">[SWS_CORE_00751]</a>. Aufrufer erzeugen Instanzen über dedizierte Konstruktoren oder Fabrikfunktionen und werten das Resultat anschließend zustandsabhängig über Prüf- und Zugriffsfunktionen wie den Wert- oder Fehlerzugriff aus. Als wesentliche Randbedingung muss der zugrunde liegende Fehlertyp zwingend dem standardmäßigen Fehlercode entsprechen, da abweichende Typbelegungen zur Übersetzungszeit abgewiesen werden. Zudem setzen Funktionen zur Ausnahmeauslösung eine Compiler-Umgebung mit aktivierten C++-Exceptions voraus <a class="spec-record-ref" data-req="SWS_CORE_00766" href="../spec/record.html?id=SWS_CORE_00766">[SWS_CORE_00766]</a>.</p>

<div class="ai-level" data-ai-level="4">
<h4>Kontext</h4>
<p>Die Klasse <code>ara::core::Result</code> ist das zentrale Konstrukt der AUTOSAR Adaptive Platform zur synchronen, typisierten Rückgabe von Operationsergebnissen ohne zwingenden Einsatz von C++-Ausnahmen. Sie repräsentiert eine disjunkte Vereinigung (Tagged Union), die zu jedem Zeitpunkt entweder einen Nutzwert vom Typ <code>value_type</code> (<code>T</code>) oder einen Fehler vom Typ <code>error_type</code> (<code>E</code>) beinhaltet <a class="spec-record-ref" data-req="SWS_CORE_00711" href="../spec/record.html?id=SWS_CORE_00711">[SWS_CORE_00711]</a> <a class="spec-record-ref" data-req="SWS_CORE_00712" href="../spec/record.html?id=SWS_CORE_00712">[SWS_CORE_00712]</a>. Standardmäßig fungiert <code>ara::core::ErrorCode</code> als Typ für <code>E</code>; abweichende Fehlerdefinitionen werden von Implementierungen bereits zur Übersetzungszeit durch einen Kompilierfehler unterbunden.</p>
<p>In der Anwendungsarchitektur vermittelt <code>ara::core::Result</code> zwischen aufgerufenen Diensten und Konsumenten. Dienste instanziieren das Objekt zur Rückgabe des Status, während Konsumenten über Zustandstests wie <a class="spec-record-ref" data-req="SWS_CORE_00751" href="../spec/record.html?id=SWS_CORE_00751">[SWS_CORE_00751]</a> oder funktionale Verkettungen wie <a class="spec-record-ref" data-req="SWS_CORE_00768" href="../spec/record.html?id=SWS_CORE_00768">[SWS_CORE_00768]</a> eine Weiterverarbeitung anstoßen. Darüber hinaus lässt sich der Zustand über <a class="spec-record-ref" data-req="SWS_CORE_00770" href="../spec/record.html?id=SWS_CORE_00770">[SWS_CORE_00770]</a> (<code>Ok</code>) und <a class="spec-record-ref" data-req="SWS_CORE_00772" href="../spec/record.html?id=SWS_CORE_00772">[SWS_CORE_00772]</a> (<code>Err</code>) in <code>ara::core::Optional</code> überführen.</p>

<h4>Lebenszyklus</h4>
<p>Die Initialisierung einer Instanz erfolgt entweder direkt über Konstruktoren für Werte (<a class="spec-record-ref" data-req="SWS_CORE_00721" href="../spec/record.html?id=SWS_CORE_00721">[SWS_CORE_00721]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00722" href="../spec/record.html?id=SWS_CORE_00722">[SWS_CORE_00722]</a>) oder explizit für Fehler (<a class="spec-record-ref" data-req="SWS_CORE_00723" href="../spec/record.html?id=SWS_CORE_00723">[SWS_CORE_00723]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00724" href="../spec/record.html?id=SWS_CORE_00724">[SWS_CORE_00724]</a>). Ergänzend stehen statische Fabrikfunktionen zur Verfügung: <code>FromValue</code> für Lvalues, Rvalues und In-Place-Argumente (<a class="spec-record-ref" data-req="SWS_CORE_00731" href="../spec/record.html?id=SWS_CORE_00731">[SWS_CORE_00731]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00732" href="../spec/record.html?id=SWS_CORE_00732">[SWS_CORE_00732]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00733" href="../spec/record.html?id=SWS_CORE_00733">[SWS_CORE_00733]</a>) sowie <code>FromError</code> zur Erzeugung von Fehlerzuständen (<a class="spec-record-ref" data-req="SWS_CORE_00734" href="../spec/record.html?id=SWS_CORE_00734">[SWS_CORE_00734]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00735" href="../spec/record.html?id=SWS_CORE_00735">[SWS_CORE_00735]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00736" href="../spec/record.html?id=SWS_CORE_00736">[SWS_CORE_00736]</a>).</p>
<p><code>ara::core::Result</code> besitzt das enthaltene Datum exklusiv und verwaltet dessen Lebensdauer. Es unterstützt vollständige Wertsemantik über Kopier- und Verschiebekonstruktoren (<a class="spec-record-ref" data-req="SWS_CORE_00725" href="../spec/record.html?id=SWS_CORE_00725">[SWS_CORE_00725]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00726" href="../spec/record.html?id=SWS_CORE_00726">[SWS_CORE_00726]</a>) sowie entsprechende Zuweisungsoperatoren (<a class="spec-record-ref" data-req="SWS_CORE_00741" href="../spec/record.html?id=SWS_CORE_00741">[SWS_CORE_00741]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00742" href="../spec/record.html?id=SWS_CORE_00742">[SWS_CORE_00742]</a>). Ein Inhaltswechsel bestehender Instanzen ist mittels <code>Swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00745" href="../spec/record.html?id=SWS_CORE_00745">[SWS_CORE_00745]</a> oder durch In-Place-Überschreiben via <code>EmplaceValue</code> <a class="spec-record-ref" data-req="SWS_CORE_00743" href="../spec/record.html?id=SWS_CORE_00743">[SWS_CORE_00743]</a> beziehungsweise <code>EmplaceError</code> <a class="spec-record-ref" data-req="SWS_CORE_00744" href="../spec/record.html?id=SWS_CORE_00744">[SWS_CORE_00744]</a> möglich.</p>
<p>Der Destruktor gibt das aktive Element frei und gilt als trivial destruierbar, wenn sowohl <code>T</code> als auch <code>E</code> trivial destruierbar sind <a class="spec-record-ref" data-req="SWS_CORE_00727" href="../spec/record.html?id=SWS_CORE_00727">[SWS_CORE_00727]</a>. Bezüglich der Nebenläufigkeit sind rein lesende Zugriffe threadsicher, während modifizierende Operationen wie <code>EmplaceValue</code>, <code>EmplaceError</code>, Verschiebe-Zuweisungen oder <code>Swap</code> nicht threadsicher sind und externer Synchronisation bedürfen.</p>

<h4>Nutzungspfad</h4>
<p>Der reguläre Ablauf umfasst die Erzeugung, Validierung und Entnahme des Ergebnisses:</p>
<ol>
<li><strong>Bereitstellung:</strong> Ein Dienst erzeugt das Ergebnis über <a class="spec-record-ref" data-req="SWS_CORE_00731" href="../spec/record.html?id=SWS_CORE_00731">[SWS_CORE_00731]</a> oder <a class="spec-record-ref" data-req="SWS_CORE_00734" href="../spec/record.html?id=SWS_CORE_00734">[SWS_CORE_00734]</a> und gibt die Instanz per Wert zurück.</li>
<li><strong>Zustandsprüfung:</strong> Der Aufrufer prüft mittels <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00751" href="../spec/record.html?id=SWS_CORE_00751">[SWS_CORE_00751]</a> oder dem expliziten Konvertierungsoperator <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00752" href="../spec/record.html?id=SWS_CORE_00752">[SWS_CORE_00752]</a>, ob ein Wert vorliegt. Letzterer ist deaktiviert, wenn <code>T</code> selbst vom Typ <code>bool</code> ist.</li>
<li><strong>Wert- und Fehlerzugriff:</strong> Liegt ein Wert vor, kann dieser über <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00756" href="../spec/record.html?id=SWS_CORE_00756">[SWS_CORE_00756]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00775" href="../spec/record.html?id=SWS_CORE_00775">[SWS_CORE_00775]</a>) oder die Operatoren <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00759" href="../spec/record.html?id=SWS_CORE_00759">[SWS_CORE_00759]</a>) und <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00777" href="../spec/record.html?id=SWS_CORE_00777">[SWS_CORE_00777]</a>) ausgelesen werden. Im Fehlerfall erfolgt der Zugriff über <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00758" href="../spec/record.html?id=SWS_CORE_00758">[SWS_CORE_00758]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>) oder die gezielte Fehlerprüfung mit <code>CheckError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00765" href="../spec/record.html?id=SWS_CORE_00765">[SWS_CORE_00765]</a>.</li>
<li><strong>Funktionale Transformation:</strong> Alternativ erlaubt <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00768" href="../spec/record.html?id=SWS_CORE_00768">[SWS_CORE_00768]</a> eine monadische Weiterverarbeitung: Das übergebene Callable wird nur ausgeführt, wenn ein Nutzwert enthalten ist; ein bestehender Fehler wird unverändert in die neue <code>Result</code>-Instanz propagiert. Fallbacks lassen sich mit <code>Resolve()</code> <a class="spec-record-ref" data-req="SWS_CORE_00767" href="../spec/record.html?id=SWS_CORE_00767">[SWS_CORE_00767]</a> abbilden.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Der Zugriff auf nicht aktive Zustände verletzt die Vorbedingungen der Klasse:</p>
<ul>
<li>Der Aufruf von <code>Value()</code>, <code>operator*</code> oder <code>operator-&gt;</code> ohne enthaltenen Wert löst die dokumentierte Systemverletzung <code>ResultWithNoValueViolation</code> aus (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>).</li>
<li>Der Aufruf von <code>Error()</code> bei vorhandenem Nutzwert führt zur Verletzung <code>ResultWithNoErrorViolation</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>).</li>
</ul>
<p>Interpretation: Das Auslösen einer solchen Vorbedingungsverletzung dürfte in Laufzeitumgebungen typischerweise zum sofortigen Prozessabbruch führen, da der Standard diese Zustände als gravierende Programmierfehler einstuft. Zur Vermeidung harter Abbrüche können defensive Methoden genutzt werden: <code>ValueOr()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00761" href="../spec/record.html?id=SWS_CORE_00761">[SWS_CORE_00761]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00762" href="../spec/record.html?id=SWS_CORE_00762">[SWS_CORE_00762]</a>) und <code>ErrorOr()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00763" href="../spec/record.html?id=SWS_CORE_00763">[SWS_CORE_00763]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00764" href="../spec/record.html?id=SWS_CORE_00764">[SWS_CORE_00764]</a>) liefern bei abwesendem Element einen vorgegebenen Standardwert zurück. Optionalvarianten wie <code>Ok()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00770" href="../spec/record.html?id=SWS_CORE_00770">[SWS_CORE_00770]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00771" href="../spec/record.html?id=SWS_CORE_00771">[SWS_CORE_00771]</a>) und <code>Err()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00772" href="../spec/record.html?id=SWS_CORE_00772">[SWS_CORE_00772]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00773" href="../spec/record.html?id=SWS_CORE_00773">[SWS_CORE_00773]</a>) kapseln den Zugriff ausnahmefrei.</p>
<p>Wird eine Ausnahmebehandlung gewünscht, wirft <code>ValueOrThrow()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00766" href="../spec/record.html?id=SWS_CORE_00766">[SWS_CORE_00766]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00769" href="../spec/record.html?id=SWS_CORE_00769">[SWS_CORE_00769]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00778" href="../spec/record.html?id=SWS_CORE_00778">[SWS_CORE_00778]</a>) im Fehlerfall die dem Fehler zugeordnete C++-Ausnahme. Sind C++-Exceptions im Compiler deaktiviert, wird <code>ValueOrThrow()</code> aus der Überladungsauflösung entfernt <a class="spec-record-ref" data-req="SWS_CORE_00766" href="../spec/record.html?id=SWS_CORE_00766">[SWS_CORE_00766]</a>; ebenso ist die nicht-konstante Lvalue-Überladung von <code>operator*</code> in diesem Fall deaktiviert <a class="spec-record-ref" data-req="SWS_CORE_00774" href="../spec/record.html?id=SWS_CORE_00774">[SWS_CORE_00774]</a>.</p>
