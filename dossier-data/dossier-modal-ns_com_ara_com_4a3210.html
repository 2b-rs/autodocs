<h4>Context</h4>
<p>The <code>ara::com</code> namespace forms the core interface for Communication Management within the AUTOSAR Adaptive Platform. It provides the standardized abstraction layer through which functional software components interact with each other or with platform services <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=8">EXP_ARAComAPI §1 “Preface”</a>. The goal is to decouple application-side components from the details of the underlying communication media, while platform vendors can implement optimized IPC bindings (Inter-Process Communication) or network protocols <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=8">EXP_ARAComAPI §1 “Preface”</a>.</p>
<p>The <code>InstanceIdentifier</code>, which uniquely addresses a specific service instance, as well as <code>InstanceIdentifierContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00319" href="../spec/record.html?id=SWS_CM_00319">[SWS_CM_00319]</a> as a structured collection of instance identifiers, serve to differentiate similar services. During dynamic instance discovery, the system generates instance handles that are aggregated in a <code>ServiceHandleContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00304" href="../spec/record.html?id=SWS_CM_00304">[SWS_CM_00304]</a> and passed to requesting software components via <code>FindServiceHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00383" href="../spec/record.html?id=SWS_CM_00383">[SWS_CM_00383]</a>.</p>

<h4>Lifecycle</h4>
<p>The lifecycle of communication relationships in <code>ara::com</code> is divided into service availability, event subscription states, and the management of data samples:</p>
<ul>
<li><strong>Service availability:</strong> The state of an offered service is represented by the enum <code>ServiceState</code> <a class="spec-record-ref" data-req="SWS_CM_01071" href="../spec/record.html?id=SWS_CM_01071">[SWS_CM_01071]</a> with the values <code>kAvailable</code> and <code>kNotAvailable</code>. State changes can be registered and evaluated asynchronously using <code>ServiceStateHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01072" href="../spec/record.html?id=SWS_CM_01072">[SWS_CM_01072]</a>.</li>
<li><strong>Subscription state:</strong> Participation in event updates follows the lifecycle of <code>SubscriptionState</code> <a class="spec-record-ref" data-req="SWS_CM_00310" href="../spec/record.html?id=SWS_CM_00310">[SWS_CM_00310]</a>. A subscription begins in <code>kNotSubscribed</code>, transitions to the transitional state <code>kSubscriptionPending</code> upon request, and changes to <code>kSubscribed</code> after successful establishment. Status changes are signaled to the application via the functor <code>SubscriptionStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00311" href="../spec/record.html?id=SWS_CM_00311">[SWS_CM_00311]</a>.</li>
<li><strong>Memory and sample lifecycle:</strong> The memory for data to be transmitted is provided on the sender side via <code>SampleAllocateePtr</code> <a class="spec-record-ref" data-req="SWS_CM_00308" href="../spec/record.html?id=SWS_CM_00308">[SWS_CM_00308]</a>, which is based on <code>std::unique_ptr</code>. Received data samples are passed to the consumer as <code>SamplePtr</code>. This emulates a <code>std::unique_ptr</code> and guarantees the validity of the data as long as the event remains subscribed.</li>
<li><strong>Concurrency in method calls:</strong> The enum <code>MethodCallProcessingMode</code> <a class="spec-record-ref" data-req="SWS_CM_00301" href="../spec/record.html?id=SWS_CM_00301">[SWS_CM_00301]</a> controls the behavior for processing incoming method calls. Possible options are synchronous polling (<code>kPoll</code>), concurrent event-driven processing (<code>kEvent</code>), or sequential processing in a single thread (<code>kEventSingleThread</code>).</li>
</ul>

<h4>Usage Path</h4>
<p>A typical communication sequence between service consumer and service provider comprises the phases discovery, notification registration, and data reception:</p>
<ol>
<li><strong>Service discovery:</strong> The consumer initiates the search for matching services. When new instances become available, the registered <code>FindServiceHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00383" href="../spec/record.html?id=SWS_CM_00383">[SWS_CM_00383]</a> is called, which passes a <code>ServiceHandleContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00304" href="../spec/record.html?id=SWS_CM_00304">[SWS_CM_00304]</a> containing matches as well as a <code>FindServiceHandle</code> to terminate the search.</li>
<li><strong>Subscription and callback registration:</strong> The event is subscribed to on the selected service instance. To be notified of incoming data, the consumer registers a <code>EventReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00309" href="../spec/record.html?id=SWS_CM_00309">[SWS_CM_00309]</a>. Analogously, <code>FieldReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_11615" href="../spec/record.html?id=SWS_CM_11615">[SWS_CM_11615]</a> is available for field notifications and <code>TriggerReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00351" href="../spec/record.html?id=SWS_CM_00351">[SWS_CM_00351]</a> for trigger events.</li>
<li><strong>Data transmission and access:</strong> As soon as new payload data is available, the runtime environment triggers the registered receive handler <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=2">EXP_ARAComAPI §1 “Changed explanation of Event reception”</a>. The application then reads the data via <code>SamplePtr</code> instances.</li>
</ol>

<h4>Error Scenarios</h4>
<p>Recoverable errors in module <code>ara::com</code> are mapped by the error domain <code>ComErrorDomain</code> and the error codes of the enum <code>ComErrc</code> <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=9">EXP_ARAComAPI §2 “Acronyms and Abbreviations”</a>. Standardized error objects are created via the helper function <code>MakeErrorCode()</code> <a class="spec-record-ref" data-req="SWS_CM_11335" href="../spec/record.html?id=SWS_CM_11335">[SWS_CM_11335]</a>, while <code>GetComErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_CM_11334" href="../spec/record.html?id=SWS_CM_11334">[SWS_CM_11334]</a> provides access to the static instance of the error domain.</p>
<p>Essential error conditions include:</p>
<ul>
<li><code>ComErrc::kServiceNotOffered</code> and <code>ComErrc::kServiceNotAvailable</code>: Method calls or accesses fail if a service is not or no longer provided via <code>OfferService()</code> <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kInstanceIDNotResolvable</code>: A logical <code>InstanceSpecifier</code> could not be resolved to a concrete <code>InstanceIdentifier</code> <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kMaxSamplesExceeded</code>: The consumer holds more concurrent <code>SamplePtr</code> instances than specified in <code>Subscribe()</code>, which can lead to dropped samples <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kMaxSampleCountNotRealizable</code>: During a resubscription, the passed counter deviates from the existing subscription <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kFieldValueNotInitialized</code> and <code>ComErrc::kFieldSetHandlerNotSet</code>: Incomplete initialization of field elements prior to data access <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kMinimumSendIntervalViolationError</code>: Transmission requests violate the minimum transmission interval configured in the interface deployment <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
<li><code>ComErrc::kCommunicationFailure</code>: An error in the underlying network binding or an error during secured communication <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>.</li>
</ul>
