<h4>Role of the LIN Driver Between LIN Interface and Controller Hardware</h4>
<p>The LIN driver (<code>Lin</code>) encapsulates the ECU's LIN hardware unit, i.e., a dedicated LIN controller or a simple UART. It provides it to the LIN Interface (<code>LinIf</code>) as channel-specific services. The driver receives frame orders as <code>Lin_PduType</code> with the following specifications: PID, checksum model, response type, data length, and SDU pointer <a class="spec-record-ref" data-req="SWS_Lin_00232" href="../../spec/record.html?id=SWS_Lin_00232">[SWS_Lin_00232]</a>. In the feature model, LIN is an optional network technology with the sub-features LIN_Master and LIN_Slave <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_FIGURE_Figure_4_47.html" data-snip="SNIP_CLASSIC_LIN_FIGURE_Figure_4_47">FO Features p. 58</a>. The driver serves both roles per channel. However, several services are available only to master channels <a class="spec-record-ref" data-req="SWS_Lin_00287" href="../../spec/record.html?id=SWS_Lin_00287">[SWS_Lin_00287]</a> <a class="spec-record-ref" data-req="SWS_Lin_00288" href="../../spec/record.html?id=SWS_Lin_00288">[SWS_Lin_00288]</a> <a class="spec-record-ref" data-req="SWS_Lin_00289" href="../../spec/record.html?id=SWS_Lin_00289">[SWS_Lin_00289]</a>.</p>
<p>The driver uses three mandatory interfaces of other modules:</p>
<ul>
<li><code>Dem_SetEventStatus</code> for production errors.</li>
<li><code>EcuM_SetWakeupEvent</code> and <code>LinIf_WakeupConfirmation</code> for detected wakeup events <a class="spec-record-ref" data-req="SWS_Lin_00234" href="../../spec/record.html?id=SWS_Lin_00234">[SWS_Lin_00234]</a>.</li>
</ul>
<p>Optionally, <code>Det_ReportError</code>, <code>EcuM_CheckWakeup</code>, and the Icu notification control are added <a class="spec-record-ref" data-req="SWS_Lin_00235" href="../../spec/record.html?id=SWS_Lin_00235">[SWS_Lin_00235]</a>. On slave channels, the driver reports headers, reception, transmit confirmation, and errors via LinIf callbacks <a class="spec-record-ref" data-req="SWS_Lin_00280" href="../../spec/record.html?id=SWS_Lin_00280">[SWS_Lin_00280]</a> <a class="spec-record-ref" data-req="SWS_Lin_00274" href="../../spec/record.html?id=SWS_Lin_00274">[SWS_Lin_00274]</a> <a class="spec-record-ref" data-req="SWS_Lin_00275" href="../../spec/record.html?id=SWS_Lin_00275">[SWS_Lin_00275]</a> <a class="spec-record-ref" data-req="SWS_Lin_00277" href="../../spec/record.html?id=SWS_Lin_00277">[SWS_Lin_00277]</a>. It does not provide callback functions of its own <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_4_Callback_notifications.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_4_Callback_notifications">SWS LINDriver p. 49</a>. Complete sequence diagrams are not located in the driver specification, but in the LinIf specification <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_9_Sequence_diagrams_LINDRIVER.html" data-snip="SNIP_CLASSIC_LIN_SECTION_9_Sequence_diagrams_LINDRIVER">SWS LINDriver p. 52</a>.</p>

<h4>Module and Channel States from Reset to Operation</h4>
<p>The driver operates with a two-stage state machine. After reset, the module is in <code>LIN_UNINIT</code> and cannot be used. Calling <code>Lin_Init</code> transitions it to <code>LIN_INIT</code>; there, every available channel is operational <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams">SWS LINDriver p. 24</a> <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-dcf2a3bff77bc510.html" data-snip="FIG-dcf2a3bff77bc510">SWS LINDriver Fig. 7.1 p. 24</a>. <code>Lin_Init</code> is synchronous and non-reentrant. The service receives a pointer to a <code>Lin_ConfigType</code>. Its content is hardware-dependent and configures the driver, hardware unit, and channels <a class="spec-record-ref" data-req="SWS_Lin_00006" href="../../spec/record.html?id=SWS_Lin_00006">[SWS_Lin_00006]</a> <a class="spec-record-ref" data-req="SWS_Lin_00227" href="../../spec/record.html?id=SWS_Lin_00227">[SWS_Lin_00227]</a>. The environment shall call <code>Lin_Init</code> only once at runtime <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams">SWS LINDriver p. 24</a>.</p>
<p>Within <code>LIN_INIT</code>, each channel has its own state <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_FIGURE_Figure_7_1_LINDRIVER.html" data-snip="SNIP_CLASSIC_LIN_FIGURE_Figure_7_1_LINDRIVER">SWS LINDriver p. 23</a>:</p>
<ul>
<li><code>LIN_CH_OPERATIONAL</code>: The channel is initialized and participates in the LIN cluster <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams">SWS LINDriver p. 24</a>.</li>
<li><code>LIN_CH_SLEEP</code>: Wakeup pulse detection is active, and the hardware is possibly in low-power mode <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_3_3_State_diagrams">SWS LINDriver p. 24</a>.</li>
<li><code>LIN_CH_SLEEP_PENDING</code>: Master channels only. Intermediate state after <code>Lin_GoToSleep</code> that is completed only by <code>Lin_GetStatus</code> <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-dcf2a3bff77bc510.html" data-snip="FIG-dcf2a3bff77bc510">SWS LINDriver Fig. 7.1 p. 24</a>.</li>

<h4>Master Channels: Frame Request and Status Polling</h4>
<p>On a master channel, LinIf triggers each schedule entry with <code>Lin_SendFrame</code>. The service is asynchronous and transmits a LIN header as well as, depending on the response type, the response <a class="spec-record-ref" data-req="SWS_Lin_00191" href="../../spec/record.html?id=SWS_Lin_00191">[SWS_Lin_00191]</a>. The fields of the <code>Lin_PduType</code> define the frame <a class="spec-record-ref" data-req="SWS_Lin_00232" href="../../spec/record.html?id=SWS_Lin_00232">[SWS_Lin_00232]</a>:</p>
<ul>
<li><code>Pid</code> (<code>Lin_FramePidType</code>, 0…0xFE): Identifier 0…0x3F including the two parity bits <a class="spec-record-ref" data-req="SWS_Lin_00228" href="../../spec/record.html?id=SWS_Lin_00228">[SWS_Lin_00228]</a>.</li>
<li><code>Cs</code> (<code>Lin_FrameCsModelType</code>): <code>LIN_CLASSIC_CS</code> or <code>LIN_ENHANCED_CS</code>. The driver calculates the appropriate checksum <a class="spec-record-ref" data-req="SWS_Lin_00229" href="../../spec/record.html?id=SWS_Lin_00229">[SWS_Lin_00229]</a> <a class="spec-record-ref" data-req="SWS_Lin_00019" href="../../spec/record.html?id=SWS_Lin_00019">[SWS_Lin_00019]</a>.</li>
<li><code>Drc</code> (<code>Lin_FrameResponseType</code>): The response comes from this node (<code>LIN_FRAMERESPONSE_TX</code>), from another relevant node (<code>LIN_FRAMERESPONSE_RX</code>), or is irrelevant (<code>LIN_FRAMERESPONSE_IGNORE</code>) <a class="spec-record-ref" data-req="SWS_Lin_00230" href="../../spec/record.html?id=SWS_Lin_00230">[SWS_Lin_00230]</a>.</li>
<li><code>Dl</code> (<code>Lin_FrameDlType</code>, 1…8): Number of data bytes to be copied <a class="spec-record-ref" data-req="SWS_Lin_00231" href="../../spec/record.html?id=SWS_Lin_00231">[SWS_Lin_00231]</a>.</li>
</ul>
<p>In memory, element 0 of the SDU array contains the byte transmitted first <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_4_4_Data_byte_mapping.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_4_4_Data_byte_mapping">SWS LINDriver p. 30</a>. If the hardware cannot buffer bytes, the driver provides a temporary buffer. Transmission and reception are non-blocking <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_7_4_2_3_Common.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_7_4_2_3_Common">SWS LINDriver p. 28</a>. The master transmits slave-to-slave frames using <code>LIN_FRAMERESPONSE_IGNORE</code> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_2_4_Lin_FrameResponseType.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_2_4_Lin_FrameResponseType">SWS LINDriver p. 37</a>. LinIf supports this communication type, but does not recommend it <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_1_4_Slave_to_slave_communication_Master_only.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_1_4_Slave_to_slave_communication_Master_only">SWS LINInterface p. 45</a>.</p>

<h4>Slave channels: Header-driven response processing</h4>
<p>A slave does not know the master's schedule. It only responds to received headers <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_1_2_2_Frame_reception_in_slave_nodes.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_1_2_2_Frame_reception_in_slave_nodes">SWS LINInterface p. 38</a>. In state <code>LIN_CH_OPERATIONAL</code>, the driver must be able to receive a header consisting of break, sync, and PID at any time <a class="spec-record-ref" data-req="SWS_Lin_00272" href="../../spec/record.html?id=SWS_Lin_00272">[SWS_Lin_00272]</a>. It then calls <code>LinIf_HeaderIndication</code>. In doing so, it passes the received PID and a pointer to its hardware or shadow buffer <a class="spec-record-ref" data-req="SWS_Lin_00280" href="../../spec/record.html?id=SWS_Lin_00280">[SWS_Lin_00280]</a>. If the hardware cannot detect invalid PIDs, the driver forwards the PID unchecked <a class="spec-record-ref" data-req="SWS_Lin_00271" href="../../spec/record.html?id=SWS_Lin_00271">[SWS_Lin_00271]</a>.</p>
<p>LinIf defines the response type in the callback. If it returns <code>E_OK</code>, the driver evaluates <code>PduPtr-&gt;Drc</code> <a class="spec-record-ref" data-req="SWS_Lin_00282" href="../../spec/record.html?id=SWS_Lin_00282">[SWS_Lin_00282]</a>:</p>
<ul>
<li><code>LIN_FRAMERESPONSE_TX</code>: The driver sets up the response from <code>Cs</code>, <code>Dl</code>, and <code>SduPtr</code> and transmits it. It reports success via <code>LinIf_TxConfirmation</code> <a class="spec-record-ref" data-req="SWS_Lin_00283" href="../../spec/record.html?id=SWS_Lin_00283">[SWS_Lin_00283]</a> <a class="spec-record-ref" data-req="SWS_Lin_00275" href="../../spec/record.html?id=SWS_Lin_00275">[SWS_Lin_00275]</a>.</li>
<li><code>LIN_FRAMERESPONSE_RX</code>: The driver configures reception with <code>Cs</code> and <code>Dl</code>. It reports success via <code>LinIf_RxIndication</code> with the received data <a class="spec-record-ref" data-req="SWS_Lin_00284" href="../../spec/record.html?id=SWS_Lin_00284">[SWS_Lin_00284]</a> <a class="spec-record-ref" data-req="SWS_Lin_00274" href="../../spec/record.html?id=SWS_Lin_00274">[SWS_Lin_00274]</a>.</li>
<li><code>E_NOT_OK</code> or <code>LIN_FRAMERESPONSE_IGNORE</code>: The driver ignores the response and reports nothing until the next header <a class="spec-record-ref" data-req="SWS_Lin_00286" href="../../spec/record.html?id=SWS_Lin_00286">[SWS_Lin_00286]</a> <a class="spec-record-ref" data-req="SWS_Lin_00276" href="../../spec/record.html?id=SWS_Lin_00276">[SWS_Lin_00276]</a>.</li>
</ul>
<p>Each relevant response must be completed before the next header indication, specifically with an Rx indication, Tx confirmation, or error indication <a class="spec-record-ref" data-req="SWS_Lin_00285" href="../../spec/record.html?id=SWS_Lin_00285">[SWS_Lin_00285]</a>. During transmission, LinIf has the data written directly into the driver buffer; the driver handles the copying <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LINIF_SECTION_9_1_2_Frame_transmission_in_slave_nodes.html" data-snip="SNIP_CLASSIC_LINIF_SECTION_9_1_2_Frame_transmission_in_slave_nodes">SWS LINInterface p. 121</a>.</p>

<h4>Sleep command, wake-up, and wake-up detection</h4>
<p>Only a master can transmit a go-to-sleep command. <code>Lin_GoToSleep</code> is asynchronous and instructs the driver to do so <a class="spec-record-ref" data-req="SWS_Lin_00166" href="../../spec/record.html?id=SWS_Lin_00166">[SWS_Lin_00166]</a>. In pure slave configurations, the service does not exist <a class="spec-record-ref" data-req="SWS_Lin_00288" href="../../spec/record.html?id=SWS_Lin_00288">[SWS_Lin_00288]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_5_1_Background_Rationale.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_5_1_Background_Rationale">SWS LINDriver p. 31</a>. The channel transitions to <code>LIN_CH_SLEEP_PENDING</code> in the process, even if the transmission fails <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_3_2_2_Lin_GoToSleep.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_3_2_2_Lin_GoToSleep">SWS LINDriver p. 43</a>.</p>
<p>In contrast, <code>Lin_GoToSleepInternal</code> works synchronously and without a bus command: The service sets the channel to <code>LIN_CH_SLEEP</code>, activates wake-up detection, and optionally switches the hardware into a power-saving mode <a class="spec-record-ref" data-req="SWS_Lin_00167" href="../../spec/record.html?id=SWS_Lin_00167">[SWS_Lin_00167]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_3_2_3_Lin_GoToSleepInternal.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_3_2_3_Lin_GoToSleepInternal">SWS LINDriver p. 44</a>. Each channel accepts sleep requests independently of the others <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_5_2_Requirements.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_5_2_Requirements">SWS LINDriver p. 31</a>.</p>

<h4>Configuration: Node type, channels, and partitions</h4>
<p>The parameter <code>LinNodeType</code> determines which services exist. <code>Lin_SendFrame</code>, <code>Lin_GoToSleep</code>, and <code>Lin_GetStatus</code> exist only if at least one channel is configured as master <a class="spec-record-ref" data-req="SWS_Lin_00287" href="../../spec/record.html?id=SWS_Lin_00287">[SWS_Lin_00287]</a> <a class="spec-record-ref" data-req="SWS_Lin_00288" href="../../spec/record.html?id=SWS_Lin_00288">[SWS_Lin_00288]</a> <a class="spec-record-ref" data-req="SWS_Lin_00289" href="../../spec/record.html?id=SWS_Lin_00289">[SWS_Lin_00289]</a>. The container <code>LinChannel</code> contains, per channel, among other things baud rate, channel ID, wake-up support, node type, an optional EcuM wake-up source, and a clock reference <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_10_2_3_LinChannel.html" data-snip="SNIP_CLASSIC_LIN_SECTION_10_2_3_LinChannel">SWS LINDriver p. 60</a>. <code>LinGeneral</code> summarizes the driver-wide parameters <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_10_2_2_LinGeneral.html" data-snip="SNIP_CLASSIC_LIN_SECTION_10_2_2_LinGeneral">SWS LINDriver p. 57</a>. According to the configuration diagram, these include development error detection, version API, and timeout duration <a class="docref internal-spec-ref" href="../../../spec/figures/FIG-a49521fd41bcd5e2.html" data-snip="FIG-a49521fd41bcd5e2">SWS LINDriver Fig. 10.1 p. 48</a>.</p>
<p>In multi-partition systems, the following rules apply:</p>
<ul>
<li>The driver operates as an independent instance in each partition; an API call affects only its own partition <a class="spec-record-ref" data-req="SWS_Lin_CONSTR_00270" href="../../spec/record.html?id=SWS_Lin_CONSTR_00270">[SWS_Lin_CONSTR_00270]</a>.</li>
<li>If <code>LinEcucPartitionRef</code> references partitions, each channel must reference exactly one of them <a class="spec-record-ref" data-req="SWS_Lin_CONSTR_00291" href="../../spec/record.html?id=SWS_Lin_CONSTR_00291">[SWS_Lin_CONSTR_00291]</a>.</li>
<li><code>LinChannel</code> and <code>LinTrcvChannel</code> of a channel must use the same partition <a class="spec-record-ref" data-req="SWS_Lin_CONSTR_00279" href="../../spec/record.html?id=SWS_Lin_CONSTR_00279">[SWS_Lin_CONSTR_00279]</a>.</li>
<li>The driver rejects unsupported partition assignments <a class="spec-record-ref" data-req="SWS_Lin_00269" href="../../spec/record.html?id=SWS_Lin_00269">[SWS_Lin_00269]</a>.</li>
</ul>
<p>The version information of the module is provided by <code>Lin_GetVersionInfo</code> <a class="spec-record-ref" data-req="SWS_Lin_00161" href="../../spec/record.html?id=SWS_Lin_00161">[SWS_Lin_00161]</a>.</p>

<h4>Behavior in the event of an error</h4>
<p>If development error detection is active, the channel services check initialization, channel number, and state. For <code>Lin_WakeupInternal</code>, this is normatively documented <a class="spec-record-ref" data-req="SWS_Lin_00258" href="../../spec/record.html?id=SWS_Lin_00258">[SWS_Lin_00258]</a> <a class="spec-record-ref" data-req="SWS_Lin_00259" href="../../spec/record.html?id=SWS_Lin_00259">[SWS_Lin_00259]</a> <a class="spec-record-ref" data-req="SWS_Lin_00260" href="../../spec/record.html?id=SWS_Lin_00260">[SWS_Lin_00260]</a>:</p>
<ul>
<li><code>LIN_E_UNINIT</code>: Call before <code>Lin_Init</code>.</li>
<li><code>LIN_E_INVALID_CHANNEL</code>: Invalid or inactive channel.</li>
<li><code>LIN_E_STATE_TRANSITION</code>: The channel is not in <code>LIN_CH_SLEEP</code>.</li>
</ul>
<p><code>Lin_Wakeup</code> checks <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_3_2_4_Lin_Wakeup.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_3_2_4_Lin_Wakeup">SWS LINDriver p. 45</a> in the same manner. <code>Lin_GetVersionInfo</code> reports <code>LIN_E_PARAM_POINTER</code> if a NULL pointer is passed <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_8_3_1_3_Lin_GetVersionInfo.html" data-snip="SNIP_CLASSIC_LIN_SECTION_8_3_1_3_Lin_GetVersionInfo">SWS LINDriver p. 41</a>. The error classes follow the scheme of the general BSW specification <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_7_6_Error_Classification.html" data-snip="SNIP_CLASSIC_LIN_SECTION_7_6_Error_Classification">SWS LINDriver p. 32</a>.</p>
<p>The driver reports <code>LIN_E_TIMEOUT</code> as a production error. If it must wait for a status change after accessing control registers, a configurable timeout protects this waiting time. If it expires, this indicates a hardware error <a class="spec-record-ref" data-req="SWS_Lin_00290" href="../../spec/record.html?id=SWS_Lin_00290">[SWS_Lin_00290]</a>. The notification goes via <code>Dem_SetEventStatus</code> to the event referenced in <code>LinDemEventParameterRefs</code> <a class="spec-record-ref" data-req="SWS_Lin_00234" href="../../spec/record.html?id=SWS_Lin_00234">[SWS_Lin_00234]</a> <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_DEM_SECTION_10_2_5_LinDemEventParameterRefs.html" data-snip="SNIP_CLASSIC_DEM_SECTION_10_2_5_LinDemEventParameterRefs">SWS LINDriver p. 65</a>.</p>
<p>On master channels, bus errors are indicated in status value <a class="spec-record-ref" data-req="SWS_Lin_00233" href="../../spec/record.html?id=SWS_Lin_00233">[SWS_Lin_00233]</a>:</p>
<ul>
<li><code>LIN_TX_HEADER_ERROR</code>: Readback error, parity error, or physical bus error in the header.</li>
<li><code>LIN_TX_ERROR</code>: Faulty response transmission.</li>
<li><code>LIN_RX_ERROR</code>: Framing, overrun, or checksum error, or a response that is too short.</li>
<li><code>LIN_RX_NO_RESPONSE</code>: No response byte received so far.</li>
</ul>
<p>The evaluation is performed by LinIf. For event-triggered frames, <code>LIN_RX_ERROR</code> is considered a collision; LinIf then switches to a collision-resolving schedule <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_9_5_1_3_With_collision.html" data-snip="SNIP_CLASSIC_LIN_SECTION_9_5_1_3_With_collision">SWS LINInterface p. 129</a>. <code>LIN_RX_NO_RESPONSE</code> is not a communication error there <a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_LIN_SECTION_9_5_1_1_With_no_answer.html" data-snip="SNIP_CLASSIC_LIN_SECTION_9_5_1_1_With_no_answer">SWS LINInterface p. 127</a>.</p>
