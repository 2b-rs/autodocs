한 문장으로 표현되는 적응형 플랫폼

AUTOSAR Adaptive Platform은 고성능 차량 컴퓨터를 위한 서비스 지향 런타임 환경이다. Adaptive Applications는 독립 POSIX 프로세스로 실행되고 동적으로 시작 및 감독되며, 정적으로 연결된 신호 대신 계약으로 정의된 Services를 통해 통신한다(EXP PlatformDesign §3.3 “Adaptive Platform – Characteristics”, §8.2 “Service Oriented Communication”).

ARA — 이 참조의 프로그래밍 인터페이스

여기에 문서화된 모든 ara::* 네임스페이스는 ARA 인터페이스(적응형 애플리케이션을 위한 AUTOSAR 런타임)를 구성합니다. 플랫폼의 각 기능 클러스터는 ara::core의 기본 유형에서 ara::com의 서비스 통신, ara::exec, ara::per 또는 ara::crypto(EXP PlatformDesign §4.1 “Logical view”, EXP SWArchitecture §9.1 “Building Block View – Overview”)와 같은 플랫폼 서비스에 이르기까지 자체 네임스페이스에서 C++ API를 내보냅니다.

Adaptive Platform의 기능 클러스터와 Adaptive 애플리케이션의 일반적인 상호 작용(노드 클릭 가능) 출처: EXP PlatformDesign §4.1, EXP SWArchitecture §9.1. 부분적 해석: 상호작용의 선택 및 라벨링은 언급된 소스의 장을 요약한다.

중요한 개념

  • Machine & Software Cluster: A Machine는 (아마도 가상화된) 실행 환경이다. 소프트웨어는 설치 가능한 Software Cluster로 패키지되어 있으며 ara::ucm(EXP SWArchitecture §13.4 “Software Cluster”, §13.5 “Machine”)를 통해 업데이트된다.
  • 기능 그룹 & 상태: 프로세스가 기능 그룹에 할당됩니다. ara::sm는 Execution Management에 기능 그룹 상태(EXP SWArchitecture §13.2 “Function Group”, EXP PlatformDesign 7장 “State Management”)를 통해 프로세스를 시작/중지하도록 지시합니다.
  • Manifests: 실행, 서비스 인스턴스 및 시스템 매니페스트는 배포, 시작 동작 및 서비스 바인딩을 선언적으로 구성한다(EXP PlatformDesign §4.4 “Manifest”, EXP SWArchitecture §13.6 “Manifest”).
  • 예외 없는 오류 처리: 플랫폼 전체에서 오류는 ara::core::Result/ErrorCode(EXP PlatformDesign §18.1 “Error Handling”, EXP SWArchitecture §13.12 “Error Handling”)로 반환된다.
  • 횡단면으로서의 안전 및 보안: E2E 보호, 상태 모니터링(ara::phm), 암호화 스택, ID 및 액세스 관리, 침입 감지(ara::idsm) 및 방화벽(ara::fw)은 플랫폼과 통신을 보호한다. (EXP PlatformDesign 17장 “Safety”, EXP SWArchitecture §13.13 “Trusted Platform”).

API 애플리케이션 가시성

여기에 문서화된 모든 사양 요소가 공용 ARA API의 일부는 아닙니다. SWS 문서는 다른 Functional Clustern에 독점적으로 제공되는 인터페이스가 5장(“Dependencies to other Functional Clusters”, 표 5.1 각각)에 나와 있다. 이 참조를 사용하면 각 요소의 페이지(탐색 줄 오른쪽에 있는 페이지 헤더 및 레이블), 상위 수준 페이지의 요소에 대한 모든 참조 및 다이어그램의 링크된 노드에서 해당 모듈, 네임스페이스 및 클래스 이름의 배경색에서 일관되게 표시된다. 기본적으로 배경은 매우 옅어서 가독성이 좋고 마우스를 올리면 좀 더 강렬해집니다.

  • APPLICATION Blue:는 적응형 애플리케이션에서 직접 사용할 수 있습니다. 예: ara::core, ara::com, ara::log, ara::per, ara::crypto, ara::diag, ara::rds, ara::shwa(응용 프로세스에서 라이브러리로 실행, SWS SHWA 1장), ara::tsync(액티브 및 패시브 시간 기반 사용량, SWS TSync §2.2) 및 ara::idsm(보안 센서로 활용, SWS IdsM §7.2). ara::exec::ExecutionClient도 여기에 속하지만 자체 프로세스 상태 [SWS_EM_01401]만 보고할 수 있습니다.
  • PRIVILEGED Red:는 IAM 또는 매니페스트 매핑을 통해 승인된 전용 애플리케이션에만 해당된다. 승인된 사용자는 탐색 줄에서 괄호 안에 표시된다. 예: ara::ucm의 PackageManagement-Service(“UCM Client” = 예: OTA 클라이언트 또는 진단 애플리케이션, SWS UCM §7.1), SM 제어 애플리케이션 [SWS_SM_00600]용 ara::sm의 StateMachine-Services, 일시 중단 RAM API ara::sm::s2r(SuspendToRamSatelliteMapping, [SWS_SM_00715]를 사용하는 IAM 인증 위성만 해당) 및 ara::fw(AdaptiveFirewallToPortPrototypeMapping, [AP_SWS_Fw_40013]를 사용하는 경우에만 상태 변경).
  • INTERNAL 진한 회색: 순전히 클러스터 내부 인터페이스이며 확실히 애플리케이션용은 아닙니다. 사용되는 기능 클러스터는 탐색 줄의 괄호 안에 있다. 예: FunctionGroup/FunctionGroupState(상태 관리에만 해당, SWS EM Tab. 5.1), 전체 모듈 ara::nm(제거된 애플리케이션을 위한 서비스 인터페이스, 상태 관리를 통해 실행되는 네트워크 요청, SWS NM §4.1 및 Tab. 5.1)를 포함하는 ara::exec::StateClient, ara::phm::RecoveryAction(SWS PHM Tab. 5.1) 및 표준 부록 “Platform Extension Interfaces”의 모든 apext::* 인터페이스(기본 소프트웨어에 대한 플랫폼 통합: Watchdog, Power, UDS 전송, Freshness Value Manager, Trace/ARTI).
