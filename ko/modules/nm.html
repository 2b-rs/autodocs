역할: State Management와 버스 간의 네트워크 요청

어댑티브 Network Management(NM)는 하위 물리 네트워크 및 부분 네트워크가 정상 작동과 Bus-Sleep 간에 언제 전환되는지를 조정한다. 이는 사용되는 통신 스택과 무관하게 동작해야 한다 SWS NM 5쪽. 기능적으로는 PRS NetworkManagementProtocol을 기반으로 한다. NM 메시지를 송수신하기 위해 통신 스택을 사용한다 SWS NM 9쪽. 제약 사항에 따르면 현재는 UdpNM만 지원된다 SWS NM 8쪽.

상위로는 시스템 경계가 엄격하게 설정되어 있다. 애플리케이션은 NM을 직접 호출하지 않는다. 애플리케이션은 State Management에 기능을 요청하고, State Management는 구성에 따라 논리 네트워크를 요청하거나 해제한다 SWS NM 14쪽 SWS NM 29쪽. 유일한 인터페이스는 헤더 ara/nm/network_handle.h에 있는 클래스 ara::nm::NetworkHandle이다 [SWS_ANM_01000]. 이는 명시적으로 State Management만을 위해 제공된다 EXP SWArch 77쪽. 따라서 State Management는 이를 필요한 인터페이스 목록에 포함하고 있다 EXP SWArch 56쪽. 두 클러스터는 모두 데몬 기반이다: State Management는 이 인터페이스를 사용하고, NM은 이를 구현한다 SWS NM 13쪽.

SWS(8/9장)의 이전 텍스트 내용은 이와 상충된다. 해당 내용에서는 NM에 API가 포함되어 있지 않으며 모든 것을 서비스를 통해 제공한다고 명시되어 있다 SWS NM 26쪽. 그러나 R25-11에서 규범적인 것은 해당 메서드 [SWS_ANM_01000]를 갖춘 C++ 클래스 NetworkHandle이다 [SWS_ANM_01009]. 플랫폼 설계 개요에서는 ara::com 인터페이스에서 직접 메서드 호출 방식으로의 이러한 전환을 설명한다 EXP PlatformDesign 60쪽.

컨텍스트 다이어그램: 애플리케이션은 NetworkHandle을(를) 통해 NM을 제어하는 State Management를 통해서만 간접적으로 NM에 접근한다. NM은 통신 스택을 통해 NM 메시지를 교환한다. 출처: SWS NM 13쪽, SWS NM 14쪽, SWS NM 9쪽, [SWS_ANM_01000]

논리 네트워크에서 채널로: 핸들, Partial Networks 및 NM 인스턴스

하나의 논리 네트워크는 정확히 하나의 부분 네트워크 또는 물리 네트워크에 매핑된다. 반면 하나의 부분 네트워크는 여러 물리 네트워크에 할당될 수 있다. NM이 제공하는 각 포트는 정확히 하나의 논리 네트워크를 제어하며, 포트는 매니페스트를 통해 논리 네트워크에 할당된다. Partial Networking을 사용하는 경우 부분 네트워크를 물리 네트워크에 할당하는 작업도 추가로 구성해야 한다. Partial Networking이 없으면 포트는 물리 네트워크에 직접 매핑된다 SWS NM 14쪽.

SWS 개요는 계층 구조를 보여준다. Network Handle 인스턴스는 Partial Network 상태 머신에 작용한다. 이는 각 네트워크에서 동작하는 하나의 Network State Machine을 각각 갖춘 채널별 NM 인스턴스를 제어한다 SWS NM 18쪽 EXP PlatformDesign 60쪽. Partial Network 상태 머신은 구현에 따라 다르다. 그러나 그 동작은 PRS의 Partial Networking 요구사항을 준수해야 한다 SWS NM 24쪽.

협동 다이어그램: 핸들은 Partial Network 상태 머신을 통해 채널별 NM 인스턴스에 작용한다. 이때 하나의 부분 네트워크(PN2)가 두 개의 네트워크에 영향을 미칠 수 있다. 출처: SWS NM 18쪽, SWS NM 14쪽, SWS NM 15쪽

해석: 유효 상태 kFullCom은(는) 할당된 채널의 Network Mode에 해당할 것으로 보인다. 즉, Network Mode는 네트워크가 요청되었거나 활성 상태임을 의미하기 때문이다 SWS NM 15쪽.

채널 동작: 분산형 NM 알고리즘 및 동작 모드

이 알고리즘은 분산형으로 직접 작동합니다. 각 노드는 수신 및 송신된 NM 패킷만을 기반으로 독립적으로 결정합니다. 모든 노드에 멀티캐스트로 전송되는 주기적인 NM 패킷이 클러스터의 웨이크 상태를 유지합니다. 수면 상태로 전환될 수 있는 노드는 더 이상 전송하지 않습니다. 그러나 다른 노드의 패킷이 계속 도착하는 한 수면 상태로의 전환을 연기합니다 SWS NM 13쪽. 각 노드는 이미 실행 중인 클러스터에 통합될 수 있습니다 SWS NM 11쪽.

물리 채널마다 NM은 Network Mode, Prepare Bus-Sleep Mode 및 Bus-Sleep Mode 모드를 구현합니다. 애플리케이션에는 이러한 모드가 표시되지 않습니다 SWS NM 15쪽. Network Mode는 Repeat Message, Normal Operation 및 Ready Sleep으로 세분화됩니다 SWS NM 16쪽. 세부 동작 순서는 다음과 같습니다:

  • Network Mode에 진입하면 Repeat Message로 들어가고 NM-Timeout-Timer가 NmTimeoutTime(으)로 시작됩니다. 성공적으로 수신되거나 송신된 각 NM 패킷은 타이머를 다시 시작합니다 SWS NM 17쪽.
  • Normal Operation에서 네트워크가 해제되면 NM은 Ready Sleep으로 전환되고 송신이 중지됩니다. 수신된 Repeat Message Request Bit는 다시 Repeat Message로 복귀하게 합니다 SWS NM 18쪽.
  • Prepare Bus-Sleep은 NmWaitBusSleepTime 동안 지속되며 Bus-Sleep으로 끝납니다. 그 전에 NM 패킷이 도착하면 NM은 즉시 Network Mode로 돌아갑니다 SWS NM 19쪽.

송신 시 Repeat Message에 진입한 후 첫 번째 패킷은 NmMsgCycleOffset만큼 지연됩니다. 그 후 NM은 NmMsgCycleTime 주기로 송신합니다 SWS NM 22쪽. 송신되는 메시지에서 Repeat Message Request Bit, Active Wakeup Bit 및 NM Coordinator Sleep Ready Bit는 항상 0입니다 SWS NM 20쪽. 노드 감지, 마스터 코디네이터로서의 역할, CBV를 통한 조정된 셧다운 및 Passive Mode는 지원되지 않습니다 SWS NM 8쪽.

상태 다이어그램: Network Mode의 하위 상태 및 시간 제어된 수면 상태로의 전이를 포함하는 채널별 NM 인스턴스의 동작 모드. 출처: SWS NM 15쪽, SWS NM 16쪽, SWS NM 17쪽, SWS NM 18쪽, SWS NM 19쪽

Partial Networking: 수신 평가 및 집계된 요청 상태

NmPnEnabled은(는) 수신 시 PN 정보 평가를 켜거나 끕니다. Partial Networking이 활성화된 경우의 규칙 SWS NM 24쪽:

  • PNI-Bit가 1인 경우, 수신된 BitVector가 관련 PN 또는 채널의 요청 상태를 변경하는 즉시 NM은 NetworkHandle-Notifier를 호출합니다.
  • PNI-Bit가 0인 경우에도 NM은 페이로드를 처리합니다.
  • Getter는 PN들의 집계된 요청 상태를 반환하며 가장 최근에 수신된 정보를 반영하지 않습니다. 아마도 이는 GetNetworkRequestedState을(를) 의미하는 것으로 추정됩니다 [SWS_ANM_01008].
  • NmPnResetTime은(는) NmMsgCycleTime보다 커야 합니다.

PN 정보 영역의 각 비트는 부분 네트워크를 나타냅니다. 선택적으로 NM은 제어기(ECU)에 대해 구성된 PNC의 1로 설정된 비트를 포함하지 않는 메시지를 필터링하여 걸러냅니다 SWS NM 25쪽. 동일한 위치에서 Adaptive Application의 메서드 RequestNetwork/ReleaseNetwork을(를) 언급합니다. R25-11에서는 State Management에 의해 호출되는 SetNetworkRequestedState이(가) 이를 대체합니다 [SWS_ANM_01009].

수신된 페이로드가 변경되면 NM은 알림을 호출합니다 SWS NM 23쪽. 페이로드와 PNI는 겹치지 않습니다 SWS NM 21쪽. 페이로드에 대한 애플리케이션 액세스는 더 이상 제공되지 않습니다. 향후 State Management를 통해 수행되어야 하는지는 미정입니다 SWS NM 8쪽.

액티비티 다이어그램: 스위치 NmPnEnabled부터 알림에 이르기까지 Partial Networking이 적용된 NM 메시지 수신 시의 결정 체인. 출처: SWS NM 24쪽, SWS NM 25쪽, SWS NM 23쪽
