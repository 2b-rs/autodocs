분류 및 목적

안전한 하드웨어 가속은 적응형 응용 프로그램이 사용 가능한 하드웨어에서 병렬 작업을 실행할 수 있도록 하는 메커니즘을 제공한다. 아키텍처는 대기열, 장치 및 버퍼의 조합을 허용한다. 다른 Functional Clusters도 API SWS SHWA §7.1 “The Architecture of Safe Hardware Acceleration”를 사용할 수 있다.

데이터, 액세스 및 저장

버퍼는 메모리 할당을 관리하는 반면, Accessor는 형식화된 읽기/쓰기 액세스를 표현한다. 액세스 모드 및 TaskHandler에 ​​대한 바인딩은 런타임 시스템에 데이터 이동 및 동기화 SWS SHWA §7.3 “Data Access Specifics” SWS SHWA §7.5 “Memory Allocation Specifics”에 대한 정보를 제공한다. 함께 제공되는 EXP 문서는 데이터 저장 및 데이터 관리 EXP Safe Hardware Acceleration API §4.3.1로 버퍼, 접근자, 범위 및 ID를 그룹화한다.

장치 선택, 실행 및 동기화

장치는 컴퓨팅 장치를 나타냅니다. 선택기 클래스는 등급을 통해 CPU, GPU 또는 가속기 장치를 선택합니다. 대기열은 작업을 전달하고 이벤트는 순서가 잘못된 실행의 경우 종속성 또는 대기 작업을 지원합니다 SWS SHWA §7.4 “Device Specifics” SWS SHWA §7.6 “Task Queuing And Ordering Specifics”.

해석: 강력한 애플리케이션 경로는 일반적으로 장치 선택, 대기열/오류 처리기 생성, 버퍼/접속자 생성, 작업 제출 및 적절한 이벤트 또는 시간 초과 기반 동기화로 구성됩니다. 이 순서는 설명된 개별 개념을 요약합니다.

보안, 오류 및 동시성

API는 예외가 없습니다. 오류 가능 작업 ara::core::Result을 사용하는 반면, 팩토리 메서드는 객체 생성 중에 오류 전송을 허용합니다. Device의 실행 오류에 대해 비동기 ErrorHandler가 제공됩니다. DeviceMonitor는 장치 상태 SWS SHWA §7.2 “General Features” SWS SHWA §7.2.5.3–7.2.5.4 모니터링을 지원합니다. SHWA 객체는 프로세스로 제한됩니다. 사양에 따르면 동일한 버퍼에 동시 쓰기 Accessor::Set 액세스하면 kResourceBusy SWS SHWA §7.2.2 “Parallel Access”가 발생합니다.

요구사항 컨텍스트

기본 요구 사항 문서에서는 안전하고 효율적인 병렬 계산, 오류 감지/처리 및 가속기 상태 모니터링(RS Safe Hardware Acceleration §4.1)을 요구합니다. 또한 Device 모니터링, 시간 제어 가능한 차단 및 프로세스 로컬 SHWA 객체 RS_SHWA_00004 RS_SHWA_00005 RS_SHWA_00011가 필요합니다.
