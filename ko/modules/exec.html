플랫폼 출시부터 프로세스 제어까지

Execution Management는 모델 프로세스 시작 및 종료는 물론 필요한 OS 구성 초기화도 담당한다. 모델 프로세스는 런타임 시 OS 프로세스이다. 시작 매개변수, 리소스 및 스케줄링 정보는 시스템 및 실행 Manifests SWS Execution Management §7 “Functional specification” SWS Operating System Interface §7.1.2 “Process Handling”에서 가져옵니다.

프로세스 수명주기 및 결정적 종속성

EM에는 Idle, Starting, Running, Terminating 및 Terminated가 포함된 자체 프로세스 상태가 있다. 보고 프로세스에서 Running는 kRunning 이후에만 발생한다. 실행 종속성은 시작 및 종료 순서만 정렬하고 SWS EM §7.3.2 “Process States” SWS EM §7.3.4 “Startup and Termination”에서 어떤 프로세스를 시작해야 하는지 결정하지 않는다.

상태 다이어그램: EM은 프로세스에서 보고한 실행 상태 SWS EM §7.3.1 “Execution State” SWS EM §7.3.2 “Process States”와 별도로 프로세스 수명주기를 추적합니다. 해석: 라벨은 여러 요구 사항에 설명된 트리거를 요약합니다.

시퀀스 다이어그램: kRunning 메시지는 EM에 대한 보고 프로세스와 살아있는 감독 시작을 표시한다([SWS_EM_01004] [SWS_EM_01210] [SWS_PHM_01331]).

State Management이 결정하고, Execution Management이 실행됩니다.

상태 관리는 StateClient 위의 기계 및 기능 그룹 상태를 요청한다. EM은 더 이상 필요하지 않은 프로세스를 종료하고 구성된 순서대로 대상 세트를 시작하고 연관된 future를 닫다. MachineFG의 초기 시작 전환만 EM 자체 SWS EM §7.4 “State Management” SWS EM §7.4.5 “State Transition”에 의해 시작된다.

시퀀스 다이어그램: State Management은 상태 결정을 공식화합니다. Execution Management는 프로세스 수준에서 이를 SWS EM §7.4.4 “State Interaction” SWS EM §7.4.5 “State Transition”로 변환합니다.

운영 체제 및 PHM에 대한 경계

EM은 스케줄링 및 리소스 관리를 위해 운영 체제를 구성하지만 런타임 스케줄링 자체를 수행하지는 않습니다. 감독되는 프로세스의 경우 EM PHM은 kRunning, 스케줄링 시작 및 프로세스 종료에 대해 알려줍니다. PHM은 이러한 이벤트를 사용하여 감독을 시작하거나 중지합니다(SWS Operating System Interface §7.1.3 “Scheduling Policies” [SWS_EM_01210] [SWS_EM_01211] [SWS_EM_01212]).

오류가 발생한 경우의 동작

ExecutionClient::ReportExecutionState()는 Result<void>를 반환합니다. 확인할 수 없는 신고는 ExecErrc::kNoCommunication로 반환됩니다. 잘못된 상태 보고서의 경우 ExecErrc::kInvalidTransition로 표시됩니다. kRunning 보고서의 경우 Execution Management에는 특히 프로세스 상태 Starting가 필요합니다. 비보고 프로세스에 의한 전화는 ReportExecutionStateViolation입니다. [SWS_EM_02003] [SWS_EM_02243] [SWS_EM_01403]

자체 종료 프로세스는 EXIT_SUCCESS로 자체 예약을 시작하거나 Execution Management에서 SIGTERM를 기다릴 수 있다. 이는 예기치 않은 종료와 구별되어야 한다. 예를 들어 자체 종료로 구성되지 않은 프로세스가 사전 요청 없이 종료되거나 kRunning를 보고하기 전에 종료되는 경우이다. 비정상적으로 종료될 수도 있다. StateClient::SetState()가 요청한 전환 외부에서 Execution Management는 연결된 Function Group를 정의되지 않은 Function Group 상태로 설정하고 undefinedStateCallback를 사용하여 ExecutionErrorEvent를 호출한다. 이벤트에는 프로세스 오류와 기능 그룹 컨텍스트가 포함된다. 후속 GetExecutionError()는 동일한 정보를 제공한다. SWS Execution Management §2 “Acronyms and Abbreviations” [SWS_EM_01309] [SWS_EM_02542] [SWS_EM_02545] [SWS_EM_02546]

시퀀스는 요청된 기능 그룹 전환 외부의 예기치 않은 종료에 대해 정의된 보고 경로를 보여준다. ExecutionErrorEvent로 오류가 발생한 후 업데이트의 영향을 받지 않는 StateMachine은 ErrorRecoveryTable에서 구성된 후속 상태를 결정한다. 출처: [SWS_EM_01309] [SWS_EM_02542] [SWS_SM_00601].

기능 그룹 전환 중에 프로세스 시작이 실패하면 실행 관리는 전환을 종료하고 현재 상태를 정의되지 않음으로 설정하고 SetState() 미래 ExecErrc::kOperationFailed를 보고한다. 구성된 ExecutionError는 GetExecutionError()를 통해 사용할 수 있다. 요청된 상태에 대해 구성된 프로세스가 비정상적이거나 예기치 않게 종료되는 경우 해당 오류는 ExecErrc::kUnexpectedTermination이다. SetState() 미래에는 kOperationCanceled, kNoCommunication 또는 kInvalidTransition가 포함될 수도 있다. 후자는 금지되거나 유효하지 않은 대상 상태를 다룹니다. [SWS_EM_02259] [SWS_EM_02315] [SWS_EM_02278]
