서비스 인터페이스 StateMachineService

ara::com 서비스로 모델링된 인터페이스. 메서드/필드는 생성된 프록시/Skeleton(IN/OUT 매개변수 방향)를 통해 호출된다.

서비스 인터페이스의 역할 및 시스템 컨텍스트

서비스 인터페이스 StateMachineService은 AUTOSAR Adaptive Platform의 Functional Cluster State Management (SM)에 대한 핵심 제어 인터페이스를 형성한다([SWS_SM_91021], [SWS_SM_91022]). 여기서 State Management 클러스터는 프로바이더로 동작하며, 구성된 각 상태 머신(StateMachine) 인스턴스를 위해 별도의 ara::com 기반 서비스를 제공한다([SWS_SM_00600]). 컨슈머로는 제어 애플리케이션인 SMControlApplication가 동작하며, 해당 프록시를 통해 각 상태 머신과 상호작용하여 상태 전환을 능동적으로 요청한다(AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 “Interfaces for a SMControlApplication”, AUTOSAR_AP_SWS_StateManagement §9.2.2 “StateMachine service”).

아키텍처적으로 State Management는 이러한 능동적 제어 상호작용과 수동적 알림을 엄격하게 구분한다: StateMachineService이 상태 제어를 위해 SMControlApplication 전용으로 사용되는 반면(AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”), 별도로 구성 가능한 서비스 인터페이스 StateMachineNotification은 발생한 상태 변경에 대해 일반 Adaptive Applications에 알린다([SWS_SM_00665]).

메서드, 이벤트 및 필드

서비스 인터페이스 StateMachineService은 필드(Fields)나 이벤트(Events)를 정의하지 않으며, 피드백을 수반하는 동기식 메서드 상호작용에 전적으로 집중한다([SWS_SM_91022], [SWS_SM_91107]). 주요 오퍼레이션으로는 참조된 StateMachine에서 상태 전환을 시작하기 위해 SMControlApplication에 의해 호출되어야 하는 메서드 RequestTransition이 명시되어 있다([SWS_SM_91107]).

이 메서드는 Fire-and-Forget 방식으로 모델링되지 않았으며(Fire & Forget false), 단일 입력 매개변수를 처리한다([SWS_SM_91107]):

  • TransitionRequest (방향: IN, 타입: TransitionRequestType): 상태 머신용으로 구성된 TransitionRequestTable에 트리거로 등록된 구체적인 요청 값을 포함한다([SWS_SM_91107], AUTOSAR_AP_SWS_StateManagement §7.8 “TransitionRequestTable”).

해석: 출력 매개변수(OUT)가 선언되어 있지 않으므로, ara::com에서 성공적인 메서드 호출은 Future 객체를 통해 빈 결과(void)를 제공할 것으로 보이며, 이를 통해 SMControlApplication에 전이의 오류 없는 완료가 확인될 것으로 보인다([SWS_SM_91107]).

시퀀스 다이어그램: SMControlApplication과 State Management 간의 RequestTransition 메서드 호출 흐름. 출처: [SWS_SM_91107], [SWS_SM_00600].

수명 주기, 제공 및 실행 조건

StateMachineService의 제공(Offer)은 각 StateMachine의 내부 라이프사이클에 직접적으로 연계된다: 구성된 각 서비스 인스턴스는 StartStateMachine 명령을 포함한 액션 요소 ActionListItem가 성공적으로 실행되는 즉시 ara::com을 통해 제공되어야 한다([SWS_SM_00618]). 이를 통해 SMControlApplication는 상태 머신이 병렬로 초기 ActionList을 여전히 처리하고 있는 중이더라도, 상태 머신이 성공적으로 생성된 직후 전환을 요청할 수 있다(AUTOSAR_AP_SWS_StateManagement §7.8 “StateMachine service interfaces - Offer”).

StateMachine이 종료되고 서비스를 더 이상 사용할 수 없어야 하는 즉시, 서비스 제공 역시 중단된다(StopOffer)([SWS_SM_00619]). 정규 런타임 동안 전환의 실행은 상위 플랫폼 상태에도 종속된다: 예를 들어 Update and Configuration Management를 통한 업데이트 세션이 진행 중인 경우, 전환 요청은 차단된다(AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”, [SWS_SM_91107]).

오류 처리 및 Application Errors

전환 요청을 수행할 수 없는 경우, 메서드 RequestTransition은 전용 Application Error를 반환한다([SWS_SM_91107]). 이를 위해 인터페이스에는 6개의 개별 오류 코드가 명시되어 있다([SWS_SM_91107]):

Application Error 의미 및 원인
kInvalidValue 전달된 값 TransitionRequest이 TransitionRequestTable의 어떤 전환에도 매핑되어 있지 않다([SWS_SM_91107]).
kTransitionNotAllowed 요청된 상태 전이는 StateMachine의 현재 상태를 기준으로 허용되지 않는다([SWS_SM_91107]).
kRecoveryTransitionOngoing 현재 오류 복구 전환(Recovery)이 활성화되어 있으므로 요청이 실행되지 않는다([SWS_SM_91107]).
kTransitionFailed 요청된 대상 상태로 전이하는 동안 오류가 발생했다([SWS_SM_91107]).
kOperationCanceled 해당 요청은 더 새로운 후속 요청에 의해 대체되어 결과적으로 취소되었다([SWS_SM_91107]).
kUpdateInProgress 현재 업데이트 세션이 실행 중이므로 요청된 오퍼레이션이 허용되지 않는다([SWS_SM_91107]).

호출하는 SMControlApplication은 이러한 오류 코드를 별도로 처리해야 하며, 예를 들어 kOperationCanceled의 경우 후속 요청의 결과를 기다리거나, kRecoveryTransitionOngoing 또는 kUpdateInProgress의 경우 나중에 호출을 재시도해야 한다([SWS_SM_91107]).

본 가이드는 State Management (sm) 모듈에 대한 AUTOSAR Adaptive Platform R25-11 사양을 기반으로 한다.

사용법 및 호출 컨텍스트

서비스 메서드 RequestTransition은(는) 참조된 StateMachine의 상태 전환을 요청하기 위해 서비스 인터페이스 StateMachineService을(를) 통해 SMControlApplication에 의해 호출됩니다([SWS_SM_91107], SWS StateManagement §7.7 “StateMachine”). 호출은 Fire & Forget으로 수행되지 않습니다([SWS_SM_91107]). 유형이 TransitionRequestType인 매개변수 TransitionRequest을(를) 통해 원하는 전환 값이 전달됩니다. State Management는 TransitionRequestTable을(를) 기반으로 다음 상태를 확인하고, SetState()을(를) 통해 Execution Management에 연관된 Function Group States을(를) 요청합니다(EXP SWArchitecture §11.4 “Scenario: Change System State”, [SWS_SM_00607]).

오류 처리

요청이 실패하거나 실행될 수 없는 경우, 이 메서드는 특정 오류를 반환합니다:

  • kInvalidValue: 전달된 값이 TransitionRequestTable에 구성되어 있지 않습니다([SWS_SM_00604]).
  • kTransitionNotAllowed: 요청된 전환이 StateMachine의 현재 상태를 기준으로 표에 따라 허용되지 않습니다([SWS_SM_00603]).
  • kRecoveryTransitionOngoing: 오류 복구가 이미 진행 중이므로 요청이 처리되지 않습니다([SWS_SM_00605]).
  • kTransitionFailed: ActionListItems을(를) 처리하는 동안 오류가 발생했습니다([SWS_SM_00650]).
  • kOperationCanceled: StateMachine에 대한 더 새로운 요청이 수락되어 해당 요청이 취소되었습니다([SWS_SM_00606]).
  • kUpdateInProgress: 현재 업데이트 세션이 활성 상태이므로 작업이 허용되지 않습니다([SWS_SM_91107]).

동시성 및 제약사항

동일한 StateMachine에 대해 이전 RequestTransition 호출이 아직 보류 중인 동안 새로운 상태 변경이 수락되면, 해당 호출은 kOperationCanceled(으)로 종료됩니다([SWS_SM_00606]). 또한 Sleep ActionListItem을(를) 통한 지연 실행은 들어오는 트리거를 차단하지 않으며, RequestTransition 호출은 이러한 대기 단계 중에도 상태 변경을 유발할 수 있습니다(SWS StateManagement §7.7.9 “ActionListItem Sleep”).

이 사용 지침은 AUTOSAR_AP_SWS_StateManagement 및 AUTOSAR_AP_EXP_SWArchitecture의 사양을 바탕으로 합니다.

    <li><code>kTransitionFailed</code>: <code>ActionListItems</code>을(를) 처리하는 동안 오류가 발생했습니다(<a class="spec-record-ref" data-req="SWS_SM_00650" href="../spec/record.html?id=SWS_SM_00650">[SWS_SM_00650]</a>).</li>

    <li><code>kUpdateInProgress</code>: 현재 업데이트 세션이 활성 상태이므로 작업이 허용되지 않습니다(<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</li>
  </ul>

  <h4>동시성 및 제약사항</h4>
  <p>
    동일한 <code>StateMachine</code>에 대해 이전 <code>RequestTransition</code> 호출이 아직 보류 중인 동안 새로운 상태 변경이 수락되면, 해당 호출은 <code>kOperationCanceled</code>(으)로 종료됩니다(<a class="spec-record-ref" data-req="SWS_SM_00606" href="../spec/record.html?id=SWS_SM_00606">[SWS_SM_00606]</a>). 또한 <code>Sleep ActionListItem</code>을(를) 통한 지연 실행은 들어오는 트리거를 차단하지 않으며, <code>RequestTransition</code> 호출은 이러한 대기 단계 중에도 상태 변경을 유발할 수 있습니다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=64">SWS StateManagement §7.7.9 “ActionListItem Sleep”</a>).
  </p>

  <p class="ai-note">
    이 사용 지침은 AUTOSAR_AP_SWS_StateManagement 및 AUTOSAR_AP_EXP_SWArchitecture의 사양을 바탕으로 합니다.
  </p>

<h4>서비스 인터페이스의 역할 및 시스템 컨텍스트</h4>
<p>서비스 인터페이스 <code>StateMachineService</code>은 AUTOSAR Adaptive Platform의 Functional Cluster State Management (SM)에 대한 핵심 제어 인터페이스를 형성한다(<a class="spec-record-ref" data-req="SWS_SM_91021" href="../spec/record.html?id=SWS_SM_91021">[SWS_SM_91021]</a>, <a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>). 여기서 State Management 클러스터는 프로바이더로 동작하며, 구성된 각 상태 머신(<code>StateMachine</code>) 인스턴스를 위해 별도의 ara::com 기반 서비스를 제공한다(<a class="spec-record-ref" data-req="SWS_SM_00600" href="../spec/record.html?id=SWS_SM_00600">[SWS_SM_00600]</a>). 컨슈머로는 제어 애플리케이션인 <code>SMControlApplication</code>가 동작하며, 해당 프록시를 통해 각 상태 머신과 상호작용하여 상태 전환을 능동적으로 요청한다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.1 “Interfaces for a SMControlApplication”</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=141">AUTOSAR_AP_SWS_StateManagement §9.2.2 “StateMachine service”</a>).</p>
<p>아키텍처적으로 State Management는 이러한 능동적 제어 상호작용과 수동적 알림을 엄격하게 구분한다: <code>StateMachineService</code>이 상태 제어를 위해 <code>SMControlApplication</code> 전용으로 사용되는 반면(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”</a>), 별도로 구성 가능한 서비스 인터페이스 <code>StateMachineNotification</code>은 발생한 상태 변경에 대해 일반 Adaptive Applications에 알린다(<a class="spec-record-ref" data-req="SWS_SM_00665" href="../spec/record.html?id=SWS_SM_00665">[SWS_SM_00665]</a>).</p>

<h4>메서드, 이벤트 및 필드</h4>
<p>서비스 인터페이스 <code>StateMachineService</code>은 필드(Fields)나 이벤트(Events)를 정의하지 않으며, 피드백을 수반하는 동기식 메서드 상호작용에 전적으로 집중한다(<a class="spec-record-ref" data-req="SWS_SM_91022" href="../spec/record.html?id=SWS_SM_91022">[SWS_SM_91022]</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>). 주요 오퍼레이션으로는 참조된 <code>StateMachine</code>에서 상태 전환을 시작하기 위해 <code>SMControlApplication</code>에 의해 호출되어야 하는 메서드 <code>RequestTransition</code>이 명시되어 있다(<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>
<p>이 메서드는 Fire-and-Forget 방식으로 모델링되지 않았으며(<code>Fire &amp; Forget false</code>), 단일 입력 매개변수를 처리한다(<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>):</p>
<ul>
<li><code>TransitionRequest</code> (방향: <code>IN</code>, 타입: <code>TransitionRequestType</code>): 상태 머신용으로 구성된 <code>TransitionRequestTable</code>에 트리거로 등록된 구체적인 요청 값을 포함한다(<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=44">AUTOSAR_AP_SWS_StateManagement §7.8 “TransitionRequestTable”</a>).</li>
</ul>
<p>해석: 출력 매개변수(OUT)가 선언되어 있지 않으므로, ara::com에서 성공적인 메서드 호출은 Future 객체를 통해 빈 결과(<code>void</code>)를 제공할 것으로 보이며, 이를 통해 <code>SMControlApplication</code>에 전이의 오류 없는 완료가 확인될 것으로 보인다(<a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<h4>수명 주기, 제공 및 실행 조건</h4>
<p><code>StateMachineService</code>의 제공(Offer)은 각 <code>StateMachine</code>의 내부 라이프사이클에 직접적으로 연계된다: 구성된 각 서비스 인스턴스는 <code>StartStateMachine</code> 명령을 포함한 액션 요소 <code>ActionListItem</code>가 성공적으로 실행되는 즉시 ara::com을 통해 제공되어야 한다(<a class="spec-record-ref" data-req="SWS_SM_00618" href="../spec/record.html?id=SWS_SM_00618">[SWS_SM_00618]</a>). 이를 통해 <code>SMControlApplication</code>는 상태 머신이 병렬로 초기 <code>ActionList</code>을 여전히 처리하고 있는 중이더라도, 상태 머신이 성공적으로 생성된 직후 전환을 요청할 수 있다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=45">AUTOSAR_AP_SWS_StateManagement §7.8 “StateMachine service interfaces - Offer”</a>).</p>
<p><code>StateMachine</code>이 종료되고 서비스를 더 이상 사용할 수 없어야 하는 즉시, 서비스 제공 역시 중단된다(StopOffer)(<a class="spec-record-ref" data-req="SWS_SM_00619" href="../spec/record.html?id=SWS_SM_00619">[SWS_SM_00619]</a>). 정규 런타임 동안 전환의 실행은 상위 플랫폼 상태에도 종속된다: 예를 들어 Update and Configuration Management를 통한 업데이트 세션이 진행 중인 경우, 전환 요청은 차단된다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=51">AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1 “Defined interfaces”</a>, <a class="spec-record-ref" data-req="SWS_SM_91107" href="../spec/record.html?id=SWS_SM_91107">[SWS_SM_91107]</a>).</p>

<th>의미 및 원인</th>

</tr>

</tr>
