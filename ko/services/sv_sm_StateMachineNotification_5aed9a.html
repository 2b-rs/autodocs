Adaptive Applications에 상태 머신의 현재 상태 및 진행 중인 전이에 대해 알립니다.

서비스 인터페이스 StateMachineNotification은 읽기 가능하고 구독 가능한 필드 CurrentState을 통해 Adaptive Applications에 상태 머신의 상태를 제공합니다([SWS_SM_91028], [SWS_SM_91109]). 상태 전환 시 필드는 모든 작업이 실행될 때까지 중간 값 "inTransition"를 알립니다([SWS_SM_00616]). 인터페이스는 상태 머신이 시작된 후 제공되며 상태 머신이 종료되면 다시 회수됩니다([SWS_SM_00618], [SWS_SM_00619]).

서비스 인터페이스의 역할 및 시스템 컨텍스트

서비스 인터페이스 StateMachineNotification은 AUTOSAR Adaptive Platform의 State Management(SM) 모듈에서 제공됩니다([SWS_SM_91028]). 제어 애플리케이션은 별도의 인터페이스를 통해 새로운 상태 전이를 요청하는 반면, StateMachineNotification은 주로 애플리케이션 레벨의 일반 Adaptive Applications와 상호작용합니다(AUTOSAR_AP_SWS_StateManagement 44쪽). 서비스는 제공자(Skeleton) 역할을 하며, 소비 애플리케이션은 ara::com를 통해 소비자(Proxy)로 연결됩니다. 특정 상태 머신에 대해 구성된 경우 State Management는 이 인터페이스의 자체 인스턴스를 인스턴스화합니다([SWS_SM_00665]). 특정 상태 머신이 순수하게 내부적으로 작동하여 애플리케이션과 관련이 없는 프로젝트에서는 구성 및 제공을 생략할 수 있습니다(AUTOSAR_AP_SWS_StateManagement 45쪽).

메서드, 이벤트 및 필드

이 인터페이스는 기존 메서드나 순수 이벤트를 정의하지 않고 모니터링되는 상태 머신의 상태를 중앙 필드([SWS_SM_91109])에 캡슐화합니다. 필드 CurrentState은 데이터 타입 StateMachineStateNameType를 가지며 순수 읽기 전용으로 설계되었습니다. 즉, Getter(HasGetter: true)와 Notifier(HasNotifier: true)를 갖추고 있지만 Setter(HasSetter: false)는 없습니다([SWS_SM_91109]). 따라서 Adaptive Applications는 Getter를 통해 동기식으로 현재 값을 조회할 수 있을 뿐만 아니라, 각 상태 머신의 상태 전환 시 ara::com을 통해 비동기식으로 알림을 받도록 구독할 수도 있습니다([SWS_SM_91109]).

상태 머신의 상태 전이가 시작되는 즉시 필드 CurrentState은 고정 값 "inTransition"을 갖습니다([SWS_SM_00616]). 이 중간 상태는 트리거 소스(예: Execution Management, Platform Health Management 또는 제어 애플리케이션)에 관계없이 설정되며, 오류 알림에 대한 응답으로 추가 전이가 발생하는 경우에도 유지됩니다(AUTOSAR_AP_SWS_StateManagement 67쪽). 모든 관련 작업이 처리된 후에야 값이 상태 머신의 실제 목표 상태로 업데이트됩니다([SWS_SM_00617]).

시퀀스 다이어그램: StateMachineNotification을 통한 상태 전이 시 제공, 조회 및 Notifier 알림. 출처: [SWS_SM_00618], [SWS_SM_91109], [SWS_SM_00616], [SWS_SM_00617]

수명 주기, 제공 및 상태 종속성

상태 머신을 시작하는 것은 다단계 프로세스입니다(AUTOSAR_AP_SWS_StateManagement 59쪽). 상위 제어기의 관점에서 상태 머신은 존재하고 관련 인터페이스가 제공될 때 비로소 시작된 것으로 간주됩니다(AUTOSAR_AP_SWS_StateManagement 59쪽). 구성된 각 StateMachineNotification 인스턴스는 StartStateMachine 명령을 포함하는 ActionListItem이(가) 성공적으로 처리되는 즉시 ara::com을(를) 통해 제공(offered)됩니다([SWS_SM_00618]). 이를 통해 애플리케이션은 서비스에 조기에 바인딩할 수 있습니다.

상태 머신이 종료되거나 축소되면 서비스가 다시 회수됩니다. 즉, 해당 종료 동작이 처리되는 시점부터 인터페이스를 더 이상 사용할 수 없습니다(StopOffer)([SWS_SM_00619]). 상태 머신이 제어기에 의해 제어되는 경우, 메타모델은 또한 각 동작 목록이 제어되는 에이전트의 전체 세트를 참조하도록 요구합니다([SWS_SM_CONSTR_00016]).

오류 처리 및 제약 조건

StateMachineNotification의 경우 인터페이스가 순수하게 관찰용으로 작동하고 수정 메서드를 제공하지 않으므로, 인터페이스 모델에 자체적인 애플리케이션별 Application Errors(예: kOperationRejected)가 정의되어 있지 않습니다([SWS_SM_91109]). 오류 처리는 필드 쿼리 시 ara::com의 통신 메커니즘과 "inTransition" 상태의 평가에 의존합니다. 소비자는 이 중간값을 진행 중인 전환 또는 오류 복구 절차의 표시로 해석할 수 있습니다(AUTOSAR_AP_SWS_StateManagement 67쪽).

이 가이드는 AUTOSAR Adaptive Platform R25-11의 명세서 발췌본만을 기반으로 합니다.
