Update and Configuration Management와 State Management 간의 소프트웨어 클러스터 업데이트 및 리셋을 조정합니다.

UpdateRequest 서비스 인터페이스는 Update and Configuration Management가 소프트웨어 클러스터의 업데이트, 설치 및 제거를 구조화된 방식으로 수행할 수 있도록 State Management에 의해 제공됩니다 [SWS_SM_91016]. 준비 또는 검증 단계를 실행하기 전에 활성 업데이트 세션이 반드시 수립되어야 하며, 그렇지 않으면 SM이 요청을 거부합니다. 준비 및 검사 단계 외에도 이 인터페이스는 머신 리셋뿐만 아니라 롤백을 통한 결함 상태에 대한 보호도 허용합니다 [SWS_SM_91105]. 주요 제약 조건은 항상 단 하나의 업데이트 세션만 병렬로 존재할 수 있다는 점입니다.

서비스 인터페이스의 역할 및 시스템 컨텍스트

서비스 인터페이스 UpdateRequest은 동명의 포트를 통해 State Management(SM) 모듈에 의해 제공됩니다 [SWS_SM_91016] [SWS_SM_91017]. 소프트웨어 클러스터의 업데이트, 설치 및 제거를 제어된 방식으로 처리하기 위해 기능 클러스터인 Update and Configuration Management(UCM)가 중앙 상호작용 파트너이자 서비스 소비자로 동작합니다 SWS StateManagement §9.2.1 “UpdateRequest”. AUTOSAR Adaptive Platform의 시스템 컨텍스트에서 SM은 서버(스켈레톤 제공)로 동작하는 반면, UCM은 함수 그룹을 안전한 작동 상태로 전환하고 상태 변경으로부터 차량 상태를 보호하기 위해 클라이언트(프록시)로 나타납니다.

메서드 및 필드 상세

이 인터페이스는 UCM과 SM 간의 상호작용을 위해 6개의 조정 메서드와 1개의 상태 필드를 정의합니다:

  • RequestUpdateSession(): 업데이트 세션을 시작합니다. 호출은 동기식 피드백과 함께 수행됩니다(Fire & Forget false) [SWS_SM_91102].
  • PrepareUpdate(IN FunctionGroupListType functionGroupList): 영향을 받는 소프트웨어 클러스터 내의 전달된 함수 그룹을 업데이트에 대비하여 준비합니다(Fire & Forget false) [SWS_SM_91103] [SWS_SM_00206].
  • VerifyUpdate(IN FunctionGroupListType functionGroupList): 성공적인 준비 후 업데이트된 함수 그룹을 검증합니다(Fire & Forget false) [SWS_SM_91104].
  • PrepareRollback(IN FunctionGroupListType functionGroupList): 실패한 업데이트의 롤백에 대비하여 함수 그룹을 준비합니다(Fire & Forget false) [SWS_SM_91105].
  • ResetMachine(): 머신 재부팅을 요청합니다. 이 호출은 비동기 Fire-and-Forget(Fire & Forget true)으로 모델링됩니다 [SWS_SM_91100].
  • StopUpdateSession(): SM에 업데이트 완료 및 안정적인 머신 상태로의 복귀를 알립니다(Fire & Forget false) [SWS_SM_91101] [SWS_SM_00205].
  • ResetMachineNotifier: UCM이 실행 중 및 실행 후에 머신 리셋 상태를 모니터링하는 Getter 및 Notifier(Setter 없음)가 포함된 UpdateStatusType 타입의 필드입니다 [SWS_SM_91106] [SWS_SM_00211].

해석: Fire & Forget false을 포함하는 모든 메서드의 경우 표준 퓨처 객체(예: ara::core::Future)를 통해 클라이언트로 동기적 결과 전달이 전송될 것으로 추정되는 반면, ResetMachine는 반환값 없이 즉시 반환되고 상태 추적은 대신 Notifier 필드로 위임됩니다 [SWS_SM_91100] [SWS_SM_91106].

수명 주기, 세션 흐름 및 상태 종속성

소프트웨어 클러스터를 수정하기 위한 모든 상호작용은 엄격하게 순차적인 세션을 필요로 합니다. State Management는 임의의 머신 리셋 후에도 이를 읽어와 계속 진행할 수 있도록 진행 중인 업데이트 세션에 대한 정보를 영속적으로 저장해야 합니다 [SWS_SM_00204] SWS StateManagement §7.x. UCM은 RequestUpdateSession를 통해 주기를 시작합니다. SM이 이 권한을 승인한 후에만 준비 또는 검증 단계를 실행할 수 있습니다 [SWS_SM_91102] [SWS_SM_91103].

진행 중에 ResetMachine을 통해 머신 리셋이 트리거되면, SM은 사전에 모든 머신 데이터를 저장합니다 [SWS_SM_91100]. 기동 시 SM은 ContinueUpdate 상태로 전환되는 반면, UCM은 필드 ResetMachineNotifier을 통해 재시작을 동기화합니다 [SWS_SM_00211] SWS StateManagement §7.x “ResetMachine notification”. 모든 업데이트 단계가 완료되고 전체 시스템이 다시 일관된 상태가 되는 즉시, UCM은 StopUpdateSession으로 세션을 종료합니다 [SWS_SM_91101] [SWS_SM_00205].

시퀀스 다이어그램: UCM과 SM 간의 업데이트 세션 상호작용 흐름. 출처: [SWS_SM_91102], [SWS_SM_91103], [SWS_SM_91104], [SWS_SM_91100], [SWS_SM_91106], [SWS_SM_91101]

오류 처리 및 Application Errors

이 인터페이스는 특정 Application Errors를 통해 흐름을 보호합니다. 활성 업데이트 세션 외부에서 메서드 PrepareUpdate, VerifyUpdate, PrepareRollback 또는 StopUpdateSession이 호출되면 SM은 오류 코드 kOperationRejected로 이를 거부합니다 [SWS_SM_00213]. 마찬가지로 이전에 업데이트 세션이 성공적으로 열리지 않았거나 내부 머신 상태로 인해 리셋이 금지된 경우 ResetMachine도 거부됩니다 [SWS_SM_91100].

이미 세션이 존재하는 상태에서 RequestUpdateSession이 다시 호출되면, 아키텍처상 단 하나의 활성 업데이트 세션만 허용되므로 kNotAllowedMultipleUpdateSessions과 함께 거부됩니다 [SWS_SM_91102]. 준비, 검사 또는 롤백 작업 실행 중에 기능적 문제가 발생하면 메서드 PrepareUpdate, VerifyUpdate 및 PrepareRollback는 오류 kOperationFailed을 반환합니다 [SWS_SM_91103] [SWS_SM_91104] [SWS_SM_91105].

이 가이드는 State Management 모듈에 대한 AUTOSAR Adaptive Platform R25-11 명세만을 기반으로 합니다.

서비스 인터페이스 UpdateRequest의 서비스 메서드 PrepareRollback은(는) 파라미터 functionGroupList(으)로 전달된 소프트웨어 클러스터 함수 그룹에 대한 변경 사항 롤백을 준비하기 위해 Update and Configuration Management에 의해 호출됩니다 [SWS_SM_91105]. 이 호출은 Fire-and-Forget 시맨틱 없이 수행되므로 State Management는 준비 결과를 호출자에게 반환합니다 [SWS_SM_91105].

호출 및 오류 처리에는 고정된 조건이 적용됩니다:

  • 세션 컨텍스트: 호출은 활성 업데이트 세션 내에서만 허용됩니다. 활성 세션 외부에서 수행되는 경우 State Management는 오류 kOperationRejected(으)로 작업을 거부합니다 [SWS_SM_00213].
  • 애플리케이션 오류: 유효하지 않은 내부 상태 시의 kOperationRejected 외에도, 준비가 실패하면 메서드가 kOperationFailed을(를) 반환할 수 있습니다 [SWS_SM_91105].

상태 모델에서 메서드 호출은 관련된 상태 머신에 직접적인 영향을 미칩니다:

  • 전달된 함수 그룹 중 하나를 관리하는 상태 머신은 제어 프로세스에 의해 ImpactedByUpdate(으)로 표시됩니다 [SWS_SM_00654].
  • Agent 타입의 상태 머신이 표시되면 이 상태는 상위 Controller에도 전이되어 적용됩니다 [SWS_SM_00655].
  • ImpactedByUpdate(으)로 표시된 상태 머신의 경우 보고된 실행 오류(ExecutionErrorEvent::executionError)는 복구를 통해 처리되지 않고 무시되며 로그에만 기록됩니다 [SWS_SM_00664].

이 사용 지침은 AUTOSAR 사양을 바탕으로 자동 생성되었습니다.

      사용
      

      
서비스 메서드 PrepareUpdate은(는) 일련의 기능 그룹의 업데이트 준비를 State Management에 요청하기 위해 Update and Configuration Management(UCM)에 의해 호출됩니다 [SWS_SM_00206], [SWS_SM_91103]. 이 메서드는 서비스 인터페이스 UpdateRequest을(를) 통해 제공되며, 소프트웨어 클러스터 내에서 업데이트할 기능 그룹을 지정하는 FunctionGroupListType 타입의 목록 functionGroupList을(를) 입력 매개변수로 받습니다 [SWS_SM_91103]. Fire & Forget이 비활성화되어 있으므로 호출자는 응답을 받는 동기 응답 시맨틱을 갖습니다 [SWS_SM_91103].

      


      순서 조건 및 동시성
      

      
호출은 이전에 RequestUpdateSession을(를) 통해 성공적으로 시작된 업데이트 세션 내에서만 허용됩니다 [SWS_SM_91103]. 호출 중에 제어 프로세스는 전달된 기능 그룹 중 하나를 관리하는 모든 상태 머신을 ImpactedByUpdate(으)로 표시합니다 [SWS_SM_00654]. 이것이 Agent 타입의 상태 머신에 영향을 미치는 경우 상위 컨트롤러 상태 머신 또한 자동으로 ImpactedByUpdate(으)로 표시됩니다 [SWS_SM_00655]. 이 상태가 유지되는 동안 외부 상태 전이가 차단됩니다. 즉, RequestTransition의 모든 호출은 kUpdateInProgress(으)로 응답됩니다 [SWS_SM_00649]. 또한 실행 오류 발생 시 복구 요청(ExecutionErrorEvent::executionError)은 무시되고 로그로만 기록됩니다 [SWS_SM_00664].

      


      오류 처리
      

      
이 메서드에는 두 가지 특정 애플리케이션 오류가 정의되어 있습니다 [SWS_SM_91103]:

      

        

      • kOperationRejected: 활성 업데이트 세션 외부에서 호출이 발생하거나 [SWS_SM_00213] State Management의 내부 상태가 해당 연산을 거부할 때 반환됩니다 [SWS_SM_91103].
        • 

      • kOperationFailed: 요청된 기능 그룹 준비에 실패했음을 나타냅니다 [SWS_SM_91103].
        • 

      

      
해석: 인터페이스에 별도의 비동기 확인 메커니즘이 정의되어 있지 않으므로, 이 메서드는 기능 그룹의 내부 상태 변경이 시작되거나 완료된 후에야 반환될 것으로 추정됩니다.

                          사용법 및 호출 컨텍스트
                          

                          
서비스 메서드 VerifyUpdate은(는) State Management에 업데이트된 함수 그룹의 검증을 요청하기 위해 Update and Configuration Management(UCM)에 의해 서비스 인터페이스 UpdateRequest을(를) 통해 호출됩니다 [SWS_SM_00207]. 파라미터로 functionGroupList(타입 FunctionGroupListType)이 전달되며, 여기에는 각 SoftwareCluster에서 검사할 함수 그룹 목록이 포함되어 있습니다 [SWS_SM_91104]. 이 메서드는 Fire-and-Forget으로 정의되어 있지 않으므로(Fire & Forget: false), 호출자는 동기식 응답 또는 완료 후 제공되는 응답을 기대합니다 [SWS_SM_91104].

                          


                          순서 및 오류 처리
                          

                          
호출은 엄격한 상태 조건을 따릅니다: 활성 업데이트 세션 내에서만 허용되며, State Management가 업데이트를 허용했고 사전에 PrepareUpdate 단계가 성공적으로 완료되었음을 전제로 합니다 [SWS_SM_91104].

                          

                            

                          • kOperationRejected: 호출이 활성 업데이트 세션 외부에서 발생하거나 [SWS_SM_00213], State Management 또는 관련된 상태 머신의 내부 상태가 검증을 거부하는 경우(예를 들어 PrepareUpdate이(가) 성공하지 못한 경우) 반환됩니다 [SWS_SM_91104].
                            • 

                          • kOperationFailed: 요청된 검증 작업이 실패했음을 나타냅니다 [SWS_SM_91104].
                            • 

                          


                          상호작용 및 동시성
                          

                          
처리하는 동안 Controller 타입의 StateMachine 제어 모델링된 프로세스는 관리 대상 함수 그룹이 functionGroupList에 나열된 각 상태 머신을 ImpactedByUpdate(으)로 표시합니다 [SWS_SM_00654]. 이것이 Agent 타입의 StateMachine에 영향을 미치는 경우 연관된 Controller도 간접적으로 ImpactedByUpdate(으)로 표시됩니다 [SWS_SM_00655]. 이 상태가 활성인 동안에는 Platform Health Management 또는 Execution Management에서 보고된 실행 오류(ExecutionErrorEvent::executionError)가 무시되고 로그에만 기록됩니다 [SWS_SM_00664]. 해당 상태 머신들은 이 단계 동안 각 StateMachine의 5대 필수 상태 중 하나인 VerifyUpdate 상태로 전환될 것으로 추정됩니다 AUTOSAR_AP_SWS_StateManagement §7.7.1 “StateMachine introduction”.
