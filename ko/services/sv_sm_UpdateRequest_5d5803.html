서비스 인터페이스의 역할 및 시스템 컨텍스트

서비스 인터페이스 UpdateRequest은 AUTOSAR Adaptive Platform AUTOSAR_AP_SWS_StateManagement §9.2 “Provided Service Interfaces”에서 State Management(SM) 기능 클러스터와 Update and Configuration Management(UCM) 간의 표준화된 상호 작용 브리지 역할을 합니다. 이 아키텍처 컨텍스트에서 State Management는 제공된 포트를 통해 서버 또는 서비스 제공자 [SWS_SM_91016]로 작동하는 반면, UCM은 서비스 소비자로 동작합니다. 이 인터페이스의 목적은 소프트웨어 클러스터의 업데이트(설치, 업데이트 및 제거 포함)를 머신의 시스템 및 기능 그룹 상태와 제어된 방식으로 조정하는 것입니다 [SWS_SM_91017].

서비스 인터페이스의 메서드 및 필드

서비스 인터페이스 UpdateRequest은 6개의 메서드와 상태 모니터링을 위한 1개의 필드로 구성됩니다. 머신 리셋을 제외한 모든 메서드는 동기 클라이언트-서버 시맨틱(Fire & Forget: false)을 가지므로 호출자는 State Management의 실행 또는 확인을 기다립니다:

  • RequestUpdateSession(): 매개변수 없이 업데이트 세션을 시작합니다. 시스템을 업데이트할 수 없거나 이미 세션이 실행 중인 경우 거부됩니다 [SWS_SM_91102].
  • PrepareUpdate(IN FunctionGroupListType functionGroupList): 해당 소프트웨어 클러스터의 기능 그룹을 업데이트할 수 있도록 준비합니다 [SWS_SM_91103] [SWS_SM_00206].
  • VerifyUpdate(IN FunctionGroupListType functionGroupList): 준비 후 업데이트된 기능 그룹을 검증합니다 [SWS_SM_91104].
  • PrepareRollback(IN FunctionGroupListType functionGroupList): 업데이트가 실패할 경우 지정된 기능 그룹의 롤백을 준비합니다 [SWS_SM_91105].
  • ResetMachine(): 머신 재부팅을 트리거합니다. 이는 Fire-and-Forget 메서드입니다(Fire & Forget: true) [SWS_SM_91100]. 리셋 전에 모든 관련 정보가 영속화되어야 합니다.
  • StopUpdateSession(): 활성 업데이트 세션을 완료하고 State Management에 머신 상태가 다시 안정화되었음을 알립니다 [SWS_SM_91101] [SWS_SM_00205].
  • ResetMachineNotifier: UCM이 ResetMachine()의 실행 중 및 실행 후 상태를 파악할 수 있는 Getter 및 Notifier(Setter 없음)가 포함된 UpdateStatusType 타입의 필드입니다 [SWS_SM_91106] [SWS_SM_00211].

수명 주기, 세션 흐름 및 상태 종속성

상호 작용에는 활성 업데이트 세션이 반드시 필요합니다. 후속 작업이 허용되기 전에 UCM은 먼저 RequestUpdateSession()을 호출해야 합니다 AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”. State Management는 계획된 또는 계획되지 않은 머신 리셋 후에도 UCM이 프로세스를 일관되게 계속할 수 있도록 진행 중인 업데이트 세션에 대한 정보를 영속화합니다 [SWS_SM_00204]. ResetMachine()을 통한 재부팅 후 State Management는 ContinueUpdate 상태로 전환되며, 이때 UCM은 ResetMachineNotifier를 통해 다시 동기화할 수 있도록 실행 가능한 상태여야 합니다 AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”.

세션 내에서 개별 단계는 상호 의존적입니다. VerifyUpdate()은 이전에 PrepareUpdate()의 성공적인 호출을 필수적으로 전제합니다 [SWS_SM_91104]. 소프트웨어 클러스터의 설치, 삭제 또는 업데이트 여부에 따라 UCM은 해당 단계를 수행합니다 AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”. 모든 변경이 완료되면 StopUpdateSession()가 프로세스를 종료합니다 [SWS_SM_00205].

시퀀스 다이어그램: 서비스 인터페이스 UpdateRequest를 통한 UCM과 State Management 간의 일반적인 상호 작용 흐름. 출처: [SWS_SM_91102], [SWS_SM_91103], [SWS_SM_91104], [SWS_SM_91100], [SWS_SM_91106], [SWS_SM_91101]

오류 처리 및 Application Errors

UpdateRequest의 메서드는 허용되지 않은 호출이나 내부 오류 상태를 알리기 위해 특정 애플리케이션 오류(Application Errors)를 정의합니다:

  • kOperationRejected: State Management 또는 머신의 현재 내부 상태로 인해 요청이 허용되지 않는 경우 모든 메서드에서 반환됩니다 [SWS_SM_91102]. 특히 활성 업데이트 세션 외부에서 수행되는 PrepareUpdate, VerifyUpdate, PrepareRollback 또는 StopUpdateSession의 호출은 이 오류를 반환합니다 [SWS_SM_00213].
  • kNotAllowedMultipleUpdateSessions: 머신에는 특정 시점에 하나의 활성 업데이트 세션만 병렬로 존재할 수 있으므로 RequestUpdateSession()에서만 독점적으로 발생합니다 [SWS_SM_91102].
  • kOperationFailed: 기능 그룹에 대해 요청된 준비 또는 검증 작업이 실패했음을 PrepareUpdate, VerifyUpdate 및 PrepareRollback에서 나타냅니다 [SWS_SM_91103] [SWS_SM_91104] [SWS_SM_91105].

사용

서비스 메서드 PrepareRollback [SWS_SM_91105]은(는) State Management가 업데이트를 승인하고 이전 업데이트 단계가 실패한 후, 서비스 인터페이스 UpdateRequest을(를) 통해 Update and Configuration Management(UCM)에 의해 호출됩니다 SWS StateManagement §7.x “ResetMachine notification”. PrepareRollback은(는) Fire-and-Forget으로 정의되어 있지 않으므로, 동기 확인 또는 오류 전송과 함께 호출이 수행됩니다 [SWS_SM_91105]. 입력 매개변수로는 롤백을 위해 준비해야 할 소프트웨어 클러스터 내의 함수 그룹 목록을 지정하는 FunctionGroupListType 유형의 functionGroupList이(가) 전달됩니다 [SWS_SM_91105].

오류 처리

사양에서는 이 메서드에 대해 특정한 반환 오류를 규정하고 있습니다 [SWS_SM_91105]:

  • kOperationRejected: State Management 또는 해당 상태 머신의 내부 상태로 인해 요청이 거부됩니다 [SWS_SM_91105]. 이는 활성 업데이트 세션 외부에서 호출이 수행되는 경우에 반드시 해당합니다 [SWS_SM_00213].
  • kOperationFailed: 롤백 준비가 실패할 때 발생합니다 [SWS_SM_91105]. 업데이트 세션 중 발생한 오류는 UCM에 보고됩니다 [SWS_SM_00644].

상호작용 및 상태 제어

PrepareRollback의 실행 중에 컨트롤러 상태 머신의 제어 프로세스는 자신이 관리하는 함수 그룹 중 적어도 하나가 매개변수 functionGroupList에 포함되어 있는 경우 각 상태 머신을 ImpactedByUpdate(으)로 표시합니다 [SWS_SM_00654]. 에이전트 상태 머신이 표시되면 컨트롤러 상태도 전이적으로 ImpactedByUpdate(으)로 설정됩니다 [SWS_SM_00655]. 이와 같이 표시된 상태 머신은 실행 오류 시 복구 요청을 무시하고 해당 이벤트를 단지 로깅만 합니다 [SWS_SM_00664]. 또한 이 메서드는 State Management의 모든 상태 머신이 가져야 하는 필수 상태 PrepareRollback과(와) 일치합니다 SWS StateManagement §7.7.1 “StateMachine introduction”.

      사용
      
  
      
    서비스 인터페이스 UpdateRequest의 서비스 메서드 PrepareUpdate([SWS_SM_91103])은 State Management에 일련의 기능 그룹의 업데이트 준비를 요청하기 위해 Update and Configuration Management (UCM)에 의해 호출됩니다 ([SWS_SM_00206], AUTOSAR_AP_SWS_StateManagement 32쪽). 입력 매개변수로 functionGroupList(유형 FunctionGroupListType)이 전달되며, 이는 해당 SoftwareCluster 내에서 업데이트할 기능 그룹의 목록을 정의합니다. 메서드 호출은 동기식이거나 응답을 제공하도록 설계되었습니다(Fire-and-Forget 아님) ([SWS_SM_91103]).
  
      

  
      순서 및 오류 처리
      
  
      
    PrepareUpdate의 호출에는 반드시 활성 업데이트 세션이 선행되어야 합니다. 이러한 세션 외부에서 호출이 발생하거나 사전에 RequestUpdateSession이(가) 성공적으로 실행되지 않은 경우, 요청은 애플리케이션 오류 kOperationRejected(으)로 거부됩니다 ([SWS_SM_00213], AUTOSAR_AP_SWS_StateManagement 31쪽, [SWS_SM_91103]). 기능 그룹의 준비에 실패하면 메서드는 kOperationFailed을(를) 반환합니다 ([SWS_SM_91103]).
  
      

  
      상호작용 및 동시성
      
  
      
    PrepareUpdate을 호출하는 동안 Controller 유형의 상태 머신의 제어 프로세스는 관리 대상 기능 그룹 중 최소 하나가 매개변수 functionGroupList에 포함되어 있는 경우 각 상태 머신을 ImpactedByUpdate로 표시합니다 ([SWS_SM_00654], AUTOSAR_AP_SWS_StateManagement 81쪽–82). <h4>서비스 인터페이스의 역할 및 시스템 컨텍스트</h4>
<p>
서비스 인터페이스 <code>UpdateRequest</code>은 AUTOSAR Adaptive Platform <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=137">AUTOSAR_AP_SWS_StateManagement §9.2 “Provided Service Interfaces”</a>에서 <em>State Management</em>(SM) 기능 클러스터와 <em>Update and Configuration Management</em>(UCM) 간의 표준화된 상호 작용 브리지 역할을 합니다. 이 아키텍처 컨텍스트에서 State Management는 제공된 포트를 통해 서버 또는 서비스 제공자 <a class="spec-record-ref" data-req="SWS_SM_91016" href="../spec/record.html?id=SWS_SM_91016">[SWS_SM_91016]</a>로 작동하는 반면, UCM은 서비스 소비자로 동작합니다. 이 인터페이스의 목적은 소프트웨어 클러스터의 업데이트(설치, 업데이트 및 제거 포함)를 머신의 시스템 및 기능 그룹 상태와 제어된 방식으로 조정하는 것입니다 <a class="spec-record-ref" data-req="SWS_SM_91017" href="../spec/record.html?id=SWS_SM_91017">[SWS_SM_91017]</a>.
</p>

<h4>서비스 인터페이스의 메서드 및 필드</h4>
<p>
서비스 인터페이스 <code>UpdateRequest</code>은 6개의 메서드와 상태 모니터링을 위한 1개의 필드로 구성됩니다. 머신 리셋을 제외한 모든 메서드는 동기 클라이언트-서버 시맨틱(<code>Fire &amp; Forget: false</code>)을 가지므로 호출자는 State Management의 실행 또는 확인을 기다립니다:
</p>
<ul>
<li><code>RequestUpdateSession()</code>: 매개변수 없이 업데이트 세션을 시작합니다. 시스템을 업데이트할 수 없거나 이미 세션이 실행 중인 경우 거부됩니다 <a class="spec-record-ref" data-req="SWS_SM_91102" href="../spec/record.html?id=SWS_SM_91102">[SWS_SM_91102]</a>.</li>
<li><code>PrepareUpdate(IN FunctionGroupListType functionGroupList)</code>: 해당 소프트웨어 클러스터의 기능 그룹을 업데이트할 수 있도록 준비합니다 <a class="spec-record-ref" data-req="SWS_SM_91103" href="../spec/record.html?id=SWS_SM_91103">[SWS_SM_91103]</a> <a class="spec-record-ref" data-req="SWS_SM_00206" href="../spec/record.html?id=SWS_SM_00206">[SWS_SM_00206]</a>.</li>
<li><code>VerifyUpdate(IN FunctionGroupListType functionGroupList)</code>: 준비 후 업데이트된 기능 그룹을 검증합니다 <a class="spec-record-ref" data-req="SWS_SM_91104" href="../spec/record.html?id=SWS_SM_91104">[SWS_SM_91104]</a>.</li>
<li><code>PrepareRollback(IN FunctionGroupListType functionGroupList)</code>: 업데이트가 실패할 경우 지정된 기능 그룹의 롤백을 준비합니다 <a class="spec-record-ref" data-req="SWS_SM_91105" href="../spec/record.html?id=SWS_SM_91105">[SWS_SM_91105]</a>.</li>
<li><code>ResetMachine()</code>: 머신 재부팅을 트리거합니다. 이는 Fire-and-Forget 메서드입니다(<code>Fire &amp; Forget: true</code>) <a class="spec-record-ref" data-req="SWS_SM_91100" href="../spec/record.html?id=SWS_SM_91100">[SWS_SM_91100]</a>. 리셋 전에 모든 관련 정보가 영속화되어야 합니다.</li>
<li><code>StopUpdateSession()</code>: 활성 업데이트 세션을 완료하고 State Management에 머신 상태가 다시 안정화되었음을 알립니다 <a class="spec-record-ref" data-req="SWS_SM_91101" href="../spec/record.html?id=SWS_SM_91101">[SWS_SM_91101]</a> <a class="spec-record-ref" data-req="SWS_SM_00205" href="../spec/record.html?id=SWS_SM_00205">[SWS_SM_00205]</a>.</li>
<li><code>ResetMachineNotifier</code>: UCM이 <code>ResetMachine()</code>의 실행 중 및 실행 후 상태를 파악할 수 있는 Getter 및 Notifier(Setter 없음)가 포함된 <code>UpdateStatusType</code> 타입의 필드입니다 <a class="spec-record-ref" data-req="SWS_SM_91106" href="../spec/record.html?id=SWS_SM_91106">[SWS_SM_91106]</a> <a class="spec-record-ref" data-req="SWS_SM_00211" href="../spec/record.html?id=SWS_SM_00211">[SWS_SM_00211]</a>.</li>
</ul>

<h4>수명 주기, 세션 흐름 및 상태 종속성</h4>
<p>
상호 작용에는 활성 업데이트 세션이 반드시 필요합니다. 후속 작업이 허용되기 전에 UCM은 먼저 <code>RequestUpdateSession()</code>을 호출해야 합니다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=31">AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”</a>. State Management는 계획된 또는 계획되지 않은 머신 리셋 후에도 UCM이 프로세스를 일관되게 계속할 수 있도록 진행 중인 업데이트 세션에 대한 정보를 영속화합니다 <a class="spec-record-ref" data-req="SWS_SM_00204" href="../spec/record.html?id=SWS_SM_00204">[SWS_SM_00204]</a>. <code>ResetMachine()</code>을 통한 재부팅 후 State Management는 <code>ContinueUpdate</code> 상태로 전환되며, 이때 UCM은 <code>ResetMachineNotifier</code>를 통해 다시 동기화할 수 있도록 실행 가능한 상태여야 합니다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=33">AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”</a>.
</p>
<p>
세션 내에서 개별 단계는 상호 의존적입니다. <code>VerifyUpdate()</code>은 이전에 <code>PrepareUpdate()</code>의 성공적인 호출을 필수적으로 전제합니다 <a class="spec-record-ref" data-req="SWS_SM_91104" href="../spec/record.html?id=SWS_SM_91104">[SWS_SM_91104]</a>. 소프트웨어 클러스터의 설치, 삭제 또는 업데이트 여부에 따라 UCM은 해당 단계를 수행합니다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=32">AUTOSAR_AP_SWS_StateManagement §7.7 “Update Handling”</a>. 모든 변경이 완료되면 <code>StopUpdateSession()</code>가 프로세스를 종료합니다 <a class="spec-record-ref" data-req="SWS_SM_00205" href="../spec/record.html?id=SWS_SM_00205">[SWS_SM_00205]</a>.
</p>

<h4>오류 처리 및 Application Errors</h4>
<p>
<code>UpdateRequest</code>의 메서드는 허용되지 않은 호출이나 내부 오류 상태를 알리기 위해 특정 애플리케이션 오류(Application Errors)를 정의합니다:
</p>
<ul>
<li><code>kOperationRejected</code>: State Management 또는 머신의 현재 내부 상태로 인해 요청이 허용되지 않는 경우 모든 메서드에서 반환됩니다 <a class="spec-record-ref" data-req="SWS_SM_91102" href="../spec/record.html?id=SWS_SM_91102">[SWS_SM_91102]</a>. 특히 활성 업데이트 세션 외부에서 수행되는 <code>PrepareUpdate</code>, <code>VerifyUpdate</code>, <code>PrepareRollback</code> 또는 <code>StopUpdateSession</code>의 호출은 이 오류를 반환합니다 <a class="spec-record-ref" data-req="SWS_SM_00213" href="../spec/record.html?id=SWS_SM_00213">[SWS_SM_00213]</a>.</li>
<li><code>kNotAllowedMultipleUpdateSessions</code>: 머신에는 특정 시점에 하나의 활성 업데이트 세션만 병렬로 존재할 수 있으므로 <code>RequestUpdateSession()</code>에서만 독점적으로 발생합니다 <a class="spec-record-ref" data-req="SWS_SM_91102" href="../spec/record.html?id=SWS_SM_91102">[SWS_SM_91102]</a>.</li>
<li><code>kOperationFailed</code>: 기능 그룹에 대해 요청된 준비 또는 검증 작업이 실패했음을 <code>PrepareUpdate</code>, <code>VerifyUpdate</code> 및 <code>PrepareRollback</code>에서 나타냅니다 <a class="spec-record-ref" data-req="SWS_SM_91103" href="../spec/record.html?id=SWS_SM_91103">[SWS_SM_91103]</a> <a class="spec-record-ref" data-req="SWS_SM_91104" href="../spec/record.html?id=SWS_SM_91104">[SWS_SM_91104]</a> <a class="spec-record-ref" data-req="SWS_SM_91105" href="../spec/record.html?id=SWS_SM_91105">[SWS_SM_91105]</a>.</li>
</ul>
