컨텍스트

네임스페이스 ara::sm::s2r은 State Management(SM) 모듈 내에서 Suspend-to-RAM(S2R) 기능을 위한 인터페이스와 메커니즘을 제공합니다(AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”). Suspend-to-RAM 동작의 목표는 완전히 시스템을 종료한 후 콜드 스타트를 수행하는 대신 머신을 빠른 재시작이 가능한 상태로 전환함으로써 시작 및 종료 시간을 대폭 최적화하는 것입니다(AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”).

이 네임스페이스에서 중심적인 역할은 클래스 S2RHub이 담당합니다(AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”). 허브는 분산된 S2RSatellite 인스턴스와의 통신을 조정합니다. 실행 파일 단위가 suspendToRamAware으로 구성된 애플리케이션은 예정된 Suspend 및 Resume 주기에 대한 알림을 받기 위해 이러한 새틀라이트 인스턴스를 통합합니다(AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”, [SWS_SM_00710]). suspendToRamNotSupported으로 선언된 프로세스는 운영체제가 Suspend 상태로 전환되기 전에 State Management 프로세스(예: 관련 기능 그룹 종료)에 의해 이미 중지되어 있어야 합니다(AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”).

S2RHub의 제어를 위해 상호 배타적인 두 가지 접근 방식이 존재합니다([SWS_SM_00684]):

  • StateMachine 접근 방식: Controller은 할당된 ActionListItem 객체를 통해 S2RHub 기능을 내부에 통합합니다. 이 작동 모드에서는 경쟁 조건과 상태 불일치를 방지하기 위해 외부 제어 애플리케이션의 허브 C++ API 접근이 금지됩니다(AUTOSAR_AP_SWS_StateManagement §7.7 “StateMachine approach”, [SWS_SM_00684]).
  • 직접 C++ API: 외부 제어 애플리케이션(예: SMControlApplication)이 S2RHub의 클래스 메서드를 직접 사용합니다(AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”).

컨텍스트 다이어그램: 제어 장치, S2RHub, S2RSatellite 및 어댑티브 애플리케이션 간의 상호작용. 출처: AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”, [SWS_SM_00710].

수명 주기

네임스페이스 ara::sm::s2r에서 인스턴스의 생성 및 해제는 권한 검사(Identity and Access Management, IAM) 및 구성된 매핑에 엄격하게 바인딩되어 있습니다:

  • 허브 인스턴스화: StateMachine 접근 방식에서 State Management는 EnterSuspendToRam, EnterSuspendToRamOS 또는 LeaveSuspendToRam 유형의 ActionListItem이 종료되는 즉시 S2RHub의 인스턴스를 생성합니다([SWS_SM_00690]). 생성자 ara::sm::s2r::S2RHub::S2RHub의 실행 중에 프로세스 컨텍스트가 SuspendToRamHubMapping.process의 매핑과 일치하는지 확인합니다([SWS_SM_00706]). SuspendToRamHubMapping를 통해 권한을 부여받은 프로세스만이 SuspendToRamModuleInstantiation으로 식별된 허브 인스턴스를 사용하여 Suspend 작업을 트리거할 수 있습니다([SWS_SM_00714]).
  • 새틀라이트 생성: 새틀라이트 인스턴스는 팩토리 메서드 ara::sm::s2r::S2RSatellite::Create을 통해 인스턴스화됩니다([SWS_SM_00716]).
  • 등록 단계: 생성 후 새틀라이트는 ara::sm::s2r::S2RSatellite::Offer을 사용하여 허브에 등록합니다([SWS_SM_00710]). 허브는 SuspendToRamSatelliteMapping.process의 구성을 기준으로 프로세스 컨텍스트를 검증하고 권한이 없는 등록 시도를 거부합니다([SWS_SM_00715]). 새틀라이트는 성공적으로 등록된 시점부터 활성 등록된 것으로 간주됩니다([SWS_SM_00710]).
  • 등록 취소: 새틀라이트가 ara::sm::s2r::S2RSatellite::StopOffer을 호출하는 즉시 활성 등록이 종료됩니다([SWS_SM_00710], [SWS_SM_00713]).

사용 경로

일반적인 사용 흐름은 절전 모드 준비, Suspend 모드로의 전환, 그리고 머신 재활성화 후 조정된 깨어나기를 포함합니다:

  1. 준비: 각 S2R 지원 애플리케이션은 자체 S2RSatellite을 초기화하고 Offer()을 통해 허브에 수신 준비 완료를 보고합니다([SWS_SM_00710]).
  2. Suspend 요청: 절전 모드를 시작하기 위해 ara::sm::s2r::S2RHub::RequestToEnterSuspendMode이 호출됩니다([SWS_SM_00701]). StateMachine 접근 방식에서는 타임아웃 파라미터로 maxActionItemDuration를 사용하여 ActionListItem EnterSuspendToRam을 통해 수행됩니다([SWS_SM_00689]).
  3. 새틀라이트 알림: 허브는 활성 등록된 모든 새틀라이트의 주소를 지정하고 해당 콜백 ara::sm::s2r::S2RSatellite::EnterSuspendMode을 트리거합니다([SWS_SM_00701], [SWS_SM_00711]). RequestToEnterSuspendMode은 주소 지정된 모든 새틀라이트가 응답하거나 등록을 취소하거나 통신 타임아웃이 발생할 때까지 차단됩니다([SWS_SM_00702]).
  4. 운영체제 Suspend: 모든 새틀라이트가 준비되면 EnterSuspendToRamOs을 통해 실제 운영체제 Suspend 명령을 실행할 수 있습니다([SWS_SM_00692]).
  5. 깨어나기 요청: 깨어난 후 제어 장치는 ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode을 호출합니다([SWS_SM_00703]). StateMachine 접근 방식에서는 ActionListItem LeaveSuspendToRam에 의해 이루어집니다([SWS_SM_00691]). 제약 조건 [SWS_SM_CONSTR_00035]에 따라 LeaveSuspendToRam은 절전 상태 자체가 아닌 Suspend 모드를 벗어나는 역할을 담당하는 상태에만 독점적으로 할당되어야 합니다.
  6. 새틀라이트 재활성화: 허브는 등록된 새틀라이트에서 ara::sm::s2r::S2RSatellite::LeaveSuspendMode을 호출합니다([SWS_SM_00703], [SWS_SM_00711]). 이 호출은 모든 새틀라이트가 응답했거나 등록 취소되었거나 타임아웃이 만료되는 즉시 반환됩니다([SWS_SM_00707]).
  7. 등록 해제: 프로세스 또는 새틀라이트가 종료되면 StopOffer()을 통해 허브에서 등록 취소가 수행됩니다([SWS_SM_00710], [SWS_SM_00713]).

시퀀스 다이어그램: 등록부터 Suspend 및 Resume을 거쳐 등록 취소까지의 호출 시퀀스. 출처: [SWS_SM_00701], [SWS_SM_00702], [SWS_SM_00703], [SWS_SM_00707], [SWS_SM_00710], [SWS_SM_00711], [SWS_SM_00713].

오류 시나리오

허브와 새틀라이트 간의 상호작용에서 다음과 같은 오류 조건 및 사전 조건이 지정되어 있습니다:

  • 허브 생성 시 IAM 위반: S2RHub::S2RHub 호출자의 프로세스 컨텍스트가 SuspendToRamHubMapping.process 구성과 일치하지 않는 경우, 위반 사항 InsufficientPermissionsViolation가 보고되고 보안 이벤트 SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED이 트리거됩니다([SWS_SM_00706]).
  • 새틀라이트 인증 누락: IAM 스위치 “Force IAM switch”가 활성화된 경우, S2RSatellite::Create은 오류 코드 kAuthenticationRequired을 반환합니다([SWS_SM_00716]).
  • 권한 없는 새틀라이트 거부: 새틀라이트의 프로세스 컨텍스트가 SuspendToRamSatelliteMapping.process과 일치하지 않으면 허브는 등록을 거부합니다([SWS_SM_00715]).
  • 통신 타임아웃: RequestToLeaveSuspendMode 진행 중 주소 지정된 새틀라이트가 timeout에 의해 지정된 시간 내에 응답하지 않으면 허브는 오류 코드 kCommunicationTimeout를 반환합니다([SWS_SM_00707]).
  • 위성에 의한 거부: 유휴 상태를 벗어날 때 적어도 하나의 위성 인스턴스가 kRejected(으)로 부정 응답을 보내면, 허브는 전체 결과로 kAtLeastOneHadIssuesToLeave을(를) 반환합니다([SWS_SM_00707]). 모든 위성이 긍정적으로 확인하거나 StopOffer을(를) 통해 정상적으로 등록 해제되는 경우에만 긍정적인 전체 결과에 도달합니다([SWS_SM_00707]).
  • 구성 및 사용 제한: StateMachine의 Suspend 상태에 LeaveSuspendToRam을(를) 할당하는 것은 허용되지 않습니다([SWS_SM_CONSTR_00035]). 마찬가지로 StateMachine 방식이 활성화된 상태에서 S2RHub의 C++ API에 동시 접근하는 것도 금지됩니다([SWS_SM_00684]).

<h4>수명 주기</h4>
<p>네임스페이스 <code>ara::sm::s2r</code>에서 인스턴스의 생성 및 해제는 권한 검사(Identity and Access Management, IAM) 및 구성된 매핑에 엄격하게 바인딩되어 있습니다:</p>
<ul>
<li><strong>허브 인스턴스화:</strong> StateMachine 접근 방식에서 State Management는 <code>EnterSuspendToRam</code>, <code>EnterSuspendToRamOS</code> 또는 <code>LeaveSuspendToRam</code> 유형의 <code>ActionListItem</code>이 종료되는 즉시 <code>S2RHub</code>의 인스턴스를 생성합니다(<a class="spec-record-ref" data-req="SWS_SM_00690" href="../spec/record.html?id=SWS_SM_00690">[SWS_SM_00690]</a>). 생성자 <code>ara::sm::s2r::S2RHub::S2RHub</code>의 실행 중에 프로세스 컨텍스트가 <code>SuspendToRamHubMapping.process</code>의 매핑과 일치하는지 확인합니다(<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>). <code>SuspendToRamHubMapping</code>를 통해 권한을 부여받은 프로세스만이 <code>SuspendToRamModuleInstantiation</code>으로 식별된 허브 인스턴스를 사용하여 Suspend 작업을 트리거할 수 있습니다(<a class="spec-record-ref" data-req="SWS_SM_00714" href="../spec/record.html?id=SWS_SM_00714">[SWS_SM_00714]</a>).</li>
<li><strong>새틀라이트 생성:</strong> 새틀라이트 인스턴스는 팩토리 메서드 <code>ara::sm::s2r::S2RSatellite::Create</code>을 통해 인스턴스화됩니다(<a class="spec-record-ref" data-req="SWS_SM_00716" href="../spec/record.html?id=SWS_SM_00716">[SWS_SM_00716]</a>).</li>
<li><strong>등록 단계:</strong> 생성 후 새틀라이트는 <code>ara::sm::s2r::S2RSatellite::Offer</code>을 사용하여 허브에 등록합니다(<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>). 허브는 <code>SuspendToRamSatelliteMapping.process</code>의 구성을 기준으로 프로세스 컨텍스트를 검증하고 권한이 없는 등록 시도를 거부합니다(<a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>). 새틀라이트는 성공적으로 등록된 시점부터 활성 등록된 것으로 간주됩니다(<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>).</li>
<li><strong>등록 취소:</strong> 새틀라이트가 <code>ara::sm::s2r::S2RSatellite::StopOffer</code>을 호출하는 즉시 활성 등록이 종료됩니다(<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>, <a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>).</li>
</ul>

<h4>사용 경로</h4>
<p>일반적인 사용 흐름은 절전 모드 준비, Suspend 모드로의 전환, 그리고 머신 재활성화 후 조정된 깨어나기를 포함합니다:</p>
<ol>
<li><strong>준비:</strong> 각 S2R 지원 애플리케이션은 자체 <code>S2RSatellite</code>을 초기화하고 <code>Offer()</code>을 통해 허브에 수신 준비 완료를 보고합니다(<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>).</li>
<li><strong>Suspend 요청:</strong> 절전 모드를 시작하기 위해 <code>ara::sm::s2r::S2RHub::RequestToEnterSuspendMode</code>이 호출됩니다(<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>). StateMachine 접근 방식에서는 타임아웃 파라미터로 <code>maxActionItemDuration</code>를 사용하여 <code>ActionListItem</code> <code>EnterSuspendToRam</code>을 통해 수행됩니다(<a class="spec-record-ref" data-req="SWS_SM_00689" href="../spec/record.html?id=SWS_SM_00689">[SWS_SM_00689]</a>).</li>
<li><strong>새틀라이트 알림:</strong> 허브는 활성 등록된 모든 새틀라이트의 주소를 지정하고 해당 콜백 <code>ara::sm::s2r::S2RSatellite::EnterSuspendMode</code>을 트리거합니다(<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>, <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>). <code>RequestToEnterSuspendMode</code>은 주소 지정된 모든 새틀라이트가 응답하거나 등록을 취소하거나 통신 타임아웃이 발생할 때까지 차단됩니다(<a class="spec-record-ref" data-req="SWS_SM_00702" href="../spec/record.html?id=SWS_SM_00702">[SWS_SM_00702]</a>).</li>
<li><strong>운영체제 Suspend:</strong> 모든 새틀라이트가 준비되면 <code>EnterSuspendToRamOs</code>을 통해 실제 운영체제 Suspend 명령을 실행할 수 있습니다(<a class="spec-record-ref" data-req="SWS_SM_00692" href="../spec/record.html?id=SWS_SM_00692">[SWS_SM_00692]</a>).</li>
<li><strong>깨어나기 요청:</strong> 깨어난 후 제어 장치는 <code>ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode</code>을 호출합니다(<a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a>). StateMachine 접근 방식에서는 <code>ActionListItem</code> <code>LeaveSuspendToRam</code>에 의해 이루어집니다(<a class="spec-record-ref" data-req="SWS_SM_00691" href="../spec/record.html?id=SWS_SM_00691">[SWS_SM_00691]</a>). 제약 조건 <a class="spec-record-ref" data-req="SWS_SM_CONSTR_00035" href="../spec/record.html?id=SWS_SM_CONSTR_00035">[SWS_SM_CONSTR_00035]</a>에 따라 <code>LeaveSuspendToRam</code>은 절전 상태 자체가 아닌 Suspend 모드를 벗어나는 역할을 담당하는 상태에만 독점적으로 할당되어야 합니다.</li>
<li><strong>새틀라이트 재활성화:</strong> 허브는 등록된 새틀라이트에서 <code>ara::sm::s2r::S2RSatellite::LeaveSuspendMode</code>을 호출합니다(<a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a>, <a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>). 이 호출은 모든 새틀라이트가 응답했거나 등록 취소되었거나 타임아웃이 만료되는 즉시 반환됩니다(<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>등록 해제:</strong> 프로세스 또는 새틀라이트가 종료되면 <code>StopOffer()</code>을 통해 허브에서 등록 취소가 수행됩니다(<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>, <a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>).</li>
</ol>

<h4>오류 시나리오</h4>
<p>허브와 새틀라이트 간의 상호작용에서 다음과 같은 오류 조건 및 사전 조건이 지정되어 있습니다:</p>
<ul>
<li><strong>허브 생성 시 IAM 위반:</strong> <code>S2RHub::S2RHub</code> 호출자의 프로세스 컨텍스트가 <code>SuspendToRamHubMapping.process</code> 구성과 일치하지 않는 경우, 위반 사항 <code>InsufficientPermissionsViolation</code>가 보고되고 보안 이벤트 <code>SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED</code>이 트리거됩니다(<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>).</li>
<li><strong>새틀라이트 인증 누락:</strong> IAM 스위치 “Force IAM switch”가 활성화된 경우, <code>S2RSatellite::Create</code>은 오류 코드 <code>kAuthenticationRequired</code>을 반환합니다(<a class="spec-record-ref" data-req="SWS_SM_00716" href="../spec/record.html?id=SWS_SM_00716">[SWS_SM_00716]</a>).</li>
<li><strong>권한 없는 새틀라이트 거부:</strong> 새틀라이트의 프로세스 컨텍스트가 <code>SuspendToRamSatelliteMapping.process</code>과 일치하지 않으면 허브는 등록을 거부합니다(<a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>).</li>
<li><strong>통신 타임아웃:</strong> <code>RequestToLeaveSuspendMode</code> 진행 중 주소 지정된 새틀라이트가 <code>timeout</code>에 의해 지정된 시간 내에 응답하지 않으면 허브는 오류 코드 <code>kCommunicationTimeout</code>를 반환합니다(<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>위성에 의한 거부:</strong> 유휴 상태를 벗어날 때 적어도 하나의 위성 인스턴스가 <code>kRejected</code>(으)로 부정 응답을 보내면, 허브는 전체 결과로 <code>kAtLeastOneHadIssuesToLeave</code>을(를) 반환합니다(<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>). 모든 위성이 긍정적으로 확인하거나 <code>StopOffer</code>을(를) 통해 정상적으로 등록 해제되는 경우에만 긍정적인 전체 결과에 도달합니다(<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>).</li>
<li><strong>구성 및 사용 제한:</strong> StateMachine의 Suspend 상태에 <code>LeaveSuspendToRam</code>을(를) 할당하는 것은 허용되지 않습니다(<a class="spec-record-ref" data-req="SWS_SM_CONSTR_00035" href="../spec/record.html?id=SWS_SM_CONSTR_00035">[SWS_SM_CONSTR_00035]</a>). 마찬가지로 StateMachine 방식이 활성화된 상태에서 <code>S2RHub</code>의 C++ API에 동시 접근하는 것도 금지됩니다(<a class="spec-record-ref" data-req="SWS_SM_00684" href="../spec/record.html?id=SWS_SM_00684">[SWS_SM_00684]</a>).</li>
</ul>
