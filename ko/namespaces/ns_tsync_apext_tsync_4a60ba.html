컨텍스트

네임스페이스 apext::tsync은 Freshness Value Management(FVM)를 위한 AUTOSAR Adaptive 모듈 tsync의 플랫폼별 확장(Platform Extensions)을 제공합니다. 분산 자동차 ECU 아키텍처에서 Freshness Value Management는 동적 신선도 값을 생성, 관리 및 검증하여 재생 및 지연 공격으로부터 시간 결정적이며 보안에 민감한 동기화 메시지를 보호합니다.

네임스페이스의 주요 역할은 모듈 ara::tsync을 위한 핵심 인터페이스 FVM 및 관련 데이터 구조를 제공하는 것입니다. 신선도 값은 값의 비트 길이와 벡터 형태의 실제 페이로드 데이터를 모두 수용하는 컨테이너 클래스 FVContainer에 의해 캡슐화됩니다. 표준화된 오류 처리를 위해 네임스페이스는 연관된 오류 열거자 TsyncFvmErrc [SWS_TS_14202]를 갖는 독립적인 오류 도메인 TsyncFvmErrorDomain, 오류 팩토리 함수 MakeErrorCode [SWS_TS_14213], 그리고 예외 클래스 TsyncFvmException을 정의합니다.

컨텍스트 다이어그램: ara::tsync, FVM 인터페이스, FVContainer 및 오류 도메인 간의 상호 작용. 출처: [SWS_TS_14202], [SWS_TS_14212], [SWS_TS_14213].

수명 주기

네임스페이스 apext::tsync의 컴포넌트는 명확히 구분된 수명 주기 및 동시성 조건의 적용을 받습니다.

  • 오류 도메인: 클래스 TsyncFvmErrorDomain은 글로벌 프로세스 전반의 오류 도메인 역할을 합니다. 함수 GetTsyncFvmErrorDomain()을 통해 언제든지 글로벌 인스턴스 객체에 대한 참조를 가져올 수 있습니다. 이 함수는 constexpr, 스레드 안전 및 예외 안전으로 지정되어 있으며 [SWS_TS_14212], 이에 따라 오류 도메인은 애플리케이션의 전체 런타임 동안 사용 가능한 상태로 유지됩니다.
  • 매니저 인스턴스: Freshness Value Manager를 위한 초기화 단계가 제공됩니다. 해석: Freshness Value Manager의 초기화는 별도의 구동 단계로 보이며, 이 단계의 실패는 매니저의 유용성을 영구적으로 방지합니다. 이는 복구 불가능한 오류("Unrecoverable Error")로 명시적으로 정의된 오류 코드 TsyncFvmErrc::kFVInitializeFailed에 의해 뒷받침되며, 이후에는 FVM을 더 이상 사용할 수 없습니다 [SWS_TS_14202].
  • 데이터 컨테이너: FVContainer의 인스턴스는 호출별 수명 주기를 갖습니다. 이들은 신선도 값을 수용하기 위해 생성되고 검사 또는 메시지 생성 중에 전달되며, 작업이 완료된 후 다시 소멸될 수 있습니다.

사용 경로

동기화 메시지를 보호하기 위한 일반적인 사용 경로는 다음 상호 작용 단계로 나뉩니다.

  1. 요청: 해석: 인터페이스 FVM은 신선도 값을 요청하고 검사하기 위해 ara::tsync 내의 컴포넌트에 의해 호출될 것으로 보입니다. 상위 시간 모듈은 발신 또는 수신 메시지에 신선도 값을 제공하기 위해 인터페이스 FVM를 통합합니다.
  2. 데이터 전달: Freshness Value Manager는 성공적으로 결정되었을 때 FVContainer의 인스턴스를 신선도 값의 비트 길이와 바이트 벡터로 채우고 이를 호출하는 시간 동기화에 전달합니다.
  3. 오류 신호: 런타임에 유효한 값을 사용할 수 없는 경우, 서브시스템은 TsyncFvmErrc::kFVNotAvailable [SWS_TS_14202]를 사용하여 MakeErrorCode [SWS_TS_14213]을 통해 ara::core::ErrorCode 타입의 표준화된 오류 코드를 생성합니다.
  4. 오류 평가: 호출자는 결과를 평가합니다. 해석: 복구 가능한 오류 상태이므로 호출자는 kFVNotAvailable에서 다시 읽기를 시도할 수 있을 것으로 보입니다.

오류 시나리오

apext::tsync의 오류 처리는 ara::core::ErrorCode을 통한 AUTOSAR Adaptive 표준 패턴을 따릅니다.

  • TsyncFvmErrc::kFVNotAvailable(값 1): 복구 가능한 오류("Recoverable Error")를 나타냅니다. 이 상태는 필요한 신선도 값을 일시적으로 검색할 수 없음을 알립니다 [SWS_TS_14202]. 호출 로직은 나중에 검색을 재시도하여 이를 처리할 수 있습니다.
  • TsyncFvmErrc::kFVInitializeFailed(값 2): 복구 불가능한 오류("Unrecoverable Error")를 나타냅니다. 이 코드는 Freshness Value Manager의 초기화가 실패했으며 모듈을 작동에 사용할 수 없음을 나타냅니다 [SWS_TS_14202].

오류 코드의 생성은 MakeErrorCode(TsyncFvmErrc, ara::core::ErrorDomain::SupportDataType) [SWS_TS_14213]을 통해 이루어지며, 이는 공급업체별 진단 데이터를 통합하고 보장된 스레드 안전 및 예외 안전으로 실행됩니다. C++ 예외로 작동하는 소프트웨어 경로의 경우 파생된 예외 클래스 TsyncFvmException가 제공됩니다.

<h4>컨텍스트</h4>
<p>네임스페이스 <code>apext::tsync</code>은 Freshness Value Management(FVM)를 위한 AUTOSAR Adaptive 모듈 <code>tsync</code>의 플랫폼별 확장(Platform Extensions)을 제공합니다. 분산 자동차 ECU 아키텍처에서 Freshness Value Management는 동적 신선도 값을 생성, 관리 및 검증하여 재생 및 지연 공격으로부터 시간 결정적이며 보안에 민감한 동기화 메시지를 보호합니다.</p>
<p>네임스페이스의 주요 역할은 모듈 <code>ara::tsync</code>을 위한 핵심 인터페이스 <code>FVM</code> 및 관련 데이터 구조를 제공하는 것입니다. 신선도 값은 값의 비트 길이와 벡터 형태의 실제 페이로드 데이터를 모두 수용하는 컨테이너 클래스 <code>FVContainer</code>에 의해 캡슐화됩니다. 표준화된 오류 처리를 위해 네임스페이스는 연관된 오류 열거자 <code>TsyncFvmErrc</code> <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>를 갖는 독립적인 오류 도메인 <code>TsyncFvmErrorDomain</code>, 오류 팩토리 함수 <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>, 그리고 예외 클래스 <code>TsyncFvmException</code>을 정의합니다.</p>

<h4>수명 주기</h4>
<p>네임스페이스 <code>apext::tsync</code>의 컴포넌트는 명확히 구분된 수명 주기 및 동시성 조건의 적용을 받습니다.</p>
<ul>
<li><strong>오류 도메인:</strong> 클래스 <code>TsyncFvmErrorDomain</code>은 글로벌 프로세스 전반의 오류 도메인 역할을 합니다. 함수 <code>GetTsyncFvmErrorDomain()</code>을 통해 언제든지 글로벌 인스턴스 객체에 대한 참조를 가져올 수 있습니다. 이 함수는 <code>constexpr</code>, 스레드 안전 및 예외 안전으로 지정되어 있으며 <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>, 이에 따라 오류 도메인은 애플리케이션의 전체 런타임 동안 사용 가능한 상태로 유지됩니다.</li>
<li><strong>매니저 인스턴스:</strong> Freshness Value Manager를 위한 초기화 단계가 제공됩니다. 해석: Freshness Value Manager의 초기화는 별도의 구동 단계로 보이며, 이 단계의 실패는 매니저의 유용성을 영구적으로 방지합니다. 이는 복구 불가능한 오류("Unrecoverable Error")로 명시적으로 정의된 오류 코드 <code>TsyncFvmErrc::kFVInitializeFailed</code>에 의해 뒷받침되며, 이후에는 FVM을 더 이상 사용할 수 없습니다 <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>.</li>
<li><strong>데이터 컨테이너:</strong> <code>FVContainer</code>의 인스턴스는 호출별 수명 주기를 갖습니다. 이들은 신선도 값을 수용하기 위해 생성되고 검사 또는 메시지 생성 중에 전달되며, 작업이 완료된 후 다시 소멸될 수 있습니다.</li>
</ul>

<h4>사용 경로</h4>
<p>동기화 메시지를 보호하기 위한 일반적인 사용 경로는 다음 상호 작용 단계로 나뉩니다.</p>
<ol>
<li><strong>요청:</strong> 해석: 인터페이스 <code>FVM</code>은 신선도 값을 요청하고 검사하기 위해 <code>ara::tsync</code> 내의 컴포넌트에 의해 호출될 것으로 보입니다. 상위 시간 모듈은 발신 또는 수신 메시지에 신선도 값을 제공하기 위해 인터페이스 <code>FVM</code>를 통합합니다.</li>
<li><strong>데이터 전달:</strong> Freshness Value Manager는 성공적으로 결정되었을 때 <code>FVContainer</code>의 인스턴스를 신선도 값의 비트 길이와 바이트 벡터로 채우고 이를 호출하는 시간 동기화에 전달합니다.</li>
<li><strong>오류 신호:</strong> 런타임에 유효한 값을 사용할 수 없는 경우, 서브시스템은 <code>TsyncFvmErrc::kFVNotAvailable</code> <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>를 사용하여 <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>을 통해 <code>ara::core::ErrorCode</code> 타입의 표준화된 오류 코드를 생성합니다.</li>
<li><strong>오류 평가:</strong> 호출자는 결과를 평가합니다. 해석: 복구 가능한 오류 상태이므로 호출자는 <code>kFVNotAvailable</code>에서 다시 읽기를 시도할 수 있을 것으로 보입니다.</li>
</ol>

<h4>오류 시나리오</h4>
<p><code>apext::tsync</code>의 오류 처리는 <code>ara::core::ErrorCode</code>을 통한 AUTOSAR Adaptive 표준 패턴을 따릅니다.</p>
<ul>
<li><strong><code>TsyncFvmErrc::kFVNotAvailable</code>(값 1):</strong> 복구 가능한 오류("Recoverable Error")를 나타냅니다. 이 상태는 필요한 신선도 값을 일시적으로 검색할 수 없음을 알립니다 <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>. 호출 로직은 나중에 검색을 재시도하여 이를 처리할 수 있습니다.</li>
<li><strong><code>TsyncFvmErrc::kFVInitializeFailed</code>(값 2):</strong> 복구 불가능한 오류("Unrecoverable Error")를 나타냅니다. 이 코드는 Freshness Value Manager의 초기화가 실패했으며 모듈을 작동에 사용할 수 없음을 나타냅니다 <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>.</li>
</ul>
<p>오류 코드의 생성은 <code>MakeErrorCode(TsyncFvmErrc, ara::core::ErrorDomain::SupportDataType)</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a>을 통해 이루어지며, 이는 공급업체별 진단 데이터를 통합하고 보장된 스레드 안전 및 예외 안전으로 실행됩니다. C++ 예외로 작동하는 소프트웨어 경로의 경우 파생된 예외 클래스 <code>TsyncFvmException</code>가 제공됩니다.</p>
