컨텍스트

네임스페이스 ara::rds은 AUTOSAR Adaptive Platform(Release R25-11) 내에서 원시 데이터 스트림(Raw Data Streams) 스트리밍을 위한 기능 인터페이스 및 데이터 구조를 제공합니다. 모듈의 주된 역할은 일반 바이너리 데이터 스트림뿐만 아니라 특수화된 형식화된 스트림 데이터그램을 네트워크 연결을 통해 효율적으로 전송하고 처리하는 것입니다. 네임스페이스는 바이너리 스트림의 일반 클라이언트-서버 전송과 IEEE 1722 표준에 따른 표준화된 전송이라는 두 가지 주요 기능 영역으로 나뉩니다.

일반 통신을 위해 네임스페이스는 핵심 엔드포인트 RawDataStreamServer 및 RawDataStreamClient을 정의합니다. 서버가 들어오는 네트워크 연결을 수락하고 데이터 스트림을 읽거나 쓰는 역할을 담당하는 반면, 클라이언트는 연결을 설정하고 이후 읽기 및 쓰기 접근을 수행하기 위한 활성 대향 엔드포인트 역할을 합니다. 읽기 작업의 결과는 헬퍼 클래스 ReadDataResult에 캡슐화됩니다.

시간 결정적인 멀티미디어 또는 시간 민감형 데이터 스트림을 위해 ara::rds은 IEEE 1722 프로토콜 전용 컴포넌트를 제공합니다. 데이터 전송 역할은 IEEE1722RawDataStreamProducer이 담당하며, 수신 및 필터링은 IEEE1722RawDataStreamConsumer에 의해 수행됩니다. 전송되는 데이터그램은 기본 표현인 IEEE1722Datagram, IEEE1722DatagramAVTPDUCommonHeaderFields 및 IEEE1722DatagramAVTPDUCommonStreamHeaderFields와 같은 공통 헤더 구조체, 그리고 IEEE1722DatagramAAF, IEEE1722DatagramRVF, IEEE1722DatagramCRF, IEEE1722DatagramTSCF, IEEE1722DatagramNTSCF, IEEE1722Datagram61883_IIDC과 같은 포맷별 파생 클래스를 포함한 일련의 구조화된 클래스에 의해 매핑됩니다.

컨텍스트 다이어그램: ara::rds 네임스페이스의 통신 엔드포인트 및 스트림 처리기 간 상호 작용. 출처: 페이로드에서 사용 가능한 직접적인 SWS 레코드 없음.

사용 경로

ara::rds 네임스페이스의 일반적인 사용 경로는 일반 점대점 스트림 연결이 구현되는지, 아니면 IEEE 1722에 따라 유형화된 스트리밍이 구현되는지에 따라 다릅니다. 일반 전송의 경우 서버 애플리케이션은 먼저 RawDataStreamServer 인스턴스를 초기화하고 들어오는 연결 요청을 기다립니다. 이와 병렬로 클라이언트 애플리케이션은 서버에 대한 네트워크 연결을 설정하는 RawDataStreamClient를 생성합니다.

성공적인 연결 설정 후 바이너리 데이터의 양방향 교환이 수행됩니다. 해석: 네트워크 연결을 통한 바이너리 데이터 전송은 TCP 또는 UDP와 같은 전송 프로토콜을 기반으로 할 것으로 보이며, 데이터 교환은 블록 단위 또는 버퍼링 방식으로 이루어집니다. 엔드포인트에 대한 읽기 작업은 읽은 페이로드 데이터 및 읽기 프로세스에 대한 상태 관련 정보를 제공하는 ReadDataResult 인스턴스를 반환값으로 제공합니다. 데이터 전송이 완료된 후 관련된 당사자들에 의해 스트림과 연결이 정돈되어 닫힙니다.

IEEE 1722 스트리밍 사용 사례에서 송신 애플리케이션은 IEEE1722RawDataStreamProducer을 생성합니다. 여기에는 구조화된 데이터그램이 공급되며, 해당 헤더는 IEEE1722DatagramAVTPDUCommonHeaderFields 또는 IEEE1722DatagramAVTPDUCommonStreamHeaderFields를 통해 매개변수화됩니다. 해석: IEEE1722DatagramAAF(오디오) 또는 IEEE1722DatagramRVF(비디오)와 같은 특정 데이터그램 클래스는 차량 네트워크에서 결정론적 오디오 및 비디오 스트리밍을 가능하게 하기 위해 표준화된 AVTP 페이로드를 캡슐화할 것으로 보입니다. 수신 측에서는 IEEE1722RawDataStreamConsumer가 형식화된 데이터 스트림을 구독하고 수신된 데이터그램을 처리 애플리케이션으로 전달합니다.

오류 시나리오

초기화, 연결 설정 또는 진행 중인 데이터 전송 중 발생하는 오류 상황은 ara::rds 네임스페이스에서 AUTOSAR Adaptive Platform의 통합 오류 모델을 통해 신호화됩니다. 이는 도메인 아키텍처 ara::core::ErrorDomain 및 ara::core::ErrorCode 타입의 오류 코드를 기반으로 합니다.

핵심 구성 요소는 enum class RdsErrc : ara::core::ErrorDomain::CodeType로 정의되고 Raw Data Stream의 모듈별 오류 상태를 나열하는 열거형 RdsErrc [SWS_RDS_12367]입니다. 선언은 헤더 파일 #include "ara/rds/rds_error_domain.h"에 있습니다.

오류 코드를 RDS 오류 도메인에 매핑하기 위해 헤더는 글로벌 도메인 객체 RdsErrorDomain에 대한 참조를 반환하는 함수 GetRdsErrorDomain [SWS_RDS_11298]을 제공합니다. 열거형 값 및 선택적 추가 데이터로부터 완전한 오류 코드를 생성하기 위해 constexpr ara::core::ErrorCode MakeErrorCode(RdsErrc code, ara::core::ErrorDomain::SupportDataType data) noexcept로 선언된 함수 MakeErrorCode [SWS_RDS_11299]가 사용됩니다.

일반적인 오류 시나리오에는 연결 설정 실패, 데이터 스트림 중 연결 중단, 버퍼 오버플로 또는 IEEE 1722 헤더 파싱 시 포맷 오류가 포함됩니다. 이러한 상태가 발생하면 영향을 받는 메서드는 일반적으로 해당하는 ara::core::ErrorCode을 반환합니다. 호출자 측에서 예외(Exception)가 사용되거나 오류가 예외 컨텍스트로 변환되어야 하는 경우, 클래스 RdsException이 해당 네임스페이스의 연관된 예외 타입을 나타냅니다.

이 가이드는 AUTOSAR Adaptive Platform Release R25-11 사양을 기반으로 합니다. 모든 정보는 사양 페이로드에 포함된 정의 및 SWS 항목에 기반합니다.

이 페이지는 SWS Raw Data Stream(R25-11)를 기반으로 완전히 AI로 생성되었다. 공식 AUTOSAR 텍스트도 없고 나머지 모듈처럼 자동으로 추출된 API 페이지도 없다. 해석으로 표시된 진술은 출처에서 도출된 결론이다.
