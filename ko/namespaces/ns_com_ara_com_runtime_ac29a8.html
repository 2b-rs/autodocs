모델에서 바인딩 공간으로의 변환

ara::com::runtime::ResolveInstanceIDs는 실행 파일의 고유한 InstanceSpecifier를 서비스 인스턴스 매니페스트에 구성된 기술 InstanceIdentifier로 변환합니다. 지정자가 다중 바인딩에서 여러 기술 인스턴스를 가리킬 수 있으므로 반환 값은 컨테이너입니다. EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers” 및 SWS CM §7.5.21 “Instance Specifier Translation” 의미 체계를 제공합니다.

명시적으로 해결이 필요한 경우

대부분의 Find 및 Skeleton API는 InstanceSpecifier를 직접 허용한다. 따라서 명시적 해결은 진단이나 특수 다중 바인딩 전략과 같이 특정 기술 할당을 의식적으로 처리해야 하는 경우에 특히 유용한다. EXP ARAComAPI §4.8.2 “When to use InstanceIdentifier versus InstanceSpecifier”는 이 제한을 설명한다.

프로세스는 모듈 가이드에 활동 다이어그램으로 문서화되어 있습니다: ara::com — Communication Management, 활동 다이어그램 “Manifest에 대한 InstanceSpecifier 해석”.

ara::core::Result< ara::com::InstanceIdentifierContainer > Resolve InstanceIDs (ara::core::InstanceSpecifier metaModelIdentifier) noexcept;

Translates an ara::core::InstanceSpecifier to a ara::com:: InstanceIdentifierContainer. The length/size of the ara::com:: InstanceIdentifierContainer is relative to the number of matches.

사용법 AI 생성 / AI generated

공식 AUTOSAR 텍스트가 아닌 참조된 AUTOSAR R25-11 문서에서 파생된 자동 생성된 사용 알림이다.

Manifest 해상도를 의식적으로 사용하십시오.

ResolveInstanceIDs()는 InstanceSpecifier의 배포 측 매핑을 읽고 InstanceIdentifierContainer를 반환한다. 빈 컨테이너는 할당이 부족함을 나타내고, 다중 값 컨테이너는 다중 바인딩을 나타냅니다. EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers”는 가능한 결과를 설명한다.

권장 프로세스
  1. 고유한 포트 컨텍스트에서 지정자를 제공한다.
  2. Result 그리고 용기 크기를 확인하세요.
  3. 여러 ID에 대해 명시적인 바인딩/장애 조치 전략을 사용한다.
  4. 표준 검색의 경우 지정자 오버로드를 사용하는 것이 좋습니다.

활동 다이어그램: 논리 InstanceSpecifier는 Manifest에 대해 하나 이상의 바인딩 관련 IDs에 매핑됩니다. 출처: EXP ARAComAPI §4.8.1 “Instance Identifiers and Instance Specifiers”.
