컨텍스트

네임스페이스 apext::com::secoc은 기능 클러스터 com(AUTOSAR_AP_SWS_CommunicationManagement §C “Platform Extension Interfaces”)을 위한 AUTOSAR Adaptive Platform의 표준 플랫폼 확장 인터페이스(Platform Extension Interfaces)를 정의합니다. 이러한 확장 인터페이스는 SecOC를 위한 Freshness Value Management를 통신 관리의 보안 아키텍처에 추가하기 위해 OEM 또는 스택 통합자에 의해 구현 및 제공되도록 설계되었습니다.

상호작용의 중심에는 세 가지 주요 역할이 있습니다:

  • 통신 관리(ara::com): 보안 메시지의 송수신 경로를 관리하고 SecOC 검증 및 신선도 값 관리의 통합을 조정합니다([SWS_CM_11272], [SWS_CM_11274]).
  • Freshness Value Manager (FVM): 송신 및 수신 메시지를 위한 신선도 값(Freshness Values)을 생성하거나 제공하기 위해 제조업체별로 구현되는 인터페이스 apext::com::secoc::FVM입니다([SWS_CM_11273], [SWS_CM_11274]).
  • 데이터 및 오류 캡슐화: 신선도 값 및 해당 비트 길이([SWS_CM_11344])를 표준화하여 수용하기 위한 구조체 FVContainer([SWS_CM_11286])과 오류 및 예외 처리를 위한 클래스 ComSecOcFvmErrorDomain 및 ComSecOcFvmException입니다([SWS_CM_11342], [SWS_CM_12521]).

컨텍스트 다이어그램: ara::com과 플랫폼 확장 인터페이스 apext::com::secoc::FVM 및 데이터 구조의 상호작용. 출처: AUTOSAR_AP_SWS_CommunicationManagement §C “Platform Extension Interfaces”, [SWS_CM_11272].

수명 주기

FVM 구현의 수명주기는 ara::com에 의해 완전히 제어됩니다([SWS_CM_11272]). 네임스페이스의 동작에는 고정된 단계가 적용됩니다:

  • 초기화: 사용하기 전에 ara::com이 라이브러리 API apext::com::secoc::FVM::Initialize을 호출하여 Freshness Value Manager의 제조업체별 구현을 반드시 초기화해야 합니다([SWS_CM_11273]). 해석: 구체적인 구현 인스턴스를 ara::com에 전달하거나 등록하는 작업은 스택 시작의 일환으로 제조업체별로 수행될 것으로 보입니다.
  • 운영 단계: 초기화가 성공하면 FVM은 활성 상태를 유지하며 최신 신선도 값을 제공하기 위한 통신 관리의 동기 또는 비동기 요청에 응답합니다([SWS_CM_11274]).
  • 오류 상태: 초기화 호출이 실패하면 오류 도메인이 코드 kFVInitializeFailed([SWS_CM_11342])을 보고하며, 이로 인해 보안 통신 경로가 정상 운영 상태로 전환될 수 없습니다.

사용 경로

네임스페이스 클래스를 통한 주요 사용 경로는 발신 메시지의 보안 보호(SecOC Secure Channel Sending)와 관련됩니다:

  1. 메시지 처리: 메시지가 SecOC를 통한 보안 보호로 구성된 경우, 통신 관리는 이를 인증된 메시지([SWS_CM_11274])로 처리합니다.
  2. 작업 순서: 종단 간 보호(E2E)를 위한 계산이 먼저 실행되며, SecOC 메시지 인증은 엄격하게 그 이후에 수행됩니다([SWS_CM_11274]).
  3. 신선도 값 쿼리: 구성 ServiceInterfaceElementSecureComConfig에 속성 freshnessValueId이 포함된 경우 통신 관리는 인터페이스 apext::com::secoc::FVM::GetTxFreshness를 호출합니다([SWS_CM_11274]). 신선도 값과 비트 단위 길이는 FVContainer에 저장됩니다([SWS_CM_11286], [SWS_CM_11344]).
  4. 카운터 관리 및 재시도: 보호해야 하는 각 메시지에 대해 ara::com은 Authentication Build Counter을 유지합니다([SWS_CM_11275]). 보호가 성공하면 카운터는 0으로 설정됩니다. GetTxFreshness이 오류 kFVNotAvailable를 반환하거나 인증자(Authenticator) 계산에 실패하면 카운터가 증가하고 구현에 따라 시도가 재시도됩니다([SWS_CM_11275]).
  5. 수신 처리: 수신 경로에서는 인증자를 추출하고 계산된 MAC을 통해 메시지를 검증합니다(AUTOSAR_AP_SWS_CommunicationManagement §8.1 “SecOC secure channel reception”, [SWS_CM_11276]). securedRxVerification가 명시적으로 false으로 설정된 경우 통신 관리에서 검증이 우회됩니다([SWS_CM_11372]).

시퀀스 다이어그램: 신선도 값 검색 및 재시도 로직을 포함한 송신 시 메시지 보안 보호 프로세스. 출처: [SWS_CM_11274], [SWS_CM_11275].

오류 시나리오

네임스페이스의 오류 동작은 오류 도메인 ComSecOcFvmErrorDomain을 통해 매핑되며, 해당 열거자 값은 ComSecOcFvmErrc에 의해 정의됩니다([SWS_CM_11342]):

  • kFVNotAvailable (Code 1): 요청된 신선도 값을 현재 사용할 수 없음을 나타냅니다([SWS_CM_11342]). 이는 복구 가능한 오류입니다. ara::com은 Authentication Build Counter를 증가시키고 시도를 반복하며, 임계값 SecOCAuthenticationBuildAttempts에 도달하면 메시지는 최종적으로 폐기됩니다([SWS_CM_11275]).
  • kFVInitializeFailed (Code 2): Freshness Value Manager의 초기화 실패를 나타냅니다([SWS_CM_11342]).
  • 오류 인스턴스화 및 예외: ara::core::ErrorCode의 인스턴스는 도우미 함수 MakeErrorCode을 사용하여 생성됩니다([SWS_CM_12522]). 싱글톤 유사 오류 도메인에 대한 접근은 GetComSecOcFvmErrorDomain을 통해 수행됩니다([SWS_CM_12521]). 예외 컨텍스트에서 오류가 발생하는 경우 특정 예외 클래스 ComSecOcFvmException가 사용됩니다.

이 가이드는 AUTOSAR Adaptive 문서를 기반으로 Release R25-11용 네임스페이스 apext::com::secoc의 사양을 요약합니다.

<h4>컨텍스트</h4>
<p>네임스페이스 <code>apext::com::secoc</code>은 기능 클러스터 <code>com</code>(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=536">AUTOSAR_AP_SWS_CommunicationManagement §C “Platform Extension Interfaces”</a>)을 위한 AUTOSAR Adaptive Platform의 표준 플랫폼 확장 인터페이스(Platform Extension Interfaces)를 정의합니다. 이러한 확장 인터페이스는 SecOC를 위한 Freshness Value Management를 통신 관리의 보안 아키텍처에 추가하기 위해 OEM 또는 스택 통합자에 의해 구현 및 제공되도록 설계되었습니다.</p>
<p>상호작용의 중심에는 세 가지 주요 역할이 있습니다:</p>
<ul>
<li><strong>통신 관리(<code>ara::com</code>)</strong>: 보안 메시지의 송수신 경로를 관리하고 SecOC 검증 및 신선도 값 관리의 통합을 조정합니다(<a class="spec-record-ref" data-req="SWS_CM_11272" href="../spec/record.html?id=SWS_CM_11272">[SWS_CM_11272]</a>, <a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>).</li>
<li><strong>Freshness Value Manager (<code>FVM</code>)</strong>: 송신 및 수신 메시지를 위한 신선도 값(Freshness Values)을 생성하거나 제공하기 위해 제조업체별로 구현되는 인터페이스 <code>apext::com::secoc::FVM</code>입니다(<a class="spec-record-ref" data-req="SWS_CM_11273" href="../spec/record.html?id=SWS_CM_11273">[SWS_CM_11273]</a>, <a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>).</li>
<li><strong>데이터 및 오류 캡슐화</strong>: 신선도 값 및 해당 비트 길이(<a class="spec-record-ref" data-req="SWS_CM_11344" href="../spec/record.html?id=SWS_CM_11344">[SWS_CM_11344]</a>)를 표준화하여 수용하기 위한 구조체 <code>FVContainer</code>(<a class="spec-record-ref" data-req="SWS_CM_11286" href="../spec/record.html?id=SWS_CM_11286">[SWS_CM_11286]</a>)과 오류 및 예외 처리를 위한 클래스 <code>ComSecOcFvmErrorDomain</code> 및 <code>ComSecOcFvmException</code>입니다(<a class="spec-record-ref" data-req="SWS_CM_11342" href="../spec/record.html?id=SWS_CM_11342">[SWS_CM_11342]</a>, <a class="spec-record-ref" data-req="SWS_CM_12521" href="../spec/record.html?id=SWS_CM_12521">[SWS_CM_12521]</a>).</li>
</ul>

<h4>수명 주기</h4>
<p>FVM 구현의 수명주기는 <code>ara::com</code>에 의해 완전히 제어됩니다(<a class="spec-record-ref" data-req="SWS_CM_11272" href="../spec/record.html?id=SWS_CM_11272">[SWS_CM_11272]</a>). 네임스페이스의 동작에는 고정된 단계가 적용됩니다:</p>
<ul>
<li><strong>초기화</strong>: 사용하기 전에 <code>ara::com</code>이 라이브러리 API <code>apext::com::secoc::FVM::Initialize</code>을 호출하여 Freshness Value Manager의 제조업체별 구현을 반드시 초기화해야 합니다(<a class="spec-record-ref" data-req="SWS_CM_11273" href="../spec/record.html?id=SWS_CM_11273">[SWS_CM_11273]</a>). 해석: 구체적인 구현 인스턴스를 <code>ara::com</code>에 전달하거나 등록하는 작업은 스택 시작의 일환으로 제조업체별로 수행될 것으로 보입니다.</li>
<li><strong>운영 단계</strong>: 초기화가 성공하면 FVM은 활성 상태를 유지하며 최신 신선도 값을 제공하기 위한 통신 관리의 동기 또는 비동기 요청에 응답합니다(<a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>).</li>
<li><strong>오류 상태</strong>: 초기화 호출이 실패하면 오류 도메인이 코드 <code>kFVInitializeFailed</code>(<a class="spec-record-ref" data-req="SWS_CM_11342" href="../spec/record.html?id=SWS_CM_11342">[SWS_CM_11342]</a>)을 보고하며, 이로 인해 보안 통신 경로가 정상 운영 상태로 전환될 수 없습니다.</li>
</ul>

<h4>사용 경로</h4>
<p>네임스페이스 클래스를 통한 주요 사용 경로는 발신 메시지의 보안 보호(SecOC Secure Channel Sending)와 관련됩니다:</p>
<ol>
<li><strong>메시지 처리</strong>: 메시지가 SecOC를 통한 보안 보호로 구성된 경우, 통신 관리는 이를 인증된 메시지(<a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>)로 처리합니다.</li>
<li><strong>작업 순서</strong>: 종단 간 보호(E2E)를 위한 계산이 먼저 실행되며, SecOC 메시지 인증은 엄격하게 그 이후에 수행됩니다(<a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>).</li>
<li><strong>신선도 값 쿼리</strong>: 구성 <code>ServiceInterfaceElementSecureComConfig</code>에 속성 <code>freshnessValueId</code>이 포함된 경우 통신 관리는 인터페이스 <code>apext::com::secoc::FVM::GetTxFreshness</code>를 호출합니다(<a class="spec-record-ref" data-req="SWS_CM_11274" href="../spec/record.html?id=SWS_CM_11274">[SWS_CM_11274]</a>). 신선도 값과 비트 단위 길이는 <code>FVContainer</code>에 저장됩니다(<a class="spec-record-ref" data-req="SWS_CM_11286" href="../spec/record.html?id=SWS_CM_11286">[SWS_CM_11286]</a>, <a class="spec-record-ref" data-req="SWS_CM_11344" href="../spec/record.html?id=SWS_CM_11344">[SWS_CM_11344]</a>).</li>
<li><strong>카운터 관리 및 재시도</strong>: 보호해야 하는 각 메시지에 대해 <code>ara::com</code>은 <code>Authentication Build Counter</code>을 유지합니다(<a class="spec-record-ref" data-req="SWS_CM_11275" href="../spec/record.html?id=SWS_CM_11275">[SWS_CM_11275]</a>). 보호가 성공하면 카운터는 0으로 설정됩니다. <code>GetTxFreshness</code>이 오류 <code>kFVNotAvailable</code>를 반환하거나 인증자(Authenticator) 계산에 실패하면 카운터가 증가하고 구현에 따라 시도가 재시도됩니다(<a class="spec-record-ref" data-req="SWS_CM_11275" href="../spec/record.html?id=SWS_CM_11275">[SWS_CM_11275]</a>).</li>
<li><strong>수신 처리</strong>: 수신 경로에서는 인증자를 추출하고 계산된 MAC을 통해 메시지를 검증합니다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=226">AUTOSAR_AP_SWS_CommunicationManagement §8.1 “SecOC secure channel reception”</a>, <a class="spec-record-ref" data-req="SWS_CM_11276" href="../spec/record.html?id=SWS_CM_11276">[SWS_CM_11276]</a>). <code>securedRxVerification</code>가 명시적으로 <code>false</code>으로 설정된 경우 통신 관리에서 검증이 우회됩니다(<a class="spec-record-ref" data-req="SWS_CM_11372" href="../spec/record.html?id=SWS_CM_11372">[SWS_CM_11372]</a>).</li>
</ol>

<h4>오류 시나리오</h4>
<p>네임스페이스의 오류 동작은 오류 도메인 <code>ComSecOcFvmErrorDomain</code>을 통해 매핑되며, 해당 열거자 값은 <code>ComSecOcFvmErrc</code>에 의해 정의됩니다(<a class="spec-record-ref" data-req="SWS_CM_11342" href="../spec/record.html?id=SWS_CM_11342">[SWS_CM_11342]</a>):</p>
<ul>
<li><strong><code>kFVNotAvailable</code> (Code 1)</strong>: 요청된 신선도 값을 현재 사용할 수 없음을 나타냅니다(<a class="spec-record-ref" data-req="SWS_CM_11342" href="../spec/record.html?id=SWS_CM_11342">[SWS_CM_11342]</a>). 이는 복구 가능한 오류입니다. <code>ara::com</code>은 <code>Authentication Build Counter</code>를 증가시키고 시도를 반복하며, 임계값 <code>SecOCAuthenticationBuildAttempts</code>에 도달하면 메시지는 최종적으로 폐기됩니다(<a class="spec-record-ref" data-req="SWS_CM_11275" href="../spec/record.html?id=SWS_CM_11275">[SWS_CM_11275]</a>).</li>
<li><strong><code>kFVInitializeFailed</code> (Code 2)</strong>: Freshness Value Manager의 초기화 실패를 나타냅니다(<a class="spec-record-ref" data-req="SWS_CM_11342" href="../spec/record.html?id=SWS_CM_11342">[SWS_CM_11342]</a>).</li>
<li><strong>오류 인스턴스화 및 예외</strong>: <code>ara::core::ErrorCode</code>의 인스턴스는 도우미 함수 <code>MakeErrorCode</code>을 사용하여 생성됩니다(<a class="spec-record-ref" data-req="SWS_CM_12522" href="../spec/record.html?id=SWS_CM_12522">[SWS_CM_12522]</a>). 싱글톤 유사 오류 도메인에 대한 접근은 <code>GetComSecOcFvmErrorDomain</code>을 통해 수행됩니다(<a class="spec-record-ref" data-req="SWS_CM_12521" href="../spec/record.html?id=SWS_CM_12521">[SWS_CM_12521]</a>). 예외 컨텍스트에서 오류가 발생하는 경우 특정 예외 클래스 <code>ComSecOcFvmException</code>가 사용됩니다.</li>
</ul>
