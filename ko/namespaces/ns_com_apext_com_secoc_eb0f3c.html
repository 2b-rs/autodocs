보안 통신 채널을 위한 신선도 값 관리 및 오류 처리 인터페이스를 정의합니다.

이 네임스페이스는 AUTOSAR Adaptive Platform Communication Management(SWS Communication Management §C.1 “Header: apext/com/secoc/fvm.h”)를 위한 Secure Onboard Communication(SecOC) 프레임워크 내에서 신선도 값을 관리하기 위한 공급업체별 인터페이스를 정의합니다. Freshness Value Manager의 수명 주기 및 초기화는 구성된 전송 작업 중에 인터페이스를 통해 신선도 값을 쿼리하는 통신 관리에 의해 완전히 제어됩니다([SWS_CM_11272]). 신선도 값이 일시적으로 사용 불가능한 경우, 결함이 있는 메시지가 폐기되기 전에 정의된 임계값까지 제어된 재시도가 수행됩니다. 또한 네임스페이스는 진단 및 예외 처리를 위한 자체 오류 도메인과 표준화된 오류 코드를 제공합니다.

컨텍스트

네임스페이스 apext::com::secoc은 AUTOSAR Adaptive Platform(SWS Communication Management §C.1 “Header: apext/com/secoc/fvm.h”)의 Communication Management(ara::com) 기능 클러스터 내에서 플랫폼 확장 인터페이스(Platform Extension Interfaces)에 대한 규범적 인터페이스를 정의합니다. 이러한 확장 인터페이스의 목표는 OEM 및 스택 공급업체가 Secure Onboard Communication(SecOC)에 필요한 재생 공격 방지용 신선도 값을 생성, 관리 및 검증하는 맞춤형 Freshness Value Manager(FVM)를 제공할 수 있도록 하는 것입니다.

이 네임스페이스는 기본적으로 세 가지 역할과 상호작용합니다: 통신 관리(ara::com), FVContainer([SWS_CM_11286], [SWS_CM_11344])와 같은 데이터 캐리어를 포함한 표준화된 인터페이스 정의(FVM), 그리고 차량 제조업체 또는 스택 공급업체의 구체적인 FVM 구현입니다. Interpretation: 사양에는 기능적 인터페이스가 명시되어 있지만 통합 형태는 스택별로 개방되어 있으므로, 공급업체별 FVM 라이브러리는 시스템 통합의 일환으로 정적 또는 동적 라이브러리로 연결된다고 가정합니다. 질문 Q-256aef3d6698cc3f (열림)

컨텍스트 다이어그램: Communication Management와 공급업체별 FVM 구현 간의 apext::com::secoc 네임스페이스 통합. 출처: [SWS_CM_11272], SWS Communication Management §C.1 “Header: apext/com/secoc/fvm.h”.

수명 주기

FVM 구현의 수명 주기 관리는 통신 관리 ara::com에 의해 완전히 제어됩니다([SWS_CM_11272]). 애플리케이션 및 서비스 인스턴스는 FVM 컴포넌트를 직접 생성하거나 관리하지 않습니다.

시운전은 라이브러리 API apext::com::secoc::FVM::Initialize을 호출하여 통신 스택 초기화 중에 결정론적으로 수행됩니다([SWS_CM_11273]). 공급업체 측에서 초기화가 올바르게 완료될 수 없는 경우, FVM 계층은 정의된 오류 코드 kFVInitializeFailed를 통해 이 오류 상태를 알립니다([SWS_CM_11342]). 성공적인 초기화 호출 후 Freshness Value Manager는 활성 작동 상태를 유지하며 송신 및 수신 신선도 값에 대한 동기 요청에 응답합니다.

사용 경로

일반적인 사용 경로는 메시지의 송신 보안과 수신 검증으로 나뉩니다:

  • 송신 메시지: 메시지가 SecOC 전송용으로 구성된 경우 신뢰할 수 있는 메시지로 처리됩니다([SWS_CM_11274]). 보안 적용은 모든 E2E 보호 계산이 완료된 후 고정된 순서로 수행됩니다([SWS_CM_11274]). 서비스 인터페이스 구성에 속성 freshnessValueId가 있는 경우 통신 관리는 apext::com::secoc::FVM::GetTxFreshness을 호출합니다([SWS_CM_11274], [SWS_CM_11275]). 신선도 값은 속성 length에 비트 길이를 보유하고 값 자체를 보유하는 FVContainer 구조체로 제공됩니다([SWS_CM_11286], [SWS_CM_11344]).
  • 송신 재시도 메커니즘: 보안이 적용된 각 메시지에 대해 시스템은 Authentication Build Counter을 유지합니다([SWS_CM_11275]). 성공적으로 생성된 후 카운터는 0으로 재설정됩니다. GetTxFreshness가 복구 가능한 오류 kFVNotAvailable을 반환하거나 Authenticator 계산이 실패하면 카운터가 증가하고 생성이 재시도됩니다([SWS_CM_11275]). 카운터가 임계값 SecOCAuthenticationBuildAttempts에 도달하면 메시지가 폐기됩니다([SWS_CM_11275]).
  • 수신 메시지: 활성 검증(속성 securedRxVerification이 참이거나 설정되지 않음)이 있는 인바운드 SecOC 메시지의 경우 Authenticator가 추출되고 E2E 검사 전에 MAC 재계산을 통해 메시지가 검증됩니다([SWS_CM_11276], SWS Communication Management §8.1 “SecOC secure channel reception”). 반면 securedRxVerification이 거짓으로 설정된 경우 검증이 우회(Bypass)되고 메시지가 검사 없이 처리됩니다([SWS_CM_11372]).

시퀀스 다이어그램: FVM을 사용한 송신 메시지 보안 적용 시 호출 및 재시도 흐름. 출처: [SWS_CM_11274], [SWS_CM_11275].

오류 시나리오

FVM 인터페이스 내의 오류 상황은 타입 안전 오류 도메인 ComSecOcFvmErrorDomain을 통해 처리되며, 해당 인스턴스는 GetComSecOcFvmErrorDomain을 통해 조회할 수 있습니다([SWS_CM_12521]). 오류 코드는 열거형 ComSecOcFvmErrc에 정의되어 있습니다([SWS_CM_11342]):

  • kFVNotAvailable(코드 1): 필요한 신선도 값을 일시적으로 사용할 수 없습니다. 이는 Communication Management에 복구 가능한 오류임을 알리고, 전송 프로토콜에 따라 재시도를 트리거합니다([SWS_CM_11275], [SWS_CM_11342]).
  • kFVInitializeFailed(코드 2): Freshness Value Manager 초기화에 실패했습니다([SWS_CM_11342]).

도우미 함수 MakeErrorCode([SWS_CM_12522])을 통해 오류 코드를 공급업체별 추가 데이터(SupportDataType)와 함께 일반 ara::core::ErrorCode 객체로 캡슐화할 수 있습니다. 예외 기반 환경에서 실패한 동기 호출을 위해 예외 클래스 ComSecOcFvmException가 제공됩니다.

이 가이드는 AUTOSAR Adaptive Platform R25-11(Communication Management) 사양을 기반으로 합니다. 모든 진술은 명시된 사양 및 문서 참조만을 근거로 합니다.

      사용
