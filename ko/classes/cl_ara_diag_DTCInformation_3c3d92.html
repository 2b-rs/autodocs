컨텍스트

ara::diag::DTCInformation 클래스는 AUTOSAR Adaptive(모듈 diag)에서 구성된 진단 메모리 타깃(DiagnosticMemoryDestination)과 관련된 DTC(Diagnostic Trouble Code) 정보에 대한 작업 및 상태 조회를 수행하기 위한 기능적 인터페이스를 제공합니다 [SWS_DM_00664]. 이는 애플리케이션별 진단 및 모니터링 로직과 기반 Diagnostic Management(DM) 간의 연결 고리 역할을 합니다.

주요 상호작용 파트너로는 Adaptive Application, DM의 내부 메모리 관리 및 외부 진단 테스터가 있습니다. 외부 진단 테스터는 서비스 0x19(ReadDTCInformation) 또는 서비스 0x85(ControlDTCSetting)와 같은 UDS 서비스를 통해 표준화된 방식으로 제어기와 상호작용하며, 이때 DM은 지원되는 하위 기능 및 메모리 영역에 대한 특정 제한사항을 정의합니다 AUTOSAR AP SWS Diagnostics §4.1 “Limitations of sub-functions of 0x19 ReadDTCInformation”. 애플리케이션은 ara::diag::DTCInformation을(를) 사용하여 DTC 상태를 조회하고, 상태 변경 시 알림을 수신하며, 제어 상태를 확인하고, 필요한 경우 결함 메모리 항목을 선택적으로 삭제합니다 [SWS_DM_00666] [SWS_DM_00671] [SWS_DM_00672].

컨텍스트 다이어그램: 전체 진단 시스템에서 ara::diag::DTCInformation 클래스의 상호작용 관계. 출처: [SWS_DM_00664], [SWS_DM_00672], AUTOSAR AP SWS Diagnostics §4.1 “Limitations of sub-functions of 0x19 ReadDTCInformation”.

수명 주기

ara::diag::DTCInformation의 인스턴스화는 DiagnosticDTCInformationInterface의 모델링된 PortPrototype을(를) 참조해야 하는 ara::core::InstanceSpecifier의 전달을 통해 명시적으로 수행됩니다 [SWS_DM_00664]. 생성자는 thread-safe이자 예외 안전(noexcept)으로 명세되어 있습니다 [SWS_DM_00664].

소유권 관계 측면에서 이 클래스는 엄격한 단일 객체로 설계되었습니다. 복사 생성자와 이동 생성자 및 해당 대입 연산자는 모두 삭제되었습니다(=delete) [SWS_DM_01611] [SWS_DM_01612] [SWS_DM_01613] [SWS_DM_01614]. 따라서 인스턴스는 복사되거나 이동될 수 없으며, 전체 수명 주기 동안 원래 생성된 위치에 유지됩니다.

소멸은 소멸자 ~DTCInformation() [SWS_DM_00665]을(를) 통해 수행됩니다. 소멸자는 not thread-safe(으)로 분류되므로, 해체 과정 중에 동일한 인스턴스에 대한 병행 액세스가 발생하지 않도록 보장해야 합니다. 동시성 모델은 읽기 메서드와 수정 메서드를 명확하게 구분합니다. GetCurrentStatus [SWS_DM_00666], GetControlDTCStatus [SWS_DM_00672], GetNumberOfStoredEntries [SWS_DM_00669] 및 GetEventMemoryOverflow [SWS_DM_00919]과(와) 같은 순수 조회 메서드는 thread-safe입니다. 오류 시나리오

오류 조건은 정적 구성 및 인스턴스화 위반과 ara::diag::DiagErrc을 통한 동적 런타임 오류로 나뉩니다:

생성자를 통한 인스턴스 생성 시 다음과 같은 위반이 발생할 수 있습니다 [SWS_DM_00664]:

  • InstanceSpecifierMappingIntegrityViolation: InstanceSpecifier이(가) 실행 모델에서 확인되지 않거나 PortPrototype을(를) 참조하지 않습니다.
  • PortInterfaceMappingViolation: 참조된 PortPrototype이(가) DiagnosticDTCInformationInterface(으)로 형식화되지 않았습니다.
  • ProcessMappingViolation: 런타임에 해당 참조에 대해 일치하는 모델링된 프로세스가 존재하지 않습니다.
  • InstanceSpecifierAlreadyInUseViolation: 이 프로세스 내에서 InstanceSpecifier이(가) 기존 인스턴스에 의해 이미 사용 중입니다.

정상 작동 중에는 비동기 메서드(ara::core::Future을(를) 통해)와 동기 호출(ara::core::Result을(를) 통해)이 특정 오류 코드를 반환합니다:

  • DiagErrc::kServiceNotAvailable: Diagnostic Management의 기본 기능을 일시적 또는 영구적으로 사용할 수 없습니다. GetCurrentStatus [SWS_DM_00666], GetNumberOfStoredEntries [SWS_DM_00669], Clear [SWS_DM_00671], GetControlDTCStatus [SWS_DM_00672] 및 GetEventMemoryOverflow [SWS_DM_00919] 등에 영향을 미칩니다.
  • DiagErrc::kNoSuchDTC: 요청된 진단 이벤트에 대해 메모리 타깃 내 할당된 DTC가 존재하지 않는 경우 GetCurrentStatus에서 발생합니다 [SWS_DM_00666].
  • DiagErrc::kBusy: 인터페이스가 현재 다른 작업으로 바쁩니다(예: 동시에 요청된 Clear [SWS_DM_00671]의 경우).
  • DiagErrc::kWrongDtc: 유효하지 않은 DTC 식별 번호가 Clear에 전달되었습니다 [SWS_DM_00671].
  • DiagErrc::kMemoryError 또는 DiagErrc::kFailed: 롤백 시맨틱을 동반한 삭제 프로세스 중의 하드웨어 또는 내부 메모리 오류 및 일반적인 처리 중단 [SWS_DM_00671].
  • DiagErrc::kInvalidArgument: 잘못된 매개변수가 전달된 경우 SetSnapshotRecordUpdatedNotifier [SWS_DM_00668], SetNumberOfStoredEntriesNotifier [SWS_DM_00670], SetControlDtcStatusNotifier [SWS_DM_00673] 또는 SetEventMemoryOverflowNotifier [SWS_DM_00918]과(와) 같은 알림자 등록 메서드에서 반환됩니다.

<h4>컨텍스트</h4>
<p><code>ara::diag::DTCInformation</code> 클래스는 AUTOSAR Adaptive(모듈 <code>diag</code>)에서 구성된 진단 메모리 타깃(<code>DiagnosticMemoryDestination</code>)과 관련된 DTC(Diagnostic Trouble Code) 정보에 대한 작업 및 상태 조회를 수행하기 위한 기능적 인터페이스를 제공합니다 <a class="spec-record-ref" data-req="SWS_DM_00664" href="../spec/record.html?id=SWS_DM_00664">[SWS_DM_00664]</a>. 이는 애플리케이션별 진단 및 모니터링 로직과 기반 Diagnostic Management(DM) 간의 연결 고리 역할을 합니다.</p>

<h4>수명 주기</h4>
<p><code>ara::diag::DTCInformation</code>의 인스턴스화는 <code>DiagnosticDTCInformationInterface</code>의 모델링된 <code>PortPrototype</code>을(를) 참조해야 하는 <code>ara::core::InstanceSpecifier</code>의 전달을 통해 명시적으로 수행됩니다 <a class="spec-record-ref" data-req="SWS_DM_00664" href="../spec/record.html?id=SWS_DM_00664">[SWS_DM_00664]</a>. 생성자는 <code>thread-safe</code>이자 예외 안전(<code>noexcept</code>)으로 명세되어 있습니다 <a class="spec-record-ref" data-req="SWS_DM_00664" href="../spec/record.html?id=SWS_DM_00664">[SWS_DM_00664]</a>.</p>
<p>소유권 관계 측면에서 이 클래스는 엄격한 단일 객체로 설계되었습니다. 복사 생성자와 이동 생성자 및 해당 대입 연산자는 모두 삭제되었습니다(<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01611" href="../spec/record.html?id=SWS_DM_01611">[SWS_DM_01611]</a> <a class="spec-record-ref" data-req="SWS_DM_01612" href="../spec/record.html?id=SWS_DM_01612">[SWS_DM_01612]</a> <a class="spec-record-ref" data-req="SWS_DM_01613" href="../spec/record.html?id=SWS_DM_01613">[SWS_DM_01613]</a> <a class="spec-record-ref" data-req="SWS_DM_01614" href="../spec/record.html?id=SWS_DM_01614">[SWS_DM_01614]</a>. 따라서 인스턴스는 복사되거나 이동될 수 없으며, 전체 수명 주기 동안 원래 생성된 위치에 유지됩니다.</p>
<p>소멸은 소멸자 <code>~DTCInformation()</code> <a class="spec-record-ref" data-req="SWS_DM_00665" href="../spec/record.html?id=SWS_DM_00665">[SWS_DM_00665]</a>을(를) 통해 수행됩니다. 소멸자는 <code>not thread-safe</code>(으)로 분류되므로, 해체 과정 중에 동일한 인스턴스에 대한 병행 액세스가 발생하지 않도록 보장해야 합니다. 동시성 모델은 읽기 메서드와 수정 메서드를 명확하게 구분합니다. <code>GetCurrentStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00666" href="../spec/record.html?id=SWS_DM_00666">[SWS_DM_00666]</a>, <code>GetControlDTCStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00672" href="../spec/record.html?id=SWS_DM_00672">[SWS_DM_00672]</a>, <code>GetNumberOfStoredEntries</code> <a class="spec-record-ref" data-req="SWS_DM_00669" href="../spec/record.html?id=SWS_DM_00669">[SWS_DM_00669]</a> 및 <code>GetEventMemoryOverflow</code> <a class="spec-record-ref" data-req="SWS_DM_00919" href="../spec/record.html?id=SWS_DM_00919">[SWS_DM_00919]</a>과(와) 같은 순수 조회 메서드는 <code>thread-safe</code>입니다. <code>Clear</code> <a class="spec-record-ref" data-req="SWS_DM_00671" href="../spec/record.html?id=SWS_DM_00671">[SWS_DM_00671]</a> 및 <code>EnableControlDtc</code> <a class="spec-record-ref" data-req="SWS_DM_00674" href="../spec/record.html?id=SWS_DM_00674">[SWS_DM_00674]</a>와(과) 같은 수정 작업 및 모든 알림자 콜백 등록은 <code>not thread-safe</code>이며 공유 액세스 시 외부 동기화가 필요합니다.</p>
