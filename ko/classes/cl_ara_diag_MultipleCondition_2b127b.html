컨텍스트

ara::diag::MultipleCondition 클래스([SWS_DM_01730])는 AUTOSAR Adaptive Platform의 diag 모듈에서 여러 진단 조건(Diagnostic Conditions)을 관리하기 위한 번들형 인터페이스를 제공한다. 개별 조건은 일반적으로 ara::diag::Condition 클래스를 통해 매핑되는 반면, ara::diag::MultipleCondition은 공통 포트 인터페이스(AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”)를 통해 여러 조건을 제어하고 조회할 수 있게 해준다.

기능적으로 두 인터페이스는 동일한 시맨틱을 가지며 유사한 연산을 제공한다(AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”). 주된 차이점은 ara::diag::MultipleCondition의 경우 각 연산이 ConditionHandleType 유형의 추가 식별자를 받는다는 것이다([SWS_DM_01728], [SWS_DM_01729]).

이 클래스의 주요 상호작용 파트너는 다음과 같다:

  • Adaptive Application: 클래스를 인스턴스화하고 SetCondition을 사용하여 할당된 조건의 상태를 제어하거나 GetCondition을 통해 이를 읽어온다([SWS_DM_01728], [SWS_DM_01729]).
  • Diagnostic Management (DM): 플랫폼 서브시스템으로 동작하며, 상태 변경을 처리하고 진단 시퀀스를 위한 조건 정보를 제공한다([SWS_DM_01728]).
  • 매니페스트 모델링: 시스템에 정의된 각 DiagnosticCondition은 이 조건에 대해 다중 조건 인터페이스를 사용할 수 있도록 지정하기 위해 DiagnosticMultipleConditionPortMapping을 통한 매핑이 필요하다(AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”). 이때 할당된 PortPrototype은 반드시 DiagnosticMultipleConditionInterface로 유형이 지정되어야 한다([SWS_DM_01727]).

컨텍스트 다이어그램: ara::diag::MultipleCondition의 임베딩 및 애플리케이션, 모델링, Diagnostic Management와의 상호작용. 출처: [SWS_DM_01727], [SWS_DM_01730], AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”

수명 주기

인스턴스 생성은 명시적 생성자 MultipleCondition(const ara::core::InstanceSpecifier &specifier)([SWS_DM_01727])을 통해 이루어진다. 인스턴스화 시 객체는 InstanceSpecifier에서 참조하는 PortPrototype에 바인딩된다. 생성자는 예외 안전(exception safe) 및 스레드 안전(thread-safe)으로 명세되어 있다([SWS_DM_01727]).

소유권 및 이동성 측면에서, 이 클래스는 생성된 위치에 엄격히 바인딩된다:

  • 복사 생성자는 삭제되었다: MultipleCondition(MultipleCondition &) = delete ([SWS_DM_02072]).
  • 복사 대입 연산자는 삭제되었다: operator=(MultipleCondition &) = delete ([SWS_DM_02073]).
  • 이동 생성자는 삭제되었다: MultipleCondition(MultipleCondition &&) noexcept = delete ([SWS_DM_02071]).
  • 이동 대입 연산자는 삭제되었다: operator=(MultipleCondition &&) = delete ([SWS_DM_02074]).

따라서 ara::diag::MultipleCondition의 인스턴스는 복사하거나 이동할 수 없다(pinned object). 전체 사용 기간 동안 고정된 메모리 주소에 유지되어야 한다.

소멸은 소멸자 ~MultipleCondition() noexcept([SWS_DM_01737])을 통해 이루어진다. 이는 예외 안전하지만, 명시적으로 not thread-safe로 선언되어 있다([SWS_DM_01737]). 따라서 호출하는 애플리케이션은 소멸 과정 중에 객체에 대한 동시 접근이 발생하지 않도록 보장해야 한다.

실행 중인 연산(GetCondition 및 SetCondition)의 스레드 안전성에 대해서는 조건부 동기화(conditional thread-safety)가 적용된다. 메서드가 스레드 안전하게 구현되어야 하는지 아니면 스레드 안전하지 않게 구현되어야 하는지는 ConcurrencyType에 의해 결정된다([SWS_DM_01728], [SWS_DM_01729]). 해석: [SWS_DM_01727]의 C++ 생성자에는 ConcurrencyType 인수가 없으므로, 이 특성은 소프트웨어 설계에서 포트 모델을 통해 구성되고 InstanceSpecifier을 통해 평가될 것으로 추정된다.

사용 경로

ara::diag::MultipleCondition 사용의 일반적인 절차는 인스턴스화, 개별 조건 식별, 그리고 쓰기 및 읽기 연산 실행 단계로 나뉜다:

  1. 인스턴스화 및 포트 바인딩: 애플리케이션은 적절한 InstanceSpecifier을 지정하여 MultipleCondition을 인스턴스화한다([SWS_DM_01727]).
  2. 핸들을 통한 조건 주소 지정: 개별 조건은 ConditionHandleType 유형의 숫자 값을 통해 주소 지정된다([SWS_DM_01735]). 모델에 DiagnosticMultipleConditionPortMapping.overrideId이 저장되어 있지 않은 경우, Diagnostic Manager는 0x010000부터 시작하여 DiagnosticCondition 짧은 이름의 알파벳순으로 핸들을 할당한다(AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”).
  3. 상태 설정(SetCondition): 애플리케이션은 SetCondition(conditionHandle, condition)([SWS_DM_01729])을 통해 조건 상태를 동기적으로 업데이트한다. 이 호출은 성공 또는 실패를 알리는 ara::core::Result<void>을 반환한다.
  4. 상태 조회(GetCondition): 현재 상태를 읽어오기 위해 애플리케이션은 GetCondition(conditionHandle)을 호출한다([SWS_DM_01728]). 이 호출은 ara::core::Future<ConditionType>을 반환한다. 그런 다음 애플리케이션은 결과를 비동기적으로 확인하고 평가할 수 있다.

시퀀스 다이어그램: ara::diag::MultipleCondition을 사용한 조건 관리 및 조회의 전형적인 호출 순서. 출처: [SWS_DM_01727], [SWS_DM_01728], [SWS_DM_01729], AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”

오류 시나리오

ara::diag::MultipleCondition 작업 시 발생하는 오류 사례는 인스턴스화 중의 구성 및 모델링 위반과 메서드 호출 시의 런타임 오류로 나뉩니다:

  • 초기화 오류(Violations) ([SWS_DM_01727]):
    • InstanceSpecifierMappingIntegrityViolation: InstanceSpecifier을(를) Executable의 모델 컨텍스트에서 확인할 수 없거나, PortPrototype이(가) 아닌 모델 요소를 참조합니다.
    • PortInterfaceMappingViolation: 참조된 PortPrototype이(가) DiagnosticMultipleConditionInterface에 의해 형식에 맞게 타입 지정되지 않았습니다.
    • ProcessMappingViolation: 모델에 일치하는 InstanceRef이(가) 존재하지만, 현재 런타임 프로세스에 일치하는 모델링된 프로세스가 존재하지 않습니다.
    • InstanceSpecifierAlreadyInUseViolation: 현재 프로세스 내에서 이미 다른 인스턴스에 의해 점유된 InstanceSpecifier(으)로 생성자가 호출되었습니다.
  • SetCondition 호출 시 런타임 오류 ([SWS_DM_01729]):
    • DiagErrc::kInvalidArgument: 유효하지 않은 인수를 나타냅니다(롤백 시맨틱, 예: 내부 디바운싱이 있는 kPreFailed의 경우).
  • GetCondition 호출 시 런타임 오류 ([SWS_DM_01728]):
    • DiagErrc::kInvalidArgument: 지정된 conditionHandle이(가) 유효하지 않습니다(롤백 시맨틱).
    • DiagErrc::kServiceNotAvailable: Diagnostic Management의 필수 기능이 현재 제공되지 않으므로 호출을 실행할 수 없습니다(롤백 시맨틱).

이 클래스 가이드는 AUTOSAR Adaptive Platform R25-11 사양(diag 모듈)을 기반으로 하며, ara::diag::MultipleCondition에 대한 요구사항을 요약합니다.

<h4>컨텍스트</h4>
<p><code>ara::diag::MultipleCondition</code> 클래스(<a class="spec-record-ref" data-req="SWS_DM_01730" href="../spec/record.html?id=SWS_DM_01730">[SWS_DM_01730]</a>)는 AUTOSAR Adaptive Platform의 <em>diag</em> 모듈에서 여러 진단 조건(Diagnostic Conditions)을 관리하기 위한 번들형 인터페이스를 제공한다. 개별 조건은 일반적으로 <code>ara::diag::Condition</code> 클래스를 통해 매핑되는 반면, <code>ara::diag::MultipleCondition</code>은 공통 포트 인터페이스(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>)를 통해 여러 조건을 제어하고 조회할 수 있게 해준다.</p>
<p>기능적으로 두 인터페이스는 동일한 시맨틱을 가지며 유사한 연산을 제공한다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>). 주된 차이점은 <code>ara::diag::MultipleCondition</code>의 경우 각 연산이 <code>ConditionHandleType</code> 유형의 추가 식별자를 받는다는 것이다(<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>).</p>
<p>이 클래스의 주요 상호작용 파트너는 다음과 같다:</p>
<ul>
<li><strong>Adaptive Application</strong>: 클래스를 인스턴스화하고 <code>SetCondition</code>을 사용하여 할당된 조건의 상태를 제어하거나 <code>GetCondition</code>을 통해 이를 읽어온다(<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>).</li>
<li><strong>Diagnostic Management (DM)</strong>: 플랫폼 서브시스템으로 동작하며, 상태 변경을 처리하고 진단 시퀀스를 위한 조건 정보를 제공한다(<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>).</li>
<li><strong>매니페스트 모델링</strong>: 시스템에 정의된 각 <code>DiagnosticCondition</code>은 이 조건에 대해 다중 조건 인터페이스를 사용할 수 있도록 지정하기 위해 <code>DiagnosticMultipleConditionPortMapping</code>을 통한 매핑이 필요하다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>). 이때 할당된 <code>PortPrototype</code>은 반드시 <code>DiagnosticMultipleConditionInterface</code>로 유형이 지정되어야 한다(<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>).</li>
</ul>

<li>복사 대입 연산자는 삭제되었다: <code>operator=(MultipleCondition &amp;) = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02073" href="../spec/record.html?id=SWS_DM_02073">[SWS_DM_02073]</a>).</li>
<li>이동 생성자는 삭제되었다: <code>MultipleCondition(MultipleCondition &amp;&amp;) noexcept = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02071" href="../spec/record.html?id=SWS_DM_02071">[SWS_DM_02071]</a>).</li>
<li>이동 대입 연산자는 삭제되었다: <code>operator=(MultipleCondition &amp;&amp;) = delete</code> (<a class="spec-record-ref" data-req="SWS_DM_02074" href="../spec/record.html?id=SWS_DM_02074">[SWS_DM_02074]</a>).</li>
</ul>
<p>따라서 <code>ara::diag::MultipleCondition</code>의 인스턴스는 복사하거나 이동할 수 없다(<em>pinned object</em>). 전체 사용 기간 동안 고정된 메모리 주소에 유지되어야 한다.</p>
<p>소멸은 소멸자 <code>~MultipleCondition() noexcept</code>(<a class="spec-record-ref" data-req="SWS_DM_01737" href="../spec/record.html?id=SWS_DM_01737">[SWS_DM_01737]</a>)을 통해 이루어진다. 이는 예외 안전하지만, 명시적으로 <em>not thread-safe</em>로 선언되어 있다(<a class="spec-record-ref" data-req="SWS_DM_01737" href="../spec/record.html?id=SWS_DM_01737">[SWS_DM_01737]</a>). 따라서 호출하는 애플리케이션은 소멸 과정 중에 객체에 대한 동시 접근이 발생하지 않도록 보장해야 한다.</p>
<p>실행 중인 연산(<code>GetCondition</code> 및 <code>SetCondition</code>)의 스레드 안전성에 대해서는 조건부 동기화(<em>conditional thread-safety</em>)가 적용된다. 메서드가 스레드 안전하게 구현되어야 하는지 아니면 스레드 안전하지 않게 구현되어야 하는지는 <code>ConcurrencyType</code>에 의해 결정된다(<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>, <a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>). 해석: <a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>의 C++ 생성자에는 <code>ConcurrencyType</code> 인수가 없으므로, 이 특성은 소프트웨어 설계에서 포트 모델을 통해 구성되고 <code>InstanceSpecifier</code>을 통해 평가될 것으로 추정된다.</p>

<h4>사용 경로</h4>
<p><code>ara::diag::MultipleCondition</code> 사용의 일반적인 절차는 인스턴스화, 개별 조건 식별, 그리고 쓰기 및 읽기 연산 실행 단계로 나뉜다:</p>
<ol>
<li><strong>인스턴스화 및 포트 바인딩</strong>: 애플리케이션은 적절한 <code>InstanceSpecifier</code>을 지정하여 <code>MultipleCondition</code>을 인스턴스화한다(<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>).</li>
<li><strong>핸들을 통한 조건 주소 지정</strong>: 개별 조건은 <code>ConditionHandleType</code> 유형의 숫자 값을 통해 주소 지정된다(<a class="spec-record-ref" data-req="SWS_DM_01735" href="../spec/record.html?id=SWS_DM_01735">[SWS_DM_01735]</a>). 모델에 <code>DiagnosticMultipleConditionPortMapping.overrideId</code>이 저장되어 있지 않은 경우, Diagnostic Manager는 <code>0x010000</code>부터 시작하여 <code>DiagnosticCondition</code> 짧은 이름의 알파벳순으로 핸들을 할당한다(<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=237">AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_01735] “MultipleCondition ConditionHandleType Generation”</a>).</li>
<li><strong>상태 설정(SetCondition)</strong>: 애플리케이션은 <code>SetCondition(conditionHandle, condition)</code>(<a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>)을 통해 조건 상태를 동기적으로 업데이트한다. 이 호출은 성공 또는 실패를 알리는 <code>ara::core::Result&lt;void&gt;</code>을 반환한다.</li>
<li><strong>상태 조회(GetCondition)</strong>: 현재 상태를 읽어오기 위해 애플리케이션은 <code>GetCondition(conditionHandle)</code>을 호출한다(<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>). 이 호출은 <code>ara::core::Future&lt;ConditionType&gt;</code>을 반환한다. 그런 다음 애플리케이션은 결과를 비동기적으로 확인하고 평가할 수 있다.</li>
</ol>

<h4>오류 시나리오</h4>
<p><code>ara::diag::MultipleCondition</code> 작업 시 발생하는 오류 사례는 인스턴스화 중의 구성 및 모델링 위반과 메서드 호출 시의 런타임 오류로 나뉩니다:</p>
<ul>
<li><strong>초기화 오류(Violations)</strong> (<a class="spec-record-ref" data-req="SWS_DM_01727" href="../spec/record.html?id=SWS_DM_01727">[SWS_DM_01727]</a>):
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: <code>InstanceSpecifier</code>을(를) Executable의 모델 컨텍스트에서 확인할 수 없거나, <code>PortPrototype</code>이(가) 아닌 모델 요소를 참조합니다.</li>
<li><code>PortInterfaceMappingViolation</code>: 참조된 <code>PortPrototype</code>이(가) <code>DiagnosticMultipleConditionInterface</code>에 의해 형식에 맞게 타입 지정되지 않았습니다.</li>
<li><code>ProcessMappingViolation</code>: 모델에 일치하는 <code>InstanceRef</code>이(가) 존재하지만, 현재 런타임 프로세스에 일치하는 모델링된 프로세스가 존재하지 않습니다.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: 현재 프로세스 내에서 이미 다른 인스턴스에 의해 점유된 <code>InstanceSpecifier</code>(으)로 생성자가 호출되었습니다.</li>
</ul>
</li>
<li><strong>SetCondition 호출 시 런타임 오류</strong> (<a class="spec-record-ref" data-req="SWS_DM_01729" href="../spec/record.html?id=SWS_DM_01729">[SWS_DM_01729]</a>):
<ul>
<li><code>DiagErrc::kInvalidArgument</code>: 유효하지 않은 인수를 나타냅니다(롤백 시맨틱, 예: 내부 디바운싱이 있는 <code>kPreFailed</code>의 경우).</li>
</ul>
</li>
<li><strong>GetCondition 호출 시 런타임 오류</strong> (<a class="spec-record-ref" data-req="SWS_DM_01728" href="../spec/record.html?id=SWS_DM_01728">[SWS_DM_01728]</a>):
<ul>
<li><code>DiagErrc::kInvalidArgument</code>: 지정된 <code>conditionHandle</code>이(가) 유효하지 않습니다(롤백 시맨틱).</li>
<li><code>DiagErrc::kServiceNotAvailable</code>: Diagnostic Management의 필수 기능이 현재 제공되지 않으므로 호출을 실행할 수 없습니다(롤백 시맨틱).</li>
</ul>
</li>
</ul>
