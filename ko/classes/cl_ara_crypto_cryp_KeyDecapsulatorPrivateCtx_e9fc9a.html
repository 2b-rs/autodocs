컨텍스트

ara::crypto::cryp::KeyDecapsulatorPrivateCtx 인터페이스는 개인 키를 기반으로 하는 비대칭 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)을 위한 암호화 컨텍스트를 정의합니다. CryptoContext의 특수화로서 비대칭으로 캡슐화된 키 구성 요소를 복구하고 이를 대칭 키 객체로 제공하는 연산을 제공합니다.

상호작용에는 주로 세 가지 역할이 관여합니다: 호출 애플리케이션, KEM 컨텍스트, 그리고 [SWS_CRYPT_21413]에 따른 개인 키(PrivateKey) 또는 [SWS_CRYPT_50083]에 따른 키 슬롯(KeySlot) 형태의 키 소스입니다. 역캡슐화의 결과는 새로운 대칭 키(SymmetricKey) 형태로 인스턴스화되어 캡슐화된 상태로 호출자에게 전달됩니다 [SWS_CRYPT_21412]. 컨텍스트 인스턴스의 수명 주기 및 전달을 위해 사양에서는 스마트 포인터 타입 별칭 Sptr을(를) 정의합니다 [SWS_CRYPT_21401].

수명 주기

KeyDecapsulatorPrivateCtx의 인스턴스는 일반적으로 암호화 스택의 담당 드라이버 또는 팩토리 컴포넌트를 통해 생성됩니다(해석: 인터페이스 자체가 순수 인터페이스로서 공개 생성자를 지정하지 않으므로, 객체 생성은 프로바이더에 따라 달라집니다). 참조 및 수명 관리는 KeyDecapsulatorPrivateCtx::Sptr [SWS_CRYPT_21401]을(를) 통해 이루어집니다.

이 컨텍스트에는 두 가지 주요 기능 단계가 있습니다:

  • 초기화되지 않음: 인스턴스화 직후에는 컨텍스트에 아직 개인 캡슐화 키가 할당되지 않은 상태입니다. 이 상태에서 Decapsulate 연산을 실행하려는 모든 시도는 실패합니다 [SWS_CRYPT_21412].
  • 키 구성됨(사용 준비 완료): PrivateKey::Sptr [SWS_CRYPT_21413] 또는 KeySlot::Sptr [SWS_CRYPT_50083]을(를) 사용하여 SetKey을(를) 통해 키를 할당하면 컨텍스트가 작동 준비 상태로 전환됩니다. 반복적인 SetKey 호출을 통한 재구성이 가능합니다.

인터페이스의 모든 핵심 연산은 예외 안전(exception safe) 및 동시성 안전(thread-safe)으로 지정되어 있습니다 [SWS_CRYPT_21412], [SWS_CRYPT_21413], [SWS_CRYPT_50083].

상태 다이어그램: KeyDecapsulatorPrivateCtx의 수명 주기 및 상태 전이. 출처: [SWS_CRYPT_21412], [SWS_CRYPT_21413], [SWS_CRYPT_50083].

사용 경로

KEM 키 역캡슐화를 위한 정규 절차는 다음 단계로 구성됩니다:

  1. 키 바인딩: 애플리케이션은 SetKey을(를) 통해 컨텍스트를 구성합니다. 이는 로드된 키(PrivateKey::Sptr)를 직접 전달하거나 [SWS_CRYPT_21413], 저장 공간(KeySlot::Sptr)과 연결함으로써 [SWS_CRYPT_50083] 수행됩니다. 후자는 역캡슐화를 실행 시점에 슬롯에 있는 키에 바인딩합니다.
  2. 역캡슐화: 애플리케이션은 Decapsulate 메서드를 호출합니다 [SWS_CRYPT_21412]. 이때 캡슐화된 키가 포함된 메모리 영역(ReadOnlyMemRegion 형식의 encapsulatedKey), 대상 알고리즘의 식별자(algId) 및 대상 키의 허용된 사용 플래그(allowedUsage)가 전달됩니다.
  3. 키 획득: 성공적으로 변환되면 호출은 새로 생성된 대칭 키 객체(SymmetricKey::Sptr)에 대한 Shared Pointer를 포함하는 ara::core::Result을(를) 반환합니다 [SWS_CRYPT_21412].

시퀀스 다이어그램: KeySlot을 통한 KEM 키 역캡슐화 절차. 출처: [SWS_CRYPT_21412], [SWS_CRYPT_50083].

오류 시나리오

메서드는 오류 신호 전달을 위해 ara::crypto::CryptoErrc의 오류 코드를 롤백 시맨틱과 함께 사용하므로, 오류가 발생한 호출이 이전 상태를 손상시키지 않습니다 [SWS_CRYPT_21412], [SWS_CRYPT_21413], [SWS_CRYPT_50083].

일반적인 오류 상황은 구성 오류와 실행 오류로 나뉩니다:

  • 호환되지 않거나 허용되지 않는 키 객체: 호출자가 SetKey에 이 컨텍스트와 호환되지 않는 객체 또는 호환되지 않는 슬롯을 전달하면 kIncompatibleObject이(가) 보고됩니다 [SWS_CRYPT_21413], [SWS_CRYPT_50083]. 개인 키에 사용 권한 kAllowKeyUnwrapping이(가) 없으면 호출이 kUsageViolation(으)로 실패합니다 [SWS_CRYPT_21413].
  • 지원되지 않는 인터페이스 변형: 구체적인 컨텍스트 구현이 KeySlot만 지원하거나 PrivateKey만 지원하는 경우, SetKey의 다른 오버로드는 kUnsupported 오류를 반환합니다 [SWS_CRYPT_21413], [SWS_CRYPT_50083].
  • Decapsulate를 위한 사전 조건 누락: 호출 전에 컨텍스트가 키로 초기화되지 않은 경우, Decapsulate은(는) UninitializedContext 오류를 반환합니다 [SWS_CRYPT_21412]. 실행 시점에 키를 포함하지 않는 KeySlot이(가) 구성된 경우, kEmptyKeySlot이(가) 보고됩니다 [SWS_CRYPT_21412].
  • 유효하지 않거나 호환되지 않는 매개변수: 잘못 형식화된 encapsulatedKey 필드는 kInvalidArgument(으)로 이어집니다 [SWS_CRYPT_21412]. 전달된 algId이(가) 알 수 없거나 지원되지 않는 경우 kUnknownIdentifier이(가) 반환됩니다 [SWS_CRYPT_21412]. 원하는 allowedUsage 플래그가 대상 알고리즘 ID와 일치하지 않거나 algId이(가) encapsulatedKey의 데이터와 호환되지 않는 경우 kIncompatibleArguments이(가) 보고됩니다 [SWS_CRYPT_21412]. 키 언래핑 권한이 없는 경우 Decapsulate 역시 kUsageViolation 오류를 보고합니다 [SWS_CRYPT_21412].
  • 리소스 충돌: 실행에 필요한 내부 리소스를 일시적으로 사용할 수 없는 경우, Decapsulate은(는) kBusyResource(으)로 실패합니다 [SWS_CRYPT_21412].

<h4>컨텍스트</h4>
<p><code>ara::crypto::cryp::KeyDecapsulatorPrivateCtx</code> 인터페이스는 개인 키를 기반으로 하는 비대칭 캡슐화 메커니즘(Key Encapsulation Mechanism, KEM)을 위한 암호화 컨텍스트를 정의합니다. <code>CryptoContext</code>의 특수화로서 비대칭으로 캡슐화된 키 구성 요소를 복구하고 이를 대칭 키 객체로 제공하는 연산을 제공합니다.</p>
<p>상호작용에는 주로 세 가지 역할이 관여합니다: 호출 애플리케이션, KEM 컨텍스트, 그리고 <a class="spec-record-ref" data-req="SWS_CRYPT_21413" href="../spec/record.html?id=SWS_CRYPT_21413">[SWS_CRYPT_21413]</a>에 따른 개인 키(<code>PrivateKey</code>) 또는 <a class="spec-record-ref" data-req="SWS_CRYPT_50083" href="../spec/record.html?id=SWS_CRYPT_50083">[SWS_CRYPT_50083]</a>에 따른 키 슬롯(<code>KeySlot</code>) 형태의 키 소스입니다. 역캡슐화의 결과는 새로운 대칭 키(<code>SymmetricKey</code>) 형태로 인스턴스화되어 캡슐화된 상태로 호출자에게 전달됩니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21412" href="../spec/record.html?id=SWS_CRYPT_21412">[SWS_CRYPT_21412]</a>. 컨텍스트 인스턴스의 수명 주기 및 전달을 위해 사양에서는 스마트 포인터 타입 별칭 <code>Sptr</code>을(를) 정의합니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21401" href="../spec/record.html?id=SWS_CRYPT_21401">[SWS_CRYPT_21401]</a>.</p>

<h4>수명 주기</h4>
<p><code>KeyDecapsulatorPrivateCtx</code>의 인스턴스는 일반적으로 암호화 스택의 담당 드라이버 또는 팩토리 컴포넌트를 통해 생성됩니다(해석: 인터페이스 자체가 순수 인터페이스로서 공개 생성자를 지정하지 않으므로, 객체 생성은 프로바이더에 따라 달라집니다). 참조 및 수명 관리는 <code>KeyDecapsulatorPrivateCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21401" href="../spec/record.html?id=SWS_CRYPT_21401">[SWS_CRYPT_21401]</a>을(를) 통해 이루어집니다.</p>
<p>이 컨텍스트에는 두 가지 주요 기능 단계가 있습니다:</p>
<ul>
<li><strong>초기화되지 않음:</strong> 인스턴스화 직후에는 컨텍스트에 아직 개인 캡슐화 키가 할당되지 않은 상태입니다. 이 상태에서 <code>Decapsulate</code> 연산을 실행하려는 모든 시도는 실패합니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21412" href="../spec/record.html?id=SWS_CRYPT_21412">[SWS_CRYPT_21412]</a>.</li>
<li><strong>키 구성됨(사용 준비 완료):</strong> <code>PrivateKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21413" href="../spec/record.html?id=SWS_CRYPT_21413">[SWS_CRYPT_21413]</a> 또는 <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50083" href="../spec/record.html?id=SWS_CRYPT_50083">[SWS_CRYPT_50083]</a>을(를) 사용하여 <code>SetKey</code>을(를) 통해 키를 할당하면 컨텍스트가 작동 준비 상태로 전환됩니다. 반복적인 <code>SetKey</code> 호출을 통한 재구성이 가능합니다.</li>
</ul>
<p>인터페이스의 모든 핵심 연산은 예외 안전(exception safe) 및 동시성 안전(thread-safe)으로 지정되어 있습니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21412" href="../spec/record.html?id=SWS_CRYPT_21412">[SWS_CRYPT_21412]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_21413" href="../spec/record.html?id=SWS_CRYPT_21413">[SWS_CRYPT_21413]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50083" href="../spec/record.html?id=SWS_CRYPT_50083">[SWS_CRYPT_50083]</a>.</p>

<h4>사용 경로</h4>
<p>KEM 키 역캡슐화를 위한 정규 절차는 다음 단계로 구성됩니다:</p>
<ol>
<li><strong>키 바인딩:</strong> 애플리케이션은 <code>SetKey</code>을(를) 통해 컨텍스트를 구성합니다. 이는 로드된 키(<code>PrivateKey::Sptr</code>)를 직접 전달하거나 <a class="spec-record-ref" data-req="SWS_CRYPT_21413" href="../spec/record.html?id=SWS_CRYPT_21413">[SWS_CRYPT_21413]</a>, 저장 공간(<code>KeySlot::Sptr</code>)과 연결함으로써 <a class="spec-record-ref" data-req="SWS_CRYPT_50083" href="../spec/record.html?id=SWS_CRYPT_50083">[SWS_CRYPT_50083]</a> 수행됩니다. 후자는 역캡슐화를 실행 시점에 슬롯에 있는 키에 바인딩합니다.</li>
<li><strong>역캡슐화:</strong> 애플리케이션은 <code>Decapsulate</code> 메서드를 호출합니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21412" href="../spec/record.html?id=SWS_CRYPT_21412">[SWS_CRYPT_21412]</a>. 이때 캡슐화된 키가 포함된 메모리 영역(<code>ReadOnlyMemRegion</code> 형식의 <code>encapsulatedKey</code>), 대상 알고리즘의 식별자(<code>algId</code>) 및 대상 키의 허용된 사용 플래그(<code>allowedUsage</code>)가 전달됩니다.</li>
<li><strong>키 획득:</strong> 성공적으로 변환되면 호출은 새로 생성된 대칭 키 객체(<code>SymmetricKey::Sptr</code>)에 대한 Shared Pointer를 포함하는 <code>ara::core::Result</code>을(를) 반환합니다 <a class="spec-record-ref" data-req="SWS_CRYPT_21412" href="../spec/record.html?id=SWS_CRYPT_21412">[SWS_CRYPT_21412]</a>.</li>
</ol>
