컨텍스트

ara::core::InstanceSpecifier 클래스는 AUTOSAR Adaptive Platform에서 모델 요소를 식별하기 위한 AUTOSAR ShortName 경로(메타모델 경로)의 타입 안전 캡슐화 역할을 합니다. 전체 시스템 내에서 소프트웨어 컴포넌트, 통신 포트 및 서비스 인스턴스를 고유하게 참조하고 확인할 수 있는 표준화된 식별자로 작동합니다.

다른 컴포넌트와의 상호 작용에서 ara::core::InstanceSpecifier은(는) 주로 다음과 같은 인터페이스를 통해 상호 작용합니다:

  • 문자열 뷰: 경로 지정은 ara::core::StringView(으)로 전달되며 필요에 따라 ToString() 메서드를 통해 다시 이와 같은 형태로 제공됩니다 [SWS_CORE_08041].
  • 결과 및 오류 처리: 정적 팩토리 메서드는 유효한 인스턴스를 반환하거나 유효성 검사 오류를 알리기 위해 ara::core::Result을(를) 사용합니다 [SWS_CORE_08032]. 반면에 오류 기반 생성 경로에서는 ara::core::CoreException이(가) 발생합니다 [SWS_CORE_08021].
  • 컨테이너 및 메타모델: 엄격한 순서 연산자 operator<을(를) 제공함으로써 이 클래스는 모델 요소 식별자를 관리하기 위해 정렬된 컨테이너(예: 연관 맵)의 키로 사용할 수 있습니다 [SWS_CORE_08046]. 또한 비교 연산자를 통해 다른 인스턴스 및 원시 경로 문자열과의 직접 비교가 가능합니다 [SWS_CORE_08042], [SWS_CORE_08043], [SWS_CORE_08044], [SWS_CORE_08045].

수명 주기

ara::core::InstanceSpecifier의 인스턴스 생성은 두 가지 서로 다른 방식으로 수행할 수 있습니다:

  1. 팩토리 메서드 Create: 정적 메서드 Create은(는) ara::core::StringView을(를) 전달받아 경로 구조의 구문 규칙을 검증합니다 [SWS_CORE_08032]. 이 메서드는 예외 안전(noexcept)하고 스레드 안전(thread-safe)하며, 성공 시 완성된 인스턴스를 캡슐화하거나 실패 시 해당 오류 코드를 캡슐화하는 ara::core::Result<InstanceSpecifier>을(를) 반환합니다.
  2. 직접 생성: 명시적 생성자 역시 ara::core::StringView을(를) 전달받지만 noexcept(false)(으)로 명세되어 있으며 ara::core::CoreException 유형의 예외를 발생시켜 유효성 검사 오류를 알립니다 [SWS_CORE_08021]. 이 생성자는 스레드에 안전합니다.

값 시맨틱을 위해 클래스는 표준화된 생성자 및 대입 연산자를 제공합니다:

  • 복사: 복사 생성자 [SWS_CORE_08022]은(는) noexcept(으)로 선언되어 있으며 스레드에 안전합니다. 복사 대입 연산자 [SWS_CORE_08024] 역시 noexcept이지만 스레드에 안전하지 않습니다.
  • 이동: 이동 생성자 [SWS_CORE_08023] 및 이동 대입 연산자 [SWS_CORE_08025]은(는) noexcept이지만 스레드에 안전하지 않습니다.
  • 소멸: 소멸자 ~InstanceSpecifier() [SWS_CORE_08029]은(는) noexcept이며 스레드에 안전하지 않습니다.

소유권 및 수명과 관련하여 중대한 제한 사항이 있습니다: ToString()에서 반환된 ara::core::StringView의 수명은 원래 생성자 또는 생성 메서드에 ara::core::StringView(으)로 전달되었던 기본 문자열의 수명 동안에만 보장됩니다 [SWS_CORE_08041]. 해석: 이 요구사항에 따르면 ara::core::InstanceSpecifier은(는) 문자열의 독립적인 딥 카피(deep copy)를 생성하지 않고, 내부적으로 원래 버퍼에 대한 뷰나 참조만을 유지할 것으로 보입니다. 따라서 개발자는 전달된 문자열 객체가 InstanceSpecifier 및 이로부터 파생된 뷰의 전체 사용 기간 동안 메모리에서 유효하게 유지되도록 해야 합니다.

동시성과 관련하여 다음이 적용됩니다: 순수 읽기 연산(ToString(), operator==, operator!=, operator< 및 복사 생성자 포함)은 완전히 스레드 안전합니다. 수정 연산(이동 생성, 대입 연산자 및 소멸)은 스레드 안전하지 않으며 동일한 객체에 대해 보호되지 않은 상태로 동시에 실행되어서는 안 됩니다.

  1. 검증된 인스턴스화: 애플리케이션이 메타모델 경로를 사용하여 ara::core::InstanceSpecifier::Create()을(를) 호출합니다 [SWS_CORE_08032].
  2. 결과 검사: 반환된 ara::core::Result의 오류 여부를 검사합니다. 유효하지 않은 문자나 누락된 경로 요소가 있는 경우 제어 로직이 오류 처리로 분기합니다.
  3. 식별 및 비교: 추출된 인스턴스는 예상 식별자 또는 문자열 뷰와의 비교에 사용됩니다 [SWS_CORE_08042], [SWS_CORE_08043].
  4. 컨테이너에 저장: 필요한 경우 인스턴스는 연관 데이터 구조에 저장되며, 정렬은 사전식 비교 연산자 operator<을(를) 통해 수행됩니다 [SWS_CORE_08046].
  5. 텍스트 출력: 로깅 또는 진단 목적으로 ToString()을(를) 통해 문자열 표현을 조회합니다 [SWS_CORE_08041].

오류 시나리오

ara::core::InstanceSpecifier 생성 시 전달된 이름 경로와 관련된 검증 오류가 발생할 수 있습니다:

  • CoreErrc::kInvalidMetaModelShortname: 이 오류는 qualifiedShortName의 경로 요소 중 하나가 누락되었거나 유효하지 않은 문자를 포함하는 경우 발생합니다 [SWS_CORE_08032], [SWS_CORE_08021].
  • CoreErrc::kInvalidMetaModelPath: 이 오류는 전달된 qualifiedShortName이(가) 모델 요소에 대한 구문론적으로 유효한 경로를 형성하지 않을 때 보고됩니다 [SWS_CORE_08032], [SWS_CORE_08021].

오류 신호 방식은 선택한 인터페이스에 따라 달라집니다:

  • 팩토리 메서드 Create을(를) 사용할 경우 연산은 롤백 의미론으로 실행되며, 반환된 ara::core::Result은(는) 예외를 발생시키지 않고 해당 오류 코드를 포함합니다 [SWS_CORE_08032].
  • 명시적 생성자를 사용할 때 이러한 오류 중 하나가 발생하면 일치하는 CoreErrc 오류 코드를 전달하는 ara::core::CoreException 유형의 예외가 발생합니다 [SWS_CORE_08021].

오류 없는 인스턴스화를 위한 사전 조건으로 입력 문자열은 항상 경로 요소 및 메타모델 경로에 대해 지정된 구문 규칙을 충족해야 합니다 [SWS_CORE_08032], [SWS_CORE_08021]. 반면에 비교 및 접근 연산자는 오류 반환 상태를 가지지 않으며, 성공적인 생성 후에는 오류 없는 평가를 보장합니다 (noexcept).

이 가이드는 릴리스 R25-11의 ara::core::InstanceSpecifier에 대한 AUTOSAR 사양만을 기반으로 합니다.

<h4>컨텍스트</h4>
<p><code>ara::core::InstanceSpecifier</code> 클래스는 AUTOSAR Adaptive Platform에서 모델 요소를 식별하기 위한 AUTOSAR ShortName 경로(메타모델 경로)의 타입 안전 캡슐화 역할을 합니다. 전체 시스템 내에서 소프트웨어 컴포넌트, 통신 포트 및 서비스 인스턴스를 고유하게 참조하고 확인할 수 있는 표준화된 식별자로 작동합니다.</p>
<p>다른 컴포넌트와의 상호 작용에서 <code>ara::core::InstanceSpecifier</code>은(는) 주로 다음과 같은 인터페이스를 통해 상호 작용합니다:</p>
<ul>
<li><strong>문자열 뷰:</strong> 경로 지정은 <code>ara::core::StringView</code>(으)로 전달되며 필요에 따라 <code>ToString()</code> 메서드를 통해 다시 이와 같은 형태로 제공됩니다 <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>.</li>
<li><strong>결과 및 오류 처리:</strong> 정적 팩토리 메서드는 유효한 인스턴스를 반환하거나 유효성 검사 오류를 알리기 위해 <code>ara::core::Result</code>을(를) 사용합니다 <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. 반면에 오류 기반 생성 경로에서는 <code>ara::core::CoreException</code>이(가) 발생합니다 <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>.</li>

<h4>수명 주기</h4>
<p><code>ara::core::InstanceSpecifier</code>의 인스턴스 생성은 두 가지 서로 다른 방식으로 수행할 수 있습니다:</p>
<ol>
<li><strong>팩토리 메서드 <code>Create</code>:</strong> 정적 메서드 <code>Create</code>은(는) <code>ara::core::StringView</code>을(를) 전달받아 경로 구조의 구문 규칙을 검증합니다 <a class="spec-record-ref" data-req="SWS_CORE_08032" href="../spec/record.html?id=SWS_CORE_08032">[SWS_CORE_08032]</a>. 이 메서드는 예외 안전(<code>noexcept</code>)하고 스레드 안전(<code>thread-safe</code>)하며, 성공 시 완성된 인스턴스를 캡슐화하거나 실패 시 해당 오류 코드를 캡슐화하는 <code>ara::core::Result&lt;InstanceSpecifier&gt;</code>을(를) 반환합니다.</li>
<li><strong>직접 생성:</strong> 명시적 생성자 역시 <code>ara::core::StringView</code>을(를) 전달받지만 <code>noexcept(false)</code>(으)로 명세되어 있으며 <code>ara::core::CoreException</code> 유형의 예외를 발생시켜 유효성 검사 오류를 알립니다 <a class="spec-record-ref" data-req="SWS_CORE_08021" href="../spec/record.html?id=SWS_CORE_08021">[SWS_CORE_08021]</a>. 이 생성자는 스레드에 안전합니다.</li>
</ol>
<p>값 시맨틱을 위해 클래스는 표준화된 생성자 및 대입 연산자를 제공합니다:</p>

<li><strong>이동:</strong> 이동 생성자 <a class="spec-record-ref" data-req="SWS_CORE_08023" href="../spec/record.html?id=SWS_CORE_08023">[SWS_CORE_08023]</a> 및 이동 대입 연산자 <a class="spec-record-ref" data-req="SWS_CORE_08025" href="../spec/record.html?id=SWS_CORE_08025">[SWS_CORE_08025]</a>은(는) <code>noexcept</code>이지만 스레드에 안전하지 않습니다.</li>
<li><strong>소멸:</strong> 소멸자 <code>~InstanceSpecifier()</code> <a class="spec-record-ref" data-req="SWS_CORE_08029" href="../spec/record.html?id=SWS_CORE_08029">[SWS_CORE_08029]</a>은(는) <code>noexcept</code>이며 스레드에 안전하지 않습니다.</li>
</ul>
<p>소유권 및 수명과 관련하여 중대한 제한 사항이 있습니다: <code>ToString()</code>에서 반환된 <code>ara::core::StringView</code>의 수명은 원래 생성자 또는 생성 메서드에 <code>ara::core::StringView</code>(으)로 전달되었던 기본 문자열의 수명 동안에만 보장됩니다 <a class="spec-record-ref" data-req="SWS_CORE_08041" href="../spec/record.html?id=SWS_CORE_08041">[SWS_CORE_08041]</a>. 해석: 이 요구사항에 따르면 <code>ara::core::InstanceSpecifier</code>은(는) 문자열의 독립적인 딥 카피(deep copy)를 생성하지 않고, 내부적으로 원래 버퍼에 대한 뷰나 참조만을 유지할 것으로 보입니다. 따라서 개발자는 전달된 문자열 객체가 <code>InstanceSpecifier</code> 및 이로부터 파생된 뷰의 전체 사용 기간 동안 메모리에서 유효하게 유지되도록 해야 합니다.</p>
