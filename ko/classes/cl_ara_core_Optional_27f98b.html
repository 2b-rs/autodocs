사용 목적

ara::core::Optional<T>는 std::optional<T>을 구현하고 기존 값을 모델링한다. 이는 각각 빈 구성 nullopt, 내부 구성, emplace(), reset(), 상태 쿼리 및 값 액세스를 지원한다. [SWS_CORE_01033] [SWS_CORE_01103] [SWS_CORE_01104] [SWS_CORE_01107] [SWS_CORE_01119] [SWS_CORE_01136] [SWS_CORE_01129]

수명주기 & 소유권

복사 및 이동 구성, 할당 및 소멸은 T noexcept 속성에 따라 조건부입니다. [SWS_CORE_01105] [SWS_CORE_01106] [SWS_CORE_01114] [SWS_CORE_01115] [SWS_CORE_01112]

다른 클래스와의 상호작용

사양에서는 특수화 Optional<T&>를 통해 lvalue 참조에 대한 지원이 필요한다. [SWS_CORE_01032]

제한 사항 및 오류 처리

액세스 operator*, operator-> 및 value()는 noexcept이지만 값이 없으면 IsoStdBadOptionalAccessViolation를 트리거할 수 있다. 접속 전 has_value() 또는 bool 변환을 사용할 수 있다. [SWS_CORE_01124] [SWS_CORE_01122] [SWS_CORE_01130] [SWS_CORE_01129] [SWS_CORE_01128]

모델링된 데이터 세트의 선택성

Optional는 단지 일반적인 편의 유형이 아닙니다. Core는 특히 카테고리 STRUCTURE의 StdCppImplementationDataType에 대한 선택적 레코드 요소에 대해 이를 호출합니다. 반면 필수 필드는 구현 데이터 유형과 함께 직접 나타납니다. 또는 Optional를 사용하면 함수에서 누락될 수 있는 반환 값을 표현할 수 있습니다. SWS Core §7.4 “Core data types” SWS Core §7.4.2 “Data types derived from the C++ standard” SWS LanguageBinding §7.1 “C++ binding for CppImplementationDataTypes”

Optional<T&>의 경우 할당은 rebind 동작을 따릅니다. 즉, 참조를 통해 원래 바인딩된 객체에 쓰는 대신 Optional 참조를 새 객체에 바인딩한다. [SWS_CORE_01032] [SWS_CORE_01034]

활동 다이어그램: 엄격한 가치 기반 액세스 전에 직업 상태를 확인합니다. 대안은 value()에 액세스하지 않고 부재를 처리합니다. 출처: SWS Core §7.4.2 “Data types derived from the C++ standard” [SWS_CORE_01129] [SWS_CORE_01130].
