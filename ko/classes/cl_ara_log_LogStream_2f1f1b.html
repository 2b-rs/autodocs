클래스 ara::log::LogStream

[SWS_LOG_00173] Upstream: RS_LT_00003, RS_LT_00046

class LogStream final {...};

Represents a Log message, allowing stream operators to be used for appending data. Note: Normally Application processes would not use this class directly. Instead one of the log methods provided in the main Logging API shall be used. Those methods automatically setup a temporary object of this class with the given log severity level. The only reason to use this class directly is, if the user wants to hold a ara::log::LogStream object longer than the default one-statement scope. This is useful in order to create log messages that are distributed over multiple code lines. See the ara::log::LogStream::Flush method for further information. Once this temporary object gets out of scope, its destructor takes care that the message buffer is ready to be processed by the Logging framework. Besides the existing supported operator<< overloads for ara::log::LogStream it can be easily extended for other derived types by providing a stream operator that makes use of already supported types.

Example: struct MyCustomType { int8_t foo; ara::core::String bar; };

LogStream& operator<<(LogStream& out, const MyCustomType& value) { return (out << value.foo << value.bar); }

// Producing the output "42 the answer is." Logger& ctx0 = CreateLogger("CTX0", "Context Description CTX0"); ctx0.LogDebug () << MyCustomType{42, " the answer is."};

ara::log::LogStream 클래스는 스트림 연산자를 통해 내부 버퍼에 데이터와 메타데이터가 점진적으로 채워지는 포맷 가능한 로그 메시지를 나타냅니다. 인스턴스는 일반적으로 로깅 메서드를 통해 임시로 획득되며, 범위를 벗어날 때 소멸자를 통해 캡처된 콘텐츠를 로깅 프레임워크로 자동 전달합니다 [SWS_LOG_00262]. 여러 줄 메시지이거나 재사용되는 메시지의 경우 Flush()을(를) 통해 명시적으로 전달을 트리거할 수 있습니다 [SWS_LOG_00039]. 핵심 제약 조건으로, 이 클래스는 스레드 안전하지 않으며 복사 작업을 완전히 금지합니다.

컨텍스트

ara::log::LogStream 클래스는 어댑티브 로깅 하위 시스템에서 포맷 가능한 로그 메시지를 나타냅니다. 이 클래스는 오버로드된 스트림 연산자를 통해 이종의 페이로드를 내부 버퍼에 점진적으로 추가할 수 있는 메시지 기반 버퍼 인터페이스를 제공합니다.

일반적인 사용 사례에서 애플리케이션 프로세스는 명시적인 인스턴스화를 통해 LogStream과(와) 직접 상호작용하지 않습니다. 대신 메인 로깅 API(예: LogDebug()과(과) 같은 로깅 메서드를 통해)가 필요한 심각도 수준으로 이미 초기화된 이 클래스의 임시 인스턴스를 제공합니다. 표준 단일 구문 범위(One-Statement-Scope)를 넘어 LogStream 객체를 유지하는 유일하게 의도된 이유는 여러 코드 라인에 걸쳐 로그 메시지를 구성하기 위한 것입니다. 객체가 범위를 벗어나거나 명시적으로 비워지면 버퍼 콘텐츠가 추가 처리를 위해 로깅 프레임워크로 전달됩니다.

컨텍스트 다이어그램: 애플리케이션 프로세스, 로깅 API, LogStream 및 로깅 프레임워크 간의 상호작용. 출처: [SWS_LOG_00039], [SWS_LOG_00262]

수명 주기

LogStream 인스턴스의 생성은 주로 메인 로깅 API의 팩토리 메서드를 통해 임시 객체로 이루어집니다. 효율적인 제공을 위해 클래스는 이동 생성자를 noexcept(으)로 선언합니다 [SWS_LOG_00176]. 이 이동 생성자는 일반적으로 선언만 되고 정의되지 않으므로, C++14 준수 컴파일러가 팩토리 함수에서 반환할 때 RVO(Return Value Optimization)를 활용할 수 있도록 합니다 [SWS_LOG_00176]. 인스턴스의 복제 또는 이동 할당은 엄격히 금지됩니다. 즉, 복사 생성자 [SWS_LOG_00174], 복사 할당 연산자 [SWS_LOG_00175] 및 이동 할당 연산자 [SWS_LOG_00177]은(는) 삭제되어 있습니다(=delete).

수명의 끝은 소멸자 ~LogStream()에 의해 관리됩니다 [SWS_LOG_00262]. 객체가 범위를 벗어나면(예: 함수 블록 또는 구문의 끝에서) 소멸자는 내부적으로 버퍼 콘텐츠가 처리를 위해 로깅 프레임워크로 전달되도록 합니다 [SWS_LOG_00039], [SWS_LOG_00262].

동일한 범위 내에서 여러 연속 메시지에 대해 LogStream 인스턴스를 재사용하는 경우 멤버 함수 Flush()을(를) 호출해야 합니다 [SWS_LOG_00039]. 여기서 중요한 점은 Flush()이(가) 버퍼를 비우는 것이 아니라 현재 데이터를 로깅 프레임워크로 전송하고 즉시 새 메시지 스트림을 시작한다는 것입니다 [SWS_LOG_00039].

동시성과 관련하여 모든 멤버 함수는 스레드 안전하지 않은 것으로 지정되어 있습니다([SWS_LOG_00039], [SWS_LOG_00040], [SWS_LOG_00129]). 따라서 LogStream 인스턴스는 외부 동기화 없이 여러 스레드에서 병렬로 사용되어서는 안 됩니다.

사용 경로

일반적인 로깅 시퀀스는 다음 단계로 구성됩니다:

  1. 스트림 제공: 애플리케이션 프로세스가 임시 LogStream 인스턴스를 생성하고 RVO를 통해 반환하는 로깅 메서드를 호출합니다 [SWS_LOG_00176].
  2. 메타데이터 강화: 데이터 입력 전 또는 도중에 WithLocation(file, line) [SWS_LOG_00129]을(를) 통한 소스 코드 위치, WithTag(tag) [SWS_LOG_00132]을(를) 통한 태그, 또는 WithPrivacy(value) [SWS_LOG_00258]을(를) 통한 기밀성 수준을 포함하여 메서드 체이닝을 통해 선택적 속성을 추가할 수 있습니다. 이러한 각 메서드는 *this에 대한 참조를 반환합니다.
  3. 데이터 채우기: 오버로드된 연산자 operator<<을(를) 통해 페이로드가 내부 버퍼에 기록됩니다. 이 인터페이스는 불리언 값 [SWS_LOG_00040], 다양한 너비의 정수 [SWS_LOG_00041], [SWS_LOG_00044], 부동 소수점 수 [SWS_LOG_00049], 문자열 및 문자열 뷰 [SWS_LOG_00051], [SWS_LOG_00062], core::Span<const core::Byte> [SWS_LOG_00128]을(를) 통한 바이트 시퀀스, Argument<T> [SWS_LOG_00203]을(를) 통한 구조화된 인수와 같은 표준 타입을 지원합니다. 또한 사용자 정의 타입을 위해 연산자를 확장할 수 있습니다.
  4. 프레임워크로 전달: 범위를 벗어날 때 소멸자가 메시지를 전달합니다 [SWS_LOG_00262]. 추가 메시지를 위해 인스턴스를 유지해야 하는 경우 Flush()이(가) 명시적으로 호출됩니다 [SWS_LOG_00039].

시퀀스 다이어그램: 스트림 생성부터 메타데이터 및 데이터 채우기를 거쳐 범위 종료 또는 Flush()를 통한 전송에 이르는 로깅 흐름. 출처: [SWS_LOG_00039], [SWS_LOG_00040], [SWS_LOG_00129], [SWS_LOG_00176], [SWS_LOG_00262]

오류 시나리오

이 클래스는 엄격한 No-Exception 설계를 따릅니다. 스트림 연산자([SWS_LOG_00040]부터 [SWS_LOG_00051], [SWS_LOG_00062], [SWS_LOG_00128], [SWS_LOG_00203]), WithLocation() [SWS_LOG_00129], WithTag() [SWS_LOG_00132], WithPrivacy() [SWS_LOG_00258], Flush() [SWS_LOG_00039] 및 소멸자 [SWS_LOG_00262]을(를) 포함한 모든 멤버 함수는 noexcept(으)로 선언되어 있으며 예외에 안전합니다(“exception safe”).

오류 조건 및 사용 위험은 다음 시나리오로 제한됩니다:

  • WithPrivacy의 타입 오류: 템플릿 WithPrivacy<T>은(는) T이(가) 정수형 또는 열거형 타입일 것을 엄격히 요구합니다. 다른 타입으로 함수가 인스턴스화되면 프로그램이 잘못 구성되어(ill-formed) 컴파일 오류가 발생합니다 [SWS_LOG_00258]. 또한 전달된 값의 최하위 8비트만 사용되며 상위 비트는 무시됩니다 [SWS_LOG_00258].
  • 스레드 안전성 부재: LogStream은(는) 스레드 안전하지 않은 것으로 정의되어 있으므로([SWS_LOG_00039], [SWS_LOG_00040]), 외부 동기화 없이 동일한 인스턴스에 대한 동시 읽기 또는 쓰기 작업은 데이터 불일치 또는 버퍼 손상을 초래할 것으로 추정됩니다(해석).
  • Flush 시 버퍼 전달: Flush()은(는) 버퍼를 물리적으로 비우지 않고 현재 콘텐츠를 로깅 프레임워크로 전달하기만 하므로 [SWS_LOG_00039], 재사용 시 시맨틱상 새 메시지가 시작된다는 점을 고려해야 합니다.
