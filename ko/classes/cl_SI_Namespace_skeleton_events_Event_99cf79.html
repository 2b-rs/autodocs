서비스 제공자가 구독 애플리케이션에 서버 측에서 이벤트를 전송할 수 있도록 합니다.

클래스 <SI-Namespace>::skeleton::events::<Event>은(는) AUTOSAR Adaptive Platform의 서비스 제공자가 구독 애플리케이션에 이벤트 데이터를 발행하는 데 사용됩니다. 이벤트는 복사 기반으로 전송되거나 사전에 Allocate()을(를) 통해 할당된 버퍼를 사용하여 복사 없이 효율적으로 전송될 수 있습니다([SWS_CM_90438]). Send()을(를) 통한 전송 호출은 관련 서비스 인스턴스가 이전에 성공적으로 제공(offered)되었고 구성된 최소 전송 간격이 준수될 것을 반드시 요구합니다([SWS_CM_00162]).

컨텍스트

클래스 <SI-Namespace>::skeleton::events::<Event>은(는) AUTOSAR Adaptive Platform 내에서 서비스 이벤트를 발행하기 위한 서버 측 인터페이스를 나타냅니다. 서비스 애플리케이션(Skeleton)이 SampleType([SWS_CM_11400]) 타입의 업데이트된 이벤트 데이터를 모든 구독 클라이언트 애플리케이션에 비동기식으로 전송할 수 있도록 합니다([SWS_CM_00162]). Skeleton은 서비스 인스턴스의 검색과 이벤트 데이터의 물리적 분배를 담당하는 통신 계층(Communication Management)과 직접 상호작용합니다. 데이터 전송 외에도 Event 인스턴스는 현재 구독 상태를 모니터링하고 구독자 그룹의 변경 사항을 서비스 제공자에게 알립니다([SWS_CM_12008], [SWS_CM_12011]).

컨텍스트 다이어그램: 서비스 제공자, Communication Management 및 구독자와 Event 클래스의 상호작용. 출처: [SWS_CM_00162], [SWS_CM_90437], [SWS_CM_12011]

수명 주기

Event 클래스의 인스턴스화는 상위 Skeleton 서비스 인스턴스와 함께 수행됩니다. Vermutlich Event 인스턴스의 수명 주기는 Skeleton의 수명 주기에 강하게 바인딩되어 있으므로, 이벤트 객체는 서비스가 생성된 후에만 사용 가능해지고 서비스 소멸과 함께 종료됩니다. 활성 데이터 전송 전에 서비스가 제공되어 있어야 하며, 서비스 제공 전에 시도되는 전송은 실패합니다([SWS_CM_00162]).

작동 단계 동안 인스턴스는 구독자 연결 상태를 반영합니다. GetSubscriptionState()을(를) 통해 현재 상태를 쿼리할 수 있습니다([SWS_CM_12011]). 상태 변경에 비동기적으로 반응하기 위해 애플리케이션은 SetSubscriptionStateChangeHandler()을(를) 사용하여 해당 콜백을 등록하며([SWS_CM_12008]), 선택적으로 실행기(Executor) 객체를 통해 특정 실행 컨텍스트에 연결할 수 있습니다([SWS_CM_12009]). 서비스 종료 또는 재구성 시 이 핸들러는 UnsetSubscriptionStateChangeHandler()을(를) 통해 등록 해제될 수 있습니다([SWS_CM_12010]). 모든 상태 쿼리 및 핸들러 메서드는 noexcept(으)로 선언되어 있으며 예외 안전성을 보장합니다([SWS_CM_12008], [SWS_CM_12011]).

사용 경로

이벤트 데이터 발행을 위해 서비스 애플리케이션에는 두 가지 원칙적인 전송 모드가 제공됩니다: 복사 기반 전송과 관리형 메모리를 통한 제로 카피(Zero-Copy) 방식입니다(EXP ara::com API 10쪽).

일반적인 사용 경로에서 서비스 제공자는 필요에 따라 먼저 구독 변경에 대한 콜백을 등록합니다([SWS_CM_12008]). 구독자가 존재하면 애플리케이션은 로컬 데이터를 생성하고 이를 값으로 Send()에 전달하며([SWS_CM_00162]), 이때 Communication Management가 데이터 사본을 생성하여 모든 구독자에게 전달합니다(EXP ara::com API 10쪽).

대안으로, 애플리케이션은 복사 오버헤드를 방지하기 위해 Allocate()을(를) 통해 통신 계층으로부터 ara::com::SampleAllocateePtr<SampleType> 형태의 메모리 버퍼를 직접 요청합니다([SWS_CM_90438], EXP ara::com API 10쪽). 버퍼를 채운 후 이는 Send()의 특수화된 오버로드를 통해 전송됩니다([SWS_CM_90437]). Interpretation: 호출 후 애플리케이션의 데이터에 대한 모든 추가 접근이 명시적으로 금지되므로, 전송과 함께 메모리에 대한 소유권이 Communication Management로 완전히 이전되는 것으로 보입니다([SWS_CM_90437]).

시퀀스 다이어그램: 핸들러 등록 및 할당을 포함한 이벤트 전송의 일반적인 절차. 출처: [SWS_CM_12008], [SWS_CM_90438], [SWS_CM_90437], [SWS_CM_00162]

오류 시나리오

Send() 호출은 오류 발생 시 ara::com::ComErrc 타입의 해당 오류 코드를 포함하는 ara::core::Result<void>을(를) 반환합니다([SWS_CM_00162], [SWS_CM_90437]). 정의된 오류 사례는 다음과 같습니다:

  • ComErrc::kServiceNotOffered: 전송 시도 전에 서비스가 아직 OfferService()을(를) 통해 제공되지 않았습니다([SWS_CM_00162], [SWS_CM_90437]).
  • ComErrc::kMinimumSendIntervalViolationError: 전송 호출이 너무 빠른 연속으로 발행되어 이벤트에 대해 구성된 최소 전송 간격(minimumSendInterval)을 밑돌았습니다([SWS_CM_00162], [SWS_CM_90437]).

또한 할당 및 핸들러 구성 시 사전 조건을 준수해야 합니다:

  • Allocate()은(는) 예외 안전(not exception safe)하지 않으며, 메모리 리소스가 부족할 경우 SampleAllocationViolation을(를) 발생시키고, 사용자 정의 할당자의 허용되지 않는 사용 시 AllocateUsageViolation을(를) 발생시킵니다([SWS_CM_90438]).
  • SetSubscriptionStateChangeHandler()은(는) 유효하고 호출 가능한 함수 객체를 필요로 합니다. 널 값이거나 존재하지 않는 핸들러가 전달되면 InvalidHandlerViolation이(가) 발생합니다([SWS_CM_12008], [SWS_CM_12009]).

이 가이드는 AUTOSAR Adaptive Platform R25-11 사양을 기반으로 합니다.

ara::com::SampleAllocateePtr< SampleType > Allocate ();

Allocating data for event transfer when Communication Management is responsible for the data.

메서드 Allocate은(는) Communication Management(ara::com)가 데이터 관리를 담당할 때 이벤트 데이터 전송을 위한 메모리를 할당하기 위해 이벤트에 대한 Skeleton 레벨에서 호출됩니다 ([SWS_CM_90438]; AUTOSAR_AP_EXP_ARAComAPI §5.4.1 “Skeleton Class API’s”; [SWS_CM_90438]). 이 메서드는 ara::com::SampleAllocateePtr<SampleType> 타입의 인스턴스를 반환합니다 ([SWS_CM_90438]). 이 포인터 타입은 개념적으로 std::unique_ptr<T>처럼 동작하므로 어느 시점에서든 하나의 주체만 포인터를 소유합니다 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”).

오류 처리 및 예외 안전성과 관련하여 Allocate은(는) not exception safe로 명시되어 있습니다 ([SWS_CM_90438]). 사양에는 두 가지 가능한 위반 사항(Violations)이 정의되어 있습니다:

  • SampleAllocationViolation: 데이터를 할당하기에 충분한 메모리 리소스가 없습니다 ([SWS_CM_90438]).
  • AllocateUsageViolation: 사용자 정의 할당자를 통해 잘못 할당되었습니다 ([SWS_CM_90438]).

Allocate 이면의 개념은 주로 판독기와 기록기 간의 엄격한 동기화를 전제로 하는 공유 메모리 기반 IPC 전송을 중심으로 Zero-Copy 메커니즘을 지원하는 것을 목표로 합니다 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”). 구현자는 배포 시 데이터 타입이 바이너리 호환되도록 구성되지 않았거나 감지 로직에 의해 배제되는 경우 직렬화 요구사항으로 인해 Zero-Copy가 무효화될 수 있음을 유의해야 합니다 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”).

이벤트 전송과의 상호 작용에서 Allocate을(를) 통해 얻은 메모리 포인터는 Send(ara::com::SampleAllocateePtr<SampleType> data)에 전달됩니다 ([SWS_CM_90437]). Send 호출 후에는 Communication Management가 구독 중인 모든 애플리케이션에 데이터를 전송하면 서비스 애플리케이션은 더 이상 데이터에 접근해서는 안 됩니다 ([SWS_CM_90437]).
