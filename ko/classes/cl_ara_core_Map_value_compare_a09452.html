컨텍스트

ara::core::Map::value_compare 클래스는 AUTOSAR Adaptive Platform의 core 모듈 내에서 연관 컨테이너(associative container) 내 전체 요소의 정렬된 비교를 위해 설계된 헬퍼 함수 객체를 제공합니다. 둘러싸는 컨테이너 ara::core::Map<Key, T, Compare, Allocator>는 키-값 쌍으로 구성된 value_type 타입의 요소를 관리합니다. 사용자는 통상적으로 순수 키 타입 Key에 대한 비교 프레디케이트(predicate)를 정의하지만, 내부 검색 및 삽입 연산과 외부 알고리즘은 완전한 요소 쌍에 대해 직접 동작할 수 있는 비교자(comparator)를 자주 요구합니다. value_compare는 키 프레디케이트를 포함하여 요소 수준에서 적용 가능하게 함으로써 이 기능을 캡슐화합니다.

해당 명세는 value_compare의 기능적 동작을 “As per corresponding usage in [map]”이라는 참조를 통해 정의합니다. 이 클래스의 컨텍스트에서 상호작용 대상으로는 ara::core::Map 컨테이너, 기반이 되는 Compare 프레디케이트 및 표준 라이브러리의 제네릭 알고리즘이 있습니다. 헤더 파일 #include "ara/core/map.h"에 선언되어 있으므로, 이 클래스는 표준화된 AUTOSAR 코어 라이브러리의 필수적인 구성 요소입니다. 이 클래스의 기술적 책임은 자체적인 데이터 또는 메모리 관리를 수행하지 않고, 보호된 멤버 변수 comp에 유지되는 키 비교자([SWS_CORE_01421])를 상위 레벨 값 비교에 사용하는 것으로 제한됩니다.

수명 주기

value_compare 객체의 수명 주기는 이를 둘러싼 컨테이너 또는 호출하는 알고리즘에 바인딩됩니다. 생성자 value_compare(Compare c)은 명시적으로 protected 가시성([SWS_CORE_01422])으로 지정되어 있습니다. 이는 임의의 사용자 코드에 의한 직접적인 인스턴스화를 배제합니다. 해석: 따라서 인스턴스 생성은 필요 시 객체를 내부적으로 인스턴스화하거나 인터페이스를 통해 외부로 전달하는 ara::core::Map에 의해서만 통제되어 이루어질 것으로 추정됩니다. 생성 시 프레디케이트 인스턴스 c가 보호된 멤버 변수 comp([SWS_CORE_01421])으로 전달되어 객체에 저장됩니다.

소유권 관계와 관련하여 value_compare은 Compare 프레디케이트를 값 복사(copy by value) 방식으로 보유합니다. 따라서 포함된 비교자의 수명은 value_compare 인스턴스의 소멸과 함께 반드시 종료됩니다. 상태가 거의 없는(state-poor) 함수 객체이므로, 독립적인 다단계 상태 머신 없이 C++의 일반적인 RAII 및 스택 메커니즘을 따라 정리가 수행됩니다. 동시성과 관련해서는 함수 호출 연산자가 const으로 선언되어 있다는 점([SWS_CORE_01423])이 중요합니다. 캡슐화된 Compare 프레디케이트가 스레드에 안전하지 않은 상태를 변경하지 않는 한, 여러 실행 스레드가 읽기 및 정렬 연산을 위해 동일한 비교자를 병렬로 사용할 수 있습니다.

사용 경로

ara::core::Map::value_compare의 일반적인 사용 경로는 프레디케이트 획득, 요소 쌍에 대한 반복 적용 및 결과 정렬 기준의 평가로 구성됩니다.

  • 제공: 호출자는 연관된 ara::core::Map 컨테이너로부터 value_compare 인스턴스를 획득하며, 해당 컨테이너는 현재 키 프레디케이트를 전달하면서 보호된 생성자 [SWS_CORE_01422]를 호출합니다.
  • 비교 호출: 호출자 또는 제네릭 알고리즘은 호출 연산자 operator()(const value_type &x, const value_type &y) const([SWS_CORE_01423])을 통해 함수 객체를 컨테이너의 두 요소에 적용합니다.
  • 위임: 해석: operator() 실행 시 객체는 값 쌍의 각 키 구성 요소 x.first 및 y.first에 접근하여 실제 비교를 보호된 멤버 comp([SWS_CORE_01421])에 위임할 것으로 추정됩니다.
  • 평가: 해당 호출은 정의된 정렬 순서와 관련하여 x 요소가 y 요소보다 엄격히 앞서는지 여부를 나타내는 bool 값([SWS_CORE_01423])을 반환합니다.

이러한 흐름은 일반적으로 std::includes과 같은 알고리즘 내에서 또는 사용자 정의 범위 분석 시 실행됩니다. 캡슐화를 통해 알고리즘이 항목의 키 구조에 수동으로 접근할 필요가 없도록 보장합니다.

오류 시나리오

명세에서 생성자 [SWS_CORE_01422]과 호출 연산자 [SWS_CORE_01423]은 모두 명시적으로 not exception safe로 분류되어 있습니다. 따라서 이 클래스는 오류 중화 또는 예외 처리에 대한 자체적인 보장을 제공하지 않습니다. 생성자에서 Compare 프레디케이트의 초기화 또는 복사 시 예외가 발생하면 인스턴스화가 중단되고 예외가 호출 측으로 전달됩니다.

이는 operator()([SWS_CORE_01423]) 호출 시에도 마찬가지입니다. 키 비교 중에 캡슐화된 프레디케이트 comp([SWS_CORE_01421])가 예외를 발생시키면, 이 예외는 완화되지 않고 연산자 외부로 전파됩니다. 논리적 정확성을 위한 필수 전제 조건으로, 구성된 프레디케이트는 엄격한 약한 순서(Strict Weak Ordering)를 구현해야 합니다. 비교자가 이러한 수학적 특성을 위반하면 Map 내에서 잘못된 정렬 상태가 발생하며, value_compare는 이 오류를 가로챌 수 없습니다. 또한 두 매개변수 x 및 y은 모두 value_type의 유효한 인스턴스를 참조해야 합니다.

이 가이드는 릴리스 R25-11의 ara::core::Map::value_compare에 대한 AUTOSAR 명세만을 기반으로 합니다.

<h4>컨텍스트</h4>
<p><code>ara::core::Map::value_compare</code> 클래스는 AUTOSAR Adaptive Platform의 <code>core</code> 모듈 내에서 연관 컨테이너(associative container) 내 전체 요소의 정렬된 비교를 위해 설계된 헬퍼 함수 객체를 제공합니다. 둘러싸는 컨테이너 <code>ara::core::Map&lt;Key, T, Compare, Allocator&gt;</code>는 키-값 쌍으로 구성된 <code>value_type</code> 타입의 요소를 관리합니다. 사용자는 통상적으로 순수 키 타입 <code>Key</code>에 대한 비교 프레디케이트(predicate)를 정의하지만, 내부 검색 및 삽입 연산과 외부 알고리즘은 완전한 요소 쌍에 대해 직접 동작할 수 있는 비교자(comparator)를 자주 요구합니다. <code>value_compare</code>는 키 프레디케이트를 포함하여 요소 수준에서 적용 가능하게 함으로써 이 기능을 캡슐화합니다.</p>
<p>해당 명세는 <code>value_compare</code>의 기능적 동작을 “As per corresponding usage in [map]”이라는 참조를 통해 정의합니다. 이 클래스의 컨텍스트에서 상호작용 대상으로는 <code>ara::core::Map</code> 컨테이너, 기반이 되는 <code>Compare</code> 프레디케이트 및 표준 라이브러리의 제네릭 알고리즘이 있습니다. 헤더 파일 <code>#include "ara/core/map.h"</code>에 선언되어 있으므로, 이 클래스는 표준화된 AUTOSAR 코어 라이브러리의 필수적인 구성 요소입니다. 이 클래스의 기술적 책임은 자체적인 데이터 또는 메모리 관리를 수행하지 않고, 보호된 멤버 변수 <code>comp</code>에 유지되는 키 비교자(<a class="spec-record-ref" data-req="SWS_CORE_01421" href="../spec/record.html?id=SWS_CORE_01421">[SWS_CORE_01421]</a>)를 상위 레벨 값 비교에 사용하는 것으로 제한됩니다.</p>

<h4>수명 주기</h4>
<p><code>value_compare</code> 객체의 수명 주기는 이를 둘러싼 컨테이너 또는 호출하는 알고리즘에 바인딩됩니다. 생성자 <code>value_compare(Compare c)</code>은 명시적으로 <code>protected</code> 가시성(<a class="spec-record-ref" data-req="SWS_CORE_01422" href="../spec/record.html?id=SWS_CORE_01422">[SWS_CORE_01422]</a>)으로 지정되어 있습니다. 이는 임의의 사용자 코드에 의한 직접적인 인스턴스화를 배제합니다. 해석: 따라서 인스턴스 생성은 필요 시 객체를 내부적으로 인스턴스화하거나 인터페이스를 통해 외부로 전달하는 <code>ara::core::Map</code>에 의해서만 통제되어 이루어질 것으로 추정됩니다. 생성 시 프레디케이트 인스턴스 <code>c</code>가 보호된 멤버 변수 <code>comp</code>(<a class="spec-record-ref" data-req="SWS_CORE_01421" href="../spec/record.html?id=SWS_CORE_01421">[SWS_CORE_01421]</a>)으로 전달되어 객체에 저장됩니다.</p>
<p>소유권 관계와 관련하여 <code>value_compare</code>은 <code>Compare</code> 프레디케이트를 값 복사(copy by value) 방식으로 보유합니다. 따라서 포함된 비교자의 수명은 <code>value_compare</code> 인스턴스의 소멸과 함께 반드시 종료됩니다. 상태가 거의 없는(state-poor) 함수 객체이므로, 독립적인 다단계 상태 머신 없이 C++의 일반적인 RAII 및 스택 메커니즘을 따라 정리가 수행됩니다. 동시성과 관련해서는 함수 호출 연산자가 <code>const</code>으로 선언되어 있다는 점(<a class="spec-record-ref" data-req="SWS_CORE_01423" href="../spec/record.html?id=SWS_CORE_01423">[SWS_CORE_01423]</a>)이 중요합니다. 캡슐화된 <code>Compare</code> 프레디케이트가 스레드에 안전하지 않은 상태를 변경하지 않는 한, 여러 실행 스레드가 읽기 및 정렬 연산을 위해 동일한 비교자를 병렬로 사용할 수 있습니다.</p>

<h4>사용 경로</h4>
<p><code>ara::core::Map::value_compare</code>의 일반적인 사용 경로는 프레디케이트 획득, 요소 쌍에 대한 반복 적용 및 결과 정렬 기준의 평가로 구성됩니다.</p>
<ul>
<li><strong>제공:</strong> 호출자는 연관된 <code>ara::core::Map</code> 컨테이너로부터 <code>value_compare</code> 인스턴스를 획득하며, 해당 컨테이너는 현재 키 프레디케이트를 전달하면서 보호된 생성자 <a class="spec-record-ref" data-req="SWS_CORE_01422" href="../spec/record.html?id=SWS_CORE_01422">[SWS_CORE_01422]</a>를 호출합니다.</li>
<li><strong>비교 호출:</strong> 호출자 또는 제네릭 알고리즘은 호출 연산자 <code>operator()(const value_type &amp;x, const value_type &amp;y) const</code>(<a class="spec-record-ref" data-req="SWS_CORE_01423" href="../spec/record.html?id=SWS_CORE_01423">[SWS_CORE_01423]</a>)을 통해 함수 객체를 컨테이너의 두 요소에 적용합니다.</li>
<li><strong>위임:</strong> 해석: <code>operator()</code> 실행 시 객체는 값 쌍의 각 키 구성 요소 <code>x.first</code> 및 <code>y.first</code>에 접근하여 실제 비교를 보호된 멤버 <code>comp</code>(<a class="spec-record-ref" data-req="SWS_CORE_01421" href="../spec/record.html?id=SWS_CORE_01421">[SWS_CORE_01421]</a>)에 위임할 것으로 추정됩니다.</li>
<li><strong>평가:</strong> 해당 호출은 정의된 정렬 순서와 관련하여 <code>x</code> 요소가 <code>y</code> 요소보다 엄격히 앞서는지 여부를 나타내는 <code>bool</code> 값(<a class="spec-record-ref" data-req="SWS_CORE_01423" href="../spec/record.html?id=SWS_CORE_01423">[SWS_CORE_01423]</a>)을 반환합니다.</li>
</ul>
<p>이러한 흐름은 일반적으로 <code>std::includes</code>과 같은 알고리즘 내에서 또는 사용자 정의 범위 분석 시 실행됩니다. 캡슐화를 통해 알고리즘이 항목의 키 구조에 수동으로 접근할 필요가 없도록 보장합니다.</p>

<h4>오류 시나리오</h4>
<p>명세에서 생성자 <a class="spec-record-ref" data-req="SWS_CORE_01422" href="../spec/record.html?id=SWS_CORE_01422">[SWS_CORE_01422]</a>과 호출 연산자 <a class="spec-record-ref" data-req="SWS_CORE_01423" href="../spec/record.html?id=SWS_CORE_01423">[SWS_CORE_01423]</a>은 모두 명시적으로 <em>not exception safe</em>로 분류되어 있습니다. 따라서 이 클래스는 오류 중화 또는 예외 처리에 대한 자체적인 보장을 제공하지 않습니다. 생성자에서 <code>Compare</code> 프레디케이트의 초기화 또는 복사 시 예외가 발생하면 인스턴스화가 중단되고 예외가 호출 측으로 전달됩니다.</p>
<p>이는 <code>operator()</code>(<a class="spec-record-ref" data-req="SWS_CORE_01423" href="../spec/record.html?id=SWS_CORE_01423">[SWS_CORE_01423]</a>) 호출 시에도 마찬가지입니다. 키 비교 중에 캡슐화된 프레디케이트 <code>comp</code>(<a class="spec-record-ref" data-req="SWS_CORE_01421" href="../spec/record.html?id=SWS_CORE_01421">[SWS_CORE_01421]</a>)가 예외를 발생시키면, 이 예외는 완화되지 않고 연산자 외부로 전파됩니다. 논리적 정확성을 위한 필수 전제 조건으로, 구성된 프레디케이트는 엄격한 약한 순서(Strict Weak Ordering)를 구현해야 합니다. 비교자가 이러한 수학적 특성을 위반하면 Map 내에서 잘못된 정렬 상태가 발생하며, <code>value_compare</code>는 이 오류를 가로챌 수 없습니다. 또한 두 매개변수 <code>x</code> 및 <code>y</code>은 모두 <code>value_type</code>의 유효한 인스턴스를 참조해야 합니다.</p>
