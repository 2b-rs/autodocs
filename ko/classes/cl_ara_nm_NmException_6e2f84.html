Network Management API 호출 시의 오류를 오류 코드 기반의 처리 가능한 예외로 표현합니다.

이 예외 클래스는 [SWS_ANM_01100]에 따른 Network Management 기능 클러스터 내의 동기 런타임 및 API 오류에 대한 표준화된 오류 유형 역할을 합니다. 인스턴스는 기저 오류 원인을 캡슐화하며 특정 오류 코드를 전달받아 생성됩니다 [SWS_ANM_01102]. 일반 기본 예외의 특수화를 통해 이 유형은 실패한 네트워크 관리 작업에 대한 타깃 예외 처리를 가능하게 합니다. 필수적인 제약 조건으로서 생성자는 완전한 스레드 안전성과 객체 생성 중 not-throw 보증 준수를 보장합니다.

컨텍스트

클래스 ara::nm::NmException은(는) 기능 클러스터 Network Management(ara::nm) 내에서 API 수준의 오류를 알리기 위한 핵심 예외 유형으로 작동합니다 [SWS_ANM_01100]. 이 클래스는 헤더 파일 ara/nm/nm_error_domain.h에 선언되어 있으며 일반 기본 클래스 ara::core::Exception에서 공개 파생됩니다 [SWS_ANM_01100]. 이를 통해 AUTOSAR Adaptive Platform 아키텍처에서 네트워크 관리의 모듈별 오류 상태와 기본 인프라의 표준화된 C++ 예외 처리 메커니즘 사이의 가교 역할을 합니다.

상호 작용 파트너로는 Network Management의 API 인터페이스 및 이 클러스터의 서비스를 사용하는 애플리케이션별 컴포넌트가 등장합니다. 이러한 인터페이스 실행 중 심각하거나 동기적으로 처리해야 하는 오류 상태가 발생하면 예외 객체가 상위 호출자로의 전달을 위해 이 오류를 캡슐화합니다 [SWS_ANM_01100]. 상속 계층 구조를 통해 NmException은(는) 일반적인 예외 처리 루틴에 원활하게 통합되며 모듈별로 캐치될 수도 있고 ara::core::Exception에 대한 참조를 통해 다형적으로 캐치될 수도 있습니다.

수명 주기

ara::nm::NmException 인스턴스의 라이프사이클은 ara::core::ErrorCode 타입의 오류 코드가 전달되는 생성자를 통한 명시적 인스턴스화로 시작됩니다 [SWS_ANM_01102]. 키워드 explicit(으)로 생성자를 표시함으로써 사양은 오류 코드로부터의 암시적 타입 변환을 차단하여 의도적이고 타입이 올바른 객체 생성을 강제합니다 [SWS_ANM_01102].

동시성과 관련하여 예외 생성은 스레드 안전(thread-safe)으로 명시되어 있습니다 [SWS_ANM_01102]. 따라서 호출 컴포넌트가 외부 동기화 메커니즘을 구축할 필요 없이 서로 다른 스레드에서 안전하게 병렬로 인스턴스화가 수행될 수 있습니다. 추가적으로 생성자는 noexcept(으)로 선언되어 있어 [SWS_ANM_01102], 객체 생성 자체에서 추가 예외가 발생할 수 없음을 공식적으로 보장합니다.

생성 후 인스턴스는 C++ 스택 메커니즘을 통해 담당 예외 핸들러로 전달됩니다. 소멸은 예외 객체에 대한 C++ 프로그래밍 언어의 표준 규칙에 따라 연관된 catch 블록을 벗어날 때 자동으로 이루어집니다.

사용 경로

일반적인 사용 경로는 Network Management API와의 상호 작용 중 오류 발생, 예외 객체 생성 및 애플리케이션에 의한 후속 평가를 포함합니다. 추정하건대 예외는 주로 동기 호출이 실패하거나 반환값의 오류가 예외로 명시적으로 언팩될 때 발생합니다.

시퀀스 다이어그램: Network Management API 호출 시 예외를 통한 오류 처리의 전형적인 흐름. 출처: [SWS_ANM_01100], [SWS_ANM_01102]

일반적인 흐름은 다음 단계로 나뉩니다:

  • API 작업 호출: 애플리케이션이 Network Management의 함수를 호출합니다.
  • 오류 감지 및 생성: API 구현에서 오류 조건을 감지하면 특정 오류 코드 [SWS_ANM_01102]을(를) 전달하여 NmException의 인스턴스를 생성합니다.
  • 예외 발생: 예외가 발생하여(throw) 정상적인 제어 흐름이 중단됩니다 [SWS_ANM_01100].
  • 캐치 및 오류 처리: 애플리케이션이 예외를 const ara::nm::NmException&에 대한 참조로 캐치하고 복구 또는 로깅을 위한 적절한 조치를 시작합니다.

오류 시나리오

예외 클래스로서 ara::nm::NmException은(는) 오류 표현 도구를 나타내며 동작 중 자체적으로 복잡한 오류 시나리오의 영향을 받지 않습니다 [SWS_ANM_01100]. 생성을 위한 필수 사전 조건은 초기화된 ara::core::ErrorCode 객체의 제공에 있습니다 [SWS_ANM_01102]. 이 오류 코드는 특정 NM 문제의 오류 도메인과 숫자 식별자를 매핑할 것으로 보입니다.

생성자가 noexcept(으)로 선언되어 있으므로 예외 객체 생성 시 실패는 배제됩니다 [SWS_ANM_01102]. 시스템 수준에서의 주요 오류 시나리오는 적절한 예외 처리를 누락하는 데 있습니다. 발생한 NmException이(가) 캐치되지 않은 채로 남으면 std::terminate의 호출로 이어져 프로세스의 통제되지 않은 중단이 발생합니다. 따라서 애플리케이션은 호출 코드 섹션이 적절한 처리 블록으로 보호되도록 보장해야 합니다.

사용

클래스 NmException은(는) Network Management(ANM)의 API 오류에 대한 특정 예외 유형을 나타내며 ara::core::Exception을(를) 상속받습니다 [SWS_ANM_01100]. 이는 헤더 ara/nm/nm_error_domain.h에 정의되어 있습니다 [SWS_ANM_01100]. 인스턴스화는 해당 오류 코드를 전달받아 명시적 생성자 explicit NmException(ara::core::ErrorCode errorCode) noexcept을(를) 통해 수행됩니다 [SWS_ANM_01102].

오류 처리 및 상호 작용

편리한 액세스를 위해 모듈은 동일한 헤더 [SWS_ANM_01104]의 타입 별칭 using Exception = NmException;을(를) 통해 동일한 예외 유형을 추가로 선언합니다. 해석: ara::core::Exception의 특수화로서 NmException은(는) 주로 Network Management의 오류 상태가 예외 기반 경로를 통해 신호되거나 결함이 있는 ara::core::Result이(가) 예외를 통해 해결될 때 발생할 것으로 추정됩니다.

동시성 및 스레드 안전성

NmException의 생성자는 명시적으로 noexcept(으)로 지정되어 있으며 스레드 안전성을 보장합니다 [SWS_ANM_01102]. 따라서 생성 중에 추가 예외가 발생하지 않고 [SWS_ANM_01102] 동시 스레드에서 추가적인 외부 동기화 없이 인스턴스를 안전하게 생성할 수 있습니다.
