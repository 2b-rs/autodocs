쓰기 진단 데이터 전송을 캡슐화하고 쓰기 핸들러를 통한 처리를 조정합니다.

클래스 ara::diag::DataTransferWriteSession은 쓰기 진단 데이터 전송을 캡슐화하고 애플리케이션별 쓰기 핸들러([SWS_DM_01555])로의 전달을 조정합니다. TransferData(0x36) 또는 RequestTransferExit(0x37)과 같은 수신 UDS 서비스의 경우 진단 서버 인스턴스는 등록된 핸들러의 해당 Write 또는 Exit 메서드를 호출합니다([SWS_DM_01317]). 기본 및 복사 생성이 삭제되어 있으므로 세션은 예외 안전한 단일 인스턴스로 존재하며, 그 생성은 템플릿 생성자를 통해 수행될 것으로 추정됩니다.

컨텍스트

클래스 ara::diag::DataTransferWriteSession은 Adaptive Platform Diagnostics([SWS_DM_01555]) 기능 영역 내의 모든 변형의 쓰기 데이터 전송을 캡슐화합니다. 이는 플랫폼의 진단 서버 인스턴스와 실제 쓰기 전송을 수행하는 애플리케이션별 구현 간의 연결 요소로 기능합니다.

RequestFileTransfer과 같은 진단 서비스(예: [SWS_DM_01313]에 따른 동작 모드 ReplaceFile(0x03))의 프레임워크 내에서 진단 서버 인스턴스는 전송 요청을 수신합니다. 이후 UDS 서비스 TransferData(0x36)의 진단 요청이 도달하면 서버는 이를 해당 DataTransferWriteSession에 바인딩된 핸들러 클래스의 Write 메서드에 위임합니다([SWS_DM_01317]). 모든 데이터 블록이 전송된 후 서비스 RequestTransferExit(0x37)이 완료를 알리고, 이에 따라 진단 서버 인스턴스는 등록된 핸들러의 Exit 메서드를 호출합니다([SWS_DM_01318]).

컨텍스트 다이어그램: 진단 서버, DataTransferWriteSession 및 애플리케이션별 핸들러 클래스 간의 상호작용. 출처: [SWS_DM_01555], [SWS_DM_01317], [SWS_DM_01318].

수명 주기

DataTransferWriteSession의 라이프사이클은 헤더 파일 ara/diag/data_transfer.h([SWS_DM_01339])의 사양을 따릅니다. 기본 생성은 명시적으로 삭제되었습니다(DataTransferWriteSession() = delete, [SWS_DM_01339]). 따라서 인스턴스화는 특정 핸들러 클래스가 세션 객체에 바인딩되는 템플릿 생성자를 통해 이루어질 것으로 추정됩니다(AUTOSAR_AP_SWS_Diagnostics §8.10 “Context of RequestFileTransfer”).

명확한 소유권을 강화하기 위해 DataTransferWriteSession은 복사할 수도 없고 복사 대입할 수도 없습니다. 복사 생성자([SWS_DM_01559])와 복사 대입 연산자([SWS_DM_01560]) 모두 delete(으)로 선언되어 있습니다. 따라서 인스턴스는 독점적인 단일 인스턴스로 존재합니다.

반면 이 클래스는 완전한 이동 시맨틱을 지원합니다. 이동 생성자([SWS_DM_01557])와 이동 대입 연산자([SWS_DM_01558])는 기본 구현으로 선언되어 있으며, noexcept 및 예외 안전(“exception safe”)으로 명시되어 있습니다. 이를 통해 프로그램 컨텍스트 간에 세션 상태를 효율적으로 전송할 수 있습니다. 소멸은 예외 안전한 기본 소멸자(~DataTransferWriteSession() noexcept = default, [SWS_DM_01556])를 통해 수행됩니다. 동시 액세스를 위한 동기화 메커니즘이 문서화되어 있지 않으므로, 동시성과 관련하여 사용은 주로 실행 중인 서버 스레드 내에서 순차적으로 이루어질 것으로 추정됩니다.

사용 경로

쓰기 전송의 일반적인 흐름은 다음 단계로 진행됩니다:

  1. 초기화: 쓰기 요청(예: [SWS_DM_01313]에 따른 kReplace을 동반한 RequestFileTransfer) 수신 시 DataTransferWriteSession이 설정됩니다. 이때 쓰기 연산을 위한 애플리케이션별 핸들러가 템플릿 생성자를 통해 등록됩니다(AUTOSAR_AP_SWS_Diagnostics §8.10 “Context of RequestFileTransfer”).
  2. 데이터 블록 전송: 수신되는 UDS 서비스 TransferData(0x36)의 각 요청에 대해 진단 서버 인스턴스는 등록된 핸들러 클래스의 Write 메서드를 호출합니다([SWS_DM_01317]). 이 단계는 전송의 모든 블록에 대해 주기적으로 반복됩니다.
  3. 세션 종료: 완전한 전송 후 진단 서버는 RequestTransferExit(0x37)을 수신하고, 이에 따라 핸들러 클래스의 Exit 메서드를 호출합니다([SWS_DM_01318]).
  4. 정리: 성공적으로 완료되거나 조기 중단된 경우 세션 객체가 소멸됩니다([SWS_DM_01556]).

시퀀스 다이어그램: 참여 인스턴스를 통한 쓰기 데이터 전송의 일반적인 흐름. 출처: [SWS_DM_01317], [SWS_DM_01318], [SWS_DM_01556].

오류 시나리오

ara::diag::DataTransferWriteSession에서 오류 처리 및 신뢰성은 주로 정적 타입 안전성과 예외 안전성에 기반합니다:

  • 유효하지 않은 객체 상태 방지: 기본 생성자([SWS_DM_01339])의 삭제는 핸들러가 바인딩되지 않은 초기화되지 않은 세션 객체가 존재하는 것을 방지합니다. 복사 연산의 금지([SWS_DM_01559], [SWS_DM_01560])는 컴파일 타임에 다중 소유권으로 인한 일관되지 않은 상태를 배제합니다.
  • 이동 및 소멸 시 예외 안전성: 이동 생성자([SWS_DM_01557]), 이동 대입([SWS_DM_01558]) 및 소멸자([SWS_DM_01556])를 noexcept(으)로 선언함으로써 런타임에 리소스 인계 및 세션 해제 시 예외가 발생하지 않음을 보장합니다.
  • 조기 중단: 전송이 조기에 실패하는 경우 noexcept 소멸자는 예외 언와인딩 프레임워크 내에서도 세션 객체가 안정적으로 정리될 수 있도록 보장합니다([SWS_DM_01556]).

이 가이드는 AUTOSAR Adaptive Platform 릴리스 R25-11의 사양 문서를 기반으로 합니다.
