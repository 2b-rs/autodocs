ara::core::variant_alternative<I, T>는 struct에서의 사용에 해당하는 템플릿 [variant]이다. 이는 ara::core::Variant에 지정된 변형 지원의 일부이다. 제공된 자료는 회원이나 추가 사용 규칙을 정의하지 않는다. [SWS_CORE_01607] 선언은 #include "ara/core/variant.h" 헤더에 제공된다. 이미 언급된 인터페이스 이외의 추가 사용 프로세스는 제공된 자료에 지정되어 있지 않는다. [SWS_CORE_01607]

분류: 기록 및 전문화

사양은 std::variant_alternative 1:1을 반영합니다. 기본 템플릿 [SWS_CORE_01607]은 부분 특수화 variant_alternative< I, Variant< Types... > > [SWS_CORE_01611], variant_alternative< I, const T > [SWS_CORE_01608], variant_alternative< I, volatile T > [SWS_CORE_01609] 및 variant_alternative< I, const volatile T >로 보완됩니다. [SWS_CORE_01610] 및 별칭 variant_alternative_t [SWS_CORE_01612]. 모든 기록은 "[변종]의 해당 용도에 따라"라는 내용으로만 콘텐츠를 설명하며 상태는 DRAFT입니다. ara::core::Variant는 독립적인 유형이므로 별도의 특성이 필요합니다. std::variant_alternative는 std::variant에만 특화되어 있으며 get [SWS_CORE_01613], get_if [SWS_CORE_01621] 및 Variant::emplace의 시그니처는 다음과 같습니다. [SWS_CORE_01663]는 variant_alternative_t에 걸쳐 공식화됩니다.

Interpretation: 실제로는 variant_alternative_t만이 애플리케이션 코드와 관련이 있다. 특성 자체가 직접 인스턴스화되는 경우는 거의 없다. cv 전문화는 [variant]의 C++17 상태를 반영한다. ISO 표준에서 volatile 및 const volatile 형식은 C++20(P1831R1 “Deprecating volatile: library”) 이후 더 이상 사용되지 않는 것으로 표시되었으며 해당 제거가 제안되었다(P2866 “Remove Deprecated Volatile Features”). const 양식은 그대로 유지된다. AUTOSAR가 R25-11에서 변경되지 않은 네 가지 cv 형식을 모두 포함한다는 사실은 사용 권장 사항이 아니라 C++17과 비교하여 완전성으로 읽어야 한다. 새 코드는 정규화되지 않은 Variant 유형에만 특성을 적용하고 volatile 정규 변형 유형을 피해야 한다. 일관된 DRAFT 상태는 인터페이스가 아직 공식적으로 바인딩되지 않았으며 향후 릴리스에서 변경될 수 있음을 의미한다.
