ara::rds::RawDataStreamServer 클래스는 서버 애플리케이션이 클라이언트 연결을 수락하고 모델링된 포트를 통해 바이너리 데이터 스트림을 읽고 쓸 수 있도록 지원합니다 SWS RawDataStream 1쪽. 정적 팩토리 메서드 Create을(를) 통해 생성된 후, 애플리케이션은 동기식으로 또는 시간 제한을 두고 연결을 대기한 뒤 ReadData 및 WriteData을(를) 통해 데이터를 교환합니다 [SWS_RDS_11312]. 이 클래스는 순수 이동 시맨틱스를 가지며 모든 연산이 noexcept(으)로 선언되어 있으므로, 오류 처리는 ara::core::Result을(를) 통해서만 이루어집니다.

컨텍스트

ara::rds::RawDataStreamServer 클래스는 AUTOSAR Adaptive Platform(모듈 rds)에서 스트림 지향 데이터 전송을 위한 서버 측 대응물을 나타냅니다 SWS RawDataStream 1쪽. 주요 임무는 모델링된 통신 포트에서 수신되는 클라이언트 연결을 수락하고, 바이너리 데이터 스트림을 통한 비구조화된 원시 데이터의 후속 양방향 교환을 처리하는 것입니다.

주요 상호작용 대상에는 다음이 포함됩니다:

  • 인스턴스를 생성하고, 연결을 대기하며, 데이터 전송을 시작하는 상위 서버 애플리케이션,
  • 모델링된 포트를 위한 ara::core::InstanceSpecifier을(를) 통해 서버가 바인딩되는 AUTOSAR 런타임 시스템 [SWS_RDS_11312],
  • 서버에 연결을 수립하고 [SWS_RDS_11318] 페이로드 데이터를 교환하는 외부 클라이언트 [SWS_RDS_11322], [SWS_RDS_11324].

수명 주기

RawDataStreamServer의 인스턴스화는 일반적인 생성자를 통해서가 아니라 정적 팩토리 메서드 Create을(를) 통해서만 수행됩니다 [SWS_RDS_11312]. 이는 서버를 ara::core::InstanceSpecifier(으)로 지정된 포트에 바인딩합니다.

소유권과 관련하여 이 클래스는 엄격한 이동 전용 시맨틱스를 강제합니다. 복사 생성자 [SWS_RDS_11316] 및 복사 할당 연산자 [SWS_RDS_11317]은(는) 명시적으로 삭제되었습니다(delete). 따라서 리소스를 다른 스코프로 전달하는 것은 이동 생성자 [SWS_RDS_11314] 또는 이동 할당 연산자 [SWS_RDS_11315]을(를) 통해서만 가능합니다.

해석: 성공적인 생성 후 서버 인스턴스는 아직 활성 연결이 없는 초기 준비 상태에 있습니다. WaitForConnection [SWS_RDS_11318] 또는 시간 감시 변형 WaitForConnection(timeout) [SWS_RDS_11319]을(를) 통해 서버는 클라이언트를 대기하고 성공 시 활성 연결 상태로 전환됩니다. 연결은 런타임에 Shutdown 호출을 통해 명시적으로 닫을 수 있습니다 [SWS_RDS_11320].

서버 인스턴스 소멸 시 소멸자 ~RawDataStreamServer은(는) 아직 열려 있는 연결이 자동으로 올바르게 종료되고 닫히도록 보장합니다 [SWS_RDS_11313].

동시성과 관련하여 생성 메서드 Create은(는) 스레드 안전한 것으로 명세되어 있습니다 [SWS_RDS_11312]. 반면에 이동 연산 [SWS_RDS_11314], [SWS_RDS_11315] 및 소멸자 [SWS_RDS_11313]은(는) 명시적으로 스레드 안전하지 않은 것(not thread-safe)으로 지정되어 있어 여러 스레드에서 동시에 접근할 때 외부 동기화 보호가 필요합니다.

상태 다이어그램: 생성부터 연결 수락 및 연결 해제까지 서버 인스턴스의 단계. 출처: [SWS_RDS_11312], [SWS_RDS_11318], [SWS_RDS_11320], [SWS_RDS_11313]

사용 경로

서버 애플리케이션의 일반적인 사용 경로는 초기화, 연결 대기, 양방향 데이터 전송 및 연결 해제 단계를 포함합니다:

  1. 서버 생성: 애플리케이션은 구성된 포트에 대해 ara::rds::RawDataStreamServer::Create(instance)(으)로 서버를 인스턴스화합니다 [SWS_RDS_11312].
  2. 연결 대기: 애플리케이션은 클라이언트가 연결을 수립할 때까지 WaitForConnection() [SWS_RDS_11318]을(를) 사용하거나 WaitForConnection(timeout) [SWS_RDS_11319]을(를) 통해 구성된 최대 시간 동안 차단(block)됩니다.
  3. 데이터 수신 및 송신: 연결이 성공한 후 애플리케이션은 ReadData(maxLength) [SWS_RDS_11322]을(를) 사용하거나 ReadData(maxLength, timeout) [SWS_RDS_11323]을(를) 통해 타임아웃 감시 하에 바이너리 데이터를 읽습니다. 바이너리 데이터를 송신하려면 WriteData을(를) 호출하며, 대기 시간 제한 없이 [SWS_RDS_11324] 호출하거나 타임아웃 감시를 적용하여 [SWS_RDS_11325] 호출할 수 있습니다. WriteData을(를) 통한 송신은 제공된 바이트 버퍼(std::unique_ptr<ara::core::Byte[]>)의 소유권을 서버로 이전하는 것으로 추정됩니다.
  4. 연결 해제: 데이터 전송이 완료되면 애플리케이션은 Shutdown() [SWS_RDS_11320]을(를) 통해 세션을 명시적으로 종료합니다.

시퀀스 다이어그램: 생성, 연결 수락, 데이터 교환 및 연결 종료 흐름. 출처: [SWS_RDS_11312], [SWS_RDS_11318], [SWS_RDS_11322], [SWS_RDS_11324], [SWS_RDS_11320]

오류 시나리오

RawDataStreamServer의 오류 처리는 결함 안전 인터페이스를 위한 AUTOSAR Adaptive Platform의 기본 원칙을 따릅니다.

어떠한 메서드도 C++ 예외를 발생시키지 않으며, 모든 함수는 noexcept(으)로 선언되어 있습니다 SWS RawDataStream 1쪽. 오류 상황은 대신 반환 타입 ara::core::Result을(를) 통해 호출자에게 전달됩니다.

전형적인 오류 시나리오는 다음과 같습니다.

  • 타임아웃: 타임아웃이 있는 WaitForConnection [SWS_RDS_11319], ReadData [SWS_RDS_11323] 및 WriteData [SWS_RDS_11325] 메서드의 경우, 지정된 시간 범위가 만료되면 반환된 ara::core::Result에 오류 상태가 발생합니다.
  • 연결 오류 및 유효하지 않은 상태: 메서드 ReadData, WriteData 및 WaitForConnection은(는) 오류 발생 시(예: 연결이 조기에 끊어지거나 내부 통신 오류가 발생한 경우) ara::core::Result에 해당 오류 코드를 반환할 것으로 보입니다.
  • 사전 및 사후 조건: 호출자는 연산의 오류 없는 상태를 보장하기 위해 데이터 값에 접근하기 전에 반환된 ara::core::Result의 유효성을 항상 검사해야 합니다.

이 가이드는 AUTOSAR Adaptive R25-11 사양을 기반으로 하며 자동으로 생성되었습니다.
