진단 서비스를 위한 동적 액세스 제어 목록의 단계적 구성 및 마무리를 지원합니다.

이 클래스는 체이닝 가능한 Fluent API([SWS_DM_01166])를 통해 진단 서비스를 위한 동적 액세스 제어 목록을 단계적으로 생성하는 데 사용됩니다. 애플리케이션은 정확한 바이트, 값 범위 및 와일드카드를 추가하여 Diagnostic Server용 액세스 패턴을 유연하게 정의합니다([SWS_DM_01175], [SWS_DM_01220]). 스레드 안전하지 않은 이동 전용 객체를 파괴하기 전에 구성을 완료하려면 반드시 Build() 메서드를 호출해야 합니다([SWS_DM_01181]).

컨텍스트

클래스 ara::diag::DynamicAccessListDiagServiceBuilder은 AUTOSAR Adaptive Platform 애플리케이션이 진단 서비스를 위한 동적 액세스 제어 목록(DynamicAccessList)을 단계적으로 구축하는 데 사용됩니다([SWS_DM_01166], AUTOSAR_AP_SWS_Diagnostics §8.15.1 “Class: DynamicAccessListDiagServiceBuilder”). 애플리케이션은 이러한 목록을 통해 런타임에 동적으로 권한이 부여되는 진단 요청(예: 특정 DID 또는 서브기능을 갖는 특정 UDS 서비스)을 제어합니다(AUTOSAR_AP_SWS_Diagnostics §8.2 “Adding wildcards to a DynamicAccessList”).

주요 상호작용 대상은 애플리케이션 자체, 클래스 ara::diag::DiagnosticServiceDynamicAccessList의 팩토리 메서드([SWS_DM_01164], [SWS_DM_01165]), 그리고 수신 요청에 대해 서비스 권한을 검사할 때 조합된 비트 및 바이트 패턴을 평가하는 Diagnostic Server 인스턴스입니다([SWS_DM_01220], [SWS_DM_01221]). 패턴 구조를 나타내기 위해 클래스는 단일 옥텟을 위한 타입 별칭 Byte(std::uint8_t)와 바이트 시퀀스를 위한 타입 별칭 ByteString(ara::core::Span<Byte>)을 제공합니다([SWS_DM_01167], [SWS_DM_01168], AUTOSAR_AP_SWS_Diagnostics §8.15.1.1 “Public Member Types”).

수명 주기

빌더 객체는 일반적으로 DiagnosticServiceDynamicAccessList::MakeServiceBuilder([SWS_DM_01164], [SWS_DM_01165])을 통해 인스턴스화되거나, 초깃값 및 직렬화 버퍼 content(ara::core::Vector<std::uint8_t>&)에 대한 참조를 받는 생성자를 통해 직접 인스턴스화됩니다([SWS_DM_01169]). 해석: 매개변수 content은 완료 후 Diagnostic Server로 전달되는 직렬화된 표현을 지속적으로 채우는 저장소 역할을 할 것으로 추정됩니다.

소유권 및 복사 가능성과 관련하여 클래스는 제한된 대입을 갖는 엄격한 이동 전용(move-only) 시맨틱을 강제합니다. 복사 생성자([SWS_DM_01171])와 복사 대입 연산자([SWS_DM_01172])는 삭제되어 있습니다(=delete). 마찬가지로 이동 대입 연산자도 삭제되어 있습니다([SWS_DM_01173]). 오직 이동 생성자만 구현되어 있으므로([SWS_DM_01170]), 필요한 경우 인스턴스를 이동할 수는 있지만 제어되지 않은 상태로 복제되거나 다시 대입될 수 없습니다.

수명 주기는 필수 사후 조건의 적용을 받습니다. 소멸자([SWS_DM_01174])를 호출하기 전에 목록 작성을 완료하기 위해 Build() 메서드를 호출해야 합니다([SWS_DM_01181]). 생성자는 스레드 안전한 것으로 명시되어 있지만([SWS_DM_01169], [SWS_DM_01170]), 패턴 확장을 위한 모든 메서드 및 소멸자는 스레드 안전하지 않습니다(not thread-safe, [SWS_DM_01174]).

상태 다이어그램: 생성부터 단계별 패턴 구성, 파괴 전 필수 마무리에 이르는 빌더의 수명 주기 단계. 출처: [SWS_DM_01169], [SWS_DM_01175], [SWS_DM_01181], [SWS_DM_01174].

사용 경로

패턴 구성은 메서드 호출이 동일한 빌더 인스턴스에 대한 참조를 반환하는 Fluent API를 통해 수행됩니다([SWS_DM_01175]):

  1. 초기화: 애플리케이션은 예를 들어 시작 바이트 또는 바이트 문자열과 함께 DiagnosticServiceDynamicAccessList::MakeServiceBuilder을 사용하여 빌더를 생성합니다([SWS_DM_01164], [SWS_DM_01165]).
  2. 패턴 확장: 오버로드된 Add() 메서드를 통해 단일 바이트([SWS_DM_01175]), 바이트 시퀀스([SWS_DM_01176]) 또는 닫힌 값 범위 ByteRange([SWS_DM_01177])가 추가됩니다. 이러한 값은 향후 평가 시 정확한 일치 여부가 검사됩니다.
  3. 와일드카드 삽입: 애플리케이션은 Any(numberOfBytesToIgnore)을 사용하여 플레이스홀더를 정의합니다([SWS_DM_01178]). Diagnostic Server는 패턴 매칭 시 지정된 바이트 수를 무시하므로, DID 범위에 대한 22F1XX와 같은 유연한 필터를 구현할 수 있습니다([SWS_DM_01220], AUTOSAR_AP_SWS_Diagnostics §8.2 “Adding wildcards to a DynamicAccessList”).
  4. 패턴 종료 및 마무리: EndsWith()을 통해 종료 바이트 또는 범위를 지정할 수 있습니다([SWS_DM_01179], [SWS_DM_01180], [SWS_DM_01221]). 마지막으로 Build() 호출을 통해 생성 프로세스를 최종 완료합니다([SWS_DM_01181]).

시퀀스 다이어그램: 패턴 정의 시 애플리케이션, 팩토리 메서드 및 빌더 간의 일반적인 상호작용 순서. 출처: [SWS_DM_01165], [SWS_DM_01175], [SWS_DM_01178], [SWS_DM_01181].

오류 시나리오

클래스의 모든 메서드는 noexcept으로 선언되어 있으며 예외 안전(exception safe)한 것으로 명시되어 있습니다([SWS_DM_01169], [SWS_DM_01174], [SWS_DM_01181]). C++ 예외 또는 오류 반환값을 통한 오류 처리는 API 수준에서 발생하지 않습니다.

주요 계약상의 사전 조건은 빌더가 파괴되기 전에 Build()을 호출하는 것입니다([SWS_DM_01181]). 해석: Build()가 실행되지 않고 빌더 객체가 파괴되면 시작된 패턴 구성이 폐기되거나 기본 액세스 목록에 유효하지 않은 상태가 남을 것으로 추정됩니다.

또한 조작 함수는 스레드 안전하지 않습니다([SWS_DM_01175], [SWS_DM_01178], [SWS_DM_01181]). 여러 스레드에서 동일한 빌더 인스턴스에 보호되지 않은 상태로 병렬 액세스하면 정의되지 않은 메모리 상태(데이터 레이스)가 발생합니다.

이 가이드는 AUTOSAR Adaptive R25-11 사양만을 기반으로 합니다.
