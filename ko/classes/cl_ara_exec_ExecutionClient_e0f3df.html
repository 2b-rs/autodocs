프로세스가 Execution Management에 실행 상태를 보고할 수 있도록 지원하며 SIGTERM 신호를 가로챕니다.

ara::exec::ExecutionClient 클래스는 애플리케이션 프로세스가 내부 실행 상태를 Execution Management에 구속력 있게 보고하는 데 사용됩니다([SWS_EM_02003]). 또한 초기화 시 SIGTERM 신호 가로채기를 담당하고 이를 백그라운드 스레드의 사용자 정의 종료 핸들러로 전달합니다([SWS_EM_02562]). 이동 전용(Move-only) 객체로서 이 인스턴스는 신호 처리를 수명 주기에 엄격하게 바인딩하며, 파괴 시 이전 신호 상태를 복원합니다. 호출자는 등록된 콜백이 인스턴스의 전체 수명 동안 호출 가능한 상태를 유지하도록 보장해야 합니다.

컨텍스트

ara::exec::ExecutionClient 클래스는 Adaptive Platform의 프로세스가 내부 실행 상태를 Execution Management에 보고하는 데 사용됩니다([SWS_EM_02003]). 이는 실행 중인 애플리케이션과 중앙 프로세스 관리 사이의 표준화된 인터페이스 역할을 합니다. 상태 전이 전달 외에도, 인스턴스는 운영체제 신호 SIGTERM 처리에 대한 책임을 집니다([SWS_EM_02562], [SWS_EM_02002]). 신호가 도착하면 애플리케이션이 질서 있게 종료될 수 있도록 별도의 백그라운드 스레드에서 사용자 정의 콜백을 실행합니다([SWS_EM_02562]). 해석: 운영체제 또는 Execution Management는 실행 단위의 종료가 요청될 때 프로세스에 신호 SIGTERM을(를) 전달할 것으로 추정됩니다. 질문 Q-51eee947d01ae8b4 (열림)

컨텍스트 다이어그램: 애플리케이션 프로세스, ExecutionClient, Execution Management 및 신호 메커니즘 간의 상호작용. 출처: [SWS_EM_02003], [SWS_EM_02562], [SWS_EM_02002].

수명 주기

ara::exec::ExecutionClient의 인스턴스화는 정적 팩토리 메서드 Create([SWS_EM_02562]) 또는 일반 생성자([SWS_EM_02560])를 통해 선택적으로 수행됩니다. Create은(는) 예외 안전(noexcept)하며 결과를 ara::core::Result에 캡슐화하여 반환하는([SWS_EM_02562]) 반면, 일반 생성자는 noexcept(false)(으)로 선언되어 있습니다([SWS_EM_02560]). 두 생성 경로 모두 매개변수로 호출 가능한 std::function<void()> 콜백을 필요로 합니다(terminationHandler). 이 콜백은 ExecutionClient 인스턴스의 전체 수명 동안 유효하고 호출 가능한 상태를 유지해야 합니다([SWS_EM_02562], [SWS_EM_02560]).

소유권과 관련하여 이 클래스는 이동 전용(Move-only)으로 설계되었습니다. 복사 생성자([SWS_EM_02563]) 및 복사 할당 연산자([SWS_EM_02564])는 명시적으로 삭제되었습니다(delete). 인스턴스 전달은 이동 생성자([SWS_EM_02580]) 및 이동 할당 연산자([SWS_EM_02581])를 통해서만 가능하며, 둘 다 예외 안전(noexcept)하지만 스레드 안전하지는 않습니다. 팩토리 메서드 Create과(와) 생성자 자체는 스레드 안전한 것으로 간주됩니다([SWS_EM_02562], [SWS_EM_02560]).

소멸자 ~ExecutionClient()은(는) noexcept(으)로 정의되어 있으며([SWS_EM_02002]) 스레드 안전하지 않습니다. 인스턴스가 파괴될 때 신호 SIGTERM에 대한 책임은 다시 반환됩니다. 즉, 소멸자는 SIGTERM에 대한 신호 핸들러를 인스턴스화 이전에 활성화되어 있던 원래 상태로 재설정합니다([SWS_EM_02002]).

사용 경로

정규 흐름은 초기화, 상태 보고 및 질서 있는 종료로 나뉩니다:

  • 생성: 프로세스 런타임 시작 시 Create을(를) 통해 인스턴스가 초기화되며, 이때 종료 핸들러가 전달됩니다([SWS_EM_02562]). 일반적으로 이 핸들러는 플래그를 설정하거나 동기화 프리미티브를 신호하여 실행 중인 스레드의 차단을 해제합니다.
  • 상태 보고: 프로세스가 준비되는 즉시 ReportExecutionState을(를) 통해 실행 상태를 Execution Management에 보고합니다([SWS_EM_02003]). 이 호출은 스레드 안전하며 서로 다른 작업 스레드에서 수행될 수 있습니다.
  • 신호 수신 및 종료: 런타임 중에 SIGTERM 신호가 도착하면, ExecutionClient은(는) 등록된 terminationHandler을(를) 백그라운드 스레드에서 비동기적으로 활성화합니다([SWS_EM_02562]). 프로세스는 미완료 작업을 질서 있게 마무리합니다.
  • 파괴: 유효 범위를 벗어날 때 소멸자는 원래 신호 구성을 복원합니다([SWS_EM_02002]).

시퀀스 다이어그램: 생성에서 상태 보고를 거쳐 신호 제어 종료에 이르는 흐름. 출처: [SWS_EM_02562], [SWS_EM_02003], [SWS_EM_02002].

오류 시나리오

ExecutionClient을(를) 사용할 때 다양한 오류 상황은 ara::exec::ExecErrc의 오류 코드를 통해 처리됩니다:

  • ara::exec::ExecErrc::kInvalidArgument: 전달된 terminationHandler 객체에 호출 가능한 함수가 포함되어 있지 않은 경우, Create([SWS_EM_02562])을(를) 통한 인스턴스화 또는 일반 생성자([SWS_EM_02560])에서 발생합니다. 시스템은 롤백 시맨틱을 적용하며, 해결을 위해서는 유효한 Callable을 전달해야 합니다.
  • ara::exec::ExecErrc::kNoCommunication: 애플리케이션 프로세스와 Execution Management 사이에 통신 오류가 있는 경우(예: 메시지 수신 확인 없음), 생성([SWS_EM_02562], [SWS_EM_02560]) 및 ReportExecutionState([SWS_EM_02003]) 모두에서 발생할 수 있습니다. 이 경우에는 롤백 시맨틱이 적용되지 않으며, 복구 조치로 재호출 시도가 예정되어 있습니다.
  • ara::exec::ExecErrc::kInvalidTransition: 이미 활성 상태인 상태(예: kRunning)를 다시 보고하는 것과 같이 허용되지 않는 상태 변경이 요청되는 경우 ReportExecutionState([SWS_EM_02003])에 의해 반환됩니다. 상태가 이미 보고되었으므로 다시 전송할 필요가 없습니다(롤백 시맨틱).

이 가이드는 exec 모듈에 대한 AUTOSAR Adaptive Platform 사양(릴리스 R25-11)을 기반으로 합니다.

정적 함수 Create은(는) ara::exec::ExecutionClient의 인스턴스화를 위한 Named Constructor 역할을 합니다 [SWS_EM_02562]. 호출 시 콜백 terminationHandler(std::function<void()> 타입)이 전달되며, 이는 SIGTERM 신호가 도달할 때 백그라운드 스레드에서 동시에 실행됩니다 [SWS_EM_02562]. 일반적으로 이 콜백은 전역 플래그를 설정하거나 차단된 스레드를 깨워 정상적인 종료(graceful termination)를 시작합니다. 호출자는 ExecutionClient 인스턴스의 전체 수명 동안 핸들러가 호출 가능한 상태로 유지되도록 보장해야 하며, 이는 특히 std::bind을(를) 통한 객체 인스턴스 바인딩 시 주의해야 합니다 [SWS_EM_02562].

반환값으로 이 함수는 생성된 인스턴스 또는 오류 코드를 포함하는 ara::core::Result<ExecutionClient>을(를) 반환합니다 [SWS_EM_02562]. 생성이 실패할 경우 두 가지 특정 오류가 정의되어 있습니다:

  • ara::exec::ExecErrc::kInvalidArgument: 전달된 terminationHandler에 호출 가능한 함수가 포함되어 있지 않습니다(롤백 시맨틱; 유효한 Callable 전달을 통해 해결) [SWS_EM_02562].
  • ara::exec::ExecErrc::kNoCommunication: 통신 오류가 발생했습니다(롤백 시맨틱 없음; 재시도를 통해 해결) [SWS_EM_02562].

이 함수는 noexcept(으)로 선언되어 있으며, Exception-safe 및 Thread-safe로 간주되고 내부적으로 개발자 정의 생성자를 호출할 수 있습니다 [SWS_EM_02562]. 해석: 이 호출은 일반적으로 메인 워크로드가 시작되기 전에 신호 처리를 적시에 설정하기 위해 프로세스의 초기화 단계 초기에 발생할 것으로 추정됩니다. 질문 Q-555aea895feb2123 (열림) 콜백 등록을 포함하는 이러한 Named Constructor 패턴은 자체 Create 함수를 통한 StateClient의 생성과 상응합니다 [SWS_EM_02276].

이 텍스트는 사양 데이터를 바탕으로 AI 시스템에 의해 생성되었습니다.
