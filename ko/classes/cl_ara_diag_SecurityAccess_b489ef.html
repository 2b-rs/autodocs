진단 보안 액세스를 위한 시드 및 키 값의 제공 및 검증 역할을 합니다.

ara::diag::SecurityAccess 클래스는 UDS 서비스 0x27([SWS_DM_00762])에 따른 진단 보안 액세스의 애플리케이션별 구현에 사용됩니다. Offer()을(를) 통한 활성화 후 핸들러는 시드 제공 요청을 수신하고 전송된 키 값을 비동기식으로 검증합니다([SWS_DM_00766]). 복사 및 이동이 불가능한 인스턴스로서 인터페이스는 생성자에서 동시성 동작에 대한 명시적인 구성을 요구하며, 처리 오류는 표준화된 UDS 반환 코드를 통해 진단 시스템에 보고됩니다([SWS_DM_00765]).

컨텍스트

ara::diag::SecurityAccess 클래스는 AUTOSAR Adaptive에서 UDS 서비스 0x27(SecurityAccess)을 구현하기 위한 인터페이스를 나타냅니다. 이는 내부 Diagnostic Management(DM)와 어댑티브 애플리케이션의 애플리케이션별 인증 로직 사이의 연결 고리 역할을 합니다. 외부 진단 테스터가 보안 관련 진단 작업을 요청하면, ISO 14229-1에 따라 차량에 해당 진단 메시지를 전송합니다(AUTOSAR_AP_SWS_Diagnostics §4.1 “Limitations of sub-functions of 0x19 ReadDTCInformation”). Diagnostic Management는 이러한 요청을 수신하고 시드 요청 및 키 비교를 등록된 ara::diag::SecurityAccess 인스턴스로 전달합니다([SWS_DM_00766]).

컨텍스트 다이어그램: 진단 테스터, Diagnostic Management 및 애플리케이션 간의 ara::diag::SecurityAccess 배치. 출처: [SWS_DM_00762], [SWS_DM_00766], AUTOSAR_AP_SWS_Diagnostics §4.1 “Limitations of sub-functions of 0x19 ReadDTCInformation”

수명 주기

인스턴스화는 ara::core::InstanceSpecifier 및 동시성 동작 concurrencyType을(를) 지정하는 생성자를 통해 수행됩니다([SWS_DM_00762]). 인스턴스 식별자는 객체를 DiagnosticSecurityLevelInterface에 의해 타입화되어야 하는 포트 프로토타입에 연결합니다([SWS_DM_00762]). concurrencyType 매개변수는 메서드 호출이 스레드 안전(kConcurrent)하게 처리되어야 하는지 아니면 스레드 안전하지 않게(kNotConcurrent) 처리되어야 하는지를 구속력 있게 정의합니다([SWS_DM_00762]).

소유권 시맨틱과 관련하여 이 클래스는 단일 인스턴스(singleton-like)로 설계되었습니다: 복사 생성자([SWS_DM_01617])와 복사 대입 연산자([SWS_DM_01615])뿐만 아니라 이동 생성자([SWS_DM_01618])와 이동 대입 연산자([SWS_DM_01616])도 삭제되었습니다(=delete). 생성 후 인스턴스는 Offer()을(를) 통해 DM에 등록될 때까지 비활성 상태를 유지합니다([SWS_DM_00766]). 종료 전에는 StopOffer()이(가) 요청 전달을 비활성화합니다([SWS_DM_00767]). 해석: 가상 소멸자([SWS_DM_00763])에 의해 객체가 파괴되기 전에 DM에 진행 중인 요청의 등록 해제를 보장하기 위해 항상 StopOffer()이(가) 호출되어야 할 것으로 보입니다.

사용 경로

파생된 핸들러 구현의 일반적인 사용 워크플로는 다음 단계들로 구성됩니다:

  1. 활성화: 애플리케이션은 파생 클래스를 인스턴스화하고 Offer()을(를) 호출하여 DM에 의한 진단 요청 전달을 활성화합니다([SWS_DM_00766]).
  2. 시드 제공: 시드 생성을 위한 진단 요청이 도착하면 DM은 GetSeed 메서드를 호출합니다([SWS_DM_00764]). 애플리케이션은 전달된 securityAccessDataRecord을(를) 처리하고 cancellationHandler을(를) 고려하여 계산된 시드를 ara::core::Future<ara::core::Vector<std::uint8_t>>을(를) 통해 비동기식으로 반환합니다([SWS_DM_00764]). 전달된 데이터 span의 버퍼는 promise가 이행되거나 취소될 때까지 유효하게 유지됩니다([SWS_DM_00764]).
  3. 키 유효성 검증: 진단 테스터가 계산된 키를 전송하자마자 DM은 CompareKey을(를) 호출합니다([SWS_DM_00765]). 애플리케이션은 key 매개변수를 확인하고 ara::core::Future<KeyCompareResultType>을(를) 통해 비동기식으로 결과를 전송합니다([SWS_DM_00765]).
  4. 비활성화: 진단 작업을 종료하기 위해 애플리케이션은 StopOffer()을(를) 호출합니다([SWS_DM_00767]).

시퀀스 다이어그램: 활성화부터 GetSeed, CompareKey 및 비활성화까지의 상호 작용 주기. 출처: [SWS_DM_00764], [SWS_DM_00765], [SWS_DM_00766], [SWS_DM_00767]

오류 시나리오

ara::diag::SecurityAccess 사용 시 여러 오류 레벨이 지정되어 있습니다:

  • 생성자 및 모델 위반: 모델에서 InstanceSpecifier을(를) 확인할 수 없거나 PortPrototype을(를) 참조하지 않는 경우 InstanceSpecifierMappingIntegrityViolation이(가) 보고됩니다([SWS_DM_00762]). 참조된 포트가 DiagnosticSecurityLevelInterface에 의해 타입화되지 않은 경우 PortInterfaceMappingViolation이(가) 발생합니다([SWS_DM_00762]). 런타임에 일치하는 모델링된 프로세스가 없으면 ProcessMappingViolation이(가) 발생하고, 프로세스 내에서 동일한 식별자를 여러 번 사용하는 경우 InstanceSpecifierAlreadyInUseViolation이(가) 트리거됩니다([SWS_DM_00762]).
  • 제공(Offer) 시 상태 오류: 서비스 제공이 이미 활성화된 상태에서 Offer()을(를) 다시 호출하면 실패하고 롤백 시맨틱과 함께 DiagOfferErrc::kAlreadyOffered 오류를 반환합니다([SWS_DM_00766]).
  • 부정 UDS 응답: 시드 생성 또는 키 확인이 실패하면 애플리케이션은 DiagUdsNrcErrc을(를) 통해 ISO 14229-1에 따른 적절한 Negative Response Code(NRC)를 보고해야 합니다([SWS_DM_00764], [SWS_DM_00765]).
  • 진단 연결 중단: cancellationHandler 매개변수를 통해 애플리케이션은 IsCanceled()을(를) 사용하여 대화가 중단되었는지 확인하거나, SetNotifier()을(를) 통해 중단에 대한 알림 함수를 등록할 수 있습니다([SWS_DM_00764], [SWS_DM_00765]).
  • 실패한 시도의 영속화: Diagnostic Management는 변조나 리셋 후에도 유지되도록 보안 레벨 변경 시도가 실패할 때마다 카운터를 영속적으로 저장하도록 요구합니다(AUTOSAR_AP_SWS_Diagnostics §4.1 “Limitations of sub-functions of 0x19 ReadDTCInformation”, [SWS_DM_00479]).

사용

클래스 ara::diag::SecurityAccess[SWS_DM_00765]의 순수 가상 메소드 CompareKey은(는) UDS 서비스 0x27 (SecurityAccess)에서 클라이언트가 전송한 키를 검증하기 위해 애플리케이션 측에 구현됩니다SWS Diagnostics §7.3.2.8.9 “Service 0x27 – SecurityAccess”. 이는 GetSeed와(과) 함께 ISO 14229-1에 따른 정적 시드-키 메커니즘의 기반을 형성합니다[SWS_DM_00863].

함수의 파라미터는 다음을 포함합니다:

  • key: 검사할 키 데이터에 대한 ara::core::Span<const std::uint8_t>입니다. 이 버퍼는 연관된 Promise가 충족되거나 실행이 cancellationHandler을(를) 통해 취소될 때까지 유효하게 유지됩니다[SWS_DM_00765].
  • metaInfo: 수신 진단 요청의 메타 정보입니다[SWS_DM_00765].
  • cancellationHandler: cancellationHandler.IsCanceled을(를) 통한 취소 확인 및 대화 취소 시 cancellationHandler.SetNotifier을(를) 통한 알림 함수 등록을 가능하게 합니다[SWS_DM_00765].

검사 결과는 ara::core::Future<KeyCompareResultType>을(를) 통해 비동기식으로 제공됩니다[SWS_DM_00765].

오류 처리 및 상호 작용

키 비교에 실패하거나 처리 중 오류가 발생하면, DiagUdsNrcErrc을(를) 통해 ISO 14229-1에 따른 적절한 Negative Response Code (NRC)가 Future를 통해 전달되어야 합니다[SWS_DM_00765]. 요청된 서브기능이 CompareKey에 대해 구성되지 않은 경우, 요청은 NRC 0x12(kSubFunctionNotSupported)(으)로 응답됩니다[SWS_DM_00363]. Diagnostic Server는 실패한 시도 횟수를 계산하고[SWS_DM_00270] 이를 임계값과 비교합니다[SWS_DM_00271].

보안 접근이 성공적으로 승인되면 서버는 내부적으로 보안 레벨을 업데이트하고[SWS_DM_00846], 실패 시도 카운터를 재설정하며[SWS_DM_00270], 보안 이벤트 SEV_UDS_SECURITY_ACCESS_SUCCESSFUL을(를) IdsM에 보고합니다[SWS_DM_02019].

동시성 및 제약사항

이 인터페이스는 noexcept(으)로 선언되어 있으며 예외 안전(exception safe)합니다[SWS_DM_00765]. 스레드 안전성은 조건부(conditional)입니다. 구현이 스레드 안전해야 하는지 여부는 SecurityAccess의 생성자에서 전달된 ConcurrencyType을(를) 통해 결정됩니다[SWS_DM_00765].
