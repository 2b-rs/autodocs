이벤트 처리를 위한 순환 컨텍스트

OperationCycle은 구성된 운영 주기를 애플리케이션 측에 표시하도록 변경합니다. DM는 이벤트 상태 및 오류 메모리 처리에서 작업 주기를 사용합니다. 따라서 주기는 테스트 결과와 특정 상태 비트가 해석되는 시간적 맥락입니다(SWS Diagnostics §7.3.4.3 “Operation Cycles Management” SWS Diagnostics §7.3.4.1.6 “Event Status processing”).

작업 주기는 이벤트 및 DTC 상태 처리에 대한 시간적 컨텍스트를 제공한다. 인터페이스는 애플리케이션의 주기 변경 사항을 보고한다. 출처: SWS Diagnostics §7.3.4.3 “Operation Cycles Management”, SWS Diagnostics §7.3.4.1.6 “Event Status processing”, SWS Diagnostics §7.3.4.4 “Event memory”. 부분적 해석: 상태 이름은 작업 주기 API의 시간적 역할을 요약한다.

상태 전송으로서의 알리미

SetNotifier는 Operation Cycle 변경을 위한 Callback을 등록하며, 후속 등록은 기존 Callback [SWS_DM_00755]을 대체한다. Notifier 구현은 주기 상태만 수신하거나 자체 검사 경로를 시작 또는 종료해야 하며, Event 상태 비트를 직접 기록해서는 안 된다.

Restart를 의미론적으로 분류

RestartOperationCycle는 작업주기를 다시 시작하라는 명시적인 DM 명령입니다. 이로 인해 어떤 Event/DTC 시퀀스가 ​​발생하는지 여부는 구성된 이벤트 처리에 따라 다릅니다. 따라서 먼저 통지되거나 구성된 주기를 명확하게 할당한 다음 재시작을 사용하십시오. 모니터 작업은 여전히 ​​Monitor를 통해 보고됩니다.
