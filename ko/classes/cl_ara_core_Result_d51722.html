template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

동기식 무예외 결과 전송을 위해 성공 값 또는 오류 값 중 하나를 캡슐화합니다.

이 클래스는 계산 결과를 동기적으로, 그리고 C++ 예외 없이 전송하기 위해 유효 페이로드 값 또는 오류 코드 중 하나를 수용하는 타입 안전 컨테이너를 나타냅니다[SWS_CORE_00751]. 호출자는 전용 생성자 또는 팩토리 함수를 통해 인스턴스를 생성한 다음, 값 또는 오류 접근과 같은 검사 및 접근 함수를 통해 상태에 따라 결과를 평가합니다. 중요한 제약 조건으로서, 기반 오류 타입은 표준 오류 코드와 반드시 일치해야 하며, 일치하지 않는 타입 지정은 컴파일 시점에 거부됩니다. 또한 예외 발생 함수는 C++ 예외가 활성화된 컴파일러 환경을 전제로 합니다[SWS_CORE_00766].

컨텍스트

ara::core::Result 클래스는 C++ 예외를 강제 사용하지 않고 연산 결과를 동기적이고 타입화된 방식으로 반환하기 위한 AUTOSAR Adaptive Platform의 핵심 구문입니다. 이는 특정 시점에 value_type(T) 타입의 유효 페이로드 값 또는 error_type(E) 타입의 오류 중 하나를 포함하는 분리 합집합(Tagged Union)을 나타냅니다[SWS_CORE_00711] [SWS_CORE_00712]. 기본적으로 ara::core::ErrorCode이(가) E의 타입으로 동작하며, 이와 다른 오류 정의는 컴파일 오류를 통해 컴파일 시점에 구현체에 의해 차단됩니다.

애플리케이션 아키텍처에서 ara::core::Result은(는) 호출된 서비스와 소비자 사이를 매개합니다. 서비스는 상태를 반환하기 위해 객체를 인스턴스화하는 반면, 소비자는 [SWS_CORE_00751]과(와) 같은 상태 테스트 또는 [SWS_CORE_00768]과(와) 같은 함수형 체이닝을 통해 후속 처리를 시작합니다. 또한 상태는 [SWS_CORE_00770](Ok) 및 [SWS_CORE_00772](Err)을(를) 통해 ara::core::Optional(으)로 변환될 수 있습니다.

수명 주기

인스턴스의 초기화는 값에 대한 생성자([SWS_CORE_00721], [SWS_CORE_00722])를 통해 직접 수행되거나 오류에 대해 명시적으로([SWS_CORE_00723], [SWS_CORE_00724]) 수행됩니다. 또한 정적 팩토리 함수도 제공됩니다. 즉, lvalue, rvalue 및 인플레이스 인수를 위한 FromValue([SWS_CORE_00731], [SWS_CORE_00732], [SWS_CORE_00733]) 및 오류 상태 생성을 위한 FromError([SWS_CORE_00734], [SWS_CORE_00735], [SWS_CORE_00736])이(가) 있습니다.

ara::core::Result은(는) 포함된 데이터를 독점적으로 소유하고 수명을 관리합니다. 이는 복사 및 이동 생성자([SWS_CORE_00725], [SWS_CORE_00726])와 해당 할당 연산자([SWS_CORE_00741], [SWS_CORE_00742])를 통한 완전한 값 의미론을 지원합니다. 기존 인스턴스의 내용 변경은 Swap [SWS_CORE_00745]을(를) 사용하거나 EmplaceValue [SWS_CORE_00743] 또는 EmplaceError [SWS_CORE_00744]을(를) 통한 인플레이스 덮어쓰기로 가능합니다.

소멸자는 활성 요소를 해제하며, T과(와) E이(가) 모두 트리비얼하게 소멸 가능한 경우 트리비얼하게 소멸 가능한 것으로 간주됩니다[SWS_CORE_00727]. 동시성과 관련하여 순수 읽기 접근은 스레드 안전하지만, EmplaceValue, EmplaceError, 이동 할당 또는 Swap과(와) 같은 수정 작업은 스레드 안전하지 않으며 외부 동기화가 필요합니다.

상태 다이어그램: Result 인스턴스의 수명 동안 값 상태와 오류 상태 간의 상태 전이. 출처: [SWS_CORE_00721], [SWS_CORE_00723], [SWS_CORE_00743], [SWS_CORE_00744], [SWS_CORE_00727]

사용 경로

정상적인 흐름은 결과의 생성, 유효성 검사 및 추출로 구성됩니다:

  1. 제공: 서비스는 [SWS_CORE_00731] 또는 [SWS_CORE_00734]을(를) 통해 결과를 생성하고 인스턴스를 값으로 반환합니다.
  2. 상태 검사: 호출자는 HasValue() [SWS_CORE_00751] 또는 명시적 변환 연산자 operator bool() [SWS_CORE_00752]을(를) 사용하여 값이 존재하는지 확인합니다. 후자는 T 자체가 bool 타입인 경우 비활성화됩니다.
  3. 값 및 오류 접근: 값이 존재하는 경우, Value()([SWS_CORE_00755], [SWS_CORE_00756], [SWS_CORE_00775]) 또는 연산자 operator*([SWS_CORE_00753], [SWS_CORE_00759]) 및 operator->([SWS_CORE_00754], [SWS_CORE_00777])을(를) 통해 이를 읽을 수 있습니다. 오류가 발생한 경우 접근은 Error()([SWS_CORE_00757], [SWS_CORE_00758], [SWS_CORE_00776]) 또는 CheckError() [SWS_CORE_00765]을(를) 사용한 표적 오류 검사를 통해 수행됩니다.
  4. 함수형 변환: 대안적으로 Bind() [SWS_CORE_00768]은(는) 모나드 방식의 후속 처리를 허용합니다. 즉, 전달된 Callable은 유효 페이로드 값이 포함된 경우에만 실행되며, 기존 오류는 새로운 Result 인스턴스로 변경 없이 전파됩니다. 폴백은 Resolve() [SWS_CORE_00767](으)로 구성할 수 있습니다.

시퀀스 다이어그램: Result 인스턴스 쿼리 및 평가 시의 일반적인 호출 흐름. 출처: [SWS_CORE_00731], [SWS_CORE_00751], [SWS_CORE_00755], [SWS_CORE_00757], [SWS_CORE_00768]

오류 시나리오

활성 상태가 아닌 상태에 접근하는 것은 클래스의 선행 조건을 위반합니다:

  • 포함된 값 없이 Value(), operator* 또는 operator->을(를) 호출하면 문서화된 시스템 위반인 ResultWithNoValueViolation이(가) 트리거됩니다([SWS_CORE_00755], [SWS_CORE_00753], [SWS_CORE_00754]).
  • 유효 페이로드 값이 존재하는 상태에서 Error()을(를) 호출하면 위반 ResultWithNoErrorViolation이(가) 발생합니다([SWS_CORE_00757], [SWS_CORE_00776]).

해석: 표준에서는 이러한 상태를 심각한 프로그래밍 오류로 분류하므로, 런타임 환경에서 이러한 선행 조건 위반이 발생하면 일반적으로 프로세스가 즉시 중단될 것으로 추정됩니다. 하드 중단을 방지하기 위해 방어적 메서드를 사용할 수 있습니다. ValueOr()([SWS_CORE_00761], [SWS_CORE_00762]) 및 ErrorOr()([SWS_CORE_00763], [SWS_CORE_00764])은(는) 요소가 없을 때 지정된 기본값을 반환합니다. Ok()([SWS_CORE_00770], [SWS_CORE_00771]) 및 Err()([SWS_CORE_00772], [SWS_CORE_00773])과(와) 같은 선택적 변형은 예외 없이 접근을 캡슐화합니다.

예외 처리가 필요한 경우, ValueOrThrow()([SWS_CORE_00766], [SWS_CORE_00769], [SWS_CORE_00778])은(는) 오류 발생 시 해당 오류에 할당된 C++ 예외를 발생시킵니다. 컴파일러에서 C++ 예외가 비활성화된 경우 ValueOrThrow()은(는) 오버로드 확인에서 제거됩니다[SWS_CORE_00766]. 마찬가지로 operator*의 비상수 lvalue 오버로드도 이 경우 비활성화됩니다[SWS_CORE_00774].

이 가이드는 AUTOSAR Adaptive R25-11의 규격 요구사항을 기반으로 AI 큐레이션 어시스턴트에 의해 생성되었습니다.
