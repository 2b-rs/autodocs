Kontext

Die Template-Klasse ara::core::Result stellt einen Werttyp dar, der entweder ein erfolgreiches Ergebnis vom Typ value_type (T) ([SWS_CORE_00711]) oder einen Fehler vom Typ error_type (E) ([SWS_CORE_00712]) enthält. Standardmäßig ist E = ErrorCode festgelegt. Weicht der Fehlertyp ab (E != ara::core::ErrorCode), fordert die Spezifikation zwingend einen Compilerfehler.

Als zentrales Idiom der AUTOSAR Adaptive Platform dient ara::core::Result der fehlerrobusten Rückgabe von Werten aus Schnittstellenaufrufen, ohne dabei auf C++-Exceptions angewiesen zu sein. Aufrufer und Dienste interagieren über diesen Typen, indem der Erzeuger den Zustand festlegt und der Empfänger den enthaltenen Zustand entweder direkt prüft, transformiert oder auflöst.

Lebenszyklus

Eine Instanz von ara::core::Result befindet sich zu jedem Zeitpunkt in genau einem von zwei disjunkten Zuständen: Sie enthält entweder einen gültigen Wert oder einen Fehler. Die Erzeugung erfolgt entweder über direkte Konstruktoren für Werte ([SWS_CORE_00721], [SWS_CORE_00722]) bzw. Fehler ([SWS_CORE_00723], [SWS_CORE_00724]) oder über explizite statische Fabriken:

  • FromValue: Erzeugt eine Instanz aus einem Lvalue, Rvalue oder konstruiert den Wert direkt in-place anhand übergebener Argumente ([SWS_CORE_00731], [SWS_CORE_00732], [SWS_CORE_00733]).
  • FromError: Erzeugt eine Instanz aus einem Fehler-Lvalue, Rvalue oder in-place via Argumentenpack ([SWS_CORE_00734], [SWS_CORE_00735], [SWS_CORE_00736]).

Bestehende Instanzen können per Kopie oder Move übertragen ([SWS_CORE_00725], [SWS_CORE_00726], [SWS_CORE_00741], [SWS_CORE_00742]) oder mittels Swap ausgetauscht werden ([SWS_CORE_00745]). Ein nachträglicher Zustandswechsel innerhalb einer bestehenden Instanz ist über EmplaceValue ([SWS_CORE_00743]) bzw. EmplaceError ([SWS_CORE_00744]) möglich, welche den bisherigen Inhalt verwerfen und das neue Element in-place konstruieren.

Der Destruktor ~Result() ([SWS_CORE_00727]) gibt den jeweils enthaltenen Wert oder Fehler frei; er ist trivial, falls sowohl T als auch E trivial destruierbar sind. Lesende Zugriffe sind thread-safe, während modifizierende Operationen (wie EmplaceValue, EmplaceError, Rvalue-Extraktionen und Zuweisungen) nicht thread-safe sind.

Nutzungspfad

Die typische Verarbeitung eines erhaltenen ara::core::Result folgt einer festen Abfolge aus Zustandsprüfung, gezieltem Wert- oder Fehlerzugriff bzw. funktionaler Weiterschaltung:

  1. Zustandsprüfung: Der Aufrufer prüft über HasValue() ([SWS_CORE_00751]) oder den Konvertierungsoperator operator bool() ([SWS_CORE_00752]), ob ein Ergebniswert vorliegt. Der bool-Operator ist dabei deaktiviert, falls T selbst der Typ bool ist.
  2. Direkter Wertzugriff: Liegt ein Wert vor, erfolgt der Zugriff über Value() ([SWS_CORE_00755], [SWS_CORE_00756], [SWS_CORE_00775]) oder zeigerähnliche Operatoren wie operator* ([SWS_CORE_00753], [SWS_CORE_00759], [SWS_CORE_00774]) und operator-> ([SWS_CORE_00754], [SWS_CORE_00777]).
  3. Fehlerbehandlung: Liegt kein Wert vor, kann der Fehler über Error() ([SWS_CORE_00757], [SWS_CORE_00758], [SWS_CORE_00776]) ausgelesen oder mittels CheckError() ([SWS_CORE_00765]) direkt auf Gleichheit mit einem erwarteten Fehler verglichen werden.
  4. Verkettung und Transformation: Über Bind ([SWS_CORE_00768]) kann eine Transformation (Callable) auf den enthaltenen Wert angewendet werden. Liegt ein Wert vor, liefert Bind das transformierte neue ara::core::Result zurück; liegt ein Fehler vor, wird dieser direkt in das neue Result übernommen. Alternativ erlaubt Resolve ([SWS_CORE_00767]), einen Fehler durch den Rückgabewert eines Callables aufzulösen.
  5. Optionale Konvertierung: Über Ok() ([SWS_CORE_00770], [SWS_CORE_00771]) und Err() ([SWS_CORE_00772], [SWS_CORE_00773]) können Wert bzw. Fehler als ara::core::Optional extrahiert werden.

Fehlerszenarien

Beim Aufruf von Zugriffsmethoden sind strikte Vorbedingungen definiert, deren Nichteinhaltung zu standardisierten Verletzungen führt:

  • ResultWithNoValueViolation: Tritt auf, wenn auf den Wert via Value() ([SWS_CORE_00755], [SWS_CORE_00756], [SWS_CORE_00775]), operator* ([SWS_CORE_00753], [SWS_CORE_00759], [SWS_CORE_00774]) oder operator-> ([SWS_CORE_00754], [SWS_CORE_00777]) zugegriffen wird, obwohl die Instanz keinen Wert enthält.
  • ResultWithNoErrorViolation: Tritt auf, wenn über Error() ([SWS_CORE_00757], [SWS_CORE_00758], [SWS_CORE_00776]) ein Fehler abgefragt wird, die Instanz jedoch einen gültigen Wert hält.

Um Verletzungen ohne vorherige Verzweigung zu vermeiden, bieten ValueOr ([SWS_CORE_00761], [SWS_CORE_00762]) und ErrorOr ([SWS_CORE_00763], [SWS_CORE_00764]) die Rückgabe eines übergebenen Standardwerts bzw. Standardfehlers bei fehlendem Inhalt.

Soll ein Fehlercode in eine C++-Exception überführt werden, steht ValueOrThrow() ([SWS_CORE_00766], [SWS_CORE_00769], [SWS_CORE_00778]) bereit. Diese Methode wirft den mit dem Fehler assoziierten Exception-Typ, sofern kein Wert vorliegt. Sind C++-Exceptions in der Compiler-Toolchain deaktiviert, nimmt ValueOrThrow() nicht an der Überladungsauflösung teil.

Dieser Leitfaden basiert ausschließlich auf den Spezifikationsanforderungen von AUTOSAR Adaptive Platform Release R25-11.

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Result</code> stellt einen Werttyp dar, der entweder ein erfolgreiches Ergebnis vom Typ <code>value_type</code> (<code>T</code>) (<a class="spec-record-ref" data-req="SWS_CORE_00711" href="../spec/record.html?id=SWS_CORE_00711">[SWS_CORE_00711]</a>) oder einen Fehler vom Typ <code>error_type</code> (<code>E</code>) (<a class="spec-record-ref" data-req="SWS_CORE_00712" href="../spec/record.html?id=SWS_CORE_00712">[SWS_CORE_00712]</a>) enthält. Standardmäßig ist <code>E = ErrorCode</code> festgelegt. Weicht der Fehlertyp ab (<code>E != ara::core::ErrorCode</code>), fordert die Spezifikation zwingend einen Compilerfehler.</p>
<p>Als zentrales Idiom der AUTOSAR Adaptive Platform dient <code>ara::core::Result</code> der fehlerrobusten Rückgabe von Werten aus Schnittstellenaufrufen, ohne dabei auf C++-Exceptions angewiesen zu sein. Aufrufer und Dienste interagieren über diesen Typen, indem der Erzeuger den Zustand festlegt und der Empfänger den enthaltenen Zustand entweder direkt prüft, transformiert oder auflöst.</p>

<h4>Lebenszyklus</h4>
<p>Eine Instanz von <code>ara::core::Result</code> befindet sich zu jedem Zeitpunkt in genau einem von zwei disjunkten Zuständen: Sie enthält entweder einen gültigen Wert oder einen Fehler. Die Erzeugung erfolgt entweder über direkte Konstruktoren für Werte (<a class="spec-record-ref" data-req="SWS_CORE_00721" href="../spec/record.html?id=SWS_CORE_00721">[SWS_CORE_00721]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00722" href="../spec/record.html?id=SWS_CORE_00722">[SWS_CORE_00722]</a>) bzw. Fehler (<a class="spec-record-ref" data-req="SWS_CORE_00723" href="../spec/record.html?id=SWS_CORE_00723">[SWS_CORE_00723]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00724" href="../spec/record.html?id=SWS_CORE_00724">[SWS_CORE_00724]</a>) oder über explizite statische Fabriken:</p>
<ul>
<li><code>FromValue</code>: Erzeugt eine Instanz aus einem Lvalue, Rvalue oder konstruiert den Wert direkt in-place anhand übergebener Argumente (<a class="spec-record-ref" data-req="SWS_CORE_00731" href="../spec/record.html?id=SWS_CORE_00731">[SWS_CORE_00731]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00732" href="../spec/record.html?id=SWS_CORE_00732">[SWS_CORE_00732]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00733" href="../spec/record.html?id=SWS_CORE_00733">[SWS_CORE_00733]</a>).</li>
<li><code>FromError</code>: Erzeugt eine Instanz aus einem Fehler-Lvalue, Rvalue oder in-place via Argumentenpack (<a class="spec-record-ref" data-req="SWS_CORE_00734" href="../spec/record.html?id=SWS_CORE_00734">[SWS_CORE_00734]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00735" href="../spec/record.html?id=SWS_CORE_00735">[SWS_CORE_00735]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00736" href="../spec/record.html?id=SWS_CORE_00736">[SWS_CORE_00736]</a>).</li>
</ul>
<p>Bestehende Instanzen können per Kopie oder Move übertragen (<a class="spec-record-ref" data-req="SWS_CORE_00725" href="../spec/record.html?id=SWS_CORE_00725">[SWS_CORE_00725]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00726" href="../spec/record.html?id=SWS_CORE_00726">[SWS_CORE_00726]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00741" href="../spec/record.html?id=SWS_CORE_00741">[SWS_CORE_00741]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00742" href="../spec/record.html?id=SWS_CORE_00742">[SWS_CORE_00742]</a>) oder mittels <code>Swap</code> ausgetauscht werden (<a class="spec-record-ref" data-req="SWS_CORE_00745" href="../spec/record.html?id=SWS_CORE_00745">[SWS_CORE_00745]</a>). Ein nachträglicher Zustandswechsel innerhalb einer bestehenden Instanz ist über <code>EmplaceValue</code> (<a class="spec-record-ref" data-req="SWS_CORE_00743" href="../spec/record.html?id=SWS_CORE_00743">[SWS_CORE_00743]</a>) bzw. <code>EmplaceError</code> (<a class="spec-record-ref" data-req="SWS_CORE_00744" href="../spec/record.html?id=SWS_CORE_00744">[SWS_CORE_00744]</a>) möglich, welche den bisherigen Inhalt verwerfen und das neue Element in-place konstruieren.</p>
<p>Der Destruktor <code>~Result()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00727" href="../spec/record.html?id=SWS_CORE_00727">[SWS_CORE_00727]</a>) gibt den jeweils enthaltenen Wert oder Fehler frei; er ist trivial, falls sowohl <code>T</code> als auch <code>E</code> trivial destruierbar sind. Lesende Zugriffe sind thread-safe, während modifizierende Operationen (wie <code>EmplaceValue</code>, <code>EmplaceError</code>, Rvalue-Extraktionen und Zuweisungen) nicht thread-safe sind.</p>

<h4>Nutzungspfad</h4>
<p>Die typische Verarbeitung eines erhaltenen <code>ara::core::Result</code> folgt einer festen Abfolge aus Zustandsprüfung, gezieltem Wert- oder Fehlerzugriff bzw. funktionaler Weiterschaltung:</p>
<ol>
<li><strong>Zustandsprüfung:</strong> Der Aufrufer prüft über <code>HasValue()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00751" href="../spec/record.html?id=SWS_CORE_00751">[SWS_CORE_00751]</a>) oder den Konvertierungsoperator <code>operator bool()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00752" href="../spec/record.html?id=SWS_CORE_00752">[SWS_CORE_00752]</a>), ob ein Ergebniswert vorliegt. Der bool-Operator ist dabei deaktiviert, falls <code>T</code> selbst der Typ <code>bool</code> ist.</li>
<li><strong>Direkter Wertzugriff:</strong> Liegt ein Wert vor, erfolgt der Zugriff über <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00756" href="../spec/record.html?id=SWS_CORE_00756">[SWS_CORE_00756]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00775" href="../spec/record.html?id=SWS_CORE_00775">[SWS_CORE_00775]</a>) oder zeigerähnliche Operatoren wie <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00759" href="../spec/record.html?id=SWS_CORE_00759">[SWS_CORE_00759]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00774" href="../spec/record.html?id=SWS_CORE_00774">[SWS_CORE_00774]</a>) und <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00777" href="../spec/record.html?id=SWS_CORE_00777">[SWS_CORE_00777]</a>).</li>
<li><strong>Fehlerbehandlung:</strong> Liegt kein Wert vor, kann der Fehler über <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00758" href="../spec/record.html?id=SWS_CORE_00758">[SWS_CORE_00758]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>) ausgelesen oder mittels <code>CheckError()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00765" href="../spec/record.html?id=SWS_CORE_00765">[SWS_CORE_00765]</a>) direkt auf Gleichheit mit einem erwarteten Fehler verglichen werden.</li>
<li><strong>Verkettung und Transformation:</strong> Über <code>Bind</code> (<a class="spec-record-ref" data-req="SWS_CORE_00768" href="../spec/record.html?id=SWS_CORE_00768">[SWS_CORE_00768]</a>) kann eine Transformation (Callable) auf den enthaltenen Wert angewendet werden. Liegt ein Wert vor, liefert <code>Bind</code> das transformierte neue <code>ara::core::Result</code> zurück; liegt ein Fehler vor, wird dieser direkt in das neue <code>Result</code> übernommen. Alternativ erlaubt <code>Resolve</code> (<a class="spec-record-ref" data-req="SWS_CORE_00767" href="../spec/record.html?id=SWS_CORE_00767">[SWS_CORE_00767]</a>), einen Fehler durch den Rückgabewert eines Callables aufzulösen.</li>
<li><strong>Optionale Konvertierung:</strong> Über <code>Ok()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00770" href="../spec/record.html?id=SWS_CORE_00770">[SWS_CORE_00770]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00771" href="../spec/record.html?id=SWS_CORE_00771">[SWS_CORE_00771]</a>) und <code>Err()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00772" href="../spec/record.html?id=SWS_CORE_00772">[SWS_CORE_00772]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00773" href="../spec/record.html?id=SWS_CORE_00773">[SWS_CORE_00773]</a>) können Wert bzw. Fehler als <code>ara::core::Optional</code> extrahiert werden.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Beim Aufruf von Zugriffsmethoden sind strikte Vorbedingungen definiert, deren Nichteinhaltung zu standardisierten Verletzungen führt:</p>
<ul>
<li><strong><code>ResultWithNoValueViolation</code>:</strong> Tritt auf, wenn auf den Wert via <code>Value()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00755" href="../spec/record.html?id=SWS_CORE_00755">[SWS_CORE_00755]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00756" href="../spec/record.html?id=SWS_CORE_00756">[SWS_CORE_00756]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00775" href="../spec/record.html?id=SWS_CORE_00775">[SWS_CORE_00775]</a>), <code>operator*</code> (<a class="spec-record-ref" data-req="SWS_CORE_00753" href="../spec/record.html?id=SWS_CORE_00753">[SWS_CORE_00753]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00759" href="../spec/record.html?id=SWS_CORE_00759">[SWS_CORE_00759]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00774" href="../spec/record.html?id=SWS_CORE_00774">[SWS_CORE_00774]</a>) oder <code>operator-&gt;</code> (<a class="spec-record-ref" data-req="SWS_CORE_00754" href="../spec/record.html?id=SWS_CORE_00754">[SWS_CORE_00754]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00777" href="../spec/record.html?id=SWS_CORE_00777">[SWS_CORE_00777]</a>) zugegriffen wird, obwohl die Instanz keinen Wert enthält.</li>
<li><strong><code>ResultWithNoErrorViolation</code>:</strong> Tritt auf, wenn über <code>Error()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00757" href="../spec/record.html?id=SWS_CORE_00757">[SWS_CORE_00757]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00758" href="../spec/record.html?id=SWS_CORE_00758">[SWS_CORE_00758]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00776" href="../spec/record.html?id=SWS_CORE_00776">[SWS_CORE_00776]</a>) ein Fehler abgefragt wird, die Instanz jedoch einen gültigen Wert hält.</li>
</ul>
<p>Um Verletzungen ohne vorherige Verzweigung zu vermeiden, bieten <code>ValueOr</code> (<a class="spec-record-ref" data-req="SWS_CORE_00761" href="../spec/record.html?id=SWS_CORE_00761">[SWS_CORE_00761]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00762" href="../spec/record.html?id=SWS_CORE_00762">[SWS_CORE_00762]</a>) und <code>ErrorOr</code> (<a class="spec-record-ref" data-req="SWS_CORE_00763" href="../spec/record.html?id=SWS_CORE_00763">[SWS_CORE_00763]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00764" href="../spec/record.html?id=SWS_CORE_00764">[SWS_CORE_00764]</a>) die Rückgabe eines übergebenen Standardwerts bzw. Standardfehlers bei fehlendem Inhalt.</p>
<p>Soll ein Fehlercode in eine C++-Exception überführt werden, steht <code>ValueOrThrow()</code> (<a class="spec-record-ref" data-req="SWS_CORE_00766" href="../spec/record.html?id=SWS_CORE_00766">[SWS_CORE_00766]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00769" href="../spec/record.html?id=SWS_CORE_00769">[SWS_CORE_00769]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00778" href="../spec/record.html?id=SWS_CORE_00778">[SWS_CORE_00778]</a>) bereit. Diese Methode wirft den mit dem Fehler assoziierten Exception-Typ, sofern kein Wert vorliegt. Sind C++-Exceptions in der Compiler-Toolchain deaktiviert, nimmt <code>ValueOrThrow()</code> nicht an der Überladungsauflösung teil.</p>
