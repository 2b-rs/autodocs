클래스 ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

자동으로 생성된 설명, 참조된 AUTOSAR R25-11 문서(SWS 사양 및 관련 표준 문서)에서 파생된 콘텐츠 — 공식 AUTOSAR 텍스트가 아닙니다. 해석으로 표시된 진술은 출처에서 도출된 결론이다.

사용 목적

동기 호출의 경우 ara::core::Result<T,E>는 T 유형의 값 또는 E 유형의 오류를 캡슐화합니다. E는 ara::core::ErrorCode여야 합니다. 따라서 이 유형은 예외 없는 오류 처리를 지원합니다. [SWS_CORE_00701] [SWS_CORE_10600]

세대 및 수명주기

Result는 FromValue() 및 FromError()뿐만 아니라 값이나 오류에서도 생성될 수 있습니다. 복사 및 이동 작업이 가능하며 조건부 noexcept; 소멸자의 사소함은 T 및 E에 따라 달라집니다. [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

다른 클래스와의 상호작용

HasValue(), Value(), Error(), Ok() 및 Err()는 상태 및 콘텐츠 액세스를 허용합니다. Bind()은 Callable이 포함된 값을 새로운 Result로 변환하고, Resolve()는 오류가 발생한 경우 함수를 호출합니다. [SWS_CORE_00751] [SWS_CORE_00755] [SWS_CORE_00757] [SWS_CORE_00770] [SWS_CORE_00772] [SWS_CORE_00768] [SWS_CORE_00767]

제한 사항 및 오류 처리

포함된 오류가 없는 오류 또는 포함된 값이 없는 값에 대한 액세스는 위반으로 정의된다. ValueOrThrow()는 트리거할 수 있으며 ara::core 초기화 없이 사용이 면제되는 유일한 결과 함수이다. [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

예외 없는 오류 경로의 역할

복구 가능한 오류의 경우 인터페이스는 ara::core::Result 또는 ara::core::Future를 사용해야 한다. Result 오류 유형은 ara::core::ErrorCode로 설정된다. RS General §4.1.2 “Error handling” EXP InterfacesGuidelines §3.1.2 “Result”

예외 없는 접근에서는 호출자가 HasValue()을 확인한 다음 Value() 또는 Error()를 읽는다. 이 Observer는 C++ Exceptions 없이 사용할 수 있지만, ValueOrThrow()은 예외 기반 경로로의 명시적 전환이다. EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result” RS General §4.1.3 “The use of noexcept”

활동 다이어그램: 일반적인 예외 없는 흐름은 HasValue() 이후 값이나 오류로 분기됩니다. ValueOrThrow()은 선택적으로 표시되는 예외 경로입니다. 출처: EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result”.

규범적 핵심: 가치 또는 오류

핵심 사양은 Result를 오류 처리 모델에 매핑한다. 복구 가능한 오류의 경우 API는 Result 또는 Future를 반환해야 한다. 따라서 Result는 데이터 값으로 전송되는 오류와 일반 값 경로를 분리한다. SWS Core §7.2 “Error handling” SWS Core §7.2.5.4 “Result”

template <typename F> auto Bind (F &&f) const -> <see below>;

Apply the given Callable to the value of this instance, and return a new ara::core:: Result with the result of the call.

The Callable is expected to be compatible to one of these two interfaces: • Result<XXX, E> f(const T&); • <ARTechTerm{XXX f(const T&);}> • <ARNewline{}> • <ARNewline{}> • <ARTechTerm{Callable}> • Result<XXX> or a XXX directly, where XXX can be any type that is suitable for use by ara::core::Result.

The return type of this function is decltype(f(Value())) for a template argument F that returns a ara::core::Result type, and it is Result<decltype(f(Value())), E> for a template argument F that does not return a ara::core::Result type.

If this instance does not contain a value, a new Result<XXX, E> is still created and returned, with the original error contents of this instance being copied into the new instance.}>}
