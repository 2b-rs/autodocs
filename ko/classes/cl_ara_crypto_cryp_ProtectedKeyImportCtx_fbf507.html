애플리케이션에서 보호된 암호화 키 및 데이터의 안전한 압축 해제 및 가져오기에 사용됩니다.

이 인터페이스는 구성된 전송 키 [SWS_CRYPT_50205]을(를) 사용하여 보호된 암호화 데이터 및 키를 안전하게 압축 해제하고 가져오는 것을 가능하게 합니다. 압축 해제된 키 자료는 영구 키 슬롯에 직접 기록되거나 타입화된 키 객체로서 메모리에 로드될 수 있습니다 [SWS_CRYPT_50207]. 모든 메서드는 스레드 안전하게 작동하고 엄격한 롤백 오류 시맨틱을 따르며, Reset은(는) 내부 버퍼의 잔여물 없는 삭제를 보장합니다 [SWS_CRYPT_50212].

컨텍스트

인터페이스 ara::crypto::cryp::ProtectedKeyImportCtx은(는) 비밀 키 자료와 같은 보호된 데이터 구조를 시스템으로 안전하게 가져오고 압축 해제하기 위한 암호화 컨텍스트를 제공합니다. 컨텍스트는 요청하는 애플리케이션, 전송 키 기반 보호 메커니즘 및 AUTOSAR 암호화의 대상 구조 간의 중재자 역할을 합니다. 들어오는 직렬화된 데이터 패킷은 컨텍스트에 의해 인증, 복호화 및 파싱됩니다 [SWS_CRYPT_50207]. 필요한 전송 키의 소스로는 독립적인 대칭 키 객체 [SWS_CRYPT_50205] 또는 키 스토리지의 키 슬롯 [SWS_CRYPT_50206]이(가) 사용됩니다. 싱크로는 압축 해제된 키 객체가 호출 애플리케이션에 직접 전달되거나 쓰기 가능한 키 슬롯으로 즉시 직렬화될 수 있습니다 [SWS_CRYPT_50207].

수명 주기

컨텍스트는 공유 액세스를 위해 일반적으로 제공된 스마트 포인터 타입 Sptr을(를) 통해 관리되며 [SWS_CRYPT_50085], 인스턴스는 담당 크립토 드라이버 컴포넌트에 의해 제공될 것으로 추정됩니다. 질문 Q-3517b24b5eec4529 (열림) 실제 처리 전에 컨텍스트는 아직 전송 키가 할당되지 않은 미구성 초기 상태에 있습니다. 전송 키 할당은 SetKey 메서드를 통해 수행되며, 이를 통해 컨텍스트가 작동 준비 상태로 전환됩니다 [SWS_CRYPT_50205] [SWS_CRYPT_50206].

Import 작업이 성공적으로 실행된 후 컨텍스트는 압축 해제된 데이터 및 메타데이터를 내부 버퍼에 유지하므로 객체 타입을 식별하고 키 객체를 읽어올 수 있습니다 [SWS_CRYPT_50207] [SWS_CRYPT_50208]. Reset 메서드를 통해 컨텍스트는 다시 초기 상태로 복원됩니다. 이전에 가져온 데이터가 있는 모든 내부 버퍼가 완전히 정리되고 저장된 전송 키가 제거됩니다 [SWS_CRYPT_50212]. 모든 인터페이스 메서드는 예외 안전 및 스레드 안전으로 지정되어 여러 실행 컨텍스트의 동시 액세스를 제어 가능한 상태로 유지합니다 [SWS_CRYPT_50207].

상태 다이어그램: 구성에서 가져오기 및 정리까지 컨텍스트의 수명 주기 단계. 출처: [SWS_CRYPT_50205], [SWS_CRYPT_50206], [SWS_CRYPT_50207], [SWS_CRYPT_50212]

사용 경로

일반적인 워크플로는 전송 키 구성으로 시작됩니다. 이를 위해 애플리케이션은 SymmetricKey::Sptr [SWS_CRYPT_50205] 또는 KeySlot::Sptr [SWS_CRYPT_50206]과(와) 함께 SetKey을(를) 호출합니다. 다음 단계에서는 직렬화된 데이터 패킷이 ReadOnlyMemRegion(으)로 전달되는 Import 메서드가 실행됩니다 [SWS_CRYPT_50207]. 키를 영구적으로 저장해야 하는 경우, 선택적으로 압축 해제된 자료가 기록될 WriteableKeySlot::Sptr을(를) 직접 전달할 수 있습니다 [SWS_CRYPT_50207].

대상 슬롯이 지정되지 않았거나 키를 휘발성으로 사용해야 하는 경우, 애플리케이션은 GetCryptoObjectType을(를) 통해 마지막으로 가져온 객체의 카테고리를 확인합니다 [SWS_CRYPT_50208]. 이 타입에 따라 애플리케이션은 타입에 맞는 조회 메서드를 호출합니다. 즉, 개인 키의 경우 GetPrivateKey [SWS_CRYPT_50209], 공개 키의 경우 GetPublicKey [SWS_CRYPT_50211], 대칭 키 자료의 경우 GetSymmetricKey입니다 [SWS_CRYPT_50210]. 사용된 가져오기 프로토콜이 발신자에게 피드백을 요구하는 경우(예: SHE-LoadKey 시퀀스의 제어 블록 M4 및 M5의 경우), 이는 GetResponse을(를) 통해 제공된 버퍼에 기록될 수 있습니다 [SWS_CRYPT_41020]. 처리 시퀀스가 완료된 후 Reset을(를) 호출하면 컨텍스트가 다시 초기 상태로 복원됩니다 [SWS_CRYPT_50212].

시퀀스 다이어그램: 키 자료 가져오기 및 조회 시의 전형적인 호출 순서. 출처: [SWS_CRYPT_50205], [SWS_CRYPT_50207], [SWS_CRYPT_50208], [SWS_CRYPT_50210], [SWS_CRYPT_50212]

오류 시나리오

메서드 호출 중 오류가 발생하면 호출 전의 상태를 유지하는 엄격한 롤백 시맨틱이 적용됩니다. SetKey을(를) 통한 구성 시 키의 사용 플래그에 kAllowKeyUnwrapping 권한이 포함되어 있지 않으면 호출이 CryptoErrc::kUsageViolation(으)로 실패합니다 [SWS_CRYPT_50205] [SWS_CRYPT_50206]. 키 객체 또는 참조된 슬롯이 기본적으로 전송 키로 사용할 수 없는 경우 CryptoErrc::kIncompatibleObject이(가) 보고됩니다 [SWS_CRYPT_50205] [SWS_CRYPT_50206].

Import 호출 시 입력 데이터의 크기 불일치는 CryptoErrc::kInvalidInputSize을(를) 초래하고 형식 위반은 CryptoErrc::kInvalidArgument을(를) 초래합니다 [SWS_CRYPT_50207]. 보호 계층의 무결성 또는 신뢰성 검사가 실패하면(예: 유효하지 않은 메시지 인증 코드 또는 잘못된 서명으로 인해) 호출은 CryptoErrc::kAuthTagNotValid을(를) 반환합니다 [SWS_CRYPT_50207]. 암호화 컴포넌트가 일시적으로 사용 중인 경우 CryptoErrc::kBusyResource을(를) 통해 신호가 전달됩니다 [SWS_CRYPT_50207].

가져온 키를 읽기 위한 사전 조건은 Import의 성공적인 실행이며, 그렇지 않으면 GetPrivateKey, GetPublicKey 및 GetSymmetricKey은(는) CryptoErrc::kProcessingNotFinished [SWS_CRYPT_50209] [SWS_CRYPT_50210] [SWS_CRYPT_50211](으)로 응답합니다. 요청된 키 타입이 실제로 압축 해제된 객체와 일치하지 않거나 아직 객체를 가져오지 않은 경우, 조회 메서드는 CryptoErrc::kNoSuchValue [SWS_CRYPT_50208] [SWS_CRYPT_50209] [SWS_CRYPT_50210] [SWS_CRYPT_50211](으)로 이를 알립니다. 출력 버퍼가 GetResponse에서 충분한 용량을 제공하지 못하면 CryptoErrc::kInsufficientCapacity이(가) 발생합니다 [SWS_CRYPT_41020]. 구체적인 구현이 부분 기능을 지원하지 않는 경우(예: 특정 키 타입 또는 재설정), 일관되게 CryptoErrc::kUnsupported이(가) 반환됩니다 [SWS_CRYPT_50205] [SWS_CRYPT_50208] [SWS_CRYPT_50212].
