컨텍스트

클래스 ara::crypto::cryp::ProtectedKeyImportCtx은(는) 암호화 키 및 관련 메타데이터의 안전한 로드 및 압축 해제를 위한 특화된 인터페이스를 정의합니다([SWS_CRYPT_50207]). 이는 키 자료를 보호되거나 암호화 또는 인증된 형식(예: 래핑된 키 토큰)으로 애플리케이션 환경에 전송하고 배포해야 할 때 사용됩니다.

다른 컴포넌트와의 상호작용에서 컨텍스트는 처리 애플리케이션, 암호화 소스 및 전송 구조, 그리고 결과로 생성되는 키 객체 간의 인터페이스 역할을 합니다:

  • 전송 키: 데이터의 복호화 및 인증을 위해 컨텍스트에는 전송 키가 필요합니다. 이는 대칭 키 객체 ara::crypto::cryp::SymmetricKey(으)로 직접 전달되거나([SWS_CRYPT_50205]), ara::crypto::keys::KeySlot을(를) 통해 참조됩니다([SWS_CRYPT_50206]).
  • 입력 데이터: 보호되고 직렬화된 키 데이터는 읽기 전용 메모리 영역(ReadOnlyMemRegion)을 통해 컨텍스트에 제공됩니다([SWS_CRYPT_50207]).
  • 대상 스토리지 또는 휘발성 키: 성공적인 가져오기 후 언팩된 키 자료는 영구 쓰기 키 슬롯(WriteableKeySlot)에 직접 저장되거나([SWS_CRYPT_50207]), 형식화된 쿼리 메서드를 통해 개인 키([SWS_CRYPT_50209]), 대칭 키([SWS_CRYPT_50210]) 또는 공개 키([SWS_CRYPT_50211])에 대한 휘발성 스마트 포인터로 가져올 수 있습니다.
  • 프로토콜 응답: 기본 가져오기 시나리오가 인증 또는 확인 프로토콜(예: SHE-LoadKey 트랜잭션의 M4 및 M5 반환값)을 지원하는 경우, 컨텍스트는 이러한 응답 데이터를 애플리케이션에 반환합니다([SWS_CRYPT_41020]).

수명 주기

ProtectedKeyImportCtx의 인스턴스는 std::shared_ptr<ProtectedKeyImportCtx>(으)로 정의된 형식 별칭 Sptr을(를) 통해 공유 포인터로 관리됩니다([SWS_CRYPT_50085]). 해석: 이는 추상 인터페이스이므로 실제 인스턴스화는 CryptoProvider의 해당 팩토리 메서드를 통해 이루어질 것으로 추정됩니다.

컨텍스트는 정상 작동 중 여러 개별 상태를 거칩니다:

  1. 초기 상태: 생성 후 또는 명시적 정리 후에는 구성된 키 가져오기 키가 존재하지 않으며 내부 데이터 버퍼가 비어 있습니다([SWS_CRYPT_50212]).
  2. 구성됨: SetKey()을(를) 통해 전송 키를 바인딩하면([SWS_CRYPT_50205], [SWS_CRYPT_50206]) 컨텍스트는 보호된 데이터 패킷을 처리할 준비가 됩니다.
  3. 데이터 사용 가능: Import()이(가) 성공적으로 실행된 후([SWS_CRYPT_50207]) 컨텍스트는 파싱된 키 객체 및 해당하는 경우 발생하는 응답 메시지를 유지합니다. 이 상태에서 getter 메서드를 호출할 수 있습니다.
  4. 재설정: Reset()을(를) 호출하면([SWS_CRYPT_50212]) 설정된 전송 키가 제거되고 내부 버퍼에서 캐시된 모든 데이터가 삭제되며 컨텍스트가 다시 초기 상태로 전환됩니다.

동시성과 관련하여 컨텍스트의 모든 인터페이스 메서드는 예외 안전(exception safe) 및 스레드 안전(thread-safe)으로 지정되어 있습니다([SWS_CRYPT_50205], [SWS_CRYPT_50207], [SWS_CRYPT_50208], [SWS_CRYPT_50212]).

상태 다이어그램: ProtectedKeyImportCtx 인스턴스의 단계 및 상태 전이. 출처: [SWS_CRYPT_50205], [SWS_CRYPT_50206], [SWS_CRYPT_50207], [SWS_CRYPT_50212].

사용 경로

보호된 키 가져오기를 수행하는 일반적인 절차는 다음과 같은 단계로 나뉩니다:

  1. 전송 키 구성: 애플리케이션은 대칭 키 객체([SWS_CRYPT_50205]) 또는 키 슬롯([SWS_CRYPT_50206])을(를) 인자로 하여 SetKey()을(를) 호출함으로써 컨텍스트를 구성합니다. 제공된 키에는 해당 사용 권한이 있어야 합니다.
  2. 가져오기 실행: 직렬화된 데이터의 데이터 버퍼를 인자로 하여 메서드 Import()이(가) 호출됩니다([SWS_CRYPT_50207]). WriteableKeySlot이(가) 추가로 지정된 경우, 컨텍스트는 언팩된 키 자료를 이 슬롯으로 즉시 직렬화합니다.
  3. 객체 유형 식별: GetCryptoObjectType()을(를) 사용하여 어떤 종류의 암호화 객체가 언팩되었는지 조회할 수 있다([SWS_CRYPT_50208]).
  4. 키 및 프로토콜 응답 조회: 애플리케이션은 객체 유형에 따라 GetSymmetricKey()([SWS_CRYPT_50210]), GetPrivateKey()([SWS_CRYPT_50209]) 또는 GetPublicKey()([SWS_CRYPT_50211])을(를) 통해 키를 요청한다. 가져오기 프로토콜이 확인 메시지를 규정하는 경우, 이 메시지는 GetResponse()을(를) 통해 제공된 버퍼로 전송된다([SWS_CRYPT_41020]).
  5. 완료 및 버퍼 정리: 성공적으로 추출한 후에는 Reset()을(를) 호출하여 내부 버퍼에서 민감한 잔류 데이터가 제거되고 컨텍스트가 깔끔하게 초기화되도록 보장한다([SWS_CRYPT_50212]).

시퀀스 다이어그램: 보호된 키를 가져오고 결과를 읽어올 때의 호출 순서. 출처: [SWS_CRYPT_50205], [SWS_CRYPT_50207], [SWS_CRYPT_50208], [SWS_CRYPT_50210], [SWS_CRYPT_41020], [SWS_CRYPT_50212].

오류 시나리오

모든 연산은 ara::core::Result을(를) 반환하며, 오류 발생 시 호출 전 상태를 유지하는 정의된 롤백 시맨틱을 사용한다:

  • 키 구성 오류:
    • CryptoErrc::kUsageViolation: 전송 키의 사용 플래그에 kAllowKeyUnwrapping 비트가 포함되어 있지 않을 때 발생한다([SWS_CRYPT_50205], [SWS_CRYPT_50206]).
    • CryptoErrc::kIncompatibleObject: 전달된 객체 또는 KeySlot에 포함된 키를 전송 키로 사용할 수 없다([SWS_CRYPT_50205], [SWS_CRYPT_50206]).
    • CryptoErrc::kUnsupported: 컨텍스트 구현이 다른 SetKey() 변형만을 지원한다(예: 키 객체 대신 KeySlot만 지원)([SWS_CRYPT_50205], [SWS_CRYPT_50206]).
  • 가져오기 중 오류:
    • CryptoErrc::kInvalidInputSize: 전달된 메모리 영역 serialized의 크기가 예상치 못한 크기여서 언팩할 수 없다([SWS_CRYPT_50207]).
    • CryptoErrc::kInvalidArgument: serialized의 데이터 형식이 요구되는 가져오기 형식과 일치하지 않는다([SWS_CRYPT_50207]).
    • CryptoErrc::kAuthTagNotValid: 인증 특성(서명 또는 MAC)이 유효하지 않아 데이터 무결성을 확인할 수 없다([SWS_CRYPT_50207]).
    • CryptoErrc::kBusyResource: 내부 리소스가 사용 중이어서 연산을 일시적으로 실행할 수 없다([SWS_CRYPT_50207]).
  • 결과 조회 시 오류:
    • CryptoErrc::kProcessingNotFinished: 사전에 성공적인 Import() 호출이 발생하지 않은 경우 GetPrivateKey(), GetPublicKey() 또는 GetSymmetricKey() 호출이 실패한다([SWS_CRYPT_50209], [SWS_CRYPT_50210], [SWS_CRYPT_50211]).
    • CryptoErrc::kNoSuchValue: 지금까지 가져온 객체가 없거나 가장 최근에 가져온 객체가 조회된 키 유형과 일치하지 않는 경우 반환된다([SWS_CRYPT_50208], [SWS_CRYPT_50209], [SWS_CRYPT_50210], [SWS_CRYPT_50211]).
    • CryptoErrc::kInsufficientCapacity: GetResponse()에 전달된 출력 버퍼가 프로토콜 응답을 수용하기에 충분하지 않다([SWS_CRYPT_41020]).
    • CryptoErrc::kUnsupported: 컨텍스트가 객체 유형 확인([SWS_CRYPT_50208]), 응답 생성([SWS_CRYPT_41020]) 또는 상태 재설정([SWS_CRYPT_50212])과 같은 특정 기능을 지원하지 않음을 나타낸다.

이 가이드는 AUTOSAR Adaptive Platform R25-11 규격(crypto 모듈)을 기반으로 한다. 명시적인 규격 참조가 없는 진술은 개념적 해석을 나타낸다.

<p>클래스 <code>ara::crypto::cryp::ProtectedKeyImportCtx</code>은(는) 암호화 키 및 관련 메타데이터의 안전한 로드 및 압축 해제를 위한 특화된 인터페이스를 정의합니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>). 이는 키 자료를 보호되거나 암호화 또는 인증된 형식(예: 래핑된 키 토큰)으로 애플리케이션 환경에 전송하고 배포해야 할 때 사용됩니다.</p>
<p>다른 컴포넌트와의 상호작용에서 컨텍스트는 처리 애플리케이션, 암호화 소스 및 전송 구조, 그리고 결과로 생성되는 키 객체 간의 인터페이스 역할을 합니다:</p>
<ul>
<li><strong>전송 키:</strong> 데이터의 복호화 및 인증을 위해 컨텍스트에는 전송 키가 필요합니다. 이는 대칭 키 객체 <code>ara::crypto::cryp::SymmetricKey</code>(으)로 직접 전달되거나(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>), <code>ara::crypto::keys::KeySlot</code>을(를) 통해 참조됩니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
<li><strong>입력 데이터:</strong> 보호되고 직렬화된 키 데이터는 읽기 전용 메모리 영역(<code>ReadOnlyMemRegion</code>)을 통해 컨텍스트에 제공됩니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
<li><strong>대상 스토리지 또는 휘발성 키:</strong> 성공적인 가져오기 후 언팩된 키 자료는 영구 쓰기 키 슬롯(<code>WriteableKeySlot</code>)에 직접 저장되거나(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>), 형식화된 쿼리 메서드를 통해 개인 키(<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>), 대칭 키(<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>) 또는 공개 키(<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>)에 대한 휘발성 스마트 포인터로 가져올 수 있습니다.</li>
<li><strong>프로토콜 응답:</strong> 기본 가져오기 시나리오가 인증 또는 확인 프로토콜(예: SHE-LoadKey 트랜잭션의 M4 및 M5 반환값)을 지원하는 경우, 컨텍스트는 이러한 응답 데이터를 애플리케이션에 반환합니다(<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
</ul>

<h4>수명 주기</h4>
<p><code>ProtectedKeyImportCtx</code>의 인스턴스는 <code>std::shared_ptr&lt;ProtectedKeyImportCtx&gt;</code>(으)로 정의된 형식 별칭 <code>Sptr</code>을(를) 통해 공유 포인터로 관리됩니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50085" href="../spec/record.html?id=SWS_CRYPT_50085">[SWS_CRYPT_50085]</a>). 해석: 이는 추상 인터페이스이므로 실제 인스턴스화는 CryptoProvider의 해당 팩토리 메서드를 통해 이루어질 것으로 추정됩니다.</p>
<p>컨텍스트는 정상 작동 중 여러 개별 상태를 거칩니다:</p>
<ol>
<li><strong>초기 상태:</strong> 생성 후 또는 명시적 정리 후에는 구성된 키 가져오기 키가 존재하지 않으며 내부 데이터 버퍼가 비어 있습니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</li>
<li><strong>구성됨:</strong> <code>SetKey()</code>을(를) 통해 전송 키를 바인딩하면(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>) 컨텍스트는 보호된 데이터 패킷을 처리할 준비가 됩니다.</li>
<li><strong>데이터 사용 가능:</strong> <code>Import()</code>이(가) 성공적으로 실행된 후(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>) 컨텍스트는 파싱된 키 객체 및 해당하는 경우 발생하는 응답 메시지를 유지합니다. 이 상태에서 getter 메서드를 호출할 수 있습니다.</li>
<li><strong>재설정:</strong> <code>Reset()</code>을(를) 호출하면(<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>) 설정된 전송 키가 제거되고 내부 버퍼에서 캐시된 모든 데이터가 삭제되며 컨텍스트가 다시 초기 상태로 전환됩니다.</li>
</ol>

<h4>사용 경로</h4>
<p>보호된 키 가져오기를 수행하는 일반적인 절차는 다음과 같은 단계로 나뉩니다:</p>
<ol>
<li><strong>전송 키 구성:</strong> 애플리케이션은 대칭 키 객체(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>) 또는 키 슬롯(<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>)을(를) 인자로 하여 <code>SetKey()</code>을(를) 호출함으로써 컨텍스트를 구성합니다. 제공된 키에는 해당 사용 권한이 있어야 합니다.</li>
<li><strong>가져오기 실행:</strong> 직렬화된 데이터의 데이터 버퍼를 인자로 하여 메서드 <code>Import()</code>이(가) 호출됩니다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>). <code>WriteableKeySlot</code>이(가) 추가로 지정된 경우, 컨텍스트는 언팩된 키 자료를 이 슬롯으로 즉시 직렬화합니다.</li>
<li><strong>객체 유형 식별:</strong> <code>GetCryptoObjectType()</code>을(를) 사용하여 어떤 종류의 암호화 객체가 언팩되었는지 조회할 수 있다(<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>).</li>
<li><strong>키 및 프로토콜 응답 조회:</strong> 애플리케이션은 객체 유형에 따라 <code>GetSymmetricKey()</code>(<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>), <code>GetPrivateKey()</code>(<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>) 또는 <code>GetPublicKey()</code>(<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>)을(를) 통해 키를 요청한다. 가져오기 프로토콜이 확인 메시지를 규정하는 경우, 이 메시지는 <code>GetResponse()</code>을(를) 통해 제공된 버퍼로 전송된다(<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
<li><strong>완료 및 버퍼 정리:</strong> 성공적으로 추출한 후에는 <code>Reset()</code>을(를) 호출하여 내부 버퍼에서 민감한 잔류 데이터가 제거되고 컨텍스트가 깔끔하게 초기화되도록 보장한다(<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>).</li>
</ol>

<h4>오류 시나리오</h4>
<p>모든 연산은 <code>ara::core::Result</code>을(를) 반환하며, 오류 발생 시 호출 전 상태를 유지하는 정의된 롤백 시맨틱을 사용한다:</p>
<ul>
<li><strong>키 구성 오류:</strong>
  <ul>
  <li><code>CryptoErrc::kUsageViolation</code>: 전송 키의 사용 플래그에 <code>kAllowKeyUnwrapping</code> 비트가 포함되어 있지 않을 때 발생한다(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  <li><code>CryptoErrc::kIncompatibleObject</code>: 전달된 객체 또는 KeySlot에 포함된 키를 전송 키로 사용할 수 없다(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  <li><code>CryptoErrc::kUnsupported</code>: 컨텍스트 구현이 다른 <code>SetKey()</code> 변형만을 지원한다(예: 키 객체 대신 <code>KeySlot</code>만 지원)(<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>).</li>
  </ul>
</li>
<li><strong>가져오기 중 오류:</strong>
  <ul>
  <li><code>CryptoErrc::kInvalidInputSize</code>: 전달된 메모리 영역 <code>serialized</code>의 크기가 예상치 못한 크기여서 언팩할 수 없다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kInvalidArgument</code>: <code>serialized</code>의 데이터 형식이 요구되는 가져오기 형식과 일치하지 않는다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kAuthTagNotValid</code>: 인증 특성(서명 또는 MAC)이 유효하지 않아 데이터 무결성을 확인할 수 없다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  <li><code>CryptoErrc::kBusyResource</code>: 내부 리소스가 사용 중이어서 연산을 일시적으로 실행할 수 없다(<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>).</li>
  </ul>
</li>
<li><strong>결과 조회 시 오류:</strong>
  <ul>
  <li><code>CryptoErrc::kProcessingNotFinished</code>: 사전에 성공적인 <code>Import()</code> 호출이 발생하지 않은 경우 <code>GetPrivateKey()</code>, <code>GetPublicKey()</code> 또는 <code>GetSymmetricKey()</code> 호출이 실패한다(<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>, <a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>).</li>

  <li><code>CryptoErrc::kInsufficientCapacity</code>: <code>GetResponse()</code>에 전달된 출력 버퍼가 프로토콜 응답을 수용하기에 충분하지 않다(<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>).</li>
  <li><code>CryptoErrc::kUnsupported</code>: 컨텍스트가 객체 유형 확인(<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>), 응답 생성(<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>) 또는 상태 재설정(<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>)과 같은 특정 기능을 지원하지 않음을 나타낸다.</li>
  </ul>
</li>
