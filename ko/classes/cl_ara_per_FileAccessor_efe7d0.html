클래스 ara::per::FileAccessor

[SWS_PER_00588] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class FileAccessor {...};

FileAccessor contains a common basis for ReadAccessor and WriteAccessor. It provides methods for checking and setting the current position in the file (GetPosition, Set Position, MovePosition, IsEof) and for checking the current size of the file (GetSize).

컨텍스트

ara::per::FileAccessor 클래스는 AUTOSAR Adaptive Platform의 Persistency 모듈에서 파일 기반 액세스 클래스의 공통 기반을 형성한다. 이 클래스는 현재 파일 위치를 조회 및 수정하고 현재 파일 크기를 확인하는 메서드를 하나로 묶으며, 특화된 클래스인 ReadAccessor 및 WriteAccessor에 의해 확장된다. 이러한 추상화를 통해 읽기 및 쓰기 파일 액세스가 위치 관리를 위한 동일한 표준화된 인터페이스를 공유하므로 중복된 제어 로직을 방지할 수 있다.

애플리케이션 컴포넌트는 일반적으로 파생된 액세스 객체의 인스턴스를 통해 FileAccessor과(와) 상호작용하지만, 공통 기본 인터페이스를 통해 위치 및 상태 관련 확인을 제네릭하게 처리할 수 있다.

컨텍스트 다이어그램: 특화된 파일 액세스를 위한 공통 기본 클래스로서 FileAccessor의 포함 관계. 출처: [SWS_PER_00589], [SWS_PER_00594]

수명 주기

ara::per::FileAccessor의 수명 주기 관리는 엄격하게 규제되며 직접 인스턴스화 및 모든 복제를 차단한다. 매개변수가 없는 기본 생성자는 명시적으로 삭제(deleted)되어 있다 [SWS_PER_00589]. 마찬가지로 복사 생성자 [SWS_PER_00592] 및 복사 할당 연산자 [SWS_PER_00593]도 삭제되어 인스턴스를 얕은 복사나 깊은 복사 모두 할 수 없다.

또한 이동 생성자 [SWS_PER_00590] 및 이동 할당 연산자 [SWS_PER_00591]도 삭제되어 있다. 해석: 모든 기본, 복사 및 이동 연산이 삭제되었으므로, FileAccessor은(는) 인스턴스화와 수명 주기가 구체적인 자식 클래스인 ReadAccessor 및 WriteAccessor에 각각 바인딩된 보호된 기본 클래스로서만 기능할 것으로 보인다. 이는 다형적 처리 시 실수로 인한 슬라이싱(slicing)을 방지한다.

리소스 정리는 가상 소멸자 ~FileAccessor() [SWS_PER_00594]을(를) 통해 수행된다. virtual 및 noexcept(으)로 선언되어 있어, 기본 클래스에 대한 포인터나 참조를 통해 해제될 때 파생 클래스의 소멸자가 예외에 안전하고 올바르게 호출되도록 보장한다 [SWS_PER_00594].

동시성과 관련하여 소멸자 및 모든 메서드는 스레드 안전하지 않은 것(not thread-safe)으로 명시되어 있다 [SWS_PER_00162], [SWS_PER_00424], [SWS_PER_00107], [SWS_PER_00164], [SWS_PER_00163], [SWS_PER_00594]. 여러 스레드가 동일한 인스턴스에 동시에 액세스하는 경우, 호출하는 애플리케이션이 외부 동기화를 보장해야 한다.

사용 경로

FileAccessor의 일반적인 사용 경로는 파일 상태 확인, 정의된 위치로의 탐색 및 파일 경계 유효성 검사를 포함한다:

  1. 크기 조회: 애플리케이션은 GetSize()을(를) 통해 현재 파일의 총 크기를 바이트 단위로 확인한다 [SWS_PER_00424]. 이는 유효한 위치에 대한 기준 틀을 제공한다.
  2. 위치 조회: 애플리케이션은 GetPosition()을(를) 사용하여 파일 시작 지점을 기준으로 한 현재 위치를 바이트 단위로 조회한다 [SWS_PER_00162]. 보고된 위치는 파일 끝에 위치할 수도 있다.
  3. 절대 위치 지정: 애플리케이션은 SetPosition()을(를) 사용하여 파일 포인터를 파일 시작 지점 기준의 절대 바이트 위치로 설정한다 [SWS_PER_00163].
  4. 상대적 이동: 다른 방법으로 MovePosition()을(를) 사용하면 기준점을 기준으로 위치를 이동할 수 있다 origin [SWS_PER_00164]:
    • Origin::kBeginning: 파일 시작 지점 기준의 양의 오프셋.
    • Origin::kCurrent: 현재 위치 기준의 양 또는 음의 오프셋이며, 오프셋이 0이면 위치가 변경되지 않고 유지된다.
    • Origin::kEnd: 파일 끝 기준의 음의 오프셋이며, 오프셋이 0이면 위치가 정확히 파일 끝으로 설정된다.
    호출이 성공하면 반환값에 파일 시작 지점 기준의 새 위치가 제공된다 [SWS_PER_00164].
  5. 파일 끝 확인: 애플리케이션은 IsEof()을(를) 통해 현재 위치가 파일 끝에 도달했는지 확인한다 [SWS_PER_00107]. 포인터가 파일 끝에 있으면 이 함수는 true을(를) 반환하고, 그렇지 않으면 false을(를) 반환한다.

시퀀스 다이어그램: 위치 확인 및 상대적 이동을 포함하는 일반적인 파일 탐색 절차. 출처: [SWS_PER_00424], [SWS_PER_00163], [SWS_PER_00164], [SWS_PER_00107]

오류 시나리오

ara::per::FileAccessor의 오류 처리는 ara::core::Result을(를) 통한 AUTOSAR Adaptive Platform의 오류 모델 기반 접근 방식을 따른다. 모든 메서드는 noexcept 및 예외 안전(exception safe)으로 선언되어 있으므로 C++ 예외가 발생하지 않는다 [SWS_PER_00162], [SWS_PER_00424], [SWS_PER_00107], [SWS_PER_00164], [SWS_PER_00163].

오류는 주로 범위 경계를 위반할 때 발생한다:

  • 절대 위치 지정 시 초과: 애플리케이션이 SetPosition()에 파일 끝을 벗어나는 값을 전달하면 호출이 실패하고 오류 코드 PerErrc::kInvalidPosition을(를) 반환한다 [SWS_PER_00163].
  • 상대적 이동 시 경계 위반: MovePosition()에서의 계산 결과 위치가 0보다 작거나 파일 끝을 초과하는 경우, 해당 작업은 PerErrc::kInvalidPosition(으)로 거부된다 [SWS_PER_00164].
  • 롤백 시맨틱: 오류 발생 시 SetPosition() 및 MovePosition() 모두 엄격한 롤백 시맨틱(rollback_semantics)을 보장한다. 오류가 발생해도 현재 파일 위치는 변경되지 않는다 [SWS_PER_00163], [SWS_PER_00164].
  • 제조사별 오류: PerErrc::kInvalidPosition 외에도 ara::core::Result에서 제조사별 오류 코드가 반환될 수 있다 [SWS_PER_00163], [SWS_PER_00164].
