사용 목적

ara::core::Future<T, E>는 비동기 호출의 나중에 사용 가능한 결과 또는 오류를 나타냅니다. 오류 유형은 ara::core::ErrorCode이어야 하며, 그렇지 않으면 컴파일 타임 오류가 필요한다. Promise와 함께 이 유형을 사용하면 스레드로부터 안전하고 예외 없이 비동기 값 및 오류를 처리할 수 있다. [SWS_CORE_00321] [SWS_CORE_10800]

수명주기 & 소유권

복사가 금지되어 있다(=delete). 이동 건설 및 이동 할당이 가능한다. 소멸자는 공유 상태를 포기한다. GetResult(), get() 및 then()는 원래 Future를 무효화한다. [SWS_CORE_00334] [SWS_CORE_00335] [SWS_CORE_00323] [SWS_CORE_00325] [SWS_CORE_00333] [SWS_CORE_00336] [SWS_CORE_00326] [SWS_CORE_00337]

다른 클래스와의 상호작용

GetResult()는 값이나 오류가 존재할 때까지 차단하고 트리거되지 않는 Result<T,E>를 반환한다. then()는 이 Result를 통해 함수에서 후속 Future를 생성한다. Executor를 사용한 오버로드는 실행 컨텍스트에서 함수를 실행한다. [SWS_CORE_00336] [SWS_CORE_00331] [SWS_CORE_00337]

제한 사항 및 오류 처리

해당 Promise가 폐기되면 GetResult()는 FutureErrc::kBrokenPromise 오류를 반환한다. 차단하기 전에 is_ready()를 확인할 수 있다. true, get(), GetResult() 및 대기 호출의 경우 차단되지 않는다. 유효하지 않은 미래에 대한 금지된 호출은 위반으로 지정된다. [SWS_CORE_00336] [SWS_CORE_00332] [SWS_CORE_13011]

비동기 오류 처리

Future는 반환되거나 실패할 수 있는 비동기 호출에 대한 조화된 반환 유형이다. get()와 달리 GetResult()는 대기 후 값이나 오류가 포함된 Result를 반환하고 예외를 트리거하지 않는다. RS General §4.1.2 “Error handling” EXP PlatformDesign §18.1.4 “Future and Promise” EXP ARAComAPI §5.3.6.2 “Event-Driven vs Polling access to method results”

메소드 기반 통신의 경우 Future/Promise 패턴을 사용하면 비차단 동작이 가능합니다. 결과 도착에 대해서는 차단 대기, then()의 지속 및 is_ready()를 통한 폴링이 가능합니다. is_ready() 성공 후 이후 접속은 차단되지 않습니다. EXP ARAComAPI §4.4 “Method based communication” EXP ARAComAPI §5.3.6.2 “Event-Driven vs Polling access to method results”

공통 상태 및 오류 전송

기능 사양은 Future 및 Promise를 오류 경로의 비동기 대응으로 처리합니다. 나중 결과는 반환에서 오류 처리를 분리하지 않고 값이나 오류를 나타낼 수 있습니다. SWS Core §7.2 “Error handling” SWS Core §7.2.5.5 “Future and Promise”

오류가 발생한 경우의 동작

GetResult()는 값이나 오류를 사용할 수 있을 때까지 차단하고 공유 상태의 내용을 Result<T,E>로 반환합니다. SetError()로 설정된 오류가 결과 경로에 남아있습니다. 해당 Promise에 의해 공유 상태가 포기된 경우 GetResult()는 대신 FutureErrc::kBrokenPromise를 반환합니다. 대조적으로, get()는 공유 상태의 오류를 예외로 전송합니다. Future가 유효하지 않은 경우에는 kNoState가 포함됩니다. [SWS_CORE_00336] [SWS_CORE_00326] [SWS_CORE_00400]

wait_for() 최대 지정된 기간 동안 대기하고 최대 wait_until() 마감일까지 대기한다. 둘 다 FutureStatus를 반환한다. kTimeout는 공유 상태가 해당 기한 내에 준비되지 않았음을 의미한다. 따라서 시간 초과는 결과로 전송되는 오류와 구별되어야 한다. [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00361]

오류는 공유 상태에서 Result로 읽혀집니다. 대체 필드에는 Promise 포기로 인해 발생한 오류와 별도의 대기 시간 초과가 표시된다. 출처: [SWS_CORE_00336] [SWS_CORE_00329] [SWS_CORE_00330].

then()는 GetResult()가 이 Future에 제공할 Result를 후속편에 제공한다. 따라서 연속 작업에서는 오류를 평가하고 이를 Result 또는 후속 조치 Future로 전달할 수 있다. then() 이후에는 원래 Future가 유효하지 않는다. 연속에서 벗어나는 예외는 위반으로 지정된다. 오류를 전달하려면 오류로 변환되어야 한다. [SWS_CORE_00337] [SWS_CORE_00331]

API 계약에 명명된 future_already_retrieved 및 promise_already_satisfied 상태는 R25-11에 Violation 설명으로 나타납니다. 유효하지 않은 Future에 액세스하려면 Violation도 지정됩니다. get()만이 kNoState로 FutureException를 지정합니다. [SWS_CORE_13013] [SWS_CORE_13014] [SWS_CORE_13015] [SWS_CORE_00326]

함수 then [SWS_CORE_00331] Upstream: RS_AP_00130

template <typename F> auto then (F &&func) noexcept -> Future< <see below> >;

Create a new Future with the content returned by func when passed the Result of this Future. The callable func may be called in the context of this call or in the context of • Promise::set_result(const T&) • Promise::set_result(T&&) • Promise::SetError(E&&) • Promise::SetError(const E&) or somewhere else.

valid() ==FALSE on the original Future object immediately after it returns.

The Callable input argument func takes a Result<T,E> object as parameter. This will be the Result obtained via GetResult() from the Future instance itself, on which then(...) is being called. The Result is passed to func as an rvalue expression.

The return type of then(...) depends on the return type of func (aka continuation).

Let U be the return type of the continuation (i.e. a type equivalent to std::invoke_result_ t<std::decay_t<F>,Result<T,E>>). Return type deduction: • If U is Future<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. This is known as implicit Future unwrapping. • If U is Result<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. This is known as implicit Result unwrapping. • Otherwise it is Future<U,E> Continuations that are registered with then(...) are registered in the Future F that then (...) returns. No such continuation shall be executed after the destructor of the Future F returns. A continuation that is already being executed shall run to completion.

Note: that means that the destructor of Future might block until the currently running continuation has been completed.
