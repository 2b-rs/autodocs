클래스 ara::shwa::ErrorHandler

이 페이지는 SWS Safe Hardware Acceleration(R25-11)를 기반으로 완전히 AI로 생성되었다. 공식 AUTOSAR 텍스트도 없고 나머지 모듈처럼 자동으로 추출된 API 페이지도 없다. 해석으로 표시된 진술은 출처에서 도출된 결론이다.

[AP_SWS_SHWA_00501] Upstream: RS_SHWA_00008

class ErrorHandler final {...};

shwa 모듈의 오류를 감지하고 이를 애플리케이션별 처리 루틴으로 전달하는 역할을 합니다.

이 클래스는 shwa 모듈 내에서 오류를 중앙에서 수신하고 전달하는 데 사용됩니다. 인스턴스는 독점 포인터로 객체를 제공하는 정적 팩토리 메서드를 통해서만 생성할 수 있습니다 [AP_SWS_SHWA_00507]. 오류 처리 메서드를 통해 특정 오류 코드가 전달되고 처리됩니다 [AP_SWS_SHWA_00508]. 오류 처리가 스레드 안전하지도 예외 안전하지도 않게 설계되었으므로, 호출 애플리케이션은 동시 접근을 외부에서 조정해야 합니다.

컨텍스트

클래스 ara::shwa::ErrorHandler은 shwa(Smart Hardware Actuator) 모듈에서 모듈별 오류 상태를 수신하고 의도된 대로 전달하기 위한 특수 인터페이스를 제공합니다. AUTOSAR Adaptive Platform의 구성 요소로서 실제 하드웨어 및 액추에이터 로직을 상위 오류 처리 전략과 분리합니다. 이 클래스는 final(으)로 선언되어 있어 파생이 불가능하며 고정적으로 정의된 사용 동작이 강제됩니다.

ara::shwa::ErrorHandler의 주요 상호작용 주체는 다음과 같습니다:

  • 인스턴스를 관리하고 오류 발생 시 처리 메서드를 트리거하는 사용하는 애플리케이션 또는 플랫폼 컴포넌트.
  • 애플리케이션 수준에서 실제 처리 반응을 실행하는, 생성 시 등록된 콜백 std::function<void(ara::core::ErrorCode)>.
  • ara::shwa::ShwaErrorCode 타입으로 표시되는 모듈별 오류 도메인.

수명 주기

ara::shwa::ErrorHandler 인스턴스의 수명 주기는 생성, 복사 가능성 및 메모리 소유권과 관련하여 엄격한 제한을 받습니다. 매개변수가 없는 생성자가 삭제되었으므로 기본 생성자를 통한 일반적인 구성은 불가능합니다 [AP_SWS_SHWA_00502]. 명확한 식별성과 명확한 책임을 보장하기 위해 클래스 정의는 모든 복사 및 이동 작업을 방지합니다:

  • 복사 생성자가 삭제되었습니다 [AP_SWS_SHWA_00503].
  • 복사 할당 연산자가 삭제되었습니다 [AP_SWS_SHWA_00504].
  • 이동 생성자가 삭제되었습니다 [AP_SWS_SHWA_00505].
  • 이동 할당 연산자가 삭제되었습니다 [AP_SWS_SHWA_00506].

인스턴스화를 위한 유일한 방법은 정적 팩토리 메서드 Create을(를) 사용하는 것입니다 [AP_SWS_SHWA_00507]. 이는 함수 객체 std::function<void(ara::core::ErrorCode)>을(를) 수신하고 그 결과를 ara::core::Result<std::unique_ptr<ErrorHandler>>의 형태로 반환합니다. std::unique_ptr을(를) 통해 객체의 독점 소유권이 호출자에게 이전됩니다. 따라서 인스턴스의 수명은 스마트 포인터의 수명에 직접 연결되며, 스마트 포인터가 소멸될 때 ErrorHandler도 해제됩니다.

동시성과 관련하여 생성 메서드 Create은 스레드 안전(thread-safe) 및 예외 안전(exception safe)으로 명시되어 있습니다 [AP_SWS_SHWA_00507]. 반면 작동 오류 처리를 위한 메서드 HandleError은(는) 스레드 안전하지도 예외 안전하지도 않게 명시되어 있습니다 [AP_SWS_SHWA_00508]. 따라서 동일한 인스턴스에 대한 경합 접근은 애플리케이션 수준에서 조정되어야 합니다.

사용 경로

ara::shwa::ErrorHandler을 사용할 때의 일반적인 흐름은 팩토리를 통한 초기화 및 후속 오류 처리를 포함합니다:

  1. 콜백 정의: 애플리케이션이 void(ara::core::ErrorCode) 시그니처를 가진 처리 루틴을 정의합니다.
  2. 생성: 애플리케이션이 정적 메서드 Create을(를) 호출하고 콜백 함수 [AP_SWS_SHWA_00507]을(를) 전달합니다. ara::core::Result을(를) 확인한 후 애플리케이션은 std::unique_ptr<ErrorHandler>을(를) 인수합니다.
  3. 오류 신호 전송: 정상 작동 중에 오류가 발생하면 인스턴스에서 해당 ara::shwa::ShwaErrorCode과(와) 함께 메서드 HandleError이(가) 호출됩니다 [AP_SWS_SHWA_00508].
  4. 전달: 인스턴스가 오류 이벤트를 처리하며, 이때 모듈별 오류 코드가 내부적으로 ara::core::ErrorCode(으)로 변환되어 등록된 콜백 함수로 전송될 것으로 보입니다(해석).

시퀀스 다이어그램: 인스턴스화부터 오류 처리까지의 일반적인 호출 순서. 출처: [AP_SWS_SHWA_00507], [AP_SWS_SHWA_00508]

오류 시나리오

클래스를 사용할 때는 주요 제약 조건과 엣지 케이스에 유의해야 합니다:

  • 객체 생성 실패: 사양에는 팩토리 메서드 Create에 대한 표준화된 오류 코드가 명시되어 있지 않습니다 [AP_SWS_SHWA_00507]. 그럼에도 불구하고 메서드가 ara::core::Result을(를) 반환하므로, 발생 가능한 오류 조건(메모리 부족 등)이 이 결과 객체를 통해 보고될 것으로 보입니다(해석). 따라서 호출자는 포인터에 접근하기 전에 Result을(를) 검증해야 합니다.
  • 오류 처리를 위한 사전 조건: HandleError의 호출은 온전한 인스턴스와 유효한 ara::shwa::ShwaErrorCode을(를) 전제로 합니다 [AP_SWS_SHWA_00508]. 메서드에 반환값이 없으므로 처리 내부의 오류를 호출자에게 상태 코드로 직접 보고할 수 없습니다.
  • 예외 및 스레드 안전성 부재: HandleError이(가) not thread-safe 및 not exception safe(으)로 선언되어 있으므로 [AP_SWS_SHWA_00508], 호출 환경은 호출이 순차적으로 이루어지고 오류 처리 내에서 처리되지 않은 예외가 전파되지 않도록 보장해야 합니다.

이 클래스 가이드는 Adaptive Platform용 AUTOSAR 사양(릴리스 R25-11)을 기반으로 하며 자동으로 생성되었습니다.
