활성 진단 기반 읽기 전송을 캡슐화하고 수신 데이터 전송을 등록된 핸들러로 전달합니다.

이 클래스는 [SWS_DM_01548]에 따라 AUTOSAR Adaptive 진단 모듈 내에서 모든 변형의 진단 기반 읽기 전송을 캡슐화하고 구조적으로 관리하는 역할을 합니다. 읽기 작업이 성공적으로 개시된 후, Diagnostic Server 인스턴스는 순차적 데이터 블록 전송 및 세션 종료에 대한 수신 요청을 읽기 핸들러 [SWS_DM_01317]의 등록된 메서드로 위임합니다. 이 클래스는 복사 작업을 명시적으로 비활성화하는 동시에 이동 의미론(Move Semantics)을 지원함으로써 기반 전송 세션에 대한 명확한 소유권 할당을 보장합니다.

컨텍스트

ara::diag::DataTransferReadSession 클래스는 Adaptive 진단 모듈 [SWS_DM_01548]에서 데이터 블록의 진단 기반 읽기를 위한 모든 변형의 캡슐화를 나타냅니다. RequestFileTransfer(0x38), TransferData(0x36), RequestTransferExit(0x37)와 같은 표준화된 UDS 서비스의 맥락에서 이 세션 클래스는 진단 서버의 내부 런타임 환경과 애플리케이션 고유의 읽기 핸들러 SWS Diagnostics §7 “Realization of TransferData and RequestTransferExit” 간의 연결 고리 역할을 합니다. 이 클래스는 ReadFile [SWS_DM_01314]을(를) 통한 파일 또는 ReadDir [SWS_DM_01315]을(를) 통한 디렉터리와 같이 진행 중인 판독 작업을 격리하여 관리하고 관련 핸들러로 전달되도록 보장합니다.

컨텍스트 다이어그램: 진단 서버와 애플리케이션 핸들러 간의 DataTransferReadSession 임베딩. 출처: [SWS_DM_01317], [SWS_DM_01318], SWS Diagnostics §7 “Realization of TransferData and RequestTransferExit”

수명 주기

ara::diag::DataTransferReadSession의 인스턴스는 전송 세션에 엄격하게 결합된 수명을 갖습니다. 기본 생성자를 통한 생성은 명시적으로 금지되어 있습니다 [SWS_DM_01549]. 대신 세션은 애플리케이션별 핸들러를 등록하는 특수화된 템플릿 생성자를 통해 초기화됩니다 SWS Diagnostics §7 “Realization of TransferData and RequestTransferExit”. 실제 환경에서의 인스턴스화는 일반적으로 파일 전송 개시 시 진단 서버 또는 서비스 핸들러에 의해 수행될 것으로 보입니다. 질문 Q-b0706bcd28c702c6 (열림)

다중 할당 또는 일관되지 않은 세션 상태를 방지하기 위해 ara::diag::DataTransferReadSession은(는) 복사 불가능한 단일 인스턴스로 설계되었습니다. 복사 생성자 [SWS_DM_01553] 및 복사 할당 연산자 [SWS_DM_01554]가 모두 삭제되었습니다(=delete). 소유권 전달은 이동 의미론(Move Semantics)을 통해서만 제공됩니다. 이동 생성자 [SWS_DM_01551] 및 이동 할당 연산자 [SWS_DM_01552]는 noexcept=default(으)로 정의됩니다. 소멸은 [SWS_DM_01550] 소멸자를 통해 결정론적으로 수행되며, 이 역시 noexcept=default(으)로 선언되어 있습니다. 아마도 RequestTransferExit를 통한 전송 완료 시 객체 해제가 이루어질 것으로 추정됩니다. 질문 Q-c1999fd1f283a007 (열림)

사용 경로

일반적인 읽기 전송 세션의 흐름은 다음과 같은 세 가지 연속적인 단계로 나뉩니다:

  • 초기화: 외부 진단 클라이언트가 ReadFile(0x04) [SWS_DM_01314] 또는 ReadDir(0x05) [SWS_DM_01315]과(와) 같은 읽기 모드로 RequestFileTransfer를 전송합니다. 이때 세션 인스턴스가 생성되고 읽기 핸들러가 등록됩니다.
  • 데이터 전송: 진단 서버는 템플릿 생성자를 통해 등록된 핸들러의 해당 Read 메서드를 호출하여 TransferData(0x36) 유형의 수신 진단 요청을 처리합니다 [SWS_DM_01317]. 이는 요청된 각 데이터 블록에 대해 반복적으로 발생합니다.
  • 완료: 모든 데이터가 전송되면 클라이언트는 RequestTransferExit(0x37)를 전송합니다. 그러면 진단 서버는 등록된 핸들러의 Exit 메서드를 호출하여 읽기 작업을 정상적으로 종료합니다 [SWS_DM_01318].

시퀀스 다이어그램: 등록된 세션으로의 전달을 포함한 UDS 읽기 전송의 호출 시퀀스. 출처: [SWS_DM_01314], [SWS_DM_01315], [SWS_DM_01317], [SWS_DM_01318]

오류 시나리오

ara::diag::DataTransferReadSession이(가) final(으)로 선언되어 있고 기본 생성자 [SWS_DM_01549]이(가) 존재하지 않으므로 등록된 핸들러가 없는 잘못된 생성은 이미 컴파일 시점에 방지됩니다. 마찬가지로 삭제된 복사 연산 [SWS_DM_01553]은(는) 세션 상태의 실수에 의한 복제를 방지합니다. 이동 생성, 이동 할당 및 소멸은 모두 noexcept 사양을 통해 완벽한 예외 안전성을 보장합니다 [SWS_DM_01551] [SWS_DM_01550]. 핸들러에서 데이터 블록 제공에 실패하는 경우 이는 UDS 통신의 프로토콜 수준에서 처리됩니다.

이 가이드는 AUTOSAR Adaptive Platform R25-11 사양(diag 모듈)을 기반으로 하며 ara::diag::DataTransferReadSession에 대한 요구사항을 요약합니다.
