컨텍스트

ara::idsm::EventReporter 클래스는 [SWS_AIDSM_10101]에 따라 보안 관련 이벤트를 감지하여 Intrusion Detection System Manager(IdsM)에 전달하기 위한 Adaptive 애플리케이션의 핵심 연결 고리입니다. 현대 차량 아키텍처에서는 기능 소프트웨어 컴포넌트가 각 도메인의 보안 관련 이상 징후, 통신 위반 또는 무단 액세스 시도를 모니터링합니다. 애플리케이션이 이러한 Security Event를 감지하면 EventReporter이(가) 보안 하위 시스템으로의 표준화된 보고를 처리합니다.

상호작용은 소프트웨어 아키텍처 모델에 공식적으로 정의된 인터페이스 유형 SecurityEventReportInterface의 포트를 통해 수행됩니다. 인스턴스를 생성할 때 이 포트는 ara::core::InstanceSpecifier을(를) 통해 주소 지정됩니다 [SWS_AIDSM_10301]. 이를 통해 이 클래스는 애플리케이션별 로직과 차량 전반의 IdsM 스택 사이에서 타입화된 인터페이스 역할을 합니다.

수명 주기

ara::idsm::EventReporter 클래스의 객체는 애플리케이션 측에서 인스턴스화됩니다. 매개변수화된 생성자는 ara::core::InstanceSpecifier에 대한 참조를 기대하며, noexcept 및 thread-safe로 선언되어 있습니다 [SWS_AIDSM_10301]. 초기화 중에 객체는 AUTOSAR 모델에 저장된 포트에 바인딩됩니다. 성공적인 생성 후 이 포트 바인딩은 변경되지 않고 유지되며, API 수준에서 사후 재구성은 제공되지 않습니다(Interpretation: EventReporter은(는) 전체 수명 주기 동안 구성된 포트에 단단히 바인딩된 상태를 유지합니다).

동시성 측면에서 이 클래스는 산업용 멀티스레딩 환경에 맞게 설계되었습니다. 생성 [SWS_AIDSM_10301]과 보고 함수의 모든 변형 ReportEvent 모두 완전히 스레드 안전(thread-safe)하도록 명시되어 있습니다([SWS_AIDSM_10302]부터 [SWS_AIDSM_10307]까지). 따라서 한 프로세스의 여러 스레드가 외부 동기화 메커니즘 없이 동일한 인스턴스를 병렬로 호출할 수 있습니다. 이 객체는 일반적인 RAII 패턴을 따르며, 유효 범위를 벗어날 때 플랫폼 리소스를 결정론적으로 해제합니다.

사용 경로

일반적인 워크플로는 시스템 시작 또는 컴포넌트 초기화 시 리포터를 인스턴스화한 후, 정상 작동 중에 반복적으로 이벤트를 보고하는 과정으로 이루어집니다:

  1. 리포터 인스턴스화: 모델별 InstanceSpecifier을 기반으로 생성자 EventReporter(const ara::core::InstanceSpecifier&)을 통해 인스턴스가 설정됩니다 [SWS_AIDSM_10301].
  2. 이벤트 데이터 수집: 보안 관련 이상이 발생하면 애플리케이션은 이벤트에 대해 사용 가능한 메타데이터에 따라 적절한 ReportEvent 오버로드를 선택합니다.
  3. 이벤트 보고: ReportEvent을 호출하여 카운터, 컨텍스트 정보 및 타임스탬프를 IdsM으로 전송합니다.

시퀀스 다이어그램: 생성부터 IdsM으로의 이벤트 보고까지의 일반적인 흐름. 출처: [SWS_AIDSM_10101], [SWS_AIDSM_10301], [SWS_AIDSM_10304]

이 인터페이스는 모델링된 이벤트 매개변수의 모든 변형을 포괄하는 총 6개의 세분화된 오버로드를 제공합니다:

  • 컨텍스트 없음: 페이로드가 없는 순수 카운터 이벤트는 ReportEvent(const CountType count = 1)을 통해 전달됩니다 [SWS_AIDSM_10302]. 특정 수집 시점을 추가로 기록해야 하는 경우 TimestampType가 포함된 시그니처를 사용할 수 있습니다 [SWS_AIDSM_10303].
  • 컨텍스트 데이터 포함: 추가 진단 또는 프레임 데이터는 ContextDataType을 통해 전송되며, 선택적으로 타임스탬프 없이 [SWS_AIDSM_10304] 또는 타임스탬프와 함께 [SWS_AIDSM_10305] 전송될 수 있습니다.
  • 버전 관리되는 컨텍스트 데이터 포함: 컨텍스트 데이터 스키마에 점진적인 변경이 발생하는 경우, 시그니처는 VersionedContextDataType을 허용하며 마찬가지로 타임스탬프 없이 [SWS_AIDSM_10306] 및 타임스탬프와 함께 [SWS_AIDSM_10307] 사용할 수 있습니다.

모든 시그니처에서 매개변수 count은 기본값 1을 가지므로, 명시적인 카운터 지정 없이 단일 이벤트를 보고할 수 있습니다.

오류 시나리오

ara::idsm::EventReporter의 API는 방어적이며 실시간에 민감한 경로를 위해 엄격하게 non-blocking 방식으로 설계되었습니다. 생성자 [SWS_AIDSM_10301]과 ReportEvent의 6가지 변형([SWS_AIDSM_10302]부터 [SWS_AIDSM_10307]까지)을 포함한 모든 메서드는 noexcept로 선언되어 있으며 반환값이 없습니다(void).

이로 인해 다음과 같은 주요 아키텍처적 기본 조건이 도출됩니다:

  • 호출 인터페이스에서는 C++ 예외가 발생하지 않으며 ara::core::Result 오류 코드도 반환되지 않습니다.
  • 올바른 작동을 위한 전제 조건은 객체 생성 시 AUTOSAR 모델에 구성된 유효한 InstanceSpecifier을 제공하는 것입니다.
  • 버퍼링 오류, 전송 채널 과부하 또는 IdsM 서비스에 연결할 수 없는 문제 등은 호출자에게 동기식으로 전달될 수 없습니다(해석: 내부 버퍼 오버플로 또는 IdsM 통신 장애는 호출하는 실시간 애플리케이션의 블로킹을 방지하기 위해 플랫폼 스택 내부에서 로깅되거나 폐기됩니다).

이 가이드는 AUTOSAR Adaptive Platform 릴리스 R25-11의 명세를 기반으로 한다.
