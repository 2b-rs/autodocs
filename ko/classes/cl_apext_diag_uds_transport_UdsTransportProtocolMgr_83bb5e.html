클래스 apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

참고문헌 SWS 진단: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

사용 목적

UdsTransportProtocolMgr는 Diagnostic Server 인스턴스와 DoIP 또는 CAN 같은 UDS 전송 프로토콜 간의 상호 작용을 관리합니다. 이는 메시지 승인, 세션 계층으로의 전송, 승인 전송 및 채널 복구를 위한 표준화된 인터페이스를 전송 핸들러에 제공합니다. [SWS_DM_00306]

메시지 수락 & 소유권

핸들러는 소스 및 대상 주소, 주소 유형, 글로벌 채널 ID, 크기 및 호출 중에만 유효한 페이로드 조각을 포함하여 IndicateMessage()를 사용하여 수신된 메시지의 시작을 보고한다. DM이 요청을 처리할 수 있으면 kIndicationOk와 UdsMessagePtr가 소유한 메모리를 반환한다. 점유, 리소스 부족 또는 대상 주소를 알 수 없는 경우 kIndicationOccupied, kIndicationOverflow 또는 kIndicationUnknownTargetAddress에 널 포인터가 제공된다. [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

반환된 메시지 객체를 채운 후 핸들러는 이를 HandleMessage()를 통해 세션 계층에 전달한다. 그렇게 하면 소유권이 일반 DM 코어로 돌아갑니다. IndicateMessage()가 kIndicationOk를 제공하지 않은 경우 HandleMessage()가 호출되지 않을 수 있다. 조기 전송 오류가 있는 경우 객체는 NotifyMessageFailure()와 함께 반환된다. [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

수명 주기 및 전송

TransmitConfirmation()는 DM이 UdsTransportProtocolHandler::Transmit()를 통해 요청한 전송에 대해 kTransmitOk 또는 kTransmitFailed를 보고한다. PeriodicTransmitConfirmation()는 성공적으로 전송된 항목 수와 함께 정기적으로 전송된 메시지의 순서 목록을 확인한다. [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

DM은 관련 핸들러가 시작된 후에만 채널 복원을 처리할 수 있다. 중지 후에는 HandlerStopped()를 제외한 다른 관리자 호출이 허용되지 않다. DM은 프로세스를 종료하기 전에 이 콜백을 기다립니다. [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

함수 HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

참고문헌 SWS 진단: [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
