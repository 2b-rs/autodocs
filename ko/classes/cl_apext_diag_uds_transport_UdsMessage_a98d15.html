클래스 apext::diag::uds_transport::UdsMessage

[SWS_DM_00291] Upstream: RS_Diag_04147

class UdsMessage {...};

class represents an UDS message exchanged between DM generic core (UdsTransport ProtocolMgr) and a specific implementation of UdsTransportProtocolHandler on diagnostic request reception path or diagnostic response transmission path. UdsMessage provides the storage for UDS requests/responses.

Instances of UdsMessage (with optimized resource allocation) are only created by DM generic core, the UdsTransportProtocolHandler can read/write on it.

Adaptive 진단 관리자에서 데이터 교환 시 UDS 메시지를 위한 저장소 및 정보 매개체 역할을 합니다.

apext::diag::uds_transport::UdsMessage 클래스는 일반 진단 코어(generic diagnostic core)와 전송별 핸들러 간에 교환되는 진단 메시지를 위한 표준화된 저장소 및 전송 객체를 나타냅니다. 인스턴스는 최적화된 메모리 할당으로 일반 코어에 의해서만 독점적으로 생성되며 UdsMessagePtr을(를) 통해 제공됩니다 [SWS_DM_09012]. 수신 경로에서 핸들러는 서비스 ID(Service-ID)부터 시작하여 제공된 데이터 버퍼를 채우고, 임의의 채널 메타데이터를 추가한 후 메시지를 전달합니다 [SWS_DM_00388]. 기존 부하로 인해 코어가 메시지를 처리할 수 없는 경우 할당이 거부되고 널 포인터가 반환됩니다 [SWS_DM_00386].

컨텍스트

apext::diag::uds_transport::UdsMessage 클래스는 Diagnostic Management의 일반 코어(DM Generic Core 또는 UdsTransportProtocolMgr)와 UdsTransportProtocolHandler의 특정 구현 간에 교환되는 UDS 메시지를 위한 중앙 데이터 및 저장소 객체를 나타냅니다. 이는 수신 UDS 요청 및 송신 UDS 응답을 위한 캡슐화 및 저장소(Storage) 역할을 합니다.

페이로드 외에도 UdsMessage은(는) 진단 통신의 주소 지정 매개변수를 전송합니다: GetSa() [SWS_DM_00297]을(를) 통한 소스 주소 Address [SWS_DM_00293], GetTa() [SWS_DM_00298]을(를) 통한 대상 주소, 그리고 GetTaType() [SWS_DM_00299]을(를) 통한 주소 유형 TargetAddressType(kPhysical이 있는 물리적 또는 kFunctional이 있는 기능적) [SWS_DM_00296]. 또한 AddMetaInfo()을(를) 통해 DoIP용 연결 매개변수와 같은 채널별 메타정보를 추가할 수 있습니다 [SWS_DM_00294], [SWS_DM_00302].

컨텍스트 다이어그램: DM 코어, 전송 핸들러 및 UdsMessage 간의 상호작용. 출처: [SWS_DM_09012], [SWS_DM_00385], [SWS_DM_00345]

수명 주기

UdsMessage의 인스턴스는 최적화된 리소스 할당과 함께 Diagnostic Management의 일반 코어에 의해서만 독점적으로 생성됩니다. 프로토콜 핸들러에 의한 제어되지 않는 인스턴스화를 방지하기 위해 기본 생성자는 보호됨(protected)(으)로 선언되어 있습니다 [SWS_DM_09012]. 핸들러는 apext::diag::uds_transport::UdsMessagePtr 유형의 소유권 포인터 [SWS_DM_00303]을(를) 통해서만, 또는 순수 읽기 접근의 경우 apext::diag::uds_transport::UdsMessageConstPtr을(를) 통해서만 메시지 객체에 대한 접근 권한을 얻습니다 [SWS_DM_00304], AUTOSAR_AP_SWS_Diagnostics 98쪽.

객체 소멸은 가상 소멸자 ~UdsMessage()을(를) 통해 수행됩니다 [SWS_DM_09010]. 동시성과 관련하여 주소 정보 쿼리 메서드(GetSa, GetTa, GetTaType)는 재진입 가능(reentrant)하며 예외 안전(noexcept)합니다 [SWS_DM_00297], [SWS_DM_00298], [SWS_DM_00299]. 반면 GetPayload()을(를) 통한 데이터 버퍼 접근 및 AddMetaInfo()을(를) 통한 메타데이터 추가는 스레드 안전하지 않은 것으로 분류되는데, 이는 구현이 이러한 호출의 일환으로 버퍼 및 리소스 할당을 수행할 수 있기 때문입니다 [SWS_DM_00300], [SWS_DM_00301], [SWS_DM_00302].

사용 경로

수신 경로의 일반적인 절차에서 UdsTransportProtocolHandler은(는) UdsTransportProtocolMgr::IndicateMessage()을(를) 통해 DM에 수신 UDS 요청을 알립니다 [SWS_DM_00385]. DM이 수신 준비가 된 경우 kIndicationOk 상태로 이를 확인 응답하고 최소 1바이트 크기 및 DM이 원하는 버퍼 용량을 갖춘 UdsMessagePtr을(를) 전달합니다 [SWS_DM_00385].

이어서 프로토콜 핸들러는 기본 메모리 영역(uds_transport::ByteSpan&)에 대한 쓰기 가능한 참조를 얻기 위해 비-const 메서드 GetPayload()을(를) 호출합니다 [SWS_DM_00301]. 핸들러는 서비스 식별자(SID)부터 시작하여 UdsMessage 객체의 최대 용량 또는 전체 메시지 길이까지 이 버퍼를 채웁니다 [SWS_DM_00388]. AddMetaInfo() [SWS_DM_00302]을(를) 통해 선택적으로 채널별 메타데이터를 보완한 후, 핸들러는 채워진 객체를 UdsTransportProtocolMgr::HandleMessage()을(를) 통해 진단 코어로 전달합니다 [SWS_DM_00345]. (해석: 진단 응답을 위한 전송 경로에서 UdsMessage의 제공은 일반 코어에 의해 유사하게 수행될 것으로 추정됩니다.)

시퀀스 다이어그램: UDS 메시지 수신 시 상호작용 시퀀스. 출처: [SWS_DM_00385], [SWS_DM_00386], [SWS_DM_00388], [SWS_DM_00301], [SWS_DM_00302], [SWS_DM_00345]

오류 시나리오

동일한 Tester-Present 세션의 서비스 활성 처리로 인해 사용 중이어서 DM이 IndicateMessage()을(를) 통해 공지된 메시지를 처리할 수 없는 경우, DM은 kIndicationOccupied 상태와 nullptr과(와) 동일한 UdsMessagePtr을(를) 반환합니다 [SWS_DM_00386]. 이 경우 UdsMessage이(가) 제공되지 않으며 수신이 중단됩니다. 마찬가지로 알 수 없는 대상 주소는 널 포인터를 메시지 참조로 갖는 결과 kIndicationUnknownTargetAddress(으)로 이어집니다 AUTOSAR_AP_SWS_Diagnostics 100쪽.

버퍼를 채울 때 프로토콜 핸들러는 지정된 버퍼 용량을 준수해야 합니다: UdsMessage의 제공된 용량을 초과하는 수신 요청은 전체 버퍼 크기로 제한됩니다 [SWS_DM_00388]. 또한 여러 스레드에서 GetPayload() 또는 AddMetaInfo()에 동시에 보호되지 않은 채로 접근하면 정의되지 않은 동작이 발생하는데, 이는 해당 인터페이스들이 명시적으로 스레드 안전하지 않음(unsafe)(으)로 지정되어 있기 때문입니다 [SWS_DM_00300], [SWS_DM_00301], [SWS_DM_00302].

이 클래스 가이드는 Adaptive Platform을 위한 AUTOSAR 사양 R25-11을 기반으로 작성되었습니다.

apext::diag::uds_transport::UdsMessage 클래스의 가상 멤버 함수 AddMetaInfo은(는) 진단 메시지에 새 메타데이터를 할당하는 역할을 합니다 [SWS_DM_00302]. 일반적으로 전송 프로토콜 플러그인에 의해 호출되어 DoIP용 사전 정의된 메타데이터 키와 같은 채널별 추가 정보를 해당 진단 요청에 첨부합니다 AUTOSAR_AP_SWS_Diagnostics §C.5.2.2.2.1 “AddMetaInfo”.

인터페이스 사용에는 다음 기본 조건이 적용됩니다 [SWS_DM_00302]:

  • 호출 컨텍스트 및 헤더: 선언은 헤더 파일 apext/diag/uds_transport/uds_message.h을(를) 통해 제공되며 UdsMessage의 인스턴스에서 직접 실행됩니다 AUTOSAR_AP_SWS_Diagnostics §C.5.2.2.2.1 “AddMetaInfo”.
  • 전달 매개변수: MetaInfoMap 타입의 입력 매개변수 metaInfo은(는) 요청에 추가할 메타 정보를 전달합니다 [SWS_DM_00302].
  • 반환값: 이 동기식 함수는 반환값을 제공하지 않습니다(void) [SWS_DM_00302].
  • 오류 처리: 연산에는 noexcept 식별자가 지정되어 있으며 예외 안전(exception safe)으로 명세되어 있습니다. 특정 오류 코드는 존재하지 않습니다 [SWS_DM_00302].

동시성과 관련하여 이 메서드는 스레드 안전하지 않음(thread safety: unsafe)으로 선언되어 있습니다 [SWS_DM_00302]. 해석: 따라서 명세에서 내부 동기화를 제공하지 않으므로 호출자는 외부 메커니즘을 통해 UdsMessage의 동일 인스턴스에 대한 경합 접근을 보호할 책임이 있을 것으로 추정됩니다 AUTOSAR_AP_SWS_Diagnostics §C.5.2.2.2.1 “AddMetaInfo”.
