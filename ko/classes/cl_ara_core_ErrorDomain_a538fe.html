클래스 ara::core::ErrorDomain

[SWS_CORE_00110] Upstream: RS_AP_00130

class ErrorDomain {...};

Encapsulation of an ErrorDomain. An ErrorDomain is the controlling entity for ErrorCode’s error code values, and defines the mapping of such error code values to textual representations. This type constitutes a base class for ErrorDomain implementations. This class is a literal type, and subclasses are strongly advised to be literal types as well.

컨텍스트

ara::core::ErrorDomain 클래스는 AUTOSAR Adaptive의 오류 처리 모델 내에서 오류 값에 대한 중앙 제어 인스턴스를 형성합니다. 이 클래스는 유효 범위뿐만 아니라 도메인별 숫자 오류 코드(std::int32_t [SWS_CORE_00122]로서의 CodeType)를 의미 있는 텍스트 메시지에 매핑하는 정의를 제공합니다. 기본 클래스로서 구체적인 오류 도메인을 명세하는 데 사용됩니다. 이 클래스는 Literal Type으로 설계되었으며, 파생 클래스 역시 Literal Type으로 구현되어야 합니다.

시스템 아키텍처에서 ara::core::ErrorDomain은(는) 오류 코드, 구체적인 서브클래스, 호출자(Client) 및 예외 메커니즘 사이의 연결 고리 역할을 합니다. ara::core::ErrorCode은(는) 정수 오류 코드 외에도 이를 제어하는 오류 도메인에 대한 참조를 항상 캡슐화합니다. 이를 통해 서로 다른 기능 영역의 동일한 숫자 값이 잘못 동일시되는 것을 방지합니다. 필요한 경우 도메인은 텍스트 변환을 수행하거나 오류 코드를 형식화된 예외로 직접 변환합니다(ara::core::Exception).

컨텍스트 다이어그램: Client, ErrorCode 및 Exception과의 상호작용에서 오류 도메인의 역할. 출처: [SWS_CORE_00153], [SWS_CORE_00154]

수명 주기

생성자가 보호(protected)로 선언되어 있으므로(protected) [SWS_CORE_00135], ara::core::ErrorDomain의 생성은 파생된 서브클래스를 통해서만 수행됩니다. 생성자는 시스템 전체에서 반드시 고유해야 하는 도메인별 식별자(std::uint64_t [SWS_CORE_00121]로서의 IdType)를 전달받습니다. constexpr 및 noexcept(으)로 한정됨에 따라 컴파일 타임에 이미 초기화가 이루어질 수 있습니다.

소유 및 복사 시맨틱과 관련하여, 해당 클래스는 모든 복제 및 이동을 금지합니다. 복사 및 이동 생성자([SWS_CORE_00131], [SWS_CORE_00132])와 관련 할당 연산자([SWS_CORE_00133], [SWS_CORE_00134])가 모두 삭제된 것(= delete)(으)로 정의되어 있습니다. 따라서 일반적인 AUTOSAR Adaptive 시스템에서 구체적인 서브클래스의 인스턴스는 영구적이고 변경 불가능한 싱글톤 객체로 제공될 것으로 보입니다.

소멸자는 trivial하게 표준화되어 있으며(= default) protected(으)로 선언되어 있습니다 [SWS_CORE_00136]. 클래스가 Literal Type의 특성을 유지하도록 의도적으로 가상(virtual)으로 구현되지 않았으며, 기본 클래스 포인터를 통한 다형적 소멸은 시스템 개념상 예정되어 있지도 않고 필요하지도 않습니다. Name() [SWS_CORE_00152] 및 Message() [SWS_CORE_00153]과(와) 같은 검사 메서드의 반환값은 상수의 널 종료 문자열(const char*)에 대한 포인터를 제공합니다. 이러한 문자열은 서브클래스의 소유로 유지되며 호출 클라이언트가 해제해서는 안 됩니다. 클래스의 모든 멤버 함수는 스레드 안전(thread-safe)하도록 명세되어 있습니다.

사용 경로

오류 검사, 텍스트 확인 및 전달을 위한 일반적인 사용 흐름은 다음 단계로 구성됩니다:

  1. 식별 확인 및 도메인 비교: 도메인의 고유 식별자는 Id()을(를) 통해 조회됩니다 [SWS_CORE_00151]. operator== [SWS_CORE_00137] 또는 operator!= [SWS_CORE_00138]을(를) 통해 두 인스턴스를 비교할 때 Id()을(를) 통해 확인된 식별자의 일치 여부가 결과를 결정합니다.
  2. 이름 및 오류 텍스트 조회: Name()을(를) 사용하여 도메인의 심볼릭 이름을 확인할 수 있습니다 [SWS_CORE_00152]. 특정 코드에 대해 Message(errorCode)은(는) 결코 nullptr이(가) 아닌 널 종료 문자열로 해당 텍스트 메시지를 반환합니다 [SWS_CORE_00153].
  3. 예외 처리 트리거: 오류 상태를 대안적으로 예외로 전파해야 하는 경우 ThrowAsException(errorCode)이(가) 호출됩니다 [SWS_CORE_00154]. 도메인은 적절한 예외 유형을 결정하고, 전달된 ErrorCode을(를) 사용하여 해당하는 ara::core::Exception 객체를 생성한 후 이를 던집니다.

시퀀스 다이어그램: 오류 검사, 텍스트 조회 및 예외 처리를 위한 일반적인 흐름. 출처: [SWS_CORE_00137], [SWS_CORE_00152], [SWS_CORE_00153], [SWS_CORE_00154]

오류 시나리오

실제 사용 및 자체 도메인 구현 시 다음의 오류 조건과 제약 사항이 관련됩니다:

  • 도메인 소속 위반: 호출된 도메인에 속하지 않는 오류 코드가 Message(errorCode) 메서드에 전달되면 명세된 위반이 발생합니다(WrongDomainOfAn-ErrorCodeViolation) [SWS_CORE_00153]. 호출자는 코드의 도메인이 인스턴스와 일치하는지 확인해야 합니다.
  • 예외 안전성 및 툴체인 구성: 클래스의 인스펙터와 연산자는 예외 안전(exception safe) 및 noexcept(으)로 선언되어 있는 반면, ThrowAsException은(는) 명시적으로 noexcept(false)(으)로 어노테이션되어 있으며 예외 안전하지 않은 것(not exception safe)으로 분류됩니다 [SWS_CORE_00154]. 컴파일러 툴체인에서 C++ 예외가 비활성화된 경우, 요구사항에 따라 이 함수는 오버로드 확인에 참여해서는 안 됩니다 [SWS_CORE_00154].
  • 도메인 추가 데이터: 공급업체별 추가 정보를 제공하기 위해 클래스는 타입 별칭 SupportDataType을(를) 제공하며 [SWS_CORE_00123], 그 구조와 평가는 제조업체별로 정의됩니다.

이 가이드는 Release R25-11의 Core 모듈에 대한 AUTOSAR Adaptive 사양의 요구사항을 기반으로 합니다.
