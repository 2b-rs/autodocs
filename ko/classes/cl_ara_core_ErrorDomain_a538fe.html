클래스 ara::core::ErrorDomain

[SWS_CORE_00110] Upstream: RS_AP_00130

class ErrorDomain {...};

Encapsulation of an ErrorDomain. An ErrorDomain is the controlling entity for ErrorCode’s error code values, and defines the mapping of such error code values to textual representations. This type constitutes a base class for ErrorDomain implementations. This class is a literal type, and subclasses are strongly advised to be literal types as well.

클래스 ara::core::ErrorDomain은 오류 값을 제어하기 위한 추상 기본 클래스 역할을 하며 도메인 특정 코드를 해당 텍스트 표현에 매핑합니다 [SWS_CORE_00153]. 서브클래스는 시스템 전체에서 고유한 식별 번호를 캡슐화하고 불변 오류 텍스트로의 변환 및 타입별 예외 처리를 정의합니다. 컴파일 타임에 리터럴 타입(Literal Type)으로 사용할 수 있도록 기본 클래스는 비가상 보호 소멸자를 가집니다 [SWS_CORE_00136]. 이때 복사 및 이동 연산은 완전히 금지되므로 인스턴스는 불변 식별자로 기능합니다.

컨텍스트

ara::core::ErrorDomain 클래스는 AUTOSAR Adaptive Platform에서 구조화된 오류 관리의 공통 기반을 형성합니다. 이 클래스는 구체적인 오류 도메인을 위한 추상 기본 클래스로 동작하며, ara::core::ErrorCode에 캡슐화되는 오류 값에 대한 중앙 제어 책임을 담당합니다. 각 도메인은 자체 네임스페이스를 생성하고, Message()([SWS_CORE_00153])를 통해 CodeType([SWS_CORE_00122]) 타입의 도메인별 오류 값을 의미 있는 텍스트 표현으로 매핑하는 규칙을 정의합니다. 또한 이 클래스는 시스템 전역에서 고유한 도메인 식별자를 위한 타입 별칭 IdType([SWS_CORE_00121]) 및 공급업체별 추가 데이터를 위한 SupportDataType([SWS_CORE_00123])을 제공합니다.

전체 시스템에서 ara::core::ErrorDomain은(는) 세 가지 주요 대상과 상호작용합니다:

  • 서브클래스: 특정 오류 도메인은 ara::core::ErrorDomain을 상속하며, 도메인 이름, 오류 메시지 및 예외 처리를 위한 순수 가상 멤버 함수를 구현합니다.
  • ara::core::ErrorCode: 구체적인 오류 값을 나타내며 설명 텍스트 결정을 할당된 오류 도메인에 위임합니다.
  • 클라이언트 / 애플리케이션 코드: 오류 코드를 통해 또는 도메인에서 직접 상태 정보를 조회하거나([SWS_CORE_00152]) 발생한 C++ 예외를 수신합니다([SWS_CORE_00154]).

컨텍스트 다이어그램: 서브클래스, 오류 코드 및 애플리케이션 코드와 ara::core::ErrorDomain의 관계 및 협력. 출처: [SWS_CORE_00151], [SWS_CORE_00152], [SWS_CORE_00153], [SWS_CORE_00154].

수명 주기

ara::core::ErrorDomain의 인스턴스화는 보호됩니다. 생성자는 protected 가시성을 가지며 IdType([SWS_CORE_00135]) 타입의 시스템 전역에서 고유한 도메인 식별자를 필요로 합니다. 생성자가 constexpr 및 noexcept로 선언되어 있으므로, 기본 클래스는 컴파일 타임에 Literal Type으로서의 생성을 지원합니다. 서브클래스 역시 이러한 Literal Type 특성을 보장할 것이 명시적으로 권장됩니다.

도메인 인스턴스의 어떠한 복제 또는 전달도 금지됩니다:

  • 복사 생성자([SWS_CORE_00131]) 및 이동 생성자([SWS_CORE_00132])는 삭제된 것(delete)으로 선언되어 있습니다.
  • 복사 대입 연산자([SWS_CORE_00133]) 및 이동 대입 연산자([SWS_CORE_00134]) 역시 삭제되어 있습니다.

소멸자는 protected로 선언되고 기본 구현([SWS_CORE_00136])으로 정의됩니다. 클래스가 Literal Type으로 유지될 수 있도록 의도적으로 사소하며(trivial) 비가상으로 유지됩니다. ara::core::ErrorDomain가 순수 가상 인터페이스를 제공하지만, 기본 클래스 포인터를 통한 다형적 소멸은 필요하지 않습니다([SWS_CORE_00136]). 실제 환경에서 구체적인 도메인 인스턴스는 수명이 긴 객체 또는 정적 객체로 관리될 것입니다(해석).

소유권 관계와 관련하여 이름([SWS_CORE_00152]) 및 오류 텍스트([SWS_CORE_00153])에 대한 모든 포인터는 도메인 클래스의 소유로 유지되며, 클라이언트가 이를 해제해서는 안 됩니다. 모든 읽기 및 비교 연산은 스레드 안전하며 예외 안전합니다([SWS_CORE_00135], [SWS_CORE_00151]).

사용 경로

ara::core::ErrorDomain의 두 인스턴스는 Id()([SWS_CORE_00151])을 통해 확인된 도메인 식별자가 일치하는 경우에만 동일한 것으로 비교됩니다([SWS_CORE_00137], [SWS_CORE_00138]). 오류 확인 및 예외 처리의 일반적인 절차는 다음 단계로 구성됩니다:

  1. 도메인 식별: 클라이언트 또는 오류 객체는 Name()([SWS_CORE_00152])을 통해 도메인 이름을 널 종료 문자열로 확인합니다.
  2. 메시지 확인: Message(errorCode)을 통해 숫자 오류 값이 도메인에 전달됩니다([SWS_CORE_00153]). 도메인은 포인터 기반의 널 종료 오류 텍스트를 반환하며, 이는 결코 nullptr가 아닙니다.
  3. 예외 처리: 오류 코드를 예외로 변환해야 하는 경우 클라이언트는 ThrowAsException(errorCode)을 호출합니다([SWS_CORE_00154]). 그러면 도메인은 전달된 오류 코드를 캡슐화하는 적절한 ara::core::Exception 인스턴스를 발생시킵니다.

시퀀스 다이어그램: ErrorDomain을 통한 텍스트 확인 및 예외 발생의 일반적인 절차. 출처: [SWS_CORE_00152], [SWS_CORE_00153], [SWS_CORE_00154].

오류 시나리오

ara::core::ErrorDomain을 다룰 때 다음과 같은 오류 시나리오 및 인터페이스 요구사항을 고려해야 합니다:

  • 잘못된 도메인 소속: Message() 메서드에 특정 ErrorDomain에서 비롯되지 않은 errorCode이 전달되는 경우, 이는 명시된 위반 사항인 WrongDomainOfAn-ErrorCodeViolation에 해당합니다([SWS_CORE_00153]). 호출자는 오류 코드가 도메인 인스턴스와 일치함을 보장해야 합니다.
  • 비활성화된 C++ 예외: ThrowAsException() 메서드는 예외 안전하지 않으며(not exception safe) 예외를 발생시킵니다([SWS_CORE_00154]). 컴파일러 툴체인에서 C++ 예외가 비활성화된 경우, 이 함수는 오버로드 확인에 참여해서는 안 됩니다([SWS_CORE_00154]).
  • 널 포인터 배제: Name()과 Message() 모두 결코 nullptr를 반환해서는 안 됩니다([SWS_CORE_00152], [SWS_CORE_00153]). nullptr를 반환하는 서브클래스 구현은 인터페이스 사양을 위반합니다.
