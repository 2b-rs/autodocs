제조업체 또는 공급업체 검사를 기반으로 Diagnostic Management에서 수신 진단 요청을 검증합니다.

ara::diag::ServiceValidation 클래스는 제조업체 또는 공급업체 기준에 따라 Diagnostic Management에서 수신 UDS 진단 요청의 애플리케이션별 검증을 수행하는 역할을 합니다 [SWS_DM_00772]. 생성 후에는 서비스가 Offer()(으)로 활성화되어야 요청 데이터가 검사를 위해 비동기적으로 Validate()에 전달된 후 Confirmation()(으)로 확인됩니다 [SWS_DM_00776]. 주요 제약사항으로 인스턴스는 포트에 바인딩되며, 복사 및 이동이 모두 불가능하고 생성자를 제외하고는 스레드 안전하지 않습니다.

컨텍스트

ara::diag::ServiceValidation 클래스는 AUTOSAR Adaptive 진단 스택 내에서 모델링 요소 DiagnosticServiceValidationInterface을 위한 프로그래밍 인터페이스를 제공합니다. 애플리케이션은 이 인터페이스를 통해 수신 진단 요청에 대한 애플리케이션별 검사를 구현할 수 있습니다. 인스턴스는 Diagnostic Management(DM)와 직접 상호작용하며, DM은 수신 진단 요청을 검증 로직으로 전달하도록 인가됩니다 [SWS_DM_00776].

검증의 기능적 할당은 모델링 속성 DiagnosticServiceValidationMapping.category을 통해 제어됩니다. 이 범주에 따라 검증 메서드 Validate()은 ISO 14229-1(8.7절)에 따른 UDS 응답 규칙의 프레임워크 내에서 제조업체 검사(“Manufacturer Check”) 또는 공급업체 검사(“Supplier Check”)의 컨텍스트로 호출됩니다 [SWS_DM_00772]. DM은 유효하지 않은 요청을 조기에 필터링하기 위해 실제 서비스 실행 전에 수신 요청 메시지를 이 검증 검사에 적용할 것으로 추정됩니다.

수명 주기

생성은 시스템 모델에 정의된 PortPrototype을 참조해야 하는 ara::core::InstanceSpecifier을 지정하여 생성자를 통해 명시적으로 수행됩니다 [SWS_DM_00772]. ara::diag::ServiceValidation은 복사 불가능하고 이동 불가능한 단일 인스턴스로 설계되었습니다: 복사 생성자 [SWS_DM_01689]와 이동 생성자 [SWS_DM_01690]뿐만 아니라 복사 대입 연산자 [SWS_DM_01687] 및 이동 대입 연산자 [SWS_DM_01688]도 삭제된 것(=delete)으로 선언되어 있습니다.

초기화 후 객체는 유휴 상태에 머뭅니다. Offer()을 호출해야만 DM에서 핸들러로의 진단 요청 전달이 활성화됩니다 [SWS_DM_00776]. 런타임 중에 StopOffer()을 통해 서비스 제공을 종료할 수 있으며, 이로 인해 DM은 전달을 다시 비활성화합니다 [SWS_DM_00777]. 리소스 해제는 가상 소멸자 ~ServiceValidation()를 통해 수행됩니다 [SWS_DM_00773].

동시성과 관련하여 생성자만이 스레드 안전한 것으로 명시되어 있습니다 [SWS_DM_00772]. 메서드 Offer() [SWS_DM_00776], StopOffer() [SWS_DM_00777], Validate() [SWS_DM_00774], Confirmation() [SWS_DM_00775] 및 소멸자 [SWS_DM_00773]은 스레드 안전하지 않은 것으로 분류되지만 예외 안전성은 보장됩니다(noexcept).

사용 경로

구체적인 검증 로직은 아마도 애플리케이션이 ara::diag::ServiceValidation에서 파생되어 가상 인터페이스 메서드를 재정의함으로써 제공될 것입니다. 일반적인 작동 절차는 다음 단계로 나뉩니다:

  1. 인스턴스화: 구성된 포트를 참조하는 InstanceSpecifier을 전달하여 인스턴스를 생성합니다 [SWS_DM_00772].
  2. 서비스 제공: DM을 통한 요청 전달을 활성화하기 위해 Offer()을 호출합니다 [SWS_DM_00776].
  3. 검증: 수신 진단 요청마다 DM은 메서드 Validate()을 호출합니다 [SWS_DM_00774]. 서비스 식별자(SID)를 포함하는 원시 데이터가 ara::core::Span<const std::uint8_t>(으)로 전달되고 요청의 MetaInfo이 [SWS_DM_00774](으)로 전달됩니다. 데이터는 반환된 ara::core::Future<void>이 충족되거나 취소 핸들러에 의해 처리가 중단될 때까지 유효하게 유지됩니다 [SWS_DM_00774].
  4. 확인: 진단 요청 처리가 완료되는 즉시 DM은 결과 상태(ConfirmationStatusType) 및 MetaInfo를 전달하면서 메서드 Confirmation()을 통해 핸들러에 알립니다 [SWS_DM_00775].
  5. 비활성화: StopOffer()을 사용하여 요청 처리를 종료합니다 [SWS_DM_00777].

시퀀스 다이어그램: 진단 요청의 검증 및 확인을 위한 호출 순서. 출처: [SWS_DM_00772], [SWS_DM_00774], [SWS_DM_00775], [SWS_DM_00776], [SWS_DM_00777].

오류 시나리오

오류 조건은 생성 중의 정적 구성 검사뿐만 아니라 런타임에서도 발생합니다:

  • 생성 위반: 생성자는 특정 모델링 오류를 Violations로 보고합니다 [SWS_DM_00772]:
    • InstanceSpecifierMappingIntegrityViolation: 식별자를 Executable의 컨텍스트에서 해석할 수 없거나 PortPrototype을 가리키지 않습니다 [SWS_DM_00772].
    • PortInterfaceMappingViolation: 참조된 PortPrototype이 DiagnosticServiceValidationInterface(으)로 유형화되지 않았습니다 [SWS_DM_00772].
    • ProcessMappingViolation: 프로세스에 대해 일치하는 모델링된 Process이 존재하지 않습니다 [SWS_DM_00772].
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier이 실행 중인 프로세스에서 이미 다른 인스턴스에 의해 사용되고 있습니다 [SWS_DM_00772].
  • 서비스 제공: 서비스가 이미 활발하게 제공되고 있을 때 Offer()을 호출하면 반환값 ara::core::Result<void>이 오류 코드 DiagOfferErrc::kAlreadyOffered를 반환합니다 [SWS_DM_00776].
  • 검증 오류: 요청에 대한 내용 검사가 실패하면 애플리케이션은 DiagUdsNrcErrc을 통해 ISO 14229-1의 해당 Negative Response Code (NRC)를 설정하여 반환된 ara::core::Future<void>을 통해 거부를 알립니다 [SWS_DM_00774].

이 가이드는 diag 모듈에 대한 AUTOSAR Adaptive 사양 R25-11을 기반으로 합니다.

사용법 및 의미론

가상 콜백 함수는 요청 처리가 완료되는 즉시 Diagnostic Management에 의해 동기식으로 호출됩니다. 반환값은 없으며(void), 두 개의 전달 매개변수를 받습니다([SWS_DM_00775]):

  • status(ConfirmationStatusType): 서비스 처리의 최종 상태 또는 결과를 나타냅니다([SWS_DM_00775]).
  • metaInfo(const Meta Info &): 진단 요청의 관련 메타 정보를 포함합니다([SWS_DM_00775]).

오류 처리 및 동시성

이 함수는 예외 안전(exception safe)으로 명시되어 있으며 식별자 noexcept(으)로 선언되어 있습니다([SWS_DM_00775]). 따라서 애플리케이션 측의 오버라이드는 외부로 예외를 전파해서는 안 됩니다. DET 또는 DEM 메시지와 같은 특정 오류 코드는 이 메서드에 대해 정의되어 있지 않습니다. 동시성과 관련하여 Confirmation은(는) 스레드 안전하지 않은 것(not thread-safe)으로 분류되어 있으며([SWS_DM_00775]), 병렬 실행 시 콜백 내에서 애플리케이션 내부 상태에 접근하려면 적절한 동기화가 필요합니다.

상호 작용

알림 트리거는 진단 요청의 수명 주기 종료와 결합되어 있습니다([SWS_DM_00775]). 이 주기는 긍정 또는 부정 응답이 전송되거나 억제되는 즉시 완료됩니다(AUTOSAR_AP_SWS_Diagnostics §7.3.2.1.2 “Life-cycle of a Diagnostic Conversation”). 해석: 모듈 레벨에서 Diagnostic Management는 TransmitConfirmation 및 결과 kTransmitOk 또는 kTransmitFailed을(를) 통해 전송 계층에서 전송이 확인된 후에만 콜백 Confirmation을(를) 시작할 것으로 보입니다([SWS_DM_00307], [SWS_DM_00351]).

이 사용 지침은 AUTOSAR Adaptive R25-11 사양을 기반으로 AI에 의해 생성되었습니다.

      사용
      

      ara::diag::ServiceValidation 클래스의 Offer 멤버 함수(헤더 ara/diag/service_validation.h)는 Diagnostic Manager(DM)가 수신된 진단 요청을 이 특정 유효성 검사 핸들러로 전달하는 것을 활성화합니다 [SWS_DM_00776]. 호출은 시그니처 ara::core::Result<void> Offer() noexcept;를 통해 전달 매개변수 없이 동기식으로 수행됩니다 [SWS_DM_00776]. 반환값으로는 ara::core::Result<void>가 사용되며, 이는 성공 시 비어 있거나 오류 발생 시 발생한 오류 코드를 캡슐화합니다 [SWS_DM_00776].
      


      오류 처리
      

      등록에 실패하면 메서드는 오류가 발생한 Result을 반환합니다. 해당 인스턴스에 대해 서비스가 이미 이전에 제공된 경우, 오류 코드 DiagOfferErrc::kAlreadyOffered이 반환됩니다 [SWS_DM_00776]. 이때 롤백 시맨틱이 적용되므로 인스턴스의 이전 상태는 변경되지 않고 그대로 유지됩니다 [SWS_DM_00776].
      


      동시성 및 제약사항
      

      이 함수는 예외 안전(exception safe)으로 지정되어 있지만 명시적으로 스레드 안전하지 않은 것(not thread-safe)으로 지정되어 있습니다 [SWS_DM_00776]. 동일한 인스턴스에 대한 병렬 접근은 호출 애플리케이션에 의해 조정되어야 합니다. 순서와 관련하여, Diagnostic Manager가 유효성 검사를 위해 서비스 요청을 전달할 수 있으려면 먼저 Offer이 호출되어야 합니다 [SWS_DM_00776].
      


      상호 작용
      

      Offer을 통한 인터페이스 제공은 AUTOSAR Adaptive 진단의 일관된 설계 패턴이며, 루틴([SWS_DM_00557], [SWS_DM_00594]), 일반 UDS 서비스([SWS_DM_00619]), DoIP 기능([SWS_DM_00725], [SWS_DM_00735]) 및 보안 접근([SWS_DM_00766]) 등에서도 유사하게 사용됩니다. 인터페이스가 Offer을 통해 제공되지 않는 한, DM은 요청을 폐기하거나 정의된 대체 값으로 대체합니다([SWS_DM_01525], [SWS_DM_01527]). ara::com과의 개념적 유사성은 기능적 동기에서 비롯된 것이지만 진단의 독자적인 구현을 나타냅니다(AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 “Monitors”).
      

      

      본 사용 지침은 AUTOSAR Adaptive R25-11 명세를 기반으로 자동 작성되었습니다.

Diagnostic Server (DM)는 이를 통해 ISO 14229-1에 따른 구성된 제조업체별 [SWS_DM_01252] 및 공급업체별 서비스 검사[SWS_DM_01253]을(를) 수행합니다. 제조업체 또는 공급업체 검사로서의 할당은 생성자의 모델링에 따릅니다[SWS_DM_00772].

                          동시성과 관련하여 Validate은(는) 예외 안전(exception safe)이지만 스레드 안전하지 않은 것(not thread-safe)(으)로 지정되어 있습니다[SWS_DM_00774]. 해석: 이 함수는 스레드 안전하지 않으므로 Diagnostic Server는 동일한 인스턴스에 대한 호출을 직렬화하거나 경합하는 액세스를 배제해야 할 것으로 보입니다. 호출 컨텍스트는 실제 서비스 실행 전 ISO 14229-1의 NRC 시퀀스에 의해 정의됩니다[SWS_DM_00772].
