ara::core 클러스터의 오류 코드를 관리하고, 이를 오류 메시지로 변환하며, 관련 예외를 발생시킵니다.

ara::core::CoreErrorDomain 클래스는 기능 클러스터 ara::core의 오류를 위한 오류 도메인을 나타내며, 숫자 오류 코드에 설명 텍스트 메시지를 매핑합니다 [SWS_CORE_05243]. 또한 ThrowAsException()을 통해 오류 코드를 유형별 CoreException 예외로 변환할 수 있도록 지원합니다 [SWS_CORE_05244]. 모든 조회 메서드가 스레드 안전하고 constexpr 생성 가능하므로, 이 도메인은 효율적인 클러스터 전체 사용에 적합합니다. 툴체인에서 C++ 예외가 비활성화된 경우, 해당 예외 메서드는 오버로드 확인에 참여하지 않습니다.

컨텍스트

ara::core::CoreErrorDomain 클래스는 기능 클러스터 ara::core에서 기원하는 모든 오류 상태에 대한 특정 오류 도메인을 나타냅니다. 이 클래스는 ErrorDomain의 final 특수화로 정의되어 추가적인 파생을 방지합니다. 이 클래스는 Name() 메서드를 통해 도메인의 고유한 짧은 이름을 제공합니다 [SWS_CORE_05242]. AUTOSAR 오류 처리 모델과의 일관된 통합을 위해 CoreErrorDomain는 핵심 형식 별칭을 정의합니다. Errc은 열거형 CoreErrc을 직접 가리키는 별칭이며 [SWS_CORE_05231], Exception는 관련 기본 예외 클래스 CoreException의 별칭을 형성합니다 [SWS_CORE_05232]. 주요 상호작용 대상에는 각 오류 도메인에 대한 참조를 보유하는 ErrorCode 유형의 일반 오류 캡슐과 오류 상태를 진단하거나 처리하는 실행 컴포넌트가 포함됩니다.

수명 주기

CoreErrorDomain의 생성은 매개변수가 없는 기본 생성자 constexpr CoreErrorDomain() noexcept을 통해 수행됩니다 [SWS_CORE_05241]. 생성자가 constexpr 및 noexcept로 선언되어 있으므로 할당 오버헤드나 예외 위험 없이 컴파일 타임에 인스턴스를 이미 생성할 수 있습니다.

Interpretation: AUTOSAR Adaptive 표준에서 오류 도메인은 상태가 없도록 설계되었으며 오직 상수 메타데이터와 변환 로직만을 제공하므로, 일반적으로 클러스터 전체에서 액세스하는 전역 또는 정적 싱글톤 인스턴스가 시스템에 존재할 것으로 추정됩니다. 이 인스턴스는 프로세스의 전체 수명 동안 유효하게 유지됩니다. 동시성과 관련하여 클래스의 연산은 스레드 안전으로 지정되어 있어 [SWS_CORE_05241], [SWS_CORE_05242], [SWS_CORE_05243], 추가적인 동기화 조치 없이 여러 병렬 스레드에서의 동시 조회가 허용됩니다.

사용 경로

정상 작동 중에 CoreErrorDomain은 런타임 시스템 또는 애플리케이션 코드에 의해 주로 텍스트 오류 검사 및 예외 처리라는 두 가지 일반적인 시나리오에서 참조됩니다.

발생한 오류가 있는 경우, 숫자 오류 코드를 전달하면서 멤버 함수 Message()을 통해 관련 텍스트 메시지를 조회할 수 있습니다 [SWS_CORE_05243]. 명세는 이 함수가 널 포인터(nullptr)를 절대 반환하지 않음을 구속력 있게 보장하므로, 반환된 const char*은 진단 출력이나 로깅에 안전하게 사용될 수 있습니다. 오류를 반환값으로 처리하지 않고 C++ 예외로 전파하려는 경우에는 ThrowAsException() 메서드가 사용됩니다 [SWS_CORE_05244]. 이 메서드는 ErrorCode 인스턴스를 받아 해당 CoreException을 인스턴스화하고 이를 현재 호출 스택으로 발생시킵니다.

시퀀스 다이어그램: 오류 코드 변환 및 조건부 예외 발생의 일반적인 흐름. 출처: [SWS_CORE_05243], [SWS_CORE_05244]

오류 시나리오

함수 Name() 및 Message()과 생성자는 noexcept로 선언되어 있으며 예외 안전으로 분류됩니다 [SWS_CORE_05241], [SWS_CORE_05242], [SWS_CORE_05243]. 이들은 오류 상황에서도 예외를 발생시키지 않으며 자체 오류 코드를 생성하지 않습니다.

이와 대조적으로 ThrowAsException()은 명시적으로 noexcept(false)이 지정되어 있으며, 예외(CoreException 형식)의 결정론적 발생이 이 인터페이스의 기본 작업이므로 예외 안전이 아닌 것으로 표시되어 있습니다 [SWS_CORE_05244]. 핵심 아키텍처 사전 조건으로 다음이 적용됩니다. 사용되는 툴체인 또는 컴파일러 설정에서 C++ 예외가 비활성화된 경우, 이 함수는 오버로드 확인에 참여해서는 안 됩니다 [SWS_CORE_05244]. 이를 통해 C++ 예외 처리 없는 내결함성 임베디드 접근 방식을 따르는 시스템 환경에서 컴파일 오류를 방지합니다.

이 가이드는 R25-11 명세를 기반으로 AI 시스템에 의해 생성되었습니다.

              ara::core::CoreErrorDomain 클래스의 멤버 함수 ThrowAsException(헤더 ara/core/core_error_domain.h에 정의됨)은 전달된 오류 코드 [SWS_CORE_05244]을 기반으로 C++ 예외를 동기식으로 발생시키는 역할을 합니다. 매개변수로서 함수는 ErrorCode의 상수 인스턴스에 대한 참조를 받습니다(const ErrorCode &errorCode) [SWS_CORE_05244]. 메서드는 반환값을 가지지 않으며, 전달된 ErrorCode 객체를 완전히 캡슐화하는 CoreException 타입의 예외를 즉시 던집니다 [SWS_CORE_05244].
              

              실행 컨텍스트, 동시성 및 컴파일러 조건과 관련하여 다음 요구사항이 적용됩니다:
              

                

              • 스레드 안전성: 이 함수는 스레드 안전(thread-safe)으로 지정되어 있으므로 동시성 컨텍스트에서 안전하게 호출될 수 있습니다 [SWS_CORE_05244].
                • 

              • 예외 안전성: 함수가 noexcept(false)로 선언되어 있고 의도적으로 예외를 던지므로, 동작은 형식상 예외 안전하지 않음(not exception safe)으로 분류됩니다 [SWS_CORE_05244].
                • 

              • 컴파일러 제한사항: 컴파일러 툴체인에서 C++ 예외가 비활성화되어 있는 경우, [SWS_CORE_10304]에 따라 메서드는 오버로드 확인에 참여해서는 안 됩니다 [SWS_CORE_05244].
                • 

              

              아키텍처 구조상 이 메서드는 추상 클래스 ara::core::ErrorDomain의 순수 가상 기본 함수 ThrowAsException을 재정의(override)합니다 [SWS_CORE_00154]. 일반적인 애플리케이션에서 이 함수는 도메인 객체에서 직접 호출되지 않고, this->Domain().ThrowAsException(*this)를 통해 호출을 담당 오류 도메인으로 동적으로 전달하는 도우미 메서드 ErrorCode::ThrowAsException()를 통해 트리거됩니다 [SWS_CORE_00519].
