State Management 내에서 오류 코드 및 예외의 정의와 변환을 담당합니다.

클래스 ara::sm::SmErrorDomain은(는) State Management의 도메인 특화 오류 도메인을 나타내며, 기능적 오류 코드를 사람이 읽을 수 있는 텍스트 메시지 및 C++ 예외에 매핑합니다([SWS_SM_81241]). 런타임에 이 클래스는 스레드 안전한 메서드를 통해 도메인을 식별하고 로깅 및 진단을 위해 개별 오류 값을 변환할 수 있도록 합니다. 중대한 오류가 발생하면 인터페이스를 통해 형식화된 예외를 발생시킬 수도 있습니다([SWS_SM_81250]). 툴체인에서 C++ 예외가 비활성화된 경우 예외 로직은 사용할 수 없으며 오류는 대신 순수하게 값 기반으로 처리되어야 합니다.

컨텍스트

클래스 ara::sm::SmErrorDomain은(는) Adaptive Platform에서 State Management 기능 클러스터에 대한 특정 오류 도메인을 정의합니다([SWS_SM_81241], SWS StateManagement §8.1.3 “Class: SmErrorDomain”). 일반 오류 도메인 아키텍처의 특수화로서 [SWS_CORE_90023]의 사양에 따라 ara::core::ErrorDomain에서 상속됩니다. 주요 책임은 State Management의 오류 상태를 의미론적으로 캡슐화하고, 표준화된 오류 식별자를 제공하며, 숫자 오류 코드, 오류 텍스트 및 예외 타입 간의 매핑을 보장하는 것입니다.

주요 상호작용 대상에는 오류를 생성하는 State Management의 내부 컴포넌트와 ara::core::ErrorCode을(를) 통해 오류를 수신하는 상위 애플리케이션 및 플랫폼 서비스가 포함됩니다. 공용 타입 별칭 Errc을(를) 통해 클래스는 도메인 특화 열거형 SmErrc을(를) 참조합니다([SWS_SM_81245]). 또한 타입 별칭 Exception은(는) 연관된 예외 기본 클래스 SmException을(를) 참조합니다([SWS_SM_81246], SWS StateManagement §8.1.3.1.2 “Type Alias: Exception”).

수명 주기

ara::sm::SmErrorDomain의 인스턴스는 매개변수가 없는 기본 생성자를 통해 생성됩니다([SWS_SM_81247], SWS StateManagement §8.1.3.2.1.1 “Default Constructor”). 이 생성자는 noexcept(으)로 선언되어 있으며 exception safe 등급을 가집니다. AUTOSAR Adaptive 에코시스템에서는 오류 코드를 해석하기 위해 프로세스 전반에서 오류 도메인이 필요하므로, 일반적인 시스템 환경에서 SmErrorDomain의 인스턴스는 수명이 긴 객체 또는 정적 객체로 존재하는 것이 좋습니다.

동시성과 관련하여 클래스의 핵심 함수는 동시 작동을 위해 명시되어 있습니다. 메서드 Name()([SWS_SM_81248]) 및 Message()([SWS_SM_81249])은(는) thread-safe 및 exception safe로 지정되어 있습니다. 따라서 여러 실행 스레드가 외부 동기화 없이도 병렬로 오류 정보를 질의할 수 있습니다.

사용 경로

일반적인 사용 경로는 오류 도메인 식별, 오류 코드를 읽기 쉬운 진단 메시지로 변환, 그리고 선택적으로 C++ 예외로 변환하는 작업을 포함합니다. 먼저 애플리케이션 또는 플랫폼 컴포넌트는 Name()을(를) 통해 도메인 이름을 조회할 수 있으며, 이는 불변의 식별자 "Sm"을(를) 반환합니다([SWS_SM_81248]).

State Management에서 오류가 발생하면 해당 코드가 Message(errorCode)을(를) 통해 전달됩니다([SWS_SM_81249], SWS StateManagement §8.1.3.2.2.1 “Message”). 이 함수는 연관된 문자열에 대한 포인터(const char*)를 반환하므로 로깅 및 진단 시스템이 의미 있는 메시지를 수신하게 됩니다. 호출하는 하위 시스템이 예외 기반 오류 처리를 사용하도록 설계된 경우, 오류 객체를 ThrowAsException()에 전달하여([SWS_SM_81250]) 오류 코드에 해당하는 예외가 인스턴스화되고 던져지도록 합니다.

시퀀스 다이어그램: 오류 정보 조회 및 선택적 예외 발생 시의 일반적인 순서. 출처: [SWS_SM_81247], [SWS_SM_81248], [SWS_SM_81249], [SWS_SM_81250].

오류 시나리오

도메인에서 관리하는 오류 상태는 Errc을(를) 통해 별칭이 지정되는 열거형 타입 SmErrc을(를) 기반으로 합니다([SWS_SM_81245]). 오류 상황은 ara::core::ErrorCode 기반의 반환값 또는 Exception 타입의 예외를 통해 나타납니다(SmException, [SWS_SM_81246]).

ThrowAsException() 호출 시 이 메서드는 개념상 오류 코드와 연결된 예외를 능동적으로 발생시키므로 not exception safe로 간주됩니다([SWS_SM_81250]). 이 메서드의 가용성에 대한 중요한 사전 조건은 툴체인 구성과 관련이 있습니다. [SWS_CORE_10304]에 따라 컴파일러 툴체인에서 C++ 예외가 비활성화된 경우 ThrowAsException()은(는) 오버로드 확인에 참여하지 않습니다([SWS_SM_81250]). 따라서 예외가 지원되지 않는 시스템 구성에서는 오류 처리가 엄격히 반환 코드를 통해서만 처리되어야 합니다.

인터페이스는 다음과 같은 매개변수 및 반환값을 가집니다[SWS_SM_81249]:

  • 매개변수: CodeType 타입의 errorCode은(는) 연관된 텍스트 메시지가 요청되는 숫자 형태의 오류 번호를 전달받습니다.
  • 반환값: 전달된 오류 코드에 할당된 오류 메시지를 가리키는 const char * 타입의 포인터입니다.

AUTOSAR Adaptive의 오류 관리 프레임워크 내에서 이 메서드는 기본 오류 도메인의 가상 함수를 재정의합니다. 해석: 반환값이 할당 인터페이스가 없는 const char *(으)로 정의되어 있으므로, 포인터는 일반적으로 전체 프로세스 런타임 동안 유효하게 유지되는 정적 문자열 리터럴을 참조할 것으로 추정됩니다.
