인터페이스 ara::crypto::cryp::SignerPrivateCtx은 Adaptive Platform에서 전자 서명 연산을 위한 비공개 키를 캡슐화합니다 [SWS_CRYPT_23501]. SetKey()을 통해 키를 구성한 후, 메시지는 Sign()을 통한 단일 단계 또는 Start(), Update(), Finish()을 통한 다단계 방식으로 서명될 수 있습니다 [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50040]. 모든 호출은 스레드 안전하며, 불충분한 버퍼 용량 또는 유효하지 않은 컨텍스트 상태와 같은 오류를 ara::core::Result을 통해 전달합니다 [SWS_CRYPT_50040].

컨텍스트

인터페이스 ara::crypto::cryp::SignerPrivateCtx은 AUTOSAR Adaptive Platform에서 비공개 키를 사용하는 전자 서명 연산의 암호화 실행 컨텍스트를 나타냅니다. 이 클래스는 CryptoContext로부터 상속되며 비대칭 서명 알고리즘을 캡슐화합니다. 필요한 키 자료를 바인딩하기 위해 컨텍스트는 PrivateKey::Sptr를 통해 비공개 키 객체와 직접 상호작용하거나 [SWS_CRYPT_23515], KeySlot::Sptr를 통해 관리형 키 슬롯과 상호작용합니다 [SWS_CRYPT_50036]. 호출자는 일반적으로 정의된 스마트 포인터 타입 에일리어스 ara::crypto::cryp::SignerPrivateCtx::Sptr을 통해 이 인터페이스의 인스턴스를 관리합니다 [SWS_CRYPT_23501].

수명 주기

SignerPrivateCtx의 인스턴스는 상태 기반 객체로 동작하며 공유 포인터 구조체(std::shared_ptr)를 통해 관리됩니다 [SWS_CRYPT_23501]. 암호화 연산을 수행하기 전 인스턴스는 초기화되지 않은 상태에 있으며 적절한 키의 할당을 필요로 합니다. 메서드 SetKey()을 통해 컨텍스트에 구체적인 비공개 키가 할당되거나 [SWS_CRYPT_23515], 서명 계산 시작 시점에 키 값이 참조되는 KeySlot이 지정됩니다 [SWS_CRYPT_50036]. 키가 성공적으로 바인딩되면 컨텍스트는 작동 준비 상태로 전환됩니다. 모든 인터페이스 메서드는 예외 안전(exception safe) 및 스레드 안전(thread-safe)으로 명세되어 있습니다 [SWS_CRYPT_23512] [SWS_CRYPT_50037].

데이터 처리 내에서 인터페이스는 단일 서명과 다단계 스트리밍 방식을 구분합니다. 스트리밍 서명 연산은 Start()에 의해 개시되고 [SWS_CRYPT_50037] [SWS_CRYPT_50038], Update()을 통해 단계별로 데이터 블록을 공급받으며 [SWS_CRYPT_50039], Finish()에 의해 완료됩니다 [SWS_CRYPT_50040]. 또는 진행 중인 스트리밍을 Cancel()을 통해 언제든지 중단할 수 있으며, 이 경우 인스턴스는 작동 준비 상태로 복귀합니다 [SWS_CRYPT_50041].

상태 다이어그램: 구성부터 연산 완료까지 서명 컨텍스트의 상태 전이. 출처: [SWS_CRYPT_23515], [SWS_CRYPT_50036], [SWS_CRYPT_23512], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040], [SWS_CRYPT_50041]

사용 경로

애플리케이션은 단일 단계(Single-Call) 또는 연속적인 데이터 스트림(Streaming) 방식으로 서명을 생성할 수 있습니다. 실행 전에 애플리케이션은 GetSignatureSize()을 통해 원하는 서명 형식에 대한 예상 버퍼 크기를 확인하고 FormatId [SWS_CRYPT_29004], GetMaximumChunkSize()을 통해 개별 읽기 연산의 최대 허용 블록 크기를 확인합니다 [SWS_CRYPT_50042].

단일 단계 경로에서는 Sign()을 사용하여 전체 메시지가 직접 서명됩니다. 이 메서드는 입력 메시지, 대상 버퍼 ReadWriteMemRegion, 서명 형식 및 선택적 알고리즘별 컨텍스트 값을 전달받아 실제로 기록된 바이트 수를 반환합니다 [SWS_CRYPT_23512].

더 큰 데이터양 또는 분할된 메시지의 경우 스트리밍 경로는 3단계 패턴을 따릅니다:

  1. 초기화: 매개변수 없이 Start()을 호출하거나 [SWS_CRYPT_50037], 애플리케이션별 컨텍스트 버퍼를 포함하여 호출합니다 ReadOnlyMemRegion [SWS_CRYPT_50038].
  2. 처리: Update()을 통해 부분 메시지를 반복적으로 공급하며, 각 블록은 GetMaximumChunkSize()에 의해 지정된 상한을 준수해야 합니다 [SWS_CRYPT_50039] [SWS_CRYPT_50042].
  3. 완료 또는 중단: Finish()을 통해 서명 생성을 완료하고 대상 메모리에 기록하거나 [SWS_CRYPT_50040], Cancel()를 사용하여 진행 중인 작업을 조기에 중단합니다 [SWS_CRYPT_50041].

시퀀스 다이어그램: 버퍼 검사 및 완료를 포함하는 스트리밍 서명 생성의 전형적인 흐름. 출처: [SWS_CRYPT_23515], [SWS_CRYPT_29004], [SWS_CRYPT_50037], [SWS_CRYPT_50039], [SWS_CRYPT_50040]

오류 시나리오

메서드 호출은 기본적으로 ara::core::Result을 반환하며, 실패 시 롤백 시맨틱을 갖는 ara::crypto::CryptoErrc의 표준화된 오류 코드를 사용합니다. 흔한 오류 원인은 다음과 같습니다:

  • CryptoErrc::kUninitializedContext: 키가 SetKey()을 통해 바인딩되기 전에 Sign() 또는 Start()를 호출함 [SWS_CRYPT_23512] [SWS_CRYPT_50037] [SWS_CRYPT_50038].
  • CryptoErrc::kUsageViolation: 제공된 키에 필요한 사용 권한이 없음 kAllowSigGeneration [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50037].
  • CryptoErrc::kIncompatibleObject: 전달된 PrivateKey 또는 KeySlot가 컨텍스트의 알고리즘과 호환되지 않음 [SWS_CRYPT_23515] [SWS_CRYPT_50036].
  • CryptoErrc::kProcessingNotStarted: 사전에 Start()가 성공적으로 호출되지 않은 상태에서 Update(), Finish() 또는 Cancel()을 호출함 [SWS_CRYPT_50039] [SWS_CRYPT_50040] [SWS_CRYPT_50041].
  • CryptoErrc::kInsufficientCapacity: Sign() 또는 Finish()에 전달된 출력 버퍼가 기록될 서명보다 작음 [SWS_CRYPT_23512] [SWS_CRYPT_50040].
  • CryptoErrc::kUnsupportedFormat: 요청된 FormatId이 컨텍스트에서 지원되지 않음 [SWS_CRYPT_29004] [SWS_CRYPT_23512] [SWS_CRYPT_50040].
  • CryptoErrc::kEmptyKeySlot: 구성된 KeySlot에 실행 시점에 키가 포함되어 있지 않음 [SWS_CRYPT_23512] [SWS_CRYPT_50037].
  • CryptoErrc::kInvalidInputSize: Sign(), Start() 또는 Update() 호출 시 유효하지 않은 버퍼 크기 [SWS_CRYPT_23512] [SWS_CRYPT_50038] [SWS_CRYPT_50039].
