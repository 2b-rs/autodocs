임의의 컨테이너 또는 버퍼의 연속된 메모리 영역에 대해 효율적인 비소유 뷰를 제공합니다.

클래스 ara::core::Span은 메모리 영역에 대한 비소유 연속 뷰를 제공하며 복사 비용 없이 배열이나 버퍼를 효율적으로 캡슐화할 수 있도록 합니다 [SWS_CORE_01942]. 애플리케이션은 일반적으로 데이터 윈도우 전달 및 슬라이싱 작업을 통한 하위 뷰 생성에 이 클래스를 사용합니다. 경계 위반은 정의되지 않은 동작을 유발하므로 호출자는 기본 메모리의 수명이 뷰의 수명보다 오래 지속되고 subspan()와 같은 작업 시 유효한 경계가 준수되는지 엄격히 확인해야 합니다 [SWS_CORE_01966].

컨텍스트

클래스 ara::core::Span은 [views.span]의 std::span을 지향하는 연속 시퀀스 뷰의 표준 준수 구현을 나타냅니다. 경량 추상화로서 데이터 자체를 소유하지 않고 첫 번째 요소에 대한 포인터와 사용 가능한 요소 수를 캡슐화합니다. 이는 데이터를 제공하는 컴포넌트와 해당 데이터를 처리하는 알고리즘 간의 통일된 인터페이스 역할을 합니다.

주요 상호작용 대상은 다음과 같습니다:

  • 호출 애플리케이션 로직: 메모리 할당이나 복사 오버헤드 없이 순차적 메모리 영역에 대한 읽기 또는 쓰기 접근을 위해 뷰를 사용합니다.
  • 메모리 소스 및 컨테이너: 기본 C 배열 [SWS_CORE_01944], ara::core::Array [SWS_CORE_01945] [SWS_CORE_01946]과 같은 표준화된 플랫폼 컨테이너, 제네릭 컨테이너 구조 [SWS_CORE_01947] [SWS_CORE_01948], 또는 포인터와 길이 지정이 포함된 원시 버퍼 [SWS_CORE_01942]와 같은 임의의 연속 메모리 영역.
  • 하위 뷰(Subspans): 상위 뷰에서 분할되어 생성되는 ara::core::Span의 추가 인스턴스 [SWS_CORE_01965] [SWS_CORE_01966].

컨텍스트 다이어그램: 애플리케이션 로직과 메모리 버퍼 사이의 비소유 뷰로서 ara::core::Span의 통합. 출처: [SWS_CORE_01942], [SWS_CORE_01945], [SWS_CORE_01951]

수명 주기

ara::core::Span의 인스턴스는 자체 리소스 관리가 없는 순수 값 객체로 설계되었습니다. 생성은 기본 생성자 [SWS_CORE_01941]을 통해 비어 있는 span으로 수행되거나, 시작 주소와 요소 수를 직접 지정하거나 [SWS_CORE_01942], 시작과 끝의 포인터 간격을 통해 선택적으로 수행됩니다 [SWS_CORE_01943]. 또한 C 배열 [SWS_CORE_01944], ara::core::Array 타입의 컨테이너 [SWS_CORE_01945] [SWS_CORE_01946], 그리고 제네릭 컨테이너 [SWS_CORE_01947] [SWS_CORE_01948]를 위한 타입화된 생성자가 제공됩니다. 기존 span은 기본 복사 생성자 [SWS_CORE_01949]을 통해 복제하거나 호환되는 요소 타입 및 익스텐트(extents)를 갖는 변환 생성자를 통해 복제할 수 있습니다 [SWS_CORE_01950].

ara::core::Span은 참조된 데이터에 대한 소유권을 전혀 갖지 않으므로 소멸자는 기본 구현을 가지며 noexcept=default로 지정됩니다 [SWS_CORE_01951]. 이로부터 기본 메모리 버퍼의 수명은 항상 이를 참조하는 모든 span 객체의 수명 이상을 포함해야 한다는 근본적인 불변 조건(해석: 가정 1)이 도출됩니다. 버퍼 소멸 시 남아 있는 span은 유효하지 않게 됩니다. 할당 연산자를 통한 할당은 얕은 복사(shallow copy)를 통해 사소하게 수행됩니다 [SWS_CORE_01952]. 모든 접근 함수가 noexcept로 선언되어 있고 내부 동기화 메커니즘을 포함하지 않으므로, 기본 메모리 영역이 병렬로 수정되지 않는 한 여러 스레드에서 동일한 span 인스턴스에 대한 동시 읽기 접근은 안전한 것으로 간주됩니다(해석: 가정 2).

사용 경로

일반적인 사용 사례는 기존 데이터 블록 캡슐화, 차원 검사, 관련 섹션 추출 및 요소 접근을 포함합니다:

  1. 뷰 생성: 애플리케이션은 ara::core::Array [SWS_CORE_01945] 인스턴스 또는 길이 정보가 있는 원시 데이터 포인터 [SWS_CORE_01942]와 같은 연속 버퍼에서 ara::core::Span을 인스턴스화합니다.
  2. 상태 및 차원 검사: 추가 처리 전에 empty() [SWS_CORE_01969], size() [SWS_CORE_01967] 또는 size_bytes() [SWS_CORE_01968]를 통해 치수를 확인하거나, data() [SWS_CORE_01971]을 사용하여 기본 주소를 쿼리합니다.
  3. 슬라이싱 / Subspan 생성: 관련 데이터 윈도우에 집중하기 위해 애플리케이션은 first() [SWS_CORE_01961] [SWS_CORE_01962]를 사용하는 접두사, last() [SWS_CORE_01963] [SWS_CORE_01964]를 사용하는 접미사, 또는 subspan() [SWS_CORE_01965] [SWS_CORE_01966]을 사용하는 임의의 하위 영역을 통해 하위 뷰를 생성합니다.
  4. 요소 처리: 실제 데이터 접근은 인덱스 연산자 operator[] [SWS_CORE_01970]을 통한 임의 접근, front() [SWS_CORE_01959] 및 back() [SWS_CORE_01960]를 통한 경계 요소 접근, 또는 begin()부터 end() [SWS_CORE_01972] [SWS_CORE_01973]까지의 반복자를 통한 순차 접근으로 수행됩니다.

시퀀스 다이어그램: 뷰의 생성, 분할 및 요소 쿼리를 위한 일반적인 호출 순서. 출처: [SWS_CORE_01942], [SWS_CORE_01966], [SWS_CORE_01970]

오류 시나리오

ara::core::Span의 모든 메서드는 예외 안전 및 noexcept로 선언되어 있습니다. C++ 예외가 발생하지 않으며 ara::core::ErrorCode와 같은 오류 객체도 반환되지 않습니다. 오류 상태는 주로 사전 조건 위반으로 인해 발생하며, 이는 즉시 정의되지 않은 동작(Undefined Behavior)으로 이어집니다:

  • 접두사 및 접미사 크기 초과: first()에서 현재 크기를 초과하는 수량이 요청되는 경우(Count > size() 또는 count > size()), 동작은 정의되지 않습니다 [SWS_CORE_01961] [SWS_CORE_01962]. 동일한 사전 조건 위반은 last()에서도 정의되지 않은 동작으로 이어집니다 [SWS_CORE_01963] [SWS_CORE_01964].
  • subspan에서 유효하지 않은 부분 영역 매개변수: subspan() 호출은 offset <= size()이 유효하고, 명시적으로 지정된 count(dynamic_extent과 다름)의 경우 추가로 count <= size() - offset가 준수될 것을 필수로 요구합니다. 이를 무시하면 정의되지 않은 동작이 발생합니다 [SWS_CORE_01966].
  • 요소 접근 시 범위 초과: 인덱스 연산자 operator[] [SWS_CORE_01970] 및 접근 함수 front() [SWS_CORE_01959], back() [SWS_CORE_01960]는 범위 검사(Bounds Checking)를 수행하지 않습니다. 유효한 범위를 벗어난 접근은 정의되지 않은 메모리 접근으로 직결되는 것으로 보입니다(해석: 가정 3).
