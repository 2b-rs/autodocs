Network Management를 위한 오류 도메인을 정의하고 오류 코드를 메시지 또는 Exception으로 변환합니다.

오류 도메인 ara::nm::NmErrorDomain은 AUTOSAR Adaptive Platform에서 Network Management의 오류 처리를 캡슐화하고 오류 코드 NmErrc 및 예외 클래스 NmException를 통합합니다 [SWS_ANM_01101]. 주요 작업에는 Message()를 통한 판독 가능한 오류 메시지 제공과 ThrowAsException()를 통한 연관된 예외의 제어된 발생이 포함됩니다 [SWS_ANM_01108]. 핵심 제약 조건으로 인스턴스화 및 모든 멤버 함수가 스레드 안전하게(thread-safe) 구현되어 전체 시스템에서 동시 오류 쿼리가 보장됩니다.

컨텍스트

클래스 ara::nm::NmErrorDomain은 AUTOSAR Adaptive Platform 내에서 Network Management 하위 시스템을 위한 도메인별 오류 도메인 역할을 합니다 [SWS_ANM_01101]. 기본 클래스 ara::core::ErrorDomain의 최종 특수화로서 Network Management 기능 작동 중에 발생할 수 있는 오류를 식별하고 텍스트로 설명하며 전달하기 위한 표준화된 프레임워크를 제공합니다 [SWS_ANM_01101].

NM 오류 처리 개념 내에서 이 클래스는 구체적인 오류 원인을 런타임 환경의 일반적인 오류 처리 메커니즘과 연결합니다. 여기서 클래스는 유형 별칭을 통해 관련 유형과의 직접적인 매핑을 정의합니다. 별칭 Errc을 통해 Network Management용 특정 오류 코드를 선언하는 기본 열거형 NmErrc을 통합합니다 [SWS_ANM_01103]. 동시에 별칭 Exception을 통해 특수화된 예외 클래스 NmException를 참조하므로, 필요한 경우 오류를 C++ 예외 메커니즘으로 변환할 수 있습니다 [SWS_ANM_01104]. 이러한 번들링을 통해 NmErrorDomain은 모듈의 오류 상태와 ara::core의 오류별 기본 시스템 사이의 중심 연결 고리 역할을 합니다.

수명 주기

ara::nm::NmErrorDomain의 인스턴스 생성은 매개변수가 없는 기본 생성자 [SWS_ANM_01105]을 통해 수행됩니다. 클래스가 final로 지정되어 있으므로 파생된 오류 도메인에 의한 추가 세분화 또는 특수화가 명시적으로 금지됩니다 [SWS_ANM_01101]. 생성자는 noexcept로 선언되어 있어 오류 도메인의 인스턴스화가 예외를 발생시키지 않고 수행됨을 보장합니다 [SWS_ANM_01105].

소유권과 관련하여 이 오류 도메인의 인스턴스는 오류 코드 객체의 참조를 통해 영구적으로 사용할 수 있도록 메모리상에 수명이 긴 전역 객체로 존재하는 것이 일반적입니다. 수명 주기의 핵심 특징은 동시성 동작입니다. 인스턴스 생성 [SWS_ANM_01105]뿐만 아니라 이름 쿼리 [SWS_ANM_01106], 메시지 생성 [SWS_ANM_01107], 예외 발생 [SWS_ANM_01108]과 같은 모든 인터페이스 함수가 완전한 스레드 안전성(thread-safe)을 갖추도록 설계되었습니다. NmErrorDomain의 인스턴스는 변경 가능한 상태를 갖지 않으므로 추가 동기화 조치 없이 여러 스레드에서 동시에 사용할 수 있습니다.

사용 경로

일반적인 사용 경로는 Network Management에서 오류 상태를 분석, 로깅 또는 예외로 변환해야 하는 즉시 시작됩니다. 이를 위해 오류 도메인은 기본적인 식별 및 평가 기능을 제공합니다.

도메인의 일반적인 식별을 위해 도메인 이름을 상수 문자열 포인터로 반환하는 Name() 메서드를 호출할 수 있습니다 [SWS_ANM_01106]. 애플리케이션 또는 기본 시스템이 발생한 오류 코드의 텍스트 의미를 확인하려는 경우, 오류 코드를 전달하여 Message() 메서드를 호출합니다 [SWS_ANM_01107]. 이 메서드는 연관된 오류 메시지를 const char*로 반환하며, noexcept 선언을 통해 진단 프로세스 자체가 예외로부터 안전함을 보장합니다 [SWS_ANM_01107].

제어 흐름에서 시스템별 예외를 발생시켜야 하는 경우 ThrowAsException() 메서드가 사용됩니다 [SWS_ANM_01108]. 이 함수는 ara::core::ErrorCode 유형의 오류 객체를 수신하고 이에 일치하는 NmException 유형의 Exception을 발생시킵니다 [SWS_ANM_01104], [SWS_ANM_01108]. 실제 환경에서 이 호출은 주로 오류 객체의 해당 도우미 메서드를 통해 간접적으로 수행될 것으로 보입니다.

시퀀스 다이어그램: 오류 도메인을 통한 Network Management 오류 코드의 유형별 NmException 변환. 출처: [SWS_ANM_01104], [SWS_ANM_01108].

오류 시나리오

오류 처리의 일환으로 도메인은 별칭 Errc을 통해 열거형 NmErrc으로 정의된 모듈의 모든 오류 사례를 다룹니다 [SWS_ANM_01103]. 도메인 자체는 오류 평가를 결정론적으로 보장하도록 설계되었습니다.

Message()을 통한 텍스트 메시지 확인 시 noexcept 선언은 유효하지 않은 오류 코드인 경우에도 예기치 않은 예외가 발생하지 않도록 보장합니다 [SWS_ANM_01107]. 클래스가 능동적으로 예외를 발생시키는 유일하게 계획된 시나리오는 ThrowAsException()의 명시적 호출입니다 [SWS_ANM_01108]. noexcept(false) 선언을 통해 이 메서드는 NmException의 인스턴스를 발생시켜 프로그램을 필수적으로 예외 처리 경로로 전환함을 알립니다 [SWS_ANM_01104], [SWS_ANM_01108]. 따라서 호출 컴포넌트는 필요한 경우 이러한 호출이 적절한 예외 블록에 의해 포착되도록 보장해야 합니다.

이 가이드는 AUTOSAR Adaptive R25-11 사양을 기반으로 하며 AI 어시스턴트에 의해 생성되었습니다.

              기본 생성자 NmErrorDomain()은(는) Network Management([SWS_ANM_01105])용 오류 도메인을 생성하는 역할을 합니다. 이 함수는 헤더 ara/nm/nm_error_domain.h에 선언되어 있으며, ara::core::ErrorDomain을(를) 상속하는 클래스 NmErrorDomain의 인스턴스를 생성합니다([SWS_ANM_01101]).
              

  
              사용 및 동시성
              
  
              생성자는 매개변수를 받지 않으며 반환값이 없습니다([SWS_ANM_01105]). 인스턴스화는 동기식으로 수행됩니다. 사양에 따라 이 호출은 thread-safe(으)로 분류되므로, 병렬 스레드에서도 오류 도메인을 안전하게 생성할 수 있습니다([SWS_ANM_01105]).
              

  
              오류 처리
              
  
              이 함수는 식별자 noexcept(으)로 명시되어 있습니다([SWS_ANM_01105]). 따라서 실행 시 예외가 발생하지 않습니다. 이 생성에 대해 특정 오류 코드나 오류 처리 메커니즘은 제공되지 않습니다.
              

  
              상호 작용
              
  
              생성된 클래스 NmErrorDomain은(는) Network Management 오류에 대한 도메인별 컨텍스트를 정의합니다([SWS_ANM_01101]). 전체 시스템에서 도메인을 제공하기 위해 주로 const ara::core::ErrorDomain& 유형의 전역 참조를 반환하는 함수 GetNmDomain()이(가) 사용됩니다([SWS_ANM_01109]). 애플리케이션 및 플랫폼 컴포넌트는 일반적으로 GetNmDomain()을(를) 통해 노출된 싱글톤 참조를 검색하므로, 일반적인 애플리케이션 시나리오에서 생성자 NmErrorDomain()을(를) 통한 직접 인스턴스화는 드물게 필요할 것으로 추정됩니다.
