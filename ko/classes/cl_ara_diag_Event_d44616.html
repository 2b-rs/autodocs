컨텍스트

ara::diag::Event 클래스는 AUTOSAR Adaptive Platform 내의 진단 이벤트에 대한 작업을 캡슐화합니다. 이 클래스는 실제 애플리케이션 소프트웨어(Adaptive Application)와 Diagnostic Management(DM) 기능 그룹 간의 프로그래밍 인터페이스 역할을 합니다. 각 인스턴스는 구체적인 진단 이벤트에 대한 소프트웨어 관점을 나타내며, DiagnosticEventInterface으로 타입 지정되어야 하는 PortPrototype에 ara::core::InstanceSpecifier을 통해 바인딩됩니다[SWS_DM_00647]. 이러한 캡슐화를 통해 클래스는 상태 확인 및 오류 모니터링에 대한 요청을 진단 관리 시스템으로 위임합니다[SWS_DM_00653].

컨텍스트 다이어그램: 애플리케이션, 이벤트 인스턴스, 포트 모델링 및 Diagnostic Management 간의 상호작용. 출처: [SWS_DM_00647], [SWS_DM_00653]

수명주기 및 동시성

이벤트 객체의 생성은 생성자 Event(const ara::core::InstanceSpecifier&)을 통해 명시적으로 이루어집니다[SWS_DM_00647]. 클래스 설계는 엄격한 고유성을 강제합니다: ara::diag::Event는 단일 인스턴스로 모델링되어 복사 생성자 [SWS_DM_01681]과 이동 생성자 [SWS_DM_01682]가 모두 삭제(delete)되어 있습니다. 마찬가지로 대입 연산자 [SWS_DM_01679] 및 이동 대입 연산자 [SWS_DM_01680]도 사후 재배치나 복제를 금지합니다. 따라서 인스턴스는 소멸자 ~Event()을 통해 해제될 때까지 정의된 포트에 고정 바인딩된 상태로 유지됩니다[SWS_DM_00648].

동시성과 관련하여 명확한 요구사항이 정의되어 있습니다:

  • 생성자 [SWS_DM_00647] 및 조회 메서드 GetDTCNumber[SWS_DM_00653]은 thread-safe로 명시되어 있습니다.
  • 소멸자 [SWS_DM_00648]과 모든 상태 조회 및 구성 호출(GetDebouncingStatus [SWS_DM_00654], GetEventStatus [SWS_DM_00649], GetFaultDetectionCounter [SWS_DM_00656], GetTestComplete [SWS_DM_00655] 및 SetEventStatusChangedNotifier [SWS_DM_00650])은 not thread-safe로 분류되며, 여러 스레드에서 호출할 때 외부 동기화가 필요합니다.
  • 모든 메서드는 예외 안전성을 보장하며 noexcept(으)로 선언되어 있습니다.

사용 경로

일반적인 사용 경로는 객체 초기화 후 이벤트 관찰자 등록으로 시작됩니다. SetEventStatusChangedNotifier을 사용하여 진단 이벤트의 상태 변경 시 트리거되는 알림 함수를 전달할 수 있습니다[SWS_DM_00650]. 이때 다시 호출하면 이전에 등록된 Notifier를 덮어씁니다.

실제 상태 모니터링은 ara::core::Future을 통한 비동기 조회를 기반으로 합니다:

  1. 진단 상태 확인: GetEventStatus은 진단 이벤트의 현재 상태 바이트(EventStatusByte)를 반환합니다[SWS_DM_00649].
  2. DTC 할당 읽기: GetDTCNumber을 통해 원하는 DTCFormatType을 지정하여 연관된 32비트 DTC 번호를 조회합니다[SWS_DM_00653].
  3. 디바운싱 및 카운터 값 모니터링: 오류 감지를 추적하기 위해 GetFaultDetectionCounter은 현재 FDC 값을 std::int8_t로 반환하는 데 사용되며[SWS_DM_00656], GetDebouncingStatus은 디바운싱 상태를 확인하는 데 사용됩니다[SWS_DM_00654].
  4. 테스트 완료 검증: GetTestComplete 메서드는 이벤트가 테스트 완료까지 성숙되었는지를 부울 값으로 알립니다(FDC = -128 또는 FDC = 127에 해당)[SWS_DM_00655].

시퀀스 다이어그램: ara::diag::Event를 통한 등록 및 비동기 상태 조회의 일반적인 호출 순서. 출처: [SWS_DM_00647], [SWS_DM_00649], [SWS_DM_00650], [SWS_DM_00653], [SWS_DM_00655], [SWS_DM_00656]

오류 시나리오

ara::diag::Event의 오류 조건은 인스턴스화 시의 정적 모델링 위반(Violations)과 기능적 런타임 오류로 나뉩니다:

잘못된 구성이나 다중 사용 시 생성자는 표준화된 Violations를 발생시킵니다[SWS_DM_00647]:

  • InstanceSpecifierMappingIntegrityViolation: 식별자를 Executable 컨텍스트에서 확인할 수 없거나 PortPrototype을 참조하지 않습니다.
  • PortInterfaceMappingViolation: 지정된 PortPrototype이 DiagnosticEventInterface(으)로 타입 지정되지 않았습니다.
  • ProcessMappingViolation: 일치하는 인스턴스 참조는 존재하지만 현재 런타임 프로세스에 해당하는 모델링된 프로세스가 누락되었습니다.
  • InstanceSpecifierAlreadyInUseViolation: 지정된 InstanceSpecifier이 프로세스 내에서 이미 기존 인스턴스에 의해 점유되어 있습니다.

런타임에 메서드는 ara::core::Result 또는 ara::core::Future을 통해 오류 코드를 보고합니다:

  • DiagErrc::kServiceNotAvailable: 기본 DM 기능에 일시적으로 접근할 수 없습니다. GetDTCNumber [SWS_DM_00653], GetDebouncingStatus [SWS_DM_00654], GetEventStatus [SWS_DM_00649], GetFaultDetectionCounter [SWS_DM_00656] 및 GetTestComplete [SWS_DM_00655]에 적용됩니다.
  • DiagErrc::kNoSuchDTC: 요청된 이벤트에 대해 시스템에 등록된 연관 DTC가 없는 경우 GetDTCNumber에서 발생합니다[SWS_DM_00653].
  • DiagErrc::kInvalidArgument: 유효하지 않은 매개변수가 전달될 때 SetEventStatusChangedNotifier에서 보고됩니다(예: 내부 디바운싱 시 kPreFailed와 같은 허용되지 않는 사전 필터링의 경우)[SWS_DM_00650].

이 클래스 가이드는 AUTOSAR Adaptive R25-11용으로 생성되었습니다. 모든 내용은 페이로드에 포함된 사양 요구사항을 기반으로 합니다.

<h4>수명주기 및 동시성</h4>
<p>이벤트 객체의 생성은 생성자 <code>Event(const ara::core::InstanceSpecifier&amp;)</code>을 통해 명시적으로 이루어집니다<a class="spec-record-ref" data-req="SWS_DM_00647" href="../spec/record.html?id=SWS_DM_00647">[SWS_DM_00647]</a>. 클래스 설계는 엄격한 고유성을 강제합니다: <code>ara::diag::Event</code>는 단일 인스턴스로 모델링되어 복사 생성자 <a class="spec-record-ref" data-req="SWS_DM_01681" href="../spec/record.html?id=SWS_DM_01681">[SWS_DM_01681]</a>과 이동 생성자 <a class="spec-record-ref" data-req="SWS_DM_01682" href="../spec/record.html?id=SWS_DM_01682">[SWS_DM_01682]</a>가 모두 삭제(<code>delete</code>)되어 있습니다. 마찬가지로 대입 연산자 <a class="spec-record-ref" data-req="SWS_DM_01679" href="../spec/record.html?id=SWS_DM_01679">[SWS_DM_01679]</a> 및 이동 대입 연산자 <a class="spec-record-ref" data-req="SWS_DM_01680" href="../spec/record.html?id=SWS_DM_01680">[SWS_DM_01680]</a>도 사후 재배치나 복제를 금지합니다. 따라서 인스턴스는 소멸자 <code>~Event()</code>을 통해 해제될 때까지 정의된 포트에 고정 바인딩된 상태로 유지됩니다<a class="spec-record-ref" data-req="SWS_DM_00648" href="../spec/record.html?id=SWS_DM_00648">[SWS_DM_00648]</a>.</p>

<p>동시성과 관련하여 명확한 요구사항이 정의되어 있습니다:</p>
<ul>
<li>생성자 <a class="spec-record-ref" data-req="SWS_DM_00647" href="../spec/record.html?id=SWS_DM_00647">[SWS_DM_00647]</a> 및 조회 메서드 <code>GetDTCNumber</code><a class="spec-record-ref" data-req="SWS_DM_00653" href="../spec/record.html?id=SWS_DM_00653">[SWS_DM_00653]</a>은 thread-safe로 명시되어 있습니다.</li>
<li>소멸자 <a class="spec-record-ref" data-req="SWS_DM_00648" href="../spec/record.html?id=SWS_DM_00648">[SWS_DM_00648]</a>과 모든 상태 조회 및 구성 호출(<code>GetDebouncingStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00654" href="../spec/record.html?id=SWS_DM_00654">[SWS_DM_00654]</a>, <code>GetEventStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00649" href="../spec/record.html?id=SWS_DM_00649">[SWS_DM_00649]</a>, <code>GetFaultDetectionCounter</code> <a class="spec-record-ref" data-req="SWS_DM_00656" href="../spec/record.html?id=SWS_DM_00656">[SWS_DM_00656]</a>, <code>GetTestComplete</code> <a class="spec-record-ref" data-req="SWS_DM_00655" href="../spec/record.html?id=SWS_DM_00655">[SWS_DM_00655]</a> 및 <code>SetEventStatusChangedNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_00650" href="../spec/record.html?id=SWS_DM_00650">[SWS_DM_00650]</a>)은 not thread-safe로 분류되며, 여러 스레드에서 호출할 때 외부 동기화가 필요합니다.</li>
<li>모든 메서드는 예외 안전성을 보장하며 <code>noexcept</code>(으)로 선언되어 있습니다.</li>
</ul>

<h4>사용 경로</h4>
<p>일반적인 사용 경로는 객체 초기화 후 이벤트 관찰자 등록으로 시작됩니다. <code>SetEventStatusChangedNotifier</code>을 사용하여 진단 이벤트의 상태 변경 시 트리거되는 알림 함수를 전달할 수 있습니다<a class="spec-record-ref" data-req="SWS_DM_00650" href="../spec/record.html?id=SWS_DM_00650">[SWS_DM_00650]</a>. 이때 다시 호출하면 이전에 등록된 Notifier를 덮어씁니다.</p>
<p>실제 상태 모니터링은 <code>ara::core::Future</code>을 통한 비동기 조회를 기반으로 합니다:</p>
<ol>
<li><strong>진단 상태 확인:</strong> <code>GetEventStatus</code>은 진단 이벤트의 현재 상태 바이트(<code>EventStatusByte</code>)를 반환합니다<a class="spec-record-ref" data-req="SWS_DM_00649" href="../spec/record.html?id=SWS_DM_00649">[SWS_DM_00649]</a>.</li>
<li><strong>DTC 할당 읽기:</strong> <code>GetDTCNumber</code>을 통해 원하는 <code>DTCFormatType</code>을 지정하여 연관된 32비트 DTC 번호를 조회합니다<a class="spec-record-ref" data-req="SWS_DM_00653" href="../spec/record.html?id=SWS_DM_00653">[SWS_DM_00653]</a>.</li>
<li><strong>디바운싱 및 카운터 값 모니터링:</strong> 오류 감지를 추적하기 위해 <code>GetFaultDetectionCounter</code>은 현재 FDC 값을 <code>std::int8_t</code>로 반환하는 데 사용되며<a class="spec-record-ref" data-req="SWS_DM_00656" href="../spec/record.html?id=SWS_DM_00656">[SWS_DM_00656]</a>, <code>GetDebouncingStatus</code>은 디바운싱 상태를 확인하는 데 사용됩니다<a class="spec-record-ref" data-req="SWS_DM_00654" href="../spec/record.html?id=SWS_DM_00654">[SWS_DM_00654]</a>.</li>
<li><strong>테스트 완료 검증:</strong> <code>GetTestComplete</code> 메서드는 이벤트가 테스트 완료까지 성숙되었는지를 부울 값으로 알립니다(FDC = -128 또는 FDC = 127에 해당)<a class="spec-record-ref" data-req="SWS_DM_00655" href="../spec/record.html?id=SWS_DM_00655">[SWS_DM_00655]</a>.</li>
</ol>

<h4>오류 시나리오</h4>
<p><code>ara::diag::Event</code>의 오류 조건은 인스턴스화 시의 정적 모델링 위반(Violations)과 기능적 런타임 오류로 나뉩니다:</p>
<p>잘못된 구성이나 다중 사용 시 생성자는 표준화된 Violations를 발생시킵니다<a class="spec-record-ref" data-req="SWS_DM_00647" href="../spec/record.html?id=SWS_DM_00647">[SWS_DM_00647]</a>:</p>
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>: 식별자를 Executable 컨텍스트에서 확인할 수 없거나 <code>PortPrototype</code>을 참조하지 않습니다.</li>
<li><code>PortInterfaceMappingViolation</code>: 지정된 <code>PortPrototype</code>이 <code>DiagnosticEventInterface</code>(으)로 타입 지정되지 않았습니다.</li>
<li><code>ProcessMappingViolation</code>: 일치하는 인스턴스 참조는 존재하지만 현재 런타임 프로세스에 해당하는 모델링된 프로세스가 누락되었습니다.</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>: 지정된 <code>InstanceSpecifier</code>이 프로세스 내에서 이미 기존 인스턴스에 의해 점유되어 있습니다.</li>
</ul>

<ul>
