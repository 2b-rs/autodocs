SOVD 진단 데이터 객체의 배열 요소에 대한 스레드 안전한 읽기 전용 액세스를 지원합니다.

ara::diag::DiagnosticSovdArrayContentElementDataConstView 클래스는 효율적인 진단 쿼리를 위해 배열 타입의 DiagnosticSovdContentElementData에 대한 읽기 전용 뷰를 제공합니다 [SWS_DM_02248]. 애플리케이션은 먼저 HasError()을(를) 사용하여 무결성 상태를 확인한 다음, operator[]을(를) 통해 임의로 또는 CBegin() 및 CEnd()을(를) 통해 반복적으로 배열 요소에 액세스합니다 [SWS_DM_02253]. 모든 작업은 스레드 안전하고 예외에 안전하게(noexcept) 실행되지만, 참조된 기본 요소의 지속적인 유효성을 전제로 합니다.

컨텍스트

ara::diag::DiagnosticSovdArrayContentElementDataConstView 클래스는 SOVD(Service-Oriented Vehicle Diagnostics)를 위한 Adaptive AUTOSAR 진단 아키텍처 내에서 배열 타입의 진단 데이터 요소에 대한 읽기 전용 뷰(const view)를 제공합니다 [SWS_DM_02248] (AUTOSAR_AP_SWS_Diagnostics §8.60.3 “Class: DiagnosticSovdArrayContentElementDataConstView”). 기본 데이터 버퍼를 복사할 필요 없이 진단 콘텐츠의 순차적 요소에 대한 제어된 읽기 액세스를 가능하게 합니다.

클래스의 기본 상호작용 대상은 다음과 같습니다:

  • 배열 데이터를 평가하는 호출 진단 애플리케이션,
  • 구체적인 배열 요소를 저장하고 [SWS_DM_02253]을(를) 통한 임의 액세스 시 참조되는, 참조된 DiagnosticSovdContentElementData,
  • 배열 요소에 대한 표준 준수 반복을 위해 생성되는 보조 타입 DiagnosticSovdArrayContentElementDataConstIterator [SWS_DM_02254].

컨텍스트 다이어그램: 진단 애플리케이션, 기본 요소 및 반복자 사이의 뷰 임베딩. 출처: [SWS_DM_02248], [SWS_DM_02253], [SWS_DM_02254].

수명 주기

이 클래스는 헤더 #include "ara/diag/diagnostic_sovd_content_element_data.h"을(를) 통해 사용할 수 있습니다 [SWS_DM_02248]. 순수 뷰 클래스로서 실제 배열 데이터에 대한 소유권을 갖지 않습니다. 해석: 뷰 인스턴스의 수명은 기본이 되는 DiagnosticSovdContentElementData의 유효성에 바인딩되며, 데이터 객체는 뷰를 사용하는 동안 메모리에 유지되어야 합니다. 질문 Q-1a3079bdd09b4ddd (열림)

동시성과 관련하여, 클래스의 모든 멤버 함수는 명시적으로 스레드 안전한 것으로 선언되어 있습니다 [SWS_DM_02250], [SWS_DM_02253]. 따라서 여러 스레드가 동일한 뷰 인스턴스에 동시에 읽기 액세스할 수 있습니다(해석: 기본 데이터 객체가 쓰기 작업에 의해 동시에 수정되지 않는 한). 질문 Q-61e5fa3990052e70 (열림) 또한 모든 메서드는 완전한 예외 안전성(exception safe)을 보장하며 예외 없이 noexcept(으)로 명시되어 있습니다 [SWS_DM_02249], [SWS_DM_02251]. 불변 뷰이므로 클래스는 내부 상태 전이나 복잡한 수명 주기 단계를 갖지 않습니다.

사용 경로

배열 데이터를 사용하기 위한 정규 흐름은 무결성 검사, 차원 쿼리 및 데이터 추출로 나뉩니다:

  1. 무결성 검사: 액세스하기 전에 애플리케이션은 HasError()을(를) 통해 콘텐츠 요소가 오류 없이 존재하는지 확인해야 합니다 [SWS_DM_02249].
  2. 차원 쿼리: Empty()을(를) 통해 배열에 요소가 포함되어 있는지 확인할 수 있습니다 ([SWS_DM_02252], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.5 “Empty”). 현재 요소 수는 Size()이(가) 제공하며 [SWS_DM_02250], Capacity()은(는) 배열의 예약된 용량을 반환합니다 ([SWS_DM_02251], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.4 “Capacity”).
  3. 데이터 액세스: 배열 요소에 액세스하기 위해 두 가지 방법이 제공됩니다:
    • 인덱스를 통한 임의 액세스: operator[](std::size_t index)을(를) 통해 대상 요소에 대한 참조가 요청되며, 이는 ara::core::Result<std::reference_wrapper<DiagnosticSovdContentElementData const>>에 캡슐화됩니다 [SWS_DM_02253].
    • 순차적 반복: 선형 순회를 위해 Begin() ([SWS_DM_02254], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.1 “Begin”) 및 End() [SWS_DM_02255], 그리고 이들의 명시적 상수 변형인 CBegin() ([SWS_DM_02256], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.2 “CBegin”) 및 CEnd() ([SWS_DM_02257], AUTOSAR_AP_SWS_Diagnostics §8.60.3.1.1.3 “CEnd”)이(가) 각각 DiagnosticSovdArrayContentElementDataConstIterator을(를) 제공합니다.

시퀀스 다이어그램: 오류 검사, 크기 결정 및 요소 쿼리를 위한 일반적인 순서. 출처: [SWS_DM_02249], [SWS_DM_02250], [SWS_DM_02253], [SWS_DM_02256], [SWS_DM_02257].

오류 시나리오

이 클래스는 C++ 예외를 사용하지 않으며 ara::core::Result을(를) 통해 기능 오류를 보고합니다:

  • 잘못된 데이터 콘텐츠: 콘텐츠 요소에 잘못된 데이터가 포함된 경우, HasError()은(는) 빈 성공 결과를 반환하지 않고 ara::diag::DiagSovdErrc 타입의 오류 코드를 반환합니다 [SWS_DM_02249].
  • 인덱스 액세스 시 타입 충돌: operator[]은(는) 참조된 요소가 실제로 ArrayContentElementData 타입일 것을 필수로 요구합니다 [SWS_DM_02253]. 그렇지 않은 경우 호출이 실패하고 참조 대신 Result에 해당 오류 객체를 반환합니다.
  • 인덱스 경계: operator[]은(는) 유효한 범위 내에서만 호출되어야 하므로, 호출자는 사전에 Size() [SWS_DM_02250] 또는 Empty() [SWS_DM_02252]을(를) 통해 요청된 인덱스가 존재하는지 확인해야 합니다.

이 가이드는 AUTOSAR Adaptive R25-11 사양을 기반으로 합니다.
