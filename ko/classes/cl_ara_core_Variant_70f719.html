컨텍스트

템플릿 클래스 ara::core::Variant은(는) AUTOSAR Adaptive Platform의 core 모듈에서 타입 안전한 유니온(합 타입)을 제공합니다. 이 구현은 개념적으로 C++ 표준의 std::variant 타입을 기반으로 하지만, 예외 처리 및 noexcept에 대한 조건과 관련하여 플랫폼에 특화된 차이점과 세부 사항을 정의합니다. ara::core::Variant은(는) 언제든지 선언된 타입 목록 Types...에서 정확히 하나의 값을 관리하거나 오류로 인해 값이 없는 상태에 있습니다.

일반적인 상호작용 대상은 동적 메모리 할당이나 상속 계층 구조 없이 다형성 데이터 구조를 타입 안전하게 전달하는 기능적 Adaptive 애플리케이션 및 서비스 인터페이스입니다. 포함은 [SWS_CORE_01649]과(와) 같은 관련 사양 요구사항에 명시된 대로 헤더 파일 ara/core/variant.h을(를) 통해 이루어집니다.

수명 주기

ara::core::Variant 인스턴스의 수명 주기는 생성, 값 변환, 오류 상태 및 파괴 단계로 구분됩니다:

  • 기본 생성: 매개변수가 없는 기본 생성자 [SWS_CORE_01649]은(는) 첫 번째 대안(인덱스 0)이 기본 생성 가능한 경우 이를 사용하여 인스턴스를 초기화합니다. 실행은 constexpr이며 조건부 noexcept입니다.
  • 값 및 이동 생성: 인스턴스는 값 전달 [SWS_CORE_01652], 복사 생성자 [SWS_CORE_01650] 또는 이동 생성자 [SWS_CORE_01651]를 통해 인스턴스화될 수 있습니다. 세 작업 모두 특정 noexcept 조건의 적용을 받습니다.
  • 인플레이스 생성: 임시 복사를 방지하기 위해 플레이스홀더 태그가 있는 생성자가 제공됩니다. in_place_type_t([SWS_CORE_01653], [SWS_CORE_01654])을 통한 타입 기반 또는 in_place_index_t([SWS_CORE_01655], [SWS_CORE_01656])을 통한 인덱스 기반입니다. 이러한 생성자는 explicit 및 constexpr로 선언되어 있습니다.
  • 값 변경 및 상태 전이: 사용 단계 동안 포함된 값은 대입 연산자([SWS_CORE_01658], [SWS_CORE_01659], [SWS_CORE_01660]), 타입 기반 emplace 메서드([SWS_CORE_01661], [SWS_CORE_01662]), 인덱스 기반 emplace 메서드([SWS_CORE_01663], [SWS_CORE_01664]) 또는 swap [SWS_CORE_01667]을 통해 교체될 수 있습니다.
  • 소멸: 소멸자 [SWS_CORE_01657]은 현재 활성 상태인 대안을 소멸시킵니다. 이는 조건부 noexcept로 선언되어 있습니다.

상태 다이어그램: 유효 상태, 오류 상태 및 소멸 간의 Variant 인스턴스 상태 및 전이. 출처: [SWS_CORE_01649], [SWS_CORE_01657], [SWS_CORE_01661], [SWS_CORE_01666].

사용 경로

일반적인 사용 경로는 인플레이스 초기화, 활성 타입 조회 및 유지되는 대안의 전환을 포함합니다:

  1. 초기화: 대상 타입의 생성자에 인수를 직접 전달하기 위해 객체는 예를 들어 [SWS_CORE_01653]에 따른 in_place_type_t을 통해 특정 대안으로 명시적으로 초기화됩니다.
  2. 상태 확인: 접근하기 전에 애플리케이션은 index() [SWS_CORE_01665] 메서드를 통해 현재 유지되는 대안의 0 기반 인덱스를 확인합니다. 아울러 valueless_by_exception() [SWS_CORE_01666]을 사용하여 인스턴스가 온전한 상태인지 검증할 수 있습니다.
  3. 재할당: 동일한 메모리 영역에 대안 타입을 배치해야 하는 경우 emplace([SWS_CORE_01661] 또는 [SWS_CORE_01663])을 호출합니다. 이는 이전 대안을 소멸시키고 새로운 값을 해당 위치에 직접 생성합니다.
  4. 소멸: 유효 범위를 벗어날 때 소멸자 [SWS_CORE_01657]이 호출되어 활성 대안을 정상적으로 정리합니다.

시퀀스 다이어그램: ara::core::Variant에서 초기화, 상태 조회 및 타입 전환의 일반적인 순서. 출처: [SWS_CORE_01653], [SWS_CORE_01661], [SWS_CORE_01665], [SWS_CORE_01666].

오류 시나리오

오류 시나리오 및 예외 처리 영역에서 ara::core::Variant은 다음과 같은 특징을 갖습니다:

  • valueless_by_exception 상태: 값 대입([SWS_CORE_01658], [SWS_CORE_01659], [SWS_CORE_01660]) 또는 emplace([SWS_CORE_01661], [SWS_CORE_01663])을 통한 재초기화 도중 새 대안의 생성자가 예외를 발생시키고 이전 대안이 이미 소멸된 경우, 객체는 값 없는 상태로 남습니다. 이 상태는 valueless_by_exception() [SWS_CORE_01666]을 통해 조회됩니다. 이 상태에서 index()은 variant_npos 값을 반환합니다. 복구는 성공적인 재대입 또는 emplace을 통해서만 가능합니다.
  • 조건부 noexcept 보장: 거의 모든 생성 및 수정 메서드(예: [SWS_CORE_01650], [SWS_CORE_01653], [SWS_CORE_01661])는 conditionally exception safe 상태를 가지며, 조건부 noexcept 절이 적용되어 있습니다(예를 들어 std::is_nothrow_constructible 기반). 이러한 메서드는 관련된 사용자 타입의 작업 자체가 noexcept인 경우에만 예외가 발생하지 않음을 보장합니다.
  • 무조건적 보장: 조회 메서드 index() [SWS_CORE_01665] 및 valueless_by_exception() [SWS_CORE_01666]은 무조건적으로 noexcept로 선언되어 있으며 완전한 예외 안전성(exception safe)을 제공합니다.
  • Swap 수정: AUTOSAR 환경에서 제어된 처리를 보장하기 위해 swap [SWS_CORE_01667]의 경우 표준과 비교하여 예외 안전성 조건이 수정되었습니다.

<h4>컨텍스트</h4>
<p>템플릿 클래스 <code>ara::core::Variant</code>은(는) AUTOSAR Adaptive Platform의 <code>core</code> 모듈에서 타입 안전한 유니온(합 타입)을 제공합니다. 이 구현은 개념적으로 C++ 표준의 <code>std::variant</code> 타입을 기반으로 하지만, 예외 처리 및 <code>noexcept</code>에 대한 조건과 관련하여 플랫폼에 특화된 차이점과 세부 사항을 정의합니다. <code>ara::core::Variant</code>은(는) 언제든지 선언된 타입 목록 <code>Types...</code>에서 정확히 하나의 값을 관리하거나 오류로 인해 값이 없는 상태에 있습니다.</p>

<h4>사용 경로</h4>
<p>일반적인 사용 경로는 인플레이스 초기화, 활성 타입 조회 및 유지되는 대안의 전환을 포함합니다:</p>
<ol>
<li><strong>초기화:</strong> 대상 타입의 생성자에 인수를 직접 전달하기 위해 객체는 예를 들어 <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>에 따른 <code>in_place_type_t</code>을 통해 특정 대안으로 명시적으로 초기화됩니다.</li>
<li><strong>상태 확인:</strong> 접근하기 전에 애플리케이션은 <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a> 메서드를 통해 현재 유지되는 대안의 0 기반 인덱스를 확인합니다. 아울러 <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>을 사용하여 인스턴스가 온전한 상태인지 검증할 수 있습니다.</li>
<li><strong>재할당:</strong> 동일한 메모리 영역에 대안 타입을 배치해야 하는 경우 <code>emplace</code>(<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a> 또는 <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>)을 호출합니다. 이는 이전 대안을 소멸시키고 새로운 값을 해당 위치에 직접 생성합니다.</li>
<li><strong>소멸:</strong> 유효 범위를 벗어날 때 소멸자 <a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a>이 호출되어 활성 대안을 정상적으로 정리합니다.</li>
</ol>

<h4>오류 시나리오</h4>
<p>오류 시나리오 및 예외 처리 영역에서 <code>ara::core::Variant</code>은 다음과 같은 특징을 갖습니다:</p>
<ul>
<li><strong>valueless_by_exception 상태:</strong> 값 대입(<a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01659" href="../spec/record.html?id=SWS_CORE_01659">[SWS_CORE_01659]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01660" href="../spec/record.html?id=SWS_CORE_01660">[SWS_CORE_01660]</a>) 또는 <code>emplace</code>(<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>)을 통한 재초기화 도중 새 대안의 생성자가 예외를 발생시키고 이전 대안이 이미 소멸된 경우, 객체는 값 없는 상태로 남습니다. 이 상태는 <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>을 통해 조회됩니다. 이 상태에서 <code>index()</code>은 <code>variant_npos</code> 값을 반환합니다. 복구는 성공적인 재대입 또는 <code>emplace</code>을 통해서만 가능합니다.</li>
<li><strong>조건부 noexcept 보장:</strong> 거의 모든 생성 및 수정 메서드(예: <a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>, <a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>)는 <em>conditionally exception safe</em> 상태를 가지며, 조건부 <code>noexcept</code> 절이 적용되어 있습니다(예를 들어 <code>std::is_nothrow_constructible</code> 기반). 이러한 메서드는 관련된 사용자 타입의 작업 자체가 <code>noexcept</code>인 경우에만 예외가 발생하지 않음을 보장합니다.</li>
<li><strong>무조건적 보장:</strong> 조회 메서드 <code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a> 및 <code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>은 무조건적으로 <code>noexcept</code>로 선언되어 있으며 완전한 예외 안전성(<em>exception safe</em>)을 제공합니다.</li>
<li><strong>Swap 수정:</strong> AUTOSAR 환경에서 제어된 처리를 보장하기 위해 <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a>의 경우 표준과 비교하여 예외 안전성 조건이 수정되었습니다.</li>
</ul>
