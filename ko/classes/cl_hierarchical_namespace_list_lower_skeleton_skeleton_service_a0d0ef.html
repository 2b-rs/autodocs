서비스 인터페이스 메서드의 서버 측 구현 및 제공을 위한 기본 클래스 역할을 합니다.

이 클래스는 서비스 제공자 애플리케이션이 상속하는 ara::com의 서비스 인터페이스 구현을 위한 서버 측 기본 클래스 역할을 합니다. 생성 시 들어오는 메서드 호출을 이벤트 기반으로 처리할지 아니면 폴링을 통해 처리할지가 생성자를 통해 결정됩니다 [SWS_CM_00130]. 예외 안전으로 선언된 메서드에서 오류가 있는 프로세스는 반환되는 ara::core::Future를 통해 오류 코드로 신호됩니다 [SWS_CM_00191].

컨텍스트

클래스 {<hierarchical-namespace-list-lower-skeleton>}::skeleton::{ <service-interface-name>}Skeleton은 Adaptive Platform의 모듈 com에서 서비스 인터페이스의 서버 측 제공을 위해 생성된 추상 기본 클래스 역할을 합니다. 애플리케이션별 서비스 제공자 컴포넌트는 서비스의 기능적 비즈니스 로직을 구현하기 위해 이 Skeleton 클래스에서 상속받습니다. 이 클래스는 구체적인 서비스 제공자 애플리케이션과 통신 미들웨어 또는 SOME/IP(SWS CommunicationManagement §8.1 “Method invocation”)와 같은 기본 프로토콜 바인딩 사이를 중재합니다. 상호작용 대상에는 인스턴스를 생성하고 소유하는 서비스 제공자 애플리케이션, Skeleton 클래스 자체, 수신 서비스 요청을 수신, 역직렬화하여 Skeleton으로 전달하는 통신 인프라가 포함됩니다([SWS_CM_10306], [SWS_CM_10307]).

컨텍스트 다이어그램: 서비스 제공자 애플리케이션, ServiceSkeleton 및 통신 미들웨어의 상호작용. 출처: [SWS_CM_10306], [SWS_CM_10307], SWS CommunicationManagement §8.1 “Method invocation”.

수명 주기

Skeleton 인스턴스의 생성은 원하는 처리 모드 ara::com::MethodCallProcessingMode이 전달되는 생성자를 통해 이루어집니다 [SWS_CM_00130]. 이 모드는 들어오는 메서드 호출에 대한 동시성 전략을 설정합니다. kEvent 또는 kEventSingleThread이 구성되면 들어오는 메서드 호출이 통신 미들웨어에 의해 이벤트 기반으로 즉시 호출됩니다 [SWS_CM_10306]. 대신 kPoll가 전달되면 애플리케이션에 의해 폴링 기반으로 처리가 수행됩니다 [SWS_CM_10307]. 해석: Skeleton 인스턴스는 활성 서비스가 제공되는 전체 기간 동안 서비스 제공자 애플리케이션의 소유로 유지되며 서비스가 종료될 때 비로소 소멸하는 것으로 추정됩니다.

사용 경로

전형적인 흐름에는 파생된 제공자 클래스에 의한 순수 가상 메서드의 구현과 이후 요청 수신 시의 실행이 포함됩니다. 일반 메서드 호출(Request-Response)의 경우 Skeleton은 해당 출력 객체가 포함된 ara::core::Future을 반환하는 인터페이스를 정의합니다 [SWS_CM_00191], [SWS_CM_99556]. 응답이 없는 Fire-and-Forget 메서드의 경우 Skeleton은 반환 타입 void을 갖는 순수 가상 작업을 제공합니다 [SWS_CM_90434]. 수신 요청이 있을 때 통신 미들웨어는 페이로드를 역직렬화하고 구성된 처리 모드에 따라 Skeleton 클래스의 구체적인 구현으로 호출을 전달합니다([SWS_CM_10306], [SWS_CM_00191]).

시퀀스 다이어그램: Skeleton을 통한 메서드 호출 흐름. 출처: [SWS_CM_00191], [SWS_CM_10306], SWS CommunicationManagement §8.1 “Method invocation”.

오류 시나리오

Request-Response 메서드와 Fire-and-Forget 메서드 모두 인터페이스 수준에서 noexcept으로 주석 처리되어 있으며 예외 안전으로 선언되어 있습니다([SWS_CM_00191], [SWS_CM_90434]). 일반 메서드 호출 처리 시의 오류는 C++ 예외를 통해 전달되지 않으며, 대신 반환된 ara::core::Future이 오류 발생 시 ara::com::ComErrc 타입의 해당 오류 코드 또는 ApApplicationError를 전달합니다 [SWS_CM_00191]. Fire-and-Forget 메서드의 경우 명세에 따라 반환값이나 표준화된 오류 코드가 제공되지 않습니다 [SWS_CM_90434].

API 함수 [SWS_CM_90434]은(는) 서버 측에서 Fire-and-Forget 메서드의 순수 가상 인터페이스를 정의합니다. 이는 생성된 Skeleton 클래스 {<hierarchical-namespace-list-lower-skeleton>}::skeleton::{<service-interface-name>}Skeleton의 구성 요소이며 헤더 파일 {<si-namespace-derived-directory-path-lower>}/{<si-shortname-lower>}_skeleton.h을(를) 통해 제공됩니다 (AUTOSAR_AP_SWS_CommunicationManagement §8.4.5.2.4.1 “{<fnfmethod-name>}”). 이 함수는 설계 모델에서 ClientServerOperation에 대해 속성 ClientServerOperation.fireAndForget == TRUE이(가) 구성되면 생성됩니다.

구현 및 런타임 동작에는 다음과 같은 주요 측면이 적용됩니다:

  • 호출 시맨틱 및 매개변수: 이 메서드는 [SWS_CM_00191]에 따른 일반 메서드와 유사하게 입력 매개변수를 받습니다. 순수 단방향 통신이므로 시그니처는 void 반환 타입을 갖습니다. 호출한 클라이언트에는 출력 매개변수나 반환값이 전달되지 않습니다.
  • 오류 처리 및 예외 안전성: 이 작업은 noexcept=0(으)로 선언되어 엄격하게 예외 안전(exception safe)으로 명시되어 있습니다 ([SWS_CM_90434]). 애플리케이션별 오류 코드나 기타 피드백 채널이 존재하지 않으며, 서비스 구현은 메서드 외부로 C++ 예외가 전파되도록 해서는 안 됩니다.
  • 실행 컨텍스트 및 동시성: Skeleton이 ara::com::MethodCallProcessingMode == kPoll 모드로 작동하는 경우, 대기 중인 [SWS_CM_90434] 호출 처리는 ProcessNextMethodCall() 호출의 스레드 컨텍스트에서 결정론적으로 발생합니다 (AUTOSAR_AP_SWS_CommunicationManagement 410쪽). 폴링 모드 외부에서는 실행이 통신 미들웨어의 내부 워커 스레드에서 동시에 발생할 것으로 보입니다.

이 사용 지침은 AUTOSAR R25-11 사양을 기반으로 자동 생성되었습니다.

순수 가상 함수 <Method>은(는) Fire-and-Forget 시맨틱이 없는 클라이언트-서버 작업을 위해 Skeleton 클래스 내에서 메서드의 공급자 측 제공에 사용됩니다([SWS_CM_00191]). 애플리케이션 개발자는 수신 호출을 수신하기 위해 서비스 인터페이스에서 파생된 스켈레톤 클래스에서 이 인터페이스를 구현합니다. 입력 매개변수로는 방향이 in 또는 inout(으)로 정의된 모델링된 모든 인수가 전달됩니다([SWS_CM_00191]).

      

      
실행은 반환 타입 ara::core::Future을(를) 통해 비동기적으로 수행되며, 성공 시 결과 값을 가진 타입화된 Output 객체를 포함합니다([SWS_CM_00191], [SWS_CM_99556]). 이 메서드는 noexcept 및 예외 안전으로 명세되어 있으며, 표준화된 동기식 오류 코드는 지정되어 있지 않습니다([SWS_CM_00191]). 처리 중 오류가 발생하면 구현체는 ara::core::Future을(를) 통해 비동기적으로 이를 제공하며, ara::com::ComErrc 타입의 오류 코드 또는 모델별 ApApplicationError(으)로 제공합니다([SWS_CM_00191]).

      

      
호출 컨텍스트와 동시성 동작은 인스턴스화 시 ServiceSkeleton의 생성자에 전달되는 처리 모드 ara::com::MethodCallProcessingMode에 따라 달라집니다([SWS_CM_00130]).

      

        

      • kEvent 또는 kEventSingleThread이(가) 구성된 경우, 해당 SOME/IP 요청 메시지가 수신 및 역직렬화되는 즉시 미들웨어에 의해 메서드가 이벤트 기반으로 호출됩니다([SWS_CM_10306]).
        • 

      • 반면 kPoll 모드에서는 서비스 애플리케이션이 스켈레톤 인스턴스에서 명시적으로 ProcessNextMethodCall()을(를) 실행할 때 해당 서비스 애플리케이션의 스레드에서 동기화되어 호출이 수행됩니다([SWS_CM_10307], [SWS_CM_00199]).
