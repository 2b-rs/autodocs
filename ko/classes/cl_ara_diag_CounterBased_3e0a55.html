컨텍스트

C++ 구조체 ara::diag::CounterBased은(는) AUTOSAR Adaptive Platform [SWS_DM_00538] 내에서 카운터 기반 이벤트 디바운싱(counter-based debouncing)을 위한 구성 매개변수를 나타낸다. 이는 진단 모니터를 위한 카운터 임계값, 스텝 크기 및 점프 값을 정의하는 데이터 구조 역할을 한다 AUTOSAR_AP_SWS_Diagnostics §8.41.2 “Struct: CounterBased”.

카운터 기반 디바운싱에는 여러 컴포넌트가 상호작용한다:

  • Diagnostic Monitor (애플리케이션): 애플리케이션별 모니터링 기능은 로컬 오류 상태를 확인하고 모니터 작업(예: kPrefailed 또는 kPrepassed)을 통해 이를 진단 관리에 주기적으로 보고한다 AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.1 “Counter-based debouncing”.
  • ara::diag::Monitor: 진단 인프라에 대한 인터페이스를 형성하며, 인스턴스화 시 ara::diag::CounterBased 형태의 디바운스 파라미터를 전달받는다 [SWS_DM_00549].
  • Diagnostic Management (DM): 이벤트별 내부 디바운스 카운터를 관리하고, 스텝 크기 [SWS_DM_00875], [SWS_DM_00876]에 따라 이를 증가 또는 감소시키며, 최종적으로 이벤트를 결함(kFinallyDefective)으로 한정한다 [SWS_DM_00024].
  • Diagnostic Extract (DEXT): 모델링된 디바운스 파라미터를 포함한다. DEXT에 해당 이벤트에 대한 디바운스 파라미터가 존재하는 경우, 이는 C++ 생성자에서 전달된 값보다 우선권을 갖는다 [SWS_DM_01099].

컨텍스트 다이어그램: Diagnostic Monitor, ara::diag::CounterBased, ara::diag::Monitor 및 Diagnostic Management (DM)의 상호작용. 출처: [SWS_DM_00538], [SWS_DM_00549], [SWS_DM_01099], [SWS_DM_01101].

수명 주기

ara::diag::CounterBased은(는) 자체 멤버 함수가 없는 순수 데이터 컨테이너(Value Object)로 선언되어 있다 [SWS_DM_00538]. 이 구조체의 수명 주기는 다음과 같은 단계로 나뉜다:

  • Instanziierung und Belegung: 애플리케이션은 ara::diag::CounterBased의 인스턴스를 생성하고(일반적으로 스택에 로컬로 또는 정적 구성 구조체로), 카운터 임계값(failedThreshold [SWS_DM_00621], passedThreshold [SWS_DM_00622]), 스텝 크기(failedStepsize [SWS_DM_00623], passedStepsize [SWS_DM_00624]) 및 점프 속성(failedJumpValue [SWS_DM_00625], passedJumpValue [SWS_DM_00626], useJumpToFailed [SWS_DM_00627] 및 useJumpToPassed [SWS_DM_00628])을 초기화한다.
  • 모니터로 전달: 채워진 구조체는 AUTOSAR_AP_SWS_Diagnostics §8.40.1.1.2.2 “Monitor”에서 ara::diag::Monitor의 생성자에 인수로 전달됩니다 [SWS_DM_00549].
  • Besitz und Weitergabe: 해석: 동적 메모리 관리가 없는 기본 C++ 구조체이므로, 생성자 호출 시 값이 복사된다. 원래 인스턴스는 모니터의 소유로 남지 않으며 생성자 호출이 반환된 후 안전하게 폐기할 수 있다.
  • Gültigkeitsdauer: DEXT에 해당 디바운스 파라미터가 없는 경우, Diagnostic Management는 내부 디바운스 알고리즘을 위해 전달된 값을 적용한다 [SWS_DM_01101]. 이 값들은 해당 모니터의 전체 수명 동안 활성 상태를 유지한다.
  • Nebenläufigkeit: 구조체 자체는 스레드 동기화를 제공하지 않는다. 그러나 전달 전에 완전히 초기화되고 그 후에는 값으로만 전달되므로, 생성자 호출 전에 동시 쓰기 접근이 발생하지 않는 한 생성 및 전달은 동시성 측면에서 안전하다.

사용 경로

ara::diag::CounterBased 사용을 위한 일반적인 절차는 파라미터화, 등록 및 이후 런타임 이벤트 처리를 포함한다:

  1. Konfiguration der Entprellparameter: 애플리케이션은 ara::diag::CounterBased의 멤버를 설정한다. 예를 들어 failedStepsize은(는) 오류 보고당 스텝 크기 [SWS_DM_00623](으)로, failedThreshold은(는) 한정된 오류에 대한 임계값 [SWS_DM_00621](으)로 설정된다. 정상 상태에서 결함 상태로 전환될 때 점프가 발생해야 하는 경우, useJumpToFailed을(를) true(으)로 설정하고 점프 값을 failedJumpValue에 저장한다 [SWS_DM_00625], [SWS_DM_00627].
  2. Monitor-Initialisierung: 애플리케이션 모듈은 ara::core::InstanceSpecifier, 초기화 알림 및 CounterBased 구조체를 전달하여 ara::diag::Monitor을(를) 인스턴스화한다 [SWS_DM_00549].
  3. DM에 의한 파라미터 적용: Diagnostic Management는 DEXT에 디바운스 파라미터가 설정되어 있는지 확인합니다. 설정된 값이 없으면, DM은 CounterBased의 값을 반드시 참조합니다 [SWS_DM_01101].
  4. Meldung von Monitor-Aktionen: 모니터링이 오류 증상을 감지하면 kPrefailed을(를) 인수로 하여 ara::diag::Monitor::ReportMonitorAction을(를) 호출한다 [SWS_DM_00875].
  5. 카운터 조정 및 자격 판정: counterJumpUp(useJumpToFailed에 해당)이 활성 상태이고 카운터가 failedJumpValue 미만인 경우, DM은 먼저 카운터를 점프 값 [SWS_DM_00022](으)로 설정합니다. 이어서 카운터가 failedStepsize만큼 증가합니다 [SWS_DM_00875]. 디바운스 카운터가 failedThreshold에 도달하거나 초과하면, 이벤트는 kFinallyDefective(으)로 처리됩니다 [SWS_DM_00024]. 정상 보고(kPrepassed)의 경우에도 마찬가지로 점프 [SWS_DM_00023] 및 감소 로직 [SWS_DM_00876]이 적용됩니다.

시퀀스 다이어그램: DEXT 평가 및 카운터 기반 한정을 포함한 초기화 및 디바운스 절차. 출처: [SWS_DM_00549], [SWS_DM_01099], [SWS_DM_01101], [SWS_DM_00875], [SWS_DM_00024].

오류 시나리오

ara::diag::CounterBased을(를) 다룰 때 특정 오류 상황 및 특수 사례가 발생할 수 있다:

  • DEXT 구성에 의한 재정의: DEXT에 디바운스 파라미터가 선언되어 있으면, Diagnostic Management는 모니터 생성자의 모든 값을 완전히 무시합니다 [SWS_DM_01099]. 따라서 DEXT의 구성 오류로 인해 소스 코드에서 유지 관리되는 CounterBased의 변경 사항이 컴파일러 또는 런타임 오류로 표시되지 않고 적용되지 않을 수 있습니다.
  • 디바운스 카운터의 포화: 증가 후 내부 카운터가 임계값 failedThreshold을 초과하면, DM은 카운터 값을 이 임계값으로 엄격히 제한합니다 [SWS_DM_00875]. 이를 통해 무제한으로 계속 카운트되거나 정수 오버플로가 발생하는 것을 방지합니다.
  • Inkonsistente Wertebelegung: 해석: 구조체 CounterBased은(는) 내장된 유효성 검사 기능을 포함하지 않는다. 타당하지 않은 값이 구성될 경우(예: failedStepsize == 0 또는 failedThreshold <= passedThreshold인 임계값), 구조체가 값을 검증 없이 저장하므로 이는 DM의 후속 처리 중 또는 런타임에 이르러서야 오작동을 유발할 것으로 추정된다.

<h4>컨텍스트</h4>
<p>C++ 구조체 <code>ara::diag::CounterBased</code>은(는) AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_DM_00538" href="../spec/record.html?id=SWS_DM_00538">[SWS_DM_00538]</a> 내에서 카운터 기반 이벤트 디바운싱(<em>counter-based debouncing</em>)을 위한 구성 매개변수를 나타낸다. 이는 진단 모니터를 위한 카운터 임계값, 스텝 크기 및 점프 값을 정의하는 데이터 구조 역할을 한다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=613">AUTOSAR_AP_SWS_Diagnostics §8.41.2 “Struct: CounterBased”</a>.</p>
<p>카운터 기반 디바운싱에는 여러 컴포넌트가 상호작용한다:</p>
<ul>
<li><strong>Diagnostic Monitor (애플리케이션):</strong> 애플리케이션별 모니터링 기능은 로컬 오류 상태를 확인하고 모니터 작업(예: <code>kPrefailed</code> 또는 <code>kPrepassed</code>)을 통해 이를 진단 관리에 주기적으로 보고한다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=239">AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.5.1 “Counter-based debouncing”</a>.</li>
<li><strong>ara::diag::Monitor:</strong> 진단 인프라에 대한 인터페이스를 형성하며, 인스턴스화 시 <code>ara::diag::CounterBased</code> 형태의 디바운스 파라미터를 전달받는다 <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a>.</li>
<li><strong>Diagnostic Management (DM):</strong> 이벤트별 내부 디바운스 카운터를 관리하고, 스텝 크기 <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>, <a class="spec-record-ref" data-req="SWS_DM_00876" href="../spec/record.html?id=SWS_DM_00876">[SWS_DM_00876]</a>에 따라 이를 증가 또는 감소시키며, 최종적으로 이벤트를 결함(<code>kFinallyDefective</code>)으로 한정한다 <a class="spec-record-ref" data-req="SWS_DM_00024" href="../spec/record.html?id=SWS_DM_00024">[SWS_DM_00024]</a>.</li>
<li><strong>Diagnostic Extract (DEXT):</strong> 모델링된 디바운스 파라미터를 포함한다. DEXT에 해당 이벤트에 대한 디바운스 파라미터가 존재하는 경우, 이는 C++ 생성자에서 전달된 값보다 우선권을 갖는다 <a class="spec-record-ref" data-req="SWS_DM_01099" href="../spec/record.html?id=SWS_DM_01099">[SWS_DM_01099]</a>.</li>
</ul>

<li><strong>Instanziierung und Belegung:</strong> 애플리케이션은 <code>ara::diag::CounterBased</code>의 인스턴스를 생성하고(일반적으로 스택에 로컬로 또는 정적 구성 구조체로), 카운터 임계값(<code>failedThreshold</code> <a class="spec-record-ref" data-req="SWS_DM_00621" href="../spec/record.html?id=SWS_DM_00621">[SWS_DM_00621]</a>, <code>passedThreshold</code> <a class="spec-record-ref" data-req="SWS_DM_00622" href="../spec/record.html?id=SWS_DM_00622">[SWS_DM_00622]</a>), 스텝 크기(<code>failedStepsize</code> <a class="spec-record-ref" data-req="SWS_DM_00623" href="../spec/record.html?id=SWS_DM_00623">[SWS_DM_00623]</a>, <code>passedStepsize</code> <a class="spec-record-ref" data-req="SWS_DM_00624" href="../spec/record.html?id=SWS_DM_00624">[SWS_DM_00624]</a>) 및 점프 속성(<code>failedJumpValue</code> <a class="spec-record-ref" data-req="SWS_DM_00625" href="../spec/record.html?id=SWS_DM_00625">[SWS_DM_00625]</a>, <code>passedJumpValue</code> <a class="spec-record-ref" data-req="SWS_DM_00626" href="../spec/record.html?id=SWS_DM_00626">[SWS_DM_00626]</a>, <code>useJumpToFailed</code> <a class="spec-record-ref" data-req="SWS_DM_00627" href="../spec/record.html?id=SWS_DM_00627">[SWS_DM_00627]</a> 및 <code>useJumpToPassed</code> <a class="spec-record-ref" data-req="SWS_DM_00628" href="../spec/record.html?id=SWS_DM_00628">[SWS_DM_00628]</a>)을 초기화한다.</li>
<li><strong>모니터로 전달:</strong> 채워진 구조체는 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=607">AUTOSAR_AP_SWS_Diagnostics §8.40.1.1.2.2 “Monitor”</a>에서 <code>ara::diag::Monitor</code>의 생성자에 인수로 전달됩니다 <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a>.</li>
<li><strong>Besitz und Weitergabe:</strong> 해석: 동적 메모리 관리가 없는 기본 C++ 구조체이므로, 생성자 호출 시 값이 복사된다. 원래 인스턴스는 모니터의 소유로 남지 않으며 생성자 호출이 반환된 후 안전하게 폐기할 수 있다.</li>
<li><strong>Gültigkeitsdauer:</strong> DEXT에 해당 디바운스 파라미터가 없는 경우, Diagnostic Management는 내부 디바운스 알고리즘을 위해 전달된 값을 적용한다 <a class="spec-record-ref" data-req="SWS_DM_01101" href="../spec/record.html?id=SWS_DM_01101">[SWS_DM_01101]</a>. 이 값들은 해당 모니터의 전체 수명 동안 활성 상태를 유지한다.</li>
<li><strong>Nebenläufigkeit:</strong> 구조체 자체는 스레드 동기화를 제공하지 않는다. 그러나 전달 전에 완전히 초기화되고 그 후에는 값으로만 전달되므로, 생성자 호출 전에 동시 쓰기 접근이 발생하지 않는 한 생성 및 전달은 동시성 측면에서 안전하다.</li>
</ul>

<h4>사용 경로</h4>
<p><code>ara::diag::CounterBased</code> 사용을 위한 일반적인 절차는 파라미터화, 등록 및 이후 런타임 이벤트 처리를 포함한다:</p>
<ol>
<li><strong>Konfiguration der Entprellparameter:</strong> 애플리케이션은 <code>ara::diag::CounterBased</code>의 멤버를 설정한다. 예를 들어 <code>failedStepsize</code>은(는) 오류 보고당 스텝 크기 <a class="spec-record-ref" data-req="SWS_DM_00623" href="../spec/record.html?id=SWS_DM_00623">[SWS_DM_00623]</a>(으)로, <code>failedThreshold</code>은(는) 한정된 오류에 대한 임계값 <a class="spec-record-ref" data-req="SWS_DM_00621" href="../spec/record.html?id=SWS_DM_00621">[SWS_DM_00621]</a>(으)로 설정된다. 정상 상태에서 결함 상태로 전환될 때 점프가 발생해야 하는 경우, <code>useJumpToFailed</code>을(를) <code>true</code>(으)로 설정하고 점프 값을 <code>failedJumpValue</code>에 저장한다 <a class="spec-record-ref" data-req="SWS_DM_00625" href="../spec/record.html?id=SWS_DM_00625">[SWS_DM_00625]</a>, <a class="spec-record-ref" data-req="SWS_DM_00627" href="../spec/record.html?id=SWS_DM_00627">[SWS_DM_00627]</a>.</li>
<li><strong>Monitor-Initialisierung:</strong> 애플리케이션 모듈은 <code>ara::core::InstanceSpecifier</code>, 초기화 알림 및 <code>CounterBased</code> 구조체를 전달하여 <code>ara::diag::Monitor</code>을(를) 인스턴스화한다 <a class="spec-record-ref" data-req="SWS_DM_00549" href="../spec/record.html?id=SWS_DM_00549">[SWS_DM_00549]</a>.</li>
<li><strong>DM에 의한 파라미터 적용:</strong> Diagnostic Management는 DEXT에 디바운스 파라미터가 설정되어 있는지 확인합니다. 설정된 값이 없으면, DM은 <code>CounterBased</code>의 값을 반드시 참조합니다 <a class="spec-record-ref" data-req="SWS_DM_01101" href="../spec/record.html?id=SWS_DM_01101">[SWS_DM_01101]</a>.</li>
<li><strong>Meldung von Monitor-Aktionen:</strong> 모니터링이 오류 증상을 감지하면 <code>kPrefailed</code>을(를) 인수로 하여 <code>ara::diag::Monitor::ReportMonitorAction</code>을(를) 호출한다 <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>.</li>
<li><strong>카운터 조정 및 자격 판정:</strong> <code>counterJumpUp</code>(<code>useJumpToFailed</code>에 해당)이 활성 상태이고 카운터가 <code>failedJumpValue</code> 미만인 경우, DM은 먼저 카운터를 점프 값 <a class="spec-record-ref" data-req="SWS_DM_00022" href="../spec/record.html?id=SWS_DM_00022">[SWS_DM_00022]</a>(으)로 설정합니다. 이어서 카운터가 <code>failedStepsize</code>만큼 증가합니다 <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>. 디바운스 카운터가 <code>failedThreshold</code>에 도달하거나 초과하면, 이벤트는 <code>kFinallyDefective</code>(으)로 처리됩니다 <a class="spec-record-ref" data-req="SWS_DM_00024" href="../spec/record.html?id=SWS_DM_00024">[SWS_DM_00024]</a>. 정상 보고(<code>kPrepassed</code>)의 경우에도 마찬가지로 점프 <a class="spec-record-ref" data-req="SWS_DM_00023" href="../spec/record.html?id=SWS_DM_00023">[SWS_DM_00023]</a> 및 감소 로직 <a class="spec-record-ref" data-req="SWS_DM_00876" href="../spec/record.html?id=SWS_DM_00876">[SWS_DM_00876]</a>이 적용됩니다.</li>

<h4>오류 시나리오</h4>
<p><code>ara::diag::CounterBased</code>을(를) 다룰 때 특정 오류 상황 및 특수 사례가 발생할 수 있다:</p>
<ul>
<li><strong>DEXT 구성에 의한 재정의:</strong> DEXT에 디바운스 파라미터가 선언되어 있으면, Diagnostic Management는 모니터 생성자의 모든 값을 완전히 무시합니다 <a class="spec-record-ref" data-req="SWS_DM_01099" href="../spec/record.html?id=SWS_DM_01099">[SWS_DM_01099]</a>. 따라서 DEXT의 구성 오류로 인해 소스 코드에서 유지 관리되는 <code>CounterBased</code>의 변경 사항이 컴파일러 또는 런타임 오류로 표시되지 않고 적용되지 않을 수 있습니다.</li>
<li><strong>디바운스 카운터의 포화:</strong> 증가 후 내부 카운터가 임계값 <code>failedThreshold</code>을 초과하면, DM은 카운터 값을 이 임계값으로 엄격히 제한합니다 <a class="spec-record-ref" data-req="SWS_DM_00875" href="../spec/record.html?id=SWS_DM_00875">[SWS_DM_00875]</a>. 이를 통해 무제한으로 계속 카운트되거나 정수 오버플로가 발생하는 것을 방지합니다.</li>
<li><strong>Inkonsistente Wertebelegung:</strong> 해석: 구조체 <code>CounterBased</code>은(는) 내장된 유효성 검사 기능을 포함하지 않는다. 타당하지 않은 값이 구성될 경우(예: <code>failedStepsize == 0</code> 또는 <code>failedThreshold &lt;= passedThreshold</code>인 임계값), 구조체가 값을 검증 없이 저장하므로 이는 DM의 후속 처리 중 또는 런타임에 이르러서야 오작동을 유발할 것으로 추정된다.</li>
</ul>
