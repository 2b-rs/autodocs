컨텍스트

ara::diag::GenericRoutine 클래스는 AUTOSAR Adaptive Platform의 진단 모듈(ara::diag)에서 진단 루틴 처리를 위한 제네릭 인터페이스를 제공합니다. 이 클래스는 애플리케이션 레벨에서 UDS 서비스 RoutineControl(ISO 14229-1 Service 0x31)과 관련된 상호작용을 캡슐화합니다. 타입별로 생성된 루틴 인터페이스와 달리 GenericRoutine은(는) 요청 데이터를 바이트 범위(Byte-Span)로 제네릭하게 처리하므로, 동일한 구현을 서로 다른 루틴 식별자(routineId)에 유연하게 활용할 수 있습니다.

주요 상호작용 파트너는 AUTOSAR 런타임 환경의 Diagnostic Management(DM)와 애플리케이션별 진단 로직입니다. Diagnostic Management는 외부 테스터의 진단 요청을 수신하고, 인스턴스가 ara::core::InstanceSpecifier을(를) 통해 DiagnosticRoutineGenericInterface 타입의 모델링된 PortPrototype에 바인딩되고 활성화되면 들어오는 RoutineControl 요청을 해당 인스턴스로 전달합니다 [SWS_DM_00552], [SWS_DM_00557]. 애플리케이션 소프트웨어는 GenericRoutine에서 자체 핸들러 클래스를 파생시키고 차량 전자제어장치에서 애플리케이션별 실행 로직을 구현합니다.

수명 주기

GenericRoutine 인스턴스의 수명 주기는 생성, 서비스 제공, 요청 처리, 등록 취소 및 소멸 단계를 포함합니다.

생성자 GenericRoutine(const ara::core::InstanceSpecifier &specifier, ConcurrencyType concurrencyType)을(를) 통한 생성 시 객체는 모델에 정의된 포트에 바인딩됩니다 [SWS_DM_00552]. 매개변수 concurrencyType은(는) 인터페이스가 스레드 안전(kConcurrent)하게 구현되었는지 또는 스레드 안전하지 않게(kNotConcurrent) 구현되었는지를 구속력 있게 정의하며, 이는 DM이 콜백 메서드를 동시 호출할 수 있는지 여부를 결정합니다 [SWS_DM_00552].

소유권 관계와 관련하여 GenericRoutine은(는) 엄격한 단일 인스턴스로 설계되었습니다: 복사 및 이동 생성자와 대입 연산자가 모두 삭제되었습니다(=delete) [SWS_DM_01635], [SWS_DM_01636], [SWS_DM_01637], [SWS_DM_01638]. 따라서 인스턴스는 생성된 위치에 고정되어 유지됩니다.

인스턴스화 후 객체는 인스턴스화됨 상태에 있습니다. DM은 이 시점에서 아직 메시지를 전달하지 않습니다. Offer()의 동기식 호출을 통해서만 전달이 활성화되고 인스턴스가 제공됨 상태로 전환됩니다 [SWS_DM_00557]. StopOffer()을(를) 통해 언제든지 DM에 의한 요청 전달을 다시 비활성화할 수 있습니다 [SWS_DM_00558].

소멸은 가상 소멸자 ~GenericRoutine()을(를) 통해 수행됩니다 [SWS_DM_00553]. 메서드 Offer(), StopOffer() 및 소멸자는 스레드 안전하지 않으므로, 수명 주기 전이는 애플리케이션 코드에서 동기화되어 실행되어야 합니다 [SWS_DM_00553], [SWS_DM_00557], [SWS_DM_00558].

상태 다이어그램: GenericRoutine 인스턴스의 수명 주기 및 상태 전이. 출처: [SWS_DM_00552], [SWS_DM_00553], [SWS_DM_00557], [SWS_DM_00558].

사용 경로

GenericRoutine의 일반적인 사용에는 다음 단계가 포함됩니다:

  1. 인스턴스화 및 등록: 애플리케이션은 InstanceSpecifier 및 ConcurrencyType을(를) 지정하여 파생 하위 클래스의 인스턴스를 생성합니다 [SWS_DM_00552]. 그런 다음 Offer()을(를) 통해 수신을 활성화합니다 [SWS_DM_00557].
  2. 루틴 시작(SubFunction 0x01): DM이 SubFunction Start가 포함된 RoutineControl 요청을 수신하면 순수 가상 메서드 Start()을(를) 호출합니다[SWS_DM_00554]. 이때 routineId, ara::core::Span<const std::uint8_t> 형태의 원시 데이터 requestData, 컨텍스트 metaInfo 및 CancellationHandler이(가) 전달됩니다[SWS_DM_00554]. requestData의 데이터는 결과 Promise가 이행되거나 처리가 중단될 때까지 유효하게 유지됩니다[SWS_DM_00554].
  3. 비동기 처리: 이 메서드는 DM에 ara::core::Future<OperationOutput>을(를) 즉시 반환합니다[SWS_DM_00554]. 실제 처리는 애플리케이션 로직에서 비동기적으로 수행됩니다. 완료 후 관련 Promise는 OperationOutput(으)로 이행됩니다.
  4. 선택적 작업: 루틴 사양에 따라 테스터는 실행 중 또는 실행 후에 추가 작업을 트리거할 수 있습니다:
    • Stop() (SubFunction 0x02): 실행 중인 루틴을 특정하여 중지하기 위해 호출됩니다[SWS_DM_00555].
    • RequestResults() (SubFunction 0x03): 루틴의 중간 또는 최종 결과를 쿼리하는 데 사용됩니다[SWS_DM_00556].
    두 메서드 모두 유사하게 ara::core::Future<OperationOutput>을(를) 반환합니다[SWS_DM_00555], [SWS_DM_00556].
  5. 서비스 종료: 시스템 종료 전에 애플리케이션은 DM에 의한 전달을 종료하기 위해 StopOffer()을(를) 호출합니다[SWS_DM_00558].

시퀀스 다이어그램: Start 및 StopOffer의 호출 및 실행 시퀀스. 출처: [SWS_DM_00554], [SWS_DM_00557], [SWS_DM_00558].

오류 시나리오

오류는 구성 시, 서비스 등록 시 및 실행 중에 발생할 수 있습니다:

  • 구성 및 인스턴스화 오류: 생성자에서 InstanceSpecifier 바인딩에 실패하면 특정 런타임 위반이 발생합니다[SWS_DM_00552]:
    • InstanceSpecifierMappingIntegrityViolation: 식별자를 Executable 컨텍스트에서 확인할 수 없거나 PortPrototype을(를) 참조하지 않습니다.
    • PortInterfaceMappingViolation: DiagnosticRoutineGenericInterface(으)로 형식화된 포트가 어떠한 DiagnosticServiceGenericMapping에도 할당되지 않았습니다.
    • ProcessMappingViolation: 기존 인스턴스 참조에 대해 런타임에 일치하는 모델링된 프로세스가 존재하지 않습니다.
    • InstanceSpecifierAlreadyInUseViolation: InstanceSpecifier이(가) 현재 프로세스에서 이미 다른 인스턴스에 의해 사용되고 있다.
  • 제공 시 오류: 서비스가 이미 활발히 제공되는 중에 Offer()을(를) 호출하면 호출이 실패하고 ara::core::Result<void>에서 롤백 의미 체계와 함께 오류 코드 DiagOfferErrc::kAlreadyOffered을(를) 반환합니다[SWS_DM_00557].
  • 부정 진단 응답(UDS NRC): 루틴 실행 중 오류가 발생하면 Future가 OperationOutput(으)로 이행되지 않습니다. 대신 오류 경로에서 DiagUdsNrcErrc을(를) 통해 ISO 14229-1에 따른 적절한 Negative Response Code를 반환해야 합니다[SWS_DM_00554], [SWS_DM_00555], [SWS_DM_00556].
  • 진단 대화 취소: 진행 중인 요청이 취소되면 애플리케이션은 cancellationHandler을(를) 통해 이를 처리할 수 있습니다[SWS_DM_00554]. cancellationHandler.IsCanceled()을(를) 통해 상태를 능동적으로 쿼리하거나(취소 시 TRUE 반환), 사전에 cancellationHandler.SetNotifier()을(를) 통해 알림 콜백을 등록하여 취소 시 트리거되도록 할 수 있습니다[SWS_DM_00554].

<p><code>ara::diag::GenericRoutine</code> 클래스는 AUTOSAR Adaptive Platform의 진단 모듈(<code>ara::diag</code>)에서 진단 루틴 처리를 위한 제네릭 인터페이스를 제공합니다. 이 클래스는 애플리케이션 레벨에서 UDS 서비스 <em>RoutineControl</em>(ISO 14229-1 Service 0x31)과 관련된 상호작용을 캡슐화합니다. 타입별로 생성된 루틴 인터페이스와 달리 <code>GenericRoutine</code>은(는) 요청 데이터를 바이트 범위(Byte-Span)로 제네릭하게 처리하므로, 동일한 구현을 서로 다른 루틴 식별자(<code>routineId</code>)에 유연하게 활용할 수 있습니다.</p>
<p>주요 상호작용 파트너는 AUTOSAR 런타임 환경의 Diagnostic Management(DM)와 애플리케이션별 진단 로직입니다. Diagnostic Management는 외부 테스터의 진단 요청을 수신하고, 인스턴스가 <code>ara::core::InstanceSpecifier</code>을(를) 통해 <code>DiagnosticRoutineGenericInterface</code> 타입의 모델링된 PortPrototype에 바인딩되고 활성화되면 들어오는 RoutineControl 요청을 해당 인스턴스로 전달합니다 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>, <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>. 애플리케이션 소프트웨어는 <code>GenericRoutine</code>에서 자체 핸들러 클래스를 파생시키고 차량 전자제어장치에서 애플리케이션별 실행 로직을 구현합니다.</p>

<h4>수명 주기</h4>
<p><code>GenericRoutine</code> 인스턴스의 수명 주기는 생성, 서비스 제공, 요청 처리, 등록 취소 및 소멸 단계를 포함합니다.</p>
<p>생성자 <code>GenericRoutine(const ara::core::InstanceSpecifier &amp;specifier, ConcurrencyType concurrencyType)</code>을(를) 통한 생성 시 객체는 모델에 정의된 포트에 바인딩됩니다 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>. 매개변수 <code>concurrencyType</code>은(는) 인터페이스가 스레드 안전(<code>kConcurrent</code>)하게 구현되었는지 또는 스레드 안전하지 않게(<code>kNotConcurrent</code>) 구현되었는지를 구속력 있게 정의하며, 이는 DM이 콜백 메서드를 동시 호출할 수 있는지 여부를 결정합니다 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>.</p>
<p>소유권 관계와 관련하여 <code>GenericRoutine</code>은(는) 엄격한 단일 인스턴스로 설계되었습니다: 복사 및 이동 생성자와 대입 연산자가 모두 삭제되었습니다(<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01635" href="../spec/record.html?id=SWS_DM_01635">[SWS_DM_01635]</a>, <a class="spec-record-ref" data-req="SWS_DM_01636" href="../spec/record.html?id=SWS_DM_01636">[SWS_DM_01636]</a>, <a class="spec-record-ref" data-req="SWS_DM_01637" href="../spec/record.html?id=SWS_DM_01637">[SWS_DM_01637]</a>, <a class="spec-record-ref" data-req="SWS_DM_01638" href="../spec/record.html?id=SWS_DM_01638">[SWS_DM_01638]</a>. 따라서 인스턴스는 생성된 위치에 고정되어 유지됩니다.</p>
<p>인스턴스화 후 객체는 <em>인스턴스화됨</em> 상태에 있습니다. DM은 이 시점에서 아직 메시지를 전달하지 않습니다. <code>Offer()</code>의 동기식 호출을 통해서만 전달이 활성화되고 인스턴스가 <em>제공됨</em> 상태로 전환됩니다 <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>. <code>StopOffer()</code>을(를) 통해 언제든지 DM에 의한 요청 전달을 다시 비활성화할 수 있습니다 <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</p>
<p>소멸은 가상 소멸자 <code>~GenericRoutine()</code>을(를) 통해 수행됩니다 <a class="spec-record-ref" data-req="SWS_DM_00553" href="../spec/record.html?id=SWS_DM_00553">[SWS_DM_00553]</a>. 메서드 <code>Offer()</code>, <code>StopOffer()</code> 및 소멸자는 스레드 안전하지 않으므로, 수명 주기 전이는 애플리케이션 코드에서 동기화되어 실행되어야 합니다 <a class="spec-record-ref" data-req="SWS_DM_00553" href="../spec/record.html?id=SWS_DM_00553">[SWS_DM_00553]</a>, <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>, <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</p>

<h4>사용 경로</h4>
<p><code>GenericRoutine</code>의 일반적인 사용에는 다음 단계가 포함됩니다:</p>
<ol>
  <li><strong>인스턴스화 및 등록:</strong> 애플리케이션은 <code>InstanceSpecifier</code> 및 <code>ConcurrencyType</code>을(를) 지정하여 파생 하위 클래스의 인스턴스를 생성합니다 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>. 그런 다음 <code>Offer()</code>을(를) 통해 수신을 활성화합니다 <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>.</li>
  <li><strong>루틴 시작(SubFunction 0x01):</strong> DM이 SubFunction <em>Start</em>가 포함된 RoutineControl 요청을 수신하면 순수 가상 메서드 <code>Start()</code>을(를) 호출합니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. 이때 <code>routineId</code>, <code>ara::core::Span&lt;const std::uint8_t&gt;</code> 형태의 원시 데이터 <code>requestData</code>, 컨텍스트 <code>metaInfo</code> 및 <code>CancellationHandler</code>이(가) 전달됩니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. <code>requestData</code>의 데이터는 결과 Promise가 이행되거나 처리가 중단될 때까지 유효하게 유지됩니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>.</li>
  <li><strong>비동기 처리:</strong> 이 메서드는 DM에 <code>ara::core::Future&lt;OperationOutput&gt;</code>을(를) 즉시 반환합니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. 실제 처리는 애플리케이션 로직에서 비동기적으로 수행됩니다. 완료 후 관련 Promise는 <code>OperationOutput</code>(으)로 이행됩니다.</li>
  <li><strong>선택적 작업:</strong> 루틴 사양에 따라 테스터는 실행 중 또는 실행 후에 추가 작업을 트리거할 수 있습니다:
    <ul>
      <li><code>Stop()</code> (SubFunction 0x02): 실행 중인 루틴을 특정하여 중지하기 위해 호출됩니다<a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>.</li>
      <li><code>RequestResults()</code> (SubFunction 0x03): 루틴의 중간 또는 최종 결과를 쿼리하는 데 사용됩니다<a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
    </ul>
    두 메서드 모두 유사하게 <code>ara::core::Future&lt;OperationOutput&gt;</code>을(를) 반환합니다<a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>, <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
  <li><strong>서비스 종료:</strong> 시스템 종료 전에 애플리케이션은 DM에 의한 전달을 종료하기 위해 <code>StopOffer()</code>을(를) 호출합니다<a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>.</li>
</ol>

<h4>오류 시나리오</h4>
<p>오류는 구성 시, 서비스 등록 시 및 실행 중에 발생할 수 있습니다:</p>
<ul>
  <li><strong>구성 및 인스턴스화 오류:</strong> 생성자에서 <code>InstanceSpecifier</code> 바인딩에 실패하면 특정 런타임 위반이 발생합니다<a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>:
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>: 식별자를 Executable 컨텍스트에서 확인할 수 없거나 <code>PortPrototype</code>을(를) 참조하지 않습니다.</li>
      <li><code>PortInterfaceMappingViolation</code>: <code>DiagnosticRoutineGenericInterface</code>(으)로 형식화된 포트가 어떠한 <code>DiagnosticServiceGenericMapping</code>에도 할당되지 않았습니다.</li>
      <li><code>ProcessMappingViolation</code>: 기존 인스턴스 참조에 대해 런타임에 일치하는 모델링된 프로세스가 존재하지 않습니다.</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>: <code>InstanceSpecifier</code>이(가) 현재 프로세스에서 이미 다른 인스턴스에 의해 사용되고 있다.</li>
    </ul>
  </li>
  <li><strong>제공 시 오류:</strong> 서비스가 이미 활발히 제공되는 중에 <code>Offer()</code>을(를) 호출하면 호출이 실패하고 <code>ara::core::Result&lt;void&gt;</code>에서 롤백 의미 체계와 함께 오류 코드 <code>DiagOfferErrc::kAlreadyOffered</code>을(를) 반환합니다<a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>.</li>
  <li><strong>부정 진단 응답(UDS NRC):</strong> 루틴 실행 중 오류가 발생하면 Future가 <code>OperationOutput</code>(으)로 이행되지 않습니다. 대신 오류 경로에서 <code>DiagUdsNrcErrc</code>을(를) 통해 ISO 14229-1에 따른 적절한 Negative Response Code를 반환해야 합니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>, <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>, <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>.</li>
  <li><strong>진단 대화 취소:</strong> 진행 중인 요청이 취소되면 애플리케이션은 <code>cancellationHandler</code>을(를) 통해 이를 처리할 수 있습니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>. <code>cancellationHandler.IsCanceled()</code>을(를) 통해 상태를 능동적으로 쿼리하거나(취소 시 <code>TRUE</code> 반환), 사전에 <code>cancellationHandler.SetNotifier()</code>을(를) 통해 알림 콜백을 등록하여 취소 시 트리거되도록 할 수 있습니다<a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>.</li>
</ul>
