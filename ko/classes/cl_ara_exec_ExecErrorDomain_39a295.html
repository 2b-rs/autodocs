Execution Management 오류의 식별과 이를 메시지 텍스트 및 예외 객체로 매핑하는 역할을 합니다.

ara::exec::ExecErrorDomain 클래스는 Execution Management를 위한 오류 도메인을 정의하고 숫자 오류 코드를 설명 메시지로 매핑합니다([SWS_EM_02288]). 이는 기본적으로 생성되며([SWS_EM_02286]) 타입 안전한 ExecException 예외를 발생시킬 수 있습니다([SWS_EM_02289]). C++ 예외가 비활성화된 경우, ThrowAsException() 함수는 [SWS_CORE_10304]에 따라 컴파일 타임에 비활성화됩니다([SWS_EM_02289]).

컨텍스트

ara::exec::ExecErrorDomain 클래스는 AUTOSAR Adaptive Platform 내의 Execution Management 기능 클러스터를 위한 특정 오류 도메인을 정의합니다. 기본 클래스 ara::core::ErrorDomain의 최종 특수화로서 도메인 특정 오류 원인의 할당을 캡슐화하고 숫자 오류 코드와 의미적 오류 설명 사이의 가교 역할을 합니다. 기본 타입 ara::core::ErrorDomain 외에도 클래스는 ara::core::ErrorCode과 밀접하게 상호작용하며 오류 발생 시 ExecException 타입의 특정 예외 객체를 인스턴스화합니다([SWS_EM_02289]). Name() 메서드를 통해 클래스는 [SWS_CORE_90023]의 명세 ara::exec::ExecErrorDomain에 해당하는 도메인의 텍스트 식별자를 제공합니다([SWS_EM_02287]).

컨텍스트 다이어그램: 오류 시스템 내 ExecErrorDomain 및 해당 상호작용 대상의 분류. 출처: [SWS_EM_02287], [SWS_EM_02289], [SWS_CORE_90023]

수명 주기

ara::exec::ExecErrorDomain의 객체는 기본 생성자를 통해 생성됩니다([SWS_EM_02286]). 생성은 noexcept로 선언되어 있으며 완전한 예외 안전성 및 스레드 안전성을 보장합니다([SWS_EM_02286]). 클래스가 가변 상태를 노출하지 않고 final로 선언되어 있으므로 모든 읽기 작업은 부작용 없이 동작합니다. 실제 애플리케이션에서는 생성자를 통한 직접 인스턴스화가 언제든지 가능하더라도 일반적으로 오류 도메인의 전역 또는 정적 인스턴스가 사용될 것으로 보입니다(해석: Adaptive AUTOSAR의 일반적인 오류 모델에 따름).

동시성과 관련하여 모든 멤버 함수(즉, Name()을 통한 이름 조회([SWS_EM_02287]), Message()를 통한 오류 메시지 확인([SWS_EM_02288]), ThrowAsException()를 사용한 예외 발생([SWS_EM_02289]))는 명시적으로 스레드 안전한 것으로 명세되어 있습니다. 따라서 여러 실행 스레드가 외부 동기화 없이 동일한 인스턴스를 병렬로 쿼리할 수 있습니다.

사용 경로

정상적인 실행 경로에서 도메인은 오류 번호를 이해하기 쉬운 진단 메시지로 변환하고 오류 코드를 예외 객체로 변환하는 역할을 합니다. Execution Management 작업 내에서 오류가 발생하면 일반적으로 내부적으로 ara::exec::ExecErrorDomain의 인스턴스를 가리키는 ara::core::ErrorCode으로 표시됩니다. 텍스트 출력을 위해 호출자는 숫자 오류 식별자를 Message()에 전달하고([SWS_EM_02288]) 원인을 설명하는 불변 문자열에 대한 포인터(const char*)를 수신합니다.

호출 컴포넌트가 예외 기반 오류 처리를 결정하는 경우 ThrowAsException() 메서드가 사용됩니다([SWS_EM_02289]). 함수는 ara::core::ErrorCode에 대한 참조를 받아 이로부터 ExecException의 새 인스턴스를 생성하고 이를 C++ 예외로서 호출 컨텍스트에 즉시 발생시킵니다([SWS_EM_02289]).

시퀀스 다이어그램: ThrowAsException을 통한 C++ 예외 발생 절차. 출처: [SWS_EM_02289], [SWS_CORE_10304]

오류 시나리오

정보 조회 메서드는 엄격한 보장을 특징으로 합니다: 생성([SWS_EM_02286])이나 Name()을 통한 이름 조회([SWS_EM_02287]), Message()을 통한 메시지 조회([SWS_EM_02288]) 모두 예외를 발생시키지 않으며(noexcept), 세 가지 모두 예외 안전(“exception safe”)으로 분류됩니다. 알 수 없는 오류 코드의 경우 Message()은 일반적인 플레이스홀더 텍스트 또는 빈 문자열을 반환할 것으로 보입니다(해석: 페이로드는 유효하지 않은 CodeType 값에 대해 별도의 오류 동작을 정의하지 않음).

ThrowAsException()에 대해서는 별도의 동작이 적용됩니다: 이 함수는 noexcept(false)이자 명시적으로 예외 안전하지 않음(“not exception safe”)으로 명세되어 있는데, 그 주된 목적이 ExecException를 던지는 데 있기 때문입니다([SWS_EM_02289]). 또한 툴체인의 필수 조건이 적용됩니다: [SWS_CORE_10304]에 따르면 컴파일러에서 C++ 예외가 비활성화된 경우 ThrowAsException()는 오버로드 확인에 참여하지 않습니다([SWS_EM_02289]). 따라서 예외 지원이 없는 시스템 환경에서는 컴파일 타임에 이 경로를 사용할 수 없으므로 오류는 반드시 반환 값을 통해 평가되어야 합니다.

이 문서는 AUTOSAR 명세 R25-11을 기반으로 인공지능에 의해 생성되었습니다.
