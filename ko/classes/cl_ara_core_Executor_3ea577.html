클래스 ara::core::Executor

[SWS_CORE_00008] Upstream: RS_AP_00130

class Executor {...};

Provides an interface for a executing context, which asynchronously invokes Callable ([4] [func.wrap.func]) objects in a guaranteed thread-safe context. The execute(...) method in [SWS_CORE_00024] returns a ara::core::Future object to the caller for further result/error extraction or management of the asynchronous-context; the execute_oneway(...) method in [SWS_CORE_00025] imply fire-and-forget semantics and thus no asynchronous-context (ara::core::Future) is returned.

참고문헌 SWS 코어: [4] ISO/IEC 14882:2014, Information technology – Programming languages – C++ – www.iso.org

컨텍스트

ara::core::Executor 클래스는 보장된 스레드 안전 환경에서 호출 가능한 객체(Callables)를 비동기적으로 실행하는 실행 컨텍스트용 인터페이스를 제공합니다. AUTOSAR Adaptive Platform의 core 모듈 내에서 이 클래스는 호출과 실제 실행의 분리를 추상화하여, 애플리케이션이 자체 스레드 구조나 동기화 프리미티브를 직접 관리할 필요 없이 백그라운드 작업을 시작할 수 있도록 합니다.

ara::core::Executor과의 상호 작용에는 기본적으로 세 주체가 참여합니다:

  • 호출자(Caller): 관련 인수와 함께 호출 가능한 단위(함수 객체, 람다 또는 함수 포인터 등)를 전달합니다.
  • 실행 컨텍스트(Executor 인스턴스 및 백그라운드 워커): 요청을 수락하고 Callable을 비동기적이면서 스레드 안전하게 실행합니다.
  • 반환 채널(ara::core::Future): 동기화가 필요한 작업의 경우 execute([SWS_CORE_00024]) 호출 시 Future 객체가 반환되며, 이를 통해 호출자는 나중에 계산 결과나 발생한 오류에 접근할 수 있습니다. oneway_execute([SWS_CORE_00025])를 통한 순수 Fire-and-Forget 작업의 경우 이 반환 채널은 완전히 생략됩니다.

수명 주기

ara::core::Executor 인스턴스의 수명 주기는 생성, 값 전달 및 소멸에 의해 결정됩니다. 사양은 스레드 안전성 및 예외 안전성과 관련하여 특정한 속성을 정의합니다:

  • 복사: 복사 생성자([SWS_CORE_00009]) 및 복사 할당 연산자([SWS_CORE_00017])는 스레드 안전(thread-safe)하지만, 명시적으로 예외 안전하지 않음(not exception safe)으로 선언되어 있습니다. 따라서 인스턴스를 동시에 복사할 수 있지만 호출자는 복사 작업 실패에 대비한 조치를 취해야 합니다.
  • 이동: 이동 생성자([SWS_CORE_00015]) 및 이동 할당 연산자([SWS_CORE_00018])는 noexcept(으)로 선언되어 있으며 예외 안전(exception safe)합니다. 그러나 스레드 안전하지 않으므로(not thread-safe), Executor 이동은 경쟁 접근 없이 독점적으로 수행되어야 합니다.
  • 소멸: 소멸자 ~Executor()([SWS_CORE_00019])은(는) noexcept이며 예외 안전하고 스레드 안전합니다. 이는 멀티스레딩 시나리오에서도 인스턴스가 질서 있게 해제되도록 보장합니다.

사용 경로

비동기 작업 처리를 위해 ara::core::Executor은(는) 두 가지 서로 다른 경로를 제공합니다:

  1. 결과 모니터링을 포함한 비동기 실행(execute): 호출자는 Callable f 및 해당 인수 p...을(를) 템플릿 메서드 execute([SWS_CORE_00024])에 전달합니다. 이 함수는 ara::core::Future<std::invoke_result_t<std::decay_t<F>, std::decay_t<P>...>> 타입의 객체를 즉시 반환합니다. f의 실행은 백그라운드에서 동시에 수행됩니다. 호출자는 적절한 시점에 Future를 통해 결과를 쿼리합니다. execute 자체는 스레드 안전하지 않음(not thread-safe)으로 선언되어 있으므로([SWS_CORE_00024]), 동일한 Executor 인스턴스에 대한 execute의 동시 호출은 호출자 측에서 동기화되어야 합니다.
  2. 반환 채널이 없는 단방향 실행(oneway_execute): 호출자에게 결과 및 오류 모니터링이 필요하지 않은 경우 oneway_execute([SWS_CORE_00025])이(가) 사용됩니다. 이 메서드는 Fire-and-Forget 시맨틱을 가지며, void을(를) 반환하고 Future를 생성하지 않습니다. execute과(와) 달리 oneway_execute은(는) 직접 스레드 안전(thread-safe)으로 선언되어 있습니다([SWS_CORE_00025]).

시퀀스 다이어그램: Future를 통한 결과 쿼리를 포함한 비동기 함수 전달의 일반적인 흐름. 출처: [SWS_CORE_00024]

오류 시나리오

오류 처리는 선택한 실행 방법 및 수명 주기 작업에 따라 다릅니다:

  • 동기 오류 코드 없음: execute([SWS_CORE_00024]) 및 oneway_execute([SWS_CORE_00025]) 모두 호출 자체에서 표준화된 오류 코드를 정의하지 않으며, 두 메서드 모두 noexcept(으)로 선언되어 있습니다.
  • execute 시 Future를 통한 오류 전파: Callable의 비동기 실행 중에 오류가 발생하면 execute에서 반환된 ara::core::Future에 저장됩니다([SWS_CORE_00024]). 성공적으로 처리되면 Future에 계산된 값이 포함되고, 오류가 발생하면 오류 코드(ErrorCode)가 포함됩니다.
  • oneway_execute 시 오류 처리: 반환 채널이 없으므로 oneway_execute([SWS_CORE_00025])을(를) 통해 전달된 Callable의 비동기 실행 중에 발생하는 오류는 호출자에게 전파될 수 없습니다. 이러한 오류는 함수 객체 자체 내에서 처리되어야 합니다.
  • 복사 작업 실패: 복사 생성자([SWS_CORE_00009]) 및 복사 할당([SWS_CORE_00017])은 예외 안전하지 않은 것으로 지정되어 있으므로 복사 작업이 실패할 수 있는 반면, 이동 작업([SWS_CORE_00015], [SWS_CORE_00018])은 noexcept 덕분에 예외 안전성이 보장됩니다.

이 가이드는 Release R25-11용 AUTOSAR Adaptive Platform 사양을 기반으로 합니다.
