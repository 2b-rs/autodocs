자동으로 생성된 설명, 참조된 AUTOSAR R25-11 문서(SWS 사양 및 관련 표준 문서)에서 파생된 콘텐츠 — 공식 AUTOSAR 텍스트가 아닙니다. 해석으로 표시된 진술은 출처에서 도출된 결론이다.

클라이언트 대화의 런타임 모델

Conversation는 특정 진단 클라이언트와 진단 서버의 관계를 나타내며 런타임 시 동적으로 생성됩니다. 클라이언트는 UDS 소스 주소와 globalChannelId [SWS_DM_00421]의 튜플로 식별됩니다. 서버는 여러 대화를 병렬로 관리할 수 있습니다. 제공되는 Conversation 인스턴스 수는 maxConversations이며, 구성이 없으면 [SWS_DM_00840]가 적용됩니다.

가시적 상태와 병렬성

인터페이스는 활동, 진단 세션, 보안 수준 및 식별자를 표시하고 Notifier을 통해 상태 변경을 보고할 수 있습니다. 기본 세션 작업에서는 병렬 클라이언트 요청이 가능합니다. 클라이언트가 기본이 아닌 세션으로 전환하면 해당 대화는 독점적인 UDS 컨텍스트 SWS Diagnostics §7.3.2.1.1 “Multiple Client Handling”가 됩니다. 따라서 애플리케이션은 상태 쿼리를 순간적인 관찰로 처리하고 Notifier을 변경의 결과로 처리해야 합니다.

수명주기는 첫 번째 UDS 요청으로 시작된다. 기본이 아닌 세션에서는 대화가 시간 초과되거나 중단될 때까지 대화가 유지된다. 출처: SWS Diagnostics §7.3.2.1.2 “Life-cycle of a Diagnostic Conversation”, [SWS_DM_00842], [SWS_DM_00843]. 부분 해석: 표현은 설명된 최종 조건을 압축한다.

구체적으로 세션 재설정

ResetToDefaultSession는 즉시 취소를 요청하지 않습니다. DM이 먼저 현재 요청을 종료한 후 Default Session [SWS_DM_00842]로 전환합니다. 대화가 끝나면 ActivityStatus가 kInactive [SWS_DM_00843]로 설정됩니다. 활동, 세션 또는 보안 알리미를 다시 설정하면 이전 등록을 덮어씁니다. 따라서 Callback 수명은 해당 대화의 소유권을 따라야 합니다.

오류 처리 및 정상적인 세션 종료

GetActivityStatus() 또는 GetDiagnosticSession()와 같은 conversation 조회는 상태를 ara::core::Result로 반환합니다. 필수 Diagnostic Manager 기능을 사용할 수 없으면 오류 DiagErrc::kServiceNotAvailable가 반환되며, 호출 애플리케이션은 부분 진행 없이 또는 롤백 의미 체계로 이 경로를 처리합니다 [SWS_DM_00694], [SWS_DM_00696]. 따라서 반환값은 도메인 오류 경로로 검사해야 하며 유효한 상태값으로 계속 사용해서는 안 됩니다.

취소 또는 타임아웃으로 conversation이 종료되면 Diagnostic Manager는 activity 상태를 kInactive로 설정하고 등록된 activity notifier를 통해 변경을 알립니다 [SWS_DM_00843], [SWS_DM_00695]. 애플리케이션 로직에서 비활성 callback은 관찰의 끝을 표시하며, 이 conversation에서 후속 요청을 도출하지 않습니다. 다시 등록하면 이전에 구성된 notifier가 대체됩니다 [SWS_DM_01355].
