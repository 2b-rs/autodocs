컨텍스트

인터페이스 클래스 apext::sm::PowerStateInterface은(는) 전력 상태 조율을 위한 State Management(SM)와 기본 운영체제 간의 기능적 연결을 정의합니다 [SWS_SM_71000]. Adaptive Platform 내에서 이 클래스는 State Management가 전역 또는 플랫폼별 전력 상태 전환에 대한 요청을 운영체제로 위임할 수 있도록 하는 추상화 계층 역할을 합니다 [SWS_SM_71001]. 동시에 전용 콜백 메커니즘을 통해 시스템의 웨이크업 신호를 수신할 수 있도록 합니다 [SWS_SM_71003].

이 조율에는 주로 세 가지 역할이 관여합니다: 제어 인스턴스로서의 State Management, 중개자 역할을 하는 인터페이스 클래스 apext::sm::PowerStateInterface, 그리고 실제 하드웨어 및 상태 전이를 실행하는 OS 래퍼 또는 운영체제 자체입니다 AUTOSAR_AP_SWS_StateManagement §C.1.2 “Class: PowerStateInterface”.

컨텍스트 다이어그램: 전력 상태 조율에 관여하는 컴포넌트. 출처: [SWS_SM_71000], [SWS_SM_71001], [SWS_SM_71003].

수명 주기

전력 상태 조율은 기본적인 플랫폼 서비스와 관련되므로, apext::sm::PowerStateInterface의 인스턴스화는 State Management 초기화 시점에 수행됩니다 [SWS_SM_71000]. 전체 활성 운영 시간 동안 요청을 수신하고 처리할 수 있도록, 인스턴스의 수명은 일반적으로 State Management 데몬의 프로세스 수명 주기에 연계될 것으로 추정됩니다.

내부 수명 주기와 관련하여, 인터페이스는 알림에 대해 기본적으로 두 가지 작동 단계를 구분합니다:

  • 등록 상태: RegisterWakeUpHandler을(를) 성공적으로 호출한 후에는 OS 래퍼에 알림 함수가 등록되어, 이를 통해 State Management에 웨이크업 이벤트가 전달됩니다 [SWS_SM_71003].
  • 미등록 상태: UnregisterWakeUpHandler 호출을 통해 OS 래퍼에서 콜백이 제거되므로, 이후의 웨이크업 이벤트는 이 핸들러에 더 이상 신호를 발생시키지 않습니다 [SWS_SM_71005].

동시성과 관련하여, 클래스의 모든 멤버 함수(RegisterWakeUpHandler, SetPowerState 및 UnregisterWakeUpHandler)는 스레드 안전하지 않음(not-threadsafe)으로 명시적으로 지정되어 있습니다 AUTOSAR_AP_SWS_StateManagement §C.1.2.1.1 “Member Functions”. 따라서 동시 스레드로부터의 호출은 호출자에 의해 직렬화되거나 전용 실행 컨텍스트로 제한되어야 합니다.

사용 경로

일반적인 사용 경로는 콜백 함수의 등록, 운영체제로의 상태 요청 전달, 그리고 종료 전이나 재구성 시의 최종 등록 취소를 포함합니다:

  1. 웨이크업 핸들러 등록: 유휴 상태를 시작하기 전에, State Management는 RegisterWakeUpHandler을(를) 사용하여 apext::sm::WakeUpHandler 형식의 함수 포인터 또는 함수 객체를 등록합니다 [SWS_SM_71003]. 이를 통해 웨이크업 발생 시 SM에 알리도록 OS 래퍼에 지시합니다.
  2. 전력 상태 요청: State Management는 원하는 목표 상태(apext::sm::PowerState)와 함께 SetPowerState을(를) 통해 전환을 요청합니다 [SWS_SM_71001]. 이 함수는 해당 요청을 운영체제에 동기적으로 전달합니다.
  3. 웨이크업 알림 처리: 운영체제가 깨어나면 OS 래퍼는 이전에 등록된 handler을(를) 실행하며 [SWS_SM_71003], 이를 통해 State Management는 웨이크업 로직을 시작할 수 있습니다.
  4. 핸들러 등록 취소: 웨이크업 메커니즘이 더 이상 필요하지 않거나 컴포넌트를 종료해야 하는 경우, State Management는 UnregisterWakeUpHandler을(를) 사용하여 콜백 등록을 취소합니다 [SWS_SM_71005].

시퀀스 다이어그램: 핸들러 등록, 상태 요청, 웨이크업 알림 및 등록 취소의 일반적인 순서. 출처: [SWS_SM_71001], [SWS_SM_71003], [SWS_SM_71005].

<h4>수명 주기</h4>
<p>전력 상태 조율은 기본적인 플랫폼 서비스와 관련되므로, <code>apext::sm::PowerStateInterface</code>의 인스턴스화는 State Management 초기화 시점에 수행됩니다 <a class="spec-record-ref" data-req="SWS_SM_71000" href="../spec/record.html?id=SWS_SM_71000">[SWS_SM_71000]</a>. 전체 활성 운영 시간 동안 요청을 수신하고 처리할 수 있도록, 인스턴스의 수명은 일반적으로 State Management 데몬의 프로세스 수명 주기에 연계될 것으로 추정됩니다.</p>

<p>내부 수명 주기와 관련하여, 인터페이스는 알림에 대해 기본적으로 두 가지 작동 단계를 구분합니다:</p>
<ul>
<li><strong>등록 상태:</strong> <code>RegisterWakeUpHandler</code>을(를) 성공적으로 호출한 후에는 OS 래퍼에 알림 함수가 등록되어, 이를 통해 State Management에 웨이크업 이벤트가 전달됩니다 <a class="spec-record-ref" data-req="SWS_SM_71003" href="../spec/record.html?id=SWS_SM_71003">[SWS_SM_71003]</a>.</li>
<li><strong>미등록 상태:</strong> <code>UnregisterWakeUpHandler</code> 호출을 통해 OS 래퍼에서 콜백이 제거되므로, 이후의 웨이크업 이벤트는 이 핸들러에 더 이상 신호를 발생시키지 않습니다 <a class="spec-record-ref" data-req="SWS_SM_71005" href="../spec/record.html?id=SWS_SM_71005">[SWS_SM_71005]</a>.</li>
</ul>

<p>동시성과 관련하여, 클래스의 모든 멤버 함수(<code>RegisterWakeUpHandler</code>, <code>SetPowerState</code> 및 <code>UnregisterWakeUpHandler</code>)는 스레드 안전하지 않음(<code>not-threadsafe</code>)으로 명시적으로 지정되어 있습니다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=165">AUTOSAR_AP_SWS_StateManagement §C.1.2.1.1 “Member Functions”</a>. 따라서 동시 스레드로부터의 호출은 호출자에 의해 직렬화되거나 전용 실행 컨텍스트로 제한되어야 합니다.</p>

<h4>사용 경로</h4>
<p>일반적인 사용 경로는 콜백 함수의 등록, 운영체제로의 상태 요청 전달, 그리고 종료 전이나 재구성 시의 최종 등록 취소를 포함합니다:</p>

<ol>
<li><strong>웨이크업 핸들러 등록:</strong> 유휴 상태를 시작하기 전에, State Management는 <code>RegisterWakeUpHandler</code>을(를) 사용하여 <code>apext::sm::WakeUpHandler</code> 형식의 함수 포인터 또는 함수 객체를 등록합니다 <a class="spec-record-ref" data-req="SWS_SM_71003" href="../spec/record.html?id=SWS_SM_71003">[SWS_SM_71003]</a>. 이를 통해 웨이크업 발생 시 SM에 알리도록 OS 래퍼에 지시합니다.</li>
<li><strong>전력 상태 요청:</strong> State Management는 원하는 목표 상태(<code>apext::sm::PowerState</code>)와 함께 <code>SetPowerState</code>을(를) 통해 전환을 요청합니다 <a class="spec-record-ref" data-req="SWS_SM_71001" href="../spec/record.html?id=SWS_SM_71001">[SWS_SM_71001]</a>. 이 함수는 해당 요청을 운영체제에 동기적으로 전달합니다.</li>
<li><strong>웨이크업 알림 처리:</strong> 운영체제가 깨어나면 OS 래퍼는 이전에 등록된 <code>handler</code>을(를) 실행하며 <a class="spec-record-ref" data-req="SWS_SM_71003" href="../spec/record.html?id=SWS_SM_71003">[SWS_SM_71003]</a>, 이를 통해 State Management는 웨이크업 로직을 시작할 수 있습니다.</li>
<li><strong>핸들러 등록 취소:</strong> 웨이크업 메커니즘이 더 이상 필요하지 않거나 컴포넌트를 종료해야 하는 경우, State Management는 <code>UnregisterWakeUpHandler</code>을(를) 사용하여 콜백 등록을 취소합니다 <a class="spec-record-ref" data-req="SWS_SM_71005" href="../spec/record.html?id=SWS_SM_71005">[SWS_SM_71005]</a>.</li>
</ol>

<h4>오류 시나리오</h4>
<p>인터페이스에 지정된 세 메서드는 모두 반환 형식이 <code>void</code>이며 <code>noexcept</code> 사양으로 선언되어 있습니다 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=165">AUTOSAR_AP_SWS_StateManagement §C.1.2.1.1 “Member Functions”</a>:</p>
<ul>
<li><strong>예외 안전성:</strong> 각 함수는 예외 안전(<code>exception safe</code>)으로 분류되어 있습니다 <a class="spec-record-ref" data-req="SWS_SM_71001" href="../spec/record.html?id=SWS_SM_71001">[SWS_SM_71001]</a>, <a class="spec-record-ref" data-req="SWS_SM_71003" href="../spec/record.html?id=SWS_SM_71003">[SWS_SM_71003]</a>, <a class="spec-record-ref" data-req="SWS_SM_71005" href="../spec/record.html?id=SWS_SM_71005">[SWS_SM_71005]</a>. 핸들러 등록 시나 상태 변경 전송 시 모두 C++ 예외가 발생하지 않습니다.</li>
<li><strong>오류 신호:</strong> 반환 코드나 <code>ara::core::Result</code> 형식이 반환되지 않으므로, 이 인터페이스 클래스 수준에서는 직접적인 오류 처리나 실패한 OS 전이에 대한 직접 호출자로의 피드백이 수행되지 않습니다.</li>
<li><strong>사전 조건:</strong> 메서드가 스레드 안전하지 않으므로, 보호되지 않은 동시 접근은 정의되지 않은 동작으로 이어집니다. 또한 전달된 <code>apext::sm::WakeUpHandler</code> 형식의 콜백은 <code>UnregisterWakeUpHandler</code>을(를) 통해 등록이 취소될 때까지 유효성을 유지해야 할 것으로 추정됩니다 <a class="spec-record-ref" data-req="SWS_SM_71005" href="../spec/record.html?id=SWS_SM_71005">[SWS_SM_71005]</a>.</li>
</ul>
