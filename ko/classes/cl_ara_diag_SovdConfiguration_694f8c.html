명시적으로 모델링된 SOVD 구성 리소스를 응용 프로그램 측에서 제공하고 처리하는 데 사용됩니다.

인터페이스 ara::diag::SovdConfiguration은 Diagnostic Server가 수신 읽기 및 쓰기 접근을 전달하는, 명시적으로 모델링된 SOVD 구성을 위한 일반 핸들러 역할을 합니다 [SWS_DM_01860], [SWS_DM_01787]. 포트 기반 인스턴스화 후 응용 프로그램은 Offer을 통해 메시지 수신을 활성화하고 필요한 경우 StopOffer로 이를 종료합니다 [SWS_DM_01872], [SWS_DM_01930]. 데이터 제공은 읽기 또는 쓰기 세션을 통해 비동기식으로 수행되며, 기술적 오류는 ISO 17978-3 또는 ASAM SOVD 1.1에 따라 신호화됩니다 [SWS_DM_01870].

컨텍스트

인터페이스 ara::diag::SovdConfiguration은 Adaptive AUTOSAR 진단 아키텍처 내에서 명시적으로 모델링된 SOVD 구성 핸들러를 위한 일반 인터페이스를 정의합니다 [SWS_DM_01860]. 시스템에 최소 하나의 SOVD 구성이 구성되어 있는 경우, Diagnostic Management (DM)의 Diagnostic Server 인스턴스는 외부에 ASAM SOVD에 따른 표준화된 SOVD 메서드 Retrieve List of All Configurations Provided by the Entity를 제공합니다 [SWS_DM_01429]. 이러한 명시적 구성에 대해 수신되는 읽기 및 쓰기 접근은 Diagnostic Server가 ara::diag::SovdConfiguration의 구체적인 구현으로 전달합니다. 즉, SOVD 메서드 Read Configuration이 호출되면 Diagnostic Server는 RequestGetConfiguration 메서드를 호출하고 [SWS_DM_01787], Write Configuration이 호출되면 RequestPutConfiguration 메서드가 실행됩니다 [SWS_DM_01788].

컨텍스트 다이어그램: 외부 SOVD 클라이언트, Diagnostic Server (DM) 및 응용 프로그램별 핸들러 간의 ara::diag::SovdConfiguration 임베딩. 출처: [SWS_DM_01429], [SWS_DM_01787], [SWS_DM_01788], [SWS_DM_01860].

수명 주기

ara::diag::SovdConfiguration의 인스턴스화는 ara::core::InstanceSpecifier을 전달하고 ConcurrencyType(kConcurrent 또는 kNotConcurrent)을 지정함으로써 응용 프로그램 측에서 수행됩니다 [SWS_DM_01864]. InstanceSpecifier은 프로세스 컨텍스트 [SWS_DM_01864]에서 DiagnosticSovdConfigurationInterface의 포트 프로토타입을 참조합니다. 이 클래스는 복사할 수 없으며(복사 생성자와 복사 할당 연산자가 delete로 선언됨) [SWS_DM_01866], [SWS_DM_01868], 보호된 이동 작업을 지원합니다 [SWS_DM_01867], [SWS_DM_01869]. Diagnostic Server로부터 요청을 수신하려면 응용 프로그램이 명시적으로 Offer을 호출해야 합니다 [SWS_DM_01872]. StopOffer을 호출하면 요청 전달이 다시 비활성화됩니다 [SWS_DM_01930]. 가상 소멸자 [SWS_DM_01865]을 통해 인스턴스가 소멸될 때 객체가 해제되며, 해제 시에는 핸들러가 사전에 적절히 등록 취소되어 있어야 합니다.

상태 다이어그램: 초기화부터 Offer 상태 및 StopOffer까지의 SovdConfiguration 인스턴스 생명주기 단계. 출처: [SWS_DM_01864], [SWS_DM_01872], [SWS_DM_01930], [SWS_DM_01865].

사용 경로

일반적인 사용 경로는 파생된 핸들러 클래스의 생성 후 Offer()을 사용하여 Diagnostic Management에 등록하는 것으로 시작됩니다 [SWS_DM_01872]. 외부 클라이언트가 엔터티에 SOVD 구성 요청을 보내는 즉시 Diagnostic Server가 이를 전달합니다. 읽기 요청 시 RequestGetConfiguration가 호출되며, 이때 configurationId, metaInfo 및 CancellationHandler이 전달됩니다 [SWS_DM_01870]. 이 메서드는 비동기식으로 DataTransferReadSession과 SovdConfigurationMetaInfo의 튜플을 제공하는 ara::core::Future을 반환합니다 [SWS_DM_01870]. 마찬가지로 서버는 DataTransferWriteSession와 SovdConfigurationMetaInfo을 포함하는 Future를 제공하는 RequestPutConfiguration을 통해 쓰기 요청을 전달합니다 [SWS_DM_01871]. 핸들러를 종료하기 전에 응용 프로그램은 더 이상 요청을 받지 않도록 StopOffer()을 호출합니다 [SWS_DM_01930].

시퀀스 다이어그램: 초기화, Read-Configuration 요청 처리 및 후속 등록 취소 시의 일반적인 상호작용 순서. 출처: [SWS_DM_01872], [SWS_DM_01787], [SWS_DM_01870], [SWS_DM_01930].

오류 시나리오

생성자에서의 인스턴스화 시점에 이미 모델 및 매핑 위반이 발생할 수 있는데, 이는 모델에서 InstanceSpecifier을 확인할 수 없거나(InstanceSpecifierMappingIntegrityViolation), 참조된 포트 프로토타입이 DiagnosticSovdConfigurationInterface로 타입화되지 않았거나(PortInterfaceMappingViolation), 일치하는 프로세스가 존재하지 않거나(ProcessMappingViolation), 현재 프로세스에서 식별자가 이미 사용 중인 경우(InstanceSpecifierAlreadyInUseViolation)에 해당합니다 [SWS_DM_01864]. Offer()을 호출할 때 메서드는 ara::core::Result<void>을 반환하며, 구성이 DEXT 모델과 일치하지 않는 경우 오류 시 DiagOfferErrc::kConfigurationMismatch를 보고하거나 서비스가 이미 제공 중인 경우 DiagOfferErrc::kAlreadyOffered을 보고합니다 [SWS_DM_01872]. 비동기 핸들러 메서드 RequestGetConfiguration 및 RequestPutConfiguration에서 응용 프로그램은 ISO 17978-3 또는 ASAM SOVD 1.1에 따른 표준화된 SOVD 오류 코드를 사용하여 ara::core::Future을 통해 오류 상태를 보고합니다 [SWS_DM_01870], [SWS_DM_01871]. 또한 CancellationHandler은 진행 중인 통신이 중단되었는지 여부를 알립니다 [SWS_DM_01870], [SWS_DM_01871].

이 가이드는 전적으로 AUTOSAR Adaptive Platform 릴리스 R25-11의 사양을 기반으로 합니다.

사용

ara::diag::SovdConfiguration 클래스의 Offer 메서드는 Diagnostic Management(DM)에 의해 구성된 핸들러로 진단 요청이 전달되는 것을 활성화하는 데 사용됩니다 [SWS_DM_01872]. 호출은 동기식으로 수행되며 매개변수를 받지 않고 ara::core::Result<void>을(를) 통해 결과를 반환합니다 [SWS_DM_01872]. 핸들러가 Offer을(를) 통해 제공되지 않은 한 DM은 들어오는 요청을 전달하지 않으며, 이는 진단 인터페이스의 기본 제공 패턴과 일치합니다([SWS_DM_01525], [SWS_DM_00809] 참조).

오류 처리

오류가 발생하면 열거형 DiagOfferErrc의 오류 코드가 포함된 ara::core::Result이(가) 반환되며 이때 롤백 시맨틱이 적용됩니다 [SWS_DM_01872]:

  • DiagOfferErrc::kAlreadyOffered: 서비스가 이미 이전에 제공된 경우 보고됩니다 [SWS_DM_01872].
  • DiagOfferErrc::kConfigurationMismatch: 구성이 DEXT 설명 데이터와 일치하지 않을 때 발생합니다 [SWS_DM_01872].

동시성 및 제약사항

이 작업은 noexcept(으)로 선언되어 있고 예외 안전(exception safe)하지만, 스레드 안전하지 않음(not thread-safe)으로 지정되어 있습니다 [SWS_DM_01872]. 여러 스레드에서 동일한 인스턴스를 동시에 호출하는 것은 호출 애플리케이션에 의해 방지되어야 합니다. 이미 제공된 후 다시 호출하면 상태 변경 없이 오류로 처리될 것으로 보입니다.

      사용
      

      ara::diag::SovdConfiguration 클래스의 순수 가상 메서드 RequestGetConfiguration은(는) 명시적으로 모델링된 SOVD 구성에 대해 SOVD 메서드 \"Read Configuration\"이 실행될 때 Diagnostic Server Instance에 의해 호출됩니다([SWS_DM_01787], AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 “Configuration – Explicit Configurations”). 매개변수로는 읽을 인스턴스의 구성 ID(configurationId), 요청 메타 정보(metaInfo), 그리고 진행 중인 대화의 중단 가능성을 알리는 cancellationHandler이(가) 전달됩니다([SWS_DM_01870]).
      

      이 함수는 비동기식으로 작동하며, 파일 읽기 세션(DataTransferReadSession)과 관련 구성 메타 정보(SovdConfigurationMetaInfo)의 튜플을 제공하는 ara::core::Future을(를) 반환합니다([SWS_DM_01870]). 인터페이스는 noexcept(으)로 선언되어 있으며 예외 안전하도록 지정되어 있습니다([SWS_DM_01870]).
      

      오류 처리 및 동시성
      

      처리 중 오류가 발생하면 C++ 오류가 발생하는 대신 Future을(를) 통해 ISO 17978-3 또는 ASAM SOVD 1.1에 따른 해당 SOVD 오류 코드가 반환됩니다([SWS_DM_01870]).
      

      스레드 안전성과 관련하여 \"conditional\" 규격이 적용됩니다. 함수의 구체적인 구현을 스레드 안전하게 설계해야 하는지 또는 스레드 안전하지 않게 설계해야 하는지는 생성자에 전달된 ConcurrencyType에 의해 결정됩니다([SWS_DM_01870]).
