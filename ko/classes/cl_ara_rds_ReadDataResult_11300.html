컨텍스트

ara::rds::ReadDataResult 구조체는 AUTOSAR Adaptive Platform의 rds(Raw Data Stream) 모듈에서 읽기 작업을 위한 결과 및 데이터 전달 객체 역할을 합니다. 주요 책임은 읽기 작업 시 반환된 데이터 버퍼를 실제로 전송된 바이트 수와 함께 타입 안전하고 번들화된 형태로 호출자에게 전달하는 것입니다. 이 구조체는 헤더 파일 ara/rds/raw_data_stream.h에 정의되어 있습니다 [SWS_RDS_11301].

주요 상호작용 파트너로는 읽기 작업을 통해 데이터를 제공하고 ara::rds::ReadDataResult을(를) 인스턴스화하는 rds 모듈의 스트리밍 인프라와, 읽기 결과를 수신하여 추가로 처리하는 컨슈머 Adaptive 애플리케이션이 있습니다.

수명 주기

ara::rds::ReadDataResult의 수명 주기는 읽기 작업의 실행과 직접 결합되어 있습니다. 인스턴스화는 원시 데이터 스트림에 대한 읽기 작업의 반환값으로 이루어집니다. 기반 메모리의 소유권은 std::unique_ptr<ara::core::Byte[]>(으)로 선언된 필드 data을(를) 통해 규율됩니다 [SWS_RDS_11301]. 일반적인 해석에 따르면 이 스마트 포인터 타입은 ara::rds::ReadDataResult에 대해 이동 전용 시맨틱을 강제합니다. 따라서 구조체는 이동될 수 있지만 복사될 수는 없으며, 이를 통해 동적으로 할당된 버퍼의 독점적 소유권이 호출자에게 이전됩니다.

파괴는 RAII(Resource Acquisition Is Initialization) 패턴을 따릅니다. ara::rds::ReadDataResult 인스턴스가 유효 범위를 벗어나는 즉시, 사전에 std::move을(를) 통해 소유권이 다른 버퍼 수신자에게 이전되지 않았다면 할당된 바이트 버퍼는 std::unique_ptr의 소멸자에 의해 자동으로 할당 해제됩니다. 동시성과 관련하여 이 구조체는 순수 데이터 컨테이너로서 내부 동기화 메커니즘을 갖지 않습니다. 여러 스레드에서 접근할 경우 동기화는 애플리케이션 소프트웨어에 의해 외부적으로 보장되어야 합니다.

사용 경로

원시 데이터를 수신하고 처리하기 위한 전형적인 사용 경로는 다음 단계들을 포함합니다:

  1. 읽기 작업 시작: Adaptive 애플리케이션이 ara/rds/raw_data_stream.h에 따른 스트림 인터페이스의 인스턴스에서 읽기 작업을 호출합니다 [SWS_RDS_11301].
  2. 결과 객체 수신: 작업이 성공적으로 완료되면 결과가 이동 시맨틱을 통해 ara::rds::ReadDataResult 인스턴스 형태로 호출자에게 반환됩니다.
  3. 길이 및 포인터 확인: 애플리케이션이 데이터 버퍼 data의 유효한 바이트 수를 결정하기 위해 [SWS_RDS_11302]에서 numberOfBytes 필드를 읽습니다 [SWS_RDS_11301].
  4. 원시 데이터 처리: 버퍼 data에 포함된 원시 데이터가 numberOfBytes 경계까지 평가되며, 예를 들어 프로토콜 파서로 전달되거나 애플리케이션 자체 데이터 구조로 변환됩니다.
  5. 메모리 전달 또는 해제: 후속 처리 단계에서 버퍼가 지속적으로 필요한 경우 std::move을(를) 통해 data을(를) 추출할 수 있으며, 그렇지 않은 경우 버퍼는 유효 범위 종료 시 자동으로 해제됩니다.

오류 시나리오

ara::rds::ReadDataResult을 다룰 때는 다음과 같은 사전 조건, 사후 조건 및 예외 상황에 유의해야 합니다:

  • 빈 읽기 결과: numberOfBytes이 0의 값을 가지는 경우[SWS_RDS_11302], 작업 중에 바이트가 수신되지 않았음을 의미합니다(예: 스트림 끝에 도달했거나 대기 중인 데이터가 없는 비차단 읽기 호출 시). 이 상태에서 타당한 해석에 따르면 data은 nullptr로 존재하거나 평가 가능한 페이로드가 없는 버퍼를 가리킬 것으로 추정됩니다.
  • 접근 시 버퍼 오버플로: data은 std::unique_ptr 내의 배열 포인터로 타입이 지정되어 있으므로[SWS_RDS_11301], 자동 범위 검사가 존재하지 않습니다. 인덱스 값 numberOfBytes을 초과하여 접근하면[SWS_RDS_11302] 정의되지 않은 동작(버퍼 오버플로)이 발생합니다.
  • Move 연산 후 접근: data 필드가 std::move을 통해 추출된 경우, 포인터는 nullptr 상태로 유지됩니다. 사전 null 검사 없이 data을 이후에 역참조하면 런타임 오류가 발생합니다.
