State Management가 논리 및 물리 네트워크의 통신 상태를 요청하고 모니터링할 수 있도록 합니다.

ara::nm::NetworkHandle은 State Management가 인스턴스 식별자를 통해 네트워크의 통신 상태를 요청하고 모니터링할 수 있도록 하는 이동 가능하고 복사 불가능한 접근 객체를 나타냅니다 [SWS_ANM_01000], [SWS_ANM_01001]. 동기식 상태 쿼리 외에도 이 클래스는 요구사항 설정과 유효 상태 또는 요청된 상태에 대한 알림자(Notifier) 등록을 지원합니다 [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]. 이때 서비스 가용성 누락 또는 결함이 있는 알림자는 결과 객체의 표준화된 오류 코드를 통해 보고됩니다.

컨텍스트

ara::nm::NetworkHandle 클래스는 nm 모듈에서 포트 프로토타입의 ara::core::InstanceSpecifier를 통해 주소 지정되는 특정 논리 또는 물리 네트워크 핸들을 위한 표준화된 접근 객체 역할을 합니다 [SWS_ANM_01000], [SWS_ANM_01001]. 이 인터페이스의 기본 사용자는 핸들을 통해 Partial Network Cluster(PNC), VLAN 또는 물리 네트워크에 대한 통신 요구를 등록하고 모니터링하는 기능적 State Management(SM)입니다 [SWS_ANM_01000], [SWS_ANM_01009]. 중개 계층으로서 이 객체는 요청하는 기능 그룹과 기본 NM 서브시스템 간의 상호작용을 캡슐화합니다.

컨텍스트 다이어그램: State Management와 네트워크 관리 간의 NetworkHandle 임베딩. 출처: [SWS_ANM_01000], [SWS_ANM_01001], [SWS_ANM_01009], [SWS_ANM_01010], [SWS_ANM_01020], [SWS_ANM_01007]

수명 주기

ara::nm::NetworkHandle은 NetworkManagementPortInterface에 대한 유효한 ara::core::InstanceSpecifier을 지정하여 명시적으로 인스턴스화되며, 이 생성자는 스레드 안전(thread-safe)한 것으로 명세되어 있습니다 [SWS_ANM_01001]. 인스턴스는 독점 시맨틱을 가집니다. 복사 생성자와 복사 할당 연산자는 명시적으로 삭제되었습니다(= delete) [SWS_ANM_01005], [SWS_ANM_01006]. 이 클래스는 이동 생성자 및 이동 할당을 통해 이동 시맨틱을 지원하지만, 할당은 스레드 안전하지 않습니다 [SWS_ANM_01003], [SWS_ANM_01004].

소멸은 스레드 안전하지 않은 소멸자 ~NetworkHandle() [SWS_ANM_01002]을 통해 수행됩니다. 유효하지 않은 컨텍스트에 대한 비동기 접근을 방지하기 위해 소멸 전 등록된 알림자는 애플리케이션에 의해 등록 해제되어야 할 것으로 보입니다(해석). 네트워크 상태와 관련하여 핸들은 열거형 NetworkStateType를 통해 두 가지 기본 단계를 매핑합니다: kNoCom(할당된 네트워크 중 하나 이상이 전체 통신 상태에 있지 않음) 및 kFullCom(할당된 모든 네트워크가 활성 상태임) [SWS_ANM_01358].

사용 경로

일반적인 절차에는 인스턴스화, 선택적 알림자 등록, 네트워크 상태 요청 및 후속 해제가 포함됩니다:

  • 인스턴스화: 인스턴스 식별자 [SWS_ANM_01001]을 사용한 핸들 생성.
  • 관찰자 등록: RegisterNetworkStateChangeNotifier [SWS_ANM_01010]을 통한 실제 유효 상태 또는 RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]를 통한 요청된 상태에 대해 NetworkStateChangeNotifier [SWS_ANM_01020] 타입의 콜백 함수 등록. 두 메서드 모두 사용자 정의 실행 컨텍스트(ExecutorT)를 지정하기 위한 템플릿 변형으로도 존재합니다 [SWS_ANM_01014], [SWS_ANM_01015]. 핸들당 범주별로 최대 하나의 알림자만 활성화될 수 있습니다.
  • 상태 요청: SetNetworkRequestedState [SWS_ANM_01009]을 통한 전체 통신(NetworkStateType::kFullCom) 또는 해제(NetworkStateType::kNoCom) 요청.
  • 상태 쿼리: GetNetworkRequestedState [SWS_ANM_01008]을 사용한 현재 요청된 상태 또는 GetNetworkState [SWS_ANM_01007]을 사용한 실제 유효 네트워크 상태의 동기식 읽기. 두 쿼리 모두 스레드 안전합니다.
  • 정리: UnregisterNetworkStateChangeNotifier [SWS_ANM_01011] 및 UnregisterNetworkRequestedStateChangeNotifier [SWS_ANM_01013]을 통한 콜백 핸들러의 명시적 등록 해제.

시퀀스 다이어그램: 알림자 등록, 상태 요청 및 쿼리를 위한 전형적인 사용 경로. 출처: [SWS_ANM_01001], [SWS_ANM_01007], [SWS_ANM_01009], [SWS_ANM_01010]

오류 시나리오

NetworkHandle의 메서드 호출은 ara::core::Result을 통해 오류를 알립니다. 다음과 같은 오류 사례가 명세되어 있습니다:

  • NmErrc::kServiceNotAvailable: 기본 네트워크 관리 서비스를 사용할 수 없거나 응답하지 않는 경우 SetNetworkRequestedState [SWS_ANM_01009], GetNetworkRequestedState [SWS_ANM_01008] 및 GetNetworkState [SWS_ANM_01007]에서 발생합니다.
  • NmErrc::kInvalidHandler: 유효하지 않은 핸들러 함수가 전달되거나 이미 알림자가 등록되어 있는 경우 알림자 등록 메서드에서 반환됩니다 [SWS_ANM_01010], [SWS_ANM_01012], [SWS_ANM_01014], [SWS_ANM_01015].

동시성과 관련하여 읽기 상태 쿼리 GetNetworkState 및 GetNetworkRequestedState은 스레드 안전(thread-safe)하지만, 수정 연산 및 등록은 스레드 안전하지 않으며 외부 동기화가 필요합니다 [SWS_ANM_01007], [SWS_ANM_01008], [SWS_ANM_01009], [SWS_ANM_01010].
