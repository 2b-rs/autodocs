애플리케이션이 특정 데이터 식별자에 대한 진단 읽기 및 쓰기 요청에 응답할 수 있도록 합니다.

인터페이스 <DataIdentifier-Namespace>::<DataIdentifierInterface>은(는) Adaptive Applications가 Diagnostic Management [SWS_DM_00585]에 모델별 진단 데이터 식별자를 제공할 수 있도록 지원합니다. 생성 후 Offer()은(는) 요청 전달을 활성화하며, 이러한 요청은 Read() 또는 Write()을(를) 통해 비동기적으로 처리되고 필요한 경우 UDS 오류 코드로 응답됩니다 [SWS_DM_00599] [SWS_DM_00640]. 인스턴스는 복사나 이동이 모두 불가능하므로 소멸 전에 StopOffer()을(를) 통해 서비스를 명시적으로 종료합니다 [SWS_DM_01665] [SWS_DM_00600].

컨텍스트

C++ 클래스 <DataIdentifier-Namespace>::<DataIdentifierInterface>은(는) Adaptive Platform SWS Diagnostics 68쪽의 diag 모듈에서 진단 데이터 식별자(Data Identifiers, DID)를 위한 기능 인터페이스 역할을 합니다. 이는 적응형 애플리케이션 계층을 중앙 Diagnostic Management(DM)와 연결합니다. Diagnostic Management는 외부 진단 요청을 수신하여 등록된 인스턴스로 전달합니다 [SWS_DM_00599]. 애플리케이션 소프트웨어는 파생 클래스를 통해 읽기 또는 쓰기 연산으로 데이터 콘텐츠를 쿼리하거나 업데이트하는 구체적인 구현을 제공합니다 [SWS_DM_00640] [SWS_DM_00598].

수명 주기

생성은 ara::core::InstanceSpecifier 및 동시성 모드 ara::diag::ConcurrencyType을(를) 전달하는 매개변수화된 생성자를 통해 이루어집니다 [SWS_DM_00585]. 후자는 인스턴스에 대한 호출이 동시(kConcurrent) 또는 비동시(kNotConcurrent)로 처리될 수 있는지를 정의합니다 [SWS_DM_00585]. 인스턴스는 모델 구성에 고정 바인딩되어 있으므로 복사 생성자와 이동 생성자가 모두 명시적으로 삭제되었습니다 [SWS_DM_01665] [SWS_DM_01666]. 복사 및 이동 할당 연산자도 마찬가지입니다 [SWS_DM_01663] [SWS_DM_01664].

인스턴스화 후 인터페이스는 비활성 상태에 있습니다. Offer()을(를) 호출해야 비로소 Diagnostic Management에 의한 진단 요청 전달이 활성화됩니다 [SWS_DM_00599]. 메서드 StopOffer()은(는) 이러한 전달을 다시 종료합니다 [SWS_DM_00600]. 리소스 해제는 가상 소멸자 [SWS_DM_00586]을(를) 통해 이루어집니다. 해석: 객체가 소멸되기 전에 DM의 진행 중이거나 새로 들어오는 전달을 질서 있게 방지하기 위해 일반적으로 StopOffer()이(가) 호출될 것으로 보입니다.

사용 경로

정규 흐름에는 인스턴스화, 서비스 등록, 비동기 요청 처리 및 후속 비활성화가 포함됩니다.

  1. 인스턴스화: 애플리케이션은 InstanceSpecifier 및 원하는 ConcurrencyType 설정을 지정하여 인터페이스 인스턴스를 생성합니다 [SWS_DM_00585].
  2. 서비스 활성화: 애플리케이션이 Offer()을(를) 호출하면 Diagnostic Management가 이 핸들러에 요청을 전달할 수 있습니다 [SWS_DM_00599].
  3. 요청 처리: 읽기 접근 시 DM은 순수 가상 메서드 Read()을(를) 호출하고 [SWS_DM_00640], 쓰기 접근 시에는 Write()을(를) 호출합니다 [SWS_DM_00598]. 전달된 cancellationHandler을(를) 통해 애플리케이션은 취소 이벤트를 모니터링할 수 있습니다. 결과는 비동기적으로 ara::core::Future(으)로 제공되며, 이는 Read() 시 출력 데이터를 포함하는 ReadOutput 객체를 포함합니다 [SWS_DM_00579] [SWS_DM_00640] [SWS_DM_80013].
  4. 서비스 종료: StopOffer()을(를) 호출하면 객체가 소멸되기 전에 [SWS_DM_00586] 전달이 중지됩니다 [SWS_DM_00600].

시퀀스 다이어그램: 초기화부터 비동기 요청 응답을 거쳐 비활성화에 이르는 DID 제공의 전형적인 흐름. 출처: [SWS_DM_00585], [SWS_DM_00599], [SWS_DM_00640], [SWS_DM_00600], [SWS_DM_00586].

오류 시나리오

객체 생성 단계에서 이미 모델링 오류로 인해 위반이 발생할 수 있습니다. 포트 또는 프로세스 연결이 누락된 경우 InstanceSpecifierMappingIntegrityViolation, PortInterfaceMappingViolation 또는 ProcessMappingViolation이(가) 발생합니다 [SWS_DM_00585]. 동일한 프로세스 내에서 동일한 InstanceSpecifier이(가) 재사용되면 프레임워크는 InstanceSpecifierAlreadyInUseViolation을(를) 보고합니다 [SWS_DM_00585].

서비스가 이미 제공되고 있음에도 Offer()을(를) 호출하면 호출이 실패하고 ara::core::Result을(를) 통해 오류 코드 DiagOfferErrc::kAlreadyOffered을(를) 반환합니다 [SWS_DM_00599]. Read() 또는 Write()의 실행이 실패하면 구현은 ISO 14229-1 UDS 오류 코드(DiagUdsNrcErrc) 또는 애플리케이션별 ApApplicationError을(를) 사용하여 Future에서 비동기적으로 오류를 전달합니다 [SWS_DM_00640] [SWS_DM_00598]. 예외 안전성과 관련하여 생성자 및 처리 메서드는 exception safe로 명시되어 있는 반면 [SWS_DM_00585] [SWS_DM_00599] [SWS_DM_00640] [SWS_DM_00598], 소멸자는 exception safe로 지정되어 있지 않습니다 [SWS_DM_00586].

이 가이드는 Adaptive Platform용 AUTOSAR 사양(Release R25-11)을 기반으로 합니다.

사용

생성자 함수 <DataIdentifierInterface>은(는) ara::core::InstanceSpecifier에서 데이터 식별자를 인스턴스화하는 데 사용됩니다 [SWS_DM_00585]. 선언은 네임스페이스 <DataIdentifier-Namespace> 내에서 헤더 파일 #include "<DataIdentifierDirectoryPath>/<DataIdentifierShortname>.h"을(를) 통해 이루어집니다 [SWS_DM_00585]. 동기 호출은 noexcept(으)로 명시되어 있으며 “exception safe” 및 “thread-safe” 특성을 갖습니다 [SWS_DM_00585].

이 함수는 다음과 같은 전달 매개변수를 받습니다 [SWS_DM_00585]:

  • instanceSpec (ara::core::InstanceSpecifier): 서비스의 구체적인 인스턴스 식별자 [SWS_DM_00585].
  • concurrencyType (ara::diag::ConcurrencyType): 인터페이스를 kConcurrent(으)로 스레드 안전하게 작동할지, 아니면 kNotConcurrent(으)로 스레드 안전하지 않게 작동할지를 정의합니다 [SWS_DM_00585].

오류 처리 및 모델링 규칙

이 함수는 반환값을 제공하지 않으며 예외를 발생시키지 않습니다. 대신 구성 또는 모델링 오류가 발생하면 정의된 Violation이 발생합니다 [SWS_DM_00585]:

  • InstanceSpecifierMappingIntegrityViolation: Executable 컨텍스트에서 instanceSpec을(를) 확인할 수 없거나 PortPrototype을(를) 가리키지 않습니다 [SWS_DM_00585].
  • PortInterfaceMappingViolation: DiagnosticDataIdentifierInterface에 의해 유형화된 PortPrototype이(가) DiagnosticDataPortMapping에 의해 참조되지 않습니다 [SWS_DM_00585].
  • ProcessMappingViolation: 인스턴스 참조에 대해 현재 런타임 프로세스에 일치하는 모델링된 프로세스가 존재하지 않습니다 [SWS_DM_00585].
  • InstanceSpecifierAlreadyInUseViolation: 생성자가 현재 프로세스에서 이미 사용 중인 instanceSpec(으)로 호출되었습니다 [SWS_DM_00585].

해석: 함수가 noexcept(으)로 선언되어 있으므로 감지된 Violation은 프레임워크 내부에서 치명적인 초기화 오류로 처리될 것으로 추정됩니다.

동시성

생성자 함수 자체는 스레드 안전하게 구현되어 있습니다 [SWS_DM_00585]. 인수 concurrencyType을(를) 통해 인스턴스의 후속 인터페이스 호출을 동시에 수행할 수 있는지 여부가 제어됩니다 [SWS_DM_00585].

본 사용 지침은 명세를 기반으로 자동 생성되었습니다.
