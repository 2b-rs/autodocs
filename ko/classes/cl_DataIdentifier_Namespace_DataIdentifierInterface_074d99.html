컨텍스트

C++ 클래스 <DataIdentifierInterface>은 AUTOSAR Adaptive Platform의 diag 모듈에서 ISO 14229-1(UDS)에 따른 진단 데이터 식별자(Data Identifier, DID)를 위한 서버 측 기본 인터페이스 역할을 합니다. 이 인터페이스는 플랫폼의 진단 관리와 진단 데이터의 제공 또는 업데이트를 위한 애플리케이션별 루틴 간의 표준화된 브리지를 정의합니다.

상호작용에는 일반적으로 세 가지 핵심 컴포넌트가 관여합니다:

  • Diagnostic Manager (DM): 외부 진단 테스터로부터 UDS 서비스 요청(예: 서비스 0x22 ReadDataByIdentifier 또는 서비스 0x2E WriteDataByIdentifier)을 수신하고 이를 적절하게 등록된 인터페이스 인스턴스로 전달합니다([SWS_DM_00599], [SWS_DM_00600]).
  • 애플리케이션 핸들러: 구체적인 Adaptive 애플리케이션 클래스는 <DataIdentifierInterface>에서 파생되어 순수 가상 메서드 Read([SWS_DM_00640]) 및 Write([SWS_DM_00598])을 구현합니다.
  • 진단 테스터 (클라이언트): 차량 제어 장치로 UDS 요청을 전송하고 Diagnostic Manager가 취합한 응답을 수신합니다.

컨텍스트 다이어그램: 진단 테스터, Diagnostic Manager 및 <DataIdentifierInterface> 간의 상호작용. 출처: [SWS_DM_00599], [SWS_DM_00600], [SWS_DM_00640], [SWS_DM_00598]

수명 주기

인스턴스 생성은 ara::core::InstanceSpecifier 및 ara::diag::ConcurrencyType 모드를 전달하는 매개변수화된 생성자를 통해 수행됩니다([SWS_DM_00585]). Concurrency 유형을 통해 호출자는 구현이 동시성 안전(kConcurrent)으로 설계되었는지 또는 동시성에 안전하지 않은 것(kNotConcurrent)으로 설계되었는지를 명시합니다([SWS_DM_00585]).

<DataIdentifierInterface>의 인스턴스는 고유한 식별성을 가지며 복사되거나 이동될 수 없습니다. 따라서 복사 생성자([SWS_DM_01665])와 이동 생성자([SWS_DM_01666])는 물론 관련 할당 연산자([SWS_DM_01663], [SWS_DM_01664])도 모두 삭제됩니다(=delete).

서비스 상태와 관련하여 클래스는 두 단계를 구분합니다:

  • 비활성 (제공되지 않음): 생성 후 객체는 로컬에 존재하지만 진단 요청을 수락하지 않습니다.
  • 활성 (제공됨): 메서드 Offer()([SWS_DM_00599])을 명시적으로 호출해야만 Diagnostic Manager에 의한 해당 인스턴스로의 요청 전달이 활성화됩니다.
  • 비활성화됨: StopOffer()([SWS_DM_00600]) 호출을 통해 전달이 중단되고, 인스턴스는 다시 비활성 상태로 전환됩니다.

소멸은 가상 소멸자 ~<DataIdentifierInterface>()([SWS_DM_00586])을 통해 이루어집니다. 이는 스레드 안전하지 않고 예외 안전하지도 않으므로, 소멸 전에 Diagnostic Manager에서 보류 중인 전달을 정돈된 방식으로 종료하기 위해 추정컨대 StopOffer()를 호출해야 합니다.

사용 경로

진단 읽기 요청의 제공 및 처리를 위한 정규 흐름은 정의된 단계 순서를 따릅니다:

  1. 생성: 애플리케이션은 파생된 DID 클래스를 인스턴스화하고 instanceSpec을 통해 이를 모델링된 포트 프로토타입과 연결합니다([SWS_DM_00585]).
  2. 제공: 애플리케이션은 Offer()을 호출합니다([SWS_DM_00599]). 이 메서드는 Diagnostic Manager에 대한 등록 성공 여부를 나타내는 ara::core::Result<void>를 반환합니다.
  3. 처리: Diagnostic Manager에 이 DID에 대한 UDS 읽기 요청이 수신되면, DM은 해당 호출을 가상 메서드 Read(metaInfo, cancellationHandler)([SWS_DM_00640])으로 위임합니다. 쓰기 요청의 경우 DM은 마찬가지로 Write(..., metaInfo, cancellationHandler)를 호출합니다([SWS_DM_00598]).
  4. 취소 처리 및 반환: 비동기 실행 중에 구현은 cancellationHandler.IsCanceled()을 통해 대화가 취소되었는지 확인하거나 cancellationHandler.SetNotifier(...)을 통해 노티파이어를 등록할 수 있습니다([SWS_DM_00640], [SWS_DM_00598]). 결과는 ara::core::Future로 제공되며, 성공 시 출력 인수([SWS_DM_00579], [SWS_DM_80013])를 포함하는 생성된 출력 객체 <DataIdentifier>ReadOutput를 포함합니다.
  5. 등록 취소: 서비스가 더 이상 필요하지 않으면 애플리케이션은 StopOffer()을 호출합니다([SWS_DM_00600]).

시퀀스 다이어그램: Offer, Read 및 StopOffer를 통한 UDS 읽기 요청의 흐름. 출처: [SWS_DM_00599], [SWS_DM_00640], [SWS_DM_00600]

오류 시나리오

오류는 초기화 시점, 서비스 제공 시점 및 메서드 처리 중에 발생할 수 있습니다:

  • 생성 위반: 모델에서 InstanceSpecifier의 확인 또는 바인딩이 실패하면 프레임워크는 정의된 위반([SWS_DM_00585])을 발생시킵니다:
    • InstanceSpecifierMappingIntegrityViolation: 실행 파일의 컨텍스트에서 식별자를 확인할 수 없거나 PortPrototype을 참조하지 않습니다.
    • PortInterfaceMappingViolation: DiagnosticDataIdentifierInterface에 의해 유형화된 PortPrototype이 DiagnosticDataPortMapping에 의해 참조되지 않습니다.
    • ProcessMappingViolation: 런타임에 기존 InstanceRef에 일치하는 모델링된 프로세스가 존재하지 않습니다.
    • InstanceSpecifierAlreadyInUseViolation: 해당 프로세스 내에서 InstanceSpecifier이 이미 다른 생성자 호출에 의해 사용되고 있습니다.
  • Offer 시 오류: 서비스가 이미 제공된 경우 Offer()이 실패하고 오류 코드 ara::diag::DiagOfferErrc::kAlreadyOffered를 포함하는 ara::core::Result을 반환합니다([SWS_DM_00599]).
  • 처리 및 UDS 오류: 읽기 또는 쓰기 요청을 성공적으로 실행할 수 없는 경우, 핸들러는 반환되는 ara::core::Future을 ISO 14229-1에 따른 ara::diag::DiagUdsNrcErrc을 통한 해당 Negative Response Code(NRC) 또는 ApApplicationError로 설정합니다([SWS_DM_00640], [SWS_DM_00598]).

</ul>

<h4>수명 주기</h4>
<p>인스턴스 생성은 <code>ara::core::InstanceSpecifier</code> 및 <code>ara::diag::ConcurrencyType</code> 모드를 전달하는 매개변수화된 생성자를 통해 수행됩니다(<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>). Concurrency 유형을 통해 호출자는 구현이 동시성 안전(<code>kConcurrent</code>)으로 설계되었는지 또는 동시성에 안전하지 않은 것(<code>kNotConcurrent</code>)으로 설계되었는지를 명시합니다(<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</p>
<p><code>&lt;DataIdentifierInterface&gt;</code>의 인스턴스는 고유한 식별성을 가지며 복사되거나 이동될 수 없습니다. 따라서 복사 생성자(<a class="spec-record-ref" data-req="SWS_DM_01665" href="../spec/record.html?id=SWS_DM_01665">[SWS_DM_01665]</a>)와 이동 생성자(<a class="spec-record-ref" data-req="SWS_DM_01666" href="../spec/record.html?id=SWS_DM_01666">[SWS_DM_01666]</a>)는 물론 관련 할당 연산자(<a class="spec-record-ref" data-req="SWS_DM_01663" href="../spec/record.html?id=SWS_DM_01663">[SWS_DM_01663]</a>, <a class="spec-record-ref" data-req="SWS_DM_01664" href="../spec/record.html?id=SWS_DM_01664">[SWS_DM_01664]</a>)도 모두 삭제됩니다(<code>=delete</code>).</p>
<p>서비스 상태와 관련하여 클래스는 두 단계를 구분합니다:</p>
<ul>
<li><strong>비활성 (제공되지 않음):</strong> 생성 후 객체는 로컬에 존재하지만 진단 요청을 수락하지 않습니다.</li>
<li><strong>활성 (제공됨):</strong> 메서드 <code>Offer()</code>(<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>)을 명시적으로 호출해야만 Diagnostic Manager에 의한 해당 인스턴스로의 요청 전달이 활성화됩니다.</li>
<li><strong>비활성화됨:</strong> <code>StopOffer()</code>(<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>) 호출을 통해 전달이 중단되고, 인스턴스는 다시 비활성 상태로 전환됩니다.</li>
</ul>
<p>소멸은 가상 소멸자 <code>~&lt;DataIdentifierInterface&gt;()</code>(<a class="spec-record-ref" data-req="SWS_DM_00586" href="../spec/record.html?id=SWS_DM_00586">[SWS_DM_00586]</a>)을 통해 이루어집니다. 이는 스레드 안전하지 않고 예외 안전하지도 않으므로, 소멸 전에 Diagnostic Manager에서 보류 중인 전달을 정돈된 방식으로 종료하기 위해 추정컨대 <code>StopOffer()</code>를 호출해야 합니다.</p>

<h4>사용 경로</h4>
<p>진단 읽기 요청의 제공 및 처리를 위한 정규 흐름은 정의된 단계 순서를 따릅니다:</p>
<ol>
<li><strong>생성:</strong> 애플리케이션은 파생된 DID 클래스를 인스턴스화하고 <code>instanceSpec</code>을 통해 이를 모델링된 포트 프로토타입과 연결합니다(<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>).</li>
<li><strong>제공:</strong> 애플리케이션은 <code>Offer()</code>을 호출합니다(<a class="spec-record-ref" data-req="SWS_DM_00599" href="../spec/record.html?id=SWS_DM_00599">[SWS_DM_00599]</a>). 이 메서드는 Diagnostic Manager에 대한 등록 성공 여부를 나타내는 <code>ara::core::Result&lt;void&gt;</code>를 반환합니다.</li>
<li><strong>처리:</strong> Diagnostic Manager에 이 DID에 대한 UDS 읽기 요청이 수신되면, DM은 해당 호출을 가상 메서드 <code>Read(metaInfo, cancellationHandler)</code>(<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>)으로 위임합니다. 쓰기 요청의 경우 DM은 마찬가지로 <code>Write(..., metaInfo, cancellationHandler)</code>를 호출합니다(<a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>).</li>
<li><strong>취소 처리 및 반환:</strong> 비동기 실행 중에 구현은 <code>cancellationHandler.IsCanceled()</code>을 통해 대화가 취소되었는지 확인하거나 <code>cancellationHandler.SetNotifier(...)</code>을 통해 노티파이어를 등록할 수 있습니다(<a class="spec-record-ref" data-req="SWS_DM_00640" href="../spec/record.html?id=SWS_DM_00640">[SWS_DM_00640]</a>, <a class="spec-record-ref" data-req="SWS_DM_00598" href="../spec/record.html?id=SWS_DM_00598">[SWS_DM_00598]</a>). 결과는 <code>ara::core::Future</code>로 제공되며, 성공 시 출력 인수(<a class="spec-record-ref" data-req="SWS_DM_00579" href="../spec/record.html?id=SWS_DM_00579">[SWS_DM_00579]</a>, <a class="spec-record-ref" data-req="SWS_DM_80013" href="../spec/record.html?id=SWS_DM_80013">[SWS_DM_80013]</a>)를 포함하는 생성된 출력 객체 <code>&lt;DataIdentifier&gt;ReadOutput</code>를 포함합니다.</li>
<li><strong>등록 취소:</strong> 서비스가 더 이상 필요하지 않으면 애플리케이션은 <code>StopOffer()</code>을 호출합니다(<a class="spec-record-ref" data-req="SWS_DM_00600" href="../spec/record.html?id=SWS_DM_00600">[SWS_DM_00600]</a>).</li>
</ol>

<h4>오류 시나리오</h4>
<p>오류는 초기화 시점, 서비스 제공 시점 및 메서드 처리 중에 발생할 수 있습니다:</p>
<ul>
<li><strong>생성 위반:</strong> 모델에서 <code>InstanceSpecifier</code>의 확인 또는 바인딩이 실패하면 프레임워크는 정의된 위반(<a class="spec-record-ref" data-req="SWS_DM_00585" href="../spec/record.html?id=SWS_DM_00585">[SWS_DM_00585]</a>)을 발생시킵니다:
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>: 실행 파일의 컨텍스트에서 식별자를 확인할 수 없거나 PortPrototype을 참조하지 않습니다.</li>
  <li><code>PortInterfaceMappingViolation</code>: <code>DiagnosticDataIdentifierInterface</code>에 의해 유형화된 PortPrototype이 <code>DiagnosticDataPortMapping</code>에 의해 참조되지 않습니다.</li>
  <li><code>ProcessMappingViolation</code>: 런타임에 기존 <code>InstanceRef</code>에 일치하는 모델링된 프로세스가 존재하지 않습니다.</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>: 해당 프로세스 내에서 <code>InstanceSpecifier</code>이 이미 다른 생성자 호출에 의해 사용되고 있습니다.</li>
