컨텍스트

apext::diag::uds_transport::UdsTransportProtocolPeriodicHandler 클래스는 모듈 diag AUTOSAR_AP_SWS_Diagnostics §C.3 “Header: apext/diag/uds_transport/protocol_periodic_handler.h”에 속한 AUTOSAR Adaptive Platform의 특화된 인터페이스입니다. 이 클래스는 전송 프로토콜 [SWS_DM_01064] 수준에서 UDS 서비스 0x2A("ReadDataByPeriodicIdentifier")를 표준화된 방식으로 지원하는 역할을 합니다.

진단 아키텍처 내에서 이 클래스는 상위 진단 관리와 구체적인 전송 연결 사이를 매개합니다. 주요 역할은 주기적 전송을 위한 채널별 용량 제한을 제공하고 주기적 진단 메시지의 정렬된 시퀀스를 하위 네트워크에 일괄 전달하는 것입니다. 관련된 상호작용 파트너는 다음과 같습니다:

  • UDS 서비스 핸들러(0x2A): 측정값의 주기적 판독을 제어하고 주기적 전송 프로세스를 시작합니다.
  • 전송 프로토콜 핸들러: 인터페이스의 구체적인 파생 클래스로서 프로토콜별 전송을 구현합니다(예: DoIP 경유).
  • 전송 채널(ChannelID): 주기적 메시지가 전송되는 구체적인 논리적 또는 물리적 연결을 나타냅니다 [SWS_DM_01066].

  4. 확인 처리: 전송 프로세스가 완료된 후 결과를 알리기 위해 확인("PeriodicTransmit Confirmation")이 호출됩니다 [SWS_DM_01067].

오류 시나리오

인터페이스의 모든 메서드가 noexcept이므로 오류는 C++ 예외를 통해 보고되지 않습니다. 오류 처리는 전송 프로토콜에 직접 통합되어 있습니다:

  • 단일 오류 시 전송 중단: 전달된 목록 내에서 단일 메시지의 전송이 실패하면 이후의 모든 전송 프로세스가 즉시 중단됩니다 [SWS_DM_01067]. 목록의 후속 메시지는 더 이상 전송되지 않습니다.
  • 확인을 통한 오류 피드백: 오류가 발생한 경우에도 PeriodicTransmit Confirmation이 호출됩니다 [SWS_DM_01067]. 이 확인은 중단 시점까지 성공적으로 전송된 메시지의 정확한 수와 원래 메시지 목록을 매개변수로 받습니다. 호출자는 전달된 수를 기반으로 어느 인덱스에서 오류가 발생했는지 정확하게 식별하고 필요한 경우 대응 조치를 취할 수 있습니다.
  • 사전 조건 위반: PeriodicTransmit에는 반환값이 없으므로(void), 호출자는 channelId이(가) 유효하고 메시지 크기가 GetMaxPayloadLength을(를) 통해 보고된 한계값을 준수하는지 사전에 확인해야 합니다 [SWS_DM_01066], [SWS_DM_01067].
