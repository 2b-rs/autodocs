AUTOSAR Adaptive를 위한 타입 안전한 범위 검사 기능을 갖춘 고정 크기 순차 컨테이너를 제공합니다.

템플릿 클래스 ara::core::Array은 T 타입 요소를 위한 순차적 고정 크기 컨테이너 역할을 하며, AUTOSAR Adaptive Platform 애플리케이션을 위해 std::array의 동작을 적응시킵니다. 호출자는 고정된 요소 수로 컨테이너를 초기화하고, fill()과 같은 메서드를 통해 콘텐츠를 조작하며, 선택적으로 operator[]를 통해 검사 없이 또는 at()를 통해 범위 검사를 거쳐 [SWS_CORE_01273]에 접근합니다. 안전 관련 제약 조건으로서 at()에서 범위를 벗어나는 경우 std::out_of_range 대신 특정 위반인 IsoStdOutOfRangeViolation이 발생하지만, 비어 있는 인스턴스에서 front() 또는 back()을 호출하면 이미 컴파일 타임에 실패합니다 [SWS_CORE_01267].

컨텍스트

템플릿 클래스 ara::core::Array은 T 타입 요소를 위해 컴파일 타임에 정적으로 고정된 크기 N을 갖는 순차 컨테이너를 캡슐화합니다. 이는 AUTOSAR Adaptive Platform의 core 모듈에서 표준화된 타입 std::array을 구현하며 연속된 메모리 블록을 위한 타입 안전한 추상화를 제공합니다. value_type([SWS_CORE_01216]), size_type([SWS_CORE_01214]), difference_type([SWS_CORE_01215])와 같은 표준화된 타입 별칭뿐만 아니라 포인터 타입([SWS_CORE_01217], [SWS_CORE_01218]) 및 참조 타입([SWS_CORE_01210], [SWS_CORE_01211])을 제공함으로써, 이 클래스는 일반적인 C++ 알고리즘 및 플랫폼 내부 데이터 흐름을 위한 상호 운용 가능한 상호 작용 파트너로 기능합니다.

수명 주기

Array 인스턴스의 생성 및 소멸은 애그리게이트 및 값 타입에 대한 표준 규칙을 따릅니다. ISO C++ 표준의 암시적으로 선언된 특수 멤버 함수가 사용되며 별도로 재선언되지 않습니다. Array는 동일한 메모리 영역 내에 인라인으로 요소를 직접 소유합니다. 따라서 포함된 요소의 수명은 이를 둘러싼 Array 객체의 수명과 불가분하게 연결됩니다. 힙(자유 저장소)에서의 동적 할당은 발생하지 않는 것으로 추정되며, 이는 결정론적인 시간 및 메모리 동작을 보장합니다.

컨테이너는 항상 유효한 상태에 있으며 정확히 N개의 요소를 관리합니다. Array가 요소를 수용할 수 있는지 또는 특수한 경우로서 N = 0 상태인지 여부는 empty()([SWS_CORE_01264]), size()([SWS_CORE_01262]) 및 max_size()([SWS_CORE_01263])을 통해 평가할 수 있습니다. 동시성과 관련하여, 동기화 없는 동시 읽기 접근은 안전하지만 병렬 쓰기 수정에는 호출자에 의한 외부 조정이 필요한 것으로 간주됩니다.

사용 경로

일반적인 사용 사례에서 ara::core::Array은 초기화, 요소 채우기, 임의 또는 순차 접근, 그리고 필요한 경우 콘텐츠 교환의 순서를 거칩니다:

  • 초기화 및 채우기: 전체 데이터 버퍼를 fill()([SWS_CORE_01241])을 통해 지정된 값으로 균일하게 채울 수 있습니다.
  • 임의 접근: 고성능 접근을 위해 검사되지 않는 인덱스 연산자 operator[]([SWS_CORE_01265], [SWS_CORE_01266])을 사용할 수 있습니다. 범위 검사가 필요한 경우에는 at()([SWS_CORE_01273], [SWS_CORE_01274])이 사용됩니다.
  • 경계 요소: 첫 번째 및 마지막 요소에 대한 직접 접근은 front()([SWS_CORE_01267], [SWS_CORE_01268]) 및 back()([SWS_CORE_01269], [SWS_CORE_01270])을 통해 수행됩니다.
  • 반복: 컨테이너 순회는 begin() 및 end()([SWS_CORE_01250], [SWS_CORE_01251], [SWS_CORE_01252], [SWS_CORE_01253])을 통해 정방향으로 수행되거나 cbegin() 및 cend()([SWS_CORE_01258], [SWS_CORE_01259])과 같은 상수 반복자를 통해 수행됩니다. 반복자 타입은 기본 포인터 T* 또는 const T*로 정의됩니다([SWS_CORE_01212], [SWS_CORE_01213]). 역방향 순회를 위해 rbegin(), rend(), crbegin() 및 crend()이 제공됩니다([SWS_CORE_01254], [SWS_CORE_01255], [SWS_CORE_01256], [SWS_CORE_01257], [SWS_CORE_01260], [SWS_CORE_01261], [SWS_CORE_01219], [SWS_CORE_01220]).
  • 포인터 접근 및 교환: 기본 메모리 영역은 data()([SWS_CORE_01271], [SWS_CORE_01272])을 통해 포인터로 전달될 수 있습니다. 동일한 크기의 두 Array는 swap()([SWS_CORE_01242])을 사용하여 교환할 수 있습니다.

시퀀스 다이어그램: Array 인스턴스의 채우기, 범위 검사 및 교환을 위한 일반적인 호출 순서. 출처: [SWS_CORE_01241], [SWS_CORE_01273], [SWS_CORE_01242].

오류 시나리오

사양은 경계 및 오류 상황에 대해 엄격한 사전 조건과 사후 조건을 정의합니다:

  • 인덱스 접근 시 범위 위반: at()에서 인덱스 n이 Array 경계를 벗어나는 경우(n >= size()), C++ 표준 예외 std::out_of_range 대신 IsoStdOutOfRangeViolation이 발생합니다([SWS_CORE_01273], [SWS_CORE_01274]). 두 오버로드 모두 noexcept로 선언되어 있습니다.
  • 비어 있는 인스턴스 접근: 비어 있는 Array(empty() == true, 즉 N = 0)에서 front() 또는 back()을 호출하면 의무적으로 컴파일 타임 오류(Compile-Time Error)가 발생합니다([SWS_CORE_01267], [SWS_CORE_01268], [SWS_CORE_01269], [SWS_CORE_01270]).
  • 반복자에서의 정의되지 않은 동작: 비어 있는 Array에서 begin()이 반환한 반복자를 역참조하는 것은 정의되지 않은 동작입니다([SWS_CORE_01250], [SWS_CORE_01251]).
  • 포인터 검색의 특수한 경우: Array의 크기가 0인 경우, 멤버 함수 data()은 반드시 nullptr를 반환합니다([SWS_CORE_01271], [SWS_CORE_01272]).
  • 조건부 예외 안전성: 작업 swap()은 타입 관련 조건 ara::core::is_nothrow_swappable<T>::value가 충족되는 경우에만 noexcept입니다([SWS_CORE_01242]). 마찬가지로 fill()의 noexcept 속성은 std::is_nothrow_copy_assignable<T>::value을 통해 결정됩니다([SWS_CORE_01241]).

ara::core::Array 클래스의 멤버 함수 at은 암시적 경계값 검사[SWS_CORE_01273]를 통해 지정된 위치 n의 배열 요소에 대한 동기식 읽기 및 쓰기 접근을 가능하게 합니다. 이 함수는 주소 지정된 요소에 대한 수정 가능한 참조(reference)를 반환하며 컴파일 시간에 평가될 수 있습니다(constexpr)[SWS_CORE_01273].

요청된 인덱스가 컨테이너 경계에 도달하거나 초과하는 오류의 경우(n >= size()), 표준 C++ 컨테이너 std::array과 동작이 다릅니다: std::out_of_range 타입의 예외 대신 IsoStdOutOfRangeViolation이 발생합니다[SWS_CORE_01273]. 시그니처가 noexcept로 선언되고 예외 안전한 것으로 분류되어 있으므로 일반적인 C++ 예외는 발생하지 않습니다[SWS_CORE_01273]. 해석: noexcept 컨텍스트에서 이러한 위반이 발생하면 즉시 실행의 제어된 종료로 이어질 것으로 보입니다.

읽기 전용 인스턴스의 경우 상수 참조를 제공하는 상보적인 상수 오버로드 [SWS_CORE_01274]이 존재합니다. IsoStdOutOfRangeViolation을 사용하는 동일한 오류 시맨틱은 ara::core::Vector([SWS_CORE_01354], [SWS_CORE_01355]) 및 ara::core::StringView [SWS_CORE_02133]와 같은 관련 컨테이너에도 일관되게 적용됩니다.
