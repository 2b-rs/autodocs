컨텍스트

구조체 <SI-Namespace>::proxy::methods::<Method>::Output은(는) Adaptive Platform(모듈 com)에서 클라이언트 또는 프록시 레벨([SWS_CM_99333], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”)의 메서드 호출 출력 매개변수(out 인수)를 캡슐화하는 역할을 합니다. 서비스 인터페이스 메서드가 여러 반환 값 또는 특정 출력 인수를 정의하는 경우, 플랫폼은 개별 값을 바인딩되지 않은 상태로 전송하는 대신 이러한 매개변수를 생성된 Output 구조체로 묶습니다.

상호작용에는 기본적으로 다음과 같은 컴포넌트가 관여합니다:

  • 호출 클라이언트 애플리케이션: 프록시 인스턴스를 통해 메서드 호출을 시작하고 완료 후 결과 데이터를 평가합니다.
  • 메서드 프록시: 호출 시 매개변수를 직렬화하고 통신을 시작하는 함수 객체 <SI-Namespace>::proxy::methods::<Method>입니다.
  • 반환 컨테이너: 성공 시 인스턴스화된 Output 구조체를 포함하는 ara::core::Future 객체입니다(AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”).
  • Skeleton 상대 측: 서비스 공급자 측에는 형식화된 대응물 {<hierarchical-namespace-list-lower-skeleton>}::skeleton::{<service-interface-name>}Skeleton::{<method-name>}Output([SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.4.6 “Struct: {<method-name>}Output”)이(가) 존재하며, 이는 서비스 공급자에 의해서도 Future를 통해 제공됩니다(AUTOSAR_AP_SWS_CommunicationManagement §8.4.6).

컨텍스트 다이어그램: 프록시 메서드의 호출 및 반환 경로에 Output 구조체 통합. 출처: [SWS_CM_99333], [SWS_CM_99556], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”.

수명 주기

Output 인스턴스의 수명 및 상태 관리는 상위 ara::core::Future 객체 및 비동기 통신과 밀접하게 연결되어 있습니다:

  • 생성: Output 객체는 애플리케이션 코드에 의해 수동으로 인스턴스화되지 않습니다. 서비스 공급자의 응답 메시지를 성공적으로 수신하고 역직렬화한 후 통신 계층에 의해 생성되어 해당 ara::core::Future에 배치됩니다(AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”).
  • 소유권 및 전달: 객체는 호출 애플리케이션이 get() 또는 GetResult()을(를) 통해 결과를 검색할 때까지 Future에 유지됩니다. 이 검색을 통해 Output 인스턴스는 호출 클라이언트 컨텍스트의 소유로 넘어갑니다.
  • 취소 및 파괴: 호출자가 반환된 ara::core::Future 객체를 조기에 파괴하면 해당 소멸자로 인해 메서드 호출이 취소됩니다([SWS_CM_00194], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). 이 경우 애플리케이션에 Output 인스턴스가 전달되지 않으며 처리가 폐기됩니다.

사용 경로

Output 구조체를 사용하기 위한 일반적인 흐름은 다음 단계로 나뉩니다:

  1. 메서드 호출: 애플리케이션은 정의된 입력 인수와 함께 프록시 메서드 객체 operator()(...)을(를) 호출합니다.
  2. Future 객체 수신: 호출자는 즉각적인 반환값으로 ara::core::Future<Output> 유형의 객체를 받습니다(AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”).
  3. 동기화 및 쿼리: 호출자는 동기적으로 차단하거나 비동기적으로 완료를 기다리며 get() 또는 GetResult()을(를) 통해 결과를 요청합니다([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6).
  4. 처리: 성공적으로 실행되면 애플리케이션은 Output 객체를 추출하고([SWS_CM_99333]) 여기에 포함된 출력 매개변수의 멤버 필드를 읽습니다.

시퀀스 다이어그램: 프록시 메서드 호출 및 Future 객체를 통한 Output 구조체 평가. 출처: [SWS_CM_99333], [SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”.

오류 시나리오

오류 발생 시 Output 구조체는 호출자에게 전달되지 않습니다:

  • 인프라 및 Future 오류: 메서드 호출이 실패한 경우, 결과로 반환되는 ara::core::Future에는 Output 객체가 포함되지 않고 오류 코드(예: ara::core::FutureErrc(AUTOSAR_AP_SWS_CommunicationManagement §8.3.6 “Struct: Output”) 또는 ara::com::ComErrc나 ApApplicationError(AUTOSAR_AP_SWS_CommunicationManagement §8.4.6))가 포함됩니다.
  • 검사된 애플리케이션 오류(Checked Errors): 메서드 호출 처리 중에 정의된 검사된 오류가 발생하면, 해당 ara::core::ErrorCode이(가) GetResult() 또는 get() 호출 컨텍스트에서 반환됩니다([SWS_CM_10371], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6). 이 경로에서는 Output 인스턴스가 생성되지 않습니다.
  • Fire-and-Forget 메서드: 사양에 따르면 Fire-and-Forget 호출에는 검사된 오류가 존재하지 않으며([SWS_CM_90436], AUTOSAR_AP_SWS_CommunicationManagement §7.5.22.6), 반환값이 전송되지 않으므로 이러한 메서드는 시스템 특성상 Output 구조체도 갖지 않습니다.
