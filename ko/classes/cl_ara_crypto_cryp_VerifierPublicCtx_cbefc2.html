단일 단계 또는 다단계 스트리밍 방식을 사용하는 비대칭 전자 서명 검증 기능을 제공합니다.

인터페이스 ara::crypto::cryp::VerifierPublicCtx은 원샷 호출 또는 다단계 스트리밍을 통해 비대칭 공개 키 기반의 전자 서명을 검증하는 데 사용됩니다([SWS_CRYPT_24112], [SWS_CRYPT_50022]). 검증 전에 컨텍스트는 할당된 사용 권한이 서명 검증을 허용하는 유효한 키로 반드시 구성되어야 합니다([SWS_CRYPT_24115]). 모든 인터페이스 메서드는 예외 안전 및 스레드 안전으로 설계되었습니다.

컨텍스트

인터페이스 ara::crypto::cryp::VerifierPublicCtx은 공개 키를 사용하는 비대칭 암호화 기반의 전자 서명 검증에 사용됩니다. 이 인터페이스는 키 객체([SWS_CRYPT_24115]) 또는 외부 키 저장소([SWS_CRYPT_50018])와 직접 상호작용하며, 서명을 단일 단계(원샷)로 검증하거나 여러 세부 단계로 스트리밍 검증할 수 있는 메서드를 제공합니다.

수명 주기

검증 컨텍스트의 인스턴스는 애플리케이션 내부에서 일반적으로 std::shared_ptr<VerifierPublicCtx>로 정의된 스마트 포인터 타입 에일리어스 ara::crypto::cryp::VerifierPublicCtx::Sptr을 통해 관리됩니다([SWS_CRYPT_24101]). 모든 인터페이스 메서드는 예외 안전(exception safe) 및 스레드 안전으로 선언되어 있습니다.

컨텍스트는 명확히 구분된 작동 단계를 거칩니다. 인스턴스화 후 컨텍스트는 초기화되지 않은 상태에 있으며, 이 상태에서는 ara::crypto::CryptoErrc::kUninitializedContext을 사용한 검증 호출이 거부됩니다([SWS_CRYPT_50019], [SWS_CRYPT_24112]). SetKey()을 통해 적절한 키를 할당해야만 컨텍스트가 작동 준비 상태로 전환됩니다([SWS_CRYPT_24115], [SWS_CRYPT_50018]). 이 상태에서 원자적 검증을 수행하거나 스트리밍 세션을 시작할 수 있습니다. 스트리밍 작업을 완료([SWS_CRYPT_50022])하거나 중단([SWS_CRYPT_50023])한 후 컨텍스트는 다시 새로운 검증을 위해 준비 상태가 될 것으로 보입니다.

사용 경로

서명 검증을 위해 상호 보완적인 두 가지 처리 경로를 사용할 수 있습니다:

  • 원샷 검증: 전체 메시지가 메모리에 존재하는 경우, SetKey()을 통한 키 할당([SWS_CRYPT_24115]) 후 Verify()를 직접 호출할 수 있습니다([SWS_CRYPT_24112]). 알고리즘이 애플리케이션별 컨텍스트 데이터를 지원하거나 요구하는 경우, 추가 컨텍스트 버퍼를 갖는 오버로드 변형이 사용됩니다([SWS_CRYPT_50024]). 두 변형 모두 ara::core::Result<bool>을 반환하며, 그 부울 값은 서명의 유효성을 나타냅니다.
  • 스트리밍 검증: 대용량 데이터이거나 데이터 블록이 점진적으로 도착하는 경우, SetKey() 이후에 먼저 Start()이 호출됩니다([SWS_CRYPT_50019], [SWS_CRYPT_50020]에 따른 컨텍스트 버퍼 선택 가능). 이후 데이터 프래그먼트가 Update()를 통해 반복적으로 입력됩니다([SWS_CRYPT_50021]). 개별 세그먼트의 최대 버퍼 크기는 사전에 GetMaximumChunkSize()을 통해 확인할 수 있습니다([SWS_CRYPT_50025]). 서명 및 해당 형식 식별자를 전달하는 Finish()의 호출로 완료됩니다([SWS_CRYPT_50022]). 진행 중인 스트리밍은 Cancel()을 통해 언제든지 폐기될 수 있습니다([SWS_CRYPT_50023]).

오류 시나리오

모든 상태 변경 및 검증 메서드는 ara::core::Result과 함께 동작하며 오류 발생 시 롤백 시맨틱을 갖습니다:

  • 키 구성: 알고리즘과 호환되지 않는 키 또는 KeySlot이 전달되면 SetKey()은 CryptoErrc::kIncompatibleObject 오류를 반환합니다([SWS_CRYPT_24115], [SWS_CRYPT_50018]). 키에 사용 권한 kAllowSigVerification가 없으면 호출은 CryptoErrc::kUsageViolation로 실패합니다([SWS_CRYPT_24115]). 또한 컨텍스트가 다른 형태의 키(KeySlot 또는 PublicKey)만을 허용하는 경우 SetKey()은 CryptoErrc::kUnsupported을 보고합니다.
  • 시퀀스 및 사전 조건 오류: 이전에 성공한 Start() 호출 없이 Update(), Finish() 또는 Cancel()가 호출되면 CryptoErrc::kProcessingNotStarted로 실패합니다([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_50023]). 사전에 키 참조 없이 Start() 또는 Verify()를 호출하면 CryptoErrc::kUninitializedContext이 발생합니다([SWS_CRYPT_50019], [SWS_CRYPT_24112]). 참조되었으나 비어 있는 KeySlot의 경우 CryptoErrc::kEmptyKeySlot이 보고됩니다.
  • 데이터 및 형식 오류: 유효하지 않은 버퍼 크기에 대해 메서드는 CryptoErrc::kInvalidInputSize으로 응답합니다([SWS_CRYPT_50021], [SWS_CRYPT_50022], [SWS_CRYPT_24112]). 지원되지 않는 서명 형식은 CryptoErrc::kUnsupportedFormat를 생성하며, 구조적으로 결함이 있는 서명은 CryptoErrc::kInvalidArgument를 발생시킵니다([SWS_CRYPT_50022], [SWS_CRYPT_24112]). 하드웨어 리소스가 사용 중인 경우 CryptoErrc::kBusyResource이 반환됩니다.

사용법 및 의미론

Cancel() 메서드는 이전에 Start()에 의해 시작되었으나 아직 완료되지 않은 진행 중인 스트리밍 작업을 중단합니다 [SWS_CRYPT_50023]. 이 메서드는 헤더 ara/crypto/cryp/verifier_public_ctx.h에 컨텍스트 ara::crypto::cryp::VerifierPublicCtx의 순수 가상 메서드로 정의되어 있습니다 [SWS_CRYPT_50023]. 호출은 동기적으로 매개변수 없이 수행됩니다. 반환값으로는 ara::core::Result<void>이(가) 사용되며, 이는 성공 시 비어 있고 작업의 성공적인 중단을 확인합니다 [SWS_CRYPT_50023].

오류 처리

Start() 메서드 호출을 통해 데이터 처리가 아직 시작되지 않은 경우 중단 작업이 실패합니다. 이 시나리오에서 함수는 롤백 시맨틱을 보장하면서 오류 코드 ara::crypto::CryptoErrc::kProcessingNotStarted을(를) 포함하는 오류 결과를 반환합니다 [SWS_CRYPT_50023].

동시성 및 제약사항

사양에서는 이 메서드를 noexcept 표시와 함께 스레드 안전(thread-safe) 및 예외 안전(exception safe)으로 지정합니다 [SWS_CRYPT_50023]. 해석: 성공적으로 중단된 후에는 컨텍스트가 처리 시작 전의 초기 상태로 되돌아가 새로운 스트리밍 작업을 시작할 수 있을 것으로 추정됩니다.

                                      동기식 메서드 Verify은(는) 단일 호출([SWS_CRYPT_50024])에서 사용자 정의 컨텍스트 값을 고려하여 전달된 메시지의 디지털 서명을 검증합니다. 입력 매개변수로 이 메서드는 각각 ReadOnlyMemRegion 형태의 버퍼 message, context, signature과 signatureFormat을(를) 통한 서명 형식을 기대합니다([SWS_CRYPT_50024]). 반환값은 ara::core::Result<bool>입니다. 이는 성공적인 검증 시 true, 서명이 올바르지 않은 경우 false, 또는 해당 오류 코드를 포함합니다([SWS_CRYPT_50024]).
                                      
  
                                      오류 발생 시 롤백 시맨틱이 적용됩니다([SWS_CRYPT_50024]). 특정 오류 코드는 다음을 포함합니다:
                                      
  
                                        
    
                                      • 검증 컨텍스트가 아직 키 값으로 초기화되지 않은 경우 UninitializedContext([SWS_CRYPT_50024]),
                                        • 
    
                                      • 허용되지 않는 버퍼 크기인 경우 ara::crypto::CryptoErrc::kInvalidInputSize([SWS_CRYPT_50024]),
                                        • 
    
                                      • 선택된 서명 알고리즘이 컨텍스트 값 지정을 지원하지 않는 경우 ara::crypto::CryptoErrc::kUnsupported([SWS_CRYPT_50024]),
                                        • 
    
                                      • 지정된 서명 형식이 지원되지 않거나 서명이 해당 형식과 일치하지 않는 경우 ara::crypto::CryptoErrc::kUnsupportedFormat 또는 ara::crypto::CryptoErrc::kInvalidArgument([SWS_CRYPT_50024]),
                                        • 
    
                                      • 허용된 키 사용에 kAllowSigVerification이(가) 포함되지 않는 경우 ara::crypto::CryptoErrc::kUsageViolation, 그리고 ara::crypto::CryptoErrc::kEmptyKeySlot 및 ara::crypto::CryptoErrc::kBusyResource([SWS_CRYPT_50024]).
                                        • 
  
                                      
  
                                      이 메서드는 const noexcept(으)로 선언되어 있고 예외 안전한 것으로 간주되며 thread-safe(으)로 지정되어 있습니다([SWS_CRYPT_50024]). 컨텍스트와의 상호 작용에서 개별 호출을 위한 최대 버퍼 크기는 GetMaximumChunkSize을(를) 통해 확인할 수 있습니다([SWS_CRYPT_50025]). 컨텍스트가 없는 검증을 위해서는 Verify의 대안적 오버로드가 제공됩니다([SWS_CRYPT_24112]).
