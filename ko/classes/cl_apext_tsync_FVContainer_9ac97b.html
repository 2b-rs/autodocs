Freshness Value Management를 위해 바이트 벡터 형태의 Frischewert를 정확한 비트 길이와 함께 캡슐화합니다.

apext::tsync::FVContainer 구조체는 tsync 모듈에서 애플리케이션과 Freshness Value Management 간에 Frischewert를 전달 및 반환하기 위한 데이터 컨테이너로 사용됩니다. 이 구조체는 방향에 따라 전체 값 또는 잘린 값을 포함하는 value의 바이트 벡터로서 실제 Frischewert를 캡슐화하고 [SWS_TS_14196], length 속성에 정확한 비트 길이를 캡슐화합니다 [SWS_TS_14195]. 동시 접근 시에는 호출자에 의한 외부 조정이 필요합니다.

컨텍스트

apext::tsync::FVContainer 구조체는 AUTOSAR Adaptive Platform의 tsync 기능 클러스터 내에서 Frischewert(Freshness Value)를 위한 전용 데이터 컨테이너 역할을 합니다. apext/tsync/fvm.h 헤더 파일을 통해 포함되는 이 구조체는 Freshness Value Management(FVM)와의 상호작용에서 표준화된 인터페이스 역할을 합니다. 주요 책임은 실제 암호화 Frischewert를 정확한 길이와 함께 제공하는 것입니다. 이를 위해 컨테이너는 length 데이터 요소에 비트 길이를 캡슐화하고 [SWS_TS_14195], 바이트 벡터 value에 실제 페이로드를 캡슐화합니다 [SWS_TS_14196]. 따라서 이 구조체는 호출 애플리케이션 또는 프로토콜 계층과 FVM 계산 루틴 사이의 브릿지 역할을 합니다.

수명 주기

경량 데이터 구조(struct)로서 apext::tsync::FVContainer은(는) C++의 일반적인 값 의미론을 따릅니다. 생성은 일반적으로 호출자의 스택에 로컬로 수행되거나 상위 메시지 생성 과정에서 동적으로 수행됩니다. 인스턴스화와 함께 구조체는 ara::core::Vector<std::uint8_t> 유형의 포함된 벡터 value의 수명 주기에 대한 책임을 집니다 [SWS_TS_14196]. 인터페이스 전달 시 구조체가 값 또는 참조로 전달될 것으로 추정되므로, 벡터의 RAII 원칙은 컨테이너 소멸 시 할당된 메모리의 결정론적 해제를 보장합니다. apext::tsync::FVContainer은(는) 동기화를 위한 내부 메커니즘을 제공하지 않으므로, 동시 읽기 및 쓰기 접근 시 스레드 안전한 조정은 전적으로 호출 소프트웨어 컴포넌트의 책임입니다.

사용 경로

실제 사용 시 apext::tsync::FVContainer은(는) 인터페이스 통신 내에서 두 가지 핵심 방향을 거칩니다:

  • 입력 매개변수: 수신 메시지의 검증 또는 처리 시 컨테이너는 애플리케이션에 의해 채워져 FVM 메서드로 전달됩니다. 컨텍스트에 따라 value 필드는 전체 Frischewert 또는 잘린 값(Truncated Value)을 수용합니다 [SWS_TS_14196]. 이와 병행하여 length 필드는 포함된 값의 정확한 비트 수를 지정합니다 [SWS_TS_14195]. 이는 Frischewert의 유효성이 정수 바이트 경계에서 끝나지 않을 때 특히 중요합니다.
  • 반환값: FVM에 의해 새로운(fresh) 값이 생성될 때 각 메서드는 apext::tsync::FVContainer의 인스턴스를 반환합니다. 호출 컨텍스트는 이후 length [SWS_TS_14195]을(를) 통해 FVM이 결정한 유효 비트 길이를 읽어오고, value [SWS_TS_14196]에서 해당 바이트를 추출하여 후속 보안 프로토콜에 임베드합니다.

해석: length에 저장된 비트 수는 value 벡터의 올림된 바이트 크기와 항상 대응할 것으로 추정되며, 이에 따라 길이 정보를 통해 벡터의 마지막 바이트에서 불완전하게 사용된 나머지 비트를 정밀하게 구분할 수 있습니다.
