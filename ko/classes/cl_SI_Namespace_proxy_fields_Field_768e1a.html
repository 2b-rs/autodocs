클라이언트 애플리케이션이 서비스 필드를 비동기적으로 쿼리, 수정 및 구독 모니터링할 수 있도록 합니다.

이 클래스는 ServiceInterface에 정의된 필드에 액세스하기 위한 클라이언트 측 인터페이스 역할을 하며 Getter, Setter 및 알림 기능을 묶습니다. 해당 작업이 모델링된 경우 [SWS_CM_00112] 및 [SWS_CM_00113]을 통해 값을 비동기식으로 쿼리하고 수정할 수 있습니다. 필드 업데이트에는 알림을 임시 저장하고 콜백 핸들러를 통해 전달하는 구독 기반 캐시 메커니즘이 사용됩니다. 주요 제약 조건으로는 최소 전송 간격의 준수 및 쓰기 액세스 시 롤백 시맨틱이 제공되지 않는다는 점이 있습니다.

컨텍스트

AUTOSAR Adaptive Platform의 통신 관리(ara::com)에서 클래스 <SI-Namespace>::proxy::fields::<Field>은 클라이언트 또는 프록시 측에서 서비스 인터페이스에 모델링된 개별 필드(Field)를 나타냅니다. 이 클래스는 속성 값에 대한 액세스를 묶고 현재 값 쿼리(Getter), 값 수정(Setter) 및 비동기 값 변경 수신(Notifier)의 세 가지 기능적 역할을 결합합니다(AUTOSAR_AP_EXP_ARAComAPI 10쪽). 이 클래스는 클라이언트 애플리케이션과 기본 통신 계층(네트워크 바인딩) 사이의 인터페이스 역할을 합니다.

인스턴스에서 사용할 수 있는 작업은 서비스 인터페이스 정의에 의해 결정됩니다. 메서드 Get()은 Field.hasGetter == TRUE이 구성된 경우에만 생성됩니다 [SWS_CM_00112]. 메서드 Set()은 Field.hasSetter == TRUE가 적용되는 경우에만 독점적으로 제공됩니다 [SWS_CM_00113]. 필드의 구체적인 데이터 유형은 제공된 형식 별칭 FieldType을 통해 형식 안전하게 매핑됩니다 [SWS_CM_11403].

수명 주기

필드 객체는 상위 프록시 클래스의 멤버로 인스턴스화됩니다. 따라서 해당 수명은 해당 프록시 인스턴스의 수명 주기에 직접 바인딩되는 것으로 추정됩니다. 이벤트 기반 Notifier 메커니즘을 위해 인스턴스는 명확하게 규정된 구독 수명 주기를 거칩니다:

  • 구독되지 않음: 초기에 필드는 kNotSubscribed 상태에 있습니다.
  • 구독 요청됨: Subscribe(maxSampleCount) [SWS_CM_11601]의 동기 호출을 통해 버퍼가 설정되고 등록이 시작됩니다. Notifier는 kSubscriptionPending로 전환되거나 통신 계층의 확인 후 kSubscribed으로 전환되며, 이 상태 전환은 비동기식으로 완료되는 것으로 추정됩니다.
  • 구독 종료됨: Unsubscribe() [SWS_CM_11602]에 의해 알림 스트림이 중지되고 상태가 다시 kNotSubscribed로 전환됩니다.

현재 상태는 GetSubscriptionState()을 사용하여 언제든지 동기식으로 쿼리할 수 있습니다 [SWS_CM_11604]. 상태 변경을 비동기식으로 확인하기 위해 선택적으로 전용 실행 컨텍스트 [SWS_CM_11608]와 함께 SetSubscriptionStateChangeHandler()를 사용하여 콜백을 등록할 수 있습니다 [SWS_CM_11607]. 인스턴스를 파괴하기 전이나 비활성화할 때 등록된 콜백은 UnsetReceiveHandler() [SWS_CM_11606], UnsetSubscriptionStateChangeHandler() [SWS_CM_11609] 및 UnsetTransportFaultConditionHandler() [SWS_CM_00126]을 통해 명시적으로 제거해야 합니다.

상태 다이어그램: ara::com::SubscriptionState를 통한 Notifier 구독의 수명 주기. 출처: [SWS_CM_11601], [SWS_CM_11602], [SWS_CM_11604].

사용 경로

일반적인 사용 경로는 알림 등록, 새 데이터 수신, 특정 시점의 읽기 및 쓰기 액세스로 구성됩니다:

  1. 구독 설정: 애플리케이션은 원하는 캐시 용량과 함께 Subscribe()을 호출하고 [SWS_CM_11601], SetReceiveHandler()를 사용하여 매개변수가 없는 알림 콜백을 등록합니다 [SWS_CM_11605]. 동시성 아키텍처의 경우 실행을 실행자(Executor)를 통해 위임할 수 있습니다 [SWS_CM_11611]. 또한 Notifier 이벤트에 대해 전송 오류 핸들러를 등록할 수 있습니다 [SWS_CM_00109], [SWS_CM_00110].
  2. 샘플 처리: 통신 관리가 새 필드 데이터를 수신하는 즉시 수신 핸들러를 트리거합니다. 핸들러는 GetFreeSampleCount() [SWS_CM_11603]을 통해 사용 가능한 버퍼 공간을 결정하고 GetNewSamples() [SWS_CM_11610]을 통해 새 값을 처리합니다. 수신된 알림의 E2E 상태는 GetE2EStateMachineStateNotifier()로 확인할 수 있습니다 [SWS_CM_11612].
  3. 명시적 읽기: 현재 값을 검색하는 작업은 Get() [SWS_CM_00112]을 통해 비동기식으로 수행되며 ara::core::Future<FieldType>를 반환합니다 [SWS_CM_11403]. 완료 후 GetE2EStateMachineStateGetter()로 E2E 검사 상태를 검증할 수 있습니다 [SWS_CM_00145].
  4. 명시적 쓰기: 값 수정은 Set(value) [SWS_CM_00113]을 통해 수행됩니다. 반환된 ara::core::Future<FieldType>는 Set 작업의 결과를 제공하며, 그 E2E 상태는 GetE2EStateMachineStateSetter()을 통해 읽을 수 있습니다 [SWS_CM_00146].

시퀀스 다이어그램: 알림과의 상호 작용 및 Get/Set 작업의 일반적인 흐름. 출처: [SWS_CM_00112], [SWS_CM_00113], [SWS_CM_11601], [SWS_CM_11605], [SWS_CM_11610].

오류 시나리오

필드 메서드를 사용할 때 다양한 오류 상태가 발생할 수 있습니다:

  • 통신 실패: Get() 또는 Set()에서 네트워크 전송이 실패하면 Future에 오류 ComErrc::kCommunicationFailure가 전달됩니다 [SWS_CM_00112], [SWS_CM_00113]. Get()에는 롤백 시맨틱이 적용되며, Set()에는 no_rollback_semantics이 적용되어 타임아웃 발생 시 서버에 미결정 상태가 발생할 수 있습니다 [SWS_CM_00113].
  • 전송 간격 위반: 배포에 구성된 것보다 빠르게 요청이 발행되면 ComErrc::kMinimumSendIntervalViolationError [SWS_CM_00112], [SWS_CM_00113]가 발생합니다.
  • 버퍼 한계: Subscribe()에서 메모리를 할당할 수 없는 경우 메서드는 ComErrc::kMaxSampleCountNotRealizable [SWS_CM_11601]를 반환합니다. GetNewSamples()에서 너무 많은 샘플을 검색하면 호출이 ComErrc::kMaxSamplesExceeded [SWS_CM_11610]로 실패합니다.
  • 액세스 및 핸들러 위반: 실행 권한이 없으면 Get(), Set() 또는 Subscribe() [SWS_CM_00112], [SWS_CM_00113], [SWS_CM_11601]에서 InsufficientPermissionsViolation이 발생합니다. 핸들러 등록에 비어 있거나 유효하지 않은 Callable 객체를 전달하면 InvalidHandlerViolation이 발생합니다 [SWS_CM_11605], [SWS_CM_11607], [SWS_CM_00109].
  • 멱등성: kSubscribed 또는 kSubscriptionPending 상태에서 동일한 버퍼 값으로 Subscribe()을 다시 호출해도 아무런 효과가 없으며 [SWS_CM_11601], 마찬가지로 활성 구독 없이 Unsubscribe()를 호출해도 효과 없이 반환됩니다 [SWS_CM_11602].

이 클래스 가이드는 AUTOSAR 사양 R25-11을 기반으로 AI에 의해 생성되었습니다.

사용

프록시 스코프 <SI-Namespace>::proxy::fields::<Field>에서 메서드 Get은 현재 필드 값의 비동기적 조회에 사용됩니다([SWS_CM_00112], AUTOSAR_AP_EXP_ARAComAPI §6 “FieldGet”도 참조). 이 함수는 프록시 헤더 <SiNamespaceDerivedDirectoryPath>/<SiShortname>_proxy.h를 통해 제공되며 해당 필드에 대해 Field.hasGetter == TRUE이 모델링된 경우에만 존재합니다([SWS_CM_00112]). 매개변수를 받지 않으며 전송 성공 후 현재 값을 포함하는 ara::core::Future<FieldType>을 반환합니다([SWS_CM_00112]).

오류 처리 및 제약 조건

이 인터페이스는 noexcept 및 예외 안전([SWS_CM_00112])으로 정의됩니다. 작업이 실패하면 반환된 ara::core::Future에는 롤백 시맨틱을 갖는 오류 코드가 포함됩니다([SWS_CM_00112]):

  • ComErrc::kCommunicationFailure: 네트워크 바인딩이 복구 가능한 통신 오류 또는 보안 통신의 실패를 보고합니다([SWS_CM_00112]).
  • ComErrc::kMinimumSendIntervalViolationError: 전송 요청이 해당 요소에 대해 구성된 최소 전송 간격(minimumSendInterval)이 허용하는 것보다 빠르게 발생했습니다([SWS_CM_00112]).
  • InsufficientPermissionsViolation: Grant Enforcement에 의해 실행이 거부되었습니다([SWS_CM_00112]).

게터(Getter)에는 애플리케이션 오류(Application Errors)가 존재하지 않습니다([SWS_CM_00113]).

상호 작용

스켈레톤 측에서 게터 요청을 처리하려면 RegisterGetHandler을 통해 등록되는 콜백이 전제되어야 합니다([SWS_CM_00114]). Get()의 각 호출은 종단 간 검사(E2E)를 수행하며, 그 결과로 나타나는 상태 상태는 프록시 측에서 GetE2EStateMachineStateGetter을 통해 동기적으로 조회할 수 있습니다([SWS_CM_00145]).
