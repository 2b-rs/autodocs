진단 요청 시 공유 메모리 영역을 통해 전체 파일 또는 디렉터리를 읽을 수 있도록 지원합니다.

ara::diag::DataTransferReadSharedDataHandler 클래스는 공유 메모리([SWS_DM_01497])를 통한 파일 및 디렉터리 내용의 읽기 진단 데이터 전송을 처리하는 데 사용됩니다. 세션이 시작된 후 애플리케이션 구현체는 Read()를 통해 전체 데이터를 공유 데이터 뷰로 제공하고, ReleaseHandler에 의한 해제 알림이 있을 때까지 할당된 버퍼를 유지합니다([SWS_DM_01504]). 핸들러 전용 객체를 소멸시키기 전에 반드시 ExitRead()를 통해 전송 세션을 종료해야 합니다. 이 객체는 단일 전송 세션 전용이므로 이동할 수는 있지만 복사할 수는 없습니다.

컨텍스트

ara::diag::DataTransferReadSharedDataHandler 클래스는 diag 모듈(AUTOSAR_AP_SWS_Diagnostics §8.10.5 “Class: DataTransferReadSharedDataHandler”) 내 AUTOSAR Adaptive Platform의 진단 영역에 속합니다. 이 클래스의 핵심 역할은 RequestReadFile 또는 RequestReadDirectory와 같은 UDS 요청에 의해 트리거된 파일 및 디렉터리 내용에 대한 데이터 전송을 처리하는 것입니다([SWS_DM_01497]). 각 전송 블록마다 개별 복사 단계를 거치는 대신, 이 핸들러를 사용하면 애플리케이션별 구현체가 전체 데이터를 연속된 공유 메모리 영역으로 제공할 수 있습니다.

전체 시스템 흐름에서 세 가지 주요 주체가 협력합니다. 외부 UDS 클라이언트가 제어기에 읽기 요청을 전송합니다. 진단 런타임 환경 AraDiag은 요청을 수신하여 DataTransferReadSharedDataHandler의 구체적인 구현체로 실행을 전달합니다([SWS_DM_01497], [SWS_DM_01504]). 세 번째 파트너인 ReleaseHandler는 플랫폼에서 공유 메모리 리소스가 더 이상 필요하지 않아 해제될 수 있는 즉시 애플리케이션에 신호를 보냅니다([SWS_DM_01504]).

컨텍스트 다이어그램: UDS 클라이언트, AraDiag 런타임 환경 및 애플리케이션 측 핸들러 구현 간의 상호작용. 출처: [SWS_DM_01497], [SWS_DM_01504], [SWS_DM_01505]

수명 주기

핸들러 생성은 매개변수가 없는 기본 생성자([SWS_DM_01498], AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.1.1 “Default Constructor”)를 통해 수행됩니다. 소유권과 관련하여 단방향 원칙이 적용됩니다. 인스턴스는 단일 파일 전송 세션에 독점적으로 바인딩되므로 핸들러를 복사해서는 안 됩니다([SWS_DM_01501], [SWS_DM_01503]). 따라서 복사 생성자(AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.2.1 “DataTransferReadSharedDataHandler”)와 복사 할당 연산자 모두 delete로 표시되어 있습니다. 인스턴스 전송은 이동 작업을 통해 가능합니다. 이동 생성자([SWS_DM_01500], AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.1.2 “Move Constructor”) 및 이동 할당 연산자([SWS_DM_01502])는 default 및 noexcept로 선언되어 있습니다.

객체 소멸에 대해 엄격한 선행 조건이 있습니다. ExitRead() 호출을 통해 전송 세션이 공식적으로 종료되기 전에는 이 클래스의 인스턴스를 절대로 소멸시켜서는 안 됩니다([SWS_DM_01499], AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.1.3 “Destructor”). 이러한 종료 처리가 완료된 후에만 가상 소멸자가 실행될 수 있습니다([SWS_DM_01499]).

동시성과 관련하여 핵심 메서드 Read() 및 ExitRead()은 스레드 안전하지 않은 것(not thread-safe)으로 식별되는 반면, 인터페이스의 모든 함수는 예외 안전성(exception safe)을 보장합니다([SWS_DM_01498], [SWS_DM_01504], [SWS_DM_01505]).

사용 경로

공유 메모리 영역을 사용한 데이터 전송의 일반적인 호출 순서는 여러 단계로 구성됩니다:

  • 공유 데이터 제공: AraDiag은 순수 가상 메서드 Read()을 호출하고 ReleaseHandler, MetaInfo 및 CancellationHandler를 전달합니다([SWS_DM_01504]). 애플리케이션은 전체 파일 또는 디렉터리 콘텐츠를 할당하고 이에 대한 공유 뷰를 ara::core::Span<ara::core::Byte>로서 ara::core::Future을 통해 AraDiag에 다시 전달합니다([SWS_DM_01504]).
  • 메모리 유지 및 해제: 애플리케이션은 메모리 영역을 안전하게 해제할 수 있음을 ReleaseHandler이 알릴 때까지 할당된 메모리를 반드시 온전하게 유지해야 합니다([SWS_DM_01504]). 애플리케이션은 이를 위해 ReleaseHandler에 알림자(notifier) 함수를 등록하거나 그 상태를 능동적으로 쿼리할 수 있습니다([SWS_DM_01504]). 해석: ReleaseHandler을 통한 신호 전달은 데이터 블록이 UDS 클라이언트에 성공적으로 전송되는 즉시 AraDiag에 의해 비동기적으로 수행될 것으로 보입니다.
  • 세션 종료: 전송을 종료하기 위해 AraDiag은 ExitRead() 메서드를 호출합니다([SWS_DM_01505], AUTOSAR_AP_SWS_Diagnostics §8.10.5.1.3.1 “ExitRead”). 종료 이유(DataTransferExitType) 외에도 차량 제조사별 요청 파라미터가 전달되며, 이 파라미터의 수명은 결과 프라미스가 충족될 때까지 보장됩니다([SWS_DM_01505]). 애플리케이션은 ara::core::Future<ara::core::Vector<ara::core::Byte>>을 통해 응답 데이터를 반환합니다([SWS_DM_01505]).
  • 객체 소멸: ExitRead()이 성공적으로 호출된 후에만 핸들러 인스턴스를 해제하고 소멸시킬 수 있습니다([SWS_DM_01499]).

시퀀스 다이어그램: Read()를 통한 데이터 제공부터 메모리 해제를 거쳐 ExitRead()를 통한 종료까지의 단계 순서. 출처: [SWS_DM_01499], [SWS_DM_01504], [SWS_DM_01505]

오류 시나리오

데이터 제공 시 또는 전송 종료 시 오류가 발생하면, ISO 14229-1에 따른 DiagUdsNrcErrc 도메인의 ara::core::ErrorCode과 함께 각 ara::core::Future을 통해 보고됩니다([SWS_DM_01504], [SWS_DM_01505]).

또 다른 시나리오는 진행 중인 진단 대화의 취소입니다. 두 메서드 모두 CancellationHandler을 수신합니다([SWS_DM_01504], [SWS_DM_01505]). 애플리케이션은 cancellation_handler.IsCanceled()을 통해 취소 상태를 동기식으로 확인하거나 조기 취소 시 즉각적으로 대응할 수 있도록 cancellation_handler.SetNotifier()를 통해 알림 함수를 등록할 수 있습니다([SWS_DM_01504], [SWS_DM_01505]).

소멸자와 관련된 선행 조건 위반(즉, ExitRead()이 호출되기 전에 객체가 소멸되는 경우)은 요구사항 [SWS_DM_01499]에 위배되며 잘못된 프로그램 상태를 초래합니다.

이 클래스 가이드는 AUTOSAR Adaptive Platform 릴리스 R25-11 사양을 기반으로 한다.

ReleaseHandler은(는) 동일한 UDS 클라이언트에 대해 MetaInfo을(를) 기반으로 저장되어야 합니다([SWS_DM_01504]). CancellationHandler을(를) 통해 진행 중인 전송을 IsCanceled()(으)로 모니터링하거나 중단 알리미를 SetNotifier()(으)로 등록할 수 있습니다([SWS_DM_01504]).
