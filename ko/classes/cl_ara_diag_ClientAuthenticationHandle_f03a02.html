진단 클라이언트의 동적 진단 권한, 세션 타이머 및 인증 철회를 관리합니다.

ara::diag::ClientAuthenticationHandle 클래스는 애플리케이션이 진단 클라이언트의 활성 인증 세션을 관리하는 데 사용됩니다[SWS_DM_01206]. 애플리케이션은 이 핸들을 통해 동적 액세스 목록을 구성하고 클라이언트의 비활성 타이머를 갱신합니다[SWS_DM_01213]. 이 객체는 복사 기능 없이 엄격한 이동 시맨틱을 따르며, 진단 관리를 사용할 수 없는 경우 DiagErrc::kServiceNotAvailable을 통해 오류를 보고합니다. Revoke 호출을 통해 부여된 역할 및 추가 권한을 언제든지 제어된 방식으로 철회할 수 있습니다.

컨텍스트

API 클래스 ara::diag::ClientAuthenticationHandle은 헤더 파일 ara/diag/client_authentication_handle.h에 정의되어 있습니다[SWS_DM_01145]. 이 클래스는 클라이언트가 성공적으로 인증되었거나 클라이언트의 기본 역할이 일시적으로 재정의되었을 때 Diagnostic Server 인스턴스에 의해 진단 애플리케이션에 제공되는 중앙 제어 객체 역할을 합니다AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”.

시스템 시작 시 클라이언트는 사전 구성된 기본 역할을 가진 채 기본적으로 kDeAuthenticated 상태에 있습니다[SWS_DM_01205], [SWS_DM_01204]. 애플리케이션이 ara::diag::ClientAuthentication::Authenticate을 호출하면 Diagnostic Server는 클라이언트를 kAuthenticated 상태로 전환하고 ara::diag::ClientAuthenticationHandle를 반환합니다[SWS_DM_01206]. 마찬가지로 역할을 일시적으로 조정하기 위해 ara::diag::ClientAuthentication::OverrideDefaultRoles을 호출할 때도 이러한 핸들이 생성됩니다[SWS_DM_01209]. 애플리케이션은 핸들을 통해 인증 상태와 동적 액세스 목록(DynamicAccessList)을 제어하며, 이 목록은 인증된 클라이언트에게 진단 익스트랙트 이외의 진단 리소스에 대한 추가 접근 권한을 부여합니다AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”.

컨텍스트 다이어그램: 애플리케이션, ClientAuthenticationHandle 및 Diagnostic Server의 상호작용. 출처: [SWS_DM_01206], [SWS_DM_01209], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”

수명 주기

ara::diag::ClientAuthenticationHandle의 인스턴스화는 일반적으로 Authenticate [SWS_DM_01206] 또는 OverrideDefaultRoles [SWS_DM_01209] 과정에서 Diagnostic Server의 팩토리 메서드에 의해 수행됩니다. 또한 이 클래스는 매개변수가 없는 기본 생성자를 제공합니다[SWS_DM_01146]. 이렇게 생성된 객체는 이동 할당을 통해 활성 핸들이 전달될 때까지 바인딩되지 않은 플레이스홀더 역할을 할 것으로 추정됩니다.

소유권과 관련하여 이 클래스는 엄격한 이동 시맨틱을 구현합니다. 이동 생성자 [SWS_DM_01148] 및 이동 할당 연산자 [SWS_DM_01149]은 noexcept = default로 정의됩니다. 복사 생성자 [SWS_DM_01150] 및 복사 할당 연산자 [SWS_DM_01151]가 삭제(=delete)되었으므로 복사는 완전히 금지됩니다. 인스턴스 해제는 소멸자 ~ClientAuthenticationHandle()을 통해 이루어집니다[SWS_DM_01147].

동시성과 관련하여 기본 생성자는 스레드 안전(thread-safe)으로 명시되어 있습니다[SWS_DM_01146]. 반면 소멸자 [SWS_DM_01147] 및 상태를 변경하는 모든 메서드 호출은 스레드 안전하지 않은 것(not thread-safe)으로 표시되어 있습니다[SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. 따라서 동일한 핸들에 대한 동시 접근에는 애플리케이션 측 동기화가 필요합니다.

사용 경로

런타임의 일반적인 흐름에는 동적 권한 구성, 권한 부여 유지 관리 및 제어된 종료가 포함됩니다:

  1. 핸들 획득: 애플리케이션은 ara::diag::ClientAuthentication에 대한 인증을 시작하고 핸들 인스턴스를 수신합니다[SWS_DM_01206].
  2. 액세스 목록 설정 또는 확장: 애플리케이션은 Set 메서드를 통해 진단 대화의 동적 액세스 목록을 완전히 교체합니다[SWS_DM_01153], [SWS_DM_01213]. 또는 Append을 통해 기존 액세스 목록에 추가 진단 패턴을 추가합니다[SWS_DM_01152], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 “DynamicAccessList Creation and Update”.
  3. 활동 갱신: 기본 세션에서 비활성 상태가 지속되면 비활성 타임아웃 경과 후 kDeAuthenticated 상태로 자동 폴백될 위험이 있습니다[SWS_DM_01210]. 애플리케이션은 Refresh를 호출하여 Authenticate 또는 OverrideDefaultRoles에 의해 시작된 타이머를 연장합니다[SWS_DM_01155], AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”.
  4. 권한 철회: 애플리케이션은 Revoke을 사용하여 클라이언트를 명시적으로 인증 해제하고, 연관된 DynamicAccessList을 삭제하며, 재정의된 기본 역할을 재설정합니다[SWS_DM_01154].

시퀀스 다이어그램: 핸들을 통한 인증, 권한 관리 및 철회 절차. 출처: [SWS_DM_01206], [SWS_DM_01153], [SWS_DM_01155], [SWS_DM_01154]

오류 시나리오

작동 메서드인 Set [SWS_DM_01153], Append [SWS_DM_01152], Refresh [SWS_DM_01155] 및 Revoke [SWS_DM_01154]은 각각 ara::core::Result<void>을 반환하며 noexcept 및 예외 안전(exception safe)으로 선언되어 있습니다.

Diagnostic Manager의 필수 기능을 현재 사용할 수 없어 통신이나 실행이 실패하는 경우, 호출은 오류 코드 DiagErrc::kServiceNotAvailable을 반환합니다[SWS_DM_01152], [SWS_DM_01153], [SWS_DM_01154], [SWS_DM_01155]. 이 경우 롤백 시맨틱이 적용되므로 클라이언트의 인증 상태나 액세스 목록에 불일치하는 부분적 변경 사항이 남지 않습니다.
