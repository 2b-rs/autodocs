지정된 네트워크 인터페이스에서 DoIP 차량 공지를 목표 지향적으로 트리거하는 역할을 합니다.

클래스 [SWS_DM_00820]은(는) Adaptive Applications가 ISO 13400-2에 따른 DoIP 차량 공지 전송을 특정 네트워크 인터페이스에서 Diagnostic Management에 명시적으로 트리거하는 데 사용됩니다. 접근은 자체 인스턴스화를 통해서가 아니라 시스템에서 제공하는 객체 참조([SWS_DM_00821])를 통해 정적으로 이루어집니다. 활성화 라인 종속 제어가 있는 인터페이스의 경우 전송이 완전 자동으로 이루어지므로 명시적 호출이 허용되지 않습니다 ([SWS_DM_00822]).

컨텍스트

클래스 ara::diag::DoIPTriggerVehicleAnnouncement([SWS_DM_00820])은(는) 헤더 ara/diag/doip_trigger_vehicle_announcement.h(AUTOSAR_AP_SWS_Diagnostics §8.36.1 “Class: DoIPTriggerVehicleAnnouncement”)에서 Adaptive Application이 DoIP 차량 공지(“Vehicle Announcement Messages”)의 목표 지향적인 전송을 트리거할 수 있는 API를 제공합니다 ([SWS_DM_00815], [SWS_DM_00822]).

ISO 13400-2에 따른 DoIP 통신에서 차량 공지 전송은 기본적으로 Diagnostic Management(DM)의 내부 작업입니다 (AUTOSAR_AP_SWS_Diagnostics §“About DiagnosticDoIPTriggerVehicleAnnouncementInterface”). DM은 기본적으로 네트워크 기동 시 다른 IP 제어기 및 게이트웨이로의 브로드캐스트로서, 그리고 외부 진단 테스터의 연결 감지 시 이 메시지들을 전송합니다 (AUTOSAR_AP_SWS_Diagnostics §“About DiagnosticDoIPTriggerVehicleAnnouncementInterface”). 그럼에도 불구하고 ara::diag::DoIPTriggerVehicleAnnouncement을(를) 통해 애플리케이션에 특정 네트워크 인터페이스에 대해 이러한 전송을 명시적으로 시작할 수 있는 기회가 제공됩니다 ([SWS_DM_00815], [SWS_DM_00820]).

컨텍스트 다이어그램: Diagnostic Manager를 통한 DoIP 차량 공지 트리거 시 상호작용 파트너. 출처: [SWS_DM_00815], [SWS_DM_00820], AUTOSAR_AP_SWS_Diagnostics §“About DiagnosticDoIPTriggerVehicleAnnouncementInterface”.

수명 주기

클래스 DoIPTriggerVehicleAnnouncement 인스턴스의 생성 및 소멸은 엄격한 요구사항의 적용을 받습니다. 기본 생성자([SWS_DM_02100])와 소멸자([SWS_DM_02101]) 모두 delete(으)로 선언되어 있으며, private이고 구체적인 형태는 제조업체에 따라 다릅니다. 따라서 애플리케이션은 이 클래스의 객체를 직접 인스턴스화하거나 소멸시킬 수 없습니다.

인터페이스 접근은 함수 GetDoIPTriggerVehicleAnnouncement()([SWS_DM_00821])을 통해 정적으로 수행됩니다. 이 함수는 ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>을(를) 반환하며, 이를 통해 호출자는 DM이 제공하는 서비스 객체에 대한 참조를 얻습니다. 해석: private 및 삭제된 생성자와 객체 참조 반환으로 인해, 이 클래스는 내부적으로 DM에 의해 수명이 긴 싱글톤으로 관리될 것으로 보입니다.

동시성 측면에서 인터페이스 쿼리 GetDoIPTriggerVehicleAnnouncement() 및 메서드 호출 TriggerVehicleAnnouncement() 모두 스레드 안전하지 않은 것(“not thread-safe”)으로 명시되어 있습니다 ([SWS_DM_00821], [SWS_DM_00822]). 따라서 여러 스레드에서의 동시 접근에는 외부 동기화가 필요합니다. 두 메서드 모두 예외 안전(“exception safe”)으로 지정되어 있습니다 ([SWS_DM_00821], [SWS_DM_00822]).

사용 경로

DoIP 차량 공지를 요청하는 일반적인 절차는 다음 단계로 구성됩니다:

  1. 인스턴스 가져오기: 애플리케이션이 정적으로 ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement()을(를) 호출합니다 ([SWS_DM_00821]).
  2. 결과 평가: 결과로 나온 ara::core::Result의 오류 여부를 확인하고, 성공 시 참조를 언패킹합니다.
  3. 공지 요청: 메서드 TriggerVehicleAnnouncement(networkInterfaceId)을(를) 통해 원하는 네트워크 인터페이스에서의 전송을 트리거합니다 ([SWS_DM_00822]).
  4. DM에 의한 메시지 전송: DM은 요청을 처리하고 networkInterfaceId(으)로 식별된 인터페이스에서 ISO 13400-2에 따른 차량 공지 메시지를 전송합니다 ([SWS_DM_00815]).

시퀀스 다이어그램: DoIP 차량 알림 트리거를 위한 호출 순서. 출처: [SWS_DM_00815], [SWS_DM_00821], [SWS_DM_00822].

오류 시나리오

TriggerVehicleAnnouncement 사용 시 주요 오류 시나리오 중 하나는 활성화 라인 종속 네트워크 인터페이스와 관련이 있습니다. 전달된 networkInterfaceId이 isActivationLineDependent = TRUE 속성이 설정된 인터페이스 구성(DoIPNetworkConfiguration)에 속하는 경우, 호출 시 오류([SWS_DM_00822])가 발생합니다. 이러한 인터페이스에서는 활성화 라인이 활성화되고 IP 주소가 할당되는 즉시 DM에 의해 알림 메시지 전송이 이미 자동으로 트리거됩니다([SWS_DM_00816], [SWS_DM_00822]).

함수 GetDoIPTriggerVehicleAnnouncement() 및 TriggerVehicleAnnouncement()에 대해서는 표준화된 오류 코드가 명시되어 있지 않습니다([SWS_DM_00821], [SWS_DM_00822]). 런타임 오류 또는 제조업체별 오류 상태가 발생할 경우 반환된 ara::core::Result를 통해 전달되며, 호출 애플리케이션에서 이를 확인해야 합니다.

이 클래스 가이드는 AUTOSAR Adaptive 사양 R25-11을 기반으로 생성되었습니다.
