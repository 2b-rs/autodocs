NVRAM 블록, 중복성 및 복구 AI 생성 / AI generated

자동으로 생성된 설명이다. 로컬 Classic 인벤토리에는 짧은 API 스텁만 포함되어 있으며, 저장소 식별자 [SWS_CP_…]는 Classic PDF에 대해 검증된 AUTOSAR 번호가 아니다. 로컬 참조가 없는 아키텍처 설명은 해석으로 표시된다. 공식 AUTOSAR 텍스트가 아니다. 소스 레지스터 ai/quellen.json에 등록된 Classic 문서가 없다.

레코드 CP_MEM는 저장소 식별자 [SWS_CP_MEM_00001] 아래에 NvM_WriteBlock(NvM_BlockIdType BlockId, const void* NvM_SrcPtr)를 문서화한다. 이 주석의 페이지 할당은 classic/memory.html이다. 그곳에서 NVRAM 관리자가 유지되기 때문이다.

해석: NvM은 블록 ID, RAM 미러 및 작업을 사용하여 블록을 관리한다. NvM_WriteBlock는 쓰기 작업을 대기열에 추가한다. Fee 또는 Ea 및 기본 스토리지 드라이버가 이를 실행한다. 대기열 등록의 반환 값은 데이터가 비휘발성 메모리에 있다는 확인이 아니다.

해석: 일반적인 블록 관리는 단일 블록, 두 개의 복사본이 있는 중복 블록 및 여러 요소가 있는 데이터 세트 블록을 구분한다. CRC 및 쓰기 검증은 구성된 보호 수단에 속한다. 로컬 레코드에는 관리 유형이 명시되어 있지 않다.

해석: 중복 블록의 경우 검사를 통과하면 손상된 기본 복사본을 두 번째 복사본에서 읽을 수 있다. 두 복사본이 모두 유효하지 않은 경우 NvM에서는 애플리케이션 값에 대한 기능적 재구성이 제공되지 않는다. 문서 이름: AUTOSAR_SWS_NVRAMManager, 여기에 등록되지 않음.

큐레이션에서 확인

Die Memory Services verwalten nicht-flüchtige Datenblöcke (NvM), abstrahieren Flash- und EEPROM-Technologien (MemIf, Fee, Ea) und gewährleisten Datenkonsistenz und Datensicherheit über ECU-Abschaltzyklen hinweg.

Module im Cluster

NVRAM Manager (NvM)

Provides synchronous and asynchronous block-based data management for non-volatile storage (EEPROM, Flash).

BSW ID 20 36 APIs (30 Funktionen, 6 Typen) #include "NvM.h"

Memory Abstraction Interface (MemIf)

Abstracts underlying Flash and EEPROM memory drivers.

BSW ID 22 12 APIs (9 Funktionen, 3 Typen) #include "MemIf.h"

Flash EEPROM Emulation (Fee)

Provides emulation of EEPROM-like data blocks on Flash memory devices.

BSW ID 40 16 APIs (15 Funktionen, 1 Typen) #include "Fee.h"

EEPROM Abstraction (Ea)

Provides uniform access to external and internal EEPROM devices.

BSW ID 41 16 APIs (15 Funktionen, 1 Typen) #include "Ea.h"
