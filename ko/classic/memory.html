시스템 아키텍처 & 모듈 클러스터의 역할

AUTOSAR Classic Platform의 메모리 서비스(Memory Services) 모듈 클러스터는 비휘발성 메모리 내 애플리케이션 및 기본 소프트웨어 데이터의 표준화되고 하드웨어 독립적인 관리 및 영속화를 보장합니다. 이 클러스터는 AUTOSAR 기본 소프트웨어 아키텍처의 두 개 계층으로 수직 분할됩니다. 즉, 서비스 계층(Services Layer)의 NVRAM Manager([SWS_NvM_00447])와 하드웨어 추상화 계층(Memory Hardware Abstraction Layer)의 Flash EEPROM Emulation([SWS_Fee_00085]) 및 EEPROM Abstraction([SWS_Ea_00083]) 하위 추상화 모듈을 포함하는 Memory Abstraction Interface([SWS_MemIf_00039])입니다 AUTOSAR SWS NVRAMManager 10쪽.

NVRAM Manager(NvM)는 소프트웨어 컴포넌트(SW-C)뿐만 아니라 Diagnostic Event Manager 모듈(Dem)과 같은 BSW 모듈의 중앙 진입점을 형성합니다 SWS DiagnosticEventManager 238쪽. 이는 비휘발성 메모리의 NV 블록, 휘발성 메모리의 RAM 블록, 그리고 초기화 데이터를 위한 선택적 ROM 블록으로 구성되는 논리적 메모리 블록을 관리합니다([SWS_NvM_00137], [SWS_NvM_00128]). 요구 사항에 따라 native(NVM_BLOCK_NATIVE), redundant(NVM_BLOCK_REDUNDANT) 또는 dataset(NVM_BLOCK_DATASET) 블록 관리 유형이 지원됩니다 AUTOSAR CP RS MemoryServices 10쪽.

모듈 Fee 및 Ea은(는) 각 물리적 저장 매체(Flash 또는 EEPROM)의 특성을 캡슐화하고 논리 블록 번호와 주소 오프셋을 각 MCAL 드라이버(Fls 또는 Eep)의 선형 주소 공간에 매핑합니다([SWS_Fee_00087], [SWS_Ea_00086]) AUTOSAR SWS EEPROMAbstraction 23쪽. 여기서 모듈 MemIf은(는) 자체 버퍼 구조를 유지하지 않고 매개변수 DeviceIndex을(를) 기반으로 대상 모듈에 접근을 전달하는 순수 라우팅 계층 역할을 합니다([SWS_MemIf_00040]).

모듈 간 상호작용 & 인터랙션 경로

모듈 간의 상호작용은 엄격하게 표준화된 동기 및 비동기 경로를 통해 이루어집니다. 사용자가 NvM_WriteBlock을(를) 통해 쓰기 작업을 시작하면 요청은 먼저 NvM의 관리 블록에 등록됩니다([SWS_NvM_00455]). 동기 호출의 경우 MemIf_Write을(를) 통해 MemIf(으)로 전달되며([SWS_MemIf_00040]), 이는 해당 호출을 Fee_Write 또는 Ea_Write에 넘깁니다([SWS_Fee_00088], [SWS_Ea_00087]) AUTOSAR SWS NVRAMManager 160쪽.

애플리케이션과 NVRAM Manager 간의 데이터 유지 및 동기화와 관련하여 두 가지 핵심 개념이 존재합니다. 영구 RAM 블록을 통한 암시적 동기화(NvMRamBlockDataAddress)와 미러 기반 버퍼를 통한 명시적 동기화(NvMBlockUseSyncMechanism)입니다 NVDataHandling 12쪽. 명시적 동기화의 경우 NvM은 구성된 콜백 루틴 NvMWriteRamBlockToNvCallback 또는 NvMReadRamBlockFromNvCallback을(를) 통해 애플리케이션 RAM과 내부 RAM 미러 간에 페이로드를 복사합니다([SWS_NvM_00514], [SWS_NvM_00515]) EXP NVDataHandling 30쪽.

데이터셋 블록(NVM_BLOCK_DATASET)을 사용할 때 호출자는 사전에 NvM_SetDataIndex을(를) 통해 원하는 데이터셋 인덱스를 선택합니다([SWS_NvM_00448]). 그런 다음 추상화 모듈은 논리 블록 번호와 인덱스로부터 MCAL 드라이버를 위한 정확한 주소 오프셋을 계산합니다([SWS_NvM_00123]) AUTOSAR SWS Flash EEPROM Emulation 21쪽. 취소 요청은 MemIf_Cancel을(를) 통해 하위 모듈 Fee_Cancel 또는 Ea_Cancel(으)로 직접 전달됩니다([SWS_MemIf_00041], [SWS_Fee_00089]).

동기화, 재진입성 및 태스크 컨텍스트

NvM_GetErrorStatus([SWS_NvM_00451]), NvM_SetBlockProtection([SWS_NvM_00450]), MemIf_GetVersionInfo([SWS_MemIf_00045])을(를) 포함하여 클러스터의 대부분의 제어 및 상태 API는 동기식으로 구현되며 호출자의 태스크 컨텍스트에서 직접 처리될 수 있습니다 AUTOSAR SWS NVRAMManager 157쪽. 반면에 데이터 전송 함수(NvM_ReadBlock, NvM_WriteBlock, Ea_Write)는 비동기식이며 재진입이 불가능하도록 설계되었습니다([SWS_MemIf_00040], [SWS_Ea_00087]).

진행 중인 작업의 주기적 업데이트는 Schedule Manager(SchM) 또는 BSW 태스크에 의해 주기적으로 호출되는 메인 함수 NvM_MainFunction 및 Fee_MainFunction의 담당입니다 AUTOSAR CP SWS FlashEEPROMEmulation 42쪽. MCAL 드라이버의 비동기 메시지의 경우 알림 Fee_JobEndNotification 또는 Fee_JobErrorNotification이(가) 인터럽트 레벨에서 직접 발생할 수 있습니다([SWS_Fee_00095]). 이는 상태를 MEMIF_JOB_OK(으)로 설정하거나 구성된 알림 루틴을 호출합니다([SWS_Fee_00142], [SWS_Fee_00194]) SWS FlashEEPROMEmulation 37쪽.

해석: 태스크 레벨의 API 호출자와 MainFunctions의 단계적 추가 처리 간의 경쟁 상태를 방지하기 위해 내부 대기열과 관리 속성은 독점 영역으로 보호될 것으로 보이며, MemIf는 상태 비저장 전달 계층으로 작동합니다 AUTOSAR SWS NVRAMManager 160쪽. 질문 Q-a50c3362a14b9e6d (열림)

일반적인 수명 주기 및 동작 모드

클러스터의 수명 주기는 Basic Software Mode Manager(BswM)와 ECU State Manager(EcuM)에 의해 밀접하게 오케스트레이션됩니다. ECU 시작(Startup Phase) 동안 드라이버 다음으로 추상화 모듈이 Fee_Init 또는 Ea_Init([SWS_Fee_00085], [SWS_Ea_00083])을(를) 통해 먼저 동기 초기화된 후, NVRAM Manager가 NvM_Init([SWS_NvM_00447])을(를) 통해 동기 초기화됩니다 AUTOSAR SWS NVRAMManager 156쪽.

초기화에 이어 BswM은 영구로 표시된 모든 RAM 블록을 비휘발성 메모리에서 복원하기 위해 멀티 블록 읽기 작업 NvM_ReadAll을(를) 트리거합니다([SWS_NvM_00460]) ModemanagementGuide 54쪽. NvM은 콜백 함수 BswM_NvM_CurrentJobMode을(를) 통해 진행 상황과 최종 결과를 BswM에 다시 보고합니다([SWS_NvM_00745], [SWS_NvM_00888]). 개별 블록 상태는 BswM_NvM_CurrentBlockMode을(를) 통해 시그널링됩니다([SWS_NvM_00746], [SWS_NvM_00890]) ModemanagementGuide 28쪽.

셧다운 단계에서 시스템은 NvM_WriteAll을(를) 통해 수정된 모든 RAM 블록을 NV 메모리로 영구 다시 쓰도록 지시합니다([SWS_NvM_00461]). Flash 쓰기 주기 횟수를 최적화하기 위해 NvM_SetRamBlockStatus을(를) 통해 블록이 수정되었는지 여부를 지정하여 표시할 수 있습니다([SWS_NvM_00453]) EXP NVDataHandling 18쪽. 조기 웨이크업 이벤트가 발생할 경우 진행 중인 쓰기 프로세스를 NvM_CancelWriteAll을(를) 통해 취소할 수 있습니다([SWS_NvM_00238]) AUTOSAR SWS NVRAMManager 161쪽.

오류 처리, DET 추적 및 성능 저하

클러스터는 다단계 오류 감지 및 디그레이디션 개념을 갖추고 있습니다. 드라이버 및 추상화 레벨에서 발생하는 오류는 반환 상태 MEMIF_JOB_FAILED을(를) MemIf_GetJobResult을(를) 통해 쿼리하거나 NvM_JobErrorNotification을(를) 통해 보고됩니다([SWS_Fee_00091], [SWS_Ea_00095]) ErrorDescription 49쪽.

읽기 오류가 발생하면 NvM은 구성된 복구 메커니즘을 사용합니다. 먼저 재시도(Read Retries)가 수행됩니다([SWS_NvM_00390]). 이것이 실패하면 중복 블록(NVM_BLOCK_REDUNDANT)의 경우 중복 복사본을 읽습니다([SWS_NvM_00171], [SWS_NvM_00531]). 여기서 중복성 손실이 감지되면 NvM은 작업 결과를 NVM_REQ_REDUNDANCY_FAILED(으)로 설정하고 프로덕션 오류 NVM_E_LOSS_OF_REDUNDANCY을(를) DEM에 보고합니다([SWS_NvM_00470], [SWS_NvM_00546]) ErrorDescription 62쪽.

ROM 기본값을 통한 복구에 성공하면 NvM은 결과 NVM_REQ_RESTORED_FROM_ROM을(를) 보고합니다([SWS_NvM_00470]). 모든 복구 조치가 실패하면 NVM_E_REQ_FAILED이(가) DEM에 보고되고([SWS_NvM_00279], [SWS_NvM_00288]) 쿼리 결과가 NVM_REQ_NOT_OK(으)로 설정됩니다([SWS_NvM_00451]). 쓰기 오류가 발생하면 NvM은 요청이 취소되기 전에 쓰기 재시도(NvMMaxNumOfWriteRetries)를 제어합니다([SWS_NvM_00168], [SWS_NvM_00213]) ErrorDescription 56쪽.
