소프트웨어 컴포넌트의 타입 기반 통신을 매개하고 기본 소프트웨어 모듈의 스케줄링을 제어합니다.

Runtime Environment(RTE) 모듈 클러스터는 제어기(ECU)에서 AUTOSAR Virtual Functional Bus를 구현하고, 소프트웨어 컴포넌트의 타입 기반 센더-리시버 및 클라이언트-서버 통신을 위한 표준화된 API를 제공합니다 [SWS_Rte_01091], [SWS_Rte_01102]. 이는 기본 소프트웨어 모듈의 주기적 스케줄링을 위한 Basic Software Scheduler(SchM)를 통합하며, OS/IOC 및 통신 스택(COM, LdCom)과 연결됩니다 [SWS_Rte_01376], [SWS_Rte_04546]. 이때 RTE는 구성 가능한 보호 영역, 버퍼링 및 정의된 10단계 전환 절차를 통해 데이터 일관성과 결정론적 모드 전환을 보장합니다 [SWS_Rte_02665], [SWS_Rte_03504].

Runtime Environment(RTE) 모듈 클러스터는 제어기 레벨에서 Virtual Functional Bus(VFB)의 구현체를 형성합니다. 이는 AUTOSAR 소프트웨어 컴포넌트(SWC)를 기본 Basic Software로부터 완전히 분리하고, Basic Software Scheduler(SchM)를 통해 BSW 모듈의 스케줄링을 조정합니다 [SWS_Rte_04546], [SWS_Rte_05165]. 이 클러스터는 파티션 내부 액세스뿐만 아니라 OS-IOC를 통한 파티션 간 데이터 흐름과 COM 및 LdCom 모듈을 통한 제어기 버스 데이터 흐름도 처리합니다 [SWS_Rte_01376], [SWS_Rte_02736], SWS_RTE 106쪽.

컨텍스트 다이어그램: 애플리케이션 계층(SWC), OS/IOC 및 Basic Software 서비스 사이의 RTE 및 SchM 클러스터 임베딩. 출처: [SWS_Rte_05165], [SWS_Rte_02736], [SWS_Rte_01376], SWS_RTE 106쪽.

통신은 센더-리시버 및 클라이언트-서버 패턴을 기반으로 합니다. S/R 데이터는 버퍼 사본(`Rte_IRead`/`Rte_IWrite`)을 통해 암시적으로 일관되게 전송되거나, 직접 및 버퍼링(`Rte_Read`/`Rte_Write`/`Rte_Receive`)되어 명시적으로 전송됩니다 [SWS_Rte_01091], [SWS_Rte_02521], [SWS_Rte_06000]. 신호의 손실 또는 유효하지 않은 신호가 존재하는 경우 `initValue` 대체 또는 `handleInvalid` 전략과 같은 메커니즘이 적용됩니다 [SWS_Rte_05030], [SWS_Rte_06009]. 클라이언트-서버 호출(`Rte_Call`, `Rte_Result`)은 비동기 실행 시 서버 및 클라이언트 측의 FIFO 대기열을 통해 동기화되며, 트랜잭션 핸들을 사용하여 고유하게 할당됩니다 [SWS_Rte_01102], [SWS_Rte_02527], [SWS_Rte_02649].

태스크 및 수명 주기 관리에서 RTE는 코드 공유를 통해 재진입성을 보장하고, 인터럽트 잠금, OS 리소스 또는 OS 스핀록과 같은 구성 가능한 잠금 메커니즘을 통해 임계 영역을 보호합니다 [SWS_Rte_03015], [SWS_Rte_03504]. 모드 변경은 OnExit, OnTransition에서 OnEntry 활성화에 이르는 엄격한 10단계 시퀀스를 거치며, 확인 이벤트를 통해 질서 있게 완료됩니다 [SWS_Rte_02665], [SWS_Rte_02679].

시스템 아키텍처 & 모듈 클러스터의 역할

Runtime Environment(RTE)의 모듈 클러스터는 AUTOSAR Classic Platform의 기능적 및 통신적 중추를 형성합니다. 이는 제어기 상에서 Virtual Functional Bus(VFB)의 구체적인 구현을 나타내며, 소프트웨어 컴포넌트(SWC)를 기본 Basic Software(BSW) 및 마이크로컨트롤러 하드웨어로부터 완전히 분리합니다 SWS_RTE 106쪽. 클러스터 내에서 실제 RTE는 애플리케이션 관련 ECU 내부 및 ECU 간 통신의 중재를 담당하는 반면, 통합된 Basic Software Scheduler(SchM)는 BSW 모듈의 실행 제어, 일관성 보장 및 주기적 스케줄링을 제어합니다 [SWS_Rte_04546], [SWS_Rte_05165].

이 아키텍처는 애플리케이션 SWC, 센서/액추에이터 컴포넌트 및 BSW 계층 사이에 표준화된 인터페이스를 확장합니다. 차량 전체의 네트워킹을 위해 RTE 클러스터는 통신 스택에 직접 의존합니다. 신호 지향 메시지는 COM 모듈로 전달되는 반면, 대용량 데이터는 LdCom 모듈(Large Data COM)을 통해 처리됩니다 [SWS_Rte_01376], [SWS_Rte_04527]. 파티션 및 코어 경계를 넘나드는 프로세스 및 메모리 격리는 AUTOSAR 운영체제(OS)와 해당 Inter-OS-Application-Communication 메커니즘(IOC)에 의해 제공됩니다 [SWS_Rte_02736]. 캘리브레이션 데이터와 메모리 블록은 표준화된 디스크립터를 통해 NVRAM Manager(NvM) 및 캘리브레이션 툴에 연결됩니다 [SWS_Rte_03961], [SWS_Rte_05118].

컨텍스트 다이어그램: 애플리케이션 계층(SWC), OS/IOC 및 Basic Software 서비스 사이의 RTE 및 SchM 클러스터 임베딩. 출처: [SWS_Rte_05165], [SWS_Rte_02736], [SWS_Rte_01376], SWS_RTE 106쪽.

모듈 간 상호작용 & 인터랙션 경로

RTE 클러스터 내의 상호작용은 센더-리시버(S/R) 통신과 클라이언트-서버(C/S) 통신을 엄격히 구분합니다. S/R 통신에서 RTE는 암시적 및 명시적 읽기/쓰기 시맨틱을 모두 지원합니다. 암시적 액세스(`Rte_IRead`, `Rte_IWrite`) 시 RTE는 Runnable 실행 시작 시 로컬 복사본을 생성하여 전체 런타임 동안 일관되게 유지합니다 [SWS_Rte_06000], [SWS_Rte_03744]. 명시적 액세스(`Rte_Read`, `Rte_Write`, `Rte_Send`, `Rte_Receive`) 시 데이터 교환은 직접 동기식으로 또는 대기열을 통해 수행됩니다 [SWS_Rte_01091], [SWS_Rte_01092]. 대기열이 있는 이벤트(`swImplPolicy = queued`)의 경우 RTE는 수신자 측에 FIFO 대기열을 설정합니다. 이러한 버퍼가 오버플로되면 요소가 폐기되고 오류 상태가 설정됩니다 [SWS_Rte_02521], [SWS_Rte_02523].

데이터 경로가 제어기 경계를 통과하는 경우(Inter-ECU), RTE는 복합 데이터 구조를 변환 및 직렬화하고, COM 모듈에서 원자적 PDU 전송을 보장하기 위해 `Com_SendSignal` 또는 `Com_SendSignalGroup`을 호출합니다 [SWS_Rte_04527]. 대용량 데이터 배열의 경우 RTE는 대안으로 `LdCom_Transmit`을 사용하며, 전송 프로토콜(TP) 시 콜백을 통한 확인이 있을 때까지 관련 버퍼를 잠급니다 [SWS_Rte_01377], [SWS_Rte_01379]. 수신자 측에서 RTE는 COM 콜백을 통해 비동기식으로 데이터를 수신하고, 이로부터 애플리케이션 Runnable을 위한 활성화 이벤트를 도출합니다 [SWS_Rte_03530], [SWS_Rte_03531]. 버스 데이터가 아직 도착하지 않은 경우 RTE는 구성된 초기값을 제공합니다 [SWS_Rte_06009], [SWS_Rte_06010].

시퀀스 다이어그램: 버퍼링 및 초기값 출력을 포함한 제어기 경계 간 명시적 센더-리시버 데이터 흐름. 출처: [SWS_Rte_06010], [SWS_Rte_04527], [SWS_Rte_03530], AUTOSAR_SWS_RTE 148쪽.

클라이언트-서버 통신에서 RTE는 동기식 호출을 위한 `Rte_Call`, 그리고 비동기식 호출을 위한 별도의 호출 및 조회 API(`Rte_Call`, `Rte_Result`)를 생성합니다 [SWS_Rte_01102], [SWS_Rte_01111]. 호출이 동일한 컨텍스트 내에서 C 함수로 직접 확인될 수 없는 한, RTE는 서버 레벨에서는 요청을 FIFO 대기열에, 클라이언트 레벨에서는 응답을 깊이 1의 대기열에 버퍼링합니다 [SWS_Rte_02527], [SWS_Rte_02528]. 파티션 또는 제어기 간 C/S 호출을 위해 RTE는 응답을 원래 호출자에게 정확하게 매핑하고자 클라이언트 ID와 시퀀스 카운터로 구성된 트랜잭션 핸들을 사용합니다 [SWS_Rte_02649], [SWS_Rte_03885].

동기화, 재진입성 및 태스크 컨텍스트

RTE 클러스터의 프로그램 코드 실행은 OS 태스크 또는 ISR 컨텍스트 내에서 발생합니다. RTE는 단순 Runnable(블로킹 OS 호출이 없는 카테고리 1)과 확장 Runnable(대기 지점이 있는 카테고리 2)을 구분하며, 후자는 `DataReceivedEvent` 또는 COM 콜백과 같은 이벤트에 의해 `WaitPoint` 상태에서 깨어납니다 [SWS_Rte_03532], SWS_RTE 304쪽. `canBeInvokedConcurrently` 속성이 `TRUE`로 명시적으로 설정되지 않는 한, 동일한 Runnable Entity 인스턴스의 동시 활성화는 엄격히 금지됩니다 [SWS_Rte_03523]. 다중 인스턴스화된 SWC의 경우 AUTOSAR는 코드 공유를 일관되게 적용합니다. 여러 인스턴스가 동일한 실행 코드를 공유하지만, 인스턴스별 디스크립터를 통해 분리된 데이터 및 Per-Instance-Memory(PIM)에 액세스합니다 [SWS_Rte_02002], [SWS_Rte_03015], [SWS_Rte_02301].

임계 영역을 보호하기 위해 RTE는 이른바 Exclusive Area(`Rte_Enter`, `Rte_Exit`)를 생성합니다. 기본 동기화 메커니즘은 `RteExclusiveAreaImplMechanism` 매개변수를 통해 구성됩니다 [SWS_Rte_03504]. 이때 다섯 가지로 정의된 전략을 사용할 수 있습니다.

  • ALL_INTERRUPT_BLOCKING: 모든 하드웨어 인터럽트의 전역 잠금 [SWS_Rte_03504].
  • OS_INTERRUPT_BLOCKING: OS 특정 인터럽트(카테고리 2)의 선택적 잠금 [SWS_Rte_03504].
  • OS_RESOURCE: 우선순위 상한 프로토콜(Priority Ceiling Protocol)을 적용한 OSEK/AUTOSAR 운영체제 리소스의 사용 [SWS_Rte_03504].
  • OS_SPINLOCK: 서로 다른 코어의 태스크와 ISR 간 조정을 위한 OS 스핀록 기반의 멀티코어 동기화 [SWS_Rte_03504].
  • NONE: 엄격한 태스크 우선순위 지정 또는 스케줄링을 통해 데이터 일관성이 이미 보장된 경우 내부 잠금 생략 [SWS_Rte_03504].
서로 다른 메모리 보호 파티션 간에 데이터가 전달되는 경우, RTE는 신뢰할 수 없는 파티션에서의 무단 메모리 액세스를 차단하기 위해 포인터 매개변수를 검사합니다 [SWS_Rte_02752], [SWS_Rte_02753].

일반적인 수명 주기 및 동작 모드

시스템 수명 주기는 초기화, 정규 작동 및 제어된 종료 간의 엄격한 단계 구분을 따릅니다. 시스템 시작 시에는 먼저 SchM 부분이 초기화됩니다. EcuM은 BswM과 같은 BSW 모듈이 시작되기 전에 각 프로세서 코어에서 `SchM_Start`를 호출합니다 [SWS_Rte_04546], [SWS_Rte_04548]. 이어서 `SchM_StartTiming`이 주기적인 BSW 이벤트와 MainFunctions를 활성화합니다 [SWS_Rte_04549], [SWS_Rte_04551]. 설계 제약조건에 따라 `SchM_Start`와 `SchM_StartTiming`은 코어당 정확히 한 번만 호출될 수 있습니다 SWS_RTE 928쪽. 그 후 `Rte_Start`가 애플리케이션 RTE를 활성화하며, 내부 자원 할당에 실패하면 초기화가 `RTE_E_LIMIT`와 함께 중단됩니다 [SWS_Rte_01261], [SWS_Rte_01262].

동작 모드는 Mode-Declaration-Group을 통해 표현됩니다. Mode Manager가 `Rte_Switch`를 통해 모드 전환을 트리거하면 이는 FIFO 대기열에 저장됩니다 [SWS_Rte_02631], [SWS_Rte_02718], [SWS_Rte_02719]. 각 모드 머신은 전환 중에 구속력 있는 10단계 시퀀스를 거칩니다 [SWS_Rte_02665]. 먼저 대상 모드에 대한 모드 비활성화가 적용되고 실행 중인 엔티티를 대기합니다(1~2단계). 이어서 OnExit(3~4단계), OnTransition(5~6단계) 및 OnEntry Executable Entity(7~8단계)의 순차적 실행 및 종료가 뒤따릅니다. 마지막으로 이전 모드의 비활성화가 해제되고 새 모드가 활성화되며(9단계), 그 후 모드 전환은 `ModeSwitchedAckEvent` 또는 `Rte_SwitchAck`를 통해 확인됩니다(10단계) [SWS_Rte_02665], [SWS_Rte_02679], [SWS_Rte_02725]. 또한 `RteModeToScheduleTableMapping`을 통해 동작 모드를 OS Schedule Table에 직접 연결할 수도 있습니다 [SWS_Rte_05146].

시퀀스 다이어그램: 확인 응답을 포함한 AUTOSAR 모드 전환의 표준화된 10단계 절차. 출처: [SWS_Rte_02665], [SWS_Rte_02679], EXP_ModeManagementGuide 16쪽.

초기화 해제는 셧다운 단계 시작 시 `Rte_Stop`을 통해 수행됩니다. 이 호출 후 RTE는 해당 코어에서 추가 Runnable의 활성화, 시작 또는 해제를 차단합니다 [SWS_Rte_02538]. RTE가 정지된 상태에서는 수신되는 S/R 데이터 및 C/S 요청이 폐기되고 무시됩니다 [SWS_Rte_02535], [SWS_Rte_02536].

오류 처리, 상태 모니터링 및 데이터 유효성 검사

오류 상태 및 인터페이스 상태는 RTE에서 스칼라 타입인 `Std_ReturnType`을 통해 호출자에게 일관되게 전달됩니다 [SWS_Rte_01034], SWS_RTE 586쪽. RTE는 애플리케이션 오류(오류 값 1~63), 직접적인 인프라 오류(값 128~255) 및 데이터 손실(`RTE_E_LOST_DATA = 64`)이나 데이터 노후화(`RTE_E_MAX_AGE_EXCEEDED = 64`)와 같은 중첩된 상태 비트를 구분합니다 SWS_RTE 586쪽. 일반적인 인프라 반환 값에는 통신 중단(`RTE_E_COM_STOPPED = 128`), 통신 및 응답 타임아웃(`RTE_E_TIMEOUT = 129`), 데이터 누락(`RTE_E_NO_DATA = 131`) 및 자원 오버플로(`RTE_E_LIMIT = 130`)가 포함됩니다 [SWS_Rte_01060], [SWS_Rte_01061], [SWS_Rte_01064]. 값 범위 검사가 활성화된 경우 RTE는 범위 초과를 `RTE_E_OUT_OF_RANGE`로 확인합니다 [SWS_Rte_03845], [SWS_Rte_03846].

비정상적이거나 오류가 있는 신호를 처리하기 위해 RTE는 데이터 무효화(invalidation) 메커니즘을 제공합니다. 송신 측에서 `Rte_Invalidate`는 신호를 정의된 대체 값으로 표시합니다 [SWS_Rte_01206], [SWS_Rte_05024]. 수신 측에서는 `handleInvalid` 속성이 대체 전략을 제어합니다. `keep`의 경우 이전 값이 유지되고 `DataReceiveErrorEvent`가 트리거되는 반면, `replace`의 경우 `initValue`로 자동 대체됩니다 [SWS_Rte_05030], [SWS_Rte_05049]. 네트워크 레벨의 통신 오류는 `aliveTimeout`을 통해 모니터링됩니다. 모니터링 시간이 만료되면 COM 모듈은 `Rte_COMCbkRxTOut`을 통해 수신 타임아웃을 RTE에 보고하며, 이에 따라 종속 컴포넌트에 통지되거나 폴백 값이 활성화됩니다 [SWS_Rte_08061].

컨텍스트 및 근거: 이 가이드는 RTE 모듈의 AUTOSAR 사양(R20-11/R25-11) 및 AUTOSAR Mode Management Guide만을 기반으로 합니다.

Runtime Environment(RTE)은 콘크리트 ECU에 가상 기능 버스(VFB)를 구현하고 소프트웨어 구성 요소(SW-C)와 기본 소프트웨어 간의 모든 내부 및 내부ECU 통신 연결을 중재합니다.
