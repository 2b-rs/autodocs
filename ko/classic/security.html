시스템 아키텍처 & 모듈 클러스터의 역할

AUTOSAR Classic Platform(릴리스 R20-11)의 Security & Intrusion Detection 모듈 클러스터는 암호화, 안전한 온보드 통신, 키 및 인증서 관리, 침입 감지를 위한 표준화된 서비스를 제공합니다. 기능적으로 이 클러스터는 여러 AUTOSAR Basic Software (BSW) 계층에 걸쳐 구성됩니다. 서비스 계층에서는 Crypto Service Manager (CSM)가 하드웨어 독립적인 암호화 서비스를 캡슐화합니다 AUTOSAR_CP_SWS_CryptoServiceManager 21쪽. I-PDU의 안전한 통신은 통신 계층의 Secure Onboard Communication (SecOC) 모듈이 담당하며 [SWS_SecOC_00162], 보안 서비스로서 Key Manager (KeyM)는 암호화 키와 인증서의 라이프사이클을 오케스트레이션합니다 SWS_KeyManager 31쪽. 추가로 Intrusion Detection System Manager (IdsM)는 전체 시스템에서 보안 관련 이벤트를 위한 중앙 어그리게이터 및 필터 역할을 합니다 AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 21쪽.

CSM 하위에서는 계층 CryIf으로서 Crypto Interface (CryIf)가 여러 암호화 드라이버 객체에 대한 하드웨어 또는 소프트웨어별 접근을 추상화하고 작업 및 키 디스패칭 메커니즘을 표준화합니다 SWS_CryptoInterface 1쪽. MCAL 및 드라이버 계층에서는 Crypto Driver(Crypto)가 소프트웨어 또는 하드웨어 보안 모듈(HSM)에서 실제 계산을 수행합니다 [SWS_Crypto_91016]. 이러한 계층 간의 상호작용은 애플리케이션 소프트웨어(SW-C) 및 통신 모듈을 하드웨어별 암호화 가속기로부터 완전히 디커플링하도록 보장합니다.

모듈 간 상호작용 & 인터랙션 경로

클러스터의 모듈들은 명확하게 정의된 제어 및 데이터 흐름 경로를 통해 서로 연결되어 있습니다. 암호화 작업의 처리는 주로 CSM을 통해 수행됩니다. 애플리케이션 모듈 또는 SecOC 및 KeyM과 같은 BSW 모듈은 Csm_MacGenerate [SWS_Csm_00982], Csm_Encrypt [SWS_Csm_00984], Csm_AEADEncrypt [SWS_Csm_01023], Csm_SignatureGenerate [SWS_Csm_00992], Csm_Hash [SWS_Csm_00980] 또는 Csm_RandomGenerate [SWS_Csm_01543]과 같은 CSM 서비스를 통해 작업을 시작합니다. 작업은 표준화된 런타임 구조체 Crypto_JobType로 캡슐화되며 [SWS_Csm_01013], 이는 동작 모드(CRYPTO_OPERATIONMODE_START, UPDATE, FINISH 또는 SINGLECALL과 같은 Crypto_OperationModeType)를 통해 제어됩니다 [SWS_Csm_00802]. CSM은 해당 작업을 CryIf_ProcessJob [SWS_CryIf_91003]에 전달하고, 이는 해당 암호화 드라이버 객체로 호출을 전달합니다.

SecOC 모듈은 PduR과 통신 버스 간의 PDU 전송을 보호합니다. SecOC_TpRxIndication [SWS_SecOC_00125]을 통해 보안 PDU를 수신할 때 SecOC는 먼저 SecOC_GetRxFreshnessAuthData를 통해 신선도 값을 조회하고 [SWS_SecOC_91006] 명세 SecOcProtocol 19쪽에 따라 인증할 데이터를 구성합니다. MAC 검증을 위해 SecOC는 CSM을 사용합니다 [SWS_SecOC_00012]. 검증에 성공하면 정품 PDU가 상위 계층으로 전달됩니다. 검증에 실패하면 결과가 상태 SecOC_VerificationStatusType에 기록되며 [SWS_SecOC_00160], [SWS_SecOC_91014], Interpretation: 이러한 실패는 Security Event로서 IdsM에 보고됩니다 AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 21쪽.

Key Manager (KeyM)에서는 키 및 인증서 업데이트가 준비되고 실행됩니다. 인증서 검증 시(예: KeyM_VerifyCertificates [SWS_KeyM_00059] 또는 KeyM_VerifyCertificateChain [SWS_KeyM_00061]을 통해) KeyM은 서명 검증을 위해 CSM의 암호화 프리미티브를 사용하고, 유효성 검사를 위해 StbM의 외부 타임베이스를 사용합니다 SWS_KeyManager 119쪽. 키 업데이트(KeyM_Update [SWS_KeyM_00052])는 사용자 정의 핸들러(KeyM_KH_Update [SWS_KeyM_00069], [SWS_KeyM_00055])를 바인딩하며, 결과 키 바이트는 Csm_KeyElementSet [SWS_Csm_00957] 및 Csm_JobKeySetValid [SWS_Csm_91027]을 통해 암호화 드라이버에서 활성화됩니다. 키 유도 및 복사 작업은 CryIf가 CryIf_KeyDerive [SWS_CryIf_91009] 또는 CryIf_KeyElementCopy [SWS_CryIf_91015]을 통해 Crypto_KeyElementCopyPartial [SWS_Crypto_91015]와 같은 드라이버 함수로 전달합니다.

IdsM은 IdsM_SetSecurityEvent [SWS_IdsM_91002] 또는 IdsM_SetSecurityEventWithCount [SWS_IdsM_91018]과 같은 인터페이스를 통해 BSW 센서(SecOC 포함) 및 애플리케이션 SW-C로부터 보안 이벤트(Security Events, SEv)를 수집합니다. 이벤트는 버퍼링되고, 필터 체인(예: Block State Filter [SWS_IdsM_01020] 또는 집합 필터 AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 40쪽)을 통해 한정(qualify)된 후 최종적으로 PduR을 통해 전달됩니다 [SWS_IdsM_91009], [SWS_IdsM_91010].

시퀀스 다이어그램: 암호화 스택을 사용한 SecOC 내 보안 PDU 검증 및 IdsM으로의 보안 이벤트 보고. 출처: [SWS_SecOC_00125], [SWS_SecOC_00012], [SWS_CryIf_91003], [SWS_CryIf_91013], [SWS_IdsM_91002].

동기화, 재진입성 및 태스크 컨텍스트

암호화 연산 및 보안 작업의 실행에는 동기식 호출 경로와 비동기식 태스크 컨텍스트의 엄격한 분리가 필요합니다. CSM 및 CryIf에서 실행 동작은 암호화 프리미티브의 구성에 따라 달라집니다. 즉, 작업이 동기 블로킹 방식 또는 비동기 방식으로 실행될 수 있습니다 [SWS_Csm_00982], [SWS_CryIf_91003]. 비동기 작업의 경우 암호화 드라이버가 CryIf_CallbackNotification [SWS_CryIf_91013]을 통해 완료를 알리고, 이에 따라 CSM이 호출자의 등록된 콜백 함수를 처리합니다 [SWS_SecOC_00012]. 중단 가능하거나 장시간 실행되는 계산을 위해 CSM은 중단 함수 Csm_CancelJob를 제공하며 [SWS_Csm_00968], 이는 CryIf_CancelJob [SWS_CryIf_91014]을 통해 드라이버에 위임됩니다.

SecOC 모듈의 전송은 시간 트리거 방식으로 디커플링됩니다. 주기적인 사이클에서 SecOC_MainFunctionTx은 서명할 새 정품 PDU가 대기 중인지 확인하고, 인증자를 계산하며, PduR 전송을 시작합니다 [SWS_SecOC_00176]. IdsM에서는 보고된 이벤트의 수신이 IdsM_SetSecurityEvent [SWS_IdsM_91002]을 통해 센서 컨텍스트(태스크 또는 ISR)에서 고성능으로 수행되며, 이벤트는 먼저 구성 가능한 이벤트 버퍼에 동기식으로 저장됩니다 [SWS_IdsM_00701], [SWS_IdsM_00702]. 많은 시간이 소요되는 필터링, 컨텍스트 데이터 처리, StbM 또는 RTE를 통한 타임스탬프 보강은 주기적인 IdsM_MainFunction 컨텍스트에서 완전히 비동기식으로 처리됩니다 SWS_IntrusionDetectionSystemManager 87쪽, AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 86쪽.

Key Manager는 시간에 민감한 태스크와 연산 집약적인 태스크를 구분합니다. 표준 상태 쿼리 및 콜백 오케스트레이션이 KeyM_MainFunction에서 실행되는 반면 [SWS_KeyM_00074], 연산 집약적인 동기식 핸들러 시퀀스(예: KeyM_KH_Update)의 경우 선점형 백그라운드 함수 KeyM_MainBackgroundFunction에서의 실행이 지정되어 있습니다 [SWS_KeyM_00075]. 또한 멀티코어 아키텍처에서 CSM은 파티션별 메인 함수 및 초기화를 지원합니다 [SWS_Csm_00646], SWS_CryptoInterface 1쪽. Interpretation: 이러한 파티셔닝은 프로세서 코어별 전용 하드웨어 드라이버 객체 할당과 일치합니다.

일반적인 수명 주기 및 동작 모드

클러스터의 초기화는 하위 계층에서 상위 계층으로의 엄격한 종속성 계층 구조를 따릅니다. 먼저 하드웨어 근접 드라이버가 Crypto_Init을 통해 구성되고 [SWS_Crypto_91016], 이어서 인터페이스 CryIf [SWS_CryIf_91118]와 Csm_Init [SWS_Csm_00646]를 통한 CSM이 구성됩니다. 그 후에야 종속 모듈인 SecOC, KeyM 및 IdsM을 초기화할 수 있습니다. SecOC는 초기화를 통해 SECOC_UNINIT 상태에서 SECOC_INIT 상태로 전환됩니다 [SWS_SecOC_00162]. KeyM에서는 구성된 모든 인증서가 NvM에서 읽히거나 KeyM_SetCertificate 또는 진단을 통해 로드 및 검증되기 전에 SWS_KeyManager 119쪽 초기에 KEYM_CERTIFICATE_NOT_AVAILABLE [SWS_KeyM_00021], [SWS_KeyM_91003] 상태를 받습니다.

런타임 시 차량 상태 변경은 IdsM의 작동 모드에 영향을 줍니다. Basic Software Manager (BswM)는 IdsM_BswM_StateChanged을 통해 IdsM에 상태 변경을 알립니다 [SWS_IdsM_91005]. 이러한 상태는 Block State Filter [SWS_IdsM_01020], [SWS_IdsM_91017]을 제어하여 특정 작동 단계(예: 프로그래밍 모드 또는 슬립 단계)에서 보안 이벤트의 전달을 억제합니다. 또한 이벤트의 보고 모드는 DCM을 통해 진단적으로 수정될 수 있으며(IdsM_Dcm_SetReportingMode_Start [SWS_IdsM_91008], [SWS_IdsM_91013]) NvM에 영구적으로 저장될 수 있습니다 [SWS_IdsM_01700], [SWS_IdsM_01701].

ECU 셧다운 시 모듈들은 순서대로 초기화 해제됩니다. SecOC_DeInit은 안전한 통신을 중지하고 모든 내부 버퍼와 변수를 비우며 SecOC를 다시 SECOC_UNINIT 상태로 전환합니다 [SWS_SecOC_00161]. KeyM_Deinit [SWS_KeyM_00047] 호출 시 대기 상태에서의 무단 판독을 방지하기 위해 보안상의 이유로 RAM에 있는 모든 암호화 키 자료가 능동적으로 파기되고 초기값으로 덮어써집니다.

오류 처리, DET 추적 및 성능 저하

이 모듈 클러스터는 개발 오류(Development Error Tracer, DET) 및 런타임 문제를 감지하기 위한 일관된 메커니즘을 구현합니다. 모든 모듈은 초기화 여부를 확인하고 초기화되지 않은 상태에서 호출 시 DET 오류를 보고합니다. 예를 들어 CryIf_RandomSeed [SWS_CryIf_91007], CryIf_CancelJob [SWS_CryIf_91014], CryIf_KeyDerive [SWS_CryIf_91009] 또는 CryIf_CallbackNotification [SWS_CryIf_91013]과 같은 CryIf 인터페이스에서의 CRYIF_E_UNINIT이 있습니다. 마찬가지로 잘못된 포인터 매개변수는 Crypto_GetVersionInfo [SWS_Crypto_91001]에서의 CRYPTO_E_PARAM_POINTER와 같은 DET 보고로 이어지며, CSM의 초기화 오류는 CSM_E_INIT_FAILED로 보고됩니다 [SWS_Csm_00646].

암호화 하드웨어 객체의 과부하 또는 장애 발생 시 드라이버는 CRYPTO_E_BUSY 상태를 알립니다 [SWS_CryIf_91003], [SWS_Csm_00957]. 이러한 성능 저하 시나리오에서 SecOC는 차량 가용성을 유지하기 위해 SecOC_SendDefaultAuthenticationInformation을 통해 인증되지 않은 대체 PDU를 하위 계층으로 구성 가능하게 전송할 수 있도록 허용합니다 [SWS_SecOC_91013]. IdsM에서는 구성된 이벤트 버퍼가 고갈되면 내부 보안 이벤트 SEV_IDSM_NO_EVENT_BUFFER_AVAILABLE [SWS_IdsM_00703]가 트리거됩니다. 수정된 IdsM 매개변수의 NvM 지속성 저장이 실패하면 IdsM은 이전 상태로 자동 롤백을 수행합니다 [SWS_IdsM_01702]. Csm_KeyElementSet에서 키 설정 중 오류가 발생하면 키 요소의 상태는 정의되지 않은 것으로 간주되며 Csm_KeyGetStatus [SWS_Csm_91047] 및 CryIf_KeyGetStatus [SWS_CryIf_91012]를 통해 유효성을 검증해야 합니다.

이 가이드는 릴리스 R20-11용 Classic Platform의 AUTOSAR 명세를 기반으로 하며 Security & Intrusion Detection 클러스터의 아키텍처를 요약합니다.

Crypto Driver (Crypto)

하드웨어 보안 모듈(HSM) 또는 소프트웨어 라이브러리에서 암호화 기본 요소를 실행하는 하위 수준 드라이버입니다.

BSW ID 114 API 20개(기능 19개, 유형 1개) #include "Crypto.h"

Crypto Service Manager (CSM)

애플리케이션 및 BSW에 표준화된 암호화 서비스(암호화, 해싱, 디지털 서명, 키 관리)를 제공합니다.

BSW ID 110 82개 API(38개 기능, 44개 유형) #include "Csm.h"

Crypto Interface (CryIf)

암호화 하드웨어 및 소프트웨어 가속 엔진을 추상화합니다.

BSW ID 112 19개 API(18개 기능, 1개 유형) #include "CryIf.h"
