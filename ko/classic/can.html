AUTOSAR Classic CAN

CAN 드라이버에 대한 전체 초기화 데이터와 모든 컨트롤러에 영향을 미치는 SFR 설정을 포함하는 외부 데이터 구조 유형입니다. 또한 컨트롤러 구성 구조에 대한 포인터도 포함되어 있습니다. 초기화 데이터 구조의 내용은 CAN 하드웨어에 따라 다릅니다.

Can_ControllerStateType 타입

CAN 컨트롤러의 오류 상태.

Can_ErrorType 타입

열거형은 일반적인 CAN HW가 보고할 수 있는 CAN 오류 유형의 상위 집합을 나타냅니다. 이는 모든 CAN HW가 전체 세트를 지원할 수는 없다는 의미입니다.

Can_HwHandleType 타입

CAN 하드웨어 장치의 하드웨어 개체 핸들을 나타냅니다. 255개 이상의 HW 개체가 포함된 CAN 하드웨어 장치의 경우 확장된 범위를 사용합니다.

Can_HwType 타입

이 유형은 해당 CAN 컨트롤러와 Can Drv 및 특정 Can ID를 포함하여 하드웨어 개체 핸들을 명확하게 제공하는 데이터 구조를 정의합니다.

Can_IdType 타입

L - PDU의 식별자를 나타냅니다. 가장 중요한 두 비트는 프레임 유형을 지정합니다. 00 CAN 표준 CAN ID 01 CAN FD 프레임 표준 CAN ID 10 CAN 확장 CAN ID 11 CAN FD 확장 CAN ID 프레임이 포함된 메시지

CanIf_SetControllerMode [SWS_CANIF_00311] 또는 CanIf_RxIndication [SWS_CANIF_00416]과 같이 유효하지 않은 ID 및 포인터에 대한 검사가 전형적입니다. 초기화 전에 CanIf 서비스는 E_NOT_OK(으)로 일반 작동을 거부하며 [SWS_CANIF_00661], CanTp는 이 경우 CANTP_E_UNINIT을(를) 보고합니다 [SWS_CanTp_00031].

런타임 오류는 Det_ReportRuntimeError(으)로 전달됩니다 [SWS_CANIF_91007] [SWS_CanTrcv_91006]. 예:

  • 실패한 길이 검사 [SWS_CANIF_00168]
  • 오프라인 채널에서의 송신 [SWS_CANIF_00382]
  • 트랜시버와의 통신 부재 [SWS_CanTrcv_00114]

프로덕션 오류는 DEM으로 전달됩니다. CanTrcv_MainFunctionDiagnostics은(는) BUSERR 플래그가 설정된 경우 CANTRCV_E_BUS_ERROR을(를) FAILED로 보고합니다. 플래그가 재설정된 경우 해당 이벤트를 그에 맞춰 다시 보고합니다 [SWS_CanTrcv_00206] [SWS_CanTrcv_00227]. 이 함수는 CanTrcvBusErrFlag = TRUE에서만 존재합니다 [SWS_CanTrcv_00205]. CanIf는 트리거 이벤트가 발생할 때만 프로덕션 오류를 보고합니다 [SWS_CANIF_00223].

Security Events: 보안 관련 버스 오류는 CanIf가 IdsM으로 전달합니다 [SWS_CANIF_00913]. 소스는 CanIf_ErrorNotification [SWS_CANIF_00915] [SWS_CANIF_00916] 및 Bus-Off 이벤트입니다 [SWS_CANIF_00918].

Bus-Off 및 재시작: Can은 CanIf_ControllerBusOff을(를) 통해 Bus-Off를 보고합니다 [SWS_CANIF_00218]. 이에 따라 CanIf는 채널을 오프라인으로 설정하고 [SWS_CANIF_00866] CanSM에 알립니다 [SWS_CANIF_00724] CanIf 154쪽. CanSM은 CanIf_SetControllerMode을(를) 사용하여 STARTED로 재시작을 시작합니다 CanIf 160쪽. CanIf_GetTxConfirmationState을(를) 사용하여 시작 이후 송신 확인이 수신되었는지 확인합니다 [SWS_CANIF_00734] [SWS_CANIF_00740].

오류 상태 및 오류 카운터는 자체 서비스를 통해 제공됩니다:

  • Can_ErrorStateType [SWS_Can_91003]을(를) 동반한 CanIf_GetControllerErrorState [SWS_CANIF_91001]
  • 카운터 API [SWS_CANIF_91003] [SWS_CANIF_91004]

CanTp에서의 성능 저하: CanTp는 오류가 발생한 세션을 개별적으로 중단합니다:

  • 시간 초과(N_As, N_Bs, N_Cr) 시 해당 세션을 종료하고 E_NOT_OK을(를) PduR에 보고합니다 [SWS_CanTp_00310] [SWS_CanTp_00316] [SWS_CanTp_00313].
  • WFTmax개의 FC(WAIT) 프레임 후에 수신을 중단합니다 [SWS_CanTp_00223].
  • CanIf_Transmit이(가) 거부하면 진행 중인 연결을 종료합니다 [SWS_CanTp_00342] [SWS_CanTp_00343].

각 채널이 자체 리소스를 가지므로 다른 채널은 영향을 받지 않습니다 [SWS_CanTp_00122].

클러스터의 모듈

CAN Driver (Can)

CAN 드라이버는 내부 및 외부 CAN 컨트롤러(CAN 2.0B, CAN FD, CAN XL)에 대한 하드웨어 종속 액세스를 제공한다.

BSW ID 80 27개 API(19개 기능, 8개 유형) #include "Can.h"

CAN Interface (CanIf)

CanIf는 CAN 하드웨어 세부사항을 추상화하고 상위 계층 모듈(PduR, CanTp, CanNm, CanSM)을 위해 여러 CAN 컨트롤러 및 트랜시버에 대한 균일한 액세스를 제공한다.

BSW ID 60 50개 API(47개 기능, 3개 유형) #include "CanIf.h"

CAN Transceiver Driver (CanTrcv)

CAN 라인의 물리적 버스 트랜시버 상태 및 웨이크업 감지를 제어한다.

BSW ID 70 23개 API(17개 기능, 6개 유형) #include "CanTrcv.h"

CAN Transport Layer (CanTp)

최대 4095바이트(ISO 15765-2)의 CAN 메시지 분할 및 재조립 기능을 제공합니다.

BSW ID 35 12개의 API(11개의 기능, 1개의 유형) #include "CanTp.h"
