Architekturüberblick CAN-Cluster

Das AUTOSAR Classic CAN-Cluster stellt die vollständige Kommunikationskette für Controller Area Networks (CAN 2.0B, CAN FD, CAN XL) bereit. Es gliedert sich in den hardwarenahen CAN Driver (Can) [SWS_Can_00223], das vermittelnde CAN Interface (CanIf) [SWS_CANIF_00001], den CAN Transceiver Driver (CanTrcv) sowie den CAN Transport Layer (CanTp) für segmentierte Diagnose- und Kommunikationsnachrichten bis zu 4095 Bytes. Das CanIf koordiniert den Sende- und Empfangsfluss via CanIf_Transmit [SWS_CANIF_00005] und abstrahiert Mehrkanal-Topologien transparent für die oberen Schichten.

CAN FD, 사서함 및 컨트롤러 상태 AI 생성 / AI generated

자동으로 생성된 설명이다. 로컬 Classic 인벤토리에는 짧은 API 스텁만 포함되어 있으며, 저장소 식별자 [SWS_CP_…]는 Classic PDF에 대해 검증된 AUTOSAR 번호가 아니다. 로컬 참조가 없는 아키텍처 설명은 해석으로 표시된다. 공식 AUTOSAR 텍스트가 아니다. 소스 레지스터 ai/quellen.json에 등록된 Classic 문서가 없다.

레코드 CP_CAN는 저장소 식별자 [SWS_CP_CAN_00001] 아래에 Can_Write(Can_HwHandleType Hth, const Can_PduType* PduInfo)를 문서화한다. Hth는 하드웨어 전송 핸들이다.

해석: Can 드라이버의 사서함(Mailbox)은 하드웨어 객체이다. 송신 객체는 HTH를 통해 주소 지정되고, 수신 객체는 HRH를 통해 주소 지정된다. Can_Write는 PDU를 송신 객체에 전달한다. 이는 COM-Com_SendSignal이 아니며 신호 레이아웃을 알지 못한다.

해석: CAN FD는 중재 비트 전송률을 데이터 단계와 분리한다. 전환은 BRS 비트로 요청되며 일치하는 컨트롤러 비트 전송률 구성이 필요하다. 특정 PDU가 FD를 사용하는지 여부는 Can_Write의 단순한 존재가 아니라 PDU 구조 및 컨트롤러 구성에 지정된다.

해석: 컨트롤러는 UNINIT, STOPPED, STARTED 및 SLEEP 상태를 가진다. Can_SetControllerMode는 드라이버 상태를 관리한다. ComM 모드로의 매핑과 Bus-off 복구는 CAN State Manager가 담당한다. 성공적인 Can_Write는 시작된 컨트롤러를 전제로 하며 Bus-off를 복구하지 않는다.

Das CAN-Cluster (Controller Area Network) stellt hardwarenahe Treiber, standardisierte Hardware-Abstraktion (CanIf), State-Management und ISO 15765-2 Transportprotokolle (CanTp) für klassische CAN-, CAN FD- und CAN XL-Netzwerke bereit.

Module im Cluster

CAN Driver (Can)

CAN 드라이버는 내부 및 외부 CAN 컨트롤러(CAN 2.0B, CAN FD, CAN XL)에 대한 하드웨어 종속 액세스를 제공한다.

BSW ID 80 27 APIs (19 Funktionen, 8 Typen) #include "Can.h"

CAN Interface (CanIf)

CanIf는 CAN 하드웨어 세부사항을 추상화하고 상위 계층 모듈(PduR, CanTp, CanNm, CanSM)을 위해 여러 CAN 컨트롤러 및 트랜시버에 대한 균일한 액세스를 제공한다.

BSW ID 60 50 APIs (47 Funktionen, 3 Typen) #include "CanIf.h"

CAN Transceiver Driver (CanTrcv)

CAN 라인의 물리적 버스 트랜시버 상태 및 웨이크업 감지를 제어한다.

BSW ID 70 23 APIs (17 Funktionen, 6 Typen) #include "CanTrcv.h"

CAN Transport Layer (CanTp)

Provides segmentation and reassembly of CAN messages up to 4095 bytes (ISO 15765-2).
