AUTOSAR Classic Microcontroller Abstraction (MCAL)

마이크로 컨트롤러 추상화 계층(MCAL)에는 내부 마이크로 컨트롤러 주변 장치(ADC 변환기, PWM 생성기, 하드웨어 감시 장치)를 위한 하드웨어별 드라이버가 포함되어 있으며 실리콘 플랫폼에서 상위 BSW 계층을 분리합니다.

Adc_Channel 타입

활성 제한 확인의 경우: Adc 채널 하한 및 Adc 채널 상한으로 정의된 보드와 관련하여 어떤 변환 값을 고려할지 정의합니다.

Adc_ChannelType 타입

ADC 채널의 숫자 ID.

Adc_ConfigType 타입

ADC Driver 및 ADC HW 유닛을 초기화하는 데 필요한 구성 매개변수 세트가 포함된 데이터 구조입니다.

Adc_ConversionTimeType 타입

변환 시간 유형, 즉 샘플링된 아날로그 값이 디지털 표현으로 변환되는 시간입니다. (이것은 API 유형이 아닙니다).

Adc_GroupAccessModeType 타입

변환 결과를 그룹화하기 위한 액세스 모드를 구성하는 유형입니다.

Adc_GroupConvModeType 타입

ADC 채널 그룹의 변환 모드를 구성하는 유형입니다. AUTOSAR CP R20 - 문서 ID : AUTOSAR_SWS_ADCDriver

Adc_GroupDefType 타입

채널 그룹에 채널을 할당하는 유형입니다(API 유형이 아님).

Adc_GroupPriorityType 타입

채널의 우선순위 수준입니다. 가장 낮은 우선순위는 0입니다.

Adc_GroupReplacementType 타입

우선 순위가 더 높은 그룹에 의해 그룹 변환이 중단되는 경우 ADC 그룹 수준에서 사용되는 대체 메커니즘입니다.

Adc_GroupType 타입

ADC 채널 그룹의 숫자 ID.

Adc_HwTriggerSignalType 타입

드라이버가 반응해야 하는 하드웨어 트리거 신호의 가장자리를 구성하기 위한 유형입니다. 즉, 변환을 시작합니다(ADC 하드웨어에서 지원하는 경우에만).

Adc_HwTriggerTimerType 타입

ADC 모듈 내장 타이머의 다시 로드 값을 입력합니다(ADC 하드웨어에서 지원하는 경우에만 해당).

Adc_PowerStateRequestResultType 타입

유형 Adc_PowerStateRequestResultType.

Adc_PowerStateType 타입

현재 활성 상태이거나 대상 전원 상태로 설정된 전원 상태입니다.

Adc_PrescaleType 타입

클록 프리스케일러 요소의 유형입니다. (이것은 API 유형이 아닙니다).

Adc_PriorityImplementationType 타입

우선순위 메커니즘을 구성하기 위한 유형입니다.

Adc_ResolutionType 타입

비트 수로 표시되는 채널 분해능 유형입니다. (이것은 API 유형이 아닙니다).

Adc_ResultAlignmentType 타입

ADC 결과 버퍼의 ADC 원시 결과 정렬 유형(왼쪽/오른쪽 정렬).

Adc_SamplingTimeType 타입

샘플링 시간 유형, 즉 값이 샘플링되는 시간(클럭 - 주기)입니다. (이것은 API 유형이 아닙니다).

Adc_StatusType 타입

요청하신 ADC 채널그룹 변환 현황입니다.

Adc_StreamBufferModeType 타입

스트리밍 액세스 모드 버퍼 유형을 구성하기 위한 유형입니다.

Adc_StreamNumSampleType 타입

스트리밍 액세스 모드에서 그룹 변환 횟수를 구성하는 유형입니다(단일 액세스 모드에서는 매개변수가 1입니다). 사용 가능 Adc.h AUTOSAR CP R20 - 문서 ID : AUTOSAR_SWS_ADCDriver를 통해

Adc_TriggerSourceType 타입

ADC 채널 그룹의 트리거 소스를 구성하는 유형입니다.

Adc_ValueGroupType 타입

시스템 아키텍처 & 모듈 클러스터의 역할

“Microcontroller Abstraction” 클러스터는 Classic Platform의 최하위 소프트웨어 계층을 형성합니다. ADC 및 PWM 드라이버 사양에서는 이러한 모듈이 최하위 아키텍처 계층에 위치하므로 하위 계층을 위한 콜백을 제공하지 않는다고 명시적으로 규정하고 있습니다(SWS ADC 79쪽, SWS PWM 40쪽). 이들의 사용자는 ECU 추상화 및 시스템 서비스의 모듈, 특히 IoHwAb, WdgIf/WdgM 그리고 EcuM 또는 BswM입니다. R20-11의 규범적 기준은 페이로드의 요구사항입니다. 이후 릴리스의 문서 위치는 IoHwAb의 ADC 예제(IoHwAb 55쪽)와 같이 설명 목적으로만 제공됩니다.

  • Adc는 아날로그 채널을 그룹 단위로 변환합니다. 변환은 소프트웨어 또는 하드웨어에 의해 트리거됩니다([SWS_Adc_00514]). 결과는 사용자가 제공하는 버퍼에 저장됩니다([SWS_Adc_91000]).
  • Pwm은 주기와 듀티 사이클을 갖는 펄스 폭 변조 신호를 생성합니다([SWS_Pwm_91001]). 선택적으로 신호 에지를 보고합니다([SWS_Pwm_00109]).
  • Wdg는 트리거 조건을 통해 내부 또는 외부 하드웨어 워치독을 처리합니다([SWS_Wdg_00144]).
  • Spi 및 Dio는 페이로드에서 외부 워치독의 액세스 경로로 입증되어 있습니다([SWS_Wdg_00076]). 페이로드에는 이 두 모듈의 자체 SWS 요구사항이 포함되어 있지 않습니다.
  • Port는 Port_Init을 통해 EcuM 인터페이스 목록에 “Initializes the Port Driver module”로 확인됩니다(SWS EcuM 142쪽). 다이어그램에서는 “Port Logic”을 PWM 장치와 핀 사이에 배치합니다(RS PWM 14쪽).

컨텍스트 다이어그램: MCAL 드라이버는 EcuM/BswM에 의해 초기화되고, IoHwAb 또는 WdgIf에 의해 사용되며, DET/DEM으로 오류를 보고합니다. 외부 워치독은 Spi 또는 Dio를 통해 하드웨어에 도달합니다. 출처: [SWS_Wdg_00076], [SWS_Adc_00082], [SWS_Pwm_00198], [SWS_Wdg_00111], [SWS_Adc_00377], [SWS_Pwm_00104], Modemanagement 54쪽

상호작용 & 인터랙션 경로

ADC 데이터 경로. 시퀀스는 결과 버퍼에서 시작됩니다.

  1. 각 리셋 후 및 첫 번째 그룹 변환 전에 사용자는 Adc_SetupResultBuffer을 사용하여 그룹의 결과 버퍼를 설정해야 합니다([SWS_Adc_91000], SWS ADC 54쪽).
  2. Adc_StartGroupConversion은 내부 버퍼 포인터를 초기화합니다. 이때 Notification은 자동으로 활성화되지 않습니다([SWS_Adc_00367], SWS ADC 57쪽).
  3. 각 그룹 변환이 완료된 후 드라이버는 IoHwAb_AdcNotification<#groupID>을 호출합니다([SWS_Adc_00082]).
  4. 사용자는 두 가지 방법 중 하나로 결과를 읽습니다:
    • Adc_ReadGroup은 이를 복사합니다([SWS_Adc_00369]).
    • Adc_GetStreamLastPointer은 버퍼 내의 포인터를 반환합니다([SWS_Adc_00375]).

버퍼가 수용하는 결과의 수는 액세스 모드(Single 또는 Streaming)에 따라 달라집니다([SWS_Adc_00528]). Streaming 모드에서 버퍼는 선형 또는 원형으로 구성됩니다([SWS_Adc_00519]).

시퀀스 다이어그램: Notification을 포함한 소프트웨어 트리거 연속 변환 – 버퍼 설정, Notification 활성화, 시작, 매 라운드 통지 및 읽기, 중지. 출처: SWS ADC 92쪽, [SWS_Adc_91000], [SWS_Adc_00082], SWS ADC 70쪽

PWM 제어 경로. 사용자는 두 가지 서비스를 통해 신호를 설정합니다:

  • Pwm_SetDutyCycle은 듀티 사이클만 변경합니다([SWS_Pwm_91000]).
  • Pwm_SetPeriodAndDuty은 주기와 듀티 사이클을 변경합니다([SWS_Pwm_91001]). 주기는 클래스 PWM_VARIABLE_PERIOD의 채널에 대해서만 변경할 수 있으며([SWS_Pwm_00110]), 그렇지 않은 경우 드라이버는 PWM_E_PERIOD_UNCHANGEABLE를 보고합니다([SWS_Pwm_40002]).

에지 통지는 Pwm_Notification_<#Channel>을 통해 사용자에게 전달됩니다. 기준이 되는 것은 Pwm_EnableNotification 또는 Pwm_DisableNotification의 마지막 호출입니다([SWS_Pwm_00105], [SWS_Pwm_91004]). Pwm_GetOutputState는 출력 신호의 내부 상태를 읽습니다([SWS_Pwm_00100]). 다이어그램에 따르면 이는 핀의 레벨이 아니라 포트 로직 이전의 탭입니다(RS PWM 14쪽).

워치독 경로. 호출 체인은 세 가지 계층을 거칩니다:

  • WdgM은 WdgIf_SetMode 및 WdgIf_SetTriggerCondition을 통해 드라이버를 제어합니다(SWS WdgM 86쪽).
  • WdgIf는 DeviceIndex을 통해 이러한 서비스를 각 드라이버 인스턴스에 매핑합니다(SWS WdgIf 17쪽).
  • Wdg는 밀리초 단위의 타임아웃을 카운터 값으로 변환하며, 이때 현재 모드를 고려합니다([SWS_Wdg_00138], [SWS_Wdg_00139]).

내부 및 외부 워치독은 하드웨어 액세스 방식에서만 차이가 있습니다:

  • 내부 드라이버는 하드웨어에 직접 액세스합니다([SWS_Wdg_00161]).
  • 외부 드라이버는 Spi 또는 Dio를 사용하며 구성에 필요한 매개변수를 포함합니다([SWS_Wdg_00076], [SWS_Wdg_00078]).
  • 두 변형의 API는 의미론적으로 동일합니다([SWS_Wdg_00077]).
  • 여러 인스턴스가 있는 경우 API 이름이 확장됩니다([SWS_Wdg_00172]).

시퀀스 다이어그램: 트리거 조건 설정은 주기적인 하드웨어 서비스와 시간적으로 분리되어 있으며, 카운터 값이 0이면 트리거가 발생하지 않습니다. 출처: SWS Wdg 31쪽, [SWS_Wdg_00134], [SWS_Wdg_00135], [SWS_Wdg_00136]

동기화, 재진입성 및 태스크 컨텍스트

모듈들은 재진입성 보장에서 뚜렷한 차이를 보입니다:

  • ADC의 데이터 경로 API는 재진입 가능합니다.
  • 채널 관련 PWM 서비스는 서로 다른 채널에 대해서만 재진입 가능합니다.
  • 초기화, 파워 상태 API 및 모든 Wdg 서비스는 재진입할 수 없습니다.

데이터 일관성을 위해 Wdg는 BSW 스케줄러를 통해 전용 영역을 정의합니다. MCAL 모듈로서 내부 드라이버는 인터럽트를 직접 비활성화할 수도 있습니다([SWS_Wdg_00040]). 모드 변경 및 서비스 루틴 중에는 상태 WDG_BUSY이 동시 액세스를 나타냅니다([SWS_Wdg_00018], [SWS_Wdg_00052]).

스케줄링된 함수. SchM을 통해 주기적으로 실행되는 것은 Adc_Main_PowerTransitionManager 및 Pwm_Main_PowerTransitionManager입니다([SWS_Adc_00479], [SWS_Pwm_00189]). 이들의 주기는 전환이 진행 중일 때만 필요하기 때문에 가변적입니다([SWS_Adc_00500]). 초기화 전에는 DET 보고 없이 반환됩니다([SWS_Adc_00502]).

인터럽트 컨텍스트. 그룹 및 에지 Notification은 인터럽트 컨텍스트에서 실행될 것으로 추정됩니다. 이를 뒷받침하는 근거는 두 가지입니다: PWM 드라이버는 Notification에 속한 인터럽트 플래그를 리셋합니다(SWS PWM 42쪽). 또한 MemMap 예제는 BswInterruptEntity Adc_IsrGroupScanCompleted를 포함합니다(SWS MemMap 54쪽). 따라서 콜백은 짧게 유지되어야 합니다. Pwm_Notification_<#Channel>의 재진입성은 명시적으로 사용자의 구현에 달려 있습니다([SWS_Pwm_00105]).

멀티코어 시스템. Adc 및 Pwm은 구현에서 지원하지 않는 파티션 할당을 거부해야 합니다([SWS_Adc_00531], [SWS_Pwm_00203]). ADC의 커널 파티션은 사용자 파티션의 하위 집합입니다([SWS_Adc_CONSTR_00001]). 이는 커널과 인터페이스 부분으로 분할되는 마스터-새틀라이트 패턴과 일치합니다(BSW Distribution 18쪽).

수명 주기 및 동작 모드

초기화. EcuM은 Adc_Init을 호출합니다([SWS_Adc_00365], SWS ADC 91쪽). EcuM의 구조 설명에서는 추가로 Port_Init, Pwm_Init, Spi_Init 및 Wdg_Init을 명시합니다(SWS EcuM 34쪽). BswM 제어 변형은 Port, Dio, Adc, Spi 순서로 초기화합니다(Modemanagement 54쪽). 해석: 핀 구성이 다른 주변장치 드라이버의 전제 조건이기 때문에 Port가 맨 앞에 오는 것으로 추정됩니다.

ADC. 드라이버는 Adc_Init을 사용하여 ADC_UNINIT에서 ADC_INIT(으)로 전환하고 Adc_DeInit을 사용하여 되돌아옵니다(SWS ADC 31쪽). 각 그룹은 ADC_IDLE, ADC_BUSY, ADC_COMPLETED 및 ADC_STREAM_COMPLETED 상태를 거칩니다([SWS_Adc_00513]). Continuous 모드는 소프트웨어 트리거에서만 사용할 수 있습니다([SWS_Adc_00515]). Adc_DeInit은 하드웨어를 리셋과 유사한 상태로 만듭니다([SWS_Adc_00366]). 이는 모든 그룹이 ADC_IDLE에 있을 때만 호출할 수 있습니다(SWS ADC 59쪽).

PWM. Pwm_Init 이후 출력은 구성에 따라 Low, High 또는 변조 상태가 됩니다. Notification은 Pwm_EnableNotification이 호출될 때까지 비활성 상태를 유지합니다([SWS_Pwm_00095], SWS PWM 46쪽). Pwm_DeInit는 출력을 Idle 상태로 설정하고 인터럽트를 비활성화합니다([SWS_Pwm_00096], SWS PWM 27쪽).

워치독. Wdg_Init은 기본 모드와 초기 타임아웃을 설정합니다([SWS_Wdg_00001], [SWS_Wdg_00100]). 그 후 모드 WDGIF_OFF_MODE, WDGIF_SLOW_MODE 및 WDGIF_FAST_MODE를 선택할 수 있습니다([SWS_Wdg_00160]). DeInit 함수는 존재하지 않습니다. 허용되는 경우 OFF 모드를 통해 전원을 끕니다([SWS_Wdg_00031]).

Adc 및 Pwm의 파워 상태. 전환은 2단계로 진행됩니다:

  1. *_PreparePowerState이 이를 개시합니다([SWS_Adc_00478], [SWS_Pwm_00183]).
  2. 비동기식의 경우 Main 함수가 이를 완료하고 IoHwAb_*_NotifyReadyForPowerState<#Mode>을 통해 준비 완료를 보고합니다([SWS_Adc_00480], [SWS_Pwm_00198]).
  3. *_SetPowerState이 전환을 수행합니다([SWS_Adc_00475], [SWS_Pwm_00166]).

사전에 IoHwAb와 같은 담당 SWC는 채널을 Idle로 설정하고 Notification을 등록 해제해야 합니다(SWS PWM 36쪽). 전환 자체 중에는 전환 전용 재구성만 허용됩니다([SWS_Adc_00484]).

시퀀스 다이어그램: IoHwAb는 BswM 모드 변경 후 Ready 콜백을 사용한 비동기 방식 또는 폴링을 통한 동기 방식으로 Adc 및 Pwm의 2단계 파워 상태 전환을 조정합니다. 출처: IoHwAb 57쪽, IoHwAb 58쪽, [SWS_Adc_00501], [SWS_Pwm_00190]

오류 처리, DET 추적 및 성능 저하

개발 오류 (DET). 지정된 세 드라이버 모두 Det_ReportError을 통해 이를 보고합니다([SWS_Adc_00377], [SWS_Pwm_00104], [SWS_Wdg_00111]):

  • Adc는 특히 ADC_E_UNINIT 및 ADC_E_PARAM_GROUP을 보고합니다([SWS_Adc_91005]).
  • Pwm은 PWM_E_UNINIT 및 PWM_E_PARAM_CHANNEL을 보고합니다([SWS_Pwm_20002], [SWS_Pwm_30002]).
  • Wdg는 잘못된 상태일 때 WDG_E_DRIVER_STATE을 보고합니다([SWS_Wdg_00017], [SWS_Wdg_00035]).

런타임 오류. 여기에는 몇 가지 경우가 있습니다:

  • ADC는 큐잉 없는 변환이 이미 실행 중인 경우 등에 ADC_E_BUSY을 보고합니다([SWS_Adc_91006], SWS ADC 95쪽).
  • 파워 상태 전환 시 채널이 여전히 활성 상태인 경우 두 드라이버 모두 *_E_NOT_DISENGAGED을 보고합니다([SWS_Adc_00487], [SWS_Pwm_00202]).
  • R20-11에서 ADC는 도달할 수 없는 목표 전원 상태(Power State)를 런타임 오류로 분류하는 반면([SWS_Adc_00489]), PWM은 이를 DET 오류로 분류합니다([SWS_Pwm_00175]).

생산 오류(DEM). 이는 페이로드에서 Wdg에 대해서만 지정되어 있으며 Dem_SetEventStatus을(를) 통해 보고됩니다([SWS_Wdg_00111]):

  • 모드 전환 실패 시 WDG_E_MODE_FAILED; 이 경우 Wdg_SetMode은(는) E_NOT_OK을(를) 반환합니다([SWS_Wdg_00016], [SWS_Wdg_00180]).
  • 비활성화가 허용되지 않는 경우 WDG_E_DISABLE_REJECTED([SWS_Wdg_00025], [SWS_Wdg_00182]).

성능 저하 및 안전 상태.

  • Pwm_SetOutputToIdle은(는) 출력을 구성된 Idle 상태로 즉시 설정합니다([SWS_Pwm_91002], SWS PWM 31쪽).
  • Pwm_GetOutputState은(는) 초기화 전이거나 유효하지 않은 채널인 경우 방어적으로 PWM_LOW을(를) 반환합니다([SWS_Pwm_30051]).
  • Watchdog에서 리셋은 최후의 폴백 레벨입니다. 타임아웃 0은 거의 즉각적인 ECU 리셋을 트리거합니다([SWS_Wdg_00140]). 만료된 트리거 카운터는 Watchdog을 만료되게 합니다([SWS_Wdg_00135]).
  • 드라이버는 너무 큰 타임아웃을 WDG_E_PARAM_TIMEOUT(으)로 거부합니다([SWS_Wdg_00146]).
  • ADC에서는 Abort/Restart 또는 Suspend/Resume을 사용하는 우선순위 메커니즘이 선점된 그룹을 재개하는 방식을 제어합니다([SWS_Adc_00522], [SWS_Adc_00523]). 한계값 검사는 선택된 범위를 벗어난 결과를 필터링합니다([SWS_Adc_00524]).

페이로드에 포함된 R20-11 요구사항 및 문서 위치를 기반으로 AI가 생성한 클러스터 가이드입니다. Dio, Port 및 Spi는 페이로드에 자체 요구사항이 없어 다른 모듈과의 인터페이스를 통해서만 설명됩니다. 링크된 사양 요소가 구속력을 갖습니다.

ADC Driver (Adc)
