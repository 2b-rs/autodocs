비휘발성 데이터 블록을 관리하며, 이를 RAM과 NV 메모리 간에 비동기적으로 동기화합니다.

NVRAM Manager(NvM)는 비휘발성 메모리로 접근하는 유일한 통로입니다. 이는 NVRAM 블록을 RAM과 NV 메모리 간에 암시적으로 복사합니다 [SWS_NvM_00038]. 시작 시에는 BswM에 의해 트리거된 NvM_ReadAll이 RAM 블록을 채우고, 셧다운 시에는 NvM_WriteAll가 변경된 블록을 저장합니다. NvM_WriteBlock과 같은 개별 요청은 비동기적으로 큐에 등록되어 우선순위에 따라 처리되며, 상태 또는 콜백을 통해 확인 응답됩니다 [SWS_NvM_00185]. NvM은 재시도, 중복 복사본 및 기본 데이터를 통해 읽기 오류를 처리하지만, 사용자는 여전히 블록 상태를 직접 확인해야 합니다.

NVRAM Manager(NvM)는 비휘발성 메모리로의 유일한 접근 통로입니다 [SWS_NvM_00384]. 이는 블록을 NVRAM과 RAM 간에 암시적으로 복사하며, 애플리케이션은 RAM 데이터와 직접 작동합니다 [SWS_NvM_00038]. 하위로는 Fee 또는 Ea와 함께 Memory Abstraction Interface를 사용합니다 [SWS_NvM_00051]. 상태는 BswM에 보고하고 오류는 DEM 및 DET에 보고합니다 [SWS_NvM_00745] [SWS_NvM_00592].

컨텍스트 다이어그램: 사용자, BswM, MemIf/Fee/Ea 그리고 DEM 및 DET 사이의 NvM 임베딩. 출처: [SWS_NvM_00384] [SWS_NvM_00465] [SWS_NvM_00746]

각 NVRAM 블록은 NV 블록, RAM 블록 및 Administrative Block으로 구성되며, 선택적으로 기본 데이터가 포함된 ROM 블록이 추가됩니다 [SWS_NvM_00138]. Native, Redundant 및 Dataset 유형이 있으며, 이들은 NV 및 ROM 블록의 수에서 차이가 납니다 [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559]. NvM은 RAM 블록을 직접 암시적으로 동기화하거나 콜백이 있는 RAM 미러를 통해 명시적으로 동기화합니다 [SWS_NvM_00511].

수명 주기는 세 단계로 진행됩니다:

  • BswM이 NvM_Init을 독점적으로 호출합니다 [SWS_NvM_00693].
  • NvM_ReadAll은 먼저 구성 ID를 확인한 다음 RAM 블록을 채웁니다 [SWS_NvM_00073] [SWS_NvM_00718].
  • 셧다운 시 NvM_WriteAll이 변경된 블록을 저장합니다 [SWS_NvM_00092]. NvM_CancelWriteAll는 비파괴적으로 중단합니다 [SWS_NvM_00238].

NvM_WriteBlock과 같은 개별 요청은 큐에 등록된 후 NVM_REQ_PENDING 상태가 됩니다 [SWS_NvM_00185]. 선택적으로 NvM은 Immediate 요청을 위한 전용 큐를 사용합니다 [SWS_NvM_00378]. 결과는 NvM_GetErrorStatus 또는 구성된 콜백이 제공합니다 [SWS_NvM_00015] [SWS_NvM_00740].

시퀀스 다이어그램: 비동기 쓰기 요청이 큐에 등록되고, NvM_MainFunction에서 처리되며, 콜백, BswM 알림 및 상태 조회를 통해 확인 응답됩니다. 출처: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00891], SWS NvM 160쪽

NvM은 세 단계를 통해 읽기 오류를 처리합니다:

  • 구성된 읽기 재시도 [SWS_NvM_00526],
  • 중복 블록의 두 번째 복사본 [SWS_NvM_00199],
  • 결과 NVM_REQ_RESTORED_DEFAULTS을 동반한 기본 데이터 [SWS_NvM_00202].

Interpretation: 단계의 순서는 Error Description의 열거를 따를 것으로 추정됩니다. 질문 Q-027e7f981e4d0a43 (열림) NvM은 쓰기 오류 시 NVM_MAX_NUM_OF_WRITE_RETRIES까지 재시도한 다음 DEM에 NVM_E_REQ_FAILED을 보고합니다 [SWS_NvM_00684]. 사용자는 자신의 블록 상태를 직접 확인합니다 [SWS_NvM_00694].

메모리 스택에서의 역할: 비휘발성 메모리로의 유일한 접근 통로

NVRAM Manager(NvM)는 비휘발성 데이터에 대한 접근을 통합합니다. 환경은 NvM만을 통해 비휘발성 메모리와 통신하며, NvM은 이를 위해 콜백 인터페이스를 제공합니다 [SWS_NvM_00384]. 접근은 암시적입니다. NvM은 NVRAM과 공유 RAM 간에 블록을 복사합니다. 애플리케이션은 동기화 규칙을 준수하면서 RAM 데이터와 직접 작동합니다 [SWS_NvM_00038] [SWS_NvM_00692]. 블록은 구성된 블록 ID를 통해 선택됩니다 [SWS_NvM_00069] [SWS_NvM_00471]. 상위 계층은 이를 위해 NvM.h만을 포함합니다 [SWS_NvM_00691]. 암시적 업데이트에 관한 다이어그램은 역할 분담을 보여줍니다. 기본 소프트웨어의 다른 부분들이 ECU 상태에 따라 모든 블록의 저장 및 복원을 트리거합니다. SW-C는 해당 RAM 블록의 내용에만 접근합니다(SWS NvM 121쪽).

하위 계층에 대해 NvM은 Memory Abstraction Interface와 연동합니다. 이는 Fee 또는 Ea와 함께 가상 선형 32비트 주소 공간을 제공합니다 [SWS_NvM_00051] [SWS_NvM_00465]. NvM은 Crc 모듈을 통해 체크섬을 생성합니다 [SWS_NvM_00466]. 하위 계층 작업의 종료는 두 가지 방식으로 인식합니다:

  • MemIf_GetJobResult을 통한 폴링 방식,
  • 폴링이 비활성화된 경우 NvM_JobEndNotification 및 NvM_JobErrorNotification을 통한 방식 [SWS_NvM_00440] [SWS_NvM_00441] (Error Description 43쪽).

프로덕션 오류는 DEM으로 전송되고 [SWS_NvM_00592], 개발 오류는 DET로 전송됩니다 [SWS_NvM_00614]. NvM은 작업 상태를 BswM에 보고합니다 [SWS_NvM_00745] [SWS_NvM_00746].

컨텍스트 다이어그램: NvM은 한쪽의 사용자와 BswM, 다른 쪽의 MemIf/Fee/Ea 사이를 중개합니다. 오류는 DEM과 DET에 보고합니다. 출처: [SWS_NvM_00384] [SWS_NvM_00745] [SWS_NvM_00746] [SWS_NvM_00465] [SWS_NvM_00466], Error Description 43쪽

NVRAM 블록의 구조와 세 가지 관리 유형

NVRAM 블록은 필수 구성 요소인 NV 블록, RAM 블록 및 Administrative Block으로 이루어집니다. 기본 데이터가 포함된 ROM 블록은 선택 사항입니다 [SWS_NvM_00138] [SWS_NvM_00139] [SWS_NvM_00020]. 구성 요소의 조합은 구성 시 블록 디스크립터에 의해 결정됩니다 [SWS_NvM_00140]. 개별 구성 요소:

  • NV 블록은 페이로드와 선택적 CRC 및 헤더를 포함합니다 [SWS_NvM_00125] (SWS NvM 39쪽).
  • RAM 블록은 주소 제한 없이 글로벌 RAM에 위치할 수 있습니다 [SWS_NvM_00088].
  • Administrative Block은 애플리케이션에 표시되지 않습니다. 이는 데이터세트 인덱스, 속성 및 오류/상태 필드를 보유합니다 [SWS_NvM_00134] [SWS_NvM_00135] [SWS_NvM_00136].

NvM은 NVM_BLOCK_NATIVE, NVM_BLOCK_REDUNDANT 및 NVM_BLOCK_DATASET 유형을 지원합니다 [SWS_NvM_00137]. 이들은 NV 및 ROM 블록의 수에서 차이가 납니다 [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] (SWS NvM 10쪽). Dataset 블록의 경우 다음이 적용됩니다:

  • NvM_SetDataIndex이 요소를 선택합니다. NvMNvBlockNum 이상의 인덱스는 ROM 블록을 어드레싱합니다 [SWS_NvM_00014] [SWS_NvM_00445] (NV Data Handling 10쪽).
  • 인덱스는 영구적으로 저장되지 않으며, NvM_Init이 이를 0으로 설정합니다 [SWS_NvM_00160] [SWS_NvM_00192].
  • 올바른 설정에 대한 책임은 SW-C에 있습니다 [SWS_NvM_00695].

협업 다이어그램(블록 구조): 관리 유형별 카디널리티를 포함한 NVRAM 블록의 필수 및 선택적 구성 요소. 출처: [SWS_NvM_00138] [SWS_NvM_00557] [SWS_NvM_00558] [SWS_NvM_00559] [SWS_NvM_00134], SWS NvM 10쪽

수명 주기: NvM_Init, NvM_ReadAll 및 NvM_WriteAll

BswM이 NvM_Init을 독점적으로 호출합니다 [SWS_NvM_00693]. NvM_Init는 큐와 상태 머신을 재설정하고 내부적으로 "INIT DONE"을 신호합니다 [SWS_NvM_00399]. 이는 RAM 블록이나 하위 모듈을 초기화하지 않습니다 [SWS_NvM_00091] [SWS_NvM_00193]. 구성 포인터는 항상 NULL_PTR입니다 [SWS_NvM_00881]. 그 이후에야 NvM_MainFunction이 요청을 처리합니다 [SWS_NvM_00257].

이어서 NvM_ReadAll이 RAM 블록을 채웁니다 [SWS_NvM_00718]. 이 호출은 요청만을 신호합니다. 처리는 개별 블록 요청이 완료될 때까지 연기됩니다 [SWS_NvM_00243]. 그 후 작업은 세 단계로 실행됩니다:

  1. 먼저 저장된 구성 ID와 컴파일된 구성 ID를 비교합니다 [SWS_NvM_00073]. 불일치할 경우의 동작은 NvMDynamicConfiguration에 따라 달라집니다. NvMDynamicConfiguration == FALSE의 경우 불일치가 무시됩니다 [SWS_NvM_00248]. 그렇지 않으면 변경에 저항력이 없는 블록에 기본 데이터가 제공됩니다 [SWS_NvM_00249] [SWS_NvM_00674] (NV Data Handling 15쪽).
  2. 그런 다음 블록 ID 0 및 1을 제외한 사용자 블록을 순회합니다 [SWS_NvM_00244]. 이때 영구 RAM 블록이 있거나 명시적 동기화를 사용하는 블록만 처리합니다 [SWS_NvM_00118].
  3. 마지막으로 전체 결과를 NVM_REQ_OK 또는 NVM_REQ_NOT_OK로 설정합니다 [SWS_NvM_00895] [SWS_NvM_00301].

모드 관리 예제에서 BswM 규칙 NvMReadAllFinished은 NvM_ReadAll이 완료된 후에야 나머지 초기화를 시작합니다 (Mode Management Guide 31쪽).

시퀀스 다이어그램: NvM_Init, NvM_ReadAll을 통한 비동기 시작 및 BswM으로의 다중 블록 상태 피드백. 출처: [SWS_NvM_00693] [SWS_NvM_00243] [SWS_NvM_00073] [SWS_NvM_00888] [SWS_NvM_00889], NV Data Handling 20쪽

셧다운 시 BswM이 NvM_WriteAll을 호출합니다 [SWS_NvM_00092]. 작업은 다음과 같이 동작합니다:

  • 영구 RAM 블록을 쓰거나, NvM_WriteRamBlockToNvm을 통해 명시적으로 동기화된 데이터를 가져옵니다 [SWS_NvM_00252].
  • 사전에 "valid/modified" 상태를 확인합니다 [SWS_NvM_00682].
  • 보호되거나 잠긴 블록은 오류 보고 없이 건너뜁니다 [SWS_NvM_00434] [SWS_NvM_00750].
  • 다른 요청이 이를 중단시키지 않습니다 [SWS_NvM_00567].

API가 활성화되어 있는 경우, 사용자는 NvM_SetRamBlockStatus(…, TRUE)을 사용하여 변경된 블록을 표시합니다 [SWS_NvM_00406] [SWS_NvM_00408]. Dirty Flag 블록의 경우 RTE가 이 호출을 수행합니다 (NV Data Handling 41쪽).

NvM_CancelWriteAll은 BswM 전용이며 [SWS_NvM_00703], 실행 중인 NvM_WriteAll가 없으면 아무런 효과가 없습니다 [SWS_NvM_00233]. 현재 블록은 비파괴적으로 완료됩니다 [SWS_NvM_00238]. 나머지 블록 및 다중 블록 결과는 NVM_REQ_CANCELED를 받습니다 [SWS_NvM_00236] [SWS_NvM_00237] (SWS NvM 161쪽).

두 개의 추가 다중 블록 요청이 수명 주기를 보완합니다:

  • NvM_ValidateAll은 자동 유효성 검사가 설정된 블록을 "VALID / CHANGED"로 설정합니다 [SWS_NvM_00856].
  • NvM_FirstInitAll은 블록에 기본 데이터를 쓰거나, 기본 데이터가 없는 경우 블록을 무효화합니다 [SWS_NvM_00913] [SWS_NvM_00919].

모든 다중 블록 요청에 대해 큐 길이는 1이 적용됩니다 [SWS_NvM_00380].

시퀀스 다이어그램: NvM_WriteAll을 사용한 셧다운 및 NvM_CancelWriteAll에 의한 선택적 중단. 출처: [SWS_NvM_00092] [SWS_NvM_00682] [SWS_NvM_00238] [SWS_NvM_00237] [SWS_NvM_00889], Mode Management Guide 37쪽

개별 요청: 큐, 우선순위 및 피드백

NvM_ReadBlock, NvM_WriteBlock 또는 NvM_RestoreBlockDefaults와 같은 개별 블록 요청은 비동기적입니다. 함수는 매개변수를 인계받아 요청을 큐에 등록하고 리턴합니다 [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00224]. 그 후 블록 결과는 NVM_REQ_PENDING 상태가 됩니다 [SWS_NvM_00185]. 큐 오버플로 시 함수는 E_NOT_OK을 반환합니다 [SWS_NvM_00184]. 블록은 이미 대기 중이거나 처리 중이 아닐 때만 큐에 등록됩니다 [SWS_NvM_00385].

다른 서비스들은 NvM_SetDataIndex, [SWS_NvM_00448] 및 NvM_GetErrorStatus와 같이 호출자의 컨텍스트에서 동기적으로 작동합니다 (SWS NvM 158쪽). NvM_CancelJobs는 블록의 대기 중인 요청을 제거하지만, 실행 중인 작업은 계속 진행됩니다 [SWS_NvM_00536] [SWS_NvM_00537].

처리는 우선순위에 따라 직렬화되어 수행됩니다 [SWS_NvM_00162]. NvMJobPrioritization이 활성화된 경우 NvM은 두 개의 큐를 사용하며, 그중 하나는 Immediate 쓰기 요청(충돌 데이터)을 위한 것입니다 [SWS_NvM_00564] [SWS_NvM_00378]. 이러한 NvM_WriteBlock는 대기 중인 작업을 파괴적으로 중단합니다 [SWS_NvM_00300]. NvM_MainFunction은 중단된 작업을 이후에 다시 시작합니다 [SWS_NvM_00258]. 우선순위 지정이 없으면 NvM은 Immediate 작업 없이 수신된 순서대로 작업합니다 [SWS_NvM_00379]. 다중 블록 요청 중에 수신된 요청은 큐에 등록된 후 이어서 실행됩니다 [SWS_NvM_00568] [SWS_NvM_00569].

각 비동기 요청은 오류/상태 필드에 결과를 저장합니다 [SWS_NvM_00175]. NvM_GetErrorStatus은 이 필드를 읽습니다 [SWS_NvM_00015]. 이외에도 두 가지 선택적 피드백 경로가 있습니다:

  • 콜백이 구성된 경우 NvM_MainFunction이 NvM_SingleBlockCallbackFunction을 호출합니다 [SWS_NvM_00740] [SWS_NvM_00347]. 콜백이 없으면 비동기 알림이 없습니다 [SWS_NvM_00742] (SWS NvM 160쪽).
  • NvM은 NvMBswMBlockStatusInformation을 통해 수락 및 결과를 BswM에 보고합니다 [SWS_NvM_00890] [SWS_NvM_00891] (SWS NvM 162쪽).

시퀀스 다이어그램: BswM 상태 알림, 콜백 및 상태 조회가 포함된 비동기 쓰기 요청. 출처: [SWS_NvM_00185] [SWS_NvM_00347] [SWS_NvM_00740] [SWS_NvM_00890] [SWS_NvM_00891], SWS NvM 160쪽

RAM 블록 동기화 및 블록 상태

NvM에는 애플리케이션의 RAM 블록과 데이터를 동기화하는 두 가지 방법이 있습니다. 암시적 동기화의 경우 이 RAM 블록에서 직접 작업합니다. 애플리케이션은 블록을 제공하고 요청이 완료될 때까지 해당 블록에 접근하지 않습니다 [SWS_NvM_00698] [SWS_NvM_00699]. 애플리케이션이 NULL_PTR를 전달하면 NvM은 영구 RAM 블록을 사용합니다 [SWS_NvM_00898] [SWS_NvM_00900]. 포인터를 통한 임시 블록도 여전히 가능합니다 [SWS_NvM_00278]. PRAM 서비스는 항상 영구 RAM 블록에서 작동합니다 [SWS_NvM_00765] [SWS_NvM_00794]. RTE 시나리오에서 이 블록은 Per-Instance-Memory입니다 (NV Data Handling 32쪽).

명시적 동기화(NvMBlockUseSyncMechanism)의 경우 교환은 내부 RAM 미러를 통해 실행됩니다 [SWS_NvM_00511]. 이는 정확히 하나만 존재하며, 영향을 받는 가장 큰 블록에 맞추어 크기가 결정됩니다 [SWS_NvM_00513]. NvM은 NvMWriteRamBlockToNvCallback 또는 NvMReadRamBlockFromNvCallback를 호출합니다 [SWS_NvM_00515] [SWS_NvM_00516]. 콜백이 E_NOT_OK을 반환하면 다음 주기에서 호출을 최대 NvMRepeatMirrorOperations회까지 재시도합니다 [SWS_NvM_00579] [SWS_NvM_00840]. 콜백 전까지 애플리케이션은 여전히 RAM 블록을 수정할 수 있습니다 [SWS_NvM_00705]. 블록은 명시적 동기화 또는 영구 RAM 블록 중 하나만 사용하며, 둘 다 사용하지는 않습니다 [SWS_NvM_00904]. 이 메커니즘을 통해 NvBlockSwComponentType을 통한 공유 블록이 가능합니다 (NV Data Handling 12쪽).

시퀀스 다이어그램: E_NOT_OK에서의 재시도를 포함한 RAM 미러를 통한 명시적 동기화 쓰기 요청. 출처: [SWS_NvM_00515] [SWS_NvM_00705] [SWS_NvM_00579] [SWS_NvM_00840], NV Data Handling 27쪽

영구 RAM 블록 또는 미러에 대해 NvM은 "valid"/"invalid" 상태를 유지합니다 [SWS_NvM_00128] [SWS_NvM_00132]. 세부 전이:

  • NvM_ReadBlock은 큐에 등록할 때 이미 영구 RAM 블록을 무효화합니다 [SWS_NvM_00198].
  • 성공적으로 읽은 후에는 "valid/unchanged" 상태가 됩니다 [SWS_NvM_00200].
  • 기본 데이터를 로드한 후에는 "valid/changed" 상태가 됩니다 [SWS_NvM_00366].
  • NvM_SetRamBlockStatus(…, TRUE)은 이를 변경됨으로 표시하고 백그라운드에서 CRC 재계산을 트리거합니다 [SWS_NvM_00406] [SWS_NvM_00121].
  • 성공적으로 쓴 후에는 "valid/unmodified"로 간주됩니다 [SWS_NvM_00472].

상태 다이어그램: RAM 블록 상태 및 트리거 이벤트. 출처: [SWS_NvM_00198] [SWS_NvM_00200] [SWS_NvM_00366] [SWS_NvM_00406] [SWS_NvM_00472] [SWS_NvM_00856]

구성, 보호 메커니즘 및 파티션 참조

제한된 리소스를 위해 세 가지 API 구성 클래스가 있습니다 [SWS_NvM_00149]. 클래스 1은 Dataset 블록을 지원하지 않습니다 [SWS_NvM_00365]. 디스크립터 테이블이 생성됩니다 [SWS_NvM_00143]. 메모리 요구 사항은 구성 시 사용자가 선언합니다 [SWS_NvM_00030]. BSW 모듈은 NvBlockNeeds를 통해 이를 수행합니다 (BSWMD Template 241쪽). ECU 통합자는 이를 바탕으로 NvM 구성을 도출합니다 (Methodology 444쪽).

개별 블록을 위해 여러 보호 메커니즘을 사용할 수 있습니다:

  • 속성 필드가 쓰기 방지를 관리하며 [SWS_NvM_00054], NvMBlockWriteProt이 이를 기본값으로 활성화합니다 [SWS_NvM_00326].
  • NvMWriteBlockOnce이 설정된 블록은 한 번만 기록됩니다 [SWS_NvM_00397]. 최초 읽기 전의 쓰기 요청은 NvM이 거부합니다 [SWS_NvM_00952].
  • 잠긴 블록(NvM_SetBlockLockStatus)에 대해 NvM_WriteBlock은 E_NOT_OK를 반환합니다 [SWS_NvM_00749]. NvM_SetRamBlockStatus도 NvM_SetBlockProtection도 잠금을 변경하지 않습니다 [SWS_NvM_00754].
  • 선택 사항으로는 정적 블록 ID 헤더 [SWS_NvM_00522], 불필요한 쓰기를 방지하기 위한 CRC 비교 [SWS_NvM_00849], CSM을 통한 암호화 [SWS_NvM_00976]도 있습니다.

파티셔닝의 경우 NvM은 각각 할당된 파티션의 컨텍스트에서 인터페이스를 호출합니다. 일반 함수는 마스터 파티션에서 실행됩니다 [SWS_NvM_00969]. NvM_ReadAll 및 NvM_WriteAll는 마스터에서만 제공합니다 [SWS_NvM_00970] [SWS_NvM_00971] [SWS_NvM_CONSTR00974]. SW-C는 블록 관련 포트를 통해 NvM에 도달합니다:

  • PS_{Block} (서비스) [SWS_NvM_00847]
  • PAdmin_{Block} (관리) [SWS_NvM_00843]
  • PM_{Block} (미러) [SWS_NvM_00844]
  • PNJF_{Block} (작업 종료 알림) [SWS_NvM_00846]

오류가 발생한 경우의 동작

읽기 시 NvM은 MemIf의 메시지를 다르게 평가합니다:

  • CRC 불일치는 NVM_E_INTEGRITY_FAILED으로 보고합니다 [SWS_NvM_00203].
  • MEMIF_JOB_FAILED은 NVM_E_REQ_FAILED로 보고합니다 [SWS_NvM_00654].
  • MEMIF_BLOCK_INVALID은 DEM 보고 없이 NVM_REQ_NV_INVALIDATED만을 생성합니다 [SWS_NvM_00341] [SWS_NvM_00652].

그 후 여러 복구 단계가 적용됩니다:

  1. CRC 오류의 경우 구성된 읽기 재시도가 따릅니다 [SWS_NvM_00526].
  2. 중복 블록의 경우 NvM은 두 번째 복사본을 읽고 중복성을 복원하려고 시도합니다 [SWS_NvM_00199] [SWS_NvM_00531]. 실패하면 NVM_E_LOSS_OF_REDUNDANCY를 보고합니다 [SWS_NvM_00546].
  3. 마지막으로 NvM은 결과 NVM_REQ_RESTORED_DEFAULTS과 함께 기본 데이터를 로드합니다 [SWS_NvM_00202]. 이때 NV 내용은 변경되지 않은 상태로 유지됩니다 [SWS_NvM_00172].

기본 데이터가 없으면 RAM 블록은 유효하지 않은 상태로 유지됩니다 [SWS_NvM_00658] [SWS_NvM_00204]. Interpretation: 단계의 순서는 Error Description의 열거를 따를 것으로 추정됩니다 (Error Description 62쪽). 질문 (열림) 이 출처는 두 가지 점에서 요구사항과 차이가 있습니다. NVM_REQ_RESTORED_DEFAULTS 대신 NVM_REQ_RESTORED_FROM_ROM을 언급합니다. 또한 최종 실패를 일괄적으로 NVM_E_REQ_FAILED로 요약합니다. 규범적인 것은 위에 언급된 요구사항입니다.

액티비티 다이어그램: 재시도부터 중복 복사본, 기본 데이터 로드에 이르는 읽기 오류 처리. Interpretation: 순서는 Error Description의 열거를 따릅니다. 출처: [SWS_NvM_00526] [SWS_NvM_00199] [SWS_NvM_00202] [SWS_NvM_00341] [SWS_NvM_00658], Error Description 62쪽

쓰기 시 NvM은 부정적인 피드백을 NVM_MAX_NUM_OF_WRITE_RETRIES까지 카운트합니다 [SWS_NvM_00213] [SWS_NvM_00216]. 한도를 초과하면 NVM_REQ_NOT_OK을 설정하고 NVM_E_REQ_FAILED를 보고합니다 [SWS_NvM_00683] [SWS_NvM_00684] (Error Description 43쪽). 두 가지 추가 오류 양상:

  • 쓰기 검증이 실패하면 NvM은 NVM_E_VERIFY_FAILED을 보고하고 쓰기를 재시도합니다 [SWS_NvM_00528] [SWS_NvM_00529].
  • 중복 블록은 한 복사본이 성공하는 즉시 작성된 것으로 간주됩니다 [SWS_NvM_00284].

개발 오류 감지가 활성화된 경우 NvM은 잘못된 조작을 DET에 보고합니다. 예로는 NVM_E_UNINIT 및 NVM_E_BLOCK_PENDING [SWS_NvM_00614] [SWS_NvM_00615]과 NVM_E_WRITE_PROTECTED [SWS_NvM_00962]가 있습니다. 다중 블록 요청은 단일 블록이 실패하는 즉시 NVM_REQ_NOT_OK으로 종료됩니다 [SWS_NvM_00318]. 사용자는 자신의 블록 상태를 직접 확인합니다 [SWS_NvM_00694]. 읽기가 실패한 후에는 다음 쓰기 전에 유효한 데이터를 제공합니다 [SWS_NvM_00696].

호출되는 동안 이 함수는 다음 동작을 수행합니다:

  • 상태 머신, 작업 큐 및 요청 플래그를 포함한 모든 내부 변수를 초기값으로 재설정[SWS_NvM_00399].
