역할 및 시스템 경계: 센서 이벤트에서 적격 Security Event까지

Intrusion Detection System Manager(IdsM)는 표준화된 인터페이스를 통해 온보드 Security Event(SEv)를 수신하는 Classic Platform의 BSW 모듈입니다. 이는 구성 가능한 규칙에 따라 이를 필터링하여 적격 이벤트(QSEv)로 만든 다음, 저장하거나 전송합니다 SWS IdsM 7쪽. 센서로는 BSW 모듈, 독자적인 CDD 및 SW-C가 보고합니다. 싱크는 PduR을 통해 도달하는 IDS Reporter(IdsR) 및 로컬 저장을 위한 DEM/Sem입니다 SWS IdsM 16쪽 [SWS_IdsM_01202] [SWS_IdsM_01601].

IdsM은 시스템이 실제로 침해되었는지 여부를 명시적으로 평가하지 않습니다. 컨텍스트 데이터의 의미를 알지 못하며, 탐지 및 대응은 SOC와 같이 모듈 외부에 위치합니다 [SWS_IdsM_CONSTR_00001]. 또한 사양서는 보고 빈도나 시스템 부하에 따라 SEv가 폐기되는 것을 감수합니다 SWS IdsM 11쪽.

기타 인접 모듈 및 해당 역할:

  • DET: 개발 오류
  • DCM: Reporting Mode에 대한 진단 접근
  • NvM: Reporting Mode의 영속성
  • BswM: Block State 제공자
  • StbM 또는 SW-C: 타임스탬프 소스
  • CSM: 서명
  • BSW 스케줄러: 주기적 호출

근거: SWS IdsM 13쪽. 어떤 헤더가 포함되는지는 관련 구성 스위치에 따라 달라지며, 예를 들어 IdsMDevErrorDetect일 때 Det.h, IdsMSinkIdsR일 때 PduR.h입니다 [SWS_IdsM_00101] [SWS_IdsM_00105].

컨텍스트 다이어그램: IdsM은 센서(BSW/CDD 직접, SW-C는 RTE를 통해)와 싱크인 IdsR(PduR을 통해) 또는 DEM/Sem 사이에 위치합니다. 제어 및 지원 모듈은 BswM, DCM, NvM, StbM, CSM 및 DET입니다. 출처: SWS IdsM 20쪽, SWS IdsM 13쪽, [SWS_IdsM_91027], [SWS_IdsM_91028].

Security Event 보고: 식별성, API 변형 및 버퍼링

각 SEv 인스턴스는 4가지 정보로 설명됩니다: IdsMExternalEventId, IdsMSensorInstanceId, 내부적으로 계산된 IdsMInternalEventId 및 이벤트 이름 [SWS_IdsM_00600] [SWS_IdsM_00601]. 사용 시 다음 규칙이 적용됩니다(SWS IdsM 21쪽):

  • 센서는 내부 숫자 값 [SWS_IdsM_00602] [SWS_IdsM_00607]이 아닌, IdsMEvent 컨테이너의 심볼릭 상수만을 독점적으로 사용합니다.
  • 외부 ID 0xFFFF는 유효하지 않습니다 [SWS_IdsM_00604].
  • 모듈 인스턴스가 하나만 있는 경우, 센서 인스턴스는 기본적으로 0입니다 [SWS_IdsM_00608].

보고를 위해 동기식이고 재진입이 불가능한(non-reentrant) 6개의 서비스가 제공됩니다. 이들은 함께 제공되는 추가 데이터에서 차이가 있습니다. 카운터와 타임스탬프가 있는 변형은 이러한 값을 자체적으로 결정하는 스마트 센서(SW-C 또는 CDD)를 대상으로 합니다 SWS IdsM 19쪽. 자체 카운터 없이 타임스탬프만 있는 경우 count = 1이 전달됩니다 [SWS_IdsM_00405].

컨텍스트 데이터는 바이트 배열에 대한 포인터로 전달되며 최대 1500바이트 길이일 수 있습니다 [SWS_IdsM_00501] [SWS_IdsM_00502]. SW-C 센서의 경우 두 가지 추가 매개변수가 적용됩니다 SWS IdsM 37쪽:

수신 시 IdsM은 SEv를 Event Buffer에 저장합니다 [SWS_IdsM_00702]. 컨텍스트 데이터는 동일하거나 다음으로 큰 크기의 Context Data Buffer에 들어가며, 이는 Event Buffer와 연결됩니다 [SWS_IdsM_00705] [SWS_IdsM_00706]. 컨텍스트 데이터가 없으면 컨텍스트 버퍼가 할당되지 않습니다 [SWS_IdsM_00709]. 버퍼의 수와 크기는 구성 가능합니다 [SWS_IdsM_00701] [SWS_IdsM_00704]. Event Buffer 수에 대해 사양서는 집계 필터 인스턴스 수에 병렬로 처리되는 이벤트의 상한을 더한 값을 권장합니다 SWS IdsM 22쪽.

액티비티 다이어그램: Event Buffer가 부족하면 내부 SEv가 트리거됩니다. Context Data Buffer가 부족하면 이벤트가 컨텍스트 데이터 없이 계속 처리됩니다. 출처: SWS IdsM 27쪽, [SWS_IdsM_00703], [SWS_IdsM_00705], [SWS_IdsM_00707], [SWS_IdsM_00708].

적격화: Reporting Mode 및 필터 체인

각 SEv에는 필수 Reporting-Mode-필터가 있습니다. 이는 필터 체인의 일부가 아니라 이벤트에 직접 연결되어 있으며, 기본값은 IdsMReportingModeFilter에서 가져옵니다 [SWS_IdsM_01010] [SWS_IdsM_01011] [SWS_IdsM_01012]. IdsM_Filters_ReportingModeType의 값은 다음을 의미합니다 [SWS_IdsM_91013] SWS IdsM 91쪽:

  • IDSM_REPORTING_MODE_OFF: 이벤트가 폐기됩니다.
  • IDSM_REPORTING_MODE_BRIEF / IDSM_REPORTING_MODE_DETAILED: 컨텍스트 데이터가 없거나 있는 상태로 보고.
  • …_BYPASSING_FILTERS: 필터 체인을 우회하여 보고.

Reporting Mode 이후에야 비로소 SEv에 할당된 필터 체인이 평가됩니다 [SWS_IdsM_01001] [SWS_IdsM_01002]. 활성화된 필터는 고정된 순서로 실행됩니다: Block State, Forward Every Nth, Event Aggregation, Event Threshold [SWS_IdsM_01004]. 필터가 SEv를 폐기하면 추가적인 평가는 모두 생략됩니다 [SWS_IdsM_01005] SWS IdsM 25쪽. 필터 체인에는 최소 하나의 필터가 필요합니다 [SWS_IdsM_CONSTR_00002]. 개별 필터는 다음과 같이 동작합니다:

  • Block State: BswM은 IdsM_BswM_StateChanged을(를) 통해 현재 상태를 보고합니다. 이 상태가 참조된 IdsMBlockState에 속하는 경우, SEv는 폐기됩니다 [SWS_IdsM_01022] [SWS_IdsM_01023] SWS IdsM 28쪽.
  • Forward Every Nth: 첫 번째 SEv 및 그 이후 매 n번째 SEv가 변경 없이 전달됩니다 [SWS_IdsM_01031] [SWS_IdsM_01032] [SWS_IdsM_01033].
  • Aggregation: IdsMEventAggregationTimeInterval 동안 SEv가 보류됩니다. 인터벌 종료 시 모든 카운터의 합계를 가진 하나의 SEv가 전달되며, 컨텍스트 데이터와 타임스탬프는 선택적으로 첫 번째 또는 마지막 SEv에서 가져옵니다 [SWS_IdsM_01043] [SWS_IdsM_01046] [SWS_IdsM_01047] [SWS_IdsM_01048] [SWS_IdsM_01049] SWS IdsM 40쪽.
  • Threshold: 인터벌 내 카운터 합계가 IdsMEventThresholdNumber 미만인 동안에는 폐기되며, 임계값에 도달한 시점부터 전달됩니다. 인터벌이 끝나면 카운터가 재설정됩니다 [SWS_IdsM_01061] [SWS_IdsM_01062] [SWS_IdsM_01063] SWS IdsM 41쪽.

액티비티 다이어그램: 먼저 Reporting Mode가 폐기, 우회 또는 필터링 여부를 결정합니다. 그런 다음 SEv는 폐기되거나 QSEv가 될 때까지 활성화된 필터를 고정된 순서로 거칩니다. 출처: SWS IdsM 35쪽, SWS IdsM 24쪽, [SWS_IdsM_01004], [SWS_IdsM_01005], [SWS_IdsM_91013].
