स्ट्रक्चर ara::log::Format

[SWS_LOG_00207] Upstream: RS_LT_00046

struct Format final {...};

A type holding a formatting hint. The interpretation of precision depends on fmt: For integral types (i.e. Fmt::kDec, Fmt::kOct, Fmt::kHex, Fmt::kBin), precision is interpreted as the minimum number of digits to output, similar to e.g. std::printf("%.7d"). For the floating-point specifiers Fmt::kDecFloat, Fmt::kEngFloat and Fmt::kHexFloat, precision denotes the exact number of digits to be shown after the decimal point; for Fmt::kAutoFloat, precision denotes the number of significant digits to be shown according to the rules of the std::printf "%g" specifier. If fmt is Fmt::kDefault, the precision field is ignored, and an implementation-defined formatting is applied. For integral types, if precision is 0, it is interpreted the same as if it was 1. For convenience, there are helper functions to create specific instances of this struct. The helper functions should be used instead of creating instances manually.

Kontext

Die Datenstruktur ara::log::Format dient innerhalb des Protokollierungssystems der AUTOSAR Adaptive Platform als Formatierungshinweis (formatting hint) für die Datenausgabe. Als struct Format final in der Header-Datei #include "ara/log/logger.h" deklariert, kapselt sie Steuerungsdaten zur Text- und Zahlendarstellung. Anstelle einer freien Formatierungszeichenkette strukturiert sie zwei fundamentale Parameter:

  • fmt: Der Formatspezifizierer vom Typ Fmt [SWS_LOG_00225], welcher die Darstellungsform wie Ganzzahlformate, Fließkommaformate oder Standardformate festlegt.
  • precision: Ein Wert vom Typ std::uint16_t [SWS_LOG_00226], dessen semantische Auswertung an den gewählten Typ in fmt gekoppelt ist.

Im Modul log interagiert die Struktur als Vermittlungselement zwischen der Anwendungslogik, zugehörigen Hilfsfunktionen zur Objekterzeugung und der Protokollierungsinfrastruktur. Sie transportiert Formatierungsvorgaben direkt an die Ausgabekanäle, ohne eigene Systemressourcen oder dynamische Puffer zu verwalten.

Lebenszyklus

Der Lebenszyklus von ara::log::Format entspricht dem eines leichtgewichtigen Wertobjekts (Value Object). Für die Instanziierung formuliert die Spezifikation eine explizite Richtlinie: Es existieren dedizierte Hilfsfunktionen zur Erstellung spezifischer Ausprägungen dieser Struktur. Entwickler sollen Instanzen nicht manuell anlegen, sondern stets diese Hilfsfunktionen nutzen.

Da der Typ als final deklariert ist und ausschließlich aus zwei einfachen Datenelementen besteht, besitzt Format keine dynamisch allokierten Ressourcen und erfordert keine komplexen Destruktions- oder Bereinigungslogiken. Exemplare können effizient auf dem Stack instanziiert oder direkt als temporäre Werte an Schnittstellen übergeben werden.

In Bezug auf die Nebenläufigkeit enthält ara::log::Format keine internen Schutzmechanismen oder Mutex-Sperren. Da Instanzen jedoch üblicherweise kurzlebig erzeugt und als Wertkopie an Log-Aufrufe übergeben werden (Interpretation: reine Wertübergabe ohne gemeinsamen Zustand), verhält sich die Nutzung in Multi-Thread-Umgebungen sicher, solange nicht dieselbe Instanz ohne externe Synchronisation nebenläufig von mehreren Threads modifiziert wird.

Nutzungspfad

Die typische Verwendung von ara::log::Format folgt einem standardisierten Muster aus Wahl der Darstellungsart, Erzeugung über Hilfsfunktionen und Übergabe an die Log-Ausgabe:

  1. Formatierungsauswahl: Festlegung des Zielformats für den auszugebenden Wert. Zur Verfügung stehen unter anderem ganzzahlige Basen (Fmt::kDec, Fmt::kOct, Fmt::kHex, Fmt::kBin), Fließkommadarstellungen (Fmt::kDecFloat, Fmt::kEngFloat, Fmt::kHexFloat, Fmt::kAutoFloat) sowie die Standardformatierung Fmt::kDefault.
  2. Erzeugung via Hilfsfunktion: Aufruf der für den Anwendungsfall vorgesehenen Hilfsfunktion, die ein entsprechend initialisiertes Format-Objekt mit gesetztem fmt [SWS_LOG_00225] und precision [SWS_LOG_00226] zurückgibt.
  3. Übergabe an den Log-Kanal: Das generierte Objekt wird an den Protokollierungsstrom weitergereicht (vermutlich über Streaming-Operatoren oder Argumentlisten des Loggers), wodurch die Formatierungsregeln auf das nachfolgende Datum angewendet werden.

Die Interpretation des Feldes precision [SWS_LOG_00226] hängt dabei direkt von fmt [SWS_LOG_00225] ab:

  • Ganzzahlige Typen (Fmt::kDec, Fmt::kOct, Fmt::kHex, Fmt::kBin): precision definiert die Mindestanzahl an Ziffern, die ausgegeben werden müssen, vergleichbar mit dem Spezifizierer std::printf("%.7d"). Kürzere Zahlenwerte werden dabei mit führenden Nullen aufgefüllt.
  • Gleitkommatypen mit fester Nachkommastellenzahl (Fmt::kDecFloat, Fmt::kEngFloat, Fmt::kHexFloat): precision bestimmt die exakte Anzahl der Ziffern, die nach dem Dezimalpunkt dargestellt werden.
  • Automatische Gleitkommadarstellung (Fmt::kAutoFloat): precision bezeichnet die Anzahl signifikanter Stellen gemäß den standardisierten Formatierungsregeln von std::printf("%g").
  • Standardformatierung (Fmt::kDefault): Bei diesem Spezifizierer wird das Feld precision vollständig ignoriert; stattdessen kommt eine implementationsdefinierte Formatierung zur Anwendung.

Fehlerszenarien

Als kompakte Datenstruktur wirft ara::log::Format keine Ausnahmen und gibt keine Fehlercodes zurück. Für Grenzfälle definiert die Spezifikation jedoch ein klares, fehlertolerantes Verhalten:

  • Präzision Null bei ganzzahligen Werten: Wird für ganzzahlige Typen (Fmt::kDec, Fmt::kOct, Fmt::kHex, Fmt::kBin) ein Wert von precision = 0 übergeben, wird dies nicht als ungültiger Parameter zurückgewiesen, sondern identisch zu precision = 1 behandelt. Dies verhindert die versehentliche Unterdrückung von Ziffernausgaben bei Nullwerten.
  • Präzisionsangaben bei Fmt::kDefault: Ein beliebiger Wert in precision bei gesetztem Fmt::kDefault erzeugt keinen Fehlerzustand, da das Feld in diesem Modus definitionsgemäß ignoriert wird.
  • Wertebereichsüberläufe: Der Wertebereich für precision ist durch den Typ std::uint16_t [SWS_LOG_00226] strikt auf den Bereich 0 bis 65535 begrenzt. Negative Werte sind typbedingt ausgeschlossen, sodass Vorzeichenfehler auf Schnittstellenebene vermieden werden.
