क्लास apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

ग्रंथ सूची एसडब्ल्यूएस डायग्नोस्टिक्स: [2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

UdsTransportProtocolMgr डायग्नोस्टिक सर्वर इंस्टेंस और UDS ट्रांसपोर्ट प्रोटोकॉल, जैसे DoIP या CAN के बीच इंटरैक्शन का प्रबंधन करता है। यह संदेश स्वीकृति, सत्र परत को सौंपने, पावती भेजने और चैनल पुनर्प्राप्ति के लिए मानकीकृत इंटरफ़ेस के साथ परिवहन Handler प्रदान करता है। [SWS_DM_00306]

संदेश स्वीकृति एवं स्वामित्व

एक हैंडलर IndicateMessage() के साथ प्राप्त संदेश की शुरुआत की रिपोर्ट करता है जिसमें स्रोत और गंतव्य पता, पता प्रकार, वैश्विक चैनल ID, आकार और एक पेलोड स्निपेट शामिल होता है जो केवल आमंत्रण के दौरान मान्य होता है। यदि DM अनुरोध को संसाधित कर सकता है, तो यह kIndicationOk और UdsMessagePtr के स्वामित्व वाली मेमोरी लौटाता है। अधिभोग, संसाधनों की कमी या अज्ञात लक्ष्य पते के मामले में, kIndicationOccupied, kIndicationOverflow या kIndicationUnknownTargetAddress को शून्य संकेतक प्रदान किए जाते हैं। [SWS_DM_00309] [SWS_DM_00385] [SWS_DM_00386] [SWS_DM_00387] [SWS_DM_00487]

लौटाए गए संदेश ऑब्जेक्ट को भरने के बाद, हैंडलर इसे HandleMessage() के माध्यम से सत्र परत पर भेजता है; ऐसा करने पर, स्वामित्व सामान्य DM कोर पर वापस चला जाता है। यदि IndicateMessage() ने kIndicationOk प्रदान नहीं किया है, तो HandleMessage() को कॉल नहीं किया जा सकता है। यदि कोई समय से पहले परिवहन त्रुटि होती है, तो ऑब्जेक्ट NotifyMessageFailure() के साथ वापस कर दिया जाता है। [SWS_DM_00311] [SWS_DM_00345] [SWS_DM_00389] [SWS_DM_00310]

जीवन चक्र एवं संचरण

TransmitConfirmation(), DM द्वारा UdsTransportProtocolHandler::Transmit() के माध्यम से अनुरोधित transfer के लिए kTransmitOk या kTransmitFailed की सूचना देता है। PeriodicTransmitConfirmation(), periodic रूप से भेजे गए messages की ordered list को सफलतापूर्वक भेजे गए elements की संख्या सहित पुष्टि करता है। [SWS_DM_00312] [SWS_DM_00351] [SWS_DM_01069]

संबंधित हैंडलर शुरू होने के बाद ही डीएम चैनल बहाली की प्रक्रिया कर सकता है। इसके रुकने के बाद, HandlerStopped() को छोड़कर किसी अन्य प्रबंधक कॉल की अनुमति नहीं है; प्रक्रिया समाप्त करने से पहले डीएम इस कॉलबैक की प्रतीक्षा करता है। [SWS_DM_00313] [SWS_DM_01744] [SWS_DM_01741] [SWS_DM_00340]

फ़ंक्शन HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

ग्रंथ सूची एसडब्ल्यूएस डायग्नोस्टिक्स: [25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
