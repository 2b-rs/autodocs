Kontext

Die Template-Klasse ara::core::Promise<T, E> stellt die AUTOSAR-Adaptive-spezifische Variante der C++-Standardklasse std::promise bereit. Ihre Kernaufgabe besteht darin, das schreibende Ende eines asynchronen Synchronisationskanals zu bilden und einen gemeinsamen Zustand (Shared State) zu verwalten. Über diesen Shared State übergibt ein erzeugender Ausführungspfad das Ergebnis einer asynchronen Berechnung – entweder einen Wert vom Typ T, einen Fehler vom Typ E oder ein zusammenhängendes ara::core::Result<T, E> – an das lesende Gegenstück ara::core::Future<T, E>, welches über get_future() bezogen wird [SWS_CORE_00344].

Eine zentrale AUTOSAR-Vorgabe der Template-Signatur ist die Standardbelegung E = ara::core::ErrorCode. Weicht die Instanziierung hiervon ab (E != ara::core::ErrorCode), fordert die Spezifikation zwingend einen Übersetzungsfehler. Vermutlich dient diese Festlegung der strikten Durchsetzung des standardisierten Fehlermodells der Adaptive Platform, damit asynchrone Schnittstellen einheitlich mit ara::core::Result zusammenarbeiten können. An der Kollaboration sind typischerweise drei Entitäten beteiligt: der erzeugende Programmteil als Besitzer des Promise, der verwaltete Shared State zur thread-übergreifenden Zustandskopplung und ein oder mehrere Konsumenten, die das asynchrone Ergebnis über ara::core::Future entgegennehmen.

Lebenszyklus

Der Lebenszyklus von ara::core::Promise folgt einer strikten Move-Only-Semantik und steuert die Existenz des zugrundeliegenden Shared State:

  • Erzeugung: Der Standard-Konstruktor Promise() konstruiert eine Instanz mit einem neuen, noch unbefriedigten Shared State [SWS_CORE_00341]. Er ist als noexcept garantiert ausnahmesicher sowie als thread-safe spezifiziert [SWS_CORE_00341].
  • Kopierschutz und Eigentumsübertragung: Kopierkonstruktor [SWS_CORE_00350] und Kopierzuweisungsoperator [SWS_CORE_00351] sind explizit gelöscht (= delete). Ein Besitzwechsel ist ausschließlich über Move-Operationen möglich. Der Move-Konstruktor übernimmt den Shared State der Quellinstanz und ist noexcept, jedoch nicht thread-safe [SWS_CORE_00342]. Der Move-Zuweisungsoperator gibt einen zuvor gehaltenen Shared State auf (abandons any shared state) und überträgt den Zustand der anderen Instanz analog zu einem anschließenden swap [SWS_CORE_00343]. Zwei Instanzen können ihren Zustand zudem über swap() vertauschen [SWS_CORE_00352].
  • Future-Kopplung: Über get_future() wird genau eine Instanz von ara::core::Future<T, E> mit demselben Shared State assoziiert [SWS_CORE_00344]. Da pro Promise nur ein Future existieren darf, ist dieser Aufruf nur ein einziges Mal zulässig [SWS_CORE_00344].
  • Zustandsübergang zu Ready: Das Einbringen eines Werts über set_value() [SWS_CORE_00345], [SWS_CORE_00346], eines Fehlers über SetError() [SWS_CORE_00353], [SWS_CORE_00354] oder eines Gesamtergebnisses über SetResult() [SWS_CORE_00355], [SWS_CORE_00356] schaltet den Shared State unumkehrbar in den Status ready. Alle diese Befriedigungsmethoden sind thread-safe deklariert.
  • Zerstörung: Der Destruktor ~Promise() verlässt und verwirft den Shared State (abandons any shared state) [SWS_CORE_00349]. Interpretation: Erfolgt die Zerstörung vor dem Setzen eines Werts oder Fehlers, dürfte der verwaiste Shared State analog zum Verhalten von std::promise für wartende Futures abgebrochen werden.

Nutzungspfad

Die typische Aufrufreihenfolge zur asynchronen Werte- oder Fehlerübermittlung umfasst die folgenden Schritte:

  1. Erzeugung: Der Erzeuger instanziiert ara::core::Promise<T, E> über den Standardkonstruktor [SWS_CORE_00341].
  2. Kanal verbinden: Vor der Übergabe der asynchronen Aufgabe an einen Hintergrund-Thread ruft der Erzeuger get_future() auf [SWS_CORE_00344] und übergibt die resultierende ara::core::Future-Instanz an den Konsumenten.
  3. Asynchrone Abarbeitung: Der Erzeuger führt die Berechnung oder den I/O-Vorgang aus. Der Konsument kann parallel weiterarbeiten oder auf das Future warten.
  4. Ergebnis setzen: Nach Abschluss der Operation hinterlegt der Erzeuger das Resultat im Shared State. Je nach Ausgang wählt er:
    • Erfolgreicher Wert: set_value() als Kopie [SWS_CORE_00345] oder Move [SWS_CORE_00346].
    • Fehlerzustand: SetError() durch Move [SWS_CORE_00353] oder Kopie [SWS_CORE_00354].
    • Vorhandenes Result-Objekt: SetResult() per Kopie [SWS_CORE_00355] oder Move [SWS_CORE_00356].
  5. Freigabe: Durch das Setzen wird der Shared State als fertig markiert; der Konsument liest den Wert aus. Das Promise wird beim Verlassen des Gültigkeitsbereichs zerstört [SWS_CORE_00349].

Fehlerszenarien

Die Spezifikation definiert für unzulässige Aufrufe feste Verletzungsbedingungen (Violations) sowie Anforderungen an die Ausnahmesicherheit:

  • Mehrfacher Future-Abruf: Wird get_future() mehr als einmal für denselben Shared State aufgerufen, tritt die Verletzung IsoStdFutureErrcFutureAlreadyRetrievedViolation auf [SWS_CORE_00344].
  • Operationen ohne Shared State: Besitzt *this keinen Shared State (etwa nach einer Move-Operation), führen Methodenaufrufe zu dokumentierten Verletzungen:
    • get_future() meldet IsoStdFutureErrcNoStateViolation [SWS_CORE_00344].
    • set_value(), SetError() und SetResult() lösen PromiseNoSharedStateToSetViolation aus ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Mehrfache Befriedigung (Double Satisfaction): Wurde im Shared State bereits ein Wert, ein Fehler oder ein Result abgelegt, führt jeder weitere Aufruf von set_value(), SetError() oder SetResult() zur Verletzung IsoStdFutureErrcPromiseAlreadySatisfiedViolation ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).
  • Kompilierfehler bei abweichendem Fehlertyp: Sofern das Klassen-Template mit einem Typ instanziiert wird, für den E != ara::core::ErrorCode gilt, bricht der Build zwingend mit einem Compile Error ab.
  • Bedingte Ausnahmesicherheit: Konstruktoren, Destruktor, Zuweisung, Move, Swap und get_future() sind uneingeschränkt noexcept und ausnahmesicher ([SWS_CORE_00341], [SWS_CORE_00342], [SWS_CORE_00343], [SWS_CORE_00344], [SWS_CORE_00349], [SWS_CORE_00352]). Die Methoden set_value(), SetError() und SetResult() sind hingegen bedingt ausnahmesicher (conditionally exception safe); ihre noexcept-Eigenschaft hängt davon ab, ob die Kopier- bzw. Verschiebekonstruktoren von T und E als nicht-werfend (std::is_nothrow_*_constructible) deklariert sind ([SWS_CORE_00345], [SWS_CORE_00346], [SWS_CORE_00353], [SWS_CORE_00354], [SWS_CORE_00355], [SWS_CORE_00356]).

<h4>Kontext</h4>
<p>Die Template-Klasse <code>ara::core::Promise&lt;T, E&gt;</code> stellt die AUTOSAR-Adaptive-spezifische Variante der C++-Standardklasse <code>std::promise</code> bereit. Ihre Kernaufgabe besteht darin, das schreibende Ende eines asynchronen Synchronisationskanals zu bilden und einen gemeinsamen Zustand (Shared State) zu verwalten. Über diesen Shared State übergibt ein erzeugender Ausführungspfad das Ergebnis einer asynchronen Berechnung – entweder einen Wert vom Typ <code>T</code>, einen Fehler vom Typ <code>E</code> oder ein zusammenhängendes <code>ara::core::Result&lt;T, E&gt;</code> – an das lesende Gegenstück <code>ara::core::Future&lt;T, E&gt;</code>, welches über <code>get_future()</code> bezogen wird <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</p>
<p>Eine zentrale AUTOSAR-Vorgabe der Template-Signatur ist die Standardbelegung <code>E = ara::core::ErrorCode</code>. Weicht die Instanziierung hiervon ab (<code>E != ara::core::ErrorCode</code>), fordert die Spezifikation zwingend einen Übersetzungsfehler. Vermutlich dient diese Festlegung der strikten Durchsetzung des standardisierten Fehlermodells der Adaptive Platform, damit asynchrone Schnittstellen einheitlich mit <code>ara::core::Result</code> zusammenarbeiten können. An der Kollaboration sind typischerweise drei Entitäten beteiligt: der erzeugende Programmteil als Besitzer des <code>Promise</code>, der verwaltete Shared State zur thread-übergreifenden Zustandskopplung und ein oder mehrere Konsumenten, die das asynchrone Ergebnis über <code>ara::core::Future</code> entgegennehmen.</p>

<h4>Lebenszyklus</h4>
<p>Der Lebenszyklus von <code>ara::core::Promise</code> folgt einer strikten Move-Only-Semantik und steuert die Existenz des zugrundeliegenden Shared State:</p>
<ul>
<li><strong>Erzeugung:</strong> Der Standard-Konstruktor <code>Promise()</code> konstruiert eine Instanz mit einem neuen, noch unbefriedigten Shared State <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>. Er ist als <code>noexcept</code> garantiert ausnahmesicher sowie als thread-safe spezifiziert <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>.</li>
<li><strong>Kopierschutz und Eigentumsübertragung:</strong> Kopierkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00350" href="../spec/record.html?id=SWS_CORE_00350">[SWS_CORE_00350]</a> und Kopierzuweisungsoperator <a class="spec-record-ref" data-req="SWS_CORE_00351" href="../spec/record.html?id=SWS_CORE_00351">[SWS_CORE_00351]</a> sind explizit gelöscht (<code>= delete</code>). Ein Besitzwechsel ist ausschließlich über Move-Operationen möglich. Der Move-Konstruktor übernimmt den Shared State der Quellinstanz und ist <code>noexcept</code>, jedoch nicht thread-safe <a class="spec-record-ref" data-req="SWS_CORE_00342" href="../spec/record.html?id=SWS_CORE_00342">[SWS_CORE_00342]</a>. Der Move-Zuweisungsoperator gibt einen zuvor gehaltenen Shared State auf (<em>abandons any shared state</em>) und überträgt den Zustand der anderen Instanz analog zu einem anschließenden <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00343" href="../spec/record.html?id=SWS_CORE_00343">[SWS_CORE_00343]</a>. Zwei Instanzen können ihren Zustand zudem über <code>swap()</code> vertauschen <a class="spec-record-ref" data-req="SWS_CORE_00352" href="../spec/record.html?id=SWS_CORE_00352">[SWS_CORE_00352]</a>.</li>
<li><strong>Future-Kopplung:</strong> Über <code>get_future()</code> wird genau eine Instanz von <code>ara::core::Future&lt;T, E&gt;</code> mit demselben Shared State assoziiert <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>. Da pro Promise nur ein Future existieren darf, ist dieser Aufruf nur ein einziges Mal zulässig <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</li>
<li><strong>Zustandsübergang zu Ready:</strong> Das Einbringen eines Werts über <code>set_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>, eines Fehlers über <code>SetError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a> oder eines Gesamtergebnisses über <code>SetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a> schaltet den Shared State unumkehrbar in den Status <em>ready</em>. Alle diese Befriedigungsmethoden sind thread-safe deklariert.</li>
<li><strong>Zerstörung:</strong> Der Destruktor <code>~Promise()</code> verlässt und verwirft den Shared State (<em>abandons any shared state</em>) <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>. Interpretation: Erfolgt die Zerstörung vor dem Setzen eines Werts oder Fehlers, dürfte der verwaiste Shared State analog zum Verhalten von <code>std::promise</code> für wartende Futures abgebrochen werden.</li>
</ul>

<h4>Nutzungspfad</h4>
<p>Die typische Aufrufreihenfolge zur asynchronen Werte- oder Fehlerübermittlung umfasst die folgenden Schritte:</p>
<ol>
<li><strong>Erzeugung:</strong> Der Erzeuger instanziiert <code>ara::core::Promise&lt;T, E&gt;</code> über den Standardkonstruktor <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>.</li>
<li><strong>Kanal verbinden:</strong> Vor der Übergabe der asynchronen Aufgabe an einen Hintergrund-Thread ruft der Erzeuger <code>get_future()</code> auf <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a> und übergibt die resultierende <code>ara::core::Future</code>-Instanz an den Konsumenten.</li>
<li><strong>Asynchrone Abarbeitung:</strong> Der Erzeuger führt die Berechnung oder den I/O-Vorgang aus. Der Konsument kann parallel weiterarbeiten oder auf das <code>Future</code> warten.</li>
<li><strong>Ergebnis setzen:</strong> Nach Abschluss der Operation hinterlegt der Erzeuger das Resultat im Shared State. Je nach Ausgang wählt er:
<ul>
<li>Erfolgreicher Wert: <code>set_value()</code> als Kopie <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a> oder Move <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>.</li>
<li>Fehlerzustand: <code>SetError()</code> durch Move <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a> oder Kopie <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>.</li>
<li>Vorhandenes Result-Objekt: <code>SetResult()</code> per Kopie <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a> oder Move <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>.</li>
</ul>
</li>
<li><strong>Freigabe:</strong> Durch das Setzen wird der Shared State als fertig markiert; der Konsument liest den Wert aus. Das <code>Promise</code> wird beim Verlassen des Gültigkeitsbereichs zerstört <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Die Spezifikation definiert für unzulässige Aufrufe feste Verletzungsbedingungen (Violations) sowie Anforderungen an die Ausnahmesicherheit:</p>
<ul>
<li><strong>Mehrfacher Future-Abruf:</strong> Wird <code>get_future()</code> mehr als einmal für denselben Shared State aufgerufen, tritt die Verletzung <code>IsoStdFutureErrcFutureAlreadyRetrievedViolation</code> auf <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</li>
<li><strong>Operationen ohne Shared State:</strong> Besitzt <code>*this</code> keinen Shared State (etwa nach einer Move-Operation), führen Methodenaufrufe zu dokumentierten Verletzungen:
<ul>
<li><code>get_future()</code> meldet <code>IsoStdFutureErrcNoStateViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>.</li>
<li><code>set_value()</code>, <code>SetError()</code> und <code>SetResult()</code> lösen <code>PromiseNoSharedStateToSetViolation</code> aus (<a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>).</li>
</ul>
</li>
<li><strong>Mehrfache Befriedigung (Double Satisfaction):</strong> Wurde im Shared State bereits ein Wert, ein Fehler oder ein Result abgelegt, führt jeder weitere Aufruf von <code>set_value()</code>, <code>SetError()</code> oder <code>SetResult()</code> zur Verletzung <code>IsoStdFutureErrcPromiseAlreadySatisfiedViolation</code> (<a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>).</li>
<li><strong>Kompilierfehler bei abweichendem Fehlertyp:</strong> Sofern das Klassen-Template mit einem Typ instanziiert wird, für den <code>E != ara::core::ErrorCode</code> gilt, bricht der Build zwingend mit einem Compile Error ab.</li>
<li><strong>Bedingte Ausnahmesicherheit:</strong> Konstruktoren, Destruktor, Zuweisung, Move, Swap und <code>get_future()</code> sind uneingeschränkt <code>noexcept</code> und ausnahmesicher (<a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00342" href="../spec/record.html?id=SWS_CORE_00342">[SWS_CORE_00342]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00343" href="../spec/record.html?id=SWS_CORE_00343">[SWS_CORE_00343]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00352" href="../spec/record.html?id=SWS_CORE_00352">[SWS_CORE_00352]</a>). Die Methoden <code>set_value()</code>, <code>SetError()</code> und <code>SetResult()</code> sind hingegen bedingt ausnahmesicher (<em>conditionally exception safe</em>); ihre <code>noexcept</code>-Eigenschaft hängt davon ab, ob die Kopier- bzw. Verschiebekonstruktoren von <code>T</code> und <code>E</code> als nicht-werfend (<code>std::is_nothrow_*_constructible</code>) deklariert sind (<a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>, <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>).</li>
</ul>
