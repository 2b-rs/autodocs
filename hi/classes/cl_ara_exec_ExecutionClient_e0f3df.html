The ara::exec::ExecutionClient API provides the functionality for a Process to report its Execution State to the Execution Management.

स्वचालित रूप से उत्पन्न विवरण, संदर्भित AUTOSAR-R25-11 दस्तावेजों (SWS विनिर्देश और मानक दस्तावेजों के साथ) से प्राप्त सामग्री - आधिकारिक AUTOSAR पाठ नहीं। व्याख्या के रूप में चिह्नित कथन स्रोतों से निकाले गए निष्कर्ष हैं।

रिपोर्ट की गई प्रक्रिया जीवनचक्र में भूमिका

ExecutionClient Reporting Process के लिए process-side interface है। report किया गया kRunning, Execution Management को process state Running तक पहुँचने देता है; Execution State और internally maintained Process State अलग models बने रहते हैं SWS EM §7.3.1 “Execution State” SWS EM §7.3.2 “Process States”।

नियतात्मक स्टार्ट-अप और शेड्यूलिंग

एक रिपोर्टिंग प्रक्रिया आरंभीकरण पूरा करने के बाद और संभावित गैर-नियतात्मक सेवा खोज चरण से पहले kRunning रिपोर्ट करती है। यह कॉन्फ़िगर की गई निर्भरता को एक लचीली प्रक्रिया स्थिति में हल करने की अनुमति देता है। शेड्यूलिंग अनुरोध पर, निष्पादन प्रबंधन SIGTERM ट्रिगर करता है; Create पर संग्रहीत हैंडलर को ExecutionClient [SWS_EM_02562] [SWS_EM_02003] [SWS_EM_02577] द्वारा कॉल किया जाता है।

राज्य आरेख: प्रक्रिया चलाने का EM दृश्य रिपोर्ट की गई निष्पादन स्थिति SWS EM §7.3.1 “Execution State” SWS EM §7.3.2 “Process States” से भिन्न है। व्याख्या: लेबल कई सामान्यीकृत संक्रमण ट्रिगर्स का सारांश प्रस्तुत करते हैं।

अनुक्रम आरेख: kRunning संदेश प्रक्रिया दृश्य को EM के जीवनचक्र ट्रैकिंग और PHM SWS EM §7.3.1 “Execution State” SWS PHM §7.2 “Supervision of Supervised Entities” द्वारा सक्रिय पर्यवेक्षण की शुरुआत से जोड़ता है।

जिम्मेदारी की सीमा

ग्राहक केवल अपनी स्थिति की रिपोर्ट करता है; निष्पादन प्रबंधन प्रारंभ, रोक और ओएस कॉन्फ़िगरेशन के लिए ज़िम्मेदार है, लेकिन प्रक्रिया की चल रही शेड्यूलिंग के लिए नहीं, जो ऑपरेटिंग सिस्टम [SWS_EM_01401] SWS Operating System Interface §7.1.2 “Process Handling” SWS Operating System Interface §7.1.3 “Scheduling Policies” के साथ निहित है।
