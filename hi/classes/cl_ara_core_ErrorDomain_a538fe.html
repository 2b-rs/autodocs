क्लास ara::core::ErrorDomain

[SWS_CORE_00110] Upstream: RS_AP_00130

class ErrorDomain {...};

Encapsulation of an ErrorDomain. An ErrorDomain is the controlling entity for ErrorCode’s error code values, and defines the mapping of such error code values to textual representations. This type constitutes a base class for ErrorDomain implementations. This class is a literal type, and subclasses are strongly advised to be literal types as well.

उपयोग का उद्देश्य

ara::core::ErrorDomain त्रुटि स्थितियों के लिए संदर्भ प्रदान करता है, ErrorCode के त्रुटि मानों को नियंत्रित करता है और उन्हें पाठ्य प्रतिनिधित्व [SWS_CORE_00110] [SWS_CORE_10303] प्रदान करता है। यह ठोस त्रुटि डोमेन का आधार वर्ग है और स्वयं एक शाब्दिक प्रकार [SWS_CORE_00110] [SWS_CORE_10400] है।

पीढ़ी & विनाश

संरक्षित पीढ़ी एक डोमेन आईडी स्वीकार करती है जो अपेक्षित [SWS_CORE_00135] के अनुसार अद्वितीय सिस्टम-व्यापी है। विध्वंसक जानबूझकर गैर-आभासी और तुच्छ है क्योंकि कोई बहुरूपी विनाश आवश्यक नहीं है और शाब्दिक प्रकार की संपत्ति [SWS_CORE_00136] संरक्षित है।

जीवनचक्र और स्वामित्व

असाइनमेंट सहित प्रतिलिपि बनाना और स्थानांतरित करना निषिद्ध है [SWS_CORE_00131] [SWS_CORE_00132] [SWS_CORE_00133] [SWS_CORE_00134]। Name() और Message() द्वारा प्रदान किए गए वर्ण सूचक डोमेन या उसके उपवर्ग की संपत्ति बने रहते हैं और ग्राहकों द्वारा जारी नहीं किए जा सकते हैं [SWS_CORE_00152] [SWS_CORE_00153]।

अन्य वर्गों के साथ सहभागिता

Id() अद्वितीय ID लौटाता है। दो डोमेन समान हैं यदि और केवल यदि उनके IDs बराबर हैं [SWS_CORE_00151] [SWS_CORE_00137] [SWS_CORE_10401]। व्युत्पन्न डोमेन Name(), Message() और ThrowAsException() को लागू करते हैं; उन्हें final होना चाहिए और उपनाम Errc और Exception [SWS_CORE_00152] [SWS_CORE_00153] [SWS_CORE_00154] [SWS_CORE_10932] [SWS_CORE_10933] [SWS_CORE_10934] प्रदान करना चाहिए।

सीमाएँ & error handling

ThrowAsException() एक उपयुक्त अपवाद प्रकार निर्धारित करता है, इसमें पारित ErrorCode शामिल है और यदि C++ अपवाद अक्षम हैं तो ओवरलोड रिज़ॉल्यूशन में भाग नहीं लेता है [SWS_CORE_00154] [SWS_CORE_10304]। इस फ़ंक्शन के अपवाद के साथ, ठोस त्रुटि डोमेन के सार्वजनिक फ़ंक्शन noexcept [SWS_CORE_10950] होने चाहिए।

त्रुटि डोमेन का चित्रण

Error domains वह context देती हैं जिसमें error value लागू होती है। manufacturer-specific errors के लिए अपनी domains हैं, ताकि उनका assignment स्पष्ट रहे; portable applications उन्हें default case के रूप में ध्यान में रखते हैं। EXP InterfacesGuidelines §3.1.5 “Standardized vs Vendor-specific ErrorCodes”

रस्ट बाइंडिंग उसी अलगाव को दर्शाता है: वहां एक एनम एररडोमेन विशेषता को लागू करता है और ErrorCode ऑब्जेक्ट बनाने के लिए उपयोग किया जाता है। EXP ARARustApplications §5.6 “Creating a new ErrorDomain”

Collaboration diagram: Domain error context निर्धारित करता है और ErrorCode के स्पष्ट exception conversion का समर्थन करता है। स्रोत: EXP InterfacesGuidelines §3.1.2 “Result” EXP ARARustApplications §5.6 “Creating a new ErrorDomain” RS General §4.1.3 “The use of noexcept”।

पहचान, संदेश और अपवाद सीमा

ErrorDomain अपने error values का अर्थ परिभाषित करता है, जिसमें stable identity और message generation शामिल हैं। इसकी भूमिका केवल enumeration नहीं है: यह वह context देता है जिसकी ErrorCode को comparison, text representation और स्पष्ट Exception conversion के लिए आवश्यकता होती है। SWS Core §7.2 “Error handling” SWS Core §7.2.5.2 “Error Domain”
