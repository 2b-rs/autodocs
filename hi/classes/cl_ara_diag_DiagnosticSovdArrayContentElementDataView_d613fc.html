Kontext

Die Klasse ara::diag::DiagnosticSovdArrayContentElementDataView definiert eine strukturierte Sicht auf Datenstrukturen des Typs ArrayContentElementData innerhalb eines übergeordneten DiagnosticSovdContentElementData [SWS_DM_02227] AUTOSAR_AP_SWS_Diagnostics §8.60.5 S. 776. Im Rahmen der Service-Oriented Vehicle Diagnostics (SOVD) der AUTOSAR Adaptive Platform ermöglicht diese View-Abstraktion Diagnoseapplikationen und Serverkomponenten die typsichere Handhabung, Befüllung und Auswertung von Array-Strukturen, ohne dass die darunterliegende generische Datenrepräsentation manuell geparst werden muss.

Als Interaktionsschnittstelle kapselt die View Operationen für heterogene und homogene Listen. Sie gestattet das Anhängen elementarer Datentypen wie ganzzahliger Werte (std::int64_t, std::uint64_t), Fließkommazahlen (double), Wahrheitswerten (bool) und Textstrukturen (ara::core::StringView) sowie eingebetteter DiagnosticSovdContentElementData-Instanzen [SWS_DM_02241] [SWS_DM_02242] [SWS_DM_02243] [SWS_DM_02244] [SWS_DM_02245] [SWS_DM_02246]. Damit fungiert die Klasse als zentrales Bindeglied zwischen der internen Repräsentation diagnoserelevanter Datenmodelle und den Anwendungsfunktionen des Moduls diag.

Lebenszyklus

Die Klasse folgt der Semantik einer nicht-besitzenden Hülle (Interpretation: Als View besitzt sie die verwalteten Daten typischerweise nicht selbst, sondern referenziert ein existentes DiagnosticSovdContentElementData-Objekt). Die Gültigkeit der View ist an die Lebensdauer des zugrunde liegenden Datenelements gebunden. Sämtliche Elementfunktionen sind gemäß Spezifikation als noexcept deklariert und garantieren sowohl Exception-Sicherheit als auch Thread-Sicherheit [SWS_DM_02230] [SWS_DM_02231] AUTOSAR_AP_SWS_Diagnostics §8.60.5.1 S. 777.

Hinsichtlich der internen Speicher- und Lebensphasenverwaltung unterstützt die Klasse vorbereitende Speicherreservierungen: Mittels Reserve lässt sich die Zielkapazität der Array-Struktur festlegen [SWS_DM_02240]. Neue Einträge werden über die überladenen PushBack-Methoden angehängt. Über Erase können gezielt einzelne Elemente entfernt werden [SWS_DM_02247], während Clear sämtliche enthaltenen Elemente freigibt und das Array zurücksetzt [SWS_DM_02233].

Nutzungspfad

Ein typischer Anwendungsfall umfasst die Bereitstellung von Kapazität, das Hinzufügen von Elementen, das Auslesen per Index oder Iterator sowie die Überprüfung des Konsistenzzustands:

  1. Kapazitätsprüfung und Vorbereitung: Vor dem Einfügen kann die Applikation mittels Empty prüfen, ob Daten vorliegen [SWS_DM_02232], die bestehende Größe über Size abrufen [SWS_DM_02230] sowie über Capacity den Puffer einsehen [SWS_DM_02231]. Eine Allokation erfolgt über Reserve [SWS_DM_02240].
  2. Einfügen von Daten: Die Anwendung nutzt PushBack, um primitive Datentypen oder vollständige DiagnosticSovdContentElementData-Knoten hinzuzufügen [SWS_DM_02241] [SWS_DM_02246].
  3. Indizierter Zugriff und Iteration: Elemente können direkt wahlfrei über operator[] adressiert werden. Sowohl die modifizierende Variante [SWS_DM_02234] als auch die konstante Variante [SWS_DM_02235] liefern eine std::reference_wrapper-Referenz innerhalb eines ara::core::Result zurück. Für sequenzielle Traversierungen stehen STL-kompatible Iteratoren über Begin [SWS_DM_02236], End [SWS_DM_02237] sowie deren konstante Gegenstücke CBegin [SWS_DM_02238] und CEnd [SWS_DM_02239] AUTOSAR_AP_SWS_Diagnostics §8.60.5.1 S. 778 zur Verfügung.
  4. Validierung: Die Applikation prüft den Fehlerstatus des Elements über HasError [SWS_DM_02228].

Sequenzdiagramm: Aufrufabfolge zur Konfiguration, Befüllung, Indizierung und Validierung eines SOVD-Array-Elements. Quellen: [SWS_DM_02240], [SWS_DM_02241], [SWS_DM_02234], [SWS_DM_02228].

Fehlerszenarien

Fehlerbedingungen werden in der Schnittstelle konsistent über den Rückgabetyp ara::core::Result abgebildet:

  • Typinkongruenz: Nahezu alle manipulierenden und abfragenden Funktionen fordern als Vorbedingung, dass das zugrunde liegende DiagnosticSovdContentElementData tatsächlich vom Typ ArrayContentElementData ist (Interpretation: Eine fehlerhafte Typisierung wird zur Laufzeit validiert). Schlägt diese Prüfung fehl, geben Methoden wie PushBack [SWS_DM_02241] oder operator[] [SWS_DM_02234] ein Fehlerergebnis im ara::core::Result zurück.
  • Fehlschlag beim Löschen: Der Aufruf von Erase erfordert einen gültigen Iterator auf ein enthaltenes Element. Kann das Element nicht gelöscht werden oder ist der Knotentyp inkorrekt, wird der Fehler im Rückgabewert signalisiert [SWS_DM_02247].
  • Explizite Fehlerzustände: Ein Array-Element kann aktiv als fehlerhaft deklariert werden, indem mittels SetError ein entsprechender ara::core::ErrorCode zugewiesen wird [SWS_DM_02229]. Aufrufer ermitteln das Vorliegen eines solchen Fehlers über HasError, welches bei gesetztem Fehlercode den Typ ara::diag::DiagSovdErrc als Fehlerwert zurückgibt [SWS_DM_02228].

Neue Einträge werden über die überladenen <code>PushBack</code>-Methoden angehängt. Über <code>Erase</code> können gezielt einzelne Elemente entfernt werden <a class="spec-record-ref" data-req="SWS_DM_02247" href="../spec/record.html?id=SWS_DM_02247">[SWS_DM_02247]</a>, während <code>Clear</code> sämtliche enthaltenen Elemente freigibt und das Array zurücksetzt <a class="spec-record-ref" data-req="SWS_DM_02233" href="../spec/record.html?id=SWS_DM_02233">[SWS_DM_02233]</a>.</p>

<h4>Nutzungspfad</h4>
<p>Ein typischer Anwendungsfall umfasst die Bereitstellung von Kapazität, das Hinzufügen von Elementen, das Auslesen per Index oder Iterator sowie die Überprüfung des Konsistenzzustands:</p>
<ol>
  <li><strong>Kapazitätsprüfung und Vorbereitung:</strong> Vor dem Einfügen kann die Applikation mittels <code>Empty</code> prüfen, ob Daten vorliegen <a class="spec-record-ref" data-req="SWS_DM_02232" href="../spec/record.html?id=SWS_DM_02232">[SWS_DM_02232]</a>, die bestehende Größe über <code>Size</code> abrufen <a class="spec-record-ref" data-req="SWS_DM_02230" href="../spec/record.html?id=SWS_DM_02230">[SWS_DM_02230]</a> sowie über <code>Capacity</code> den Puffer einsehen <a class="spec-record-ref" data-req="SWS_DM_02231" href="../spec/record.html?id=SWS_DM_02231">[SWS_DM_02231]</a>. Eine Allokation erfolgt über <code>Reserve</code> <a class="spec-record-ref" data-req="SWS_DM_02240" href="../spec/record.html?id=SWS_DM_02240">[SWS_DM_02240]</a>.</li>
  <li><strong>Einfügen von Daten:</strong> Die Anwendung nutzt <code>PushBack</code>, um primitive Datentypen oder vollständige <code>DiagnosticSovdContentElementData</code>-Knoten hinzuzufügen <a class="spec-record-ref" data-req="SWS_DM_02241" href="../spec/record.html?id=SWS_DM_02241">[SWS_DM_02241]</a> <a class="spec-record-ref" data-req="SWS_DM_02246" href="../spec/record.html?id=SWS_DM_02246">[SWS_DM_02246]</a>.</li>
  <li><strong>Indizierter Zugriff und Iteration:</strong> Elemente können direkt wahlfrei über <code>operator[]</code> adressiert werden. Sowohl die modifizierende Variante <a class="spec-record-ref" data-req="SWS_DM_02234" href="../spec/record.html?id=SWS_DM_02234">[SWS_DM_02234]</a> als auch die konstante Variante <a class="spec-record-ref" data-req="SWS_DM_02235" href="../spec/record.html?id=SWS_DM_02235">[SWS_DM_02235]</a> liefern eine <code>std::reference_wrapper</code>-Referenz innerhalb eines <code>ara::core::Result</code> zurück. Für sequenzielle Traversierungen stehen STL-kompatible Iteratoren über <code>Begin</code> <a class="spec-record-ref" data-req="SWS_DM_02236" href="../spec/record.html?id=SWS_DM_02236">[SWS_DM_02236]</a>, <code>End</code> <a class="spec-record-ref" data-req="SWS_DM_02237" href="../spec/record.html?id=SWS_DM_02237">[SWS_DM_02237]</a> sowie deren konstante Gegenstücke <code>CBegin</code> <a class="spec-record-ref" data-req="SWS_DM_02238" href="../spec/record.html?id=SWS_DM_02238">[SWS_DM_02238]</a> und <code>CEnd</code> <a class="spec-record-ref" data-req="SWS_DM_02239" href="../spec/record.html?id=SWS_DM_02239">[SWS_DM_02239]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=778">AUTOSAR_AP_SWS_Diagnostics §8.60.5.1 S. 778</a> zur Verfügung.</li>
  <li><strong>Validierung:</strong> Die Applikation prüft den Fehlerstatus des Elements über <code>HasError</code> <a class="spec-record-ref" data-req="SWS_DM_02228" href="../spec/record.html?id=SWS_DM_02228">[SWS_DM_02228]</a>.</li>
</ol>

<h4>Fehlerszenarien</h4>
<p>Fehlerbedingungen werden in der Schnittstelle konsistent über den Rückgabetyp <code>ara::core::Result</code> abgebildet:</p>
<ul>
  <li><strong>Typinkongruenz:</strong> Nahezu alle manipulierenden und abfragenden Funktionen fordern als Vorbedingung, dass das zugrunde liegende <code>DiagnosticSovdContentElementData</code> tatsächlich vom Typ <code>ArrayContentElementData</code> ist (Interpretation: Eine fehlerhafte Typisierung wird zur Laufzeit validiert). Schlägt diese Prüfung fehl, geben Methoden wie <code>PushBack</code> <a class="spec-record-ref" data-req="SWS_DM_02241" href="../spec/record.html?id=SWS_DM_02241">[SWS_DM_02241]</a> oder <code>operator[]</code> <a class="spec-record-ref" data-req="SWS_DM_02234" href="../spec/record.html?id=SWS_DM_02234">[SWS_DM_02234]</a> ein Fehlerergebnis im <code>ara::core::Result</code> zurück.</li>
  <li><strong>Fehlschlag beim Löschen:</strong> Der Aufruf von <code>Erase</code> erfordert einen gültigen Iterator auf ein enthaltenes Element. Kann das Element nicht gelöscht werden oder ist der Knotentyp inkorrekt, wird der Fehler im Rückgabewert signalisiert <a class="spec-record-ref" data-req="SWS_DM_02247" href="../spec/record.html?id=SWS_DM_02247">[SWS_DM_02247]</a>.</li>
  <li><strong>Explizite Fehlerzustände:</strong> Ein Array-Element kann aktiv als fehlerhaft deklariert werden, indem mittels <code>SetError</code> ein entsprechender <code>ara::core::ErrorCode</code> zugewiesen wird <a class="spec-record-ref" data-req="SWS_DM_02229" href="../spec/record.html?id=SWS_DM_02229">[SWS_DM_02229]</a>. Aufrufer ermitteln das Vorliegen eines solchen Fehlers über <code>HasError</code>, welches bei gesetztem Fehlercode den Typ <code>ara::diag::DiagSovdErrc</code> als Fehlerwert zurückgibt <a class="spec-record-ref" data-req="SWS_DM_02228" href="../spec/record.html?id=SWS_DM_02228">[SWS_DM_02228]</a>.</li>
</ul>
