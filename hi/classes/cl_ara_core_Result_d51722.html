क्लास ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

उपयोग का उद्देश्य

सिंक्रोनस कॉल के लिए, ara::core::Result<T,E> या तो प्रकार T का मान या प्रकार E की त्रुटि समाहित करता है; E ara::core::ErrorCode होना चाहिए. इसलिए प्रकार अपवाद-मुक्त त्रुटि प्रबंधन का समर्थन करता है। [SWS_CORE_00701] [SWS_CORE_10600]

पीढ़ी & जीवनचक्र

परिणाम मान या त्रुटि के साथ-साथ FromValue() और FromError() के माध्यम से उत्पन्न किया जा सकता है। कॉपी और मूव ऑपरेशन उपलब्ध हैं और सशर्त noexcept; विध्वंसक की तुच्छता T और E पर निर्भर करती है। [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

अन्य वर्गों के साथ सहभागिता

HasValue(), Value(), Error(), Ok() और Err() स्थिति और सामग्री तक पहुंच की अनुमति देते हैं। Bind() एक निहित मान को Callable के माध्यम से एक नए Result में बदल देता है, जबकि Resolve() किसी त्रुटि की स्थिति में एक फ़ंक्शन को कॉल करता है। [SWS_CORE_00751] [SWS_CORE_00755] [SWS_CORE_00757] [SWS_CORE_00770] [SWS_CORE_00772] [SWS_CORE_00768] [SWS_CORE_00767]

सीमाएँ & error handling

सम्मिलित त्रुटि के बिना त्रुटियों तक पहुंच या सम्मिलित मूल्य के बिना मूल्य तक पहुंच को उल्लंघन के रूप में परिभाषित किया गया है। ValueOrThrow() ट्रिगर हो सकता है और यह एकमात्र परिणाम फ़ंक्शन है जिसे ara::core आरंभीकरण के बिना उपयोग से छूट प्राप्त है। [SWS_CORE_13010] [SWS_CORE_13009] [SWS_CORE_00766] [SWS_CORE_15002]

अपवाद रहित त्रुटि पथ में भूमिका

पुनर्प्राप्त किए जा सकने वाले errors के लिए interfaces को ara::core::Result अथवा ara::core::Future का उपयोग करना चाहिए; Result error type ara::core::ErrorCode पर निर्धारित है। RS General §4.1.2 “Error handling” EXP InterfacesGuidelines §3.1.2 “Result”

अपवाद रहित पहुंच में, कॉल करने वाला HasValue() की जांच करता है और फिर Value() या Error() पढ़ता है। इन पर्यवेक्षकों का उपयोग C++ अपवादों के बिना किया जा सकता है; दूसरी ओर, ValueOrThrow(), अपवाद-आधारित पथ पर स्पष्ट संक्रमण है। EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result” RS General §4.1.3 “The use of noexcept”

गतिविधि आरेख: HasValue() के बाद मूल्य या त्रुटि के लिए सामान्य अपवाद-मुक्त प्रवाह शाखाएँ; ValueOrThrow() वैकल्पिक रूप से प्रदर्शित अपवाद पथ है। स्रोत: EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result”.

मानक कोर: मूल्य या त्रुटि

कोर विनिर्देश Result को त्रुटि प्रबंधन मॉडल पर मैप करता है: पुनर्प्राप्त करने योग्य त्रुटियों के लिए, APIs को या तो Result या Future वापस करना चाहिए। Result इस प्रकार सामान्य मान पथ को डेटा मान के रूप में ट्रांसपोर्ट की गई त्रुटि से अलग करता है। SWS Core §7.2 “Error handling” SWS Core §7.2.5.4 “Result”

The return type of this function is decltype(f(Value())) for a template argument F that returns a ara::core::Result type, and it is Result<decltype(f(Value())), E> for a template argument F that does not return a ara::core::Result type.
