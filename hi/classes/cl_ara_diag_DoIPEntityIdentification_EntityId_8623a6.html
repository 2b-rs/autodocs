संदर्भ

डेटा संरचना ara::diag::DoIPEntityIdentification::EntityId header ara/diag/doip_entity_identification.h में interface क्लास ara::diag::DoIPEntityIdentification के एक embedded type के रूप में परिभाषित है (SWS Diagnostics §8.33 “Header: ara/diag/doip_entity_identification.h”, [SWS_DM_01362])। इसका कार्य DoIP प्रोटोकॉल (Diagnostic communication over Internet Protocol) के लिए ISO 13400-2:2019 में मानकीकृत Entity Identification मान (EID) को encapsulated रूप में प्रदान करना है। इसके लिए यह संरचना member entityIdentification को ara::core::Array<std::uint8_t, 6> प्रकार के निश्चित byte array के रूप में encapsulate करती है ([SWS_DM_01496])।

समग्र प्रणाली में, EntityId के उपयोग के दौरान अनिवार्य रूप से तीन घटक परस्पर क्रिया करते हैं:

  • Adaptive Application (AA): सिस्टम-विशिष्ट entity identification उपलब्ध कराने के लिए API क्लास ara::diag::DoIPEntityIdentification ([SWS_DM_01364]) को implement या instantiate करती है। व्याख्या: ISO 13400-2:2019 के अनुसार, 6-byte लंबा पहचानकर्ता सामान्यतः DoIP इंस्टेंस के MAC address या समान hardware identification पर आधारित होना चाहिए।
  • Diagnostic Management (DM): Adaptive daemon में केंद्रीय इंटरैक्शन पार्टनर के रूप में कार्य करता है। यदि सिस्टम पैरामीटर DoIpNetworkConfiguration.eidRetrieval के माध्यम से मान DoIpEidRetrievalEnum.eidUseApi पर कॉन्फ़िगर किया गया है, तो DM सक्रिय रूप से method ara::diag::DoIPEntityIdentification::GetEntityId के माध्यम से EID का अनुरोध करता है ([SWS_DM_01361], SWS Diagnostics §7.2.1.2)।
  • DoIP नेटवर्क / बाहरी परीक्षक: नेटवर्क स्तर पर वह समकक्ष, जिसे DM मानकीकृत DoIP संदेशों (जैसे Vehicle Announcement Message) के भीतर प्राप्त EID प्रेषित करता है (SWS Diagnostics §7.2.1.2)।

Context diagram: EntityId के प्रावधान में Adaptive Application, Diagnostic Management daemon और DoIP नेटवर्क की परस्पर क्रिया। स्रोत: [SWS_DM_01361], [SWS_DM_01496], SWS Diagnostics §7.2.1.2।

जीवनचक्र

संरचना EntityId एक शुद्ध डेटा ट्रांसफर ऑब्जेक्ट (Value Object) के रूप में एक सरल जीवन चक्र के अधीन है:

  • निर्माण और स्वामित्व: व्याख्या: चूँकि specification केवल सार्वजनिक चर entityIdentification को दर्शाती है ([SWS_DM_01496]), इसलिए EntityId को जटिल निर्माण तर्क के बिना आसानी से बनने वाले value type के रूप में डिज़ाइन किया गया होना चाहिए। इसका निर्माण Adaptive Application द्वारा GetEntityId के कॉल के संदर्भ में किया जाता है। डेटा का स्वामित्व value return द्वारा Diagnostic Management को स्थानांतरित कर दिया जाता है।
  • जीवनकाल और अवस्थाएँ: EntityId में कोई आंतरिक state machines या जीवन चरण नहीं होते हैं। किसी instance का जीवनकाल आम तौर पर API कॉल के निष्पादन और DM द्वारा DoIP पैकेट में 6 बाइट्स के बाद के serialization तक सीमित होता है।
  • विनाश: संबंधित scope से बाहर निकलते ही release स्वचालित रूप से हो जाता है। पैरेंट interface instance को destructor ara::diag::DoIPEntityIdentification::~DoIPEntityIdentification के माध्यम से रिलीज़ किया जाता है ([SWS_DM_01365], SWS Diagnostics §8.33.1.1.1.1)।
  • समवर्तीता: चूँकि यह 6-byte array से बनी एक प्राथमिक डेटा संरचना है, इसलिए समवर्ती रीड एक्सेस गैर-महत्वपूर्ण है, बशर्ते ऑब्जेक्ट को अपरिवर्तनीय रूप से पास किया गया हो या एप्लिकेशन पक्ष पर thread-safe तरीके से बनाया गया हो।

उपयोग पथ

EntityId के उपयोग की नियमित प्रक्रिया निम्नलिखित चरणों में विभाजित है:

  1. कॉन्फ़िगरेशन जाँच: Diagnostic Management डेटा मॉडल के आधार पर जाँच करता है कि क्या DoIP नेटवर्क के लिए इंटरफ़ेस के माध्यम से entity identification प्राप्त करना कॉन्फ़िगर किया गया है (DoIpNetworkConfiguration.eidRetrieval == DoIpEidRetrievalEnum.eidUseApi) ([SWS_DM_01361])।
  2. API कॉल: DM एप्लिकेशन द्वारा पहले instantiate की गई क्लास पर ara::diag::DoIPEntityIdentification::GetEntityId को कॉल करके EID की पुनर्प्राप्ति शुरू करता है ([SWS_DM_01361], [SWS_DM_01364])।
  3. संरचना को भरना: Adaptive Application संरचना EntityId के भीतर member entityIdentification को पहचानकर्ता के 6 बाइट्स ([SWS_DM_01496]) के साथ initialize करती है और ऑब्जेक्ट को DM को return value के रूप में वापस लौटाती है।
  4. प्रोटोकॉल प्रोसेसिंग: DM EntityId से 6 बाइट्स निकालता है और नेटवर्क में वाहन या इकाई की घोषणा करने के लिए उन्हें भेजे जाने वाले DoIP प्रोटोकॉल संदेशों में सम्मिलित करता है (SWS Diagnostics §7.2.1.2)।

Sequence diagram: GetEntityId() के माध्यम से EID पुनर्प्राप्ति का विशिष्ट प्रवाह और अनुपलब्धता की स्थिति में fallback व्यवहार। स्रोत: [SWS_DM_01361], [SWS_DM_01496], [SWS_DM_01528]।

त्रुटि परिदृश्य

EntityId के प्रावधान और प्रसंस्करण में निम्नलिखित त्रुटि स्थितियों और पूर्व-शर्तों पर ध्यान दिया जाना चाहिए:

  • पूर्व-शर्त: C++ API के माध्यम से पुनर्प्राप्ति के लिए यह अनिवार्य है कि DoIpNetworkConfiguration.eidRetrieval को eidUseApi पर कॉन्फ़िगर किया गया हो ([SWS_DM_01361])। अन्यथा method GetEntityId को DM द्वारा कॉल नहीं किया जाएगा।
  • अनुपलब्ध इंटरफ़ेस: यदि DM द्वारा EID क्वेरी के समय इंटरफ़ेस ara::diag::DoIPEntityIdentification अभी तक उपलब्ध नहीं कराया गया है या EID का पढ़ना विफल हो जाता है ([SWS_DM_01528], SWS Diagnostics §7.2.1.2), तो एक मानकीकृत fallback लागू होता है।
  • Fallback व्यवहार (EID प्रतिस्थापन मान): त्रुटि की स्थिति में, DM DoIP प्रोटोकॉल संदेशों में एक निश्चित रूप से परिभाषित 6-बाइट प्रतिस्थापन मान प्रसारित करता है, जिसमें सभी बाइट्स 0xFF पर सेट होते हैं (0xFF 0xFF 0xFF 0xFF 0xFF 0xFF) ([SWS_DM_01528])।
  • उत्तर-शर्त: सफल निष्पादन के बाद, DM के पास एक पूर्ण 6-बाइट पहचानकर्ता उपलब्ध होता है ([SWS_DM_01496]), जिससे प्रतिस्थापन मान का सहारा लिए बिना अनुरूप DoIP संदेश उत्पन्न किए जा सकते हैं।
