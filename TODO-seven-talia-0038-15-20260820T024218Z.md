- Added `POLICY_SCHEMAS` pinned expected `schema` field per JSON policy file (`issue-authorities@v1`, `credential-handles@v1`, `runner-service@v1`); missing/mismatched schema is reported as a "stale policy" `BLOCKED` finding rather than silently accepted. - Added a genuine capability/metadata distinction: `_fingerprint_from_keydata` independently recomputes the OpenSSH SHA256 fingerprint from raw base64 key bytes (verified to match real `ssh-keygen -lf` output). `allowed_signers` entries, `authorities.json` principal fingerprints (cross-checked against `allowed_signers`), and credential-handle fingerprints (cross-checked against their own `public_key` field) are elevated from `capability: "metadata"` to `capability: "verified"` only when this independent recomputation succeeds; otherwise reported `"unavailable"`. `runner-service.json` controls remain `capability: "metadata"` by design — the tool deliberately never executes `health_check`/`restart_path`/`rollback_path` as commands (that would turn a readiness check into an arbitrary-command mutator).
- Added `revoked` field handling for principals/handles/signers (the "revoke" fixture category): a revoked entry no longer counts toward role/handle coverage.
- Fixed a real field-name bug: the old code checked `public_key_fingerprint` but the live schema's field is `fingerprint`, so credential-handle verification was previously silently ineffective.
- `check_signing_key` and all other checks never print the configured signing-key file path or any private-key-adjacent path; only booleans/status text.
- Every check now takes an explicit `root: Path` parameter (via `policy_paths(root)`) instead of hardcoded module-level path constants, making it independently testable against synthetic fixture trees.
