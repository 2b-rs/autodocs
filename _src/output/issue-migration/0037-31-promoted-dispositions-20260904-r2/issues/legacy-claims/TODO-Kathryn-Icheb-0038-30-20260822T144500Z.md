## Decision: the checker is wrong, the manifest text is right

The manifest defines activation itself, in two places, and both contradict the checker:

1. `consumers[].task == "0037-46.01"` carries the obligation:
   *"Register every `typed-action` disposition's action IDs in the permanent typed-action
   registry (`_src/runner/actions-v1.json`) with the compatibility note honoured and the
   named test fixtures inherited; implement no generic shell action; **do not activate**."*
   The manifest therefore **commissions `_src/runner/` itself** and, in the same sentence,
   states that creating it is not activation. The existence of that path cannot be the
   activation signal without the manifest contradicting its own consumer obligation.
2. `singleton.note`: *"The singleton remains the only mechanism that accepts mutating requests
   **until `0037-46.02` bumps the protocol epoch**."* — and the companion page
   `docs/pipeline/legacy-handoff-manifest.md` (line 103) spells that out:
   *"`0037-46.02` bumps the runner protocol epoch **in the live bootstrap selector** after
   queue health, round-trip, concurrency, restart and mutation-isolation tests pass durably."*

So the manifest's own definition of activation is: **the live bootstrap selector's runner
protocol epoch has been bumped**, at which point the queue — not the singleton — accepts
mutating requests. Liveness, not the presence of a source file.

Consequence: the manifest JSON is **not** edited. The fix is confined to the checker.

## Chosen distinguishing signal

`LHM035` ("the queue is live") fires on either of two liveness signals, and on neither
registry-on-disk signal:

- **`.runner/` runtime root exists** — unchanged from `0038-16.01`. This is git-ignored
  *runtime* state; it comes into being only when a dispatcher actually runs. Presence is
  liveness. (The existing fault-injection test for this keeps passing untouched.)
- **`agent-workflow.json` (`agent-workflow-bootstrap@v1`, the live bootstrap selector) declares
  a `runner_protocol` other than the pre-activation `runner-request@v1`** — i.e. exactly the
  epoch bump `0037-46.02` performs, read from exactly the artifact
  `legacy-handoff-manifest.md` names.
- **`_src/runner/` alone no longer fires.** It is the versioned typed-action *registry source*
  the manifest commissions under `0037-46.01` with "do not activate".

A missing or unparsable selector is deliberately **not** treated as activation: activation
requires the selector to positively declare the new protocol, and selector corruption is the
fail-closed responsibility of the bootstrap path (`docs/pipeline/agent-workflow.md`), not of
this read-only manifest checker. Recorded as an assumption rather than left implicit.
