Rolle im gemeldeten Prozess-Lifecycle

ExecutionClient ist die Prozess-seitige Schnittstelle für einen Reporting Process. Ein gemeldetes kRunning lässt Execution Management den Prozesszustand Running erreichen; Execution State und der intern geführte Process State bleiben dabei getrennte Modelle SWS EM §7.3.1 „Execution State“ SWS EM §7.3.2 „Process States“.

Deterministischer Anlauf und Terminierung

Ein Reporting Process meldet kRunning nach Abschluss seiner Initialisierung und vor einer potenziell nichtdeterministischen Service-Discovery-Phase. Dadurch können konfigurierte Abhängigkeiten auf einen belastbaren Process State auflösen. Bei einer Terminierungsanforderung löst Execution Management SIGTERM aus; der bei Create hinterlegte Handler wird von ExecutionClient aufgerufen [SWS_EM_02562] [SWS_EM_02003] [SWS_EM_02577].

Grenzen der Verantwortung

Der Client meldet nur den eigenen Zustand; Execution Management ist zwar für Start, Stopp und OS-Konfiguration zuständig, nicht aber für das laufende Scheduling des Prozesses, das beim Operating System liegt [SWS_EM_01401] SWS Operating System Interface §7.1.2 „Process Handling“ SWS Operating System Interface §7.1.3 „Scheduling Policies“.
