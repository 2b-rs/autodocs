Die Adaptive Platform in einem Satz

Die AUTOSAR Adaptive Platform ist eine service-orientierte Laufzeitumgebung für leistungsfähige Fahrzeugrechner: Adaptive Applications laufen als eigenständige POSIX-Prozesse, werden dynamisch gestartet und überwacht und kommunizieren über vertraglich definierte Services statt über statisch verdrahtete Signale (EXP PlatformDesign §3.3 „Adaptive Platform – Characteristics“, §8.2 „Service Oriented Communication“).

ARA — die Programmierschnittstelle dieser Referenz

Alle hier dokumentierten ara::*-Namespaces bilden zusammen das ARA-Interface (AUTOSAR Runtime for Adaptive Applications). Jeder Functional Cluster der Plattform exportiert seine C++-API in einem eigenen Namespace — von den Basistypen in ara::core über die Service-Kommunikation in ara::com bis zu Plattformdiensten wie ara::exec, ara::per oder ara::crypto (EXP PlatformDesign §4.1 „Logical view“, EXP SWArchitecture §9.1 „Building Block View – Overview“).

Übergreifende Konzepte

  • Machine & Software Cluster: Eine Machine ist die (ggf. virtualisierte) Ausführungsumgebung; Software wird als installierbare Software Cluster paketiert und per ara::ucm aktualisiert (EXP SWArchitecture §13.4 „Software Cluster“, §13.5 „Machine“).
  • Function Groups & States: Prozesse werden Function Groups zugeordnet; ara::sm beauftragt über Function-Group-States das Execution Management, Prozesse zu starten/stoppen (EXP SWArchitecture §13.2 „Function Group“, EXP PlatformDesign Kap. 7 „State Management“).
  • Manifeste: Execution-, Service-Instance- und Machine-Manifest konfigurieren Deployment, Startverhalten und Service-Bindung deklarativ (EXP PlatformDesign §4.4 „Manifest“, EXP SWArchitecture §13.6 „Manifest“).
  • Fehlerbehandlung ohne Exceptions: Plattformweit werden Fehler als ara::core::Result/ErrorCode zurückgegeben (EXP PlatformDesign §18.1 „Error Handling“, EXP SWArchitecture §13.12 „Error Handling“).
  • Safety & Security als Querschnitt: E2E-Schutz, Health Monitoring (ara::phm), Krypto-Stack, Identity & Access Management, Intrusion Detection (ara::idsm) und Firewall (ara::fw) sichern Plattform und Kommunikation ab (EXP PlatformDesign Kap. 17 „Safety“, EXP SWArchitecture §13.13 „Trusted Platform“).
