## Incident — foreign stash popped into this worktree (self-reported)

While comparing `process_doc_doctor` output against a baseline, this session ran
`git stash` followed by `git stash pop` from within its worktree. **The stash stack is
repository-wide, not per-worktree.** This session had nothing to stash, so the `pop`
restored a **pre-existing foreign entry** (`stash@{0}`, "Auto stash before rebase of
`main`", ~16,900 paths) into this worktree's index.

- **Detected by** reading the `git stash pop` output — "The stash entry is kept in case you
  need it again" — which does not appear on a normal successful pop.
- **Recovery:** `git reset --hard 154ebeaa8` in this worktree only.
- **Verified after recovery:** all three stash entries still present and undropped
  (`git stash list | wc -l` = 3, and `stash@{0}` still shows its 16,921-file content);
  `git status --porcelain` empty; 21/21 tests green; AE-8 projection check exit `0`.
- **Damage:** none persisted. No foreign content was committed, no other worktree was
  touched, the root checkout was not written to, and `refs/heads/main` was not moved.
  One `automation_safety` run had executed against the contaminated tree; it was
  **discarded and re-run**, not reported.
- **Root cause:** treating `git stash` as worktree-local. It is not.

## Collaboration suggestion (recorded here, not appended to `AGENTS.md`)

`AGENTS.md` requires recording insights immediately, but also permits recording them in
the active claim when a safe append is not available. This session's authorized
`AGENTS.md` write scope is the reviewed requirement block only; widening it to the
suggestion log would mutate a governance artifact beyond what `data` reviewed, and
`DEC-0044-012` puts governance changes on `main`. So it is recorded here for reconciliation
by whoever holds that authority.

- **Date / proposer / scope:** 2026-08-25 — `agent:tom-sisko-20260825t091500z:0038-34:20260825T091500Z` — general / worktree isolation.
- **Observation:** `git stash` and `git stash pop` operate on a **repository-wide** stack
  shared by every worktree and the root checkout. An agent that runs `stash` with nothing
  to stash and then `stash pop` will silently restore **another agent's** stashed state
  into its own index. With 100+ registered worktrees and a stash stack that persists for
  months (the entry hit here dates from a `main` rebase, and two others from `0042-02.01`
  in August), this is reachable by any agent doing an ordinary baseline comparison.
  `DEC-0044-015` isolates *worktrees*; it does not isolate the stash stack, and nothing in
  the authority documents currently warns that this shared mutable stack exists.
- **Suggestion:** state in `AGENTS.md`/`SANDBOX.md` that the stash stack is shared and that
  agents must not use `git stash` for baseline comparison; use a detached temporary
  worktree (`git worktree add --detach /tmp/... <ref>`) instead, which is genuinely
  isolated. Optionally have the hygiene check report a non-empty stash stack as advisory,
  so long-lived entries are visible rather than latent.
- **Expected benefit:** removes a silent cross-agent contamination path that looks like a
  local operation and produces no error on the way in. Recovery here was clean only
  because the `pop` conflicted and git therefore *kept* the entry; had it applied cleanly,
  git would have **dropped** the foreign entry and the owning agent's state would have
  been destroyed with no copy.
- **Risk/tradeoff:** a temporary worktree costs a checkout; prose alone will not prevent
  this, since the hazard is invisible at the call site. Building the advisory check is a
  Task, not authorized by this suggestion.
- **Evidence:** this claim's incident section; `154ebeaa8`; stash stack intact at 3 entries.
