State Management 的角色及其与 Execution Management 的界分

State Management 确定平台的运行状态。Execution Management 执行状态之间的转换（SWS EM 第51页）。State Management 从特定于应用的输入中派生出活动 Function Group State 的目标集合。它通过 StateClient API 向 Execution Management 请求对其进行切换（EXP SWArch 第50页；SWS SM 第40页）。StateMachine 方法是可选的。它将项目特定的仲裁转移到仅请求已配置转换的 SMControlApplication 中（SWS SM 第28页；SWS SM 第42页）。

State Management 提供以下 ara::com 服务：

  • 用于 Update and Configuration Management 的 UpdateRequest（[SWS_SM_91102]）。
  • 用于 SMControlApplication 的 StateMachineService 和 UpdateAllowedService（[SWS_SM_91107]，[SWS_SM_91108]）。
  • 用于任意 Adaptive Application 的 StateMachineNotification::CurrentState（[SWS_SM_91109]）。

针对内存挂起（Suspend-to-RAM），增加了 S2RHub 和 S2RSatellite，针对操作系统增加了平台扩展 PowerStateInterface（EXP SWArch 第51页；SWS SM 第163页）。State Management 本身需要来自 Execution Management、Platform Health Management 和 Network Management 的接口（SWS SM 第17页；EXP SWArch 第77页）。

从机器启动到控制器 StateMachine

操作系统将 Execution Management 作为首个进程启动。Execution Management 激活 Machine Function Group State Startup，且 State Management 必须是该状态的一部分（EXP SWArch 第216页）。该自发发起的转换结果由 GetInitialMachineStateTransitionResult 提供。此后，状态切换的职责落在 State Management 上（SWS EM 第48页；SWS EM 第56页）。如果始终未达到 Startup，State Management 可以通过 SetState 中断该转换。此时初始结果为 kOperationCanceled（SWS EM 第57页）。

在 StateMachine 方法中，首先启动类型为 Controller 的 StateMachine。它管理 MachineFG 并启动 Agents（SWS SM 第46页）。如果更新会话处于活动状态，控制器将进入状态 ContinueUpdate 而非初始状态（SWS SM 第91页）。在“StartStateMachine”成功执行后，将提供 StateMachineService 和 StateMachineNotification。控制器不会等待初始 ActionList 结束（SWS SM 第45页；SWS SM 第59页）。

时序图：Execution Management 在 Startup 之后移交控制权，控制器启动各 Agent。来源：SWS SM 第93页、SWS EM 第56页、SWS SM 第45页

停止操作会使 Agent-StateMachine 转换至其“Off”状态，之后它便不再存在。对于已在运行的 Agent，若带有参数调用“StartStateMachine”，则会转换至所传入的状态（SWS SM 第63页；SWS SM 第60页）。

状态转换：RequestTransition 与 ActionLists

RequestTransition 针对当前状态评估 TransitionRequestTable 中传入的值（[SWS_SM_91107]；SWS SM 第50页）。在下列情况下，该调用将返回错误：

  • kInvalidValue：该值未配置。
  • kTransitionNotAllowed：该值未针对当前状态进行配置。
  • kRecoveryTransitionOngoing：错误恢复正在运行。
  • kUpdateInProgress：StateMachine 被标记为“ImpactedByUpdate”。

参考凭据：SWS SM 第49页；SWS SM 第83页。如果请求被接受，尚未完成的请求将收到 kOperationCanceled。当前正在运行的 ActionList 将被停止，目标状态的 ActionList 立即启动（SWS SM 第50页）。

ActionListItems 按配置的顺序启动并并行运行，直到遇到 SYNC。在每个 ActionList 结束时应用隐式 SYNC（SWS SM 第55页）。存在用于 Function Group States、Sleep、SetNetworkHandle、Start/Stop StateMachine 以及 Suspend-to-RAM 的项（SWS SM 第54页）。Sleep 不会阻止传入的触发（SWS SM 第64页）。执行中的错误会导致 kTransitionFailed（SWS SM 第51页）。在转换期间，CurrentState 处于“InTransition”状态（[SWS_SM_91109]）。NetworkHandle 转换到 FullCom 或 NoCom 也会触发基于表的转换（SWS SM 第52页）。

与 Update and Configuration Management 的更新会话

会话以 RequestUpdateSession 开始。如果机器不可更新，State Management 可以拒绝该会话。对于第二个并行会话，它会以 kNotAllowedMultipleUpdateSessions 拒绝（[SWS_SM_91102]；SWS SM 第30页）。更新是否被允许由 SMControlApplication 通过字段 UpdateAllowed 决定。每台机器最多存在一个 UpdateRequest 端口，且仅由控制器的进程对其进行实例化（[SWS_SM_91108]；SWS SM 第79页）。

PrepareUpdate、VerifyUpdate 和 PrepareRollback 接收受影响的 Function Group 列表。管理其中任一 Function Group 的每个 StateMachine 都会被标记为“ImpactedByUpdate”。如果某个 Agent 受到影响，控制器也会被标记（[SWS_SM_91103]、[SWS_SM_91104]、[SWS_SM_91105]；SWS SM 第82页）。在活动会话之外，这些方法以及 StopUpdateSession 会返回 kOperationRejected（SWS SM 第31页）。受影响的 Agent 根据所用方法受到不同处理：

  • 在 PrepareUpdate 和 PrepareRollback 下，它们会被停止。
  • 在 VerifyUpdate 下，它们会被置于状态 VerifyUpdate。

参考凭据：SWS SM 第84页；SWS SM 第85页；SWS SM 第89页。StopUpdateSession 将控制器引导至 AfterUpdate 并重新释放 RequestTransition（[SWS_SM_91101]；SWS SM 第95页）。

时序图：从控制器视角看更新会话的流程。来源：SWS SM 第81页、SWS SM 第84页、SWS SM 第89页、[SWS_SM_91102]

ResetMachine 为 Fire&Forget。Update and Configuration Management 通过 ResetMachineNotifier 跟踪进度，因为在重启后机器与 UCM 必须重新同步（[SWS_SM_91100]、[SWS_SM_91106]；SWS SM 第33页）。

通过 S2R Hub、Satellite 和 PowerStateInterface 实现 Suspend-to-RAM

应用程序根据 suspendToRamAwareness 受到不同处理（SWS SM 第109页）：

  • 在 suspendToRamNotSupported 下，它们通过 Function Group 转换终止。
  • 在 suspendToRamAware 下，它们作为 S2R Satellite 收到通知。

Satellite 通过 Create 或带有 InstanceSpecifier 的构造函数创建，并使用 Offer 进行注册（[SWS_SM_81014]、[SWS_SM_81003]、[SWS_SM_81012]）。StopOffer 用于将其注销，该操作会阻塞直到正在运行的回调结束，并且必须在析构之前调用（[SWS_SM_81013]；SWS SM 第38页）。回调 EnterSuspendMode 和 LeaveSuspendMode 是纯虚函数并返回 ara::core::Future<void>（[SWS_SM_81010]、[SWS_SM_81011]）。

RequestToEnterSuspendMode 和 RequestToLeaveSuspendMode 调用所有已激活注册且经 IAM 鉴权的 Satellite。一旦所有 Satellite 均已响应、已注销或超时（默认 1000）到期，它们便返回（[SWS_SM_81110]、[SWS_SM_81111]；SWS SM 第36页）。随后，EnterSuspendToRamOs 触发操作系统的挂起。解释：这可能是通过带有 kPmSuspendToRam 的 PowerStateInterface::SetPowerState 完成的（[SWS_SM_81112]、[SWS_SM_71001]、[SWS_SM_71002]）。

操作系统通过使用 RegisterWakeUpHandler 注册的 WakeUpHandler 报告唤醒事件。随后，控制器自主转换至 LeaveSuspend，其 ActionList 必须包含 LeaveSuspendToRam（[SWS_SM_71003]、[SWS_SM_71004]；SWS SM 第103页）。在 StateMachine 方法中，控制器在内部使用 Hub。届时应用程序不得使用 S2RHub（SWS SM 第96页）。所有 S2R API 均处于 DRAFT 状态。

配置规则与职责划分

除 Off 之外的每个 MachineFG 状态中，都必须运行一个关联性为 STATE_MANAGEMENT 的进程。否则，机器将（例如）停滞在 Startup 中（SWS SM 第146页）。对于 Function Group 和 NmNetworkHandle，适用唯一性规则：

  • 每个 Function Group 和每个 NmNetworkHandle 仅由一个 StateMachine 引用。
  • StateMachine 的所有 ActionList 包含相同集合的 Function Group 和 NmNetworkHandle。

参考凭据：SWS SM 第48页；SWS SM 第66页；SWS SM 第57页；SWS SM 第58页。仅控制器使用 Start/StopStateMachine。Agent 仅管理来自相同 claimedFunctionGroups 集合的 Function Group，并且需要一个“Off”状态（SWS SM 第58页；SWS SM 第47页；SWS SM 第48页）。maxActionListDuration 限制了 ActionList 的持续时间。若缺少该值，则适用模块实例的全局值（SWS SM 第68页）。

发生错误时的行为

如果 Platform Health Management 或 Execution Management 报告错误，且该 StateMachine 未处于“ImpactedByUpdate”状态，则其设置一个恢复标志。它会评估 ErrorRecoveryTable 并立即转换至目标状态。一个强制性条目 ANY 用于捕获未配置的 ErrorCode（SWS SM 第69页；SWS SM 第70页）。受更新影响的 StateMachine 会忽略此类请求且仅对其进行记录（SWS SM 第82页）。在恢复进行过程中出现的新错误被视为“nested recovery”。随后所有相关的 RecoveryHandler() 调用都将收到相同的结果（SWS SM 第29页）。仅当恢复 ActionList 成功执行完毕后，该标志才会被复位（SWS SM 第72页）。

其他错误源构成单独的 ErrorCode：

  • SetState 错误 kNoCommunication、kInvalidTransition 和 kInvalidMetaModelIdentifier 被映射到 functionGroupTransitionRequestFailedError。
  • ActionList 超时、Agent 启动和停止以及 LeaveSuspendToRam 具有各自的 ErrorCode，默认值为 1。

参考凭据：SWS SM 第73页；SWS SM 第74页；SWS SM 第76页。kIntegrityOrAuthenticityCheckFailed 在每次进一步尝试中都会重复发生，其解决办法在 State Management 之外（SWS SM 第40页）。如果 State Management 未及时响应 RecoveryHandler()，Platform Health Management 将调用 FireWatchdogReaction()。State Management 本身的监控错误会导致机器重启（EXP SWArch 第234页；EXP SWArch 第235页）。

在 API 级别，State Management 通过名为“Sm”的 SmErrorDomain 以及诸如 kOfferFailed 或 kCommunicationFailed 之类的 SmErrc 值报告错误（[SWS_SM_81240]、[SWS_SM_81248]）。MakeErrorCode 和 GetSmDomain 生成这些代码（[SWS_SM_81244]、[SWS_SM_81251]）。如果启用了 C++ 异常，SmException 会传递它们（[SWS_SM_81243]、[SWS_SM_81250]）。Hub 将 Satellite 的响应汇总为 kAtLeastOneRejected、kAtLeastOneHadIssuesToLeave、kCommunicationTimeout 或 kCommunicationFailed（SWS SM 第37页）。
