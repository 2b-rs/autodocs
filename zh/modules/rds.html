实现非结构化 IP 和 IEEE 1722 原始数据流的高性能、免序列化传输。

自适应集群 Raw Data Stream (RDS) 用于在绕过面向服务的序列化开销的情况下，优化非结构化数据流以及时效性传感器与多媒体数据的传输延迟与吞吐量 AUTOSAR_AP_EXP_SWArchitecture 第74页。它为基于 IP 的点对点字节流 (TCP/UDP) 以及符合 AVTP 标准 IEEE 1722 的第 2 层流传输提供 C++ API [SWS_RDS_10482], [SWS_RDS_90312]。这两种通信形式均严格通过静态工厂方法工作，并通过平台范围的 Result 结构以节省资源的方式报告错误 [SWS_RDS_12367]。

功能集群 Raw Data Stream (RDS) 为 AUTOSAR Adaptive Platform 提供用于传输未格式化字节流和时效性传感器数据的高性能接口 AUTOSAR_AP_EXP_SWArchitecture 第73页。通过直接抽象 POSIX 网络套接字以及第 2 层以太网接口，RDS 绕过了标准面向服务通信 (ara::com) 复杂的序列化 AUTOSAR_AP_EXP_SWArchitecture 第74页。

对于基于 TCP 或 UDP 的 IP 字节流，应用程序使用类 RawDataStreamClient 和 RawDataStreamServer，这些类通过静态 Create 方法绑定到建模的端口 [SWS_RDS_10482], [SWS_RDS_11312]。在通过 Connect 或 WaitForConnection 建立连接后，数据量无需不必要的内存复制即可借助 std::unique_ptr<ara::core::Byte[]> 通过 ReadData 和 WriteData 进行交换 [SWS_RDS_10486], [SWS_RDS_10487], [SWS_RDS_11301]。

对于来自摄像头或音频源的确定性实时数据流，RDS 实现了符合 IEEE 1722 (AVTP) 的类，例如 IEEE1722RawDataStreamProducer 和 IEEE1722RawDataStreamConsumer [SWS_RDS_90312], [SWS_RDS_90323]。特定的子类型类，如 RVF（视频）、AAF（音频）和 CRF（时钟参考），在此封装了符合标准的帧头与有效负载数据 [SWS_RDS_90262], [SWS_RDS_90276], [SWS_RDS_90295]。

错误以符合平台规范的方式在不使用 C++ 异常的情况下通过 ara::core::Result 和带有特定错误码 (RdsErrc) 的错误域 RdsErrorDomain 进行指示 [SWS_RDS_11298], [SWS_RDS_12367]。在 AUTOSAR 清单中，接口定义通过 RawDataStreamClientMapping 和 RawDataStreamServerMapping 无缝绑定到以太网端点 AUTOSAR_AP_TPS_ManifestSpecification 第851页。

架构归属与系统边界

AUTOSAR Adaptive Platform 的功能集群 Raw Data Stream (RDS) 为非结构化或实时关键数据流的高性能传输提供标准化应用程序编程接口 (API) AUTOSAR_AP_EXP_SWArchitecture 第73页。与通过 ServiceInterfaces（如 SOME/IP 或 DDS）进行的强类型、面向服务的通信相反，RDS 完全绕过了 ara::com 的序列化和协议开销 AUTOSAR_AP_EXP_SWArchitecture 第74页。这使得能够将宽带传感器（如视频摄像头、雷达、LiDAR 传感器或音频系统）直接以支持实时且吞吐量优化的方式连接到 Adaptive Applications AUTOSAR_AP_EXP_SWArchitecture 第61页。

在架构上，该模块分为两大基本通信支柱：其一是通过传输协议（如 TCP 或 UDP）进行的基于 IP 的字节流传输，封装了 POSIX 套接字并带有可选的 TLS/IPsec 保护 AUTOSAR_SWS_CommunicationManagement 第58页。其二，该模块为通过以太网和时间敏感网络 (TSN) 网络按照 IEEE 1722（音频视频传输协议，AVTP）进行第 2 层流传输提供了专用子系统 AUTOSAR_AP_EXP_SWArchitecture 第74页。这两种通信形式都将系统特定的网络和缓冲区结构抽象到命名空间 ara::rds 中的统一 C++ 类之后 AUTOSAR_AP_SWS_RawDataStream 第39页。

实例化与连接管理

在 RDS 中，通信端点的创建严格通过绑定到建模端口实例的静态工厂方法进行 [SWS_RDS_10482]。对于基于 IP 的字节流，类 ara::rds::RawDataStreamClient 和 ara::rds::RawDataStreamServer 封装了发起方和侦听方的角色 AUTOSAR_AP_EXP_SWArchitecture 第73页。工厂 RawDataStreamClient::Create 通过 ara::core::InstanceSpecifier 为清单中定义的端口线程安全地实例化客户端端点 [SWS_RDS_10482]。类似地，RawDataStreamServer::Create 创建关联的服务器端点实例 [SWS_RDS_11312]。这两个类均禁止复制构造函数和复制赋值，但显式支持移动语义以实现明确的资源归属 [SWS_RDS_11303], [SWS_RDS_11305], [SWS_RDS_11316], [SWS_RDS_11314]。

初始化成功后，服务器通过 WaitForConnection 以阻塞方式或使用指定的超时等待传入连接 [SWS_RDS_11318], [SWS_RDS_11319]。客户端则通过 Connect 主动建立连接，可选择无限制或在以毫秒为单位的时间段内 [SWS_RDS_10484], [SWS_RDS_11307]。活动会话的终止既可以通过调用 Shutdown [SWS_RDS_10485], [SWS_RDS_11320] 确定性地发生，也可以在析构函数调用中隐式发生，析构函数会自动关闭并释放仍处于打开状态的连接 [SWS_RDS_10483], [SWS_RDS_11313]。

通过套接字进行非结构化 IP 数据交换

IP 连接的数据传输设计为双向，并通过具有可选超时监控的可同步处理操作执行 [SWS_RDS_10486], [SWS_RDS_11309]。在接收方，操作 ReadData 返回类型为 ara::rds::ReadDataResult 的数据结构 [SWS_RDS_10486], [SWS_RDS_11322]。该结构以智能指针 data (std::unique_ptr<ara::core::Byte[]>) 的形式封装读取的二进制数据，并通过字段 numberOfBytes 指定实际接收的字节数 [SWS_RDS_11301], [SWS_RDS_11302]。通过转移缓冲区所有权，避免了不必要的内存复制。

为了发送二进制数据，应用程序同样使用移动语义通过 std::unique_ptr<ara::core::Byte[]> 传递字节缓冲区，并在 WriteData 中指定最大长度 maxLength [SWS_RDS_10487], [SWS_RDS_11324]。对于对延迟敏感或存在阻塞风险的网络路径，可以使用带有以毫秒为单位的显式超时规范的 ReadData 和 WriteData 的重载变体 [SWS_RDS_11310], [SWS_RDS_11323], [SWS_RDS_11325]。藉此可以确定性地拦截对端未响应或网络缓冲区卡顿的情况 AUTOSAR_AP_EXP_InterfacesGuidelines 第41页。

使用 IEEE 1722 (AVTP) 进行近实时流传输

对于确定性的等时多媒体与传感器流，RDS 提供了符合 IEEE 1722 的用于消费者和生产者的专用模板类 [SWS_RDS_90312], [SWS_RDS_90323]。类 ara::rds::IEEE1722RawDataStreamConsumer<T> 用作数据槽并通过 Create 实例化 [SWS_RDS_90312]。借助 Connect，它绑定到分配的流（在过滤多播 MAC、VLAN 和流 ID 的情况下）AUTOSAR_AP_EXP_SWArchitecture 第203页，以便随后通过 ReadData 读取最多 maxNumberOfDatagrams 个结构化数据报作为 std::vector<T> [SWS_RDS_90319], [SWS_RDS_90321]。类似地，ara::rds::IEEE1722RawDataStreamProducer<T> 负责通过 WriteData(std::vector<T>) 生成和发送 AVTP 帧 [SWS_RDS_90323], [SWS_RDS_90330], [SWS_RDS_90332]。

发生错误时的行为

RDS 中的错误处理遵循 AUTOSAR Adaptive Platform 通过 ara::core::Result 和 ara::core::ErrorCode 进行错误求值的方法 [SWS_RDS_10484], [SWS_RDS_11299]。所有可能失败的 API 方法——包括 Create、Connect、WaitForConnection、ReadData 和 WriteData——均声明为 noexcept，并通过返回类型 ara::core::Result 返回错误码 [SWS_RDS_10482], [SWS_RDS_10484], [SWS_RDS_11318]。模块特定的错误状态在枚举 ara::rds::RdsErrc 中管理 [SWS_RDS_12367]，可通过类型别名 ara::rds::RdsErrorDomain::Errc 引用 [SWS_RDS_11326]。

该模块为此定义了错误域 RdsErrorDomain，其实例通过 GetRdsErrorDomain() 获取 [SWS_RDS_11298]。显式删除了 RdsErrorDomain 的默认构造函数 [SWS_RDS_11294]。错误描述和域名可以通过虚方法 Message(CodeType) 和 Name() 读取 [SWS_RDS_11295], [SWS_RDS_11296]。工厂函数 MakeErrorCode 允许从 RdsErrc 码和附加数据创建类型化错误对象 [SWS_RDS_11299]。对于启用了 C++ 异常的环境，该模块提供了异常 ara::rds::RdsException [SWS_RDS_11292], [SWS_RDS_11327]，其可以通过 RdsErrorDomain::ThrowAsException 抛出 [SWS_RDS_11297]。
