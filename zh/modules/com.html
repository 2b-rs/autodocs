沟通模式

ara::com是通信管理功能集群的标准化应用接口。集群构建并监控相同或不同机器上的应用程序之间的通信路径；然而，具体的内部中间件架构仍然是实现的问题。 SWS CM §7.1.1 “Architectural concepts” 和 SWS CM §7.1.2 “Design decisions” 将 API 归类为协议抽象、面向服务的接口。

建模的Service Interface中出现了两个角色：Proxy是消费者的本地代表，Skeleton将提供者实现与传输基础设施连接起来。方法、事件、字段和触发器是四种预期的通信形式。 EXP ARAComAPI §4.1 “Proxy/Skeleton Architecture”、EXP ARAComAPI §4.2 “Means of Communication”和SWS CM §7.1.3 “Communication paradigms and Definitions”描述了这种分工。

从服务提供到使用

在提供者方面，创建并提供框架。在消费端，一次性 FindService 提供当前已知的实例； StartFindService 监视可用性变化。句柄标识找到的实例并用于代理创建。如果出现暂时不可用的情况，应在以后的报价中重新建立通信路径。 SWS CM §7.5.1 “Offer service”、SWS CM §7.5.10 “Find service” 和 SWS CM §7.5.11 “Service proxy creation” 提供函数语义。

数据和交互形式

事件将数据传输给注册消费者；触发器使用相同的订阅机制，无需负载。方法模型请求/响应并可以提供Future。字段将读写方法字符与值更改通知结合起来。 EXP ARAComAPI §4.3 “Event and Trigger based communication”、EXP ARAComAPI §4.4 “Method based communication” 和 EXP ARAComAPI §4.5 “Field based communication” 解释应用程序视图。

操作规则和安全上下文

Subscribe()是异步的：只有状态或状态处理程序中的kSubscribed证明实际已建立订阅。收到的样品具有受控的所有权转让，并且必须在注销或Proxy销毁之前归还。 [SWS_CM_12006]和[SWS_CM_00085]是与此相关的规则。 E2E保护通过可以根据样本进行评估的状态信息来补充数据传输； SecOC可以通过平台扩展使用新鲜度值管理。 SWS CM §7.4 “Safety”和SWS CM §7.3.2 “Secure Communication”提供了总体框架。

发生错误时的行为

一次性服务搜索FindService()返回当时合适的服务句柄；如果当前不存在合适的服务实例，结果列表可以为空。另一方面，技术搜索错误被报告为 ara::core::Result 错误，其中 API 指定了 ComErrc::kCommunicationFailure 等。使用StartFindService()的连续搜索通过其处理程序报告可用性更改，该处理程序接收所有匹配实例的Container。 EXP ARAComAPI §5.3.2 “RadarService Proxy Class Example”[SWS_CM_00122][SWS_CM_00383]

事件订阅具有状态kNotSubscribed、kSubscriptionPending和kSubscribed。由于Subscribe()最初只接受申购订单，所以查询时状态仍可为kSubscriptionPending； GetSubscriptionState()和SetSubscriptionStateChangeHandler()使有效状态可访问。如果服务暂时不可用，处理程序报告kSubscriptionPending；成功重新订阅后，它会报告kSubscribed。通信管理实现必须在暂时不可用后恢复活动订阅。如果应用程序持有的SamplePtr对象多于承诺的Subscribe()，则GetNewSamples()返回错误ComErrc::kMaxSamplesExceeded；示例可能已被跳过。 [SWS_CM_00310][SWS_CM_00333][SWS_CM_00315][SWS_CM_00701]EXP ARAComAPI §5.3.5.2 “Monitoring Event Subscription”
