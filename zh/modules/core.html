分类及用途

ara::core模块是AUTOSARAdaptive Platform的基础库，在官方规范AUTOSAR_AP_SWS_Core.pdf (R25-11)中定义。它提供了无错误返回类型ara::core::Result以及错误域基类ara::core::ErrorDomain，它定义了一组错误条件的上下文； ErrorDomain子类是所有错误数据[SWS_CORE_10303]的根。 Adaptive Platform中的错误处理通常根据“ValueOrError”概念（EXP InterfacesGuidelines）通过ara::core::ErrorCode和ara::core::Result进行，没有C++异常。命名空间ara以及所有底层命名空间也被AUTOSAR保留；如果自适应应用程序在那里添加自己的声明，则行为是未定义的 (EXP InterfacesGuidelines)。这意味着ara::core构成了所有AP函数集群的初始化、错误处理和并发规则的共同基础。

关键对象和典型用法

ara::core::Result<T, E> 包含一个值或一个错误；错误类型必须是ErrorCode，否则会出现编译错误[SWS_CORE_00701]，具体化为引用类型[SWS_CORE_00901]和void值[SWS_CORE_00801]。 Result 是使用静态工厂函数 FromValue [SWS_CORE_00733] 或 FromError [SWS_CORE_00736] 创建的。 Bind 将可调用应用到包含的值并返回新的 Result；如果实例不包含值，则采用原始错误而不更改 [SWS_CORE_00768]。 Resolve 返回该值，或者在发生错误时调用兼容的可调用 [SWS_CORE_00767]，而 ErrorOr [SWS_CORE_00764][SWS_CORE_00763] 提供简单的回退值。当且仅当它们的 64 位唯一标识符匹配时，ErrorDomain 实例才相等；通常通过非成员访问器进行访问，例如 GetFutureErrorDomain [SWS_CORE_10401]。

对于Container和文字处理，该模块提供C++标准库的支持PMR的实现：ara::core::Vector[SWS_CORE_01301]、ara::core::Map[SWS_CORE_01400]、ara::core::StringView[SWS_CORE_02001]、 ara::core::BasicString[SWS_CORE_03000]和ara::core::Span[SWS_CORE_01900]。对于应用程序级模型引用，final类ara::core::InstanceSpecifier存在于ara/core/instance_specifier.h中，它封装了AUTOSARshortName路径[SWS_CORE_08001]。

创建、生命周期 & Ownership

整个 ARA 的生命周期通过两个自由函数 ara::core::Initialize 和 ara::core::Deinitialize 集中控制。Initialize 启动 ARA-Framework；这可能包括初始化内部数据结构和系统资源，以及启动后台线程 [SWS_CORE_15003]。如果 Initialize 使用命令行参数注入，则必须透明地移除相应参数，以免影响应用程序的参数解析 [SWS_CORE_15006]。成功调用会使 Framework 进入一个状态，在该状态下所有配置的组件都能立即处理 API 调用 [SWS_CORE_90026]；如果未先调用 Deinitialize 而进行第二次调用，则会返回 kAlreadyInitialized，且不会干扰正在运行的实例 [SWS_CORE_90029]。相反，Deinitialize 会启动 Framework 的关闭过程，包括终止已启动的后台线程、释放动态内存和其他系统资源 [SWS_CORE_15004]；如果 Framework 未成功初始化或已被反初始化，每次调用都会返回 kNotInitialized [SWS_CORE_90030]。

其中只有 ara::core 的一个明确命名的小子集。 ErrorCode、StringView、Result（不含ValueOrThrow）、ErrorDomain（不含ThrowAsException）、Initialize、Abort、SetAbortHandler 和AddAbortHandler – 可以独立于Initialize/Deinitialize[SWS_CORE_15002]使用。 Initialize之前的所有其他 ARA 函数的行为是实现定义的[SWS_CORE_15005]，并且Deinitialize之后在此子集之外的调用也具有实现定义的行为，因为出于性能原因[SWS_CORE_90022]故意不需要相应的运行时检查。 Guidelines for using Adaptive Platform interfaces将其总结为绑定启动/关闭合约：Initialize将在入口点调用，Deinitialize仅在所有ARA资源在其他线程中释放后调用；两者都返回Result<void>，必须进行检查，并且无法纠正错误，因此应用程序必须以EXIT_FAILURE（EXP InterfacesGuidelines）终止。此外，AUTOSAR AP RS General禁止特定于集群的初始化函数：如果函数集群需要显式初始化或取消初始化，则只能使用ara::core::Initialize/ara::core::Deinitialize。

错误处理、并发和限制

该规范精确地定义了线程安全：如果一个非静态 AUTOSAR API 成员函数可以从多个线程在同一个对象上同时调用，而无需调用者进行同步，则该函数是线程安全的；析构函数和赋值运算符通常不是线程安全的 [SWS_CORE_13200]。如果在同一个对象上同时调用非线程安全成员函数，则行为是未定义的 - 即使涉及的其他函数是线程安全的 [SWS_CORE_13203]；但是，允许在不同实例 [SWS_CORE_13205] 上进行竞争调用，无需同步。 ARA 实现仅顺序调用指定为非线程安全的回调或纯虚函数，例如 ara::tsync::SynchronizedTimeBaseNotifier，而例如 B. ara::phm::RecoveryAction::RecoveryHandler 线程安全的是 [SWS_CORE_13214]。在信号处理程序中使用任何 ARA API 都会导致未定义的行为，除非另有指定 [SWS_CORE_13210]（EXP InterfacesGuidelines：异步信号安全）。此外，AUTOSAR AP RS General 要求每个 API 函数将其线程安全级别指定为 “thread-safe”、“not thread-safe” 或 “conditional”，并且线程安全契约双向适用：如果 API 被指定为线程安全，则供应商或用户提供的实现（例如回调或纯虚拟骨架函数）应遵守此承诺（EXP InterfacesGuidelines）。

对于不可恢复的错误，ara::core将Violation与常规错误处理区分开来：Violation是违反框架前置条件或后置条件的结果，并且不可恢复，与失败的断言[SWS_CORE_00021]类似。标准化的Violation，进程通过ara::core::Abort异常终止；根据DLT定义的调试消息在stderr上输出，并且应该使用识别功能集群[SWS_CORE_00090]的上下文ID写入日志接收器。当对Abort的调用正在进行时，进一步的调用会阻塞调用线程[SWS_CORE_12407]；以相反的安装顺序调用已安装的中止处理程序；没有Handler，std::abort()称为[SWS_CORE_12404]。 Result/ErrorCode可恢复错误和不可恢复Violations[SWS_CORE_00021]的这种分离得到AUTOSAR AP RS General的支持，作为所有AP特征集群的一般原则。

集成 & 配置

通过ara::log进行日志记录时，每个 ARA Functional Cluster 使用ara::core规定的标准化 Log-and-Trace 设置，尤其是 Context ID 和 Message-ID 范围[SWS_CORE_00055]。为此，规范为每个 Functional Cluster 定义了标准化日志 Context ID，包括：com 使用#COM、core 使用#COR、crypto 使用#CRY、diag 使用#DIA、exec 使用#EXE、log 使用#LOG，以及 per 使用#PER [SWS_CORE_90024]。在要求层面，AUTOSAR AP RS General补充规定，若ara::core提供等效类型，ARA 接口必须使用ara::core类型而非 C++ 标准类型。由于命名空间ara完全保留给 AUTOSAR，Functional Cluster 的全部数据类型还可通过转发头文件<fc>_fwd.h获得（EXP InterfacesGuidelines）。
