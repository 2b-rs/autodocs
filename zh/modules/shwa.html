Safe Hardware Acceleration 的作用及其与应用程序进程的边界

Safe Hardware Acceleration（SHWA，命名空间 ara::shwa）使硬件加速能够以标准化且可移植的方式用于安全高效的计算 SWS SHWA 第4页。根据功能概述，SHWA 为 Adaptive Applications 和其他 Functional Clusters 提供 API。该集群涵盖三项任务：

  • 在硬件加速器（HWA）上并行执行计算密集型工作，
  • 检测并纠正其中运行的 Task 的错误，
  • 监控加速器的工作状态 SWS SHWA 第7页。

该集群的 Requirements 应考量 AUTOSAR 安全要求 SWS SHWA 第5页。

架构概述将 SHWA 归入 Safety 类别。与 Platform Health Management 不同，SHWA 在其中未被标记为 daemon-based EXP SW-Architektur 第127页。这些接口是 Adaptive Application 直接使用的原生 C++ 接口 EXP SW-Architektur 第132页。其他 Functional Clusters 也可以在没有 Adaptive Application 参与的情况下使用 SHWA。其库部分为此使用自身的 Deployment 信息，其守护进程则像 Adaptive Applications 一样进行建模 SWS SHWA 第23页。

在硬件方面，Device 通过 IsCpu、IsGpu 和 IsAccelerator 区分计算单元的类型 [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00311] [AP_SWS_SHWA_00312]。枚举 Target 指定了两个执行位置：针对设备或加速器的 kDevice，以及针对主机 CPU 的 kHostTask [AP_SWS_SHWA_00102]。

上下文图：Adaptive Applications 和其他 Functional Clusters 将 SHWA 用作原生接口；SHWA 接入 CPU、GPU 和加速器。来源：SWS SHWA 第23页、EXP SW-Architektur 第127页、[AP_SWS_SHWA_00310]

ara::shwa 的四个接口领域

规范中的图表将 API 划分为四个区域：数据管理、Task 执行、设备管理与监控以及错误处理 SWS SHWA 第17页。API 说明将前三个区域描述为层 EXP SHWA-API 第15页。

  • 数据管理：Range 和 Id 描述一维至三维的大小与索引 [AP_SWS_SHWA_01009] [AP_SWS_SHWA_00709]。此外还有 Buffer [AP_SWS_SHWA_00209]、Accessor [AP_SWS_SHWA_00007] 和 PropertyList [AP_SWS_SHWA_00802]。
  • Task 执行：Queue [AP_SWS_SHWA_00908]、TaskHandler [AP_SWS_SHWA_01202] 和 Event [AP_SWS_SHWA_00602]。
  • 设备管理与监控：Platform [AP_SWS_SHWA_01107] 和 Device [AP_SWS_SHWA_00308]。此外还有带有 GpuSelector、CpuSelector 和 AcceleratorSelector 的 DeviceSelector [AP_SWS_SHWA_00403] [AP_SWS_SHWA_00407] [AP_SWS_SHWA_00410] [AP_SWS_SHWA_00413] 以及 DeviceMonitor [AP_SWS_SHWA_01407]。
  • 错误处理：ErrorHandler [AP_SWS_SHWA_00507]、ShwaErrorCode [AP_SWS_SHWA_01301]、ShwaErrorDomain [AP_SWS_SHWA_01307] 和 ShwaException [AP_SWS_SHWA_01303]。

应用程序可以组合多个 Queue、Device 和 Buffer。这同样适用于其他 Functional Clusters SWS SHWA 第22页。相关图表展示了两个独立的组。每个组由一个包含多个 Task 的 Queue、Buffer 和一个 Device 组成 SWS SHWA 第23页。

协作图：各领域的核心类之间的关联如下：Queue 绑定到一个 Device，Submit 提供一个 Event，而 Accessor 访问一个 Buffer。来源：SWS SHWA 第17页、[AP_SWS_SHWA_00910]、[AP_SWS_SHWA_00912]、[AP_SWS_SHWA_00008]、[AP_SWS_SHWA_01407]

从设备到 Queue：选择与设置

可以通过三种方式确定 Device：

  1. 枚举：Platform::GetPlatforms 提供可用平台，GetDevices 提供其 Device [AP_SWS_SHWA_01107] [AP_SWS_SHWA_01108]。
  2. 无参数：Device::Create() [AP_SWS_SHWA_00308]。
  3. 通过选择器：Device::Create(deviceSelector) [AP_SWS_SHWA_00309]。

DeviceSelector 使用 operator() 评估 Device 并为此提供一个 Result<int>。SelectDevice 提供所选的 Device [AP_SWS_SHWA_00404] [AP_SWS_SHWA_00403]。GetInfo<InfoType> 从 [AP_SWS_SHWA_00313] 读取关于设备的更多信息。

Queue 既可以直接从选择器创建，也可以从具体 Device 创建。在这两种变体中，ErrorHandler 都是必选参数，PropertyList 则是可选的 [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00909]。GetDevice 提供所绑定的 Device。IsInOrder 指示该 Queue 的 Task 是否按序执行 [AP_SWS_SHWA_00910] [AP_SWS_SHWA_00911] EXP SW-Architektur 第133页。

活动图：通向 Device 有三种途径，通向 Queue 有两种工厂；每个结果都作为 Result 进行检查。来源：[AP_SWS_SHWA_01107]、[AP_SWS_SHWA_00308]、[AP_SWS_SHWA_00309]、[AP_SWS_SHWA_00908]、[AP_SWS_SHWA_00909]

提供数据并提交 Task

Range 描述具有一至三个维度的大小 [AP_SWS_SHWA_01007] [AP_SWS_SHWA_01009]。Buffer::Create 存在多种变体 [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00210] [AP_SWS_SHWA_00212] [AP_SWS_SHWA_00211] [AP_SWS_SHWA_00213] [AP_SWS_SHWA_00214]：

  • 仅带有 Range，
  • 带有 Range 和额外的分配器，
  • 仅带有分配器，
  • 带有可变或常量主机数据。

Accessor 访问一个 Buffer。它在没有或带有 TaskHandler 的情况下创建 [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00008]。它提供带有 Id 或线性索引的 operator[] [AP_SWS_SHWA_00009] [AP_SWS_SHWA_00010]。此外，它还提供带有 Result 返回值的 Set 和 Get [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012]。访问取决于具有值 kRead、kWrite 和 kReadWrite 的 AccessMode。在 kRead 时，ReferenceT 是一个常量引用 [AP_SWS_SHWA_00101] [AP_SWS_SHWA_00014]。

Queue::Submit(cfg, ErrorHandler&&) 提交一个 Task 并返回一个 Event [AP_SWS_SHWA_00912]。TaskHandler 提供两种执行形式：用于单个任务的 SingleTask 和用于数据并行执行的 ParallelFor(bufferSize, cfg) [AP_SWS_SHWA_01203] [AP_SWS_SHWA_01204]。用例图将“Single Instructions on Multiple Data”和“Multiple Instructions on Multiple Data”列为使用场景 EXP SW-Architektur 第203页。

解释：cfg 应该是一个可调用的配置。它可能获取 TaskHandler，在其中创建 Accessor 并调用 SingleTask 或 ParallelFor。带有 TaskHandler 参数的 Accessor 工厂表明了这一点 [AP_SWS_SHWA_00008]。

时序图：提供数据，提交数据并行 Task 并等待其完成。对 cfg 的调用被标记为解释。来源：[AP_SWS_SHWA_01007]、[AP_SWS_SHWA_00211]、[AP_SWS_SHWA_00912]、[AP_SWS_SHWA_00008]、[AP_SWS_SHWA_01204]、[AP_SWS_SHWA_00604]

通过 Event 和 Queue 的等待函数进行同步

每个 Submit 都会返回一个 Event [AP_SWS_SHWA_00912]。在 Event 级别有三个等待函数 [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00605] [AP_SWS_SHWA_00606]：

  • Event::Wait() 等待关联任务完成。
  • 带有事件列表的静态变体等待多个 Event。
  • WaitFor(ms) 对等待进行时间限制。

GetWaitList 返回一个 Event 列表 [AP_SWS_SHWA_00603]。在 Queue 级别，Wait() 阻塞式等待所有排队的 Task，WaitFor(ms) 在时间限制下执行相同操作 [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] EXP SW-Architektur 第133页。

Requirements 分别指明了每个函数的线程安全性：

  • 线程安全：Queue::Create、Accessor::Create、Range::Create 以及 Accessor::Set 和 Get [AP_SWS_SHWA_00908] [AP_SWS_SHWA_00007] [AP_SWS_SHWA_01007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00012]。
  • 非线程安全：Queue::Submit、Queue::Wait、Event::Wait、Device::Create 和 Accessor::operator[] [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00604] [AP_SWS_SHWA_00308] [AP_SWS_SHWA_00009]。
  • 同一个类内部的差异：Buffer::Create 是线程安全的，而仅带有分配器的变体则不是 [AP_SWS_SHWA_00209] [AP_SWS_SHWA_00212]。

第二种 Submit 变体接收 secondaryQueue 而非 ErrorHandler [AP_SWS_SHWA_00913]。解释：如果在主 Queue 上的执行失败，该 Queue 应该用作备用 Queue。该变体可追溯到与 ErrorHandler 相同的上游需求 [AP_SWS_SHWA_00507]。

时序图：两个 Queue 独立工作；应用程序通过 Event 列表或 Queue 的等待函数进行同步。来源：[AP_SWS_SHWA_00912]、[AP_SWS_SHWA_00605]、[AP_SWS_SHWA_00914]、[AP_SWS_SHWA_00917]、SWS SHWA 第22页

发生错误时的行为

SHWA 通过 ara::core::Result 报告错误，并使用来自 ShwaErrorCode 的代码。其中包括 kRuntime、kTaskExecutionFailure、kMemoryNotAllocated、kIntegrityCorrupted（无法恢复缓冲区存储器的完整性）、kResourceBusy 以及 kInvalidAccessMode [AP_SWS_SHWA_01301]。个别函数指明了其他代码：kAccessorFailure、kInvalidIndex、kFeatureNotSupported 和 kEventInvalidOperation [AP_SWS_SHWA_00007] [AP_SWS_SHWA_00011] [AP_SWS_SHWA_00313] [AP_SWS_SHWA_00603]。

域 ShwaErrorDomain 提供 Name、Message 和 ThrowAsException。GetShwaDomain 和 MakeErrorCode 将这些代码与该域关联。ShwaException 将代码作为异常进行传递 [AP_SWS_SHWA_01308] [AP_SWS_SHWA_01309] [AP_SWS_SHWA_01310] [AP_SWS_SHWA_01311] [AP_SWS_SHWA_01312] [AP_SWS_SHWA_01303]。

执行和等待过程中的错误后果尤为严重。如果 Submit、Queue::Wait、Queue::WaitFor 或 Event::Wait 报告代码 kRuntime，则失败任务的数据必须被视为已被意外更改。对于 Event::Wait，这同样适用于 kTaskExecutionFailure [AP_SWS_SHWA_00912] [AP_SWS_SHWA_00914] [AP_SWS_SHWA_00917] [AP_SWS_SHWA_00604]。Submit 的错误说明带有标识 no_rollback_semantics [AP_SWS_SHWA_00912]。

设备查询以及 Accessor::Get 等通过 kResourceBusy [AP_SWS_SHWA_00310] [AP_SWS_SHWA_00012] 报告资源被占用。Buffer::Create 则通过 kMemoryNotAllocated [AP_SWS_SHWA_00212] 报告分配失败。

ErrorHandler 封装了一个函数 std::function<void(ara::core::ErrorCode)> [AP_SWS_SHWA_00507]。HandleError(ShwaErrorCode) 执行处理且不是线程安全的 [AP_SWS_SHWA_00508]。每个队列在创建时都会获得一个 ErrorHandler [AP_SWS_SHWA_00908]。解读：实现可能会通过 HandleError 报告已提交任务的错误，这些错误不会直接作为 Submit 的返回值出现；至于由谁调用 HandleError，来源中并未明确规定。在设备级别，DeviceStatus::kFailure 指示错误状态 [AP_SWS_SHWA_00103]。

活动图：评估 Result 并对 SHWA 错误代码进行分类，包括任务失败对数据的影响。来源：[AP_SWS_SHWA_01301]、[AP_SWS_SHWA_00912]、[AP_SWS_SHWA_00604]、[AP_SWS_SHWA_01310]、[AP_SWS_SHWA_00508]

AcceleratorSelector 类

AcceleratorSelector manages accelerator selection for operations on HWA if available.

Accessor 类

Accessor manages read and write access to allocated memory by Buffer. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

Buffer 类

Buffer manages memory allocation for operations on the host or/and HWA. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ptr, which may be moved. ≙ std::unique_ptr

CpuSelector 类

CpuSelector manages CPU selection for operations on HWA if available Allows to get a device from any supported backends for which the device type is CPU.

Device 类

Device class represents HWA device. Provides access to the device but not controlling it. Designed as copyable since not owning resources.

DeviceMonitor 类

DeviceMonitor API class. Designed as copyable since not owning resources.

DeviceSelector 类

Class allowing to choose the most appropriate device of the available ones. This is a callable object taking a device reference and returning an integer rank. One of the device with the highest non-negative value is selected.

ErrorHandler 类

ErrorHandler manages asynchronous error handling for operations on HWA.

Event 类

Event class helps to manage task execution synchronization between HWA and Host application. Can be created only inside of the Queue otherwise it’s meaningless.

GpuSelector 类

GpuSelector manages GPU selection for operations on HWA if available Select a device from any supported backends for which the device type is GPU.

Id 类

Id API class. Designed as copyable since not owning resources.

Platform 类

Platform class is responsible for extracting different HWA platforms available for current application and listing Devices bind to each platform. Designed as copyable since not owning resources.

PropertyList 类

Property List class is designed to enable vendor specific SHWA functionality extension and adjustment. Properties are not standardized and can be defined by Vendor. Class using Property list is obliged to have HasProperty() and GetProperty() methods defined.

Queue 类

Queue API provides the functionality for parallel processing on selected Device. Designed as not copyable, since it’s owning resources. Intended to be managed exclusively by std::unique_ ptr, which may be moved. ≙ std::unique_

Range 类

Defines size of Buffer for one, two or three dimensions. Designed as copyable since not owning resources.

ShwaErrorDomain 类

Defines the error domain for Safe Hardware Acceleration.

ShwaException 类

Exception type could be thrown by application or other FC using Safe Hardware Acceleration. Safe Hardware Acceleration API is exception free and can only return an ErrorCode, but user code can transform this error to exception and throw if it’s alligned with system error handling architecture.

TaskHandler 类

Handles tasks execution on the selected Device Can be created only inside of the Queue otherwise it’s meaningless.
