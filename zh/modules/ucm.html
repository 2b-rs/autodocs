<h4>Software Packages、Software Cluster 与版本规则</h4>
<p>UCM 的输入单元是 Software Package。每个软件包恰好寻址一个 SoftwareCluster <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P29_50.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P29_50">SWS UCM 第29页</a>。从概念上讲，带有自身清单和自身签名的 Software Package 封装了 Software Cluster 以及集群清单和集群签名 <a class="docref internal-spec-ref" href="../../spec/figures/FIG-26c60ef08ae70aa0.html" data-snip="FIG-26c60ef08ae70aa0">TR Methodology 第77页</a>。软件包清单应在开始时传输，以便 UCM 能够及早获取有关存储需求或流式传输等信息 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_7_3_UPDATEANDCONFIGURATIONMANAGEMENT.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_7_3_UPDATEANDCONFIGURATIONMANAGEMENT">SWS UCM 第27页</a>。</p>
<p>每个 SoftwareCluster 清单都包含一个名称和格式为 <code>StrongRevisionLabelString</code> 的版本。如果传入的软件包更改了已安装集群的内容，则其版本必须更高；否则 UCM 会报告错误 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P31_52.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P31_52">SWS UCM 第31页</a>。因此，降级是通过使用更高的版本号重新打包旧的、正常工作的软件来执行的 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P31_52.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P31_52">SWS UCM 第31页</a>。</p>

<h4>传输：分块传输、注册与流式传输</h4>
<p>传输以 <code>TransferStart</code> <a class="spec-record-ref" data-req="SWS_UCM_00345" href="../spec/record.html?id=SWS_UCM_00345">[SWS_UCM_00345]</a> 开始。客户端指定包大小；UCM 分配一个 TransferId，并通过 <code>blockSize</code> 返回每次调用 <code>TransferData</code> <a class="spec-record-ref" data-req="SWS_UCM_00346" href="../spec/record.html?id=SWS_UCM_00346">[SWS_UCM_00346]</a> 时允许的最大块大小 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P34_55.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P34_55">SWS UCM 第34页</a>。各个块带有连续的 <code>blockCounter</code>，该编号在 R21-11 中从 0x01 开始，且每块递增 1 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P35_56.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P35_56">SWS UCM 第35页</a>。<code>TransferExit</code> <a class="spec-record-ref" data-req="SWS_UCM_00347" href="../spec/record.html?id=SWS_UCM_00347">[SWS_UCM_00347]</a> 完成传输；在此过程中，UCM 检查接收到的包 <a class="docref internal-spec-ref" href="../../spec/figures/FIG-71ef285b53676690.html" data-snip="FIG-71ef285b53676690">SWS UCM 第136页</a>。</p>
<p>传输与包管理的状态解耦，只要 UCM 正在运行便随时可以进行 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P34_55.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P34_55">SWS UCM 第34页</a>。只要包大小总和不超过 UCM 缓冲区，就可以启动更多传输 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P35_56.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P35_56">SWS UCM 第35页</a>。作为备选方案，<code>RegisterSoftwarePackage</code> <a class="spec-record-ref" data-req="SWS_UCM_00344" href="../spec/record.html?id=SWS_UCM_00344">[SWS_UCM_00344]</a> 可以通过 URI 注册已位于文件系统中或仍在下载的包。在此情况下，UCM 同样会提供一个 TransferId，并使用 <code>TransferExit</code> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-9aec9bfc9fa11eeb.html" data-snip="FIG-9aec9bfc9fa11eeb">SWS UCM 第137页</a> 完成。不再需要的包由 <code>DeleteTransfer</code> <a class="spec-record-ref" data-req="SWS_UCM_00348" href="../spec/record.html?id=SWS_UCM_00348">[SWS_UCM_00348]</a> 移除。一旦包达到其最终状态，TransferId 即失效 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P36_57.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P36_57">SWS UCM 第36页</a>。</p>
<p>如果 UCM 支持从流中进行处理，则在传输期间便可以调用 <code>ProcessSwPackage</code>。随后包切换至 <code>kProcessingStream</code>，并在后续调用 <code>TransferData</code> 时保持在该状态。随着 <code>TransferExit</code> 的执行以及处理的完全结束，它变为 <code>kProcessed</code> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P40_61.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P40_61">SWS UCM 第40页</a>。R25-11 类型定义 <code>SwPackageStateType</code> 正好包含这五种包状态。每个包的状态由 <code>GetSwPackages</code> <a class="spec-record-ref" data-req="SWS_UCM_00359" href="../spec/record.html?id=SWS_UCM_00359">[SWS_UCM_00359]</a> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-8522e69c55d822cf.html" data-snip="FIG-8522e69c55d822cf">SWS UCM 第86页</a> 提供。自 R24-11 起，规范还额外将生命周期表示为分别针对传输状态和处理状态的两个独立状态机 <a class="docref internal-spec-ref" href="../../spec/figures/FIG-2b83f262a89dbd57.html" data-snip="FIG-2b83f262a89dbd57">SWS UCM 第38页</a>。</p>

<h4>Preparation 阶段中的处理</h4>
<p><code>ProcessSwPackage</code> <a class="spec-record-ref" data-req="SWS_UCM_00349" href="../spec/record.html?id=SWS_UCM_00349">[SWS_UCM_00349]</a> 处理完全或部分传输的包。根据包内容，这意味对所寻址 SoftwareCluster 进行安装、更新或移除（<code>kInstall</code>、<code>kUpdate</code>、<code>kRemove</code>）<a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P29_50.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P29_50">SWS UCM 第29页</a>。与传输不同，为了保持一致性，同一时间只能处理一个包。但多个客户端可以依次处理已传输的包 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P40_61.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P40_61">SWS UCM 第40页</a> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_13_8.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_13_8">EXP PlatformDesign 第58页</a>。在正在进行处理期间发起的并行调用，UCM 在 R21-11 中会以 <code>ServiceBusy</code> 拒绝 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P42_63.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P42_63">SWS UCM 第42页</a>。</p>
<p><code>Cancel</code> <a class="spec-record-ref" data-req="SWS_UCM_00351" href="../spec/record.html?id=SWS_UCM_00351">[SWS_UCM_00351]</a> 中止正在进行的处理，撤销其更改并释放预留的资源。相反，<code>RevertProcessedSwPackages</code> <a class="spec-record-ref" data-req="SWS_UCM_00350" href="../spec/record.html?id=SWS_UCM_00350">[SWS_UCM_00350]</a> 则丢弃迄今已处理包的所有更改 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62">SWS UCM 第41页</a>。需要与之区分的是 <code>Rollback</code> <a class="spec-record-ref" data-req="SWS_UCM_00353" href="../spec/record.html?id=SWS_UCM_00353">[SWS_UCM_00353]</a>：Revert 仅在成功激活之前可行，而 Rollback 仅在激活之后可行 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62">SWS UCM 第41页</a>。</p>
<p><code>CurrentStatus</code> <a class="spec-record-ref" data-req="SWS_UCM_00361" href="../spec/record.html?id=SWS_UCM_00361">[SWS_UCM_00361]</a> 将总体状态作为带有 Getter 和 Notifier 的字段发布；客户端订阅该字段并以此跟踪处理过程 <a class="docref internal-spec-ref" href="../../spec/figures/FIG-469e0c0880b8fb0c.html" data-snip="FIG-469e0c0880b8fb0c">SWS UCM 第123页</a>。在 R25-11 中，不带 TransferId 参数的 <code>GetProgress</code> <a class="spec-record-ref" data-req="SWS_UCM_00360" href="../spec/record.html?id=SWS_UCM_00360">[SWS_UCM_00360]</a> 提供活动状态的进度。较早版本则采用 <code>GetSwProcessProgress</code>，按每个 TransferId 提供百分比值 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P41_62">SWS UCM 第41页</a>。解释：<code>GetProgress</code> 预计会取代该查询，并推广至所有状态。</p>
<p>耗时或受状态约束的操作可以通过 <code>Suspend</code> <a class="spec-record-ref" data-req="SWS_UCM_00397" href="../spec/record.html?id=SWS_UCM_00397">[SWS_UCM_00397]</a> 暂停，并通过 <code>Resume</code> <a class="spec-record-ref" data-req="SWS_UCM_00398" href="../spec/record.html?id=SWS_UCM_00398">[SWS_UCM_00398]</a> 恢复。据推测，这主要涉及长时间运行的处理步骤；Requirements 未提及具体操作。</p>

<h4>激活、验证与完成</h4>
<p>在 R24-11 和 R25-11 中，更新周期分为三个阶段：Preparation、Activation 和 CleaningUp。类型 <code>UpdateStateType</code> 包含状态 <code>kPreparing</code>、<code>kActivating</code>、<code>kVerifying</code>、<code>kActivated</code>、<code>kRollingBack</code>、<code>kRolledBack</code>、<code>kRollingBackFailed</code> 和 <code>kCleaningUp</code> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-b57057eb2a74ace2.html" data-snip="FIG-b57057eb2a74ace2">SWS UCM 第59页</a> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-ba7a5362410a91b2.html" data-snip="FIG-ba7a5362410a91b2">SWS UCM 第85页</a>。较早的章节仍使用状态 <code>kIdle</code>、<code>kProcessing</code> 和 <code>kReady</code> 描述激活之前的阶段 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P50_71.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P50_71">SWS UCM 第50页</a>。</p>
<p><code>Activate</code> <a class="spec-record-ref" data-req="SWS_UCM_00352" href="../spec/record.html?id=SWS_UCM_00352">[SWS_UCM_00352]</a> 共同激活所有已处理的包，无论是由哪个客户端处理的 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P45_66.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P45_66">SWS UCM 第45页</a>。UCM 首先检查依赖关系。随后，它使用 <code>RequestUpdateSession</code> 在 State Management 处打开一个更新会话，并针对每个受影响的 Function Group 调用 <code>PrepareUpdate</code> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P33_54.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P33_54">SWS UCM 第33页</a> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_13_8.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_13_8">EXP PlatformDesign 第58页</a>。此后，根据系统的不同，执行 Machine-Reset 或 Function Groups 的重启，并通过 <code>VerifyUpdate</code> 进行验证。只有当验证成功时，才达到 <code>kActivated</code> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P51_72.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P51_72">SWS UCM 第51页</a> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-1d49867fef5b2f50.html" data-snip="FIG-1d49867fef5b2f50">SWS UCM 第138页</a>。在 R21-11 中，<code>Activate</code> 仅允许从 <code>kReady</code> 执行 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P46_67.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P46_67">SWS UCM 第46页</a>。对于 R25-11，这可能对应于 Preparation 阶段的结束。</p>
<p><code>Finish</code> <a class="spec-record-ref" data-req="SWS_UCM_00354" href="../spec/record.html?id=SWS_UCM_00354">[SWS_UCM_00354]</a> 从 <code>kActivated</code> 或 <code>kRolledBack</code> 完成该周期，并清理所有处理数据（包括包源）。在离开 <code>kCleaningUp</code> 时，UCM 使用 <code>StopUpdateSession</code> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P48_69.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P48_69">SWS UCM 第48页</a> 结束会话。所有阶段切换均可通过 <code>CurrentStatus</code> 进行观察 <a class="docref internal-spec-ref" href="../../spec/figures/FIG-7f6e0aab02be3112.html" data-snip="FIG-7f6e0aab02be3112">EXP PlatformDesign 第70页</a>。</p>

<h4>嵌入车辆活动：标识与访问保护</h4>
<p>为了让 V-UCM 能够有针对性地分发包，它通过 Service Discovery 搜索所有 UCM 实例。随后，它在每个代理上调用 <code>GetId</code> <a class="spec-record-ref" data-req="SWS_UCM_00343" href="../spec/record.html?id=SWS_UCM_00343">[SWS_UCM_00343]</a>，并获取相应 <code>UcmModuleInstantiation</code> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P58_79.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P58_79">SWS UCM 第58页</a> <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_12_35.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_12_35">TPS Manifest 第631页</a> 的标识符。对于车辆中的每台 Machine，该标识符必须是唯一的 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ADAPTIVE_CAN_FIGURE_Figure_12_35.html" data-snip="SNIP_ADAPTIVE_CAN_FIGURE_Figure_12_35">TPS Manifest 第631页</a>。</p>
<p>V-UCM 通过其自身包含 SYNCING、TRANSFERRING、PROCESSING、ACTIVATING 和 VEHICLE_CHECKING 阶段的状态机来执行活动。在同步时，除其他内容外，它还会查询 <code>GetSwClusterInfo</code>，在 ACTIVATING 中，它调用各 UCM 的 <code>Activate</code> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-82aac9ab9fcea284.html" data-snip="FIG-82aac9ab9fcea284">SWS V-UCM 第37页</a> <a class="docref internal-spec-ref" href="../../spec/figures/FIG-642d46c2c786c61a.html" data-snip="FIG-642d46c2c786c61a">EXP SWArchitecture 第146页</a>。根据 R21-11，诸如 <a class="spec-record-ref" data-req="SWS_UCM_00357" href="../spec/record.html?id=SWS_UCM_00357">[SWS_UCM_00357]</a> 或 <a class="spec-record-ref" data-req="SWS_UCM_00355" href="../spec/record.html?id=SWS_UCM_00355">[SWS_UCM_00355]</a> 等信息可能包含个人身份数据。因此，<code>PackageManagement</code> 应仅通过受机密性保护的通道进行映射。此外，UCM 仅在完成初始化后才提供其服务 <a class="docref internal-spec-ref" href="../../spec/snippets/SNIP_ucm_AUTOSAR_AP_SWS_U_P55_76.html" data-snip="SNIP_ucm_AUTOSAR_AP_SWS_U_P55_76">SWS UCM 第55页</a>。</p>
