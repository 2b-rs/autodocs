命名空间 ara::nm 通过 NetworkHandle 提供受控访问 AUTOSAR Adaptive Platform 请求的网络状态和实际有效网络状态的接口。运行过程中的可能错误情况通过枚举 NmErrc 的标准化错误码（如 kServiceNotAvailable 或 kInvalidHandler）表示 [SWS_ANM_01111]。为了进行结构化错误处理，MakeErrorCode 以线程安全的方式为错误域 NmErrorDomain 生成错误码，该错误域通过 GetNmDomain 引用 [SWS_ANM_01109]。应用程序在调用前必须考虑 Network Management 服务的可达性，以避免状态查询时发生故障。

上下文

命名空间 ara::nm 在 AUTOSAR Adaptive Platform 上为功能性 Network Management 提供核心接口。主要功能接口由类 NetworkHandle 构成，该类封装了对请求的网络状态以及实际有效网络状态的受控访问。通过这种抽象机制，功能应用程序和平台服务可以监控底层通信网络的当前运行状态并发起状态更改。

为了实现一致且健壮的错误处理，ara::nm 提供了集成到 AUTOSAR Adaptive 错误架构中的标准化类型和辅助函数。其中包括错误域 NmErrorDomain、异常类 NmException 以及域特定枚举 NmErrc [SWS_ANM_01111]。此外，还提供了线程安全函数 GetNmDomain [SWS_ANM_01109] 和 MakeErrorCode [SWS_ANM_01110]，以确保错误状态符合实例化和类型规范的处理。

使用路径

在典型应用场景中，Adaptive Application 与命名空间 ara::nm 交互以控制网络状态并对运行时事件做出反应。交互序列包括以下步骤：

  • 发起状态访问：应用程序使用 NetworkHandle 查询请求的网络状态或当前有效的网络状态。
  • 错误检测：如果无法正常处理网络请求，接口将发出相应的错误事件信号。解读：在底层网络服务发生故障时，NetworkHandle 可能在内部基于 NmErrc 生成错误码。
  • 生成错误码：辅助函数 MakeErrorCode [SWS_ANM_01110] 接收来自 NmErrc 的值 [SWS_ANM_01111] 以及应用特定附加数据（ara::core::ErrorDomain::SupportDataType），并据此生成完整的 ara::core::ErrorCode。该函数被指定为 constexpr 和 noexcept，并保证完全的线程安全性 [SWS_ANM_01110]。
  • 验证错误域：调用组件可以通过 GetNmDomain [SWS_ANM_01109] 获取对全局 NmErrorDomain 的线程安全引用，以检查返回代码的错误域并解析域特定错误描述。

时序图：通过 ara::nm 进行网络状态查询和错误解析的流程。来源：[SWS_ANM_01109]、[SWS_ANM_01110]、[SWS_ANM_01111]。

错误场景

该模块的标准化错误码汇集在基于 ara::core::ErrorDomain::CodeType 的枚举 NmErrc 中 [SWS_ANM_01111]。该模块区分以下错误情况：

  • NmErrc::kServiceNotAvailable（代码 1）：此错误表示网络管理所需的服务在运行时不可达或未就绪 [SWS_ANM_01111]。在这种情况下，调用方必须通过重试或回退策略做出响应。
  • NmErrc::kInvalidHandler（代码 2）：在操作过程中传递或引用了无效或未注册的处理程序时发生 [SWS_ANM_01111]。这通常表明调用方存在配置或初始化错误。

健壮调用的前提条件是初始化的服务基础设施，以及在访问 NetworkHandle 时使用有效参数，以避免 NmErrc::kServiceNotAvailable 或 NmErrc::kInvalidHandler [SWS_ANM_01111]。所有错误处理核心函数（如 MakeErrorCode [SWS_ANM_01110] 和 GetNmDomain [SWS_ANM_01109]）本身均不抛出异常（noexcept）。解读：对于偏好基于异常的控制结构的应用程序，异常类 NmException 可能充当载体，以结构化方式通过调用栈传递错误状态。

标准化网络管理错误代码。

枚举 [SWS_ANM_01111] 在头文件 ara/nm/nm_error_domain.h 中定义了 Network Management（NM）的标准化错误码。它还通过类型别名 Errc [SWS_ANM_01103] 提供，并与线程安全的工厂函数 MakeErrorCode [SWS_ANM_01110] 一起用于将错误状态封装在 ara::core::Result 返回值中。

定义的错误值针对 NM 接口处的特定错误情况：

  • kServiceNotAvailable（值 1）：在同步查询和请求网络状态时发生（当底层 NM 服务不可用时）。这涉及通过 GetNetworkState [SWS_ANM_01007] 读取有效网络状态、通过 GetNetworkRequestedState [SWS_ANM_01008] 查询请求的状态，以及通过 SetNetworkRequestedState [SWS_ANM_01009] 请求或释放网络。
  • kInvalidHandler（值 2）：由通知处理程序的注册函数报告，具体为 RegisterNetworkStateChangeNotifier [SWS_ANM_01010]、[SWS_ANM_01015] 以及 RegisterNetworkRequestedStateChangeNotifier [SWS_ANM_01012]、[SWS_ANM_01014]。由于每个接口最多只允许注册一个通知器，因此当传入空回调或已存在注册时可能会发生此错误（解读）。

关于并发性，需要注意的是，对网络状态的纯读取操作是线程安全的，而 SetNetworkRequestedState 以及所有通知器注册均被显式规范为非线程安全。因此，调用方必须对注册和请求更改的并发访问进行外部同步，以避免错误的调用状态。

          使用
          

          函数 MakeErrorCode 在模块 anm 中用于为 Network Management 错误创建标准化的 ara::core::ErrorCode [SWS_ANM_01110]。该函数在头文件 ara/nm/nm_error_domain.h 中定义，并将枚举类型 NmErrc 的特定错误代码 code 与类型为 ara::core::ErrorDomain::SupportDataType 的供应商特定附加数据 data 同步封装到相应的错误对象中 [SWS_ANM_01110]。调用方传递相应的错误状态以及上下文数据，以获取用于后续错误处理的统一错误对象 [SWS_ANM_01110]。
          

          错误处理与并发
          

          由于 MakeErrorCode 使用说明符 noexcept 声明，因此该函数在执行时保证不抛出异常 [SWS_ANM_01110]。关于并发行为，该函数被归类为 thread-safe；因此无需额外的外部同步措施即可安全地从并行线程调用 [SWS_ANM_01110]。通过限定为 constexpr，当传递常量实参时，错误对象的构造可能已经在编译时由编译器完全完成 [SWS_ANM_01110]。
          

          相互作用
          

          作为 Network Management 错误代码的核心生成函数，MakeErrorCode 将模块连接到 AUTOSAR Adaptive 平台的通用错误处理概念 [SWS_ANM_01110]。它在此直接满足了上游需求 RS_AP_00119、RS_AP_00120、RS_AP_00121、RS_AP_00159 以及 RS_AP_00135 [SWS_ANM_01110]。
