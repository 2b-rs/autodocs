命名空间 ara::per 提供了用于持久数据存储的接口，它允许 Adaptive 应用程序通过实例标识符访问基于文件的存储区和基于键值的存储区（[SWS_PER_00052]、[SWS_PER_00116]）。应用程序通过共享句柄管理打开的存储，在清单更改时执行协调更新，并可以通过恢复机制修复不一致的数据（[SWS_PER_00333]、[SWS_PER_00357]）。虽然存储访问是通过句柄并发执行的，但诸如更新或存储重置等管理操作需要不存在并发访问（[SWS_PER_00311]）。

上下文

命名空间 ara::per 为 AUTOSAR Adaptive Platform 提供了持久性功能组的接口。它的主要职责是在系统启动和进程生命周期中实现跨会话的应用程序数据持久存储。该模块区分两种基本存储范式：用于结构化键值对的 KeyValueStorage 和用于基于文件的存储访问的 FileStorage。Adaptive 应用程序通过配置的 Port-Prototype 使用 ara::core::InstanceSpecifier 访问这些资源（[SWS_PER_00052]、[SWS_PER_00116]）。

该命名空间的重要交互伙伴是 Update and Configuration Management（UCM）以及物理存储介质，UCM 可以在运行时提供更新后的目标配置（Target Configuration）（[SWS_PER_00576]、[SWS_PER_00577]），而 ara::per 在物理存储介质上确保一致性、冗余和数据安全性（[SWS_PER_00311]）。

生命周期

对存储对象的访问通过句柄抽象进行管控。通过 OpenKeyValueStorage 或 OpenFileStorage 打开存储会生成一个 SharedHandle（[SWS_PER_00052]、[SWS_PER_00116]）。由于多个线程可以并发访问同一存储，因此当单个 SharedHandle 离开其作用域时，物理资源不一定会关闭；只有当所有引用的 SharedHandle 实例都被销毁后，才会执行关闭（[SWS_PER_00052]、[SWS_PER_00116]）。

对于 FileStorage 内的文件，会详细跟踪其创建和修改状态。枚举 FileCreationState 映射了文件是在安装时（kCreatedDuringInstallation）、更新期间（kCreatedDuringUpdate）、通过重置（kCreatedDuringReset）、由于恢复（kCreatedDuringRecovery）还是由应用程序本身（kCreatedByApplication）创建的（[SWS_PER_00435]）。类似地，FileModificationState 反映了文件最近一次在何时以及通过何种操作被修改（[SWS_PER_00436]）。

为了管理初始状态，该命名空间提供了重置功能：ResetKeyValueStorage（[SWS_PER_00334]）和 ResetAllFiles（[SWS_PER_00336]）将单个存储重置为最初在清单中定义的值。相比之下，全局操作 ResetPersistency（[SWS_PER_00358]）会完全清空所有键值存储和文件存储；在下次调用 OpenFileStorage 或 OpenKeyValueStorage 时会重新创建它们。

在并发性方面，打开函数（OpenFileStorage、OpenKeyValueStorage）、存储大小查询（GetCurrentFileStorageSize、GetCurrentKeyValueStorageSize）以及与存储相关的恢复和重置函数都是线程安全的（[SWS_PER_00052]、[SWS_PER_00116]、[SWS_PER_00405]、[SWS_PER_00406]、[SWS_PER_00333]、[SWS_PER_00334]、[SWS_PER_00335]、[SWS_PER_00336]）。相比之下，全局更新和清理操作如 UpdatePersistency（[SWS_PER_00357]）、CleanUpPersistency（[SWS_PER_00567]）、ResetPersistency（[SWS_PER_00358]）、CheckForManifestUpdate（[SWS_PER_00576]）和 ReloadPersistencyManifest（[SWS_PER_00577]）被声明为非线程安全。

使用路径

典型的应用程序流程包括检查配置更新、应用数据迁移以及随后的存储访问：

在正常运行之前或期间，应用程序使用 CheckForManifestUpdate 检查 UCM 是否已安装新的目标配置（[SWS_PER_00576]）。如果是，则通过 ReloadPersistencyManifest 读取新清单（[SWS_PER_00577]）。在随后的验证阶段，应用程序触发 UpdatePersistency（[SWS_PER_00357]）。为了控制版本特定的数据迁移，应用程序预先通过 RegisterApplicationDataUpdateCallback 注册一个回调函数，该函数接收有关较旧契约版本的信息并执行应用程序自有的迁移步骤（[SWS_PER_00356]）。此外，可以通过 RegisterDataUpdateIndication 监视元素更改（[SWS_PER_00578]）。更新完成后，CleanUpPersistency 会删除过时的备份和冗余的历史数据（[SWS_PER_00567]）。

对于常规访问，应用程序通过 OpenKeyValueStorage（[SWS_PER_00052]）或 OpenFileStorage（[SWS_PER_00116]）打开目标资源。FileStorage 中的文件访问由枚举 OpenMode 的位掩码控制（例如 kAtTheBeginning、kAtTheEnd、kTruncate、kAppend），这些位掩码通过运算符 operator|（[SWS_PER_00144]）和 operator|=（[SWS_PER_00434]）进行组合（[SWS_PER_00147]）。定位相对于 Origin（kBeginning、kCurrent、kEnd）进行（[SWS_PER_00146]）。当前占用的存储大小可在运行时通过 GetCurrentKeyValueStorageSize（[SWS_PER_00405]）和 GetCurrentFileStorageSize（[SWS_PER_00406]）确定。

错误场景

该命名空间中的错误通过枚举 PerErrc（[SWS_PER_00311]）结合 PerErrorDomain（[SWS_PER_00352]）和 MakeErrorCode（[SWS_PER_00351]）以标准化方式发出信号。声明的类 PerException 可能是用作 C++ 异常类型，适用于不通过 ara::core::Result 而是通过异常处理错误的各种环境（解释）。

主要错误场景包括：

  • 配置与寻址错误：如果传递的 InstanceSpecifier 与模型中配置的 Port-Interface 均不匹配，则使用 PerErrc::kStorageNotFound 打开失败（[SWS_PER_00052]、[SWS_PER_00116]、[SWS_PER_00311]）。对不存在文件的文件访问会生成 PerErrc::kFileNotFound（[SWS_PER_00311]）。
  • 资源冲突：如果存储已打开或同时运行管理命令，则 OpenKeyValueStorage、OpenFileStorage、RecoverKeyValueStorage、RecoverAllFiles、ResetKeyValueStorage、ResetAllFiles、UpdatePersistency、CleanUpPersistency 或 ResetPersistency 等操作将失败并出现 PerErrc::kResourceBusy（[SWS_PER_00052]、[SWS_PER_00116]、[SWS_PER_00333]、[SWS_PER_00334]、[SWS_PER_00335]、[SWS_PER_00336]、[SWS_PER_00357]、[SWS_PER_00358]、[SWS_PER_00567]）。
  • 完整性丢失与恢复：在发生结构损坏（PerErrc::kIntegrityCorrupted）或冗余检查失败（PerErrc::kValidationFailed）时，ara::per 允许通过 RecoverKeyValueStorage（[SWS_PER_00333]）或 RecoverAllFiles（[SWS_PER_00335]）进行最大努力恢复。通过 RegisterRecoveryReportCallback（[SWS_PER_00433]），安全相关应用程序可以根据 RecoveryReportKind（例如 kKeyValueStorageRecovered、kFileRecovered）自动记录纠正措施（[SWS_PER_00432]）。
  • 存储限制与物理错误：如果超出配额或物理容量，将报告 PerErrc::kOutOfStorageSpace、PerErrc::kQuotaExceeded 或 PerErrc::kTooManyFiles（[SWS_PER_00311]）。硬件或文件系统错误会导致 PerErrc::kPhysicalStorageFailure（[SWS_PER_00311]）。
  • 安全性与访问模式：如果加密验证或计算失败，该模块将返回 PerErrc::kEncryptionFailed 或 PerErrc::kAuthenticationFailed（[SWS_PER_00311]）。对只读存储区的写尝试将被拒绝并返回 PerErrc::kIllegalWriteAccess（[SWS_PER_00311]）。
