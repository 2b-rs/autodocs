提供用于保障时间同步安全性的 Freshness Value Management 接口和容器。

命名空间 apext::tsync 为 Adaptive 时间同步的 Freshness Value Management 提供接口和数据容器。通过接口 FVM，新鲜度值被封装在 FVContainer 实例中，以防止时间报文遭受重放攻击。如果在初始化期间发生不可恢复的错误，或者值暂时不可用，则通过 TsyncFvmErrorDomain 的错误代码进行映射 [SWS_TS_14202]。标准化错误对象的实例化通过 MakeErrorCode 以异常安全且线程安全的方式进行 [SWS_TS_14213]。

上下文

命名空间 apext::tsync 代表 AUTOSAR Adaptive 时间同步（ara::tsync）的平台特定扩展。其核心任务是 Freshness Value Management（FVM），它提供确保时间信息新鲜度的机制，以防止时间同步网络中的重放攻击和过时状态。核心组件包括接口 FVM、数据容器 FVContainer、错误域 TsyncFvmErrorDomain 以及异常类 TsyncFvmException。

类 FVContainer 通过管理其以位为单位的长度以及字节向量形式的值本身，封装了一个新鲜度值。接口 FVM 用作 ara::tsync 的功能桥梁。FVM 可能用作抽象接口，ara::tsync 的时间同步实例通过该接口获取或验证当前的新鲜度值。错误域 TsyncFvmErrorDomain 及关联的辅助函数确保了标准化的错误报告 [SWS_TS_14212]。

上下文图：命名空间 apext::tsync 的组件及其与 ara::tsync 的交互。来源：[SWS_TS_14202]、[SWS_TS_14212]。

生命周期

命名空间 apext::tsync 中组件的生命周期分为初始化、运行和终止阶段。对于初始化阶段，枚举 TsyncFvmErrc 定义了错误值 kFVInitializeFailed（= 2），该值被指定为不可恢复错误（unrecoverable error），表示无法使用 Freshness Value Manager [SWS_TS_14202]。错误 kFVInitializeFailed 可能表明在检索 Freshness Value 之前必须完成 FVM 的初始化阶段，其失败将导致无法进一步使用。

在运行期间，FVContainer 实例具有临时生命周期：它们根据需要被实例化，填充向量和位长度，并传递给同步协议实例。相比之下，错误域对象 TsyncFvmErrorDomain 在整个进程运行期间具有静态生命周期。函数 GetTsyncFvmErrorDomain() 返回对全局实例对象的引用 [SWS_TS_14212]。GetTsyncFvmErrorDomain() 以及工厂函数 MakeErrorCode() 均被声明为 constexpr 和 noexcept，并被指定为异常安全且线程安全 [SWS_TS_14212]、[SWS_TS_14213]。这允许在没有同步锁的情况下并发进行错误生成和查询。

使用路径

与时间同步交互的典型使用路径包括新鲜度值的提供和评估：

  1. 来自 ara::tsync 的组件通过接口 FVM 请求当前的新鲜度值，以保障时间报文的安全。
  2. 成功确定值后，FVM 会创建或填充 FVContainer 的实例（包含该值的位长度和字节向量），并将其返回给调用方。
  3. 如果新鲜度值在运行时暂时无法提供，FVM 会报告可恢复错误 kFVNotAvailable [SWS_TS_14202]。为此，通过 MakeErrorCode() 创建带有特定于供应商的附加数据的相应 ara::core::ErrorCode 对象 [SWS_TS_14213]。
  4. 调用组件评估结果并决定是否进行重试或采取替代措施。

时序图：新鲜度值的检索以及可能错误状态的处理。来源：[SWS_TS_14202]、[SWS_TS_14213]。

错误场景

apext::tsync 中的错误处理基于 ara::core::ErrorDomain 和 ara::core::ErrorCode 的架构。TsyncFvmErrorDomain 的错误代码列在枚举 TsyncFvmErrc 中，其基础类型为 ara::core::ErrorDomain::CodeType [SWS_TS_14202]：

  • kFVNotAvailable（= 1）：可恢复错误（recoverable error），指示 Freshness Value 当前不可用 [SWS_TS_14202]。调用方可以重新发起请求或跳过当前处理周期。
  • kFVInitializeFailed（= 2）：不可恢复错误（unrecoverable error），表示无法初始化或使用 Freshness Value Manager [SWS_TS_14202]。这会导致依赖的时间同步服务中止。

具体错误对象的创建通过辅助函数 MakeErrorCode(TsyncFvmErrc code, ara::core::ErrorDomain::SupportDataType data) 进行，该函数接收枚举项和特定于供应商的附加数据 [SWS_TS_14213]。声明位于头文件 apext/tsync/fvm_error_domain.h 中，而前向声明可通过 apext/tsync/tsync_fwd.h 获取 [SWS_TS_14202]。对于基于异常的错误路径，该命名空间提供了类 TsyncFvmException。当 TsyncFvmErrorDomain 的错误在异常上下文中报告而非通过 ara::core::ErrorCode 报告时，TsyncFvmException 大概率会被抛出。

使用与错误语义

枚举 TsyncFvmErrc 根据 [SWS_TS_14202] 为错误域 apext::tsync::TsyncFvmErrorDomain 定义特定错误码。在域内部，该枚举还通过类型别名 apext::tsync::TsyncFvmErrorDomain::Errc 提供 [SWS_TS_14206]。该枚举区分 Freshness Value Manager (FVM) 的两种核心错误状态：

  • kFVNotAvailable (= 1)：当所需的新鲜度值不可用时，指示可恢复错误（Recoverable Error）[SWS_TS_14202]。该错误码尤其在通过 apext::tsync::FVM::GetTxFreshness 查询发送新鲜度值时出现 [SWS_TS_14199]。
  • kFVInitializeFailed (= 2)：当 Freshness Value Manager 处于未就绪状态且发生故障时，指示不可恢复错误（Unrecoverable Error）[SWS_TS_14202]。它在初始化失败时由 apext::tsync::FVM::Initialize 发出信号 [SWS_TS_14200]。

交互与错误处理

为了进行错误处理，枚举项与厂商特定附加数据一起通过辅助函数 apext::tsync::MakeErrorCode 转换为 ara::core::ErrorCode 对象 [SWS_TS_14213]。FVM 的函数如 Initialize [SWS_TS_14200]、GetTxFreshness [SWS_TS_14199] 和 GetRxFreshness [SWS_TS_14198] 将结果或错误状态封装在 ara::core::Result 中。应用程序和 TimeSync 组件对该 Result 对象进行求值，以区分单个新鲜度值的可恢复故障与 FVM 的严重初始化错误。
