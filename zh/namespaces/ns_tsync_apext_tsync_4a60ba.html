上下文

命名空间 apext::tsync 为 Freshness Value Management（FVM）提供 AUTOSAR Adaptive 模块 tsync 的平台特定扩展（Platform Extensions）。在分布式汽车 ECU 架构中，Freshness Value Management 通过生成、管理和验证动态新鲜度值，保护时间关键型以及安全相关的同步消息免受重放和延迟攻击。

该命名空间的主要任务是为模块 ara::tsync 提供核心接口 FVM 以及相关的数据结构。新鲜度值由此通过容器类 FVContainer 封装，该类既包含值的位长度，也包含以向量形式表示的实际有效载荷数据。为了进行标准化错误处理，该命名空间定义了独立的错误域 TsyncFvmErrorDomain 及其关联的错误枚举器 TsyncFvmErrc [SWS_TS_14202]、错误工厂函数 MakeErrorCode [SWS_TS_14213] 以及异常类 TsyncFvmException。

上下文图：ara::tsync、FVM 接口、FVContainer 和错误域之间的交互。来源：[SWS_TS_14202]、[SWS_TS_14212]、[SWS_TS_14213]。

生命周期

命名空间 apext::tsync 中的组件受明确划分的生命周期和并发条件的约束：

  • 错误域：类 TsyncFvmErrorDomain 用作全局的进程级错误域。通过函数 GetTsyncFvmErrorDomain() 可以随时检索对全局实例对象的引用。该函数被指定为 constexpr、线程安全且异常安全 [SWS_TS_14212]，因此错误域在应用程序的整个运行期间保持可用。
  • 管理器实例：为 Freshness Value Manager 规划了初始化阶段。Interpretation：Freshness Value Manager 的初始化应代表一个明确的启动阶段，其失败将永久阻止管理器的可用性。错误代码 TsyncFvmErrc::kFVInitializeFailed 证实了这一点，该错误代码被显式定义为不可恢复错误（“Unrecoverable Error”），在此之后 FVM 将无法再使用 [SWS_TS_14202]。
  • 数据容器：FVContainer 的实例具有特定于调用的生命周期。创建它们是为了容纳新鲜度值，在验证或消息创建期间传递它们，并可在过程完成后再次销毁。

使用路径

用于保护同步消息的典型使用路径分为以下交互步骤：

  1. 请求：Interpretation：接口 FVM 应由 ara::tsync 内部的组件调用，以请求和验证新鲜度值。上层时间模块集成接口 FVM，以便为外发或传入消息提供新鲜度值。
  2. 数据传递：成功确定后，Freshness Value Manager 会将新鲜度值的位长度和字节向量填充到 FVContainer 的实例中，并将其传递给调用方时间同步。
  3. 错误指示：如果在运行时没有有效值可用，子系统将利用 TsyncFvmErrc::kFVNotAvailable [SWS_TS_14202] 通过 MakeErrorCode [SWS_TS_14213] 生成类型为 ara::core::ErrorCode 的标准化错误代码。
  4. 错误评估：调用方评估结果。Interpretation：调用方应能够针对 kFVNotAvailable 进行重试读取，因为这属于可恢复的错误状态。

错误场景

apext::tsync 中的错误处理遵循通过 ara::core::ErrorCode 的 AUTOSAR Adaptive 标准模式：

  • TsyncFvmErrc::kFVNotAvailable（值 1）：表示可恢复错误（“Recoverable Error”）。该状态表明所需的新鲜度值暂时不可获取 [SWS_TS_14202]。调用逻辑可以通过在稍后时间点重试检索来处理此问题。
  • TsyncFvmErrc::kFVInitializeFailed（值 2）：表示不可恢复错误（“Unrecoverable Error”）。该代码表明 Freshness Value Manager 的初始化失败，且该模块不可用 [SWS_TS_14202]。

错误代码的构造通过 MakeErrorCode(TsyncFvmErrc, ara::core::ErrorDomain::SupportDataType) [SWS_TS_14213] 完成，该函数集成了特定于供应商的诊断数据，并保证以线程安全和异常安全的方式执行。对于使用 C++ 异常工作的软件路径，派生的异常类 TsyncFvmException 可供使用。

<li><strong>错误域：</strong>类 <code>TsyncFvmErrorDomain</code> 用作全局的进程级错误域。通过函数 <code>GetTsyncFvmErrorDomain()</code> 可以随时检索对全局实例对象的引用。该函数被指定为 <code>constexpr</code>、线程安全且异常安全 <a class="spec-record-ref" data-req="SWS_TS_14212" href="../spec/record.html?id=SWS_TS_14212">[SWS_TS_14212]</a>，因此错误域在应用程序的整个运行期间保持可用。</li>
<li><strong>管理器实例：</strong>为 Freshness Value Manager 规划了初始化阶段。Interpretation：Freshness Value Manager 的初始化应代表一个明确的启动阶段，其失败将永久阻止管理器的可用性。错误代码 <code>TsyncFvmErrc::kFVInitializeFailed</code> 证实了这一点，该错误代码被显式定义为不可恢复错误（“Unrecoverable Error”），在此之后 FVM 将无法再使用 <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>。</li>

</ul>

<h4>使用路径</h4>
<p>用于保护同步消息的典型使用路径分为以下交互步骤：</p>

<li><strong>请求：</strong>Interpretation：接口 <code>FVM</code> 应由 <code>ara::tsync</code> 内部的组件调用，以请求和验证新鲜度值。上层时间模块集成接口 <code>FVM</code>，以便为外发或传入消息提供新鲜度值。</li>
<li><strong>数据传递：</strong>成功确定后，Freshness Value Manager 会将新鲜度值的位长度和字节向量填充到 <code>FVContainer</code> 的实例中，并将其传递给调用方时间同步。</li>
<li><strong>错误指示：</strong>如果在运行时没有有效值可用，子系统将利用 <code>TsyncFvmErrc::kFVNotAvailable</code> <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a> 通过 <code>MakeErrorCode</code> <a class="spec-record-ref" data-req="SWS_TS_14213" href="../spec/record.html?id=SWS_TS_14213">[SWS_TS_14213]</a> 生成类型为 <code>ara::core::ErrorCode</code> 的标准化错误代码。</li>
<li><strong>错误评估：</strong>调用方评估结果。Interpretation：调用方应能够针对 <code>kFVNotAvailable</code> 进行重试读取，因为这属于可恢复的错误状态。</li>
</ol>

<h4>错误场景</h4>
<p><code>apext::tsync</code> 中的错误处理遵循通过 <code>ara::core::ErrorCode</code> 的 AUTOSAR Adaptive 标准模式：</p>

<li><strong><code>TsyncFvmErrc::kFVInitializeFailed</code>（值 2）：</strong>表示不可恢复错误（“Unrecoverable Error”）。该代码表明 Freshness Value Manager 的初始化失败，且该模块不可用 <a class="spec-record-ref" data-req="SWS_TS_14202" href="../spec/record.html?id=SWS_TS_14202">[SWS_TS_14202]</a>。</li>
