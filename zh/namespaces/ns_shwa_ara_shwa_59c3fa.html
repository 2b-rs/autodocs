上下文

命名空间ara::shwa（Safe Hardware Acceleration）为 AUTOSAR Adaptive Platform 上计算密集型任务提供用于硬件加速器（如 GPU 或 CPU）发现、分配和使用的接口。该模块在结构上将系统探测、资源管理与实际的异步任务处理分离开来。

核心识别单元由Platform构成，通过它可以确定系统中可用的硬件加速器平台并查询所连接的Device实例。为了选择具体的执行目标，该命名空间提供了诸如DeviceSelector、CpuSelector、GpuSelector和AcceleratorSelector等选择器，借助它们可根据应用程序特定的优先级或目标架构确定合适的Device。

任务不会直接在Device上启动，而是通过Queue进行协调，由其控制所选目标上的并行处理。数据通过Buffer提供，其尺寸通过Range确定，其内存访问则通过Accessor予以保护。核心组件的相互协作由此涵盖了选择、内存管理与并行执行。

生命周期

在相关对象的生命周期中，ara::shwa严格区分拥有资源的实体和非拥有资源的实体：

  • 拥有资源的对象：Queue、Buffer和Accessor拥有具体的硬件或内存资源。它们明确不可复制（non-copyable），并设计为专门通过std::unique_ptr进行管理并在需要时被移动（move）。
  • 无资源引用对象：Platform、Device、DeviceMonitor、Id和Range本身不拥有底层资源。它们被设计为可复制（copyable）的描述符和句柄。
  • Queue 绑定对象：Event（用于主机与 HWA 之间的同步）以及TaskHandler（用于控制任务执行）的实例只能在Queue内进行实例化；在 Queue 之外，它们没有任何功能意义。

Device在其可用性方面反映了离散的运行状态，这些状态通过枚举DeviceStatus映射[AP_SWS_SHWA_00103]。在任务分配之前，状态kReady指示已准备好执行，而kNotAccesible、kFailure或kUnknown则限制或阻止其使用。

使用路径

典型的处理流程涉及该命名空间的多个类，并遵循设备选择、执行流水线创建、内存缓冲和同步执行的固定顺序：

  1. 平台与设备选择：应用程序通过Platform读取可用设备，或者使用DeviceSelector（或GpuSelector、CpuSelector、AcceleratorSelector）来选择具有最高优先级的最合适Device实例。
  2. Queue 实例化：为了进行并行处理，会为所选的Device创建一个作为std::unique_ptr<Queue>的Queue。
  3. 内存分配与访问管理：通过Range定义维度。随后在主机或加速器上创建一个用于内存分配的Buffer。为了进行受控的读写操作，会实例化一个Accessor，其模式通过AccessMode指定为kRead、kWrite或kReadWrite [AP_SWS_SHWA_00101]。
  4. 任务提交与同步：通过Queue将用于在目标（通过Target::kDevice或Target::kHostTask [AP_SWS_SHWA_00102]指定）上执行的TaskHandler排队。借助在 Queue 内部创建的Event实现主机应用程序与 HWA 处理之间的同步。

错误场景

Safe Hardware Acceleration 的 API 基本上采用无异常设计（exception-free）。各操作通过归属于特定错误域ShwaErrorDomain的ara::core::ErrorCode类型错误代码来指示错误。

对该域的访问通过GetShwaDomain() [AP_SWS_SHWA_01311]进行，而标准化错误代码则通过辅助函数MakeErrorCode()构建[AP_SWS_SHWA_01312]。枚举ShwaErrorCode定义了以下原因等[AP_SWS_SHWA_01301]：

  • kRuntime：运行期间的一般运行时错误。
  • kTaskExecutionFailure：所提交任务在加速器或主机上的执行错误。
  • kMemoryNotAllocated：通过Buffer分配内存失败。
  • kIntegrityCorrupted：无法保持Buffer的内存完整性。
  • kResourceBusy：所请求的设备或 Queue 资源已被占用。
  • kInvalidAccessMode和kAccessorFailure：AccessMode中的访问模式不允许，或创建及使用Accessor失败。
  • kEventInvalidOperation：对Event同步对象的操作不允许。
  • kFeatureNotSupported：后端或驱动程序不支持所请求的硬件特性。
  • kInvalidIndex、kInvalidParameter和kInvalidObject：错误的传递值、无效索引，或使用了已销毁或无效的对象。
  • kTimedOut：执行或同步期间超时。

对于基于 C++ 异常的架构，提供了类ShwaException。API 本身不会抛出此异常，但应用程序可以在需要时将错误代码转换为异常并继续传递。对于 HWA 级别的异步错误处理，应用程序还会引入ErrorHandler。

  <h4>上下文</h4>
  <p>
    命名空间<code>ara::shwa</code>（Safe Hardware Acceleration）为 AUTOSAR Adaptive Platform 上计算密集型任务提供用于硬件加速器（如 GPU 或 CPU）发现、分配和使用的接口。该模块在结构上将系统探测、资源管理与实际的异步任务处理分离开来。
  </p>
  <p>
    核心识别单元由<code>Platform</code>构成，通过它可以确定系统中可用的硬件加速器平台并查询所连接的<code>Device</code>实例。为了选择具体的执行目标，该命名空间提供了诸如<code>DeviceSelector</code>、<code>CpuSelector</code>、<code>GpuSelector</code>和<code>AcceleratorSelector</code>等选择器，借助它们可根据应用程序特定的优先级或目标架构确定合适的<code>Device</code>。
  </p>
  <p>
    任务不会直接在<code>Device</code>上启动，而是通过<code>Queue</code>进行协调，由其控制所选目标上的并行处理。数据通过<code>Buffer</code>提供，其尺寸通过<code>Range</code>确定，其内存访问则通过<code>Accessor</code>予以保护。核心组件的相互协作由此涵盖了选择、内存管理与并行执行。
  </p>

  <h4>生命周期</h4>
  <p>
    在相关对象的生命周期中，<code>ara::shwa</code>严格区分拥有资源的实体和非拥有资源的实体：
  </p>
  <ul>
    <li>
      <strong>拥有资源的对象：</strong><code>Queue</code>、<code>Buffer</code>和<code>Accessor</code>拥有具体的硬件或内存资源。它们明确不可复制（non-copyable），并设计为专门通过<code>std::unique_ptr</code>进行管理并在需要时被移动（move）。
    </li>
    <li>
      <strong>无资源引用对象：</strong><code>Platform</code>、<code>Device</code>、<code>DeviceMonitor</code>、<code>Id</code>和<code>Range</code>本身不拥有底层资源。它们被设计为可复制（copyable）的描述符和句柄。
    </li>
    <li>
      <strong>Queue 绑定对象：</strong><code>Event</code>（用于主机与 HWA 之间的同步）以及<code>TaskHandler</code>（用于控制任务执行）的实例只能在<code>Queue</code>内进行实例化；在 Queue 之外，它们没有任何功能意义。
    </li>
  </ul>
  <p>
    <code>Device</code>在其可用性方面反映了离散的运行状态，这些状态通过枚举<code>DeviceStatus</code>映射<a class="spec-record-ref" data-req="AP_SWS_SHWA_00103" href="../spec/record.html?id=AP_SWS_SHWA_00103">[AP_SWS_SHWA_00103]</a>。在任务分配之前，状态<code>kReady</code>指示已准备好执行，而<code>kNotAccesible</code>、<code>kFailure</code>或<code>kUnknown</code>则限制或阻止其使用。
  </p>

  <h4>使用路径</h4>
  <p>
    典型的处理流程涉及该命名空间的多个类，并遵循设备选择、执行流水线创建、内存缓冲和同步执行的固定顺序：
  </p>
  <ol>
    <li>
      <strong>平台与设备选择：</strong>应用程序通过<code>Platform</code>读取可用设备，或者使用<code>DeviceSelector</code>（或<code>GpuSelector</code>、<code>CpuSelector</code>、<code>AcceleratorSelector</code>）来选择具有最高优先级的最合适<code>Device</code>实例。
    </li>
    <li>
      <strong>Queue 实例化：</strong>为了进行并行处理，会为所选的<code>Device</code>创建一个作为<code>std::unique_ptr&lt;Queue&gt;</code>的<code>Queue</code>。
    </li>
    <li>
      <strong>内存分配与访问管理：</strong>通过<code>Range</code>定义维度。随后在主机或加速器上创建一个用于内存分配的<code>Buffer</code>。为了进行受控的读写操作，会实例化一个<code>Accessor</code>，其模式通过<code>AccessMode</code>指定为<code>kRead</code>、<code>kWrite</code>或<code>kReadWrite</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00101" href="../spec/record.html?id=AP_SWS_SHWA_00101">[AP_SWS_SHWA_00101]</a>。
    </li>
    <li>
      <strong>任务提交与同步：</strong>通过<code>Queue</code>将用于在目标（通过<code>Target::kDevice</code>或<code>Target::kHostTask</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_00102" href="../spec/record.html?id=AP_SWS_SHWA_00102">[AP_SWS_SHWA_00102]</a>指定）上执行的<code>TaskHandler</code>排队。借助在 Queue 内部创建的<code>Event</code>实现主机应用程序与 HWA 处理之间的同步。
    </li>
  </ol>

  <h4>错误场景</h4>
  <p>
    Safe Hardware Acceleration 的 API 基本上采用无异常设计（exception-free）。各操作通过归属于特定错误域<code>ShwaErrorDomain</code>的<code>ara::core::ErrorCode</code>类型错误代码来指示错误。
  </p>
  <p>
    对该域的访问通过<code>GetShwaDomain()</code> <a class="spec-record-ref" data-req="AP_SWS_SHWA_01311" href="../spec/record.html?id=AP_SWS_SHWA_01311">[AP_SWS_SHWA_01311]</a>进行，而标准化错误代码则通过辅助函数<code>MakeErrorCode()</code>构建<a class="spec-record-ref" data-req="AP_SWS_SHWA_01312" href="../spec/record.html?id=AP_SWS_SHWA_01312">[AP_SWS_SHWA_01312]</a>。枚举<code>ShwaErrorCode</code>定义了以下原因等<a class="spec-record-ref" data-req="AP_SWS_SHWA_01301" href="../spec/record.html?id=AP_SWS_SHWA_01301">[AP_SWS_SHWA_01301]</a>：
  </p>
  <ul>
    <li><code>kRuntime</code>：运行期间的一般运行时错误。</li>
    <li><code>kTaskExecutionFailure</code>：所提交任务在加速器或主机上的执行错误。</li>
    <li><code>kMemoryNotAllocated</code>：通过<code>Buffer</code>分配内存失败。</li>
    <li><code>kIntegrityCorrupted</code>：无法保持<code>Buffer</code>的内存完整性。</li>
    <li><code>kResourceBusy</code>：所请求的设备或 Queue 资源已被占用。</li>
    <li><code>kInvalidAccessMode</code>和<code>kAccessorFailure</code>：<code>AccessMode</code>中的访问模式不允许，或创建及使用<code>Accessor</code>失败。</li>
    <li><code>kEventInvalidOperation</code>：对<code>Event</code>同步对象的操作不允许。</li>
    <li><code>kFeatureNotSupported</code>：后端或驱动程序不支持所请求的硬件特性。</li>
    <li><code>kInvalidIndex</code>、<code>kInvalidParameter</code>和<code>kInvalidObject</code>：错误的传递值、无效索引，或使用了已销毁或无效的对象。</li>
    <li><code>kTimedOut</code>：执行或同步期间超时。</li>
  </ul>
  <p>
    对于基于 C++ 异常的架构，提供了类<code>ShwaException</code>。API 本身不会抛出此异常，但应用程序可以在需要时将错误代码转换为异常并继续传递。对于 HWA 级别的异步错误处理，应用程序还会引入<code>ErrorHandler</code>。
  </p>
