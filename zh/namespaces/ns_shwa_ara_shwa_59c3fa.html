实现将计算密集型任务安全卸载到专用硬件加速器。

命名空间 ara::shwa 提供用于安全硬件加速（Safe Hardware Acceleration）的接口，并允许通过目标格式 Target 将并行计算任务有针对性地卸载到 GPU 或 CPU 等设备（[AP_SWS_SHWA_00102]）。应用程序通过选择器选择加速器，创建独占管理的执行队列，并通过缓冲区访问器控制内存访问。核心边界条件是具有不可复制资源的严格所有权模型，以及通过 ShwaErrorCode 的无异常错误指示（[AP_SWS_SHWA_01301]）。

上下文

命名空间 ara::shwa（Safe Hardware Acceleration）在 AUTOSAR Adaptive Platform 内提供接口，以便将计算密集型任务卸载到专用硬件加速器。该模块允许集成不同类型的加速器，例如图形处理器（GPU）、数字信号处理器或专用主处理器（CPU）。

系统环境的检测通过类 Platform 进行，该类确定电子控制单元（ECU）上可用的硬件平台并列出关联的 Device 实例。合适设备的选择可以通过专用选择器动态或静态控制：DeviceSelector 作为可调用函数对象，根据整数等级对可用单元进行优先级排序，而 CpuSelector、GpuSelector 和 AcceleratorSelector 则有针对性地寻址特定的执行单元。加速器的当前运行状态通过枚举 DeviceStatus（[AP_SWS_SHWA_00103]）映射。

Queue 负责计算操作的并行执行。计算作业通过 TaskHandler 封装，其中执行位置通过 Target（[AP_SWS_SHWA_00102]）可选地指定在加速器（kDevice）或主机 CPU（kHostTask）上。用于输入和输出数据的内存区域通过 Buffer 使用维度规范 Range 进行分配。对这些缓冲区的访问由 Accessor 对象管理，这些对象通过 AccessMode（[AP_SWS_SHWA_00101]）限制访问模式。

生命周期

ara::shwa 中的资源和生命周期模型严格区分了拥有资源的对象、描述性句柄和依赖于队列的组件：

  • 拥有资源的类：Queue、Buffer 和 Accessor 独占管理硬件资源和内存区域。它们不可复制（not copyable），且必须强制通过 std::unique_ptr 进行管理。仅允许通过移动语义进行传递或转交。
  • 描述性句柄和辅助类：Platform、Device、DeviceMonitor、Id、Range 和 PropertyList 不独占拥有硬件资源。它们被设计为可复制。Device 的实例仅代表对设备的访问接口，但不独占控制该设备。解释：执行队列（Queue）的初始化绑定到先前选择的特定 Device，因为 Queue 独占管理资源。
  • 依赖组件：类 Event（用于同步）和 TaskHandler（用于任务处理）只能在 Queue 内部创建；在队列上下文之外，它们不具有任何功能意义。

设备的生命周期反映在 DeviceStatus（[AP_SWS_SHWA_00103]）中：除了就绪状态 kReady 之外，设备还可以被标示为不可访问（kNotAccesible）、故障（kFailure）或未知（kUnknown）。解释：设备在 kReady、kNotAccesible 和 kFailure 之间的状态变化在运行时通过辅助类（如 DeviceMonitor）或平台来检测。

使用路径

使用 ara::shwa 执行加速计算的典型过程分为五个步骤：

  1. 平台和设备选择：应用程序通过 Platform 查询现有的硬件平台及其关联的 Device 实例。选择器（如 DeviceSelector、GpuSelector 或 CpuSelector）确定最合适的设备，该设备的 DeviceStatus（[AP_SWS_SHWA_00103]）具有状态 kReady。
  2. 实例化队列：为所选的 Device 创建 Queue 并作为 std::unique_ptr 持有。
  3. 分配并准备内存：对于输入和输出数据，通过 Range 创建具有所需维度的 Buffer。为了填充或求值，应用程序请求一个 Accessor，其中访问模式通过 AccessMode（[AP_SWS_SHWA_00101]）声明为 kRead、kWrite 或 kReadWrite。
  4. 注册并执行任务：在 Queue 内创建一个 TaskHandler。启动执行，其中通过 Target（[AP_SWS_SHWA_00102]）指定任务是在加速器（kDevice）上还是在主机（kHostTask）上运行。
  5. 同步：Queue 提供一个 Event，主机应用程序通过它监控硬件加速器上计算的异步完成情况，并同步数据比对。

时序图：从平台查询到缓冲区分配直至同步执行的流程。来源：[AP_SWS_SHWA_00101]、[AP_SWS_SHWA_00102]、[AP_SWS_SHWA_00103]

错误场景

ara::shwa 的编程接口采用无异常（exception-free）设计。错误状态通过 ara::core::ErrorCode 同步返回。错误码的创建通过工厂函数 MakeErrorCode（[AP_SWS_SHWA_01312]）并参考错误域 GetShwaDomain（[AP_SWS_SHWA_01311]）进行。如果应用程序架构采用基于异常的错误模型，则可以将错误码转换为 ShwaException 并抛出。

枚举 ShwaErrorCode（[AP_SWS_SHWA_01301]）指定了标准化的错误原因：

  • 内存和访问问题：主内存分配失败会导致 kMemoryNotAllocated。若无法维持缓冲区的数据一致性，则会报告 kIntegrityCorrupted。非法访问模式或对 Accessor 对象的操作失败会导致 kInvalidAccessMode 或 kAccessorFailure。
  • 执行和同步错误：目标设备上的任务处理失败时会指示 kTaskExecutionFailure。对同步对象的非法操作会导致 kEventInvalidOperation，而阻塞的资源会触发 kResourceBusy。如果超过配置的执行时间，则返回 kTimedOut。
  • 无效参数和对象状态：对已销毁或无效对象调用方法会导致 kInvalidObject。无效索引或参数通过 kInvalidIndex 或 kInvalidParameter 予以拒绝。不支持的功能报告 kFeatureNotSupported，而一般错误则通过 kRuntime 捕获。

为了处理在加速器上进行异步计算期间发生的错误，使用类 ErrorHandler。
