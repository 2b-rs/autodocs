为自适应通信的端到端保护提供类型、校验状态和错误域。

命名空间 ara::com::e2e 定义了用于自适应通信端到端保护的类型、状态和错误代码。使用端应用程序根据 ProfileCheckStatus 和 SMState 评估接收到的数据样本，并且仅当存在状态 kValid 时才允许使用数据 ([SWS_CM_90422])。在提供端，可以通过 TransportFaultConditionHandler 监控截止时间冲突或数据包丢失等错误 ([SWS_CM_00091])。错误状态通过错误域 ComE2EErrorDomain 进行标准化映射。

上下文

命名空间 ara::com::e2e 为 AUTOSAR Adaptive 通信模块中的端到端保护 (E2E) 提供数据类型、状态枚举和错误处理结构。其主要任务是在应用层和传输层透明且标准化地检测传输错误和数据完整性错误。

在通信架构内部，该命名空间与多个关键组件进行交互：

  • 服务提供者（Skeleton）：在提供端，可以通过函数指针监控传输的错误情况。类型 TransportFaultConditionHandler ([SWS_CM_00092]) 允许针对 Skeleton 的所有方法 (AUTOSAR_AP_EXP_SWArchitecture 第68页) 以及单个 Skeleton 字段的 Getter 和 Setter 调用 (AUTOSAR_AP_EXP_SWArchitecture 第69页) 注册和注销相应的监控回调。
  • 消费者与事件数据（SamplePtr）：在消费者端，接收到的数据样本会接受 E2E 校验。单个样本的校验结果通过 ProfileCheckStatus 映射 ([SWS_CM_90421])，而监控的总体状态通过 SMState 记录 ([SWS_CM_90422])。
  • 错误处理：错误域 ComE2EErrorDomain (AUTOSAR_AP_EXP_ARAComAPI 第9页) 和关联的错误代码 ComE2EErrc ([SWS_CM_10474]) 将 E2E 错误无缝集成到 ara::core 的错误架构模型中。类 ComE2EException 用于异常处理。

上下文图：服务提供者（Skeleton）、样本管理（SamplePtr）与错误域 ara::com::e2e 的交互。来源：AUTOSAR_AP_EXP_SWArchitecture 第68页、[SWS_CM_90421]、[SWS_CM_10474]。

生命周期与状态监控

E2E 监控具有基于状态的生命周期阶段，该阶段与通过事件接收数据样本相耦合。状态由枚举 SMState 表示 ([SWS_CM_90422])：

  • kInit：初始化后，尚无足够数量通过 E2E 校验的数据样本；不得使用样本。
  • kValid：根据 E2E 校验，数据样本通信正常工作；允许消费样本。
  • kInvalid：在 E2E 时间窗口内接收到的无错误样本太少，或错误样本过多；不得使用样本。
  • kNoData：尚未从发布者处接收到任何数据。
  • kStateMDisabled：E2E 状态机已被管理性禁用。
  • kIncompatibleQoS：两个通信端点配置的服务质量策略 (QoS) 不匹配。

与此同时，ProfileCheckStatus 提供单个数据样本的周期状态 ([SWS_CM_90421])：除成功状态 kOk 外，校验还能区分计数器重复 (kRepeated)、不允许的计数器跳变 (kWrongSequence) 以及数据校验错误 (kError，如 CRC、长度或 Data-ID 错误)。当校验被禁用时，返回 kCheckDisabled。

作为数据处理的基本前提条件：应用程序仅当 SMState == kValid 成立且数据样本的校验 (GetProfileCheckStatus) 未导致错误 (kError) 时，才可以使用接收到的数据样本 ([SWS_CM_90422])。

使用路径

典型的使用路径涵盖消费者端接收到的事件数据校验以及提供端传输错误通知的配置：

  1. 数据样本状态查询：通过 ara::com::SamplePtr 接收到数据样本后，使用端应用程序调用 GetProfileCheckStatus() 以确定该样本的特定校验结果 ([SWS_CM_90421])。
  2. 监控状态检查：应用程序调用 GetSMState() 以查询 E2E 状态机的聚合状态 ([SWS_CM_90422])。
  3. 处理或错误处理：如果存在 SMState == kValid 且未报告错误，则进行有效负载数据处理 ([SWS_CM_90422])。否则，通过标准化错误结构处理 E2E 错误或通过 MakeErrorCode 向后传递 ([SWS_CM_12511])。
  4. Skeleton 上的传输错误处理：服务提供者注册一个 TransportFaultConditionHandler 以监控其方法和字段操作 ([SWS_CM_00092], AUTOSAR_AP_EXP_SWArchitecture 第68页, AUTOSAR_AP_EXP_SWArchitecture 第69页)。发生与传输相关的错误时，将使用相应的 TransportFaultCondition 调用回调 ([SWS_CM_00091])。

时序图：用于校验接收到的数据样本及错误处理的调用顺序。来源：[SWS_CM_90421]、[SWS_CM_90422]、[SWS_CM_12511]。

错误场景

在发生错误时，该命名空间提供两种独立的机制，用于映射不同的错误源：

传输错误通过枚举 TransportFaultCondition 进行信号通知 ([SWS_CM_00091])：

  • kSampleRejected：由于端点处的资源耗尽，数据样本在第 4 层或更高层被丢弃。
  • kDeadlineMissed：数据样本已超出其配置的截止时间间隔（Deadline）。
  • kSampleLost：检测到数据样本丢失（例如序列号中存在间隙）。

E2E 转换的协议和校验错误通过 ComE2EErrc 进行分类 ([SWS_CM_10474])。这些错误代码包括计数器重复 (kRepeated)、超出允许增量的计数器跳变 (kWrongSequence)、CRC/长度错误 (kError)、缺少新数据 (kNoNewData) 以及远程服务错误 (kUnspecifiedE2EError)。函数 MakeErrorCode 用于构造类型 ara::core::ErrorCode 的实例 ([SWS_CM_12511])，而 GetComE2EErrorDomain 返回对 ComE2EErrorDomain 的单例实例的引用 ([SWS_CM_12510])。解释：类 ComE2EException 可能主要用于在启用了 C++ 异常的执行路径中映射错误。

枚举 ComE2EErrc 在命名空间 ara::com::e2e 中基于 ara::core::ErrorDomain::CodeType [SWS_CM_10474] 定义了端到端保护（E2E）的特定错误码。在错误域 ara::com::e2e::ComE2EErrorDomain 内，该类型通过类型别名 Errc 提供 [SWS_CM_12504]。

枚举器值描述了确定的校验结果和错误状态 [SWS_CM_10474]：

  • kRepeated：数据呈现出重复的计数值 [SWS_CM_10474]。
  • kWrongSequence：校验成功，但计数跳变超过了允许的增量 [SWS_CM_10474]。
  • kError：发生了与计数器无关的错误（例如错误的CRC、错误的长度或无效的Data-ID），或者校验函数的返回结果不正常 [SWS_CM_10474]。
  • kNoNewData：没有新数据可用 [SWS_CM_10474]。
  • kUnspecifiedE2EError：远端服务返回了未指定的E2E错误 [SWS_CM_10474]。

在服务端请求处理中，当消息的E2E校验失败时，ComE2EErrc 将作为参数 errorCode 传递给骨架的方法 E2EErrorHandler [SWS_CM_10470]，AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.3.3 “E2E error notification”。如果没有新的请求消息就绪，则必须使用 ComE2EErrc::kNoNewData 以及 dataID = 0 和 messageCounter = 0 调用处理程序 [SWS_CM_00047]。在错误处理程序执行完毕后，将进行响应消息的E2E保护 [SWS_CM_90481]。

关于并发性和边界条件：方法 E2EErrorHandler 未被指定为可重入，且不是 exception safe [SWS_CM_10470]。其注册完全在运行时之前静态进行；不提供动态注册或注销 AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.3.3 “E2E error notification”。此外，在发生CRC错误时，服务端应用程序不得依赖传入的Data-ID，因为该标识符可能已损坏 [SWS_CM_10470]。

      用法与调用上下文
      

      命名空间 ara::com::e2e 中的枚举 ProfileCheckStatus 表示对单个接收到的数据样本进行端到端检查 (E2E) 的结果 [SWS_CM_90421]。接收到受 E2E 保护的样本时，通信管理会在 GetNewSamples() 内执行例程 E2E_check，该例程返回 ProfileCheckStatus [SWS_CM_90411]。该状态直接保存在相关的 ara::com::SamplePtr 中 [SWS_CM_90413]。接收方通过类 ara::com::SamplePtr 的方法 GetProfileCheckStatus() 以同步且异常安全的方式访问检查状态 [SWS_CM_00042]，[SWS_CM_90420]。
      

      状态值与错误处理
      

      底层类型采用 std::uint8_t [SWS_CM_90421]。该枚举定义了以下状态用于单独的错误分析：
      

        

      • kOk：当前周期中样本的所有检查（包括计数器检查）均成功 [SWS_CM_90421]。
        • 

      • kRepeated：接收到的数据样本具有重复的计数器值 [SWS_CM_90421]。
        • 

      • kWrongSequence：检查成功，但存在超出允许增量的不合规计数器跳跃 [SWS_CM_90421]。
        • 

      • kError：发生了与计数器无关的错误，例如 CRC 错误、长度不正确或 Data ID 错误 [SWS_CM_90421]。
        • 

      • kCheckDisabled：当 EndToEndTransformationComSpecProps.disableEndToEndCheck 配置为 TRUE 时，表示没有处于激活状态的 E2E 检查 [SWS_CM_90421]。
        • 

      

      交互与约束条件
      

      虽然 ProfileCheckStatus 反映了单个样本的独立检查结果 [SWS_CM_90421]，但事件类并行管理上层状态机 ara::com::e2e::SMState [SWS_CM_90413]，该状态机可通过 GetE2EStateMachineState() 获取 [SWS_CM_10475]。其定义位于头文件 ara/com/e2e/profile_check_status.h [SWS_CM_90421] 中。
