上下文

命名空间 ara::sm::s2r 为 State Management (SM) 模块内的 Suspend-to-RAM (S2R) 功能提供接口和机制（AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。Suspend-to-RAM 运行的目标是通过将 Machine 置于允许快速重新启动的状态，而不是执行完全关闭及随后的冷启动，从而显著优化启动和关机时间（AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。

该命名空间中的核心角色由类 S2RHub 承担（AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”）。Hub 协调与分布式 S2RSatellite 实例的通信。其可执行单元配置为 suspendToRamAware 的应用程序会集成此类 Satellite 实例，以便接收有关即将到来的 Suspend 和 Resume 周期的通知（AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”、[SWS_SM_00710]）。声明为 suspendToRamNotSupported 的进程必须在操作系统转换到 Suspend 状态之前，已通过 State Management 流程（例如终止受影响的功能组）停止（AUTOSAR_AP_SWS_StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。

对于 S2RHub 的控制，存在两种互斥的方法（[SWS_SM_00684]）：

  • StateMachine 方法：Controller 通过关联的 ActionListItem 对象在内部集成 S2RHub 功能。在这种操作模式下，禁止外部控制应用程序访问 Hub 的 C++ API，以防止竞争条件和状态不一致（AUTOSAR_AP_SWS_StateManagement §7.7 “StateMachine approach”、[SWS_SM_00684]）。
  • 直接 C++ API：外部控制应用程序（例如 SMControlApplication）直接使用 S2RHub 的类方法（AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”）。

生命周期

命名空间 ara::sm::s2r 中实例的创建和释放严格绑定到权限检查（Identity and Access Management，IAM）和已配置的映射：

  • Hub 实例化：在 StateMachine 方法中，一旦类型为 EnterSuspendToRam、EnterSuspendToRamOS 或 LeaveSuspendToRam 的 ActionListItem 终止，State Management 就会创建 S2RHub 的一个实例（[SWS_SM_00690]）。在构造函数 ara::sm::s2r::S2RHub::S2RHub 执行期间，将检查进程上下文是否与 SuspendToRamHubMapping.process 中的分配相匹配（[SWS_SM_00706]）。只有通过 SuspendToRamHubMapping 获得授权的进程才允许通过由 SuspendToRamModuleInstantiation 标识的 Hub 实例触发挂起操作（[SWS_SM_00714]）。
  • Satellite 创建：Satellite 实例通过工厂方法 ara::sm::s2r::S2RSatellite::Create 进行实例化（[SWS_SM_00716]）。
  • 注册阶段：创建后，Satellite 通过 ara::sm::s2r::S2RSatellite::Offer 在 Hub 上注册（[SWS_SM_00710]）。Hub 根据 SuspendToRamSatelliteMapping.process 中的配置验证进程上下文，并拒绝未授权的注册尝试（[SWS_SM_00715]）。从成功注册起，Satellite 被视为处于活动注册状态（[SWS_SM_00710]）。
  • 注销：一旦 Satellite 调用 ara::sm::s2r::S2RSatellite::StopOffer，活动注册即告终止（[SWS_SM_00710]、[SWS_SM_00713]）。

使用路径

典型的使用流程包括休眠状态的准备、切换到 Suspend 模式，以及在 Machine 重新激活后的协同唤醒：

  1. 准备就绪：每个支持 S2R 的应用程序都会初始化其 S2RSatellite，并通过 Offer() 向 Hub 报告接收就绪状态（[SWS_SM_00710]）。
  2. Suspend 请求：为了启动休眠状态，调用 ara::sm::s2r::S2RHub::RequestToEnterSuspendMode（[SWS_SM_00701]）。在 StateMachine 方法中，这是通过 ActionListItem EnterSuspendToRam 并使用 maxActionItemDuration 作为超时参数来执行的（[SWS_SM_00689]）。
  3. Satellite 通知：Hub 寻址所有处于活动注册状态的 Satellite，并触发它们的回调 ara::sm::s2r::S2RSatellite::EnterSuspendMode（[SWS_SM_00701]、[SWS_SM_00711]）。RequestToEnterSuspendMode 保持阻塞，直到所有被寻址的 Satellite 均已响应、注销，或发生通信超时（[SWS_SM_00702]）。
  4. 操作系统挂起：当所有 Satellite 准备就绪后，可以通过 EnterSuspendToRamOs 触发操作系统的实际挂起命令（[SWS_SM_00692]）。
  5. 唤醒请求：唤醒后，控制器调用 ara::sm::s2r::S2RHub::RequestToLeaveSuspendMode（[SWS_SM_00703]）。在 StateMachine 方法中，这通过 ActionListItem LeaveSuspendToRam 实现（[SWS_SM_00691]）。根据约束 [SWS_SM_CONSTR_00035]，LeaveSuspendToRam 只能分配给负责离开 Suspend 模式的状态，而不能分配给休眠状态本身。
  6. Satellite 重新激活：Hub 在已注册的 Satellite 上调用 ara::sm::s2r::S2RSatellite::LeaveSuspendMode（[SWS_SM_00703]、[SWS_SM_00711]）。一旦所有 Satellite 均已响应、已被注销或超时已过，该调用立即返回（[SWS_SM_00707]）。
  7. 注销退出：当进程或 Satellite 终止时，通过 StopOffer() 在 Hub 上执行注销（[SWS_SM_00710]、[SWS_SM_00713]）。

错误场景

在 Hub 和 Satellite 的交互中，指定了以下错误条件和前置条件：

  • Hub 创建时的 IAM 违规：若 S2RHub::S2RHub 调用者的进程上下文不符合配置 SuspendToRamHubMapping.process，则会报告违规 InsufficientPermissionsViolation 并触发安全事件 SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED（[SWS_SM_00706]）。
  • Satellite 上缺少身份验证：若 IAM 开关“Force IAM switch”已启用，则 S2RSatellite::Create 返回错误代码 kAuthenticationRequired（[SWS_SM_00716]）。
  • 拒绝未授权的 Satellite：若 Satellite 的进程上下文与 SuspendToRamSatelliteMapping.process 不一致，Hub 将拒绝该注册（[SWS_SM_00715]）。
  • 通信超时：若在 RequestToLeaveSuspendMode 期间被寻址的 Satellite 未在 timeout 指定的时间跨度内做出响应，Hub 将返回错误代码 kCommunicationTimeout（[SWS_SM_00707]）。
  • 卫星拒绝：若在退出休眠状态时至少有一个卫星实例以 kRejected 作出否定响应，则 Hub 将 kAtLeastOneHadIssuesToLeave 作为总体结果返回（[SWS_SM_00707]）。只有当所有卫星均给出肯定确认或通过 StopOffer 正常注销时，才会获得肯定的总体结果（[SWS_SM_00707]）。
  • 配置与使用限制：将 LeaveSuspendToRam 分配给 StateMachine 的 Suspend 状态是不允许的（[SWS_SM_CONSTR_00035]）。同样，在 StateMachine 方法处于活动状态时，禁止同时访问 S2RHub 的 C++ API（[SWS_SM_00684]）。
