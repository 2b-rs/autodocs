上下文

命名空间 ara::exec 提供 AUTOSAR Adaptive Platform 上 Execution Management 模块的接口。该模块负责进程的生命周期、控制系统启动并监控已配置功能组（Function Groups）的状态迁移。该命名空间的类封装了三个核心参与者之间的交互：应用程序特定进程、中央 Execution Management 和 State Management。

对于进程而言，类 ExecutionClient 用作主要通信通道，已启动的进程通过该通道向 Execution Management 报告其当前执行状态。State Management 通过类 StateClient 访问 Execution Management，以请求功能组（FunctionGroup）与其目标状态（FunctionGroupState）之间定义的状态迁移。如果在功能组运行期间发生执行错误，则通过 ExecutionErrorEvent 以及相应的错误类型 ExecutionError [SWS_EM_02541] 表示该错误。

上下文图：进程、Execution Management 与 State Management 之间的相互作用。来源：[SWS_EM_02000]、[SWS_EM_02281]

生命周期

进程的生命周期由状态描述，这些状态部分由 Execution Management 隐式管理，部分由进程主动报告 [SWS_EM_02000]。枚举 ExecutionState 仅描述进程可主动向 Execution Management 传输的那些状态。为此定义的唯一状态值是 ExecutionState::kRunning [SWS_EM_02000]。

从 Execution Management 的角度来看，进程经历以下阶段：

  • Initializing：一个隐式状态，该状态在操作系统调度进程（执行应用程序特定代码之前）时开始，并在进程报告 kRunning 时结束 [SWS_EM_02000]。
  • Running：成功报告 ExecutionState::kRunning 后的活动执行状态 [SWS_EM_02000]。
  • Terminating：另一个隐式状态，该状态在 Execution Management 请求终止进程时启动，并在进程完全结束时结束 [SWS_EM_02000]。

状态图：进程在 Execution Management 中的状态阶段。来源：[SWS_EM_02000]

使用路径

应用程序进程的典型使用路径包括初始化以及随后的就绪状态信号发送。由 Execution Management 启动后，进程执行其内部启动例程。一旦初始化完成且常规工作运行开始，进程将创建 ExecutionClient 的实例并传输状态 ExecutionState::kRunning [SWS_EM_02000]。

Execution Management 接收该报告并验证该迁移。如果进程在已处于 Running 状态时尝试报告 kRunning，则这将被判定为不允许的迁移 [SWS_EM_02281]。同样，Execution Management 还会监控报告是否及时发生，因为未报告可能导致功能组迁移失败 [SWS_EM_02281]。

时序图：通过 ExecutionClient 发送 kRunning 信号。来源：[SWS_EM_02000]、[SWS_EM_02281]

错误场景

模块内的错误条件由错误域 ExecErrorDomain 映射。函数 GetExecErrorDomain() [SWS_EM_02290] 提供对全局域实例的线程安全且异常安全的引用。函数 MakeErrorCode() [SWS_EM_02291] 用于通过指定错误代码和厂商特定附加数据来生成类型为 ara::core::ErrorCode 的标准化错误对象。

具体的错误原因在枚举 ExecErrc [SWS_EM_02281] 中定义：

  • kNoCommunication（=3）：通信错误，例如在发送请求或检索结果时。如果该错误发生在 Execution Management 和 State Management 之间，则整个系统在某些情况下必须进入不可恢复状态（Unrecoverable State）[SWS_EM_02281]。
  • kInvalidMetaModelIdentifier（=4）：函数调用时元模型标识符无效 [SWS_EM_02281]。
  • kOperationCanceled（=5）：向功能组的状态迁移已被较新的请求中止 [SWS_EM_02281]。
  • kOperationFailed（=6）：请求的操作失败，例如由于未及时报告进程的 kRunning [SWS_EM_02281]。
  • kInvalidTransition（=9）：请求了无效的状态迁移，例如在进程已在运行时再次报告 kRunning [SWS_EM_02281]。
  • kIntegrityOrAuthenticityCheckFailed（=14）：待启动进程的完整性或真实性检查失败 [SWS_EM_02281]。
  • kUnexpectedTermination（=15）：进程在状态迁移期间意外终止 [SWS_EM_02281]。
  • kInvalidArgument（=16）：传递的实参无效 [SWS_EM_02281]。

针对基于异常的错误处理，该模块还提供了异常类 ExecException。

ExecutionState 枚举

Defines the internal states of a Process. Scoped enumeration of uint32_t. Please note that ara::exec::ExecutionState includes only states reportable by the Process to Execution Management and therefore does not include enumerations e.g. the "Initializing" state mentioned in Figure 7.2 and Figure 7.12, which are an implied states for Execution Management. The Initializing state starts when Process is first scheduled (so no code executed yet) and ends when kRunning is reported ([SWS_EM_01004]). The Terminating state starts when termination is requested by Execution Management and ends when the Process terminates ([SWS_EM_01404]). For the reasons mentioned, Execution Management assumes that Process is in initializing state until kRunning will be reported by it.

<h4>上下文</h4>
<p>命名空间 <code>ara::exec</code> 提供 AUTOSAR Adaptive Platform 上 Execution Management 模块的接口。该模块负责进程的生命周期、控制系统启动并监控已配置功能组（<em>Function Groups</em>）的状态迁移。该命名空间的类封装了三个核心参与者之间的交互：应用程序特定进程、中央 Execution Management 和 State Management。</p>
<p>对于进程而言，类 <code>ExecutionClient</code> 用作主要通信通道，已启动的进程通过该通道向 Execution Management 报告其当前执行状态。State Management 通过类 <code>StateClient</code> 访问 Execution Management，以请求功能组（<code>FunctionGroup</code>）与其目标状态（<code>FunctionGroupState</code>）之间定义的状态迁移。如果在功能组运行期间发生执行错误，则通过 <code>ExecutionErrorEvent</code> 以及相应的错误类型 <code>ExecutionError</code> <a class="spec-record-ref" data-req="SWS_EM_02541" href="../spec/record.html?id=SWS_EM_02541">[SWS_EM_02541]</a> 表示该错误。</p>

<h4>生命周期</h4>
<p>进程的生命周期由状态描述，这些状态部分由 Execution Management 隐式管理，部分由进程主动报告 <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。枚举 <code>ExecutionState</code> 仅描述进程可主动向 Execution Management 传输的那些状态。为此定义的唯一状态值是 <code>ExecutionState::kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。</p>
<p>从 Execution Management 的角度来看，进程经历以下阶段：</p>
<ul>
<li><strong>Initializing：</strong>一个隐式状态，该状态在操作系统调度进程（执行应用程序特定代码之前）时开始，并在进程报告 <code>kRunning</code> 时结束 <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。</li>
<li><strong>Running：</strong>成功报告 <code>ExecutionState::kRunning</code> 后的活动执行状态 <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。</li>
<li><strong>Terminating：</strong>另一个隐式状态，该状态在 Execution Management 请求终止进程时启动，并在进程完全结束时结束 <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。</li>
</ul>

<h4>使用路径</h4>
<p>应用程序进程的典型使用路径包括初始化以及随后的就绪状态信号发送。由 Execution Management 启动后，进程执行其内部启动例程。一旦初始化完成且常规工作运行开始，进程将创建 <code>ExecutionClient</code> 的实例并传输状态 <code>ExecutionState::kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02000" href="../spec/record.html?id=SWS_EM_02000">[SWS_EM_02000]</a>。</p>
<p>Execution Management 接收该报告并验证该迁移。如果进程在已处于 <em>Running</em> 状态时尝试报告 <code>kRunning</code>，则这将被判定为不允许的迁移 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。同样，Execution Management 还会监控报告是否及时发生，因为未报告可能导致功能组迁移失败 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</p>

<h4>错误场景</h4>
<p>模块内的错误条件由错误域 <code>ExecErrorDomain</code> 映射。函数 <code>GetExecErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_EM_02290" href="../spec/record.html?id=SWS_EM_02290">[SWS_EM_02290]</a> 提供对全局域实例的线程安全且异常安全的引用。函数 <code>MakeErrorCode()</code> <a class="spec-record-ref" data-req="SWS_EM_02291" href="../spec/record.html?id=SWS_EM_02291">[SWS_EM_02291]</a> 用于通过指定错误代码和厂商特定附加数据来生成类型为 <code>ara::core::ErrorCode</code> 的标准化错误对象。</p>
<p>具体的错误原因在枚举 <code>ExecErrc</code> <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a> 中定义：</p>
<ul>
<li><code>kNoCommunication</code>（=3）：通信错误，例如在发送请求或检索结果时。如果该错误发生在 Execution Management 和 State Management 之间，则整个系统在某些情况下必须进入不可恢复状态（<em>Unrecoverable State</em>）<a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kInvalidMetaModelIdentifier</code>（=4）：函数调用时元模型标识符无效 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kOperationCanceled</code>（=5）：向功能组的状态迁移已被较新的请求中止 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kOperationFailed</code>（=6）：请求的操作失败，例如由于未及时报告进程的 <code>kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kInvalidTransition</code>（=9）：请求了无效的状态迁移，例如在进程已在运行时再次报告 <code>kRunning</code> <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kIntegrityOrAuthenticityCheckFailed</code>（=14）：待启动进程的完整性或真实性检查失败 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kUnexpectedTermination</code>（=15）：进程在状态迁移期间意外终止 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
<li><code>kInvalidArgument</code>（=16）：传递的实参无效 <a class="spec-record-ref" data-req="SWS_EM_02281" href="../spec/record.html?id=SWS_EM_02281">[SWS_EM_02281]</a>。</li>
</ul>
<p>针对基于异常的错误处理，该模块还提供了异常类 <code>ExecException</code>。</p>
