提供标准化接口和类型，以便向 IdsM 报告安全相关事件。

命名空间 ara::idsm 提供了标准化的接口和类型，自适应应用程序可借此以结构化方式向侵入检测系统管理（Intrusion Detection System Management）报告安全事件（[SWS_AIDSM_10205]）。通过 EventReporter 以及时间戳、上下文数据和传输模式的关联 Provider，可以详细记录或筛选记录事件（[SWS_AIDSM_10207]）。当遇到未知事件标识符时，IdsmErrorDomain 提供针对性的错误代码以供进一步处理。

上下文

命名空间 ara::idsm 为入侵检测系统管理（IdsM）提供了 AUTOSAR Adaptive Platform 编程接口。其核心任务是以标准化方式从应用程序进程和平台实例中捕获安全相关事件（Security Events），并将其转发到上级 IdsM。

进行报告的应用程序的主要交互接口由类 EventReporter 构成。该捕获过程由专门的功能接口协同配合：ReportingModeProvider 管理当前传输模式（[SWS_AIDSM_10207]），ContextDataProvider 提供动态随附数据（[SWS_AIDSM_10201]、[SWS_AIDSM_10206]），而 TimestampProvider 提供时间信息（[SWS_AIDSM_10202]）。在接收方，QualifiedEventsReceiver 处理已限定的事件。这些角色的相互配合将自适应应用程序接入面向安全的监控体系中。

上下文图：应用程序组件、ara::idsm 接口与 IdsM 之间的交互。来源：[SWS_AIDSM_10205]、[SWS_AIDSM_10207]

使用路径

用于指示安全事件的典型流程分为：查询报告状态、汇总相关上下文信息以及传输至 EventReporter。

在发出事件之前，应用程序通过 ReportingModeProvider 查询激活的报告模式（[SWS_AIDSM_10207]）。枚举 ReportingModeType 区分了包括禁用传输（kOff）、紧凑报告（kBrief）、详细报告（kDetailed）以及绕过本地筛选规则的模式（kBriefBypassingFilters、kDetailedBypassingFilters）等。如果未禁用报告，应用程序将准备有效数据。类型 EventIdType 的标识符用作事件标识符（[SWS_AIDSM_10205]）。对于深入分析，ContextDataProvider 以字节范围 ContextDataType（[SWS_AIDSM_10201]）或带有版本计数器的版本化对 VersionedContextDataType（[SWS_AIDSM_10206]）的形式提供可变上下文数据。此外，还可以通过 TimestampProvider 包含用于预限定事件的类型 CountType 计数器（[SWS_AIDSM_10203]）以及类型 TimestampType 时间戳（[SWS_AIDSM_10202]）。最后，应用程序将数据传递给 EventReporter。

时序图：用于检查报告状态和传输 Security Event 的调用顺序。来源：[SWS_AIDSM_10201]、[SWS_AIDSM_10205]、[SWS_AIDSM_10207]

错误场景

命名空间 ara::idsm 内的错误操作通过错误领域 IdsmErrorDomain 和错误代码类型 IdsmErrc 进行指示（[SWS_AIDSM_10204]）。为了实现符合标准的错误处理，存在函数 GetIdsmErrorDomain（[SWS_AIDSM_10702]）和 MakeErrorCode（[SWS_AIDSM_10703]），可利用它们以线程安全的方式构造 ara::core::ErrorCode 实例。

一个核心错误场景是使用了未知的事件 ID。在这种情况下，系统报告错误 IdsmErrc::kUnknownEventId（[SWS_AIDSM_10204]）。当调用方传递了 IdsM 未知或未在清单中配置的类型 EventIdType 标识符时，就会发生这种情况。对于带有异常处理的同步接口，此状态由类 IdsmException 呈现。因此，每次成功报告的前提条件是传递的 EventIdType 值与 IdsM 配置相匹配。

      使用与目的
      

      枚举 IdsmErrc 表示 IdsM 错误域的错误代码（头文件 ara/idsm/idsm_error_domain.h），并基于基础类型 ara::core::ErrorDomain::CodeType [SWS_AIDSM_10204]。为了在客户端应用程序中进行紧凑处理，AUTOSAR 提供了类型相同的别名 Errc [SWS_AIDSM_10707]。为了集成到 AUTOSAR Adaptive 的标准化错误处理模型中，提供了函数 MakeErrorCode：它将错误代码与供应商特定的附加数据（SupportDataType）一起以 noexcept 方式转换为 ara::core::ErrorCode 对象 [SWS_AIDSM_10703]。
      


      错误代码与交互
      

      该规范定义了具体的错误值：
      

        

      • kUnknownEventId = 3：指示传入的 eventId 未被 Intrusion Detection System Manager 识别为已配置的安全事件 [SWS_AIDSM_10204]。
        • 

      

      此代码在同步接口中作为错误状态在返回类型 ara::core::Result 内传递。如果寻址了未配置的事件，则无论是通过 GetReportingMode [SWS_AIDSM_10602] 查询报告模式还是通过 SetReportingMode [SWS_AIDSM_10603] 更新报告模式，都会因 IdsmErrc::kUnknownEventId 而失败。Interpretation：鉴于显式分配了值 3，推测值 1 和 2 保留供该域内部使用或将来使用的错误状态。
      


      并发性与限制
      

      用于创建错误对象的辅助函数 MakeErrorCode 是线程安全的（thread-safe），并被标为 constexpr [SWS_AIDSM_10703]。与此相反，返回这些错误状态的 reporting_mode_provider.h 操作函数（GetReportingMode [SWS_AIDSM_10602] 以及 SetReportingMode [SWS_AIDSM_10603]）被显式声明为非线程安全（not thread-safe）。因此，并行调用必须由调用方进行同步。
