为加密服务和密钥管理提供基本类型、错误域和工厂函数。

命名空间 ara::crypto 为 AUTOSAR Adaptive 中的加密服务提供了通用的基本类型、内存缓冲区和全局工厂函数。应用程序通过诸如 LoadCryptoProvider [SWS_CRYPT_20099] 等入口点确定性地创建或获取子系统实例（如加密和密钥存储 Provider）。所有加密操作和密钥使用均通过定义的使用标志以及带有 CryptoErrc [SWS_CRYPT_10099] 的标准化错误域进行严格监控。所有工厂接口均以前置有效的进程映射为条件，并设计为线程安全的。

上下文

命名空间 ara::crypto 构成了 AUTOSAR Adaptive Platform 所有加密服务、密钥管理功能和证书操作的共同基础与中心入口点。该命名空间并未公开底层驱动程序或硬件安全模块的实现细节，而是定义了标准化接口和全局工厂函数。通过这些入口点，应用程序请求专用子系统的实例：通用加密 Provider [SWS_CRYPT_20099]、X.509 Provider [SWS_CRYPT_40099]、对密钥存储槽的读写访问 [SWS_CRYPT_50004] [SWS_CRYPT_50005] 以及用于对象序列化的格式化器 [SWS_CRYPT_50200]。

为了安全且一致地传递数据，ara::crypto 提供了基础内存抽象和类型系统。缓冲区区域通过用于输入数据的 ReadOnlyMemRegion [SWS_CRYPT_10033] 和用于输出数据的 ReadWriteMemRegion [SWS_CRYPT_10031] 进行类型安全封装。算法通过 AlgId [SWS_CRYPT_10014] 或 AlgIdString [SWS_CRYPT_50000] 进行标准化引用，时间戳基于 Timestamp [SWS_CRYPT_50003]。此外，枚举 CryptoObjectType [SWS_CRYPT_10016] 对可存放在密钥存储中的对象类型进行分类，而诸如加密或解密等转换方向由 CryptoTransform [SWS_CRYPT_10019] 预先指定。允许的密钥操作通过 AllowedUsageFlags [SWS_CRYPT_10015] 类型的位掩码进行管理，其中包括加解密 [SWS_CRYPT_13101] [SWS_CRYPT_13102]、签名 [SWS_CRYPT_13103] [SWS_CRYPT_13104]、密钥协商 [SWS_CRYPT_13105] 和导出 [SWS_CRYPT_40991] [SWS_CRYPT_40992]。对于序列化，提供了 FormatId [SWS_CRYPT_10701] 类型的格式标识符，如 kFormatRawValueOnly [SWS_CRYPT_60017]、kFormatDerEncoded [SWS_CRYPT_60018] 和 kFormatPemEncoded [SWS_CRYPT_60019]。

生命周期

核心加密对象的生命周期管理通过全局入口点遵循工厂模式：

  • 实例化与所有权关系：应用程序不通过构造函数手动创建实例。相反，工厂函数 LoadCryptoProvider [SWS_CRYPT_20099]、LoadKeySlot [SWS_CRYPT_50004]、LoadWriteableKeySlot [SWS_CRYPT_50005]、LoadX509Provider [SWS_CRYPT_40099] 和 LoadFormatter [SWS_CRYPT_50200] 以 ara::core::Result<...::Sptr> 的形式返回共享所有权引用。
  • 单例与 Provider 生命周期：函数 LoadX509Provider 提供单例 X.509 Provider 的唯一实例 [SWS_CRYPT_40099]。LoadCryptoProvider 创建或引用通过 ara::core::InstanceSpecifier 建模的加密 Provider 的现有实例 [SWS_CRYPT_20099]。
  • 并发与销毁：所有工厂函数以及错误域辅助函数 GetCryptoErrorDomain [SWS_CRYPT_19952] 和 MakeErrorCode [SWS_CRYPT_19951] 均被指定为异常安全（noexcept）和线程安全（thread-safe）。一旦持有的最后一个共享指针失效，被引用的对象就会自动释放。

使用路径

执行加密操作或管理密钥的典型使用路径包含以下步骤：

  1. 加载 Provider：应用程序使用匹配的 ara::core::InstanceSpecifier 调用 LoadCryptoProvider，以获取对加密操作的访问权限 [SWS_CRYPT_20099]。
  2. 引用密钥槽：对于基于密钥的流程，加载关联的存储空间：通过 LoadKeySlot [SWS_CRYPT_50004] 以只读方式加载，或通过 LoadWriteableKeySlot [SWS_CRYPT_50005] 以写权限加载。
  3. 对象验证与权限检查：在执行之前，应用程序会验证对象类型（CryptoObjectType [SWS_CRYPT_10016]）和配置的使用限制（AllowedUsageFlags [SWS_CRYPT_10015]），例如与 CryptoTransform [SWS_CRYPT_10019] 匹配的 kAllowDataEncryption [SWS_CRYPT_13101] 或 kAllowDataDecryption [SWS_CRYPT_13102]。
  4. 序列化：如果需要格式化或导出密钥对象，则通过 LoadFormatter [SWS_CRYPT_50200] 请求序列化器，只要 kAllowPlaintextExport [SWS_CRYPT_40992] 或 kAllowSecuredExport [SWS_CRYPT_40991] 允许，该序列化器即可支持 DER [SWS_CRYPT_60018] 或 PEM [SWS_CRYPT_60019] 等格式。

错误场景

ara::crypto 中的错误处理基于全局错误域 CryptoErrorDomain [SWS_CRYPT_19952]，其枚举 CryptoErrc [SWS_CRYPT_10099] 定义了所有具体的错误代码：

  • 参数与缓冲区错误：无效参数会导致 kInvalidArgument，未知标识符会导致 kUnknownIdentifier，不匹配的参数组合会导致 kIncompatibleArguments [SWS_CRYPT_10099]。如果 ReadWriteMemRegion [SWS_CRYPT_10031] 的容量不足，接口会发出 kInsufficientCapacity [SWS_CRYPT_10099] 信号。输入大小有误时会出现 kInvalidInputSize [SWS_CRYPT_10099]。
  • 状态与流程违规：在调用顺序错误时，系统会报告 kInvalidUsageOrder [SWS_CRYPT_10099]。如果在初始化之前使用上下文或在完成之前查询计算步骤，则会导致 kUninitializedContext、kProcessingNotStarted 或 kProcessingNotFinished [SWS_CRYPT_10099]。
  • 权限与安全违规：违反 AllowedUsageFlags 中声明的权限的操作会引发 kUsageViolation [SWS_CRYPT_10099]。如果身份验证标签验证失败，则会触发 kAuthTagNotValid [SWS_CRYPT_10099]。
  • 槽与映射错误：空密钥容器或不兼容的密钥容器会导致 kEmptyKeySlot 或 kIncompatibleObject [SWS_CRYPT_10099]。如果 LoadCryptoProvider、LoadKeySlot 或 LoadWriteableKeySlot 处的 InstanceSpecifier 未指向为当前进程建模的 PortPrototype，则这会被视为 ProcessMappingViolation（[SWS_CRYPT_20099]、[SWS_CRYPT_50004]、[SWS_CRYPT_50005]）。

错误实例在程序端通过辅助函数 MakeErrorCode 生成，并且无一例外地引用 CryptoErrorDomain [SWS_CRYPT_19951]。
