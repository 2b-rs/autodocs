上下文

命名空间ara::com构成了 AUTOSAR Adaptive Platform 内 Communication Management 的核心接口。它提供了标准化的抽象层，功能性软件组件通过该层相互交互或与平台服务进行交互EXP_ARAComAPI §1 “Preface”。其目标是将应用程序端组件与底层通信介质的细节解耦，同时允许平台供应商实现优化的 IPC 绑定（Inter-Process Communication）或网络协议EXP_ARAComAPI §1 “Preface”。

用于区分同类服务的是唯一寻址特定服务实例的 InstanceIdentifier，以及作为实例标识符结构化集合的 InstanceIdentifierContainer [SWS_CM_00319]。在动态搜索实例时，系统会生成实例句柄，这些句柄被聚合在 ServiceHandleContainer [SWS_CM_00304] 中，并通过 FindServiceHandler [SWS_CM_00383] 传递给发出请求的软件组件。

上下文图：软件组件、ara::com 运行时与 IPC 绑定的相互作用。来源：EXP_ARAComAPI §1 “Preface”、[SWS_CM_00304]、[SWS_CM_00319]。

生命周期

ara::com 中通信关系的生命周期分为服务可用性、事件订阅状态以及数据样本（Samples）的管理：

  • 服务可用性：所提供服务的状态由包含取值 kAvailable 和 kNotAvailable 的枚举 ServiceState [SWS_CM_01071] 表示。状态变更可通过 ServiceStateHandler [SWS_CM_01072] 进行注册并异步评估。
  • 订阅状态（Subscription State）：参与事件更新遵循 SubscriptionState [SWS_CM_00310] 的生命周期。订阅始于 kNotSubscribed，在发出请求时转入过渡状态 kSubscriptionPending，并在成功建立后切换到 kSubscribed。状态变更通过仿函数 SubscriptionStateChangeHandler [SWS_CM_00311] 通知应用程序。
  • 内存和样本生命周期：待传输数据的内存在发送端通过基于 std::unique_ptr 构建的 SampleAllocateePtr [SWS_CM_00308] 提供。接收到的数据样本作为 SamplePtr 传递给消费者。它模拟一个 std::unique_ptr，并在事件保持订阅期间保证数据的有效性。
  • 方法调用的并发性：对于传入方法调用的处理，枚举 MethodCallProcessingMode [SWS_CM_00301] 控制其行为。可用的方式包括同步轮询（kPoll）、并发事件驱动处理（kEvent）或在单个线程中的顺序处理（kEventSingleThread）。

状态图：通过 SubscriptionState 呈现的事件订阅生命周期。来源：[SWS_CM_00310]、[SWS_CM_00311]。

使用路径

服务消费者与服务提供者之间的典型通信流程包括服务发现、通知注册以及数据接收阶段：

  1. 服务发现：消费者发起对匹配服务的搜索。当有新实例可用时，已注册的 FindServiceHandler [SWS_CM_00383] 将被调用，它会传递包含匹配结果的 ServiceHandleContainer [SWS_CM_00304] 以及用于终止搜索的 FindServiceHandle。
  2. 订阅与回调注册：在所选服务实例上订阅该事件。为了接收有关到达数据的通知，消费者会设置一个 EventReceiveHandler [SWS_CM_00309]。类似地，对于字段通知提供了 FieldReceiveHandler [SWS_CM_11615]，对于触发事件提供了 TriggerReceiveHandler [SWS_CM_00351]。
  3. 数据传输与访问：一旦有新的有效负载数据可用，运行时环境就会触发所设置的接收处理程序 EXP_ARAComAPI §1 “Changed explanation of Event reception”。随后应用程序通过 SamplePtr 实例读取数据。

错误场景

模块 ara::com 中的可恢复错误通过错误域 ComErrorDomain 以及枚举 ComErrc [SWS_CM_10432] 的错误代码来映射 EXP_ARAComAPI §2 “Acronyms and Abbreviations”。标准化错误对象的创建通过辅助函数 MakeErrorCode() [SWS_CM_11335] 进行，而 GetComErrorDomain() [SWS_CM_11334] 则提供对错误域静态实例的访问。

主要错误条件包括：

  • ComErrc::kServiceNotOffered 和 ComErrc::kServiceNotAvailable：如果某服务未通过或不再通过 OfferService() 提供，则方法调用或访问将失败 [SWS_CM_10432]。
  • ComErrc::kInstanceIDNotResolvable：逻辑 InstanceSpecifier 无法解析为具体的 InstanceIdentifier [SWS_CM_10432]。
  • ComErrc::kMaxSamplesExceeded：消费者同时持有的 SamplePtr 实例数量多于 Subscribe() 中指定的数量，这可能导致样本被丢弃 [SWS_CM_10432]。
  • ComErrc::kMaxSampleCountNotRealizable：在重新订阅时，传入的计数与现有订阅不一致 [SWS_CM_10432]。
  • ComErrc::kFieldValueNotInitialized 和 ComErrc::kFieldSetHandlerNotSet：在数据访问之前 Field 元素的初始化不完整 [SWS_CM_10432]。
  • ComErrc::kMinimumSendIntervalViolationError：发送请求违反了在接口部署中配置的最小发送间隔 [SWS_CM_10432]。
  • ComErrc::kCommunicationFailure：底层网络绑定中的错误，或安全通信中的错误 [SWS_CM_10432]。

<h4>上下文</h4>
<p>命名空间<code>ara::com</code>构成了 AUTOSAR Adaptive Platform 内 Communication Management 的核心接口。它提供了标准化的抽象层，功能性软件组件通过该层相互交互或与平台服务进行交互<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=8">EXP_ARAComAPI §1 “Preface”</a>。其目标是将应用程序端组件与底层通信介质的细节解耦，同时允许平台供应商实现优化的 IPC 绑定（Inter-Process Communication）或网络协议<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=8">EXP_ARAComAPI §1 “Preface”</a>。</p>
<p>用于区分同类服务的是唯一寻址特定服务实例的 <code>InstanceIdentifier</code>，以及作为实例标识符结构化集合的 <code>InstanceIdentifierContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00319" href="../spec/record.html?id=SWS_CM_00319">[SWS_CM_00319]</a>。在动态搜索实例时，系统会生成实例句柄，这些句柄被聚合在 <code>ServiceHandleContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00304" href="../spec/record.html?id=SWS_CM_00304">[SWS_CM_00304]</a> 中，并通过 <code>FindServiceHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00383" href="../spec/record.html?id=SWS_CM_00383">[SWS_CM_00383]</a> 传递给发出请求的软件组件。</p>

<h4>生命周期</h4>
<p><code>ara::com</code> 中通信关系的生命周期分为服务可用性、事件订阅状态以及数据样本（Samples）的管理：</p>
<ul>
<li><strong>服务可用性：</strong>所提供服务的状态由包含取值 <code>kAvailable</code> 和 <code>kNotAvailable</code> 的枚举 <code>ServiceState</code> <a class="spec-record-ref" data-req="SWS_CM_01071" href="../spec/record.html?id=SWS_CM_01071">[SWS_CM_01071]</a> 表示。状态变更可通过 <code>ServiceStateHandler</code> <a class="spec-record-ref" data-req="SWS_CM_01072" href="../spec/record.html?id=SWS_CM_01072">[SWS_CM_01072]</a> 进行注册并异步评估。</li>
<li><strong>订阅状态（Subscription State）：</strong>参与事件更新遵循 <code>SubscriptionState</code> <a class="spec-record-ref" data-req="SWS_CM_00310" href="../spec/record.html?id=SWS_CM_00310">[SWS_CM_00310]</a> 的生命周期。订阅始于 <code>kNotSubscribed</code>，在发出请求时转入过渡状态 <code>kSubscriptionPending</code>，并在成功建立后切换到 <code>kSubscribed</code>。状态变更通过仿函数 <code>SubscriptionStateChangeHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00311" href="../spec/record.html?id=SWS_CM_00311">[SWS_CM_00311]</a> 通知应用程序。</li>
<li><strong>内存和样本生命周期：</strong>待传输数据的内存在发送端通过基于 <code>std::unique_ptr</code> 构建的 <code>SampleAllocateePtr</code> <a class="spec-record-ref" data-req="SWS_CM_00308" href="../spec/record.html?id=SWS_CM_00308">[SWS_CM_00308]</a> 提供。接收到的数据样本作为 <code>SamplePtr</code> 传递给消费者。它模拟一个 <code>std::unique_ptr</code>，并在事件保持订阅期间保证数据的有效性。</li>
<li><strong>方法调用的并发性：</strong>对于传入方法调用的处理，枚举 <code>MethodCallProcessingMode</code> <a class="spec-record-ref" data-req="SWS_CM_00301" href="../spec/record.html?id=SWS_CM_00301">[SWS_CM_00301]</a> 控制其行为。可用的方式包括同步轮询（<code>kPoll</code>）、并发事件驱动处理（<code>kEvent</code>）或在单个线程中的顺序处理（<code>kEventSingleThread</code>）。</li>
</ul>

<h4>使用路径</h4>
<p>服务消费者与服务提供者之间的典型通信流程包括服务发现、通知注册以及数据接收阶段：</p>
<ol>
<li><strong>服务发现：</strong>消费者发起对匹配服务的搜索。当有新实例可用时，已注册的 <code>FindServiceHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00383" href="../spec/record.html?id=SWS_CM_00383">[SWS_CM_00383]</a> 将被调用，它会传递包含匹配结果的 <code>ServiceHandleContainer</code> <a class="spec-record-ref" data-req="SWS_CM_00304" href="../spec/record.html?id=SWS_CM_00304">[SWS_CM_00304]</a> 以及用于终止搜索的 <code>FindServiceHandle</code>。</li>
<li><strong>订阅与回调注册：</strong>在所选服务实例上订阅该事件。为了接收有关到达数据的通知，消费者会设置一个 <code>EventReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00309" href="../spec/record.html?id=SWS_CM_00309">[SWS_CM_00309]</a>。类似地，对于字段通知提供了 <code>FieldReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_11615" href="../spec/record.html?id=SWS_CM_11615">[SWS_CM_11615]</a>，对于触发事件提供了 <code>TriggerReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00351" href="../spec/record.html?id=SWS_CM_00351">[SWS_CM_00351]</a>。</li>

<h4>错误场景</h4>
<p>模块 <code>ara::com</code> 中的可恢复错误通过错误域 <code>ComErrorDomain</code> 以及枚举 <code>ComErrc</code> <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a> 的错误代码来映射 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=9">EXP_ARAComAPI §2 “Acronyms and Abbreviations”</a>。标准化错误对象的创建通过辅助函数 <code>MakeErrorCode()</code> <a class="spec-record-ref" data-req="SWS_CM_11335" href="../spec/record.html?id=SWS_CM_11335">[SWS_CM_11335]</a> 进行，而 <code>GetComErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_CM_11334" href="../spec/record.html?id=SWS_CM_11334">[SWS_CM_11334]</a> 则提供对错误域静态实例的访问。</p>
<p>主要错误条件包括：</p>
<ul>
<li><code>ComErrc::kServiceNotOffered</code> 和 <code>ComErrc::kServiceNotAvailable</code>：如果某服务未通过或不再通过 <code>OfferService()</code> 提供，则方法调用或访问将失败 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kInstanceIDNotResolvable</code>：逻辑 <code>InstanceSpecifier</code> 无法解析为具体的 <code>InstanceIdentifier</code> <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kMaxSamplesExceeded</code>：消费者同时持有的 <code>SamplePtr</code> 实例数量多于 <code>Subscribe()</code> 中指定的数量，这可能导致样本被丢弃 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kMaxSampleCountNotRealizable</code>：在重新订阅时，传入的计数与现有订阅不一致 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kFieldValueNotInitialized</code> 和 <code>ComErrc::kFieldSetHandlerNotSet</code>：在数据访问之前 Field 元素的初始化不完整 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kMinimumSendIntervalViolationError</code>：发送请求违反了在接口部署中配置的最小发送间隔 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
<li><code>ComErrc::kCommunicationFailure</code>：底层网络绑定中的错误，或安全通信中的错误 <a class="spec-record-ref" data-req="SWS_CM_10432" href="../spec/record.html?id=SWS_CM_10432">[SWS_CM_10432]</a>。</li>
</ul>
