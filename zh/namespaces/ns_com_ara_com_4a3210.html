为 AUTOSAR Adaptive 中的面向服务的通信提供基类型、错误域和接口。

该命名空间通过 Proxy 连接服务使用者并通过 Skeleton 连接服务提供者（ARAComAPI §7.6 “meta-model to Implementation”），为面向服务的通信提供核心构件。交互包括异步服务搜索、通过 Future 返回的方法调用，以及通过定义状态进行的事件订阅（[SWS_CM_00310]）。核心职责包括正确解析实例标识符，以及遵守配置的样本配额与发送间隔（[SWS_CM_10432]）。

上下文

命名空间 ara::com 为 AUTOSAR Adaptive Platform 内的面向服务的通信（Communication Management）提供核心类型与机制。架构模型严格区分服务使用者与服务提供者：在使用者端（R-Port），客户端应用程序通过生成的 Proxy 实例进行交互（ARAComAPI §7.6 “meta-model to Implementation”），而服务提供者在服务器端通过 Skeleton 实现公开其功能（ARAComAPI §6.2 “Definition of BatteryState”）。

技术中间件（Binding）在 Proxy 与 Skeleton 之间进行调解。InstanceIdentifier 用于识别和区分各个服务实例，并通过 InstanceIdentifierContainer 管理具体实例的集合（[SWS_CM_00319]）。该平台支持多绑定场景，在这些场景中，抽象模型标识符被解析为技术 Binding 和实例的列表（ARAComAPI §6.6 “InstanceIdentifier Resolution”）。

上下文图：服务通信中 Proxy、中间件 Binding 与 Skeleton 之间的相互协作。来源：ARAComAPI §7.6 “meta-model to Implementation”、ARAComAPI §6.6 “InstanceIdentifier Resolution”、[SWS_CM_10432]。

生命周期

在 ara::com 中，服务和通信连接遵循明确定义的状态模型。常规服务可用性通过具有值 kAvailable 和 kNotAvailable 的枚举 ServiceState 表示（[SWS_CM_01071]）。可通过已注册的 ServiceStateHandler 监控状态变化（[SWS_CM_01072]）。

对于事件（Event）和字段，SubscriptionState 控制具有状态 kNotSubscribed、kSubscriptionPending 和 kSubscribed 的订阅生命周期（[SWS_CM_00310]）。状态转换被异步报告给 SubscriptionStateChangeHandler（[SWS_CM_00311]）。从 kNotSubscribed 到 kSubscriptionPending 的转换推测是通过向底层传输 Binding 发送订阅请求而立即发生的。

在服务实现端，MethodCallProcessingMode 控制传入方法调用的并发性：kPoll 用于手动轮询，kEvent 用于并发、事件驱动的处理，而 kEventSingleThread 用于单线程中的顺序处理（[SWS_CM_00301]）。样本管理（Samples）在发送端使用 SampleAllocateePtr 来优化分配（例如通过共享内存的零拷贝方法）（[SWS_CM_00308]、ARAComAPI §6.18 “Event Allocate/Send sample Binding implementer hint”），在接收端使用 SamplePtr（[SWS_CM_10432]）。

使用路径

使用服务的典型流程包括以下步骤：

  1. 服务搜索：使用者启动对兼容服务实例的搜索。在可用时，中间件通过 FindServiceHandler 传递包含已找到句柄的 ServiceHandleContainer，以及可用于停止正在运行的搜索的 FindServiceHandle（[SWS_CM_00383]、[SWS_CM_00304]）。
  2. Proxy 实例化：使用匹配的句柄在客户端本地创建 Proxy 实例（ARAComAPI §6.3 “Handling of optional data elements on Skeleton side”）。
  3. 方法调用：方法调用重载方法包装器类的括号运算符。传递输入参数，且调用返回一个封装输出参数的 ara::com::Future（ARAComAPI §6.10 “Adjust Method Class”、ARAComAPI §6.12 “Adjust Method Class”）。
  4. 结果处理：客户端同步或异步获取结果（例如通过 get()），并在访问可选字段元素前检查其是否存在（ARAComAPI §6.3 “Handling of optional data elements on Skeleton side”）。
  5. 事件接收：已订阅 Event、字段或触发器的传入数据通过已注册的回调进行处理，例如 EventReceiveHandler（[SWS_CM_00309]）、FieldReceiveHandler（[SWS_CM_11615]）或 TriggerReceiveHandler（[SWS_CM_00351]）。

时序图：从服务搜索经由带 Future 的方法调用到结果获取的调用顺序。来源：[SWS_CM_00383]、[SWS_CM_00304]、ARAComAPI §6.3 “Handling of optional data elements on Skeleton side”、ARAComAPI §6.10 “Adjust Method Class”。

错误场景

通信子系统中的错误条件通过 ComErrorDomain 和 ComErrc 中的错误代码进行映射（[SWS_CM_10432]）。通过 GetComErrorDomain() 访问域（[SWS_CM_11334]），而具体错误通过 MakeErrorCode()（[SWS_CM_11335]）实例化。在异常情况下抛出 ComException。

典型的错误场景包括：

  • 服务可用性：对未提供服务的调用会导致 ComErrc::kServiceNotOffered 或 ComErrc::kServiceNotAvailable（[SWS_CM_10432]）。
  • 配置与实例解析错误：若标识符无法映射到 InstanceIdentifier，系统会报告 ComErrc::kInstanceIDNotResolvable（[SWS_CM_10432]、ARAComAPI §6.6 “InstanceIdentifier Resolution”）。
  • 资源与订阅限制：若应用程序持有的 SamplePtr 实例多于在 Subscribe() 中约定的数量，则会发生 ComErrc::kMaxSamplesExceeded（[SWS_CM_10432]）。若重新订阅时最大样本数量出现偏差，会导致 ComErrc::kMaxSampleCountNotRealizable（[SWS_CM_10432]）。
  • 协议与时序条件：发生网络错误或安全通信错误时，报告 ComErrc::kCommunicationFailure。若低于发送间隔，传输将以 ComErrc::kMinimumSendIntervalViolationError 失败（[SWS_CM_10432]）。
  • 字段处理：未初始化的字段值会导致 ComErrc::kFieldValueNotInitialized，缺失的 Set-Handler 会导致 ComErrc::kFieldSetHandlerNotSet（[SWS_CM_10432]）。

根据 [SWS_CM_10432]，枚举 ComErrc 针对符合 EXP ARAComAPI §2 “Recoverable Errors” 的可恢复错误（Recoverable Errors）定义了 ara::com::ComErrorDomain 的标准化错误代码。它在通信管理的同步和异步 API 的返回类型（如 ara::core::Result 或 ara::core::Future）中传输，以在客户端或服务器上下文中精确指示功能错误原因。

枚举项涵盖了服务生命周期和数据传输过程中的特定错误情况：

  • 服务生命周期与绑定：kServiceNotOffered 表示服务尚未通过 OfferService() 提供（[SWS_CM_00101]），而 kServiceNotAvailable 则指示其在此期间丢失。当无法解析 InstanceSpecifier 时，将发生 kInstanceIDNotResolvable（[SWS_CM_00118]）。
  • 事件与样本订阅：kMaxSamplesExceeded 针对超出承诺的 SamplePtr 配额发出警告，而 kMaxSampleCountNotRealizable 在通过 [SWS_CM_00141] 重新订阅时报告不匹配的值。
  • 字段与传输：kFieldValueNotInitialized 指示在 Update() 之前缺少初始化（[SWS_CM_00119]），kFieldSetHandlerNotSet 指示缺少 setter 处理器。本地网络问题（例如在通过 [SWS_CM_00721] 发送触发时）会导致 kCommunicationFailure（[SWS_CM_10517]）。此外，kMinimumSendIntervalViolationError 针对时钟速率违规进行处理，kUnknownApplicationError 则针对意外的服务器错误进行处理（[SWS_CM_10432]）。

作为纯枚举类型，ComErrc 没有自身的状态；因此，在调用线程中对错误值的读取和比较操作应该是并发安全的。实际的错误检查由应用程序在评估相应结果对象后负责。
