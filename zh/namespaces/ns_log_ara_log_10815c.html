支持创建日志记录上下文、格式化消息流和客户端状态监控。

命名空间 ara::log 通过管理上下文记录器并将消息流类型化输出到 DLT 后端或控制台等接收器，提供自适应日志记录服务 [SWS_LOG_00021]。应用程序通过工厂函数获取记录器，通过参数包装器准备格式化有效负载，并将数据线程安全地送入日志消息。作为一项重要约束条件，所有记录器实例的所有权仍归框架所有，而连接状态处理程序的注册显式为非线程安全 [SWS_LOG_00205]。

上下文

命名空间 ara::log 为自适应应用程序提供中央日志记录基础设施。其核心职责包括通过类 Logger 管理日志记录上下文、通过 LogStream 结构化生成日志消息，以及通过 Argument 和 Format 类型化传递格式化有效负载。该框架充当应用程序端日志调用与目标接收器之间的纽带：DLT 后端（Diagnostic Log and Trace）用作主要接收器，其连接状态通过枚举 ClientState 表示 [SWS_LOG_00098]。如果无可用模型，控制台默认用作接收器 [SWS_LOG_00021]。外部对端的状态变化可以通过类型为 ConnectionStateHandler 的回调函数进行监控 [SWS_LOG_00265]。

上下文图：日志框架在应用程序、控制台、DLT 后端与外部客户端之间的交互伙伴。来源：[SWS_LOG_00021]、[SWS_LOG_00098]、[SWS_LOG_00205]。

生命周期

Logger 的实例不直接由应用程序构造，而是通过工厂函数 CreateLogger 实例化并在日志框架中注册 [SWS_LOG_00021]、[SWS_LOG_00263]。所有权关系已明确定义：所有权完全保留在日志框架内（“Ownership stays within the Logging framework”），该框架向调用方返回引用（Logger&）[SWS_LOG_00021]。或者，可以基于 ara::core::InstanceSpecifier 按照模型进行创建 [SWS_LOG_00256]。解释：由于框架保留所有权，已注册记录器的生命周期应当绑定到上级进程。

在并发性方面，通过 CreateLogger 创建记录器被指定为线程安全 [SWS_LOG_00021]。相比之下，通过 RegisterConnectionStateHandler 注册连接状态处理程序显式为非线程安全（“not thread-safe”）[SWS_LOG_00205]；因此，它通常必须在初始化阶段、并发活动启动之前完成。此外，始终只能有一个处理程序处于活动状态；重新注册会立即替换先前的回调 [SWS_LOG_00205]。外部对端的连接生命周期经历阶段 kUnknown（DLT 后端尚未激活）、kNotConnected 和 kConnected [SWS_LOG_00098]。

使用路径

常规流程包括配置监控、获取记录器和格式化消息输出：

  • 通过 RegisterConnectionStateHandler 注册连接回调 [SWS_LOG_00205]。
  • 通过 CreateLogger 获取 Logger 引用，需指定上下文 ID、描述以及可选的来自 LogLevel 的默认严重级别（例如 kWarn 或 kInfo）[SWS_LOG_00018]、[SWS_LOG_00021]。
  • 通过 Arg 创建结构化参数，并附带标识符、单位和格式化提示 [SWS_LOG_00201]。为此提供了辅助函数如 Dflt [SWS_LOG_00208]、整型格式如 Dec [SWS_LOG_00211]、Hex [SWS_LOG_00209]、Bin [SWS_LOG_00215] 和 Oct [SWS_LOG_00213]，以及浮点格式如 DecFloat [SWS_LOG_00217]、EngFloat [SWS_LOG_00219]、HexFloat [SWS_LOG_00221] 或 AutoFloat [SWS_LOG_00223]，这些函数封装了来自 Fmt 的说明符 [SWS_LOG_00206]。
  • 通过重载运算符 operator<< 将有效负载传输至 LogStream 中，包括用于 LogLevel [SWS_LOG_00063]、ara::core::ErrorCode [SWS_LOG_00124]、std::chrono::duration [SWS_LOG_00125]、ara::core::InstanceSpecifier [SWS_LOG_00126] 和指针 const void* [SWS_LOG_00127] 的重载。

时序图：初始化、记录器创建以及通过 LogStream 输出格式化数据时的典型交互序列。来源：[SWS_LOG_00021]、[SWS_LOG_00063]、[SWS_LOG_00124]、[SWS_LOG_00201]、[SWS_LOG_00205]。

错误场景

该命名空间的函数大部分声明为 noexcept 并提供 no-throw 保证，但受严格的前置条件和违规规则约束：

  • 清单违规：通过 CreateLogger(const ara::core::InstanceSpecifier&) 基于模型创建记录器时，可能会触发特定的运行时违规：InstanceSpecifierMappingIntegrityViolation（说明符无法在模型中解析或未指向 PortPrototype）、PortInterfaceMappingViolation（映射类型与预期的 PortInterface 不匹配）、ProcessMappingViolation（未找到匹配的进程）以及 InstanceSpecifierAlreadyInUseViolation（说明符已在进程中使用）[SWS_LOG_00256]。
  • 无效参数类型化：如果类型 T 既不是算术类型也不是 bool，并且既不能转换为 ara::core::StringView 也不能转换为 ara::core::Span<const ara::core::Byte>，则调用 Arg 在句法上是不合法的（“ill-formed”）。同样，在字符串、字节范围或布尔类型中传递不同于 nullptr 的单位文本 unit 会导致错误 [SWS_LOG_00201]。
  • 错误表示：将 core::ErrorCode 实例输出到控制台时，错误代码按实现定义的方式进行格式化，其中必须包含域名（ErrorCode::Domain().Name()）和整型错误编号 [SWS_LOG_00124]。

枚举 ara::log::ClientState 表示外部客户端到 DLT 后端的当前连接状态 [SWS_LOG_00098]。它基于数据类型 std::int8_t，并通过头文件 #include "ara/log/common.h" 或转发头文件 #include "ara/log/log_fwd.h" 包含 [SWS_LOG_00098]。

状态与语义

该枚举定义了三种离散的连接状态 [SWS_LOG_00098]：

  • kUnknown (-1)：DLT 后端尚未准备就绪；此时无法确定实际的连接状态 [SWS_LOG_00098]。
  • kNotConnected：未检测到外部客户端[SWS_LOG_00098]。
  • kConnected：远程客户端已成功连接[SWS_LOG_00098]。

协同交互与并发性

该枚举主要用作函数回调ConnectionStateHandler（定义为std::function<void(ClientState)>）的传递参数，该回调通过ara::log::RegisterConnectionStateHandler注册[SWS_LOG_00265]。该处理程序被声明为线程安全的[SWS_LOG_00265]。解释：一旦 DLT 后端检测到外部客户端的状态变化，已注册的处理程序可能会被异步调用。
