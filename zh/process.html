出版流程

本页描述了 AUTOSAR Adaptive Platform API 参考的完整流程：从领先的规范记录，通过翻译和图表，到 HTML 输出、验证、报告和可追溯性。它针对的是管理者、维护者和人工智能代理。操作代理指令（如AGENTS.md）本身作为独立的管道工件进行维护，具有自己的管理和审查生命周期，并在此处引用。

1. 概述

该管道遵循确定性分层模型：规范数据库 → 管理和审核 → i18n 细分 → 图表翻译 → HTML 生成 → 验证 → 报告和可追溯性。每个出版物都是根据_src/下定义的来源可重复创建的。

2. 真相来源和文物类别

文件结构严格区分权威来源、托管管道工件和临时构建产品：

  • 事实来源（相关）： _src/spec/records/**/*.json（规范记录）以及_src/spec/namespaces.json和_src/spec/projects.json等目录。所有内容更改都必须在此处进行。
  • 管道工件（版本化/策划）：_src/sources/pages/下的页面模型、审核和策划队列、i18n寄存器（_src/i18n/）、图表源（.dot、.seq.json）和代理指令（例如AGENTS.md）。
  • 生成的构建工件（一次性）：整个HTML树（index.html、classes/、namespaces/、modules/、services/）和所有本地化语言树（en/、 es/、pt/、fr/、ru/、ar/、hi/、ko/、zh/、nl/）。
  • 工作和缓存产品： PDF缓存 (_src/spec/pdf-cache/)、output/，以及output/run-archive/的执行和日志存档。

3.1 审核和反馈流程

该平台提供了两个独立的、明确定义的交互路径，用于质量保证和纠正：

策展人决策日志 (review.js)

供授权策展人和审稿人直接在需求面板上批准（accept）或拒绝（reject）不清楚的提取候选者。

流程：决策在浏览器的本地数据包中收集，然后作为结构化 GitHub 问题提交。摄取后，决策将直接应用于数据集。

审核标记申请流程 (review_request.js)

让所有网站访问者报告已发布数据集中的差异、过时的来源或缺失的上下文。

流程：请求创建不可变队列任务。人工智能代理分析线索并准备建议；最终决定权始终在于人类策展人。

存储、身份和数据保护

两个进程都在浏览器中高效地运行数据并隔离（localStorage）：

  • ara-review-package-v1：缓存收集的 Curator 面板共享。
  • ara-review-github-token-v1：可选的 GitHub 令牌，用于经过身份验证的提交（在两个对话框之间重复使用）。
  • ara-review-identity：为未经身份验证的提交自行选择的名称。
  • 没有 cookie，没有跟踪，也没有服务器端存储不完整的表单数据。

4. 多语言（i18n）：提取、翻译和合并

国际化通过确定性的 JSONL 管道进行：

  1. 提取： python3 _src/i18n_extract.py 从规范的德语源中提取所有新的和更改的文本片段，并为其分配稳定的 ID。
  2. 翻译：将片段翻译成 10 种目标语言（en、es、pt、fr、ru、ar、hi、ko、zh、nl）。代码片段、标识符和占位符标记保持受保护且不变。
  3. 合并： _src/i18n_translate.py merge 将翻译片段与源清单合并，并报告缺失或不完整的翻译。

未翻译的片段会自动回退到生成的语言树中的原始德语版本。

5. 图表翻译

图表是从 .dot 和 .seq.json 源生成的。其中包含的标签像普通文本一样被提取，在构建过程中以特定于语言的方式翻译并插入到生成的图表中。这意味着所有图表都以所有 10 种语言一致可用。

6.HTML一代

_src/generate.py生成器将页面模型（_src/sources/pages/*.json）和规范记录转换为静态HTML页面。为每种语言生成一个完整的、独立的HTML树。呼叫是通过以下方式进行的：

python3 _src/generate.py --lang=all

7. 验证和质量检查

在发布之前，_src/validate.py检查整体结果的一致性：

  • 检查所有内部和外部链接和锚点。
  • 检查是否有孤立页面或丢失的引用。
  • 验证命名空间成员身份和签名一致性。
  • 控制i18n完整性并检测无意的语言混合。

0 以外的退出代码会阻止发布步骤并强制纠正底层源。

9. 错误处理和指南

偏差、验证错误或翻译差距可能永远不会直接在生成的 HTML 中进行修补。错误修复始终在权威源级别（_src/spec/或_src/sources/pages/）完成，然后进行完整的重建和验证。翻译批次中的拒绝必须由管理团队检查并重新提交。
