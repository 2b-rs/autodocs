系统架构与模块集群的角色

该集群仅包含一个模块，即 Runtime Environment（Rte）。它在每个 ECU 上实现 ECU 配置所指定的通信路径。在此过程中，它还实现了来自组件描述的通信属性的语义 [SWS_Rte_02200] [SWS_Rte_02201]。RTE 针对每个 ECU 单独配置和生成 [SWS_Rte_05000] [SWS_Rte_01316]。生成器产生必须符合 MISRA C 的 C 代码 [SWS_Rte_01167] [SWS_Rte_01168]。ECU 架构图展示了 RTE 在应用软件与基础软件之间的位置（SWS RTE 第113页）。

在下层，RTE 仅使用标准化的 AUTOSAR 服务，其中包括 OS、COM、LdCom 和 Transformer [SWS_Rte_02250]。生成物中还包括 Basic Software Scheduler (SchM)。它负责 BSW 模块的调度、模式、触发器和 Exclusive Areas。为此，方法论规定了一个独立的生成步骤，仅生成调度器代码（TR Methodology 第463页）。

生成器将生成的 RTE 本身描述为一个 BSW 模块。这包括 BswModuleDescription、BswInternalBehavior 和 BswImplementation [SWS_Rte_05165] [SWS_Rte_05166] [SWS_Rte_05167]。Rte 和 SchM 的生命周期 API 在其中显示为 BswModuleEntry [SWS_Rte_05177]。核心接口文件包括：

  • Rte.h [SWS_Rte_01157] 以及生命周期头文件 Rte_Main.h [SWS_Rte_01158]，
  • 包含类型声明的 Rte_Type.h [SWS_Rte_01161]，
  • 每个组件类型的 Application Header Rte_[Byps_]<name>.h [SWS_Rte_01003]，
  • 包含回调原型的 Rte_Cbk.h [SWS_Rte_03796]。

上下文图：RTE 在 SW-C 与 BSW 服务 OS、IOC、COM、LdCom、NvM（通过 NvBlockSwComponentType）以及 BndM 之间进行协调。BSW 调度器属于同一生成物。来源：[SWS_Rte_02250]、[SWS_Rte_03001]、[SWS_Rte_01377]、[SWS_Rte_03884]、SWS RTE 第259页、SWS OS 第128页

协作与交互路径

一个 SW-C 由多个 RunnableEntity 组成。RTE 根据关联的 RTEEvent 启动它们 [SWS_Rte_02202] [SWS_Rte_02203]（SWS RTE 第119页）。

对于 Sender-Receiver 通信：

  • 缓冲区：在接收方进行缓冲 [SWS_Rte_02515]。
    • “data”（非排队）遵循 last-is-best：新值覆盖旧值 [SWS_Rte_02516] [SWS_Rte_02520]。
    • “events”进入 FIFO 队列 [SWS_Rte_02521] [SWS_Rte_02522]。当缓冲区满时，丢弃新事件并设置错误标志 [SWS_Rte_02523]。应用程序将其视为 RTE_E_LOST_DATA [SWS_Rte_02571]。
  • 访问方式：
    • 在隐式读取中，RTE 在 Runnable 启动前提供一份副本，该副本在执行期间保持不变 [SWS_Rte_06000] [SWS_Rte_06001] [SWS_Rte_06004]。
    • Runnable 通过 Rte_Read、Rte_Receive 和 Rte_Send 进行显式访问 [SWS_Rte_01091] [SWS_Rte_01092] [SWS_Rte_01072]。
    • Runnable 通过 Rte_IWrite [SWS_Rte_03744] 进行隐式写入。

通过 COM 进行的 ECU 间通信：

  • RTE 通过信号组以原子方式传输复合数据 [SWS_Rte_04527] [SWS_Rte_03008]（SWS RTE 第326页）。
  • COM 通过 Rte_COMCbk_<sn> [SWS_Rte_03530] [SWS_Rte_03001] 等回调报告事件。这些回调激活 Runnable 或在等待点唤醒第 2 类 Runnable [SWS_Rte_03531] [SWS_Rte_03532]。
  • 数值过滤器在 ECU 间通信中运行于 COM，在 ECU 内部通信中运行于 RTE [SWS_Rte_05500]。
  • 版本差异：在 R20-11 中，[SWS_Rte_04505] 要求 ComHandleId。而较新的文档段落则称其为 Com Symbolic Name（SWS RTE 第324页）。

通过 LdCom 的大字节数组：

  • 在 R20-11 中，RTE 通过 LdCom 以及 LdCom_Transmit [SWS_Rte_01376] [SWS_Rte_01377] [SWS_Rte_01378] 发送和接收大字节数组。
  • 在 TP 传输时，RTE 会锁定信号缓冲区直至收到确认 [SWS_Rte_01379] [SWS_Rte_01380]（SWS RTE 第350页）。
  • 版本差异：R25-11 中的出处则描述了带有 Com_Transmit 的“Large Data Path in COM”（SWS RTE 第343页）。对于 R20-11，适用 LdCom。

客户端-服务器通信：

  • 客户端通过 Rte_Call 进行同步或异步调用 [SWS_Rte_01102] [SWS_Rte_01293] [SWS_Rte_01294]。它们通过 Rte_Result 获取异步结果 [SWS_Rte_01111]。
  • 若该调用不是直接函数调用，RTE 将在服务端将请求缓冲在 FIFO 队列中，并在客户端将响应缓冲在长度为 1 的队列中 [SWS_Rte_02527] [SWS_Rte_02528]。它通过请求队列将服务器访问串行化 [SWS_Rte_02530]。
  • 无论采用何种接收模式，RTE 都会监控超时 [SWS_Rte_03763]（SWS RTE 第358页）。

其他路径：

  • SW-C 的 NvM 请求由 NvBlockSwComponentType 的 Runnable 转发给 NvM（SWS RTE 第259页）。NvM API 的返回值由 [SWS_Rte_04535] 规定。
  • RTE 通过 BndM 读取 Bulk-NvData [SWS_Rte_03883] [SWS_Rte_03884]。
  • 在核心之间，Rte_Call 写入 IOC 并激活目标核心上的服务器任务（SWS OS 第128页）。在 IOC 回调中，RTE 不执行任何 ExecutableEntities，并且它会阻止对同一 IOC API 的并发访问 [SWS_Rte_02736] [SWS_Rte_02737]。

同步、重入性与任务上下文

执行上下文：

  • Runnable 在 OS 任务或 ISR2 的上下文中运行（SWS RTE 第119页）。在同一个任务内，RTE 保持配置的执行顺序 [SWS_Rte_02207]。
  • 第 1 类中断不得到达 RTE。生成器会拒绝相应的配置 [SWS_Rte_03594]（SWS RTE 第182页）。
  • ISR2 可以通过外部触发器激活 ExecutableEntities [SWS_Rte_04564]。相反，RTE 不允许 SW-C 的 Runnable 在中断上下文中运行 [SWS_Rte_03600]。
  • RTE 的回调不得阻塞 [SWS_Rte_01165]。
  • 在 Runnable 执行后是否调用 Schedule，由 [SWS_Rte_05113] 至 [SWS_Rte_05115] 规定。

数据一致性：RTE 保证通过 AUTOSAR 接口进行的通信 [SWS_Rte_03514] 以及 InterRunnableVariables [SWS_Rte_03516] 的一致性。

  • 对于隐式 InterRunnableVariables，它避免并发访问。对于显式 InterRunnableVariables，它阻塞竞争访问 [SWS_Rte_03517] [SWS_Rte_03519]（SWS RTE 第207页）。
  • Exclusive Areas 通过 Rte_Enter 和 Rte_Exit 进行进入与退出 [SWS_Rte_03515] [SWS_Rte_01120] [SWS_Rte_01123]。不同的 Area 允许嵌套 [SWS_Rte_01122]。
  • 保护机制由 RteExclusiveAreaImplMechanism 选择：ALL_INTERRUPT_BLOCKING [SWS_Rte_03504]、OS_INTERRUPT_BLOCKING [SWS_Rte_05164]、OS_RESOURCE [SWS_Rte_03595] 或 NONE [SWS_Rte_03999]。
  • 若 Runnable 在 Exclusive Area 内调用阻塞 API，该 API 将返回 RTE_E_IN_EXCLUSIVE_AREA [SWS_Rte_02739]。

重入性：

  • 仅当设置了 canBeInvokedConcurrently 时，才允许并发激活同一个 Runnable 实例 [SWS_Rte_03523] [SWS_Rte_05083]。
  • RTE 仅通过代码共享支持多实例 [SWS_Rte_03015] [SWS_Rte_02002]。实例通过 Instance Handle 进行标识，Entry Point 将其作为第一个参数接收 [SWS_Rte_01016] [SWS_Rte_02015]。
  • 由于实例是独立调度的，Entry Point 应当是可重入的（SWS RTE 第804页）。

多核与分区系统：在此，[SWS_Rte_02711] 限制了 Rte.c 中的全局变量。此外，[SWS_Rte_02712] 要求独立的文件 Rte_Partition_<PartitionName>。

生命周期与运行模式

BSW 调度器的启动：

  • 在其初始化之前，仅 SchM_Enter 和 SchM_Exit 可用（SWS RTE 第400页）。
  • SchM_Start 始终生成，在有限时间内返回，并且必须在 BswM_Init() 之前调用 [SWS_Rte_04546] [SWS_Rte_04547] [SWS_Rte_04548]（SWS RTE 第927页）。
  • SchM_StartTiming 启动周期性事件，并以先前已执行 SchM_Init 为前提条件 [SWS_Rte_04549] [SWS_Rte_04550] [SWS_Rte_04551]。
  • 所有这三个调用均由 EcuM 在每个核心上恰好执行一次（SWS RTE 第928页）。

RTE 的启动：

  • 当 OS 可用且所有 BSW 模块均已初始化时，EcuM 在 Startup-Phase II 结束时调用 Rte_Start [SWS_Rte_02569] [SWS_Rte_02585]（SWS RTE 第460页）。
  • 若资源分配失败，Rte_Start 返回 RTE_E_LIMIT，否则返回 RTE_E_OK [SWS_Rte_01261] [SWS_Rte_01262]（SWS RTE 第806页）。
  • 初始值保护接收者免受未初始化数据的影响 [SWS_Rte_06009] [SWS_Rte_06010] [SWS_Rte_02517]。

关闭与分区重启：

  • Rte_Stop 在 Shutdown-Phase I 开始时执行 [SWS_Rte_02570] [SWS_Rte_02584]。若无法释放资源，该函数将报告 RTE_E_LIMIT [SWS_Rte_01260]。
  • 此后，RTE 在该核心上不再激活任何 Runnable [SWS_Rte_02538]。
  • 在完全初始化之前以及停止之后，RTE 忽略传入的客户端-服务器请求以及发送者-接收者数据 [SWS_Rte_02535] [SWS_Rte_02536]（SWS RTE 第461页）。BSW 调度器的行为与之类似 [SWS_Rte_04552]。
  • 在分区重启时，RTE 恢复初始环境 [SWS_Rte_02735]。

时序图：每个核心上 BSW 调度器和 RTE 的启动与关闭，由 EcuM 控制。推断：SchM_Init 与 SchM_Start 的先后顺序并无明确凭据。来源：[SWS_Rte_04546]、[SWS_Rte_04549]、[SWS_Rte_02569]、[SWS_Rte_02570]、[SWS_Rte_02538]、SWS RTE 第400页、SWS RTE 第460页

模式管理：

  • RTE 维护每个 Mode Machine Instance 的活动模式 [SWS_Rte_02546]，并在初始化时启动向初始模式的转换 [SWS_Rte_02544]（SWS RTE 第433页）。
  • Mode Manager 通过 Rte_Switch 请求切换 [SWS_Rte_02631]。通知进入每个实例的 FIFO 队列 [SWS_Rte_02718] [SWS_Rte_02719]。
  • 当队列已满时，丢弃新通知 [SWS_Rte_02720]。在分区之间，RTE 随后会报告 RTE_E_LIMIT [SWS_Rte_02675]。仅在切换完成后，它才会从队列中移除该通知 [SWS_Rte_02721]。
  • [SWS_Rte_02665] 将转换本身划分为十个步骤（EXP ModeManagementGuide 第15页）：
    1. 激活 Mode Disablings [SWS_Rte_02661]。
    2. 执行 On-exit-Entities [SWS_Rte_02562]。
    3. 执行 On-transition-Entities [SWS_Rte_02707] [SWS_Rte_02708]。
    4. 执行 On-entry-Entities [SWS_Rte_02564]。
    5. 切换 Mode Disablings [SWS_Rte_02563]。
    6. 触发 ModeSwitchedAckEvent [SWS_Rte_02587]。
  • 在模式切换时正在运行的 Runnable 不会被中止 [SWS_Rte_02504]。切换到相同模式的操作也会完整执行 [SWS_Rte_02669]。
  • Mode Manager 通过 Rte_SwitchAck 查询确认信息 [SWS_Rte_02725]。
  • 此外，模式还可以激活 OS Schedule Tables [SWS_Rte_05146]。

活动图：模式切换请求被排入队列，若队列已满则被丢弃。随后它经历按序排列的转换步骤直至确认。来源：[SWS_Rte_02665]、[SWS_Rte_02718]、[SWS_Rte_02720]、[SWS_Rte_02721]、[SWS_Rte_02587]、EXP ModeManagementGuide 第15页

错误处理、跟踪与降级

SW-C 仅通过类型为 Std_ReturnType 的 RTE API 返回值获取错误状态 [SWS_Rte_01034]（SWS RTE 第579页）。该规范区分了三个错误类别：

  • Immediate Infrastructure Errors 会覆盖应用程序错误 [SWS_Rte_02593]。
  • Overlayed Errors 使用单独的一位，并且可以与其他错误组合 [SWS_Rte_01318]（SWS RTE 第686页）。
  • 应用程序错误占用低 6 位 [SWS_Rte_02573]。

降级：

  • 对于未连接的端口，RTE 定义了固定行为 [SWS_Rte_01329] [SWS_Rte_01330]。Rte_Call 随后会报告 RTE_E_UNCONNECTED [SWS_Rte_01334]。
  • 发送者通过 Rte_Invalidate 使数据失效 [SWS_Rte_01206]，该功能通过 handleInvalid 启用 [SWS_Rte_05024]。在 ECU 内部，RTE 自行实现失效处理 [SWS_Rte_05025]：
    • 对于 keep，它将接收视为错误 [SWS_Rte_05030]。
    • 对于 replace，它将无效值替换为 initValue [SWS_Rte_05049]。
  • 无效值会导致 RTE_E_INVALID [SWS_Rte_02626]。在范围检查激活时，超出范围的值会导致 RTE_E_OUT_OF_RANGE [SWS_Rte_03845] [SWS_Rte_03846] [SWS_Rte_01371]（SWS RTE 第420页）。
  • 陈旧数据监控遵循 aliveTimeout。值 0 将其关闭 [SWS_Rte_03759] [SWS_Rte_02710]。在隐式访问中，Rte_IStatus 提供状态 [SWS_Rte_02600]。

内存保护：在具有内存保护的系统中，RTE 会在传递来自非受信任分区的指针之前对其进行检查 [SWS_Rte_02752] [SWS_Rte_02753]。它将违规报告为 RTE_E_SEG_FAULT [SWS_Rte_02754]（SWS RTE 第378页）。

配置错误：生成器在生成时就会拦截许多错误并拒绝配置，例如 [SWS_Rte_02009] 和 [SWS_Rte_05083]。其检查的严格程度由 strictConfigurationCheck [SWS_Rte_05148] [SWS_Rte_05149] 控制。

跟踪：有效载荷中不包含 RTE 的 DET 或 DEM 需求。相反，VFB 跟踪提供了可观测性，它可以关闭或针对配置的事件激活 [SWS_Rte_01327] [SWS_Rte_01328]。它用于 SW-C 的调试，而非 RTE 本身（SWS RTE 第836页）。Hook 的示例包括 API 启动 Hook [SWS_Rte_01238] 以及 Task_Dispatch [SWS_Rte_01244]。它们在头文件 Rte_Hook[_<client>].h 中声明 [SWS_Rte_01250]。

测量与标定支持

RTE 为校准参数 [SWS_Rte_03961] (SWS RTE 第241页) 分配内存。在具有 SW 支持的仿真方法中，每次仅有一种处于激活状态 [SWS_Rte_03909] [SWS_Rte_03943]：

  • Single Pointered：RAM 中的参考表 [SWS_Rte_03913]。
  • Double Pointered：ROM 或 Flash 中的参考表 [SWS_Rte_03914]。
  • InitRam：来自 ROM/Flash 的参数的 RAM 副本 [SWS_Rte_03915]。

测量支持可以与此分开关闭 [SWS_Rte_03903]。生成器在 McSupportData 以及 McSwEmulationMethodSupport [SWS_Rte_05118] [SWS_Rte_05137] 中记录所选方法和符号信息（SWS RTE 第258页）。
