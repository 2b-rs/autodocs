系统架构与模块集群的角色

该集群构成了 Classic Platform 从硬件到模式管理的 LIN 通信栈。四个模块的任务分配如下：

  • Lin 是 MCAL 驱动程序。它封装了 LIN 控制器或 UART，并计算经典或增强型校验和 [SWS_Lin_00019]。它以 Lin_PduType 的形式接收帧，并带有 PID、校验和模型、响应类型、长度和 SDU 指针 [SWS_Lin_00232]。
  • LinTrcv 通过模式 LINTRCV_TRCV_MODE_NORMAL、…_STANDBY 和 …_SLEEP 控制外部收发器 [SWS_LinTrcv_00168] 并检查唤醒事件 [SWS_LinTrcv_00012]。
  • LinIf 是硬件抽象。它管理调度表和通道状态，并包含传输协议 LinTp [SWS_LinIf_00350]。
  • LinSM 实现 ComM 的模式请求 [SWS_LinSM_00126] 并向 BswM 报告状态和调度 [SWS_LinSM_00229]。

节点角色通过配置决定模块提供哪些功能：

  • 仅在 Master 中才存在 Lin_SendFrame、Lin_GoToSleep 和 Lin_GetStatus [SWS_Lin_00287] [SWS_Lin_00288] [SWS_Lin_00289] 以及 LinSM_ScheduleRequest [SWS_LinSM_00241]。
  • 仅在 Slave 中才存在 LinIf 的驱动程序回调 [SWS_LinIf_00863] [SWS_LinIf_00866] 和 LinSM_GotoSleepIndication [SWS_LinSM_00243]。
  • 对于 Slave，LinIf 还根据 ISO 17987-3 的节点模型管理 NAD 和 PID [SWS_LinIf_00767] [SWS_LinIf_00778] LinIf-SWS 第59页。

协作与交互路径

Master 路径。LinIf 在 LinIf_MainFunction_<LinIfChannel.ShortName> 中处理调度表 [SWS_LinIf_00384]。发送时隙的流程如下：

  1. LinIf 通过 <User_TriggerTransmit> 获取数据 [SWS_LinIf_00528] 并通过 Lin_SendFrame 传递它们 [SWS_Lin_00191]。
  2. 如果上层返回 E_NOT_OK，则不会发送该帧 [SWS_LinIf_00706]。
  3. LinIf 最早在达到最大帧长后通过 Lin_GetStatus 查询状态 [SWS_Lin_00168] LinIf-SWS 第35页。
  4. 在 LIN_TX_ERROR 或 LIN_TX_BUSY 时，紧接着是带有 E_NOT_OK 的 <User_TxConfirmation> [SWS_LinIf_00728]。

如果上层是 PduR，则 <User_TriggerTransmit> 是固定的 PduR_LinIfTriggerTransmit [SWS_LinIf_00722]。LinIf_Transmit 仅登记偶尔（Master）或事件驱动（Slave）帧 [SWS_LinIf_00201] LinIf-SWS 第79页。在 NULL_SCHEDULE 下它会予以拒绝 [SWS_LinIf_00719]。

Slave 路径。该流程由 Master 的报头触发：

  1. 驱动程序通过 LinIf_HeaderIndication 报告每个报头，并附带 PID 和指向其缓冲区的指针 [SWS_Lin_00280] [SWS_LinIf_91004]。
  2. LinIf 评估 PID：
    • 对于发送帧，<User_TriggerTransmit> 直接写入驱动程序缓冲区 [SWS_LinIf_00738]，且 LinIf 设置 Drc = LIN_FRAMERESPONSE_TX [SWS_LinIf_00739]。
    • 接收帧获得 LIN_FRAMERESPONSE_RX [SWS_LinIf_00733]。
    • 不相关的帧获得 LIN_FRAMERESPONSE_IGNORE [SWS_LinIf_00748]。
  3. Lin 评估 Drc、Cs 和 Dl [SWS_Lin_00282] [SWS_Lin_00283] [SWS_Lin_00286]。
  4. Lin 在下一个报头之前通过 Rx-Indication、Tx-Confirmation 或 Error-Indication 完成每个相关的 Response [SWS_Lin_00285]。
  5. LinIf 将结果传递给 <User_RxIndication> 或 <User_TxConfirmation> [SWS_LinIf_00734] [SWS_LinIf_00741]。

较新的版本用 LSduR 路径（状态 DRAFT）替代了这些 Callout LinIf-SWS 第43页。对于 R20-11，适用的则是 <User_…> 接口。

传输协议与调度切换。LinTp_Transmit 准备一条 TP 消息 [SWS_LinIf_00351]。在 Master 中，LinTp 通过带有 LinTp_Mode 的 BswM_LinTp_RequestMode 请求调度切换 [SWS_LinIf_00360] [SWS_LinIf_00629]。随后调用链按如下方式运行 LinIf-SWS 第132页：

  1. BswM 调用 LinSM_ScheduleRequest [SWS_LinSM_00113]。
  2. LinSM 调用 LinIf_ScheduleRequest [SWS_LinIf_00202]。
  3. LinIf 通过 <User>_ScheduleRequestConfirmation 向 LinSM_ScheduleRequestConfirmation 确认 [SWS_LinIf_00520] [SWS_LinSM_00129]。

这些 API 的参数名称在 R22-11 中被重命名 Release Overview 第50页。在 R20-11 中它们仍被称为 Schedule/schedule。

同步、重入性与任务上下文

周期性处理。每个通道存在一个 LinIf_MainFunction_<LinIfChannel.ShortName>。其他 LinIf API（如 LinIf_GotoSleep、LinIf_Transmit、LinIf_ScheduleRequest 和 LinIf_Wakeup）可以中断它。因此必须保护共享区域 LinIf-SWS 第119页。LinSM_MainFunction 维护超时定时器 [SWS_LinSM_00156]。

直接调用。Sleep 转换特意不等待下一个 MainFunction。因此它们在调用者的上下文中运行：

  • LinSM 立即调用 LinIf_GotoSleep [SWS_LinSM_00036] [SWS_LinSM_00231]。
  • LinIf 立即调用 Lin_GoToSleepInternal [SWS_LinIf_00757]。

Slave 回调。这些回调针对不同通道是可重入的，但针对同一通道则不可重入 [SWS_LinIf_91005] [SWS_LinIf_91006] [SWS_LinIf_91007]。在图表中，LinIf_HeaderIndication 直接跟随硬件中断 LinIf-SWS 第121页。解释：因此回调大多可能在 ISR 上下文中运行。<User_TriggerTransmit> 因而应保持简短。驱动程序本身的发送和接收是非阻塞的 Lin-SWS 第28页。

R20-11 中的可重入性。R20-11 将 Lin_GoToSleep、Lin_Wakeup 和 Lin_GetStatus 声明为“Non Reentrant” [SWS_Lin_00166] [SWS_Lin_00169] [SWS_Lin_00168]。较新的文档允许针对不同通道的可重入性 Lin-SWS 第43页。对于 R20-11，以更严格的版本为规范准则。

收发器处也存在类似的落差：LinIf_SetTrcvMode 是可重入的 [SWS_LinIf_00544]，而所调用的 LinTrcv_SetOpMode 则不是 [SWS_LinTrcv_00002]。解释：并发调用应当在集成端进行串行化。

多核。通道和收发器通道必须属于同一个 ECUC 分区 [SWS_Lin_CONSTR_00279] [SWS_LinTrcv_00177]。

生命周期与运行模式

初始化。模式管理指南按以下顺序进行初始化：Lin_Init、LinIf_Init、LinSM_Init、LinTp_Init [SWS_Lin_00006] [SWS_LinIf_00198] [SWS_LinSM_00155] ModeManagementGuide 第54页。LinTrcv_Init [SWS_LinTrcv_00001] 的位置在依据中未明确体现。各模块在此过程中设置以下初始状态：

  • LinIf_Init 在 Master 中设置 NULL_SCHEDULE [SWS_LinIf_00197] LinIf-SWS 第90页。
  • LinTp_Init 将每个通道设置为 LINTP_CHANNEL_IDLE [SWS_LinIf_00710]。
  • LinSM 在 LINSM_NO_COM 中启动，而不通知 ComM 或 BswM LinSM-SWS 第23页。

Master 中的 Sleep。若 ComM 请求 COMM_NO_COMMUNICATION，则 LinSM 调用 LinIf_GotoSleep [SWS_LinSM_10208]。随后 LinIf 通过 Lin_GoToSleep 发送 Go-to-sleep 命令。在此过程中，即使发生错误，通道也会进入 LIN_CH_SLEEP_PENDING Lin-SWS 第43页。确认信息以 LinSM_GotoSleepConfirmation 到达 LinSM [SWS_LinSM_00135]。

Slave 中的 Sleep。两类事件会发起转换：NAD 为 0 的 MRF [SWS_LinIf_00750] 或总线空闲超时（Bus-Idle-Timeout）[SWS_LinIf_00755]。LinIf 均通过 LinSM_GotoSleepIndication 报告 [SWS_LinIf_00756] [SWS_LinSM_91000]。后续流程 LinIf-SWS 第55页：

  1. LinSM 调用 LinIf_GotoSleep。
  2. LinIf 通过 Lin_GoToSleepInternal 使驱动程序进入睡眠状态，并通过 TRUE 进行确认 [SWS_LinIf_00759]。
  3. 如果 ComM 先前请求了 COMM_NO_COMMUNICATION [SWS_LinSM_00230]，则 ComM 收到 ComM_BusSM_BusSleepMode [SWS_LinSM_00233]。
  4. 否则 LinSM 会重新启动唤醒过程 [SWS_LinSM_00234]。

收发器可选地通过 LinIf_SetTrcvMode(LINTRCV_TRCV_MODE_SLEEP) 一并切换 [SWS_LinSM_00138] LinIf-SWS 第137页。

由 ComM 发起的唤醒过程。在 COMM_FULL_COMMUNICATION 时，LinSM 启动一个确认定时器并直接调用 LinIf_Wakeup LinSM-SWS 第27页 LinSM-SWS 第27页。正在运行的 Silence-after-Wakeup 定时器会延迟该调用 [SWS_LinSM_00237]。LinIf 根据唤醒标志进行决定：

  • 如果该标志未设置，LinIf 会调用带有唤醒脉冲的 Lin_Wakeup [SWS_LinIf_00205] LinIf-SWS 第89页。
  • 如果该标志已设置，不带脉冲的 Lin_WakeupInternal 应该就足够了 [SWS_Lin_00262]。

Slave 仅在接收到第一个报头时才确认唤醒 [SWS_LinIf_00761]。

外部唤醒事件。EcuM 调用 LinIf_CheckWakeup。LinIf 根据来源分支到 Lin_CheckWakeup 或 LinTrcv_CheckWakeup [SWS_LinIf_00378] [SWS_Lin_00160]。驱动程序将检测到的事件报告给 EcuM，并通过 LinIf_WakeupConfirmation 报告给 LinIf [SWS_LinIf_00715] [SWS_LinTrcv_91002] Lin-SWS 第42页。收发器的唤醒通知由 LinIf_SetTrcvWakeupMode 控制 [SWS_LinIf_00550] [SWS_LinTrcv_00169]。

错误处理、DET 跟踪与降级

开发错误（DET）。所有模块针对 DET 检查参数和初始化状态：

  • LinIf：[SWS_LinIf_00376] [SWS_LinIf_00849]
  • Lin，包括 LIN_E_STATE_TRANSITION [SWS_Lin_00258] [SWS_Lin_00260]
  • LinSM：[SWS_LinSM_00053] [SWS_LinSM_00240]
  • LinTrcv：[SWS_LinTrcv_00005] LinTrcv-SWS 第26页

运行时错误。Lin 强制需要 Dem_SetEventStatus [SWS_Lin_00234]。驱动程序将硬件超时报告为 LIN_E_TIMEOUT [SWS_Lin_00290]。在 Slave 中，Lin 将错误作为 Lin_SlaveErrorType 返回 [SWS_Lin_91140] [SWS_Lin_00277]。随后 LinIf 将 Response 视为丢失并报告 LINIF_E_RESPONSE，除了 LIN_ERR_HEADER [SWS_LinIf_00735] [SWS_LinIf_00729] 的情况。LinSM 将未出现的 Callbacks 报告为 LINSM_E_CONFIRMATION_TIMEOUT [SWS_LinSM_00224]。

降级。发生错误后，多种机制可维持有序运行：

  • response_error 信号：Response 错误通过 Com_SendSignal 设置该信号 [SWS_LinIf_00744] [SWS_LinIf_00764]。成功发送后它会被复位 [SWS_LinIf_00747] LinIf-SWS 第58页。
  • LinSM 一致性：在 E_NOT_OK 时，LinSM 会重新设置先前的状态，以使 ComM 和 BswM 接收到指示 [SWS_LinSM_00177]。
  • LinTp 中止：发生 N_As 或 N_Cr 超时时，LinTp 中止并向 PduR 报告 E_NOT_OK [SWS_LinIf_00801] [SWS_LinIf_00806]。
  • 缓冲区不足：若缺少接收缓冲区，LinTp 会暂停 SRF 报头 [SWS_LinIf_00679]。或者，它会中止并返回应用程序调度 [SWS_LinIf_00792] [SWS_LinIf_00879]。
  • Node Configuration：在 N_As 超时时，LinIf 会丢弃待处理的响应 [SWS_LinIf_00786]。
