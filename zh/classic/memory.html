在 Classic Platform 中，Memory Services 是软件组件和 BSW 模块非易失性存储数据的途径。向上仅有 NVRAM Manager (NvM) 提供服务。它管理逻辑 NVRAM 块。此类块强制由 NV 块、RAM 块和 Administrative 块组成 [SWS_NvM_00138]。可选地，还可以添加包含默认数据的 ROM 块 [SWS_NvM_00139]。支持的块类型有 NVM_BLOCK_NATIVE、NVM_BLOCK_REDUNDANT 和 NVM_BLOCK_DATASET [SWS_NvM_00137]。逻辑块结构示意图展示了这一分解（SWS NVRAMManager 第10页）。

在 NvM 之下是包含三个模块的 Memory Hardware Abstraction：

  • MemIf（Memory Abstraction Interface）将每个调用转发给通过 DeviceIndex 选择的抽象模块 [SWS_MemIf_00039] [SWS_MemIf_00040]。在 R20-11 中，DeviceIndex 的类型为 uint8。更新的文档位置显示为 uint16（SWS MemIf 第18页）；对于 R20-11，以该 Requirement 为准。
  • Fee（Flash EEPROM Emulation）在 Flash 驱动程序 Fls 之上模拟按块可写的存储器 [SWS_Fee_00084] [SWS_Fee_00104]。
  • Ea（EEPROM Abstraction）将逻辑块映射到 EEPROM 驱动程序 Eep [SWS_Ea_00083]。

MemIf、Fee 和 Ea 共同为 NvM 提供一个虚拟的线性 32 位地址空间 [SWS_NvM_00051]。NV 块基号位于 Fee/Ea 块号的高位中 [SWS_NvM_00123]。冗余块的寻址方式与 Dataset 块相同 [SWS_NvM_00343]。

上下文图：NvM 是用户的唯一访问入口。MemIf 将调用分发给 Fee 或 Ea，它们分别访问 Fls 或 Eep，反馈则通过回调向上传递。来源：[SWS_MemIf_00047] [SWS_Fee_00098] [SWS_Ea_00099] [SWS_NvM_00745] SWS FEE 第48页。解释：类似于 Fls 和 Fee，Eep 调用 Ea_JobEndNotification。

协作与交互路径

作业接收与处理。NvM_WriteBlock 接收参数，将作业排入 Job-Queue 并立即返回 [SWS_NvM_00208] [SWS_NvM_00162]。成功入队后，NVM_REQ_PENDING [SWS_NvM_00185] 成立。若队列溢出，该函数返回 E_NOT_OK [SWS_NvM_00184]。实际处理在 NvM_MainFunction [SWS_NvM_00256] 中进行。从那里，调用链经由 MemIf_Write 通向 Fee_Write 或 Ea_Write。Ea 根据块号计算写入地址，并设置已配置的块长度（SWS EA 第25页）。

反馈路径。状态通过以下两种途径之一返回给 NvM：

  • 轮询：NvM_MainFunction 通过 MemIf_GetJobResult 查询作业状态 [SWS_NvM_00346] [SWS_MemIf_00043]。
  • 回调：Fee 或 Ea 调用 NvM_JobEndNotification 或 NvM_JobErrorNotification。仅当轮询模式被禁用时，NvM 才提供这些函数 [SWS_NvM_00440] [SWS_NvM_00441]。Fee 本身通过 Fee_JobEndNotification [SWS_Fee_00095] 从 Flash 驱动程序接收作业结束通知。

NvM 在读取时按如下方式转换 MemIf_JobResultType [SWS_MemIf_00065] 的值：

  • MEMIF_BLOCK_INVALID → 结果 NVM_REQ_NV_INVALIDATED [SWS_NvM_00341]
  • MEMIF_BLOCK_INCONSISTENT → DEM 报告 NVM_E_INTEGRITY_FAILED [SWS_NvM_00653]
  • MEMIF_JOB_FAILED → DEM 报告 NVM_E_REQ_FAILED [SWS_NvM_00654]

向用户传递缓冲区。具有显式同步的块共享 NvM 中的单个 RAM-Mirror [SWS_NvM_00513]。数据通过 NvMWriteRamBlockToNvCallback 和 NvMReadRamBlockFromNvCallback 复制 [SWS_NvM_00515] [SWS_NvM_00516]（EXP NVDataHandling 第14页）。作业完成后，NvM_MainFunction 调用配置的回调 [SWS_NvM_00347] [SWS_NvM_00113]。可选地，NvM 还会向 BswM 通知块状态和多块状态 [SWS_NvM_00746]。

时序图：写入作业被异步接收，周期性处理，并通过回调或轮询返回结果。来源：[SWS_NvM_00208] [SWS_NvM_00256] [SWS_NvM_00346] [SWS_Fee_00095] SWS FEE 第48页

同步、重入性与任务上下文

执行上下文。NvM 不直接使用 OS 对象，而是仅使用 BSW-Scheduler [SWS_NvM_00332]。每个模块都有自己的周期性处理：NvM_MainFunction [SWS_NvM_00464]、Fee_MainFunction [SWS_Fee_00097] 和 Ea_MainFunction [SWS_Ea_00096]。下层的状态和转发函数是不可重入的，例如 MemIf_Read [SWS_MemIf_00039]、Fee_GetStatus [SWS_Fee_00090] 以及 Ea_GetStatus [SWS_Ea_00089]。因此串行化由 NvM 的 Job-Queue 处理。

中断级和任务级。R24-11 中的一处文档位置指出，Fee_JobEndNotification 应可在中断级调用（SWS FEE 第37页）。R20-11 将该函数定义为同步的 [SWS_Fee_00095]，NvM_JobEndNotification [SWS_NvM_00462] 亦是如此。相比之下，向用户发送的回调则在 NvM_MainFunction [SWS_NvM_00347] 上下文中的任务级运行。

优先级和一致性。

  • 在优先级处理模式下，存在一个用于 Immediate 作业（碰撞数据）的独立队列 [SWS_NvM_00378]。这些作业会中断正在运行的作业 [SWS_NvM_00182]。
  • 来自 NvM_WriteAll 的作业不会被中断 [SWS_NvM_00567]。在 NvM_ReadAll 期间的读取作业会被排队并在之后执行 [SWS_NvM_00568]。
  • 在隐式同步下，应用程序只能在作业结束后重新修改 RAM 块 [SWS_NvM_00698]。在显式同步下，应用程序在复制回调之前均可继续对其进行修改 [SWS_NvM_00705]。
  • 在多分区系统中，仅 NvM-Master 提供 NvM_ReadAll 和 NvM_WriteAll [SWS_NvM_00970] [SWS_NvM_00971]。
  • Fee_Cancel 和 Ea_Cancel 在 R20-11 中是同步的 [SWS_Fee_00089] [SWS_Ea_00088]。后续版本将其作为异步实现（SWS EA 第27页）。

生命周期与运行模式

初始化。NvM_Init 仅由 BswM 调用 [SWS_NvM_00693]，此时尚未初始化任何块 [SWS_NvM_00091]。下层此时必须已经初始化 [SWS_NvM_00157] [SWS_NvM_00193]。Fee_Init 在 R20-11 中是异步的 [SWS_Fee_00085]。模式管理指南展示了一个典型的顺序：Eep_Init、Fls_Init、NvM_Init，之后是 NvM_ReadAll（ModeManagementGuide 第38页）。

使用 NvM_ReadAll 启动。NvM_ReadAll 加载 RAM 块。该函数仅接收作业；实际处理在 NvM_MainFunction [SWS_NvM_00158] [SWS_NvM_00243] 中完成。第一步是比对配置 ID [SWS_NvM_00073]。在 NvMDynamicConfiguration == FALSE 时，偏差会被忽略 [SWS_NvM_00248]。可选地，NvM 在执行前通过 MemIf_SetMode 将存储设备切换为 Fast-Mode，并在执行后切换回 Slow-Mode [SWS_NvM_00426] [SWS_NvM_00427] [SWS_MemIf_00066]。NvM 向 BswM 报告多块作业的接收和结束 [SWS_NvM_00888] [SWS_NvM_00889]。后者的规则随后启动其余的初始化。

使用 NvM_WriteAll 关闭。BswM 通过 NvM_WriteAll 发起关闭 [SWS_NvM_00092]。仅写入具有永久 RAM 块或显式同步的块 [SWS_NvM_00252]。通过 NvM_SetRamBlockStatus 可以将其限制为实际已更改的块（EXP NVDataHandling 第18页）。NvM_CancelWriteAll 仅保留给 BswM [SWS_NvM_00703]。在 NvM_WriteAll 完成后，BswM 调用 EcuM_GoDown（ModeManagementGuide 第37页）。

时序图：BswM 控制启动和关闭。NvM 对多块作业的反馈分别触发下一阶段。来源：[SWS_NvM_00693] [SWS_NvM_00460] [SWS_NvM_00461] [SWS_NvM_00888] SWS NVRAMManager 第163页

Fee 和 Ea 的运行状态。两个模块均将其状态作为 MemIf_StatusType 报告，具有值 MEMIF_UNINIT、MEMIF_IDLE、MEMIF_BUSY 和 MEMIF_BUSY_INTERNAL [SWS_MemIf_00064]。MEMIF_BUSY_INTERNAL 代表垃圾回收（Garbage Collection）等内部管理（SWS EA 第28页）。Ea_Write 在该状态下同样接收作业。

状态图：Fee 和 Ea 在空闲、作业处理和内部管理之间切换。来源：[SWS_Fee_00090] [SWS_Ea_00089] SWS FEE 第29页 SWS EA 第25页。解释：在接收来自 MEMIF_BUSY_INTERNAL 的作业后，该模块可能报告 MEMIF_BUSY。

错误处理、DET 跟踪与降级

跨层检测。错误逐层进行检测：

  1. 驱动程序（Fls 或 Eep）检测到该错误。
  2. Fee 或 Ea 以实现特定的方式处理它。
  3. Fee 或 Ea 进一步报告该错误：通过作业结果 MEMIF_JOB_FAILED 或通过 NvM_JobErrorNotification（ErrorDescription 第40页、ErrorDescription 第48页）。

恢复由 NvM 控制（ErrorDescription 第43页）。

NvM 的恢复机制。

  • 写入：NvM 重复执行写入过程，直至达到配置的最大次数 [SWS_NvM_00168] [SWS_NvM_00213] [SWS_NvM_00296]。
  • 读取冗余块：NvM 还会读取第二个 NV 块 [SWS_NvM_00199] [SWS_NvM_00288]。
  • 最终回退层级：NvM 从 ROM 块加载默认数据 [SWS_NvM_00389] [SWS_NvM_00171]。在此过程中，NV 块保持不变 [SWS_NvM_00172]。如果使用了 ROM 数据，结果为 NVM_REQ_RESTORED_FROM_ROM [SWS_NvM_00470]。
  • 冗余丢失：NvM 向 DEM 报告 NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00546]（ErrorDescription 第62页、EXP ErrorDescription 第76页）。

向 DEM 和用户报告。作为生产错误，NvM 向 DEM 报告：

  • NVM_E_INTEGRITY_FAILED [SWS_NvM_00864]
  • NVM_E_REQ_FAILED [SWS_NvM_00865]
  • NVM_E_WRONG_BLOCK_ID [SWS_NvM_00866]
  • NVM_E_VERIFY_FAILED [SWS_NvM_00867]
  • NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00868]

用户根据配置通过使用 NvM_GetErrorStatus [SWS_NvM_00451] 轮询，或通过单块和多块回调 [SWS_NvM_00113] [SWS_NvM_00260] 获取结果。

DET 跟踪与降级。模块将开发错误报告给 DET，例如：

  • NVM_E_UNINIT [SWS_NvM_00614]
  • FEE_E_UNINIT [SWS_Fee_00010]
  • EA_E_UNINIT [SWS_Ea_91001]
  • MEMIF_E_PARAM_DEVICE [SWS_MemIf_00006]

如果缺少默认数据，则在读取失败后 RAM 块保持无效 [SWS_NvM_00658] [SWS_NvM_00680]。应用程序随后必须在下一次写入尝试之前自行提供有效数据 [SWS_NvM_00696]。
