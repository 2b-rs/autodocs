系统架构 & 模块集群的角色

AUTOSAR Classic Platform 的存储服务（Memory Services）模块集群确保非易失性存储器中应用程序和基础软件数据的标准化、独立于硬件的管理与持久化。该集群在纵向上划分为 AUTOSAR 基础软件架构的两层：服务层（Services Layer）的 NVRAM Manager（[SWS_NvM_00447]），以及存储硬件抽象层（Memory Hardware Abstraction Layer）上带有下层抽象模块 Flash EEPROM Emulation（[SWS_Fee_00085]）和 EEPROM Abstraction（[SWS_Ea_00083]）的 Memory Abstraction Interface（[SWS_MemIf_00039]）AUTOSAR SWS NVRAMManager 第10页。

NVRAM Manager（NvM）构成了软件组件（SW-C）以及 BSW 模块（例如诊断事件管理器模块 (Dem)）的核心入口点 SWS DiagnosticEventManager 第238页。它管理逻辑存储块，这些存储块由非易失性存储器中的 NV 块、易失性存储器中的 RAM 块以及用于初始化数据的可选 ROM 块组成（[SWS_NvM_00137]、[SWS_NvM_00128]）。根据需求，支持原生（NVM_BLOCK_NATIVE）、冗余（NVM_BLOCK_REDUNDANT）或数据集（NVM_BLOCK_DATASET）等块管理类型 AUTOSAR CP RS MemoryServices 第10页。

模块 Fee 和 Ea 封装了各自物理存储介质（Flash 或 EEPROM）的特性，并将逻辑块号和地址偏移映射到各自 MCAL 驱动程序（Fls 或 Eep）的线性地址空间（[SWS_Fee_00087]、[SWS_Ea_00086]）AUTOSAR SWS EEPROMAbstraction 第23页。模块 MemIf 在此作为纯路由层，根据参数 DeviceIndex 将访问转发到目标模块，而不保留自身的缓冲区结构（[SWS_MemIf_00040]）。

各模块之间的交互配合与交互路径

模块之间的交互通过严格标准化的同步和异步路径进行。用户通过 NvM_WriteBlock 发起写入操作时，请求首先在 NvM 的管理块中注册（[SWS_NvM_00455]）。在同步调用时，通过 MemIf_Write 转发到 MemIf（[SWS_MemIf_00040]），再由其将调用传递给 Fee_Write 或 Ea_Write（[SWS_Fee_00088]、[SWS_Ea_00087]）AUTOSAR SWS NVRAMManager 第160页。

在应用程序与 NVRAM Manager 之间的数据保存和同步方面存在两个核心概念：通过永久 RAM 块的隐式同步（NvMRamBlockDataAddress）和通过基于镜像的缓冲区的显式同步（NvMBlockUseSyncMechanism）NVDataHandling 第12页。在显式同步中，NvM 通过配置的回调例程 NvMWriteRamBlockToNvCallback 或 NvMReadRamBlockFromNvCallback 在应用程序 RAM 和内部 RAM 镜像之间复制有效负载数据（[SWS_NvM_00514]、[SWS_NvM_00515]）EXP NVDataHandling 第30页。

使用数据集块（NVM_BLOCK_DATASET）时，调用方预先通过 NvM_SetDataIndex 选择所需的数据集索引（[SWS_NvM_00448]）。抽象模块随后根据逻辑块号和索引计算 MCAL 驱动程序的精确地址偏移（[SWS_NvM_00123]）AUTOSAR SWS Flash EEPROM Emulation 第21页。中止请求通过 MemIf_Cancel 直接透传给子模块 Fee_Cancel 或 Ea_Cancel（[SWS_MemIf_00041]、[SWS_Fee_00089]）。

同步、重入性与任务上下文

集群的大多数控制和状态 API（包括 NvM_GetErrorStatus ([SWS_NvM_00451])、NvM_SetBlockProtection ([SWS_NvM_00450]) 和 MemIf_GetVersionInfo ([SWS_MemIf_00045])）均同步执行，并可直接在调用方的任务上下文中处理 AUTOSAR SWS NVRAMManager 第157页。与此相反，数据传输函数（NvM_ReadBlock、NvM_WriteBlock、Ea_Write）设计为异步且不可重入（[SWS_MemIf_00040]、[SWS_Ea_00087]）。

正在运行作业的周期性推进由调度管理器（SchM）或 BSW 任务定期调用的主函数 NvM_MainFunction 和 Fee_MainFunction 负责 AUTOSAR CP SWS FlashEEPROMEmulation 第42页。对于来自 MCAL 驱动程序的异步消息，通知 Fee_JobEndNotification 或 Fee_JobErrorNotification 可以直接在中断级别进行（[SWS_Fee_00095]）。这会将状态设置为 MEMIF_JOB_OK 或调用配置的通知例程（[SWS_Fee_00142]、[SWS_Fee_00194]）SWS FlashEEPROMEmulation 第37页。

典型的生命周期和操作模式

该集群的生命周期由 Basic Software Mode Manager（BswM）和 ECU State Manager（EcuM）紧密编排。在控制器启动期间（启动阶段），在驱动程序之后首先通过 Fee_Init 或 Ea_Init 同步初始化抽象模块（[SWS_Fee_00085]、[SWS_Ea_00083]），随后通过 NvM_Init 同步初始化 NVRAM Manager（[SWS_NvM_00447]）AUTOSAR SWS NVRAMManager 第156页。

初始化完成后，BswM 触发多块读取操作 NvM_ReadAll，以从非易失性存储器中恢复所有标记为持久的 RAM 块（[SWS_NvM_00460]）ModemanagementGuide 第54页。NvM 通过回调函数 BswM_NvM_CurrentJobMode 向 BswM 报告进度和最终结果（[SWS_NvM_00745]、[SWS_NvM_00888]）。单块状态通过 BswM_NvM_CurrentBlockMode 进行指示（[SWS_NvM_00746]、[SWS_NvM_00890]）ModemanagementGuide 第28页。

在关机阶段，系统通过 NvM_WriteAll 促使将所有已更改的 RAM 块持久写回非易失性存储器（[SWS_NvM_00461]）。为了优化 Flash 写入周期的次数，可以通过 NvM_SetRamBlockStatus 有针对性地标记某个块是否已被修改（[SWS_NvM_00453]）EXP NVDataHandling 第18页。在发生过早唤醒事件时，正在进行的写入过程可以通过 NvM_CancelWriteAll 中止（[SWS_NvM_00238]）AUTOSAR SWS NVRAMManager 第161页。

错误处理、DET 跟踪与降级

该集群具有多级错误检测和降级概念。驱动层和抽象层出现的错误通过返回状态 MEMIF_JOB_FAILED 借助 MemIf_GetJobResult 查询，或通过 NvM_JobErrorNotification 报告（[SWS_Fee_00091]、[SWS_Ea_00095]）ErrorDescription 第49页。

发生读取错误时，NvM 会采用配置的恢复机制：首先执行重试（Read Retries）（[SWS_NvM_00390]）。如果重试失败，对于冗余块（NVM_BLOCK_REDUNDANT）将读取冗余副本（[SWS_NvM_00171]、[SWS_NvM_00531]）。如果在此过程中检测到冗余丢失，NvM 会将作业结果设置为 NVM_REQ_REDUNDANCY_FAILED 并向 DEM 报告生产错误 NVM_E_LOSS_OF_REDUNDANCY（[SWS_NvM_00470]、[SWS_NvM_00546]）ErrorDescription 第62页。

如果通过 ROM 默认值恢复成功，NvM 会报告结果 NVM_REQ_RESTORED_FROM_ROM（[SWS_NvM_00470]）。如果所有恢复措施均告失败，则向 DEM 报告 NVM_E_REQ_FAILED（[SWS_NvM_00279]、[SWS_NvM_00288]）并将查询结果设置为 NVM_REQ_NOT_OK（[SWS_NvM_00451]）。发生写入错误时，NvM 在中止请求之前控制写入重试（NvMMaxNumOfWriteRetries）（[SWS_NvM_00168]、[SWS_NvM_00213]）ErrorDescription 第56页。
