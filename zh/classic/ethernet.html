系统架构与模块集群的角色

模块集群“Ethernet Services”在 AUTOSAR Classic Platform（版本 R20-11）中构成了通过以太网网络进行有线分组通信的功能骨干。它跨越了一条从微控制器抽象层 (MCAL) 的底层驱动层、经由 ECU 抽象层一直到通信服务层 (Communication Services) 中标准化互联网传输与网络互连协议的连续抽象链。该集群满足了现代电子电气架构日益增长的带宽需求，并通过服务于诸如 Socket Adaptor (SoAd) 等上层模块，将诸如基于 IP 的诊断服务（符合 ISO 13400 的 DoIP）以及面向服务的通信 (SOME/IP) 等标准车载协议无缝集成到 AUTOSAR 基础软件中 SWS_TcpIp 第123页。

该集群的三个核心模块各自承担明确划分的架构职责：

  • Ethernet Driver (Eth)：作为 MCAL 模块，Eth 直接控制以太网 MAC 控制器。它管理底层发送和接收缓冲区描述符，控制用于收发器配置的 MII/MDIO 寄存器接口（[SWS_Eth_00058]），设置物理过滤规则（[SWS_Eth_00152]），并为全局时间同步机制提供高精度硬件时间戳（[SWS_Eth_00186]、[SWS_Eth_00190]）。
  • Ethernet Interface (EthIf)：构成核心抽象层，并将上层与物理硬件拓扑解耦。EthIf 抽象了多个以太网控制器、交换机和收发器 (PHY)。它负责虚拟局域网处理（符合 IEEE 802.1Q 的 VLAN 标记）、帧类型多路复用、缓冲区分配以及交换机端口组和链路状态的聚合（[SWS_EthIf_00075]、[SWS_EthIf_91102]、AUTOSAR_CP_SWS_EthernetInterface 第213页）。
  • TCP/IP Stack (TcpIp)：作为通信服务实现互联网协议族。该模块包括 IPv4 和 IPv6、通过 Auto-IP (RFC 3927) 和 DHCPv6 (RFC 3315) 进行动态地址分配（[SWS_TCPIP_00057]、[SWS_TCPIP_00166]）、通过 ARP (RFC 826) 进行地址解析（[SWS_TCPIP_00056]）、使用 UDP 的无连接传输以及使用 TCP 的面向连接、可靠的字节流传输（[SWS_TCPIP_00050]）。此外，它还支持通过 TLS 进行传输加密（[SWS_TCPIP_00300]）。

模块间的相互配合与交互路径

数据传输（Transmission Path）基于支持网卡缓冲区零拷贝设计的两阶段缓冲区请求和发送过程。上层协议参与者或模块 TcpIp 通过 EthIf_ProvideTxBuffer() 请求一段连续的存储缓冲区，同时指定优先级和所需的帧长度（[SWS_Eth_00077]、AUTOSAR_SWS_EthernetInterface 第87页）。EthIf 使用 Eth_ProvideTxBuffer() 将此请求委托给相应的驱动程序，从而使驱动程序锁定硬件缓冲区并返回描述符索引 (Eth_BufIdxType) 及缓冲区指针（[SWS_Eth_00077]）。在填充有效负载后，调用层通过 EthIf_Transmit() 触发发送（[SWS_EthIf_00075]）。在相应配置下，EthIf 会插入 VLAN 标签（EtherType 0x8100）并调用 Eth_Transmit()，随后驱动程序构建以太网报头，设置目标 MAC 地址并将发送请求移交给 MAC 控制器（[SWS_Eth_00087]、[SWS_EthIf_00250]）。

接收路径（Reception Path）以基于中断的事件驱动方式或基于轮询的方式处理传入的以太网帧。在使用 Eth_Receive() 从硬件队列中读取缓冲区后（[SWS_Eth_00095]、[SWS_Eth_00162]），驱动程序通过 EthIf_RxIndication() 将数据包通知给接口（[SWS_EthIf_00085]）。EthIf 检查控制器的有效性以及可能的 VLAN 标签，过滤无效数据报（[SWS_EthIf_00309]），并根据 EtherType 将帧转发给分配的上层。接收到的 IP 数据包由 TcpIp 接收，该模块根据引用的接收 PDU (TcpIpCtrlRxPdu) 和元数据评估该帧（[SWS_TcpIp_00411]、[SWS_TcpIp_00412]）。如果接口和目标 IP 满足本地地址表的匹配条件（[SWS_TCPIP_00169]），则解包数据包并通过接口 <Up_RxIndication>() 同步移交给负责的套接字所有者（例如 SoAd）（[SWS_TCPIP_00220]、[SWS_TCPIP_00223]）。

在地址解析和数据包过滤领域，TcpIp 和 Eth 通过 EthIf 紧密交互。如果 TcpIp 通过传入数据包或 ARP 响应检测到新的地址关系，它将更新 ARP 缓存（[SWS_TCPIP_00056]、[SWS_TcpIp_00092]）并通过 Up_PhysAddrTableChg() 报告更改（[SWS_TCPIP_00142]）。如果缺少 MAC 地址，TcpIp_GetRemotePhysAddr() 会启动地址解析（[SWS_TCPIP_00137]）。为了限制网络广播和多播流量，EthIf 通过 Eth_UpdatePhysAddrFilter() 在 MAC 控制器中配置基于硬件的哈希过滤器或表，以便在第 2 层有针对性地允许通过或丢弃多播帧（[SWS_Eth_00152]、[SWS_Eth_00245]）。

同步、重入性与任务上下文

该模块集群支持两种用于时间解耦的运行模式：轮询模式和中断模式。在轮询模式下，任务级别的周期性函数 EthIf_MainFunctionTx() 通过为所有已配置的驱动程序调用 Eth_TxConfirmation() 来查询已完成的发送过程（[SWS_EthIf_00115]、AUTOSAR_SWS_EthernetInterface 第87页）。类似地，接收队列通过在任务上下文中周期性调用 Eth_Receive() 来清空（[SWS_Eth_00095]）。在中断模式下，发送和接收 ISR（Eth_TxIrqHdlr_<CtrlIdx>()、Eth_RxIrqHdlr_<CtrlIdx>()）直接从中断上下文将事件报告给 EthIf_TxConfirmation() 和 EthIf_RxIndication()（[SWS_EthIf_00091]、AUTOSAR_SWS_EthernetInterface 第88页、SWS_EthernetInterface 第173页）。收发器和交换机连接的周期性状态监控在 EthIf_MainFunctionState() 中解耦执行（AUTOSAR_CP_SWS_EthernetInterface 第213页）。

可重入性规定精确适配于多核和多任务系统。Eth_ProvideTxBuffer() 被设计为完全可重入（[SWS_Eth_00077]）。发送 API Eth_Transmit() 和 EthIf_Transmit() 对于不同的控制器和缓冲区索引是可重入的（[SWS_Eth_00087]、[SWS_EthIf_00075]）。相比之下，针对同一控制器的控制函数（如 Eth_SetPhysAddr() 或 Eth_UpdatePhysAddrFilter()）是不可重入的，但允许针对不同的控制器并发执行（[SWS_Eth_00151]、[SWS_Eth_00152]）。状态采集和硬件时间戳查询（例如 Eth_GetCurrentTime() 或 EthIf_GetCurrentTime()）被明确指定在互斥区（Exclusive Areas）内调用，以确保诸如 gPTP (IEEE 802.1AS) 等协议的时间戳无抖动一致性（SWS_EthernetDriver 第82页、SWS_EthernetInterface 第140页）。

典型的生命周期和操作模式

集群的生命周期需要严格的初始化顺序，通常由 ECU State Manager (EcuM) 控制：首先使用 Eth_Init() 初始化底层驱动程序，随后是 EthIf_Init()，最后是协议栈 TcpIp_Init()。在常规运行中，所有接口都会检查初始化是否已成功完成，否则将拒绝执行并报告开发错误（[SWS_Eth_00027]、[SWS_Eth_00051]、[SWS_EthIf_00024]）。

第 2 层的模式管理通过 EthIf_SetControllerMode() 控制，由此所寻址控制器的模式在 ETH_MODE_DOWN、ETH_MODE_ACTIVE 和 ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST 之间切换（[SWS_EthIf_00034]、[SWS_Eth_91008]）。驱动程序执行模式切换并通过回调 EthIf_CtrlModeIndication() 异步确认，该回调将状态更改传递给 Ethernet State Manager (EthSM)（[SWS_EthIf_00231]、[SWS_EthIf_00252]）。对于联网交换机，EthIf 还使用 EthIf_SwitchPortGroupRequestMode() 控制交换机端口组，或通过 EthIf_StartAllPorts() 启动所有端口（[SWS_EthIf_91102]、[SWS_EthIf_91103]）。在 TcpIp 协议栈中，网络的通信状态通过 TcpIp_RequestComMode() 单独控制：TCPIP_STATE_ONLINE 激活 IP 地址分配，TCPIP_STATE_ONHOLD 暂停发送活动，而 TCPIP_STATE_OFFLINE 关闭所有活动套接字（[SWS_TCPIP_00070]、[SWS_TCPIP_00071]、[SWS_TCPIP_00072]、[SWS_TCPIP_00074]）。

在关闭、休眠和唤醒领域，该集群支持符合 OPEN Alliance TC10 的标准化唤醒序列（SWS_ECUStateManager 第192页）。如果以太网硬件（PHY 或交换机端口）在休眠状态下检测到唤醒信号，中断将发出该事件信号。随后集成代码或 EcuM 触发 EthIf_CheckWakeup()，指示相关收发器驱动程序进行异步验证（[SWS_EthIf_00244]、[SWS_EthIf_00245]）。可以通过 EthIf_GetSwitchPortWakeupReason() 读取详细的唤醒原因（[SWS_EthIf_91005]）。在关闭时，TcpIp_ResetIpAssignment() 允许有针对性地重置 NvM 中持久化的 IP 分配（[SWS_TCPIP_00215]、[SWS_TCPIP_00216]）。

错误处理、DET 跟踪与降级

该集群的模块实现了多级错误监控和诊断概念。在开发和系统集成期间，Default Error Tracer (DET) 拦截编程和配置错误。其中包括在模块初始化完成之前的调用（ETH_E_UNINIT、ETHIF_E_UNINIT）（[SWS_Eth_00228]、[SWS_EthIf_00036]）、无效的控制器或收发器索引（ETH_E_INV_CTRL_IDX、ETHIF_E_INV_TRCV_IDX）（[SWS_Eth_00229]、[SWS_EthIf_00326]）以及无效的指针参数（[SWS_Eth_00230]、[SWS_Eth_00250]）。对于 MII 总线上的硬件相关通信故障，Eth_WriteMii() 报告运行时错误 ETH_E_COMMUNICATION（[SWS_Eth_00058]、[SWS_Eth_00286]）。

对于运行诊断和错误内存管理 (DEM)，Eth 和 EthIf 提供符合 IETF-RFC 标准的标准化计数器结构。通过 Eth_GetCounterValues() 和 Eth_GetRxStats() 记录符合 RFC 1757、RFC 1643 和 RFC 2819 的因缓冲区溢出 (Buffer Overrun)、CRC 错误、超大包和欠小包（Jabbers、Undersize）以及对齐错误引起的丢弃事件（[SWS_Eth_00226]、[SWS_Eth_00233]、[SWS_Eth_91007]、[SWS_Eth_91002]）。发送计数器和错误统计信息通过 Eth_GetTxStats() 和 Eth_GetTxErrorCounterValues() 提供（[SWS_Eth_91005]、[SWS_Eth_91006]、[SWS_Eth_91003]）。EthIf 通过 EthIf_SwitchPortGetCounterValues() 和 EthIf_SwitchPortGetTxErrorCounterValues() 透明转发外部交换机硬件的这些计数器查询（[SWS_EthIf_91115]、[SWS_EthIf_91118]）。

降级机制和链路质量监控确保了功能稳健性：EthIf_GetTrcvSignalQuality() 提供物理收发器的当前、最小和最大连接质量（[SWS_EthIf_91056]、[SWS_EthIf_91057]），从而可以在链路断开前诊断退化的传输路径。EthIf_GetAndResetMeasurementData() 允许读取和重置有关丢弃数据报的详细测量数据，例如在涉及 VLAN ID 或控制器分配的配置缺陷时（[SWS_EthIf_91011]、[SWS_EthIf_00309]）。发生连接中断时，EthIf_Transmit() 停止向驱动程序转发（[SWS_EthIf_00076]），而 TcpIp 在处于离线状态时终止套接字并清空发送队列（[SWS_TCPIP_00072]）。
