将 RTE 的信号映射到 I-PDU，并通过 PDU Router 控制其发送、接收和监控。

COM 将 RTE 的信号和信号组打包到 I-PDU 中，且仅通过 PDU Router 将其传递到总线。反之，它从 Com_RxIndication 解包接收到的 I-PDU 并通知 RTE [SWS_Com_00123]。发送根据配置的传输模式进行，周期性部分由 Com_MainFunctionTx 处理。通信仅针对其 I-PDU 组已启动的 I-PDU 进行，通常由 BswM [SWS_Com_91001] 启动。停止的组会导致 COM_SERVICE_NOT_AVAILABLE；截止时间监控会检测丢失的确认。

COM 在面向信号的 RTE 与面向 I-PDU 的通信栈之间进行协调。RTE 使用 Com_SendSignal 写入信号，并使用 Com_SendSignalGroup [SWS_Com_00197] [SWS_Com_00200] 写入信号组。通过相应的 Receive-API [SWS_Com_00198] 进行读取。向下的唯一接口是 PDU Router（RS COM 第12页）。PduR 调用 Com_RxIndication、Com_TxConfirmation 和 Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001]。

上下文图：COM 嵌入在 RTE、BswM、J1939Rm 与 PduR 之间。来源：SWS PduR 第24页、SWS BswM 第93页

在 Com_Init 之后，ECU 间通信尚未使能 [SWS_Com_00432]。使能是通过 I-PDU 组进行的，通常由 BswM 使用 Com_IpduGroupStart 和 Com_IpduGroupStop 控制 [SWS_Com_91001] [SWS_Com_91002]。只要某个 I-PDU 的至少一个组已启动，该 I-PDU 就处于活动状态 [SWS_Com_00771]。在停止时，COM 会丢弃未决的发送请求 [SWS_Com_00777]。

在发送时，Transmission Mode Selection 在两种配置的模式之间进行选择（TPS SystemTemplate 第274页）。周期性部分由 Com_MainFunctionTx [SWS_Com_00399] 接管。在 CAN 上直接传递，而在 FlexRay 上，FrIf 通过 TriggerTransmit 获取数据（SWS PduR 第101页）。在接收时，COM 会丢弃 Update-Bit 未置位的信号，并在某个组信号被过滤掉时丢弃整个信号组 [SWS_Com_00802] [SWS_Com_00836]。对于转换器链，提供了通过 Com_SendSignalGroupArray [SWS_Com_00851] 的数组访问。

时序图：通过 CAN（直接）或 FlexRay（TriggerTransmit）发送信号组，随后向 RTE 进行确认。来源：SWS COM 第87页、SWS RTE 第329页

出现错误时，适用以下规则：

  • 诸如 COM_E_UNINIT 或 COM_E_PARAM_POINTER 之类的开发错误会发送给 DET [SWS_Com_00442] [SWS_Com_00804]。
  • 当组处于停止状态时，API 会返回 COM_SERVICE_NOT_AVAILABLE [SWS_Com_00865]。
  • 若未收到发送确认，发送截止时间监控会通过 ComTimeoutNotification [SWS_Com_00304] 报告此情况。

COM 在 RTE 与 PDU Router 之间的角色

AUTOSAR COM 模块在 RTE 的面向信号视角与通信栈的面向 I-PDU 视角之间进行协调。信号和信号组通过 Com_SendSignal 和 Com_SendSignalGroup 写入 I-PDU [SWS_Com_00197] [SWS_Com_00200]。通过 Com_ReceiveSignal 和 Com_ReceiveSignalGroup 再次将其读出 [SWS_Com_00198] [SWS_Com_00201]。向下而言，PDU Router 是 COM 的唯一接口（RS COM 第12页）。COM 在该接口调用 PduR_ComTransmit [SWS_Com_00669]。反之，COM 向 PduR 提供回调 Com_RxIndication、Com_TxConfirmation 和 Com_TriggerTransmit [SWS_Com_00123] [SWS_Com_00124] [SWS_Com_00001]。在此过程中，PduR 在源模块与目标模块之间转换 I-PDU-ID（SWS PduR 第33页）。

除 RTE 之外，其他基础软件模块也使用 COM 接口：

  • BswM 通过可选接口控制 I-PDU 组、接收截止时间监控以及发送模式（SWS BswM 第93页）。
  • J1939Rm 通过 Com_TriggerIPDUSendWithMetaData 定向触发 I-PDU [SWS_Com_00858]（SWS J1939Rm 第62页）。
  • COM 将错误报告给 DET [SWS_Com_00670]。

生命周期：初始化、I-PDU 组与状态

Com_Init 使用类型为 Com_ConfigType 的配置初始化内部和外部接口及变量。此后 ECU 间通信尚未使能 [SWS_Com_00432] [SWS_Com_00825]。Com_GetStatus 返回 COM_UNINIT 或 COM_INIT；复位后为 COM_UNINIT [SWS_Com_00194] [SWS_Com_00819]。Com_DeInit 停止所有已启动的 I-PDU 组，并将模块恢复为未初始化状态 [SWS_Com_00130]。

按各个 I-PDU 组使能通信：

  • Com_IpduGroupStart 启动一个组，并可根据需要重新初始化 I-PDU 数据。Com_IpduGroupStop 再次将其停止 [SWS_Com_91001] [SWS_Com_91002]。
  • 只要某个 I-PDU 的至少一个组已启动，该 I-PDU 就处于活动状态 [SWS_Com_00771]。
  • 未分配组的 I-PDU 已由 Com_Init 启动，且处理方式如同带有 initialize = true [SWS_Com_00840]。
  • 在停止时，COM 会丢弃未决的发送请求，包括重发 [SWS_Com_00777]。COM 会忽略针对已停止 I-PDU 的后续发送确认 [SWS_Com_00800]。

通常，BswM 通过动作 BswMPduGroupSwitch 切换这些组。其参数 BswMPduGroupSwitchReinit 对应于实参 initialize（SWS BswM 第165页）。周期性发送部分在自 Com_IpduGroupStart 起经过配置的 timeOffset 后开始（TPS SystemTemplate 第268页）。

发送：从信号到总线上的 I-PDU

Com_SendSignal 以异步方式工作 [SWS_Com_00197]。对于需要原子传输的数据，RTE 分两步进行：首先使用 Com_SendSignal 写入所有组信号。随后使用 Com_SendSignalGroup 触发该组的传输（SWS RTE 第329页）。在此过程中，COM 置位该组的 Update-Bit [SWS_Com_00801]。

传输模式决定 I-PDU 何时以及以何种频率发送：

  • 每个 I-PDU 静态配置了两种模式（True/False）。Transmission Mode Selection 在它们之间进行选择，包括在运行时（TPS SystemTemplate 第274页）。
  • 或者，Com_SwitchIpduTxMode 显式设置模式 [SWS_Com_00784]。周期性发送随后会偏移 ComTxModeTimeOffset [SWS_Com_00881]。
  • Com_TriggerIPDUSend 触发单次发送，不受传输模式影响，但仅针对已启动的 I-PDU [SWS_Com_00348] [SWS_Com_00861]（TPS SystemTemplate 第371页）。
  • ComMinimumDelayTime 强制两次发送之间的最小间隔 [SWS_Com_00828]。

Com_MainFunctionTx 接管所有未直接在 RTE 所调用的函数中完成的发送活动 [SWS_Com_00399]。若配置了 ComPreparationNotification，它将在 I-PDU 处理之前调用 Com_CbkTxPrep [SWS_Com_00886] [SWS_Com_91013]。Com_TxIpduCallout 可通过 false 阻止 I-PDU 的进一步处理 [SWS_Com_00346]。

各总线系统的流程有所不同：

  • CAN：I-PDU 直接通过 PduR_ComTransmit 传递。
  • FlexRay：在 PduR_ComTransmit 之后，FrIf 直到发送时隙才通过 Com_TriggerTransmit 获取数据（SWS PduR 第101页）。
  • LIN：非偶发帧（Sporadic Frames）的帧完全根据调度表通过 TriggerTransmit 获取（SWS PduR 第88页）。

如果提供的缓冲区过小或 I-PDU 已停止，Com_TriggerTransmit 不会复制任何内容并返回 E_NOT_OK [SWS_Com_00869] [SWS_Com_00884]。通过 Com_TxConfirmation，COM 中止正在运行的发送截止时间定时器 [SWS_Com_00880]。此外，它通过配置的 Notification 报告每次成功的发送 [SWS_Com_00883]。在 IMMEDIATE 处理时立即进行，在 DEFERRED 处理时则通过标志延迟进行（SWS COM 第91页）。

时序图：发送信号组、传递给 CAN（直接）或 FlexRay（TriggerTransmit）以及随后的确认。来源：SWS COM 第87页、SWS PduR 第101页、SWS RTE 第329页、[SWS_Com_00880]

接收：指示、解包与通知

PduR 使用 I-PDU-ID、长度、数据指针和 MetaData 调用 Com_RxIndication [SWS_Com_00123]。该路径对于 CanIf、FrIf 和 LinIf 是相同的；PduR 在此过程中不进行缓冲（SWS PduR 第97页）。随后，I-PDU 经历以下检查：

  • 已配置的 Com_RxIpduCallout 始终会被调用，且在计数器处理之前调用并传入完整的 I-PDU [SWS_Com_00889] [SWS_Com_00816]。若其返回 false，则不再进一步处理该 I-PDU [SWS_Com_00700]。
  • COM 丢弃 Update-Bit 未置位的信号 [SWS_Com_00802]。
  • 若因接收到的 I-PDU 短于预期而缺少 Update-Bit，则将其视为已置位 [SWS_Com_00794]。
  • 若 COM 过滤掉某个组信号，则会丢弃整个信号组 [SWS_Com_00836]。

活动图：处理接收到的 I-PDU 直至发出通知过程中的决策。来源：[SWS_Com_00889] [SWS_Com_00700] [SWS_Com_00802] [SWS_Com_00794] [SWS_Com_00836] [SWS_Com_00726]；Update-Bit 位于过滤器之前的顺序为一种解释。

COM 如何通知 RTE 取决于处理方式。在 IMMEDIATE 方式下，COM 直接在指示的上下文中调用 RTE 回调。在 DEFERRED 方式下，COM 最初仅设置一个标志并复制数据（SWS COM 第92页）。对该标志的检查推测在 Com_MainFunctionRx 中进行，该函数负责接管未在 Com_RxIndication 中直接完成的接收处理 [SWS_Com_00398]。对于信号组，COM 仅在所有组信号均已解包后才发出通知。随后 RTE 对每个组信号严格调用一次 Com_ReceiveSignalGroup，紧接着调用 Com_ReceiveSignal（SWS RTE 第329页）。COM 为 RTE 保存接收到的 MetaData [SWS_Com_00888]。

时序图：PduR 进行指示、IMMEDIATE 与 DEFERRED 通知对比，以及 RTE 获取信号组。来源：SWS COM 第92页、SWS RTE 第329页、[SWS_Com_00123]

大型 I-PDU、信号组数组与元数据

大型 I-PDU 通过传输协议进行传输。为此，COM 提供了专用的 TP 接口，该接口与 PduR 的上层 TP 接口相匹配（SWS PduR 第24页）：

  • 接收：Com_StartOfReception、Com_CopyRxData 和 Com_TpRxIndication [SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650]。
  • 发送：Com_CopyTxData 和 Com_TpTxConfirmation [SWS_Com_00693] [SWS_Com_00725]。

TP 运行适用若干特殊规则：

  • 在 TpSduLength = 0 时，COM 报告配置的最大长度 [SWS_Com_00874]。
  • 若大型 I-PDU 在传输过程中被再次触发，COM 将丢弃额外的请求 [SWS_Com_00863]。
  • 当缓冲区被锁定时，若 Com_TriggerIPDUSend 触发发送，COM 会暂存该请求并稍后发送 [SWS_Com_00867]。

时序图：通过 CanTp 和 PduR 分段接收大型 I-PDU，简化未包含 SecOC。来源：SWS SecOC 第111页、[SWS_Com_00691] [SWS_Com_00692] [SWS_Com_00650] [SWS_Com_00838]

针对转换器链，RTE 将信号组作为字节数组进行访问。为此提供了 Com_SendSignalGroupArray 和 Com_ReceiveSignalGroupArray [SWS_Com_00851] [SWS_Com_00854]。相关规则如下：

  • 数组范围：它始于具有最小 ComBitPosition 的组信号的字节偏移量处。止于具有最大 ComBitPosition 的组信号的最后一个字节 [SWS_Com_00844] [SWS_Com_00845]。
  • 处理：在发送时，COM 就传输属性（Transfer Properties）和 Transmission Mode Selection 而言，将该调用视为 Com_SendSignalGroup [SWS_Com_00847]。仅支持受限的过滤器集合 [SWS_Com_00848]。
  • 前提条件：数据必须具有固定大小、按字节对齐映射且不得包含无关信号 [SWS_Com_00841]。对于此类组，不允许使用单信号和组 API [SWS_Com_00843]。

COM Based Transformer 按照 COM 自身的方式对数据进行序列化。随后的其他转换器接着补充 CRC 和序列计数器（SWS ComXf 第14页、EXP LSA 第103页）。

时序图：RTE 执行转换器链并通过对 Com_SendSignalGroupArray 的单次调用传递结果。来源：SWS ComXf 第14页、[SWS_Com_00846] [SWS_Com_00847]

发送 I-PDU 的 MetaData 来自 RTE 的上一次传递；若不存在，则来自 ComMetaDataDefault。通过 Com_TriggerIPDUSendWithMetaData 传递的 MetaData 仅对由此触发的发送有效 [SWS_Com_00887] [SWS_Com_00862]。

配置、调度与信号网关

COM 具有三种 Main Function：Com_MainFunctionRx、Com_MainFunctionTx 和 Com_MainFunctionRouteSignals。每种都可以多次实例化，并且对于不同实例是可重入的 [SWS_Com_00398] [SWS_Com_00399] [SWS_Com_00400]。它们由 BSW 调度器无参数调用（SWS BSWGeneral 第79页）。它们的周期由 EcuInstance 通过 comConfigurationRxTimeBase、comConfigurationTxTimeBase 和 comConfigurationGwTimeBase 进行描述（TR Interoperability 第98页）。相关的通知 Rte_COMCbkTxPrep_<mn> 绑定到特定的 Com_MainFunctionTx 实例（SWS RTE 第832页）。

信号网关是 COM 的组成部分（SRS Gateway 第11页）。它将接收到的信号在 Com_MainFunctionRouteSignals 中转发 [SWS_Com_00400]。在此过程中，它在接收侧和发送侧经历已定义的处理阶段 [SWS_Com_00872] [SWS_Com_00873]。它还可以将各个组信号映射到独立信号上 [SWS_Com_00833]。

配置受若干边界条件约束：

  • 支持来自 [SWS_Com_00675] 的数据类型。类型为 UINT8_N 和 UINT8_DYN 的信号必须按字节对齐 [SWS_Com_00105]。
  • 一个组的所有 I-PDU 具有相同的方向 [SWS_Com_00871]。
  • 若为接收信号配置了无效值，则还必须配置 ComDataInvalidAction [SWS_Com_00859]。

信号 ID、组 ID 和 I-PDU 组 ID 是从零开始的 uint16 值 [SWS_Com_00820] [SWS_Com_00821] [SWS_Com_00822]。它们的符号名称由 ComHandleId 生成（TPS ECUConfiguration 第138页）。

发生错误时的行为

COM 通过 Det_ReportError 报告开发错误，ModuleId 为 50 [SWS_Com_00442]。定义了以下错误：

  • COM_E_PARAM 用于错误参数 [SWS_Com_00803]。
  • COM_E_UNINIT 用于在 Com_Init 之前或 Com_DeInit 之后的调用。状态函数、版本函数和 Main Function 除外 [SWS_Com_00804]。
  • COM_E_PARAM_POINTER 用于空指针 [SWS_Com_00805]。
  • COM_E_INIT_FAILED 用于无效的配置选择 [SWS_Com_00837]。
  • 作为运行时错误 COM_E_SKIPPED_TRANSMISSION 用于被丢弃的发送请求 [SWS_Com_00864]。

当 I-PDU 组停止或存在开发错误时，信号 API 返回 COM_SERVICE_NOT_AVAILABLE [SWS_Com_00865]。Com_ReceiveSignalGroupArray 仍会复制最近已知的有效数据 [SWS_Com_00857]。

对于发送截止时间监控，规则如下：

  • 定时器在信号传递到底层时启动。首次加载 ComFirstTimeout，之后加载 ComTimeout [SWS_Com_00878] [SWS_Com_00879]。
  • 若定时器超时，COM 会调用 ComTimeoutNotification [SWS_Com_00304]。
  • 在传输模式 NONE 下，监控被禁用 [SWS_Com_00835]。

在接收侧存在以下机制：

  • BswM 通过 Com_DisableReceptionDM 和 Com_EnableReceptionDM 关闭并重新开启截止时间监控 [SWS_Com_91003] [SWS_Com_91004]（SWS BswM 第148页）。
  • 若接收定时器超时，SUBSTITUTE 会将这些值替换为 ComTimeoutSubstitutionValue [SWS_Com_00875] [SWS_Com_00876]。
  • 若 TP 接收失败或 Callout 返回 false，COM 将该 I-PDU 的所有信号视为无效 [SWS_Com_00838] [SWS_Com_00839]。
  • 若 I-PDU 计数器出现偏差，COM 会调用 Com_CbkCounterErr [SWS_Com_00726]。
