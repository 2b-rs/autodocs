在通信协议栈中的角色：上层为信号，下层为 I-PDU

AUTOSAR COM 将 RTE 的面向信号视角与下层的面向 PDU 视角连接起来。向上，COM 为单个信号、动态长度信号和信号组提供发送和接收服务，例如 Com_SendSignal、Com_ReceiveSignal、Com_SendSignalGroup 和 Com_ReceiveSignalGroup（[SWS_Com_00197]、[SWS_Com_00198]、[SWS_Com_00200]、[SWS_Com_00201]、[SWS_Com_00627]）。向下，PDU Router 是唯一的通信伙伴。COM 通过 PduR_ComTransmit 发送（[SWS_Com_00669]）。反之，PduR 调用 Com_RxIndication、Com_TxConfirmation、Com_TriggerTransmit 以及 COM 的 TP 函数（SWS PduR 第24页）。

BswM 从旁控制 COM。它启动和停止 I-PDU 组、切换接收截止时间监视并选择发送模式（SWS BswM 第93页）。COM 向 DET 报告开发错误和运行时错误（[SWS_Com_00670]）。支持的数据类型包括 boolean、最大 64 位的无符号和有符号整数、float32/float64 以及 uint8[n]。后者映射到 UINT8_N 或 UINT8_DYN（[SWS_Com_00675]），且此类信号必须按字节对齐（[SWS_Com_00105]）。

生命周期：Com_Init、I-PDU 组与 Com_DeInit

Com_Init 初始化内部和外部接口。但此后 ECU 之间的通信仍然处于禁止状态（[SWS_Com_00432]）。未分配给任何组的 I-PDU 是一个例外。Com_Init 会自行启动它们，就像使用 initialize = true 调用了 Com_IpduGroupStart 一样（[SWS_Com_00840]）。它们的初始发送模式由 ComSignalInitValues 决定（[SWS_Com_00877]）。模块状态 COM_UNINIT/COM_INIT 由 Com_GetStatus 提供（[SWS_Com_00194]、[SWS_Com_00819]）。

只要 I-PDU 的组中至少有一个已启动，该 I-PDU 即处于活动状态（[SWS_Com_00771]）。一个组的所有 I-PDU 都具有相同的 ComIPduDirection（[SWS_Com_00871]）。

  • Com_IpduGroupStart 启动一个组。使用 initialize = true 时，其 I-PDU 数据会被重新初始化（[SWS_Com_91001]）。在 BswM 中，这对应于参数 BswMPduGroupSwitchReinit（SWS BswM 第165页）。
  • 组启动后的首次周期性传输在 CyclicTiming 的 timeOffset 之后进行（SystemTemplate 第268页）。
  • Com_IpduGroupStop 中止受影响 I-PDU 的未决发送任务，包括重传（[SWS_Com_91002]、[SWS_Com_00777]）。COM 会忽略此后到达的发送确认（[SWS_Com_00800]）。
  • Com_DeInit 停止所有已启动的组并将 COM 置于未初始化状态（[SWS_Com_00130]）。

状态图：I-PDU 在模块初始化、组启动/停止与去初始化之间的生命周期。来源：[SWS_Com_00432]、[SWS_Com_00840]、[SWS_Com_00771]、[SWS_Com_91001]、[SWS_Com_91002]、[SWS_Com_00130]

发送：从信号值到已确认的 I-PDU

对于原子数据，RTE 使用 Com_SendSignal 单独写入每个组信号。随后它通过 Com_SendSignalGroup 触发传输（SWS RTE 第329页）。在此过程中，COM 设置该组的 Update-Bit（[SWS_Com_00801]）。发送服务以异步方式工作。如果关联的 I-PDU 组已停止，它们将返回 E_OK 或 COM_SERVICE_NOT_AVAILABLE（[SWS_Com_00197]、[SWS_Com_00865]）。

RTE 调用的函数未能直接完成的工作由 Com_MainFunctionTx 接管（[SWS_Com_00399]）。在 I-PDU 处理之前，它在需要时调用 Com_CbkTxPrep（[SWS_Com_00886]、[SWS_Com_91013]）。如果配置的 Com_TxIpduCallout 返回 false，则不再进一步处理该 I-PDU（[SWS_Com_00346]）。如果配置了重传，则仅当 PduR_ComTransmit 返回 E_OK 时才启动最小延迟（[SWS_Com_00828]）。Com_TxConfirmation 报告成功或失败（[SWS_Com_00124]），并且每次成功的传输都会触发所配置的 Notification（[SWS_Com_00883]、[SWS_Com_00468]）。

时序图：填充信号组，通过 PduR 和 CanIf 发送并确认。来源：SWS RTE 第329页、SWS PduR 第33页、[SWS_Com_00399]、[SWS_Com_00124]

对于诸如 FlexRay 的 Trigger Transmit 总线连接，接口最初仅记录发送请求。随后它通过 PduR 使用 Com_TriggerTransmit 请求数据（SWS PduR 第106页、[SWS_Com_00001]）。在两种情况下，COM 不复制任何内容并返回 E_NOT_OK：缓冲区过小或 I-PDU 已停止（[SWS_Com_00869]、[SWS_Com_00884]）。

时序图：在 Trigger Transmit 中，发送请求与数据获取在时间上解耦。来源：SWS PduR 第106页、[SWS_Com_00001]、[SWS_Com_00869]、[SWS_Com_00884]

可以通过三种方式从外部影响发送时刻：

  • Com_SwitchIpduTxMode 设置发送模式。周期性传输在此过程中会偏移 ComTxModeTimeOffset（[SWS_Com_00784]、[SWS_Com_00881]、SWS BswM 第178页）。
  • Com_TriggerIPDUSend 触发单次传输，与发送模式无关。这仅在 I-PDU 已启动时有效（[SWS_Com_00348]、[SWS_Com_00861]、SystemTemplate 第371页）。
  • Com_TriggerIPDUSendWithMetaData 的工作方式相同，但会传递仅对该单次传输有效的元数据（[SWS_Com_00858]、[SWS_Com_00862]、[SWS_Com_00887]）。J1939Rm 使用这种变体（SWS J1939Rm 第62页）。

接收：检查链与一致信号组

PduR 使用 Com_RxIndication 传递接收到的 I-PDU（[SWS_Com_00123]、SWS PduR 第103页）。随后 COM 运行一个检查链：

  1. 配置的 Rx Callout 接收完整的 I-PDU。它始终会被调用，且在计数器处理之前调用（[SWS_Com_00816]、[SWS_Com_00889]）。如果它返回 false，则不对该 I-PDU 进行处理（[SWS_Com_00700]）。
  2. 如果 I-PDU 计数器出现偏差，COM 将调用 Com_CbkCounterErr（[SWS_Com_00726]）。
  3. 如果 Update-Bit 未置位，则丢弃该信号（[SWS_Com_00802]）。如果因 I-PDU 过短而缺少 Update-Bit，则该信号被视为已更新（[SWS_Com_00794]）。
  4. 如果 COM 过滤掉某个组信号，则会丢弃整个信号组（[SWS_Com_00836]）。

活动图：从接收 I-PDU 到 Notification 的分支。解读：虽然展示了 Update-Bit 在 Filter 之前的顺序，但并无依据证明。来源：[SWS_Com_00889]、[SWS_Com_00700]、[SWS_Com_00802]、[SWS_Com_00794]、[SWS_Com_00836]、[SWS_Com_00555]

在接收端，RTE 恰好调用 Com_ReceiveSignalGroup 一次，随后使用 Com_ReceiveSignal 读取组信号。COM 仅在组的所有信号都已解包到缓冲区中后才发出通知（SWS RTE 第329页、[SWS_Com_00201]）。COM 存储接收到的元数据，以便通过 Com_ReceiveSignalWithMetaData 进行访问（[SWS_Com_00888]、[SWS_Com_91005]）。

数组访问、大型 I-PDU 与 Transformer

Com_SendSignalGroupArray 和 Com_ReceiveSignalGroupArray 将信号组作为 uint8 数组传输。该数组的范围从 ComBitPosition 最小的组信号起始字节，到最高组信号的最后一个字节（[SWS_Com_00851]、[SWS_Com_00854]、[SWS_Com_00844]、[SWS_Com_00845]）。此访问适用以下条件：

  • 该组仅包含固定大小的数据，按字节对齐，且不包含外来信号（[SWS_Com_00841]）。
  • 对于此类组，单一信号 API 和常规组 API 不可用（[SWS_Com_00843]）。
  • 这些 API 必须通过 ComEnableSignalGroupArrayApi 启用（[SWS_Com_00853]、[SWS_Com_00856]）。

对于发送模式选择，COM 将数组发送视为 Com_SendSignalGroup 处理（[SWS_Com_00847]）。COM Based Transformer 正是使用这种途径（SWS ComXf 第14页）。

大型 I-PDU 通过 TP 接口运行。在接收时，包括 Com_StartOfReception、Com_CopyRxData 和 Com_TpRxIndication（[SWS_Com_00691]、[SWS_Com_00692]、[SWS_Com_00650]）。在 TpSduLength = 0 中，COM 返回配置的最大长度（[SWS_Com_00874]）。在发送时，则包括 Com_CopyTxData 和 Com_TpTxConfirmation（[SWS_Com_00693]、[SWS_Com_00725]、SWS SecOC 第108页）。如果在正在进行的传输期间收到另一个发送请求，COM 会将其跳过（[SWS_Com_00863]）。相反，在缓冲区锁定时发生的 Com_TriggerIPDUSend 则会被保存并在随后补行（[SWS_Com_00867]）。

时序图：大型 I-PDU 通过 CanTp 和 PduR 的分段接收直至结果评估。来源：SWS SecOC 第111页、[SWS_Com_00691]、[SWS_Com_00692]、[SWS_Com_00650]、[SWS_Com_00838]

主函数、时间监控与信号网关

COM 具有三个周期性主函数：Com_MainFunctionRx、Com_MainFunctionTx 和 Com_MainFunctionRouteSignals（[SWS_Com_00398]、[SWS_Com_00399]、[SWS_Com_00400]）。它们的周期由时基 comConfigurationRxTimeBase、comConfigurationTxTimeBase 和 comConfigurationGwTimeBase 描述（SWC-Template 第841页）。如果某个主函数存在多个实例，ComIPduMainFunctionRef 会将每个 I-PDU 分配给其中之一（SWS RTE 第1470页）。

发送截止时间监控的工作原理如下：

  • 定时器在发送时启动（若尚未运行）。在监控（重新）启动后的首次启动时适用 ComFirstTimeout，否则适用 ComTimeout（[SWS_Com_00878]、[SWS_Com_00879]）。
  • 发送确认会停止定时器（[SWS_Com_00880]）。
  • 如果定时器超时，COM 会调用 ComTimeoutNotification（[SWS_Com_00304]）。
  • 在发送模式 NONE 下，该监控处于关闭状态（[SWS_Com_00835]）。

在接收时，超时可以用 ComTimeoutSubstitutionValue 替换这些值（[SWS_Com_00875]、[SWS_Com_00876]）。该监控可以针对每个组单独开启和关闭（[SWS_Com_91003]、[SWS_Com_91004]）。

活动图：发送截止时间监控的启动、中止和超时。来源：[SWS_Com_00835]、[SWS_Com_00878]、[SWS_Com_00879]、[SWS_Com_00880]、[SWS_Com_00304]

信号网关是 COM 的固有组成部分（SRS Gateway 第11页）。它可以将组信号路由到单个信号（[SWS_Com_00833]），并在接收端和发送端经历规定的处理阶段（[SWS_Com_00872]、[SWS_Com_00873]）。

发生错误时的行为

  • COM 使用 ModuleId 50 向 Det_ReportError 报告开发错误（[SWS_Com_00442]）。错误代码如下：
    • COM_E_PARAM ([SWS_Com_00803])
    • COM_E_UNINIT 用于在 Com_Init 之前或 Com_DeInit 之后的 API 调用，但状态函数、版本函数和主函数除外（[SWS_Com_00804]）
    • COM_E_PARAM_POINTER ([SWS_Com_00805])
    • COM_E_INIT_FAILED ([SWS_Com_00837])
  • 跳过的大型 I-PDU 发送请求将作为运行时错误 COM_E_SKIPPED_TRANSMISSION 进行报告（[SWS_Com_00863]、[SWS_Com_00864]）。
  • 当组停止时，服务返回 COM_SERVICE_NOT_AVAILABLE。如果大型 I-PDU 的缓冲区被锁定，可能会返回 COM_BUSY（[SWS_Com_00865]）。Com_CbkTxErr 表示在组停止时尝试发送（[SWS_Com_00491]）。
  • 带有 E_NOT_OK 的 TP 接收或 Callout 结果 false 会导致 COM 将该 I-PDU 的所有信号视为已失效处理，并执行 ComDataInvalidAction（[SWS_Com_00838]、[SWS_Com_00839]）。
  • 在发送端，Com_InvalidateSignal 和 Com_InvalidateSignalGroup 使值失效（[SWS_Com_00203]、[SWS_Com_00557]）。在接收端，配置的无效值也需要一个 ComDataInvalidAction（[SWS_Com_00859]、[SWS_Com_00860]）。无效值的接收通过 Com_CbkInv 报告（[SWS_Com_00536]）。
  • 即使在 I-PDU 停止时，Com_ReceiveSignalGroupArray 也会提供最后已知的数据或初始值（[SWS_Com_00857]）。
