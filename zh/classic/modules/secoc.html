SecOC的作用：在PDU-Router旁保护I-PDU

SecOC（Secure Onboard Communication）保护I-PDU免遭篡改和重放。发送时，SecOC会在Authentic I-PDU上附加认证信息，该信息由可能经过截断的Freshness Value和Authenticator组成。由此生成Secured I-PDU。接收时，在转发Authentic I-PDU之前会先检查此信息（[SWS_SecOC_00040]、SWS SecOC 图 7.2 第30页）。Authenticator通过三部分的拼接计算得出：Data Identifier（SecOCDataId）、Authentic I-PDU的安全部分以及完整的Freshness Value（SWS SecOC 第29页）。

在架构中，SecOC 与 PduR 并列。诸如 Com 之类的上层通过 PduR_<Up>Transmit 发送。随后 PduR 调用 SecOC_[If|Tp]Transmit，SecOC 再通过 PduR 将 Secured I-PDU 传递给总线接口或传输协议（SWS SecOC 第40页、SWS SecOC 图 1.1 第10页）。Authentic PDU 的 MetaData 会原封不动地出现在 Secured PDU 中，反之亦然（[SWS_SecOC_00212]）。任何其他模块都不得依赖 SecOC，以便系统在没有 SecOC 的情况下也能构建（SWS SecOC 第39页）。

SecOC 与其他多个模块协同工作：

  • 密码学功能由 CSM 提供，其中包括通过 Csm_MacGenerate 和 Csm_MacVerify（[SWS_SecOC_00138]）。对于异步 CSM 作业，SecOC 提供供应商特定的回调（SWS SecOC 第78页）。
  • Freshness Value 来自 Freshness Manager。在 SecOCQueryFreshnessValue = RTE 下，它通过端口 FreshnessManagement 连接（[SWS_SecOC_91001]），在 CFUNC 下则通过 C 函数连接（[SWS_SecOC_00231]、[SWS_SecOC_00247]）。
  • SecOC 向 DET 报告错误（[SWS_SecOC_00101]）。
  • Security Event 发送给 IdsM（[SWS_SecOC_00273]）。

模块状态和周期性 Main Function

SecOC 包含两种状态，SECOC_UNINIT 和 SECOC_INIT（[SWS_SecOC_00162]）：

  • 使用 SecOC_Init 成功初始化后会进入 SECOC_INIT（[SWS_SecOC_00106]）。
  • SecOC_DeInit 会停止安全通信，丢弃所有已缓冲的 I-PDU，并将模块置于未初始化状态（[SWS_SecOC_00161]）。在此过程中，内部全局变量也会被清除（SWS SecOC 第65页）。
  • 对于未初始化时的 API 调用，预留了错误 SECOC_E_UNINIT；对于初始化失败，则预留了 SECOC_E_INIT_FAILED（[SWS_SecOC_00101]）。
  • 若模块未初始化，SecOC_MainFunctionTx 会立即返回（SWS SecOC 第84页）。

实际的密码学处理并不在发送或接收函数的调用上下文中运行，而是周期性运行。对于 SecOCMainFunctionTx 或 SecOCMainFunctionRx 的每个配置实例，都有各自的 SecOC_MainFunctionTx_<shortName> 或 SecOC_MainFunctionRx_<shortName>（[SWS_SecOC_00176]、[SWS_SecOC_00171]）。各自的周期通过 SecOCMainFunctionPeriodTx 或 SecOCMainFunctionPeriodRx 设置（SWS SecOC 第130页、SWS SecOC 第129页）。Tx-PDU 在通过 SecOCTxPduMainFunctionRef 引用的 Main Function 中进行处理（[SWS_SecOC_00276]）。

状态图：处理仅在 SECOC_INIT 中进行；SecOC_DeInit 会丢弃所有缓冲区。来源：[SWS_SecOC_00162]、[SWS_SecOC_00106]、[SWS_SecOC_00161]、[SWS_SecOC_00101]、SWS SecOC 第84页

发送路径：从 Authentic 到 Secured I-PDU

发送过程始于 SecOC_IfTransmit 或 SecOC_TpTransmit（[SWS_SecOC_00112]、[SWS_SecOC_91008]）。SecOC 在 Secured I-PDU 的传输开始之前，将完整的 Authentic I-PDU 复制到自己的内存中（[SWS_SecOC_00252]）。随后调用返回。

在下一次调用 SecOC_MainFunctionTx 时，所有新的 Authentic I-PDU 都会被认证。每个完成的 Secured I-PDU 都会立即通过 PduR 发送（SWS SecOC 第84页）。生成过程包含六个步骤，从准备 Secured I-PDU 到递增 Freshness Counter 以及发送（SWS SecOC 第33页）。

在模式 CFUNC 下，Freshness Value 由两个函数之一提供，具体取决于 SecOCProvideTxTruncatedFreshnessValue：

  • SecOC_GetTxFreshnessTruncData，它还提供截断值（[SWS_SecOC_00230]、[SWS_SecOC_91003]），或者
  • SecOC_GetTxFreshness ([SWS_SecOC_00231], [SWS_SecOC_91004]).

SecOC 通过 SecOC_SPduTxConfirmation 或 FreshnessManagement_SPduTxConfirmation 向 Freshness Manager 报告已触发 Secured I-PDU 的发送（[SWS_SecOC_00232]、[SWS_SecOC_00233]）。

发送后，SecOC 相对下层承担起上层模块的角色（SWS SecOC 第40页）：

  • 触发传输（例如 FrIf）：下层使用 SecOC_TriggerTransmit 获取数据（[SWS_SecOC_00127]）。这以先前调用 SecOC_IfTransmit 为前提；不得使用 AlwaysTransmit 工作模式（SWS SecOC 第44页）。
  • 传输协议：数据通过 SecOC_CopyTxData 获取（[SWS_SecOC_00129]）。
  • 确认：SecOC 通过 PduR_SecOC[If|Tp]TxConfirmation 将来自 SecOC_[If|Tp]TxConfirmation 的结果向上层传递（[SWS_SecOC_00063]）。

若配置了 SecOCPduType = SECOC_TPPDU，则由 SecOC_TpTransmit 触发发送过程。SecOC 随后通过 PduR_SecOCTpCopyTxData 从上层分段获取 Authentic I-PDU（[SWS_SecOC_00253]、[SWS_SecOC_00254]、SWS SecOC 图 9.4 第109页）。

时序图：发送调用仅进行缓冲；新鲜度、MAC 和发送在 SecOC_MainFunctionTx 中解耦进行。在成功的发送调用之后放置 SecOC_SPduTxConfirmation 属于一种推断。来源：SWS SecOC 图 9.1 第96页、[SWS_SecOC_00252]、[SWS_SecOC_00231]、[SWS_SecOC_00232]、[SWS_SecOC_00063]

接收路径：缓冲、验证、传递

在接收时，SecOC 始终遵循相同的顺序：首先将完整的 Secured I-PDU 接收到自己的内存中，然后在下一个 SecOC_MainFunctionRx 中进行验证（SWS SecOC 第50页）。仅当完整的 Secured I-PDU 就绪时，才会复制 Authentic I-PDU（[SWS_SecOC_00255]）。

  • 总线接口：接收通过 SecOC_RxIndication 报告（[SWS_SecOC_00124]）。
  • 传输协议：接收通过 SecOC_StartOfReception、SecOC_CopyRxData 和 SecOC_TpRxIndication 进行（[SWS_SecOC_00130]、[SWS_SecOC_00128]、[SWS_SecOC_00125]）。在 SECOC_TPPDU 时，SecOC 通过 PduR_SecOCTpStartOfReception 将接收开始转发给上层（SWS SecOC 第54页）。

验证遵循六个固定的步骤（[SWS_SecOC_00040]）：

  1. 分解 Authentic I-PDU、Freshness Value 和 Authenticator。
  2. 从 Freshness Manager 获取 Freshness Value。
  3. 构建待认证数据。
  4. 检查 Authenticator。
  5. 向 DEM Freshness Manager 确认结果。
  6. 将 Authentic I-PDU 传递给上层。

由哪个函数提供 Freshness Value，取决于 SecOCUseAuthDataFreshness：

  • 在 FALSE 时，SecOC 调用 SecOC_GetRxFreshness（[SWS_SecOC_00247]、[SWS_SecOC_91007]）。
  • 在 TRUE 时，SecOC 调用 SecOC_GetRxFreshnessAuthData 并在此过程中传递 Authentic I-PDU 的一个片段（[SWS_SecOC_00246]、[SWS_SecOC_91006]）。
  • 在 RTE 模式下，相同的规则适用于 FreshnessManagement 的操作（[SWS_SecOC_00244]、[SWS_SecOC_00245]）。

若检查成功，结果为 SECOC_VERIFICATIONSUCCESS（[SWS_SecOC_00242]），并且 Authentic I-PDU 会发送给上层（PRS SecOC 第18页）。

对于网关，SecOC 支持重新认证路径，即在源总线上进行验证并针对目标总线重新认证。在此过程中不支持“Gatewaying-on-the-fly”（SWS SecOC 第57页、SWS SecOC 图 9.9 第102页）。

时序图：Indication 仅进行缓冲。验证、向 Freshness Manager 确认以及传递在 SecOC_MainFunctionRx 中按照 SWS_SecOC_00040 的顺序进行。来源：SWS SecOC 图 9.5 第100页、[SWS_SecOC_00040]、[SWS_SecOC_00247]、[SWS_SecOC_00243]

时序图：在 TP 接收时，Secured I-PDU 按段完全缓冲，之后才进行验证。来源：SWS SecOC 图 9.6 第101页、[SWS_SecOC_00130]、[SWS_SecOC_00128]、[SWS_SecOC_00125]、[SWS_SecOC_00255]、[SWS_SecOC_00040]

应用接口：验证状态、Override、Default-Pattern

验证状态。每次验证的结果由 SecOC_VerificationStatusType 汇总：Freshness Value ID 以及类型为 SecOC_VerificationResultType 的结果（[SWS_SecOC_00160]、[SWS_SecOC_00149]）。状态报告到何处由 Propagation Mode 规定：

  • 在 BOTH 或 FAILURE_ONLY 时，它通过 VerificationStatusIndication 发送给应用；在 NONE 时，则不进行报告（[SWS_SecOC_00271]、[SWS_SecOC_91016]）。
  • 使用 SecOCPropagateOnlyFinalVerificationStatus = TRUE 时仅报告最终状态，否则还会报告每次失败的中间尝试（[SWS_SecOC_00272]）。
  • Freshness Manager 通过 SecOC_VerificationStatusCallout 获取结果，例如用于同步计数器（[SWS_SecOC_00119]、[SWS_SecOC_00243]）。
  • SecOC_VerifyStatus 将检查结果通知应用（[SWS_SecOC_91014]）。

Override。应用可以通过 SecOC_VerifyStatusOverride 强制指定特定 Freshness Value ID 或 Data ID 的行为（[SWS_SecOC_00122]、[SWS_SecOC_00142]）。SecOC_OverrideStatusType 的 R20-11 取值（[SWS_SecOC_00991]）为：

  • SECOC_OVERRIDE_DROP_UNTIL_NOTICE 和 SECOC_OVERRIDE_DROP_UNTIL_LIMIT：不进行 CSM 检查，丢弃 I-PDU，结果为 SECOC_NO_VERIFICATION。
  • SECOC_OVERRIDE_PASS_UNTIL_NOTICE：执行检查，但无论结果如何，I-PDU 都会被传递。
  • SECOC_OVERRIDE_CANCEL：终止活动的 Override。

来自 R23-11 的文档出处还提到了 SECOC_OVERRIDE_SKIP_UNTIL_LIMIT 和 SECOC_OVERRIDE_PASS_UNTIL_LIMIT（SWS SecOC 第102页）。R20-11 的需求文本在此处的有效负载中被截断。

Default-Pattern。SecOC_SendDefaultAuthenticationInformation 针对每个 Freshness Value ID 开启或关闭使用 SecOCDefaultAuthenticationInformationPattern 发送（[SWS_SecOC_91013]）。仅当配置了此 Pattern 时，该接口才存在（[SWS_SecOC_00002]、[SWS_SecOC_91020]）。

配置、PDU 结构和分离的 Cryptographic I-PDU

配置容器。每个需要保护的发送 PDU 都在 SecOCTxPduProcessing 中配置，每个需要检查的接收 PDU 都在 SecOCRxPduProcessing 中配置。其中分别包括 Data ID、Freshness Value ID、长度和重试计数器（SWS SecOC 第155页、SWS SecOC 第140页）。

PDU 结构。Secured I-PDU 由可选的报头、Authentic I-PDU、可选的 Freshness Value 以及 Authenticator 组成。Freshness Value 和 Authenticator 可以截断传输（SWS SecOC 图 5 第29页）。未使用的区域由 SecOC 填充 SecOCTxPduUnusedAreasDefault（[SWS_SecOC_00269]）。接收端截取多少作为 Authentic I-PDU，取决于报头和长度类型：

  • 在无报头且为静态长度时，以全局 PDU 的配置长度为准（[SWS_SecOC_00257]）。
  • 在无报头且为动态长度时，以下层报告的长度为准（[SWS_SecOC_00258]）。
  • 在有报头时，以报头中的长度为准（[SWS_SecOC_00259]）。

分离的 Cryptographic I-PDU。使用 SecOCTxSecuredPduCollection 时，Secured I-PDU 会作为两条报文发送：作为 Authentic I-PDU 和作为单独的 Cryptographic I-PDU（[SWS_SecOC_00201]、TPS SystemTemplate 图 6.18 第244页）。为此适用以下规则：

  • 两条报文在同一个 Main Function 周期内发送（[SWS_SecOC_00202]）。
  • Message Linker（即在 Cryptographic I-PDU 中重复的 Authentic I-PDU 片段）将这两条报文关联起来（[SWS_SecOC_00209]、[SWS_SecOC_00210]）。
  • 只有当两条带有匹配 Linker 的报文均就绪时，接收端才会进行验证（[SWS_SecOC_00203]、[SWS_SecOC_00211]）。
  • 成功后，SecOC 清空两个缓冲区。失败后，两者均保持缓冲状态，并在有新数据时重新进行检查（[SWS_SecOC_00207]、[SWS_SecOC_00208]）。
  • 仅当两次发送确认均为 E_OK 时，上层才会收到 E_OK（[SWS_SecOC_00270]）。
  • 在采用溢出策略 QUEUE 时，不允许进行 Rx-Collection（[SWS_SecOC_CONSTR_00265]）。

发生错误时的行为

发送端。

  • 若 CSM 报告可恢复错误（例如 E_BUSY），则 SecOC 不发送 Secured I-PDU。Authentic I-PDU 将被保留，并在下一个 Main Function 中重新认证（[SWS_SecOC_00151]）。
  • 若达到 SecOCAuthenticationBuildAttempts，SecOC 向 DET 报告 SECOC_E_CRYPTO_FAILURE（[SWS_SecOC_00155]）。
  • 在达到上限、Freshness 查询出现 E_NOT_OK 或发生不可恢复的 CSM 错误时，如果启用了 Default-Pattern，SecOC 将使用 Default-Pattern 发送（[SWS_SecOC_00229]）。
  • 若未配置该 Pattern，SecOC 会移除 Authentic I-PDU 并中止发送请求（SWS SecOC 第124页）。已配置但未激活的 Pattern 大概也会按相同方式处理，因为 [SWS_SecOC_00229] 的其余部分在有效负载中被截断。

数据传输中的中止和错误。

  • 若上层通过 SecOC_IfCancelTransmit 或 SecOC_TpCancelTransmit 中止（[SWS_SecOC_00113]、[SWS_SecOC_91009]），SecOC 会立即通知下层，停止所有关联动作并释放缓冲区（SWS SecOC 第48页）。
  • 若下层报告发送错误，SecOC 对其的处理仅为不向上层发送确认（同上）。
  • 若 PduR_SecOCTpCopyTxData 返回 BUFREQ_E_BUSY，SecOC 会在下一个 Main Function 中重试该调用。对于 BUFREQ_E_NOT_OK，SecOC 立即以 E_NOT_OK 中止（[SWS_SecOC_00260]、[SWS_SecOC_00266]）。
  • 对于接收，当出现 PduR_SecOCTpCopyRxData 时情况相同（[SWS_SecOC_00267]）。

接收端。SecOC 为每个 Secured I-PDU 维护两个计数器，在首次处理时其值为 0（[SWS_SecOC_00234]、[SWS_SecOC_00235]）：

  • 构建计数器：在新鲜度查询返回 E_BUSY 以及发生可恢复的 CSM 错误（[SWS_SecOC_00236]、[SWS_SecOC_00237]）时递增。低于 SecOCAuthenticationBuildAttempts 时，将在下一个 Rx Main Function 中重试（[SWS_SecOC_00238]）。达到上限时，SecOC 会以 SECOC_AUTHENTICATIONBUILDFAILURE 丢弃该 PDU（[SWS_SecOC_00240]）。
  • 验证计数器：在发生真正的校验失败时递增，同时构建计数器会被重置（[SWS_SecOC_00239]）。达到上限 SecOCAuthenticationVerifyAttempts 或在 E_NOT_OK/KEY_FAILURE 时，SecOC 会以 SECOC_VERIFICATIONFAILURE 丢弃该 PDU（[SWS_SecOC_00241]）。

如果新鲜度查询返回 E_NOT_OK，则该 PDU 将以 SECOC_FRESHNESSFAILURE 被丢弃（[SWS_SecOC_00256]）。相反，[SWS_SecOC_00248] 将同一种情况描述为计数的验证失败，并带有 DET 报告 SECOC_E_FRESHNESS_FAILURE（[SWS_SecOC_00114]）。解释：两项需求均适用于 R20-11。规范未明确二者如何相互区分；集成项目应与供应商澄清该问题。

Override 可以覆盖丢弃行为（[SWS_SecOC_00240]）。如果静态长度的 PDU 过短，SecOC 会静默丢弃它（[SWS_SecOC_00268]）。R20-11 将此与 EcuC 参数 DynamicLength 关联；而 R23-11 文档位置则改用 SecOCDynamicRuntimeLengthHandling（SWS SecOC 第52页）。

安全事件。SecOC 将失败的 MAC 校验和缺失的新鲜度值分别作为 SECOC_SEV_MAC_VERIFICATION_FAILED 和 SECOC_SEV_FRESHNESS_NOT_AVAILABLE 上报给 IdsM（[SWS_SecOC_00274]、[SWS_SecOC_00275]）。

活动图：可恢复错误计入 SecOCAuthenticationBuildAttempts，真正的校验失败计入 SecOCAuthenticationVerifyAttempts；每次中止都会获得独立的结果。来源：SWS SecOC 图 7.5 第42页、SWS SecOC 图 9.10 第103页、[SWS_SecOC_00236]–[SWS_SecOC_00242]、[SWS_SecOC_00256]

Secure Onboard Communication (SecOC)

为关键通信 PDU 提供加密身份验证和新鲜度保护。

特点——概述

  • void SecOC_Init (const SecOC_ConfigType* config); Initializes the the Sec OC module.
  • void SecOC_DeInit (void); This service stops the secure onboard communication.
  • void SecOC_GetVersionInfo (Std_VersionInfoType* versioninfo); Returns the version information of this module.
  • Std_ReturnType SecOC_IfTransmit (PduIdType TxPduId, const PduInfoType* PduInfoPtr); Requests transmission of a PDU.
  • Std_ReturnType SecOC_TpTransmit (PduIdType TxPduId, const PduInfoType* PduInfoPtr); Requests transmission of a PDU.

SecOC_OverrideStatusType 的使用

枚举类型 SecOC_OverrideStatusType 根据 [SWS_SecOC_00991] 定义了用于覆盖 SecOC 模块中验证状态的各种操作模式。该类型通过头文件 Rte_SecOC_Type.h 提供，并控制处理 I-PDU 以及将其转发到上层时的行为。

枚举值根据其语义和有效期进行划分（直至撤销或直至达到计数器 Number Of Messages To Override）：

  • 丢弃（Drop）：在 SECOC_OVERRIDE_DROP_UNTIL_NOTICE（0x00）和 SECOC_OVERRIDE_DROP_UNTIL_LIMIT（0x01）中，不执行认证符验证（不进行 CSM 调用）。受影响的 I-PDU 将被丢弃，且验证结果设置为 SECOC_NO_VERIFICATION。
