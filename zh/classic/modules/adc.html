ADC 驱动程序在 MCAL 中的角色与系统边界

ADC 驱动程序封装了微控制器的模数转换器。Adc_Init 初始化 ADC 硬件单元及驱动程序本身（[SWS_Adc_00365]）。ECU State Manager 将该服务作为可选接口（SWS EcuM 第142页）。典型的使用者是 I/O Hardware Abstraction。它启动组转换，并在组转换完成后接收回调 IoHwAb_AdcNotification<#groupID>（[SWS_Adc_00082]、SWS IoHwAb 第58页）。

向下而言，该驱动程序是最后一层软件层。因此，它不为更低层的模块提供回调（SWS ADC 第79页）。API 不允许直接访问硬件结果寄存器。结果仅存放在应用程序的缓冲区中（SWS ADC 第27页）。驱动程序向 Default Error Tracer 报告错误（[SWS_Adc_00377]）。

分区适用两条规则。模块必须拒绝其实现不支持的分区分配（[SWS_Adc_00531]）。此外，内核分区必须是模块分区的子集（[SWS_Adc_CONSTR_00001]）。

从复位到首次转换：初始化、结果缓冲区、去初始化

Adc_Init 是同步且不可重入的。在变体 PB 中，该服务需要一个指向配置集的指针，而在变体 PC 中则需要 NULL_PTR（[SWS_Adc_00365]）。Adc_ConfigType 的内容是特定于实现的（[SWS_Adc_00505]）。BswM 控制的启动阶段示例调用了 Adc_Init(null)（Modemanagement-Guide 第54页）。第二次 Init 调用被视为开发错误 ADC_E_ALREADY_INITIALIZED（[SWS_Adc_91005]）。

在首次转换之前，每个组都必须获得其结果缓冲区。这通过 Adc_SetupResultBuffer 完成（[SWS_Adc_91000]）。应用程序确保该缓冲区能够容纳该组的所有结果。环境不得在没有有效缓冲区指针的情况下启动转换（SWS ADC 第54页）。Adc_StartGroupConversion 和 Adc_EnableHardwareTrigger 分别将内部写指针重置为此缓冲区的基地址（SWS ADC 第57页、SWS ADC 第62页）。

Adc_DeInit 将所有 ADC 单元置于类似于上电复位的状态（[SWS_Adc_00366]）。在此过程中，所有使用的中断和通知都会被关闭。环境仅当所有组都处于 ADC_IDLE 状态时才允许调用该服务。该服务是否可用取决于开关 AdcDeInitApi（SWS ADC 第59页）。

状态图：模块生命周期在 ADC_UNINIT 和 ADC_INIT 之间切换。在 ADC_INIT 内部，每个组根据配置遵循 One-Shot 或 Continuous 状态机。来源：[SWS_Adc_00365]、[SWS_Adc_00366]、SWS ADC 第31页、SWS ADC 第37页

作为控制单元的通道组：触发源、转换模式与访问方式

受控的始终是通过 Adc_GroupType 标识的通道组（[SWS_Adc_00507]）。通道（[SWS_Adc_00506]）到组的分配在 Adc_GroupDefType 中描述（[SWS_Adc_00517]）。配置器生成通道和组的符号名称（SWS ADC 第123页）。一个组可以包含一个或多个通道（SWS ADC 第35页）。

三个配置维度决定了组的行为：

  • 触发源：软件（ADC_TRIGG_SRC_SW）或硬件（ADC_TRIGG_SRC_HW）（[SWS_Adc_00514]）。对于硬件触发，还可配置边沿选择（[SWS_Adc_00520]）和嵌入式定时器（[SWS_Adc_00521]）。
  • 转换模式：One-Shot 对每次触发将每个通道精确转换一次。Continuous 连续重复转换，且仅支持软件触发（[SWS_Adc_00515]）。
  • 访问方式：Single 或 Streaming（[SWS_Adc_00528]）。采样轮数由 Adc_StreamNumSampleType 确定；在 Single 模式下为 1（[SWS_Adc_00518]）。流式缓冲区以线性或循环方式工作（[SWS_Adc_00519]）。

规范中的图示从这些维度推导出各自的组状态机。软件触发的 One-Shot 在其中仅支持 Single 访问（SWS ADC 第38页、SWS ADC 第39页）。结果是未经缩放的原始值（[SWS_Adc_00508]）。它们在缓冲区中的对齐方式可配置为左对齐或右对齐（[SWS_Adc_00525]）。

活动图：根据转换模式、触发源和访问方式确定适用的组状态机。来源：[SWS_Adc_00514]、[SWS_Adc_00515]、[SWS_Adc_00528]、SWS ADC 第38页、SWS ADC 第39页

触发转换、跟踪状态、获取结果

Adc_StartGroupConversion 启动某个组中所有通道的转换，并且是异步工作的（[SWS_Adc_00367]）。根据配置，随后执行 One-Shot 或 Continuous 转换。在此过程中，通知明确不会自动开启（SWS ADC 第57页）。Adc_StopGroupConversion 同步工作（[SWS_Adc_00368]）。该服务停止正在进行的转换，并从队列中移除排队的启动作业（SWS ADC 第58页）。

在没有通知的情况下，用户使用 Adc_GetGroupStatus 查询组状态（[SWS_Adc_00374]）。可能的值包括 ADC_IDLE、ADC_BUSY、ADC_COMPLETED 和 ADC_STREAM_COMPLETED（[SWS_Adc_00513]）。随后，用户使用 Adc_ReadGroup 读取结果。当存在结果时，该服务返回 E_OK（[SWS_Adc_00369]）。它将最后一个完整轮次按通道升序复制到用户的读取缓冲区中。该顺序与流式结果缓冲区中的存储顺序不同（SWS ADC 第61页）。根据状态图，带有软件触发的 One-Shot 组在读取后返回到 ADC_IDLE（SWS ADC 第35页）。

时序图：在没有通知的软件触发 One-Shot 转换中，用户轮询状态直至该组完成，然后进行读取。来源：[SWS_Adc_00367]、[SWS_Adc_00374]、[SWS_Adc_00369]、SWS ADC 第91页、SWS ADC 第92页

用户使用 Adc_EnableGroupNotification 和 Adc_DisableGroupNotification 开关通知（[SWS_Adc_91003]、[SWS_Adc_91004]）。这两个服务均可通过 AdcGrpNotifCapability 在编译时禁用（SWS ADC 第67页）。

硬件触发的组通过 Adc_EnableHardwareTrigger 使能（[SWS_Adc_91001]）。此后，它们在每次触发事件时进行转换。Adc_DisableHardwareTrigger 终止此运行模式（[SWS_Adc_91002]）。该服务移除排队的作业，并在硬件支持的情况下中止正在进行的转换，同时关闭通知。此后该组处于 ADC_IDLE 状态（SWS ADC 第65页）。

时序图：在带有通知的硬件触发下，每个转换轮次都会触发一次回调，随后用户进行读取。在没有通知的情况下，转换则静默继续运行。来源：[SWS_Adc_91001]、[SWS_Adc_91002]、[SWS_Adc_91003]、[SWS_Adc_91004]、SWS ADC 第94页、SWS ADC 第93页

在流式模式下，驱动程序将多个轮次按通道分块写入应用程序的结果缓冲区。仅 Adc_ReadGroup 需要单独的读取缓冲区（SWS ADC 第32页、SWS ADC 第33页）。或者，Adc_GetStreamLastPointer 提供每个通道的有效采样值数量（[SWS_Adc_00375]）。此外，该服务将指针设置到该组第一个通道的最新结果。用户在此必须自行考虑缓冲区结构（SWS ADC 第27页）。线性缓冲区在满时停止转换。循环缓冲区则继续运行并覆盖最旧的值（[SWS_Adc_00519]）。

状态图：在使用软件触发和流式传输的 Continuous 转换中，ADC_COMPLETED 用于区分中间轮次和满缓冲区（ADC_STREAM_COMPLETED）。线性缓冲区和循环缓冲区在读取时分支不同。来源：[SWS_Adc_00513]、[SWS_Adc_00519]、SWS ADC 第39页、SWS ADC 第44页

竞争组：优先级、队列与抢占

Adc_PriorityImplementationType 规定了如何处理并发的组请求。可能的机制包括无机制、仅硬件或硬件与软件（[SWS_Adc_00522]）。优先级范围为 0 到 255；0 为最低（[SWS_Adc_00516]）。

在没有优先级机制且没有队列的情况下，冲突的启动和触发使能将被拒绝并报告运行时错误 ADC_E_BUSY（[SWS_Adc_91006]、SWS ADC 第95页）。若使用软件队列，驱动程序则会存储该作业。一旦当前运行的组完成，它就会处理该作业（SWS ADC 第96页）。

在优先级机制激活的情况下，具有较高优先级的组可以抢占正在运行的组（[SWS_Adc_00523]）。被抢占的组如何处理由 Adc_GroupReplacementType 决定：

  • Abort/Restart: 被中断的轮次完全重新启动。在流式模式下，仅该轮次的值会丢失。
  • Suspend/Resume: 被中断的轮次继续执行。

在这两种情况下，缓冲区中先前轮次的结果均保持不受影响（SWS ADC 第50页）。

时序图：优先级更高的组 1 的硬件触发抢占组 2 正在进行的软件转换。组 2 随后重新启动或恢复执行。来源：[SWS_Adc_00523]、[SWS_Adc_00522]、[SWS_Adc_91001]、SWS ADC 第98页、SWS ADC 第99页

功率状态：IoHwAb 主导下的两阶段切换

功率控制是一项可选功能，且仅影响 ADC 外设。上层必须已经满足系统视角的边界条件。驱动程序仅检查调用是否按正确顺序进行（SWS ADC 第39页）。ADC_FULL_POWER 对应值 0。值 1 至 255 代表功耗递减的状态（[SWS_Adc_00526]）。

切换分为两个阶段进行。

  1. 准备：Adc_PreparePowerState 触发准备工作（[SWS_Adc_00478]）。异步部分由 Adc_Main_PowerTransitionManager 在后台完成（[SWS_Adc_00498]、[SWS_Adc_00499]）。该函数以 AdcMainSchedulePeriod 的周期循环调用，且仅在转换期间需要（[SWS_Adc_00500]）。解释：该调用推测由 BSW-Scheduler 负责，因为该服务通过 SchM_Adc.h 提供（[SWS_Adc_00479]）。在异步情况下，驱动程序通过 IoHwAb_Adc_NotifyReadyForPowerState<#Mode> 报告完成（[SWS_Adc_00480]、[SWS_Adc_00501]）。
  2. 切换：Adc_SetPowerState 激活准备好的状态（[SWS_Adc_00475]）。诸如将通道置于 IDLE 或注销通知等准备步骤必须由 IoHwAb 事先完成。不存在隐式中间状态（SWS ADC 第81页）。

对于正常状态，驱动程序使用来自 Adc_Init 的参数（[SWS_Adc_00483]）。对于其他状态，仅允许进行特定于转换的重新配置（[SWS_Adc_00484]、[SWS_Adc_00485]）。当前状态和目标状态由 Adc_GetCurrentPowerState 和 Adc_GetTargetPowerState 提供（[SWS_Adc_00476]、[SWS_Adc_00477]）。在没有进行转换时，两者相同（SWS ADC 第77页）。

时序图：BswM 模式切换通过 IoHwAb 触发准备、后台完成、就绪通知，并最终完成 ADC 的切换。来源：[SWS_Adc_00478]、[SWS_Adc_00479]、[SWS_Adc_00480]、[SWS_Adc_00475]、SWS IoHwAb 第60页、SWS IoHwAb 第57页

发生错误时的行为

开发错误在 [SWS_Adc_91005] 中定义，并通过 Det_ReportError 报告（[SWS_Adc_00377]）：

  • ADC_E_UNINIT：初始化前调用。
  • ADC_E_PARAM_POINTER：无效指针，例如 Adc_GetVersionInfo 中的 NULL 指针（SWS ADC 第80页）。
  • ADC_E_PARAM_GROUP：组不存在。该服务随后不执行任何操作直接返回（SWS ADC 第67页）。
  • ADC_E_WRONG_CONV_MODE 和 ADC_E_WRONG_TRIGG_SRC：调用与组配置不匹配。
  • ADC_E_NOTIF_CAPABILITY：通知指针为 NULL。

[SWS_Adc_91006] 定义了运行时错误：

  • ADC_E_BUSY：与正在进行的转换、活动的触发器或已排队的作业冲突。
  • ADC_E_IDLE：对处于 ADC_IDLE 状态的组进行调用。
  • ADC_E_NOT_DISENGAGED：组未处于空闲状态。
  • ADC_E_TRANSITION_NOT_POSSIBLE：功率状态不可达。

无优先级的示意图展示了如何通过 Det_ReportRuntimeError 报告 ADC_E_BUSY（SWS ADC 第95页）。

数据访问通过返回值指示问题。当不存在结果时，Adc_ReadGroup 返回 E_NOT_OK（[SWS_Adc_00369]）。失败时 Adc_SetupResultBuffer 同样如此（[SWS_Adc_91000]）。组非静止时调用 Adc_DeInit 属于错误使用，驱动程序会对此进行报告（SWS ADC 第59页）。

功率服务还通过 Adc_PowerStateRequestResultType 报告结果（[SWS_Adc_00527]）。可能的值包括 ADC_NOT_INIT、ADC_SEQUENCE_ERROR、ADC_HW_FAILURE、ADC_POWER_STATE_NOT_SUPP 和 ADC_TRANS_NOT_POSSIBLE。此外还适用以下通知：

  • 未初始化时报告 ADC_E_UNINIT（[SWS_Adc_00486]、[SWS_Adc_00496]）。
  • 不支持的状态下报告 ADC_E_POWER_STATE_NOT_SUPPORTED（[SWS_Adc_00488]、[SWS_Adc_00497]）。
  • 通道处于活动状态或仍有注册的通知时报告 ADC_E_NOT_DISENGAGED（[SWS_Adc_00487]）。
  • 目标不可直接到达时报告 ADC_E_TRANSITION_NOT_POSSIBLE（[SWS_Adc_00489]）。

若模块尚未初始化，Adc_Main_PowerTransitionManager 将直接返回而不发送 DET 报告。背景：在启动阶段，调度器可能已调用该函数（[SWS_Adc_00502]）。
