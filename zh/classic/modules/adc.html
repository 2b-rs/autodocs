通过通道组控制微控制器的模拟-数字转换器，并提供其原始值。

ADC 驱动程序在 MCAL 中封装微控制器的模拟-数字转换器，并始终将通道作为已配置的组进行转换：由软件或硬件触发，单次或连续 [SWS_Adc_00515]。在 Adc_Init 之后，诸如 IoHwAb 等用户启动转换。他们通过状态轮询或通知获悉完成情况，然后使用 Adc_ReadGroup 或 Adc_GetStreamLastPointer 读取原始值。该驱动程序可选地支持两级电源状态切换。最重要的约束条件：若未预先使用 Adc_SetupResultBuffer 配置结果缓冲区，则不得启动任何组转换 [SWS_Adc_91000]。

ADC 驱动程序在 MCAL 中封装微控制器的模拟-数字转换器。EcuM 使用 Adc_Init 对其进行初始化 [SWS_Adc_00365]。典型用户是 IoHwAb；它在组转换完成之后接收通知 IoHwAb_AdcNotification<#groupID> [SWS_Adc_00082]。在每次复位之后，首次转换之前必须使用 Adc_SetupResultBuffer 设置足够大的结果缓冲区 [SWS_Adc_91000]。

上下文图：EcuM 初始化，IoHwAb 控制并接收通知，错误发送至 DET，转换在外设中运行。来源：SWS IoHwAb 第55页、[SWS_Adc_00377]

驱动程序始终将通道作为已配置的组进行转换。每个组具有三个设置项：

  • 触发源：软件或硬件 [SWS_Adc_00514]。
  • 转换模式：One-Shot 或 Continuous；Continuous 仅适用于软件触发 [SWS_Adc_00515]。
  • 访问模式：Single 或带有线性或循环缓冲区的 Streaming [SWS_Adc_00528]，[SWS_Adc_00519]。

进度由组状态通过 ADC_IDLE、ADC_BUSY、ADC_COMPLETED 和 ADC_STREAM_COMPLETED 指示 [SWS_Adc_00513]。

状态图：连续 Streaming 转换下的组状态；线性缓冲区在读取后以 ADC_IDLE 结束。来源：SWS ADC 第39页

软件触发的组由 Adc_StartGroupConversion 启动并由 Adc_StopGroupConversion 停止。硬件触发的组通过 Adc_EnableHardwareTrigger 和 Adc_DisableHardwareTrigger 进行切换 [SWS_Adc_00367]，[SWS_Adc_91001]。用户通过轮询 Adc_GetGroupStatus 或通过通知来识别完成情况；通知必须单独使能 SWS ADC 第57页。未缩放的原始值使用 Adc_ReadGroup 或 Adc_GetStreamLastPointer 进行读取 [SWS_Adc_00369]，[SWS_Adc_00375]。

竞争请求由优先级机制、排队和抢占策略来调度 [SWS_Adc_00522]，[SWS_Adc_00523]。若两者皆无，驱动程序将使用 ADC_E_BUSY 拒绝第二个请求 [SWS_Adc_91006]。可选地，驱动程序分两个阶段切换电源状态：使用 Adc_PreparePowerState 进行准备，使用 Adc_SetPowerState 进行切换。异步部分在 Adc_Main_PowerTransitionManager 中运行 [SWS_Adc_00478]，[SWS_Adc_00479]。

ADC 驱动程序在 IoHwAb 与转换器硬件之间的角色

ADC 驱动程序是用于微控制器模拟-数字转换器的 MCAL 模块。Adc_Init 初始化 ADC 硬件单元和驱动程序 [SWS_Adc_00365]。所有其他服务均在通道组上操作，通道组通过数值 ID（Adc_GroupType）进行寻址 [SWS_Adc_00507]。典型用户是 I/O Hardware Abstraction：它代表传感器 SWC 启动转换，并在完成后通过 IoHwAb_AdcNotification<#groupID> 获知通知 [SWS_Adc_00082]，SWS IoHwAb 第55页。驱动程序由 EcuM 初始化，对 EcuM 而言 Adc_Init 是一项可选接口 SWS EcuM 第142页。

该驱动程序位于最底层架构级别。因此，它不为更低层模块提供回调 SWS ADC 第79页。ADC API 不直接访问硬件结果寄存器。结果始终通过应用程序的缓冲区传递给用户 SWS ADC 第27页。驱动程序通过 Det_ReportError 报告错误 [SWS_Adc_00377]。引用的文档出处主要来自 R23-11 至 R25-11。对于 R20-11，规范性约束来自需求。

实现必须拒绝具有不受支持的分区分配的配置 [SWS_Adc_00531]。通过 AdcKernelEcucPartitionRef 引用的分区必须是 AdcEcucPartitionRef 分区的子集 [SWS_Adc_CONSTR_00001]。解释：其背后可能是划分为靠近中断的内核部分和接口部分，正如 Adc 的内存映射示例所示 SWS MemMap 第57页。

生命周期：初始化、结果缓冲区和去初始化

复位后，驱动程序处于 ADC_UNINIT。Adc_Init 导向 ADC_INIT，Adc_DeInit 导向返回 SWS ADC 第31页。Adc_Init 为同步且不可重入。在 PB 变体中，ConfigPtr 指向配置集，PC 变体需要 NULL_PTR [SWS_Adc_00365]。Adc_ConfigType 是特定于实现的结构 [SWS_Adc_00505]。通道和组的符号名称由配置器在配置头文件中创建 SWS ADC 第123页。

每次复位后，在对某一组执行首次转换之前，用户必须使用 Adc_SetupResultBuffer 传递结果缓冲区的起始地址。应用程序确保该缓冲区能够容纳该组的所有结果 [SWS_Adc_91000]。如果没有有效初始化的缓冲区指针，则不得启动任何转换 SWS ADC 第54页。

Adc_DeInit 将所有硬件单元置于与上电复位相当的状态 [SWS_Adc_00366]。该服务禁用所有已使用的中断和通知。仅当所有组均处于 ADC_IDLE 时它才被允许，并且可以通过 AdcDeInitApi 关闭 SWS ADC 第59页。

通道组：触发源、转换模式与访问模式

一个组绑定若干通道 [SWS_Adc_00517]，[SWS_Adc_00506]。它在三个维度上进行配置：

  • 触发源：ADC_TRIGG_SRC_SW 或 ADC_TRIGG_SRC_HW [SWS_Adc_00514]。
  • 转换模式：ADC_CONV_MODE_ONESHOT 在每次触发时对每个通道精确转换一次。ADC_CONV_MODE_CONTINUOUS 连续转换，且仅在使用软件触发时可行 [SWS_Adc_00515]。
  • 访问模式：ADC_ACCESS_MODE_SINGLE 或 ADC_ACCESS_MODE_STREAMING [SWS_Adc_00528]。在 Streaming 时，Adc_StreamNumSampleType 确定轮数 [SWS_Adc_00518]。线性缓冲区一旦填满便停止转换；循环缓冲区则回绕循环 [SWS_Adc_00519]。

分频器、转换时间、采样时间和分辨率不是 API 类型 [SWS_Adc_00509]、[SWS_Adc_00510]、[SWS_Adc_00511]、[SWS_Adc_00512]。对于硬件触发，只要硬件支持，即可设置沿和定时器重载 [SWS_Adc_00520]、[SWS_Adc_00521]。结果为未定标的原始值，采用左对齐或右对齐 [SWS_Adc_00508]、[SWS_Adc_00525]。

Adc_StatusType 描述了组的进度 [SWS_Adc_00513]：

  • ADC_IDLE：未启动。
  • ADC_BUSY：转换正在进行。
  • ADC_COMPLETED：一轮已完成，但不是最后一轮。
  • ADC_STREAM_COMPLETED：结果缓冲区已满。

状态转换取决于配置 SWS ADC 第39页。

读取有两种方式：

竞争组：优先级、排队和抢占

并发请求由 Adc_PriorityImplementationType 调节：无机制、仅硬件或硬件加软件 [SWS_Adc_00522]。优先级范围从 0（最低）到 255 [SWS_Adc_00516]。若某个组被更高优先级的组中断，其当前轮次将重新开始（ADC_GROUP_REPL_ABORT_RESTART）或继续执行（ADC_GROUP_REPL_SUSPEND_RESUME）。在这两种情况下，先前轮次的结果均予以保留 [SWS_Adc_00523]。

在无优先级且无排队的情况下，驱动程序会以 ADC_E_BUSY 拒绝第二个请求 SWS ADC 第95页。采用软件排队时，驱动程序会将其保存并在稍后启动 SWS ADC 第96页。采用优先级机制时，较高优先级的组会抢占正在运行的组 SWS ADC 第97页、SWS ADC 第98页。Adc_StopGroupConversion 还会移除等待中的启动请求 SWS ADC 第58页。

ADC 硬件的功率状态

功率控制为可选功能，且仅限于 ADC 外设。由上层满足架构相关的边界条件；驱动程序仅检查调用顺序 SWS ADC 第39页。Adc_PowerStateType 定义了 ADC_FULL_POWER (0) 以及功耗递减的状态 1..255 [SWS_Adc_00526]。每个请求的结果由 Adc_PowerStateRequestResultType 报告 [SWS_Adc_00527]。

切换分两阶段进行：

  1. 准备：Adc_PreparePowerState 启动准备流程 [SWS_Adc_00478]。异步部分在周期性的 Adc_Main_PowerTransitionManager 中运行 [SWS_Adc_00498]、[SWS_Adc_00479]。其周期由 AdcMainSchedulePeriod 确定 [SWS_Adc_00500]。在异步模式下，它通过 IoHwAb_Adc_NotifyReadyForPowerState<#Mode> 报告就绪状态 [SWS_Adc_00501]、[SWS_Adc_00480]。
  2. 切换：Adc_SetPowerState 激活已准备好的状态 [SWS_Adc_00475]。前置准备工作（如静止通道）由用户负责。不存在隐式中间状态 SWS ADC 第81页。

时序图：由 IoHwAb 协调的异步功率状态切换。来源：SWS IoHwAb 第57页、SWS IoHwAb 第57页、[SWS_Adc_00479]

对 Adc_SetPowerState 推测还适用：正常状态使用与 Adc_Init 相同的配置容器，其他状态仅使用特定于转换的重配置 [SWS_Adc_00483]、[SWS_Adc_00484]、[SWS_Adc_00485]。Adc_GetCurrentPowerState 和 Adc_GetTargetPowerState 提供实际状态和目标状态 [SWS_Adc_00476]、[SWS_Adc_00477]。在没有正在进行的转换时，两者保持一致 SWS ADC 第77页。

发生错误时的行为

驱动程序通过 Det_ReportError 报告开发错误 [SWS_Adc_00377]。[SWS_Adc_91005] 列出了以下内容等：

  • ADC_E_WRONG_TRIGG_SRC
