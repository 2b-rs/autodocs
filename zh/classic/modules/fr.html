在 FlexRay 协议栈中的角色及系统边界

FlexRay 驱动程序（Fr）提供对一个或多个 FlexRay 通信控制器（CC）的统一访问。其唯一用户是 FlexRay 接口（FrIf）。唯一的例外是初始化：EcuM 调用 Fr_Init SWS FrDriver 第15页。除 Fr_Init 和 Fr_GetVersionInfo 之外的所有服务均通过 Fr_CtrlIdx 来寻址控制器，即“Index of FlexRay CC within the context of the FlexRay Driver”（[SWS_Fr_00017]、[SWS_Fr_00032]、[SWS_Fr_00070]）。

向下，Fr 访问 CC 硬件。向外，该模块强制需要 Dem_SetEventStatus 和 Det_ReportRuntimeError [SWS_Fr_00390]。作为可选项，它使用 Det_ReportError 以及 SchM_Enter_Fr/SchM_Exit_Fr [SWS_Fr_00391]。CC 与其他组件共享某些资源，例如 PLL 或内存映射。Fr 本身不配置这些资源；其初始化必须在 Fr 初始化之前完成 SWS FrDriver 第15页。

FrIf 在 Fr 服务中区分强制服务和可选服务：

  • 强制服务包括 Fr_ControllerInit、Fr_GetPOCStatus、Fr_ReceiveRxLPdu、Fr_CheckTxLPduStatus 以及绝对定时器服务 SWS FrIf 第95页。
  • 可选服务包括 Fr_AllSlots、Fr_CancelTxLPdu 以及诊断服务 SWS FrIf 第97页。

许多 FrIf 函数直接封装了一个 Fr 服务。例如 FrIf_GetPOCStatus 封装了函数 Fr_GetPOCStatus SWS FrIf 第67页。

POC 状态机：哪个服务触发哪个转换

FlexRay CC 内部运行协议操作控制（Protocol Operation Control，POC）状态机。其状态转换由硬件事件和主机的 CHI 命令触发。只有五个服务会触发此类命令：Fr_StartCommunication、Fr_HaltCommunication、Fr_AbortCommunication、Fr_SendWUP 和 Fr_ControllerInit。所有其余服务均不得更改 POC 状态 SWS FrDriver 第23页。Fr_POCStateType 映射了这些状态 [SWS_Fr_00505]。各个转换如下：

  • Fr_ControllerInit 从任意状态切换至 POC:config，配置集群、节点和缓冲区参数，并结束于 POC:ready SWS FrDriver 第41页。
  • Fr_StartCommunication 发送命令 RUN 并进入过渡状态 POC:startup。CC 之后是否达到 normal active 或 normal passive，无法得到保证 SWS FrDriver 第42页。
  • Fr_SendWUP 经由 POC:wakeup 转换，随后返回 POC:ready SWS FrDriver 第48页。
  • Fr_HaltCommunication 发送 DEFERRED_HALT；直到当前周期结束时才会达到 POC:halt SWS FrDriver 第45页。
  • Fr_AbortCommunication 发送 FREEZE 并立即从任意状态切换至 POC:halt；在此过程中会设置 vPOC!Freeze SWS FrDriver 第47页。

一个特殊情况是 Fr_SetWakeupChannel。该函数通过 CONFIG 短暂切换至 POC:config，并通过 CONFIG_COMPLETE 返回 POC:ready [SWS_Fr_00091], SWS FrDriver 第49页。它在状态变更服务列表中缺失。净结果是 CC 保持在 POC:ready，但必须注意该中间步骤。

Fr_GetPOCStatus 读取 CHI 变量 vPOC，且没有 CC 前置条件 SWS FrDriver 第51页。结果为一个包含以下字段的 Fr_POCStatusType [SWS_Fr_00510]：

  • State;
  • ErrorMode，其取值为 FR_ERRORMODE_ACTIVE、FR_ERRORMODE_PASSIVE 和 FR_ERRORMODE_COMM_HALT [SWS_Fr_00507]；
  • SlotMode [SWS_Fr_00506];
  • StartupState [SWS_Fr_00509];
  • WakeupStatus [SWS_Fr_00508];
  • 标志 Freeze、CHIHaltRequest、CHIReadyRequest 和 ColdstartNoise。

从 Fr_Init 到所有时隙中的通信

Fr_Init 是同步且不可重入的 [SWS_Fr_00032]。该函数保存配置地址以供所有后续调用使用 SWS FrDriver 第39页。在 R20-11 中，Fr_ConfigType 是一种特定于实现的 Post-Build 类型，“derived from void” [SWS_Fr_91001]。后续文档版本将其描述为 Structure SWS FrDriver 第34页。变更历史将此更改定位于 R22-11 SWS FrDriver 第1页。对于 R20-11，以需求文本为准。

此后，Fr_ControllerInit 将每个 CC 置于 POC:ready，并确保不再有待处理的发送请求 SWS FrDriver 第41页。对于唤醒，Fr_SetWakeupChannel 选择通道；仅 FR_CHANNEL_A 和 FR_CHANNEL_B 有效 [SWS_Fr_00091]。随后 Fr_SendWUP 在 POC:ready 中发送唤醒图案。这并不一定会唤醒所有节点 SWS FrDriver 第48页。重试由 FrSM 负责：它等待 FR_READY 并评估 vPOC!WakeupStatus，例如 FR_WAKEUP_RECEIVED_HEADER 或 FR_WAKEUP_TRANSMITTED SWS FrSM 第27页。Fr_GetWakeupRxStatus 按通道按位编码报告接收到的唤醒 [SWS_Fr_00587]。

启动时调用 Fr_AllowColdstart（在 POC:ready 或 POC:startup 中允许），然后调用 Fr_StartCommunication SWS FrDriver 第43页, [SWS_Fr_00010]。这两个服务都是异步的。因此，调用者很可能通过重复调用 Fr_GetPOCStatus 来观察是否成功（推断）。该流程推测由 FrSM 通过 FrIf 控制；其状态映射到 POC 状态 SWS FrSM 第18页。一旦 CC 与全局时间同步，Fr_AllSlots 就会请求在下一个周期从仅密钥时隙模式切换到全时隙模式 SWS FrDriver 第44页。在此之前，SlotMode 显示值 FR_SLOTMODE_ALL_PENDING [SWS_Fr_00506]。

LPdu 数据路径：发送、确认、取消、接收

所有与发送和接收相关的参数均位于 FrIf 配置中（FrIfLPdu, FrIfFrameTriggering）。FrIf 仅向 Fr 传递 Fr_LPduIdx SWS FrDriver 第25页。Fr_TransmitTxLPdu 是异步的，并接收 LSdu 的缓冲区指针和长度 [SWS_Fr_00092]。调用者可通过 Fr_SlotAssignmentPtr 查询周期、时隙 ID 和通道（Fr_SlotAssignmentType）；NULL_PTR 则无需此操作 [SWS_Fr_91002], SWS FrDriver 第53页。

确认在 FrIf 作业列表中产生。在该列表中，操作 TX_CONFIRMATION 调用 Fr_CheckTxLPduStatus SWS FrIf 第38页。返回状态为 FR_TRANSMITTED、FR_TRANSMITTED_CONFLICT 或 FR_NOT_TRANSMITTED [SWS_Fr_00511]。FrIf 仅在 FR_TRANSMITTED 时确认所包含的 PDU SWS FrIf 第112页。Fr_CancelTxLPdu 取消硬件缓冲区中待处理的发送并返回 E_OK。如果没有任何待处理项，该函数返回 E_NOT_OK SWS FrDriver 第54页。

Fr_ReceiveRxLPdu 是同步的。该函数写入 LSdu、状态（Fr_RxLPduStatusType）和长度 [SWS_Fr_00093], [SWS_Fr_00512]。FrIf 以两种方式使用它：

如果过滤条件与硬件的接收 FIFO 匹配，Fr 就会将 LPdu 分配给它。一次调用将取出第一个有效帧，并没有专用的 FIFO API SWS FrDriver 第22页。FR_RECEIVED_MORE_DATA_AVAILABLE 用于指示更多条目 [SWS_Fr_00512]。

发生错误时的行为

所有服务均遵循统一约定：E_OK 表示成功且有效写入了输出参数。在 E_NOT_OK 时，输出参数保持不变 SWS FrDriver 第36页。

硬件错误：如果服务检测到 CC 硬件错误，它将调用 Dem_SetEventStatus(FR_E_CTRL_TESTRESULT, DEM_EVENT_STATUS_FAILED) 并返回 E_NOT_OK SWS FrDriver 第43页。当 Fr_ControllerInit 成功验证寄存器后，将报告 PASS SWS FrDriver 第26页。该事件明确不涵盖网络上的协议错误 SWS FrDriver 第28页。

协议错误：为此每个 LPdu 提供 FR_E_LPDU_SLOTSTATUS。它报告时隙状态中的语法、内容和边界违规 [SWS_Fr_00600]。

开发错误：当错误检测启用时，适用代码包括 FR_E_INV_CTRL_IDX、FR_E_INV_TIMER_IDX、FR_E_INV_CYCLE、FR_E_INV_LPDU_IDX、FR_E_PARAM_POINTER 和 FR_E_INIT_FAILED [SWS_Fr_91003]。在初始化之前调用时，推测会报告 FR_E_INIT_FAILED（“Fr module was not initialized”）。这是一项推断，因为相关的需求文本在有效载荷中被截断 SWS FrDriver 第51页。记录了两个特定情况：

  • Fr_GetSyncFrameList 在 Fr_ListSize > 15 时报告错误 FR_E_INV_FRAMELIST_SIZE [SWS_Fr_00667]。
  • Fr_GetVersionInfo 在 NULL_PTR 时报告错误 FR_E_PARAM_POINTER SWS FrDriver 第86页。

运行时错误：定义的唯一运行时错误为 FR_E_INV_POCSTATE（0x09；CC 未处于预期的 POC 状态）[SWS_Fr_91004]。对于此类报告，Det_ReportRuntimeError 被指定为强制接口 [SWS_Fr_00390]。关于错误分类的章节在 R20-11 中进行了修订 SWS FrDriver 第1页。

恢复：Fr_AbortCommunication 立即停止 CC。Fr_ControllerInit 从任意状态（包括 POC:halt）经由 POC:config 返回 POC:ready SWS FrDriver 第41页。如果在唤醒期间 CC 因错误进入 HALT，FrSM 将中止唤醒发送 SWS FrSM 第27页。
