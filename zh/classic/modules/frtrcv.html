控制 FlexRay 收发器硬件：设置操作模式、检测唤醒事件并报告总线错误。

FlexRay 收发器驱动程序通过 Dio 或 Spi 控制 ECU 的收发器芯片，并在 ACTIVE 中提供 NORMAL、RECEIVEONLY、STANDBY 和 SLEEP 模式 [SWS_FrTrcv_00481]。它设置和读取模式，通过周期性轮询或通知检测唤醒事件，将其报告给 EcuM 并提供唤醒原因。对于有源星型拓扑，它按分支查询总线错误并关断或接通分支。如果模式切换失败，它将返回 E_NOT_OK 并保持先前状态不变 [SWS_FrTrcv_00323]。

FlexRay 收发器驱动程序控制 ECU 的收发器芯片。它通过从零开始的索引 FrTrcv_TrcvIdx 寻址各个芯片 [SWS_FrTrcv_00323]。在下层方向上，它根据配置通过 Dio 或 Spi 访问硬件 SWS FrTrcv 图 10.4 第77页。此外，它还使用 Icu、EcuM、Dem 和 Det [SWS_FrTrcv_00334]。在上层方向上，推测主要由 FrIf 代表 FlexRay State Manager 使用这些服务（解释）SWS FrSM 第20页。 问题 (未决)

角色：FlexRay 收发器芯片的硬件抽象

FlexRay 收发器驱动程序控制 ECU 的一个或多个 FlexRay 收发器芯片。所有与通道相关的服务均通过在驱动程序上下文中有效的从零开始的索引 FrTrcv_TrcvIdx 来选择芯片 [SWS_FrTrcv_00323]。该驱动程序提供三组服务：

  • 设置和查询操作模式 [SWS_FrTrcv_00324]，
  • 处理唤醒事件 [SWS_FrTrcv_00325] [SWS_FrTrcv_00331]，
  • 针对有源星型拓扑管理单个分支 [SWS_FrTrcv_00419]。

FrTrcv_GetVersionInfo 明确提供软件模块的版本，而非收发器硬件的版本 SWS FrTrcv 第43页。

在下层方向上，驱动程序通过 Dio 或 Spi 访问芯片。针对唤醒通知，它使用 Icu，报告则发送给 EcuM、Dem 和 Det [SWS_FrTrcv_00334] [SWS_FrTrcv_00321]。访问方式由选择容器 FrTrcvAccess 确定：它仅允许两种备选方案中的一种，即 Dio 访问或 SPI 序列 SWS FrTrcv 图 10.4 第77页。

在上层方向上，推测主要由 FlexRay Interface 使用这些服务。FlexRay State Manager 通过 FrIf_GetTransceiverWUReason 获取集群中每个收发器的唤醒原因 SWS FrSM 第20页。解释：FrIf 将这些请求转发给 FrTrcv。与此相符的是，Fr_GeneralTypes.h 中的公共类型受 FR_GENERAL_TYPES 保护，以便多个收发器驱动程序和 FrIf 可以共享它们 SWS FrTrcv 第34页。 问题 Q-29229b532631a6b5 (未决)

NOT_ACTIVE 与 ACTIVE 之间的操作模式

规范的图 7.1 将这些模式描述为嵌套状态机。在 POWER_ON 内部，驱动程序在上电后处于 NOT_ACTIVE 状态，并通过 FrTrcv_Init() 进入 ACTIVE 状态 SWS FrTrcv 图 7.1 第23页。仅在 ACTIVE 状态下，FrTrcv_TrcvModeType 的四个值有效：FRTRCV_TRCVMODE_NORMAL、FRTRCV_TRCVMODE_RECEIVEONLY、FRTRCV_TRCVMODE_STANDBY 和 FRTRCV_TRCVMODE_SLEEP [SWS_FrTrcv_00481]。调用层使用 FrTrcv_SetTransceiverMode 在这些模式之间切换 [SWS_FrTrcv_00323]。

STANDBY 和 SLEEP 中的唤醒检测、唤醒原因

在切换至 STANDBY 时，驱动程序重新启用 ICU 通道 [SWS_FrTrcv_00491]。此外，只要硬件支持，FrTrcv_SetTransceiverMode 每次切换至 STANDBY 时都会清除收发器中的错误历史记录 SWS FrTrcv 第39页。

发生错误时的行为

开发错误已作规定[SWS_FrTrcv_00085]：

  • FRTRCV_E_FR_INVALID_TRCVIDX (0x01),
  • FRTRCV_E_FR_INVALID_BRANCHIDX (0x02),
  • FRTRCV_E_UNINIT (0x10),
  • FRTRCV_E_PARAM_POINTER (0x15).

它们仅在开发错误检测使能时才会报告。示例包括分支服务中的 FRTRCV_E_UNINIT SWS FrTrcv 第50页 以及 FrTrcv_GetVersionInfo 中的 NULL 指针 SWS FrTrcv 第43页。

作为运行时错误，驱动程序将错误模式下的调用报告为 FRTRCV_E_FR_TRCV_NOT_STANDBY 至 FRTRCV_E_FR_TRCV_NOT_RECEIVEONLY（0x11 至 0x14）。它使用 FRTRCV_E_FR_NO_CONTROL_TRCV (0x16) 报告与器件通信缺失或故障 [SWS_FrTrcv_91001]。这些报告通过 Det_ReportRuntimeError 传递 [SWS_FrTrcv_00493]。例如在收发器访问出错时，FrTrcv_GetTransceiverMode 会触发错误 FRTRCV_E_FR_NO_CONTROL_TRCV SWS FrTrcv 第41页。

出现 E_NOT_OK 时，输出参数保持不变，例如在 FrTrcv_GetTransceiverMode 和 FrTrcv_GetTransceiverError 中 SWS FrTrcv 第48页。模式切换失败时将保持先前的状态 [SWS_FrTrcv_00323]。

活动图：参数和初始化检查会导致开发错误，访问错误会导致运行时错误。检查的顺序属于一种解释。DET 检查仅在错误检测使能时存在。来源：[SWS_FrTrcv_00085]、[SWS_FrTrcv_91001]、[SWS_FrTrcv_00493]

对于生产诊断，驱动程序区分两类收发器：

  • 对于 A 类 GPIO 控制的收发器，活动的 ERRN 引脚（低电平）表示“Fail”，非活动的引脚（高电平）表示“Pass” [SWS_FrTrcv_00489]。
  • 对于 B 类 SPI 控制的收发器，每个置位的位 1…9 都会触发一个总线错误 [SWS_FrTrcv_00488]。

评估在控制器发生意外 HALT 或处于 NORMAL_ACTIVE 时进行。在总线短路的情况下，仅凭驱动程序的“Pass”不足以作为证明 SWS FrTrcv 第26页。Dem_SetEventStatus 仅在 STANDARD_REPORTING 下可用 [SWS_FrTrcv_00334]。
