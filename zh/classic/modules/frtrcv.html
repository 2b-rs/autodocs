FrTrcv 在 FlexRay Interface 与收发器硬件之间的角色

FlexRay 收发器驱动程序（FrTrcv）控制并监控外部 FlexRay 收发器芯片。它设置并读取其工作模式（[SWS_FrTrcv_00323]、[SWS_FrTrcv_00324]）。此外，它还确定唤醒原因（[SWS_FrTrcv_00325]）并清除待处理的唤醒事件（[SWS_FrTrcv_00329]）。对于有源星型收发器，它还会提供每个分支的故障状态，并且可以接通和断开单个分支（[SWS_FrTrcv_00419]、[SWS_FrTrcv_00442]、[SWS_FrTrcv_00443]）。FrTrcv_GetVersionInfo 明确提供该模块的版本，而非收发器硬件的版本（[SWS_FrTrcv_00326]、SWS FrTrcv 第43页）。

面向硬件，该驱动程序通过 MCAL 驱动程序 Dio、Spi 和 Icu 进行访问。它向 DEM、DET 和 EcuM 报告事件。所需的服务和导入的类型在 [SWS_FrTrcv_00334] 和 [SWS_FrTrcv_00321] 中规定。状态转换时的等待时间由其使用 Tm_BusyWait1us16bit 实现（[SWS_FrTrcv_00485]）。

向上层方向，FlexRay Interface 调用 FrTrcv_SetTransceiverMode（SWS FrTrcv 第57页）。FlexRay State Manager 通过 FrIf_SetTransceiverMode 和 FrIf_GetTransceiverWUReason 控制两个通道的收发器（SWS FrSM 第54页）。解释：FrIf 可能会将这些调用映射到同名的 FrTrcv 服务。

上下文图：FrTrcv 位于一方的 FrIf/FrSM 与另一方的 MCAL 驱动程序及收发器硬件之间；诊断和唤醒消息发送至 DEM、DET 和 EcuM。来源：[SWS_FrTrcv_00334]、[SWS_FrTrcv_00485]、[SWS_FrTrcv_00330]、SWS FrTrcv 第57页、SWS FrSM 第54页

从上电到工作模式：初始化与模式切换

上电后，该驱动程序处于 NOT_ACTIVE 状态且未初始化。调用 FrTrcv_Init(ConfigPtr)（[SWS_FrTrcv_00322]）将其转换至 ACTIVE 状态，并进入配置所指定的模式（SWS FrTrcv 第21页、SWS FrTrcv 第23页）。FrTrcv_ConfigType 的结构取决于具体实现（[SWS_FrTrcv_00487]）。用于处理唤醒源的驱动程序必须在 EcuM 的 Restart 块中重新初始化；在此过程中，唤醒通知的触发机制被重新激活（SWS FrTrcv 第37页）。

在 ACTIVE 内部，FrTrcv_TrcvModeType 支持四种模式（[SWS_FrTrcv_00481]）：

  • NORMAL：完全通信。
  • RECEIVEONLY：同 NORMAL，但仅接收。
  • STANDBY：无通信；如果收发器控制供电，ECU 将保持供电。
  • SLEEP：无通信；根据供电职责划分，ECU 可能处于断电状态。

在 STANDBY 和 SLEEP 模式下，只要硬件支持，即可通过总线或本地进行唤醒（SWS FrTrcv 第21页）。对于被动运行（Receive-Only），FrSM 维护并发状态 FRSM_ECU_ACTIVE 和 FRSM_ECU_PASSIVE（SWS FrSM 第18页）。

FrTrcv_SetTransceiverMode 同步工作且不可重入。成功时，该服务返回 E_OK。返回 E_NOT_OK 时，先前的状态保持不变；向可选状态的转换允许失败（[SWS_FrTrcv_00323]）。转换到 STANDBY 时，只要硬件支持，收发器中的错误历史记录将被清除（SWS FrTrcv 第39页）。如果配置了 FrTrcvIcuChannelRef，则通过 ICU 通道进行的唤醒通知适用以下规则：

  • 通道在转换至 STANDBY 时被使能（[SWS_FrTrcv_00491]）。
  • 在转换至 NORMAL 时它们被禁用（[SWS_FrTrcv_00492]）。
  • 驱动程序为此使用 Icu_EnableNotification 和 Icu_DisableNotification（[SWS_FrTrcv_00490]）。

可重入的 FrTrcv_GetTransceiverMode 提供当前模式（[SWS_FrTrcv_00324]）。

状态图：FrTrcv_Init 从 NOT_ACTIVE 引导至所配置的启动模式；之后 FrTrcv_SetTransceiverMode 在四种模式之间切换，且失败的切换会保持模式不变。来源：SWS FrTrcv 第23页、SWS FrTrcv 第21页、[SWS_FrTrcv_00323]、[SWS_FrTrcv_00491]、[SWS_FrTrcv_00492]

时序图：Dio 控制的收发器通过端口访问被置于 STANDBY 并可选进一步置于 SLEEP；等待时间和 ICU 使能对该流程进行补充。来源：SWS FrTrcv 第57页、[SWS_FrTrcv_00485]、[SWS_FrTrcv_00491]

唤醒检测：采样、向 EcuM 报告及唤醒原因

对于 R20-11，针对 FrTrcv_MainFunction 仅记录了签名：服务 ID 为 0x0d，可通过 SchM_FrTrcv.h 获取（[SWS_FrTrcv_00330]）。来自 R23-11 的文档位置更详细地描述了该任务：该函数对处于 STANDBY 和 SLEEP 状态的所有总线进行唤醒事件采样并将其内部存储。其周期由配置确定，且独立于 FlexRay 总线调度（SWS FrTrcv 第49页）。该周期通过 FrTrcvMainFunctionCycleTime 进行设置（ECUC-Parameter 第250页）。

如果调用 FrTrcv_CheckWakeupByTransceiver（[SWS_FrTrcv_00331]），驱动程序会向 ECU State Manager 报告唤醒事件（SWS FrTrcv 第46页）。为此它使用 EcuM_SetWakeupEvent（[SWS_FrTrcv_00334]）。据推测，该报告涉及之前在内部存储的事件。对于通过总线进行的唤醒，还存在一种由驱动程序在 SPI 或 DIO 驱动程序通知它时立即触发的通知。它在调用方上下文中运行，因此在某些情况下可能在中断上下文中运行（SWS FrTrcv 第46页）。

FrTrcv_GetTransceiverWUReason（[SWS_FrTrcv_00325]）以 FrTrcv_TrcvWUReasonType（[SWS_FrTrcv_00074]）的形式提供唤醒原因，具有以下值：

  • FRTRCV_WU_NOT_SUPPORTED
  • FRTRCV_WU_BY_BUS
  • FRTRCV_WU_BY_PIN
  • FRTRCV_WU_INTERNALLY
  • FRTRCV_WU_RESET
  • FRTRCV_WU_POWER_ON

类型定义位于 Fr_GeneralTypes.h 中，因此可由多个收发器驱动程序共享（SWS FrTrcv 第34页）。唤醒原因的具体区分方式在很大程度上取决于硬件（SWS FrTrcv 第42页）。FrTrcv_ClearTransceiverWakeup 在上一层的控制下清除所有类型挂起的唤醒事件。即使在唤醒通知被禁用的情况下，该服务也可使用（[SWS_FrTrcv_00329]、SWS FrTrcv 第44页）。

在双通道唤醒中，FrSM 查询两个通道的唤醒原因，例如 FRTRCV_WU_POWER_ON 或 FRTRCV_WU_BY_BUS。随后它将两个收发器切换至 FRTRCV_TRCVMODE_NORMAL（SWS FrSM 第54页、SWS FrSM 第56页）。

时序图：周期性采样存储唤醒事件；调用 FrTrcv_CheckWakeupByTransceiver 将其报告给 EcuM，随后查询唤醒原因并清除事件。来源：[SWS_FrTrcv_00330]、[SWS_FrTrcv_00331]、[SWS_FrTrcv_00325]、[SWS_FrTrcv_00329]、SWS FrTrcv 第49页

时序图（简化）：FrSM 利用两个通道的唤醒原因来选择唤醒通道，随后将两个收发器切换至 NORMAL。来源：SWS FrSM 第54页、SWS FrSM 第56页、[SWS_FrTrcv_00325]

Active-Star 分支：错误状态和分支控制

仅当配置了 Active Star 的分支时，分支 API 才可用。可选功能在预编译阶段开启或关闭（SWS FrTrcv 第52页）。FrTrcv_GetTransceiverError 针对由 FrTrcv_TrcvIdx 和 FrTrcv_BranchIdx 组成的一对提供 uint32 错误状态。该服务不可重入（[SWS_FrTrcv_00419]）。通过该服务可访问硬件支持的所有 FlexRay EPL 强制错误。在索引无效或缺少状态时，它返回 E_NOT_OK（SWS FrTrcv 第48页）。

故障分支通过 FrTrcv_DisableTransceiverBranch 关闭（[SWS_FrTrcv_00442]）。使用 FrTrcv_EnableTransceiverBranch 重新开启的操作与 FlexRay 总线调度同步进行（[SWS_FrTrcv_00443]、SWS FrTrcv 第51页）。如果索引超出范围，分支状态保持不变。在未预先初始化的情况下，若错误检测处于激活状态，两个服务均报告 FRTRCV_E_UNINIT（SWS FrTrcv 第50页）。

配置、硬件访问和分区

该模块仅支持 VARIANT-PRE-COMPILE，不支持后构建变体。配置由恰好一个容器 FrTrcvGeneral 以及至少一个容器 FrTrcvChannel 组成（SWS FrTrcv 第59页）。针对每个通道，选择容器 FrTrcvAccess 在通过 Dio 进行引脚访问（FrTrcvDioAccess）与通过 Spi 进行访问（FrTrcvSpiSequence）之间进行选择（SWS FrTrcv 第59页、SWS FrTrcv 第77页）。这些依据源自 R23-11 及更高版本。解释：该结构在核心上对于 R20-11 应当是相同的。

全局参数包括：

  • FrTrcvMainFunctionCycleTime
  • FrTrcvDevErrorDetect
  • FrTrcvGetVersionInfo
  • FrTrcvSleepSupported
  • FrTrcvReceiveonlySupport

该列表来自 ECUC-Parameter 第250页。如果设置了 FrTrcvDemReportErrorStatusConfiguration，驱动程序将调用此处配置的具有相同签名的函数，而不是 Dem_SetEventStatus（[SWS_FrTrcv_00475]）。

在分区系统中，该模块在每个分区中作为独立实例工作；API 调用仅对调用分区生效（[SWS_FrTrcv_00494]）。该模块必须拒绝实现不支持的分区分配（[SWS_FrTrcv_00497]）。

发生错误时的行为

开发错误定义在 [SWS_FrTrcv_00085] 中：

  • FRTRCV_E_FR_INVALID_TRCVIDX (0x01)：收发器索引超出范围。
  • FRTRCV_E_FR_INVALID_BRANCHIDX (0x02)：分支索引超出范围。
  • FRTRCV_E_UNINIT (0x10)：在未初始化的情况下调用服务。
  • FRTRCV_E_PARAM_POINTER (0x15)：NULL 指针作为参数。

例如，在错误检测处于激活状态时，向 FrTrcv_GetVersionInfo 传递 NULL 指针会导致 FRTRCV_E_PARAM_POINTER（SWS FrTrcv 第43页）。

运行时错误描述了两种故障表现（[SWS_FrTrcv_91001]）：

  • 在错误的操作模式下调用：FRTRCV_E_FR_TRCV_NOT_STANDBY (0x11) 至 FRTRCV_E_FR_TRCV_NOT_RECEIVEONLY (0x14)。
  • 与收发器通信缺失或错误：FRTRCV_E_FR_NO_CONTROL_TRCV (0x16)。

在收发器访问出错时，FrTrcv_GetTransceiverMode 报告 FRTRCV_E_FR_NO_CONTROL_TRCV（SWS FrTrcv 第41页）。运行时错误通过 Det_ReportRuntimeError 报告；如果配置了 Callout，则会调用该 Callout（[SWS_FrTrcv_00493]）。

针对生产诊断，每个收发器有两个 DEM 事件：

  • 适用于 B 类 SPI 控制的收发器的 FRTRCV_E_FR_BUSERROR_TRCV_<TrcvIdx>。一旦位 1…9 中有任一位被置位，该事件即被视为失败（[SWS_FrTrcv_00488]）。
  • 适用于 A 类 GPIO 控制的收发器的 FRTRCV_E_FR_ERRN_TRCV_<TrcvIdx>。当 ERRN 引脚为低电平有效时，该事件即被视为失败（[SWS_FrTrcv_00489]）。

通信控制器的非预期 HALT 用作“错误”标准，NORMAL_ACTIVE 用作“通过”标准。当总线发生短路时，仅凭驱动程序的通过信息并不充分（SWS FrTrcv 第25页）。更高版本在编写事件名称时不带尖括号；对于 R20-11，规范性依据是来自需求中的名称（SWS FrTrcv 第27页）。

对于返回值始终适用：E_NOT_OK 保持输出参数不变（[SWS_FrTrcv_00324]、[SWS_FrTrcv_00325]、[SWS_FrTrcv_00419]）。在 E_NOT_OK 时收发器模式同样保持不变（[SWS_FrTrcv_00323]）。

使用

同步函数 FrTrcv_ClearTransceiverWakeup 用于根据 [SWS_FrTrcv_00329] 复位收发器待处理的唤醒事件。它可通过头文件 FrTrcv.h 获取，其服务 ID 为 0x0c。

该函数需要的输入参数如下：

类型为 Std_ReturnType 的返回值表示执行结果：

  • E_OK：收发器的唤醒源已成功复位。
  • E_NOT_OK：参数 FrTrcv_TrcvIdx 超出有效取值范围。在这种情况下，唤醒状态保持不变。

错误处理与并发

根据 [SWS_FrTrcv_00329] 中的规范，无效的收发器索引会直接导致返回 E_NOT_OK，而不会篡改内部状态。
