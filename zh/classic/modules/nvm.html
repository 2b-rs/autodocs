NvM 在存储栈中的角色

NVRAM Manager (NvM) 是 Classic Platform 非易失性数据的核心服务。它仅提供隐式访问：在 NV 存储器与 RAM 之间复制块，而应用程序使用 RAM 数据进行操作 [SWS_NvM_00038] [SWS_NvM_00692]。外部环境应仅通过 NvM 访问非易失性存储器 [SWS_NvM_00384]。在下层，NvM 基于 Memory Abstraction Interface (MemIf)。它与 Flash EEPROM Emulation (Fee) 或 EEPROM Abstraction (Ea) 一起提供一个虚拟的线性 32 位地址空间 [SWS_NvM_00051]。上层仅包含 NvM.h [SWS_NvM_00691]。

根据配置，NvM 可通过两种方式获取下层的处理结果。要么由 Fee/Ea 调用回调 NvM_JobEndNotification 和 NvM_JobErrorNotification，要么由 NvM 在轮询模式下查询作业状态 [SWS_NvM_00438] [SWS_NvM_00440] [SWS_NvM_00346]。ErrorDescription 第43页 也对这两种检测方式进行了描述。其他相邻模块：

  • 生产错误发送至 DEM [SWS_NvM_00592]。
  • 开发错误发送至 DET [SWS_NvM_00614]。
  • CRC 由 Crc 模块计算 [SWS_NvM_00466]。
  • NvM 将多块和单块状态通知 BswM [SWS_NvM_00745] [SWS_NvM_00746]。
  • NvM 可选地通过 CSM 对块进行加密 [SWS_NvM_00976]。

NVRAM 块：结构与管理类型

每个 NVRAM 块由三个必需部分组成：NV 块、RAM 块和管理块。ROM 块是可选的 [SWS_NvM_00138] [SWS_NvM_00139]。其组成由块描述符在配置时确定 [SWS_NvM_00140]。各组成部分具体如下：

  • NV 块包含有效数据以及可选的 CRC 和标头 [SWS_NvM_00125]。
  • ROM 块为空或损坏的 NV 块提供默认数据 [SWS_NvM_00020]。
  • 管理块位于 RAM 中，且对应用程序不可见。它保存 Dataset 索引、属性以及错误/状态信息 [SWS_NvM_00134] [SWS_NvM_00135]。

块通过其块 ID 进行寻址 [SWS_NvM_00069]。NvM_BlockIdType 是一个 uint16；Dataset 选择位会缩小其值域 [SWS_NvM_00471]。保留了两个 ID：0 用于多块结果，1 用于配置 ID [SWS_NvM_00244]。

启动：NvM_Init 与 NvM_ReadAll

NvM_Init 仅由 BswM 调用 [SWS_NvM_00693]。配置指针始终为 NULL_PTR [SWS_NvM_00881]。该函数重置内部变量并发出“INIT DONE”信号；此后 NvM 才会处理作业 [SWS_NvM_00399] [SWS_NvM_00257]。出于时间原因，它既不初始化 NVRAM 块也不初始化其他模块，并且不修改任何永久 RAM 块 [SWS_NvM_00091] [SWS_NvM_00193] [SWS_NvM_00400]。

随后由多块作业 NvM_ReadAll [SWS_NvM_00158] 加载数据。该调用仅发出作业信号并立即返回 [SWS_NvM_00243]。它仅在 NvM Master 中可用 [SWS_NvM_00970]。该作业按以下步骤执行：

  1. 首先，它将存储的配置 ID 与编译的配置 ID 进行比较 [SWS_NvM_00073] [SWS_NvM_00246]。
  2. 若 NvMDynamicConfiguration 为 FALSE，它将忽略偏差 [SWS_NvM_00248]。否则执行扩展运行时准备 [SWS_NvM_00249]（NVDataHandling 第15页）。
  3. 之后，它遍历用户块 [SWS_NvM_00244]。它仅处理具有永久 RAM 块或显式同步的块 [SWS_NvM_00118]。

若配置的 RAM-CRC 校验一致，则 RAM 内容被视为有效 [SWS_NvM_00364]。可针对每个块调用单块回调 [SWS_NvM_00281]。总结果为 NVM_REQ_OK，或者一旦有块失败则为 NVM_REQ_NOT_OK [SWS_NvM_00895] [SWS_NvM_00301]。

NvM 向 BswM 报告作业的接受与完成 [SWS_NvM_00888] [SWS_NvM_00889]。BswM 随后继续启动流程，例如使用 Rte_Start()（NVDataHandling 第20页；ModeManagementGuide 第38页）。

时序图：NvM_Init 仅对 NvM 进行准备；块数据仅由异步的 NvM_ReadAll 加载，其完成释放后续的启动流程。来源：[SWS_NvM_00091]、[SWS_NvM_00243]、[SWS_NvM_00516]、[SWS_NvM_00889]、NVDataHandling 第20页、AUTOSAR_SWS_NVRAMManager 第163页

单块作业：队列、优先级与反馈

单块服务如 NvM_ReadBlock 或 NvM_WriteBlock 采用异步工作方式。它们接收参数，将作业排入队列并返回 [SWS_NvM_00195] [SWS_NvM_00208] [SWS_NvM_00766]。成功排队后，结果为 NVM_REQ_PENDING [SWS_NvM_00185]。若队列溢出，该调用返回 E_NOT_OK [SWS_NvM_00184]。仅当某个块未处于等待或处理状态时，才会将其排入队列 [SWS_NvM_00385]。

实际工作在 NvM_MainFunction [SWS_NvM_00256] 中完成。NvM 在此处取出最高优先级的作业并依次处理这些作业 [SWS_NvM_00155]。执行顺序遵循以下规则：

  • 通过 NvMJobPrioritization，NvM 使用两个队列；其中一个用于即时写入作业（碰撞数据）[SWS_NvM_00564] [SWS_NvM_00378]。
  • 即时作业会破坏性地中断正在运行的作业；后者随后会被重新启动 [SWS_NvM_00182] [SWS_NvM_00300] [SWS_NvM_00258]。
  • 若未进行优先级排序，则适用进入顺序 [SWS_NvM_00379]。
  • NvM_WriteAll 不会被中断。在多块作业执行期间到达的读取和写入作业会被排入队列并在其后执行 [SWS_NvM_00567] [SWS_NvM_00568] [SWS_NvM_00569]。

使用哪个 RAM 缓冲区取决于传入的指针。当传入 NULL_PTR 时，NvM 使用永久 RAM 块或显式同步 [SWS_NvM_00898] [SWS_NvM_00899] [SWS_NvM_00900] [SWS_NvM_00901]。其他地址则用作临时 RAM 块，即使已配置了永久 RAM 块 [SWS_NvM_00278] [SWS_NvM_00280]。对于永久 RAM 块，存在专用的 PRAM 服务 [SWS_NvM_00764] [SWS_NvM_00793]（NVDataHandling 第32页）。

结果保存在管理块的错误/状态字段中 [SWS_NvM_00175]，并可通过 NvM_GetErrorStatus 查询 [SWS_NvM_00451]。若配置了单块回调，则每个作业结束时都会从 NvM_MainFunction [SWS_NvM_00740] [SWS_NvM_00347] [SWS_NvM_00467] 中调用该回调。此外，还可以逐块通知 BswM [SWS_NvM_00890] [SWS_NvM_00891]。NvM_CancelJobs 移除某个块的等待中作业；已在运行的作业将继续执行 [SWS_NvM_00536] [SWS_NvM_00537]。

时序图：该调用立即返回；处理以及通过回调或状态查询进行的反馈在后续的 NvM_MainFunction 调用中进行。来源：[SWS_NvM_00185]、[SWS_NvM_00184]、[SWS_NvM_00346]、[SWS_NvM_00347]、[SWS_NvM_00451]、NVDataHandling 第43页

RAM 块状态以及与应用程序的同步

NvM 为永久 RAM 块或镜像维护“有效”或“无效”状态 [SWS_NvM_00132] [SWS_NvM_00128]。对于有效块，它还进一步区分为已更改和未更改 [SWS_NvM_00682] [SWS_NvM_00472]。具体的状态转换如下：

  • 读取和恢复作业在排队或作业启动时使块失效 [SWS_NvM_00198] [SWS_NvM_00227]。
  • 成功读取产生“有效/未更改”状态 [SWS_NvM_00200]。
  • 加载默认值产生“有效/已更改”状态 [SWS_NvM_00366] [SWS_NvM_00228]。若没有默认值，该块保持无效 [SWS_NvM_00658]。
  • 带有 TRUE 的 NvM_SetRamBlockStatus 以及 NvM_ValidateAll 将该块标记为已更改 [SWS_NvM_00406] [SWS_NvM_00856]（EXP_NVDataHandling 第18页）。
  • 成功写入后，该块被视为未更改 [SWS_NvM_00472]。

状态图：读取和恢复作业使 RAM 块暂时无效；只有写入操作才会将“已更改”恢复为“未更改”。初始状态属于推断。来源：[SWS_NvM_00198]、[SWS_NvM_00200]、[SWS_NvM_00366]、[SWS_NvM_00406]、[SWS_NvM_00472]、[SWS_NvM_00658]

在隐式同步中，NvM 与应用程序访问同一个 RAM 块。因此在发出读取或写入作业后，应用程序只有在收到反馈后才可再次使用该块 [SWS_NvM_00698] [SWS_NvM_00699]（EXP_NVDataHandling 第27页）。若多个应用程序共享同一个块，则它们自行负责其一致性 [SWS_NvM_00697]。

作为备选方案，NvMBlockUseSyncMechanism 配置显式同步 [SWS_NvM_00511]。NvM 此时会创建恰好一个 RAM 镜像并将其用作缓冲区 [SWS_NvM_00513] [SWS_NvM_00514]。回调 NvMWriteRamBlockToNvCallback 和 NvMReadRamBlockFromNvCallback 在应用程序与镜像之间进行复制 [SWS_NvM_00515] [SWS_NvM_00516]。它们的签名为 NvM_WriteRamBlockToNvm 和 NvM_ReadRamBlockFromNvm [SWS_NvM_00539] [SWS_NvM_00540]。对于此用例，它们是必需项（BSWModuleDescriptionTemplate 第242页）。

在回调执行前，应用程序可以继续修改其块 [SWS_NvM_00705]（NVDataHandling 第26页）。若回调返回 E_NOT_OK，NvM 将在 NvM_MainFunction 的下一次运行中再次调用它，最多调用 NvMRepeatMirrorOperations 次 [SWS_NvM_00840] [SWS_NvM_00579]。采用显式同步的块不得具有永久 RAM 块 [SWS_NvM_00904]。通过 NvBlockSwComponent，RTE 实现这些回调（NVDataHandling 第34页）。

时序图：在显式同步中，NvM 仅在镜像回调中获取数据，即相对于作业存在延迟；失败的回调会被重试。来源：[SWS_NvM_00515]、[SWS_NvM_00579]、[SWS_NvM_00705]、[SWS_NvM_00840]、[SWS_NvM_00901]、EXP_NVDataHandling 第13页

关闭、保护机制与配置

BswM 通过 NvM_WriteAll 触发关闭 [SWS_NvM_00092]。该调用立即返回，且仅在 NvM Master 中可用 [SWS_NvM_00254] [SWS_NvM_00971]。该作业写入永久 RAM 块或调用镜像回调 [SWS_NvM_00018] [SWS_NvM_00252]。在此之前，它会检查“有效/已更改”状态 [SWS_NvM_00682]。对于写保护和锁定的块，它会跳过而不报告错误 [SWS_NvM_00434] [SWS_NvM_00750]。

为了仅写入已更改的块，如果配置了该 API，用户应通过 NvM_SetRamBlockStatus 报告更改 [SWS_NvM_00408] [SWS_NvM_00453]。对于 storeAtShutdown，这由 RTE 处理（NVDataHandling 第41页）。NvM_CancelWriteAll 仅供 BswM 使用 [SWS_NvM_00703]。当前正在处理的块将以一致的方式完成；其余块将获得 NVM_REQ_CANCELED [SWS_NvM_00238] [SWS_NvM_00236] [SWS_NvM_00237]（ModeManagementGuide 第37页）。

时序图：在运行时报告的更改仅在 NvM_WriteAll 时写入；BswM 可以中止并等待结果通知。来源：[SWS_NvM_00092]、[SWS_NvM_00238]、[SWS_NvM_00682]、[SWS_NvM_00889]、NVDataHandling 第41页

其他保护与配置机制概览：

  • 写保护：写保护是一个块属性。通过 NvMBlockWriteProt，它默认处于激活状态，外部环境可以通过 NvM_SetBlockProtection 解除该保护 [SWS_NvM_00054] [SWS_NvM_00326] [SWS_NvM_00578]。
  • 单次写入：具有 NvMWriteBlockOnce 的块仅写入一次。其保护无法解除，且在首次读取之前的写入作业会被拒绝 [SWS_NvM_00397] [SWS_NvM_00398] [SWS_NvM_00952]。
  • 锁定：通过 NvM_SetBlockLockStatus 进行的锁定无法由其他服务更改 [SWS_NvM_00548] [SWS_NvM_00754]。
  • 完整性：报头中的 Static Block ID 在写入时存入并在读取时校验 [SWS_NvM_00522] [SWS_NvM_00523] [SWS_NvM_00524]。CRC 比较可以避免写入未更改的数据 [SWS_NvM_00849] [SWS_NvM_00850]。
  • 范围：共有三个 API 配置类；Class 1 不支持 DATASET [SWS_NvM_00149] [SWS_NvM_00365]。
  • 首次初始化：NvM_FirstInitAll 写入默认值或使块失效，同时忽略写保护 [SWS_NvM_91001] [SWS_NvM_00913] [SWS_NvM_00919] [SWS_NvM_00931]。

发生错误时的行为

开发错误。在启用错误检测时，NvM 会向 DET 报告以下内容等：

  • NVM_E_UNINIT [SWS_NvM_00614]
  • NVM_E_PARAM_BLOCK_ID [SWS_NvM_00618]
  • NVM_E_PARAM_ADDRESS [SWS_NvM_00616]
  • NVM_E_BLOCK_PENDING [SWS_NvM_00615]
  • NVM_E_BLOCK_LOCKED [SWS_NvM_00748]
  • NVM_E_WRITE_PROTECTED [SWS_NvM_00962]

针对队列已满的情况，还额外定义了 NVM_E_QUEUE_FULL [SWS_NvM_00947]。

读取错误。NvM 自行控制恢复过程（ErrorDescription 第62页）。它逐步执行以下操作：

  1. 发生 CRC 或 Static Block ID 错误时，它会在必要时重新读取 [SWS_NvM_00526] [SWS_NvM_00582]。
  2. 对于 REDUNDANT 块，它会读取第二个 NV 块 [SWS_NvM_00199]。若其中一个副本有效，则结果为 NVM_REQ_OK，且不向 DEM 发送报告 [SWS_NvM_00279] [SWS_NvM_00655]。随后 NvM 尝试恢复冗余；若失败，它将报告 NVM_E_LOSS_OF_REDUNDANCY [SWS_NvM_00531] [SWS_NvM_00546]。
  3. 否则它加载默认值（NVM_REQ_RESTORED_DEFAULTS），而不修改 NV 块 [SWS_NvM_00202] [SWS_NvM_00172]。
  4. 若没有默认值，RAM 块将保持无效 [SWS_NvM_00658]。此时结果取决于错误类型：
    • CRC错误：NVM_REQ_INTEGRITY_FAILED与DEM报告NVM_E_INTEGRITY_FAILED [SWS_NvM_00204] [SWS_NvM_00203]
    • 作业错误：NVM_REQ_NOT_OK与DEM报告NVM_E_REQ_FAILED [SWS_NvM_00359] [SWS_NvM_00654]

已作废的块会产生NVM_REQ_NV_INVALIDATED，且不生成DEM条目[SWS_NvM_00341] [SWS_NvM_00652]。

ErrorDescription 中存在差异地指出了结果值 NVM_REQ_REDUNDANCY_FAILED 和 NVM_REQ_RESTORED_FROM_ROM（ErrorDescription 第62页）。但对于 R20-11，以需求 [SWS_NvM_00279] [SWS_NvM_00202] 为准。

活动图：读取恢复过程经历 Read-Retry、冗余副本和默认数据；之后才会设置错误并报告给 DEM。来源：[SWS_NvM_00526]、[SWS_NvM_00199]、[SWS_NvM_00279]、[SWS_NvM_00202]、[SWS_NvM_00204]、[SWS_NvM_00359]、[SWS_NvM_00341]、AUTOSAR_EXP_ErrorDescription 第76页

写入错误。无论管理类型为何，NvM 都会重试失败的写入过程，最多重试 NVM_MAX_NUM_OF_WRITE_RETRIES 次 [SWS_NvM_00168] [SWS_NvM_00213] [SWS_NvM_00216]。随后它设置 NVM_REQ_NOT_OK 并报告 NVM_E_REQ_FAILED [SWS_NvM_00683] [SWS_NvM_00684]（ErrorDescription 第43页）。若写入校验失败，它会报告 NVM_E_VERIFY_FAILED 并重试写入 [SWS_NvM_00528] [SWS_NvM_00529]。对于 REDUNDANT 块，只要有一个成功写入的副本就足以判定为 NVM_REQ_OK [SWS_NvM_00284]。检查错误数据并在下一次写入前提供有效数据是应用程序的职责 [SWS_NvM_00694] [SWS_NvM_00696]。

类型 NvM_RequestResultType（[SWS_NvM_00470]）基于 uint8，并定义 NVRAM 管理器异步作业的结果和状态值。它通过头文件 Rte_NvM_Type.h 提供（[SWS_NvM_00470]）。异步请求的结果通过 API 服务 NvM_GetErrorStatus 查询，或者可以额外通过回调函数进行指示（[SWS_NvM_00470]）。

  • NVM_REQ_OK（0x00）：上一个异步请求已成功完成。这是复位后的默认值（[SWS_NvM_00470]）。
