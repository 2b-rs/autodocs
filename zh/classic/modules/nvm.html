管理非易失性数据块，并在 RAM 与非易失性存储器之间进行异步同步。

NVRAM 管理器（NvM）是非易失性存储器的唯一访问入口。它在 RAM 与非易失性存储器之间隐式复制 NVRAM 块[SWS_NvM_00038]。启动时，由 BswM 触发的NvM_ReadAll填充 RAM 块；关机时，NvM_WriteAll保存已更改的块。诸如NvM_WriteBlock之类的单个请求被异步排队、按优先级处理，并通过状态或回调进行确认[SWS_NvM_00185]。NvM 通过重试、冗余副本和默认数据来截获读取错误；用户仍必须自行检查块状态。

NVRAM 管理器（NvM）是非易失性存储器的唯一访问入口[SWS_NvM_00384]。它在 NVRAM 与 RAM 之间隐式复制块；应用程序直接使用 RAM 数据[SWS_NvM_00038]。向下它使用带有 Fee 或 Ea 的 Memory Abstraction Interface[SWS_NvM_00051]。它向 BswM 报告状态，向 DEM 和 DET 报告错误[SWS_NvM_00745][SWS_NvM_00592]。

上下文图：NvM 嵌入在用户、BswM、MemIf/Fee/Ea 以及 DEM 和 DET 之间。来源：[SWS_NvM_00384][SWS_NvM_00465][SWS_NvM_00746]

每个 NVRAM 块由 NV 块、RAM 块和管理块组成，可选用包含默认数据的 ROM 块进行补充[SWS_NvM_00138]。存在 Native、Redundant 和 Dataset 类型；它们在 NV 块和 ROM 块的数量上有所不同[SWS_NvM_00557][SWS_NvM_00558][SWS_NvM_00559]。NvM 隐式直接同步 RAM 块，或通过带有回调的 RAM 镜像进行显式同步[SWS_NvM_00511]。

生命周期分为三个步骤：

  • BswM 独占调用NvM_Init[SWS_NvM_00693]。
  • NvM_ReadAll首先检查配置 ID，然后填充 RAM 块[SWS_NvM_00073][SWS_NvM_00718]。
  • 关机时，NvM_WriteAll保存已更改的块[SWS_NvM_00092]。NvM_CancelWriteAll以非破坏性方式中止[SWS_NvM_00238]。

诸如NvM_WriteBlock之类的单个请求被排队，随后处于NVM_REQ_PENDING状态[SWS_NvM_00185]。可选地，NvM 为立即请求使用专用队列[SWS_NvM_00378]。结果由NvM_GetErrorStatus或配置的回调提供[SWS_NvM_00015][SWS_NvM_00740]。

时序图：异步写入请求被排队，在NvM_MainFunction中处理，并通过回调、BswM 消息和状态查询进行确认。来源：[SWS_NvM_00185][SWS_NvM_00347][SWS_NvM_00891]，SWS NvM 第160页

NvM 通过三个阶段截获读取错误：

  • 配置的读取重试[SWS_NvM_00526]，
  • 冗余块的第二个副本[SWS_NvM_00199]，
  • 带有结果NVM_REQ_RESTORED_DEFAULTS的默认数据[SWS_NvM_00202]。

解释：各阶段的顺序可能遵循 Error Description 中的列举。NvM 重复写入错误直至NVM_MAX_NUM_OF_WRITE_RETRIES，然后向 DEM 报告NVM_E_REQ_FAILED[SWS_NvM_00684]。用户自行检查其块的状态[SWS_NvM_00694]。

在存储栈中的角色：非易失性存储器的唯一访问入口

NVRAM 管理器（NvM）统管对非易失性数据的访问。外部环境仅通过 NvM 访问非易失性存储器，NvM 为此提供了回调接口[SWS_NvM_00384]。该访问是隐式的：NvM 在 NVRAM 与共享 RAM 之间复制块。应用程序在遵守同步规则的前提下直接使用 RAM 数据[SWS_NvM_00038][SWS_NvM_00692]。块通过其配置的块 ID 进行选择[SWS_NvM_00069][SWS_NvM_00471]。上层为此仅包含NvM.h[SWS_NvM_00691]。关于隐式更新的图表展示了分工：基础软件的其他部分根据 ECU 状态触发所有块的保存和恢复。SW-C 仅访问其 RAM 块的内容（SWS NvM 第121页）。

向下，NvM 面向 Memory Abstraction Interface 工作。它与 Fee 或 Ea 一起提供虚拟的线性 32 位地址空间[SWS_NvM_00051][SWS_NvM_00465]。NvM 通过 Crc 模块生成校验和[SWS_NvM_00466]。它通过两种途径获知下层作业的结束：

  • 通过MemIf_GetJobResult进行轮询，
  • 在禁用轮询时通过NvM_JobEndNotification和NvM_JobErrorNotification[SWS_NvM_00440][SWS_NvM_00441]（Error Description 第43页）。

生产错误发送至 DEM[SWS_NvM_00592]，开发错误发送至 DET[SWS_NvM_00614]。NvM 向 BswM 报告作业状态[SWS_NvM_00745][SWS_NvM_00746]。

NVRAM 块的结构与三种管理类型

一个 NVRAM 块由必选组成部分 NV 块、RAM 块和管理块构成。带有默认数据的 ROM 块是可选的[SWS_NvM_00138][SWS_NvM_00139][SWS_NvM_00020]。其组成由块描述符在配置时确定[SWS_NvM_00140]。各个组成部分：

  • NV 块携带有效负载数据以及可选的 CRC 和头部[SWS_NvM_00125]（SWS NvM 第39页）。
  • RAM 块可位于全局 RAM 中，不受地址限制[SWS_NvM_00088]。
  • 管理块对应用程序不可见。它保存数据集索引、属性以及错误/状态字段[SWS_NvM_00134][SWS_NvM_00135][SWS_NvM_00136]。

NvM 支持类型NVM_BLOCK_NATIVE、NVM_BLOCK_REDUNDANT和NVM_BLOCK_DATASET[SWS_NvM_00137]。它们在 NV 块和 ROM 块的数量上有所不同[SWS_NvM_00557][SWS_NvM_00558][SWS_NvM_00559]（SWS NvM 第10页）。对于 Dataset 块：

  • NvM_SetDataIndex选择元素。从NvMNvBlockNum开始的索引寻址 ROM 块[SWS_NvM_00014][SWS_NvM_00445]（NV Data Handling 第10页）。
  • 索引不会持久化保存；NvM_Init将其重置为零[SWS_NvM_00160][SWS_NvM_00192]。
  • SW-C 负责正确设置[SWS_NvM_00695]。

生命周期：NvM_Init、NvM_ReadAll 和 NvM_WriteAll

BswM 独占调用NvM_Init[SWS_NvM_00693]。NvM_Init重置队列和状态机，并在内部发出“INIT DONE”信号[SWS_NvM_00399]。它既不初始化 RAM 块，也不初始化下层模块[SWS_NvM_00091][SWS_NvM_00193]。配置指针始终为NULL_PTR[SWS_NvM_00881]。此后NvM_MainFunction才处理请求[SWS_NvM_00257]。

随后NvM_ReadAll填充 RAM 块[SWS_NvM_00718]。该调用仅通知请求。处理过程将被推迟，直至单块请求处理完毕[SWS_NvM_00243]。随后该作业分三步运行：

  1. 首先，它比较存储的配置 ID 与编译的配置 ID[SWS_NvM_00073]。若有偏差，行为取决于NvMDynamicConfiguration：使用NvMDynamicConfiguration == FALSE时，偏差将被忽略[SWS_NvM_00248]。否则，非抗变更块将获得默认数据[SWS_NvM_00249][SWS_NvM_00674]（NV Data Handling 第15页）。
  2. 然后，它遍历除块 ID 0 和 1 之外的用户块[SWS_NvM_00244]。在此过程中，它仅处理具有永久 RAM 块或显式同步的块[SWS_NvM_00118]。
  3. 最后，它将总体结果设置为NVM_REQ_OK或NVM_REQ_NOT_OK[SWS_NvM_00895][SWS_NvM_00301]。

在模式管理示例中，BswM 规则NvMReadAllFinished仅在NvM_ReadAll完成后才启动其余的初始化（Mode Management Guide 第31页）。

时序图：使用NvM_Init、NvM_ReadAll的异步启动，并将多块状态反馈给 BswM。来源：[SWS_NvM_00693][SWS_NvM_00243][SWS_NvM_00073][SWS_NvM_00888][SWS_NvM_00889]，NV Data Handling 第20页

关机时，BswM 调用NvM_WriteAll[SWS_NvM_00092]。该作业的行为如下：

  • 它写入永久 RAM 块，或通过NvM_WriteRamBlockToNvm获取显式同步的数据[SWS_NvM_00252]。
  • 在此之前，它检查“valid/modified”状态[SWS_NvM_00682]。
  • 它跳过受保护和锁定的块，而不报告错误[SWS_NvM_00434][SWS_NvM_00750]。
  • 其他请求不会中断它[SWS_NvM_00567]。

只要 API 已启用，用户就可以使用NvM_SetRamBlockStatus(…, TRUE)标记已更改的块[SWS_NvM_00406][SWS_NvM_00408]。对于 Dirty-Flag 块，由 RTE 执行此调用（NV Data Handling 第41页）。

NvM_CancelWriteAll保留给 BswM[SWS_NvM_00703]，且在没有正在运行的NvM_WriteAll时不起作用[SWS_NvM_00233]。当前块以非破坏性方式完成[SWS_NvM_00238]。其余块和多块结果被赋予NVM_REQ_CANCELED[SWS_NvM_00236][SWS_NvM_00237]（SWS NvM 第161页）。

另外两个多块请求完善了生命周期：

  • NvM_ValidateAll将具有自动验证的块设置为“VALID / CHANGED”[SWS_NvM_00856]。
  • NvM_FirstInitAll使用默认数据写入块，或在不存在默认数据时将其置为无效[SWS_NvM_00913][SWS_NvM_00919]。

所有多块请求的队列长度均为一[SWS_NvM_00380]。

时序图：使用NvM_WriteAll的关机以及通过NvM_CancelWriteAll的可选中止。来源：[SWS_NvM_00092][SWS_NvM_00682][SWS_NvM_00238][SWS_NvM_00237][SWS_NvM_00889]，Mode Management Guide 第37页

单项请求：队列、优先级与反馈

诸如NvM_ReadBlock、NvM_WriteBlock或NvM_RestoreBlockDefaults之类的单块请求是异步的。函数接收参数，将请求排队并返回[SWS_NvM_00195][SWS_NvM_00208][SWS_NvM_00224]。随后块结果处于NVM_REQ_PENDING状态[SWS_NvM_00185]。在队列溢出时，函数返回E_NOT_OK[SWS_NvM_00184]。仅当块尚未处于挂起状态或未在处理中时，才会被排队[SWS_NvM_00385]。

其他服务在调用者上下文中同步生效，例如NvM_SetDataIndex[SWS_NvM_00448]和NvM_GetErrorStatus（SWS NvM 第158页）。NvM_CancelJobs移除某块挂起的请求；但是正在运行的作业将继续执行[SWS_NvM_00536][SWS_NvM_00537]。

处理按优先级串行进行[SWS_NvM_00162]。如果NvMJobPrioritization处于激活状态，NvM 将使用两个队列，其中一个用于立即写入请求（碰撞数据）[SWS_NvM_00564][SWS_NvM_00378]。这样的NvM_WriteBlock会破坏性地中止正在挂起的作业[SWS_NvM_00300]。随后NvM_MainFunction重新启动被中止的作业[SWS_NvM_00258]。在未配置优先级的情况下，NvM 按到达顺序工作，不含立即作业[SWS_NvM_00379]。在多块请求期间到达的请求将被排队并在随后执行[SWS_NvM_00568][SWS_NvM_00569]。

每个异步请求都将其结果存放在错误/状态字段中[SWS_NvM_00175]。NvM_GetErrorStatus读取该字段[SWS_NvM_00015]。此外，还有两条可选的反馈途径：

  • 若配置了回调，NvM_MainFunction将调用NvM_SingleBlockCallbackFunction[SWS_NvM_00740][SWS_NvM_00347]。若无回调，则没有异步通知[SWS_NvM_00742]（SWS NvM 第160页）。
  • 通过NvMBswMBlockStatusInformation，NvM 向 BswM 报告接受状态和结果[SWS_NvM_00890][SWS_NvM_00891]（SWS NvM 第162页）。

时序图：包含 BswM 状态通知、回调和状态查询的异步写入请求。来源：[SWS_NvM_00185][SWS_NvM_00347][SWS_NvM_00740][SWS_NvM_00890][SWS_NvM_00891]，SWS NvM 第160页

RAM 块同步与块状态

NvM 具有两种与应用程序的 RAM 块同步数据的方式。在隐式同步中，它直接在应用程序的该 RAM 块上操作。应用程序提供该块，并在请求结束前不再访问它[SWS_NvM_00698][SWS_NvM_00699]。若传递NULL_PTR，NvM 将使用永久 RAM 块[SWS_NvM_00898][SWS_NvM_00900]。通过指针使用临时块仍然是可行的[SWS_NvM_00278]。PRAM 服务始终在永久 RAM 块上操作[SWS_NvM_00765][SWS_NvM_00794]。在 RTE 场景中，该块是一个 Per-Instance-Memory（NV Data Handling 第32页）。

在显式同步（NvMBlockUseSyncMechanism）中，数据交换通过内部 RAM 镜像进行[SWS_NvM_00511]。该镜像恰好只有一个，按涉及的最大块确定大小[SWS_NvM_00513]。NvM 调用NvMWriteRamBlockToNvCallback或NvMReadRamBlockFromNvCallback[SWS_NvM_00515][SWS_NvM_00516]。如果回调返回E_NOT_OK，它将在下一个周期重试调用，最多重试NvMRepeatMirrorOperations次[SWS_NvM_00579][SWS_NvM_00840]。在回调发生之前，应用程序仍可修改 RAM 块[SWS_NvM_00705]。一个块要么使用显式同步，要么使用永久 RAM 块，不能二者兼具[SWS_NvM_00904]。该机制允许通过 NvBlockSwComponentType 共享块（NV Data Handling 第12页）。

时序图：通过 RAM 镜像进行显式同步的写入请求，包括在返回E_NOT_OK时的重试。来源：[SWS_NvM_00515][SWS_NvM_00705][SWS_NvM_00579][SWS_NvM_00840]，NV Data Handling 第27页

对于永久 RAM 块或镜像，NvM 维护“valid”/“invalid”状态[SWS_NvM_00128][SWS_NvM_00132]。具体的状态转换如下：

  • NvM_ReadBlock在排队时就已将永久 RAM 块置为无效[SWS_NvM_00198]。
  • 读取成功后，其状态为“valid/unchanged”[SWS_NvM_00200]。
  • 加载默认数据后，其状态为“valid/changed”[SWS_NvM_00366]。
  • NvM_SetRamBlockStatus(…, TRUE)将其标记为已更改，并在后台触发 CRC 重新计算[SWS_NvM_00406][SWS_NvM_00121]。
  • 写入成功后，其状态视为“valid/unmodified”[SWS_NvM_00472]。

配置、保护机制与分区关联

对于受限资源，提供了三个 API 配置类[SWS_NvM_00149]。类别 1 不支持 Dataset 块[SWS_NvM_00365]。描述符表通过生成获得[SWS_NvM_00143]。用户在配置时声明内存需求[SWS_NvM_00030]。BSW 模块通过NvBlockNeeds完成此声明（BSWMD Template 第241页）。ECU 集成商由此推导 NvM 配置（Methodology 第444页）。

针对单个块，提供了多种保护机制：

  • 一个属性字段用于管理写保护[SWS_NvM_00054]；NvMBlockWriteProt将其激活为预设值[SWS_NvM_00326]。
  • 带有NvMWriteBlockOnce的块仅能写入一次[SWS_NvM_00397]。在首次读取之前的写入请求会被 NvM 拒绝[SWS_NvM_00952]。
  • 对于锁定的块（NvM_SetBlockLockStatus），NvM_WriteBlock返回E_NOT_OK[SWS_NvM_00749]。NvM_SetRamBlockStatus和NvM_SetBlockProtection均不会改变锁定状态[SWS_NvM_00754]。
  • 可选的还包括 Static-Block-ID 头部[SWS_NvM_00522]、用于防止不必要写入的 CRC 比较[SWS_NvM_00849]以及通过 CSM 的加密[SWS_NvM_00976]。

在存在分区的情况下，NvM 在相应分配的分区上下文中调用接口。通用功能在主分区中运行[SWS_NvM_00969]。NvM_ReadAll和NvM_WriteAll仅由主分区提供[SWS_NvM_00970][SWS_NvM_00971][SWS_NvM_CONSTR00974]。SW-C 通过与块相关的端口访问 NvM：

  • PS_{Block}（服务）[SWS_NvM_00847]
  • PAdmin_{Block}（管理）[SWS_NvM_00843]
  • PM_{Block}（镜像）[SWS_NvM_00844]
  • PNJF_{Block}（作业结束通知）[SWS_NvM_00846]

发生错误时的行为

读取时，NvM 对 MemIf 的消息进行不同处理：

  • CRC 偏差被报告为NVM_E_INTEGRITY_FAILED[SWS_NvM_00203]。
  • 它将MEMIF_JOB_FAILED报告为NVM_E_REQ_FAILED[SWS_NvM_00654]。
  • MEMIF_BLOCK_INVALID仅产生NVM_REQ_NV_INVALIDATED，而无 DEM 报告[SWS_NvM_00341][SWS_NvM_00652]。

随后有多个恢复阶段生效：

  1. 发生 CRC 错误时，接下来执行配置的读取重试[SWS_NvM_00526]。
  2. 对于冗余块，NvM 读取第二个副本并尝试恢复冗余性[SWS_NvM_00199][SWS_NvM_00531]。若失败，它将报告NVM_E_LOSS_OF_REDUNDANCY[SWS_NvM_00546]。
  3. 最后，NvM 加载默认数据，结果为NVM_REQ_RESTORED_DEFAULTS[SWS_NvM_00202]。NV 内容在此过程中保持不变[SWS_NvM_00172]。

如果缺少默认数据，RAM 块仍保持无效[SWS_NvM_00658][SWS_NvM_00204]。解释：各阶段的顺序可能遵循 Error Description 中的列举（Error Description 第62页）。该来源在两点上偏离了 Requirements。它提及NVM_REQ_RESTORED_FROM_ROM而非NVM_REQ_RESTORED_DEFAULTS。此外，它将最终失败笼统地归纳为NVM_E_REQ_FAILED。以上述 Requirements 为规范准则。
