PWM 驱动程序在定时器硬件与 IoHwAb 之间的角色

PWM 驱动程序属于 MCAL。它直接访问微控制器的寄存器，因此不需要下层接口（PWM-SWS 第44页）。作为最底层模块，它不为更深层模块提供任何回调（PWM-SWS 第40页）。它同样不提供服务接口（PWM-SWS 第44页）。它通过 Pwm.h 提供其服务，例如 Pwm_Init [SWS_Pwm_00095]。它从 Std_Types.h [SWS_Pwm_00094] 获取标准类型。文件结构显示在头文件结构图中（PWM-SWS 第12页）。

典型用户包括 I/O Hardware Abstraction 的功率级驱动程序。它通过 PWM 驱动程序设置电压和频率，并通过信号抽象使这些输出对软件组件可见（IoHwAb-SWS 第37页）。ECU State Manager 将 Pwm_Init 列在其可选接口中（EcuM-SWS 第152页）。向上，该驱动程序仅调用三类服务：

  • 已配置的通道回调 Pwm_Notification_<#Channel> [SWS_Pwm_00105]，
  • Det_ReportError [SWS_Pwm_00104],
  • 向 IoHwAb 发送的就绪通知 [SWS_Pwm_00198]。

微控制器各通道之间的差异不是通过 Vendor-API-Infix 进行抽象的，而是通过传入的通道号进行抽象的（BSWMDT 第122页）。需要注意版本之间的差异：R24-11 版本将 Det_ReportRuntimeError 列为必需接口（PWM-SWS 第44页）。对于 R20-11，有效负载仅证明 Det_ReportError 作为可选接口 [SWS_Pwm_00104]。该运行时错误本身在 R20-11 中已有定义 [SWS_Pwm_00202]。

上下文图：PWM 驱动程序位于 PWM 单元与用户之间；向上它仅调用回调、就绪通知和 DET。来源：IoHwAb-SWS 第37页、EcuM-SWS 第152页、[SWS_Pwm_00189]、[SWS_Pwm_00198]、[SWS_Pwm_00104]

通道模型：极性、周期、占空比与通道类

通道通过数值标识符 Pwm_ChannelType 进行寻址 [SWS_Pwm_00106]。周期具有类型 Pwm_PeriodType，其根据平台高效地选定为 8 至 32 位 [SWS_Pwm_00107]。基本概念在术语表中已作规定（PWM-SWS 第9页）：

  • 极性决定了周期开始时的电平。
  • 占空比给出了该起始电平在周期中所占的比例。
  • 空闲状态是 Pwm_SetOutputToIdle 或 Pwm_DeInit 之后的电平。

规范的信号描述针对 PWM_HIGH 和 PWM_LOW 展示了这一点（PWM-SWS 第7页）。

占空比为 16 位宽：0x0000 代表 0 %，0x8000 代表 100 %。作为换算方法，规范推荐 AbsoluteDutyCycle = ((uint32)AbsolutePeriodTime * RelativeDutyCycle) >> 15（PWM-SWS 第18页）。相应地，各服务将该参数限制为 Min=0x0000 和 Max=0x8000 [SWS_Pwm_91000] [SWS_Pwm_91001]。

通道类 Pwm_ChannelClassType 规定了在运行时允许修改的内容 [SWS_Pwm_00110]：

  • PWM_VARIABLE_PERIOD：周期和占空比，
  • PWM_FIXED_PERIOD：仅占空比，
  • PWM_FIXED_PERIOD_SHIFTED：固定且存在相移的周期（若硬件支持）。

相移周期的示意图展示了具有相同周期且起始边沿错开的通道（PWM-SWS 第23页）。各通道的类通过容器 PwmChannel 中的 PwmChannelClass 进行配置（PWM-SWS 第57页）。

通道的必选参数包括（PWM-SWS 第25页）：

  • 所分配的硬件通道，
  • 默认周期和默认占空比，
  • 极性和空闲电平，
  • 通道类。

相移和参考通道是可选的。初始化数据由 Pwm_ConfigType 汇总；其内容取决于具体硬件 [SWS_Pwm_00111]。

生命周期：从 Pwm_Init 到 Pwm_DeInit

Pwm_Init 是同步且不可重入的，并接收指向配置集的指针 [SWS_Pwm_00095]。此后，根据配置，输出处于低电平、高电平或调制状态。在首次调用 Pwm_EnableNotification 之前不会发出通知（PWM-SWS 第46页）。驱动程序已初始化时的二次调用会报告 PWM_E_ALREADY_INITIALIZED [SWS_Pwm_50002]。在初始化之前调用任何其他服务均会报告 PWM_E_UNINIT [SWS_Pwm_20002]。

Pwm_DeInit 同样是同步且不可重入的 [SWS_Pwm_00096]。该函数对模块进行去初始化，将输出置于空闲状态，并关闭 PWM 中断以及边沿通知。通过 PwmDeInitApi 可以将其启用和禁用（PWM-SWS 第27页）。解读：在 Pwm_DeInit 之后，重新执行 Pwm_Init 应该是允许的，因为此时驱动程序再次被视为未初始化（PWM-SWS 第47页）。Pwm_GetVersionInfo 与生命周期无关且是可重入的 [SWS_Pwm_00103]。

状态图：驱动程序通过 Pwm_Init 和 Pwm_DeInit 在未初始化和已初始化之间切换；错误调用将以 DET 报告告终。来源：[SWS_Pwm_00095]、[SWS_Pwm_00096]、[SWS_Pwm_20002]、[SWS_Pwm_50002]、PWM-SWS 第27页

在运行时设置和查询信号

Pwm_SetDutyCycle 用于设置通道的占空比。根据 API 表，该服务是异步的，并且对于不同通道是可重入的 [SWS_Pwm_91000]。在 0 % 和 100 % 时，输出被设置为静态电平：在 0 % 时与极性相反，在 100 % 时与极性相同。在此之间，驱动程序根据周期、占空比和极性进行调制（PWM-SWS 第28页）。如果实现支持，新值将在当前周期结束时生效，否则立即生效（PWM-SWS 第37页）。

活动图：在进行 DET 检查之后，占空比的值决定是输出静态电平还是进行调制。来源：PWM-SWS 第28页、PWM-SWS 第44页、[SWS_Pwm_20002]、[SWS_Pwm_30002]

Pwm_SetPeriodAndDuty 同时设置周期和占空比 [SWS_Pwm_91001]。占空比作为调用参数的一部分，以使频率和占空比保持一致（PWM-RS 第14页）。如果实现支持且配置了 PwmPeriodUpdatedEndperiod，则周期将在当前周期结束时更新。在此过程中，驱动程序必须抑制输出端的毛刺（PWM-SWS 第30页）。该服务仅允许用于 PWM_VARIABLE_PERIOD 类的通道；对于其他通道，驱动程序会报告 PWM_E_PERIOD_UNCHANGEABLE [SWS_Pwm_40002]。时序图仅显示了调用和返回（PWM-SWS 第49页）。API 表中的分类“Asynchronous”具有规范效力。

Pwm_SetOutputToIdle 立即将输出置于配置的空闲状态 [SWS_Pwm_91002]。具有可变周期的通道随后通过 Pwm_SetPeriodAndDuty 重新激活（PWM-SWS 第31页）。

时序图：通道立即被置为空闲状态，并在需要时通过 Pwm_SetPeriodAndDuty 以定义的周期重新激活。来源：PWM-SWS 第50页、PWM-SWS 第31页、[SWS_Pwm_91002]

Pwm_GetOutputState 同步读取输出信号的内部状态，并返回 PWM_HIGH 或 PWM_LOW [SWS_Pwm_00100] [SWS_Pwm_00108]。读取的是 PWM 单元的状态，而非端口引脚上的电平（PWM-RS 第14页）。这两个服务均可关闭：Pwm_SetOutputToIdle 通过 PwmSetOutputToIdle 关闭，Pwm_GetOutputState 通过 PwmGetOutputState 关闭（PWM-SWS 第33页）。

关于并发性：运行时服务仅对不同的通道号可重入 [SWS_Pwm_91001]。Init 和 DeInit 完全不可重入 [SWS_Pwm_00096]。模块必须拒绝包含实现不支持的分区分配的配置 [SWS_Pwm_00203]。分布式使用时的重入级别请参见分发指南（BSW-Verteilungsleitfaden 第18页）。

各通道的边沿通知

Pwm_EnableNotification 用于开启通道的通知。类型为 Pwm_EdgeNotificationType 的参数可选择 PWM_RISING_EDGE、PWM_FALLING_EDGE 或 PWM_BOTH_EDGES [SWS_Pwm_91004] [SWS_Pwm_00109]。挂起的中断将在此过程中被丢弃（PWM-SWS 第35页）。Pwm_DisableNotification 再次关闭通知 [SWS_Pwm_91003]。这两个服务仅在启用 PwmNotificationSupported 时可用（PWM-SWS 第34页）。

驱动程序根据该通道最后一次 Enable 或 Disable 调用来调用回调 Pwm_Notification_<#Channel>。它在 Pwm_Externals.h 中声明；其可重入性取决于用户实现 [SWS_Pwm_00105]。对应的中断标志由驱动程序自行复位（PWM-SWS 第42页）。该示意图展示了这一流程（PWM-SWS 第48页）：

  1. 在 Pwm_Init 之后，通道进行调制，但不发出通知。
  2. 在 Enable 之后，在所选边沿会触发回调。
  3. 在 Disable 之后，不再产生回调。

时序图：通知仅在 Enable 和 Disable 之间发生，根据 Notification 针对每个信号边沿触发。来源：PWM-SWS 第52页、[SWS_Pwm_91004]、[SWS_Pwm_91003]、[SWS_Pwm_00105]

可选的电源状态和 Power Transition Manager

电源状态控制是可选的。仅当设置了 PwmLowPowerStatesSupport 时才会生成其服务（PWM-SWS 第16页）。驱动程序仅负责 PWM 外设。其余边界条件必须已由应用程序、模式管理和 IoHwAb 满足；但调用顺序由驱动程序自行检查（PWM-SWS 第17页）。Pwm_PowerStateType 支持 PWM_FULL_POWER（0x00）以及表示功耗逐渐降低的状态的值 1..255 [SWS_Pwm_00197]。在 R20-11 中，该类型为枚举；后续版本将其派生自 uint8（PWM-SWS 第25页）。

状态切换分为三个步骤进行：

  1. Pwm_PreparePowerState 启动针对目标状态的准备工作 [SWS_Pwm_00183]。
  2. 周期性调用的 Pwm_Main_PowerTransitionManager 处理无法立即完成的步骤 [SWS_Pwm_00189] [SWS_Pwm_00190]。准备就绪后，它会调用 IoHwAb_Pwm_NotifyReadyForPowerState<#Mode> [SWS_Pwm_00198]。该就绪通知仅在异步模式下存在。在初始化之前，该函数返回且不报告 DET 错误（PWM-SWS 第41页）。
  3. Pwm_SetPowerState 将硬件置于已准备好的状态 [SWS_Pwm_00166]。在此之前，负责的 SWC（例如 IoHwAb）必须已将通道置为空闲状态并注销通知。驱动程序不会隐式经历中间状态（PWM-SWS 第36页）。

Pwm_GetCurrentPowerState 返回当前状态 [SWS_Pwm_00177]，Pwm_GetTargetPowerState 返回请求的状态 [SWS_Pwm_00180]。若没有正在进行的转换，两者一致（PWM-SWS 第38页）。在同步流程中，一旦 Prepare 调用返回，准备工作即告完成（IoHwAb-SWS 第61页）。在异步流程中，准备工作在后台继续执行（IoHwAb-SWS 第60页）。

状态图：仅能通过先准备然后设置来达到新的电源状态；错误的顺序将被拒绝。来源：[SWS_Pwm_00183]、[SWS_Pwm_00166]、[SWS_Pwm_00165]、PWM-SWS 第39页、PWM-SWS 第17页

时序图：在异步切换过程中，IoHwAb 协调电源状态的准备、就绪通知和设置。解读：IoHwAb 的步骤顺序经过了简化。来源：IoHwAb-SWS 第60页、[SWS_Pwm_00189]、[SWS_Pwm_00198]

发生错误时的行为

如果开发错误检测处于激活状态，服务会将每个错误报告给 DET。随后跳过其功能执行，以免破坏数据或寄存器（PWM-SWS 第44页）。错误代码在 [SWS_Pwm_00201] 中定义：

代码值原因
PWM_E_INIT_FAILED0x10Pwm_Init 的参数错误
PWM_E_UNINIT0x11未初始化即调用服务 [SWS_Pwm_20002]
PWM_E_PARAM_CHANNEL0x12无效的通道号 [SWS_Pwm_30002]
PWM_E_PERIOD_UNCHANGEABLE0x13对固定周期通道更改周期 [SWS_Pwm_40002]
PWM_E_ALREADY_INITIALIZED0x14重复调用 Pwm_Init [SWS_Pwm_50002]
PWM_E_PARAM_POINTER0x15向 Pwm_GetVersionInfo 传递 NULL

Pwm_GetOutputState 是一个例外：在初始化之前或通道无效时，该服务返回 PWM_LOW [SWS_Pwm_30051]。

电源状态服务还会通过 Pwm_PowerStateRequestResultType 报告其结果 [SWS_Pwm_00165]。不支持的目标状态会导致 PWM_E_POWER_STATE_NOT_SUPPORTED [SWS_Pwm_00174]。若从当前状态无法直接达到目标状态，则会产生 PWM_E_TRANSITION_NOT_POSSIBLE [SWS_Pwm_00175]。查询服务在初始化之前报告 PWM_E_UNINIT（PWM-SWS 第37页）。只要模块仍在使用中，Pwm_SetPowerState 就会报告运行时错误 PWM_E_NOT_DISENGAGED（0x16）[SWS_Pwm_00202]。当通道未处于空闲状态或仍注册有通知时，即属于这种情况（PWM-SWS 第20页）。

Pwm_DisableNotification 的使用

函数 Pwm_DisableNotification（[SWS_Pwm_91003]）用于禁用特定通道的 PWM 信号边沿通知（PWM signal edge notification）。它是模块 Pwm 的组成部分，并通过头文件 Pwm.h 提供。该服务的服务 ID 为 0x06。

调用与参数：

  • 输入参数（in）：传入类型为 Pwm_ChannelType 的 Channel Number 作为输入参数（[SWS_Pwm_91003]）。该参数表示相关 PWM 通道的数字标识符。
  • 输入/输出参数（inout）：无参数（None）。
  • 输出参数（out）：无参数（None）。
  • 返回值：该服务无返回值（返回类型 void）。
  • 执行行为：函数语义被指定为异步（Asynchronous）（[SWS_Pwm_91003]）。

并发性与限制：

在并发调用方面，Pwm_DisableNotification 针对不同通道号是可重入的（Reentrant for different channel numbers）（[SWS_Pwm_91003]）。因此，涉及不同 PWM 通道的调用可以并行或并发执行。

本使用说明基于 AUTOSAR Classic R20-11 版本的规范自动生成。
