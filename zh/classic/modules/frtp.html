在 PDU Router 与 FlexRay Interface 之间根据 ISO 10681-2 对大报文进行分段和重组。

FrTp 根据 ISO 10681-2 在 PduR 和 FrIf 之间传输大报文（[SWS_FrTp_01005]）。它对报文进行分段和重组、控制流量并通过共享的 Tx-PDU 池分配带宽。FrTp_Transmit 仅接收发送请求；实际工作由周期性 FrTp_MainFunction 完成，该函数必须在每个 FlexRay 周期中至少运行一次（[SWS_FrTp_01152]）。支持已确认和未确认的传输，以及未知长度的报文。发生协议错误或无效分段时，FrTp 会中止并向 PduR 报告 E_NOT_OK。

FrTp 是符合 ISO 10681-2 的 FlexRay 传输层。在规范未做专有规定的地方，该模块遵循此标准（[SWS_FrTp_01005]）。它将 PduR 的大 N-SDU 分解为 N-PDU，通过 FrIf_Transmit 转发给 FrIf，并重新组装接收到的帧（[SWS_FrTp_01050]、FrTp SWS 第19页）。仅在状态 FRTP_ON 下进行处理，即在 FrTp_Init 与 FrTp_Shutdown 之间（[SWS_FrTp_01032]、[SWS_FrTp_01036]）。FrTp_MainFunction 必须在每个 FlexRay 周期中至少运行一次（[SWS_FrTp_01152]）。

上下文图：PduR 与 FrIf 之间的 FrTp，由 EcuM 和 BSW-Scheduler 控制。来源：[SWS_FrTp_00577]、FrTp SWS 第21页

发送始终从 FrTp_Transmit 开始。调用仅占用一个通道并设置 TX_SDU_AVAILABLE（[SWS_FrTp_00136]、[SWS_FrTp_01039]）。MainFunction 完成剩余工作：它通过 PduR_FrTpCopyTxData 获取数据，占用第一个空闲的池 PDU，并决定是否分段（[SWS_FrTp_01045]、[SWS_FrTp_01048]）。在“Decoupled Buffer Access”模式下，FrIf 稍后通过 FrTp_TriggerTransmit 获取数据（[SWS_FrTp_01060]）。在每个被接受的请求之后都会有 PduR_FrTpTxConfirmation（[SWS_FrTp_01058]）。

时序图：请求的接收、MainFunction 中的处理、每个 N-PDU 的确认以及最后向 PduR 的确认。来源：FrTp SWS 第44页、[SWS_FrTp_01042]

接收时，FrTp 根据连接配置检查 RxPduId 和地址（[SWS_FrTp_01069]、[SWS_FrTp_01071]）。对于新连接，它调用 PduR_FrTpStartOfReception，将分片向上复制，并在需要时发送 FlowControl（[SWS_FrTp_01078]、[SWS_FrTp_01080]）。支持六种变体：未分段或已分段、带确认或不带确认、已知长度或未知长度（[SWS_FrTp_01007]–[SWS_FrTp_01012]）。多个连接共享 Tx-PDU 池并交替提供服务（[SWS_FrTp_01020]、[SWS_FrTp_01096]）。

发生错误时，FrTp 会在三种情况下中止并向 PduR 报告 E_NOT_OK：Flow Status 无效或中止时，以及在 1:n 连接上需要分段时（[SWS_FrTp_01198]、[SWS_FrTp_01208]）。运行时错误包括 FRTP_E_SEG_ERROR 和 FRTP_E_NO_CHANNEL。FC.WAIT 限制等定时器和计数器用于限制等待时间（[SWS_FrTp_01100]、[SWS_FrTp_01114]）。正在进行的传输可以通过 FrTp_CancelTransmit 和 FrTp_CancelReceive 中止（[SWS_FrTp_01116]、[SWS_FrTp_01181]）。

在 FlexRay 协议栈中的角色与模块状态

FrTp 是符合 ISO 10681-2 的 FlexRay 传输层。在规范未做专有规定的地方，该模块遵循此标准并支持其 N-PDU 格式（[SWS_FrTp_01005]、[SWS_FrTp_01006]）。向上，FrTp 为 PduR 提供服务。PduR 通过 FrTp_Transmit 启动传输、中止传输或修改参数。FrTp 通过 PduR_FrTpStartOfReception、PduR_FrTpCopyRxData、PduR_FrTpCopyTxData、PduR_FrTpRxIndication 和 PduR_FrTpTxConfirmation 返回数据和结果（FrTp SWS 第19页）。向下，FrTp 通过 FrIf_Transmit 传递 N-PDU（[SWS_FrTp_01050]）。FrIf 通过 FrTp_RxIndication、FrTp_TxConfirmation 和 FrTp_TriggerTransmit 回调反馈（FrTp SWS 第21页）。EcuM 调用 FrTp_Init 和 FrTp_Shutdown（FrTp SWS 第19页）。BSW-Scheduler 调用 FrTp_MainFunction（[SWS_FrTp_00162]、FrTp SWS 第81页）。

版本之间的一个差异：后续版本在 FrTp 与 FrIf 之间插入了一个 L-SDU 路由器（LSduR）（FrTp SWS 第19页）。对于 R20-11，适用由 [SWS_FrTp_00577] 和 [SWS_FrTp_01050] 规定的通往 FrIf 的直接接口。

上下文图：FrTp 位于 PduR 与 FrIf 之间，由 EcuM 和 BSW-Scheduler 控制。来源：FrTp SWS 第19页、FrTp SWS 第21页、[SWS_FrTp_00577]

该模块具有两种状态：FRTP_OFF 和 FRTP_ON（[SWS_FrTp_01028]）。状态变量 FrTpState 记录当前适用的状态（[SWS_FrTp_01029]、[SWS_FrTp_01106]）。上电后，FrTp 处于 FRTP_OFF（[SWS_FrTp_01030]）。只有携带指向 FrTp_ConfigType 的指针成功执行 FrTp_Init 后，才会切换到 FRTP_ON（[SWS_FrTp_01032]、[SWS_FrTp_00147]、[SWS_FrTp_01194]）。分段和重组仅在 FRTP_ON 中运行（[SWS_FrTp_01033]）。FrTp_Shutdown 通过直接停止操作来终止所有打开的连接。它释放资源并返回到 FRTP_OFF（[SWS_FrTp_00148]、[SWS_FrTp_01036]）。

状态图：FrTp 仅在 FrTp_Init 和 FrTp_Shutdown 之间处理数据。来源：[SWS_FrTp_01030]、[SWS_FrTp_01032]、[SWS_FrTp_01036]、FrTp SWS 第38页

FrTp_MainFunction 对模块进行调度，是所有处理任务的入口点（[SWS_FrTp_00203]、[SWS_FrTp_00580]）。它必须在每个 FlexRay 周期中至少运行一次（[SWS_FrTp_01152]）。相比之下，回调基本上只设置标志：每个通道存在一个 TX_SDU_AVAILABLE（[SWS_FrTp_00415]、[SWS_FrTp_00416]）。每个可接收的 N-PDU 存在一个 RX_PDU_AVAILABLE，并在处理后清除（[SWS_FrTp_00418]、[SWS_FrTp_00421]）。

符合 ISO 10681-2 的传输变体

FrTp 支持六种帧序列。它们在三个方面有所不同：报文是否分段、接收方是否确认以及传输开始时长度是否已知（FrTp SWS 第27页、FrTp SWS 第31页）：

未分段，无确认，长度已知STFU[SWS_FrTp_01007]
未分段，带确认，长度已知STFA → FC.ACK[SWS_FrTp_01008]
已分段，无确认，长度已知STFU, FC.CTS, CF, CFEOB, LF[SWS_FrTp_01009]
已分段，带确认，长度已知STFA, FC.CTS, CF, CFEOB, LF, FC.ACK[SWS_FrTp_01010]
已分段，无确认，长度未知同上，总长度仅在 LF 中给出[SWS_FrTp_01011], [SWS_FrTp_01067]
已分段，带确认，长度未知同上，另有 FC.ACK[SWS_FrTp_01012]

未知长度传输：

  • 通过编译器开关启用（[SWS_FrTp_01062]）。
  • 使用 FrTp_Transmit 且长度为 0 启动（[SWS_FrTp_01064]、[SWS_FrTp_01043]）。
  • 当通报的长度参数为 0 时结束（[SWS_FrTp_01066]）。
  • 每个通道的标志 TX_SDU_UNKNOWN_MSG_LENGTH 维护该状态（[SWS_FrTp_01101]、[SWS_FrTp_01102]）。
  • 接收方调用 PduR_FrTpStartOfReception，预期长度为 0（[SWS_FrTp_01184]）。
  • 在 1:n 连接上，FrTp_Transmit 通过 E_NOT_OK 拒绝此类请求并报告 FRTP_E_SEG_ERROR（[SWS_FrTp_01187]、FrTp SWS 第47页）。

连接、通道和 PDU 池

每个通信关系都是一个专有的 FrTpConnection。其数量可在 post-build 时配置（[SWS_FrTp_01014]、[SWS_FrTp_01015]）。每个连接都具有一个模块范围内唯一的地址对和一个唯一的 FRTP_SDUID（[SWS_FrTp_01017]、[SWS_FrTp_01018]）。多个连接可以共享一个 FrTpConnectionControl 和一个 FrTpTxPduPool（[SWS_FrTp_01022]、[SWS_FrTp_01020]）。在运行时，多个 FrTpChannel 并行工作；其数量由 FrTpChanNum 确定（[SWS_FrTp_00088]、[SWS_FrTp_00228]）。对于发送和接收，通道分别在“idle”和“busy”之间切换（[SWS_FrTp_01117]、[SWS_FrTp_01025]）。

上下文图：一个半双工通道引用一个 Tx 连接和一个 Rx 连接。两者都引用控制参数和一个 Tx-PDU 池。来源：FrTp SWS 第39页、[SWS_FrTp_01020]、[SWS_FrTp_01088]

地址：

  • 发送时，FrTp 从元数据 SOURCE_ADDRESS_16 和 TARGET_ADDRESS_16 中获取地址。配置的 FrTpLa/FrTpRa 在此具有优先权（[SWS_FrTp_01204]、[SWS_FrTp_01205]）。
  • 接收时，FrTp 将地址作为元数据向上传递。它将相同的地址用于 FlowControl（[SWS_FrTp_01206]）。

FrTp 通过池分配带宽：

  • 池中的 Tx-N-PDU 按网络规划升序排列，并且长度可以不同（[SWS_FrTp_01088]、[SWS_FrTp_01089]）。
  • 通道的 TxPduPendingCounter 对未确认的 N-PDU 进行计数（[SWS_FrTp_01091]、[SWS_FrTp_01092]）。仅当其为 0 时才处理连接（[SWS_FrTp_01094]）。这样 Consecutive Frame 就不会发生超越（FrTp SWS 第61页）。
  • 活动连接轮流处理（[SWS_FrTp_01096]）。
  • 在带宽受限时适用三条规则：StartFrame 和 FlowControl 使用池中的第一个 PDU（[SWS_FrTp_01174]、[SWS_FrTp_01177]）。发送方仅使用 BC.MPPC 个 PDU（[SWS_FrTp_01175]）。池允许重叠（[SWS_FrTp_01176]）。
  • FrIf 必须在一个作业内按升序调度连接的 PDU（FrTp SWS 第122页）。

发送路径：从 FrTp_Transmit 到 PduR_FrTpTxConfirmation

每次发送均以 FrTp_Transmit 开始（[SWS_FrTp_00136]、[SWS_FrTp_00149]）。仅当 TxPduId 有效且通道空闲时，调用才会设置 TX_SDU_AVAILABLE（[SWS_FrTp_01039]）。否则，它以 E_NOT_OK 结束。若针对同一地址已存在正在进行的传输，亦是如此（[SWS_FrTp_01041]、[SWS_FrTp_01200]）。

实际工作由 FrTp_MainFunction 完成：

  1. 它通过 PduR_FrTpCopyTxData 查询可用长度（[SWS_FrTp_01042]）。
  2. 它占用第一个空闲的 FrTpTxPdu（[SWS_FrTp_01045]）。
  3. 它决定是否进行分段（[SWS_FrTp_01048]）。
  4. 它按 PDU 长度复制数据（[SWS_FrTp_01123]）。
  5. 它将具有精确长度的 N-PDU 传递给 FrIf_Transmit（[SWS_FrTp_01051]）。

该流程如 FrTp SWS 第44页 所示。

活动图：在未分段与分段传输之间的决策，包括在 1:n 连接上的中止。来源：[SWS_FrTp_01047]、[SWS_FrTp_01048]、[SWS_FrTp_01208]、FrTp SWS 第51页

对吞吐量至关重要的是：若没有 PDU 空闲，FrTp 将挂起该连接，直至下一次 MainFunction 调用（[SWS_FrTp_01047]）。

在每个 N-PDU 之后，FrIf 都会调用 FrTp_TxConfirmation。这会将 FrTpTxPdu 设置为“idle”（[SWS_FrTp_01052]、[SWS_FrTp_01054]）。一旦满足三个条件，通道和标志即被释放：所有数据已发送、得到肯定确认，以及（若已配置）收到确认（[SWS_FrTp_01056]、[SWS_FrTp_01057]）。每个被接受的请求之后都会有 PduR_FrTpTxConfirmation，仅在成功情况下带有 E_OK（[SWS_FrTp_01058]）。发送有两种缓冲区访问类型：“Immediate”和“Decoupled Buffer Access”（[SWS_FrTp_01084]）。在“Decoupled”情况下，FrIf 稍后通过 FrTp_TriggerTransmit 获取数据。该调用将 Address Information、PCI 和有效负载数据复制到所提供的缓冲区中（[SWS_FrTp_01060]、[SWS_FrTp_01061]、FrTp SWS 第50页）。

时序图：请求同步到达，并在 MainFunction 中异步处理；可选随后进行 TriggerTransmit（Decoupled）。来源：FrTp SWS 第44页、FrTp SWS 第50页、[SWS_FrTp_01058]

接收路径与重组

接收从 FrTp_RxIndication 开始（[SWS_FrTp_00137]）。FrTp 仅在满足两个条件时才处理 N-PDU（[SWS_FrTp_01069]、[SWS_FrTp_01071]）：

  • RxPduId 有效。
  • 目标地址对应于 FrTpLa，源地址对应于 FrTpRa。

否则，该 N-PDU 将被忽略（[SWS_FrTp_01072]）。若没有空闲的 Rx 通道，则处理结束，且 FrTp 报告 FRTP_E_NO_CHANNEL（[SWS_FrTp_01076]、[SWS_FrTp_01186]）。FrTp 将 StartFrame 存放在本地缓冲区中。这样网关即使在短暂资源匮乏的情况下也能正确处理它（FrTp SWS 第56页）。

对于新连接，FrTp 调用 PduR_FrTpStartOfReception。传递的内容包括预期长度以及 StartFrame 的内容和大小（[SWS_FrTp_01078]、[SWS_FrTp_01193]）。R20-11 图示展示了发起此调用的两种变体位置：在 FrTp_RxIndication 中（FrTp SWS 第55页）以及在 FrTp_MainFunction 中（FrTp SWS 第86页）。R23-11 明确允许这两种方式（FrTp SWS 第54页）。

随后，FrTp 通过 PduR_FrTpCopyRxData 复制分片，并在协议有要求时发送 FlowControl（[SWS_FrTp_01138]、[SWS_FrTp_01080]）。当所有数据均已接收且所有 FlowControl 均已确认时，释放该通道（[SWS_FrTp_01081]）。每当 PduR_FrTpStartOfReception 成功时，总会有 PduR_FrTpRxIndication（[SWS_FrTp_01083]）。

时序图：回调进行检查和缓冲，MainFunction 进行重组并发送 FlowControl。来源：FrTp SWS 第55页、[SWS_FrTp_01074]、[SWS_FrTp_01083]

中止与运行时参数

是否支持发送中止由 FrTpTransmitCancellation 静态确定；通过 FrTp_CancelTransmit 触发（[SWS_FrTp_01097]、[SWS_FrTp_00384]）。其作用取决于处理进度：

  • 若请求已被接受但尚未启动，则连接立即释放。接收方察觉不到任何异常（[SWS_FrTp_00385]、FrTp SWS 第63页）。
  • 若传输正在进行，FrTp 将使用 E_OK 将其中止（[SWS_FrTp_01116]）。
  • 当没有活动连接，或者未确认传输的最后一个 N-PDU 已传递给 FrIf 时，将返回 E_NOT_OK（[SWS_FrTp_01116]）。

在分段情况下，接收方会发生超时，从而终止接收（FrTp SWS 第59页）。

时序图：若发送方中止正在进行的分段传输，接收方将通过超时终止接收。来源：[SWS_FrTp_01116]、FrTp SWS 第69页

若 RxPduId 有效，FrTp_CancelReceive 会中止正在进行的接收，并随后返回 E_OK（[SWS_FrTp_01181]、[SWS_FrTp_01183]）。对于未分段接收或正在进行 LastFrame 的情况，该函数将予以拒绝（[SWS_FrTp_01182]）。FrTp_ChangeParameter 在运行时修改 BandwidthControl 值 FrTpSCexp 和 FrTpMaxNbrOfNPduPerCycle（[SWS_FrTp_00242]）。其位布局对应于 FC(CTS) 帧的位布局（[SWS_FrTp_01195]）。用于此的参数标识符为 TP_BC（ComStack Types 第18页）。在正在进行的接收期间，该修改将被拒绝（[SWS_FrTp_01115]）。成功修改后，连接将使用新值（[SWS_FrTp_01156]）。

发生错误时的行为

开发错误定义在 [SWS_FrTp_01201] 中：

  • FRTP_E_UNINIT：未初始化时调用；FrTp_Init 和 FrTp_GetVersionInfo 除外。
  • FRTP_E_PARAM_POINTER：NULL 指针。
  • FRTP_E_INVALID_PDU_SDU_ID：无效的 SDU 或 PDU ID。
  • FRTP_E_INVALID_PARAMETER：无效参数。
  • FRTP_E_UMSG_LENGTH_ERROR：在没有相应配置的情况下使用未知长度（[SWS_FrTp_01134]）。
  • 用于初始化失败的错误码。

这些 API 会检查 ID 和指针，并在有返回值的情况下在出错时返回 E_NOT_OK（[SWS_FrTp_01139]、[SWS_FrTp_01145]、[SWS_FrTp_01147]）。运行时错误为 FRTP_E_SEG_ERROR（0x05）和 FRTP_E_NO_CHANNEL（0x07）。它们通过 Det_ReportRuntimeError 传递（[SWS_FrTp_01208]、[SWS_FrTp_00577]）。

在三种情况下，发送方会中止并伴随 E_NOT_OK 报告 PduR_FrTpTxConfirmation：

  • FlowControl 具有无效的 Flow Status 或 OVFLW/ABT（[SWS_FrTp_01198]）。
  • ACK_RET 指向缓冲区之外的位置（[SWS_FrTp_01199]）。
  • 1:n 连接必须进行分段（FrTp SWS 第51页）。

带有 E_NOT_OK 的 FrTp_TxConfirmation 会释放两侧的通道（[SWS_FrTp_01056]、[SWS_FrTp_01081]）。标志位 RX_ERROR 会记录接收错误，直到允许发送 FlowControl 为止。在做出响应（Retry、否定确认或中止）后，该标志位会被清除（[SWS_FrTp_00429]、[SWS_FrTp_00430]）。在 1:n 连接上既没有确认也没有 Retry（[SWS_FrTp_00598]）。

定时器和超时遵循规范中的表格（[SWS_FrTp_01099]、[SWS_FrTp_01100]、FrTp SWS 第67页）。配置必须满足以下条件：

  • FRTP_TIMEOUT_BS > FRTP_TIME_BR + FRTP_TIME_AR（[SWS_FrTp_00599]）
  • FRTP_TIMEOUT_CR > FRTP_TIME_CS + FRTP_TIME_AS（[SWS_FrTp_01153]）
  • 分离周期指数的界限（[SWS_FrTp_00180]）

关于并发性，该函数针对不同的 PDU-ID 是可重入的，但不得针对相同的 TxPduId 进行并发调用（[SWS_FrTp_00153]）。在每次带有对应 FrTpTxConfirmationPduId 的调用中，该模块会将计数器 TxPduPendingCounter 递减（[SWS_FrTp_01092]）。

  • 在发送端，一旦所有 N-SDU 数据均已发送、result 具有值 E_OK 且已收到可能配置的确认，或者当 result 等于 E_NOT_OK 时直接发生，被占用的通道就会转换到状态 Idle（FrTpTxChannelState = Idle），并且标志 TX_SDU_AVAILABLE 以及 TX_SDU_UNKNOWN_MSG_LENGTH 会被复位（[SWS_FrTp_01056]、[SWS_FrTp_01057]、[SWS_FrTp_01124]）。
  • 在接收端，当所有数据均已接收且所有必需的 Flow-Control-PDU 均已通过 E_OK 确认，或者当确认以 E_NOT_OK 发生时，被占用的接收通道（FrTpRxChannelState = Idle）会被释放（[SWS_FrTp_01081]）。
