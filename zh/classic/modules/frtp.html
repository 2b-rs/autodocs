定位：PduR 与 FlexRay Interface 之间的传输层

FrTp 是 FlexRay 通信的 ISO-10681-2 传输层。该模块位于 PDU Router 与 FlexRay Interface 之间。它将无法装入分配的 FlexRay-L-PDU 中的 I-PDU 拆分为段，并在接收时重新组装它们（SWS FrTp 第11页）。凡 AUTOSAR 未作专门规定之处，均适用 ISO 10681-2（[SWS_FrTp_01005]）。该模块支持其 N-PDU 格式（[SWS_FrTp_01006]）。

PduR 调用服务 FrTp_Transmit、FrTp_CancelTransmit、FrTp_ChangeParameter 和 FrTp_CancelReceive（[SWS_FrTp_00149]、[SWS_FrTp_00150]、[SWS_FrTp_00151]、[SWS_FrTp_01172]）。在反方向上，FrTp 使用 PduR_FrTpStartOfReception、PduR_FrTpCopyRxData、PduR_FrTpRxIndication、PduR_FrTpCopyTxData 和 PduR_FrTpTxConfirmation（SWS FrTp 第19页）。

向下，FrTp 使用 FrIf_Transmit 传递 N-PDU。从下方，它接收调用 FrTp_RxIndication、FrTp_TxConfirmation 和 FrTp_TriggerTransmit（[SWS_FrTp_00152]、[SWS_FrTp_00153]、[SWS_FrTp_00154]、SWS FrTp 第20页）。自 R24-11 起，两者之间还额外设置了一个 L-SDU Router（SWS FrTp 第19页）。而对于 R20-11，适用的则是对 FrIf_Transmit 的直接调用（[SWS_FrTp_01050]、[SWS_FrTp_00577]）。

其他伙伴模块包括：

  • ECU State Manager 调用 FrTp_Init 和 FrTp_Shutdown（SWS FrTp 第19页）。
  • BSW Scheduler 调用 FrTp_MainFunction（[SWS_FrTp_00162]、SWS FrTp 第81页）。
  • FrTp 通过 Det_ReportRuntimeError 报告运行时错误（[SWS_FrTp_00577]）。

上下文图：FrTp 在 PduR 与 FrIf 之间起中介作用，并由 EcuM 和 BSW Scheduler 控制。来源：SWS FrTp 第19页、SWS FrTp 第20页、[SWS_FrTp_00577]

模块生命周期与周期性处理

FrTp 仅有两个内部状态：FRTP_OFF 和 FRTP_ON（[SWS_FrTp_01028]）。当前状态保存在静态变量 FrTpState 中（[SWS_FrTp_01029]、[SWS_FrTp_01106]）。

  • 上电后，该模块处于 FRTP_OFF（[SWS_FrTp_01030]）。
  • 带有指向 FrTp_ConfigType 的指针且成功的 FrTp_Init 会切换到 FRTP_ON（[SWS_FrTp_00147]、[SWS_FrTp_01194]、[SWS_FrTp_01032]）。在此过程中，所有全局变量都会被初始化，并且实例会进入空闲状态。
  • 分段、重组以及所有其余任务仅在 FRTP_ON 中运行（[SWS_FrTp_01033]）。
  • 如果在未初始化的情况下调用某个服务，该服务会报告 FRTP_E_UNINIT。FrTp_Init 和 FrTp_GetVersionInfo 除外（[SWS_FrTp_01201]）。

FrTp_Shutdown 直接中止所有打开的连接并释放资源（[SWS_FrTp_00148]）。之后模块重新回到 FRTP_OFF（[SWS_FrTp_01036]、SWS FrTp 第36页）。

协议进展由 FrTp_MainFunction 驱动。它是所有处理任务的入口点（[SWS_FrTp_00203]、[SWS_FrTp_00580]），并且必须每个 FlexRay 周期至少运行一次（[SWS_FrTp_01152]）。为此，各项服务会设置内部标志，例如 TX_SDU_AVAILABLE 和 RX_PDU_AVAILABLE（[SWS_FrTp_00416]、[SWS_FrTp_00418]、SWS FrTp 第37页）。

状态图：只有 FrTp_Init 能从 FRTP_OFF 转换到 FRTP_ON，且仅在该状态下进行处理。来源：[SWS_FrTp_01030]、[SWS_FrTp_01032]、[SWS_FrTp_01036]、SWS FrTp 第36页

符合 ISO 10681-2 的传输类型

FrTp 支持六种传输类型：

  • 未分段、无确认及带确认，在已知长度时（[SWS_FrTp_01007]、[SWS_FrTp_01008]）；
  • 分段、无确认及带确认，在已知长度时（[SWS_FrTp_01009]、[SWS_FrTp_01010]）；
  • 分段、无确认及带确认，在未知长度时（[SWS_FrTp_01011]、[SWS_FrTp_01012]）。

分段传输由 StartFrame、FlowControl、ConsecutiveFrames 和 LastFrame 组成。ConsecutiveFrame_EOB 结束一个块；随后接收方通过 FlowControl 释放下一个块（SWS FrTp 第28页）。

未知长度的传输按如下方式工作：

  • 该功能通过编译器开关激活（[SWS_FrTp_01062]）。
  • 上层通过 SduLength = 0 对其进行请求（[SWS_FrTp_01043]、[SWS_FrTp_01064]）。
  • 一旦上层报告长度为 0，传输即告结束（[SWS_FrTp_01066]）。
  • FrTp 累加各部分长度并在 LastFrame 中传输总长度（[SWS_FrTp_01067]）。

在 1:n 连接上既没有确认也没有重试（[SWS_FrTp_00598]）。在此类连接上进行分段会导致错误 FRTP_E_SEG_ERROR（[SWS_FrTp_01187]、[SWS_FrTp_01208]）。

时序图：具有两个块的已知长度分段无确认传输，每个块分别通过 FlowControl_CTS 释放。来源：[SWS_FrTp_01009]、SWS FrTp 第28页

发送流程：从 FrTp_Transmit 到 PduR_FrTpTxConfirmation

每个发送过程均始于 FrTp_Transmit（[SWS_FrTp_00136]）。该服务仅在 TxPduId 有效且有通道空闲时才设置 TX_SDU_AVAILABLE（[SWS_FrTp_01039]）。否则它返回 E_NOT_OK（[SWS_FrTp_01040]、[SWS_FrTp_01041]）。如果针对相同的地址信息已有传输在进行，同样适用此规则（[SWS_FrTp_01200]）。地址来自 FrTpLa/FrTpRa 或来自元数据 SOURCE_ADDRESS_16/TARGET_ADDRESS_16（[SWS_FrTp_01204]、[SWS_FrTp_01205]）。

在 MainFunction 中，发送过程按以下步骤进行：

  1. FrTp 通过 PduR_FrTpCopyTxData 确定可用长度（[SWS_FrTp_01042]）。
  2. FrTp 占用池中第一个空闲的 FrTpTxPdu（[SWS_FrTp_01045]）。若无空闲，连接将顺延至下一次调用（[SWS_FrTp_01047]）。
  3. FrTp 根据该 PDU 的长度决定是否必须进行分段（[SWS_FrTp_01048]）。
  4. FrTp 复制 PDU 长度的有效载荷数据（[SWS_FrTp_01123]），并以精确长度通过 FrIf_Transmit 发送（[SWS_FrTp_01050]、[SWS_FrTp_01051]）。
  5. FrTp_TxConfirmation 确认每个 N-PDU 并将 FrTpTxPdu 重置回“idle”（[SWS_FrTp_01052]、[SWS_FrTp_01054]）。

如果 PduR_FrTpCopyTxData 返回 BUFREQ_E_BUSY，FrTp 会重试最多 FrTpTimeCs 次（[SWS_FrTp_01196]）。

一旦满足三个条件，通道和标志即变为空闲：所有数据均已发送、确认是肯定的、且在带确认时最终确认已到达（[SWS_FrTp_01056]、[SWS_FrTp_01057]）。对于每个被接受的作业，FrTp 恰好调用一次 PduR_FrTpTxConfirmation，带有 E_OK 或 E_NOT_OK（[SWS_FrTp_01058]）。

对于发送方向，有两种缓冲模式：“Immediate”和“Decoupled Buffer Access”（[SWS_FrTp_01084]）。在解耦模式下，下层通过 FrTp_TriggerTransmit 获取 N-PDU。此时 FrTp 以精确长度复制地址信息、PCI 和数据（[SWS_FrTp_01060]、[SWS_FrTp_01061]）。由于该调用在中断上下文中运行，AI 和 PCI 应预先在本地缓冲（SWS FrTp 第50页）。

时序图：发送作业被同步接受，并在 MainFunction 中异步处理（Immediate Buffer Access；在 Decoupled 模式下还会增加 FrTp_TriggerTransmit）。来源：SWS FrTp 第44页、[SWS_FrTp_01039]、[SWS_FrTp_01042]、[SWS_FrTp_01058]

活动图：池中第一个空闲 PDU 的长度决定是否进行分段；在 1:n 连接上，若需要分段则会中止传输。来源：[SWS_FrTp_01047]、[SWS_FrTp_01048]、SWS FrTp 第46页、SWS FrTp 第52页

接收流程与重组

接收始终始于 FrTp_RxIndication（[SWS_FrTp_00137]）。FrTp 仅在满足两个条件时才处理 N-PDU（[SWS_FrTp_01069]、[SWS_FrTp_01071]）：

  • RxPduId 有效。
  • 目标地址和源地址与某个 FrTpConnection 的 FrTpLa/FrTpRa 相匹配。

否则该 N-PDU 将被忽略（[SWS_FrTp_01070]、[SWS_FrTp_01072]）。此外，只有在有通道空闲时才会设置 RX_PDU_AVAILABLE（[SWS_FrTp_01074]）。如果缺少空闲通道，FrTp 会报告 FRTP_E_NO_CHANNEL（[SWS_FrTp_01186]）。StartFrame 保持在本地缓冲。这样，网关等便可在通道变为空闲后补发 FlowControl（SWS FrTp 第56页）。

新连接按如下方式进行：

  • FrTp 携带预期长度调用 PduR_FrTpStartOfReception（[SWS_FrTp_01078]）。在未知长度时，该值为 0（[SWS_FrTp_01184]）。StartFrame 的数据和大小会一同传递（[SWS_FrTp_01193]）。
  • 分段通过 PduR_FrTpCopyRxData 向上层传递（[SWS_FrTp_01138]）。
  • FrTp 自身发送协议所要求的 FlowControl-N-PDU（[SWS_FrTp_01080]）。
  • 完全接收后，通道变为空闲（[SWS_FrTp_01081]）。由 PduR_FrTpRxIndication 报告完成（[SWS_FrTp_01083]）。
  • FrTp 将接收到的地址作为元数据转发（[SWS_FrTp_01206]）。

关于在何种上下文中调用 PduR_FrTpStartOfReception，各来源表述不一：

  • R20-11 图示展示了 MainFunction（SWS FrTp 第86页）。
  • 较新的版本展示了 FrTp_RxIndication（SWS FrTp 第49页）。
  • 有一条提示允许两者（SWS FrTp 第53页）。

时序图：指示进行检查与缓冲，MainFunction 进行重组、发送 FlowControl 并向 PduR 报告。来源：SWS FrTp 第86页、[SWS_FrTp_01074]、[SWS_FrTp_01078]、[SWS_FrTp_01083]

通道、连接、PDU 池和带宽控制

每个通信关系都是一个独立的 FrTpConnection 容器（[SWS_FrTp_01014]）。它具有一个在模块范围内唯一的 N-SDU-ID 和一个唯一的地址对（[SWS_FrTp_01018]、[SWS_FrTp_01017]）。连接数量可在 post-build 时配置（[SWS_FrTp_01015]）。通道数量由 FrTpChanNum 确定，且各通道并行工作（[SWS_FrTp_00088]、[SWS_FrTp_00228]）。

FrTp 将带宽表示为直接映射到 L-PDU 上的 N-PDU（SWS FrTp 第60页）。对于发送 PDU 池，以下规则适用：

  • 多个连接允许引用同一个 FrTpTxPduPool（[SWS_FrTp_01020]）。
  • 池之间允许重叠（[SWS_FrTp_01176]）。
  • 池中的 PDU 按照其在网络计划中的位置升序排列（[SWS_FrTp_01088]），并且长度可以不同（[SWS_FrTp_01089]）。

ConsecutiveFrame 之间不得相互超越。为此，每个通道都有一个 TxPduPendingCounter 来统计尚未确认的 N-PDU（[SWS_FrTp_01090]、[SWS_FrTp_01091]、[SWS_FrTp_01092]）。仅当某个连接的计数器为 0 时，该连接才会被处理（[SWS_FrTp_01094]、[SWS_FrTp_01095]）。只要池中有空闲 PDU，所有活动连接就会轮流获得处理（[SWS_FrTp_01096]、SWS FrTp 第61页）。

在运行时，FrTp_ChangeParameter 使用 TP_BC 修改 BandwidthControl 参数。它由 FrTpSCexp 和 FrTpMaxNbrOfNPduPerCycle 组成（[SWS_FrTp_00242]、[SWS_FrTp_01178]、ComStack Types 第18页）。位 3..7 携带 PDU 数量，位 0..2 携带指数（[SWS_FrTp_01195]）。在正在进行的接收期间，FrTp 会以 E_NOT_OK 拒绝该修改（[SWS_FrTp_01115]）；否则自那时起新值生效（[SWS_FrTp_01156]）。

作为发送方，FrTp 遵守接收方报告的限制：

  • 在 BC.MPPC ≠ 0 时，它仅使用相应数量的池 PDU（[SWS_FrTp_01175]）。
  • 如果设置了 FrTpBandwidthLimitation，StartFrame 和 FlowControl 始终进入池的第一个 PDU 中（[SWS_FrTp_01174]、[SWS_FrTp_01177]、SWS FrTp 第134页）。

协作图（示意性示例）：连接共享重叠的 Tx-PDU 池，其 N-PDU 一对一映射到 FrIf 的 L-PDU 上。来源：[SWS_FrTp_01020]、[SWS_FrTp_01176]、SWS FrTp 第60页

发生错误时的行为

开发与运行时错误。在启用开发错误检测时，各项服务会检查其参数。它们随后报告 FRTP_E_INVALID_PDU_SDU_ID、FRTP_E_PARAM_POINTER 或 FRTP_E_INVALID_PARAMETER（[SWS_FrTp_01201]）。

  • 带返回值的服务在此会返回 E_NOT_OK，例如 FrTp_Transmit（[SWS_FrTp_01139]、[SWS_FrTp_01140]）、FrTp_CancelTransmit（[SWS_FrTp_01141]）、FrTp_ChangeParameter（[SWS_FrTp_01143]、[SWS_FrTp_01144]）、FrTp_TriggerTransmit（[SWS_FrTp_01145]、[SWS_FrTp_01146]）和 FrTp_CancelReceive（[SWS_FrTp_01180]）。
  • 回调 FrTp_RxIndication 和 FrTp_TxConfirmation 仅报告错误（[SWS_FrTp_01147]、[SWS_FrTp_01148]、[SWS_FrTp_01149]、[SWS_FrTp_01203]）。
  • 未配置的未知长度传输将导致 FRTP_E_UMSG_LENGTH_ERROR（[SWS_FrTp_01134]）。
  • 运行时错误为 FRTP_E_SEG_ERROR 和 FRTP_E_NO_CHANNEL（[SWS_FrTp_01208]）。

协议错误。发生这些错误时，FrTp 会主动中止传输并报告 PduR_FrTpTxConfirmation(E_NOT_OK)（[SWS_FrTp_01198]、[SWS_FrTp_01199]）：

  • 带有无效 FS 或带有 OVFLW 或 ABT 的 FlowControl；
  • 其缓冲区位置处于发送方缓冲区之外的 ACK_RET。

否定的 FrTp_TxConfirmation 会释放被占用的通道（[SWS_FrTp_01056]、[SWS_FrTp_01081]）。

定时器与计数器。时间监控遵循所定义的定时器和超时响应（[SWS_FrTp_01055]、[SWS_FrTp_01099]、[SWS_FrTp_01100]）。它们的配置必须满足固定的不等式（[SWS_FrTp_00599]、[SWS_FrTp_01153]、[SWS_FrTp_01154]、[SWS_FrTp_01155]）。计数器 COUNTER_FCWT 和 Counter_RX_RN 是受限的；达到限制时适用已定义的响应（[SWS_FrTp_01105]、[SWS_FrTp_01114]、[SWS_FrTp_01113]、SWS FrTp 第69页）。如果在分段接收期间发生错误，标志 RX_ERROR 会将其保持直至作出响应（[SWS_FrTp_00429]、[SWS_FrTp_00430]）。

发送取消。发送取消（Transmit Cancellation）通过 FrTpTransmitCancellation 启用（[SWS_FrTp_01097]），并通过 FrTp_CancelTransmit 请求（[SWS_FrTp_00384]）。结果取决于执行进度：

  • 尚未启动的作业会立即释放连接（[SWS_FrTp_00385]）。
  • 正在运行的传输被停止；该服务返回 E_OK（[SWS_FrTp_01116]）。
  • 在连接处于非活动状态时，或者当无确认传输的最后一个 N-PDU 已经移交时，该服务返回 E_NOT_OK（[SWS_FrTp_01116]）。

接收方仅通过超时来检测取消，并通过 PduR_FrTpRxIndication 报告（SWS FrTp 第65页）。

接收取消。FrTp_CancelReceive 中止分段接收并随后返回 E_OK（[SWS_FrTp_01181]、[SWS_FrTp_01183]）。在未分段接收时或在 LastFrame 期间，该服务予以拒绝（[SWS_FrTp_01182]）。

时序图：在分段传输中间取消发送，接收方以超时告终并附带否定完成消息。来源：SWS FrTp 第65页、[SWS_FrTp_01116]、SWS FrTp 第58页
