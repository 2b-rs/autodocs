为目标处理器的寄存器宽度和字节序提供统一定名的基础类型和特征符号。

Platform_Types.h 提供 Classic Platform 的平台相关基础类型：从 uint8 到 sint64 的固定宽度整数类型、优化的 *_least 类型、float32/float64、带有 TRUE/FALSE 的 boolean 以及缓冲区指针 VoidPtr 和 ConstVoidPtr。此外，CPU_TYPE、CPU_BIT_ORDER 和 CPU_BYTE_ORDER 标识目标的寄存器宽度和字节序 [SWS_Platform_00046]。boolean 只能与 TRUE 和 FALSE 一起使用，且不得使用算术或位运算符 [SWS_Platform_00034]。不得扩展该头文件，否则将失去 AUTOSAR 一致性。

Platform_Types.h 是 Classic Platform 的平台相关类型基础。该头文件将目标的字长和字节序封装在统一定名之后，且不得进行扩展，因为任何扩展都会破坏 AUTOSAR 一致性 [SWS_Platform_00002]。在模型视图中，这些类型位于固定路径下，如 /AUTOSAR_Platform/ImplementationDatatypes/uint8 TPS StandardizationTemplate 第77页。

该头文件提供以下类型组：

  • 从 uint8 到 sint64 的固定宽度整数类型 [SWS_Platform_00013] [SWS_Platform_00067]；对于有符号类型，仅适用二进制补码 [SWS_Platform_00061]。
  • 具有最小宽度的优化类型 *_least，例如用于循环计数器 [SWS_Platform_00020]。
  • 符合 IEEE 754-2008 的 float32 和 float64 [SWS_Platform_00041]。
  • 用于向调用者传递数据的缓冲区指针 VoidPtr 以及用于向被调用者传递数据的缓冲区指针 ConstVoidPtr [SWS_Platform_91001] [SWS_Platform_91002]。

boolean 在 R20-11 中被实现为最短的原生支持无符号整数类型，通常为 8 位 [SWS_Platform_00027]。后续版本对此有所偏离，使用 _Bool SWS PlatformTypes 第18页。该类型必须支持指针 [SWS_Platform_00060]，并且只能与 TRUE 和 FALSE 一起使用。禁止使用算术和位运算符 [SWS_Platform_00034]，并且应通过条件检查避免符号的重复定义 [SWS_Platform_00054]。

每个平台还必须指定三个符号：用于寄存器宽度的 CPU_TYPE [SWS_Platform_00045]、带有 MSB_FIRST 或 LSB_FIRST 的 CPU_BIT_ORDER [SWS_Platform_00048] [SWS_Platform_00049] 以及带有 HIGH_BYTE_FIRST 或 LOW_BYTE_FIRST 的 CPU_BYTE_ORDER [SWS_Platform_00050] [SWS_Platform_00051]。在此过程中不得混淆位名称和权值，因为 MSB 在累加器中始终位于左侧 SWS PlatformTypes 第15页。Interpretation：该模块不知道运行时错误；错误分配仅在集成或一致性测试时才会显现。

Platform_Types.h 的角色：平台相关的类型基础

该模块不是可执行组件，而是一个头文件。所有指定的类型和符号均为“Available via Platform_Types.h”，例如 uint8 [SWS_Platform_00013] 或 CPU_TYPE [SWS_Platform_00064]。该头文件将目标微控制器和编译器的特性隐藏在统一的名称之后：字宽、位序和字节序。因此，它属于 SRS_BSW_00161 中所要求的具有面向更高层标准接口的微控制器抽象 SRS BSWGeneral 第88页。字节序规则 SWS PlatformTypes 第16页 正是引用了这一上游需求。

系统边界被严格限定。该头文件不得扩展，因为任何扩展都会破坏 AUTOSAR 一致性 [SWS_Platform_00002]。相比之下，用于指示 API 调用成功或失败的返回类型位于 Std_Types.h SRS BSWGeneral 第68页 中。在模型视图中，平台类型作为蓝图存放，例如在 /AUTOSAR/Platform/ImplementationDatatypes_Blueprint/uint8 下。它们在 /AUTOSAR_Platform/ImplementationDatatypes/uint8 下实现，以便组件供应商可以通过可预测的路径访问它们 TPS StandardizationTemplate 第77页。

具有保证宽度的整数和浮点类型

该模块的核心是宽度为 8 至 64 位的固定宽度无符号和有符号类型，以及两种浮点类型。需求规范性地规定了宽度和取值范围，例如针对 uint32 的“32 bit unsigned” [SWS_Platform_00015]。API 目录中的 C typedef（例如 typedef unsigned long uint32;）应当理解为一种典型映射，其可能因编译器而异（解读）。

用于计数器和状态的优化类型 *_least

除了精确宽度的类型外，该模块还定义了六种优化类型。它们仅保证最小宽度，并分别派生自 uint 或 sint：

  • uint8_least [SWS_Platform_00020]
  • uint16_least [SWS_Platform_00021]
  • uint32_least [SWS_Platform_00022]
  • sint8_least [SWS_Platform_00023]
  • sint16_least [SWS_Platform_00024]
  • sint32_least [SWS_Platform_00025]

因此，实现可以选择更宽的表示形式。目录签名将所有六种类型映射到 unsigned int 或 signed int [SWS_Platform_00020]。

作为应用示例，规范列举了循环计数器（最多 124 次迭代 ⇒ uint8_least）和 switch 参数（17 个状态 ⇒ uint8_least）。详细信息请参见通用 BSW 需求中“AUTOSAR Integer Data Types”一章 SWS PlatformTypes 第17页。

合规使用 boolean、TRUE 和 FALSE

boolean 的取值范围为 FALSE = 0 和 TRUE = 1，并且只能与这些定义一起使用 [SWS_Platform_00026]。对于 R20-11，规则为：boolean 实现为平台原生支持的最短位长的无符号整数类型，通常为 8 位 [SWS_Platform_00027]。来自 R24-11/R25-11 的一处文档对同一标识符的表述有所不同：在其中，boolean 通过 C99 类型 _Bool 实现，并且 AUTOSAR 不再规定确切大小 SWS PlatformTypes 第18页。对于 R20-11，这一后续版本不具有规范性。

boolean 还必须映射到指针可以指向的类型，以便可以通过 API 传递参数。某些硬件的高效位类型无法使用指针，因此不予考虑 [SWS_Platform_00060]。对于符号 TRUE 和 FALSE，适用三条规则：

  • 它们使用 #ifndef 保护被定义为 1 和 0 [SWS_Platform_00056]。
  • 如果编译器已自带这些符号，则必须通过条件检查来避免重新定义 [SWS_Platform_00054]。
  • 它们只能与 boolean 一起使用 [SWS_Platform_00055]。

对 boolean 变量赋值时，禁止使用算术和按位运算符：+、++、-、--、*、/、%、<<、>>、~ 和 &。仅允许赋值 TRUE 或 FALSE，以及关系运算、逻辑运算和（不）等式检查的结果。比较时仅使用 == 或 != 与 TRUE/FALSE 进行，或通过 if (var) 或 if (!var) 进行 [SWS_Platform_00034]。使用该类型的模块遵循此模式。例如，Bfx_GetBit 明确将位测试的结果作为 TRUE 或 FALSE 返回 SWS BFXLibrary 第19页。

活动图：对于 boolean 变量，仅允许使用列出的赋值和比较形式，不允许使用算术和位运算符。来源：[SWS_Platform_00034]、[SWS_Platform_00026]

无类型缓冲区指针：VoidPtr 和 ConstVoidPtr

这两种指针类型在数据流方向上有所不同：

  • VoidPtr 是用于包含返回给调用者的数据的缓冲区的 void* [SWS_Platform_91001]。
  • ConstVoidPtr 是用于传递给被调用者的缓冲区的 const void* [SWS_Platform_91002]。

因此，数据流方向已隐含在类型名称中 SWS PlatformTypes 第27页 SWS PlatformTypes 第28页。

Key Manager 展示了这在接口中的表现形式。KeyMServiceCertificateByCertId 将 RequestData 作为 ConstVoidPtr 连同类型为 uint32 的长度一起传递。响应由类型为 VoidPtr 的 ResponseData 接收；此时 ResponseDataLength（INOUT）指定可用的缓冲区长度 SWS KeyManager 第111页。更多示例：

  • KeyM_CertDataType 通过 VoidPtr 引用调用者本地数据区中的证书数据 SWS KeyManager 第97页。
  • Crypto Service Manager 将种子作为 ConstVoidPtr 传递 SWS CryptoServiceManager 第124页。

在这全部三个示例中，长度都作为独立的 uint32 参数或独立的结构体成员传递，因为无类型指针不携带长度信息。

平台标识：CPU_TYPE、CPU_BIT_ORDER、CPU_BYTE_ORDER

必须在头文件中为每个平台指定三项属性：

  • 通过 CPU_TYPE [SWS_Platform_00044] 指定寄存器宽度，其值为 CPU_TYPE_8、CPU_TYPE_16、CPU_TYPE_32 或 CPU_TYPE_64 之一 [SWS_Platform_00045] [SWS_Platform_00064]。
  • 通过 CPU_BIT_ORDER [SWS_Platform_00043] 指定寄存器级别的位序。
  • 通过 CPU_BYTE_ORDER [SWS_Platform_00046] 指定内存中的字节序。

两个顺序符号均为 #define，且取允许值中的恰好一个 [SWS_Platform_00038] [SWS_Platform_00039]。

活动图：移植到目标平台时，确定寄存器宽度、位序和字节序，并分别映射到恰好一个符号值。来源：[SWS_Platform_00045]、[SWS_Platform_00048]、[SWS_Platform_00049]、[SWS_Platform_00050]、[SWS_Platform_00051]

对于大端位序，适用 CPU_BIT_ORDER = MSB_FIRST；对于小端位序，适用 LSB_FIRST [SWS_Platform_00048] [SWS_Platform_00049]。位名称与位权必须严格区分。在累加器中，无论 CPU 类型如何，MSB 始终位于最左侧。在 Motorola 架构（大端位序）中，Bit0 表示最高有效位，而在所有其他架构中表示最低有效位 SWS PlatformTypes 第15页 SWS PlatformTypes 图 7.1 第14页。

基于图 7.1 的结构图：寄存器位的位权是固定的，只有 Bit0 的编号取决于 CPU_BIT_ORDER。来源：SWS PlatformTypes 图 7.1 第14页、SWS PlatformTypes 第15页

对于大端字节序，适用 CPU_BYTE_ORDER = HIGH_BYTE_FIRST：16 位值的最高有效字节位于地址 n，最低有效字节位于 n+1。对于小端字节序，适用 LOW_BYTE_FIRST，且映射相反 [SWS_Platform_00050] [SWS_Platform_00051]。名称 Byte0 和 Byte1 仅用于说明，在制造商的参考文档中可能会有所不同 SWS PlatformTypes 第16页。

基于图 7.2/7.3 的结构图：相同的 uint16 根据 CPU_BYTE_ORDER 以交换字节的方式映射到地址 n 和 n+1。来源：SWS PlatformTypes 图 7.2 第16页、SWS PlatformTypes 图 7.3 第15页、[SWS_Platform_00039]

其他规范解释了为什么需要这些规范。数据的内存表示在很大程度上取决于处理器架构和编译器设置。因此，SOME/IP 要求使用序列化算法将其转换为通用的网络表示 RS SOMEIPProtocol 第21页。据推测，实现中的此类转换可能依赖于 CPU_BYTE_ORDER；但有效载荷并未明确证实这一点。

发生错误时的行为

解读：由于 Platform_Types.h 仅提供类型和符号，该模块不存在运行时错误和错误代码。故障现象出现在编译、集成或一致性测试期间。需求指出了典型原因 [SWS_Platform_00002]：

  • 禁止对头文件进行扩展；任何扩展都会破坏一致性 [SWS_Platform_00002]。
  • 在已有编译器支持的情况下，必须通过条件检查来防止 TRUE/FALSE 的重复定义 [SWS_Platform_00054] [SWS_Platform_00056]。
  • 错误配置顺序符号会违反 [SWS_Platform_00048] 至 [SWS_Platform_00051]。将制造商文档中的位名称与位权混淆尤其容易出错 SWS PlatformTypes 第15页。
  • 无法使用指针的 boolean 会违反 [SWS_Platform_00060]，因为届时参数无法通过 API 传递。
  • 对 boolean 进行算术或位操作是不允许的，使用列出形式之外的比较形式也是不允许的 [SWS_Platform_00034]。
  • 假定反码或对称取值范围的代码不受支持，因为仅支持二进制补码 [SWS_Platform_00061]。
  • 在切换版本时，必须注意 boolean 的规范：R20-11 [SWS_Platform_00027] 与更高版本 SWS PlatformTypes 第18页 存在差异。因此，在切换之前必须检查假定 boolean 具有固定大小的代码。
