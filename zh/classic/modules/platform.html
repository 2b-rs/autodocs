Platform_Types.h的作用：Classic基础软件的通用类型基础

模块“platform”由头文件Platform_Types.h组成。通过该文件，所有标准化的基础类型和平台符号均可用，例如uint8 [SWS_Platform_00013]、boolean [SWS_Platform_00026]以及CPU_TYPE [SWS_Platform_00064]。该模块不包含任何函数。它规定了代码在特定平台上可以假定的取值范围、位宽和编码。其原因在于所有基础软件模块都只能使用AUTOSAR数据类型的要求。原生C类型（如char、int或long）被禁止使用，因为它们的大小、符号和精度取决于平台（RS_BSWGeneral 第65页）。

各模块通常不直接包含这些类型。在需求规范的示例中，Eep.h包含了文件Std_Types.h，而后者又自动包含了Platform_Types.h（RS_BSWGeneral 第65页）。诸如Bfx之类的库将其缩写u8、u16、s32和boolean明确归结为平台类型（SWS_BFXLibrary 第8页）。该文件本身不得修改：任何扩展都会破坏AUTOSAR的一致性[SWS_Platform_00002]。

上下文图：Platform_Types.h是通用类型基础。BSW模块通过Std_Types.h访问它，库、服务接口和模型蓝图则直接引用它。来源：RS_BSWGeneral 第65页、SWS_BFXLibrary 第8页、StandardizationTemplate 第77页、[SWS_Platform_00002]

整数类型：精确宽度或平台优化的最小范围

标准整数类型具有固定的位宽和取值范围。uint8、uint16、uint32 和 uint64 是 8、16、32 和 64 位的无符号类型（[SWS_Platform_00013]、[SWS_Platform_00014]、[SWS_Platform_00015]、[SWS_Platform_00066]）。sint8 到 sint64 是对应的有符号类型（[SWS_Platform_00016]、[SWS_Platform_00017]、[SWS_Platform_00018]、[SWS_Platform_00067]）。它们的范围（例如 sint8 的 -128..+127）源于 AUTOSAR 对编译器和目标系统仅支持二进制补码算术 [SWS_Platform_00061]。

相比之下，优化类型仅保证最小范围。uint8_least、uint16_least 和 uint32_least 分别至少具有 8、16 和 32 位，并且派生自 uint（[SWS_Platform_00020]、[SWS_Platform_00021]、[SWS_Platform_00022]）。sint8_least 到 sint32_least 是有符号变体，派生自 sint（[SWS_Platform_00023]、[SWS_Platform_00024]、[SWS_Platform_00025]）。该规范提到了两种典型用例：最多 124 次迭代的循环计数器，以及具有 17 种状态的 switch 参数。在这两种情况下，均应选择 uint8_least（SWS_PlatformTypes 第17页）。

在有效载荷中包含诸如 typedef unsigned int uint8_least; 或 typedef unsigned long uint32; 的声明。解释：这些是针对特定编译器的映射。具有规范约束力的仅有所要求的宽度或最小宽度（[SWS_Platform_00015]、[SWS_Platform_00020]）。

用于值和数据缓冲区的浮点与指针类型

对于浮点值，适用符合 IEEE 754-2008 的格式：

  • float32 遵循 binary32 格式，范围为 ±3.4028235e+38 [SWS_Platform_00041]。
  • float64 遵循 binary64 格式，范围为 ±1.7976931348623157e+308 [SWS_Platform_00042]。

对于没有固定类型的数据缓冲区，有两种具有固定方向的指针类型：

  • VoidPtr（void*）用于向调用者返回数据的缓冲区 [SWS_Platform_91001]（SWS_PlatformTypes 第27页）。
  • ConstVoidPtr（const void*）用于传递给被调用者的缓冲区 [SWS_Platform_91002]（SWS_PlatformTypes 第28页）。

boolean、TRUE 与 FALSE：表示形式及允许的表达式

在 R20-11 中，boolean 被实现为无符号整数类型，并采用平台原生支持的最短位长，通常为 8 位 [SWS_Platform_00027]。所提供的声明为 typedef unsigned char boolean; [SWS_Platform_00026]。

后续版本中的差异：R24-11/R25-11 的版本要求使用 C99 类型 _Bool，且不再规定对象大小（SWS_PlatformTypes 第18页）。对于 R20-11，上述要求仍然适用。

此外，boolean 必须映射到指针可以指向的类型。因此排除了一些硬件的高效位类型 [SWS_Platform_00060]。这是诸如 CanNm_CheckRemoteSleepIndication 等通过 boolean* 返回结果的接口的前提条件（SWS_CANNetworkManagement 第68页）。

TRUE（1）和 FALSE（0）仅在尚未存在时才会被定义（#ifndef TRUE）[SWS_Platform_00056]。它们只能与 boolean 一起使用 [SWS_Platform_00055]。处理 boolean 变量时适用以下规则 [SWS_Platform_00034]：

  • 赋值仅允许使用 TRUE、FALSE、比较或逻辑表达式（&&、||、!）。
  • 算术和按位运算符（如 +、++、<<、~ 或 &）均被禁止。
  • 比较仅限于 == TRUE、== FALSE、!= TRUE、!= FALSE、if (var) 和 if (!var)（SWS_PlatformTypes 第18页）。

活动图：检查对 boolean 变量的赋值或比较是否合法。来源：[SWS_Platform_00034]、[SWS_Platform_00055]、SWS_PlatformTypes 第18页

平台符号 CPU_TYPE、CPU_BIT_ORDER 和 CPU_BYTE_ORDER

Platform_Types.h 为每个平台指定了 CPU 的三个属性，均作为 #define：

  • 通过 CPU_TYPE 指定寄存器宽度 [SWS_Platform_00044]。允许的值为 CPU_TYPE_8、CPU_TYPE_16、CPU_TYPE_32 和 CPU_TYPE_64（[SWS_Platform_00045]、[SWS_Platform_00064]）。
  • 通过 CPU_BIT_ORDER 指定寄存器级别的位序（[SWS_Platform_00043]、[SWS_Platform_00038]）。
  • 通过 CPU_BYTE_ORDER 指定内存中的字节序（[SWS_Platform_00046]、[SWS_Platform_00039]）。

与端序的对应关系是明确的。大端位序对应 MSB_FIRST，小端位序对应 LSB_FIRST（[SWS_Platform_00048]、[SWS_Platform_00049]）。大端字节序对应 HIGH_BYTE_FIRST，小端字节序对应 LOW_BYTE_FIRST（[SWS_Platform_00050]、[SWS_Platform_00051]）。

规范警告不要混淆位编号与有效位。在采用大端位序的 Motorola 架构中，Bit0 表示最高有效位，而在所有其他架构中表示最低有效位。相比之下，在累加器中，MSB 始终位于最左侧（SWS_PlatformTypes 第15页）。

活动图：在不扩展文件的情况下为目标平台确定三个平台符号的流程。来源：[SWS_Platform_00045]、[SWS_Platform_00048]、[SWS_Platform_00049]、[SWS_Platform_00050]、[SWS_Platform_00051]、[SWS_Platform_00002]

关于字节序，规范展示了一个 16 位值。其最高有效字节称为 Byte1，最低有效字节称为 Byte0。在 HIGH_BYTE_FIRST 中，Byte1 位于地址 n 处，Byte0 位于 n+1 处；在 LOW_BYTE_FIRST 中则相反（SWS_PlatformTypes 第16页）。这种命名并非唯一，在芯片厂商文档中可能会有所不同（SWS_PlatformTypes 第16页）。在总线表示与处理器表示之间转换数据时，字节序具有实际重要性。例如，AUTOSAR COM 必须支持 uint16 到 float64 的端序转换（出处见 R25-11：RS_COM 第14页）。

活动图：根据 CPU_BYTE_ORDER 存储 uint16 值的内存布局，参考规范中的 Figure 7.2/7.3。来源：SWS_PlatformTypes 第16页、[SWS_Platform_00039]

服务接口和模型中的平台类型

其他规范基于这些类型构建其签名。来自 R24-11/R25-11 的两个示例展示了缓冲区指针的方向规则（[SWS_Platform_91001]、[SWS_Platform_91002]）：

  • CSM 操作 RandomSeed 将种子作为 ConstVoidPtr 传入（SWS_CryptoServiceManager 第124页）。

发生错误时的行为

Platform_Types.h 仅提供通过该文件可用的类型和符号（[SWS_Platform_00013]、[SWS_Platform_00038]）。因此，应该不存在带有返回值或错误消息的运行时错误行为。错误反而产生于集成和使用过程中：

  • 扩展或补充的文件：任何扩展都会破坏 AUTOSAR 合规性 [SWS_Platform_00002]。
  • 重复定义：如果编译器已自带这些符号，则应通过条件检查避免重复定义（[SWS_Platform_00054]、[SWS_Platform_00056]）。
  • 错误的平台符号：与硬件不匹配的 CPU_BYTE_ORDER 或 CPU_BIT_ORDER 会违反 [SWS_Platform_00048] 到 [SWS_Platform_00051]。解释：依据这些符号进行分支的代码随后会错误地组装多字节值（参见 SWS_PlatformTypes 第16页）。
  • boolean 的位类型：如果不具备指针寻址能力，则无法通过指针传递参数 [SWS_Platform_00060]。
  • 诸如 var++ 或 var = a & b 等不允许的表达式违反了 [SWS_Platform_00034]。
  • AUTOSAR 不支持补码以外的负数表示形式 [SWS_Platform_00061]。
