收集监控器的诊断结果，对其进行确认判定，并为测试仪管理包含环境数据的故障存储器。

每个ECU恰好存在一个Diagnostic Event Manager [SWS_Dem_00126]。它接收来自诊断监控器的测试结果，对其进行消抖，并据此维护UDS状态位以及包含冻结帧（Freeze Frames）和扩展数据（Extended Data）的事件存储器条目。DCM和J1939Dcm通过面向客户端的API对这些数据进行过滤、读取和清除。在此过程中，它们大多遵循“先选择，后请求”模式[SWS_Dem_01253]。最重要的约束条件是生命周期：在Dem_Init之前，消息仅被缓冲，模块在此之后才具备完整功能。

每个ECU恰好存在一个Diagnostic Event Manager [SWS_Dem_00126]。它接收SW-C和BSW模块中诊断监控器的结果并对其进行确认判定。它向DCM和J1939Dcm提供故障存储器内容。它嵌入在EcuM、Dem_MainFunction的调度、NvM、FiM和DET之间SWS DEM 第247页。

生命周期将预初始化模式与完整功能区分开[SWS_Dem_00169]。在Dem_PreInit之后报告的结果将被缓冲，且尚不触发监控器状态回调（[SWS_Dem_00167]、[SWS_Dem_01289]）。通过Dem_Init，DEM具备完整功能[SWS_Dem_00340]。Dem_Shutdown完成未决的操作并将修改后的数据移交给NvM（[SWS_Dem_00102]、[SWS_Dem_00341]）。

监控器使用Dem_SetEventStatus报告确认的或初步的结果[SWS_Dem_00926]。DEM按事件以基于计数器、基于时间或监控器内部方式进行消抖[SWS_Dem_00413]。由此生成从-128至+127的故障检测计数器（Fault Detection Counter）[SWS_Dem_00415]。消抖和监控器状态同步运行，UDS状态字节异步运行（[SWS_Dem_01279]、[SWS_Dem_01285]）。使能条件（Enable Conditions）和禁用的DTC设置将阻塞处理SWS DEM 第83页。

时序图：报告被同步消抖，UDS处理在MainFunction中随后进行。来源：SWS DEM 图 9.12 第372页、[SWS_Dem_01285]

DEM根据配置的触发器创建包含计数器、冻结帧和扩展数据的条目（[SWS_Dem_00783]、[SWS_Dem_00039]、[SWS_Dem_00809]）。若存储器已满，则由置换策略决定（[SWS_Dem_00400]、[SWS_Dem_00402]）。DCM按照“先选择，后请求”的模式进行访问。Dem_SelectDTC确定读取、状态查询和清除的目标[SWS_Dem_01253]。Dem_SetDTCFilter确定DTC列表的标准[SWS_Dem_00057]。

DEM将错误作为DET开发错误报告，例如DEM_E_UNINIT或DEM_E_WRONG_CONDITION [SWS_Dem_00173]。在运行时，它提供诸如DEM_WRONG_DTC或DEM_BUSY的返回值（[SWS_Dem_01261]、[SWS_Dem_01306]）。对于NvM无法读取的数据，它进行初始化[SWS_Dem_00578]。

角色与系统边界：ECU的中央故障存储器服务

Diagnostic Event Manager接收来自诊断监控器的结果，并将其确认为事件。它将这些事件连同环境数据一起存入事件存储器。每个ECU恰好存在一个DEM模块[SWS_Dem_00126]。每个诊断事件均由唯一的EventId和一个EventName表示（[SWS_Dem_00153]、[SWS_Dem_00154]）。Dem_EventIdType基于uint16，值0无效[SWS_Dem_00925] SWS DEM 第339页。

生命周期：预初始化、运行与关断

DEM区分为预初始化模式和完全初始化模式[SWS_Dem_00169]。Dem_PreInit初始化事件处理所需的状态[SWS_Dem_00180]，其中包括内部消抖[SWS_Dem_01213]。此后报告的事件进入缓冲区[SWS_Dem_00167]，且尚不触发监控器状态回调[SWS_Dem_01289] SWS DEM 图 7.42 第169页。

Dem_Init接收指向Dem_ConfigType的构建后指针（[SWS_Dem_00181]、[SWS_Dem_00924]）。该函数初始化或重新初始化模块SWS DEM 第260页。此后DEM具备完整功能[SWS_Dem_00340]。监控器状态由先前报告的结果或NvM状态生成[SWS_Dem_01326]。在此之后才执行FiM_DemInit [SWS_Dem_01325]。在Dem_Init之前触发的周期重启将被补行执行[SWS_Dem_01318]。

在运行中，Dem_MainFunction处理所有非事件驱动的功能[SWS_Dem_00125]。Dem_Shutdown完成未决的操作[SWS_Dem_00102]。修改后的非易失性数据最迟在此时发送给NvM [SWS_Dem_00341]。推测理解：鉴于根据[SWS_Dem_00181] Dem_Init亦执行重新初始化，在Dem_Shutdown之后的重启推测应通过再次调用Dem_Init进行。 问题 (未决)

从监控器报告到确认结果

一旦有新结果可用，监控器即使用Dem_SetEventStatus报告测试结果（[SWS_Dem_00330]、SWS DEM 第81页）。Dem_EventStatusType区分三种报告类型[SWS_Dem_00926]：

  • 确认的结果（DEM_EVENT_STATUS_PASSED/_FAILED），
  • 用于内部消抖的预结果（_PREPASSED/_PREFAILED），
  • DEM_EVENT_STATUS_FDC_THRESHOLD_REACHED.

消抖针对每个事件可配置[SWS_Dem_00413]：

  • 基于计数器[SWS_Dem_00414]，
  • 基于时间[SWS_Dem_00426]，
  • 监控器内部[SWS_Dem_00437]。
DEM将计数器值或定时器值线性映射到-128至+127的Fault Detection Counter（[SWS_Dem_00415]、[SWS_Dem_00427]）。基于计数器的消抖和监控器状态在调用上下文中同步运行（[SWS_Dem_01279]、[SWS_Dem_01280]）。与此相对，DEM异步计算UDS状态字节[SWS_Dem_01285] SWS DEM 第83页。

时序图：报告被同步消抖，UDS后续处理异步运行。来源：SWS DEM 图 9.12 第372页、[SWS_Dem_01285]

DEM根据自身的状态转移规则设置UDS状态位0至7（[SWS_Dem_00386]、[SWS_Dem_00395]）。Dem_ResetEventStatus异步复位位0并初始化消抖，而不报告Passed结果[SWS_Dem_00187] SWS DEM 第79页。若该事件在当前周期中已被测试，则该调用返回E_NOT_OK [SWS_Dem_00638]。Dem_ResetEventDebounceStatus冻结或复位消抖（[SWS_Dem_00684]、[SWS_Dem_00685]）。

使能条件、操作周期与可用性

使能条件和禁用的DTC设置将阻塞状态消息的处理SWS DEM 第83页。相关规则参见[SWS_Dem_00449]和[SWS_Dem_00079]。DemDebounceBehavior确定消抖在此过程中是被复位[SWS_Dem_00654]还是被冻结[SWS_Dem_00655]。相反，存储条件（Storage Conditions）仅阻止存入存储器（[SWS_Dem_00455]、[SWS_Dem_00556]）。

Dem_RestartOperationCycle以异步方式工作。受影响的监控器通过InitMonitorForEvent重新初始化[SWS_Dem_00679] SWS DEM 第274页。重启不被缓冲[SWS_Dem_01316]。InitMonitorForEvent的其他触发因素包括：

  • 清除[SWS_Dem_00680]，
  • 再次满足的使能条件[SWS_Dem_00681]，
  • 存储条件[SWS_Dem_01113]。
在同时触发的情况下，回调仅被调用一次，并带有最高优先级的原因[SWS_Dem_01046] SWS DEM 第47页。

DEM将使用Dem_SetEventAvailable标记为不可用的事件视为未配置处理[SWS_Dem_01108] SWS DEM 第66页。在VARIANT-POST-BUILD中缺少该API [SWS_Dem_01106]。相反，被抑制的DTC仅对测试仪不可见，事件处理继续进行[SWS_Dem_01102]。

事件存储器：存储、环境数据与置换

DEM维护主事件存储器[SWS_Dem_00010]以及具有相同行为的可选用户定义存储器[SWS_Dem_01063]。一个条目捆绑计数器、冻结帧和扩展数据SWS DEM 图 7.13 第77页。DemEventMemoryEntryStorageTrigger确定条目何时生成：

  • 处于 TestFailed 或达到 FDC 阈值时 [SWS_Dem_00783]，
  • 处于 Pending 时 [SWS_Dem_00784]，
  • 处于 Confirmed 时 [SWS_Dem_00785]。
通过老化（Aging），事件相关数据会被移除 [SWS_Dem_01075]。

冻结帧是针对具体事件的，由配置的 DID 组成（[SWS_Dem_00039]、[SWS_Dem_00040]）。对于易失性数据，监控器会使用 Dem_PrestoreFreezeFrame 预先采集。DEM 在存储时会使用这些数据 [SWS_Dem_00464] SWS DEM 图 7.37 第128页。扩展数据记录（Extended Data Records）根据配置的触发条件进行采集 [SWS_Dem_00809]。它们可以包含内部值，例如发生次数计数器（Occurrence Counter）[SWS_Dem_00471]。

如果缺少空闲条目，DEM 会检查是否进行置换 [SWS_Dem_00400]。DEM_DISPLACEMENT_NONE 则排除了置换 [SWS_Dem_00402]。若没有候选条目，则放弃存储 [SWS_Dem_00407]。否则将移除该条目并调整状态位（[SWS_Dem_00408]、[SWS_Dem_00409]）。DEM 会针对每个存储区指示溢出 [SWS_Dem_00397]。

发生错误时的行为

DEM 向 DET 报告开发错误，例如 DEM_E_UNINIT、DEM_E_PARAM_POINTER 或 DEM_E_WRONG_CONDITION [SWS_Dem_00173] SWS DEM 第238页。在初始化之前的调用会引发 DEM_E_UNINIT；其中包括 Dem_SetEventStatus 和 Dem_ResetEventStatus 等例外 [SWS_Dem_00124]。在关断（Shutdown）之后同样如此 [SWS_Dem_00368]。

在运行时，各 API 提供以下返回值：

  • 在未事先选择或未设置过滤器时返回 E_NOT_OK（[SWS_Dem_01299]、[SWS_Dem_01300]），
  • 在 DTC 或 Origin 未知时返回 DEM_WRONG_DTC 或 DEM_WRONG_DTCORIGIN（[SWS_Dem_01261]、[SWS_Dem_01262]），
  • 在同一客户端存在并发操作时返回 DEM_BUSY（[SWS_Dem_01306]、SWS DEM 第259页）。
在何种条件下清除过程被视为失败由 [SWS_Dem_01202] 定义。

对于 NvM 无法读取的数据，DEM 会对其进行初始化 [SWS_Dem_00578]。它会忽略写入错误 [SWS_Dem_00579]。如果在重编程后布局不再匹配，预存（Prestore）数据将被跳过 [SWS_Dem_01323]。
