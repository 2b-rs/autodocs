DEM 在诊断协议栈中的角色

Diagnostic Event Manager 收集 ECU 的所有诊断事件。每个 ECU 恰好有一个 DEM 模块 [SWS_Dem_00126]。每个事件由唯一的 EventId 和一个关联的名称表示 [SWS_Dem_00153]。在类型 Dem_EventIdType 中，值 0 是不允许的 [SWS_Dem_00925]。在输入端，SW-C 和 BSW 模块通过 Dem_SetEventStatus [SWS_Dem_00183] 报告其测试结果。在输出端，DCM 使用 DEM 来读取和清除故障码、状态及关联数据 SWS DCM 第103页。

DEM 的其他协作者：

  • NvM 负责持久存储 [SWS_Dem_00164] [SWS_Dem_00329]。
  • FiM 会收到状态变更通知 [SWS_Dem_00029] [SWS_Dem_01132]。
  • 监视器通过 InitMonitorForEvent 进行重新初始化，每次均带有来自 Dem_InitMonitorReasonType [SWS_Dem_00003] [SWS_Dem_00942] 的原因。
  • 当配置了 DemGeneralJ1939 时，提供 J1939 支持 [SWS_Dem_00845]。

启动、运行和 Shutdown

DEM 区分预初始化模式与完全初始化的运行状态 [SWS_Dem_00169]。

  • Dem_PreInit初始化事件处理所需的内部状态[SWS_Dem_00180]。这包括DEM内部防抖[SWS_Dem_01213]。
  • 从此时起，消抖后的报告成为可能 [SWS_Dem_01212]。
  • 对于在 Dem_Init 之前到达的报告，DEM 将其缓存在队列中 [SWS_Dem_00167]。其大小是可配置的 [SWS_Dem_00207] [SWS_Dem_01079]。
  • 这些早期报告不会触发监视器状态回调 [SWS_Dem_01289] SWS DEM 第169页。

Dem_Init 接收指向 Dem_ConfigType 的指针并初始化或重新初始化该模块 [SWS_Dem_00181] [SWS_Dem_00924]。

  • 只有在此期间才会初始化监视器状态。在此之前，Dem_GetMonitorStatus 返回值 E_NOT_OK [SWS_Dem_01326]。
  • 在 Dem_Init 之后，DEM 完全具备运行就绪状态 [SWS_Dem_00340]。
  • 先前请求的运行周期重启直到此后才被处理 [SWS_Dem_01318]。
  • 所有非事件驱动的任务均由 Dem_MainFunction [SWS_Dem_00125] [SWS_Dem_00266] 处理。
  • Dem_Shutdown 完成未决操作 [SWS_Dem_00102]。已更改的非易失性数据最晚在 Shutdown 期间触发写入 NVRAM [SWS_Dem_00341]。

从监视器结果到合格事件

Dem_SetEventStatus 传递来自 Dem_EventStatusType [SWS_Dem_00926] 的值：

  • DEM_EVENT_STATUS_PASSED 和 DEM_EVENT_STATUS_FAILED 是已经合格的结果。
  • …_PREPASSED 和 …_PREFAILED 是由 DEM 内部进行消抖的预备结果 SWS DEM 第351页。

消抖算法按每个事件进行配置 [SWS_Dem_00413]。可选项包括基于计数器 [SWS_Dem_00414]、基于时间 [SWS_Dem_00426] 或监视器内部 [SWS_Dem_00437]。

基于计数器的消抖：

  • 预备结果按配置的步长递增或递减内部计数器 [SWS_Dem_00418] [SWS_Dem_00419]。
  • 合格结果直接设置计数器 [SWS_Dem_00420] [SWS_Dem_00421]。
  • 阈值确定故障状态或正常状态 [SWS_Dem_00416] [SWS_Dem_00417]。
  • 跳转行为可选配置 [SWS_Dem_00422] [SWS_Dem_00424]。
  • 计数器线性映射到 Fault Detection Counter（−128…+127）[SWS_Dem_00415] SWS DEM 第108页。

在基于时间的消抖中，预备结果会启动一个定时器 [SWS_Dem_00428] [SWS_Dem_00432]。

活动图：在基于计数器的消抖中，所报告的状态决定计数器的变化；达到阈值即判定事件合格。来源：[SWS_Dem_00415]–[SWS_Dem_00421]、SWS DEM 第108页、[SWS_Dem_00414]、[SWS_Dem_00424]、[SWS_Dem_00422]

处理分为两个部分：

  • 基于计数器的消抖 [SWS_Dem_01279] 以及监视器状态的位 0 和位 1 [SWS_Dem_01280] 在调用者上下文中同步运行。
  • 相比之下，DEM 异步计算 UDS 状态 [SWS_Dem_01285]。

使能条件与存储条件：

  • 使能条件按事件进行检查 [SWS_Dem_00447]，并通过 Dem_SetEnableCondition 设置 [SWS_Dem_00201]。
  • 只要使能条件未满足，报告就不会被接受 [SWS_Dem_00449] DEXT 第198页。根据 DemDebounceBehavior，消抖随后会被重置或冻结 [SWS_Dem_00654] [SWS_Dem_00655]。
  • 相比之下，存储条件仅控制事件是否存储在内存中 [SWS_Dem_00459] [SWS_Dem_00556]。

对事件处理的进一步干预：

  • Dem_ResetEventDebounceStatus 重置或冻结消抖 [SWS_Dem_00684] [SWS_Dem_00685]。事件的合格判定不受此影响 SWS DEM 第267页。
  • Dem_ResetEventStatus 异步重置 TestFailed [SWS_Dem_00187]。

时序图：使能检查、消抖和监视器状态同步运行，UDS 状态和回调异步运行。来源：[SWS_Dem_00449]、[SWS_Dem_01279]、[SWS_Dem_01280]、[SWS_Dem_01285]、[SWS_Dem_00016]、SWS DEM 第85页

事件内存、状态字节和运行周期

DEM 默认维护所有 UDS 状态位 [SWS_Dem_00006]。每个位转换都是单独规定的，例如针对 TestFailed [SWS_Dem_00386]、ConfirmedDTC [SWS_Dem_00391] 和 WarningIndicatorRequested [SWS_Dem_00395] SWS DEM 第88页。

事件内存的结构：

  • 存在一个主内存 [SWS_Dem_00010] 以及可选的用户自定义内存 [SWS_Dem_00548]。
  • 它们组织在事件内存集中 [SWS_Dem_01247]。
  • 创建条目的触发器是可配置的 [SWS_Dem_00783]–[SWS_Dem_00786] SWS DEM 第94页。

当内存已满时：

  • DEM 设置一个溢出指示 [SWS_Dem_00397]，该指示可通过 Dem_GetEventMemoryOverflow 读取 [SWS_Dem_00559]。
  • 它根据置换策略寻找候选条目 [SWS_Dem_00400] [SWS_Dem_00401]。
  • 如果没有候选条目，它将丢弃存储请求 [SWS_Dem_00407]。

冻结帧（Freeze Frame）和扩展数据记录（Extended Data Record）根据配置的触发器进行采集 [SWS_Dem_00799]–[SWS_Dem_00802] [SWS_Dem_00809]。其中预先存储的冻结帧具有优先级 [SWS_Dem_00464]。

活动图：事件存储过程经过存储条件、空闲条目、溢出和置换。来源：[SWS_Dem_00459]、[SWS_Dem_00397]、[SWS_Dem_00406]–[SWS_Dem_00409]、SWS DEM 第94页、[SWS_Dem_00783]、[SWS_Dem_00786]、[SWS_Dem_00401]、[SWS_Dem_00809]

老化（Aging）：

  • 每个条目都有一个老化计数器 [SWS_Dem_00019]。
  • 老化在自愈完成之后开始 [SWS_Dem_00698] SWS DEM 第133页。
  • 如果达到阈值，ConfirmedDTC 将被重置 [SWS_Dem_00498] 并且事件数据被移除 [SWS_Dem_01075]。

运行周期：

  • Dem_RestartOperationCycle 异步工作并重新初始化受影响的监视器 [SWS_Dem_00194] [SWS_Dem_00679]。
  • 重启不存在排队队列 [SWS_Dem_01316]。
  • 依赖的周期通过 Dem_SetCycleQualified 判定合格 [SWS_Dem_01221] [SWS_Dem_91001]。

按“选择和查询”原则访问故障内存

许多 DCM 服务遵循相同的模式：客户端首先选择一个 DTC 或 DTC 组，然后调用对该选择进行操作的函数 SWS DEM 第215页。

  • Dem_SelectDTC 为 Dem_ClearDTC、Dem_GetStatusOfDTC 和 Dem_SelectFreezeFrameData 等确定目标 [SWS_Dem_91016] [SWS_Dem_01253]。
  • 该选择涉及分配给 ClientId 的事件内存 [SWS_Dem_01254]。
  • 具有不同 ClientId 的客户端允许并行工作 [SWS_Dem_01251]。
  • 如果同一个客户端在先前的操作仍在运行时再次调用 Dem_SelectDTC，它将获得 DEM_BUSY [SWS_Dem_01306]。

读取冻结帧和扩展数据：

  • Dem_SelectFreezeFrameData 和 Dem_SelectExtendedDataRecord 基于 DTC 选择构建 [SWS_Dem_01268] [SWS_Dem_01272]。
  • 随后大小函数和 Next 函数提供数据 [SWS_Dem_00074] [SWS_Dem_00071] [SWS_Dem_00075]。冻结帧具有格式 {RecordNumber, NumOfDIDs, DID, data…} SWS DEM 第225页。
  • 如果请求了一个有效但未存储的记录，DEM 会返回带有空缓冲区的 E_OK [SWS_Dem_00630]。
  • 为了保持数据一致性，DCM 在读取期间通过 Dem_DisableDTCRecordUpdate 锁定更新，并通过 Dem_EnableDTCRecordUpdate 再次解除锁定 [SWS_Dem_00270] [SWS_Dem_00271]。

时序图：在更新被锁定的情况下选择并读取冻结帧；DEM_PENDING 导致重复调用。来源：[SWS_Dem_01253]、[SWS_Dem_01268]、[SWS_Dem_00238]、[SWS_Dem_00236]、[SWS_Dem_00270]、SWS DEM 第290页、[SWS_Dem_00071]、[SWS_Dem_00271]

过滤功能：

  • Dem_SetDTCFilter 设置后续查询的过滤条件 [SWS_Dem_00057]。每次调用都会重新启动迭代 [SWS_Dem_00649]。
  • 随后 Dem_GetNumberOfFilteredDTC 和 Dem_GetNextFilteredDTC 提供匹配项 [SWS_Dem_00061] [SWS_Dem_00216]。
  • 在 OBD 格式下，Dem_GetNextFilteredDTC 不返回 DEM_PENDING [SWS_Dem_00653]。

清除与 DTC-Setting：

  • Dem_ClearDTC 可选地查询 DemClearEventAllowed [SWS_Dem_00665] [SWS_Dem_00515]，并重新初始化受影响的监视器 [SWS_Dem_00680]。
  • Dem_DisableDTCSetting 禁止存储受影响的事件 [SWS_Dem_00079] [SWS_Dem_00626]。

依赖于配置的功能块：OBD、J1939、组件

OBD：

  • 仅当 DemOBDSupport 不等于 DEM_OBD_NO_OBD_SUPPORT 时，OBD API 才可用 SWS DEM 第315页。
  • Master ECU 在整车范围内计算 PID $31/$4D/$4E [SWS_Dem_00703]，并且是唯一向扫描工具报告这些值的 ECU [SWS_Dem_00704]。
  • Primary ECU 通过调用 Dem_SetDataOfPID… 的 SW-C 获取这些值 [SWS_Dem_00735] [SWS_Dem_00736] SWS DEM 第170页。
  • IUMPR 分母条件的状态在各 ECU 之间传输 [SWS_Dem_00714] [SWS_Dem_00716]。
  • 测试结果（DTR）由应用程序通过 Dem_SetDTR [SWS_Dem_00756] 报告。

组件（DemComponent）：

  • 每个组件都具有 FAILED 状态，并可以与其他组件存在有向依赖关系 [SWS_Dem_01118] [SWS_Dem_01119] [SWS_Dem_01120]。

  • 被抑制的 DTC 对测试仪不可见 [SWS_Dem_01100]，但会在内部继续进行处理 [SWS_Dem_01102]。

发生错误时的行为

使用与流程

函数 Dem_ClearDTC 异步删除单个 DTC 以及配置的 DTC 组 [SWS_Dem_00665]。调用者通过参数 ClientId 进行标识 [SWS_Dem_00665]。在调用之前，必须已通过 Dem_SelectDTC 选定要删除的 DTC 或组，包括 DTCOrigin 和 DTCFormat [SWS_Dem_01253]。只要删除过程正在运行，该 API 就会返回 DEM_PENDING，这需要在稍后时间点重新调用；仅在成功完成后才会返回 E_OK [SWS_Dem_00665]。

错误处理与返回值

如果发生错误，可使用特定的返回值 [SWS_Dem_00665]：

  • E_NOT_OK：事先未选择 DTC [SWS_Dem_00665]。
  • DEM_WRONG_DTC：DTC 在所选格式中不存在 [SWS_Dem_00665]，所选 DTC 被抑制 [SWS_Dem_01100]，或者删除操作受 DemClearDTCLimitation 限制为 DEM_ONLY_CLEAR_ALL_DTCS，而选择了另一个组 [SWS_Dem_00670]。
  • DEM_WRONG_DTCORIGIN：指定的存储位置不存在 [SWS_Dem_00665]。
  • DEM_CLEAR_FAILED 或 DEM_CLEAR_MEMORY_ERROR：删除失败，或者在删除 NVRAM 块时发生错误 [SWS_Dem_00665]。
  • DEM_CLEAR_BUSY：另一个客户端已在执行删除过程 [SWS_Dem_00665]。
  • DEM_BUSY：对于同一个客户端，另一个依赖于 Dem_SelectDTC 的操作已在运行 [SWS_Dem_00665]。

并发性与交互

Dem_ClearDTC 对于不同的 ClientId 值是可重入的，但对于相同的 ClientId 则不可重入 [SWS_Dem_00665]。DEM 在内部处理多个客户端的并行调用 [SWS_Dem_00661]；如果删除过程已在运行，请求的客户端将收到 DEM_PENDING [SWS_Dem_00664]。

如果删除了一个组合 DTC，DEM 将清除所有关联的事件 [SWS_Dem_00440]。此时，该模块会针对受影响的事件触发回调 InitMonitorForEvent，原因设为 DEM_INIT_MONITOR_CLEAR [SWS_Dem_00680]。如果 DemTriggerMonitorInitBeforeClearOk 配置为 TRUE，则仅在触发了该初始化后才会返回 E_OK [SWS_Dem_00573]。此外，一旦其中包含的所有 DTC 均被删除，存储器的溢出指示就会被复位 [SWS_Dem_00399]。
