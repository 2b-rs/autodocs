在上层与 LIN 驱动之间转发 LIN 报文帧，并控制调度表、休眠、唤醒以及 LIN-TP。

LIN Interface 连接上层通信模块与 LIN 驱动及收发器，并且还包含 LIN 传输协议。作为 Master，通道执行通过LinIf_ScheduleRequest选择的调度表[SWS_LinIf_00202]。相比之下，作为 Slave，它仅响应驱动的报头消息[SWS_LinIf_91004]。此外，它按通道控制休眠与唤醒、诊断传输以及 Slave 中的 Node Configuration。哪些服务可用取决于通道所配置的节点类型。

LIN Interface（LinIf）在上层通信模块与 LIN 驱动之间进行协调，并同时包含 LIN 传输协议[SWS_LinIf_00351]。向上，它在 R20-11 中调用可配置的标注（Callout）<User_TriggerTransmit>、<User_TxConfirmation>和<User_RxIndication>[SWS_LinIf_00528][SWS_LinIf_00529][SWS_LinIf_00530]；使用者为 PduR 或 CDD。它通过<User>_…Confirmation标注向 LinSM 回报模式切换[SWS_LinIf_00521]。向下它使用 Lin 以及可选的 LinTrcv[SWS_LinIf_00359]。

在LinIf_Init[SWS_LinIf_00198]之后，每个通道均处于LINIF_CHANNEL_SLEEP状态。LinIf 仅在LINIF_CHANNEL_OPERATIONAL中处理报文帧SWS LinIf 第45页。每个通道由其专属的 MainFunction 处理工作[SWS_LinIf_00384]。

Master 和 Slave 的工作方式截然不同。Master 通道执行调度表，通过索引 1..255 的LinIf_ScheduleRequest进行选择；0 代表NULL_SCHEDULE[SWS_LinIf_00197][SWS_LinIf_00202]。在此过程中，LinIf_Transmit仅标记偶发帧（Sporadic Frames）；LinIf 仅在相应时隙到期时才获取数据[SWS_LinIf_00706]。相比之下，Slave 仅对LinIf_HeaderIndication作出响应。它根据 PID 决定发送、接收还是忽略[SWS_LinIf_00738][SWS_LinIf_00733][SWS_LinIf_00748]，并自主管理response_error信号[SWS_LinIf_00763]。

Slave 在收到休眠命令（Go-to-sleep）或总线空闲超时后进入休眠[SWS_LinIf_00750][SWS_LinIf_00755]。它仅在收到第一个报头时才确认唤醒[SWS_LinIf_00761]。对于诊断，LinTp 在 Master 中通过BswM_LinTp_RequestMode切换调度表[SWS_LinIf_00629]。在 Slave 中，LinIf 支持符合 ISO 17987-3 的 Node Configuration[SWS_LinIf_00771]。LinIf 向 DET 报告错误，例如LINIF_E_RESPONSE[SWS_LinIf_00729]。发生超时时，它以E_NOT_OK中止 TP 传输[SWS_LinIf_00801][SWS_LinIf_00806]。

LIN Interface 在使用者、驱动与收发器之间的角色

LIN Interface（LinIf）在上层通信模块与 LIN 驱动之间进行协调。它同时包含 LIN 传输协议：其诸如LinTp_Init和LinTp_Transmit之类的服务也可通过LinIf.h使用[SWS_LinIf_00350][SWS_LinIf_00351]。向下，LinIf 使用驱动服务，如Lin_GoToSleepInternal、Lin_Wakeup和Lin_WakeupInternal[SWS_LinIf_00359]。可选地，还可以添加 LIN Transceiver Driver，LinIf 将所有收发器的模式服务和唤醒服务映射到统一接口上SWS LinIf 第24页。为此，LinIf_SetTrcvMode、LinIf_GetTrcvMode、LinIf_GetTrcvWakeupReason和LinIf_SetTrcvWakeupMode将调用转发给收发器驱动[SWS_LinIf_00544][SWS_LinIf_00545][SWS_LinIf_00547][SWS_LinIf_00550]。

向上，LinIf 通过可配置的标注调用其使用者：<User_TriggerTransmit>、<User_TxConfirmation>和<User_RxIndication>[SWS_LinIf_00528][SWS_LinIf_00529][SWS_LinIf_00530]。使用者为 PduR（此时应填入PduR_LinIfTriggerTransmit[SWS_LinIf_00722]）或 CDD（LinIf 包含其回调头文件[SWS_LinIf_00669]）。LinIf 通过<User>_ScheduleRequestConfirmation、<User>_GotoSleepConfirmation和<User>_WakeupConfirmation回报模式切换[SWS_LinIf_00520][SWS_LinIf_00521][SWS_LinIf_00522]。这些消息的接收者是 LinSMSWS LinSM 第24页。此外，LinIf 需要服务BswM_LinTp_RequestMode、Com_SendSignal和Det_ReportError[SWS_LinIf_00360]。从 R24-11 起，LSduR 取代 PduR 或 CDD 成为上层使用者SWS LinIf 第1页。对于 R20-11，适用<User_…>标注。

每个通道要么是 Master，要么是 Slave。仅当配置了至少一个 Slave 通道时，诸如LinIf_HeaderIndication或LinIf_GetConfiguredNAD之类的 Slave 服务才存在[SWS_LinIf_00863][SWS_LinIf_00861]。仅当存在至少一个 Master 通道时，LinIf_ScheduleRequest才存在[SWS_LinIf_00858]。周期性处理在LinIf_MainFunction_<LinIfChannel.ShortName>中运行[SWS_LinIf_00384]。该函数在每个通道存在一个SWS LinIf 第119页，并以周期LinIfMainFunctionPeriod被调用。在 Master 中它查询 Schedule Table Manager，在 Slave 中它监控时间条件SWS LinIf 第45页。总线镜像（Bus Mirroring）通过LinIf_EnableBusMirroring按通道激活；之后，LinIf 向 Mirror 模块报告接收和发送的报文帧[SWS_LinIf_00876][SWS_LinIf_00838][SWS_LinIf_00873]。

LinIf_Init 接收指向 LinIf_ConfigType 的指针 [SWS_LinIf_00198] [SWS_LinIf_00668]，并将模块从 LINIF_UNINIT 引导至 LINIF_INIT SWS LinIf 第47页。每个通道都拥有独立的子状态机。初始化完成后，通道处于 LINIF_CHANNEL_SLEEP 状态，而无需发送 Go-to-sleep 命令。LinIf 仅在 LINIF_CHANNEL_OPERATIONAL 状态下处理报头与响应 SWS LinIf 第45页。主节点通道以 NULL_SCHEDULE 启动 SWS LinIf 第90页。从节点通道从配置中获取初始及配置的 NAD 以及 PID [SWS_LinIf_00767] [SWS_LinIf_00768]，并提供 LIN Product Identification [SWS_LinIf_00769]。

主节点通道：调度表决定总线通信

在主节点中，调度表构成了所有通信的基础。每个通道都有一个空的 NULL_SCHEDULE，且帧之间的间距为 LinIfMainFunctionPeriod 的整数倍 SWS LinIf 第44页。LinIf_SchHandleType 将 NULL_SCHEDULE 编码为 0x00，将其余表编码为索引 1..255。该索引在通道内是唯一的，但并非在每个 ECU 内唯一 [SWS_LinIf_00197]。LinIf_ScheduleRequest 采用异步工作方式 [SWS_LinIf_00202]；已完成的切换由 <User>_ScheduleRequestConfirmation 上报 [SWS_LinIf_00520]。在配置中，每个表都被分配了一个 LinIfRunMode，即 RUN_CONTINUOUS 或 RUN_ONCE ECUC-Parameter 第265页。参数 Schedule 直到 R22-11 才被重命名 SWS LinIf 第1页。

LinIf_Transmit [SWS_LinIf_00201] 不会触发立即发送。它仅将偶发帧（主节点）或事件触发帧（从节点）标记为挂起 SWS LinIf 第79页。对于其他帧，它仍返回 E_OK [SWS_LinIf_00700]，但在 NULL_SCHEDULE 期间则返回 E_NOT_OK [SWS_LinIf_00719]。当发送时隙到期时，LinIf 通过 <User_TriggerTransmit> 获取数据，并通过 Lin_SendFrame 传递给驱动程序 SWS LinIf 第37页。若用户返回 E_NOT_OK，则该帧被忽略 [SWS_LinIf_00706]。LinIf 使用 Lin_GetStatus 检查结果，最早在最大帧长度之后，最晚在下一个表条目时 SWS LinIf 第35页。LIN_TX_ERROR 和 LIN_TX_BUSY 导致带有 E_NOT_OK 的 <User_TxConfirmation> [SWS_LinIf_00728]，LIN_TX_OK 则导致 E_OK SWS LinIf 第40页。

从节点通道：对主节点报头的响应

从节点没有调度表。它仅对 LinIf_HeaderIndication [SWS_LinIf_91004] SWS LinIf 第39页 做出响应。LinIf 首先评估 PID：

  • 发送帧：<User_TriggerTransmit> 直接写入驱动缓冲区 [SWS_LinIf_00738]。随后 LinIf 设置 Cs 和 Dl 并报告 LIN_FRAMERESPONSE_TX [SWS_LinIf_00739]。如果用户返回 E_NOT_OK，LinIf 将报告 LIN_FRAMERESPONSE_IGNORE [SWS_LinIf_00740]。
  • 接收帧：LinIf 报告 LIN_FRAMERESPONSE_RX [SWS_LinIf_00733]。
  • 不相关的帧：LinIf 报告 LIN_FRAMERESPONSE_IGNORE [SWS_LinIf_00748]。

成功接收后，驱动程序调用 LinIf_RxIndication，LinIf 将数据转发至 <User_RxIndication> [SWS_LinIf_91005] [SWS_LinIf_00734]。成功发送后，驱动程序调用 LinIf_TxConfirmation，LinIf 通过 E_OK 确认 [SWS_LinIf_91006] [SWS_LinIf_00741]。对于事件触发帧，关联的无条件帧的 PID 位于第一个数据字节中 [SWS_LinIf_00731]。成功传输后，挂起标志会被清除 [SWS_LinIf_00732]。

LinIf 独立管理每个从节点通道的 response_error 信号 [SWS_LinIf_00763]，并通过 Com_SendSignal 进行更新 [SWS_LinIf_00764]。传输成功后该信号被清除 [SWS_LinIf_00747]。任何更改都可以选择通过 <User_ResponseErrorSignalChanged> 进行报告 [SWS_LinIf_00765] [SWS_LinIf_00766]。NAD 和 PID 列表可在运行时读取和写入 [SWS_LinIf_00829] [SWS_LinIf_00833] [SWS_LinIf_91002] [SWS_LinIf_91003]。MRF 和 SRF 的 PID 除外 [SWS_LinIf_00809] [SWS_LinIf_00824]。这些值的典型来源是非易失性存储器 SWS LinIf 第57页。

发生错误时的行为

LinIf 向 DET 报告开发错误，其中包括 LINIF_E_UNINIT、LINIF_E_NONEXISTENT_CHANNEL、LINIF_E_PARAMETER、LINIF_E_PARAM_POINTER 和 LINIF_E_SCHEDULE_REQUEST_ERROR [SWS_LinIf_00376]。回调函数检查通道和指针 [SWS_LinIf_00843] [SWS_LinIf_00844]。LinIf 忽略在未接收报头的情况下对 LinIf_RxIndication 或 LinIf_TxConfirmation 的意外调用 [SWS_LinIf_00848] [SWS_LinIf_00852]。

LinIf 识别的运行时错误包括 LINIF_E_RESPONSE 和 LINIF_E_NC_NO_RESPONSE [SWS_LinIf_00729]。如果驱动程序在从节点中调用 LinIf_LinErrorIndication，则该帧被视为丢失。LinIf 随后报告 LINIF_E_RESPONSE，LIN_ERR_HEADER [SWS_LinIf_00735] [SWS_LinIf_00743] 除外。此外，它通过 E_NOT_OK 确认发送尝试 [SWS_LinIf_00742]，并在发生响应错误时设置 response_error 信号 [SWS_LinIf_00736] [SWS_LinIf_00744]。在仍在等待响应时到达的新报头会使旧帧失效 [SWS_LinIf_00846]。在镜像功能激活时，LinIf 会报告此类错误并转换状态码 [SWS_LinIf_00869] [SWS_LinIf_00870]。

LinTp 监控三个时间限制，并在超时时通过向 PduR 发送 E_NOT_OK 来中止：

  • N_As [SWS_LinIf_00799] [SWS_LinIf_00801]
