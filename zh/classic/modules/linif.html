在 LIN 栈中的角色：统一接口背后的主节点与从节点通道

LIN 接口（LinIf）是 LIN 驱动程序之上的抽象层 Lin。它接收上层的请求，将其在总线上实现，并且还包含 LIN 传输协议（LinTp）。LIN State Manager 向 LinIf 传递调度表请求（仅在主节点中）以及唤醒和休眠请求（SWS LinIf 第23页）。LIN 驱动程序仅向 LinIf 报告其事件（SWS LIN-Treiber 第53页）。LinIf 通过可配置的 callout 访问上层用户（SWS LinIf 第113页）。在 R20-11 中，这些调用称为 <User_TriggerTransmit>、<User_TxConfirmation> 和 <User_RxIndication>（[SWS_LinIf_00528]、[SWS_LinIf_00529]、[SWS_LinIf_00530]）。较新的文档出处和示意图则以 LSduR 取代它们。根据修订历史，此更改直到 R24-11 才引入（SWS LinIf 第1页）。

参数 LinIfNodeType 规定通道作为主节点还是作为从节点工作。只有在至少配置了一个从节点通道时，才存在特定于从节点的服务（如 LinIf_HeaderIndication、LinIf_RxIndication 或 LinIf_SetPIDTable）。反之，只有在至少配置了一个主节点通道时，才存在 LinIf_ScheduleRequest（[SWS_LinIf_00858]、[SWS_LinIf_00860]、[SWS_LinIf_00863]、[SWS_LinIf_00864]）。其他组件可在编译前启用或禁用：

  • 通过 LinIfTpSupported 配置 LinTp（SWS LinIf 第99页），
  • 通过 LinIfBusMirroringSupported 配置 Bus Mirroring（[SWS_LinIf_00875]），
  • 用于 response_error 信号的 callout（[SWS_LinIf_00766]）。

结构 LinIf_ConfigType 和 LinTp_ConfigType 是特定于实现的（[SWS_LinIf_00668]、[SWS_LinIf_00426]）。SWS LinIf 第96页 提供了参数概述。

上下文图：LinIf 在上层的 PduR、LinSM、BswM、EcuM 和 Com 与下层的 Lin、LinTrcv、DET 和 Mirror 之间进行中介。来源：[SWS_LinIf_00359]、[SWS_LinIf_00360]、[SWS_LinIf_00378]、[SWS_LinIf_00764]、[SWS_LinIf_00838]、SWS LinIf 第23页

针对收发器，LinIf 跨所有 LinTrcv 驱动程序提供了统一的接口。LinIf_SetTrcvMode、LinIf_GetTrcvMode、LinIf_GetTrcvWakeupReason 和 LinIf_SetTrcvWakeupMode 将调用传递给匹配的 LinTrcv 服务（SWS LinIf 第24页、[SWS_LinIf_00544]、[SWS_LinIf_00545]、[SWS_LinIf_00547]、[SWS_LinIf_00550]）。如果使用 LinIf_EnableBusMirroring 为某个通道启用了 Bus Mirroring，LinIf 会通过 Mirror_ReportLinFrame() 报告接收、发送或受干扰的每个帧（[SWS_LinIf_00876]、[SWS_LinIf_00838]、[SWS_LinIf_00839]、[SWS_LinIf_00869]、SWS BusMirroring 第30页）。

生命周期：LinIf_Init、通道状态及每个通道的主函数

复位后，LinIf 处于状态 LINIF_UNINIT。LinIf_Init 转换至 LINIF_INIT。在该状态下，每个通道都有一个包含状态 LINIF_CHANNEL_OPERATIONAL 和 LINIF_CHANNEL_SLEEP 的独立子状态机（[SWS_LinIf_00198]、SWS LinIf 第47页、SWS LinIf 第34页）。在主节点通道上，LinIf_Init 设置 NULL_SCHEDULE（SWS LinIf 第90页）。在从节点通道上，它从配置中加载 Initial-NAD、配置的 NAD 和 PID（[SWS_LinIf_00767]、[SWS_LinIf_00768]）。

状态图：LinIf_Init 从 LINIF_UNINIT 转换至 LINIF_INIT；在此状态下，每个通道在 OPERATIONAL 和 SLEEP 之间切换。来源：[SWS_LinIf_00198]、[SWS_LinIf_00204]、[SWS_LinIf_00205]、SWS LinIf 第34页

实际的处理工作由 LinIf_MainFunction_<LinIfChannel.ShortName> 完成。它在每个通道中存在一个实例，并由 SchM 以 LinIfMainFunctionPeriod 的周期调用（[SWS_LinIf_00384]、SWS LinIf 第45页）。在主节点中，它查询调度表管理器并触发发送和接收。在从节点中，它主要监控时间；帧本身也可以直接在回调中处理。其他调用（如 LinIf_Transmit、LinIf_ScheduleRequest、LinIf_GotoSleep 或 LinIf_Wakeup）可能会中断主函数。因此，必须对共享数据进行保护（SWS LinIf 第119页）。

主节点通道：调度表决定总线通信

在主节点通道上，调度表是所有通信的基础。两个帧之间的间隔是 LinIfMainFunctionPeriod 的倍数。预定义的 NULL_SCHEDULE 不包含任何条目（SWS LinIf 第44页）。通过 LinIf_SchHandleType 每个通道最多可寻址 255 个表；值 0 代表 NULL_SCHEDULE（[SWS_LinIf_00197]）。LinIf_ScheduleRequest 异步工作。当通道处于休眠状态或表未知时，它会以 E_NOT_OK 拒绝（[SWS_LinIf_00202]、SWS LinIf 第86页）。切换完成后，由 <User>_ScheduleRequestConfirmation 进行报告（[SWS_LinIf_00520]）。在 R20-11 中，该参数仍称为 Schedule；它直到后来才被重命名（SWS LinIf 第1页）。

LinIf_Transmit不会直接向总线发送任何内容。它仅将偶发帧（Master）或事件触发帧（Slave）标记为挂起。对于其他帧类型，只要活动调度表不是 NULL_SCHEDULE，它仍然返回 E_OK；在该调度表下，它返回 E_NOT_OK（[SWS_LinIf_00201]、[SWS_LinIf_00700]、[SWS_LinIf_00719]、SWS LinIf 第125页）。

当发送条目到期时，执行以下流程：

  1. LinIf 使用 <User_TriggerTransmit> 获取有效负载数据。
  2. 它通过 Lin_SendFrame 将其传递给驱动程序。如果用户返回 E_NOT_OK，则不发送该帧（[SWS_LinIf_00706]、SWS LinIf 第37页）。
  3. LinIf 最早要在最大帧长度之后才通过 Lin_GetStatus 查询状态（SWS LinIf 第35页）。
  4. 对于 LIN_TX_ERROR 或 LIN_TX_BUSY，随后是带有 E_NOT_OK 的 <User_TxConfirmation>（[SWS_LinIf_00728]）。

时序图：数据在到期的周期内被获取并发送；确认仅在后续周期的状态查询之后发生。来源：[SWS_LinIf_00384]、[SWS_LinIf_00706]、[SWS_LinIf_00728]、[SWS_LinIf_00874]、SWS LinIf 第82页

从节点通道：根据接收报头的节拍进行处理

从节点不知道主节点的调度。它仅对 LIN 驱动程序通过 LinIf_HeaderIndication 报告的报头做出反应（SWS LinIf 第38页、[SWS_LinIf_91004]）。LinIf 对 PID 进行求值，并通过 PduPtr 告知驱动程序应当接收、发送还是忽略该帧（[SWS_LinIf_00733]、[SWS_LinIf_00739]、[SWS_LinIf_00748]）。对于发送帧，LinIf 仍在回调内部使用驱动程序的缓冲区调用 <User_TriggerTransmit>。响应的复制由驱动程序负责（[SWS_LinIf_00738]、SWS LinIf 第121页）。

报头之后是驱动程序回调：

  • 接收到的响应由 LinIf_RxIndication 报告；LinIf 通过 <User_RxIndication> 将其转发（[SWS_LinIf_91005]、[SWS_LinIf_00734]）。
  • 发送的响应由 LinIf_TxConfirmation 进行确认；随后是带有 E_OK 的 <User_TxConfirmation>（[SWS_LinIf_91006]、[SWS_LinIf_00741]）。
  • 如果在没有事先匹配报头的情况下收到这些回调，LinIf 会将其忽略（[SWS_LinIf_00848]、[SWS_LinIf_00852]）。

活动图：LinIf_HeaderIndication 中的 PID 求值决定了驱动程序是接收、发送还是忽略。来源：[SWS_LinIf_00733]、[SWS_LinIf_00738]、[SWS_LinIf_00739]、[SWS_LinIf_00740]、[SWS_LinIf_00748]、[SWS_LinIf_00775]、[SWS_LinIf_00776]、[SWS_LinIf_00846]、SWS LinIf 第134页

仅当存在挂起的响应时，从节点才会发送事件触发帧（Event-triggered Frame）。此时第一个数据字节包含相关无条件帧（Unconditional Frame）的 PID。发送成功后，挂起标志将被清除（[SWS_LinIf_00731]、[SWS_LinIf_00732]、SWS LinIf 第130页）。LinIf 在节点配置与传输层之间分发 MRF 和 SRF。如果存在挂起的配置响应，Node Configuration Handler 会应答 SRF；否则 SRF 报头将传递给 LinTp（[SWS_LinIf_00772]、[SWS_LinIf_00773]、[SWS_LinIf_00775]、[SWS_LinIf_00776]、SWS LinIf 第54页）。

休眠与唤醒：主节点与从节点的分离路径

LinIf_GotoSleep 异步工作。即使转换已在进行中或通道已处于休眠状态，它也会返回 E_OK（[SWS_LinIf_00204]、SWS LinIf 第88页）。对于主节点，示意图展示了其流程：主函数发送 Go-to-sleep 命令，随后对 Lin_GetStatus 进行求值。结果由 <User>_GotoSleepConfirmation 报告（SWS LinIf 第136页、[SWS_LinIf_00521]）。如果从节点在此确认之前请求唤醒，通道将保持处于 operational 状态（SWS LinIf 第37页）。

从节点在两种情况下进入休眠：接收到 NAD 为 0 的 MRF，或者总线空闲定时器（LinIfBusIdleTimeoutPeriod）超时。该定时器仅在 LINIF_CHANNEL_OPERATIONAL 中运行，并在每次驱动程序回调时重新启动（[SWS_LinIf_00750]、[SWS_LinIf_00751]、[SWS_LinIf_00752]、[SWS_LinIf_00753]、[SWS_LinIf_00754]、[SWS_LinIf_00755]）。LinIf 通过 <User>_GotoSleepIndication 报告休眠请求。如果用户随后调用 LinIf_GotoSleep，则会立即发生以下情况，而无需等待主函数：LinIf 调用 Lin_GoToSleepInternal，清除唤醒标志，并通过 TRUE 报告 <User>_GotoSleepConfirmation（[SWS_LinIf_00756]、[SWS_LinIf_00757]、[SWS_LinIf_00758]、[SWS_LinIf_00759]、SWS LinIf 第55页）。

时序图：在从节点中，LinIf_GotoSleep 直接调用驱动程序；收发器由用户选择性切换。来源：[SWS_LinIf_00756]、[SWS_LinIf_00757]、[SWS_LinIf_00758]、[SWS_LinIf_00759]、[SWS_LinIf_00544]、SWS LinIf 第137页

唤醒有两种途径（SWS LinIf 第51页）：

  • Bus-Wakeup：EcuM 通过 LinIf_CheckWakeup 对其进行检查。LinIf 根据来源调用 Lin_CheckWakeup 或 LinTrcv_CheckWakeup。驱动程序通过 LinIf_WakeupConfirmation 确认，随后 LinIf 设置通道的唤醒标志（[SWS_LinIf_00378]、[SWS_LinIf_00715]、SWS LinIf 第112页、SWS LinIf 第98页）。
  • 内部唤醒：用户调用 LinIf_Wakeup。如果通道处于休眠状态且未设置唤醒标志，LinIf 会调用 Lin_Wakeup。如果通道处于唤醒状态，LinIf 返回 E_OK，而不会调用驱动程序（[SWS_LinIf_00205]、SWS LinIf 第89页）。如果该标志已设置，则推测可能会改用 Lin_WakeupInternal；返回值描述表明了这一点（SWS LinIf 第89页）。

在从节点中，LinIf 只有在收到第一个报头且值为 TRUE 时才会确认唤醒。如果 LinIf_Wakeup 返回 E_NOT_OK，LinIf 会在此之前报告 FALSE。如果未收到第一个报头，则不会进行确认，且 LinSM 中会发生超时（[SWS_LinIf_00761]、[SWS_LinIf_00762]、SWS LinIf 第52页、SWS LinSM 第27页）。

时序图：Bus-Wakeup 会设置唤醒标志；从节点中的内部唤醒仅在收到第一个报头时才被确认。来源：[SWS_LinIf_00378]、[SWS_LinIf_00715]、[SWS_LinIf_00205]、[SWS_LinIf_00761]、[SWS_LinIf_00762]、SWS LinIf 第94页

通过 LIN TP 进行诊断以及符合 ISO 17987-3 的节点配置

LinTp 实现了 ISO 17987 的诊断传输层（Diagnostic Transport Layer），并且针对每个通道相互独立（SWS LinIf 第61页）。每个通道都有其独立的 LinTp 状态机：

  • LinTp_Init 设置状态 LINTP_INIT 及其子状态 LINTP_CHANNEL_IDLE。
  • 检测到 TP 报文会转换至 LINTP_CHANNEL_BUSY。
  • LinTp_Shutdown 关闭所有连接并转换回 LINTP_UNINIT。

依据：[SWS_LinIf_00350]、[SWS_LinIf_00710]、[SWS_LinIf_00322]、[SWS_LinIf_00323]、[SWS_LinIf_00355]、SWS LinIf 第102页。LinTp_ChangeParameter 仅为空存根且总是拒绝（[SWS_LinIf_00501]、SWS LinIf 第103页）。

状态图：每个通道的 LinTp 在 IDLE 和 BUSY 之间切换；LinTp_Shutdown 从任何子状态转换至 LINTP_UNINIT。来源：[SWS_LinIf_00322]、[SWS_LinIf_00323]、[SWS_LinIf_00710]、[SWS_LinIf_00355]、SWS LinIf 第43页

在主节点通道上，如果设置了 LinTpScheduleChangeDiag，LinTp 可以自行切换调度表。为此，它使用来自 LinTp_Mode 的值调用 BswM_LinTp_RequestMode（[SWS_LinIf_00629]、[SWS_LinIf_00360]、[SWS_LinIf_00707]、SWS LinIf 第62页）：

  • 在发送请求时切换至诊断请求调度表，
  • 在物理请求之后切换至诊断响应调度表，
  • 在响应之后切换至应用调度表，
  • 在功能请求之后切换回先前的调度表。

只有在请求的调度表切换已完成或失败后，才会执行 PduR_LinTpTxConfirmation。如果关联的调度表请求被拒绝，LinTp_Transmit 将返回 E_NOT_OK（[SWS_LinIf_00351]、[SWS_LinIf_00702]、[SWS_LinIf_00878]）。

时序图：在主节点收到诊断请求时，LinTp 通过 BswM 和 LinSM 触发三次调度表切换。来源：[SWS_LinIf_00360]、[SWS_LinIf_00520]、[SWS_LinIf_00702]、[SWS_LinIf_00878]、SWS LinIf 第62页、SWS LinIf 第92页

在从节点通道上，LinIf 管理节点模型：Initial-NAD、配置的 NAD、PID 和产品标识（[SWS_LinIf_00767]、[SWS_LinIf_00769]、SWS LinIf 第170页）。Node Configuration Handler 分别在下一个 SRF 报头时应答“Assign NAD”和“Assign Frame ID range”等。 “Assign NAD”和“Save Configuration”是可选的（[SWS_LinIf_00779]、[SWS_LinIf_00780]、[SWS_LinIf_00781]、[SWS_LinIf_00810]、[SWS_LinIf_00811]、[SWS_LinIf_00812]、[SWS_LinIf_00813]、SWS LinIf 第59页）。上层可以读取和设置 NAD 与 PID，例如使用来自非易失性存储器的数据。为此使用 LinIf_GetConfiguredNAD/LinIf_SetConfiguredNAD 以及 LinIf_GetPIDTable/LinIf_SetPIDTable。在此过程中，MRF 和 SRF 的 PID 无法更改（[SWS_LinIf_00830]、[SWS_LinIf_00834]、[SWS_LinIf_00816]、[SWS_LinIf_00823]、[SWS_LinIf_00809]、SWS LinIf 第57页）。

发生错误时的行为

如果开发错误检测处于激活状态，LinIf 会向 DET 报告错误。其中包括 LINIF_E_UNINIT、LINIF_E_NONEXISTENT_CHANNEL、LINIF_E_PARAM_POINTER 和 LINIF_E_SCHEDULE_REQUEST_ERROR 等（[SWS_LinIf_00376]）。此类错误例如发生在从节点回调中出现无效通道或无效指针时（[SWS_LinIf_00843]、[SWS_LinIf_00844]、[SWS_LinIf_00849]、[SWS_LinIf_00853]、[SWS_LinIf_00855]）。LinIf 识别的运行时错误包括 LINIF_E_RESPONSE 和 LINIF_E_NC_NO_RESPONSE（[SWS_LinIf_00729]、SWS LinIf 第71页）。

在从节点中，由 LinIf_LinErrorIndication 报告的故障被视作丢失响应。LinIf 随后会报告 LINIF_E_RESPONSE，但 LIN_ERR_HEADER 除外。对于受影响的发送帧，它以 E_NOT_OK 进行确认（[SWS_LinIf_91007]、[SWS_LinIf_00735]、[SWS_LinIf_00742]、[SWS_LinIf_00743]）。当仍在等待接收指示而新的报头到达时，同样适用此规则（[SWS_LinIf_00846]）。

特定响应错误会设置response_error信号。LinIf通过Com_SendSignal对其进行自主维护，并在成功发送后重新将其清除。该信号的每次更改均可由Callout上报（[SWS_LinIf_00736]、[SWS_LinIf_00744]、[SWS_LinIf_00763]、[SWS_LinIf_00764]、[SWS_LinIf_00747]、[SWS_LinIf_00765]、SWS LinIf 第58页）。

在节点配置中适用以下规则（[SWS_LinIf_00785]、[SWS_LinIf_00786]、[SWS_LinIf_00787]、[SWS_LinIf_00788]、[SWS_LinIf_00789]、[SWS_LinIf_00790]、[SWS_LinIf_00791]、SWS LinIf 第66页）：

  • N_As超时会中止待决的响应。
  • 带有未知NAD的请求会被丢弃。
  • 带有功能NAD（0x7E）或无效PCI的请求会被忽略。
  • 新的有效Request会替换待决的响应。
  • 受到干扰的MRF会保留待决的响应。

在LinTp中，N_As、N_Cs和N_Cr超时会终止传输或接收；PduR会收到E_NOT_OK（[SWS_LinIf_00799]、[SWS_LinIf_00801]、[SWS_LinIf_00802]、[SWS_LinIf_00804]、[SWS_LinIf_00806]、SWS LinIf 第73页、SWS LinIf 第66页）。同样，在序列号错误、CF之后出现FF或SF，以及——取决于LinTpDropNotRequestedNad——Response中出现外部NAD时，接收也会以E_NOT_OK结束（[SWS_LinIf_00081]、[SWS_LinIf_00653]、[SWS_LinIf_00655]）。

在缓冲区不足时，LinIf会采取分级响应（[SWS_LinIf_00676]、[SWS_LinIf_00677]、[SWS_LinIf_00792]、[SWS_LinIf_00879]、[SWS_LinIf_00679]、[SWS_LinIf_00680]、[SWS_LinIf_00793]、[SWS_LinIf_00795]、SWS LinIf 第65页）：

  • 如果启动接收失败，LinIf会直接中止，而不会再次调用PduR。
  • 如果复制失败，Master中的LinIf会首先切换回应用调度表，然后使用E_NOT_OK调用PduR_LinTpRxIndication。
  • 如果缓冲区过小，LinIf会暂停发送SRF报头，直到有足够的空闲空间。

较新的文档章节还描述了针对LinTp超时的Extended Production Errors。这些错误是在R23-11中才引入的，对于R20-11而言不具规范性（SWS LinIf 第1页）。
