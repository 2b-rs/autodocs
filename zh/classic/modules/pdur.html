通信栈中的角色：I-PDU的中立中介

PDU Router（PduR）将诸如Com或Dcm等与总线无关的用户与通信接口（CanIf、FrIf、LinIf）及传输协议（CanTp、FrTp）连接起来。它将I-PDU原封不动且一致地从源传输到目标[SWS_PduR_00160]。在此过程中，它仅沿着配置好的路由路径进行路由[SWS_PduR_00162]。一条路径由两项信息唯一确定：PduR配置的源I-PDU ID以及被调用模块的目标I-PDU ID[SWS_PduR_00161]。PduR在发送路径以及确认和指示路径中同样对这些ID进行转换[SWS_PduR_00766]、SWS PduR 第33页。

从ECU的角度来看，存在三类操作。第一类是向本地模块的接收，第二类是来自本地模块的发送，第三类是接口模块或TP模块之间的网关。接收和网关可以组合使用SWS PduR 第29页。相邻模块通过占位符<Up>、<Lo>和<LoTp>进行通用描述SWS PduR 第96页。也可以接入Complex Driver；届时其apiServicePrefix会替换占位符[SWS_PduR_00504]。每个相邻模块都有一个专属头文件，例如PduR_CanIf.h [SWS_PduR_00216]。

上下文图：PduR位于上层用户、接口模块和TP模块之间，并由BswM通过路由路径组进行控制。来源：[SWS_PduR_00424]、[SWS_PduR_00504]、SWS PduR 第96页、SWS BswM 第166页

在满足两个条件时，相邻模块允许直接相互调用：已设置PduRZeroCostOperation，且所有路由路径均为Pre-Compile[SWS_PduR_00287]。此时PduR成为纯宏层SWS PduR 第65页。如果哪怕只有一条路径不是Pre-Compile，生成器就必须报告错误[SWS_PduR_00619]。除此之外，生成器应优化掉未使用的特性，例如TP、网关或FIFO处理[SWS_PduR_00764]。

生命周期与配置状态：从PDUR_UNINIT到PDUR_ONLINE

恰好存在一个状态机[SWS_PduR_00644]。它包含来自PduR_StateType的PDUR_UNINIT和PDUR_ONLINE状态[SWS_PduR_00324]、[SWS_PduR_00742]。上电后，PduR处于PDUR_UNINIT [SWS_PduR_00325]。只有成功的PduR_Init才会将其带入PDUR_ONLINE [SWS_PduR_00326]、[SWS_PduR_00334]。仅在PDUR_ONLINE中进行路由[SWS_PduR_00328]，在PDUR_UNINIT中完全不进行路由[SWS_PduR_00330]。较旧的图表还显示了一个状态PDUR_REDUCED SWS PduR 第30页。然而对于R20-11，符合[SWS_PduR_00324]的双状态模型适用。

状态图：仅PduR_Init能从PDUR_UNINIT引导进入路由运行状态；重复进行Init调用属于错误。来源：[SWS_PduR_00324]、[SWS_PduR_00100]、[SWS_PduR_00296]、SWS PduR 第53页

PduR_Init接收指向PduR_PBConfigType的指针[SWS_PduR_00743]。该结构是具体实现相关的，位于PduR_PBcfg.c中[SWS_PduR_00241]。在初始化时，PduR完成三件事：

  • 它释放所有缓冲区[SWS_PduR_00645]。
  • 它使用配置的默认值填充发送缓冲区[SWS_PduR_00308]。
  • 它根据启动配置[SWS_PduR_00709]激活路由路径组，即依据PduRIsEnabledAtInit SWS PduR 第131页。

在Post-Build变体中，路由表是可替换的[SWS_PduR_00295]，但仅限于在未初始化状态下[SWS_PduR_00296]。PduR_GetConfigurationId提供当前活动配置的唯一PduRConfigurationId [SWS_PduR_00341]、[SWS_PduR_00280]、[SWS_PduR_00281]。其类型是基于uint16的PduR_PBConfigIdType [SWS_PduR_00771]。PduR_GetVersionInfo [SWS_PduR_00338]仅在设置了PduRVersionInfoApi时才可用System Template 第656页。

通过通信接口进行本地发送与接收

如果上层模块调用PduR_<User:Up>Transmit [SWS_PduR_00406]，PduR会为每个目标接口调用<Lo>_Transmit [SWS_PduR_00625]。在此过程中，它既不缓冲I-PDU[SWS_PduR_00629]，也不检查其长度[SWS_PduR_00745]。在单播情况下，它直接透传返回值[SWS_PduR_00432]。在多播情况下，只要有一个目标成功就足以获得E_OK [SWS_PduR_00218]。随后，仅在收到最后一个接口确认之后，才会向上层模块发送确认[SWS_PduR_00589]。在单播中，PduR将PduR_<User:Lo>TxConfirmation [SWS_PduR_00365]连同结果一起转发给<Up>_TxConfirmation [SWS_PduR_00627]。

在时间触发总线中，接口会自行获取数据，具体是通过PduR_<User:Lo>TriggerTransmit [SWS_PduR_00369]。PduR将此请求转发给<Up>_TriggerTransmit [SWS_PduR_00430]，并返回其返回值[SWS_PduR_00661]。接口使用PduR_<User:Lo>RxIndication报告接收到的I-PDU[SWS_PduR_00362]。随后，PduR为每个目标模块调用<Up>_RxIndication [SWS_PduR_00621]、[SWS_PduR_00164]，同样不进行长度检查[SWS_PduR_00744]。

时序图：通过FrIf发送分为时间上分离的三个阶段：请求、通过TriggerTransmit获取数据以及确认。来源：[SWS_PduR_00430]、[SWS_PduR_00627]、SWS PduR 第106页

用于分段I-PDU的传输协议路径

在TP路径上，PduR使用复制握手机制，从而支持大于单个帧的I-PDULayered Architecture 第97页。接收过程分为三个步骤：

  1. PduR将PduR_<User:LoTp>StartOfReception [SWS_PduR_00507]转发给<Up>_StartOfReception [SWS_PduR_00549]，并透传其返回值[SWS_PduR_00623]。
  2. 随后是对各个段的CopyRxData调用[SWS_PduR_00512]、[SWS_PduR_00428]。
  3. 最后以接收指示[SWS_PduR_00375]、[SWS_PduR_00429]结束。

使用SduLength = 0的复制调用仅查询可用缓冲区或可用数据[SWS_PduR_00740]。

时序图：在TP接收过程中，PduR针对每个段向上层模块请求缓冲区，并原封不动地返回其响应。来源：[SWS_PduR_00549]、[SWS_PduR_00428]、[SWS_PduR_00429]、SWS PduR 第75页

在发送时，PduR 为每个目标 TP 调用 <LoTp>_Transmit [SWS_PduR_00634]。TP 模块随后使用 PduR_<User:LoTp>CopyTxData 获取数据 [SWS_PduR_00518]。PduR 将这些调用转发给 <Up>_CopyTxData [SWS_PduR_00299]、[SWS_PduR_00676]。在多播情况下，它首先针对每个位置使用 TP_CONFPENDING 进行复制；对于所有其他目标，它使用 TP_DATARETRY 复制相同的数据 [SWS_PduR_00631]、[SWS_PduR_00632]。在单播情况下，<Up>_TpTxConfirmation 直接跟随 [SWS_PduR_00301]。在多播情况下，它仅在最后一次确认后发生，并且若至少有一个目标成功，则伴随 E_OK [SWS_PduR_00765]、[SWS_PduR_00381]。发送请求的目标要么仅为接口，要么仅为 TP 模块，绝不可混合 [SWS_PduR_00633]。

时序图：在 TP 多播中，PduR 从上层模块多次获取相同数据，并将确认合并为一个。来源：[SWS_PduR_00631]、[SWS_PduR_00632]、[SWS_PduR_00765]、SWS PduR 第86页

网络间的网关操作：缓冲、FIFO 和 On-the-fly

在接口之间，PduR 支持 1:n 网关路由 [SWS_PduR_00436]。它会立即转发 I-PDU，且不生成自身的发送时钟 [SWS_PduR_00437]。I-PDU 仅在接口之间或仅在 TP 之间路由，绝不可混合 [SWS_PduR_00638]。PduR 是否进行缓冲，取决于目标的数据提供方式：

  • 对于 PDUR_DIRECT，目标接口已在 Transmit 调用中复制数据 [SWS_PduR_00303]。
  • 对于 PDUR_TRIGGERTRANSMIT，PduR 会对 I-PDU 进行缓冲，直到触发 TriggerTransmit 调用 [SWS_PduR_00306]。

在没有缓冲的情况下，PduR 转发接收长度或目标长度这两者中的较小值 [SWS_PduR_00783]。在有缓冲的情况下，它最多复制 PduRPduMaxLength [SWS_PduR_00746]。

可以为每个目标 I-PDU 配置一个 FIFO [SWS_PduR_00307]。从 PduRQueueDepth > 1 起，缓冲区表现为 FIFO [SWS_PduR_00785]，并且新的 I-PDU 会追加在末尾 [SWS_PduR_00787]。在直接提供方式下，规则如下：如果 FIFO 为空且没有未决确认，PduR 会立即发送 [SWS_PduR_00665]。否则，它会将 I-PDU 入队 [SWS_PduR_00793]，并在下一次确认后发送 [SWS_PduR_00667]。对于 Trigger-Transmit，PduR 复制最早的条目并将其移除；如果之后仍有内容残留，它将再次调用 <DstLo>_Transmit [SWS_PduR_00666]。如果 FIFO 为空，则检索返回 E_NOT_OK [SWS_PduR_00662]。

活动图：在接口网关中，数据提供方式和 FIFO 状态决定 PduR 是立即发送、入队还是等待 TriggerTransmit。来源：[SWS_PduR_00665]、[SWS_PduR_00786]、[SWS_PduR_00255]、SWS PduR 第112页

TP 网关在以下两种模式之一中工作：

  • 直接：PduR 仅在成功接收指示之后才调用 <DstLoTp>_Transmit [SWS_PduR_00551]。
  • On-the-fly：一旦达到 PduRTpThreshold，便开始进一步发送 [SWS_PduR_00317]。该模式仅允许用于恰好一个目标 TP [SWS_PduR_00708]、SWS PduR 第58页。

如果 TpSduLength 适合专用缓冲区，PduR 将使用该缓冲区；否则，它从 PduRTxBuffer 中动态获取缓冲区 [SWS_PduR_00797]、[SWS_PduR_00798]。它将 MetaData 透传给目标 [SWS_PduR_00794]。如果额外配置了本地接收器，PduR 会在成功接收后在该模块处启动单独的接收会话 [SWS_PduR_00789]。

时序图：在 On-the-fly 网关中，一旦达到阈值，CAN1 上的接收与 CAN2 上的发送便会重叠。来源：[SWS_PduR_00317]、[SWS_PduR_00708]、[SWS_PduR_00518]、SWS PduR 第100页

在运行时切换路由路径组

PduRRoutingPathGroup 容器对某个网络或某种 PDU 类型的路径进行汇总 SWS PduR 第131页。它们通过 PduR_RoutingPathGroupIdType（一个 uint16）进行寻址 [SWS_PduR_00654]。它们使用 PduR_EnableRouting 和 PduR_DisableRouting 进行切换 [SWS_PduR_00615]、[SWS_PduR_00617]。参数 initialize 决定单个缓冲区是重置为默认值还是予以保留 [SWS_PduR_00617]。激活立即生效 [SWS_PduR_00715]。如果某个 API 使用了已禁用路径的 I-PDU-ID，则在返回类型允许的前提下，PduR 会不执行进一步操作直接返回 E_NOT_OK [SWS_PduR_00717]。这明确同样适用于取消函数 [SWS_PduR_00710]、[SWS_PduR_00726]。

典型的调用者是通过操作 BswMPduRouterControl 进行调用的 BswM SWS BswM 第166页。《模式管理指南》提到了两个用例：没有 Com-I-PDU 组的 I-PDU（例如通过 LdCom），以及根据 ComM 向 BswM 报告的 PNC 状态进行切换 Mode-Management-Guide 第50页。后续版本明确了如何重新评估具有多个组的路径 SWS PduR 第69页。这些规则不属于此处呈现的 R20-11 要求。

时序图：BswM 禁用路由路径组；受影响路径上的发送调用将失败，直到该组被重新激活。来源：[SWS_PduR_00617]、[SWS_PduR_00717]、[SWS_PduR_00715]、Mode-Management-Guide 第50页

发生错误时的行为

如果 PduRDevErrorDetect 处于激活状态，PduR 会向 DET 报告开发错误 [SWS_PduR_00100]、SWS PduR 第72页：

  • 配置指针无效时报告 PDUR_E_INIT_FAILED [SWS_PduR_00100]。
  • PDUR_E_UNINIT 在初始化前的调用中，PduR_Init 和 PduR_GetVersionInfo [SWS_PduR_00119] 除外，以及在 PDUR_UNINIT [SWS_PduR_00100] 之外 PduR_Init 时。
  • PDU-ID 无效时报告 PDUR_E_PDU_ID_INVALID [SWS_PduR_00221]。
  • 空指针时报告 PDUR_E_PARAM_POINTER [SWS_PduR_00100]。
  • 组 ID 未知时报告 PDUR_E_ROUTING_PATH_GROUP_ID_INVALID [SWS_PduR_00648]、[SWS_PduR_00649]。在这种情况下，切换函数本身无效果直接返回 [SWS_PduR_00647]、[SWS_PduR_00716]。

PduR 不报告生产错误 SWS PduR 第60页。

若丢失 I-PDU 实例，PduR 会报告运行时错误 PDUR_E_PDU_INSTANCES_LOST。该错误是在 AUTOSAR 4.3.1 中引入的 SWS PduR 第3页；它通过 Det_ReportRuntimeError 报告 [SWS_PduR_91001]。两种情况会触发该错误：

  • FIFO 已满：PduR 清空它，并像 FIFO 为空时一样处理新的 I-PDU [SWS_PduR_00255]、[SWS_PduR_00669]、[SWS_PduR_00670]。
  • <DstLo>_Transmit 返回 E_NOT_OK：PduR 丢弃该实例并发送下一个 [SWS_PduR_00788]、[SWS_PduR_00807]。

解读：禁用某个组应被视为 [SWS_PduR_00663] 意义上的“停止”；关联的 FIFO 届时也应被清空。

PduR 不会重试失败的网关发送 [SWS_PduR_00256]。对于具有单个目标的本地发送，上层模块会接收到目标的返回值 [SWS_PduR_00626]、[SWS_PduR_00700]。对于多个目标，[SWS_PduR_00701] 要求所有目标均返回 E_OK；推测这涉及 TP 发送路径，而对于接口多播，根据 [SWS_PduR_00218]，一次成功即已足够。

对于 TP 接收和 TP 网关，以下规则适用：

  • 错误的 TP 接收指示，PduR 在本地仅予以转发 [SWS_PduR_00207]；在网关中，它们会终止处理 [SWS_PduR_00689]。
  • 如果 On-the-fly 网关无法存储数据，PduR 将返回 BUFREQ_E_NOT_OK [SWS_PduR_00687]。如果完全缺少缓冲区，它将返回 BUFREQ_E_OVFL [SWS_PduR_00799]。
  • 如果某个目标发生故障，其余目标继续运行 [SWS_PduR_00803]、[SWS_PduR_00806]。只有当所有 TP 目标均失败时，PduR 才会终止接收端 [SWS_PduR_00804]。
  • 在发生错误时，PduR 会中止网关中的本地 TP 接收器，或使用 E_NOT_OK 对其进行指示 [SWS_PduR_00790]、[SWS_PduR_00791]、[SWS_PduR_00792]。

使用

错误处理

关于可能出现的错误状态，为 PduR_EnableRouting 指定了以下错误代码（[SWS_PduR_00100]）：

  • PDUR_E_ROUTING_PATH_GROUP_ID_INVALID（0x08）：当向函数传入无效的路由表或路由路径组 ID 时检测到（[SWS_PduR_00100]）。
  • PDUR_E_UNINIT（0x01）：在 PDU 路由器模块成功初始化之前调用此 API 服务时发生（[SWS_PduR_00100]）。

使用

同步函数 PduR_DisableRouting（[SWS_PduR_00617]）用于停用 PDU 路由器中的路由路径组（Routing Path Group）。它没有返回值（void），并通过头文件 PduR.h 提供。

调用时，该函数需要两个输入参数：

  • id：标识待停用的路由路径组，如 PDU 路由器配置中所确定。
  • initialize：控制单缓冲区（Single Buffers）的处理。当传入 true 时，这些缓冲区被初始化为其默认值；传入 false 时，则保留当前缓冲区内容。

并发性与限制

根据 [SWS_PduR_00617]，该函数被指定为可重入。为了使调用有效，必须预先初始化 PduR 模块。

  • 若在模块未初始化的情况下调用该函数，则涉及错误 PDUR_E_UNINIT（错误值 0x01）。
