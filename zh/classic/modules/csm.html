CSM 在加密用户与驱动层之间的角色

Crypto Service Manager（CSM）是 Classic 加密栈的服务层。它提供两类服务：加密服务本身与密钥管理 SWS CSM 第25页。加密操作通过与作业相关的函数进行请求。示例包括 Csm_Hash [SWS_Csm_00980]、Csm_MacGenerate [SWS_Csm_00982]、Csm_Encrypt [SWS_Csm_00984]、Csm_AEADEncrypt [SWS_Csm_01023]、Csm_SignatureVerify [SWS_Csm_00996] 和 Csm_RandomGenerate [SWS_Csm_01543]。

向下，CSM 通过 Crypto Interface（CryIf）将作业转发给 Crypto Driver Objects。规范将从 CSM 队列经由 CryIf 到 Crypto Driver Object 的路径称为通道。Crypto Driver Object 可以是硬件（例如 HSM 中的 AES 加速器）或软件 SWS CSM 第29页。向上，应用程序通过 RTE 端口将 CSM 作为 AUTOSAR 服务使用 SWS CSM 第85页。BSW 模块也会访问它：

  • SecOC 由此计算并校验 Authenticator SWS SecOC 第78页。
  • DCM 由此在身份验证时校验签名 SWS DCM 第152页。
  • KeyM 由此设置并验证密钥 SWS KeyM 第80页。

自 R19-11 起，证书处理不再属于 CSM，而是属于 Key Manager Release Overview 第32页。

作为配置对象的 Job、原语、密钥和队列

核心单元是 Job，即已配置的加密原语 [SWS_Csm_00941] 的实例。在运行时由 Crypto_JobType 对其进行描述。该结构尤其包含 jobId、jobState、输入和输出结构 Crypto_JobPrimitiveInputOutputType 以及指向常量 Crypto_JobPrimitiveInfoType 的指针 [SWS_Csm_01013] [SWS_Csm_01009] SWS CSM 第20页。Crypto_JobPrimitiveInfoType 携带回调标识、CryIf 密钥和处理方式 Crypto_ProcessingType [SWS_Csm_01012] [SWS_Csm_01049]。原语本身由 Crypto_PrimitiveInfoType 确定，由服务和算法组成。算法包括族、次要族、密钥长度和模式 [SWS_Csm_01011] [SWS_Csm_01031] [SWS_Csm_01008]。可选地，Crypto_JobRedirectionInfoType 可将输入和输出重定向至密钥元素 [SWS_Csm_91026] [SWS_Csm_91024]。

从服务调用到驱动程序处理

服务是同步还是异步运行，由 Job 配置决定。因此，服务函数被指定为“Synchronous or Async, depending on the job configuration” [SWS_Csm_00980] [SWS_Csm_00982]。第 7.2 章（引自 R24-11）规定了以下规则 SWS CSM 第21页：

  • 每个 Job 在同一时刻仅处理一个实例；不同的 Job 允许并行运行。
  • 如果 Job 已经处于 ACTIVE 状态，CSM 直接调用 CryIf_ProcessJob 并透传其返回值。
  • 如果必须排队 Job 且队列已满，CSM 将以 CRYPTO_E_BUSY 拒绝。

队列根据配置的优先级对 Job 进行排序 [SWS_Csm_00940] [SWS_Csm_00944]。

流式处理、单次调用与 Job 状态

类型为 Crypto_OperationModeType 的参数 mode 是由 START (0x01)、UPDATE (0x02) 和 FINISH (0x04) 组成的位字段。组合值为 CRYPTO_OPERATIONMODE_STREAMSTART (0x03) 和 CRYPTO_OPERATIONMODE_SINGLECALL (0x07) [SWS_Csm_01029] [SWS_Csm_01039]。模式的作用如下：

  • START 重置 Job 并丢弃之前的输入和中间结果 [SWS_Csm_01029]。
  • 重复的 UPDATE 以流式处理方式处理大数据量。相比之下，单次调用（Single Call）可节省小数据量时的调用开销 EXP Krypto-Dienste 第12页。
  • 没有 UPDATE 的 START 和 FINISH 将被以 E_NOT_OK 拒绝 [SWS_Csm_01045]。
  • FINISH 完成计算 [SWS_Csm_01046]。

Crypto_JobStateType 具有两种状态 [SWS_Csm_01028]：

  • CRYPTO_JOBSTATE_IDLE：在 Csm_Init 之后或完成 FINISH 之后，
  • CRYPTO_JOBSTATE_ACTIVE：在 START 或 UPDATE 之后。

根据规范说明，实际的状态转换由 Crypto Driver 执行 SWS CSM 第22页。

状态图：Job 通过 START 转换为 ACTIVE，在 UPDATE 时保持在该状态，并在 FINISH 后返回 IDLE。SINGLECALL 在单次调用中遍历所有步骤。来源：[SWS_Csm_01028]、[SWS_Csm_01029]、[SWS_Csm_01039]

运行中的 Job 可以中断和继续。Csm_SaveContextJob 将工作上下文保存在应用缓冲区中，Csm_RestoreContextJob 恢复该上下文 [SWS_Csm_91063] [SWS_Csm_91064]。密钥元素不属于该上下文 SWS CSM 第35页。Csm_CancelJob 取消异步或流式 Job [SWS_Csm_00968]。为此，CSM 从其队列中移除该 Job 或调用 CryIf_CancelJob SWS CSM 第80页。

密钥管理：元素、有效性、生成与交换

一个密钥由一个或多个密钥元素组成 [SWS_Csm_00954]。它们的 ID 已标准化，例如 CRYPTO_KE_MAC_KEY (1)、CRYPTO_KE_CIPHER_IV (5) 和 CRYPTO_KE_KEYGENERATE_SEED (16) [SWS_Csm_01022]。密钥服务仅作为 Csm_<Service> 函数提供 [SWS_Csm_00950]。基本服务是同步的，其中包括 Csm_KeyElementSet、Csm_KeySetValid 和 Csm_KeyElementGet [SWS_Csm_00957] [SWS_Csm_00958] [SWS_Csm_00959]。如果元素直接位于 Flash 中，这些调用可能会耗费更长时间。只要密钥函数在运行，CSM 直到下一次 MainFunction 调用前都不会从队列中取出新 Job SWS CSM 第60页。

密钥状态（CRYPTO_KEYSTATUS_INVALID 或 CRYPTO_KEYSTATUS_VALID）由 Csm_KeyGetStatus [SWS_Csm_91102] [SWS_Csm_91047] 返回。Csm_KeySetValid 将密钥设为有效。Csm_KeySetInvalid 阻止其用于加密操作，直到再次将其设为有效 [SWS_Csm_00958] [SWS_Csm_91075]。此外还有基于作业的变体，如 Csm_JobKeySetValid、Csm_JobKeyGenerate 和 Csm_JobKeyDerive。根据 Job 配置，它们同步或异步运行 [SWS_Csm_91027] [SWS_Csm_91029] [SWS_Csm_91030]。

其他密钥服务：

  • 复制：通过 Csm_KeyElementCopy 按元素复制，通过 Csm_KeyElementCopyPartial 部分复制，或通过 Csm_KeyCopy [SWS_Csm_00969] [SWS_Csm_91025] [SWS_Csm_01034] 作为完整密钥复制。
  • 生成：在 Csm_KeyGenerate 之前，CRYPTO_KE_KEYGENERATE_SEED 中必须存在随机值，例如来自 Csm_RandomGenerate。算法由 CRYPTO_KE_KEYGENERATE_ALGORITHM [SWS_Csm_00955] SWS CSM 第67页 确定。
  • 派生：Csm_KeyDerive 写入目标密钥并调用 CryIf_KeyDerive [SWS_Csm_00956] [SWS_Csm_01018]。
  • 交换：对于 Diffie-Hellman，两个通信方使用 Csm_KeyExchangeCalcPubVal 和 Csm_KeyExchangeCalcSecret 确定共享秘密，而无需暴露各自的私有部分 [SWS_Csm_00966] [SWS_Csm_00967] SWS CSM 第70页。

发生错误时的行为

服务返回 Std_ReturnType，异步结果返回 Crypto_ResultType。除 E_OK 和 E_NOT_OK 外，还存在特定代码，如 CRYPTO_E_BUSY、CRYPTO_E_ENTROPY_EXHAUSTED、CRYPTO_E_KEY_READ_FAIL、CRYPTO_E_KEY_WRITE_FAIL、CRYPTO_E_KEY_NOT_AVAILABLE 以及 CRYPTO_E_KEY_NOT_VALID [SWS_Csm_91044] [SWS_Csm_91043]。密钥函数还报告 CRYPTO_E_KEY_SIZE_MISMATCH 与 CRYPTO_E_KEY_EMPTY [SWS_Csm_00969] [SWS_Csm_00956]。如果 Csm_KeyElementSet 失败，则元素的状态视为未知。应用程序随后可通过 Csm_KeyGetStatus 对其进行检查 SWS CSM 第62页。

  • CSM_E_PARAM_POINTER：空指针，
  • CSM_E_PARAM_HANDLE：ID 超出范围，
  • CSM_E_UNINIT：初始化前调用，
  • CSM_E_INIT_FAILED：初始化失败，
  • CSM_E_PROCESSING_MODE：无效的处理模式。

  • E_OK：作业已从队列中移除，且在适用情况下已从驱动程序硬件中移除。
  • CRYPTO_E_JOB_CANCELED：无法立即取消。取消操作将在下一个合适步骤进行，并通过负向完成回调进行报告。
