控制每个 LIN 网络的通信模式、唤醒、休眠和调度表切换。

LIN State Manager 将 ComM 针对每个 LIN 网络的通信请求转换为对 LIN Interface 的调用。它将由此产生的状态 LINSM_FULL_COM 和 LINSM_NO_COM 报告给 ComM 与 BswM [SWS_LinSM_00126]。它直接启动唤醒、休眠以及仅在主节点（Master）上的调度表切换，并使用 LinSM_MainFunction 中的定时器监控确认信息。在从节点（Slave）上，由主节点决定休眠：仅 LinSM_GotoSleepIndication 会触发 LinIf_GotoSleep [SWS_LinSM_00231]。如果迁移失败，LinSM 会重新报告先前的状态，以使上层保持一致。

LIN State Manager 是面向 LIN 的总线状态管理器（Bus State Manager）。ComM 通过它请求网络的通信能力（SWS ComM 第19页）。它通过 LinSM_RequestComMode 接收模式请求 [SWS_LinSM_00126]。它控制 LinIf 并向 ComM 和 BswM 报告状态 [SWS_LinSM_00229]。哪个 LIN 驱动程序服务于网络则对上隐藏在 LinIf 之后（SWS LinSM 第28页）。

上下文图：ComM 和 BswM 控制 LinSM，LinSM 控制 LinIf，LinIf 通过回调返回报告。来源：[SWS_LinSM_00229]、[SWS_LinSM_00138]、SWS LinSM 第28页

在 LinSM_Init 之后，每个网络均处于 LINSM_NO_COM 状态 [SWS_LinSM_00155]。此时不会通知 ComM 和 BswM（SWS LinSM 第23页）。仅允许在 LINSM_FULL_COM 中进行通信。进入该状态时，ComM 和 BswM 会收到通知，并进入子状态 LINSM_RUN_COMMUNICATION [SWS_LinSM_00301]。对于 BswM 而言，仅 LINSM_FULL_COM 和 LINSM_NO_COM 可见 [SWS_LinSM_00220]。

状态图：针对每个网络，LinSM 通过唤醒和休眠确认在 LINSM_NO_COM 与 LINSM_FULL_COM 之间切换。来源：[SWS_LinSM_00155]、[SWS_LinSM_00301]、SWS LinSM 第20页

LinSM 在调用中直接启动唤醒与休眠。它使用 LinSM_MainFunction [SWS_LinSM_00156] 中的定时器监控 LinIf 的确认（SWS LinSM 第28页）。在主节点上，对 COMM_NO_COMMUNICATION 的请求会立即导致 LinIf_GotoSleep [SWS_LinSM_00036]。在从节点上，该请求仅被保存 [SWS_LinSM_00230]；只有 LinSM_GotoSleepIndication 才会触发休眠 [SWS_LinSM_00231]。Silence-after-Wakeup 定时器会延迟再次唤醒尝试 [SWS_LinSM_00237]。

调度切换仅存在于主节点上 [SWS_LinSM_00241]。LinSM 将 LinSM_ScheduleRequest 直接传递给 LinIf，并通过 BswM_LinSM_CurrentSchedule 报告结果（SWS LinSM 第26页）。对于错误处理，规定如下：

  • LinSM 向 DET 报告开发错误，错误代码来自 [SWS_LinSM_00053]。
  • LinIf 未返回回调被视为 LINSM_E_CONFIRMATION_TIMEOUT [SWS_LinSM_00224]。
  • 迁移失败后，LinSM 会重新设置先前的状态，以便一致地通知 ComM 和 BswM [SWS_LinSM_00177]。

在 ComM、BswM 与 LIN Interface 之间的角色

LIN State Manager（LinSM）是面向 LIN 的总线状态管理器。与其他总线状态管理器一样，ComM 通过它请求网络的通信能力（SWS ComM 第19页）。用于此目的的核心入口接口是 LinSM_RequestComMode [SWS_LinSM_00126]。当前模式由 LinSM_GetCurrentComMode [SWS_LinSM_00122] 提供。LinSM 仅在网络层面上工作。由哪个 LIN 驱动程序服务于网络被 LinIf 所屏蔽。因此，包含多个不同 LIN 驱动程序的 ECU 不会对 LinSM 产生影响（SWS LinSM 第28页）。

必选接口包括向下的 LinIf_GotoSleep 与 LinIf_ScheduleRequest，以及向上的通知 ComM_BusSM_ModeIndication、ComM_BusSM_BusSleepMode、BswM_LinSM_CurrentState 和 BswM_LinSM_CurrentSchedule [SWS_LinSM_00229]（SWS LinSM 第41页）。LinSM 在唤醒序列中调用 LinIf_Wakeup（SWS LinSM 第27页）。它可以选择性使用 Det_ReportError 和 LinIf_SetTrcvMode [SWS_LinSM_00138]。LinIf 通过以下回调返回报告：

  • LinSM_WakeupConfirmation [SWS_LinSM_00132]
  • LinSM_GotoSleepConfirmation [SWS_LinSM_00135]
  • LinSM_GotoSleepIndication [SWS_LinSM_91000]
  • LinSM_ScheduleRequestConfirmation [SWS_LinSM_00129]

导入的类型如 ComM_ModeType、NetworkHandleType 和 LinIf_SchHandleType 由 [SWS_LinSM_00219] 确定。

上下文图：LinSM 充当上方 ComM、BswM 与下方 LinIf 之间的中介；LIN 驱动程序隐藏在 LinIf 之后。来源：[SWS_LinSM_00126]、[SWS_LinSM_00229]、[SWS_LinSM_00138]、[SWS_LinSM_00156]、SWS LinSM 第28页、Mode-Management-Guide 第54页

每个 LIN 网络的状态模型、初始化与周期性部分

启动时，在任何 API 调用之前，模块范围的状态 LINSM_UNINIT 处于激活状态（SWS LinSM 第22页）。LinSM_Init 是同步且不可重入的 [SWS_LinSM_00155]。该函数接收一个指向实现特定类型 LinSM_ConfigType [SWS_LinSM_00221] 的 post-build 配置的指针。此后，每个网络均处于父状态 LINSM_INIT 的子状态 LINSM_NO_COM 中。LinSM_Init 不会将这第一次迁移通知 ComM，也不会通知 BswM，因为 ComM 在此时尚未完成初始化（SWS LinSM 第23页）。在模式管理指南的示例中，BswM 规则在 Lin_Init 和 LinIf_Init 之后调用 LinSM_Init(null)（Mode-Management-Guide 第54页）。

在 LINSM_NO_COM 下总线保持静止（SWS LinSM 第23页）。仅在 LINSM_FULL_COM 下允许在总线上通信，并且每个网络独立于其他网络达到该状态。进入时发生以下情况（SWS LinSM 第23页）：

  • ComM 收到带有 COMM_FULL_COMMUNICATION 的消息，BswM 收到带有 LINSM_FULL_COM 的消息。
  • 若配置了 LinSMTransceiverPassiveMode，LinSM 会通过 LinIf_SetTrcvMode 将收发器切换为激活状态。
  • 进入子状态 LINSM_RUN_COMMUNICATION [SWS_LinSM_00301]。

临时子状态 LINSM_GOTO_SLEEP 用于过渡等待睡眠确认的过程（SWS LinSM 第20页，SWS LinSM 第21页）。对于 BswM，只有 LinSM_ModeType 的两个值可见：LINSM_FULL_COM (0x01) 和 LINSM_NO_COM (0x02) [SWS_LinSM_00220]。

时间监控运行在 LinSM_MainFunction 中。该周期性函数维护请求超时的定时器 [SWS_LinSM_00156]。唤醒确认定时器也在其中运行，每个网络具有独立的定时器（SWS LinSM 第28页）。相反，实际的总线操作由 LinSM 在调用中直接启动，而无需等待下一个 Main-Function 周期 [SWS_LinSM_00036] [SWS_LinSM_00231]。

状态图：针对每个网络，LinSM 通过唤醒和睡眠确认在 LINSM_NO_COM 与 LINSM_FULL_COM 之间切换；LINSM_GOTO_SLEEP 仅为等待状态。来源：[SWS_LinSM_00155]，[SWS_LinSM_00301]，SWS LinSM 第20页，SWS LinSM 第21页，SWS LinSM 第24页

唤醒：从 LINSM_NO_COM 到 LINSM_FULL_COM

当 ComM 通过 LinSM_RequestComMode 请求完全通信时，LIN 网络被唤醒。若其他节点唤醒总线，则不由此 LinSM 处理，而由 EcuM 处理；该情况同样会导致 ComM 发起请求（SWS LinSM 第27页）。随后 LinSM 直接调用 LinIf_Wakeup 并重置最大重试次数计数器。若 LinIf 已处于唤醒状态，则会忽略该调用。在调用之前，LinSM 会使用 LinSMConfirmationTimeout 为该通道启动唤醒确认定时器。该值必须为 0 或 Main-Function 周期的整数倍（SWS LinSM 第28页）。

若 LinSM_WakeupConfirmation 报告 success = TRUE，则网络切换至 LINSM_FULL_COM [SWS_LinSM_00132]。在所有其他情况下，LinSM 会重新设置请求前的状态，以便 ComM 和 BswM 仍能收到模式指示（SWS LinSM 第27页）。对于从节点，LinIf 仅在接收到主节点的第一个 LIN 报头时才进行确认。若主节点未开始调度，则不会收到确认，并触发 LinSM 的超时（SWS LinIf 第52页）。

时序图：LinSM 在调用中立即唤醒网络，但状态更改仅随 LinIf 的异步确认发生。来源：[SWS_LinSM_00126]，[SWS_LinSM_00132]，[SWS_LinSM_00224]，SWS LinSM 第42页，SWS LinSM 第27页

第二个时间限制是带有 LinSMSilenceAfterWakeupTimeout 的唤醒后静默定时器（Silence-after-Wakeup 定时器）[SWS_LinSM_00235]。只要它在运行，即使 ComM 请求完全通信，LinSM 也会延迟 LinIf_Wakeup 的新调用 [SWS_LinSM_00237]。超时后，只要 ComM 继续请求 COMM_FULL_COMMUNICATION，LinSM 就会重新启动唤醒流程 [SWS_LinSM_00236]。启动定时器的条件位于此处未提供的需求中，因此不作描述。

活动图：对完全通信的请求根据定时器状态和反馈结束于 LINSM_FULL_COM、旧状态或确认超时中。来源：[SWS_LinSM_00237]，[SWS_LinSM_00236]，[SWS_LinSM_00224]，SWS LinSM 第27页，SWS LinSM 第28页

进入睡眠：主节点请求，从节点跟随总线

Goto-Sleep 流程在主节点与从节点之间有所不同。在两种情况下，LinSM 都会向 BswM 和 ComM 报告进入无通信模式（No-Communication 模式），即使发生问题也是如此（SWS LinSM 第24页）。

对于主节点适用：

  • 若 ComM 在 LINSM_FULL_COM 下请求 COMM_NO_COMMUNICATION，LinSM 会调用 LinIf_GotoSleep，后者发送 Goto-Sleep 命令 [SWS_LinSM_10208]。
  • 该调用直接执行 [SWS_LinSM_00036]。在所有其他情况下均不执行 [SWS_LinSM_10209]。
  • 该调用仅在子状态 LINSM_RUN_COMMUNICATION 下被允许（SWS LinSM 第24页）。
  • 若 LinIf_GotoSleep 返回 E_NOT_OK，则 LinSM_RequestComMode 同样返回 E_NOT_OK。原状态被重新设置，以便 ComM 和 BswM 获得指示 [SWS_LinSM_00177]。

随后 LinIf 调用 LinSM_GotoSleepConfirmation [SWS_LinSM_00135]。若 LinSM 当时处于 LINSM_FULL_COM/LINSM_GOTO_SLEEP，则无论参数 success 为何，均切换至 LINSM_NO_COM。在任何其他状态下，它都会忽略该确认（SWS LinSM 第24页）。规范示意图在 LinIf_GotoSleep 之前启动定时器，并在确认后停止该定时器（SWS LinSM 第47页）。

时序图：在主节点中，ComM 触发进入睡眠；LINSM_NO_COM 仅在收到睡眠确认后才达到，LinIf_GotoSleep 返回 E_NOT_OK 会导致重新报告旧状态。来源：[SWS_LinSM_00036]，[SWS_LinSM_00177]，[SWS_LinSM_00135]，SWS LinSM 第47页，SWS LinSM 第24页

在从节点中，由主节点决定进入睡眠。若 ComM 在 LINSM_FULL_COM 下请求 COMM_NO_COMMUNICATION，LinSM 仅保存该请求并返回 E_OK [SWS_LinSM_00230]。当接收到 Goto-Sleep 命令或发生总线空闲超时时，LinIf 报告 LinSM_GotoSleepIndication [SWS_LinSM_91000]。只有在此之后，LinSM 才会直接调用 LinIf_GotoSleep [SWS_LinSM_00231]。后续流程取决于所保存的请求：

  • 若请求了 COMM_NO_COMMUNICATION 且 LinIf_GotoSleep 返回 E_OK，则 ComM 通过 ComM_BusSM_BusSleepMode 获知总线睡眠事件 [SWS_LinSM_00233]。
  • 若请求了完全通信，则 LinSM 在睡眠确认后重新启动唤醒流程 [SWS_LinSM_00234]。

在 LinIf 中，从节点流程将控制器以及（若支持）收发器置于睡眠模式（SWS LinIf 第137页）。

时序图：在从节点中，ComM 的睡眠请求仅被保存，进入睡眠由 LinIf 的指示触发。来源：[SWS_LinSM_00230]，[SWS_LinSM_00231]，[SWS_LinSM_00233]，[SWS_LinSM_00234]，SWS LinSM 第48页，SWS LinSM 第24页

切换调度表（仅主节点）

仅当至少有一个通道配置为主节点时，LinSM_ScheduleRequest [SWS_LinSM_00113] 才存在 [SWS_LinSM_00241]。回调 LinSM_ScheduleRequestConfirmation [SWS_LinSM_00242] 亦是如此。该异步函数直接将请求传递至 LinIf_ScheduleRequest，无需通过 Main Function 中转。它将其返回值返回给调用方（SWS LinSM 第26页）。调用方是 BswM。它使用 LinSMScheduleIndex 作为符号引用，其值必须与 LinIf 中的值一致（SWS LinSM 第52页）。LIN 传输协议的诊断调度切换同样通过 BswM 和 LinSM_ScheduleRequest 进行（SWS LinIf 第142页）。

LinSM 通过 BswM_LinSM_CurrentSchedule 报告结果（SWS BswM 第80页）。报告哪个调度取决于执行过程（SWS LinSM 第26页）：

  • 若 LinSM_ScheduleRequestConfirmation [SWS_LinSM_00129] 在定时器到期前确认，LinSM 则报告新调度。
  • 若定时器已到期，它报告未更改的调度。
  • 若 LinIf_ScheduleRequest 返回 E_NOT_OK，它会在下一次 Main-Function 调用中报告旧调度。
  • 它也会报告未经预先请求的切换，例如 LinIf 在进入睡眠时执行的向 NULL 调度的切换。

时序图：调度切换被直接传递并受时间监控；BswM 在每种结果中都能获知实际有效的调度。来源：[SWS_LinSM_00113]，[SWS_LinSM_00129]，[SWS_LinSM_00156]，SWS LinSM 第26页，SWS LinSM 第48页

节点类型、配置及与后续版本的差异

参数 LinSMNodeType 决定某通道适用主节点还是从节点行为。LinSM_ScheduleRequest、LinSM_ScheduleRequestConfirmation 和 LinSM_GotoSleepIndication 是否可用取决于此 [SWS_LinSM_00241] [SWS_LinSM_00242] [SWS_LinSM_00243]。最重要的时间参数是 LinSMConfirmationTimeout（SWS LinSM 第28页）和 LinSMSilenceAfterWakeupTimeout [SWS_LinSM_00235]。LinSMSchedule 容器引用 LinIf 配置中的调度（SWS LinSM 第52页）。DET 检查依赖于 LinSMDevErrorDetect [SWS_LinSM_00239]。

许多文档出处来自后续版本。对于 R20-11，以需求为准，并在某些地方有所偏差：

  • LinSM_ScheduleRequest 的第二个参数在 R20-11 中名为 schedule，并被描述为“Pointer to the new Schedule table”，尽管其类型为 LinIf_SchHandleType [SWS_LinSM_00113]。在 R22-11 中它被重命名（SWS LinSM 第1页，Release Overview 第50页）；在 R24-11 中它名为 ScheduleTableIdx（SWS LinSM 第34页）。
  • 在 R20-11 中，LinSM_GetCurrentComMode 具有服务 ID 0x11 [SWS_LinSM_00122]，LinSM_RequestComMode 具有服务 ID 0x12 [SWS_LinSM_00126]。后续版本指定为 0x41 和 0x40，并仅允许针对不同网络重入（SWS LinSM 第35页，SWS LinSM 第36页）。
  • ComM 回调在 R20-11 中名为 ComM_BusSM_… [SWS_LinSM_00233]，在 R25-11 中名为 ComM_<Bus>SM_…（SWS LinSM 第41页）。

发生错误时的行为

[SWS_LinSM_00053] 规定了开发错误：

  • LINSM_E_UNINIT (0x00)
  • LINSM_E_NONEXISTENT_NETWORK (0x20)
  • LINSM_E_PARAMETER (0x30)
  • LINSM_E_PARAM_POINTER (0x40)
  • LINSM_E_INIT_FAILED (0x50)

当 LinSMDevErrorDetect 激活时，回调会检查网络和初始化，例如 LinSM_GotoSleepIndication [SWS_LinSM_00239] [SWS_LinSM_00240]。回调没有返回值，因此在这些地方仅进行 DET 报告（SWS LinSM 第40页，SWS LinSM 第39页）。带有 Std_ReturnType 的 API 还会返回 E_NOT_OK，例如在网络、模式或调度无效时，或在 LINSM_UNINIT 状态下（SWS LinSM 第36页，SWS LinSM 第34页）。解释：这些检查源自 R24-11 起的版本，且在内容上对 R20-11 应该同样适用。值得注意的是，后续版本对于 void API LinSM_GetVersionInfo [SWS_LinSM_00117] 在指针为 NULL 时同样要求返回 E_NOT_OK（SWS LinSM 第34页）。

对于未收到的 LinIf 回调，LINSM_E_CONFIRMATION_TIMEOUT (0x00) 被指定为运行时错误 [SWS_LinSM_00224]。推测其通过 Det_ReportRuntimeError 报告，后续版本将其列为必选接口（SWS LinSM 第41页）。在功能上，LinSM 确保 ComM 和 BswM 始终看到一致的状态：

  • 在唤醒失败后，它会重新设置并报告旧状态（SWS LinSM 第27页）。
  • 当 LinIf_GotoSleep 返回 E_NOT_OK 时同样如此 [SWS_LinSM_00177]。
  • 即使 success = FALSE，睡眠确认也会导致切换至 LINSM_NO_COM（SWS LinSM 第24页）。
  • 在调度切换失败时，BswM 会收到旧调度或未更改的调度（SWS LinSM 第26页）。

LIN State Manager (LinSM)

管理LIN网络的状态转换。

特点——概述

  • void LinSM_Init (const LinSM_ConfigType* ConfigPtr); This function initializes the Lin SM.
  • Std_ReturnType LinSM_ScheduleRequest (NetworkHandleType network, LinIf_SchHandleType schedule); The upper layer requests a schedule table to be changed on one LIN network.
  • void LinSM_GetVersionInfo (Std_VersionInfoType* versioninfo); -
  • Std_ReturnType LinSM_GetCurrentComMode (NetworkHandleType network, ComM_ModeType* mode); Function to query the current communication mode.
  • Std_ReturnType LinSM_RequestComMode (NetworkHandleType network, ComM_ModeType mode); Requesting of a communication mode.
