LinSM 在 ComM、BswM 和 LinIf 之间的角色

LIN State Manager（LinSM）是 LIN 的总线状态管理器。ComM 向各总线状态管理器请求其用户所需的通信能力 SWS ComM 第19页。对于 LIN，这是通过 LinSM_RequestComMode 实现的 [SWS_LinSM_00126]。LinSM 将每个 LIN 网络的这些请求转换为对 LIN Interface 的调用。它通过必选接口 ComM_BusSM_ModeIndication、ComM_BusSM_BusSleepMode、BswM_LinSM_CurrentState 和 BswM_LinSM_CurrentSchedule 返回结果。它还通过 LinIf_GotoSleep 和 LinIf_ScheduleRequest 等来控制总线 [SWS_LinSM_00229]。可选地，它使用 Det_ReportError 和 LinIf_SetTrcvMode [SWS_LinSM_00138]。

系统边界划分严格。LinSM 仅管理网络；由哪个 LIN 驱动程序服务于网络则由 LinIf 进行封装 SWS LinSM 第28页。由集群引起的唤醒不由 LinSM 处理，而是由 EcuM 处理。这会导致 ComM 请求网络，因此 LinSM 在这两种情况下都只能看到 COMM_FULL_COMMUNICATION SWS LinSM 第27页。该模块导入类型 ComM_ModeType、NetworkHandleType 和 LinIf_SchHandleType [SWS_LinSM_00219]。

每个 LIN 网络的状态模型

启动时，甚至在调用任何 API 之前，LINSM_UNINIT 就处于激活状态SWS LinSM 第22页。LinSM_Init 使用指向 LinSM_ConfigType 的指针初始化该模块[SWS_LinSM_00155] [SWS_LinSM_00221]。此后，每个网络均适用 LINSM_NO_COM。LinSM_Init 既不会向 ComM 也不会向 BswM 报告此首次转换，因为此时 ComM 可能尚未初始化SWS LinSM 第23页。在 LINSM_NO_COM 中，总线保持静默。

LINSM_FULL_COM 是唯一允许在 LIN 总线上进行通信的状态。每个网络均独立于其他网络达到该状态。进入时，ComM 接收 COMM_FULL_COMMUNICATION，BswM 接收 LINSM_FULL_COM SWS LinSM 第23页。子状态 LINSM_RUN_COMMUNICATION 变为激活状态[SWS_LinSM_00301]。LinSM 通过 LinSM_ModeType 使用值 LINSM_FULL_COM (0x01) 和 LINSM_NO_COM (0x02) 向 BswM 报告[SWS_LinSM_00220] SWS BswM 第72页。

第二个子状态 LINSM_GOTO_SLEEP 用于过渡等待休眠确认的时间。如果在该子状态下收到 LinSM_GotoSleepConfirmation，LinSM 将独立于参数 success 转换至 LINSM_NO_COM；在所有其他状态下，该回调均被忽略SWS LinSM 第24页。据推测，一旦 LinIf_GotoSleep 返回 E_OK 就会进入 LINSM_GOTO_SLEEP；资料在此处中断。较早的示意图将该运行状态称为 LINSM_RUN_SCHEDULE SWS LinSM 图 5 第22页。应以 [SWS_LinSM_00301] 中的名称为准。

唤醒：从 ComM 请求到 LINSM_FULL_COM

LinSM_RequestComMode 异步工作。模式切换不会立即发生，LinSM 会在完成后通知调用者[SWS_LinSM_00126]。当处于 COMM_FULL_COMMUNICATION 时，LinSM 会直接调用 LinIf_Wakeup（即无需等待下一个 Main Function），并重置重试计数器SWS LinSM 第27页。在此之前，它使用 LinSMConfirmationTimeout 为该网络启动一个确认定时器SWS LinSM 第27页。

LinIf 通过 LinSM_WakeupConfirmation 报告唤醒信号的发送[SWS_LinSM_00132]。当 success = TRUE 时，网络转换至 LINSM_FULL_COM。否则，LinSM 会重新设置之前的状态，以便 ComM 和 BswM 仍能收到模式通知SWS LinSM 第27页。如果配置了 LinSMTransceiverPassiveMode，LinSM 在进入 LINSM_FULL_COM 时通过 LinIf_SetTrcvMode 将收发器激活SWS LinSM 第23页。

带有 LinSMSilenceAfterWakeupTimeout 的 Silence-after-Wakeup 定时器可防止过于密集的唤醒尝试[SWS_LinSM_00235]。如果 ComM 在该定时器运行期间请求 COMM_FULL_COMMUNICATION，LinSM 会将 LinIf_Wakeup 延迟至超时[SWS_LinSM_00237]。如果在超时后仍请求完全通信，LinSM 将重新启动唤醒过程[SWS_LinSM_00236]。

从节点仅在接收到主节点的第一个 LIN 报头时才确认唤醒SWS LinIf 第52页。如果主节点未开始调度，则不会收到确认。随后 LinSM 中的定时器会超时，以避免其无休止等待SWS LinSM 第27页。

休眠：主节点发送，从节点响应

Master:如果 ComM 在 LINSM_FULL_COM 中请求 COMM_NO_COMMUNICATION，LinSM 会调用 LinIf_GotoSleep 以发送 Goto-Sleep 命令[SWS_LinSM_10208]。该调用直接发生，即无需等待下一个 Main Function[SWS_LinSM_00036]。在所有其他情况下均不执行该调用[SWS_LinSM_10209]。若 LinIf_GotoSleep 返回 E_NOT_OK，则 LinSM_RequestComMode 也会返回 E_NOT_OK。与此同时，LinSM 会重新设置之前的状态，以便通知 ComM 和 BswM[SWS_LinSM_00177]。

命令是否已发送由 LinIf 通过 LinSM_GotoSleepConfirmation 报告[SWS_LinSM_00135]。向 BswM 和 ComM 报告进入 LINSM_NO_COM 在任何情况下都会发生，即使在出现问题后也是如此SWS LinSM 第24页。

时序图：主节点上的 Goto-Sleep，包含根据 LinIf_GotoSleep 的返回值进行的分支。来源：[SWS_LinSM_00036]、[SWS_LinSM_00177]、[SWS_LinSM_00135]、SWS LinSM 图 6 第47页

Slave:如果 ComM 在 LINSM_FULL_COM 中请求 COMM_NO_COMMUNICATION，LinSM 仅保存该请求并返回 E_OK [SWS_LinSM_00230]。触发由总线发起。当接收到 Goto-Sleep 命令或发生总线空闲超时时，LinIf 会调用 LinSM_GotoSleepIndication [SWS_LinSM_91000]。随后 LinSM 会在 LINSM_FULL_COM 中直接调用 LinIf_GotoSleep [SWS_LinSM_00231]。

如果 LinIf_GotoSleep 返回 E_OK 且曾请求过 COMM_NO_COMMUNICATION，LinSM 会通过 ComM_BusSM_BusSleepMode 向 ComM 报告总线休眠事件[SWS_LinSM_00233]。后续版本在表述该义务时没有包含 E_OK 条件SWS LinSM 第26页；对于 R20-11，该需求有效。反之，如果请求了完全通信，LinSM 会在 Goto-Sleep 序列之后重新启动唤醒过程[SWS_LinSM_00234]。

切换调度表（仅 LIN 主节点）

LinSM_ScheduleRequest 和 LinSM_ScheduleRequestConfirmation 仅在至少有一个通道被配置为主节点时存在[SWS_LinSM_00241] [SWS_LinSM_00242]。上层通过 LinSM_ScheduleRequest 异步请求另一张调度表[SWS_LinSM_00113]。LinSM 立即将该请求转发给 LinIf_ScheduleRequest 并返回其返回值SWS LinSM 第26页。典型的调用者是使用符号 LinSMScheduleIndex 的 BswMSWS LinSM 第52页。LIN 传输协议流程 (LinTp) 也以此方式通过 BswM 切换至诊断表SWS LinIf 第142页。

配置：节点类型、时间基准与初始化

LinSMNodeType 决定 API 范围。一旦某个通道为主节点，就会提供主节点功能；一旦某个通道为从节点，就会提供 LinSM_GotoSleepIndication [SWS_LinSM_00241] [SWS_LinSM_00243]。因此混合配置是可行的。Post-Build 参数位于特定于实现的结构体 LinSM_ConfigType 中[SWS_LinSM_00221]。

LinSM 通过 LinSMDevErrorDetect 向 DET 报告开发错误。代码为 LINSM_E_UNINIT、LINSM_E_NONEXISTENT_NETWORK、LINSM_E_PARAMETER、LINSM_E_PARAM_POINTER 和 LINSM_E_INIT_FAILED [SWS_LinSM_00053]。诸如 LinSM_GotoSleepIndication 之类的回调会报告无效网络或 UNINIT 状态[SWS_LinSM_00239] [SWS_LinSM_00240]。服务在发生此类错误时还会额外返回 E_NOT_OK SWS LinSM 第36页。传递给 LinSM_GetCurrentComMode 和 LinSM_GetVersionInfo 的无效指针会导致 LINSM_E_PARAM_POINTER SWS LinSM 第35页 SWS LinSM 第34页。

用法与语义

函数 LinSM_ScheduleRequest（[SWS_LinSM_00113]）用于上层请求在 LIN 网络上切换调度表。该服务通过头文件 LinSM.h 提供，异步工作，并被指定为可重入。

传入参数：

  • network（NetworkHandleType）：LIN 通道的标识。
  • schedule（LinIf_SchHandleType）：指向新请求的调度表的指针或句柄。

返回值与错误行为

该函数返回类型为 Std_ReturnType 的状态（[SWS_LinSM_00113]）：

  • E_OK：对调度表的请求已成功接受。
  • E_NOT_OK：无法执行该请求（例如，当模块未初始化时）。
