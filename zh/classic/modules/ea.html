将逻辑存储块映射到 EEPROM 地址，并异步处理读取和写入作业。

EEPROM Abstraction 将 NvM 的逻辑块映射到 EEPROM 的地址，并在 R20-11 中使用驱动程序 Eep。读取、写入、无效化和擦除作业被同步接收，并在周期性调用的 Main Function 中异步执行（[SWS_Ea_00096]）。模块通过回调向 NvM 报告完成或失败，或通过作业结果进行报告。写入始终涉及整个块。只有在 R20-11 中仍存在 Ea_SetMode 和同步的 Ea_Cancel（[SWS_Ea_00088]）。

EEPROM Abstraction (Ea) 将逻辑块映射到 EEPROM 地址。它位于 MemIf 和 EEPROM 驱动程序 Eep 之间；块编号同时表示该块的起始地址（[SWS_Ea_00087]）。在底层，Ea 在 R20-11 中使用 Eep 服务进行读取、写入、擦除、取消和模式切换（[SWS_Ea_00097]）。直到 R21-11，MemAcc 才取代驱动程序 Eep，并且 Ea_SetMode 不复存在（SWS EA 第1页）。

上下文图：Ea 位于 NvM/MemIf 与 Eep 之间，由 EcuM 初始化并由 BSW 调度器驱动。来源：[SWS_Ea_00084]、[SWS_Ea_00096]、[SWS_Ea_00097]

在使用指向配置集的指针（[SWS_Ea_00084]）执行 Ea_Init 之后，Ea_GetStatus 报告状态 MEMIF_IDLE、MEMIF_BUSY 或 MEMIF_BUSY_INTERNAL 之一（[SWS_Ea_00089]）。最后一个状态代表诸如垃圾回收之类的内部管理（SWS EA 第28页）。

读取、写入、无效化和立即擦除均为异步。E_OK 仅确认作业已被接收。执行在周期性调用的 Ea_MainFunction 中进行（[SWS_Ea_00086]，[SWS_Ea_00096]）。读取可以采用任意偏移量和任意长度。写入始终涉及偏移量为零的整个块（SWS EA 第25页）。写入作业也在 Main Function 中启动属于一种解释。

时序图：同步接收，通过 Eep 异步执行，并通过回调向 NvM 提供反馈。来源：SWS Eep 第50页、[SWS_Ea_00094]、[SWS_Ea_00099]

Ea_Cancel 在 R20-11 中是同步的（[SWS_Ea_00088]）。模块通过代码 EA_E_UNINIT 至 EA_E_INVALID_CANCEL 报告错误（[SWS_Ea_91001]，[SWS_Ea_91002]）。根据配置，硬件错误通过两种途径之一传递到 NvM：

  • 通过查询作业结果 MEMIF_JOB_FAILED，
  • 通过回调 NvM_JobErrorNotification。

恢复分别由 NvM 接管（ErrorDescription 第48页）。

在存储栈中的角色：从逻辑块到 EEPROM 地址

EEPROM Abstraction (Ea) 位于存储栈中的 Memory Abstraction Interface (MemIf) 与 EEPROM 驱动程序 (Eep) 之间。它向上层提供面向块的服务。块编号表示一个逻辑块，同时表示其在 EEPROM 中的起始地址（[SWS_Ea_00086]，[SWS_Ea_00087]）。MemIf 将读取和写入作业转发给参数 DeviceIndex 所选取的抽象模块，并透传其返回值（SWS MemIf 第18页，SWS MemIf 第19页）。

在底层，Ea 在 R20-11 中使用 EEPROM 驱动程序的服务：Eep_Read、Eep_Write、Eep_Erase、Eep_Cancel、Eep_GetStatus、Eep_GetJobResult 和 Eep_SetMode。此外还有 Det_ReportRuntimeError（[SWS_Ea_00097]）。Det_ReportError 是可选接口（[SWS_Ea_00098]）。导入的类型 Eep_AddressType、Eep_LengthType、MemIf_StatusType、MemIf_JobResultType 和 MemIf_ModeType 反映了这种嵌入结构（[SWS_Ea_00083]）。

关于版本分类：根据变更历史记录，从 R21-11 起 Ea_SetMode 被移除。此外，Ea_Cancel 变为异步，引入了缓冲区对齐，且 MemAcc 取代 Eep 成为下层（SWS EA 第1页）。因此对于 R20-11，Eep 仍作为下层，且 Ea_SetMode 仍作为服务。缓冲区对齐的规则（SWS EA 第19页）不适用于 R20-11。

上下文图：Ea 在上层的 NvM/MemIf 与底层的驱动程序 Eep 之间起中介作用。EcuM 初始化该模块，BSW 调度器周期性驱动它，DET 接收错误消息。来源：[SWS_Ea_00084]、[SWS_Ea_00096]、[SWS_Ea_00097]、[SWS_Ea_00098]、[SWS_Ea_00099]、[SWS_Ea_00100]、SWS EA 第34页

启动与模块状态

Ea_Init 同步初始化该模块且不可重入。ConfigPtr 指向所选的配置集（[SWS_Ea_00084]）。Ea_ConfigType 是具有实现特定元素的结构（[SWS_Ea_00190]）。根据规范的时序图，ECU State Manager 在启动时调用 Ea_Init（SWS EA 第47页）。由于这只是单次调用，因此它在下方的状态图中显示为转换。

Ea_GetStatus 将操作状态同步返回为 MemIf_StatusType（[SWS_Ea_00089]）：

  • MEMIF_UNINIT：初始化之前。
  • MEMIF_IDLE：既没有作业也没有内部管理在运行。
  • MEMIF_BUSY：正在处理上层作业。
  • MEMIF_BUSY_INTERNAL：内部管理操作正在运行，例如 EEPROM 存储器的重组（垃圾回收）。在此期间，驱动程序也可能暂时被占用。

这些状态在 SWS EA 第28页 中进行了描述。模块在状态 MEMIF_IDLE 以及状态 MEMIF_BUSY_INTERNAL 下都会接收写入作业（SWS EA 第25页）。

状态图：模块状态从 MEMIF_UNINIT 经由 MEMIF_IDLE 到 MEMIF_BUSY 或 MEMIF_BUSY_INTERNAL 的生命周期。在内部管理期间也可以接收写入作业。来源：[SWS_Ea_00084]、[SWS_Ea_00089]、SWS EA 第28页、SWS EA 第25页、SWS EA 第27页

接收作业并在 Ea_MainFunction 中处理

Ea_Read、Ea_Write、Ea_InvalidateBlock 和 Ea_EraseImmediateBlock 是异步的。E_OK 仅表示模块已接收该作业。E_NOT_OK 表示它拒绝了该作业（[SWS_Ea_00086]、[SWS_Ea_00087]、[SWS_Ea_00091]、[SWS_Ea_00093]）。在得出结果之前，Ea_GetJobResult 报告值 MEMIF_JOB_PENDING（[SWS_Ea_00090]）。

实际工作由 Ea_MainFunction 完成，可通过 SchM_Ea.h 使用（[SWS_Ea_00096]）。Basic Software 调度器直接调用该函数。它既没有参数也没有返回值，且不可重入（SWS EA 第36页）。

活动图：接收作业时的检查及其错误代码。检查顺序为一种假定。来源：[SWS_Ea_91001]、[SWS_Ea_91002]、[SWS_Ea_00089]、[SWS_Ea_00090]、SWS EA 第25页

Ea_Read 根据块编号和偏移量计算读取地址。偏移量和长度可取其类型范围内的任意值，从而允许从块内的任意位置读取任意数量的字节。读取操作明确在 Main Function 中异步运行（SWS EA 第24页）。

Ea_Write 根据块编号以固定的零偏移量计算写入地址。该函数将长度设置为为该块配置的长度（SWS EA 第25页）。因此，写入始终涉及整个块（[SWS_Ea_00087]）。关于写入作业的图表显示了经由 Eep_Write、周期性 Eep_MainFunction、Ea_JobEndNotification 和 NvM_JobEndNotification 的进一步路径（SWS Eep 第50页）。

解释：对于读取，明确要求在 Ea_MainFunction 中启动驱动程序作业。对于写入，应该同样适用，因为 Ea_MainFunction 会处理所请求的作业（[SWS_Ea_00096]）。对于特定制造商的库，时序图仅对与调用模块的关系具有约束力，对驱动程序的调用则不具约束力（SWS EA 第45页）。

时序图：写入作业被同步接收，通过驱动程序异步执行，并通过回调报告给 NvM。来源：SWS Eep 第50页、SWS MemIf 第19页、[SWS_Ea_00087]、[SWS_Ea_00094]、[SWS_Ea_00099]

块管理：地址映射、一致性与无效化

图 7.1 对比了虚拟存储器和物理存储器。块编号（16 位）和偏移量（16 位）构成虚拟地址，使得一个块最多可包含 64 KiB。在物理上，块按照配置的虚拟页大小 EA_VIRTUAL_PAGE_SIZE 对齐；未使用的虚拟空间不占用存储（SWS EA 第23页）。

Ea 为每个块维护各自的一致性信息。在写入过程启动时，该块被视为不一致；成功结束后，再次被视为一致。Ea 必须能够将不一致的块与有意无效化的块区分开来（SWS EA 第19页，R24-11 版本）。对于调用者而言，这两种情况通过作业结果 MEMIF_BLOCK_INCONSISTENT 和 MEMIF_BLOCK_INVALID 可见（[SWS_Ea_00090]）。

Ea_InvalidateBlock 将块 BlockNumber 无效化（[SWS_Ea_00091]）。根据具体实现，这可以通过驱动程序的擦除函数进行，也可以通过内部管理信息进行（该信息随后必须非易失性存储）（SWS EA 第31页）。

Ea_EraseImmediateBlock 删除一个块（[SWS_Ea_00093]）。该函数专为诊断或可比较的系统服务而设计，这些服务会预先删除即时数据（Immediate 数据）所在的区域。该函数计算地址时采用偏移量零。它确保 Ea 能够写入即时数据（SWS EA 第34页）。

运行模式、取消与通知

在 R20-11 中，Ea_SetMode 使用 MemIf_ModeType 类型的参数 Mode 切换 EEPROM 驱动程序的模式。该服务是异步且不可重入的（[SWS_Ea_00085]）。API 元素中不带参数的简短签名与此不符；以服务描述为准。示意图展示了链路 NvM → MemIf_SetMode → Ea_SetMode → Eep_SetMode（SWS EA 第42页）。自 R21-11 起，该服务被移除（SWS EA 第1页）。

时序图：模式切换从 NvM 经由 MemIf 和 Ea 一直透传至驱动程序（仅至 R20-11）。来源：[SWS_Ea_00085]、SWS EA 第52页、SWS EA 第42页

Ea_Cancel 取消正在执行的异步作业，并且在 R20-11 中是同步的（[SWS_Ea_00088]）。后续文档位置将该服务描述为异步；对于 R20-11，以需求为准。根据该处的内容规定：在状态 MEMIF_BUSY 下，Ea 调用驱动程序的取消函数并重置其内部变量。作业结果随后为 MEMIF_JOB_CANCELED（SWS EA 第27页）。MemIf 转发该取消请求（SWS MemIf 第20页）。在没有挂起作业的情况下执行取消将返回 EA_E_INVALID_CANCEL（[SWS_Ea_91002]）。

时序图：Ea_Cancel 根据模块状态分支为在驱动程序处取消、错误消息或无更改返回。来源：[SWS_Ea_00088]、[SWS_Ea_91002]、[SWS_Ea_00097]、SWS EA 第27页、SWS MemIf 第20页

底层通过 Ea_JobEndNotification 或 Ea_JobErrorNotification 报告异步作业的成功或失败（[SWS_Ea_00094]、[SWS_Ea_00095]）。Ea 随后向 NvM 发出来自 NvM_MemIf.h 的 NvM_JobEndNotification 或 NvM_JobErrorNotification 信号（[SWS_Ea_00099]、[SWS_Ea_00100]）。MemIf 本身不提供回调（SWS MemIf 第24页）。

回调可以在中断级别运行。因此其运行时间必须保持很短，且系统设计必须使配置与其相协调（SWS EA 第35页）。Ea_GetVersionInfo 是唯一可重入的服务（[SWS_Ea_00092]）。

发生错误时的行为

错误代码位于两个表中。

  • 第一个表（[SWS_Ea_91001]）：EA_E_UNINIT (0x01)、EA_E_INVALID_BLOCK_NO (0x02)、EA_E_INVALID_BLOCK_OFS (0x03)、EA_E_PARAM_POINTER (0x04) 和 EA_E_INVALID_BLOCK_LEN (0x05)。
  • 第二个表（[SWS_Ea_91002]）：EA_E_BUSY (0x06) 和 EA_E_INVALID_CANCEL (0x08)。

EA_E_INIT_FAILED 在 R20-11 中被移除（SWS EA 第1页）。解释：第一个表可能通过可选的 Det_ReportError 记录开发错误，第二个表通过 Det_ReportRuntimeError 记录运行时错误（[SWS_Ea_00097]、[SWS_Ea_00098]）。

在开发错误检测处于激活状态且处于未初始化状态时：Ea_GetJobResult 报告 EA_E_UNINIT 并返回 MEMIF_JOB_FAILED（SWS EA 第30页）。Ea_Cancel 报告 EA_E_UNINIT 并在不更改内部变量的情况下返回（SWS EA 第27页）。Ea_GetVersionInfo 在指针为 NULL 时报告 EA_E_PARAM_POINTER（SWS EA 第32页）。Ea_InvalidateBlock 和 Ea_EraseImmediateBlock 仅在 DET 处于激活状态时返回 E_NOT_OK（[SWS_Ea_00091]、[SWS_Ea_00093]）。

硬件错误由 EEPROM 驱动程序检测。Ea 的响应取决于具体实现。根据配置，可通过以下两种途径之一进行报告：通过查询作业结果 MEMIF_JOB_FAILED，或通过回调 NvM_JobErrorNotification。恢复由 NvM 负责（ErrorDescription 第48页、[SWS_Ea_00095]、[SWS_Ea_00100]）。对于查询途径，错误描述指明了 Eep_GetJobResult。Ea 在其 Main Function 中查询此函数推测意图如此，但未明确规定。

作业结果对错误类型进行了细致区分（[SWS_Ea_00090]）：

  • MEMIF_JOB_CANCELED：已取消，视为失败。
  • MEMIF_JOB_FAILED：作业失败。
  • MEMIF_BLOCK_INCONSISTENT：块可能包含损坏的数据。
  • MEMIF_BLOCK_INVALID：块已被作废，操作无法执行。

时序图：根据配置，驱动程序错误通过回调或通过查询作业结果传达至 NvM。来源：ErrorDescription 第48页、[SWS_Ea_00095]、[SWS_Ea_00100]、[SWS_Ea_00090]、[SWS_Ea_00097]
