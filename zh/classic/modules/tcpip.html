在以太网栈中通过 TCP 和 UDP 为上一层提供 IP 通信以及地址管理。

TcpIp 在 Classic 以太网栈中提供带有 ARP、NDP、ICMP 和 DHCP 的 IPv4 与 IPv6，以及 UDP 和 TCP，从而为 SoAd 等 Socket-Owner 提供服务 [SWS_TCPIP_00052]。EthSM 为每个 EthIf 控制器管理 ONLINE、ONHOLD 和 OFFLINE 状态。仅当为控制器分配了本地地址时，它才会变为 ONLINE [SWS_TCPIP_00085]。Socket 被请求、绑定，并在 TCP 情况下进行主动或被动连接，数据通过发送服务和回调运行。最重要的边界条件：TcpIp 仅在 ONLINE 状态下接受新的 TCP 连接，并且在 ONHOLD 下拒绝新的发送请求。

在 Classic 以太网栈中，TcpIp 负责 IP 通信。它由针对 IPv4（带有 ARP、ICMP、DHCP 和 Auto-IP）、IPv6（带有 NDP、ICMPv6 和 DHCPv6）以及 UDP、TCP 和 TLS 的子模块构成（[SWS_TCPIP_00052]，[SWS_TCPIP_00150]）。向上，它通过专属的 TcpIp_<Up>GetSocket 函数和回调为 Socket-Owner（即 SoAd 或 CDD）提供服务（[SWS_TCPIP_00220]，[SWS_TCPIP_00222]）。向下，它与 EthIf 交换帧 [SWS_TCPIP_00029]。

上下文图：TcpIp 位于 Socket-Owner 与 EthIf 之间，由 EthSM 控制，并向 DET 和 IdsM 报告。来源：[SWS_TCPIP_00220]，[SWS_TCPIP_00070]，[SWS_TCPIP_00361]，SWS TcpIp 第17页

TcpIp 为每个 EthIf 控制器单独维护通信状态 [SWS_TCPIP_00083]。EthSM 通过 TcpIp_RequestComMode 请求 ONLINE、ONHOLD 或 OFFLINE 状态之一 [SWS_TCPIP_00070]。STARTUP 和 SHUTDOWN 为过渡状态，无法被请求 [SWS_TCPIP_00089]。ONLINE 启动地址分配。ONHOLD 保留 Socket 和地址，但不接受发送请求。OFFLINE 关闭 Socket（[SWS_TCPIP_00075]，[SWS_TCPIP_00074]，[SWS_TCPIP_00072]）。

状态图：只有在为控制器分配了地址后，它才会变为 ONLINE。它通过释放资源的 SHUTDOWN 走向 OFFLINE。来源：[SWS_TCPIP_00085]，[SWS_TCPIP_00077]，[SWS_TCPIP_00087]，SWS TcpIp 第60页

地址源自一个已配置的本地地址表。它们以静态方式、通过 DHCP 或作为链路本地地址进行分配，按优先级选择，并可根据需要保存在 NvM 中（[SWS_TCPIP_00099]，[SWS_TCPIP_00065]，[SWS_TCPIP_00127]，[SWS_TCPIP_00219]）。<Up_LocalIpAddrAssignmentChg> 向上一层通知变更 [SWS_TCPIP_00229]。Socket 被请求并使用 TcpIp_Bind 绑定。TCP 连接通过 TcpIp_TcpConnect 或 TcpIp_TcpListen 建立（[SWS_TCPIP_00111]，[SWS_TCPIP_00112]，[SWS_TCPIP_00113]）。

发送通过 TcpIp_TcpTransmit 异步进行，或通过 TcpIp_UdpTransmit 同步进行。对于 TCP，上一层直接传递数据或通过 <Up_CopyTxData> 提供数据（[SWS_TCPIP_00124]，[SWS_TCPIP_00120]）。TcpIp 根据本地地址和端口将接收到的数据报分配给某个 Socket [SWS_TCPIP_00170]。若缺少目标的 MAC 地址，则 TcpIpArpPacketQueueEnabled 决定是将报文排队还是丢弃 [SWS_TCPIP_00192]。超时、无法访问的主机或地址冲突等运行时错误由 TcpIp 报告给 DET。在 R20-11 中为此定义了代码 0x01 至 0x05 [SWS_TCPIP_00255]。为了实现安全防护，还加入了 TLS 1.2 及以上版本以及带有 IKEv2 的 IPsec（[SWS_TCPIP_00302]，[SWS_TCPIP_00353]）。

在以太网栈中的角色：Socket-Owner 与 EthIf 之间的中介

TcpIp 在各子模块中汇集了 Classic ECU 的基于 IP 的通信 [SWS_TCPIP_00052]。对于 IPv4，要求支持 IP、ARP、ICMP、DHCPv4（客户端和服务器）、Auto-IP、UDP 和 TCP（[SWS_TCPIP_00053]，[SWS_TCPIP_00056]，[SWS_TCPIP_00058]，[SWS_TCPIP_00057]，[SWS_TCPIP_00061]）。对于 IPv6，还增加了 IPv6、NDP、ICMPv6 和一个 DHCPv6 客户端（[SWS_TCPIP_00160]，[SWS_TCPIP_00164]，[SWS_TCPIP_00166]）。三个扩展类别对支持范围进行了划分：IPv4 栈、IPv6 栈和双栈 SWS TcpIp 第18页。对于类别 3，全部范围均为强制性要求 [SWS_TCPIP_00150]。

向上，TcpIp 为 Socket-Owner 提供服务。若 TcpIpSocketOwnerUpperLayerType 设为 SOAD，回调名称为 SoAd_…。对于 CDD，适用的则是配置的函数名称（[SWS_TCPIP_00220]，[SWS_TCPIP_00221]）。每个 Owner 获得一个专属的 TcpIp_<Up>GetSocket 函数，由此请求的 Socket 归其独占 [SWS_TCPIP_00222]。

向下，TcpIp 通过 TcpIp_RxIndication 接收帧 [SWS_TCPIP_00029]。它通过 EthIf_Transmit 发送，并且始终伴随 TxConfirmation = FALSE [SWS_TCPIP_00131]。EthSM 通过 TcpIp_RequestComMode 控制其状态 SWS EthSM 第27页。TcpIp 可选使用 CSM 服务 [SWS_TCPIP_00028]，并向 IdsM 报告安全事件 [SWS_TCPIP_00361]。SWS TcpIp 第17页 给出了嵌入架构的概览。

上下文图：TcpIp 位于 Socket-Owner（SoAd 或 CDD）与 EthIf 之间。它由 EthSM 控制，向 DET 报告错误并向 IdsM 报告事件，且可选使用 CSM。来源：[SWS_TCPIP_00220]，[SWS_TCPIP_00222]，[SWS_TCPIP_00029]，[SWS_TCPIP_00070]，[SWS_TCPIP_00028]，[SWS_TCPIP_00361]，[SWS_TCPIP_00255]，[SWS_TCPIP_00219]，SWS TcpIp 第17页

控制器状态：从 TCPIP_STATE_OFFLINE 到 TCPIP_STATE_ONLINE

该模块使用 TcpIp_Init 和与具体实现相关的 TcpIp_ConfigType 进行初始化（[SWS_TCPIP_00002]，[SWS_TCPIP_00067]）。TcpIp_MainFunction 是 Scheduler 的入口点 [SWS_TCPIP_00026]。解释：诸如超时等时间控制的过程很可能在此执行。 问题 Q-77b083e447651768 (未决)规范对此仅称“Schedules the TCP/IP stack”。

TcpIp 为每个 EthIf 控制器维护独立的状态：OFFLINE、STARTUP、ONLINE、ONHOLD 或 SHUTDOWN [SWS_TCPIP_00083]。若保存的请求与活动状态不同，TcpIp 会启动必要步骤 [SWS_TCPIP_00136]。

  • 来自 OFFLINE 的 ONLINE 请求会激活已配置的地址分配 [SWS_TCPIP_00075]。一旦分配了地址，控制器就切换到 ONLINE [SWS_TCPIP_00085]。
  • ONHOLD 针对所有地址报告 TCPIP_IPADDR_STATE_ONHOLD。Socket 和地址保持保留，但不接受新的发送请求（[SWS_TCPIP_00076]，[SWS_TCPIP_00074]）。返回 ONLINE 再次报告 TCPIP_IPADDR_STATE_ASSIGNED [SWS_TCPIP_00086]。
  • OFFLINE 请求或释放所有地址会报告 TCPIP_IPADDR_STATE_UNASSIGNED 并关闭 Socket（[SWS_TCPIP_00077]，[SWS_TCPIP_00072]）。资源释放后，转入 OFFLINE [SWS_TCPIP_00087]。

状态图：每个 EthIf 控制器拥有独立的状态机。仅可请求 ONLINE、ONHOLD 和 OFFLINE，STARTUP 和 SHUTDOWN 为过渡状态。来源：[SWS_TCPIP_00075]，[SWS_TCPIP_00085]，[SWS_TCPIP_00076]，[SWS_TCPIP_00086]，[SWS_TCPIP_00077]，[SWS_TCPIP_00087]，[SWS_TCPIP_00088]，SWS TcpIp 第60页（图表来自 R25-11，状态转换由 R20-11 Requirements 涵盖）

在 STARTUP 中，OFFLINE 请求会中止正在进行的分配 [SWS_TCPIP_00088]。若有人请求 STARTUP 或 SHUTDOWN，将以 E_NOT_OK 予以拒绝 [SWS_TCPIP_00089]。

典型的启动流程如下：EthSM 应 ComM 的请求发起 ONLINE SWS EthSM 第42页。随后 TcpIp 报告已分配的地址。之后 SoAd 请求 Socket 并进行绑定（[SWS_TCPIP_00229]，SWS SoAd 第20页）。来自 R25-11 的图表还展示了通过 EthSM_TcpIpModeIndication 得到的反馈 SWS TcpIp 第60页。对于 R20-11，该情况大概率同样适用。 问题 Q-a5e26ad792c23d58 (未决)

时序图：只有异步地址分配才会使控制器进入 ONLINE。之后 SoAd 才能请求并绑定 Socket。来源：[SWS_TCPIP_00070]，[SWS_TCPIP_00075]，[SWS_TCPIP_00085]，[SWS_TCPIP_00229]，[SWS_TCPIP_00018]，[SWS_TCPIP_00015]，SWS EthSM 第42页。向 EthSM 的反馈推测在 R20-11 中同样存在。

本地地址及其分配

其基础是一个来自 TcpIpLocalAddr 的本地地址表，这些地址在运行时分配给 EthIf 控制器（[SWS_TCPIP_00099]，SWS TcpIp 第220页）。条目通过 TcpIp_LocalAddrIdType 访问 [SWS_TCPIP_00030]。每个条目均可采用多种方式，例如静态、DHCP 或链路本地（[SWS_TCPIP_00065]，SWS TcpIp 第224页）。若具有更高优先级的地址变得可用，它将替换原有地址 [SWS_TCPIP_00127]。

分配与释放如何触发，取决于所配置的触发方式：

  • 在 TCPIP_MANUAL 下，TcpIp_RequestIpAddrAssignment 和 TcpIp_ReleaseIpAddrAssignment 控制可用性（[SWS_TCPIP_00195]，[SWS_TCPIP_00196]）。
  • 在 TCPIP_AUTOMATIC 下，两个调用均以 E_NOT_OK 予以拒绝（[SWS_TCPIP_00198]，[SWS_TCPIP_00199]）。
  • 在 TCPIP_STORE 下，TcpIp 从 NvM 块中采纳有效地址 [SWS_TCPIP_00219]。TcpIp_ResetIpAssignment 使这些保存的地址失效 [SWS_TCPIP_00216]。

每次分配变更均由 <Up_LocalIpAddrAssignmentChg> 报告，附带一个类型为 TcpIp_IpAddrStateType 的值（[SWS_TCPIP_00229]，[SWS_TCPIP_00082]）。TcpIp 通过免费 ARP 宣告新的 IPv4 地址 [SWS_TCPIP_00093]。它通过重复地址检测检查 IPv6 地址 [SWS_TCPIP_00159]。TcpIp_GetIpAddr、TcpIp_GetPhysAddr 和 TcpIp_GetCtrlIdx 用于查询（[SWS_TCPIP_00032]，[SWS_TCPIP_00033]，[SWS_TCPIP_00141]）。若查询未设置的 DHCP 选项，读取服务将返回长度 0 [SWS_TCPIP_00237]。

Socket：请求、绑定、连接、关闭

通过地址族和协议请求套接字（[SWS_TCPIP_00018]、[SWS_TCPIP_00009]、[SWS_TCPIP_00010]）。TcpIp_Bind 将其绑定到本地地址和端口 [SWS_TCPIP_00111]。如果端口、协议和地址已被占用，或者地址未分配，则此操作失败（[SWS_TCPIP_00146]、[SWS_TCPIP_00254]）。使用 TCPIP_PORT_ANY 时，协议栈会自行在 49152 到 65535 之间选择一个端口 SWS TcpIp 第85页。

对于 TCP，有两种建立连接的途径：

  • 作为客户端，TcpIp_TcpConnect 异步建立连接。连接建立后，TcpIp 调用 <Up_TcpConnected>（[SWS_TCPIP_00112]、[SWS_TCPIP_00227]）。
  • 作为服务器，TcpIp_TcpListen 将套接字置于 Listen 状态 [SWS_TCPIP_00113]。对于每个入站连接，TcpIp 都会派生出一个专有套接字，并通过 <Up_TcpAccepted> 进行通报 [SWS_TCPIP_00226]。若上限层返回 E_NOT_OK，TcpIp 将关闭连接 SWS SoAd 第81页。

TcpIp 仅在 ONLINE 状态下接受新的 TCP 连接 [SWS_TCPIP_00094]。

时序图：客户端通过 <Up_TcpConnected> 接收确认。服务器为每个连接获取一个派生套接字，上限层可以接受或拒绝该套接字。来源：[SWS_TCPIP_00022]、[SWS_TCPIP_00023]、[SWS_TCPIP_00226]、[SWS_TCPIP_00227]、SWS TcpIp 第129页（后面的示意图还包含 LSduR，在此处省略）、SWS TcpIp 第107页

TcpIp_Close 正常终止 TCP 连接。若 Abort = TRUE，则通过 RST 立即中止连接。对于 UDP，资源会立即释放（[SWS_TCPIP_00109]、[SWS_TCPIP_00110]）。重置、FIN 或关闭等事件由 <Up_TcpIpEvent> 通报 [SWS_TCPIP_00144]。通过 TcpIp_ChangeParameter 可以修改套接字参数，例如接收窗口、帧优先级、Nagle 算法、TCP 选项过滤器或 UDP 校验和（[SWS_TCPIP_00126]、[SWS_TCPIP_00266]、[SWS_TCPIP_00279]）。

数据路径：发送、接收、地址解析

TcpIp_TcpTransmit 异步工作。若设置了 DataPtr，它将从该线性缓冲区中接收数据。若 DataPtr 为 NULL_PTR，则通过 <Up_CopyTxData> 获取数据。若 ForceRetrieve = TRUE，则恰好为 AvailableLength 字节；若为 FALSE，则可能更少（[SWS_TCPIP_00124]、[SWS_TCPIP_00125]、[SWS_TCPIP_00228]）。对于 TCP，TcpIp 仅在对端确认后才会调用 <Up_TxConfirmation>（[SWS_TCPIP_00225]、SWS SoAd 第86页）。相比之下，TcpIp_UdpTransmit 则同步且立即发送（[SWS_TCPIP_00025]、[SWS_TCPIP_00120]）。

时序图：数据直接传递或通过复制回调获取。向 EthIf 的发送在 MainFunction 上下文中运行，确认仅在对端返回 ACK 后到来。来源：[SWS_TCPIP_00050]、[SWS_TCPIP_00123]、[SWS_TCPIP_00124]、[SWS_TCPIP_00131]、SWS TcpIp 第109页

接收时，IP 层将每个数据报分配给本地地址表中的一个条目 [SWS_TCPIP_00169]。UDP 和 TCP 随后通过目标端口和本地地址选择套接字（[SWS_TCPIP_00170]、[SWS_TCPIP_00172]）。对于现有的 TCP 连接，源地址和源端口还必须匹配 [SWS_TCPIP_00173]。UDP 广播发送到所有匹配的套接字，发往广播地址的 TCP 段将被丢弃（[SWS_TCPIP_00171]、[SWS_TCPIP_00174]）。TcpIp 会重新组装分片的数据报，并允许为此对接收进行解耦（[SWS_TCPIP_00054]、SWS TcpIp 第131页）。数据通过 <Up_RxIndication> 到达上限层。上限层处理完 TCP 数据后，TcpIp_TcpReceived 会重新打开接收窗口（[SWS_TCPIP_00223]、[SWS_TCPIP_00115]）。

时序图：接收到的帧通过本地地址和端口分配给套接字。对于 TCP，上限层的确认会释放接收窗口。来源：[SWS_TCPIP_00029]、[SWS_TCPIP_00169]、[SWS_TCPIP_00170]、[SWS_TCPIP_00223]、[SWS_TCPIP_00115]、SWS TcpIp 第108页

为了发送，TcpIp 需要目标的 MAC 地址，并将其保存在 ARP 表中：

  • 该表限制为 TcpIpArpTableSizeMax 个条目 [SWS_TCPIP_00090]。未使用的条目在 TcpIpArpTableEntryTimeout 后失效 [SWS_TCPIP_00091]。
  • TcpIp 会在 TcpIpArpRequestTimeout 期间抑制针对同一目标的重复请求 [SWS_TCPIP_00350]。
  • 在 R20-11 中，每个接收到的 IP 数据包都会更新该表 [SWS_TCPIP_00092]。后续版本将此绑定到 TcpIpArpDefensiveProcessing = FALSE SWS TcpIp 第29页。
  • 若缺少条目，TcpIpArpPacketQueueEnabled 决定是对数据包排队还是拒绝（[SWS_TCPIP_00191]、[SWS_TCPIP_00192]）。对于 NDP，适用相应规则 [SWS_TCPIP_00193]。

ARP 表的每次更改，TcpIp 都会通过 <Up_PhysAddrTableChg> 通报 [SWS_TCPIP_00142]。若 Neighbor Cache 已满，则会逐出最旧的条目 [SWS_TCPIP_00264]。TcpIp_GetRemotePhysAddr 和缓存读取服务允许进行查询（[SWS_TCPIP_00138]、[SWS_TCPIP_91002]、[SWS_TCPIP_91001]）。

活动图：若发送时缺少 ARP 条目，则根据配置对数据包进行排队或拒绝。针对同一目标的新请求将受到限制。来源：[SWS_TCPIP_00191]、[SWS_TCPIP_00192]、[SWS_TCPIP_00350]、[SWS_TCPIP_00142]、SWS TcpIp 第176页。Interpretation：排队的数据包在解析成功后发送。

安全防护与过滤：TLS、IPsec、IdsM

对于 TCP 连接，TcpIp 支持符合 IETF RFC 5246 的 TLS。低于 1.2 的版本将被拒绝（[SWS_TCPIP_00300]、[SWS_TCPIP_00302]）。PSK 身份和当前时间由可配置的 Callout 提供（[SWS_TCPIP_91014]、[SWS_TCPIP_91012]）。加密通过 CSM 进行（[SWS_TCPIP_00028]、SWS TcpIp 第251页）。

IPsec 支持 IKEv2，不支持 IKEv1（[SWS_TCPIP_00352]、[SWS_TCPIP_00353]）。每个数据报都被分配一个策略，并根据该策略进行保护、放行或丢弃（[SWS_TCPIP_00359]、[SWS_TCPIP_00360]）。不允许的 IPv6 扩展头会导致静默丢弃 [SWS_TCPIP_00260]。若设置了 TcpIpEnableSecurityEventReporting，TcpIp 会向 IdsM 报告安全事件 [SWS_TCPIP_00361]。

发生错误时的行为

开发错误（包括 TCPIP_E_UNINIT、TCPIP_E_PARAM_POINTER、TCPIP_E_INV_ARG 和 TCPIP_E_ADDRINUSE）在 [SWS_TCPIP_00042] 中定义。检查内容包括：

  • 请求套接字时无效的地址族 [SWS_TCPIP_00128]，
  • TcpIp_Bind 处无效的 LocalAddrId [SWS_TCPIP_00147]，
  • TcpIp_GetIpAddr 处冲突的地址族 [SWS_TCPIP_00206]，
  • DHCP 选项服务无效的参数 [SWS_TCPIP_00243]，
  • 在 TcpIp_TcpConnect 中使用 NULL_PTR 作为目标地址 SWS TcpIp 第86页。

独立于错误检测，TcpIp 会将某些拒绝作为 E_NOT_OK 返回，例如已被占用的端口或不匹配的地址族（[SWS_TCPIP_00146]、[SWS_TCPIP_00205]）。

运行时错误由 TcpIp 通过 Det_ReportRuntimeError 报告：

  • 当 SYN 未收到应答、保活监控超时或重试次数耗尽时的 TCPIP_E_TIMEDOUT [SWS_TCPIP_00256]，
  • 收到相应 ICMP 报文后的 TCPIP_E_CONNREFUSED、TCPIP_E_HOSTUNREACH 和 TCPIP_E_PACKETTOBIG（[SWS_TCPIP_00257]、[SWS_TCPIP_00258]、[SWS_TCPIP_00259]），
  • 地址重复分配时的 TCPIP_E_DADCONFLICT [SWS_TCPIP_00282]。

R20-11 仅定义了代码 0x01 至 0x05 [SWS_TCPIP_00255]。后续版本中新增的代码 TCPIP_E_TX_QUEUE_OVERRUN 和 TCPIP_E_TX_INTERNAL_PROCESSING_FAILED 在此处不适用 SWS TcpIp 第65页。

许多错误情况保持静默，因为不合规的数据包会被直接丢弃。TcpIp_GetAndResetMeasurementData 统计此类丢弃的数据包并重置计数器（[SWS_TCPIP_91006]、[SWS_TCPIP_00296]）。若无法解析 MAC 地址，TcpIp 会通报 TCPIP_E_PHYS_ADDR_MISS [SWS_TCPIP_00066]。对于自身子网之外的目标，TcpIp_GetRemotePhysAddr 立即返回 TCPIP_E_NOT_OK [SWS_TCPIP_00139]。
