FrSM 的角色：ComM、BswM 与 FlexRay Interface 之间的模式转换器

FlexRay State Manager (FrSM) 是用于 FlexRay 的总线状态管理器。它针对每个 FlexRay Cluster 通过 FrSM_RequestComMode 接收通信模式（[SWS_FrSM_00020]）。它将该模式转换为用于通信控制器和收发器的控制时序，并为此触发 FlexRay Interface 的函数（FrIf_*、[SWS_FrSM_00096]）。状态机示意图将此目的描述为将 COMM_NO_COMMUNICATION 和 COMM_FULL_COMMUNICATION 转换为底层硬件流程（SWS FrSM Fig. 7.1 第24页）。

FrSM 向两个方向提供反馈。它使用 ComM_BusSM_ModeIndication 向 ComM 报告达到的总线模式，使用 BswM_FrSM_CurrentState 向 BswM 报告其内部状态（[SWS_FrSM_00096]）。向 BswM 报告的值具有类型 FrSM_BswM_StateType（[SWS_FrSM_00199]）。BswM 同时充当请求方：例如在诊断用例中，它可以通过 FrSm_SetEcuPassive() 将 FrSM 置为被动状态（EXP ModeMgmt 第36页）。在 Key-Slot-Only 模式下，它释放全部运行（SWS FrSM Fig. 9.10 第55页）。

EcuM 使用 FrSm_Init 初始化该模块，并在此过程中传递指向 Post-Build 结构 FrSM_ConfigType 的指针（[SWS_FrSM_00013]、[SWS_FrSM_00198]）。Figure 9.1 显示了作为该阶段参与者的 EcuM、FrIf 和 FrSM（SWS FrSM Fig. 9.1 第46页）。随后，BSW 调度器针对每个 Cluster 调用其专属的 FrSM_MainFunction_<FrSMCluster.ShortName>（服务 ID 0x80，通过 SchM_FrSm.h、[SWS_FrSM_00118] 提供）。FrSM 可选择性集成 DEM、DET、FrNm_StartupError 以及其他 FrIf 服务（[SWS_FrSM_00097]）。此外还包括一个在同步丢失时可配置的 CDD 回调（[SWS_FrSM_00190]）。

上下文图：FrSM 从 EcuM、SchM、ComM 和 BswM 接收请求，仅通过 FrIf 控制硬件，并向 ComM、BswM、DEM、DET、FrNm 以及可选的 CDD 进行报告。来源：[SWS_FrSM_00096]、[SWS_FrSM_00097]、[SWS_FrSM_00118]、[SWS_FrSM_00190]、SWS FrSM Fig. 9.1 第46页、EXP ModeMgmt 第36页

两个并发区域：每个 Cluster 的控制器状态与 ECU 被动模式

该状态机由两个并发区域组成（SWS FrSM 第18页、SWS FrSM Fig. 7.1 第24页）：

  • 区域 [CcCtrl] 包含每个 Cluster 的八个状态。
  • 区域 [TrcvCtrl] 通过 FRSM_ECU_ACTIVE 和 FRSM_ECU_PASSIVE 控制接收运行。

表 7.1 将每个 Cluster 状态映射到 FlexRay 控制器的一个 POC 状态（SWS FrSM 第18页）：

FrSM 状态POC 状态含义
FRSM_READYready初始化后的空闲状态
FRSM_WAKEUPwake-upFrSM 执行唤醒
FRSM_STARTUPstart-upFrSM 执行启动
FRSM_HALT_REQnormal active/passiveFrSM 正在关闭
FRSM_ONLINEnormal active完全通信
FRSM_ONLINE_PASSIVEnormal passive因时钟同步错误而无数据
FRSM_KEYSLOT_ONLYnormal active，时隙模式 ≠ AllSlots仅在 Key-Slot 中发送
FRSM_LOW_NUMBER_OF_COLDSTARTERSnormal active完全通信，仅通过同步帧进行同步

状态 FRSM_ONLINE、FRSM_KEYSLOT_ONLY、FRSM_LOW_NUMBER_OF_COLDSTARTERS 和 FRSM_ONLINE_PASSIVE 构成 FullCom 组（SWS FrSM 第36页）。当源状态中满足其条件且事件发生时，转移即发生。FrSM 按照转移表的顺序执行相应的动作（SWS FrSM 第24页）。诸如 reqComMode 或 wakeupCounter 之类的变量仅是提高规范可读性的辅助工具（SWS FrSM 第18页）。

FrSm_SetEcuPassive 同时切换所有 Cluster 的 [TrcvCtrl] 区域（[SWS_FrSM_00174]）。通过 TRUE 它转换至 FRSM_ECU_PASSIVE，通过 FALSE 转换至 FRSM_ECU_ACTIVE。如果在此过程中某个 Cluster 未处于 FRSM_READY（即其收发器不处于待机状态），则针对该 Cluster 执行 FE_TRCV_NORMAL（SWS FrSM 第40页）。

状态图：区域 [CcCtrl] 引导每个 Cluster 从 FRSM_READY 经由唤醒和启动进入 FullCom，并经由 FRSM_HALT_REQ 返回。区域 [TrcvCtrl] 独立于此切换被动模式。FullCom 内部的转移由转移表管理；此处未予显示。来源：SWS FrSM 第27页、SWS FrSM 第35页、[SWS_FrSM_00174]、[SWS_FrSM_00209]

从 FullCom 请求到在线运行：启动与唤醒

FrSM_RequestComMode 异步工作（[SWS_FrSM_00020]）。该函数将期望的模式保存为 reqComMode；该模式将在受影响 Cluster 的 MainFunction 下一次运行时被处理（SWS FrSM 第36页）。对于 R20-11，根据 [SWS_FrSM_00020] 适用以下内容：

  • 参数 NetworkHandle 和 ComM_Mode，
  • 服务 ID 0x02，
  • 针对不同 Cluster 可重入。

而较新版本中的文档处则指明了服务 ID 0x40 以及参数 network/mode。对于 R20-11，应以需求为准（SWS FrSM 第36页）。

如果不发送唤醒模式，Cluster 将从 FRSM_READY 直接进入启动（SWS FrSM 第52页、SWS FrSM Fig. 9.3 第48页）：

  1. 收发器被设置为 FRTRCV_TRCVMODE_NORMAL。
  2. 控制器通过 FrIf_StartCommunication 启动。
  3. 对于冷启动 ECU（FrSMIsColdstartEcu），FrIf_AllowColdstart 释放冷启动。

定时器 t1 将该释放延迟 FrSMDurationT1。若为 0，则紧随 FrIf_StartCommunication 之后进行（SWS FrSM 第21页）。

此后，MainFunction 周期性查询 FrIf_GetPOCStatus（SWS FrSM Fig. 9.5 第50页、[SWS_FrSM_00096]）。若其返回 FR_POCSTATE_NORMAL_ACTIVE，则：

  • FrSM 将 DEM 事件 FRSM_E_CLUSTER_STARTUP 报告为 PASSED，
  • 它使用 FRIF_GOTO_ONLINE 将 FrIf 置为在线状态，
  • 它通知 BswM 和 ComM。

时序图：请求被保存并由 MainFunction 转换为启动动作。仅当 POC 状态报告 normal active 时，才会切换为在线。此处使用 FrSM_BswM_StateType 的 R20-11 值代替图中标注。来源：SWS FrSM Fig. 9.3 第48页、SWS FrSM 第52页、SWS FrSM Fig. 9.7 第52页、[SWS_FrSM_00020]、[SWS_FrSM_00199]

如果 ECU 必须先唤醒 Cluster，它将遍历 FRSM_WAKEUP（[SWS_FrSM_00097]）。它使用 FrIf_SetWakeupChannel 选择唤醒通道，其中不得使用 FR_CHANNEL_AB。随后它使用 FrIf_SendWUP 发送唤醒模式。在通道 A 上被总线唤醒的双通道 ECU 会有针对性地将唤醒请求转发至通道 B（SWS FrSM 第56页、SWS FrSM Fig. 9.8 第53页）。

模式重复的次数由 FrSMNumWakeupPatterns 确定（SWS FrSM 第27页）。一旦检测到总线通信，重复即告结束。如果控制器因错误进入 HALT，发送将被中止。该文档处来自 R23-11/R24-11；有效负载中不包含对此单独的 R20-11 需求。

活动图：唤醒模式发送在计数器控制下重复进行。当检测到总线通信、达到次数上限或控制器因错误进入 HALT 时结束。来源：SWS FrSM 第27页、SWS FrSM 第18页

基于 BswM 请求的 Key-Slot-Only 启动与接收运行

如果控制器上设置了 pKeySlotOnlyEnabled，则节点在启动后最初仅在 Key-Slot 中发送（SWS FrSM Fig. 9.10 第55页、[SWS_FrSM_00199]）。此时 Cluster 处于 FRSM_KEYSLOT_ONLY，FrSM 将其作为 FRSM_BSWM_KEYSLOT_ONLY 报告给 BswM。根据 Figure 9.10，BswM 随后使用 FrSm_AllSlots 释放全部运行（[SWS_FrSM_00172]）。对于该异步函数，适用以下内容（SWS FrSM 第41页）：

  • 它针对 Cluster 的每个控制器调用 FrIf_AllSlots。
  • 仅当所有这些调用均返回 E_OK 时，它才返回 E_OK。
  • 它可以在编译时通过 FrSMAllSlotsSupport 禁用。

如果 POC 状态随后报告 FR_SLOTMODE_ALL，则 Cluster 转换至 FRSM_ONLINE（SWS FrSM 第57页）。

时序图：仅当 BswM 调用 FrSm_AllSlots 时，才会从 Key-Slot 运行进入全部运行。一旦 POC 状态显示时隙模式为 ALL，FrSM 即报告该转换。Figure 9.10 将 BswM 状态标注为 FRSM_ONLINE_KEYSLOT_ONLY，而 R20-11 类型将其列为 FRSM_BSWM_KEYSLOT_ONLY。来源：[SWS_FrSM_00172]、[SWS_FrSM_00199]、SWS FrSM 第57页、SWS FrSM Fig. 9.10 第55页

FrSm_SetEcuPassive 是同步且不可重入的；单次调用作用于 ECU 的所有 FlexRay Cluster（[SWS_FrSM_00174]）。类型 FrSM_BswM_StateType 为每个状态值包含一个带有后缀 _ECU_PASSIVE 的变体，例如 FRSM_BSWM_ONLINE_ECU_PASSIVE (0x0B)（[SWS_FrSM_00199]）。解读：FrSM 大概以此在单个值中向 BswM 报告 [CcCtrl] 的状态和 [TrcvCtrl] 的被动状态，从而使 BswM 规则可以共同评估二者（SWS FrSM 第35页）。

返回 NoCom 与当前通信模式查询

如果在 Cluster 处于 FullCom 状态期间请求 NoCom，根据较新版本的规范，FrSM_RequestComMode 会在调用中立即处理该转换（SWS FrSM 第36页）。Figure 9.11 对此展示了一个两阶段流程（SWS FrSM 第58页、SWS FrSM Fig. 9.11 第56页）：

  1. 在调用本身中：执行带有 FRIF_GOTO_OFFLINE 的 FrIf_SetState、FrIf_HaltCommunication、向 BswM 报告 HALT_REQ 以及向 ComM 报告 COMM_NO_COMMUNICATION。
  2. 在接下来的 MainFunction 运行中：使用 FrIf_ControllerInit 重新初始化控制器、将收发器置为 STANDBY、报告 READY。

如果未配置 FrSMTrcvStdbyDelay 或将其设置为 0，则定时器 t_TrcvStdbyDelay 不会启动；从 FRSM_HALT_REQ 到 FRSM_READY 的转换随后立即发生（[SWS_FrSM_00209]）。在多个总线的协调关闭中，FrSM 作为 Nm 协调的参与者出现（SWS Nm Fig. 9.1 第83页）。

时序图：NoCom 请求停止通信并立即报告 NoCom。控制器重新初始化与收发器待机周期性地紧随其后，适当时在 t_TrcvStdbyDelay 之后发生。来源：SWS FrSM 第58页、SWS FrSM Fig. 9.11 第56页、[SWS_FrSM_00209]、[SWS_FrSM_00096]

FrSM_GetCurrentComMode 在 R20-11 中是同步的，服务 ID 为 0x03，且针对不同 Cluster 可重入（[SWS_FrSM_00024]）。该函数将当前模式写入传递的地址。它仅在 FRSM_ONLINE 和 FRSM_LOW_NUMBER_OF_COLDSTARTERS 下返回 COMM_FULL_COMMUNICATION，在所有其他状态下均返回 COMM_NO_COMMUNICATION（SWS FrSM 第38页）。因此这也适用于 FRSM_KEYSLOT_ONLY 和 FRSM_ONLINE_PASSIVE，尽管两者均属于 FullCom 组。FlexRay 上不支持 SilentCom（SWS FrSM 第18页）。

每个 FlexRay Cluster 的配置：角色、定时器和开关

每个 Cluster 由一个容器 FrSMCluster（多重性 1..*）描述，该容器可包含每台 ECU 的多个控制器（SWS FrSM 第62页）。它除其他内容外还包含：

  • 引用 FrSMComMNetworkHandleRef 和 FrSMFrIfClusterRef，
  • 角色 FrSMIsColdstartEcu 和 FrSMIsWakeupEcu，
  • 重试参数 FrSMStartupRepetitions、FrSMStartupRepetitionsWithWakeup 和 FrSMNumWakeupPatterns，
  • 周期时间 FrSMMainFunctionCycleTime。

容器描述来自 R23-11 及更高版本。在 R20-11 需求中，其中的 FrSMTrcvStdbyDelay 已得到证实（[SWS_FrSM_00209]）。每个 Cluster 的定时器如下（SWS FrSM 第21页）：

  • t1 (FrSMDurationT1)：延迟对 FrIf_AllowColdstart 的调用。
  • t2 (FrSMDurationT2)：重复启动的时间间隔。
  • t3 (FrSMDurationT3)：监视向 FullCom 的转换。
  • t4：确保双通道节点清除其冷启动抑制并成为 Leading Coldstarter。
  • t_TrcvStdbyDelay：延迟控制器重新初始化和收发器待机（[SWS_FrSM_00209]）。

模块范围内生效的开关如下：

  • FrSMDevErrorDetect 激活开发错误检测（SWS FrSM 第35页）。
  • FRSM_VERSION_INFO_API 在编译时启用或禁用版本信息 API（[SWS_FrSM_00029]）；在系统模板中该参数称为 FrSMVersionInfoApi。
  • FrSMSyncLossErrorIndicationName 指定 CDD 回调；如果缺少该参数，则不进行指示（SystemTemplate 第1528页、[SWS_FrSM_00190]）。

[SWS_FrSM_00095] 列出了导入的类型，其中包括 ComM_ModeType、NetworkHandleType 以及来自 Fr_GeneralTypes.h 的类型。

发生错误时的行为

FrSM 通过 Det_ReportError（[SWS_FrSM_00097]）使用来自 [SWS_FrSM_91001] 的代码报告开发错误：

  • FRSM_E_PARAM_POINTER (0x01)：服务在不执行进一步操作的情况下返回。
  • FRSM_E_INV_HANDLE (0x02)：无效的网络句柄。
  • FRSM_E_UNINIT (0x03)：模块未初始化。
  • FRSM_E_INV_MODE (0x04)：请求了无效的通信模式。
  • FRSM_INIT_FAILED (0x05)：初始化失败。

为了使其他函数能够检查初始化状态，在错误检测处于激活状态时，FrSm_Init 会记录初始化成功（SWS FrSM 第35页）。在 R20-11 中，FrSM_GetCurrentComMode 在初始化之前使用 E_NOT_OK 拒绝请求（[SWS_FrSM_00024]）。传递给 FrSm_AllSlots 的无效 NetworkHandle 会导致 FRSM_E_INV_HANDLE 和 E_NOT_OK（SWS FrSM 第41页）。SilentCom 请求大概属于 FRSM_E_INV_MODE，因为 FlexRay 上不支持此模式（SWS FrSM 第18页）。

若启动失败，定时器将介入：t2 重复启动，t3 监测 FullCom 的达成情况（SWS FrSM 第21页）。若群集无法同步，FrSM 将调用 FrNm_StartupError（[SWS_FrSM_00097]）。它将群集的启动作为 DEM 事件 FRSM_E_CLUSTER_STARTUP 进行上报（SWS FrSM Fig. 9.7 第52页）。关联事件在容器 FrSMClusterDemEventParameterRefs 中被引用（SWS FrSM 第62页）。

在运行过程中，状态机区分两种故障情况（SWS FrSM 第18页）：

  • 时钟同步错误将导致进入 FRSM_ONLINE_PASSIVE；不传输任何数据。
  • 在冷启动节点过少时，适用 FRSM_LOW_NUMBER_OF_COLDSTARTERS：仅通过同步帧进行同步，通信保持完整。

若 ECU 失去同步，则调用带有 true 的 <Cdd>_SyncLossErrorIndication（[SWS_FrSM_00190]）。一旦 ECU 能够重新同步或 FullCom 请求已被释放，便会随之调用 false。在唤醒过程中，控制器因故障导致的 HALT 会中止图案发送（SWS FrSM 第27页）。

用法与调用上下文

函数 FrSM_RequestComMode（[SWS_FrSM_00020]）供 Communication Manager（ComM）用于启动或关闭（启动或关断）特定 FlexRay 集群上的通信。它通过头文件 FrSm.h 提供，并具有服务 ID 0x02。

该函数的执行是异步的。它接收以下参数：

  • NetworkHandle（输入参数）：标识请求通信模式的具体 FlexRay 集群。
  • ComM_Mode（输入参数）：传递请求的通信模式。

返回值与错误处理

该函数返回类型为 Std_ReturnType 的状态值：

  • E_OK：模式请求已被接受（Request accepted）。由于该调用为异步执行，因此该返回值确认 FlexRay State Manager 已接受该任务。
  • E_NOT_OK：模式请求已被拒绝（Request not accepted）。

并发性

关于并发性，[SWS_FrSM_00020] 指定 FrSM_RequestComMode 对于不同的 FlexRay 集群是可重入的（Reentrant for different Flex Ray clusters）。
