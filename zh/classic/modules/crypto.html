Crypto Driver 在加密栈中的角色

Crypto Driver 位于微控制器抽象层（Microcontroller Abstraction Layer），处于 Crypto Interface（CryIf）和 Crypto Service Manager（CSM）之下。它为同步和异步加密原语提供通用接口，并负责密钥存储、密钥配置和密钥管理。一个 ECU 恰好集成一个 CSM 和一个 CryIf。然而 CryIf 可以寻址多个 Crypto Driver SWS_CryptoDriver 第15页。规范将提供的功能总结为两类服务：加密服务和密钥管理 SWS_CryptoDriver 第24页。

核心执行单元是 Crypto Driver Object。它代表一个独立的加密单元，例如 HSM 上的 AES 加速器或 RSA 的软件实现。每个 Crypto Driver Object 都是一个加密通道的端点 SWS_CryptoDriver 第15页。一个对象一次只处理一个任务。拥有 n 个对象的驱动程序可以并行处理 n 个任务，其中队列中的任务不算作“处理中”（R25-11 版本的文档出处）SWS_CryptoDriver 第23页。因此，Crypto_ProcessJob 和 Crypto_CancelJob 通过 objectId 来寻址该对象 [SWS_Crypto_91003] [SWS_Crypto_00122]。

启动、实例化与分区

Crypto_Init 是同步且不可重入的，用于初始化驱动程序 [SWS_Crypto_91000]。此时参数 configPtr 必须始终为空指针 [SWS_Crypto_00215]。解释：因此配置不是在运行时选择的，而是可能静态绑定在驱动程序中。这与 Crypto_ConfigType 的内容取决于具体实现相吻合 [SWS_Crypto_91016]。在启动时，驱动程序会读回持久化密钥值 SWS_CryptoDriver 第35页。如果某个值无法加载，它会将受影响的密钥设置为无效 [SWS_Crypto_00198]。如果出现空指针，Crypto_GetVersionInfo 会向 DET 报告 CRYPTO_E_PARAM_POINTER [SWS_Crypto_91001] SWS_CryptoDriver 第56页。

如果一个 ECU 中存在多个驱动程序实例，则文件名、API 名称和发布的参数必须按照模式 Crypto_<vi>_<ai> 进行区分 SWS_CryptoDriver 第23页。NvM 回调也带有此前缀，例如 Crypto_<vi>_<ai>_NvBlock_Init_<NvBlock> [SWS_Crypto_91023]。如果驱动程序内部需要随机数（例如用于 Crypto_KeyExchangeCalcPubVal），则必须为此配置 Crypto Driver Object 0 [SWS_Crypto_00224]。没有独立默认随机数生成器的对象将从对象 0 获取其随机数 [SWS_Crypto_00225]。在此过程中，它们仅调用所属驱动程序的生成器 [SWS_Crypto_00226]。

在分区情况下，驱动程序在每个分区中作为独立实例运行。API 调用仅对发生调用的分区生效 [SWS_Crypto_CONSTR_00001]。Crypto Driver Object 的分区必须是驱动程序分区的子集 [SWS_Crypto_CONSTR_00002]。专用于 HSM 的对象最多只能分配给一个分区 [SWS_Crypto_CONSTR_00003]。BSW 分布指南（BSW-Distribution-Guide）将这种划分归因于每个加密实例的负载均衡 BSWDistributionGuide 第59页。

通过 Crypto_ProcessJob 进行任务处理

所有加密服务均通过可重入函数 Crypto_ProcessJob(objectId, job) 运行。任务是同步运行还是异步运行取决于其配置 [SWS_Crypto_91003]。该信息包含在 Crypto_JobType 中 SWS_CryptoDriver 第26页。驱动程序从 CSM 的 Crypto_GeneralTypes.h 导入任务类型 [SWS_Crypto_00042]。

在异步情况下，接口函数仅将必要的信息传递给原语。计算可由 Main Function 触发。完成后，驱动程序通过 CRYIF_CallbackNotification 通知 CryIf，并传递任务与结果 SWS_CryptoDriver 第27页。当配置了异步处理且存在任务队列时，会周期性调用 Crypto_MainFunction [SWS_Crypto_91012]。

时序图：异步任务立即返回，在 Main Function 中进行计算并通过回调完成。从 CryIf 到 CSM 的转发被标记为解释。来源：[SWS_Crypto_91003]、[SWS_Crypto_91012]、SWS_CryptoDriver 第27页

任务包含一个带有运行模式 START、UPDATE 和 FINISH 的标志字段。这些标志可以组合，并且始终按此顺序执行。START 会取消同一任务的所有先前请求 SWS_CryptoDriver 第25页。单次调用对应于组合 START|UPDATE|FINISH SWS_CryptoInterface 第22页。对于密钥管理任务，规范建议使用 CRYPTO_OPERATIONMODE_SINGLECALL SWS_CryptoDriver 第66页。

密钥、密钥元素与访问权限

一个密钥由一个或多个密钥元素组成。例如密钥材料、初始化向量或种子状态。每个元素都带有作为枚举值的读写权限，其数值构成等级顺序 SWS_CryptoDriver 第28页。直接进行读写访问时必须遵守这些权限 [SWS_Crypto_00219]。解释：仅在 CRYPTO_RA_ALLOWED/CRYPTO_RA_ENCRYPTED [SWS_Crypto_00222] 或 CRYPTO_WA_ALLOWED/CRYPTO_WA_ENCRYPTED [SWS_Crypto_00223] 时执行“该操作”的规定，可能指的是 Crypto_KeyElementGet [SWS_Crypto_91006] 和 Crypto_KeyElementSet [SWS_Crypto_91004]。相比之下，任务使用其分配的元素时无需进行权限检查。重定向（Redirection）除外 [SWS_Crypto_00221]。

Crypto_KeyElementIdsGet 列出密钥现有的元素 ID。调用时 keyElementIdsLengthPtr 包含缓冲区大小，完成后包含实际数量 [SWS_Crypto_00160] SWS_CryptoDriver 第78页。复制功能有两个函数：

  • Crypto_KeyCopy 在同一驱动程序内复制包含所有元素的密钥 [SWS_Crypto_00155]。
  • Crypto_KeyElementCopy 复制单个元素 [SWS_Crypto_00148]。

源元素必须至少具有与目标相同的权限。源密钥至少需要 CRYPTO_RA_INTERNAL_COPY [SWS_Crypto_00220]。如果元素直接映射到 Flash，则同步调用可能会显著耗时更长 SWS_CryptoDriver 第77页。

Crypto_KeyElementCopyPartial 复制带有源偏移量和目标偏移量的片段 [SWS_Crypto_91015]。如果源元素短于偏移量加上长度 [SWS_Crypto_00207]，或者目标的最大缓冲区不足 [SWS_Crypto_00208]，该函数将返回 CRYPTO_E_KEY_SIZE_MISMATCH。否则，它会复制 [SWS_Crypto_00209] 并在需要时调整目标长度 [SWS_Crypto_00210] [SWS_Crypto_00211]。

取消正在运行的任务

Crypto_CancelJob(objectId, job) 是同步且可重入的，但对于同一个 Crypto Driver Object 不可重入 [SWS_Crypto_00122]。返回值取决于处理状态：

  • 如果驱动程序当前未处理该任务，则返回 E_OK 且不进行进一步处理 [SWS_Crypto_00214]。
  • 如果它可以取消正在运行的任务，则将其移除并返回 E_OK [SWS_Crypto_00122]。
  • 如果无法取消（例如由于硬件限制），则返回 CRYPTO_E_JOB_CANCELED [SWS_Crypto_00183]。

此处的“处理中”是指该对象正在积极处理该任务。仅剩下 FINISH 待执行的任务不算作处于处理中 SWS_CryptoDriver 第25页。对于 CRYPTO_E_JOB_CANCELED，CSM 会在下一个合适步骤做出中止反应，并通过负 Closing 回调报告该情况 SWS_CryptoServiceManager 第80页。

发生错误时的行为

如果开发错误检测处于激活状态，驱动程序会向 DET 报告以下代码：CRYPTO_E_UNINIT (0x00)、CRYPTO_E_INIT_FAILED (0x01)、CRYPTO_E_PARAM_POINTER (0x02)、CRYPTO_E_PARAM_HANDLE (0x04)、CRYPTO_E_PARAM_VALUE (0x05) 以及一个用于缓冲区过小的代码 [SWS_Crypto_00040]。这些代码不会通过 API 返回 SWS_CryptoDriver 第15页。例如 Crypto_KeySetValid：在未初始化时，它会报告 CRYPTO_E_UNINIT 并返回 E_NOT_OK [SWS_Crypto_00196]。在 cryptoKeyId 无效时，它会报告 CRYPTO_E_PARAM_HANDLE [SWS_Crypto_00197]。相同的模式例如适用于 Crypto_KeyElementCopyPartial [SWS_Crypto_00205] 以及 Crypto_KeyDerive 时的 targetCryptoKeyId [SWS_Crypto_00180]。

在每个作业之前，驱动程序会检查 job->cryptoKeyId 以及在必要时检查 targetCryptoKeyId [SWS_Crypto_00217]。对于 CRYPTO_KEYDERIVE，目标必须始终位于有效范围内 [SWS_Crypto_00202]。如果缓冲区过小，驱动程序则不执行该操作。在 DET 处于活动状态时，它会报告 CRYPTO_E_SMALL_BUFFER；若没有 DET，它将返回 E_NOT_OK [SWS_Crypto_00195]。对于 CRYPTO_HASH 和 CRYPTO_MACGENERATE，则会输出截断至最高有效位的结果作为替代 [SWS_Crypto_00065]。较新的文档位置还额外提及了 CRYPTO_RANDOMGENERATE。这一点在此处给出的 R20-11 需求中并未得到证实 SWS_CryptoDriver 第49页。

驱动程序通过 CRYPTO_E_BUSY、CRYPTO_E_KEY_READ_FAIL、CRYPTO_E_KEY_WRITE_FAIL、CRYPTO_E_KEY_NOT_AVAILABLE 和 CRYPTO_E_KEY_NOT_VALID 等返回值报告运行时结果 [SWS_Crypto_91018]。当熵耗尽时，随机数服务会返回 CRYPTO_E_ENTROPY_EXHAUSTED。随后 Crypto_ProcessJob 还会额外报告运行时错误 CRYPTO_E_RE_ENTROPY_EXHAUSTED [SWS_Crypto_00141]。对于 NvM 错误，则提供 CRYPTO_E_RE_NVM_ACCESS_FAILED [SWS_Crypto_00194]。不过，损坏的 NvM 块必须由应用程序来处理 SWS_CryptoDriver 第35页。
