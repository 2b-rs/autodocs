为面向硬件的 AUTOSAR Classic 加密栈提供加密原语和密钥管理。

Crypto Driver 作为 MCAL 模块，为 AUTOSAR Classic 加密栈提供面向硬件的加密计算以及密钥管理（EXP_UtilizationOfCryptoServices 第8页）。它将硬件安全模块（HSM）或软件库封装在 Driver Objects 中，并通过中央接口 Crypto_ProcessJob 处理同步和异步作业（[SWS_Crypto_91003]）。密钥访问受可配置权限的约束，并且只有在成功进行密钥验证时才会触发在 NVM 中的持久化存储（SWS_CryptoDriver 第37页）。

Crypto Driver（模块 Crypto）作为 MCAL 驱动程序构成了 AUTOSAR Classic 加密栈的最底层基础，并将硬件安全模块（HSM）、加密加速器以及软件例程直接连接到加密接口（CryIf）（EXP_UtilizationOfCryptoServices 第8页、SWS_CryptoDriver 第15页）。在多重实现的情况下，实例根据模式 Crypto_<vi>_<ai> 进行特定于供应商的命名（[SWS_Crypto_00012]）。初始化通过 [SWS_Crypto_91000] 同步进行，且 [SWS_Crypto_91016] 必须传入空指针（[SWS_Crypto_00215]）。在内部，该模块将独立的计算单元封装在 Crypto Driver Objects 中，其中每个对象在同一时间只能精确执行一个作业（[SWS_Crypto_00014]），而 n 个对象则支持并行计算（[SWS_Crypto_00117]）。在此过程中，Driver Object 0 作为中央随机数生成器，用于同一实例的所有其他驱动程序对象的内部需求（[SWS_Crypto_00224]、[SWS_Crypto_00225]）。

加密作业通过 [SWS_Crypto_91003]（Crypto_ProcessJob）进行处理，其中模式位字段（START、UPDATE、FINISH）统一了流式传输和整体调用（SWS_CryptoDriver 第25页、[SWS_Crypto_00017]）。异步作业通过周期性函数 [SWS_Crypto_91012]（Crypto_MainFunction）进行计算，并在完成后通过 CRYIF_CallbackNotification 向 CryIf 报告（[SWS_Crypto_00027]、[SWS_Crypto_00028]）。正在运行的作业可以通过 [SWS_Crypto_00122] 同步取消（[SWS_Crypto_00183]、[SWS_Crypto_00214]），而直接重定向到密钥元素的缓冲区重定向则减少了复制操作（[SWS_Crypto_00203]、[SWS_Crypto_00221]）。

密钥管理包括在严格的访问权限控制下对密钥元素进行设置（[SWS_Crypto_91004]）、读取（[SWS_Crypto_91006]）、复制（[SWS_Crypto_00155]、[SWS_Crypto_91015]）、生成（[SWS_Crypto_91007]）和派生（[SWS_Crypto_91008]）（[SWS_Crypto_00219]、[SWS_Crypto_00220]）。出于一致性原因，在 Non-Volatile RAM Manager（NvM）中的持久化绝不会在单次写入时触发，而仅在通过 [SWS_Crypto_91014]（Crypto_KeySetValid）进行密钥验证时触发（SWS_CryptoDriver 第37页、[SWS_Crypto_91025]）。在多核环境中，该模块在每个分区中独立运行（[SWS_Crypto_CONSTR_00001]），其中 HSM 对象最多只能分配给一个分区（[SWS_Crypto_CONSTR_00003]）。

Crypto Driver 在 Classic 加密栈中的角色和系统边界

Crypto Driver（模块缩写 Crypto）位于微控制器抽象层（MCAL）中 AUTOSAR Classic 基础软件的最底层（EXP_UtilizationOfCryptoServices 第8页）。它直接位于加密接口（Crypto Interface, CryIf）下方，并通过该接口为 Crypto Service Manager（CSM）提供服务（SWS_CryptoDriver 第15页）。其主要任务在于封装具体的加密计算单元——无论是硬件安全模块（Hardware Security Modules, HSM）、专用加密加速器（如 AES 引擎）还是纯软件库（SWS_CryptoDriver 第15页）。除了加密原语的实际计算之外，其功能范围还包括加密密钥的存储、配置和管理（SWS_CryptoDriver 第24页）。

在一个 ECU 中，可以并行存在来自不同供应商的多个驱动程序实例；在这种情况下，文件、API 和配置标识符通过符合模式 Crypto_<vi>_<ai> 的特定于供应商的中缀进行唯一定义和区分（[SWS_Crypto_00012]）。模块的初始化通过函数 [SWS_Crypto_91000] 进行（Crypto_Init）。作为一项特殊规定，类型为 [SWS_Crypto_91016] 的配置指针（Crypto_ConfigType）必须始终作为空指针传递（[SWS_Crypto_00215]）。版本信息可以通过 [SWS_Crypto_91001]（Crypto_GetVersionInfo）同步查询，如果在开发错误检测处于激活状态时传递空指针，则会以错误 CRYPTO_E_PARAM_POINTER 报告给 DET（SWS_CryptoDriver 第56页）。

Crypto Driver Objects 的管理和硬件抽象

Crypto Driver 的每个实例在内部划分为一个或多个逻辑驱动程序对象（Crypto Driver Objects）（SWS_CryptoDriver 第15页）。Crypto Driver Object 构成了加密通道的功能端点，并代表独立的硬件计算单元或软件实现（SWS_CryptoDriver 第15页）。原则上，单个 Driver Object 在给定时间只能主动执行一个作业（Job）（[SWS_Crypto_00014]）。因此，具有 n 个 Driver Objects 的 Crypto Driver 具备并行计算 n 个加密作业的能力（[SWS_Crypto_00117]）。所分配对象的性能决定了支持哪些数学和安全相关的原语（[SWS_Crypto_00013]）。

如果驱动程序对象需要内部随机数（例如在通过 [SWS_Crypto_91009] 进行密钥交换的框架下计算公开值）且自身没有随机数生成器，则必须强制使用同一驱动程序的 Crypto Driver Object 0（[SWS_Crypto_00224]、[SWS_Crypto_00225]）。在此情况下，驱动程序对象在任何情况下均不得寻址其他加密驱动程序实例的随机数生成器（[SWS_Crypto_00226]）。解读：Driver Object 0 因此充当同一分区中所有其他驱动程序对象的中央内部参考随机数生成器。

同步直接调用与异步流式传输之间的作业处理

加密处理作为类型为 Crypto_JobType 的作业结构，通过中央接口 [SWS_Crypto_91003]（Crypto_ProcessJob）传递给该模块（[SWS_Crypto_00042]、AUTOSAR_CP_SWS_CryptoServiceManager 第21页）。该接口通过模式特定的位字段统一了基于块的整体调用和连续数据流传输：操作 START、UPDATE 和 FINISH 可以单独或组合传递（SWS_CryptoDriver 第25页）。设置 START 标志标记了一个新作业，并中止同一作业的所有先前实例（[SWS_Crypto_00017]）。在组合传递的情况下，各步骤始终以固定顺序执行：START、UPDATE，最后是 FINISH（SWS_CryptoDriver 第25页）。

作业是同步处理还是异步处理，属于 Crypto_JobType 中元数据配置的一部分（SWS_CryptoDriver 第26页）。在异步模式下，[SWS_Crypto_91003] 仅接收作业数据；实际执行由周期性主函数 [SWS_Crypto_91012]（Crypto_MainFunction）触发或处理（[SWS_Crypto_00027]、[SWS_Crypto_91012]）。在异步计算完成后，Crypto Driver 通过调用回调函数 CRYIF_CallbackNotification 并返回状态和结果指针，规范地通知上层 CryIf（[SWS_Crypto_00028]）。解读：与此相反，同步调用在调用方的上下文中以阻塞方式执行加密操作，而无需通过主函数进行解耦。

正在运行或待处理的加密作业可以通过函数 [SWS_Crypto_00122]（Crypto_CancelJob）取消。如果请求的作业未处于驱动程序对象的主动处理中，则该作业会立即被移除，并且该调用返回 E_OK（[SWS_Crypto_00214]）。然而，如果硬件无法立即中断活动计算过程，则该 API 会以 CRYPTO_E_JOB_CANCELED 确认该尝试，并且取消操作将在下一个可到达的步骤完成（[SWS_Crypto_00183]）。

时序图：通过 Crypto_CancelJob 同步取消加密作业，包含活动硬件执行情况下的分支处理。来源：SWS_Crypto_00122、SWS_Crypto_00183、SWS_Crypto_00214

为了避免应用程序和硬件内存之间不必要的复制操作，Crypto Driver 支持直接缓冲区重定向（作业重定向）：输入和输出数据可以通过 jobRedirectionInfoRef 直接引用到内部密钥元素（[SWS_Crypto_00203]、[SWS_Crypto_00204]）。为了防止数据泄漏，此处适用严格的权限检查：对于加密和解密服务的输入重定向，密钥元素必须至少具有权限 CRYPTO_RA_ENCRYPTED；对于纯读取重定向，至少需要 CRYPTO_RA_INTERNAL_COPY（[SWS_Crypto_00221]）。

密钥管理、访问权限和加密密钥操作

在 Crypto Driver 中，逻辑密钥（Key）由一个或多个密钥元素（Key Elements）组成，这些元素容纳实际的密钥材料、初始化向量（IV）、随机种子或 SHE 证明（Proof）（SWS_CryptoDriver 第28页）。对每个单独元素的访问均受到严格规范：根据配置的权限层次结构（例如 CRYPTO_RA_ALLOWED、CRYPTO_RA_ENCRYPTED、CRYPTO_RA_INTERNAL_COPY）监视读写访问，其中较小的枚举值代表更高级别的访问权限（SWS_CryptoDriver 第28页、[SWS_Crypto_00219]）。直接读取操作仅在 CRYPTO_RA_ALLOWED 或 CRYPTO_RA_ENCRYPTED 时被允许（[SWS_Crypto_00222]）；写入访问至少需要 CRYPTO_WA_ALLOWED 或 CRYPTO_WA_ENCRYPTED（[SWS_Crypto_00223]）。复制时，源元素必须至少具有 CRYPTO_RA_INTERNAL_COPY，且其权限不得低于目标元素（[SWS_Crypto_00220]）。

为了直接操作密钥及其元素，Crypto Driver 提供了一系列同步 API：数据的设置和读取分别通过 [SWS_Crypto_91004]（Crypto_KeyElementSet）和 [SWS_Crypto_91006]（Crypto_KeyElementGet）进行。密钥的现有元素标识符可以通过 [SWS_Crypto_00160]（Crypto_KeyElementIdsGet）确定。完整的密钥或单个元素通过 [SWS_Crypto_00155]（Crypto_KeyCopy）或 [SWS_Crypto_00148]（Crypto_KeyElementCopy）进行复制。对于部分复制，存在 [SWS_Crypto_91015]（Crypto_KeyElementCopyPartial），它对源缓冲区和目标缓冲区强制执行精确的长度和偏移量检查（[SWS_Crypto_00207]、[SWS_Crypto_00208]、[SWS_Crypto_00209]），并动态调整目标长度（[SWS_Crypto_00210]、[SWS_Crypto_00211]）。

此外，该模块还支持复杂的密钥操作：密钥生成通过 [SWS_Crypto_91007]（Crypto_KeyGenerate）基于先前通过 [SWS_Crypto_91013]（Crypto_RandomSeed）初始化的熵数据进行。新密钥材料的派生由 [SWS_Crypto_91008]（Crypto_KeyDerive）接管。对于 Diffie-Hellman 密钥交换协议，提供了用于生成公开值的函数 [SWS_Crypto_91009]（Crypto_KeyExchangeCalcPubVal）以及用于确定共享秘密的函数 [SWS_Crypto_91010]（Crypto_KeyExchangeCalcSecret）（SWS_CryptoServiceManager 第70页）。

每个逻辑密钥都维护一个状态，该状态可以通过 [SWS_Crypto_91019]（Crypto_KeyGetStatus）查询。新写入的密钥最初处于 invalid 状态，并且仅在通过 [SWS_Crypto_91014]（Crypto_KeySetValid）成功验证后才释放为 valid，而 [SWS_Crypto_91020]（Crypto_KeySetInvalid）则显式锁定该密钥。在数据格式方面，该驱动程序处理符合 RFC 5958 且采用 ASN.1-PKCS#8 编码的非对称密钥（[SWS_Crypto_00184]）、符合 RFC 8017 且具有固定算法 OID 1.2.840.113549.1.1.1 的 RSA 密钥结构（[SWS_Crypto_00185]、[SWS_Crypto_00186]、[SWS_Crypto_00187]、[SWS_Crypto_00188]），以及采用小端点坐标的 ECC 曲线数据（NIST、Brainpool、ED25519）（[SWS_Crypto_00189]、[SWS_Crypto_00190]、[SWS_Crypto_00191]、[SWS_Crypto_00192]、[SWS_Crypto_00193]）。面向硬件的 SHE 密钥以格式 M1M2M3 传递；其验证证明 M4M5 在验证后立即可在密钥元素 2 中临时读取（[SWS_Crypto_00255]）。

通过 Non-Volatile RAM Manager 持久化密钥元素

如果要使密钥在跨电压周期中保持非易失性，则将 Crypto Driver 连接到 Non-Volatile RAM Manager（NvM）（SWS_CryptoDriver 第35页、AUTOSAR_CP_SWS_CryptoDriver 第37页）。一项核心架构原则规定，向 NvM 的写入过程绝不能在通过 Crypto_KeyElementSet 填充单个元素时直接触发（SWS_CryptoDriver 第37页）。相反，持久化完全由状态验证 KEYSETVALID 通过 [SWS_Crypto_91014]（Crypto_KeySetValid）或等效的加密作业发起（SWS_CryptoDriver 第37页）。这确保了相互依赖的密钥元素得到一致的检查，并在单次 NvM 写入访问中保存，从而节省 Flash 周期（SWS_CryptoDriver 第37页）。

与 NvM 的交互通过专用回调接口进行：在 ECU 启动期间，NvM 通过 [SWS_Crypto_91023]（Crypto_<vi>_<ai>_NvBlock_Init_<NvBlock>）提供初始化块。从 NvM 的 RAM 镜像加载持久化数据通过 [SWS_Crypto_91024]（Crypto_<vi>_<ai>_NvBlock_ReadFrom_<NvBlock>）进行。在写入之前，NvM 调用 [SWS_Crypto_91025]（Crypto_<vi>_<ai>_NvBlock_WriteTo_<NvBlock>），以便加密驱动程序将其内部密钥数据复制到 NvM 缓冲区中；异步块传输的完成通过 [SWS_Crypto_91026]（Crypto_<vi>_<ai>_NvBlock_Callback_<NvBlock>）报告。为了进行控制，驱动程序使用 NvM 服务 NvM_SetRamBlockStatus 和 NvM_WriteBlock（[SWS_Crypto_91017]）。如果在启动时加载持久密钥失败，则驱动程序会规范地将该密钥标记为 invalid（[SWS_Crypto_00198]）。

分区和多核运行规则

为了在多核系统上高效分配加密操作，加密栈可以分布到多个软件分区中（BSWDistributionGuide 第59页）。Crypto 模块在每个分区中作为完全独立的实例运行：每个 API 调用仅在发起该调用的分区内处理数据（[SWS_Crypto_CONSTR_00001]）。驱动程序对象的分区遵循固定的配置规则：由 CryptoDriverObjectEcucPartitionRef 引用的分区必须强制构成分配给该模块的分区（CryptoEcucPartitionRef）的真子集（[SWS_Crypto_CONSTR_00002]）。如果 Crypto Driver Object 耦合到硬件安全模块（HSM），出于硬件隔离的原因，它最多只能分配给 0 个或 1 个分区（[SWS_Crypto_CONSTR_00003]）。

发生错误时的行为

Crypto Driver 实现了由开发错误检测（Development Errors）和运行时错误（Runtime Errors）组成的两级错误监控。当开发安全模式（DET）激活时，形式接口违规将发送至 Det_ReportError（[SWS_Crypto_91017]）。这包括驱动程序初始化之前的调用（CRYPTO_E_UNINIT, 0x00）（[SWS_Crypto_00040]、[SWS_Crypto_00196]、[SWS_Crypto_00205]）、无效的初始化数据（CRYPTO_E_INIT_FAILED, 0x01）以及不允许的空指针（CRYPTO_E_PARAM_POINTER, 0x02）（[SWS_Crypto_00040]）。如果密钥标识符或目标密钥句柄超出允许的值范围，驱动程序将以 E_NOT_OK 中止该调用，并报告 CRYPTO_E_PARAM_HANDLE（0x04）（[SWS_Crypto_00040]、[SWS_Crypto_00180]、[SWS_Crypto_00197]、[SWS_Crypto_00202]、[SWS_Crypto_00217]）。

如果传入的输入或输出缓冲区不足以执行某项操作，则拒绝执行，并在 DET 激活时报告错误 CRYPTO_E_SMALL_BUFFER（[SWS_Crypto_00195]、SWS_CryptoDriver 第49页）。服务 CRYPTO_HASH 和 CRYPTO_MACGENERATE 适用一项规范性例外：如果此处的输出缓冲区小于本机哈希或 MAC 长度，则结果不会被丢弃，而是以最高有效位（MSB）的形式截断写入缓冲区（[SWS_Crypto_00065]）。在运行过程中，驱动程序通过返回值报告特定的运行时错误：随机熵耗尽时，[SWS_Crypto_91003] 会以返回码 CRYPTO_E_ENTROPY_EXHAUSTED 进行确认，并报告运行时错误 CRYPTO_E_RE_ENTROPY_EXHAUSTED（0x03）（[SWS_Crypto_00141]、[SWS_Crypto_00194]、[SWS_Crypto_91018]）。如果对 NVM 的读写访问失败，则发出 CRYPTO_E_RE_NVM_ACCESS_FAILED（0x04）信号（[SWS_Crypto_00194]）。其他标准化的 API 返回值包括 CRYPTO_E_BUSY、CRYPTO_E_KEY_READ_FAIL、CRYPTO_E_KEY_WRITE_FAIL、CRYPTO_E_KEY_NOT_AVAILABLE、CRYPTO_E_KEY_NOT_VALID、CRYPTO_E_KEY_SIZE_MISMATCH 和 CRYPTO_E_KEY_EMPTY（[SWS_Crypto_00155]、[SWS_Crypto_00207]、[SWS_Crypto_91018]）。
