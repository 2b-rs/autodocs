BswM 的角色：基础软件模式的仲裁者

在 ECU 中，模式请求汇集到 BSW Mode Manager (BswM)，并由其转换为动作。它基于传入的模式指示 [SWS_BswM_00035] 进行仲裁。规范在此区分了两种输入类型（SWS BswM 第26页）：

  • 模式请求通常来自应用 SW-C，有时也来自 BSW 模块（例如 DCM）。
  • 模式指示始终来自 BSW 模块，例如总线专用的 State Manager 或 EcuM。

在组件模型中，BswM 是一个服务组件，仅服务于自身 ECU 的 Mode Request（SWS BswM 第48页）。

BswM 通过动作发挥作用。原则上它允许调用 AUTOSAR-BSW 的任何函数（SWS BswM 第92页）。规范列出的可选接口包括 Com_IpduGroupStart、Com_IpduGroupStop 以及 Com_EnableReceptionDM [SWS_BswM_00008] 等。此外，BswM 还可以执行用户 Callout [SWS_BswM_00270]。其参数在配置时于容器 BswMUserCallout 中确定 [SWS_BswM_00054]。BswM 没有针对其他模块的强制接口 [SWS_BswM_00007]。

输入：指示、请求和事件

BswM 为每个源的 BSW 模块提供一个 C-API。在内部，它将每个调用映射到一个 Mode Request Port（Guide Modemanagement 第18页）。映射表为此分别将一个 API 参数与一个配置引用相关联（SWS BswM 第87页）。例如：BswM_CanSM_CurrentState 通过键值对 Network / BswMCanSMChannelRef 分配给源 BswMCanSMIndication [SWS_BswM_00049]。每个 CAN 通道创建该源一次（Guide Modemanagement 第24页）。

按来源划分的报告 API：

  • Bus State Manager：CanSM、LinSM、FrSM 和 EthSM 报告其状态（[SWS_BswM_00049]、[SWS_BswM_00052]、[SWS_BswM_00051]、[SWS_BswM_00050]）。LinSM 还报告活动调度表 [SWS_BswM_00058]，且 LinTp 请求 LIN-TP 模式 [SWS_BswM_00156]。
  • ComM：报告通道模式 [SWS_BswM_00047] 和 PNC 模式 [SWS_BswM_00148]，并通过 BswM_ComM_InitiateReset 发出关闭信号 [SWS_BswM_00217]。
  • 网络管理：Nm 和 J1939Nm 报告状态切换（[SWS_BswM_91002]、[SWS_BswM_00194]）。Nm 还指示 CarWakeUp [SWS_BswM_00235]。
  • 存储与诊断：报告来自 NvM（[SWS_BswM_00104]、[SWS_BswM_00152]）、DCM（[SWS_BswM_00048]、[SWS_BswM_00158]）和 J1939Dcm [SWS_BswM_00165]。
  • Service Discovery：通过三个回调进行报告（[SWS_BswM_00204]、[SWS_BswM_00207]、[SWS_BswM_00210]）。
  • EthIf 与 WdgM：EthIf 报告交换机端口组的链路状态 [SWS_BswM_91001]。WdgM 请求分区复位 [SWS_BswM_00157]。

如果 BSW 模块没有自己的请求接口，则使用带有类型 BswM_UserType 和 BswM_ModeType 的通用调用 BswM_RequestMode（[SWS_BswM_00046]、[SWS_BswM_00216]、[SWS_BswM_00214]）。SW-C 通过三种端口类型访问 BswM：

  • modeRequestPort：用于模式请求的 Required Port [SWS_BswM_00201]。
  • modeNotificationPort：BswM 用来接收所观察到的模式切换的 Required Port [SWS_BswM_00200]。
  • modeSwitchPort：BswM 自身用于切换模式的 Provided Port [SWS_BswM_00202]。

像 BswM_ComM_InitiateReset 这样的事件被配置为 BswMEventRequestPort（SWS BswM 第102页）。仲裁既考虑事件的发生，也考虑其清除（SWS BswM 第26页）。

Release 参考 R20-11：根据变更历史（SWS BswM 第2页），R20-11 带来了以下变更：

  • 重新引入 BswM_EcuM_CurrentState [SWS_BswM_91003] 和 BswM_EcuM_RequestedState [SWS_BswM_91004]。
  • 对以太网交换机端口组的支持。
  • 新动作 BswMEthIfStartAllPorts [SWS_BswM_00286]。
  • 废除 Pretended Networking。

两项后续变更尚不涉及 R20-11：BswM_WdgM_RequestPartitionReset [SWS_BswM_00157] 直到 R21-11 才被标记为已废弃，而 SoAd-Mode-Request 也是直到 R21-11 才添加（SWS BswM 第2页）。

规则、动作列表与评估时机

BswM 的行为通过规则和动作列表进行配置（Guide Modemanagement 第32页）：

  • 规则是基于 Mode Request Port 当前值的逻辑表达式。
  • 根据结果，BswM 执行 True 动作列表或 False 动作列表。
  • 动作列表包含原子动作、嵌套动作列表或对其他规则的引用。

动作仅允许在动作列表的上下文中调用 [SWS_BswM_00147]。

何时对规则求值由每个端口的参数 BswMRequestProcessing 确定：

  • IMMEDIATE：引用该端口的所有规则都会被立即评估（Guide Modemanagement 第32页）。对于 SW-C 请求，RTE 必须为此通过 DataReceiveEvent 触发仲裁 Runnable（SWS BswM 第48页）。
  • BSWM_DEFERRED：规则在 BswM_MainFunction [SWS_BswM_00053] 中求值 [SWS_BswM_00075]。

对于定时器适用特殊规则。无论其配置如何，BswMTimer 始终被视为 DEFERRED 并在 Main Function 中进行仲裁 [SWS_BswM_00220]。在 R23-11 版本中，它只能通过动作 BswMTimerControl 进行控制，且其分辨率是 Main Function 周期时间的整数倍（SWS BswM 第37页）。

初始值会影响哪些规则会被仲裁。如果缺少初始值（BswMModeInitValue），则模式条件在首次更新之前均被视为未定义。包含未定义条件的规则将不会被仲裁（SWS BswM 第30页）。该细化说明源自 R23-11 版本。推测其在含义上已适用于 R20-11；但此处未提供相应的 R20-11 需求。

活动图：检查消息、进行存储，并根据处理方式立即求值或在 Main Function 中求值；随后执行 True 或 False 动作列表。来源：[SWS_BswM_00080]、[SWS_BswM_00095]、[SWS_BswM_00075]、[SWS_BswM_00147]、[SWS_BswM_00238]、Guide Modemanagement 第32页、SWS BswM 第30页

EcuM 主导下的生命周期与启动

BswM_Init [SWS_BswM_00002] 初始化所有模块全局变量。之后，BswM 即可仲裁模式请求。在调用前，只需初始化 OS 和 SchM（SWS BswM 第69页）。传入的指针指向 BswM_ConfigType 中的 Post-Build 数据 [SWS_BswM_00213]。BswM_Init 为“Conditionally Reentrant”，因为 BswM 可以在多个分区中被实例化（SWS BswM 第69页）。因此，EcuM 会在循环中为核心的每个 BswM 实例调用 BswM_Init（SWS EcuM 第83页）。

在 StartPostOS 序列中，EcuM 首先启动 BSW 调度程序。随后初始化 BswM，并紧接着完成 SchM 初始化（SWS EcuM 第42页）。从此时起，BswM 控制后续的启动过程：它确保其余 BSW 模块的初始化例程运行并启动 RTE（Guide Modemanagement 第36页）。在指南的示例中，该过程如下进行：

  1. 一条 DEFERRED 规则触发 NvM_ReadAll。
  2. NvM 通过 BswM_NvM_CurrentJobMode [SWS_BswM_00152] 报告完成。
  3. 随后一条后续规则启动 RTE（NV-Daten-Leitfaden 第20页）。

序列图：EcuM 在 StartPostOS 中初始化 BswM；随后 BswM 规则通过 NvM_ReadAll 和 Rte_Start 推进启动过程。来源：SWS EcuM 第42页、Guide Modemanagement 第36页、NV-Daten-Leitfaden 第20页、[SWS_BswM_00002]

在关闭过程中，EcuM 在 OffPreOS 序列中为核心的每个 BswM 实例调用 BswM_Deinit [SWS_BswM_00119]（SWS EcuM 第90页）。此后，即使继续收到请求或调用 Main Function，BswM 也不再处理模式 [SWS_BswM_00120]。如果 BswM 的分区重新启动，RestartTask 会通过 BswM_BswMPartitionRestarted [SWS_BswM_00193] 对此进行报告。

状态图：BswM 仅在 BswM_Init 和 BswM_Deinit 之间进行仲裁；在此之前和之后均不进行模式处理。来源：[SWS_BswM_00002]、[SWS_BswM_00119]、[SWS_BswM_00120]、[SWS_BswM_00076]、[SWS_BswM_00078]、SWS BswM 第69页

与 EcuM、唤醒源及以太网端口组的交互

在 ECU Mode Handling 中，EcuM 没有自己的状态机（SWS EcuM 第99页）。它仲裁 SW-C 的 RUN 和 POST_RUN 请求，并通过 BswM_EcuM_RequestedState [SWS_BswM_91004] 报告结果，因为只有 BswM 决定转换。该流程是一个循环：

  1. BswM 使用 EcuM_SetState 设置状态。
  2. EcuM 将模式传递给 RTE（SWS EcuM 第99页）。
  3. 在RTE反馈后，EcuM通过BswM_EcuM_CurrentState [SWS_BswM_91003]向BswM报告新状态（Guide Modemanagement 第34页）。

通过这种结构，也可以继续使用针对具有固定状态机的EcuM编写的Legacy-SW-C（Guide Modemanagement 第61页）。

序列图：EcuM报告RUN Request Protocol的结果，BswM做出决策并设置状态，且仅在RTE反馈后才跟随BswM_EcuM_CurrentState。来源：SWS EcuM 第99页、Guide Modemanagement 第34页、Guide Modemanagement 第61页、[SWS_BswM_91003]、[SWS_BswM_91004]

唤醒源在EcuM中经历NONE、PENDING、VALIDATED和EXPIRED状态。每次进入这些状态之一，EcuM都会通过BswM_EcuM_CurrentWakeup [SWS_BswM_00131]进行报告（SWS EcuM 第64页）。在BswM中，对应的源是具有初始值ECUM_WKSTATUS_NONE的BswMEcuMWakeupSource，该源会为每个唤醒源创建一次（Guide Modemanagement 第29页）。

状态图：唤醒源的每次状态变化都作为模式指示传递给BswM。来源：SWS EcuM 第60页、SWS EcuM 第63页、SWS EcuM 第64页、[SWS_BswM_00131]

以太网交换机端口组在R20-11中是新增内容。ComM通过BswM_ComM_CurrentPNCMode [SWS_BswM_00148]报告PNC模式。BswM知晓PNC到端口组的映射关系，并使用ETH_MODE_ACTIVE或ETH_MODE_DOWN调用EthIf_SwitchPortGroupRequestMode（Guide Modemanagement 第49页）。在反方向上，EthIf通过BswM_EthIf_PortGroupLinkStateChg [SWS_BswM_91001]报告未分配给任何EthIfController的那些端口组的累加链路状态（SWS EthIf 第29页）。通过动作BswMEthIfStartAllPorts，BswM通过EthIf_StartAllPorts [SWS_BswM_00286]启动所有端口。

序列图：PNC模式控制端口组，且累加链路状态回传给BswM。来源：Guide Modemanagement 第49页、SWS EthIf 第92页、SWS EthIf 第29页、[SWS_BswM_00148]、[SWS_BswM_91001]

发生错误时的行为

若BswMDevErrorDetect处于激活状态，则报告API会检查两项内容：

  • 初始化：若BswM未初始化，则该报告将被忽略，并向DET报告BSWM_E_UNINIT。示例包括CanSM [SWS_BswM_00080]、EthSM [SWS_BswM_00081]、LinSM调度[SWS_BswM_00086]、PNC [SWS_BswM_00149]以及NvM作业[SWS_BswM_00153]。
  • 取值范围：超出允许范围的值同样会被丢弃并通过BSWM_E_REQ_MODE_OUT_OF_RANGE报告，例如在[SWS_BswM_00095]、[SWS_BswM_00150]、[SWS_BswM_00133]和[SWS_BswM_00154]中。

Main Function的表现有所不同：若在初始化之前被调用，它会立即返回且不报告任何错误[SWS_BswM_00076]。

开发错误码包括BSWM_E_UNINIT (0x01)、BSWM_E_NULL_POINTER、BSWM_E_REQ_USER_OUT_OF_RANGE、BSWM_E_REQ_MODE_OUT_OF_RANGE和BSWM_E_PARAM_CONFIG [SWS_BswM_00230]等。若某个动作返回E_NOT_OK，BswM将报告运行时错误BSWM_E_ACTION_FAILED。其值介于0x80和0xFF之间，并在BswMReportFailRuntimeErrorId中配置[SWS_BswM_00238]。

系统错误作为常规模式指示到达BswM。发生Bus-Off时，CanSM按以下顺序报告（SWS CanSM 第70页）：

  1. 向BswM报告CANSM_BSWM_BUS_OFF，
  2. 向ComM报告COMM_SILENT_COMMUNICATION，
  3. 向DEM报告一个PRE_FAILED事件。

若恢复成功，则接着是CANSM_BSWM_FULL_COMMUNICATION（SWS CanSM 第65页）。系统对此如何反应完全取决于通过BswMCanSMIndication [SWS_BswM_00049]制定的规则。其他错误路径包括WdgM请求的分区复位[SWS_BswM_00157]以及分区重启报告[SWS_BswM_00193]。
