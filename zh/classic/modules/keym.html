KeyM 在密钥主节点、应用程序与 CSM 之间的角色

Key Manager（KeyM）由两个子模块组成。加密密钥子模块（Crypto-Key-Submodul）负责初始化、更新和维护 ECU 的加密密钥材料，例如用于 Secured I-PDU 的密钥。这些密钥由位于车辆内部或后端中的密钥主控端（Key Master）提供。与其进行的通信通常通过诊断命令（SWS KeyM 第24页）进行。证书子模块维护 PKI 证书的状态并提供其内容（[SWS_KeyM_00066]、[SWS_KeyM_00083]）。KeyM 本身不存储密钥材料。它通过强制接口 Csm_KeyElementSet、Csm_KeyElementGet 和 Csm_KeySetValid 将其传递给 CSM 密钥（[SWS_KeyM_00076]）。其他使用的接口包括 Csm_KeyDerive、Csm_SignatureVerify、Det_ReportError 和 IdsM_SetSecurityEvent（[SWS_KeyM_00078]）。

应用 SWC 通过 RTE 端口进行访问。每个证书对应一个端口 KeyMCertificate_{KeyMCertificate}，每个证书元素对应一个端口 KeyMCertificateElement_…，此外还有端口 KeyMCryptoKey 和 KeyMCryptoKeyNotification（[SWS_KeyM_00160]、[SWS_KeyM_00162]、[SWS_KeyM_00163]、[SWS_KeyM_00164]）。BSW 模块同样使用 KeyM：

  • TcpIp 的 TLS 实现使用 KeyM_GetCertificate 获取证书（SWS TcpIp 第134页）。
  • DCM 使用 KeyM_CertElementGetFirst/KeyM_CertElementGetNext 读取白名单（SWS DCM 第162页）。
  • DCM 通过配置为回调的 Dcm_KeyMAsyncCertificateVerifyFinished 接收验证结果（SWS DCM 第245页）。

证书链及其配置

证书在配置中通过 KeyMCertificate 容器进行描述。在运行时，通过句柄 KeyM_CertificateIdType 和 KeyM_CertElementIdType 对其进行寻址，两者类型均为 uint16（[SWS_KeyM_00301]、[SWS_KeyM_00300]）。每个容器包含三个引用：

  • 指向上一级证书；其中根证书指向自身，
  • 指向用于签名校验的 CSM 作业，
  • 指向用于该证书公钥的 CSM 密钥。

该结构如图 SWS KeyM (图 7.3) 第22页 所示。如果所有校验步骤均无错误，KeyM 会将公钥写入通过 KeyMCertCsmSignatureVerifyKeyRef 引用的 CSM 密钥中，并通过 Csm_KeySetValid 进行有效性验证（[SWS_KeyM_00170]）。

证书数据以 KeyM_CertDataType 形式传递。该结构由 certDataLength 以及指向调用方缓冲区的指针 certData 组成（[SWS_KeyM_00041]）。RTE 数据类型的大小取决于配置：KeyMKeyCertNameMaxLength 用于名称，KeyMCertificateElementMaxLength 用于元素缓冲区（[SWS_KeyM_91000]、[SWS_KeyM_91004]）。

上下文图：由 Root – Intermediate – Working Certificate 组成的三级证书链，分别引用一个 CSM 作业和一个 CSM 密钥；Root 引用自身。来源：SWS KeyM (图 7.3) 第22页、[SWS_KeyM_00170]

证书状态：从设置到有效

每个证书都具有一个类型为 KeyM_CertificateStatusType 的状态，由 KeyM_CertGetStatus 返回（[SWS_KeyM_91003]、[SWS_KeyM_00066]）。符合 SWS KeyM (图 7.4) 第24页 的生命周期：

  • 执行 KeyM_Init 后，证书处于 KEYM_CERTIFICATE_NOT_AVAILABLE 状态。
  • 长度 > 0 的 KeyM_SetCertificate、KeyM_ServiceCertificate 或启动时的加载操作会导致转换到瞬态状态 KEYM_CERTIFICATE_NOT_PARSED。
  • 解析成功后进入 KEYM_CERTIFICATE_PARSED_NOT_VALIDATED。
  • 长度为 0 的 KeyM_SetCertificate 会重置证书和状态。

证书只有在完整、无差错地通过验证后才会达到 KEYM_CERTIFICATE_VALID（[SWS_KeyM_00170]）。如果校验失败，则停留在特定的错误状态，例如 KEYM_E_CERTIFICATE_VALIDITY_PERIOD_FAIL、KEYM_E_CERTIFICATE_SIGNATURE_FAIL 或 KEYM_E_CERTIFICATE_INVALID_CHAIN_OF_TRUST（[SWS_KeyM_91003]）。

状态图：证书经历“不可用 → 未解析 → 已解析 → 有效”；解析和验证错误会导致进入各自的错误状态。解释：验证错误状态的分配以及从所有状态退出的重置路径均为推导得出。来源：SWS KeyM (图 7.4) 第24页、SWS KeyM (图 7.4) 第33页、[SWS_KeyM_91003]

KeyM_SetCertificate 仅将提交的证书临时存放在已配置的存储类别中，通常在 RAM 中。对于持久存储（例如根证书），则预留了 KeyM_ServiceCertificate（[SWS_KeyM_00057]、SWS KeyM 第31页）。对于异步验证，存在三种变体：

  • KeyM_VerifyCertificates 校验恰好由下级和上级证书组成的一对证书（[SWS_KeyM_00059]）。
  • KeyM_VerifyCertificate 自行从已存储的证书中确定已设置证书的证书链（[SWS_KeyM_00060]）。
  • KeyM_VerifyCertificateChain 校验由调用方传入的、按 PKI 顺序排序的证书链（[SWS_KeyM_00061]）。

如果调用返回 E_OK，则配置的 KeyMCertificateVerifyCallbackNotificationFunc 随后会将结果作为 KeyM_CertificateStatusType 进行通报（[SWS_KeyM_00153]、[SWS_KeyM_00073]）。

时序图：工作证书被设置、解析并进行异步验证；随后公钥在 CSM 中被设置并验证其有效性，结果通过回调进行通报。来源：SWS KeyM (图 9.4) 第119页、[SWS_KeyM_00060]、[SWS_KeyM_00170]、[SWS_KeyM_00153]

证书服务与证书元素访问

如果设置了 KeyMServiceCertificateFunctionEnabled 和 KeyMCertificateManagerEnabled，证书子模块将提供 KeyM_ServiceCertificate。密钥主控端通过它引入或更新持久存储的证书（[SWS_KeyM_00021]、[SWS_KeyM_00056]）。该操作通过 KeyM_ServiceCertificateType 进行选择（[SWS_KeyM_00039]）：

  • 请求 CSR 或写回已签名的 CSR，
  • 设置或更新根证书或中间证书，
  • 提供吊销列表，
  • 保留范围 0x80–0x9F 内的制造商特定扩展。

该操作异步执行，并以 KeyM_ServiceCertificateCallbackNotification 结束（[SWS_KeyM_00149]、[SWS_KeyM_00152]）。可选择接入 Key-Handler KeyM_KH_ServiceCertificate（[SWS_KeyM_00072]）。

与后续版本的差异：后续版本补充了 KeyM_ServiceCertificateByCertId，并将回调缩减为 CertId 和 Result（SWS KeyM 第92页）。对于 R20-11，适用带有 ResultDataLength 和 ResultDataPtr 的签名（[SWS_KeyM_00147]）。根证书和中间证书的安装和更新尝试已被标准化为安全事件 KEYM_SEV_INST_ROOT_CERT_OP 至 KEYM_SEV_UPD_INTERMEDIATE_CERT_OP（[SWS_KeyM_00172]）。

时序图：通过 KeyM_ServiceCertificate 引入根证书或中间证书，进行解析、时间校验，并根据配置存入 NvM 或 CSM；操作结束由服务回调通报。来源：SWS KeyM (图 9.5) 第120页、[SWS_KeyM_00056]、[SWS_KeyM_00149]、[SWS_KeyM_00147]

已解析证书的内容由 KeyM_CertElementGet 根据配置的对象 ID 进行读取（[SWS_KeyM_00063]、[SWS_KeyM_00127]）。对于包含多个值的元素，可以通过两种方式进行遍历：

  • 使用 KeyM_CertElementGetFirst/KeyM_CertElementGetNext 以及由调用方持有的 KeyM_CertElementIteratorType，该标记在遍历结束前必须保持不变（[SWS_KeyM_00064]、[SWS_KeyM_00065]、[SWS_KeyM_00042]），
  • 基于索引，使用 KeyM_CertificateElementGetCount 和 KeyM_CertificateElementGetByIndex（[SWS_KeyM_91015]、[SWS_KeyM_91014]）。

迭代仅允许用于 KeyMCertificateElementHasIteration = TRUE 的元素（[SWS_KeyM_00148]）。

作为 Start–Prepare–Update–Finalize 会话的密钥更新

加密密钥子模块可以以会话方式运行。KeyM_Start 打开会话，KeyM_Finalize 关闭会话；在此期间接受诸如 KeyM_Prepare 和 KeyM_Update 等操作（[SWS_KeyM_00050]、[SWS_KeyM_00053]、SWS KeyM 第25页）。KeyM_StartType 用于区分权限较高的 OEM 生产模式与维修厂模式（[SWS_KeyM_00038]）。

若启用了 Key-Handler，KeyM_Start 会将参数传递给 KeyM_KH_Start 并采用其返回值。以此可以实现例如制造商特定的签名校验（[SWS_KeyM_00067]、SWS KeyM 第25页）。相应地，KeyM_Prepare 和 KeyM_Finalize 委托给 KeyM_KH_Prepare 或 KeyM_KH_Finalize（[SWS_KeyM_00068]、[SWS_KeyM_00070]）。若设置了 KeyMCryptoKeyStartFinalizeFunctionEnabled，则由 KeyM_CryptoKeyFinalizeCallbackNotification 通报完成状态（[SWS_KeyM_00080]、[SWS_KeyM_00079]）。

时序图：密钥会话通过 KeyM_Start 打开，通过 KeyM_Prepare 进行准备，通过 KeyM_Update 进行异步更新，并通过 KeyM_Finalize 关闭；根据配置接入 Key-Handler。来源：[SWS_KeyM_00050]、[SWS_KeyM_00067]、[SWS_KeyM_00068]、[SWS_KeyM_00077]、[SWS_KeyM_00080]、SWS KeyM (图 9.2) 第117页

KeyM_Update 采用异步工作方式（[SWS_KeyM_00052]）。KeyM 通过以下两种途径之一找到目标密钥：

  • 通过 KeyMCryptoKeyName 中的名称（[SWS_KeyM_00091]），
  • 在没有有效名称的情况下，通过被解释为 SHE-M1M2M3 的请求数据的位 121..124 与 KeyMCryptoKeyCryptoProps 进行比对（[SWS_KeyM_00154]）。

在未匹配且未配置 Key-Handler 的情况下，调用以 KEYM_E_PARAMETER_MISMATCH 结束（[SWS_KeyM_00155]）。在使用 Key-Handler 时，更新流程如下：

  1. KeyM 携带找到的密钥或 0xFFFFFFFFul 调用 KeyM_KH_Update（[SWS_KeyM_00092]），并在此过程中提供内部缓冲区（[SWS_KeyM_00097]）。
  2. 如果 Handler 返回带有数据的 KEYM_KH_UPDATE_KEY_UPDATE_REPEAT，KeyM 会在 CSM 中存储或派生该密钥，并再次调用 Handler（[SWS_KeyM_00096]、[SWS_KeyM_00055]）。
  3. 如果 Handler 返回 KEYM_KH_UPDATE_FINISH，KeyM 会将结果复制到调用方的缓冲区中并调用 KeyM_CryptoKeyUpdateCallbackNotification（[SWS_KeyM_00093]）。

在收到该回调之前，调用方不得修改结果缓冲区（[SWS_KeyM_00156]）。

活动图：KeyM_Update 通过名称或 SHE 数据确定目标密钥，并直接处理该密钥或在 Key-Handler 循环中处理直至 KEYM_KH_UPDATE_FINISH。来源：[SWS_KeyM_00091]、[SWS_KeyM_00092]、[SWS_KeyM_00093]、[SWS_KeyM_00096]、[SWS_KeyM_00154]、[SWS_KeyM_00155]

KeyM_Verify 根据配置同步校验密钥。在 KeyMCryptoKeyVerifyAsyncMode = TRUE 时，校验异步运行，结果通过 KeyM_CryptoKeyVerifyCallbackNotification 返回（[SWS_KeyM_00054]、[SWS_KeyM_00151]、[SWS_KeyM_00081]）。

模块运行：初始化、时序控制和调用规则

KeyM_Init 初始化该模块（[SWS_KeyM_00043]）。配置指针必须始终为 NULL_PTR（[SWS_KeyM_00158]），尽管参数描述中提到了 Post-Build 配置集。解释：因此在 R20-11 中，配置实际上可能无法通过该指针传递。KeyM_Deinit 将模块置于未初始化状态（[SWS_KeyM_00047]）。R23-11 起的版本还额外要求主动清除 RAM 中的密钥材料（SWS KeyM 第49页）。

KeyM_MainFunction 按照配置的周期被周期性调用（[SWS_KeyM_00074]）。KeyM_MainBackgroundFunction 在抢占式操作系统的空闲时间运行，适用于诸如 KeyM_KH_Update 等耗时的同步函数（[SWS_KeyM_00075]）。推测这些函数推进了异步服务的执行：API 通过 E_OK 通报其已被接受，其完成状态则由回调通报（[SWS_KeyM_00060]、[SWS_KeyM_00052]）。这些服务均不可重入；迭代器函数仅在每个迭代器级别上可重入（[SWS_KeyM_00057]、[SWS_KeyM_00064]）。回调名称可配置，并通过 KeyM_Externals.h 引入（[SWS_KeyM_00073]、SWS KeyM 第91页）。

发生错误时的行为

在启用开发错误检测时，KeyM 在每次调用时都会检查（[SWS_KeyM_00144]、[SWS_KeyM_00145]、[SWS_KeyM_00146]、[SWS_KeyM_00036]）：

  • 初始化状态（KEYM_E_UNINIT），
  • 缓冲区大小（KEYM_E_SMALL_BUFFER），
  • 意外的 NULL 指针（KEYM_E_PARAM_POINTER）。

如果引用的证书具有存储类别 KEYM_STORAGE_IN_CSM 或 KEYM_STORAGE_IN_NVM，规范要求 KEYM_E_CONFIG_FAILURE，在非开发模式下为 E_NOT_OK（[SWS_KeyM_00166]）。

同步返回值使用 KeyM 特定的值（[SWS_KeyM_00040]）：

  • KEYM_E_BUSY：其他作业仍在运行，
  • KEYM_E_PENDING：作业已接受，异步处理，
  • KEYM_E_KEY_CERT_SIZE_MISMATCH、KEYM_E_PARAMETER_MISMATCH 和 KEYM_E_KEY_CERT_INVALID。

证书函数补充了其他代码。KEYM_E_KEY_CERT_EMPTY 表示空插槽，KEYM_E_KEY_CERT_READ_FAIL 表示访问被拒绝，KEYM_E_CERT_INVALID_CHAIN_OF_TRUST 表示无效的上级证书（[SWS_KeyM_00058]、[SWS_KeyM_00060]、SWS KeyM 第66页）。不可迭代的元素返回 KEYM_E_CERT_INVALID（[SWS_KeyM_00148]）。KeyM_CertElementGet 在失败时将输出长度置零（[SWS_KeyM_00063]、SWS KeyM 第71页）。

异步错误在回调中接收。KeyM_ResultType 可区分 KEYM_RT_NOT_OK、KEYM_RT_KEY_CERT_INVALID、KEYM_RT_KEY_CERT_WRITE_FAIL、KEYM_RT_KEY_CERT_UPDATE_FAIL 和 KEYM_RT_CERT_INVALID_CHAIN_OF_TRUST 等（[SWS_KeyM_91008]）。证书校验提供来自 KeyM_CertificateStatusType 的详细状态（[SWS_KeyM_00073]、[SWS_KeyM_91003]）。

失败的证书链校验同时也是安全事件 KEYM_SEV_CERT_VERIF_FAILED（ID 5）（[SWS_KeyM_00172]）。仅在 KeyMEnableSecurityEventReporting = TRUE 时才会向 IdsM 报告该事件。后续版本将该事件命名为 SEV_CERT_CHAIN_VERIFICATION_FAILED（SWS KeyM 第38页）；对于 R20-11，适用来自 [SWS_KeyM_00172] 的名称。
