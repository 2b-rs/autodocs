管理 ECU 的密钥和证书：证书链的更新、解析和校验。

Key Manager 在 AUTOSAR 加密栈中管理 ECU 的密钥材料和证书，并为此依托于 CSM。Crypto-Key 子模块在来自 KeyM_Start、KeyM_Prepare、KeyM_Update 和 KeyM_Finalize 的可选会话中接收密钥；可以集成特定于制造商的 Key Handler。证书子模块存储证书、解析证书并针对配置的证书链异步校验它们；回调 [SWS_KeyM_00153] 报告其结果。证书仅在校验无误后才生效，并且只有在此之后其公钥才会在 CSM 中启用 [SWS_KeyM_00170]。

Key Manager 在加密栈中管理 ECU 的密钥材料和证书。为此它包含两个子模块：Crypto-Key 子模块从车辆中或后端的 Key Master 接收密钥，主要通过诊断命令接收。证书子模块存储证书、解析证书并针对其证书链进行校验（SWS KeyM 第24页）。向下，KeyM 使用 CSM，强制要求实现 Csm_KeyElementGet、Csm_KeyElementSet 和 Csm_KeySetValid [SWS_KeyM_00076]。

密钥操作可以采用类似会话的方式进行（SWS KeyM 第25页）。KeyM_Start() 开启会话，KeyM_Prepare() 同步提供用于 Key Server 的数据，而 KeyM_Finalize() 关闭会话。KeyM_Update() 异步运行并通过 KeyM_CryptoKeyUpdateCallbackNotification() 给出返回反馈（[SWS_KeyM_00052]，[SWS_KeyM_00077]）。可选地，由 Key Handler 承担特定于制造商的步骤。在此过程中，KeyM_KH_Update() 会被持续调用，直到其报告 KEYM_KH_UPDATE_FINISH（[SWS_KeyM_00092]，[SWS_KeyM_00096]）。

时序图：会话从 Start 经过 Prepare 以及异步的 Update 一直运行到 Finalize，并带有可选的 Key Handler 和结果回调。来源：SWS KeyM 第25页、[SWS_KeyM_00052]、[SWS_KeyM_00079]

证书通过两种途径引入。持久性引入通过 KeyM_ServiceCertificate() 进行，由 Key Master 触发 [SWS_KeyM_00021]。临时性引入则是由调用方使用 KeyM_SetCertificate() 传递证书进行校验 [SWS_KeyM_00057]。每个证书都根据 KeyM_CertificateStatusType 维护一个状态 [SWS_KeyM_91003]。只有在校验无误后它才会变为 KEYM_CERTIFICATE_VALID，并且只有在此之后其公钥才会在 CSM 中启用 [SWS_KeyM_00170]。

状态图：证书从 NOT_AVAILABLE 经过解析进入 PARSED_NOT_VALIDATED，校验后进入 VALID 或进入错误状态；长度为 0 的复位将使其返回。对 INVALID_CONTENT 和 REVOKED 的分配属于一种解释。来源：SWS KeyM 第24页、[SWS_KeyM_91003]

校验通过 KeyM_VerifyCertificate()、KeyM_VerifyCertificates() 或 KeyM_VerifyCertificateChain() 异步进行。可配置的回调 [SWS_KeyM_00153] 报告其结果。通过 KeyM_CertElementGet() 读取单个内容；迭代器 [SWS_KeyM_00064] 遍历多次分配的元素。KeyM 通过三种途径报告错误：作为开发错误（例如 KEYM_E_UNINIT [SWS_KeyM_00036]）、作为回调 [SWS_KeyM_91008] 中的 KeyM_ResultType，以及在链校验失败时额外作为安全事件 [SWS_KeyM_00172]。

在加密栈中的角色：位于 CSM 之上的密钥和证书管理

Key Manager (KeyM) 是 AUTOSAR 加密栈中的一个服务模块，由两个子模块组成。Crypto-Key 子模块初始化、更新和维护 ECU 的密钥材料。证书子模块存储证书、解析证书并针对其证书链进行校验（SWS KeyM 第23页，SWS KeyM 第28页）。Crypto-Key 子模块的一个典型用例是将用于安全车载通信的密钥分发给 CSM 密钥。数据由位于车辆中或后端中的 Key Master 提供；通信主要通过诊断命令进行（SWS KeyM 第24页）。

向下，KeyM 依托于 CSM。[SWS_KeyM_00076] 指出的强制接口为 Csm_KeyElementGet、Csm_KeyElementSet 和 Csm_KeySetValid。此外，[SWS_KeyM_00078] 列出了 Csm_KeyDerive、Csm_SignatureVerify、Det_ReportError 和 IdsM_SetSecurityEvent。对于时间有效性校验，KeyM 导入 StbM 的类型 [SWS_KeyM_00037]。向上，KeyM 针对证书、证书元素和加密密钥提供 C API 和 RTE 服务接口（[SWS_KeyM_00082]，[SWS_KeyM_00083]，[SWS_KeyM_00084]）。特定于制造商的逻辑通过可配置的 Key Handler 函数集成，例如通过 KeyM_KH_Start() [SWS_KeyM_00067]。

上下文图：KeyM 在 Key Master 或用户、可选的 Key Handler 以及服务 CSM、StbM、NvM、IdsM 和 DET 之间进行中介协调。来源：SWS KeyM 第23页、[SWS_KeyM_00076]、[SWS_KeyM_00078]、[SWS_KeyM_00037]、SWS KeyM 第119页

初始化、调度和安全拆除

KeyM_Init() 初始化模块 [SWS_KeyM_00043]。KeyM_ConfigType 的内容取决于具体实现 [SWS_KeyM_00157]，并且配置指针应始终为 NULL_PTR [SWS_KeyM_00158]。初始化后，所有证书的状态均为 KEYM_CERTIFICATE_NOT_AVAILABLE（SWS KeyM 第34页）。KeyM_Deinit() 将模块重置为未初始化状态 [SWS_KeyM_00047]。相应的文档位置还要求 Crypto-Key 子模块主动覆盖 RAM 中的密钥材料和中间结果（SWS KeyM 第49页）。

在运行期间，KeyM_MainFunction() 按配置的周期被周期性调用 [SWS_KeyM_00074]。KeyM_MainBackgroundFunction() 在抢占式操作系统没有其他任务时运行。它可以调用耗时的同步函数，例如 KeyM_KH_Update() [SWS_KeyM_00075]。该周期是容器 KeyMGeneral 的一个参数（SWS KeyM 第131页）。KeyM_GetVersionInfo() 提供版本信息 [SWS_KeyM_00049]。

密钥会话：从 KeyM_Start 到 KeyM_Finalize

密钥操作可以配置为类似会话的方式。KeyM_Start() 开启会话。此后 KeyM 接收 KeyM_Prepare() 和 KeyM_Update()，直到 KeyM_Finalize() 关闭会话（SWS KeyM 第25页）。KeyM_StartType 区分 OEM 生产模式和车间售后模式；生产模式拥有更高的权限 [SWS_KeyM_00038]。默认情况下，KeyM_Start() 不评估任何输入数据。如果设置了 KeyMCryptoKeyHandlerStartFinalizeEnabled，它会使用相同的参数调用 KeyM_KH_Start() 并接管其返回值，例如用于 OEM 特定的签名校验（[SWS_KeyM_00050]，[SWS_KeyM_00067]）。

会话的各个步骤：

  • KeyM_Prepare() 同步工作，主要为 Key Server 提供信息 [SWS_KeyM_00051]。如果设置了 KeyMCryptoKeyPrepareFunctionEnabled 和 KeyMCryptoKeyHandlerPrepareEnabled，KeyM 将立即调用 KeyM_KH_Prepare()（[SWS_KeyM_00068]，SWS KeyM 第82页）。
  • KeyM_Update() 是异步的。KeyM_CryptoKeyUpdateCallbackNotification() 报告其结束（[SWS_KeyM_00052]，[SWS_KeyM_00077]，[SWS_KeyM_00150]）。在收到该回调之前，调用方不得触碰传入的结果缓冲区；回调将返回相同的指针 [SWS_KeyM_00156]。
  • KeyM_Finalize()同样是异步的，并将密钥操作置于空闲状态（SWS KeyM 第56页）。在启用 Key Handler 的情况下，它会委托给 KeyM_KH_Finalize()（[SWS_KeyM_00053]、[SWS_KeyM_00070]）。KeyM_CryptoKeyFinalizeCallbackNotification()报告是否所有密钥均已成功验证（[SWS_KeyM_00079]、[SWS_KeyM_00080]）。

在会话之外，KeyM_Verify()以同步或异步方式验证密钥[SWS_KeyM_00054]。当 KeyMCryptoKeyVerifyAsyncMode = TRUE 时，结果通过 KeyM_CryptoKeyVerifyCallbackNotification() 返回（[SWS_KeyM_00081]、[SWS_KeyM_00151]）。可以通过 KeyM_KH_Verify() 集成 Key Handler [SWS_KeyM_00071]。

时序图：会话从 Start 经 Prepare 以及异步 Update 运行至 Finalize；Key Handler 是可选的，结果通过回调返回。来源：SWS KeyM 第25页、SWS KeyM 第116页、[SWS_KeyM_00052]、[SWS_KeyM_00075]、[SWS_KeyM_00079]

KeyM_Update 详解：密钥选择与 Key Handler 循环

首先，KeyM 确定目标密钥：

  • KeyM 使用密钥名称查找具有匹配 KeyMCryptoKeyName 的 KeyMCryptoKey 容器[SWS_KeyM_00091]。
  • 在没有有效名称且定义了 KeyMCryptoKeyCryptoProps 的情况下，KeyM 将 RequestData 解释为 SHE 值 M1M2M3，并比对位 121..124 [SWS_KeyM_00154]。
  • 如果无法确定 KeyID 且没有激活 Update-Key-Handler，则调用以 KEYM_E_PARAMETER_MISMATCH 结束[SWS_KeyM_00155]。

在配置了 KeyMCryptoKeyHandlerUpdateEnabled 的情况下，KeyM_Update()调用函数 KeyM_KH_Update()。它传递请求数据、名称以及找到的 KeymId，否则传递 0xFFFFFFFFul [SWS_KeyM_00092]。为此，KeyM 提供一个内部缓冲区，在 Handler 返回之前不对其进行修改[SWS_KeyM_00097]。Handler 的反馈控制后续流程[SWS_KeyM_00055]：

  • 带数据的 KEYM_KH_UPDATE_KEY_UPDATE_REPEAT：KeyM 将密钥存储在 CSM 中或在其中派生密钥，并再次调用 Handler [SWS_KeyM_00096]。
  • KEYM_KH_UPDATE_FINISH：KeyM 复制结果数据并触发更新回调[SWS_KeyM_00093]。

KeyM 是存储还是派生，由 KeyMCryptoKeyGenerationType 确定，其取值为 KEYM_STORED_KEY 或 KEYM_DERIVED_KEY（SWS KeyM 第164页）。派生时，Csm_KeyDerive取代对 Csm_KeyElementSet 的调用（SWS KeyM 第118页）。在两种情况下，Csm_KeySetValid随后都会释放密钥（SWS KeyM 第116页）。

活动图：KeyM_Update 通过名称或 SHE 标识符选择密钥，在没有 KeyID 且没有 Key Handler 时中止，并重复调用 Key Handler 直至 KEYM_KH_UPDATE_FINISH。来源：[SWS_KeyM_00091]、[SWS_KeyM_00154]、[SWS_KeyM_00155]、[SWS_KeyM_00092]、[SWS_KeyM_00096]、[SWS_KeyM_00093]

证书：持久与临时存储、层级与状态

对于持久存储的证书，提供了 KeyM_ServiceCertificate()。当设置了 KeyMServiceCertificateFunctionEnabled 和 KeyMCertificateManagerEnabled 时，证书子模块提供该函数；它由 Key Master 调用[SWS_KeyM_00021]。KeyM_ServiceCertificateType区分以下服务[SWS_KeyM_00039]：

  • 请求 CSR 并返回已签名的 CSR，
  • 设置或更新根证书与中间证书，
  • 提供或更新 CRL。

该服务异步运行并通过 KeyM_ServiceCertificateCallbackNotification() 报告（[SWS_KeyM_00056]、[SWS_KeyM_00149]、[SWS_KeyM_00152]）。安装或更新根证书或中间证书的尝试被定义为安全事件（[SWS_KeyM_00172]、SWS KeyM 第38页）。

时序图：引入根证书或中间证书时，首先进行解析和验证；仅在验证成功后才存入 NvM 或 CSM，随后是服务回调。来源：SWS KeyM 第120页、[SWS_KeyM_00039]、[SWS_KeyM_00056]、[SWS_KeyM_00149]、[SWS_KeyM_00172]

与此相对，调用者通过 KeyM_SetCertificate() 临时传递出示的证书[SWS_KeyM_00057]。它存入配置的 KeyMCertificateStorage（通常在 RAM 中），并非用于持久保存（SWS KeyM 第31页）。数据在 KeyM_CertDataType 中连同长度和指针一起传递[SWS_KeyM_00041]。证书链本身是静态配置的。每个 KeyMCertificate 指向其上级证书，根证书指向其自身。此外，每个证书都引用一个 CSM 作业和一个 CSM 密钥以进行签名验证（SWS KeyM 第22页）。

结构图：在三级证书链中，每个 KeyMCertificate 指向其上级证书（根证书指向自身），并指向用于签名验证的 CSM 作业和 CSM 密钥。来源：SWS KeyM 第22页、SWS KeyM 第31页、[SWS_KeyM_00170]

每个证书都有一个类型为 KeyM_CertificateStatusType 的状态[SWS_KeyM_91003]，KeyM_CertGetStatus()对其进行查询[SWS_KeyM_00066]。生命周期：

  • 在 KeyM_Init() 之后，状态为 KEYM_CERTIFICATE_NOT_AVAILABLE。
  • certDataLength = 0 的 KeyM_SetCertificate() 会重置证书和状态（SWS KeyM 第34页）。
  • 已设置的数据经历解析（NOT_PARSED → PARSED_NOT_VALIDATED），随后进行验证（SWS KeyM 第24页）。
  • 仅在无错验证之后，KeyM 才通过 Csm_KeySetValid() 释放公钥并设置 KEYM_CERTIFICATE_VALID [SWS_KeyM_00170]。

解读：KEYM_E_CERTIFICATE_INVALID_CONTENT应属于解析错误，而 KEYM_E_CERTIFICATE_REVOKED 应属于验证错误。这仅针对 INVALID_FORMAT 和 INVALID_TYPE 有明确证明（SWS KeyM 第33页）。

状态图：证书从 NOT_AVAILABLE 经解析进入 PARSED_NOT_VALIDATED，并在成功验证后进入 VALID；错误会导致进入错误状态，长度为 0 的重置会导致返回初始状态。INVALID_CONTENT 和 REVOKED 的归类属于一种解读。来源：SWS KeyM 第24页、[SWS_KeyM_91003]、[SWS_KeyM_00170]、SWS KeyM 第34页

证书验证与证书内容访问

对于验证，有三个异步、非重入的作业：

  • KeyM_VerifyCertificate()自行确定关联的证书链（[SWS_KeyM_00060]、SWS KeyM 第68页）。
  • KeyM_VerifyCertificates()针对上级证书验证下级证书[SWS_KeyM_00059]。
  • KeyM_VerifyCertificateChain()接收按 PKI 顺序排序的证书列表[SWS_KeyM_00061]。

如果 KeyM 以 E_OK 接受了作业且配置了 KeyMCertificateVerifyCallbackNotificationFunc，则回调将结果报告为 KeyM_CertificateStatusType（[SWS_KeyM_00153]、[SWS_KeyM_00073]）。如果该函数为 NULL，则改为提供 Required Port KeyMCertificateNotification [SWS_KeyM_00161]。根据后续版本现有的 DCM 文档出处，DCM 使用此途径进行身份验证（SWS DCM 第147页、SWS DCM 第245页）。

时序图：设置并解析工作证书；随后的验证使用 StbM 时间、Subject 验证和 CSM 签名验证，并以密钥释放和回调结束。来源：SWS KeyM 第119页、[SWS_KeyM_00057]、[SWS_KeyM_00060]、[SWS_KeyM_00170]、[SWS_KeyM_00153]

对于证书内容的访问，提供了多个函数：

  • KeyM_GetCertificate()将证书数据提供到调用者的缓冲区中[SWS_KeyM_00058]。TcpIp 的 TLS 流程使用该函数（SWS TcpIp 第134页）。
  • KeyM_CertElementGet()通过对象 ID 从已解析且已验证的证书中读取配置的元素（[SWS_KeyM_00063]、[SWS_KeyM_00127]）。
  • 对于具有多重值的元素，调用者使用 KeyM_CertElementGetFirst() 和 KeyM_CertElementGetNext() 以及自行维护的迭代器进行遍历（[SWS_KeyM_00064]、[SWS_KeyM_00065]、[SWS_KeyM_00042]）。这仅适用于带有 KeyMCertificateElementHasIteration 的元素[SWS_KeyM_00148]。
  • 或者，KeyM_CertificateElementGetCount()和 KeyM_CertificateElementGetByIndex() 提供数量以及针对性的单个条目（[SWS_KeyM_91015]、[SWS_KeyM_91014]）。

通过迭代，DCM 从证书中读取白名单（SWS DCM 第155页）。

发生错误时的行为

在启用开发错误检测时，KeyM 在每次调用时检查：

  • 初始化状态（KEYM_E_UNINIT）[SWS_KeyM_00144]，
  • 结果缓冲区的大小（KEYM_E_SMALL_BUFFER）[SWS_KeyM_00145]，
  • 空指针（KEYM_E_PARAM_POINTER）[SWS_KeyM_00146]。

其他开发错误包括 KEYM_E_INIT_FAILED 和 KEYM_E_CONFIG_FAILURE [SWS_KeyM_00036]。如果证书的存储类为 KEYM_STORAGE_IN_CSM 或 KEYM_STORAGE_IN_NVM，KeyM 报告 KEYM_E_CONFIG_FAILURE；在非开发模式下返回 E_NOT_OK [SWS_KeyM_00166]。解读：这大概涉及通过 KeyM_SetCertificate() 进行的临时存储途径，根据文档出处该途径是为 RAM 设计的（SWS KeyM 第31页）。

运行时错误发生在三个层级：

  • 同步返回值使用诸如 KEYM_E_BUSY、KEYM_E_PENDING、KEYM_E_KEY_CERT_SIZE_MISMATCH 或 KEYM_E_PARAMETER_MISMATCH 等 KeyM 代码[SWS_KeyM_00040]。验证作业在接收时就拒绝空证书槽（KEYM_E_KEY_CERT_EMPTY）和无效的上级证书（KEYM_E_CERT_INVALID_CHAIN_OF_TRUST）（[SWS_KeyM_00060]、SWS KeyM 第68页）。
  • 异步密钥与证书服务将它们的结果报告为 KeyM_ResultType，例如 KEYM_RT_KEY_CERT_WRITE_FAIL 或 KEYM_RT_CERT_INVALID_CHAIN_OF_TRUST [SWS_KeyM_91008]。
  • 验证结果带有诸如有效期限错误、签名错误或信任链错误等错误状态[SWS_KeyM_91003]。失败的证书链验证还会作为安全事件 KEYM_SEV_CERT_VERIF_FAILED 进行报告[SWS_KeyM_00172]。
