Default Error Tracer 的角色及其系统边界

Default Error Tracer (DET) 在 Classic 协议栈中集中接收错误报告。它提供三种报告服务。Det_ReportError 用于开发错误 [SWS_Det_00009]，Det_ReportRuntimeError 用于运行时错误 [SWS_Det_01001]。对于瞬态错误，R20-11 中还有 Det_ReportTransientFault [SWS_Det_01003]。此外还有管理服务 Det_Init、Det_Start 和 Det_GetVersionInfo [SWS_Det_00008] [SWS_Det_00010] [SWS_Det_00011]。所有服务均可通过 Det.h 获取。

DET 本身不从业务层面评估报告。它将报告分发至配置的 Error Hook 和 Callout (SWS DET 第16页)。根据适用于 R20-11 的错误描述，它以此通过特定于集成商的代码访问 DEM 和 RTE (ErrorDescription 第10页)。此外，还规定通过 Dlt_DetForwardErrorTrace 可选转发至 Dlt [SWS_Det_00211]。

上下文图：DET 位于报告模块和集成商代码之间。通向 DEM 和 Dlt 的路径仅通过配置和 Callout 打开。来源：SWS DET Abb. Interfaces 第28页、ErrorDescription 第10页、[SWS_Det_00211]

启动：EcuM 启动流程中的 Det_Init 与 Det_Start

EcuM 在其可选接口中列出了 Det_Init 和 Det_ReportError（SWS EcuM 第142页）。Det_Init 的服务 ID 为 0x00，且是同步且不可重入的。参数 ConfigPtr 指向所选的配置集 [SWS_Det_00008]。其类型 Det_ConfigType 的结构取决于具体实现 [SWS_Det_00210]。Det_Start (0x02) 启动跟踪器，同样是同步且不可重入的 [SWS_Det_00010]。

根据初始化示意图，EcuM 首先调用 Det_Init，随后调用 Det_Start（SWS DET Abb. Initialisierung 第32页）。在这两次调用之间有哪些服务已经起作用，源文档未作规定。该点在此保留未定。Det_GetVersionInfo (0x03) 是可重入的，并将版本信息写入所传入的指针 [SWS_Det_00011]。

时序图：EcuM 使用配置集初始化 DET 并在此后启动它。只有在此之后，才会在运行期间进行报告。来源：SWS DET Abb. Initialisierung 第32页、[SWS_Det_00008]、[SWS_Det_00010]

具有统一编号方案的三条报告路径

所有三个报告服务都具有相同的参数：ModuleId (uint16)、InstanceId、ApiId 以及 ErrorId 或 FaultId（各为 uint8）[SWS_Det_00009] [SWS_Det_01001] [SWS_Det_01003]。

  • ModuleId 源自基础软件模块列表。BSW 仅使用 0..255 的范围。
  • InstanceId 从 0 开始计数。仅具有一个实例的模块传递 0。
  • ApiId 和 ErrorId 由报告模块的 SWS (EXP LSA 第157页) 定义。

适用哪个服务取决于错误类型：

  • BSW 模块通过带其模块标识符的 Det_ReportError 报告开发错误。这仅在配置了开发错误检测时才适用 (SWS BSWGeneral 第57页)。典型的做法是诸如 #if (SPI_DEV_ERROR_DETECT == ON) 之类的查询 (EXP LSA 第113页)。一个示例是 CanIf 中的无效参数 (SWS CanIf 第101页)。
  • 诸如 ADC_E_BUSY 之类的运行时错误通过 Det_ReportRuntimeError 处理 (SWS Adc 第95页)。
  • 瞬态错误通过瞬态故障服务 (SWS BSWGeneral 第53页) 处理。

模块在其模块描述中将此需求声明为 ErrorTracerNeeds。这三个服务中的每一个在其中都是可选角色 (TPS BSWMDT 第266页)。

版本说明：Det_ReportTransientFault 在 R20-11 中是规范性的 [SWS_Det_01003]。后续版本将该服务列为已废弃 (SWS DET 第24页)。在 R24-11 中，瞬态错误已被完全移除 (SWS DET 第1页)。

活动图：错误类型决定了报告服务、所调用的 Hook 或 Callout 列表以及对报告者的影响。来源：SWS BSWGeneral 第57页、[SWS_Det_00501]、[SWS_Det_00009]

分发至 Error Hook 和 Callout

Det_ReportError 的每次调用都会调用在 DetErrorHook 中配置的所有函数 [SWS_Det_00501]。这些 Hook 接收与原始调用相同的参数 (SWS DET 第16页)。Hook 接口 <User_Error_Hooks> 的服务 ID 为 0x10，并且是同步且可重入的 [SWS_Det_00181]。它始终返回 E_OK (SWS DET 第25页)。

时序图：Det_ReportError 依次调用所有已配置的 Hook，可选地也调用 Dlt。在 R20-11 中，该服务不会返回给报告者。来源：SWS DET Abb. ReportError 第36页、[SWS_Det_00501]、[SWS_Det_00009]、SWS Dlt 第25页

对于 Det_ReportRuntimeError，列表 DetReportRuntimeErrorCallout 适用相同的原则 [SWS_Det_00501]。Callout <DetReportRuntimeErrorCallout> 的服务 ID 为 0x11 [SWS_Det_00184]。DET 向报告者返回 E_OK (SWS DET Abb. Runtime mit Hook 第35页)。如果未配置 Callout，则它立即以 E_OK 响应 (SWS DET Abb. Runtime ohne Hook 第35页)。

时序图：对于运行时错误，无论是否配置了 Callout，返回值均为 E_OK。来源：SWS DET Abb. Runtime mit Hook 第35页、SWS DET Abb. Runtime ohne Hook 第35页、[SWS_Det_00184]

DET 将瞬态错误分发到列表 DetReportTransientFaultCallout [SWS_Det_00501]。该 Callout 的服务 ID 为 0x12 [SWS_Det_00187]。与运行时错误不同，DET 在此处将 Callout 的返回值传递给报告者。如果没有 Callout，它将返回 E_OK (SWS DET Abb. Transient mit Hook 第36页、SWS DET Abb. Transient ohne Hook 第36页)。后续版本针对多个 Callout 规定了返回值的逻辑或 (SWS DET 第24页)。推测该规则在 R20-11 中就已适用。

时序图：对于瞬态错误，Callout 的结果决定了对报告者的返回值。来源：SWS DET Abb. Transient mit Hook 第36页、SWS DET Abb. Transient ohne Hook 第36页、[SWS_Det_00187]

通过服务端口 DETService 连接 SW-C

SW-C 通过 RTE 访问 DET。对于每个已配置的模块实例，DET 提供一个带有接口 DETService 的端口 Det_{Name} [SWS_Det_00205]。操作 ReportError 和 ReportRuntimeError 使用该端口的模块标识符调用 C-API [SWS_Det_00202]。所需的类型 uint8 和 uint16 是 AUTOSAR 数据类型 [SWS_Det_00200]。

ModuleId 和 InstanceId 并非由 SW-C 本身传递。RTE 将它们作为“port defined argument values”进行补充 [SWS_Det_00203] [SWS_Det_00204]。因此它们的设定属于 RTE 配置 [SWS_Det_00206]。ApiId 和 ErrorId 对于 SW-C 而言未进行标准化，取值范围在 0x00..0xFF 之间 [SWS_Det_00203]。

协作图：每个 SW-C 实例都有自己的 DET 端口。RTE 在此补充标识符。来源：SWS DET Abb. Service-Ports 第33页、[SWS_Det_00205]、[SWS_Det_00206]

Hook 列表和 Callout 签名的配置

通知在容器 DetNotification (0..1) 中进行配置。它包含列表 DetErrorHook 和 DetReportRuntimeErrorCallout（各为 0..*）。在当前的后续版本中，它们的配置类为 Pre-compile (SWS DET 第37页)。R20-11 还额外包含列表 DetReportTransientFaultCallout [SWS_Det_00501]。Hook 必须具有与 Det_ReportError 相同的类型，即 Std_ReturnType (*f)(uint16, uint8, uint8, uint8)。

通常，Callout 具有与相关函数相同的签名。针对同一服务的多个 Callout 具有相同的 ID (SWS DET 第25页)。R20-11 的错误描述限制了此类处理程序允许执行的操作：存储事件、调用 DEM 或执行简短、恰当的操作 (ErrorDescription 第10页)。所有三个 Callout 接口均被指定为可重入的 [SWS_Det_00181] [SWS_Det_00184] [SWS_Det_00187]。

发生错误时的行为

在 R20-11 中，对于 Det_ReportError，Sync/Async 下标有“Not Applicable: The function never returns”[SWS_Det_00009]。因此，开发错误被当作断言处理。在 Hook 之后，正常控制流不再继续，例如通过死循环或停机。如果仅配置了一个 Hook，则该 Hook 可以接管异常处理 (RS BSWGeneral 第33页)。

流程图与此有所不同：它显示了一个返回箭头，并将该行为称为实现相关的 (SWS DET Abb. ReportError 第36页)。直到 R21-11 才阐明了调用行为 (SWS DET 第1页)。对于 R20-11，以该需求为准。

对于运行时错误，报告者会继续运行，因为 Det_ReportRuntimeError 始终返回 E_OK [SWS_Det_01001] (SWS DET 第23页)。对于瞬态错误，报告者接收 Callout 的结果作为返回值 [SWS_Det_01003] (SWS DET Abb. Transient mit Hook 第36页)。

DET 本身仅具有一个自身的开发错误：DET_E_PARAM_POINTER (0x01)。当使用空指针调用 Det_GetVersionInfo 时会发生该错误 [SWS_Det_00301]。DET 将此错误报告给在 Callout 中配置的所有函数。运行时错误和生产错误不适用于 DET (SWS DET 第18页)。

函数 Det_ReportError 作为 Default Error Tracer (DET) 的核心服务，用于报告开发错误（[SWS_Det_00009]）。该接口可通过头文件 Det.h 使用。

用法与参数

BSW 模块在检测到开发错误时调用该服务，并传递精确的错误上下文（[SWS_Det_00009]）：

  • ModuleId：调用方软件模块的模块标识符。
  • InstanceId：模块的基于索引的实例 ID（从 0 开始；仅具有一个实例的模块传递 0）。
  • ApiId：发生错误的 API 服务标识符。
  • ErrorId：根据调用方模块的规范定义的特定开发错误标识符。

形式上，该函数具有返回类型 Std_ReturnType，但并不返回任何值，具有该类型仅用于与服务和钩子保持兼容（[SWS_Det_00009]）。同步或异步语义的分类不适用，因为根据规范，Det_ReportError 绝不返回给调用者（[SWS_Det_00009]）。

并发性与流程

该函数被指定为可重入的（[SWS_Det_00009]）。在调用 Det_ReportError 时，DET 会执行在参数 DetErrorHook 中配置的所有回调函数（[SWS_Det_00501]）。

相互作用

其他 BSW 模块直接向该服务报告参数错误。例如，CAN 接口在 CanIf_SetTrcvMode() 或 CanIf_SetTrcvWakeupMode() 中的参数 TransceiverId 无效时报告错误代码 CANIF_E_PARAM_TRCV（[SWS_CANIF_00538], CAN Interface §8.3 “CanIf_SetTrcvMode”；[SWS_CANIF_00535], CAN Interface §8.3 “CanIf_SetTrcvWakeupMode”）。在模式参数不允许时，CanIf_SetTrcvWakeupMode() 相应地向 Det_ReportError 报告 CANIF_E_PARAM_TRCVWAKEUPMODE（[SWS_CANIF_00536], CAN Interface §8.3 “CanIf_SetTrcvWakeupMode”）。

本使用说明基于 AUTOSAR 版本 R20-11 的规范。

使用与签名

同步服务 Det_ReportRuntimeError（[SWS_Det_01001]）用于向 Default Error Tracer (DET) 报告运行时错误，并通过头文件 Det.h 提供。该函数具有以下参数：

  • ModuleId：调用方模块的模块标识符。
  • InstanceId：模块的基于索引的实例 ID（对于单实例模块为 0）。
  • ApiId：检测到错误的 API 服务标识符。
  • ErrorId：检测到的运行时错误的特定标识符（在调用方模块的规范中定义）。

返回值始终为 E_OK（[SWS_Det_01001]）。

并发性与行为

该接口定义为可重入的（[SWS_Det_01001]）。在调用 Det_ReportRuntimeError 时，将调用在 DetReportRuntimeErrorCallout 中配置的所有回调函数（[SWS_Det_00503]）。

协同交互与错误上下文

调用方模块使用该服务在运行时报告特定错误状态。例如，模块 CanIf 在通过处于模式 CANIF_OFFLINE 的通道发出发送请求时，向 Det_ReportRuntimeError 报告错误代码 CANIF_E_STOPPED（[SWS_CANIF_00382], AUTOSAR_SWS_CANInterface 第40页 §7.10 “Transmit data flow”）。另一个使用场景是在 CanIf_Transmit() 中禁用截断时超出全局 PDU 长度，这会触发运行时错误 CANIF_E_TXPDU_LENGTH_EXCEEDED 的报告（[SWS_CANIF_00900], AUTOSAR_SWS_CANInterface 第81页 §8.3.7 “CanIf_ReadRxPduData”）。

本使用说明基于 AUTOSAR Classic Release R20-11 规范。

用法与语义

根据 [SWS_Det_01003]，函数 Det_ReportTransientFault 用于向 Default Error Tracer 报告瞬态故障。该服务以同步方式执行，并被指定为可重入。声明通过 Det.h 提供。

传入参数包括：

  • ModuleId：调用方软件模块的模块标识符。
  • InstanceId：模块基于索引的实例 ID（从 0 开始；单实例模块始终传入 0）。
  • ApiId：发生瞬态故障的 API 服务标识符。
  • FaultId：所检测到的各个瞬态故障的标识符。

交互与 Callout 行为

调用 Det_ReportTransientFault 时，将根据 [SWS_Det_00502] 调用在 DetReportTransientFaultCallout 下配置的所有回调函数。

根据 [SWS_Det_01003]，类型为 Std_ReturnType 的返回值适用以下语义：

  • 若未配置 Callout，则立即返回 E_OK。
  • 若存在 Callout，则返回该已配置 Callout 的返回值。
  • 若设置了多个 Callout，则返回所有 Callout 返回值的逻辑或运算结果（总和）。由于定义了 E_OK = 0，仅当所有被调用的 Callout 均无一例外地报告 E_OK 时，该服务才会返回 E_OK。

并发性与限制

基于所指定的可重入性（[SWS_Det_01003]），只要配置的 Callout 支持此行为，该接口即可由多个模块实例或任务并发调用。

本使用说明完全基于 AUTOSAR Classic R20-11 的规范内容。

使用

符合 [SWS_Det_00181] 的回调函数 <User_Error_Hooks> 用作用于通知 Default Error Tracer (DET) 中所发生开发错误的用户自定义钩子接口。它具有服务 ID 0x10，并通过头文件 Det_Externals.h 提供。

调用在报告错误的时刻同步进行。该接口接收以下参数：

  • ModuleId（uint16）：报告错误的软件模块的模块标识符。
  • InstanceId（uint8）：模块的基于索引的实例 ID（从 0 开始；对于单一实例模块应传递 0）。
  • ApiId（uint8）：检测到错误的 API 服务的标识符（根据源模块的规范）。
  • ErrorId（uint8）：检测到的开发错误的标识符（根据源模块的规范）。

返回值与错误处理

该函数作为类型为 Std_ReturnType 的返回值始终返回 E_OK [SWS_Det_00181]。不支持自定义错误状态或不同的返回值；根据规范，在该接口上未规定向 Diagnostic Event Manager (DEM) 进行内部转发或生成单独的错误日志。

并发性与限制

根据 [SWS_Det_00181]，该函数定义为可重入的。由于处理是同步进行的，用户自定义钩子实现应设计为非阻塞的，以免不当延迟调用方组件的执行时间。
