集中接收基础软件和 SW-C 的错误报告，并将其转发给集成商 Hook。

Default Error Tracer 集中接收来自 BSW 模块和 SW-C 的错误报告。为此提供了用于开发错误的 Det_ReportError、用于运行时错误的 Det_ReportRuntimeError 以及用于瞬态错误的 Det_ReportTransientFault，各自带有模块、实例、API 和错误标识。DET 将每条报告转发给集成商的所有已配置 Hook 或 Callout [SWS_Det_00501]。从 EcuM 中通过 Det_Init 和 Det_Start 启动运行。最重要的边界条件：Det_ReportError 在 R20-11 中不会返回给调用方，而是像断言一样停止程序流 [SWS_Det_00009]。

Default Error Tracer 是来自基础软件和软件组件的错误报告的中央收集点。它提供了三个结构相同的报告服务，带有参数 ModuleId、InstanceId、ApiId 以及 ErrorId 或 FaultId：用于开发错误的 Det_ReportError、用于运行时错误的 Det_ReportRuntimeError 以及用于瞬态错误的 Det_ReportTransientFault（[SWS_Det_00009]、[SWS_Det_01001]、[SWS_Det_01003]）。EcuM 通过 Det_Init 以及随后的 Det_Start 使 DET 投入运行（[SWS_Det_00008]、SWS DET 图 1 第34页）。

上下文图：DET 接收来自 BSW 模块和 SW-C 的报告，并将其转发给集成商 Hook 以及可选地转发给 Dlt。来源：SWS DET 图 2 第28页、[SWS_Det_00202]

DET 本身不对报告进行评估。每个报告服务都会调用为其配置的所有 Hook 或 Callout（DetErrorHook、DetReportRuntimeErrorCallout、DetReportTransientFaultCallout），且所使用的参数与报告的参数相同 [SWS_Det_00501]。通过这些集成商代码，DET 也能访问 DEM 或错误存储器。在此过程中，Callout 应限制在简短、适当的操作范围内 ErrorDescription 第10页。

SW-C 通过客户端-服务器接口 DETService 进行报告。RTE 从 DET 配置中补充 ModuleId 和 InstanceId 作为“port defined argument values”，SW-C 始终收到返回值 E_OK（[SWS_Det_00203]、[SWS_Det_00204]）。

对于错误情况，这三个服务如何返回至关重要。Det_ReportError 在 R20-11 中不会返回：在执行 Hook 之后，控制流将被停止，就像断言一样（[SWS_Det_00009]、RS BSWGeneral 第33页）。相反，运行时报告返回 E_OK。瞬态报告传递 Callout 值，没有 Callout 时返回 E_OK SWS DET 图 6 第36页。瞬态错误自 R24-11 起被取消，Dlt 调用自 R25-11 起被取消 SWS DET 第1页。

时序图：发生开发错误时，DET 调用所有已配置的 Hook，随后停止运行，而不返回给报告方。来源：SWS DET 图 9.2 第34页、[SWS_Det_00009]

Default Error Tracer 在系统边界的作用

Default Error Tracer（DET）是基础软件模块和软件组件报告已检测到错误的中央收集点。在 R20-11 中，它为此提供了三个结构相同的报告服务：用于开发错误的 Det_ReportError [SWS_Det_00009]、用于运行时错误的 Det_ReportRuntimeError [SWS_Det_01001] 以及用于瞬态错误的 Det_ReportTransientFault [SWS_Det_01003]。此外还包括管理服务 Det_Init、Det_Start 和 Det_GetVersionInfo（[SWS_Det_00008]、[SWS_Det_00010]、[SWS_Det_00011]）。DET 本身不对报告内容进行评估。它通过收到的每条报告通知已配置的错误 Hook SWS DET 第16页。

对外而言，DET 的连接十分狭窄。作为唯一预期的接口，规范提及了通过来自 Dlt_Det.h 的 Dlt_DetForwardErrorTrace 可选转发给 Dlt（[SWS_Det_00211]、SWS DET 图 2 第28页）。DET 仅能通过 Callout 中的集成商特定代码访问 DEM 和 RTE ErrorDescription 第10页。

上下文图：DET 接收来自 BSW 模块的报告，并通过 RTE 接收来自 SW-C 的报告。它由 EcuM 启动，并仅将报告转发给已配置的集成商代码以及可选地转发给 Dlt。来源：SWS DET 图 2 第28页、[SWS_Det_00202]、[SWS_Det_00211]、ErrorDescription 第10页

启动：由 EcuM 进行初始化和启动

ECU State Manager 使用 Det_Init（Service-ID 0x00）初始化 DET。在此过程中，它传递一个指向所选配置集的指针，类型为 Det_ConfigType，其内容因实现而异（[SWS_Det_00008]、[SWS_Det_00210]）。随后，Det_Start（Service-ID 0x02）启动 Tracer [SWS_Det_00010]。两个服务都是同步且不可重入的。R20-11 图表显示了来自 EcuM 的先后两次调用 SWS DET 图 1 第34页。EcuM 相应地将 Det_Init 和 Det_ReportError 列为可选接口 SWS EcuM 第142页。

规范并未解释为何将初始化与启动分开。Interpretation：这种两阶段划分大概允许在启动过程中非常早期地初始化 DET，而仅在稍后的步骤中才启用常规操作 [SWS_Det_00010]。 问题 Q-fee4462bdf189dcf (未决)

时序图：EcuM 首先同步调用带有配置指针的 Det_Init，然后调用 Det_Start。来源：SWS DET 图 1 第34页、[SWS_Det_00008]、[SWS_Det_00010]

三种报告途径及其标识

所有三个报告服务具有相同的参数结构：

  • ModuleId（uint16）；
  • InstanceId（uint8），对于单实例模块，该值为 0；
  • ApiId（uint8）；
  • ErrorId 或 FaultId（uint8）。

API 标识和错误标识分别由报告模块的 SWS 确定（[SWS_Det_00009]、[SWS_Det_01001]、[SWS_Det_01003]）。模块 ID 来自基础软件模块列表。基础软件仅使用其中的 0..255 范围 EXP LSA 第157页。

哪种途径正确取决于错误分类。违反基本前置条件属于开发错误，并被当作断言处理；例如软件错误、不正确的集成或无效配置。其余错误属于运行时错误或生产错误 EXP LSA 第154页。如果配置了开发错误检测，BSW 模块将带有其分配的模块 ID 通过 Det_ReportError 报告开发错误 SWS BSWGeneral 第57页。诸如 SPI_DEV_ERROR_DETECT 等预处理器开关可启用或禁用该调用 EXP LSA 第113页。

活动图：如果违反了基本前置条件，则通过 Det_ReportError 报告开发错误。否则，诊断相关性在生产错误和运行时错误之间做出决定（Det_ReportRuntimeError）。来源：EXP LSA 第154页、[SWS_Det_00009]、[SWS_Det_01001]

例如 ADC 驱动程序使用 ADC_E_BUSY 报告运行时错误，或者 Dds 在消息被丢弃时报告运行时错误，分别通过 Det_ReportRuntimeError（SWS Adc 第95页、SWS Dds 第53页）。BSW 模块使用 ServiceNeeds 类型 ErrorTracerNeeds 描述其需求。它包含角色 Det_ReportError、Det_ReportRuntimeError 和 Det_ReportTransientFault TPS BSWMDT 第266页。

Hook 和 Callout 作为通向集成商代码的桥梁

对 Det_ReportError 的每次调用都会调用在 DetErrorHook 中配置的所有函数。同样，Det_ReportRuntimeError 和 Det_ReportTransientFault 分别调用来自 DetReportRuntimeErrorCallout 或 DetReportTransientFaultCallout 的所有 Callout [SWS_Det_00501]。Hook 和 Callout 具有触发服务的签名，并接收相同的参数（[SWS_Det_00181]、[SWS_Det_00184]、[SWS_Det_00187]、SWS DET 第16页）。Hook 接口 <User_Error_Hooks> 的 Service-ID 为 0x10。它是同步且可重入的，并始终返回 E_OK SWS DET 第25页。

Callout 执行什么操作由集成商决定。对于运行时错误和瞬态错误，它们应限制在少数操作中：保存事件、调用 DEM 或执行其他简短、适当的操作 ErrorDescription 第10页。在调用 Det_ReportRuntimeError 之后，无论是否配置了 Callout，DET 始终返回 E_OK（SWS DET 图 4 第35页、SWS DET 图 5 第35页）。

时序图：Det_ReportRuntimeError 调用所有已配置的 Callout，并无论如何都向报告方返回 E_OK。来源：SWS DET 图 4 第35页、SWS DET 图 5 第35页、[SWS_Det_00501]

相反，在 Det_ReportTransientFault 中，DET 将 Callout 的返回值透传给报告方。在没有 Callout 的情况下，它返回 E_OK（SWS DET 图 6 第36页、SWS DET 图 7 第36页）。对于多个 Callout，较新的版本描述了对返回值进行逻辑“或”运算：仅当所有 Callout 都返回 E_OK 时，才会返回 E_OK。该规则大概率在 R20-11 中就已适用 SWS DET 第24页。 问题 (未决)

通过服务端口连接软件组件

SW-C 通过客户端-服务器接口 DETService 访问 DET。其操作使用端口的模块 ID 调用 Det_ReportError 或运行时报告 [SWS_Det_00202]。SW-C 本身并不传递 ModuleId 和 InstanceId。RTE 将其作为“port defined argument values”进行补充，其值来自 DET 配置的 DetModuleId 和 DetInstanceId（[SWS_Det_00204]、[SWS_Det_00205]、[SWS_Det_00206]）。对于 SW-C，ApiId 和 ErrorId 未标准化，可在 0x00..0xFF 范围内自由分配。返回值始终为 E_OK [SWS_Det_00203]。端口接口使用 AUTOSAR 数据类型 uint8 和 uint16 [SWS_Det_00200]。

时序图：SW-C 仅传递 ApiId 和 ErrorId。RTE 从配置中补充 ModuleId 和 InstanceId，返回值为 E_OK。来源：[SWS_Det_00202]、[SWS_Det_00203]、[SWS_Det_00204]、SWS DET 图 3 第33页

通知的配置

通知函数位于可选容器 DetNotification（多重性 0..1）中。它包含列表 DetErrorHook 和 DetReportRuntimeErrorCallout（各为 0..*）。DetErrorHook 在预编译期配置，并要求函数类型 Std_ReturnType (*f)(uint16, uint8, uint8, uint8) SWS DET 第37页。在 R20-11 中增加了 DetReportTransientFaultCallout [SWS_Det_00501]。参数图表还显示了包含 DetVersionInfoApi 和 DetForwardToDlt 的必选容器 DetGeneral SWS DET (alt) 图 6 第43页。配置从 DetConfigSet/DetModule 和 DetModuleInstance 构建端口 Det_{Name} 以及模块和实例标识 [SWS_Det_00205]。

开发错误被当作断言处理。在调用已配置的 Hook 之后，正常的控制流不会继续，DET 会停止执行，例如通过死循环或挂起指令 RS BSWGeneral 第33页。这与 R20-11 中 Det_ReportError 在 Sync/Async 下的条目相匹配：“Not Applicable: The function never returns” [SWS_Det_00009]。图表显示了带有和不带有已配置 Hook 的这种 HALT（SWS DET 图 9.2 第34页、SWS DET 图 9.3 第35页）。
