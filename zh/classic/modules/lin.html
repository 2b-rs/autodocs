控制 LIN 硬件，并为 LIN Interface 提供针对每个通道的报文、睡眠状态和唤醒服务。

LIN 驱动程序封装微控制器的 LIN 硬件，并为 LIN Interface 提供与通道相关的报文、睡眠状态和唤醒服务。主节点通道使用 Lin_SendFrame 异步触发报文，并通过 Lin_GetStatus 对其进行评估。从节点通道通过向 LIN Interface 发送指示来响应每个接收到的报头，然后发送、接收或忽略响应（[SWS_Lin_00280]）。哪些服务可用取决于所配置的节点类型；主节点服务仅在至少存在一个主节点通道时才提供（[SWS_Lin_00287]）。

LIN 驱动程序 Lin 是 LIN 协议栈的硬件驱动程序。它封装 LIN 控制器或 SCI/UART（SWS LIN Driver 第9页），并为 LIN Interface 提供与通道相关的报文、睡眠状态和唤醒服务。它固定需要 Dem_SetEventStatus、EcuM_SetWakeupEvent 和 LinIf_WakeupConfirmation（[SWS_Lin_00234]）。可选使用 DET、Icu 以及 LinIf 的从节点回调（[SWS_Lin_00235]）。

上下文图：Lin 位于 LinIf 与 LIN 硬件之间，并向 EcuM、LinIf、DEM 和 DET 报告唤醒与错误。来源：[SWS_Lin_00234]、[SWS_Lin_00235]

Lin_Init 将模块从 LIN_UNINIT 迁移至 LIN_INIT（[SWS_Lin_00006]、SWS LIN Driver 第24页）。之后，每个通道在 LIN_CH_OPERATIONAL、LIN_CH_SLEEP_PENDING（仅主节点）和 LIN_CH_SLEEP 之间切换。为此提供了 Lin_GoToSleep、Lin_GoToSleepInternal、Lin_Wakeup 和 Lin_WakeupInternal（[SWS_Lin_00166]、[SWS_Lin_00167]、[SWS_Lin_00169]、[SWS_Lin_00256]）。

状态图：模块状态和通道状态及其转换。Lin_GetStatus 完成进入 LIN_CH_SLEEP 的步骤，是对图表的一种解释。来源：SWS LIN Driver 第24页、[SWS_Lin_00166]

主节点和从节点通道的工作方式截然不同。主节点使用 Lin_SendFrame 异步触发报文，随后使用 Lin_GetStatus 查询结果（[SWS_Lin_00191]、[SWS_Lin_00168]）。仅当至少一个通道配置为主节点时，才提供这些服务（[SWS_Lin_00287]）。从节点通过 LinIf_HeaderIndication 报告每个报头（[SWS_Lin_00280]）。取决于 Drc，它随后发送、接收或忽略响应，并使用 LinIf_TxConfirmation 或 LinIf_RxIndication 结束响应（[SWS_Lin_00282]、[SWS_Lin_00274]、[SWS_Lin_00275]）。

来自总线的唤醒由 Lin_CheckWakeup 检查并报告给 EcuM 和 LinIf（[SWS_Lin_00160]）。出现错误时，错误用法将报告给 DET，例如 LIN_E_UNINIT（[SWS_Lin_00258]）。硬件超时作为 LIN_E_TIMEOUT 报告给 DEM（[SWS_Lin_00290]）。主节点通道将总线错误作为状态返回，从节点通道则通过 LinIf_LinErrorIndication 报告总线错误（[SWS_Lin_00233]、[SWS_Lin_00277]）。

LIN 驱动程序的作用、系统边界和实例关联

LIN 驱动程序 Lin 封装微控制器的 LIN 硬件。它为 LIN Interface（LinIf）提供与通道相关的服务：发送和接收报文、使通道进入睡眠以及唤醒通道，以及检查唤醒。所有服务均可通过 Lin.h 获取（[SWS_Lin_00191]、[SWS_Lin_00160]）。规范中作为硬件提到了三种 LIN 硬件单元：功能完备的 LIN 控制器、简易 SCI/UART 和增强型 SCI/UART。它们分别通过收发器 IC 连接到 LIN 集群（SWS LIN Driver 第9页）。驱动程序本身不提供回调函数（SWS LIN Driver 第49页）。相反，它调用其周边环境的函数。

对外的强制接口为 Dem_SetEventStatus、EcuM_SetWakeupEvent 和 LinIf_WakeupConfirmation（[SWS_Lin_00234]）。驱动程序可选使用的接口除其他外包括：

  • Det_ReportError 和 EcuM_CheckWakeup，
  • Icu_EnableNotification 和 Icu_DisableNotification，
  • 用于从节点通道的回调 LinIf_HeaderIndication、LinIf_RxIndication 和 LinIf_LinErrorIndication（[SWS_Lin_00235]）。

诸如 NetworkHandleType、EcuM_WakeupSourceType 或 Std_ReturnType 等导入类型在 [SWS_Lin_00226] 中列出。

上下文图：Lin 位于 LinIf 与 LIN 硬件单元之间。驱动程序向 EcuM 和 LinIf 报告唤醒，向 DEM 和 DET 报告错误。来源：[SWS_Lin_00234]、[SWS_Lin_00235]、SWS LIN Driver 第9页

该驱动程序支持分区。它在每个分区中作为独立实例运行，且 API 调用仅影响发生该调用的分区（[SWS_Lin_CONSTR_00270]）。如果 LinEcucPartitionRef 引用了分区，则 LinChannelEcucPartitionRef 必须精确引用其中一个（[SWS_Lin_CONSTR_00291]）。通信通道的 LinChannel 和 LinTrcvChannel 必须引用同一分区（[SWS_Lin_CONSTR_00279]）。模块会拒绝实现不支持的分区分配（[SWS_Lin_00269]）。针对每个通道，除其他外还配置了波特率、通道 ID、LinChannelWakeupSupport 以及节点类型 LinNodeType。该容器描述源自后续 Release（SWS LIN Driver 第60页）。

从 Lin_Init 到睡眠状态的模块与通道状态

复位后，模块处于状态 LIN_UNINIT 且不可用。Lin_Init 将其转入 LIN_INIT；在其中每个可用通道均已准备好提供服务（SWS LIN Driver 第24页）。Lin_Init 接收指向 Lin_ConfigType 结构的指针。其内容特定于硬件；它包含驱动程序、硬件单元和通道的初始化数据（[SWS_Lin_00006]、[SWS_Lin_00227]）。运行环境中在运行时应对 Lin_Init 仅调用一次（SWS LIN Driver 第24页）。

在 LIN_INIT 内部，每个通道都有其自身的状态：

  • LIN_CH_OPERATIONAL：通道参与集群。
  • LIN_CH_SLEEP：唤醒检测处于激活状态，硬件视情况处于低功耗模式。
  • LIN_CH_SLEEP_PENDING：仅针对主节点通道，在 Lin_GoToSleep 之后。

证据：SWS LIN Driver 第24页、[SWS_Lin_00166]。Lin_GoToSleepInternal 将通道直接置为 LIN_CH_SLEEP（[SWS_Lin_00167]）。Lin_Wakeup 带有唤醒脉冲返回到 LIN_CH_OPERATIONAL，Lin_WakeupInternal 则不带脉冲（[SWS_Lin_00169]、[SWS_Lin_00256]）。

解释：从 LIN_CH_SLEEP_PENDING 到 LIN_CH_SLEEP 的转换大概由 Lin_GetStatus 完成。图表将 Lin_GetStatus 列为主节点部分的转换，且 LIN Interface 在检查 go-to-sleep 命令时期望返回值 LIN_CH_SLEEP（SWS LIN Interface 第56页）。

状态图：Lin_Init 将模块从 LIN_UNINIT 提升至 LIN_INIT。在其中，每个通道通过睡眠和唤醒服务在运行和睡眠之间切换；通过 Lin_GetStatus 的转换属于解释。来源：SWS LIN Driver 第24页、[SWS_Lin_00166]、[SWS_Lin_00167]、[SWS_Lin_00169]、[SWS_Lin_00256]

通过 Lin_PduType 的报文描述与数据映射

在 LinIf 与驱动程序之间，Lin_PduType 用于描述报文。该结构包含 Pid、校验和模型 Cs、响应方向 Drc、数据长度 Dl 以及数据指针 SduPtr（[SWS_Lin_00232]）。元素类型：

  • Lin_FramePidType：带两个奇偶校验位的标识符 0…0x3F，取值范围 0…0xFE（[SWS_Lin_00228]）。
  • Lin_FrameDlType：1…8 个数据字节（[SWS_Lin_00231]）。
  • Lin_FrameCsModelType：LIN_ENHANCED_CS 或 LIN_CLASSIC_CS（[SWS_Lin_00229]）。驱动程序必须能够计算这两种校验和（[SWS_Lin_00019]）。

Lin_FrameResponseType 确定节点如何处理响应（[SWS_Lin_00230]）：自行发送响应（LIN_FRAMERESPONSE_TX）、接收相关的外部响应（LIN_FRAMERESPONSE_RX）或忽略响应（LIN_FRAMERESPONSE_IGNORE）。在内存中，最先传输的字节位于元素 0 中，最后传输的字节位于元素 n-1 中（SWS LIN Driver 第30页）。如果硬件无法对字节进行缓冲（例如在简易 UART 的情况下），驱动程序将提供临时缓冲区。带回读检查的发送以及接收均以非阻塞方式运行（SWS LIN Driver 第28页）。

主节点通道：Lin_SendFrame 与状态查询

在主节点通道上，LinIf 使用异步 Lin_SendFrame 触发每个报文。该服务发送 LIN 报头，并视情况发送响应（[SWS_Lin_00191]）。这适用于调度表的接收、发送以及从节点到从节点（Slave-to-Slave）条目（SWS LIN Interface 第34页、SWS LIN Interface 第37页、SWS LIN Interface 第40页）。

LinIf 使用同步 Lin_GetStatus 查询结果：最早在最大报文长度之后，最迟在下一个到期的调度条目时（SWS LIN Interface 第35页、[SWS_Lin_00168]）。该服务返回 Lin_StatusType，例如 LIN_TX_OK、LIN_TX_BUSY、LIN_RX_OK、LIN_RX_BUSY 或 LIN_RX_NO_RESPONSE。通过 Lin_SduPtr，它还返回指向影子或硬件接收缓冲区的指针（[SWS_Lin_00233]）。

接收到的数据保持一致，直到成功接收到下一个报文或通道状态发生变化。完整的接收处理可以位于 Lin_GetStatus 中（SWS LIN Driver 第30页）。对于事件触发报文（Event-triggered Frame），适用以下规则（SWS LIN Interface 第127页、SWS LIN Interface 第129页）：

  • LIN_RX_NO_RESPONSE 不将 LinIf 视为错误。
  • LIN_RX_ERROR 被视为冲突，并导致切换到冲突解决调度表。

仅当至少一个通道通过 LinNodeType 配置为主节点时，才提供 Lin_SendFrame、Lin_GoToSleep 和 Lin_GetStatus（[SWS_Lin_00287]、[SWS_Lin_00288]、[SWS_Lin_00289]）。在 R20-11 中，这些服务被指定为不可重入（[SWS_Lin_00168]）。较后版本允许针对不同通道的可重入性（SWS LIN Driver 第48页）；对于 R20-11，该需求有效。

时序图：主节点使用 Lin_SendFrame 异步触发报文，并在后续 MainFunction 调用中通过 Lin_GetStatus 评估结果。来源：[SWS_Lin_00191]、[SWS_Lin_00168]、SWS LIN Interface 第128页、SWS LIN Interface 第129页、SWS LIN Interface 第40页

从节点通道：报头驱动的响应处理

从节点通道在 LIN_CH_OPERATIONAL 中必须能够随时接收报头（[SWS_Lin_00272]）。针对每个报头，驱动程序调用 LinIf_HeaderIndication。此时 PduPtr->Pid 包含接收到的 PID，且 PduPtr->SduPtr 指向其硬件或影子缓冲区（[SWS_Lin_00280]）。如果硬件无法识别无效 PID，驱动程序将未经检查直接传递 PID（[SWS_Lin_00271]）。在返回 E_OK 后，它评估 PduPtr->Drc（[SWS_Lin_00282]）：

  • 在 LIN_FRAMERESPONSE_TX 时，它使用 Cs、Dl 和 SduPtr 来发送响应（[SWS_Lin_00283]）。
  • 在 LIN_FRAMERESPONSE_RX 时，它使用 Cs 和 Dl 配置接收（[SWS_Lin_00284]）。

如果 LinIf_HeaderIndication 返回 E_NOT_OK 或 Drc 等于 LIN_FRAMERESPONSE_IGNORE，驱动程序将忽略响应（[SWS_Lin_00286]）。在下一个报头之前，它不报告任何内容（[SWS_Lin_00276]）。成功接收到的响应直接通过 LinIf_RxIndication 传递，已发送的响应通过 LinIf_TxConfirmation 确认（[SWS_Lin_00274]、[SWS_Lin_00275]）。每个相关响应必须在报告下一个报头之前通过这些回调之一或通过 LinIf_LinErrorIndication 完成（[SWS_Lin_00285]）。接收图表区分了两种硬件变体：硬件 LIN 控制器和简易 UART（其中驱动程序通过中断将每个字节复制到缓冲区中）（SWS LIN Driver 第57页）。

时序图：在从节点通道上，每个报头触发对 LinIf 的指示。取决于 Drc，驱动程序发送、接收或忽略响应。来源：[SWS_Lin_00280]、[SWS_Lin_00282]、[SWS_Lin_00283]、[SWS_Lin_00284]、[SWS_Lin_00286]、[SWS_Lin_00274]、[SWS_Lin_00275]、SWS LIN Interface 第121页、SWS LIN Interface 第132页

睡眠、唤醒与唤醒检测

仅主节点可以发送 go-to-sleep 命令。Lin_GoToSleep 按照 LIN 2.1 异步发送该命令，且即使在传输错误时也将通道置为 LIN_CH_SLEEP_PENDING。如果配置了 LinChannelWakeupSupport，该服务还会激活总线监控（[SWS_Lin_00166]、SWS LIN Driver 第43页）。对于从节点，Lin_GoToSleep 不适用；它们使用 Lin_GoToSleepInternal（SWS LIN Driver 第31页）。该服务同步设置 LIN_CH_SLEEP，激活唤醒检测，并可选地将硬件置于低功耗模式（[SWS_Lin_00167]、SWS LIN Driver 第44页）。每个通道独立于其余通道接受睡眠请求（SWS LIN Driver 第31页）。

提供了两个用于唤醒的服务。Lin_Wakeup 向总线发送唤醒脉冲，Lin_WakeupInternal 在不发送脉冲的情况下使通道投入运行（[SWS_Lin_00169]、[SWS_Lin_00262]）。来自总线的唤醒由 Lin_CheckWakeup 检查。如果该服务检测到事件（例如持续的低 RxD 电平），它将立即通过 EcuM_SetWakeupEvent 报告给 EcuM，并通过 LinIf_WakeupConfirmation 报告给 LinIf（[SWS_Lin_00160]、SWS LIN Driver 第42页）。LinIf_CheckWakeup 根据唤醒源决定是调用 Lin_CheckWakeup 还是 LinTrcv_CheckWakeup（SWS LIN Interface 第112页）。LIN 不需要唤醒验证（SWS EcuM 第173页）。

时序图：来自总线的唤醒经由 EcuM 和 LinIf_CheckWakeup 传递给 Lin_CheckWakeup。驱动程序将检测到的事件上报给 EcuM 和 LinIf。来源：[SWS_Lin_00160]、[SWS_Lin_00234]、SWS LIN Driver 第42页、SWS LIN Interface 第112页、SWS EcuM 第147页

发生错误时的行为

在开发错误检测使能时，各服务向 DET 上报错误使用（[SWS_Lin_00258]、[SWS_Lin_00259]、[SWS_Lin_00260]；针对 Lin_Wakeup 类似 SWS LIN Driver 第45页）：

  • 初始化前调用时报 LIN_E_UNINIT，
  • 通道无效或未激活时报 LIN_E_INVALID_CHANNEL，
  • 在 LIN_CH_SLEEP 之外发生唤醒时报 LIN_E_STATE_TRANSITION。

Lin_GetVersionInfo 通过 LIN_E_PARAM_POINTER 上报 NULL 指针（[SWS_Lin_00161]、SWS LIN Driver 第41页）。在 DET 禁用时，Lin_CheckWakeup 针对无效通道返回 E_NOT_OK（SWS LIN Driver 第42页）。通常，E_NOT_OK 和 LIN_NOT_OK 表示发生了开发错误或生产错误（[SWS_Lin_00191]、[SWS_Lin_00233]）。

LIN_E_TIMEOUT 被指定为生产错误。若在更改硬件控制寄存器后必须等待状态切换，则由一个可配置的超时来保障该等待。若超时到期，则上报该错误（[SWS_Lin_00290]）。该上报经由 Dem_SetEventStatus（[SWS_Lin_00234]）发送至 LinDemEventParameterRefs 中引用的事件（SWS LIN Driver 第65页）。

驱动程序根据节点类型以不同方式上报通信错误。Master 通道将其作为 Lin_GetStatus 的状态返回（[SWS_Lin_00233]）：

  • 头中出现回读错误、奇偶校验错误或总线错误时报 LIN_TX_HEADER_ERROR，
  • 响应传输错误时报 LIN_TX_ERROR，
  • 出现成帧错误、溢出错误或校验和错误以及响应过短时报 LIN_RX_ERROR。

Slave 通道中止帧处理，并携带 Lin_SlaveErrorType 调用 LinIf_LinErrorIndication（[SWS_Lin_00277]、[SWS_Lin_91140]）。在等待头期间出现的无效总线事件，它们作为 LIN_ERR_HEADER 上报（[SWS_Lin_00281]）。

活动图：开发错误发送至 DET，硬件超时发送至 DEM。总线通信错误由 Master 通道作为状态上报，由 Slave 通道作为错误指示上报。来源：[SWS_Lin_00258]、[SWS_Lin_00290]、[SWS_Lin_00233]、[SWS_Lin_00277]、[SWS_Lin_00281]、[SWS_Lin_00235]
