LIN 驱动在 LIN Interface 与控制器硬件之间的角色

LIN 驱动（Lin）封装了 ECU 的 LIN 硬件单元，即专用的 LIN 控制器或简易 UART。它以基于通道的服务形式将其提供给 LIN Interface（LinIf）。驱动以Lin_PduType的形式接收帧请求任务，并包含以下信息：PID、校验和模型、响应类型、数据长度和 SDU 指针[SWS_Lin_00232]。在特性模型中，LIN 是一项可选的网络技术，包含子特性 LIN_Master 和 LIN_Slave FO Features 第58页。驱动在每个通道上均支持这两种角色。然而，有多个服务仅适用于 Master 通道[SWS_Lin_00287] [SWS_Lin_00288] [SWS_Lin_00289]。

该驱动使用了其他模块的三个必需接口：

  • 用于生产错误的Dem_SetEventStatus。
  • 用于检测到的唤醒事件的EcuM_SetWakeupEvent和LinIf_WakeupConfirmation [SWS_Lin_00234]。

可选地增加Det_ReportError、EcuM_CheckWakeup以及 Icu 通知控制[SWS_Lin_00235]。在 Slave 通道上，驱动通过 LinIf 的回调报告报头、接收、发送确认和错误[SWS_Lin_00280] [SWS_Lin_00274] [SWS_Lin_00275] [SWS_Lin_00277]。它本身不提供回调函数SWS LINDriver 第49页。完整的时序图不在驱动规范中，而是在 LinIf 规范中SWS LINDriver 第52页。

从复位到运行的模块与通道状态

该驱动采用两级状态机工作。复位后，模块处于LIN_UNINIT且不可使用。调用Lin_Init使其转入LIN_INIT；在此状态下，每个可用通道均处于就绪状态SWS LINDriver 第24页 SWS LINDriver 图 7.1 第24页。Lin_Init是同步且不可重入的。该服务接收指向Lin_ConfigType的指针。其内容与硬件相关，用于配置驱动、硬件单元和通道[SWS_Lin_00006] [SWS_Lin_00227]。运行环境在运行时应仅调用Lin_Init一次SWS LINDriver 第24页。

在LIN_INIT内，每个通道都有各自的状态SWS LINDriver 第23页：

  • LIN_CH_OPERATIONAL：通道已初始化并加入 LIN 集群SWS LINDriver 第24页。
  • LIN_CH_SLEEP：唤醒脉冲检测处于激活状态，硬件在适当时处于低功耗模式SWS LINDriver 第24页。
  • LIN_CH_SLEEP_PENDING：仅适用于 Master 通道。Lin_GoToSleep之后的中间状态，该状态仅由Lin_GetStatus结束SWS LINDriver 图 7.1 第24页。

Lin_Init建立了哪种通道状态，在有效负载中仅被简要提及。推测每个通道都在LIN_CH_SLEEP中启动；状态图的描述表明了这一点SWS LINDriver 图 7.1 第23页。通道通过Lin_Wakeup或Lin_WakeupInternal返回到LIN_CH_OPERATIONAL [SWS_Lin_00169] [SWS_Lin_00256]。

Master 通道：帧请求任务与状态轮询

在 Master 通道上，LinIf 使用Lin_SendFrame触发每个调度表项。该服务是异步的，发送一个 LIN 报头以及根据响应类型发送 Response [SWS_Lin_00191]。Lin_PduType的各个字段定义了帧[SWS_Lin_00232]：

  • Pid（Lin_FramePidType，0…0xFE）：标识符 0…0x3F，包括两个奇偶校验位[SWS_Lin_00228]。
  • Cs（Lin_FrameCsModelType）：LIN_CLASSIC_CS或LIN_ENHANCED_CS。驱动计算匹配的校验和[SWS_Lin_00229] [SWS_Lin_00019]。
  • Drc（Lin_FrameResponseType）：Response 来自此节点（LIN_FRAMERESPONSE_TX）、来自另一个相关节点（LIN_FRAMERESPONSE_RX），或是无关的（LIN_FRAMERESPONSE_IGNORE）[SWS_Lin_00230]。
  • Dl（Lin_FrameDlType，1…8）：要复制的数据字节数[SWS_Lin_00231]。

在内存中，SDU 数组的元素 0 包含最先传输的字节 SWS LINDriver 第30页。若硬件无法缓冲字节，则驱动程序提供临时缓冲区。发送与接收均以非阻塞方式运行 SWS LINDriver 第28页。主节点使用 LIN_FRAMERESPONSE_IGNORE 发送 Slave-to-Slave 帧 SWS LINDriver 第37页。LinIf 支持该通信方式，但不推荐 SWS LINInterface 第45页。

时序图：已发送的帧在 LinIf 主函数的三个周期内被触发、传输并通过状态轮询进行确认。在较新的版本中，上层被称为 LSduR。来源：SWS LINInterface 图 9.1 第120页 [SWS_Lin_00191] [SWS_Lin_00168] SWS LINInterface 第37页

同步服务 Lin_GetStatus 提供帧的结果。它返回一个 Lin_StatusType。在接收时，它将 Lin_SduPtr 设置为影子缓冲区或映射的硬件接收缓冲区 [SWS_Lin_00168] [SWS_Lin_00233]。LinIf 最早会在最大帧长之后、最晚在下一个调度条目时调用它 SWS LINInterface 第35页。完整的接收处理可以位于 Lin_GetStatus 中。接收到的数据保持一致，直到成功接收下一帧或通道状态发生改变 SWS LINDriver 第30页。帧结束由硬件控制器识别，或由驱动程序自身通过 UART 中断逐字节识别 SWS LINDriver 图 9.1 第56页。

时序图：主节点上的帧接收，根据硬件不同使用控制器或 UART，由 Lin_GetStatus 完成。来源：SWS LINDriver 图 9.1 第56页 SWS LINInterface 图 9.4 第122页 [SWS_Lin_00168]

从节点通道：报头驱动的响应处理

从节点不知道主节点的调度表。它仅对接收到的报头作出反应 SWS LINInterface 第38页。在状态 LIN_CH_OPERATIONAL 下，驱动程序必须能够随时接收由 Break、Sync 和 PID 组成的报头 [SWS_Lin_00272]。随后它调用 LinIf_HeaderIndication。在此过程中，它传递接收到的 PID 以及指向其硬件或影子缓冲区的指针 [SWS_Lin_00280]。若硬件无法识别无效 PID，则驱动程序不加检查地直接传递该 PID [SWS_Lin_00271]。

LinIf 在回调中指定响应类型。如果其返回 E_OK，则驱动程序评估 PduPtr->Drc [SWS_Lin_00282]：

  • LIN_FRAMERESPONSE_TX：驱动程序根据 Cs、Dl 和 SduPtr 构建响应并发送。它通过 LinIf_TxConfirmation 报告成功 [SWS_Lin_00283] [SWS_Lin_00275]。
  • LIN_FRAMERESPONSE_RX：驱动程序使用 Cs 和 Dl 配置接收。它通过带有接收数据的 LinIf_RxIndication 报告成功 [SWS_Lin_00284] [SWS_Lin_00274]。
  • E_NOT_OK 或 LIN_FRAMERESPONSE_IGNORE：驱动程序忽略响应，并且在下一个报头之前不报告任何内容 [SWS_Lin_00286] [SWS_Lin_00276]。

每个相关的响应都必须在下一次报头指示之前完成，即通过接收指示、发送确认或错误指示 [SWS_Lin_00285]。发送时，LinIf 使数据直接写入驱动程序缓冲区；复制工作由驱动程序完成 SWS LINInterface 第121页。

时序图：在每个报头之后，从节点驱动程序根据 Drc 分支到发送、接收或忽略。来源：SWS LINInterface 图 9.3 第121页 SWS LINInterface 第123页 SWS LINInterface 第134页 [SWS_Lin_00282] [SWS_Lin_00286]

睡眠命令、唤醒与唤醒检测

只有主节点才能发送 Go-to-sleep 命令。Lin_GoToSleep 是异步的，并指示驱动程序执行此操作 [SWS_Lin_00166]。在纯从节点配置中不存在该服务 [SWS_Lin_00288] SWS LINDriver 第31页。即使传输失败，通道也会转入 LIN_CH_SLEEP_PENDING SWS LINDriver 第43页。

相比之下，Lin_GoToSleepInternal 是同步工作的且没有总线命令：该服务将通道置于 LIN_CH_SLEEP，激活唤醒检测，并可选择将硬件切换到节能模式 [SWS_Lin_00167] SWS LINDriver 第44页。每个通道独立于其他通道接受睡眠请求 SWS LINDriver 第31页。

时序图：主节点通道通过 LIN_CH_SLEEP_PENDING 进入睡眠，或者如果已处于睡眠状态，则直接通过 Lin_GoToSleepInternal 进入睡眠。来源：SWS LINInterface 图 9.15 第136页 [SWS_Lin_00166] [SWS_Lin_00167] SWS LINInterface 第56页

用于唤醒的服务有两个：

  • Lin_Wakeup 生成唤醒脉冲并将通道置于 LIN_CH_OPERATIONAL [SWS_Lin_00169]。
  • Lin_WakeupInternal 同样将通道置于 LIN_CH_OPERATIONAL，但不在总线上发送脉冲 [SWS_Lin_00256] [SWS_Lin_00262]。

一种特殊情况涉及在进入睡眠过程中的唤醒：若用户在睡眠命令仍处于待决状态时请求唤醒，且此后 Lin_GetStatus 已经报告了睡眠状态，则 LinIf 会再次调用 Lin_Wakeup SWS LINInterface 第56页。

如果配置了 LinChannelWakeupSupport，硬件在睡眠状态下会监控总线上的唤醒请求 SWS LINDriver 第31页。Lin_CheckWakeup 同步检查通道上是否存在唤醒事件 [SWS_Lin_00160]。该服务会立即将检测到的事件报告给 EcuM_SetWakeupEvent 和 LinIf_WakeupConfirmation SWS LINDriver 第42页 [SWS_Lin_00234]。Lin_CheckWakeup 由 LinIf_CheckWakeup 调用。后者根据唤醒源查询驱动程序或收发器驱动程序 SWS LINInterface 第112页。LIN 不需要唤醒校验 SWS EcuM 第173页。

配置：节点类型、通道与分区

参数 LinNodeType 决定存在哪些服务。只有当至少有一个通道配置为主节点时，才会存在 Lin_SendFrame、Lin_GoToSleep 和 Lin_GetStatus [SWS_Lin_00287] [SWS_Lin_00288] [SWS_Lin_00289]。容器 LinChannel 每个通道包含波特率、通道 ID、唤醒支持、节点类型、可选的 EcuM 唤醒源以及时钟参考等 SWS LINDriver 第60页。LinGeneral 汇总了驱动程序范围的参数 SWS LINDriver 第57页。根据配置图，其中包括开发错误检测、版本 API 和超时时长 SWS LINDriver 图 10.1 第48页。

在多分区系统中，适用以下规则：

  • 驱动程序在每个分区中作为一个独立的实例运行；API 调用仅在自身分区中生效 [SWS_Lin_CONSTR_00270]。
  • 若 LinEcucPartitionRef 引用了分区，则每个通道必须恰好引用其中一个 [SWS_Lin_CONSTR_00291]。
  • 通道的 LinChannel 和 LinTrcvChannel 必须使用相同的分区 [SWS_Lin_CONSTR_00279]。
  • 驱动程序会拒绝不受支持的分区分配 [SWS_Lin_00269]。

模块的版本信息由 Lin_GetVersionInfo 提供 [SWS_Lin_00161]。

发生错误时的行为

若开发错误检测处于激活状态，通道服务会检查初始化、通道号和状态。对于 Lin_WakeupInternal，这已由规范证明 [SWS_Lin_00258] [SWS_Lin_00259] [SWS_Lin_00260]：

  • LIN_E_UNINIT：在 Lin_Init 之前调用。
  • LIN_E_INVALID_CHANNEL：无效或未激活的通道。
  • LIN_E_STATE_TRANSITION：通道未处于 LIN_CH_SLEEP 状态。

Lin_Wakeup 以相同方式检查 SWS LINDriver 第45页。Lin_GetVersionInfo 在传递 NULL 指针时 SWS LINDriver 第41页 报告 LIN_E_PARAM_POINTER。错误类别遵循通用 BSW 规范的模式 SWS LINDriver 第32页。

驱动程序将 LIN_E_TIMEOUT 作为生产错误进行报告。如果其在访问控制寄存器后必须等待状态变化，则可配置的超时对此等待时间提供保护。如果超时耗尽，则表明存在硬件错误 [SWS_Lin_00290]。该报告通过 Dem_SetEventStatus 发送至 LinDemEventParameterRefs 中引用的事件 [SWS_Lin_00234] SWS LINDriver 第65页。

在主节点通道上，总线错误反映在状态值 [SWS_Lin_00233] 中：

  • LIN_TX_HEADER_ERROR：报头中的回读错误、奇偶校验错误或物理总线错误。
  • LIN_TX_ERROR：响应传输错误。
  • LIN_RX_ERROR：帧错误、溢出错误、校验和错误或响应过短。
  • LIN_RX_NO_RESPONSE：迄今未接收到任何响应字节。

评估由 LinIf 负责。对于事件触发帧，LIN_RX_ERROR 被视为冲突；随后 LinIf 切换到冲突解决调度表 SWS LINInterface 第129页。LIN_RX_NO_RESPONSE 在此处不是通信错误 SWS LINInterface 第127页。

用法与语义

函数 Lin_CheckWakeup 用于检查在所寻址的 LIN 通道上是否发生了唤醒事件（[SWS_Lin_00160]）。它通过头文件 Lin.h 提供，并具有服务 ID 0x0a（[SWS_Lin_00160]）。

  • 调用上下文与参数：调用时需传入参数 Channel（类型 uint8），该参数用于标识要寻址的 LIN 通道（[SWS_Lin_00160]）。既不存在输入/输出参数，也不存在纯输出参数（[SWS_Lin_00160]）。
  • 执行行为：该函数完全同步工作（Synchronous）（[SWS_Lin_00160]）。

返回值与错误处理

函数结果通过返回类型 Std_ReturnType 进行指示（[SWS_Lin_00160]）：

  • E_OK：在执行 API 调用期间未发生错误（[SWS_Lin_00160]）。
  • E_NOT_OK：在执行 API 调用期间发生了错误（[SWS_Lin_00160]）。

并发性与限制

Lin_CheckWakeup 被指定为不可重入（Non Reentrant）（[SWS_Lin_00160]）。因此，针对相同或并行通道的调用不得在无保护的情况下并发进行，而是必须由调用者进行串行化或提供相应保护。
