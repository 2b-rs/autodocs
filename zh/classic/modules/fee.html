在存储栈中的角色：位于 MemIf 与 Flash 驱动程序之间的 Fee

Fee（Flash EEPROM Emulation）模块将按块寻址的、类似 EEPROM 的数据存储映射到闪存上。NVRAM Manager 通过 Memory Abstraction Interface 与 Fee 通信。在向下方向，Fee 在 R20-11 中依赖于 Flash 驱动程序 Fls：其服务（如Fls_Read、Fls_Write、Fls_Erase、Fls_Cancel和Fls_SetMode）位于所需接口列表中[SWS_Fee_00105]。Fee 还导入Fls_AddressType和Fls_LengthType以及类型MemIf_StatusType、MemIf_JobResultType和MemIf_ModeType[SWS_Fee_00084]。规范的写入时序展示了具有周期性 BSW 任务的链条 NvM → MemIf → Fee → Fls（SWS Fee 图 7 第40页、SWS Fee 图 6 第48页）。

发布说明：较新的规范版本用 MemAcc 和 Mem 驱动程序取代了 Fls。因此，带有 MemAcc 的模块概览以及带有MemAcc_BlankCheck的可选接口列表不适用于 R20-11（SWS Fee 图 1.1 第9页、SWS Fee 第40页）。在 R20-11 中，Det_ReportError和Fls_BlankCheck是可选接口[SWS_Fee_00104]。

反馈不通过 MemIf 进行。Fee 向下层提供回调Fee_JobEndNotification和Fee_JobErrorNotification[SWS_Fee_00095][SWS_Fee_00096]。Fee 自身调用NvM_JobEndNotification或NvM_JobErrorNotification[SWS_Fee_00098][SWS_Fee_00099]。MemIf 未定义自己的回调，因为 NVRAM Manager 为抽象模块提供了回调（SWS MemIf 第24页）。

上下文图：Fee 位于 MemIf 和 Fls 之间；EcuM 初始化该模块，BSW Scheduler 周期性驱动它，并且反馈直接发送给 NvM。来源：[SWS_Fee_00104]、[SWS_Fee_00105]、[SWS_Fee_00098]、SWS Fee 图 9.1 第42页、SWS Fee 图 7 第40页

启动：从 Fee_Init 经 MEMIF_BUSY_INTERNAL 到 MEMIF_IDLE

Fee_Init接收指向所选配置集的指针，并在 R20-11 中被指定为异步[SWS_Fee_00085]。相应图表显示了该流程：EcuM 调用Fee_Init，模块切换到MEMIF_BUSY_INTERNAL。在此状态下，它已能接受作业。随后，BSW Scheduler 周期性调用Fee_MainFunction，直到内部管理完成（SWS Fee 图 9.1 第42页）。较旧的图表（R18-10）还包含一种同步变体：在其中，初始化在Fee_Init中即已结束，且状态直接为MEMIF_IDLE（SWS Fee 图 4 第47页）。

Fee_MainFunction标志着完成。如果不需要内部管理操作或管理操作已结束，它会将状态从MEMIF_BUSY_INTERNAL设置为MEMIF_IDLE。在此期间，管理可能需要多次调用（SWS Fee 第38页）。主函数由 Basic Software Scheduler 直接调用。它既没有参数也没有返回值，并且不可重入（SWS Fee 第40页、[SWS_Fee_00097]）。

时序图：在异步Fee_Init之后，只有Fee_MainFunction才会结束初始化；同步变体源自较旧的图表。来源：[SWS_Fee_00085]、SWS Fee 图 9.1 第42页、SWS Fee 图 4 第47页、SWS Fee 第38页

Fee_GetStatus返回四个值之一[SWS_Fee_00090]：

  • MEMIF_UNINIT：初始化之前。
  • MEMIF_IDLE：既没有上层作业也没有内部管理在运行。
  • MEMIF_BUSY：正在处理上层作业。
  • MEMIF_BUSY_INTERNAL：内部管理操作正在运行，例如重组（Garbage Collection）。

状态定义位于SWS Fee 第30页中。

状态图：从MEMIF_IDLE和MEMIF_BUSY_INTERNAL接受作业；MEMIF_BUSY以作业结束或以Fee_Cancel结束。来源：[SWS_Fee_00090]、SWS Fee 第30页、SWS Fee 第28页、SWS Fee 第29页、SWS Fee 第38页

逻辑块、虚拟地址和块正确性

所有作业服务均通过 BlockNumber 寻址逻辑块。该值同时表示该块的起始地址 [SWS_Fee_00087] [SWS_Fee_00088]。内存映射示意图将虚拟地址分解为 16 位块号和 16 位块偏移量；在虚拟空间中，页的大小为 64 KB。物理上，块占用整块 Flash 页，因此可能会产生未使用的剩余空间（SWS Fee 图 3 第20页）。下表重现了示意图中的示例：

块有效数据占用的页（每页 8 字节）内部剩余空间
#132 字节40 字节
#5100 字节134 字节
#1738 字节52 字节

读取和写入在粒度上有所不同：

  • Fee_Read 根据块起始地址和偏移量计算读取地址。偏移量和长度可以在其取值范围内取任意值（SWS Fee 第26页）。
  • Fee_Write 没有偏移量参数；每次写入操作均从偏移量零开始（SWS Fee 第28页）。

底层需求通过与虚拟 64K 边界对齐来解释写入规则：块只能被完整擦除或写入，或者根本不擦除或写入（RS MemHwAb 第24页）。

无论内容如何，Fee 都会为每个块维护内部正确性信息。在写入过程开始时，该块被视为“corrupted”，在成功结束后重新被视为“not corrupted”。该信息必须与 Fee_InvalidateBlock 设置的有效性严格区分（SWS Fee 第21页、[SWS_Fee_00092]）。解释：以这种方式标记的块在读取时可能会报告为 MEMIF_BLOCK_INCONSISTENT。根据返回值说明，该值代表不一致、可能损坏的块 [SWS_Fee_00091]。

异步作业：接收、在 Fee_MainFunction 中处理、反馈

Fee_Read、Fee_Write、Fee_InvalidateBlock 和 Fee_EraseImmediateBlock 是异步且不可重入的。它们的返回值仅表示作业是否已被接收（E_OK）或未被接收（E_NOT_OK）[SWS_Fee_00087] [SWS_Fee_00088] [SWS_Fee_00092] [SWS_Fee_00094]。在状态 MEMIF_IDLE 或 MEMIF_BUSY_INTERNAL 下，Fee 会接收作业：它获取参数、启动作业、将状态设置为 MEMIF_BUSY 并将作业结果设置为 MEMIF_JOB_PENDING，然后返回 E_OK（SWS Fee 第28页、SWS Fee 第26页）。在 MEMIF_UNINIT 或 MEMIF_BUSY 下，作业可能会被以 E_NOT_OK 拒绝；相关规则在有效载荷中仅被略微提及（SWS Fee 第28页）。

实际工作由 Fee_MainFunction 完成。它异步处理读取、写入、擦除和使无效作业以及内部管理操作（SWS Fee 第38页）。对于读取作业，它会检查上层是否已使该块无效。如果确实如此，它会将作业结果设置为 MEMIF_BLOCK_INVALID，并调用错误通知（如果已配置）。如果 Flash 驱动程序中配置了 Fls_BlankCheck，Fee_Read 会预先调用此函数。这样可以避免例如在读取已擦除但未编程的单元时发生 ECC 错误 [SWS_Fee_00187]。

活动图：读取作业仅在 MEMIF_IDLE 或 MEMIF_BUSY_INTERNAL 下被接收；已使无效的块以 MEMIF_BLOCK_INVALID 结束，若配置了查空（Blank-Check）则在读取前执行。来源：[SWS_Fee_00087]、[SWS_Fee_00187]、SWS Fee 第26页、SWS Fee 第38页

在作业结束时，驱动程序调用 Fee_JobEndNotification。Fee 执行必要的块管理，并将挂起的 MEMIF_JOB_PENDING 设置为 MEMIF_JOB_OK；否则作业结果保持不变。随后，Fee 调用上层的结束通知（如果已配置）（SWS Fee 第37页）。或者，上层可以使用 Fee_GetJobResult 查询最近接收的作业的结果 [SWS_Fee_00091]。回调可以在中断级别运行，因此必须保持简短（SWS Fee 第36页）。

时序图：写入作业立即返回 E_OK，异步执行并通过回调级联 Fls → Fee → NvM 完成。Fee 是已经在 Fee_Write 中触发驱动程序还是直到 Fee_MainFunction 中才触发，并没有强制性规定。来源：[SWS_Fee_00088]、[SWS_Fee_00095]、SWS Fee 图 7 第40页、SWS Fee 第42页、SWS Fee 第21页

特殊服务：取消、使无效、立即数据和模式切换

Fee_Cancel 在 R20-11 中是同步的 [SWS_Fee_00089]。后续版本将该服务列为异步，但同时将其描述为自身是同步的，仅相对于硬件而言是异步的（SWS Fee 第29页、SWS Fee 第45页）。在状态 MEMIF_BUSY 下，Fee_Cancel 调用驱动程序的 Cancel 函数并重置内部变量。由此，该模块在 MEMIF_IDLE 中准备好接收新作业（SWS Fee 第29页）。此时作业结果为 MEMIF_JOB_CANCELED [SWS_Fee_00091]。针对在没有挂起作业时的调用，定义了错误代码 FEE_E_INVALID_CANCEL [SWS_Fee_91002]。

时序图：Fee_Cancel 通过 Fls_Cancel 取消正在运行的写入作业，并使 Fee 立即空闲以接收新作业。原始示意图展示了带有 MemAcc 的较新堆栈；此处已将其转写至 Fls (R20-11) 。来源：[SWS_Fee_00089]、[SWS_Fee_00105]、[SWS_Fee_91002]、SWS Fee 图 9.3 第44页、SWS Fee 第29页

Fee_InvalidateBlock 根据块号计算块地址。它通过驱动程序的擦除函数和/或通过非易失性存储的内部管理信息使该块无效（SWS Fee 第32页）。Fee_EraseImmediateBlock 适用于诊断或类似的系统服务，这些服务会预先擦除立即数据区域。在此过程中是否进行物理擦除取决于具体实现（SWS Fee 第35页）。在 R20-11 中，这两个服务仅在启用 DET 时才返回 E_NOT_OK [SWS_Fee_00092] [SWS_Fee_00094]；更新的版本对 E_NOT_OK 的表述则没有此限制（SWS Fee 第32页）。

Fee_SetMode 切换底层 Flash 驱动程序的操作模式，并在 R20-11 中是异步的 [SWS_Fee_00086]。相比之下，较早的示意图显示了一条连续的调用链 MemIf_SetMode → Fee_SetMode → Fls_SetMode（SWS Fee 图 6 第44页）。Fee_GetVersionInfo 是唯一的重入 Fee 服务 [SWS_Fee_00093]。在启用 DET 的情况下，它会检查传入的指针，并在 NULL 时报告错误 FEE_E_PARAM_POINTER（SWS Fee 第34页）。

配置集和可配置的反馈路径

Fee_ConfigType 是一个包含具体实现相关元素的结构体 [SWS_Fee_00188]；Fee_Init 接收指向它的指针 [SWS_Fee_00085]。ECU 配置参数示意图显示了一个多重性为 0..1 的模块容器。它包含诸如 FeeDevErrorDetect、FeeVersionInfoApi 和 FeeVirtualPageSize 等参数以及函数名称 FeeJobEndNotification 和 FeeJobErrorNotification（ECUC-Parameter 图 7.7 第578页）。不过，该示意图基于 2006 年的规范版本；因此有效载荷并未证实 R20-11 的准确参数列表。有效载荷中的变更历史还提到了参数 FeeMainFunctionPeriod（SWS MemIf 第2页）。

可配置的通知解释了流程中“若已配置”的附加说明。Fee 仅在注册了此类例程时才会调用上层的结束或错误通知（SWS Fee 第37页、SWS Fee 第38页）。相应地，错误说明根据配置给出了两种通知路径：轮询或回调（ErrorDescription 第40页）。

发生错误时的行为

Fee 定义了以下错误代码 [SWS_Fee_00010] [SWS_Fee_91002]。检查的一个示例：在启用 DET 的情况下，Fee_Cancel 在状态 MEMIF_UNINIT 下报告错误 FEE_E_UNINIT（SWS Fee 第29页）。

错误代码值原因
FEE_E_UNINIT0x01在未预先初始化的情况下调用了服务
FEE_E_INVALID_BLOCK_NO0x02无效的块号
FEE_E_INVALID_BLOCK_OFS0x03无效的块偏移量
FEE_E_PARAM_POINTER0x04无效的数据指针
FEE_E_INVALID_BLOCK_LEN0x05无效的长度说明
FEE_E_BUSY0x06在上层作业正在运行时调用
FEE_E_INVALID_CANCEL0x08无挂起作业时调用 Fee_Cancel

硬件错误由 Flash 驱动程序检测。它通过 Fee_JobErrorNotification 报告异步操作的失败 [SWS_Fee_00096]。Fee 中的反应取决于具体实现。根据配置，MemIf 通过 Fee_GetJobResult 查询作业结果 MEMIF_JOB_FAILED，或者 Fee 通过 NvM_JobErrorNotification 报告错误。恢复工作由 NvM 负责（ErrorDescription 第40页、[SWS_Fee_00099]）。MemIf 可以通过 Fee_GetStatus 检测到未初始化的状态（ErrorDescription 第53页、[SWS_Fee_00090]）。

发生一致性错误时，Fee 会检查读取的数据并将检测到的错误转发给 NvM。NvM 向 DEM 报告 NVM_E_INTEGRITY_FAILED，并在配置的情况下启动恢复：重新读取、读取冗余块或读取 ROM 块。如果恢复失败，作业结果为 NVM_REQ_INTEGRITY_FAILED。相关示意图来自 R22-11（ErrorDescription 图 6.11 第64页）。Fee 本身在其作业结果中还区分已使无效（MEMIF_BLOCK_INVALID）、不一致（MEMIF_BLOCK_INCONSISTENT）和已取消的作业（MEMIF_JOB_CANCELED）[SWS_Fee_00091]。

时序图：根据配置，驱动程序错误通过回调或轮询传递给 NvM；一致性错误触发 NvM 中的恢复。来源：[SWS_Fee_00096]、[SWS_Fee_00099]、[SWS_Fee_00091]、ErrorDescription 第40页、ErrorDescription 图 6.11 第64页

用法与语义

函数 Fee_Read（[SWS_Fee_00087]）用于触发异步读取作业，并通过头文件 Fee.h 提供，服务 ID 为 0x02。控制和缓冲区传递通过以下参数进行：

  • Block Number：逻辑块号，同时指定该块在 Flash 存储器中的起始地址。
  • Block Offset：指定块内的读取偏移量。
  • Length：要从存储器读取的字节数。
  • DataBufferPtr：指向数据缓冲区（输出参数）的指针，读取的数据将写入其中。

作为返回值，函数提供 Std_ReturnType：E_OK 表示模块已接受读取请求，而 E_NOT_OK 则指示作业被拒绝。

并发性与限制

根据 [SWS_Fee_00087]，Fee_Read 被指定为不可重入（Non Reentrant）。由于这是异步服务，返回 E_OK 仅确认已接受该作业以供进一步处理，并不代表其已完成执行。

与 Flash 驱动程序的协同工作

若 Flash 驱动程序中配置了函数 Fls_BlankCheck，根据 [SWS_Fee_00187]，Fee_Read 必须预先调用该函数。由此在事前检查相关存储区域是否可以读取，而不会在尝试读取已擦除但尚未编程的 Flash 单元时触发例如 ECC 错误。

Fee_Write 的使用

函数 Fee_Write 用于在模块 Fee（[SWS_Fee_00088]）中发起写入作业。该服务拥有服务 ID 0x03，通过头文件 Fee.h 提供，并以异步方式工作（[SWS_Fee_00088]）。

针对该调用指定了两个输入参数（[SWS_Fee_00088]）：

  • BlockNumber：逻辑块号，同时指定该块在仿真的 EEPROM 中的起始地址（[SWS_Fee_00088]）。
  • DataBufferPtr：指向包含待传输有效数据的数据缓冲区的指针（[SWS_Fee_00088]）。

该接口不存在输出参数以及输入/输出参数（[SWS_Fee_00088]）。
