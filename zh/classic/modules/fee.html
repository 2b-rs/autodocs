Fee 将模拟 EEPROM 的逻辑块映射到 Flash 存储器上。BlockNumber 同时表示块的起始地址 [SWS_Fee_00087]。调用来自 NVRAM Manager，经由通过 DeviceIndex 选择相应服务的 Memory Abstraction Interface SWS MemIf 第18页。其下层运行 Flash 驱动程序 Fls。Fee 通过 NvM_JobEndNotification 和 NvM_JobErrorNotification 直接向 NVRAM Manager 提供反馈 [SWS_Fee_00098]、[SWS_Fee_00099]。

Fee_Cancel 在 R20-11 中是同步的，并通过 Flash 驱动程序中止挂起的作业 [SWS_Fee_00089]。在没有挂起作业的情况下，它报告 FEE_E_INVALID_CANCEL [SWS_Fee_91002]。Flash 错误由驱动程序检测。Fee 根据配置通过两种途径报告这些错误：作为 MEMIF_JOB_FAILED 供查询，或通过 NvM_JobErrorNotification。恢复由 NVRAM Manager 负责 ErrorDescription 第40页。Fee 将未初始化或无效块号等错误操作报告为开发错误 [SWS_Fee_00010]。

在 NV 存储栈中的角色：Flash 存储器作为模拟 EEPROM

Flash EEPROM Emulation (Fee) 为上层提供逻辑块，并将其映射到 Flash 存储器上。在此过程中，BlockNumber 同时表示块在存储器中的起始地址 [SWS_Fee_00087]、[SWS_Fee_00088]。NVRAM Manager 并不直接调用 Fee，而是通过 Memory Abstraction Interface 调用。MemIf_Read 和 MemIf_Write 调用通过 DeviceIndex 选择的抽象模块的函数，并传递其返回值 SWS MemIf 第18页、SWS MemIf 第19页。向下，Fee 基于 Flash 驱动程序 Fls。它从那里导入 Fls_AddressType 和 Fls_LengthType，从 MemIf 导入状态、结果和模式类型 [SWS_Fee_00084]。

反馈绕过 MemIf。MemIf 本身不提供回调；用于底层抽象模块的回调例程由 NVRAM Manager 提供 SWS MemIf 第24页。为此，Fee 调用 NvM_JobEndNotification 和 NvM_JobErrorNotification [SWS_Fee_00098]、[SWS_Fee_00099]。反之，驱动程序通过 Fee_JobEndNotification 和 Fee_JobErrorNotification 向 Fee 报告其作业的结束 [SWS_Fee_00095]、[SWS_Fee_00096]。Fee 由 EcuM 初始化，由 Basic Software Scheduler 周期性触发 SWS Fee 第42页。

上下文图：Fee 位于 MemIf 和 Fls 之间。它由 EcuM 初始化，由 SchM 周期性触发，并直接向 NvM 报告作业结束。来源：[SWS_Fee_00085]、[SWS_Fee_00097]、[SWS_Fee_00098]、[SWS_Fee_00104]、[SWS_Fee_00105]、SWS MemIf 第18页。

作为所需的驱动程序服务，R20-11 列出了以下等函数 [SWS_Fee_00105]：

  • Fls_Read、Fls_Write、Fls_Erase 和 Fls_Compare，
  • Fls_Cancel、Fls_GetStatus、Fls_GetJobResult 和 Fls_SetMode，
  • Det_ReportRuntimeError.

可选地添加 Det_ReportError 和 Fls_BlankCheck [SWS_Fee_00104]。同一需求的后续版本则列出 MemAcc_BlankCheck SWS Fee 第40页。对于 R20-11，规范性要求仍为 Fls 变体。

启动：从 Fee_Init 到准备好接受作业

EcuM 使用指向所选配置集的指针调用 Fee_Init [SWS_Fee_00085]。类型 Fee_ConfigType 是一个包含实现特定元素的结构体 [SWS_Fee_00188]。值得注意的是，R20-11 将 Fee_Init 列为异步 [SWS_Fee_00085]。根据变更历史，初始化不必在 Fee_Init 内完成，状态机也作了相应调整 SWS Fee 第4页。

规范的时序图展示了该流程 SWS Fee 第42页：

  1. 在 Fee_Init 之后，模块状态为 MEMIF_BUSY_INTERNAL。
  2. 在此状态下已可接受作业。
  3. 调度器持续调用 Fee_MainFunction，直至内部管理完成。

后续版本规定，Fee_MainFunction 随后将状态从 MEMIF_BUSY_INTERNAL 置为 MEMIF_IDLE。在此期间，管理过程可能持续多次调用 SWS Fee 第38页。图表的较早版本仅显示了由 EcuM 进行的同步调用 SWS Fee 第38页。

时序图：Fee_Init 将模块置于 MEMIF_BUSY_INTERNAL。只有重复调用 Fee_MainFunction 才能完成内部管理并转换至 MEMIF_IDLE。来源：[SWS_Fee_00085]、[SWS_Fee_00097]、SWS Fee 第42页。

Fee_MainFunction 处理所请求的读、写和擦除作业以及内部管理操作 [SWS_Fee_00097]。作为调度函数，它由 Basic Software Scheduler 直接调用。它既无参数也无返回值，且是不可重入的 SWS Fee 第40页。

作为控制变量的模块状态和作业结果

上层通过两个同步查询来控制其调用。Fee_GetStatus 返回四个值之一 [SWS_Fee_00090]：

  • MEMIF_UNINIT：模块未初始化。
  • MEMIF_IDLE：模块处于空闲状态。
  • MEMIF_BUSY：正在处理上层的作业。
  • MEMIF_BUSY_INTERNAL：正在执行内部管理操作。

规范将所用 Flash 存储器的重组（垃圾回收）列为内部管理操作的一个示例 SWS Fee 第30页。新作业在 MEMIF_IDLE 和 MEMIF_BUSY_INTERNAL 中均被接受，并导致转换至 MEMIF_BUSY SWS Fee 第28页。在正常作业结束后，状态应重新回到 MEMIF_IDLE。在此处，明确有据可查的返回至 MEMIF_IDLE 仅针对中止情况 SWS Fee 第29页。

状态图：模块状态从 MEMIF_UNINIT 经由 MEMIF_BUSY_INTERNAL 到 MEMIF_IDLE 和 MEMIF_BUSY 的生命周期。正常作业结束时的转换被标记为假定。来源：[SWS_Fee_00090]、SWS Fee 第42页、SWS Fee 第28页、SWS Fee 第29页。

Fee_GetJobResult 涉及最近接受的作业 [SWS_Fee_00091]、SWS Fee 第31页。它区分六种结果：

  • MEMIF_JOB_OK：作业已成功完成。
  • MEMIF_JOB_PENDING：作业正在等待或仍在运行。
  • MEMIF_JOB_CANCELED：作业已被取消。
  • MEMIF_JOB_FAILED：作业已失败。
  • MEMIF_BLOCK_INCONSISTENT：该块可能包含已损坏的数据。
  • MEMIF_BLOCK_INVALID：该块已被置为无效；无法读取。

因此，状态描述的是模块，而结果描述的是单个作业；两者需分别查询 [SWS_Fee_00090]。

读、写和块管理作业

作业服务异步工作：E_OK 仅表示作业已被接受 [SWS_Fee_00087]、[SWS_Fee_00088]。Fee_Read 根据块起始地址和 BlockOffset 计算读取地址。偏移量和长度可取其类型范围内的任意值。由此可以从块的任意位置开始读取任意数量的字节 SWS Fee 第26页。如果在 Flash 驱动程序中配置了 Fls_BlankCheck，Fee_Read 会借此预先检查该区域是否可读。这可以避免例如已擦除但未编程的单元触发 ECC 错误 [SWS_Fee_00187]。

相反，Fee_Write 始终写入整个块；偏移量固定为零 SWS Fee 第28页。这是由擦除和写作业必须始终从虚拟 64K 边界开始的上层需求决定的：一个块要么完整写入，要么根本不写 RS MemHwAb 第24页。接受时，Fee 将状态置为 MEMIF_BUSY，将结果置为 MEMIF_JOB_PENDING，并返回 E_OK。对于 Fee_Read，适用相同的接受条件 SWS Fee 第26页。

为了使被中断的写入过程保持可识别，Fee 为每个块维护内部正确性信息 SWS Fee 第21页。在写入过程启动时，该块被标记为“corrupted”，成功结束后再次标记为“not corrupted”。该信息必须与上层通过 Fee_InvalidateBlock 设置的有效性严格区分开来。

时序图：写入作业被同步接收，但通过 Fee_MainFunction 和驱动程序反馈异步完成。在此过程中，该块首先被标记为“corrupted”，最后再次被标记为“not corrupted”。来源：[SWS_Fee_00088]、[SWS_Fee_00095]、[SWS_Fee_00098]、SWS Fee 第28页、SWS Fee 第21页、SWS Fee 第37页。

Fee_InvalidateBlock 将逻辑块声明为无效 [SWS_Fee_00092]。为此，它调用驱动程序的擦除函数和/或更改内部管理信息，该信息本身必须进行非易失性存储 SWS Fee 第32页。如果上层稍后读取此类块，Fee_MainFunction 会将结果设置为 MEMIF_BLOCK_INVALID。如果已配置，它还会调用上层的错误通知 SWS Fee 第38页。

Fee_EraseImmediateBlock [SWS_Fee_00094] 适用于诊断或类似的系统服务。它们可根据需要在事前预先擦除立即数数据区域。在此过程中是否进行物理擦除取决于具体实现 SWS Fee 第35页。对于 Fee_InvalidateBlock 和 Fee_EraseImmediateBlock，R20-11 明确规定仅在启用 DET 时才返回 E_NOT_OK [SWS_Fee_00092]，[SWS_Fee_00094]。

反馈、取消与模式切换

Flash 驱动程序通过 Fee_JobEndNotification [SWS_Fee_00095] 报告驱动程序作业的成功结束。Fee 随后执行必要的块管理，并在已配置的情况下调用上层的作业结束通知。它将仍处于 MEMIF_JOB_PENDING 状态的结果设置为 MEMIF_JOB_OK SWS Fee 第37页。根据存储堆栈的结构，回调可以在中断级别运行并向上穿透多个层。因此其运行时间必须保持较短；在中断级别调用是否被允许取决于系统设计 SWS Fee 第36页。

Fee_Cancel 调用 Flash 驱动程序的取消函数 [SWS_Fee_00089]。上层通过 MemIf_Cancel SWS MemIf 第20页 访问该服务。取消操作仅在状态 MEMIF_BUSY 下生效：Fee 调用驱动程序取消，重置其内部变量并返回到 MEMIF_IDLE。如果启用了 DET，Fee 会预先检查模块是否已初始化 SWS Fee 第29页。

各版本在 Fee_Cancel 方面存在差异。上述较新的版本将该服务归为异步服务，而 R20-11 则将其归为同步服务 [SWS_Fee_00089]。对于 R20-11，以同步分类为准。

Fee_SetMode 切换底层 Flash 驱动程序的操作模式 [SWS_Fee_00086]。相应的图表显示了调用链 NvM → MemIf_SetMode → Fee_SetMode → Fls_SetMode SWS Fee 第39页。Fee_GetVersionInfo 是唯一的重入 Fee 服务 [SWS_Fee_00093]。当 DET 启用时，它会检查传递的指针是否为 NULL SWS Fee 第34页。

发生错误时的行为

Fee 定义了五个开发错误代码 [SWS_Fee_00010]：

  • FEE_E_UNINIT (0x01)：在初始化之前调用了服务。
  • FEE_E_INVALID_BLOCK_NO (0x02)：无效的块编号。
  • FEE_E_INVALID_BLOCK_OFS (0x03)：无效的块偏移量。
  • FEE_E_PARAM_POINTER (0x04)：无效的数据指针。
  • FEE_E_INVALID_BLOCK_LEN (0x05)：无效的长度说明。

R20-11 补充了另外两个代码 [SWS_Fee_91002]。FEE_E_BUSY (0x06) 适用于在处理用户作业期间进行的调用。FEE_E_INVALID_CANCEL (0x08) 适用于在没有挂起作业的情况下调用 Fee_Cancel。因此，在状态 MEMIF_BUSY 下发起的全新作业应该会被拒绝并以 E_NOT_OK 响应。相关规则在此处仅不完整地给出 SWS Fee 第28页。

Flash 存储器的错误由 Flash 驱动程序检测；Fee 对此如何响应取决于具体实现 ErrorDescription 第40页。根据配置，通过两种途径之一进行报告。要么 MemIf 查询 Fee_GetJobResult 并接收 MEMIF_JOB_FAILED，要么 Fee 主动调用 NvM_JobErrorNotification。恢复由 NVRAM Manager 接管。上层通过 Fee_GetStatus 中的 MEMIF_UNINIT 识别未初始化的模块 ErrorDescription 第53页，[SWS_Fee_00090]。

时序图：驱动程序错误可选择通过向 NvM 发送回调或轮询 Fee_GetJobResult 来到达上层。来源：[SWS_Fee_00096]、[SWS_Fee_00099]、[SWS_Fee_00091]、ErrorDescription 第40页。

对于数据一致性，来自 R22-11 的图表描述了信息链 ErrorDescription 第64页：

  1. Fee 检查所读取数据的一致性，并将错误转发给 NVRAM Manager。
  2. NVRAM Manager 向 DEM 报告 NVM_E_INTEGRITY_FAILED。
  3. 它启动已配置的恢复机制：重新读取、冗余块或 ROM 块。
  4. 如果这些机制均失败，它会将结果设置为 NVM_REQ_INTEGRITY_FAILED。

在 Fee 端，推测与此对应的是结果 MEMIF_BLOCK_INCONSISTENT [SWS_Fee_00091]。

协作图：一致性错误由 Fee 传递给 NvM。NvM 将其报告给 DEM，尝试恢复，并在失败时设置 NvM 结果（截至 R22-11 版本）。来源：ErrorDescription 第64页。
