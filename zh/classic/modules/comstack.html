ComStack_Types 的作用：通信栈的通用类型词汇

模块“comstack”并非执行组件。它通过 ComStack_Types.h 提供 Classic 通信栈模块用于描述 PDU、缓冲区和通道的数据类型。根据规范，该发布版本的所有九种类型均“Available via ComStack_Types.h”，从 PduInfoType 到 NetworkHandleType（[SWS_COMTYPE_00011]、[SWS_COMTYPE_00038]）。PduLengthType 应在 ECU 的整个 AUTOSAR Com 栈中使用，总线驱动程序除外（[SWS_COMTYPE_00008]、SWS ComStackTypes 第16页）。系统边界由此划定：在总线驱动程序之上，接口、路由模块、传输协议以及上层均使用相同的类型。RTE 还针对大数据回调等功能从 ComStack_Types.h 中导入 BufReq_ReturnType、PduIdType、PduInfoType、PduLengthType 以及 RetryInfoType（SWS RTE 第833页）。

关于资料来源：所引用的文档出处主要来自发布版本 R23-11 至 R25-11。仅有 J1939Tp 规范的重试示意图在 R20-11 中同样得到证实。对 R20-11 具有规范约束力的是这些需求。差异会在文本中注明，例如 PNCHandleType（[SWS_COMTYPE_00036]、SWS ComStackTypes 第17页）。

上下文图：ComStack_Types.h 为总线驱动程序之上的所有协议栈模块提供通用类型；范围边界源自 EcuC 配置。来源：[SWS_COMTYPE_00005]、[SWS_COMTYPE_00008]、[SWS_COMTYPE_00038]、TPS EcuC 第205页、SWS RTE 第833页

PDU 标识：PduIdType 与模块局部句柄 ID

PduIdType 在 R20-11 中可变更为 uint16 或 uint8。其大小取决于单个软件模块所使用的最大 PDU 数量。生成器根据 ComStack_Cfg.h 中的 EcuC 配置生成范围边界（[SWS_COMTYPE_00005]）。在 EcuC 中，与之对应的是带有值 UINT8 和 UINT16 的参数 PduIdTypeEnum。若至少有一个模块管理超过 256 个 PDU，则必须使用 uint16（ECUConfiguration 第153页）。

PduIdType 值并非全系统键。它是相应被调用模块内的句柄：每个带有 PDU-API 的 BSW 模块均维护一个独立的 PDU-ID 列表作为查找表（SWS PduR 第33页）。PDU 路由模块通过源 ID 和目标 ID 标识路由路径。它在发送路径和确认路径中转换该 ID，并在此过程中保持 PduInfoType 值不变进行透传（SWS PduR 第33页）。为了使相邻模块指向同一 PDU，EcuC 定义了包含全局 Pdu 对象的跨模块 EcucPduCollection（TPS EcuC 第190页）。

时序图：PduR 针对每个目标模块转换 PduIdType 值，原样透传 PduInfoType，并将带有复位 ID 的确认转发给 Com。来源：SWS PduR 第33页、SWS PduR 第33页、[SWS_COMTYPE_00005]

PDU 内容：PduInfoType、PduLengthType 与元数据

PduInfoType 汇总了任意类型 PDU 的基础信息。SduDataPtr 指向有效数据，MetaDataPtr 指向元数据，且 SduLength 以字节为单位指定长度（[SWS_COMTYPE_00011]、SWS ComStackTypes 第17页）。长度的类型为 PduLengthType。根据 ECU 的最大 PDU 长度，它被生成为 uint8、uint16 或 uint32。在无分段的情况下，总线的帧大小决定了位宽，对于 FlexRay 最大为 255 字节，从而为 uint8。在有分段的情况下，分段 N-PDU 的最大长度决定了位宽（[SWS_COMTYPE_00008]、SWS ComStackTypes 第16页）。

元数据例如为 CAN-ID、套接字 ID 或诊断地址。它们由每个 PDU 静态配置的元素序列组成。超过 8 位的元素采用平台字节序（[SWS_COMTYPE_00011]）。元素的顺序和位置由全局 PDU 的 EcuC 配置确定。按长度排序使得无需进行填充（SWS BSWGeneral 第67页）。应用示例：对于套接字连接组，SoAd 仅在 PduInfoType.MetaDataPtr 指定的连接上进行发送（SWS SoAd 第30页）。

针对指针的生命周期适用一条运行规则：在接收指示时，传入的数据指针仅在指示返回前有效（SWS CanNm 第73页）。长度 0 具有多种特殊含义。带有 SduLength 0 的 CopyRxData 调用用于查询上层的空闲接收缓冲区；此时 SduDataPtr 允许为 NULL_PTR（SWS DoIP 第77页）。在发送时，SduLength 0 表示长度未知的 I-PDU。PduR 将该长度转发给所有目标 TP 模块（SWS PduR 第43页）。

TP 接收时的缓冲区握手：BufReq_ReturnType

BufReq_ReturnType 存储缓冲区请求的结果。这些值是固定预设的：BUFREQ_OK（0）、BUFREQ_E_NOT_OK（1）、BUFREQ_E_BUSY（2）以及 BUFREQ_E_OVFL（3）。在 BUFREQ_E_BUSY 的情况下，请求方必须在一定时间内重试该请求（[SWS_COMTYPE_00012]、SWS ComStackTypes 第19页）。

TP 接收分三步进行：

  1. 传输协议通过 PduR_<User:LoTp>StartOfReception 通告总长度 TpSduLength 以及首帧的数据。通过 bufferSizePtr 它接收返回的可用缓冲区，并据此计算块大小。
  2. 它通过 CopyRxData 透传各分段。
  3. 它通过 RxIndication 结束接收（SWS PduR 第92页）。

BUFREQ_OK 在此表示“连接已接受”，即使通报的缓冲区大小为 0（SWS PduR 第92页）。FlexRay-AR-TP 本身不保留消息缓冲区。它与上层逐段交换数据（SWS FrArTp 第50页）。

时序图：TP 接收以 StartOfReception 开始，通过 CopyRxData 提供数据，并以 RxIndication 结束；在单帧启动被拒绝时，不随之执行 RxIndication。来源：SWS FrArTp 第50页、SWS FrArTp 第50页、SWS PduR 第92页、[SWS_COMTYPE_00012]

带重试的发送：RetryInfoType 与 TpDataStateType

在逐段发送时，传输协议通过 CopyTxData 传递一个 RetryInfoType。它由 TpDataState 和 TxTpDataCnt 组成；后者是重新传输的字节的偏移量（[SWS_COMTYPE_00037]、SWS ComStackTypes 第20页）。这三种状态的含义为（[SWS_COMTYPE_00027]、SWS ComStackTypes 第19页）：

  • TP_DATACONF：迄今为止复制的所有数据均已确认，并允许从 TP 缓冲区中移除。
  • TP_DATARETRY：已复制的数据须从偏移量 TxTpDataCnt 开始重新提供。
  • TP_CONFPENDING：先前复制的数据必须予以保留。

SAE-J1939-TP 规范的重试示意图展示了各组件间的相互协作。每个块的第一包通过 TP_DATACONF 请求，后续各包通过 TP_CONFPENDING 请求。若一个 TP.DT 丢失，TP 将跳回该块的第一包。随后它通过 TP_DATARETRY 重新请求；其中 TxTpDataCnt 是到块起始处的偏移量（SWS J1939Tp 第55页）。FrArTp 在启用重试的非分段发送时同样会设置 TP_CONFPENDING（SWS FrArTp 第50页）。

时序图：针对每个块，TpDataState 控制是确认数据、保留数据还是从块起始处重新复制。来源：SWS J1939Tp 第55页、[SWS_COMTYPE_00027]、[SWS_COMTYPE_00037]

PduR 用于单帧的直接 TP 网关展示了上层如何对该状态做出反应。在 TP_DATACONF、TP_CONFPENDING 或缺少 RetryInfoType 指针的情况下，它会复制 SduLength 字节。在 TP_DATARETRY 的情况下，它事先将位置回退 TxTpDataCnt 字节（SWS PduR 第57页）。并非每个上层都会评估重试信息：根据规范，对于 LdCom 回调，LdCom 及其上层不处理 retry（SWS LdCom 第34页）。自 AUTOSAR 4.3.1 起，PduR_<User:LoTp>CopyTxData 中的参数为指向 const RetryInfoType 的指针（SWS PduR 第3页）。

活动图：PduR 根据 TpDataState 决定是直接复制、复位位置还是拒绝请求。来源：SWS PduR 第57页、[SWS_COMTYPE_00027]、[SWS_COMTYPE_00012]

通道、部分网络与可修改的 TP 参数

NetworkHandleType 存储通信通道的标识符。它是一个从零开始的 uint8，取值范围为 0..255（[SWS_COMTYPE_00038]、SWS ComStackTypes 第20页）。在 Mirror_GetNetworkId 中它代表 ComM 通道，在 CanSM_TxTimeoutException 中它代表受影响的 CAN 网络（SWS Mirror 第78页、SWS CanSM 第87页）。诸如 Nm_RemoteSleepIndication 等网络管理回调也通过该类型标识 NM 通道（SWS Nm 第89页）。

PNCHandleType 存储部分网络群集的标识符。在 R20-11 中它派生自 uint8（[SWS_COMTYPE_00036]）。而当前来自 R23-11 的文档出处则将 uint16 列为基础类型（SWS ComStackTypes 第17页）。对于 R20-11，适用需求版本 uint8。

TPParameterType 指定应在运行时修改的参数。其取值为 TP_STMIN（Separation Time）、TP_BS（Block Size）以及 TP_BC（FlexRay 传输协议的带宽控制）（[SWS_COMTYPE_00031]、SWS ComStackTypes 第18页）。各模块对使用做出了限制。J1939Tp_ChangeParameter 仅接受取值不超过 255 的 TP_BS（SWS J1939Tp 第42页）。FrArTp 拒绝在正在进行的接收期间通过 E_NOT_OK 进行修改（SWS FrArTp 第49页）。

发生错误时的行为

这些类型本身不包含错误行为。但它们传递各个模块据以做出响应的结果（[SWS_COMTYPE_00012]）。在非分段 FrArTp 发送中适用：

  • 若 PduR_FrArTpCopyTxData 返回 BUFREQ_E_BUSY，TP 将重复该调用直至 FrArTpTimeCs 超时。
  • 在 BUFREQ_E_NOT_OK 或超时后，它将中止并调用带有 E_NOT_OK 的 PduR_FrArTpTxConfirmation。
  • 若 PduR_FrArTpStartOfReception 针对单帧返回 BUFREQ_E_NOT_OK 或 BUFREQ_E_OVFL，接收立即终止，且不执行 PduR_FrArTpRxIndication（SWS FrArTp 第50页）。

活动图：BUFREQ_E_BUSY 会导致重试直至超时；BUFREQ_E_NOT_OK 和 BUFREQ_E_OVFL 会导致中止。来源：SWS FrArTp 第50页、SWS FrArTp 第44页、[SWS_COMTYPE_00012]

在直接 TP 网关中，针对 TP_DATARETRY 适用两条规则。若 PduR 无法回退位置，则以 BUFREQ_E_NOT_OK 响应，并保持位置和数据不变。若回退后缺少数据，则以 BUFREQ_E_BUSY 响应（SWS PduR 第57页）。在动态网关（On-the-fly-Gateway）中，PduR 不支持重试已发送的数据（SWS PduR 第58页）。在多播 TP 路由中，根据文档出处，它针对 TP_DATARETRY 返回 E_NOT_OK（SWS PduR 第41页）。

此外，PduR 本身不采取任何错误处理措施。它将返回值中的错误转发给负责处理的上层源模块（SWS PduR 第46页，SWS PduR 第49页）。

Communication Stack Types (ComStack_Types)

跨所有通信层使用标准化类型、PDU标识符、长度和缓冲区请求类型（PduIdType、PduLengthType、PduInfoType、BufReq_ReturnType）。

  • typedef PduLengthType This type shall be used within the entire AUTOSAR Com Stack of an ECU except for bus drivers.
  • struct PduInfoType Variables of this type shall be used to store the basic information about a PDU of any type, namely a pointer variable...
  • typedef PNCHandleType Used to store the identifier of a partial network cluster.
  • enum TPParameterType Specify the parameter to which the value has to be changed (BS or STmin).
  • enum BufReq_ReturnType Variables of this type shall be used to store the result of a buffer request.
  • enum TpDataStateType Variables of this type shall be used to store the state of TP buffer.
  • struct RetryInfoType Variables of this type shall be used to store the information about Tp buffer handling.
  • typedef NetworkHandleType Variables of the type Network Handle Type shall be used to store the identifier of a communication channel.
