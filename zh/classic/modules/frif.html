封装 FlexRay 驱动程序和收发器，并针对每个集群控制状态、PDU 流量以及作业列表执行。

FlexRay Interface 将 FlexRay 驱动程序和收发器驱动程序封装在统一的控制器索引之后，并在上层与总线之间中继 PDU。它为每个集群维护一个包含状态 FRIF_STATE_OFFLINE 和 FRIF_STATE_ONLINE 的状态机，FlexRay State Manager 通过 FrIf_SetState 对其进行切换 [SWS_FrIf_05174]。发送和接收在集群的 Job List Execution 中按时间控制执行，并且仅在 online 状态下进行（SWS FrIf 第37页）。启动、停止和唤醒服务以异步方式工作。因此，调用者通过 FrIf_GetPOCStatus 获取所达到的 POC 状态。

FlexRay Interface（FrIf）位于上层通信模块与驱动程序 Fr 及 FrTrcv 之间。为了实现其核心功能，它需要驱动程序服务如 Fr_ControllerInit、Fr_GetPOCStatus 和 Fr_ReceiveRxLPdu [SWS_FrIf_05043]。大多数控制服务封装了一个驱动程序服务：它们根据静态配置将 FrIf_CtrlIdx 转换为元组（FlexRay Driver | Fr_CtrlIdx），并返回驱动程序的结果（SWS FrIf 第55页）。启动、停止、冷启动使能和唤醒以异步方式工作 [SWS_FrIf_05005]。因此，调用者使用 FrIf_GetPOCStatus 获取实际达到的状态。

FrIf 为每个集群维护一个包含状态 FRIF_STATE_OFFLINE 和 FRIF_STATE_ONLINE 的状态机 [SWS_FrIf_05755]。FrIf_Init() 将每个集群置为 Offline。环境使用 FrIf_SetState 以及 FRIF_GOTO_ONLINE 或 FRIF_GOTO_OFFLINE 请求状态转换 [SWS_FrIf_05174]。仅在 online 时才执行接收、发送和发送确认。在切换到 Offline 时，Upper Layers 会针对未决确认收到 E_NOT_OK [SWS_FrIf_05501]。

整个流程由 FrSM 控制。在启动过程中，它将收发器切换到 Normal，启动通信，并在需要时释放冷启动。然后，它查询 POC 状态直至达到 FR_POCSTATE_NORMAL_ACTIVE，并在此之后才将集群设置为 online（SWS FrSM 第50页）。关闭过程分两个阶段进行：首先是 Offline 和 Halt，然后是控制器重新初始化和收发器 Standby（SWS FrSM 第58页）。

FrIf_Transmit 起初仅对发送请求进行计数 [SWS_FrIf_05033]。实际的传输在每个集群的 Job List Execution 中进行 [SWS_FrIf_05040]。在此处，FrIf 通过 TriggerTransmit 获取数据、确认传输并报告接收。它将错误分为三类进行报告：向 DET 报告开发错误 [SWS_FrIf_05145]，报告运行时错误 FRIF_E_JLE_SYNC [SWS_FrIf_05432]，以及按通道向 DEM 报告生产错误 [SWS_FrIf_05146]。

在 FlexRay 协议栈中的角色及系统边界

FlexRay Interface（FrIf）位于上层通信模块与底层硬件驱动程序之间。为了实现其核心功能，它需要 FlexRay 驱动程序的服务。其中包括 Fr_ControllerInit、Fr_GetPOCStatus、Fr_ReceiveRxLPdu 和 Fr_CheckTxLPduStatus 以及 Det_ReportRuntimeError [SWS_FrIf_05043]。可选的包括 Fr_AllSlots、Fr_CancelTxLPdu 和 Dem_SetEventStatus [SWS_FrIf_05044] 等。头文件结构展示了 Fr.h、FrTrcv.h、PduR_FrIf.h、FrNm_Cbk.h 和 FrTp_Cbk.h 的集成（SWS FrIf 第18页）。

生命周期由 FlexRay State Manager 控制。它将其功能元素映射到 FrIf 调用（SWS FrSM 第22页）。PDU 用户通过可配置的回调进行连接：<User_RxIndication>、<User_TxConfirmation> 和 <User_TriggerTransmit> [SWS_FrIf_05045] [SWS_FrIf_05046] [SWS_FrIf_05047]。允许的目标包括 FrTSyn [SWS_FrIf_05434]、FrNm 和 FrArTp 等。具有类似接口的 Complex Drivers 也可以被连接（SWS FrIf 第97页）。其他用户具有各自的任务：

  • FrTSyn 读取时间和状态信息（SWS FrTSyn 第13页）。
  • EcuM 检查收发器唤醒（SWS EcuM 第186页）。
  • Bus Mirroring 切换报文镜像（SWS Mirror 第31页）。

适用于所有驱动程序的单一控制器索引：包装器原理

大多数控制服务通过 FrIf_CtrlIdx 寻址 Communication Controller（CC）。以 FrIf_ControllerInit 为例可以展示这种模式。该服务根据静态配置将索引转换为元组（FlexRay Driver | Fr_CtrlIdx）。随后它调用所确定驱动程序的 Fr_ControllerInit()（SWS FrIf 第55页）。返回值反映驱动程序的结果 [SWS_FrIf_05004]。按照相同的模式，其他服务也封装了它们对应的驱动程序操作：启动、停止、中止、冷启动使能、唤醒、POC 状态和全局时间 [SWS_FrIf_05005] [SWS_FrIf_05006] [SWS_FrIf_05007] [SWS_FrIf_05017] [SWS_FrIf_05011] [SWS_FrIf_05014] [SWS_FrIf_05015]。这同样适用于绝对定时器服务 [SWS_FrIf_05021] [SWS_FrIf_05025] [SWS_FrIf_05029]。

对于调用者而言，同步性至关重要。FrIf_StartCommunication、FrIf_HaltCommunication、FrIf_AllowColdstart 和 FrIf_SendWUP 以异步方式工作 [SWS_FrIf_05005] [SWS_FrIf_05011]。相比之下，FrIf_ControllerInit 和 FrIf_AbortCommunication 以同步方式工作 [SWS_FrIf_05007]。对于异步服务，E_OK 仅表示驱动程序调用返回了 E_OK。实际达到的 POC 状态由 FrSM 通过使用 FrIf_GetPOCStatus 重复查询来确定（SWS FrSM 第50页）。

收发器服务还寻址一个通道 FrIf_ChnlIdx，并封装 FlexRay Transceiver Driver [SWS_FrIf_05034] [SWS_FrIf_05036] [SWS_FrIf_05039]。在此过程中，值 FR_CHANNEL_AB 是非法的（SWS FrIf 第73页）。像 FrIf_GetMacroticksPerCycle 或 FrIf_GetCycleLength 这样的查询不会调用驱动程序，而是读取静态配置 [SWS_FrIf_05018] [SWS_FrIf_05239]。

每个集群的状态机：FRIF_STATE_OFFLINE 和 FRIF_STATE_ONLINE

FrIf 为每个 FlexRay 集群维护独立的状态机。FrIf_Init() 首先将每个集群设置为 FRIF_STATE_OFFLINE（SWS FrIf 第25页）。这两个状态具有以下含义 [SWS_FrIf_05755]：

  • FRIF_STATE_OFFLINE：CC 未就绪于通信，集群未同步。
  • FRIF_STATE_ONLINE：CC 已就绪于通信，集群已同步。

环境使用 FrIf_SetState 请求状态转换，且使用字面量 FRIF_GOTO_ONLINE 或 FRIF_GOTO_OFFLINE [SWS_FrIf_05174] [SWS_FrIf_05303]。只有当集群处于另一种状态时，转换才会发生（SWS FrIf 第25页）。FrIf_GetState 是可重入的 [SWS_FrIf_05170]，而 FrIf_SetState 则不可重入。

状态决定了是否发生数据通信。在 Offline 状态下，FrIf 不执行任何通信服务。在 Online 状态下，它执行接收、发送和发送确认（SWS FrIf 第25页）。在切换到 Offline 时，FrIf 会检查每个 PDU：如果其 TxConfCounter > 0，则 Upper Layer 会收到 <UL>_TxConfirmation(id, E_NOT_OK) [SWS_FrIf_05501]。从 R23-11 开始，规范还要求 FrIf_Transmit() 在状态 Offline 下返回 E_NOT_OK（SWS FrIf 第68页）。较早的示意图显示了四种状态，其中包括 FRIF_STATE_HALT（SWS FrIf 第28页）。它不适用于 R20-11，因为此处的 FrIf_StateType 仅包含两个值 [SWS_FrIf_05755]。

状态图：每个集群都以 offline 启动，并且仅在通过 FrIf_SetState 提出请求时才发生转换。在切换到 Offline 时，未决的发送确认会被否定终止。来源：[SWS_FrIf_05174]、[SWS_FrIf_05303]、[SWS_FrIf_05501]、SWS FrIf 第25页

由 FrSM 主导的启动、唤醒和关闭

EcuM 使用 FrIf_Init 初始化 FrIf，且在 FrSM_Init 之前进行（SWS FrSM 第46页）。在此过程中，它传递指向 FrIf_ConfigType 的指针 [SWS_FrIf_05003]。所有后续步骤均由 FrSM 通过其功能元素进行控制。每个元素针对集群的每个控制器调用相应的 FrIf 服务（SWS FrSM 第22页）：

  • FE_CONFIG 调用 FrIf_ControllerInit。
  • FE_START 调用 FrIf_StartCommunication。
  • FE_ALLOW_COLDSTART 调用 FrIf_AllowColdstart，但仅在设置了 FrSMIsColdstartEcu 时执行。
  • FE_WAKEUP 调用 FrIf_SendWUP。
  • FE_HALT 调用 FrIf_HaltCommunication。

总线唤醒后的被动启动按以下顺序进行（SWS FrSM 第50页）：

  1. 收发器被切换到 FRTRCV_TRCVMODE_NORMAL。
  2. 启动通信。
  3. 冷启动节点还会释放冷启动。
  4. FrSM 查询 POC 状态，直至达到 FR_POCSTATE_NORMAL_ACTIVE。
  5. 只有在此之后才执行 FrIf_SetState(…, FRIF_GOTO_ONLINE)。

在主动唤醒时，双通道节点使用 FrIf_SetWakeupChannel 选择唤醒通道 [SWS_FrIf_05010]。FrIf_GetWakeupRxStatus 以位编码方式报告在哪个通道上接收到了唤醒 [SWS_FrIf_05102]。

时序图：直至 online 状态的被动启动。FrIf 仅执行单个服务，流程控制由 FrSM 负责。Interpretation：启动前的顺序经过了简化。来源：SWS FrSM 第50页、SWS FrSM 第21页

关闭过程分两个阶段进行。首先，FrSM 使用 FRIF_GOTO_OFFLINE 将集群置为 offline 并调用 FrIf_HaltCommunication。稍后，它重新初始化控制器并将收发器置于模式 STANDBY（SWS FrSM 第58页）。这两个阶段之间的延迟由定时器 t_TrcvStdbyDelay 决定（SWS FrSM 第21页）。

时序图：从 FullCom 到 NoCom 的转换，先是停止，然后是重新初始化和 Standby。Interpretation：第一阶段内部的顺序经过了简化。来源：SWS FrSM 第58页、SWS FrSM 第56页

PDU 通信：发送请求与 Job List Execution

FrIf_Transmit 是同步的，并且对于不同的 TxPduId 是可重入的 [SWS_FrIf_05033]。在解耦缓冲区访问时，FrIf 仅将发送请求的次数存储在 TrigTxCounter 中，而不存储数据本身（SWS FrIf 第38页）。对于定长 Immediate-PDU，FrIf 会根据配置检查所传递的长度 [SWS_FrIf_05757]。可以使用 FrIf_CancelTransmit 中止正在进行的传输 [SWS_FrIf_05070]。

实际的总线通信在 Job List Execution Function FrIf_JobListExec_<FrIfCluster.ShortName> 中进行，每个集群都存在该函数 [SWS_FrIf_05040]。在各图表中，它由中断服务例程调用（SWS FrIf 第102页）。该例程大概是通过 CC 的 Absolute Timer 触发的 [SWS_FrIf_05021]。只要集群处于在线状态，周期性 FrIf_MainFunction_<FrIfCluster.ShortName> [SWS_FrIf_05042] 就会监控作业列表的持续执行。这也包括（重新）同步（SWS FrIf 第26页）。

每个 Communication Operation 仅在状态 FRIF_STATE_ONLINE 下执行，否则将被忽略（SWS FrIf 第37页）。最重要的操作按如下方式工作：

  • 解耦发送：对于 TrigTxCounter > 0 的每个 PDU，FrIf 通过 <User_TriggerTransmit> [SWS_FrIf_05047] 获取数据。随后它将报文传递给 Fr_TransmitTxLPdu()。如果驱动程序拒绝，FrIf 会将计数器重置为其先前状态（SWS FrIf 第102页）。
  • TX_CONFIRMATION：如果驱动程序报告 FR_TRANSMITTED，FrIf 将通过 <User_TxConfirmation> [SWS_FrIf_05046] 确认传输。
  • RECEIVE_AND_INDICATE：FrIf 最多读取 FrIfRxComOpMaxLoop 次，并通过 <User_RxIndication> [SWS_FrIf_05045] 报告每次接收（SWS FrIf 第41页）。

诸如 <Free_Op_A> 等硬件特定操作同样在作业列表中运行 [SWS_FrIf_05316]。FrIf 通过 <UL_TxConflictNotification> [SWS_FrIf_91001] 报告发送冲突。

时间基准、附加服务与配置

FrTSyn 仅在 FrIf_GetState 返回值 FRIF_STATE_ONLINE 时才调用 FrIf_GetGlobalTime。只有在此之后，CC 才与全局 FlexRay 时间同步（SWS FrTSyn 第19页）。FrIf_GetGlobalTime 也允许在 Exclusive Area 内被调用（SWS FrIf 第64页）。FrNm 同样通过该服务确定当前周期（SWS FrNm 第38页）。FrIf_GetNmVector [SWS_FrIf_05016] 可通过 FrIfGetNmVectorSupport 关闭。

FrIf_EnableBusMirroring 针对每个集群确定是否为每个发送或接收的报文调用 Mirror_ReportFlexRayFrame。如果 FrIfBusMirroringSupport 被全局停用，则该服务返回 E_NOT_OK [SWS_FrIf_05726]。Post-Build 配置是特定于实现的，且仅能通过指向 FrIf_ConfigType 的指针进行访问 [SWS_FrIf_05301]。自 R22-11 起的一张图表展示了其结构：存在一个或多个 FrIfCtrlIdx 为 0…31 的 FrIfController，每个带有最多两个收发器（SWS FrIf 第139页）。诸如 FrIf_DisableLPdu [SWS_FrIf_05710] 等可选服务通过预编译开关启用，此处通过 FrIfDisableLPduSupport（SWS FrIf 第84页）。

发生错误时的行为

如果 FrIfDevErrorDetect 设置为 ON，各服务会向 Det_ReportError 报告开发错误。错误代码范围从 FRIF_E_PARAM_POINTER (0x01) 到 FRIF_E_INV_FRIF_STATE (0x0A)，除其他外还包括 FRIF_E_INV_CTRL_IDX 和 FRIF_E_UNINIT [SWS_FrIf_05145]。最重要的情形：

  • 无效的 FrIf_CtrlIdx：包装函数报告 FRIF_E_INV_CTRL_IDX 并返回 E_NOT_OK（SWS FrIf 第55页）。
  • FrIf_SetState 中的无效转换：该服务报告 FRIF_E_INV_FRIF_STATE [SWS_FrIf_05037]。
  • Immediate-PDU 长度错误：FrIf_Transmit() 返回 E_NOT_OK 并报告 FRIF_E_INV_PDULENGTH [SWS_FrIf_05757]。

活动图：包装服务从参数检查、索引转换到返回驱动程序结果的流程。来源：[SWS_FrIf_05004]、[SWS_FrIf_05145]、SWS FrIf 第55页

规范将 FRIF_E_JLE_SYNC 定义为运行时错误。当 Job List Execution 失去与 FlexRay 时间的同步时，会发生该错误 [SWS_FrIf_05432]。解释：恢复工作可能属于通过 Main Function 进行的（重新）同步任务（SWS FrIf 第26页）。

FrIf 按通道向 DEM 报告生产错误：FRIF_E_NIT_CH_A/B、FRIF_E_SW_CH_A/B 和 FRIF_E_ACS_CH_A/B [SWS_FrIf_05146]。一旦诸如 vSS!SyntaxError 等错误位被置位，报告内容即为 DEM_EVENT_STATUS_PREFAILED [SWS_FrIf_05426] [SWS_FrIf_05428]。相比之下，集群启动的结果由 FrSM 报告（SWS FrSM 第50页）。
