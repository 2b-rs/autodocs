FrIf作为FlexRay栈与硬件驱动程序之间的中介

FlexRay Interface对通信栈的模块封装了FlexRay驱动程序（Fr）和收发器驱动程序（FrTrcv）。大多数控制服务是薄封装。例如，FrIf_StartCommunication根据静态配置将FrIf范围的控制器索引转换为元组（FlexRay驱动程序 | 驱动程序特定的Fr_CtrlIdx）。随后它调用所确定的驱动程序的Fr_StartCommunication()（[SWS_FrIf_05005]、SWS FrIf 第56页）。所需的驱动程序服务被定义为强制接口和可选接口（[SWS_FrIf_05043]、[SWS_FrIf_05044]）。其中包括CC-CHI命令’FREEZE’、’DEFERRED_HALT’、’WAKEUP’和’ALL_SLOTS’。

用户访问接口的不同部分：

  • FrSM通过FE_CONFIG、FE_START和FE_HALT等功能元素控制控制器和集群（SWS FrSM 第22页）。
  • PduR接收收到的I-PDU并将其传递给Com（SWS PduR 第98页）。
  • FrNm通过FrIf_Transmit发送NM-Vote和NM-Data，并通过FrIf_GetGlobalTime读取周期（SWS FrNm 第38页）。
  • FrTp同样通过FrIf_Transmit发送其N-PDU（SWS FrTp 第20页）。
  • FrTSyn使用状态和时间服务（SWS FrTSyn 第13页）。

从FrIf_Init到同步集群

FrIf_Init接收指向FrIf_ConfigType的指针（[SWS_FrIf_05003]、[SWS_FrIf_05301]）。该函数将每个集群的FrIf_State设置为FRIF_STATE_OFFLINE（SWS FrIf 第25页）。在初始化序列中，EcuM在FrSm_Init之前调用FrIf_Init（SWS FrSM 第46页）。

启动过程由FrSM执行。它为集群的每个控制器调用FrIf_ControllerInit、FrIf_StartCommunication和FrIf_AllowColdstart（[SWS_FrIf_05004]、[SWS_FrIf_05017]）。FrIf_AllowColdstart仅在FrSMIsColdstartEcu时跟随，并可通过定时器t1延迟（SWS FrSM 第21页）。

启动、冷启动使能、唤醒和停止均为异步（[SWS_FrIf_05011]、[SWS_FrIf_05006]）。在此，E_OK仅表示驱动程序调用返回了E_OK。FrSM通过FrIf_GetPOCStatus周期性查询实际协议状态，直至达到FR_POCSTATE_NORMAL_ACTIVE。在此之后，它才会请求FRIF_GOTO_ONLINE（[SWS_FrIf_05014]、SWS FrSM 第50页）。

序列图：仅当通过轮询确认POC状态为NORMAL_ACTIVE后，FrIf集群才会上线。来源：SWS FrSM 第46页、SWS FrSM 第50页、[SWS_FrIf_05005]

针对唤醒，提供了多项服务：

  • FrIf_SendWUP发送Wakeup-Pattern。
  • 对于双通道节点，FrIf_SetWakeupChannel用于选择唤醒通道。此时不得使用FR_CHANNEL_AB（[SWS_FrIf_05010]、SWS FrIf 第61页）。
  • FrIf_SetTransceiverMode、FrIf_GetTransceiverWUReason和FrIf_GetWakeupRxStatus提供收发器控制和唤醒原因（[SWS_FrIf_05034]、[SWS_FrIf_05036]、[SWS_FrIf_05102]）。
  • 在Sleep模式下，EcuM集成通过FrIf_CheckWakeupByTransceiver检查总线唤醒（[SWS_FrIf_05041]、SWS EcuM 第178页）。

序列图：具有本地唤醒原因的双通道节点激活两个收发器，将通道A设为唤醒通道并发送WUP。解读：调用顺序根据图中文本重构。来源：SWS FrSM 第52页、SWS FrSM 第22页

集群状态ONLINE/OFFLINE作为通信服务的开关

每个集群恰好存在两个状态：FRIF_STATE_OFFLINE和FRIF_STATE_ONLINE（[SWS_FrIf_05755]）。状态转换通过FrIf_SetState以及取自FrIf_StateTransitionType的值来请求（[SWS_FrIf_05174]、[SWS_FrIf_05303]）。FRIF_GOTO_ONLINE仅在OFFLINE状态下生效，FRIF_GOTO_OFFLINE仅在ONLINE状态下生效；任何其他请求均不会触发状态转换（SWS FrIf 第25页）。

FrIf_GetState是可重入的，而FrIf_SetState则不是（[SWS_FrIf_05170]、SWS FrIf 第63页）。两个服务都需要一个集群索引FrIf_ClstIdx。一些FrSM示意图将该参数标记为“CtrlIdx”；具体以函数签名准。

在OFFLINE状态下，FrIf_Transmit拒绝发送请求并返回E_NOT_OK（SWS FrIf 第68页）。切换到OFFLINE时，FrIf会通过<UL>_TxConfirmation(id, E_NOT_OK)确认返回TxConfCounter > 0的每个PDU（[SWS_FrIf_05501]）。一张较旧的示意图还显示了HALT和RXONLY状态。这些状态不适用于R20-11，因为[SWS_FrIf_05755]仅包含两个字面量（SWS FrIf (alt) 第28页）。

状态图：集群生命周期始于OFFLINE，且仅在明确请求时才发生转换。来源：[SWS_FrIf_05755]、[SWS_FrIf_05303]、[SWS_FrIf_05501]、SWS FrIf 第25页

Job List Execution：基于时间控制的发送与接收

每个集群都有一个Job List Execution Function FrIf_JobListExec_<FrIfCluster.ShortName>和一个Main Function（[SWS_FrIf_05040]、[SWS_FrIf_05042]）。Main Function由BSW调度器周期性调用。在ONLINE状态下，它监视作业列表的持续执行，包括（重新）同步（SWS FrIf 第26页）。示意图显示ISR作为触发源，且FrIfJobList引用了FrIfAbsTimer。因此，推测是由绝对定时器中断触发作业列表（SWS FrIf 第125页）。

对于通过FrIf_Transmit的发送，存在两种缓冲模式（[SWS_FrIf_05033]）：

  • 对于Immediate-PDU，数据直接传送到Fr_TransmitTxLPdu。若长度固定，则会对照配置进行检查（[SWS_FrIf_05757]、SWS FrIf 第106页）。
  • 对于解耦访问，FrIf_Transmit仅预记该PDU。数据随后才由作业列表通过<UL_TriggerTransmit>提取（[SWS_FrIf_05047]、SWS FrIf 第107页）。

序列图：在解耦发送中，发送请求与数据获取位于不同的上下文中；计数器确保重试与取消。来源：SWS FrIf 第107页、SWS FrIf 第102页

作业列表通过Fr_CheckTxLPduStatus获取发送确认。然后它减少TxConfCounter并调用<UL_TxConfirmation>（[SWS_FrIf_05046]、SWS FrIf 第112页）。在接收时，Fr_ReceiveRxLPdu将报文帧读取到临时缓冲区中。随后FrIf检查每个PDU的Update-Bit。<UL_RxIndication>要么立即执行（ReceiveAndIndicate），要么稍后从FrIf缓冲区中执行（[SWS_FrIf_05045]、SWS FrIf 第115页、SWS FrIf 第117页）。

作业列表的其他操作：

  • Prepare LPdu在需要时重新配置硬件缓冲区（SWS FrIf 第113页）。
  • <Free_Op_A>和<Free_Op_B>集成用户自定义操作（[SWS_FrIf_05316]、[SWS_FrIf_05317]）。
  • FrIf通过<UL_TxConflictNotification>报告发送冲突（[SWS_FrIf_91001]）。

针对每个操作的ONLINE检查仅在后续版本中得到明确证实（SWS FrIf 第41页）。但这与[SWS_FrIf_05755]中的R20-11状态描述相符。

活动图：在Receive-and-Indicate中，集群状态、接收状态以及Update-Bit共同决定转发。来源：SWS FrIf 第115页、SWS FrIf 第41页、[SWS_FrIf_05045]

面向相邻模块的时基、定时器和状态服务

FrIf_GetGlobalTime提供周期和宏刻度。该服务可在Exclusive Area内被调用（[SWS_FrIf_05015]、SWS FrIf 第64页）。仅当FrIf_GetState报告状态FRIF_STATE_ONLINE时，FrTSyn才会调用它；唯有此时时间信息才有效（SWS FrTSyn 第19页）。每个周期的宏刻度数、宏刻度持续时间以及周期长度来自静态配置（[SWS_FrIf_05018]、[SWS_FrIf_05019]、[SWS_FrIf_05239]）。

序列图：FrTSyn时间从节点仅在通过ONLINE检查后才读取FlexRay时间。来源：SWS FrTSyn 第38页、SWS FrTSyn 第19页、[SWS_FrIf_05434]

绝对定时器通过专用服务进行设置、停止、使能、禁用、确认和查询（[SWS_FrIf_05021]、[SWS_FrIf_05023]、[SWS_FrIf_05025]、[SWS_FrIf_05031]、[SWS_FrIf_05029]、[SWS_FrIf_05027]）。对于同一个 CC，这些服务是不可重入的。对于诊断和 FrSM，提供了通道状态、时钟校正、同步帧列表、启动帧以及 NM 向量（[SWS_FrIf_05030]、[SWS_FrIf_05071]、[SWS_FrIf_05072]、[SWS_FrIf_05073]、[SWS_FrIf_05016]）。在 Key-Slot-Only 模式下，FrIf_AllSlots 使能完整的时隙运行（[SWS_FrIf_05020]、SWS FrSM 第57页）。

索引、配置与可选服务

FrIf 使用三个索引空间：

  • FrIf_CtrlIdx 寻址 CC 并被转换为驱动程序索引。
  • FrIf_ClstIdx 寻址集群，例如在 FrIf_EnableBusMirroring 中（[SWS_FrIf_05726]）。
  • FrIf_ChnlIdx 寻址通道。对于收发器服务，FR_CHANNEL_AB 是不允许的（SWS FrIf 第69页）。

FrIf_ConfigType 是一种特定于实现的 Post-Build 结构体，仅允许使用指向它的指针（SWS FrIf 第50页）。

许多附加服务可在编译时启用或禁用。其中包括通过 FrIfDisableLPduSupport 的 FrIf_DisableLPdu（[SWS_FrIf_05710]、SWS FrIf 第84页）以及通过 FrIfCancelTransmitSupport 的 FrIf_CancelTransmit（[SWS_FrIf_05070]、SWS FrIf 第88页）。如果 Bus Mirroring 被全局禁用，则返回 E_NOT_OK（SWS FrIf 第92页）。在运行时，可通过 FrIf_ReconfigLPdu 重新配置 L-PDU，并通过 FrIf_ReadCCConfig 读取 CC 参数（[SWS_FrIf_05048]、[SWS_FrIf_05313]）。

发生错误时的行为

FrIf 仅在 FrIfDevErrorDetect = ON 时向 Det_ReportError 报告开发错误（SWS FrIf 第59页）。错误代码除其他外包括 FRIF_E_INV_CTRL_IDX、FRIF_E_INV_CLST_IDX、FRIF_E_INV_CHNL_IDX、FRIF_E_PARAM_POINTER、FRIF_E_UNINIT 和 FRIF_E_INV_FRIF_STATE（[SWS_FrIf_05145]、[SWS_FrIf_05037]）。当驱动程序返回 E_NOT_OK 或检测到开发错误时，包装函数会返回 E_NOT_OK（[SWS_FrIf_05004]）。

如果 Job List Execution 失去与全局时间的同步，FrIf 会报告运行时错误 FRIF_E_JLE_SYNC（[SWS_FrIf_05432]、SWS FrIf 第45页）。每个通道在 NIT、Symbol Window 和 ACS 中的错误作为 Production Errors 通过带有 DEM_EVENT_STATUS_PREFAILED 的 Dem_SetEventStatus 发送给 DEM（[SWS_FrIf_05146]、[SWS_FrIf_05426]、[SWS_FrIf_05428]）。不过 [SWS_FrIf_05430] 的文本在准则中提及了 FRIF_E_SW_CH_B 而非 FRIF_E_ACS_CH_B；这是需求中的一处不一致。

关闭有两种方式。FrIf_AbortCommunication 是同步的并触发 ’FREEZE’，而 FrIf_HaltCommunication 则触发延迟的 ’DEFERRED_HALT’（[SWS_FrIf_05007]、SWS FrIf 第94页）。常规关闭时，FrSM 将集群置于离线状态并停止控制器。随后，它将收发器置于待机状态并重新初始化控制器（SWS FrSM 第58页）。
