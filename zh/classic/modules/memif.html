通过设备索引将 NVRAM 管理器的存储作业转发至 Flash EEPROM 仿真或 EEPROM 抽象。

MemIf 将 NVRAM 管理器的存储作业转发至 Fee 或 Ea 模块，并在统一 API 之后隐藏其数量 SWS MemIf 第7页。参数 DeviceIndex 用于选择模块；如果仅配置了一个模块，则该参数会被忽略，且 MemIf 实现为宏集 SWS MemIf 第17页。服务以同步方式接受作业并传递返回值，而存储操作则在底层以异步方式运行。状态和结果由 MemIf_GetStatus 和 MemIf_GetJobResult 提供。在开发错误检测处于激活状态时，错误的调用会返回 E_NOT_OK 或 MEMIF_JOB_FAILED。

Memory Abstraction 接口取代了原先用于 Flash 和 EEPROM 的驱动程序接口层。它允许 NVRAM 管理器通过统一 API 访问多个抽象模块：Flash EEPROM 仿真（Fee）和 EEPROM 抽象（Ea）SRS MemHwAb 第5页。MemIf 隐藏了这些模块的数量，并在线性地址空间上提供虚拟分段 SWS MemIf 第7页。

MemIf 没有自己的存储逻辑。参数 DeviceIndex 用于选择模块；如果仅配置了一个模块，则该参数会被忽略，且 MemIf 实现为宏集。在存在多个模块时，分配大致通过函数指针表进行 SWS MemIf 第17页。在 R20-11 中，DeviceIndex 的类型为 uint8 [SWS_MemIf_00039]；后续版本使用 uint16。

各服务同步接受作业并传递模块的返回值 [SWS_MemIf_00040]。随后，存储操作在下层的主函数中异步运行。NvM 通过来自 Fee/Ea 的回调或通过轮询 MemIf_GetJobResult 来获知完成情况 SWS Fee 第48页。MemIf_GetStatus 报告 UNINIT、IDLE、BUSY 或 BUSY_INTERNAL [SWS_MemIf_00064]。作业结果始终针对上一作业，并能够区分中止、不一致和无效的块等 [SWS_MemIf_00065]。MemIf_SetMode 同时作用于所有模块 [SWS_MemIf_00038]。

在存储栈中的角色：NvM 与 Fee/Ea 之间的分流器

Memory Abstraction Interface（MemIf）取代了原先针对 Flash 和 EEPROM 的驱动程序接口层。它允许 NVRAM Manager（NvM）通过单一 API 访问多个存储抽象模块：Flash EEPROM Emulation（Fee）和 EEPROM Abstraction（Ea）SRS MemHwAb 第5页。对上层而言，MemIf 屏蔽了底层存在多少个 Fee 和 Ea 模块。它在统一的线性地址空间上提供虚拟分段 SWS MemIf 第7页。Fee 和 Ea 提供基于块的寻址以及“虚拟无限制”的擦写循环次数。因此，当更换驱动程序或器件时，NvM 无需进行修改 SRS MemHwAb 第5页。

MemIf 本身不包含任何存储逻辑。其 API 需映射到抽象模块的 API 上，而功能行为则由它们的规范或存储器驱动程序的规范确定 SWS MemIf 第17页。相应地，MemIf 需要抽象模块的服务，例如针对 Ea 的 Ea_Read、Ea_Cancel、Ea_GetStatus 和 Ea_GetJobResult [SWS_MemIf_00047]。它可选使用 Det_ReportError [SWS_MemIf_00048]。在 MemIf.h 中定义的类型 MemIf_StatusType、MemIf_JobResultType 和 MemIf_ModeType 构成了该协议栈的通用词汇 [SWS_MemIf_00064] [SWS_MemIf_00065] [SWS_MemIf_00066]。例如，Fls_GetJobResult 直接返回 MemIf_JobResultType SWS Fls 第36页。

较新版本的图示在 Ea 和 Fee 下方额外展示了 MemAcc 和 Mem 模块 SWS Ea 第42页。对于 R20-11，推测可能以较早的概览为准，其中 Fee 基于 Flash 驱动程序构建，而 Ea 基于 EEPROM 驱动程序构建 SWS Fee 第6页。对于 MemIf 而言，该差异无关紧要，因为它仅转发至抽象层 SWS MemIf 第17页。

通过 DeviceIndex 进行设备选择：宏或分发分派表

参数 DeviceIndex 用于选择抽象模块，从而选择存储器件。若仅配置了一个模块，该参数将被忽略 SWS MemIf 第17页。在此情况下，MemIf 应实现为一组宏，例如 #define MemIf_Write(DeviceIndex, BlockNumber, DataPtr) Fee_Write(BlockNumber, DataPtr)。当存在多个模块时，调用必须通过高效机制进行分发；作为一种解决方案，规范列出了通过 DeviceIndex 进行索引的函数指针表 SWS MemIf 第17页。若某厂商特有库替代了所有所需的 Fee 和 Ea 模块，则 MemIf 仅由宏构成 SRS MemHwAb 第5页。

在 R20-11 中，DeviceIndex 的类型为 uint8 [SWS_MemIf_00039] [SWS_MemIf_00041]。规范的后续版本将其列为 uint16 SWS MemIf 第18页。针对该版本，具有规范约束力的是 uint8。

作业流程：同步接收，异步执行

所有 MemIf 服务均被规范为同步服务。每个服务都会调用所选模块的同名函数并返回其返回值，例如 Read、Write 和 InvalidateBlock [SWS_MemIf_00039] [SWS_MemIf_00040] [SWS_MemIf_00044]。实际的存储操作随后在下层周期性调用的主函数中异步执行。为此，Ea 序列展示了在 BSW 任务中遍历 Eep_MainFunction 的循环 SWS Ea 第41页。根据 Fee 规范，该模式同样适用于其余异步服务 SWS Fee 第48页。

根据协议栈配置，NvM 可通过两种途径之一获知作业结束。要么抽象模块调用诸如 NvM_JobEndNotification 或 NvM_JobErrorNotification 的回调函数，要么 NvM 轮询 MemIf_GetJobResult SWS Fee 第48页 EXP ErrorDescription 第45页。MemIf 本身不提供回调函数；其 API 由以下服务组成 [SWS_MemIf_00038] [SWS_MemIf_00046]。

状态、作业结果与运行模式

MemIf_GetStatus 返回所选模块的状态 [SWS_MemIf_00042]。可能的状态包括 MEMIF_UNINIT、MEMIF_IDLE、MEMIF_BUSY 和 MEMIF_BUSY_INTERNAL。处于 MEMIF_BUSY_INTERNAL 时，抽象模块忙于内部管理，而驱动程序可能处于 busy 或 idle [SWS_MemIf_00064]。Fee 规范对这些条件进行了具体说明，并将 Flash 重组（垃圾回收）列为内部管理的示例 SWS Fee 第30页。对于 Flash 驱动程序，允许在初始化之前查询状态，此时状态为 MEMIF_UNINIT SWS Fls 第35页。

状态图：通过 MemIf_GetStatus 可见的模块状态的生命周期。来源：[SWS_MemIf_00064]、SWS Fee 第30页

MemIf_GetJobResult 返回上一个作业的结果 [SWS_MemIf_00043] [SWS_MemIf_00065]。读、写和擦除共用单一作业结果，因此仅可查询上一个作业的结果。随着新作业被接收，它将被设置为 MEMIF_JOB_PENDING SWS Fls 第36页；Fee 称其为最后接收的作业 SWS Fee 第31页。除 OK、FAILED 和 CANCELED 之外，还存在两个与块相关的结果。MEMIF_BLOCK_INCONSISTENT 表示块已损坏或未找到；MEMIF_BLOCK_INVALID 则表示其被标记为无效 [SWS_MemIf_00065]。

状态图：已接收的作业处于 PENDING 状态，并以恰好一种最终结果结束。来源：[SWS_MemIf_00065]、SWS Fls 第36页、SWS Fee 第31页

MemIf_SetMode 是唯一没有 DeviceIndex 的服务，它调用所有抽象模块的 SetMode [SWS_MemIf_00038]。模式包括 MEMIF_MODE_SLOW 和 MEMIF_MODE_FAST [SWS_MemIf_00066]。在驱动程序端，这分别代表慢速读访问或常规 SPI 访问，以及快速读访问或 SPI 突发传输。不得在正在进行的操作期间调用 Eep_SetMode SWS Eep 第34页。当检查处于激活状态时，Fls_SetMode 会拒绝处于 Busy 状态的请求 SWS Fls 第42页。解释：由于 MemIf_SetMode 作用于所有模块，因此仅应在所有设备均报告 MEMIF_IDLE 时调用。

中止正在运行的作业

MemIf_Cancel 调用所选模块的 Cancel 函数 [SWS_MemIf_00041]。中止本身是同步的，但相对于硬件而言是异步的：当调用已返回时，硬件可能仍在继续运行 SWS Fee 第45页 SWS Ea 第44页。此后的作业结果为 MEMIF_JOB_CANCELED [SWS_MemIf_00065]，Fee 明确将其视为失败 SWS Fee 第31页。

针对 Flash 路径，驱动程序规范展示了 MemIf_Cancel → Fee_Cancel → Fls_Cancel 链条及后续的错误通知。此外，该规范还要求不得在正在运行的 Fls_MainFunction 期间调用 Fls_Cancel。为此有两种途径：同步 NvM 和 Flash 驱动程序的作业函数，或者不中断 Fls_MainFunction 的任务 SWS Fls 第58页。

调用规则、可重入性与 BSW 嵌入

除 MemIf_GetVersionInfo 外，所有服务均为不可重入 [SWS_MemIf_00045] [SWS_MemIf_00040]。因此必须杜绝来自多个上下文的并发调用。由于每个模块的状态和作业结果仅反映上一个作业，调用方应仅在上一作业完成后才发出新作业 SWS Fls 第36页。

ICC2 簇“MEM”的内存映射示例将 MemIf 与 NvM 一同列出。在那里，MemIf_SetMode 被建模为 BswCalledEntity，且 MemIf 具有节前缀 MEMIF SWS MemoryMapping 第50页。BSW Distribution Guide 将 MEMIF 与 FLS 和 FEE 并列作为“Type I”的示例；其作用域可通过具有本地作用域的 SwAddrMethod 限制在单个核上 EXP BSWDistributionGuide 第31页。据推测，在多核系统中 MemIf 应作为核局部模块运行。

发生错误时的行为

MemIf 包含两个开发错误。MEMIF_E_PARAM_DEVICE（0x01）代表错误的 DeviceIndex，MEMIF_E_PARAM_POINTER（0x02）代表 NULL 指针 [SWS_MemIf_00006]。它们通过可选的 Det_ReportError 进行报告 [SWS_MemIf_00048]。根据跟踪表，特定错误代码不会通过 API 返回 SWS MemIf 第12页。
