角色：NvM对Fee和Ea的统一访问

Memory Abstraction Interface（MemIf）是Memory Hardware Abstraction的最顶层。它对上层屏蔽了底层存在多少个Fee和Ea模块，并为上层提供统一线性地址空间上的虚拟分段（SWS MemIf 第7页）。根据SRS，MemIf取代了以前用于EEPROM和Flash的驱动程序接口层。NVRAM管理器可以通过它寻址多个抽象模块，而无需在更换存储器驱动程序或存储器芯片时进行修改（SRS MemHwAb 第5页）。

MemIf没有自身的存储行为。它的API映射到底层抽象模块的API上。对于功能行为，规范指引参考这些模块或存储器驱动程序（SWS MemIf 第17页）。相应地，每个服务定义仅描述了对所选模块同名函数的调用，例如MemIf_Read [SWS_MemIf_00039]和MemIf_Write [SWS_MemIf_00040]。所需的Ea函数作为Required Interfaces列出[SWS_MemIf_00047]。

通过DeviceIndex选择设备：宏或分派表

参数DeviceIndex用于选择抽象模块，从而选择存储设备。如果仅配置了一个抽象模块，则该参数会被忽略。在这种情况下，MemIf应实现为一组直接映射到该模块API的宏，例如#define MemIf_Write(DeviceIndex, BlockNumber, DataPtr) Fee_Write(BlockNumber, DataPtr)（SWS MemIf 第17页，截至R24-11）。SRS也遵循相同方向：如果厂商库替换了所有Fee和Ea模块，则MemIf仅由宏组成（SRS MemHwAb 第5页）。

如果配置了多个模块，MemIf应通过高效机制将调用映射到合适的模块上。规范为此提到了函数指针表。对该处被截断提示的解释：DeviceIndex可能用作这些表的索引（SWS MemIf 第17页）。

该参数的类型存在版本差异。在R20-11中，DeviceIndex的类型为uint8（[SWS_MemIf_00039]、[SWS_MemIf_00041]）。来自R23-11及更高版本的文档出处显示为uint16（SWS MemIf 第18页）。对于R20-11，适用uint8。

“同步”仅指作业的接收。实际工作在底层模块的周期性Main函数中异步运行。在Ea_Write流程中，这是在BSW任务中通过Eep_MainFunction的循环来完成的（SWS Ea 第41页）。根据规范，Fee_Write流程同样适用于其余异步服务（SWS Fee 第48页）。MemIf_Write的返回值是被调用模块函数的返回值[SWS_MemIf_00040]。

NvM通过以下两种途径之一获知作业的结束：

  • 抽象模块直接调用NvM_JobEndNotification；MemIf不参与其中（SWS Fee 第48页）。
  • NvM在轮询模式下查询MemIf_GetJobResult [SWS_MemIf_00043]。

MemIf API本身不包含回调函数[SWS_MemIf_00038]。

设备状态、作业结果与运行模式

MemIf_GetStatus [SWS_MemIf_00042]返回MemIf_StatusType [SWS_MemIf_00064]的值。可能的值包括MEMIF_UNINIT、MEMIF_IDLE、MEMIF_BUSY和MEMIF_BUSY_INTERNAL。处于MEMIF_BUSY_INTERNAL时，抽象模块正忙于内部管理；此时底层驱动程序可能处于忙碌或空闲状态。Fee例如会在Flash存储器重组期间报告该值（SWS Fee 第30页）。驱动程序也使用相同的类型，例如Fls_GetStatus（SWS Fls 第35页）。因此，来自MemIf.h的类型构成了存储协议栈的通用词汇。

状态图：抽象模块的状态过程，如MemIf_GetStatus所透传的那样。来源：[SWS_MemIf_00064]、SWS Fee 第30页

MemIf_GetJobResult返回MemIf_JobResultType [SWS_MemIf_00065]。各值概览：

  • MEMIF_JOB_OK和MEMIF_JOB_FAILED：作业分别成功或未成功结束。
  • MEMIF_JOB_PENDING：作业尚未结束。
  • MEMIF_JOB_CANCELED：作业已取消。
  • MEMIF_BLOCK_INCONSISTENT：块不一致或未找到。
  • MEMIF_BLOCK_INVALID：块被标记为无效。

始终只能查询最近接受的作业的结果（SWS Fee 第31页）。在Flash驱动程序中，所有作业类型共享一个结果，该结果在每个新作业开始时都会被MEMIF_JOB_PENDING覆盖（SWS Fls 第36页）。

状态图：作业结果从接收到最终值的生命周期。来源：[SWS_MemIf_00065]、SWS Fls 第36页、SWS Fee 第31页

MemIf_SetMode是唯一没有DeviceIndex的作业服务。它会调用所有下层模块的 SetMode 函数[SWS_MemIf_00038]。参数MemIf_ModeType包含MEMIF_MODE_SLOW和MEMIF_MODE_FAST[SWS_MemIf_00066]。驱动程序将其解释为常规 SPI 访问或 SPI 突发传输（SWS Eep 第34页）。Eep_SetMode 不得在正在进行操作期间被调用。Fls_SetMode 会拒绝处于“busy”状态下的模式切换（SWS Fls 第42页）。解释：因此，只有在没有设备处理作业时，调用MemIf_SetMode才可能有意义。

取消正在进行的作业

MemIf_Cancel不返回值，并将取消操作转发给所选模块[SWS_MemIf_00041]。Fee_Cancel 和 Ea_Cancel 本身同步执行，但相对于硬件而言是异步的（SWS Fee 第45页、SWS Ea 第44页）。在 Flash 路径中，取消操作将继续传递给Fls_Cancel。错误反馈通过Fee_JobErrorNotification和NvM_JobErrorNotification返回给 NvM（SWS Fls 第58页）。随后作业结果报告MEMIF_JOB_CANCELED，Fee 将其归类为“失败”（SWS Fee 第31页）。

调度存在一个约束条件：不得在正在进行的Fls_MainFunction期间调用Fls_Cancel。这可以通过两种方式来确保（SWS Fls 第58页）：

  • NvM 与驱动程序的作业函数在同一任务中依次运行。
  • Main 函数的任务是不可中断的。

时序图：取消操作同步向下执行；错误消息绕过 MemIf 发送至 NvM。来源：SWS Fls 第58页、[SWS_MemIf_00041]、SWS Fee 第31页

发生错误时的行为

MemIf 定义了两个开发错误[SWS_MemIf_00006]：

  • MEMIF_E_PARAM_DEVICE (0x01)：错误的设备索引。
  • MEMIF_E_PARAM_POINTER (0x02)：NULL 指针作为参数。

推测该指针错误涉及参数DataBufferPtr和VersionInfoPtr。通过Det_ReportError进行报告[SWS_MemIf_00048]。在错误检测处于激活状态且检测到错误时，适用以下规则：

  • Read、Write、InvalidateBlock 和 EraseImmediateBlock 返回E_NOT_OK（[SWS_MemIf_00044]、[SWS_MemIf_00046]）。
  • MemIf_GetJobResult返回MEMIF_JOB_FAILED（SWS MemIf 第21页）。

API 不返回特定的开发错误代码（SWS MemIf 第12页）。

来自 Fee 或 Ea 的运行时错误并不由 MemIf 自行处理；预期的响应为“N/A”。仅在轮询模式下，NvM 才会通过MemIf_GetJobResult获知该错误，结果为MEMIF_JOB_FAILED（ErrorDescription 第58页、ErrorDescription 第60页，各为 R20-11）。未初始化的 Fee 可通过其状态查询来识别（ErrorDescription 第53页）。

恢复操作由 NvM 负责。如果涉及写入过程，它会递增重试计数器并在超过限制后终止。它会将错误报告给 DEM；随后可通过NvM_GetErrorStatus查询到NVM_REQ_NOT_OK（EXP ErrorDescription 第45页、EXP ErrorDescription 第58页，截至 R25-11）。相比之下，MEMIF_BLOCK_INCONSISTENT和MEMIF_BLOCK_INVALID描述了块内容的状态，并会被原样透传[SWS_MemIf_00065]。

活动图：根据协议栈配置，运行时错误通过 MemIf 的轮询或通过回调传递给 NvM；响应操作由 NvM 负责。来源：ErrorDescription 第58页、EXP ErrorDescription 第45页、[SWS_MemIf_00043]

Memory Abstraction Interface (MemIf)

抽象底层 Flash 和 EEPROM 内存驱动程序。

特点——概述

  • void MemIf_SetMode (Mem If_ModeTypeMode); Invokes the "Set Mode" functions of all underlying memory abstraction modules.
  • Std_ReturnType MemIf_Read (uint8 Device Index, uint16 Block Number, uint16 Block Offset, uint8* DataBufferPtr, uint16 Length); Invokes the "Read" function of the underlying memory abstraction module selected by the parameter Device Index.
  • Std_ReturnType MemIf_Write (uint8 Device Index, uint16 Block Number, const uint8* DataBufferPtr); Invokes the "Write" function of the underlying memory abstraction module selected by the parameter Device Index.
  • void MemIf_Cancel (uint8 Device Index); Invokes the "Cancel" function of the underlying memory abstraction module selected by the parameter Device Index.
  • MemIf_StatusType MemIf_GetStatus (uint8 Device Index); Invokes the "Get Status" function of the underlying memory abstraction module selected by the parameter Device Index.
  • MemIf_JobResultType MemIf_GetJobResult (uint8 Device Index); Invokes the "Get Job Result" function of the underlying memory abstraction module selected by the parameter Device Index.
  • Std_ReturnType MemIf_InvalidateBlock (uint8 Device Index, uint16 Block Number); Invokes the "Invalidate Block" function of the underlying memory abstraction module
  • void MemIf_GetVersionInfo (Std_VersionInfoType* VersionInfoPtr); Returns version information.
  • Std_ReturnType MemIf_EraseImmediateBlock (uint8 Device Index, uint16 Block Number); Invokes the "Erase Immediate Block" function of the underlying memory abstraction module selected by the parameter Device Index.

类型 — 概述

  • enum MemIf_StatusType Denotes the current status of the underlying abstraction module and device drive.
  • enum MemIf_JobResultType Denotes the result of the last job.
  • enum MemIf_ModeType Denotes the operation mode of the underlying abstraction mod ules and device drivers.

使用

同步函数 MemIf_Read（[SWS_MemIf_00039]）调用通过参数 DeviceIndex 选择的下层存储抽象模块的 Read 函数。该函数具有服务 ID 0x02，并通过头文件 MemIf.h 进行声明。

根据 [SWS_MemIf_00039]，传入参数包括：

  • DeviceIndex（输入，uint8）：选择底层的存储抽象模块。
  • BlockNumber（输入，uint16）：指定块编号。
  • BlockOffset（输入，uint16）：确定块内的偏移量。
  • DataBufferPtr（输出，uint8*）：指向用于读取结果的数据缓冲区的指针。
  • Length（输入，uint16）：确定要读取的数据长度。

错误处理与返回值

作为返回类型，函数 Std_ReturnType 提供（[SWS_MemIf_00039]）：

  • 否则，它返回所调用的下层模块函数的返回值。

并发性与限制

规范将 MemIf_Read 标记为不可重入（Non Reentrant）且同步（Synchronous）（[SWS_MemIf_00039]）。解读：由于缺乏可重入性，从中断上下文或并行任务进行并发调用应该是不允许的，并且需要调用方协调调用。

<h4>通过DeviceIndex选择设备：宏或分派表</h4>
<p>参数<code>DeviceIndex</code>用于选择抽象模块，从而选择存储设备。如果仅配置了一个抽象模块，则该参数会被忽略。在这种情况下，MemIf应实现为一组直接映射到该模块API的宏，例如<code>#define MemIf_Write(DeviceIndex, BlockNumber, DataPtr) Fee_Write(BlockNumber, DataPtr)</code>（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf 第17页</a>，截至R24-11）。SRS也遵循相同方向：如果厂商库替换了所有Fee和Ea模块，则MemIf仅由宏组成（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER.html" data-snip="SNIP_CLASSIC_MEMIF_FIGURE_Figure_1_1_MEMORYHWABSTRACTIONLAYER">SRS MemHwAb 第5页</a>）。</p>
<p>如果配置了多个模块，MemIf应通过高效机制将调用映射到合适的模块上。规范为此提到了函数指针表。对该处被截断提示的解释：<code>DeviceIndex</code>可能用作这些表的索引（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_Function_definitions">SWS MemIf 第17页</a>）。</p>
<p>该参数的类型存在版本差异。在R20-11中，<code>DeviceIndex</code>的类型为<code>uint8</code>（<a class="spec-record-ref" data-req="SWS_MemIf_00039" href="../../spec/record.html?id=SWS_MemIf_00039">[SWS_MemIf_00039]</a>、<a class="spec-record-ref" data-req="SWS_MemIf_00041" href="../../spec/record.html?id=SWS_MemIf_00041">[SWS_MemIf_00041]</a>）。来自R23-11及更高版本的文档出处显示为<code>uint16</code>（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_1_MemIf_Read.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_1_MemIf_Read">SWS MemIf 第18页</a>）。对于R20-11，适用<code>uint8</code>。</p>

<h4>取消正在进行的作业</h4>
<p><code>MemIf_Cancel</code>不返回值，并将取消操作转发给所选模块<a class="spec-record-ref" data-req="SWS_MemIf_00041" href="../../spec/record.html?id=SWS_MemIf_00041">[SWS_MemIf_00041]</a>。Fee_Cancel 和 Ea_Cancel 本身同步执行，但相对于硬件而言是异步的（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_3_Fee_Cancel.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_3_Fee_Cancel">SWS Fee 第45页</a>、<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_3_Ea_Cancel.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_3_Ea_Cancel">SWS Ea 第44页</a>）。在 Flash 路径中，取消操作将继续传递给<code>Fls_Cancel</code>。错误反馈通过<code>Fee_JobErrorNotification</code>和<code>NvM_JobErrorNotification</code>返回给 NvM（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job">SWS Fls 第58页</a>）。随后作业结果报告<code>MEMIF_JOB_CANCELED</code>，Fee 将其归类为“失败”（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_FEE_SECTION_8_3_6_Fee_GetJobResult.html" data-snip="SNIP_CLASSIC_FEE_SECTION_8_3_6_Fee_GetJobResult">SWS Fee 第31页</a>）。</p>
<p>调度存在一个约束条件：不得在正在进行的<code>Fls_MainFunction</code>期间调用<code>Fls_Cancel</code>。这可以通过两种方式来确保（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_9_4_Canceling_a_running_job">SWS Fls 第58页</a>）：</p>
<ul>
<li>NvM 与驱动程序的作业函数在同一任务中依次运行。</li>
<li>Main 函数的任务是不可中断的。</li>
</ul>

<h4>发生错误时的行为</h4>
<p>MemIf 定义了两个开发错误<a class="spec-record-ref" data-req="SWS_MemIf_00006" href="../../spec/record.html?id=SWS_MemIf_00006">[SWS_MemIf_00006]</a>：</p>
<ul>
<li><code>MEMIF_E_PARAM_DEVICE</code> (0x01)：错误的设备索引。</li>
<li><code>MEMIF_E_PARAM_POINTER</code> (0x02)：NULL 指针作为参数。</li>
</ul>
<p>推测该指针错误涉及参数<code>DataBufferPtr</code>和<code>VersionInfoPtr</code>。通过<code>Det_ReportError</code>进行报告<a class="spec-record-ref" data-req="SWS_MemIf_00048" href="../../spec/record.html?id=SWS_MemIf_00048">[SWS_MemIf_00048]</a>。在错误检测处于激活状态且检测到错误时，适用以下规则：</p>
<ul>
<li>Read、Write、InvalidateBlock 和 EraseImmediateBlock 返回<code>E_NOT_OK</code>（<a class="spec-record-ref" data-req="SWS_MemIf_00044" href="../../spec/record.html?id=SWS_MemIf_00044">[SWS_MemIf_00044]</a>、<a class="spec-record-ref" data-req="SWS_MemIf_00046" href="../../spec/record.html?id=SWS_MemIf_00046">[SWS_MemIf_00046]</a>）。</li>
<li><code>MemIf_GetJobResult</code>返回<code>MEMIF_JOB_FAILED</code>（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_8_3_5_MemIf_GetJobResult.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_8_3_5_MemIf_GetJobResult">SWS MemIf 第21页</a>）。</li>
</ul>
<p>API 不返回特定的开发错误代码（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_6_Requirements_Tracing.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_6_Requirements_Tracing">SWS MemIf 第12页</a>）。</p>
<p>来自 Fee 或 Ea 的运行时错误并不由 MemIf 自行处理；预期的响应为“N/A”。仅在轮询模式下，NvM 才会通过<code>MemIf_GetJobResult</code>获知该错误，结果为<code>MEMIF_JOB_FAILED</code>（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_3_1_2_2_Memory_Abstraction_Interface.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_3_1_2_2_Memory_Abstraction_Interface">ErrorDescription 第58页</a>、<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_3_2_2_2_Memory_Abstraction_Interface.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_3_2_2_2_Memory_Abstraction_Interface">ErrorDescription 第60页</a>，各为 R20-11）。未初始化的 Fee 可通过其状态查询来识别（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_5_2_2_Flash_Eeprom_emulation.html" data-snip="SNIP_CLASSIC_ERRORDESCRIPTION_SECTION_6_2_5_2_2_Flash_Eeprom_emulation">ErrorDescription 第53页</a>）。</p>
<p>恢复操作由 NvM 负责。如果涉及写入过程，它会递增重试计数器并在超过限制后终止。它会将错误报告给 DEM；随后可通过<code>NvM_GetErrorStatus</code>查询到<code>NVM_REQ_NOT_OK</code>（<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_6_2_2_2_5_NVRAM_Manager.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_6_2_2_2_5_NVRAM_Manager">EXP ErrorDescription 第45页</a>、<a class="docref internal-spec-ref" href="../../../spec/snippets/SNIP_CLASSIC_MEMIF_SECTION_6_2_7_2_5_NVRAM_Manager.html" data-snip="SNIP_CLASSIC_MEMIF_SECTION_6_2_7_2_5_NVRAM_Manager">EXP ErrorDescription 第58页</a>，截至 R25-11）。相比之下，<code>MEMIF_BLOCK_INCONSISTENT</code>和<code>MEMIF_BLOCK_INVALID</code>描述了块内容的状态，并会被原样透传<a class="spec-record-ref" data-req="SWS_MemIf_00065" href="../../spec/record.html?id=SWS_MemIf_00065">[SWS_MemIf_00065]</a>。</p>
