通过检查点监控软件的执行流程和时序，并据此控制看门狗的触发。

Watchdog Manager 监控软件的执行。Supervised Entities 通过 WdgM_CheckpointReached 报告检查点 [SWS_WdgM_00263]。周期性的 WdgM_MainFunction 评估 Alive、Deadline 和 Logical Supervision，并将结果汇总为局部状态和一个全局状态。只要一切正常，WdgM 就会通过 Watchdog Interface 设置有效的触发条件。一旦全局状态达到 STOPPED，驱动程序将不再触发，随后引发看门狗复位 [SWS_WdgM_00360]。仅在全局状态为 OK 或 FAILED 时才允许进行模式切换。

Watchdog Manager 监控 Supervised Entities 的执行，并且仅在监控正常时才允许继续触发硬件看门狗。触发时序本身由看门狗驱动程序负责。WdgM 仅通过 Watchdog Interface 设置触发条件（SWS WdgM 第56页）。为此必须强制需要 WdgIf_SetMode、WdgIf_SetTriggerCondition、GetElapsedValue 和 Det_ReportRuntimeError [SWS_WdgM_00161]。

在 WdgM_Init 之后，监控随着 WdgM_MainFunction 的首次调用而开始 [SWS_WdgM_00406]。Entities 通过 WdgM_CheckpointReached 报告检查点 [SWS_WdgM_00263]。每次调用都会增加 Alive Counter，并立即检查 Deadline 和 Logical Supervision（SWS WdgM 第79页）。主函数周期性评估 Alive Counter 和 Deadline 超时 [SWS_WdgM_00404]。

时序图：检查点按事件驱动方式采集，评估和触发则周期性执行。来源：SWS WdgM 第32页、[SWS_WdgM_00263]

根据这些结果为每个 Entity 生成一个局部状态。其中 FAILED 是可恢复的，EXPIRED 则不可恢复 [SWS_WdgM_00359]。WdgM 据此形成全局状态，该状态经由 EXPIRED 逐级上报至 STOPPED。在 STOPPED 状态下，驱动程序不再触发，随后引发看门狗复位 [SWS_WdgM_00360]。WdgM 通过局部模式端口和一个全局模式端口报告状态更改 [SWS_WdgM_00197] [SWS_WdgM_00198]。

状态图：从 DEACTIVATED 到 STOPPED 的 Global Supervision Status；两个状态转换标记为解读。来源：[SWS_WdgM_00387]、[SWS_WdgM_00360]

仅在全局状态为 OK 或 FAILED 时，才可以通过 WdgM_SetMode 进行模式切换 [SWS_WdgM_00145]。若 WdgMOffModeEnabled 为 FALSE，则 WdgM 会拒绝 Off 模式 [SWS_WdgM_00031]。若 WdgIf_SetMode 失败，全局状态将转为 STOPPED（SWS WdgM 第57页）。复位后，WdgM_GetFirstExpiredSEID 早在 WdgM_Init 之前即可提供最先超时的 Entity [SWS_WdgM_00346] [SWS_WdgM_00348]。

角色：Supervised Entities 与硬件看门狗之间的软件监控

Watchdog Manager (WdgM) 监控 Supervised Entities（即 SW-C、CDD 或 BSW 流程）的执行。它根据监控结果决定是否继续触发硬件看门狗。实际的触发时序由看门狗驱动程序负责。WdgM 仅通过 Watchdog Interface 设置指示驱动程序继续触发的触发条件（SWS WdgM 第56页）。为此必须强制需要 WdgIf_SetMode、WdgIf_SetTriggerCondition、GetElapsedValue 和 Det_ReportRuntimeError [SWS_WdgM_00161]。它可选择性地使用 Dem_SetEventStatus、Det_ReportError、Mcu_PerformReset 和 BswM_WdgM_RequestPartitionReset [SWS_WdgM_00162]。

Supervised Entities 通过 WdgM_CheckpointReached 报告检查点 [SWS_WdgM_00263]。模式管理模块使用 WdgM_Init、WdgM_SetMode 和 WdgM_DeInit 控制生命周期 [SWS_WdgM_00151] [SWS_WdgM_00154] [SWS_WdgM_00261]。周期性评估由来自 SchM_WdgM.h 的 WdgM_MainFunction 完成 [SWS_WdgM_00159]。安全概念将基于检查点和允许转换的逻辑程序流监控分配给 WdgM（SafetyConceptStatusReport 第15页）。

上下文图：WdgM 将应用程序的检查点报告与看门狗栈以及 Os、DET、DEM、Mcu 和 BswM 连接起来。来源：[SWS_WdgM_00161]、[SWS_WdgM_00162]、SWS WdgM 第85页

生命周期：初始化、模式切换与去初始化

Global Supervision Status 静态预置为 WDGM_GLOBAL_STATUS_DEACTIVATED [SWS_WdgM_00387]。在此状态下，服务返回 WDGM_E_UNINIT 予以拒绝或直接返回而不产生任何效果 [SWS_WdgM_00253] [SWS_WdgM_00395]。WdgM_Init 接收指向 WdgM_ConfigType 的指针 [SWS_WdgM_00355]。该函数初始化所有模块变量并建立初始模式（SWS WdgM 第74页）。解读：此后全局状态应为 WDGM_GLOBAL_STATUS_OK，因为在初始模式下处于活动状态的 Entity 在局部均以 OK 启动（SWS WdgM 第30页）。 问题 Q-a1728b38f957607d (未决)

在 DEACTIVATED 之外再次调用 WdgM_Init 不会产生任何效果 [SWS_WdgM_00390]。因此，重新初始化需通过 WdgM_DeInit 及随后的 WdgM_Init 进行（SWS WdgM 第74页）。监控和看门狗处理仅在初始化后首次调用 WdgM_MainFunction 时开始 [SWS_WdgM_00406]。

WdgM_SetMode 切换到另一个已配置的模式 [SWS_WdgM_00154]，但仅在全局状态为 OK 或 FAILED 时允许 [SWS_WdgM_00145]。对于在新模式下停用的 Entity，适用以下规则：

  • 它们切换到 WDGM_LOCAL_STATUS_DEACTIVATED [SWS_WdgM_00315]。
  • 其结果重新被视为正确 [SWS_WdgM_00315]。
  • 其错误计数器被重置为 0 [SWS_WdgM_00315]。

保持活动状态的 Entity 保留其状态 [SWS_WdgM_00182]。对于每个看门狗，WdgM 通过 WdgIf_SetMode 设置模式参数 [SWS_WdgM_00186]。在切换进行期间，WdgM_GetMode 仍返回旧模式（SWS WdgM 第77页）。

活动图：模式切换经历状态检查、Off 模式保护和看门狗模式设置；若后者失败，则以 STOPPED 结束。来源：[SWS_WdgM_00145]、[SWS_WdgM_00031]、[SWS_WdgM_00186]、[SWS_WdgM_00139]；检查顺序为一种解读

在转换到 SLEEP 时，EcuM 调用 WdgM_DeInit。该函数首先切换到由集成商定义的休眠模式。这样，尽管存在基于窗口的看门狗，触发条件仍允许在不复位的情况下完成剩余的关机操作。随后该模块执行去初始化（SWS WdgM 第59页）。在此过程中，监控和看门狗处理均停止 [SWS_WdgM_00407]。在 SLEEP 期间，必须由 BswM 或 EcuM 接管触发。

检查点与三种监控功能

Supervised Entity 使用 WdgM_CheckpointReached(SEID, CheckpointID) 报告检查点 [SWS_WdgM_00263]。两个标识符均为 uint16 类型。检查点仅通过 SE-ID 和 Checkpoint-ID 这一对标识符唯一确定 [SWS_WdgM_00356] [SWS_WdgM_00357]。该调用执行三项操作（SWS WdgM 第79页）：

  • 它递增该检查点的 Alive Counter。
  • 它检查 Deadline Supervision 是否到达过早或过晚。
  • 它执行 Logical Supervision。

若该 Entity 在当前模式下被停用，该服务返回 E_NOT_OK 并报告 WDGM_E_SEDEACTIVATED [SWS_WdgM_00319]。

Alive Supervision 检查周期性流程。主函数按照 WdgMSupervisionReferenceCycle 的节拍评估 Alive Counter，该节拍是 Supervision Cycle 的整数倍（SWS WdgM 第42页）。Deadline Supervision 检查在起始与结束检查点之间是否遵守了边界 WdgMDeadlineMin/WdgMDeadlineMax。时间戳由 GetElapsedValue 借助该 Entity 的 OS 计数器提供；定标通过 OsSecondsPerTick 进行 [SWS_WdgM_00373] [SWS_WdgM_00374]。若起始时间戳为 0，则检查成功结束且不执行测量 [SWS_WdgM_00354]。若缺少结束检查点，只要设置了 WdgMEnableTimeoutDetection，WdgM_MainFunction 就会识别出超时 [SWS_WdgM_00403] [SWS_WdgM_00404]。

Logical Supervision 检查检查点的顺序。每个图都有一个 Activity Flag，WdgM_Init 会将其设置为 false。图始于 Initial Checkpoint（SWS WdgM 第51页）。内部图属于单个 Entity，并在所有模式下有效。外部图连接多个 Entity，并按模式进行配置（SWS WdgM 第46页、[SWS_WdgM_00366]）。

时序图：检查点按事件驱动方式采集，评估和触发在主函数中周期性进行。来源：SWS WdgM 第32页、[SWS_WdgM_00263]、[SWS_WdgM_00404]、[SWS_WdgM_00197]

局部与全局监控状态

WdgM 根据这三个结果为每个 Entity 构建 Local Supervision Status（SWS WdgM 第30页）。WDGM_LOCAL_STATUS_FAILED 是可恢复的：若 Entity 恢复正常行为，它将返回到 OK。若失败次数超过限制，它将转换为 WDGM_LOCAL_STATUS_EXPIRED [SWS_WdgM_00359]。该容差仅适用于 Alive Supervision。对于 Deadline 和 Logical 错误，首次出现错误结果就会直接导致 EXPIRED（SWS WdgM 第30页）。

状态图：Supervised Entity 的 Local Supervision Status 生命周期。来源：SWS WdgM 第30页、[SWS_WdgM_00359]、[SWS_WdgM_00315]

对于整个软件，存在一个取值为 DEACTIVATED、OK、FAILED、EXPIRED 和 STOPPED 的 Global Supervision Status（SWS WdgM 第36页）。EXPIRED 意味着：已超过故障限值，但驱动程序仍在触发。在 STOPPED 状态下，驱动程序被指示停止触发，随后发生看门狗复位 [SWS_WdgM_00360]。WdgM 在 EXPIRED 状态停留的时长，由 WdgMExpiredSupervisionCycleTol 以 Supervision Cycle 的倍数设定（SWS WdgM 第36页）。

状态图：Global Supervision Status 逐步升级至复位；标记为解释的两个转换均无明确凭据。来源：[SWS_WdgM_00387]、[SWS_WdgM_00360]、SWS WdgM 第36页、SWS WdgM 第57页

端口、状态消息与查询服务

WdgM 为每个 Supervised Entity 提供一个 Supervision 端口 [SWS_WdgM_00146]。它被命名为 localSupervision_{SupervisedEntityCheckpointName}，并包含作为端口定义实参的 SE-ID 和 Checkpoint-ID [SWS_WdgM_00147] [SWS_WdgM_00333]。本地状态通过 localSupervisonStatus_{SupervisedEntityName} 查询 [SWS_WdgM_91003] [SWS_WdgM_91004]。诸如 GetGlobalStatus 或 GetFirstExpiredSEID 等全局查询则通过 globalSupervision 进行 [SWS_WdgM_91002] [SWS_WdgM_91001]。

WdgM 会主动通过 Mode 端口通报状态变更：每个 Entity 一个 mode_{SupervisedEntityName}，全局一个 globalmode [SWS_WdgM_00149] [SWS_WdgM_00150]。两者均使用 Mode Declaration Group WdgM_Mode，其取值范围为 SUPERVISION_OK 至 SUPERVISION_DEACTIVATED [SWS_WdgM_00334]。本地变更会被立即通报，而全局变更仅通报一次 [SWS_WdgM_00197] [SWS_WdgM_00199]。本地与全局 Mode 端口具有不同的接口。这样就可以通过 Indirect Port API 访问本地端口，而全局端口不会出现在该列表中（SWS WdgM 第101页）。

协作图：SW-C 与全局用户通过 Service 端口和 Mode 端口绑定到 WdgM。来源：SWS WdgM 第99页、[SWS_WdgM_00147]、[SWS_WdgM_00149]、[SWS_WdgM_00150]、[SWS_WdgM_91002]

查询服务和 WdgM_CheckpointReached 是可重入的。WdgM_SetMode 和 WdgM_PerformReset 则不可重入 [SWS_WdgM_00175] [SWS_WdgM_00263] [SWS_WdgM_00154] [SWS_WdgM_00264]。全局控制或查询 WdgM 的 BSW 模块通过 GlobalSupervisionNeeds 对此进行描述（TPS BSWMDT 第257页）。

配置：模式、Supervised Entity 与看门狗触发

WdgM 支持 VARIANT-PRE-COMPILE 和 VARIANT-POST-BUILD（SWS WdgM 第97页）。支持 post-build 的参数位于 WdgM_ConfigType [SWS_WdgM_00355]。ECU Integrator 采用自顶向下的方式进行配置，并为此评估来自 ECU Extract 的 ServiceNeeds（TR Methodology 第389页）。SupervisedEntityNeeds 为每个 Entity 描述了启动时的激活状态、允许的停用、Alive 周期时间以及容忍的故障周期数等（SWC-Template 第716页）。

一个 WdgMMode 包含以下组成部分（SWS WdgM 第119页）：

  • WdgMModeId
  • WdgMExpiredSupervisionCycleTol
  • 用于 Alive、Deadline 和外部 Logical Supervision 的容器
  • 用于本地状态参数的容器
  • WdgMTrigger

触发器定义了 WdgMWatchdogMode（FAST/SLOW/OFF）和 WdgMTriggerConditionValue（SWS WdgM 第125页）。WdgMGeneral 包含诸如 WdgMDevErrorDetect 和 WdgMImmediateReset 等开关（SWS WdgM 第107页）。对于 Deadline Supervision，每个 Entity 都需要一个 OS 计数器（SWS WdgM 第46页）。

发生错误时的行为

在 WdgMDevErrorDetect 处于激活状态时，WdgM 会向 DET 报告开发错误，例如 WDGM_E_UNINIT、WDGM_E_PARAM_SEID、WDGM_E_INV_POINTER 或 WDGM_E_CPID [SWS_WdgM_00004]。在模块未初始化时遵循固定模式：启用检查时报告 WDGM_E_UNINIT，未启用检查时服务无操作返回 [SWS_WdgM_00279] [SWS_WdgM_00394]。运行时错误包括 WDGM_E_DISABLE_NOT_ALLOWED、WDGM_E_SEDEACTIVATED 和 WDGM_E_SET_MODE [SWS_WdgM_00402]。

若 WdgMOffModeEnabled 为 FALSE，WdgM_SetMode 将拒绝带有 WDGIF_OFF_MODE 的模式。该服务随后报告 WDGM_E_DISABLE_NOT_ALLOWED 并返回 E_NOT_OK [SWS_WdgM_00031]。WdgM_Init 在遇到此类初始模式时的行为完全相同 [SWS_WdgM_00030]。如果 WdgIf_SetMode 失败，WdgM 会报告 WDGM_E_SET_MODE 并将全局状态置为 STOPPED [SWS_WdgM_00139]。若配置了 Immediate Reset，则立即执行复位；否则在第一个看门狗超时时发生复位（SWS WdgM 第57页）。

当全局状态达到 STOPPED 时，WdgM 会将 DEM 事件 WDGM_E_SUPERVISION 报告为错误 [SWS_WdgM_00375]。启动后，它可选地将同一事件报告为 PASSED [SWS_WdgM_00408]。重新启动后，WdgM_GetFirstExpiredSEID 提供最先达到 EXPIRED 的 Entity [SWS_WdgM_00346]。该服务在 WdgM_Init 之前即可使用 [SWS_WdgM_00348]。它从未初始化的 RAM 中以双重反转方式读取该值，若不一致则返回 E_NOT_OK [SWS_WdgM_00349]。WdgM_Init 清除该值 [SWS_WdgM_00370]。据推测，WdgM 会在某个 Entity 首次转换到 EXPIRED 时写入该值。 问题 Q-bb8ada25b04b0758 (未决)

WdgM_PerformReset 将所有驱动程序的触发条件置为 0，且在此之后不再进行更新（SWS WdgM 第82页）。EcuM 将该服务作为其复位目标之一（SWS EcuM 第72页）。
