通过配置的通道将 CSM 的加密作业和密钥调用转发给负责的 Crypto 驱动程序。

CryIf 在 Classic 加密协议栈中负责在 CSM 与 Crypto Driver 之间进行中介，并通过配置的通道将作业和密钥调用转发给负责的 Crypto Driver Object SWS CSM 第26页。核心接口是 CryIf_ProcessJob，它根据配置以同步或异步方式工作 [SWS_CryIf_91003]。驱动程序通过回调向 CryIf 报告异步结果，CryIf 再将其传递给 CSM。在转发之前，CryIf 将其自身的密钥 ID 映射到驱动程序的密钥 ID，并检查其范围。对于 R20-11，需要注意的是后续 release 已更改了错误代码和同步性规则。

在转发之前，CryIf 将其自身的密钥 ID 映射到驱动程序的 ID。如果它们超出范围，它会向 DET 报告 CRYPTO_E_PARAM_HANDLE 并返回 E_NOT_OK [SWS_CryIf_00133] [SWS_CryIf_00134]。此外，CryIf 还提供用于设置、置为有效和置为无效、读取、生成、派生、交换和复制密钥的同步函数。在部分复制时，如果源和目标位于不同的驱动程序中，CryIf 会读取该元素并自行将其写入目标 [SWS_CryIf_00140]。

CryIf 在 Crypto Service Manager 与 Crypto Driver 之间的角色

Crypto Interface (CryIf) 位于 Classic 加密协议栈中的 ECU Abstraction Layer。应用程序通过 RTE 和 CSM 请求加密服务。这些请求通过逻辑通道穿过 CryIf 到达 MCAL 中的 Crypto Driver，并进一步到达其硬件引擎，例如 HSM 中的 HW-AES 和 HW-RSA SWS CSM 图 7.4 第27页。Crypto Driver Object 代表硬件或软件中独立的加密“设施”，例如 AES 加速器或软件中的 RSA 实现 SWS CSM 第26页。CryIf 本身不执行计算。其函数将各自的调用转发给配置的 Crypto Driver Object，例如 [SWS_CryIf_91005]、[SWS_CryIf_91007]、[SWS_CryIf_91009] 和 [SWS_CryIf_91014]。

向上，CryIf 提供三组接口：

  • 作业接口 CryIf_ProcessJob [SWS_CryIf_91003]，
  • 作业中止接口 CryIf_CancelJob [SWS_CryIf_91014]，
  • 从 CryIf_KeyElementSet [SWS_CryIf_91004] 到 CryIf_KeySetInvalid [SWS_CryIf_91021] 的直接密钥管理。

对于处于“ACTIVE”状态的作业，CSM 调用 CryIf_ProcessJob 并原样传递其返回值 SWS CSM 第22页。向下，CryIf 通过 CryIf_CallbackNotification [SWS_CryIf_91013] 接收驱动程序的完成通知 SWS Crypto 第27页。它从其他模块需要 Csm_CallbackNotification 和 Det_ReportRuntimeError [SWS_CryIf_91100]，可选地还需要 Det_ReportError [SWS_CryIf_91101]。

通道、配置与初始化

通道是从 CSM 队列经由 CryIf 到 Crypto Driver Object 的路径。CSM 的每个队列恰好分配给一个通道；可选地，Crypto Driver 也拥有自己的队列 SWS CSM 第26页。通道在容器 CryIfChannel 中进行配置，多重度为 0..*，且在所有变体中均采用 pre-compile 配置。该容器包含参数 CryIfChannelId 和 CryIfDriverObjectRef SWS CryIf 第51页。CryIfChannelId 确定 CSM 队列连接到哪个通道。在运行时，[SWS_CryIf_91003] 和 [SWS_CryIf_91014] 的参数 channelId 同样表示加密通道。解释：CryIfDriverObjectRef 大概是将通道绑定到执行该通道作业的 Crypto Driver Object。

在每次使用前必须调用 CryIf_Init [SWS_CryIf_91000]。该函数是同步且不可重入的。它接收一个指向类型为 CryIf_ConfigType 的所选配置的指针，其内容是特定于实现的 [SWS_CryIf_91118] SWS CryIf 第20页。针对失败的初始化，错误列表规定了 CRYIF_E_INIT_FAILED (0x01) [SWS_CryIf_00009]。CryIf_GetVersionInfo 是可重入的，并提供模块的版本信息 [SWS_CryIf_91001]。

除了通道之外，CryIf 还维护自身的密钥标识符（cryIfKeyId）。它将它们映射到负责的驱动程序的密钥 ID [SWS_CryIf_00133]。如果作业使用了作业处理重定向 (job processing redirection)，CryIf 还会额外将传入的密钥和密钥元素引用调整为驱动程序的引用 [SWS_CryIf_00136]。密钥由一个或多个密钥元素组成，例如密钥材料、初始化向量或种子 SWS CSM 第30页。

从 CryIf_ProcessJob 到返回确认的作业处理

单次调用和流式处理通过相同的函数 CryIf_ProcessJob 进行。字段 job->jobPrimitiveInputOutput.mode 包含操作模式“START”、“UPDATE”和“FINISH”，这些模式可以组合。在单次调用中完成的完整服务对应于所有三种模式的组合 SWS CryIf 第22页。该函数是可重入的，并根据配置以同步或异步方式工作 [SWS_CryIf_91003]。作业的状态转换由 Crypto Driver 执行，而非 CSM SWS CSM 第22页。

在异步情况下，驱动程序仅将必要的信息传递给原语。随后可以从 main 函数触发计算。完成后，驱动程序通过 CryIf_CallbackNotification 向 CryIf 报告作业和结果 SWS Crypto 第27页。该函数是同步且不可重入的；传入的作业包含用于标识该作业的回调 ID [SWS_CryIf_91013]。然后 CryIf 通过 Csm_CallbackNotification 向 CSM 报告结束；该函数明确专用于其下层 CRYIF [SWS_CryIf_91100]。如果设置了 FINISH 位，CSM 将调用配置的回调 SWS CSM 第82页。

映射并检查作业中的密钥 ID

某些 Job 会携带密钥管理服务：CRYPTO_KEYSETVALID、CRYPTO_KEYSETINVALID、CRYPTO_RANDOMSEED、CRYPTO_KEYGENERATE、CRYPTO_KEYDERIVE、CRYPTO_KEYEXCHANGECALCPUBVAL 或 CRYPTO_KEYEXCHANGECALCSECRET。对于这些 Job，CryIf 会检查 job->jobPrimitiveInputOutput->cryIfKeyId 以及在适当时检查 targetCryIfKeyId 是否处于有效范围内。如果是，则它会将 job->cryptoKeyId 或 job->targetCryptoKeyId 设置为驱动的密钥 ID [SWS_CryIf_00133] [SWS_CryIf_00141]。如果源 ID 超出范围，CryIf_ProcessJob 会向 DET 报告 CRYPTO_E_PARAM_HANDLE 并返回 E_NOT_OK [SWS_CryIf_00134]。对于 CRYPTO_KEYDERIVE，同样的处理也适用于目标 ID [SWS_CryIf_00135]。

与密钥相关的原语也会被检查。在 CRYPTO_MACGENERATE、CRYPTO_MACVERIFY、CRYPTO_ENCRYPT、CRYPTO_DECRYPT、CRYPTO_AEADENCRYPT、CRYPTO_AEADDECRYPT、CRYPTO_RANDOMGENERATE、CRYPTO_SIGNATUREGENERATE 和 CRYPTO_SIGNATUREVERIFY 中，会对 job->jobPrimitiveInfo->cryIfKeyId 检查其是否处于有效范围内 [SWS_CryIf_00143]。

活动图：CryIf 根据服务类型检查密钥 ID，并在转发 Job 之前将其映射到驱动 ID。来源：[SWS_CryIf_00133]、[SWS_CryIf_00134]、[SWS_CryIf_00135]、[SWS_CryIf_00143]

该范围在各 Release 之间发生了变化。R20-11 在检查中提及了 CRYPTO_E_PARAM_HANDLE，而模块的错误列表则定义了 CRYIF_E_PARAM_HANDLE (0x03) [SWS_CryIf_00009]。根据变更历史，直到 R22-11 才将其统一为 CRYIF_E_PARAM_HANDLE SWS CryIf 第1页。在同一次变更中，移除了 DET 报告后的返回值。此外还新增了服务 CRYPTO_CUSTOM，该服务在文档后续位置已包含在列表中 SWS CryIf 第23页。对于 R20-11，需求以在此引用的形式为准。

密钥管理：材料、状态、生成与交换

直接密钥 API 是同步的。非可重入的有 CryIf_KeyElementSet [SWS_CryIf_91004]、CryIf_KeySetValid [SWS_CryIf_91005]、CryIf_KeySetInvalid [SWS_CryIf_91021] 和 CryIf_KeyGetStatus [SWS_CryIf_91012]。根据变更历史，用于密钥状态的功能是在 R20-11 中新增的 SWS CryIf 第1页。如果设置某个元素失败，根据 CSM 规范，其状态被视为未知 SWS CSM 第62页。该状态可通过 Csm_KeyGetStatus 进行检查，后者本身会调用 CryIf_KeyGetStatus SWS CSM 第63页。

CryIf_KeyElementGet 是可重入的 [SWS_CryIf_91006]。参数 resultLengthPtr 用作输入和输出。在调用时，它包含缓冲区大小；对于部分访问的元素，则包含要读取的数据量。完成后，它包含实际存放的数据量 SWS CryIf 第30页。

状态图：密钥在设置其元素后被声明为有效，并且可以重新置为无效。当密钥无效时，带有 CRYPTO_E_KEY_NOT_VALID 的操作将失败。CryIf_KeySetValid 之前的初始状态为一种解释。来源：[SWS_CryIf_91004]、[SWS_CryIf_91005]、[SWS_CryIf_91021]、[SWS_CryIf_91012]、SWS CSM 第70页

对于密钥生成，CryIf_RandomSeed [SWS_CryIf_91007] 提供初始值，而 CryIf_KeyGenerate [SWS_CryIf_91008] 生成密钥。根据 CSM 规范，密钥在元素 CRYPTO_KE_KEYGENERATE_KEY 中生成。其基础是 CRYPTO_KE_KEYGENERATE_SEED 中的种子以及 CRYPTO_KE_KEYGENERATE_ALGORITHM SWS CSM 第67页 中的算法。在 R20-11 中，这两个函数根据配置以同步或异步方式工作 [SWS_CryIf_91007] [SWS_CryIf_91008]。直到 R21-11 才将它们定为同步 SWS CryIf 第1页。CryIf_KeyDerive 是同步且可重入的，它从源密钥派生出一个密钥，并存放在目标密钥中 [SWS_CryIf_91009] SWS CryIf 第42页。

对于 Diffie-Hellman 密钥交换，存在两个函数。CryIf_KeyExchangeCalcPubVal [SWS_CryIf_91010] 计算自身的公钥值。CryIf_KeyExchangeCalcSecret [SWS_CryIf_91011] 根据通信伙伴的值计算共享秘密。密钥材料位于元素 CRYPTO_KE_KEYEXCHANGE_BASE、CRYPTO_KE_KEYEXCHANGE_PRIVKEY 和 CRYPTO_KE_KEYEXCHANGE_OWNPUBKEY SWS CSM 第70页 中。驱动将该秘密作为元素存放在同一密钥中 SWS Crypto 第84页。解释：即使在直接密钥 API 中，CryIf 可能也会像在 Job 路径中一样，将 cryIfKeyId 映射到驱动的密钥 ID [SWS_CryIf_00133]。

时序图：密钥交换在两次 CryIf 调用中进行。在此期间，应用程序在 CryIf 外部与通信伙伴交换公钥值。来源：[SWS_CryIf_91010]、[SWS_CryIf_91011]、SWS CSM 第70页、SWS Crypto 第84页

在 Crypto Driver 内部及之间复制密钥

对于复制操作，存在 CryIf_KeyElementCopy [SWS_CryIf_91015]、CryIf_KeyCopy [SWS_CryIf_91016] 和 CryIf_KeyElementCopyPartial [SWS_CryIf_91018]。三者均为同步且可重入，但针对同一 cryIfKeyId 时不可重入。除 E_OK 和 E_NOT_OK 外，它们还可以返回 CRYPTO_E_KEY_READ_FAIL、CRYPTO_E_KEY_WRITE_FAIL、CRYPTO_E_KEY_SIZE_MISMATCH 以及 CRYPTO_E_KEY_EMPTY 等 SWS CryIf 第35页。

在部分复制时，规范区分了两种情况：

  • 源密钥与目标密钥位于同一 Crypto Driver 中：CryIf 调用所分配驱动的 Crypto_<vi>_<ai>_KeyElementCopyPartial()，并转发其返回值 [SWS_CryIf_00139]。
  • 密钥位于不同的驱动中：CryIf 使用 Crypto_<vi>_<ai>_KeyElementGet() 读取该元素，将部分数据复制到目标位置，并使用 Crypto_<vi>_<ai>_KeyElementSet() [SWS_CryIf_00140] 写入目标元素。

驱动的复制函数是可选接口。如果某个元素直接位于 Flash 中，则调用可能会耗费明显更长的时间 SWS CryIf 第45页。
