CryIf 的角色：Crypto Service Manager 与加密驱动程序之间的分发器

Crypto Interface (CryIf) 位于 Classic Platform 的加密栈中，介于 Crypto Service Manager (CSM) 与一个或多个加密驱动程序之间。它接收作业并将其转发给所配置的 Crypto Driver Object。这既适用于通过 CryIf_ProcessJob [SWS_CryIf_91003] 进行的作业处理，也适用于 CryIf “分发给所配置的 Crypto Driver Object” 的作业取消[SWS_CryIf_91014]。在 CSM 规范的分层图中，CryIf 位于 ECU 抽象层。其上方是位于服务层的 CSM，下方是位于微控制器抽象层的加密驱动程序SWS CSM 第28页。

对于活动作业，CSM 调用 CryIf_ProcessJob 并将其返回值传递给其调用者SWS CSM 第22页。CryIf 本身需要以下接口：

  • Csm_CallbackNotification，通过该接口“下层（CRYIF）”向 CSM 报告作业的结束，以及 Det_ReportRuntimeError [SWS_CryIf_91100]。
  • 可选用于开发错误的 Det_ReportError [SWS_CryIf_91101]。

规范的 API 调用树区分了两种途径：基于作业的服务和用于密钥管理的直接 API SWS CSM 第20页。

上下文图：CryIf 通过通道将 CSM 队列与 Crypto Driver Objects 连接，向 CSM 转发反馈，并向 DET 报告错误。来源：[SWS_CryIf_91003]、[SWS_CryIf_91100]、SWS CSM 第28页、SWS CSM 第26页

通道、Crypto Driver Objects 与配置

通道是从 CSM 队列经由 CryIf 到 Crypto Driver Object 的路径。每个 CSM 队列精确分配给一个通道。Crypto Driver Object 代表硬件或软件中独立的加密“设备”，例如 HSM 中的 AES 加速器或软件中的 RSA 实现SWS CSM 第26页。

通道在容器 CryIfChannel 中配置（多重性 0..*，仅 Pre-compile）。它包含参数 CryIfChannelId 和 CryIfDriverObjectRef。CryIfChannelId 确定 CSM 队列与哪个通道相连SWS CryptoInterface 第51页。解释：CryIf_ProcessJob 和 CryIf_CancelJob 的参数 channelId 预计会通过此容器解析为通过 CryIfDriverObjectRef 引用的 Crypto Driver Object[SWS_CryIf_91003] [SWS_CryIf_91014]。

配置结构体 CryIf_ConfigType 的内容特定于实现；规范并未对其进行规定[SWS_CryIf_91118]。CSM、CryIf 与驱动程序之间的包含依赖关系 Crypto_<vi>_<ai> 展示在规范的文件结构中SWS CryptoInterface 第11页。

作业处理：操作模式与异步反馈

所有加密原语均通过单个函数 CryIf_ProcessJob 运行。字段 job->jobPrimitiveInputOutput.mode 包含操作模式 START、UPDATE 和 FINISH，这些模式可以相互组合。单次调用相当于所有三种模式的组合SWS CryptoInterface 第22页。在 R20-11 中，该可重入函数是同步还是异步工作取决于配置[SWS_CryIf_91003]。在 CSM 端有一条附加规则：如果设置了 START 和 FINISH 但没有设置 UPDATE，CSM 将以 E_NOT_OK 拒绝该调用SWS CSM 第22页。

在异步情况下，接口仅向下传递必要的信息SWS CSM 第26页。随后反馈分三个阶段进行：

  1. 驱动程序可以通过其 Main 函数触发计算。完成后，它通过CryIf_CallbackNotification向 CryIf 报告作业和结果SWS Crypto 第27页 [SWS_CryIf_91013]。
  2. CryIf 通过Csm_CallbackNotification通知 CSM [SWS_CryIf_91100]。
  3. CSM 调用在作业原语中配置的回调SWS CSM 第26页。

R20-11 的 CSM 规范中的时序图也展示了这一级联过程SWS CSM 第164页。

时序图：作业立即返回，结果稍后通过回调从驱动程序经由 CryIf 和 CSM 传递至应用程序。来源：[SWS_CryIf_91013]、[SWS_CryIf_91100]、SWS CSM 第164页、SWS Crypto 第27页

CSM 可以通过两种方式中止正在运行的作业：将其从自身的队列中移除，或者调用CryIf_CancelJob。CryIf 将此中止同步分发给 Crypto Driver Object SWS CSM 第80页 [SWS_CryIf_91014]。在E_OK的情况下，CSM 调用作业的完成回调。后续版本的文档位置还额外提到了CRYPTO_E_JOB_CANCELED：此时中止仅在下一个合适的处理步骤进行，并返回否定反馈SWS CryptoInterface 第24页。简化的需求文本并未明确 R20-11 是否已包含该值。

时序图：作业的中止经由 CryIf 传递给驱动程序，其结果决定了向用户的反馈。来源：[SWS_CryIf_91014]、SWS CSM 第80页、SWS CryptoInterface 第46页

密钥引用：从 cryIfKeyId 到驱动程序的密钥 ID

CryIf 使用自己的密钥标识符（cryIfKeyId）并将其转换为负责的驱动程序的密钥 ID。这涉及密钥管理服务CRYPTO_KEYSETVALID、CRYPTO_KEYSETINVALID、CRYPTO_RANDOMSEED、CRYPTO_KEYGENERATE、CRYPTO_KEYDERIVE、CRYPTO_KEYEXCHANGECALCPUBVAL和CRYPTO_KEYEXCHANGECALCSECRET。对于这些服务，CryIf_ProcessJob会检查cryIfKeyId以及在适当时targetCryIfKeyId是否在有效范围内。如果是，CryIf 将设置job->cryptoKeyId以及在适当时设置job->targetCryptoKeyId [SWS_CryIf_00133]。如果某个标识符超出范围，CryIf 会向 DET 报告CRYPTO_E_PARAM_HANDLE并返回E_NOT_OK。对于CRYPTO_KEYDERIVE，这同样适用于目标标识符[SWS_CryIf_00134] [SWS_CryIf_00135] [SWS_CryIf_00141]。

对于基于密钥的原语，CryIf 以相同的方式检查job->jobPrimitiveInfo->cryIfKeyId。其中包括 MAC、加密和解密、AEAD、随机数生成以及签名生成和验证[SWS_CryIf_00143]。在作业重定向（job processing redirection）时，CryIf 还会将传入的密钥和密钥元素引用转换为驱动程序的值[SWS_CryIf_00136]。后续版本的文档位置在服务列表中还额外列出了CRYPTO_CUSTOM。根据变更历史，该服务直到 R22-11 才添加，因此不适用于 R20-11 SWS CryptoInterface 第23页 SWS CryptoInterface 第1页。

初始化与并发性

在进行任何其他使用之前，必须使用指向所选配置的指针调用CryIf_Init。该函数是同步且不可重入的[SWS_CryIf_91000]。如果在初始化之前调用 API，且启用了开发错误检测，CryIf 将报告CRYIF_E_UNINIT [SWS_CryIf_00009]。规范在例如CryIf_KeyGetStatus中展示了这一点SWS CryptoInterface 第29页。版本信息由CryIf_GetVersionInfo以同步且可重入的方式提供[SWS_CryIf_91001]。

关于并发性：

  • CryIf_ProcessJob和CryIf_CancelJob是可重入的[SWS_CryIf_91003] [SWS_CryIf_91014]。
  • CryIf_CallbackNotification是不可重入的。因此来自多个驱动程序的调用不得重叠[SWS_CryIf_91013]。
  • 复制函数可以并行运行，但不能针对相同的cryIfKeyId [SWS_CryIf_91015]。

发生错误时的行为

对于开发错误，R20-11 定义了以下代码[SWS_CryIf_00009]：

  • CRYIF_E_UNINIT (0x00)：在初始化之前调用
  • CRYIF_E_INIT_FAILED (0x01)：初始化失败
  • CRYIF_E_PARAM_POINTER (0x02)：空指针
  • CRYIF_E_PARAM_HANDLE (0x03)：参数超出范围
  • CRYIF_E_PARAM_VALUE (0x04)：无效值
  • CRYIF_E_KEY_SIZE_MISMATCH (0x05)：源元素的大小与目标元素不匹配

代码CRYIF_E_KEY_SIZE_MISMATCH可能主要在驱动程序之间的复制中相关，因为 CryIf 自身执行该复制[SWS_CryIf_00140]。

在密钥的范围检查中，R20-11 给出的名称与错误表不同。需求中称为CRYPTO_E_PARAM_HANDLE [SWS_CryIf_00134] [SWS_CryIf_00143]，而表格中则定义为CRYIF_E_PARAM_HANDLE。在 R22-11 中对此进行了统一，并且取消了 DET 报告后的返回值SWS CryptoInterface 第1页。对于 R20-11：密钥标识符的范围错误即使在非开发模式下也会导致E_NOT_OK [SWS_CryIf_00141]。

功能性错误作为 Crypto 返回值来自驱动程序[SWS_CryIf_91020]：

  • CRYPTO_E_BUSY (0x02)
  • CRYPTO_E_ENTROPY_EXHAUSTED (0x04)
  • CRYPTO_E_KEY_READ_FAIL (0x06)
  • CRYPTO_E_KEY_WRITE_FAIL (0x07)
  • CRYPTO_E_KEY_NOT_AVAILABLE (0x08)
  • CRYPTO_E_KEY_NOT_VALID (0x09)

CryIf 会传递这些值。例如，CryIf_ProcessJob可能以CRYPTO_E_BUSY、CRYPTO_E_KEY_NOT_VALID或CRYPTO_E_KEY_SIZE_MISMATCH结束[SWS_CryIf_91003]。如果设置密钥元素失败，则应将其状态视为未知。应用程序可以使用Csm_KeyGetStatus进行检查，该函数反过来又会调用CryIf_KeyGetStatus SWS CSM 第62页 SWS CSM 第63页。

Std_ReturnType CryIf_ProcessJob (uint32 channelId, Crypto_JobType* job);

服务 CryIf_ProcessJob。

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: ddb7806dc298 Provenance

函数 CryIf_ProcessJob（[SWS_CryIf_91003]）将传入的加密作业转发给配置的 Crypto Driver Object。它接收通道标识符 channelId 以及指向作业配置 job（类型为 Crypto_JobType*）的指针。根据配置，作业以同步或异步方式执行。该函数设计为可重入。

参数检查与 DET 报告

在处理之前，该函数对密钥参数执行特定检查：

  • 如果在 job->jobPrimitiveInfo->primitiveInfo->service 中配置了服务 CRYPTO_KEYSETVALID、CRYPTO_KEYSETINVALID、CRYPTO_RANDOMSEED、CRYPTO_KEYGENERATE、CRYPTO_KEYDERIVE、CRYPTO_KEYEXCHANGECALCPUBVAL 或 CRYPTO_KEYEXCHANGECALCSECRET 之一，则 job->cryIfKeyId 必须在有效范围内。否则，CryIf_ProcessJob 向 DET 报告错误 CRYPTO_E_PARAM_HANDLE 并返回 E_NOT_OK（[SWS_CryIf_00134]）。
  • 如果设置了服务 CRYPTO_KEYDERIVE，则目标密钥 job->cryIfTargetKeyId 也必须在有效值范围内。超出范围时，该函数同样向 DET 报告 CRYPTO_E_PARAM_HANDLE 并返回 E_NOT_OK（[SWS_CryIf_00135]）。

返回值

类型为 Std_ReturnType 的返回值指示成功（E_OK）、一般失败（E_NOT_OK）或特定错误状态（[SWS_CryIf_91003]）：

  • CRYPTO_E_BUSY：Crypto Driver Object 正忙。
