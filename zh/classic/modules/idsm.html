角色与系统边界：从传感器事件到合格的安全事件

Intrusion Detection System Manager (IdsM) 是 Classic Platform 的 BSW 模块，通过标准化接口接收板载安全事件（SEv）。它根据可配置的规则将其过滤为合格事件（QSEv），并随后对其进行存储或发送 SWS IdsM 第7页。作为传感器进行报告的有 BSW 模块、专有 CDD 和 SW-C。接收端（Sink）为通过 PduR 访问的 IDS Reporter (IdsR)，以及用于本地存储的 DEM/Sem SWS IdsM 第16页 [SWS_IdsM_01202] [SWS_IdsM_01601]。

IdsM 明确不对系统是否真正受到威胁进行评估。它不知道上下文数据的含义；检测和响应位于该模块之外，例如在 SOC 中 [SWS_IdsM_CONSTR_00001]。此外，该规范允许根据报告频率或系统负载丢弃 SEv SWS IdsM 第11页。

其他相邻模块及其任务：

  • DET：开发错误
  • DCM：对 Reporting Mode 的诊断访问
  • NvM：Reporting Mode 的持久化
  • BswM：Block State 的提供者
  • StbM 或 SW-C：时间戳源
  • CSM：签名
  • BSW 调度器：周期性调用

证据：SWS IdsM 第13页。包含哪些头文件取决于相应的配置开关，例如在 IdsMDevErrorDetect 时的 Det.h 以及在 IdsMSinkIdsR 时的 PduR.h [SWS_IdsM_00101] [SWS_IdsM_00105]。

生命周期：初始化与周期性处理

IdsM_Init 初始化所有内部变量，并将模块置于“已初始化”状态 [SWS_IdsM_00202] [SWS_IdsM_91001]。在已初始化状态下的再次调用不会重新初始化。而在激活 IdsMDevErrorDetect 时，它会报告 IDSM_E_ALREADY_INITIALIZED [SWS_IdsM_00204]。在未初始化状态下，除 IdsM_Init 和 IdsM_GetVersionInfo 之外的任何 API 调用都会导致 DET 错误 [SWS_IdsM_00203]。

实际工作以异步方式运行。IdsM_MainFunction 被周期性调用，并处理在 API 调用期间排队的事件 [SWS_IdsM_91000] SWS IdsM 第19页。周期 IdsMMainFunctionPeriod 同时也是所有区间过滤器的时基。它们的区间必须是该周期的倍数，并从第一次 MainFunction 调用开始 [SWS_IdsM_01050] [SWS_IdsM_01051] [SWS_IdsM_01064] [SWS_IdsM_01065]。

状态图：只有 IdsM_Init 才能使模块变为可用。在两种状态下的错误调用都会报告给 DET，而不会改变状态。来源：[SWS_IdsM_00202]、[SWS_IdsM_00203]、[SWS_IdsM_00204]、[SWS_IdsM_91000]。

安全事件的报告：身份、API 变体与缓冲

每个 SEv 实例由四项信息描述：IdsMExternalEventId、IdsMSensorInstanceId、内部计算得出的 IdsMInternalEventId 以及事件名称 [SWS_IdsM_00600] [SWS_IdsM_00601]。使用时适用以下规则（SWS IdsM 第21页）：

  • 传感器仅使用 IdsMEvent 容器的符号常量，绝不使用内部数值 [SWS_IdsM_00602] [SWS_IdsM_00607]。
  • 外部 ID 0xFFFF 是无效的 [SWS_IdsM_00604]。
  • 若只有一个模块实例，则传感器实例默认为 0 [SWS_IdsM_00608]。

对于报告，提供了六个同步、非重入的服务。它们随附的附加数据各不相同。带有计数器和时间戳的变体针对自行确定这些值的 Smart Sensors（SW-C 或 CDD）SWS IdsM 第19页。如果仅有时间戳而没有自己的计数器，则传递 count = 1 [SWS_IdsM_00405]。

资格确认：Reporting Mode 与过滤链

每个 SEv 都有一个强制性的 Reporting-Mode 过滤器。它不是过滤链的一部分，而是直接依附于事件；其默认值来自 IdsMReportingModeFilter [SWS_IdsM_01010] [SWS_IdsM_01011] [SWS_IdsM_01012]。IdsM_Filters_ReportingModeType 的取值含义如下 [SWS_IdsM_91013] SWS IdsM 第91页：

  • IDSM_REPORTING_MODE_OFF：事件被丢弃。
  • IDSM_REPORTING_MODE_BRIEF / IDSM_REPORTING_MODE_DETAILED：分别在不带或带上下文数据的情况下进行报告。
  • …_BYPASSING_FILTERS：绕过过滤链进行报告。

只有在 Reporting Mode 之后，才会对分配给该 SEv 的过滤链进行求值 [SWS_IdsM_01001] [SWS_IdsM_01002]。已激活的过滤器按固定顺序运行：Block State、Forward Every Nth、Event Aggregation、Event Threshold [SWS_IdsM_01004]。如果某个过滤器丢弃了该 SEv，则不再进行后续求值 [SWS_IdsM_01005] SWS IdsM 第25页。一条过滤链至少需要一个过滤器 [SWS_IdsM_CONSTR_00002]。各个过滤器的工作方式如下：

  • Block State：BswM 通过 IdsM_BswM_StateChanged 报告当前状态。如果该状态属于所引用的 IdsMBlockState，则丢弃该 SEv [SWS_IdsM_01022] [SWS_IdsM_01023] SWS IdsM 第28页。
  • Forward Every Nth：第 1 个以及此后每第 n 个 SEv 将被原封不动地转发 [SWS_IdsM_01031] [SWS_IdsM_01032] [SWS_IdsM_01033]。
  • Aggregation：SEv 会在 IdsMEventAggregationTimeInterval 期间被保留。在间隔结束时，一个包含所有计数器总和的 SEv 被继续传递；上下文数据和时间戳可选地来自第一个或最后一个 SEv [SWS_IdsM_01043] [SWS_IdsM_01046] [SWS_IdsM_01047] [SWS_IdsM_01048] [SWS_IdsM_01049] SWS IdsM 第40页。
  • Threshold：只要间隔内的计数器总和低于 IdsMEventThresholdNumber，就会被丢弃；一旦达到阈值，就会被转发。在间隔结束时，计数器被重置 [SWS_IdsM_01061] [SWS_IdsM_01062] [SWS_IdsM_01063] SWS IdsM 第41页。

活动图：首先由 Reporting Mode 决定丢弃、旁路还是过滤。随后，SEv 按固定顺序遍历已激活的过滤器，直到被丢弃或成为 QSEv。来源：SWS IdsM 第35页、SWS IdsM 第24页、[SWS_IdsM_01004]、[SWS_IdsM_01005]、[SWS_IdsM_91013]。

合格事件的丰富与转发

无论接收端（Sink）为何，QSEv 都具有符合 IDS 协议的固定结构 [SWS_IdsM_01200]。具体使用哪些接收端，由每个 IdsMEvent 的配置决定 [SWS_IdsM_01201] SWS IdsM 第35页。通过 IdsMSinkIdsR，QSEv 通过 PduR_IdsMTransmit 作为 IDS Message 发送 [SWS_IdsM_01203] [SWS_IdsM_01498]。在发送至 IdsR 之前，实例级限制会生效：速率限制约束每个间隔的 QSEv 数量，流量限制约束每个间隔的字节数 [SWS_IdsM_01070] [SWS_IdsM_01081] [SWS_IdsM_01091] SWS IdsM 第32页。

传输路径取决于大小 SWS IdsM 第38页：

  • 如果 IDS Message 连同签名能容纳在一个总线 PDU 中，则使用 IF-PDU [SWS_IdsM_01400]；确认通过 IdsM_TxConfirmation 传入 [SWS_IdsM_01500]。
  • 否则将使用 TP-PDU [SWS_IdsM_01401]。PduR 通过 IdsM_CopyTxData 分段获取数据 [SWS_IdsM_01501]，并通过 IdsM_TpTxConfirmation 进行确认 [SWS_IdsM_01502]。
  • 在收到确认之前，IdsM 不会再次调用 PduR_IdsMTransmit [SWS_IdsM_01499]。

时序图：在限制之后，QSEv 根据大小作为 IF- 或 TP-PDU 进行传输。只有在确认之后，才允许开始下一次传输。来源：[SWS_IdsM_01070]、[SWS_IdsM_01400]、[SWS_IdsM_01401]、[SWS_IdsM_01499]、[SWS_IdsM_01501]、[SWS_IdsM_01502]。

IdsM 可选地对每个 QSEv 进行签名。该功能通过由 IdsMCsmJobReference 引用的 CSM 作业进行全局激活。签名通过 Csm_SignatureGenerate 生成；对于异步作业，CSM 通过 IdsM_CsmNotification 报告结果 [SWS_IdsM_01204] [SWS_IdsM_01206] [SWS_IdsM_01208] SWS IdsM 第36页。DEM/Sem 接收端在 R20-11 中被标记为 DRAFT；它存储完整的 IDS Message [SWS_IdsM_01600] [SWS_IdsM_01602]。

时间戳通过 IdsMTimestampOption 进行全局切换 [SWS_IdsM_01100] [SWS_IdsM_01103] SWS IdsM 第33页。适用以下规则 SWS IdsM 第34页：

  • 如果传感器未提供时间戳，IdsM 会自行获取：对于“AUTOSAR”，通过 StbM_GetCurrentTime 获取；对于“Custom”，通过来自 SW-C 的接口 IdsM_CustomTimestamp 获取 [SWS_IdsM_01104] [SWS_IdsM_01107] [SWS_IdsM_01109] [SWS_IdsM_01111]。
  • 传感器报告的时间戳具有优先级，并会被截短至低 62 位 [SWS_IdsM_01108] [SWS_IdsM_01110]。
  • 对于“None”，传入的时间戳也会被忽略 [SWS_IdsM_01106]。

规范中的一个待定问题：当使用不带时间戳参数的时间戳 API 时，[SWS_IdsM_01112] 要求将时间戳选项位设为 0。这与 [SWS_IdsM_01101] 的关系如何，正文未作说明。

活动图：时间戳源由 IdsMTimestampOption 和所报告的参数确定。来源：SWS IdsM 第87页、[SWS_IdsM_01104]、[SWS_IdsM_01106]、[SWS_IdsM_01108]、[SWS_IdsM_01109]、[SWS_IdsM_01110]。

值范围与语义

该类型规定了所检测到的安全事件（Security-Event）将如何或是否进一步报告：

  • IDSM_REPORTING_MODE_OFF（0x00）：不报告该事件。
  • IDSM_REPORTING_MODE_BRIEF（0x01）：以紧凑形式报告该事件，不含上下文数据。
  • IDSM_REPORTING_MODE_DETAILED（0x02）：以详细形式报告该事件，包含上下文数据。
  • IDSM_REPORTING_MODE_BRIEF_BYPASSING_FILTERS（0x03）：绕过过滤器，以未过滤的形式报告该事件，不含上下文数据。
  • IDSM_REPORTING_MODE_DETAILED_BYPASSING_FILTERS（0x04）：绕过过滤器，以未过滤的形式连同上下文数据一起报告该事件。
