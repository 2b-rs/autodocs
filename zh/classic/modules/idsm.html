收集传感器的安全事件，对其进行过滤并将合格事件转发至接收端。

IdsM 收集由 BSW 模块、CDD 和 SW-C 报告的 Security Event，对其进行缓冲并在 IdsM_MainFunction 中进行异步处理 [SWS_IdsM_00702]。Reporting Mode 以及由 Block-State、Sampling、Aggregation 和阈值过滤器组成的过滤链将其转换为合格事件 [SWS_IdsM_01004]。这些事件通过 PduR 发送至 IdsR，或存储在 DEM/Sem 中。时间戳、签名和诊断访问是可选的。IdsM 不评估上下文数据的含义；对攻击的响应位于模块外部。

IdsM 接收来自安全传感器的 Security Event（SEv），即来自 BSW 模块、CDD 和 SW-C。它通过过滤链将其转换为 Qualified Security Event（QSEv）[SWS_IdsM_00902]。它通过 PduR 将 QSEv 发送至 IdsR，存储在 DEM/Sem 中，或两者兼有 [SWS_IdsM_01202] [SWS_IdsM_01600]。它不评估上下文数据的含义。对攻击的响应位于模块外部，例如在 SOC 中 [SWS_IdsM_CONSTR_00001]。

传感器通过 IdsM_SetSecurityEvent 或带有上下文数据（最多 1500 字节）、计数器和时间戳的五种变体之一进行报告 [SWS_IdsM_00300] [SWS_IdsM_00404] [SWS_IdsM_00501]。在此过程中，它们始终使用 IdsMEvent 的符号名称 [SWS_IdsM_00607]。报告服务仅缓冲 SEv。实际处理在 IdsM_MainFunction 中异步运行 [SWS_IdsM_00702]。若缺少空闲的 Event Buffer，只要进行了配置，IdsM 就会触发一个内部 SEv [SWS_IdsM_00703]。

限定始于 Reporting Mode。可能的值包括 OFF、BRIEF、DETAILED 以及绕过过滤器的变体 [SWS_IdsM_01002] [SWS_IdsM_91013]。随后活动过滤器按固定顺序运行：Block State、Forward Every n-th、Aggregation、Threshold [SWS_IdsM_01004]。若过滤器丢弃了 SEv，则评估结束 [SWS_IdsM_01005]。在发送至 IdsR 之前，速率和流量限制也会生效 [SWS_IdsM_01070]。这些限制大概率也适用于绕过模式（解读）。

活动图：先是 Reporting Mode，然后是过滤链，最后是 IdsR 之前的实例限制。来源：SWS IdsM 第35页、[SWS_IdsM_01004]、[SWS_IdsM_01070]

可选地可以启用其他功能 [SWS_IdsM_01100] [SWS_IdsM_01204] [SWS_IdsM_01901] [SWS_IdsM_01702]：

  • 来自 StbM 或来自应用程序的时间戳
  • 通过 CSM 进行签名
  • 通过 DCM 读取和修改 Reporting Mode，具备 NvM 持久化并在出错时回滚

IdsM 仅在 IdsMDevErrorDetect 处于激活状态时才向 DET 报告开发错误 [SWS_IdsM_02003]。接收端 DEM/Sem 在 R20-11 中的状态为 DRAFT [SWS_IdsM_01601]。

角色：从上报的安全事件到合格事件

Intrusion Detection System Manager (IdsM) 收集安全事件（SEv）。这些事件由安全传感器检测并上报，即 BSW 模块、Complex Device Driver 或 SW-C SWS IdsM 第10页。IdsM 会根据可配置的过滤器序列（即过滤链）检查每个 SEv。若 SEv 通过该检查，则转变为合格安全事件（QSEv）[SWS_IdsM_00902]。只有 QSEv 会被进一步处理。它们通过 PduR 发送到另一台控制器上的 IdsR，存储在 DEM/Sem 中，或者两者兼有 [SWS_IdsM_01202] [SWS_IdsM_01600] SWS IdsM 第35页。

系统边界划分得很窄。IdsM 不了解上下文数据的含义，因此不会自行判断系统是否受到损害。检测与响应位于该模块外部，例如在 SOC 中 [SWS_IdsM_CONSTR_00001]。与其他模块之间不存在强制接口 [SWS_IdsM_91023]。所有耦合均通过配置启用。条件头文件包含体现了这一点：

  • Det.h 在 IdsMDevErrorDetect 下
  • Dem.h 在 IdsMSinkDem 下
  • Dcm.h 在 IdsMDiagnosticSupport 下
  • NvM.h 在 IdsMNvmBlockDescriptor 下
  • PduR.h 在 IdsMSinkIdsR 下

这些包含关系的依据：[SWS_IdsM_00101] 至 [SWS_IdsM_00105]。

启动、事件标识与上报接口

IdsM_Init 初始化所有内部变量，并将模块置于“已初始化”状态 [SWS_IdsM_00202] [SWS_IdsM_91001]。在此时间点之前，仅允许调用 IdsM_Init 和 IdsM_GetVersionInfo SWS IdsM 第21页。再次调用 IdsM_Init 不会对模块进行二次初始化 [SWS_IdsM_00204]。

状态图：该模块具有两个状态。在两种状态下的错误调用，仅在开发错误检测处于激活状态时才会向 DET 报告错误。来源：[SWS_IdsM_00202]、[SWS_IdsM_00203]、[SWS_IdsM_00204]、SWS IdsM 第21页

每个 SEv 由三个标识符和事件名称来标识 [SWS_IdsM_00600]：

  • IdsMExternalEventId 全局唯一且源自 Security Extract。值 0xFFFF 无效 [SWS_IdsM_00603] [SWS_IdsM_00604]。
  • 若只有一个模块实例，IdsMSensorInstanceId 默认值为 0 [SWS_IdsM_00608]。
  • IdsMInternalEventId 由 IdsM 内部计算 [SWS_IdsM_00601]。

传感器仅通过 IdsMEvent 容器的符号名称进行上报。不得依赖其内部值 [SWS_IdsM_00602] [SWS_IdsM_00607]。提供了六个用于上报的服务：

服务附加数据出处
IdsM_SetSecurityEvent无[SWS_IdsM_00300]
IdsM_SetSecurityEventWithContextData上下文数据[SWS_IdsM_00301]
IdsM_SetSecurityEventWithCount计数器（智能传感器）[SWS_IdsM_00401]
IdsM_SetSecurityEventWithCountContextData计数器、上下文数据[SWS_IdsM_00402]
IdsM_SetSecurityEventWithTimestampCount时间戳、计数器[SWS_IdsM_00403]
IdsM_SetSecurityEventWithTimestampCountContextData时间戳、计数器、上下文数据[SWS_IdsM_00404]

传感器将上下文数据作为指向字节数组的指针传递。支持最多 1500 字节 [SWS_IdsM_00501] [SWS_IdsM_00502]。具有时间戳但没有独立计数器的实体，使用 count = 1 进行上报 [SWS_IdsM_00405]。

外部 ID 在 0x8000–0xFFFE 范围内的 SW-C 通过服务接口 IdsMService_{EventName} 或 IdsMSmartSensorService_{EventName} 访问 IdsM。适用哪个接口取决于 IdsMAdditionalParameterOption（None、Count、CountTimestamp）[SWS_IdsM_91027] [SWS_IdsM_91028] [SWS_IdsM_01301] [SWS_IdsM_01303]。在 R20-11 中，这些服务具有规范性。后续版本将其标记为 OBSOLETE SWS IdsM 第67页。

IdsM_MainFunction 中的缓冲与异步处理

上报服务不会立即处理 SEv。IdsM 首先将其存放在 Event Buffer 中。过滤与传递在周期性调用的 IdsM_MainFunction 中稍后异步执行 [SWS_IdsM_00702] [SWS_IdsM_00901] [SWS_IdsM_91000]。Event Buffer 的数量（IdsMNumberOfEventBuffers）是可配置的 [SWS_IdsM_00701]。作为参考值，规范建议采用聚合过滤器实例数加上并行处理事件上限的总和 SWS IdsM 第24页。

时序图：上报在缓冲后立即返回。时间戳、过滤和传递直到 IdsM_MainFunction 中才执行。来源：SWS IdsM 第86页、[SWS_IdsM_00702]、[SWS_IdsM_00901]、[SWS_IdsM_01107]

上下文数据存放在大小可配置（最大 1500 字节）的专用 Context Data Buffer 中 [SWS_IdsM_00704] SWS IdsM 第122页。IdsM 选择相同或下一个更大尺寸的缓冲区，并将其与 Event Buffer 关联 [SWS_IdsM_00705] [SWS_IdsM_00706]。不带上下文数据的 SEv 不会占用此类缓冲区 [SWS_IdsM_00709]。对于 IdsM 自身的内部 SEv，设有专门且独立的缓冲区 [SWS_IdsM_00802]。

合格化：Reporting Mode、过滤链与实例限制

IdsM 首先评估 Reporting Mode。每个 SEv 恰好具有一个 Reporting Mode 过滤器。该过滤器为必选，直接挂接在 SEv 上，不属于过滤链 [SWS_IdsM_01010] [SWS_IdsM_01011]。起始值来自 IdsMReportingModeFilter [SWS_IdsM_01012]。过滤链在此之后才起作用 [SWS_IdsM_01002]。IdsM_Filters_ReportingModeType 支持以下模式 [SWS_IdsM_91013]：

  • IDSM_REPORTING_MODE_OFF：不报告该事件。
  • IDSM_REPORTING_MODE_BRIEF：不带上下文数据进行上报。
  • IDSM_REPORTING_MODE_DETAILED：带上下文数据进行上报。
  • 两种 …_BYPASSING_FILTERS 变体：像 BRIEF 或 DETAILED 那样上报，但不过滤。

过滤链分配给 SEv [SWS_IdsM_01001] [SWS_IdsM_00903]。每个 IdsMFilterChain 至少需要一个过滤器 [SWS_IdsM_CONSTR_00002]。活动的过滤器按固定顺序执行 [SWS_IdsM_01004]。一旦某个过滤器丢弃了该 SEv，评估立即终止。否则，SEv 将传递给下一个过滤器 [SWS_IdsM_00904] [SWS_IdsM_00905] [SWS_IdsM_01005]。按此顺序排列的四个过滤器：

  1. Block State：BswM 通过 IdsM_BswM_StateChanged 以类型为 IdsM_Filters_BlockStateType 的位掩码形式报告当前状态。若该状态在 IdsMBlockState 中被引用，则过滤器丢弃该 SEv [SWS_IdsM_01022] [SWS_IdsM_01023] [SWS_IdsM_91017]。一个过滤器最多可引用 16 个状态 SWS IdsM 第85页。
  2. Forward Every n-th：转发第一个 SEv，此后根据 IdsMNthParameter 转发每第 n 个。在此期间数据保持不变 [SWS_IdsM_01031] [SWS_IdsM_01032] [SWS_IdsM_01033]。
  3. Event Aggregation：在时间间隔内，过滤器不转发任何内容。在时间间隔结束时，生成一个带有累计计数器 [SWS_IdsM_01043] 的单一 SEv [SWS_IdsM_01046]。上下文数据和时间戳来自该间隔内的第一个或最后一个 SEv，具体取决于 IdsMContextDataSourceSelector [SWS_IdsM_01047] [SWS_IdsM_01049]。示例见 SWS IdsM 第40页。
  4. Event Threshold：只要当前间隔内的计数器总和低于 IdsMEventThresholdNumber，过滤器就会丢弃 SEv。随着间隔期满，总和将被重置 [SWS_IdsM_01061] [SWS_IdsM_01062] [SWS_IdsM_01063]。示例见 SWS IdsM 第41页。

所有间隔均为 IdsMMainFunctionPeriod 的整数倍。聚合和阈值间隔自 Main Function 首次调用起开始运行 [SWS_IdsM_01050] [SWS_IdsM_01051] [SWS_IdsM_01065]。

在发送给 IdsR 之前，针对整个 IdsM 实例会有两项限制生效 [SWS_IdsM_01070]：

  • 速率限制允许每个间隔最多 IdsMRateLimitationMaximumEvents 个 QSEv [SWS_IdsM_01081]。
  • 流量限制允许每个间隔最多 IdsMTrafficLimitationMaximumBytes 字节 [SWS_IdsM_01091] [SWS_IdsM_01093]。

IdsM 的内部 SEv 不经过这些实例过滤器。但它们允许拥有特定于事件的过滤器 [SWS_IdsM_00803] [SWS_IdsM_00804]。解释：Bypass 模式仅绕过过滤链。速率和流量限制大概率也适用于它们，因为 [SWS_IdsM_01070] 要求在向 IdsR 进行每次传输之前都执行这些限制。

活动图：先是 Reporting Mode，然后是按固定顺序的过滤器，最后是在 IdsR 之前的实例限制。未配置的过滤器将被省略。来源：SWS IdsM 第35页、[SWS_IdsM_01002]、[SWS_IdsM_01004]、[SWS_IdsM_01070]、[SWS_IdsM_91013]

时间戳、IDS 报文与接收端

时间戳是可选的，通过 IdsMTimestampOption 进行全局控制 [SWS_IdsM_01100]：

  • None：该功能已关闭。随同上报的时间戳将被忽略 [SWS_IdsM_01103] [SWS_IdsM_01106]。
  • AUTOSAR：来源为 StbM_GetCurrentTime [SWS_IdsM_01104] [SWS_IdsM_01107]。
  • Custom：IdsM 通过端口 CustomTimestamp 处的接口 IdsM_CustomTimestamp（操作 Get）查询应用程序 [SWS_IdsM_01109] [SWS_IdsM_01111]。

若传感器自身提供了时间戳，则优先使用该时间戳 [SWS_IdsM_01108]。IdsM 将其截断为低 62 位 [SWS_IdsM_01110]。根据时序流程图，IdsM 在 Main Function 中为所有已缓冲事件确定时间戳 SWS IdsM 第87页。

活动图：如何根据 IdsMTimestampOption 选择时间戳来源。来源：[SWS_IdsM_01106]、[SWS_IdsM_01107]、[SWS_IdsM_01108]、[SWS_IdsM_01109]、[SWS_IdsM_01110]、SWS IdsM 第86页

无论发送至哪个接收端，QSEv 都具有相同的结构 [SWS_IdsM_01200]。IDS 报文由 Event Frame 以及可选的 Timestamp、Context Data 和 Signature 组成 PRS IDS 第11页。事件使用哪些接收端由 IdsMEvent 的配置决定 [SWS_IdsM_01201]。

签名是可选的。一旦配置了 IdsMCsmJobReference，它就会全局激活。它通过 Csm_SignatureGenerate 触发。对于同步任务，签名立即可用；对于异步任务，IdsM_CsmNotification 会报告结果 [SWS_IdsM_01204] [SWS_IdsM_01206] [SWS_IdsM_01207] [SWS_IdsM_01208]。

对于接收端 IdsR，IdsM 通过 PduR_IdsMTransmit 发送 [SWS_IdsM_01498]。若报文能容纳在总线 PDU 中，则使用 IF-PDU，否则使用 TP-PDU [SWS_IdsM_01400] [SWS_IdsM_01401]。只有在前一个发送请求确认之后，才会发起新的发送请求 [SWS_IdsM_01499]。接收端 DEM/Sem 存储完整的 IDS 报文。它在 R20-11 中的状态为 DRAFT [SWS_IdsM_01601] [SWS_IdsM_01602]。

时序图：首先是通过 CSM 进行可选签名，然后作为 IF-PDU 或分段的 TP-PDU 进行带确认的传输。来源：[SWS_IdsM_01207]、[SWS_IdsM_01208]、[SWS_IdsM_01500]、[SWS_IdsM_01501]、[SWS_IdsM_01502]、SWS IdsM 第49页

诊断重配置与 Reporting Mode 的持久化

诊断访问是可选的，通过 IdsMDiagnosticSupport 启用 [SWS_IdsM_01800]。

  • 修改：DCM 使用新值调用 IdsM_Dcm_SetReportingMode_Start [SWS_IdsM_01901] [SWS_IdsM_91008]。若模式或事件 ID 无效，IdsM 将响应 E_NOT_OK 和 DCM_E_REQUESTOUTOFRANGE [SWS_IdsM_01902] [SWS_IdsM_01903]。
  • 读取：DCM 首先调用 IdsM_Dcm_GetReportingMode_Start，然后使用 IdsM_Dcm_GetReportingMode_RequestResults 获取结果 [SWS_IdsM_02001] [SWS_IdsM_02002]。

成功修改后，IdsM 触发 NvM_WriteBlock [SWS_IdsM_01701]。若持久化失败，它将恢复先前的值并报告 DCM_E_GENERALPROGRAMMINGFAILURE [SWS_IdsM_01702] [SWS_IdsM_01904] [SWS_IdsM_01905]。

启动时，IdsM 使用持久化的值。若不存在，则配置生效 [SWS_IdsM_01703] [SWS_IdsM_01704]。NvM 块必须包含在 NvM_ReadAll 中，其名称为 IdsM_NvMRamBlockData 或 IdsM_NvMRomBlockData [SWS_IdsM_01705] [SWS_IdsM_01706] [SWS_IdsM_01707]。推测 DCM 是通过使用 OpStatus 的重复调用获知持久化结果的 DCM_PENDING。后续版本为此指定了 DCM_E_BUSYREPEATREQUEST SWS IdsM 第75页。

时序图：具有 NvM 持久化和回滚的 Reporting Mode 修改以及两阶段读取。来源：[SWS_IdsM_01901]、[SWS_IdsM_01904]、[SWS_IdsM_01905]、[SWS_IdsM_91007]、SWS IdsM 第74页。持久化的反馈路径被标记为解释。

发生错误时的行为

IdsM 仅在 IdsMDevErrorDetect 处于激活状态时才向 DET 报告开发错误。错误代码见 [SWS_IdsM_02003]：

  • IDSM_E_PARAM_INVALID：当事件 ID 未知时，所有六个上报服务均会报告该错误。计数器变体在 count = 0 时也会报告该错误 [SWS_IdsM_02101] [SWS_IdsM_02103] [SWS_IdsM_02106]。
  • IDSM_E_PARAM_LENGTH：当 contextDataSize 超过最大 IdsMContextDataBufferSize 时发生该错误 [SWS_IdsM_02107] [SWS_IdsM_02109]。
  • 初始化前的调用和重复初始化也会被报告 [SWS_IdsM_00203] [SWS_IdsM_00204]。

注意命名：[SWS_IdsM_00203] 将该代码命名为 IDSM_E_PARAM_UNINIT，而错误表将其列为 IDSM_E_UNINIT (0x0D) [SWS_IdsM_02003]。

如果已配置，IdsM 会将资源瓶颈作为自身的内部 SEv 进行报告 [SWS_IdsM_91015]：

  • 无可用 Event Buffer (ID 46) [SWS_IdsM_00703]
  • 无匹配的 Context Data Buffer (ID 47)。此时该 SEv 将在不带上下文数据的情况下被处理 [SWS_IdsM_00707] [SWS_IdsM_00708]
  • 超出流量限制 (ID 48) [SWS_IdsM_01094]

如果过滤器丢弃了某个 SEv，这是正常行为，而非错误 [SWS_IdsM_00904]。发送错误在确认中以 E_NOT_OK 的形式返回 [SWS_IdsM_91009]。带有 IdsMTransmissionRetryDelay 的重试规则直到 R25-11 才引入 SWS IdsM 第51页。
