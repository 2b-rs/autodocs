CanTp作为PduR与CanIf之间的分段层

CanTp是Classic通信栈的CAN Transport Layer。该模块对无法装入单个CAN帧的N-SDU进行分段，通过流控制进行传输，并在接收时重新组装（SWS CanTp 第23页）。专业基础是ISO 15765-2：凡在其中未明确排除的建议均须遵守[SWS_CanTp_00033]。分段和重组仅在状态CANTP_ON下进行[SWS_CanTp_00238]。

向上，CanTp仅与PDU Router协同工作。诸如DCM或Com等用户通过PduR访问CanTp_Transmit、CanTp_CancelTransmit和CanTp_CancelReceive（SWS PduR 第24页）。在相反方向上，CanTp调用服务PduR_CanTp…；向下，它使用CanIf_Transmit [SWS_CanTp_00216]。CanTp为下层提供回调CanTp_RxIndication和CanTp_TxConfirmation [SWS_CanTp_00078] [SWS_CanTp_00076]。二者都必须可在中断上下文中调用[SWS_CanTp_00235] [SWS_CanTp_00236]。较新的文档章节将下层协作伙伴称为“LSduR”（SWS CanTp 第26页）。在R20-11中，该伙伴为CanIf[SWS_CanTp_00335]。

从上电、CanTp_Init到通道状态

CanTp具有全局状态CANTP_OFF和CANTP_ON [SWS_CanTp_00027]。上电后，该模块处于CANTP_OFF中[SWS_CanTp_00168]。在此状态下允许更新Post-Build配置[SWS_CanTp_00169]。环境必须在进行任何进一步使用之前调用CanTp_Init [SWS_CanTp_00199]。该函数在此接收指向CanTp_ConfigType的指针[SWS_CanTp_00208] [SWS_CanTp_00340]。在模式管理指南的示例中，该调用位于NvM_ReadAll之后的BswM规则中（Modemanagement-Guide 第54页）。

成功初始化后，CanTp切换到CANTP_ON [SWS_CanTp_00170]。CanTp_Init初始化所有全局变量，并将每个连接分别设置为CANTP_RX_WAIT或CANTP_TX_WAIT [SWS_CanTp_00030]。在CANTP_ON中再次调用会导致返回空闲状态；在此过程中所有正在进行的连接都会丢失[SWS_CanTp_00111] [SWS_CanTp_00273]。CanTp_Shutdown关闭所有打开的连接，释放资源并切换到CANTP_OFF [SWS_CanTp_00202]。在此过程中不会对中止的传输发出通知[SWS_CanTp_00200]。

状态图：在CANTP_ON内部，Rx和Tx通道彼此独立地经历子状态WAIT和PROCESSING。来源：[SWS_CanTp_00027] [SWS_CanTp_00030] [SWS_CanTp_00202] SWS CanTp 第27页

发送N-SDU：Single Frame或分段会话

CanTp_Transmit传递总长度以及可能的MetaData，但不传递有效载荷数据。在没有MetaData的情况下，CanTp仅使用SduLength来准备Single Frame（SF）或First Frame（FF）的PCI[SWS_CanTp_00225] [SWS_CanTp_00299]。

解读：[SWS_CanTp_00212]将该API描述为同步的，而[SWS_CanTp_00176]则要求异步行为。推测该调用仅确认接收，传输随后进行。

如果数据无法装入分配的N-PDU中，则启动多帧会话[SWS_CanTp_00232]（SWS CanTp 第60页）。最大发送长度（TX_DL）由EcuC参数PduLength得出[SWS_CanTp_00354]。

CanTp针对每个段（SF、FF、CF）使用PduR_CanTpCopyTxData获取有效载荷数据[SWS_CanTp_00086] [SWS_CanTp_00298]。当为BUFREQ_E_BUSY时，CanTp会在稍后重试复制尝试[SWS_CanTp_00184]。Retry参数始终为NULL指针[SWS_CanTp_00272]。

在FF之后，定时器N_Bs监视Flow Control（FC）的到达[SWS_CanTp_00315]。FC分别在一个由BS个Consecutive Frame组成的块之后到来[SWS_CanTp_00278]。最后，CanTp使用PduR_CanTpTxConfirmation和E_OK报告完成情况[SWS_CanTp_00090] [SWS_CanTp_00204]。每个被接受的请求都以恰好一次此类反馈结束，即使在失败时也是如此[SWS_CanTp_00177]。

当通道被占用（CANTP_TX_PROCESSING）或N-SDU已在某个会话中运行时，CanTp会使用E_NOT_OK拒绝新的请求[SWS_CanTp_00123] [SWS_CanTp_00206]。

接收：缓冲区承诺、Flow Control与等待阶段

接收到的SF或FF会触发PduR_CanTpStartOfReception [SWS_CanTp_00079]。可用缓冲区大小通过输出指针返回，并且可以小于N-SDU[SWS_CanTp_00080]。针对FF的FC仅在此结果产生后发送，其内容取决于该结果[SWS_CanTp_00064] [SWS_CanTp_00277]。

在每个Consecutive Frame（CF）之后，CanTp使用PduR_CanTpCopyRxData传递数据：对于CAN 2.0为6或7字节，对于CAN FD为DLC-1或DLC-2字节。作为返回值，CanTp获得剩余缓冲区大小[SWS_CanTp_00269]。无论成功与否，CanTp在任何情况下都会使用PduR_CanTpRxIndication [SWS_CanTp_00084]报告完成。

如果缓冲区不足以容纳下一个块，CanTp会启动定时器N_Br[SWS_CanTp_00082] [SWS_CanTp_00325]。只要N_Br正在运行，CanTp就会在每个MainFunction中使用长度0和NULL_PTR查询空闲缓冲区[SWS_CanTp_00222]。在此过程中，它最多发送WFTmax个连续的FC(WAIT)；之后它以E_NOT_OK中止[SWS_CanTp_00223]。BS和STmin在同一个接收会话内保持恒定[SWS_CanTp_00067]。规范示例展示了在25字节缓冲区下接收49字节的过程（SWS CanTp 第38页）。

连接通道、寻址与缓冲区策略

CanTp同时服务于多个连接[SWS_CanTp_00096]。每个N-SDU静态分配给一个连接通道；一个通道可以服务于多个N-SDU[SWS_CanTp_00121]。每个通道拥有自己的缓冲区、定时器和状态机[SWS_CanTp_00122]。这些通道仅在内部可见[SWS_CanTp_00285]。它们的数量由配置工具根据N-SDU到通道的分配情况确定[SWS_CanTp_00289]。如果多个N-SDU共享一个通道且没有通道空闲，CanTp会拒绝发送或中止接收[SWS_CanTp_00288]（SWS CanTp 第41页）。

功能寻址（1:n）仅适用于Single Frame[SWS_CanTp_00092]。CanTp会拒绝通过功能句柄进行的分段会话并报告CANTP_E_INVALID_TATYPE [SWS_CanTp_00093]。在扩展寻址或混合寻址中，第一个数据字节（分别为N_TA或N_AE）决定关联的N-SDU[SWS_CanTp_00095] [SWS_CanTp_00284]。

通用连接使用MetaData进行工作。CanTp保存来自接收到的SF/FF或来自CanTp_Transmit的地址信息[SWS_CanTp_00330] [SWS_CanTp_00334]。它将其进一步传递给PduR或CanIf[SWS_CanTp_00331] [SWS_CanTp_00335]。它对照保存的值检查到达的CF和FC[SWS_CanTp_00333] [SWS_CanTp_00336]。只有在扩展/混合寻址或带有MetaData的情况下，一个N-PDU才允许被多个N-SDU引用[SWS_CanTp_00328]。

CanTp不在内部复制有效载荷数据，而是通过复制服务直接在上层缓冲区上进行操作[SWS_CanTp_00298]。因此，上层保持其缓冲区锁定。锁定始于CanTp_Transmit的E_OK或PduR_CanTpStartOfReception的BUFREQ_OK，并以相应的Confirmation或Indication结束（SWS CanTp 第35页）。

对于填充（Padding），适用以下规则（SWS CanTp 第43页）：

  • 仅将已使用的数据字节传递给上层[SWS_CanTp_00116]。
  • 填充值为CANTP_PADDING_BYTE [SWS_CanTp_00059]。
  • 在激活填充时，SF、最后一个CF和FC作为8字节帧发送[SWS_CanTp_00348] [SWS_CanTp_00347]。
  • 在CAN FD中，会填充到下一个有效的DLC[SWS_CanTp_00351]。

MainFunction节拍与运行时参数BS/STmin

CanTp_MainFunction由调度器周期性调用。它监视时间限制N_As、N_Bs、N_Cs、N_Ar、N_Br和N_Cr以及STmin[SWS_CanTp_00213] [SWS_CanTp_00164]。其行为取决于CanTpMainFunctionPeriod [SWS_CanTp_00300]。后续版本中的一处文档章节建议为此使用调用任务的周期时间（SWS CanTp 第77页）。时序分析给出了一个5 ms任务的示例（TR Timing 第117页）。

使用CanTp_ChangeParameter和CanTp_ReadParameter可以在运行时设置和读取接收N-SDU的BS与STmin[SWS_CanTp_00302] [SWS_CanTp_00323]。其中BS是一个最大值，出于缓冲区考虑，CanTp可以采用小于该值的数值[SWS_CanTp_00091]。在正在进行的接收期间无法进行修改；此时该服务返回E_NOT_OK [SWS_CanTp_00303] [SWS_CanTp_00304]。对于通用连接，修改对所有连接均有效[SWS_CanTp_00338]。这些服务是否存在由CanTpChangeParameterApi控制（SWS CanTp 第61页）。发送中止通过CanTpTc静态激活[SWS_CanTp_00242]。

发生错误时的行为

发生开发错误时，服务返回E_NOT_OK并将错误报告给DET[SWS_CanTp_00294]。典型情况：

  • 在CanTp_Init之前的调用会产生CANTP_E_UNINIT；CanTp_GetVersionInfo [SWS_CanTp_00031]除外。
  • NULL指针会产生CANTP_E_PARAM_POINTER [SWS_CanTp_00321] [SWS_CanTp_00322] [SWS_CanTp_00319]。

对于CanTp_CancelTransmit和CanTp_CancelReceive处的无效ID，R20-11要求CANTP_E_PARAM_ID [SWS_CanTp_00254] [SWS_CanTp_00260]。较新的文档章节则代之以CANTP_E_INVALID_TX_ID或CANTP_E_INVALID_RX_ID（SWS CanTp 第59页）。对于R20-11而言，该Requirement适用。[SWS_CanTp_00352]定义了运行时错误，如CANTP_E_PADDING、CANTP_E_INVALID_TATYPE和CANTP_E_OPER_NOT_SUPPORTED。

协议错误会终止会话，并使用E_NOT_OK报告给上层。恢复是用户（例如DCM）的职责（EXP Error 第30页；[SWS_CanTp_00205]）。

用法与调用上下文

上层通过函数 CanTp_Transmit 请求传输 PDU [SWS_CanTp_00212]。通过参数 TxPduId 识别 PDU，而 PduInfoPtr 指向数据长度、有效载荷数据以及可选的元数据 [SWS_CanTp_00212]。该函数在成功接受时以 E_OK 同步确认传输请求，在拒绝时以 E_NOT_OK 同步确认 [SWS_CanTp_00212]；实际的发送过程是异步的 [SWS_CanTp_00176]。

错误处理与拒绝条件

  • 无效指针：如果 DET 已启用且为 PduInfoPtr 传递了 NULL 指针，则该函数向 DET 报告错误 CANTP_E_PARAM_POINTER 并中止且不采取进一步操作 [SWS_CanTp_00321]。
  • 通道被占用：如果配置的传输通道处于状态 CANTP_TX_PROCESSING，则模块拒绝该通道的新发送请求并返回 E_NOT_OK [SWS_CanTp_00123]。
  • 正在进行的会话：如果传递的 N-SDU 标识符已在当前处于活动状态的 CanTp 传输会话中使用，发送请求同样会被拒绝 [SWS_CanTp_00206]。

并发性与数据处理

CanTp_Transmit 对于不同的 PDU-ID 是可重入的，但对于相同的 PDU-ID 是不可重入的 [SWS_CanTp_00212]。

对于没有元数据的连接，CanTp_Transmit 仅评估规范 SduLength 以创建单帧（SF）或首帧（FF）的 PCI，并且不访问 N-SDU 的数据缓冲区 [SWS_CanTp_00225]。如果使用元数据，模块将存储包含的地址信息（例如根据寻址格式的 N_SA、N_TA 或 N_AE），用于稍后发送 SF、FF 和 CF-N-PDU 以及识别 FC-N-PDU [SWS_CanTp_00334]。

使用

同步函数 CanTp_CancelTransmit（[SWS_CanTp_00246]）请求中止下层通信模块中正在进行的 PDU 传输。该调用启动发送中止（[SWS_CanTp_00274]），随后在相应连接上的传输被中止（[SWS_CanTp_00243]）。

  • 参数：TxPduId 确定要中止的 PDU 的标识符（[SWS_CanTp_00246]）。
  • 返回值：E_OK 表示目标模块已成功执行中止；E_NOT_OK 表示中止被拒绝（[SWS_CanTp_00246]）。

错误处理

如果开发错误检测处于激活状态，CanTp_CancelTransmit 会检查传入参数 TxPduId 的有效性（[SWS_CanTp_00254]）：

  • 如果参数值无效，该函数将报告开发错误 CANTP_E_PARAM_ID 并返回 E_NOT_OK（[SWS_CanTp_00254]）。
  • 如果针对当前未处于传输过程中的 N-SDU 请求中止，CanTp 模块将向 Default Error Tracer（DET）报告运行时错误 CANTP_E_OPER_NOT_SUPPORTED 并返回 E_NOT_OK（[SWS_CanTp_00254]）。

并发性与限制

CanTp_CancelTransmit 对于不同的 PDU ID 是可重入的，但对于相同的 PDU ID 是不可重入的（[SWS_CanTp_00246]）。
