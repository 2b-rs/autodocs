将长报文分段为 CAN 帧，并利用流控制重组接收到的分段。

CAN Transport Layer 将无法装入单个 CAN 帧的报文进行分段，通过 Flow Control 控制数据流，并根据 ISO 15765-2 重组接收到的分段 [SWS_CanTp_00033]。它位于 PduR 与 CanIf 之间，没有专属的有效负载缓冲区，并通过上一层的复制服务按段复制发送和接收数据 [SWS_CanTp_00298]。它向上一层发送消息来结束每个接受的传输：成功时为 E_OK，超时或中止时为 E_NOT_OK。所有这一切均以 CanTp_Init 为前提；周期性 MainFunction 负责监控超时。

CanTp 即 CAN Transport Layer。它将长报文分段为 CAN 帧，控制数据流，并重组接收到的分段；在此过程中，只要规范未另作规定，它均遵循 ISO 15765-2 [SWS_CanTp_00033]。该模块位于 PduR 与 CanIf 之间，没有专属的有效负载缓冲区。它通过上一层的复制服务按段复制数据 [SWS_CanTp_00298] [SWS_CanTp_00216]。

上下文图：CanTp 到 PduR、CanIf、模式管理、Scheduler 和 DET 的接口。来源：[SWS_CanTp_00216]，SWS CanTp 第17页

上电后，CanTp 处于 CANTP_OFF [SWS_CanTp_00168]。带有 CanTp_ConfigType [SWS_CanTp_00208] 的 CanTp_Init 将所有连接置于空闲状态 [SWS_CanTp_00030]；之后 CANTP_ON 生效 [SWS_CanTp_00170]。CanTp_Shutdown 关闭所有连接且不通知任何人 [SWS_CanTp_00202] [SWS_CanTp_00200]。连接通道彼此独立工作，并具有各自的定时器 [SWS_CanTp_00122]。若某个发送通道被占用，CanTp 会以 E_NOT_OK 拒绝新请求 [SWS_CanTp_00123]。

发送时，CanTp_Transmit 仅评估长度（以及可能的 MetaData）[SWS_CanTp_00225]。根据长度，接下来是 SF 或分段会话 [SWS_CanTp_00232]。对于每个分段，CanTp 使用 PduR_CanTpCopyTxData 获取数据 [SWS_CanTp_00086]，并在 FF 及每个块之后在 N_Bs 监控下等待 Flow Control [SWS_CanTp_00315]。解释：该调用仅通知已被接受；传输的结束则通过 PduR_CanTpTxConfirmation 异步到来 [SWS_CanTp_00176] [SWS_CanTp_00204]。

接收时，CanTp 首先通过 PduR_CanTpStartOfReception 请求一个缓冲区 [SWS_CanTp_00079]。随后它使用 PduR_CanTpCopyRxData 复制每个 CF [SWS_CanTp_00269]。若缓冲区紧张，CanTp 会在每次 MainFunction 运行中重新查询该缓冲区，并最多发送 WFTmax 个 FC(WAIT) [SWS_CanTp_00222] [SWS_CanTp_00223]。最后是 PduR_CanTpRxIndication [SWS_CanTp_00084]。周期性 CanTp_MainFunction 负责监控超时 [SWS_CanTp_00164]。

时序图：带有缓冲区协商和 Flow Control CTS/WAIT 的分段接收。来源：[SWS_CanTp_00269]，[SWS_CanTp_00222]，SWS CanTp 第38页

CanTp 以三种方式处理错误。它向 DET 报告开发错误并返回 E_NOT_OK [SWS_CanTp_00294]。超时等协议错误会中止会话，并通过 E_NOT_OK 传递给 PduR [SWS_CanTp_00205] [SWS_CanTp_00311]。这同样适用于通过 Cancel 服务根据请求进行的中止 [SWS_CanTp_00255] [SWS_CanTp_00263]。对于 Cancel 服务中的无效 ID，R20-11 要求使用 CANTP_E_PARAM_ID [SWS_CanTp_00254]，而较新的发布版本则指明其他代码。

在 CAN 栈中的角色：PduR 与 CanIf 之间的传输协议

CanTp 即 CAN Transport Layer。它将无法装入单个 CAN 帧的报文划分为段，控制数据流，并重组接收到的分段（SWS CanTp 第24页，SWS CanTp 第17页）。其基础是 ISO 15765-2：只要规范未明确排除，该标准的各项建议均适用 [SWS_CanTp_00033]。CanTp 仅在状态 CANTP_ON 下执行分段和重组 [SWS_CanTp_00238]。

向上，CanTp 为 PduR 提供以下服务：CanTp_Transmit [SWS_CanTp_00212]、CanTp_CancelTransmit [SWS_CanTp_00246] 和 CanTp_CancelReceive [SWS_CanTp_00257]。CanTp 自身向上调用 PduR_CanTpStartOfReception、PduR_CanTpCopyRxData、PduR_CanTpCopyTxData、PduR_CanTpRxIndication 和 PduR_CanTpTxConfirmation，向下调用 CanIf_Transmit [SWS_CanTp_00216]。下层通过 CanTp_RxIndication 报告接收到的帧 [SWS_CanTp_00078]，并通过 CanTp_TxConfirmation 报告发送确认 [SWS_CanTp_00076]。这两个函数必须能够在中断上下文中被调用 [SWS_CanTp_00235] [SWS_CanTp_00236]。较新的文档位置将调用方称为 L-SDU Router（LSduR）（SWS CanTp 第27页）。相比之下，R20-11 的 Requirements 则称其为 CAN Interface，例如 [SWS_CanTp_00031] 和 [SWS_CanTp_00335]。

CanTp 没有专属的有效负载缓冲区。它直接从上一层获取发送数据 [SWS_CanTp_00298]，并将接收到的数据直接复制到上一层的存储器中（SWS CanTp 第35页）。由此对上一层产生了锁定时间（SWS CanTp 第35页）：

  • 一旦 CanTp_Transmit 返回 E_OK，上一层就会锁定发送缓冲区，直到 PduR_CanTpTxConfirmation 到达。
  • 一旦上一层在 PduR_CanTpStartOfReception 上提供了 BUFREQ_OK，它就会锁定接收缓冲区，直到 PduR_CanTpRxIndication 到达。

上下文图：CanTp 位于 PduR 与 CanIf 之间。它由模式管理初始化，由 Scheduler 周期性触发，并向 DET 报告错误。来源：[SWS_CanTp_00216]，[SWS_CanTp_00217]，[SWS_CanTp_00164]，SWS CanTp 第17页，Mode Management Guide 第54页

生命周期：CANTP_OFF、CanTp_Init 和独立的连接通道

CanTp 具有状态 CANTP_OFF 和 CANTP_ON [SWS_CanTp_00027]。上电后，该模块处于 CANTP_OFF [SWS_CanTp_00168]；仅在该状态下才允许更新 Post-Build 配置 [SWS_CanTp_00169]。

CanTp_Init 接收指向 CanTp_ConfigType 的指针 [SWS_CanTp_00208] [SWS_CanTp_00340]。该函数初始化所有全局变量，并将每个连接置于空闲状态 CANTP_RX_WAIT 或 CANTP_TX_WAIT [SWS_CanTp_00030]；之后 CANTP_ON 生效 [SWS_CanTp_00170]。环境必须在任何进一步使用之前调用 CanTp_Init [SWS_CanTp_00199]。在模式管理指南中，这由 NvM_ReadAll 之后的一个 BswM 规则接管（Mode Management Guide 第54页）。在 CANTP_ON 中再次调用会丢弃所有正在运行的连接并返回空闲状态 [SWS_CanTp_00273] [SWS_CanTp_00111]。

CanTp_Shutdown 关闭所有打开的连接，释放资源并设置 CANTP_OFF [SWS_CanTp_00202]。在此过程中，CanTp 不会向任何人通知中止的传输 [SWS_CanTp_00200]（SWS CanTp 第58页）。

在 CANTP_ON 中同时运行多个连接 [SWS_CanTp_00096]：

  • 每个 N-SDU 静态分配给一个连接通道。每个通道具有独立的定时器、缓冲区和自身的状态机 [SWS_CanTp_00121] [SWS_CanTp_00122]。
  • 通道仅在内部可见 [SWS_CanTp_00285]。其数量由配置工具确定 [SWS_CanTp_00289]。
  • 若某个发送通道处于 CANTP_TX_PROCESSING，CanTp 会在 CanTp_Transmit 上以 E_NOT_OK 拒绝新请求 [SWS_CanTp_00123]。这同样适用于已处于正在运行会话中的 N-SDU [SWS_CanTp_00206]。
  • 若多个 N-SDU 共享一个通道且没有可用空闲通道，CanTp 会拒绝发送或中止接收 [SWS_CanTp_00288]（SWS CanTp 第42页）。

状态图：在 CanTp_Init 之后，接收通道和发送通道彼此独立地在 WAIT 和 PROCESSING 之间切换；CanTp_Shutdown 引导返回 CANTP_OFF。来源：[SWS_CanTp_00027]，[SWS_CanTp_00030]，[SWS_CanTp_00170]，[SWS_CanTp_00202]，SWS CanTp 第27页

发送：从 CanTp_Transmit 到确认

CanTp_Transmit 接收 TxPduId 和 PduInfoPtr [SWS_CanTp_00212]。若无 MetaData，CanTp 仅评估总长度 SduLength 且不访问数据缓冲区 [SWS_CanTp_00225] [SWS_CanTp_00299]。带有 MetaData 时，它还会为所有 SF、FF 和 CF 保存地址信息 [SWS_CanTp_00334]。若数据能装入一个 N-PDU，CanTp 会发送 SF，否则开启多帧会话 [SWS_CanTp_00232]（SWS CanTp 第60页）。最大发送长度（TX_DL）由 EcuC 中的 PduLength 决定 [SWS_CanTp_00354]。解释：该调用仅同步通知请求是否被接受；实际的传输以异步方式进行 [SWS_CanTp_00176]。接受之后，CanTp 无论如何都会通过 PduR_CanTpTxConfirmation 报告结束 [SWS_CanTp_00177] [SWS_CanTp_00204]。

对于每个分段（SF、FF、CF），CanTp 均调用 PduR_CanTpCopyTxData [SWS_CanTp_00086]；在首次调用之前，定时器 N_Cs 处于运行状态 [SWS_CanTp_00167]。若上一层返回 BUFREQ_E_BUSY，CanTp 稍后重试 [SWS_CanTp_00184]。CanTp 始终将 Retry 参数设为 NULL，因为 ISO 15765-2 不支持重传 [SWS_CanTp_00272]。

在 FF 以及每个块的最后一个 CF 之后，CanTp 在 N_Bs 监控下等待 Flow Control 帧 [SWS_CanTp_00315]。接收端借助它放行更多 CF 或对其进行延迟 [SWS_CanTp_00282]。若会话成功结束，接下来是带有 E_OK 的 PduR_CanTpTxConfirmation [SWS_CanTp_00090]。50 字节示例（SWS CanTp 第37页）以及从 DCM 到 CanTp 的路径（SWS PduR 第104页）展示了相同的拉取过程。

时序图：CanTp 向 PduR 按段请求数据，在 FF 和每个块之后等待 Flow Control，最后以 E_OK 确认。来源：[SWS_CanTp_00212]，[SWS_CanTp_00086]，[SWS_CanTp_00315]，[SWS_CanTp_00090]，SWS CanTp 第73页

接收：缓冲区协商、Flow Control 与重组

在每个传入的 SF 或 FF 处，CanTp 均通过 PduR_CanTpStartOfReception 报告接收开始 [SWS_CanTp_00079]。可用缓冲区大小通过输出参数返回，且允许小于 N-SDU [SWS_CanTp_00080]。在出现 FF 时，CanTp 会预先启动定时器 N_Br [SWS_CanTp_00166]。只有当结果得出后，它才会发送 Flow Control；其内容取决于该结果 [SWS_CanTp_00064] [SWS_CanTp_00277]。接收会话的所有 FC 均携带相同的 BS 和 STmin 值 [SWS_CanTp_00067]。每个 FC 分别在 BS 个 Consecutive Frame 之后发送 [SWS_CanTp_00278]。

在每个 CF 之后，CanTp 使用 PduR_CanTpCopyRxData 交付有效负载，并在此过程中得知剩余缓冲区 [SWS_CanTp_00269]。在 CAN 2.0 中，每个 CF 为六或七个字节。若块中最后一个 CF 之后的剩余缓冲区不足以容纳下一个块，CanTp 会启动定时器 N_Br [SWS_CanTp_00325] [SWS_CanTp_00082]。只要该定时器处于运行状态：

  • CanTp 就在 MainFunction 的每次运行中查询缓冲区，即以长度 0 和 NULL_PTR 进行查询 [SWS_CanTp_00222]；
  • CanTp 最多发送 WFTmax 个连续的 FC(WAIT) [SWS_CanTp_00223]（SWS CanTp 第38页）。

会话结束时，无论成功与否，CanTp 都会调用 PduR_CanTpRxIndication [SWS_CanTp_00084]。在有无 Padding 的情况下，CanTp 仅将实际使用的数据字节向上传递 [SWS_CanTp_00116]。

时序图：带有缓冲区协商、逐块 Flow Control 以及缓冲区紧张时等待阶段的分段接收。来源：[SWS_CanTp_00079]，[SWS_CanTp_00269]，[SWS_CanTp_00222]，[SWS_CanTp_00084]，SWS CanTp 第76页

活动图：CanTp 在传入 SF 或 FF 时如何根据通道状态和 PduR_CanTpStartOfReception 的结果作出决策。来源：[SWS_CanTp_00124]，[SWS_CanTp_00337]，[SWS_CanTp_00081]，[SWS_CanTp_00318]，[SWS_CanTp_00353]，SWS CanTp 第67页

寻址、MetaData 与 Padding

功能寻址（1:n）仅允许用于 SF [SWS_CanTp_00092]。通过功能句柄进行的分段会话会被 CanTp 拒绝并报告 CANTP_E_INVALID_TATYPE [SWS_CanTp_00093]（SWS CanTp 第39页）。在 Extended 或 Mixed Addressing 下，CanTp 根据首个数据字节中的 N_TA 或 N_AE 确定 N-SDU [SWS_CanTp_00095] [SWS_CanTp_00284] [SWS_CanTp_00283]。对于标识符的分配规则如下（SWS CanTp 第44页）：

  • 每个 NSduId 恰好分配给一个 LSduId [SWS_CanTp_00035]。
  • FC 的 LSduId 与 N_TA 或 N_AE 一起恰好标识一个 NSduId [SWS_CanTp_00094]。
  • 仅在 Extended/Mixed Addressing 或存在 MetaData 的情况下，多个 N-SDU 才允许引用同一个 N-PDU [SWS_CanTp_00328]。

泛型连接使用 MetaData 工作。CanTp 保存来自 SF 或 FF 的地址信息 [SWS_CanTp_00330]，将其转发给 PduR_CanTpStartOfReception [SWS_CanTp_00331]，并以此检查随后的 CF [SWS_CanTp_00333]。若通道已在接收中，CanTp 将忽略带有 MetaData 的另一个 SF 或 FF [SWS_CanTp_00337]。

Padding 是按 N-SDU 激活的（SWS CanTp 第43页）。填充值为 CANTP_PADDING_BYTE [SWS_CanTp_00059]。对于有效负载最多为 8 字节的帧，规则如下：

  • 采用 Rx-Padding 时，CanTp 仅接受 8 字节的 SF 和最后一个 CF [SWS_CanTp_00344]，并以 8 字节发送 FC [SWS_CanTp_00347]。
  • 采用 Tx-Padding 时，CanTp 将 SF 和最后一个 CF 填充至 8 字节 [SWS_CanTp_00348]。

若发送长度与任何有效的 DLC 均不匹配，CanTp 将填充至下一个更高的有效值 [SWS_CanTp_00351]。接收长度 RX_DL 由 CanTp 根据首次接收到的 CAN_DL 推导得出 [SWS_CanTp_00350]。

时间监控、运行时参数以及按请求中止

CanTp_MainFunction [SWS_CanTp_00213] 被周期性调用。它监控 N_As、N_Bs、N_Cs、N_Ar、N_Br、N_Cr 以及 STmin [SWS_CanTp_00164]（SWS CanTp 第63页）。其节拍取决于 CanTpMainFunctionPeriod [SWS_CanTp_00300]。该值应与调用任务的周期时间相对应（SWS CanTp 第77页）。作为示例，时序分析提到了一个 5 ms 任务（TR Timing Analysis 第117页）。

两个服务在运行时访问某个 N-SDU 的接收参数 BS 和 STmin：CanTp_ChangeParameter 对其进行修改 [SWS_CanTp_00302]，CanTp_ReadParameter 对其进行读取 [SWS_CanTp_00323]。仅当 CanTpChangeParameterApi = TRUE 时，才存在这两个服务（SWS CanTp 第61页）。BS 仅为一个最大值，CanTp 出于缓冲区原因可以低于该值 [SWS_CanTp_00091]。在正在运行的接收会话的 FF 与最后一个 CF 之间，CanTp 会以 E_NOT_OK 拒绝任何修改 [SWS_CanTp_00303] [SWS_CanTp_00304]。对于泛型连接，一项修改适用于所有连接 [SWS_CanTp_00338]。

正在运行的传输可以根据请求予以中止：

  • 发送：该功能通过 CanTpTc 静态激活 [SWS_CanTp_00242]，并通过 CanTp_CancelTransmit 触发 [SWS_CanTp_00274]。在 E_OK 时，CanTp 中止传输 [SWS_CanTp_00243] [SWS_CanTp_00256]，并以 E_NOT_OK 报告 PduR_CanTpTxConfirmation [SWS_CanTp_00255]。在对端，这会导致超时（SWS CanTp 第26页）。
  • 接收：CanTp_CancelReceive 终止以 FF 开始的接收 [SWS_CanTp_00261]，并以 E_NOT_OK 报告 PduR_CanTpRxIndication [SWS_CanTp_00263]。对于 SF 或仅剩最后一个 CF 待接收的情况，CanTp 会拒绝中止 [SWS_CanTp_00262]（SWS CanTp 第60页）。

发生错误时的行为

开发错误。若检测功能处于激活状态，CanTp 会向 DET 报告错误并返回 E_NOT_OK [SWS_CanTp_00294] [SWS_CanTp_00217]（SWS CanTp 第49页）。代码由 [SWS_CanTp_00293] 定义。典型情况：

  • CANTP_E_UNINIT：在 CanTp_Init 之前使用了除 CanTp_GetVersionInfo 以外的函数 [SWS_CanTp_00031]。
  • CANTP_E_PARAM_POINTER：某个指针为 NULL [SWS_CanTp_00319] [SWS_CanTp_00321] [SWS_CanTp_00322]。
  • CANTP_E_PARAM_ID：CanTp_ReadParameter 接收到无效参数 [SWS_CanTp_00324]。

发布版本之间的差异：对于 Cancel 服务中的无效 PduId，R20-11 要求使用 CANTP_E_PARAM_ID [SWS_CanTp_00254] [SWS_CanTp_00260]。较新的文档位置则指出应使用 CANTP_E_INVALID_TX_ID 或 CANTP_E_INVALID_RX_ID（SWS CanTp 第59页）。对于 R20-11，以 Requirement 为准。

运行时错误。它们被发送至 Default Error Tracer [SWS_CanTp_00352]：

  • CANTP_E_PADDING：尽管存在 Padding，帧依然过短 [SWS_CanTp_00345] [SWS_CanTp_00346] [SWS_CanTp_00349]。
  • CANTP_E_OPER_NOT_SUPPORTED：Cancel 涉及未处于运行中传输的 N-SDU [SWS_CanTp_00254]。
  • 对于协议错误，文档位置还列出了 CANTP_E_COM、CANTP_E_RX_COM 和 CANTP_E_TX_COM（SWS CanTp 第52页）。

协议错误。它们以向上一层发送 E_NOT_OK 的方式终止会话 [SWS_CanTp_00205]：

  • 发送端（通过 PduR_CanTpTxConfirmation 报告）：复制时缺少数据 [SWS_CanTp_00087]、N_Cs [SWS_CanTp_00280]、N_As [SWS_CanTp_00310] 或 N_Bs [SWS_CanTp_00316] 到期、带有 OVFLW 或无效 FS 的 FC [SWS_CanTp_00309] [SWS_CanTp_00317]。在 N_As 之后，N-PDU 保持锁定，直至 TxConfirmation 到达 [SWS_CanTp_00075]。
  • 接收端（通过 PduR_CanTpRxIndication 报告）：N_Ar [SWS_CanTp_00311] 或 N_Cr [SWS_CanTp_00313] 到期、复制被拒绝 [SWS_CanTp_00271]。
  • 无通知中止：若 PduR_CanTpStartOfReception 返回 BUFREQ_E_NOT_OK，CanTp 会发生中止；既不发送 FC 也不发送指示 [SWS_CanTp_00081]。
  • 非预期 N-PDU：CanTp 根据表格进行处理 [SWS_CanTp_00057]（SWS CanTp 第45页）。

PduR 将否定确认转发给用户，例如转发给负责恢复的 DCM（Error Description 第29页，Error Description 第28页）。生产错误由 DEM 通过 FiM 处理 [SWS_CanTp_00291]。
