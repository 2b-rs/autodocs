DCM 在测试仪、基础软件与应用程序之间的角色

DCM 接收来自外部测试仪的诊断请求并对其进行响应。它根据表 7.5 实现了 UDS 服务 [SWS_Dcm_00442] 以及诸如 $01 [SWS_Dcm_00243] 和 $09 [SWS_Dcm_00421] 的 OBD 服务。内部有三个子模块协同工作：

  • DSL 子模块维护活动会话 [SWS_Dcm_00022] 和活动安全等级 [SWS_Dcm_00020]。
  • DSD 子模块分析服务标识符 [SWS_Dcm_00192] 并查找执行该服务的 DSP 函数 [SWS_Dcm_00221]。
  • DSP 子模块执行该服务并向 DSD 报告结束 [SWS_Dcm_00222]。

系统边界包括多个相邻模块和接口：

  • 模式管理器：DCM 管理诊断模式 [SWS_Dcm_00775]。为此它提供 ModeDeclarationGroup，例如 DcmDiagnosticSessionControl [SWS_Dcm_91019]、DcmEcuReset [SWS_Dcm_00777]、DcmControlDTCSetting [SWS_Dcm_00781] 以及 DcmSecurityAccess [SWS_Dcm_01327]。针对 CommunicationControl，每个网络都有一个独立的组 [SWS_Dcm_00780]。
  • DEM：故障内存访问通过 DEM 进行，例如先 Dem_SetDTCFilter，然后 Dem_GetNextFilteredDTC [SWS_Dcm_00835]。
  • NvM：此处存放 DDDID 定义等持久性数据 [SWS_Dcm_00867]。
  • ComM：它通过回调报告通信模式 [SWS_Dcm_00356]。
  • CSM/KeyM：它们异步响应加密和证书作业 [SWS_Dcm_91076] [SWS_Dcm_91077]。

初始化、主函数与 Bootloader 转换

Dcm_Init [SWS_Dcm_00037] 接收指向带有 Post-Build 参数的 Dcm_ConfigType 的指针（SWS DCM 第275页）。该函数使用配置值对所有全局变量进行赋值 [SWS_Dcm_00334]。此后以下初始状态生效：

  • 安全等级为 DCM_SEC_LEV_LOCKED [SWS_Dcm_00033]。
  • 默认会话 0x01 处于激活状态 [SWS_Dcm_00034]。
  • 所有 ROE 事件均处于“ROE cleared”状态 [SWS_Dcm_00872]。
  • ActiveDiagnostic 处于 DCM_COMM_ACTIVE [SWS_Dcm_01069]。
  • 尝试计数器通过 Xxx_GetSecurityAttemptCounter 读取 [SWS_Dcm_01154]。

启动时，DCM 还会查询 Dcm_GetProgConditions [SWS_Dcm_00536]。返回值 DCM_WARM_START [SWS_Dcm_00987] 表示从 Bootloader 返回。在这种情况下，可能还需要发出响应（$50/$51）[SWS_Dcm_00537]（SWS DCM 第299页）。

Dcm_MainFunction [SWS_Dcm_00053] 处理正在进行的任务。如果某个操作返回 DCM_E_PENDING，DCM 会再次调用它，例如在下一个周期 [SWS_Dcm_00760]。

进入 Bootloader 的流程如下：

  1. 测试仪通过 0x10 请求会话，从而触发 Bootloader 跳转 [SWS_Dcm_00532] [SWS_Dcm_00592]。
  2. 根据配置，DCM 首先发送 NRC 0x78 [SWS_Dcm_00535]。
  3. 解读：随后 DcmEcuReset 预计将切换为 JUMPTOBOOTLOADER。紧接着 DCM 调用 Dcm_SetProgConditions [SWS_Dcm_00720] [SWS_Dcm_00543]。
  4. 在 E_OK 处将进行进一步的模式切换 [SWS_Dcm_00719]。

Dcm_ProgConditionsType 在此期间传输 ConnectionId、TesterAddress、Sid 和 ResponseRequired 等 [SWS_Dcm_00988]。

请求经过 DSL、DSD 和 DSP 的路径

接收。PduR 通过 Dcm_StartOfReception [SWS_Dcm_00094] 开始接收。它通过 Dcm_CopyRxData 将数据复制到 DCM 缓冲区 [SWS_Dcm_00443]。它通过 Dcm_TpRxIndication [SWS_Dcm_00093] 报告完成。仅当 E_OK 时，DSL 才会将请求转发给 DSD [SWS_Dcm_00111]。对于通用连接，DCM 会保存来自 MetaData 的源地址 [SWS_Dcm_00848]。

DSD 中的检查。检查顺序遵循 ISO 14229-1 [SWS_Dcm_00827]：

  • 未知的服务标识符将导致 NRC 0x11 [SWS_Dcm_00197]。
  • 不支持的子功能将导致 NRC 0x12 [SWS_Dcm_00273]。
  • 此外还会检查会话 [SWS_Dcm_00211]、安全等级 [SWS_Dcm_00217] 以及模式规则 [SWS_Dcm_00773]。
  • 应用程序可通过 Xxx_Indication 进行干预 [SWS_Dcm_00218] [SWS_Dcm_01341]。
  • 如果设置了 suppressPosRspMsgIndicationBit，则不会发送肯定响应 [SWS_Dcm_00200]。

活动图：DSD 中的接收检查直到移交给 DSP（解读：简化顺序）。来源：[SWS_Dcm_00196]、[SWS_Dcm_00677]、[SWS_Dcm_00678]、[SWS_Dcm_00815]、[SWS_Dcm_00827]

响应与确认。

  1. DSD 补全响应 SID [SWS_Dcm_00223] 并将响应移交给 DSL [SWS_Dcm_00232]。DSL 将其转发给 PduR [SWS_Dcm_00237]。
  2. PduR 通过 Dcm_CopyTxData 获取数据 [SWS_Dcm_00092]。
  3. 在 Dcm_TpTxConfirmation [SWS_Dcm_00351] 之后，确认通过 DspInternal_DcmConfirmation [SWS_Dcm_00236] 到达 DSP。应用程序通过 Xxx_Confirmation [SWS_Dcm_00741] 接收它。

DCM 可以通过分页缓冲区（Paged Buffer）按页发送大响应 [SWS_Dcm_00028]。如果下一页尚未准备就绪，Dcm_CopyTxData 将返回值 BUFREQ_E_BUSY [SWS_Dcm_01186]（SWS DCM 第481页）。

时序图：接收、检查、执行以及已确认的肯定响应。来源：[SWS_Dcm_00111]、[SWS_Dcm_00235]、[SWS_Dcm_00236]、SWS DCM 第479页

异步 Callout、OpStatus 和 Response Pending

异步应用程序接口接收一个 Dcm_OpStatusType [SWS_Dcm_00984]：

  • 首次调用时，值为 DCM_INITIAL [SWS_Dcm_00527]。
  • 在 DCM_E_PENDING 之后跟随 DCM_PENDING [SWS_Dcm_00530]。
  • 中止通过 DCM_CANCEL [SWS_Dcm_00735] 进行。DCM 会忽略此调用的返回值 [SWS_Dcm_01413]。

接口是同步工作还是异步工作由配置决定。一个例子是 Xxx_ReadData：存在同步变体 [SWS_Dcm_00793] 和异步变体 [SWS_Dcm_91006]。内存访问使用专用的返回类型，如 Dcm_ReturnReadMemoryType [SWS_Dcm_00985]（SWS DCM 第281页）。

Response Pending。DSL 监视时间限制 P2ServerMax 和 P2*ServerMax [SWS_Dcm_00027]。如果处理需要更长时间，它将发送 NRC 0x78 [SWS_Dcm_00024]（SWS DCM 第433页）。应用程序也可以通过返回 DCM_E_FORCE_RCRRP 立即强制发送 NRC 0x78 [SWS_Dcm_00528]。在发送确认之后，DCM 随后使用 DCM_FORCE_RCRRP_OK 调用该操作 [SWS_Dcm_00529]。连续允许多少个 NRC 0x78 是受限的 [SWS_Dcm_00120] [SWS_Dcm_01567]。

会话、安全等级和身份验证作为访问控制

会话。DCM 实现了 UDS 0x10 [SWS_Dcm_00250]。未配置的会话类型将导致 NRC 0x12 [SWS_Dcm_00307]。新会话仅在发送确认时生效。与此同时，DCM 设置新的 P2 值并执行模式切换 [SWS_Dcm_00311]（SWS DCM 第107页）。DCM 通过两种途径返回默认会话：

  • 在发生 S3Server 超时时 [SWS_Dcm_00140]（SWS DCM 第492页），
  • 当应用程序调用 Dcm_ResetToDefaultSession 时 [SWS_Dcm_01062]。

会话切换具有副作用：

  • 活动的 IO 控制将被终止 [SWS_Dcm_00858]。
  • 在默认会话中，周期性 DID 将停止 [SWS_Dcm_01107]。
  • 已启动的 ROE 事件切换至“ROE stopped” [SWS_Dcm_00879]。

状态图：诊断会话从启动到返回默认会话的生命周期。来源：[SWS_Dcm_00034]、[SWS_Dcm_00311]、[SWS_Dcm_00140]、[SWS_Dcm_00520]、[SWS_Dcm_00532]、[SWS_Dcm_00978]

SecurityAccess (0x27) [SWS_Dcm_00252]：

  • 对于 requestSeed，DCM 调用 Xxx_GetSeed [SWS_Dcm_00323]。
  • 对于 sendKey，它调用 Xxx_CompareKey [SWS_Dcm_00324]。在 E_OK 时，它设置新等级 [SWS_Dcm_00325] 并通过 DcmSecurityAccess [SWS_Dcm_01329] 进行报告。
  • 失败尝试次数达到限制后将导致锁定时长 [SWS_Dcm_00660] [SWS_Dcm_01350]。成功的 sendKey 或超时的延时定时器会重置该计数器 [SWS_Dcm_01357]。
  • 每次等级切换都会终止活动的 IO 控制 [SWS_Dcm_00859]。

身份验证 (0x29)。DCM 实现了 Authentication 服务 [SWS_Dcm_01559]。它为每个连接维护一个单独的身份验证状态 [SWS_Dcm_01477]。在证书验证 [SWS_Dcm_01468] 和所有权证明（Proof of Ownership）[SWS_Dcm_01511] 成功之后，连接切换至“authenticated”状态 [SWS_Dcm_01528]。在空闲或 S3Server 超时时，它会回退到“deauthenticated”状态 [SWS_Dcm_01482] [SWS_Dcm_01483]。此时配置的去身份验证角色生效 [SWS_Dcm_01485]（SWS DCM 第69页）。

通信模式、协议与事件驱动的响应

通信模式。ComM 通过回调控制 DCM 允许发送的内容：

  • Dcm_ComM_NoComModeEntered 禁止接收和发送 [SWS_Dcm_00148]。
  • Dcm_ComM_SilentComModeEntered 禁止发送 [SWS_Dcm_00153]。
  • Dcm_ComM_FullComModeEntered 允许全部 [SWS_Dcm_00157]。

周期性传输和 ROE 仅在 Full Communication 下允许 [SWS_Dcm_00123] [SWS_Dcm_00133]。DCM 会丢弃该模式之外的事件 [SWS_Dcm_00125] [SWS_Dcm_00135]。反之，DCM 向 ComM 报告处于激活状态的诊断 [SWS_Dcm_01373]。应用程序可通过 Dcm_SetActiveDiagnostic 关闭此报告 [SWS_Dcm_01068]。

状态图：每个 ComM 通信模式下的 DCM 许可状态。来源：[SWS_Dcm_00148]、[SWS_Dcm_00149]、[SWS_Dcm_00154]、[SWS_Dcm_00159]、SWS DCM 第499页

协议。在某个协议的第一条请求到来时，DCM 调用 Xxx_StartProtocol [SWS_Dcm_00036]。如果该调用未返回 E_OK，DCM 将回复 NRC 0x22 [SWS_Dcm_00674]。较高优先级的协议可以抢占正在运行的协议 [SWS_Dcm_00015] [SWS_Dcm_00459]。应用程序通过 Xxx_StopProtocol（SWS DCM 第495页）获知此事。DCM 会与正在运行的 UDS 请求并行处理 OBD 请求 [SWS_Dcm_01367]。

ResponseOnEvent。每个 RoeEvent 具有“cleared”、“stopped”和“started”状态 [SWS_Dcm_00871]。事件通过 Dcm_TriggerOnEvent [SWS_Dcm_00920] 或通过 DTC 的状态切换触发 [SWS_Dcm_00914]。届时应执行的 ServiceToRespondTo 像普通请求一样运行 [SWS_Dcm_00922]。

发生错误时的行为

接收时。

  • 如果请求超出缓冲区，Dcm_StartOfReception 将返回值 BUFREQ_E_OVFL [SWS_Dcm_00444]。
  • 当 TpSduLength 为 0 时，该函数返回 BUFREQ_E_NOT_OK [SWS_Dcm_00642]（SWS DCM 第57页）。
  • 如果 Dcm_TpRxIndication 报告错误，DCM 不会对数据进行求值 [SWS_Dcm_00344]。
  • 在当前处理期间到来的其他请求，它可以予以拒绝 [SWS_Dcm_00557]。根据配置，它对此回复 NRC 0x21 [SWS_Dcm_00789]。

发送时。Dcm_TpTxConfirmation 释放发送缓冲区 [SWS_Dcm_00352] 并结束正在进行的错误处理 [SWS_Dcm_00353]（ErrorDescription 第26页）。对于失败的传输，[SWS_Dcm_00118] 适用。如果请求被抢占，DCM 将中止在 PduR 处的传输 [SWS_Dcm_00079] [SWS_Dcm_00575]。它通过 NvM_CancelJobs [SWS_Dcm_01048] 终止正在运行的 NvM 作业。

来自应用程序和相邻模块的错误。

  • 如果 Callout 返回 E_NOT_OK 或 DCM_READ_FAILED，DCM 会将 ErrorCode 作为 NRC 发送，例如 [SWS_Dcm_00668] [SWS_Dcm_00644]。
  • 值范围和非预期返回值由 [SWS_Dcm_01414] 和 [SWS_Dcm_01415] 规定（SWS DCM 第346页）。
  • 如果 Dem_ClearDTC 报告 DEM_CLEAR_FAILED，则随之产生 NRC 0x22 [SWS_Dcm_00704]。对于 DEM_WRONG_DTC，则随之产生 NRC 0x31 [SWS_Dcm_00708]。
  • 如果 Dcm_SetProgConditions 返回值 E_NOT_OK，DCM 将不请求复位 [SWS_Dcm_01181]。在 Bootloader 跳转时，它还会额外报告一个 DET 错误 [SWS_Dcm_01185]。
  • 错误类型在 [SWS_Dcm_00044] 和 [SWS_Dcm_01416] 中定义。
