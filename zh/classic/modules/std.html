为所有 Classic 模块提供统一的返回值、版本、转换器及常量类型。

模块 std 通过 Std_Types.h 提供平台范围内统一的类型和常量，但既不包含代码也不包含配置。其核心是具有 E_OK 和 E_NOT_OK 的 Std_ReturnType（uint8）。模块仅允许在 0x02–0x3F 范围内定义带有模块前缀的私有值，因为 Bit 7 和 Bit 8 保留给 RTE [SWS_Std_00011]。此外，该模块还提供常量 STD_HIGH/STD_LOW、STD_ON/STD_OFF 和 STD_ACTIVE/STD_IDLE，用于版本查询的类型 Std_VersionInfoType，以及用于客户端-服务器通信的转换器和消息类型。在 R20-11 中，该头文件还包含了 Compiler.h SRS BSWGeneral 第62页。

模块 std 是一个纯类型头文件。它通过 Std_Types.h 提供类型和符号，但不提供函数 [SWS_Std_00005]。在 R20-11 中，该头文件包含 Platform_Types.h 和 Compiler.h，并定义了 Std_ReturnType 以及值 E_OK/E_NOT_OK 和 STD_* 常量。使用这些类型的每个模块都会包含它 SRS BSWGeneral 第62页。根据规范的后续版本，不存在配置和私有错误处理；推测这同样适用于 R20-11（解释）SWS StandardTypes 第27页。

该模块的核心是带有值 E_OK（0）和 E_NOT_OK（1）的 Std_ReturnType（uint8）。0x02–0x3F 范围保留给带有模块前缀的模块特定错误；Bit 7 和 Bit 8 由 RTE 规范定义 [SWS_Std_00011]。此类扩展的示例包括 CAN_BUSY 和 Csm_ReturnType BSWUML Guide 第29页。由于 OSEK 的原因，E_OK 通过 STATUSTYPEDEFINED 得到防护 [SWS_Std_00006]。

此外还有三对分别取值 0x01u/0x00u 的常量：用于物理电平的 STD_HIGH/STD_LOW，作为开关的 STD_ON/STD_OFF，以及用于逻辑状态的 STD_ACTIVE/STD_IDLE（[SWS_Std_00007]、[SWS_Std_00010]、[SWS_Std_00013]）。Std_VersionInfoType 为同步、可重入函数 <Ma>_GetVersionInfo 传递厂商 ID、模块 ID 和软件版本 [SWS_Std_00015]。

对于数据转换，std 定义了两种用于转换器错误的类型：由错误代码和转换器类别构成的结构体 Std_TransformerError，以及 Std_TransformerClass [SWS_Std_00021]。RTE 通过可选参数 transformerError 传递该错误 SWS RTE 第731页。对于客户端-服务器通信，Std_MessageTypeType 和 Std_MessageResultType 对请求/响应以及 OK/ERROR 进行编码。类型为 Std_ExtractProtocolHeaderFieldsType 的函数指针从转换器头中读取这两个值 [SWS_Std_91003]。前向类型在 R20-11 中仍处于草案阶段 [SWS_Std_00029]。

角色与系统边界：无运行时行为的纯类型头文件

模块 std（Standard Types）不包含任何函数。它仅提供通过 Std_Types.h 可用的类型和符号。该模块的每个需求都将此头文件列为引用源，例如 [SWS_Std_00005] 和 [SWS_Std_00015]。该规范明确指出：该头文件既不提供代码也不需要其他 BSW 模块，它没有配置，也没有私有错误处理 SWS StandardTypes 第27页。这些表述出自 R23-11 起的版本。由于 R20-11 需求仅包含类型和符号定义，因此推测同样适用于 R20-11（解释）。

其目的是以统一且跨平台的方式访问标准类型。因此，针对标准类型头文件的 BSW 需求要求：使用 AUTOSAR 整数类型或标准返回类型的每个模块都必须包含 Std_Types.h SRS BSWGeneral 第62页。返回类型 Std_ReturnType 明确由 RTE 和 BSW 模块共享 [SWS_Std_00005]。在方法论中，标准类型还被描述为 ARXML 工件“AUTOSAR Standard Types”Methodology 第400页。

Std_Types.h 的结构及其在头文件树中的引入

对于 R20-11，BSW 需求规定了 Std_Types.h 必须实现的内容 SRS BSWGeneral 第62页：

  • 包含平台特有类型头文件 Platform_Types.h，
  • 包含编译器特有头文件 Compiler.h，

Std_ReturnType：取值范围、位布局与模块特定扩展

Std_ReturnType 派生自 uint8。标准值为 E_OK（0）和 E_NOT_OK（1）；0x02–0x3F 范围可供用户特有错误使用 [SWS_Std_00005]。[SWS_Std_00011] 对该规则进行了细化：

  • 通常，该类型与 E_OK 或 E_NOT_OK 一起使用。
  • 若这些值不够用，可在低 6 位中定义私有值，并使用模块前缀进行命名。
  • Bit 7 和 Bit 8 为保留位。如同整体布局一样，它们由 RTE 规范确定。

RTE 规范将 Std_ReturnType 描述为用于 API 函数的状态和错误值的类型；值 0 保留用于“未发生错误”SWS RTE 第675页。根据 BSW 建模指南，它是服务接口的客户端-服务器操作中唯一允许的返回类型 BSWUML Guide 第28页。模块特定扩展的一个示例是 CAN 驱动程序的 CAN_BUSY（0x02）。当没有发送对象空闲时，Can_Write() 返回该值 SWS CANDriver 第54页。

std 为 Transformer 链提供了多种类型。在 R20-11 中，Std_TransformerError 是由 errorCode（uint8）和类型为 Std_TransformerClass 的 transformerClass 组成的结构体 [SWS_Std_00021]。Std_TransformerClass 派生自 uint8 并包含五个值 [SWS_Std_00024]：STD_TRANSFORMER_UNSPECIFIED (0x00)、STD_TRANSFORMER_SERIALIZER (0x01)、STD_TRANSFORMER_SAFETY (0x02)、STD_TRANSFORMER_SECURITY (0x03) 和 STD_TRANSFORMER_CUSTOM (0xFF)。

发生错误时的行为

该模块本身不检测也不报告错误。R23-11 及更高版本指出，标准类型未提供错误处理，也不支持安全事件 SWS StandardTypes 第27页；对于 R20-11 应该同样适用（推断）。因此错误行为仅在使用这些类型的模块中产生。基本信号是 E_NOT_OK [SWS_Std_00006]；其具体含义由各 API 规定。在 Adc_ReadGroup 中表示“无可用结果或存在开发错误” SWS ADCDriver 第61页，在 CanIf_Transmit 中表示“发送请求未接受” SWS CANInterface 第87页。

更精细的错误特征通过 0x02–0x3F 范围内的模块特定值进行报告 [SWS_Std_00011]，例如 CAN_BUSY SWS CANDriver 第54页。因此调用者必须考虑到 Std_ReturnType 会取两个以上的值。一种特殊情况是通过 RTE 路由为 AUTOSAR 服务的回调：调用者虽然可以假定 E_OK，但在分区系统等环境中此类回调可能会失败 SWS BSWGeneral 第69页。

在 Transformer 链中，除返回值外，还会通过带有错误代码和 Transformer 类别的 Std_TransformerError 报告错误 [SWS_Std_00021]。仅当为端口配置了错误处理 transformerErrorHandling 时，RTE 才会生成可选参数 transformerError SWS RTE 第774页。如果提取头字段失败，SomeIpXf_ExtractProtocolHeaderFields 将返回 E_NOT_OK，例如在协议版本错误或缓冲区过短的情况下 SWS SOMEIPTransformer 第61页。E2E Transformer 逻辑仅在 E_OK 时继续检查 SWS E2ETransformer 第45页。
