RTE 在软件组件与基础软件之间的角色

RTE 是一个针对每个 ECU 实例单独配置和生成的运行时层 [SWS_Rte_05000] [SWS_Rte_01316]。它实现 ECU 配置中描述的通信路径，并实现软件组件通信属性的语义 [SWS_Rte_02200] [SWS_Rte_02201]。架构示意图展示了其在应用软件与基础软件之间的位置 (SWS_RTE 第113页)。在实现中，RTE 仅使用指定的基础服务，其中包括 AUTOSAR OS、COM 和 Efficient COM for Large Data [SWS_Rte_02250]。该模块还包括调度 BSW 模块执行的 Basic Software Scheduler (SchM) (SWS_RTE 第459页)。

上下文图：RTE 在 SW-C、BSW 模块、OS、COM/LdCom 与 NvM 之间进行协调。EcuM 控制其生命周期。来源：[SWS_Rte_02250] [SWS_Rte_03530] [SWS_Rte_89015] SWS_RTE 第259页 SWS_RTE 第928页

RTE 以 C 语言生成。其代码必须符合 MISRA-C 标准，且所有外部可见符号均带有前缀 Rte_ [SWS_Rte_01167] [SWS_Rte_01168] [SWS_Rte_01171]。对于每个组件类型，都会生成一个仅包含与该组件相关信息的 Application Header File Rte_[Byps_]<name>.h。生命周期 API 在 Rte_Main.h 中声明，类型在 Rte_Type.h [SWS_Rte_01000] [SWS_Rte_01003] [SWS_Rte_01004] [SWS_Rte_01158] [SWS_Rte_01161] 中声明。

生命周期：RTE 和 BSW-Scheduler 的启动与关闭

只要 BSW-Scheduler 尚未初始化，就只有 SchM_Enter 和 SchM_Exit 可用。在必须调度第一个 BSW 模块之前，EcuM 调用 SchM_Init。SchM_Init 接收配置指针 [SWS_Rte_08060]，在有限时间内返回 [SWS_Rte_07273]，并初始化关联的 mode machine instances，包括初始模式的 on-entry-ExecutableEntity [SWS_Rte_02544]。通过 SchM_Init 开始通过 BswBackgroundEvent 进行激活，通过 SchM_StartTiming 开始通过 BswTimingEvent 进行激活 (SWS_RTE 第459页)。

对于 SchM_Start 和 SchM_StartTiming 同样适用：两个 API 始终都会生成，并且必须在有限时间内返回 [SWS_Rte_04546] [SWS_Rte_04547] [SWS_Rte_04548] [SWS_Rte_04549] [SWS_Rte_04550] [SWS_Rte_04551]。后续版本的文档位置补充了三条规则 (SWS_RTE 第927页、SWS_RTE 第928页)：

  • SchM_Start 在 BswM_Init 之前被调用。
  • SchM_Init 在 SchM_StartTiming 之前被调用。
  • EcuM 在每个核上对所有三个函数均恰好调用一次，并且仅在所需模块（如 OS）初始化之后调用。

Rte_Start 在 Startup-Phase II 结束时执行。此时 OS 和所有 BSW 模块均已就绪 (SWS_RTE 第460页)。该 API 始终会生成，并且必须在有限时间内返回 [SWS_Rte_01309] [SWS_Rte_02569] [SWS_Rte_02585]。Rte_Start 初始化 RTE 的模式机，并将 ECU 间 Client-Server 连接的序列计数器清零 [SWS_Rte_02544] [SWS_Rte_02655]。对于通过 TimingEvent 或 BackgroundEvent 触发的 Runnable，仅在不存在 Rte_StartTiming 时，Rte_Start 才会启动它们 (SWS_RTE 第460页)。解读：如果存在 Rte_StartTiming，则推测该激活可能仅在调用 Rte_StartTiming 时才开始 [SWS_Rte_06753]。

在关闭过程中，EcuM 在 Shutdown-Phase I 开始时调用 Rte_Stop，此时 OS 仍可用 [SWS_Rte_02570] [SWS_Rte_01310] [SWS_Rte_02584] (SWS_RTE 第461页)。从此调用开始，RTE 在相关核上不再激活任何 Runnable。然而，它不会中止已经在运行的 Runnable [SWS_Rte_02538]。随后是 SchM_Deinit，它受两个条件约束：必须在 Rte_Stop 结束之后且在 OS 关闭之前被调用。SchM_Deinit 释放 Scheduler 部分的资源并在有限时间内返回 [SWS_Rte_07277] (SWS_RTE 第951页)。根据 R23-11 起的文档位置，SchM_Deinit 在此过程中还会调用所有相关插件的 Rte_Rips_SchM_Deinit [SWS_Rte_89019] (SWS_RTE 第1028页)。

Runnable 的执行与多实例

一个软件组件由多个 RunnableEntity 组成。它们在 OS-Task 或 ISR2 中运行，并通过 RTEEvent 触发 [SWS_Rte_02202] [SWS_Rte_02203] (SWS_RTE 第119页)。在 Task 内部，按已配置的执行顺序运行。Task 主体由生成器自身生成 [SWS_Rte_02207] [SWS_Rte_06200] [SWS_Rte_06201]。同一个 Runnable 实例可以通过多个 RTEEvent 激活，也可以通过不同类型的 Event 激活 [SWS_Rte_03520] [SWS_Rte_03524]。

关于中断上下文，适用以下规则：

  • 原则上，RTE 会阻止组件的 Runnable 在中断上下文中运行 [SWS_Rte_03600]。
  • 第 1 类中断不得到达 RTE [SWS_Rte_03594]。
  • 如果 Event 映射到 ISR2，则明确规定在那里激活 [SWS_Rte_04564] (SWS_RTE 第182页)。

RTE 仅通过共享代码支持一个组件类型的多个实例，而不通过代码复制 [SWS_Rte_02002] [SWS_Rte_03015] (SWS_RTE 第126页)。每个实例都可以通过实例句柄唯一标识。Runnable 的入口点将该句柄作为第一个参数接收 [SWS_Rte_02015] [SWS_Rte_01012] [SWS_Rte_01016]。由于各个实例是相互独立调度的，因此入口点应具备可重入性 (SWS_RTE 第804页)。仅当 canBeInvokedConcurrently 为 TRUE 时，才允许同时多次激活同一个 Runnable 实例 [SWS_Rte_03523] [SWS_Rte_05083] (SWS_RTE 第208页)。

Sender-Receiver 与 Client-Server 通信及其缓冲区

对于 Sender-Receiver 通信，RTE 支持显式和隐式访问 [SWS_Rte_06011]。在隐式读取时，RTE 在 Runnable 启动之前读取数据并将其作为副本提供。该副本在整个执行期间保持不变 [SWS_Rte_06000] [SWS_Rte_06001] [SWS_Rte_06004] (SWS_RTE 第286页)。缓冲在接收方进行 [SWS_Rte_02515]，根据语义有所不同：

  • 在数据语义下，RTE 仅保留一条数据记录。每个新值都会覆盖先前的值；在首次接收之前，使用初始值 [SWS_Rte_02516] [SWS_Rte_02518] [SWS_Rte_02520] [SWS_Rte_06010]。
  • 在事件语义下 (queued)，RTE 将 Event 存放在 FIFO 队列中 [SWS_Rte_02521] [SWS_Rte_02522]。其长度由 RteQueuedReceiverQueueLength 确定，或替代地由 queueLength 确定 (SWS_RTE 第320页)。

活动图：追加 Event，或者在队列满时将其丢弃。下一次显式读取访问会报告丢失并重置错误标志。来源：[SWS_Rte_02522] [SWS_Rte_02523] [SWS_Rte_02524] [SWS_Rte_02525] [SWS_Rte_02572]

在 ECU 之间，RTE 通过 COM 传输信号。它将复合数据作为信号组进行原子处理 [SWS_Rte_04527] (SWS_RTE 第326页)。通过 COM 回调，COM 可以激活 Runnable [SWS_Rte_03530] [SWS_Rte_03531]。在 R20-11 中，RTE 通过 LdCom 发送和接收大型字节数组 [SWS_Rte_01376] [SWS_Rte_01377] (SWS_RTE 第350页)。来自 R25-11 的文档位置对此描述为“Large Data Path in COM” (SWS_RTE 第343页)。对于 R20-11，以需求为准。

根据服务器调用点，RTE 将 Client-Server 调用生成为同步或异步 Rte_Call [SWS_Rte_01102] [SWS_Rte_01293] [SWS_Rte_01294]。操作的参数被原子化处理 [SWS_Rte_04518]。如果调用未实现为直接调用或受信任函数 (Trusted Function) 调用，则 RTE 会在两个位置进行缓冲 [SWS_Rte_02527] [SWS_Rte_02528] (SWS_RTE 第358页)：

  • 服务器端的请求缓存在 FIFO 队列中，
  • 客户端的响应缓存在长度为 1 的队列中。

RTE 独立于接收模式监控超时。值 0 关闭监控 [SWS_Rte_03763] [SWS_Rte_03767] (SWS_RTE 第355页)。

时序图：在异步 Client-Server 调用中，请求和响应经过两个缓冲区。客户端使用 Rte_Result 获取结果，超时时返回 RTE_E_TIMEOUT。来源：[SWS_Rte_01109] [SWS_Rte_02527] [SWS_Rte_02528] [SWS_Rte_01111] [SWS_Rte_01114] SWS_RTE 第750页

模式机与模式转换流程

对于每个模式管理器的 ModeDeclarationGroupPrototypes，RTE 在 mode machine instances 中维护活动模式 [SWS_Rte_02546]。模式切换通过 ModeSwitchInterfaces 作为 1:n 通信进行异步报告。该报告仅指明下一个模式 [SWS_Rte_02508] [SWS_Rte_02566] [SWS_Rte_02567]。RTE 不支持同一模式机有多个发送方 [SWS_Rte_02670]。每个模式机都有一个用于切换报告的 FIFO 队列。如果队列已满，RTE 将丢弃新报告。一条报告会保留在队列中，直到切换完成 [SWS_Rte_02718] [SWS_Rte_02719] [SWS_Rte_02720] [SWS_Rte_02721] (SWS_RTE 第322页)。

一个转换按十个步骤进行 [SWS_Rte_02665]：

  1. 激活 Mode Disablings [SWS_Rte_02661]。
  2. RTE 执行 on-exit-ExecutableEntity [SWS_Rte_02562]。
  3. 它执行 on-transition-ExecutableEntity 并等待其结束 [SWS_Rte_02707] [SWS_Rte_02708]。
  4. 它执行 on-entry-ExecutableEntity [SWS_Rte_02564]。
  5. 它解除之前的 Disablings [SWS_Rte_02563]。
  6. 最后，它触发 ModeSwitchedAckEvents [SWS_Rte_02587]。

步骤 1 至 9 允许在每个核上并行运行。仅当整个模式机的其余步骤均已完成时，才执行步骤 10 (ModemanagementGuide 第15页)。即使新模式与旧模式相同，也会执行该转换 [SWS_Rte_02669]。生成器会拒绝在模式事件上配置第 2 类 Runnable 的配置 [SWS_Rte_02500] [SWS_Rte_02662] (SWS_RTE 第426页)。

活动图：模式转换的十个步骤。步骤 1–9 在每个核上运行，步骤 10 仅在所有核上均完成后运行。来源：[SWS_Rte_02665] [SWS_Rte_02708] [SWS_Rte_02721] ModemanagementGuide 第15页

模式管理器可以通过 Rte_SwitchAck 确认切换已完成。一旦切换完成，该 API 返回 RTE_E_TRANSMIT_ACK；如果超时，则返回 RTE_E_TIMEOUT [SWS_Rte_02725] [SWS_Rte_02729] [SWS_Rte_02728] (SWS_RTE 第716页)。根据活动模式，RTE 可以激活 OS-Schedule-Table [SWS_Rte_05146]。类型 Rte_Rips_SwitchNotificationStatusType 和 Rte_DsmqStatusType 描述切换报告入队和出队时的状态 [SWS_Rte_91113] [SWS_Rte_91102]。不过，相应的文档位置来自 R24-11 和 R25-11 (SWS_RTE 第980页、SWS_RTE 第982页)。

生成、变体绑定以及测量与标定

在方法论中，RTE 在“Generate BSW and RTE”活动中生成。输入为 ECU Extract 和 ECU Configuration Values (Methodology 第103页)。具有绑定时间点 SystemDesignTime 和 CodeGenerationTime 的可变性已由生成器在 Contract 阶段和 Generation 阶段绑定。它会拒绝没有明确选择变体的输入 [SWS_Rte_06501] [SWS_Rte_06502] [SWS_Rte_06507] [SWS_Rte_06509] (SWS_RTE 第467页)。他在生成的代码中实现 PreCompileTime 可变性。他拒绝与 RTE 相关的 LinkTime 可变性 [SWS_Rte_06510] [SWS_Rte_06511]。开关 strictConfigurationCheck 控制生成器是否可以自行补充缺失的配置部分 [SWS_Rte_05148] [SWS_Rte_05150]。他将生成的 RTE 本身描述为一个 BSW 模块。这包括生命周期 API 的 BswModuleDescription、BswInternalBehavior、BswImplementation 以及 BswModuleEntry [SWS_Rte_05165] [SWS_Rte_05166] [SWS_Rte_05167] [SWS_Rte_05177] (SWS_RTE 第101页)。

RTE 自行分配标定参数的存储空间 [SWS_Rte_03961]。对于带有软件支持的数据仿真，有 single pointered、double pointered 和 initRam 变体可供选择。每个 RTE 构建中恰好激活其中一种 [SWS_Rte_03943] [SWS_Rte_03909] [SWS_Rte_03913] [SWS_Rte_03914] [SWS_Rte_03915]。也可以针对整个 RTE 代码禁用仿真 [SWS_Rte_03942] (SWS_RTE 第232页)。是否启用标定支持可以按组件类型进行定义 [SWS_Rte_05145]。针对测量与标定工具，生成器生成 McSupportData。其中 McSwEmulationMethodSupport 元素记录了所选的方法 [SWS_Rte_05118] [SWS_Rte_05137] [SWS_Rte_05138] (SWS_RTE 第258页)。这些数据汇入 A2L 生成中 (Methodology 第414页)。

发生错误时的行为

组件仅通过 RTE-API 的返回值获取错误和状态信息 [SWS_Rte_01034] (SWS_RTE 第579页)。各错误类型具有不同的优先级：

  • Immediate Infrastructure Errors 优先于应用程序错误 [SWS_Rte_02593]。
  • Overlayed Errors 通过专有位报告，并可与任何其他代码组合 [SWS_Rte_01318] (SWS_RTE 第584页)。

通信。

AUTOSAR RTE

RTE在特定的ECU上实现虚拟功能总线（VFB），提供软件组件和基础软件之间的通信。

特点——概述

  • Std_ReturnType Rte_Start (void); Rte_Start is intended to allocate and initialize system resources and communication resources used by the RTE.
  • Std_ReturnType Rte_Stop (void); Rte_Stop is used to finalize the RTE on the core it is called.
  • void Rte_StartTiming (void); Rte_StartTiming API is intended to release the activation of RunnableEntitys triggered by TimingEvents and BackgroundEvents...
  • void SchM_Init (const SchM_ConfigType* ConfigPtr); SchM_Init is intended to allocate and initialize system resources used by the Basic Software Scheduler part of the RTE for the...
  • void SchM_Start (void); Basic Software Scheduler initialized.
  • void SchM_StartTiming (void); Start periodical events for BSW/SWCs.
  • void SchM_Deinit (void); SchM_Deinit is used to finalize Basic Software Scheduler part of the RTE of the core on which it is called.
  • void SchM_GetVersionInfo (Std_VersionInfoType* versioninfo); Returns the version information of the Basic Software Scheduler.
