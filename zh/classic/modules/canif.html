CanIf 的角色：CAN 驱动程序与通信协议栈之间的硬件无关枢纽

CAN 接口（CanIf）承担 ECU 的 CAN 通信中所有与硬件无关的任务。底层 CAN 驱动程序因此仅负责对相应 CAN 硬件的访问和控制。CanIf 处理发送请求、发送确认、接收和错误报告以及 CAN 控制器的启动和停止。其数据 API 基于 CAN-L-SDU 操作，其控制 API 则针对 CAN 控制器（SWS CanIf 第13页）。CanIf 绝不直接访问特定于硬件的通信缓冲区，而是仅通过 CanDrv 的服务进行访问 [SWS_CANIF_00023]。

向下，CanIf 为一个或多个 CanDrv 提供服务。在链接时配置下，这是通过每个驱动程序的一组函数指针实现的 [SWS_CANIF_00378]。此外，CanIf 将多个 CanTrcv 的 API 整合为一个统一接口，而自身不包含收发器逻辑（SWS CanIf 第21页、[SWS_CANIF_00358]）。向上则存在可配置的用户：

  • PduR、CanNm、CanTp、Xcp 和 CDD 作为数据用户（[SWS_CANIF_00439]、[SWS_CANIF_00445]、[SWS_CANIF_00448]、[SWS_CANIF_00555]），
  • CanSM 作为控制器模式和收发器模式的控制实例 [SWS_CANIF_00711]，
  • EcuM 用于初始化和唤醒（SWS CanIf 第40页、[SWS_CANIF_00563]）。

上下文图：CanIf 将上层、CanSM 和 EcuM 与 CanDrv 及 CanTrcv 解耦，并向 Mirror、IdsM 和 DET 进行报告。来源：SWS CanIf 第13页、[SWS_CANIF_00724]、[SWS_CANIF_00905]、[SWS_CANIF_00913]

配置、抽象 ID 与初始化

CanIf_Init() [SWS_CANIF_00001] 从容器和参数中读取 CAN 配置。这样无需重新构建模块即可更改配置（SWS CanIf 第22页）。CanIf_ConfigType [SWS_CANIF_00144] 包含公共参数以及每个 L-PDU/L-SDU 的定义 [SWS_CANIF_00523]。初始化具有以下效果：

  • 变量、标志和所有发送缓冲区均被重置（[SWS_CANIF_00085]、[SWS_CANIF_00387]）。
  • 每个通道均设置为 CANIF_OFFLINE [SWS_CANIF_00864]。
  • 动态 Tx-CanId 获取来自 CanIfTxPduCanId 的值 [SWS_CANIF_00857]。

控制器随后保持在 STOPPED 状态（SWS CanIf 第40页）。在 CanIf_Init() 之前，除 CanIf_Init() 和 CanIf_GetVersionInfo() 之外的所有服务均返回值 E_NOT_OK [SWS_CANIF_00661]。

CanIf 分配从 0 开始的专用抽象 ID：

  • ControllerId 用于控制器 [SWS_CANIF_00653]，
  • TransceiverId 用于收发器 [SWS_CANIF_00655]。

为了访问硬件对象，CanIf 使用 HTH（发送）和 HRH（接收）（[SWS_CANIF_00662]、[SWS_CANIF_00291]、[SWS_CANIF_00292]）。每个 CanDrv 的 HTH 和 HRH 构成一个共同的编号范围 [SWS_CANIF_00115]。BasicCAN 类型的 HRH 需要软件过滤器（[SWS_CANIF_00663]、SWS CanIf 第38页）。

上层的目标回调由配置决定。如果没有配置名称，则省略该调用；与接收者的关联通过 L-SDU-ID 进行（SWS CanIf 第133页）。但是必须有一个 BusOff 用户 [SWS_CANIF_00524]。可选服务可在编译时关闭，例如：

  • CanIf_ReadRxPduData() [SWS_CANIF_00330],
  • CanIf_SetDynamicTxId() [SWS_CANIF_00357],
  • CanIf_TriggerTransmit() [SWS_CANIF_00884],
  • CanIf_EnableBusMirroring() [SWS_CANIF_00911].

在 CanIf_DeInit() [SWS_CANIF_91002] 之前，调用者必须确保不再有未决的传输和发送确认（SWS CanIf 第81页）。

发送路径：从 CanIf_Transmit 经由缓冲直到确认

CanIf_Transmit() [SWS_CANIF_00005] 确定与 TxPduId 匹配的 HTH 并调用 Can_Write()。作为 swPduHandle，CanIf 传入稍后在确认中返回的 ID [SWS_CANIF_00318]。如果 Can_Write() 返回 E_OK，则 CanIf_Transmit() 也返回 E_OK [SWS_CANIF_00162]。如果控制器不在 CAN_CS_STARTED 状态，且发送路径既非 online 也非 offline-active，则该作业会被拒绝（[SWS_CANIF_00317]、[SWS_CANIF_00677]）。

在启用缓冲 [SWS_CANIF_00063] 时，CanIf 会将以 CAN_BUSY 被拒绝的 L-PDU 存入分配的 CanIfTxBuffer 中（[SWS_CANIF_00381]、[SWS_CANIF_00836]）。前提是缓冲区大小大于零 [SWS_CANIF_00835]。如果相同的 L-PDU 已经处于缓冲中，则会被覆盖 [SWS_CANIF_00068]。如果缓冲区已满，则调用返回 E_NOT_OK [SWS_CANIF_00837]。原则上，L-PDU 仅存在于确切的一处：要么在硬件对象中，要么在 CanIf 缓冲区中（SWS CanIf 第43页）。

时序图：在硬件对象空闲时 CanIf 直接写入，在 CAN_BUSY 时进行缓冲；上层在两种情况下均接收到 E_OK。来源：SWS CanIf 第138页、[SWS_CANIF_00162]、[SWS_CANIF_00381]、[SWS_CANIF_00837]

发送成功后，CanDrv 会调用 CanIf_TxConfirmation() [SWS_CANIF_00007]。随后执行以下流程：

  1. CanIf 检查在空闲出来的 HTH 的缓冲区中是否有作业在等待 [SWS_CANIF_00386]。
  2. 它发送具有最高优先级的作业（[SWS_CANIF_00668]、[SWS_CANIF_00070]）。
  3. 在 E_OK 之后，它会立即从缓冲区中移除该作业 [SWS_CANIF_00183]。
  4. 最后，它通过 <User_TxConfirmation>(E_OK) 通知上层（[SWS_CANIF_00383]、[SWS_CANIF_00011]）。

较新的版本将此调用称为 LSduR_CanIfTxConfirmation()（SWS CanIf 第157页）。对于 R20-11，适用的则是可配置的 <User_TxConfirmation>。

时序图：在发送确认内部，首先顺推缓冲区，随后确认上层。来源：SWS CanIf 第143页、[SWS_CANIF_00386]、[SWS_CANIF_00183]、[SWS_CANIF_00383]

对于发送，存在两种特殊形式以及一条长度规则：

  • 触发传输：SduDataPtr 允许为 NULL [SWS_CANIF_00882]。CanIf_TriggerTransmit() 仅在硬件空闲时才通过 <User_TriggerTransmit> 获取数据（[SWS_CANIF_00885]、SWS CanIf 第145页）。
  • 动态 Tx-L-PDU：它们在一致性保护下通过 CanIf_SetDynamicTxId() 获取其 CanId（[SWS_CANIF_00189]、[SWS_CANIF_00673]），或从 MetaData 中获取（[SWS_CANIF_00854]、[SWS_CANIF_00855]）。
  • 超长数据：使用 CanIfTxPduTruncation 会将其截断 [SWS_CANIF_00894]。若未启用截断（Truncation），结果将是带有 E_NOT_OK 的运行时错误 [SWS_CANIF_00900]。

接收路径：软件过滤、数据长度检查与转发

在每次接收时，CanDrv 都会调用 CanIf_RxIndication(Mailbox, PduInfoPtr)（[SWS_CANIF_00006]、SWS CanIf 第48页）。CanIf 分两个阶段检查 L-PDU：

  1. 软件过滤（若已配置）。如果它拒绝该 L-PDU，则处理结束 [SWS_CANIF_00389]。与 L-SDU 的分配还会考虑两个最高有效 ID 位 [SWS_CANIF_00877]。单个 CanId 优先于范围 [SWS_CANIF_00852]。
  2. 数据长度检查 [SWS_CANIF_00390]。只要长度至少等于配置的长度，即被接受 [SWS_CANIF_00026]。较短的 L-PDU 会导致运行时错误 CANIF_E_INVALID_DATA_LENGTH [SWS_CANIF_00168]。

被接受的 L-PDU 连同接收到的长度一起传给配置的 <User_RxIndication>（[SWS_CANIF_00056]、[SWS_CANIF_00135]、[SWS_CANIF_00829]）。对于动态 L-SDU，CanIf 将接收到的 CanId 存放在 MetaDataItem CAN_ID_32 中 [SWS_CANIF_00848]。有两种轮询路径是可选的：

  • 一个供 CanIf_ReadRxPduData() 读取的接收缓冲区（[SWS_CANIF_00199]、[SWS_CANIF_00194]）。
  • 遵循“读取并消费”原则的通知状态：状态在接收时置位，并在读取时复位（[SWS_CANIF_00392]、[SWS_CANIF_00394]、SWS CanIf 第55页）。

在通道模式 CANIF_OFFLINE 下，不进行接收通知 [SWS_CANIF_00073]。

活动图：L-PDU 仅在通过软件过滤和数据长度检查后才能到达上层。来源：SWS CanIf 第51页、[SWS_CANIF_00389]、[SWS_CANIF_00390]、[SWS_CANIF_00168]、[SWS_CANIF_00421]

控制器模式、PDU 通道模式和收发器模式

CanIf_SetControllerMode() [SWS_CANIF_00003] 以异步方式工作。它调用 Can_SetControllerMode() [SWS_CANIF_00308]。CanDrv 稍后通过 CanIf_ControllerModeIndication() 报告实际的切换，CanIf 将其转发给 CanSM（[SWS_CANIF_00699]、[SWS_CANIF_00711]）。如果切换失败，上层必须对此进行跟踪。它们可以通过 CanIf_GetControllerMode() 查询该模式（SWS CanIf 第55页、[SWS_CANIF_00229]）。

每个通道都有一个类型为 CanIf_PduModeType 的 PDU 通道模式 [SWS_CANIF_00137]。CanIf_SetPduMode() 仅在 CAN_CS_STARTED 时接受请求（[SWS_CANIF_00008]、[SWS_CANIF_00874]）。某些切换由 CanIf 自身触发：CAN_CS_SLEEP 导致 CANIF_OFFLINE [SWS_CANIF_00865]，STOPPED 或 BusOff 导致 CANIF_TX_OFFLINE [SWS_CANIF_00866]。一份 R20-11 文本摘录将 CANIF_TX_OFFLINE_ACTIVE 描述为“无监听”（SWS CanIf 第58页）。但具有决定性的是 [SWS_CANIF_00137]，据此接收路径保持活动状态。

在局部网络（Partial Networking）中，每个控制器都会在通道模式之上覆盖一个 PnTxFilter（[SWS_CANIF_00747]、[SWS_CANIF_00748]）：

  • 它在初始化时、在 CAN_CS_SLEEP 时以及在 CANIF_TX_OFFLINE 时被激活（[SWS_CANIF_00863]、[SWS_CANIF_00749]、[SWS_CANIF_00878]）。
  • 作用：它仅允许已配置的 CanIfTxPduPnFilterPdus 通过 [SWS_CANIF_00750]。
  • 它通过发送确认或接收被停用（[SWS_CANIF_00751]、[SWS_CANIF_00896]）。

对于收发器，CanIf 将调用透传给 CanTrcv 并转发其消息：

  • 设置和读取模式（[SWS_CANIF_00358]、[SWS_CANIF_00363]），
  • 唤醒原因和唤醒模式（[SWS_CANIF_00368]、[SWS_CANIF_00372]），
  • 向 CanSM 发送模式切换指示 [SWS_CANIF_00712]，
  • 带反馈的 PN 标志服务（[SWS_CANIF_00766]、[SWS_CANIF_00757]、[SWS_CANIF_00765]、[SWS_CANIF_00753]）。

唤醒检测与唤醒验证

集成代码调用 CanIf_CheckWakeup() [SWS_CANIF_00219]。CanIf 随后查询 Can_CheckWakeup() 或 CanTrcv_CheckWakeup() [SWS_CANIF_00395]。如果至少有一个驱动程序报告 E_OK，则 CanIf 返回 E_OK，否则返回 E_NOT_OK（[SWS_CANIF_00720]、[SWS_CANIF_00678]）。该服务仅在配置了唤醒支持时才存在（[SWS_CANIF_00180]、SWS CanIf 第56页）。

对于验证，以下规则适用：

  1. 通过 CanIfPublicWakeupCheckValidSupport，CanIf 保存已启动控制器的第一次有效 CanIf_RxIndication() 调用。根据配置，此时可能仅计入 NM 报文 [SWS_CANIF_00286]。
  2. CanIf_CheckValidation() 通过 <User_ValidateWakeupEvent>(sources) 报告此事件，通常为 EcuM_ValidateWakeupEvent（[SWS_CANIF_00179]、[SWS_CANIF_00563]）。
  3. 在 CAN_CS_SLEEP 时，保存的事件会被清除 [SWS_CANIF_00756]。

只要正在进行验证，通道就不得处于 CANIF_ONLINE 或 CANIF_TX_OFFLINE。否则上层就会提前接收到接收消息（SWS CanIf 第60页）。

时序图：检测与验证是分开的调用；验证使用已开启控制器上的接收报文。来源：SWS EcuM 第181页、[SWS_CANIF_00395]、[SWS_CANIF_00720]、[SWS_CANIF_00286]、[SWS_CANIF_00179]

发生错误时的行为

BusOff。CanDrv 通过 CanIf_ControllerBusOff() 报告 BusOff [SWS_CANIF_00218]。CanIf 作出如下响应：

  • 它调用 CanSM_ControllerBusOff() [SWS_CANIF_00724]。
  • 它将通道设置为 CANIF_TX_OFFLINE [SWS_CANIF_00866]。
  • 在进入 STOPPED 时，它会清空发送缓冲区 [SWS_CANIF_00485]。
  • 对于每个未决的确认，它都会调用 <User_TxConfirmation>(id, E_NOT_OK) [SWS_CANIF_00739]。
  • 它还会额外报告安全事件 CANIF_SEV_ERRORSTATE_BUSOFF [SWS_CANIF_00918]。

CanSM 使用 CanIf_SetControllerMode(…STARTED) 控制重新启动（SWS CanIf 第160页）。较早的错误描述对此仍使用 CANIF_CS_*（ErrorDescription 第16页）；在 R20-11 中适用的则是 CAN_CS_* [SWS_CANIF_00003]。为了进行恢复，CanIf 还提供了 CanIf_GetTxConfirmationState()（[SWS_CANIF_00734]、[SWS_CANIF_00738]）。

时序图：BusOff 消息之后是发送禁止和缓冲区清空；重启由 CanSM 发起，并进行异步确认。来源：SWS CanIf 第148页、[SWS_CANIF_00218]、[SWS_CANIF_00724]、[SWS_CANIF_00866]、[SWS_CANIF_00711]

DET 错误。无效参数由 CanIf 作为开发错误 CANIF_E_PARAM_* 或 CANIF_E_INVALID_* 进行报告（[SWS_CANIF_00311]、[SWS_CANIF_00319]、[SWS_CANIF_00416]、[SWS_CANIF_91006]）。运行时错误 [SWS_CANIF_91007] 包括：

  • 数据长度检查失败 [SWS_CANIF_00168]，
  • 在离线通道上发送（CANIF_E_STOPPED）[SWS_CANIF_00382]，
  • 缓冲时的数据长度冲突 [SWS_CANIF_00895]。

在初始化之前到达的回调将被忽略（[SWS_CANIF_00412]、[SWS_CANIF_00421]、[SWS_CANIF_00431]）。

安全事件（Security Events）。如果启用了上报 [SWS_CANIF_00913]，CanIf 会将来自 CanDrv 的两条消息作为事件转发给 IdsM [SWS_CANIF_91010]：

  • CanIf_ErrorNotification() 作为 Tx 或 Rx 错误（[SWS_CANIF_00915]、[SWS_CANIF_00916]），
  • CanIf_ControllerErrorStatePassive() 作为被动错误（Error-Passive）事件 [SWS_CANIF_00917]。

对此参见 SWS CanDrv 第50页。错误状态和错误计数器可以被查询（[SWS_CANIF_91001]、[SWS_CANIF_91003]、[SWS_CANIF_91004]）。
