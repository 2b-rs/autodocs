在 Ethernet 驱动程序、交换机与通信栈之间转发帧、模式切换以及链路状态。

Ethernet Interface 在一侧的 EthSM 与 Upper Layer，与另一侧的控制器、收发器和交换机驱动程序之间进行转发。它通过异步的 EthIf_SetControllerMode 切换控制器连同引用的硬件 [SWS_EthIf_00034]。它分两步发送帧，分发接收指示，并将链路状态报告给 EthSM 或 BswM。它延迟关闭端口组，并将唤醒检查转发至收发器和交换机。最重要的边界条件：在错误检测激活时，几乎每个服务都以预先执行 EthIf_Init 为前提，否则将报告 ETHIF_E_UNINIT [SWS_EthIf_00155]。

Ethernet Interface 将 Ethernet 栈的用户与控制器、收发器和交换机的驱动程序连接起来。它通过一个或多个 Ethernet Switch Driver 访问交换机 [SWS_EthIf_00228]。向上，EthSM 控制控制器模式并接收模式与链路报告 [SWS_EthIf_00252]。BswM 接收独立端口组的链路状态 [SWS_EthIf_00261]。

通信启动由异步的 EthIf_SetControllerMode 触发 [SWS_EthIf_00034]。EthIf 在此过程中一并切换引用的收发器和端口组 [SWS_EthIf_00266]、[SWS_EthIf_00264]。它通过 EthSM_CtrlModeIndication 报告达到的控制器模式 [SWS_EthIf_00252]。

发送分两步使用 EthIf_ProvideTxBuffer 和 EthIf_Transmit 进行 [SWS_EthIf_00067]、[SWS_EthIf_00075]。确认通过 <UL>_TxConfirmation 到达 Upper Layer；在轮询模式下由 EthIf_MainFunctionTx 触发确认 [SWS_EthIf_00255]、[SWS_EthIf_00113]。EthIf 通过 <User>_RxIndication 分发接收到的帧 [SWS_EthIf_00104]。它会丢弃并计数具有无效 VLAN 的帧 [SWS_EthIf_00317]、[SWS_EthIf_00309]。

EthIf 在 EthIf_MainFunctionState 中周期性确定链路状态 [SWS_EthIf_00407]。对于端口组，它对链路状态进行累加 [SWS_EthIf_00259]，对于活动链路，它轮询信号质量 [SWS_EthIf_00409]。EthIf 通过定时器 EthIfSwitchOffPortTimedelay 延迟关闭端口组的交换机端口 [SWS_EthIf_00270]。EthIf_CheckWakeup 将唤醒检查转发至收发器和交换机 [SWS_EthIf_00245]、[SWS_EthIf_00500]。

在 DET 激活时，各服务会报告无效索引以及未初始化（ETHIF_E_UNINIT）等错误 [SWS_EthIf_00017]、[SWS_EthIf_00155]。如果 DET 被关闭，许多服务将改为返回 E_NOT_OK [SWS_EthIf_00325]。诸如时间戳或 Wireless Ethernet 等可选服务可以通过配置参数关闭 [SWS_EthIf_00164]、[SWS_EthIf_00342]。

EthIf在以太网驱动程序与通信栈之间的角色

以太网接口（Ethernet Interface）是以太网栈用户与控制器（Eth）、收发器（EthTrcv）及交换机（EthSwt）驱动程序之间的独立于硬件的中介层。对于交换机，EthIf使用一个或多个以太网交换机驱动程序，这些驱动程序封装了相应硬件的特性[SWS_EthIf_00228]。通过EthIfSwitchIdx进行的访问由EthIf使用其EthSwtIdx分发至主管的EthSwt模块[SWS_EthIf_00224]。随EthIfEnableWEthApi增加了无线控制器与收发器驱动程序[SWS_EthIf_00340]。分层结构见图示EthSwt-SWS 第5页和Eth-SWS 第18页。

向上，EthIf与多个伙伴协同工作：

  • EthSM控制控制器模式并接收模式与链路消息[SWS_EthIf_00252]、[SWS_EthIf_00262]。
  • BswM接收无控制器关联的端口组的链路状态[SWS_EthIf_00261]。
  • Upper Layer发送帧并接收接收指示以及发送确认[SWS_EthIf_00104]、[SWS_EthIf_00106]。
  • Integration Code通过EthIf_CheckWakeup触发唤醒检查[SWS_EthIf_00244]。

导入的类型（包括Eth_BufIdxType和EcuM_WakeupSourceType）由[SWS_EthIf_00023]确定。文件结构见EthIf-SWS 第15页。

从EthIf_Init到活动的EthIfController

EthIf_Init [SWS_EthIf_00024]接收类型为EthIf_ConfigType的特定于实现的构建后（Post-Build）结构[SWS_EthIf_00149]。在启用错误检测的情况下，几乎所有服务都会检查是否已执行初始化。否则它们会报告ETHIF_E_UNINIT，例如依据[SWS_EthIf_00155]或[SWS_EthIf_00273]。

通信启动由EthIf_SetControllerMode触发；该服务以异步方式工作[SWS_EthIf_00034]。在此过程中，EthIf会一同切换所引用的硬件：

  • 若引用的EthIfTransceiver处于ETH_MODE_DOWN，则按固定顺序执行EthTrcv_SetTransceiverMode及后续调用[SWS_EthIf_00266]。
  • 对于类型为“control”的端口组，将切换其端口[SWS_EthIf_00264]。
  • 在直接关联交换机的情况下，将切换交换机的所有端口（DRAFT）[SWS_EthIf_00478]。

控制器与其他硬件相互独立地受控EthIf-SWS 第30页。反馈以异步方式到来：驱动程序调用EthIf_CtrlModeIndication [SWS_EthIf_00231]，且EthIf继续上报给EthSM_CtrlModeIndication [SWS_EthIf_00252]。收发器通过EthIf_TrcvModeIndication [SWS_EthIf_00232]进行报告。

使用ETH_MODE_DOWN关断时，EthIf仅关闭活动的收发器或交换机端口[SWS_EthIf_00484]、[SWS_EthIf_00485]、[SWS_EthIf_00265]。相反，EthIf在每次调用时都会转发ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST，而与当前模式无关[SWS_EthIf_00479]、[SWS_EthIf_00480]、[SWS_EthIf_00481]。关于交换机关断的较旧规则在R20-11中已作废（OBSOLETE）[SWS_EthIf_00256]、[SWS_EthIf_00257]。

发送和接收帧：缓冲区、VLAN与确认

发送分两步进行：

  1. EthIf_ProvideTxBuffer [SWS_EthIf_00067]提供缓冲区索引和缓冲区指针。若未配置EthIfVlanID，则FrameType和Priority保持未使用状态[SWS_EthIf_00146]。
  2. EthIf_Transmit [SWS_EthIf_00075]触发已填充缓冲区的发送。对于VLAN控制器，EthIf向Eth_Transmit传递值0x8100而非FrameType [SWS_EthIf_00250]。

来自R23-11的文档出处补充了一个条件：仅当最近接受的模式为ETH_MODE_ACTIVE或ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST时才进行转发EthIf-SWS 第101页。通过ETH_MODE_TX_OFFLINE的静默通信（Silent Communication）直到该版本才被描述EthIf-SWS 第34页。它不属于有效载荷中的R20-11需求。

EthIf_TxConfirmation [SWS_EthIf_00091]通过<UL>_TxConfirmation将结果透传至Upper Layer [SWS_EthIf_00255]、[SWS_EthIf_00106]。在轮询模式下，EthIf_MainFunctionTx生成确认并额外检查收发器的状态切换[SWS_EthIf_00113]。在中断模式下，驱动程序的ISR直接回调EthIf-SWS 第88页。自R24-11起EthIf_Transmit基于PDU的签名EthIf-SWS 第97页不适用于R20-11。

链路状态、端口组与信号质量

无收发器引用的控制器的行为表现为链路为ETHTRCV_LINK_STATE_ACTIVE [SWS_EthIf_00229]。若链路发生变化，EthIf为每个受影响的EthIfController调用<User>_TrcvLinkStateChg [SWS_EthIf_00230]、[SWS_EthIf_00108]。在无端口组的情况下，EthIf将主机端口的状态报告给EthSM [SWS_EthIf_00260]。

对于端口组，EthIf累加跨端口的状态。例如，当主机或上行链路端口处于down状态时，ETHTRCV_LINK_STATE_DOWN适用[SWS_EthIf_00259]。当该组分配给某一控制器时，结果发送给EthSM [SWS_EthIf_00262]，否则发送给BswM [SWS_EthIf_00261]。

查询以周期EthIfMainFunctionStatePeriod在EthIf_MainFunctionState [SWS_EthIf_91104]中周期性执行[SWS_EthIf_00407]。若缺少此参数，根据图示由EthIf_MainFunctionRx接管查询EthIf-SWS 第89页。

对于活动链路，EthIf还通过EthSwt_GetPortSignalQuality [SWS_EthIf_00408]或EthTrcv_GetPhySignalQuality [SWS_EthIf_00409]轮询信号质量。当前值、最大值和最小值位于EthIf_SignalQualityResultType [SWS_EthIf_91057]中。它们通过[SWS_EthIf_91056]读取，通过[SWS_EthIf_00400]和[SWS_EthIf_00404]复位。关于更新的规则在EthIf-SWS 第176页中描述。

唤醒、休眠与透传的特殊服务

EthIf_CheckWakeup [SWS_EthIf_00244]以异步方式工作。Integration Code调用该服务，亦可在中断上下文中调用EthIf-SWS 第56页。EthIf转发至所有受影响收发器的EthTrcv_CheckWakeup [SWS_EthIf_00245]以及交换机的EthSwt_SwitchCheckWakeup [SWS_EthIf_00500]。通过EthIfWakeUpSupport可关闭该服务[SWS_EthIf_00248]。

发生错误时的行为

EthIf向DET报告开发错误。[SWS_EthIf_00017]定义了包括ETHIF_E_INV_CTRL_IDX（0x01）和ETHIF_E_INV_TRCV_IDX（0x02）等。各服务的需求还额外使用：

  • ETHIF_E_UNINIT [SWS_EthIf_00155]
  • ETHIF_E_PARAM_POINTER [SWS_EthIf_00157]
  • ETHIF_E_INV_PARAM [SWS_EthIf_00247]
  • ETHIF_E_INV_SWT_IDX [SWS_EthIf_00397]
  • ETHIF_E_INV_PORT_IDX [SWS_EthIf_00493]
  • 针对带有控制器引用的端口组的ETHIF_E_INV_PORT_GROUP_IDX [SWS_EthIf_00274]

若DET被关闭，许多服务则返回E_NOT_OK [SWS_EthIf_00325]、[SWS_EthIf_00326]。与此不同，[SWS_EthIf_00319]给出了代码ETHIF_E_NOTINIT。

运行时错误通过返回值显现：

  • 当传输失败时，EthIf_Transmit返回E_NOT_OK [SWS_EthIf_00075]。
  • EthIf_ProvideTxBuffer返回一个BufReq_ReturnType [SWS_EthIf_00067]。
  • EthIf_TxConfirmation将负的发送结果原样透传至Upper Layer [SWS_EthIf_00255]。
  • 当没有端口或有多个端口匹配时，EthIf_GetPortMacAddr报告E_NOT_OK [SWS_EthIf_00191]。
  • 在索引不受支持时，EthIf_GetAndResetMeasurementData报告E_NOT_OK [SWS_EthIf_00310]。计数器不会溢出[SWS_EthIf_00313]，且ETHIF_MEAS_ALL仅用于复位[SWS_EthIf_00312]、EthIf-SWS 第65页。

在网络层级，EthIf对丢弃的帧进行计数，并可选地将其作为安全事件报告[SWS_EthIf_00309]、[SWS_EthIf_00503]。EthIf将链路丢失传播给用户或EthSM或BswM [SWS_EthIf_00230]、[SWS_EthIf_00262]、[SWS_EthIf_00261]。对于作为被动从机工作的收发器，EthIf还会检测意外的链路断开（Link-Down）[SWS_EthIf_00499]。
