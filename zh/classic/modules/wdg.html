在看门狗栈中的角色与系统边界

看门狗驱动（Wdg）是看门狗栈中贴近硬件的部分。它初始化看门狗硬件[SWS_Wdg_00001]，并在静态配置的模式之间对其进行切换[SWS_Wdg_00160]。只要存在有效的触发条件，它就会服务（“触发”）硬件[SWS_Wdg_00144]。触发的时序封装在驱动程序中。Watchdog Manager（WdgM）仅通过 Watchdog Interface（WdgIf）设置触发条件，指示驱动程序继续触发SWS WatchdogManager 第56页。公共接口包含四个函数以及配置类型 Wdg_ConfigType：

  • Wdg_Init [SWS_Wdg_00106]
  • Wdg_SetMode [SWS_Wdg_00107]
  • Wdg_SetTriggerCondition [SWS_Wdg_00155]
  • Wdg_GetVersionInfo [SWS_Wdg_00109]
  • Wdg_ConfigType [SWS_Wdg_00171]

在驱动程序之上，WdgIf 将 API 映射到负责的驱动程序，并通过DeviceIndex对其进行选择。如果仅配置了一个驱动程序，则DeviceIndex会被忽略，并且该映射应在没有运行时开销的情况下完成，例如通过宏SWS WatchdogInterface 第17页。为此，WdgM 需要WdgIf_SetMode和WdgIf_SetTriggerCondition作为强制接口SWS WatchdogManager 第86页。相比之下，初始化由 ECU State Manager 直接通过Wdg_Init SWS ECUStateManager 第34页 SWS WatchdogDriver 第30页完成。

在驱动程序之下有两种具体实现形式。内部看门狗的实例直接访问硬件[SWS_Wdg_00161]。外部看门狗的实例则使用处理程序或驱动程序（例如 Spi 或 Dio）的 API[SWS_Wdg_00076]。驱动程序可选地向 DET（Det_ReportError）和 DEM（Dem_SetEventStatus）进行报告[SWS_Wdg_00111]。

上下文图：Wdg 位于 WdgIf/EcuM 与内部硬件或通过 Spi/Dio 连接的外部硬件之间。解释：EcuM 初始化这两个实例。来源：[SWS_Wdg_00076] [SWS_Wdg_00161] [SWS_Wdg_00111] SWS WatchdogManager 第9页

启动：从 Wdg_Init 到首个触发条件

Wdg_Init的 Service-ID 为 0x00，是同步且不可重入的。该函数接收一个指向配置集的指针[SWS_Wdg_00106]。它初始化所有全局变量，并根据配置集设置默认模式及初始超时周期[SWS_Wdg_00100] [SWS_Wdg_00001]。它仅写入既不影响其他硬件模块也不依赖于它们的寄存器。跨模块的寄存器由一个通用的系统模块初始化[SWS_Wdg_00101]。根据 WdgM 的图表，硬件看门狗在此过程中已然启动SWS WatchdogManager 第74页。

在开发错误检测（DET）激活时，成功初始化后模块状态从WDG_UNINIT变为WDG_IDLE [SWS_Wdg_00019]。特意未提供去初始化函数。如果硬件支持关闭且环境允许，则通过带有 OFF 模式的Wdg_SetMode来进行关闭[SWS_Wdg_00031]。

随后由 WdgM 接管控制。它通过WdgIf_SetTriggerCondition设置触发条件，并通过WdgIf_SetMode切换模式SWS WatchdogDriver 第34页 SWS WatchdogInterface 第19页。WdgIf_SetMode原封不动地传递Wdg_SetMode的返回值SWS WatchdogInterface 第18页。

时序图：EcuM 直接初始化驱动程序，而 WdgM 通过 WdgIf 控制触发条件和模式。来源：SWS WatchdogDriver 第34页 [SWS_Wdg_00001] [SWS_Wdg_00136] [SWS_Wdg_00103]

触发条件、超时计数器与服务例程

触发条件的含义是：“允许在接下来的 n 毫秒内服务看门狗”。在此时间窗口内，控制实体必须更新该条件，否则看门狗将会超时[SWS_Wdg_00144]。Wdg_SetTriggerCondition（Service-ID 0x03）根据传入的值重置超时计数器[SWS_Wdg_00155] [SWS_Wdg_00136]。该值以毫秒为单位。转换为计数器值是在内部完成的，并会考虑当前模式[SWS_Wdg_00138] [SWS_Wdg_00139]。

服务例程的工作与其解耦：

  • 如果触发计数器大于零，它会将其递减并触发硬件[SWS_Wdg_00134]。
  • 如果其为零，它不执行任何操作，看门狗超时[SWS_Wdg_00135]。

在规范的图表中，定时器中断触发该例程。WdgM 与之异步地更新触发条件SWS WatchdogDriver 第31页。如果该例程实现为中断，则中断框架位于Wdg_Irq.c [SWS_Wdg_00079]中。

明确允许传入值 0。它几乎立即终止触发，并导致 ECU 发生看门狗复位。如果存储的计数器值已为 0，则Wdg_SetTriggerCondition会忽略任何后续值。由此引发的复位无法撤销[SWS_Wdg_00140] SWS WatchdogDriver 第29页。如果硬件需要可变的激活码，驱动程序会在内部对其进行管理。此时触发周期的选择必须确保硬件能够安全地更新该代码[SWS_Wdg_00093] [SWS_Wdg_00094]。

时序图：定时器驱动的服务与触发条件的异步更新在时间上是解耦的。来源：SWS WatchdogDriver 第31页 [SWS_Wdg_00134] [SWS_Wdg_00135] [SWS_Wdg_00093]

活动图：Wdg_SetTriggerCondition 中直到值为 0 触发既定复位的决策分支。解释：检查的顺序未作规定。来源：[SWS_Wdg_00146] [SWS_Wdg_00140] [SWS_Wdg_00138] [SWS_Wdg_00139]

较旧的图表仍显示调用链WdgIf_Trigger/Wdg_Trigger SWS WatchdogDriver 第30页 SWS WatchdogManager 第75页。R20-11 API 不包含此调用。其中以触发条件概念为准[SWS_Wdg_00144]。

看门狗模式与模式切换

Wdg_SetMode（Service-ID 0x01，同步，不可重入）将驱动程序和硬件切换为三种模式之一：WDGIF_OFF_MODE、WDGIF_SLOW_MODE或WDGIF_FAST_MODE [SWS_Wdg_00107] [SWS_Wdg_00160]。每种模式对应一个静态配置的设置，例如翻转看门狗或窗口看门狗，或特定的超时周期[SWS_Wdg_00160]。每种模式的参数包含在用于Wdg_Init的配置集中[SWS_Wdg_00051]。驱动程序从WdgIf.h导入类型WdgIf_ModeType [SWS_Wdg_00105]。

仅当切换已完全执行且模块与硬件均已采纳所有新值时，该函数才返回 E_OK [SWS_Wdg_00103]。能否关闭取决于预编译参数WdgDisableAllowed。只要默认模式带有关闭设定，就会在Wdg_Init中被拒绝[SWS_Wdg_00025]。WDG_E_DISABLE_REJECTED明确同样适用于模式切换[SWS_Wdg_00179]。在 WdgM 侧，容器WdgMTrigger为每个看门狗确定模式和触发值（1 至 65535）SWS WatchdogManager 第125页。

状态图：Wdg_Init 设置默认模式，Wdg_SetMode 在各模式之间切换，且仅在允许关闭时才可进入 OFF 模式。来源：[SWS_Wdg_00160] [SWS_Wdg_00025] [SWS_Wdg_00179] [SWS_Wdg_00001]

内部与外部实例、配置及代码组织

用于外部看门狗的 Wdg 必须提供与用于内部看门狗的 Wdg 相同的功能范围以及语义相同的 API[SWS_Wdg_00077]。其源代码是平台无关的[SWS_Wdg_00055]。如果同一 ECU 上同时存在这两种实例，则 API 名称、类型名称以及代码与头文件名称将根据 SRS_BSW_00347 进行扩展[SWS_Wdg_00172] [SWS_Wdg_00169] [SWS_Wdg_00170] SWS WatchdogDriver 第24页。相应的包含关系图展示了诸如Wdg<xxx>.h SWS WatchdogDriver 第11页等文件。为了访问外部硬件，驱动程序添加了发布参数和配置参数，例如 Spi 通道或 Dio 端口[SWS_Wdg_00078]。后续版本将此建模为对 DioChannelGroup、SpiSequence 或 I2CSequence 的选择引用SWS WatchdogDriver 第40页。

Wdg_ConfigType是一个与硬件相关的结构，其指针会传递给初始化过程[SWS_Wdg_00171]。如果激活码是可配置的，则其初始值属于该配置集[SWS_Wdg_00095]。

  • 这些参数最迟在编译时进行静态检查[SWS_Wdg_00086]。
  • 链接时参数和后构建参数分别位于Wdg_Lcfg.c和Wdg_PBcfg.c中[SWS_Wdg_00079]。
  • 根据配置，代码在 ROM 或 RAM 中运行[SWS_Wdg_00168]。

并发性与模块状态

MCAL 驱动程序的服务 API 可以从多个任务或 ISR 上下文中调用。共享数据和寄存器在此过程中面临竞态风险BSWDistributionGuide 第37页。如果 Wdg 必须禁用中断（例如在模式切换期间或在触发例程中），它会尽可能使用 BSW Scheduler 的 Exclusive Area。内部驱动程序作为 MCAL 模块也可以直接禁用中断[SWS_Wdg_00040]。仅Wdg_GetVersionInfo是可重入的[SWS_Wdg_00109]。

在 DET 处于激活状态时，模块状态使得这种互斥性变得可检查：

  • Wdg_SetMode和服务例程在执行期间设置WDG_BUSY，并在作为最后的操作重新设置WDG_IDLE [SWS_Wdg_00018] [SWS_Wdg_00052]。
  • 两者预先都会检查是否处于WDG_IDLE。若不处于该状态，则不执行操作，并报告WDG_E_DRIVER_STATE [SWS_Wdg_00017] [SWS_Wdg_00035]。

发生错误时的行为

开发错误已作规定[SWS_Wdg_00010]：

错误代码值
WDG_E_DRIVER_STATE0x10
WDG_E_PARAM_MODE0x11
WDG_E_PARAM_CONFIG0x12
WDG_E_PARAM_TIMEOUT0x13
WDG_E_PARAM_POINTER0x14
WDG_E_INIT_FAILED0x15

各个函数的反应如下：

  • Wdg_Init: 如果配置超出允许的限制，则中止初始化并报告WDG_E_PARAM_CONFIG [SWS_Wdg_00090]。带有不允许关闭特性的默认模式同样会导致中止，并报告WDG_E_DISABLE_REJECTED [SWS_Wdg_00025]。
  • Wdg_SetMode: 错误的状态会导致WDG_E_DRIVER_STATE并返回 E_NOT_OK [SWS_Wdg_00017]。无效的Mode或超出硬件限制的设置会导致WDG_E_PARAM_MODE并返回 E_NOT_OK [SWS_Wdg_00091] [SWS_Wdg_00092]。
  • Wdg_SetTriggerCondition: 超过WdgMaxTimeout的超时会被拒绝并报告WDG_E_PARAM_TIMEOUT。计数器不会被重新加载[SWS_Wdg_00146]。
  • Wdg_GetVersionInfo: 后续版本要求在指针为 NULL 时报告WDG_E_PARAM_POINTER且不执行任何操作直接返回SWS WatchdogDriver 第30页。解释：这应该也适用于 R20-11。该错误代码在其中存在[SWS_Wdg_00010]，且变更历史记录自 4.0.3 起就列出了该 DET 错误SWS WatchdogDriver 第3页。

独立于 DET，驱动程序报告两个扩展生产错误，分别带有 FAILED 或 PASSED [SWS_Wdg_00180] [SWS_Wdg_00181] [SWS_Wdg_00182] [SWS_Wdg_00183]：

  • WDG_E_MODE_FAILED：在初始化或模式切换期间设置模式失败[SWS_Wdg_00178]。
  • WDG_E_DISABLE_REJECTED：请求了不允许的关闭[SWS_Wdg_00179]。

如果无法进行切换（例如由于设置不一致或违反时间条件），Wdg_SetMode将返回 E_NOT_OK 并报告WDG_E_MODE_FAILED [SWS_Wdg_00016]。

活动图：从 Wdg_SetMode 到 E_OK 的检查与错误路径。解释：检查的顺序未作规定。来源：[SWS_Wdg_00017] [SWS_Wdg_00091] [SWS_Wdg_00092] [SWS_Wdg_00179] [SWS_Wdg_00016] [SWS_Wdg_00103]

看门狗超时是整个系统的既定错误路径。如果未更新触发条件，触发将停止，硬件将触发复位[SWS_Wdg_00135] SWS WatchdogManager 第56页。
