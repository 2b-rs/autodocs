系统架构与模块集群的角色

该 Cluster 将 Classic Platform 的 Crypto Stack 映射为三个层级。Crypto Service Manager (CSM) 为应用程序和 BSW 用户提供标准化的加密服务。Crypto Interface (CryIf) 将作业分发到已配置的驱动程序。Crypto Driver (Crypto) 位于 CryIf 和 CSM 之下微控制器抽象层中，负责实现原语及密钥存储。一个 ECU 仅集成一个 CSM 和一个 CryIf。然而 CryIf 可以访问多个 Crypto 驱动（SWS CryptoDriver 第15页）。多个驱动实例通过命名模式 Crypto_<vi>_<ai> 进行区分（SWS CryptoDriver 第23页）。

为了理解该 Cluster，有四个核心概念至关重要：

  • 作业是已配置原语的实例 [SWS_Csm_00941]。它作为 Crypto_JobType 传递通过所有三个层级 [SWS_Csm_01013]。
  • 通道是从 CsmQueue 经由 CryIf 到 Crypto Driver Object 的路径（SWS CSM 第29页）。
  • 队列根据作业配置的优先级对其进行排序 [SWS_Csm_00944]。
  • 密钥由密钥元素组成 [SWS_Csm_00954]。它们的 ID 是标准化的 [SWS_Csm_01022]。

CSM 的典型用户包括：

  • 带有异步回调的 SecOC [SWS_Csm_00971]（SWS SecOC 第78页），
  • 用于 TLS 的 TcpIp（SWS TcpIp 第115页），
  • 用于身份验证的 DCM（SWS DCM 第279页）。

驱动程序本身使用 NvM 和 DET [SWS_Crypto_91017]。

上下文图：用户调用 CSM，CSM 通过 CryIf 通道访问一个或多个 Crypto 驱动，结果通过回调链返回。来源：SWS CryptoDriver 第15页、[SWS_CryIf_91100]、[SWS_Crypto_91017]

协作与交互路径

该规范区分了基于作业的 API 和直接 API（SWS CSM 第20页）。

  • 基于作业的服务（如 Csm_Hash 或 Csm_Encrypt）通过统一接口 CryIf_ProcessJob [SWS_CryIf_91003] 运行至 Crypto_ProcessJob [SWS_Crypto_91003]。
  • 密钥管理服务仅由 CSM 作为 Csm_<Service> 提供 [SWS_Csm_00950]。它们被直接透传，例如 Csm_KeyElementSet → CryIf_KeyElementSet → Crypto_KeyElementSet [SWS_Csm_00957] [SWS_CryIf_91004] [SWS_Crypto_91004]。类似地，Csm_KeyDerive 和 Csm_RandomSeed 调用其 CryIf 对应项 [SWS_Csm_01018] [SWS_Csm_01052]。

操作模式以位掩码 Crypto_OperationModeType 的形式传递。START、UPDATE 和 FINISH 可以组合，CRYPTO_OPERATIONMODE_SINGLECALL (0x07) 结合了这三者 [SWS_Csm_01029] [SWS_Csm_01039]。不带 UPDATE 的 START|FINISH 会导致 E_NOT_OK [SWS_Csm_01045]。带有多次 UPDATE 调用的流式传输适用于大数据量（EXP Crypto 第12页）。

指针和长度位于 Crypto_JobPrimitiveInputOutputType [SWS_Csm_01009] 中。长度参数为 inout：在调用时包含缓冲区大小，完成后包含实际长度（SWS CSM 第49页）。对于缓冲区大小适用两条规则：

  • Hash 和 MAC 结果会被截断至最高有效位 [SWS_Crypto_00065]。
  • 对于所有其他操作，过小的缓冲区将阻止执行 [SWS_Crypto_00195]。

通过 Redirection 可以将输入和输出重定向到密钥元素 [SWS_Csm_91026] [SWS_Crypto_00203] [SWS_Crypto_00204]。

CryIf 有两项自身任务：

  • 它将 cryIfKeyId 映射到负责驱动程序的密钥 ID [SWS_CryIf_00133]。
  • 如果部分复制的源密钥和目标密钥位于不同的驱动程序中，它会自行通过 Crypto_KeyElementGet 和 Crypto_KeyElementSet 进行复制 [SWS_CryIf_00140]。

异步结果通过回调链返回：CryIf_CallbackNotification [SWS_CryIf_91013] → Csm_CallbackNotification [SWS_Csm_00970]。仅当设置了 FINISH 位时才会调用应用程序回调 [SWS_Csm_01044]。

时序图：一个异步作业被排入队列，由 Csm_MainFunction 传递给 CryIf 和驱动程序，并通过回调级联进行返回通知。来源：SWS CSM 第146页、[SWS_Csm_00479]、[SWS_Crypto_91012]、[SWS_Csm_01044]

同步、重入性与任务上下文

作业是同步运行还是异步运行取决于其配置 [SWS_Csm_01049]。该信息包含在 Crypto_JobType 中（SWS CryptoDriver 第26页）。在异步情况下，有两个周期性函数在工作：

  • 每个配置的 Csm_MainFunction_<shortName> 检查队列并将作业转发给 CryIf [SWS_Csm_00479]。
  • Crypto_MainFunction 处理驱动程序队列 [SWS_Crypto_91012]。实际的计算可以在那里触发（SWS CryptoDriver 第27页）。

对于 R20-11，需要注意版本差异。此处 CryIf_RandomSeed 和 CryIf_KeyGenerate 根据配置仍为同步或异步 [SWS_CryIf_91007] [SWS_CryIf_91008]。从 R21-11 开始它们才始终是同步的（SWS CryIf 第1页）。

CSM 对每个作业同时最多处理一个实例，但可以并行处理不同的作业。处于 ACTIVE 状态的作业直接发送到 CryIf_ProcessJob。如果队列已满，CSM 将以 CRYPTO_E_BUSY 响应（SWS CSM 第21页）。

活动图：根据作业状态、处理类型、队列填充程度和优先级，Csm_<Service> 调用会被直接转发、排入队列或以 CRYPTO_E_BUSY 拒绝（同步分支的分配是对图表标签的解释）。来源：SWS CSM 第30页、SWS CSM 第21页、[SWS_Csm_00944]

在多核系统上，Crypto Driver 在每个分区作为独立实例运行 [SWS_Crypto_CONSTR_00001]。一个 HSM 对象最多属于一个分区 [SWS_Crypto_CONSTR_00003]。每个 CsmQueue 分配给一个 MainFunction。因此，通过栈的流保持在一个分区内（BSW Distribution 第59页）。

生命周期与运行模式

每个模块都有一个同步、不可重入的 Init 函数：Crypto_Init [SWS_Crypto_91000]、CryIf_Init [SWS_CryIf_91000] 和 Csm_Init [SWS_Csm_00646]。驱动程序的配置指针始终为 NULL [SWS_Crypto_00215]。CSM 可以为每个分区提供一个 Init 函数（SWS CSM 第48页）。初始化可能自底向上进行（Crypto → CryIf → CSM）。在初始化之前的调用将报告 *_E_UNINIT [SWS_Crypto_00040] [SWS_CryIf_00009] [SWS_Csm_91004]。

作业具有状态 CRYPTO_JOBSTATE_IDLE 和 CRYPTO_JOBSTATE_ACTIVE [SWS_Csm_01028]。START 重置输入和中间结果 [SWS_Csm_01029] 并丢弃同一作业先前的请求（SWS CryptoDriver 第25页）。

状态图：START/STREAMSTART 转换至 ACTIVE，UPDATE 保持在 ACTIVE，FINISH 返回至 IDLE；SINGLECALL 在单次调用中经历所有阶段。来源：[SWS_Csm_01028]、[SWS_Csm_01029]、[SWS_Csm_01039]

密钥状态（CRYPTO_KEYSTATUS_VALID/INVALID）在 R20-11 中新引入 [SWS_Csm_91102]。它通过 Crypto_KeySetValid 和 Crypto_KeySetInvalid 进行设置 [SWS_Crypto_91014] [SWS_Crypto_91020]。其查询通过 Csm_KeyGetStatus → CryIf_KeyGetStatus [SWS_Csm_91047] [SWS_CryIf_91012] 进行。在 Csm_KeyElementSet 中发生错误后，该状态被视为未知，应进行检查（SWS CSM 第62页）。

对于密钥持久化，驱动程序定义了 NvM 回调 [SWS_Crypto_91023]–[SWS_Crypto_91026]。如果持久密钥在初始化时无法加载，它将失效 [SWS_Crypto_00198]。后续版本规定仅在 KEYSETVALID 时存储密钥（SWS CryptoDriver 第37页）。此规则在 R20-11 中未被作为需求证实。

在 R20-11 中同样新增的是作业上下文的保存与恢复（SWS CryptoDriver 第2页）。为此提供了 Csm_SaveContextJob 和 Csm_RestoreContextJob [SWS_Csm_91063] [SWS_Csm_91064]。密钥元素不是该上下文的一部分（SWS CSM 第35页）。Payload 未提及专用的 Shutdown 或 Sleep 服务。正在运行的异步或流式作业由 Csm_CancelJob [SWS_Csm_00968] 终止。

错误处理、DET 跟踪与降级

每个层都使用各自的代码报告开发错误 [SWS_Crypto_00040] [SWS_CryIf_00009] [SWS_Csm_91004]。作为错误服务，各模块仅请求 DET，不请求 DEM 接口 [SWS_Csm_91101] [SWS_CryIf_91101] [SWS_Crypto_91017]。例如：驱动程序在每个作业之前检查密钥 ID，并在发生错误时报告 CRYPTO_E_PARAM_HANDLE 并返回 E_NOT_OK [SWS_Crypto_00217]。

与后续版本相比，R20-11 在两点上有所不同：

  • CryIf 在 R20-11 中仍报告 CRYPTO_E_PARAM_HANDLE [SWS_CryIf_00134]。从 R22-11 起，该代码命名为 CRYIF_E_PARAM_HANDLE（SWS CryIf 第1页）。
  • 从 R22-11 起，在 DET 报告之后不再有返回值（同上）。

当熵耗尽以及 NvM 访问失败时，驱动程序会报告运行时错误 [SWS_Crypto_00194] [SWS_Crypto_00141]。CSM 报告 CSM_E_QUEUE_FULL [SWS_Csm_01089]。CryIf 请求 Det_ReportRuntimeError [SWS_CryIf_91100]。

操作反馈由 Crypto_ResultType [SWS_Csm_91044] 提供，例如 CRYPTO_E_BUSY 或 CRYPTO_E_KEY_NOT_VALID。CRYPTO_E_BUSY 大致是指一种暂态，用户可以通过稍后重试来解决。

通过 Csm_CancelJob 进行的中止操作会从队列中移除作业或调用 CryIf_CancelJob [SWS_CryIf_91014]。CryIf 将其转发至 Crypto_CancelJob [SWS_Crypto_00122]。根据驱动程序中的情况，有三种可能的结果：

  • 作业当前未被处理：E_OK [SWS_Crypto_00214]。
  • 无法立即中止：CRYPTO_E_JOB_CANCELED [SWS_Crypto_00183]。稍后通过否定回调进行中止（SWS CSM 第80页）。

针对降级运行，该规范提供了三种机制：

  • 密钥元素的访问权限保护其内容 [SWS_Crypto_00219] [SWS_Crypto_00220]。
  • 没有独立随机数生成器的 Driver Object 会退避使用 Object 0 [SWS_Crypto_00224] [SWS_Crypto_00225]。
  • NvM 故障必须由应用程序处理（SWS CryptoDriver 第35页）。
