通过硬件和软件驱动程序提供标准化的加密计算与密钥管理服务。

该集群捆绑了 CSM、CryIf 和 Crypto Driver 模块，用于在 AUTOSAR Classic Platform 中以独立于硬件的方式提供加密服务和密钥管理功能 EXP_UtilizationOfCryptoServices 第8页。加密作业通过 CSM 进行优先级排序，在 CryIf 中路由到逻辑通道，并在 Crypto Driver 中同步或异步执行 [SWS_CryIf_91003]。出于一致性原因，NVM 中的密钥持久化严格仅在通过 KeySetValid 成功验证后进行 SWS_CryptoDriver 第37页。

“Crypto Services & Hardware Abstraction”模块集群包含 AUTOSAR Classic 模块 Crypto Service Manager（csm）、Crypto Interface（cryif）和 Crypto Driver（crypto）EXP_UtilizationOfCryptoServices 第8页。它为加密操作（其中包括加密、签名、MAC 计算和随机数生成）以及安全密钥管理提供了一个独立于硬件的抽象层 [SWS_Csm_00982]、[SWS_Csm_00984]、SWS_CryptoDriver 第15页。

加密请求被封装为 Crypto_JobType，其定义了优先级、输入和输出缓冲区以及操作模式（用于流式处理或 SingleCall 的 Start、Update、Finish）[SWS_Csm_01013]、[SWS_Csm_01039]。CSM 接收作业，将其分配给软件队列，并通过 CryIf_ProcessJob() 转发 [SWS_Csm_00017]、[SWS_CryIf_91003]。CryIf 负责到驱动程序的通道路由，并将 CSM 密钥标识符转换为模块特定的驱动程序密钥 ID [SWS_CryIf_00133]。

1. 系统架构与模块群集的作用

“Crypto Services & Hardware Abstraction”模块集群构成了 AUTOSAR Classic Platform 中加密操作、基于软件和硬件的密钥管理以及安全板载通信的功能基础 EXP_UtilizationOfCryptoServices 第8页。该架构严格按照 AUTOSAR 分层模型划分为三个标准化 BSW 模块：服务层中的 Crypto Service Manager（csm）、ECU Abstraction Layer 中的 Crypto Interface（cryif）以及 Microcontroller Abstraction Layer（MCAL）上的至少一个 Crypto Driver（crypto）SWS_CryptoDriver 第15页。该分层体系将安全应用（例如 SecOC、TLS 连接建立和 UDS 诊断身份验证）与专有加密协处理器（如硬件安全模块（HSM）或安全硬件扩展（SHE））完全抽象隔离开来 SWS_SecureOnboardCommunication 第78页。

Crypto Service Manager（CSM）充当应用程序组件（SW-C）和更高层 BSW 模块的主要服务提供商。它为对称和非对称算法（例如 AES、RSA）、哈希、消息身份验证码（MAC）、随机数生成（RNG）以及 AEAD 方法提供标准化编程接口 [SWS_Csm_00980]、[SWS_Csm_00982]、[SWS_Csm_00984]、[SWS_Csm_01023]。此外，CSM 还实现软件作业队列并控制并行加密作业的优先级排序 [SWS_Csm_00022]、SWS_CryptoServiceManager 第29页。

Crypto Interface（CryIf）作为抽象层，在 CSM 和任意数量的加密驱动程序之间提供统一的 1:n 接口。其核心任务是分发（Dispatching）：它根据配置的逻辑通道（channelId）将作业转发给相应的 Crypto Driver 实例，并将逻辑密钥引用（cryIfKeyId）转换为驱动程序特定标识符（cryptoKeyId）[SWS_CryIf_00133]、[SWS_CryIf_91003]。Crypto Driver 封装了物理执行单元（Crypto Driver Object），并服务于纯软件加密原语或专用硬件安全模块 [SWS_Crypto_00224]、SWS_CryptoDriver 第15页。

2. 模块间的相互协作与交互路径

集群内的作业处理主要通过使用结构 Crypto_JobType 的基于作业的模型进行 [SWS_Csm_01013]、AUTOSAR_CP_SWS_CryptoServiceManager 第21页。一个加密作业捆绑了作业 ID、优先级信息、密钥引用、原语元数据以及用于输入、输出和长度参数指针管理的结构 Crypto_JobPrimitiveInputOutputType [SWS_Csm_01012]。通过位掩码字段 Crypto_OperationModeType（包含标志 START、UPDATE、FINISH）来控制作业是作为连贯的单次调用（SINGLECALL）计算，还是在流模式下增量计算 [SWS_Csm_01039]、[SWS_Csm_01029]。

当同步调用 CSM 服务函数时，CSM 会检查作业状态。若驱动程序空闲或作业被配置为同步，CSM 将直接调用 CryIf_ProcessJob() [SWS_Csm_00017]、[SWS_CryIf_91003]。CryIf 映射密钥 ID 并通过 Crypto_ProcessJob() 将作业分发至分配的驱动程序实例 [SWS_CryIf_00133]。对于异步请求，当驱动程序对象被占用时，作业会被排入 CSM 队列 [SWS_Csm_00018]、AUTOSAR_CP_SWS_CryptoServiceManager 第30页。在异步驱动程序计算完成后，驱动程序触发 CryIf_CallbackNotification() [SWS_CryIf_91013]，CryIf 将该消息转发给 Csm_CallbackNotification() [SWS_Csm_00970]，最终 CSM 通过其配置的回调通知请求的应用程序 [SWS_Csm_01044]、[SWS_Csm_00928]。

时序图：具有排队和回调级联的异步加密作业流程。来源：[SWS_Csm_00970]、[SWS_CryIf_91013]、AUTOSAR_CP_SWS_CryptoServiceManager 第146页

除主要的加密执行外，密钥管理也是该集群不可或缺的交互路径 SWS_CryptoDriver 第24页。一个密钥由多个逻辑密钥元素（如密钥材料、初始化向量或迭代值）组成 [SWS_Csm_00954]、[SWS_Csm_01022]。诸如通过 Csm_KeyElementSet() 设置密钥材料、通过 Csm_KeyElementCopy() 复制或通过 Csm_KeyDerive() 导出密钥等操作，均通过 CryIf（CryIf_KeyElementCopy()、CryIf_KeyDerive()）同步转发至驱动程序函数 [SWS_Csm_00957]、[SWS_Csm_00969]、[SWS_CryIf_91015]、[SWS_CryIf_91009]。在此过程中，对密钥元素的访问受到配置的访问权限（CRYPTO_RA_ALLOWED、CRYPTO_RA_ENCRYPTED、CRYPTO_RA_INTERNAL_COPY）的严格监控 [SWS_Crypto_00219]。

3. 同步、可重入性与任务上下文

加密操作的执行时间差异极大。虽然快速的分组密码或哈希计算可以在调用者的任务上下文中同步执行，但非对称计算（例如 RSA 签名生成）或耗时的硬件流程需要进行异步处理 [SWS_Csm_00984]、[SWS_Csm_00992]。为了实现解耦，CSM 提供了循环调用的主函数 Csm_MainFunction() [SWS_Csm_00479]。该函数监控队列，将待处理作业分发至 CryIf，并推进异步原语的内部状态机 [SWS_Csm_00019]。

在现代多核和多扇区架构中，CSM 支持多个实例 Csm_MainFunction_<shortName>()，这些实例分配给专用的 OS 分区 [SWS_Csm_00479]、AUTOSAR_SWS_CryptoServiceManager 第170页。在异步驱动程序执行中，计算要么通过驱动程序 MainFunction 中的轮询完成，要么通过基于硬件的加密引擎的中断服务例程（ISR）完成 [SWS_Crypto_00027]、[SWS_Crypto_00028]。根据定义，单个 Crypto Driver Object 同一时间只能恰好处理一个加密作业；具有 n 个对象的驱动程序可以真正并行处理 n 个作业 [SWS_Crypto_00014]、[SWS_Crypto_00117]。

关于可重入性，诸如 Csm_MacGenerate() 或 CryIf_ProcessJob() 之类的服务接口被设计为针对不同作业是可重入的，但禁止对同一作业实例进行并行多次调用 [SWS_Csm_00016]、[SWS_CryIf_91003]。诸如 Csm_KeyElementCopy()、CryIf_KeyElementCopy() 或 Crypto_KeyCopy() 等密钥管理功能实现为可重入的，但不得并发应用于同一源密钥标识符（keyId 或 cryptoKeyId），以避免数据不一致和竞态条件 [SWS_Csm_00969]、[SWS_CryIf_91015]、[SWS_Crypto_00155]。硬件驱动程序可以使用内部互斥区域（Exclusive Areas）来修改内部工作区和密钥寄存器，以拦截 ISR 与任务级别之间的竞态条件 SWS_CryptoDriver 第27页。

4. 典型生命周期与运行模式

加密集群的初始化在 BSW 启动期间按分层顺序进行。首先，EcuM 或 BswM 通过传递配置 Crypto_ConfigType 经由 Crypto_Init() 初始化驱动程序级 [SWS_Crypto_91016]，随后通过带有 CryIf_ConfigType 的 CryIf_Init() 初始化接口层 [SWS_CryIf_91118]。最后，通过 Csm_Init() 启动 CSM，其中根据规范，其配置指针必须始终设置为 NULL_PTR [SWS_Csm_00646]。只有在所有层完全初始化后，才允许接受加密作业或密钥访问 [SWS_CryIf_00076]、[SWS_Crypto_00196]。

密钥生命周期的一个核心方面是非易失性存储器（NVM）中的验证与持久化。在通过 Csm_KeyElementSet() 加载新密钥值后，密钥保持在“不完整或未知”状态 [SWS_Csm_00957]。只有显式调用 Csm_JobKeySetValid() 或 Crypto_KeySetValid() 才会检查一致性并将密钥状态切换为有效 [SWS_Csm_91027]、[SWS_Crypto_91014]。对于持久化密钥，仅此验证会触发在 NVM 中的存储 [SWS_Crypto_91026]、SWS_CryptoDriver 第37页。这可以防止多次零碎的 NVM 写入周期并防止出现不完整的密钥集 SWS_CryptoDriver 第37页。为了与 NVRAM Manager 同步，Crypto Driver 使用回调 Crypto_<vi>_<ai>_NvBlock_ReadFrom_<NvBlock>() 和 Crypto_<vi>_<ai>_NvBlock_WriteTo_<NvBlock>() 以及 NvM_WriteBlock() [SWS_Crypto_91024]、[SWS_Crypto_91025]、[SWS_Crypto_91017]。

正在运行的流作业在需要时可以通过 Csm_SaveContextJob() 中断，保存在应用程序专用的缓冲区中，并在稍后通过上下文恢复继续进行 [SWS_Csm_91063]、[SWS_Csm_01029]。在 ECU 关机或转换到低功耗模式之前，可以通过 Csm_CancelJob() 受控地中止异步作业，从而使 CryIf 通过 CryIf_CancelJob() 从驱动程序队列和硬件通道中移除作业 [SWS_Csm_00968]、[SWS_CryIf_91014]。

5. 错误处理、DET 跟踪与降级

该集群实现了多级错误检测与防御策略。在激活跟踪时，开发错误会直接报告给 Default Error Tracer（DET）模块 [SWS_Csm_91101]、[SWS_Crypto_91017]。典型的 DET 事件包括初始化之前的模块调用（CRYIF_E_UNINIT、CRYPTO_E_UNINIT）、无效的句柄或密钥参数（CRYIF_E_PARAM_HANDLE、CRYPTO_E_PARAM_HANDLE）以及空指针传递 [SWS_CryIf_00076]、[SWS_CryIf_00134]、[SWS_Crypto_00196]、[SWS_Crypto_00217]。

运行时过载和资源瓶颈通过定义的返回值进行确定性拦截。如果用于异步作业的 CSM 队列已耗尽，CSM 将以状态代码 CRYPTO_E_BUSY 拒绝该作业，并生成运行时错误 CSM_E_QUEUE_FULL [SWS_Csm_00018]、[SWS_Csm_01089]。如果提供的结果缓冲区尺寸不足，驱动程序将以 CRYPTO_E_SMALL_BUFFER 中止操作 [SWS_Crypto_00195]。如果加密服务引用了未初始化或显式失效的密钥（例如在调用 Csm_JobKeySetInvalid() 或 Crypto_KeySetInvalid() 之后），服务请求将受控地失败并返回 CRYPTO_E_KEY_NOT_VALID 或 CRYPTO_E_KEY_EMPTY [SWS_Csm_91002]、[SWS_CryIf_91003]、[SWS_Crypto_91020]。

降级和回退机制在系统级得以实现：应用程序可以在提交作业前通过 Csm_KeyGetStatus() 检查密钥的完整性状态 [SWS_Csm_91047]、[SWS_CryIf_91012]。如果硬件加密加速器被永久占用或发生故障，只要集成了冗余的软件驱动程序，CryIf 通道配置就允许采用基于软件的替代路由 SWS_CryptoDriver 第15页。
