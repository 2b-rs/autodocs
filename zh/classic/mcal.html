系统架构 & 模块集群的角色

“Microcontroller Abstraction”集群构成了 Classic Platform 的最底层软件层。ADC 和 PWM 驱动的规范明确指出，这些模块位于最底层架构级别，因此不向更低层提供回调（SWS ADC 第79页，SWS PWM 第40页）。它们的用户是 ECU 抽象和系统服务模块，尤其是 IoHwAb、WdgIf/WdgM 以及 EcuM 或 BswM。对于 R20-11，有效载荷的 Requirements 具有规范性。较新 Release 中的文档出处在此仅用于说明，例如 IoHwAb 的 ADC 示例（IoHwAb 第55页）。

  • Adc 按组转换模拟通道。转换由软件或硬件触发（[SWS_Adc_00514]）。结果存放在由用户提供的缓冲区中（[SWS_Adc_91000]）。
  • Pwm 生成具有周期和占空比的脉冲宽度调制信号（[SWS_Pwm_91001]）。它可以选择性地报告信号沿（[SWS_Pwm_00109]）。
  • Wdg 通过触发条件服务内部或外部硬件看门狗（[SWS_Wdg_00144]）。
  • Spi 和 Dio 在有效载荷中被证明是外部看门狗的访问路径（[SWS_Wdg_00076]）。该有效载荷不包含这两个模块自身的 SWS Requirements。
  • Port 通过 Port_Init 作为“Initializes the Port Driver module”记录在 EcuM 接口列表中（SWS EcuM 第142页）。一张图表将“Port Logic”定位于 PWM 单元和引脚之间（RS PWM 第14页）。

  2. Adc_StartGroupConversion 会重置内部缓冲区指针。此时 Notification 不会自动激活（[SWS_Adc_00367]，SWS ADC 第57页）。
  3. 每次完成组转换后，驱动都会调用 IoHwAb_AdcNotification<#groupID>（[SWS_Adc_00082]）。
  4. 用户可以通过以下两种途径之一读取结果：
    • Adc_ReadGroup 复制结果（[SWS_Adc_00369]）。
    • Adc_GetStreamLastPointer 返回指向缓冲区的指针（[SWS_Adc_00375]）。

缓冲区容纳多少个结果取决于访问模式：Single 还是 Streaming（[SWS_Adc_00528]）。在 Streaming 模式下，缓冲区呈线性或循环组织（[SWS_Adc_00519]）。

PWM 控制路径。用户通过两个服务设置信号：

  • Pwm_SetDutyCycle 仅更改占空比（[SWS_Pwm_91000]）。
  • Pwm_SetPeriodAndDuty 更改周期和占空比（[SWS_Pwm_91001]）。周期只能在类别为 PWM_VARIABLE_PERIOD 的通道上更改（[SWS_Pwm_00110]）；否则驱动会报告 PWM_E_PERIOD_UNCHANGEABLE（[SWS_Pwm_40002]）。

沿通知通过 Pwm_Notification_<#Channel> 送达用户。以 Pwm_EnableNotification 或 Pwm_DisableNotification 的最后一次调用为准（[SWS_Pwm_00105]，[SWS_Pwm_91004]）。Pwm_GetOutputState 读取输出信号的内部状态（[SWS_Pwm_00100]）。根据图表，这是在端口逻辑之前的抽头，而不是引脚处的电平（RS PWM 第14页）。

Watchdog 路径。调用链跨越三个层级：

  • WdgM 通过 WdgIf_SetMode 和 WdgIf_SetTriggerCondition 控制驱动（SWS WdgM 第86页）。
  • WdgIf 通过 DeviceIndex 将这些服务映射到相应的驱动实例（SWS WdgIf 第17页）。
  • Wdg 将超时时间从毫秒换算为计数值，并在此过程中考虑当前模式（[SWS_Wdg_00138]，[SWS_Wdg_00139]）。

内部看门狗与外部看门狗仅在硬件访问方式上有所不同：

  • 内部驱动直接访问硬件（[SWS_Wdg_00161]）。
  • 外部驱动使用 Spi 或 Dio，并在其配置中包含所需的参数（[SWS_Wdg_00076]，[SWS_Wdg_00078]）。
  • 两种变体的 API 在语义上完全相同（[SWS_Wdg_00077]）。
  • 如果存在多个实例，则会展开 API 名称（[SWS_Wdg_00172]）。

同步、重入性与任务上下文

各模块在可重入性承诺方面存在显著差异：

  • ADC 的数据路径 API 是可重入的。
  • 基于通道的 PWM 服务仅针对不同通道可重入。
  • 初始化、Power-State API 以及所有 Wdg 服务均不可重入。

生命周期与运行模式

初始化。EcuM 调用 Adc_Init（[SWS_Adc_00365]，SWS ADC 第91页）。EcuM 的结构描述还提到了 Port_Init、Pwm_Init、Spi_Init 和 Wdg_Init（SWS EcuM 第34页）。由 BswM 控制的变体按 Port、Dio、Adc、Spi 的顺序进行初始化（Modemanagement 第54页）。解读：Port 大概排在最前面，因为引脚配置是其余外设驱动的前提条件。

ADC。驱动通过 Adc_Init 从 ADC_UNINIT 转换到 ADC_INIT，并通过 Adc_DeInit 转换回来（SWS ADC 第31页）。每个组都会经历状态 ADC_IDLE、ADC_BUSY、ADC_COMPLETED 和 ADC_STREAM_COMPLETED（[SWS_Adc_00513]）。Continuous 模式仅在软件触发时可用（[SWS_Adc_00515]）。Adc_DeInit 将硬件置于类似复位的状态（[SWS_Adc_00366]）。仅当所有组都处于 ADC_IDLE 时才允许调用它（SWS ADC 第59页）。

PWM。在 Pwm_Init 之后，输出根据配置为 Low、High 或调制。在调用 Pwm_EnableNotification 之前，Notification 保持关闭（[SWS_Pwm_00095]，SWS PWM 第46页）。Pwm_DeInit 将输出设置为 Idle 状态并禁用中断（[SWS_Pwm_00096]，SWS PWM 第27页）。

Watchdog。Wdg_Init 设置默认模式和初始超时时间（[SWS_Wdg_00001]，[SWS_Wdg_00100]）。此后可选择模式 WDGIF_OFF_MODE、WDGIF_SLOW_MODE 和 WDGIF_FAST_MODE（[SWS_Wdg_00160]）。不存在 DeInit 函数。如果允许，则通过 OFF 模式进行关闭（[SWS_Wdg_00031]）。

Adc 和 Pwm 的 Power-State。转换分两个阶段进行：

  1. *_PreparePowerState 发起转换（[SWS_Adc_00478]，[SWS_Pwm_00183]）。
  2. 在异步情况下，Main 函数完成该转换并通过 IoHwAb_*_NotifyReadyForPowerState<#Mode> 报告就绪状态（[SWS_Adc_00480]，[SWS_Pwm_00198]）。
  3. *_SetPowerState 执行切换（[SWS_Adc_00475]，[SWS_Pwm_00166]）。

在此之前，负责的 SWC（例如 IoHwAb）必须将通道设置为 Idle 并取消注册 Notification（SWS PWM 第36页）。在转换本身期间，仅允许进行特定于转换的重新配置（[SWS_Adc_00484]）。

时序图：在 BswM 模式切换之后，IoHwAb 协调 Adc 和 Pwm 的两阶段 Power-State 切换，可以通过 Ready 回调异步进行，也可以通过轮询同步进行。来源：IoHwAb 第57页、IoHwAb 第58页、[SWS_Adc_00501]、[SWS_Pwm_00190]

错误处理、DET 跟踪与降级

开发错误（DET）。所有三个已指定的驱动都通过 Det_ReportError 报告它们（[SWS_Adc_00377]，[SWS_Pwm_00104]，[SWS_Wdg_00111]）：

  • Adc 报告 ADC_E_UNINIT 和 ADC_E_PARAM_GROUP 等（[SWS_Adc_91005]）。
  • Pwm 报告 PWM_E_UNINIT 和 PWM_E_PARAM_CHANNEL（[SWS_Pwm_20002]，[SWS_Pwm_30002]）。
  • Wdg 在状态不正确时报告 WDG_E_DRIVER_STATE（[SWS_Wdg_00017]，[SWS_Wdg_00035]）。

运行时错误。这里有几种情况：

  • ADC 在无队列转换已在运行等情况下报告 ADC_E_BUSY（[SWS_Adc_91006]，SWS ADC 第95页）。
  • 如果在 Power-State 切换期间仍有通道处于活动状态，则两个驱动都会报告 *_E_NOT_DISENGAGED（[SWS_Adc_00487]，[SWS_Pwm_00202]）。
  • 在 R20-11 中，ADC 将无法达到的目标电源状态归类为运行时错误（[SWS_Adc_00489]），而 PWM 则将其归类为 DET 错误（[SWS_Pwm_00175]）。

生产错误（DEM）。在 Payload 中，这些仅针对 Wdg 进行了定义，并通过 Dem_SetEventStatus 上报（[SWS_Wdg_00111]）：

  • 模式切换失败时的 WDG_E_MODE_FAILED；此时 Wdg_SetMode 返回 E_NOT_OK（[SWS_Wdg_00016]、[SWS_Wdg_00180]）。
  • 当不允许关闭时的 WDG_E_DISABLE_REJECTED（[SWS_Wdg_00025]、[SWS_Wdg_00182]）。

降级与安全状态。

  • Pwm_SetOutputToIdle 会立即将输出设置为配置的空闲状态（[SWS_Pwm_91002]、SWS PWM 第31页）。
  • 在初始化之前或通道无效时，Pwm_GetOutputState 会防御性地返回 PWM_LOW（[SWS_Pwm_30051]）。
  • 对于看门狗而言，复位是最后的后备机制。超时时间为 0 会触发近乎即时的 ECU 复位（[SWS_Wdg_00140]）。已到期的触发计数器会导致看门狗超时（[SWS_Wdg_00135]）。
  • 驱动程序会使用 WDG_E_PARAM_TIMEOUT 拒绝过大的超时时间（[SWS_Wdg_00146]）。
  • 在 ADC 中，带有 Abort/Restart 或 Suspend/Resume 的优先级机制用于控制如何继续执行被抢占的组（[SWS_Adc_00522]、[SWS_Adc_00523]）。限值检查会过滤掉超出所选范围的结果（[SWS_Adc_00524]）。
