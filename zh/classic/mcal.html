提供底层驱动，用于直接封装和控制微控制器外设与内部寄存器。

Microcontroller Abstraction（MCAL）模块集群包含驱动Port、Dio、Adc、Pwm、Spi和Wdg，用于对片上外设进行底层封装与控制（SWS_ECUStateManager 第34页）。核心任务包括外设访问前的引脚配置、模拟与脉冲调制信号管理以及受时间监控的执行控制（[SWS_Adc_00507]、[SWS_Wdg_00155]）。在此过程中，核心模式和电源状态切换必须严格按顺序且不可重入地执行（[SWS_Wdg_00107]）。

Microcontroller Abstraction（MCAL）模块集群封装微控制器的物理片上资源，并为I/O硬件抽象（IoHwAb）、看门狗接口（WdgIf）以及EcuM和BswM提供标准化接口（SWS_ECUStateManager 第34页）。它包含六个驱动构件：Port（引脚复用）、Dio（数字量输入/输出）、Adc（模数转换）、Pwm（脉冲宽度调制）、Spi（串行外设通信）和Wdg（硬件执行监控）（[SWS_Adc_00507]、[SWS_Pwm_00197]、[SWS_Wdg_00155]）。

这些模块在固定依赖关系下运行：Port_Init在驱动（如Pwm或Adc）激活相应硬件块之前配置引脚分配（AUTOSAR_CP_RS_PWMDriver 第14页、ModemanagementGuide 第54页）。数据缓冲区由应用程序端通过Adc_SetupResultBuffer提供（[SWS_Adc_91000]），而看门狗服务则通过定时器中断异步解耦（AUTOSAR_SWS_WatchdogDriver 第31页）。

虽然针对不相交实例的通道和组相关驱动调用是可重入的（[SWS_Pwm_91000]、[SWS_Adc_00367]），但模式和状态切换需要严格同步且不可重入的路径（[SWS_Wdg_00107]）。为了降低能耗，Adc和Pwm执行两阶段电源状态迁移，并向IoHwAb发出异步就绪报告（[SWS_Adc_00478]、[SWS_Pwm_00183]、AUTOSAR_CP_SWS_IOHardwareAbstraction 第57页）。

系统架构 & 模块集群的角色

微控制器抽象层（Microcontroller Abstraction Layer，MCAL）模块群构成了 AUTOSAR Classic Platform 最贴近硬件的基础。它封装了片上外设单元的寄存器访问，并为上层提供标准化且独立于微控制器的接口。在分层架构内部，这些驱动程序为 I/O 硬件抽象（IoHwAb）、看门狗接口（WdgIf）以及中央系统服务（如 ECU State Manager（EcuM）和 Basic Software Mode Manager（BswM））提供服务（SWS_ECUStateManager 第34页）。

该模块群包含六个互补的驱动程序模块：Port 负责微控制器引脚的全局引脚配置和复用（AUTOSAR_CP_RS_PWMDriver 第14页）。Dio 实现快速的按位和按端口数字 I/O 访问，而 Spi 则封装了与板载外设模块的同步和异步串行总线通信。对于模拟和脉宽调制信号，Adc（[SWS_Adc_00507]）和 Pwm（[SWS_Pwm_00197]）提供先进的转换与调制服务。Wdg 控制基于硬件的时间监控，以保障程序流完整性（[SWS_Wdg_00155]）。

各模块之间的交互配合与交互路径

各模块在清晰定义的信号流和缓冲区流中运行。驱动程序 Port 预先初始化电气端口逻辑和复用，随后如 Pwm 或 Adc 等驱动程序控制所分配的外设块，而无需了解焊盘互连情况（AUTOSAR_CP_RS_PWMDriver 第14页）。当通过 [SWS_Pwm_00100] 读取内部逻辑状态时，Pwm_GetOutputState 读取的是 PWM 单元的寄存器状态，而非物理端口引脚（[SWS_Pwm_00108]、AUTOSAR_SWS_PWMDriver 第51页）。

在模拟路径中，上层 IoHwAb 请求测量并提供应用侧缓冲区（AUTOSAR_CP_SWS_IOHardwareAbstraction 第55页）。Adc_SetupResultBuffer 通过 [SWS_Adc_91000] 初始化指向调用者内存区域的内部指针（AUTOSAR_SWS_ADCDriver 第31页）。在通过软件（[SWS_Adc_00367]）或硬件触发（[SWS_Adc_91001]）启动转换后，原始数据被写入缓冲区。读取访问通过 [SWS_Adc_00369]（复制最新结果）同步进行，或通过 [SWS_Adc_00375] 经由 Adc_GetStreamLastPointer 进行（SWS_ADCDriver 第27页）。

看门狗路径将逻辑控制流与硬件服务（Servicing）解耦：WdgM 控制监控预算，并通过 WdgIf 使用 [SWS_Wdg_00155] 设置 Wdg_SetTriggerCondition 中的时间窗口（SWS_WatchdogDriver 第29页）。实际的硬件服务通过硬件定时器中断周期性执行（AUTOSAR_SWS_WatchdogDriver 第31页）。在此过程中，外部看门狗芯片在需要时通过 Dio 或 Spi 的驱动程序实例进行访问（[SWS_Wdg_00111]、AUTOSAR_SWS_WatchdogDriver 第11页）。

时序图：在周期性触发延长和模式切换过程中 WdgM、WdgIf 和 Wdg 的相互协作。来源：AUTOSAR_SWS_WatchdogDriver 第31页、AUTOSAR_SWS_WatchdogDriver 第34页、[SWS_Wdg_00155]、[SWS_Wdg_00107]。

同步、重入性与任务上下文

MCAL 驱动程序遵循差异化的重入规则。在模块 Pwm 中，控制函数如 Pwm_SetDutyCycle（[SWS_Pwm_91000]）、Pwm_SetPeriodAndDuty（[SWS_Pwm_91001]）和 Pwm_SetOutputToIdle（[SWS_Pwm_91002]）对于不同通道是可重入的，但对于同一通道不得并发调用（AUTOSAR_CP_SWS_PWMDriver 第46页）。在模块 Adc 中，控制和读取 API 如 Adc_StartGroupConversion（[SWS_Adc_00367]）、Adc_StopGroupConversion（[SWS_Adc_00368]）和 Adc_ReadGroup（[SWS_Adc_00369]）对于不同通道组是可重入的。

相比之下，核心配置和模式 API 被严格设计为不可重入。这适用于 Wdg_SetMode（[SWS_Wdg_00107]）、Wdg_SetTriggerCondition（[SWS_Wdg_00155]）以及所有驱动程序的初始化和反初始化例程（[SWS_Adc_00366]、[SWS_Pwm_00096]）。来自不同 OS 任务的并发调用必须通过 SchM 独占区进行保护（AUTOSAR_SWS_WatchdogDriver 第11页）。

事件通知（例如沿变化或转换结束）在中断上下文（ISR）中通过可配置的回调（如 Pwm_Notification_<#Channel>（[SWS_Pwm_00105]）或 Adc_Notification_Group_<x>（[SWS_Adc_91003]））触发。在激活通知时，挂起的中断标志会被复位（[SWS_Pwm_91004]）。如果多个 ADC 组争用转换器资源，则根据配置采用硬件优先级排序或软件排队（[SWS_Adc_00522]），并具有可配置的中止/重启（Abort/Restart）或挂起/恢复（Suspend/Resume）机制（[SWS_Adc_00523]、SWS_ADCDriver 第97页）。

典型的生命周期和操作模式

MCAL 驱动程序的生命周期在整个系统的启动阶段开始，受 EcuM 控制（SWS_ECUStateManager 第34页）。通过 BswM 规则强制执行确定性顺序：首先由 Port_Init 初始化引脚功能（ModemanagementGuide 第54页）。只有在此之后，外设驱动程序如 Dio_Init、Spi_Init、Adc_Init（[SWS_Adc_00365]）、Pwm_Init（[SWS_Pwm_00095]）和 Wdg_Init（[SWS_Wdg_00106]、AUTOSAR_CP_SWS_PWMDriver 第47页）才会依次跟进。

在运行期间，Wdg 具有三种静态模式：WDGIF_OFF_MODE、WDGIF_SLOW_MODE 和 WDGIF_FAST_MODE（[SWS_Wdg_00107]）。模块 Adc 区分单次转换和连续转换（[SWS_Adc_00515]），以及单次和流式访问模式（[SWS_Adc_00528]、[SWS_Adc_00519]）。在此期间，组状态会历经 ADC_IDLE、ADC_BUSY、ADC_COMPLETED 和 ADC_STREAM_COMPLETED 状态（[SWS_Adc_00513]、[SWS_Adc_00374]、SWS_ADCDriver 第37页）。

对于低功耗模式（Low Power），Adc 和 Pwm 实现了标准化的两阶段电源状态协议：首先由 Adc_PreparePowerState（[SWS_Adc_00478]）和 Pwm_PreparePowerState（[SWS_Pwm_00183]）准备转换（[SWS_Pwm_00165]、[SWS_Adc_00527]）。异步完成后，硬件抽象通过如 IoHwAb_Adc_NotifyReadyForPowerState<#Mode>（[SWS_Adc_00480]）等回调报告就绪状态。最后，Adc_SetPowerState（[SWS_Adc_00475]）和 Pwm_SetPowerState（[SWS_Pwm_00166]）将硬件切换到目标状态（AUTOSAR_CP_SWS_IOHardwareAbstraction 第57页）。任务中的周期性监控由 Pwm_Main_PowerTransitionManager 确保（[SWS_Pwm_00189]、[SWS_Pwm_00190]）。

在系统关闭或复位时，反初始化服务如 Adc_DeInit（[SWS_Adc_00366]、AUTOSAR_SWS_ADC_Driver 第76页）和 Pwm_DeInit（[SWS_Pwm_00096]、AUTOSAR_SWS_PWMDriver 第47页）将单元转换为安全休眠状态并禁用所有中断。

错误处理、DET 跟踪与降级

错误严格划分为开发错误和生产错误。在开发检查处于活动状态时，驱动程序会将初始化完成前的调用报告给 Default Error Tracer（DET），例如通过 PWM_E_UNINIT（[SWS_Pwm_00177]、[SWS_Pwm_00104]）或 ADC_E_UNINIT（[SWS_Adc_00476]）。指针参数会被检查是否为 NULL，例如在 GetVersionInfo 中通过 ADC_E_PARAM_POINTER（[SWS_Adc_00376]）和 WDG_E_PARAM_POINTER（[SWS_Wdg_00109]）。

运行时错误用于防范非法的操作转换：如果在通道不处于 IDLE 状态或仍有活动通知存在时调用 Pwm_SetPowerState，驱动程序会报告运行时错误 PWM_E_NOT_DISENGAGED（[SWS_Pwm_00202]）。在 Adc 中，在无排队配置下尝试重新触发已被占用的通道组会导致向 DET 报告运行时消息 ADC_E_BUSY（SWS_ADCDriver 第95页）。

严重的生产错误和外设故障通过 Dem_SetEventStatus 报告给 Diagnostic Event Manager（DEM）（[SWS_Wdg_00111]）。为了在应急运行模式下进行降级，Pwm_SetOutputToIdle 提供了单个 PWM 输出的立即停用功能（[SWS_Pwm_91002]）。在看门狗驱动程序中，将触发超时值设置为 0 允许立即停止服务，并强制进行及时的 ECU 复位（[SWS_Wdg_00155]、[SWS_Wdg_00136]、SWS_WatchdogDriver 第29页）。
