系统架构与模块集群定位

在 AUTOSAR Classic Platform 架构中，通信服务（Communication Services）集群占据服务层（Services Layer）的核心位置，由通信管理器（ComM）、通信模块（Com）和协议数据单元路由器（PduR）三大核心模块共同构成，向下对接通信硬件抽象层与传输协议，向上为运行时环境（RTE）、应用软件组件（SW-C）、诊断通信管理器（DCM）以及基础软件模式管理器（BswM）提供标准化、总线无关的通信服务接口 SWS_PDURouter 第24页。

ComM 作为总线管理协调者，负责简化通信资源管理并控制通信通道的可用性。它将用户（如 SW-C、BswM、DCM）的通信需求聚合后映射至物理通道或部分网络（PNC），并通过统一的接口调度总线状态管理器（BusSM）与网络管理（Nm）模块 [SWS_ComM_00867]、[SWS_ComM_00110]。Com 模块面向信号，负责信号与信号组（Signal Groups）在 I-PDU（交互层协议数据单元）中的打包、解包、大小端转换、符号扩展、滤波以及基于发送模式和周期因子的传输调度，并实现发送与接收截止期限监控（Deadline Monitoring） [SWS_Com_00197]、[SWS_Com_00784]。PduR 作为协议不可知的中枢路由引擎，在无修改的前提下将 I-PDU 在上层模块（如 Com、DCM）与底层接口（如 CanIf、LinIf、FrIf）或传输协议模块（如 CanTp）之间分发，同时支持多播分发（Fan-out）与网关（Gatewaying）互联 [SWS_PduR_00160]、[SWS_PduR_00161]。

集群内部的协同工作构成了 AUTOSAR 数据平面与控制平面的核心通路。控制平面上，当 SW-C 或 DCM 请求启动通信时，调用 [SWS_ComM_00110] 触发 ComM 进入完全通信状态，ComM 进而向相应总线的状态管理器请求完全通信模式 [SWS_ComM_00069]；同时，BswM 或相关控制流通过启用或禁用 PduR 路由路径组（Routing Path Groups）与 Com I-PDU 组，实现对特定报文收发通路的精细化通断控制 [SWS_PduR_00615]、[SWS_Com_91001]。

同步、可重入性与任务上下文

通信服务集群跨越了硬实时中断上下文与任务级调度周期，具有严格的重入性与线程安全要求。ComM 模块的模式请求接口 ComM_RequestComMode 和查询接口设计为可重入，允许不同的应用可运行实体（Runnable Entities）在多任务甚至多核环境中并发调用 [SWS_ComM_00110]、SWS_COMManager 第107页。与之对应，ComM 的管理配置与抑制控制 API（如 ComM_LimitECUToNoComMode、ComM_PreventWakeUp）由于涉及全局状态更新，被定义为不可重入服务 [SWS_ComM_00124]、[SWS_ComM_00156]。

PduR 的大部分数据路径转发接口（如 PduR_EnableRouting、PduR_GetConfigurationId）均具备可重入特性，保证多通道并发收发时互不干扰 [SWS_PduR_00615]、[SWS_PduR_00341]。取消传输服务 PduR_<User:Up>CancelTransmit 针对不同 PDU ID 可重入，但针对同一 PDU ID 则属于不可重入调用 [SWS_PduR_00769]。对于接收指示和发送确认回调，它们通常直接运行在底层中断服务例程（ISR）或驱动的轮询任务上下文中；为防止并发访问引起 I-PDU 缓存竞争，Com 与 PduR 内部广泛使用独占区（Exclusive Areas）以及多缓冲机制保障数据读写的一致性 SWS_RTE 第329页。

典型生命周期与运行模式

通信集群各模块在系统启动与关闭过程中遵循严谨的生命周期约束。系统上电后，EcuM 引导基础软件初始化。ComM 在初始化 ComM_Init 时必须依赖 NvM 已就绪以读取非易失性抑制参数及 PNC 映射配置，并将通道状态机置入默认初始状态 [SWS_ComM_00146]、[SWS_ComM_00793]。PduR 初始处于 PDUR_UNINIT 状态，此时所有路由功能被完全禁止；在调用 PduR_Init 完成静态路由表加载并清空所有传输缓冲区后，状态机迁移至 PDUR_ONLINE，正式具备转发能力 [SWS_PduR_00324]、[SWS_PduR_00328]、[SWS_PduR_00645]。

在运行阶段，ComM 通道状态机管理三大基础模式：无通信（COMM_NO_COMMUNICATION）、静默通信（COMM_SILENT_COMMUNICATION）和完全通信（COMM_FULL_COMMUNICATION） [SWS_ComM_00867]。当处于无通信子状态 COMM_NO_COM_NO_PENDING_REQUEST 时，若收到用户通信请求或 DCM 激活诊断通知，状态机立即切换至 COMM_NO_COM_REQUEST_PENDING，并在底层允许通信标志置位后跳转至 COMM_FULL_COM_NETWORK_REQUESTED，开启通道收发能力并启动运行定时器 [SWS_ComM_00875]、[SWS_ComM_00895]、[SWS_ComM_00886]。在所有通信用户释放请求后，状态机转入 COMM_FULL_COM_READY_SLEEP，通知网络管理释放网络并等待静默与总线睡眠转换 [SWS_ComM_00133]、[SWS_ComM_00071]。系统休眠或关机前，只有在所有通道均处于 COMM_NO_COMMUNICATION 模式且无挂起请求时，才允许执行 ComM_DeInit 将运行时参数回写至 NVRAM [SWS_ComM_00147]、[SWS_ComM_00794]、[SWS_ComM_00865]。
