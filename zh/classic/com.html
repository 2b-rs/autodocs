“Communication Services”模块集群构成了服务层内 AUTOSAR Classic Platform（版本 R20-11）通信栈的功能中心。它由三个紧密协作的基础软件模块 com（AUTOSAR COM）、comm（Communication Manager）和 pdur（PDU Router）组成。根据 AUTOSAR 分层架构，这些模块共同向运行时环境（RTE）和应用软件组件（SW-C）封装了 ECU 网络的独立于总线的管理、交换和信号抽象 SWS_PDURouter 第24页。该集群向下直接与通信硬件抽象层接口（CanIf、LinIf、FrIf、EthIf）以及基于 ISO 11898（CAN）、ISO 17987（LIN）、ISO 10681（FlexRay）和 ISO 15765-2（传输层）等标准的传输协议（CanTp、FrTp、LinTp）进行交互 AUTOSAR_CP_SWS_PDURouter 第110页。

集群内的交互通过用于发送、接收和确认路径的明确定义的调用链进行。在发送时，RTE 调用 com 的模块特定发送 API（例如 Com_SendSignal 或 Com_SendSignalGroup）以原子方式提供数据 [SWS_Com_00197]、[SWS_Com_00200]。模块 com 将信号打包到关联的 I-PDU 中，并通过 PduR_ComTransmit 同步传递给 PDU Router [SWS_PduR_00406]。PDU Router 在其静态路由表中查找目标 I-PDU，转换 I-PDU-ID，并将发送请求不作修改地传递至负责的下层，例如通过 CanIf_Transmit [SWS_PduR_00161]、[SWS_PduR_00766]。在总线上成功发送后，接口通过 PduR_<User:Lo>TxConfirmation 向 pdur 确认传输 [SWS_PduR_00365]，后者将调用转发给 Com_TxConfirmation [SWS_Com_00124]。

对于时间触发或基于轮询的总线系统（如 LIN 或 FlexRay），协议栈通过 TriggerTransmit 机制对发送请求进行解耦：模块 com 初始化发送就绪状态，但将有效负载数据存储在内部 AUTOSAR_CP_SWS_PDURouter 第101页。一旦总线调度器（例如在 LinIf 或 FrIf 中）到达发送时间点，底层就会调用 PduR_<User:Lo>TriggerTransmit [SWS_PduR_00430]。PDU Router 会立即且无缓冲地将此调用转发给 Com_TriggerTransmit [SWS_Com_00001]，随后 com 将最新数据直接复制到驱动程序缓冲区中 SWS_PDURouter 第107页。

在接收路径中，底层通信接口通过 PduR_<User:Lo>RxIndication [SWS_PduR_00362] 指示 I-PDU 的到达。PDU Router 通过 Com_RxIndication 将 PDU 同步转发至 com [SWS_Com_00123]，在此处对信号进行解包、过滤并提供给 RTE AUTOSAR_CP_SWS_PDURouter 第97页。与此同时，pdur 支持网关路由功能：接收到的 I-PDU 可以同时在本地递送至 com，并并行转发至外向网络接口 [SWS_PduR_00621], SWS_PDURouter 第114页。对于传输协议 PDU（例如 CanTp 或 DCM），pdur 负责编排经由 StartOfReception、CopyRxData 和 TpRxIndication 的分段传输 [SWS_PduR_00507], [SWS_Com_00691], [SWS_Com_00692]。

同步、重入性与任务上下文

该集群的模块运行在由同步函数调用和周期性任务处理组成的混合执行上下文中。接收回调（RxIndication）和发送传输确认（TxConfirmation）通常在底层驱动程序的中断上下文或通信接口的任务上下文中触发。因此，PDU Router 的路由转发函数被严格设计为可重入的 SWS_PDURouter 第88页。通过 PduR_<User:Up>CancelTransmit 中止正在进行的传输对于不同的 PDU-ID 是可重入的，但对于相同的 PDU-ID 则被规范为不可重入 [SWS_PduR_00769]。

在模块 comm 中，主用户接口 ComM_RequestComMode 显式设计用于支持多个 Runnable 的并发调用（canbeInvokedConcurrently = TRUE），并实现为可重入的 [SWS_ComM_00110], SWS_COMManager 第107页。诸如 ComM_GetRequestedComMode [SWS_ComM_00079] 和 ComM_GetMaxComMode [SWS_ComM_00085] 等状态查询也是可重入的。相比之下，管理类函数（如 ComM_SetECUGroupClassification [SWS_ComM_00552]、ComM_GetInhibitionStatus [SWS_ComM_00619]）以及动态分配 API（例如 ComM_UpdatePncToChannelMapping [SWS_ComM_01037]）则被定义为不可重入，并要求从受保护的任务级别进行调用。

为了防止多次信号访问时出现数据不一致，AUTOSAR 规定复合数据类型必须通过信号组进行原子化信号处理 [SWS_Com_00197], [SWS_Com_00200]。RTE 分解信号并将其一致地序列化到本地影子缓冲区中，然后 Com_SendSignalGroup 释放该 I-PDU SWS_RTE 第329页。周期性发送活动和超时监控通过模块的周期性 MainFunctions 进行处理，其中 I-PDU 组由 BswM 根据需求通过 Com_IpduGroupStart 和 Com_IpduGroupStop 进行激活或停止 [SWS_Com_00784], SWS_BSWModeManager 第93页。

典型的生命周期和操作模式

模块集群的生命周期遵循严格的初始化和运行顺序。在启动时，PDU Router 最初处于状态 PDUR_UNINIT，在此状态下不允许进行任何路由 [SWS_PduR_00325], [SWS_PduR_00330]。通过调用 PduR_Init，所有内部缓冲区被分配并初始化，模块切换到状态 PDUR_ONLINE [SWS_PduR_00308], [SWS_PduR_00742]。模块 comm 同样在状态 COMM_UNINIT [SWS_ComM_00668] 下启动。通过 ComM_Init 从 NVRAM 读取持久化参数（例如禁止计数器和 PNC 映射），并将通道状态机转换到默认状态 COMM_NO_COM_NO_PENDING_REQUEST [SWS_ComM_00146], [SWS_ComM_00674]。

comm 中的通道状态机控制三种上级通信模式：COMM_NO_COMMUNICATION、COMM_SILENT_COMMUNICATION 和 COMM_FULL_COMMUNICATION [SWS_ComM_00871]。用户只能请求完全通信或无通信 [SWS_ComM_00110]。如果在 COMM_NO_COM_NO_PENDING_REQUEST 中接收到来自用户或 DCM 的请求（ComM_DCM_ActiveDiagnostic），状态机将切换到 COMM_NO_COM_REQUEST_PENDING [SWS_ComM_00873]。一旦获得通信许可，就会转换到 COMM_FULL_COM_NETWORK_REQUESTED，随后 comm 通过相应的 Bus State Manager 请求发送和接收就绪状态 [SWS_ComM_01018], SWS_COMManager 第64页。

如果所有用户都释放了完全通信，通道将切换到 COMM_FULL_COM_READY_SLEEP，并在完全网络管理下请求 Nm_NetworkRelease SWS_COMManager 第78页。为准备 Bus-Sleep，状态机切换到 COMM_SILENT_COM，在此状态下发送被禁止，但接收仍保持激活以进行同步 [SWS_ComM_00391], [SWS_ComM_00829]。在收到 ComM_<Bus>SM_BusSleepMode 的报告时，再次达到 COMM_NO_COM_NO_PENDING_REQUEST [SWS_ComM_91000]。来自 EcuM 的唤醒通过 ComM_EcuM_WakeUpIndication 或 ComM_EcuM_PNCWakeUpIndication 进行处理 [SWS_ComM_91001]。只有当所有通道完全在 COMM_NO_COMMUNICATION 中去初始化后，才允许通过 ComM_DeInit 进行 ECU 关机 [SWS_ComM_00147]。

错误处理、DET 跟踪与降级

该集群的错误与降级管理依赖于向开发错误追踪器（DET）发送的标准化报告以及可配置的限制机制（Communication Inhibition）。如果启用了开发错误检测，pdur 将通过错误代码 PDUR_E_UNINIT 报告未初始化的调用 [SWS_PduR_00100], [SWS_PduR_00119]。控制调用中的错误路由表 ID 将被处以 PDUR_E_ROUTING_PATH_GROUP_ID_INVALID 报错 [SWS_PduR_00648]，而无效的指针参数则作为 PDUR_E_PARAM_POINTER 报告 SWS_PDURouter 第72页。在模块 comm 中，在初始化完成前调用监控 API 会导致返回状态 COMM_UNINIT [SWS_ComM_00242], [SWS_ComM_00668]。

为了实现受控降级和降低功耗，comm 提供了用于限制通信的接口：通过 ComM_LimitChannelToNoComMode 或 ComM_LimitECUToNoComMode 可以禁止单个通道或整个 ECU 转换到完全通信 [SWS_ComM_00124], [SWS_ComM_00163]。此外，ComM_PreventWakeUp 会抑制基于网络的 ECU 唤醒 [SWS_ComM_00156]。这些禁止权限通过屏蔽位进行控制（ComM_SetECUGroupClassification [SWS_ComM_00552]）。被拒绝的完全通信请求记录在非易失性错误存储器计数器中，该计数器可通过 ComM_ReadInhibitCounter 和 ComM_ResetInhibitCounter 进行诊断 [SWS_ComM_00108], [SWS_ComM_00224]。DCM 的诊断请求会临时覆写激活的通信限制，以确保 ECU 始终可达 [SWS_ComM_00873], SWS_COMManager 第69页。

在运行期间，PDU Router 中的通信路径可以动态降级或激活：BswM 通过 PduR_EnableRouting 和 PduR_DisableRouting 立即切换已配置的路由路径组 [SWS_PduR_00615], [SWS_PduR_00617], [SWS_PduR_00715]。如果某个路由路径被禁用，受影响 I-PDU 的发送和接收调用将立即以 E_NOT_OK 或 BUFREQ_E_NOT_OK 拒绝数据传输 SWS_PDURouter 第69页。对于 Post-Build 配置，pdur 通过 PduR_GetConfigurationId 监控配置完整性，以排除在 RAM 和 NVRAM 中表边界与缓冲区边界发生改变时出现错误分配的情况 [SWS_PduR_00341], [SWS_PduR_00771], SWS_PDURouter 第160页。
