代表 L 的标识符 - PDU。两个最高有效位指定帧类型： 00 CAN 标准消息 CAN ID 01 CAN FD 标准帧 CAN ID 10带有扩展 CAN 消息 CAN ID 11 CAN FD 带有扩展 CAN ID 的帧

Can_PduType 类型

系统架构与模块集群的角色

“CAN Communication”集群涵盖了 Classic Platform 中从控制器硬件到传输层的 CAN 栈。

  • Can (CAN Driver)：封装控制器硬件。它通过 Can_Write 将 L-PDU 写入硬件对象 [SWS_Can_00233]。在此过程中会传递一个由 swPduHandle、长度、数据和 CAN-ID 组成的 Can_PduType 结构 [SWS_Can_00415]。
  • CanIf (CAN Interface)：通过专用的 ControllerId 和 TransceiverId 对多个驱动程序实例进行抽象 [SWS_CANIF_00653] [SWS_CANIF_00655]。

上层既不访问驱动程序的接收缓冲区，也不访问 CanIf 的发送缓冲区 CanIf 第48页。CanIf 本身仅通过驱动程序的服务访问硬件缓冲区 [SWS_CANIF_00023]。

CAN 收发器驱动程序（CanTrcv）控制外部收发器芯片。对于每种硬件类型，所有同类收发器仅存在一个驱动程序实例 [SWS_CanTrcv_00016]。其通用状态模型将 ComM 和 EcuM 与芯片特有的状态解耦 CanTrcv 第19页。

只要 SWS 没有排除，CAN 传输层（CanTp）就遵循 ISO 15765-2 [SWS_CanTp_00033]。它对 N-SDU 进行分段和重组，并同时管理多个连接 [SWS_CanTp_00096]，例如并行处理一个 UDS 请求和一个 OBD 请求 CanTp 第41页。

CanIf 向上通过回调进行耦合，其目标通过配置确定 CanIf 第133页。典型目标包括：

  • PduR_CanIfRxIndication [SWS_CANIF_00442]
  • CanTp_RxIndication [SWS_CANIF_00448]
  • CanSM_ControllerBusOff [SWS_CANIF_00559]
  • EcuM_ValidateWakeupEvent [SWS_CANIF_00563]

协作与交互路径

发送路径：CanIf_Transmit [SWS_CANIF_00005] 使用属于 TxPduId 的 HTH 调用 Can_Write [SWS_CANIF_00318]。如果驱动程序返回 E_OK，CanIf 也会返回 E_OK [SWS_CANIF_00162]。

如果没有空闲的硬件对象，Can_Write 会报告 CAN_BUSY [SWS_Can_00039]。在激活缓冲时，CanIf 随后会将 L-PDU 存放在 CanIfTxBuffer 中 [SWS_CANIF_00381] CanIf 第138页。

在每次发送确认时，都会执行以下调用链：

  1. CanIf 检查已变为空闲的硬件对象的缓冲区 [SWS_CANIF_00386]。
  2. 它会根据 [SWS_CANIF_00668] 补发等待中具有最高优先级的 L-PDU [SWS_CANIF_00070]。
  3. 如果为 E_OK，它甚至在确认返回之前就将其从缓冲区中移除 [SWS_CANIF_00183]。
  4. 随后，CanIf 通过 <User_TxConfirmation> 通知用户 [SWS_CANIF_00383]。对于 PduR，该通知为 PduR_CanIfTxConfirmation [SWS_CANIF_00439]。

开发错误：所有模块都会将其报告给 DET。每个模块的错误代码均以表格列出：Can [SWS_Can_91019]、CanIf [SWS_CANIF_91006]、CanTp [SWS_CanTp_00293]、CanTrcv [SWS_CanTrcv_00050]。典型检查包括针对无效 ID 和指针的检查，例如在 CanIf_SetControllerMode [SWS_CANIF_00311] 或 CanIf_RxIndication [SWS_CANIF_00416] 中。在初始化之前，CanIf 服务会以 E_NOT_OK [SWS_CANIF_00661] 拒绝正常运行；在这种情况下，CanTp 会报告 CANTP_E_UNINIT [SWS_CanTp_00031]。
