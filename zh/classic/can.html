该 Cluster 将 CAN 驱动程序、CAN Interface、符合 ISO 15765-2 的传输协议以及收发器驱动程序连接为 CAN 通信栈的下半部分。上层通过 CanIf_Transmit() 发送。CanIf 将 L-PDU 映射到硬件对象，在硬件繁忙时对其进行缓冲，并分发接收和确认消息 [SWS_CANIF_00005]。CanTp 对大型报文进行分段，并通过 PduR 逐步获取数据 [SWS_CanTp_00086]。仅当控制器处于 CAN_CS_STARTED 状态且 PDU 通道处于就绪发送状态时才进行发送；模式由 CanSM 通过 CanIf 进行控制。

该 Cluster 构成 CAN 通信栈的下部。Can 控制控制器和邮箱，CanIf 抽象驱动程序、控制器和收发器，CanTp 按照 ISO 15765-2 进行分段，CanTrcv 管理收发器的运行模式。CanIf 仅通过驱动程序服务访问硬件缓冲区 [SWS_CANIF_00023]。它为上层提供统一的 ControllerId 和 TransceiverId 范围 [SWS_CANIF_00653] [SWS_CANIF_00655]。

发送时，CanIf_Transmit() 使用匹配的 HTH 调用 Can_Write() [SWS_CANIF_00318]。若驱动程序报告 CAN_BUSY，CanIf 会缓冲该 L-PDU [SWS_CANIF_00381]。在发送确认期间，它会补发具有最高优先级的缓冲条目 [SWS_CANIF_00668]。接收到的 L-PDU 在 CanIf 中经过软件过滤和数据长度检查后，再由 CanIf 转发给 CanTp 或 PduR [SWS_CANIF_00389] [SWS_CANIF_00390]。CanTp 本身不缓冲有效数据，而是通过 PduR_CanTpCopyTxData() 获取数据或通过 PduR_CanTpCopyRxData() 传递数据 [SWS_CanTp_00086] [SWS_CanTp_00269]。

在 CanIf_Transmit() 内部，模块首先校验控制器运行状态必须为 CAN_CS_STARTED 且 PDU 通道模式处于激活状态[SWS_CANIF_00317]。随后，CanIf 将目标 TxPduId 映射到具体的控制器与 HTH，并同步调用底层驱动的 Can_Write()SWS CANInterface 第42页。若硬件邮箱空闲，Can_Write() 返回 E_OK；若邮箱繁忙返回 CAN_BUSY，CanIf 会将待发 L-PDU 存入内部缓冲队列 CanIfTxBuffers 中[SWS_CANIF_00070]。一旦硬件释放并触发 CanIf_TxConfirmation() 回调，CanIf 会立即评估缓冲队列，按 CAN 标识符优先级取出最高优先级报文再次调用 Can_Write()，并在底层确认后调用上层确认服务 <User_TxConfirmation>(E_OK)[SWS_CANIF_00183][SWS_CANIF_00383][SWS_CANIF_00386]。对于动态 CAN ID 传输，CanIf_SetDynamicTxId() 允许运行时重构标识符，并在高位指定标准、扩展或 FD 帧格式[SWS_CANIF_00188][SWS_CANIF_00189]。

在接收数据流方向，当物理总线收到有效报文后，Can 驱动在中断或轮询上下文中调用 CanIf_RxIndication() 并传入对应的 HRH 邮箱信息与数据指针[SWS_CANIF_00006]。CanIf 依次执行硬件对象映射、BasicCAN/FullCAN 软件过滤以及数据长度检查（DLC Check）[SWS_CANIF_00389][SWS_CANIF_00467]。校验通过后，CanIf 依据配置将数据分发给目标模块：普通通信报文直达 PduR，网络管理报文分发至 CanNm，分段诊断报文则递交给 CanTp_RxIndication()[SWS_CANIF_00415][SWS_CanTp_00330]。若使能了接收缓冲 API，上层还可通过 CanIf_ReadRxPduData() 异步读取最新接收的数据[SWS_CANIF_00194][SWS_CANIF_00198]。

同步机制、可重入性与任务上下文

CAN 集群的运行涉及中断服务例程（ISR）与周期性调度任务（Task）的高度协同。驱动层支持中断与轮询双重处理模式：当配置为轮询或混合模式时，调度实体通过 Can_MainFunction_Write() 轮询发送确认，通过 Can_MainFunction_Read() 轮询接收指示，并通过 Can_MainFunction_BusOff() 和 Can_MainFunction_Wakeup() 轮询总线关闭与唤醒事件[SWS_Can_00031][SWS_Can_00108][SWS_Can_00109][SWS_Can_00112]。为保护外设临界区，Can_DisableControllerInterrupts() 与 Can_EnableControllerInterrupts() 提供了支持多重嵌套的递增式中断屏蔽与恢复机制[SWS_Can_00049][SWS_Can_00202]。

在传输层与收发器层，周期性调度实体负责核心定时机制与诊断监控。CanTp_MainFunction() 由调度管理器（SchM）周期性触发，专门监控 ISO 15765-2 规定的全套协议超时计时器（包括发送端 $N\_As$、$N\_Bs$、$N\_Cs$，接收端 $N\_Ar$、$N\_Br$、$N\_Cr$ 以及帧间最小间隔 $ST_{min}$）[SWS_CanTp_00164][SWS_CanTp_00213]。CanTrcv_MainFunctionDiagnostics() 则周期性读取物理收发器硬件状态，并在检测到总线错误时向诊断事件管理器（DEM）上报故障[SWS_CanTrcv_00204][SWS_CanTrcv_00206]。

在重入性规则方面，CanIf_Transmit() 与 CanTp_Transmit() 均支持针对不同 PDU ID 的可重入调用，但针对同一 PDU ID 为不可重入[SWS_CANIF_00005][SWS_CanTp_00212]。CanTp 内部通过独立的连接通道（Connection Channels）支持多路并发传输（例如同时处理物理寻址与功能寻址会话），各通道拥有专用的缓冲区、状态机和定时器资源[SWS_CanTp_00096][SWS_CanTp_00122]。此外，对于非重入的 CanIf_SetDynamicTxId()，协议要求其必须防范同报文并发 CanIf_Transmit() 调用带来的数据一致性风险[SWS_CANIF_00189][SWS_CANIF_00673]。

典型生命周期与运行模式管理

CAN 通信集群严格遵循 AUTOSAR 标准启动与关闭序列。在系统上电复位后，ECU 状态管理器（EcuM）依次调用 Can_Init()、CanTrcv_Init() 与 CanIf_Init()，初始化全局变量、缓冲区与状态标记[SWS_CANIF_00001][SWS_CANIF_00085]。初始化完成后，CAN 控制器默认停留在 CAN_CS_STOPPED 状态，禁止收发任何报文SWS CANInterface 第40页。与此同时，CanTp_Init() 使传输层从 CANTP_OFF 进入 CANTP_ON 运行态，并将所有通道复位为等待空闲状态（CANTP_RX_WAIT 与 CANTP_TX_WAIT）[SWS_CanTp_00027][SWS_CanTp_00030]。

系统运行期间的模式切换由 CanSM 全程协调。CanSM 经由 CanIf_SetControllerMode() 驱动底层 Can_SetControllerMode() 异步执行控制器状态机转换（CAN_CS_STOPPED、CAN_CS_STARTED、CAN_CS_SLEEP）[SWS_CANIF_00003][SWS_Can_00017][SWS_Can_00230]。每次控制器切换至 CAN_CS_STARTED，底层驱动均会重新应用预设波特率与控制器参数配置[SWS_Can_00384]。对于物理收发器，CanSM 通过 CanIf_SetTrcvMode() 驱动 CanTrcv_SetOpMode() 进入 CANTRCV_TRCVMODE_NORMAL、CANTRCV_TRCVMODE_STANDBY 或 CANTRCV_TRCVMODE_SLEEP 模式[SWS_CANIF_00287][SWS_CanTrcv_00102]。

除物理控制器状态外，CanIf 维护着独立的逻辑 PDU 通道状态（PduMode）：初始状态及进入 CAN_CS_SLEEP 时通道处于 CANIF_OFFLINE；控制器处于 CAN_CS_STOPPED 或发生 BusOff 时进入 CANIF_TX_OFFLINE，此时阻断所有发送请求并清空队列，但保留接收能力；在全功能通信时通道切换至 CANIF_ONLINE；此外支持仅模拟内部确认的 CANIF_TX_OFFLINE_ACTIVE 模式[SWS_CANIF_00137][SWS_CANIF_00485][SWS_CANIF_00489][SWS_CANIF_00864][SWS_CANIF_00865][SWS_CANIF_00866]。在休眠与唤醒流程中，集群通过 Can_CheckWakeup() 或 CanTrcv_GetBusWuReason() 捕获总线唤醒源，并经由 CanIf_CheckValidation() 完成唤醒验证闭环[SWS_CANIF_00178][SWS_Can_00361][SWS_CanTrcv_00107]。

故障处理、DET 追踪与降级策略

当 CAN 控制器因严重通信干扰导致发送错误计数超限（$TEC > 255$）触发 BusOff 时，硬件产生中断或由轮询函数捕获，驱动层立即调用 CanIf_ControllerBusOff() 指示接口层[SWS_CANIF_00218]。CanIf 随即执行降级防御：强制复位当前控制器的发送缓冲队列、将通道模式置为 CANIF_TX_OFFLINE 并调用 <User_ControllerBusOff> 转发至 CanSM，由 CanSM 依据总线恢复算法完成分阶段重启与通信复原[SWS_CANIF_00485][SWS_CANIF_00866]。在错误状态演进中，控制器状态细分为 CAN_ERRORSTATE_ACTIVE、CAN_ERRORSTATE_PASSIVE 与 CAN_ERRORSTATE_BUSOFF[SWS_Can_91003]；若使能了安全事件追踪，CanIf 还可通过 CanIf_ErrorNotification() 与 CanIf_ControllerErrorStatePassive() 解析错误细节并向入侵防御系统管理器（IdsM）报告安全事件[SWS_CANIF_91008][SWS_CANIF_91009][SWS_Can_91021]。

在局域网络管理（Partial Networking）与低功耗保护场景下，CanIf 提供了 PnTxFilter 发送过滤机制：当控制器进入休眠态时自动激活该过滤器，除特定配置的唤醒报文（CanIfTxPduPnFilterPdu）允许通过外，所有常规发送请求均被直接拦截并返回 E_NOT_OK，直到成功收到接收指示或发送确认后才解除过滤SWS CANInterface 第70页[SWS_CANIF_00747][SWS_CANIF_00749][SWS_CANIF_00750]。同时，针对支持选择性唤醒的物理收发器，CanSM 经由 CanIf_ClearTrcvWufFlag() 与 CanTrcv_ClearTrcvWufFlag() 异步清除唤醒标志，防止虚假唤醒事件残留[SWS_CANIF_00760][SWS_CanTrcv_00194]。

开发错误追踪（DET）与生产故障记录（DEM）在集群内紧密配合：集群各模块均对输入参数（如 ControllerId、TransceiverId、PDU 句柄和空指针）以及未初始化状态实施严格防御，触发时向 DET 上报规范化错误码（如 CANIF_E_PARAM_CONTROLLERID、CANTP_E_UNINIT、CANTRCV_E_UNINIT）[SWS_CANIF_00311][SWS_CanTp_00031][SWS_CanTrcv_00220]。收发器检测到的硬件总线故障则通过 Dem_SetEventStatus() 上报 CANTRCV_E_BUS_ERROR，实现软硬件全方位的故障容错与可维护性闭环[SWS_CanTrcv_00206]。
