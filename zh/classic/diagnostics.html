系统架构与模块集群的角色

“Diagnostic Services” Cluster 包含四个 BSW 模块，Classic Platform ECU 通过这些模块检测、存储错误，并将其报告给测试仪以及进行记录。DCM 接收符合 ISO 14229-2 会话层服务的诊断请求（SWS DCM 第57页）。各模块的角色为：

  • DCM (Diagnostic Communication Manager)：用于测试仪请求的服务器。它实现了符合 ISO 14229-1 的 UDS 服务，其中包括 0x19 ReadDTCInformation、0x14 ClearDiagnosticInformation 和 0x85 ControlDTCSetting（[SWS_Dcm_00248]、[SWS_Dcm_00247]、[SWS_Dcm_00249]）。在内部，它被划分为子模块 DSL、DSD 和 DSP（[SWS_Dcm_00111]、[SWS_Dcm_00221]）。
  • DEM (Diagnostic Event Manager)：通过 EventIds 管理诊断事件（[SWS_Dem_00153]），维护 UDS 状态位（[SWS_Dem_00006]）和主要错误内存（[SWS_Dem_00010]）。每个 ECU 恰好有一个 DEM（[SWS_Dem_00126]）。
  • DET (Default Error Tracer)：通过 Det_ReportError 和 Det_ReportRuntimeError 接收开发错误和运行时错误（[SWS_Det_00009]、[SWS_Det_01001]）。
  • Dlt (Diagnostic Log and Trace)：缓冲来自 BSW 和 SW-C 的 Log 与 Trace 消息（[SWS_Dlt_00003]），并通过 PduR_DltTransmit 进行传输（[SWS_Dlt_00762]）。

持久化和通信控制位于该 Cluster 之外。DEM 和 Dlt 通过 NvM 存储非易失性数据（[SWS_Dem_00164]、[SWS_Dlt_00453]）。DCM 从 ComM 接收通信模式（[SWS_Dcm_00356]）。

上下文图：DCM 和 DEM 构成通往测试仪的诊断路径，DET 和 Dlt 构成错误与日志记录路径；NvM、PduR 和 ComM 为外部伙伴。来源：[SWS_Dcm_00094]、[SWS_Dem_00183]、[SWS_Dem_00124]、[SWS_Dlt_00763]、[SWS_Dlt_00430]、[SWS_Dlt_00377]、[SWS_Dlt_00736]

协作与交互路径

主路径是 PduR 与 DCM 之间的请求-响应链（SWS DCM 第55页）。它分三步进行：

  • PduR 使用 Dcm_StartOfReception 报告开始接收（[SWS_Dcm_00094]）。
  • 它使用 Dcm_CopyRxData 复制各分段（[SWS_Dcm_00556]）。
  • 它使用 Dcm_TpRxIndication 完成接收（[SWS_Dcm_00093]）。

DSL 仅在 Dcm_TpRxIndication 之后才通过 E_OK 将数据传递给 DSD（[SWS_Dcm_00111]）。如果请求的长度大于 DCM 缓冲区，Dcm_StartOfReception 将返回 BUFREQ_E_OVFL。长度为 0 的请求将被以 BUFREQ_E_NOT_OK 拒绝（[SWS_Dcm_00444]、[SWS_Dcm_00642]）。

DSD 检查服务标识符、会话和安全级别（[SWS_Dcm_00196]、[SWS_Dcm_00211]、[SWS_Dcm_00217]）。随后它调用 DSP 的相应功能（[SWS_Dcm_00221]）。响应通过 DSD 和 DSL 发送给 PduR（[SWS_Dcm_00232]、[SWS_Dcm_00237]）。DSL 将确认 Dcm_TpTxConfirmation 传递给 DSD，DSD 通过 DspInternal_DcmConfirmation 将其报告给 DSP（[SWS_Dcm_00235]、[SWS_Dcm_00236]；SWS DCM 第479页）。

时序图：只有在成功指示接收后才会处理请求；响应和确认经由所有三个 DCM 子模块返回。来源：[SWS_Dcm_00094]、[SWS_Dcm_00556]、[SWS_Dcm_00111]、[SWS_Dcm_00236]、SWS DCM 第479页

错误内存服务的数据在 DCM 和 DEM 之间流动：

  • 过滤器与迭代：DCM 在每次通过 Dem_SetDTCFilter 读取之前都会设置一个过滤器，随后使用 Dem_GetNextFilteredDTC 进行迭代（[SWS_Dcm_00835]、[SWS_Dem_00215]）。每个新过滤器都会重置客户端的序列（[SWS_Dem_00649]）。
  • 状态掩码：可用性掩码由 Dem_GetDTCStatusAvailabilityMask 提供（[SWS_Dcm_00007]）。DEM 据此对其传递给 DCM 的所有状态字节进行掩码处理（[SWS_Dem_00657]）。
  • Freeze-Frames：DEM 已经按照 0x19 0x04 的响应布局提供它们（[SWS_Dem_00071]；SWS DEM 第225页）。
  • 一致性：在读取期间，DCM 锁定条目的更新（[SWS_Dcm_00371]）。Dem_EnableDTCRecordUpdate 重新将其释放（[SWS_Dem_00271]）。
  • OBD：DEM 为 DCM 提供专用接口，例如 Dem_DcmReadDataOfPID01（[SWS_Dem_00304]、[SWS_Dem_00318]）。

同步、重入性与任务上下文

Dcm_CopyRxData、Dcm_TpRxIndication 和 Dcm_TpTxConfirmation 可以在中断上下文中调用（[SWS_Dcm_00556]、[SWS_Dcm_00093]、[SWS_Dcm_00351]；SWS DCM 第274页）。解释：因此，实际的服务处理应该在任务级别的 Dcm_MainFunction 中进行。支持这一点的依据是，在 DCM_E_PENDING 之后的调用会在下一个 MainFunction 周期中重复（[SWS_Dcm_00760]）。

DCM 中的异步操作遵循 Dcm_OpStatusType 协议（[SWS_Dcm_00527]、[SWS_Dcm_00530]、[SWS_Dcm_00528]）：

  • 第一次调用使用 DCM_INITIAL 执行（[SWS_Dcm_00527]）。
  • 在 DCM_E_PENDING 时，该操作会被再次调用（[SWS_Dcm_00530]）。
  • 在 DCM_E_FORCE_RCRRP 时，DCM 发送 NRC 0x78（[SWS_Dcm_00528]）。

相同的模式也适用于对 DEM 的交互：如果 Dem_ClearDTC 返回 DEM_PENDING，DCM 会在下一个 Dcm_MainFunction 中再次调用该函数（[SWS_Dcm_00703]）。

在 DEM 中，Dem_MainFunction 处理所有非事件驱动的内部功能（[SWS_Dem_00125]、[SWS_Dem_00266]）。关于可重入性规定如下：

  • Dem_SetEventStatus 仅对不同的 EventIds 可重入（[SWS_Dem_00183]）。
  • Dem_ResetEventStatus 会在稍后的时间点异步生效（[SWS_Dem_00187]）。
  • 读取 API 对于不同的 ClientIds 是可重入的，但对于同一客户端不可重入（[SWS_Dem_00215]、[SWS_Dem_00227]）。

在多核系统中，模块会在出现错误的核上调用 DEM（BSWDistributionGuide 第43页）。Dlt_SendLogMessage 和 Dlt_SendTraceMessage 是可重入的（[SWS_Dlt_00241]、[SWS_Dlt_00243]）。这也适用于 DET 回调 <User_Error_Hooks>（[SWS_Det_00181]）。

典型的生命周期和操作模式

DEM 区分预初始化模式和完全初始化模式（[SWS_Dem_00169]）。其生命周期包括：

  • 预初始化：在 Dem_PreInit 之后，DEM 将事件消息缓存在一个可配置的队列中（[SWS_Dem_00179]、[SWS_Dem_00180]、[SWS_Dem_00167]、[SWS_Dem_00207]）。这些消息尚不会触发监控器状态回调（SWS DEM 第169页）。
  • 运行：在 Dem_Init 之后，DEM 完全就绪（[SWS_Dem_00181]、[SWS_Dem_00340]）。
  • 关闭：Dem_Shutdown 完成未决操作并触发已更改非易失性数据的保存（[SWS_Dem_00182]、[SWS_Dem_00102]、[SWS_Dem_00341]）。

Dem_RestartOperationCycle 重新启动一个操作周期并通过 InitMonitorForEvent 重新初始化监控器（[SWS_Dem_00194]、[SWS_Dem_00679]）。周期状态是否能在上电循环（Power-Cycle）后保持，由属性 cycleStatusStorage 决定。automaticEnd 在 R20-11 的 Classic Platform 上不再具有任何意义（DEXT 第225页）。

DCM 经历以下状态和模式切换：

  • 启动：DCM 在默认会话（Default-Session）中以锁定的安全级别启动（[SWS_Dcm_00033]、[SWS_Dcm_00034]）。在初始化期间，它通过 Dcm_GetProgConditions 检查是否存在从 Bootloader 返回跳转的情况（[SWS_Dcm_00536]、[SWS_Dcm_00544]）。
  • 跳转至 Bootloader：在此之前，Dcm_SetProgConditions 保存上下文数据（[SWS_Dcm_00535]、[SWS_Dcm_00543]）。
  • 会话超时：如果 S3Server 超时，DCM 返回默认会话（[SWS_Dcm_00140]）。应用程序可以使用 Dcm_ResetToDefaultSession 强制执行此操作（[SWS_Dcm_00520]）。
  • 通信模式：No-Communication 和 Silent-Communication 阻止传输，Full-Communication 允许传输（[SWS_Dcm_00148]、[SWS_Dcm_00153]、[SWS_Dcm_00157]）。

如果开发错误检测处于激活状态，各模块会向 DET 报告开发错误。对于 DEM，这是通过带有来自 [SWS_Dem_00173] 错误代码的 DemDevErrorDetect 进行的（[SWS_Dem_00124]）。Dlt 定义了自己的开发错误和运行时错误，例如 DLT_E_SKIPPED_TRANSMISSION（[SWS_Dlt_00727]、[SWS_Dlt_00728]）。Det_ReportError 调用所有具有 <User_Error_Hooks> 签名的已配置 Callout（[SWS_Det_00501]、[SWS_Det_00181]）。

DEM 中有多个降级机制生效：

  • 错误内存已满：置换策略决定替换规则。如果没有可置换的条目，则丢弃存储请求（[SWS_Dem_00401]、[SWS_Dem_00407]）。Dem_GetEventMemoryOverflow 指示溢出（[SWS_Dem_00398]、[SWS_Dem_00559]）。
  • NvM 错误：DEM 会重新初始化无法读取的数据，并忽略写入错误（[SWS_Dem_00578]、[SWS_Dem_00579]）。
  • DTC 存储已禁用：如果通过 0x85 将其关闭，DEM 将忽略状态通知（[SWS_Dem_00626]、[SWS_Dcm_00406]）。当切换到默认会话时，DCM 会重新将其激活（[SWS_Dcm_00751]）。

在通信侧，Dcm_TpTxConfirmation 解锁发送缓冲区并中止正在进行的错误处理（如超时）（[SWS_Dcm_00352]、[SWS_Dcm_00353]；ErrorDescription 第26页）。如果 Dlt 无法在任何关联的 LogChannel 中缓冲 Log 消息，Dlt_SendLogMessage 将返回 DLT_E_NO_BUFFER，而不是阻塞（[SWS_Dlt_00241]）。
