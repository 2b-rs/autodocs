系统架构 & 模块集群的角色

AUTOSAR Classic Platform（版本R20-11）的模块集群Security & Intrusion Detection提供了用于密码学、安全车载通信、密钥与证书管理以及入侵检测的标准化服务。在功能上，该集群划分贯穿AUTOSAR基础软件（Basic Software，BSW）的多个层级：在服务层，Crypto Service Manager (CSM)封装了与硬件无关的加密服务AUTOSAR_CP_SWS_CryptoServiceManager 第21页。通信层中的Secure Onboard Communication (SecOC)模块负责I-PDU的安全通信[SWS_SecOC_00162]，而Key Manager (KeyM)作为安全服务编排加密密钥和证书的生命周期SWS_KeyManager 第31页。作为补充，Intrusion Detection System Manager (IdsM)作为整个系统中安全相关事件的中央聚合器与过滤器发挥作用AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 第21页。

在CSM下方，Crypto Interface (CryIf)作为CryIf层抽象了对多个加密驱动对象的硬件或软件特定访问，并统一了任务与密钥的分发机制SWS_CryptoInterface 第1页。在MCAL与驱动层，Crypto Driver (Crypto)在软件中或硬件安全模块（HSM）上执行实际的计算[SWS_Crypto_91016]。这些层之间的协同工作确保了应用软件（SW-C）及通信模块与硬件特定加密加速器的完全解耦。

各模块之间的交互配合与交互路径

该集群的各模块通过定义明确的控制流与数据流路径相互连接。加密任务的处理主要通过CSM进行。应用模块或BSW模块（如SecOC和KeyM）通过CSM服务（如Csm_MacGenerate [SWS_Csm_00982]、Csm_Encrypt [SWS_Csm_00984]、Csm_AEADEncrypt [SWS_Csm_01023]、Csm_SignatureGenerate [SWS_Csm_00992]、Csm_Hash [SWS_Csm_00980]或Csm_RandomGenerate [SWS_Csm_01543]）发起任务。这些任务被封装在标准化运行时结构Crypto_JobType中[SWS_Csm_01013]，该结构通过运行模式（如CRYPTO_OPERATIONMODE_START、UPDATE、FINISH或SINGLECALL等Crypto_OperationModeType）进行控制[SWS_Csm_00802]。CSM将Job传递给CryIf_ProcessJob [SWS_CryIf_91003]，后者将调用转发至负责的Crypto驱动对象。

SecOC模块保护PduR与通信总线之间的PDU传输。当通过SecOC_TpRxIndication [SWS_SecOC_00125]接收到安全PDU时，SecOC首先通过SecOC_GetRxFreshnessAuthData检索新鲜度值[SWS_SecOC_91006]，并根据规范构建待认证数据SecOcProtocol 第19页。SecOC利用CSM进行MAC验证[SWS_SecOC_00012]。检查成功后，真实PDU被传递给上层。如果验证失败，结果将记录在状态SecOC_VerificationStatusType中[SWS_SecOC_00160]、[SWS_SecOC_91014]；解读：此失败将作为安全事件上报给IdsMAUTOSAR_CP_SWS_IntrusionDetectionSystemManager 第21页。

在Key Manager (KeyM)中准备并执行密钥和证书的更新。在证书验证时（例如通过KeyM_VerifyCertificates [SWS_KeyM_00059]或KeyM_VerifyCertificateChain [SWS_KeyM_00061]），KeyM使用CSM的加密原语进行签名检查，并使用StbM的外部时间基准进行有效性检查SWS_KeyManager 第119页。密钥更新（KeyM_Update [SWS_KeyM_00052]）会集成用户自定义的处理程序（KeyM_KH_Update [SWS_KeyM_00069]、[SWS_KeyM_00055]），其中生成的密钥字节通过Csm_KeyElementSet [SWS_Csm_00957]和Csm_JobKeySetValid [SWS_Csm_91027]在Crypto驱动中激活。CryIf通过CryIf_KeyDerive [SWS_CryIf_91009]或CryIf_KeyElementCopy [SWS_CryIf_91015]将密钥派生和复制操作转发至驱动函数（如Crypto_KeyElementCopyPartial [SWS_Crypto_91015]）。

IdsM通过IdsM_SetSecurityEvent [SWS_IdsM_91002]或IdsM_SetSecurityEventWithCount [SWS_IdsM_91018]等接口从BSW传感器（包括SecOC）以及应用SW-C收集安全事件（Security Events，SEv）。这些Event被缓冲，通过过滤链（例如阻塞状态过滤器[SWS_IdsM_01020]或聚合过滤器AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 第40页）进行鉴别，并最终通过PduR转发[SWS_IdsM_91009]、[SWS_IdsM_91010]。

同步、重入性与任务上下文

加密计算和安全操作的执行需要严格分离同步调用路径与异步任务上下文。在CSM和CryIf中，执行行为取决于加密原语的配置：操作既可以同步阻塞运行，也可以异步运行[SWS_Csm_00982]、[SWS_CryIf_91003]。对于异步任务，Crypto驱动通过CryIf_CallbackNotification [SWS_CryIf_91013]报告完成情况，随后CSM调用调用方注册的回调函数[SWS_SecOC_00012]。针对可中断或长时间运行的计算，CSM提供了取消函数Csm_CancelJob[SWS_Csm_00968]，该函数通过CryIf_CancelJob [SWS_CryIf_91014]委托给驱动。

SecOC模块中的传输采用时间控制解耦：在周期性循环中，SecOC_MainFunctionTx检查是否有新的真实PDU等待签名，计算认证符并发起PduR发送[SWS_SecOC_00176]。在IdsM中，上报事件的接收是在传感器上下文（Task或ISR）中通过IdsM_SetSecurityEvent [SWS_IdsM_91002]高性能完成的，此时Event首先被同步存放在可配置的事件缓冲区中[SWS_IdsM_00701]、[SWS_IdsM_00702]。耗时的过滤、上下文数据处理以及通过StbM或RTE的时间戳丰富完全在周期性IdsM_MainFunction的上下文中异步处理SWS_IntrusionDetectionSystemManager 第87页、AUTOSAR_CP_SWS_IntrusionDetectionSystemManager 第86页。

Key Manager区分时间关键型任务与计算密集型任务：标准状态查询和回调编排在KeyM_MainFunction中运行[SWS_KeyM_00074]，而计算密集型同步处理程序流程（如KeyM_KH_Update）则计划在抢占式后台函数KeyM_MainBackgroundFunction中执行[SWS_KeyM_00075]。在多核架构中，CSM还支持特定分区的MainFunction和初始化[SWS_Csm_00646]、SWS_CryptoInterface 第1页；解读：这种分区与为每个处理器核心分配专用硬件驱动对象相对应。

典型的生命周期和操作模式

集群的初始化遵循自底向上的严格依赖层级。首先通过Crypto_Init配置底层驱动[SWS_Crypto_91016]，随后是通过Csm_Init [SWS_Csm_00646]初始化的CryIf接口[SWS_CryIf_91118]和CSM。只有在此之后，才允许初始化依赖模块SecOC、KeyM和IdsM。通过初始化，SecOC从状态SECOC_UNINIT切换到SECOC_INIT [SWS_SecOC_00162]。在KeyM中，所有配置的证书初始均获得状态KEYM_CERTIFICATE_NOT_AVAILABLE [SWS_KeyM_00021]、[SWS_KeyM_91003]，之后才从NvM中读取，或者通过KeyM_SetCertificate或诊断进行加载和验证SWS_KeyManager 第119页。

在运行时，车辆状态变化会影响IdsM的运行模式：Basic Software Manager (BswM)通过IdsM_BswM_StateChanged向IdsM通知状态变更[SWS_IdsM_91005]。这些状态控制阻塞状态过滤器[SWS_IdsM_01020]、[SWS_IdsM_91017]，从而在特定运行阶段（例如编程模式或休眠阶段）抑制安全事件的转发。此外，Event的上报模式可以通过DCM进行诊断修改（IdsM_Dcm_SetReportingMode_Start [SWS_IdsM_91008]、[SWS_IdsM_91013]）并持久保存在NvM中[SWS_IdsM_01700]、[SWS_IdsM_01701]。

在ECU关闭（Shutdown）时，各模块按顺序反初始化。SecOC_DeInit停止安全通信，清空所有内部缓冲区和变量，并将SecOC转换回状态SECOC_UNINIT [SWS_SecOC_00161]。出于安全考虑，在调用KeyM_Deinit [SWS_KeyM_00047]时，RAM中的所有加密密钥材料都会被主动销毁并覆写为初始值，以防止在静止状态下遭到未经授权的读取。

错误处理、DET 跟踪与降级

该模块集群实现了用于检测开发错误（Development Error Tracer，DET）和运行时问题的贯穿机制。所有模块均会检查自身初始化情况，并在未初始化调用时报告DET错误，例如CryIf接口中的CRYIF_E_UNINIT（如CryIf_RandomSeed [SWS_CryIf_91007]、CryIf_CancelJob [SWS_CryIf_91014]、CryIf_KeyDerive [SWS_CryIf_91009]或CryIf_CallbackNotification [SWS_CryIf_91013]）。同样，错误的指针参数会导致DET报告，例如Crypto_GetVersionInfo [SWS_Crypto_91001]中的CRYPTO_E_PARAM_POINTER，而CSM中的初始化错误则通过CSM_E_INIT_FAILED进行报告[SWS_Csm_00646]。

当加密硬件对象过载或发生故障时，驱动程序会指示状态CRYPTO_E_BUSY [SWS_CryIf_91003]、[SWS_Csm_00957]。在发生此类降级的情况下，SecOC允许通过SecOC_SendDefaultAuthenticationInformation可配置地向底层发送未认证的替代PDU，以维持车辆可用性[SWS_SecOC_91013]。在IdsM中，配置的事件缓冲区耗尽将触发内部安全事件SEV_IDSM_NO_EVENT_BUFFER_AVAILABLE [SWS_IdsM_00703]。如果修改后的IdsM参数的NvM持久化失败，IdsM将自动回滚到先前状态[SWS_IdsM_01702]。如果在Csm_KeyElementSet中设置密钥时发生错误，则该密钥元素的状态视为未定义，必须通过Csm_KeyGetStatus [SWS_Csm_91047]和CryIf_KeyGetStatus [SWS_CryIf_91012]进行验证。
