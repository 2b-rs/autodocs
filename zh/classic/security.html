系统架构与模块集群的角色

该集群涵盖两项任务。第一项是通过加密栈（Crypto-Stack）、KeyM 和 SecOC 对数据和通信进行密码学保护。第二项是通过 IdsM 采集并判定安全相关事件的资格。加密栈分为三层。Crypto Driver 位于 Microcontroller Abstraction Layer 中，处于 CryIf 和 CSM 之下。一个 ECU 恰好集成一个 CSM 和一个 CryIf；CryIf 可以寻址多个 Crypto Driver 及其 Crypto Driver Object（SWS CryptoDriver 第15页）。因此，CryIf_ProcessJob 通过 channelId 寻址一个通道，而 Crypto_ProcessJob 则通过 objectId 寻址一个对象（[SWS_CryIf_91003]、[SWS_Crypto_91003]）。

KeyM 由两个子模块组成。Crypto-Key 子模块与配置实体协同工作，并将密钥分配给 CSM-Key。证书子模块存储并验证证书链（SWS KeyManager 第23页）。KeyM 通过诸如 Csm_KeyElementGet 和 Csm_KeyDerive 等 CSM 服务访问密钥（[SWS_KeyM_00076]、[SWS_KeyM_00078]）。

SecOC 位于 PduR 旁，并将 Authentic I-PDU 转换为 Secured I-PDU（SWS SecOC 第43页）。SecOC 通过诸如 Csm_MacGenerate 的 CSM 作业生成并验证 Authenticator（[SWS_SecOC_00138]）。新鲜度值由 Freshness Manager 提供，可以通过 RTE 端口或 C 函数提供（[SWS_SecOC_91001]、[SWS_SecOC_00230]）。

IdsM 接收来自传感器（例如来自 SecOC（[SWS_SecOC_00273]）或来自 KeyM（[SWS_KeyM_00172]））的安全事件（SEv）。它通过过滤链对它们进行资格判定（[SWS_IdsM_00902]），并将符合资格的事件（QSEv）通过 PduR 转发给 IdsR（[SWS_IdsM_01202]）。可选地，它通过 Csm_SignatureGenerate 对其进行签名（[SWS_IdsM_01206]），并将其存储在 DEM/Sem 中（DRAFT，[SWS_IdsM_01600]）。DCM 用于更改 Reporting Mode（[SWS_IdsM_01901]）。全局视图见 SWS IdsM 第21页。

协作与交互路径

作业路径。调用 Csm_<Service> 提交一个带有 Start、Update 和 Finish 位的 Crypto_OperationModeType（[SWS_Csm_01029]、[SWS_Csm_01039]）。CSM 将同步作业直接传递给 CryIf_ProcessJob。对于异步作业，在队列被占用时，它按优先级将其排队（SWS CSM 第30页、[SWS_Csm_00944]）。带有缓冲区和 jobState 的结构体 Crypto_JobType 穿过所有三层（[SWS_Csm_01013]、[SWS_Csm_01028]）。一旦 Finish 位置位，结果通过回调链返回：CryIf_CallbackNotification → Csm_CallbackNotification → 配置的应用程序回调（[SWS_CryIf_91013]、[SWS_Csm_00970]、[SWS_Csm_01044]）。

密钥路径。密钥服务是直接 API，例如 Csm_KeyElementSet → CryIf_KeyElementSet → Crypto_KeyElementSet（[SWS_Csm_00957]、[SWS_CryIf_91004]、[SWS_Crypto_91004]）。验证遵循相同的链条（[SWS_Csm_00958]、[SWS_CryIf_91005]、[SWS_Crypto_91014]）。如果源密钥和目标密钥位于不同的 Crypto Driver 中，CryIf 会自行复制数据（[SWS_CryIf_00140]）。在证书验证成功后，KeyM 设置公钥并通过 Csm_KeySetValid 对其进行验证（[SWS_KeyM_00170]）。

SecOC。在发送端，SecOC_MainFunctionTx 认证新的 Authentic I-PDU 并通过 PduR 触发传输（[SWS_SecOC_00176]、SWS SecOC 第84页）。之后 SecOC 报告 SecOC_SPduTxConfirmation（[SWS_SecOC_00232]）。在接收端，验证分六个步骤进行（[SWS_SecOC_00040]）。其结果作为 SecOC_VerificationStatusType 发送给 Freshness Manager（[SWS_SecOC_00160]、[SWS_SecOC_00243]）。对于异步 CSM 作业，SecOC 必须提供回调；这些回调是特定于供应商的（SWS SecOC 第78页、[SWS_Csm_00971]）。

同步、重入性与任务上下文

实际处理在 MainFunction 中进行：

  • 每个配置的实例中，SecOC 都有一个 SecOC_MainFunctionTx 和一个 SecOC_MainFunctionRx（[SWS_SecOC_00171]、[SWS_SecOC_00276]）。
  • Csm_MainFunction 处理作业队列（[SWS_Csm_00479]）。在后续版本中，它可以按分区进行实例化（SWS CSM 第150页）。
  • Crypto_MainFunction 处理异步作业（[SWS_Crypto_91012]）。Crypto Driver 针对每个分区作为独立实例工作（[SWS_Crypto_CONSTR_00001]）。
  • KeyM 在 KeyM_MainFunction 中周期性运行。长耗时操作（如 KeyM_KH_Update）在 KeyM_MainBackgroundFunction 中运行（[SWS_KeyM_00074]、[SWS_KeyM_00075]）。

在 IdsM 中，传感器调用仅将 SEv 存入 Event Buffer。过滤和时间戳（StbM）由 IdsM_MainFunction 异步完成（[SWS_IdsM_00702]、[SWS_IdsM_01104]、SWS IdsM 第86页）。所有过滤间隔均为 IdsMMainFunctionPeriod 的倍数（[SWS_IdsM_01050]、[SWS_IdsM_01064]、[SWS_IdsM_01082]）。

生命周期与运行模式

每个模块都有各自的 Init 函数（[SWS_Crypto_91000]、[SWS_CryIf_91000]、[SWS_Csm_00646]、[SWS_KeyM_00043]、[SWS_SecOC_00106]、[SWS_IdsM_91001]）。对于 Crypto 和 KeyM，配置指针始终为空指针（[SWS_Crypto_00215]、[SWS_KeyM_00158]）。推测按照 Crypto → CryIf → CSM → KeyM/SecOC/IdsM 的顺序是合理的，因为每一层都使用其下层，且在其初始化之前的调用会引发未初始化错误（[SWS_CryIf_00009]）。如果持久密钥在初始化时无法加载，Crypto Driver 会将其设置为无效（[SWS_Crypto_00198]）。IdsM 通过 NvM_ReadAll 读取其 Reporting Mode；若缺失，则配置的值生效（[SWS_IdsM_01705]、[SWS_IdsM_01704]）。

在运行时起作用的操作模式如下：

  • IdsM：BswM 通过 IdsM_BswM_StateChanged 报告 ECU 状态。Block-State 过滤器在配置的状态下丢弃 SEv（[SWS_IdsM_91005]、[SWS_IdsM_01023]）。如果 DCM 更改 Reporting Mode，新值将写入 NvM；若写入失败，则将其回滚（[SWS_IdsM_01701]、[SWS_IdsM_01702]）。
  • KeyM：密钥更新会话通过 KeyM_Start（例如在 OEM 生产或车间模式下）、KeyM_Prepare、KeyM_Update 和 KeyM_Finalize 进行。Finalize 将会话恢复为空闲状态（[SWS_KeyM_00038]、[SWS_KeyM_00052]、[SWS_KeyM_00053]）。
  • SecOC：SecOC_VerifyStatusOverride 可以覆盖验证，例如通过 SECOC_OVERRIDE_DROP_UNTIL_NOTICE（[SWS_SecOC_00122]、[SWS_SecOC_00991]）。
  • 密钥状态：状态通过 Csm_KeySetValid 和 Csm_KeySetInvalid 在 Crypto_KeyStatusType 的值之间切换（[SWS_Csm_91102]、[SWS_Csm_91075]）。

关闭时，SecOC_DeInit 丢弃所有已缓冲的 I-PDU 并设置状态 SECOC_UNINIT（[SWS_SecOC_00161]、[SWS_SecOC_00162]）。KeyM_Deinit 主动从 RAM 中擦除密钥材料（[SWS_KeyM_00047]、SWS KeyManager 第49页）。

错误处理、DET 跟踪与降级

开发与运行时错误。在启用错误检测时，所有模块均向 DET 报告开发错误（[SWS_SecOC_00101]、[SWS_Csm_91004]、[SWS_Crypto_00040]、[SWS_KeyM_00144]、[SWS_IdsM_02003]）。此外还存在运行时错误：SECOC_E_FRESHNESS_FAILURE、CSM_E_QUEUE_FULL 以及 Crypto Driver 的熵错误和 NvM 错误（[SWS_SecOC_00114]、[SWS_Csm_01089]、[SWS_Crypto_00194]）。

SecOC 中的降级。在发送端，如果发生可恢复的 CSM 错误，SecOC 不会提供 Secured I-PDU，而是重试。重试次数由 SecOCAuthenticationBuildAttempts 限制（[SWS_SecOC_00151]、[SWS_SecOC_00155]）。此后，SecOC 可以发送默认认证信息（[SWS_SecOC_00229]、[SWS_SecOC_91013]）。在接收端，Build 和 Verify 计数器对尝试次数进行计数（[SWS_SecOC_00236]、[SWS_SecOC_00239]）。若达到限制或新鲜度查询返回 E_NOT_OK，则丢弃该 PDU（[SWS_SecOC_00241]、[SWS_SecOC_00256]）。

Crypto-Stack。Csm_CancelJob 从队列中移除一个作业，或通过驱动程序中的 CryIf_CancelJob 将其中止（[SWS_Csm_00968]、[SWS_CryIf_91014]）。如果驱动程序无法立即中止，则返回 CRYPTO_E_JOB_CANCELED（[SWS_Crypto_00183]）。如果 Csm_KeyElementSet 失败，则密钥状态未知，应通过 Csm_KeyGetStatus 进行检查（SWS CSM 第62页）。

IdsM。若缺少空闲缓冲区，IdsM 会触发内部 SEv（[SWS_IdsM_00703]、[SWS_IdsM_00708]）。若仅缺少匹配的上下文缓冲区，它会在不包含上下文数据的情况下处理该事件（[SWS_IdsM_00707]）。在发送前，它限制速率和数据量（[SWS_IdsM_01070]、[SWS_IdsM_01094]）。

活动图：SEv 依次经过缓冲、Reporting Mode、固定过滤顺序以及接收端；每个过滤器都可以将其丢弃。来源：[SWS_IdsM_00702]、[SWS_IdsM_01002]、[SWS_IdsM_01004]、[SWS_IdsM_01005]、[SWS_IdsM_91013]、[SWS_IdsM_01070]、SWS IdsM 第26页
