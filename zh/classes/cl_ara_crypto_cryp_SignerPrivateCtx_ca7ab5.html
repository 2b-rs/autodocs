用于在单步或流式过程中使用私有加密密钥创建数字签名。

接口 ara::crypto::cryp::SignerPrivateCtx 封装了 Adaptive Platform 上用于数字签名操作的私钥 [SWS_CRYPT_23501]。通过 SetKey() 配置密钥后，消息既可以通过 Sign() 在单步中签名，也可以通过 Start()、Update() 和 Finish() 进行多阶段签名 [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50040]。所有调用均是线程安全的，并通过 ara::core::Result [SWS_CRYPT_50040] 发出缓冲区容量不足或无效上下文状态等错误信号。

上下文

接口 ara::crypto::cryp::SignerPrivateCtx 表示在 AUTOSAR Adaptive Platform 上使用私钥执行数字签名操作的加密执行上下文。该类继承自 CryptoContext 并封装了非对称签名算法。为了绑定所需的密钥材料，上下文既可以通过 PrivateKey::Sptr [SWS_CRYPT_23515] 直接与私钥对象交互，也可以通过 KeySlot::Sptr [SWS_CRYPT_50036] 与受管密钥插槽交互。调用方通常通过定义的智能指针类型别名 ara::crypto::cryp::SignerPrivateCtx::Sptr [SWS_CRYPT_23501] 来管理此接口的实例。

生命周期

SignerPrivateCtx 的实例作为有状态对象运行，并通过共享指针结构（std::shared_ptr）进行管理 [SWS_CRYPT_23501]。在执行加密计算之前，该实例处于未初始化状态，并要求分配匹配的密钥。通过方法 SetKey()，可以为上下文分配具体的私钥 [SWS_CRYPT_23515]，或者存入一个 KeySlot，其密钥值将在签名计算开始时被采用 [SWS_CRYPT_50036]。一旦成功绑定密钥，上下文即转入就绪状态。所有接口方法均被指定为异常安全（exception safe）和线程安全（thread-safe）[SWS_CRYPT_23512] [SWS_CRYPT_50037]。

在数据处理内部，该接口区分单次签名与多阶段流式处理。流式签名操作由 Start() 发起 [SWS_CRYPT_50037] [SWS_CRYPT_50038]，通过 Update() 逐步提供数据块 [SWS_CRYPT_50039]，并通过 Finish() 结束 [SWS_CRYPT_50040]。或者，可以随时通过 Cancel() 中止正在进行的流式处理，从而使实例返回就绪状态 [SWS_CRYPT_50041]。

状态图：签名上下文从配置到操作完成的状态转换。来源：[SWS_CRYPT_23515]、[SWS_CRYPT_50036]、[SWS_CRYPT_23512]、[SWS_CRYPT_50037]、[SWS_CRYPT_50039]、[SWS_CRYPT_50040]、[SWS_CRYPT_50041]

使用路径

应用程序既可以在单步（Single-Call）中生成签名，也可以将其作为连续数据流（Streaming）生成。在执行之前，应用程序通过 GetSignatureSize() 确定所需签名格式的预期缓冲区大小 FormatId [SWS_CRYPT_29004]，并通过 GetMaximumChunkSize() 确定单次读取操作的最大允许块大小 [SWS_CRYPT_50042]。

在单步路径中，完整消息通过 Sign() 直接签名。该方法接收输入消息、目标缓冲区 ReadWriteMemRegion、签名格式以及可选的特定于算法的上下文值，并返回实际写入的字节数 [SWS_CRYPT_23512]。

对于较大的数据量或分段消息，流式路径遵循三阶段模式：

  1. 初始化：调用不带参数 [SWS_CRYPT_50037] 的 Start()，或带有应用程序特定上下文缓冲区 ReadOnlyMemRegion [SWS_CRYPT_50038]。
  2. 处理：通过 Update() 重复提供部分消息，其中每个块必须遵守 GetMaximumChunkSize() 给出的上限 [SWS_CRYPT_50039] [SWS_CRYPT_50042]。
  3. 完成或中止：通过 Finish() [SWS_CRYPT_50040] 完成签名生成并写入目标存储器，或使用 Cancel() [SWS_CRYPT_50041] 提前中止正在进行的过程。

时序图：包含缓冲区检查和完成的流式签名创建的典型流程。来源：[SWS_CRYPT_23515]、[SWS_CRYPT_29004]、[SWS_CRYPT_50037]、[SWS_CRYPT_50039]、[SWS_CRYPT_50040]

错误场景

方法调用默认返回 ara::core::Result，并在失败时使用来自 ara::crypto::CryptoErrc 具有回滚语义的标准化错误代码。常见的错误原因包括：

  • CryptoErrc::kUninitializedContext：在通过 SetKey() 绑定密钥之前调用 Sign() 或 Start() [SWS_CRYPT_23512] [SWS_CRYPT_50037] [SWS_CRYPT_50038]。
  • CryptoErrc::kUsageViolation：提供的密钥不具备所需的使用权限 kAllowSigGeneration [SWS_CRYPT_23515] [SWS_CRYPT_23512] [SWS_CRYPT_50037]。
  • CryptoErrc::kIncompatibleObject：传入的 PrivateKey 或 KeySlot 与上下文的算法不兼容 [SWS_CRYPT_23515] [SWS_CRYPT_50036]。
  • CryptoErrc::kProcessingNotStarted：在先前未成功调用 Start() 的情况下调用 Update()、Finish() 或 Cancel() [SWS_CRYPT_50039] [SWS_CRYPT_50040] [SWS_CRYPT_50041]。
  • CryptoErrc::kInsufficientCapacity：为 Sign() 或 Finish() 传入的输出缓冲区小于要写入的签名 [SWS_CRYPT_23512] [SWS_CRYPT_50040]。
  • CryptoErrc::kUnsupportedFormat：上下文不支持请求的 FormatId [SWS_CRYPT_29004] [SWS_CRYPT_23512] [SWS_CRYPT_50040]。
  • CryptoErrc::kEmptyKeySlot：配置的 KeySlot 在执行时不包含密钥 [SWS_CRYPT_23512] [SWS_CRYPT_50037]。
  • CryptoErrc::kInvalidInputSize：调用 Sign()、Start() 或 Update() 时缓冲区大小无效 [SWS_CRYPT_23512] [SWS_CRYPT_50038] [SWS_CRYPT_50039]。

virtual ara::core::Result< void > Cancel () noexcept=0;

Cancel the ongoing streaming operation that has been initiated by Start() and has not yet been finished.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: add6f8db34cb Provenance

方法 Cancel() 用于在类 ara::crypto::cryp::SignerPrivateCtx 内部同步中止正在进行且尚未完成的流式传输操作，该操作先前通过调用 Start() 启动 [SWS_CRYPT_50041]。纯虚接口 virtual ara::core::Result<void> Cancel() noexcept = 0; 在头文件 ara/crypto/cryp/signer_private_ctx.h 中声明，不接受任何传入参数，并通过空的 ara::core::Result<void> [SWS_CRYPT_50041] 指示成功中止。对于调用方而言，该方法被指定为异常安全的（exception safe）且并发线程安全的（thread-safe）[SWS_CRYPT_50041]。

关于调用顺序和错误处理，Cancel() 强制要求必须存在活动处理：如果此前未通过调用方法 Start() 启动数据处理，则中止将失败，并返回具有定义的回滚语义的错误代码 ara::crypto::CryptoErrc::kProcessingNotStarted [SWS_CRYPT_50041]。解释：在成功调用 Cancel() 之后，上下文推测会恢复到未启动的初始状态，以便可以开始新的签名或流过程。

该设计遵循加密模块中所有流操作的统一原则。对于相关上下文，存在完全相同的签名和错误语义，如 VerifierPublicCtx [SWS_CRYPT_50023]、MessageAuthnCodeCtx [SWS_CRYPT_50027]、SymmetricCipherCtx [SWS_CRYPT_50046]、HashFunctionCtx [SWS_CRYPT_50058]、DecryptorPrivateCtx [SWS_CRYPT_50069]、AuthCipherCtx [SWS_CRYPT_50077] 以及 EncryptorPublicCtx [SWS_CRYPT_50089]。

      使用
