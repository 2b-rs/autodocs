用于检索认证实例以管理外部诊断客户端的状态。

类 ara::diag::ExternalAuthentication 提供了一个端口接口，Adaptive 应用程序通过该接口查询 ara::diag::ClientAuthentication 的实例以管理外部诊断客户端的认证状态 [SWS_DM_01191]。绑定到建模的服务端口后，根据源地址或元信息从 Diagnostic Manager 定向请求认证对象 [SWS_DM_01200]。该实例具有移动语义，禁止拷贝操作，并且由于析构函数非线程安全而需要同步销毁。

上下文

类 ara::diag::ExternalAuthentication 在 AUTOSAR Adaptive Platform 中充当用于外部诊断客户端认证的端口接口 [SWS_DM_01191]、AUTOSAR_AP_SWS_Diagnostics §8.17 “Header: ara/diag/external_authentication.h”。通过此端口，Adaptive 应用程序可以访问 ara::diag::ClientAuthentication 的特定实例，这些实例映射并管理对应诊断客户端的认证状态 [SWS_DM_01202]。

可用客户端实例的分配和数量在软件模型中通过元素 DiagnosticExternalAuthenticationIdentification 定义。如果最终源地址直到运行时才可知，该元素允许应用程序为诊断测试仪指定固定的源地址或类型为 Address（std::uint16_t [SWS_DM_01192] 的别名）的配置地址范围 AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 “Get ClientAuthentication Instance”。

参与的交互方包括：

  • Adaptive 应用程序：创建端口实例并查询认证状态。
  • Diagnostic Manager (DM)：控制诊断连接并管理客户端的认证状态 [SWS_DM_01202]。
  • ara::diag::ClientAuthentication 对象：分配给发起请求的客户端。
  • 外部诊断客户端：其连接通过源地址或元信息进行标识。

上下文图：端口类在应用程序、Diagnostic Manager 和客户端认证之间的集成。来源：[SWS_DM_01191]、[SWS_DM_01202]、AUTOSAR_AP_SWS_Diagnostics §7.3.2.2 “Get ClientAuthentication Instance”。

生命周期

ara::diag::ExternalAuthentication 实例的创建通过向构造函数 [SWS_DM_01193] 显式传入 ara::core::InstanceSpecifier 来进行。该标识符将对象绑定到 DiagnosticExternalAuthenticationInterface 的建模 PortPrototype。

关于所有权关系，该类具有纯移动语义：提供移动构造函数 [SWS_DM_01194] 和移动赋值运算符 [SWS_DM_01195]（default），而拷贝构造函数 [SWS_DM_01196] 和拷贝赋值运算符 [SWS_DM_01197] 已被删除（delete）。因此，端口表示一个不可分割、不可拷贝的接口对象。

对于销毁，析构函数 ~ExternalAuthentication() 可用 [SWS_DM_01198]。关于并发性，构造函数以及查询方法被指定为线程安全（thread-safe）和异常安全（exception safe）[SWS_DM_01193]、[SWS_DM_01199]、[SWS_DM_01200]、[SWS_DM_01201]。相反，析构函数明确为非线程安全（not thread-safe）[SWS_DM_01198]。因此，应用程序必须确保在销毁对象之前不再发生并发调用。

使用路径

典型流程包括端口的初始化以及随后对认证对象的检索：

  1. 应用程序在指定实例标识符 [SWS_DM_01193] 的情况下实例化 ExternalAuthentication。
  2. 应用程序请求具体客户端的认证实例。为此，可使用重载方法 Get(Address)（利用测试仪地址 [SWS_DM_01200]）或 Get(const MetaInfo&)（根据接收到的请求元数据 [SWS_DM_01199]）。或者，它可以通过 GetAll() 查询 Diagnostic Manager 当前维护的所有实例的列表 [SWS_DM_01201]。
  3. Diagnostic Manager 确定相应对象并返回 ara::core::Result<ClientAuthentication> 或向量 [SWS_DM_01202]。
  4. 应用程序检查结果，随后与获得的 ClientAuthentication 实例交互，该实例推测用作应用端认证会话状态的句柄。 问题 Q-e7ddbab981bf21de (未决)

时序图：用于实例化和查询 ClientAuthentication 实例的典型调用顺序。来源：[SWS_DM_01193]、[SWS_DM_01200]、[SWS_DM_01202]。

错误场景

通过构造函数实例化时，配置和建模错误可能导致已定义的违规 [SWS_DM_01193]：

  • InstanceSpecifierMappingIntegrityViolation：该标识符无法在可执行文件的上下文中解析，或未引用 PortPrototype。
  • PortInterfaceMappingViolation：引用的 PortPrototype 未被类型化为 DiagnosticExternalAuthenticationInterface。
  • ProcessMappingViolation：不存在适用于运行时进程的匹配建模进程定义。
  • InstanceSpecifierAlreadyInUseViolation：该标识符在同一进程中已被另一个端口实例使用。

在调用 Get(const MetaInfo&) 或 Get(Address) 时，通过 ara::core::Result 的返回值可能包含错误代码 DiagErrc::kServiceNotAvailable [SWS_DM_01199]、[SWS_DM_01200]。这表示 Diagnostic Manager 的关键功能暂时不可用。调用 GetAll() 在缺少实例时不返回错误代码，而是返回一个空向量 [SWS_DM_01201]。
