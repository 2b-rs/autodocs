上下文

类 ara::tsync::SynchronizedTimeBaseConsumer 构成了 Adaptive Platform 上的应用程序访问同步时间基准的核心接口，该时间基准通过实例标识符（ara::core::InstanceSpecifier）寻址。该消费者支持读取当前时间点、时钟速率偏差、当前状态以及接收到的用户数据。

在系统架构中，该类在使用它的应用软件与 Tsync 子系统之间起中介作用：

  • 应用软件：要么使用该实例进行周期性的状态与时间轮询，要么对已配置的时间基准事件做出异步响应。
  • SynchronizedTimeBaseConsumer：管理与端口的系统特定绑定，并封装查询及 Notifier 逻辑。
  • Tsync 子系统 / 时间基准：提供同步时间戳、状态信息和验证数据块。

生命周期

SynchronizedTimeBaseConsumer 的实例通过显式构造函数 [SWS_TS_01001] 指定 ara::core::InstanceSpecifier 来创建。该构造函数被指定为异常安全（exception safe）且线程安全（thread-safe）。

在对象所有权方面，该类强制执行严格的移动语义：

  • 拷贝构造函数 [SWS_TS_01005] 和拷贝赋值运算符 [SWS_TS_01006] 已删除（=delete），从而杜绝了复制消费者实例的操作。
  • 支持通过移动构造函数 [SWS_TS_01003] 以及移动赋值运算符 [SWS_TS_01004] 进行的移动操作。这两项操作均为 noexcept，但被归类为非线程安全（non_threadsafe）。

销毁通过析构函数 [SWS_TS_01002] 进行，该函数同样为 noexcept，但为 non_threadsafe。解读：为避免在销毁或重新分配时出现并发冲突，注册的回调函数很可能必须在实例生命周期结束前通过相应的 Unregister 函数显式注销。

关于运行时的并发性，需要注意的是，对时间基准的纯读取访问（[SWS_TS_01008]、[SWS_TS_01009]）是线程安全的，而用于 Notifier 的所有注册和注销调用（例如 [SWS_TS_01010]、[SWS_TS_01011]）均被归类为 non_threadsafe，且需要外部同步。

使用路径

使用同步时间基准的典型流程分为初始化、事件配置、运行时查询和清理：

  1. 实例化：使用相匹配的 InstanceSpecifier [SWS_TS_01001] 创建对象。
  2. 事件注册：应用程序根据需要针对相关状态变更注册回调函数：
    • RegisterStatusChangeNotifier [SWS_TS_01010] 用于状态标志的常规变更（同步状态、时间跳变或用户数据）。
    • RegisterSynchronizationStateChangeNotifier [SWS_TS_01012] 仅用于同步状态的切换。
    • RegisterTimeLeapNotifier [SWS_TS_01014] 用于单独处理发生的时间跳变。
    • RegisterTimePrecisionMeasurementNotifier [SWS_TS_01018] 在有新的时间精度快照可用时使用。
    • RegisterTimeValidationNotification [SWS_TS_01016] 用于接收时间基准的验证数据块。
  3. 运行时时间与状态查询：应用程序通过 GetTimeWithStatus [SWS_TS_01009] 获取时钟状态的快照，其中包含状态标志、时钟配置以及本地和同步时间值。时钟当前的速率偏差可通过 GetRateDeviation [SWS_TS_01008] 查询。
  4. 注销：不再需要的通知通过对应的对应项移除：UnregisterStatusChangeNotifier [SWS_TS_01011]、UnregisterSynchronizationStateChangeNotifier [SWS_TS_01013]、UnregisterTimeLeapNotifier [SWS_TS_01015]、UnregisterTimeValidationNotification [SWS_TS_01017] 以及 UnregisterTimePrecisionMeasurementNotifier [SWS_TS_01019]。

错误场景

SynchronizedTimeBaseConsumer 的所有成员函数均定义为 noexcept 和 exception safe。错误条件主要由错误的建模或不允许的调用上下文引起：

  • 端口接口配置错误：若由 TimeSyncPortPrototypeToTimeBaseMapping 引用的 PortPrototype 未使用接口类型 SynchronizedTimeBaseConsumerInterface 进行类型化，则在实例化时会存在 PortInterfaceMappingViolation [SWS_TS_01001]。
  • 覆盖现有 Notifier：每个事件类别最多可同时注册一个 Notifier。每次重复调用注册函数（[SWS_TS_01010]、[SWS_TS_01012]、[SWS_TS_01014]、[SWS_TS_01016]、[SWS_TS_01018]）都会直接覆盖现有注册，而不会事先发出警告。
  • 因缺少队列导致测量值丢失：根据 [SWS_TS_01018]，Tsync 不对时间精度测量执行任何队列管理（Queuing）。如果应用程序无法立即处理连续的快照，则必须在 Notifier 内部自行对其进行缓冲，否则新到达的数据可能会被丢弃。
  • 违反线程安全性：由于 Notifier 的注册和注销被声明为 non_threadsafe，因此并发调用这些方法会导致回调管理中的数据不一致。

<h4>上下文</h4>
<p>类 <code>ara::tsync::SynchronizedTimeBaseConsumer</code> 构成了 Adaptive Platform 上的应用程序访问同步时间基准的核心接口，该时间基准通过实例标识符（<code>ara::core::InstanceSpecifier</code>）寻址。该消费者支持读取当前时间点、时钟速率偏差、当前状态以及接收到的用户数据。</p>
<p>在系统架构中，该类在使用它的应用软件与 Tsync 子系统之间起中介作用：</p>
<ul>
<li><strong>应用软件：</strong>要么使用该实例进行周期性的状态与时间轮询，要么对已配置的时间基准事件做出异步响应。</li>
<li><strong>SynchronizedTimeBaseConsumer：</strong>管理与端口的系统特定绑定，并封装查询及 Notifier 逻辑。</li>
<li><strong>Tsync 子系统 / 时间基准：</strong>提供同步时间戳、状态信息和验证数据块。</li>
</ul>

<h4>生命周期</h4>
<p><code>SynchronizedTimeBaseConsumer</code> 的实例通过显式构造函数 <a class="spec-record-ref" data-req="SWS_TS_01001" href="../spec/record.html?id=SWS_TS_01001">[SWS_TS_01001]</a> 指定 <code>ara::core::InstanceSpecifier</code> 来创建。该构造函数被指定为异常安全（<code>exception safe</code>）且线程安全（<code>thread-safe</code>）。</p>
<p>在对象所有权方面，该类强制执行严格的移动语义：</p>
<ul>
<li>拷贝构造函数 <a class="spec-record-ref" data-req="SWS_TS_01005" href="../spec/record.html?id=SWS_TS_01005">[SWS_TS_01005]</a> 和拷贝赋值运算符 <a class="spec-record-ref" data-req="SWS_TS_01006" href="../spec/record.html?id=SWS_TS_01006">[SWS_TS_01006]</a> 已删除（<code>=delete</code>），从而杜绝了复制消费者实例的操作。</li>
<li>支持通过移动构造函数 <a class="spec-record-ref" data-req="SWS_TS_01003" href="../spec/record.html?id=SWS_TS_01003">[SWS_TS_01003]</a> 以及移动赋值运算符 <a class="spec-record-ref" data-req="SWS_TS_01004" href="../spec/record.html?id=SWS_TS_01004">[SWS_TS_01004]</a> 进行的移动操作。这两项操作均为 <code>noexcept</code>，但被归类为非线程安全（<code>non_threadsafe</code>）。</li>
</ul>
<p>销毁通过析构函数 <a class="spec-record-ref" data-req="SWS_TS_01002" href="../spec/record.html?id=SWS_TS_01002">[SWS_TS_01002]</a> 进行，该函数同样为 <code>noexcept</code>，但为 <code>non_threadsafe</code>。解读：为避免在销毁或重新分配时出现并发冲突，注册的回调函数很可能必须在实例生命周期结束前通过相应的 Unregister 函数显式注销。</p>
<p>关于运行时的并发性，需要注意的是，对时间基准的纯读取访问（<a class="spec-record-ref" data-req="SWS_TS_01008" href="../spec/record.html?id=SWS_TS_01008">[SWS_TS_01008]</a>、<a class="spec-record-ref" data-req="SWS_TS_01009" href="../spec/record.html?id=SWS_TS_01009">[SWS_TS_01009]</a>）是线程安全的，而用于 Notifier 的所有注册和注销调用（例如 <a class="spec-record-ref" data-req="SWS_TS_01010" href="../spec/record.html?id=SWS_TS_01010">[SWS_TS_01010]</a>、<a class="spec-record-ref" data-req="SWS_TS_01011" href="../spec/record.html?id=SWS_TS_01011">[SWS_TS_01011]</a>）均被归类为 <code>non_threadsafe</code>，且需要外部同步。</p>

<p>使用同步时间基准的典型流程分为初始化、事件配置、运行时查询和清理：</p>
<ol>
<li><strong>实例化：</strong>使用相匹配的 <code>InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_TS_01001" href="../spec/record.html?id=SWS_TS_01001">[SWS_TS_01001]</a> 创建对象。</li>
<li><strong>事件注册：</strong>应用程序根据需要针对相关状态变更注册回调函数：

<li><code>RegisterSynchronizationStateChangeNotifier</code> <a class="spec-record-ref" data-req="SWS_TS_01012" href="../spec/record.html?id=SWS_TS_01012">[SWS_TS_01012]</a> 仅用于同步状态的切换。</li>
<li><code>RegisterTimeLeapNotifier</code> <a class="spec-record-ref" data-req="SWS_TS_01014" href="../spec/record.html?id=SWS_TS_01014">[SWS_TS_01014]</a> 用于单独处理发生的时间跳变。</li>
<li><code>RegisterTimePrecisionMeasurementNotifier</code> <a class="spec-record-ref" data-req="SWS_TS_01018" href="../spec/record.html?id=SWS_TS_01018">[SWS_TS_01018]</a> 在有新的时间精度快照可用时使用。</li>
<li><code>RegisterTimeValidationNotification</code> <a class="spec-record-ref" data-req="SWS_TS_01016" href="../spec/record.html?id=SWS_TS_01016">[SWS_TS_01016]</a> 用于接收时间基准的验证数据块。</li>
</ul>
</li>
<li><strong>运行时时间与状态查询：</strong>应用程序通过 <code>GetTimeWithStatus</code> <a class="spec-record-ref" data-req="SWS_TS_01009" href="../spec/record.html?id=SWS_TS_01009">[SWS_TS_01009]</a> 获取时钟状态的快照，其中包含状态标志、时钟配置以及本地和同步时间值。时钟当前的速率偏差可通过 <code>GetRateDeviation</code> <a class="spec-record-ref" data-req="SWS_TS_01008" href="../spec/record.html?id=SWS_TS_01008">[SWS_TS_01008]</a> 查询。</li>

</ol>

<h4>错误场景</h4>
<p><code>SynchronizedTimeBaseConsumer</code> 的所有成员函数均定义为 <code>noexcept</code> 和 <code>exception safe</code>。错误条件主要由错误的建模或不允许的调用上下文引起：</p>
<ul>
<li><strong>端口接口配置错误：</strong>若由 <code>TimeSyncPortPrototypeToTimeBaseMapping</code> 引用的 <code>PortPrototype</code> 未使用接口类型 <code>SynchronizedTimeBaseConsumerInterface</code> 进行类型化，则在实例化时会存在 <code>PortInterfaceMappingViolation</code> <a class="spec-record-ref" data-req="SWS_TS_01001" href="../spec/record.html?id=SWS_TS_01001">[SWS_TS_01001]</a>。</li>
<li><strong>覆盖现有 Notifier：</strong>每个事件类别最多可同时注册一个 Notifier。每次重复调用注册函数（<a class="spec-record-ref" data-req="SWS_TS_01010" href="../spec/record.html?id=SWS_TS_01010">[SWS_TS_01010]</a>、<a class="spec-record-ref" data-req="SWS_TS_01012" href="../spec/record.html?id=SWS_TS_01012">[SWS_TS_01012]</a>、<a class="spec-record-ref" data-req="SWS_TS_01014" href="../spec/record.html?id=SWS_TS_01014">[SWS_TS_01014]</a>、<a class="spec-record-ref" data-req="SWS_TS_01016" href="../spec/record.html?id=SWS_TS_01016">[SWS_TS_01016]</a>、<a class="spec-record-ref" data-req="SWS_TS_01018" href="../spec/record.html?id=SWS_TS_01018">[SWS_TS_01018]</a>）都会直接覆盖现有注册，而不会事先发出警告。</li>
<li><strong>因缺少队列导致测量值丢失：</strong>根据 <a class="spec-record-ref" data-req="SWS_TS_01018" href="../spec/record.html?id=SWS_TS_01018">[SWS_TS_01018]</a>，Tsync 不对时间精度测量执行任何队列管理（Queuing）。如果应用程序无法立即处理连续的快照，则必须在 Notifier 内部自行对其进行缓冲，否则新到达的数据可能会被丢弃。</li>
<li><strong>违反线程安全性：</strong>由于 Notifier 的注册和注销被声明为 <code>non_threadsafe</code>，因此并发调用这些方法会导致回调管理中的数据不一致。</li>
</ul>
