提供用于带有完整性保护的经过身份验证的对称加密和解密的接口。

接口 ara::crypto::cryp::AuthCipherCtx 用于在维护机密性和完整性的同时对数据进行身份验证加解密 [SWS_CRYPT_23911]。配置密钥后，处理既可以作为原子单次调用进行，也可以作为由初始化、可选验证数据、有效负载更新和最终化组成的流式序列进行。作为关键安全条件，如果身份验证标签无效，解密将失败，因此解密后的有效负载数据只有在验证成功后才能进行处理 [SWS_CRYPT_50075]。

上下文

接口 ara::crypto::cryp::AuthCipherCtx 定义了 AUTOSAR Adaptive Platform 内用于经过身份验证的密码操作（关联数据的认证加密，AEAD）的标准化应用程序编程接口。它通过在实际对有效负载数据进行加解密的同时始终生成或验证加密身份验证标签，将机密性与完整性保护结合起来。调用方应用程序和密钥对象充当核心交互伙伴：在使用前，上下文要么绑定到 SymmetricKey 的具体实例 [SWS_CRYPT_23911]，要么使用持久化或提供的 KeySlot 进行配置 [SWS_CRYPT_50072]。除了分步流式处理之外，该类还支持独立的单次调用，以便在一步中处理完整消息 [SWS_CRYPT_50078]。

生命周期

在应用程序范围中，上下文通过共享指针类型 ara::crypto::cryp::AuthCipherCtx::Sptr 进行管理 [SWS_CRYPT_20101]。（解读：由于 AuthCipherCtx 被指定为纯接口，对象创建通常通过上级提供方工厂进行）。所有成员函数均声明为异常安全（exception safe）和线程安全（thread-safe）[SWS_CRYPT_23911]、[SWS_CRYPT_24715]。功能生命周期经历明确定义的状态：

  • 未初始化：紧接着实例化之后。由于尚未分配密钥，对数据处理的调用将被拒绝 [SWS_CRYPT_50081]。
  • 密钥已配置：通过使用 SymmetricKey [SWS_CRYPT_23911] 或 KeySlot [SWS_CRYPT_50072] 成功调用 SetKey，上下文转换到就绪状态。在此状态下可以直接执行单次操作。
  • 流式处理活动：通过在指定转换方向的情况下调用 Start 进入，可以带有初始化向量 (IV) [SWS_CRYPT_24715] 或不带显式 IV [SWS_CRYPT_50073]。
  • 完成 / 重置：正在进行的流式操作通常通过 Finish [SWS_CRYPT_50075] 或 FinishEncrypt [SWS_CRYPT_50076] 完成，或者通过 Cancel 提前中止 [SWS_CRYPT_50077]。之后上下文再次就绪以进行新的处理序列。

使用路径

对于连续数据流处理，该接口需要有序的调用序列：

  1. 配置：通过 SetKey [SWS_CRYPT_23911] 或使用 KeySlot [SWS_CRYPT_50072] 的 SetKey 分配密钥。
  2. 参数查询：可选通过 GetMinimumChunkSize [SWS_CRYPT_50162]、GetMaximumChunkSize [SWS_CRYPT_50082]、GetMinimumInputIvSize [SWS_CRYPT_50163]、GetMaximumInputIvSize [SWS_CRYPT_50164]、GetTagSize [SWS_CRYPT_50161] 以及 GetRequiredOutputBufferSize [SWS_CRYPT_50081] 确定限值与缓冲区大小。
  3. 操作启动：调用 Start，指定方向（加密或解密），并提供 IV [SWS_CRYPT_24715] 或请求上下文拥有的 IV [SWS_CRYPT_50073]。
  4. 关联数据 (AAD)：如果额外的明文数据需要纳入完整性计算，则通过 UpdateAuthenticatedData 传入 [SWS_CRYPT_20313]。最大允许的 AAD 大小可通过 GetMaxAssociatedDataSize 查询 [SWS_CRYPT_20103]。重要提示：AAD 块必须强制在实际有效负载数据之前传输。
  5. 有效负载数据处理：通过 UpdateConfidentialData [SWS_CRYPT_50074] 逐步传递数据块。在解密时，明文会在确定其真实性之前返回；应用程序仅允许在成功完成 Finalize 之后使用这些数据。
  6. 完成：通过 Finish [SWS_CRYPT_50075] 或 FinishEncrypt [SWS_CRYPT_50076] 结束操作，由此处理最终块并计算或验证身份验证标签（Tag）。

对于紧凑的负载存在单次调用替代方案：ProcessSingleCall 在不传递 IV 的情况下处理数据 [SWS_CRYPT_50078]，ProcessSingleCallWithInputIv 接受外部 IV [SWS_CRYPT_50079]，而 EncryptSingleCallWithOutputIv 将由上下文生成的 IV 返回给调用者 [SWS_CRYPT_50080]。

错误场景

AuthCipherCtx 的方法通过 ara::core::Result 返回结果，并在出错时具有回滚语义。来自 ara::crypto::CryptoErrc 的相关错误码包括：

  • kUninitializedContext：在尚未通过 SetKey 配置密钥的情况下调用 Start [SWS_CRYPT_24715]、ProcessSingleCall [SWS_CRYPT_50078] 或缓冲区计算 [SWS_CRYPT_50081] 时发生。
  • kProcessingNotStarted：在没有预先 Start 的情况下调用 UpdateAuthenticatedData [SWS_CRYPT_20313]、UpdateConfidentialData [SWS_CRYPT_50074]、Finish [SWS_CRYPT_50075] 或 Cancel [SWS_CRYPT_50077] 时报告。
  • kInvalidUsageOrder：在已通过 UpdateConfidentialData 处理有效负载数据之后调用 UpdateAuthenticatedData 时指示错误的调用顺序 [SWS_CRYPT_20313]。
  • kAuthTagNotValid：在 Finish [SWS_CRYPT_50075] 解密或单次调用方法 [SWS_CRYPT_50078] 中指示计算出的标签与传入的标签不匹配且真实性检查失败。
  • kUsageViolation：在密钥的使用属性与所请求的操作不匹配（例如缺少 kAllowDataEncrypt 或 kAllowDataDecrypt）时发生 [SWS_CRYPT_23911]，[SWS_CRYPT_50078]。
  • kInsufficientCapacity / kInvalidInputSize：指示输出缓冲区尺寸不足或输入、IV 或标签长度无效 [SWS_CRYPT_24715]、[SWS_CRYPT_50074]、[SWS_CRYPT_50075]。
  • kEmptyKeySlot / kBusyResource：涉及使用已配置密钥存储槽时的错误状态 [SWS_CRYPT_24715]、[SWS_CRYPT_50078]。

使用

接口 ara::crypto::cryp::AuthCipherCtx 的方法 Cancel() 用于中止此前通过 Start() 启动且尚未完成的活动流式操作 [SWS_CRYPT_50077]。该函数通过头文件 ara/crypto/cryp/auth_cipher_ctx.h 提供，同步执行且不带入参 [SWS_CRYPT_50077]。它返回一个在成功情况下为空的 ara::core::Result<void>。

中止的前提是此前确实已通过 Start() 开始了数据处理。如果未启动流式操作，则调用失败并返回具有回滚语义的错误码 ara::crypto::CryptoErrc::kProcessingNotStarted [SWS_CRYPT_50077]。
