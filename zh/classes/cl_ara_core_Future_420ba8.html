类 ara::core::Future 用作异步操作结果的接收端句柄，并管理对共享状态（Shared State）的访问 [SWS_CORE_00327]。消费者可以非阻塞地检查状态、同步等待完成，或者通过 GetResult() 以无异常方式作为 ara::core::Result 获取结果 [SWS_CORE_00336]。由于复制操作已被删除，所有权受到独占管理，并且在获取结果或通过 Continuation 转发之后，该对象会立即变为无效。

上下文

模板类 ara::core::Future 代表 AUTOSAR Adaptive Platform 内异步操作结果的接收端元素。它允许对由生成方实例异步填充的共享状态（Shared State）进行受控访问 [SWS_CORE_00327]。从概念上讲，该类实现了 C++17 标准 ISO/IEC 14882:2017 [11] 中的 std::future，但无缝集成到了平台的基于非异常错误的概念中：模板参数 E 必须指定错误类型 ara::core::ErrorCode；任何偏离的规范都会导致编译错误。主要交互方包括提供值或错误的异步生成方（例如关联的 Promise）、作为独占接收端的 Future 实例，以及后续任务所传递至的消费者或执行上下文 (ExecutorT) [SWS_CORE_00331] [SWS_CORE_00337]。

生命周期

ara::core::Future 的创建、状态管理和销毁遵循严格的规则，以确保确定性的所有权关系：

  • 创建：默认构造函数创建一个没有共享状态（Shared State）的空实例，对此 valid() == false 适用 [SWS_CORE_00322] [SWS_CORE_00327]。解释：有效实例通常由异步平台接口或耦合的 Promise 对象生成。
  • 所有权与转移：复制构造函数和复制赋值运算符被显式删除 (delete)，从而排除了复制访问句柄的可能性 [SWS_CORE_00334] [SWS_CORE_00335]。实例的移动（Move）可以通过移动构造函数和移动赋值运算符进行，并将共享状态（Shared State）的所有权完全转移 [SWS_CORE_00323] [SWS_CORE_00325]。
  • 状态与转换：状态分为无效 (valid() == false)、有效但待定 (valid() == true, is_ready() == false) 以及就绪 (valid() == true, is_ready() == true) [SWS_CORE_00327] [SWS_CORE_00332]。在通过 GetResult() 或 get() 成功获取结果后，以及通过 then() 转发后，对象将失去其状态并立即变为无效 (valid() == false) [SWS_CORE_00326] [SWS_CORE_00331] [SWS_CORE_00336] [SWS_CORE_00337]。
  • 销毁：析构函数 ~Future() 释放仍持有的共享状态（Shared State）[SWS_CORE_00333]。如果注册了延续函数（Continuations），则返回实例的析构函数将发生阻塞，直到已经运行的延续函数完全执行完毕 [SWS_CORE_00331] [SWS_CORE_00337]。
  • 并发性：状态方法 valid() 和 is_ready() 是线程安全的 [SWS_CORE_00327] [SWS_CORE_00332]。对于同一实例，所有其他接口（包括 wait()、wait_for()、wait_until()、GetResult()、get()、then() 以及析构函数）均不是线程安全的 [SWS_CORE_00323] [SWS_CORE_00325] [SWS_CORE_00326] [SWS_CORE_00328] [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00331] [SWS_CORE_00333] [SWS_CORE_00336] [SWS_CORE_00337]。

使用路径

用于结果处理的典型使用路径分为以下阶段：

  1. 状态检查与同步：可以使用 is_ready() 预先确定异步结果是否已经就绪 [SWS_CORE_00332]。如果已经就绪，后续获取保证不再阻塞 [SWS_CORE_00332]。否则，可以使用 wait() 进行无期限同步 [SWS_CORE_00328]，或通过 wait_for() 或 wait_until() 进行有时间限制的同步 [SWS_CORE_00329] [SWS_CORE_00330]。
  2. 结果提取：在 AUTOSAR Adaptive 应用程序中，调用 GetResult() 至关重要：该方法在需要时发生阻塞，但绝不抛出异常，并以 Move 方式将值或错误作为 ara::core::Result<T, E> 传递 [SWS_CORE_00336]。方法 get() 提供 STL 符合性，在出错时抛出 C++ 异常，并在工具链禁用异常处理时不参与重载决议 [SWS_CORE_00326]。
  3. 异步链式调用（Continuations）：除了同步阻塞之外，还可以通过 then() 注册回调，可选地分配给执行上下文（Executor）[SWS_CORE_00331] [SWS_CORE_00337]。回调将结果作为 Result<T, E> 右值接收。如果延续函数本身返回 Future 或 Result，则 then() 执行自动解包（Unwrapping）并直接提供相应的 Future<T2, E2> [SWS_CORE_00331] [SWS_CORE_00337]。

错误场景

在使用 ara::core::Future 时，规定了以下错误情况：

  • 在无效实例上调用：在无效实例 (valid() == false) 上调用 is_ready()、wait()、wait_for()、wait_until()、GetResult() 或 then() 构成 FutureInvalidViolation [SWS_CORE_00328] [SWS_CORE_00329] [SWS_CORE_00330] [SWS_CORE_00331] [SWS_CORE_00332] [SWS_CORE_00336] [SWS_CORE_00337]。在这种情况下调用 get() 时，将抛出带有错误码 kNoState 的 FutureException [SWS_CORE_00326]。
  • 废弃的共享状态（Broken Promise）：如果共享状态被关联的 Promise 提前放弃，GetResult() 将返回带有标准化错误码 FutureErrc::kBrokenPromise 的 Result [SWS_CORE_00336]。调用 get() 时会触发相应的异常 [SWS_CORE_00326]。
  • 延续函数中的异常：已注册的 Continuation 不得抛出异常，除非是为了实现 Violation。如果它仍然引发异常，将导致 FutureContinuationHasThrownViolation [SWS_CORE_00331] [SWS_CORE_00337]。闭包中的异常必须被捕获，并以 Result 或 Future 的形式作为错误状态返回 [SWS_CORE_00331] [SWS_CORE_00337]。

                  使用
                  

                  方法 get() 从 ara::core::Future 中同步检索类型为 T 的结果 [SWS_CORE_00326]。该函数的行为与 std::future 中的对应部分完全相同；如果异步计算仍在进行，调用将阻塞直到完成或直到发生错误 [SWS_CORE_00336]。通过该调用，对象会失去其状态，从而使 Future 立即失效（valid() == false）[SWS_CORE_00326]。可以通过 is_ready() 预先确保非阻塞调用 [SWS_CORE_00332]。
                  

                  错误处理
                  

                  失败会通过 C++ 异常进行报告 [SWS_CORE_00326]：
                  

                    

                  • 如果在关联的 Promise 中通过 SetError() 或 SetResult() 存放了错误，则会触发相应错误类型的异常 [SWS_CORE_00326]。
                    • 

                  • 如果共享状态被异步操作提前放弃，根据 FutureErrc 这会导致错误 kBrokenPromise [SWS_CORE_00326]、[SWS_CORE_00400]。
                    • 

                  • 如果调用是在无效实例上进行的，则抛出带有错误码 kNoState 的 FutureException [SWS_CORE_00326]。
                    • 

                  

                  并发性与限制
                  

                  该操作既不是线程安全的，也不是异常安全的（not exception safe）[SWS_CORE_00326]。从多个线程对同一个 Future 的并发访问需要外部同步。如果在编译器工具链中禁用了异常，则 get() 不参与重载解析 [SWS_CORE_00326]；针对这种情况存在无异常的替代方案 GetResult() [SWS_CORE_00336]。对于没有返回值的实例，可以使用特化 Future<void, E>::get() [SWS_CORE_06226]。
