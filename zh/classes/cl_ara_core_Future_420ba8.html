使用目的

ara::core::Future<T, E> 表示异步调用的后续可用结果或错误。错误类型必须是 ara::core::ErrorCode，否则需要 Compile-Time 错误。与 Promise 一起，该类型可以实现异步值和错误的线程安全、无异常处理。 [SWS_CORE_00321] [SWS_CORE_10800]

生命周期和所有权

禁止复制（=delete）；可以进行移动构建和移动分配。析构函数放弃每个Shared State。 GetResult()、get()和then()使原来的Future无效。 [SWS_CORE_00334][SWS_CORE_00335][SWS_CORE_00323][SWS_CORE_00325][SWS_CORE_00333][SWS_CORE_00336][SWS_CORE_00326][SWS_CORE_00337]

与其他班级的互动

GetResult() 会阻塞，直到出现值或错误并返回非触发Result<T,E>。 then() 通过此 Result 的函数生成后续的 Future； Executor 的重载在其执行上下文中执行该函数。 [SWS_CORE_00336][SWS_CORE_00331][SWS_CORE_00337]

限制&错误处理

如果相应的Promise被放弃，GetResult()返回错误FutureErrc::kBrokenPromise。在阻止之前，可以检查is_ready()；对于 true、get()、GetResult() 和 wait 调用不会阻塞。禁止对无效期货的调用被指定为违规行为。 [SWS_CORE_00336][SWS_CORE_00332][SWS_CORE_13011]

异步错误处理

Future 是异步调用的统一返回类型，可以返回值或失败。与get()相反，GetResult()在等待后返回带有值或错误的Result，并且不会触发异常。 RS General §4.1.2 “Error handling”EXP PlatformDesign §18.1.4 “Future and Promise”EXP ARAComAPI §5.3.6.2 “Event-Driven vs Polling access to method results”

与ara::com一起使用

在基于方法的通信中，Future/Promise模式支持非阻塞行为。对于结果的到达，可以使用阻塞等待、then()延续以及通过is_ready()轮询； is_ready()成功后，后续访问不被阻塞。 EXP ARAComAPI §4.4 “Method based communication”EXP ARAComAPI §5.3.6.2 “Event-Driven vs Polling access to method results”

公共状态和错误传输

功能规范将Future和Promise视为错误路径的异步对应部分：后面的结果可以表示值或错误，而无需将错误处理与返回分开。 SWS Core §7.2 “Error handling”SWS Core §7.2.5.5 “Future and Promise”

发生错误时的行为

GetResult() 阻塞，直到值或错误可用为止，并将共享状态的内容返回为Result<T,E>；因此，SetError() 设置的错误仍保留在结果路径中。如果共享状态被相应的Promise放弃，则GetResult()返回FutureErrc::kBrokenPromise。相反，get()将共享状态中的错误传输为Exception；如果 Future 无效，则将 kNoState 包含在那里。 [SWS_CORE_00336][SWS_CORE_00326][SWS_CORE_00400]

wait_for() 最多等待传输的持续时间，wait_until() 最多等待截止时间。两者都返回FutureStatus； kTimeout 专门表示 Shared State 未在各自的截止日期内准备好。因此，必须将超时与结果中传输的错误区分开来。 [SWS_CORE_00329][SWS_CORE_00330][SWS_CORE_00361]

该错误从 Shared State 读取为 Result；替代字段显示因放弃Promise而导致的错误以及单独的等待超时。来源：[SWS_CORE_00336][SWS_CORE_00329][SWS_CORE_00330]。

then()将GetResult()为此Future交付的Result准确地传递到其延续；因此，延续可以评估错误并将其作为Result或后续的Future传递。根据then()，原Future无效。从延续中逃逸的异常被指定为违规；为了传递错误，应该将其翻译为错误。 [SWS_CORE_00337][SWS_CORE_00331]

API 合同中指定的状态 future_already_retrieved 和 promise_already_satisfied 在 R25-11 中显示为违规描述。访问无效的 Future 也设置了违规；仅 get() 指定 FutureException 和 kNoState。 [SWS_CORE_13013] [SWS_CORE_13014] [SWS_CORE_13015] [SWS_CORE_00326]

Create a new Future with the content returned by func when passed the Result of this Future. The callable func may be called in the context of this call or in the context of • Promise::set_result(const T&) • Promise::set_result(T&&) • Promise::SetError(E&&) • Promise::SetError(const E&) or somewhere else.

valid() ==FALSE on the original Future object immediately after it returns.

The Callable input argument func takes a Result<T,E> object as parameter. This will be the Result obtained via GetResult() from the Future instance itself, on which then(...) is being called. The Result is passed to func as an rvalue expression.

The return type of then(...) depends on the return type of func (aka continuation).

Let U be the return type of the continuation (i.e. a type equivalent to std::invoke_result_ t<std::decay_t<F>,Result<T,E>>). Return type deduction: • If U is Future<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. This is known as implicit Future unwrapping. • If U is Result<T2,E2> for some types T2, E2, then the return type of then(...) is Future<T2,E2>. No such continuation shall be executed after the destructor of the Future F returns. A continuation that is already being executed shall run to completion.
