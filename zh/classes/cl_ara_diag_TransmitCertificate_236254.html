使应用程序能够在 UDS 服务 Authentication 中接收并校验诊断证书。

类 ara::diag::TransmitCertificate 实现了服务 Authentication [SWS_DM_01961] 的 UDS 子功能 TransmitCertificate（0x29 0x04）的应用程序接口。通过 Offer() 发布后，应用程序在异步方法 Process() 中接收传输的证书数据，并启动特定于应用程序的验证 [SWS_DM_01968]。校验成功时，Diagnostic Management 会促成带有返回参数 0x13（CertificateVerified）的 UDS 肯定响应，而错误则以带有相应 NRC 的否定响应予以应答。该实例固定绑定到一个端口接口，既不可复制也不可移动。

上下文

头文件 ara/diag/transmit_certificate.h（AUTOSAR_AP_SWS_Diagnostics §8.26 “Header: ara/diag/transmit_certificate.h”）中的类 ara::diag::TransmitCertificate [SWS_DM_01961] 代表 Adaptive 应用程序用于实现服务 Authentication 的 UDS 子功能 TransmitCertificate（0x29 0x04）的接口。作为通用接口，它使应用程序能够根据 16 位标识符（certificateEvaluationId）接收并处理一个或多个传输的证书。

交互涉及三个主要组件：

  • 外部诊断测试仪：向车辆发送用于证书传输的 UDS 请求 [SWS_DM_01968]。
  • Adaptive Platform 的 Diagnostic Server（Diagnostic Management，DM）：过滤并转发传入的诊断请求，并生成最终的 UDS 响应 [SWS_DM_01251]，[SWS_DM_01969]。
  • Adaptive 应用程序：提供派生自 ara::diag::TransmitCertificate 的实例，执行证书校验并将结果异步返回给服务器 [SWS_DM_01968]。

上下文图：通过 UDS 0x29 04 进行证书传输所涉及的组件。来源：[SWS_DM_01968]，[SWS_DM_01969]，AUTOSAR_AP_SWS_Diagnostics §7.3.2.8 “Successful verification of transmitCertificate”。

生命周期

ara::diag::TransmitCertificate 的实例通过构造函数在指定 ara::core::InstanceSpecifier 以及并发模式 ConcurrencyType 的情况下创建 [SWS_DM_01962]。InstanceSpecifier 必须在清单中引用一个由 DiagnosticTransmitCertificateInterface 定型的 PortPrototype [SWS_DM_01962]。如果该映射失败，或者实例标识符在当前进程中被多次使用，则会出现 InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation 或 InstanceSpecifierAlreadyInUseViolation 等运行时违规 [SWS_DM_01962]。

该类遵循严格的所有权和实例化规则：身份验证处理程序被设计为唯一、不可复制且不可移动的实例。相应地，复制构造函数 [SWS_DM_01964]、复制赋值运算符 [SWS_DM_01966] 以及移动构造函数 [SWS_DM_01963] 和移动赋值运算符 [SWS_DM_01965] 均被显式删除（=delete）。

构造函数本身被指定为线程安全且异常安全 [SWS_DM_01962]。释放通过虚拟默认析构函数 [SWS_DM_01967] 进行。实际执行方法 Process 是否必须以线程安全的方式实现，取决于所选的 concurrencyType（kConcurrent 或 kNotConcurrent）[SWS_DM_01962]，[SWS_DM_01968]。

使用路径

常规流程包括处理程序的注册、传入证书的处理以及后续的注销：

  1. 提供服务（Offer）：应用程序调用 Offer()，以向 Diagnostic Management 发送信号，指示允许将针对已配置接口的请求转发至该处理程序 [SWS_DM_01969]。
  2. 接收请求（Process）：当子功能 TransmitCertificate 的 UDS 请求到达 Diagnostic Server 时，该服务器会将数据转发给应用程序的纯虚方法 Process() [SWS_DM_01968]。该方法接收 16 位标识符 certificateEvaluationId、作为 ara::core::Span<ara::core::Byte const> 的证书原始数据、元数据（metaInfo）以及一个 cancellationHandler [SWS_DM_01968]。
  3. 评估与操作：由于 AUTOSAR 未对证书规定固定语义，因此校验及推导必要措施完全由应用程序负责 [SWS_DM_01968]。解释：应用程序通常会对传输的证书进行加密验证，或用于更新内部密钥存储。
  4. 结果传输：该方法返回一个 ara::core::Future<void> [SWS_DM_01968]。若应用程序成功完成该 Future 且无错误，则 Diagnostic Server 会向测试仪发送肯定 UDS 响应，其中参数 authenticationReturnParameter（RV）被设置为值 0x13（CertificateVerified）[SWS_DM_01251]（AUTOSAR_AP_SWS_Diagnostics §7.3.2.8 “Successful verification of transmitCertificate”）。
  5. 停止服务（StopOffer）：若处理程序不再接收更多请求，应用程序通过调用 StopOffer() 终止转发 [SWS_DM_01970]。

时序图：从 Offer 到 UDS 响应的证书传输典型流程。来源：[SWS_DM_01968]，[SWS_DM_01969]，[SWS_DM_01970]，[SWS_DM_01249]，[SWS_DM_01251]。

错误场景

错误状态可能在生命周期的不同阶段发生：

  • 已激活的提供：如果在该实例的服务已处于激活提供状态时调用 Offer()，则调用失败并在 ara::core::Result<void> 中返回具有回滚语义的错误代码 DiagOfferErrc::kAlreadyOffered [SWS_DM_01969]。Offer() 和 StopOffer() 不是线程安全的，不得并发调用 [SWS_DM_01969]，[SWS_DM_01970]。
  • 证书校验失败：若应用程序在 Process() 的评估中发现错误，它将根据 ISO 14229-1 使用来自 DiagUdsNrcErrc 的相应错误代码完成 Future [SWS_DM_01968]。Diagnostic Server 捕获该返回值并向测试仪发送否定诊断响应（Negative Response），其否定响应码（NRC）与传输的错误代码完全对应 [SWS_DM_01249]（AUTOSAR_AP_SWS_Diagnostics §7.3.2.8 “Handling Negative return values of ara::diag::TransmitCertificate::Process method”）。
  • 中断正在进行的会话：在异步处理期间，应用程序可通过 cancellationHandler.IsCanceled() 查询状态，以确定诊断会话是否已中断 [SWS_DM_01968]。此外，可通过 cancellationHandler.SetNotifier(...) 注册一个回调函数，该函数在发生中断时立即得到通知 [SWS_DM_01968]。

通过方法 Offer，Adaptive Application 激活 Diagnostic Management（DM）向类 ara::diag::TransmitCertificate 的负责处理程序转发诊断请求 [SWS_DM_01969]。调用以同步且无参数的方式进行；接口被定义为异常安全（noexcept）[SWS_DM_01969]。返回类型为 ara::core::Result<void>，用于向调用者传达注册成功或错误状态 [SWS_DM_01969]。

如果之前已针对相关处理程序实例调用过该函数，则再次调用将失败并返回带有回滚语义的特定错误 DiagOfferErrc::kAlreadyOffered [SWS_DM_01969]，该错误对应于 DiagErrc 中的标准化错误值 [SWS_DM_00514]。由于该方法被显式指定为非线程安全 [SWS_DM_01969]，因此必须避免在同一实例上进行并发访问（Interpretation：防止并发调用属于使用该接口的软件的职责）。

Offer 的功能模式遵循诊断处理程序的统一提供概念，这同样应用于 ara::diag::Authentication::Offer [SWS_DM_01130]、ara::diag::CommunicationControl::Offer [SWS_DM_00809] 或 ara::diag::GenericRoutine::Offer [SWS_DM_00557]。AUTOSAR 明确指出，尽管同名借鉴了 ara::com，但这属于独立的诊断实现（AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 “Monitors”）。在通过 Offer 提供之前，DM 不会向处理程序转发任何请求，类似于 DoIP 服务在调用前被视为未就绪 [SWS_DM_01525]。

          类 ara::diag::TransmitCertificate（[SWS_DM_01970]）的方法 StopOffer 终止为 Diagnostic Management（DM）提供证书传输服务。通过调用，停用 DM 向此处理程序转发传入的诊断请求消息（[SWS_DM_01970]）。
          


          用法与语义
          

          该调用通过头文件 ara/diag/transmit_certificate.h（[SWS_DM_01970]）中的签名 void StopOffer() noexcept; 无参数进行。该函数无返回值，并被指定为 noexcept 以及 exception safe（[SWS_DM_01970]），因此保证不抛出异常。
          


          并发性与限制
          

          该方法被显式指定为 not thread-safe（[SWS_DM_01970]）。因此，调用者必须确保通过外部机制同步对 ara::diag::TransmitCertificate 的同一实例的并发调用。Interpretation：在销毁服务实例之前或在临时停用时，大概会调用 StopOffer，以防止在状态更改期间有新请求到达。
          


          相互作用
