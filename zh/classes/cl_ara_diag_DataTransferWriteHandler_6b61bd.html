上下文

类 ara::diag::DataTransferWriteHandler [SWS_DM_01539] 在自适应诊断架构（ara::diag）中充当处理传入写传输 AUTOSAR AP SWS Diagnostics §8.10.6 “Class: DataTransferWriteHandler” 的专用接口。它用于处理由操作模式 AddFile、ResumeFile 或 ReplaceFile 下的诊断 RequestWriteFile 请求所触发的数据传输。

执行写传输涉及三个主要实体：

  • 外部 UDS-Client，负责请求文件传输并通过诊断消息逐块传输写入数据 [SWS_DM_01546]。
  • 平台的诊断管理（ara::diag），负责管理传输层和协议层上的通信并协调传输。
  • 具体的应用软件，继承自 DataTransferWriteHandler 并将传输的文件块持久化到本地存储或进行处理 [SWS_DM_01546]。

上下文图：基于文件的写传输中 DataTransferWriteHandler 类的交互伙伴。来源：[SWS_DM_01539]、[SWS_DM_01546]、AUTOSAR AP SWS Diagnostics §8.10.6 “Class: DataTransferWriteHandler”。

生命周期

DataTransferWriteHandler 的实例遵循严格的、会话绑定的生命周期。它们专门设计用于单个文件传输会话期间的单向使用（“one way usage i.e. per single file transfer session”）[SWS_DM_01544]、[SWS_DM_01545]。

  • 创建：默认构造函数 DataTransferWriteHandler() 为 protected 并被声明为 default 和 noexcept [SWS_DM_01540]。因此，实例化始终通过应用特定的派生子类进行；解释：Handler 实例的提供可能在写请求开始时由应用逻辑完成。
  • 复制与移动：禁止复制 Handler：复制构造函数 [SWS_DM_01544] 和复制赋值运算符 [SWS_DM_01545] 均被显式删除（=delete）AUTOSAR AP SWS Diagnostics §8.10.6.1.2 “Constructors”。相反，移动语义得到完全支持；移动构造函数 [SWS_DM_01542] 和移动赋值 [SWS_DM_01543] 通过 =default 和 noexcept 定义 AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”。
  • 析构与前置条件：虚析构函数 ~DataTransferWriteHandler() 具有异常安全性（noexcept）[SWS_DM_01541] AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”。作为显式前置条件，在调用终止方法 ExitWrite() 之前不得销毁该类的实例 [SWS_DM_01541]。
  • 并发性：方法 Write()、ExitWrite() 及析构函数被指定为非线程安全（not thread-safe）[SWS_DM_01541]、[SWS_DM_01546]、[SWS_DM_01547]。解释：对 Handler 实例的调用可能按顺序来自诊断框架的同一处理上下文。

使用路径

文件写传输的常规流程分为重复的数据接收和有序的会话终止：

  1. 接收文件内容：一旦从 UDS-Client 收到第一个或后续文件块，诊断系统就会调用方法 Write(requestData, metaInfo, cancellationHandler) [SWS_DM_01546] AUTOSAR AP SWS Diagnostics §8.10.6.1.3.2 “Write”。应用程序接收原始数据（ara::core::Span<ara::core::Byte>）并将其写入指定的缓冲区。传入的数据在返回的 ara::core::Future<void> 被满足或操作被取消之前保持有效 [SWS_DM_01546]。
  2. 迭代传输：对于文件的每个后续数据块，此步骤按顺序重复进行。
  3. 终止传输会话：在所有块到达之后或发生取消时，平台会调用 ExitWrite(exitType, transferRequestParameterRecord, metaInfo, cancellationHandler) [SWS_DM_01547] AUTOSAR AP SWS Diagnostics §8.10.6.1.3.1 “ExitWrite”。此时会传递终止原因（DataTransferExitType）以及厂商特定参数。
  4. 终止响应：该方法返回一个 ara::core::Future<ara::core::Vector<ara::core::Byte>>。成功完成时，其中包含的数据作为 transferResponseParameterRecord 直接放置在肯定响应消息中 SID 的后面 [SWS_DM_01547]。
  5. 释放实例：只有在调用 ExitWrite() 之后，才允许销毁 Handler [SWS_DM_01541]。

时序图：逐块写入和有序终止传输会话时的典型调用流程。来源：[SWS_DM_01546]、[SWS_DM_01547]、[SWS_DM_01541]、AUTOSAR AP SWS Diagnostics §8.10.6.1.3.1 “ExitWrite”、AUTOSAR AP SWS Diagnostics §8.10.6.1.3.2 “Write”。

错误场景

错误和取消状态通过 Future 返回值和 CancellationHandler 进行异步控制：

  • 否定响应码（NRC）：如果写操作或终止操作无法成功执行，应用程序将通过使用相应的错误码（根据 ISO 14229-1 来自 DiagUdsNrcErrc 的 ErrorCode）完成 ara::core::Future 来发出此信号 [SWS_DM_01546]、[SWS_DM_01547]。这会促使诊断框架发送 UDS Negative Response Message。
  • 取消处理：Write() 和 ExitWrite() 中的参数 cancellationHandler 允许应用程序在耗时的写操作之前或期间通过 cancellationHandler.IsCanceled() 查询会话是否已被取消 [SWS_DM_01546]、[SWS_DM_01547]。或者，可以通过 cancellationHandler.SetNotifier 注册一个通知函数，该函数在连接中断时被主动调用。
  • 过早销毁：如果在执行 ExitWrite() 之前销毁了 DataTransferWriteHandler 的实例，则调用组件违反了接口的契约前置条件 [SWS_DM_01541]。

<h4>上下文</h4>
<p>类 <code>ara::diag::DataTransferWriteHandler</code> <a class="spec-record-ref" data-req="SWS_DM_01539" href="../spec/record.html?id=SWS_DM_01539">[SWS_DM_01539]</a> 在自适应诊断架构（<code>ara::diag</code>）中充当处理传入写传输 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=387">AUTOSAR AP SWS Diagnostics §8.10.6 “Class: DataTransferWriteHandler”</a> 的专用接口。它用于处理由操作模式 <code>AddFile</code>、<code>ResumeFile</code> 或 <code>ReplaceFile</code> 下的诊断 <code>RequestWriteFile</code> 请求所触发的数据传输。</p>
<p>执行写传输涉及三个主要实体：</p>
<ul>
  <li>外部 <strong>UDS-Client</strong>，负责请求文件传输并通过诊断消息逐块传输写入数据 <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>。</li>
  <li>平台的<strong>诊断管理</strong>（<code>ara::diag</code>），负责管理传输层和协议层上的通信并协调传输。</li>
  <li>具体的<strong>应用软件</strong>，继承自 <code>DataTransferWriteHandler</code> 并将传输的文件块持久化到本地存储或进行处理 <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>。</li>
</ul>

<h4>生命周期</h4>
<p><code>DataTransferWriteHandler</code> 的实例遵循严格的、会话绑定的生命周期。它们专门设计用于单个文件传输会话期间的单向使用（“one way usage i.e. per single file transfer session”）<a class="spec-record-ref" data-req="SWS_DM_01544" href="../spec/record.html?id=SWS_DM_01544">[SWS_DM_01544]</a>、<a class="spec-record-ref" data-req="SWS_DM_01545" href="../spec/record.html?id=SWS_DM_01545">[SWS_DM_01545]</a>。</p>
<ul>
  <li><strong>创建：</strong>默认构造函数 <code>DataTransferWriteHandler()</code> 为 <code>protected</code> 并被声明为 <code>default</code> 和 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_01540" href="../spec/record.html?id=SWS_DM_01540">[SWS_DM_01540]</a>。因此，实例化始终通过应用特定的派生子类进行；解释：Handler 实例的提供可能在写请求开始时由应用逻辑完成。</li>
  <li><strong>复制与移动：</strong>禁止复制 Handler：复制构造函数 <a class="spec-record-ref" data-req="SWS_DM_01544" href="../spec/record.html?id=SWS_DM_01544">[SWS_DM_01544]</a> 和复制赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_01545" href="../spec/record.html?id=SWS_DM_01545">[SWS_DM_01545]</a> 均被显式删除（<code>=delete</code>）<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR AP SWS Diagnostics §8.10.6.1.2 “Constructors”</a>。相反，移动语义得到完全支持；移动构造函数 <a class="spec-record-ref" data-req="SWS_DM_01542" href="../spec/record.html?id=SWS_DM_01542">[SWS_DM_01542]</a> 和移动赋值 <a class="spec-record-ref" data-req="SWS_DM_01543" href="../spec/record.html?id=SWS_DM_01543">[SWS_DM_01543]</a> 通过 <code>=default</code> 和 <code>noexcept</code> 定义 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”</a>。</li>
  <li><strong>析构与前置条件：</strong>虚析构函数 <code>~DataTransferWriteHandler()</code> 具有异常安全性（<code>noexcept</code>）<a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=388">AUTOSAR AP SWS Diagnostics §8.10.6.1.1 “Special Member Functions”</a>。作为显式前置条件，在调用终止方法 <code>ExitWrite()</code> 之前不得销毁该类的实例 <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>。</li>
  <li><strong>并发性：</strong>方法 <code>Write()</code>、<code>ExitWrite()</code> 及析构函数被指定为非线程安全（<code>not thread-safe</code>）<a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>、<a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>、<a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>。解释：对 Handler 实例的调用可能按顺序来自诊断框架的同一处理上下文。</li>
</ul>

<h4>使用路径</h4>
<p>文件写传输的常规流程分为重复的数据接收和有序的会话终止：</p>
<ol>
  <li><strong>接收文件内容：</strong>一旦从 UDS-Client 收到第一个或后续文件块，诊断系统就会调用方法 <code>Write(requestData, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=390">AUTOSAR AP SWS Diagnostics §8.10.6.1.3.2 “Write”</a>。应用程序接收原始数据（<code>ara::core::Span&lt;ara::core::Byte&gt;</code>）并将其写入指定的缓冲区。传入的数据在返回的 <code>ara::core::Future&lt;void&gt;</code> 被满足或操作被取消之前保持有效 <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>。</li>
  <li><strong>迭代传输：</strong>对于文件的每个后续数据块，此步骤按顺序重复进行。</li>
  <li><strong>终止传输会话：</strong>在所有块到达之后或发生取消时，平台会调用 <code>ExitWrite(exitType, transferRequestParameterRecord, metaInfo, cancellationHandler)</code> <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a> <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=389">AUTOSAR AP SWS Diagnostics §8.10.6.1.3.1 “ExitWrite”</a>。此时会传递终止原因（<code>DataTransferExitType</code>）以及厂商特定参数。</li>
  <li><strong>终止响应：</strong>该方法返回一个 <code>ara::core::Future&lt;ara::core::Vector&lt;ara::core::Byte&gt;&gt;</code>。成功完成时，其中包含的数据作为 <code>transferResponseParameterRecord</code> 直接放置在肯定响应消息中 SID 的后面 <a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>。</li>
  <li><strong>释放实例：</strong>只有在调用 <code>ExitWrite()</code> 之后，才允许销毁 Handler <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>错误和取消状态通过 <code>Future</code> 返回值和 <code>CancellationHandler</code> 进行异步控制：</p>
<ul>
  <li><strong>否定响应码（NRC）：</strong>如果写操作或终止操作无法成功执行，应用程序将通过使用相应的错误码（根据 ISO 14229-1 来自 <code>DiagUdsNrcErrc</code> 的 <code>ErrorCode</code>）完成 <code>ara::core::Future</code> 来发出此信号 <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>、<a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>。这会促使诊断框架发送 UDS Negative Response Message。</li>
  <li><strong>取消处理：</strong><code>Write()</code> 和 <code>ExitWrite()</code> 中的参数 <code>cancellationHandler</code> 允许应用程序在耗时的写操作之前或期间通过 <code>cancellationHandler.IsCanceled()</code> 查询会话是否已被取消 <a class="spec-record-ref" data-req="SWS_DM_01546" href="../spec/record.html?id=SWS_DM_01546">[SWS_DM_01546]</a>、<a class="spec-record-ref" data-req="SWS_DM_01547" href="../spec/record.html?id=SWS_DM_01547">[SWS_DM_01547]</a>。或者，可以通过 <code>cancellationHandler.SetNotifier</code> 注册一个通知函数，该函数在连接中断时被主动调用。</li>
  <li><strong>过早销毁：</strong>如果在执行 <code>ExitWrite()</code> 之前销毁了 <code>DataTransferWriteHandler</code> 的实例，则调用组件违反了接口的契约前置条件 <a class="spec-record-ref" data-req="SWS_DM_01541" href="../spec/record.html?id=SWS_DM_01541">[SWS_DM_01541]</a>。</li>
</ul>
