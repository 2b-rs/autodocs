在写入文件传输时，在应用程序中处理并保存传入的数据块。

类 ara::diag::DataTransferWriteHandler 在 AUTOSAR Adaptive 中用于在应用程序端处理由 RequestWriteFile 在模式 AddFile、ResumeFile 或 ReplaceFile 下发起的写入文件传输 [SWS_DM_01539]。传入的数据包通过 Write() 异步写入内存，随后使用 ExitWrite() 结束会话。实例严格绑定至单个传输会话，绝不能在调用 ExitWrite() 之前被销毁 [SWS_DM_01541]。

上下文

抽象基类 ara::diag::DataTransferWriteHandler 在 AUTOSAR Adaptive Platform 中定义了用于写入文件传输的接口 [SWS_DM_01539]（AUTOSAR_AP_SWS_Diagnostics §8.10.6 “Class: DataTransferWriteHandler”）。它用于在应用程序端处理在 RequestWriteFile 框架下通过操作模式 AddFile、ResumeFile 或 ReplaceFile 发起的数据传输。

在诊断架构内部，该处理程序与外部 UDS 客户端、诊断中间件以及应用程序进行交互。客户端传输分段的数据块，这些数据块由该处理程序的派生实现接收并存储在应用程序内存中 [SWS_DM_01546]。据推测，平台的 Diagnostic Management 在此过程中承担 UDS 协议协调工作，并通过处理程序接口将有效载荷传递给目标应用程序。

生命周期

ara::diag::DataTransferWriteHandler 的实例化仅通过应用程序的专用子类进行：无参构造函数定义为 protected 和 noexcept=default [SWS_DM_01540]，这阻止了基类的直接实例化。处理程序实例严格绑定至单个文件传输会话（“one way usage i.e. per single file transfer session”）。出于此原因，复制构造函数 [SWS_DM_01544]（AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.2.1 “DataTransferWriteHandler”）和复制赋值运算符 [SWS_DM_01545] 被删除（=delete）。

相比之下，移动操作是允许的：移动构造函数 [SWS_DM_01542]（AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.1 “Move Constructor”）和移动赋值运算符 [SWS_DM_01543] 均以 noexcept=default 实现，并被视为具备异常安全性（exception safe）。

对于实例的析构存在具有约束力的前置条件：在调用方法 ExitWrite() 之前，绝不能销毁该类的实例 [SWS_DM_01541]（AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.1.2 “Destructor”）。只有在完全执行 ExitWrite() 之后，才允许调用虚析构函数 ~DataTransferWriteHandler()。成员函数和析构函数被指定为非线程安全（not thread-safe）[SWS_DM_01541]、[SWS_DM_01546]、[SWS_DM_01547]。

使用路径

写入传输的常规流程包括逐步接收数据块以及随后的会话结束：

  • 对于每个到达的数据段，诊断系统都会调用纯虚方法 Write() [SWS_DM_01546]（AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.2 “Write”）。数据作为 ara::core::Span<ara::core::Byte> 传递。该内存区域的有效性保持至关联的 Promise 完成或操作被取消为止。应用程序将数据追加到内部缓冲区并返回一个 ara::core::Future<void>。
  • 在所有分段均已传输后，平台调用纯虚方法 ExitWrite() [SWS_DM_01547]（AUTOSAR_AP_SWS_Diagnostics §8.10.6.1.3.1 “ExitWrite”）。传入的参数包括终止原因（DataTransferExitType）、整车制造商特定参数（transferRequestParameterRecord）、metaInfo 以及一个 CancellationHandler。
  • 方法 ExitWrite() 返回一个 ara::core::Future<ara::core::Vector<ara::core::Byte>>。在成功完成时，其中包含的数据作为 transferResponseParameterRecord 插入到服务 ID 之后的 UDS 肯定响应消息中 [SWS_DM_01547]。

时序图：传输会话期间 Write 和 ExitWrite 操作的调用时序。来源：[SWS_DM_01546]、[SWS_DM_01547]。

错误场景

数据处理和传输过程中的错误通过标准化的返回值和取消机制进行管理：

  • 如果写入数据块或结束传输失败，则为相应的 Future 提供来自 DiagUdsNrcErrc 的 ara::core::ErrorCode [SWS_DM_01546]、[SWS_DM_01547]。这会导致向客户端生成相应的 UDS 否定响应（符合 ISO 14229-1 的 NRC）。
  • 两种方法均提供一个 CancellationHandler。应用程序可以通过 cancellationHandler.IsCanceled() 检查对话是否已取消，或者通过 cancellationHandler.SetNotifier() 注册在对话取消时执行的通知函数 [SWS_DM_01546]、[SWS_DM_01547]。
  • 如果在调用 ExitWrite() 之前销毁实例，则构成对所指定生命周期规则的违反 [SWS_DM_01541]，这据推测会导致未定义系统状态和不完整的文件。此外，由于该接口显式为非线程安全，未受保护的并发访问会导致数据不一致。
