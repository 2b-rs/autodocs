上下文

生成的类 <SI-Namespace>::proxy::triggers::<Trigger> 代表在 ServiceInterface 中定义的处于 trigger 角色的 Trigger 元素的客户端接口 AUTOSAR AP SWS CommunicationManagement 第39页。与传输序列化有效载荷的基于事件的机制（Events）不同，Trigger 仅用于在不带应用数据的情况下通知事件的发生。交互伙伴包括 Proxy 应用程序（Client）、用于传输信号的中间件 Communication Management（ara::com）以及用于解耦异步任务的可选执行上下文（ExecutorT）[SWS_CM_00352]、[SWS_CM_01106]。此外，还存在一个用于端到端保护（E2E）的接口，以便接收传输错误 [SWS_CM_00106]。

生命周期

Trigger 实例推测作为成员对象与上层 Service-Proxy 的生命周期紧密绑定，并与其一同实例化和释放。该类被声明为 final。功能生命周期主要由订阅状态（ara::com::SubscriptionState）决定 [SWS_CM_01105]：

  • 未订阅：实例的初始状态。在此状态下调用 Unsubscribe() 不会产生任何效果并立即返回 [SWS_CM_00810]。
  • 已请求订阅：通过调用 Subscribe() [SWS_CM_00723] 发起向 Communication Management 的订阅。状态转换为 kSubscriptionPending 或直接转换为 kSubscribed。若调用 Subscribe() 时 Trigger 已处于 kSubscribed 或 kSubscriptionPending，该方法将不执行任何操作直接返回 [SWS_CM_00723]。
  • 已订阅（kSubscribed）：主动接收服务提供者的触发器信号。当前状态可以通过 GetSubscriptionState() 同步查询 [SWS_CM_01105]。状态变化可通过已注册的处理程序进行异步跟踪 [SWS_CM_01107]。
  • 取消订阅：通过调用 Unsubscribe() [SWS_CM_00810] 终止传递，并将触发器恢复到未订阅状态。

状态图：触发器订阅的状态转换。来源：[SWS_CM_00723]、[SWS_CM_00810]、[SWS_CM_01105]

使用路径

使用代理触发器的典型调用序列分为配置、订阅、信号处理和清理：

  1. 处理程序注册：应用程序可根据需要预先注册通知回调。通过 SetReceiveHandler() 注册一个无参数函数，当触发器到达时由 Communication Management 调用 [SWS_CM_00250]。对于在专用线程上下文中执行，提供了带有 ExecutorT 的模板重载 [SWS_CM_00352]。订阅的状态更改可通过 SetSubscriptionStateChangeHandler() 进行监控 [SWS_CM_01107]、[SWS_CM_01106]，而传输错误则通过 SetTransportFaultConditionHandler() 进行报告 [SWS_CM_00106]、[SWS_CM_00107]。
  2. 激活订阅：应用程序调用 Subscribe() [SWS_CM_00723] 以启动信号通知。
  3. 信号检索与计数器更新：当触发器到达时，Communication Management 调用 TriggerReceiveHandler [SWS_CM_00250]。应用程序在处理程序内部或周期性调用 GetNewTriggers() [SWS_CM_00226]。该方法读取自上次调用以来到达的触发器数量并更新计数器。返回值 0 表示自那时起未接收到新的触发器 [SWS_CM_00226]。
  4. 终止订阅与注销：为了终止接收，应用程序调用 Unsubscribe() [SWS_CM_00810]。已注册的处理程序可通过 UnsetReceiveHandler() [SWS_CM_11614]、UnsetSubscriptionStateChangeHandler() [SWS_CM_01108] 以及 UnsetTransportFaultConditionHandler() [SWS_CM_00108] 进行重置。

顺序图：处理程序注册、订阅、触发器接收和计数器查询的流程。来源：[SWS_CM_00226]、[SWS_CM_00250]、[SWS_CM_00723]、[SWS_CM_00810]

错误场景

触发器类的方法主要声明为 noexcept 并被指定为异常安全 [SWS_CM_00226]、[SWS_CM_00723]、[SWS_CM_00810]、[SWS_CM_01105]。定义了以下错误情况和违规（Violations）：

  • 无效回调（InvalidHandlerViolation）：如果向 SetReceiveHandler() [SWS_CM_00250]、[SWS_CM_00352]、SetSubscriptionStateChangeHandler() [SWS_CM_01107]、[SWS_CM_01106] 或 SetTransportFaultConditionHandler() [SWS_CM_00106]、[SWS_CM_00107] 传递了一个不存在或空的可调用对象（空处理程序），系统将报告 InvalidHandlerViolation。
  • 缺少访问权限（InsufficientPermissionsViolation）：如果 Grant Enforcement 拒绝了对触发器元素的访问权限，则对 Subscribe() 的调用将被拒绝并带有 InsufficientPermissionsViolation [SWS_CM_00723]。
  • 移除接收处理程序时的异常安全性：与方法 UnsetSubscriptionStateChangeHandler() [SWS_CM_01108] 和 UnsetTransportFaultConditionHandler() [SWS_CM_00108] 不同，UnsetReceiveHandler() 被指定为 not exception safe [SWS_CM_11614]。
  • 网络层传输错误：端到端传输中的错误通过经由 SetTransportFaultConditionHandler() 注册的处理程序进行异步通知 [SWS_CM_00106]。

<h4>上下文</h4>
<p>生成的类 <code>&lt;SI-Namespace&gt;::proxy::triggers::&lt;Trigger&gt;</code> 代表在 <code>ServiceInterface</code> 中定义的处于 <em>trigger</em> 角色的 Trigger 元素的客户端接口 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=39">AUTOSAR AP SWS CommunicationManagement 第39页</a>。与传输序列化有效载荷的基于事件的机制（Events）不同，Trigger 仅用于在不带应用数据的情况下通知事件的发生。交互伙伴包括 Proxy 应用程序（Client）、用于传输信号的中间件 Communication Management（<code>ara::com</code>）以及用于解耦异步任务的可选执行上下文（<code>ExecutorT</code>）<a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>、<a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a>。此外，还存在一个用于端到端保护（E2E）的接口，以便接收传输错误 <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>。</p>

<h4>生命周期</h4>
<p>Trigger 实例推测作为成员对象与上层 Service-Proxy 的生命周期紧密绑定，并与其一同实例化和释放。该类被声明为 <code>final</code>。功能生命周期主要由订阅状态（<code>ara::com::SubscriptionState</code>）决定 <a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>：</p>
<ul>
<li><strong>未订阅：</strong>实例的初始状态。在此状态下调用 <code>Unsubscribe()</code> 不会产生任何效果并立即返回 <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>。</li>
<li><strong>已请求订阅：</strong>通过调用 <code>Subscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a> 发起向 Communication Management 的订阅。状态转换为 <code>kSubscriptionPending</code> 或直接转换为 <code>kSubscribed</code>。若调用 <code>Subscribe()</code> 时 Trigger 已处于 <code>kSubscribed</code> 或 <code>kSubscriptionPending</code>，该方法将不执行任何操作直接返回 <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>。</li>
<li><strong>已订阅（<code>kSubscribed</code>）：</strong>主动接收服务提供者的触发器信号。当前状态可以通过 <code>GetSubscriptionState()</code> 同步查询 <a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>。状态变化可通过已注册的处理程序进行异步跟踪 <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>。</li>

</ul>

<h4>使用路径</h4>
<p>使用代理触发器的典型调用序列分为配置、订阅、信号处理和清理：</p>
<ol>
<li><strong>处理程序注册：</strong>应用程序可根据需要预先注册通知回调。通过 <code>SetReceiveHandler()</code> 注册一个无参数函数，当触发器到达时由 Communication Management 调用 <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>。对于在专用线程上下文中执行，提供了带有 <code>ExecutorT</code> 的模板重载 <a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>。订阅的状态更改可通过 <code>SetSubscriptionStateChangeHandler()</code> 进行监控 <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>、<a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a>，而传输错误则通过 <code>SetTransportFaultConditionHandler()</code> 进行报告 <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>、<a class="spec-record-ref" data-req="SWS_CM_00107" href="../spec/record.html?id=SWS_CM_00107">[SWS_CM_00107]</a>。</li>
<li><strong>激活订阅：</strong>应用程序调用 <code>Subscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a> 以启动信号通知。</li>
<li><strong>信号检索与计数器更新：</strong>当触发器到达时，Communication Management 调用 <code>TriggerReceiveHandler</code> <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>。应用程序在处理程序内部或周期性调用 <code>GetNewTriggers()</code> <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>。该方法读取自上次调用以来到达的触发器数量并更新计数器。返回值 <code>0</code> 表示自那时起未接收到新的触发器 <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>。</li>
<li><strong>终止订阅与注销：</strong>为了终止接收，应用程序调用 <code>Unsubscribe()</code> <a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>。已注册的处理程序可通过 <code>UnsetReceiveHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_11614" href="../spec/record.html?id=SWS_CM_11614">[SWS_CM_11614]</a>、<code>UnsetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01108" href="../spec/record.html?id=SWS_CM_01108">[SWS_CM_01108]</a> 以及 <code>UnsetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00108" href="../spec/record.html?id=SWS_CM_00108">[SWS_CM_00108]</a> 进行重置。</li>
</ol>

<h4>错误场景</h4>
<p>触发器类的方法主要声明为 <code>noexcept</code> 并被指定为异常安全 <a class="spec-record-ref" data-req="SWS_CM_00226" href="../spec/record.html?id=SWS_CM_00226">[SWS_CM_00226]</a>、<a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>、<a class="spec-record-ref" data-req="SWS_CM_00810" href="../spec/record.html?id=SWS_CM_00810">[SWS_CM_00810]</a>、<a class="spec-record-ref" data-req="SWS_CM_01105" href="../spec/record.html?id=SWS_CM_01105">[SWS_CM_01105]</a>。定义了以下错误情况和违规（Violations）：</p>
<ul>
<li><strong>无效回调（<code>InvalidHandlerViolation</code>）：</strong>如果向 <code>SetReceiveHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00250" href="../spec/record.html?id=SWS_CM_00250">[SWS_CM_00250]</a>、<a class="spec-record-ref" data-req="SWS_CM_00352" href="../spec/record.html?id=SWS_CM_00352">[SWS_CM_00352]</a>、<code>SetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01107" href="../spec/record.html?id=SWS_CM_01107">[SWS_CM_01107]</a>、<a class="spec-record-ref" data-req="SWS_CM_01106" href="../spec/record.html?id=SWS_CM_01106">[SWS_CM_01106]</a> 或 <code>SetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>、<a class="spec-record-ref" data-req="SWS_CM_00107" href="../spec/record.html?id=SWS_CM_00107">[SWS_CM_00107]</a> 传递了一个不存在或空的可调用对象（空处理程序），系统将报告 <code>InvalidHandlerViolation</code>。</li>
<li><strong>缺少访问权限（<code>InsufficientPermissionsViolation</code>）：</strong>如果 Grant Enforcement 拒绝了对触发器元素的访问权限，则对 <code>Subscribe()</code> 的调用将被拒绝并带有 <code>InsufficientPermissionsViolation</code> <a class="spec-record-ref" data-req="SWS_CM_00723" href="../spec/record.html?id=SWS_CM_00723">[SWS_CM_00723]</a>。</li>
<li><strong>移除接收处理程序时的异常安全性：</strong>与方法 <code>UnsetSubscriptionStateChangeHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_01108" href="../spec/record.html?id=SWS_CM_01108">[SWS_CM_01108]</a> 和 <code>UnsetTransportFaultConditionHandler()</code> <a class="spec-record-ref" data-req="SWS_CM_00108" href="../spec/record.html?id=SWS_CM_00108">[SWS_CM_00108]</a> 不同，<code>UnsetReceiveHandler()</code> 被指定为 <em>not exception safe</em> <a class="spec-record-ref" data-req="SWS_CM_11614" href="../spec/record.html?id=SWS_CM_11614">[SWS_CM_11614]</a>。</li>
<li><strong>网络层传输错误：</strong>端到端传输中的错误通过经由 <code>SetTransportFaultConditionHandler()</code> 注册的处理程序进行异步通知 <a class="spec-record-ref" data-req="SWS_CM_00106" href="../spec/record.html?id=SWS_CM_00106">[SWS_CM_00106]</a>。</li>
</ul>
