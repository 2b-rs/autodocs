订阅无数据的服务触发器，并为客户端应用程序统计传入的触发脉冲。

类 <SI-Namespace>::proxy::triggers::<Trigger> 允许客户端应用程序通过 Communication Management 订阅无数据的触发脉冲 [SWS_CM_00723]。通过 SetReceiveHandler() 注册回调后，应用程序使用 GetNewTriggers() 读取新到达的脉冲 [SWS_CM_00226]，[SWS_CM_00250]。除 UnsetReceiveHandler() 外，默认保证异常安全性 [SWS_CM_11614]。

上下文

生成的代理类 <SI-Namespace>::proxy::triggers::<Trigger> 在客户端表示恰好一个在服务接口中被建模为角色 trigger 的触发器元素 AUTOSAR_AP_SWS_CommunicationManagement §8 “Service proxy Trigger class”。与基于事件的数据流不同，触发器传输不带有效负载的纯触发脉冲。该类充当使用它的客户端应用程序、Communication Management (ara::com) 以及 E2E 监控系统之间的中介。其核心任务是控制传入触发器的订阅，为脉冲到达或状态更改注册通知回调，并通过计数器提供已到达触发的次数 [SWS_CM_00226]，[SWS_CM_00250]。

生命周期

<SI-Namespace>::proxy::triggers::<Trigger> 实例的生命周期绑定到父服务代理对象的生命周期，并在其中作为类成员存在。在状态方面，触发器订阅经历多个阶段，这些阶段由 ara::com::SubscriptionState 映射并可通过 GetSubscriptionState() 查询 [SWS_CM_01105]：

  • 未订阅：调用 Subscribe() 之前或成功 Unsubscribe() 之后的初始状态 [SWS_CM_00723]，[SWS_CM_00810]。
  • 订阅挂起（kSubscriptionPending）：触发 Subscribe() 之后确认订阅期间的中间状态 [SWS_CM_00723]。
  • 已订阅（kSubscribed）：订阅处于活动状态；传入的触发脉冲会递增内部计数器并通知已注册的处理程序 [SWS_CM_00226]，[SWS_CM_00250]。

在状态 kSubscribed 或 kSubscriptionPending 下再次调用 Subscribe() 无效并直接返回而不执行任何操作 [SWS_CM_00723]。若在调用时触发器订阅不存在，Unsubscribe() 的行为与此类似 [SWS_CM_00810]。为了观察状态变化，应用程序可以通过 SetSubscriptionStateChangeHandler() 设置相应的回调 [SWS_CM_01107] 或通过 UnsetSubscriptionStateChangeHandler() 注销 [SWS_CM_01108]。

状态图：包含通过 Subscribe 和 Unsubscribe 进行转换的触发器订阅生命周期。来源：[SWS_CM_00723]、[SWS_CM_00810]、[SWS_CM_01105]。

使用路径

事件驱动处理触发信号的典型使用路径包括配置回调、激活订阅以及查询计数器：

  1. 处理程序注册：应用程序可选地通过 SetSubscriptionStateChangeHandler() 设置状态处理程序 [SWS_CM_01107]，且必须通过 SetReceiveHandler() 设置接收处理程序 [SWS_CM_00250]。对于并发架构，提供了带有专用 ExecutorT 的重载，用于指定异步计算的执行上下文 [SWS_CM_00352]，[SWS_CM_01106]。
  2. 请求订阅：使用 Subscribe() 启动触发器订阅 [SWS_CM_00723]。
  3. 信号接收与计数器查询：一旦触发脉冲到达，Communication Management 便会无参数调用 TriggerReceiveHandler [SWS_CM_00250]。在该处理程序内部，应用程序调用 GetNewTriggers() 以更新触发计数器并读取自上次调用以来到达的脉冲数 [SWS_CM_00226]。此时值 0 表示没有新脉冲。
  4. 终止：为了有序析构，应用程序调用 Unsubscribe() [SWS_CM_00810]，并通过 UnsetReceiveHandler() [SWS_CM_11614] 以及 UnsetSubscriptionStateChangeHandler() [SWS_CM_01108] 移除已设置的处理程序。

时序图：从注册和订阅到信号接收再到注销的典型触发处理流程。来源：[SWS_CM_00226]、[SWS_CM_00250]、[SWS_CM_00723]、[SWS_CM_00810]、[SWS_CM_11614]。

错误场景

规范为接口方法定义了特定的违规条件（Violations）和异常安全性：

  • InvalidHandlerViolation：在 SetReceiveHandler() [SWS_CM_00250]、[SWS_CM_00352]、SetSubscriptionStateChangeHandler() [SWS_CM_01106]、[SWS_CM_01107] 或 SetTransportFaultConditionHandler() [SWS_CM_00106]、[SWS_CM_00107] 中传入无效或空 Callable 时发生。
  • InsufficientPermissionsViolation：在 Subscribe() 期间，当访问控制（Grant Enforcement）拒绝触发器订阅权限时触发 [SWS_CM_00723]。
  • E2E 保护中的传输错误：错误的传输状态通过使用 SetTransportFaultConditionHandler() 注册的处理程序报告 [SWS_CM_00106]，[SWS_CM_00107]，该处理程序可以通过 UnsetTransportFaultConditionHandler() 重新注销 [SWS_CM_00108]。
  • 异常安全性：几乎所有操作都被声明为 noexcept 且是异常安全的（exception safe）[SWS_CM_00226]，[SWS_CM_00723]。一个例外是 UnsetReceiveHandler()，根据规范其被明确归类为非异常安全（not exception safe）[SWS_CM_11614]；推测该调用在出错时可能会传播异常，或者需要在客户端应用程序中进行专门的错误处理。

          使用
          

          函数SetReceiveHandler在服务代理（<SI-Namespace>::proxy::triggers::<Trigger>）的触发器类作用域中调用，并通过头文件<SiNamespaceDerivedDirectoryPath>/<SiShortname>_proxy.h包含[SWS_CM_00250]。触发器与事件、方法和字段一起构成了ara::com中的四种通信机制之一EXP_ARAComAPI §4.2 “Means of Communication”。
          

          类型为ara::com::TriggerReceiveHandler的参数handler接收一个可调用对象，当触发器到达时，Communication Management 会调用该对象。处理程序本身没有参数；要在回调函数内部查询当前触发器计数值，必须调用特定触发器类的GetNewTriggers方法[SWS_CM_00250]。
          

          错误处理与异常安全性
          

          该注册不返回任何返回值（void），并被定义为noexcept以及exception safe[SWS_CM_00250]。如果传入的 Callable 不存在或为null，则会发生形式为InvalidHandlerViolation的调用约定违规[SWS_CM_00250]。
          

          交互与变体
          

          针对需要在定义的执行上下文中处理触发器处理程序的场景，存在带有ExecutorT的模板重载[SWS_CM_00352]。在代理层级，也为事件（[SWS_CM_00181]、[SWS_CM_11356]）以及字段（[SWS_CM_11605]、[SWS_CM_11611]）提供了类似的回调注册方法EXP_ARAComAPI §5.3.1 “Proxy Class API’s”。
