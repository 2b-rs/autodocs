在单调增长的缓冲区中管理内存块，具有无异常分配和集中释放特性。

类 ara::core::MonotonicBufferResource 提供了一种专门的内存资源，用于从固定内存缓冲区或通过上游资源进行快速、单调的分配。请求的内存按步分配，且在单个释放操作中不会立即释放，而是统一通过 release()（[SWS_CORE_06530]）进行重置。所有操作均声明为完全无异常，其中内存不足通过返回 nullptr 而非异常来指示（[SWS_CORE_06569]）。这些实例不可拷贝，并且在从多个线程并发访问时需要外部同步。

上下文

类 ara::core::MonotonicBufferResource 是 AUTOSAR Adaptive Platform 模块 core 内的具体内存资源，并继承自基类 ara::core::MemoryResource。它针对安全相关和确定性车载应用调整了来自 [mem.res.monotonic.buffer] 的 C++ 标准已知概念 std::pmr::monotonic_buffer_resource。该类的主要作用是通过单调分配内存，以最小的管理开销满足来自连续内存区域的分配请求。

交互对象一方面是调用组件、多态分配器以及在运行时请求内存块的容器。另一方面，该类与可选的上层上游内存资源（MemoryResource）进行交互。该上游资源可以通过诸如 [SWS_CORE_06521] 等构造函数传入，并通过访问方法 upstream_resource()（[SWS_CORE_06531]）进行查询。

生命周期

ara::core::MonotonicBufferResource 的初始化可通过多个构造函数进行控制。除无参数默认构造函数（[SWS_CORE_06524]）外，还提供了接收显式上游资源的重载（[SWS_CORE_06521]）、定义初始缓冲区大小的重载（[SWS_CORE_06525], [SWS_CORE_06522]），或将外部提供的原始内存区域（void* buffer, std::size_t buffer_size）用作初始缓冲区的重载（[SWS_CORE_06526], [SWS_CORE_06523]）。

在所有权关系方面，该类被定义为严格不可复制：复制构造函数（[SWS_CORE_06527]）和复制赋值运算符（[SWS_CORE_06529]）已被删除（=delete）。然而与 ISO-14882 标准不同，AUTOSAR 类通过移动构造函数（[SWS_CORE_06576]）和移动赋值运算符（[SWS_CORE_06577]）实现了显式移动语义，两者分别定义为 noexcept=default。

销毁通过析构函数 ~MonotonicBufferResource()（[SWS_CORE_06528]）进行。AUTOSAR 相对该标准的一个重要偏差在于析构函数未声明为虚函数。通过方法 release()（[SWS_CORE_06530]），可在对象生命周期结束前重置全部已分配的内存。

在并发方面必须注意严格分离：无参构造函数（[SWS_CORE_06524]）、相等性检查 do_is_equal()（[SWS_CORE_06571]）以及查询 upstream_resource()（[SWS_CORE_06531]）被声明为线程安全。所有带参数的构造函数（[SWS_CORE_06521]、[SWS_CORE_06522]、[SWS_CORE_06523]、[SWS_CORE_06525]、[SWS_CORE_06526]）、分配操作（[SWS_CORE_06569]、[SWS_CORE_06570]）、release()（[SWS_CORE_06530]）以及析构函数（[SWS_CORE_06528]）均非线程安全，并行访问时需要外部同步。

使用路径

典型的应用流程包括提供、连续分配以及集中释放：

  1. 实例化：应用程序创建实例，例如指定缓冲区大小和上游资源（[SWS_CORE_06522]）或固定缓冲区（[SWS_CORE_06526]）。
  2. 分配：内存请求通过受保护的方法 do_allocate(bytes, alignment)（[SWS_CORE_06569]）处理。若现有缓冲区不足，该实例会从上游资源获取新的缓冲区。
  3. 释放：对 do_deallocate(p, bytes, alignment)（[SWS_CORE_06570]）的调用不会单独缩小缓冲区；内部配额指针单调向前移动。
  4. 缓冲区重置：使用 release()（[SWS_CORE_06530]）可一次性释放所有通过上游获取的内存块，缓冲区便可用于新的周期。
  5. 资源比较：通过 do_is_equal()（[SWS_CORE_06571]）可以检查两个内存资源是否相同。

时序图：从分配、忽略释放到通过 release() 进行集体重置的典型内存周期。来源：[SWS_CORE_06522]、[SWS_CORE_06569]、[SWS_CORE_06570]、[SWS_CORE_06530]

错误场景

该类遵循针对无异常嵌入式系统的严格规定：所有成员函数、构造函数和运算符均声明为 noexcept，并提供完全的异常安全性。

在发生错误时，其行为特意偏离了标准库：

  • 分配失败：若 do_allocate()（[SWS_CORE_06569]）中的请求无法满足，不会抛出异常 std::bad_alloc，而是返回 nullptr。调用方必须强制检查返回值是否为 nullptr。
  • 释放错误：若在 do_deallocate()（[SWS_CORE_06570]）中释放时发生错误，根据规范将静默忽略该错误。
  • 通过基类指针销毁：由于析构函数（[SWS_CORE_06528]）不是虚函数，通过指向基类 MemoryResource 的指针进行销毁可能会导致未定义行为（Interpretation：销毁必须通过具体类型进行）。
