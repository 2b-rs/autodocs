类 ara::core::Span 提供了针对内存区域的非所有权连续视图，并允许在无拷贝开销的情况下高效封装数组或缓冲区 [SWS_CORE_01942]。应用程序通常使用该类来传递数据窗口以及通过切片操作生成子视图。调用方必须严格确保底层内存的生命周期超出视图的生命周期，并且在诸如 subspan() 等操作中保持有效边界，因为越界会导致未定义行为 [SWS_CORE_01966]。

上下文

类 ara::core::Span 提供了连续序列视图的标准兼容实现，参考了 [views.span] 中的 std::span。作为轻量级抽象，它封装了指向第一个元素的指针以及可用元素的数量，而自身并不拥有数据。它用作提供数据的组件与处理这些数据的算法之间的统一接口。

主要交互对象包括：

  • 调用方应用逻辑：使用该视图对顺序内存区域进行读或写访问，无需内存分配或拷贝开销。
  • 内存源与容器：任意连续内存区域，例如原生 C 数组 [SWS_CORE_01944]、标准化平台容器如 ara::core::Array [SWS_CORE_01945] [SWS_CORE_01946]、通用容器结构 [SWS_CORE_01947] [SWS_CORE_01948]，或带有指针和长度说明的原始缓冲区 [SWS_CORE_01942]。
  • 子视图（Subspans）：通过从上级视图进行分解而产生的 ara::core::Span 的其他实例 [SWS_CORE_01965] [SWS_CORE_01966]。

上下文图：ara::core::Span 作为非所有权视图在应用逻辑与内存缓冲区之间的集成。来源：[SWS_CORE_01942]、[SWS_CORE_01945]、[SWS_CORE_01951]

生命周期

ara::core::Span 的实例被设计为不具备自身资源管理的纯值对象。创建方式既可以是通过默认构造函数 [SWS_CORE_01941] 作为空 Span，也可以是通过直接指定起始地址和元素数量 [SWS_CORE_01942]，或者通过由起始和结束组成的指针区间 [SWS_CORE_01943]。此外，还提供了用于 C 数组 [SWS_CORE_01944]、ara::core::Array 类型的容器 [SWS_CORE_01945] [SWS_CORE_01946] 以及通用容器 [SWS_CORE_01947] [SWS_CORE_01948] 的类型化构造函数。现有的 Span 可以通过默认拷贝构造函数 [SWS_CORE_01949] 或通过具有兼容元素类型和 Extent 的转换构造函数进行复制 [SWS_CORE_01950]。

由于 ara::core::Span 不对引用的数据承担任何所有权，因此析构函数具有默认实现，并被指定为 noexcept=default [SWS_CORE_01951]。由此得出了基本不变式（解释：假设 1）：底层内存缓冲区的生命周期必须始终至少包含引用它的所有 Span 对象的生命周期；当缓冲区销毁时，剩余的 Span 将失效。通过赋值运算符进行的赋值通过浅拷贝平凡完成 [SWS_CORE_01952]。由于所有访问函数均声明为 noexcept 且不包含内部同步机制，因此从多个线程对同一 Span 实例并发进行读取访问应该是安全的，前提是底层内存区域没有被并行修改（解释：假设 2）。

使用路径

典型用例包括封装现有数据块、检查尺寸、提取相关区段以及访问元素：

  1. 视图创建：应用程序在连续缓冲区上实例化 ara::core::Span，例如从 ara::core::Array [SWS_CORE_01945] 的实例或通过带有长度说明的原始数据指针 [SWS_CORE_01942]。
  2. 状态与尺寸检查：在进一步处理之前，通过 empty() [SWS_CORE_01969]、size() [SWS_CORE_01967] 或 size_bytes() [SWS_CORE_01968] 验证尺寸，或者使用 data() [SWS_CORE_01971] 查询基地址。
  3. 切片 / 子视图形成：为了聚焦于相关数据窗口，应用程序通过使用 first() [SWS_CORE_01961] [SWS_CORE_01962] 的前缀、使用 last() [SWS_CORE_01963] [SWS_CORE_01964] 的后缀或使用 subspan() [SWS_CORE_01965] [SWS_CORE_01966] 的任意子区域来创建子视图。
  4. 元素处理：实际的数据访问通过下标运算符 operator[] [SWS_CORE_01970] 随机进行，通过 front() [SWS_CORE_01959] 和 back() [SWS_CORE_01960] 进行边界元素访问，或通过从 begin() 到 end() [SWS_CORE_01972] [SWS_CORE_01973] 的迭代器顺序进行。

时序图：用于创建、切分和查询视图元素的典型调用序列。来源：[SWS_CORE_01942]、[SWS_CORE_01966]、[SWS_CORE_01970]

错误场景

ara::core::Span 的所有方法均被声明为异常安全且为 noexcept；既不抛出 C++ 异常，也不返回如 ara::core::ErrorCode 之类的错误对象。错误状态主要源于违反前置条件，这会直接导致未定义行为（Undefined Behavior）：

  • 前缀和后缀的大小超出：如果在 first() 中请求的数量超过了当前大小（Count > size() 或 count > size()），则行为未定义 [SWS_CORE_01961] [SWS_CORE_01962]。相同的前置条件违规在 last() 中同样会导致未定义行为 [SWS_CORE_01963] [SWS_CORE_01964]。
  • subspan 中的子区域参数无效：调用 subspan() 强制要求满足 offset <= size()，并且在显式指定 count（不等于 dynamic_extent）时还必须满足 count <= size() - offset。忽略此要求将导致未定义行为 [SWS_CORE_01966]。
  • 元素访问时的范围超出：下标运算符 operator[] [SWS_CORE_01970] 以及访问函数 front() [SWS_CORE_01959] 和 back() [SWS_CORE_01960] 不执行范围检查（Bounds Checking）。在有效边界之外的访问应该会直接导致未定义的内存访问（解释：假设 3）。
