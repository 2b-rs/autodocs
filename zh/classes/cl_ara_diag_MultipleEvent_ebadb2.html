上下文

类 ara::diag::MultipleEvent 通过多事件接口提供诊断事件操作。与专用的单事件接口相比，MultipleEvent 允许通过公共端口与多个诊断事件进行捆绑交互，其中具体事件在每次方法调用时通过 EventHandleType 类型的标识符寻址。该类在此充当自适应应用软件与 AUTOSAR Adaptive Platform 的中央 Diagnostic Management (DM) 之间的适配器。

该交互主要涉及三个组件：调用方软件组件、ara::diag::MultipleEvent 的实例以及底层的 Diagnostic Management 服务。应用程序在指定模型引用的情况下初始化该实例，并使用它针对具体的事件句柄进行状态查询、去抖检查和通知程序注册 [SWS_DM_01705] [SWS_DM_01707] [SWS_DM_01708]。

生命周期

ara::diag::MultipleEvent 的实例通过其显式构造函数创建，该构造函数接收一个 ara::core::InstanceSpecifier [SWS_DM_01705]。该标识符必须指向在 AUTOSAR 模型中声明的 DiagnosticMultipleEventInterface 的 PortPrototype。该构造函数声明为异常安全（exception safe）且线程安全 [SWS_DM_01705]。

该类在标识和资源绑定方面具有严格的语义：拷贝构造函数和赋值运算符均被显式删除 (=delete) [SWS_DM_02070] [SWS_DM_02067]。同样，移动构造函数和移动赋值运算符也被删除 [SWS_DM_02069] [SWS_DM_02068]。因此，MultipleEvent 的实例既不可复制也不可移动；它始终固定在其存储位置，通常作为应用程序组件的长期成员存在。

析构函数 ~MultipleEvent() 是异常安全的，但被指定为非线程安全 [SWS_DM_01706]。因此，只有当对象上不再发生并发查询或注册操作时，才允许释放该实例。关于状态查询方法的线程安全性，适用条件性行为：查询方法是否必须以线程安全的方式执行，取决于构造函数中提供的并发类型 [SWS_DM_01707] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711]。

使用路径

典型的使用路径包括接口的实例化、变更通知的可选注册以及事件特定诊断数据的查询：

  1. 实例化：应用程序通过传递配置的 InstanceSpecifier 来创建 MultipleEvent 对象 [SWS_DM_01705]。
  2. 注册通知器：通过 SetEventStatusChangedNotifier 为特定的 eventHandle 存储类型为 EventStatusByteNotifier 的回调 [SWS_DM_01708]。再次调用会覆盖先前注册的通知器。该方法返回 ara::core::Result<void> 且非线程安全 [SWS_DM_01708]。
  3. 查询状态和故障计数器：通过 GetEventStatus(eventHandle) 查询当前状态（EventStatusByte）[SWS_DM_01707]。额外的诊断信息可通过用于消抖状态的 GetDebouncingStatus(eventHandle) [SWS_DM_01710] 以及用于故障检测计数器的 GetFaultDetectionCounter(eventHandle) [SWS_DM_01711] 异步获取。
  4. 读取 DTC 映射：使用 GetDTCNumber(eventHandle, dtcFormat) 可以获取按所请求格式（DTCFormatType）分配给该事件的 DTC 编号 [SWS_DM_01709]。

所有查询方法均返回 ara::core::Future，从而使调用以非阻塞方式进行，并可通过 Future 接口异步接收结果 [SWS_DM_01707] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711]。

错误场景

错误条件既会在初始化期间出现，也会在常规运行期间出现：

  • 建模与实例化错误：如果在进程上下文中无法解析 InstanceSpecifier（InstanceSpecifierMappingIntegrityViolation）、引用的 PortPrototype 未由 DiagnosticMultipleEventInterface 进行类型化（PortInterfaceMappingViolation）、缺少与进程运行时的映射（ProcessMappingViolation），或者标识符在进程内已被使用（InstanceSpecifierAlreadyInUseViolation），则构造函数会报告与模型相关的违规 [SWS_DM_01705]。
  • 无效参数：当传递不合法的句柄或无效参数时，诸如 SetEventStatusChangedNotifier、GetEventStatus、GetDebouncingStatus、GetFaultDetectionCounter 和 GetDTCNumber 等方法会返回错误代码 DiagErrc::kInvalidArgument [SWS_DM_01707] [SWS_DM_01708] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711]。
  • 缺少 DTC 映射：如果系统中未为传入的 eventHandle 存储 DTC，则对 GetDTCNumber 的调用将失败并返回 DiagErrc::kNoSuchDTC [SWS_DM_01709]。
  • 服务可用性：如果 Diagnostic Management 的基本功能在运行时不可用，则返回错误 DiagErrc::kServiceNotAvailable [SWS_DM_01707] [SWS_DM_01709] [SWS_DM_01710] [SWS_DM_01711]。所有错误调用均具有回滚语义。

<h4>生命周期</h4>
<p><code>ara::diag::MultipleEvent</code> 的实例通过其显式构造函数创建，该构造函数接收一个 <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>。该标识符必须指向在 AUTOSAR 模型中声明的 <code>DiagnosticMultipleEventInterface</code> 的 <code>PortPrototype</code>。该构造函数声明为异常安全（<em>exception safe</em>）且线程安全 <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>。</p>
<p>该类在标识和资源绑定方面具有严格的语义：拷贝构造函数和赋值运算符均被显式删除 (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_02070" href="../spec/record.html?id=SWS_DM_02070">[SWS_DM_02070]</a> <a class="spec-record-ref" data-req="SWS_DM_02067" href="../spec/record.html?id=SWS_DM_02067">[SWS_DM_02067]</a>。同样，移动构造函数和移动赋值运算符也被删除 <a class="spec-record-ref" data-req="SWS_DM_02069" href="../spec/record.html?id=SWS_DM_02069">[SWS_DM_02069]</a> <a class="spec-record-ref" data-req="SWS_DM_02068" href="../spec/record.html?id=SWS_DM_02068">[SWS_DM_02068]</a>。因此，<code>MultipleEvent</code> 的实例既不可复制也不可移动；它始终固定在其存储位置，通常作为应用程序组件的长期成员存在。</p>
<p>析构函数 <code>~MultipleEvent()</code> 是异常安全的，但被指定为非线程安全 <a class="spec-record-ref" data-req="SWS_DM_01706" href="../spec/record.html?id=SWS_DM_01706">[SWS_DM_01706]</a>。因此，只有当对象上不再发生并发查询或注册操作时，才允许释放该实例。关于状态查询方法的线程安全性，适用条件性行为：查询方法是否必须以线程安全的方式执行，取决于构造函数中提供的并发类型 <a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a> <a class="spec-record-ref" data-req="SWS_DM_01709" href="../spec/record.html?id=SWS_DM_01709">[SWS_DM_01709]</a> <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a> <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a>。</p>

<h4>使用路径</h4>
<p>典型的使用路径包括接口的实例化、变更通知的可选注册以及事件特定诊断数据的查询：</p>
<ol>
<li><strong>实例化：</strong>应用程序通过传递配置的 <code>InstanceSpecifier</code> 来创建 <code>MultipleEvent</code> 对象 <a class="spec-record-ref" data-req="SWS_DM_01705" href="../spec/record.html?id=SWS_DM_01705">[SWS_DM_01705]</a>。</li>
<li><strong>注册通知器：</strong>通过 <code>SetEventStatusChangedNotifier</code> 为特定的 <code>eventHandle</code> 存储类型为 <code>EventStatusByteNotifier</code> 的回调 <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>。再次调用会覆盖先前注册的通知器。该方法返回 <code>ara::core::Result&lt;void&gt;</code> 且非线程安全 <a class="spec-record-ref" data-req="SWS_DM_01708" href="../spec/record.html?id=SWS_DM_01708">[SWS_DM_01708]</a>。</li>
<li><strong>查询状态和故障计数器：</strong>通过 <code>GetEventStatus(eventHandle)</code> 查询当前状态（<code>EventStatusByte</code>）<a class="spec-record-ref" data-req="SWS_DM_01707" href="../spec/record.html?id=SWS_DM_01707">[SWS_DM_01707]</a>。额外的诊断信息可通过用于消抖状态的 <code>GetDebouncingStatus(eventHandle)</code> <a class="spec-record-ref" data-req="SWS_DM_01710" href="../spec/record.html?id=SWS_DM_01710">[SWS_DM_01710]</a> 以及用于故障检测计数器的 <code>GetFaultDetectionCounter(eventHandle)</code> <a class="spec-record-ref" data-req="SWS_DM_01711" href="../spec/record.html?id=SWS_DM_01711">[SWS_DM_01711]</a> 异步获取。</li>
