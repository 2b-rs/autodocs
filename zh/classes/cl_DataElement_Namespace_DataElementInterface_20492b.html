使应用程序能够为 Diagnostic Manager 提供并响应诊断读取查询。

该接口用于 Adaptive 应用程序为 Diagnostic Management 的读取访问提供诊断数据。通过实例指定符进行实例化后，应用程序必须主动提供该服务，以便能够接收传入的读取请求 [SWS_DM_00597]。传入的请求通过异步读取方法进行处理，该方法在未来值中提供所请求的输出数据或否定反馈代码 [SWS_DM_00596]。由于复制和移动操作已被删除，每个实例都牢固绑定到其上下文中。

上下文

生成的 C++ 类 <DataElementInterface> 在功能集群 diag（AUTOSAR Adaptive Platform）内充当标准化的服务器接口，用于提供可读诊断数据 AUTOSAR_AP_SWS_Diagnostics 第68页。具体而言，它在角色 read 中映射了一个 DiagnosticDataElementInterface，Adaptive 应用程序通过该接口向 Diagnostic Manager（DM）传输诊断请求（例如 UDS ReadDataByIdentifier）的数据值 [SWS_DM_00596]。

关键交互方是平台守护进程的 Diagnostic Management（负责协调传入的诊断请求）以及实现该接口并具体阐明提供逻辑的 Adaptive 应用程序。通过建模的端口原型进行实例化并映射到软件架构，该端口原型通过 ara::core::InstanceSpecifier 进行连接 [SWS_DM_00587]。输出数据被封装在类型特定的结构中，其参数由相应的输出元素表示 [SWS_DM_80023]，[SWS_DM_00581]。

生命周期

实例的创建通过构造函数在指定 ara::core::InstanceSpecifier 以及并发模式 ara::diag::ConcurrencyType 的情况下进行 [SWS_DM_00587]。为了在进程内保持唯一的映射，复制构造函数和移动构造函数均被删除 [SWS_DM_01661]，[SWS_DM_01662]。同样地，复制和移动赋值运算符也被显式删除 [SWS_DM_01659]，[SWS_DM_01660]。因此，实例固定保留在其创建的地址处。

关于运行，该对象经历定义的阶段：

  • 未提供（Not Offered）：构造后，对象最初处于非活动状态，在该状态下 DM 不会递送任何读取请求。
  • 已提供（Offered）：通过调用 Offer()，在 DM 处激活该服务，以便转发传入的读取请求 [SWS_DM_00597]。
  • 已注销：调用 StopOffer() 会停用 DM 对未来诊断请求的转发 [SWS_DM_00617]。
  • 销毁：虚拟析构函数 ~<DataElementInterface>() 结束接口实例的生命周期 [SWS_DM_00588]。

虽然构造函数被指定为线程安全 [SWS_DM_00587]，但 Offer()、StopOffer()、Read() 和析构函数不是线程安全的 [SWS_DM_00597]，[SWS_DM_00617]，[SWS_DM_00596]，[SWS_DM_00588]。构造函数中的参数 concurrencyType 确定处理程序实现是以线程安全（kConcurrent）还是非线程安全（kNotConcurrent）的方式执行 [SWS_DM_00587]。

状态图：接口实例在初始化、发布状态和销毁之间的状态阶段。来源：[SWS_DM_00587]，[SWS_DM_00597]，[SWS_DM_00617]，[SWS_DM_00588]。

使用路径

数据查询的常规流程遵循固定的步骤顺序：

  1. 实例化：应用程序使用所需的 instanceSpec 和 concurrencyType 实例化派生的处理程序类 [SWS_DM_00587]。
  2. 服务发布：应用程序调用 Offer()，从而使 DM 能够转发读取请求 [SWS_DM_00597]。
  3. 读取请求处理：当读取请求到达 DM 时，DM 调用处理程序上的纯虚方法 Read(metaInfo, cancellationHandler) [SWS_DM_00596]。应用程序对 metaInfo 进行求值，并可通过 cancellationHandler.IsCanceled() 检查会话是否已中断，或通过 cancellationHandler.SetNotifier 注册一个回调 [SWS_DM_00596]。
  4. 反馈：解释：输出数据的实际确定通常应异步进行；结果在一个带有相应 ReadOutput 对象的 ara::core::Future 中提供 [SWS_DM_00596]，[SWS_DM_00581]。
  5. 服务终止：在关闭之前，应用程序调用 StopOffer() 以阻止转发 [SWS_DM_00617]，随后进行对象销毁 [SWS_DM_00588]。

时序图：从服务注册、异步读取到注销的调用序列。来源：[SWS_DM_00597]，[SWS_DM_00596]，[SWS_DM_00617]。

错误场景

在错误情况下，必须对不同的生命周期阶段进行区别看待：

在构造时就可能出现完整性违规，这些违规通过特定的 Violation 发出信号 [SWS_DM_00587]：

  • InstanceSpecifierMappingIntegrityViolation：实例指定符无法在 Executable 的模型中解析，或者未引用 PortPrototype。
  • PortInterfaceMappingViolation：由 DiagnosticDataElementInterface 定型的 PortPrototype 未被 DiagnosticDataPortMapping 引用。
  • ProcessMappingViolation：尽管存在匹配的 InstanceRef，但未找到与运行时进程相对应的匹配建模进程。
  • InstanceSpecifierAlreadyInUseViolation：使用在当前进程中已被使用的 InstanceSpecifier 调用了构造函数。

如果针对已提供的服务调用 Offer()，该方法将返回一个带有错误代码 DiagOfferErrc::kAlreadyOffered 的 ara::core::Result（回滚语义）[SWS_DM_00597]。

若 Read() 中的读取请求无法成功应答，返回的 ara::core::Future 必须通过 DiagUdsNrcErrc 包含相应的 ISO 14229-1 否定响应码（NRC），或包含一个 ApApplicationError [SWS_DM_00596]。
