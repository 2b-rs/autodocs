上下文

接口类 ara::diag::SovdBulkData [SWS_DM_01841] 提供了用于根据 Service-Oriented Vehicle Diagnostics（SOVD）访问大容量数据（Bulk Data）的通用服务接口 SWS Diagnostics §8.53 “Class: SovdBulkData”。它充当特定于应用程序的数据源与 Adaptive Platform 的中央诊断服务器之间的纽带。

至少有三个组件参与整个处理过程：

  • SOVD 客户端：检索、上传或删除大容量数据的外部诊断工具。通信通常可能通过 HTTP/REST 机制处理。
  • Diagnostic Management (DM)：Diagnostic Server Instance 接收外部 SOVD 服务调用，并将其转换为本地方法调用 SWS Diagnostics §7.x “SOVD Bulk Data Realization”。
  • 自适应应用程序：用户自定义应用程序继承自 ara::diag::SovdBulkData，实例化该类并提供实际的数据流和元数据。

生命周期

ara::diag::SovdBulkData 的实例化通过构造函数进行，同时传递一个 ara::core::InstanceSpecifier 并通过 ConcurrencyType [SWS_DM_01847] 指定并发行为。InstanceSpecifier 将该对象绑定到 DiagnosticSovdBulkDataInterface 在设计模型中定义的 PortPrototype。

关于所有权关系，该类被设计为独占实例：复制构造函数 [SWS_DM_01848] 和复制赋值运算符 [SWS_DM_01850] 被显式删除（=delete）。实例的转移仅通过移动操作进行；移动构造函数 [SWS_DM_01849] 和移动赋值 [SWS_DM_01851] 实现为受保护的。

功能生命周期分为以下阶段：

  • 非活动：构造后对象在本地存在，但尚不接收来自 Diagnostic Management 的诊断请求。
  • 活动（Offered）：通过调用方法 Offer() [SWS_DM_01857]，该对象在 DM 中注册。仅从该时间点起，DM 才会将传入的 SOVD 请求转发给虚处理程序方法。
  • 已停止：调用 StopOffer() [SWS_DM_01858] 会再次停用请求的转发。
  • 销毁：虚析构函数 ~SovdBulkData() [SWS_DM_01852] 终止对象的生命周期。在销毁之前，大概率应调用 StopOffer()，以便彻底断开待处理的访问。

关于并发性，构造函数中传递的 ConcurrencyType 确定了虚回调方法是必须以线程安全（kConcurrent）还是非线程安全（kNotConcurrent）方式执行 [SWS_DM_01847]。控制方法 Offer() [SWS_DM_01857]、StopOffer() [SWS_DM_01858] 以及析构函数 [SWS_DM_01852] 本身并不是线程安全的。

使用路径

提供和执行 SOVD 大容量数据操作的典型流程包括以下步骤：

  1. 类派生：应用程序实现继承自 ara::diag::SovdBulkData 的具体类，并重写纯虚方法。
  2. 提供服务：实例化后，应用程序调用 Offer() [SWS_DM_01857] 以提供该服务。
  3. 请求处理：
    • 如果客户端请求元数据，诊断服务器调用 GetBulkDataMetaData [SWS_DM_01791]，这会通过 ara::core::Future 返回一个包含 BulkDataMetaDataDescriptor 的向量 [SWS_DM_01853]。
    • 在下载调用时，DM 调用 RequestBulkDataDownload [SWS_DM_01792]。应用程序以包含元数据的读取会话（DataTransferReadSession）或 HTTP 重定向（HttpRedirect）进行响应 [SWS_DM_01873]。
    • 对于上传操作，DM 调用 RequestBulkDataUpload [SWS_DM_01793]，随后提供一个写入会话（DataTransferWriteSession）[SWS_DM_01854]。
    • DM 将删除请求转发给 DeleteSpecificBulkData（针对单个资源）[SWS_DM_01856] 或 DeleteAllBulkData（按类别）[SWS_DM_01855]。
  4. 服务注销：一旦要停止处理，应用程序就调用 StopOffer() [SWS_DM_01858]。

错误场景

使用 ara::diag::SovdBulkData 时需区分不同类型的错误：

  • 实例化时的配置违规：如果模型解析失败或映射不匹配，构造函数会报告特定的 Violation [SWS_DM_01847]。其中包括 InstanceSpecifierMappingIntegrityViolation（模型无效或非 PortPrototype）、PortInterfaceMappingViolation（端口映射的类型定义错误）、ProcessMappingViolation（未建模匹配的进程）以及 InstanceSpecifierAlreadyInUseViolation（进程内的 Specifier 已被占用）。
  • Offer 时的注册错误：调用 Offer() 会返回一个 ara::core::Result<void> [SWS_DM_01857]。可能的错误包括：当服务已被提供时的 DiagOfferErrc::kAlreadyOffered，以及当配置与 DEXT 描述不一致时的 DiagOfferErrc::kConfigurationMismatch。
  • 异步操作中的错误代码：如果无法成功执行所请求的大容量数据操作，错误将在返回的 ara::core::Future 中传递。为此，应用程序必须使用符合 ISO 17978-3 或 ASAM SOVD 1.1 的标准化 SOVD 错误代码（通过使用 DiagSovdErrc）[SWS_DM_01854]、[SWS_DM_01855]、[SWS_DM_01856]、[SWS_DM_01873]。相比之下，对于 GetBulkDataMetaData 则未指定标准化错误 [SWS_DM_01853]。
  • 中止处理：回调方法会接收一个 CancellationHandler 对象，该对象用于在底层诊断会话提前中止时发出信号 [SWS_DM_01853]、[SWS_DM_01873]。
