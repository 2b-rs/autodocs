用于标识和文本转换 crypto 模块的所有错误代码。

该类定义了可通过命名空间 ara::crypto 中的公共接口报告的所有错误的核心错误域 [SWS_CRYPT_19950]。其核心任务包括返回唯一的域名，以及将枚举 CryptoErrc 中的错误代码转换为可理解的错误消息 [SWS_CRYPT_19953]。所有查询函数均设计为线程安全且异常安全的，而在禁用 C++ 异常时，用于触发异常的方法不参与重载解析 [SWS_CRYPT_19954]。

上下文

类 ara::crypto::CryptoErrorDomain 充当 AUTOSAR Adaptive 平台内的专用错误域。根据其类定义，它派生自 ara::core::ErrorDomain 并被声明为 final。其核心职责在于映射可通过命名空间 ara::crypto 内的公共接口报告的所有错误。它为错误分配唯一的域标识，该标识可通过方法 Name 查询 [SWS_CRYPT_19950]。

为了统一类型绑定，该类提供了两个与类型相关的别名：Errc 作为别名直接引用加密错误代码的枚举 CryptoErrc [SWS_CRYPT_19903]，而 Exception 引用基类异常 CryptoException [SWS_CRYPT_19904]。主要交互伙伴包括生成该域错误的加密功能构件，以及通过 ara::core 的基础机制接收和评估错误的应用程序软件。

上下文图：CryptoErrorDomain 在 ara::crypto API、基类 ara::core::ErrorDomain 与应用程序之间的错误处理中的集成。来源：[SWS_CRYPT_19950]、[SWS_CRYPT_19903]、[SWS_CRYPT_19904]。

生命周期

CryptoErrorDomain 的对象创建通过标准无参数构造函数完成，该构造函数被指定为 constexpr 和 noexcept [SWS_CRYPT_19902]。通过声明为 constexpr，可以在编译时构造实例。解释：在典型的平台实现中，错误域可能作为长生存期或静态单例存在，以便在整个进程生命周期中错误代码可以引用同一域实例而无需动态内存分配。

实例化后，该对象具有常量、无状态的特性；通过关键字 final 排除了该类之下的继承层次结构。关于并发性，构造函数 [SWS_CRYPT_19902] 以及查询方法 Name [SWS_CRYPT_19950]、Message [SWS_CRYPT_19953] 和 ThrowAsException [SWS_CRYPT_19954] 均被明确归类为线程安全（thread-safe）。因此，多个线程可以并行使用实例而无需外部同步。

使用路径

与 CryptoErrorDomain 交互的常规流程分为以下几个步骤：

  1. 命名空间 ara::crypto 内的操作失败并生成 ara::core::ErrorCode 类型的错误对象，该对象与 CryptoErrorDomain 关联。
  2. 调用方应用程序或错误处理例程检查错误的来源，并可在需要时使用 Name() 获取域的唯一名称 [SWS_CRYPT_19950]。
  3. 为了生成日志输出或诊断消息，使用传入的 errorCode 调用方法 Message()，该方法解析代码并将关联的文本消息作为 const char* 返回 [SWS_CRYPT_19953]。
  4. 如果调用者希望将错误转换为 C++ 异常，则调用 ThrowAsException()，从而触发基于 CryptoException 的适当异常 [SWS_CRYPT_19954]、[SWS_CRYPT_19904]。

时序图：通过 CryptoErrorDomain 的接口进行错误解析和文本输出。来源：[SWS_CRYPT_19950]、[SWS_CRYPT_19953]。

错误场景

在错误处理方面，该类在异常安全性方面具有差异化的保证。方法 Name [SWS_CRYPT_19950] 和 Message [SWS_CRYPT_19953] 被声明为 noexcept 并且完全异常安全（exception safe）。如果向 Message 传递了未在枚举 CryptoErrc 中定义的数值，则大概率会返回一条通用后备消息；排除因异常而中止的情况。

与此相反，方法 ThrowAsException 被指定为非异常安全（not exception safe）并带有属性 [[noreturn]]，因为其预期目的是抛出异常 [SWS_CRYPT_19954]。一个重要的边界条件涉及不支持异常的平台配置：如果在编译器工具链中禁用了 C++ 异常，则 ThrowAsException 不参与重载解析 [SWS_CRYPT_19954]。在此类系统中，该调用无法编译，且错误处理必须强制通过基于错误值的机制（如结果对象）来完成。
