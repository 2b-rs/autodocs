上下文

类 ara::sm::s2r::S2RHub 在功能集群 State Management（SM）中构成了 Suspend-to-RAM 流程的核心中介和协调实例（EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”、SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。为了优化机器的关机和启动时间，可以转换为 Suspend-to-RAM 状态以替代完整的系统重启（SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。S2RHub 并非供常规 Adaptive Applications 使用，而是仅用于 State Management 实现或专用的控制应用程序（SMControlApplication）（EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。

Suspend-to-RAM 的协调既可以通过 State Management 的 StateMachine 方法以声明方式进行，也可以在 SMControlApplication 中通过 S2RHub 的 C++ API 以命令方式进行；这两种使用方式严格互斥（[SWS_SM_00684]、SWS StateManagement §7.5.1 “S2R Hub”、SWS StateManagement §7.7.15）。主要的交互伙伴包括：

  • SMControlApplication / State Management：通过 Hub 的 C++ 接口启动 Suspend 和 Resume 流程，并在确认准备就绪后触发操作系统的 Suspend（[SWS_SM_81110]、[SWS_SM_81111]、[SWS_SM_81112]）。
  • S2R Satellites：其 Executable 被配置为 suspendToRamAware 的 Adaptive Applications 进程中的 ara::sm::s2r::S2RSatellite 实例（SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”）。它们通过 Offer 向 Hub 注册，并接收用于保存持久化数据和停止服务的指令（[SWS_SM_00701]、[SWS_SM_00710]、EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。
  • Identity and Access Management（IAM）：对注册的 Satellite 进行身份验证，并将 Hub 的创建限制在部署模型中引用的进程（[SWS_SM_00706]、[SWS_SM_00714]、[SWS_SM_00715]）。
  • 操作系统（OS）：由 Hub 置于低功耗 Suspend 状态（[SWS_SM_81112]）。

生命周期

Hub 实例的创建通过构造函数 S2RHub(const ara::core::InstanceSpecifier &instance) 显式进行（[SWS_SM_81103]）。在构造期间，Hub 强制执行 IAM 检查：如果当前进程的上下文与 SuspendToRamHubMapping.process 中的建模不一致，则创建将被拒绝（[SWS_SM_00706]、[SWS_SM_00714]）。

该类具有移动语义，并完全禁止复制操作：

  • 复制构造函数和复制赋值运算符已删除（=delete）（[SWS_SM_81107]、[SWS_SM_81109]）。
  • 移动构造函数和移动赋值运算符将资源转移到新实例，并声明为线程安全（thread-safe）（[SWS_SM_81106]、[SWS_SM_81108]）。
  • 析构函数 ~S2RHub() 为虚函数，并指定为非线程安全（not thread-safe）（[SWS_SM_81105]）。

在并发性方面，操作方法（RequestToEnterSuspendMode、RequestToLeaveSuspendMode、EnterSuspendToRamOs）被归类为非线程安全（[SWS_SM_81110]、[SWS_SM_81111]、[SWS_SM_81112]）。因此，调用方必须确保对同一实例的控制调用以顺序或外部同步的方式进行。

使用路径

典型的使用流程包括 Satellite 的注册阶段、协同关闭至 Suspend 状态以及随后的重新激活：

  1. 初始化与注册：SMControlApplication 实例化 S2RHub（[SWS_SM_81103]）。与此同时，参与的 Satellite 通过 ara::sm::s2r::S2RSatellite::Offer 向 Hub 注册，并在发生可能的 StopOffer 之前均被视为处于活动注册状态（[SWS_SM_00710]、[SWS_SM_00713]）。Hub 会验证每个 Satellite 的 IAM 真实性（[SWS_SM_00715]）。
  2. Suspend 请求：为准备 Suspend 过程，控制应用程序调用 RequestToEnterSuspendMode(timeout)（[SWS_SM_81110]）。Hub 向所有处于活动注册状态的 Satellite 发送消息，随后这些 Satellite 执行其回调 EnterSuspendMode（[SWS_SM_00701]、[SWS_SM_00711]）并为冻结做好准备（保存持久化数据、终止服务提供和安全活动）（EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。
  3. 等待就绪：一旦所有被寻址的 Satellite 均做出了肯定响应、已注销或发生超时，由 RequestToEnterSuspendMode 提供的 ara::core::Future<void> 就会被解析（[SWS_SM_00702]、[SWS_SM_81110]）。
  4. 启动 OS-Suspend：在 Future 成功返回后，应用程序通过 EnterSuspendToRamOs() 触发操作系统向 Suspend-to-RAM 的转换（[SWS_SM_81112]）。
  5. 唤醒与正常运行：操作系统重新唤醒后，控制应用程序调用 RequestToLeaveSuspendMode(timeout)（[SWS_SM_81111]）。Hub 请求所有已注册的 Satellite 执行其回调 LeaveSuspendMode 并恢复正常功能（[SWS_SM_00703]、[SWS_SM_00707]、[SWS_SM_00711]）。

时序图：Suspend-to-RAM 周期的典型流程，从准备工作、OS-Suspend 到重新激活。来源：[SWS_SM_00701]、[SWS_SM_00702]、[SWS_SM_00703]、[SWS_SM_00707]、[SWS_SM_81110]、[SWS_SM_81111]、[SWS_SM_81112]。

错误场景

所有构造函数和接口方法均声明为 noexcept，并提供无条件的异常安全性（exception safe）（[SWS_SM_81103]、[SWS_SM_81110]、[SWS_SM_81111]、[SWS_SM_81112]）。错误状态通过违规（Violations）或返回的 ara::core::Future 中的特定错误代码进行指示。

创建对象时可能会出现以下 Violations（[SWS_SM_81103]）：

  • InsufficientPermissionsViolation：调用进程权限不足或与建模的 SuspendToRamHubMapping.process 不符；此外还会触发安全事件 SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED（[SWS_SM_00706]）。
  • InstanceSpecifierMappingIntegrityViolation：传入的 InstanceSpecifier 无法在模型中解析或未引用 PortPrototype 元素。
  • PortInterfaceMappingViolation：映射类型与端口接口的预期类型不符。
  • ProcessMappingViolation：存在匹配的 InstanceRef，但没有任何建模进程与当前运行时进程相匹配。
  • InstanceSpecifierAlreadyInUseViolation：该进程内已有一个现有实例在使用 InstanceSpecifier。
  • AraNotInitializedViolation：Adaptive Platform 的运行时环境（ara）在调用时尚未初始化。

在异步 Suspend 和 Resume 请求期间，Future 对象中可能会报告以下错误：

  • SmErrc::kCommunicationFailed：与 Satellite 的通信在底层传输层失败（具有回滚语义）（[SWS_SM_81110]、[SWS_SM_81111]）。
  • SmErrc::kCommunicationTimeout：至少有一个 Satellite 未在指定的 timeout 内做出响应（具有回滚语义）（[SWS_SM_00707]、[SWS_SM_81110]、[SWS_SM_81111]）。
  • SmErrc::kAtLeastOneRejected：在 RequestToEnterSuspendMode 时个别 Satellite 进入了 Suspend 状态，但至少有一个 Satellite 拒绝了请求（无回滚语义）（[SWS_SM_81110]）。
  • SmErrc::kAtLeastOneHadIssuesToLeave：在 RequestToLeaveSuspendMode 时至少有一个 Satellite 响应了 kRejected，导致并非所有 Satellite 都能正常恢复到正常状态（无回滚语义）（[SWS_SM_00707]、[SWS_SM_81111]）。

<h4>上下文</h4>
<p>类 <code>ara::sm::s2r::S2RHub</code> 在功能集群 <em>State Management</em>（SM）中构成了 Suspend-to-RAM 流程的核心中介和协调实例（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=34">SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”</a>）。为了优化机器的关机和启动时间，可以转换为 Suspend-to-RAM 状态以替代完整的系统重启（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=34">SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”</a>）。<code>S2RHub</code> 并非供常规 Adaptive Applications 使用，而是仅用于 State Management 实现或专用的控制应用程序（<code>SMControlApplication</code>）（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>）。</p>
<p>Suspend-to-RAM 的协调既可以通过 State Management 的 <em>StateMachine</em> 方法以声明方式进行，也可以在 <code>SMControlApplication</code> 中通过 <code>S2RHub</code> 的 C++ API 以命令方式进行；这两种使用方式严格互斥（<a class="spec-record-ref" data-req="SWS_SM_00684" href="../spec/record.html?id=SWS_SM_00684">[SWS_SM_00684]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=35">SWS StateManagement §7.5.1 “S2R Hub”</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=96">SWS StateManagement §7.7.15</a>）。主要的交互伙伴包括：</p>
<ul>
<li><strong>SMControlApplication / State Management：</strong>通过 Hub 的 C++ 接口启动 Suspend 和 Resume 流程，并在确认准备就绪后触发操作系统的 Suspend（<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>、<a class="spec-record-ref" data-req="SWS_SM_81112" href="../spec/record.html?id=SWS_SM_81112">[SWS_SM_81112]</a>）。</li>
<li><strong>S2R Satellites：</strong>其 Executable 被配置为 <code>suspendToRamAware</code> 的 Adaptive Applications 进程中的 <code>ara::sm::s2r::S2RSatellite</code> 实例（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=34">SWS StateManagement §7.5 “Interaction with Suspend-to-RAM Functionality”</a>）。它们通过 <code>Offer</code> 向 Hub 注册，并接收用于保存持久化数据和停止服务的指令（<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>、<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>）。</li>
<li><strong>Identity and Access Management（IAM）：</strong>对注册的 Satellite 进行身份验证，并将 Hub 的创建限制在部署模型中引用的进程（<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>、<a class="spec-record-ref" data-req="SWS_SM_00714" href="../spec/record.html?id=SWS_SM_00714">[SWS_SM_00714]</a>、<a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>）。</li>
<li><strong>操作系统（OS）：</strong>由 Hub 置于低功耗 Suspend 状态（<a class="spec-record-ref" data-req="SWS_SM_81112" href="../spec/record.html?id=SWS_SM_81112">[SWS_SM_81112]</a>）。</li>
</ul>

<h4>生命周期</h4>
<p>Hub 实例的创建通过构造函数 <code>S2RHub(const ara::core::InstanceSpecifier &amp;instance)</code> 显式进行（<a class="spec-record-ref" data-req="SWS_SM_81103" href="../spec/record.html?id=SWS_SM_81103">[SWS_SM_81103]</a>）。在构造期间，Hub 强制执行 IAM 检查：如果当前进程的上下文与 <code>SuspendToRamHubMapping.process</code> 中的建模不一致，则创建将被拒绝（<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>、<a class="spec-record-ref" data-req="SWS_SM_00714" href="../spec/record.html?id=SWS_SM_00714">[SWS_SM_00714]</a>）。</p>
<p>该类具有移动语义，并完全禁止复制操作：</p>
<ul>
<li>复制构造函数和复制赋值运算符已删除（<code>=delete</code>）（<a class="spec-record-ref" data-req="SWS_SM_81107" href="../spec/record.html?id=SWS_SM_81107">[SWS_SM_81107]</a>、<a class="spec-record-ref" data-req="SWS_SM_81109" href="../spec/record.html?id=SWS_SM_81109">[SWS_SM_81109]</a>）。</li>
<li>移动构造函数和移动赋值运算符将资源转移到新实例，并声明为线程安全（<code>thread-safe</code>）（<a class="spec-record-ref" data-req="SWS_SM_81106" href="../spec/record.html?id=SWS_SM_81106">[SWS_SM_81106]</a>、<a class="spec-record-ref" data-req="SWS_SM_81108" href="../spec/record.html?id=SWS_SM_81108">[SWS_SM_81108]</a>）。</li>
<li>析构函数 <code>~S2RHub()</code> 为虚函数，并指定为非线程安全（<code>not thread-safe</code>）（<a class="spec-record-ref" data-req="SWS_SM_81105" href="../spec/record.html?id=SWS_SM_81105">[SWS_SM_81105]</a>）。</li>
</ul>
<p>在并发性方面，操作方法（<code>RequestToEnterSuspendMode</code>、<code>RequestToLeaveSuspendMode</code>、<code>EnterSuspendToRamOs</code>）被归类为非线程安全（<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>、<a class="spec-record-ref" data-req="SWS_SM_81112" href="../spec/record.html?id=SWS_SM_81112">[SWS_SM_81112]</a>）。因此，调用方必须确保对同一实例的控制调用以顺序或外部同步的方式进行。</p>

<h4>使用路径</h4>
<p>典型的使用流程包括 Satellite 的注册阶段、协同关闭至 Suspend 状态以及随后的重新激活：</p>
<ol>
<li><strong>初始化与注册：</strong><code>SMControlApplication</code> 实例化 <code>S2RHub</code>（<a class="spec-record-ref" data-req="SWS_SM_81103" href="../spec/record.html?id=SWS_SM_81103">[SWS_SM_81103]</a>）。与此同时，参与的 Satellite 通过 <code>ara::sm::s2r::S2RSatellite::Offer</code> 向 Hub 注册，并在发生可能的 <code>StopOffer</code> 之前均被视为处于活动注册状态（<a class="spec-record-ref" data-req="SWS_SM_00710" href="../spec/record.html?id=SWS_SM_00710">[SWS_SM_00710]</a>、<a class="spec-record-ref" data-req="SWS_SM_00713" href="../spec/record.html?id=SWS_SM_00713">[SWS_SM_00713]</a>）。Hub 会验证每个 Satellite 的 IAM 真实性（<a class="spec-record-ref" data-req="SWS_SM_00715" href="../spec/record.html?id=SWS_SM_00715">[SWS_SM_00715]</a>）。</li>
<li><strong>Suspend 请求：</strong>为准备 Suspend 过程，控制应用程序调用 <code>RequestToEnterSuspendMode(timeout)</code>（<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>）。Hub 向所有处于活动注册状态的 Satellite 发送消息，随后这些 Satellite 执行其回调 <code>EnterSuspendMode</code>（<a class="spec-record-ref" data-req="SWS_SM_00701" href="../spec/record.html?id=SWS_SM_00701">[SWS_SM_00701]</a>、<a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>）并为冻结做好准备（保存持久化数据、终止服务提供和安全活动）（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_SWArchitecture&amp;page=53">EXP SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”</a>）。</li>
<li><strong>等待就绪：</strong>一旦所有被寻址的 Satellite 均做出了肯定响应、已注销或发生超时，由 <code>RequestToEnterSuspendMode</code> 提供的 <code>ara::core::Future&lt;void&gt;</code> 就会被解析（<a class="spec-record-ref" data-req="SWS_SM_00702" href="../spec/record.html?id=SWS_SM_00702">[SWS_SM_00702]</a>、<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>）。</li>
<li><strong>启动 OS-Suspend：</strong>在 Future 成功返回后，应用程序通过 <code>EnterSuspendToRamOs()</code> 触发操作系统向 Suspend-to-RAM 的转换（<a class="spec-record-ref" data-req="SWS_SM_81112" href="../spec/record.html?id=SWS_SM_81112">[SWS_SM_81112]</a>）。</li>
<li><strong>唤醒与正常运行：</strong>操作系统重新唤醒后，控制应用程序调用 <code>RequestToLeaveSuspendMode(timeout)</code>（<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>）。Hub 请求所有已注册的 Satellite 执行其回调 <code>LeaveSuspendMode</code> 并恢复正常功能（<a class="spec-record-ref" data-req="SWS_SM_00703" href="../spec/record.html?id=SWS_SM_00703">[SWS_SM_00703]</a>、<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>、<a class="spec-record-ref" data-req="SWS_SM_00711" href="../spec/record.html?id=SWS_SM_00711">[SWS_SM_00711]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>所有构造函数和接口方法均声明为 <code>noexcept</code>，并提供无条件的异常安全性（<code>exception safe</code>）（<a class="spec-record-ref" data-req="SWS_SM_81103" href="../spec/record.html?id=SWS_SM_81103">[SWS_SM_81103]</a>、<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>、<a class="spec-record-ref" data-req="SWS_SM_81112" href="../spec/record.html?id=SWS_SM_81112">[SWS_SM_81112]</a>）。错误状态通过违规（Violations）或返回的 <code>ara::core::Future</code> 中的特定错误代码进行指示。</p>
<p>创建对象时可能会出现以下 Violations（<a class="spec-record-ref" data-req="SWS_SM_81103" href="../spec/record.html?id=SWS_SM_81103">[SWS_SM_81103]</a>）：</p>
<ul>
<li><code>InsufficientPermissionsViolation</code>：调用进程权限不足或与建模的 <code>SuspendToRamHubMapping.process</code> 不符；此外还会触发安全事件 <code>SEV_ACCESS_CONTROL_SM_IAM_ACCESS_DENIED</code>（<a class="spec-record-ref" data-req="SWS_SM_00706" href="../spec/record.html?id=SWS_SM_00706">[SWS_SM_00706]</a>）。</li>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>：传入的 <code>InstanceSpecifier</code> 无法在模型中解析或未引用 <code>PortPrototype</code> 元素。</li>
<li><code>PortInterfaceMappingViolation</code>：映射类型与端口接口的预期类型不符。</li>
<li><code>ProcessMappingViolation</code>：存在匹配的 <code>InstanceRef</code>，但没有任何建模进程与当前运行时进程相匹配。</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>：该进程内已有一个现有实例在使用 <code>InstanceSpecifier</code>。</li>
<li><code>AraNotInitializedViolation</code>：Adaptive Platform 的运行时环境（<code>ara</code>）在调用时尚未初始化。</li>
</ul>
<p>在异步 Suspend 和 Resume 请求期间，Future 对象中可能会报告以下错误：</p>
<ul>
<li><code>SmErrc::kCommunicationFailed</code>：与 Satellite 的通信在底层传输层失败（具有回滚语义）（<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>）。</li>
<li><code>SmErrc::kCommunicationTimeout</code>：至少有一个 Satellite 未在指定的 <code>timeout</code> 内做出响应（具有回滚语义）（<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>、<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>）。</li>
<li><code>SmErrc::kAtLeastOneRejected</code>：在 <code>RequestToEnterSuspendMode</code> 时个别 Satellite 进入了 Suspend 状态，但至少有一个 Satellite 拒绝了请求（无回滚语义）（<a class="spec-record-ref" data-req="SWS_SM_81110" href="../spec/record.html?id=SWS_SM_81110">[SWS_SM_81110]</a>）。</li>
<li><code>SmErrc::kAtLeastOneHadIssuesToLeave</code>：在 <code>RequestToLeaveSuspendMode</code> 时至少有一个 Satellite 响应了 <code>kRejected</code>，导致并非所有 Satellite 都能正常恢复到正常状态（无回滚语义）（<a class="spec-record-ref" data-req="SWS_SM_00707" href="../spec/record.html?id=SWS_SM_00707">[SWS_SM_00707]</a>、<a class="spec-record-ref" data-req="SWS_SM_81111" href="../spec/record.html?id=SWS_SM_81111">[SWS_SM_81111]</a>）。</li>
</ul>
