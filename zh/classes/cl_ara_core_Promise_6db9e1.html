上下文

模板类 ara::core::Promise<T, E> 提供了 C++ 标准类 std::promise 的 AUTOSAR Adaptive 特定变体。其核心任务是构成异步同步通道的写入端，并管理共享状态（Shared State）。通过该 Shared State，生产者执行路径将异步计算的结果——类型为 T 的值、类型为 E 的错误或连贯的 ara::core::Result<T, E>——传递给读取端对等体 ara::core::Future<T, E>，后者通过 get_future() 获取 [SWS_CORE_00344]。

模板签名的一个核心 AUTOSAR 规定是默认赋值 E = ara::core::ErrorCode。如果实例化与此不同（E != ara::core::ErrorCode），规范强制要求报告编译错误。推测该规定旨在严格推行 Adaptive Platform 的标准化错误模型，以便异步接口能够统一与 ara::core::Result 协同工作。协作中通常涉及三个实体：作为 Promise 所有者的生成程序部分、用于跨线程状态耦合的受管 Shared State，以及一个或多个通过 ara::core::Future 接收异步结果的消费者。

生命周期

ara::core::Promise 的生命周期遵循严格的仅移动（Move-Only）语义，并控制底层 Shared State 的存在：

  • 创建：默认构造函数 Promise() 构造一个带有新的、尚未满足的 Shared State [SWS_CORE_00341] 的实例。规范将其指定为保证具有 noexcept 的异常安全以及是线程安全的 [SWS_CORE_00341]。
  • 复制保护与所有权转移：复制构造函数 [SWS_CORE_00350] 和复制赋值运算符 [SWS_CORE_00351] 已被显式删除（= delete）。所有权的变更仅可通过移动操作进行。移动构造函数接管源实例的 Shared State，并且是 noexcept，但不是线程安全的 [SWS_CORE_00342]。移动赋值运算符放弃先前持有的 Shared State（abandons any shared state），并转移另一实例的状态，这类似于后续的 swap [SWS_CORE_00343]。此外，两个实例可以通过 swap() 交换其状态 [SWS_CORE_00352]。
  • Future 关联：通过 get_future()，恰好有一个 ara::core::Future<T, E> 实例与同一个 Shared State 相关联 [SWS_CORE_00344]。由于每个 Promise 只能存在一个 Future，因此该调用仅允许执行一次 [SWS_CORE_00344]。
  • 向 Ready 的状态转换：通过 set_value() [SWS_CORE_00345]、[SWS_CORE_00346] 传入值，通过 SetError() [SWS_CORE_00353]、[SWS_CORE_00354] 传入错误，或通过 SetResult() [SWS_CORE_00355]、[SWS_CORE_00356] 传入整体结果，会将 Shared State 不可逆地切换为 ready 状态。所有这些满足方法均被声明为线程安全。
  • 销毁：析构函数 ~Promise() 离开并放弃 Shared State（abandons any shared state）[SWS_CORE_00349]。解释：如果在设置值或错误之前发生销毁，类似于 std::promise 的行为，孤立的 Shared State 预计将对等待中的 Future 进行中止。

使用路径

用于异步传递值或错误的典型调用顺序包括以下步骤：

  1. 创建：生成者通过默认构造函数 [SWS_CORE_00341] 实例化 ara::core::Promise<T, E>。
  2. 连接通道：在将异步任务传递给后台线程之前，生成者调用 get_future() [SWS_CORE_00344]，并将生成的 ara::core::Future 实例传递给消费者。
  3. 异步处理：生成者执行计算或 I/O 操作。消费者可以并行继续工作或等待 Future。
  4. 设置结果：操作完成后，生成者将结果存放在 Shared State 中。根据执行结果，其选择：
    • 成功的值：set_value() 作为复制 [SWS_CORE_00345] 或移动 [SWS_CORE_00346]。
    • 错误状态：SetError() 通过移动 [SWS_CORE_00353] 或复制 [SWS_CORE_00354]。
    • 现有 Result 对象：SetResult() 通过复制 [SWS_CORE_00355] 或移动 [SWS_CORE_00356]。
  5. 释放：通过设置，Shared State 被标记为完成；消费者读取该值。Promise 在离开作用域时被销毁 [SWS_CORE_00349]。

时序图：用于异步传递值或错误的典型调用与交互序列。来源：[SWS_CORE_00341]、[SWS_CORE_00344]、[SWS_CORE_00345]、[SWS_CORE_00353]、[SWS_CORE_00355]。

错误场景

该规范针对非法调用定义了固定的违规条件（Violations）以及对异常安全性的要求：

  • 多次获取 Future：如果针对同一个 Shared State 调用 get_future() 超过一次，则会发生违规 IsoStdFutureErrcFutureAlreadyRetrievedViolation [SWS_CORE_00344]。
  • 无 Shared State 的操作：如果 *this 不拥有 Shared State（例如在移动操作之后），方法调用会导致文档记录的违规：
    • get_future() 报告 IsoStdFutureErrcNoStateViolation [SWS_CORE_00344]。
    • set_value()、SetError() 和 SetResult() 引发 PromiseNoSharedStateToSetViolation（[SWS_CORE_00345]、[SWS_CORE_00346]、[SWS_CORE_00353]、[SWS_CORE_00354]、[SWS_CORE_00355]、[SWS_CORE_00356]）。
  • 多次满足（Double Satisfaction）：如果在 Shared State 中已经存入了值、错误或 Result，则对 set_value()、SetError() 或 SetResult() 的任何进一步调用都会导致违规 IsoStdFutureErrcPromiseAlreadySatisfiedViolation（[SWS_CORE_00345]、[SWS_CORE_00346]、[SWS_CORE_00353]、[SWS_CORE_00354]、[SWS_CORE_00355]、[SWS_CORE_00356]）。
  • 错误类型不一致时的编译错误：如果类模板使用满足 E != ara::core::ErrorCode 的类型进行实例化，则构建必然因 Compile Error 而中止。
  • 有条件的异常安全：构造函数、析构函数、赋值、移动、交换以及 get_future() 无条件为 noexcept 且具备异常安全性（[SWS_CORE_00341]、[SWS_CORE_00342]、[SWS_CORE_00343]、[SWS_CORE_00344]、[SWS_CORE_00349]、[SWS_CORE_00352]）。相比之下，方法 set_value()、SetError() 和 SetResult() 是有条件的异常安全（conditionally exception safe）；它们的 noexcept 属性取决于 T 和 E 的复制或移动构造函数是否被声明为不抛出异常（std::is_nothrow_*_constructible）（[SWS_CORE_00345]、[SWS_CORE_00346]、[SWS_CORE_00353]、[SWS_CORE_00354]、[SWS_CORE_00355]、[SWS_CORE_00356]）。

<h4>上下文</h4>
<p>模板类 <code>ara::core::Promise&lt;T, E&gt;</code> 提供了 C++ 标准类 <code>std::promise</code> 的 AUTOSAR Adaptive 特定变体。其核心任务是构成异步同步通道的写入端，并管理共享状态（Shared State）。通过该 Shared State，生产者执行路径将异步计算的结果——类型为 <code>T</code> 的值、类型为 <code>E</code> 的错误或连贯的 <code>ara::core::Result&lt;T, E&gt;</code>——传递给读取端对等体 <code>ara::core::Future&lt;T, E&gt;</code>，后者通过 <code>get_future()</code> 获取 <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>。</p>
<p>模板签名的一个核心 AUTOSAR 规定是默认赋值 <code>E = ara::core::ErrorCode</code>。如果实例化与此不同（<code>E != ara::core::ErrorCode</code>），规范强制要求报告编译错误。推测该规定旨在严格推行 Adaptive Platform 的标准化错误模型，以便异步接口能够统一与 <code>ara::core::Result</code> 协同工作。协作中通常涉及三个实体：作为 <code>Promise</code> 所有者的生成程序部分、用于跨线程状态耦合的受管 Shared State，以及一个或多个通过 <code>ara::core::Future</code> 接收异步结果的消费者。</p>

<h4>生命周期</h4>
<p><code>ara::core::Promise</code> 的生命周期遵循严格的仅移动（Move-Only）语义，并控制底层 Shared State 的存在：</p>
<ul>
<li><strong>创建：</strong>默认构造函数 <code>Promise()</code> 构造一个带有新的、尚未满足的 Shared State <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a> 的实例。规范将其指定为保证具有 <code>noexcept</code> 的异常安全以及是线程安全的 <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a>。</li>
<li><strong>复制保护与所有权转移：</strong>复制构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00350" href="../spec/record.html?id=SWS_CORE_00350">[SWS_CORE_00350]</a> 和复制赋值运算符 <a class="spec-record-ref" data-req="SWS_CORE_00351" href="../spec/record.html?id=SWS_CORE_00351">[SWS_CORE_00351]</a> 已被显式删除（<code>= delete</code>）。所有权的变更仅可通过移动操作进行。移动构造函数接管源实例的 Shared State，并且是 <code>noexcept</code>，但不是线程安全的 <a class="spec-record-ref" data-req="SWS_CORE_00342" href="../spec/record.html?id=SWS_CORE_00342">[SWS_CORE_00342]</a>。移动赋值运算符放弃先前持有的 Shared State（<em>abandons any shared state</em>），并转移另一实例的状态，这类似于后续的 <code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_00343" href="../spec/record.html?id=SWS_CORE_00343">[SWS_CORE_00343]</a>。此外，两个实例可以通过 <code>swap()</code> 交换其状态 <a class="spec-record-ref" data-req="SWS_CORE_00352" href="../spec/record.html?id=SWS_CORE_00352">[SWS_CORE_00352]</a>。</li>
<li><strong>Future 关联：</strong>通过 <code>get_future()</code>，恰好有一个 <code>ara::core::Future&lt;T, E&gt;</code> 实例与同一个 Shared State 相关联 <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>。由于每个 Promise 只能存在一个 Future，因此该调用仅允许执行一次 <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>。</li>
<li><strong>向 Ready 的状态转换：</strong>通过 <code>set_value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a> 传入值，通过 <code>SetError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a> 传入错误，或通过 <code>SetResult()</code> <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a> 传入整体结果，会将 Shared State 不可逆地切换为 <em>ready</em> 状态。所有这些满足方法均被声明为线程安全。</li>
<li><strong>销毁：</strong>析构函数 <code>~Promise()</code> 离开并放弃 Shared State（<em>abandons any shared state</em>）<a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>。解释：如果在设置值或错误之前发生销毁，类似于 <code>std::promise</code> 的行为，孤立的 Shared State 预计将对等待中的 Future 进行中止。</li>
</ul>

<h4>使用路径</h4>
<p>用于异步传递值或错误的典型调用顺序包括以下步骤：</p>
<ol>
<li><strong>创建：</strong>生成者通过默认构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00341" href="../spec/record.html?id=SWS_CORE_00341">[SWS_CORE_00341]</a> 实例化 <code>ara::core::Promise&lt;T, E&gt;</code>。</li>
<li><strong>连接通道：</strong>在将异步任务传递给后台线程之前，生成者调用 <code>get_future()</code> <a class="spec-record-ref" data-req="SWS_CORE_00344" href="../spec/record.html?id=SWS_CORE_00344">[SWS_CORE_00344]</a>，并将生成的 <code>ara::core::Future</code> 实例传递给消费者。</li>
<li><strong>异步处理：</strong>生成者执行计算或 I/O 操作。消费者可以并行继续工作或等待 <code>Future</code>。</li>
<li><strong>设置结果：</strong>操作完成后，生成者将结果存放在 Shared State 中。根据执行结果，其选择：
<ul>
<li>成功的值：<code>set_value()</code> 作为复制 <a class="spec-record-ref" data-req="SWS_CORE_00345" href="../spec/record.html?id=SWS_CORE_00345">[SWS_CORE_00345]</a> 或移动 <a class="spec-record-ref" data-req="SWS_CORE_00346" href="../spec/record.html?id=SWS_CORE_00346">[SWS_CORE_00346]</a>。</li>
<li>错误状态：<code>SetError()</code> 通过移动 <a class="spec-record-ref" data-req="SWS_CORE_00353" href="../spec/record.html?id=SWS_CORE_00353">[SWS_CORE_00353]</a> 或复制 <a class="spec-record-ref" data-req="SWS_CORE_00354" href="../spec/record.html?id=SWS_CORE_00354">[SWS_CORE_00354]</a>。</li>
<li>现有 Result 对象：<code>SetResult()</code> 通过复制 <a class="spec-record-ref" data-req="SWS_CORE_00355" href="../spec/record.html?id=SWS_CORE_00355">[SWS_CORE_00355]</a> 或移动 <a class="spec-record-ref" data-req="SWS_CORE_00356" href="../spec/record.html?id=SWS_CORE_00356">[SWS_CORE_00356]</a>。</li>
</ul>
</li>
<li><strong>释放：</strong>通过设置，Shared State 被标记为完成；消费者读取该值。<code>Promise</code> 在离开作用域时被销毁 <a class="spec-record-ref" data-req="SWS_CORE_00349" href="../spec/record.html?id=SWS_CORE_00349">[SWS_CORE_00349]</a>。</li>
</ol>
