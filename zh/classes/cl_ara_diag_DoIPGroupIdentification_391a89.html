用于向 Diagnostic Manager 提供 DoIP 组识别状态。

类 ara::diag::DoIPGroupIdentification 用作 Adaptive 应用程序的抽象接口，以便向 Diagnostic Management 提供 DoIP 组识别的当前状态 [SWS_DM_00724]。在特定于端口的实例化之后，应用程序通过 Offer() 激活请求转发，并在对象销毁前通过 StopOffer() 将其终止 [SWS_DM_00725]。处理器实例是唯一的，既不可复制也不可移动，并通过 ara::core::Future 异步响应查询。

上下文

类 ara::diag::DoIPGroupIdentification 提供诊断管理（AUTOSAR AP SWS Diagnostics 第73页）的功能接口，自适应应用程序通过该接口为 DoIP 协议提供当前组识别状态（GID 状态）[SWS_DM_00724]。在平台架构中，该类充当两个主要交互伙伴之间的中介：内部 Diagnostic Management 守护进程（DM）（负责通过网络处理标准化车辆识别和 DoIP 消息）与具体实现纯虚方法 GetGidStatus() 的应用程序特定实现。请求的提供和接收通过显式服务提供进行控制 [SWS_DM_00725]。

生命周期

DoIPGroupIdentification 的实例表示一个唯一的诊断端口。出于这个原因，该类被设计为唯一管理的对象：拷贝构造函数 [SWS_DM_01641] 和移动构造函数 [SWS_DM_01642] 以及相应的赋值运算符 [SWS_DM_01639]、[SWS_DM_01640] 均被显式删除（=delete）。

创建必须通过指定 ara::core::InstanceSpecifier 以及并发模式 ConcurrencyType 的参数化构造函数进行 [SWS_DM_00722]。生命周期分为以下阶段：

  • 未提供（Not Offered）：构造后，对象存在于进程的地址空间中，但尚未接收来自 DM 的请求。
  • 已提供（Offered）：通过同步调用 Offer() [SWS_DM_00725]，处理器在 DM 处被激活，从而转发传入的 DoIP 状态请求。
  • 已停止（Stopped）：调用 StopOffer() [SWS_DM_00726] 会撤销 DM 的转发权限，并将对象转换回非活动状态。

销毁通过虚析构函数 ~DoIPGroupIdentification() 进行 [SWS_DM_00723]。在并发性方面，构造函数是线程安全的，而 Offer()、StopOffer() 以及析构函数不是线程安全的 [SWS_DM_00722]、[SWS_DM_00723]、[SWS_DM_00725]、[SWS_DM_00726]。查询函数 GetGidStatus() 的线程安全性由构造函数中选择的 ConcurrencyType 有条件地定义 [SWS_DM_00724]。解释：如果在析构函数之前未调用 StopOffer()，析构函数可能会隐式终止正在进行的转发。

使用路径

典型用法包括初始化、激活、异步处理和停用：

  1. 具体的诊断类继承自 ara::diag::DoIPGroupIdentification 并实现方法 GetGidStatus() [SWS_DM_00724]。
  2. 应用程序使用配置的 PortPrototype 的 InstanceSpecifier 创建对象，并确定 GetGidStatus() 是否允许并发调用（kConcurrent）或不允许（kNotConcurrent）[SWS_DM_00722]。
  3. 通过 Offer()，应用程序激活用于 Diagnostic Management 的处理器 [SWS_DM_00725]。
  4. 一旦 DoIP 请求到达，DM 就会调用 GetGidStatus()；应用程序通过 ara::core::Future<GidStatus> 异步返回 GID 状态 [SWS_DM_00724]。
  5. 在终止服务或关闭组件之前，应用程序调用 StopOffer() [SWS_DM_00726]，随后销毁对象 [SWS_DM_00723]。

错误场景

使用 DoIPGroupIdentification 时，在构造和提供阶段定义了以下错误条件：

  • 模型与映射错误（构造函数）：如果实例化失败，将报告标准化违规 [SWS_DM_00722]：
    • InstanceSpecifierMappingIntegrityViolation：标识符无法解析或未引用 PortPrototype。
    • PortInterfaceMappingViolation：引用的端口未类型化为 DiagnosticDoIPGroupIdentificationInterface。
    • ProcessMappingViolation：在模型中没有与执行上下文相匹配的进程。
    • InstanceSpecifierAlreadyInUseViolation：指定的端口标识符在当前运行的进程中已被另一个实例使用。
  • 服务提供错误（Offer()）：该方法返回一个 ara::core::Result<void>。如果已成功为该处理器提供了服务，则再次调用将失败并带有错误码 DiagOfferErrc::kAlreadyOffered [SWS_DM_00725]。
  • 状态查询错误：接口 GetGidStatus() 未指定标准化错误码 [SWS_DM_00724]；应用程序内部错误必须通过返回的 Future 的结果对象来体现。
