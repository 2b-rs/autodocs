类 ara::core::Executor

[SWS_CORE_00008] Upstream: RS_AP_00130

class Executor {...};

Provides an interface for a executing context, which asynchronously invokes Callable ([4] [func.wrap.func]) objects in a guaranteed thread-safe context. The execute(...) method in [SWS_CORE_00024] returns a ara::core::Future object to the caller for further result/error extraction or management of the asynchronous-context; the execute_oneway(...) method in [SWS_CORE_00025] imply fire-and-forget semantics and thus no asynchronous-context (ara::core::Future) is returned.

参考书目SWS核心：[4] ISO/IEC 14882:2014, Information technology – Programming languages – C++ – www.iso.org

使用目的

ara::core::Executor 提供了一个执行上下文，可在有保证的线程安全上下文中异步调用Callable 对象。 [SWS_CORE_00008]

与其他班级的互动

execute() 使用其参数异步调用函数，并返回包含结果或错误的Future。 oneway_execute() 也异步启动该函数，但遵循即发即弃语义并且不返回 Future。 [SWS_CORE_00024][SWS_CORE_00025]

生命周期和所有权

可以进行复制移动构造和复制移动分配；移动操作和析构函数是noexcept。 [SWS_CORE_00009][SWS_CORE_00015][SWS_CORE_00017][SWS_CORE_00018][SWS_CORE_00019]

销毁未完成的可调用对象

该规范没有指定当Executor被销毁时，仍在运行或等待的Callables会发生什么：[SWS_CORE_00019]描述了没有任何行为承诺的析构函数（没有加入、分离或中止），并且功能章节SWS Core §7.4.1.2 “ara::core::Executor”也没有对执行上下文的生命周期做出任何声明。该规范本身将唯一的非正式行为描述命名为已知限制SWS Core §4.1 “Known limitations”。因此，该行为取决于实现；目前还不清楚从 execute() 获得的 Future 在执行器被销毁后是否会准备就绪。

解释：由于 Executor 可以复制 [SWS_CORE_00009]，句柄语义建议共享执行上下文 - 这是无法保证的。可移植代码使Executor至少在所有以它开始的可调用对象中保持活动状态：在execute()完成交付的Future，然后使用wait()/GetResult()销毁它或检查is_ready()；对于oneway_execute()和Future::then(func, executor)延续，将Executor链接到应用程序生命周期。
