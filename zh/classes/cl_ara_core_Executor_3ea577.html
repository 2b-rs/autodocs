类 ara::core::Executor

[SWS_CORE_00008] Upstream: RS_AP_00130

class Executor {...};

Provides an interface for a executing context, which asynchronously invokes Callable ([4] [func.wrap.func]) objects in a guaranteed thread-safe context. The execute(...) method in [SWS_CORE_00024] returns a ara::core::Future object to the caller for further result/error extraction or management of the asynchronous-context; the execute_oneway(...) method in [SWS_CORE_00025] imply fire-and-forget semantics and thus no asynchronous-context (ara::core::Future) is returned.

参考书目SWS核心：[4] ISO/IEC 14882:2014, Information technology – Programming languages – C++ – www.iso.org

上下文

类 ara::core::Executor 为执行上下文提供了一个接口，该上下文在保证线程安全的环境中异步执行可调用对象（Callables）。在 AUTOSAR Adaptive Platform 的 core 模块内，该类抽象了调用与实际执行之间的解耦，从而使应用程序能够启动后台任务，而无需直接管理自己的线程结构或同步原语。

与 ara::core::Executor 的交互主要涉及三方：

  • 调用方（Caller）：传递可调用单元（如函数对象、Lambda 或函数指针）及其关联实参。
  • 执行上下文（Executor 实例和后台 Worker）：接收任务并以异步且线程安全的方式执行 Callable。
  • 返回通道（ara::core::Future）：对于需要同步的任务，调用 execute（[SWS_CORE_00024]）会返回一个 Future 对象，调用方稍后可通过该对象访问计算结果或发生的错误。对于通过 oneway_execute（[SWS_CORE_00025]）执行的纯 Fire-and-Forget 任务，此返回通道则完全省略。

生命周期

ara::core::Executor 实例的生命周期由构造、值传递和析构决定。规范在此定义了有关线程安全性和异常安全性的特定属性：

  • 复制：复制构造函数（[SWS_CORE_00009]）和复制赋值运算符（[SWS_CORE_00017]）被声明为线程安全（thread-safe），但明确声明为非异常安全（not exception safe）。因此实例可以并发复制，但调用方必须针对失败的复制操作做好防范措施。
  • 移动：移动构造函数（[SWS_CORE_00015]）和移动赋值运算符（[SWS_CORE_00018]）被声明为带有 noexcept 且异常安全（exception safe）。然而它们不是线程安全的（not thread-safe），因此移动 Executor 必须在没有并发访问的情况下以排他方式进行。
  • 销毁：析构函数 ~Executor()（[SWS_CORE_00019]）为 noexcept、异常安全且线程安全。即使在多线程场景下，它也能确保实例的有序销毁。

使用路径

对于异步任务处理，ara::core::Executor 提供了两条不同的路径：

  1. 带结果监控的异步执行（execute）： 调用方将 Callable f 及其参数 p... 传递给模板方法 execute（[SWS_CORE_00024]）。该函数立即返回一个类型为 ara::core::Future<std::invoke_result_t<std::decay_t<F>, std::decay_t<P>...>> 的对象。f 的执行在后台并发进行。调用方在适当的时候通过 Future 查询结果。需要注意的是，execute 本身被声明为非线程安全（not thread-safe）（[SWS_CORE_00024]）；因此在同一个 Executor 实例上对 execute 的并发调用必须由调用方进行同步。
  2. 无返回通道的单向执行（oneway_execute）： 如果调用方不需要结果和错误监控，则使用 oneway_execute（[SWS_CORE_00025]）。该方法具有 Fire-and-Forget 语义，返回 void 且不生成 Future。与 execute 不同，oneway_execute 被直接声明为线程安全（thread-safe）（[SWS_CORE_00025]）。

时序图：通过 Future 进行结果查询的异步函数传递典型流程。来源：[SWS_CORE_00024]

错误场景

错误处理方式因所选的执行方法和生命周期操作而异：

  • 无同步错误代码：无论 execute（[SWS_CORE_00024]）还是 oneway_execute（[SWS_CORE_00025]）在调用本身时均未定义标准化错误代码；这两种方法均被声明为带有 noexcept。
  • 在 execute 中通过 Future 传递错误：如果在 Callable 的异步执行过程中发生错误，该错误将保存在由 execute 返回的 ara::core::Future 中（[SWS_CORE_00024]）。在执行成功时，Future 包含计算得到的值；在发生错误时，则包含错误代码（ErrorCode）。
  • oneway_execute 的错误处理：由于不存在返回通道，因此在通过 oneway_execute（[SWS_CORE_00025]）传递的 Callable 异步执行期间发生的错误无法传播给调用方。这些错误必须在函数对象内部自行捕获。
  • 复制操作失败：由于复制构造函数（[SWS_CORE_00009]）和复制赋值操作（[SWS_CORE_00017]）被标明为非异常安全，复制操作可能会失败，而移动操作（[SWS_CORE_00015]、[SWS_CORE_00018]）通过 noexcept 保证异常安全。

<h4>上下文</h4>
<p>类 <code>ara::core::Executor</code> 为执行上下文提供了一个接口，该上下文在保证线程安全的环境中异步执行可调用对象（Callables）。在 AUTOSAR Adaptive Platform 的 <code>core</code> 模块内，该类抽象了调用与实际执行之间的解耦，从而使应用程序能够启动后台任务，而无需直接管理自己的线程结构或同步原语。</p>
<p>与 <code>ara::core::Executor</code> 的交互主要涉及三方：</p>
<ul>
<li><strong>调用方（Caller）</strong>：传递可调用单元（如函数对象、Lambda 或函数指针）及其关联实参。</li>
<li><strong>执行上下文（Executor 实例和后台 Worker）</strong>：接收任务并以异步且线程安全的方式执行 Callable。</li>
<li><strong>返回通道（<code>ara::core::Future</code>）</strong>：对于需要同步的任务，调用 <code>execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>）会返回一个 Future 对象，调用方稍后可通过该对象访问计算结果或发生的错误。对于通过 <code>oneway_execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>）执行的纯 Fire-and-Forget 任务，此返回通道则完全省略。</li>
</ul>

<h4>生命周期</h4>
<p><code>ara::core::Executor</code> 实例的生命周期由构造、值传递和析构决定。规范在此定义了有关线程安全性和异常安全性的特定属性：</p>
<ul>
<li><strong>复制</strong>：复制构造函数（<a class="spec-record-ref" data-req="SWS_CORE_00009" href="../spec/record.html?id=SWS_CORE_00009">[SWS_CORE_00009]</a>）和复制赋值运算符（<a class="spec-record-ref" data-req="SWS_CORE_00017" href="../spec/record.html?id=SWS_CORE_00017">[SWS_CORE_00017]</a>）被声明为线程安全（<em>thread-safe</em>），但明确声明为非异常安全（<em>not exception safe</em>）。因此实例可以并发复制，但调用方必须针对失败的复制操作做好防范措施。</li>
<li><strong>移动</strong>：移动构造函数（<a class="spec-record-ref" data-req="SWS_CORE_00015" href="../spec/record.html?id=SWS_CORE_00015">[SWS_CORE_00015]</a>）和移动赋值运算符（<a class="spec-record-ref" data-req="SWS_CORE_00018" href="../spec/record.html?id=SWS_CORE_00018">[SWS_CORE_00018]</a>）被声明为带有 <code>noexcept</code> 且异常安全（<em>exception safe</em>）。然而它们不是线程安全的（<em>not thread-safe</em>），因此移动 Executor 必须在没有并发访问的情况下以排他方式进行。</li>
<li><strong>销毁</strong>：析构函数 <code>~Executor()</code>（<a class="spec-record-ref" data-req="SWS_CORE_00019" href="../spec/record.html?id=SWS_CORE_00019">[SWS_CORE_00019]</a>）为 <code>noexcept</code>、异常安全且线程安全。即使在多线程场景下，它也能确保实例的有序销毁。</li>
</ul>

<h4>使用路径</h4>
<p>对于异步任务处理，<code>ara::core::Executor</code> 提供了两条不同的路径：</p>
<ol>
<li><strong>带结果监控的异步执行（<code>execute</code>）</strong>：
调用方将 Callable <code>f</code> 及其参数 <code>p...</code> 传递给模板方法 <code>execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>）。该函数立即返回一个类型为 <code>ara::core::Future&lt;std::invoke_result_t&lt;std::decay_t&lt;F&gt;, std::decay_t&lt;P&gt;...&gt;&gt;</code> 的对象。<code>f</code> 的执行在后台并发进行。调用方在适当的时候通过 Future 查询结果。需要注意的是，<code>execute</code> 本身被声明为非线程安全（<em>not thread-safe</em>）（<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>）；因此在同一个 Executor 实例上对 <code>execute</code> 的并发调用必须由调用方进行同步。</li>
<li><strong>无返回通道的单向执行（<code>oneway_execute</code>）</strong>：
如果调用方不需要结果和错误监控，则使用 <code>oneway_execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>）。该方法具有 Fire-and-Forget 语义，返回 <code>void</code> 且不生成 Future。与 <code>execute</code> 不同，<code>oneway_execute</code> 被直接声明为线程安全（<em>thread-safe</em>）（<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>错误处理方式因所选的执行方法和生命周期操作而异：</p>
<ul>
<li><strong>无同步错误代码</strong>：无论 <code>execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>）还是 <code>oneway_execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>）在调用本身时均未定义标准化错误代码；这两种方法均被声明为带有 <code>noexcept</code>。</li>
<li><strong>在 <code>execute</code> 中通过 Future 传递错误</strong>：如果在 Callable 的异步执行过程中发生错误，该错误将保存在由 <code>execute</code> 返回的 <code>ara::core::Future</code> 中（<a class="spec-record-ref" data-req="SWS_CORE_00024" href="../spec/record.html?id=SWS_CORE_00024">[SWS_CORE_00024]</a>）。在执行成功时，Future 包含计算得到的值；在发生错误时，则包含错误代码（<code>ErrorCode</code>）。</li>
<li><strong><code>oneway_execute</code> 的错误处理</strong>：由于不存在返回通道，因此在通过 <code>oneway_execute</code>（<a class="spec-record-ref" data-req="SWS_CORE_00025" href="../spec/record.html?id=SWS_CORE_00025">[SWS_CORE_00025]</a>）传递的 Callable 异步执行期间发生的错误无法传播给调用方。这些错误必须在函数对象内部自行捕获。</li>
<li><strong>复制操作失败</strong>：由于复制构造函数（<a class="spec-record-ref" data-req="SWS_CORE_00009" href="../spec/record.html?id=SWS_CORE_00009">[SWS_CORE_00009]</a>）和复制赋值操作（<a class="spec-record-ref" data-req="SWS_CORE_00017" href="../spec/record.html?id=SWS_CORE_00017">[SWS_CORE_00017]</a>）被标明为非异常安全，复制操作可能会失败，而移动操作（<a class="spec-record-ref" data-req="SWS_CORE_00015" href="../spec/record.html?id=SWS_CORE_00015">[SWS_CORE_00015]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00018" href="../spec/record.html?id=SWS_CORE_00018">[SWS_CORE_00018]</a>）通过 <code>noexcept</code> 保证异常安全。</li>
</ul>
