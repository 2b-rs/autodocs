上下文

数据结构apext::com::secoc::FVContainer是 AUTOSAR Adaptive Platform 在 Communication Management 模块中规范性 Platform Extension Interfaces 的组成部分（[SWS_CM_11286]、AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 “Struct: FVContainer”）。Platform Extension Interfaces 是由车辆制造商（OEM）或系统集成商提供或使用的功能接口，用于针对性地扩展 Adaptive 系统项的基础功能（AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 “Struct: FVContainer”）。在该扩展概念内，FVContainer通过头文件apext/com/secoc/fvm.h定义，并充当新鲜度值（Freshness Values）的标准化传输容器角色。

在安全车载通信（Secure Onboard Communication，SecOC）领域中，新鲜度值的验证与生成对于有效防止对传输消息的重放攻击至关重要。结构FVContainer在此充当平台通信服务与制造商特定 Freshness Value Manager（FVM）之间的专用纽带。该 struct 没有采用复杂的接口参数，而是将新鲜度值信息封装在两个基本组件中：值的精确位长度以及字节形式的实际有效负载数据（[SWS_CM_11344]、[SWS_CM_11345]）。无论交换的是完整值还是截断值，这都实现了灵活的传递。

上下文图：FVContainer 在 Communication Management 与 FVM 平台扩展之间接口处的集成。来源：[SWS_CM_11286]、AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 “Struct: FVContainer”。

生命周期

结构FVContainer被设计为纯被动数据传输对象（Value Object）（[SWS_CM_11286]）。它不拥有自己的状态机，也不管理活动后台资源或线程。其实例化通常直接在即将进行的消息发送或消息接收操作的上下文中进行，要么位于调用线程的栈上，要么作为处理流水线内的临时对象。

在所有权方面，FVContainer遵循标准 C++ 值语义。该实例独占拥有其成员变量。在赋值或传递给接口方法时，这些值会被复制或通过移动语义进行传输。元素value封装了一个类型为ara::core::Vector<std::uint8_t>的 vector（[SWS_CM_11345]），该 vector 动态管理其内存区域。FVContainer的销毁遵循 RAII 原则，在离开外围作用域时确定性地发生，此时 vector 动态分配的缓冲区会自动释放。

在并发性方面，FVContainer不提供固有的线程安全性。解释：由于该 struct 不提供内部同步机制或互斥锁，因此多个线程对同一实例的并发访问必须完全由调用组件进行串行化。

使用路径

FVContainer的主要使用流程包括在对消息进行身份验证或验证时，SecOC 子系统与 FVM 功能之间的数据交换。取决于该容器是充当输入值还是返回值，它传输完整或截断的新鲜度值（[SWS_CM_11345]、AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 “value”）。

  1. 实例化与准备：Communication Management 创建FVContainer的局部实例（[SWS_CM_11286]）。在消息验证的情况下，子系统从接收到的报文中提取截断的新鲜度值（Truncated Freshness Value），并填充 vector value以及length中的位长度（[SWS_CM_11344]、[SWS_CM_11345]）。
  2. 接口调用：该实例被传递给相应的 FVM 接口函数（AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 “Struct: FVContainer”）。解释：FVM 根据传入的截断值和内部计数器重构出完整的新鲜度值。
  3. 返回与后续处理：FVM 以新创建或修改后的FVContainer实例的形式返回结果（[SWS_CM_11345]）。调用系统从length读取实际位长度（[SWS_CM_11344]），并从value读取字节序列（[SWS_CM_11345]），以最终执行加密身份验证（例如 MAC 计算）。

时序图：以 FVContainer 作为输入和输出参数的新鲜度值处理典型调用流程。来源：[SWS_CM_11344]、[SWS_CM_11345]、AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 “value”。

错误场景

作为纯数据结构，FVContainer未声明任何自身的成员函数，因此既不定义特定错误码，也不抛出平台特定的异常（[SWS_CM_11286]）。尽管如此，对于所包含属性的使用仍存在严格的功能前置条件：

  • 长度规格不一致：变量length以位为单位精确定义新鲜度值的长度（[SWS_CM_11344]），而value则在字节 vector 中保存数据（[SWS_CM_11345]）。存在的前置条件是：以字节为单位的 vector 大小必须至少等于向上取整后的位数。解释：若length的值为 0，或者 vector 容量低于指定的位长度，被调用的 FVM 函数必须将该输入作为无效输入予以拒绝。
  • 内存分配错误：在对 vector value（[SWS_CM_11345]）进行赋值或扩容时，若系统内存资源耗尽，可能会发生类型为std::bad_alloc的异常。调用层必须在平台级别确保对此类分配错误进行受控捕获。
  • 无效的新鲜度值：若 FVM 无法成功确定或验证新鲜度值，调用系统则不得继续使用FVContainer中保留的原始数据，以免危及安全架构的完整性。

<h4>生命周期</h4>
<p>结构<code>FVContainer</code>被设计为纯被动数据传输对象（Value Object）（<a class="spec-record-ref" data-req="SWS_CM_11286" href="../spec/record.html?id=SWS_CM_11286">[SWS_CM_11286]</a>）。它不拥有自己的状态机，也不管理活动后台资源或线程。其实例化通常直接在即将进行的消息发送或消息接收操作的上下文中进行，要么位于调用线程的栈上，要么作为处理流水线内的临时对象。</p>

<p>在所有权方面，<code>FVContainer</code>遵循标准 C++ 值语义。该实例独占拥有其成员变量。在赋值或传递给接口方法时，这些值会被复制或通过移动语义进行传输。元素<code>value</code>封装了一个类型为<code>ara::core::Vector&lt;std::uint8_t&gt;</code>的 vector（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>），该 vector 动态管理其内存区域。<code>FVContainer</code>的销毁遵循 RAII 原则，在离开外围作用域时确定性地发生，此时 vector 动态分配的缓冲区会自动释放。</p>

<p>在并发性方面，<code>FVContainer</code>不提供固有的线程安全性。解释：由于该 struct 不提供内部同步机制或互斥锁，因此多个线程对同一实例的并发访问必须完全由调用组件进行串行化。</p>

<h4>使用路径</h4>
<p><code>FVContainer</code>的主要使用流程包括在对消息进行身份验证或验证时，SecOC 子系统与 FVM 功能之间的数据交换。取决于该容器是充当输入值还是返回值，它传输完整或截断的新鲜度值（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=537">AUTOSAR_AP_SWS_CommunicationManagement §C.1.1.1.2 “value”</a>）。</p>

<ol>
<li><strong>实例化与准备：</strong>Communication Management 创建<code>FVContainer</code>的局部实例（<a class="spec-record-ref" data-req="SWS_CM_11286" href="../spec/record.html?id=SWS_CM_11286">[SWS_CM_11286]</a>）。在消息验证的情况下，子系统从接收到的报文中提取截断的新鲜度值（Truncated Freshness Value），并填充 vector <code>value</code>以及<code>length</code>中的位长度（<a class="spec-record-ref" data-req="SWS_CM_11344" href="../spec/record.html?id=SWS_CM_11344">[SWS_CM_11344]</a>、<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>）。</li>
<li><strong>接口调用：</strong>该实例被传递给相应的 FVM 接口函数（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=536">AUTOSAR_AP_SWS_CommunicationManagement §C.1.1 “Struct: FVContainer”</a>）。解释：FVM 根据传入的截断值和内部计数器重构出完整的新鲜度值。</li>
<li><strong>返回与后续处理：</strong>FVM 以新创建或修改后的<code>FVContainer</code>实例的形式返回结果（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>）。调用系统从<code>length</code>读取实际位长度（<a class="spec-record-ref" data-req="SWS_CM_11344" href="../spec/record.html?id=SWS_CM_11344">[SWS_CM_11344]</a>），并从<code>value</code>读取字节序列（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>），以最终执行加密身份验证（例如 MAC 计算）。</li>
</ol>

<h4>错误场景</h4>
<p>作为纯数据结构，<code>FVContainer</code>未声明任何自身的成员函数，因此既不定义特定错误码，也不抛出平台特定的异常（<a class="spec-record-ref" data-req="SWS_CM_11286" href="../spec/record.html?id=SWS_CM_11286">[SWS_CM_11286]</a>）。尽管如此，对于所包含属性的使用仍存在严格的功能前置条件：</p>

<ul>
<li><strong>长度规格不一致：</strong>变量<code>length</code>以位为单位精确定义新鲜度值的长度（<a class="spec-record-ref" data-req="SWS_CM_11344" href="../spec/record.html?id=SWS_CM_11344">[SWS_CM_11344]</a>），而<code>value</code>则在字节 vector 中保存数据（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>）。存在的前置条件是：以字节为单位的 vector 大小必须至少等于向上取整后的位数。解释：若<code>length</code>的值为 0，或者 vector 容量低于指定的位长度，被调用的 FVM 函数必须将该输入作为无效输入予以拒绝。</li>
<li><strong>内存分配错误：</strong>在对 vector <code>value</code>（<a class="spec-record-ref" data-req="SWS_CM_11345" href="../spec/record.html?id=SWS_CM_11345">[SWS_CM_11345]</a>）进行赋值或扩容时，若系统内存资源耗尽，可能会发生类型为<code>std::bad_alloc</code>的异常。调用层必须在平台级别确保对此类分配错误进行受控捕获。</li>
<li><strong>无效的新鲜度值：</strong>若 FVM 无法成功确定或验证新鲜度值，调用系统则不得继续使用<code>FVContainer</code>中保留的原始数据，以免危及安全架构的完整性。</li>
</ul>
