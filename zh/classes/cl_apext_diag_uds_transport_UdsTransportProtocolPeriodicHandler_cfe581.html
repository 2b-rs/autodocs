上下文

apext::diag::uds_transport::UdsTransportProtocolPeriodicHandler 类是 AUTOSAR Adaptive Platform 在模块 diag AUTOSAR_AP_SWS_Diagnostics §C.3 “Header: apext/diag/uds_transport/protocol_periodic_handler.h” 中的专用接口。它用于在传输协议 [SWS_DM_01064] 层面上对 UDS 服务 0x2A（“ReadDataByPeriodicIdentifier”）提供标准化支持。

在诊断架构内部，该类在上一级诊断管理与具体传输连接之间起到协调中介作用。其主要职责是提供周期性传输的通道特定容量限制，并将周期性诊断消息的有序序列集中传递给下层网络。参与的交互伙伴包括：

  • UDS 服务处理程序（0x2A）：控制测量值的周期性读取，并触发周期性发送过程。
  • 传输协议处理程序：作为接口的具体派生类实现协议特定的传输（例如通过 DoIP）。
  • 传输通道（ChannelID）：表示用于发送周期性消息的具体逻辑或物理连接 [SWS_DM_01066]。

生命周期

该类被设计为带有纯虚方法的抽象基接口，不会被直接实例化。对象创建通过相应传输协议的具体实现来进行。

  • 创建与所有权：具体实例通常可能与上一级传输协议服务一同创建，并由诊断基础设施持有（解释：生命周期与通信通道的运行时间绑定）。
  • 析构：虚析构函数 ~UdsTransportProtocolPeriodicHandler() 确保派生类可以通过指向接口的指针进行类型安全且节省资源的释放 [SWS_DM_02089]。它被定义为 noexcept AUTOSAR_AP_SWS_Diagnostics §C.3.1.1.1.1 “Destructor”。
  • 并发性：接口的所有操作均被明确归类为非线程安全（“not thread-safe”）[SWS_DM_01065]、[SWS_DM_01066]、[SWS_DM_01067]、[SWS_DM_02089]。调用方必须确保对同一实例的调用进行串行化或进行外部同步。
  • 异常安全性：所有方法均使用 noexcept 声明，并被指定为异常安全（“exception safe”）。

使用路径

周期性诊断消息的典型发送周期包括确定连接参数、准备消息列表以及进行传输调用：

  1. 确定通道限制：在首次传输之前，调用方通过 GetMaxPayloadLength(channelId) 确定该通道每条周期性消息所允许的最大有效负载长度 [SWS_DM_01066]。此外，GetNumberOfPeriodicMessages(channelId) 提供实现与连接特定的可能周期性消息数量 [SWS_DM_01065]。
  2. 组合消息列表：要发送的消息在 ara::core::Vector<UdsMessageConstPtr> 中按期望的发送顺序进行聚合。
  3. 发起周期性发送：通过 PeriodicTransmit(channelId, messages) 将该列表传递给处理程序 [SWS_DM_01067]。消息将按指定顺序依次进行传输 AUTOSAR_AP_SWS_Diagnostics §C.3.1.1.2.3 “PeriodicTransmit”。
  4. 处理确认：发送过程结束后，会调用确认（“PeriodicTransmit Confirmation”）以通知结果 [SWS_DM_01067]。

顺序图：用于周期性消息传输和确认的典型调用序列。来源：[SWS_DM_01065]、[SWS_DM_01066]、[SWS_DM_01067]

错误场景

由于该接口的所有方法均为 noexcept，因此不会通过 C++ 异常来报告错误。错误处理直接集成在传输协议中：

  • 单个错误时中止传输：如果传递的列表中单条消息的传输失败，则整个后续发送过程会立即中止 [SWS_DM_01067]。列表中后续的消息将不再发送。
  • 通过确认进行错误反馈：即使在出错的情况下，也会调用 PeriodicTransmit Confirmation [SWS_DM_01067]。它接收直到中止前成功发送的消息的确切数量以及原始消息列表作为参数。根据所传递的数量，调用方可以精确识别错误发生的索引，并在必要时采取应对措施。
  • 前置条件违反：由于 PeriodicTransmit 没有返回值（void），调用方必须预先确保 channelId 有效，且消息大小符合通过 GetMaxPayloadLength 报告的限值 [SWS_DM_01066]、[SWS_DM_01067]。

<li><strong>发起周期性发送：</strong>通过 <code>PeriodicTransmit(channelId, messages)</code> 将该列表传递给处理程序 <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>。消息将按指定顺序依次进行传输 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=968">AUTOSAR_AP_SWS_Diagnostics §C.3.1.1.2.3 “PeriodicTransmit”</a>。</li>
<li><strong>处理确认：</strong>发送过程结束后，会调用确认（“PeriodicTransmit Confirmation”）以通知结果 <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>由于该接口的所有方法均为 <code>noexcept</code>，因此不会通过 C++ 异常来报告错误。错误处理直接集成在传输协议中：</p>
<ul>
<li><strong>单个错误时中止传输：</strong>如果传递的列表中单条消息的传输失败，则整个后续发送过程会立即中止 <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>。列表中后续的消息将不再发送。</li>
<li><strong>通过确认进行错误反馈：</strong>即使在出错的情况下，也会调用 PeriodicTransmit Confirmation <a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>。它接收直到中止前成功发送的消息的确切数量以及原始消息列表作为参数。根据所传递的数量，调用方可以精确识别错误发生的索引，并在必要时采取应对措施。</li>
<li><strong>前置条件违反：</strong>由于 <code>PeriodicTransmit</code> 没有返回值（<code>void</code>），调用方必须预先确保 <code>channelId</code> 有效，且消息大小符合通过 <code>GetMaxPayloadLength</code> 报告的限值 <a class="spec-record-ref" data-req="SWS_DM_01066" href="../spec/record.html?id=SWS_DM_01066">[SWS_DM_01066]</a>、<a class="spec-record-ref" data-req="SWS_DM_01067" href="../spec/record.html?id=SWS_DM_01067">[SWS_DM_01067]</a>。</li>
</ul>
