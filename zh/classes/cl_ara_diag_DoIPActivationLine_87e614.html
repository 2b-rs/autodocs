用于向 Diagnostic Manager 传输和管理 DoIP 激活线的状态。

类 ara::diag::DoIPActivationLine 允许应用程序提供 DoIP 激活线的状态并将变更传输给 Diagnostic Manager [SWS_DM_00830]。基于端口实例化后，通过 Offer() 激活服务，随后 DM 查询线路状态和网络 ID，并通过 UpdateActivationLineState() 接收状态变更 [SWS_DM_00834]。作为核心边界条件，模型中关联的网络接口必须配置为依赖激活线 [SWS_DM_00833]。

上下文

类 ara::diag::DoIPActivationLine 表示符合 [SWS_DM_00830] 的接口 DiagnosticDoIPActivationLineInterface。它允许 Adaptive Application（AA）向 Diagnostic Manager（DM）报告并提供 DoIP 激活线的物理或逻辑状态。通过此激活线，应用程序可间接控制 DoIP 车辆通告消息（Vehicle Announcement Messages）的发送（如 AUTOSAR_AP_SWS_Diagnostics, 第107页 中所规定），而无需自行显式触发发送。

交互主要涉及三个组件：实现该接口的 Adaptive Application、作为服务接口的 ara::diag::DoIPActivationLine 实例以及基础系统的 Diagnostic Manager。如果 DM 通过此接口检测到激活线的状态变更，它将通知相关网络接口并启动标准化 DoIP 流程 [SWS_DM_00816]。

上下文图：应用程序与 Diagnostic Management 之间 DoIP 激活线的交互伙伴。来源：[SWS_DM_00830]、[SWS_DM_00816]、AUTOSAR_AP_SWS_Diagnostics, 第107页。

生命周期

ara::diag::DoIPActivationLine 的实例通过引用 PortPrototype 的 ara::core::InstanceSpecifier 来创建 [SWS_DM_00831]。该类建模了一个唯一实例：复制和移动构造函数以及复制和移动赋值运算符均被删除（=delete），从而排除了移动或复制（[SWS_DM_01631]、[SWS_DM_01632]、[SWS_DM_01633]、[SWS_DM_01634]）。

实例化后，对象处于“未提供”状态。通过调用 Offer() 激活提供，使 DM 能够侦听激活线的状态变更 [SWS_DM_00836]。通过 StopOffer() 再次停用此提供 [SWS_DM_00837]。虚析构函数声明为默认析构函数并释放资源 [SWS_DM_00832]。关于并发性，构造函数 [SWS_DM_00831] 以及纯读取查询 GetActivationLineState() [SWS_DM_00835] 和 GetNetworkInterfaceId() [SWS_DM_00833] 为线程安全执行，而 Offer() [SWS_DM_00836]、StopOffer() [SWS_DM_00837] 和 UpdateActivationLineState() [SWS_DM_00834] 不是线程安全的。

使用路径

常规流程包括派生和注册应用程序特定类以及持续的状态传输：

  1. 实例化：Adaptive Application 在指定适当的 InstanceSpecifier [SWS_DM_00831] 的情况下实例化派生类。
  2. 提供服务：应用程序调用 Offer() 以向 DM 发布接口 [SWS_DM_00836]。
  3. 网络与初始查询：DM 通过纯虚方法 GetNetworkInterfaceId() 确定关联的接口 ID [SWS_DM_00833]，并使用 GetActivationLineState() 查询当前线路状态 [SWS_DM_00835]。这两个方法均返回一个 ara::core::Future。
  4. 状态更新：如果线路的物理状态发生变化（例如硬件线路上的电平变化），应用程序通过 UpdateActivationLineState() [SWS_DM_00834] 同步通知 DM。这将促使 DM 采取后续操作，例如向网络接口发送状态通知 [SWS_DM_00816]。
  5. 终止：在关闭之前或停用时，应用程序调用 StopOffer() [SWS_DM_00837]。

时序图：激活线注册、查询和更新的典型流程。来源：[SWS_DM_00831]、[SWS_DM_00833]、[SWS_DM_00834]、[SWS_DM_00835]、[SWS_DM_00836]、[SWS_DM_00837]。

错误场景

使用 ara::diag::DoIPActivationLine 时可能会出现功能和配置方面的错误：

  • 创建时的模型与端口违规：构造函数检查 InstanceSpecifier [SWS_DM_00831] 的有效性。如果解析失败，将触发标准化的违规通知：InstanceSpecifierMappingIntegrityViolation（无效的模型元素）、PortInterfaceMappingViolation（端口未按 DiagnosticDoIPActivationLineInterface 定型）、ProcessMappingViolation（缺少进程引用）或 InstanceSpecifierAlreadyInUseViolation（Specifier 在进程内已被分配）。
  • 重复提供：如果在已提供服务的情况下调用 Offer()，则操作失败并返回错误码 DiagOfferErrc::kAlreadyOffered [SWS_DM_00836]。
  • 网络接口配置不一致：如果应用程序通过 GetNetworkInterfaceId() 报告了一个其关联的 DoIpNetworkConfiguration 具有属性 isActivationLineDependent = 'FALSE' 的接口 ID，根据规范这明确属于严重配置错误 [SWS_DM_00833]。
  • 异常安全性：虽然构造函数、Getter、Offer()、StopOffer() 和析构函数均指定为异常安全（exception safe），但 UpdateActivationLineState() 被明确指出为非异常安全（not exception safe）[SWS_DM_00834]。因此，调用该接口的应用程序必须仔细处理此调用内的错误。

本指南仅基于 AUTOSAR AP Release R25-11 的规范要求。

                      类 ara::diag::DoIPActivationLine（[SWS_DM_00836]，头文件 #include "ara/diag/doip_activationline.h"）的同步方法 Offer 使 Diagnostic Management（DM）能够检测激活线的状态变化。该操作不包含输入参数，并通过返回类型 ara::core::Result<void> 返回结果。
                      

                      一旦通过 Offer 提供了该接口，DM 就会监视激活线。如果 DM 检测到向“active”状态的转换，它会触发在相关网络接口上根据 ISO 13400-2 发送车辆通告报文（Vehicle Announcement Messages）（[SWS_DM_00816]，AUTOSAR_AP_SWS_Diagnostics §[SWS_DM_00816] 第106页）。Interpretation：Offer 的调用通常可能在应用程序的初始化阶段进行，以便及早检测到状态变化。 问题 Q-254ced2fd3a1e3d2 (未决)
                      

                      发生错误时，将在 Result 中返回相应的错误码。如果在服务已提供期间针对同一实例重复调用该方法，它将返回具有回滚语义的错误码 DiagOfferErrc::kAlreadyOffered（[SWS_DM_00836]）。
                      

                      关于并发性，该方法被指定为非线程安全（not thread-safe）（[SWS_DM_00836]）。因此，针对同一实例的并发调用必须在应用端进行同步。通过声明为 noexcept，该函数是完全异常安全的（[SWS_DM_00836]）。

                          方法 ara::diag::DoIPActivationLine::StopOffer 根据 [SWS_DM_00837] 终止向 Diagnostic Management (DM) 提供 DoIP 激活线（Activation Line）的状态。
                          

                          该函数具有签名 void StopOffer() noexcept，并在 ara::diag::DoIPActivationLine 的实例上同步执行（AUTOSAR_AP_SWS_Diagnostics §5 “Overview”）。它不接受任何参数，也不提供返回值。通过该调用，将停用向 Diagnostic Manager 主动传输激活线状态变更的功能。
                          

                          在错误处理方面，该方法被指定为 exception safe，并通过 noexcept 保证不抛出任何异常（[SWS_DM_00837]）。根据规范，由于该操作为 not thread-safe，因此不允许在同一实例上不受保护地跨多个线程并发调用；并行访问必须在应用程序端进行同步。
                          

                          该设计模式遵循 Adaptive 平台中已确立的服务提供命名规则（AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 “Monitors”）。在相关的 DoIP 类（如 ara::diag::DoIPGroupIdentification ([SWS_DM_00726]) 或 ara::diag::DoIPPowerMode ([SWS_DM_00736])）中，StopOffer 用于停用传入 DM 请求的转发，而在此处，它专门停止向 DM 报告激活线状态。Interpretation：为了确保一致的操作流程，通常假定在调用 StopOffer 之前，已通过同一实例主动启动了提供。 问题 Q-c5d38151ef8198e7 (未决)
