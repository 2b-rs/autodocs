定义用于识别、文本翻译和异常处理来自 SOVD 的错误的错误域。

类 ara::diag::DiagSovdErrorDomain 封装了 AUTOSAR Adaptive Platform（[SWS_DM_01809]）内针对 SOVD 特定诊断错误的标准化错误域。通过其线程安全的成员函数，它能够可靠地将数字错误码转换为文本消息，并受控地触发适当的 C++ 异常类型（[SWS_DM_01814]）。如果编译器工具链中禁用了 C++ 异常，则用于触发异常的方法按规则不参与重载解析。

上下文

类 ara::diag::DiagSovdErrorDomain 表示源自 SOVD 子系统（Service-Oriented Vehicle Diagnostics）的错误状态的特定错误域（[SWS_DM_01809]、AUTOSAR_AP_SWS_Diagnostics §8.51.3 “Class: DiagSovdErrorDomain”）。作为基础架构基类 ara::core::ErrorDomain 的 final 特化，它将 SOVD 上下文的错误码及相关异常处理无缝集成到 AUTOSAR Adaptive Platform 的统一错误模型中（[SWS_DM_01809]）。

为了进行标准化识别，成员函数 Name() 提供了根据 [SWS_CORE_90023] 的错误域短名称（ApApplicationErrorDomain.SN）（[SWS_DM_01813]、AUTOSAR_AP_SWS_Diagnostics §8.51.3 “Class: DiagSovdErrorDomain”）。此外，该类为其命名空间定义了两个核心类型别名：Errc 充当底层枚举 DiagSovdErrc 的别名（[SWS_DM_01810]、AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.1 “Type Alias: Errc”），而 Exception 代表相关的基异常类 DiagSovdException（[SWS_DM_01811]、AUTOSAR_AP_SWS_Diagnostics §8.51.3.1.2 “Type Alias: Exception”）。在实践中，通常通过自由函数 ara::diag::GetDiagSovdErrorDomain 访问该域（[SWS_DM_01816]、AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 “GetDiagSovdErrorDomain”）。

生命周期

ara::diag::DiagSovdErrorDomain 的实例化通过无参默认构造函数 constexpr DiagSovdErrorDomain() noexcept 进行（[SWS_DM_01812]、AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.1.1 “Default Constructor”）。得益于被指定为 constexpr 和 noexcept，对象的创建保证是异常安全的，并且可以在编译期或静态初始化期间进行。解释：提供 constexpr 构造函数推测使平台能够维护一个通过 GetDiagSovdErrorDomain 引用的长生命周期单例实例（[SWS_DM_01816]）。

在并发方面，该类的所有成员函数均被显式声明为线程安全（“thread-safe”）。这既适用于构造函数（[SWS_DM_01812]），也适用于读取操作 Name()（[SWS_DM_01813]）和 Message()（[SWS_DM_01814]），以及通过 ThrowAsException() 触发异常（[SWS_DM_01815]）。因此，多个线程可以并行操作同一域实例，而无需外部同步机制。

使用路径

使用 ara::diag::DiagSovdErrorDomain 的常规流程分为以下步骤：

  • 获取域：调用者通常通过全局函数 ara::diag::GetDiagSovdErrorDomain（[SWS_DM_01816]、AUTOSAR_AP_SWS_Diagnostics §8.51.2.1.1 “GetDiagSovdErrorDomain”）获取对错误域的引用，或者在需要时通过默认构造函数创建自己的实例（[SWS_DM_01812]）。
  • 查询错误消息：为了将 ara::core::ErrorDomain::CodeType 类型的数字错误码（对应于根据 [SWS_DM_01810] 的 Errc）转换为可读文本，将调用 Message(errorCode)（[SWS_DM_01814]、AUTOSAR_AP_SWS_Diagnostics §8.51.3.2.2.1 “Message”）。该函数返回一个指向字符串的常量指针（const char*），该指针保证绝不会是 nullptr（[SWS_DM_01814]）。解释：生成的字符串推测是静态字面量，因为该函数被分类为 noexcept。
  • 异常处理：若要改为通过 C++ 异常传播错误状态，应用程序会将 ara::core::ErrorCode 的实例传递给 ThrowAsException(errorCode)（[SWS_DM_01815]），从而触发类型相符的 Exception 类型异常（DiagSovdException）（[SWS_DM_01811]）。

错误场景

在错误处理框架内，ara::diag::DiagSovdErrorDomain 的接口表现出特定的行为特征：

  • 保证文本返回：方法 Message 被声明为 noexcept 并且完全异常安全（“exception safe”）（[SWS_DM_01814]）。它绝不会失败，并且始终返回一个有效的、非空的字符串（[SWS_DM_01814]）。
  • 定向触发异常：方法 ThrowAsException 专门用于抛出异常，因此带有 noexcept(false) 以及“not exception safe”评级（[SWS_DM_01815]）。它根据传入的 ara::core::ErrorCode 触发相应的 Exception 类型异常（DiagSovdException）（[SWS_DM_01811]、[SWS_DM_01815]）。
  • 禁用 C++ 异常：根据 [SWS_CORE_10304]，若在编译器工具链中禁用了 C++ 异常，则 ThrowAsException 不参与重载解析（[SWS_DM_01815]）。在此类环境中，该函数不可用，必须强制通过错误码来评估错误。
