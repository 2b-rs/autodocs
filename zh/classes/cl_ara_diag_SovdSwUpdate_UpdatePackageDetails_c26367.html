上下文

数据结构 ara::diag::SovdSwUpdate::UpdatePackageDetails（[SWS_DM_01877]、AUTOSAR_AP_SWS_Diagnostics §8.58.4 “Struct: UpdatePackageDetails”）在 AUTOSAR Adaptive Platform 的 diag 模块中用作软件包元数据和执行参数的结构化信息载体。它在头文件 #include "ara/diag/sovd_sw_update.h" 中声明，并构成了通过 ASAM SOVD（Service-Oriented Vehicle Diagnostics）标准提供的、与软件相关的诊断和更新流程的重要接口参数（[SWS_DM_01796]）。

架构嵌入遵循 SOVD 软件更新的功能分工（AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API”）：由于软件更新的实际业务逻辑不在 Functional Cluster Diagnostics 内部执行，因此业务实现主要由相应的应用程序负责。Diagnostic Server 的实例 ara::diag::SovdSwUpdate::SovdSwUpdate 专注于根据 ASAM SOVD（[SWS_DM_01796]）处理底层 SOVD 协议。在此上下文中，UpdatePackageDetails 充当标准化传输对象，应用程序通过 API 函数 ara::diag::SovdSwUpdate::GetUpdatePackageDetails（[SWS_DM_01917]、AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”）向 Diagnostic Server 提供详细的软件包数据，以便其为外部 SOVD 客户端提供服务。

上下文图：UpdatePackageDetails 在 SOVD 客户端、Diagnostic Server 与应用程序协作中的定位。来源：[SWS_DM_01796]、[SWS_DM_01877]、[SWS_DM_01917]、AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API”。

生命周期

作为被动数据结构（struct）[SWS_DM_01877]，UpdatePackageDetails 没有自己的状态机，也不控制自主生命周期阶段。其创建由应用程序在具体查询时实例化完成，随后公共成员变量被填入静态和动态软件包属性：

  • 标识与命名：字段 id（[SWS_DM_01878]）存储软件包的唯一 ID。名称 name（[SWS_DM_01879]）指定软件包名称，而 translation_id（[SWS_DM_01881]）提供用于本地化表示的键。
  • 大小与执行信息：软件包的大小（以字节为单位）通过 size（[SWS_DM_01893]）定义为 std::uint64_t。其他控制参数包括以秒为单位的估计执行时间 duration（[SWS_DM_01891]、AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.3 “duration”）（类型为 ara::core::Optional<std::uint64_t>）以及标识 automated（[SWS_DM_01882]、AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.2 “automated”）（类型为 ara::core::Optional<bool>）。
  • 前置条件与用户活动：执行条件在 preconditions（[SWS_DM_01888]）以及 preconditions_translation_id（[SWS_DM_01889]）和 execution_conditions（[SWS_DM_01890]）中传递。应用程序在 user_activity（[SWS_DM_01886]）和 user_activity_translation_id（[SWS_DM_01887]）中存放所需的操作员操作。附加提示可以通过 notes（[SWS_DM_01884]）和 notes_translation_id（[SWS_DM_01885]）传递。
  • 组件关系与来源：受软件包影响的组件由 Vector affected_components（[SWS_DM_01895]、AUTOSAR_AP_SWS_Diagnostics §8.58.4.1.1 “affected_components”）列出，而 updated_components（[SWS_DM_01894]）指定明确更新的组件。更新软件包的来源通过 origin（[SWS_DM_01883]）传达。

关于所有权关系，该实例由应用程序创建并通过返回值传递给调用方。根据标准 C++ 语义（RAII），该实例在离开作用域后会自动销毁。该结构不提供内部线程同步；在跨线程边界进行并发读或写访问时，保护该实例的职责由调用方软件组件承担。

使用路径

UpdatePackageDetails 的常规使用是在用于查询软件更新详情的标准化 SOVD 方法（[SWS_DM_01796]）过程中进行的。客户端通常会预先检索所有可用更新的列表（[SWS_DM_01797]），然后再有针对性地请求软件包详情。

调用流程如下：

  1. SOVD 客户端请求：外部诊断客户端向 Diagnostic Server Instance（[SWS_DM_01796]）发送对特定软件包详情的请求。
  2. 转发至应用程序：Diagnostic Server 通过 ara::diag::SovdSwUpdate::GetUpdatePackageDetails 将详情获取委托给已注册的应用程序（[SWS_DM_01917]、AUTOSAR_AP_SWS_Diagnostics §8.58.2.1.3.4 “GetUpdatePackageDetails”）。
  3. 整理数据：应用程序确定软件包的元数据，实例化 UpdatePackageDetails（[SWS_DM_01877]）并填充诸如 id（[SWS_DM_01878]）和 size（[SWS_DM_01893]）等标识数据以及诸如 affected_components（[SWS_DM_01895]）等依赖项。
  4. 返回：解释：应用程序推测会直接将填充完毕的 UpdatePackageDetails 对象作为 GetUpdatePackageDetails 的函数结果返回给 Diagnostic Server。
  5. 协议响应：解释：Diagnostic Server 推测会负责将 C++ 属性序列化为标准化的 SOVD 响应格式，并将其分发给发起请求的客户端（[SWS_DM_01796]）。
