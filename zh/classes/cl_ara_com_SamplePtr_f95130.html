类 ara::com::SamplePtr

[SWS_CM_00306] Upstream: RS_CM_00202, RS_CM_00203, RS_AP_00114, RS_AP_00122, RS_AP_00135, RS_AP_00145

template <typename T> class SamplePtr {...};

Emulates a std::unique_ptr to an event sample.

The ara::com::SamplePtr behaves as a std::unique_ptr as long as the event/ field is subscribed to, or the Proxy it belongs to is not destroyed. The precondition defined in [SWS_CM_00085] and [SWS_CM_00087] must be fulfilled. Otherwise it is considered a violation.

Note: The SamplePtr is always passed with a const SampleType to the callable in GetNewSamples() (see [SWS_CM_00701]). Therefore the sample datatype (typename T) and the SamplePtr operators using the sample datatype (typename T) are implicitly declared as const. This means that the sample data will always be read-only.

上下文

类模板 ara::com::SamplePtr 是 Adaptive Platform 通信管理中对接收到的事件数据（Event Samples）进行读取访问的核心访问点和入口点 (EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。根据 [SWS_CM_00306]，该类在语义上模仿 std::unique_ptr 模拟了指向具体事件样本的独占指针。

在整个系统中，ara::com::SamplePtr 与三个主要伙伴进行交互：

  • 应用程序逻辑 (Callable)：应用程序提供具有签名 void(ara::com::SamplePtr<SampleType const>) 的可调用实体 (Callable) (EXP_ARAComAPI §5.3.5 “Event Reception”, EXP_ARAComAPI §5.3.5.3 “GetNewSamples”)。有效数据始终作为 const SampleType 传递给该 Callable，从而使数据类型及所有访问操作符隐式地处于只读（read-only）状态 ([SWS_CM_00701])。
  • 通信管理（Proxy 事件包装器）：在同步调用 GetNewSamples() 时，运行时环境将新数据反序列化到缓冲区槽中，并通过 SamplePtr 实例将每个槽的生命周期职责移交给应用程序 (EXP_ARAComAPI §5.3.5.3 “GetNewSamples”, EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。
  • 本地缓存与中间件缓冲区：该架构支持针对 1:N 事件通信的基于引用的方法。SamplePtr 直接指向中间件的受管缓冲区区域，而不是通过复制在本地内存中对事件数据进行备份，从而实现了高效的零拷贝处理 (EXP_ARAComAPI §5.3.5 “Buffer Management”)。

除数据封装外，SamplePtr 还通过 GetProfileCheckStatus() ([SWS_CM_90420]) 提供了用于查询所接收样本的端到端 (E2E) 保护状态的接口。

生命周期

ara::com::SamplePtr 的生命周期遵循严格的独占所有权规则（仅移动语义）：

  • 创建：空指针可以通过默认构造函数 ([SWS_CM_11534]) 或通过空指针构造函数 ([SWS_CM_11535]) 显式创建。这两个构造函数均被定义为 constexpr 和 noexcept。有效且包含数据的 SamplePtr 仅由 ara::com 实现创建，并在执行 GetNewSamples() 时通过所有权转移传递给应用程序自有的 Callable (EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。
  • 排除复制操作：为了保持缓冲区访问的唯一性，复制构造函数 ([SWS_CM_11536]) 以及复制赋值运算符 ([SWS_CM_11538]) 已被显式删除 (= delete)。
  • 所有权转移与交换：缓冲区槽的所有权可以通过移动构造 ([SWS_CM_11537]) 或移动赋值 ([SWS_CM_11540]) 转移至其他 SamplePtr 实例。方法 Swap() ([SWS_CM_11544]) 支持在两个实例的受管对象之间进行异常安全的交换。
  • 释放与销毁：只要应用程序持有一个 SamplePtr，中间件就无法收回被占用的内存槽 (EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。将该槽归还给中间件通过调用 Reset(nullptr) ([SWS_CM_11545])、赋值 nullptr ([SWS_CM_11539]) 或在离开作用域时通过析构函数 ~SamplePtr() ([SWS_CM_11547]) 进行。
  • 有效性边界：SamplePtr 仅在相关事件或字段处于活跃订阅状态且关联的 Proxy 存在期间，才表现为仿照 std::unique_ptr 的有效代理。若违反这些前提条件，根据 [SWS_CM_00085] 和 [SWS_CM_00087]，后续使用将被视为违反规范。

使用路径

接收和处理事件数据的典型调用顺序分为以下步骤：

  1. 提供回调：应用程序向 GetNewSamples() 传递一个具有签名 void(ara::com::SamplePtr<SampleType const>) 的可调用函数 f 以及可选参数 maxNumberOfSamples (EXP_ARAComAPI §5.3.5.3 “GetNewSamples”)。
  2. 接收与所有权接管：对于每个可用事件，中间件反序列化该数据并调用 f。随着传递的完成，独占所有权转移给用户 (EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。
  3. 有效性与保护检查：
    • 检查该实例的有效性。解读：尽管规范在 [SWS_CM_11543] 中将 operator bool() 的返回值描述为“TRUE if the stored pointer is null, FALSE otherwise”，但类比标准智能指针，该转换运算符推测用于查询受管对象是否存在。
    • 应用程序通过 GetProfileCheckStatus() ([SWS_CM_90420]) 查询 E2E 检查状态，以便在进一步处理之前识别损坏或不完整的样本。
  4. 数据读取访问：状态检查成功后，应用程序通过解引用运算符 operator*() ([SWS_CM_11541])、箭头运算符 operator->() ([SWS_CM_11542]) 或通过原生指针 Get() ([SWS_CM_11546]) 访问有效数据。由于常量类型化，修改性访问已被排除 ([SWS_CM_00701])。
  5. 释放或生命周期延长：
    • 若仅在回调内部需要该样本，则在离开作用域时通过调用析构函数 ([SWS_CM_11547]) 使其生命周期自动结束，从而立即释放中间件槽 (EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。通过 Reset(nullptr) ([SWS_CM_11545]) 可以进行提前手动释放。
    • 若需要在回调之外继续保留该样本，应用程序必须通过移动语义 ([SWS_CM_11537], [SWS_CM_11540]) 将 SamplePtr 转移到其自身的数据结构中。

时序图：调用 GetNewSamples() 时事件样本的处理顺序。来源：[SWS_CM_00701]、[SWS_CM_11541]、[SWS_CM_11545]、[SWS_CM_11547]、[SWS_CM_90420]、EXP_ARAComAPI §5.3.5.3 “GetNewSamples”、EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”。

错误场景

在使用 ara::com::SamplePtr 时，需注意以下错误情况和约束条件：

  • 超出缓冲区配额 (Quota Violation)：ara::com 实现会在反序列化之前检查当前由应用程序持有的 SamplePtr 实例数量是否超过先前在 Subscribe() 中约定的最大数量。若出现这种情况，GetNewSamples() 将中止并在 ara::core::Result 中返回错误代码 (EXP_ARAComAPI §5.3.5.3 “GetNewSamples”, EXP_ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”)。只有当应用程序通过析构或 Reset(nullptr) 释放持有的实例时，才会缓解此限制。
  • 违反 Proxy 和订阅绑定：如果在关联的 Proxy 对象被销毁后或取消订阅后继续使用 SamplePtr，则违反了 [SWS_CM_00085] 和 [SWS_CM_00087] 规定的前提条件，从而导致未定义的系统行为。
  • E2E 检查失败：如果 GetProfileCheckStatus() ([SWS_CM_90420]) 的结果偏离成功状态，则所引用的数据不得被解读为有效控制数据。在这种情况下，应用程序必须触发该指针的释放。
  • 异常安全性：类 ara::com::SamplePtr 的所有操作和构造函数均具有规范 noexcept ([SWS_CM_11534], [SWS_CM_11535], [SWS_CM_11537], [SWS_CM_11539] 至 [SWS_CM_11547], [SWS_CM_90420])。它们不引发异常，并提供完全的无抛出（No-Throw）保证。
