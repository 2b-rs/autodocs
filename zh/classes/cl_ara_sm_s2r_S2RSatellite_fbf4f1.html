为应用程序接收 Suspend-to-RAM 通知，以实现协调的准备和恢复。

接口 ara::sm::s2r::S2RSatellite 用作 Adaptive Applications 接收来自 State Management 的 Suspend-to-RAM 通知的接收器（[SWS_SM_81002]、AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。在初始化并经由 Offer() 激活后，已实现的回调函数 EnterSuspendMode() 和 LeaveSuspendMode() 将被调用，以异步控制特定于应用程序的准备工作，如数据备份或服务重启（[SWS_SM_00710]、[SWS_SM_81010]、[SWS_SM_81011]）。在中央 Hub 处的注册强制要求具有经过适度建模且经过 IAM 认证的进程上下文（[SWS_SM_00715]）。

上下文

抽象基类 ara::sm::s2r::S2RSatellite 为 Adaptive Applications 定义了接收进入和退出“prepared for Suspend-to-RAM”状态通知的接口（[SWS_SM_81002]、AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。虽然 State Management 内部的中央 S2RHub 负责协调挂起流程（AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”），但 S2RSatellite 的实例充当相应应用程序中的本地端点。Adaptive Application 实现抽象回调函数，以执行特定于应用程序的准备工作，例如保存持久性数据、停止提供的服务或停止安全关键活动（AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”）。

上下文图：Adaptive Application、S2RSatellite、S2RHub 和 Identity Access Management 之间的交互。来源：[SWS_SM_00710]、[SWS_SM_00715]、AUTOSAR_AP_EXP_SWArchitecture §9.2.2.1.4 “Interfaces for Suspend-to-Ram Notifications”、AUTOSAR_AP_SWS_StateManagement §7.5.1 “S2R Hub”。

注册和交互受 Identity and Access Management (IAM) 的安全检查约束：仅当卫星的进程上下文与配置的 SuspendToRamSatelliteMapping 一致时，S2RHub 才允许注册（[SWS_SM_00715]）。

生命周期

实例的创建通过显式构造函数 S2RSatellite(const ara::core::InstanceSpecifier&)（[SWS_SM_81003]）或静态工厂方法 Create()（[SWS_SM_81014]）进行。默认构造函数已被删除（[SWS_SM_81004]）。该类具有严格的所有权语义：拷贝构造函数和拷贝赋值运算符被显式删除（[SWS_SM_81007]、[SWS_SM_81009]），而移动构造函数和移动赋值是允许的、异常安全的且线程安全的（[SWS_SM_81006]、[SWS_SM_81008]）。

实例化后，对象处于非活动状态。只有通过调用 Offer()，卫星才会在 Hub 处主动注册并激活处理程序调用（[SWS_SM_00710]、[SWS_SM_81012]）。卫星保持活动注册状态，直到调用 StopOffer()（[SWS_SM_00710]、[SWS_SM_81013]）。通过虚析构函数 ~S2RSatellite()（[SWS_SM_81005]）销毁时，推测该实例必须事先已注销或会被隐式释放。虽然构造函数和赋值是线程安全的，但 Offer()、StopOffer()、析构函数以及处理程序都不是线程安全的（[SWS_SM_81003]、[SWS_SM_81005]、[SWS_SM_81010]、[SWS_SM_81011]、[SWS_SM_81012]、[SWS_SM_81013]）。

使用路径

常规流程包括提供、处理状态更改以及最终注销：

  1. 提供：应用程序实例化其派生的卫星类并调用 Offer()，以建立与 S2RHub 的通信就绪状态（[SWS_SM_00710]、[SWS_SM_81012]）。
  2. 挂起请求：当 State Management 触发挂起过程时（[SWS_SM_00701]），卫星调用纯虚方法 EnterSuspendMode()（[SWS_SM_00711]、[SWS_SM_81010]）。应用程序执行其保存例程，并通过返回的 ara::core::Future<void> 异步指示就绪状态（[SWS_SM_81010]）。
  3. 恢复请求：唤醒后，Hub 请求退出挂起模式（[SWS_SM_00703]）。卫星执行方法 LeaveSuspendMode()（[SWS_SM_00711]、[SWS_SM_81011]），随后应用程序重新激活服务。
  4. 终止：在关闭之前，应用程序调用 StopOffer()，从而在 Hub 处注销卫星并停用处理程序（[SWS_SM_00713]、[SWS_SM_81013]）。

时序图：注册、Suspend-to-RAM 通知、恢复和注销的典型流程。来源：[SWS_SM_00701]、[SWS_SM_00703]、[SWS_SM_00710]、[SWS_SM_00711]、[SWS_SM_00713]、[SWS_SM_81010]、[SWS_SM_81011]、[SWS_SM_81012]、[SWS_SM_81013]。

错误场景

在实例化阶段就可能发生错误。只要强制的 IAM 切换处于活动状态，静态方法 Create() 就会返回错误 ara::sm::SmErrc::kAuthenticationRequired；在这种情况下，必须改用带有 InstanceSpecifier 的参数化构造函数（[SWS_SM_00716]、[SWS_SM_81014]）。构造函数 S2RSatellite(const ara::core::InstanceSpecifier&) 检查建模和平台状态，并在发生错误时引发运行时违规：

  • 如果平台运行时环境未初始化，则为 AraNotInitializedViolation（[SWS_SM_81003]）。
  • 如果标识符无法解析或未引用 PortPrototype，则为 InstanceSpecifierMappingIntegrityViolation（[SWS_SM_81003]）。
  • 如果接口类型与预期的接口映射不匹配，则为 PortInterfaceMappingViolation（[SWS_SM_81003]）。
  • 如果实例引用不存在匹配的建模进程，则为 ProcessMappingViolation（[SWS_SM_81003]）。
  • 如果实例标识符已在进程中使用，则为 InstanceSpecifierAlreadyInUseViolation（[SWS_SM_81003]）。

如果因与 State Management 守护进程的连接问题导致在 Offer() 处的注册失败，调用将返回包含错误 SmErrc::kOfferFailed 的 ara::core::Result（[SWS_SM_81012]）。如果在执行 EnterSuspendMode() 或 LeaveSuspendMode() 期间出现问题，卫星通过返回的 Future 标明错误 SmErrc::kRejected（[SWS_SM_81010]、[SWS_SM_81011]）。在退出挂起模式时，这会导致 Hub 端产生总体结果 kAtLeastOneHadIssuesToLeave（[SWS_SM_00707]）。

使用

静态工厂方法 ara::sm::s2r::S2RSatellite::Create 用于在同一台机器内同步实例化一个卫星端，以便直接连接到 S2RHub（[SWS_SM_81014]）。该调用不接收任何参数，并返回一个 ara::core::Result<S2RSatellite>，成功时其提供创建的卫星端对象（[SWS_SM_81014]）。

错误处理

如果配置中的开关“Force IAM switch”设置为 true，则调用失败并返回错误码 ara::sm::SmErrc::kAuthenticationRequired（[SWS_SM_00716]）。在这种情况下，必须强制改用构造函数 ara::sm::s2r::S2RSatellite::S2RSatellite（[SWS_SM_81014]）。此外，如果在调用时 ARA 运行时环境未初始化，则会引发 AraNotInitialized-Violation（[SWS_SM_81014]）。

并发性与边界条件

该函数被指定为线程安全以及异常安全，并声明为 noexcept（[SWS_SM_81014]）。因此，可以安全地从并发应用上下文中调用它。

相互作用

S2RSatellite 的实例用于支持 S2R 的应用中，以处理挂起模式之前和之后的通知（SWS StateManagement §7.5.2 “S2R Satellite”）。实例化成功后，应用通过 Offer 在 Hub 上注册（[SWS_SM_00710]）。在销毁对象之前，必须调用 StopOffer 进行注销（[SWS_SM_00713]）。Interpretation：方法 Create 预计主要用于未对卫星端强制执行 IAM 认证的应用场景。

                                  用法与语义
                                  

                                  方法 StopOffer() 在 S2R Hub 处注销 ara::sm::s2r::S2RSatellite 的实例，并停用未来的回调调用（[SWS_SM_81013]、[SWS_SM_00710]）。该调用同步进行，并一直阻塞到当前所有活动的回调执行完全结束（[SWS_SM_00713]）。该函数不接收参数，也没有返回值。
                                  


                                  生命周期与错误处理

                                  在挂起到 RAM 流程中的交互
                                  

                                  当 S2R Hub 处于执行 RequestToEnterSuspendMode 或 RequestToLeaveSuspendMode 的过程中时，它会等待所有寻址的卫星端。如果卫星端在此阶段通过 StopOffer() 注销，Hub 会将其视为肯定确认，从而避免状态切换失败（[SWS_SM_00702]、[SWS_SM_00707]）。
