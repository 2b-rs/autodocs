上下文

类 ara::per::KeyValueStorage 在 AUTOSAR Adaptive Platform 内提供持久化键值存储。其主要职责是封装和管理一组唯一键及其各自关联的数据值。该类充当使用它的进程与物理存储介质之间的事务性接口。读写操作通过事务语义解耦执行，因此修改只有通过显式的同步步骤才能持久保存到物理存储中 [SWS_PER_00049]。

上下文图：应用程序与物理存储之间的 KeyValueStorage 接口集成。来源：[SWS_PER_00042]、[SWS_PER_00046]、[SWS_PER_00049]

生命周期

ara::per::KeyValueStorage 的实例遵循严格的所有权和生命周期规则。默认构造函数 [SWS_PER_00459]、复制和移动构造函数 [SWS_PER_00324]、[SWS_PER_00322] 以及赋值运算符 [SWS_PER_00325]、[SWS_PER_00323] 均被指定为已删除（=delete）。对象的创建通过函数 OpenKeyValueStorage() [SWS_PER_00365] 进行。据推测，实例管理由调用方通过诸如智能指针等基于指针的所有权结构来进行。

在运行期间，该类被设计为线程安全的：所有功能接口均可由多个线程并行调用，但并发调用可能会导致相互延迟 [SWS_PER_00046]、[SWS_PER_00049]。通过析构函数 [SWS_PER_00050] 进行销毁时，该保护终止：析构函数本身被明确指定为非线程安全，并且需要进行协调释放且不得发生并发访问。

使用路径

典型的使用路径包括验证现有键、设置或更新值以及最终的持久化保存：

  1. 检查与查询：在更新之前，可通过 KeyExists [SWS_PER_00043] 检查键是否存在。已存在的键可以使用 GetAllKeys [SWS_PER_00042] 列出，其字节大小可通过 GetCurrentValueSize [SWS_PER_00554] 获取，或者其内容可通过 GetValue [SWS_PER_00332]、[SWS_PER_00044] 读取。
  2. 事务性写入：通过 SetValue [SWS_PER_00046] 可以类型化地存储或覆盖值。类似地，RemoveKey [SWS_PER_00047] 或 RemoveAllKeys [SWS_PER_00048] 用于移除条目。所有更改最初仅在当前事务中生效。
  3. 提交或放弃：调用 SyncToStorage [SWS_PER_00049] 会将所有待处理的更改持久写入物理存储。如果需要撤销自上次同步或打开以来未保存的修改，则可使用 DiscardPendingChanges [SWS_PER_00365]。发生故障或错误配置时，可通过 ResetKey [SWS_PER_00426] 将键重置为配置的初始值，或者在发生完整性错误后通过 RecoverKey [SWS_PER_00427] 进行恢复。

错误场景

KeyValueStorage 的方法通过 ara::core::Result 并使用来自 PerErrc 的特定错误代码来指示错误：

  • 键与类型错误：如果调用方尝试访问不存在的条目，GetValue、GetCurrentValueSize、RemoveKey 和 RecoverKey 将返回错误 PerErrc::kKeyNotFound [SWS_PER_00332]、[SWS_PER_00554]、[SWS_PER_00047]、[SWS_PER_00427]。如果 SetValue 或 GetValue 中的模板数据类型与存储的类型不匹配，API 将以 PerErrc::kDataTypeMismatch 响应 [SWS_PER_00046]、[SWS_PER_00044]。如果某个键不存在初始值，ResetKey 会返回代码 PerErrc::kInitValueNotAvailable [SWS_PER_00426]。
  • 访问与容量限制：如果存储区为只读或配置为 write-only-once 且键已存在，则任何写入操作（如 SetValue、RemoveKey、SyncToStorage）都会导致 PerErrc::kIllegalWriteAccess [SWS_PER_00046]、[SWS_PER_00049]。超出存储容量会导致 PerErrc::kOutOfStorageSpace，或者在达到配置的限制时导致 PerErrc::kQuotaExceeded [SWS_PER_00046]、[SWS_PER_00049]。
  • 硬件、完整性与安全错误：存储介质故障表现为 PerErrc::kPhysicalStorageFailure。若校验和、验证、加密或解密或 MAC 校验失败，操作将分别报告 PerErrc::kIntegrityCorrupted、PerErrc::kValidationFailed、PerErrc::kEncryptionFailed 或 PerErrc::kAuthenticationFailed [SWS_PER_00042]、[SWS_PER_00046]、[SWS_PER_00049]。

<h4>生命周期</h4>
<p><code>ara::per::KeyValueStorage</code> 的实例遵循严格的所有权和生命周期规则。默认构造函数 <a class="spec-record-ref" data-req="SWS_PER_00459" href="../spec/record.html?id=SWS_PER_00459">[SWS_PER_00459]</a>、复制和移动构造函数 <a class="spec-record-ref" data-req="SWS_PER_00324" href="../spec/record.html?id=SWS_PER_00324">[SWS_PER_00324]</a>、<a class="spec-record-ref" data-req="SWS_PER_00322" href="../spec/record.html?id=SWS_PER_00322">[SWS_PER_00322]</a> 以及赋值运算符 <a class="spec-record-ref" data-req="SWS_PER_00325" href="../spec/record.html?id=SWS_PER_00325">[SWS_PER_00325]</a>、<a class="spec-record-ref" data-req="SWS_PER_00323" href="../spec/record.html?id=SWS_PER_00323">[SWS_PER_00323]</a> 均被指定为已删除（<code>=delete</code>）。对象的创建通过函数 <code>OpenKeyValueStorage()</code> <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a> 进行。据推测，实例管理由调用方通过诸如智能指针等基于指针的所有权结构来进行。</p>
<p>在运行期间，该类被设计为线程安全的：所有功能接口均可由多个线程并行调用，但并发调用可能会导致相互延迟 <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>、<a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>。通过析构函数 <a class="spec-record-ref" data-req="SWS_PER_00050" href="../spec/record.html?id=SWS_PER_00050">[SWS_PER_00050]</a> 进行销毁时，该保护终止：析构函数本身被明确指定为非线程安全，并且需要进行协调释放且不得发生并发访问。</p>

<h4>使用路径</h4>
<p>典型的使用路径包括验证现有键、设置或更新值以及最终的持久化保存：</p>
<ol>
<li><strong>检查与查询：</strong>在更新之前，可通过 <code>KeyExists</code> <a class="spec-record-ref" data-req="SWS_PER_00043" href="../spec/record.html?id=SWS_PER_00043">[SWS_PER_00043]</a> 检查键是否存在。已存在的键可以使用 <code>GetAllKeys</code> <a class="spec-record-ref" data-req="SWS_PER_00042" href="../spec/record.html?id=SWS_PER_00042">[SWS_PER_00042]</a> 列出，其字节大小可通过 <code>GetCurrentValueSize</code> <a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a> 获取，或者其内容可通过 <code>GetValue</code> <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>、<a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a> 读取。</li>
<li><strong>事务性写入：</strong>通过 <code>SetValue</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a> 可以类型化地存储或覆盖值。类似地，<code>RemoveKey</code> <a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a> 或 <code>RemoveAllKeys</code> <a class="spec-record-ref" data-req="SWS_PER_00048" href="../spec/record.html?id=SWS_PER_00048">[SWS_PER_00048]</a> 用于移除条目。所有更改最初仅在当前事务中生效。</li>
<li><strong>提交或放弃：</strong>调用 <code>SyncToStorage</code> <a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a> 会将所有待处理的更改持久写入物理存储。如果需要撤销自上次同步或打开以来未保存的修改，则可使用 <code>DiscardPendingChanges</code> <a class="spec-record-ref" data-req="SWS_PER_00365" href="../spec/record.html?id=SWS_PER_00365">[SWS_PER_00365]</a>。发生故障或错误配置时，可通过 <code>ResetKey</code> <a class="spec-record-ref" data-req="SWS_PER_00426" href="../spec/record.html?id=SWS_PER_00426">[SWS_PER_00426]</a> 将键重置为配置的初始值，或者在发生完整性错误后通过 <code>RecoverKey</code> <a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a> 进行恢复。</li>
</ol>

<h4>错误场景</h4>
<p><code>KeyValueStorage</code> 的方法通过 <code>ara::core::Result</code> 并使用来自 <code>PerErrc</code> 的特定错误代码来指示错误：</p>
<ul>
<li><strong>键与类型错误：</strong>如果调用方尝试访问不存在的条目，<code>GetValue</code>、<code>GetCurrentValueSize</code>、<code>RemoveKey</code> 和 <code>RecoverKey</code> 将返回错误 <code>PerErrc::kKeyNotFound</code> <a class="spec-record-ref" data-req="SWS_PER_00332" href="../spec/record.html?id=SWS_PER_00332">[SWS_PER_00332]</a>、<a class="spec-record-ref" data-req="SWS_PER_00554" href="../spec/record.html?id=SWS_PER_00554">[SWS_PER_00554]</a>、<a class="spec-record-ref" data-req="SWS_PER_00047" href="../spec/record.html?id=SWS_PER_00047">[SWS_PER_00047]</a>、<a class="spec-record-ref" data-req="SWS_PER_00427" href="../spec/record.html?id=SWS_PER_00427">[SWS_PER_00427]</a>。如果 <code>SetValue</code> 或 <code>GetValue</code> 中的模板数据类型与存储的类型不匹配，API 将以 <code>PerErrc::kDataTypeMismatch</code> 响应 <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>、<a class="spec-record-ref" data-req="SWS_PER_00044" href="../spec/record.html?id=SWS_PER_00044">[SWS_PER_00044]</a>。如果某个键不存在初始值，<code>ResetKey</code> 会返回代码 <code>PerErrc::kInitValueNotAvailable</code> <a class="spec-record-ref" data-req="SWS_PER_00426" href="../spec/record.html?id=SWS_PER_00426">[SWS_PER_00426]</a>。</li>
<li><strong>访问与容量限制：</strong>如果存储区为只读或配置为 <code>write-only-once</code> 且键已存在，则任何写入操作（如 <code>SetValue</code>、<code>RemoveKey</code>、<code>SyncToStorage</code>）都会导致 <code>PerErrc::kIllegalWriteAccess</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>、<a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>。超出存储容量会导致 <code>PerErrc::kOutOfStorageSpace</code>，或者在达到配置的限制时导致 <code>PerErrc::kQuotaExceeded</code> <a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>、<a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>。</li>
<li><strong>硬件、完整性与安全错误：</strong>存储介质故障表现为 <code>PerErrc::kPhysicalStorageFailure</code>。若校验和、验证、加密或解密或 MAC 校验失败，操作将分别报告 <code>PerErrc::kIntegrityCorrupted</code>、<code>PerErrc::kValidationFailed</code>、<code>PerErrc::kEncryptionFailed</code> 或 <code>PerErrc::kAuthenticationFailed</code> <a class="spec-record-ref" data-req="SWS_PER_00042" href="../spec/record.html?id=SWS_PER_00042">[SWS_PER_00042]</a>、<a class="spec-record-ref" data-req="SWS_PER_00046" href="../spec/record.html?id=SWS_PER_00046">[SWS_PER_00046]</a>、<a class="spec-record-ref" data-req="SWS_PER_00049" href="../spec/record.html?id=SWS_PER_00049">[SWS_PER_00049]</a>。</li>
</ul>
