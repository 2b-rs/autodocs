上下文

类 ara::diag::DynamicAccessListDiagServiceBuilder（[SWS_DM_01166]、AUTOSAR_AP_SWS_Diagnostics §8.15 “Class: DynamicAccessListDiagServiceBuilder”）用于应用程序逐步定义并序列化诊断服务的动态访问列表（DynamicAccessList）。它是根据单字节、字节序列、值范围或通配符对诊断请求的访问模式进行细粒度结构化组织的核心工具。

在整个系统中，该 Builder 与三个主要伙伴进行交互：

  • 应用程序（Application）：通过 Builder 的 Fluent API 为传入的诊断请求配置所需的过滤模式。
  • DiagnosticServiceDynamicAccessList：通过如 MakeServiceBuilder（[SWS_DM_01164]、[SWS_DM_01165]）等工厂方法提供入口点，并接收已定义的访问列表。
  • Diagnostic Server Instance：诊断服务器实例在运行时对诊断服务访问权限进行模式匹配（Pattern Matching）时，评估传入的字节模式、通配符和结束模式（[SWS_DM_01220]、[SWS_DM_01221]）。

上下文图：应用程序、访问列表、Builder 与诊断服务器之间的协作。来源：[SWS_DM_01164]、[SWS_DM_01166]、[SWS_DM_01220]。

生命周期

Builder 实例的创建既可以直接通过模板构造函数指定初始值和序列化缓冲区引用（ara::core::Vector<std::uint8_t>& content）来进行（[SWS_DM_01169]），也可以通过如 MakeServiceBuilder 等辅助函数来进行（[SWS_DM_01164]、[SWS_DM_01165]）。

在所有权和复制语义方面，该类强制执行严格的线性使用：

  • 复制构造函数（[SWS_DM_01171]）和复制赋值运算符（[SWS_DM_01172]）均被声明为已删除（=delete）。
  • 移动赋值运算符同样已删除（[SWS_DM_01173]）。传递只能通过移动构造函数（[SWS_DM_01170]）进行。

对于通过析构函数（[SWS_DM_01174]）进行销毁，存在一个固定的不变式：在销毁对象之前，必须强制调用方法 Build()（[SWS_DM_01181]），以完成列表的创建。

在并发性方面，模板构造函数和移动构造函数被指定为线程安全（thread-safe）（[SWS_DM_01169]、[SWS_DM_01170]）。相反，所有构建模式的操作（Add、Any、EndsWith、Build）以及析构函数则被明确指定为非线程安全（not thread-safe）（[SWS_DM_01174]、[SWS_DM_01175]、[SWS_DM_01181]），且不得在同一实例上并发调用。

使用路径

配置诊断访问模式的典型流程分为三个步骤：

  1. 初始化：通过 DiagnosticServiceDynamicAccessList::MakeServiceBuilder（[SWS_DM_01164]、[SWS_DM_01165]）使用服务标识符请求 Builder，或者直接通过构造函数请求（[SWS_DM_01169]）。
  2. 通过 Fluent API 构建模式：
    • 通过 Add(Byte) 添加单个字节（Byte / std::uint8_t、[SWS_DM_01167]）（[SWS_DM_01175]）、通过 Add(ByteString) 添加字节序列（[SWS_DM_01168]、[SWS_DM_01176]）或通过 Add(ByteRange) 添加值范围（[SWS_DM_01177]）。
    • 通过 Any(numberOfBytesToIgnore) 插入占位符（[SWS_DM_01178]、[SWS_DM_01220]、AUTOSAR_AP_SWS_Diagnostics §7.1.3 “Adding wildcards to a DynamicAccessList”）。以此在模式中保存后续匹配时将被忽略的字节（例如用于 DID 前缀的 22F1XX）。
    • 可选地使用 EndsWith(Byte)（[SWS_DM_01179]）或 EndsWith(ByteRange)（[SWS_DM_01180]、[SWS_DM_01221]）指定结束模式。
  3. 完成：调用 Build()（[SWS_DM_01181]），从而完成列表构建。

时序图：通过 Fluent API 配置和完成模式的典型流程。来源：[SWS_DM_01164]、[SWS_DM_01175]、[SWS_DM_01178]、[SWS_DM_01181]。

错误场景

ara::diag::DynamicAccessListDiagServiceBuilder 的整个接口一律使用 noexcept 并且被指定为异常安全（exception safe）（[SWS_DM_01169]、[SWS_DM_01175]、[SWS_DM_01181]）。既不抛出 C++ 异常，也不通过 ara::core::Result 返回错误状态。

因此，错误情况主要由违反前置条件所导致：

  • 未调用完成方法：如果在未事先调用 Build() 的情况下销毁 Builder，则违反了 [SWS_DM_01181] 的前置条件。解释：在这种情况下，访问模式可能会保持不完整，且不会被诊断服务器作为有效条件予以考虑。
  • 未受保护的并发：由于用于添加元素的所有方法以及 Build() 均被分类为 not thread-safe，从多个线程并发调用将导致所引用缓冲区中的数据损坏。

<li><strong>DiagnosticServiceDynamicAccessList：</strong>通过如 <code>MakeServiceBuilder</code>（<a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>、<a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>）等工厂方法提供入口点，并接收已定义的访问列表。</li>

</ul>

<h4>生命周期</h4>
<p>Builder 实例的创建既可以直接通过模板构造函数指定初始值和序列化缓冲区引用（<code>ara::core::Vector&lt;std::uint8_t&gt;&amp; content</code>）来进行（<a class="spec-record-ref" data-req="SWS_DM_01169" href="../spec/record.html?id=SWS_DM_01169">[SWS_DM_01169]</a>），也可以通过如 <code>MakeServiceBuilder</code> 等辅助函数来进行（<a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>、<a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>）。</p>
<p>在所有权和复制语义方面，该类强制执行严格的线性使用：</p>
<ul>
<li>复制构造函数（<a class="spec-record-ref" data-req="SWS_DM_01171" href="../spec/record.html?id=SWS_DM_01171">[SWS_DM_01171]</a>）和复制赋值运算符（<a class="spec-record-ref" data-req="SWS_DM_01172" href="../spec/record.html?id=SWS_DM_01172">[SWS_DM_01172]</a>）均被声明为已删除（<code>=delete</code>）。</li>
<li>移动赋值运算符同样已删除（<a class="spec-record-ref" data-req="SWS_DM_01173" href="../spec/record.html?id=SWS_DM_01173">[SWS_DM_01173]</a>）。传递只能通过移动构造函数（<a class="spec-record-ref" data-req="SWS_DM_01170" href="../spec/record.html?id=SWS_DM_01170">[SWS_DM_01170]</a>）进行。</li>
</ul>
<p>对于通过析构函数（<a class="spec-record-ref" data-req="SWS_DM_01174" href="../spec/record.html?id=SWS_DM_01174">[SWS_DM_01174]</a>）进行销毁，存在一个固定的不变式：在销毁对象之前，必须强制调用方法 <code>Build()</code>（<a class="spec-record-ref" data-req="SWS_DM_01181" href="../spec/record.html?id=SWS_DM_01181">[SWS_DM_01181]</a>），以完成列表的创建。</p>
<p>在并发性方面，模板构造函数和移动构造函数被指定为线程安全（<code>thread-safe</code>）（<a class="spec-record-ref" data-req="SWS_DM_01169" href="../spec/record.html?id=SWS_DM_01169">[SWS_DM_01169]</a>、<a class="spec-record-ref" data-req="SWS_DM_01170" href="../spec/record.html?id=SWS_DM_01170">[SWS_DM_01170]</a>）。相反，所有构建模式的操作（<code>Add</code>、<code>Any</code>、<code>EndsWith</code>、<code>Build</code>）以及析构函数则被明确指定为非线程安全（<code>not thread-safe</code>）（<a class="spec-record-ref" data-req="SWS_DM_01174" href="../spec/record.html?id=SWS_DM_01174">[SWS_DM_01174]</a>、<a class="spec-record-ref" data-req="SWS_DM_01175" href="../spec/record.html?id=SWS_DM_01175">[SWS_DM_01175]</a>、<a class="spec-record-ref" data-req="SWS_DM_01181" href="../spec/record.html?id=SWS_DM_01181">[SWS_DM_01181]</a>），且不得在同一实例上并发调用。</p>

<h4>使用路径</h4>
<p>配置诊断访问模式的典型流程分为三个步骤：</p>
<ol>
<li><strong>初始化：</strong>通过 <code>DiagnosticServiceDynamicAccessList::MakeServiceBuilder</code>（<a class="spec-record-ref" data-req="SWS_DM_01164" href="../spec/record.html?id=SWS_DM_01164">[SWS_DM_01164]</a>、<a class="spec-record-ref" data-req="SWS_DM_01165" href="../spec/record.html?id=SWS_DM_01165">[SWS_DM_01165]</a>）使用服务标识符请求 Builder，或者直接通过构造函数请求（<a class="spec-record-ref" data-req="SWS_DM_01169" href="../spec/record.html?id=SWS_DM_01169">[SWS_DM_01169]</a>）。</li>
<li><strong>通过 Fluent API 构建模式：</strong>
<ul>
<li>通过 <code>Add(Byte)</code> 添加单个字节（<code>Byte</code> / <code>std::uint8_t</code>、<a class="spec-record-ref" data-req="SWS_DM_01167" href="../spec/record.html?id=SWS_DM_01167">[SWS_DM_01167]</a>）（<a class="spec-record-ref" data-req="SWS_DM_01175" href="../spec/record.html?id=SWS_DM_01175">[SWS_DM_01175]</a>）、通过 <code>Add(ByteString)</code> 添加字节序列（<a class="spec-record-ref" data-req="SWS_DM_01168" href="../spec/record.html?id=SWS_DM_01168">[SWS_DM_01168]</a>、<a class="spec-record-ref" data-req="SWS_DM_01176" href="../spec/record.html?id=SWS_DM_01176">[SWS_DM_01176]</a>）或通过 <code>Add(ByteRange)</code> 添加值范围（<a class="spec-record-ref" data-req="SWS_DM_01177" href="../spec/record.html?id=SWS_DM_01177">[SWS_DM_01177]</a>）。</li>
<li>通过 <code>Any(numberOfBytesToIgnore)</code> 插入占位符（<a class="spec-record-ref" data-req="SWS_DM_01178" href="../spec/record.html?id=SWS_DM_01178">[SWS_DM_01178]</a>、<a class="spec-record-ref" data-req="SWS_DM_01220" href="../spec/record.html?id=SWS_DM_01220">[SWS_DM_01220]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=134">AUTOSAR_AP_SWS_Diagnostics §7.1.3 “Adding wildcards to a DynamicAccessList”</a>）。以此在模式中保存后续匹配时将被忽略的字节（例如用于 DID 前缀的 <code>22F1XX</code>）。</li>
<li>可选地使用 <code>EndsWith(Byte)</code>（<a class="spec-record-ref" data-req="SWS_DM_01179" href="../spec/record.html?id=SWS_DM_01179">[SWS_DM_01179]</a>）或 <code>EndsWith(ByteRange)</code>（<a class="spec-record-ref" data-req="SWS_DM_01180" href="../spec/record.html?id=SWS_DM_01180">[SWS_DM_01180]</a>、<a class="spec-record-ref" data-req="SWS_DM_01221" href="../spec/record.html?id=SWS_DM_01221">[SWS_DM_01221]</a>）指定结束模式。</li>
</ul>
</li>
<li><strong>完成：</strong>调用 <code>Build()</code>（<a class="spec-record-ref" data-req="SWS_DM_01181" href="../spec/record.html?id=SWS_DM_01181">[SWS_DM_01181]</a>），从而完成列表构建。</li>
</ol>

<h4>错误场景</h4>
<p><code>ara::diag::DynamicAccessListDiagServiceBuilder</code> 的整个接口一律使用 <code>noexcept</code> 并且被指定为异常安全（<code>exception safe</code>）（<a class="spec-record-ref" data-req="SWS_DM_01169" href="../spec/record.html?id=SWS_DM_01169">[SWS_DM_01169]</a>、<a class="spec-record-ref" data-req="SWS_DM_01175" href="../spec/record.html?id=SWS_DM_01175">[SWS_DM_01175]</a>、<a class="spec-record-ref" data-req="SWS_DM_01181" href="../spec/record.html?id=SWS_DM_01181">[SWS_DM_01181]</a>）。既不抛出 C++ 异常，也不通过 <code>ara::core::Result</code> 返回错误状态。</p>
<p>因此，错误情况主要由违反前置条件所导致：</p>
<ul>
<li><strong>未调用完成方法：</strong>如果在未事先调用 <code>Build()</code> 的情况下销毁 Builder，则违反了 <a class="spec-record-ref" data-req="SWS_DM_01181" href="../spec/record.html?id=SWS_DM_01181">[SWS_DM_01181]</a> 的前置条件。解释：在这种情况下，访问模式可能会保持不完整，且不会被诊断服务器作为有效条件予以考虑。</li>
<li><strong>未受保护的并发：</strong>由于用于添加元素的所有方法以及 <code>Build()</code> 均被分类为 <code>not thread-safe</code>，从多个线程并发调用将导致所引用缓冲区中的数据损坏。</li>
</ul>
