实现诊断服务动态访问权限列表的逐步构建和完成。

该类用于通过可链式调用的 Fluent API ([SWS_DM_01166]) 逐步为诊断服务创建动态访问权限列表。应用程序添加精确字节、值范围以及通配符，以便为 Diagnostic Server 灵活定义访问模式 ([SWS_DM_01175], [SWS_DM_01220])。在销毁该不可线程安全的 Move-Only 对象之前，必须强制调用方法 Build() 以完成配置 ([SWS_DM_01181])。

上下文

类 ara::diag::DynamicAccessListDiagServiceBuilder 用于 AUTOSAR Adaptive Platform 应用程序逐步构建诊断服务 ([SWS_DM_01166], AUTOSAR_AP_SWS_Diagnostics §8.15.1 “Class: DynamicAccessListDiagServiceBuilder”) 的动态访问权限列表 (DynamicAccessList)。通过这些列表，应用程序控制在运行时动态授权哪些诊断请求（例如具有具体 DID 或子功能的特定 UDS 服务）(AUTOSAR_AP_SWS_Diagnostics §8.2 “Adding wildcards to a DynamicAccessList”)。

核心交互方是应用程序本身、类 ara::diag::DiagnosticServiceDynamicAccessList 的工厂方法 ([SWS_DM_01164], [SWS_DM_01165]) 以及 Diagnostic Server 实例，后者在根据传入请求检查服务权限时评估组合的位模式和字节模式 ([SWS_DM_01220], [SWS_DM_01221])。为了表示模式结构，该类提供了用于单个八位位组 (std::uint8_t) 的类型别名 Byte 和用于字节序列 (ara::core::Span<Byte>) 的 ByteString ([SWS_DM_01167], [SWS_DM_01168], AUTOSAR_AP_SWS_Diagnostics §8.15.1.1 “Public Member Types”)。

生命周期

Builder 对象通常通过 DiagnosticServiceDynamicAccessList::MakeServiceBuilder ([SWS_DM_01164], [SWS_DM_01165]) 或直接通过构造函数进行实例化，该构造函数接收初始值以及对序列化缓冲区 content (ara::core::Vector<std::uint8_t>&) 的引用 ([SWS_DM_01169])。解释：参数 content 推测用作序列化表示的连续填充存储，该序列化表示在完成后传递给 Diagnostic Server。

在所有权和可复制性方面，该类强制执行具有受限赋值的严格 Move-Only 语义：复制构造函数 ([SWS_DM_01171]) 和复制赋值运算符 ([SWS_DM_01172]) 已删除 (=delete)。同样，移动赋值运算符也已删除 ([SWS_DM_01173])。仅实现了移动构造函数 ([SWS_DM_01170])，因此实例可以在需要时移动，但不能不受控地复制或重新赋值。

生命周期遵循一项强制后置条件：在调用析构函数 ([SWS_DM_01174]) 之前，必须调用方法 Build() 以完成列表的创建 ([SWS_DM_01181])。虽然构造函数被规范为线程安全 ([SWS_DM_01169], [SWS_DM_01170])，但所有用于模式扩展的方法以及析构函数都是非线程安全的 (not thread-safe, [SWS_DM_01174])。

使用路径

模式的配置通过 Fluent API 进行，其中方法调用返回对同一 Builder 实例的引用 ([SWS_DM_01175])：

  1. 初始化：应用程序创建 Builder，例如通过 DiagnosticServiceDynamicAccessList::MakeServiceBuilder 并传入引导字节或字节字符串 ([SWS_DM_01164], [SWS_DM_01165])。
  2. 模式扩展：通过重载的 Add() 方法附加单个字节 ([SWS_DM_01175])、字节序列 ([SWS_DM_01176]) 或闭合值范围 ByteRange ([SWS_DM_01177])。这些值在后续评估中针对完全匹配进行检查。
  3. 插入通配符：应用程序使用 Any(numberOfBytesToIgnore) 定义占位符 ([SWS_DM_01178])。Diagnostic Server 在模式匹配时忽略指定数量的字节，由此可实现针对 DID 范围的灵活过滤器（如 22F1XX）([SWS_DM_01220], AUTOSAR_AP_SWS_Diagnostics §8.2 “Adding wildcards to a DynamicAccessList”)。
  4. 模式结束与完成：通过 EndsWith() 可以指定终止字节或范围 ([SWS_DM_01179], [SWS_DM_01180], [SWS_DM_01221])。最后，调用 Build() 最终完成创建过程 ([SWS_DM_01181])。

时序图：在模式定义期间应用程序、工厂方法与 Builder 之间的典型交互顺序。来源：[SWS_DM_01165]、[SWS_DM_01175]、[SWS_DM_01178]、[SWS_DM_01181]。

错误场景

该类的所有方法均声明为 noexcept 并被规范为异常安全 (exception safe) ([SWS_DM_01169], [SWS_DM_01174], [SWS_DM_01181])。在 API 级别不发生通过 C++ 异常或错误返回值的错误处理。

关键的契约性前置条件在于销毁 Builder 之前调用 Build() ([SWS_DM_01181])。解释：如果在未执行 Build() 的情况下销毁 Builder 对象，推测已开始的模式配置将被丢弃或在底层访问列表中留下无效状态。

此外，进行操纵的函数不是线程安全的 ([SWS_DM_01175], [SWS_DM_01178], [SWS_DM_01181])。从多个线程对同一 Builder 实例进行未受保护的并发访问会导致未定义的内存状态（数据竞争）。
