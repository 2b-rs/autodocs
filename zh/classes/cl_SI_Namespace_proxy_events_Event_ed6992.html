上下文

生成的 C++ 类 <SI-Namespace>::proxy::events::<Event> 代表 AUTOSAR Adaptive 中服务代理内部特定服务事件的接收端接口（AUTOSAR_AP_EXP_ARAComAPI 第10页）。其主要职责包括管理事件订阅、注册通知回调，以及通过类型别名 SampleType 实现对传入事件数据的类型安全访问 [SWS_CM_11401]。

该类主要与三个参与方进行交互：

  • 应用软件：通过 Subscribe [SWS_CM_00141] 和 Unsubscribe [SWS_CM_00151] 等方法发起订阅、设置回调，并在 GetNewSamples 中使用仿函数处理接收到的数据样本 [SWS_CM_00701]。
  • Communication Management（运行时环境）：监控连接和订阅状态，接收序列化的事件数据，并在数据到达时触发已注册的 EventReceiveHandler [SWS_CM_00181]。
  • 执行上下文（ExecutorT）：允许可选地传递自定义执行上下文，以便在特定的线程或工作队列中针对性地处理通知、状态切换和错误处理程序 [SWS_CM_11354]、[SWS_CM_11356]、[SWS_CM_00100]。
  • 端到端保护（E2E）：支持通过 SetTransportFaultConditionHandler [SWS_CM_00099] 监控传输错误，并在评估接收到的样本后查询 E2E 状态 [SWS_CM_11554]。

生命周期

<SI-Namespace>::proxy::events::<Event> 的实例作为上级服务代理的组成部分进行实例化，并共享其生命周期；因此所有权归代理对象所有。功能生命周期主要由订阅的内部状态（SubscriptionState）决定，该状态可随时通过 GetSubscriptionState 查询 [SWS_CM_00316]。

最初，事件处于未订阅状态。通过调用 Subscribe(maxSampleCount) [SWS_CM_00141] 启动状态转换：实例根据通信状态转换到状态 kSubscriptionPending 或直接进入 kSubscribed [SWS_CM_00141]。状态变更会通知给通过 SetSubscriptionStateChangeHandler [SWS_CM_00333] 或 [SWS_CM_11354] 注册的回调。如果再次使用相同的缓冲区值调用 Subscribe，则该调用不会产生任何效果 [SWS_CM_00141]。

终止操作通过 Unsubscribe [SWS_CM_00151] 进行，从而使事件返回到未订阅状态。若事件此前未被订阅，则该调用不起作用 [SWS_CM_00151]。为了释放资源，可以通过 UnsetSubscriptionStateChangeHandler [SWS_CM_00334]、UnsetReceiveHandler [SWS_CM_00183] 和 UnsetTransportFaultConditionHandler [SWS_CM_00105] 显式移除已注册的处理程序。所有 API 方法均被声明为 noexcept。

状态图：包含状态与转换的事件订阅生命周期。来源：[SWS_CM_00141]、[SWS_CM_00151]、[SWS_CM_00316]、[SWS_CM_00333]。

使用路径

用于事件驱动处理数据样本的典型使用路径分为以下步骤：

  1. 配置处理程序：应用程序首先通过 SetReceiveHandler [SWS_CM_00181] 注册接收处理程序，或结合执行上下文通过 SetReceiveHandler(handler, executor) [SWS_CM_11356] 注册。可选地，可以为状态切换 [SWS_CM_00333] 或 E2E 传输错误 [SWS_CM_00099] 设置处理程序。
  2. 激活订阅：通过 Subscribe(maxSampleCount) [SWS_CM_00141]，应用程序告知中间件本地缓存中最多可以同时保留多少个样本。
  3. 通知与数据检索：一旦有新数据可用，Communication Management 便会触发已注册的处理程序 [SWS_CM_00181]。在此处理程序中，应用程序调用 GetNewSamples [SWS_CM_00701]。传入的可调用仿函数将每个新数据项作为类型化指针接收 ara::com::SamplePtr<SampleType const>。返回值指示已处理样本的总数。
  4. 检查缓冲区与状态：应用程序可以通过 GetFreeSampleCount [SWS_CM_00705] 查询空闲缓存槽位，并在 GetNewSamples 之后通过 GetE2EStateMachineState [SWS_CM_11554] 评估 E2E 校验的结果。
  5. 停用：处理完成后，应用程序注销处理程序（[SWS_CM_00183]、[SWS_CM_00334]、[SWS_CM_00105]）并通过 Unsubscribe 取消订阅 [SWS_CM_00151]。

时序图：处理程序注册、事件订阅及样本处理时的调用序列。来源：[SWS_CM_00141]、[SWS_CM_00181]、[SWS_CM_00701]、[SWS_CM_00151]。

错误场景

接口方法主要通过 ara::core::Result 以及指定的 API 违规情况来指示错误条件：

  • ComErrc::kMaxSamplesExceeded：当应用程序同时持有的 ara::com::SamplePtr 实例数超过此前在 Subscribe 中承诺的数量时，由 GetNewSamples 返回。此时不采用回滚语义，且后续样本可能已被丢弃 [SWS_CM_00701]。
  • ComErrc::kMaxSampleCountNotRealizable：在调用 Subscribe 时发生，如果重新订阅时传入的 maxSampleCount 与当前现有订阅约定的不一致 [SWS_CM_00141]。
  • InsufficientPermissionsViolation：如果在调用 Subscribe 时授权执行（Grant Enforcement）拒绝了对事件订阅的访问，则会触发该错误 [SWS_CM_00141]。
  • InvalidHandlerViolation：当在注册方法 SetReceiveHandler [SWS_CM_00181]、[SWS_CM_11356]、SetSubscriptionStateChangeHandler [SWS_CM_00333]、[SWS_CM_11354] 或 SetTransportFaultConditionHandler [SWS_CM_00099]、[SWS_CM_00100] 中传入无效或空的处理程序时发生。
  • DanglingSamplesViolation：在调用 Unsubscribe 时指示应用程序上下文中仍存在悬挂样本（dangling samples），且违反了取消订阅的前提条件 [SWS_CM_00151]。
