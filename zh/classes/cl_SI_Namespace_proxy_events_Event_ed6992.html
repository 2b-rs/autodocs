使用目的

对于每个建模为 Event 的 Service-Interface 元素，Proxy 都会创建一个 Event wrapper。连接服务实例后，Consumer 订阅该 Event；Provider 将数据发送给 Communication Management，后者通知订阅者。随后通过 GetNewSamples() 显式获取 Samples。EXP ARAComAPI §4.3 “Event and Trigger based communication” §5.3.5 “Events”

订阅、缓存和接收模型

Subscribe(maxSampleCount) 同时设置本地 Sample 缓存的最大预算。该调用异步接受请求；可查询 Subscription 状态，或通过状态变更处理程序对其进行监测。对于循环应用程序，使用 GetNewSamples() 轮询即可；响应式应用程序则注册一个 SetReceiveHandler()，以便在有新数据时请求提取。EXP ARAComAPI §5.3.5.1 “Event Subscription and Local Cache” §5.3.5.2 “Monitoring Event Subscription” §5.3.5.5 “Event-Driven vs Polling-Based access”

样品所有权

传递给 Callback 的 SamplePtr 将缓存槽的责任转移给应用程序。只要持有SamplePtr，该槽位就不能重复使用；这限制了同时访问的样本数量。 EXP ARAComAPI §5.3.5.4 “Event Sample Management via SamplePtrs”

序列图：订阅和接收。来源：EXP ARAComAPI §4.3 “Event and Trigger based communication”、§5.3.5.1 “Event Subscription and Local Cache” 和 §5.3.5.5 “Event-Driven vs Polling-Based access”。
