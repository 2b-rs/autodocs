上下文

结构体 ara::diag::DiagnosticSovdContentData 是 AUTOSAR Adaptive Platform diag 模块的组成部分，并通过头文件 ara/diag/diagnostic_sovd_content_data.h 提供（[SWS_DM_02385]、AUTOSAR_AP_SWS_Diagnostics §8.59.1 “Struct: DiagnosticSovdContentData”）。它用作 Diagnostic Management (DM) 内 ASAM Service-Oriented Vehicle Diagnostics (SOVD) 协议内容的标准化数据传输容器。

从业务功能上看，该数据结构通过类型为 ara::core::Vector<DiagnosticSovdContentElementData> 的公共成员 elements 封装了 SOVD 内容元素的集合（[SWS_DM_02386]、AUTOSAR_AP_SWS_Diagnostics §8.59.1.1.1 “elements”）。该结构出现在三个主要参与者之间的接口处：外部 SOVD 客户端、车内 Diagnostic Management 守护进程（DM）以及 Adaptive 应用程序的具体诊断服务提供商（例如 ara::diag::GenericDiagnosticSovdOperation 或 SovdOperationExecution 的实例）（[SWS_DM_02174]、[SWS_DM_02180]、AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operations – Start execution of an operation”）。

生命周期

作为纯数据结构（struct），ara::diag::DiagnosticSovdContentData 遵循 C++ 的常规值语义（[SWS_DM_02385]）。它没有独立的生命周期管理器或状态存储，而是根据需要进行实例化和传输。

通常，当 SOVD 操作完成或为读取请求提供数据时，执行诊断的应用程序会创建一个实例（AUTOSAR_AP_SWS_Diagnostics §8.70 “virtual ara::core::Future<DiagnosticSovdContentData> Read”）。应用程序使用相应的 DiagnosticSovdContentElementData 条目填充向量 elements（[SWS_DM_02386]）。随后，该结构作为返回值或在响应容器内（例如 StartSynchronousExecution 返回值或 GetStatusResponse.Parameters）传递给 DM（[SWS_DM_02176]、[SWS_DM_02181]）。

Diagnostic Management 获取所有权或读取所包含的值，以便根据 ASAM SOVD 填充出站 SOVD 响应体的属性 parameters（[SWS_DM_02176]、[SWS_DM_02181]）。在序列化或响应生成完成后，该实例将根据正常的 C++ 作用域规则被销毁。由于它是一个数据结构，因此不存在内部线程同步；跨线程边界的访问需要移动语义或由调用方进行外部协调。

使用路径

ara::diag::DiagnosticSovdContentData 的主要使用路径在于 SOVD 操作的执行和状态反馈，以及专用的 SOVD 读取查询：

  1. 接收请求：外部客户端向诊断服务器发送 SOVD 方法“Start Execution of an Operation”（[SWS_DM_01396]、AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operations – Start execution of an operation”）。
  2. 调用应用程序操作：验证成功后，Diagnostic Management 通过 ara::diag::GenericDiagnosticSovdOperation::StartExecution 将调用转发给应用程序（[SWS_DM_02174]）。
  3. 填充数据结构：应用程序逻辑处理该操作，并以 DiagnosticSovdContentData 实例的形式生成结果，其向量 elements 用于接收输出数据（[SWS_DM_02386]）。
  4. DM 准备响应：DM 接收结果，由此推导出 SOVD 属性 parameters 的值，并将符合规范的 SOVD 响应正文发送给客户端（[SWS_DM_02176]）。

在状态查询（“Read the Status of an operation”）中的使用方式与此类似：成功调用 SovdOperationExecution::GetStatus 后，响应正文中 parameters 的值将从 GetStatusResponse.Parameters 中提供的 DiagnosticSovdContentData 中派生出来（[SWS_DM_02180]、[SWS_DM_02181]、AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operation Read the Status of an operation”）。此外，该结构还作为异步接口（例如 Read(...)）的结果通过 ara::core::Future<DiagnosticSovdContentData> 返回（AUTOSAR_AP_SWS_Diagnostics §8.70 “virtual ara::core::Future<DiagnosticSovdContentData> Read”）。

错误场景

在 ara::diag::DiagnosticSovdContentData 的使用和传递过程中，涉及若干前置条件和故障模式：

  • 安全验证失败：无论是在启动操作（[SWS_DM_02174]）还是在查询操作状态（[SWS_DM_02180]）时，成功验证 proximity_challenge 都是强制性的前提条件。如果此项检查失败，操作将被拒绝；应用程序函数不会被调用，也不会提供或评估 DiagnosticSovdContentData。
  • 状态查询失败：如果 SovdOperationExecution::GetStatus 无法成功执行，则无需构建常规 SOVD 响应正文，也不会从 DiagnosticSovdContentData 中派生 parameters（[SWS_DM_02181]）。
  • 读取操作时的异步取消：如果在 Read(...) 的上下文中请求 DiagnosticSovdContentData，系统会传递一个 ara::diag::CancellationHandler（AUTOSAR_AP_SWS_Diagnostics §8.70 “virtual ara::core::Future<DiagnosticSovdContentData> Read”）。如果该对象请求取消，则可以或必须提前终止 DiagnosticSovdContentData 的创建和填充。

<h4>使用路径</h4>
<p><code>ara::diag::DiagnosticSovdContentData</code> 的主要使用路径在于 SOVD 操作的执行和状态反馈，以及专用的 SOVD 读取查询：</p>
<ol>
  <li><strong>接收请求：</strong>外部客户端向诊断服务器发送 SOVD 方法“Start Execution of an Operation”（<a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=217">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operations – Start execution of an operation”</a>）。</li>
  <li><strong>调用应用程序操作：</strong>验证成功后，Diagnostic Management 通过 <code>ara::diag::GenericDiagnosticSovdOperation::StartExecution</code> 将调用转发给应用程序（<a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>）。</li>
  <li><strong>填充数据结构：</strong>应用程序逻辑处理该操作，并以 <code>DiagnosticSovdContentData</code> 实例的形式生成结果，其向量 <code>elements</code> 用于接收输出数据（<a class="spec-record-ref" data-req="SWS_DM_02386" href="../spec/record.html?id=SWS_DM_02386">[SWS_DM_02386]</a>）。</li>
  <li><strong>DM 准备响应：</strong>DM 接收结果，由此推导出 SOVD 属性 <code>parameters</code> 的值，并将符合规范的 SOVD 响应正文发送给客户端（<a class="spec-record-ref" data-req="SWS_DM_02176" href="../spec/record.html?id=SWS_DM_02176">[SWS_DM_02176]</a>）。</li>
</ol>
<p>在状态查询（“Read the Status of an operation”）中的使用方式与此类似：成功调用 <code>SovdOperationExecution::GetStatus</code> 后，响应正文中 <code>parameters</code> 的值将从 <code>GetStatusResponse.Parameters</code> 中提供的 <code>DiagnosticSovdContentData</code> 中派生出来（<a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>、<a class="spec-record-ref" data-req="SWS_DM_02181" href="../spec/record.html?id=SWS_DM_02181">[SWS_DM_02181]</a>、<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=219">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operation Read the Status of an operation”</a>）。此外，该结构还作为异步接口（例如 <code>Read(...)</code>）的结果通过 <code>ara::core::Future&lt;DiagnosticSovdContentData&gt;</code> 返回（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=852">AUTOSAR_AP_SWS_Diagnostics §8.70 “virtual ara::core::Future&lt;DiagnosticSovdContentData&gt; Read”</a>）。</p>

<h4>错误场景</h4>
<p>在 <code>ara::diag::DiagnosticSovdContentData</code> 的使用和传递过程中，涉及若干前置条件和故障模式：</p>
<ul>
  <li><strong>安全验证失败：</strong>无论是在启动操作（<a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>）还是在查询操作状态（<a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>）时，成功验证 <em>proximity_challenge</em> 都是强制性的前提条件。如果此项检查失败，操作将被拒绝；应用程序函数不会被调用，也不会提供或评估 <code>DiagnosticSovdContentData</code>。</li>
  <li><strong>状态查询失败：</strong>如果 <code>SovdOperationExecution::GetStatus</code> 无法成功执行，则无需构建常规 SOVD 响应正文，也不会从 <code>DiagnosticSovdContentData</code> 中派生 <code>parameters</code>（<a class="spec-record-ref" data-req="SWS_DM_02181" href="../spec/record.html?id=SWS_DM_02181">[SWS_DM_02181]</a>）。</li>
  <li><strong>读取操作时的异步取消：</strong>如果在 <code>Read(...)</code> 的上下文中请求 <code>DiagnosticSovdContentData</code>，系统会传递一个 <code>ara::diag::CancellationHandler</code>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=852">AUTOSAR_AP_SWS_Diagnostics §8.70 “virtual ara::core::Future&lt;DiagnosticSovdContentData&gt; Read”</a>）。如果该对象请求取消，则可以或必须提前终止 <code>DiagnosticSovdContentData</code> 的创建和填充。</li>
</ul>
