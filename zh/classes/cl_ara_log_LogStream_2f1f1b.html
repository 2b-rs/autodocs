类 ara::log::LogStream

[SWS_LOG_00173] Upstream: RS_LT_00003, RS_LT_00046

class LogStream final {...};

Represents a Log message, allowing stream operators to be used for appending data. Note: Normally Application processes would not use this class directly. Instead one of the log methods provided in the main Logging API shall be used. Those methods automatically setup a temporary object of this class with the given log severity level. The only reason to use this class directly is, if the user wants to hold a ara::log::LogStream object longer than the default one-statement scope. This is useful in order to create log messages that are distributed over multiple code lines. See the ara::log::LogStream::Flush method for further information. Once this temporary object gets out of scope, its destructor takes care that the message buffer is ready to be processed by the Logging framework. Besides the existing supported operator<< overloads for ara::log::LogStream it can be easily extended for other derived types by providing a stream operator that makes use of already supported types.

Example: struct MyCustomType { int8_t foo; ara::core::String bar; };

LogStream& operator<<(LogStream& out, const MyCustomType& value) { return (out << value.foo << value.bar); }

// Producing the output "42 the answer is." Logger& ctx0 = CreateLogger("CTX0", "Context Description CTX0"); ctx0.LogDebug () << MyCustomType{42, " the answer is."};

类 ara::log::LogStream 表示格式化日志消息，其内部缓冲区通过流运算符逐步填充数据和元数据。实例通常通过日志记录方法临时获取，并在离开作用域时通过析构函数自动将记录的内容转发给日志记录框架 [SWS_LOG_00262]。对于多行或复用的消息，可以通过 Flush() 显式触发转发 [SWS_LOG_00039]。作为核心边界条件，该类不是线程安全的，并完全禁止复制操作。

上下文

类 ara::log::LogStream 表示自适应日志子系统中的可格式化日志消息。它提供了一个基于消息的缓冲区接口，该接口通过重载的流运算符支持将异构有效负载逐步追加到内部缓冲区。

在常规应用场景中，应用程序进程不会通过显式实例化直接与 LogStream 交互。相反，主日志记录 API（例如通过诸如 LogDebug() 等日志记录方法）会提供已使用所需严重性级别完成初始化的该类临时实例。在默认的单语句作用域（One-Statement-Scope）之外持有 LogStream 对象的唯一预定原因，是跨多行代码组装日志消息。一旦该对象离开其作用域或被显式清空，缓冲区内容就会被传递给日志记录框架以进行进一步处理。

生命周期

LogStream 实例的创建主要作为临时对象通过主日志记录 API 的工厂方法进行。为了实现高效提供，该类将移动构造函数声明为 noexcept [SWS_LOG_00176]。该移动构造函数通常仅声明而不定义，这允许符合 C++14 标准的编译器在从工厂函数返回时利用返回值优化（RVO）[SWS_LOG_00176]。严格排除了实例的复制或移动赋值：复制构造函数 [SWS_LOG_00174]、复制赋值运算符 [SWS_LOG_00175] 以及移动赋值运算符 [SWS_LOG_00177] 均已被删除（=delete）。

生命周期终点由析构函数 ~LogStream() 管理 [SWS_LOG_00262]。当对象离开其作用域（例如在函数块或语句的末尾）时，析构函数在内部确保将缓冲区内容转发到日志记录框架以进行处理 [SWS_LOG_00039]、[SWS_LOG_00262]。

如果在同一作用域内复用 LogStream 实例来处理多条连续消息，则必须调用成员函数 Flush() [SWS_LOG_00039]。此处重要的是，Flush() 并不清空缓冲区，而是将当前数据发送到日志记录框架并立即发起新的消息流 [SWS_LOG_00039]。

在并发性方面，所有成员函数均被指定为非线程安全（[SWS_LOG_00039]、[SWS_LOG_00040]、[SWS_LOG_00129]）。因此，在没有外部同步的情况下，不得由多个线程并行使用 LogStream 实例。

使用路径

典型的日志记录流程包括以下阶段：

  1. 流提供：应用程序进程调用日志记录方法，该方法创建临时 LogStream 实例并通过 RVO 返回 [SWS_LOG_00176]。
  2. 元数据丰富：在数据输入之前或期间，可以通过方法链添加可选属性，包括通过 WithLocation(file, line) [SWS_LOG_00129] 添加源代码位置、通过 WithTag(tag) [SWS_LOG_00132] 添加标签或通过 WithPrivacy(value) [SWS_LOG_00258] 添加机密性级别。这些方法中的每一个都返回对 *this 的引用。
  3. 数据填充：通过重载的运算符 operator<< 将有效负载数据写入内部缓冲区。该接口支持标准类型，如布尔值 [SWS_LOG_00040]、不同宽度的整数 [SWS_LOG_00041]、[SWS_LOG_00044]、浮点数 [SWS_LOG_00049]、字符串和字符串视图 [SWS_LOG_00051]、[SWS_LOG_00062]、通过 core::Span<const core::Byte> [SWS_LOG_00128] 传入的字节序列以及通过 Argument<T> [SWS_LOG_00203] 传入的结构化实参。此外，还可以针对用户定义的类型对该运算符进行扩展。
  4. 传递给框架：离开作用域时，析构函数转发消息 [SWS_LOG_00262]。若实例要保留用于后续消息，则显式调用 Flush() [SWS_LOG_00039]。

时序图：从流创建、元数据和数据填充，直到通过作用域结束或 Flush() 发送的日志记录流程。来源：[SWS_LOG_00039]、[SWS_LOG_00040]、[SWS_LOG_00129]、[SWS_LOG_00176]、[SWS_LOG_00262]

错误场景

该类遵循严格的无异常设计。所有成员函数，包括流运算符（[SWS_LOG_00040] 至 [SWS_LOG_00051]、[SWS_LOG_00062]、[SWS_LOG_00128]、[SWS_LOG_00203]）、WithLocation() [SWS_LOG_00129]、WithTag() [SWS_LOG_00132]、WithPrivacy() [SWS_LOG_00258]、Flush() [SWS_LOG_00039] 以及析构函数 [SWS_LOG_00262]，均被声明为 noexcept 且异常安全（“exception safe”）。

错误条件和使用风险仅限于以下场景：

  • WithPrivacy 中的类型错误：模板 WithPrivacy<T> 强制要求 T 为整数类型或枚举类型。如果使用不符合要求的类型实例化该函数，则程序格式错误（ill-formed）并导致编译错误 [SWS_LOG_00258]。此外，仅使用所传递值的最低有效 8 位，更高位将被忽略 [SWS_LOG_00258]。
  • 缺乏线程安全性：由于 LogStream 被定义为非线程安全（[SWS_LOG_00039]、[SWS_LOG_00040]），在没有外部同步的情况下对同一实例进行并发读写操作大概率会导致数据不一致或缓冲区损坏（Interpretation）。
  • Flush 时的缓冲区接管：由于 Flush() 并不物理清空缓冲区，而只是将当前内容传递给日志记录框架 [SWS_LOG_00039]，因此在复用时必须考虑到在语义上已开始一条新消息。
