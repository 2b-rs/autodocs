为可变加密上下文提供基础接口，用于线程安全地查询算法 ID。

该接口充当未牢固绑定到单个加密对象的可变加密上下文的通用基类。通过纯虚方法 GetAlgId()，它允许线程安全地将算法标识符查询为 ara::core::Result [SWS_CRYPT_20411]。为了防止不希望的状态重复，完全禁止了复制和移动操作 [SWS_CRYPT_41003]。释放通过虚默认析构函数确定性且安全地进行。

上下文

接口 ara::crypto::cryp::CryptoContext 定义了 AUTOSAR Adaptive Platform 加密模块内可变加密上下文（mutable cryptographic contexts）的基本抽象。与静态加密对象不同，此类上下文并不硬性绑定到单个加密对象。相反，它充当各种加密处理上下文的通用基类，这些上下文的内部状态在执行加密操作期间可能会发生变化。

纯虚成员函数 GetAlgId() 充当该基本接口的核心元素。它允许交互伙伴查询当前在上下文中配置的加密算法的标识符 [SWS_CRYPT_20411]。系统中的具体加密计算和转换上下文（例如用于哈希、签名或加密服务）可能派生自 CryptoContext，以提供特定的算法功能。

生命周期

CryptoContext 的生命周期具有明确的标识和严格的所有权特征。为了防止在编译时对上下文状态进行不受控制的复制或不一致的传输，完全禁止了语义复制过程。复制构造函数 [SWS_CRYPT_41003] 和复制赋值运算符 [SWS_CRYPT_30214] 均被显式声明为已删除（=delete）。

同样，接口定义禁止移动上下文：移动构造函数 [SWS_CRYPT_41004] 和移动赋值运算符 [SWS_CRYPT_30215] 均已删除（=delete）。因此，派生类的实例永久保留在其原始内存位置。销毁和资源释放通过定义为 default 和 noexcept 的虚析构函数确定性地发生 [SWS_CRYPT_20401]。这确保了派生上下文对象可以通过指向基接口的指针安全地释放，且不会发生资源泄漏。

关于并发性，针对 GetAlgId() 的要求明确指定了线程安全性 [SWS_CRYPT_20411]。因此，多个线程可以同时且无需外部同步地读取同一上下文的算法标识符。

使用路径

由于 CryptoContext 是纯虚接口，应用程序开发人员无法直接创建实例。特化上下文类的实例通常可能通过加密栈的工厂函数或提供者组件进行实例化，并通过指针或引用提供给调用者。基接口级别的典型使用流程包括以下阶段：

  • 提供：调用者从加密提供者接收对已配置上下文的引用或指针。
  • 算法检查：通过调用 GetAlgId() 查询并评估算法标识符 [SWS_CRYPT_20411]，以确保上下文满足所需规范。
  • 操作和清理：在通过派生接口执行特定于算法的操作后，上下文将通过虚析构函数自动释放 [SWS_CRYPT_20401]。

错误场景

CryptoContext 的错误处理概念遵循 AUTOSAR Adaptive Platform 的通用故障安全设计，并且不使用 C++ 异常。方法 GetAlgId() 被指定为异常安全（exception safe），并在 ara::core::Result<ara::crypto::AlgIdString> 中返回其结果 [SWS_CRYPT_20411]。如果在确定算法 ID 时发生错误，该错误将在 Result 对象的错误通道中传输。

根据规范，GetAlgId() 未定义标准化的错误代码 [SWS_CRYPT_20411]。因此，调用者在访问算法 ID 字符串之前，必须主要检查 Result 是否包含有效值。在拆卸对象时，声明为 noexcept 的虚析构函数可确保在销毁期间不传播异常，并始终可靠地完成清理 [SWS_CRYPT_20401]。
