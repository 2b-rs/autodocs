上下文

类 ara::diag::ServiceValidation 是 AUTOSAR Adaptive 模块 diag 中用于对传入诊断请求进行制造商和供应商特定验证的功能接口元素 [SWS_DM_00772]。根据属性 DiagnosticServiceValidationMapping.category 的建模，通过方法 Validate 进行的验证既可作为制造商检查，也可作为供应商检查，并在 ISO 14229-1 第 8.7 章规定的否定响应码顺序（NRC）框架内执行 [SWS_DM_00772]。

该交互主要涉及三方：

  • Adaptive 应用程序：通过特化虚方法 Validate [SWS_DM_00774] 和 Confirmation [SWS_DM_00775] 来实现具体的验证逻辑。
  • Diagnostic Management (DM)：接收 UDS 请求，在通过 Offer 成功激活后将其转发给实例进行预检查 [SWS_DM_00776]，并通过 Confirmation 报告最终完成情况 [SWS_DM_00775]。
  • 诊断测试仪：发起诊断报文，其原始数据和元信息是检查的对象 [SWS_DM_00774]。

生命周期

ServiceValidation 的实例化通过显式传递一个 ara::core::InstanceSpecifier 来完成，该参数必须指向 DiagnosticServiceValidationInterface 中建模的 PortPrototype [SWS_DM_00772]。构造函数被指定为线程安全的 [SWS_DM_00772]。ServiceValidation 的实例既不能复制也不能移动：复制构造函数 [SWS_DM_01689]、赋值运算符 [SWS_DM_01687]、移动构造函数 [SWS_DM_01690] 和移动赋值运算符 [SWS_DM_01688] 已被显式删除（= delete）。

构造完成后，实例处于未提供状态。通过调用 Offer()，Diagnostic Management 对传入请求的转发将被启用 [SWS_DM_00776]。如果需要暂停或终止处理，调用 StopOffer() 将阻止后续诊断消息的转发 [SWS_DM_00777]。可以通过再次调用 Offer() 重新激活启用状态。最终的析构通过虚析构函数 ~ServiceValidation() [SWS_DM_00773] 完成。

在并发性方面，方法 Offer、StopOffer、Validate、Confirmation 以及析构函数被归类为非线程安全 [SWS_DM_00773] [SWS_DM_00774] [SWS_DM_00775] [SWS_DM_00776] [SWS_DM_00777]。在并发访问时，这些操作的调用必须由应用程序进行同步。

使用路径

保护诊断服务的典型流程分为以下步骤：

  1. 实例化：应用程序创建实例并绑定到建模的端口 [SWS_DM_00772]。
  2. 启用：调用 Offer()。Diagnostic Management 收到指示，将传入的诊断报文转发给该实例 [SWS_DM_00776]。
  3. 验证：对于每个传入的诊断请求，DM 都会调用方法 Validate [SWS_DM_00774]。请求数据（包括服务标识符）作为 ara::core::Span<const std::uint8_t> 传递，上下文通过 MetaInfo 传递。请求数据的有效期将一直持续，直到关联的 Promise 被完成或通过 CancellationHandler 中止处理 [SWS_DM_00774]。
  4. 异步结果：该方法返回一个 ara::core::Future<void> [SWS_DM_00774]。验证成功时，Future 将无错误解析。如果请求不合法，则 Future 将根据 ISO 14229-1 使用来自 DiagUdsNrcErrc 的相应否定响应码（NRC）终止 [SWS_DM_00774]。
  5. 完成确认：诊断请求的处理一旦完全完成，DM 便会调用 Confirmation 以传达总体结果（status）和 metaInfo [SWS_DM_00775]。
  6. 注销：在关闭之前，应用程序调用 StopOffer() [SWS_DM_00777]。解释：在调用 StopOffer() 之后，其 Future 尚未完成的正在进行的验证请求很可能会被 DM 丢弃或中止。

错误场景

错误情况可能出现在不同阶段，并通过特定机制进行指示：

  • 构造与模型违规：如果 InstanceSpecifier 的绑定失败，框架将报告定义的违规 [SWS_DM_00772]：
    • InstanceSpecifierMappingIntegrityViolation：该标识符无法解析，或未指向 PortPrototype。
    • PortInterfaceMappingViolation：PortPrototype 未由 DiagnosticServiceValidationInterface 进行类型化。
    • ProcessMappingViolation：针对该引用，当前运行时进程不存在匹配的已建模进程。
    • InstanceSpecifierAlreadyInUseViolation：InstanceSpecifier 在运行中的进程内已被另一个实例使用。
  • 错误的启用：如果在服务已在提供时调用 Offer()，则调用失败，并在返回值 ara::core::Result<void> 中提供带有回滚语义的错误码 DiagOfferErrc::kAlreadyOffered [SWS_DM_00776]。
  • 验证错误：如果检查发现违反条件（例如先决条件或安全要求不足），则通过 ara::core::Future<void> 中的 DiagUdsNrcErrc 传递该错误 [SWS_DM_00774]。由于 Validate 被声明为 noexcept，因此不得抛出 C++ 异常。
  • 异常安全性：该类的所有方法均被指定为异常安全（exception safe），并带有 noexcept 注解 [SWS_DM_00772] [SWS_DM_00773] [SWS_DM_00774] [SWS_DM_00775] [SWS_DM_00776] [SWS_DM_00777]。错误状态无一例外通过返回类型和平台消息来表示。

<h4>上下文</h4>
<p>类 <code>ara::diag::ServiceValidation</code> 是 AUTOSAR Adaptive 模块 <code>diag</code> 中用于对传入诊断请求进行制造商和供应商特定验证的功能接口元素 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>。根据属性 <code>DiagnosticServiceValidationMapping.category</code> 的建模，通过方法 <code>Validate</code> 进行的验证既可作为制造商检查，也可作为供应商检查，并在 ISO 14229-1 第 8.7 章规定的否定响应码顺序（NRC）框架内执行 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>。</p>
<p>该交互主要涉及三方：</p>
<ul>
<li><strong>Adaptive 应用程序：</strong>通过特化虚方法 <code>Validate</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> 和 <code>Confirmation</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> 来实现具体的验证逻辑。</li>
<li><strong>Diagnostic Management (DM)：</strong>接收 UDS 请求，在通过 <code>Offer</code> 成功激活后将其转发给实例进行预检查 <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>，并通过 <code>Confirmation</code> 报告最终完成情况 <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>。</li>
<li><strong>诊断测试仪：</strong>发起诊断报文，其原始数据和元信息是检查的对象 <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。</li>
</ul>

<h4>生命周期</h4>
<p><code>ServiceValidation</code> 的实例化通过显式传递一个 <code>ara::core::InstanceSpecifier</code> 来完成，该参数必须指向 <code>DiagnosticServiceValidationInterface</code> 中建模的 <code>PortPrototype</code> <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>。构造函数被指定为线程安全的 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>。<code>ServiceValidation</code> 的实例既不能复制也不能移动：复制构造函数 <a class="spec-record-ref" data-req="SWS_DM_01689" href="../spec/record.html?id=SWS_DM_01689">[SWS_DM_01689]</a>、赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_01687" href="../spec/record.html?id=SWS_DM_01687">[SWS_DM_01687]</a>、移动构造函数 <a class="spec-record-ref" data-req="SWS_DM_01690" href="../spec/record.html?id=SWS_DM_01690">[SWS_DM_01690]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_01688" href="../spec/record.html?id=SWS_DM_01688">[SWS_DM_01688]</a> 已被显式删除（<code>= delete</code>）。</p>
<p>构造完成后，实例处于<em>未提供</em>状态。通过调用 <code>Offer()</code>，Diagnostic Management 对传入请求的转发将被启用 <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>。如果需要暂停或终止处理，调用 <code>StopOffer()</code> 将阻止后续诊断消息的转发 <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>。可以通过再次调用 <code>Offer()</code> 重新激活启用状态。最终的析构通过虚析构函数 <code>~ServiceValidation()</code> <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> 完成。</p>
<p>在并发性方面，方法 <code>Offer</code>、<code>StopOffer</code>、<code>Validate</code>、<code>Confirmation</code> 以及析构函数被归类为非线程安全 <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>。在并发访问时，这些操作的调用必须由应用程序进行同步。</p>

<h4>使用路径</h4>
<p>保护诊断服务的典型流程分为以下步骤：</p>
<ol>
<li><strong>实例化：</strong>应用程序创建实例并绑定到建模的端口 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>。</li>
<li><strong>启用：</strong>调用 <code>Offer()</code>。Diagnostic Management 收到指示，将传入的诊断报文转发给该实例 <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>。</li>
<li><strong>验证：</strong>对于每个传入的诊断请求，DM 都会调用方法 <code>Validate</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。请求数据（包括服务标识符）作为 <code>ara::core::Span&lt;const std::uint8_t&gt;</code> 传递，上下文通过 <code>MetaInfo</code> 传递。请求数据的有效期将一直持续，直到关联的 Promise 被完成或通过 CancellationHandler 中止处理 <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。</li>
<li><strong>异步结果：</strong>该方法返回一个 <code>ara::core::Future&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。验证成功时，Future 将无错误解析。如果请求不合法，则 Future 将根据 ISO 14229-1 使用来自 <code>DiagUdsNrcErrc</code> 的相应否定响应码（NRC）终止 <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。</li>
<li><strong>完成确认：</strong>诊断请求的处理一旦完全完成，DM 便会调用 <code>Confirmation</code> 以传达总体结果（<code>status</code>）和 <code>metaInfo</code> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a>。</li>
<li><strong>注销：</strong>在关闭之前，应用程序调用 <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>。解释：在调用 <code>StopOffer()</code> 之后，其 Future 尚未完成的正在进行的验证请求很可能会被 DM 丢弃或中止。</li>
</ol>

<h4>错误场景</h4>
<p>错误情况可能出现在不同阶段，并通过特定机制进行指示：</p>
<ul>
<li><strong>构造与模型违规：</strong>如果 <code>InstanceSpecifier</code> 的绑定失败，框架将报告定义的违规 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a>：
<ul>
<li><code>InstanceSpecifierMappingIntegrityViolation</code>：该标识符无法解析，或未指向 PortPrototype。</li>
<li><code>PortInterfaceMappingViolation</code>：PortPrototype 未由 <code>DiagnosticServiceValidationInterface</code> 进行类型化。</li>
<li><code>ProcessMappingViolation</code>：针对该引用，当前运行时进程不存在匹配的已建模进程。</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>：<code>InstanceSpecifier</code> 在运行中的进程内已被另一个实例使用。</li>
</ul>
</li>
<li><strong>错误的启用：</strong>如果在服务已在提供时调用 <code>Offer()</code>，则调用失败，并在返回值 <code>ara::core::Result&lt;void&gt;</code> 中提供带有回滚语义的错误码 <code>DiagOfferErrc::kAlreadyOffered</code> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a>。</li>
<li><strong>验证错误：</strong>如果检查发现违反条件（例如先决条件或安全要求不足），则通过 <code>ara::core::Future&lt;void&gt;</code> 中的 <code>DiagUdsNrcErrc</code> 传递该错误 <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a>。由于 <code>Validate</code> 被声明为 <code>noexcept</code>，因此不得抛出 C++ 异常。</li>
<li><strong>异常安全性：</strong>该类的所有方法均被指定为异常安全（<code>exception safe</code>），并带有 <code>noexcept</code> 注解 <a class="spec-record-ref" data-req="SWS_DM_00772" href="../spec/record.html?id=SWS_DM_00772">[SWS_DM_00772]</a> <a class="spec-record-ref" data-req="SWS_DM_00773" href="../spec/record.html?id=SWS_DM_00773">[SWS_DM_00773]</a> <a class="spec-record-ref" data-req="SWS_DM_00774" href="../spec/record.html?id=SWS_DM_00774">[SWS_DM_00774]</a> <a class="spec-record-ref" data-req="SWS_DM_00775" href="../spec/record.html?id=SWS_DM_00775">[SWS_DM_00775]</a> <a class="spec-record-ref" data-req="SWS_DM_00776" href="../spec/record.html?id=SWS_DM_00776">[SWS_DM_00776]</a> <a class="spec-record-ref" data-req="SWS_DM_00777" href="../spec/record.html?id=SWS_DM_00777">[SWS_DM_00777]</a>。错误状态无一例外通过返回类型和平台消息来表示。</li>
</ul>
