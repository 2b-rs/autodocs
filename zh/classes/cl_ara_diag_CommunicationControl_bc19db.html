使应用程序能够处理 UDS 服务 0x28 的诊断请求以进行通信控制。

类 ara::diag::CommunicationControl 在 AUTOSAR Adaptive 中用作处理用于切换通信信道的 UDS 服务 0x28 (CommunicationControl) 的接口 [SWS_DM_00808]。在通过 InstanceSpecifier 进行基于模型的实例化之后，Offer() 激活 Diagnostic Manager 对请求的转发，随后这些请求通过 CommCtrlRequest 进行异步处理 [SWS_DM_00806]，[SWS_DM_00809]。作为一个严格的唯一实例，该类排除了复制和移动操作，并要求在退出前通过 StopOffer() 进行注销 [SWS_DM_00810]。

上下文

类 ara::diag::CommunicationControl 定义了在 AUTOSAR Adaptive Platform 中处理 UDS 诊断服务 0x28 (CommunicationControl) 的标准化接口 AUTOSAR_AP_SWS_Diagnostics, 第70页。作为抽象基类，它在 Diagnostic Manager (DM) 与应用程序特定的诊断功能之间进行调解，通过该功能控制在车辆网络中发送或接收特定通信消息。应用程序软件派生自该类并实现纯虚方法 CommCtrlRequest，以接收并执行传入的控制指令 [SWS_DM_00808]。通过引用 DiagnosticComControlInterface 的 PortPrototype 的 ara::core::InstanceSpecifier 完成与 AUTOSAR 系统模型的绑定 [SWS_DM_00806]。

生命周期

通过显式指定 ara::core::InstanceSpecifier 以及并发模型 ConcurrencyType（kConcurrent 或 kNotConcurrent）经由构造函数创建实例 [SWS_DM_00806]。该类具有严格的唯一实例语义，既不可复制也不可移动：复制构造函数 [SWS_DM_01677] 和移动构造函数 [SWS_DM_01678] 以及复制赋值运算符 [SWS_DM_01675] 和移动赋值运算符 [SWS_DM_01676] 均已被删除（=delete）。

创建后，该实例最初保持非活动状态。只有通过调用 Offer()，Diagnostic Manager 才被授权将传入的诊断请求转发给处理程序 [SWS_DM_00809]。相反，StopOffer() 撤销此授权并禁用转发 [SWS_DM_00810]。销毁通过虚析构函数 [SWS_DM_00807] 进行。解释：在销毁对象之前可能需要调用 StopOffer()，以使 Diagnostic Manager 不会维持孤立的转发。 问题 Q-f67e35c9fea508d8 (未决)

在并发性方面，构造函数是线程安全的 [SWS_DM_00806]，而析构函数 [SWS_DM_00807]、Offer() [SWS_DM_00809] 和 StopOffer() [SWS_DM_00810] 不是线程安全的。CommCtrlRequest 的执行是条件线程安全的（conditional）：实现是否必须是线程安全的，由在构造函数中指定的 ConcurrencyType 决定 [SWS_DM_00808]。

使用路径

常规流程包括派生类的实例化、服务注册、诊断请求的异步处理以及最终的注销：

  1. 初始化：应用程序在指定 InstanceSpecifier 和所需的 ConcurrencyType 的情况下实例化处理程序 [SWS_DM_00806]。
  2. 服务提供：通过 Offer() 在 Diagnostic Manager 处激活该服务 [SWS_DM_00809]。
  3. 请求处理：如果收到带有任意子功能的针对服务 0x28 的 UDS 请求，Diagnostic Manager 将调用 CommCtrlRequest [SWS_DM_00808]。参数包括：
    • controlType（ComCtrlRequestParamsType）：包括可选元素在内的所有 UDS 请求参数。
    • metaInfo（const MetaInfo&）：诊断请求的元信息。
    • cancellationHandler（CancellationHandler）：用于通过 IsCanceled() 查询状态以及通过 SetNotifier() 注册取消回调函数。
  4. 反馈：处理异步完成并通过 ara::core::Future<void> 报告结果 [SWS_DM_00808]。
  5. 注销：在关闭或退出之前，应用程序使用 StopOffer() 停止转发 [SWS_DM_00810]。

时序图：从初始化、UDS 0x28 请求处理到注销的典型流程。来源：[SWS_DM_00806]，[SWS_DM_00808]，[SWS_DM_00809]，[SWS_DM_00810]。

错误场景

在构造期间，AUTOSAR 模型中的不一致就可能导致运行时违规（Violations）[SWS_DM_00806]：

  • InstanceSpecifierMappingIntegrityViolation：InstanceSpecifier 无法在可执行文件的上下文中解析，或者未指向 PortPrototype。
  • PortInterfaceMappingViolation：由 DiagnosticComControlInterface 定型的 PortPrototype 未被 DiagnosticServiceGenericMapping 引用。
  • ProcessMappingViolation：存在匹配的实例引用，但不存在与当前进程匹配的建模进程。
  • InstanceSpecifierAlreadyInUseViolation：该标识符已在同一进程中被另一个实例使用。

在运行过程中，如果该服务先前已被提供且仍处于活动状态，则 Offer() 通过返回值 ara::core::Result<void> 报告错误 DiagOfferErrc::kAlreadyOffered [SWS_DM_00809]。如果在 CommCtrlRequest 中由于业务原因无法满足诊断请求，则该方法通过 ara::core::Future<void> 使用 DiagUdsNrcErrc 返回符合 ISO 14229-1 的 Negative Response Code (NRC) [SWS_DM_00808]。

纯虚方法 ara::diag::CommunicationControl::CommCtrlRequest（[SWS_DM_00808]）由 Diagnostic Server 实例调用，以处理 UDS 服务 0x28（CommunicationControl）的诊断请求（[SWS_DM_00865]，SWS Diagnostics §7.3.2.8.10 “Service 0x28 – CommunicationControl”）。包括子功能在内的所有 UDS 请求参数均通过结构体 controlType 捆绑传递（[SWS_DM_00808]）。该调用返回 ara::core::Future<void>，由此处理以异步方式进行。通过参数 cancellationHandler，应用程序可以使用 IsCanceled() 查询取消状态，或通过 SetNotifier() 注册用于会话取消的回调（[SWS_DM_00808]）。

如果应用程序无错误地完成处理，Diagnostic Server 将发送肯定的 UDS 响应（[SWS_DM_00199]）。如果发生错误，必须通过 ara::diag::DiagUdsNrcErrc 将其作为符合 ISO 14229-1 的相应否定响应码（NRC）上报（[SWS_DM_00808]）；随后服务器将使用此错误码对此服务请求进行否定响应（[SWS_DM_00866]）。对于未配置的子功能，服务器预先就会使用 NRC 0x12（kSubFunctionNotSupported）予以拒绝（[SWS_DM_00252]）。

该方法声明为 noexcept 且是异常安全的（[SWS_DM_00808]，SWS Diagnostics §8.7.1.1.3.1 “CommCtrlRequest”）。其线程安全性是有条件的：该函数是否必须以线程安全的方式实现，由该实例的构造函数参数 ConcurrencyType 决定（[SWS_DM_00808]）。在 future 被解析之前，通信模式的实际切换可能在后台异步进行。 问题 Q-8a8e1bd2585fa859 (未决)

                  使用
                  

                  类 ara::diag::CommunicationControl（头文件 #include "ara/diag/communication_control.h"）的方法 Offer 允许 Diagnostic Management (DM) 将传入的通信控制诊断请求转发给提供服务的处理器实例 [SWS_DM_00809]。该调用不带参数并返回类型 ara::core::Result<void> [SWS_DM_00809]。由于未使用 ara::core::Future 或回调机制，因此执行应理解为同步的。
                  


                  错误处理
                  

                  如果成功，该函数返回空的 ara::core::Result。如果此前已针对该实例提供了服务，则调用失败并返回带有回滚语义的错误代码 DiagOfferErrc::kAlreadyOffered [SWS_DM_00809]。该错误状态对应于 Adaptive AUTOSAR 中诊断提供的统一错误处理，例如在 DiagErrc [SWS_DM_00514] 以及 DiagReportingErrc [SWS_DM_00560] 中所指定的。
                  


                  并发性与限制
                  

                  该函数被声明为 noexcept 且异常安全（exception safe），但明确为非线程安全（not thread-safe）[SWS_DM_00809]。因此，对同一实例的调用必须由调用应用程序进行同步，以防止注册时的竞态条件。
                  


                  相互作用
                  

                  通过 Offer 实现的注册模式是 Diagnostic Management 中的核心惯用法，并在各个处理器之间保持一致使用，例如例程 [SWS_DM_00557]、通用 UDS 服务 [SWS_DM_00619]、安全访问接口 [SWS_DM_00766] 以及上传和下载服务 [SWS_DM_00792] [SWS_DM_00802]。在此需要注意与通信基础设施的区分：正如 AUTOSAR_AP_SWS_Diagnostics §7.3.4.1.2 “Monitors” 中所强调的，这是一个特定于诊断的实现，切勿与 ara::com 混淆。
