模板类 ara::core::Array 用作 T 类型元素的固定大小顺序容器，并针对 AUTOSAR Adaptive Platform 应用程序适配了 std::array 的行为。调用方使用固定数量的元素初始化该容器，通过诸如 fill() 等方法操作内容，并可选择通过 operator[] 进行无检查访问或通过 at() 进行范围检查访问 [SWS_CORE_01273]。作为与安全相关的边界条件，at() 发生越界时会触发特定违规 IsoStdOutOfRangeViolation 而非 std::out_of_range，而在空实例上调用 front() 或 back() 在编译期即会失败 [SWS_CORE_01267]。

上下文

模板类 ara::core::Array 封装了一个大小在编译期静态确定（N）、用于 T 类型元素的顺序容器。它在 AUTOSAR Adaptive Platform 的模块 core 中实现了标准化类型 std::array，并提供了针对连续内存块的类型安全抽象。通过提供标准化类型别名，如 value_type（[SWS_CORE_01216]）、size_type（[SWS_CORE_01214]）、difference_type（[SWS_CORE_01215]）以及指针类型（[SWS_CORE_01217]、[SWS_CORE_01218]）和引用类型（[SWS_CORE_01210]、[SWS_CORE_01211]），该类可作为通用 C++ 算法与平台内部数据流的可互操作交互伙伴。

生命周期

Array 实例的创建与销毁遵循聚合类型和值类型的标准规则：使用 ISO C++ 标准隐式声明的特殊成员函数，且不进行单独的重新声明。Array 直接在相同的内存区域中内联持有其元素。因此，所包含元素的生命周期与外层 Array 对象的生命周期不可分割地绑定在一起；推测不会在自由存储区（堆）上发生动态分配，从而确保了确定性的时间与内存行为。

该容器始终处于有效状态，并精确管理 N 个元素。Array 是否能够容纳元素，或者是否存在 N = 0 的特殊情况，可以通过 empty()（[SWS_CORE_01264]）、size()（[SWS_CORE_01262]）以及 max_size()（[SWS_CORE_01263]）进行评估。关于并发性，应该适用的是：并发读访问无需同步即可确保安全，而并行写修改则需要调用方进行外部协调。

使用路径

在典型用例中，ara::core::Array 会经历初始化、元素填充、随机或顺序访问以及适时的内容交换序列：

  • 初始化与填充：整个数据缓冲区可通过 fill()（[SWS_CORE_01241]）统一填充预设值。
  • 随机访问：为了实现高性能访问，提供了未经检查的下标运算符 operator[]（[SWS_CORE_01265]、[SWS_CORE_01266]）。如果需要进行范围检查，则使用 at()（[SWS_CORE_01273]、[SWS_CORE_01274]）。
  • 边界元素：通过 front()（[SWS_CORE_01267]、[SWS_CORE_01268]）和 back()（[SWS_CORE_01269]、[SWS_CORE_01270]）直接访问第一个和最后一个元素。
  • 迭代：容器的遍历通过 begin() 和 end()（[SWS_CORE_01250]、[SWS_CORE_01251]、[SWS_CORE_01252]、[SWS_CORE_01253]）正向进行，或者通过常量迭代器如 cbegin() 和 cend()（[SWS_CORE_01258]、[SWS_CORE_01259]）进行。迭代器类型被定义为基本指针 T* 或 const T*（[SWS_CORE_01212]、[SWS_CORE_01213]）。对于反向遍历，提供了 rbegin()、rend()、crbegin() 和 crend()（[SWS_CORE_01254]、[SWS_CORE_01255]、[SWS_CORE_01256]、[SWS_CORE_01257]、[SWS_CORE_01260]、[SWS_CORE_01261]、[SWS_CORE_01219]、[SWS_CORE_01220]）。
  • 指针访问与交换：底层内存区域可通过 data()（[SWS_CORE_01271]、[SWS_CORE_01272]）作为指针传递。两个尺寸相同的 Array 可以使用 swap()（[SWS_CORE_01242]）进行交换。

错误场景

规范针对边界和错误情况定义了严格的前置条件和后置条件：

  • 带索引访问时的范围违规：在 at() 中，如果索引 n 超出 Array 边界（n >= size()），则会触发 IsoStdOutOfRangeViolation，而非 C++ 标准异常 std::out_of_range（[SWS_CORE_01273]、[SWS_CORE_01274]）。两个重载均被声明为 noexcept。
  • 访问空实例：在空 Array（empty() == true，即 N = 0）上调用 front() 或 back() 必然导致编译期错误（Compile-Time Error）（[SWS_CORE_01267]、[SWS_CORE_01268]、[SWS_CORE_01269]、[SWS_CORE_01270]）。
  • 迭代器的未定义行为：在空 Array 上解引用由 begin() 返回的迭代器属于未定义行为（[SWS_CORE_01250]、[SWS_CORE_01251]）。
  • 指针获取的特殊情况：若 Array 的大小为 0，则成员函数 data() 必须返回 nullptr（[SWS_CORE_01271]、[SWS_CORE_01272]）。
  • 有条件的异常安全性：操作 swap() 仅在满足类型相关条件 ara::core::is_nothrow_swappable<T>::value 时才是 noexcept（[SWS_CORE_01242]）。相应地，fill() 的 noexcept 特性由 std::is_nothrow_copy_assignable<T>::value 决定（[SWS_CORE_01241]）。
