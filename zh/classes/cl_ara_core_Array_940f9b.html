上下文

模板类 ara::core::Array 在 Adaptive Platform 中提供了对 std::array 符合标准的适配。它封装了一个具有类型为 T 的元素的固定大小数组 N，并避免了运行时的动态内存分配。作为基础的顺序容器，ara::core::Array 为功能集群以及 AUTOSAR 应用程序提供了一种类型安全的数据结构，用于传递具有静态已知元素数量的有效负载数据。

该接口紧密遵循 C++ 标准的规范，但针对 AUTOSAR 运行时环境定义了专门的调整。这包括用于索引、迭代器和内存查询的类型化接口。用于引用和指针（[SWS_CORE_01210]、[SWS_CORE_01211]、[SWS_CORE_01217]、[SWS_CORE_01218]）、索引（[SWS_CORE_01214]、[SWS_CORE_01215]）以及正向和反向迭代器（[SWS_CORE_01212]、[SWS_CORE_01213]、[SWS_CORE_01219]、[SWS_CORE_01220]）的类型别名确保了与标准算法和泛型接口的互操作性。

生命周期

作为聚合类型，ara::core::Array 将所包含的元素直接绑定到其自身的内存表示中。根据规范，隐式声明的特殊成员函数（如默认构造函数、复制构造函数和移动构造函数以及析构函数）不会被重新显式声明，而是遵循 C++ 数组的标准行为。因此，所有 N 个元素的生命周期与容器实例的生命周期不可分割地绑定在一起。

尺寸在编译时通过模板参数 N 确定。诸如 size()（[SWS_CORE_01262]）、max_size()（[SWS_CORE_01263]）和 empty()（[SWS_CORE_01264]）等大小查询方法被声明为 constexpr 和 noexcept。两个相同尺寸实例的内容交换通过 swap()（[SWS_CORE_01242]）进行。swap() 的异常安全性在条件上取决于元素类型 T 是否通过 ara::core::is_nothrow_swappable<T>::value 被标识为不抛出异常（[SWS_CORE_01242]）。在并发性方面，ara::core::Array 不提供内部同步；对同一实例的并发写入访问必须由应用程序端进行保护（解释）。

使用路径

ara::core::Array 的典型用法分为初始化、顺序或随机数据处理以及传递给底层接口：

  • 初始化与填充：该容器可进行初始赋值，或通过方法 fill()（[SWS_CORE_01241]）使用某个值的副本进行同质写入。只要元素类型是赋值安全的（std::is_nothrow_copy_assignable<T>::value），该操作就是 noexcept。
  • 随机与直接元素访问：为实现无运行时检查的高性能访问，提供了 operator[]（[SWS_CORE_01265]、[SWS_CORE_01266]）。边界元素可通过 front()（[SWS_CORE_01267]、[SWS_CORE_01268]）和 back()（[SWS_CORE_01269]、[SWS_CORE_01270]）引用。
  • 符合迭代器的处理：算法可以通过前向迭代器（begin() / end()，依据 [SWS_CORE_01250]、[SWS_CORE_01251]、[SWS_CORE_01252]、[SWS_CORE_01253]）、常量迭代器（cbegin() / cend()，依据 [SWS_CORE_01258]、[SWS_CORE_01259]）或反向迭代器（rbegin() / rend() / crbegin() / crend()，依据 [SWS_CORE_01254]、[SWS_CORE_01255]、[SWS_CORE_01256]、[SWS_CORE_01257]、[SWS_CORE_01260]、[SWS_CORE_01261]）遍历序列。
  • C-API 桥接：通过方法 data()（[SWS_CORE_01271]、[SWS_CORE_01272]）提供指向底层连续内存段的直接指针，例如用于传递给驱动程序或序列化例程。

错误场景

在错误处理和边界值保护方面，ara::core::Array 在关键要点上偏离了 ISO-C++ 标准，以遵循 AUTOSAR 特定的异常安全性准则：

front() / back() empty() == true (d. h. N == 0) 在空数组上调用必然导致编译时错误（Compile-Time Error）（[SWS_CORE_01267]、[SWS_CORE_01268]、[SWS_CORE_01269]、[SWS_CORE_01270]）。

<h4>上下文</h4>
<p>模板类 <code>ara::core::Array</code> 在 Adaptive Platform 中提供了对 <code>std::array</code> 符合标准的适配。它封装了一个具有类型为 <code>T</code> 的元素的固定大小数组 <code>N</code>，并避免了运行时的动态内存分配。作为基础的顺序容器，<code>ara::core::Array</code> 为功能集群以及 AUTOSAR 应用程序提供了一种类型安全的数据结构，用于传递具有静态已知元素数量的有效负载数据。</p>
<p>该接口紧密遵循 C++ 标准的规范，但针对 AUTOSAR 运行时环境定义了专门的调整。这包括用于索引、迭代器和内存查询的类型化接口。用于引用和指针（<a class="spec-record-ref" data-req="SWS_CORE_01210" href="../spec/record.html?id=SWS_CORE_01210">[SWS_CORE_01210]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01211" href="../spec/record.html?id=SWS_CORE_01211">[SWS_CORE_01211]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01217" href="../spec/record.html?id=SWS_CORE_01217">[SWS_CORE_01217]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01218" href="../spec/record.html?id=SWS_CORE_01218">[SWS_CORE_01218]</a>）、索引（<a class="spec-record-ref" data-req="SWS_CORE_01214" href="../spec/record.html?id=SWS_CORE_01214">[SWS_CORE_01214]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01215" href="../spec/record.html?id=SWS_CORE_01215">[SWS_CORE_01215]</a>）以及正向和反向迭代器（<a class="spec-record-ref" data-req="SWS_CORE_01212" href="../spec/record.html?id=SWS_CORE_01212">[SWS_CORE_01212]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01213" href="../spec/record.html?id=SWS_CORE_01213">[SWS_CORE_01213]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01219" href="../spec/record.html?id=SWS_CORE_01219">[SWS_CORE_01219]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01220" href="../spec/record.html?id=SWS_CORE_01220">[SWS_CORE_01220]</a>）的类型别名确保了与标准算法和泛型接口的互操作性。</p>

<h4>生命周期</h4>
<p>作为聚合类型，<code>ara::core::Array</code> 将所包含的元素直接绑定到其自身的内存表示中。根据规范，隐式声明的特殊成员函数（如默认构造函数、复制构造函数和移动构造函数以及析构函数）不会被重新显式声明，而是遵循 C++ 数组的标准行为。因此，所有 <code>N</code> 个元素的生命周期与容器实例的生命周期不可分割地绑定在一起。</p>
<p>尺寸在编译时通过模板参数 <code>N</code> 确定。诸如 <code>size()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01262" href="../spec/record.html?id=SWS_CORE_01262">[SWS_CORE_01262]</a>）、<code>max_size()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01263" href="../spec/record.html?id=SWS_CORE_01263">[SWS_CORE_01263]</a>）和 <code>empty()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01264" href="../spec/record.html?id=SWS_CORE_01264">[SWS_CORE_01264]</a>）等大小查询方法被声明为 <code>constexpr</code> 和 <code>noexcept</code>。两个相同尺寸实例的内容交换通过 <code>swap()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>）进行。<code>swap()</code> 的异常安全性在条件上取决于元素类型 <code>T</code> 是否通过 <code>ara::core::is_nothrow_swappable&lt;T&gt;::value</code> 被标识为不抛出异常（<a class="spec-record-ref" data-req="SWS_CORE_01242" href="../spec/record.html?id=SWS_CORE_01242">[SWS_CORE_01242]</a>）。在并发性方面，<code>ara::core::Array</code> 不提供内部同步；对同一实例的并发写入访问必须由应用程序端进行保护（解释）。</p>

<h4>使用路径</h4>
<p><code>ara::core::Array</code> 的典型用法分为初始化、顺序或随机数据处理以及传递给底层接口：</p>
<ul>
<li><strong>初始化与填充：</strong>该容器可进行初始赋值，或通过方法 <code>fill()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01241" href="../spec/record.html?id=SWS_CORE_01241">[SWS_CORE_01241]</a>）使用某个值的副本进行同质写入。只要元素类型是赋值安全的（<code>std::is_nothrow_copy_assignable&lt;T&gt;::value</code>），该操作就是 <code>noexcept</code>。</li>
<li><strong>随机与直接元素访问：</strong>为实现无运行时检查的高性能访问，提供了 <code>operator[]</code>（<a class="spec-record-ref" data-req="SWS_CORE_01265" href="../spec/record.html?id=SWS_CORE_01265">[SWS_CORE_01265]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01266" href="../spec/record.html?id=SWS_CORE_01266">[SWS_CORE_01266]</a>）。边界元素可通过 <code>front()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01267" href="../spec/record.html?id=SWS_CORE_01267">[SWS_CORE_01267]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01268" href="../spec/record.html?id=SWS_CORE_01268">[SWS_CORE_01268]</a>）和 <code>back()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01269" href="../spec/record.html?id=SWS_CORE_01269">[SWS_CORE_01269]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01270" href="../spec/record.html?id=SWS_CORE_01270">[SWS_CORE_01270]</a>）引用。</li>
<li><strong>符合迭代器的处理：</strong>算法可以通过前向迭代器（<code>begin()</code> / <code>end()</code>，依据 <a class="spec-record-ref" data-req="SWS_CORE_01250" href="../spec/record.html?id=SWS_CORE_01250">[SWS_CORE_01250]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01251" href="../spec/record.html?id=SWS_CORE_01251">[SWS_CORE_01251]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01252" href="../spec/record.html?id=SWS_CORE_01252">[SWS_CORE_01252]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01253" href="../spec/record.html?id=SWS_CORE_01253">[SWS_CORE_01253]</a>）、常量迭代器（<code>cbegin()</code> / <code>cend()</code>，依据 <a class="spec-record-ref" data-req="SWS_CORE_01258" href="../spec/record.html?id=SWS_CORE_01258">[SWS_CORE_01258]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01259" href="../spec/record.html?id=SWS_CORE_01259">[SWS_CORE_01259]</a>）或反向迭代器（<code>rbegin()</code> / <code>rend()</code> / <code>crbegin()</code> / <code>crend()</code>，依据 <a class="spec-record-ref" data-req="SWS_CORE_01254" href="../spec/record.html?id=SWS_CORE_01254">[SWS_CORE_01254]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01255" href="../spec/record.html?id=SWS_CORE_01255">[SWS_CORE_01255]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01256" href="../spec/record.html?id=SWS_CORE_01256">[SWS_CORE_01256]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01257" href="../spec/record.html?id=SWS_CORE_01257">[SWS_CORE_01257]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01260" href="../spec/record.html?id=SWS_CORE_01260">[SWS_CORE_01260]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01261" href="../spec/record.html?id=SWS_CORE_01261">[SWS_CORE_01261]</a>）遍历序列。</li>
<li><strong>C-API 桥接：</strong>通过方法 <code>data()</code>（<a class="spec-record-ref" data-req="SWS_CORE_01271" href="../spec/record.html?id=SWS_CORE_01271">[SWS_CORE_01271]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01272" href="../spec/record.html?id=SWS_CORE_01272">[SWS_CORE_01272]</a>）提供指向底层连续内存段的直接指针，例如用于传递给驱动程序或序列化例程。</li>
</ul>
