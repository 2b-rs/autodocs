使服务 Skeleton 能够发送触发信号并监控订阅者状态。

类 <SI-Namespace>::skeleton::triggers::<Trigger> 使服务器应用程序能够通过 Communication Management（[SWS_CM_00721]）向订阅 Client 发送触发信号。为了进行流程控制，可以监控订阅者状态并注册通知处理程序（[SWS_CM_01109]，[SWS_CM_01110]）。通过 Send() 触发需要已提供的服务 Skeleton，并针对违反最小发送间隔或网络错误的情况通过相应的错误代码进行确认（[SWS_CM_00721]，[SWS_CM_10517]）。

上下文

模板类 <SI-Namespace>::skeleton::triggers::<Trigger> 表示在 ServiceInterface 内以 trigger 角色定义的触发器的服务端接口。作为服务骨架（Skeleton）的组成部分，该类用于服务实例向整个系统中的订阅 Client 应用程序发送异步通知或触发信号。触发器与常规事件的区别在于，它主要充当没有复杂有效负载的纯信号指示事件，如 EXP_ARAComAPI §3 “Trigger::Send” 和 SWS_CommunicationManagement §7.2.2.1.4 “Handling Triggers” 中的归类所述。交互伙伴包括提供服务的服务器应用程序、中间件 Communication Management（ara::com）以及通过网络连接的 Subscriber Client。

生命周期

触发器对象的实例化通常作为相应 ServiceInterface 的 Skeleton 实例的组成部分执行。在主动使用之前，必须通过 Communication Management 提供 Skeleton；如果尝试在此之前触发 Trigger，则传输将失败（[SWS_CM_00721]）。该类通过 ara::com::SubscriptionState 管理订阅者的订阅状态，该状态可随时通过 GetSubscriptionState() 查询（[SWS_CM_01109]）。为了进行异步状态监控，可以通过 SetSubscriptionStateChangeHandler() 注册回调（[SWS_CM_01110]）。对于并发架构，存在一个接受用户定义的 Executor 的重载，以便在所需的线程或任务上下文中执行通知（[SWS_CM_01111]）。可以通过 UnsetSubscriptionStateChangeHandler() 再次取消注册（[SWS_CM_01112]）。该类的所有方法均提供异常安全保证 noexcept（exception safe）。

使用路径

使用触发器的典型流程包括观察订阅状态以及实际向所有活动订阅者触发传输：

  • 处理程序注册：服务应用程序可选地通过 SetSubscriptionStateChangeHandler() 注册状态处理程序（[SWS_CM_01110]，[SWS_CM_01111]），以便获知新加入的订阅者。
  • 状态检查：服务器使用 GetSubscriptionState() 检查是否存在至少一个活动的 Subscriber（[SWS_CM_01109]），根据 [SWS_CM_10518]，这是发送请求的前提条件。
  • 发送触发器：发送通过调用 Send() 发起（[SWS_CM_00721]，EXP_ARAComAPI §3 “Trigger::Send”），随后 Communication Management 将信号分发给所有已订阅的应用程序。
  • 注销：在关机时或不再需要状态通知时，调用 UnsetSubscriptionStateChangeHandler()（[SWS_CM_01112]）。

时序图：带有订阅监控的触发器传输典型流程。来源：[SWS_CM_01110]，[SWS_CM_01109]，[SWS_CM_00721]，SWS_CommunicationManagement §7.2.2.1.4。

错误场景

方法 Send() 返回一个 ara::core::Result<void>，可能的传输和配置错误将通过它进行传递（[SWS_CM_00721]）：

  • ComErrc::kServiceNotOffered：当服务实例尚未通过 OfferService() 提供时发生（[SWS_CM_00721]）。
  • ComErrc::kMinimumSendIntervalViolationError：如果在连续传输之间低于配置的最小发送间隔（minimumSendInterval），则返回此项（[SWS_CM_00721]）。
  • ComErrc::kCommunicationFailure：如果触发器的发送由于底层网络错误而在本地失败，则报告此项（[SWS_CM_10517]）。
  • 无效的处理程序（InvalidHandlerViolation）：向 SetSubscriptionStateChangeHandler() 传递不存在或空的可调用对象（Callable）构成对 API 契约条件的违反（[SWS_CM_01110]，[SWS_CM_01111]）。

                  用法与语义：该接口具有签名 void UnsetSubscriptionStateChangeHandler() noexcept，不期望任何传入参数，且没有返回值（[SWS_CM_01112]）。根据规范，它被归类为异常安全（exception safe）（[SWS_CM_01112]）。此调用未预设错误代码或特定的报告机制（DET/DEM）。
                  


                  协作与生命周期：一旦相应触发器的订阅状态发生改变，通过 [SWS_CM_01112] 移除的回调就会由 Communication Management 调用（[SWS_CM_01101]、AUTOSAR_AP_SWS_CommunicationManagement §7.5.15 “Query Service Trigger Subscription State on Skeleton side”）。例如，当活动订阅数量大于零时，以状态 kSubscribed 发生（[SWS_CM_01102]），或以 kNotSubscribed 发生（[SWS_CM_01103]）。该处理程序允许在运行时被覆盖（[SWS_CM_01101]）；调用 UnsetSubscriptionStateChangeHandler 将取消该注册。
                  


                  并发性与相关接口：关于并发性，注销应同步进行，从而在函数调用返回后不再向先前注册的处理程序传递任何进一步的状态通知。类似的注销函数在 Skeleton 端针对事件（[SWS_CM_12010]）以及在 Proxy 端针对事件（[SWS_CM_00334]）、触发器（[SWS_CM_01108]）和字段（[SWS_CM_11609]、AUTOSAR_AP_EXP_ARAComAPI §5.3.1 “Proxy Class API’s”）进行了规范。
