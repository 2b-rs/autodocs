类 ara::per::ReadAccessor

[SWS_PER_00342] Upstream: RS_PER_00004, RS_AP_00122, RS_AP_00146

class ReadAccessor :            public virtual FileAccessor {...};

ReadAccessor is used to read file data. It provides binary and text mode methods for checking or getting the current byte/character (PeekByte/PeekChar, GetByte/GetChar) methods for reading a section of a binary/text file (Read Binary/ReadText), a method to read a line of text (ReadLine).

Kontext

Die Klasse ara::per::ReadAccessor dient innerhalb des Moduls per (Persistency) der Adaptive Platform dem sequentiellen Lesen von persistenten Dateiinhalten. Sie erbt virtuell von FileAccessor und stellt Lesezugriffe sowohl im Binärmodus als auch im Textmodus bereit. Über diese Abstraktion greifen Anwendungen auf gespeicherte Daten zu, ohne die physische Ablage direkt verwalten zu müssen. Die Schnittstelle bietet granulare Operationen zur Inspektion einzelner Zeichen oder Bytes sowie Methoden zum blockweisen oder vollständigen Auslesen von Inhalten und Zeilen.

Lebenszyklus

Der Lebenszyklus einer Instanz von ara::per::ReadAccessor unterliegt strikten Vorgaben bezüglich Erzeugung und Ressourcenmanagement:

  • Erzeugung: Der Standardkonstruktor ist gemäß [SWS_PER_00461] explizit gelöscht (delete). Eine direkte parameterlose Initialisierung durch die Anwendung ist damit ausgeschlossen. Interpretation: Eine Instanz dürfte folglich über übergeordnete Mechanismen des Persistenz-Dateizugriffs erzeugt und an den Aufrufer übergeben werden.
  • Zerstörung: Der Destruktor ~ReadAccessor() ist virtuell deklariert, mit override versehen und als noexcept definiert [SWS_PER_00417]. Bei der Zerstörung des Objekts werden die zugrunde liegenden Lese-Deskriptoren freigegeben.
  • Nebenläufigkeit und Ausnahmesicherheit: Sämtliche Methoden der Klasse sind als not thread-safe spezifiziert (z. B. [SWS_PER_00417], [SWS_PER_00419]). Der gleichzeitige Zugriff mehrerer Threads auf dieselbe Instanz erfordert daher eine externe Synchronisation. Gleichzeitig sind alle Leseoperationen ausnahmesicher (exception safe) und als noexcept deklariert; Fehler werden über den Rückgabetyp ara::core::Result transportiert.

Nutzungspfad

Die Nutzung von ara::per::ReadAccessor unterscheidet zwischen inspektiven Operationen (ohne Positionsänderung) und konsumierenden Leseoperationen (mit Fortschreiten des Dateizeigers):

  • Inspektion (Peeking): Mittels PeekByte() [SWS_PER_00418] oder PeekChar() [SWS_PER_00167] kann das an der aktuellen Position anliegende Byte bzw. Zeichen abgefragt werden, ohne dass die Leseposition verändert wird. Beide Methoden sind als const deklariert.
  • Schrittweises Lesen: Über GetByte() [SWS_PER_00419] bzw. GetChar() [SWS_PER_00168] wird das aktuelle Element gelesen und der interne Zeiger um eine Position weitergerückt.
  • Abschnittsweises Lesen (Binärmodus): Mit ReadBinary(std::uint64_t n) [SWS_PER_00422] wird eine definierte Anzahl an Bytes in einen ara::core::Vector<ara::core::Byte> eingelesen. Wird das Dateiende vor Erreichen von n erreicht, enthält der Vektor weniger Bytes als angefordert. Die parameterlose Überladung ReadBinary() [SWS_PER_00421] liest alle verbleibenden Bytes bis zum Dateiende ein.
  • Textmodus und Zeilenverarbeitung: Mittels ReadText(std::uint64_t n) [SWS_PER_00165] oder ReadText() [SWS_PER_00420] werden Zeichenketten in einen ara::core::String gelesen. Für strukturierte Textdateien erlaubt ReadLine(char delimiter = '\n') [SWS_PER_00119] das zeilenweise Auslesen bis zum Trennzeichen. Das Trennzeichen ist im resultierenden String nicht enthalten. Falls die Leseposition innerhalb eines Unicode-Codepoints liegt, kann der zurückgegebene Text unvollständige Codepoints aufweisen.

Fehlerszenarien

Alle Lese- und Inspektionsmethoden geben ein ara::core::Result zurück. Bei einem aufgetretenen Fehler greift eine Rollback-Semantik: Die aktuelle Leseposition der Datei wird im Fehlerfall nicht verändert (spezifiziert u. a. in [SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00421], [SWS_PER_00119]). Folgende Fehlerzustände aus dem Fehlerbereich PerErrc sind spezifiziert:

  • PerErrc::kEof: Wird zurückgegeben, wenn sich die aktuelle Leseposition bereits am Ende der Datei befindet oder die Datei leer ist ([SWS_PER_00419], [SWS_PER_00168], [SWS_PER_00418], [SWS_PER_00167], [SWS_PER_00421], [SWS_PER_00422], [SWS_PER_00119], [SWS_PER_00165], [SWS_PER_00420]).
  • PerErrc::kPhysicalStorageFailure: Tritt auf, wenn der physische Lesezugriff auf das Speichermedium fehlschlägt ([SWS_PER_00420]).
  • PerErrc::kValidationFailed: Zeigt an, dass die Integrität oder Validität der gespeicherten Daten nicht gewährleistet werden kann ([SWS_PER_00419]).
  • PerErrc::kEncryptionFailed: Wird zurückgegeben, wenn die Entschlüsselung der gespeicherten Nutzdaten fehlschlägt ([SWS_PER_00419]).
  • PerErrc::kAuthenticationFailed: Tritt auf, wenn die Überprüfung des Message Authentication Code (MAC) der gespeicherten Daten fehlschlägt ([SWS_PER_00419]).

ReadLine 函数

Reads a complete line of characters into a String, advancing the current position accordingly. The end of the line is demarcated by the delimiter, or by "\\n" (ASCII 0x0a) if that parameter is omitted. The delimiter itself is not included in the returned String. Only Unicode code points with one character (code unit) can be used as delimiters. The returned string may start with an incomplete Unicode code point in case the current read position is in the middle of a code point. If the end of the file is reached, the remaining characters are returned and the current position is set to the end of the file. In case of an error, the current position is not changed.

ReadText 函数 2

Reads a number of characters into a String, starting from the current position. The returned string may start and/or end with incomplete Unicode code points in case the current read position and/or the last read character (code unit) is in the middle of a code point. The current position is advanced accordingly. If the end of the file is reached, the number of returned characters can be less than the requested number, and the current position is set to the end of the file. In case of an error, the current position is not changed.

<h4>Kontext</h4>
<p>
Die Klasse <code>ara::per::ReadAccessor</code> dient innerhalb des Moduls <code>per</code> (Persistency) der Adaptive Platform dem sequentiellen Lesen von persistenten Dateiinhalten. Sie erbt virtuell von <code>FileAccessor</code> und stellt Lesezugriffe sowohl im Binärmodus als auch im Textmodus bereit. Über diese Abstraktion greifen Anwendungen auf gespeicherte Daten zu, ohne die physische Ablage direkt verwalten zu müssen. Die Schnittstelle bietet granulare Operationen zur Inspektion einzelner Zeichen oder Bytes sowie Methoden zum blockweisen oder vollständigen Auslesen von Inhalten und Zeilen.
</p>

<h4>Lebenszyklus</h4>
<p>
Der Lebenszyklus einer Instanz von <code>ara::per::ReadAccessor</code> unterliegt strikten Vorgaben bezüglich Erzeugung und Ressourcenmanagement:
</p>
<ul>
<li><strong>Erzeugung:</strong> Der Standardkonstruktor ist gemäß <a class="spec-record-ref" data-req="SWS_PER_00461" href="../spec/record.html?id=SWS_PER_00461">[SWS_PER_00461]</a> explizit gelöscht (<code>delete</code>). Eine direkte parameterlose Initialisierung durch die Anwendung ist damit ausgeschlossen. Interpretation: Eine Instanz dürfte folglich über übergeordnete Mechanismen des Persistenz-Dateizugriffs erzeugt und an den Aufrufer übergeben werden.</li>
<li><strong>Zerstörung:</strong> Der Destruktor <code>~ReadAccessor()</code> ist virtuell deklariert, mit <code>override</code> versehen und als <code>noexcept</code> definiert <a class="spec-record-ref" data-req="SWS_PER_00417" href="../spec/record.html?id=SWS_PER_00417">[SWS_PER_00417]</a>. Bei der Zerstörung des Objekts werden die zugrunde liegenden Lese-Deskriptoren freigegeben.</li>
<li><strong>Nebenläufigkeit und Ausnahmesicherheit:</strong> Sämtliche Methoden der Klasse sind als <code>not thread-safe</code> spezifiziert (z.&nbsp;B. <a class="spec-record-ref" data-req="SWS_PER_00417" href="../spec/record.html?id=SWS_PER_00417">[SWS_PER_00417]</a>, <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a>). Der gleichzeitige Zugriff mehrerer Threads auf dieselbe Instanz erfordert daher eine externe Synchronisation. Gleichzeitig sind alle Leseoperationen ausnahmesicher (<code>exception safe</code>) und als <code>noexcept</code> deklariert; Fehler werden über den Rückgabetyp <code>ara::core::Result</code> transportiert.</li>
</ul>

<h4>Nutzungspfad</h4>
<p>
Die Nutzung von <code>ara::per::ReadAccessor</code> unterscheidet zwischen inspektiven Operationen (ohne Positionsänderung) und konsumierenden Leseoperationen (mit Fortschreiten des Dateizeigers):
</p>
<ul>
<li><strong>Inspektion (Peeking):</strong> Mittels <code>PeekByte()</code> <a class="spec-record-ref" data-req="SWS_PER_00418" href="../spec/record.html?id=SWS_PER_00418">[SWS_PER_00418]</a> oder <code>PeekChar()</code> <a class="spec-record-ref" data-req="SWS_PER_00167" href="../spec/record.html?id=SWS_PER_00167">[SWS_PER_00167]</a> kann das an der aktuellen Position anliegende Byte bzw. Zeichen abgefragt werden, ohne dass die Leseposition verändert wird. Beide Methoden sind als <code>const</code> deklariert.</li>
<li><strong>Schrittweises Lesen:</strong> Über <code>GetByte()</code> <a class="spec-record-ref" data-req="SWS_PER_00419" href="../spec/record.html?id=SWS_PER_00419">[SWS_PER_00419]</a> bzw. <code>GetChar()</code> <a class="spec-record-ref" data-req="SWS_PER_00168" href="../spec/record.html?id=SWS_PER_00168">[SWS_PER_00168]</a> wird das aktuelle Element gelesen und der interne Zeiger um eine Position weitergerückt.</li>
<li><strong>Abschnittsweises Lesen (Binärmodus):</strong> Mit <code>ReadBinary(std::uint64_t n)</code> <a class="spec-record-ref" data-req="SWS_PER_00422" href="../spec/record.html?id=SWS_PER_00422">[SWS_PER_00422]</a> wird eine definierte Anzahl an Bytes in einen <code>ara::core::Vector&lt;ara::core::Byte&gt;</code> eingelesen.
