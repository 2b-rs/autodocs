使用目的

ara::core::Optional<T> 实现 std::optional<T> 并对可能存在的值进行建模。它支持空构造或nullopt、就地构造、emplace()、reset()、状态查询和值访问。 [SWS_CORE_01033] [SWS_CORE_01103] [SWS_CORE_01104] [SWS_CORE_01107] [SWS_CORE_01119] [SWS_CORE_01136] [SWS_CORE_01129]

生命周期和所有权

复制和移动构造、赋值和销毁是有条件的，具体取决于 T noexcept 的属性。 [SWS_CORE_01105] [SWS_CORE_01106] [SWS_CORE_01114] [SWS_CORE_01115] [SWS_CORE_01112]

与其他班级的互动

该规范要求通过 Optional<T&> 专业化支持 lvalue 引用。 [SWS_CORE_01032]

限制&错误处理

访问operator*、operator->和value()是noexcept，但如果没有值则可以触发IsoStdBadOptionalAccessViolation。访问前可以使用has_value()或者bool转换。 [SWS_CORE_01124][SWS_CORE_01122][SWS_CORE_01130][SWS_CORE_01129][SWS_CORE_01128]

建模数据集中的可选性

Optional 不仅仅是一个一般的便利类型：Core 特别提到它是 STRUCTURE 类别的 StdCppImplementationDataType 的可选记录元素。另一方面，强制字段直接与其实现数据类型一起出现。或者，Optional 可以表示函数可能缺少的返回值。 SWS Core §7.4 “Core data types” SWS Core §7.4.2 “Data types derived from the C++ standard” SWS LanguageBinding §7.1 “C++ binding for CppImplementationDataTypes”

对于 Optional<T&>，赋值遵循 rebind 行为：它将 Optional 引用重新绑定到新对象，而不是通过该引用写入原先绑定的对象。[SWS_CORE_01032] [SWS_CORE_01034]

活动图：在严格基于价值的访问之前，检查职业状态；另一种方法可以在不访问 value() 的情况下处理缺席情况。来源：SWS Core §7.4.2 “Data types derived from the C++ standard” [SWS_CORE_01129] [SWS_CORE_01130]。
