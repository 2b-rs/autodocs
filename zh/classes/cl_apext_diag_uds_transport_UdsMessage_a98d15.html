类 apext::diag::uds_transport::UdsMessage

class UdsMessage {...};

class represents an UDS message exchanged between DM generic core (UdsTransport ProtocolMgr) and a specific implementation of UdsTransportProtocolHandler on diagnostic request reception path or diagnostic response transmission path. UdsMessage provides the storage for UDS requests/responses.

Instances of UdsMessage (with optimized resource allocation) are only created by DM generic core, the UdsTransportProtocolHandler can read/write on it.

上下文

类 apext::diag::uds_transport::UdsMessage 封装了一条 UDS 消息（Request 或 Response），并充当在 Diagnostic Management 的通用核心（UdsTransportProtocolMgr）与具体传输协议实现（UdsTransportProtocolHandler）之间交换的诊断数据的核心存储库。该实例既在诊断请求的接收路径（RX）上，也在诊断响应的传输路径（TX）上提供底层的消息缓冲区。

除了纯有效负载数据外，UdsMessage 还管理元数据和寻址信息。通过 GetSa() 查询源地址（[SWS_DM_00297]），通过 GetTa() 查询类型为 Address 的目标地址（[SWS_DM_00298]）（[SWS_DM_00293]）。目标地址类型通过 GetTaType() 确定（[SWS_DM_00299]），其中枚举 TargetAddressType 区分物理寻址（kPhysical）与功能寻址（kFunctional）（[SWS_DM_00296]）。此外，特定于通道的附加信息（例如针对 DoIP 插件的预定义元数据）可通过方法 AddMetaInfo() 以 MetaInfoMap 的形式附加到消息中（[SWS_DM_00302]、[SWS_DM_00294]）。

上下文图：DM 核心、传输协议处理程序与 UdsMessage 的交互。来源：[SWS_DM_00385]、[SWS_DM_09012]。

生命周期

UdsMessage 的实例仅由 Diagnostic Management 的通用核心在优化的资源分配下创建。默认构造函数 UdsMessage() 被声明为受保护的（protected）（[SWS_DM_09012]），以明确防止传输协议处理程序自行实例化其实例。

UdsMessage 对象的所有权关系和传递通过智能指针进行管理。为此，平台定义了用于写入访问（[SWS_DM_00303]）的类型别名 UdsMessagePtr 以及用于常量读取访问（[SWS_DM_00304]）的类型别名 UdsMessageConstPtr。在接收消息时，DM 核心通过 UdsMessagePtr 将实例的所有权传递给处理程序（[SWS_DM_00385]）。在完成填充后，该消息再次传递给 DM 核心以供处理（[SWS_DM_00345]）。其释放与销毁通过虚拟默认析构函数 ~UdsMessage() 确定性地进行（[SWS_DM_09010]）。

在并发性方面，用于地址查询的方法（GetSa()、GetTa()、GetTaType()）被指定为可重入的（[SWS_DM_00297]、[SWS_DM_00298]、[SWS_DM_00299]）。相比之下，用于有效负载数据和元数据访问的方法（GetPayload() 和 AddMetaInfo()）则是非线程安全的（unsafe）（[SWS_DM_00300]、[SWS_DM_00301]、[SWS_DM_00302]），因为允许实现在调用 GetPayload() 时执行缓冲区和资源分配。

使用路径

诊断接收路径（RX）上的典型流程分为以下步骤：

  1. 通告：UdsTransportProtocolHandler 从网络接收 UDS 请求，并通过调用 UdsTransportProtocolMgr::IndicateMessage() 指示其到达 ([SWS_DM_00385])。
  2. 实例化与缓冲区提供：若 DM 能够处理该请求，IndicateMessage() 将返回状态为 kIndicationOk 的 std::pair ([SWS_DM_00309]) 以及拥有所创建 UdsMessage 的 UdsMessagePtr。所分配的缓冲区最小大小为 1 个字节 ([SWS_DM_00385])。
  3. 有效数据填充：Handler 调用非常量重载 GetPayload() ([SWS_DM_00301]) 并获取对 uds_transport::ByteSpan& 的引用。Handler 从服务 ID（SID）开始，使用接收到的 UDS 数据填充 UdsMessage 对象，直至达到消息的全部容量或接收到的 UDS 请求的完整长度 ([SWS_DM_00388])。
  4. 附加元数据：如有需要，Handler 通过 AddMetaInfo() 添加通道特定的元数据 ([SWS_DM_00302])。
  5. 转发至 DM 核心：一旦有效数据已完全写入 UdsMessage，Handler 便通过 UdsTransportProtocolMgr::HandleMessage() 将消息传递给通用 DM 核心以进行进一步的诊断处理 ([SWS_DM_00345])。
  6. DM 核心中的读取访问：诊断核心通过常量重载 GetPayload() const 以只读方式读取消息数据（符合 ISO 的 A_Data）([SWS_DM_00300])。

解读：在诊断响应路径 (TX) 上，通用 DM 核心推测会类似地自行用响应数据填充 UdsMessage 对象，并将其传递给 UdsTransportProtocolHandler 进行传输。

时序图：接收路径中消息接收与缓冲区填充的流程。来源：[SWS_DM_00301]、[SWS_DM_00302]、[SWS_DM_00345]、[SWS_DM_00385]、[SWS_DM_00388]。

错误场景

在交互和缓冲区分配过程中可能会出现以下错误情况：

  • DM 繁忙 (Busy)：如果 DM 已在忙于主动处理同一会话的服务，则 IndicateMessage() 返回状态 kIndicationOccupied 以及针对 UdsMessagePtr 的空指针 ([SWS_DM_00386])。在这种情况下，不会提供 UdsMessage。设置了 suppressPosRspMsgIndicationBit（有效负载 0x3E 0x80）的功能性 TesterPresent 请求属于例外情况，它们在任何时候都有效并且允许被处理 ([SWS_DM_00386], [SWS_DM_00126])。
  • 未知目标地址：若无法解析消息的目标地址，DM 会通过结果 kIndicationUnknownTargetAddress 发送信号，并将 UdsMessagePtr 设置为 nullptr (AUTOSAR_AP_SWS_Diagnostics 第100页)。不会分配消息对象。
  • 缓冲区限制：所传递 UdsMessage 对象的容量受到 DM 所设定分配的限制。Handler 最多只能写入缓冲区直至达到其容量上限 ([SWS_DM_00388])。

<h4>上下文</h4>
<p>类 <code>apext::diag::uds_transport::UdsMessage</code> 封装了一条 UDS 消息（Request 或 Response），并充当在 Diagnostic Management 的通用核心（<code>UdsTransportProtocolMgr</code>）与具体传输协议实现（<code>UdsTransportProtocolHandler</code>）之间交换的诊断数据的核心存储库。该实例既在诊断请求的接收路径（RX）上，也在诊断响应的传输路径（TX）上提供底层的消息缓冲区。</p>
<p>除了纯有效负载数据外，<code>UdsMessage</code> 还管理元数据和寻址信息。通过 <code>GetSa()</code> 查询源地址（<a class="spec-record-ref" data-req="SWS_DM_00297" href="../spec/record.html?id=SWS_DM_00297">[SWS_DM_00297]</a>），通过 <code>GetTa()</code> 查询类型为 <code>Address</code> 的目标地址（<a class="spec-record-ref" data-req="SWS_DM_00298" href="../spec/record.html?id=SWS_DM_00298">[SWS_DM_00298]</a>）（<a class="spec-record-ref" data-req="SWS_DM_00293" href="../spec/record.html?id=SWS_DM_00293">[SWS_DM_00293]</a>）。目标地址类型通过 <code>GetTaType()</code> 确定（<a class="spec-record-ref" data-req="SWS_DM_00299" href="../spec/record.html?id=SWS_DM_00299">[SWS_DM_00299]</a>），其中枚举 <code>TargetAddressType</code> 区分物理寻址（<code>kPhysical</code>）与功能寻址（<code>kFunctional</code>）（<a class="spec-record-ref" data-req="SWS_DM_00296" href="../spec/record.html?id=SWS_DM_00296">[SWS_DM_00296]</a>）。此外，特定于通道的附加信息（例如针对 DoIP 插件的预定义元数据）可通过方法 <code>AddMetaInfo()</code> 以 <code>MetaInfoMap</code> 的形式附加到消息中（<a class="spec-record-ref" data-req="SWS_DM_00302" href="../spec/record.html?id=SWS_DM_00302">[SWS_DM_00302]</a>、<a class="spec-record-ref" data-req="SWS_DM_00294" href="../spec/record.html?id=SWS_DM_00294">[SWS_DM_00294]</a>）。</p>

<h4>生命周期</h4>
<p><code>UdsMessage</code> 的实例仅由 Diagnostic Management 的通用核心在优化的资源分配下创建。默认构造函数 <code>UdsMessage()</code> 被声明为受保护的（<code>protected</code>）（<a class="spec-record-ref" data-req="SWS_DM_09012" href="../spec/record.html?id=SWS_DM_09012">[SWS_DM_09012]</a>），以明确防止传输协议处理程序自行实例化其实例。</p>
<p><code>UdsMessage</code> 对象的所有权关系和传递通过智能指针进行管理。为此，平台定义了用于写入访问（<a class="spec-record-ref" data-req="SWS_DM_00303" href="../spec/record.html?id=SWS_DM_00303">[SWS_DM_00303]</a>）的类型别名 <code>UdsMessagePtr</code> 以及用于常量读取访问（<a class="spec-record-ref" data-req="SWS_DM_00304" href="../spec/record.html?id=SWS_DM_00304">[SWS_DM_00304]</a>）的类型别名 <code>UdsMessageConstPtr</code>。在接收消息时，DM 核心通过 <code>UdsMessagePtr</code> 将实例的所有权传递给处理程序（<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>）。在完成填充后，该消息再次传递给 DM 核心以供处理（<a class="spec-record-ref" data-req="SWS_DM_00345" href="../spec/record.html?id=SWS_DM_00345">[SWS_DM_00345]</a>）。其释放与销毁通过虚拟默认析构函数 <code>~UdsMessage()</code> 确定性地进行（<a class="spec-record-ref" data-req="SWS_DM_09010" href="../spec/record.html?id=SWS_DM_09010">[SWS_DM_09010]</a>）。</p>
<p>在并发性方面，用于地址查询的方法（<code>GetSa()</code>、<code>GetTa()</code>、<code>GetTaType()</code>）被指定为可重入的（<a class="spec-record-ref" data-req="SWS_DM_00297" href="../spec/record.html?id=SWS_DM_00297">[SWS_DM_00297]</a>、<a class="spec-record-ref" data-req="SWS_DM_00298" href="../spec/record.html?id=SWS_DM_00298">[SWS_DM_00298]</a>、<a class="spec-record-ref" data-req="SWS_DM_00299" href="../spec/record.html?id=SWS_DM_00299">[SWS_DM_00299]</a>）。相比之下，用于有效负载数据和元数据访问的方法（<code>GetPayload()</code> 和 <code>AddMetaInfo()</code>）则是非线程安全的（unsafe）（<a class="spec-record-ref" data-req="SWS_DM_00300" href="../spec/record.html?id=SWS_DM_00300">[SWS_DM_00300]</a>、<a class="spec-record-ref" data-req="SWS_DM_00301" href="../spec/record.html?id=SWS_DM_00301">[SWS_DM_00301]</a>、<a class="spec-record-ref" data-req="SWS_DM_00302" href="../spec/record.html?id=SWS_DM_00302">[SWS_DM_00302]</a>），因为允许实现在调用 <code>GetPayload()</code> 时执行缓冲区和资源分配。</p>

<h4>使用路径</h4>
<p>诊断接收路径（RX）上的典型流程分为以下步骤：</p>
<ol>
<li><strong>通告：</strong><code>UdsTransportProtocolHandler</code> 从网络接收 UDS 请求，并通过调用 <code>UdsTransportProtocolMgr::IndicateMessage()</code> 指示其到达 (<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>)。</li>
<li><strong>实例化与缓冲区提供：</strong>若 DM 能够处理该请求，<code>IndicateMessage()</code> 将返回状态为 <code>kIndicationOk</code> 的 <code>std::pair</code> (<a class="spec-record-ref" data-req="SWS_DM_00309" href="../spec/record.html?id=SWS_DM_00309">[SWS_DM_00309]</a>) 以及拥有所创建 <code>UdsMessage</code> 的 <code>UdsMessagePtr</code>。所分配的缓冲区最小大小为 1 个字节 (<a class="spec-record-ref" data-req="SWS_DM_00385" href="../spec/record.html?id=SWS_DM_00385">[SWS_DM_00385]</a>)。</li>
<li><strong>有效数据填充：</strong>Handler 调用非常量重载 <code>GetPayload()</code> (<a class="spec-record-ref" data-req="SWS_DM_00301" href="../spec/record.html?id=SWS_DM_00301">[SWS_DM_00301]</a>) 并获取对 <code>uds_transport::ByteSpan&amp;</code> 的引用。Handler 从服务 ID（SID）开始，使用接收到的 UDS 数据填充 <code>UdsMessage</code> 对象，直至达到消息的全部容量或接收到的 UDS 请求的完整长度 (<a class="spec-record-ref" data-req="SWS_DM_00388" href="../spec/record.html?id=SWS_DM_00388">[SWS_DM_00388]</a>)。</li>
<li><strong>附加元数据：</strong>如有需要，Handler 通过 <code>AddMetaInfo()</code> 添加通道特定的元数据 (<a class="spec-record-ref" data-req="SWS_DM_00302" href="../spec/record.html?id=SWS_DM_00302">[SWS_DM_00302]</a>)。</li>
<li><strong>转发至 DM 核心：</strong>一旦有效数据已完全写入 <code>UdsMessage</code>，Handler 便通过 <code>UdsTransportProtocolMgr::HandleMessage()</code> 将消息传递给通用 DM 核心以进行进一步的诊断处理 (<a class="spec-record-ref" data-req="SWS_DM_00345" href="../spec/record.html?id=SWS_DM_00345">[SWS_DM_00345]</a>)。</li>
<li><strong>DM 核心中的读取访问：</strong>诊断核心通过常量重载 <code>GetPayload() const</code> 以只读方式读取消息数据（符合 ISO 的 A_Data）(<a class="spec-record-ref" data-req="SWS_DM_00300" href="../spec/record.html?id=SWS_DM_00300">[SWS_DM_00300]</a>)。</li>
</ol>
<p>解读：在诊断响应路径 (TX) 上，通用 DM 核心推测会类似地自行用响应数据填充 <code>UdsMessage</code> 对象，并将其传递给 <code>UdsTransportProtocolHandler</code> 进行传输。</p>

<h4>错误场景</h4>
<p>在交互和缓冲区分配过程中可能会出现以下错误情况：</p>
<ul>
<li><strong>DM 繁忙 (Busy)：</strong>如果 DM 已在忙于主动处理同一会话的服务，则 <code>IndicateMessage()</code> 返回状态 <code>kIndicationOccupied</code> 以及针对 <code>UdsMessagePtr</code> 的空指针 (<a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>)。在这种情况下，不会提供 <code>UdsMessage</code>。设置了 <code>suppressPosRspMsgIndicationBit</code>（有效负载 <code>0x3E 0x80</code>）的功能性 <code>TesterPresent</code> 请求属于例外情况，它们在任何时候都有效并且允许被处理 (<a class="spec-record-ref" data-req="SWS_DM_00386" href="../spec/record.html?id=SWS_DM_00386">[SWS_DM_00386]</a>, <a class="spec-record-ref" data-req="SWS_DM_00126" href="../spec/record.html?id=SWS_DM_00126">[SWS_DM_00126]</a>)。</li>
<li><strong>未知目标地址：</strong>若无法解析消息的目标地址，DM 会通过结果 <code>kIndicationUnknownTargetAddress</code> 发送信号，并将 <code>UdsMessagePtr</code> 设置为 <code>nullptr</code> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=100">AUTOSAR_AP_SWS_Diagnostics 第100页</a>)。不会分配消息对象。</li>
<li><strong>缓冲区限制：</strong>所传递 <code>UdsMessage</code> 对象的容量受到 DM 所设定分配的限制。Handler 最多只能写入缓冲区直至达到其容量上限 (<a class="spec-record-ref" data-req="SWS_DM_00388" href="../spec/record.html?id=SWS_DM_00388">[SWS_DM_00388]</a>)。</li>
</ul>
