上下文

类 ara::nm::NmErrorDomain 为 AUTOSAR Adaptive Platform [SWS_ANM_01101] 内的功能集群 Network Management（nm）定义了官方错误域。根据平台范围的错误处理模型，它派生自基类 ara::core::ErrorDomain 并被声明为 final，从而在此处明确终止了继承层次结构 [SWS_ANM_01101]。

其主要职责是以类型化方式将特定于网络管理的错误状态集成到 AUTOSAR Adaptive 的统一错误系统中。为此，该类提供了两个核心类型别名：Errc 引用包含具体错误代码 [SWS_ANM_01103] 的枚举 NmErrc，而 Exception 则绑定到类型专用的异常类 NmException [SWS_ANM_01104]。在运行时系统中，最重要的交互伙伴是 ara::core::ErrorCode [SWS_ANM_01108]，它封装了错误值，并将其文本表示以及异常处理委托给 NmErrorDomain 的相应实例。

生命周期

实例化通过默认构造函数 NmErrorDomain() [SWS_ANM_01105] 进行。该构造函数被定义为 noexcept，从而完全排除了构造过程中的异常 [SWS_ANM_01105]。规范依据还明确证明构造过程是线程安全的 [SWS_ANM_01105]。

在所有权关系和实例管理方面，错误域通常充当不可变的、长生命周期的描述符对象。在 Adaptive 应用程序中，NmErrorDomain 的实例推测作为进程范围的单例或静态引用保留（解读），从而确保在应用程序的整个运行期间具有一致的访问权限。

该类不具有可变内部状态，设计为无状态。用于查询信息的所有成员函数（例如 Name() [SWS_ANM_01106]、Message() [SWS_ANM_01107]）以及例程 ThrowAsException() [SWS_ANM_01108] 均被声明为 const 并标识为线程安全 [SWS_ANM_01106]、[SWS_ANM_01107]、[SWS_ANM_01108]。这使得来自任意数量线程的并发访问成为可能，而无需额外的同步开销。

使用路径

在实践中，NmErrorDomain 的使用主要通过 ara::core::Result 和 ara::core::ErrorCode 的错误处理模式间接进行。如果网络管理操作失败，该层会生成一个归属于该域的相应错误代码。

错误检查和处理的典型流程分为以下步骤：

  1. 结果检查：在 NM 调用后，应用逻辑接收到一个与 NmErrorDomain 关联的 ara::core::ErrorCode 类型错误对象。
  2. 识别域：为了归类错误来源，可以通过 Name() [SWS_ANM_01106] 查询错误域的标识符。
  3. 获取错误消息：对于日志记录或诊断输出，Message() [SWS_ANM_01107] 会返回特定错误代码的描述性字符串。
  4. 触发异常：若在出错时需要切换到基于异常的控制流，则调用 ThrowAsException() [SWS_ANM_01108]，从而抛出与该错误代码关联的异常。

时序图：通过错误域查询错误文本及抛出异常的交互序列。来源：[SWS_ANM_01106]、[SWS_ANM_01107]、[SWS_ANM_01108]

错误场景

类 NmErrorDomain 用作模块 nm 的错误代码和异常的管理框架。错误情况由枚举 NmErrc 表示，通过类型别名 Errc 对其进行访问 [SWS_ANM_01103]。

对于各个方法调用，以下条件和行为是相关的：

  • 名称与消息查询：方法 Name() [SWS_ANM_01106] 和 Message() [SWS_ANM_01107] 被声明为 noexcept。它们保证即使在关键错误状态下查询诊断信息时，也不会抛出后续异常。如果向 Message() 传递了未知的数值错误值，实现可能会返回通用提示或默认文本（解读）。
  • 异常处理：方法 ThrowAsException() 被显式限定为 noexcept(false) [SWS_ANM_01108]。调用的后置条件是抛出特定的异常 NmException（通过别名 Exception [SWS_ANM_01104] 引用），该异常以传入的 ErrorCode [SWS_ANM_01108] 进行参数化。如果应用程序直接或间接调用此方法，则必须存在针对 NmException 或 ara::core::Exception 的相应 catch 块，以防止进程终止。
