用作在 AUTOSAR 诊断服务器中通过 ASAM SOVD 协议处理软件更新的接口。

该类提供了应用程序端接口，用于根据 ASAM SOVD 通过 SOVD 协议处理标准化的软件更新 [SWS_DM_01796]。实例化后，应用程序通过方法 Offer() [SWS_DM_01924] 激活将诊断请求转发给特定的更新处理程序。通过异步方法注册、准备、自动或手动安装以及再次删除软件包。所有与数据传输和生命周期相关的操作都通过 Future 以非阻塞方式进行处理。

上下文

类 ara::diag::SovdSwUpdate 定义了在 AUTOSAR Adaptive Platform 内根据 ASAM SOVD 实现标准化软件更新的接口 [SWS_DM_01874]。由于软件更新的实际业务逻辑不位于 Diagnostic Management（DM）功能集群中，因此执行仍由相应的应用程序负责，而 ara::diag::SovdSwUpdate 则专注于底层 SOVD 协议的合规处理 AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API - concept”。对于更新文件的上传，这里采用了针对 UDS 服务 0x38（RequestFileTransfer）所指定的传输策略 AUTOSAR_AP_SWS_Diagnostics §7.4 “SOVD Software Update API - concept”、[SWS_DM_01923]。

在流程中涉及三个主要组件：外部 SOVD 客户端、用于协议和路由管理的 Diagnostic Server (DM) 实例，以及 ara::diag::SovdSwUpdate 的特定于应用程序的处理程序实现 [SWS_DM_01796]、[SWS_DM_01924]。

生命周期

ara::diag::SovdSwUpdate 的实例化通过构造函数进行，需指定指向已建模 DiagnosticSovdUpdateInterface 的端口原型的 ara::core::InstanceSpecifier 以及并发模式（ConcurrencyType：kConcurrent 或 kNotConcurrent）[SWS_DM_01910]。该构造函数被指定为线程安全和异常安全 [SWS_DM_01910]。作为唯一接口实例的代表，复制构造函数和复制赋值运算符已删除（=delete）且受保护 [SWS_DM_01912]、[SWS_DM_01914]。移动构造和移动赋值作为受保护成员可用，但不是线程安全的 [SWS_DM_01913]、[SWS_DM_01915]。

对象的析构通过虚析构函数 ~SovdSwUpdate() 处理，该函数被视为非线程安全 [SWS_DM_01911]。该类的虚回调方法是否必须并发执行，直接取决于传递给构造函数的 ConcurrencyType [SWS_DM_01910]、[SWS_DM_01916]。

使用路径

解释：由于提供的接口方法被声明为纯虚函数（=0），派生的应用程序类应当实现这些方法以执行实际的更新执行，而基类则管理平台连接。

常规流程分为以下阶段：

  • 提供：创建对象后，应用程序调用 Offer()，以使 Diagnostic Management 能够将传入的 SOVD 消息转发至该实例 [SWS_DM_01924]。
  • 查询与注册：通过 GetAllUpdates() 可以查询现有的更新包 [SWS_DM_01797]、[SWS_DM_01916]。如果要传输新包，Diagnostic Server 通过 RequestUpdatePackageRegistration() 请求注册，该操作异步提供写入会话（DataTransferWriteSession）以及更新包 ID [SWS_DM_01923]。详细信息和状态通过 GetUpdatePackageDetails() 和 GetUpdatePackageStatus() 获取 [SWS_DM_01802]、[SWS_DM_01917]、[SWS_DM_01921]。
  • 安装或删除：安装既可以通过 PutUpdatePackageAutomated() 自动触发 [SWS_DM_01799]、[SWS_DM_01918]，也可以分两步通过 PrepareUpdatePackage() [SWS_DM_01800]、[SWS_DM_01919] 随后通过 ExecuteUpdatePackage() [SWS_DM_01801]、[SWS_DM_01920] 进行。不再需要的包通过 DeleteUpdatePackage() 移除 [SWS_DM_01922]。
  • 终止：在关闭之前，应用程序通过调用 StopOffer() 停用消息转发 [SWS_DM_01925]。

时序图：通过 SOVD 进行包注册和安装的典型流程。来源：[SWS_DM_01799]、[SWS_DM_01800]、[SWS_DM_01801]、[SWS_DM_01919]、[SWS_DM_01920]、[SWS_DM_01923]、[SWS_DM_01924]

错误场景

通过 Offer() 提供服务时，返回类型 ara::core::Result<void> 中可能会出现特定错误：如果实例已在提供中，则出现 DiagOfferErrc::kAlreadyOffered；如果配置与诊断提取（DEXT）不匹配，则出现 DiagOfferErrc::kConfigurationMismatch [SWS_DM_01924]。

如果使用错误的模型状态调用构造函数，将报告架构违规，包括 InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation 或 InstanceSpecifierAlreadyInUseViolation [SWS_DM_01910]。

所有功能性更新操作均返回 ara::core::Future，在出错时传递符合 ASAM SOVD 1.1 或 ISO 17978-3 的错误代码 [SWS_DM_01917]、[SWS_DM_01919]、[SWS_DM_01920]、[SWS_DM_01923]。此外，所有异步方法均接收一个 CancellationHandler，通过该参数指示当前诊断连接的提前中止 [SWS_DM_01916]、[SWS_DM_01919]、[SWS_DM_01923]。
