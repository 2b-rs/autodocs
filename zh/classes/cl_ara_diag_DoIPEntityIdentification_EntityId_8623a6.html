结构体 ara::diag::DoIPEntityIdentification::EntityId 用作符合 ISO 13400-2 的 DoIP 实例的 6 字节实体标识符（EID）的数据容器（[SWS_DM_01496]）。在相应配置下，Diagnostic Manager 通过方法 ara::diag::DoIPEntityIdentification::GetEntityId 从自适应应用程序检索该标识符，以便将其嵌入车辆声明等 DoIP 协议消息中（[SWS_DM_01361]）。如果接口尚未就绪或检索失败，则作为强制约束，将回退到全部由字节值 0xFF 组成的固定替代值（[SWS_DM_01528]）。

上下文

数据结构 ara::diag::DoIPEntityIdentification::EntityId 用于表示符合 ISO 13400-2 的 Internet 协议诊断通信（DoIP）的标准实体标识符（Entity Identification，EID）（[SWS_DM_01496]、AUTOSAR_AP_SWS_Diagnostics §8.33 “Header: ara/diag/doip_entity_identification.h”）。在 AUTOSAR Adaptive Platform 内部，它被定义为 API 类 ara::diag::DoIPEntityIdentification 内部的公共结构体类型（[SWS_DM_01362]、[SWS_DM_01496]）。

其主要职责是封装 DoIP 实体的恰好 6 字节长度的标识值（[SWS_DM_01496]）。在平台架构中，有三个主要参与方进行交互：首先是管理实体标识符或从硬件读取该标识符的自适应应用程序。其次是接口类 ara::diag::DoIPEntityIdentification，它提供用于提供该标识符的方法（[SWS_DM_01362]）。第三是 Diagnostic Manager（DM），它在车辆标识过程中为传出的 DoIP 消息检索 EID（[SWS_DM_01361]、AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”）。

上下文图：EntityId 在 Diagnostic Manager、接口类与自适应应用程序之间的集成。来源：[SWS_DM_01361]、[SWS_DM_01496]。

生命周期

作为仅具有 ara::core::Array<std::uint8_t, 6> 类型的成员 entityIdentification 的数据结构，EntityId 具备轻量级 C++ 值对象的特性（[SWS_DM_01496]）。解读：由于缺乏动态资源分配，该结构体推测默认支持常规复制和移动操作，且不会经历复杂的内部状态转换。

一旦 Diagnostic Manager 通过调用 ara::diag::DoIPEntityIdentification::GetEntityId 查询身份数据，自适应应用程序就会实例化 EntityId（[SWS_DM_01361]）。实例的生命周期通常绑定到方法调用的返回和处理周期。外层服务类 ara::diag::DoIPEntityIdentification 拥有显式的构造函数（[SWS_DM_01364]、AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.2.1 “DoIPEntityIdentification”）和析构函数（[SWS_DM_01365]、AUTOSAR_AP_SWS_Diagnostics §8.33.1.1.1.1 “Destructor”），而值对象 EntityId 在 Diagnostic Manager 读取字段数据并在离开作用域后会自动释放。

使用路径

EntityId 的常规使用遵循诊断协议流程中的定义序列：

  • 配置检查：Diagnostic Manager 检查属性 DoIpNetworkConfiguration.eidRetrieval。如果此处配置为 DoIpEidRetrievalEnum.eidUseApi，则 DM 必须强制通过 API 检索该标识符（[SWS_DM_01361]）。
  • 通过 API 检索：Diagnostic Manager 调用方法 ara::diag::DoIPEntityIdentification::GetEntityId（[SWS_DM_01361]）。
  • 数据提供：应用程序创建 EntityId 的实例，用符合 ISO 13400-2 的 6 字节标识符填充成员 entityIdentification（[SWS_DM_01496]），并传递该结构体。
  • 协议使用：Diagnostic Manager 提取该标识符并将其插入 DoIP 消息中，例如车辆声明消息（Vehicle Announcement Message）（[SWS_DM_01361]、AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”）。

时序图：EntityId 的检索和进一步处理流程，包含错误回退。来源：[SWS_DM_01361]、[SWS_DM_01496]、[SWS_DM_01528]。

错误场景

一个关键的错误场景发生在接口 ara::diag::DoIPEntityIdentification 在要求的查询时间点尚未由自适应应用程序提供，或者通过 GetEntityId 的检索失败时（[SWS_DM_01528]、AUTOSAR_AP_SWS_Diagnostics §8.33 “Providing EID in DoIP protocol messages using Application Interface”）。

为了避免持续阻止 DoIP 消息的发送，规范在此情况下规定了具有约束力的替代值行为：Diagnostic Manager 必须传输具有固定值 0xFF 0xFF 0xFF 0xFF 0xFF 0xFF 的 6 字节 EID 字段，而不是常规的应用程序数据（[SWS_DM_01528]）。在类型级别上，定长数组 ara::core::Array<std::uint8_t, 6> 在编译时消除了长度错误和缓冲区溢出（[SWS_DM_01496]）。
