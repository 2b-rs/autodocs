上下文

类 ara::crypto::cryp::ProtectedKeyImportCtx 定义了一个专门用于安全加载和解包加密密钥及相关元数据（[SWS_CRYPT_50207]）的专用接口。当密钥材料以受保护、加密或已认证的形式（例如作为 Wrapped Key Token）传输到应用程序环境中并在该环境中提供时，就会使用该接口。

在与其他组件交互时，该上下文充当处理应用程序、加密源结构与传输结构以及生成的密钥对象之间的接口：

  • 传输密钥：为了对数据进行解密和身份验证，上下文需要一个传输密钥。该密钥要么直接作为对称密钥对象 ara::crypto::cryp::SymmetricKey 传递（[SWS_CRYPT_50205]），要么通过 ara::crypto::keys::KeySlot 进行引用（[SWS_CRYPT_50206]）。
  • 输入数据：受保护的序列化密钥数据通过只读存储区（ReadOnlyMemRegion）提供给上下文（[SWS_CRYPT_50207]）。
  • 目标存储或易失性密钥：导入成功后，解包后的密钥材料既可以直接存储在持久性写入密钥槽（WriteableKeySlot）中（[SWS_CRYPT_50207]），也可以通过类型化查询方法获取为指向私钥（[SWS_CRYPT_50209]）、对称密钥（[SWS_CRYPT_50210]）或公钥（[SWS_CRYPT_50211]）的易失性智能指针。
  • 协议响应：如果底层导入方案支持身份验证或确认协议（例如 SHE-LoadKey 事务的返回结果 M4 和 M5），则上下文会将这些响应数据返回给应用程序（[SWS_CRYPT_41020]）。

生命周期

ProtectedKeyImportCtx 的实例通过类型化别名 Sptr 作为共享指针进行管理，该别名定义为 std::shared_ptr<ProtectedKeyImportCtx>（[SWS_CRYPT_50085]）。Interpretation: 实际的实例化很可能是通过 CryptoProvider 的相应工厂方法进行的，因为这是一个抽象接口。

该上下文在运行操作中经历多个离散状态：

  1. 初始状态：在创建后或显式清理后，不存在配置的 Key-Import-Key，且内部数据缓冲区为空（[SWS_CRYPT_50212]）。
  2. 已配置：通过经由 SetKey() 绑定传输密钥（[SWS_CRYPT_50205]，[SWS_CRYPT_50206]），上下文已准备好处理受保护的数据包。
  3. 数据可用：在成功执行 Import()（[SWS_CRYPT_50207]）后，上下文将保存解析后的密钥对象以及可能产生的任何响应消息。在此状态下可以调用 Getter 方法。
  4. 重置：调用 Reset()（[SWS_CRYPT_50212]）会移除设置的传输密钥，清除内部缓冲区中的所有缓存数据，并将上下文转换回初始状态。

在并发性方面，上下文的所有接口方法均被指定为异常安全（exception safe）以及线程安全（thread-safe）（[SWS_CRYPT_50205]，[SWS_CRYPT_50207]，[SWS_CRYPT_50208]，[SWS_CRYPT_50212]）。

使用路径

执行受保护密钥导入的典型流程分为以下步骤：

  1. 配置传输密钥：应用程序通过使用对称密钥对象（[SWS_CRYPT_50205]）或密钥槽（[SWS_CRYPT_50206]）调用 SetKey() 来配置上下文。所提供的密钥必须具备相应的使用权限。
  2. 执行导入：使用序列化数据的数据缓冲区调用方法 Import()（[SWS_CRYPT_50207]）。如果还指定了 WriteableKeySlot，上下文会直接将解包后的密钥材料序列化到该槽中。
  3. 识别对象类型：可通过 GetCryptoObjectType() 查询解包了哪种加密对象（[SWS_CRYPT_50208]）。
  4. 获取密钥和协议响应：取决于对象类型，应用程序通过 GetSymmetricKey()（[SWS_CRYPT_50210]）、GetPrivateKey()（[SWS_CRYPT_50209]）或 GetPublicKey()（[SWS_CRYPT_50211]）请求密钥。如果导入协议规定了确认消息，则该消息会通过 GetResponse() 传输至提供的缓冲区中（[SWS_CRYPT_41020]）。
  5. 完成与缓冲区清理：成功取出后，调用 Reset() 以确保从内部缓冲区中清除敏感残留数据，并干净地重置上下文（[SWS_CRYPT_50212]）。

错误场景

所有操作均返回 ara::core::Result，并在发生错误时使用定义的向后回滚语义，以保留调用前的状态：

  • 密钥配置错误：
    • CryptoErrc::kUsageViolation：当传输密钥的使用标志未包含位 kAllowKeyUnwrapping 时发生（[SWS_CRYPT_50205]，[SWS_CRYPT_50206]）。
    • CryptoErrc::kIncompatibleObject：传入的对象或 KeySlot 中包含的密钥无法用作传输密钥（[SWS_CRYPT_50205]，[SWS_CRYPT_50206]）。
    • CryptoErrc::kUnsupported：上下文实现仅支持另一种 SetKey() 变体（例如仅支持 KeySlot 而非密钥对象）（[SWS_CRYPT_50205]，[SWS_CRYPT_50206]）。
  • 导入期间的错误：
    • CryptoErrc::kInvalidInputSize：传入的内存区域 serialized 大小异常，无法解包（[SWS_CRYPT_50207]）。
    • CryptoErrc::kInvalidArgument：serialized 的数据格式不符合要求的导入格式（[SWS_CRYPT_50207]）。
    • CryptoErrc::kAuthTagNotValid：认证特征（签名或 MAC）无效，无法确认数据完整性（[SWS_CRYPT_50207]）。
    • CryptoErrc::kBusyResource：由于内部资源被占用，操作暂时无法执行（[SWS_CRYPT_50207]）。
  • 结果查询时的错误：
    • CryptoErrc::kProcessingNotFinished：如果此前未成功调用 Import()，则调用 GetPrivateKey()、GetPublicKey() 或 GetSymmetricKey() 失败（[SWS_CRYPT_50209]，[SWS_CRYPT_50210]，[SWS_CRYPT_50211]）。
    • CryptoErrc::kNoSuchValue：在迄今尚未导入任何对象或最后导入的对象与所查询的密钥类型不符时返回（[SWS_CRYPT_50208]，[SWS_CRYPT_50209]，[SWS_CRYPT_50210]，[SWS_CRYPT_50211]）。
    • CryptoErrc::kInsufficientCapacity：为 GetResponse() 传入的输出缓冲区不足以容纳协议响应（[SWS_CRYPT_41020]）。
    • CryptoErrc::kUnsupported：指示上下文不支持特定功能——例如确定对象类型（[SWS_CRYPT_50208]）、生成响应（[SWS_CRYPT_41020]）或重置状态（[SWS_CRYPT_50212]）。

<h4>上下文</h4>
<p>类 <code>ara::crypto::cryp::ProtectedKeyImportCtx</code> 定义了一个专门用于安全加载和解包加密密钥及相关元数据（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）的专用接口。当密钥材料以受保护、加密或已认证的形式（例如作为 Wrapped Key Token）传输到应用程序环境中并在该环境中提供时，就会使用该接口。</p>
<p>在与其他组件交互时，该上下文充当处理应用程序、加密源结构与传输结构以及生成的密钥对象之间的接口：</p>
<ul>
<li><strong>传输密钥：</strong>为了对数据进行解密和身份验证，上下文需要一个传输密钥。该密钥要么直接作为对称密钥对象 <code>ara::crypto::cryp::SymmetricKey</code> 传递（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>），要么通过 <code>ara::crypto::keys::KeySlot</code> 进行引用（<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>）。</li>
<li><strong>输入数据：</strong>受保护的序列化密钥数据通过只读存储区（<code>ReadOnlyMemRegion</code>）提供给上下文（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。</li>
<li><strong>目标存储或易失性密钥：</strong>导入成功后，解包后的密钥材料既可以直接存储在持久性写入密钥槽（<code>WriteableKeySlot</code>）中（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>），也可以通过类型化查询方法获取为指向私钥（<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>）、对称密钥（<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>）或公钥（<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>）的易失性智能指针。</li>
<li><strong>协议响应：</strong>如果底层导入方案支持身份验证或确认协议（例如 SHE-LoadKey 事务的返回结果 M4 和 M5），则上下文会将这些响应数据返回给应用程序（<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>）。</li>
</ul>

<h4>生命周期</h4>
<p><code>ProtectedKeyImportCtx</code> 的实例通过类型化别名 <code>Sptr</code> 作为共享指针进行管理，该别名定义为 <code>std::shared_ptr&lt;ProtectedKeyImportCtx&gt;</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50085" href="../spec/record.html?id=SWS_CRYPT_50085">[SWS_CRYPT_50085]</a>）。Interpretation: 实际的实例化很可能是通过 CryptoProvider 的相应工厂方法进行的，因为这是一个抽象接口。</p>
<p>该上下文在运行操作中经历多个离散状态：</p>
<ol>
<li><strong>初始状态：</strong>在创建后或显式清理后，不存在配置的 Key-Import-Key，且内部数据缓冲区为空（<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>）。</li>
<li><strong>已配置：</strong>通过经由 <code>SetKey()</code> 绑定传输密钥（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>），上下文已准备好处理受保护的数据包。</li>
<li><strong>数据可用：</strong>在成功执行 <code>Import()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）后，上下文将保存解析后的密钥对象以及可能产生的任何响应消息。在此状态下可以调用 Getter 方法。</li>
<li><strong>重置：</strong>调用 <code>Reset()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>）会移除设置的传输密钥，清除内部缓冲区中的所有缓存数据，并将上下文转换回初始状态。</li>
</ol>
<p>在并发性方面，上下文的所有接口方法均被指定为异常安全（exception safe）以及线程安全（thread-safe）（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>）。</p>

<h4>使用路径</h4>
<p>执行受保护密钥导入的典型流程分为以下步骤：</p>
<ol>
<li><strong>配置传输密钥：</strong>应用程序通过使用对称密钥对象（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>）或密钥槽（<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>）调用 <code>SetKey()</code> 来配置上下文。所提供的密钥必须具备相应的使用权限。</li>
<li><strong>执行导入：</strong>使用序列化数据的数据缓冲区调用方法 <code>Import()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。如果还指定了 <code>WriteableKeySlot</code>，上下文会直接将解包后的密钥材料序列化到该槽中。</li>
<li><strong>识别对象类型：</strong>可通过 <code>GetCryptoObjectType()</code> 查询解包了哪种加密对象（<a class="spec-record-ref" data-req="SWS_CRYPT_50208" href="../spec/record.html?id=SWS_CRYPT_50208">[SWS_CRYPT_50208]</a>）。</li>
<li><strong>获取密钥和协议响应：</strong>取决于对象类型，应用程序通过 <code>GetSymmetricKey()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50210" href="../spec/record.html?id=SWS_CRYPT_50210">[SWS_CRYPT_50210]</a>）、<code>GetPrivateKey()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50209" href="../spec/record.html?id=SWS_CRYPT_50209">[SWS_CRYPT_50209]</a>）或 <code>GetPublicKey()</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50211" href="../spec/record.html?id=SWS_CRYPT_50211">[SWS_CRYPT_50211]</a>）请求密钥。如果导入协议规定了确认消息，则该消息会通过 <code>GetResponse()</code> 传输至提供的缓冲区中（<a class="spec-record-ref" data-req="SWS_CRYPT_41020" href="../spec/record.html?id=SWS_CRYPT_41020">[SWS_CRYPT_41020]</a>）。</li>
<li><strong>完成与缓冲区清理：</strong>成功取出后，调用 <code>Reset()</code> 以确保从内部缓冲区中清除敏感残留数据，并干净地重置上下文（<a class="spec-record-ref" data-req="SWS_CRYPT_50212" href="../spec/record.html?id=SWS_CRYPT_50212">[SWS_CRYPT_50212]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>所有操作均返回 <code>ara::core::Result</code>，并在发生错误时使用定义的向后回滚语义，以保留调用前的状态：</p>
<ul>
<li><strong>密钥配置错误：</strong>
  <ul>
  <li><code>CryptoErrc::kUsageViolation</code>：当传输密钥的使用标志未包含位 <code>kAllowKeyUnwrapping</code> 时发生（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>）。</li>
  <li><code>CryptoErrc::kIncompatibleObject</code>：传入的对象或 KeySlot 中包含的密钥无法用作传输密钥（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>）。</li>
  <li><code>CryptoErrc::kUnsupported</code>：上下文实现仅支持另一种 <code>SetKey()</code> 变体（例如仅支持 <code>KeySlot</code> 而非密钥对象）（<a class="spec-record-ref" data-req="SWS_CRYPT_50205" href="../spec/record.html?id=SWS_CRYPT_50205">[SWS_CRYPT_50205]</a>，<a class="spec-record-ref" data-req="SWS_CRYPT_50206" href="../spec/record.html?id=SWS_CRYPT_50206">[SWS_CRYPT_50206]</a>）。</li>
  </ul>
</li>
<li><strong>导入期间的错误：</strong>
  <ul>
  <li><code>CryptoErrc::kInvalidInputSize</code>：传入的内存区域 <code>serialized</code> 大小异常，无法解包（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。</li>
  <li><code>CryptoErrc::kInvalidArgument</code>：<code>serialized</code> 的数据格式不符合要求的导入格式（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。</li>
  <li><code>CryptoErrc::kAuthTagNotValid</code>：认证特征（签名或 MAC）无效，无法确认数据完整性（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。</li>
  <li><code>CryptoErrc::kBusyResource</code>：由于内部资源被占用，操作暂时无法执行（<a class="spec-record-ref" data-req="SWS_CRYPT_50207" href="../spec/record.html?id=SWS_CRYPT_50207">[SWS_CRYPT_50207]</a>）。</li>
  </ul>
</li>
