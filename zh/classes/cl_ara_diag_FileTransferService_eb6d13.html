允许自适应应用程序为 UDS 诊断服务提供文件和目录操作。

该服务接口用于将特定于应用程序的文件传输连接到 Diagnostic Management，以支持 UDS 服务 RequestFileTransfer（[SWS_DM_01320]、SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”）。实例化后，应用程序使用 Offer() 激活传入文件请求的转发，并通过专用处理程序方法异步处理读取、写入或删除等文件操作（[SWS_DM_01336]）。在读取和写入过程中，服务提供会话对象，实际的数据传输将通过这些对象进行处理。该类的实例不可复制，并且需要通过实例说明符进行固定绑定。

上下文

类 ara::diag::FileTransferService 定义了用于在 AUTOSAR Adaptive Platform 中实现 UDS 服务 RequestFileTransfer (0x38) 的诊断接口（[SWS_DM_01320]、SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”）。它充当 Diagnostic Management（DM 或 Diagnostic Server）与具体诊断应用程序之间的 ServiceInterface，以跨越进程边界灵活处理文件或目录的读取、写入、恢复和删除（SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”）。

文件传输场景通常涉及三方：外部 UDS 客户端（诊断测试仪）、作为中介的 Diagnostic Server 以及继承自 FileTransferService 的自适应应用程序。收到传入的诊断请求时，Diagnostic Server 将请求委托给服务的已实现虚方法（[SWS_DM_01313]、[SWS_DM_01314]）。对于后续的数据传输（UDS 0x36 TransferData）和终止（UDS 0x37 RequestTransferExit），Diagnostic Management 直接访问通过会话对象（DataTransferReadSession 或 DataTransferWriteSession）提供的处理程序类（[SWS_DM_01317]、[SWS_DM_01318]）。

生命周期

通过指定建模的 ara::core::InstanceSpecifier 以及并发模型 ConcurrencyType 来创建 FileTransferService 的实例（[SWS_DM_01325]）。通过 ConcurrencyType 指定该类的回调方法必须实现为线程安全（kConcurrent）还是非线程安全（kNotConcurrent）（[SWS_DM_01325]、[SWS_DM_01331]）。作为受保护的单一功能，该类不可复制（[SWS_DM_01327]、[SWS_DM_01329]），但支持移动语义（[SWS_DM_01328]、[SWS_DM_01330]）。

实例化后，必须通过方法 Offer() 显式激活服务，以便 Diagnostic Management 转发传入请求（[SWS_DM_01336]）。使用 StopOffer() 可以随时再次停用转发（[SWS_DM_01337]）。解读：可能需要在对象被虚析构函数 ~FileTransferService() 销毁之前调用 StopOffer()（[SWS_DM_01326]），以避免 Diagnostic Management 进行孤立的回调访问。Offer()、StopOffer() 以及析构函数均不是线程安全的（[SWS_DM_01326]、[SWS_DM_01336]、[SWS_DM_01337]）。

使用路径

文件操作的典型流程分为配置、触发操作以及随后的块传输。首先，在模式为 ReadFile (0x04) 的 UDS 请求 0x38 中，Diagnostic Management 将调用转发给 RequestReadFile（[SWS_DM_01314]、[SWS_DM_01331]）。应用程序处理文件名以及格式和元信息，并通过 ara::core::Future 异步返回由 DataTransferReadSession 和文件大小（FileSizes）组成的元组（[SWS_DM_01331]）。解读：应用程序推测在实例化相应会话类时确定使用哪种传输策略（例如复制、零拷贝或文件系统句柄）（SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”、[SWS_DM_01317]）。

在获得肯定确认后，客户端通过 TransferData (0x36) 请求数据块。随后，Diagnostic Server 直接调用 DataTransferReadSession 的已注册处理程序的 Read 方法（[SWS_DM_01317]）。一旦所有块均已传输，客户端便使用 RequestTransferExit (0x37) 结束事务，随后 Diagnostic Server 调用处理程序的 Exit 方法（[SWS_DM_01318]）。类似的模式适用于通过模式为 WriteFileMode（[SWS_DM_01324]）的 RequestWriteFile（[SWS_DM_01313]、[SWS_DM_01333]）进行写入、通过 RequestResumeWriteFile（[SWS_DM_01316]、[SWS_DM_01334]）进行恢复、通过 RequestReadDirectory（[SWS_DM_01315]、[SWS_DM_01332]）进行目录读取，或通过 DeleteFile（[SWS_DM_01335]）直接删除。

时序图：通过 UDS 0x38、0x36 和 0x37 执行读取操作的流程。来源：[SWS_DM_01314]、[SWS_DM_01317]、[SWS_DM_01318]、[SWS_DM_01331]。

错误场景

错误可能会在多个阶段发生：

  • 构造违规：如果解析或分配 InstanceSpecifier 失败，则会出现建模错误，例如 InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation 或 InstanceSpecifierAlreadyInUseViolation（[SWS_DM_01325]）。
  • 激活错误：在服务已处于活动状态时重复调用 Offer() 将返回错误 DiagOfferErrc::kAlreadyOffered（[SWS_DM_01336]）。
  • 诊断错误代码 (NRC)：如果操作无法成功执行，回调方法将在 ara::core::Future 中通过 DiagUdsNrcErrc 返回相应的否定 UDS 响应代码（符合 ISO 14229-1 的 NRC）（[SWS_DM_01331]、[SWS_DM_01333]、[SWS_DM_01335]）。
  • 取消处理：通过传入的 CancellationHandler 对象，应用程序可以使用 IsCanceled 检查会话是否已取消，或者通过 SetNotifier 注册用于异步取消的通知函数（[SWS_DM_01331]、[SWS_DM_01335]）。

调用时传递三个参数 [SWS_DM_01335]：

  • fileName (ara::core::String)：目标文件的路径说明和名称（解释：尽管规范文本中编辑性地注明为“file to read”，但其仍指要删除的文件）。
  • metaInfo (MetaInfo const &)：当前诊断请求的元信息。
  • cancellationHandler (CancellationHandler)：允许通过 cancellationHandler.IsCanceled() 检查取消状态，以及在当前会话中断时通过 cancellationHandler.SetNotifier() 注册通知函数。

作为异步结果，该函数返回一个 ara::core::Future<void> [SWS_DM_01335]。成功完成向诊断客户端指示积极的响应行为。在发生错误的情况下，必须在 Future 中通过 DiagUdsNrcErrc 提供符合 ISO 14229-1 的适用 UDS NRC [SWS_DM_01335]。

该函数被指定为 noexcept，并被视为异常安全（“exception safe”）[SWS_DM_01335]。对线程安全性的要求是有条件的，并通过传递给构造函数的 ConcurrencyType 进行控制 [SWS_DM_01335]。
