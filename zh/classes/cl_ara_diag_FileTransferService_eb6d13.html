上下文

接口类 ara::diag::FileTransferService ([SWS_DM_01320], AUTOSAR_AP_SWS_Diagnostics §8.18 “Header: ara/diag/file_transfer.h”) 在 AUTOSAR Adaptive 中提供了基于文件的诊断传输的功能抽象。它用于实现 UDS 服务 0x38 (RequestFileTransfer)，并支持跨进程边界对文件和目录信息进行标准化交换 (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”)。

文件传输流程涉及三个主要组件：

  • Diagnose-Client: 通过标准化的 UDS 服务调用（RequestFileTransfer 0x38、TransferData 0x36 以及 RequestTransferExit 0x37）发起文件操作。
  • Diagnostic Management (Diagnostic Server Instance): 接收客户端的诊断消息，处理协议操作，并将请求转发给已注册的 Service 实例 (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Realization of modeOfOperation”)。
  • Adaptive Application: 实现 ara::diag::FileTransferService 的业务回调方法，创建数据会话并访问本地文件系统。

该架构支持不同的数据交换策略 (AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”)：

  • Simple: 在 Adaptive Application 与 Diagnostic Management 之间复制数据；适用于较小的文件大小。
  • Zero Copy: 避免应用程序与 Diagnostic Management 之间的内存复制，以提高处理大数据量时的资源效率。
  • OS File System Handle: 传递操作系统的原生文件句柄，以便直接传输而无需在诊断栈中进行复制开销。

生命周期

类 ara::diag::FileTransferService 充当特定于应用程序的诊断 Handler 的基类。在实例化时，构造函数需要一个指向类型为 DiagnosticRequestFileTransferInterface 的建模 PortPrototype 的 ara::core::InstanceSpecifier，并通过 ConcurrencyType 指定并发行为 ([SWS_DM_01325])。

实例关系和所有权关系受到严格规范：

  • Kopierschutz: 该类表示唯一实例；拷贝构造函数 ([SWS_DM_01327]) 和拷贝赋值运算符 ([SWS_DM_01329]) 已被删除 (delete)。
  • Verschiebbarkeit: 移动构造函数 ([SWS_DM_01328]) 和移动赋值运算符 ([SWS_DM_01330]) 定义在 protected 作用域内。
  • 销毁：虚析构函数 ~FileTransferService() ([SWS_DM_01326]) 确保派生类的正确清理。

功能生命周期由应用程序主动控制：

  1. Bereitgestellt: 创建后，Diagnostic Management 尚不会将请求转发给该实例。
  2. Aktiv (Angeboten): 通过调用 Offer()，Diagnostic Management 获得授权将请求转接给 Service Handler ([SWS_DM_01336])。
  3. Deaktiviert: 调用 StopOffer() 会撤销授权并阻止转发新请求 ([SWS_DM_01337])。

关于线程安全性，AUTOSAR 进行了区分：接口的回调根据构造函数中传入的 ConcurrencyType（kConcurrent 或 kNotConcurrent）来调整其并发行为 ([SWS_DM_01325])。相比之下，诸如 Offer()、StopOffer() 等管理方法以及析构函数则被指定为非线程安全 ([SWS_DM_01326], [SWS_DM_01336], [SWS_DM_01337])。

使用路径

该接口通过专用的纯虚方法涵盖了 UDS 服务 0x38 中定义的所有操作模式：

  • RequestReadFile: 在 modeOfOperation ReadFile (0x04) 时被调用 ([SWS_DM_01314], [SWS_DM_01331])。
  • RequestWriteFile: 在带有 WriteFileMode::kReplace 的 modeOfOperation ReplaceFile (0x03) ([SWS_DM_01313], [SWS_DM_01324], [SWS_DM_01333]) 以及 kAdd 时被调用。
  • RequestResumeWriteFile: 在 modeOfOperation ResumeFile (0x06) 时被调用 ([SWS_DM_01316], [SWS_DM_01334])。
  • RequestReadDirectory: 在 modeOfOperation ReadDir (0x05) 时被调用 ([SWS_DM_01315], [SWS_DM_01332])。
  • DeleteFile: 在 modeOfOperation DeleteFile 时执行文件的完全删除 ([SWS_DM_01335])。

读取文件 (ReadFile) 的典型使用路径包括以下步骤：

  1. 提供：应用程序实例化其派生的服务类，并通过 Offer() 激活接口（[SWS_DM_01336]）。
  2. 初始传输请求：诊断客户端发送 UDS 命令 0x38（ReadFile）。Diagnostic Server 通过 RequestReadFile(fileName, dataFormatIdentifier, metaInfo, cancellationHandler) 将该调用转发给应用程序（[SWS_DM_01314]、[SWS_DM_01331]）。
  3. 会话建立：应用程序检查该请求并异步返回一个 ara::core::Future，其中包含一个由已初始化的 DataTransferReadSession 和文件大小（FileSizes）组成的元组（[SWS_DM_01331]）。Diagnostic Management 对该 UDS 请求进行肯定响应。
  4. 块传输：针对客户端随后发出的每个 TransferData 请求（0x36），Diagnostic Server 会调用在会话中注册的 Handler 的读取方法（[SWS_DM_01317]）。
  5. 传输结束：完全传输后，客户端发送 RequestTransferExit（0x37）。Diagnostic Server 随后调用会话的 Exit 方法（[SWS_DM_01318]）并完成该过程。

时序图：根据 UDS 服务 0x38、0x36 和 0x37 的文件读取过程流程。来源：[SWS_DM_01314]、[SWS_DM_01317]、[SWS_DM_01318]、[SWS_DM_01331]、[SWS_DM_01336]。

错误场景

错误条件在系统的不同层中被捕获并报告：

  • 构造与建模错误：如果配置与系统模型不符，则实例化失败（[SWS_DM_01325]）：
    • InstanceSpecifierMappingIntegrityViolation：该标识符无法解析，或未指向 PortPrototype。
    • PortInterfaceMappingViolation：由 DiagnosticRequestFileTransferInterface 定型的 DEM 端口缺少 DiagnosticServiceGenericMapping。
    • ProcessMappingViolation：对于所建模的进程，不存在匹配的运行时进程。
    • InstanceSpecifierAlreadyInUseViolation：InstanceSpecifier 在进程内已被使用。
  • 多次提供：在已处于活动状态的实例上再次调用 Offer() 会返回带有 DiagOfferErrc::kAlreadyOffered 的错误（[SWS_DM_01336]）。
  • 诊断否定响应（NRC）：如果虚方法中的文件操作无法成功执行，应用程序会通过返回的 ara::core::Future 以及来自 ISO 14229-1 错误域 DiagUdsNrcErrc 的 UDS 否定响应码（NRC）指示此情况（[SWS_DM_01331]、[SWS_DM_01332]、[SWS_DM_01333]、[SWS_DM_01334]、[SWS_DM_01335]）。
  • 操作中止：在异步文件操作期间，应用程序可以通过参数 CancellationHandler 使用 cancellationHandler.IsCanceled() 持续检查中止状态，或通过 cancellationHandler.SetNotifier() 注册通知，以便在会话提前中止时立即释放资源（[SWS_DM_01331]、[SWS_DM_01335]）。

<h4>上下文</h4>
<p>接口类 <code>ara::diag::FileTransferService</code> (<a class="spec-record-ref" data-req="SWS_DM_01320" href="../spec/record.html?id=SWS_DM_01320">[SWS_DM_01320]</a>, <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=467">AUTOSAR_AP_SWS_Diagnostics §8.18 “Header: ara/diag/file_transfer.h”</a>) 在 AUTOSAR Adaptive 中提供了基于文件的诊断传输的功能抽象。它用于实现 UDS 服务 0x38 (RequestFileTransfer)，并支持跨进程边界对文件和目录信息进行标准化交换 (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=183">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”</a>)。</p>
<p>文件传输流程涉及三个主要组件：</p>
<ul>
<li><strong>Diagnose-Client:</strong> 通过标准化的 UDS 服务调用（RequestFileTransfer 0x38、TransferData 0x36 以及 RequestTransferExit 0x37）发起文件操作。</li>
<li><strong>Diagnostic Management (Diagnostic Server Instance):</strong> 接收客户端的诊断消息，处理协议操作，并将请求转发给已注册的 Service 实例 (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=184">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Realization of modeOfOperation”</a>)。</li>
<li><strong>Adaptive Application:</strong> 实现 <code>ara::diag::FileTransferService</code> 的业务回调方法，创建数据会话并访问本地文件系统。</li>
</ul>
<p>该架构支持不同的数据交换策略 (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=183">AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.20 “Service 0x38 – RequestFileTransfer”</a>)：</p>
<ul>
<li><strong>Simple:</strong> 在 Adaptive Application 与 Diagnostic Management 之间复制数据；适用于较小的文件大小。</li>
<li><strong>Zero Copy:</strong> 避免应用程序与 Diagnostic Management 之间的内存复制，以提高处理大数据量时的资源效率。</li>
<li><strong>OS File System Handle:</strong> 传递操作系统的原生文件句柄，以便直接传输而无需在诊断栈中进行复制开销。</li>
</ul>

<h4>生命周期</h4>
<p>类 <code>ara::diag::FileTransferService</code> 充当特定于应用程序的诊断 Handler 的基类。在实例化时，构造函数需要一个指向类型为 <code>DiagnosticRequestFileTransferInterface</code> 的建模 PortPrototype 的 <code>ara::core::InstanceSpecifier</code>，并通过 <code>ConcurrencyType</code> 指定并发行为 (<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>)。</p>
<p>实例关系和所有权关系受到严格规范：</p>
<ul>
<li><strong>Kopierschutz:</strong> 该类表示唯一实例；拷贝构造函数 (<a class="spec-record-ref" data-req="SWS_DM_01327" href="../spec/record.html?id=SWS_DM_01327">[SWS_DM_01327]</a>) 和拷贝赋值运算符 (<a class="spec-record-ref" data-req="SWS_DM_01329" href="../spec/record.html?id=SWS_DM_01329">[SWS_DM_01329]</a>) 已被删除 (<code>delete</code>)。</li>
<li><strong>Verschiebbarkeit:</strong> 移动构造函数 (<a class="spec-record-ref" data-req="SWS_DM_01328" href="../spec/record.html?id=SWS_DM_01328">[SWS_DM_01328]</a>) 和移动赋值运算符 (<a class="spec-record-ref" data-req="SWS_DM_01330" href="../spec/record.html?id=SWS_DM_01330">[SWS_DM_01330]</a>) 定义在 <code>protected</code> 作用域内。</li>
<li><strong>销毁：</strong>虚析构函数 <code>~FileTransferService()</code> (<a class="spec-record-ref" data-req="SWS_DM_01326" href="../spec/record.html?id=SWS_DM_01326">[SWS_DM_01326]</a>) 确保派生类的正确清理。</li>
</ul>
<p>功能生命周期由应用程序主动控制：</p>
<ol>
<li><strong>Bereitgestellt:</strong> 创建后，Diagnostic Management 尚不会将请求转发给该实例。</li>
<li><strong>Aktiv (Angeboten):</strong> 通过调用 <code>Offer()</code>，Diagnostic Management 获得授权将请求转接给 Service Handler (<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>)。</li>
<li><strong>Deaktiviert:</strong> 调用 <code>StopOffer()</code> 会撤销授权并阻止转发新请求 (<a class="spec-record-ref" data-req="SWS_DM_01337" href="../spec/record.html?id=SWS_DM_01337">[SWS_DM_01337]</a>)。</li>
</ol>
<p>关于线程安全性，AUTOSAR 进行了区分：接口的回调根据构造函数中传入的 <code>ConcurrencyType</code>（<code>kConcurrent</code> 或 <code>kNotConcurrent</code>）来调整其并发行为 (<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>)。相比之下，诸如 <code>Offer()</code>、<code>StopOffer()</code> 等管理方法以及析构函数则被指定为非线程安全 (<a class="spec-record-ref" data-req="SWS_DM_01326" href="../spec/record.html?id=SWS_DM_01326">[SWS_DM_01326]</a>, <a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>, <a class="spec-record-ref" data-req="SWS_DM_01337" href="../spec/record.html?id=SWS_DM_01337">[SWS_DM_01337]</a>)。</p>

<h4>使用路径</h4>
<p>该接口通过专用的纯虚方法涵盖了 UDS 服务 0x38 中定义的所有操作模式：</p>
<ul>
<li><code>RequestReadFile</code>: 在 <code>modeOfOperation</code> ReadFile (0x04) 时被调用 (<a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a>, <a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>)。</li>
<li><code>RequestWriteFile</code>: 在带有 <code>WriteFileMode::kReplace</code> 的 <code>modeOfOperation</code> ReplaceFile (0x03) (<a class="spec-record-ref" data-req="SWS_DM_01313" href="../spec/record.html?id=SWS_DM_01313">[SWS_DM_01313]</a>, <a class="spec-record-ref" data-req="SWS_DM_01324" href="../spec/record.html?id=SWS_DM_01324">[SWS_DM_01324]</a>, <a class="spec-record-ref" data-req="SWS_DM_01333" href="../spec/record.html?id=SWS_DM_01333">[SWS_DM_01333]</a>) 以及 kAdd 时被调用。</li>
<li><code>RequestResumeWriteFile</code>: 在 <code>modeOfOperation</code> ResumeFile (0x06) 时被调用 (<a class="spec-record-ref" data-req="SWS_DM_01316" href="../spec/record.html?id=SWS_DM_01316">[SWS_DM_01316]</a>, <a class="spec-record-ref" data-req="SWS_DM_01334" href="../spec/record.html?id=SWS_DM_01334">[SWS_DM_01334]</a>)。</li>
<li><code>RequestReadDirectory</code>: 在 <code>modeOfOperation</code> ReadDir (0x05) 时被调用 (<a class="spec-record-ref" data-req="SWS_DM_01315" href="../spec/record.html?id=SWS_DM_01315">[SWS_DM_01315]</a>, <a class="spec-record-ref" data-req="SWS_DM_01332" href="../spec/record.html?id=SWS_DM_01332">[SWS_DM_01332]</a>)。</li>
<li><code>DeleteFile</code>: 在 <code>modeOfOperation</code> DeleteFile 时执行文件的完全删除 (<a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>)。</li>
</ul>
<p>读取文件 (<code>ReadFile</code>) 的典型使用路径包括以下步骤：</p>
<ol>
<li><strong>提供：</strong>应用程序实例化其派生的服务类，并通过 <code>Offer()</code> 激活接口（<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>）。</li>
<li><strong>初始传输请求：</strong>诊断客户端发送 UDS 命令 0x38（ReadFile）。Diagnostic Server 通过 <code>RequestReadFile(fileName, dataFormatIdentifier, metaInfo, cancellationHandler)</code> 将该调用转发给应用程序（<a class="spec-record-ref" data-req="SWS_DM_01314" href="../spec/record.html?id=SWS_DM_01314">[SWS_DM_01314]</a>、<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>）。</li>
<li><strong>会话建立：</strong>应用程序检查该请求并异步返回一个 <code>ara::core::Future</code>，其中包含一个由已初始化的 <code>DataTransferReadSession</code> 和文件大小（<code>FileSizes</code>）组成的元组（<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>）。Diagnostic Management 对该 UDS 请求进行肯定响应。</li>
<li><strong>块传输：</strong>针对客户端随后发出的每个 TransferData 请求（0x36），Diagnostic Server 会调用在会话中注册的 Handler 的读取方法（<a class="spec-record-ref" data-req="SWS_DM_01317" href="../spec/record.html?id=SWS_DM_01317">[SWS_DM_01317]</a>）。</li>
<li><strong>传输结束：</strong>完全传输后，客户端发送 RequestTransferExit（0x37）。Diagnostic Server 随后调用会话的 <code>Exit</code> 方法（<a class="spec-record-ref" data-req="SWS_DM_01318" href="../spec/record.html?id=SWS_DM_01318">[SWS_DM_01318]</a>）并完成该过程。</li>
</ol>

<h4>错误场景</h4>
<p>错误条件在系统的不同层中被捕获并报告：</p>
<ul>
<li><strong>构造与建模错误：</strong>如果配置与系统模型不符，则实例化失败（<a class="spec-record-ref" data-req="SWS_DM_01325" href="../spec/record.html?id=SWS_DM_01325">[SWS_DM_01325]</a>）：
  <ul>
  <li><code>InstanceSpecifierMappingIntegrityViolation</code>：该标识符无法解析，或未指向 PortPrototype。</li>
  <li><code>PortInterfaceMappingViolation</code>：由 <code>DiagnosticRequestFileTransferInterface</code> 定型的 DEM 端口缺少 <code>DiagnosticServiceGenericMapping</code>。</li>
  <li><code>ProcessMappingViolation</code>：对于所建模的进程，不存在匹配的运行时进程。</li>
  <li><code>InstanceSpecifierAlreadyInUseViolation</code>：<code>InstanceSpecifier</code> 在进程内已被使用。</li>
  </ul>
</li>
<li><strong>多次提供：</strong>在已处于活动状态的实例上再次调用 <code>Offer()</code> 会返回带有 <code>DiagOfferErrc::kAlreadyOffered</code> 的错误（<a class="spec-record-ref" data-req="SWS_DM_01336" href="../spec/record.html?id=SWS_DM_01336">[SWS_DM_01336]</a>）。</li>
<li><strong>诊断否定响应（NRC）：</strong>如果虚方法中的文件操作无法成功执行，应用程序会通过返回的 <code>ara::core::Future</code> 以及来自 ISO 14229-1 错误域 <code>DiagUdsNrcErrc</code> 的 UDS 否定响应码（NRC）指示此情况（<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>、<a class="spec-record-ref" data-req="SWS_DM_01332" href="../spec/record.html?id=SWS_DM_01332">[SWS_DM_01332]</a>、<a class="spec-record-ref" data-req="SWS_DM_01333" href="../spec/record.html?id=SWS_DM_01333">[SWS_DM_01333]</a>、<a class="spec-record-ref" data-req="SWS_DM_01334" href="../spec/record.html?id=SWS_DM_01334">[SWS_DM_01334]</a>、<a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>）。</li>
<li><strong>操作中止：</strong>在异步文件操作期间，应用程序可以通过参数 <code>CancellationHandler</code> 使用 <code>cancellationHandler.IsCanceled()</code> 持续检查中止状态，或通过 <code>cancellationHandler.SetNotifier()</code> 注册通知，以便在会话提前中止时立即释放资源（<a class="spec-record-ref" data-req="SWS_DM_01331" href="../spec/record.html?id=SWS_DM_01331">[SWS_DM_01331]</a>、<a class="spec-record-ref" data-req="SWS_DM_01335" href="../spec/record.html?id=SWS_DM_01335">[SWS_DM_01335]</a>）。</li>
</ul>
