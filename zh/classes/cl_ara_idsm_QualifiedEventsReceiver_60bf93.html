上下文

类 ara::idsm::QualifiedEventsReceiver 在 AUTOSAR Adaptive Platform 的 idsm 模块内提供了用于从 Intrusion Detection System Manager (IdsM) 接收合格安全事件（Qualified Security Events，QSEv）的核心接口 [SWS_AIDSM_10800]。声明位于头文件 ara/idsm/qualified_events_receiver.h 中 [SWS_AIDSM_10800]。

在系统架构中，该实例充当设计中建模的 PPort（Provided Port）的接收器 [SWS_AIDSM_10801]。IdsM 对安全相关事件进行合格化并将其转发给已注册的接收器。解释：由于该接口定义了两个纯虚方法 OnEventQualification（[SWS_AIDSM_10807]、[SWS_AIDSM_10810]），因此该类充当抽象基类；Adaptive 应用程序派生出一个具体的接收器类，以按应用特定方式处理传入的安全事件。

生命周期

接收器实例的生命周期包括构造、激活、回调执行以及停用或销毁阶段：

  • 创建：实例化通过显式构造函数 QualifiedEventsReceiver(const ara::core::InstanceSpecifier& instance) 进行 [SWS_AIDSM_10801]。该构造函数将接收器绑定到指定的 PPort，并被指定为线程安全 [SWS_AIDSM_10801]。
  • 所有权与拷贝语义：该类遵循严格的 Move-Only 语义。拷贝构造函数 [SWS_AIDSM_10804] 和拷贝赋值运算符 [SWS_AIDSM_10806] 已删除（= delete）。相比之下，提供了线程安全的移动构造函数 [SWS_AIDSM_10803] 以及非线程安全的移动赋值运算符 [SWS_AIDSM_10805]，分别声明为 noexcept（[SWS_AIDSM_10803]、[SWS_AIDSM_10805]）。
  • 提供与停用：在实例化之后，只有通过调用 Offer() 才会接收事件，从而授权 IdsM 执行回调 [SWS_AIDSM_10808]。通过 StopOffer() 可再次阻止接收后续调用 [SWS_AIDSM_10809]。
  • 销毁：虚析构函数 ~QualifiedEventsReceiver() [SWS_AIDSM_10802] 释放所有关联资源。它被声明为非线程安全且为 noexcept [SWS_AIDSM_10802]。

使用路径

典型用例分为以下调用：

  1. 类派生：具体的接收器类继承自 ara::idsm::QualifiedEventsReceiver 并重写两个纯虚方法：
    • 用于无版本上下文数据的 OnEventQualification(EventIdType event, ara::core::Optional<ContextDataType> contextData, ara::core::Optional<TimestampType> timestamp) [SWS_AIDSM_10807]。
    • 用于带版本或不存在上下文数据的 OnEventQualification(EventIdType event, ara::core::Optional<VersionedContextDataType> contextData, ara::core::Optional<TimestampType> timestamp) [SWS_AIDSM_10810]。
  2. 实例化：创建派生的接收器对象，并传入建模的 PPort 的 ara::core::InstanceSpecifier [SWS_AIDSM_10801]。
  3. 服务提供：调用 Offer() 以激活接口 [SWS_AIDSM_10808]。返回的 ara::core::Result<void> 指示服务提供成功。
  4. 事件接收：当发生合格的 Security Events 时，IdsM 会调用已实现的 OnEventQualification 方法，并传入事件 ID 以及可选的上下文数据和时间戳（[SWS_AIDSM_10807]、[SWS_AIDSM_10810]）。
  5. 终止：为了结束接收，应用程序调用 StopOffer() [SWS_AIDSM_10809]。随后即可销毁该对象 [SWS_AIDSM_10802]。

时序图：注册、IdsM 对事件的限定以及接收终止的典型流程。来源：[SWS_AIDSM_10801]、[SWS_AIDSM_10807]、[SWS_AIDSM_10808]、[SWS_AIDSM_10809]、[SWS_AIDSM_10810]、[SWS_AIDSM_10802]。

错误场景

在使用该类时，需注意以下错误和同步条件：

  • 提供错误：Offer() 返回一个 ara::core::Result<void> [SWS_AIDSM_10808]。解释：如果配置的 PPort 无效，或者无法提供用于与 IdsM 交互的内部通信资源，则 Result 中可能会出现错误码。应用程序必须先检查该结果，然后才能假定事件接收已处于活动状态。
  • 异常安全性（noexcept）：所有方法和构造函数均被声明为 noexcept（[SWS_AIDSM_10801]、[SWS_AIDSM_10802]、[SWS_AIDSM_10803]、[SWS_AIDSM_10805]、[SWS_AIDSM_10807]、[SWS_AIDSM_10808]、[SWS_AIDSM_10809]、[SWS_AIDSM_10810]）。因此，在 OnEventQualification 的派生实现中不得抛出 C++ 异常，因为未处理的异常会直接导致 std::terminate。
  • 并发风险：除构造函数 [SWS_AIDSM_10801] 和移动构造函数 [SWS_AIDSM_10803] 之外，所有操作均被归类为非线程安全（[SWS_AIDSM_10802]、[SWS_AIDSM_10805]、[SWS_AIDSM_10807]、[SWS_AIDSM_10808]、[SWS_AIDSM_10809]、[SWS_AIDSM_10810]）。在未经应用端同步的情况下，并发调用 Offer()、StopOffer() 或析构操作会导致未定义行为。特别是，在销毁对象之前应确保已调用 StopOffer() 且不再有任何回调调用处于活动状态。

<h4>上下文</h4>
<p>类 <code>ara::idsm::QualifiedEventsReceiver</code> 在 AUTOSAR Adaptive Platform 的 <code>idsm</code> 模块内提供了用于从 Intrusion Detection System Manager (IdsM) 接收合格安全事件（Qualified Security Events，QSEv）的核心接口 <a class="spec-record-ref" data-req="SWS_AIDSM_10800" href="../spec/record.html?id=SWS_AIDSM_10800">[SWS_AIDSM_10800]</a>。声明位于头文件 <code>ara/idsm/qualified_events_receiver.h</code> 中 <a class="spec-record-ref" data-req="SWS_AIDSM_10800" href="../spec/record.html?id=SWS_AIDSM_10800">[SWS_AIDSM_10800]</a>。</p>
<p>在系统架构中，该实例充当设计中建模的 PPort（Provided Port）的接收器 <a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a>。IdsM 对安全相关事件进行合格化并将其转发给已注册的接收器。解释：由于该接口定义了两个纯虚方法 <code>OnEventQualification</code>（<a class="spec-record-ref" data-req="SWS_AIDSM_10807" href="../spec/record.html?id=SWS_AIDSM_10807">[SWS_AIDSM_10807]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10810" href="../spec/record.html?id=SWS_AIDSM_10810">[SWS_AIDSM_10810]</a>），因此该类充当抽象基类；Adaptive 应用程序派生出一个具体的接收器类，以按应用特定方式处理传入的安全事件。</p>

<h4>生命周期</h4>
<p>接收器实例的生命周期包括构造、激活、回调执行以及停用或销毁阶段：</p>
<ul>
<li><strong>创建：</strong>实例化通过显式构造函数 <code>QualifiedEventsReceiver(const ara::core::InstanceSpecifier&amp; instance)</code> 进行 <a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a>。该构造函数将接收器绑定到指定的 PPort，并被指定为线程安全 <a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a>。</li>
<li><strong>所有权与拷贝语义：</strong>该类遵循严格的 Move-Only 语义。拷贝构造函数 <a class="spec-record-ref" data-req="SWS_AIDSM_10804" href="../spec/record.html?id=SWS_AIDSM_10804">[SWS_AIDSM_10804]</a> 和拷贝赋值运算符 <a class="spec-record-ref" data-req="SWS_AIDSM_10806" href="../spec/record.html?id=SWS_AIDSM_10806">[SWS_AIDSM_10806]</a> 已删除（<code>= delete</code>）。相比之下，提供了线程安全的移动构造函数 <a class="spec-record-ref" data-req="SWS_AIDSM_10803" href="../spec/record.html?id=SWS_AIDSM_10803">[SWS_AIDSM_10803]</a> 以及非线程安全的移动赋值运算符 <a class="spec-record-ref" data-req="SWS_AIDSM_10805" href="../spec/record.html?id=SWS_AIDSM_10805">[SWS_AIDSM_10805]</a>，分别声明为 <code>noexcept</code>（<a class="spec-record-ref" data-req="SWS_AIDSM_10803" href="../spec/record.html?id=SWS_AIDSM_10803">[SWS_AIDSM_10803]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10805" href="../spec/record.html?id=SWS_AIDSM_10805">[SWS_AIDSM_10805]</a>）。</li>
<li><strong>提供与停用：</strong>在实例化之后，只有通过调用 <code>Offer()</code> 才会接收事件，从而授权 IdsM 执行回调 <a class="spec-record-ref" data-req="SWS_AIDSM_10808" href="../spec/record.html?id=SWS_AIDSM_10808">[SWS_AIDSM_10808]</a>。通过 <code>StopOffer()</code> 可再次阻止接收后续调用 <a class="spec-record-ref" data-req="SWS_AIDSM_10809" href="../spec/record.html?id=SWS_AIDSM_10809">[SWS_AIDSM_10809]</a>。</li>
<li><strong>销毁：</strong>虚析构函数 <code>~QualifiedEventsReceiver()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10802" href="../spec/record.html?id=SWS_AIDSM_10802">[SWS_AIDSM_10802]</a> 释放所有关联资源。它被声明为非线程安全且为 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10802" href="../spec/record.html?id=SWS_AIDSM_10802">[SWS_AIDSM_10802]</a>。</li>
</ul>

<h4>使用路径</h4>
<p>典型用例分为以下调用：</p>
<ol>
<li><strong>类派生：</strong>具体的接收器类继承自 <code>ara::idsm::QualifiedEventsReceiver</code> 并重写两个纯虚方法：
<ul>
<li>用于无版本上下文数据的 <code>OnEventQualification(EventIdType event, ara::core::Optional&lt;ContextDataType&gt; contextData, ara::core::Optional&lt;TimestampType&gt; timestamp)</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10807" href="../spec/record.html?id=SWS_AIDSM_10807">[SWS_AIDSM_10807]</a>。</li>
<li>用于带版本或不存在上下文数据的 <code>OnEventQualification(EventIdType event, ara::core::Optional&lt;VersionedContextDataType&gt; contextData, ara::core::Optional&lt;TimestampType&gt; timestamp)</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10810" href="../spec/record.html?id=SWS_AIDSM_10810">[SWS_AIDSM_10810]</a>。</li>
</ul>
</li>
<li><strong>实例化：</strong>创建派生的接收器对象，并传入建模的 PPort 的 <code>ara::core::InstanceSpecifier</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a>。</li>
<li><strong>服务提供：</strong>调用 <code>Offer()</code> 以激活接口 <a class="spec-record-ref" data-req="SWS_AIDSM_10808" href="../spec/record.html?id=SWS_AIDSM_10808">[SWS_AIDSM_10808]</a>。返回的 <code>ara::core::Result&lt;void&gt;</code> 指示服务提供成功。</li>
<li><strong>事件接收：</strong>当发生合格的 Security Events 时，IdsM 会调用已实现的 <code>OnEventQualification</code> 方法，并传入事件 ID 以及可选的上下文数据和时间戳（<a class="spec-record-ref" data-req="SWS_AIDSM_10807" href="../spec/record.html?id=SWS_AIDSM_10807">[SWS_AIDSM_10807]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10810" href="../spec/record.html?id=SWS_AIDSM_10810">[SWS_AIDSM_10810]</a>）。</li>
<li><strong>终止：</strong>为了结束接收，应用程序调用 <code>StopOffer()</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10809" href="../spec/record.html?id=SWS_AIDSM_10809">[SWS_AIDSM_10809]</a>。随后即可销毁该对象 <a class="spec-record-ref" data-req="SWS_AIDSM_10802" href="../spec/record.html?id=SWS_AIDSM_10802">[SWS_AIDSM_10802]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>在使用该类时，需注意以下错误和同步条件：</p>
<ul>
<li><strong>提供错误：</strong><code>Offer()</code> 返回一个 <code>ara::core::Result&lt;void&gt;</code> <a class="spec-record-ref" data-req="SWS_AIDSM_10808" href="../spec/record.html?id=SWS_AIDSM_10808">[SWS_AIDSM_10808]</a>。解释：如果配置的 PPort 无效，或者无法提供用于与 IdsM 交互的内部通信资源，则 Result 中可能会出现错误码。应用程序必须先检查该结果，然后才能假定事件接收已处于活动状态。</li>
<li><strong>异常安全性（noexcept）：</strong>所有方法和构造函数均被声明为 <code>noexcept</code>（<a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10802" href="../spec/record.html?id=SWS_AIDSM_10802">[SWS_AIDSM_10802]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10803" href="../spec/record.html?id=SWS_AIDSM_10803">[SWS_AIDSM_10803]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10805" href="../spec/record.html?id=SWS_AIDSM_10805">[SWS_AIDSM_10805]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10807" href="../spec/record.html?id=SWS_AIDSM_10807">[SWS_AIDSM_10807]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10808" href="../spec/record.html?id=SWS_AIDSM_10808">[SWS_AIDSM_10808]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10809" href="../spec/record.html?id=SWS_AIDSM_10809">[SWS_AIDSM_10809]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10810" href="../spec/record.html?id=SWS_AIDSM_10810">[SWS_AIDSM_10810]</a>）。因此，在 <code>OnEventQualification</code> 的派生实现中不得抛出 C++ 异常，因为未处理的异常会直接导致 <code>std::terminate</code>。</li>
<li><strong>并发风险：</strong>除构造函数 <a class="spec-record-ref" data-req="SWS_AIDSM_10801" href="../spec/record.html?id=SWS_AIDSM_10801">[SWS_AIDSM_10801]</a> 和移动构造函数 <a class="spec-record-ref" data-req="SWS_AIDSM_10803" href="../spec/record.html?id=SWS_AIDSM_10803">[SWS_AIDSM_10803]</a> 之外，所有操作均被归类为非线程安全（<a class="spec-record-ref" data-req="SWS_AIDSM_10802" href="../spec/record.html?id=SWS_AIDSM_10802">[SWS_AIDSM_10802]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10805" href="../spec/record.html?id=SWS_AIDSM_10805">[SWS_AIDSM_10805]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10807" href="../spec/record.html?id=SWS_AIDSM_10807">[SWS_AIDSM_10807]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10808" href="../spec/record.html?id=SWS_AIDSM_10808">[SWS_AIDSM_10808]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10809" href="../spec/record.html?id=SWS_AIDSM_10809">[SWS_AIDSM_10809]</a>、<a class="spec-record-ref" data-req="SWS_AIDSM_10810" href="../spec/record.html?id=SWS_AIDSM_10810">[SWS_AIDSM_10810]</a>）。在未经应用端同步的情况下，并发调用 <code>Offer()</code>、<code>StopOffer()</code> 或析构操作会导致未定义行为。特别是，在销毁对象之前应确保已调用 <code>StopOffer()</code> 且不再有任何回调调用处于活动状态。</li>
</ul>
