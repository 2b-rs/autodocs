上下文

类 ara::idsm::QualifiedEventsReceiver 代表 AUTOSAR Adaptive Platform 模块 idsm 中用于接收合格安全事件（Qualified Security Events，QSEv）的功能接口 [SWS_AIDSM_10800]。它用作软件设计中建模的提供端口（Provided-Port，PPort）的应用程序端端点 [SWS_AIDSM_10801]。

该概念基于抽象基类的原理：ara::idsm::QualifiedEventsReceiver 声明了纯虚回调方法 [SWS_AIDSM_10807]、[SWS_AIDSM_10810]。主要的交互对象是实现专用子类的自适应应用程序，以及检测合格安全事件并通过 PPort 转发给实例的 Intrusion Detection System Manager (IdsM)。

生命周期

接收器的创建是通过实例化继承自 QualifiedEventsReceiver 的类来进行的，同时指定引用建模 PPort 的 ara::core::InstanceSpecifier [SWS_AIDSM_10801]。此有参构造函数被指定为线程安全（thread-safe）[SWS_AIDSM_10801]。

关于所有权和值语义，该类被严格设计为仅移动（Move-Only）。拷贝构造函数 [SWS_AIDSM_10804] 和拷贝赋值运算符 [SWS_AIDSM_10806] 均已删除（= delete）。不过所有权转移是允许的：移动构造函数被实现为线程安全 [SWS_AIDSM_10803]，而移动赋值运算符不是线程安全的（not thread-safe）[SWS_AIDSM_10805]。

功能生命周期分为两个主要阶段：

  • 提供：实例化后不会立即传递任何事件。只有调用 Offer() 才会启用事件接收，并授权 IdsM 调用回调方法 [SWS_AIDSM_10808]。
  • 停用：通过方法 StopOffer() 阻止进一步接收事件 [SWS_AIDSM_10809]。

销毁通过虚析构函数 ~QualifiedEventsReceiver() 执行 [SWS_AIDSM_10802]。由于析构函数不是线程安全的，因此在释放接收器对象之前应始终执行 StopOffer()，以确保排除销毁过程中并发执行回调的情况。

使用路径

使用接收器的典型流程包括派生、提供和有序拆除：

  1. 类定义：应用程序定义一个子类，并重写两个纯虚方法：用于具有无版本上下文数据事件的 OnEventQualification() [SWS_AIDSM_10807]，以及用于有版本或空上下文数据的 [SWS_AIDSM_10810]。
  2. 实例化：实例化子类，并将端口的实例标识符传递给基类构造函数 [SWS_AIDSM_10801]。
  3. 通过 Offer 激活：应用程序调用 Offer() 以启动事件接收 [SWS_AIDSM_10808]。返回的 ara::core::Result<void> 确认成功启用。
  4. 事件接收：如果 IdsM 检测到合格安全事件，它会根据数据格式调用相应的回调方法：
    • 用于无版本数据的 OnEventQualification(EventIdType, ara::core::Optional<ContextDataType>, ara::core::Optional<TimestampType>) [SWS_AIDSM_10807]。
    • 用于有版本上下文数据或事件特有缺失数据的 OnEventQualification(EventIdType, ara::core::Optional<VersionedContextDataType>, ara::core::Optional<TimestampType>) [SWS_AIDSM_10810]。
  5. 停用与销毁：在应用程序终止之前调用 StopOffer() [SWS_AIDSM_10809]，并通过析构函数正常释放对象 [SWS_AIDSM_10802]。

错误场景

在使用时可能会出现各种错误条件和并发冲突：

  • Offer() 失败：方法 Offer() 返回 ara::core::Result<void> [SWS_AIDSM_10808]。Interpretation：如果建模的端口无法在系统中绑定，或者向 IdsM 注册失败，则 Result 对象会返回错误。应用程序只有在成功验证后，才能认为回调会被触发。
  • 缺失上下文或时间戳值：在两个回调签名中，上下文数据和时间戳都封装在 ara::core::Optional 中（[SWS_AIDSM_10807]、[SWS_AIDSM_10810]）。未经检查和验证的访问（例如访问空上下文数据）会导致应用程序处理逻辑中出现错误。
  • 非线程安全操作：除构造函数（[SWS_AIDSM_10801]、[SWS_AIDSM_10803]）外，所有操作——即 Offer() [SWS_AIDSM_10808]、StopOffer() [SWS_AIDSM_10809]、赋值运算符 [SWS_AIDSM_10805]、析构函数 [SWS_AIDSM_10802] 以及回调（[SWS_AIDSM_10807]、[SWS_AIDSM_10810]）——都不是线程安全的。从不同线程对 Offer() 或 StopOffer() 进行不协调的调用会导致未定义行为。
