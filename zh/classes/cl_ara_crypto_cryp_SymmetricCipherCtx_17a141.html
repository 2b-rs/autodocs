上下文

接口ara::crypto::cryp::SymmetricCipherCtx代表了AUTOSAR Adaptive Platform的crypto模块内用于对称加密和解密操作的核心抽象。它允许使用对称密钥材料安全地转换明文和密文。该上下文实例的生命周期和处理通常通过智能指针类型别名SymmetricCipherCtx::Sptr [SWS_CRYPT_50137]进行管理。

在应用程序架构中，SymmetricCipherCtx直接与调用方以及加密密钥对象交互。密钥材料既可以直接作为内存中密钥对象SymmetricKey::Sptr提供，也可以间接通过托管密钥槽KeySlot::Sptr集成。根据算法和工作模式，该上下文会处理初始化向量（IV）或Nonce，这些向量或Nonce要么由应用程序传递，要么由上下文自身生成。

生命周期

SymmetricCipherCtx的实例会经历由密钥提供和处理模式确定的明确定义的状态：

  • 未初始化（Uninitialized）：刚创建后，上下文没有绑定的密钥材料。在此状态下进行数据处理的调用将被拒绝并返回错误CryptoErrc::kUninitializedContext。通过SetKey()转换到就绪状态，其中可以选择配置KeySlot [SWS_CRYPT_50043]或SymmetricKey [SWS_CRYPT_50138]。
  • 已初始化 / 密钥已配置（Ready）：上下文已配置密钥。从该状态开始，既可以执行无状态单次调用（单次调用处理），也可以发起多阶段流式会话。
  • 流式处理活动（Processing）：通过调用Start()——无论带有显式初始化向量[SWS_CRYPT_23625]，还是不带或带有上下文自身的IV [SWS_CRYPT_50044]——启动流式处理。在此状态下，可以通过Update() [SWS_CRYPT_50139]连续转换数据。此外，在受支持的工作模式下，Seek() [SWS_CRYPT_23613]允许在数据流中重新定位。
  • 完成或中止：正在进行的流式事务要么通过Finish() [SWS_CRYPT_50045]或FinishEncrypt() [SWS_CRYPT_23618]正常完成，要么通过Cancel() [SWS_CRYPT_50046]放弃。在成功结束或中止后，上下文返回到已初始化的基本状态。

该接口的所有方法均被指定为异常安全（exception safe）和线程安全（thread-safe）。

使用路径

该规范支持用于加密和解密任务的两种主要执行路径：无状态单次调用和流式块处理。

在单次调用处理（Single-Call）中，所有数据都在单个操作中转换。根据IV处理方式，为此提供了三种方法：

  • ProcessSingleCall() [SWS_CRYPT_50047]用于既不需要也不返回IV的算法。
  • ProcessSingleCallWithInputIv() [SWS_CRYPT_50048]，当调用方显式指定初始化向量时。
  • EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049]，当执行加密且上下文将生成的IV返回给调用方时。

在流式处理中，转换通过多个缓冲区块增量进行。开始前可以确定缓冲区边界：GetMinimumChunkSize() [SWS_CRYPT_50144]和GetMaximumChunkSize() [SWS_CRYPT_50050]定义了最小和最大块大小。允许的IV长度可以使用GetMinimumInputIvSize() [SWS_CRYPT_50141]、GetMaximumInputIvSize() [SWS_CRYPT_50142]以及GetOutputIvSize() [SWS_CRYPT_50143]进行查询。所需的目标缓冲区大小视情况通过GetRequiredOutputBufferSize() [SWS_CRYPT_50140]进行计算。

典型流程分为：

  1. 通过SetKey() [SWS_CRYPT_50138]进行密钥配置。
  2. 通过Start()启动流式会话，并指定方向（CryptoTransform）和可选的IV [SWS_CRYPT_23625]。
  3. 通过Update() [SWS_CRYPT_50139]重复转换数据块。
  4. 通过Finish() [SWS_CRYPT_50045]或FinishEncrypt() [SWS_CRYPT_23618]进行最终完成以获取生成的IV。

错误场景

SymmetricCipherCtx的方法在操作失败时返回具有回滚语义的枚举ara::crypto::CryptoErrc的错误代码：

  • CryptoErrc::kUninitializedContext：如果在之前未配置兼容的密钥，则在Start() [SWS_CRYPT_23625] [SWS_CRYPT_50044]、ProcessSingleCall() [SWS_CRYPT_50047]、ProcessSingleCallWithInputIv() [SWS_CRYPT_50048]、EncryptSingleCallWithOutputIv() [SWS_CRYPT_50049]或GetRequiredOutputBufferSize() [SWS_CRYPT_50140]中发生。
  • CryptoErrc::kProcessingNotStarted：如果在之前未通过Start()启动流式操作的情况下调用流式相关方法（如Update() [SWS_CRYPT_50139]、Finish() [SWS_CRYPT_50045]、FinishEncrypt() [SWS_CRYPT_23618]、Seek() [SWS_CRYPT_23613]或Cancel() [SWS_CRYPT_50046]），则会触发此错误。
  • CryptoErrc::kInsufficientCapacity：在Update()、Finish()、FinishEncrypt()以及单次调用例程中指示传递的输出或IV缓冲区尺寸过小。
  • CryptoErrc::kInvalidInputSize / CryptoErrc::kInvalidArgument：指示无效的缓冲区大小、Seek()处的逐块未对齐或无效的输入数据。
  • CryptoErrc::kUsageViolation / CryptoErrc::kIncompatibleObject / CryptoErrc::kEmptyKeySlot：当密钥使用标志禁止请求的转换方向（例如缺少kAllowDataEncryption或kAllowDataDecryption）、密钥类型不兼容或引用的KeySlot为空时发生。
  • CryptoErrc::kUnsupported：表明具体上下文或算法不支持流式处理、定位（Seek）操作、单次调用或特定IV配置。

<h4>上下文</h4>
<p>接口<code>ara::crypto::cryp::SymmetricCipherCtx</code>代表了AUTOSAR Adaptive Platform的<code>crypto</code>模块内用于对称加密和解密操作的核心抽象。它允许使用对称密钥材料安全地转换明文和密文。该上下文实例的生命周期和处理通常通过智能指针类型别名<code>SymmetricCipherCtx::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50137" href="../spec/record.html?id=SWS_CRYPT_50137">[SWS_CRYPT_50137]</a>进行管理。</p>
<p>在应用程序架构中，<code>SymmetricCipherCtx</code>直接与调用方以及加密密钥对象交互。密钥材料既可以直接作为内存中密钥对象<code>SymmetricKey::Sptr</code>提供，也可以间接通过托管密钥槽<code>KeySlot::Sptr</code>集成。根据算法和工作模式，该上下文会处理初始化向量（IV）或Nonce，这些向量或Nonce要么由应用程序传递，要么由上下文自身生成。</p>

<h4>生命周期</h4>
<p><code>SymmetricCipherCtx</code>的实例会经历由密钥提供和处理模式确定的明确定义的状态：</p>
<ul>
  <li><strong>未初始化（Uninitialized）：</strong>刚创建后，上下文没有绑定的密钥材料。在此状态下进行数据处理的调用将被拒绝并返回错误<code>CryptoErrc::kUninitializedContext</code>。通过<code>SetKey()</code>转换到就绪状态，其中可以选择配置<code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50043" href="../spec/record.html?id=SWS_CRYPT_50043">[SWS_CRYPT_50043]</a>或<code>SymmetricKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a>。</li>
  <li><strong>已初始化 / 密钥已配置（Ready）：</strong>上下文已配置密钥。从该状态开始，既可以执行无状态单次调用（单次调用处理），也可以发起多阶段流式会话。</li>
  <li><strong>流式处理活动（Processing）：</strong>通过调用<code>Start()</code>——无论带有显式初始化向量<a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a>，还是不带或带有上下文自身的IV <a class="spec-record-ref" data-req="SWS_CRYPT_50044" href="../spec/record.html?id=SWS_CRYPT_50044">[SWS_CRYPT_50044]</a>——启动流式处理。在此状态下，可以通过<code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>连续转换数据。此外，在受支持的工作模式下，<code>Seek()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23613" href="../spec/record.html?id=SWS_CRYPT_23613">[SWS_CRYPT_23613]</a>允许在数据流中重新定位。</li>
  <li><strong>完成或中止：</strong>正在进行的流式事务要么通过<code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a>或<code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>正常完成，要么通过<code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50046" href="../spec/record.html?id=SWS_CRYPT_50046">[SWS_CRYPT_50046]</a>放弃。在成功结束或中止后，上下文返回到已初始化的基本状态。</li>
</ul>
<p>该接口的所有方法均被指定为异常安全（<em>exception safe</em>）和线程安全（<em>thread-safe</em>）。</p>

<h4>使用路径</h4>
<p>该规范支持用于加密和解密任务的两种主要执行路径：无状态单次调用和流式块处理。</p>
<p>在<strong>单次调用处理（Single-Call）</strong>中，所有数据都在单个操作中转换。根据IV处理方式，为此提供了三种方法：</p>
<ul>
  <li><code>ProcessSingleCall()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50047" href="../spec/record.html?id=SWS_CRYPT_50047">[SWS_CRYPT_50047]</a>用于既不需要也不返回IV的算法。</li>
  <li><code>ProcessSingleCallWithInputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50048" href="../spec/record.html?id=SWS_CRYPT_50048">[SWS_CRYPT_50048]</a>，当调用方显式指定初始化向量时。</li>
  <li><code>EncryptSingleCallWithOutputIv()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50049" href="../spec/record.html?id=SWS_CRYPT_50049">[SWS_CRYPT_50049]</a>，当执行加密且上下文将生成的IV返回给调用方时。</li>
</ul>
<p>在<strong>流式处理</strong>中，转换通过多个缓冲区块增量进行。开始前可以确定缓冲区边界：<code>GetMinimumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50144" href="../spec/record.html?id=SWS_CRYPT_50144">[SWS_CRYPT_50144]</a>和<code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50050" href="../spec/record.html?id=SWS_CRYPT_50050">[SWS_CRYPT_50050]</a>定义了最小和最大块大小。允许的IV长度可以使用<code>GetMinimumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50141" href="../spec/record.html?id=SWS_CRYPT_50141">[SWS_CRYPT_50141]</a>、<code>GetMaximumInputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50142" href="../spec/record.html?id=SWS_CRYPT_50142">[SWS_CRYPT_50142]</a>以及<code>GetOutputIvSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50143" href="../spec/record.html?id=SWS_CRYPT_50143">[SWS_CRYPT_50143]</a>进行查询。所需的目标缓冲区大小视情况通过<code>GetRequiredOutputBufferSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50140" href="../spec/record.html?id=SWS_CRYPT_50140">[SWS_CRYPT_50140]</a>进行计算。</p>
<p>典型流程分为：</p>
<ol>
  <li>通过<code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50138" href="../spec/record.html?id=SWS_CRYPT_50138">[SWS_CRYPT_50138]</a>进行密钥配置。</li>
  <li>通过<code>Start()</code>启动流式会话，并指定方向（<code>CryptoTransform</code>）和可选的IV <a class="spec-record-ref" data-req="SWS_CRYPT_23625" href="../spec/record.html?id=SWS_CRYPT_23625">[SWS_CRYPT_23625]</a>。</li>
  <li>通过<code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50139" href="../spec/record.html?id=SWS_CRYPT_50139">[SWS_CRYPT_50139]</a>重复转换数据块。</li>
  <li>通过<code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50045" href="../spec/record.html?id=SWS_CRYPT_50045">[SWS_CRYPT_50045]</a>或<code>FinishEncrypt()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_23618" href="../spec/record.html?id=SWS_CRYPT_23618">[SWS_CRYPT_23618]</a>进行最终完成以获取生成的IV。</li>
</ol>
