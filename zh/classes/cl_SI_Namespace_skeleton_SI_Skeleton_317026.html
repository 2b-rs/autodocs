上下文

生成的类 <SI-Namespace>::skeleton::<SI>Skeleton 构成了在模块 com（SWS CommunicationManagement 第39页）内提供 AUTOSAR Adaptive 服务接口的服务器端基础。它接收传入的方法调用，管理传出的事件和字段，并控制服务在整个系统中的功能可见性。

作为接口实例，Skeleton 主要与三种角色交互：

  • 服务器应用程序：创建 Skeleton 实例，实现与服务相关的方法体，并满足功能需求。
  • 通信基础设施 / 绑定：中间件负责请求的反序列化、通过协议特定绑定的路由以及权限和授权检查（SWS CommunicationManagement 第40页）。
  • 服务使用者（Proxy）：调用通过网络提供的方法，或订阅提供的事件和字段。

Skeleton 聚合了类型相关的成员，如事件（events::<Event>、[SWS_CM_99557]）、字段（fields::<Field>、[SWS_CM_99558]）和触发器元素（triggers::<Trigger>、[SWS_CM_99559]）。此外，还提供了用于方法调用输出参数的结构体（<MethodOutArgType> <MethodOutArg>、[SWS_CM_11550]）。为了防范传输错误和端到端完整性违规，该类提供了错误处理程序的注册方法（[SWS_CM_00093]、[SWS_CM_10470]）。

生命周期

Skeleton 的创建通过服务器应用程序的专用构造函数进行。根据系统设计和映射，有三种构造函数变体可用：

  • 通过显式实例标识符 ara::com::InstanceIdentifier 进行实例化（[SWS_CM_00130]）。
  • 通过引用 PortPrototype 的 ara::core::InstanceSpecifier 进行基于模型的绑定（[SWS_CM_00152]）。
  • 通过 ara::com::InstanceIdentifierContainer 进行实例化，以同时寻址多个实例或绑定（[SWS_CM_00153]）。

所有构造函数都接受模式 ara::com::MethodCallProcessingMode 作为可选参数，该模式默认预设为 kEvent（[SWS_CM_00130]、[SWS_CM_00152]、[SWS_CM_00153]）。

关于所有权关系，Skeleton 具有严格的同一性：复制构造函数（[SWS_CM_00134]）和复制赋值运算符（[SWS_CM_11548]）已被删除（delete）。资源的转移可以通过移动构造函数（[SWS_CM_00135]）和移动赋值运算符（[SWS_CM_11549]）进行。需要注意的是，移动构造函数被指定为非异常安全，而移动赋值运算符被声明为 noexcept。

成功构造后，Skeleton 最初保持在非活动状态。只有通过调用 OfferService()（[SWS_CM_00101]、ARAComAPI 第10页），服务才会在网络中切换为可见并对请求开放。可以使用 StopOfferService()（[SWS_CM_00111]、ARAComAPI 第10页）随时暂停或终止服务提供。解释：在最终销毁 Skeleton 实例之前，应调用 StopOfferService() 以确保在调用虚析构函数 ~<SI>Skeleton()（[SWS_CM_11370]）之前进行正确的注销。

使用路径

服务 Skeleton 的典型使用分为以下几个连续阶段：

  1. 实例化：创建对象，分配 InstanceIdentifier 或 InstanceSpecifier，并指定处理模式（[SWS_CM_00130]、[SWS_CM_00152]）。
  2. 配置与处理程序注册：通过 SetTransportFaultConditionHandler()（[SWS_CM_00093]、[SWS_CM_00094]）注册用于传输错误的可选错误处理例程，或重写虚 E2EErrorHandler()（[SWS_CM_10470]）。此外，可能存在的字段必须预先初始化。
  3. 提供服务：通过 OfferService()（[SWS_CM_00101]）激活 Skeleton。该方法返回一个 ara::core::Result<void>，指示成功或前提条件错误。
  4. 方法处理：如果 Skeleton 在模式 MethodCallProcessingMode::kPoll 下运行，应用程序将通过 ProcessNextMethodCall()（[SWS_CM_00199]）主动控制挂起的客户端调用的执行。这会在调用线程的上下文中直接执行挂起的方法。在事件驱动模式（kEvent）下，中间件负责分发。
  5. 停止服务与终止：调用 StopOfferService()（[SWS_CM_00111]）会使服务在网络中不再可见，随后通过析构函数释放实例（[SWS_CM_11370]）。

时序图：从提供服务、可选的轮询处理到终止服务的调用序列。来源：[SWS_CM_00101]、[SWS_CM_00111]、[SWS_CM_00199]、ARAComAPI 第10页。

错误场景

在 Skeleton 的运行和初始化过程中，指定了特定的错误条件和运行时违规（Violations）：

OfferService 时的错误代码（[SWS_CM_00101]）：在发生错误时，返回值 ara::core::Result<void> 传递具有明确回滚语义的枚举 ara::com::ComErrc 的值：

  • ComErrc::kFieldValueNotInitialized：已定义的字段在调用 OfferService() 之前尚未初始化。
  • ComErrc::kFieldSetHandlerNotSet：对于具有 Set 功能的字段，未注册 SetHandler。
  • ComErrc::kCommunicationFailure：绑定中发生了可恢复的网络或通信错误，或者安全连接失败。

运行时违规（Violations）：

  • 构造错误：如果权限检查失败，则会触发 InsufficientPermissionsViolation（[SWS_CM_00130]、[SWS_CM_00152]）。对于无效的处理模式，会导致 WrongMethodCallProcessingModeViolation。通过 InstanceSpecifier（[SWS_CM_00152]）进行实例化时，错误的映射会导致 InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation 或 InstanceSpecifierAlreadyInUseViolation。
  • 方法处理错误：如果在 Skeleton 配置为 kEvent 或 kEventSingleThread 的情况下调用了 ProcessNextMethodCall()，则会导致违规 WrongMethodCallProcessingModeViolation（[SWS_CM_00199]）。
  • 无效处理程序：向 SetTransportFaultConditionHandler() 传递空的或空值处理程序时，会发出 InvalidHandlerViolation 信号（[SWS_CM_00093]）。
  • 析构错误：如果在销毁 Skeleton 期间仍持有引用，则可能触发 DanglingSamplesViolation（[SWS_CM_11370]）。
  • E2E 错误处理：在 E2E 监控中发生 CRC 错误时，服务器代码不得信任传递给 E2EErrorHandler() 的 DataID，因为数据完整性错误可能会影响消息头（[SWS_CM_10470]）。此外，该处理程序不是可重入的。
