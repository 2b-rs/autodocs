用于在服务器端提供服务并处理传入的方法调用。

类 <SI-Namespace>::skeleton::<SI>Skeleton 用作在 AUTOSAR Adaptive Platform 中提供服务的服务器端基础，并将 Event、Field 和 Method 绑定到中间件。使用实例标识符进行实例化后，服务通过 OfferService() 对网络中的使用者可用，并可通过 StopOfferService() 重新撤回 [SWS_CM_00101]，[SWS_CM_00111]。根据所配置的处理模式，传入的方法调用要么基于事件进行处理，要么必须由应用程序通过轮询主动触发。由于复制操作已删除，实例的所有权严格保留在创建服务的应用程序中。

上下文

模板类 <SI-Namespace>::skeleton::<SI>Skeleton 构成在 AUTOSAR Adaptive Platform 上提供 Service Interface 的服务器端端点。作为应用程序逻辑与通信层之间的纽带，Skeleton 封装了特定于中间件的绑定并提供类型化接口元素。为此，该类通过 events::<Event> [SWS_CM_99557] 为 Event、通过 fields::<Field> [SWS_CM_99558] 为 Field、通过 triggers::<Trigger> [SWS_CM_99559] 为 Trigger 以及通过 <MethodOutArgType> [SWS_CM_11550] 为方法输出参数声明成员变量。解释：为了提供实际的服务功能，服务应用程序通常从 <SI>Skeleton 派生具体类，以完整实现接口方法。

生命周期

Skeleton 的实例化在指定实例映射和方法调用的处理模式（ara::com::MethodCallProcessingMode，默认为 kEvent）下进行。有效构造函数接受 ara::core::InstanceSpecifier [SWS_CM_00152]、单个 ara::com::InstanceIdentifier [SWS_CM_00130] 或通过 ara::com::InstanceIdentifierContainer [SWS_CM_00153] 接受一组标识符。由于服务端点的标识是唯一的，因此复制构造函数 [SWS_CM_00134] 和复制赋值运算符 [SWS_CM_11548] 已显式删除 (delete)。但可以通过移动构造函数 [SWS_CM_00135] 以及移动赋值运算符 [SWS_CM_11549] 转移资源。

构造之后，服务实例立即在本地创建，但在通信网络中尚不可见。只有通过调用 OfferService() [SWS_CM_00101]、EXP_ARAComAPI 第10页 才会对服务使用者进行发布。如果不再提供该服务，StopOfferService() 将撤回提供 [SWS_CM_00111]、EXP_ARAComAPI 第10页。之后可以重新提供 Skeleton 或通过虚析构函数 ~<SI>Skeleton() 将其销毁 [SWS_CM_11370]。

使用路径

提供服务的常规流程分为以下步骤：

  1. 配置和注册 Handler：在提供服务之前，可以存储特定于应用程序的 Handler。通过 SetTransportFaultConditionHandler() 注册传输错误 Handler，可直接注册 [SWS_CM_00093] 或带有用于异步任务的专用执行器 [SWS_CM_00094]；如有需要，可通过 UnsetTransportFaultConditionHandler() 将其移除 [SWS_CM_00095]。端到端错误处理可以通过虚方法 E2EErrorHandler() 覆盖 [SWS_CM_10470]。
  2. 提供服务：服务应用程序调用 OfferService() [SWS_CM_00101]。成功的调用返回一个空的 ara::core::Result<void> 并在网络上启用服务实例。
  3. 处理传入请求：如果 Skeleton 是在模式 MethodCallProcessingMode::kPoll 下实例化的，应用程序必须通过调用 ProcessNextMethodCall() 主动执行待处理的客户端调用 [SWS_CM_00199]。方法调用在该线程的上下文中执行；返回值指示是否还有更多调用待处理。
  4. 服务终止：在销毁实例之前，使用 StopOfferService() 终止提供 [SWS_CM_00111]。

错误场景

使用 Skeleton 类时，必须注意各种错误场景和前置条件：

  • 构造冲突：如果通过 Grant Enforcement 的授权失败，构造将中止并产生 InsufficientPermissionsViolation [SWS_CM_00130]、[SWS_CM_00152]、[SWS_CM_00153]。传入不允许的处理模式会导致 WrongMethodCallProcessingModeViolation。如果使用了 InstanceSpecifier，模型不一致或重复分配可能会引起错误 InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation 或 InstanceSpecifierAlreadyInUseViolation [SWS_CM_00152]。
  • 提供服务失败：如果 OfferService() 失败，将返回来自 ara::com::ComErrc 的错误码 [SWS_CM_00101]：ComErrc::kFieldValueNotInitialized（Field 事先未通过 Update() 初始化）、ComErrc::kFieldSetHandlerNotSet（缺少 Field 所需的 Set Handler）或 ComErrc::kCommunicationFailure（网络绑定的连接或安全错误）。
  • 处理模式冲突：如果 Skeleton 未配置为 kPoll，而是配置为 kEvent 或 kEventSingleThread，则调用 ProcessNextMethodCall() 会触发 WrongMethodCallProcessingModeViolation [SWS_CM_00199]。
  • 无效的错误 Handler：如果向 SetTransportFaultConditionHandler() 传递了不存在或空的 Callable，则会导致 InvalidHandlerViolation [SWS_CM_00093]、[SWS_CM_00094]。
  • E2E 错误和数据损坏：接收到损坏报文时，将带有相应 ComE2EErrc 调用 E2EErrorHandler() [SWS_CM_10470]。如果属于 CRC 错误，DataID 也可能损坏，因此应用程序不得将传入的标识符视为可靠。
  • 销毁错误：如果在销毁 Skeleton 时仍有未决的数据样本，析构函数将中止并产生 DanglingSamplesViolation [SWS_CM_11370]。
