上下文

类模板 ara::core::Bitset<std::size_t N> 在 AUTOSAR Adaptive Platform 的模块 core 中为安全相关车辆软件提供了标准类型 std::bitset 的适配。其声明位于头文件 ara/core/bitset.h 中。它用于高效管理和按位操作固定长度 N 的位序列。

与 ISO-C++ 原型相比，ara::core::Bitset 针对 AUTOSAR 的容错且无异常编程模型进行了专门适配。这尤其涉及与平台特定数据类型（如 ara::core::BasicString）的交互、在基于位置的操作中返回 ara::core::Result 以进行同步错误传递，以及转换为整型类型固定宽度的专用转换函数。

生命周期

ara::core::Bitset 的实例具有严格规范的生命周期行为，且位向量不采用动态内存管理。初始化可通过多种途径进行：

  • 默认初始化：无参默认构造函数 [SWS_CORE_01713] 被声明为 constexpr 和 noexcept，并将所有 N 个位预置为零值。
  • 整型初始化：通过构造函数 [SWS_CORE_01719]，可以从类型为 unsigned long long 的值创建位集，同样被声明为 constexpr 和 noexcept。
  • 从字符串初始化：通过 ara::core::BasicString，构造函数 [SWS_CORE_01749] 允许解析字符序列。该构造函数被定义为 noexcept。此外，还存在一个用于经典 C 字符串的构造函数，其接受类型为 const CharT* [SWS_CORE_01750] 的指针，该构造函数被归类为非异常安全（not exception safe）。

该类实现了完整的值语义。复制构造函数 [SWS_CORE_01714]、移动构造函数 [SWS_CORE_01716]、复制赋值运算符 [SWS_CORE_01715] 和移动赋值运算符 [SWS_CORE_01717] 均被显式指定为 noexcept=default。析构函数 [SWS_CORE_01718] 被声明为异常安全且线程安全。

使用路径

使用 ara::core::Bitset 的典型处理流程分为三个连续阶段：

  1. 创建与初始化：应用程序在编译时创建具有所需位宽度的位集，例如通过默认构造函数 [SWS_CORE_01713] 或通过转换位掩码 [SWS_CORE_01719]。
  2. 位操作与运算：
    • 整体修改通过 set() [SWS_CORE_01725]、reset() [SWS_CORE_01727] 和 flip() [SWS_CORE_01730] 进行。
    • 对位置 pos 处单个位的针对性操作通过 set(pos, val) [SWS_CORE_01726]、reset(pos) [SWS_CORE_01728] 或 flip(pos) [SWS_CORE_01731] 进行。
    • 逻辑位运算通过复合赋值运算符提供，例如 operator&= [SWS_CORE_01720]、operator|= [SWS_CORE_01721] 和 operatorˆ= [SWS_CORE_01722]。按位取反通过 operator~ [SWS_CORE_01729] 提供。
    • 位的移位通过 operator<<= [SWS_CORE_01723]、operator>>= [SWS_CORE_01724] 以及相应的移位运算符 [SWS_CORE_01747] 和 [SWS_CORE_01748] 实现。
    • 对单个位的读写访问可以直接通过带索引的 operator[] [SWS_CORE_01732]（常量）或 [SWS_CORE_01733]（引用）进行。
  3. 求值与转换：
    • 状态检查通过 all() [SWS_CORE_01744]、any() [SWS_CORE_01745]、none() [SWS_CORE_01746]、count() [SWS_CORE_01740] 以及 size() [SWS_CORE_01741] 执行。两个实例的相等性由 operator== [SWS_CORE_01742] 检查。单个位置由 test(pos) [SWS_CORE_01743] 检查。
    • 对于反向转换，ara::core::Bitset 除了提供 to_ulong() [SWS_CORE_01734]、to_ullong() [SWS_CORE_01735] 和 to_string() [SWS_CORE_01751] 外，还提供了专用的线程安全定宽转换：to_uint8t() [SWS_CORE_01736]、to_uint16t() [SWS_CORE_01737]、to_uint32t() [SWS_CORE_01738] 和 to_uint64t() [SWS_CORE_01739]。

错误场景

Adaptive Platform 在 ara::core::Bitset 中未使用 C++ 标准异常，而是采用了统一的违规与错误模型，且大多数方法均严格使用 noexcept 声明：

  • 位置违规（Out of Range）：基于位置的修饰符 set(pos, val) [SWS_CORE_01726]、reset(pos) [SWS_CORE_01728] 和 flip(pos) [SWS_CORE_01731] 返回一个 ara::core::Result。如果 pos 不是有效的位位置，则会触发违规 IsoStdOutOfRangeViolation（而非 std::out_of_range）。查询函数 test(pos) [SWS_CORE_01743] 在位置无效时也会触发 IsoStdOutOfRangeViolation。
  • 字符串解析错误：在基于 ara::core::BasicString [SWS_CORE_01749] 的构造函数中，起始位置 pos > size() 会导致违规 IsoStdOutOfRangeViolation。若被解析的字符串包含既不是零也不是一的字符，则会发出 IsoStdInvalidArgumentViolation 信号（而非 std::invalid_argument）。
  • 转换溢出：若位集中表示的整数值无法在对应的返回类型中表示，则转换函数 to_ulong() [SWS_CORE_01734]、to_ullong() [SWS_CORE_01735] 以及 to_uint8t() [SWS_CORE_01736]、to_uint16t() [SWS_CORE_01737]、to_uint32t() [SWS_CORE_01738] 和 to_uint64t() [SWS_CORE_01739] 会触发违规 IsoStdOverflowErrorViolation（而非 std::overflow_error）。
  • 异常安全性：虽然该类中几乎所有函数都被指定为 exception safe，但基于 const CharT* [SWS_CORE_01750] 的构造函数以及 to_string() [SWS_CORE_01751] 被明确归类为 not exception safe，这推测是由字符串处理过程中的动态内存分配所致。

      <strong>默认初始化：</strong>无参默认构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01713" href="../spec/record.html?id=SWS_CORE_01713">[SWS_CORE_01713]</a> 被声明为 <code>constexpr</code> 和 <code>noexcept</code>，并将所有 <code>N</code> 个位预置为零值。
    </li>
    <li>
      <strong>整型初始化：</strong>通过构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01719" href="../spec/record.html?id=SWS_CORE_01719">[SWS_CORE_01719]</a>，可以从类型为 <code>unsigned long long</code> 的值创建位集，同样被声明为 <code>constexpr</code> 和 <code>noexcept</code>。
    </li>
    <li>
      <strong>从字符串初始化：</strong>通过 <code>ara::core::BasicString</code>，构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01749" href="../spec/record.html?id=SWS_CORE_01749">[SWS_CORE_01749]</a> 允许解析字符序列。该构造函数被定义为 <code>noexcept</code>。此外，还存在一个用于经典 C 字符串的构造函数，其接受类型为 <code>const CharT*</code> <a class="spec-record-ref" data-req="SWS_CORE_01750" href="../spec/record.html?id=SWS_CORE_01750">[SWS_CORE_01750]</a> 的指针，该构造函数被归类为非异常安全（<em>not exception safe</em>）。
    </li>
  </ul>
  <p>
    该类实现了完整的值语义。复制构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01714" href="../spec/record.html?id=SWS_CORE_01714">[SWS_CORE_01714]</a>、移动构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01716" href="../spec/record.html?id=SWS_CORE_01716">[SWS_CORE_01716]</a>、复制赋值运算符 <a class="spec-record-ref" data-req="SWS_CORE_01715" href="../spec/record.html?id=SWS_CORE_01715">[SWS_CORE_01715]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_CORE_01717" href="../spec/record.html?id=SWS_CORE_01717">[SWS_CORE_01717]</a> 均被显式指定为 <code>noexcept=default</code>。析构函数 <a class="spec-record-ref" data-req="SWS_CORE_01718" href="../spec/record.html?id=SWS_CORE_01718">[SWS_CORE_01718]</a> 被声明为异常安全且线程安全。

  <h4>错误场景</h4>
  <p>
    Adaptive Platform 在 <code>ara::core::Bitset</code> 中未使用 C++ 标准异常，而是采用了统一的违规与错误模型，且大多数方法均严格使用 <code>noexcept</code> 声明：
  </p>
  <ul>
    <li>
      <strong>位置违规（Out of Range）：</strong>基于位置的修饰符 <code>set(pos, val)</code> <a class="spec-record-ref" data-req="SWS_CORE_01726" href="../spec/record.html?id=SWS_CORE_01726">[SWS_CORE_01726]</a>、<code>reset(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01728" href="../spec/record.html?id=SWS_CORE_01728">[SWS_CORE_01728]</a> 和 <code>flip(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01731" href="../spec/record.html?id=SWS_CORE_01731">[SWS_CORE_01731]</a> 返回一个 <code>ara::core::Result</code>。如果 <code>pos</code> 不是有效的位位置，则会触发违规 <code>IsoStdOutOfRangeViolation</code>（而非 <code>std::out_of_range</code>）。查询函数 <code>test(pos)</code> <a class="spec-record-ref" data-req="SWS_CORE_01743" href="../spec/record.html?id=SWS_CORE_01743">[SWS_CORE_01743]</a> 在位置无效时也会触发 <code>IsoStdOutOfRangeViolation</code>。
    </li>
    <li>
      <strong>字符串解析错误：</strong>在基于 <code>ara::core::BasicString</code> <a class="spec-record-ref" data-req="SWS_CORE_01749" href="../spec/record.html?id=SWS_CORE_01749">[SWS_CORE_01749]</a> 的构造函数中，起始位置 <code>pos &gt; size()</code> 会导致违规 <code>IsoStdOutOfRangeViolation</code>。若被解析的字符串包含既不是零也不是一的字符，则会发出 <code>IsoStdInvalidArgumentViolation</code> 信号（而非 <code>std::invalid_argument</code>）。
    </li>
    <li>
      <strong>转换溢出：</strong>若位集中表示的整数值无法在对应的返回类型中表示，则转换函数 <code>to_ulong()</code> <a class="spec-record-ref" data-req="SWS_CORE_01734" href="../spec/record.html?id=SWS_CORE_01734">[SWS_CORE_01734]</a>、<code>to_ullong()</code> <a class="spec-record-ref" data-req="SWS_CORE_01735" href="../spec/record.html?id=SWS_CORE_01735">[SWS_CORE_01735]</a> 以及 <code>to_uint8t()</code> <a class="spec-record-ref" data-req="SWS_CORE_01736" href="../spec/record.html?id=SWS_CORE_01736">[SWS_CORE_01736]</a>、<code>to_uint16t()</code> <a class="spec-record-ref" data-req="SWS_CORE_01737" href="../spec/record.html?id=SWS_CORE_01737">[SWS_CORE_01737]</a>、<code>to_uint32t()</code> <a class="spec-record-ref" data-req="SWS_CORE_01738" href="../spec/record.html?id=SWS_CORE_01738">[SWS_CORE_01738]</a> 和 <code>to_uint64t()</code> <a class="spec-record-ref" data-req="SWS_CORE_01739" href="../spec/record.html?id=SWS_CORE_01739">[SWS_CORE_01739]</a> 会触发违规 <code>IsoStdOverflowErrorViolation</code>（而非 <code>std::overflow_error</code>）。
    </li>
    <li>
      <strong>异常安全性：</strong>虽然该类中几乎所有函数都被指定为 <code>exception safe</code>，但基于 <code>const CharT*</code> <a class="spec-record-ref" data-req="SWS_CORE_01750" href="../spec/record.html?id=SWS_CORE_01750">[SWS_CORE_01750]</a> 的构造函数以及 <code>to_string()</code> <a class="spec-record-ref" data-req="SWS_CORE_01751" href="../spec/record.html?id=SWS_CORE_01751">[SWS_CORE_01751]</a> 被明确归类为 <em>not exception safe</em>，这推测是由字符串处理过程中的动态内存分配所致。
    </li>
  </ul>
