为 Adaptive Core 提供符合标准、具有 noexcept 保证且固定大小的类型安全位域抽象。

类模板 ara::core::Bitset 为固定大小的位序列提供了适配 AUTOSAR Adaptive 的 std::bitset 实现 [SWS_CORE_01741]。它提供了全面的位操作运算、逻辑运算以及转换为标量整数类型的优化转换，并具有严格的 noexcept 保证 [SWS_CORE_01738]。基于位置的修改通过 ara::core::Result 报告无效索引而非抛出 C++ 异常，而转换则确定性地处理溢出错误。因此，该类特别适用于资源高效且具故障容容性的 ECU 功能。

上下文

模板类 ara::core::Bitset 在 Adaptive Platform 中为编译期确定长度 N 的位序列提供了 C++ 标准类型 std::bitset 的实现 [SWS_CORE_01741]。在 AUTOSAR 生态系统中，该类用于在 ECU 上高性能且类型安全地处理位域、状态掩码和标志寄存器。它通过支持平台特定类型 ara::core::BasicString 代替 std::basic_string，无缝集成到模块 core 的类型系统中 [SWS_CORE_01749]、[SWS_CORE_01751]。此外，AUTOSAR 扩展了标准化接口，增加了专用于转换为无符号固定宽度整数类型（如 std::uint8_t、std::uint16_t、std::uint32_t 和 std::uint64_t）的转换函数 [SWS_CORE_01736]、[SWS_CORE_01737]、[SWS_CORE_01738]、[SWS_CORE_01739]。

生命周期

实例的创建通过多个构造函数灵活完成。默认构造函数将所有 N 位初始化为零值，并声明为 constexpr 以及 noexcept [SWS_CORE_01713]。或者，可以从 unsigned long long 类型的标量值 [SWS_CORE_01719]，或基于文本从 ara::core::BasicString [SWS_CORE_01749] 或以 null 结尾的字符串指针 const CharT* 实例化 Bitset [SWS_CORE_01750]。提供了拷贝和移动构造函数，并定义为 noexcept=default [SWS_CORE_01714]、[SWS_CORE_01716]。同样也提供了相应的赋值运算符 [SWS_CORE_01715]、[SWS_CORE_01717]。析构函数被指定为 noexcept 且是线程安全的 [SWS_CORE_01718]。在并发性方面，整数转换函数同样是线程安全的 [SWS_CORE_01736]、[SWS_CORE_01737]，而对同一 Bitset 实例的修改访问必须进行同步。

使用路径

典型的使用路径包括实例化、随后操作单个位或位掩码，以及最后对位域进行求值或转换：

  • 创建：Bitset 通常使用初始值创建 [SWS_CORE_01719]，或通过默认构造函数初始化 [SWS_CORE_01713]。
  • 操作：可以通过基于位置调用 set [SWS_CORE_01726]、reset [SWS_CORE_01728] 和 flip [SWS_CORE_01731] 来修改单个位。对于整个位域，提供了 set [SWS_CORE_01725]、reset [SWS_CORE_01727] 和 flip [SWS_CORE_01730] 的无参变体，以及按位逻辑与移位运算符，如 operator&= [SWS_CORE_01720]、operator|= [SWS_CORE_01721]、operatorˆ= [SWS_CORE_01722]、operator~ [SWS_CORE_01729]、operator<<= [SWS_CORE_01723] 和 operator>>= [SWS_CORE_01724]。
  • 求值：状态可通过 test [SWS_CORE_01743]、operator[] [SWS_CORE_01732]、[SWS_CORE_01733] 或谓词如 all [SWS_CORE_01744]、any [SWS_CORE_01745]、none [SWS_CORE_01746] 以及 count [SWS_CORE_01740] 查询。
  • 转换：为了进一步处理，位域内容可以转换为数值固定宽度类型，例如通过 to_uint32t [SWS_CORE_01738]，或者使用 to_string 导出为字符串 [SWS_CORE_01751]。

错误场景

与 std::bitset 相比，ara::core::Bitset 采用了无异常（noexcept）的容错、确定性错误处理概念：

  • 位置访问越界：在修改函数 set(pos) [SWS_CORE_01726]、reset(pos) [SWS_CORE_01728] 和 flip(pos) [SWS_CORE_01731] 中，使用了返回类型 Result<Bitset<N>&>。若 pos 超出有效范围，则会报告 IsoStdOutOfRangeViolation 而非 std::out_of_range。解释：一致使用 ara::core::Result 和 noexcept 推测是为了遵循 Adaptive Platform 安全关键领域中严格的无异常要求。检查函数 test(pos) 在 pos 无效时也会指示 IsoStdOutOfRangeViolation [SWS_CORE_01743]。
  • 无效字符串：从 ara::core::BasicString [SWS_CORE_01749] 构造时，若出现 pos > size() 会触发 IsoStdOutOfRangeViolation，若出现不等于 0 或 1 的字符则会触发 IsoStdInvalidArgumentViolation（而非 std::invalid_argument）。
  • 数值溢出：如果所表示的位状态无法在所请求的目标类型中表示，则转换函数 to_uint8t [SWS_CORE_01736]、to_uint16t [SWS_CORE_01737]、to_uint32t [SWS_CORE_01738]、to_uint64t [SWS_CORE_01739]、to_ulong [SWS_CORE_01734] 和 to_ullong [SWS_CORE_01735] 将分别报告 IsoStdOverflowErrorViolation 而非 std::overflow_error。
  • 受限的异常安全性：虽然大多数操作均为 noexcept 且是异常安全的，但从指针构造 const CharT* [SWS_CORE_01750] 以及使用 to_string [SWS_CORE_01751] 导出被明确归类为非异常安全（not exception safe）。
