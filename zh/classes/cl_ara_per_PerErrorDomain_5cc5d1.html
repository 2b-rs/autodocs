上下文

类 ara::per::PerErrorDomain 定义了 AUTOSAR Adaptive Platform 内针对持久化模块（ara::per）的特定错误域。作为派生自 ara::core::ErrorDomain 且声明为 final 的特化，它将持久化特定的错误集成到平台的统一错误处理概念中。其核心任务在于对错误情况进行语义界定，并将错误代码转换为文本描述或异常。

为了实现统一的类型化，PerErrorDomain 提供了两个重要的类型别名：

  • Errc [SWS_PER_00411]：充当枚举 PerErrc 的别名，该枚举定义了持久化模块的具体错误代码。
  • Exception [SWS_PER_00412]：定义了基异常类 PerException 的别名，该基异常类在模块发生错误时抛出。

主要交互对象包括模块 ara::per 的存储与持久化服务（例如键值存储或文件操作）、封装错误值并将其绑定到该域的平台类型 ara::core::ErrorCode，以及生成诊断输出或通过异常传递错误的应用软件组件。

生命周期

错误域的实例通过默认构造函数 PerErrorDomain() [SWS_PER_00313] 创建。根据规范，该构造函数声明为 noexcept，并且是异常安全的（exception safe）以及线程安全的（thread-safe）。它不需要初始化参数，并将该域初始化为就绪状态。

在生命周期和所有权方面，该类遵循 AUTOSAR Adaptive 的域模型（解释：该实例通常可能是一个长寿命、全进程可用的单例或静态实例化的对象，以便 ara::core::ErrorCode 实例在其整个生命周期内安全引用错误域）。必须避免在现有错误对象的生命周期内过早销毁域对象。

关于并发性，所有成员函数——即构造函数 [SWS_PER_00313]、Name() [SWS_PER_00314]、Message() [SWS_PER_00315] 以及 ThrowAsException() [SWS_PER_00350]——均被指定为线程安全（thread-safe）。该类不执行有状态的变更，也不具有内部生命周期阶段或状态转换。构造完成后，可以在没有外部同步的情况下从任意线程并发使用该域。

使用路径

常规流程包括提供、识别域以及对持久化错误进行求值和转换：

  1. 实例化：错误域在需要时或系统启动时通过 PerErrorDomain() [SWS_PER_00313] 初始化。
  2. 域识别：框架或诊断工具可以通过 Name() [SWS_PER_00314] 获取域的符号标识符。
  3. 错误消息解析：如果持久化子系统中发生错误，数字错误值（类型 CodeType 或 Errc [SWS_PER_00411]）将通过方法 Message() [SWS_PER_00315] 转换为有意义的以 null 结尾的文本（const char*）。
  4. 异常处理：若在应用程序中使用异常进行错误传播，则运行时系统将使用相关错误代码调用方法 ThrowAsException() [SWS_PER_00350]，该方法抛出相应的 Exception（PerException [SWS_PER_00412]）。

错误场景

使用 PerErrorDomain 时，必须注意系统特定的边界条件以及接口的错误与异常行为：

  • 有保证的异常安全性：方法 Name() [SWS_PER_00314] 和 Message() [SWS_PER_00315] 声明为 noexcept，并被指定为异常安全（exception safe）。它们绝不会失败，并提供可靠的诊断字符串。
  • 通过 ThrowAsException() 抛出异常：与其余方法不同，ThrowAsException() [SWS_PER_00350] 声明为 noexcept(false) 并归类为非异常安全（not exception safe），因为该函数按预期抛出异常并中断调用层次结构。
  • 禁用 C++ 异常：如果编译器工具链在不支持 C++ 异常的情况下运行，则 ThrowAsException() [SWS_PER_00350] 不参与重载解析。在此类环境中尝试调用将直接导致编译时错误。
  • 未定义的错误代码：如果向 Message() [SWS_PER_00315] 传递了不对应于 Errc [SWS_PER_00411] 中任何已知值的数字错误代码，则该方法可能会返回通用的默认文本（解释：该方法为 noexcept，并且必须始终提供指向以 null 结尾的字符串的有效指针，以防止未定义行为）。

<h4>上下文</h4>
<p>类 <code>ara::per::PerErrorDomain</code> 定义了 AUTOSAR Adaptive Platform 内针对持久化模块（<code>ara::per</code>）的特定错误域。作为派生自 <code>ara::core::ErrorDomain</code> 且声明为 <code>final</code> 的特化，它将持久化特定的错误集成到平台的统一错误处理概念中。其核心任务在于对错误情况进行语义界定，并将错误代码转换为文本描述或异常。</p>
<p>为了实现统一的类型化，<code>PerErrorDomain</code> 提供了两个重要的类型别名：</p>
<ul>
<li><code>Errc</code> <a class="spec-record-ref" data-req="SWS_PER_00411" href="../spec/record.html?id=SWS_PER_00411">[SWS_PER_00411]</a>：充当枚举 <code>PerErrc</code> 的别名，该枚举定义了持久化模块的具体错误代码。</li>
<li><code>Exception</code> <a class="spec-record-ref" data-req="SWS_PER_00412" href="../spec/record.html?id=SWS_PER_00412">[SWS_PER_00412]</a>：定义了基异常类 <code>PerException</code> 的别名，该基异常类在模块发生错误时抛出。</li>
</ul>
<p>主要交互对象包括模块 <code>ara::per</code> 的存储与持久化服务（例如键值存储或文件操作）、封装错误值并将其绑定到该域的平台类型 <code>ara::core::ErrorCode</code>，以及生成诊断输出或通过异常传递错误的应用软件组件。</p>

<h4>生命周期</h4>
<p>错误域的实例通过默认构造函数 <code>PerErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_PER_00313" href="../spec/record.html?id=SWS_PER_00313">[SWS_PER_00313]</a> 创建。根据规范，该构造函数声明为 <code>noexcept</code>，并且是异常安全的（<em>exception safe</em>）以及线程安全的（<em>thread-safe</em>）。它不需要初始化参数，并将该域初始化为就绪状态。</p>
<p>在生命周期和所有权方面，该类遵循 AUTOSAR Adaptive 的域模型（解释：该实例通常可能是一个长寿命、全进程可用的单例或静态实例化的对象，以便 <code>ara::core::ErrorCode</code> 实例在其整个生命周期内安全引用错误域）。必须避免在现有错误对象的生命周期内过早销毁域对象。</p>
<p>关于并发性，所有成员函数——即构造函数 <a class="spec-record-ref" data-req="SWS_PER_00313" href="../spec/record.html?id=SWS_PER_00313">[SWS_PER_00313]</a>、<code>Name()</code> <a class="spec-record-ref" data-req="SWS_PER_00314" href="../spec/record.html?id=SWS_PER_00314">[SWS_PER_00314]</a>、<code>Message()</code> <a class="spec-record-ref" data-req="SWS_PER_00315" href="../spec/record.html?id=SWS_PER_00315">[SWS_PER_00315]</a> 以及 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_PER_00350" href="../spec/record.html?id=SWS_PER_00350">[SWS_PER_00350]</a>——均被指定为线程安全（<em>thread-safe</em>）。该类不执行有状态的变更，也不具有内部生命周期阶段或状态转换。构造完成后，可以在没有外部同步的情况下从任意线程并发使用该域。</p>

<h4>使用路径</h4>
<p>常规流程包括提供、识别域以及对持久化错误进行求值和转换：</p>
<ol>
<li><strong>实例化：</strong>错误域在需要时或系统启动时通过 <code>PerErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_PER_00313" href="../spec/record.html?id=SWS_PER_00313">[SWS_PER_00313]</a> 初始化。</li>
<li><strong>域识别：</strong>框架或诊断工具可以通过 <code>Name()</code> <a class="spec-record-ref" data-req="SWS_PER_00314" href="../spec/record.html?id=SWS_PER_00314">[SWS_PER_00314]</a> 获取域的符号标识符。</li>
<li><strong>错误消息解析：</strong>如果持久化子系统中发生错误，数字错误值（类型 <code>CodeType</code> 或 <code>Errc</code> <a class="spec-record-ref" data-req="SWS_PER_00411" href="../spec/record.html?id=SWS_PER_00411">[SWS_PER_00411]</a>）将通过方法 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_PER_00315" href="../spec/record.html?id=SWS_PER_00315">[SWS_PER_00315]</a> 转换为有意义的以 null 结尾的文本（<code>const char*</code>）。</li>
<li><strong>异常处理：</strong>若在应用程序中使用异常进行错误传播，则运行时系统将使用相关错误代码调用方法 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_PER_00350" href="../spec/record.html?id=SWS_PER_00350">[SWS_PER_00350]</a>，该方法抛出相应的 <code>Exception</code>（<code>PerException</code> <a class="spec-record-ref" data-req="SWS_PER_00412" href="../spec/record.html?id=SWS_PER_00412">[SWS_PER_00412]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>使用 <code>PerErrorDomain</code> 时，必须注意系统特定的边界条件以及接口的错误与异常行为：</p>
<ul>
<li><strong>有保证的异常安全性：</strong>方法 <code>Name()</code> <a class="spec-record-ref" data-req="SWS_PER_00314" href="../spec/record.html?id=SWS_PER_00314">[SWS_PER_00314]</a> 和 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_PER_00315" href="../spec/record.html?id=SWS_PER_00315">[SWS_PER_00315]</a> 声明为 <code>noexcept</code>，并被指定为异常安全（<em>exception safe</em>）。它们绝不会失败，并提供可靠的诊断字符串。</li>
<li><strong>通过 <code>ThrowAsException()</code> 抛出异常：</strong>与其余方法不同，<code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_PER_00350" href="../spec/record.html?id=SWS_PER_00350">[SWS_PER_00350]</a> 声明为 <code>noexcept(false)</code> 并归类为非异常安全（<em>not exception safe</em>），因为该函数按预期抛出异常并中断调用层次结构。</li>
<li><strong>禁用 C++ 异常：</strong>如果编译器工具链在不支持 C++ 异常的情况下运行，则 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_PER_00350" href="../spec/record.html?id=SWS_PER_00350">[SWS_PER_00350]</a> 不参与重载解析。在此类环境中尝试调用将直接导致编译时错误。</li>
<li><strong>未定义的错误代码：</strong>如果向 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_PER_00315" href="../spec/record.html?id=SWS_PER_00315">[SWS_PER_00315]</a> 传递了不对应于 <code>Errc</code> <a class="spec-record-ref" data-req="SWS_PER_00411" href="../spec/record.html?id=SWS_PER_00411">[SWS_PER_00411]</a> 中任何已知值的数字错误代码，则该方法可能会返回通用的默认文本（解释：该方法为 <code>noexcept</code>，并且必须始终提供指向以 null 结尾的字符串的有效指针，以防止未定义行为）。</li>
</ul>
