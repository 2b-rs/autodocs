该接口允许应用程序在 Adaptive 平台内创建、解析和管理 X.509 证书、证书吊销列表以及验证上下文（[SWS_CRYPT_40614]）。除了检查证书链之外，它还与加密子系统协作控制签名请求和 OCSP 查询的创建。它还封装了通过标准化实例标识符在单个证书槽以及证书组中的持久存储（[SWS_CRYPT_40621]）。所有操作均设计为线程安全，并且为了避免多次实例化，要求通过无拷贝或移动权限的智能指针进行严格引用。

上下文

在 AUTOSAR Adaptive Platform 中，类 ara::crypto::x509::X509Provider 构成了符合 X.509 标准的公钥基础设施（PKI）工件的核心抽象和管理接口。它将应用程序进程与加密驱动程序的厂商特定实现细节解耦，并为证书和证书吊销列表（CRL）的解析、创建和持久存储提供了统一的机制。

该接口主要与三个功能区域进行交互：

  • 应用程序 / 安全服务：使用该接口解码序列化的证书（[SWS_CRYPT_40614]）或证书链（[SWS_CRYPT_40616]），生成可分辨名称（[SWS_CRYPT_50186]、[SWS_CRYPT_50187]），并提供专用验证上下文（[SWS_CRYPT_50125]）。
  • 持久证书存储：允许通过 ara::core::InstanceSpecifier 在单个证书槽（[SWS_CRYPT_40621]、[SWS_CRYPT_40641]、[SWS_CRYPT_40622]）中或在配置的证书组（[SWS_CRYPT_50126]、[SWS_CRYPT_50127]、[SWS_CRYPT_50128]）内对证书进行持久保存、读取和删除。
  • 加密子系统（ara::crypto::cryp）：提供密钥和签名上下文（例如 cryp::SignerPrivateCtx 和 cryp::PublicKey），用于根据 RFC 2986 签发证书签名请求（CSR）（[SWS_CRYPT_40640]）或根据 RFC 6960 签发已签名的 OCSP 请求（[SWS_CRYPT_40626]、[SWS_CRYPT_40627]）。

生命周期

接口 X509Provider 被定义为抽象类。在应用程序级别，通过标准化的智能指针 Sptr（std::shared_ptr<X509Provider> 的别名）来引用和管理实例（[SWS_CRYPT_40601]）。特定于平台的实现的实际实例化大概是通过加密模块的上层入口点完成的（解释）。

为了防止多次实例化以及不受控的拷贝或移动操作，显式删除了拷贝构造函数（[SWS_CRYPT_41013]）、移动构造函数（[SWS_CRYPT_41014]）以及相应的赋值运算符（[SWS_CRYPT_30226]、[SWS_CRYPT_30227]）（=delete）。生命周期随着通过虚析构函数 ~X509Provider()（[SWS_CRYPT_40604]）进行的销毁而结束。

在并发性方面，该类的所有成员函数均被指定为线程安全（thread-safe）和异常安全（exception safe）（其中包括 [SWS_CRYPT_40614]、[SWS_CRYPT_40621]、[SWS_CRYPT_50125]）。因此，多个线程可以并行使用同一个 Provider 实例，而无需手动同步机制。

使用路径

用于注册、存储和随后检查证书的典型流程包括以下步骤：

  1. 解析：通过传递内存区域和格式标识符，使用 ParseCert 读取以二进制或文本方式序列化的 X.509v3 证书，并将其转换为瞬态证书对象（[SWS_CRYPT_40614]）。对于证书链，等效提供 ParseCertChain（[SWS_CRYPT_40616]）。
  2. 持久存储：证书对象通过 ImportCertificate 永久保存在由实例标识符寻址的槽中（[SWS_CRYPT_40621]），或者通过 ImportCertificateInGroup 分配给某个证书组（[SWS_CRYPT_50127]）。已存储的证书可在需要时通过 LoadCertificate（[SWS_CRYPT_40641]）或 LoadCertificateGroup（[SWS_CRYPT_50126]）加载。
  3. 创建验证上下文：为了检查证书，通过 CreateCertificateValidationCtx 创建一个上下文对象（[SWS_CRYPT_50125]）。
  4. 管理吊销信息：为了确保吊销状态，可以通过 ImportCrl 导入 CRL（[SWS_CRYPT_50183]），或者通过 CreateOcspRequest 生成 OCSP 请求（[SWS_CRYPT_40626]）并使用 ParseOcspResponse 评估其响应（[SWS_CRYPT_50185]）。

时序图：解析、存储和准备证书验证的流程。来源：[SWS_CRYPT_40614]、[SWS_CRYPT_40621]、[SWS_CRYPT_50125]

错误场景

该接口通过 ara::core::Result 发出错误信号，而不使用 C++ 异常。错误处理分为功能性加密错误代码和流程性配置违规。

功能性错误代码（ara::crypto::CryptoErrc）包括：

  • kInvalidArgument：无法解释输入格式（例如在 ParseCert [SWS_CRYPT_40614]、ParseCertChain [SWS_CRYPT_40616]、ImportCrl [SWS_CRYPT_50183] 或 CreateDn [SWS_CRYPT_50186] 中缓冲区错误时），或者在 CreateCertSignRequest 中公钥与私有签名密钥不匹配（[SWS_CRYPT_40640]）。
  • kUnsupportedFormat：指定的格式标识符（FormatId）未知或不受支持（[SWS_CRYPT_40614]、[SWS_CRYPT_50185]）。
  • kBusyResource：持久资源或加密上下文暂时被阻塞（[SWS_CRYPT_40621]、[SWS_CRYPT_40622]、[SWS_CRYPT_40626]）。
  • kEmptyCertificateSlot：在调用 LoadCertificate 时发生，如果寻址的槽不包含持久化的证书（[SWS_CRYPT_40641]）。
  • kInsufficientCapacity：当证书组的容量不足以进行另一次导入时发生（[SWS_CRYPT_50127]）。
  • kNoSuchValue：当从组中移除的证书在该组中找不到时报告（[SWS_CRYPT_50128]）。
  • kUninitializedContext：签名上下文在调用 CreateCertSignRequest（[SWS_CRYPT_40640]）或 CreateOcspRequest（[SWS_CRYPT_40626]）之前未用密钥初始化。

在架构层面上区分清单冲突和权限冲突：

  • ProcessMappingViolation：传递的 InstanceSpecifier 未指向为正在运行的进程建模的 CryptoCertificateInterface 或 CryptoCertificateGroupInterface 类型的 Port-Prototype（[SWS_CRYPT_40621]、[SWS_CRYPT_40641]、[SWS_CRYPT_50126]）。
  • InsufficientPermissionsViolation：对于建模的 Port-Prototype，清单中未配置写权限（writeAccess != True），而这对于导入或删除方法是绝对必需的前提条件（[SWS_CRYPT_40621]、[SWS_CRYPT_40622]、[SWS_CRYPT_50127]、[SWS_CRYPT_50183]、[SWS_CRYPT_50184]）。
