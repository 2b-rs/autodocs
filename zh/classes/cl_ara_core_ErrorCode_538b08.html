类 ara::core::ErrorCode

[SWS_CORE_00501] Upstream: RS_AP_00130, RS_AP_00140

class ErrorCode final {...};

Encapsulation of an error code. An ErrorCode contains a raw error code value and an Error Domain. The raw error code value is specific to this ErrorDomain.

使用目的

ErrorCode封装了特定于域的原始错误值、对相关ErrorDomain的引用以及可选的制造商特定的附加数据。该类型是文字类型。 [SWS_CORE_00501][SWS_CORE_10302][SWS_CORE_10300]

生成与交互

它可以从错误枚举或值、错误域和附加数据创建。 Domain()、Value()、SupportData()和Message()分别提供其组件和错误文本； ThrowAsException() 确定跨域的适当异常类型。 [SWS_CORE_00512][SWS_CORE_00513][SWS_CORE_00515][SWS_CORE_00514][SWS_CORE_00516][SWS_CORE_00518][SWS_CORE_00519]

限制&错误处理

比较仅考虑误差值和误差域，而不考虑附加数据。 ErrorCode及其成员可以独立于ara::core::Initialize和Deinitialize使用。 [SWS_CORE_10301][SWS_CORE_15002]

使用错误上下文，而非通用错误值

ErrorCode将类型化错误值与其ErrorDomain上下文相关联；可选地，它可以携带消息和附加的制造商特定信息。 ARA 接口在Result 内使用它来处理可恢复的错误。 EXP InterfacesGuidelines §3.1.2 “Result”EXP ARAComAPI §4.7 “Error Handling”

制造商特定的错误代码需要自己的ErrorDomain；可移植的、堆栈中立的应用程序应将此类Domain视为一般默认情况。 EXP InterfacesGuidelines §3.1.5 “Standardized vs Vendor-specific ErrorCodes”

协作图：ErrorCode 从其域获取上下文和消息；异常转换是显式异常路径。来源：EXP InterfacesGuidelines §3.1.2 “Result” RS General §4.1.3 “The use of noexcept”。

输入已删除的错误值

SWS 将 ErrorCode 描述为具有 Domain 上下文的错误值：特定于 Domain 的代码经类型擦除后成为一个整数值，以便统一传输；还可传递额外的支持数据。比较会考虑值和 Domain，而不考虑支持数据。SWS Core §7.2 “Error handling” SWS Core §7.2.5.1 “ErrorCode” [SWS_CORE_10301] [SWS_CORE_10302]
