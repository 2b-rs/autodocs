类 ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

上下文

ara::log::Logger类代表 AUTOSAR Adaptive 应用程序进程或进程区域内的日志记录上下文。此类上下文封装了日志记录的核心属性：上下文 ID、该上下文 ID 的关联描述以及可配置的默认日志级别（Default Log Level）。通过这些上下文，系统内的日志输出得以进行区分和控制。

在系统架构中，ara::log::Logger充当三个参与方之间的中介：

  • 应用程序进程（Application Process）：使用ara::log::Logger的实例来发送消息、动态查询或调整过滤阈值。
  • 日志框架：对所有 Logger 实例保持严格的所有权（“strong ownership”），通过诸如ara::log::CreateLogger等工厂函数控制其创建，并负责内务管理。
  • 日志后端：接收实际的日志数据；Logger 上下文在初始化阶段自动向后端注册，并在进程有序关闭期间注销。

上下文图：Logger 类在与应用程序、日志框架和后端交互中的嵌入情况。来源：[SWS_LOG_00259]

生命周期

ara::log::Logger实例的管理受到框架的严格控制，以确保与日志后端的无缝同步：

  • 创建与所有权关系：默认构造函数已被显式删除（Logger() = delete、[SWS_LOG_00259]）。禁止应用程序直接实例化。创建过程通过诸如ara::log::CreateLogger等函数受控进行。所有权保留在日志框架中。
  • 注册与清理：Logger 上下文在创建时会自动向日志后端注册。在进程终止时，注销会自动进行，从而减轻了应用程序开发人员手动管理生命周期的负担。
  • 销毁：规范了析构函数~Logger()（[SWS_LOG_00260]）。它被声明为线程安全，但被标明为非异常安全（“not exception safe”）（[SWS_LOG_00260]）。
  • 并发性：所有用于日志记录和阈值查询的方法均被规范为线程安全（[SWS_LOG_00070]、[SWS_LOG_00255]、[SWS_LOG_00064]）。多个线程可以并行使用同一个 Logger 实例。

使用路径

发送日志消息的典型流程分为以下几个阶段：

  1. 检查或配置过滤阈值：应用程序可以在运行时通过SetThreshold(threshold)设置实例的过滤阈值（[SWS_LOG_00255]）。在进行计算密集型的日志数据准备之前，可以使用IsEnabled(logLevel)查询所需的日志级别是否满足已配置的报告阈值（[SWS_LOG_00070]）。如果检查返回false，则可以跳过准备工作。
  2. 启动基于流的日志记录：对于文本日志记录，该类为每个严重级别都提供了特定方法：
    • LogFatal() ([SWS_LOG_00064])
    • LogError() ([SWS_LOG_00065])
    • LogWarn() ([SWS_LOG_00066])
    • LogInfo() ([SWS_LOG_00067])
    • LogDebug() ([SWS_LOG_00068])
    • LogVerbose() ([SWS_LOG_00069])
    • WithLevel(logLevel)（[SWS_LOG_00131]）用于以编程方式确定紧急程度。
    这些方法中的每一个都返回一个LogStream对象，该对象通过流运算符<<接收参数（[SWS_LOG_00064]）。
  3. 流生命周期与输出：在默认情况下，LogStream对象的生命周期仅限于单个语句，并在最后一个参数之后的分号处结束（[SWS_LOG_00064]）。如果需要，可以将流分配给一个变量，以便将其生命周期扩展到多个语句（[SWS_LOG_00064]）。
  4. 输出建模消息：作为流式传输的替代方案，可以通过Log(id, args...)输出预先建模的消息（[SWS_LOG_00204]）。如果要传递额外的属性，则通过带有属性元组的LogWith(attrs, msgId, params...)进行调用（[SWS_LOG_00133]）。

错误场景

ara::log::Logger中的错误处理主要基于编译时的静态类型检查和严格的异常安全性：

  • 建模消息的参数不匹配：如果调用模板函数Log(id, args...)时传入的参数与建模消息的定义不完全匹配，则程序格式错误（“ill-formed”）（[SWS_LOG_00204]）。这会导致编译时出错。
  • LogWith 中的无效属性：对于LogWith(attrs, msgId, params...)，如果属性元组的某个元素不是有效属性，则该函数将通过 SFINAE 从重载解析中排除（[SWS_LOG_00133]）。
  • 异常保证：所有日志记录和查询函数（包括IsEnabled、SetThreshold、所有Log*方法、WithLevel、Log和LogWith）均被规范为异常安全（“exception safe”），并使用noexcept进行声明（[SWS_LOG_00070]、[SWS_LOG_00255]、[SWS_LOG_00064]、[SWS_LOG_00131]、[SWS_LOG_00204]、[SWS_LOG_00133]）。析构函数~Logger()是一个例外，它被列为非异常安全（“not exception safe”）（[SWS_LOG_00260]）。解释：这可能意味着在后端内务管理过程中的内部清理或释放错误发生时，错误状态未能被完全捕获，因此注销应在常规进程关闭期间进行。

<h4>上下文</h4>
<p><code>ara::log::Logger</code>类代表 AUTOSAR Adaptive 应用程序进程或进程区域内的日志记录上下文。此类上下文封装了日志记录的核心属性：上下文 ID、该上下文 ID 的关联描述以及可配置的默认日志级别（Default Log Level）。通过这些上下文，系统内的日志输出得以进行区分和控制。</p>
<p>在系统架构中，<code>ara::log::Logger</code>充当三个参与方之间的中介：</p>
<ul>
<li><strong>应用程序进程（Application Process）：</strong>使用<code>ara::log::Logger</code>的实例来发送消息、动态查询或调整过滤阈值。</li>
<li><strong>日志框架：</strong>对所有 Logger 实例保持严格的所有权（“strong ownership”），通过诸如<code>ara::log::CreateLogger</code>等工厂函数控制其创建，并负责内务管理。</li>
<li><strong>日志后端：</strong>接收实际的日志数据；Logger 上下文在初始化阶段自动向后端注册，并在进程有序关闭期间注销。</li>
</ul>

<h4>生命周期</h4>
<p><code>ara::log::Logger</code>实例的管理受到框架的严格控制，以确保与日志后端的无缝同步：</p>
<ul>
<li><strong>创建与所有权关系：</strong>默认构造函数已被显式删除（<code>Logger() = delete</code>、<a class="spec-record-ref" data-req="SWS_LOG_00259" href="../spec/record.html?id=SWS_LOG_00259">[SWS_LOG_00259]</a>）。禁止应用程序直接实例化。创建过程通过诸如<code>ara::log::CreateLogger</code>等函数受控进行。所有权保留在日志框架中。</li>
<li><strong>注册与清理：</strong>Logger 上下文在创建时会自动向日志后端注册。在进程终止时，注销会自动进行，从而减轻了应用程序开发人员手动管理生命周期的负担。</li>
<li><strong>销毁：</strong>规范了析构函数<code>~Logger()</code>（<a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>）。它被声明为线程安全，但被标明为非异常安全（“not exception safe”）（<a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>）。</li>
<li><strong>并发性：</strong>所有用于日志记录和阈值查询的方法均被规范为线程安全（<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>）。多个线程可以并行使用同一个 Logger 实例。</li>
</ul>

<h4>使用路径</h4>
<p>发送日志消息的典型流程分为以下几个阶段：</p>
<ol>
<li><strong>检查或配置过滤阈值：</strong>应用程序可以在运行时通过<code>SetThreshold(threshold)</code>设置实例的过滤阈值（<a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>）。在进行计算密集型的日志数据准备之前，可以使用<code>IsEnabled(logLevel)</code>查询所需的日志级别是否满足已配置的报告阈值（<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>）。如果检查返回<code>false</code>，则可以跳过准备工作。</li>
<li><strong>启动基于流的日志记录：</strong>对于文本日志记录，该类为每个严重级别都提供了特定方法：
<ul>
<li><code>LogFatal()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>)</li>
<li><code>LogError()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00065" href="../spec/record.html?id=SWS_LOG_00065">[SWS_LOG_00065]</a>)</li>
<li><code>LogWarn()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00066" href="../spec/record.html?id=SWS_LOG_00066">[SWS_LOG_00066]</a>)</li>
<li><code>LogInfo()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00067" href="../spec/record.html?id=SWS_LOG_00067">[SWS_LOG_00067]</a>)</li>
<li><code>LogDebug()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00068" href="../spec/record.html?id=SWS_LOG_00068">[SWS_LOG_00068]</a>)</li>
<li><code>LogVerbose()</code> (<a class="spec-record-ref" data-req="SWS_LOG_00069" href="../spec/record.html?id=SWS_LOG_00069">[SWS_LOG_00069]</a>)</li>
<li><code>WithLevel(logLevel)</code>（<a class="spec-record-ref" data-req="SWS_LOG_00131" href="../spec/record.html?id=SWS_LOG_00131">[SWS_LOG_00131]</a>）用于以编程方式确定紧急程度。</li>
</ul>
这些方法中的每一个都返回一个<code>LogStream</code>对象，该对象通过流运算符<code>&lt;&lt;</code>接收参数（<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>）。</li>
<li><strong>流生命周期与输出：</strong>在默认情况下，<code>LogStream</code>对象的生命周期仅限于单个语句，并在最后一个参数之后的分号处结束（<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>）。如果需要，可以将流分配给一个变量，以便将其生命周期扩展到多个语句（<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>）。</li>
<li><strong>输出建模消息：</strong>作为流式传输的替代方案，可以通过<code>Log(id, args...)</code>输出预先建模的消息（<a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>）。如果要传递额外的属性，则通过带有属性元组的<code>LogWith(attrs, msgId, params...)</code>进行调用（<a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p><code>ara::log::Logger</code>中的错误处理主要基于编译时的静态类型检查和严格的异常安全性：</p>
<ul>
<li><strong>建模消息的参数不匹配：</strong>如果调用模板函数<code>Log(id, args...)</code>时传入的参数与建模消息的定义不完全匹配，则程序格式错误（“ill-formed”）（<a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>）。这会导致编译时出错。</li>
<li><strong>LogWith 中的无效属性：</strong>对于<code>LogWith(attrs, msgId, params...)</code>，如果属性元组的某个元素不是有效属性，则该函数将通过 SFINAE 从重载解析中排除（<a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>）。</li>
<li><strong>异常保证：</strong>所有日志记录和查询函数（包括<code>IsEnabled</code>、<code>SetThreshold</code>、所有<code>Log*</code>方法、<code>WithLevel</code>、<code>Log</code>和<code>LogWith</code>）均被规范为异常安全（“exception safe”），并使用<code>noexcept</code>进行声明（<a class="spec-record-ref" data-req="SWS_LOG_00070" href="../spec/record.html?id=SWS_LOG_00070">[SWS_LOG_00070]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00255" href="../spec/record.html?id=SWS_LOG_00255">[SWS_LOG_00255]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00064" href="../spec/record.html?id=SWS_LOG_00064">[SWS_LOG_00064]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00131" href="../spec/record.html?id=SWS_LOG_00131">[SWS_LOG_00131]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00204" href="../spec/record.html?id=SWS_LOG_00204">[SWS_LOG_00204]</a>、<a class="spec-record-ref" data-req="SWS_LOG_00133" href="../spec/record.html?id=SWS_LOG_00133">[SWS_LOG_00133]</a>）。析构函数<code>~Logger()</code>是一个例外，它被列为非异常安全（“not exception safe”）（<a class="spec-record-ref" data-req="SWS_LOG_00260" href="../spec/record.html?id=SWS_LOG_00260">[SWS_LOG_00260]</a>）。解释：这可能意味着在后端内务管理过程中的内部清理或释放错误发生时，错误状态未能被完全捕获，因此注销应在常规进程关闭期间进行。</li>
</ul>
