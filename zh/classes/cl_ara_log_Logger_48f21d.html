类 ara::log::Logger

[SWS_LOG_00172] Upstream: RS_LT_00003, RS_LT_00046

class Logger final {...};

Represents a logger context. The Logging framework defines contexts which can be seen as logger instances within one Application process or process scope. The contexts have the following properties: • Context ID • Description of the Context ID • Default log level A context will be automatically registered against the Logging backend during creation phase, as well as automatically deregistered during process shutdown phase. So the end user does not care for the objects life time. To ensure such housekeeping functionality, a strong ownership of the logger instances needs to be ensured towards the Logging framework. This means that the Application process are not supposed to call the Logger constructor themselves. The user is not allowed to create a Logger object by himself. Logger context needs to be created by one of the ara::log::CreateLogger functions.

封装日志记录上下文，用于以线程安全的方式记录格式化或模型化日志消息。

类 ara::log::Logger 表示通过临时流或模型化消息格式在应用程序进程内记录日志消息的上下文 [SWS_LOG_00064]。由于默认构造函数已被删除，因此生命周期的创建和管理完全由日志记录框架负责 [SWS_LOG_00259]。在耗时准备消息数据之前，可以查询当前活动的报告级别。该类的所有接口均指定为线程安全，并允许从多个线程进行无同步调用。

上下文

类 ara::log::Logger 表示模块 log 中应用程序进程或进程区域内的 Logger 上下文。此类上下文封装了特定的上下文 ID、关联的描述以及默认日志级别。应用程序开发人员与 Logger 实例交互，以通过诸如 LogStream [SWS_LOG_00064] 等流对象或作为结构化的模型化消息将日志消息传递给日志记录框架 [SWS_LOG_00204]。这些实例充当应用程序内部线程与日志记录后端之间的中介。

上下文图：Logger 在应用程序、日志记录框架和 LogStream 之间的集成。来源：[SWS_LOG_00064]、[SWS_LOG_00259]。

生命周期

实例的管理受日志框架的严格所有权控制。为了确保在创建时自动向日志后端注册并在应用程序进程关闭时注销，默认构造函数已被删除 [SWS_LOG_00259]。应用程序不得且无法直接实例化 Logger 对象，而是必须使用创建函数 ara::log::CreateLogger。销毁和释放通过析构函数 [SWS_LOG_00260] 进行，该函数由日志框架控制，因此用户无需关心生命周期。

关于并发性，所有访问方法均被指定为线程安全（thread-safe），其中包括 [SWS_LOG_00070]、[SWS_LOG_00255] 和 [SWS_LOG_00260]。因此，多个并发线程可以同时使用相同的记录器上下文，而无需在应用程序端使用额外的同步机制。

使用路径

记录器的典型使用包括检查当前配置、调整阈值以及发送消息：

  • 检查输出权限：在进行复杂的日志数据准备之前，可以使用 IsEnabled 查询是否主动报告了所需的日志级别 [SWS_LOG_00070]。
  • 配置：记录器实例的最小报告阈值可以在运行时通过 SetThreshold 重新配置 [SWS_LOG_00255]。
  • 基于流的日志记录：通过用于各个严重级别的特定方法——LogFatal [SWS_LOG_00064]、LogError [SWS_LOG_00065]、LogWarn [SWS_LOG_00066]、LogInfo [SWS_LOG_00067]、LogDebug [SWS_LOG_00068] 或 LogVerbose [SWS_LOG_00069]——以及通过动态的 WithLevel [SWS_LOG_00131]，可以创建一个 LogStream 对象。该对象通过运算符 << 接收数据。通常，流对象的生命周期在语句的分号处结束 [SWS_LOG_00064]。
  • 建模消息：或者，也可以直接使用 Log [SWS_LOG_00204] 传递类型化和建模的消息，或者通过指定属性使用 LogWith [SWS_LOG_00133] 传递。

时序图：阈值检查和基于流的日志记录的典型顺序。来源：[SWS_LOG_00070]、[SWS_LOG_00067]、[SWS_LOG_00064]。

错误场景

该类的接口在很大程度上被指定为 noexcept 和异常安全（exception safe），从而最大限度地减少了意外的运行时中断 [SWS_LOG_00070]、[SWS_LOG_00255]。尽管如此，仍存在形式上的错误条件和边界情况：

  • 模型参数不正确：如果使用与建模消息的规范不匹配的参数调用 Log，则 C++ 程序结构不正确（ill-formed），并在编译时失败 [SWS_LOG_00204]。
  • 缺少属性特性：如果用于 LogWith 的元组包含不符合所需属性条件的类型，则该函数不参与重载解析 [SWS_LOG_00133]。隐藏可能通过 SFINAE 或 Concepts 进行。
  • 析构时的异常安全性：析构函数 ~Logger 被声明为 not exception safe [SWS_LOG_00260]。这可能是因为在向日志后端注销时可能会发生错误，而这些错误不得通过异常传播。
