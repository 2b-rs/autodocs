使用目的

ara::core::InstanceSpecifier 表示 AUTOSAR 实例说明符作为 ShortName 路径的包装器。对于应用程序交互，有效路径以 / 开头，并包含由 / 分隔的 ShortNames，直到 PortPrototype；功能簇交互还需要前导路径分隔符。 [SWS_CORE_08001] [SWS_CORE_10200] [SWS_CORE_10203]

生成&销毁

StringView的构造函数可以触发； Create() 或者返回Result<InstanceSpecifier>。语法上无效的元模型路径必须被拒绝。 [SWS_CORE_08021][SWS_CORE_08032][SWS_CORE_10201][SWS_CORE_10202]

生命周期和所有权

复制和移动构造并且两个作业都可用并且noexcept。 ToString() 返回的字符串内容的生命周期仅保证传递给构造函数的 StringView 内容的生命周期。 [SWS_CORE_08022][SWS_CORE_08023][SWS_CORE_08024][SWS_CORE_08025][SWS_CORE_08041]

限制&错误处理

如果路径元素丢失或无效，则Create()返回CoreErrc::kInvalidMetaModelShortname，如果模型路径无效，则返回CoreErrc::kInvalidMetaModelPath。 [SWS_CORE_08032]

宣言参考和解决方案

InstanceSpecifier 是由 / 分隔的模型路径概念，它唯一地将应用程序代码指向系统模型中定义的资源。构造函数检查语法；功能集群仅在访问指定资源时检查路径的语义有效性。 EXP ARAComAPI §6.2 “Usage of InstanceSpecifier”

对于ara::com，服务实例Manifest将这样的说明符与端口原型实例相关联，从而与具体的服务实例相关联。由此产生的 InstanceIdentifier 取决于技术。 EXP ARAComAPI §6.2.1 “Modeling and configuration/mapping”TPS ManifestSpecification §B.5.1 “Relation between Instance Specifier and Instance Ref”

模型上下文中的核心数据类型

核心规范将实例说明符列为“00001”自己的数据类型。因此，用作近模型路径和随后在Functional Cluster中的解析是单独的步骤；具体的目标承诺仅出现在纯符号路径之外。 SWS Core §7.4 “Core data types”SWS Core §7.4.1 – Data types devised by AUTOSAR
