上下文

类 apext::tsync::TsyncFvmErrorDomain 表示 AUTOSAR Adaptive Platform 模块 tsync 内 Freshness Value Manager (FVM) 的错误域。作为 ara::core::ErrorDomain 的特化，它为在管理和验证新鲜度值时可能发生的错误状态和诊断消息提供语义上下文。通过类型别名 Errc [SWS_TS_14206] 和 Exception [SWS_TS_14207]，该域将特定枚举 TsyncFvmErrc 以及基础异常类型 TsyncFvmException 直接绑定到错误域。由此，该类充当 FVM 子系统、通用错误处理结构（如 ara::core::ErrorCode）与时间同步应用组件之间的纽带。

生命周期

apext::tsync::TsyncFvmErrorDomain 的实例通过默认构造函数 [SWS_TS_14208] 创建。该构造函数被指定为 constexpr 和 noexcept，从而在编译时即可实现异常安全的初始化 [SWS_TS_14208]。释放通过虚拟默认析构函数 [SWS_TS_14201] 进行，该析构函数同样为 noexcept 且为异常安全实现。解释：作为 AUTOSAR 错误域的一种实现，该类通常可以作为长生命周期实例运行，以便为应用模块提供用于错误解析的持久引用。所有观察性操作以及构造函数均被指定为线程安全 [SWS_TS_14208] [SWS_TS_14209] [SWS_TS_14210] [SWS_TS_14211]，因此可以跨线程边界进行并发使用，而无需外部同步。

使用路径

错误域的主要使用路径包括识别、文本解析错误原因以及可选地作为 C++ 异常进行转发：

  1. 域的识别：运行时系统通过方法 Name() [SWS_TS_14209] 查询错误域的标识符。返回值是唯一分配给该域的基于字符的常量 [SWS_TS_14209]。
  2. 文本错误描述：如果在 FVM 处理期间发生错误，则通过 Message() [SWS_TS_14210] 将其数字错误代码转换为可读字符串。解释：由 Message() 提供的消息文本可能基于静态字符串字面量，因为该方法被声明为线程安全且无动态内存管理的异常安全。
  3. 升级为异常：如果发生的错误无法在本地处理，ThrowAsException() [SWS_TS_14211] 允许将 ara::core::ErrorCode 转换为类型为 apext::tsync::TsyncFvmException 的异常，随后立即将其抛出。

错误场景

类 apext::tsync::TsyncFvmErrorDomain 的错误处理分为诊断信息的查询和运行时错误的传递：

  • 无异常的错误解析：查询方法 Name() [SWS_TS_14209] 和 Message() [SWS_TS_14210] 是完全异常安全的，并标有 noexcept。它们保证在检查错误状态时不会引发额外的异常。
