上下文

类 ara::diag::ClientAuthenticationHandle（[SWS_DM_01145]）用作活动诊断身份验证会话的控制接口。一旦通过 ara::diag::ClientAuthentication::Authenticate（[SWS_DM_01206]）成功完成身份验证，或通过 ara::diag::ClientAuthentication::OverrideDefaultRoles（[SWS_DM_01209]）成功完成对默认角色的临时覆盖（AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”），Diagnostic Server Instance 就会向自适应应用程序提供该句柄的一个实例。

Diagnostic Manager 为每个已通过身份验证的客户端管理一个动态访问控制列表（DynamicAccessList）。该列表包含诊断请求模式，这些模式向已通过身份验证的客户端授予超出 Diagnostic Extract 中所存配置之外的对诊断资源附加访问权限（AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”、AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.4 “DynamicAccessList Creation and Update”）。应用程序通过 ClientAuthenticationHandle 针对服务器实例控制这些动态访问权限以及身份验证状态和相关的非活动与到期定时器（[SWS_DM_01213]、[SWS_DM_01155]）。

上下文图：应用程序、句柄与 Diagnostic Server Instance 之间的交互。来源：AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”、[SWS_DM_01206]、[SWS_DM_01209]。

生命周期

有效句柄的创建通常不是通过默认构造函数进行，而是作为类 ara::diag::ClientAuthentication 身份验证方法的返回值（[SWS_DM_01206]、[SWS_DM_01209]）。虽然该类提供了一个线程安全且异常安全的默认构造函数（[SWS_DM_01146]），但它创建的是一个未初始化或空的句柄。在所有权方面，ClientAuthenticationHandle 实现了严格的仅移动语义：拷贝构造函数（[SWS_DM_01150]）和拷贝赋值运算符（[SWS_DM_01151]）已被删除（=delete）。句柄只能被移动（移动构造函数 [SWS_DM_01148] 和移动赋值 [SWS_DM_01149]），从而确保每个身份验证上下文具有唯一的所有者。

对象的销毁通过析构函数 ~ClientAuthenticationHandle() 进行（[SWS_DM_01147]）。在并发性方面需要注意，析构函数和控制成员函数（Set、Append、Refresh、Revoke）都不是线程安全的（[SWS_DM_01147]、[SWS_DM_01152]、[SWS_DM_01153]、[SWS_DM_01154]、[SWS_DM_01155]）。如果应用程序的多个线程访问同一个句柄，则必须对访问进行同步。

使用路径

典型的使用路径包括成功的身份验证、访问权限的定义与扩展、有效期的定期延长以及最终对权限的撤销：

  1. 获取句柄：应用程序调用 Authenticate 或 OverrideDefaultRoles，并在成功时获得 ClientAuthenticationHandle（[SWS_DM_01206]、[SWS_DM_01209]）。
  2. 设置权限：应用程序通过 Set(dynamicAccessList) 完全替换诊断客户端的动态访问列表（[SWS_DM_01153]、[SWS_DM_01213]）。
  3. 扩展权限：根据需要，可通过 Append(dynamicAccessList) 增量地将更多诊断服务模式追加到现有的 DynamicAccessList 中（[SWS_DM_01152]）。
  4. 刷新定时器：在持续的诊断通信中，应用程序调用 Refresh() 来重置非活动或角色超时定时器（[SWS_DM_01155]、AUTOSAR_AP_SWS_Diagnostics §7.3.2.3.3 “ClientAuthenticationHandle”、[SWS_DM_01210]）。如果此前同时使用了身份验证和角色覆盖，该调用将同时刷新这两个定时器（[SWS_DM_01155]）。
  5. 撤销权限：应用程序通过 Revoke() 显式将客户端重置回状态 kDeAuthenticated，丢弃分配的 DynamicAccessList，并取消临时覆盖的角色（[SWS_DM_01154]）。

时序图：通过句柄进行权限管理和定时器延长的典型交互序列。来源：[SWS_DM_01152]、[SWS_DM_01153]、[SWS_DM_01154]、[SWS_DM_01155]、[SWS_DM_01206]。

错误场景

句柄的所有更改状态的方法（Set、Append、Refresh 和 Revoke）均被声明为 noexcept，并通过返回类型 ara::core::Result<void> 报告错误：

  • DiagErrc::kServiceNotAvailable：当由于 Diagnostic Manager 的关键功能当前不可用而导致操作无法执行时发生（[SWS_DM_01152]、[SWS_DM_01153]、[SWS_DM_01154]、[SWS_DM_01155]）。在此情况下将采用回滚语义，以使系统中的先前状态保持不受影响。
  • 超时和自动取消身份验证：如果未及时通过 UDS 请求或 Refresh() 刷新非活动定时器，Diagnostic Server Instance 会自动将客户端置于状态 kDeAuthenticated（[SWS_DM_01210]）。解释：在已过期的上下文上后续的控制尝试可能会失败或保持无效。
