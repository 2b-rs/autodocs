上下文

类ara::rds::RdsErrorDomain代表了 AUTOSAR Adaptive Platform 在 Release R25-11 中 Raw Data Stream (RDS) 模块的核心错误域。它被声明为final，并继承自基类ara::core::ErrorDomain。其主要任务是对 RDS 功能领域内发生的错误进行唯一标识、分类和文本描述。

作为ara::core::ErrorDomain的特化形式，RdsErrorDomain关联了错误系统的多种类型和组件：

  • 错误枚举RdsErrc，通过类型化别名Errc直接在类作用域内可用（[SWS_RDS_11326]）。
  • 异常类型RdsException，通过别名Exception锚定在该域内（[SWS_RDS_11327]）。
  • 标准错误对象ara::core::ErrorCode，它将来自Errc的具体错误代码与RdsErrorDomain的实例关联起来。
  • 应用程序代码和框架服务，它们通过Name()（[SWS_RDS_11295]）和Message()（[SWS_RDS_11296]）查询错误消息，或将错误转发以进行异常处理。

生命周期

类RdsErrorDomain对象的创建受到严格限制：默认构造函数被明确定义为已删除（RdsErrorDomain() = delete，[SWS_RDS_11294]）。因此，排除了用户应用程序在栈或堆上直接或多次实例化的情况。

域实例的提供在内部可能通过长生命周期或静态单例对象实现，因为在 AUTOSAR Adaptive 错误模型中，通常每个错误域仅存在一个全局实例。通过声明为final，禁止了通过继承进行特化。

在并发性方面，该类表现为无状态。检查方法Name()（[SWS_RDS_11295]）和Message()（[SWS_RDS_11296]）被声明为const noexcept。它们不修改内部状态，并允许来自多个线程的同时并发读取访问，而无需同步开销。

使用路径

在常规运行中，该类很少直接由应用程序代码实例化，而是作为ara::core::ErrorCode和ara::core::Result的后端使用。错误处理的典型流程如下：

  1. 模块rds内部的操作失败，并生成枚举类型Errc的错误值（[SWS_RDS_11326]）。
  2. 该错误值与RdsErrorDomain结合封装在ara::core::ErrorCode中，并传递给调用方。
  3. 应用程序检查错误对象。通过Name()（[SWS_RDS_11295]）可以验证该错误来自 RDS 错误域。
  4. 为了进行诊断或记录日志，系统调用Message()（[SWS_RDS_11296]）以获取与该错误代码关联的文本消息。
  5. 如果选择了异常机制，则ErrorCode::ThrowAsException()的调用会委托给方法RdsErrorDomain::ThrowAsException()（[SWS_RDS_11297]），从而触发类型为Exception（[SWS_RDS_11327]）的异常。

错误场景

RdsErrorDomain本身用于处理错误情况，并为其接口定义了稳健的保证：

  • 错误代码：具体原因由枚举RdsErrc映射，该枚举被类型化为Errc（[SWS_RDS_11326]）。
  • 查询的异常安全性：方法Name()（[SWS_RDS_11295]）和Message(CodeType errorCode)（[SWS_RDS_11296]）被规范为noexcept。它们保证即使在资源紧张或发生错误时也不会抛出更多异常。如果传入了未知的错误代码，推测可能会返回通用的后备文本，以维持noexcept保证。
  • 异常触发：方法ThrowAsException(const ara::core::ErrorCode &errorCode)被声明为noexcept(false)（[SWS_RDS_11297]）。它确定性地抛出RdsException的一个实例（[SWS_RDS_11327]）。前置条件是一个有效的ErrorCode对象；不会发生常规返回。

<h4>生命周期</h4>
<p>类<code>RdsErrorDomain</code>对象的创建受到严格限制：默认构造函数被明确定义为已删除（<code>RdsErrorDomain() = delete</code>，<a class="spec-record-ref" data-req="SWS_RDS_11294" href="../spec/record.html?id=SWS_RDS_11294">[SWS_RDS_11294]</a>）。因此，排除了用户应用程序在栈或堆上直接或多次实例化的情况。</p>
<p>域实例的提供在内部可能通过长生命周期或静态单例对象实现，因为在 AUTOSAR Adaptive 错误模型中，通常每个错误域仅存在一个全局实例。通过声明为<code>final</code>，禁止了通过继承进行特化。</p>
<p>在并发性方面，该类表现为无状态。检查方法<code>Name()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>）和<code>Message()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>）被声明为<code>const noexcept</code>。它们不修改内部状态，并允许来自多个线程的同时并发读取访问，而无需同步开销。</p>

<h4>使用路径</h4>
<p>在常规运行中，该类很少直接由应用程序代码实例化，而是作为<code>ara::core::ErrorCode</code>和<code>ara::core::Result</code>的后端使用。错误处理的典型流程如下：</p>
<ol>
<li>模块<code>rds</code>内部的操作失败，并生成枚举类型<code>Errc</code>的错误值（<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>）。</li>
<li>该错误值与<code>RdsErrorDomain</code>结合封装在<code>ara::core::ErrorCode</code>中，并传递给调用方。</li>
<li>应用程序检查错误对象。通过<code>Name()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>）可以验证该错误来自 RDS 错误域。</li>
<li>为了进行诊断或记录日志，系统调用<code>Message()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>）以获取与该错误代码关联的文本消息。</li>
<li>如果选择了异常机制，则<code>ErrorCode::ThrowAsException()</code>的调用会委托给方法<code>RdsErrorDomain::ThrowAsException()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>），从而触发类型为<code>Exception</code>（<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>）的异常。</li>
</ol>

<h4>错误场景</h4>
<p><code>RdsErrorDomain</code>本身用于处理错误情况，并为其接口定义了稳健的保证：</p>
<ul>
<li><strong>错误代码：</strong>具体原因由枚举<code>RdsErrc</code>映射，该枚举被类型化为<code>Errc</code>（<a class="spec-record-ref" data-req="SWS_RDS_11326" href="../spec/record.html?id=SWS_RDS_11326">[SWS_RDS_11326]</a>）。</li>
<li><strong>查询的异常安全性：</strong>方法<code>Name()</code>（<a class="spec-record-ref" data-req="SWS_RDS_11295" href="../spec/record.html?id=SWS_RDS_11295">[SWS_RDS_11295]</a>）和<code>Message(CodeType errorCode)</code>（<a class="spec-record-ref" data-req="SWS_RDS_11296" href="../spec/record.html?id=SWS_RDS_11296">[SWS_RDS_11296]</a>）被规范为<code>noexcept</code>。它们保证即使在资源紧张或发生错误时也不会抛出更多异常。如果传入了未知的错误代码，推测可能会返回通用的后备文本，以维持<code>noexcept</code>保证。</li>
<li><strong>异常触发：</strong>方法<code>ThrowAsException(const ara::core::ErrorCode &amp;errorCode)</code>被声明为<code>noexcept(false)</code>（<a class="spec-record-ref" data-req="SWS_RDS_11297" href="../spec/record.html?id=SWS_RDS_11297">[SWS_RDS_11297]</a>）。它确定性地抛出<code>RdsException</code>的一个实例（<a class="spec-record-ref" data-req="SWS_RDS_11327" href="../spec/record.html?id=SWS_RDS_11327">[SWS_RDS_11327]</a>）。前置条件是一个有效的<code>ErrorCode</code>对象；不会发生常规返回。</li>
</ul>
