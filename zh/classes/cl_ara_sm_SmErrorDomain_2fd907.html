上下文

类 ara::sm::SmErrorDomain 为 AUTOSAR Adaptive Platform 内的功能集群 State Management (SM) 定义了特定领域的错误域 SWS StateManagement §8.1.3 “Class: SmErrorDomain”。根据 [SWS_SM_81241] 中的类定义，声明为 final 的类直接派生自基础基础设施 ara::core::ErrorDomain。它充当 State Management 的内部错误状态与 Adaptive Core 库通用错误处理机制之间的连接纽带。

在系统架构中，SmErrorDomain 负责识别、分类和文本转换与 State Management 交互时发生的错误。这里的重要交互对象包括：

  • 基类 ara::core::ErrorDomain，其接口由 SmErrorDomain 重写并提供。
  • 类型为 ara::core::ErrorCode 的错误对象，持有对 SmErrorDomain 实例的引用，以封装领域特定错误代码。
  • 错误原因的枚举，通过类型别名 Errc [SWS_SM_81245] 引用，该别名指向枚举类型 SmErrc。
  • 评估返回值或在启用异常处理时使用类型别名 Exception [SWS_SM_81246] 的应用组件和功能集群，该类型别名引用基础异常类 SmException。

通过成员函数 Name()，该域由字符串 "Sm" 唯一标识 [SWS_SM_81248]，从而使诊断和日志服务能够将错误的来源明确归因于 State Management。

生命周期

SmErrorDomain 实例的创建通过声明为 noexcept 的默认构造函数 SmErrorDomain() 进行 [SWS_SM_81247]。该规范为该构造函数赋予了“exception safe”以及“thread-safe”的属性，因此在实例化时既不会引发异常，也不会产生同步问题。

在并发性方面，该类的所有成员函数均被指定为 thread-safe：名称查询 Name() [SWS_SM_81248]、文本解析 Message() [SWS_SM_81249] 以及引发异常 ThrowAsException() [SWS_SM_81250] 均可从不同线程并发调用。该类不具有可变状态，并将其方法定义为 const。在 AUTOSAR Adaptive 中，错误域通常作为长寿命实例保留；因此，SmErrorDomain 实例的生命周期通常应当涵盖进程的整个执行时间（解读）。

使用路径

在典型的应用场景中，SmErrorDomain 不会单独使用，而是通过 State Management 操作的错误处理被间接调用。典型的使用流程分为以下步骤：

  1. 某项 State Management 操作失败并返回一个 ara::core::Result，其中包含一个与 SmErrorDomain 相关的类型为 ara::core::ErrorCode 的对象。
  2. 调用方通过错误代码查询所发生错误的描述。ErrorCode 在内部将该调用委托给 SmErrorDomain::Message(CodeType errorCode) [SWS_SM_81249]。
  3. 函数 Message() 将关联的错误文本作为 const char* 返回 SWS StateManagement §8.1.3.2.2.1 “Message”。
  4. 在启用了异常处理的环境中，错误代码可通过 ThrowAsException() [SWS_SM_81250] 作为异常触发，从而抛出类型为 Exception [SWS_SM_81246] 的异常对象。

时序图：通过 SmErrorDomain 进行错误文本解析和可选异常处理的流程。来源：[SWS_SM_81248]、[SWS_SM_81249]、[SWS_SM_81250]。

错误场景

类 SmErrorDomain 本身用于表示错误，并为 State Management 模块的错误系统定义类型别名：

  • Errc：枚举 SmErrc [SWS_SM_81245] 的别名，该枚举定义了该模块的特定数值错误代码。
  • Exception：SmException [SWS_SM_81246] 的别名，该类是所有与状态管理相关异常的基类。

在使用这些接口时，须考虑以下特定的前置条件和后置条件：

  • 触发时的异常安全性：成员函数 ThrowAsException() [SWS_SM_81250] 被归类为 not exception safe。这符合预期行为，因为该函数会抛出异常对象且不会正常返回。
  • 禁用 C++ 异常：若工具链中禁用了 C++ 异常，根据 [SWS_SM_81250]，ThrowAsException() 将不参与重载解析。在这种情况下，调用会导致编译错误。
  • 错误代码解析：函数 Message() [SWS_SM_81249] 接收一个数值代码。对于 SmErrc 之外的未知或无效值，实现推测会返回静态默认提示文本（解释），而不会抛出异常，因为该方法被声明为 noexcept。

<li>评估返回值或在启用异常处理时使用类型别名 <code>Exception</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a> 的应用组件和功能集群，该类型别名引用基础异常类 <code>SmException</code>。</li>
</ul>

<p>通过成员函数 <code>Name()</code>，该域由字符串 <code>"Sm"</code> 唯一标识 <a class="spec-record-ref" data-req="SWS_SM_81248" href="../spec/record.html?id=SWS_SM_81248">[SWS_SM_81248]</a>，从而使诊断和日志服务能够将错误的来源明确归因于 State Management。</p>

<h4>生命周期</h4>
<p><code>SmErrorDomain</code> 实例的创建通过声明为 <code>noexcept</code> 的默认构造函数 <code>SmErrorDomain()</code> 进行 <a class="spec-record-ref" data-req="SWS_SM_81247" href="../spec/record.html?id=SWS_SM_81247">[SWS_SM_81247]</a>。该规范为该构造函数赋予了“exception safe”以及“thread-safe”的属性，因此在实例化时既不会引发异常，也不会产生同步问题。</p>

<p>在并发性方面，该类的所有成员函数均被指定为 thread-safe：名称查询 <code>Name()</code> <a class="spec-record-ref" data-req="SWS_SM_81248" href="../spec/record.html?id=SWS_SM_81248">[SWS_SM_81248]</a>、文本解析 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a> 以及引发异常 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a> 均可从不同线程并发调用。该类不具有可变状态，并将其方法定义为 <code>const</code>。在 AUTOSAR Adaptive 中，错误域通常作为长寿命实例保留；因此，<code>SmErrorDomain</code> 实例的生命周期通常应当涵盖进程的整个执行时间（解读）。</p>

<h4>使用路径</h4>
<p>在典型的应用场景中，<code>SmErrorDomain</code> 不会单独使用，而是通过 State Management 操作的错误处理被间接调用。典型的使用流程分为以下步骤：</p>
<ol>
<li>某项 State Management 操作失败并返回一个 <code>ara::core::Result</code>，其中包含一个与 <code>SmErrorDomain</code> 相关的类型为 <code>ara::core::ErrorCode</code> 的对象。</li>
<li>调用方通过错误代码查询所发生错误的描述。<code>ErrorCode</code> 在内部将该调用委托给 <code>SmErrorDomain::Message(CodeType errorCode)</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a>。</li>
<li>函数 <code>Message()</code> 将关联的错误文本作为 <code>const char*</code> 返回 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_StateManagement&amp;page=119">SWS StateManagement §8.1.3.2.2.1 “Message”</a>。</li>
<li>在启用了异常处理的环境中，错误代码可通过 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a> 作为异常触发，从而抛出类型为 <code>Exception</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a> 的异常对象。</li>
</ol>

<h4>错误场景</h4>
<p>类 <code>SmErrorDomain</code> 本身用于表示错误，并为 State Management 模块的错误系统定义类型别名：</p>
<ul>
<li><code>Errc</code>：枚举 <code>SmErrc</code> <a class="spec-record-ref" data-req="SWS_SM_81245" href="../spec/record.html?id=SWS_SM_81245">[SWS_SM_81245]</a> 的别名，该枚举定义了该模块的特定数值错误代码。</li>
<li><code>Exception</code>：<code>SmException</code> <a class="spec-record-ref" data-req="SWS_SM_81246" href="../spec/record.html?id=SWS_SM_81246">[SWS_SM_81246]</a> 的别名，该类是所有与状态管理相关异常的基类。</li>
</ul>

<p>在使用这些接口时，须考虑以下特定的前置条件和后置条件：</p>
<ul>
<li><strong>触发时的异常安全性</strong>：成员函数 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a> 被归类为 <em>not exception safe</em>。这符合预期行为，因为该函数会抛出异常对象且不会正常返回。</li>
<li><strong>禁用 C++ 异常</strong>：若工具链中禁用了 C++ 异常，根据 <a class="spec-record-ref" data-req="SWS_SM_81250" href="../spec/record.html?id=SWS_SM_81250">[SWS_SM_81250]</a>，<code>ThrowAsException()</code> 将不参与重载解析。在这种情况下，调用会导致编译错误。</li>
<li><strong>错误代码解析</strong>：函数 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_SM_81249" href="../spec/record.html?id=SWS_SM_81249">[SWS_SM_81249]</a> 接收一个数值代码。对于 <code>SmErrc</code> 之外的未知或无效值，实现推测会返回静态默认提示文本（解释），而不会抛出异常，因为该方法被声明为 <code>noexcept</code>。</li>
</ul>
