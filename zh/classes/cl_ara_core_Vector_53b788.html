上下文

ara::core::Vector 在 AUTOSAR Adaptive Platform 内表示一个用于同构数据元素的顺序、动态可调内存容器。其实现在概念上参考了 C++ 标准模板 std::pmr::vector，并直接与模块 core 的分配器架构相绑定。内存管理主要通过模板参数 Allocator 或类型别名 allocator_type [SWS_CORE_01303] 控制，其实例可通过 get_allocator() [SWS_CORE_01331] 进行查询。通过这种方式，容器直接与特定于应用程序或平台范围的内存资源进行交互，这对于安全关键型车辆系统中的确定性分配策略至关重要。

为了集成到算法和数据流中，该类声明了用于值、指针、引用和迭代器的标准化类型别名：有效载荷数据类型 value_type [SWS_CORE_01302]、pointer [SWS_CORE_01304] 和 const_pointer [SWS_CORE_01305] 以及 reference [SWS_CORE_01306] 和 const_reference [SWS_CORE_01307]。对元素范围的访问通过标准化正向和反向迭代器（[SWS_CORE_01310]、[SWS_CORE_01311]、[SWS_CORE_01312]、[SWS_CORE_01313]）进行，而距离和大小则通过 difference_type [SWS_CORE_01309] 和 size_type [SWS_CORE_01308] 表示。

生命周期

ara::core::Vector 实例的生命周期始于通过构造函数之一进行的缓冲区初始化。除了默认构造 [SWS_CORE_01318] 之外，还可以专门使用分配器实例来创建容器 [SWS_CORE_01319]。其他初始化途径允许指定初始元素数量 [SWS_CORE_01320]（可选通过默认值 [SWS_CORE_01321] 进行预置）、读取迭代器范围 [SWS_CORE_01322] 或通过 std::initializer_list [SWS_CORE_01325] 进行初始化。

复制、移动和销毁操作具有特定的所有权和异常条件：

  • 复制：复制构造函数 [SWS_CORE_01314] 被指定为 default，但与标准不同的是，只要 std::is_nothrow_copy_constructible<T>::value 成立，它就会被有条件地声明为 noexcept。相应地，复制赋值 [SWS_CORE_01315] 有条件地为 noexcept。此外，还可以在指定单独分配器的情况下创建副本 [SWS_CORE_01323]。
  • 移动：移动构造函数 [SWS_CORE_01316] 和移动赋值运算符 [SWS_CORE_01317] 高效地传输所管理的缓冲区。它们被定义为有条件地 noexcept，取决于分配器在移动操作时是否支持缓冲区传递（propagate_on_container_move_assignment），或者分配器是否始终相同（is_always_equal）。同时也提供了带有分配器传递的移动 [SWS_CORE_01324]。
  • 状态交换：方法 swap() [SWS_CORE_01374] 交换两个实例的容器内容，并在相同的分配器条件（传播或相等性）下为 noexcept。
  • 销毁：析构函数 ~Vector() [SWS_CORE_01326] 被显式指定为 noexcept。它有序析构所有包含的元素，并释放已分配的内存区域。

ara::core::Vector 独占拥有其内存区域；指向缓冲区的指针可通过 data()（[SWS_CORE_01360]、[SWS_CORE_01361]）获取。关于并发性，该容器不提供内部同步：通过常量方法进行的并行读取访问是安全的，而并发写入访问则需要外部保护。

使用路径

ara::core::Vector 的典型用法分为分配器初始化、容量预留、填充和元素评估：

  1. 初始化与分配器分配：使用指定的内存管理器（[SWS_CORE_01319]）实例化容器。
  2. 预先预留：通过调用 reserve() [SWS_CORE_01347] 专门请求容量，以避免在插入期间发生后续动态重新分配。可用缓冲区大小可通过 capacity() [SWS_CORE_01348] 进行验证。
  3. 元素接收：元素通过 push_back()（[SWS_CORE_01363]、[SWS_CORE_01364]）或通过 emplace_back() [SWS_CORE_01362] 原位构造添加到末尾。或者，可以通过 insert()（[SWS_CORE_01367]、[SWS_CORE_01368]、[SWS_CORE_01369]）或 emplace() [SWS_CORE_01366] 将值放置在任意位置。
  4. 检查与访问：通过 empty() [SWS_CORE_01344] 和 size() [SWS_CORE_01345] 检查填充状态后，通过 operator[]（[SWS_CORE_01352]、[SWS_CORE_01353]）、通过 at()（[SWS_CORE_01354]、[SWS_CORE_01355]）进行范围检查、或在缓冲区边界处通过 front()（[SWS_CORE_01356]、[SWS_CORE_01357]）和 back()（[SWS_CORE_01358]、[SWS_CORE_01359]）来访问元素。顺序处理可通过从 begin() [SWS_CORE_01332] 到 end() [SWS_CORE_01334] 的迭代器进行。
  5. 清理：可以通过 pop_back() [SWS_CORE_01365] 或 erase()（[SWS_CORE_01372]、[SWS_CORE_01373]）删除单个元素。使用 clear() [SWS_CORE_01375] 可完全清空容器；未使用的内存可以通过 shrink_to_fit() [SWS_CORE_01349] 归还给分配器。

错误场景

与标准库的行为不同，ara::core::Vector 采用特定于 AUTOSAR 的 Violation 而非传统的标准异常来指示错误调用：

  • 索引越界：访问方法 at()（[SWS_CORE_01354]、[SWS_CORE_01355]）验证传入的索引。如果 n >= size() 成立，则会触发 IsoStdOutOfRangeViolation（而不是 std::out_of_range）。
  • 超出容量限制：在调用 reserve() [SWS_CORE_01347] 以及 resize()（[SWS_CORE_01350]、[SWS_CORE_01351]）时，会根据 max_size() [SWS_CORE_01346] 检查请求。当超出此最大限制时，会触发 IsoStdLengthErrorViolation（而不是 std::length_error）。
  • 未检查的直接访问：下标运算符 operator[]（[SWS_CORE_01352]、[SWS_CORE_01353]）以及边界方法 front()（[SWS_CORE_01356]、[SWS_CORE_01357]）和 back()（[SWS_CORE_01358]、[SWS_CORE_01359]）不执行运行时检查。在容器为空或索引超出范围时调用这些方法会违反其前置条件，并导致未定义行为。
  • 修改操作的异常安全性：许多修改状态的操作（如 assign()（[SWS_CORE_01328]、[SWS_CORE_01329]、[SWS_CORE_01330]）、insert()（[SWS_CORE_01367]、[SWS_CORE_01368]）或 erase()（[SWS_CORE_01372]、[SWS_CORE_01373]））在规范中被归类为 not exception safe。解释：在诸如 push_back() [SWS_CORE_01363] 等扩容操作中，若缓冲区分配失败或元素构造失败，由于缺乏完全的强异常保证，该容器在某些情况下可能会停留在已修改的状态。
