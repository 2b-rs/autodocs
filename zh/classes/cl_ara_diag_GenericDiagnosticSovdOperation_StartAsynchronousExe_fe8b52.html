结构体 ara::diag::GenericDiagnosticSovdOperation::StartAsynchronousExecutionResponse 是 AUTOSAR Adaptive Platform（[SWS_DM_02209]、AUTOSAR_AP_SWS_Diagnostics §8.62.3 “Struct: StartAsynchronousExecutionResponse”）中诊断模块（diag）的组成部分。在基于服务的车辆诊断框架（SOVD）中，当请求的诊断操作无法立即完成而转入异步后台处理时，它用作标准化返回结构体（[SWS_DM_01396]）。

在整个系统中，有三个主要参与方相互交互（AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.5 “Operations – Start execution of an operation”）：

  • 外部 SOVD 客户端，其根据 ASAM SOVD 规范通过 Start Execution of an Operation 方法请求诊断操作（[SWS_DM_01396]）。
  • Diagnostic Server 实例（Diagnostic Management，DM），负责接收传入的 SOVD 调用，执行所需的安全检查（如邻近质询），并将执行委托给应用程序（[SWS_DM_02174]）。
  • 诊断服务实现，其派生自抽象基类 ara::diag::GenericDiagnosticSovdOperation 并实现纯虚方法 StartExecution（AUTOSAR_AP_SWS_Diagnostics 第858页）。

在此结构中，StartAsynchronousExecutionResponse 向 Diagnostic Management 指示请求的操作已成功启动，目前正在异步继续运行。

使用路径

典型使用路径包括通过 Diagnostic Management 启动异步 SOVD 操作：

  6. SOVD 响应：Diagnostic Management 接收结果，并向客户端传输符合标准的、表示异步启动成功的 SOVD 响应（[SWS_DM_01396]）。

错误场景

在与 StartAsynchronousExecutionResponse 的使用相关方面，有若干前置条件、后置条件以及错误情况具有重要意义：

  • 安全验证失败：若启动前置的验证（例如邻近质询）失败，则 DM 不会调用 StartExecution（[SWS_DM_02174]）。因此不会创建 StartAsynchronousExecutionResponse 的实例。
  • 无异常（noexcept）：接口 StartExecution 被声明为 noexcept（AUTOSAR_AP_SWS_Diagnostics 第858页）。异步操作初始化期间的错误不得作为 C++ 异常抛出，而必须通过 ara::core::Future 作为错误状态进行报告。
  • 执行模式偏差：若操作与最初设想相反可以立即同步完成，则不得返回 StartAsynchronousExecutionResponse。取而代之的是，应在 ara::core::Variant 中设置 StartSynchronousExecutionResponse（AUTOSAR_AP_SWS_Diagnostics 第858页、[SWS_DM_02176]）。
  • 处理期间中止：若 DM 或客户端在正在进行的后台活动期间请求中止，则通过传入的 ara::diag::CancellationHandler 发出信号（AUTOSAR_AP_SWS_Diagnostics 第858页）。

<h4>错误场景</h4>
<p>在与 <code>StartAsynchronousExecutionResponse</code> 的使用相关方面，有若干前置条件、后置条件以及错误情况具有重要意义：</p>
<ul>
<li><strong>安全验证失败：</strong>若启动前置的验证（例如邻近质询）失败，则 DM 不会调用 <code>StartExecution</code>（<a class="spec-record-ref" data-req="SWS_DM_02174" href="../spec/record.html?id=SWS_DM_02174">[SWS_DM_02174]</a>）。因此不会创建 <code>StartAsynchronousExecutionResponse</code> 的实例。</li>
<li><strong>无异常（<code>noexcept</code>）：</strong>接口 <code>StartExecution</code> 被声明为 <code>noexcept</code>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=858">AUTOSAR_AP_SWS_Diagnostics 第858页</a>）。异步操作初始化期间的错误不得作为 C++ 异常抛出，而必须通过 <code>ara::core::Future</code> 作为错误状态进行报告。</li>
<li><strong>执行模式偏差：</strong>若操作与最初设想相反可以立即同步完成，则不得返回 <code>StartAsynchronousExecutionResponse</code>。取而代之的是，应在 <code>ara::core::Variant</code> 中设置 <code>StartSynchronousExecutionResponse</code>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=858">AUTOSAR_AP_SWS_Diagnostics 第858页</a>、<a class="spec-record-ref" data-req="SWS_DM_02176" href="../spec/record.html?id=SWS_DM_02176">[SWS_DM_02176]</a>）。</li>
<li><strong>处理期间中止：</strong>若 DM 或客户端在正在进行的后台活动期间请求中止，则通过传入的 <code>ara::diag::CancellationHandler</code> 发出信号（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=858">AUTOSAR_AP_SWS_Diagnostics 第858页</a>）。</li>
</ul>
