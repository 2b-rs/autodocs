上下文

类 ara::rds::IEEE1722Datagram 封装了 AUTOSAR Adaptive Platform 的原始数据流模块（Raw Data Stream，rds）内符合 IEEE 1722 标准的数据报表示。IEEE 1722 协议（Audio Video Transport Protocol，AVTP）用于通过车辆中的以太网网络对多媒体数据、控制信息和带时间戳的数据流进行时间关键型传输。

在此环境中，ara::rds::IEEE1722Datagram 承担传入或待发送 AVTP 有效负载的标准传输容器角色。由于核心数据字段声明为 protected 且该类具有虚析构函数 [SWS_RDS_90228]，因此该类大概主要用作更具体数据报实现或模块内部管理内存结构的多态基类。此时的交互伙伴一方面是接收或注入网络数据包的 RDS 子系统流接口，另一方面是评估或填充 AVTP 数据包数据的应用特定处理组件。

生命周期

ara::rds::IEEE1722Datagram 的生命周期主要由所封装有效负载的所有权概念决定。用于数据报数据的字节数组在内部通过指针类型 std::unique_ptr<ara::core::Byte[]> data 持有 [SWS_RDS_90226]。这表明该实例对所分配的原始数据缓冲区具有专有所有权。

解释：通过使用 std::unique_ptr，该类大概会强制执行严格的移动语义并禁止复制操作，这对于在不进行内存复制的情况下进行资源节约型且低延迟的连续数据流传输至关重要。当前缓冲区中包含的数据流长度通过受保护字段 std::uint16_t stream_data_length 并行维护 [SWS_RDS_90227]。

生命周期的结束由虚析构函数 ~IEEE1722Datagram() noexcept 规定 [SWS_RDS_90228]。其虚声明确保了通过基类指针删除数据报时，任何特化子类的析构函数也能正常执行。在销毁实例时，std::unique_ptr 会自动且异常安全地释放为原始数据分配的内存区域。关于并发性，需要注意的是，由于独占指针语义，数据报实例不应在没有同步的情况下在多个执行上下文之间共享；通常，所有权通过移动传递给下一个处理步骤。

使用路径

由于规范摘录中未列出公共工厂函数或参数化标准构造函数，因此实例化和初始化大概通常在特化子类中或通过 RDS 栈的驱动内部工厂机制完成。

典型处理流程分为以下步骤：

  • 分配与缓冲区绑定：派生类或 RDS 栈分配适当大小的原始数据缓冲区，并将控制权交给数据元素 data [SWS_RDS_90226]。
  • 长度初始化：流的有效负载长度通过受保护属性 stream_data_length 存储 [SWS_RDS_90227]，以记录缓冲区内有效 IEEE 1722 字节的确切边界。
  • 消费或传输：数据报被传递给处理系统。数据的评估按照 IEEE 1722 标头规范进行。
  • 析构：处理完成后释放数据报，此时调用虚析构函数 ~IEEE1722Datagram() [SWS_RDS_90228]，并保证无异常抛出地释放资源。

本指南完全基于 Release R25-11 的 Raw Data Stream（RDS）模块 AUTOSAR 规范。
