Freshness-Value-Management 作为平台扩展

apext::com::secoc::FVM 为SecOC 处理提供接收和发送Freshness 值。它是平台集成的原生接口；通信管理规范将其调用与安全消息的处理联系起来。 SWS CM §7.3.2 “Secure Communication”和EXP SW Architecture §9.3.1.1.3 “Interfaces for freshness value management”描述角色和嵌入。

来电订购

在操作使用之前，平台会初始化FVM。发送时，请求新鲜度值；当接收到时，传输的、可能缩短的新鲜度值被用于检查或重建。验证结果为设定状态。计数器和 ID 的具体管理仍然是实现/配置的问题。

错误处理

这四个操作通过扩展语义返回其成功。错误属于特殊的FVM错误域；应用程序不应将它们与 E2E Profile 或一般 ComErrc 错误等同起来。 EXP ARAComAPI §4.7 “Error Handling” 解释了故障域的高级分离。

协作：平台扩展FVM为SecOC交付或检查Freshness-Werte；验证状态被赋予配置的状态接口。来源：SWS CM §7.3.2 “Secure Communication”、EXP SW Architecture §9.3.1.1.3 “Interfaces for freshness value management”。
