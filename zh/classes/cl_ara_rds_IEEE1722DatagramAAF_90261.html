类 ara::rds::IEEE1722DatagramAAF 表示 AUTOSAR Adaptive Platform 的 Raw Data Stream（rds）模块中遵循 IEEE 1722 标准的 AVTP 音频格式（AAF）数据报的功能性表示。它用于对以太网网络上时间关键型音频流的协议字段和格式参数进行结构化保存与管理。

该类封装了音频格式的协议特定控制与格式属性。其中包括定义音频有效负载基本结构的基础数据字段 format [SWS_RDS_90262]，以及用于指定所包含音频通道或子流的 streams_per_frame [SWS_RDS_90263]。由于所有声明的字段均具有访问修饰符 protected，因此该类推测主要被设计为 AAF 数据报类层次结构中可特化的基类。因此，与上层应用程序或流端点的交互通常通过派生类或 RDS 子系统的特定接口进行。

使用路径

在典型应用场景中，IEEE1722DatagramAAF 用于音频原始数据包的传输或接收上下文中：

  • 初始化和格式定义：在建立流或进行打包时，通过字段 format [SWS_RDS_90262] 配置基本格式定义，并通过 streams_per_frame [SWS_RDS_90263] 配置流的数量。
  • 可选音频属性的配置：根据音频规范设置特定的元数据。其中包括通过 evt [SWS_RDS_90264] 设置的事件标志、通过 nsr [SWS_RDS_90268] 与 nfr [SWS_RDS_90265] 设置的采样率和帧率，以及诸如 bit_depth [SWS_RDS_90266] 和 channels_per_frame [SWS_RDS_90267] 等格式参数。额外的流细化参数可以通过 sp [SWS_RDS_90269] 进行映射。
  • AES3 特性：对于符合 AES3 标准的数字音频数据流，提供了可选参数 aes3_data_type_h [SWS_RDS_90270]、aes3_data_type_l [SWS_RDS_90271] 以及引用 aes3_dt_ref [SWS_RDS_90272]。
  • 处理与传递：在读取或设置属性之后，数据报通过 RDS 驱动程序的接口进行序列化并传输到网络上，或转发至音频接收端。

错误场景

使用 IEEE1722DatagramAAF 时的错误情况主要与 IEEE 1722 头部字段的不完整或不一致相关：

  • 缺少可选字段：许多属性封装为 ara::core::Optional，例如 evt [SWS_RDS_90264]、bit_depth [SWS_RDS_90266] 或 channels_per_frame [SWS_RDS_90267]。在未预先检查的情况下访问空 Optional 的值会导致运行时错误或派生层中的异常处理。

  • 析构时的异常安全性：通过使用 noexcept [SWS_RDS_90273] 标记析构函数，可确保在销毁对象时不会逃逸任何异常。析构过程中的错误必须在内部处理或记录，以防止通过 std::terminate 导致程序终止。

  <h4>上下文</h4>
  <p>
    类 <code>ara::rds::IEEE1722DatagramAAF</code> 表示 AUTOSAR Adaptive Platform 的 <em>Raw Data Stream</em>（<code>rds</code>）模块中遵循 IEEE 1722 标准的 AVTP 音频格式（AAF）数据报的功能性表示。它用于对以太网网络上时间关键型音频流的协议字段和格式参数进行结构化保存与管理。
  </p>
  <p>
    该类封装了音频格式的协议特定控制与格式属性。其中包括定义音频有效负载基本结构的基础数据字段 <code>format</code> <a class="spec-record-ref" data-req="SWS_RDS_90262" href="../spec/record.html?id=SWS_RDS_90262">[SWS_RDS_90262]</a>，以及用于指定所包含音频通道或子流的 <code>streams_per_frame</code> <a class="spec-record-ref" data-req="SWS_RDS_90263" href="../spec/record.html?id=SWS_RDS_90263">[SWS_RDS_90263]</a>。由于所有声明的字段均具有访问修饰符 <code>protected</code>，因此该类推测主要被设计为 AAF 数据报类层次结构中可特化的基类。因此，与上层应用程序或流端点的交互通常通过派生类或 RDS 子系统的特定接口进行。
  </p>

  <h4>生命周期</h4>
  <p>
    <code>ara::rds::IEEE1722DatagramAAF</code> 的生命周期与 Raw Data Stream 驱动程序的缓冲和流式传输机制紧密耦合。由于该类在规范范围内没有提供公共构造函数且所有属性均为受保护的，因此实例的创建推测是在接收或发送过程中由派生的具体数据报类或模块 <code>rds</code> 的平台内部工厂完成的。
  </p>
  <p>
    对于销毁，该类提供了一个虚析构函数 <code>~IEEE1722DatagramAAF()</code>，其被显式声明为 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_RDS_90273" href="../spec/record.html?id=SWS_RDS_90273">[SWS_RDS_90273]</a>。这保证了通过基类的指针或引用对资源进行安全且无异常的多态清理。在生命周期内，所有权通常保留在正在处理的流式传输管道中，其中实例沿着处理链路（例如在网络驱动程序与音频处理节点之间）传递。
  </p>

  <h4>使用路径</h4>
  <p>
    在典型应用场景中，<code>IEEE1722DatagramAAF</code> 用于音频原始数据包的传输或接收上下文中：
  </p>
  <ul>
    <li>
      <strong>初始化和格式定义：</strong>在建立流或进行打包时，通过字段 <code>format</code> <a class="spec-record-ref" data-req="SWS_RDS_90262" href="../spec/record.html?id=SWS_RDS_90262">[SWS_RDS_90262]</a> 配置基本格式定义，并通过 <code>streams_per_frame</code> <a class="spec-record-ref" data-req="SWS_RDS_90263" href="../spec/record.html?id=SWS_RDS_90263">[SWS_RDS_90263]</a> 配置流的数量。
    </li>
    <li>
      <strong>可选音频属性的配置：</strong>根据音频规范设置特定的元数据。其中包括通过 <code>evt</code> <a class="spec-record-ref" data-req="SWS_RDS_90264" href="../spec/record.html?id=SWS_RDS_90264">[SWS_RDS_90264]</a> 设置的事件标志、通过 <code>nsr</code> <a class="spec-record-ref" data-req="SWS_RDS_90268" href="../spec/record.html?id=SWS_RDS_90268">[SWS_RDS_90268]</a> 与 <code>nfr</code> <a class="spec-record-ref" data-req="SWS_RDS_90265" href="../spec/record.html?id=SWS_RDS_90265">[SWS_RDS_90265]</a> 设置的采样率和帧率，以及诸如 <code>bit_depth</code> <a class="spec-record-ref" data-req="SWS_RDS_90266" href="../spec/record.html?id=SWS_RDS_90266">[SWS_RDS_90266]</a> 和 <code>channels_per_frame</code> <a class="spec-record-ref" data-req="SWS_RDS_90267" href="../spec/record.html?id=SWS_RDS_90267">[SWS_RDS_90267]</a> 等格式参数。额外的流细化参数可以通过 <code>sp</code> <a class="spec-record-ref" data-req="SWS_RDS_90269" href="../spec/record.html?id=SWS_RDS_90269">[SWS_RDS_90269]</a> 进行映射。
    </li>
    <li>

    </li>
    <li>
      <strong>处理与传递：</strong>在读取或设置属性之后，数据报通过 RDS 驱动程序的接口进行序列化并传输到网络上，或转发至音频接收端。
    </li>
  </ul>

  <h4>错误场景</h4>
  <p>
    使用 <code>IEEE1722DatagramAAF</code> 时的错误情况主要与 IEEE 1722 头部字段的不完整或不一致相关：
  </p>
  <ul>
    <li>
      <strong>缺少可选字段：</strong>许多属性封装为 <code>ara::core::Optional</code>，例如 <code>evt</code> <a class="spec-record-ref" data-req="SWS_RDS_90264" href="../spec/record.html?id=SWS_RDS_90264">[SWS_RDS_90264]</a>、<code>bit_depth</code> <a class="spec-record-ref" data-req="SWS_RDS_90266" href="../spec/record.html?id=SWS_RDS_90266">[SWS_RDS_90266]</a> 或 <code>channels_per_frame</code> <a class="spec-record-ref" data-req="SWS_RDS_90267" href="../spec/record.html?id=SWS_RDS_90267">[SWS_RDS_90267]</a>。在未预先检查的情况下访问空 Optional 的值会导致运行时错误或派生层中的异常处理。
    </li>
    <li>
      <strong>格式与通道描述不一致：</strong>如果 <code>format</code> <a class="spec-record-ref" data-req="SWS_RDS_90262" href="../spec/record.html?id=SWS_RDS_90262">[SWS_RDS_90262]</a>、<code>bit_depth</code> <a class="spec-record-ref" data-req="SWS_RDS_90266" href="../spec/record.html?id=SWS_RDS_90266">[SWS_RDS_90266]</a> 和 <code>channels_per_frame</code> <a class="spec-record-ref" data-req="SWS_RDS_90267" href="../spec/record.html?id=SWS_RDS_90267">[SWS_RDS_90267]</a> 中的指定值与底层数据报的实际有效负载大小不一致，则在序列化或反序列化期间可能导致 RDS 子系统中的缓冲区溢出或协议丢弃。
    </li>
    <li>
      <strong>析构时的异常安全性：</strong>通过使用 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_RDS_90273" href="../spec/record.html?id=SWS_RDS_90273">[SWS_RDS_90273]</a> 标记析构函数，可确保在销毁对象时不会逃逸任何异常。析构过程中的错误必须在内部处理或记录，以防止通过 <code>std::terminate</code> 导致程序终止。
    </li>
  </ul>
