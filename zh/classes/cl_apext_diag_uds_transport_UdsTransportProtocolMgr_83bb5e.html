The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

协调传输层插件与 Diagnostic Server 会话层之间的 UDS 消息交换。

类 apext::diag::uds_transport::UdsTransportProtocolMgr 根据 AUTOSAR AP SWS Diagnostics §7.1.1 “Support of UDS Transport Layer” 管理 Diagnostic Server 与特定 UDS 传输协议之间的交互。它通过预指示和向会话层的异步转发来控制两阶段消息接收，并控制发送事件与生命周期事件（[SWS_DM_00309]、[SWS_DM_00311]）的反馈。所有接口调用均设计为异常安全，但非线程安全。

上下文

类 apext::diag::uds_transport::UdsTransportProtocolMgr 充当 Diagnostic Server 实例或 DM-Core（会话层）与符合 AUTOSAR AP SWS Diagnostics §7.1.1 “Support of UDS Transport Layer” 的各种 UDS 传输协议（如 DoIP 或 CAN）之间的核心中介。它提供了一个可扩展接口，派生自基类 UdsTransportProtocolHandler 的具体实现传输插件（[SWS_DM_00315]）可通过该接口报告传入的 UDS 消息并将传输确认转发给诊断核心。Interpretation：该管理器实例大概率由 Diagnostic Management 作为长期运行的中介组件运行，以便统一整合各类异构传输接口。

上下文图：UdsTransportProtocolMgr 嵌入在传输层处理程序与会话层之间。来源：[SWS_DM_00309]、[SWS_DM_00311]、[SWS_DM_00312]、[SWS_DM_01069]、AUTOSAR AP SWS Diagnostics §7.1.1 “Support of UDS Transport Layer”。

生命周期

销毁通过虚析构函数 ~UdsTransportProtocolMgr() 执行，该析构函数被指定为 noexcept = default（[SWS_DM_01524]）。在运行期间，管理器根据 AUTOSAR AP SWS Diagnostics §7.1.1.1 “Initialization, Starting and Stopping of a UDS TransportLayer” 和 [SWS_DM_00329] 响应已注册传输协议处理程序的生命周期事件：若处理程序关闭，它会通过 HandlerStopped()（[SWS_DM_00314]）向管理器报告完成。若先前断开连接的通道再次可用，则在预先通过 ChannelReestablished() 激活后，通过指定 GlobalChannelIdentifier 将此情况告知管理器（[SWS_DM_00313]、[SWS_DM_09021]）。

关于所有权，消息处理时适用基于 unique pointer 语义的严格缓冲区传递：诊断核心在通告消息时创建对象 UdsMessagePtr，并将其临时移交给处理程序进行填充（[SWS_DM_00309]）。在成功接收或传输中止时，消息的所有权将完全归还给通用 DM 核心（[SWS_DM_00310]、[SWS_DM_00311]）。该接口的所有回调方法均归类为异常安全（noexcept），但明确归类为非线程安全（[SWS_DM_00309]、[SWS_DM_00311]）。

使用路径

常规的 UDS 消息接收流程分为两个连续阶段。首先，传输处理程序通过 IndicateMessage() 指示消息的开始（[SWS_DM_00309]）。此时会传递源地址和目标地址、寻址类型（物理或功能）、通道 ID、总大小以及前几个有效负载字节的视图（payloadInfo）。该预先信息允许诊断核心提前评估请求，例如用于识别功能性 Tester Present（[SWS_DM_00309]）。如果核心接受该请求，管理器将返回由 IndicationResult::kIndicationOk 和待填充的消息缓冲区组成的对。

一旦传输处理程序接收到完整消息，便通过 HandleMessage() 将其转发给会话层（[SWS_DM_00311]）。这对应于 ISO 14229-2 中的原语 T_Data.ind。Interpretation：要求 HandleMessage() 立即返回大概率是通过移交给会话层的内部队列来实现的，因为实际处理必须在后台异步执行（[SWS_DM_00311]）。出站传输在完成后由处理程序通过 TransmitConfirmation() 进行确认（[SWS_DM_00312]），而周期性消息则通过 PeriodicTransmitConfirmation() 确认（[SWS_DM_01069]）。

时序图：通过 IndicateMessage 和 HandleMessage 进行 UDS 消息接收的典型流程。来源：[SWS_DM_00309]、[SWS_DM_00311]。

错误场景

若 DM 核心无法接受通告的消息，则 IndicateMessage() 便会失败。枚举 IndicationResult 为此定义了错误原因 kIndicationOccupied（通道繁忙）、kIndicationOverflow（缓冲区溢出）或 kIndicationUnknownTargetAddress（未知目标地址），随后将不提供消息缓冲区（[SWS_DM_00309]、[SWS_DM_00384]）。

如果在成功指示后，在传输层级别的后续传输期间发生错误，导致无法再形成 HandleMessage()，则处理程序必须强制调用 NotifyMessageFailure()（[SWS_DM_00310]）。由此，先前分配的消息缓冲区将受控地归还给会话层并释放。在发送操作中，TransmitConfirmation() 通过 TransmissionResult 报告结果；若在网络层发送失败，则传输 kTransmitFailed（[SWS_DM_00307]、[SWS_DM_00312]）。

使用

类 apext::diag::uds_transport::UdsTransportProtocolMgr 的方法 ChannelReestablished 用作 UDS 传输协议实现向 Diagnostic Management (DM) 的反馈，表明通信通道在（重新）启动后再次可用 [SWS_DM_00313]。一旦检测到由 ChannelID 表示的网络通道重新可用，传输协议实现就恰好调用此方法一次 [SWS_DM_00358]。作为参数传递 globalChannelId，其由自身 handlerIdent 与 ChannelID 组成的元组构成 [SWS_DM_00358]。

交互和生命周期

通知的前提条件是先前调用过 NotifyReestablishment [SWS_DM_00313]，[SWS_DM_00356]。典型的用例是执行 ECU 重置（UDS 服务 0x11）并带有在重启后发送肯定响应的选项 [SWS_DM_00326]。为了确保在 DM 重启后也能收到通知，通知请求必须由传输协议进行持久化存储 [SWS_DM_00359]。

错误处理与并发

该函数没有返回值，并被指定为 noexcept（exception safe）[SWS_DM_00313]。由于该接口被归类为非线程安全（not thread-safe）[SWS_DM_00313]，调用处理程序可能必须对访问进行外部同步。作为时间限制，DM 仅在调用 UdsTransportProtocolHandler::Start 之后才允许处理对 ChannelReestablished 的调用 [SWS_DM_01744]。

      方法 HandleMessage 用于将完整接收到的有效 UDS 请求消息从传输层传递到诊断管理的会话层（[SWS_DM_00311]）。这对应于符合 ISO 14229-2 的服务 T_Data.ind（[SWS_DM_00311]、AUTOSAR_AP_SWS_Diagnostics §C.2.1.2.2.2 “HandleMessage”）。
      

      调用与参数
      

      一旦传输协议实现填充了先前通过 IndicateMessage 请求的缓冲区的有效负载（[SWS_DM_00388]），它就会在 apext::diag::uds_transport::UdsTransportProtocolMgr 的实例上调用 HandleMessage（[SWS_DM_00345]）。类型为 UdsMessagePtr 的 message 作为实参传递。通过 std::unique_ptr 语义，UDS 消息的所有权返回给通用 DM 核心（[SWS_DM_00311]）。该函数不提供返回值。
      

      语义、并发与错误处理
      

        

      • 异步性：该调用必须立即返回（“instantly returns”）（[SWS_DM_00311]）。解释：诊断请求的实际处理可能在 DM 核心中的独立执行上下文中异步继续进行。
        • 

      • 错误情况：该方法被声明为 noexcept 且异常安全（[SWS_DM_00311]）。如果消息的接收或填充失败，则不得调用 HandleMessage；而必须通过 NotifyMessageFailure 报告错误（[SWS_DM_00310]）。
        • 

      • 线程安全性：该操作被指定为 not thread-safe（[SWS_DM_00311]）。调用方必须同步对同一实例的并行访问。
        •

      该接口属于传输协议层，应与应用侧的服务处理方法 ara::diag::GenericUDSService::HandleMessage（[SWS_DM_00618]）区分开来。

          管理接口 apext::diag::uds_transport::UdsTransportProtocolMgr 的纯虚回调方法 HandlerStopped 用作 UDS 传输插件对 Diagnostic Manager (DM) 的反馈，表明其执行已终止，且所有关联资源及网络连接已完全释放 [SWS_DM_00314]。该调用被预期为处理程序对先前调用 UdsTransportProtocolHandler::Stop() 的强制响应 [SWS_DM_00314], [SWS_DM_00323]。
          

          调用上下文与参数：受影响的插件在调用时通过类型为 UdsTransportProtocolHandlerID 的输入参数 handlerId 标识自身 [SWS_DM_00314]。该方法没有返回值（void），并通过指定为 noexcept 确保了完全的异常安全性（exception safe）[SWS_DM_00314]。未为此接口定义特定的错误码、错误反应或向 DET 或 DEM 的报告。
          

          流程与限制：如果 Diagnostic Manager 在关闭过程中转换为状态 ApplicationState.kTerminating，它首先在每个已启动的 UDS 传输协议实现上调用 Stop() [SWS_DM_00333]。从 Stop() 返回后，适用严格的调用禁止：除了 HandlerStopped [SWS_DM_01741], [SWS_DM_00323] 之外，处理程序插件不得再针对 UdsTransportProtocolMgr 调用任何其他方法。在最终终止 DM 进程之前，DM 会等待具有匹配 handlerId 的相应 HandlerStopped 回调到达 [SWS_DM_00340]。该接口被标明为非线程安全（not thread-safe）[SWS_DM_00314]。解释：由于 DM 单独等待回调的到达，插件中网络连接的实际终止大概率与 Stop() 方法的返回异步发生。
