类 apext::diag::uds_transport::UdsTransportProtocolMgr

[SWS_DM_00306] Upstream: RS_Diag_04147, RS_Diag_04168

class UdsTransportProtocolMgr {...};

The UdsTransportProtocolMgr class manages the interaction between the Diagnostic Server instance(s) and various UDS Transport Protocols (e.g., DoIP[2], CAN[21]). It provides a standard, extensible API for handling transport-specific message reception and optional early payload access.

参考书目SWS诊断：[2] ISO 13400-2:2019 – Road vehicles – Diagnostic communication over Internet Protocol (DoIP) – Part 2: Network and transport layer requirements and services (Edition 2, Release 2019-12) – www.iso.org
[21] ISO 15765-2 – Road vehicles – Diagnostics on Controller Area Networks (CAN) – Part2: Network layer services

使用目的

UdsTransportProtocolMgr 管理诊断服务器实例和 UDS 传输协议（例如 DoIP 或 CAN）之间的交互。它为传输处理程序提供标准化接口，用于消息接受、传输到会话层、发送确认和通道恢复。 [SWS_DM_00306]

消息接受和所有权

Handler用IndicateMessage()报告接收到的消息的开头，包括源和目标地址、地址类型、全局通道ID、大小和仅在呼叫期间有效的有效负载片段。如果DM可以处理该请求，则它返回kIndicationOk和UdsMessagePtr拥有的内存。在占用、缺乏资源或未知目标地址的情况下，为kIndicationOccupied、kIndicationOverflow或kIndicationUnknownTargetAddress提供空指针。 [SWS_DM_00309][SWS_DM_00385][SWS_DM_00386][SWS_DM_00387][SWS_DM_00487]

Handler填充返回的消息对象后，通过HandleMessage()将其传递给会话层；所有权回到通用DM核心。如果IndicateMessage()未提供kIndicationOk，则HandleMessage()可能不会被调用。如果发生过早的传输错误，则对象将返回并带有NotifyMessageFailure()。 [SWS_DM_00311][SWS_DM_00345][SWS_DM_00389][SWS_DM_00310]

生命周期和传输

TransmitConfirmation()报告kTransmitOk或kTransmitFailed由DM通过UdsTransportProtocolHandler::Transmit()请求的转账。 PeriodicTransmitConfirmation() 确认定期发送的消息的有序列表以及成功发送的项目数。 [SWS_DM_00312][SWS_DM_00351][SWS_DM_01069]

DM 只能在关联的处理程序启动后处理通道恢复。停止后，除HandlerStopped()外，不允许其他管理员调用； DM 在进程结束之前等待Callback。 [SWS_DM_00313][SWS_DM_01744][SWS_DM_01741][SWS_DM_00340]

函数 HandleMessage [SWS_DM_00311] Upstream: RS_Diag_04147, RS_Diag_04168

virtual void HandleMessage (UdsMessagePtr message) noexcept=0;

Hands over a valid received UDS message (currently this is only a request type) from the Transport Layer to the Session Layer. This corresponds to T_Data.ind of Figure 2 from ISO 14229-2[25]. The behavior is asynchronously, i.e. the UDS Message is handed over to the Session Layer and it is expected, that it "instantly" returns, which means, that real processing of the message shall be done asynchronously by the Transport Layer!

参考书目SWS诊断：[25] ISO 14229-2(2021) – Unified diagnostic services (UDS) - Part 2: Session layer services (Release 2021-10) – www.iso.org
