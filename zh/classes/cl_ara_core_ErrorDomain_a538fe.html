Encapsulation of an ErrorDomain. An ErrorDomain is the controlling entity for ErrorCode’s error code values, and defines the mapping of such error code values to textual representations. This type constitutes a base class for ErrorDomain implementations. This class is a literal type, and subclasses are strongly advised to be literal types as well.

类 ara::core::ErrorDomain 用作控制错误值的抽象基类，并将领域特定代码映射到其文本表示 [SWS_CORE_00153]。子类封装了系统范围内唯一的标识号，并定义了向不可变错误文本的转换以及特定于类型的异常处理。为了能够作为字面量类型（Literal Type）在编译期使用，该基类具有一个非虚的受保护析构函数 [SWS_CORE_00136]。复制和移动操作被完全禁止，因此其实例充当不可变的实体。

上下文

类 ara::core::ErrorDomain 构成了 AUTOSAR Adaptive Platform 中结构化错误管理的通用基础。它充当具体错误领域的抽象基类，并承担对封装在 ara::core::ErrorCode 中的错误值的中央控制职责。每个领域建立自己的命名空间，并通过 Message() ([SWS_CORE_00153]) 定义类型为 CodeType ([SWS_CORE_00122]) 的领域特定错误值到具有明确含义的文本表示的映射。此外，该类还提供了用于系统唯一领域标识符的类型别名 IdType ([SWS_CORE_00121])，以及用于制造商特定附加数据的 SupportDataType ([SWS_CORE_00123])。

在整个系统中，ara::core::ErrorDomain 与三个主要伙伴进行交互：

  • 子类：特定错误领域继承自 ara::core::ErrorDomain，并实现用于领域名称、错误消息和异常处理的纯虚成员函数。
  • ara::core::ErrorCode：表示具体的错误值，并将描述文本的获取委托给关联的错误领域。
  • 客户端/应用程序代码：通过错误码或直接在领域上查询状态信息 ([SWS_CORE_00152])，或接收抛出的 C++ 异常 ([SWS_CORE_00154])。

生命周期

ara::core::ErrorDomain 的实例化受保护：构造函数具有 protected 可见性，并期望一个类型为 IdType ([SWS_CORE_00135]) 的系统唯一领域标识符。由于构造函数被声明为 constexpr 和 noexcept，基类支持在编译期作为字面量类型（Literal Type）进行创建。明确建议子类同样保证这种作为字面量类型的特性。

完全禁止领域实例的任何复制或传递：

  • 复制构造函数 ([SWS_CORE_00131]) 和移动构造函数 ([SWS_CORE_00132]) 均被声明为已删除 (delete)。
  • 复制赋值运算符 ([SWS_CORE_00133]) 和移动赋值运算符 ([SWS_CORE_00134]) 同样被删除。

析构函数被声明为 protected 并定义为默认实现 ([SWS_CORE_00136])。它特意保持为平凡且非虚的，以便该类可以保持为字面量类型（Literal Type）。尽管 ara::core::ErrorDomain 提供了纯虚接口，但不需要通过基类指针进行多态析构 ([SWS_CORE_00136])。在实践中，具体的领域实例很可能作为长生命周期或静态对象进行管理（解释）。

关于所有权关系，所有指向名称 ([SWS_CORE_00152]) 和错误文本 ([SWS_CORE_00153]) 的指针均归领域类所有，客户端不得将其释放。所有读取和比较操作都是线程安全且异常安全的 ([SWS_CORE_00135], [SWS_CORE_00151])。

使用路径

当且仅当通过 Id() ([SWS_CORE_00151]) 获取的领域标识符一致时，ara::core::ErrorDomain 的两个实例比较结果才为相等 ([SWS_CORE_00137], [SWS_CORE_00138])。错误解析和异常处理的典型流程分为以下步骤：

  1. 领域标识：客户端或错误对象通过 Name() ([SWS_CORE_00152]) 获取以空字符结尾的字符串形式的领域名称。
  2. 消息解析：通过 Message(errorCode) 将数值错误值传递给领域 ([SWS_CORE_00153])。该领域返回一个基于指针的、以空字符结尾的错误文本，该文本绝不能为 nullptr。
  3. 异常处理：若要将错误码转换为异常，客户端将调用 ThrowAsException(errorCode) ([SWS_CORE_00154])。该领域随后会抛出封装了所传递错误码的合适 ara::core::Exception 实例。

时序图：通过 ErrorDomain 进行文本解析和异常抛出的典型序列。来源：[SWS_CORE_00152]、[SWS_CORE_00153]、[SWS_CORE_00154]。

错误场景

在使用 ara::core::ErrorDomain 时，必须考虑以下错误场景和接口要求：

  • 错误的领域归属：如果向方法 Message() 传递了一个并非源自该特定 ErrorDomain 的 errorCode，则构成规定的违例 WrongDomainOfAn-ErrorCodeViolation ([SWS_CORE_00153])。调用者必须确保错误码与领域实例相匹配。
  • 禁用的 C++ 异常：方法 ThrowAsException() 不是异常安全的 (not exception safe) 并且会抛出异常 ([SWS_CORE_00154])。如果在编译器工具链中禁用了 C++ 异常，则该函数不得参与重载决议 ([SWS_CORE_00154])。
  • 排除空指针：Name() 和 Message() 都绝不允许返回 nullptr ([SWS_CORE_00152], [SWS_CORE_00153])。返回 nullptr 的子类实现违反了接口规范。
