类型安全地存储来自定义类型集中的恰好一个值，并具有有条件的异常安全性。

模板类 ara::core::Variant 用作类型安全的 Union，用于存储和管理来自给定类型集中的恰好一个值 [SWS_CORE_01649]。它支持灵活的构造、赋值和 Emplace 机制，并允许通过 index() 确定活动候选项 [SWS_CORE_01665]。与标准相比，最重要的区别在于所有修改操作均具有修改后的条件式 Noexcept 规范，以及针对状态 valueless_by_exception() 的防护 [SWS_CORE_01666]。

上下文

模板类 ara::core::Variant 代表 AUTOSAR Adaptive Platform 的类型安全 Union，通过头文件 ara/core/variant.h 引入。它封装了对来自编译时定义的类型列表 (template <typename... Types> class Variant) 中恰好一个值的管理。该定义从根本上基于 C++ 标准 [variant] 中 std::variant 的行为，但在异常规范方面具有特定的 AUTOSAR 差异。该类的描述在元数据资产中引用了 [basic.string]；解释：由于所有要求均一致引用标准章节 [variant]，这推测属于编排上的不一致。 问题 Q-809de1af74fcb689 (未决)

生命周期

ara::core::Variant 的实例经历从初始化、值切换到销毁的确定性生命周期阶段。创建可以通过初始化第一个候选项的无参默认构造函数 [SWS_CORE_01649] 进行，通过复制和移动构造函数 [SWS_CORE_01650]、[SWS_CORE_01651] 进行，或通过直接值传递 [SWS_CORE_01652] 进行。此外，还提供了通过 in_place_type_t [SWS_CORE_01653]、[SWS_CORE_01654] 以及 in_place_index_t [SWS_CORE_01655]、[SWS_CORE_01656] 进行就地构造的重载，也可与初始化列表结合使用。

在常规状态下，对象始终持有一个有效候选项，其从零开始的索引可通过方法 index() 确定 [SWS_CORE_01665]。如果在构造或赋值期间值切换因抛出异常而失败，实例将转入状态 valueless_by_exception() [SWS_CORE_01666]。对象将保持该状态，直到通过成功的重新初始化再次占用有效候选项。析构函数按规则销毁当前持有的对象，并声明为具有条件的异常安全性 [SWS_CORE_01657]。

使用路径

典型使用流程包括实例化、赋值或替换内容、查询状态以及交换值：

  • 初始化：通过其中一个构造函数创建实例，例如通过直接值传递 [SWS_CORE_01652] 或显式按类型使用 in_place_type_t [SWS_CORE_01653]。
  • 值更新和重新占用：通过复制赋值运算符 [SWS_CORE_01658]、移动赋值运算符 [SWS_CORE_01659] 或通用值赋值 [SWS_CORE_01660] 赋予新值。或者，可以通过 emplace 按类型 [SWS_CORE_01661]、[SWS_CORE_01662] 或按索引 [SWS_CORE_01663]、[SWS_CORE_01664] 直接就地重新构造值。
  • 状态检查：通过 index() [SWS_CORE_01665] 查询活动类型索引，并通过 valueless_by_exception() [SWS_CORE_01666] 防范先前的错误。
  • 对象交换：通过成员函数 swap() [SWS_CORE_01667] 高效交换两个 Variant 实例。

由于当前的规范记录集仅包含成员函数，缺少直接读取操作（如值访问）；访问和访问者函数（类似于 std::get 或 std::visit）推测在命名空间 ara::core 中作为自由辅助函数提供。 问题 Q-75847ac18088da57 (未决)

错误场景

错误处理的核心是条件式异常安全性 (conditionally exception safe) 特性。虽然标准库为 std::variant 规定了固定的 Noexcept 规则，但 AUTOSAR 进行了有针对性的偏离：所有构造函数 [SWS_CORE_01650]、[SWS_CORE_01653]、赋值运算符 [SWS_CORE_01658]、emplace 操作 [SWS_CORE_01661]、[SWS_CORE_01663]、交换函数 swap() [SWS_CORE_01667] 以及析构函数 [SWS_CORE_01657] 均为条件式 noexcept。它们的异常保证直接取决于底层类型构造函数的 Noexcept 特性。

如果在赋值或 emplace 调用期间新值的构造抛出异常，Variant 可能会陷入无效中间状态。这通过 valueless_by_exception() 发出信号 [SWS_CORE_01666]。唯独两个查询函数 index() [SWS_CORE_01665] 和 valueless_by_exception() [SWS_CORE_01666] 提供不受限制的 noexcept 保证并且是完全异常安全的。
