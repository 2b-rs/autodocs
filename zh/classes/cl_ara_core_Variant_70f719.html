上下文

模板类 ara::core::Variant 在 AUTOSAR Adaptive Platform 的 core 模块中提供了一个类型安全联合体（求和类型）。该实现概念上基于 C++ 标准中的类型 std::variant，但针对该平台在异常处理以及 noexcept 的条件方面定义了特定的差异与明确规范。在任何时刻，ara::core::Variant 要么精确管理声明类型列表 Types... 中的一个值，要么由于错误而处于无值状态。

典型的交互伙伴是功能性 Adaptive 应用程序和服务接口，它们在不使用动态内存分配或继承层次结构的情况下类型安全地传递多态数据结构。正如 [SWS_CORE_01649] 等相关规范要求所规定的，包含通过头文件 ara/core/variant.h 进行。

生命周期

ara::core::Variant 实例的生命周期分为创建、取值转换、错误状态和销毁几个阶段：

  • 默认构造：无参默认构造函数 [SWS_CORE_01649] 使用第一个候选类型（索引 0）初始化该实例（前提是该类型支持默认构造）。执行为 constexpr 并且有条件地为 noexcept。
  • 按值与移动构造：实例可以通过按值采用[SWS_CORE_01652]、通过复制构造函数[SWS_CORE_01650]或通过移动构造函数[SWS_CORE_01651]进行实例化。所有这三项操作均受特定的noexcept条件约束。
  • 原位构造：为了避免临时副本，提供了带有占位符标记的构造函数：通过in_place_type_t（[SWS_CORE_01653]、[SWS_CORE_01654]）基于类型，或通过in_place_index_t（[SWS_CORE_01655]、[SWS_CORE_01656]）基于索引。这些构造函数被声明为explicit和constexpr。
  • 值变更与状态转换：在使用阶段，所包含的值可以通过赋值运算符（[SWS_CORE_01658]、[SWS_CORE_01659]、[SWS_CORE_01660]）、基于类型的emplace方法（[SWS_CORE_01661]、[SWS_CORE_01662]）、基于索引的emplace方法（[SWS_CORE_01663]、[SWS_CORE_01664]）或通过swap [SWS_CORE_01667]进行替换。
  • 析构：析构函数[SWS_CORE_01657]销毁当前活动的备选项。它被声明为条件性noexcept。

使用路径

典型的使用路径包括原位初始化、查询活动类型以及切换所持有的备选项：

  1. 初始化：专门使用一个备选项初始化该对象，例如根据[SWS_CORE_01653]通过in_place_type_t，以便将参数直接传递给目标类型的构造函数。
  2. 状态检查：在访问之前，应用程序通过方法index() [SWS_CORE_01665]检查当前所持有备选项的从零开始的索引。此外，可以使用valueless_by_exception() [SWS_CORE_01666]验证实例是否处于完好状态。
  3. 重新赋值：如果要在同一内存区域中放置备选类型，则调用emplace（[SWS_CORE_01661]或[SWS_CORE_01663]）。这将销毁先前的备选项并直接在原位创建新值。
  4. 析构：在离开作用域时，将调用析构函数[SWS_CORE_01657]，以正确销毁活动的备选项。

错误场景

在错误场景和异常处理方面，ara::core::Variant具有以下特征：

  • valueless_by_exception状态：如果在赋值（[SWS_CORE_01658]、[SWS_CORE_01659]、[SWS_CORE_01660]）或通过emplace（[SWS_CORE_01661]、[SWS_CORE_01663]）重新初始化期间，新备选项的构造函数抛出异常且旧备选项已被销毁，则对象将保持无值状态。该状态通过valueless_by_exception() [SWS_CORE_01666]进行查询。在此状态下，index()返回计算值variant_npos。只能通过再次成功赋值或emplace来恢复。
  • 条件性noexcept保证：几乎所有构造和修改方法（例如[SWS_CORE_01650]、[SWS_CORE_01653]、[SWS_CORE_01661]）都具有conditionally exception safe状态，并带有条件性noexcept子句（例如基于std::is_nothrow_constructible）。仅当所涉及的用户类型操作本身为noexcept时，它们才保证无异常。
  • 无条件保证：查询方法index() [SWS_CORE_01665]和valueless_by_exception() [SWS_CORE_01666]被无条件声明为noexcept，并提供无限制的异常安全性（exception safe）。
  • Swap修改：对于swap [SWS_CORE_01667]，相比标准修改了异常安全性条件，以确保在AUTOSAR环境中的受控处理。

<h4>上下文</h4>
<p>模板类 <code>ara::core::Variant</code> 在 AUTOSAR Adaptive Platform 的 <code>core</code> 模块中提供了一个类型安全联合体（求和类型）。该实现概念上基于 C++ 标准中的类型 <code>std::variant</code>，但针对该平台在异常处理以及 <code>noexcept</code> 的条件方面定义了特定的差异与明确规范。在任何时刻，<code>ara::core::Variant</code> 要么精确管理声明类型列表 <code>Types...</code> 中的一个值，要么由于错误而处于无值状态。</p>
<p>典型的交互伙伴是功能性 Adaptive 应用程序和服务接口，它们在不使用动态内存分配或继承层次结构的情况下类型安全地传递多态数据结构。正如 <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a> 等相关规范要求所规定的，包含通过头文件 <code>ara/core/variant.h</code> 进行。</p>

<h4>生命周期</h4>
<p><code>ara::core::Variant</code> 实例的生命周期分为创建、取值转换、错误状态和销毁几个阶段：</p>
<ul>
<li><strong>默认构造：</strong>无参默认构造函数 <a class="spec-record-ref" data-req="SWS_CORE_01649" href="../spec/record.html?id=SWS_CORE_01649">[SWS_CORE_01649]</a> 使用第一个候选类型（索引 0）初始化该实例（前提是该类型支持默认构造）。执行为 <code>constexpr</code> 并且有条件地为 <code>noexcept</code>。</li>
<li><strong>按值与移动构造：</strong>实例可以通过按值采用<a class="spec-record-ref" data-req="SWS_CORE_01652" href="../spec/record.html?id=SWS_CORE_01652">[SWS_CORE_01652]</a>、通过复制构造函数<a class="spec-record-ref" data-req="SWS_CORE_01650" href="../spec/record.html?id=SWS_CORE_01650">[SWS_CORE_01650]</a>或通过移动构造函数<a class="spec-record-ref" data-req="SWS_CORE_01651" href="../spec/record.html?id=SWS_CORE_01651">[SWS_CORE_01651]</a>进行实例化。所有这三项操作均受特定的<code>noexcept</code>条件约束。</li>
<li><strong>原位构造：</strong>为了避免临时副本，提供了带有占位符标记的构造函数：通过<code>in_place_type_t</code>（<a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01654" href="../spec/record.html?id=SWS_CORE_01654">[SWS_CORE_01654]</a>）基于类型，或通过<code>in_place_index_t</code>（<a class="spec-record-ref" data-req="SWS_CORE_01655" href="../spec/record.html?id=SWS_CORE_01655">[SWS_CORE_01655]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01656" href="../spec/record.html?id=SWS_CORE_01656">[SWS_CORE_01656]</a>）基于索引。这些构造函数被声明为<code>explicit</code>和<code>constexpr</code>。</li>
<li><strong>值变更与状态转换：</strong>在使用阶段，所包含的值可以通过赋值运算符（<a class="spec-record-ref" data-req="SWS_CORE_01658" href="../spec/record.html?id=SWS_CORE_01658">[SWS_CORE_01658]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01659" href="../spec/record.html?id=SWS_CORE_01659">[SWS_CORE_01659]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01660" href="../spec/record.html?id=SWS_CORE_01660">[SWS_CORE_01660]</a>）、基于类型的<code>emplace</code>方法（<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01662" href="../spec/record.html?id=SWS_CORE_01662">[SWS_CORE_01662]</a>）、基于索引的<code>emplace</code>方法（<a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>、<a class="spec-record-ref" data-req="SWS_CORE_01664" href="../spec/record.html?id=SWS_CORE_01664">[SWS_CORE_01664]</a>）或通过<code>swap</code> <a class="spec-record-ref" data-req="SWS_CORE_01667" href="../spec/record.html?id=SWS_CORE_01667">[SWS_CORE_01667]</a>进行替换。</li>
<li><strong>析构：</strong>析构函数<a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a>销毁当前活动的备选项。它被声明为条件性<code>noexcept</code>。</li>
</ul>

<h4>使用路径</h4>
<p>典型的使用路径包括原位初始化、查询活动类型以及切换所持有的备选项：</p>
<ol>
<li><strong>初始化：</strong>专门使用一个备选项初始化该对象，例如根据<a class="spec-record-ref" data-req="SWS_CORE_01653" href="../spec/record.html?id=SWS_CORE_01653">[SWS_CORE_01653]</a>通过<code>in_place_type_t</code>，以便将参数直接传递给目标类型的构造函数。</li>
<li><strong>状态检查：</strong>在访问之前，应用程序通过方法<code>index()</code> <a class="spec-record-ref" data-req="SWS_CORE_01665" href="../spec/record.html?id=SWS_CORE_01665">[SWS_CORE_01665]</a>检查当前所持有备选项的从零开始的索引。此外，可以使用<code>valueless_by_exception()</code> <a class="spec-record-ref" data-req="SWS_CORE_01666" href="../spec/record.html?id=SWS_CORE_01666">[SWS_CORE_01666]</a>验证实例是否处于完好状态。</li>
<li><strong>重新赋值：</strong>如果要在同一内存区域中放置备选类型，则调用<code>emplace</code>（<a class="spec-record-ref" data-req="SWS_CORE_01661" href="../spec/record.html?id=SWS_CORE_01661">[SWS_CORE_01661]</a>或<a class="spec-record-ref" data-req="SWS_CORE_01663" href="../spec/record.html?id=SWS_CORE_01663">[SWS_CORE_01663]</a>）。这将销毁先前的备选项并直接在原位创建新值。</li>
<li><strong>析构：</strong>在离开作用域时，将调用析构函数<a class="spec-record-ref" data-req="SWS_CORE_01657" href="../spec/record.html?id=SWS_CORE_01657">[SWS_CORE_01657]</a>，以正确销毁活动的备选项。</li>
</ol>
