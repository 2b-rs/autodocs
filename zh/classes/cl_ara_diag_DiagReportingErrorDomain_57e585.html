上下文

类 ara::diag::DiagReportingErrorDomain 为 Adaptive Platform [SWS_DM_00996]（AUTOSAR_AP_SWS_Diagnostics §8.11.7 “Class: DiagReportingErrorDomain”）诊断报告领域的错误状态定义了标准化错误域。作为基类 ara::core::ErrorDomain 的最终特化，它实现了诊断模块内报告错误的统一归类和传递。

该错误域通常与以下组件和基础架构协同工作：

  • 诊断报告功能：报告诊断流程中发生的特定错误状态，并将其分配给诊断报告域。
  • 错误封装（ara::core::ErrorCode）：将对 DiagReportingErrorDomain 实例的引用与特定错误码值绑定在一起。
  • 应用和基础系统：使用该域将错误信息转换为人类可读的文本，或生成相应的异常对象。

为了统一类型定义，该类提供了两个公共类型别名：Errc 引用具体错误值的枚举 DiagReportingErrc [SWS_DM_00997]，而 Exception 定义域特定异常的基类型 DiagReportingException [SWS_DM_00998]（AUTOSAR_AP_SWS_Diagnostics §8.11.7.1 “Public Member Types”）。

生命周期

ara::diag::DiagReportingErrorDomain 的实例化通过一个默认构造函数进行，该构造函数被声明为 constexpr 和 noexcept [SWS_DM_00999]（AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 “Default Constructor”）。这允许在编译时进行构造，并保证了异常安全的提供。

关于所有权关系，其解释为：此错误域的实例通常作为长生命周期的全局或静态对象（Singletons）持有，因为它们仅提供错误码的元数据和转换函数。该类不封装任何可变状态；创建后不存在状态转换。

在并发性方面，所有成员函数均设计为线程安全（thread-safe）。无论是通过构造函数 [SWS_DM_00999] 进行实例化，还是后续对 Name() [SWS_DM_01000]、Message() [SWS_DM_01001] 和 ThrowAsException() [SWS_DM_01002] 的调用，都可以由多个线程安全且并发地执行。实例的销毁非常简单，伴随外围静态存储区的释放而进行。

使用路径

诊断运行中的典型使用路径包括错误的创建、查询和进一步处理：

  1. 错误标识：如果在诊断过程中发生报告错误，则通过别名 Errc 从 DiagReportingErrc 获取相应的枚举值 [SWS_DM_00997]，并与该域一起封装在 ara::core::ErrorCode 中。
  2. 获取域名：为了标识错误域，可以通过 Name() 查询该域的短名称 [SWS_DM_01000]。其命名符合 [SWS_CORE_90023]（AUTOSAR_AP_SWS_Diagnostics §8.11.7 “Class: DiagReportingErrorDomain”）的规定。
  3. 解析错误消息：通过方法 Message(errorCode) 将数值型错误值转换为可读的明文消息 [SWS_DM_01001]（AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 “Message”）。保证返回值绝不为 nullptr。
  4. 抛出异常：如果上层应用逻辑需要异常处理，则调用 ThrowAsException(errorCode) [SWS_DM_01002]，从而触发相应的 DiagReportingException [SWS_DM_00998]。

错误场景

在处理 ara::diag::DiagReportingErrorDomain 时，以下异常安全性与前置条件方面的内容具有相关性：

  • 异常安全的基本函数：默认构造函数 DiagReportingErrorDomain() [SWS_DM_00999]、名称查询 Name() [SWS_DM_01000] 以及 Message() [SWS_DM_01001] 均声明为 noexcept，并且完全具备异常安全性（exception safe）。
  • 保证返回文本消息：由于按照契约 Message() 绝不返回 nullptr [SWS_DM_01001]，因此该实现对于未知或无效的错误码大概率也会提供标准化的回退文本。
  • 抛出异常时的行为：函数 ThrowAsException() 使用 noexcept(false) 进行注解，并被归类为非异常安全（not exception safe）[SWS_DM_01002]，因为其主要目的就在于针对性地抛出异常。
  • 禁用的 C++ 异常：如果在编译器的工具链中禁用了 C++ 异常，则根据 [SWS_CORE_10304]，ThrowAsException() 将不参与重载解析 [SWS_DM_01002]。在这些环境中，调用方必须完全通过 ara::core::ErrorCode 实现错误处理。

<li><strong>应用和基础系统：</strong>使用该域将错误信息转换为人类可读的文本，或生成相应的异常对象。</li>
</ul>

<p>为了统一类型定义，该类提供了两个公共类型别名：<code>Errc</code> 引用具体错误值的枚举 <code>DiagReportingErrc</code> <a class="spec-record-ref" data-req="SWS_DM_00997" href="../spec/record.html?id=SWS_DM_00997">[SWS_DM_00997]</a>，而 <code>Exception</code> 定义域特定异常的基类型 <code>DiagReportingException</code> <a class="spec-record-ref" data-req="SWS_DM_00998" href="../spec/record.html?id=SWS_DM_00998">[SWS_DM_00998]</a>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=411">AUTOSAR_AP_SWS_Diagnostics §8.11.7.1 “Public Member Types”</a>）。</p>

<h4>生命周期</h4>
<p><code>ara::diag::DiagReportingErrorDomain</code> 的实例化通过一个默认构造函数进行，该构造函数被声明为 <code>constexpr</code> 和 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=412">AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.1.1 “Default Constructor”</a>）。这允许在编译时进行构造，并保证了异常安全的提供。</p>

<p>关于所有权关系，其解释为：此错误域的实例通常作为长生命周期的全局或静态对象（Singletons）持有，因为它们仅提供错误码的元数据和转换函数。该类不封装任何可变状态；创建后不存在状态转换。</p>

<p>在并发性方面，所有成员函数均设计为线程安全（thread-safe）。无论是通过构造函数 <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a> 进行实例化，还是后续对 <code>Name()</code> <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a>、<code>Message()</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a> 和 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a> 的调用，都可以由多个线程安全且并发地执行。实例的销毁非常简单，伴随外围静态存储区的释放而进行。</p>

<h4>使用路径</h4>
<p>诊断运行中的典型使用路径包括错误的创建、查询和进一步处理：</p>
<ol>
<li><strong>错误标识：</strong>如果在诊断过程中发生报告错误，则通过别名 <code>Errc</code> 从 <code>DiagReportingErrc</code> 获取相应的枚举值 <a class="spec-record-ref" data-req="SWS_DM_00997" href="../spec/record.html?id=SWS_DM_00997">[SWS_DM_00997]</a>，并与该域一起封装在 <code>ara::core::ErrorCode</code> 中。</li>
<li><strong>获取域名：</strong>为了标识错误域，可以通过 <code>Name()</code> 查询该域的短名称 <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a>。其命名符合 <a class="spec-record-ref" data-req="SWS_CORE_90023" href="../spec/record.html?id=SWS_CORE_90023">[SWS_CORE_90023]</a>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=410">AUTOSAR_AP_SWS_Diagnostics §8.11.7 “Class: DiagReportingErrorDomain”</a>）的规定。</li>
<li><strong>解析错误消息：</strong>通过方法 <code>Message(errorCode)</code> 将数值型错误值转换为可读的明文消息 <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=412">AUTOSAR_AP_SWS_Diagnostics §8.11.7.2.2.1 “Message”</a>）。保证返回值绝不为 <code>nullptr</code>。</li>
<li><strong>抛出异常：</strong>如果上层应用逻辑需要异常处理，则调用 <code>ThrowAsException(errorCode)</code> <a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a>，从而触发相应的 <code>DiagReportingException</code> <a class="spec-record-ref" data-req="SWS_DM_00998" href="../spec/record.html?id=SWS_DM_00998">[SWS_DM_00998]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>在处理 <code>ara::diag::DiagReportingErrorDomain</code> 时，以下异常安全性与前置条件方面的内容具有相关性：</p>
<ul>
<li><strong>异常安全的基本函数：</strong>默认构造函数 <code>DiagReportingErrorDomain()</code> <a class="spec-record-ref" data-req="SWS_DM_00999" href="../spec/record.html?id=SWS_DM_00999">[SWS_DM_00999]</a>、名称查询 <code>Name()</code> <a class="spec-record-ref" data-req="SWS_DM_01000" href="../spec/record.html?id=SWS_DM_01000">[SWS_DM_01000]</a> 以及 <code>Message()</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a> 均声明为 <code>noexcept</code>，并且完全具备异常安全性（exception safe）。</li>
<li><strong>保证返回文本消息：</strong>由于按照契约 <code>Message()</code> 绝不返回 <code>nullptr</code> <a class="spec-record-ref" data-req="SWS_DM_01001" href="../spec/record.html?id=SWS_DM_01001">[SWS_DM_01001]</a>，因此该实现对于未知或无效的错误码大概率也会提供标准化的回退文本。</li>
<li><strong>抛出异常时的行为：</strong>函数 <code>ThrowAsException()</code> 使用 <code>noexcept(false)</code> 进行注解，并被归类为非异常安全（not exception safe）<a class="spec-record-ref" data-req="SWS_DM_01002" href="../spec/record.html?id=SWS_DM_01002">[SWS_DM_01002]</a>，因为其主要目的就在于针对性地抛出异常。</li>
