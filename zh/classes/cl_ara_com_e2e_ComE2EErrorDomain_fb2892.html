上下文

类 ara::com::e2e::ComE2EErrorDomain 表示 AUTOSAR Adaptive Communication Management 中间件（ara::com）内端到端保护（E2E）框架下错误的特定错误域。它继承自基础架构基类 ara::core::ErrorDomain，并为消息 E2E 验证期间发生的所有通信错误定义了标准化的错误上下文。

在分布式自适应应用程序的交互中，ComE2EErrorDomain 负责识别和映射在发送或接收受 E2E 保护的方法和事件数据时检测到的错误。如果在方法调用期间，服务端在请求消息的 E2E 检查（E2E_check）过程中检测到错误，则会生成一条 E2E 错误响应消息（AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.4.2 “Serializing the response payload”）。该错误响应的有效载荷包含一个 ara::core::ErrorCode，其错误域必须设置为 ara::com::e2e::ComE2EErrorDomain（[SWS_CM_00033]）。错误值本身反映了校验例程的具体结果（[SWS_CM_00033]）。

在客户端，中间件对响应消息进行评估：如果客户端在反序列化或通知时检测到 E2E 错误，通信层会向调用应用程序提供一个 ara::core::Result（AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”）。如果发生 E2E 检查错误，该 Result 会封装一个来自域 ComE2EErrorDomain 的 ara::core::ErrorCode，其中包含枚举 ComE2EErrc 对应的错误代码（AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”）。

生命周期

ComE2EErrorDomain 的实例化通过一个无参 constexpr 构造函数（[SWS_CM_12506]）进行。由于该构造函数被声明为 constexpr 和 noexcept（[SWS_CM_12506]），因此实例在编译时或应用程序的静态初始化阶段即可创建。

解释：根据 ara::core::ErrorDomain 的通用架构模式，该类通常应该作为全局不可变的单例提供，以便在整个运行期间保留与错误相关的文本和类型信息。

该类被声明为 final，因此排除了进一步派生的可能。由于所有查询成员函数（如 Name()（[SWS_CM_12507]）和 Message()（[SWS_CM_12508]））均被指定为 const 和 noexcept，因此该类不包含可变状态。这带来了完全的异常安全性（exception safe）以及在应用程序或中间件例程的多个线程并发访问时的无限制线程安全性。在实例的整个生命周期中，无需采取特殊的同步或加锁措施。

使用路径

ComE2EErrorDomain 的常规使用路径涵盖服务端错误检测、错误信息传输以及客户端评估：

  1. 服务端 E2E 检查：当收到受 E2E 保护的方法调用时，服务端的通信层执行检查 E2E_check（[SWS_CM_00033]）。
  2. 生成错误响应：如果检查失败，服务端将序列化一个 E2E 错误响应，其有效载荷包含具有域 ComE2EErrorDomain 的 ara::core::ErrorCode（[SWS_CM_00033]）。
  3. 客户端评估：在接收并反序列化响应消息（AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”）之后，ara::com 向客户端应用程序提供一个 ara::core::Result，在发生错误时该对象封装了传输的 ara::core::ErrorCode。
  4. 查询错误详细信息：应用程序检查 Result，并通过错误域 ComE2EErrorDomain 使用 Message()（[SWS_CM_12508]）获取文本描述，或使用 Name()（[SWS_CM_12507]）获取域名。
  5. 可选的异常处理：如果应用程序倾向于异常处理，则通过 ThrowAsException() 将 ErrorCode 转换为具体异常（[SWS_CM_12509]）。

错误场景

在发生故障的通信场景中，ComE2EErrorDomain 充当数字检查代码与易于理解的诊断之间的纽带：

  • 错误代码映射：类型别名 Errc 映射枚举 ComE2EErrc（[SWS_CM_12504]）。每个具体的错误值均通过函数 Message() 解析为描述性字符串（[SWS_CM_12508]），以实现精确的根本原因分析（例如校验和错误或计数器值无效）。
  • 域标识：通过 Name()，实例返回错误域的标准化名称（[SWS_CM_12507]），从而使应用程序能够可靠地检查发生的错误对象是否来自 E2E 域。
  • 异常处理和编译器配置：类型别名 Exception 绑定异常类 ComE2EException（[SWS_CM_12505]）。如果使用 ara::core::ErrorCode 调用 ThrowAsException()，则该方法实例化一个 ComE2EException 并将其抛出（[SWS_CM_12509]）。该函数被声明为非异常安全（not exception safe）（[SWS_CM_12509]）。如果编译器工具链中禁用了 C++ 异常，则按照规范 ThrowAsException() 不参与重载决议（[SWS_CM_12509]），因此应用程序必须改为通过 ara::core::Result 基于错误代码进行工作。

本类指南基于 AUTOSAR Adaptive R25-11 Communication Management 规范，并对 E2E 错误域进行了总结。

<h4>上下文</h4>
<p>类 <code>ara::com::e2e::ComE2EErrorDomain</code> 表示 AUTOSAR Adaptive Communication Management 中间件（<code>ara::com</code>）内端到端保护（E2E）框架下错误的特定错误域。它继承自基础架构基类 <code>ara::core::ErrorDomain</code>，并为消息 E2E 验证期间发生的所有通信错误定义了标准化的错误上下文。</p>
<p>在分布式自适应应用程序的交互中，<code>ComE2EErrorDomain</code> 负责识别和映射在发送或接收受 E2E 保护的方法和事件数据时检测到的错误。如果在方法调用期间，服务端在请求消息的 E2E 检查（<code>E2E_check</code>）过程中检测到错误，则会生成一条 E2E 错误响应消息（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=254">AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.4.2 “Serializing the response payload”</a>）。该错误响应的有效载荷包含一个 <code>ara::core::ErrorCode</code>，其错误域必须设置为 <code>ara::com::e2e::ComE2EErrorDomain</code>（<a class="spec-record-ref" data-req="SWS_CM_00033" href="../spec/record.html?id=SWS_CM_00033">[SWS_CM_00033]</a>）。错误值本身反映了校验例程的具体结果（<a class="spec-record-ref" data-req="SWS_CM_00033" href="../spec/record.html?id=SWS_CM_00033">[SWS_CM_00033]</a>）。</p>
<p>在客户端，中间件对响应消息进行评估：如果客户端在反序列化或通知时检测到 E2E 错误，通信层会向调用应用程序提供一个 <code>ara::core::Result</code>（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=261">AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”</a>）。如果发生 E2E 检查错误，该 <code>Result</code> 会封装一个来自域 <code>ComE2EErrorDomain</code> 的 <code>ara::core::ErrorCode</code>，其中包含枚举 <code>ComE2EErrc</code> 对应的错误代码（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=261">AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”</a>）。</p>

<h4>生命周期</h4>
<p><code>ComE2EErrorDomain</code> 的实例化通过一个无参 <code>constexpr</code> 构造函数（<a class="spec-record-ref" data-req="SWS_CM_12506" href="../spec/record.html?id=SWS_CM_12506">[SWS_CM_12506]</a>）进行。由于该构造函数被声明为 <code>constexpr</code> 和 <code>noexcept</code>（<a class="spec-record-ref" data-req="SWS_CM_12506" href="../spec/record.html?id=SWS_CM_12506">[SWS_CM_12506]</a>），因此实例在编译时或应用程序的静态初始化阶段即可创建。</p>
<p>解释：根据 <code>ara::core::ErrorDomain</code> 的通用架构模式，该类通常应该作为全局不可变的单例提供，以便在整个运行期间保留与错误相关的文本和类型信息。</p>
<p>该类被声明为 <code>final</code>，因此排除了进一步派生的可能。由于所有查询成员函数（如 <code>Name()</code>（<a class="spec-record-ref" data-req="SWS_CM_12507" href="../spec/record.html?id=SWS_CM_12507">[SWS_CM_12507]</a>）和 <code>Message()</code>（<a class="spec-record-ref" data-req="SWS_CM_12508" href="../spec/record.html?id=SWS_CM_12508">[SWS_CM_12508]</a>））均被指定为 <code>const</code> 和 <code>noexcept</code>，因此该类不包含可变状态。这带来了完全的异常安全性（<code>exception safe</code>）以及在应用程序或中间件例程的多个线程并发访问时的无限制线程安全性。在实例的整个生命周期中，无需采取特殊的同步或加锁措施。</p>

<h4>使用路径</h4>
<p><code>ComE2EErrorDomain</code> 的常规使用路径涵盖服务端错误检测、错误信息传输以及客户端评估：</p>
<ol>
<li><strong>服务端 E2E 检查：</strong>当收到受 E2E 保护的方法调用时，服务端的通信层执行检查 <code>E2E_check</code>（<a class="spec-record-ref" data-req="SWS_CM_00033" href="../spec/record.html?id=SWS_CM_00033">[SWS_CM_00033]</a>）。</li>
<li><strong>生成错误响应：</strong>如果检查失败，服务端将序列化一个 E2E 错误响应，其有效载荷包含具有域 <code>ComE2EErrorDomain</code> 的 <code>ara::core::ErrorCode</code>（<a class="spec-record-ref" data-req="SWS_CM_00033" href="../spec/record.html?id=SWS_CM_00033">[SWS_CM_00033]</a>）。</li>
<li><strong>客户端评估：</strong>在接收并反序列化响应消息（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_CommunicationManagement&amp;page=261">AUTOSAR_AP_SWS_CommunicationManagement §7.4.1.2.5.2 “Deserializing the payload”</a>）之后，<code>ara::com</code> 向客户端应用程序提供一个 <code>ara::core::Result</code>，在发生错误时该对象封装了传输的 <code>ara::core::ErrorCode</code>。</li>
<li><strong>查询错误详细信息：</strong>应用程序检查 <code>Result</code>，并通过错误域 <code>ComE2EErrorDomain</code> 使用 <code>Message()</code>（<a class="spec-record-ref" data-req="SWS_CM_12508" href="../spec/record.html?id=SWS_CM_12508">[SWS_CM_12508]</a>）获取文本描述，或使用 <code>Name()</code>（<a class="spec-record-ref" data-req="SWS_CM_12507" href="../spec/record.html?id=SWS_CM_12507">[SWS_CM_12507]</a>）获取域名。</li>
<li><strong>可选的异常处理：</strong>如果应用程序倾向于异常处理，则通过 <code>ThrowAsException()</code> 将 <code>ErrorCode</code> 转换为具体异常（<a class="spec-record-ref" data-req="SWS_CM_12509" href="../spec/record.html?id=SWS_CM_12509">[SWS_CM_12509]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>在发生故障的通信场景中，<code>ComE2EErrorDomain</code> 充当数字检查代码与易于理解的诊断之间的纽带：</p>
<ul>
<li><strong>错误代码映射：</strong>类型别名 <code>Errc</code> 映射枚举 <code>ComE2EErrc</code>（<a class="spec-record-ref" data-req="SWS_CM_12504" href="../spec/record.html?id=SWS_CM_12504">[SWS_CM_12504]</a>）。每个具体的错误值均通过函数 <code>Message()</code> 解析为描述性字符串（<a class="spec-record-ref" data-req="SWS_CM_12508" href="../spec/record.html?id=SWS_CM_12508">[SWS_CM_12508]</a>），以实现精确的根本原因分析（例如校验和错误或计数器值无效）。</li>
<li><strong>域标识：</strong>通过 <code>Name()</code>，实例返回错误域的标准化名称（<a class="spec-record-ref" data-req="SWS_CM_12507" href="../spec/record.html?id=SWS_CM_12507">[SWS_CM_12507]</a>），从而使应用程序能够可靠地检查发生的错误对象是否来自 E2E 域。</li>
<li><strong>异常处理和编译器配置：</strong>类型别名 <code>Exception</code> 绑定异常类 <code>ComE2EException</code>（<a class="spec-record-ref" data-req="SWS_CM_12505" href="../spec/record.html?id=SWS_CM_12505">[SWS_CM_12505]</a>）。如果使用 <code>ara::core::ErrorCode</code> 调用 <code>ThrowAsException()</code>，则该方法实例化一个 <code>ComE2EException</code> 并将其抛出（<a class="spec-record-ref" data-req="SWS_CM_12509" href="../spec/record.html?id=SWS_CM_12509">[SWS_CM_12509]</a>）。该函数被声明为非异常安全（<code>not exception safe</code>）（<a class="spec-record-ref" data-req="SWS_CM_12509" href="../spec/record.html?id=SWS_CM_12509">[SWS_CM_12509]</a>）。如果编译器工具链中禁用了 C++ 异常，则按照规范 <code>ThrowAsException()</code> 不参与重载决议（<a class="spec-record-ref" data-req="SWS_CM_12509" href="../spec/record.html?id=SWS_CM_12509">[SWS_CM_12509]</a>），因此应用程序必须改为通过 <code>ara::core::Result</code> 基于错误代码进行工作。</li>
</ul>
