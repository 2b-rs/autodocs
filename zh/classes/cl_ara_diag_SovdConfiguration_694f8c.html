用于在应用程序端提供和处理显式建模的 SOVD 配置资源。

接口 ara::diag::SovdConfiguration 用作显式建模的 SOVD 配置的通用处理程序，Diagnostic Server 会将收到的读写访问转发给它 [SWS_DM_01860]、[SWS_DM_01787]。在完成基于端口的实例化后，应用程序通过 Offer 激活消息接收，并在需要时通过 StopOffer 终止接收 [SWS_DM_01872]、[SWS_DM_01930]。数据提供通过读会话或写会话异步进行，并根据 ISO 17978-3 或 ASAM SOVD 1.1 发出业务错误信号 [SWS_DM_01870]。

上下文

接口 ara::diag::SovdConfiguration 定义了 Adaptive AUTOSAR 诊断架构中显式建模的 SOVD 配置处理程序的通用接口 [SWS_DM_01860]。只要系统中配置了至少一个 SOVD 配置，Diagnostic Management (DM) 的 Diagnostic Server 实例就会按照 ASAM SOVD 向外提供标准化的 SOVD 方法 Retrieve List of All Configurations Provided by the Entity [SWS_DM_01429]。Diagnostic Server 会将针对此类显式配置的传入读写访问转发给 ara::diag::SovdConfiguration 的具体实现：当调用 SOVD 方法 Read Configuration 时，Diagnostic Server 会调用方法 RequestGetConfiguration [SWS_DM_01787]；而当调用 Write Configuration 时，则会执行方法 RequestPutConfiguration [SWS_DM_01788]。

上下文图：ara::diag::SovdConfiguration 在外部 SOVD 客户端、Diagnostic Server (DM) 和应用程序特定 Handler 之间的嵌入。来源：[SWS_DM_01429]、[SWS_DM_01787]、[SWS_DM_01788]、[SWS_DM_01860]。

生命周期

ara::diag::SovdConfiguration 的实例化在应用程序端通过传入一个 ara::core::InstanceSpecifier 以及指定一个 ConcurrencyType（kConcurrent 或 kNotConcurrent）来完成 [SWS_DM_01864]。InstanceSpecifier 引用了进程上下文中 DiagnosticSovdConfigurationInterface 的端口原型 [SWS_DM_01864]。该类不可复制（拷贝构造函数和拷贝赋值运算符被声明为 delete）[SWS_DM_01866]、[SWS_DM_01868]，但支持受保护的移动操作 [SWS_DM_01867]、[SWS_DM_01869]。为了接收来自 Diagnostic Server 的请求，应用程序必须显式调用 Offer [SWS_DM_01872]。通过调用 StopOffer，将再次停用请求的转发 [SWS_DM_01930]。当通过虚析构函数 [SWS_DM_01865] 销毁实例时，对象将被释放；该释放要求此前已正确注销处理程序。

状态图：SovdConfiguration 实例从初始化、Offer 状态到 StopOffer 的生命周期阶段。来源：[SWS_DM_01864]、[SWS_DM_01872]、[SWS_DM_01930]、[SWS_DM_01865]。

使用路径

派生处理程序类构建完成后，典型使用路径始于使用 Offer() 向 Diagnostic Management 注册 [SWS_DM_01872]。一旦外部客户端向实体发起 SOVD 配置请求，Diagnostic Server 就会转发该请求：遇到读取请求时，会调用 RequestGetConfiguration 并传入 configurationId、metaInfo 以及一个 CancellationHandler [SWS_DM_01870]。该方法返回一个 ara::core::Future，它异步提供由 DataTransferReadSession 和 SovdConfigurationMetaInfo 组成的元组 [SWS_DM_01870]。类似地，服务器通过 RequestPutConfiguration 转发写入请求，该方法返回包含 DataTransferWriteSession 和 SovdConfigurationMetaInfo 的 Future [SWS_DM_01871]。在关闭处理程序之前，应用程序会调用 StopOffer()，以不再接受更多请求 [SWS_DM_01930]。

时序图：初始化、处理 Read-Configuration 请求及后续注销的典型交互序列。来源：[SWS_DM_01872]、[SWS_DM_01787]、[SWS_DM_01870]、[SWS_DM_01930]。

错误场景

如果在模型中无法解析 InstanceSpecifier（InstanceSpecifierMappingIntegrityViolation）、所引用的端口原型未由 DiagnosticSovdConfigurationInterface 进行类型化（PortInterfaceMappingViolation）、不存在匹配的进程（ProcessMappingViolation）或标识符在当前进程中已被占用（InstanceSpecifierAlreadyInUseViolation），则在构造函数中进行实例化时就可能出现模型和映射违规 [SWS_DM_01864]。在调用 Offer() 时，该方法返回一个 ara::core::Result<void>；发生错误时，若配置与 DEXT 模型不匹配，则报告 DiagOfferErrc::kConfigurationMismatch；若服务已在提供中，则报告 DiagOfferErrc::kAlreadyOffered [SWS_DM_01872]。在异步处理程序方法 RequestGetConfiguration 和 RequestPutConfiguration 中，应用程序使用符合 ISO 17978-3 或 ASAM SOVD 1.1 的标准化 SOVD 错误代码通过 ara::core::Future 报告错误状态 [SWS_DM_01870]、[SWS_DM_01871]。此外，CancellationHandler 会指示正在进行的通信是否已被中止 [SWS_DM_01870]、[SWS_DM_01871]。

函数 Offer [SWS_DM_01872] Upstream: RS_Diag_04261

ara::core::Result< void > Offer () noexcept;

This Offer will enable the DM to forward request messages to this handler.

使用

类 ara::diag::SovdConfiguration 的方法 Offer 用于启用 Diagnostic Management（DM）向已配置处理程序转发诊断请求 [SWS_DM_01872]。该调用同步发生，不接受任何参数，并通过 ara::core::Result<void> 返回结果 [SWS_DM_01872]。只要处理程序未通过 Offer 提供，DM 就不会转发任何传入请求，这符合诊断接口的基本提供模式（参见 [SWS_DM_01525]，[SWS_DM_00809]）。

错误处理

在发生错误时，将返回带有枚举 DiagOfferErrc 中错误码的 ara::core::Result，并适用回滚语义 [SWS_DM_01872]：

  • DiagOfferErrc::kAlreadyOffered：在服务此前已提供时报告 [SWS_DM_01872]。
  • DiagOfferErrc::kConfigurationMismatch：在配置与 DEXT 描述数据不匹配时发生 [SWS_DM_01872]。

并发性与限制

该操作被声明为 noexcept 且具有异常安全性（exception safe），但被指定为非线程安全（not thread-safe）[SWS_DM_01872]。调用方应用程序必须防止来自多个线程对同一实例的并发调用。推测在已经提供服务后再次调用可能会在不改变状态的情况下返回错误并确认。

      使用
      

      当针对显式建模的 SOVD 配置执行 SOVD 方法“Read Configuration”时，Diagnostic Server Instance 会调用类 ara::diag::SovdConfiguration 的纯虚方法 RequestGetConfiguration（[SWS_DM_01787]，AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.2.1 “Configuration – Explicit Configurations”）。传递的参数包括要读取实例的配置 ID（configurationId）、请求的元信息（metaInfo）以及一个通知当前会话可能已中止的 cancellationHandler（[SWS_DM_01870]）。
      

      该函数以异步方式工作并返回一个 ara::core::Future，该对象提供由文件读取会话（DataTransferReadSession）和关联的配置元信息（SovdConfigurationMetaInfo）组成的元组（[SWS_DM_01870]）。该接口被声明为 noexcept，并被指定为具有异常安全性（[SWS_DM_01870]）。
      

      错误处理与并发
      

      如果处理过程中发生错误，不会抛出 C++ 错误，而是通过 Future 返回符合 ISO 17978-3 或 ASAM SOVD 1.1 的相应 SOVD 错误码（[SWS_DM_01870]）。
      

      关于线程安全性，适用“conditional”规定：该函数的具体实现必须设计为线程安全还是非线程安全，由传递给构造函数的 ConcurrencyType 决定（[SWS_DM_01870]）。
