类 ara::com::InstanceIdentifier

[SWS_CM_00302] Upstream: RS_CM_00101, RS_CM_00102, RS_AP_00114, RS_AP_00127

class InstanceIdentifier {...};

Unique identifier of a specific AdaptivePlatformServiceInstance, to distinguish different instances of exactly the same service. ara::com::InstanceIdentifier satisfies the [equalitycomparable], [lessthancomparable] and [copyassignable] requirements as per [30] to allow for logging of ara::com::InstanceIdentifiers as well as storing and managing ara::com::InstanceIdentifiers by the application (see operators). ara:: com::InstanceIdentifier does not contain a fully qualified name, which would also have service type information.

上下文

类 ara::com::InstanceIdentifier 用于在 Adaptive Platform 上唯一标识具体服务实例（AdaptivePlatformServiceInstance），以区分同一服务类型的不同实例（AUTOSAR_AP_EXP_ARAComAPI 第22页 “InstanceIdentifier class”）。该标识符特意不包含完全限定类型名称，因此不携带任何服务类型信息。

虽然应用程序开发人员通常使用来自软件组件模型的抽象实例说明符（ara::core::InstanceSpecifier）进行工作（AUTOSAR_AP_EXP_ARAComAPI 第23页 “InstanceSpecifier class”，AUTOSAR_AP_EXP_ARAComAPI 第25页 “Direct use of InstanceIdentifier”），但 ara::com::InstanceIdentifier 代表耦合到具体中间件绑定（Middleware-Binding）的技术标识符。抽象模型说明符与技术实例 ID 之间的映射由集成商在部署时通过清单文件确定（AUTOSAR_AP_EXP_ARAComAPI 第23页 “InstanceSpecifier class”）。这允许使用不同的清单和绑定多次启动同一个 Executable。

通过函数 ResolveInstanceIDs()，应用程序可以将 ara::core::InstanceSpecifier 解析为 InstanceIdentifier 对象的集合（AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”）。除其他功能外，服务器端和客户端的多绑定（Multi-Binding）也是通过该方式实现的。

生命周期

作为常规值类型，ara::com::InstanceIdentifier 遵循完整的值语义。该类满足 ISO/IEC 14882:2014 的 C++ 要求 [equalitycomparable]、[lessthancomparable] 和 [copyassignable]，因此实例可以在标准容器中轻松进行管理和排序。

  • 创建：实例主要通过 ResolveInstanceIDs() 进行解析生成（AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”）。对于特定用例和持久化，还提供了显式构造函数 [SWS_CM_11521] 以及静态工厂方法 Create() [SWS_CM_11520]，它们接收序列化格式（ara::core::StringView）。
  • 复制与移动：拷贝和移动构造函数（[SWS_CM_00056]，[SWS_CM_00053]）以及相应的赋值运算符（[SWS_CM_11525]，[SWS_CM_00054]）均声明为 noexcept，并保证异常安全性。
  • 序列化：可以通过方法 toString() [SWS_CM_11522] 查询序列化表示。与字符串构造函数一起，这使得标识符的传输、持久化存储以及后续复用成为可能（AUTOSAR_AP_EXP_ARAComAPI 第22页 “InstanceIdentifier class”）。
  • 销毁：析构函数 [SWS_CM_00055] 为 noexcept，并确定性地释放资源。
  • 并发性：Interpretation: 由于 ara::com::InstanceIdentifier 在构造后代表一个不可变的值对象，且读取接口为 const，因此多个线程的并发读取访问在无需同步的情况下应当是安全的。

使用路径

ara::com::InstanceIdentifier 的直接使用适用于高级用例（AUTOSAR_AP_EXP_ARAComAPI 第25页 “Direct use of InstanceIdentifier”）。典型流程如下：

  1. 解析：应用程序使用 ResolveInstanceIDs() 解析抽象的 ara::core::InstanceSpecifier 并获取 InstanceIdentifierContainer（AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”）。或者，它通过 Create() [SWS_CM_11520] 重构实例。
  2. 服务搜索或绑定：该标识符被传递给重载 FindService(instanceId)（AUTOSAR_AP_EXP_ARAComAPI 第31页 “FindService Overload”）以专门搜索该服务实例，或直接传递给服务代理（Service-Proxy）或服务骨架（Service-Skeleton）的构造函数（AUTOSAR_AP_EXP_ARAComAPI 第30页 “InstanceId in Proxy and Skeleton”）。
  3. 实例查询：正在运行的实例通过方法 GetInstanceId() 提供其标识符（AUTOSAR_AP_EXP_ARAComAPI 第30页 “InstanceId in Proxy and Skeleton”）。
  4. 比较与记录：标识符使用 operator== [SWS_CM_11523] 和 operator< [SWS_CM_11524] 进行比较，或通过 toString() [SWS_CM_11522] 记录用于日志记录。

错误场景

在使用 ara::com::InstanceIdentifier 时，可能会出现以下错误条件和偏差：

  • 无效的字符串表示：如果在通过构造函数 [SWS_CM_11521] 或 Create() [SWS_CM_11520] 进行构造时传递了损坏的、不合规的或重复的字符串，则会发生违规 InvalidInstanceIdentifierStringViolation。虽然构造函数被明确归类为 not exception safe，但 Create() 被指定为 noexcept。Interpretation: 由于 Create() 不返回 ara::core::Result，所报告的违规在平台端可能会导致进程立即终止。
  • 缺少部署映射：如果集成商在清单中未为抽象说明符配置映射，ResolveInstanceIDs() 将返回一个空列表（AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”）。因此，调用方必须在进一步使用之前检查有效标识符是否存在。
  • 不允许的自省：序列化字符串的内容严格特定于中间件和绑定（AUTOSAR_AP_EXP_ARAComAPI 第22页 “InstanceIdentifier class”）。应用程序端对其进行解析或格式分解的任何尝试都会导致可移植性问题，并构成误操作。

<h4>上下文</h4>
<p>类 <code>ara::com::InstanceIdentifier</code> 用于在 Adaptive Platform 上唯一标识具体服务实例（<code>AdaptivePlatformServiceInstance</code>），以区分同一服务类型的不同实例（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=22">AUTOSAR_AP_EXP_ARAComAPI 第22页 “InstanceIdentifier class”</a>）。该标识符特意不包含完全限定类型名称，因此不携带任何服务类型信息。</p>
<p>虽然应用程序开发人员通常使用来自软件组件模型的抽象实例说明符（<code>ara::core::InstanceSpecifier</code>）进行工作（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=23">AUTOSAR_AP_EXP_ARAComAPI 第23页 “InstanceSpecifier class”</a>，<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=25">AUTOSAR_AP_EXP_ARAComAPI 第25页 “Direct use of InstanceIdentifier”</a>），但 <code>ara::com::InstanceIdentifier</code> 代表耦合到具体中间件绑定（Middleware-Binding）的技术标识符。抽象模型说明符与技术实例 ID 之间的映射由集成商在部署时通过清单文件确定（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=23">AUTOSAR_AP_EXP_ARAComAPI 第23页 “InstanceSpecifier class”</a>）。这允许使用不同的清单和绑定多次启动同一个 Executable。</p>
<p>通过函数 <code>ResolveInstanceIDs()</code>，应用程序可以将 <code>ara::core::InstanceSpecifier</code> 解析为 <code>InstanceIdentifier</code> 对象的集合（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=24">AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”</a>）。除其他功能外，服务器端和客户端的多绑定（Multi-Binding）也是通过该方式实现的。</p>

<h4>生命周期</h4>
<p>作为常规值类型，<code>ara::com::InstanceIdentifier</code> 遵循完整的值语义。该类满足 ISO/IEC 14882:2014 的 C++ 要求 <code>[equalitycomparable]</code>、<code>[lessthancomparable]</code> 和 <code>[copyassignable]</code>，因此实例可以在标准容器中轻松进行管理和排序。</p>

<h4>错误场景</h4>
<p>在使用 <code>ara::com::InstanceIdentifier</code> 时，可能会出现以下错误条件和偏差：</p>
<ul>
<li><strong>无效的字符串表示：</strong>如果在通过构造函数 <a class="spec-record-ref" data-req="SWS_CM_11521" href="../spec/record.html?id=SWS_CM_11521">[SWS_CM_11521]</a> 或 <code>Create()</code> <a class="spec-record-ref" data-req="SWS_CM_11520" href="../spec/record.html?id=SWS_CM_11520">[SWS_CM_11520]</a> 进行构造时传递了损坏的、不合规的或重复的字符串，则会发生违规 <code>InvalidInstanceIdentifierStringViolation</code>。虽然构造函数被明确归类为 <em>not exception safe</em>，但 <code>Create()</code> 被指定为 <code>noexcept</code>。Interpretation: 由于 <code>Create()</code> 不返回 <code>ara::core::Result</code>，所报告的违规在平台端可能会导致进程立即终止。</li>
<li><strong>缺少部署映射：</strong>如果集成商在清单中未为抽象说明符配置映射，<code>ResolveInstanceIDs()</code> 将返回一个空列表（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=24">AUTOSAR_AP_EXP_ARAComAPI 第24页 “InstanceSpecifier Resolution”</a>）。因此，调用方必须在进一步使用之前检查有效标识符是否存在。</li>
<li><strong>不允许的自省：</strong>序列化字符串的内容严格特定于中间件和绑定（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_EXP_ARAComAPI&amp;page=22">AUTOSAR_AP_EXP_ARAComAPI 第22页 “InstanceIdentifier class”</a>）。应用程序端对其进行解析或格式分解的任何尝试都会导致可移植性问题，并构成误操作。</li>
</ul>
