上下文

接口 ara::crypto::cryp::VerifierPublicCtx 在 Adaptive AUTOSAR 平台中构成了通过非对称密码学（公钥方法）进行数字签名验证的标准化抽象。它继承自基础上下文 CryptoContext，并封装了签名验证算法的状态以及数学运算。

签名验证主要涉及三个组件和对象：

  • 调用应用程序：控制验证过程，提供消息数据及签名，并评估验证结果。
  • 密钥源：该类既可以通过 PublicKey::Sptr [SWS_CRYPT_24115] 将公钥作为独立的密钥对象处理，也可以通过受管理的密钥存储位置 KeySlot::Sptr [SWS_CRYPT_50018] 进行处理。
  • 加密上下文 (VerifierPublicCtx)：执行密码学签名比对，可选择单步验证（One-Shot）[SWS_CRYPT_24112] [SWS_CRYPT_50024] 或多步流式验证 [SWS_CRYPT_50019] [SWS_CRYPT_50021] [SWS_CRYPT_50022]。

生命周期

为了进行引用和生命周期管理，该接口将智能指针别名 Sptr 定义为 std::shared_ptr<VerifierPublicCtx> [SWS_CRYPT_24101]。所有接口方法均声明为 noexcept，提供完全异常安全性（exception safe），并且针对并发访问规范为线程安全（thread-safe）。

上下文的生命周期经历三个主要阶段：

  1. 未初始化 (Uninitialized)：创建后，上下文尚未绑定到公钥。在此阶段调用验证方法将因错误而失败。
  2. 就绪 / 已配置 (Configured)：通过使用 PublicKey::Sptr [SWS_CRYPT_24115] 或 KeySlot::Sptr [SWS_CRYPT_50018] 经由 SetKey() 分配密钥，上下文即可投入使用。在此阶段，可以执行单次（One-Shot）验证或初始化流式会话。
  3. 流式活动 (Streaming)：调用 Start() [SWS_CRYPT_50019] 或 Start(context) [SWS_CRYPT_50020] 会使上下文进入正在进行的数据处理状态。随后通过 Update() [SWS_CRYPT_50021] 输入消息分片。该阶段通过 Finish() [SWS_CRYPT_50022] 正常结束，或通过 Cancel() [SWS_CRYPT_50023] 提前结束。解读：假设在流式阶段完成或中止后，上下文仍保持在已配置状态，并且可以使用现有密钥重新启动。

使用路径

签名验证有两种可选的使用模式：

1. 多步流式验证：此模式适用于大数据量或分片接收的消息：

  • 密钥绑定：通过 SetKey() [SWS_CRYPT_24115] 或 [SWS_CRYPT_50018] 分配密钥。
  • 查询缓冲区限制：GetMaximumChunkSize() [SWS_CRYPT_50025] 可选用于获取后续调用中可处理的最大块大小（以字节为单位）。
  • 初始化：若算法需要特定于应用程序的上下文数据，则使用 Start() [SWS_CRYPT_50019] 或 Start(context) [SWS_CRYPT_50020] 启动验证。
  • 数据输入：通过 Update(data) [SWS_CRYPT_50021] 单次或多次传递消息分片。
  • 完成与评估：调用 Finish(signature, signatureFormat) [SWS_CRYPT_50022]。返回的 ara::core::Result<bool> 在签名完好时包含 true，在无效时包含 false。
  • 中止：如果在传输过程中发生错误，可以通过 Cancel() [SWS_CRYPT_50023] 放弃该操作。

时序图：多步签名验证的典型调用顺序，包含中止选项。来源：[SWS_CRYPT_24115]、[SWS_CRYPT_50019]、[SWS_CRYPT_50021]、[SWS_CRYPT_50022]、[SWS_CRYPT_50023]、[SWS_CRYPT_50025]

2. 单步验证 (One-Shot)：如果整个消息已存在于内存中，则在成功执行 SetKey() 后，可以直接调用 Verify(message, signature, signatureFormat) [SWS_CRYPT_24112]，或者在使用了附加上下文时调用 Verify(message, context, signature, signatureFormat) [SWS_CRYPT_50024]。这两种方法均声明为 const。

      <strong>流式活动 (Streaming)：</strong>调用 <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50019" href="../spec/record.html?id=SWS_CRYPT_50019">[SWS_CRYPT_50019]</a> 或 <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50020" href="../spec/record.html?id=SWS_CRYPT_50020">[SWS_CRYPT_50020]</a> 会使上下文进入正在进行的数据处理状态。随后通过 <code>Update()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50021" href="../spec/record.html?id=SWS_CRYPT_50021">[SWS_CRYPT_50021]</a> 输入消息分片。该阶段通过 <code>Finish()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50022" href="../spec/record.html?id=SWS_CRYPT_50022">[SWS_CRYPT_50022]</a> 正常结束，或通过 <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50023" href="../spec/record.html?id=SWS_CRYPT_50023">[SWS_CRYPT_50023]</a> 提前结束。解读：假设在流式阶段完成或中止后，上下文仍保持在已配置状态，并且可以使用现有密钥重新启动。
    </li>
  </ol>

  <h4>使用路径</h4>
  <p>
    签名验证有两种可选的使用模式：
  </p>
  <p>
    <strong>1. 多步流式验证：</strong>此模式适用于大数据量或分片接收的消息：
  </p>
  <ul>
    <li><strong>密钥绑定：</strong>通过 <code>SetKey()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_24115" href="../spec/record.html?id=SWS_CRYPT_24115">[SWS_CRYPT_24115]</a> 或 <a class="spec-record-ref" data-req="SWS_CRYPT_50018" href="../spec/record.html?id=SWS_CRYPT_50018">[SWS_CRYPT_50018]</a> 分配密钥。</li>
    <li><strong>查询缓冲区限制：</strong><code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50025" href="../spec/record.html?id=SWS_CRYPT_50025">[SWS_CRYPT_50025]</a> 可选用于获取后续调用中可处理的最大块大小（以字节为单位）。</li>
    <li><strong>初始化：</strong>若算法需要特定于应用程序的上下文数据，则使用 <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50019" href="../spec/record.html?id=SWS_CRYPT_50019">[SWS_CRYPT_50019]</a> 或 <code>Start(context)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50020" href="../spec/record.html?id=SWS_CRYPT_50020">[SWS_CRYPT_50020]</a> 启动验证。</li>
    <li><strong>数据输入：</strong>通过 <code>Update(data)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50021" href="../spec/record.html?id=SWS_CRYPT_50021">[SWS_CRYPT_50021]</a> 单次或多次传递消息分片。</li>
    <li><strong>完成与评估：</strong>调用 <code>Finish(signature, signatureFormat)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50022" href="../spec/record.html?id=SWS_CRYPT_50022">[SWS_CRYPT_50022]</a>。返回的 <code>ara::core::Result&lt;bool&gt;</code> 在签名完好时包含 <code>true</code>，在无效时包含 <code>false</code>。</li>
    <li><strong>中止：</strong>如果在传输过程中发生错误，可以通过 <code>Cancel()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50023" href="../spec/record.html?id=SWS_CRYPT_50023">[SWS_CRYPT_50023]</a> 放弃该操作。</li>
  </ul>
