用作客户端应用程序的类型化代理，用于服务发现以及与服务实例交互。

类 <SI>Proxy 用作客户端应用程序针对 Service Interface 的类型化代理，用于传输方法调用、事件和字段 [SWS_CM_99447]。在成功进行服务发现后，优先通过无异常的工厂方法 Create() 创建该实例 [SWS_CM_10438]。该类具有仅移动语义，并要求在其析构前完全释放所有引用的数据样本，以避免前置条件违规 [SWS_CM_99444]。

上下文

生成的类 <SI>Proxy 在 AUTOSAR Adaptive Platform 的通信架构中充当已定义 Service Interface 的类型化客户端端点。它封装了客户端应用程序与该服务的远程或本地实例之间的交互。交互伙伴包括使用它的软件组件、代理实例本身以及控制网络绑定和消息传输的基础通信管理（ara::com）。通过专用数据元素 events::<Event> [SWS_CM_99445]、fields::<Field> [SWS_CM_99446] 和 methods::<Method> [SWS_CM_99447]，代理提供对服务接口的事件、字段和方法的直接访问。

上下文图：Service Interface 代理在客户端应用程序与通信管理之间的集成。来源：[SWS_CM_99445]、[SWS_CM_99446]、[SWS_CM_99447]。

生命周期

代理实例的创建以先前成功执行的服务发现为前提，该发现提供有效的句柄实例（HandleType）。首选创建方式是根据命名构造函数惯用法 [SWS_CM_10438]，通过静态工厂方法 Create() 无异常地创建，该方法返回包含代理或错误代码的 ara::core::Result。或者，存在一个显式构造函数 <SI>Proxy(handle)，它被指定为非异常安全，在出错时可能抛出 ara::com::ComException [SWS_CM_00131]。用于初始化的句柄可随时通过 GetHandle() 查询 [SWS_CM_10383]。

在所有权关系方面，代理具有仅移动语义：复制构造函数 [SWS_CM_00136] 和复制赋值运算符 [SWS_CM_11551] 已被显式删除。实例的转移仅允许通过移动构造函数 [SWS_CM_00137] 或异常安全的移动赋值运算符 [SWS_CM_11552] 进行。在生命周期内，可以通过 GetServiceState() 主动确定服务的可用性状态 [SWS_CM_01073]。或者，SetServiceStateChangeHandler() 允许在状态发生变化时注册回调函数 [SWS_CM_01074]，该函数可选择通过 ExecutorT 绑定到用户定义的上下文 [SWS_CM_01076]。处理程序注册可通过 UnsetServiceStateChangeHandler() 注销 [SWS_CM_01075]。

析构通过析构函数 ~<SI>Proxy() 进行 [SWS_CM_99444]。该析构函数未声明为异常安全，并要求强制性前置条件：在析构前，客户端不得再持有未完成的数据样本，以避免违规 [SWS_CM_99444]。

使用路径

典型使用路径分为四个阶段：

  1. 服务发现：客户端寻找服务实例，既可以通过带有 InstanceIdentifier [SWS_CM_00122] 或基于模型的 InstanceSpecifier [SWS_CM_00622] EXP ARAComAPI §2 “Service Interface Proxy” 的 FindService() 同步进行，也可以通过 StartFindService() [SWS_CM_00123] [SWS_CM_00623] 异步进行。对于异步发现，还可以额外传递 ExecutorT [SWS_CM_11352] [SWS_CM_11365] EXP ARAComAPI §2 “Service Interface Proxy”。在找到所需实例后，必须通过 StopFindService() 停止异步发现 [SWS_CM_00125] EXP ARAComAPI §2 “Service Interface Proxy”。
  2. 实例化：从确定的 ServiceHandleContainer 中选择一个句柄，并传递给 Create() 以创建代理实例 [SWS_CM_10438]。解释：相比于会抛出异常的构造函数，工厂方法 Create() 应当是主要的实例化路径。
  3. 交互：应用程序通过方法调用（methods::<Method>）[SWS_CM_99447]、事件监控（events::<Event>）[SWS_CM_99445] 或字段访问（fields::<Field>）[SWS_CM_99446] 与服务进行交互。
  4. 清理：交互完成后，代理实例被析构，此时必须确保不残留无效的样本引用 [SWS_CM_99444]。

时序图：服务发现、代理实例化和方法交互的典型流程。来源：[SWS_CM_00122]、[SWS_CM_10438]、[SWS_CM_99447]、[SWS_CM_99444]。

错误场景

错误主要通过 ara::core::Result 中的错误类型 ara::com::ComErrc 返回：

  • ComErrc::kServiceNotAvailable：在 Create() 时出现，当先前提供的服务不再可用时 [SWS_CM_10438]。直接调用构造函数时，将导致抛出 ara::com::ComException [SWS_CM_00131]。
  • ComErrc::kCommunicationFailure：由 FindService() [SWS_CM_00122] [SWS_CM_00622]、StartFindService() [SWS_CM_00123] [SWS_CM_00623]、Create() [SWS_CM_10438] 和 GetServiceState() [SWS_CM_01073] 报告，当网络绑定检测到可恢复的通信错误或安全通信错误时。

此外，还指定了以下违规（Violations）：

  • ErroneousServiceHandleViolation：传递给 Create() 或构造函数的句柄无效或已损坏 [SWS_CM_10438] [SWS_CM_00131]。
  • InsufficientPermissionsViolation：在服务发现或实例化期间由于权限强制执行（Grant Enforcement）而拒绝访问 [SWS_CM_00122] [SWS_CM_10438]。
  • InvalidHandlerViolation：向 StartFindService() [SWS_CM_00123] 或 SetServiceStateChangeHandler() [SWS_CM_01074] 传递了无效或空的回调。
  • InstanceSpecifierMappingIntegrityViolation、PortInterfaceMappingViolation、ProcessMappingViolation、InstanceSpecifierAlreadyInUseViolation：在基于模型的发现调用中出现，当 InstanceSpecifier 的分配错误或已被使用时 [SWS_CM_00622] [SWS_CM_00623]。
  • DanglingSamplesViolation：在仍存在数据样本引用的情况下析构代理 [SWS_CM_99444]。

本指南基于 Adaptive Platform Release R25-11 的 AUTOSAR 规范，并总结了 Service Interface 代理的通信机制。

用法与语义

静态工厂方法Create用于根据[SWS_CM_10438]按照具名构造函数惯用法（Named-Constructor-Idiom）无异常地创建代理实例（<SI>Proxy）。它需要一个事先根据[SWS_CM_00131]确定的服务句柄作为参数handle。该调用同步进行，并被声明为noexcept。结果在ara::core::Result中返回，在成功情况下，该对象包含就绪可用的代理实例。

错误处理

如果在实例化期间发生错误，Create将通过ara::core::Result返回类型为ara::com::ComErrc的错误代码[SWS_CM_10438]：

  • ComErrc::kServiceNotAvailable：服务在先前通过OfferService()提供后不再可用。
  • ComErrc::kCommunicationFailure：网络绑定报告可恢复的通信错误或安全连接建立失败。

这两种错误都具有回滚语义[SWS_CM_10438]。对于结构性或安全性相关错误，适用的违规（Violations）规则为：如果传入的句柄为 null 或损坏，则存在ErroneousServiceHandleViolation。如果调用进程在授权强制执行（Grant Enforcement）框架内缺少该实例所需的权限，则请求将被拒绝并被视为InsufficientPermissionsViolation（SWS CommunicationManagement §8 “Security”、[SWS_CM_10438]）。

并发性与边界条件

解释：由于Create同步工作并绑定通信资源，因此针对不同句柄的调用可能是可重入的，但由于可能涉及网络初始化，不应在时间关键的硬实时循环中执行。
