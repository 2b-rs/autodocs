上下文

类 ara::crypto::x509::CertificateValidationCtx 提供了符合 RFC 5280 的 X.509 证书和证书路径的验证上下文（[SWS_CRYPT_50122]、[SWS_CRYPT_50123]）。在 Adaptive Platform 的 crypto 模块内，它汇集了配置、受信任的根证书、中间证书以及校验规则，并执行加密路径验证。

验证流程主要涉及以下组件和数据类型：

  • 应用程序：通过验证选项（[SWS_CRYPT_50120]）配置上下文，根据需要设置参考时间（[SWS_CRYPT_50121]），注册信任锚并触发校验。
  • 证书（Certificate）：构成信任基础和校验对象。区分为受信任证书（[SWS_CRYPT_50117]）、用于路径构建的不受信任中间证书（[SWS_CRYPT_50118]）以及目标证书（[SWS_CRYPT_50122]）或证书链（[SWS_CRYPT_50123]）。
  • OCSP 响应（OcspResponse）：用于证明证书的吊销状态，并传递给验证上下文以供考量（[SWS_CRYPT_50124]）。
  • 验证结果（CertificateValidationResult）：在校验完成后封装 RFC 5280 路径验证过程的详细结果（[SWS_CRYPT_50122]、[SWS_CRYPT_50123]）。

上下文图：证书和路径校验中 CertificateValidationCtx 的交互伙伴。来源：[SWS_CRYPT_50117]、[SWS_CRYPT_50118]、[SWS_CRYPT_50122]、[SWS_CRYPT_50123]、[SWS_CRYPT_50124]

生命周期

为了持有和传递上下文实例，接口提供了类型别名 Sptr 作为 std::shared_ptr<CertificateValidationCtx>（[SWS_CRYPT_50116]）。由于该类定义了纯虚方法，具体实现的实例化推测通过加密栈的上层工厂类或提供者类进行。

创建后，上下文处于可配置状态。应用程序逐步注册选项（[SWS_CRYPT_50120]）、证书（[SWS_CRYPT_50117]、[SWS_CRYPT_50118]）、OCSP 响应（[SWS_CRYPT_50124]）或要忽略的关键扩展的 OID（[SWS_CRYPT_50119]）。不支持重置单个注册；针对不同的验证域，应实例化单独的上下文。

关于并发性和容错性，该接口的所有虚成员函数均明确指定为线程安全（thread-safe）和异常安全（exception safe）（[SWS_CRYPT_50117] 至 [SWS_CRYPT_50124]）。因此，多个线程可以并发使用实例。

使用路径

CertificateValidationCtx 的典型用法遵循配置、填充和执行的固定顺序：

  1. 确定配置：通过 SetValidationOptions 传递一个位掩码，用于定义要执行的校验（[SWS_CRYPT_50120]）。可选地，可以通过 SetCurrentTime 选择用于有效性校验的显式参考时间点（[SWS_CRYPT_50121]）；如果未调用此函数，上下文将采用系统时间。如果要容忍应用程序特定验证的关键扩展，则通过 IgnoreCriticalExtension 存入其 OID（[SWS_CRYPT_50119]）。
  2. 注册证书和状态数据：通过 AddTrustedCertificate 添加权威信任锚（根 CA）（[SWS_CRYPT_50117]）。为了便于路径查找，可以通过 AddUntrustedCertificate 输入中间证书（[SWS_CRYPT_50118]）。如果需要纳入吊销信息，则通过 AddOcspResponse 添加 OCSP 响应（[SWS_CRYPT_50124]）。
  3. 执行验证：通过以下两种方法之一进行校验：
    • ValidateCertificate 校验单个终端实体证书，并借助上下文中存储的受信任和不受信任证书构建路径（[SWS_CRYPT_50122]）。
    • ValidateCertificateChain 将现有证书链作为 ara::core::Span 进行验证（[SWS_CRYPT_50123]）。其中元素 0 代表叶证书，每个后续元素代表相应的颁发者。在此模式下，先前通过 AddUntrustedCertificate 存入的证书将被忽略；验证仅针对通过 AddTrustedCertificate 设置的信任锚来校验所传递的证书链。
  4. 评估结果：两个验证函数在成功时均返回一个 CertificateValidationResult::Sptrc，用于评估详细结果（[SWS_CRYPT_50122]、[SWS_CRYPT_50123]）。

时序图：用于配置、注册证书以及执行验证的典型调用顺序。来源：[SWS_CRYPT_50117]、[SWS_CRYPT_50120]、[SWS_CRYPT_50121]、[SWS_CRYPT_50122]、[SWS_CRYPT_50123]、[SWS_CRYPT_50124]

错误场景

所有操作均通过 ara::core::Result 返回错误。标准化的错误代码和特定前置条件包括：

  • 不兼容参数（ara::crypto::CryptoErrc::kIncompatibleArguments）：当虽已通过 AddOcspResponse（[SWS_CRYPT_50124]）存入了 OCSP 响应，但通过 SetValidationOptions（[SWS_CRYPT_50120]）设置的选项并未定义相应的 OCSP 行为时，会在 ValidateCertificate（[SWS_CRYPT_50122]）和 ValidateCertificateChain（[SWS_CRYPT_50123]）中发生。这两个函数都具有回滚语义。
  • 无效配置选项（ara::crypto::CryptoErrc::kInvalidArgument）：如果使用不允许的位掩码调用 SetValidationOptions（[SWS_CRYPT_50120]），则调用失败并具有回滚语义。
  • OCSP 响应的验证错误：对于 AddOcspResponse（[SWS_CRYPT_50124]），OCSP 响应的颁发者必须事先在上下文中存入为受信任或不受信任、由同一 CA 具有 Extended-Key-Usage id-kp-OCSPSigning 的证书签名，或通过可选参数 trustedOcspIssuerCertificate 提供。返回的 Result<CertificateValidationStatus> 在成功采纳时指示 kValid，或提供 OCSP 响应的具体验证状态。
  • 实现特定错误：发生内部错误或达到系统极限时，所有方法均可在 Result 中返回实现特定的错误代码（[SWS_CRYPT_50117] 至 [SWS_CRYPT_50124]）。

本指南基于针对 crypto 模块的 AUTOSAR Adaptive R25-11 规范。

AddOcspResponse 函数

Validate and add an OCSP response to be used during certificate validation to the set of previously added OCSP responses. Multiple OCSP responses may be added to one context. In order to validate the OCSP response, the issuer of the OCSP response must have been a) set as a trusted or untrusted certificate in this context previously, or b) the CRL must have been signed by another certificate that has the id-kp-OCSPSigning extended key usage set issued by the same CA, or c) the CRL must be signed by a trusted CA passed to this function using the optional trustedOcspIssuerCertificate parameter.

<h4>上下文</h4>
<p>
类 <code>ara::crypto::x509::CertificateValidationCtx</code> 提供了符合 RFC 5280 的 X.509 证书和证书路径的验证上下文（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）。在 Adaptive Platform 的 <code>crypto</code> 模块内，它汇集了配置、受信任的根证书、中间证书以及校验规则，并执行加密路径验证。
</p>
<p>
验证流程主要涉及以下组件和数据类型：
</p>
<ul>
<li><strong>应用程序：</strong>通过验证选项（<a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a>）配置上下文，根据需要设置参考时间（<a class="spec-record-ref" data-req="SWS_CRYPT_50121" href="../spec/record.html?id=SWS_CRYPT_50121">[SWS_CRYPT_50121]</a>），注册信任锚并触发校验。</li>
<li><strong>证书（<code>Certificate</code>）：</strong>构成信任基础和校验对象。区分为受信任证书（<a class="spec-record-ref" data-req="SWS_CRYPT_50117" href="../spec/record.html?id=SWS_CRYPT_50117">[SWS_CRYPT_50117]</a>）、用于路径构建的不受信任中间证书（<a class="spec-record-ref" data-req="SWS_CRYPT_50118" href="../spec/record.html?id=SWS_CRYPT_50118">[SWS_CRYPT_50118]</a>）以及目标证书（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>）或证书链（<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）。</li>
<li><strong>OCSP 响应（<code>OcspResponse</code>）：</strong>用于证明证书的吊销状态，并传递给验证上下文以供考量（<a class="spec-record-ref" data-req="SWS_CRYPT_50124" href="../spec/record.html?id=SWS_CRYPT_50124">[SWS_CRYPT_50124]</a>）。</li>
<li><strong>验证结果（<code>CertificateValidationResult</code>）：</strong>在校验完成后封装 RFC 5280 路径验证过程的详细结果（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）。</li>
</ul>

为了持有和传递上下文实例，接口提供了类型别名 <code>Sptr</code> 作为 <code>std::shared_ptr&lt;CertificateValidationCtx&gt;</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50116" href="../spec/record.html?id=SWS_CRYPT_50116">[SWS_CRYPT_50116]</a>）。由于该类定义了纯虚方法，具体实现的实例化推测通过加密栈的上层工厂类或提供者类进行。
</p>
<p>
创建后，上下文处于可配置状态。应用程序逐步注册选项（<a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a>）、证书（<a class="spec-record-ref" data-req="SWS_CRYPT_50117" href="../spec/record.html?id=SWS_CRYPT_50117">[SWS_CRYPT_50117]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50118" href="../spec/record.html?id=SWS_CRYPT_50118">[SWS_CRYPT_50118]</a>）、OCSP 响应（<a class="spec-record-ref" data-req="SWS_CRYPT_50124" href="../spec/record.html?id=SWS_CRYPT_50124">[SWS_CRYPT_50124]</a>）或要忽略的关键扩展的 OID（<a class="spec-record-ref" data-req="SWS_CRYPT_50119" href="../spec/record.html?id=SWS_CRYPT_50119">[SWS_CRYPT_50119]</a>）。不支持重置单个注册；针对不同的验证域，应实例化单独的上下文。
</p>
<p>
关于并发性和容错性，该接口的所有虚成员函数均明确指定为线程安全（<code>thread-safe</code>）和异常安全（<code>exception safe</code>）（<a class="spec-record-ref" data-req="SWS_CRYPT_50117" href="../spec/record.html?id=SWS_CRYPT_50117">[SWS_CRYPT_50117]</a> 至 <a class="spec-record-ref" data-req="SWS_CRYPT_50124" href="../spec/record.html?id=SWS_CRYPT_50124">[SWS_CRYPT_50124]</a>）。因此，多个线程可以并发使用实例。
</p>

<h4>使用路径</h4>
<p>
<code>CertificateValidationCtx</code> 的典型用法遵循配置、填充和执行的固定顺序：
</p>
<ol>
<li><strong>确定配置：</strong>通过 <code>SetValidationOptions</code> 传递一个位掩码，用于定义要执行的校验（<a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a>）。可选地，可以通过 <code>SetCurrentTime</code> 选择用于有效性校验的显式参考时间点（<a class="spec-record-ref" data-req="SWS_CRYPT_50121" href="../spec/record.html?id=SWS_CRYPT_50121">[SWS_CRYPT_50121]</a>）；如果未调用此函数，上下文将采用系统时间。如果要容忍应用程序特定验证的关键扩展，则通过 <code>IgnoreCriticalExtension</code> 存入其 OID（<a class="spec-record-ref" data-req="SWS_CRYPT_50119" href="../spec/record.html?id=SWS_CRYPT_50119">[SWS_CRYPT_50119]</a>）。</li>
<li><strong>注册证书和状态数据：</strong>通过 <code>AddTrustedCertificate</code> 添加权威信任锚（根 CA）（<a class="spec-record-ref" data-req="SWS_CRYPT_50117" href="../spec/record.html?id=SWS_CRYPT_50117">[SWS_CRYPT_50117]</a>）。为了便于路径查找，可以通过 <code>AddUntrustedCertificate</code> 输入中间证书（<a class="spec-record-ref" data-req="SWS_CRYPT_50118" href="../spec/record.html?id=SWS_CRYPT_50118">[SWS_CRYPT_50118]</a>）。如果需要纳入吊销信息，则通过 <code>AddOcspResponse</code> 添加 OCSP 响应（<a class="spec-record-ref" data-req="SWS_CRYPT_50124" href="../spec/record.html?id=SWS_CRYPT_50124">[SWS_CRYPT_50124]</a>）。</li>
<li><strong>执行验证：</strong>通过以下两种方法之一进行校验：
<ul>
<li><code>ValidateCertificate</code> 校验单个终端实体证书，并借助上下文中存储的受信任和不受信任证书构建路径（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>）。</li>
<li><code>ValidateCertificateChain</code> 将现有证书链作为 <code>ara::core::Span</code> 进行验证（<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）。其中元素 0 代表叶证书，每个后续元素代表相应的颁发者。在此模式下，先前通过 <code>AddUntrustedCertificate</code> 存入的证书将被忽略；验证仅针对通过 <code>AddTrustedCertificate</code> 设置的信任锚来校验所传递的证书链。</li>
</ul>
</li>
<li><strong>评估结果：</strong>两个验证函数在成功时均返回一个 <code>CertificateValidationResult::Sptrc</code>，用于评估详细结果（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p>
所有操作均通过 <code>ara::core::Result</code> 返回错误。标准化的错误代码和特定前置条件包括：
</p>
<ul>
<li><strong>不兼容参数（<code>ara::crypto::CryptoErrc::kIncompatibleArguments</code>）：</strong>当虽已通过 <code>AddOcspResponse</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50124" href="../spec/record.html?id=SWS_CRYPT_50124">[SWS_CRYPT_50124]</a>）存入了 OCSP 响应，但通过 <code>SetValidationOptions</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a>）设置的选项并未定义相应的 OCSP 行为时，会在 <code>ValidateCertificate</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50122" href="../spec/record.html?id=SWS_CRYPT_50122">[SWS_CRYPT_50122]</a>）和 <code>ValidateCertificateChain</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50123" href="../spec/record.html?id=SWS_CRYPT_50123">[SWS_CRYPT_50123]</a>）中发生。这两个函数都具有回滚语义。</li>
<li><strong>无效配置选项（<code>ara::crypto::CryptoErrc::kInvalidArgument</code>）：</strong>如果使用不允许的位掩码调用 <code>SetValidationOptions</code>（<a class="spec-record-ref" data-req="SWS_CRYPT_50120" href="../spec/record.html?id=SWS_CRYPT_50120">[SWS_CRYPT_50120]</a>），则调用失败并具有回滚语义。</li>

</ul>
