用于基于配置的信任锚对 X.509 证书和证书链进行路径验证。

类 ara::crypto::x509::CertificateValidationCtx 用于根据 RFC 5280 验证 X.509 证书和完整证书链（[SWS_CRYPT_50122]）。在执行之前，应用程序通过添加信任锚、可选的中间证书、检查时间点以及检查选项来配置上下文，并在需要时集成用于吊销检查的 OCSP 响应（[SWS_CRYPT_50117]）。如果注册了 OCSP 响应，则验证选项必须强制定义相应的 OCSP 行为，以避免路径检查期间的不兼容错误。所有接口方法均具备异常安全性，并针对并发访问设计。

上下文

类 ara::crypto::x509::CertificateValidationCtx 定义了根据 RFC 5280 验证 X.509 证书和证书链的标准化接口（[SWS_CRYPT_50122]，[SWS_CRYPT_50123]）。在 AUTOSAR Adaptive Platform 的整个系统中，它承担着证明信任关系、验证证书路径以及在加密证书用于安全关系之前确定其状态的任务。

调用方应用程序作为核心交互伙伴，为上下文提供信任锚（[SWS_CRYPT_50117]）、不可信的中间证书（[SWS_CRYPT_50118]）以及采用 OCSP 响应形式的吊销信息（[SWS_CRYPT_50124]）。验证结果作为 CertificateValidationResult（[SWS_CRYPT_50122]）提供。

上下文图：CertificateValidationCtx 在应用程序、输入证书、吊销检查与结果对象之间的集成。来源：[SWS_CRYPT_50117]，[SWS_CRYPT_50122]，[SWS_CRYPT_50124]。

生命周期

该接口的实例通过类型别名 Sptr（[SWS_CRYPT_50116]）作为 std::shared_ptr<CertificateValidationCtx> 进行管理，这实现了使用该接口的软件组件的共享所有权和灵活的生命周期控制。由于它是一个纯虚接口类，因此不存在公共构造函数；具体上下文实例的创建推测可能通过加密栈的提供程序实现的相应创建函数来完成。

在并发性方面，所有虚成员函数均被指定为线程安全（thread-safe）（[SWS_CRYPT_50117]，[SWS_CRYPT_50120]，[SWS_CRYPT_50122]）。此外，所有方法均保证异常安全（exception safe），并声明为 noexcept（[SWS_CRYPT_50117]，[SWS_CRYPT_50122]）。在状态方面，上下文表现为一个可配置的累加器：它接收检查参数、证书和状态响应，并将其保留用于验证步骤。

使用路径

验证上下文的典型用法分为由配置步骤和随后的验证执行构成的结构化序列：

  1. 存储信任锚：通过 AddTrustedCertificate（[SWS_CRYPT_50117]）添加一个或多个受信任的证书作为路径验证的起点。额外的不可信中间证书可以通过 AddUntrustedCertificate（[SWS_CRYPT_50118]）提供。
  2. 配置验证规则和参考时间：通过 SetValidationOptions（[SWS_CRYPT_50120]）传递一个位掩码以控制检查行为。使用 SetCurrentTime（[SWS_CRYPT_50121]）可以为有效性检查定义显式的时间点；如果省略此调用，上下文将自动采用系统时间（[SWS_CRYPT_50121]）。如果要从检查中排除特定的不受支持的关键扩展，则可以通过 IgnoreCriticalExtension（[SWS_CRYPT_50119]）注册其 OID。如果设置了选项 kIgnoreUnknownCriticalExtensions，则此操作无效（[SWS_CRYPT_50119]）。
  3. 补充吊销信息：可以通过 AddOcspResponse（[SWS_CRYPT_50124]）添加一个或多个 OCSP 响应。OCSP 响应的颁发者必须此前已作为证书存储在上下文中、具有同一 CA 的扩展密钥用法属性 id-kp-OCSPSigning，或者通过可选参数 trustedOcspIssuerCertificate 传递（[SWS_CRYPT_50124]）。
  4. 执行验证：ValidateCertificate（[SWS_CRYPT_50122]）用于检查目标证书。或者，ValidateCertificateChain（[SWS_CRYPT_50123]）验证有序证书链，从位置 0 处的叶证书开始。在此过程中，先前通过 AddUntrustedCertificate 注册的证书将被忽略，仅针对受信任证书检查所传递的链（[SWS_CRYPT_50123]）。

时序图：用于配置和验证证书的典型调用顺序。来源：[SWS_CRYPT_50117]，[SWS_CRYPT_50120]，[SWS_CRYPT_50122]，[SWS_CRYPT_50124]。

错误场景

错误处理通过 ara::core::Result 一致进行，不使用 C++ 异常：

  • 无效的配置选项：如果使用非法的位掩码调用 SetValidationOptions，则调用失败并返回具有回滚语义的错误代码 ara::crypto::CryptoErrc::kInvalidArgument（[SWS_CRYPT_50120]）。
  • 相互矛盾的 OCSP 配置：如果已通过 AddOcspResponse 存储了至少一个 OCSP 响应，而未在 CertificateValidationOptions 中指定 OCSP 的行为，则 ValidateCertificate（[SWS_CRYPT_50122]）和 ValidateCertificateChain（[SWS_CRYPT_50123]）均返回具有回滚语义的错误 ara::crypto::CryptoErrc::kIncompatibleArguments。
  • OCSP 验证失败：如果在 AddOcspResponse（[SWS_CRYPT_50124]）中无法根据定义的准则验证 OCSP 响应的签名或来源，则该函数返回相应的状态码 CertificateValidationStatus 或特定于实现的错误，而不是 kValid。
  • 特定于实现的错误：如果加密库发生内部问题，诸如 AddTrustedCertificate（[SWS_CRYPT_50117]）或 IgnoreCriticalExtension（[SWS_CRYPT_50119]）之类的方法可能会在结果对象中报告特定于实现的错误代码。

使用

类 ara::crypto::x509::CertificateValidationCtx 的方法 AddOcspResponse 验证传入的 OCSP 响应（ocspResponse），并在有效时将其添加到验证上下文中已存储的 OCSP 响应集中 [SWS_CRYPT_50124]。可以向一个上下文中添加多个响应 [SWS_CRYPT_50124]。通过可选参数 trustedOcspIssuerCertificate 可以传入特定证书，该证书在检查 OCSP 响应时被视为受信任；如果省略此参数，验证将采用先前通过 AddTrustedCertificate 配置的证书 [SWS_CRYPT_50124]。

同步调用返回一个 ara::core::Result<CertificateValidationStatus>，其在成功接收时包含状态 kValid，或在其他情况下反映 OCSP 验证的结果或错误 [SWS_CRYPT_50124]。

错误处理

规范未为此调用定义标准化的错误码 [SWS_CRYPT_50124]。如果操作失败，则要么在结果中传递相应的验证状态，要么通过 Result 对象指示特定于实现的错误 [SWS_CRYPT_50124]。

并发性与限制

该操作被指定为线程安全且异常安全 [SWS_CRYPT_50124]。为了使 OCSP 响应的验证成功，必须满足以下条件之一 [SWS_CRYPT_50124]：

  • 签发者之前已作为受信任或不受信任的证书存储在上下文中 [SWS_CRYPT_50124]。
  • 签名来自同一证书颁发机构（CA）且设置了扩展 id-kp-OCSPSigning 的证书 [SWS_CRYPT_50124]。
  • 签名来自直接通过 trustedOcspIssuerCertificate 传入的受信任 CA [SWS_CRYPT_50124]。

相互作用

已注册的 OCSP 响应会进入后续的验证检查中，正如 [SWS_CRYPT_50122]（ValidateCertificate）和 [SWS_CRYPT_50123]（ValidateCertificateChain）所执行的那样。解释：OCSP 响应大概率需要在路径验证启动之前添加，以便能够考虑证书的吊销状态。
