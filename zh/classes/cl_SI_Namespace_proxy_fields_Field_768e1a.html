上下文

C++ 类<SI-Namespace>::proxy::fields::<Field>表示在服务接口中声明的字段的客户端代表。在 AUTOSAR Adaptive Platform 中，字段结合了可查询状态值、可修改状态值以及用于值变更通知的事件流的特性。

该类主要与调用应用程序逻辑以及底层的 Communication Management 进行交互。根据服务接口中的建模，该类提供不同的接口元素：

  • Getter：如果在接口中配置了Field.hasGetter == TRUE，则存在用于异步值查询的方法Get()（[SWS_CM_00112]；AUTOSAR_AP_EXP_ARAComAPI 第10页）。
  • Setter：如果定义了Field.hasSetter == TRUE，该类提供用于更改值的方法Set()（[SWS_CM_00113]；AUTOSAR_AP_EXP_ARAComAPI 第10页）。
  • Notifier：关于已更改字段值的传入通知通过基于订阅的接收机制在本地数据缓存中提供（[SWS_CM_11601]，[SWS_CM_11610]）。

此外，该类还为端到端保护（E2E）提供监控功能：可以分别针对 Getter（[SWS_CM_00145]）、Setter（[SWS_CM_00146]）和 Notifier（[SWS_CM_11612]）单独检索 E2E 状态机的状态。

生命周期

<SI-Namespace>::proxy::fields::<Field>实例的生命周期推测与聚合该字段的上层服务代理实例的生命周期绑定。

对于 Notifier 功能，存在一个显式的订阅生命周期。状态包括kNotSubscribed、kSubscriptionPending和kSubscribed。通过调用Subscribe()并指定缓冲区大小maxSampleCount来请求订阅（[SWS_CM_11601]）。若在此调用时字段已处于状态kSubscribed或kSubscriptionPending且配额未变，则该调用无效果（[SWS_CM_11601]）。

当前订阅状态可通过GetSubscriptionState()查询（[SWS_CM_11604]）。状态转换可通过使用SetSubscriptionStateChangeHandler()注册处理程序来进行监控（[SWS_CM_00106]，[SWS_CM_11607]），也可选择使用自定义执行器（[SWS_CM_11608]）。处理程序可通过UnsetSubscriptionStateChangeHandler()重新移除（[SWS_CM_11609]）。

终止通知通过Unsubscribe()完成（[SWS_CM_11602]）。如果调用时字段未被订阅，该方法不执行任何操作直接返回（[SWS_CM_11602]）。此外，针对 Notifier 通道上的传输故障，可以注册（[SWS_CM_00109]，[SWS_CM_00110]）和注销传输故障处理程序（[SWS_CM_00126]）。

状态图：代理字段的 Notifier 订阅状态转换。来源：[SWS_CM_11601]、[SWS_CM_11602]、[SWS_CM_11604]。

使用路径

与字段的典型交互包括两个独立的通信路径：

  1. 订阅与样本处理：
    • 应用程序使用Subscribe(maxSampleCount)为更新预留缓冲区槽位（[SWS_CM_11601]）。
    • 通过SetReceiveHandler()注册一个回调，该回调在新的字段数据到达时被触发（[SWS_CM_11605]，根据[SWS_CM_11611]可选配合执行器）。
    • 在处理程序中，应用程序调用GetNewSamples(f, maxNumberOfSamples)以处理本地缓存中的新值（[SWS_CM_11610]）。使用GetFreeSampleCount()可以查询剩余的空闲缓存位置数量（[SWS_CM_11603]）。
    • 最后，通过UnsetReceiveHandler()注销处理程序（[SWS_CM_11606]），并通过Unsubscribe()终止订阅（[SWS_CM_11602]）。
  2. 直接值检索与修改：
    • 应用程序使用Get()请求当前值，并获得一个ara::core::Future<FieldType>（[SWS_CM_00112]；根据[SWS_CM_11403]的类型别名FieldType）。
    • 通过Set(value)将新值传输到服务骨架，这也通过一个ara::core::Future<FieldType>进行同步（[SWS_CM_00113]）。

时序图：由订阅、Notifier 接收以及 Get 和 Set 调用组成的典型序列。来源：[SWS_CM_00112]、[SWS_CM_00113]、[SWS_CM_11601]、[SWS_CM_11605]、[SWS_CM_11610]、[SWS_CM_11602]。

错误场景

该类的方法通过错误码、异常和访问限制来确保其功能正常：

  • 通信故障（ComErrc::kCommunicationFailure）： 在传输错误或安全通信发生故障时由网络绑定报告。在Get()中会应用回滚语义（[SWS_CM_00112]）。在Set()中则不存在回滚语义，因为如果发生通信超时，服务器端的远程状态可能仍处于不确定状态（[SWS_CM_00113]）。
  • 违反最小发送间隔（ComErrc::kMinimumSendIntervalViolationError）： 当传输请求的触发频率高于配置的最小发送间隔（minimumSendInterval）所允许的频率时，会在 Get()（[SWS_CM_00112]）和 Set()（[SWS_CM_00113]）中发生。
  • 缓冲区限制（ComErrc::kMaxSampleCountNotRealizable 和 ComErrc::kMaxSamplesExceeded）： 当系统无法提供所请求的样本数量（[SWS_CM_11601]）时，Subscribe() 失败。当超过最大样本数量（[SWS_CM_11610]）时，GetNewSamples() 报告错误。
  • 安全违规（InsufficientPermissionsViolation）： 当客户端没有足够的权限执行 Get()（[SWS_CM_00112]）、Set()（[SWS_CM_00113]）或 Subscribe()（[SWS_CM_11601]）时，由 Grant Enforcement 触发。
  • 无效回调处理程序（InvalidHandlerViolation）： 如果在通过 SetReceiveHandler()（[SWS_CM_11605]、[SWS_CM_11611]）、SetSubscriptionStateChangeHandler()（[SWS_CM_11607]、[SWS_CM_11608]）或 SetTransportFaultConditionHandler()（[SWS_CM_00109]、[SWS_CM_00110]）进行注册时传递了空的或无效的 Callable，则会抛出此异常。
