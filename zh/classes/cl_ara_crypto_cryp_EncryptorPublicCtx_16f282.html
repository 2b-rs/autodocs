该接口用于在 AUTOSAR Adaptive Platform 上非对称加密明文数据，并通过提供的智能指针进行管理 [SWS_CRYPT_50174]。在分配了匹配的公钥后，消息既可以在单个处理流程中紧凑转换，也可以通过多分部流式会话连续转换 [SWS_CRYPT_50090]。为了正确执行，必须预先计算缓冲区大小，其中上下文的所有操作均被指定为异常安全和线程安全。

上下文

C++ 类 ara::crypto::cryp::EncryptorPublicCtx 为 AUTOSAR Adaptive Platform 中的非对称数据加密提供了标准化接口。它供客户端应用程序使用非对称公钥加密明文数据。加密密钥的配置既可以直接通过密钥对象（[SWS_CRYPT_50175]）进行，也可以通过对密钥存储位置的引用（KeySlot、[SWS_CRYPT_50086]）进行。数据传递通过高效利用内存的缓冲区区域进行（ReadOnlyMemRegion 用于明文数据，ReadWriteMemRegion 用于密文输出）。

生命周期

上下文的实例通过类型别名 Sptr 中定义的共享指针 std::shared_ptr<EncryptorPublicCtx> 进行管理（[SWS_CRYPT_50174]）。创建本身不属于此接口定义的一部分；推测通过加密架构的上层工厂组件进行实例化。该对象在其生命周期内经历明确定义的状态：

  • 未初始化：实例化后，上下文尚未拥有密钥。在此状态下不允许执行数据处理操作。
  • 已配置（就绪）：通过使用 PublicKey（[SWS_CRYPT_50175]）或 KeySlot（[SWS_CRYPT_50086]）调用 SetKey()，上下文进入就绪状态。在此状态下，既可以执行单步加密，也可以启动流式会话。
  • 流式处理活动：调用 Start()（[SWS_CRYPT_50087]）将上下文置于流式状态。连续的数据块通过 Update()（[SWS_CRYPT_50176]）进行处理。会话要么通过 Finish()（[SWS_CRYPT_50088]）完成，要么通过 Cancel()（[SWS_CRYPT_50089]）中止，从而使上下文返回到已配置状态。

该类的所有方法均被指定为异常安全（exception safe）和线程安全（thread-safe）。如果在流式操作尚未结束时销毁上下文，则底层实现可能会清理分配的缓冲区并隐式丢弃该会话。

状态图：上下文从配置到转换的生命周期和状态转换。来源：[SWS_CRYPT_50086]、[SWS_CRYPT_50175]、[SWS_CRYPT_50087]、[SWS_CRYPT_50176]、[SWS_CRYPT_50088]、[SWS_CRYPT_50089]、[SWS_CRYPT_50090]

使用路径

该类支持两种处理模式：用于完整数据集的单步处理和用于分段数据流的多步流式处理。在执行加密之前，应用程序必须考虑缓冲区限制：

  • 通过 GetMinimumChunkSize()` (<a class="spec-record-ref" data-req="SWS_CRYPT_50178">[SWS_CRYPT_50178]</a>) und <code>GetMaximumChunkSize()（[SWS_CRYPT_50091]）可以确定单次调用所支持的最小和最大输入大小。
  • 必须预先使用 GetRequiredOutputBufferSize()（[SWS_CRYPT_50177]）查询输出缓冲区所需的容量。参数 isFinal 在此控制计算是针对中间步骤（false）还是针对最终调用或单步操作（true）进行。

流式加密的典型流程分为以下步骤：

  1. 使用有效的 PublicKey（[SWS_CRYPT_50175]）通过 SetKey() 分配密钥。
  2. 通过调用 Start()（[SWS_CRYPT_50087]）初始化流式会话。
  3. 使用 GetRequiredOutputBufferSize(inputSize, false)（[SWS_CRYPT_50177]）计算中间块所需的输出缓冲区大小。
  4. 通过 Update()（[SWS_CRYPT_50176]）重复转换数据块。
  5. 确定最后一个块的缓冲区大小（isFinal = true），并通过 Finish()（[SWS_CRYPT_50088]）完成操作。

对于可以在单次处理中完成的紧凑数据，Encrypt()（[SWS_CRYPT_50090]）提供直接的单步调用，而无需划分为启动、更新和完成阶段。

时序图：包含缓冲区大小确定的多分部流式加密的典型流程。来源：[SWS_CRYPT_50175]、[SWS_CRYPT_50087]、[SWS_CRYPT_50177]、[SWS_CRYPT_50176]、[SWS_CRYPT_50088]

错误场景

所有方法均使用 ara::core::Result 进行错误指示，并在发生错误时保证回滚语义：

  • 状态错误：在未初始化的上下文上调用 Start()、Encrypt() 或 GetRequiredOutputBufferSize() 会导致 ara::crypto::CryptoErrc::kUninitializedContext（[SWS_CRYPT_50087]、[SWS_CRYPT_50090]、[SWS_CRYPT_50177]）。如果在未预先执行 Start() 的情况下调用 Update()、Finish() 或 Cancel()，则操作失败并返回 ara::crypto::CryptoErrc::kProcessingNotStarted（[SWS_CRYPT_50176]、[SWS_CRYPT_50088]、[SWS_CRYPT_50089]）。
  • 密钥和使用错误：如果提供的密钥或 KeySlot 与上下文不兼容，则会报告 ara::crypto::CryptoErrc::kIncompatibleObject（[SWS_CRYPT_50175]、[SWS_CRYPT_50086]、[SWS_CRYPT_50087]、[SWS_CRYPT_50090]）。如果允许的密钥使用规则不包含权限 kAllowDataEncryption，则会导致 ara::crypto::CryptoErrc::kUsageViolation（[SWS_CRYPT_50175]、[SWS_CRYPT_50087]、[SWS_CRYPT_50090]）。如果引用的 KeySlot 为空，则会报告 ara::crypto::CryptoErrc::kEmptyKeySlot（[SWS_CRYPT_50087]、[SWS_CRYPT_50090]）。
  • 缓冲区和数据错误：如果传入的输出缓冲区过小，Encrypt()、Update() 和 Finish() 将响应 ara::crypto::CryptoErrc::kInsufficientCapacity（[SWS_CRYPT_50090]、[SWS_CRYPT_50176]、[SWS_CRYPT_50088]）。与允许的分块大小的偏差会导致 ara::crypto::CryptoErrc::kInvalidInputSize，无效的输入数据会导致 ara::crypto::CryptoErrc::kInvalidArgument。
  • 不支持的功能和资源瓶颈：如果实现不支持流式处理或不支持单步调用，则操作失败并返回 ara::crypto::CryptoErrc::kUnsupported（[SWS_CRYPT_50087]、[SWS_CRYPT_50090]、[SWS_CRYPT_50176]、[SWS_CRYPT_50088]）。当加密资源被占用时，将返回 ara::crypto::CryptoErrc::kBusyResource（[SWS_CRYPT_50087]、[SWS_CRYPT_50090]）。

方法 Cancel() 中止上下文 ara::crypto::cryp::EncryptorPublicCtx 中活动的流式操作，该操作先前通过 Start() 启动且尚未结束 [SWS_CRYPT_50089]。它不接受任何传入参数，并返回一个在成功情况下为空的 ara::core::Result<void> [SWS_CRYPT_50089]。由于该签名直接提供 Result 而非 Future，因此中止可能是同步执行的。

错误处理与并发

如果数据处理未事先通过 Start() 启动，则该操作在遵循回滚语义的情况下失败，并带有错误代码 ara::crypto::CryptoErrc::kProcessingNotStarted [SWS_CRYPT_50089]。根据规范，该接口声明为 noexcept，具有异常安全性（exception safe），且针对并发访问被归类为线程安全（thread-safe）[SWS_CRYPT_50089]。

加密栈中的相互作用

通过 Cancel() 实现的中止行为遵循加密模块中有状态流式操作的统一设计模式。具有相同错误语义的类似接口存在于：

  • SignerPrivateCtx [SWS_CRYPT_50041] 和 VerifierPublicCtx [SWS_CRYPT_50023] 中的签名与验证操作，
  • SymmetricCipherCtx [SWS_CRYPT_50046] 以及 AuthCipherCtx [SWS_CRYPT_50077] 中的对称与经过身份验证的加密，
  • DecryptorPrivateCtx [SWS_CRYPT_50069] 中的非对称解密，
  • MessageAuthnCodeCtx [SWS_CRYPT_50027] 中的消息认证码以及 HashFunctionCtx [SWS_CRYPT_50058] 中的哈希计算。

          使用
