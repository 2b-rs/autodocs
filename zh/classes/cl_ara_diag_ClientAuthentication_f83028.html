供应用程序向 Diagnostic Server 报告认证状态和活动用户角色。

该接口允许应用程序向 Diagnostic Server 通报诊断客户端的认证状态及活动用户角色 [SWS_DM_01132]。通过诸如 Authenticate 或 OverrideDefaultRoles 的调用来控制状态转换，并提供用于管理动态访问列表的句柄 [SWS_DM_01206]。因超时引起的状态变化可通过通知程序进行异步监控。由于该类非线程安全且不允许复制，因此应用程序内的访问必须同步进行。

上下文

类 ara::diag::ClientAuthentication 用作应用程序的核心接口，以向 Diagnostic Server 实例通知认证状态和当前已认证的用户角色 [SWS_DM_01132]、SWS Diagnostics, 第129页。有三个主要参与方参与此交互：

  • 应用程序 (Application)：执行认证检查——无论是利用 Diagnostic Server 的接口还是通过应用自身的机制——并将用户角色传输给 Diagnostic Server [SWS_DM_01142]。
  • Diagnostic Server / Diagnostic Manager：管理诊断会话，并基于角色和认证状态强制执行对诊断资源的访问权限 [SWS_DM_01206]。
  • 诊断客户端：向电子控制单元发送诊断请求的外部测试仪或 SOVD 客户端 [SWS_DM_01210]、[SWS_DM_01470]。

ClientAuthentication 的实例数量由模型元素 DiagnosticExternalAuthenticationIdentification 确定 SWS Diagnostics, 第129页。如果最终的源地址在编译时未知，该元素允许针对具有固定源地址的客户端或通过地址范围配置认证 SWS Diagnostics, 第129页。解释：运行时根据这些源地址范围将诊断客户端分配给 ClientAuthentication 的具体实例。对于 SOVD 客户端，Diagnostic Server 在通过 ara::diag::SovdAuthorization::ValidateAuthorization 验证授权令牌时直接向应用程序传递一个 ClientAuthentication 对象 [SWS_DM_01470]。

上下文图：认证接口的交互伙伴。来源：[SWS_DM_01132]、[SWS_DM_01202]、[SWS_DM_01470]、SWS Diagnostics, 第129页

生命周期

应用程序通过 ara::diag::ExternalAuthentication::Get 的重载方法 [SWS_DM_01202] 或在 SOVD 令牌验证的上下文中 [SWS_DM_01470] 获取 ClientAuthentication 的实例。该类具有严格的所有权语义：复制构造函数 [SWS_DM_01139] 和复制赋值运算符 [SWS_DM_01140] 已被删除（=delete）。移动操作（移动构造函数 [SWS_DM_01137] 和移动赋值运算符 [SWS_DM_01138]）预定义为默认并声明为 noexcept。析构函数同样为 noexcept [SWS_DM_01136]。所有成员函数以及析构函数均非线程安全（not thread-safe）[SWS_DM_01136]、[SWS_DM_01141]、[SWS_DM_01142]、[SWS_DM_01143]、[SWS_DM_01144]。

认证状态通过枚举类型 DiagnosticAuthState 表示 [SWS_DM_01133]：

  • kDeAuthenticated (0x00)：没有诊断客户端经过认证。系统启动时，客户端默认处于该状态 [SWS_DM_01205]。此时，其属性 isDefault 配置为 TRUE 的角色（DiagnosticAuthRole）被视作默认角色 [SWS_DM_01204]、[SWS_DM_01134]。通过 OverrideDefaultRoles 可以为指定的超时时间临时覆盖这些默认角色 [SWS_DM_01141]、[SWS_DM_01209]。
  • kAuthenticated (0x01)：诊断客户端已通过认证。通过调用 Authenticate 达到此状态，从而激活 Diagnostic Server 中传递的用户角色 [SWS_DM_01142]、[SWS_DM_01206]。

如果在默认会话中客户端在最后一次传输确认（TransmitConfirmation）后未发送进一步的请求并且不活动时间到期 [SWS_DM_01210]，或者发生 S3 超时 [SWS_DM_01144]、[SWS_DM_02077]，将触发从 kAuthenticated 自动转换回 kDeAuthenticated。

状态图：客户端认证的生命周期与状态转换。来源：[SWS_DM_01133]、[SWS_DM_01204]、[SWS_DM_01205]、[SWS_DM_01206]、[SWS_DM_01209]、[SWS_DM_01210]

使用路径

管理客户端认证的常规流程包括以下步骤：

  1. 注册通知程序：应用程序使用 SetNotifier 注册类型为 ClientAuthenticationSetNotifier（std::function<void(DiagnosticAuthState)>）的回调函数 [SWS_DM_01144]、[SWS_DM_02077]。借此，当发生状态转换（例如因不活动或 S3 超时而转换至 kDeAuthenticated）时，应用程序会收到通知 [SWS_DM_01144]。再次调用将覆盖先前设置的通知程序 [SWS_DM_01144]。
  2. 查询状态：通过方法 GetState()，应用程序可以同步查询客户端当前的认证状态 [SWS_DM_01143]。
  3. 报告认证：一旦认证成功完成，应用程序将调用带有要激活的用户角色（ara::core::Vector<DiagnosticAuthRole>）的 Authenticate [SWS_DM_01142]、[SWS_DM_01134]。Diagnostic Server 将状态设置为 kAuthenticated 并返回一个 ClientAuthenticationHandle [SWS_DM_01206]。
  4. 管理访问权限：通过获取的 ClientAuthenticationHandle，应用程序可以为客户端配置动态访问列表（DynamicAccessList）[SWS_DM_01213]、SWS Diagnostics, 第132页。同时，使用该句柄会刷新客户端的不活动时间窗口 SWS Diagnostics, 第133页。

如果客户端处于状态 kDeAuthenticated，则应用程序可以改为调用 OverrideDefaultRoles(defaultRoles, timeout) 来临时激活备用标准角色；成功时该调用同样会返回一个 ClientAuthenticationHandle [SWS_DM_01141]、[SWS_DM_01209]。

时序图：身份验证期间的调用与通知流程。来源：[SWS_DM_01142]、[SWS_DM_01144]、[SWS_DM_01206]、[SWS_DM_01210]

错误场景

方法 Authenticate、OverrideDefaultRoles 和 GetState 将其返回值封装在 ara::core::Result 中返回，并被规范为异常安全（exception safe）以及 noexcept [SWS_DM_01141]、[SWS_DM_01142]、[SWS_DM_01143]。发生错误时将报告以下标准化错误代码：

  • DiagErrc::kServiceNotAvailable：当由于 Diagnostic Manager 的核心功能当前不可用而导致调用无法执行时发生 [SWS_DM_01141]、[SWS_DM_01142]、[SWS_DM_01143]。该错误具有回滚语义（rollback_semantics），因此不会残留未完成的状态更改 [SWS_DM_01141]、[SWS_DM_01142]、[SWS_DM_01143]。

对于 SetNotifier，未定义标准化的错误代码 [SWS_DM_01144]。作为基本前置条件，OverrideDefaultRoles 要求客户端在调用时处于状态 kDeAuthenticated [SWS_DM_01209]。

ara::core::Result< ClientAuthenticationHandle > Authenticate (ara::core::Vector< DiagnosticAuthRole > userRoles) noexcept;

This function is used by the application to report the authenticated state to the Diagnostic Server instance. The authentication could be either done using the Authentication interfaces of the Diagnostic Server instance, or through other means in the application.

使用与调用

应用程序调用函数 ara::diag::ClientAuthentication::Authenticate，以向 Diagnostic Server 实例告知诊断客户端的成功身份验证 [SWS_DM_01142]。这可以在通过 Diagnostic Server 的接口完成身份验证之后进行，也可以通过应用程序专有机制进行 [SWS_DM_01142]。

该函数接收 userRoles（类型为 ara::core::Vector<DiagnosticAuthRole>）作为输入参数。成功调用后，该实例的身份验证状态更改为 kAuthenticated，并且传入的用户角色被牢固采纳 [SWS_DM_01206]。它返回一个 ara::core::Result<ClientAuthenticationHandle> 作为返回值 [SWS_DM_01142]。由于直接提供了一个 Result 对象，因此推测处理在调用上下文中同步进行。

错误处理与并发

该方法声明为 noexcept 并被视为异常安全（exception safe）[SWS_DM_01142]。如果因 Diagnostic Manager 的基本功能在调用时不可用而发生错误，则该操作以回滚语义失败，并在 Result 对象中返回 DiagErrc::kServiceNotAvailable [SWS_DM_01142]。

在并发性方面，该方法明确指定为 not thread-safe [SWS_DM_01142]。因此，在同一个 ClientAuthentication 对象上的并行调用是不允许的，必须由应用程序进行同步。

交互和生命周期

获取的 ClientAuthenticationHandle 使应用程序能够为已验证身份的客户端定义或扩展 DynamicAccessList [SWS_DM_01142]。此外，该调用还会启动或引用客户端的不活动监控：如果在默认会话状态下成功完成身份验证后，在 authenticationTimeout 持续时间内未发生进一步的 UDS 请求，则 Diagnostic Server 实例会自动将客户端重置回 kDeAuthenticated [SWS_DM_01210]。为了防止此超时，应用程序可以通过句柄的方法 Refresh 更新定时器 [SWS_DM_01155]。
