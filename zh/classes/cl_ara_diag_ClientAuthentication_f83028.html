上下文

类 ara::diag::ClientAuthentication [SWS_DM_01132] 代表核心接口，自适应应用程序通过该接口将外部诊断客户端的认证状态以及当前已认证的用户角色通知诊断服务器实例（AUTOSAR_AP_SWS_Diagnostics, 第130页）。该接口的必要性在于，实际的认证检查既可以通过诊断服务器实例本身的机制处理，也可以通过前置的应用逻辑处理 [SWS_DM_01142]。

主要交互对象包括：

  • 自适应应用程序：执行授权检查（例如根据 [SWS_DM_01470] 在 SOVD 上下文中通过令牌验证），并将用户角色报告给服务器。
  • 诊断服务器（Diagnostic Manager）：管理会话状态，控制对诊断资源的访问，并监控不活动时间 [SWS_DM_01210]。
  • 诊断客户端：通过 UDS 或 SOVD 进行通信。ClientAuthentication 的每个实例都通过模型元素 DiagnosticExternalAuthenticationIdentification 分配给诊断客户端的固定源地址或地址范围（AUTOSAR_AP_SWS_Diagnostics, 第129页）。

上下文图：客户端认证中 ara::diag::ClientAuthentication 的交互伙伴。来源：[SWS_DM_01132]、[SWS_DM_01202]、AUTOSAR_AP_SWS_Diagnostics, 第129页。

生命周期

ClientAuthentication 的实例不能由应用程序的构造函数直接随意实例化。相反，应用程序会调用重载的工厂方法 ara::diag::ExternalAuthentication::Get 之一，随后 Diagnostic Manager 返回相应的实例 [SWS_DM_01202]。或者，在授权验证过程中将实例传递给应用程序 [SWS_DM_01470]。系统中实例的总数由模型中配置的 DiagnosticExternalAuthenticationIdentification 元素决定（AUTOSAR_AP_SWS_Diagnostics, 第129页）。

在所有权方面，该对象被设计为仅支持移动（Move-only）：复制构造函数 [SWS_DM_01139] 和复制赋值运算符 [SWS_DM_01140] 被显式删除（delete）。但是，可以通过移动构造函数 [SWS_DM_01137] 和移动赋值 [SWS_DM_01138] 高效传递实例。析构函数声明为 noexcept [SWS_DM_01136]。该类被指定为非线程安全；对同一实例的并发调用需要外部同步。

认证的逻辑生命周期基于枚举 DiagnosticAuthState [SWS_DM_01133]：

  • kDeAuthenticated: 系统启动后的初始状态[SWS_DM_01205]。DEM 客户端仅被分配了在诊断提取中定义为 Default 的角色（属性isDefault = TRUE）[SWS_DM_01204]。在此状态下，可以通过OverrideDefaultRoles对标准角色进行临时修改[SWS_DM_01209]。
  • kAuthenticated：一旦应用程序成功调用 Authenticate 即可进入该状态 [SWS_DM_01206]。此时，显式传递的用户角色将被分配给客户端。
  • 回退到 kDeAuthenticated：若客户端处于标准诊断会话中，且在最后一次传输确认后未收到进一步的请求，则诊断服务器会因不活动而将状态重置为 kDeAuthenticated [SWS_DM_01210]（例如由于 S3 超时 [SWS_DM_01144]）。

使用路径

ClientAuthentication 的典型用法遵循由实例获取、回调注册、角色设置以及可选的运行时扩展组成的有序序列：

  1. Instanz beschaffen: 应用程序使用期望的源地址调用 ara::diag::ExternalAuthentication::Get，以获取对应的 ClientAuthentication 对象 [SWS_DM_01202]。
  2. Zustandsbeobachter registrieren: 应用程序通过 SetNotifier [SWS_DM_01144] 注册 ClientAuthenticationSetNotifier [SWS_DM_02077] 类型的函数回调。该回调在状态发生变化时由 Diagnostic Server 实例调用——尤其是在自动回退到状态 kDeAuthenticated 时。再次调用会覆盖先前注册的 Notifier [SWS_DM_01144]。
  3. Zustand abfragen: 应用程序可以使用 GetState [SWS_DM_01143] 随时同步检查客户端当前是处于未认证还是已认证状态。
  4. Rollen zuweisen: 一旦客户端身份得到验证，应用程序便通过 Authenticate [SWS_DM_01142] 将要启用的角色作为 DiagnosticAuthRole [SWS_DM_01134] 向量上报。Diagnostic Server 实例切换至状态 kAuthenticated [SWS_DM_01206]。
  5. 接收并继续使用句柄：成功完成时，Authenticate 返回一个 ClientAuthenticationHandle [SWS_DM_01142], [SWS_DM_01206]。通过此句柄，应用程序可以通过 DynamicAccessList 定义进一步的访问列表 [SWS_DM_01213] (AUTOSAR_AP_SWS_Diagnostics, 第132页)。此外，创建句柄会导致不活动时间跨度刷新 (AUTOSAR_AP_SWS_Diagnostics, 第133页)。

时序图：用于认证和状态监控的典型调用序列。来源：[SWS_DM_01142], [SWS_DM_01144], [SWS_DM_01202], [SWS_DM_01206], [SWS_DM_01210]。

<h4>生命周期</h4>
<p><code>ClientAuthentication</code> 的实例不能由应用程序的构造函数直接随意实例化。相反，应用程序会调用重载的工厂方法 <code>ara::diag::ExternalAuthentication::Get</code> 之一，随后 Diagnostic Manager 返回相应的实例 <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a>。或者，在授权验证过程中将实例传递给应用程序 <a class="spec-record-ref" data-req="SWS_DM_01470" href="../spec/record.html?id=SWS_DM_01470">[SWS_DM_01470]</a>。系统中实例的总数由模型中配置的 <code>DiagnosticExternalAuthenticationIdentification</code> 元素决定（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=129">AUTOSAR_AP_SWS_Diagnostics, 第129页</a>）。</p>
<p>在所有权方面，该对象被设计为仅支持移动（Move-only）：复制构造函数 <a class="spec-record-ref" data-req="SWS_DM_01139" href="../spec/record.html?id=SWS_DM_01139">[SWS_DM_01139]</a> 和复制赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_01140" href="../spec/record.html?id=SWS_DM_01140">[SWS_DM_01140]</a> 被显式删除（<code>delete</code>）。但是，可以通过移动构造函数 <a class="spec-record-ref" data-req="SWS_DM_01137" href="../spec/record.html?id=SWS_DM_01137">[SWS_DM_01137]</a> 和移动赋值 <a class="spec-record-ref" data-req="SWS_DM_01138" href="../spec/record.html?id=SWS_DM_01138">[SWS_DM_01138]</a> 高效传递实例。析构函数声明为 <code>noexcept</code> <a class="spec-record-ref" data-req="SWS_DM_01136" href="../spec/record.html?id=SWS_DM_01136">[SWS_DM_01136]</a>。该类被指定为非线程安全；对同一实例的并发调用需要外部同步。</p>
<p>认证的逻辑生命周期基于枚举 <code>DiagnosticAuthState</code> <a class="spec-record-ref" data-req="SWS_DM_01133" href="../spec/record.html?id=SWS_DM_01133">[SWS_DM_01133]</a>：</p>
<ul>
<li><strong><code>kDeAuthenticated</code>:</strong> 系统启动后的初始状态<a class="spec-record-ref" data-req="SWS_DM_01205" href="../spec/record.html?id=SWS_DM_01205">[SWS_DM_01205]</a>。DEM 客户端仅被分配了在诊断提取中定义为 Default 的角色（属性<code>isDefault = TRUE</code>）<a class="spec-record-ref" data-req="SWS_DM_01204" href="../spec/record.html?id=SWS_DM_01204">[SWS_DM_01204]</a>。在此状态下，可以通过<code>OverrideDefaultRoles</code>对标准角色进行临时修改<a class="spec-record-ref" data-req="SWS_DM_01209" href="../spec/record.html?id=SWS_DM_01209">[SWS_DM_01209]</a>。</li>
<li><strong><code>kAuthenticated</code>：</strong>一旦应用程序成功调用 <code>Authenticate</code> 即可进入该状态 <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>。此时，显式传递的用户角色将被分配给客户端。</li>
<li><strong>回退到 <code>kDeAuthenticated</code>：</strong>若客户端处于标准诊断会话中，且在最后一次传输确认后未收到进一步的请求，则诊断服务器会因不活动而将状态重置为 <code>kDeAuthenticated</code> <a class="spec-record-ref" data-req="SWS_DM_01210" href="../spec/record.html?id=SWS_DM_01210">[SWS_DM_01210]</a>（例如由于 S3 超时 <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>）。</li>
</ul>

<h4>使用路径</h4>
<p><code>ClientAuthentication</code> 的典型用法遵循由实例获取、回调注册、角色设置以及可选的运行时扩展组成的有序序列：</p>
<ol>
<li><strong>Instanz beschaffen:</strong> 应用程序使用期望的源地址调用 <code>ara::diag::ExternalAuthentication::Get</code>，以获取对应的 <code>ClientAuthentication</code> 对象 <a class="spec-record-ref" data-req="SWS_DM_01202" href="../spec/record.html?id=SWS_DM_01202">[SWS_DM_01202]</a>。</li>
<li><strong>Zustandsbeobachter registrieren:</strong> 应用程序通过 <code>SetNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a> 注册 <code>ClientAuthenticationSetNotifier</code> <a class="spec-record-ref" data-req="SWS_DM_02077" href="../spec/record.html?id=SWS_DM_02077">[SWS_DM_02077]</a> 类型的函数回调。该回调在状态发生变化时由 Diagnostic Server 实例调用——尤其是在自动回退到状态 <code>kDeAuthenticated</code> 时。再次调用会覆盖先前注册的 Notifier <a class="spec-record-ref" data-req="SWS_DM_01144" href="../spec/record.html?id=SWS_DM_01144">[SWS_DM_01144]</a>。</li>
<li><strong>Zustand abfragen:</strong> 应用程序可以使用 <code>GetState</code> <a class="spec-record-ref" data-req="SWS_DM_01143" href="../spec/record.html?id=SWS_DM_01143">[SWS_DM_01143]</a> 随时同步检查客户端当前是处于未认证还是已认证状态。</li>
<li><strong>Rollen zuweisen:</strong> 一旦客户端身份得到验证，应用程序便通过 <code>Authenticate</code> <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a> 将要启用的角色作为 <code>DiagnosticAuthRole</code> <a class="spec-record-ref" data-req="SWS_DM_01134" href="../spec/record.html?id=SWS_DM_01134">[SWS_DM_01134]</a> 向量上报。Diagnostic Server 实例切换至状态 <code>kAuthenticated</code> <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>。</li>
<li><strong>接收并继续使用句柄：</strong>成功完成时，<code>Authenticate</code> 返回一个 <code>ClientAuthenticationHandle</code> <a class="spec-record-ref" data-req="SWS_DM_01142" href="../spec/record.html?id=SWS_DM_01142">[SWS_DM_01142]</a>, <a class="spec-record-ref" data-req="SWS_DM_01206" href="../spec/record.html?id=SWS_DM_01206">[SWS_DM_01206]</a>。通过此句柄，应用程序可以通过 <code>DynamicAccessList</code> 定义进一步的访问列表 <a class="spec-record-ref" data-req="SWS_DM_01213" href="../spec/record.html?id=SWS_DM_01213">[SWS_DM_01213]</a> (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=132">AUTOSAR_AP_SWS_Diagnostics, 第132页</a>)。此外，创建句柄会导致不活动时间跨度刷新 (<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=133">AUTOSAR_AP_SWS_Diagnostics, 第133页</a>)。</li>
</ol>
