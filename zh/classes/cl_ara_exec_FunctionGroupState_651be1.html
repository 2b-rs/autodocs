类 ara::exec::FunctionGroupState

[SWS_EM_02269] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150, RS_AP_00129

class FunctionGroupState final {...};

Class representing Function Group State defined in meta-model (ARXML). An instance of this class will represent Function Group State defined inside meta-model (ARXML). This class is intended to be an implementation specific representation, of information inside meta-model. Once created based on ARXML path, its internal value stays bounded to it for entire lifetime of a object.

上下文

在 AUTOSAR Adaptive Platform 中，ara::exec::FunctionGroupState 类表示在元模型（ARXML）中定义的功能组状态（Function Group State）。它在运行时用作 ARXML 元模型中所建模状态信息的特定于实现的表示。该类的每个实例都绑定到一个具体的功能组（FunctionGroup），并通过相应元模型声明（ModeDeclaration）的短名称（Short Name）来标识该状态 [SWS_EM_02324]。作为 final 类（final），它不适用于继承体系。通过与 ARXML 路径的直接绑定，它构成了基于模型的配置与 Execution Management 运行时机制之间的类型化桥梁。

上下文图：FunctionGroupState 在功能组与元模型之间的集成。来源：[SWS_EM_02324]

生命周期

FunctionGroupState 实例的生命周期始于通过参数化构造函数进行创建，创建时需传入对所属功能组的引用以及用于状态标识符的 ara::core::StringView [SWS_EM_02324]。根据规范，对象在初始化后的内部值在整个生命周期内保持不可变，并绑定到底层的 ARXML 路径。该类具有完整的值语义，并支持实例的复制和移动：

  • 通过复制构造函数 [SWS_EM_02325] 和复制赋值运算符 [SWS_EM_02330] 可以复制实例，其中赋值操作返回对目标对象的引用。
  • 通过移动构造函数 [SWS_EM_02331] 和移动赋值运算符 [SWS_EM_02332] 可以高效地将资源转移到新的或现有的实例。

一旦离开作用域，对象的销毁就会通过析构函数 [SWS_EM_02272] 确定性地发生。

在并发性和线程安全方面，该类有着细致的规范：参数化构造函数被显式标明为线程安全 [SWS_EM_02324]。同样，用于读取访问的比较运算符也被定义为线程安全（[SWS_EM_02273]、[SWS_EM_02274]）。相比之下，复制构造函数 [SWS_EM_02325]、移动构造函数 [SWS_EM_02331]、赋值运算符（[SWS_EM_02330]、[SWS_EM_02332]）以及析构函数 [SWS_EM_02272] 不是线程安全的。因此，针对同一实例的修改性生命周期操作需要外部同步。

使用路径

典型的使用路径包括实例化、作为状态值传递以及随后的逻辑比较：

  1. 创建：应用程序通过指定现有的 FunctionGroup 以及目标 ModeDeclaration 的短名称来实例化 FunctionGroupState 的对象 [SWS_EM_02324]。
  2. 传递与存储：由于该实例不可变地表示目标状态，因此可以通过复制或移动将其传递给其他功能模块，或存储在数据结构中（[SWS_EM_02325]、[SWS_EM_02331]、[SWS_EM_02330]、[SWS_EM_02332]）。
  3. 状态值检查：应用程序通过相等和不等运算符比较实例。当且仅当两个 FunctionGroupState 实例表示完全相同的元模型元素时，运算符 operator== 返回 true，否则返回 false [SWS_EM_02273]。作为补充，当且仅当映射同一元模型实体时 operator!= 返回 false，而不相等时返回 true [SWS_EM_02274]。
  4. 释放：离开作用域时，所有绑定的资源都会由析构函数自动清理 [SWS_EM_02272]。

错误场景

ara::exec::FunctionGroupState 的接口设计旨在实现最大的稳健性与无异常执行：

  • 异常安全与 noexcept：所有成员函数——包括参数化构造函数 [SWS_EM_02324]、复制和移动操作（[SWS_EM_02325]、[SWS_EM_02331]、[SWS_EM_02330]、[SWS_EM_02332]）、比较运算符（[SWS_EM_02273]、[SWS_EM_02274]）以及析构函数 [SWS_EM_02272]——均声明为 noexcept 且被指定为异常安全（exception safe）。因此，该类在任何情况下都不会抛出 C++ 异常。
  • 前置条件与错误代码：成员函数不返回错误代码（例如通过 ara::core::Result）。无错使用的重要前置条件是，传给构造函数的短名称确实对应于 ARXML 元模型中所指定功能组定义的 ModeDeclaration [SWS_EM_02324]。解读：由于构造函数既不抛出异常也不返回错误代码，元模型标识符的有效性应被假定为对调用方的严格前置条件；无效标识符可能会导致该实例无法与任何有效的模型元素相关联，从而使通过 operator== 进行的比较失败。

<h4>上下文</h4>
<p>在 AUTOSAR Adaptive Platform 中，<code>ara::exec::FunctionGroupState</code> 类表示在元模型（ARXML）中定义的功能组状态（Function Group State）。它在运行时用作 ARXML 元模型中所建模状态信息的特定于实现的表示。该类的每个实例都绑定到一个具体的功能组（<code>FunctionGroup</code>），并通过相应元模型声明（<code>ModeDeclaration</code>）的短名称（Short Name）来标识该状态 <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>。作为 final 类（<code>final</code>），它不适用于继承体系。通过与 ARXML 路径的直接绑定，它构成了基于模型的配置与 Execution Management 运行时机制之间的类型化桥梁。</p>

<h4>生命周期</h4>
<p><code>FunctionGroupState</code> 实例的生命周期始于通过参数化构造函数进行创建，创建时需传入对所属功能组的引用以及用于状态标识符的 <code>ara::core::StringView</code> <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>。根据规范，对象在初始化后的内部值在整个生命周期内保持不可变，并绑定到底层的 ARXML 路径。该类具有完整的值语义，并支持实例的复制和移动：</p>
<ul>
<li>通过复制构造函数 <a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a> 和复制赋值运算符 <a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a> 可以复制实例，其中赋值操作返回对目标对象的引用。</li>
<li>通过移动构造函数 <a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a> 可以高效地将资源转移到新的或现有的实例。</li>
</ul>
<p>一旦离开作用域，对象的销毁就会通过析构函数 <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a> 确定性地发生。</p>
<p>在并发性和线程安全方面，该类有着细致的规范：参数化构造函数被显式标明为线程安全 <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>。同样，用于读取访问的比较运算符也被定义为线程安全（<a class="spec-record-ref" data-req="SWS_EM_02273" href="../spec/record.html?id=SWS_EM_02273">[SWS_EM_02273]</a>、<a class="spec-record-ref" data-req="SWS_EM_02274" href="../spec/record.html?id=SWS_EM_02274">[SWS_EM_02274]</a>）。相比之下，复制构造函数 <a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a>、移动构造函数 <a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a>、赋值运算符（<a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a>、<a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a>）以及析构函数 <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a> 不是线程安全的。因此，针对同一实例的修改性生命周期操作需要外部同步。</p>

<h4>使用路径</h4>
<p>典型的使用路径包括实例化、作为状态值传递以及随后的逻辑比较：</p>
<ol>
<li><strong>创建：</strong>应用程序通过指定现有的 <code>FunctionGroup</code> 以及目标 <code>ModeDeclaration</code> 的短名称来实例化 <code>FunctionGroupState</code> 的对象 <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>。</li>
<li><strong>传递与存储：</strong>由于该实例不可变地表示目标状态，因此可以通过复制或移动将其传递给其他功能模块，或存储在数据结构中（<a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a>、<a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a>、<a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a>、<a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a>）。</li>
<li><strong>状态值检查：</strong>应用程序通过相等和不等运算符比较实例。当且仅当两个 <code>FunctionGroupState</code> 实例表示完全相同的元模型元素时，运算符 <code>operator==</code> 返回 <code>true</code>，否则返回 <code>false</code> <a class="spec-record-ref" data-req="SWS_EM_02273" href="../spec/record.html?id=SWS_EM_02273">[SWS_EM_02273]</a>。作为补充，当且仅当映射同一元模型实体时 <code>operator!=</code> 返回 <code>false</code>，而不相等时返回 <code>true</code> <a class="spec-record-ref" data-req="SWS_EM_02274" href="../spec/record.html?id=SWS_EM_02274">[SWS_EM_02274]</a>。</li>
<li><strong>释放：</strong>离开作用域时，所有绑定的资源都会由析构函数自动清理 <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a>。</li>
</ol>

<h4>错误场景</h4>
<p><code>ara::exec::FunctionGroupState</code> 的接口设计旨在实现最大的稳健性与无异常执行：</p>
<ul>
<li><strong>异常安全与 noexcept：</strong>所有成员函数——包括参数化构造函数 <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>、复制和移动操作（<a class="spec-record-ref" data-req="SWS_EM_02325" href="../spec/record.html?id=SWS_EM_02325">[SWS_EM_02325]</a>、<a class="spec-record-ref" data-req="SWS_EM_02331" href="../spec/record.html?id=SWS_EM_02331">[SWS_EM_02331]</a>、<a class="spec-record-ref" data-req="SWS_EM_02330" href="../spec/record.html?id=SWS_EM_02330">[SWS_EM_02330]</a>、<a class="spec-record-ref" data-req="SWS_EM_02332" href="../spec/record.html?id=SWS_EM_02332">[SWS_EM_02332]</a>）、比较运算符（<a class="spec-record-ref" data-req="SWS_EM_02273" href="../spec/record.html?id=SWS_EM_02273">[SWS_EM_02273]</a>、<a class="spec-record-ref" data-req="SWS_EM_02274" href="../spec/record.html?id=SWS_EM_02274">[SWS_EM_02274]</a>）以及析构函数 <a class="spec-record-ref" data-req="SWS_EM_02272" href="../spec/record.html?id=SWS_EM_02272">[SWS_EM_02272]</a>——均声明为 <code>noexcept</code> 且被指定为异常安全（exception safe）。因此，该类在任何情况下都不会抛出 C++ 异常。</li>
<li><strong>前置条件与错误代码：</strong>成员函数不返回错误代码（例如通过 <code>ara::core::Result</code>）。无错使用的重要前置条件是，传给构造函数的短名称确实对应于 ARXML 元模型中所指定功能组定义的 <code>ModeDeclaration</code> <a class="spec-record-ref" data-req="SWS_EM_02324" href="../spec/record.html?id=SWS_EM_02324">[SWS_EM_02324]</a>。解读：由于构造函数既不抛出异常也不返回错误代码，元模型标识符的有效性应被假定为对调用方的严格前置条件；无效标识符可能会导致该实例无法与任何有效的模型元素相关联，从而使通过 <code>operator==</code> 进行的比较失败。</li>
</ul>
