上下文

ara::exec::ExecutionClient 类用于 AUTOSAR Adaptive Platform 内的进程向 Execution Management 报告其内部执行状态（Execution State）[SWS_EM_02003]。此外，该实例还负责处理操作系统信号 SIGTERM [SWS_EM_02002]。交互伙伴包括应用程序本身、作为接收控制实体的 Execution Management 以及传递终止信号的操作系统。

上下文图：ara::exec::ExecutionClient 的交互伙伴与通信关系。来源：[SWS_EM_02003]、[SWS_EM_02562]、[SWS_EM_02002]

生命周期

对于 ara::exec::ExecutionClient 的实例化，有两种构造方式可供使用：

  • 命名构造函数 Create [SWS_EM_02562] 创建一个 ara::core::Result<ExecutionClient>，被声明为 noexcept，并且是异常安全的（exception safe）和线程安全的（thread-safe）。
  • 常规构造函数 [SWS_EM_02560] 被声明为线程安全，但不是异常安全的（noexcept(false)）。

两个构造函数都要求传入类型为 std::function<void()> 的 terminationHandler 回调 [SWS_EM_02562]、[SWS_EM_02560]。一旦接收到 SIGTERM 信号，该回调就会在后台线程中执行。在 ExecutionClient 实例的整个生命周期内，terminationHandler 必须保持可调用状态 [SWS_EM_02562]、[SWS_EM_02560]。

在所有权方面，该类禁止复制：复制构造函数 [SWS_EM_02563] 和复制赋值运算符 [SWS_EM_02564] 均被显式删除（=delete）。所有权的转移仅能通过移动语义实现：移动构造函数 [SWS_EM_02580] 和移动赋值运算符 [SWS_EM_02581] 均存在，被指定为 noexcept 且异常安全，但不是线程安全的。

通过析构函数 [SWS_EM_02002]（同样为 noexcept 且非线程安全）进行销毁时，SIGTERM 处理程序会被重置为其原始状态。

使用路径

典型的使用流程包括以下步骤：

  1. 创建：应用程序通过 Create 初始化客户端，并指定用于受控终止的回调 [SWS_EM_02562]。
  2. 状态报告：内部初始化完成后，进程通过 ReportExecutionState 向 Execution Management 报告其状态 [SWS_EM_02003]。该方法是线程安全和异常安全的。
  3. 信号处理：若在执行期间收到 SIGTERM 信号，ExecutionClient 会在独立的后台线程中调用所注册的 terminationHandler，以便例如设置全局标志并唤醒被阻塞的线程 [SWS_EM_02562]。
  4. 销毁：在离开生命周期时，析构函数会恢复原始的信号处理程序 [SWS_EM_02002]。

时序图：应用程序、ExecutionClient 与 Execution Management 之间的调用和信号流程。来源：[SWS_EM_02562]、[SWS_EM_02003]、[SWS_EM_02002]

错误场景

ExecutionClient 的方法通过返回类型 ara::core::Result 或领域 ara::exec::ExecErrc 的相应错误代码来指示错误状态：

错误代码 受影响的操作 含义与恢复
ara::exec::ExecErrc::kInvalidArgument Create [SWS_EM_02562]，构造函数 [SWS_EM_02560] 传入的 terminationHandler 不包含可调用的函数。回滚语义。恢复：使用有效回调重试调用。
ara::exec::ExecErrc::kNoCommunication Create [SWS_EM_02562]，构造函数 [SWS_EM_02560]，ReportExecutionState [SWS_EM_02003] 与 Execution Management 连接时的通信错误，例如缺少报告的接收确认。无回滚语义。恢复：重新执行调用（“try again”）。
ara::exec::ExecErrc::kInvalidTransition ReportExecutionState [SWS_EM_02003] 非法状态转换（例如在进程已处于该状态时报告 kRunning）。回滚语义。恢复：无需重新报告。

<h4>生命周期</h4>
<p>对于 <code>ara::exec::ExecutionClient</code> 的实例化，有两种构造方式可供使用：</p>
<ul>
<li>命名构造函数 <code>Create</code> <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a> 创建一个 <code>ara::core::Result&lt;ExecutionClient&gt;</code>，被声明为 <code>noexcept</code>，并且是异常安全的（exception safe）和线程安全的（thread-safe）。</li>
<li>常规构造函数 <a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a> 被声明为线程安全，但不是异常安全的（<code>noexcept(false)</code>）。</li>
</ul>
<p>两个构造函数都要求传入类型为 <code>std::function&lt;void()&gt;</code> 的 <code>terminationHandler</code> 回调 <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>、<a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a>。一旦接收到 <code>SIGTERM</code> 信号，该回调就会在后台线程中执行。在 <code>ExecutionClient</code> 实例的整个生命周期内，<code>terminationHandler</code> 必须保持可调用状态 <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>、<a class="spec-record-ref" data-req="SWS_EM_02560" href="../spec/record.html?id=SWS_EM_02560">[SWS_EM_02560]</a>。</p>
<p>在所有权方面，该类禁止复制：复制构造函数 <a class="spec-record-ref" data-req="SWS_EM_02563" href="../spec/record.html?id=SWS_EM_02563">[SWS_EM_02563]</a> 和复制赋值运算符 <a class="spec-record-ref" data-req="SWS_EM_02564" href="../spec/record.html?id=SWS_EM_02564">[SWS_EM_02564]</a> 均被显式删除（<code>=delete</code>）。所有权的转移仅能通过移动语义实现：移动构造函数 <a class="spec-record-ref" data-req="SWS_EM_02580" href="../spec/record.html?id=SWS_EM_02580">[SWS_EM_02580]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_EM_02581" href="../spec/record.html?id=SWS_EM_02581">[SWS_EM_02581]</a> 均存在，被指定为 <code>noexcept</code> 且异常安全，但不是线程安全的。</p>
<p>通过析构函数 <a class="spec-record-ref" data-req="SWS_EM_02002" href="../spec/record.html?id=SWS_EM_02002">[SWS_EM_02002]</a>（同样为 <code>noexcept</code> 且非线程安全）进行销毁时，<code>SIGTERM</code> 处理程序会被重置为其原始状态。</p>

<h4>使用路径</h4>
<p>典型的使用流程包括以下步骤：</p>
<ol>
<li><strong>创建：</strong>应用程序通过 <code>Create</code> 初始化客户端，并指定用于受控终止的回调 <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>。</li>
<li><strong>状态报告：</strong>内部初始化完成后，进程通过 <code>ReportExecutionState</code> 向 Execution Management 报告其状态 <a class="spec-record-ref" data-req="SWS_EM_02003" href="../spec/record.html?id=SWS_EM_02003">[SWS_EM_02003]</a>。该方法是线程安全和异常安全的。</li>
<li><strong>信号处理：</strong>若在执行期间收到 <code>SIGTERM</code> 信号，<code>ExecutionClient</code> 会在独立的后台线程中调用所注册的 <code>terminationHandler</code>，以便例如设置全局标志并唤醒被阻塞的线程 <a class="spec-record-ref" data-req="SWS_EM_02562" href="../spec/record.html?id=SWS_EM_02562">[SWS_EM_02562]</a>。</li>
<li><strong>销毁：</strong>在离开生命周期时，析构函数会恢复原始的信号处理程序 <a class="spec-record-ref" data-req="SWS_EM_02002" href="../spec/record.html?id=SWS_EM_02002">[SWS_EM_02002]</a>。</li>
</ol>
