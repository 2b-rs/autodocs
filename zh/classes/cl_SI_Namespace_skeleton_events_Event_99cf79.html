使服务提供者能够在服务器端向订阅应用程序发送事件。

类 <SI-Namespace>::skeleton::events::<Event> 用于 AUTOSAR Adaptive Platform 上的服务提供者向订阅应用程序发布事件数据。事件既可以基于复制发送，也可以通过预先由 Allocate() 分配的缓冲区高效地进行零复制发送（[SWS_CM_90438]）。通过 Send() 的发送调用强制要求此前已成功提供相应的服务实例，并遵守配置的最小发送间隔（[SWS_CM_00162]）。

上下文

类 <SI-Namespace>::skeleton::events::<Event> 表示在 AUTOSAR Adaptive Platform 内发布服务事件的服务器端接口。它允许服务应用程序（Skeleton）将类型为 SampleType（[SWS_CM_11400]）的更新事件数据异步传输至所有订阅的客户端应用程序（[SWS_CM_00162]）。在此过程中，Skeleton 直接与通信层（Communication Management）交互，后者负责查找服务实例并物理分发事件数据。除了发送数据外，Event 实例还监视当前订阅状态，并将订阅者群体的变更告知服务提供者（[SWS_CM_12008]、[SWS_CM_12011]）。

上下文图：Event 类与服务提供者、Communication Management 及订阅者的交互。来源：[SWS_CM_00162]、[SWS_CM_90437]、[SWS_CM_12011]

生命周期

Event 类的实例化与上层 Skeleton 服务实例联合进行。推测 Event 实例的生命周期与 Skeleton 的生命周期紧密绑定，因此事件对象仅在服务构造完成后才可用，并随着服务的销毁而终止。在进行活动数据传输之前必须已经提供该服务，因为在提供服务之前的传输尝试将会失败（[SWS_CM_00162]）。

在运行阶段，该实例反映订阅者连接的状态。可通过 GetSubscriptionState() 查询当前状态（[SWS_CM_12011]）。为了对状态变更做出异步响应，应用程序使用 SetSubscriptionStateChangeHandler() 注册相应的回调（[SWS_CM_12008]），并可选择通过 Executor 对象耦合到特定的执行上下文（[SWS_CM_12009]）。在服务终止或重置方向时，可通过 UnsetSubscriptionStateChangeHandler() 再次注销此处理程序（[SWS_CM_12010]）。所有状态查询和处理程序方法均声明为 noexcept，并确保异常安全性（[SWS_CM_12008]、[SWS_CM_12011]）。

使用路径

服务应用程序有两种基本的传输模式可用于发布 Event 数据：基于复制的传输以及通过托管内存的零复制机制（EXP ara::com API 第10页）。

在常规使用路径中，服务提供者首先在需要时为订阅变更注册回调（[SWS_CM_12008]）。一旦存在订阅者，应用程序要么生成本地数据并将其按值传递给 Send()（[SWS_CM_00162]），此时 Communication Management 会创建数据的副本并转发给所有订阅者（EXP ara::com API 第10页）。

或者，为了避免复制开销，应用程序通过 Allocate() 直接从通信层请求形式为 ara::com::SampleAllocateePtr<SampleType> 的内存缓冲区（[SWS_CM_90438]、EXP ara::com API 第10页）。填充缓冲区后，通过 Send() 的专用重载进行传输（[SWS_CM_90437]）。解读：发送后，该内存的所有权可能会完全转移给 Communication Management，因为明确禁止应用程序在调用后对数据进行任何进一步访问（[SWS_CM_90437]）。

时序图：包括处理程序注册和分配在内的 Event 传输典型流程。来源：[SWS_CM_12008]、[SWS_CM_90438]、[SWS_CM_90437]、[SWS_CM_00162]

错误场景

对 Send() 的调用返回一个 ara::core::Result<void>，在发生错误时包含类型为 ara::com::ComErrc 的相应错误代码（[SWS_CM_00162]、[SWS_CM_90437]）。定义的错误情况包括：

  • ComErrc::kServiceNotOffered：在尝试发送之前，服务尚未通过 OfferService() 提供（[SWS_CM_00162]、[SWS_CM_90437]）。
  • ComErrc::kMinimumSendIntervalViolationError：低于为该事件配置的最小发送间隔（minimumSendInterval），因为发送调用发起的频率过快（[SWS_CM_00162]、[SWS_CM_90437]）。

此外，在分配和处理程序配置时需注意前置条件：

  • Allocate() 不是异常安全的（not exception safe），并且在内存资源不足时会导致 SampleAllocationViolation，或在不当使用自定义分配器时导致 AllocateUsageViolation（[SWS_CM_90438]）。
  • SetSubscriptionStateChangeHandler() 需要一个有效的、可调用的函数对象；如果传递了空值或不存在的处理程序，则会导致 InvalidHandlerViolation（[SWS_CM_12008]、[SWS_CM_12009]）。

函数 Allocate [SWS_CM_90438] Upstream: RS_CM_00201, RS_AP_00114, RS_AP_00115, RS_AP_00120

ara::com::SampleAllocateePtr< SampleType > Allocate ();

Allocating data for event transfer when Communication Management is responsible for the data.

AI-GENERATED unreviewed Model: gemini-3.8-flash-medium · Effort: medium · Temperature: nicht steuerbar · Prompt: fc3608719061 Provenance

当 Communication Management (ara::com) 负责数据管理时 ([SWS_CM_90438])，在 Skeleton 级别为事件调用方法 Allocate ([SWS_CM_90438]; AUTOSAR_AP_EXP_ARAComAPI §5.4.1 “Skeleton Class API’s”)，以分配用于传输事件数据的内存。它返回一个类型为 ara::com::SampleAllocateePtr<SampleType> 的实例 ([SWS_CM_90438])。该指针类型在概念上表现得像一个 std::unique_ptr<T>，因此在任何时间点都只有一个参与方拥有该指针的所有权 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”)。

关于错误处理和异常安全性，Allocate 被指定为 not exception safe ([SWS_CM_90438])。规范定义了两种可能的违例（Violations）：

  • SampleAllocationViolation：没有足够的内存资源来分配数据 ([SWS_CM_90438])。
  • AllocateUsageViolation：通过用户自定义分配器进行了不允许的分配 ([SWS_CM_90438])。

Allocate 背后的概念主要旨在支持零拷贝机制，特别是在基于共享内存的 IPC 传输中，此时假定读取器和写入器之间存在严格同步 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”)。实现者必须注意，如果部署中的数据类型未配置为二进制兼容，或者识别逻辑排除了这一点，则序列化要求可能会破坏零拷贝 (ARAComAPI §6 “Event Allocate/Send sample Binding implementer hint”)。

在与发送事件的交互中，通过 Allocate 获取的内存指针被传递给 Send(ara::com::SampleAllocateePtr<SampleType> data) ([SWS_CM_90437])。在调用 Send 之后，一旦 Communication Management 将数据发送给所有订阅应用程序，服务应用程序便不得再访问该数据 ([SWS_CM_90437])。

              用法与调用上下文
