通过可替换的内存资源管理对象和容器的多态内存分配。

该模板类将自适应应用程序和容器的基于内存资源的动态分配封装为多态分配器的完全无异常实现 [SWS_CORE_06541]。为了灵活控制对象生命周期，实例将所有内存请求委托给可替换的内存资源，其中失败的分配确定性地返回空指针而非 C++ 异常 [SWS_CORE_06547]。作为重要的功能边界条件，常规拷贝赋值被显式禁止，而在运行过程中有缺陷的释放操作始终被静默忽略。

上下文

模板类 ara::core::PolymorphicAllocator 在 AUTOSAR Adaptive 中根据 C++ 标准模式实现了有状态多态内存分配的接口，并定义了底层元素类型 value_type [SWS_CORE_06572]。它充当调用方组件（例如容器或应用程序结构）与具体内存资源之间的适配器。通过方法 resource()，可以随时查询指向所用 MemoryResource 的指针 [SWS_CORE_06557]。通过这种封装，内存请求在语义上与内存管理的具体实现分离。

生命周期

分配器的实例既可以通过默认方式 [SWS_CORE_06541] 构造，也可以使用指向特定 MemoryResource 的指针进行构造 [SWS_CORE_06542]。由于分配器仅引用内存资源，因此其生命周期的责任推测由调用方承担。除了常规拷贝构造函数 [SWS_CORE_06543] 外，转换构造函数还允许从针对其他元素类型的分配器进行初始化 U [SWS_CORE_06544]。

关于所有权转移，常规拷贝赋值运算符已被删除（=delete）[SWS_CORE_06545]。与此相反，AUTOSAR 显式定义了一个移动构造函数 [SWS_CORE_06546] 以及一个标准移动赋值运算符 [SWS_CORE_00066]。在容器的拷贝操作中，方法 select_on_container_copy_construction() 会创建相应的分配器实例 [SWS_CORE_06573]。

在并发性方面，默认构造函数、转换构造函数以及内存资源的查询被规范为线程安全的（[SWS_CORE_06541]、[SWS_CORE_06542]、[SWS_CORE_06544]、[SWS_CORE_06557]）。相比之下，移动操作（[SWS_CORE_06546]）、拷贝选择（[SWS_CORE_06573]）以及所有分配、构造和解分配操作均被声明为非线程安全。

使用路径

常规流程包括内存提供、对象构造以及后续的对象销毁和释放：

  • 内存分配：用于类型为 Tp 的 n 个对象的原始内存使用 allocate() 请求 [SWS_CORE_06547]。或者，allocate_bytes() 可用于按字节且带对齐的分配 [SWS_CORE_06549]，而模板 allocate_object() 则可用于类型化分配 [SWS_CORE_06551]。
  • 对象初始化：方法 construct() 在先前分配的内存区域上创建对象 [SWS_CORE_06555]。作为组合操作，new_object() 在单个调用中提供分配和就地构造 [SWS_CORE_06553]。
  • 销毁与释放：销毁通过 destroy() 进行 [SWS_CORE_06556]，随后通过 deallocate() [SWS_CORE_06548]、deallocate_bytes() [SWS_CORE_06550] 或 deallocate_object() [SWS_CORE_06552] 释放。两者也可以改为使用 delete_object() 结合在一起 [SWS_CORE_06554]。

错误场景

该类在核心错误处理机制上与 ISO C++ 标准不同，以满足无异常系统的严格要求：

  • 分配时不抛出异常：所有分配方法（allocate() [SWS_CORE_06547]、allocate_bytes() [SWS_CORE_06549] 和 allocate_object() [SWS_CORE_06551]）均为 noexcept。如果内存保留失败，将返回 nullptr 而非异常。调用方可能必须在进一步使用之前对该指针进行强制验证。
  • 有条件的异常安全性：构造和析构例程（construct() [SWS_CORE_06555]、destroy() [SWS_CORE_06556]、new_object() [SWS_CORE_06553] 和 delete_object() [SWS_CORE_06554]）是有条件 noexcept 的，取决于相关类型的 std::is_nothrow_constructible 或 std::is_nothrow_destructible。在 new_object() 失败时，同样会返回 nullptr [SWS_CORE_06553]。
  • 解分配时的错误抑制：如果释放操作失败，在 deallocate() [SWS_CORE_06548]、deallocate_bytes() [SWS_CORE_06550]、deallocate_object() [SWS_CORE_06552] 和 delete_object() [SWS_CORE_06554] 中发生的错误将无一例外地被静默忽略。
