在存储模型中的角色

FileStorage 表示一组已配置的、类似目录的命名文件。文件可以预安装、在更新期间创建或在运行时创建和删除。 SWS Persistency §7.4 “File Storage specific Features”

从存储到文件

在OpenFileStorage、FileExists和GetAllFileNames之后检查库存。 OpenFileReadOnly、OpenFileWriteOnly和OpenFileReadWrite创建相应的专有Accessor；内容处理由ReadAccessor、WriteAccessor或ReadWriteAccessor负责。

写入、锁定和重置

打开的 Accessor 会以独占方式绑定文件。因此，不要将 DeleteFile、ResetFile 和 RecoverFile 与活动访问并行计划。资源限制以及冗余和备份数据均计入已占用的 Storage 内存。SWS Persistency §7.2.6 “Resource Management Concepts”

失败策略

检查每个 Result，特别是访问权限、物理存储、完整性、加密、身份验证、磁盘空间和资源争用。修复不能替代技术一致性检查。 SWS Persistency §7.2.4 “Redundancy Concepts”

一个File Storage管理着很多命名文件； Accessor 对特定开放的访问权限具有独占访问权限。来源：SWS Persistency §7.4 “File Storage specific Features”[SWS_PER_00113]。

尽最大努力康复；如果发生错误，报告可以命名受影响的存储或元素。来源：SWS Persistency §7.2.4 “Redundancy Concepts”。 部分解释：活动序列结合了几个允许的冗余过程。

Resets a file of this File Storage to its initial content. ResetFile allows to reset a single file to its initial content. If the file is currently not available in the File Storage, it is re-created. Afterwards, the file will appear in both cases as if it was newly installed from the current Target Configuration. It will fail with kResourceBusy when the file is currently open, and with kInitValueNotAvailable when neither Application Design nor Target Configuration define an initial content for the file.
