类 ara::per::FileStorage 支持通过唯一文件名管理和打开一组配置的持久性文件 [SWS_PER_00110]。实际的读写访问通过基于 UniqueHandle 的访问器进行，该访问器在离开作用域时自动重新关闭文件 [SWS_PER_00114]。由于已打开的文件受到保护以防止并发删除或恢复操作，因此此类并发访问将因 PerErrc::kResourceBusy 失败 [SWS_PER_00111]。

上下文

类 ara::per::FileStorage 封装了对一组通过唯一文件名标识的配置持久性文件的访问。它作为应用程序的核心接口，用于执行诸如通过 GetAllFileNames [SWS_PER_00110] 列出已有文件、使用 FileExists [SWS_PER_00112] 检查是否存在，以及通过 GetFileInfo [SWS_PER_00438] 和 GetCurrentFileSize [SWS_PER_00407] 查询元数据和文件大小等文件操作。字节级的直接读写访问并不在存储实例本身上进行，而是通过打开方法作为 UniqueHandle 提供的专用访问器对象来进行中介 [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00115]。

生命周期

FileStorage 的实例化受到严格限制：默认构造函数 [SWS_PER_00460]、复制和移动构造函数 [SWS_PER_00328] [SWS_PER_00326] 以及复制和移动赋值运算符 [SWS_PER_00329] [SWS_PER_00327] 均已被显式删除。因此，FileStorage 的实例通常应当通过持久性模块的平台侧工厂函数打开并提供。 问题 (未决)析构函数 ~FileStorage 是异常安全的（noexcept），但显式指定为非线程安全 [SWS_PER_00330]，因此必须确保在析构期间不会在该对象上发生并发调用。

在运行过程中，诸如 FileExists、DeleteFile 或打开文件等常规文件操作均设计为线程安全 [SWS_PER_00111] [SWS_PER_00112] [SWS_PER_00114]。但需要注意的是，诸如 GetAllFileNames [SWS_PER_00110] 或 FileExists [SWS_PER_00112] 等状态查询的结果，仅在没有其他线程同时添加或删除文件时才具有精确的有效性。GetFileInfo 也是类似情况：修改时间和访问时间以及处理状态只有在目标文件未打开时才是可靠准确的 [SWS_PER_00438]。

使用路径

典型使用路径包括检查、针对性打开、通过访问器句柄处理数据以及最终清理：

  1. 检查文件状态：在访问之前，可选择通过 FileExists 确定所需文件是否存在 [SWS_PER_00112]，或通过 GetAllFileNames 查询现有文件 [SWS_PER_00110]。
  2. 打开文件：根据预期的访问模式，该类提供了专用方法。对于纯读取访问，提供了 OpenFileReadOnly 重载 [SWS_PER_00114] [SWS_PER_00376] [SWS_PER_00430]。对于读写访问，使用 OpenFileReadWrite [SWS_PER_00113] [SWS_PER_00375] [SWS_PER_00429]，其中不存在的文件会自动新建。对于纯写入，存在 OpenFileWriteOnly [SWS_PER_00115] [SWS_PER_00377] [SWS_PER_00431]，默认截断文件（kTruncate）或新建文件。为了在进行大量小规模访问时提高性能，重载版本允许传递用户定义的缓冲区以进行分块读取或写入 [SWS_PER_00430] [SWS_PER_00429] [SWS_PER_00431]。
  3. 关闭文件并释放资源：打开方法返回的 ara::core::Result 封装了指向相应访问器的 UniqueHandle。一旦该 UniqueHandle 离开其作用域，文件将自动关闭 [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00115]。推测此时也会解除 FileStorage 中与文件相关的占用标记。 问题 (未决)
  4. 维护与清理：不再需要的文件通过 DeleteFile 删除 [SWS_PER_00111]。发生完整性破坏时，RecoverFile 提供冗余数据的尽力恢复 [SWS_PER_00337]，而 ResetFile 将文件重置为其初始部署内容，或在缺失时重新创建 [SWS_PER_00338]。

错误场景

FileStorage 的方法使用错误枚举 PerErrc 通过 ara::core::Result 发出错误信号。最重要的错误情况包括：

  • 资源冲突（PerErrc::kResourceBusy）：当文件已打开，或在相同文件名上并行执行 DeleteFile、RecoverFile 或 ResetFile 时，无法打开、删除、恢复或重置文件 [SWS_PER_00111] [SWS_PER_00114] [SWS_PER_00113] [SWS_PER_00337] [SWS_PER_00338]。
  • 未找到文件（PerErrc::kFileNotFound）：当试图打开不存在的文件进行纯读取 [SWS_PER_00114]、删除 [SWS_PER_00111]、查询 [SWS_PER_00407] [SWS_PER_00438] 或恢复 [SWS_PER_00337] 时发生。
  • 访问与权限违规：如果存储被配置为只读（read-only），则写入打开或删除操作将因 PerErrc::kIllegalWriteAccess 失败 [SWS_PER_00111] [SWS_PER_00113] [SWS_PER_00115]。无效的模式组合将被 PerErrc::kInvalidOpenMode 拒绝 [SWS_PER_00114] [SWS_PER_00113]。
  • 存储限制与配额：在新建或扩大规模时，可能会出现 PerErrc::kOutOfStorageSpace（物理存储已满）、PerErrc::kTooManyFiles（超过 maxNumberOfFiles）或 PerErrc::kQuotaExceeded（超出 maximumAllowedSize）[SWS_PER_00113] [SWS_PER_00337] [SWS_PER_00338]。
  • 完整性与安全错误：物理存储层出现故障时报告 PerErrc::kPhysicalStorageFailure。损坏的数据结构、失败的验证或密码学问题将导致 PerErrc::kIntegrityCorrupted、PerErrc::kValidationFailed、PerErrc::kEncryptionFailed 或 PerErrc::kAuthenticationFailed [SWS_PER_00110] [SWS_PER_00112] [SWS_PER_00114] [SWS_PER_00337]。
  • 缺少初始数据（PerErrc::kInitValueNotAvailable）：通过 ResetFile 重置时，若在 Application Design 和目标配置中均未定义初始值，则失败 [SWS_PER_00338]。

在调用之前，必须结束对目标文件的所有活动访问。如果文件当前处于打开状态，则删除操作失败并返回错误 PerErrc::kResourceBusy [SWS_PER_00111]。因此，应用程序必须确保先前通过 OpenFileReadWrite [SWS_PER_00113]、OpenFileReadOnly [SWS_PER_00114] 或 OpenFileWriteOnly [SWS_PER_00115] 创建的 UniqueHandle 实例已离开其作用域，从而关闭文件。同样，针对相同文件名并行执行 RecoverFile [SWS_PER_00337] 或 ResetFile [SWS_PER_00338] 会导致 PerErrc::kResourceBusy [SWS_PER_00111]。
