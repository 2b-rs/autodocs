上下文

类 ara::core::FutureException 在 AUTOSAR Adaptive Platform 的模块 core 中充当异步操作环境下错误状态的专用异常类型。根据规范，该异常由 ara::core::Future 和 ara::core::Promise 触发，以结构化方式向调用方报告发生的错误条件。在 Adaptive Platform 的整体架构中，该类应在基于错误代码的错误处理与建模的异常机制之间建立起功能桥梁：它派生自基类 Exception，并将具体错误状态封装为 ara::core::ErrorCode 的形式 [SWS_CORE_00412]。

参与异步交互的通常包括通过 ara::core::Promise 的生成上下文、通过 ara::core::Future 的消费上下文以及上层应用程序。如果异步处理失败或查询了无效状态，ara::core::FutureException 将充当信号载体。通过头文件 ara/core/future_error_domain.h 提供，该异常与异步流程的领域特定错误定义 [SWS_CORE_00412] 紧密结合。

生命周期

ara::core::FutureException 实例的生命周期始于通过为其指定的构造函数进行创建，该构造函数接收一个起初始化作用的 ara::core::ErrorCode [SWS_CORE_00412]。声明为 explicit 可防止错误代码意外隐式类型转换为异常对象，并确保创建始终是有意进行的 [SWS_CORE_00412]。构造函数还被声明为 noexcept，从而在对象创建时保证完全的异常安全性 [SWS_CORE_00412]。

关于在并发系统中的运行，根据规范该类被归类为 thread-safe [SWS_CORE_00412]。该属性对其使用目的至关重要，因为 ara::core::Promise 和 ara::core::Future 通常在相互独立的线程中执行。当触发异常时，该对象会在 C++ 运行时系统中被实例化。在堆栈展开期间，所有权沿调用层次结构转移到负责处理的 catch 块，在离开异常块后，异常对象将在该处被自动销毁。

使用路径

ara::core::FutureException 的常规使用路径沿着异步任务的调用链展开。通常，应用程序组件会启动一个异步操作，其结果通过一对相关联的 ara::core::Promise 和 ara::core::Future 进行管理。如果在执行任务或查询结果时出现错误情况，则会抛出该异常。

在典型流程中，使用者尝试通过 ara::core::Future 获取结果。如果底层 ara::core::Promise 中不存在有效结果或已设置了错误状态，则此访问将导致触发 ara::core::FutureException。此时构造函数强制要求传递关联的错误代码 err [SWS_CORE_00412]。消费方应用程序在匹配的异常处理程序中捕获该异常。推测调用方可以对封装的 ara::core::ErrorCode 进行求值，以精确确定错误域内的具体错误原因并采取适当的应对措施。

错误场景

在使用和处理 ara::core::FutureException 时，以下错误场景和系统安全保证至关重要：

  • 异常安全实例化：由于构造函数标有 noexcept，因此异常本身的对象创建绝不会失败，也不会抛出进一步的二次异常 [SWS_CORE_00412]。这确保了即使在负载下也能确定性地转换到异常处理。
  • 强制指定错误代码：该类不提供无参默认构造函数；其实例化强制要求有效的 ara::core::ErrorCode 作为参数 [SWS_CORE_00412]。因此，无法创建未设置错误代码的异常对象。
  • 未处理的异常：如果由 ara::core::Future 或 ara::core::Promise 触发的 ara::core::FutureException 未被应用程序的匹配 catch 块捕获，则会采用 C++ 的标准运行时行为，从而导致进程终止。由于该类公有继承自 Exception，因此它既可以被特异性捕获，也可以通过基类引用进行多态捕获。
