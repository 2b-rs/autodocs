上下文

类 [SWS_DM_00529] ara::diag::DiagUdsNrcErrorDomain 表示源自 AUTOSAR Adaptive Platform 不同诊断类和接口的诊断错误的标准错误域。根据 [SWS_DM_00529]，它派生自基类 ara::core::ErrorDomain，并充当应用端诊断例程与 Diagnostic Management（DM）之间的主要纽带。

在整个系统中，错误域在三个核心组件的接口处发挥作用：

  • Diagnostic Server (DM)：处理车载诊断测试仪的诊断请求、检查环境条件并生成符合标准的 UDS 响应的实例。
  • 外部诊断应用：实现车辆特定诊断服务并通过 ara::diag 接口返回结果或错误的应用逻辑或外部诊断处理器。
  • 诊断客户端（Tester）：向控制单元发送诊断命令，并在发生错误时期望收到标准化否定响应码（Negative Response Codes, NRC）的外部测试设备。

如果诊断应用程序通过 ara::diag 接口返回包含 ara::diag::DiagUdsNrcErrorDomain 域错误的结果，Diagnostic Server 会针对性地处理该错误：它从上报的错误码中推导出 UDS Negative Response Code [SWS_DM_02059]，并向诊断客户端发送包含该代码的否定响应 [SWS_DM_02060]。此外，该域还会与可配置环境条件的检查进行交互：如果因该域的错误导致获取数据元素失败，服务器会将该条件判定为未满足，并发出一条日志与跟踪消息 [SWS_DM_00970]。

生命周期

ara::diag::DiagUdsNrcErrorDomain 的生命周期遵循该平台无状态错误域的规范：

  • 创建与初始化：该类提供一个被定义为 constexpr 和 noexcept 的无参默认构造函数 [SWS_DM_00532]。解释：DiagUdsNrcErrorDomain 的实例在编译时或加载时作为长生命周期常量或单例对象创建，以便在整个进程运行期间均可用。
  • 所有权关系：应用程序通常不会在堆上动态创建实例，而是在对 ara::core::ErrorCode 值进行类型化时通过常量引用来引用该域。
  • 状态与转换：该域不包含可变的内部状态，也不需要状态转换。像 Name() [SWS_DM_00533] 或 Message() [SWS_DM_00534] 这样的观察性查询表现为无状态且确定性。
  • 并发性：所有成员函数——构造函数 [SWS_DM_00532]、Name() [SWS_DM_00533]、Message() [SWS_DM_00534] 以及 ThrowAsException() [SWS_DM_00535]——均被显式指定为线程安全。它们可以从不同的执行上下文中并行调用，无需额外的锁。

使用路径

诊断错误信号通知的常规流程分为以下步骤：

  1. 服务请求：诊断客户端向 Diagnostic Server 发送 UDS 服务请求。
  2. 调用诊断应用程序：Diagnostic Server 通过类型化的 ara::diag 接口将处理委托给负责的外部诊断处理器。
  3. 错误返回：如果诊断应用程序检测到无效条件，它会生成 ara::diag::DiagUdsNrcErrorDomain::Errc [SWS_DM_00530] 类型的错误码，并在 ara::core::Result 中将其返回。
  4. NRC 推导：如果 Diagnostic Server 识别出 ara::diag::DiagUdsNrcErrorDomain 域的错误，它会从 DiagUdsNrcErrc 值中推导出 UDS Negative Response Code [SWS_DM_02059]。这通常通过类型转换（static_cast）为允许范围 0x01 至 0xFE [SWS_DM_02059] 内的 1 字节值来实现。
  5. 协议响应：Diagnostic Server 使用确定的错误码生成 UDS 否定响应，并将其发送给客户端 [SWS_DM_02060]。
  6. 错误文本解析：对于诊断日志或系统消息，可以通过 Message() 查询错误描述，该函数始终提供有效的文本指针 [SWS_DM_00534]。

时序图：诊断操作失败时的错误传播与 UDS NRC 推导。来源：[SWS_DM_02059]、[SWS_DM_02060]

错误场景

为了对错误状态进行可控处理，该类提供了专用类型和转换机制：

  • 错误码枚举：类型别名 Errc 指向枚举 DiagUdsNrcErrc [SWS_DM_00530]。解释：枚举值反映了标准化的 UDS Negative Response Code。用于推导的有效值位于 0x01 至 0xFE [SWS_DM_02059] 的范围内。
  • 异常映射：别名 Exception 指向 DiagUdsNrcException [SWS_DM_00531]。通过 ThrowAsException() [SWS_DM_00535]，可以将错误码转换为相应的异常并抛出。如果在工具链中禁用了 C++ 异常，则该函数不参与重载解析 [SWS_DM_00535]。
  • 获取数据元素时出错：如果外部处理器获取数据元素导致 ara::diag::DiagUdsNrcErrorDomain 域的错误，诊断管理会将环境条件的相关公式部分视为未满足，并触发一条日志与跟踪消息 [SWS_DM_00970]。
  • 多 DID 请求时的行为：结果中存在 ara::diag::DiagUdsNrcErrorDomain 表示外部处理器的否定部分结果。然而在涉及多个 DID 的请求中，单个错误并不必然导致全局否定响应，只要在活动会话中支持至少一个 DID 即可（AUTOSAR_AP_SWS_Diagnostics §7.3.x 第160页）。

<p>类 <a class="spec-record-ref" data-req="SWS_DM_00529" href="../spec/record.html?id=SWS_DM_00529">[SWS_DM_00529]</a> <code>ara::diag::DiagUdsNrcErrorDomain</code> 表示源自 AUTOSAR Adaptive Platform 不同诊断类和接口的诊断错误的标准错误域。根据 <a class="spec-record-ref" data-req="SWS_DM_00529" href="../spec/record.html?id=SWS_DM_00529">[SWS_DM_00529]</a>，它派生自基类 <code>ara::core::ErrorDomain</code>，并充当应用端诊断例程与 Diagnostic Management（DM）之间的主要纽带。</p>
<p>在整个系统中，错误域在三个核心组件的接口处发挥作用：</p>
<ul>
<li><strong>Diagnostic Server (DM)：</strong>处理车载诊断测试仪的诊断请求、检查环境条件并生成符合标准的 UDS 响应的实例。</li>
<li><strong>外部诊断应用：</strong>实现车辆特定诊断服务并通过 <code>ara::diag</code> 接口返回结果或错误的应用逻辑或外部诊断处理器。</li>
<li><strong>诊断客户端（Tester）：</strong>向控制单元发送诊断命令，并在发生错误时期望收到标准化否定响应码（Negative Response Codes, NRC）的外部测试设备。</li>
</ul>
<p>如果诊断应用程序通过 <code>ara::diag</code> 接口返回包含 <code>ara::diag::DiagUdsNrcErrorDomain</code> 域错误的结果，Diagnostic Server 会针对性地处理该错误：它从上报的错误码中推导出 UDS Negative Response Code <a class="spec-record-ref" data-req="SWS_DM_02059" href="../spec/record.html?id=SWS_DM_02059">[SWS_DM_02059]</a>，并向诊断客户端发送包含该代码的否定响应 <a class="spec-record-ref" data-req="SWS_DM_02060" href="../spec/record.html?id=SWS_DM_02060">[SWS_DM_02060]</a>。此外，该域还会与可配置环境条件的检查进行交互：如果因该域的错误导致获取数据元素失败，服务器会将该条件判定为未满足，并发出一条日志与跟踪消息 <a class="spec-record-ref" data-req="SWS_DM_00970" href="../spec/record.html?id=SWS_DM_00970">[SWS_DM_00970]</a>。</p>

<h4>使用路径</h4>
<p>诊断错误信号通知的常规流程分为以下步骤：</p>
<ol>
<li><strong>服务请求：</strong>诊断客户端向 Diagnostic Server 发送 UDS 服务请求。</li>
<li><strong>调用诊断应用程序：</strong>Diagnostic Server 通过类型化的 <code>ara::diag</code> 接口将处理委托给负责的外部诊断处理器。</li>
<li><strong>错误返回：</strong>如果诊断应用程序检测到无效条件，它会生成 <code>ara::diag::DiagUdsNrcErrorDomain::Errc</code> <a class="spec-record-ref" data-req="SWS_DM_00530" href="../spec/record.html?id=SWS_DM_00530">[SWS_DM_00530]</a> 类型的错误码，并在 <code>ara::core::Result</code> 中将其返回。</li>
<li><strong>NRC 推导：</strong>如果 Diagnostic Server 识别出 <code>ara::diag::DiagUdsNrcErrorDomain</code> 域的错误，它会从 <code>DiagUdsNrcErrc</code> 值中推导出 UDS Negative Response Code <a class="spec-record-ref" data-req="SWS_DM_02059" href="../spec/record.html?id=SWS_DM_02059">[SWS_DM_02059]</a>。这通常通过类型转换（<code>static_cast</code>）为允许范围 <code>0x01</code> 至 <code>0xFE</code> <a class="spec-record-ref" data-req="SWS_DM_02059" href="../spec/record.html?id=SWS_DM_02059">[SWS_DM_02059]</a> 内的 1 字节值来实现。</li>
<li><strong>协议响应：</strong>Diagnostic Server 使用确定的错误码生成 UDS 否定响应，并将其发送给客户端 <a class="spec-record-ref" data-req="SWS_DM_02060" href="../spec/record.html?id=SWS_DM_02060">[SWS_DM_02060]</a>。</li>
<li><strong>错误文本解析：</strong>对于诊断日志或系统消息，可以通过 <code>Message()</code> 查询错误描述，该函数始终提供有效的文本指针 <a class="spec-record-ref" data-req="SWS_DM_00534" href="../spec/record.html?id=SWS_DM_00534">[SWS_DM_00534]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>为了对错误状态进行可控处理，该类提供了专用类型和转换机制：</p>
<ul>
<li><strong>错误码枚举：</strong>类型别名 <code>Errc</code> 指向枚举 <code>DiagUdsNrcErrc</code> <a class="spec-record-ref" data-req="SWS_DM_00530" href="../spec/record.html?id=SWS_DM_00530">[SWS_DM_00530]</a>。解释：枚举值反映了标准化的 UDS Negative Response Code。用于推导的有效值位于 <code>0x01</code> 至 <code>0xFE</code> <a class="spec-record-ref" data-req="SWS_DM_02059" href="../spec/record.html?id=SWS_DM_02059">[SWS_DM_02059]</a> 的范围内。</li>
<li><strong>异常映射：</strong>别名 <code>Exception</code> 指向 <code>DiagUdsNrcException</code> <a class="spec-record-ref" data-req="SWS_DM_00531" href="../spec/record.html?id=SWS_DM_00531">[SWS_DM_00531]</a>。通过 <code>ThrowAsException()</code> <a class="spec-record-ref" data-req="SWS_DM_00535" href="../spec/record.html?id=SWS_DM_00535">[SWS_DM_00535]</a>，可以将错误码转换为相应的异常并抛出。如果在工具链中禁用了 C++ 异常，则该函数不参与重载解析 <a class="spec-record-ref" data-req="SWS_DM_00535" href="../spec/record.html?id=SWS_DM_00535">[SWS_DM_00535]</a>。</li>
<li><strong>获取数据元素时出错：</strong>如果外部处理器获取数据元素导致 <code>ara::diag::DiagUdsNrcErrorDomain</code> 域的错误，诊断管理会将环境条件的相关公式部分视为未满足，并触发一条日志与跟踪消息 <a class="spec-record-ref" data-req="SWS_DM_00970" href="../spec/record.html?id=SWS_DM_00970">[SWS_DM_00970]</a>。</li>
<li><strong>多 DID 请求时的行为：</strong>结果中存在 <code>ara::diag::DiagUdsNrcErrorDomain</code> 表示外部处理器的否定部分结果。然而在涉及多个 DID 的请求中，单个错误并不必然导致全局否定响应，只要在活动会话中支持至少一个 DID 即可（<a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=160">AUTOSAR_AP_SWS_Diagnostics §7.3.x 第160页</a>）。</li>
</ul>
