上下文

类ara::diag::DoIPTriggerVehicleAnnouncement [SWS_DM_00820]在AUTOSAR Adaptive Platform（模块diag）内提供了一个编程接口，Adaptive Application可以通过该接口发起DoIP车辆声明消息（Vehicle Announcement Messages）的发送。

根据AUTOSAR_AP_SWS_Diagnostics 第106页 “About DiagnosticDoIPTriggerVehicleAnnouncementInterface”，发送这些消息的主要责任直接由Diagnostic Manager（DM）承担。该标准规定，DM应根据ISO 13400-2中定义的长景自主发送车辆声明：

  • 在网络启动时作为广播发送给其他基于IP的ECU和网关，
  • 通过激活线（Activation Line）检测到外部测试仪时。

尽管ISO 13400-2规定的常规流程由DM自主处理，且其中原本并未规定由Adaptive Application进行手动触发（AUTOSAR_AP_SWS_Diagnostics 第106页 “About DiagnosticDoIPTriggerVehicleAnnouncementInterface”），但接口ara::diag::DoIPTriggerVehicleAnnouncement仍允许应用程序进行显式触发。在此过程中，DM充当执行者，按照ISO 13400-2在指定的网络接口上发送这些消息[SWS_DM_00815]。

生命周期

ara::diag::DoIPTriggerVehicleAnnouncement的实例化和生命周期管理完全由Diagnostic Manager负责：

  • 创建与销毁：默认构造函数被声明为已删除（DoIPTriggerVehicleAnnouncement() = delete）且为私有保护[SWS_DM_02100]。同样，析构函数也是私有且已删除的（~DoIPTriggerVehicleAnnouncement() noexcept = delete）[SWS_DM_02101]。两种方法均为厂商特定实现[SWS_DM_02100]、[SWS_DM_02101]。因此，Adaptive Application无法在栈或堆上实例化自己的实例。
  • 实例获取：对该接口的访问只能通过静态工厂方法GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]进行。该方法返回一个类型为ara::core::Result<std::reference_wrapper<DoIPTriggerVehicleAnnouncement>>的对象，该对象提供对DM管理对象的引用。
  • 并发性：工厂方法GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]与方法TriggerVehicleAnnouncement() [SWS_DM_00822]均被明确指定为非线程安全（not thread-safe）。如果应用程序的多个线程访问该接口，调用方必须确保同步。两种方法均被指定为异常安全（exception safe）[SWS_DM_00821]、[SWS_DM_00822]。

使用路径

触发车辆声明的典型流程分为以下步骤：

  1. 请求接口引用：Adaptive Application调用静态函数ara::diag::DoIPTriggerVehicleAnnouncement::GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]。
  2. 验证结果：应用程序检查返回的ara::core::Result是否成功，并解包std::reference_wrapper。
  3. 触发声明：应用程序通过获取到的引用调用方法TriggerVehicleAnnouncement(networkInterfaceId) [SWS_DM_00822]。参数networkInterfaceId（类型为std::uint8_t）指定目标网络接口。
  4. 通过DM发送：Diagnostic Manager在指定的网络接口上按照ISO 13400-2触发声明消息的发送[SWS_DM_00815]，并通过ara::core::Result<void>向应用程序确认执行[SWS_DM_00822]。

时序图：显式触发DoIP车辆声明的交互模式。来源：[SWS_DM_00821]、[SWS_DM_00822]、[SWS_DM_00815]。

错误场景

调用TriggerVehicleAnnouncement()时，在网络配置方面适用特定的前置条件：

  • 与激活线控制接口的冲突：如果传入的networkInterfaceId属于设置了属性isActivationLineDependent = TRUE的配置，则该方法调用构成错误[SWS_DM_00822]。其原因在于，根据[SWS_DM_00816]，一旦激活线电平升高且分配了IP地址，DM便会在这些接口上全自动进行发送[SWS_DM_00822]。
  • 缺失标准化错误码：标准中对于GetDoIPTriggerVehicleAnnouncement() [SWS_DM_00821]和TriggerVehicleAnnouncement() [SWS_DM_00822]均未预定义特定的错误码（“This function does not specify any standardized errors”）。如果仍然发生错误（例如传入了依赖激活线的接口或内部错误），ara::core::Result可能传递厂商特定的错误码。
