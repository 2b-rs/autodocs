类 ara::exec::StateClient

[SWS_EM_02275] Upstream: RS_EM_00101, RS_AP_00154, RS_AP_00150

class StateClient final {...};

ara::exec::StateClient is an interface of Execution Management that is used by State Management to request transitions between Function Group States or to perform other related operations. Class used to perform Function Group state management operation needed during lifetime of a Machine. State Management during its own lifetime will need to start and stop software, that is intended to run on a Machine managed by it. This can be achieved by performing state transition of a Function Group to which required software is assigned. Integrator will assign software to run in a particular state (of Function Group) and State Management can start it, by requesting Execution Management to perform state transition (of this Function Group) to the mentioned state. Execution Management will then start mentioned software and report transition result back to State Management. Please note that stopping software can be done in similar way (i.e. Function Group state transition, to a state in which software is not configured to be run).

上下文

类 ara::exec::StateClient 充当 Execution Management 面向 State Management 的功能接口。在整个系统中，State Management 负责控制机器的生命周期，并根据需要启动和停止软件组件。这是通过配置的功能组（Function Groups）的状态转换来实现的，集成商已向这些功能组分配了具体的软件进程。

State Management 使用 ara::exec::StateClient 向 Execution Management 请求单个功能组的状态转换 [SWS_EM_02278]。Execution Management 通过启动或终止分配给该功能组的软件来执行这些转换，并将转换结果报告给 State Management。在后台建立到 Execution Management 的连接时，很可能会使用平台特定的 IPC 通道（如 Unix 域套接字），因为该规范未对具体的 IPC 技术做进一步限制。

生命周期

对于 ara::exec::StateClient 的实例化，AUTOSAR 提供了两条构建路径：

  • 具名工厂方法：静态函数 Create 返回一个 ara::core::Result<StateClient>，并以基于错误码且异常安全的方式封装创建时的潜在错误（[SWS_EM_02276]）。
  • 常规构造函数：直接构造函数被声明为 noexcept(false)，并在发生错误时通过异常指示错误（[SWS_EM_02561]）。

两种创建路径均要求传递一个签名格式为 std::function<void(const ara::exec::ExecutionErrorEvent&)> 的回调 undefinedStateCallback。如果某个功能组意外且未事先通过 SetState 请求而转换到未定义状态（Undefined Function Group State），该回调将由 StateClient 库调用（[SWS_EM_02276]，[SWS_EM_02561]）。在生命周期方面，必须确保该回调在 StateClient 实例的整个生命周期内保持可调用状态；这在通过 std::bind 绑定实例方法时尤为重要（[SWS_EM_02276]，[SWS_EM_02561]）。

复制操作被完全禁止：复制构造函数和赋值运算符均被显式删除（delete）（[SWS_EM_02565]，[SWS_EM_02568]）。相反，该类支持移动语义：移动构造函数和移动赋值运算符被定义为 noexcept（[SWS_EM_02566]，[SWS_EM_02567]）。析构函数被声明为 noexcept（[SWS_EM_02277]）。一旦状态更改被 Execution Management 接收，无论 StateClient 实例的生命周期如何，它都会被处理完毕；然而由 SetState 返回的 ara::core::Future 取决于该实例的生命周期（[SWS_EM_02278]）。

在并发性方面，实例方法 SetState、GetExecutionError 和 GetInitialMachineStateTransitionResult 以及 Create 和常规构造函数被指定为线程安全（[SWS_EM_02276]，[SWS_EM_02278]，[SWS_EM_02279]，[SWS_EM_02542]，[SWS_EM_02561]）。相比之下，移动操作和析构函数则不是线程安全的（[SWS_EM_02566]，[SWS_EM_02567]，[SWS_EM_02277]）。

使用路径

State Management 的典型使用流程分为以下步骤：

  1. 客户端创建：State Management 通过 Create 实例化 StateClient 并注册错误回调（[SWS_EM_02276]）。
  2. 同步启动状态：在机器运行开始时，通过 GetInitialMachineStateTransitionResult() 查询机器转换到 Startup 初始状态的结果（[SWS_EM_02279]）。该方法返回一个 ara::core::Future<void>。由于此转换在每个机器生命周期中仅发生一次，因此该结果在剩余的运行时间内保持不变（[SWS_EM_02279]）。
  3. 请求状态更改：在运行时，State Management 通过 SetState(state) 请求单个功能组的转换（[SWS_EM_02278]）。该方法立即返回并提供一个 ara::core::Future<void>，用于指示转换成功或提供 ExecErrorDomain 的错误。
  4. 分析错误状态：如果功能组意外进入未定义状态，将触发已注册的回调。只要功能组仍处于该状态，State Management 就可以通过 GetExecutionError(functionGroupState) 获取引发此状态的 ExecutionErrorEvent（[SWS_EM_02542]）。

错误场景

ara::exec::StateClient 的方法使用来自 Execution Management 错误域（ara::exec::ExecErrc）的错误码。以下错误场景相关：

  • 通信故障（ExecErrc::kNoCommunication）：当客户端与 Execution Management 之间的连接受到干扰或中断时发生。该错误针对所有操作进行了指定（[SWS_EM_02276]、[SWS_EM_02561]、[SWS_EM_02278]、[SWS_EM_02279]、[SWS_EM_02542]）。重试调用是预期的恢复措施。
  • 无效传递与元模型冲突：
    • ExecErrc::kInvalidArgument 在创建时指示传入的 undefinedStateCallback 不可调用（[SWS_EM_02276]，[SWS_EM_02561]）。
    • ExecErrc::kInvalidMetaModelIdentifier 指出目标状态在清单中不存在，或者调用进程没有到相应功能组的映射（[SWS_EM_02278]，[SWS_EM_02279]，[SWS_EM_02542]）。
  • 状态转换失败或中止：
    • ExecErrc::kOperationCanceled 提示转换已被更新的请求抢占或已被 State Management 中止（[SWS_EM_02278]，[SWS_EM_02279]）。
    • 当转换不合法（例如切换至 MachineFG 的 Off 状态）或状态在软件更新后不再存在（[SWS_EM_02278]）时，将返回 ExecErrc::kInvalidTransition。
    • ExecErrc::kIntegrityOrAuthenticityCheckFailed 报告状态切换期间真实性或完整性检查的失败（[SWS_EM_02278]）。
    • 当参与的进程在转换过程中意外终止时，会出现 ExecErrc::kUnexpectedTermination（[SWS_EM_02278]）。
    • ExecErrc::kOperationFailed 表示转换的一般性失败（[SWS_EM_02278]、[SWS_EM_02279]）。而在调用 GetExecutionError 时，该错误则表示功能组并未处于未定义状态，且问题可能已经得到解决（[SWS_EM_02542]）。

<h4>上下文</h4>
<p>类 <code>ara::exec::StateClient</code> 充当 Execution Management 面向 State Management 的功能接口。在整个系统中，State Management 负责控制机器的生命周期，并根据需要启动和停止软件组件。这是通过配置的功能组（<em>Function Groups</em>）的状态转换来实现的，集成商已向这些功能组分配了具体的软件进程。</p>
<p>State Management 使用 <code>ara::exec::StateClient</code> 向 Execution Management 请求单个功能组的状态转换 <a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>。Execution Management 通过启动或终止分配给该功能组的软件来执行这些转换，并将转换结果报告给 State Management。在后台建立到 Execution Management 的连接时，很可能会使用平台特定的 IPC 通道（如 Unix 域套接字），因为该规范未对具体的 IPC 技术做进一步限制。</p>

<h4>生命周期</h4>
<p>对于 <code>ara::exec::StateClient</code> 的实例化，AUTOSAR 提供了两条构建路径：</p>
<ul>
<li><strong>具名工厂方法：</strong>静态函数 <code>Create</code> 返回一个 <code>ara::core::Result&lt;StateClient&gt;</code>，并以基于错误码且异常安全的方式封装创建时的潜在错误（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>）。</li>
<li><strong>常规构造函数：</strong>直接构造函数被声明为 <code>noexcept(false)</code>，并在发生错误时通过异常指示错误（<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>）。</li>
</ul>
<p>两种创建路径均要求传递一个签名格式为 <code>std::function&lt;void(const ara::exec::ExecutionErrorEvent&amp;)&gt;</code> 的回调 <code>undefinedStateCallback</code>。如果某个功能组意外且未事先通过 <code>SetState</code> 请求而转换到未定义状态（<em>Undefined Function Group State</em>），该回调将由 StateClient 库调用（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>，<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>）。在生命周期方面，必须确保该回调在 <code>StateClient</code> 实例的整个生命周期内保持可调用状态；这在通过 <code>std::bind</code> 绑定实例方法时尤为重要（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>，<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>）。</p>
<p>复制操作被完全禁止：复制构造函数和赋值运算符均被显式删除（<code>delete</code>）（<a class="spec-record-ref" data-req="SWS_EM_02565" href="../spec/record.html?id=SWS_EM_02565">[SWS_EM_02565]</a>，<a class="spec-record-ref" data-req="SWS_EM_02568" href="../spec/record.html?id=SWS_EM_02568">[SWS_EM_02568]</a>）。相反，该类支持移动语义：移动构造函数和移动赋值运算符被定义为 <code>noexcept</code>（<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>，<a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>）。析构函数被声明为 <code>noexcept</code>（<a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>）。一旦状态更改被 Execution Management 接收，无论 <code>StateClient</code> 实例的生命周期如何，它都会被处理完毕；然而由 <code>SetState</code> 返回的 <code>ara::core::Future</code> 取决于该实例的生命周期（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>）。</p>
<p>在并发性方面，实例方法 <code>SetState</code>、<code>GetExecutionError</code> 和 <code>GetInitialMachineStateTransitionResult</code> 以及 <code>Create</code> 和常规构造函数被指定为线程安全（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>，<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>，<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>，<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>，<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>）。相比之下，移动操作和析构函数则不是线程安全的（<a class="spec-record-ref" data-req="SWS_EM_02566" href="../spec/record.html?id=SWS_EM_02566">[SWS_EM_02566]</a>，<a class="spec-record-ref" data-req="SWS_EM_02567" href="../spec/record.html?id=SWS_EM_02567">[SWS_EM_02567]</a>，<a class="spec-record-ref" data-req="SWS_EM_02277" href="../spec/record.html?id=SWS_EM_02277">[SWS_EM_02277]</a>）。</p>

<h4>使用路径</h4>
<p>State Management 的典型使用流程分为以下步骤：</p>
<ol>
<li><strong>客户端创建：</strong>State Management 通过 <code>Create</code> 实例化 <code>StateClient</code> 并注册错误回调（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>）。</li>
<li><strong>同步启动状态：</strong>在机器运行开始时，通过 <code>GetInitialMachineStateTransitionResult()</code> 查询机器转换到 Startup 初始状态的结果（<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>）。该方法返回一个 <code>ara::core::Future&lt;void&gt;</code>。由于此转换在每个机器生命周期中仅发生一次，因此该结果在剩余的运行时间内保持不变（<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>）。</li>
<li><strong>请求状态更改：</strong>在运行时，State Management 通过 <code>SetState(state)</code> 请求单个功能组的转换（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>）。该方法立即返回并提供一个 <code>ara::core::Future&lt;void&gt;</code>，用于指示转换成功或提供 <code>ExecErrorDomain</code> 的错误。</li>
<li><strong>分析错误状态：</strong>如果功能组意外进入未定义状态，将触发已注册的回调。只要功能组仍处于该状态，State Management 就可以通过 <code>GetExecutionError(functionGroupState)</code> 获取引发此状态的 <code>ExecutionErrorEvent</code>（<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>）。</li>
</ol>

<h4>错误场景</h4>
<p><code>ara::exec::StateClient</code> 的方法使用来自 Execution Management 错误域（<code>ara::exec::ExecErrc</code>）的错误码。以下错误场景相关：</p>
<ul>
<li><strong>通信故障（<code>ExecErrc::kNoCommunication</code>）：</strong>当客户端与 Execution Management 之间的连接受到干扰或中断时发生。该错误针对所有操作进行了指定（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>、<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>、<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>、<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>、<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>）。重试调用是预期的恢复措施。</li>
<li><strong>无效传递与元模型冲突：</strong>
<ul>
<li><code>ExecErrc::kInvalidArgument</code> 在创建时指示传入的 <code>undefinedStateCallback</code> 不可调用（<a class="spec-record-ref" data-req="SWS_EM_02276" href="../spec/record.html?id=SWS_EM_02276">[SWS_EM_02276]</a>，<a class="spec-record-ref" data-req="SWS_EM_02561" href="../spec/record.html?id=SWS_EM_02561">[SWS_EM_02561]</a>）。</li>
<li><code>ExecErrc::kInvalidMetaModelIdentifier</code> 指出目标状态在清单中不存在，或者调用进程没有到相应功能组的映射（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>，<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>，<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>）。</li>
</ul>
</li>
<li><strong>状态转换失败或中止：</strong>
<ul>
<li><code>ExecErrc::kOperationCanceled</code> 提示转换已被更新的请求抢占或已被 State Management 中止（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>，<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>）。</li>
<li>当转换不合法（例如切换至 MachineFG 的 Off 状态）或状态在软件更新后不再存在（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>）时，将返回 <code>ExecErrc::kInvalidTransition</code>。</li>
<li><code>ExecErrc::kIntegrityOrAuthenticityCheckFailed</code> 报告状态切换期间真实性或完整性检查的失败（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>）。</li>
<li>当参与的进程在转换过程中意外终止时，会出现 <code>ExecErrc::kUnexpectedTermination</code>（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>）。</li>
<li><code>ExecErrc::kOperationFailed</code> 表示转换的一般性失败（<a class="spec-record-ref" data-req="SWS_EM_02278" href="../spec/record.html?id=SWS_EM_02278">[SWS_EM_02278]</a>、<a class="spec-record-ref" data-req="SWS_EM_02279" href="../spec/record.html?id=SWS_EM_02279">[SWS_EM_02279]</a>）。而在调用 <code>GetExecutionError</code> 时，该错误则表示功能组并未处于未定义状态，且问题可能已经得到解决（<a class="spec-record-ref" data-req="SWS_EM_02542" href="../spec/record.html?id=SWS_EM_02542">[SWS_EM_02542]</a>）。</li>
</ul>
</li>
</ul>
<p class="ai-note">本指南基于 AUTOSAR Adaptive Platform 在 Release R25-11 中针对 Execution Management 的规范。</p>
