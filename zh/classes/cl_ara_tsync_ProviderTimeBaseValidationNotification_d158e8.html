上下文

类 ara::tsync::ProviderTimeBaseValidationNotification 是 AUTOSAR Adaptive 模块 tsync 内的一个抽象接口（回调接口）。它用于在上层验证应用程序（Validator Application）有一批为时间基准记录的新测量数据块可用时通知该应用程序。

在时间同步的整个系统中，通常有三个核心组件进行交互：

  • tsync-Provider（Time Base）：同步子系统在运行时采集协议和时序数据。一旦有新的测量数据块就绪，提供方就会调用相应的通知方法。
  • ProviderTimeBaseValidationNotification：该抽象回调接口定义了用于传递主节点和响应端测量数据（[SWS_TS_00421]、[SWS_TS_00423]）的调用契约。
  • 验证器应用程序：特定于应用程序的逻辑实现此接口，以评估接收到的测量数据块、执行合理性检查并监控时间基准的有效性。

上下文图：tsync-Provider、回调接口与验证器应用程序之间的相互协作。来源：[SWS_TS_00421]、[SWS_TS_00423]。

生命周期

由于 ProviderTimeBaseValidationNotification 是一个带有纯虚成员函数的纯抽象基类，因此无法直接实例化。其生命周期分为以下阶段：

  • 创建与所有权：验证器应用程序从 ProviderTimeBaseValidationNotification 派生出一个具体观察者类并将其实例化。所有权（Ownership）保留在验证器应用程序中。
  • 提供：解释：创建的回调实例将在 tsync-Provider 要监控的时间基准上进行注册，以便提供方能够持有其引用并执行方法调用。
  • 状态：接口本身不具有内部状态存储。注册后，对象保持在准备接收传入测量数据的状态。
  • 销毁：该类具有一个虚默认析构函数 ~ProviderTimeBaseValidationNotification() noexcept = default;（[SWS_TS_01301]）。这确保了多态实例在通过指向接口的指针释放时能够被正确清理。在销毁对象之前，必须确保 tsync-Provider 不再向该实例发送其他通知。
  • 并发性：根据规范，接口方法被归类为 non_threadsafe（[SWS_TS_00421]、[SWS_TS_00423]）。因此，验证器应用程序不能假定并行调用在没有外部同步机制的情况下能够以线程安全的方式进行处理。

使用路径

典型使用路径描述了在时间基准处于活动运行期间对时序测量数据的接收和转发：

  1. 回调的实现：应用程序重写这两个接口方法 SetMasterTimingData（[SWS_TS_00421]）和 SetPdelayResponderData（[SWS_TS_00423]）。
  2. 提供给时间基准：推测应用程序将派生实例的引用传递给 tsync 子系统以激活监控。
  3. 接收 Time Master 数据：一旦为时间基准的 Time Master 准备好了新的测量数据块，tsync 子系统就会调用方法 SetMasterTimingData（[SWS_TS_00421]）。此时调用方会传递类型为 const TimeMasterMeasurementType& 的参数 measurementData，其中包含 Time Master 的详细验证数据。
  4. 接收 Pdelay-Responder 数据：如果存在为时间基准的 pDelay Responder 记录的测量数据，则会调用 SetPdelayResponderData（[SWS_TS_00423]）。此时会传递一个类型为 const PdelayResponderMeasurementType& 的数据块以供评估。
  5. 评估与终止：验证器应用程序检查接收到的测量数据的一致性和阈值偏差。在系统停止或验证终止时，该实例将通过虚析构函数（[SWS_TS_01301]）释放。

时序图：通过通知接口提供测量数据块。来源：[SWS_TS_00421]、[SWS_TS_00423]、[SWS_TS_01301]。

错误场景

关于错误处理和边界条件，ProviderTimeBaseValidationNotification 适用以下规定：

  • 异常安全性：所有成员函数——SetMasterTimingData（[SWS_TS_00421]）、SetPdelayResponderData（[SWS_TS_00423]）以及析构函数（[SWS_TS_01301]）——均声明为 noexcept 并指定为 exception safe。验证器应用程序的实现不得让任何 C++ 异常从回调中逸出，因为在 noexcept 函数中发生异常状态会导致立即通过 std::terminate 终止程序。
  • 返回值与错误信号传输：这些方法具有返回类型 void。此接口未提供向 tsync-Provider 直接反馈成功或失败的机制。
  • 引用的有效性：传递的测量数据结构作为常量引用传入。被调用的应用程序必须假定数据的有效性可能仅限于方法调用的持续时间内，因此需要持久化的值应复制到应用程序自有的结构中。
  • 并发访问：由于两个通知函数均标记为 non_threadsafe（[SWS_TS_00421]、[SWS_TS_00423]），因此从多个线程同时调用构成违反前置条件。调用推测由框架同步执行；若实现修改了内部数据结构，则必须采取自身的同步防范措施。

<h4>生命周期</h4>
<p>由于 <code>ProviderTimeBaseValidationNotification</code> 是一个带有纯虚成员函数的纯抽象基类，因此无法直接实例化。其生命周期分为以下阶段：</p>
<ul>
<li><strong>创建与所有权：</strong>验证器应用程序从 <code>ProviderTimeBaseValidationNotification</code> 派生出一个具体观察者类并将其实例化。所有权（Ownership）保留在验证器应用程序中。</li>
<li><strong>提供：</strong>解释：创建的回调实例将在 tsync-Provider 要监控的时间基准上进行注册，以便提供方能够持有其引用并执行方法调用。</li>
<li><strong>状态：</strong>接口本身不具有内部状态存储。注册后，对象保持在准备接收传入测量数据的状态。</li>
<li><strong>销毁：</strong>该类具有一个虚默认析构函数 <code>~ProviderTimeBaseValidationNotification() noexcept = default;</code>（<a class="spec-record-ref" data-req="SWS_TS_01301" href="../spec/record.html?id=SWS_TS_01301">[SWS_TS_01301]</a>）。这确保了多态实例在通过指向接口的指针释放时能够被正确清理。在销毁对象之前，必须确保 tsync-Provider 不再向该实例发送其他通知。</li>
<li><strong>并发性：</strong>根据规范，接口方法被归类为 <code>non_threadsafe</code>（<a class="spec-record-ref" data-req="SWS_TS_00421" href="../spec/record.html?id=SWS_TS_00421">[SWS_TS_00421]</a>、<a class="spec-record-ref" data-req="SWS_TS_00423" href="../spec/record.html?id=SWS_TS_00423">[SWS_TS_00423]</a>）。因此，验证器应用程序不能假定并行调用在没有外部同步机制的情况下能够以线程安全的方式进行处理。</li>
</ul>

<h4>使用路径</h4>
<p>典型使用路径描述了在时间基准处于活动运行期间对时序测量数据的接收和转发：</p>
<ol>
<li><strong>回调的实现：</strong>应用程序重写这两个接口方法 <code>SetMasterTimingData</code>（<a class="spec-record-ref" data-req="SWS_TS_00421" href="../spec/record.html?id=SWS_TS_00421">[SWS_TS_00421]</a>）和 <code>SetPdelayResponderData</code>（<a class="spec-record-ref" data-req="SWS_TS_00423" href="../spec/record.html?id=SWS_TS_00423">[SWS_TS_00423]</a>）。</li>
<li><strong>提供给时间基准：</strong>推测应用程序将派生实例的引用传递给 tsync 子系统以激活监控。</li>
<li><strong>接收 Time Master 数据：</strong>一旦为时间基准的 Time Master 准备好了新的测量数据块，tsync 子系统就会调用方法 <code>SetMasterTimingData</code>（<a class="spec-record-ref" data-req="SWS_TS_00421" href="../spec/record.html?id=SWS_TS_00421">[SWS_TS_00421]</a>）。此时调用方会传递类型为 <code>const TimeMasterMeasurementType&amp;</code> 的参数 <code>measurementData</code>，其中包含 Time Master 的详细验证数据。</li>
<li><strong>接收 Pdelay-Responder 数据：</strong>如果存在为时间基准的 pDelay Responder 记录的测量数据，则会调用 <code>SetPdelayResponderData</code>（<a class="spec-record-ref" data-req="SWS_TS_00423" href="../spec/record.html?id=SWS_TS_00423">[SWS_TS_00423]</a>）。此时会传递一个类型为 <code>const PdelayResponderMeasurementType&amp;</code> 的数据块以供评估。</li>
<li><strong>评估与终止：</strong>验证器应用程序检查接收到的测量数据的一致性和阈值偏差。在系统停止或验证终止时，该实例将通过虚析构函数（<a class="spec-record-ref" data-req="SWS_TS_01301" href="../spec/record.html?id=SWS_TS_01301">[SWS_TS_01301]</a>）释放。</li>
</ol>

<h4>错误场景</h4>
<p>关于错误处理和边界条件，<code>ProviderTimeBaseValidationNotification</code> 适用以下规定：</p>
<ul>
<li><strong>异常安全性：</strong>所有成员函数——<code>SetMasterTimingData</code>（<a class="spec-record-ref" data-req="SWS_TS_00421" href="../spec/record.html?id=SWS_TS_00421">[SWS_TS_00421]</a>）、<code>SetPdelayResponderData</code>（<a class="spec-record-ref" data-req="SWS_TS_00423" href="../spec/record.html?id=SWS_TS_00423">[SWS_TS_00423]</a>）以及析构函数（<a class="spec-record-ref" data-req="SWS_TS_01301" href="../spec/record.html?id=SWS_TS_01301">[SWS_TS_01301]</a>）——均声明为 <code>noexcept</code> 并指定为 <code>exception safe</code>。验证器应用程序的实现不得让任何 C++ 异常从回调中逸出，因为在 <code>noexcept</code> 函数中发生异常状态会导致立即通过 <code>std::terminate</code> 终止程序。</li>
<li><strong>返回值与错误信号传输：</strong>这些方法具有返回类型 <code>void</code>。此接口未提供向 tsync-Provider 直接反馈成功或失败的机制。</li>
<li><strong>引用的有效性：</strong>传递的测量数据结构作为常量引用传入。被调用的应用程序必须假定数据的有效性可能仅限于方法调用的持续时间内，因此需要持久化的值应复制到应用程序自有的结构中。</li>
<li><strong>并发访问：</strong>由于两个通知函数均标记为 <code>non_threadsafe</code>（<a class="spec-record-ref" data-req="SWS_TS_00421" href="../spec/record.html?id=SWS_TS_00421">[SWS_TS_00421]</a>、<a class="spec-record-ref" data-req="SWS_TS_00423" href="../spec/record.html?id=SWS_TS_00423">[SWS_TS_00423]</a>），因此从多个线程同时调用构成违反前置条件。调用推测由框架同步执行；若实现修改了内部数据结构，则必须采取自身的同步防范措施。</li>
</ul>
