上下文

模板类特化 ara::core::Result<void, E> 表示在成功执行时不返回有效负载数据值、而仅指示成功或发生错误的操作结果。在 AUTOSAR Adaptive Platform 内，它用作具有 void 语义的函数的标准化返回类型，并支持无 C++ 异常的结构化错误处理。值类型通过类型别名固定指定为 value_type = void [SWS_CORE_00811]，而错误类型通过类型别名 error_type = E [SWS_CORE_00812] 进行参数化。该实现强制在编译时使包含 E != ara::core::ErrorCode 的条件导致编译错误。

作为标准化结果类型，该类构成了调用方应用程序组件与执行方平台服务或应用程序服务之间的接口。它确保无返回值操作采用与 ara::core::Result 的带值特化相同的统一接口理念和函数式后续处理。

生命周期

ara::core::Result<void, E> 的实例在任何时刻都恰好处于两种不同状态之一：它要么表示成功流程（具有 void 值的状态），要么表示包含类型为 E 的错误对象的错误状态。

成功实例的创建通过无参默认构造函数 [SWS_CORE_00821] 或静态工厂方法 FromValue() [SWS_CORE_00831] 进行。错误状态则在构造时通过传入作为左值 [SWS_CORE_00823] 或右值 [SWS_CORE_00824] 的错误对象来建立。此外，静态方法 FromError() 提供了通过复制 [SWS_CORE_00834]、通过移动 [SWS_CORE_00835] 或就地从参数创建错误 [SWS_CORE_00836] 的工厂。后一种重载通过 SFINAE 进行约束，并且仅当 E 可从参数构造且第一个参数既非 E 也非 Result 的特化时才参与重载决议 [SWS_CORE_00836]。

该类通过复制构造函数 [SWS_CORE_00825]、复制赋值运算符 [SWS_CORE_00841]、移动构造函数 [SWS_CORE_00826] 和移动赋值运算符 [SWS_CORE_00842] 拥有完整的值语义和移动语义。现有实例可以通过改变状态进行覆盖：EmplaceValue() 将实例置于具有 void 值的状态 [SWS_CORE_00843]，而 EmplaceError() 就地构造一个错误 [SWS_CORE_00844]。通过 Swap() 可以交换两个实例 [SWS_CORE_00845]。

如果满足 std::is_trivially_destructible<E>::value，则析构函数 ~Result() 是平凡的 [SWS_CORE_00827]。关于并发性，非修改性访问（如 HasValue() [SWS_CORE_00851] 以及左值错误访问 Error() const & [SWS_CORE_00857]）是线程安全的。修改性调用（如 EmplaceValue() [SWS_CORE_00843]、EmplaceError() [SWS_CORE_00844]、Swap() [SWS_CORE_00845] 以及移动操作 [SWS_CORE_00826]、[SWS_CORE_00835]、[SWS_CORE_00842]）显式地非线程安全。

使用路径

典型的使用流程分为服务提供方生成返回值、调用方进行检查以及条件后续处理：

  1. 生成结果：函数成功完成操作并通过 Result::FromValue() [SWS_CORE_00831] 或默认构造函数 [SWS_CORE_00821] 生成返回对象。若操作失败，则通过 Result::FromError(...) [SWS_CORE_00834] 返回结果。
  2. 状态检查：调用方通过 HasValue() [SWS_CORE_00851] 或布尔转换 operator bool() [SWS_CORE_00852] 来评估是否存在成功，它们在成功时返回 true，在发生错误时返回 false。具体的错误值可以直接与 CheckError() 进行比对 [SWS_CORE_00865]。
  3. Monad 式链接：在结果成功时，可通过 Bind() 调用后续函数 [SWS_CORE_00870]。传入的可调用函数仅在实例包含 void 值时才会被执行；如果存在错误，则不会调用该函数，并将现有的错误内容复制到新的结果对象中 [SWS_CORE_00870]。
  4. 错误查询与解决：方法 Resolve() 在成功情况下不执行任何操作，但在发生错误时会使用 const E& 调用传入的可调用函数 [SWS_CORE_00867]。此外，包含的错误还可以通过 Err() 作为 ara::core::Optional<E> 进行查询 [SWS_CORE_00868]、[SWS_CORE_00869]，或者通过 ErrorOr() 使用后备错误进行保护 [SWS_CORE_00863]、[SWS_CORE_00864]。

时序图：通过 Bind() 或 Error() 进行调用、状态检查和分支处理的典型流程。来源：[SWS_CORE_00831]、[SWS_CORE_00834]、[SWS_CORE_00851]、[SWS_CORE_00857]、[SWS_CORE_00870]。

错误场景

在访问 ara::core::Result<void, E> 的实例时，适用严格的前置条件以避免运行时违规：

  • 访问缺失的值（ResultWithNoValueViolation）：方法 Value() [SWS_CORE_00855] 和 operator*() [SWS_CORE_00853] 是为了泛型编程而存在的，并返回 void。如果实例不包含值（即存储了错误），则调用这两个函数都会触发 ResultWithNoValueViolation [SWS_CORE_00853]、[SWS_CORE_00855]。函数 ValueOr() 在泛型上不执行任何操作，且不会引发违规 [SWS_CORE_00861]。
  • 访问缺失的错误（ResultWithNoErrorViolation）：通过 Error() 的重载 [SWS_CORE_00857]、[SWS_CORE_00858]、[SWS_CORE_00876] 直接访问错误对象的前提是实例包含错误。如果相反存在 void 值，则会导致 ResultWithNoErrorViolation。
  • 通过 ValueOrThrow 引发异常：如果不存在值，ValueOrThrow() 会抛出与所包含错误关联的异常 [SWS_CORE_00866]。如果在编译器工具链中禁用了 C++ 异常，则此函数不参与重载决议 [SWS_CORE_00866]。
  • 函数对象的异常安全性：操作 Bind() [SWS_CORE_00870] 和 Resolve() [SWS_CORE_00867] 被指定为非异常安全；它们的线程安全性条件性地取决于所传入的对应 Callable 的线程安全性。

<h4>上下文</h4>
<p>模板类特化 <code>ara::core::Result&lt;void, E&gt;</code> 表示在成功执行时不返回有效负载数据值、而仅指示成功或发生错误的操作结果。在 AUTOSAR Adaptive Platform 内，它用作具有 void 语义的函数的标准化返回类型，并支持无 C++ 异常的结构化错误处理。值类型通过类型别名固定指定为 <code>value_type = void</code> <a class="spec-record-ref" data-req="SWS_CORE_00811" href="../spec/record.html?id=SWS_CORE_00811">[SWS_CORE_00811]</a>，而错误类型通过类型别名 <code>error_type = E</code> <a class="spec-record-ref" data-req="SWS_CORE_00812" href="../spec/record.html?id=SWS_CORE_00812">[SWS_CORE_00812]</a> 进行参数化。该实现强制在编译时使包含 <code>E != ara::core::ErrorCode</code> 的条件导致编译错误。</p>
<p>作为标准化结果类型，该类构成了调用方应用程序组件与执行方平台服务或应用程序服务之间的接口。它确保无返回值操作采用与 <code>ara::core::Result</code> 的带值特化相同的统一接口理念和函数式后续处理。</p>

<h4>生命周期</h4>
<p><code>ara::core::Result&lt;void, E&gt;</code> 的实例在任何时刻都恰好处于两种不同状态之一：它要么表示成功流程（具有 void 值的状态），要么表示包含类型为 <code>E</code> 的错误对象的错误状态。</p>
<p>成功实例的创建通过无参默认构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> 或静态工厂方法 <code>FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> 进行。错误状态则在构造时通过传入作为左值 <a class="spec-record-ref" data-req="SWS_CORE_00823" href="../spec/record.html?id=SWS_CORE_00823">[SWS_CORE_00823]</a> 或右值 <a class="spec-record-ref" data-req="SWS_CORE_00824" href="../spec/record.html?id=SWS_CORE_00824">[SWS_CORE_00824]</a> 的错误对象来建立。此外，静态方法 <code>FromError()</code> 提供了通过复制 <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a>、通过移动 <a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a> 或就地从参数创建错误 <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a> 的工厂。后一种重载通过 SFINAE 进行约束，并且仅当 <code>E</code> 可从参数构造且第一个参数既非 <code>E</code> 也非 <code>Result</code> 的特化时才参与重载决议 <a class="spec-record-ref" data-req="SWS_CORE_00836" href="../spec/record.html?id=SWS_CORE_00836">[SWS_CORE_00836]</a>。</p>
<p>该类通过复制构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00825" href="../spec/record.html?id=SWS_CORE_00825">[SWS_CORE_00825]</a>、复制赋值运算符 <a class="spec-record-ref" data-req="SWS_CORE_00841" href="../spec/record.html?id=SWS_CORE_00841">[SWS_CORE_00841]</a>、移动构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a> 拥有完整的值语义和移动语义。现有实例可以通过改变状态进行覆盖：<code>EmplaceValue()</code> 将实例置于具有 void 值的状态 <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>，而 <code>EmplaceError()</code> 就地构造一个错误 <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>。通过 <code>Swap()</code> 可以交换两个实例 <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a>。</p>
<p>如果满足 <code>std::is_trivially_destructible&lt;E&gt;::value</code>，则析构函数 <code>~Result()</code> 是平凡的 <a class="spec-record-ref" data-req="SWS_CORE_00827" href="../spec/record.html?id=SWS_CORE_00827">[SWS_CORE_00827]</a>。关于并发性，非修改性访问（如 <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> 以及左值错误访问 <code>Error() const &amp;</code> <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a>）是线程安全的。修改性调用（如 <code>EmplaceValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00843" href="../spec/record.html?id=SWS_CORE_00843">[SWS_CORE_00843]</a>、<code>EmplaceError()</code> <a class="spec-record-ref" data-req="SWS_CORE_00844" href="../spec/record.html?id=SWS_CORE_00844">[SWS_CORE_00844]</a>、<code>Swap()</code> <a class="spec-record-ref" data-req="SWS_CORE_00845" href="../spec/record.html?id=SWS_CORE_00845">[SWS_CORE_00845]</a> 以及移动操作 <a class="spec-record-ref" data-req="SWS_CORE_00826" href="../spec/record.html?id=SWS_CORE_00826">[SWS_CORE_00826]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00835" href="../spec/record.html?id=SWS_CORE_00835">[SWS_CORE_00835]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00842" href="../spec/record.html?id=SWS_CORE_00842">[SWS_CORE_00842]</a>）显式地非线程安全。</p>

<h4>使用路径</h4>
<p>典型的使用流程分为服务提供方生成返回值、调用方进行检查以及条件后续处理：</p>
<ol>
<li><strong>生成结果：</strong>函数成功完成操作并通过 <code>Result::FromValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00831" href="../spec/record.html?id=SWS_CORE_00831">[SWS_CORE_00831]</a> 或默认构造函数 <a class="spec-record-ref" data-req="SWS_CORE_00821" href="../spec/record.html?id=SWS_CORE_00821">[SWS_CORE_00821]</a> 生成返回对象。若操作失败，则通过 <code>Result::FromError(...)</code> <a class="spec-record-ref" data-req="SWS_CORE_00834" href="../spec/record.html?id=SWS_CORE_00834">[SWS_CORE_00834]</a> 返回结果。</li>
<li><strong>状态检查：</strong>调用方通过 <code>HasValue()</code> <a class="spec-record-ref" data-req="SWS_CORE_00851" href="../spec/record.html?id=SWS_CORE_00851">[SWS_CORE_00851]</a> 或布尔转换 <code>operator bool()</code> <a class="spec-record-ref" data-req="SWS_CORE_00852" href="../spec/record.html?id=SWS_CORE_00852">[SWS_CORE_00852]</a> 来评估是否存在成功，它们在成功时返回 <code>true</code>，在发生错误时返回 <code>false</code>。具体的错误值可以直接与 <code>CheckError()</code> 进行比对 <a class="spec-record-ref" data-req="SWS_CORE_00865" href="../spec/record.html?id=SWS_CORE_00865">[SWS_CORE_00865]</a>。</li>
<li><strong>Monad 式链接：</strong>在结果成功时，可通过 <code>Bind()</code> 调用后续函数 <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>。传入的可调用函数仅在实例包含 void 值时才会被执行；如果存在错误，则不会调用该函数，并将现有的错误内容复制到新的结果对象中 <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a>。</li>
<li><strong>错误查询与解决：</strong>方法 <code>Resolve()</code> 在成功情况下不执行任何操作，但在发生错误时会使用 <code>const E&amp;</code> 调用传入的可调用函数 <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a>。此外，包含的错误还可以通过 <code>Err()</code> 作为 <code>ara::core::Optional&lt;E&gt;</code> 进行查询 <a class="spec-record-ref" data-req="SWS_CORE_00868" href="../spec/record.html?id=SWS_CORE_00868">[SWS_CORE_00868]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00869" href="../spec/record.html?id=SWS_CORE_00869">[SWS_CORE_00869]</a>，或者通过 <code>ErrorOr()</code> 使用后备错误进行保护 <a class="spec-record-ref" data-req="SWS_CORE_00863" href="../spec/record.html?id=SWS_CORE_00863">[SWS_CORE_00863]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00864" href="../spec/record.html?id=SWS_CORE_00864">[SWS_CORE_00864]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>在访问 <code>ara::core::Result&lt;void, E&gt;</code> 的实例时，适用严格的前置条件以避免运行时违规：</p>
<ul>
<li><strong>访问缺失的值（ResultWithNoValueViolation）：</strong>方法 <code>Value()</code> <a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a> 和 <code>operator*()</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a> 是为了泛型编程而存在的，并返回 <code>void</code>。如果实例不包含值（即存储了错误），则调用这两个函数都会触发 <code>ResultWithNoValueViolation</code> <a class="spec-record-ref" data-req="SWS_CORE_00853" href="../spec/record.html?id=SWS_CORE_00853">[SWS_CORE_00853]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00855" href="../spec/record.html?id=SWS_CORE_00855">[SWS_CORE_00855]</a>。函数 <code>ValueOr()</code> 在泛型上不执行任何操作，且不会引发违规 <a class="spec-record-ref" data-req="SWS_CORE_00861" href="../spec/record.html?id=SWS_CORE_00861">[SWS_CORE_00861]</a>。</li>
<li><strong>访问缺失的错误（ResultWithNoErrorViolation）：</strong>通过 <code>Error()</code> 的重载 <a class="spec-record-ref" data-req="SWS_CORE_00857" href="../spec/record.html?id=SWS_CORE_00857">[SWS_CORE_00857]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00858" href="../spec/record.html?id=SWS_CORE_00858">[SWS_CORE_00858]</a>、<a class="spec-record-ref" data-req="SWS_CORE_00876" href="../spec/record.html?id=SWS_CORE_00876">[SWS_CORE_00876]</a> 直接访问错误对象的前提是实例包含错误。如果相反存在 void 值，则会导致 <code>ResultWithNoErrorViolation</code>。</li>
<li><strong>通过 ValueOrThrow 引发异常：</strong>如果不存在值，<code>ValueOrThrow()</code> 会抛出与所包含错误关联的异常 <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>。如果在编译器工具链中禁用了 C++ 异常，则此函数不参与重载决议 <a class="spec-record-ref" data-req="SWS_CORE_00866" href="../spec/record.html?id=SWS_CORE_00866">[SWS_CORE_00866]</a>。</li>
<li><strong>函数对象的异常安全性：</strong>操作 <code>Bind()</code> <a class="spec-record-ref" data-req="SWS_CORE_00870" href="../spec/record.html?id=SWS_CORE_00870">[SWS_CORE_00870]</a> 和 <code>Resolve()</code> <a class="spec-record-ref" data-req="SWS_CORE_00867" href="../spec/record.html?id=SWS_CORE_00867">[SWS_CORE_00867]</a> 被指定为非异常安全；它们的线程安全性条件性地取决于所传入的对应 Callable 的线程安全性。</li>
</ul>
