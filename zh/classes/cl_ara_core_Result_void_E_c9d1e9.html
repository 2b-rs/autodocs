类 ara::core::Result<void, E> 为无返回值的操作特化了 Result 模式，并映射成功完成或错误（[SWS_CORE_00811]）。执行后，调用方通过 HasValue()（[SWS_CORE_00851]）或 operator bool() 检查成功状态，并在出错时访问所包含的错误原因。作为具有约束力的边界条件，错误类型 E 必须与类型 ara::core::ErrorCode 匹配，因为不同的类型在编译期就会被拒绝。

上下文

模板类 ara::core::Result<void, E> 代表了 Result 模式的部分特化，用于在成功时不传递返回值（void），而仅指示操作成功或失败的情况。根据类型定义，值类型 value_type 始终固定为 void（[SWS_CORE_00811]），而 error_type 表示参数化的错误类型 E（[SWS_CORE_00812]）。对于类型 E，其功能规范要求任何与 ara::core::ErrorCode 的偏离都必须被实现作为编译错误予以拒绝。

在 AUTOSAR Adaptive Platform 中，ara::core::Result<void, E> 用作调用组件与执行接口之间易出错过程和控制命令的标准化返回类型。该类代替了传统的 C++ 异常处理，提供了一种资源节约型、显式的错误传递方式，既支持直接状态查询，又支持调用路径中的函数式链式调用。

生命周期

ara::core::Result<void, E> 的实例在其整个生命周期中恰好处于两个离散状态之一：值状态（成功）或错误状态。使用 void 值的初始化通过默认构造函数 Result()（[SWS_CORE_00821]）或静态工厂方法 FromValue()（[SWS_CORE_00831]）完成。对于错误状态下的创建，提供了针对错误类型 E 的左值和右值的显式构造函数（[SWS_CORE_00823]、[SWS_CORE_00824]）。此外，工厂函数 FromError() 允许从错误左值（[SWS_CORE_00834]）、右值（[SWS_CORE_00835]）或通过参数包直接就地构造（[SWS_CORE_00836]）。

现有实例随后可以通过 EmplaceValue() 置于值状态（[SWS_CORE_00843]），或通过 EmplaceError() 直接赋予新错误（[SWS_CORE_00844]）。拷贝和移动构造函数（[SWS_CORE_00825]、[SWS_CORE_00826]）以及相应的赋值运算符（[SWS_CORE_00841]、[SWS_CORE_00842]）在实例之间传递状态；Swap() 交换两个对象的内容（[SWS_CORE_00845]）。

析构函数 ~Result() 终止生命周期（[SWS_CORE_00827]），并在 std::is_trivially_destructible<E>::value 成立时是平凡的。关于并发性，纯读取操作是线程安全的，而状态改变操作（如 EmplaceValue()、EmplaceError()、赋值或 Swap()）不是线程安全的。

使用路径

常规流程始于从函数调用中接收 ara::core::Result<void, E> 实例。调用方通过 HasValue()（[SWS_CORE_00851]）或转换 operator bool()（[SWS_CORE_00852]）对结果进行评估。执行成功时，可以通过 Bind()（[SWS_CORE_00870]）函数式地附加后续操作：Bind() 仅在实例包含值时才执行传入的可调用对象，并返回其转换后的结果。如果相反存在错误，则跳过被调用的函数，并将错误内容接纳到新结果中。

为了在通用代码中实现统一，该特化提供了形式上与常规 Result 类相对应的接口：Value()（[SWS_CORE_00855]）、operator*()（[SWS_CORE_00853]）和 ValueOr()（[SWS_CORE_00861]）不返回任何值并充当空操作（No-Op）方法。与此类似，Resolve()（[SWS_CORE_00867]）仅在存在错误时执行传入的可调用对象，而在成功情况下保持非活动状态。

错误场景

若实例处于错误状态，则可以通过 Error() 的重载作为引用查询所包含的错误（[SWS_CORE_00857]、[SWS_CORE_00858]、[SWS_CORE_00876]）。此时适用严格的前置条件：在不包含错误的实例上调用 Error() 构成 ResultWithNoErrorViolation。反之，在处于错误状态的实例上调用 Value()（[SWS_CORE_00855]）或 operator*()（[SWS_CORE_00853]）会触发 ResultWithNoValueViolation。

为了避免前置条件违规，提供了备选查询方法：Err() 返回打包在 ara::core::Optional<E> 中的错误，该容器在成功情况下保持为空（[SWS_CORE_00868]、[SWS_CORE_00869]）。通过 ErrorOr() 可以指定一个默认错误，若未包含错误则返回该默认错误（[SWS_CORE_00863]、[SWS_CORE_00864]）。对于针对特定错误值的检查，CheckError() 将内部错误与比较值进行比对（[SWS_CORE_00865]）。

如果首选基于异常的错误处理，ValueOrThrow()（[SWS_CORE_00866]）在出错时抛出与该错误关联的异常；若存在值，则调用正常返回。若工具链中禁用了 C++ 异常，则 ValueOrThrow() 不参与重载解析（[SWS_CORE_00866]）。

用法与调用上下文

来自 ara/core/result.h 的特化 ara::core::Result<void, E> 的成员函数 Bind 在没有结果值的成功实例上执行后续计算 [SWS_CORE_00870]。如果存在值，则同步且无参数地调用传入的 Callable f。该 Callable 必须满足接口 Result<XXX, E> f() 或 XXX f()，其中 XXX 必须是 Result 允许的类型 [SWS_CORE_00870]。如果 Callable 返回 Result，则返回类型对应于 decltype(f())；如果它直接返回 XXX，则结果将被封装为 Result<decltype(f()), E> [SWS_CORE_00870]。

错误处理与并发

如果实例不包含值，则返回一个新的 Result<XXX, E>，原始错误会被复制到其中 [SWS_CORE_00870]。理解：在这种情况下，推测不应执行 Callable f。关于执行安全性，该函数被视为 not exception safe [SWS_CORE_00870]。线程安全性是有条件的（conditional），完全取决于传入的 Callable f 的线程安全性 [SWS_CORE_00870]。

与相关要求的交互

与来自 [SWS_CORE_00768] 和 [SWS_CORE_00941] 的主 Result<T, E> 函数不同（在那些函数中，Callable 通过 f(const T&) 接收实例的值），本重载 [SWS_CORE_00870] 将操作绑定到 void 结果，因此需要一个无参 Callable。
