使用目的

SovdAuthorization 实现应用层的 SOVD 授权。GetAuthorizationUrl() 和 GetTokenUrl() 分别提供授权和 Token 请求的 URL；DM 随后以 HTTP 307 和含此 URL 的 Location header 作出响应。[SWS_DM_01485] [SWS_DM_01484] [SWS_DM_01472] [SWS_DM_01471] ValidateAuthorization() 验证 HTTP-Authorization header 中的 Token，并在传递的 ClientAuthentication 中标记已授权角色。[SWS_DM_01483] [SWS_DM_01470]

生成和生命周期

构造函数将 PortPrototype 绑定到 DiagnosticSovdAuthorizationInterface 并接受 ConcurrencyType。 [SWS_DM_01489] Offer() 激活转发，StopOffer() 再次停用转发。优惠可送kAlreadyOffered或kConfigurationMismatch。 [SWS_DM_01487] [SWS_DM_01486] 析构函数是异常安全的。 [SWS_DM_01488]

限制&错误处理

部署 future 后，应用程序不再允许使用引用的 ClientAuthentication 对象。 [SWS_DM_01483] 成功的返回值允许 DM 对于已验证的相同令牌处理最多 validUntil 的卷。 [SWS_DM_01469] 验证可以报告kInvalidAccessToken或kTemporarilyNotAvailable。 [SWS_DM_01483]URL，验证操作依赖于ConcurrencyType； Offer和StopOffer不是thread-safe。 [SWS_DM_01485][SWS_DM_01484][SWS_DM_01483][SWS_DM_01487][SWS_DM_01486]

如果令牌与之前验证的仍然有效的令牌不同，则 DM 会重新验证授权。 [SWS_DM_01470] 如果到validUntil 为止令牌相同且返回的身份相同，则可以将客户端视为相同。 [SWS_DM_01781] [SWS_DM_01782] URL 方法接收请求查询参数和MetaInfo，并各自异步返回一个字符串。 [SWS_DM_01484][SWS_DM_01485]

SOVD访问上下文

SOVD 授权在请求标头中使用 OAuth 令牌。在这样的请求中，Diagnostic Manager使用SovdAuthorization向应用程序请求编码的授权角色；根据这个角色，它决定所请求的SOVD操作是否被授权。 EXP SOVD §3.2.1 “Access Permissions”

函数 ValidateAuthorization [SWS_DM_01483] Upstream: RS_Diag_04268

virtual ara::core::Future< ValidateAuthorizationOutput > Validate Authorization (ara::core::StringView token, const MetaInfo &metaInfo, ClientAuthentication &clientAuthentication) noexcept=0;

This function validates the authorization token sent by the SOVD client. The application shall validate the authorization token according to the authorization protocol used in the system and then according to the outcome set the respective roles as authorized in the clientAuthentication that is passed as parameter. If OAuth 2.0 is used, this would implement the validation that is supposed to happen in the Resource Server.

使用量AI 生成 / AI generated

源自此 AUTOSAR R25-11 规范元素的自动生成的使用通知 — 非官方 AUTOSAR 文本。文档：[SWS_…]。

虚方法 ValidateAuthorization 根据系统中使用的授权协议，验证 SOVD 客户端通过 HTTP Authorization Header 发送的 Token（token）；对于 OAuth 2.0，这等同于 Resource Server 的验证。根据结果，应用程序会将通过参数 clientAuthentication 传递的对象中的相应角色设置为已授权 [SWS_DM_01483]。此外，还会传递诊断端口的 metaInfo。返回的 ara::core::Future<ValidateAuthorizationOutput> 在成功时提供验证结果，否则提供错误。
