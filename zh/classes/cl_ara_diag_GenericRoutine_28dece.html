上下文

类 ara::diag::GenericRoutine 在 AUTOSAR Adaptive Platform 的诊断模块 (ara::diag) 中提供了用于处理诊断例程的通用接口。它在应用层封装了围绕 UDS 服务 RoutineControl (ISO 14229-1 Service 0x31) 的交互。与特定类型生成的例程接口不同，GenericRoutine 将请求数据作为字节跨度进行通用处理，因此相同的实现可以灵活地用于不同的例程标识符 (routineId)。

核心交互协作方是 AUTOSAR 运行时环境的 Diagnostic Management (DM) 和特定于应用程序的诊断逻辑。Diagnostic Management 接收外部测试仪的诊断请求，并在该实例通过 ara::core::InstanceSpecifier 绑定到类型为 DiagnosticRoutineGenericInterface 的已建模 PortPrototype 并被激活后，将传入的 RoutineControl 请求转发给该实例 [SWS_DM_00552]、[SWS_DM_00557]。应用软件从 GenericRoutine 派生出自己的处理程序类，并在车载控制器中实现特定于应用程序的执行逻辑。

生命周期

GenericRoutine 实例的生命周期包括创建、服务提供、请求处理、注销和销毁阶段。

通过构造函数 GenericRoutine(const ara::core::InstanceSpecifier &specifier, ConcurrencyType concurrencyType) 创建时，该对象绑定到模型中定义的端口 [SWS_DM_00552]。参数 concurrencyType 强制确定该接口是实现为线程安全 (kConcurrent) 还是非线程安全 (kNotConcurrent)，这决定了 DM 是否可以并发调用回调方法 [SWS_DM_00552]。

关于所有权关系，GenericRoutine 被设计为严格的单实例：复制和移动构造函数以及赋值运算符均已被删除 (=delete) [SWS_DM_01635]、[SWS_DM_01636]、[SWS_DM_01637]、[SWS_DM_01638]。因此，实例始终保留在其创建位置。

实例化后，对象处于 已实例化 状态。此时 DM 尚不转发任何消息。只有通过同步调用 Offer()，转发才会被激活，并且实例转换为 已提供 状态 [SWS_DM_00557]。通过 StopOffer()，可以随时再次停用 DM 对请求的转发 [SWS_DM_00558]。

销毁通过虚析构函数 ~GenericRoutine() [SWS_DM_00553] 进行。方法 Offer()、StopOffer() 以及析构函数是非线程安全的；因此生命周期转换必须在应用程序代码中同步执行 [SWS_DM_00553]、[SWS_DM_00557]、[SWS_DM_00558]。

使用路径

GenericRoutine 的典型用法包括以下步骤：

  1. 实例化与注册：应用程序在指定 InstanceSpecifier 和 ConcurrencyType [SWS_DM_00552] 的情况下创建派生子类的实例。随后通过 Offer() 启用接收 [SWS_DM_00557]。
  2. 例程启动 (SubFunction 0x01)：如果 DM 接收到子功能为 Start 的 RoutineControl 请求，则会调用纯虚方法 Start()[SWS_DM_00554]。此时将传递 routineId、作为 ara::core::Span<const std::uint8_t> 的原始数据 requestData、上下文 metaInfo 以及 CancellationHandler[SWS_DM_00554]。requestData 中的数据在产生的 Promise 被解决或处理被中止之前保持有效 [SWS_DM_00554]。
  3. 异步处理：该方法立即向 DM 返回一个 ara::core::Future<OperationOutput> [SWS_DM_00554]。实际处理在应用逻辑中异步进行。完成后，关联的 Promise 将使用 OperationOutput 得到满足。
  4. 可选操作：根据例程的规范，测试仪可在执行期间或执行之后触发进一步的操作：
    • Stop() (SubFunction 0x02)：被调用以有针对性地停止正在运行的例程 [SWS_DM_00555]。
    • RequestResults() (SubFunction 0x03)：用于查询例程的中间结果或最终结果 [SWS_DM_00556]。
    这两种方法类似地返回一个 ara::core::Future<OperationOutput> [SWS_DM_00555]，[SWS_DM_00556]。
  5. 服务终止：在关闭之前，应用程序调用 StopOffer() 以终止 DM 的转发 [SWS_DM_00558]。

错误场景

错误可能在配置、服务注册以及执行期间发生：

  • 配置与实例化错误：如果在构造函数中绑定 InstanceSpecifier 失败，则会触发特定的运行时违规 [SWS_DM_00552]：
    • InstanceSpecifierMappingIntegrityViolation：该标识符在 Executable 的上下文中无法解析，或未指向 PortPrototype。
    • PortInterfaceMappingViolation：由 DiagnosticRoutineGenericInterface 定型的端口未分配给任何 DiagnosticServiceGenericMapping。
    • ProcessMappingViolation：对于现有的实例引用，运行时不存在匹配的建模进程。
    • InstanceSpecifierAlreadyInUseViolation：InstanceSpecifier 已在当前进程中被另一个实例使用。
  • 服务提供错误：如果在服务已处于活动提供状态时调用 Offer()，则调用失败并在 ara::core::Result<void> 中返回具有回滚语义的错误代码 DiagOfferErrc::kAlreadyOffered [SWS_DM_00557]。
  • 诊断否定响应 (UDS NRC)：如果例程执行期间发生错误，Future 将不会被 OperationOutput 满足。相反，必须在错误路径中通过 DiagUdsNrcErrc 返回符合 ISO 14229-1 的相应 Negative Response Code [SWS_DM_00554]，[SWS_DM_00555]，[SWS_DM_00556]。
  • 诊断会话中止：如果正在进行的请求被中止，应用程序可通过 cancellationHandler 对此进行处理 [SWS_DM_00554]：状态可通过 cancellationHandler.IsCanceled() 主动查询（中止时返回 TRUE），或者预先通过 cancellationHandler.SetNotifier() 注册一个通知回调，在中止时触发该回调 [SWS_DM_00554]。

<h4>上下文</h4>
<p>类 <code>ara::diag::GenericRoutine</code> 在 AUTOSAR Adaptive Platform 的诊断模块 (<code>ara::diag</code>) 中提供了用于处理诊断例程的通用接口。它在应用层封装了围绕 UDS 服务 <em>RoutineControl</em> (ISO 14229-1 Service 0x31) 的交互。与特定类型生成的例程接口不同，<code>GenericRoutine</code> 将请求数据作为字节跨度进行通用处理，因此相同的实现可以灵活地用于不同的例程标识符 (<code>routineId</code>)。</p>
<p>核心交互协作方是 AUTOSAR 运行时环境的 Diagnostic Management (DM) 和特定于应用程序的诊断逻辑。Diagnostic Management 接收外部测试仪的诊断请求，并在该实例通过 <code>ara::core::InstanceSpecifier</code> 绑定到类型为 <code>DiagnosticRoutineGenericInterface</code> 的已建模 PortPrototype 并被激活后，将传入的 RoutineControl 请求转发给该实例 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>、<a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>。应用软件从 <code>GenericRoutine</code> 派生出自己的处理程序类，并在车载控制器中实现特定于应用程序的执行逻辑。</p>

<h4>生命周期</h4>
<p><code>GenericRoutine</code> 实例的生命周期包括创建、服务提供、请求处理、注销和销毁阶段。</p>
<p>通过构造函数 <code>GenericRoutine(const ara::core::InstanceSpecifier &amp;specifier, ConcurrencyType concurrencyType)</code> 创建时，该对象绑定到模型中定义的端口 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>。参数 <code>concurrencyType</code> 强制确定该接口是实现为线程安全 (<code>kConcurrent</code>) 还是非线程安全 (<code>kNotConcurrent</code>)，这决定了 DM 是否可以并发调用回调方法 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>。</p>
<p>关于所有权关系，<code>GenericRoutine</code> 被设计为严格的单实例：复制和移动构造函数以及赋值运算符均已被删除 (<code>=delete</code>) <a class="spec-record-ref" data-req="SWS_DM_01635" href="../spec/record.html?id=SWS_DM_01635">[SWS_DM_01635]</a>、<a class="spec-record-ref" data-req="SWS_DM_01636" href="../spec/record.html?id=SWS_DM_01636">[SWS_DM_01636]</a>、<a class="spec-record-ref" data-req="SWS_DM_01637" href="../spec/record.html?id=SWS_DM_01637">[SWS_DM_01637]</a>、<a class="spec-record-ref" data-req="SWS_DM_01638" href="../spec/record.html?id=SWS_DM_01638">[SWS_DM_01638]</a>。因此，实例始终保留在其创建位置。</p>
<p>实例化后，对象处于 <em>已实例化</em> 状态。此时 DM 尚不转发任何消息。只有通过同步调用 <code>Offer()</code>，转发才会被激活，并且实例转换为 <em>已提供</em> 状态 <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>。通过 <code>StopOffer()</code>，可以随时再次停用 DM 对请求的转发 <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>。</p>

<h4>使用路径</h4>
<p><code>GenericRoutine</code> 的典型用法包括以下步骤：</p>
<ol>
  <li><strong>实例化与注册：</strong>应用程序在指定 <code>InstanceSpecifier</code> 和 <code>ConcurrencyType</code> <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a> 的情况下创建派生子类的实例。随后通过 <code>Offer()</code> 启用接收 <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>。</li>
  <li><strong>例程启动 (SubFunction 0x01)：</strong>如果 DM 接收到子功能为 <em>Start</em> 的 RoutineControl 请求，则会调用纯虚方法 <code>Start()</code><a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>。此时将传递 <code>routineId</code>、作为 <code>ara::core::Span&lt;const std::uint8_t&gt;</code> 的原始数据 <code>requestData</code>、上下文 <code>metaInfo</code> 以及 <code>CancellationHandler</code><a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>。<code>requestData</code> 中的数据在产生的 Promise 被解决或处理被中止之前保持有效 <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>。</li>
  <li><strong>异步处理：</strong>该方法立即向 DM 返回一个 <code>ara::core::Future&lt;OperationOutput&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>。实际处理在应用逻辑中异步进行。完成后，关联的 Promise 将使用 <code>OperationOutput</code> 得到满足。</li>
  <li><strong>可选操作：</strong>根据例程的规范，测试仪可在执行期间或执行之后触发进一步的操作：
    <ul>
      <li><code>Stop()</code> (SubFunction 0x02)：被调用以有针对性地停止正在运行的例程 <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>。</li>
      <li><code>RequestResults()</code> (SubFunction 0x03)：用于查询例程的中间结果或最终结果 <a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>。</li>
    </ul>
    这两种方法类似地返回一个 <code>ara::core::Future&lt;OperationOutput&gt;</code> <a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>，<a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>。</li>
  <li><strong>服务终止：</strong>在关闭之前，应用程序调用 <code>StopOffer()</code> 以终止 DM 的转发 <a class="spec-record-ref" data-req="SWS_DM_00558" href="../spec/record.html?id=SWS_DM_00558">[SWS_DM_00558]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>错误可能在配置、服务注册以及执行期间发生：</p>
<ul>
  <li><strong>配置与实例化错误：</strong>如果在构造函数中绑定 <code>InstanceSpecifier</code> 失败，则会触发特定的运行时违规 <a class="spec-record-ref" data-req="SWS_DM_00552" href="../spec/record.html?id=SWS_DM_00552">[SWS_DM_00552]</a>：
    <ul>
      <li><code>InstanceSpecifierMappingIntegrityViolation</code>：该标识符在 Executable 的上下文中无法解析，或未指向 <code>PortPrototype</code>。</li>
      <li><code>PortInterfaceMappingViolation</code>：由 <code>DiagnosticRoutineGenericInterface</code> 定型的端口未分配给任何 <code>DiagnosticServiceGenericMapping</code>。</li>
      <li><code>ProcessMappingViolation</code>：对于现有的实例引用，运行时不存在匹配的建模进程。</li>
      <li><code>InstanceSpecifierAlreadyInUseViolation</code>：<code>InstanceSpecifier</code> 已在当前进程中被另一个实例使用。</li>
    </ul>
  </li>
  <li><strong>服务提供错误：</strong>如果在服务已处于活动提供状态时调用 <code>Offer()</code>，则调用失败并在 <code>ara::core::Result&lt;void&gt;</code> 中返回具有回滚语义的错误代码 <code>DiagOfferErrc::kAlreadyOffered</code> <a class="spec-record-ref" data-req="SWS_DM_00557" href="../spec/record.html?id=SWS_DM_00557">[SWS_DM_00557]</a>。</li>
  <li><strong>诊断否定响应 (UDS NRC)：</strong>如果例程执行期间发生错误，Future 将不会被 <code>OperationOutput</code> 满足。相反，必须在错误路径中通过 <code>DiagUdsNrcErrc</code> 返回符合 ISO 14229-1 的相应 Negative Response Code <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>，<a class="spec-record-ref" data-req="SWS_DM_00555" href="../spec/record.html?id=SWS_DM_00555">[SWS_DM_00555]</a>，<a class="spec-record-ref" data-req="SWS_DM_00556" href="../spec/record.html?id=SWS_DM_00556">[SWS_DM_00556]</a>。</li>
  <li><strong>诊断会话中止：</strong>如果正在进行的请求被中止，应用程序可通过 <code>cancellationHandler</code> 对此进行处理 <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>：状态可通过 <code>cancellationHandler.IsCanceled()</code> 主动查询（中止时返回 <code>TRUE</code>），或者预先通过 <code>cancellationHandler.SetNotifier()</code> 注册一个通知回调，在中止时触发该回调 <a class="spec-record-ref" data-req="SWS_DM_00554" href="../spec/record.html?id=SWS_DM_00554">[SWS_DM_00554]</a>。</li>
</ul>
