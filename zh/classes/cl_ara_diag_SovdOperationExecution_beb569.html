上下文

在 AUTOSAR Adaptive 中，类 ara::diag::SovdOperationExecution 构成了用于控制和状态监控正在运行的 SOVD 操作执行（Service-Oriented Vehicle Diagnostics）[SWS_DM_02197] 的接口。它充当中央诊断服务器（Diagnostic Management，DM）与诊断操作的应用特定实现之间的纽带。

在整个系统中，有三个主要伙伴相互交互：

  • SOVD-Client：根据 ASAM SOVD 或 ISO 17978-3 通过 SOVD 协议发起诊断方法（例如启动、查询执行状态或终止操作）[SWS_DM_01392]、[SWS_DM_01396]。
  • Diagnostic Management (DM)：处理传入的 SOVD 请求，执行前置的安全与邻近性检查，并根据唯一的 execution-id 将操作转发给 SovdOperationExecution 的关联实例 [SWS_DM_02179]、[SWS_DM_02180]。
  • Adaptive 应用程序（子类）：实现纯虚方法，以提供车辆中的实际执行逻辑、报告状态变更并处理诸如冻结或重置之类的控制命令。

上下文图：SovdOperationExecution 在 SOVD-Client、Diagnostic Management 与应用程序相互协作中的定位。来源：[SWS_DM_02179]、[SWS_DM_02180]、[SWS_DM_02197]。

生命周期

类 SovdOperationExecution 被设计为抽象基接口。其默认构造函数是受保护的（protected），并定义为 noexcept=default [SWS_DM_02198]。虚析构函数是公开的，且同样被声明为 noexcept=default [SWS_DM_02199]。一旦启动 SOVD 操作，具体实例推测会由 Adaptive 应用程序创建，并在执行期间始终分配给指定的 execution-id [SWS_DM_02180]。正如 AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.6 “Operations – Terminate execution of an operation” 中所指出的，诊断操作通常在同一时刻仅允许一个活动实例。

在并发和资源管理方面存在严格的规范：

  • 线程安全性：所有功能方法（ExecuteCapability、GetStatus、Terminate）均被指定为异常安全（exception safe）和线程安全（thread-safe）。它们各自返回一个 ara::core::Future，从而支持应用程序进行并发和异步处理。
  • 内容数据的有效性：传递给 ExecuteCapability 的数据对象 DiagnosticSovdContentData 保持有效，直至相关的 Promise 被履行或处理被取消 [SWS_DM_02384]。
  • 取消处理程序的生命周期：传入的 ara::diag::CancellationHandler 绝不得在相应方法调用的生命周期之外被存储或引用 [SWS_DM_02201]、[SWS_DM_02202]、[SWS_DM_02384]。

使用路径

SOVD 操作执行的典型流程包括提供状态、执行期间可选的能力调用以及最终的终止：

  1. 状态查询：当 DM 收到 Read the Status of an operation 方法的 SOVD 请求时，DM 根据 execution-id 确定该实例并调用 SovdOperationExecution::GetStatus [SWS_DM_02180]、[SWS_DM_02201]。在成功返回 GetStatusResponse 后，DM 会使用状态值、属性 capability=execute 以及来自 DiagnosticSovdContentData 的参数生成 SOVD 响应 [SWS_DM_02181]。
  2. 执行 Capabilities：为了有针对性地控制子能力（例如 execute、freeze 或 reset），DM 会调用方法 ExecuteCapability [SWS_DM_02384]。应用程序处理该命令并通过 Future 返回一个 OperationExecutionStatus。
  3. 终止：当 DM 收到 SOVD 方法 Terminate execution of an Operation [SWS_DM_01392] 时，它会调用 SovdOperationExecution::Terminate 并附带原因 TerminateOperationExecutionReason [SWS_DM_02179]、[SWS_DM_02202]。终止 Future（ara::core::Future<void>）结束本次执行。

顺序图：用于状态查询、Capability 执行及 SOVD 操作终止的典型调用顺序。来源：[SWS_DM_02180]、[SWS_DM_02181]、[SWS_DM_02201]、[SWS_DM_02202]、[SWS_DM_02384]。

错误场景

操作执行期间的错误通过异步返回值及先前的协议检查进行处理：

  • SOVD 错误码：若对 ExecuteCapability、GetStatus 或 Terminate 的调用失败，应用程序通过返回的 Future 并使用符合 ISO 17978-3 或 ASAM SOVD 1.1 的适用 SOVD 错误码发出信号 [SWS_DM_02201]、[SWS_DM_02202]、[SWS_DM_02384]。DM 随后向客户端拟定负面的 SOVD 响应。
  • Proximity 验证失败：若已配置，针对 Terminate 或 Read the Status of an operation 的传入客户端请求需要接受 Proximity Challenge（proximity_response）[SWS_DM_01391]、[SWS_DM_02179]、[SWS_DM_02180] 的验证。若该检查未成功，DM 将不会调用 SovdOperationExecution 的方法。
  • 通过 CancellationHandler 处理取消：若 DM 中止正在运行的过程，DM 会通过对象 ara::diag::CancellationHandler 发送信号。应用程序必须立即停止处理；所提供的内容数据（sovd_content_data）随着取消而失效 [SWS_DM_02384]。

<ul>
<li><strong>SOVD-Client：</strong>根据 ASAM SOVD 或 ISO 17978-3 通过 SOVD 协议发起诊断方法（例如启动、查询执行状态或终止操作）<a class="spec-record-ref" data-req="SWS_DM_01392" href="../spec/record.html?id=SWS_DM_01392">[SWS_DM_01392]</a>、<a class="spec-record-ref" data-req="SWS_DM_01396" href="../spec/record.html?id=SWS_DM_01396">[SWS_DM_01396]</a>。</li>
<li><strong>Diagnostic Management (DM)：</strong>处理传入的 SOVD 请求，执行前置的安全与邻近性检查，并根据唯一的 <code>execution-id</code> 将操作转发给 <code>SovdOperationExecution</code> 的关联实例 <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>、<a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>。</li>
<li><strong>Adaptive 应用程序（子类）：</strong>实现纯虚方法，以提供车辆中的实际执行逻辑、报告状态变更并处理诸如冻结或重置之类的控制命令。</li>
</ul>

<h4>生命周期</h4>
<p>类 <code>SovdOperationExecution</code> 被设计为抽象基接口。其默认构造函数是受保护的（<code>protected</code>），并定义为 <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_02198" href="../spec/record.html?id=SWS_DM_02198">[SWS_DM_02198]</a>。虚析构函数是公开的，且同样被声明为 <code>noexcept=default</code> <a class="spec-record-ref" data-req="SWS_DM_02199" href="../spec/record.html?id=SWS_DM_02199">[SWS_DM_02199]</a>。一旦启动 SOVD 操作，具体实例推测会由 Adaptive 应用程序创建，并在执行期间始终分配给指定的 <code>execution-id</code> <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>。正如 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=218">AUTOSAR_AP_SWS_Diagnostics §7.3.3.5.5.6 “Operations – Terminate execution of an operation”</a> 中所指出的，诊断操作通常在同一时刻仅允许一个活动实例。</p>
<p>在并发和资源管理方面存在严格的规范：</p>
<ul>
<li><strong>线程安全性：</strong>所有功能方法（<code>ExecuteCapability</code>、<code>GetStatus</code>、<code>Terminate</code>）均被指定为异常安全（<code>exception safe</code>）和线程安全（<code>thread-safe</code>）。它们各自返回一个 <code>ara::core::Future</code>，从而支持应用程序进行并发和异步处理。</li>
<li><strong>内容数据的有效性：</strong>传递给 <code>ExecuteCapability</code> 的数据对象 <code>DiagnosticSovdContentData</code> 保持有效，直至相关的 Promise 被履行或处理被取消 <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>。</li>
<li><strong>取消处理程序的生命周期：</strong>传入的 <code>ara::diag::CancellationHandler</code> 绝不得在相应方法调用的生命周期之外被存储或引用 <a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>、<a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>、<a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>。</li>
</ul>

<h4>使用路径</h4>
<p>SOVD 操作执行的典型流程包括提供状态、执行期间可选的能力调用以及最终的终止：</p>
<ol>
<li><strong>状态查询：</strong>当 DM 收到 <em>Read the Status of an operation</em> 方法的 SOVD 请求时，DM 根据 <code>execution-id</code> 确定该实例并调用 <code>SovdOperationExecution::GetStatus</code> <a class="spec-record-ref" data-req="SWS_DM_02180" href="../spec/record.html?id=SWS_DM_02180">[SWS_DM_02180]</a>、<a class="spec-record-ref" data-req="SWS_DM_02201" href="../spec/record.html?id=SWS_DM_02201">[SWS_DM_02201]</a>。在成功返回 <code>GetStatusResponse</code> 后，DM 会使用状态值、属性 <code>capability=execute</code> 以及来自 <code>DiagnosticSovdContentData</code> 的参数生成 SOVD 响应 <a class="spec-record-ref" data-req="SWS_DM_02181" href="../spec/record.html?id=SWS_DM_02181">[SWS_DM_02181]</a>。</li>
<li><strong>执行 Capabilities：</strong>为了有针对性地控制子能力（例如 <em>execute</em>、<em>freeze</em> 或 <em>reset</em>），DM 会调用方法 <code>ExecuteCapability</code> <a class="spec-record-ref" data-req="SWS_DM_02384" href="../spec/record.html?id=SWS_DM_02384">[SWS_DM_02384]</a>。应用程序处理该命令并通过 Future 返回一个 <code>OperationExecutionStatus</code>。</li>
<li><strong>终止：</strong>当 DM 收到 SOVD 方法 <em>Terminate execution of an Operation</em> <a class="spec-record-ref" data-req="SWS_DM_01392" href="../spec/record.html?id=SWS_DM_01392">[SWS_DM_01392]</a> 时，它会调用 <code>SovdOperationExecution::Terminate</code> 并附带原因 <code>TerminateOperationExecutionReason</code> <a class="spec-record-ref" data-req="SWS_DM_02179" href="../spec/record.html?id=SWS_DM_02179">[SWS_DM_02179]</a>、<a class="spec-record-ref" data-req="SWS_DM_02202" href="../spec/record.html?id=SWS_DM_02202">[SWS_DM_02202]</a>。终止 Future（<code>ara::core::Future&lt;void&gt;</code>）结束本次执行。</li>
</ol>

<h4>错误场景</h4>
