上下文

接口 ara::crypto::cryp::KeyEncapsulatorPublicCtx 表示 AUTOSAR Adaptive Platform 模块 crypto 内的公钥 KEM（Key Encapsulation Mechanism）上下文。其主要职责是，通过非对称封装机制准备用于安全传输或导出的对称密钥。在此过程中，既可以打包内存中已存在的对称密钥，也可以在运行时生成新的对称密钥并在同一步骤中进行封装。

该上下文的直接交互对象包括：

  • 调用方（应用程序）：控制配置、确定缓冲区大小并触发封装。
  • 封装公钥：既可以作为直接实例（PublicKey）引入，也可以通过密钥槽（KeySlot）间接引入。
  • 对称密钥（SymmetricKey）：用作封装现有密钥材料的输入，或者作为动态生成的结果返回。
  • 输出缓冲区（ReadWriteMemRegion）：接收封装密钥所生成的密文数据。

生命周期

该上下文作为长生命周期接口对象运行；对于生命周期和所有权管理，该类定义了智能指针别名 Sptr [SWS_CRYPT_21801]。推测该上下文的实例化可能通过加密栈的 Provider 或 Factory 组件进行。

创建后，该上下文处于未初始化状态。为了能够投入使用，必须为其分配封装密钥。这可以通过传递 PublicKey::Sptr [SWS_CRYPT_21815] 或分配 KeySlot::Sptr [SWS_CRYPT_50012] 来实现，后者的密钥会在执行封装时进行求值。成功配置后，该上下文即处于就绪状态，并可重复用于封装操作。所有方法均被规范为异常安全（exception safe）和线程安全（thread-safe）[SWS_CRYPT_21813]、[SWS_CRYPT_50011]、[SWS_CRYPT_50013]、[SWS_CRYPT_21815]、[SWS_CRYPT_50012]。如果操作期间发生错误，则通过定义的回滚语义确保上下文状态保持不变且一致。

使用路径

密钥封装的典型流程分为三个连续阶段：

  1. 配置：封装密钥通过 SetKey 注册，既可以作为直接公钥 [SWS_CRYPT_21815]，也可以通过密钥槽 [SWS_CRYPT_50012] 注册。
  2. 缓冲区大小确定：应用程序使用所需的 AlgId 调用 GetRequiredOutputBufferSize，以计算当前上下文状态下封装的最大字节大小 [SWS_CRYPT_50013]，并分配相应的 ReadWriteMemRegion 缓冲区。
  3. 封装：执行两个 Encapsulate 重载中的一个：
    • 封装现有密钥：传递现有的对称密钥 key 和缓冲区 encapsulatedKey；返回值是实际的封装大小（以字节为单位）[SWS_CRYPT_21813]。
    • 生成并封装新密钥：指定算法标识符 algId、使用标志 allowedUsage 和输出缓冲区；返回值是由封装大小和指向新生成的 SymmetricKey 的指针组成的对 [SWS_CRYPT_50011]。

时序图：用于配置和执行密钥封装的典型调用顺序。来源：[SWS_CRYPT_21815]、[SWS_CRYPT_50012]、[SWS_CRYPT_50013]、[SWS_CRYPT_21813]、[SWS_CRYPT_50011]

错误场景

各操作通过 ara::core::Result 类型的返回值指示错误情况。其中，尤其可能出现来自 ara::crypto::CryptoErrc 的以下错误码：

  • kUninitializedContext：在通过 SetKey 将上下文与密钥或槽关联之前调用 GetRequiredOutputBufferSize 或 Encapsulate 时发生 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]、[SWS_CRYPT_50013]。
  • kUsageViolation：指示使用权限不足。当封装密钥不具备 kAllowKeyWrapping 权限，或者在封装现有密钥时其使用规则禁止通过 kAllowSecuredExport 导出时发生 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]、[SWS_CRYPT_21815]。
  • kIncompatibleObject：传递的密钥对象或密钥槽与该特定 KEM 上下文不兼容 [SWS_CRYPT_21813]、[SWS_CRYPT_21815]、[SWS_CRYPT_50012]。
  • kInsufficientCapacity / kInvalidInputSize：传递的内存区域 encapsulatedKey 为密文提供的容量不足，或者要封装的密钥大小不被算法支持 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]。
  • kUnsupported：选定的操作模式不受具体上下文实现的支持——例如仅接受 KeySlot 而非 PublicKey [SWS_CRYPT_21815]、仅允许 PublicKey 而非 KeySlot [SWS_CRYPT_50012]，或者当上下文仅支持密钥生成或仅支持外部传递密钥的封装时 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]。
  • kEmptyKeySlot：先前通过 SetKey 注册的 KeySlot 在调用 Encapsulate 时为空 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]。
  • kUnknownIdentifier：传递给 Encapsulate 的算法标识符 algId 对系统而言未知或无效 [SWS_CRYPT_50011]。
  • kBusyResource：封装操作所需的加密资源或硬件资源当前被占用 [SWS_CRYPT_21813]、[SWS_CRYPT_50011]。

本指南基于针对 crypto 模块的 AUTOSAR Adaptive 规范 R25-11。

<h4>上下文</h4>
<p>接口 <code>ara::crypto::cryp::KeyEncapsulatorPublicCtx</code> 表示 AUTOSAR Adaptive Platform 模块 <code>crypto</code> 内的公钥 KEM（Key Encapsulation Mechanism）上下文。其主要职责是，通过非对称封装机制准备用于安全传输或导出的对称密钥。在此过程中，既可以打包内存中已存在的对称密钥，也可以在运行时生成新的对称密钥并在同一步骤中进行封装。</p>
<p>该上下文的直接交互对象包括：</p>
<ul>
<li><strong>调用方（应用程序）：</strong>控制配置、确定缓冲区大小并触发封装。</li>
<li><strong>封装公钥：</strong>既可以作为直接实例（<code>PublicKey</code>）引入，也可以通过密钥槽（<code>KeySlot</code>）间接引入。</li>
<li><strong>对称密钥（<code>SymmetricKey</code>）：</strong>用作封装现有密钥材料的输入，或者作为动态生成的结果返回。</li>
<li><strong>输出缓冲区（<code>ReadWriteMemRegion</code>）：</strong>接收封装密钥所生成的密文数据。</li>
</ul>

<h4>生命周期</h4>
<p>该上下文作为长生命周期接口对象运行；对于生命周期和所有权管理，该类定义了智能指针别名 <code>Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21801" href="../spec/record.html?id=SWS_CRYPT_21801">[SWS_CRYPT_21801]</a>。推测该上下文的实例化可能通过加密栈的 Provider 或 Factory 组件进行。</p>
<p>创建后，该上下文处于未初始化状态。为了能够投入使用，必须为其分配封装密钥。这可以通过传递 <code>PublicKey::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a> 或分配 <code>KeySlot::Sptr</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a> 来实现，后者的密钥会在执行封装时进行求值。成功配置后，该上下文即处于就绪状态，并可重复用于封装操作。所有方法均被规范为异常安全（<code>exception safe</code>）和线程安全（<code>thread-safe</code>）<a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>。如果操作期间发生错误，则通过定义的回滚语义确保上下文状态保持不变且一致。</p>

<h4>使用路径</h4>
<p>密钥封装的典型流程分为三个连续阶段：</p>
<ol>
<li><strong>配置：</strong>封装密钥通过 <code>SetKey</code> 注册，既可以作为直接公钥 <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>，也可以通过密钥槽 <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a> 注册。</li>
<li><strong>缓冲区大小确定：</strong>应用程序使用所需的 <code>AlgId</code> 调用 <code>GetRequiredOutputBufferSize</code>，以计算当前上下文状态下封装的最大字节大小 <a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>，并分配相应的 <code>ReadWriteMemRegion</code> 缓冲区。</li>
<li><strong>封装：</strong>执行两个 <code>Encapsulate</code> 重载中的一个：
<ul>
<li><em>封装现有密钥：</em>传递现有的对称密钥 <code>key</code> 和缓冲区 <code>encapsulatedKey</code>；返回值是实际的封装大小（以字节为单位）<a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>。</li>
<li><em>生成并封装新密钥：</em>指定算法标识符 <code>algId</code>、使用标志 <code>allowedUsage</code> 和输出缓冲区；返回值是由封装大小和指向新生成的 <code>SymmetricKey</code> 的指针组成的对 <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
</ul>
</li>
</ol>

<h4>错误场景</h4>
<p>各操作通过 <code>ara::core::Result</code> 类型的返回值指示错误情况。其中，尤其可能出现来自 <code>ara::crypto::CryptoErrc</code> 的以下错误码：</p>
<ul>
<li><code>kUninitializedContext</code>：在通过 <code>SetKey</code> 将上下文与密钥或槽关联之前调用 <code>GetRequiredOutputBufferSize</code> 或 <code>Encapsulate</code> 时发生 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50013" href="../spec/record.html?id=SWS_CRYPT_50013">[SWS_CRYPT_50013]</a>。</li>
<li><code>kUsageViolation</code>：指示使用权限不足。当封装密钥不具备 <code>kAllowKeyWrapping</code> 权限，或者在封装现有密钥时其使用规则禁止通过 <code>kAllowSecuredExport</code> 导出时发生 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>。</li>
<li><code>kIncompatibleObject</code>：传递的密钥对象或密钥槽与该特定 KEM 上下文不兼容 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>。</li>
<li><code>kInsufficientCapacity</code> / <code>kInvalidInputSize</code>：传递的内存区域 <code>encapsulatedKey</code> 为密文提供的容量不足，或者要封装的密钥大小不被算法支持 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
<li><code>kUnsupported</code>：选定的操作模式不受具体上下文实现的支持——例如仅接受 <code>KeySlot</code> 而非 <code>PublicKey</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21815" href="../spec/record.html?id=SWS_CRYPT_21815">[SWS_CRYPT_21815]</a>、仅允许 <code>PublicKey</code> 而非 <code>KeySlot</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50012" href="../spec/record.html?id=SWS_CRYPT_50012">[SWS_CRYPT_50012]</a>，或者当上下文仅支持密钥生成或仅支持外部传递密钥的封装时 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
<li><code>kEmptyKeySlot</code>：先前通过 <code>SetKey</code> 注册的 <code>KeySlot</code> 在调用 <code>Encapsulate</code> 时为空 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
<li><code>kUnknownIdentifier</code>：传递给 <code>Encapsulate</code> 的算法标识符 <code>algId</code> 对系统而言未知或无效 <a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
<li><code>kBusyResource</code>：封装操作所需的加密资源或硬件资源当前被占用 <a class="spec-record-ref" data-req="SWS_CRYPT_21813" href="../spec/record.html?id=SWS_CRYPT_21813">[SWS_CRYPT_21813]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50011" href="../spec/record.html?id=SWS_CRYPT_50011">[SWS_CRYPT_50011]</a>。</li>
</ul>
