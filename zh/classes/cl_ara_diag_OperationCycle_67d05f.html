上下文

类 ara::diag::OperationCycle 按照 AUTOSAR_AP_SWS_Diagnostics 第81页 映射了 DiagnosticOperationCycleInterface 的 C++ 接口。它为应用软件提供了用于控制和监视操作循环（Operation Cycles）的功能机制。操作循环在诊断中是决定性的参考时间段和状态窗口，以此为基础评估故障检查、去抖动和故障存储器条目（DTC）的确认。

该交互主要涉及三个实体：

  • 应用软件：根据端口标识符实例化类对象，根据需要注册用于监视循环变化的回调函数，并在相关运行条件到来时触发循环的重新启动。
  • ara::diag::OperationCycle：充当应用程序进程中的本地代理，绑定配置的端口并将调用转发给平台子系统。
  • 诊断管理：管理操作循环的整体状态，协调相关的诊断监视器，并将状态转换报告回已注册的实例。

上下文图：应用软件、ara::diag::OperationCycle 与平台诊断管理之间的相互作用。来源：[SWS_DM_00752]、AUTOSAR_AP_SWS_Diagnostics 第81页。

生命周期

实例的创建通过显式构造函数 OperationCycle(const ara::core::InstanceSpecifier &specifier)（[SWS_DM_00752]）进行。该构造函数声明为 noexcept，并被视为异常安全（exception safe）。

在所有权关系和语义方面，该类被设计为严格绑定的单一实例：

  • 复制构造函数（[SWS_DM_01598]）和赋值运算符（[SWS_DM_01596]）被显式删除（=delete），从而杜绝了对接口绑定的复制。
  • 同样，移动构造函数（[SWS_DM_01599]）和移动赋值运算符（[SWS_DM_01597]）也被删除（=delete）。因此，现有实例无法移动到其他作用域。

实例的释放通过虚析构函数 ~OperationCycle()（[SWS_DM_00753]）进行，该析构函数同样被实现为 noexcept。

对于并发性适用不同的保证：虽然通过构造函数进行的实例化被指定为线程安全（thread-safe）（[SWS_DM_00752]），但析构函数（[SWS_DM_00753]）以及所有常规方法调用均被声明为非线程安全（not thread-safe）。如果多个应用程序线程访问同一个 OperationCycle 对象，则必须由调用方对访问进行同步。

使用路径

监视和控制操作循环的常规流程分为以下步骤：

  1. 实例化：应用程序通过传递 ara::core::InstanceSpecifier 来创建对象，该标识符引用清单中对应的 PortPrototype（[SWS_DM_00752]）。
  2. 注册通知：通过 SetNotifier()（[SWS_DM_00755]）注册类型为 OperationCycleSetNotifier（定义为 std::function<void(void)>，[SWS_DM_02078]）的回调。随后对 SetNotifier() 的调用将完全覆盖先前设置的通知器。
  3. 请求重新启动：一旦操作循环需要重新开始（例如在端子切换或行驶循环结束之后），应用程序就会调用 RestartOperationCycle()（[SWS_DM_01102]）。
  4. 事件反馈：解读：在操作循环状态发生变化时，已注册通知器的执行推测由诊断子系统异步进行，因为未指定同步上下文。一旦系统中的循环状态完成调整，就会调用所设置的回调函数。

时序图：初始化、通知器注册和触发循环重新启动。来源：[SWS_DM_00752]、[SWS_DM_00755]、[SWS_DM_01102]、[SWS_DM_02078]。

错误场景

在实例化过程中可能会出现配置和模型冲突，这些冲突会通过特定的运行时违规（Violations）报告（[SWS_DM_00752]）：

  • InstanceSpecifierMappingIntegrityViolation：指定的 InstanceSpecifier 无法在 Executable 的模型上下文中解析，或指向非 PortPrototype 的模型元素。
  • PortInterfaceMappingViolation：由 DiagnosticOperationCyclePortMapping 引用的 PortPrototype 在设计模型中未被类型化为 DiagnosticOperationCycleInterface。
  • ProcessMappingViolation：虽然存在匹配的实例引用（InstanceRef），但缺少与正在运行的进程相对应的建模进程（Process）的映射。
  • InstanceSpecifierAlreadyInUseViolation：调用构造函数时使用的 InstanceSpecifier 已在同一进程内被现有实例使用。

对于操作调用 RestartOperationCycle()（[SWS_DM_01102]）和 SetNotifier()（[SWS_DM_00755]），API 分别返回一个 ara::core::Result<void>。接口规范未对这两个函数指定标准化的错误代码。这两个方法均声明为 noexcept。

<h4>上下文</h4>
<p>类 <code>ara::diag::OperationCycle</code> 按照 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=81">AUTOSAR_AP_SWS_Diagnostics 第81页</a> 映射了 <code>DiagnosticOperationCycleInterface</code> 的 C++ 接口。它为应用软件提供了用于控制和监视操作循环（Operation Cycles）的功能机制。操作循环在诊断中是决定性的参考时间段和状态窗口，以此为基础评估故障检查、去抖动和故障存储器条目（DTC）的确认。</p>
<p>该交互主要涉及三个实体：</p>
<ul>
<li><strong>应用软件：</strong>根据端口标识符实例化类对象，根据需要注册用于监视循环变化的回调函数，并在相关运行条件到来时触发循环的重新启动。</li>
<li><strong>ara::diag::OperationCycle：</strong>充当应用程序进程中的本地代理，绑定配置的端口并将调用转发给平台子系统。</li>
<li><strong>诊断管理：</strong>管理操作循环的整体状态，协调相关的诊断监视器，并将状态转换报告回已注册的实例。</li>
</ul>

<h4>生命周期</h4>
<p>实例的创建通过显式构造函数 <code>OperationCycle(const ara::core::InstanceSpecifier &amp;specifier)</code>（<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>）进行。该构造函数声明为 <code>noexcept</code>，并被视为异常安全（exception safe）。</p>
<p>在所有权关系和语义方面，该类被设计为严格绑定的单一实例：</p>
<ul>
<li>复制构造函数（<a class="spec-record-ref" data-req="SWS_DM_01598" href="../spec/record.html?id=SWS_DM_01598">[SWS_DM_01598]</a>）和赋值运算符（<a class="spec-record-ref" data-req="SWS_DM_01596" href="../spec/record.html?id=SWS_DM_01596">[SWS_DM_01596]</a>）被显式删除（<code>=delete</code>），从而杜绝了对接口绑定的复制。</li>
<li>同样，移动构造函数（<a class="spec-record-ref" data-req="SWS_DM_01599" href="../spec/record.html?id=SWS_DM_01599">[SWS_DM_01599]</a>）和移动赋值运算符（<a class="spec-record-ref" data-req="SWS_DM_01597" href="../spec/record.html?id=SWS_DM_01597">[SWS_DM_01597]</a>）也被删除（<code>=delete</code>）。因此，现有实例无法移动到其他作用域。</li>
</ul>
<p>实例的释放通过虚析构函数 <code>~OperationCycle()</code>（<a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>）进行，该析构函数同样被实现为 <code>noexcept</code>。</p>
<p>对于并发性适用不同的保证：虽然通过构造函数进行的实例化被指定为线程安全（<code>thread-safe</code>）（<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>），但析构函数（<a class="spec-record-ref" data-req="SWS_DM_00753" href="../spec/record.html?id=SWS_DM_00753">[SWS_DM_00753]</a>）以及所有常规方法调用均被声明为非线程安全（<code>not thread-safe</code>）。如果多个应用程序线程访问同一个 <code>OperationCycle</code> 对象，则必须由调用方对访问进行同步。</p>

<h4>使用路径</h4>
<p>监视和控制操作循环的常规流程分为以下步骤：</p>
<ol>
<li><strong>实例化：</strong>应用程序通过传递 <code>ara::core::InstanceSpecifier</code> 来创建对象，该标识符引用清单中对应的 <code>PortPrototype</code>（<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>）。</li>
<li><strong>注册通知：</strong>通过 <code>SetNotifier()</code>（<a class="spec-record-ref" data-req="SWS_DM_00755" href="../spec/record.html?id=SWS_DM_00755">[SWS_DM_00755]</a>）注册类型为 <code>OperationCycleSetNotifier</code>（定义为 <code>std::function&lt;void(void)&gt;</code>，<a class="spec-record-ref" data-req="SWS_DM_02078" href="../spec/record.html?id=SWS_DM_02078">[SWS_DM_02078]</a>）的回调。随后对 <code>SetNotifier()</code> 的调用将完全覆盖先前设置的通知器。</li>
<li><strong>请求重新启动：</strong>一旦操作循环需要重新开始（例如在端子切换或行驶循环结束之后），应用程序就会调用 <code>RestartOperationCycle()</code>（<a class="spec-record-ref" data-req="SWS_DM_01102" href="../spec/record.html?id=SWS_DM_01102">[SWS_DM_01102]</a>）。</li>
<li><strong>事件反馈：</strong>解读：在操作循环状态发生变化时，已注册通知器的执行推测由诊断子系统异步进行，因为未指定同步上下文。一旦系统中的循环状态完成调整，就会调用所设置的回调函数。</li>
</ol>

<h4>错误场景</h4>
<p>在实例化过程中可能会出现配置和模型冲突，这些冲突会通过特定的运行时违规（Violations）报告（<a class="spec-record-ref" data-req="SWS_DM_00752" href="../spec/record.html?id=SWS_DM_00752">[SWS_DM_00752]</a>）：</p>

<li><code>PortInterfaceMappingViolation</code>：由 <code>DiagnosticOperationCyclePortMapping</code> 引用的 <code>PortPrototype</code> 在设计模型中未被类型化为 <code>DiagnosticOperationCycleInterface</code>。</li>
<li><code>ProcessMappingViolation</code>：虽然存在匹配的实例引用（<code>InstanceRef</code>），但缺少与正在运行的进程相对应的建模进程（<code>Process</code>）的映射。</li>
<li><code>InstanceSpecifierAlreadyInUseViolation</code>：调用构造函数时使用的 <code>InstanceSpecifier</code> 已在同一进程内被现有实例使用。</li>
