上下文

接口 ara::crypto::cryp::HashFunctionCtx 定义了 AUTOSAR Adaptive Platform [SWS_CRYPT_21101] 的模块 crypto 内加密哈希函数的标准化抽象。其主要职责是针对任意字节流或结构化密钥对象计算加密校验和以及消息摘要。

主要作为交互伙伴的是调用方应用软件，该软件通过 ReadOnlyMemRegion 提供输入数据并通过 ReadWriteMemRegion 接收计算得出的哈希值 [SWS_CRYPT_50060]。除常规内存区域外，该上下文还可以直接与加密对象进行交互，以将类型为 CryptoObject::Sptr 的密钥材料安全地纳入摘要计算中 [SWS_CRYPT_50057]。此外，该上下文还可能通过内部处理状态的导入与导出，与同一算法和加密提供商的其他上下文实例进行交互 [SWS_CRYPT_50065]。

生命周期

实例的生命周期和所有权通常通过智能指针类型别名 ara::crypto::cryp::HashFunctionCtx::Sptr（std::shared_ptr<HashFunctionCtx>）进行管理 [SWS_CRYPT_21101]。由于 HashFunctionCtx 是纯抽象接口，具体实例的创建应当是通过加密提供商的工厂方法进行的（Interpretation）。所有成员函数均声明为 noexcept，并被指定为异常安全且线程安全（例如 [SWS_CRYPT_50060]、[SWS_CRYPT_50058] 等）。

操作流程遵循包含三个主要阶段的有状态模型：

  • 就绪 / 未启动（Bereit / Nicht gestartet）：创建后，上下文处于空闲状态。在此状态下，既可以通过 CalculateHashDigest() [SWS_CRYPT_50060] 执行单步哈希过程，也可以通过 Start() 启动不带初始化向量（IV）[SWS_CRYPT_50152] 或带 IV [SWS_CRYPT_50153] 的迭代计算。使用 ImportContextState() 进行导入会使上下文直接进入所导入映像的状态 [SWS_CRYPT_50065]。
  • 处理中（流式处理，In Verarbeitung (Streaming)）：成功完成 Start() 后，上下文通过重复调用 Update() 来接收数据片段 [SWS_CRYPT_21113] 或密钥对象 [SWS_CRYPT_50057]。在此阶段，随时可以通过 GetIntermediateDigest() 查询中间状态，而不会中断数据流 [SWS_CRYPT_50059]。使用 ExportContextState() 可以对计算状态进行序列化 [SWS_CRYPT_50064]。调用 Cancel() 会中止操作并重置处理 [SWS_CRYPT_50058]；同样，再次调用 Start() 也会中止正在进行的操作 [SWS_CRYPT_50152]。
  • 已完成（Finished，Abgeschlossen）：调用 Finish() 将结束计算 [SWS_CRYPT_21115]。在此状态下，无法再通过 Update() 输入更多数据。此时可以通过 GetDigest() 读取最终哈希值 [SWS_CRYPT_21116]，或者使用 Compare() 直接针对参考值进行校验 [SWS_CRYPT_50154]。通过再次执行 Start()，上下文将重新进入新的计算阶段。

使用路径

该接口支持两种使用模式：

1. 单步计算（Single-Call）：当整条消息已存在于内存中时，CalculateHashDigest() 会在单个原子步骤中执行初始化、转换和摘要生成 [SWS_CRYPT_50060]。

2. 分步流式计算（Multi-Call）：对于流式数据或大于最大块大小 GetMaximumChunkSize() [SWS_CRYPT_50062] 的消息，调用通常按以下单独步骤进行：

  1. 缓冲区大小调整：应用程序通过 GetDigestSize() [SWS_CRYPT_50061] 确定输出大小并分配适当的缓冲区。
  2. 启动：调用 Start() [SWS_CRYPT_50152] 或 Start(iv) [SWS_CRYPT_50153] 以激活计算。
  3. 提供数据：通过 Update(data) [SWS_CRYPT_21113] 顺序传递数据段，或通过 Update(key) [SWS_CRYPT_50057] 顺序传递密钥。
  4. 完成：调用 Finish() 完成摘要计算 [SWS_CRYPT_21115]。
  5. 结果处理：要么使用 GetDigest() 将摘要写入提供的目标缓冲区 [SWS_CRYPT_21116]，要么使用 Compare() 直接与预期的参考值进行比较 [SWS_CRYPT_50154]。

错误场景

所有方法均返回一个 ara::core::Result 并实现回滚语义，从而确保在发生错误时上下文保持一致状态。定义的错误代码涵盖以下问题领域：

  • 调用顺序错误：
    • ara::crypto::CryptoErrc::kProcessingNotStarted：在未通过 Start() 启动计算的情况下，调用了 Update()（[SWS_CRYPT_21113]、[SWS_CRYPT_50057]）或 Cancel() [SWS_CRYPT_50058]。
    • ara::crypto::CryptoErrc::kInvalidUsageOrder：在哈希过程此前未成功启动的情况下，调用了 Finish() [SWS_CRYPT_21115] 或 GetIntermediateDigest() [SWS_CRYPT_50059]。
    • ara::crypto::CryptoErrc::kProcessingNotFinished：在计算被 Finish() 完成之前，调用了 GetDigest() [SWS_CRYPT_21116] 或 Compare() [SWS_CRYPT_50154]。
  • 缓冲区和大小问题：
    • ara::crypto::CryptoErrc::kInsufficientCapacity：提供的输出缓冲区对于 CalculateHashDigest() [SWS_CRYPT_50060]、GetDigest() [SWS_CRYPT_21116]、GetIntermediateDigest() [SWS_CRYPT_50059] 或 ExportContextState() [SWS_CRYPT_50064] 中的结果过小。
    • ara::crypto::CryptoErrc::kInvalidInputSize：输入数据或 IV 的大小无效（[SWS_CRYPT_50060]、[SWS_CRYPT_50153]、[SWS_CRYPT_21113]、[SWS_CRYPT_50057]）。
  • 不兼容与缺少支持：
    • ara::crypto::CryptoErrc::kUnsupported：上下文不支持该函数或配置，例如单次调用 [SWS_CRYPT_50060]、在无 IV 的算法中使用 IV 或在需要 IV 的函数中缺少 IV（[SWS_CRYPT_50060]、[SWS_CRYPT_50152]、[SWS_CRYPT_50153]）、中间结果 [SWS_CRYPT_50059]、密钥哈希 [SWS_CRYPT_50057] 或状态导出/导入（[SWS_CRYPT_50063]、[SWS_CRYPT_50064]、[SWS_CRYPT_50065]）。
    • ara::crypto::CryptoErrc::kIncompatibleObject 与 ara::crypto::CryptoErrc::kUsageViolation：传递给 Update() 的密钥对象不兼容，或禁止用于哈希计算（缺少 kAllowHashCalculation）[SWS_CRYPT_50057]。
    • ara::crypto::CryptoErrc::kInvalidArgument：传递给 ImportContextState() 的状态数据无效 [SWS_CRYPT_50065]。
    • ara::crypto::CryptoErrc::kBusyResource：所需的加密硬件或软件资源被占用（[SWS_CRYPT_50152]、[SWS_CRYPT_50153]）。

<h4>上下文</h4>
<p>接口 <code>ara::crypto::cryp::HashFunctionCtx</code> 定义了 AUTOSAR Adaptive Platform <a class="spec-record-ref" data-req="SWS_CRYPT_21101" href="../spec/record.html?id=SWS_CRYPT_21101">[SWS_CRYPT_21101]</a> 的模块 <code>crypto</code> 内加密哈希函数的标准化抽象。其主要职责是针对任意字节流或结构化密钥对象计算加密校验和以及消息摘要。</p>
<p>主要作为交互伙伴的是调用方应用软件，该软件通过 <code>ReadOnlyMemRegion</code> 提供输入数据并通过 <code>ReadWriteMemRegion</code> 接收计算得出的哈希值 <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>。除常规内存区域外，该上下文还可以直接与加密对象进行交互，以将类型为 <code>CryptoObject::Sptr</code> 的密钥材料安全地纳入摘要计算中 <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>。此外，该上下文还可能通过内部处理状态的导入与导出，与同一算法和加密提供商的其他上下文实例进行交互 <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>。</p>

<h4>生命周期</h4>
<p>实例的生命周期和所有权通常通过智能指针类型别名 <code>ara::crypto::cryp::HashFunctionCtx::Sptr</code>（<code>std::shared_ptr&lt;HashFunctionCtx&gt;</code>）进行管理 <a class="spec-record-ref" data-req="SWS_CRYPT_21101" href="../spec/record.html?id=SWS_CRYPT_21101">[SWS_CRYPT_21101]</a>。由于 <code>HashFunctionCtx</code> 是纯抽象接口，具体实例的创建应当是通过加密提供商的工厂方法进行的（Interpretation）。所有成员函数均声明为 <code>noexcept</code>，并被指定为异常安全且线程安全（例如 <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>、<a class="spec-record-ref" data-req="SWS_CRYPT_50058" href="../spec/record.html?id=SWS_CRYPT_50058">[SWS_CRYPT_50058]</a> 等）。</p>
<p>操作流程遵循包含三个主要阶段的有状态模型：</p>
<ul>
<li><strong>就绪 / 未启动（Bereit / Nicht gestartet）：</strong>创建后，上下文处于空闲状态。在此状态下，既可以通过 <code>CalculateHashDigest()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a> 执行单步哈希过程，也可以通过 <code>Start()</code> 启动不带初始化向量（IV）<a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a> 或带 IV <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a> 的迭代计算。使用 <code>ImportContextState()</code> 进行导入会使上下文直接进入所导入映像的状态 <a class="spec-record-ref" data-req="SWS_CRYPT_50065" href="../spec/record.html?id=SWS_CRYPT_50065">[SWS_CRYPT_50065]</a>。</li>
<li><strong>处理中（流式处理，In Verarbeitung (Streaming)）：</strong>成功完成 <code>Start()</code> 后，上下文通过重复调用 <code>Update()</code> 来接收数据片段 <a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a> 或密钥对象 <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a>。在此阶段，随时可以通过 <code>GetIntermediateDigest()</code> 查询中间状态，而不会中断数据流 <a class="spec-record-ref" data-req="SWS_CRYPT_50059" href="../spec/record.html?id=SWS_CRYPT_50059">[SWS_CRYPT_50059]</a>。使用 <code>ExportContextState()</code> 可以对计算状态进行序列化 <a class="spec-record-ref" data-req="SWS_CRYPT_50064" href="../spec/record.html?id=SWS_CRYPT_50064">[SWS_CRYPT_50064]</a>。调用 <code>Cancel()</code> 会中止操作并重置处理 <a class="spec-record-ref" data-req="SWS_CRYPT_50058" href="../spec/record.html?id=SWS_CRYPT_50058">[SWS_CRYPT_50058]</a>；同样，再次调用 <code>Start()</code> 也会中止正在进行的操作 <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a>。</li>
<li><strong>已完成（Finished，Abgeschlossen）：</strong>调用 <code>Finish()</code> 将结束计算 <a class="spec-record-ref" data-req="SWS_CRYPT_21115" href="../spec/record.html?id=SWS_CRYPT_21115">[SWS_CRYPT_21115]</a>。在此状态下，无法再通过 <code>Update()</code> 输入更多数据。此时可以通过 <code>GetDigest()</code> 读取最终哈希值 <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a>，或者使用 <code>Compare()</code> 直接针对参考值进行校验 <a class="spec-record-ref" data-req="SWS_CRYPT_50154" href="../spec/record.html?id=SWS_CRYPT_50154">[SWS_CRYPT_50154]</a>。通过再次执行 <code>Start()</code>，上下文将重新进入新的计算阶段。</li>
</ul>

<h4>使用路径</h4>
<p>该接口支持两种使用模式：</p>
<p><strong>1. 单步计算（Single-Call）：</strong>当整条消息已存在于内存中时，<code>CalculateHashDigest()</code> 会在单个原子步骤中执行初始化、转换和摘要生成 <a class="spec-record-ref" data-req="SWS_CRYPT_50060" href="../spec/record.html?id=SWS_CRYPT_50060">[SWS_CRYPT_50060]</a>。</p>
<p><strong>2. 分步流式计算（Multi-Call）：</strong>对于流式数据或大于最大块大小 <code>GetMaximumChunkSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50062" href="../spec/record.html?id=SWS_CRYPT_50062">[SWS_CRYPT_50062]</a> 的消息，调用通常按以下单独步骤进行：</p>
<ol>
<li><strong>缓冲区大小调整：</strong>应用程序通过 <code>GetDigestSize()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50061" href="../spec/record.html?id=SWS_CRYPT_50061">[SWS_CRYPT_50061]</a> 确定输出大小并分配适当的缓冲区。</li>
<li><strong>启动：</strong>调用 <code>Start()</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50152" href="../spec/record.html?id=SWS_CRYPT_50152">[SWS_CRYPT_50152]</a> 或 <code>Start(iv)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50153" href="../spec/record.html?id=SWS_CRYPT_50153">[SWS_CRYPT_50153]</a> 以激活计算。</li>
<li><strong>提供数据：</strong>通过 <code>Update(data)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_21113" href="../spec/record.html?id=SWS_CRYPT_21113">[SWS_CRYPT_21113]</a> 顺序传递数据段，或通过 <code>Update(key)</code> <a class="spec-record-ref" data-req="SWS_CRYPT_50057" href="../spec/record.html?id=SWS_CRYPT_50057">[SWS_CRYPT_50057]</a> 顺序传递密钥。</li>
<li><strong>完成：</strong>调用 <code>Finish()</code> 完成摘要计算 <a class="spec-record-ref" data-req="SWS_CRYPT_21115" href="../spec/record.html?id=SWS_CRYPT_21115">[SWS_CRYPT_21115]</a>。</li>
<li><strong>结果处理：</strong>要么使用 <code>GetDigest()</code> 将摘要写入提供的目标缓冲区 <a class="spec-record-ref" data-req="SWS_CRYPT_21116" href="../spec/record.html?id=SWS_CRYPT_21116">[SWS_CRYPT_21116]</a>，要么使用 <code>Compare()</code> 直接与预期的参考值进行比较 <a class="spec-record-ref" data-req="SWS_CRYPT_50154" href="../spec/record.html?id=SWS_CRYPT_50154">[SWS_CRYPT_50154]</a>。</li>
</ol>

<h4>错误场景</h4>
<p>所有方法均返回一个 <code>ara::core::Result</code> 并实现回滚语义，从而确保在发生错误时上下文保持一致状态。定义的错误代码涵盖以下问题领域：</p>
