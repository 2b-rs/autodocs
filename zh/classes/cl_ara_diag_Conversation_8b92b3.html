上下文

类 ara::diag::Conversation 代表 AUTOSAR Adaptive Diagnostic Management 内的一个活动诊断连接。它作为诊断应用程序和服务处理程序的核心抽象，用于查看和控制正在进行的 UDS 或 DoIP 通信的上下文和状态 AUTOSAR_AP_SWS_Diagnostics 第80页。

核心任务包括提供当前活动状态、会话的唯一标识属性，以及活动诊断会话（SessionControlType）和安全级别（SecurityLevelType）。此外，该接口还允许在状态切换时注册 Notifier 回调，并将诊断会话重置为默认会话。

交互主要在三个参与方之间进行：应用软件（例如诊断服务处理程序）通过静态方法检索会话引用并查询属性。ara::diag::Conversation 的实例保存并传递连接属性，而底层的 Diagnostic Management (DM) 负责协议处理并向会话报告状态变更。

上下文图：ara::diag::Conversation 在应用程序与 Diagnostic Management 之间的嵌入。来源：[SWS_DM_00692]、[SWS_DM_00782]、AUTOSAR_AP_SWS_Diagnostics 第80页

生命周期

会话实例的生命周期受严格的语义规则控制。该类被声明为 final，并禁止任何形式的复制或按值传递：复制构造函数 [SWS_DM_02090]、移动构造函数 [SWS_DM_02092]、复制赋值运算符 [SWS_DM_02091] 和移动赋值运算符 [SWS_DM_02093] 均已被显式删除。

解读：由于未提供公共构造函数且仅对外提供长寿命引用，Conversation 对象的创建和销毁完全由 Diagnostic Management 的内部运行时环境负责。应用程序通过静态查询函数获取现有实例：

  • GetConversation 根据请求随附的 MetaInfo 返回会话的引用 [SWS_DM_00692]。
  • GetAllConversations 返回所有可能会话的引用包装器向量 [SWS_DM_00782]。
  • GetCurrentActiveConversations 筛选出所有状态为 kActive 的会话 [SWS_DM_00783]。

在并发性方面：纯查询操作（如 GetActivityStatus [SWS_DM_00694]、GetConversationIdentifier [SWS_DM_00700]、GetDiagnosticSession [SWS_DM_00696]、GetDiagnosticSecurityLevel [SWS_DM_00698] 以及 ShortName 转换器 [SWS_DM_00707] 和 [SWS_DM_00708]）是线程安全且异常安全的。相比之下，修改状态的调用（如 ResetToDefaultSession [SWS_DM_00701] 以及 Notifier 注册 [SWS_DM_00695]、[SWS_DM_00697] 和 [SWS_DM_00699]）不是线程安全的（not thread-safe），必须同步调用。

使用路径

诊断服务处理程序使用会话实例的典型流程分为以下步骤：

  1. 确定会话：在请求处理期间，通过 ara::diag::Conversation::GetConversation(metaInfo) 获取实例 [SWS_DM_00692]。
  2. 注册状态观察者：根据需要，调用方可通过 SetActivityNotifier [SWS_DM_00695] [SWS_DM_02126]、SetDiagnosticSessionNotifier [SWS_DM_00697] [SWS_DM_02127] 或 SetSecurityLevelNotifier [SWS_DM_00699] [SWS_DM_02128] 注册通知函数。再次调用始终会覆盖之前注册的 Notifier。
  3. 检查会话和安全级别：处理程序通过 GetDiagnosticSession [SWS_DM_00696] 和 GetDiagnosticSecurityLevel [SWS_DM_00698] 检查访问权限。标识符可以通过 GetDiagnosticSessionShortName [SWS_DM_00707] 或 GetDiagnosticSecurityLevelShortName [SWS_DM_00708] 解析为 StringView，用于跟踪或日志输出。
  4. 重置会话状态：当应用逻辑或错误状态强制返回到默认状态时，将调用 ResetToDefaultSession() [SWS_DM_00701]。

错误场景

该类的方法通过类型为 ara::core::Result 的返回对象指示错误条件。所有操作均声明为 noexcept，因此不会发生 C++ 异常：

  • 服务不可用（DiagErrc::kServiceNotAvailable）：如果 Diagnostic Management 的基本功能当前不可用，则由 GetConversation [SWS_DM_00692]、GetActivityStatus [SWS_DM_00694]、GetConversationIdentifier [SWS_DM_00700]、GetDiagnosticSession [SWS_DM_00696] 和 GetDiagnosticSecurityLevel [SWS_DM_00698] 返回。
  • 无效参数（DiagErrc::kInvalidArgument）：当传递未定义的枚举值时，发生在 GetDiagnosticSessionShortName [SWS_DM_00707] 和 GetDiagnosticSecurityLevelShortName [SWS_DM_00708] 中。
  • 无标准化错误代码的方法：对于 ResetToDefaultSession [SWS_DM_00701] 以及方法 SetActivityNotifier [SWS_DM_00695]、SetDiagnosticSessionNotifier [SWS_DM_00697] 和 SetSecurityLevelNotifier [SWS_DM_00699]，未定义标准化的错误代码；但是返回的 ara::core::Result<void> 允许实现特定的错误。

<h4>上下文</h4>
<p>类 <code>ara::diag::Conversation</code> 代表 AUTOSAR Adaptive Diagnostic Management 内的一个活动诊断连接。它作为诊断应用程序和服务处理程序的核心抽象，用于查看和控制正在进行的 UDS 或 DoIP 通信的上下文和状态 <a class="docref internal-spec-ref" href="../spec/record.html?doc=AUTOSAR_AP_SWS_Diagnostics&amp;page=80">AUTOSAR_AP_SWS_Diagnostics 第80页</a>。</p>
<p>核心任务包括提供当前活动状态、会话的唯一标识属性，以及活动诊断会话（<code>SessionControlType</code>）和安全级别（<code>SecurityLevelType</code>）。此外，该接口还允许在状态切换时注册 Notifier 回调，并将诊断会话重置为默认会话。</p>
<p>交互主要在三个参与方之间进行：应用软件（例如诊断服务处理程序）通过静态方法检索会话引用并查询属性。<code>ara::diag::Conversation</code> 的实例保存并传递连接属性，而底层的 Diagnostic Management (DM) 负责协议处理并向会话报告状态变更。</p>

<h4>生命周期</h4>
<p>会话实例的生命周期受严格的语义规则控制。该类被声明为 <code>final</code>，并禁止任何形式的复制或按值传递：复制构造函数 <a class="spec-record-ref" data-req="SWS_DM_02090" href="../spec/record.html?id=SWS_DM_02090">[SWS_DM_02090]</a>、移动构造函数 <a class="spec-record-ref" data-req="SWS_DM_02092" href="../spec/record.html?id=SWS_DM_02092">[SWS_DM_02092]</a>、复制赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_02091" href="../spec/record.html?id=SWS_DM_02091">[SWS_DM_02091]</a> 和移动赋值运算符 <a class="spec-record-ref" data-req="SWS_DM_02093" href="../spec/record.html?id=SWS_DM_02093">[SWS_DM_02093]</a> 均已被显式删除。</p>
<p>解读：由于未提供公共构造函数且仅对外提供长寿命引用，<code>Conversation</code> 对象的创建和销毁完全由 Diagnostic Management 的内部运行时环境负责。应用程序通过静态查询函数获取现有实例：</p>
<ul>
<li><code>GetConversation</code> 根据请求随附的 <code>MetaInfo</code> 返回会话的引用 <a class="spec-record-ref" data-req="SWS_DM_00692" href="../spec/record.html?id=SWS_DM_00692">[SWS_DM_00692]</a>。</li>
<li><code>GetAllConversations</code> 返回所有可能会话的引用包装器向量 <a class="spec-record-ref" data-req="SWS_DM_00782" href="../spec/record.html?id=SWS_DM_00782">[SWS_DM_00782]</a>。</li>
<li><code>GetCurrentActiveConversations</code> 筛选出所有状态为 <code>kActive</code> 的会话 <a class="spec-record-ref" data-req="SWS_DM_00783" href="../spec/record.html?id=SWS_DM_00783">[SWS_DM_00783]</a>。</li>
</ul>
<p>在并发性方面：纯查询操作（如 <code>GetActivityStatus</code> <a class="spec-record-ref" data-req="SWS_DM_00694" href="../spec/record.html?id=SWS_DM_00694">[SWS_DM_00694]</a>、<code>GetConversationIdentifier</code> <a class="spec-record-ref" data-req="SWS_DM_00700" href="../spec/record.html?id=SWS_DM_00700">[SWS_DM_00700]</a>、<code>GetDiagnosticSession</code> <a class="spec-record-ref" data-req="SWS_DM_00696" href="../spec/record.html?id=SWS_DM_00696">[SWS_DM_00696]</a>、<code>GetDiagnosticSecurityLevel</code> <a class="spec-record-ref" data-req="SWS_DM_00698" href="../spec/record.html?id=SWS_DM_00698">[SWS_DM_00698]</a> 以及 ShortName 转换器 <a class="spec-record-ref" data-req="SWS_DM_00707" href="../spec/record.html?id=SWS_DM_00707">[SWS_DM_00707]</a> 和 <a class="spec-record-ref" data-req="SWS_DM_00708" href="../spec/record.html?id=SWS_DM_00708">[SWS_DM_00708]</a>）是线程安全且异常安全的。相比之下，修改状态的调用（如 <code>ResetToDefaultSession</code> <a class="spec-record-ref" data-req="SWS_DM_00701" href="../spec/record.html?id=SWS_DM_00701">[SWS_DM_00701]</a> 以及 Notifier 注册 <a class="spec-record-ref" data-req="SWS_DM_00695" href="../spec/record.html?id=SWS_DM_00695">[SWS_DM_00695]</a>、<a class="spec-record-ref" data-req="SWS_DM_00697" href="../spec/record.html?id=SWS_DM_00697">[SWS_DM_00697]</a> 和 <a class="spec-record-ref" data-req="SWS_DM_00699" href="../spec/record.html?id=SWS_DM_00699">[SWS_DM_00699]</a>）不是线程安全的（<em>not thread-safe</em>），必须同步调用。</p>
