向正在运行的诊断例程发出提早中止会话的信号，以节省资源。

类 ara::diag::CancellationHandler 通知诊断应用程序 Diagnostic Management 中正在运行的处理已提前中止 [SWS_DM_00608]。由 DM Core 生成的对象允许服务处理器通过 IsCanceled() 查询中止状态，或通过 SetNotifier() 接收回调通知，以便立即停止服务处理 [SWS_DM_00615]。一旦设置了中止状态便不可撤销，并且由于接口不是线程安全的，访问该实例必须在应用程序端进行保护。

上下文

类 ara::diag::CancellationHandler 在模块 diag 内充当共享状态指示器，指示是否应提前中止正在运行的诊断处理 [SWS_DM_00608]。在 AUTOSAR Adaptive Platform 中，该类在 Diagnostic Management（DM）的服务器实例与执行应用逻辑之间进行调解，例如在处理特定于制造商的 UDS 服务时（AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.24 “Custom Diagnostic Services”、[SWS_DM_00502]）。

如果活动的诊断会话因外部事件或协议要求而被取消，则诊断服务器实例有义务尽快停止已启动的活动 [SWS_DM_00278]。通过 CancellationHandler 将该中止信号发送给服务处理器，以便中止资源密集型计算，并在开始传输之前防止不合规地发送诊断响应 [SWS_DM_00279]。

生命周期

ara::diag::CancellationHandler 的实例化受诊断框架的排他性控制：默认构造函数对应用程序显式删除（delete），因此实例只能由 DM Core 创建 [SWS_DM_00609]。为了确保明确的状态归属，该类被指定为不可复制的单实例；复制构造函数 [SWS_DM_00611] 和复制赋值运算符 [SWS_DM_00613] 已删除。

相反，该类支持移动语义：移动构造函数 [SWS_DM_00610] 和移动赋值运算符 [SWS_DM_00612] 作为默认实现声明为 noexcept。这大概允许框架将实例的所有权高效地转移到下游的执行上下文中。

在状态方面，该实例表现出单调的行为。初始化后，IsCanceled() 立即发出值 false [SWS_DM_00984]。一旦关联的诊断会话被取消，状态就会更改为 true。该中止状态将不可逆地保留，直到实例被销毁 [SWS_DM_00984]。

状态图：CancellationHandler 的生命周期和状态转换。来源：[SWS_DM_00609]、[SWS_DM_00984]、AUTOSAR_AP_SWS_Diagnostics §7.3.2 “Return of cancellation status”

使用路径

该 Handler 的典型用法分为以下相互协调的步骤：

  1. 提供：当诊断请求到达时，DM Core 会创建 CancellationHandler 对象并将其传递给诊断应用程序的处理例程（AUTOSAR_AP_SWS_Diagnostics §7.3.2.8.24 “Custom Diagnostic Services”、[SWS_DM_00609]）。
  2. 注册或轮询：应用程序使用 SetNotifier() 注册类型为 ara::diag::CancellationHandler::CancellationHandlerSetNotifier 的通知函数（[SWS_DM_02075]），该函数在发生中止时被调用 [SWS_DM_00615]。或者/同时，它循环查询 IsCanceled() [SWS_DM_00614]。
  3. 发送信号：如果 DM 中止会话，Handler 中的状态将变为 true [SWS_DM_00984]，并触发配置的通知程序 [SWS_DM_00615]。
  4. 中止：应用程序立即停止已开始的工作 [SWS_DM_00278]。如果响应尚未传输，DM 会抑制发送 [SWS_DM_00279]。
  5. 完成：处理结束后，Handler 对象与服务上下文一起被销毁。

时序图：DM Core、CancellationHandler 与诊断应用程序之间的交互模式。来源：[SWS_DM_00278]、[SWS_DM_00614]、[SWS_DM_00615]、[SWS_DM_00984]、[SWS_DM_00609]、[SWS_DM_00279]

错误场景

ara::diag::CancellationHandler 的接口具有无错误的设计特点。所有方法（如 IsCanceled() [SWS_DM_00614]、SetNotifier() [SWS_DM_00615]）以及移动操作 [SWS_DM_00610] [SWS_DM_00612] 均具有异常安全性（noexcept），且不返回错误代码。

多次调用 SetNotifier() 不会导致错误：后续注册会完全覆盖先前设置的回调 [SWS_DM_00615]、[SWS_DM_01348]。

需要特别注意线程安全性：所有成员函数（IsCanceled、SetNotifier）和回调类型均明确声明为非线程安全 [SWS_DM_00614]、[SWS_DM_00615]、[SWS_DM_02075]。如果跨线程边界进行状态查询或通知程序注册，应用程序必须使用外部保护机制。此外，回调可能在 DM 的触发线程中同步调用，因此应用程序端通知函数应保持非阻塞。

                  使用
                  

                  
来自头文件 ara/diag/cancellation_handler.h 的方法 ara::diag::CancellationHandler::SetNotifier ([SWS_DM_00615]) 注册类型为 CancellationHandlerSetNotifier 的回调函数。一旦诊断服务的执行被中止，Diagnostic Management (DM) 便会调用此函数。注册本身以同步方式执行且无返回值 (void)。

                  


                  错误处理与执行语义
                  

                  
该调用被指定为 noexcept 并被视为异常安全（exception safe）([SWS_DM_00615])。未针对此接口预设特定的错误代码、错误返回值或 DET/DEM 消息。

                  


                  并发性与限制
                  

                  
在线程安全性方面，该方法归类为 not thread-safe ([SWS_DM_00615])。因此，不得在未受保护的情况下并发修改 CancellationHandler 的实例。如果在同一实例上多次连续调用 SetNotifier，DM 将覆盖先前注册的通知程序 ([SWS_DM_01348], SWS Diagnostics 第193页)。此外，回调函数最好不要执行阻塞操作，以免延迟 DM 的内部中止处理。

                  


                  相互作用
                  

                  
DM 会将 CancellationHandler 实例作为参数传递给服务处理程序和例程处理程序，例如在通用服务处理 ([SWS_DM_00618])、数据访问 ([SWS_DM_00636]) 或例程 ([SWS_DM_00554]) 中。若诊断会话中止，DM 会尽可能中止正在运行的内部活动 ([SWS_DM_00278]) 并放弃响应的传输 ([SWS_DM_00279])。除了通过 IsCanceled ([SWS_DM_00984]) 同步查询中止状态外，通过 SetNotifier 注册还提供了一条事件驱动的反应路径。
