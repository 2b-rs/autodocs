该类表示一个类型安全的容器，它容纳有效负载值或错误代码，以同步且无需 C++ 异常的方式传递计算结果 [SWS_CORE_00751]。调用方通过专用构造函数或工厂函数创建实例，随后根据状态通过检查和访问函数（例如值或错误访问）评估结果。作为关键约束，底层错误类型必须强制对应于标准错误代码，因为偏离的类型配置在编译时会被拒绝。此外，用于触发异常的函数以启用了 C++ 异常的编译器环境为前提 [SWS_CORE_00766]。

上下文

类 ara::core::Result 是 AUTOSAR Adaptive Platform 的核心结构，用于同步、类型化地返回操作结果，而无需强制使用 C++ 异常。它表示一个可辨识联合（Tagged Union），在任何时间点要么包含类型为 value_type（T）的有效负载值，要么包含类型为 error_type（E）的错误 [SWS_CORE_00711] [SWS_CORE_00712]。默认情况下，ara::core::ErrorCode 用作 E 的类型；偏离的错误定义在编译时就会被实现通过编译错误所阻止。

在应用架构中，ara::core::Result 在被调用的服务和使用者之间进行中介。服务实例化该对象以返回状态，而使用者通过状态测试（如 [SWS_CORE_00751]）或函数式链接（如 [SWS_CORE_00768]）触发进一步处理。此外，该状态可通过 [SWS_CORE_00770]（Ok）和 [SWS_CORE_00772]（Err）转换为 ara::core::Optional。

生命周期

实例的初始化要么直接通过针对值的构造函数（[SWS_CORE_00721]、[SWS_CORE_00722]）进行，要么显式通过针对错误的构造函数（[SWS_CORE_00723]、[SWS_CORE_00724]）进行。此外还提供静态工厂函数：针对左值、右值和原位（in-place）参数的 FromValue（[SWS_CORE_00731]、[SWS_CORE_00732]、[SWS_CORE_00733]），以及用于创建错误状态的 FromError（[SWS_CORE_00734]、[SWS_CORE_00735]、[SWS_CORE_00736]）。

ara::core::Result 独占拥有所包含的数据并管理其生命周期。它通过复制和移动构造函数（[SWS_CORE_00725]、[SWS_CORE_00726]）以及相应的赋值运算符（[SWS_CORE_00741]、[SWS_CORE_00742]）支持完整的值语义。现有实例的内容替换可通过 Swap [SWS_CORE_00745] 或通过借助 EmplaceValue [SWS_CORE_00743] 或 EmplaceError [SWS_CORE_00744] 原位覆盖来实现。

析构函数释放活动元素；如果 T 和 E 都是平凡可析构的，则该析构函数被视为平凡可析构 [SWS_CORE_00727]。关于并发性，纯读取访问是线程安全的，而诸如 EmplaceValue、EmplaceError、移动赋值或 Swap 等修改性操作不是线程安全的，需要外部同步。

使用路径

常规流程包括结果的创建、验证和获取：

  1. 提供：服务通过 [SWS_CORE_00731] 或 [SWS_CORE_00734] 创建结果，并按值返回该实例。
  2. 状态检查：调用方利用 HasValue() [SWS_CORE_00751] 或显式转换运算符 operator bool() [SWS_CORE_00752] 检查是否存在值。如果 T 本身属于类型 bool，则后者被禁用。
  3. 值与错误访问：如果存在值，则可以通过 Value()（[SWS_CORE_00755]、[SWS_CORE_00756]、[SWS_CORE_00775]）或运算符 operator*（[SWS_CORE_00753]、[SWS_CORE_00759]）和 operator->（[SWS_CORE_00754]、[SWS_CORE_00777]）读取该值。在发生错误的情况下，通过 Error()（[SWS_CORE_00757]、[SWS_CORE_00758]、[SWS_CORE_00776]）进行访问，或者通过 CheckError() [SWS_CORE_00765] 进行针对性的错误检查。
  4. 函数式转换：或者，Bind() [SWS_CORE_00768] 允许进行 monadic 进一步处理：仅当包含有效负载值时才执行传入的可调用对象；现有错误将不加修改地传播到新的 Result 实例中。回退可以通过 Resolve() [SWS_CORE_00767] 实现。

错误场景

访问非活动状态会违反该类的前置条件：

  • 在不包含值的情况下调用 Value()、operator* 或 operator-> 会触发已记录的系统违例 ResultWithNoValueViolation（[SWS_CORE_00755]、[SWS_CORE_00753]、[SWS_CORE_00754]）。
  • 在存在有效负载值的情况下调用 Error() 会导致违例 ResultWithNoErrorViolation（[SWS_CORE_00757]、[SWS_CORE_00776]）。

解释：触发此类前置条件违例在运行时环境中通常很可能会导致进程立即中止，因为标准将这些状态归类为严重的编程错误。为避免硬性中止，可以使用防御性方法：ValueOr()（[SWS_CORE_00761]、[SWS_CORE_00762]）和 ErrorOr()（[SWS_CORE_00763]、[SWS_CORE_00764]）在元素缺失时返回指定的默认值。诸如 Ok()（[SWS_CORE_00770]、[SWS_CORE_00771]）和 Err()（[SWS_CORE_00772]、[SWS_CORE_00773]）等可选变体以无异常方式封装访问。

如果需要异常处理，ValueOrThrow()（[SWS_CORE_00766]、[SWS_CORE_00769]、[SWS_CORE_00778]）在发生错误时会抛出与该错误关联的 C++ 异常。如果编译器中禁用了 C++ 异常，则 ValueOrThrow() 将从重载解析中移除 [SWS_CORE_00766]；同样，operator* 的非 const 左值重载在此情况下也会被禁用 [SWS_CORE_00774]。
