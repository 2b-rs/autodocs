类 ara::core::Result

[SWS_CORE_00701] Upstream: RS_AP_00130

template <typename T, typename E = ErrorCode> class Result final {...};

This class is a type that contains either a value or an error. The implementation shall flag the condition E != ara::core::ErrorCode as a compile error.

使用目的

对于同步调用，ara::core::Result<T,E> 封装 T 类型的值或 E 类型的错误； E 必须是 ara::core::ErrorCode。因此，该类型支持无异常错误处理。 [SWS_CORE_00701] [SWS_CORE_10600]

生成和生命周期

结果可以从值或错误以及FromValue()和FromError()生成。复制和移动操作可用且有条件noexcept；析构函数的简单性取决于 T 和 E。 [SWS_CORE_00721] [SWS_CORE_00724] [SWS_CORE_00731] [SWS_CORE_00734] [SWS_CORE_00725] [SWS_CORE_00726] [SWS_CORE_00741] [SWS_CORE_00742] [SWS_CORE_00727]

与其他班级的互动

HasValue()、Value()、Error()、Ok() 和 Err() 允许状态和内容访问。 Bind() 使用可调用函数将包含的值转换为新结果，而 Resolve() 在发生错误时调用函数。 [SWS_CORE_00751] [SWS_CORE_00755] [SWS_CORE_00757] [SWS_CORE_00770] [SWS_CORE_00772] [SWS_CORE_00768] [SWS_CORE_00767]

限制&错误处理

访问不包含错误的错误或访问不包含值的值被定义为违规。 ValueOrThrow() 可以触发，并且是唯一在没有ara::core初始化的情况下被排除使用的Result函数。 [SWS_CORE_13010][SWS_CORE_13009][SWS_CORE_00766][SWS_CORE_15002]

在无异常错误路径中的作用

对于可恢复错误，接口应使用ara::core::Result或ara::core::Future； Result 错误类型设置为 ara::core::ErrorCode。 RS General §4.1.2 “Error handling”EXP InterfacesGuidelines §3.1.2 “Result”

在无异常访问中，调用方检查 HasValue()，然后读取 Value() 或 Error()。这些 observer 可不使用 C++ Exception；而 ValueOrThrow() 则是显式转入基于异常路径的操作。EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result” RS General §4.1.3 “The use of noexcept”

活动图：通常的无异常流程在 HasValue() 之后分支到值或错误； ValueOrThrow() 是可选显示的异常路径。来源：EXP InterfacesGuidelines §3.1.2.3 “Advanced topics” EXP PlatformDesign §18.1.3 “Result”。

规范核心：价值还是错误

核心规范将Result映射到错误处理模型：对于可恢复错误，APIs应返回Result或Future。因此，Result 将正常值路径与作为数据值传输的错误分开。 SWS Core §7.2 “Error handling”SWS Core §7.2.5.4 “Result”
